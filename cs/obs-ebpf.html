eBPF 的入门与应用 ​

把小程序送进内核、验证之后执行：观测从「把原始事件搬出来」变成「在事件发生的地方折减成摘要」。

—— 据 Gregg, BPF Performance Tools, 2019；Linux bpf(2) 手册整理

上一课把埋点定为预算内的工程决策：指标、日志、追踪都从应用与系统事件流里分岔。缺口是事件流里没有的东西——第三方库不吐、内核悄悄做、而你恰好想问的问题：每次 ext4 写的延迟分布、每条 TCP 重传发生在哪个队列上。eBPF 观测已钉核心机制：tracepoint 与 kprobe 挂钩、map 核内聚合、verifier、CO-RE。本课按「入门到应用」补差：工具链怎么选、能问什么问题、为什么它敢常开在生产。不重讲 verifier 的检查清单。

问题 ​

你想观测的大部分东西没有现成接口。改内核加 printk 要重编译重启，问题早凉了；ptrace 跟踪每次系统调用进出各一次停走，跟一个高 QPS 进程等于把它按在地上；ftrace 的环形缓冲会满，读出来还是原始事件流，出核带宽按事件量付。kprobes 与 uprobes 给了挂钩点，但裸 kprobe 模块一个空指针就能带崩内核。缺口是第四种：动态、安全、低开销——不重启、不改代码，程序在核内过滤聚合，只有摘要出核。这就是 eBPF 在观测里的位置。

工具链谱系 ​

三档工具对应三种使用方式。bpftrace 一行脚本回答即席问题：一条命令挂上 tracepoint，直方图当场打出来，用于「现在就要答案」。BCC 用 Python 前端包 C 内核段，适合写原型与教学工具，代价是每次运行都要编译、依赖目标机的内核头。libbpf 加 CO-RE 一次编译、到处运行，靠 BTF 描述内核结构布局，随产品发布、长期跑在生产里——这是从「调惯了再看」到「默认在岗」的分界。

verifier 的两个具体数：BPF 栈上限 512 字节；指令数上限早期 4096 条，内核 5.2 起放宽到一百万。表达力就是被这些数切出来的。

术语翻译：verifier 就是内核的「程序安检门」——加载前把 BPF 程序逐条模拟执行，确认它必然终止、不越界访问内存、只调白名单函数，才放行进内核跑；安检不过，程序根本装不进去。

方法 ​

选事件源按稳定性排：tracepoint 是内核承诺的语义点，跨版本最稳；tracepoint 覆盖不到才用 kprobe 挂函数名，承担符号漂移的风险；用户态 USDT 挂在应用自留的探针上。写程序时把工作留在核内：过滤条件、按 pid 聚合、log2 直方图分桶都在 BPF 里做，用户态只轮询 map。应用面按 Gregg 的路数过一遍就是一张清单：块设备 I/O 延迟直方图看盘慢不慢，TCP 重传定位网络抖动，run queue 延迟看调度拥挤，文件系统延迟拆「慢在 VFS 还是慢在盘」。每条都是上一课的事件流里原本没有的维度。

直觉类比：tracepoint 像高速公路上的固定收费站——位置由内核开发者承诺不变，随便哪个版本都认得；kprobe 像在任意小路边临时设卡，哪里都能设，但路一改（内核升级动了函数），卡点就悬空失效。

机制 ​

为什么 eBPF 敢常开而内核模块不敢：verifier 把程序在加载前符号执行一遍——禁止无界循环、禁止未初始化指针解引用、只许调白名单 helper、出核数据要显式拷贝。观测代码被证明不会把内核带挂，这是「生产默认在岗」与「出事才敢上」的本质差别，代价是表达力受限。为什么核内聚合决定成败：每事件出核一次是拷贝加调度的开销，高事件率下观测本身改写被测系统；聚合之后出的只是桶计数，一亿次事件可能只出一张一百桶的直方图。CO-RE 为什么可行：BTF 把结构体布局嵌进内核镜像，加载时按目标内核重定位字段偏移，同一份二进制跨版本运行，不必在每台机器上装内核头。

数字实例：一亿次事件若每条 200 字节原始记录出核，就是约 20 GB 的拷贝流量；在核内聚合成一张 100 桶的延迟直方图，出核的只有几百字节。同一个问题，两种答案，开销差八个数量级。

边界 ​

本课不写成 bpftrace 语法手册，也不碰数据面——包处理与早丢是XDP 与 eBPF 网络的口径。观测程序自己占内核内存，map 要过 memcg 限额，否则观测把系统吃穿。eBPF 看得到内核与被插桩点，看不到 GPU 内部与未插桩的用户态黑盒；读用户内存的能力同时是合规边界，敏感进程的观测要有授权。CPU 微观行为——cache 未中、分支预测失败——不是挂钩点能数的，下一课交给 PMU 与 perf。

小结 ​

  • 缺口是动态、安全、低开销的观测：不重启、不改代码、摘要出核。
  • 工具三档：bpftrace 即席、BCC 原型、libbpf+CO-RE 上生产。
  • 事件源按稳定性选：tracepoint 优先，kprobe 兜底，USDT 进用户态。
  • verifier 用受限表达力换内核安全，512 字节栈与指令上限是刻度。
  • 核内聚合是常开的前提：直方图在核内分桶，而不是事件出核。
  • 出处：Gregg, BPF Performance Tools, 2019；Linux bpf(2)；主干课 eBPF 观测的机制口径。
