指针与别名 ​

指针保存的是对象的地址；两个指针若指向同一对象，通过其中一个写入，另一个立刻看见——优化必须把这种可能算进去。

—— 据 Kernighan & Ritchie, The C Programming Language, 2nd ed.；ISO/IEC 9899；Bryant and O'Hallaron, Computer Systems: A Programmer's Perspective 整理

上一课栈、堆与静态存储把三种寿命钉在三片区域上。本课不重讲 malloc，也不从类型论另起。缺口是：区域里的对象已经有名字，指针可以再制造跨作用域的名字。同一块存储多个视图时，读写通过谁发生？编译器何时不能假定「这两个指针绝不重叠」？

问题 ​

C 里指针是对象的地址值。&x 取址，*p 解引用，指针赋值把同一视图交给别人。若 p 与 q 都指向 x，则 *p = 1 与 *q = 2 写的是同一存储。缺口因此不是 * 的语法，而是别名对语义与优化的约束：未声明 restrict 时，通过指针的写可能改掉「看似无关」的自动变量或全局。后课的未定义行为、悬挂，都先要承认「地址可以共享」。

传参默认按值：指针本身被拷贝，指向的对象不拷贝。这让 callee 能改 caller 的栈对象或堆块，而不必把结构体整份搬进帧。链表、树、输出参数都靠这一条。本课只钉「指向对象」；数组表达式为何常常变成指针，是下一课。

指针不是整数 ​

调试时可以把地址印成整数，但指针算术与比较受对象类型和对象边界约束。把任意整数转换成指针再解引用，是未定义行为的入口，不是「底层很自由」。本课语义里，指针首先是指向某个活着的对象，不是机器字上的无符号算术。

K&R 用指针把数组、字符串与函数参数串起来。ISO C 的有效类型与别名规则约束「用哪种类型的左值去读这块存储」。CSAPP 把指针当地址，但立刻强调越界与类型错误会离开抽象机器。

方法 ​

int *p 表示 p 保存某个 int 对象的地址，*p 是该对象的左值。指针参数把 caller 与 callee 绑到同一存储。void * 可以携带任意对象地址，但不携带类型；解引用前必须转回实际类型。空指针不指向任何对象，解引用它是 UB。

两个指针是否别名，编译器在一般函数里无法静态看穿。于是它必须保守：不能把 *p 的旧值缓存过一次 *q 的写入。restrict 是程序员对「不重叠」的承诺，本课只点名，不把优化器内部展开。

函数若接受两个指针参数，文档必须声明它们是否允许重叠：memcpy 禁止，memmove 允许。这是别名写进契约的样板。实现可以用 restrict 让编译器按不重叠优化，一旦调用方违反，又是 UB。后课数组衰减会让 int a[] 与 int * 在参数上变成同一件事，别名分析看见的是指针，不是「数组对象不能重叠」的幻想。先把对象与指向它的指针分清，衰减才好讲。

机制 ​

别名让「局部变量没人改」不再自动成立。一次通过指针的存储，可能让另一条看似无关的读必须重新从内存取。这不是编译器笨，是语言允许共享。反过来，若程序保证两路指针永不重叠，却不告诉编译器，就会留下本可去掉的 load。

堆上尤其如此：malloc 返回的地址进入多个指针变量之后，释放与再分配会让同一数值地址稍后属于另一个对象。别名是空间上的重叠；悬挂是时间上的错位。本课先把空间重叠钉死。

别名也解释了为何「看起来没人写的局部变量」在优化报告里仍被反复加载：只要存在一个可能指向它的指针参数，编译器就必须假定一次未知存储会改掉它。restrict 是把这个假定反过来写成程序员承诺，本课不把它当默认。结构体字段指针与数组元素指针都是同一机制的特例。后课未定义行为会把「用错类型的左值去读」也称为别名违规；这里先只要空间重叠这一层。

边界 ​

本课不展开 strict aliasing 的逐条规则，也不讲整程序别名分析。数组与指针的互换见下一课。后课默认：指针表示活对象的地址；可能别名的指针限制优化；非法转换与空指针解引用属 UB。

小结 ​

  • 指针保存地址；多指针可指向同一对象，写入立刻共享。
  • 指针参数拷贝的是地址，不是对象；callee 能改 caller 的存储。
  • 把指针当任意整数用会离开语言；void * 必须先恢复类型。
  • 下一课处理数组在表达式里如何变成指针。
  • 出处：K&R；ISO C 有效类型；CSAPP 对指针即地址的程序员模型。
