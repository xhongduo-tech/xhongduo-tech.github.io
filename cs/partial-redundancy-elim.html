先修：死代码消除与 ADCE

下一课：值范围分析

部分冗余消除 ​

表达式在某些路径上已算过、某些没有：在缺少的路径上插入计算，使汇合点可用，再删除冗余。这是全局 CSE 与 LICM 的共同推广。

—— 据 Morel and Renvoise, Global Optimization by Suppression of Partial Redundancies, 1979；Knoop, Rüthing and Steffen, Lazy Code Motion 整理

后课SROA把更多表达式变成标量。缺口是部分冗余：a+b 在 if 的一枝算过，汇合后再算。PRE / lazy code motion：插入使变成完全可用，且尽量懒（不无故延长存活）。本课钉思想，不把全部数据流方程展开成作业。

问题 ​

可用表达式要求所有前驱都可用才消除。部分：有的前驱有。插入：在没有的前驱出口补上。缺口是插入点选择，避免多余计算与非法投机（陷阱）。

「部分冗余」翻译成白话：同一条 a+b，在 if 的左枝已经算过、右枝还没算，汇合点之后又算一次。对左枝来说汇合后那次是「完全冗余」可删，对右枝不是——整体是「部分」冗余——PRE 的办法就是在右枝也补一次计算，让汇合点两边都可用，再把汇合后那次删掉。

LCM（lazy code motion）把计算下移到尽可能晚，减寄存器压力。

「懒」在这里是褒义：计算不提前、拖到真正要用结果的前一刻。好处是结果值的存活期变短——类比网购宁可选晚一天送达，家里（寄存器）就不用腾地方早存货。寄存器紧张时，这个差别直接决定要不要溢出到栈。

插入不是随便投机 ​

不能在不执行的路径上插入可能除零的运算，除非证明安全或原程序也会执行。与 LICM 的「必执行」同一类约束。

Morel–Renvoise 1979。Knoop–Rüthing–Steffen LCM。龙书 9.5 相关。LLVM 有 GVN-PRE。

方法 ​

数据流：预期（anticipated）、可用、稍后。解方程，标记插入与删除。SSA 上可用 φ 与新名实现。

与 GVN：先编号再 PRE，识别代数等价。与循环：不变式外提是 PRE 的特例（环外插入）。

机制 ​

代码体积：插入复制运算。临界边（从多后继到多前驱）要拆，否则插入点不唯一——CFG 变换。不要在 PRE 里移动 store；那是另一套（store PRE 更危险）。

「临界边」就是从多后继块跳到多前驱块的那条边：往它上面插计算，说不清该插进哪个后继、又会被哪些前驱共享。做法是凭空加一个空基本块把边一分为二，插入点就唯一了。数字实例：循环头本就有入口与回边多个前驱，if 的两个出口块又各是多后继（比如收尾还是条件跳转），这样汇入的边才都是临界边，拆开后各得一个空块放插入的 a+b。

初学者容易以为 PRE 一定净赚：插入本身也是一次计算，若补出来的那条路径从来不执行，省下的只有汇合后那一次，代码体积却白涨——所以优化器要权衡插入的代价，且不能把可能除零的运算投机到未必执行的路径上。

边界 ​

本课不证 LCM 最优性。后课默认：部分冗余可经插入变成 CSE。下一课值范围：另一格，服务消除比较与越界。

也不把 PRE 当死代码（那是删除无观察，不是移动计算）。

小结 ​

  • PRE：插入补齐路径，消除部分冗余。
  • 懒移动减寄存器压力；投机受陷阱约束。
  • LICM 是循环上的特例。
  • 出处：Morel and Renvoise, 1979；Knoop et al. LCM；龙书。
