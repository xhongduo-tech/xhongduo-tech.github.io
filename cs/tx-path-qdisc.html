发送路径与 qdisc ​

qdisc 是设备出口的排队规则：FIFO、fq_codel、HTB 等在把 sk_buff 交给驱动之前做整形、分类与丢包。

—— 据 Linux tc 与 qdisc 文档；Gettys and Nichols 对 bufferbloat 的论述；Van Jacobson 对队列的背景

上一课走到套接字。sendfile 从文件进 skb。缺口是 TX：dev_queue_xmit、流量控制、驱动 ndo_start_xmit，以及 bufferbloat 为何是队列问题。

问题 ​

无队列：突发被网卡环丢。无限队列：延迟爆炸（bufferbloat）。qdisc：默认 pfifo_fast 或 fq_codel，按 band 或流公平排队，Codel 控延迟。缺口：BQL（字节队列限制）让驱动环不要堆太多；TC 分类器把 skb 送进不同 class；与 blk 调度 对照——一个整形包，一个整形 bio，不要混。本课不把 eBPF 分类器写成观测课。

锁：今日 xmit 常 per-queue；老的 qdisc_lock 是历史。GSO 在出队后切，避免 qdisc 按大包不公平。

方法 ​

sendmsg → TCP 分段策略 → ip_output → POSTROUTING → dev_queue_xmit → qdisc enqueue。设备空闲则 dequeue 到驱动。拥塞：qdisc 丢或标记 ECN。对照 NAPI：TX 完成中断会 net_tx_action 再拉队列。对照 cgroup：net_cls/net_prio 给 skb 打类。

机制 ​

qdisc 把「共享出口」收成可策略对象：延迟、公平、限速。没有它，多流 TCP 会在驱动环里互相伤害。不要写成 ISP 计费。与 GRO：收侧聚合，发侧整形，方向相反。

失败：ENOBUFS/EAGAIN 在套接字层因 sndbuf 或 qdisc 满——下一课背压。

数字实例：100 Mbps 链路、1 MB 的无限 FIFO——队尾包要等 \(8\times10^6/10^8 = 80\) ms 才出去，比典型 RTT 还长。Codel 的做法是「包在队列里驻留超过约 5 ms 就开始丢弃」，直接把这 80 ms 摁回几毫秒。

直觉类比：BQL 是给驱动环立一条「只堆半箱货」的规矩——常驻字节刚好够网卡不停工，而不是堆满整箱。货堆得越满，最后一件货等得越久；bufferbloat 的延迟全是队尾攒出来的。

实现上：BQL 按完成速率限制驱动环字节，减轻 bufferbloat。GSO 包在出队后切，以免一个 64K 逻辑包占满 band。锁less 的 pfifo 适合极高 PPS 的内部口。 读法上只引用上一课的结论，不把对象换成训练推理或限价簿。

边界 ​

本课不引入所有 HTB 层级实验。不保证无线 mac80211 的 qdisc 形状。下一课套接字自己的缓冲与窗口如何反过来压应用。

版本字段会变，课序钉的是机制对象「发送路径与 qdisc」，不是某一主线内核的结构体名。 后课默认：出口经 qdisc 再进驱动。sk 的 rcv/snd 缓冲如何限制未读/未确认字节，下一课。

常见误区：以为队列越长吞吐越高、丢包全都是坏事。bufferbloat 恰恰让 TCP 迟迟感知不到拥塞，把 RTT 撑大、交互流量受害；fq_codel 的「主动早丢」是用小概率丢包换低延迟，网页与语音这类小包流收益最大。

小结 ​

  • TX 经 qdisc 整形再交给驱动。
  • BQL 与 Codel 对抗无界延迟。
