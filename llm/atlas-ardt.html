大模型 · 2026-09-03

多模态自回归扩散 Transformer ​

文本、图像、相机与深度进同一条序列；每个新元素按自回归条件于前文，连续像素则靠扩散（整流流）去噪，而不是词表上的 softmax。

—— 归纳自 World Labs, Atlas: A World Model for Spatial Intelligence

Atlas 被写成从零预训练的 omni 世界模型：同一套权重处理文本、图像、视频与三维。架构名称是 multimodal autoregressive diffusion transformer（ARDT）——多模态自回归扩散 Transformer。四个词各管一件约束：多种数据类型进共享上下文；元素一个接一个生成；连续高维输出用去噪而不是离散词；骨干是矩阵乘友好的 Transformer。本篇拆这四个词如何接到一起；图像如何钉在位姿上见 共享空间上下文，整流流见 Rectified flow 潜空间扩散。

问题 ​

语言模型的自回归假定元素来自有限词表，一步一个 token、交叉熵即可。图像与深度是连续场，Ho 等人的 DDPM 用逐步加噪/去噪处理这种数据，但经典扩散一次生成整张图，不天然提供「先看这些视、再问下一个视」的接口。视频模型往往沿时间轴展开，相机是文本里的「缓缓左移」，三维重建又是另一族专用网络。世界模型若要在生成、重建、仿真之间共用权重，就需要一种序列，其元素可以是文本、一张图、一份位姿、一张深度，并且下一个元素可以是其中任何一种。

分开训四个专家再胶水拼接，会把空间对齐推到接口上，接口一变任务就断。ARDT 的赌注是：任务只是序列里输入与输出的排列不同，网络不必按产品功能切块。

离散逐步与连续去噪必须共存 ​

自回归提供可变长度与 KV cache；扩散提供像素。二者合在一起时，时间轴有两层：元素级的「下一个是图还是深度」，以及一张图内部的去噪步。若把每个像素当 token 自回归，长度不可接受；若把整段视频一次扩散、没有元素界，就无法在中途插入一张新的参考图或一条新的相机。ARDT 选择：序列的原子是模态元素，元素内部用扩散生成。

官方没有公开「一个元素对应多少潜 token、扩散多少步」。能写的是接口分层，不是一份可复现的超参表。不要把 RTFM 或某篇开源 AR 视频论文的配置填进 Atlas。

方法 ​

Atlas 把输入编码进上下文，再条件于上下文生成后续。与 LLM 的差别是：每张图（及深度图）落在三维位置上，上下文是空间的，不只是时间的。当前公开的模态包括文本、图像、相机位姿、三维深度；视频被表示为图像序列，每张图带显式相机。自回归规则是：每个输出元素条件于序列中更早的部分。换任务等于换序列模板：若干参考图加一条相机轨迹再出视频，或若干带位姿的图然后出逐像素三维点。

扩散一侧，Atlas 称自己是 rectified flow 模型，通过逐步去噪生成；并称它是潜扩散模型，可使用蒸馏、CFG、偏移噪声日程、VAE 进展。Transformer 提供注意力骨干，从而能沿用 LLM 服务里的 KV cache、感知缓存的路由、分离式 serving。这是架构兼容性声明，不是一份已公开的 Atlas 服务拓扑。

公式上的两层 ​

元素级：记序列 \(x_{<k}\)，下一个元素的类型与条件为 \(c_k\)，则 \(x_k\) 来自条件生成器 \(p_\theta(x_k\mid x_{<k},c_k)\)。若 \(x_k\) 是词，这一步可以是 softmax；若是图像潜变量，则 \(p_\theta\) 由整流流定义。潜空间里一条常用的直线路径（Lipman 一流匹配 / 整流流叙述）是

\[z_t=(1-t)z_0+t z_1,\qquad v^\star=z_1-z_0, \]

网络学 \(v_\theta(z_t,t,\mathrm{context})\approx v^\star\)，推理时沿速度场积分得到干净潜变量，再经 VAE 解码。Rombach 等人的 LDM 把扩散从像素挪到潜空间；Atlas 声明自己属于这一支，并用整流流而不是必须复述 DDPM 的离散时间马尔可夫链。

CFG 在条件生成里把无条件与有条件预测做外推，Ho & Salimans 给出图像扩散上的形式。Atlas 说可以使用 CFG，没有给出引导尺度表。把它写成「Atlas 的 CFG 等于某常数」是伪造。

任务即序列模板 ​

同一权重上，稀疏重建是「带位姿的图 → 逐像素三维点」；相机可控视频是「参考图 + 路径 → 后续图像元素」；文生图是「文本 → 图像」。差别只在 \(x_{<k}\) 里放什么、请求什么类型的 \(x_k\)。这比「四个专家加路由器」更接近 LLM 的 prompt 编程，也把空间位姿变成所有任务共享的字段，而不是某个专家私有的相机头。序列一旦写错（忘了给参考图钉 \(P\)），任务就退回普通图文模型。

omni 不表示每一个下游指标都超过专用模型。博客在相机跟随与稀疏重建上给了对照；其他任务（纯文本聊天、物理 rollout）没有作为本篇可引用的胜出声明。

机制 ​

四词能成一项，是因为注意力不在乎 token 来自哪个模态，只要进同一套 \(Q,K,V\)。空间位姿必须被编码进这些 token，否则「共享序列」只是把图文拼在一起的 VLM，相机仍会退化成文本。自回归让参考图数量可变：两张也可以、一百张也可以，这与稀疏新视合成、长空间上下文是同一接口。扩散让输出停在连续外观上，避免把图像量化成 codec token 再承受码本误差——那是另一条离散图像语言模型的路，Atlas 没走那条作为主声明。

与 RTFM 的关系：二者都是自回归扩散 Transformer、都把帧与位姿放在一起。Atlas 明确多模态（含深度与文本）、明确整流流与潜扩散、并展示写出点云与 splat。World Labs 没有说 Atlas 是 RTFM 换权升级，也没有公开两套权重的继承关系。技术笔记里只应写「同一思想家族」，不要写成论文实验的 ablation。

边界与工程取舍 ​

ARDT 没有公开层数、宽度、专家数、潜维。评测表在博客里针对相机跟随与稀疏重建，不能外推成「单一架构已经在所有世界模型任务上最优」。自回归元素越长，KV 越大，实时交互未必是 Atlas 首发形态——那是 RTFM 的产品点。扩散步与分辨率（博客展示到 1440p、约一分钟）是质量/延迟旋钮，步少靠蒸馏，步多靠等待。

不要给 Atlas 编造 arXiv。应引用的是 World Labs, Atlas: A World Model for Spatial Intelligence（2026 博客）。背景对照：Vaswani Transformer、Ho DDPM、Rombach LDM、Ho & Salimans CFG、Lipman et al. 2023 流匹配。这些是家族文献，不是 Atlas 作者列表。

小结 ​

  • ARDT = 多模态 + 自回归 + 扩散 + Transformer：任务是序列模板，不是四套模型胶水。
  • 元素可以是文本、图像、相机、深度；视频是带位姿的图像序列。
  • 元素之间自回归，元素内部整流流去噪；连续外观走潜空间，不走词表 softmax。
  • 因此能同时接 LLM 服务技巧（KV、分离式 serving）与扩散技巧（蒸馏、CFG、VAE）。
  • 与 RTFM 同属帧+位姿+AR 扩散家族，但 Atlas 的模态与写出三维是公开增量。
  • 出处：World Labs Atlas 博客（2026）。无 World Labs arXiv。背景为 Ho DDPM、Rombach LDM、Lipman 流匹配、CFG。
