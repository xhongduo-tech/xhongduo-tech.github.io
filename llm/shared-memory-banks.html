Shared memory 与 bank conflict ​

共享内存按 bank 交错编址：同一时钟里，一个 warp 若打到同一 bank 的不同字，硬件只能串行化，吞吐按冲突度成倍下降。

—— NVIDIA CUDA C++ Programming Guide, Shared Memory

片上共享内存（shared memory）是 CTA 内线程协作的暂存：容量远小于 HBM，带宽却高一个数量级以上。GEMM tile、FlashAttention 的 \(K,V\) 块、softmax 的行统计，几乎都先落到这里再喂 Tensor Core。带宽不是「整块 SRAM 任意读」，而是拆成 32 条 bank；地址映射决定一次 warp 访存是一次完成，还是变成两次、四次甚至三十二次。Bank conflict 是共享内存屋顶线里最常见、也最容易被 kernel 名字掩盖的那一项。

本篇按 CUDA 编程指南写编址、广播、填充与 swizzle，以及它和 MMA 布局的交接。不编造未公开的 bank 周期表。

问题 ​

CTA 把一块 shared memory 看成线性字节数组，硬件却按 32-bit 字交错映射到 32 个 bank：第 \(i\) 个字落在 bank \(i \bmod 32\)。一个 warp 的 32 个线程若访问 32 个不同 bank，一次发行即可；若多个线程访问同一 bank 的不同字，这些请求在该 bank 上排队，称为 \(n\)-way conflict，\(n\) 是该 bank 上互异地址的个数。冲突度直接乘在共享内存的有效带宽上：32-way 时，这块 SRAM 看起来并不比精心排队的全局内存快多少。

两种访问不是冲突。全体线程读同一地址，硬件做广播；多个线程写同一地址则是数据竞争，结果未定义，必须用原子或先规约再写。问题因此不是「共享内存慢」，而是「地址模式有没有把 32 路 bank 打满」。列优先扫一张 \(32\times 32\) 的 32-bit 表，正好让一列落在同一 bank，是教科书级的 32-way conflict。

64-bit 与向量化访问 ​

现代核常按 64-bit 或 128-bit 向量从共享内存取数，再喂 MMA 或寄存器流水。64-bit 字跨两个 32-bit bank。若一个 warp 的向量化负载在 bank 对上仍互不重叠，可以保持冲突免费；若步幅让偶数线程和奇数线程打到同一对 bank，就会出现 2-way 一类冲突。指南按计算能力写了 64-bit 的冲突规则，不能把 32-bit 的「连续线程、连续字」口诀原样套到 float2 / int4 上。Hopper 上 TMA 写入共享内存的粒度更大，冲突检查要从「线程自己算地址」改成「描述符落地后的物理 bank 分布」——搬得快不等于随后 warp 读得也快。

Nsight Compute 的 shared memory efficiency / bank conflict 计数器，比「核里用了 __shared__」更能回答问题。效率低而 HBM 命中很好，优先查 swizzle 与 padding，而不是再加大 tile。

方法 ​

避免冲突的工程手段是改布局，不是改算法数学。三条常用路。

第一，padding。二维 tile 的行宽若是 32 的倍数，按列访问必冲突；把行宽垫成 33 个 32-bit 字，列方向的 bank 号就错开。代价是浪费一块容量、以及后续地址计算要带上新 stride。小核、教学核常用；大 GEMM 会嫌 padding 打乱向量化对齐。

第二，XOR swizzle / permutation。把列号与行号异或后再作为 bank 索引，使「按行写、按列读」或「按 MMA 需要的 K-major 读」都尽量冲突免费。CUTLASS 与手写 Tensor Core 核几乎都走这条路：共享内存里的 \(A\)、\(B\) 瓦片不是行主序的朴素矩阵，而是为 ldmatrix / WGMMA 描述符准备的 swizzle 布局。改错一位，轻则 2-way，重则静默变慢且难以从源码看出来。

第三，改变访问主体。Ampere 的 cp.async 仍是线程协作拷贝；Hopper 的 TMA 由拷贝引擎按张量描述符写入共享内存，线程侧只在 mbarrier 之后按约定布局去读。冲突从「拷贝阶段」转移到「消费阶段」。消费方必须与生产者约定同一套 swizzle，否则 TMA 填得再满，WGMMA 读时仍会串行化。

与 MMA 布局绑在一起 ​

Tensor Core 不从「任意 shared memory 地址」吃数。ldmatrix 要求 8×8 或 16×16 一类碎片在共享内存里按特定跨距排列；Hopper 的 WGMMA 进一步要求 \(A\)、\(B\) 在 smem 中的 swizzle 与指令形状匹配。Bank 友好的布局若破坏了 MMA 碎片，编译器会插入额外 shuffle，或根本发不出 MMA。正确顺序是：先定 MMA 原子与 smem 布局，再验证该布局对消费 warp 冲突免费，而不是先 padding 再发现 Tensor Core 读不动。

FlashAttention 一类融合核还要把 softmax 的行向量放进同一块共享内存。行向量长度等于头维，往往不是 32 的倍数；归约时的跨步访问要单独做 padding 或 warp shuffle，不能共用 GEMM tile 的 swizzle。一块 smem 多种布局并存时，bank 规划是分区问题，不是单一公式。

机制 ​

Bank 是硬件上的独立存储体，每个时钟每个 bank 能服务有限次（对 32-bit 路径通常理解为一次）。Warp 的共享内存指令在发射前被拆成「按 bank 分组」的子请求。广播被识别为同一地址，不占用多次。冲突则让该指令的完成时间与 \(n\) 成正比，期间算术流水线只能等。这与全局内存的合并（coalescing）对称：那边按 128-byte 事务，这边按 32 路 bank；两边都是「地址模式决定有效带宽」，只是层次不同。

占用率与 bank 冲突会耦合。为了放下双缓冲 tile 而把每个 CTA 的 smem 用满，调度器能同时驻留的 CTA 变少；此时若再叠加高冲突，每个 CTA 的 smem 阶段更长，SM 更容易饿计算。软件流水 加大 smem 用量，换的是拷贝与计算重叠；重叠的前提是消费阶段本身不因冲突拉长，否则流水线填的是串行化气泡。

「冲突免费」只对某一个访问模式成立。同一块 tile 按行写、按对角读，不可能两种都免费，除非做两次转置或两份拷贝。GEMM 核选择让 MMA 读取免费，拷贝阶段用 TMA 或向量化写去摊薄生产者侧的代价。

调试时看什么 ​

先看核是否真的受 smem 约束：计数器里 shared efficiency 低、bank conflicts 高，同时 Tensor Pipe 不饱和，才值得改布局。若 Tensor Pipe 已高、冲突只是几个百分点，去抠 padding 的收益常被占用率损失抵消。改 swizzle 后必须重测数值：布局错会表现为静默错位，而不是 CUDA error。单元测试应用已知 GEMM / 注意力对照，不能只看墙钟变快。

边界与工程取舍 ​

不要把 bank conflict 解释成「共享内存坏了」。不要在任意架构上假设 32-bit 口诀适用于 128-bit 向量。不要为消除 2-way 冲突而把 tile 降到填不满 MMA 的尺寸——算术强度塌掉，比轻微冲突更伤。CUTLASS 的默认布局已经为各代 MMA 调过，手改一处 stride 就要把冲突与 MMA 合法性一起回归。

Cluster 与分布式共享内存（Hopper 起）让 CTA 能看到邻居的 smem。跨 CTA 的访问同样走 bank 规则，且多了跨 SM 的一致性与延迟。TMA multicast 把同一份数据写入多个 CTA 的 smem，能减少 HBM 流量，但每个 CTA 内部的消费布局仍要各自冲突免费。把 multicast 当成「自动无冲突」没有文档依据。

出处：NVIDIA CUDA C++ Programming Guide（Shared Memory、Memory Banks）；Volta / Ampere / Hopper 白皮书中的 SM 存储层次。CUTLASS 文档中的 smem swizzle 与 ldmatrix 布局是工程落地的对照实现，不是另一套硬件规则。

小结 ​

  • 共享内存按 32 个 bank 交错编址；同一 warp 打到同一 bank 的不同字就会 \(n\)-way 串行化。
  • 同地址广播不是冲突；同地址多写是竞争，必须另做同步或原子。
  • Padding 与 XOR swizzle 是改布局的两种手段；MMA 核几乎总走 swizzle，并与指令碎片绑定。
  • TMA 只改变谁来写 smem，不免除消费 warp 的 bank 规划。
  • 占用率、双缓冲容量与冲突要一起看；单纯消冲突而缩小 tile，可能更慢。
  • 出处：CUDA C++ Programming Guide 与各代 GPU 白皮书的共享内存章节。
