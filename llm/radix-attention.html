RadixAttention ​

请求结束后不要把键值丢掉；把它们挂进一棵按 token 前缀压缩的基数树，下一次共享前缀的调用就能少算一整段预填充。

—— Zheng 等，SGLang，2023–2024

自回归服务里，KV 缓存通常被当成「这一次请求的私有便签」：生成结束就释放，下一轮哪怕只多了一句用户话，也要把系统提示、历史轮次重新预填充一遍。Zheng 等人在 SGLang 里把这件事反过来：缓存是跨请求可检索的前缀索引，数据结构是基数树（radix tree）。他们把这套机制叫 RadixAttention。它不改注意力公式，改的是键值的生命周期、共享粒度和调度顺序。本篇写这棵树如何工作，以及它和分页、哈希前缀缓存的差别；块大小与布局见 分页 KV、前缀缓存。

问题 ​

语言模型程序很少是一次 generate 就结束。少样本里几十条示例反复出现；智能体把同一段工具说明贴到每一步；多轮对话的系统提示几乎不变；自洽性采样对同一题干抽许多条回答。这些调用在 token 序列上共享长前缀，数学上对应同一段 \(K,V\)。若每次都从头算预填充，浪费的是计算；若每次都独占一份缓存，浪费的是显存。更糟的是两者同时发生：引擎既重算，又无法把热前缀钉在卡上。

朴素的「系统提示缓存」只覆盖一层：所有请求共用同一段固定前缀。真实负载是一棵树。两条对话共享系统提示，在第一轮用户话处分叉；少样本的题干共享示例池，在题目处分叉。要索引这棵树，扁平哈希表不够自然——它能回答「这一整块是否见过」，却不容易回答「最长公共前缀停在哪、从哪一段开始必须新算」。RadixAttention 要解决的，正是多级前缀共享加上自动插入与淘汰，而不是让用户手工声明 cache id。

共享的对象是已经算好的 KV，不是原始文本。分词器或聊天模板稍有不同，token 序列就对不上，树走不下去。产品侧若把「语义相似」当成命中，会得到静默的错缓存。

方法 ​

基数树而不是朴素前缀树 ​

基数树是压缩过的 trie：边上可以挂一整段 token，而不必每个 token 一个节点。SGLang 用它保存「token 序列 → KV 张量（分页存放）」的映射。新请求从根向下匹配，走到第一个分叉或失配处，匹配上的节点所挂的 KV 直接复用，只对后缀做预填充，再把新节点插进去。生成出的回答也可以挂到叶子上，好让下一轮多轮对话把「系统 + 用户 + 助手」整段当成新的前缀。

树的节点与分页块对齐：论文实现里一页对应一个 token，便于任意长度的前缀切开；工程上也可以按更大的块切，代价是共享粒度变粗，见 分页 KV 与块大小。插入、查找、分裂都是树操作，和注意力核无关。注意力核仍然按块表去读非连续的 KV，因此 RadixAttention 与 PagedAttention、连续批处理、张量并行兼容；未命中时只多一次树行走，开销可忽略。

先淘汰叶子的 LRU ​

GPU 显存装不下整棵历史。淘汰不能按「最老的块」随便扔：若先丢掉靠近根的系统提示，所有分支一起失效。SGLang 的策略是 LRU，并且先驱逐最久未用的叶子。叶子对应某条请求独有的后缀；丢掉它只伤害那一支，公共前缀仍在。节点被访问时沿路径刷新时间戳，热分支会一直沉在根附近。

这与操作系统的页面 LRU 不同：这里的「页」有树形依赖，父节点的引用计数为零才能真正释放。实现上每个节点记引用次数（正在解码的请求、子节点、外部 pinning），引用归零才进入可驱逐集。

按最长共享前缀调度 ​

缓存命中率不只取决于树，还取决于请求到来的顺序。先来先服务会把两条共享长前缀的请求拆开，中间插入无关流量，把热节点挤出显存。SGLang 的缓存感知调度按已匹配前缀长度排序，优先跑更长命中的请求。离线情形下，Zheng 等人证明：当缓存容量不小于最长请求时，按基数树的深度优先遍历能达到最优命中率，而「最长共享前缀优先」与 DFS 等价。在线时 DFS 会被新请求打断，这一启发式仍然近似地先把当前热子树走完。

机制 ​

命中的本质是：因果注意力里，位置 \(1,\ldots,p\) 的键值只依赖于这些位置自己的输入。两条请求若 token 前缀相同，且位置编码从同一起点计，则前 \(p\) 步的 \(K,V\) 逐元素相等，可以指针级共享，不必拷贝。RoPE 若在写入缓存前就旋进键里，这条等式只在相同绝对下标下成立——所以能共享的是真正的前缀，不是「出现在别处的同一句话」。把一段话插到文档中间再想复用 KV，相位已经变了，树也不会（也不该）命中。

预填充代价从 \(O(n^2)\) 的注意力（外加线性的 FFN）变成只对后缀 \(n-p\) 计。当 \(p\) 接近 \(n\)，首 token 延迟接近「几乎只有解码」。吞吐增益在前缀很重的负载上最大：论文报告相对当时的先进推理系统，在智能体、少样本、JSON、检索增强与多轮对话等任务上，吞吐最高约 \(6.4\) 倍。这个数字不是注意力核变快，而是少做了重复预填充、并靠调度把命中率抬上去。

基数树的边压缩降低节点数，不降低 KV 字节。省显存靠的是多请求指向同一块物理页。一条从未共享的长提示，树帮不上忙，只是多了一层索引。

边界与工程取舍 ​

RadixAttention 吃的是精确 token 前缀。模板空格、工具 schema 的字段顺序、系统提示里一个标点，都会让匹配在根附近就断开。多租户下还要隔离：不能让用户 B 命中用户 A 的对话节点。实现上通常在根下先按模型、采样参数、lora 适配器分叉，再进 token 树；采样温度不同未必阻止 KV 复用（KV 与采样无关），但 LoRA 权重不同则必须分树。

淘汰策略在「树形 LRU」和「按字节的全局 LRU」之间会打架。只按叶子 LRU，可能留下很多半热的中层节点，碎片看起来像「树很大、命中却一般」。需要周期性合并或对长期无子、无引用的内部节点回收。调度的最长前缀优先会牺牲公平：一条短请求可能一直排在长前缀批后面。延迟敏感的入口要限制重排窗口，而不是无界 DFS。

与哈希块前缀缓存相比，树的优势是多级共享与自然的分裂；哈希的优势是每块 \(O(1)\) 查找、实现更贴近分页块表。两者可以合流：用哈希给块打指纹，用树（或父块哈希链）表达前缀关系。不要把 RadixAttention 理解成一种新的 softmax。它是缓存索引。注意力核仍然可以是 FlashAttention 或分页核；换核只影响「如何读这些页」，不影响「哪些页被哪些请求共享」。

自洽性采样是树的典型赢家：同一题干挂出许多叶子。若采样时把题干 KV 复制成 \(k\) 份，显存立刻按 \(k\) 倍涨；挂到同一父节点则只为每条回答增长后缀。

另一条边界是生成长度未知。定理里的最优命中假定缓存装得下最长请求；真实解码会把叶子不断拉长，可能反过来挤掉父前缀。这时要给正在运行的请求 pin 住路径，只从空闲叶子里驱逐，否则会出现「自己把脚下的前缀回收掉、被迫重算」的抖动。

小结 ​

  • RadixAttention 用基数树索引 token 前缀到分页 KV，使跨请求、跨调用的键值可以自动复用。
  • 请求结束后缓存保留；新请求走最长前缀，只预填充后缀。
  • 淘汰采用先丢叶子的 LRU，避免先拆公共根；调度按最长共享前缀，离线时等价于 DFS 最优命中。
  • 共享要求 token 与位置都一致；RoPE 已写入的键不能挪到别的下标上再用。
  • 未命中时开销很小；增益来自少算预填充和高命中率，不是新的注意力公式。
  • 多租户、LoRA、模板漂移会切断匹配，需要在树的上层先按运行时上下文分叉。
  • 出处：Zheng 等，SGLang 系统中的 RadixAttention（论文题为高效执行结构化语言模型程序，预印本 2023 起，后续修订把系统名定为 SGLang）。
