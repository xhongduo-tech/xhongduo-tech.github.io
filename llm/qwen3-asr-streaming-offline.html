流式与离线统一推理 ​

动态注意力窗口使 Qwen3-ASR 能以短块做流式推理，也能对长查询做离线推理。

—— Qwen Team, Qwen3-ASR Technical Report, arXiv:2601.21337

许多识别系统把流式和离线训成两套权：一套因果卷积加右上下文，一套全句 AED。Qwen3-ASR 的设计目标相反：同一套权重，推理时只切换窗口与块的消费方式。1.7B 与 0.6B 都标成 Offline / Streaming。评测用 2 秒块、5-token 回退、最后四块不固化，流式比离线略掉点，但不必换模型。本篇写统一如何成立、流式协议里各整数做什么、以及不能靠「再训一个流式头」来补的边界。

问题 ​

离线要质量：看见整句甚至整段歌，LID、专名、歌词才稳。流式要延迟：首字要在百毫秒到秒级出现，不能等用户说完。若用两套权，产品要维护双倍检查点，还要在「用户突然停止说话」时在两套模型间切换，槽位格式还可能不一致。LALM 的前缀结构其实允许第三种路：编码器对已到达的音频算表示，解码器立刻在现有前缀上生成；未到达的帧不进入卷积块和注意力窗。问题是训练分布必须覆盖「前缀不完整」，否则上线短窗就是域外。

报告用动态 FlashAttention 窗口 1s–8s 覆盖这一域。统一推理不是口号，是「训练见过短窗与长窗、卷积按块、解码器是同一 Qwen3」。需要写清推理期还有哪些非权重旋钮：块长、回退、未固化块数。这些旋钮会改 WER 和 TTFT，但不应被误写成第二套结构。

统一指权重与槽位，不指延迟相同 ​

输出格式仍是 language … <asr_text> …。流式与离线都先出语种再出字，产品才能用同一解析器。延迟不可能相同：离线等全段编码完再解码，流式在第一块后就解码。0.6B 平均 TTFT 可到约 92 ms，那是在线异步、块已在路上时的数，不能拿去要求离线批处理也 92 ms 出整篇转写。

「统一」容易被理解成 RTF 相同。离线批处理可以用大 batch 把 GPU 打满，流式受到达过程限制。表 2 分开报 offline batch 与 online async，正是因为两种负载的屋顶线不同。权重统一，调度不统一。

方法 ​

同一前向，不同可见集 ​

记发布权重为 \(\theta\)。流式与离线是同一映射 \(f_\theta\)，差别只在时刻 \(\tau\) 的可见音频 \(x_{\le\tau}\)：

\[y_{\mathrm{off}}=f_\theta(x_{1:T}),\qquad y_{\mathrm{str}}(\tau)=f_\theta(x_{\le\tau}). \]

前向路径不变：Fbank → 分块 Conv2D → AuT 窗内 FlashAttention → projector → Qwen3。离线：\(T\) 可达约 20 分钟，注意力窗取 8 秒量级并沿时间滑动或分段。流式：\(\tau\) 按约 1–2 秒前进，只编码新块，窗取短。不存在另一份 \(\theta_{\mathrm{str}}\)。

评测协议里的三个整数 ​

报告在开源集上的流式设定包括：2 秒块、5-token 回退、最后四块不固化。2 秒块与动态窗下界同数量级，保证每块有足够 12.5 Hz token。回退表示已发出的文字在后续块到来时允许改前 5 个 token，避免「过早固化」把还没听完的词写死。最后四块不固化，等于在尾部保留约 8 秒的可修订区，与离线 8 秒窗呼应。产品若把回退设为 0，延迟更好看，WER 会接近「假流式」的掉点上界。

离线可以视为「块数 = 全句、回退无意义、窗 = 8 秒」的端点。两端之间没有额外损失项专门叫 streaming loss；SFT 里包含 streaming-enhancement 数据，是让模型在不完整前缀上仍输出合法槽位，而不是另开一组参数。

5-token 回退改的是已经展示给用户的字，不是编码器状态。编码器块一旦算完通常不重算（除非产品做 overlap）。把回退理解成「重新听一遍」，会高估流式算力。算力仍按新块的 13×2 量级 token 走。

机制 ​

统一能成立，因为时间轴上的三个原子已经对齐：卷积块约 1 秒、注意力窗 1–8 秒、音频 token 12.5 Hz。流式只是停在原子网格的较早位置。Qwen3 的因果掩码本来就不看未来文字；只要音频前缀也不含未来帧，整网因果。动态窗训练让短前缀不是域外：模型在 1 秒上下文里见过如何 LID、如何开始转写。于是推理换窗等于换条件长度，而不是换函数族。

质量差来自信息，不是来自另一套归纳偏置 ​

表 8 上同一规格离线优于流式，差额来自「后几秒还没听见」以及回退仍有限。这不是 CTC 与 AED 两种损失的差，也不是因果卷积与双向卷积的差。把差额误诊为「需要再加一个流式编码器」，会破坏统一、并把维护成本送回去。应先调块长与回退，再考虑是否真的要第二套权。歌声、带伴奏长歌曲尤其依赖离线长窗；流式听歌产品应接受延迟换质量，而不是期望 1 秒窗打平 8 秒窗。

RL 阶段含提升复杂环境稳定性的功能数据，对流式也有帮助：短窗下噪声比例更高，策略需要更稳。但 RL 仍在同一解码器上跑，没有分流式策略头。机制上，统一贯穿预训练（动态窗 AuT）、Omni、SFT、RL 四段。

边界 ​

统一不覆盖任意块长。块远小于 1 秒会打断 100 帧卷积几何；块远大于 8 秒会离开训练窗。2 秒是评测点，不是唯一合法值，但应落在 \([1,8]\) 内。跨说话人实时字幕若要求「谁在说」的帧级标签，当前统一 ASR 不提供；那是日记化，不是本家族的流式模式。

ForcedAligner 是 NAR、离线批处理，不以流式统一为目标。不要把 ASR 的 Offline/Streaming 开关套到对齐器上。时间戳在转写完成（或局部固化）之后再填槽。

另一边界：vLLM 服务。在线异步与离线批的队列不同，CUDA Graph 与并发度会改 TTFT 分布。权重统一之后，产品仍要为两种入口写两种调度。把「一个检查点」理解成「一个服务进程打天下」可以，但要在网关层区分超时与回退策略。指令注入约束在两种模式下都有效：流式也不跟用户用语音改槽位格式的指令走。

相对传统流式 CTC / Transducer：那些系统用预测网络和联合网络做帧级发射，天然低延迟，但没有 52 语种 LALM 的世界知识。Qwen3-ASR 用统一 LALM 换的是秒级块延迟加可修订输出，不是 40 ms 的逐帧发射。选型时应把延迟预算说清楚，不要用 Transducer 的延迟表来审这份统一推理。

小结 ​

  • 流式与离线共用同一套 Qwen3-ASR 权重，差别是可见窗、块的到达与文字回退。
  • 动态 1s–8s 窗加上分块 Conv2D，使短前缀落在训练分布内。
  • 评测示例：2 秒块、5-token 回退、最后四块不固化；这些是推理旋钮。
  • 流式掉点主要来自未听见的未来，不是来自第二套归纳偏置。
  • ForcedAligner 与 ASR 的流式开关不是同一接口。
  • 出处：Qwen Team, Qwen3-ASR Technical Report, arXiv:2601.21337；对照 CTC / AED / Transducer 的专门流式系统；Whisper 的固定切段是离线对照而非统一权。
