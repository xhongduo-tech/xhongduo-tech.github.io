FlashKDA 关联记忆内核 ​

KDA 把有限维的循环状态当联想记忆：通道级遗忘决定哪一维该淡，delta 规则决定当前键方向该怎么改写；核必须把这条递推收成 Hopper 上的分块 GEMM，而不是逐步 for 循环。

—— Kimi Team，Kimi Linear: An Expressive, Efficient Attention Architecture，arXiv:2510.26692；核实现见 MoonshotAI/FlashKDA

Gated DeltaNet 已经把标量遗忘门乘进 delta 更新；DeltaNet 把联想记忆写成对当前键的一步回归。Moonshot 的 Kimi Delta Attention（KDA） 再把遗忘从「一头一个标量」拆成通道级对角门，让有限维状态 \(S_t\in\mathbb{R}^{d_k\times d_v}\) 按特征维分别过期。数学对象仍是一块联想表：读是 \(S^\top q\)，写是带衰减的 rank-1 修正。FlashKDA 是这条更新在 GPU 上的融合核：CUTLASS 实现、对接 flash-linear-attention 的 chunk_kda，服务 Kimi Linear 一类 3:1 线性层加全局 MLA 的混合骨干。本篇写核要匹配的状态几何与调度，不把 Kimi Linear 的全部评测表再抄一遍。

问题 ​

Softmax 注意力的缓存随长度线性涨、计算随长度二次涨。线性注意力把过去收成固定大小的状态，decode 变成「读表 + 改表」，KV 体积不再跟 \(T\) 走。代价是容量大约只有键维：正交联想超过 \(d_k\) 就开始碰撞。Gated DeltaNet 用一头共享的 \(\alpha_t\) 衰减整张表，清得快、改得粗；KDA 要的是：某些通道该记住远距离标识符，另一些通道该在场景切换时立刻忘掉。通道级门一旦进递推，状态转移变成对角加低秩（DPLR）一类结构。通用 DPLR 分块算法算得动，但常数大，Triton 参考核喂不饱 Hopper 的 Tensor Core。

没有专用核时的失败模式有两种。一种是逐步循环：每个 token 一次小 GEMM，启动开销和寄存器抖动把线性复杂度的墙钟优势吃掉。一种是把 KDA 当成普通 GDN 或 Mamba-2，丢掉通道门，数值对不上检查点。FlashKDA 的对象是第一种：在已经定死的头宽、分块与门控语义上，把 prefill 的块内并行和块间状态传递叠起来。

联想记忆不是 KV cache 的别名 ​

KV cache 存的是过去每一格的键与值；联想状态 \(S\) 存的是「键方向 → 值」的压缩表。读查询时不再扫全部过去 token，只做一次 \(S^\top q\)。写入遵循 delta 规则：先读出当前键上的旧值，再按 \(\beta_t\) 把新值写回去，相当于对 \(\tfrac12\|S^\top k_t-v_t\|^2\) 做一步 SGD。KDA 在此之前先把 \(S\) 乘上 \(\mathrm{Diag}(\alpha_t)\)，让每一维有自己的半衰期。混合模型里，每四层里三层走 KDA、一层走全局 MLA：长程精确检索留给那一层 softmax，其余层用固定状态扛吞吐。Kimi Linear 报告在公平对比的 1.4T token 设置里，相对满 MLA 可把 KV 用量降到约四分之一，1M 上下文解码吞吐可到约 \(6\times\)。那是架构账，不是核单独刷出来的峰值。

仓库把核函数写成 flash_kda.fwd，张量是 \(q,k,v,g,\beta\) 加 \(A_{\log}\)、\(\mathrm{dt\_bias}\) 与下界。\(\beta\) 在核内做 sigmoid；头宽当前要求 \(K=V=128\)。不要把 FlashKDA 当成任意线性注意力的通用后端，GLA / Mamba-2 仍走自己的核。

方法 ​

Kimi Linear 把 KDA 的块算法写成专用 DPLR 变体：对角遗忘加 rank-1 修正，比一般 DPLR 少做若干项，同时保持与经典 delta 规则一致。序列切成块长 \(C\) 的 chunk；块内可以矩阵化，块间必须把 \(S\) 传下去。FlashKDA 站在这条公式上，用 CUTLASS / CuTe 在 SM90+ 上排 TMA 与 WGMMA，而不是再写一层 Python 循环。公开仓库说明：安装后由 flash-linear-attention 的 chunk_kda 自动分发，模型代码不必改；可变长 batch 走 cu_seqlens，此时 batch 维必须为 1，状态形状变成按序列条数 \(N\) 索引。可选 initial_state / final_state 用于多段拼接或跨请求携带联想表。

一次前向里要对齐的张量 ​

查询、键为 [B,T,H,K]，值为 [B,T,H,V]，门控 \(g\) 与键同宽，在激活前进入核；\(\beta\) 是 [B,T,H] 的 logits。尺度是标量。输出写进预先分配的 [B,T,H,V]。A_log 是每头一份的对数门参数，dt_bias 是 [H,K] 的通道偏置，lower_bound 把遗忘门钉在 \([-5,0]\) 一类区间，避免 \(\alpha\to 0\) 时状态数值炸掉。无状态调用时不传 initial/final；有状态时两者 dtype 必须一致，可取 bf16 或 fp32。这些约束来自核的寄存器与 MMA 形状，不是随意的 API 口味。

Prefill 与 decode 不是同一工作点 ​

Prefill 的 \(T\) 大，块内 GEMM 饱满，核的价值是把对角门与 delta 更新融进同一套流水，避免「先算衰减再算 Householder」两次读状态。Decode 一步 \(T\) 很小，真正贵的是反复加载 \(S\) 以及混合骨干里那一层 MLA 的 KV。FlashKDA 公开材料把加速重点放在 prefill：相对 FLA 里的 Triton chunk_kda，第三方在 H20 上量到大约一点七到两点多倍的墙钟，口径是核对比，不是端到端生成。服务若只换 decode 循环却仍用慢 prefill，长请求的首 token 延迟不会动。KDA 层本身不维护 token 级 KV；混合模型里 MLA 层仍要分页缓存。核加速的是线性层，不是把 MLA 也线性化。

机制 ​

通道级门能工作，是因为联想表的不同奇异方向对应不同寿命的模式：局部句法、实体标识、场景开关。标量 \(\alpha_t\) 只能给整张表同一个半衰期；对角 \(\mathrm{Diag}(\alpha_t)\) 允许「这一维快忘、那一维慢忘」，更接近 GLA 的细门，同时保留 delta 的定点改写。专用 DPLR 变体的意义是：一般 DPLR 为任意对角加低秩准备了额外校正项，KDA 的低秩部分就是 delta 的 \(k k^\top\)，可以消掉若干矩阵，让块算法的算术强度落到 Tensor Core 友好的 GEMM 上。Triton 也能发 WGMMA，但不保证 ping-pong、warp 分工与 TMA 切块和手写 CUTLASS 一样紧。FlashKDA 吃的就是这最后一截调度，不是新的注意力公式。

Kimi Linear 公平对比用的是 48B 总参 / 3B 激活、KDA 与 MLA 3:1 交错，训练约 1.4T token；另有 5.7T 的更长程检查点。引用 51.0 MMLU-Pro、84.3 RULER 时必须写「相对同配方满 MLA」，不要写成 FlashKDA 核的分数。

为什么不能把状态当成普通 KV 来分页 ​

分页 KV 的单位是 token 块；KDA 状态的单位是每头一张 \(V\times K\) 的表。cu_seqlens 把变长样本拼成一条，状态按序列条数存，而不是按 token 页表间接。实现若误用 MLA 的 block table 去索引 \(S\)，会读到错误的联想。多轮对话要携带 final_state 到下一轮 initial_state，相当于 RNN 隐状态，而不是把历史 token 再 prefill 一遍——这正是线性层省 KV 的来源。MLA 层仍要真实缓存。混合比例 3:1 是报告里的经验点：再稀全局层，精确针测会掉；再密全局层，缓存账作废。

边界与工程取舍 ​

FlashKDA 公开合同绑在 SM90+、头宽 128、bf16 主路径。A100 没有这条 TMA/WGMMA 组合，不能把仓库核当可移植后端。门控下界、A_log 与 dt_bias 必须与训练时的参数化一致，否则遗忘曲线对不上。不要把 FlashKDA 接到纯 softmax 模型上「加速注意力」：没有 KDA 层就没有这份状态。也不要把第三方 H20 的核加速比抄成 1M 上下文 \(6\times\) 解码——后者来自 Kimi Linear 相对 MLA 的端到端 TPOT，含缓存体积，不是 CUTLASS 单独的数字。

与 DeepSeek 的 FlashMLA 分工相反：FlashMLA 加速的是潜向量上的 softmax；FlashKDA 加速的是有限维联想更新。同一套服务里两者可以并存，前提是层类型交替，调度器按层选核。评测必须声明：测的是 chunk_kda 替换、还是整网 1M 解码。出处：Kimi Team，Kimi Linear，arXiv:2510.26692；核仓库 MoonshotAI/FlashKDA。不要伪造独立会议论文号。

FLA 原作者路径在 fla-org/flash-linear-attention 的 fla/ops/kda。FlashKDA 是 CUTLASS 后端，不是第二套数学。对照时应写清：Triton 参考、CUTLASS 生产、以及是否启用变长 cu_seqlens。

小结 ​

  • FlashKDA 是 Kimi Delta Attention 的 CUTLASS 核：把通道级遗忘加 delta 改写的联想状态，收成分块 GEMM。
  • 头宽当前钉在 128；状态可跨请求携带；变长走 cu_seqlens。
  • 加速对象主要是 prefill 的 chunk_kda，不要与混合模型 1M 解码的 \(6\times\) 混为一谈。
  • KDA 层无 token 级 KV；全局精确检索仍靠交错的 MLA。
  • 出处：arXiv:2510.26692 与 MoonshotAI/FlashKDA。不编未公开的 TFLOPS 表。
