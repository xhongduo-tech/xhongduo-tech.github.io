AlphaZero 式语言模型 ​

学一个价值函数，让树搜索既能在推理时指导解码，又能当作策略改进算子，把搜到的轨迹蒸馏回策略。

—— Feng et al., AlphaZero-like Tree-Search can Guide Large Language Model Decoding and Training，arXiv:2309.17179，ICML 2024

RAP 与 ToT 证明：在冻结大模型上用提示当价值，浅树搜索就能抬多步推理。它们的上限也写在论文里——价值依赖「够强的模型 + 精心提示」，深度往往停在个位数，棋类里那种几十上百步的搜索深度达不到。Feng 等人的 TS-LLM（tree-search enhanced LLM）要把 AlphaZero 的闭环搬过来：不是提示一个评论员，而是训练一个与策略同族的价值头（以及终局 ORM）；搜索不只服务一次 decode，还作为策略改进算子，迭代地做蒸馏与价值评估。这与 MCTS 用于语言模型 的默认形态——网络冻结、树随查询清空——明确分道。本篇写 TS-LLM 实际训了什么、五种搜索变体差在哪，以及「像 AlphaZero」仍然缺哪一块（没有围棋规则、没有从零自我对弈出超人类棋力）。

问题 ​

语言生成可以写成 MDP：状态是已写前缀，动作是 token 或一个句子，奖励在多数任务上稀疏，只在序列结束时出现（对错、偏好标量）。直接对 \(\pi_\theta\) 做 RL，中间步没有学习信号；只在测试时搜，下次查询能力不增长。ToT/RAP 的提示价值在小模型上不可靠：论文指出 125M–7B 档很难靠「请给这步打分」得到可规划的 \(V\)，而 AlphaZero 的价值网是从对局结果里学出来的。

第二个缺口是深度。ToT 深度约 10、RAP 约 7；AlphaZero 在棋上可以走到深得多的树。语言若按 token 展开，深度等于生成长度，RLHF 一类对齐任务没有自然的「步骤」边界。TS-LLM 要同时覆盖句子级推理（GSM8K、Game24、PrOntoQA）和 token 级对齐（深度 64）、以及棋残局决策。价值必须在这些不同动作定义下都能训，而不能假设每次都有 GPT-4 当裁判。

提示价值不是学出来的 \(V\) ​

把「是否正确」问回同一个生成模型，得到的是该模型的口头自信，与真实回报的校准可以很差。TS-LLM 用训练数据上的真标签或给定奖励函数，对采样轨迹做 TD-\(\lambda\) 或蒙特卡洛目标，最小化价值头的均方误差；ORM 在完整序列的最后位置回归终局回报。价值解码器通常从策略解码器适配，或共享骨干再加 MLP 出标量。没有这套回归，后面的 MCTS-\(\alpha\) 无法在中间节点备份，只能像 RAP 那样走到终点再估。

论文强调价值可在 125M 到 7B 上工作，甚至在部分比较里优于 GPT-3.5 的提示自评。这是「小模型 + 学出来的 \(V\)」对「大模型口头打分」，不要读成 TS-LLM 在绝对分数上击败 GPT-4。

方法 ​

动作有两档。句子级：思维或等式一步一条边，树浅但扩展时只能子采样 \(w\) 个候选（类似 Sampled MuZero），搜索空间与 \(\pi\) 的生成空间有缺口。token 级：动作是词表符号，树深、宽度大，但不再需要「何为一步」的启发式。超参表里 GSM8K 宽 6、深 8；Game24 宽 20、深 4；RLHF 宽 50、深 64；棋残局深 50。这些数字是搜索空间声明，不是模型参数量。

推理期，固定 \(\pi\)，用学好的 \(v_\phi\) 与 ORM 跑树搜索。论文列了五种算法：带价值剪枝的 BFS-V / DFS-V（ToT 风格）；经典 MCTS（RAP 风格，从根走到终局再备份）；MCTS-\(\alpha\)（AlphaZero 变体：中间节点用 \(v_\phi\) 备份，按访问次数的温度分布走子，走完不能回溯除非多次搜索）；MCTS-Rollout（始终从根重搜，用价值做中间备份，直到凑满 \(N\) 条完整答案或打到 token 预算）。多次搜索默认 intra-tree：同一棵树复用，省计算，但多样性下降。聚合可以多数票、ORM-Max 或 ORM-Vote。

训练期把搜索当成策略改进：用树产出更高回报的轨迹，扩充数据集，再对 \(\pi\) 做监督蒸馏，对 \(v_\phi\) 做策略评估。如此迭代。这是相对 RAP/LATS 真正多出来的半边——测试时搜索变成了数据生成器。

五种搜索不要画成一条「越 AlphaZero 越好」的轴 ​

BFS-V 像以累计奖励为目标的束搜，宽度固定、不回溯。普通 MCTS 需要终局样本，树深时方差大。MCTS-\(\alpha\) 能在中间备份，但一旦走子就不能悔棋，适合在线逐步生成。MCTS-Rollout 用更多 token 换从根重新分配预算，更接近「同一题上加测试时计算」。选哪种应由任务深度与是否允许后悔决定，而不是品牌名。句子级任务上过宽的 \(w\) 只是更贵的采样；token 级上深度 64 已经接近对齐回复的长度，再深首先撞的是 KV 而不是算法。

机制 ​

AlphaZero 的核心不是 UCB 本身，而是「搜索改进策略分布，再用改进后的分布训练策略与价值」。TS-LLM 把改进后的分布落实为树上的访问或 ORM 选出的完整 \(y\)，蒸馏是最大似然去模仿这些 \(y\)，不是直接拟合 \(\pi_{\mathrm{MCTS}}\) 的逐步访问计数（实现上可以，论文主路径是轨迹级增强）。价值学习与 ORM 把稀疏终局回报变成树上可用的标量，使中间备份合法。没有可靠 \(V\) 时，MCTS-\(\alpha\) 退化为乱备份，深度优势消失。

与棋的差别写在转移上。围棋规则确定、终局可判定；语言的「环境」在 GSM8K 上是答案核对，在 RLHF 上是奖励模型，在棋残局上才接近真规则。奖励模型会黑客，ORM 会偏爱某种风格，搜索会放大这些偏置——这与 Best-of-N 的核对器上限是同一件事，只是树把预算花在共享前缀上。

论文标题里的 “AlphaZero-like” 是算法类比：学 \(V\)、用访问指导走子、迭代改进。它没有从随机初始化自我对弈出新的语言能力，基座仍然是已经预训练的 LM。不要写成「语言模型版 AlphaZero 已完成」。

多答案聚合是第二层测试时计算 ​

同一棵树上抽出 \(N\) 条完整答案，再用 ORM 加权，等于在搜索之外又做了一次 BoN。报成绩必须拆开：单次搜索的根策略、多次 intra-tree、以及 ORM 聚合。把三者叠成一个数字，无法判断增益来自 \(V\)、来自宽度，还是来自核对器。

边界与工程取舍 ​

TS-LLM 的实验规模是公开可训的小到中等 LM 与标准集（GSM8K 7.5k 训练、RLHF 约 30k），不是前沿闭源模型的秘密搜索。深度 64 的 token 树在词表为数万时仍然极度稀疏，扩展必须靠 \(\pi\) 提议，不是枚举合法棋步。句子级一旦扩展就把 \(w\) 个节点钉死，后续多次搜索无法再从 \(\pi\) 里抽出新的同层候选——论文把可重采样的 inter-tree 放在附录，主文默认 intra-tree。

计算账：每次备份一次价值前向，每次扩展多次 decode。相对单次 CoT 的墙钟是数量级差距，必须按 测试时计算 报预算。蒸馏会把搜索时找到的模式写进权重，也会把 ORM 的偏见写进权重；迭代越多越像在拟合核对器。安全上，对齐任务的 token 级 MCTS 会最大化奖励模型，拒答若不在 \(R\) 里，搜索比贪心更会越狱。

开源实现以作者仓库为准（如 LLM_Tree_Search）。不要把后续过程奖励、o1 系统卡或 DeepSeek-R1 的 GRPO 倒填进 2309.17179：那些是另一条「长链 RL」路线，不一定显式建树。

对照表：ToT/RAP = 冻结大模型 + 提示价值 + 浅树；TS-LLM = 可训价值 + 深树 + 可选蒸馏。LATS = 环境反馈的智能体 MCTS，通常仍不更新 \(\theta\)。三条不要合成「MCTS 论文一篇」。

小结 ​

  • TS-LLM 用学得的价值/ORM 做 AlphaZero 风格的树搜索，并可把轨迹蒸馏回策略，覆盖推理、规划、对齐与决策。
  • 句子级与 token 级动作决定树深与搜索缺口；MCTS-\(\alpha\) 与 MCTS-Rollout 的差别是能否从根重搜。
  • 提示自评被回归价值替换，这是相对 RAP/ToT 的关键可扩展点。
  • 仍不是棋类自我对弈：转移与奖励来自语言任务，基座是预训练 LM。
  • 出处：Feng et al., AlphaZero-like Tree-Search can Guide Large Language Model Decoding and Training，arXiv:2309.17179，ICML 2024。
