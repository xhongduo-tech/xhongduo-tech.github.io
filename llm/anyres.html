动态分辨率与 AnyRes ​

与其把整张高清图硬缩进 ViT 的固定窗口，不如留一张全局缩略图，再按原图长宽比切成若干格，每格仍用原来的编码器走一遍。

—— Liu 等, LLaVA-NeXT AnyRes

CLIP 与早期 LLaVA 的视觉输入边长是固定的：224 或 336。文档上的小字、屏幕截图上的图标，缩进去就不可逆。LLaVA-NeXT 提出 AnyRes：高分辨率图不单次 resize 到固定画布，而是选一个接近原图长宽比的网格，切成多块，每块缩放到 ViT 的原生边长，外加一张全局低分辨率图，分别编码再拼接视觉 token。本篇只讲这种「固定编码器、可变切格」；按原生分辨率直接切 patch、不强制缩进固定格，见 Naive Dynamic Resolution。

问题 ​

ViT 的位置嵌入与预训练分布绑在固定 \(S\times S\) 输入上。把 4K 截图一次性双线性缩到 336，面积缩小两个数量级，12 号字变成不足一个像素的纹理，OCR 无从谈起。把 \(S\) 提到 1024 又会让 patch 数按平方涨，单张图就吞掉 LLM 窗口，且位置嵌入要大幅插值，偏离预训练。

AnyRes 的问题设定是：编码器权重与 \(S\) 不变，用「多张 \(S\times S\) 的作物」去覆盖高分辨率，作物数量与排列随原图形状变。动态的是格数与拼接长度，不是 ViT 内部的 patch 大小。必须同时保留一张全局图，否则模型只看见拼图碎片，丢了整页布局。

方法 ​

选格、切块、全局视图 ​

记 ViT 原生边长为 \(S\)。对原图做缩放与填充，使它能铺成 \(a\times b\) 个 \(S\times S\) 作物，\((a,b)\) 来自预定义集合（如 \(1\times2\)、\(2\times1\)、\(2\times2\)、\(3\times1\) 等），选取规则是贴近原图长宽比，且 \(ab\) 不超过设定的最大格数。每个作物独立过同一 ViT 与同一投影器。另将整图缩放到 \(S\times S\) 作为全局视图，同样编码。视觉前缀是

\[[z_{\mathrm{global}};\,z_{1,1};\ldots;z_{a,b}] \]

各段内部仍是该作物的 patch 序列。LLaVA-NeXT 用这套方案抬高有效输入分辨率，而不改 CLIP ViT 的核与位置表。

AnyRes 的每一格仍然经历一次 resize 到 \(S\)。它不是无损高清：格内若还有更小的字，照样糊。它买到的是「用更多 \(S\times S\) 窗口去扫原图」，不是「像素原样进网络」。

长宽比与格数预算 ​

宽表优先 \(1\times n\) 横条，长截图优先 \(n\times 1\) 竖条，近方形海报才用 \(n\times n\)。这比一律 \(2\times 2\) 少浪费：少切空白填充，也少产生只含垫边的 token。最大格数是质量–延迟旋钮：3×3 相对单视图可以接近一个数量级的像素覆盖，视觉 token 也接近乘上格数（外加全局）。服务必须按最坏 \(ab\) 预留上下文，而不能按平均图尺寸。

拼接顺序要在训练模板里固定，并最好有分隔标记，让 LLM 知道何时从全局切换到某一格。否则模型会把相邻两格的边缘当成一张图里的真实邻接——它们在原图上相邻，但在 token 序列里隔着各自的 patch 光栅。

与单视图、原生切块的差别 ​

单视图：一张 \(S\times S\)，最快，细字差。AnyRes：多张 \(S\times S\)，编码器不变，长度随格数线性涨。原生动态分辨率：patch 格子跟着 \(H\times W\) 走，不一定先切成 \(S\times S\) 作物，也不把每格再 squish 到训练边长。AnyRes 对「只能吃固定边长的 CLIP ViT」最友好；已经用二维 RoPE、可变长视觉序列的骨干，更自然走向 Qwen2-VL 那条路。

机制 ​

AnyRes 能读到更小的字，是因为有效采样密度提高：原图被分成 \(ab\) 块再各自占满 \(S\)，每块对应的原图像素更少，patch 覆盖的物理面积变小。全局支路提供低通布局：栏目、页眉、图相对表格的位置。LLM 用注意力在「概貌 token」与「某格里的细 token」之间跳，类似先看缩略图再读某一栏。

失败机制也来自拼接。模型必须学会格与格的空间关系；若指令问的是跨两格的表格，证据被切开，需要全局支路或足够的指令数据教它拼回来。填充黑边会产生无信息 token，浪费窗口，也会干扰注意力。选格算法若只按面积、不顾长宽比，宽图会被切成 squish 的方格，AnyRes 退化成多张同样畸变的图。

token 数约 \((1+ab)\times (S/P)^2\)。这是给 LLM 的账单，不是给 ViT 的。AnyRes 把分辨率问题部分转化成上下文问题，所以必须和 视觉 token 压缩 一起看，而不能只报「最高支持多少像素」。

边界与工程取舍 ​

最大格数一封顶，更大的图仍要先缩小，只是缩小得没那么狠。格与格边界上的字符被切断，OCR 会在接缝处丢笔画。多图输入时格数相乘，必须另设总视觉 token 上限。训练若只用单视图、推理突然 AnyRes，分布不一致，效果会小于论文；切格策略属于训练图的一部分。

不要把 AnyRes 写成「任意分辨率无损」。名字里的 Any 指配置可随形状变，不是像素级任意。也不要与 InternVL 的动态切 tile、Qwen2-VL 的 naive dynamic resolution 混名：后两者各自定义了格子如何随 \(H,W\) 变，编码器假设不同。

评测应分开报：自然图像 VQA、文档 OCR、宽表。AnyRes 的增益主要出现在后两类；只在短边自然图上平均，会得出「多格没用」的假结论，因为那些图单视图已经够清。

取舍：手里是固定边长 CLIP ViT，要做文档与截图，AnyRes 是改动最小的升分辨率；能改视觉位置编码与可变长序列，应评估原生切块，少一次 per-tile resize。无论哪条，都要给视觉前缀设硬预算，防止 3×3 多图打满窗口。

小结 ​

  • AnyRes 用全局低分辨率图加一组随长宽比变化的 \(S\times S\) 作物，覆盖高分辨率，而不改 ViT 原生边长。
  • 动态的是格数 \(a\times b\) 与拼接长度，每格内部仍 resize 到固定 \(S\)。
  • 有效采样密度提高，故细字更好；跨格结构依赖全局支路与固定拼接模板。
  • 视觉 token 近似按格数线性涨，分辨率账变成 LLM 上下文账。
  • 训练–推理的切格策略必须一致；接缝与填充是 OCR 失败点。
  • 与 Qwen2-VL 原生分辨率切块不是同一件事：后者不强制每格缩进固定画布。
