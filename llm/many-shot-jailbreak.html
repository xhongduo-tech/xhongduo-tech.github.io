大模型 · 2026-09-03

Many-shot jailbreak ​

当上下文里塞进足够多「用户提出违规请求、助手却详尽配合」的示范，长上下文模型会把这种对话模式当成应当模仿的任务，对齐在上下文尺度上被淹没。

—— Anil et al., Many-shot Jailbreaking, Anthropic, 2024

Anil 等人指出：对齐主要发生在「短对话、少示范」的测度上；一旦上下文窗口能装下上百轮伪造的配合示范，模型会像做上下文学习那样拟合示范的条件分布，包括示范里的有害配合。Many-shot jailbreak 因此不是一条新的修辞技巧，而是上下文长度变成攻击面：示范条数 \(k\) 增大时，越狱成功率沿类似对数的曲线上升，直到饱和。本篇写长上下文下的分布竞争、与普通 few-shot 的差别、以及防御与评测；不提供示范内容、轮次脚本或可粘贴的超长前缀。

问题 ​

指令微调与偏好优化改变的是「在常见长度的用户消息下」\(p_\theta(y \mid x)\)。上下文学习改变的是「在当前窗口里看到的示范下」同一条件。两者在短窗口里大致同向：系统提示与少量安全示范会加强拒答。窗口拉到数万 token 后，攻击者可以在单次请求里放入大量格式正确、角色标记齐全的伪历史：看起来像多轮已经发生的对话，每一轮都是违规请求加上配合回答。模型没有独立的「这些轮是假的」通道，只有下一词预测。当伪历史的 token 数远大于系统提示与真用户句，预测会被伪历史主导。

这与单轮越狱、GCG 后缀不同。后者改的是当前句的局部 logits；many-shot 改的是任务推断：模型推断「当前任务是继续这种已经建立的助手人格」。长上下文服务、前缀缓存 与多轮产品把超长窗口当成特性，于是 \(k\) 可以大到对齐训练从未见过的量级。

条数 \(k\) 本身是自变量 ​

Anil 等人把成功率写成 \(k\) 的函数，而不是写成某一条神奇提示的函数。\(k\) 小（个位数）时，对齐仍常占优；\(k\) 增大，曲线上升。这要求防御评测必须扫 \(k\)，而不能只测「带 3 个例子的提示」。也要求报告所用窗口是否真的装得下这些示范：截断、滑动、或服务端丢弃早期轮次，会在不知情中改变 \(k\)。

Many-shot 利用的是模型擅长的那件事：从上下文里学格式。安全团队若只红队单轮短提示，等于从未测量过产品已经打开的窗口。

方法 ​

从机制上刻画，而不是从内容上刻画。输入是系统提示（若有）、一段长度为 \(k\) 的伪对话、以及最后一轮真用户句。伪对话的角色标记必须与生产用 chat template 一致，否则测的是模板鲁棒性而非 many-shot。评测应使用独立的危害分类器判定最后一轮模型输出，而不是看它是否复述了示范里的某句套话。对照包括：\(k=0\) 的单轮基线、仅有无害 many-shot、以及把伪对话的助手轮全部改成拒答的「安全 many-shot」——后者检验模型是在学「多轮格式」还是在学「配合有害」。

缩放律式的观察是：在所测模型上，需要的 \(k\) 随模型能力与对齐强度变化，但形态都是「更多示范 → 更高成功率」，直到上下文或注意力稀释把增益吃掉。防御声明若只针对 \(k=5\)，不能外推到 \(k=100\)。对超长输入，还要测分块 prefill 与缓存命中会不会改变模型看到的有效前缀（例如只缓存系统提示、把伪历史每次重算）。

与其它越狱族的正交性 ​

Many-shot 可与后缀优化、预填充、多模态图文拆台组合，但评测应先单独报告再组合，否则无法归因。它不依赖白盒梯度，因此对闭源长窗口接口同样构成威胁模型。它也不依赖用户可见的「请进入某角色」一句咒语：角色已经写在伪历史的助手行为里。输出分类器仍然适用，但分类器自己若是短上下文模型，可能看不到 \(k\) 很大时的任务漂移，需要在同等长度或滑动窗口上评。

机制 ​

上下文学习可以被看成在残差流里写入一个任务向量：示范越多，该向量越稳。对齐则是在权重里写入「危害请求 → 拒答」的映射。两者在最后一层 logits 上相加。当示范诱导的任务向量指向「详尽配合」且范数随 \(k\) 增长，它会盖过权重里较浅的拒答方向。这与表示工程的读写是对偶：many-shot 是用上下文写入；拒绝向量是用激活加法写入。谁的范数大，谁主导。

注意力分配提供补充图像。系统提示通常很短，伪历史很长；若没有特殊的注意力偏置，后期层对近期示范的权重会高于对系统条款的权重。位置编码与窗口实现（滑动、分块、压缩）会进一步改写「模型还记不记得开头的安全条款」。因此 many-shot 既是数据问题，也是长上下文实现问题。

把系统提示重复插入每一轮可以短期抬高条款的注意力质量，但会改变产品格式，且攻击者仍可把伪历史写得更长。它是缓解，不是认证。

防御评测该看的曲线 ​

横轴用 \(k\) 或伪历史 token 数，纵轴用攻击成功率与过拒绝率两条。过拒绝的对照是：无害的长 many-shot（例如大量合法的客服示范）之后接无害请求，模型是否仍正常回答。若防御手段是「长上下文一律拒」或「超过 \(N\) 轮就丢掉历史」，要报对合法多轮产品的伤害。宪法分类器 与 Llama Guard 应在包含伪历史的完整输入上跑，而不是只分类最后一句用户话；只看最后一句会把 many-shot 判成普通短请求。检测「对话是否像在教模型做违规任务」本身是一种输入分类问题，可用一致性：用户句与近期助手轮是否在政策上冲突。

边界与工程取舍 ​

不是所有长窗口模型都同等脆弱：对齐更深入表示（Circuit Breaker）或在训练里见过「长上下文仍须拒答」的数据，曲线会右移。但右移不是消失；评测仍要扫到产品允许的最大 \(k\)。压缩上下文、摘要历史、只保留最近若干轮，会降低有效 \(k\)，也会伤多轮有用性（用户要模型记住早先约束时）。服务端应区分「用户可注入的历史」与「服务端签发的历史」：前者不可信，后者可签名；若接口允许客户端提交完整 messages 数组，则伪历史与真历史不可区分。

Many-shot 的示范若改成无害任务，就是普通 in-context learning，不能把「长上下文」本身当成有害信号。检测器必须看内容是否违规，而不是看轮数。本篇不讨论如何构造那些违规示范，只强调：凡是把客户端提供的多轮消息直接填进模板的 API，都要把 \(k\)-曲线纳入红队，而不是只扫单轮。

前缀缓存会让超长伪历史在预填充上变便宜，从而降低攻击者的时间成本。性能优化与攻击面有时是同一条路径，容量规划时应把异常长的 messages 计入限流，而不是只限单句长度。

小结 ​

  • Many-shot jailbreak 用大量格式正确的伪配合示范，在长上下文里淹没权重中的拒答。
  • 自变量是示范条数 \(k\) 与 token 长度，不是单条咒语；评测必须扫 \(k\)。
  • 它与梯度后缀、预填充正交，且不需要白盒。
  • 分类器要看完整窗口或等价的长上下文摘要，不能只看最后一句。
  • 缓解包括限 \(k\)、签发行、表示级中断与输出分类，均须报过拒绝。
  • 客户端提交的 messages 默认不可信；缓存与长窗口会降低攻击成本。
  • 出处：Anil et al., Many-shot Jailbreaking, Anthropic, 2024。
