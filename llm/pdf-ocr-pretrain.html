PDF / 扫描件进预训练 ​

书籍与论文的知识经常锁在 PDF 里；不经校对的 OCR 会把栏序、公式和印刷噪声写成「语言」，模型学到的是扫描件的错误，而不是书。

—— 学术 PDF 理解见 Blecher et al. Nougat；开放混合物中的论文源见 Soldaini Dolma

网页配方处理的是 HTML。人类知识的另一大块写在 PDF 里：教材、专著、技术报告、扫描的旧刊。Penedo 的 FineWeb 几乎不碰它们；Wenzek 的 CCNet 也是网页单语。要把 PDF 推进预训练，必须先决定文档是数字原生（有文本层）还是仅图像，再决定用 GROBID 一类结构解析还是 Nougat 一类神经 OCR，最后用与数学校对同构的门把乱码拦在训练分布之外。Soldaini 的 Dolma 用 peS2o 等处理论文，优先结构化源而不是对所有 PDF 盲目 OCR——这是正确的偏置：能拿到 TeX 或干净文本层时，不要走扫描件路径。

问题 ​

PDF 不是文本。它是绘图指令：字形位置、图片、矢量公式。数字原生 PDF 往往能抽出字符，但阅读顺序可能按印刷坐标而不是逻辑栏序，双栏论文会左右交错。扫描件只有光栅，必须 OCR。错误模式不同：文本层乱序是结构错误；OCR 是替换、切分与公式崩溃。二者都会进入 NTP，成为高置信的「拼写变体」。

版式对象比新闻网页更丰富。页眉页脚、脚注、水印、参考文献、分栏、跨页表格，通用 Trafilatura 帮不上忙。数学与化学公式常是图。若用普通 OCR 引擎按行读，上下标消失，积分号变成噪声。预训练若大量吞下这种序列，会在科学域表现出「能说术语、不能写合法公式」。许可与来源同样成问题：影书扫描件、受版权保护的教材，不能因为 OCR 成功就进开放混合物。

文本层优先于 OCR ​

数字原生 PDF 应先抽文本层并做栏序恢复（基于坐标聚类），只有文本层空洞、乱码或明显与页面图像不对齐时才 OCR。全程 OCR 更匀质，但更贵、更易引入系统性拼写错误。「PDF 抽出来的字符数」与 HTML 抽取一样，不能当质量。扫描件 OCR 总是更长或更短得离谱。质检应看：栏序抽检、词错误率代理、公式解析率，以及是否残留页眉「第 n 页」在段落中间反复出现。

扫描质量决定上限。低 dpi、倾斜、装订阴影、双页对开被当成一页，任何神经 OCR 都会崩。管线应先做图像质检（分辨率、倾斜、对比度），不达标的页丢掉或降权，而不是全部塞进 Nougat。预训练不缺「更多坏书」。

方法 ​

分流：有 TeX 源的论文走数学抽取篇的 TeX 路径；有结构化 XML 的出版商数据走 XML；其余 PDF 进入本文。数字原生：用 PDF 解析库提取带坐标的 span，按栏聚类恢复阅读顺序，表格用专用检测，页眉页脚用跨页重复度剥离。扫描件：版面分析（分栏、图、表）→ 区域 OCR 或整页 Nougat / Marker 一类学术模型 → 后处理。学术论文上，Nougat 的目标是恢复 Markup 与公式，而不是纯纯文本行；其输出仍要过解析与密度门。

校对门：语言识别（OCR 常把公式页判成错误语言）、异常字符率、字典 OOV 率、栏序启发式（是否在行末反复切断单词）、公式 KaTeX 通过率、页眉页脚重复 n-gram。通过后按文档级去重：同一书的多个扫描版、预印本与正式版。MinHash 应在 OCR 规范化（折叠空白、去连字符断行）之后做，否则同一页的两次扫描会被当成新文档。

神经 OCR 仍是有噪声的教师 ​

Nougat 一类模型在学术版式上优于通用 OCR，但会幻觉章节标题、漏图表、在未见宏包上失败。它的错误比 Tesseract 更「像 LaTeX」，因而更难被启发式发现。必须用独立信号交叉：与文本层对齐的页应比较二者差异；仅图像页应抽样人工看，或与可获得的 HTML 版对拍。Dolma 选择 Semantic Scholar 处理好的 peS2o，是把校对前移到上游，而不是在预训练前夜对千万 PDF 现场 OCR。

HTML 抽取器与 PDF OCR 不要争同一文档的两个坏版本。能找到 arXiv HTML 或 TeX，就不要用出版社 PDF 的 OCR。跨源去重必须在混合物层做，否则 Dolma 的论文桶与 FineWeb 里转载的摘要会叠三份。

机制 ​

OCR 噪声使经验分布在真实词 \(w\) 的邻域上扩散出 \(w'\)。模型同时学习 \(w\) 与 \(w'\)，解码时二者竞争。若 \(w'\) 在扫描语料中更频繁（系统性把 rn 认成 m），错误会赢。校对是把 \(p(w')\) 压回去。栏序错误则破坏长程依赖：左右栏交错相当于把两篇文章 zip 在一起，注意力学到的是虚假相邻。这比单字 OCR 错误更伤，因为局部 n-gram 仍像英语，KenLM 与 DCLM 头都可能放行。

公式 OCR 把数学支撑从可解析集合里拖出。与数学抽取篇相同：解析门应成为科学 PDF 的硬条件。对纯人文扫描件，公式门可关，但栏序与页眉门仍要开。语言识别应在校对之后：OCR 乱码会被 lid 标成「未知」丢掉，看起来像过滤，其实是扫描失败。

与网页、合成数据的配比 ​

PDF 桶信息密度高、文体旧、版权风险高。它不能按 token 与 FineWeb 对等比较。应用文档数或「有效干净页」计量，并设上限，以免旧刊文体支配生成。合成改写（把 OCR 输出交给 LM 润色）能降噪声，但会引入教师腔，且可能把错误「通顺化」——错误被改成语法正确的错事实。有源校对优于无源润色：能对齐到文本层或 TeX 的，不要用 LM 改写冒充干净书。

边界与工程取舍 ​

版权是硬边界。Gutenberg 一类公有领域、明确开放的论文源，才适合开放配方。来源不明的「Books」扫描件不应出现在声称可审计的混合物里。即使法律允许，扫描件的伦理与退出机制也要写进数据卡片。多语言 OCR 模型质量差距大，低资源扫描件应更依赖数字原生文本层，或干脆不进预训练。

成本：神经 OCR 每页的计算可能高于训练时读该页。应只对高价值、无文本层的页使用。存储 PDF 原件以便将来换 OCR 引擎重抽，比只存一份脏文本更符合「配方可修订」。FineWeb 不包含这一桶，并不意味着网页已覆盖书中知识；意味着网页配方拒绝为脏 OCR 买单。把 PDF 加进来是新的配方决策，不是默认下一步。

不要用维基 KenLM 给 OCR 输出打分来当质检。通顺的错字对 \(n\)-gram LM 仍然低困惑。OOV、公式解析、栏序抽检才是 PDF 专用门。CCNet 的质量定义在这里不适用。

小结 ​

  • PDF 进预训练必须分流：TeX / 文本层优先，扫描件才 OCR。
  • 栏序错误比单字错误更阴险，通用网页质量头看不见。
  • Nougat 等神经 OCR 会产出「像 LaTeX 的错」，仍要独立校对。
  • 规范化后再去重；跨源不要与 HTML / arXiv 叠脏副本。
  • 版权与图像质检是硬门；宁缺毋脏。
  • Dolma 式论文源把结构处理放在上游，优于现场盲 OCR。
  • 出处：Blecher et al.，Nougat；Soldaini et al.，Dolma / peS2o；网页上限对照 Penedo FineWeb 与 Trafilatura / Resiliparse；勿套用 Wenzek CCNet 困惑度当 OCR 质检。
