视觉 token 压缩 ​

高分辨率把字看清了，也把语言模型的窗口塞满了；压缩要删的是空间冗余，不是把文档理解所需的格子一并抹掉。

—— 对照 LLaVA 直连、Qwen-VL 查询与 InternVL 像素 shuffle

AnyRes 与更高清的 ViT 输入让视觉前缀从数百涨到数千 token。LLM 的注意力仍是序列长度二次，decode 的 KV 也按视觉前缀长度线性涨。视觉 token 压缩的目标是：在进语言模型之前（或刚进去时）把 \(N_{\mathrm{vis}}\) 降下来，同时尽量保住布局与细字。它和文本侧的 KV 压缩 同属预算问题，但删的是二维格子上的冗余，不是生成过程中的过去词。本篇对照查询瓶颈、规则下采样与池化，Qwen2-VL 的 \(2\times 2\) merge 训练细节留给下一篇。

问题 ​

一张 336 边长、\(P=14\) 的图约 576 个视觉 token；2×2 AnyRes 加上全局视图可以到两千以上；多页文档再乘页数。对话模型还要留系统提示、多轮文本。若不压缩，高分辨率与长对话互斥。若压缩太狠，OCR 与小物体检测先崩：被合并的格子里塞进了多个字符，语言模型再强也解不开混叠。

问题于是有约束：压缩比可调；尽量保持二维拓扑（读序、表结构）；最好不引入与 LLM 核不一致的不规则 gather。内容自适应压缩上限更高，也更难训、更难复现。规则 \(2\times 2\) 最稳，压缩比钉死。

方法 ​

查询瓶颈 ​

Q-Former 与 Qwen-VL 适配器 用 \(M\) 个可学习查询交叉注意全部 patch，输出长度恒为 \(M\)。压缩比 \(N_{\mathrm{vis}}/M\) 随分辨率自动变大：图越大，每个查询要覆盖的面积越大。这适合「视觉前缀必须钉死」的服务配额。信息选择是内容相关的，查询可以学会盯标题；也可以学会偷懒只看中心物体，把边缘小字丢掉。

规则空间合并 ​

像素 shuffle / \(2\times 2\) 合并把邻接四块拼成一个更宽向量，再投影。长度降为约 \(1/4\)，格子仍是图。没有离散选择，训练稳定，和卷积里的空间–通道重排同构。可以叠两次得到 16×，但混叠按幂加重。平均池化或步盘卷积是更糊的同类：同样降网格，通道不增，信息更易丢。LLaVA 式 MLP 直连则相当于压缩比为 1，长度问题原样交给 LLM。

\[N_{\mathrm{out}}\approx\frac{H}{P\cdot r}\cdot\frac{W}{P\cdot r} \]

\(r=2\) 即一次 \(2\times 2\)。\(r\) 与输入分辨率联合决定 OCR 粒度：先升分辨率再 \(r=2\)，往往优于低分辨率直连。

和文本 KV 压缩不是同一刀 ​

H2O、SnapKV 删的是时间上的过去 token；视觉压缩删的是空间上的邻域。视觉前缀通常一次性进 prefill，之后作为静态键被所有生成步读取，所以更像「prompt 侧的 SnapKV」，但栅格结构允许用确定性 merge，而不必依赖观察窗注意力。对视觉前缀再做文本式驱逐（按注意力分数扔 patch）是可行的实验，却容易把唯一的那个字扔掉；文档任务上优先规则合并或查询，而不是生成中途再丢格子。

压缩发生在连接器，还是发生在 LLM 的 KV 里，服务形态不同。前者缩短 prefill 序列，KV 从一开始就短；后者先算满视觉注意力再量化/驱逐。文档 VLM 应尽量在进 LLM 前压完，避免为已经混叠的 token 再付二次注意力。

机制 ​

规则合并假设局部四块统计上冗余：自然图像的纹理、大色块背景确实如此。文字图像相反：相邻 patch 往往是不同字符，合并等于人为制造「两字合一」的视觉词，语言模型只能靠上下文猜。因此同一 \(r=2\)，在照片字幕上几乎无感，在扫描件上掉字。查询瓶颈的机制是软选择：容量 \(M\) 的槽位，梯度会把它们推向训练集里最能降损失的区域——若数据以自然图为主，槽位不会自动去盯页脚页码。

评测压缩必须按任务拆开。只报综合 VQA 平均值，会被自然图稀释。应单独报：小字 OCR、表格格点、多物体计数。这三项对 \(N_{\mathrm{vis}}\) 最敏感。

长度降下来之后，LLM 的 softmax 分母更短，每个视觉键的权重更大，这有时反而改善「图被长问题淹没」。压缩不是单向损质量，它也在重新校准跨模态注意力。前提是留下的键仍对应任务所需的空间尺度。

边界与工程取舍 ​

没有对所有任务最优的压缩比。端侧聊天可以 \(M=64\) 或两次 shuffle；文档解析应提高输入分辨率，只做一次 \(2\times 2\)，甚至直连再配合窗口注意力。多图、视频会把 \(N_{\mathrm{vis}}\) 再乘时间或张数，必须有总预算，否则单张图的精心切格会在第二张图上被截断。

不要把视觉压缩写成「免费的 AnyRes」。升分辨率再压回原来的 token 数，中间仍有混叠，只是混叠发生在更细的原图像素上——这对中等字号有效，对更小的字仍要继续加格。也不要把 Qwen2-VL 的 merge 与 InternVL 的 shuffle 当成算法论文里的不同发明来夸大：工程上都是 \(2\times 2\) 空间重排加线性，差别在是否与原生可变分辨率、窗口注意力一起训。

服务日志里若视觉 token 数随用户上传的像素线性涨、没有上限，压缩策略等于没落地。应在预处理就设定最小/最大像素或最大 \(N_{\mathrm{vis}}\)，过大则先缩小，过小则上采样，避免极端长度打爆 KV。

取舍顺序：先定任务最小可读字号，反推 \(P\) 与输入边长；再选 \(r\) 或 \(M\) 把 \(N_{\mathrm{out}}\) 落入 LLM 窗口；最后才考虑对视觉 KV 做量化。倒过来先压长度，再抱怨 OCR 差，是预算写错了轴。

小结 ​

  • 视觉 token 压缩把高分辨率带来的 \(N_{\mathrm{vis}}\) 降到 LLM 窗口可承受的范围。
  • 查询瓶颈钉死长度、内容选择不可逆；规则 \(2\times 2\) 保拓扑、压缩比固定；直连不压缩。
  • 自然图纹理冗余高，文档文字冗余低，同一压缩比不可混用验收。
  • 压缩应尽量发生在进 LLM 之前，使 prefill 与 KV 一起变短。
  • 升分辨率再合并，对中等字号优于低分辨率直连，但不能替代真正的细格子。
  • 必须设 \(N_{\mathrm{vis}}\) 上限；与文本 KV 驱逐是不同轴。
