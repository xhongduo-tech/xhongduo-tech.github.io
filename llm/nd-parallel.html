3D / 5D 并行组合 ​

三维并行把 batch、矩阵宽和层深切开；再要放下超长上下文或稀疏专家，就得在同一张设备网上多两维。

—— Shoeybi et al., Megatron-LM, 2019；Narayanan et al., 2021

单卡放不下现代预训练模型，并行必须同时切数据、切参数、切层。业界把数据并行（DP）、张量并行（TP）与流水线并行（PP）合称 3D 并行：DP 切 batch，TP 切单层里的矩阵宽，PP 切层深。这套组合在 Megatron-LM 一类 GPU 框架里被写成本地拓扑——张量并行优先吃节点内 NVLink，流水线沿节点排列，数据并行做跨副本的梯度同步。当序列极长或 FFN 换成 MoE，三维不够用：上下文并行（CP，也称序列并行的一种强形式）沿序列切注意力，专家并行（EP）沿专家切 FFN。两者补进去之后，常被叫做 5D 并行。本篇讲这几维如何叠、通信怎样正交，不把每一维的算法细节再写一遍。

问题 ​

只开数据并行，每张卡都要存完整参数与优化器状态，模型稍大就爆显存。只开张量并行，能把单层矩阵切开，但节点内 GPU 数有限，跨节点做 TP 会把 All-Reduce 打到 InfiniBand 上，算力利用率迅速下降。只开流水线，能把层分到不同机，却引入流水线气泡，microbatch 太少时设备空转。三维并行的动机是让每一维都只承担自己最擅长的那一段：TP 吃高带宽短距离，PP 吃层间点对点，DP 吃可以重叠的梯度同步。

MoE 与长上下文把同一层内部又切开。专家数涨到几十上百，单层 FFN 的参数已经不是 TP 能单独消化的；序列涨到几十万 token，注意力激活按序列平方或线性增长，也不是 DP 的 batch 维能吸收的。于是在三维之上加 EP 与 CP，不是概念游戏，而是显存与通信域的再划分。

维与维之间必须正交 ​

若两维切的是同一块内存、走同一条集体通信，组合会互相踩。典型错误是把专家切分写进张量并行组，或把序列切分写进数据并行组：前者让 All-to-All 与 All-Reduce 抢同一组设备，后者让不同序列分片错误地同步梯度。正交的意思是：每一维有自己的进程组，集体通信只在组内发生。进程组一旦配错，症状往往不是立刻 NaN，而是「损失还能降、吞吐却莫名差一截」或「MoE 专家梯度被加到一起」。调试 5D 配置，先画设备网格，再标每一维的通信原语，比先调 batch 更有效。

方法 ​

3D 的标准排法可以写成网格 \(D\times T\times P\)。一张卡的逻辑坐标是数据副本编号、张量分片编号、流水线阶段编号。前向时，同一流水线阶段内先做 TP 切分的注意力与 FFN，阶段之间用点对点把激活送到下一阶段；反向再反向走一遍，最后在 DP 组上对梯度 All-Reduce（或 ZeRO 式的 Reduce-Scatter）。Microbatch 把流水线填满，气泡比例大约是阶段数与 microbatch 数之比。

5D 在同一网格上再乘专家维与上下文维。EP 组通常嵌在同一流水线阶段、同一段序列分片之内，对 MoE 层做 All-to-All。CP 组沿序列切开 \(Q,K,V\)，用环或 All-Gather 补齐注意力需要的键值，再把输出按序列分片写回。常见约束是：TP 组必须落在 NVLink 域，CP 次之（注意力通信量大），EP 视专家是否跨节点而定，PP 与 DP 可以跨机。

通信原语如何各管一段 ​

  • DP：梯度 All-Reduce 或 ZeRO 的 Reduce-Scatter / All-Gather，可与计算重叠。
  • TP：层内 All-Reduce 或 All-Gather / Reduce-Scatter，对延迟最敏感。
  • PP：阶段间 Send/Recv，带宽需求低于 TP，但对调度与气泡敏感。
  • EP：MoE 层的 All-to-All，负载随路由波动。
  • CP：沿序列的 P2P 环或集体通信，量与序列长度、头数成正比。

同一层里通常不会五维同时打满。稠密短序列训练往往是 3D；开 MoE 才点亮 EP；上下文拉到必须切激活时才点亮 CP。工程上的「5D」是能力集合，不是每一步都五维全开。

机制 ​

显存账本按维拆开看会清楚很多。TP 把参数与激活的隐藏维除以 \(T\)，但会保留通信缓冲区；PP 把参数除以 \(P\)，激活只在本阶段驻留，却要为气泡准备多份 microbatch 的中间态；DP 不减参数（ZeRO 除外），只把 batch 摊开；EP 把专家参数除以 \(E\)，激活在 All-to-All 前后各有一份重排缓冲；CP 把序列维激活除以上下文并行度，注意力通信再把部分键值聚回来。总显存不是五维简单相除，因为每一维都引入自己的临时缓冲。

吞吐则由最慢的那条通信或计算墙决定。TP 组若跨节点，层内 All-Reduce 会成为墙；EP 组若跨太多节点，All-to-All 会成为墙；CP 度过高时，环上的键值传递会成为墙；PP 阶段过多而 microbatch 不足时，气泡会成为墙。3D / 5D 调参的实质是把墙从「放不下」推到「算得动」，再把各墙尽量对齐，避免一张卡等另一维的集体通信。ZeRO 与 DP 不是互斥的第五维。ZeRO-1/2/3 是数据并行内部对优化器状态、梯度、参数的再切分，通信仍发生在 DP 组。写并行配置时，ZeRO 阶段属于 DP 的实现细节，不要再占一个独立字母把网格说成六维，除非你真的把参数分片组从 DP 里拆了出来。

拓扑映射比乘积更重要 ​

同样的 \(D,T,P,E,C\) 乘积，映射到机柜的方式可以差出一倍吞吐。优先保证 TP（以及高带宽 CP）落在 NVLink 全连接的节点内；PP 沿机柜的节点维排列，使相邻阶段尽量走同一交换机；DP 与跨节点 EP 走 InfiniBand。DeepSeek 一类 MoE 预训练还会限制每个 token 访问的节点数，等于在 5D 之上再加一条路由拓扑约束。这些约束写进并行计划之后，模型代码里的 parallel_state 才能和集群的真实链路一致。

边界与工程取舍 ​

3D 不是唯一能训大模型的办法。纯 ZeRO-3 加少量 TP、FSDP 式全分片，也能在特定集群上跑起来，只是通信模式从「层内短距离 All-Reduce」变成「参数反复 Gather」。5D 也不是越多越好：每加一维就多一套进程组、一套检查点切分、一套故障恢复语义。序列不长就开 CP，专家不多就开 EP，只会增加调度复杂度。

流水线的调度（GPipe 式、1F1B、交错流水线）会改变激活驻留与气泡，但不改变三维的切分语义。序列并行若只切 LayerNorm 与 Dropout 的序列维、用来省 TP 的激活，和这里的 CP（注意力也沿序列切开）不是同一强度，配置名称在不同框架里容易混。写文档时应写清：切的是激活的哪一维、集体通信是哪一种。检查点与并行网格绑定。恢复到不同的 \(T\) 或 \(E\) 需要对权重做重切分；恢复到不同的 \(P\) 要对层重新划段。并行度当作超参随便改，比改学习率更容易把一次续训变成一次静默错位。

最后，5D 解决的是「怎么放下、怎么跑满」，不解决「该训多大、该看多少 token」。后者是扩展律的问题。并行网格选错，扩展律实验会得到被通信墙污染的假曲线：看起来是模型变差，其实是 step 里有一半时间在等 All-to-All。

小结 ​

  • 3D 并行是 DP 切 batch、TP 切矩阵宽、PP 切层深，对应 Megatron 一类预训练的基本网格。
  • 5D 在三维之上加 EP 与 CP：专家维用 All-to-All，序列维用上下文并行补齐注意力。
  • 各维必须使用正交进程组；通信原语不同，不能把专家或序列塞进错误的组。
  • 拓扑映射优先保证 TP / 高带宽 CP 在 NVLink 域，PP 与 DP 可以跨节点。
  • 显存与吞吐都不是五维简单相除，每一维都有自己的缓冲区与墙。
  • 不是每项预训练都要五维全开；维数是能力，开启是代价。
  • 出处：Shoeybi et al., Megatron-LM, 2019；Narayanan et al., Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM, 2021。EP / CP 的组合见 GShard、Switch 以及后续长上下文与 MoE 预训练系统。
