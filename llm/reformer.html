Reformer ​

用哈希把注意力限制在同类桶里，用可逆残差把激活从显存里拿掉：效率来自近似邻居与重算，而不是改写 softmax 核。

—— Kitaev, Kaiser & Levskaya, Reformer, ICLR 2020

2019–2020 年，长序列 Transformer 同时撞上两堵墙：注意力的 \(n^2\) 项，以及反向传播要存下每一层激活。Kitaev、Kaiser 与 Levskaya 的 Reformer 把这两件事打包进同一篇系统论文：局部敏感哈希（LSH）注意力把每个查询的可见集缩到哈希邻居；可逆残差让前向不必保留子层输入；前馈再沿长度分块。稀疏图的一般设计见 BigBird / Longformer 稀疏模式；核化线性路线见 线性注意力。本篇写 Reformer 原文选的近似与显存技巧，以及哈希与因果掩码之间的摩擦。

问题 ​

若目标是把 Transformer 用到几万 token 的字符流或长文档，稠密注意力的显存先于质量爆掉。稀疏若按固定窗，远距离邻居永远进不了同一层的可见集；若按内容选邻居，又要回答「如何在次二次时间内找到近邻」。同时，即使注意力稀疏了，标准残差网络仍按层存储激活，深度与宽度会把显存第二次打满。Reformer 的命题是：用同一套实现同时打注意力复杂度与激活存储，使「长而深」在当时的单机或小集群上可行。

LSH 的经典用途是近似近邻检索。搬进注意力，意味着承认：高点积的查询–键对更可能落在同一哈希桶，因而只在桶内做 softmax 是对满注意力的内容相关近似。这个假设对、桶大小可控，复杂度接近 \(O(n\log n)\) 量级（再乘桶内二次）；假设不成立，就变成随机掉边。

同时打显存与注意力平方 ​

只换 LSH 而保留标准反向，激活存储仍按 \(O(L\cdot n\cdot d)\) 涨。只上可逆残差而保留稠密注意力，\(n^2\) 的分数矩阵或等价算力仍在。原文把二者绑在一起，是因为它的目标场景是超长序列上的完整 Transformer，而不是给短句翻译省几个百分点。评测因此偏向 enwik8、imagenet64 一类长序列，而不是 GLUE 短句——短句上 LSH 的近似误差更可见，收益更小。

可逆网络省的是 激活显存，不是参数或优化器状态。Adam 的一、二阶矩仍按参数量存。把 Reformer 说成「显存随深度无关」时，应写明指激活，否则与优化器峰值对不上。

方法 ​

LSH 注意力先把查询与键投到同一空间（原文常让 \(Q=K\) 的投影共享，否则不同投影下哈希不可比），再对每个向量抽若干随机超平面，得到哈希码，按码排序后分桶。每个位置主要与同桶（及因排序形成的块）内位置计算注意力；多轮哈希（n_rounds）用来降低漏掉真近邻的概率。桶内仍是 softmax 加权，不是核特征。为了负载，过长的桶会再切成定长块，避免最坏 \(O(n^2)\) 回潮。

可逆残差把一层拆成对偶分支，前向

\[y_1 = x_1 + F(x_2),\qquad y_2 = x_2 + G(y_1), \]

反向由 \(y\) 代数恢复 \(x\)，因而训练时不必存 \(x\)。注意力与 FFN 分别充当 \(F,G\) 一类子层。FFN 沿序列分块计算，使中间宽 \(4d\) 的激活不必整段同时驻留。这三项是配套工程：哈希减边，可逆减深度方向的激活，分块减宽度方向的峰值。

LSH 注意力 ​

哈希是随机的，同一输入每次前向的图可以不同，除非固定随机投影。训练因而带噪声，相当于对注意力边的数据增强；推理若重抽哈希，生成会不稳，应固定或与训练一致。多轮哈希提高召回，费用线性涨。共享 \(Q/K\) 投影降低表达力（查询与键不再是两套几何），却是 LSH 能工作的代价之一。这与后来 GQA 合并 KV 头不是同一动机：这里合并的是 Q 与 K 的几何，为了可比哈希。

可逆残差与分块 FFN ​

可逆的数值问题是：反向重算 \(F\) 时，浮点误差会累积，极深或半精度时需要核对。它还强制子层写成对偶加法形式，和 Pre-LN 解码器的标准实现不完全同构，移植现代块时不能「只换注意力」。分块 FFN 与序列并行兼容，但块太小则矩阵乘效率差。原文的效率数字应在长 \(n\) 下读：短 \(n\) 上排序、哈希、可逆的开销会吃掉稀疏收益。

机制 ​

LSH 近似的是「谁与谁算注意力」，不是近似 softmax 核的值。桶内仍可以有尖锐的权重。漏掉的真近邻永远是零权重，这一误差不可被更多层完全补回，只能靠多轮哈希或局部窗旁路。许多实现因此把邻域窗与 LSH 并在一起：近邻有确定边，远处靠哈希碰运气。这已经接近 Longformer 的「窗 + 额外边」，只是额外边由哈希而不是膨胀或全局点给出。

可逆机制与注意力近似正交。它可以接到稠密注意力上（当时的 RevNet 传统），Reformer 把它用在 Transformer 上是为了让长 \(n\) 的深度仍装得进卡。贡献是系统集成，不是发明可逆网络。

因果 LSH 必须禁止看未来桶成员。排序打乱位置顺序后，掩码不能再假设下标相邻即时间相邻。实现错误会泄漏未来，评测却仍可能看起来困惑度很好。因果任务上应单独测泄漏，不要只报 enwik8。

哈希与因果的摩擦 ​

语言建模是因果的，LSH 邻居却按内容聚，未来 token 可能与当前同桶。必须在桶内再施因果掩码，并且在构造桶时避免用未来信息做哈希——查询的哈希若依赖于尚未合法看见的键，定义就圆不回来。编码器双向任务没有这个问题，这也是为何 LSH 注意力在双向长序列上更好讲。生成任务上，逐步解码时哈希桶随新 token 变化，过去的「同桶」关系会改，和固定稀疏图不同。

边界与工程取舍 ​

Reformer 没有成为现代 LLM 的默认层。原因主要在硬件与生态：按桶 gather 打散 GEMM；排序与哈希在 GPU 上不如稠密 FlashAttention 吃得饱；共享 QK 与可逆块和后来的标准 Pre-LN + RoPE + 内核栈不合。作为论文，它证明了「内容稀疏 + 激活重算」可以在 2020 年把 Transformer 推到很长的字符序列；它没有证明这是服务稠密解码器的正确内核。

近似质量依赖数据几何。若点积近邻与哈希近邻不一致（投影后各向异性严重），LSH 掉边。超参（桶大小、轮数、是否加局部窗）必须跟 \(n\) 一起扫。不要把复杂度写成严格线性——桶内二次与负载不均会让常数很难看。与 Routing Transformer 的差别是：那里用在线 k-means 学簇，这里用随机哈希；一个可训，一个固定随机投影。

引用 Reformer 来论证「稀疏注意力已解决长上下文」会过满。它解决的是 2020 年实验设定下的显存与长度；针测、指令跟随、KV 缓存服务均不在原文范围。

小结 ​

  • Reformer 原文把 LSH 注意力、可逆残差与分块 FFN 集成到同一长序列 Transformer 里。
  • LSH 按内容近似邻居，桶内仍是 softmax；漏边靠多轮哈希或局部窗补。
  • 共享 Q/K 是为了哈希可比，不是为了推理期省 KV。
  • 可逆残差省激活显存，不省优化器状态，且与标准 Pre-LN 块不同构。
  • 因果掩码与动态分桶是主要工程风险；双向长序列更契合其假设。
  • 未成为现代稠密 LLM 默认内核，价值在系统证明而非当前服务栈。
  • 出处：Kitaev, Kaiser & Levskaya, Reformer: The Efficient Transformer, ICLR 2020。
