下一课：Triton Inference Server

NVIDIA Dynamo ​

把前填与解码拆到可独立扩缩的工人池，再用规划器、缓存感知路由、分层 KV 与统一传输库把跨节点的状态搬完；引擎仍可以是 TensorRT-LLM、vLLM 或 SGLang。

—— NVIDIA, Introducing NVIDIA Dynamo, GTC 2025 技术博客

2018 年的 Triton Inference Server 把多框架推理收进同一进程：模型仓库、动态批、HTTP/gRPC。生成式模型把一次请求拆到多节点、把前填与解码拆到不同 GPU 之后，单进程里的 backend 调度不够用了——要有人决定这块 GPU 这会儿做前填还是解码，要有人知道 KV 现在住在哪台卡的哪一级存储，还要有一条能在 HBM、主机内存、NVLink 与 InfiniBand 之间走同一套语义的搬运。NVIDIA 在 GTC 2025 发布的 Dynamo（仓库 ai-dynamo/dynamo）按这个缺口重画控制面。本篇写 Planner、Smart Router、Distributed KV Cache Manager 与 NIXL 四件套；单引擎内部的分页与连续批仍见 vLLM 架构 与 SGLang。

问题 ​

前填偏计算、解码偏带宽，绑在同一组 GPU 上会互相抢时间和并行策略，这是 DistServe 与 Splitwise 已经写清的阶段干扰。Dynamo 面对的下一层是规模：推理模型把输出长度拉到成千上万 token，智能体工作流让同一前缀在多步之间反复出现，KV 的体积与存活时间都超出单节点 HBM。Triton 式的「一个模型仓库 + 每模型一个调度器」假设请求在同一后端实例内完整执行；拆开之后，一次用户请求的生命周期要穿过前填工人、传输、解码工人，还可能把冷 KV 卸到 CPU 或对象存储。

若路由仍做轮询，前缀缓存作废，二次前填把拆分省下的干扰又交回去。若传输仍走通用 NCCL 集合通信，DRAM↔VRAM、动态增减工人、存储层次之间的拷贝没有统一原语。若工人池比例写死，摘要突发会打满前填、解码空转。问题因此是编排，不是再写一个注意力核。

30 倍请求数钉在哪张图上 ​

NVIDIA 博客给出两条对照。DeepSeek-R1 在 GB200 NVL72 上、TensorRT-LLM FP4、输入/输出约 32K/8K：不拆分时是 inflight batching、TEP16PP4DP4；Dynamo 拆分后前填 EP4DP16、解码 EP64DP3，报告请求数最高约 30 倍。Llama 70B 在 Hopper 上、vLLM FP8、约 3K/50：不拆分 TP8DP2，拆分后前填 TP2DP4、解码 TP8，报告吞吐一倍以上。这些数字是特定 ISL/OSL、精度与并行度的对照，并且标注了 projected 字样。不要写成「任意模型装上 Dynamo 就 30 倍」。

Dynamo 不是替换 vLLM 或 TensorRT-LLM 的运行时。它是多节点上的控制面与数据面库，后端仍然做前向。把博客里的加速理解成「换了一个更快的 GEMM」，会和引擎自己的核优化混在一张表里。

方法 ​

架构按四条职责切开。Planner 持续看前填/解码队列、KV 传输耗时、TTFT 与 ITL 预算，决定下一条请求走分离还是临时聚合，以及要不要把工人从一池挪到另一池。摘要突发时前填打满、解码闲着，让解码工人临时做前填（或整条请求走聚合）可能比死守分离更划算——这与 Splitwise 的 mixed 池同一类阀门，只是 Dynamo 把它写成在线规划，而不是静态三类机器。

Smart Router 把到达请求哈希进一棵 radix 树，跟踪 KV 块在集群里的位置，用 overlap score（与已有块的重叠）加工人负载挑前填/解码工人。相对轮询，它少做前填重算；相对纯会话粘滞，它仍能把过热的工人上的新请求洒开。评测片段里，两台 HGX-H100、8 路蒸馏 Llama-70B、约 10 万条真实 R1 请求、平均 4K/800，用来说明缓存感知相对盲目路由的收益。

Distributed KV Cache Manager 把不热的块从 GPU 卸到主机内存、本地盘或网络对象存储，目标是把可复用 KV 做到 PB 量级而不把 HBM 当唯一仓库。淘汰要在「缓存过多导致查找变慢」和「缓存过少导致重算」之间折中，并支持节点级与集群级的层次。

NIXL（NVIDIA Inference Transfer Library）给出点对点、非阻塞、可非连续的搬运 API，后端可走 UCX、GPUDirect Storage 等，按源/目的内存类型选 NVLink、InfiniBand、RoCE 或存储路径。分离式服务里，前填工人算出 KV 后返回 disaggregated_params，解码工人用这份元数据经 NIXL 做 GPU 到 GPU 的拉取，前向可以与传输重叠。

与 Triton、Mooncake、vLLM 的层位 ​

Triton 管单机/单进程里的模型仓库、动态批与解耦流式；Dynamo 管跨节点的工人角色与 KV 数据面。Mooncake 的 Store 与 Transfer Engine 是另一条 KV 中心栈，来自 FAST 2025 论文；Dynamo 用 NIXL 做类似的异构内存抽象。引擎侧，vLLM V1 的 统一调度 仍在工人内部决定「这一步算几个 token」；Dynamo 决定「这一步由哪类工人算」。三层叠在一起时，出了 TTFT 问题要先问路由命中、再问传输、最后问核。

官方文档把分离流程写成 PrefillRouter 编排：按缓存重叠与负载选前填工人 → 工人返回传输元数据 → 注入解码请求 → 解码工人经 NIXL 拉 KV。工人可在运行时增减，形成可重配的 \(x\) 前填 \(+ y\) 解码（xPyD）。这是 分离 Prefill 资源池 在 NVIDIA 栈上的落点。

机制 ​

拆分收益来自屋顶线对齐：前填工人可以用较小的张量并行减少通信、把 SM 留给大 GEMM；解码工人可以用更大的并行度换 HBM 带宽与 KV 容量。Planner 存在是因为这条对齐不是恒成立——当传输时间或前填排队超过聚合执行，拆分是亏的。路由收益来自 KV 对前缀的确定性：相同 token 前缀对应相同 KV，重叠分数高的工人少算二次项。卸载收益来自时间局部性：系统提示、多轮历史、智能体工具说明的 KV 值得离开 HBM 但留在近 GPU 的下一层，而不是每次从文本重算。

NIXL 的机制是把「内存段」当成统一对象。HBM、DRAM、本地 SSD、远端对象在 API 上都是可注册的区间；库按两端类型选后端，调用方不写四套拷贝代码。这对分离式服务是硬需求：P→D 要 GPU Direct，D→CPU 要主机通道，命中存储层时可能走 GDS。没有这层，Planner 的「把块卸到 SSD」会在实现上变成无法调度的特例。

Overlap score 不是用户 ID。两条无关会话可以共享系统提示块，路由应把它们导向持有该前缀的工人；同一用户的两条独立任务若前缀不同，不应被会话亲和强行绑在一起。键是块，不是连接。

控制面与数据面的异步 ​

传输非阻塞：解码工人在拉 KV 的同时可以继续为其他请求做前向。这要求块表与「传输未完成」状态同时存在——注意力核不能读尚未落地的页。PrefillRouter 返回的元数据必须足以建立 RDMA 端点；工人动态加入时，NIXL 要重新握手。这与 Triton 里「一次 backend execute 对应一组输入输出」的同步模型不同，也是 Dynamo 不能只当 Triton 的配置开关打开的原因。

边界与工程取舍 ​

博客数字不能外推到短提示、短输出的聊天。32K 前填、8K 生成是推理模型的极端档，拆分与专家并行的相对收益最大；ISL/OSL 只有几百时，传输与编排税可能吃掉拆分红利。Planner 若观测延迟，会在负载震荡时来回切分离/聚合，表现为 TTFT 方差变大。Smart Router 的 radix 要与引擎内前缀缓存一致：路由器以为命中、工人已经淘汰，仍会全额前填。

NIXL 与 Mooncake Transfer Engine 都解决近 GPU 搬运，生态与后端集合不同；生产上选一条当数据面，不要在同一条 KV 路径上叠两套注册。KV Manager 卸到对象存储后，不等式与 Mooncake 论文写的一样：加载带宽必须高过重算，否则卸载是在买更慢的 TTFT。多租户下，radix 与卸载对象的键必须带模型版本、精度与租户，否则共享前缀会串。

企业发行计划挂在 NVIDIA AI Enterprise / NIM 上；开源仓库与企业分支的 SLA 不是同一份合同。已有 Triton 部署继续走生产支持，Dynamo 是新的分布式生成式路径，而不是对 Triton 配置文件的原地升级。

出处钉 NVIDIA 开发者博客 NVIDIA Dynamo, A Low-Latency Distributed Inference Framework…（GTC 2025）、文档中的 Disaggregated Serving 设计说明，以及 https://github.com/ai-dynamo/dynamo、https://github.com/ai-dynamo/nixl。30× / 2× 以博客图注中的模型、精度与并行度为准。

小结 ​

  • Dynamo 是面向多节点生成式推理的控制面：Planner、缓存感知路由、分层 KV、NIXL，后端仍是 TRT-LLM / vLLM / SGLang。
  • 分离式 xPyD 可运行时改比例；Planner 在分离与聚合之间做负载阀。
  • Smart Router 用 radix 重叠分数减少前填重算；KV Manager 把冷块卸到更便宜的层次。
  • NIXL 用统一内存段 API 做非阻塞 GPU/主机/存储搬运。
  • 公开加速数字钉在 DeepSeek-R1×GB200 与 Llama-70B×Hopper 的特定 ISL/OSL 上。
  • 出处：NVIDIA Dynamo GTC 2025 博客与 ai-dynamo/dynamo；前身职责见 Triton，阶段动机见 DistServe / Splitwise。
