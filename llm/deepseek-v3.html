DeepSeek-V3 ​

671B 总参、每 token 激活 37B：沿用 MLA 与 DeepSeekMoE，改用无辅助损失的负载均衡，并加上多 token 预测目标。

—— DeepSeek-AI, DeepSeek-V3 Technical Report, 2024

DeepSeek-V3 把 V2 验证过的 MLA 与 DeepSeekMoE 放大：总参数 671B，每 token 激活约 37B。报告强调训练成本可控——全文训练约 2.788M H800 GPU 小时——以及过程稳定：没有不可恢复的 loss 尖峰、没有回滚。预训练 14.8T token，再接 SFT 与强化学习。相对 V2，算法上多两件关键事：无辅助损失的负载均衡，以及 多 token 预测（MTP）。本篇写规模、这两项训练改动与效率叙事，部署约束见 开源栈。

问题 ​

V2 的 236B / 21B 已经证明细粒度 MoE 可训，但要把总容量再抬一个数量级，辅助损失会更明显地跟主损失抢梯度：均衡项太大，专家变「平均人」；太小，路由塌缩。同时，标准下一词预测只在每个位置监督一个 token，样本效率在 14.8T 这种体量上仍嫌浪费。V3 要在不把激活打到 70B+ 稠密档的前提下，把专家数与 \(k\) 再抬，并让训练硬件（H800 集群、FP8）真正吃满，而不是卡在流水线气泡和 All-to-All。

术语翻译：「辅助损失」是在主任务之外额外加的「别偏科」罚项；「无辅助损失的负载均衡」不是不管均衡，而是把「别偏科」从罚项改成调度规则——哪个专家太忙就临时调低它的中签率（偏置），主损失里不再掺别的项，专家也不用被迫变成「平均人」。

激活 37B 不是「小模型」 ​

37B 激活决定单步 GEMM 量级，671B 决定存储、EP 宽度和冷启动。评测若只报「对标稠密 70B / 封闭旗舰」，必须同时报：你的服务是按 37B 计费还是按 671B 显存计费。V3 的产品矛盾正在这里——推理 FLOPs 像中大模型，权重像超大模型。

Hugging Face 上的权重体积大于 671B 主模型，因为还包含 MTP 模块（报告与仓库说明约 14B 量级）。部署若不用 MTP 解码，仍可能要先加载或裁掉这部分。不要把磁盘上的 685B 与「每 token 激活 37B」混成一个数。

方法 ​

MoE 放大为约 1 个共享专家 + 256 个路由专家，每 token 激活 8 个路由专家。注意力仍是 MLA。负载均衡改为专家偏置：路由 logits 加 \(b_i\)，\(b_i\) 按近期负载升降，不进入对路由权重 \(W_r\) 的交叉熵梯度。主损失不再被 aux 项直接扭曲；均衡走控制器。设备限制路由一类通信约束仍然需要，否则 256 专家的 All-to-All 不可接受。

MTP 在训练时对同一骨干预测多个未来 token，额外模块在序列方向上提供更深的监督。推理可以丢掉 MTP 头，只做标准自回归；也可以利用 MTP 做推测解码一类加速，这是部署选项，不是默认必须。报告把 MTP 写成增强目标，而不是改 Transformer 块内部公式。

训练效率还依赖工程：FP8 混合精度、流水线通信与计算重叠（报告中的 DualPipe 等）。这些不改变 MLA/MoE 的数学对象，但解释了为何 14.8T 能在约 2.8M GPU 小时内跑完。稳定叙事——无回滚——说明配方在他们的集群上没有反复炸，不保证换一套并行实现同样平滑。

2.788M GPU 小时什么概念：约等于 318 张 H800 不间断跑一整年（\(2.788\times10^6 \div 24 \div 365 \approx 318\) 卡·年）。这就是「从零训一个旗舰」的真实量级——复现的成本大头是租卡钱，不是抄超参。

机制 ​

无辅助损失均衡的机制是负反馈在统计量上，而不是在每个 token 的损失上。热专家的 \(b_i\) 被调低，后续 batch 更少选它；冷专家相反。\(W_r\) 只为主任务打分，专家专业化不容易被「必须均匀」抹平。部署若丢掉 \(b_i\)，负载会回到训练末期的瞬时快照，可能过载个别专家——服务栈要把偏置当成模型状态的一部分，或在线重估。

MTP 让表示在位置 \(t\) 不仅对 \(t+1\) 可分，还对 \(t+2,\ldots\) 可分，梯度更稠。

直觉类比：标准下一词预测像做完一页只对一次答案；MTP 像要求写这页时同时预判后面两三行。同一段文本能多对几次答案，样本效率更高——这就是 V3 在 14.8T token 上「多榨一点」的办法。

这与投机解码的草稿头思想相关，但 V3 把它做成预训练目标。激活参数 37B 仍远小于 671B 稠密前向；相对 V2 的 21B，FFN 激活加宽，对应更大的 \(k\) 与专家宽度设定。MLA 继续压 KV，使 128K 级上下文在 37B 激活下仍可能服务，否则超长 decode 会先被缓存打死。

和 V2、和 Mixtral 的规模对照 ​

V2：160 路由、\(k=6\)、2 共享、aux loss、8.1T。V3：256 路由、\(k=8\)、1 共享、无 aux、14.8T、MTP。Mixtral：8 专家、\(k=2\)、无共享、无 MLA。三条线都是稀疏 FFN，只有 V3 同时把「旗舰总参」和「可公开复现的训练小时数」写到同一摘要里。不要用 Mixtral 的 13B 激活去外推 V3 的延迟：专家数差两个数量级，通信形态完全不同。

报告中的封闭模型对照（当时的 GPT-4o、Claude 等）是评测声明，会过时。写架构应钉住 671B/37B、MLA、DeepSeekMoE、无 aux 均衡、MTP、14.8T、2.788M H800 小时这些报告内数字，而不是把某次榜一锁死成「已经超过谁」。

边界 ​

缺一块核就不再是报告中的 V3 ​

V3 的训练设定绑定大 EP 与 FP8 栈；小集群用 BF16 复现 671B 不现实。开源推理框架必须同时实现 MLA 吸收、共享专家、细粒度 grouped GEMM 和偏置路由，缺一项延迟或质量都不可比。MTP 权重若留在卡上会占显存，不用则应卸载。无 aux 不代表不需要均衡：只是均衡不走 \(\mathcal{L}_{\mathrm{aux}}\)。把 V3 量化到极端比特再宣称「单卡旗舰」时，应同时报准确率与上下文；显存账做假，架构主张就做假。对研究而言，V3 最可引用的不是某次聊天印象，而是可核对的三元组：671B/37B、无辅助损失偏置、MTP 训练目标。

后训练的 SFT/RL 细节以报告为准，不要把 R1 的长链推理训练提前安到 V3 基座上。V3 后来可用 R1 轨迹做蒸馏以加强推理，那是报告提到的增强路径，不是预训练默认就带 o1 式长思维。

文献引用 DeepSeek-V3 技术报告（arXiv:2412.19437）。不要伪造 DualPipe 的独立 arXiv 号；它是报告内的工程名称。专家数、共享数以报告当时配置为准，后续开源修订以模型卡为准。

2.788M GPU 小时是「他们那套实现 + H800」的账单，不是理论 FLOPs 下限。换网络拓扑、关掉 FP8、MTP 头配置不同，墙钟会变。引用时应带硬件型号。

小结 ​

  • DeepSeek-V3：671B 总参、约 37B 激活；MLA + 放大的 DeepSeekMoE。
  • 负载均衡改为专家偏置、无辅助损失；预训练目标含多 token 预测。
  • 14.8T token，约 2.788M H800 GPU 小时，报告称训练稳定无回滚。
  • 服务成本按激活算 FLOPs、按总参算显存；MTP 模块另计。
  • 出处：DeepSeek-AI, DeepSeek-V3 Technical Report，arXiv:2412.19437，2024。
