FineWeb / FineWeb-Edu ​

闭源基座的预训练数据几乎不可见；把九十六个 Common Crawl 快照收成一万五千亿可训练 token，并把每一步过滤做成可消融的公开实验，才能把网页配方从商业秘密变回公共知识。

—— Penedo et al., The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale, NeurIPS 2024

Penedo、Kydlíček、Ben Allal 等人在 Hugging Face 放出 FineWeb：从 96 个 Crawl 快照抽出约 15T token 的英语网页，以及用教育价值分类器切出的 1.3T FineWeb-Edu。配套的不只是数据，还有 datatrove 处理库、七十多个消融模型，以及 ODC-By 许可。它把 RefinedWeb 的主张——仔细处理的网页可以很强——推到「逐步换刀、每刀都有下游分数」的工程科学。Edu 变体则把质量定义从「像通顺网页」改成「像能教东西的页面」，在 MMLU 与 ARC 上拉开明显差距。今日开源配比里出现 FineWeb 或 FineWeb-Edu，多半是在引用这次消融，而不是又一个匿名 tar 包。

问题 ​

Llama 3 与 Mixtral 开了权重，配方仍是黑盒。公开网页集已经很多：C4、Pile-CC、RefinedWeb、Dolma 的 CC 子集、SlimPajama、RedPajama V2，但彼此换了抽取器、快照集合与去重范围，分数无法归因。需要一次把变量锁死的马拉松：同一 1.82B Llama 结构、同一评测套件，每次只改管道里的一截。评测本身也要筛选——小模型上方差大、非单调、贴随机基线的任务不能拿来指导万亿级数据决策。他们留下 CommonSenseQA、HellaSwag、PIQA、ARC、MMLU 等一组「有信号」的探针，大基准截到 1000 条以便训练中反复测。

第二个问题是去重的尺度。直觉说「全局去重越干净越好」。在 96 个快照上按时间从新到旧做全局 MinHash 之后，最老的快照可能被删掉九成，剩下的 4T 在 350B token 训练里几乎不涨分，还明显落后 RefinedWeb。检查 2013-48 这一刀：被全局去重保留的 10% 反而比被删的 90% 更差，广告与关键词堆砌更多。全局连通把「跨年转载的稍好文章」删掉，留下每个快照里独一无二的垃圾长尾。问题变成：重复该在哪一层消灭，才不会把质量分布拧反。

抽取是所有过滤器的天花板 ​

WET 是 Common Crawl 预抽的纯文本，便宜，但菜单与样板大量残留。他们改用 trafilatura 打 WARC，只加 fastText 英语门，28B token 消融已经稳定胜出 WET。这与 RefinedWeb、后来 DCLM 用 resiliparse 的结论一致：先把主文拿对，再谈启发式。自定义抽取贵，却是一次性资本。FineWeb 把这笔成本摊到 96 个快照上。复现若图省事从 WET 起步，后面再精密的 MinHash 也只是在给导航条做近重复检测。

方法 ​

基础过滤沿 RefinedWeb：URL 成人黑名单、fastText 英语分 \(\ge 0.65\)、MassiveText 的质量与重复规则（原阈值）。96 个快照过完这一段约 36T（GPT-2 词表）。MinHash 取词级 5-gram、112 个哈希、14 桶 × 8，目标约 75% 相似。关键选择是：每个快照单独去重，而不是全球一张图。快照内去重得到约 20T，随机抽样训练即可追上 RefinedWeb；他们试过的「更轻的全局去重」都没再涨分。假设是：真正有害的是每个快照里动辄数十万篇的巨大重复簇，跨快照去重那些小于快照数的小簇，会误伤多样性。

随后对准 C4。C4 在 HellaSwag 上仍硬，他们把 Raffel 的规则拆开打：去 javascript / cookie 声明 / lorem ipsum / 花括号 / 过短文档，能贴近 C4；「行必须有终结标点」单独贡献最大，却砍掉约 30% token。最终采用除终结标点外的 C4 规则。再自造过滤器：用「快照内去重」当高质量参照、「全局去重残留」当低质量参照，比较五十多种文档统计的直方图，找出低质量密度更高的区间，得到 17 个候选阈值，消融留下三条——行末标点比例 \(\le 0.12\)、重复行字符比例 \(\ge 0.1\)、短于 30 字符的行占比 \(\ge 0.67\)。三条合砍约 22% token，聚合分数再升约一个点，并在去掉更少数据的前提下超过 C4。公开 FineWeb 还做了邮箱与公网 IP 的 PII 匿名。全程约 15T。

FineWeb-Edu：把「教育价值」从黑盒里拿出来 ​

Llama 3 与 Phi-3 都提到过用合成标注做教育过滤，公开网页上缺大规模验证。他们对 FineWeb 抽 46 万条，用 Llama-3-70B-Instruct 按 0–5 分打教育质量，提示采用 Yuan 等人的加性量表、并压低对 arXiv 式高技术页的偏好，把目标放在中小学可学的解释。410k 条用来在冻结的 Snowflake-arctic-embed-m 上训线性回归，50k 作验证，输出四舍五入回整数。阈值扫过后取 3，验证集 F1 约 82%，在知识推理与 HellaSwag 之间折中。全库打分约 6000 H100 小时，得到 1.3T。350B token 的 1.82B 消融上，MMLU 从约 33% 到 37%，ARC 从约 46% 到 57%；38B token 处 Edu 的 MMLU 已到 33.6%，对照集往往要多一个数量级的 token 才追上。

阈值 3 不是教育的客观定义，是这条蒸馏头与这套探针的工作点。调到 4 会更「像教材」、更小、更伤杂项常识。把 Edu 当唯一预训练桶，等于用中小学解释体覆盖全分布——代码、对话、新闻会缺。它是网页桶内的专科滤镜，不是通用语料的替代。

机制 ​

每一步都应在固定计算下移动同一组探针，否则「更干净」只是体积变小。抽取改输入测度；基础启发式改支撑；快照内 MinHash 改频率且避免全局拧反质量；C4 与自研规则对准「终结标点、重复行、短行」这类与 HellaSwag 相关的表面统计；Edu 分类器则把参照换成大模型的教育判断。Penedo 等人在 RefinedWeb 里拒绝内容分类器，是为了中性与规模；FineWeb-Edu 把分类器请回来，是因为下游已经变成知识考试。两条原则针对不同目标，不是自我否定。

全局去重失败的机制值得单独记住。设文档质量 \(q\)，出现次数 \(n\)。跨快照的转载往往 \(n\) 大、\(q\) 中等偏上；每个快照特有的 SEO 页 \(n=1\)、\(q\) 低。全局近重复删除按 \(n\) 开刀，于是高 \(n\) 的中等质量被灭，低 \(n\) 的垃圾被保留，训练分布的期望质量下降。快照内去重消灭的是「同一爬取里铺天盖地的模板」，不动跨年新闻的合理重复。FineWeb 用实验否决了「去重范围越大越好」的默认。

与 RefinedWeb、DCLM 的继承 ​

基础过滤与 trafilatura 来自 RefinedWeb；系统消融、快照内去重、C4 规则拆解与 Edu 头是新的。DCLM 随后在公共池上比较分类器，发现 OpenHermes+ELI5 的 fastText 比维基参照更贴 MMLU——与 Edu 的「解释体」方向一致，只是正例从合成教育分换成指令与论坛长解释。三者连起来读：先把抽取与启发式地板垫高（RefinedWeb / FineWeb），再决定质量头的参照（Edu 或 DCLM），不要跳过地板直接上 70B 打分。

边界与工程取舍 ​

FineWeb 是英语网页。多语言、代码、数学公式（LaTeX 是否被 trafilatura 保住）都不在优化目标里。Edu 提示刻意避开高技术页，对大学教材与论文不友好；要 Minerva 式能力得另加 OpenWebMath 或 arXiv。PII 只匿名邮箱和公网 IP，间接标识仍在。分类器会过时：2024 年的教育分头，打 2026 年的模型生成「讲解文」可能全面高分。消融模型 1.82B、最长 350B token，不能保证 70B、15T 上每条启发式仍同号；他们用公开对比模型把 FineWeb / Edu 放到与 RefinedWeb、Dolma、SlimPajama 同一张图上，这是目前能给出的最强公开证据，仍不是闭源配方的上界。

datatrove 才是可引用的配方载体。只下载 FineWeb parquet、却用另一套抽取器去处理新年份 Crawl，得到的不是 FineWeb。报告应包含：快照列表、是否快照内 MinHash、C4 规则是否含终结标点、Edu 阈值。

小结 ​

  • FineWeb 从 96 个 Crawl 快照得到约 15T 英语网页 token；FineWeb-Edu 是其中 1.3T 教育子集。
  • 抽取用 trafilatura；去重必须快照内做，全局 MinHash 会留下更差的长尾。
  • 启发式经对照直方图筛选，并拆开验证 C4 规则；强终结标点门因砍量过大被放弃。
  • Edu 用 Llama-3-70B 合成 0–5 分，蒸馏成嵌入上的线性头，阈值 3；知识类基准显著上升。
  • 每一步都用固定小模型消融，代码与消融权重一并公开。
  • Edu 改的是网页桶内参照，不能单源覆盖代码与高等数学。
  • 出处：Penedo et al.，The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale，arXiv:2406.17557，NeurIPS 2024；对照同组 RefinedWeb、Raffel C4、Li et al. DCLM。
