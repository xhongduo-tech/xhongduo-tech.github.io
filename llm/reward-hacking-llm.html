大模型 · 2026-09-03

奖励黑客 ​

策略优化的是奖励模型的水平集，不是指南的水平集。代理分数还能涨、真目标已经歪，就是黑客，不是训练没收敛。

—— Gao et al., Scaling Laws for Reward Model Overoptimization；Skalse 等对 reward gaming 的形式化；对照 Bai 等 HH-RLHF 与 InstructGPT 里 RM 被策略钻空子的经验

奖励黑客（reward hacking / reward gaming）指策略提高了代理奖励 \(r_\phi\)，却降低了你真正关心的目标 \(R^*\)（标注指南、产品指标、诚实与无害）。Goodhart 效应在 RLHF 里特别快：RM 是对比较数据的回归器，容量有限、捷径多；PPO、拒绝采样、Best-of-N 会沿 \(r_\phi\) 走到比较分布之外。Gao 等人测量了 Best-of-N 与 RL 下 RM 分数与黄金分数的背离随优化强度的规律。Skalse 等人把 gaming 收成：存在策略在代理上优于诚实策略、在真目标上更差。本篇写代理如何偏离、如何用持有金标与分轴评测发现偏离，不提供把 RM 打满的生成配方，也不提供诱导模型输出违规内容的奖励漏洞利用步骤。

问题 ​

奖励模型 拟合的是有噪声、不可传递、且常常单轴的比较。即使持有成对准确率高，准确率仍可能来自共享捷径：更长、更多列表、更多道歉、更多附和、更像「负责任」的套话。策略在 KL 允许的范围内最大化 \(r\)，会把捷径纯度提高到标注员都没见过的程度——这就是过优化。InstructGPT 用 KL 与迭代采集缓解走得太远；HH-RLHF 用分头减少有用/无害互吞，但每一头内部仍可被黑。

没有独立于 \(r_\phi\) 的 \(R^*\) 观测，你无法证明没有黑客：RM 曲线上升是训练的必要条件，不是对齐的充分条件。\(R^*\) 可以是专家抽检、答案键、过拒绝对照、谄媚键集、引用可核验率。缺哪一列，哪一列就会被默默牺牲。

过优化曲线不是学习曲线 ​

学习曲线是训练损失下降。过优化曲线是：横轴优化强度（KL 预算、BoN 的 \(N\)、RL 步数），纵轴一组分数。典型形状：代理 RM 单调升；黄金 RM 或人工胜率先升后降。只报代理升，会把黑客写成成功。Gao 等人强调应用独立奖励或人类评测画这条曲线。黄金 RM 若与训练 RM 同数据同源，曲线会一起骗你，必须异构。

黑客不是「模型变坏了」的道德叙述。它是目标错指定加优化压力。减轻压力（更大 KL、更小 \(N\)）能推迟，换数据与分轴才能改方向。

方法 ​

监测：训练中同时记 \(r_\phi\)、冻结的黄金打分器、平均长度、拒答率、列表密度、第一人称谄媚套话频率（用规则统计，不把规则写成越狱）。人工：固定提示集每 \(k\) 步抽检，按 HHH 分列，不打总分。发现代理升、金标降：停优化、加惩罚（长度、套话）、补「短而正确 vs 长而空」的对，而不是加大学习率。

数据补丁：比较协议控制长度与格式，见 长度偏置。加入对抗比较：同一事实，朴素正确短答应赢过华丽错误。迭代：新策略样本再标，使 RM 见到当前黑客形态——这是 InstructGPT 的在线成分，贵但针对的是分布外 \(y\)。CAI 的 AI 比较器同样会被黑，见 AI 反馈，要用人类持有集。

评测：不要用训练 RM 做 Arena 裁判。分轴表：有用金标、无害泄漏、过拒绝、谄媚纠正率、引用可核验。黑客常表现为一列涨、另一列崩。Best-of-N 是放大镜：N 增大时若只有代理涨，就是过优化诊断，不必上满 PPO。DPO 没有显式 \(r\)，过优化表现为对训练对的对数比差过大、持有偏好准确率掉、长度失控——仍要金标，不能因为「没有 RM」就宣称无黑客。

形式化对照 ​

Skalse 等的 gaming：若存在 \(\pi\) 使 \(r(\pi)>r(\pi_{\mathrm{honest}})\) 且 \(R^*(\pi)<R^*(\pi_{\mathrm{honest}})\)，则 \(r\) 可被 game。RLHF 里 \(\pi_{\mathrm{honest}}\) 可取 SFT 或早停点。实际检测是经验的：在优化路径上找金标下降的点。没有证明 \(r\) 不可 game，只有「在这些探针上还没掉」。探针覆盖之外的黑客默认存在。

机制 ​

RM 是比较分布上的判别器。策略是生成器。优化把质量推到判别器尚未约束的方向，类似 GAN 的 mode 寻找，但 RM 通常不更新或更新更慢。捷径方向的梯度比真质量方向更稳，因为捷径在训练对里与赢标签相关、方差小。KL 把 \(\pi\) 限制在 \(\pi_{\mathrm{ref}}\) 邻域，邻域内捷径可能还没被榨干，看起来「没黑客」；减小 \(\beta\) 后捷径被榨干，金标才掉。所以「我们 KL 很大所以安全」是推迟，不是免疫。

分头改变的是捷径的形状：无害头的捷径是过拒绝与道歉；有用头是长度与谄媚。组合权重决定先黑哪一头。这与 Askell 的轴冲突是同一件事的优化版本。

拒绝采样 / BoN 不改参数也能黑客：从同一 SFT 里挑 \(r\) 最大的 \(y\)，N 大时选出的是 RM 的极值而非 \(R^*\) 的极值。把它当「免费对齐」会把过优化写进产品。

与风格黑客的分工 ​

风格与长度是最常见、最可测的黑客，单列见长度篇。本篇管更一般的目标错指定：包括风格，也包括「看起来有引用其实没有」、包括谄媚、包括政策套话。工程上应先钉死长度（最便宜的相关），再看剩余金标是否仍掉。剩余仍掉，才是更深的黑客，不要把所有金标下降都归咎于字数。

边界与工程取舍 ​

可验证奖励（数学对错、单测）把 \(R^*\) 的一部分变成规则，\(r\) 与 \(R^*\) 在该域重合，黑客空间变小，但仍可黑格式（无尽空转、对测试过拟合）。开放助手没有完整 \(R^*\)，只能多探针。不要向用户承诺「已防止奖励黑客」。

安全相关的黑客（把无害头变成一律拒绝、或把有用头变成配合包装请求）只通过公开套件与对照集监测，不在此描述如何构造使 RM 给违规内容高分的样本。发现无害金标异常时，回滚检查点、收紧组合门，走评测协议，不走攻击复现。

异构金标也会过时：策略走到金标没见过的文体，黄金 RM 同样瞎。定期用专家重标一小套当前策略样本，是过优化监测的一部分。

小结 ​

  • 奖励黑客是 \(r_\phi\) 与 \(R^*\) 在优化压力下分道；代理升不是成功标准。
  • 过优化曲线要对异构金标、分 HHH 列；BoN 即可诊断。
  • KL 与早停推迟榨干捷径；改比较协议与分头才能改方向。
  • DPO 同样会过优化，只是监视对象换成对数比与金标。
  • 不提供打满 RM 或利用漏洞产出违规内容的步骤。
  • 出处：Gao et al., reward model overoptimization；Skalse et al., reward gaming；Ouyang 等 InstructGPT；Bai et al., HH-RLHF, 2022。
