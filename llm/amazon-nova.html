Amazon Nova ​

Nova 家族按价、速、准三条轴分层：Micro 做纯文本最低延迟，Lite / Pro 做多模态理解，Premier 做复杂任务并充当蒸馏教师。

—— Amazon AGI，The Amazon Nova Family of Models: Technical Report and Model Card，arXiv:2506.12103

Amazon 在 2024 年 re:Invent 放出 Nova：理解侧是 Micro / Lite / Pro，生成侧是 Canvas（图）与 Reel（视频），一律走 Bedrock。2025 年 4 月再加 Premier，窗口到约 1M token，并明确当教师去蒸馏更小的 Nova。相对 Gemini / GPT 的「一张旗舰打天下」，Nova 的公开叙事是云上价绩比与可定制（微调、蒸馏），而不是开源权重。层数、头数、总参数公开信息有限；能写的是模态、窗口、训练阶段名称与产品角色。

问题 ​

企业要把助手接到已有 AWS 身份、日志与数据驻留，而不是再养一套模型园。问题变成：能否在同一套 Converse / Bedrock API 里，按请求在「极便宜纯文本」和「能看图看视频的中档」之间切换，并且允许用私有数据微调或蒸馏，而不把教师权重下载出域。Nova 把这个问题收成家族矩阵：理解模型共享 Transformer 骨架与后训练哲学，生成模型走另一套扩散式管线，二者都叫 Nova，但不是同一个解码器。

第二个问题是窗口与账单。长文档、长视频、代码仓若都按旗舰 1M 计价，多数 RAG 并不需要。于是 Micro 给 128k 纯文本，Lite / Pro 给约 300k 多模态，Premier 给 1M。窗口是产品档位，不是「同一个权重改了 max_position」。

理解档与生成档不要写进同一张结构表 ​

Canvas 与 Reel 解决的是图像 / 视频生成与可控性，技术报告把它们与理解模型并列在家族里，但预训练目标、架构（扩散 vs 自回归）并不相同。本篇以理解模型为主：Micro 只吃文本；Lite / Pro / Premier 吃文本、图像、视频，输出仍以文本为主（后续卡片若扩展语音/图像输出，以当时模型卡为准）。把 Reel 的时长规格写进 Pro 的上下文窗口，是常见错位。

Bedrock 模型 ID 形如 amazon.nova-pro-v1:0，跨区推理还有 us.amazon.nova-… 前缀。应用应钉 ID 与推理档（区域内 / 地理 / 全球），不要只写商品名「Nova Pro」。

方法 ​

技术报告写明：Pro / Lite / Micro 基于 Transformer；预训练混合多语与多模态数据，来源包括许可、专有、开源与公开数据；语种覆盖声称 200+，并点名阿语、荷兰语、英语、法语、德语、希伯来语、印地语、意大利语、日语、韩语、葡语、俄语、简体中文、西班牙语、土耳其语等。后训练迭代进行：指令 SFT（含多模态演示）、由人类偏好训练奖励模型，再用 DPO 与 PPO 对齐质量与责任。这是可核对的阶段名称；数据配比、token 总数、是否 MoE，公开信息有限。

Premier：教师，而不是另一套开源旗舰 ​

Premier 被定位为最强多模态理解档，窗口 1M，适合长文档、长视频、大代码仓与多步智能体。Bedrock Model Distillation 允许用 Premier 当教师，定制 Pro / Lite / Micro；Pro 也可以当更小档的教师。官方例子是：用 Premier 蒸馏 Pro 做复杂工具选择与 API 调用，蒸馏后的 Pro 在 API 调用准确率上相对基线提高约 20%，并在速度与成本上保留 Pro 档。定制微调（CFT）对 Micro / Lite / Pro 开放；Premier 的角色首先是教师与重任务端点，而不是「再下一个开源 405B」。

公开窗口（以用户指南当时表格为准，会随文档修订）：

  • Micro：文本，约 128k 上下文，最大输出约 10k。
  • Lite / Pro：文本 + 图像 + 视频，约 300k。
  • Premier：约 1M（后续卡片上的最大输出 token 可能与初版 10k 不同，以模型卡为准）。

安全叙事是贯穿预训练到部署的责任 AI：红队、隐私处理、输出水印等写在报告后半，细节以责任 AI 文档为准，本文不把未公开的拒答率表写成定理。

「200+ 语言」是预训练覆盖声明，不等于 200 种语言都达到同一安全与事实性门槛。产品上应按业务语种单独评测，尤其是未点名强调的长尾语。

机制 ​

价绩比的机制是同一后训练哲学下的容量分级：小档少算力、短窗口、纯文本；大档多模态融合与更长上下文。融合模块、视觉编码器是否共享、视频如何抽帧，报告未给到可复现的算子图，公开信息有限。能确定的是：输出默认是文本补全，理解视频/图表是为了写分析、做 RAG 与智能体，而不是在 Pro 里直接出片——出片走 Reel。

蒸馏的机制是把教师在特定任务（工具选择、领域问答）上的分布压到学生，使学生在 Bedrock 计价档里接近教师准确率。这依赖教师已经对工具 JSON 与企业模板做过对齐；换一套自创 XML 工具标签，蒸馏信号会对不齐。DPO 与 PPO 并用，说明 Amazon 没有把后训练收成单一算法口号：离线偏好与在线 RL 都在配方里，超参未公开。

长上下文的机制与所有云模型相同：窗口规格是训练过并按文档验收的上限。把 1M 配给 Premier，是让「整本手册 + 多段视频」的请求不要落到 128k 的 Micro 上。注意力是否稀疏、是否分块，公开信息有限。针检索与「能综合」仍是两张表。

定制发生在云内 ​

CFT 与蒸馏的梯度与数据不出客户约定的边界（以 AWS 当时数据处理附录为准）。这与「下载权重自己训」是不同契约：可审计性换成合规与 IAM。换模型世代时，蒸馏出来的学生不会自动跟上教师的新快照，需要重新蒸馏。

边界与工程取舍 ​

参数量、层数、词表、是否 GQA / MoE，技术报告没有给出与 Llama 3 同等级的表。第三方「估算几十 B」不得写成官方规格。Canvas / Reel 的内容策略、水印与人像限制独立于理解模型的拒答。Premier 与 Pro 的知识截止以模型卡为准（卡片上出现过 2024-10 一类日期），长窗口不能补训练截止之后的世界。

工程上，300k / 1M 的预填充费用会主导账单；RAG 仍应切块。跨区推理降低延迟，但驻留要求必须读推理档说明。把 Nova 与 Claude / Llama 在 Bedrock 里并列时，工具模板与引用格式并不互通。后续模型卡若把最大输出从 10k 改到 25k、或加上推理（reasoning）开关，应以新卡为准，不要冻结在 2024-12 的发布稿。

Nova 没有可下载的 Apache 权重。评测复现只能走 API，系统提示、安全模式与区域都会改变分数。对比开源 70B 时要把「能否本地部署」单列，不要只比 MMLU。

小结 ​

  • Nova 理解档：Micro（文本、约 128k）、Lite / Pro（多模态、约 300k）、Premier（约 1M，蒸馏教师）；生成档 Canvas / Reel 另算。
  • 公开训练阶段：多语多模态预训练 → SFT → 奖励模型 → DPO / PPO；参数量与层数公开信息有限。
  • 定制走 Bedrock 微调与教师蒸馏，而不是开源检查点。
  • 出处：Amazon AGI，The Amazon Nova Family of Models，arXiv:2506.12103；Premier 增补报告（2025-04）；Amazon Nova 用户指南与 Bedrock 模型卡。re:Invent 2024 为首发时间点。
