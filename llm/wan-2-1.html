Wan 2.1 ​

Wan 建立在扩散 Transformer 与流匹配的主流范式上，用新型时空 VAE、可缩放预训练、大规模数据策展与自动评测，把开源视频生成推到与商用方案可对标的位置。

—— Wan Team, Wan: Open and Advanced Large-Scale Video Generative Models, arXiv:2503.20314

阿里巴巴通义万相团队在 2025 年公开 Wan 2.1：一套开源视频基础模型，代码与权重放在 Wan-Video/Wan2.1，技术报告为 arXiv:2503.20314。主轴不是再发明一套生成论，而是把 DiT 加 Flow Matching 做到 14B 量级，并配上专为视频设计的 3D 因果 VAE。报告写明四条产品主张：14B 在内部与外部基准上超过当时开源与若干商用方案；同时提供 1.3B 与 14B 两档；下游覆盖图生视频、指令编辑、个性化等至多八项任务；1.3B 文生视频约 8.19 GB 显存，可在消费级 GPU 上跑。它还自称是当时能在画面里同时生成中英文视觉文字的视频模型。本篇只写这篇报告与官方仓库已写明的方法，不把后来的 Wan 2.2 倒填进来。

问题 ​

视频生成要同时压缩空间与时间。只做空间 VAE，时间维仍随帧数爆炸；做 3D VAE 又要面对因果性：未来帧不应泄漏进过去帧的表征，否则无法把图像当单帧视频、也无法做任意长解码。开源社区此前多在 U-Net 上插 1D 时间注意力，或把空间、时间注意力拆开；全时空注意力表达力更强，但 token 数到几十万时二次复杂度会压垮训练。文本侧还要同时吃中英文提示与画面里的文字渲染，单向 LLM 编码器并不自动等于好的构图控制。

第二个问题是缩放路径。直接在 720P、81 帧上从零训 14B，序列太长、batch 太小、梯度方差会炸。报告把问题收成：先有一个足够好的潜空间，再有一条从低分辨率图像到高分辨率视频的课程，最后用同一套 DiT 去接多种可控任务。

因果压缩与无限长解码不是同一句话 ​

Wan-VAE 把输入 \(V\in\mathbb{R}^{(1+T)\times H\times W\times 3}\) 压到 \([1+T/4,\,H/8,\,W/8]\)，通道扩到 16；第一帧只做空间压缩，以兼容图像，做法对齐 MagViT-v2。这解决的是「一分钟视频的 token 预算」。任意长 1080P 编解码靠因果卷积上的特征缓存：卷积核为 3 时保留前一块的末两帧，下一块接着用，而不是把整段视频一次装进显存。缓存是推理工程，不等于训练时已经看见无限未来。

Wan-VAE 约 127M 参数。报告称同硬件下重建速度约为当时 HunyuanVideo VAE 的 2.5 倍。不要把「第一帧只空间压缩」写成「图像与视频用两套 VAE」——是同一 3D 因果网络，图像是 \(T=0\) 的特例。

方法 ​

骨干是冻结的 Wan-VAE 加可训练的 DiT。文本用 umT5，序列长 512。作者写明选择理由：多语（中英及画面文字）、相对单向注意力 LLM 在构图上更好、同规模收敛更快。条件注入走交叉注意力；动态靠全时空注意力，而不是拆成「先空间后时间」的两套块。生成目标是 Flow Matching 的速度场，而不是经典 DDPM 的噪声预测。对潜变量 \(x\)、文本 \(c_{\mathrm{txt}}\) 与时间 \(t\)，模型输出 \(u(x_t,c_{\mathrm{txt}},t;\theta)\)。

预训练课程：先在低分辨率（约 256 px）做文生图，把语义与几何对齐稳住；再多阶段联合图像与视频，分辨率与时长逐步拉高。只训 DiT，文本编码器与 VAE 冻结。计算上 DiT 占训练前向 85% 以上；注意力代价随 token 二次增长，视频序列可达数十万甚至百万级，14B 在微 batch 为 1、百万 token 时激活显存可超过 8 TB 量级——这是报告给出的量级，用来解释为何必须课程与并行，不是一张可复现的集群账单。

图生视频是掩码条件，不是另一套权重叙事 ​

图生视频把条件图像当作首帧：沿时间与全零帧拼接，经 Wan-VAE 得到 \(z_c\)，再与噪声潜变量、二值掩码沿通道拼接。掩码标明哪些帧保留、哪些帧生成。同一掩码机制扩展到首尾帧变换、视频续写与随机帧插值。联合预训练让模型学会「看掩码决定保还是生」；SFT 阶段才为图生视频等单任务加图像编码器，用解耦交叉注意力补全局外观。480P 与 720P 各有检查点。下游八项任务是这一条件接口的排列，不是八个互不相关的网络。

机制 ​

Flow Matching 把图像与视频放进同一条从噪声到数据的常微分方程。低分辨率图像预训练的作用是：在 token 还短、吞吐还高时先学会「提示对应物体与构图」，再把时间维当作额外的网格轴加进去。全时空注意力让跨帧的对应（同一只手、同一行字）可以直接打分，代价是长度二次；Wan 没有在报告里用线性注意力替换这一内核。

中英文视觉文字被写成一项可观察能力：VAE 重建阶段已强调文字场景，生成器再在潜空间里维持笔划结构。这不等于 OCR 保证。缩放叙事是数据和模型规模一起走：14B 吃数十亿图像与视频量级的语料；1.3B 用来证明「小模型 + 好 VAE + 同配方」仍能在消费卡上超过更大但配方更旧的开源模型。报告同时给出自动评测指标，用于内部迭代，主文仍以人工与基准对照为主。

umT5 的 512 token 上限会截断超长分镜剧本。交叉注意力把文本当另一路键值，不是把提示词拼进视觉 token；与 HunyuanVideo 的双流拼接不是同一接口。引用时不要把 SD3 的 MMDiT 画进 Wan 的块图。

1.3B 与 14B 共用范式，不共用服务假设 ​

1.3B 的卖点是 8.19 GB 显存与「几乎所有消费级 GPU」。它仍然是 DiT + Wan-VAE + umT5，不是蒸馏成 4 步的一致性模型。14B 才是报告里对标商用闭源的那一档，支持 480P 与 720P。部署时不要用 1.3B 的显存数字去外推 14B 的 720P 延迟。开源范围包括源码与全部所列模型；许可证与商用条款以仓库当时文件为准。

边界与工程取舍 ​

评测含内部基准，跨实验室复现要以公开提示与同一采样步数为准。商用方案的「全面超过」是报告当时的对照，闭源模型随后会迭代。任意长解码依赖缓存正确性，接缝处仍可能出现时间不一致。视觉文字在复杂透视、运动模糊下会碎。图生视频的身份锁定来自首帧加后期图像编码器，不是公开的人脸 ID 嵌入 API。

不要把报告未给出的层数表、噪声日程或数据配比补进架构图。不要把社区 LoRA、Comfy 工作流里的模块当成官方设计。与 HunyuanVideo、Sora 比较时：Sora 只公开博客级时空 patch；Wan 公开 VAE 压缩比、umT5 与 Flow Matching；HunyuanVideo 公开 13B 双流块数。三者都不要用未公开的 FVD 私榜当唯一尺子。

出处：Wan Team，Wan: Open and Advanced Large-Scale Video Generative Models，arXiv:2503.20314（2025）。代码 https://github.com/Wan-Video/Wan2.1。权重如 Hugging Face Wan-AI/Wan2.1-T2V-14B 与 Wan2.1-T2V-1.3B。DiT 引用 Peebles & Xie；Flow Matching 引用 Lipman et al. 与 SD3（Esser et al.）。

小结 ​

  • Wan 2.1 是开源视频基础模型：Wan-VAE + 全时空注意力 DiT + umT5，训练目标为 Flow Matching。
  • Wan-VAE 做 \(4\times 8\times 8\) 因果压缩、16 通道，特征缓存支持任意长 1080P 编解码。
  • 14B 走图像预训练再联合视频；1.3B 把消费卡显存打到约 8.19 GB。
  • 图生视频、续写、首尾帧共用掩码条件；SFT 才加图像交叉注意力。
  • 官方强调中英文画面文字与最多八项下游任务；评测含对当时商用模型的对照。
  • 出处：Wan Team，arXiv:2503.20314。
