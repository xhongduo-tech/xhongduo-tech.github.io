OCR 与文档 VLM ​

认出每一个字只是文档理解的下限；版式、读序、表格结构与字段关系，才是要把页面当作一张图交给语言模型的原因。

—— 从 LLaVA-NeXT、Qwen-VL 到 InternVL 的文档侧

传统 OCR 管的是「图上这些笔画是什么字符」。文档问答、表单抽取、报告解析管的是「这些字符在版面上构成什么」。视觉语言模型把整页当作图像 token 送进 LLM，输出可以是自然语言，也可以是 Markdown、HTML 或 JSON。Qwen-VL、InternVL、LLaVA-NeXT 都把文档与文字理解写入能力范围，但能力不是「OCR 准确率」一个数能概括。本篇把文档 VLM 与识别引擎分开，并说明分辨率、连接器与读序为何比再堆一个识别头更关键。

问题 ​

印刷或扫描页上同时存在至少四层结构。字形：字符类别。几何：行、栏、段落的空间邻接。逻辑：标题统领正文、单元格属于哪一列、脚注不是正文。任务：用户要的是全文转写、还是「发票税额」、还是「把表变成 CSV」。只做字形层，得到的是乱序或按检测框堆起来的字符串，表格会塌成线性垃圾，多栏会左右读串。

把页面当自然语言继续写，又会丢掉必须对齐到像素的约束：坐标、框、阅读顺序。文档 VLM 的问题设定是：用高分辨率视觉 token 让 LLM 同时看见字形与几何，再用生成目标输出带结构的文本。它包含 OCR，但不等于 OCR。评测若只用字符准确率，会选出「会念字、不会读表」的模型。

方法 ​

整页图像条件生成 ​

流水线是：页图 → 高分辨率 ViT → 连接器 → LLM。没有独立的检测–识别两阶段也可以工作：注意力在 patch 格子上隐式完成「看哪里」。输出模板决定任务：纯转写、带坐标的定位、键值抽取、或问答。Qwen-VL 把图文任务与指向写进同一解码器；InternVL 与 LLaVA-NeXT 则证明，升分辨率（动态切格或 AnyRes）对文字任务的增益远大于对自然图 VQA。

\[p(y\mid I,x)=\prod_t p(y_t\mid I,x,y_{<t}) \]

\(I\) 是页图，\(x\) 是指令（「转成 Markdown」「抽取日期」）。结构监督来自回答本身：若训练目标是带表格语法的文本，模型才有压力保持格线关系。

检测式 OCR 先出框再识别，读序要另做排序。VLM 把读序留给注意力与语言模型先验。先验有用（它知道表格通常先读表头），也会幻觉（它按「像一张发票」的模板填不存在的字段）。文档任务必须同时测漏读与瞎编。

分辨率与文字尺度 ​

文字的最小笔画宽度必须在 patch 里可辨。固定 224/336 画布上，A4 扫描件的正文会小于一个 patch，连接器再精巧也是在噪声上做语言建模。AnyRes 与动态切格提高采样密度；原生分辨率切块 避免宽页被压成方图。这是文档 VLM 的主开关。视觉 token 变多之后，再用一次温和的 压缩，而不是先压后升。

结构输出而不是字符流 ​

同样读对了字，输出 JSON 字段、HTML 表格或纯文本，下游可用性差一个数量级。训练数据应含版式标记：空格与缩进、表管道符、标题层级。Qwen 系列后续的文档解析把 HTML/版式当作一等目标，那是同一思想的强化，本篇只强调：文档 VLM 的监督信号是结构文本，不是字符分类 logit。没有结构目标时，模型退化为「会念字的字幕模型」。

机制 ​

LLM 能「理解文档」，是因为视觉 token 仍按二维邻接排列（或带二维位置），自注意力可以同时混合「这个字」和「它上面的表头」。字符识别于是成为生成过程中的局部对齐，表格结构成为跨区域对齐。这与独立 OCR 再拼接字符串不同：后者在进语言模型之前已经丢掉了大量几何。

幻觉机制也特殊。语言模型先验很强，发票、简历、试卷都有刻板模板。当某格看不清时，它会按模板补全，字符错误率可能看起来还行，字段却张冠李戴。另一失败是读序：多栏、竖排、插入框图，栅格的 raster 顺序与人类读序不一致，若没有足够数据或二维位置，模型会按 token 序硬读。高分辨率减少「看不清」，二维位置与结构监督减少「读错序、补错槽」。

「OCR 能力」在 VLM 报告里常常是文档 VQA 或转写基准的混合。应拆开：单行清晰印刷、密集小字、表格、手写、旋转、低对比扫描。旋转与弯曲属于几何归一，和认字不是同一模块，不要用一个分数解释所有掉点。

边界与工程取舍 ​

VLM 不是在所有场景替代工业 OCR。极长多页、极严的字符级 SLA、需要逐字置信度与框的流水线，检测–识别仍更可控。VLM 的优势在开放指令、跨页推理、以及「认字 + 解释 + 抽取」同一模型。多页要把每一页的视觉预算加起来，否则后页被截断，跨页问答是假的。

不要声称某模型「解决了 OCR」。公开论文给出的是特定基准上的生成质量，不是印刷线的工程认证。也不要把 Layout 专用编码器与通用 VLM 混成一篇发明：本篇只讨论通用视觉编码器 + LLM 这条路在文档上的用法。连接器若用过小的查询集 \(M\)，等于在进 LLM 前做了一次毁版面的池化，文档任务应拒绝这种默认。

落地时先看输入 DPI 与最短边像素，再看模型。用户上传手机拍页、反光、歪斜，任何 VLM 都会先在成像上失败。旋转矫正、切边、二值化仍是合法前处理，不是「不够端到端」的耻辱；它们只是把问题送回模型能读的尺度。

取舍：以开放文档问答和结构化抽取为主，上高分辨率通用 VLM；以海量票据的稳定字段为主，专用 OCR + 规则/小模型可能更省。两者可以串联：OCR 提供可复制字符串，VLM 提供版式与推理，但要避免两套读序互相打架。

小结 ​

  • 文档 VLM 做的是版式条件下的生成，OCR（认字）只是其中一层，不是全部。
  • 需要同时看见字形与几何，因此分辨率与二维布局比再加一个识别头更关键。
  • 监督应是结构文本（表、字段、层级），否则模型只会念字。
  • 看不清就靠语言模板补全，是文档幻觉的主因；要拆开测漏读与瞎编。
  • 查询式过度压缩会毁版面；文档路径应先升采样密度，再轻度合并。
  • 工业逐字 SLA 与开放指令理解不是同一产品，不必互相替代。
