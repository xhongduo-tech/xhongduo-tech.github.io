输出过滤与分类器 ​

生成器负责把话说完，分类器负责在话离开系统之前按政策打分：两套模型可以分开训练、分开失败，也可以串通着一起失败。

—— 对照 Inan 等 Llama Guard 把安全分类做成独立的指令式判别器，以及产品把输入/输出筛与生成器叠层

上一课把记忆写成分布属性：去重与数据最小化是主防，补全接口攻击面通常更大。缺口是安全决策仍挤在生成器权重里，政策难以热更新。本课把分类器从生成器里拆出来：放行、改写、拒答或送人审。不重讲暴露度公式。它是 越狱评测 里必须打开的产品叠层，也是 提示注入 里动作门控的落点；不能单独特替对齐。

问题 ​

只靠生成器对齐时，安全政策与有用性抢同一组权重，边界难以热更新：换一条政策往往要再训。过滤器把政策的一部分变成可热更新的阈值、类别表与小模型。代价是两条失败：漏放（有害输出得低风险分）与过拦（无害输出被挡）。漏放在越狱与注入评测里表现为叠层全开后 ASR 仍高；过拦在 XSTest 一类探针上表现为可用性问题。两者必须成对扫阈值，不能只报过滤器准确率。

过滤器看到的特征决定它能拦什么。只看输出字符串的分类器，拦不住「看起来像食谱、实际是被禁止的操作步骤」若其表面分布像普通教程——这要求类别定义与训练数据覆盖意图，而不是关键词。只看用户输入的分类器，拦不住模型自己在多轮中滑向违规。产品通常要对 用户输入、模型输出、工具参数 分别打分，策略可以不同：输入高风险直接拒，输出高风险则尝试安全改写或拒。

分类器与生成器的相关性 ​

若分类器用与生成器同源的模型、同一套包装数据训练，越狱包装可能同时骗过两者。评测必须包含「生成器已越狱、过滤器是否仍拦住」的条件指标，而不是假设独立。异构分类器（不同家族、不同词表、规则+模型）降低共模失败，但提高延迟与过拦。这是工程取舍，不是道德口号。

过滤器不是对用户的攻击工具。日志里应存类别与分值以审计漏放，不应把完整有害输出再写入可被广泛访问的工单。评测集使用公开套件的官方标签，不在文档展开失败样例全文。

方法 ​

Llama Guard 一类方案：给分类器一个固定的分类 taxonomy（暴力、自伤、隐私等），输入是对话片段，输出是类别与是否违反。它可以跑在输入侧（用户话）、输出侧（助手话）或两端。部署时与主模型分离：主模型生成，Guard 再前向一次。延迟上这是一次额外 prefill，长度等于待分类文本；可用较小规格、量化、或只对高风险路由调用。规则层并行：密钥与内网 URL 用模式匹配，不把这件事交给生成器「自己发誓不泄露」。

阈值扫描在验证集上画两条曲线：危害漏放率（相对政策标签）与过拒绝率（相对无害敏感探针）。工作点选在产品能承受的过拦之下、漏放低于合规线。多类别不要共用一个阈值：自伤与版权侵权的代价不同。热更新政策时先改分类器提示或类别说明，再决定是否重训；只改提示的 Guard 要重新做完整扫描，因为类别边界已经移动。

改写、拒答与人审 ​

高风险输出有三种处置。硬拒：返回固定安全话术，不回显模型原文。安全改写：用第二个生成器在「去掉违规部分、保留可回答的合法信息」的指令下重写，再送分类器，失败则硬拒。人审：高影响工具或高分不确定区进队列。改写层会引入新的泄露（把违规细节改写成仍可用的形式），必须用同一套危害可用性判分再测，而不能假设「已经过过滤器」即安全。本篇不讨论改写提示的对抗写法。

与约束解码的关系 ​

JSON 约束 保证结构，不保证安全。可以要求输出含 risk 字段，但不能让模型自评替代独立分类器——自评与生成器完全相关。约束可以缩小工具参数的字母表（枚举操作名），降低注入后的执行面；安全判定仍由分类器与后端白名单做。

机制 ​

设生成器给出 \(y\sim p_\theta(\cdot\mid x)\)，分类器给出 \(s(x,y)\in\mathbb{R}\)，放行当 \(s\lt \tau\)。系统的漏放率是 \(\Pr(s\lt \tau \mid y\text{ 违规})\)，过拦率是 \(\Pr(s\ge\tau \mid y\text{ 合规})\)。\(\tau\) 的移动在两条率之间权衡。若 \(s\) 与「\(y\) 是否违规」在对抗包装下变得近独立，曲线退化成随机，叠层失效。训练分类器时要用 带包装的违规样本与带敏感词的合规样本，否则 \(s\) 学成关键词检测。这些样本来自政策团队构造的评测/训练集，不在此列出文本。

把分类器做成与主模型同提示的「请判断是否有害」，等于再要一次对齐。Llama Guard 的价值在于固定 taxonomy 与独立权重，可以单独迭代。仍须用越狱套件测共模失败。

流式输出的时机 ​

用户希望首 token 尽快出现。若等整段生成再分类，TTFT 不受影响但完整延迟增加，且已经流出的前缀可能已含违规内容。策略包括：先缓冲 \(k\) 个 token 再开始流；对流式块做增量分类，触发则切断并撤回（客户端要支持撤回）；对高风险会话关闭流式。增量分类会有前缀未完成造成的误报，阈值与块大小要单独扫。密钥类规则应在流式块上立刻触发，不要等句末。

边界与工程取舍 ​

过滤器改变的是离开系统的字符串，不改变模型内部表示。研究性「表示层消融」不在本篇；产品上不要假设拦过一次的模型下次会自己拒绝。多语言与代码需要分类器有对应训练分布，否则英语 Guard 会对其他语言漏放、对英文技术名词过拦。工具参数过滤失败的代价通常高于聊天漏放，阈值应更严，过拦用「请用户确认」消化，而不是悄悄放行。

公开分类器（Llama Guard 各版本、WildGuard 等）有固定 taxonomy，与你们的政策可能不一致。要对齐映射表：套件类别如何并入内部类别，未覆盖的政策类别要自建数据。不要把论文里的 F1 抄进产品 SLA；SLA 必须在自己的分布上测漏放与过拦。Constitutional classifiers 一类工作用原则生成判别数据，迭代的是分类器而不是主模型，仍须走同一套成对曲线。

关闭过滤器来「提高有用性」会直接改写越狱 ASR。任何 A/B 若改变 \(\tau\) 或关掉 Guard，必须同步跑安全门禁，不能只看会话满意度。

发布门禁 ​

门禁：HarmBench/JailbreakBench 在叠层全开下的 ASR；XSTest 过拒绝；密钥与 PII 规则的召回抽检；流式切断是否在客户端真正撤回。分类器或 \(\tau\) 变更视为安全发布，不是纯体验发布。日志保留分值与类别以做漏放复盘，访问权限按隐私政策最小化。

小结 ​

  • 输出过滤用独立分类器与规则在输入、输出、工具参数上执行政策，便于热更新阈值。
  • 必须成对扫漏放与过拒绝；异构分类器降低与生成器的共模失败。
  • Llama Guard 是指令式安全分类器的代表，taxonomy 要映射到自身政策。
  • 结构约束不能替代安全分类；模型自评不能替代独立 \(s(x,y)\)。
  • 流式场景要规定缓冲、增量分类与撤回。
  • 不讨论绕过过滤器的方法；评测走公开套件与内部政策标签。
  • 出处：Inan et al., Llama Guard；越狱套件见 HarmBench / JailbreakBench；过拒绝见 XSTest。WildGuard 等后续分类器用于对照，不以单次 F1 为 SLA。
