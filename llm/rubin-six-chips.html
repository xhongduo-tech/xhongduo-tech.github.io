六芯片共设计：GPU/CPU/交换/网卡/DPU/以太 ​

把 GPU、CPU、交换、网卡、DPU 与以太网交换当成六个彼此独立的采购项，机柜就变回一堆要对齐固件的盒子。

—— NVIDIA 对 Vera Rubin 平台的公开命题：six new chips, one AI supercomputer

NVL72 是封装。封装里面是六颗被一起设计的芯片，而不是「先选 GPU 再配任意网卡」。NVIDIA 技术博客把这六颗写成：Rubin GPU、Vera CPU、NVLink 6 交换、ConnectX-9 SuperNIC、BlueField-4 DPU、Spectrum-6 以太网交换。角色分别是：算、编排与近端数据、机柜全互连、柜外端点、基础设施卸载、柜外交换。2026 年 3 月的更新把 Groq 3 列为第七颗芯片；本篇按知识树锁定的六芯片来写，第七颗是后补的推理加速路径，不改变这六颗的共设计关系。

问题 ​

传统数据中心把计算、网络、存储分层采购：GPU 服务器一套 BOM，InfiniBand 另一套，以太网再一套，DPU 可选。分层在企业网里合理，在通信密集的 MoE 与长上下文推理上会裂开——GPU 的集合通信假设一种拥塞语义，网卡固件实现另一种，交换机队列再实现第三种。共设计要回答的问题是：这六颗芯片是否从一开始就约定同一套流量模式、同一套安全边界、同一套液冷与供电包络，而不是靠集成商在机柜里「调通」。

只优化 GPU 峰值，CPU 喂不饱、交换过订阅、网卡在 MoE All-to-All 的同步突发里打满、DPU 缺席导致主机被存储中断打断，整柜 MFU 仍然上不去。六芯片是把这些失败模式收进同一代硅，而不是同一代营销口号。

六颗芯片各管哪一层 ​

芯片公开角色主要落点
Rubin GPU训练 / 推理执行HBM4、Transformer Engine、NVFP4
Vera CPU编排、数据搬运、agent 控制Olympus 核、与 GPU 一致性
NVLink 6 SwitchScale-Up 交换72 GPU 全互连、SHARP
ConnectX-9Scale-Out 端点每 GPU 对外注入、拥塞与隔离
BlueField-4基础设施处理器网络 / 存储 / 安全卸载
Spectrum-6Scale-Out 交换共封装光学以太网

表中的带宽与端口数以 NVIDIA 当时产品页为准。本篇只锁定分工，不把某一栏 Tb/s 抄成自己的测量。

「共设计」不是「全部焊在同一块硅上」。六颗仍是六颗封装，靠 NVLink、NVLink-C2C、PCIe 与以太网协议对齐。程序员看见的是 CUDA device、CPU NUMA、RDMA 网卡与 DPU 上的 DOCA 服务。共设计体现在流量与安全语义一致，不是体现在 hid 掉所有设备节点。

方法 ​

规划机柜时按六层同时画，而不是先填满 GPU 再补网。Scale-Up 平面只允许 NVLink 6：TP、域内 EP、域内集合通信走这里。Scale-Out 平面由 ConnectX-9 注入、Spectrum-6 交换：DP、跨柜 PP、多柜 MoE、存储。控制与安全平面落到 BlueField-4，避免租户作业与基础设施抢同一颗 Vera 核。CPU–GPU 平面走 NVLink-C2C，把 LPDDR 与 HBM 收成一致性视图，供 KV 卸载与数据预置。

软件栈按这个切分来绑进程：训练作业的 NCCL 通信子不要跨越 NVLink 域；存储与遥测走 DPU；柜外拥塞控制交给 SuperNIC 与 Spectrum-X，而不是在应用里重写一套公平队列。CUDA 向后兼容被 NVIDIA 写成平台约束：已有核不必为第六代互连重写，但要吃到 SHARP 与 counted writes，仍需通信库与框架版本跟上。

端点、交换与卸载为什么要三颗网侧芯片 ​

把「网络」写成一颗芯片会混掉三件不同的事。交换（Spectrum-6）决定柜外拓扑与共封装光学；端点（ConnectX-9）决定每个 GPU 如何把突发注入网络，并做租户隔离；DPU（BlueField-4）决定这些注入是否消耗主机核。NVIDIA 公开把 BlueField-4 写成 64 核 Grace 加集成 ConnectX-9，带宽相对上一代翻倍——这些是产品规格，用来理解「基础设施有自己的处理器」，不是本博客的测试。缺任意一颗，剩下两颗都会被错用：没有端点整形，交换再快也要吃同步突发；没有 DPU，Vera 核会被 NVMe 与加密拖成编排瓶颈。

机制 ​

共设计的机制是接口先行。GPU 的 NVLink 端口速率与交换芯片的端口匹配，才有「每 GPU 3.6 TB/s 卡间」这一公开规格，见 NVLink 6。CPU 的 C2C 端口与 GPU 匹配，才有超芯上的一致性。ConnectX-9 与 Spectrum-6 共用面向 AI 突发的拥塞控制，而不是把数据中心以太网的 ECN 参数直接套到 MoE All-to-All 上。BlueField 上的 DOCA 服务与主机 CUDA 作业分域，安全边界不依赖「租户承诺不碰管理面」。

液冷、托盘、电源平滑属于同一共设计的封装层。芯片再快，若供电包络按平均功率设计、峰值把机柜拉闸，六颗硅的峰值表都没有意义。NVIDIA 把功率平滑与温水液冷写成平台特性；具体千瓦与摄氏度以产品页为准，本篇不外推。

六芯片里没有单独的「HBM 芯片」或「光模块芯片」叶子：HBM4 叠在 GPU 封装上，共封装光学叠在 Spectrum-6 上。讨论带宽时要说清是 HBM 屋顶线、NVLink 屋顶线还是以太网屋顶线，三张表不能加减成一张。

第七颗芯片不改六颗的拓扑 ​

Groq 3 LPU 被写成低延迟 decode 加速，与 NVL72 的 GPU 域并列部署，而不是把 72 GPU 换成 72 LPU。知识树后续叶子会写 LPX 机柜。共设计的教训不变：加速卡若只通过 PCIe 挂上、不参与 NVLink 域，它就不是这块机柜加速器的一部分，只是柜外的异构加速器。不要把 LPU 的片上 SRAM 带宽与 NVLink 6 的卡间带宽加在同一行比较。

边界与工程取舍 ​

不要在非 NVIDIA 机柜上假设这六颗的拓扑可替换：昇腾超节点、AMD 平台各有自己的 CPU / 交换 / 网卡组合，只能类比「计算 + 编排 + Scale-Up + Scale-Out + 卸载」，不能抄 36+72 或 SuperNIC 配比。不要把六芯片写成必须自研全部硅才能训练大模型——租用已集成的 NVL72 仍是这套设计的消费方式。

采购上拒绝「GPU 一代、网络上一代」的混搭，除非测量证明柜外不是瓶颈。混搭最常见的失败是：Rubin 的域内 EP 很快，柜外仍是上一代网卡，DP 与检查点变成新的墙。软件上也不要把 DPU 当普通网卡用掉，那是在浪费卸载核，并把安全面交回主机。

小结 ​

  • Vera Rubin 平台的公开共设计是六芯片：GPU / CPU / NVLink 交换 / SuperNIC / DPU / 以太网交换。
  • Scale-Up、Scale-Out、控制面分属不同芯片，混用平面等于买错屋顶线。
  • 端点、交换、卸载是三件网侧的事，不能收成「有一张网卡就够」。
  • 第七芯片（LPU）是后补推理路径，不改变 NVL72 六芯片拓扑。
  • 非 NVIDIA 超节点只可类比分层，不可抄配比与速率。
  • 出处：NVIDIA Vera Rubin 六芯片技术博客；机柜形态见 NVL72。
