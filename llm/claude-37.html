Claude 3.7 / extended thinking ​

同一模型既可以近乎即时作答，也可以先进行对用户可见的逐步思考；API 用思考预算控制想多久。延长思考不是换另一个模型。

—— Anthropic，Claude 3.7 Sonnet and Claude Code（2025-02-24）；Claude's extended thinking

2025 年 2 月 24 日 Anthropic 发布 Claude 3.7 Sonnet，自称当时市场上第一个混合推理模型：标准模式是 3.5 Sonnet 的升级；extended thinking 模式下先写出一长段可展示的思维 token，再给最终答案。用户在产品里开关；开发者在 Messages API 里设 thinking.type: "enabled" 与 budget_tokens。价格与前代中档相同：输入 $3 / 百万、输出 $15 / 百万，思维 token 按输出计费。免费档无延长思考；Pro/Team/Enterprise 与 API、Bedrock、Vertex 提供。同期发布 Claude Code 终端编码智能体。系统卡覆盖计算机使用、提示注入、以及「思维是否可信」。本篇只写发布博文、extended thinking 研究说明与系统卡口径，不编参数量、不把后续 4.x 的 adaptive thinking 倒填进来。

问题 ​

o 系列把「总是先想」做成默认，延迟与费用在简单题上浪费；普通 LLM 在竞赛数学与难编码上又想得不够。Anthropic 要把两种行为放进同一套权重：简单题走标准前向，难题加串行测试时计算。研究博文把延长思考写成 serial test-time compute——准确率随允许的思维 token 大致对数上升（例如数学题）。并行测试时计算（同时多条思维再汇总）在研究里有效，未进入这次部署的模型。

可见性是第二条产品问题。隐藏链无法审计；完全展示又可能泄漏不安全的中间计划。3.7 选择对用户可见的思考，并在系统卡里问：这些文字是否真是决策依据，还是事后合理化。计算机使用在 3.5 测试版之后成为默认风险面：思维里若规划点击序列，注入攻击的载荷可以写进「想法」。

预算是硬上限，不是温度 ​

budget_tokens 限制思考段最多写多长，与 max_tokens 的最终答案上限分开。预算过小，难题退回标准模式的智能；预算过大，账单按 $15/百万输出线性涨，且可能出现重复推理。官方称两种模式下提示方式大体相同，不必为 thinking 重写全部提示词。这与「另起一个 o 模型名」的产品策略不同：名称仍是 3.7 Sonnet，模式是请求参数。

研究博文举过内部 QA：给另一份 Claude 当评委等设置，用来论证加思维能抬分。那些数字是 Anthropic 自有协议，不能直接当公开榜。SWE-bench 等外部表以当时系统卡/博文表格为准，并声明是否启用 thinking 以及脚手架。

方法 ​

训练：系统卡写延长思考经强化学习得到，使模型在需要大量推理的问题上愿意花更多时间。这与 o3 的「链上 RL」同类，但公开材料没有给算法名（PPO/GRPO 等）或是否过程奖励。标准模式与思考模式共享权重，开关不是加载另一检查点——研究文明确否认「换一个带单独策略的模型」。

评测：系统卡对多个快照（含预览候选与最终发布）在标准/思考两种模式下重复测，优先覆盖更接近发布候选的版本。内容包括能力、拒答、计算机使用、注入、以及思维可靠性。计算机使用的注入：页面或截图里的恶意指令 vs 用户目标，模型是否在思考中采纳。部署面：所有付费 Claude 方案；免费仅标准模式。输出长度在思考开启时可到很大（第三方文档常写 128K 级上限，以当时 API 文档为准）。

Claude Code 是围绕该模型的终端智能体产品，能多步改仓库；它不是模型卡里的新注意力，而是工具环 + 3.7 的编码与思考。不要把 Claude Code 的演示成功率写成 3.7 的零样本 HumanEval。

对数增益与任务可核对性 ​

思维 token 增加时，数学一类可核对任务最容易出现平滑增益，因为中间检查有真假。开放写作上加长思考可能只是更啰嗦。官方「对数」描述针对他们画过的数学曲线，不要推广成一切任务的定律。并行采样多条 thinking 再选，属于研究中的 test-time 集成，3.7 上线形态是单条串行链。

机制 ​

混合推理的机制是可变计算图：标准模式近似普通解码；思考模式先在专用块里自回归出「草稿纸」，再条件于这些 token 写答案。草稿纸占用上下文，真正留给题目与工具返回的窗口变小——200K 级窗口在长思考时会被思维挤占。计费把草稿纸算输出，是因为它们确实被生成并通常被返回。

「同一模型」意味着无需另做路由分类器选 o 或非 o；用户或客户端用开关当路由。模型若在标准模式下就写得很长，开关的边际变小。强化学习让模型学会在难题上用满预算、在简单题上早停——校准不好就会出现「简单题仍写两千 token」或「难题预算用尽仍空」。系统卡关心思维是否可信：若思维写「我应拒答」而答案却执行了注入指令，可见性会误导审计。

后续 Claude 4.6+ 文档把 budget_tokens 标为将弃用，改 adaptive thinking。那是另一代 API。写 3.7 时机制就是显式预算的 extended thinking。不要用 4.x 的 effort 字段解释 2025-02 的请求。

与 o 系列、与 3.5 computer use ​

o3 默认总是推理模型，工具在链内；3.7 让用户选是否推理，计算机使用继承 3.5 的截图-动作工具。3.7 系统卡把注入与 computer use 写得更重，因为思考块提供了额外的攻击表面（恶意内容可以出现在「想法」里再被执行）。deliberative alignment 是 OpenAI 的词；Anthropic 用可见思考 + 政策与红队。不要混用两家术语冒充同一算法。

边界与工程取舍 ​

无参数、无 RL 配方、无确认内部搜索树。免费档无 thinking，产品评测若含免费用户，不能代表 3.7 的推理档。思维展示策略（完整、摘要、可关闭）以客户端为准。价格 $3/$15 含思维，长思考任务的账单可以远超标准模式。上下文 200K 仍是这一代的默认叙事；不要写成 1M。

把 3.7 写成「Claude 的 o1」只在「可花更多测试时计算」这一层成立；混合开关、可见链、同一价目表是差异。编码智能体成绩必须拆开：模型、Claude Code 脚手架、是否 thinking、步数上限。系统卡对「思维可信度」持研究态度，不是宣称链上每句都是因果解释。

出处：Anthropic，Claude 3.7 Sonnet and Claude Code（2025-02-24）；Claude's extended thinking；Claude 3.7 Sonnet 系统卡 PDF。参数量未公开。

小结 ​

  • 3.7 Sonnet 是同一权重上的混合模型：标准作答或 extended thinking。
  • API 用 budget_tokens 限制思维长度；思维按输出计费；$3/$15。
  • 串行测试时计算；准确率在官方数学曲线上随思维 token 近似对数升。并行思考未部署。
  • 系统卡覆盖注入、computer use 与思维可信度；ASL 叙事以卡片为准。
  • 出处：上述 Anthropic 博文与系统卡。不编参数量。
