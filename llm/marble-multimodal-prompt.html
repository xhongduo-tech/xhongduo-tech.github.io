多模态提示到三维世界（文/图/视频/布局） ​

Marble 能从文本、图像、视频或粗三维布局创建三维世界，并允许交互编辑、扩展与组合。

—— World Labs，Marble: A Multimodal World Model

人用多种感官与语言建立对外界的心理模型。World Labs 把同一原则写进 Marble：能拿到什么信号，就把什么信号抬成完整三维世界，而不是只提供一种「文生视频再截帧」的入口。当前产品把提示分成文本、图像、视频、粗布局（以及全景、多图等变体），输出则是可漫游、可导出的世界。本篇只写提示侧：四种输入各自约束了什么、模型必须发明什么，以及为何「多模态」在这里不是把图片贴进提示词那么简单。

问题 ​

单一模态会把创作自由度与可重复性绑死。纯文本最省事，也最不可控：模型必须发明布局、尺度、家具件数和没写出来的风格细节，两次生成可以是两个房间。单图把一个视锥钉死，背面与侧向仍全是发明。视频与多图提供了时间或角度上的额外测量，但若系统仍当它们是「更长的文本描述」，空间关系会被扁平化。粗布局相反：结构清楚、外观空虚，没有风格通道就会得到正确的方盒子和错误的材质。

多模态世界模型要解决的是：把不同缺口的输入登记到同一三维对象上。文本缺几何、图缺未见侧面、视频缺显式网格、布局缺外观。登记失败的典型症状是「按图的那一面很像、转过九十度像另一个地方」，或「按布局的墙对了、但提示里的木头地板变成了大理石」。提示工程在二维扩散里已经难；在三维里，未写明的自由度会变成真实的墙和门，代价更高。

输入决定合同 ​

每种提示对应一份合同。文本合同：符合描述，允许发明。图像合同：所见视锥应像该图，其余允许补全。视频合同：序列中出现的内容应能在一个空间里对上，而不是做成幻灯片拼贴。布局合同：粗形状的尺度与邻接应保住，风格由附加文本或参考外观来填。混用合同时必须写清谁优先：布局与文本冲突时，Chisel 类工作流选择结构听几何、风格听文字——那是后文的编辑器，本篇只把布局列为一种提示模态。

全景是图像的一种强约束特例：水平一周的观测已经很多，系统更接近重建而非纯生成。产品上全景通常不能与其它图或视频随便混在同一条提示里，属于输入互斥，不是「再多贴几张更准」。

方法 ​

记提示为多源集合 \(\mathcal{P}=\{p_{\mathrm{txt}}, p_{\mathrm{img}}, p_{\mathrm{vid}}, p_{\mathrm{lay}}\}\)，其中若干项可空。生成器输出世界 \(W\)，使得每类非空提示都有对应的符合度：

\[W^\ast=\arg\min_W \sum_{m} \lambda_m \, d_m(W, p_m). \]

\(d_{\mathrm{txt}}\) 是语义与风格距离，\(d_{\mathrm{img}}\) 是已见图的重投影误差，\(d_{\mathrm{vid}}\) 是多帧之间的时空一致，\(d_{\mathrm{lay}}\) 是粗几何的占据对齐。\(\lambda_m\) 由产品在不同模式里写死：纯文本时只有第一项；单图时图像项权重大、文本可作可选说明；布局模式把几何项抬到最高。

文本与单图：最快的入口 ​

文本适合概念和风格探索。短句会迫使模型用训练先验填满房间，这是「魔法」也是不可复现的来源。单图适合与其它二维工具衔接：先用图像模型迭代构图，再抬到三维。二者共同的缺口是未见区域。World Labs 写明：文本或单图里没有的细节必须由 Marble 发明。用户若把发明当成测量，后续会在数字孪生里踩坑。

视频与布局：分别钉时间与结构 ​

视频把同一场所的多时刻、多角度送进去，提示从「一张明信片」变成「一段观察」。它仍可能是生成：镜头没扫到的储藏室会被补上。粗布局（盒子、平面、导入的简单资产）钉的是结构：墙在哪、房间多大，外观交给文本。四种模态不是精度阶梯上的四级，而是正交的约束轴：语义、外观快照、时空观测、尺度邻接。

API 与文档把类型写成 text、image、video、multi-image、布局类输入等。本篇用「文/图/视频/布局」概括产品叙事；多图拼接是图模态的多视图加强，专论见下一篇，这里只把它视为图像合同的延伸。

机制 ​

多模态成立，依赖于不同信号被抬到同一空间上下文，而不是先各自生成二维再手工对齐。图像与视频应带着「这是某个视点的投影」进入模型；布局应带着「这是世界坐标里的占据」进入模型；文本应约束外观与物体类别，而不是偷偷改墙的位置（在布局模式下）。若所有模态都先被写成一段英文提示再送进文生图，三维一致性就退化成运气。

权重 \(\lambda_m\) 的实践含义是冲突裁决。用户给一张现代客厅照片，又写「巴洛克宫殿」，图像合同与文本合同打架。产品若允许 recaption，文本可能被改写成更贴图的句子；若关闭 recaption，则按字面文本拉风格，图的语义可能让步。布局加文本是刻意解耦：几何通道不读形容词，形容词通道不搬墙。理解机制时要问：这次生成，哪一条通道有权改结构。

迭代更新而不是一次提示 ​

世界模型还应在新信息到达时更新理解。产品侧体现为：先文生一个世界，再换成图去编辑；或先布局再改文本重生风格。这与聊天里追加一句不同——追加的是对同一 \(W\) 的新约束，应尽量少破坏已满足的旧约束。做不到时，用户会感到「越改越不是刚才那个房间」。多模态不是输入格式清单，而是约束的可追加性。

可选文本在视频或图像模式下常常自动生成说明。自动说明是另一条文本通道，可能把用户没说的物体写进去。关闭 recaption 是为了让 \(d_{\mathrm{txt}}\) 只对用户原句负责。

边界与工程取舍 ​

多模态不表示任意组合都合法。全景与多图、视频的互斥，流式大小与格式限制，都是工程边界。布局作为提示，粒度止于粗几何：它不是 BIM，也不是可施工图纸。视频不是免费的完美重建：运动模糊、曝光变化、纯旋转镜头都会让时空项 \(d_{\mathrm{vid}}\) 变吵。文本越短，生成项越主导，越不适合当测量。

也不要把「能输入视频」理解成产品已是视频扩散。Marble 的输出主对象是三维世界，视频只是输入之一，以及事后从世界再渲出的分享介质。用视频模型的镜头语言去写 Marble 提示，会低估空间约束、高估剪辑。反过来，用摄影测量软件的控制点精度去要求单图文生世界，会低估生成合同里的合法发明。

模态增多会提高失败的诊断成本。坏结果时要先问：是文本在挪墙，是图在锁死错误透视，是视频各帧不在同一空间，还是布局尺度以米为单位却被当成了道具尺寸。没有分通道的错误归属，用户只会反复改那句形容词。本篇停在提示合同；具体的多图方位、Chisel 操作、扩展与拼接，各自是独立的一件事。

小结 ​

  • Marble 的提示可以是文本、图像、视频或粗布局，目标是同一份三维世界，不是四套生成器。
  • 各模态钉不同缺口：语义风格、视锥外观、时空观测、结构尺度。
  • 未见区域由生成补全；不要把补全写成扫描。
  • 冲突由模式权重与是否 recaption 裁决；布局加文本是结构与风格解耦的特例。
  • 并非任意模态都可在一条提示里堆叠，产品有互斥与格式边界。
  • 出处：World Labs，Marble: A Multimodal World Model；Marble 产品文档与 API 中的提示类型说明。
