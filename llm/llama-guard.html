Llama Guard / 安全分类器 ​

把政策写成一套可生成的类别标签，用指令微调后的模型对输入或输出做安全分类：它不替代对话模型的对齐，而是在旁边加一道可独立更新的门。

—— Inan et al., Llama Guard: LLM-based Input-Output Safeguard for Human-AI Conversations, 2023

Inan 等人把内容审核从「另一个与生成模型缠在一起的拒答头」里拆出来：Llama Guard 是一个专门微调的分类器，吃对话片段，吐出是否允许以及命中哪些风险类别。生成模型可以继续追求有用；政策变更时先改分类器与其提示里的分类法（taxonomy），而不必每次重做整套 RLHF。本篇写分类器扮演的角色、输入/输出两道门、类别体系与评测；不把分类器提示写成可绕过的对照表，也不给越狱样本。

问题 ​

只靠对话模型自己拒绝，有三处不稳。政策与有用性在同一交叉熵里打架，见安全 SFT 比例；越狱改变的是生成模型的条件，不一定同时骗过一个另训的分类器；产品需要审计：哪一条政策被触发、该拦输入还是拦输出。传统关键词与线性分类器对改写、代码、多轮指代很脆。需要一种能读自然语言对话、输出结构化判定、并且比生成模型更小、更好更的组件。

Llama Guard 的设定是：分类器本身也是因果语言模型，但解码目标不是回答用户，而是生成类似 safe / unsafe 加上类别代码的短序列。这样可以复用指令微调配方，把政策写进分类器的系统说明，用标注对话做监督。

输入门与输出门不是同一任务 ​

输入分类：用户（及可选的系统、历史）是否在请求不允许的帮助。输出分类：助手即将或已经生成的内容是否本身有害。前者拦的是意图，后者拦的是泄漏。一个只做输入分类的系统，挡不住模型在无害提问下幻觉出危险步骤；一个只做输出分类的系统，会让有害请求消耗完整预填充再在首段被截断。Inan 等人把两者做成同一模型的两种用法：上下文里放不同角色的文本，标签定义略有不同。评测必须分列，不能合成一个「Guard 准确率」。

分类器误报会直接变成产品过拒绝；漏报会变成越狱成功。对话模型的拒答可以被有用性压力下调，分类器的阈值却是显式旋钮。两者一起调，才能画 ROC，而不是各调各的。

方法 ​

Llama Guard 的监督数据按分类法打多标签：暴力、犯罪、自伤、性、枪械、管制品等（具体类名与版本以原文与后续 Llama Guard 2/3 文档为准，本篇不把类别当攻击字典展开）。训练是标准指令 SFT：给定对话片段，生成判定文本。推理时用约束或短解码拿到标签，再映射成放行/拦截。部署上常见模式是：请求进入对话模型前跑输入 Guard；生成结束后（或流式窗口上）跑输出 Guard；拦截时返回固定的安全回复，而不是把分类器的思维链给用户。

后续版本扩大类别、换基座、加强对工具调用与代码的覆盖，但角色没变：独立、可版本化的 LLM 审核器。它与奖励模型不同，见奖励模型：RM 打的是偏好标量，Guard 打的是政策类别。也可以把 Guard 的负类当 RL 的惩罚项，但那是集成，不是 Guard 本身的定义。

分类法写进提示，权重写进模型 ​

政策有一部分在分类器的系统提示里（定义每类覆盖什么、什么是允许的讨论），一部分在微调权重里。只改提示、不改权重，能快速试验条款，但对分布外改写的召回有限；只改权重、提示含糊，标注员与模型会对边界类产生漂移。工程上应把分类法版本、提示版本、权重版本绑在一起发版，评测集也按版本切。对多模态输入，纯文本 Guard 必须先有看图模块，否则见多模态越狱。

机制 ​

机制是条件生成被训成分类。短目标序列使校准相对容易：可以读 unsafe 的对数概率当分数，而不是对长回答做语义聚类。因为基座是语言模型，改写、指代、多轮里「把刚才那个做出来」这类省略，比词表黑名单更扛。但也因此继承语言模型的弱点：长上下文稀释、many-shot 伪历史可能把分类器也推向「这是在继续任务」、对抗后缀可能同时转移，见 GCG。所以 Guard 不是不可攻击的根证书，它是另一道、最好与生成模型异构的关卡：不同基座、不同对齐数据、不同解码长度。

输入侧 Guard 看到的是用户句，对预填充 造成的助手开场无直接视野，必须靠输出侧。输出侧 Guard 若与生成模型同族且共享 tokenizer，转移风险更高。异构（例如生成用大模型、Guard 用另一家族的小模型）是有意的归纳偏置。

把 Guard 的完整政策提示打印给最终用户，等于把分类边界交给红队。对用户只给通用拒答；对内部审计保留类别代码。

防御评测：阈值、延迟、异构 ​

报告精确率/召回或 ROC 时，必须按类别与按「输入 vs 输出」切开，并单列过拒绝集（合法医疗、新闻、安全研究、虚构作品）。对抗评测用 HarmBench 等协议，见 WildGuard / HarmBench，比较：无 Guard、仅输入、仅输出、双门。延迟上，Guard 是一次短生成，应与主模型并行或在小卡上跑；把它同步放在 prefill 前会叠加 TTFT。校准：用概率阈值而不是贪心解码一个词，以便在召回与过拒绝之间滑点。与宪法分类器 相比，Llama Guard 更依赖固定分类法与对话标注；宪法路线用自然语言条款合成数据，政策迭代更快，但合成偏差要另测。

边界与工程取舍 ​

Guard 不能修复生成模型在被放行区域内的幻觉与偏见；它只执行分类法里写过的危害类型。分类法滞后于新风险（新型诈骗话术、新型工具调用）时，漏报是预期行为，需要数据飞轮而不是更大的生成模型。对代码与工具，标签定义必须区分「讨论漏洞机理」与「提供可执行危害步骤」——这是政策问题，分类器只是执行。开源 Guard 权重让攻击者可以本地优化对抗输入；缓解是经常更新、异构集成、以及对 Guard 自身做对抗训练，而不是指望权重保密。

不要用 Guard 替代表示级防御。GCG 与 many-shot 都可以既骗生成又骗同族分类器；Circuit Breaker 改的是生成模型内部，Guard 改的是暴露面。生产上两者叠用，评测上分别消融。本篇不列出可用于对照测试的有害提示。

「safe」不是道德证明，只是「未命中当前分类法」。换一版分类法，昨天的 safe 可能变 unsafe。日志应存分类法版本，否则事后审计对不上。

小结 ​

  • Llama Guard 是 LLM 形式的输入/输出安全分类器，输出允许与否及风险类别，与对话模型解耦。
  • 输入门拦意图，输出门拦泄漏；评测与部署都必须分列。
  • 分类法、提示、权重应版本绑定；政策迭代优先改 Guard，而不是每次重训对话模型。
  • 它仍是语言模型，会受长上下文、对抗后缀与同族转移影响，故宜异构、宜双门。
  • 用阈值滑点同时看召回与过拒绝；延迟计入 TTFT 预算。
  • 不替代表示干预或生成模型对齐，只增加一道可审计的门。
  • 出处：Inan et al., Llama Guard: LLM-based Input-Output Safeguard for Human-AI Conversations, 2023；后续版本见 Meta 发布说明。
