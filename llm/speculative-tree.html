树状验证 ​

把多条候选写成一棵 token 树，用一次带树状掩码的目标前向并行校验所有分支，而不是只赌一条链。

—— Miao et al., SpecInfer: Accelerating Generative Large Language Model Serving with Tree-based Speculative Inference and Verification, ASPLOS 2024

链式投机每轮只提议一条长度为 \(\gamma\) 的路径。草稿在高熵位置一旦猜错，该位置右侧全部作废，一轮往往只收下几个 token。Miao 等人的 SpecInfer 把提议从链改成树：在不确定的位置保留多个子节点，用树状注意力让目标模型一次前向打出每个节点的条件分布，再按保持 \(p\) 的规则沿树接受。Chen 等人 2023 年的投机采样仍是链；树是 Miao / SpecInfer 一线把「多候选」收成可批校验的结构。本篇写树比链多了什么、掩码怎么构造、接受规则如何仍无损。

问题 ​

草稿 \(q\) 在位置 \(t\) 的质量往往不够尖：正确的 \(p\)-token 排在前 3、前 5，但不排第一。链式方法只提交 argmax 或一条样本，命中率被 top-1 绑死。若串行提交 \(k\) 条独立链，目标要校验 \(k\) 次，或把 \(k\) 条 pad 成批但共享前缀的计算重复做。需要一种结构：共享已确定的前缀计算，在分歧点展开兄弟，一次前向覆盖整棵候选。

树还改变失败模式。链的拒绝是「这一点之后全没了」。树的拒绝是「这个子树没了」，兄弟子树仍可能被同一轮校验救回。高熵位置正是链最容易断的地方，也是分支最值得买的地方。问题变成：树有多宽、多深、如何采样子节点，以及目标注意力如何只让每个节点看见自己的祖先。

链是树的退化 ​

一条链是每个节点恰好一个孩子的树。SpecInfer 的一般对象是 token 树：根为已接受前缀的最后一个 token，每条从根到叶的路径是一条候选续写。节点数 \(N\) 代替链的 \(\gamma\)，目标一次前向的序列长与 \(N\) 同阶（加上前缀）。\(N\) 受显存与算力墙约束：decode 从带宽墙走进算力墙之后，再加兄弟会让 \(c_p(N)\) 明显变大，加速比回头跌破 1。

树状验证不是 beam search。Beam 在目标模型自己的分数上保留多条假设并改写分布；树状投机的候选来自草稿，目标只做校验，接受规则的设计目标是仍采样自 \(p\)，而不是变成 \(p\) 的 beam 解码器。

方法 ​

草稿侧：在需要的节点从 \(q\) 取 top-\(k\) 或无放回样本作为孩子，深度与宽度由预算给出。可以用一个草稿，也可以像 SpecInfer 那样融合多个小投机模型的提议。构造完成后，把树按某种遍历展开成序列，并构造注意力掩码：位置 \(j\) 只能看见从根到 \(j\) 的祖先（以及原始前缀），不能看见兄弟或旁支。这就是树注意力。目标一次前向，每个节点得到 \(p(\cdot\mid \mathrm{ancestors})\)。

一次前向里的掩码 ​

设展开后的索引为 \(1..N\)，父指针 \(\mathrm{parent}(j)\)。掩码 \(M_{j,i}=0\) 当且仅当 \(i\) 是 \(j\) 的祖先或 \(j\) 自身（再并上共享前缀）。缩放点积在加 \(M\) 之后 softmax，值也只从祖先来。实现上它与「带自定义掩码的一次性 prefill」同类，可以走现成的变长注意力核，不必真的递归走树。KV 布局要能索引到树节点；分页块按节点分配，拒绝整棵子树时回收块。

沿树的接受规则 ​

链式拒绝采样要推广到有兄弟的节点。SpecInfer 给出在树上保持目标分布的验证过程：在一个节点，用目标分布审视各孩子，按投机采样的思想决定接受哪一个孩子或在此结束并补采样。关键约束与链相同——不能因为看过兄弟就把 \(p\) 改成「在候选集合上的条件」。错误的实现是：在孩子集合里做 softmax 再选，这会变成在草稿提出的支持上截断的 \(p\)，有损。正确的实现保持「对完整词表的 \(p\)」负责，候选只是提议，未提议到的质量用 residual / 拒绝来补。

若某一支在中途拒绝，校验已经算过的兄弟支仍可继续匹配，这是树相对链的超额收益。最后输出仍是一条路径，加上可能的一个目标侧补 token，而不是把整棵树写给用户。

机制 ​

树提高的是在 \(q\) 的 top-\(k\) 里覆盖 \(p\) 的质量的概率。若 \(p\) 的下一个 token 经常落在 \(q\) 的前 \(k\) 而不在前 1，宽度 \(k\) 直接抬高该层的命中，期望路径长度随深度复利。共享前缀让这 \(k\) 条不是 \(k\) 倍目标步：共同祖先只算一次 QKV。这与批处理里的前缀共享是同一类计算图。

代价是掩码变不规则、序列变长、\(c_p(N)\) 上升，以及草稿要在分支上多跑几步。宽度应集中在高熵层：模板性前几个 token 保持链，遇到 identifer、数字再张开。均匀的完全 \(k\) 叉树很快把 \(N\) 打爆。后续 Sequoia 一类工作用动态规划按硬件预算长树，说明树形本身是超参，不是越大越好。本篇只强调 SpecInfer 把问题定义成树校验；最优树形是下一层系统活。

无损仍然是对 \(p\) 的序列分布。若实现把校验简化成「孩子里谁和目标 argmax 一致就走谁」，温度为 0 时近似成立，温度 \(>0\) 时有损。评测必须钉采样器，不能只在贪心上宣称树状投机无损。

边界与工程取舍 ​

树状核不是所有服务框架的默认路径。没有树掩码时，退回批处理 \(k\) 条链，共享前缀靠 Radix / 前缀缓存间接拿到，但不如一次树前向干净。\(N\) 太大时，一次校验走进算力墙，链式小 \(\gamma\) 反而更快——要按硬件画曲线。多草稿融合增加覆盖，也增加提议延迟与系统复杂度；单草稿 top-\(k\) 往往是先做的 80%。

与连续批的接口：一轮树校验是一个调度原子，中途抢占会丢掉整棵树的计算。KV 池按节点峰值而不是按最终路径计费，规划并发时要用 \(N\) 而不是用输出长度。结构化约束应在长树之前剪掉非法孩子，免得把预算花在目标稍后也会拒绝的边上。

Chen 的投机采样与 Miao 的 SpecInfer 不要写成一篇论文。前者把无损链式投机做到 70B 级语言模型；后者把多候选做成树并给出并行校验。引用树状验证时，主出处是 SpecInfer。

小结 ​

  • 树状验证把草稿的多条候选收成一棵 token 树，目标用树注意力一次校验所有节点。
  • 链是单孩子退化；分支买的是 \(q\) 的 top-\(k\) 覆盖，共享前缀避免 \(k\) 倍目标步。
  • 接受规则必须仍对完整 \(p\) 负责，在孩子集合上截断 softmax 会有损。
  • 节点数 \(N\) 受算力墙限制，宽度应给高熵位置，不是均匀 \(k\) 叉。
  • 调度上整棵树是一个原子，KV 按峰值节点计。
  • 无树核时可退回多链加前缀共享，通常更不整齐。
  • 出处：Miao et al., SpecInfer, ASPLOS 2024。链式原理见 Leviathan et al., ICML 2023；大模型链式验证见 Chen et al., 2023。
