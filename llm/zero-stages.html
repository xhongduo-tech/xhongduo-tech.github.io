ZeRO-1 / 2 / 3 ​

第一刀切优化器状态，第二刀切梯度，第三刀切参数；每一刀换显存，也换一次聚集时序。

—— Rajbhandari 等，ZeRO，DeepSpeed

ZeRO 的三档是同一条分片轴上的三个停靠点，不是三种互不相干的算法。数据并行组有 \(N\) 张卡，参数量为 \(\Phi\)。标准混合精度 Adam 大约 16 字节/参数的复制量，可以拆成：优化器状态约 12 字节（FP32 主权重 \(+m+v\)）、梯度 2、参数 2。ZeRO-1 只把 12 字节按 \(N\) 切开；ZeRO-2 再把梯度切开；ZeRO-3 把参数也切开，前向、反传时按层 All-Gather。DeepSpeed 用这套编号；PyTorch FSDP 对应最接近的是第三档。本篇把每档的内存公式、通信模式和该停的位置写清，不重讲「什么是数据并行」。

问题 ​

只说「ZeRO 省显存」不够用来选档。切得越深，单卡持久状态越接近 \(16\Phi/N\) 字节，但瞬时峰值——某层参数被聚集齐的那一瞬间——以及通信次数，都在涨。小模型上 ZeRO-3 可能比 DDP 慢一截：省掉的内存用不上，每层两次聚集的延迟却是实的。大模型上 ZeRO-1 可能根本放不下梯度。需要一张表：哪一档切掉哪一块，通信从几次集体操作变成几次，峰值显存在公式之外还要加什么。

卸载（offload）是同一条轴的延长：把切开的状态放到 CPU 或 NVMe，GPU 只留正在算的那一层。它不是第四档语义，是第三档的存储层级。混着写「我们用了 ZeRO-3」却不写是否 offload，别人无法估计 step time。

ZeRO-1：只切优化器状态 ​

每张卡仍持有完整 BF16 参数与完整梯度。Adam 的 FP32 主权重、\(m\)、\(v\) 按参数下标切成 \(N\) 片，第 \(r\) 卡只更新第 \(r\) 片。通信仍接近一次对全体梯度的 All-Reduce（或等价的 Reduce-Scatter + 把平均梯度收回）。更新后，各卡需要把新的 BF16 参数片广播出去，使每卡再次持有完整参数——这一步可以与 All-Gather 合并进实现。内存近似：

\[M_1 \approx 2\Phi + 2\Phi + 12\Phi/N \]

字节，分别是参数、梯度、分片后的优化器状态。\(N=8\) 时优化器从 12 降到 1.5，总内存从 16 降到约 5.5 的量级（不计激活）。这是最便宜的一刀：前向代码几乎不用改，没有「用完一层丢掉权重」。

字节数假设梯度以 2 字节存储。有的实现用 FP32 累积梯度，ZeRO-1 的第二项变成 \(4\Phi\)，省内存的效果会被吃掉一块。读公式前先看梯度 dtype。

方法 ​

ZeRO-2 在 1 的基础上对梯度做 Reduce-Scatter：每张卡只留下自己负责的那一片平均梯度，立刻用它更新自己的优化器分片，不整份持有 \(\bar g\)。参数仍完整。内存：

\[M_2 \approx 2\Phi + (2+12)\Phi/N. \]

通信：Reduce-Scatter 梯度 + All-Gather 更新后的参数片。元素计数仍与 All-Reduce 同阶。和 ZeRO-1 相比，省下的是梯度副本；瞬时上，Reduce-Scatter 完成前可能仍有完整梯度缓冲，峰值不等于 \(M_2\) 公式。实现质量决定峰值能不能贴近公式。

ZeRO-3 连参数也分片。每张卡只持久保存 \(\Phi/N\) 的参数。前向到某一层时，All-Gather 该层完整权重，算完（或反传用完）就释放。反传再聚集一次（或与前向缓存折中）。内存：

\[M_3 \approx 16\Phi/N \]

加上「当前层完整参数 + 其梯度 + 激活」的峰值。模型总参数可以远超单卡容量，只要一层加激活放得下。这已经接近模型并行的能力，但切分单位仍是参数下标，数据仍按 batch 切，语义仍是 DP。

ZeRO-2：梯度也不再整份复制 ​

Reduce-Scatter 要求参与者对同一参数的分片约定一致。与流水线叠用时，只有处于同一阶段、持有同一层参数的 DP 组才能做这次 Scatter。ZeRO-2 对「前向不用改」仍然成立，对「反传结束立刻释放梯度」要求优化器步与通信完成的顺序正确。梯度累积（多 microbatch 再更新）时，必须在累积缓冲区上分片，而不是每个 microbatch 持有完整 \(g\) 再累积——否则 ZeRO-2 的内存收益在累积场景里消失。

ZeRO-3：参数按需聚集 ​

FSDP 的 wrapping 粒度就是在选 All-Gather 的单位：整模型一个单位，通信少、峰值高（一次取齐太多权重）；每层一个单位，峰值低、启动次数多。Transformer 块级包裹是常见折中。前向 All-Gather 的权重若留给反传用，省一次通信、多占一截显存，等于用内存换带宽。prefetch 下一层权重可以掩盖延迟，也把峰值再抬一点。这些旋钮都属于第三档，不存在于 ZeRO-1。

机制 ​

三档的通信次数（粗算，忽略分桶）：

  • DDP / ZeRO-1：每步对 \(\Phi\) 量级做一次 All-Reduce 族操作。
  • ZeRO-2：一次 Reduce-Scatter（\(\Phi\)）+ 一次参数 All-Gather（\(\Phi\)）。
  • ZeRO-3：每层前向 All-Gather、反传 All-Gather（或等价），再加梯度 Reduce-Scatter。次数 \(\propto\) 层数 \(\times\) wrap 数。

延迟项与次数成正比，带宽项与体积成正比。大 \(\Phi\)、少层（极宽）更容易带宽受限；深而窄更容易延迟受限。ZeRO-3 在「深而窄、wrap 很细」时，NCCL 启动开销会盖过省下的显存所换来的微批。这是选档的动力学，不是内存公式能读出的。

卸载把 \(12\Phi/N\) 甚至参数片放到 CPU。PCIe 带宽远低于 HBM，必须靠与计算重叠、以及足够大的层计算量来掩盖。小层（RMSNorm、偏置）offload 往往亏；大 GEMM 层才可能打平。NVMe 更慢，只适合极端放不下、能接受 step time 翻倍的实验。Rajbhandari 等人后续的 ZeRO-Infinity 讨论过这条存储层级，工程上把它当成第三档加卸载，而不是新的并行维。

ZeRO-3 的 All-Gather 得到的是「逻辑完整层」，不是张量并行意义下的完整层。若同时还开了 TP，聚集的是当前 TP 分片所需要的那一块。两套分片下标同时存在，检查点格式必须同时记录 DP 片与 TP 片。

卸载与通信的下一档 ​

CPU 卸载优化器状态，对 ZeRO-1 就有意义：GPU 只留参数、梯度、当前计算。更新时把 \(m,v\) 流过 GPU 或在 CPU 上做 Adam（CPU Adam 慢，但 \(N\) 大时每卡只更新 \(\Phi/N\)，有时划算）。参数卸载则几乎总伴随 ZeRO-3：GPU 连完整层都只是过客。调试时应能一键关掉卸载并缩小模型，确认数值与 GPU 常驻一致。浮点路径在 CPU Adam 与 GPU Adam 之间并不保证比特一致。

边界与工程取舍 ​

不要在单卡已经放得下 DDP 全套状态时默认开 ZeRO-3。先 ZeRO-1，显存仍紧再 2，单层仍放不下或激活需要更多空间再 3。激活才是长上下文的大头；ZeRO 切的是参数侧，序列并行 / 重计算切的是激活侧。两者要一起看，不能用第三档去补序列长度。

与梯度裁剪：全局范数必须在分片上做 All-Reduce 得到 \(\|g\|_2\)，再各自按同一系数缩放自己那一片。漏掉这次归约，等效阈值随 \(N\) 漂。与混合精度：Gather 来的权重要么是 BF16，要么是 FP8 再转，amax 统计的归属要与分片一致。

FSDP 的 FULL_SHARD 接近 ZeRO-3，SHARD_GRAD_OP 接近 ZeRO-2，NO_SHARD 接近 DDP。名字不同，切的对象同一张表。写报告时最好同时写 DeepSpeed 档位与「切了状态 / 梯度 / 参数」三句话，避免跨框架对不上。

检查点：ZeRO-3 默认每卡一份分片。要导出完整 HF 权重，必须做一次聚集，需要短暂的巨大 CPU 或 GPU 内存。训练中途做完整聚集可能 OOM，应在专门的导出作业里做。卡数从 \(N\) 改到 \(N'\) 不是改个配置就能 resume，需要按新 \(N'\) 重切。

小结 ​

  • ZeRO-1 切 Adam 状态，前向几乎不改，内存约 \(4\Phi+12\Phi/N\)。
  • ZeRO-2 再切梯度，通信改为 Reduce-Scatter + 参数 All-Gather，同阶体积。
  • ZeRO-3 再切参数，按层 All-Gather，持久状态约 \(16\Phi/N\)，次数随层数涨，峰值取决于 wrap 与 prefetch。
  • 卸载是第三档的存储层级，不是新语义；PCIe 掩盖取决于层 FLOPs。
  • 选档看「哪一块显存先爆」和「通信次数能否被计算盖住」，不是看模型参数口号。
  • 出处：Rajbhandari 等，ZeRO（DeepSpeed）；后续 ZeRO-Offload / ZeRO-Infinity 讨论存储层级；PyTorch FSDP 为近亲接口。
