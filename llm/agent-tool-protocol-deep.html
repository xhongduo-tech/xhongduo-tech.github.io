工具协议深钻 ​

工具描述不是文档，是提示词的一部分；schema 里每一次措辞修改，都是一次条件分布的移动。

—— 据 Schick et al., Toolformer, NeurIPS 2023；Anthropic，Model Context Protocol 规范（2024）整理

上一课把循环立成五根轴，其中「模型选动作」这一环在本课下钻：动作不是自由文本，是走协议的事件。主干已有 function calling 的信封格式与 MCP 的宿主—服务器生态；本课把协议当成接口契约来审——schema 即提示、回填即合同、错误通道即自纠的原料。训练侧怎么让模型学会这套协议（Function calling 训练、工具 schema 训练）只引用不重讲。

问题 ​

模型看到工具定义后才决定调不调、怎么调，所以 schema 的每一行都直接进入条件分布。schema（模式）就是给参数立的规矩：字段叫什么、什么类型、哪些必填哪些可选——像快递下单表单，收件人、电话、地址一栏一格，格式定死了才不会把「电话」填进「地址」。工具 schema 就是给模型看的这张表单。第一类失败是描述漂移：文档说参数可选，实现却必填；描述写得像开发者备注，模型按字面理解就传错。第二类是清单膨胀：把几十个工具静态写进每次请求，上下文被说明书占满，真正相关的用法描述反而被稀释——Gorilla 的结论之一就是让模型按需检索文档，而不是全量背下 API。第三类是回填混乱：同一轮并行发起多个调用时，结果必须按调用 ID 各自配对；错配之后模型把 A 的输出当成 B 的观察，后续推理整条链被污染。第四类是大结果：一次读取返回几千行，全文回填会挤占轨迹预算（处置策略是上下文管理策略的主题，协议层先要留出「落盘给句柄」的表达）。

方法 ​

协议分四层来抠。schema 层：命名空间防冲突（同义工具来自不同服务器时必须可区分）；描述写成给新同事的操作手册——何时用、何时不该用、参数举例；能用枚举就不用自由字符串，能少一个参数就少一个。枚举（enum）就是把参数限制成固定几个选项。数字实例：参数「城市」若不限枚举，模型可能传「上海」「魔都」「Shanghai」三种写法；写成枚举 [「北京」,「上海」,「广州」]，第四种写法在解码层就根本出不来，这类参数错误被整类消灭。信封层：调用与结果按 ID 严格配对，并行调用各自独立回填；结构化参数用 JSON / 结构化输出的约束通道在解码层保证合法，而不是靠模型自觉。结果层：成功结果回填数据，失败结果回填错误原文——stderr、校验消息、HTTP 状态码原样给模型，让它有机会修正参数重试；重试设上限，防振荡。治理层：schema 变更是破坏性变更，走灰度；权限随工具走，MCP 协议设计按服务器隔离鉴权是这层的基础。

机制 ​

为什么错误回喂是控制信号：参数校验失败时，把「哪个字段、违反了什么约束」的原文还给模型，等价于给了一次有方向的文本梯度——模型下一轮的修正是条件化的，不是再掷一次骰子。「文本梯度」是类比：训练时梯度告诉参数往哪个方向调；把「city 字段拼写不合法，应为拼音」这样的错误原文回给模型，等于告诉它下一轮往哪个方向修——比只回一句「调用失败」让它盲试要省好几轮。这与 Toolformer 的教训同源：模型能自学调用，但自学出来的格式必须被协议固定，否则每次采样的表面形式都在漂。回填错配则是配对机制的意义所在：并行调用共享一轮对话，唯一能把「哪个结果属于哪个请求」钉死的就是调用 ID；这层出错的排障代价远高于省掉它的便利。

幂等性是协议层对重试的授权：查询类工具天然可重试，写入类工具必须有幂等键，否则「错误原文回喂后重试」会把一次失败放大成两次下单。工具描述里应写明幂等语义。

边界 ​

执行在哪里跑、能碰什么文件与网络，是沙箱问题（工具沙箱），本课只管「执行前后事件如何交换」。跨组织的代理互调不是工具协议而是服务协议（A2A 协议），发现与信任模型不同。工具数量大到单清单装不下时，动态发现与按需加载涉及检索与权限，围栏视角在安全围栏补全。schema 的措辞优化没有终点：它是对条件分布的持续调参，必须与提示一起进版本管理——这条约定在回归测试与版本回滚兑现。

小结 ​

  • schema 即提示：描述的措辞直接改调用分布，改 schema 就是改模型行为。
  • 调用与结果按 ID 严格配对；并行调用错配会污染整条推理链。
  • 失败要回喂错误原文并设重试上限；回喂是方向性信号，无上限是振荡。
  • 大结果落盘给句柄，回填句柄不回填全文。
  • schema 变更走破坏性变更流程，权限按服务器隔离。
  • 出处：据 Schick et al., Toolformer, NeurIPS 2023 与 Anthropic MCP 规范（2024）的协议口径整理。
