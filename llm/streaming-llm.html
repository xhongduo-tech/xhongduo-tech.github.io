StreamingLLM ​

不必为了流式生成去重训模型；把注意力汇点留在缓存里，再拼上最近窗口，就可以在常数显存上一直写下去。

—— Xiao 等，Efficient Streaming Language Models with Attention Sinks，2023

Attention Sink 一篇只讲现象：softmax 把质量沉到最初几个标记，滑窗一旦切掉它们，窗口内权重失真。Xiao 等人 2023 年的 StreamingLLM 把现象收成一套推理配方，并在语言建模与流式生成上证明：不微调、不恢复全历史，也能让已训好的稠密注意力模型在「任意长」的生成中保持稳定的困惑度。本篇写这套配方与它的产品边界，汇点机制不重复展开。

问题 ​

服务端希望对话和长生成的 KV 不随 \(t\) 线性膨胀。滑动窗口 把可见集裁成最近 \(w\) 个，缓存是 \(O(w)\)，这正是流式想要的。直接把全注意力训出来的模型改成滑窗推，却会在某个 \(t>w\) 突然胡言——不是因为当前句已经滑出窗口，而是文首汇点被环形缓冲覆盖。Mistral 一类训练即滑窗、且窗口总含起始标记的模型，对这件事不敏感；Llama 一类全注意力预训练、推理想改窗的模型，对它极其敏感。

第二层问题是位置。RoPE 按下标旋转。若缓存里同时放着「逻辑上的 token 0」和「逻辑上的 token \(t-w\)」，实现者容易把它们重排成 \(0,1,\ldots,k+w-1\)。相位全错，等于在汇点之外又引入一场分布偏移。StreamingLLM 要同时回答：留哪些键、键上写什么位置、缓存如何滚动，才能让已有权重在无限长的生成里仍待在训练流形附近。「无限」在这里指生成步数不受 KV 预算截断，不指模型真能检索任意远的事实。文案若写成无限记忆，是把缓存常数和记忆容量混为一谈。

方法 ​

缓存组成：sink ∪ window ​

令汇点长度为 \(k\)（论文常用 4 量级），窗口为 \(w\)。时刻 \(t\) 的可见键集合为

\[\mathcal{C}_t=\{1,\ldots,k\}\cup\{t-w+1,\ldots,t\} \]

（\(t\le k+w\) 时退化为全前缀。）注意力仍是因果 softmax，只是求和范围换成 \(\mathcal{C}_t\)。空间与计算都是 \(O(k+w)\)，与 \(t\) 无关。\(k\) 只承担锚定配分函数的角色，不承担读章节开头的角色，所以不必随任务加到几百。

位置下标跟逻辑位置走 ​

每个 KV 槽保存该 token 被写入时的逻辑下标 \(p\)，RoPE 用 \(p\) 而不是缓存数组里的物理下标。汇点永远是 \(p=0,1,\ldots,k-1\)，窗口槽是最近 \(w\) 个真实 \(p\)。滚动时淘汰的是最老的窗口槽，不是汇点。实现上汇点区与窗口区分成两段环形缓冲，避免一次 memmove 把汇点下标洗掉。

无需微调的接入方式 ​

StreamingLLM 的承诺是零训练：加载原权重，改注意力掩码与 KV 管理即可。评测主轴是滑动窗口语言建模困惑度随 \(t\) 的曲线——朴素滑窗在切掉文首后陡升，sink+window 保持平坦。生成侧则看是否还能续写、是否突然重复。它不是长上下文微调方法，也不与位置插值抢同一张表：PI / YaRN 解决的是「一次前向里 \(L'>L\)」，StreamingLLM 解决的是「前向始终很短，但生成步数可以无限」。

机制 ​

配方有效，是因为训练时每个位置的 softmax 分母里几乎总有汇点那一项大贡献。推理时把该项留住，窗口内内容键的相对比值不变，只是绝对质量被一个近似常数的 \(Z\) 重新归一化。于是局部句法、最近实体、刚写出的括号，仍按训练时的尺度竞争。切掉汇点等价于把所有内容权重乘 \(1/(1-p_{\mathrm{sink}})\)，多头还乘上不同的系数，组合离开训练分布。

与「真正的长记忆」相比，机制刻意放弃了中间历史。位置 \(k+1\) 到 \(t-w\) 的键不在 \(\mathcal{C}_t\) 里，事实一旦滑出窗口就不可读。稳定来自归一化，不是来自压缩。这也解释了为何随机、无语义的初始 token 也能当汇点：要的是稳定的大 logit。把系统提示既当语义前缀又当汇点时，应保证提示的前 \(k\) 个槽不可驱逐；提示很长时，语义前缀和汇点要分开记账，否则会用汇点预算去存整份政策文档。调试时最干净的对照是：同样 \(w\)，一组丢文首，一组强制留前 \(k\) 个 KV。若第二组立刻恢复，问题就是汇点，加长 \(w\) 是错药。

层间差异存在：有的层汇点在 token 0，有的在前几个，有的头几乎不沉。固定 \(k=4\) 是经验折中。若资源允许，可按校准集统计每层注意力质量最高的初始位置，做成每层一张小常驻表，仍保持 \(O(1)\) 缓存。

边界与工程取舍 ​

StreamingLLM 不能替代 128k 预训练，也不能替代检索。用户问「三小时前那张表的数字」，窗口里没有，汇点里也没有。产品上应暴露窗口长度，或在窗口外接检索，而不是暗示模型还记得全文。与分页 KV、前缀缓存共用时，驱逐器必须理解「汇点不可扔」；只按 LRU 会在内存压力下把 BOS 挤掉，故障会以偶发胡言出现，极难复现。

已用滑窗训练且训练掩码总含文首的模型，再叠一套 StreamingLLM 可能重复保留，浪费槽位。应先画注意力图。另一边界是位置外推：若单次提示本身已经超过训练长度 \(L\)，StreamingLLM 不管相位出界——那是 YaRN / 插值的问题。它只保证「可见集很小且含汇点」时与训练时的短上下文同构。

和 LM-Infinite、Self-Extend 的分工：StreamingLLM 优化的是流式 KV 与汇点；后两者还显式改相对距离，为的是一次前向里看见更长的（被压缩或封顶的）历史。需要读长文档，不要只开 StreamingLLM；需要无限轮对话且每轮很短，它往往是最便宜的补丁。

小结 ​

  • StreamingLLM 用常驻汇点加最近窗口，使全注意力预训练模型能在常数 KV 上稳定流式生成。
  • 无需微调；位置必须使用逻辑下标，不能按缓存物理顺序重排。
  • 稳定来自 softmax 分母被锚住，不提供窗口外的事实检索。
  • \(k\) 取很小即可；加大 \(k\) 当记忆用，会挤占窗口且读不完整章。
  • 与训练即滑窗的模型可能重复；与超长单次前向的位置外推是不同问题。
  • 调度、量化、分页淘汰都要把汇点槽标成不可驱逐。
  • 出处：Xiao 等，Efficient Streaming Language Models with Attention Sinks，2023；现象综述见 Attention Sink 一篇，滑窗架构对照 Mistral 7B（2023）。
