训练-评测污染检测 ​

若评测题或其释义已经写进预训练语料，上涨的分数衡量的是记忆与检索，不是你声称的泛化。

—— 训练-评测重叠的方法论共识；公开语料上的实证见 Dodge 等人对 C4 与基准的分析，以及后续模型报告中的 n-gram 审计

数据配方越强，污染越隐蔽。Penedo 的 FineWeb 与 Li 的 DCLM 用下游套件证明过滤有效——若过滤器或网页池已经含 MMLU、GSM8K、HumanEval 的原文或近释义，竞赛排名会奖励「最会挑泄漏」的 \(f\)。Wenzek 的 CCNet 头档像维基，而许多基准正是从维基与网页出题。Soldaini 的 Dolma 公开训练数据，反而使外部可以做重叠审计；闭源混合物只能靠模型侧探测。污染检测要在训练前对语料做，在训练后对模型做，两套证据，不能互相替代。更细的 n-gram 与嵌入近邻实现留给后续专篇；本篇定任务、证据层级与工程位置。

问题 ​

污染不是单一事件。原题全文出现；题干出现、选项另写；释义与翻译；从同一网页模板生成的同类题；基准官方仓库被 Crawl 收进去。Lee 等人已说明训练重复会抬高与训练集重叠的评测项；污染是把「评测项」这个特定子集重复进训练。字面 MinHash 只能抓高 Jaccard 的近重复，抓不住翻译题与改写题。Abbas 的 SemDeDup 可能碰巧删掉一些释义，但它优化的是训练内部冗余，不是对基准的召回，阈值也不为评测服务。

第二问题是标准本身在变脏。基准一旦公开，就会被博客、题解、Chegg 式站点、合成数据工厂复制。2020 年干净的套件，2026 年的 Crawl 头档里可能到处都是。动态基准与题库轮换是下游应对；上游仍必须检测当前冻结套件与当前训练快照的重叠，否则你无法解释这一版模型的分数。

语料审计与成员推断是两种证据 ​

语料审计：在可获得的训练集上对评测文档做 n-gram、哈希、嵌入检索，报告命中率与最长重叠。这是因果上最干净的，前提是数据公开或内部可扫。成员推断：只有模型权重时，用损失、Min-K% Prob 一类分数猜某条评测是否被见过。它有假阳性，不能单独当「无污染」证明。开放配方的隐蔽优势：Dolma / FineWeb 允许第三方复现污染表。只发布模型、声称「我们做了去污」而不给重叠统计，等于不可审计。DCLM 竞赛应强制提交与套件的重叠率，否则过滤领袖板会被泄漏劫持。

翻译与跨语言污染常被漏掉。英语基准的中文译本出现在中文桶，单语 n-gram 为零。必须把评测题译成各训练语言再检索，或用多语言嵌入——与跨语言去重同一工具，阈值改为「宁肯误报」。评测去污的代价是丢掉少量合法网页；训练去重的代价是配比变化。两者阈值不应共用。

方法 ​

训练前：把评测集（含多语言译本、官方示例、常见题解页 URL）建成检索库。对训练文档做：文档级精确哈希；长 n-gram 倒排（如 13-gram，GPT-3 报告用过类似粒度）；MinHash 对整题；嵌入近邻抓释义。命中则整页丢弃或剪重叠跨度。跨度剪更保信息，但实现重，且可能留下「只改了数字的应用题」。对数学与代码基准，规范化（去空白、TeX 规范化、AST 规范化）后再比，否则格式差异造成漏报。

训练后：对每条评测算模型损失或 Min-K% 一类分数，与对照集比较。异常低损且语料审计未覆盖时，标记为可疑，人工看是否公开题解风格。合成预训练特别危险：教师会默写基准，必须对合成桶单独做更严的重叠（Lee 的警告在生成器主动复述时更急）。Canary 字符串用于探测「是否训练了某批数据」，不能代替全量基准审计。

过滤器不得以套件当正例 ​

DCLM-baseline 的正例若含指令数据，而指令数据抄了基准，分类器会提高泄漏页的权重。FineWeb-Edu 的教育分同样可能偏爱「题干+解析」页。质量头的训练与评测套件必须做隔离：正例来源去污，或至少报告正例与套件的重叠。CCNet 的维基 KenLM 会给维基出处的基准题低困惑度，头档富集泄漏。去污应发生在分层之后、训练之前，对各层都跑，而不是只对尾档。

报告「n-gram 重叠低于 x%」而不写 \(n\)、是否规范化、是否含选项、是否含多语言译本，等于没报告。污染统计与 MinHash 去重一样，超参就是定义。

机制 ​

设评测项为 \(x\)，训练分布为 \(p\)。若 \(p(x)\) 或 \(p(\mathrm{para}(x))\) 显著大于自然尾部，NTP 会降低 \(x\) 的损失，评测准确率上升，这部分上升不是能力。检测是在估计 \(p\) 在 \(\{x\}\) 及其邻域上的质量。n-gram 命中估计的是字面邻域；嵌入估计释义邻域；成员推断估计模型内化后的 \(p_\theta(x)\)。三者不一致时，应以语料字面命中为「确定污染」，嵌入命中为「疑似」，仅模型侧为「待查」——因为低损也可能来自简单题或分布内风格，而不是见过原题。

去污改变评测的解释，也轻微改变训练分布。丢掉含题网页，可能丢掉该页其余知识。应优先剪跨度；整页删除留给高密度题库站。污染检测本身会成为配比：对 HumanEval 去污会少掉一些 GitHub gist，代码能力的真实部分与泄漏部分同时下降，这是诚实，不是退步。

与内部去重的分工 ​

训练内部 MinHash / SemDeDup 降低记忆与浪费；对基准的检索降低分数虚高。前者的簇中心是高频网页，后者的查询是少量评测文档。实现上可以共用嵌入索引：先用评测向量检索训练集，再对剩余做 SemDeDup。不要指望内部去重「顺便」去污——评测项在训练里可能只出现一次，内部去重不会删孤例，而孤例已经足够污染。

边界与工程取舍 ​

完全无污染不现实。开放网页总会碰到与基准同事实的独立陈述。目标是去掉题干级复制与题解页，而不是去掉所有相关知识。过严的嵌入阈值会把「法国首都」一类事实题的所有提及删光，评测变成对过滤的考试。应按基准类型分档：闭书知识题允许事实共存，阅读理解与竞赛题干必须严。

闭源套件与动态题库减轻未来污染，不赦免已经训完的模型。新快照上线应重跑审计：FineWeb 某月干净，不代表下一爬次干净。生成数据工厂会把套件改写成「新题」，字面 n-gram 失效，必须上嵌入与人工抽检。跨语言译本要纳入索引，否则多语言模型的「跨语泛化」可能是跨语记忆。

污染检测是评测方法学，也是数据配方的最后一刀。写在 Dolma / FineWeb / DCLM 卡片末尾的重叠表，应与准确率表同等重要。没有重叠表的 SOTA，优先怀疑泄漏，而不是架构。

小结 ​

  • 污染包括原文、释义、翻译与题解页；内部去重不会自动删掉孤例泄漏。
  • 语料审计是一等证据；成员推断是模型侧补充，不能单证清白。
  • 训练前检索评测集（含译本与规范化代码 / TeX），命中则剪跨度或丢页。
  • 质量分类器的正例必须先去污，以免 DCLM / Edu 头放大泄漏。
  • 报告须写 \(n\)、规范化、是否含选项与多语言，否则不可比。
  • 开放数据使第三方能复现污染表，这是 Dolma / FineWeb 的方法学价值。
  • 出处：Dodge 等对 C4 与基准重叠的分析；n-gram 审计见 GPT-3 及后续模型报告；去重背景见 Lee 等人；数据池见 Wenzek CCNet、Soldaini Dolma、Penedo FineWeb、Li DCLM；释义近邻思想见 Abbas SemDeDup。
