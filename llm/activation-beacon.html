Activation Beacon ​

在激活流里插入信标标记，让它们学会概括刚刚过去的那一截；后面的层可以读信标，而不必把整段原始键值一直带着。

—— Zhang 等，Soaring from 4K to 400K: Extending LLM's Context with Activation Beacon，2024

滑窗丢掉中间，线性记忆把中间收进矩阵，分组位置则让中间以糊掉的 \(\Delta\) 继续参加点积。Zhang 等人 2024 年的 Activation Beacon 选择第四条路：在序列中插入特殊的信标（beacon）token，用它们的激活去压缩前一块普通 token 的激活；之后的注意力可以主要读信标，从而把有效上下文从 4k 量级拉到论文标题所写的 400k 量级。信标是学出来的，不是推理期重编号。本篇写这一插入式压缩，并和 Infini-Attention 的矩阵记忆区分开。

问题 ​

已有 LLM 的权重里已经有很好的短窗注意力。若完全改成线性记忆，短窗质量要重训；若只做 Self-Extend，二次复杂度仍在；若只做 StreamingLLM，中间事实消失。能否在尽量冻结原模型的前提下，加一种新 token，让它在前向里看到刚过去的一块激活，并把这块写成一个或少数几个向量，供后续 token 当长程键用？这要求：信标能进 embedding 表或旁路投影；注意力掩码允许信标看一块过去、后续 token 看信标；训练目标仍是普通语言建模，使信标必须携带对预测有用的信息。

压缩率是显式的：每 \(c\) 个普通 token 插入 \(b\) 个信标（常 \(b=1\)），则远历史的 KV 从 \(O(t)\) 变成 \(O(t/c)\)。标题中的 4K 到 400K，依赖的是 \(c\) 可以到 100 量级，而不是 RoPE 真的在 400k 下标上外推成功。信标延长的是「以压缩后的激活来条件化」的长度，不是无损窗口。宣传 400k 时，应同时报压缩率与在该压缩率下的针检索、摘要质量。否则会与原生 400k 全注意力混淆。

方法 ​

插入与可见性 ​

把输入按块大小 \(c\) 切开。块末（或块内均匀）插入信标。掩码规定：信标可以看见本块的普通 token（以及更早的信标，视方案而定）；块内普通 token 仍按原因果窗或短窗看邻居；后续块的普通 token 默认不直接看更早块的全部普通 KV，而是看累积下来的信标 KV。于是远距边的条数按信标数计。

信标的位置编码要单独设计：它们代表一块时间，而不是某一个词。可以用块索引的 RoPE、可学习的信标位置，或与普通 token 共享但加类型偏置。错误地给信标一个普通词的下标，会让模型把它当成那个位置上的词，压缩语义被位置通道污染。

训练：学压缩，而不是只改 \(\Delta\) ​

与 Self-Extend 相反，Beacon 要优化。常见做法是冻结或近冻结原 LLM 的主体，训练信标嵌入、可能的投影、以及少量注意力适配，使语言建模损失在「只能通过信标看前文」的掩码下仍下降。也可以短续训全模型。数据必须含长序列，否则信标没有梯度去携带远距信息，会退化成停用标记。

压缩后的有效长度

\[n_{\mathrm{eff}}\approx n_{\mathrm{local}}+b\cdot\Bigl\lfloor\frac{n}{c}\Bigr\rfloor \]

其中 \(n_{\mathrm{local}}\) 是仍以满分辨率看见的最近普通 token 数。KV 预算按 \(n_{\mathrm{eff}}\) 而不是 \(n\) 来算。

流式与滑动信标 ​

生成时可以保留最近普通窗，加一条信标 FIFO：每完成一块，新信标入队，最老的信标出队或再压缩。这与 Compressive Transformer 的两级记忆同构，只不过压缩器是「一个特殊 token 的前向」，而不是额外的卷积模块。Zhang 等人强调可以接到已有 4k 级模型上做扩展，而不是从零训无限注意力。

机制 ​

信标是插在残差流里的可学习查询：它的 \(q\) 去汇总本块的 \(k,v\)，输出写入它自己的隐状态，成为以后的键。这与注意力池化压缩函数是同一类运算，只是接口变成了「序列里的一个 token」，因此能复用现成的 Transformer 层、检查点、FlashAttention，而不必另写 \(d\times d\) 记忆核。后续 softmax 仍然尖、仍可解释「这个查询看了第 3 个信标」。

信息瓶颈在 \(b\) 和层数上。一层信标大约做一次池化；深层的信标可以读浅层信标，形成金字塔。\(c\) 太大，一块里的针会被平均掉，NIAH 中间深度变红——这是压缩失败，不是 RoPE 失败。把信标当 YaRN 用会评错：相位可能仍在 4k 支撑内（因为普通 token 的位置在块内循环或只对短窗旋转），真正变长的是内容通道上的摘要链。若块内位置用循环下标 0…c−1，普通 RoPE 永不 OOD，这是 Beacon 相对「把绝对位置拉到 400k」的便宜之处。代价是块与块之间的精确相对距离交给信标内容，而不是交给 \(\cos(\theta\Delta)\)。

和 Infini-attention 比：一个把摘要写成可见 token（可被普通 \(q^\top k\) 读），一个写成不可见矩阵（只能线性读）。和 Dual Chunk Attention 比：DCA 训练免费、仍试图用位置映射看见早块的原始键；Beacon 付训练成本，看见的是摘要键。需要原始键时 DCA 或全注意力更合适；需要极大 \(n\) 且接受有损时 Beacon 更合适。

边界与工程取舍 ​

必须训练，数据要长，否则信标是死参数。压缩率与任务绑定：条款逐字引用要求小 \(c\)；章节摘要可以大 \(c\)。不要用单一 400k 数字覆盖两种任务。插入信标会改变序列长度与位置对齐，分词、工具调用、logit 屏蔽要跳过信标 id，避免模型把信标当输出词。

KV 缓存要实现「普通槽 + 信标槽」两种寿命：普通槽按窗淘汰，信标槽按块淘汰。驱逐器若把信标当普通 LRU，长程通道会先于窗口被扔掉，故障表现为「刚还能概括前文、突然失忆」，而局部仍流畅。多请求前缀缓存时，信标依赖块边界，提示共享必须在相同切块对齐上，否则缓存命中但摘要错位。

评测应同时跑：块内任务（应接近原 4k 模型）、跨块 NIAH（考信标是否记下针）、∞Bench 类长书问答（考摘要是否有用）。只报能跑 400k 前向，与本方法的宣称无关——400k 是压缩后的条件长度，前向本身可以很窄。

信标数量随 \(n/c\) 线性涨，极长时仍可能要二次压缩（信标的信标）。那一层更糊，应视为另一档产品能力，不要和第一层 \(c\) 混在同一张表里报准确率。

小结 ​

  • Activation Beacon 用可学习信标 token 压缩块内激活，后续注意力读信标以降低 KV 增长。
  • 需要在长序列上训练信标（及少量适配），不是纯推理重编号。
  • 有效上下文 \(\approx\) 最近满分辨率窗 + 信标链；400k 依赖压缩率，不是无损 400k softmax。
  • 块内可用短位置避免 RoPE 外推；块间精确距离改由信标内容承担。
  • 相对 Infini-attention，摘要可被普通点积寻址，便于调试与缓存分层。
  • 切块对齐、信标不可当输出词、驱逐策略要把信标与普通 KV 分开。
  • 出处：Zhang 等，Soaring from 4K to 400K: Extending LLM's Context with Activation Beacon，2024；对照 Rae 等压缩记忆（2020）、Munkhdalai 等 Infini-attention（2024）以及训练免费的 Self-Extend / DCA。
