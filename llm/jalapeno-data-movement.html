减少数据搬运、让利用率贴近峰值 ​

峰值 FLOPS 只在数据已经在运算单元旁边时存在。长延迟路径、争用的统一内存和昂贵的全局栅栏，会让计算单元在数据路上空转。

—— Hot Chips 2026 Jalapeño 架构叙述：把数据放在需要它的地方、在需要的时刻到达，减少空等

推理专用 把指标收成延迟与焦耳。本篇写 OpenAI 给出的机制性原因：观察到的延迟往往被架构造成的等待主导，而不是被矩阵单元的峰值时钟主导。Jalapeño 被说成 memory-sliced：每个核有自己那一份 HBM 的本地视图；常见跨核模式走专用低延迟集合网络，其余走更灵活的通用 NoC。公开规格里单封装 15.4 TB/s HBM4、216 GiB，128 芯片聚合带宽被讲者用来估算「若只看带宽天花板」的每用户 token 率，并立刻承认真实系统远低于该天花板——也就是说，搬得动不等于用得满。不确定的微架构参数（切片数、NoC 频率）不编造。

问题 ​

逐步推理的算术强度低：每步要见权重与不断变长的 KV，见显存墙。GPU 用缓存与运行时 DMA 去猜下一拍；猜错就是暂停。OpenAI 把失败模式说得很具体：长延迟路径、被争用的统一内存子系统、昂贵的全局内存栅栏，都会让计算单元等「还在路上的数据」，利用率掉到峰值以下。HBM4 把带宽抬到 15.4 TB/s 量级之后，若核心仍通过一个过载的共享交叉去够所有字节，墙只是从「HBM 不够」变成「片上调度不够」。

128 芯片聚合超过 1 PB/s 的带宽，按讲者的粗算，若没有投机、只看带宽，可能暗示每用户 1000–2000 tokens/s 量级；加上投机 5000–10000。真实系统明显更低。这个对比的教学意义是：再买带宽，若不改数据放置与同步，利用率仍贴不近峰值。Jalapeño 的设计问题因此不是「如何公布更高 TB/s」，而是如何让操作数本地、让集合通信走专用短路、让栅栏变便宜或消失。

本地视图对抗统一内存幻想 ​

「统一 HBM 池、任何核随便 load」在编程上舒服，在物理上等于所有流量挤进同一套一致性或同一套交叉开关。memory-sliced 的意思是：每个核默认只快看自己的切片；跨切片是显式通信，而不是隐式缓存填充。这与 GPU 的缓存一致性编程模型不同，也与「整颗芯片一个共享 SRAM」的 LPU 不同。代价是编译器必须把张量布局写进物理位置——公开说 tensor layout 显式捕获放置，Gluon 把核当 thread block。人要理解「数据在哪」；模型搜索负责把放置与流水排好。

后续题目会写「每核本地 HBM 视图 + 集合网络」的切片细节。本篇只锁定动机：减少搬运与空等。不要在本篇填写未公开的每核 HBM 容量。

方法 ​

公开方法分成三层。封装内：核与 HBM 切片配对，常用操作数尽量不出切片。芯片内：专用集合网络服务常见跨核模式（可理解为为 TP / 规约这类规则通信准备的短路），通用 NoC 服务其余。芯片间：本地 128 卡高带宽域给张量并行，全局 2048 卡较低带宽给专家并行，避免所有通信都走同一档延迟。阶段门控则减少「单元闲着仍占数据路径底噪」——闲置不搬，也是一种减少搬运。

软件上，从功能正确的核出发，用内部系统去搜映射、放置、调度与流水。公开称注意力与 MoE 核相对专家手写快约 1.5×–1.8×，验证在芯片上端到端做。这暗示瓶颈确实在数据移动与调度，而不只在矩阵峰值：手写专家已经会写矩阵乘，搜索提升的是放置与流水。编程模型故意暴露本地张量与显式通信，让搜索空间可被机器遍历，而不是隐藏在缓存启发式里。

带宽天花板只用来做反证 ​

用 15.4 TB/s 去除以每 token 要搬的字节，可以得到一个假想 TPOT。OpenAI 把这个假想值摆出来，是为了说明「我们并未活在带宽屋顶上」。工程上应把同样的方法用在自己的模型：写出一步 decode 的权重字节 + KV 字节 + 激活交换字节，除以有效带宽（不是峰值），再与矩阵时间取大。有效带宽在切片架构里是本地切片带宽；跨切片与跨芯片的部分用 600 GB/s / 200 GB/s 的公开域口径去估。若激活交换接近这些口径，AFD 式拆分 或过宽的 EP 会先打满网络，矩阵单元继续空等——这正是 Jalapeño 要用专用集合网络去防的事。

机制 ​

利用率 \(\eta \approx T_{\mathrm{compute}} / (T_{\mathrm{compute}} + T_{\mathrm{stall}})\)。\(T_{\mathrm{stall}}\) 来自远量子、锁与拥塞。切片把大多数访问的跳数降到 0（本地 HBM）；集合网络把规约/广播的跳数与争用从通用 NoC 里拿开；显式放置让编译器把 \(T_{\mathrm{stall}}\) 编进时间表而不是在运行时发现。门控让不用的数据路径不参与争用。于是 \(\eta\) 可以靠近峰值，而不要求峰值本身是世界第一——公开 13.4 PFLOP/s MXFP4 相对同节点训练 GPU 的宣传峰值并不以「更大」为卖点，卖点是用得上。

对 MoE，突发 All-to-All 是经典的利用率杀手：专家一切换，权重与 token 都要搬家。公开拓扑把 EP 放到全局域、带宽较低，说明他们接受跨 2048 的专家并行更稀、更不能每步全交换。能做的是：专家尽量落在本地 128 域，或接受较低的全局带宽并靠门控与调度避免热线。具体放置策略未公开，不要写成已经实现了某种动态专家迁移算法。

「减少数据搬运」不是减少数学上的 FLOPs，而是减少跨切片、跨芯片、跨阶段（KV 搬家）的字节。FLOPs 仍在；空等下降。与 FlashAttention 减少 HBM 往返是同一类动机，层次不同。

和投机、MTP 的关系 ​

投机解码用额外计算换更少的大模型逐步扫描，本质上也是减少「大权重重复搬运」。OpenAI 演示多用单 token 路径，并声称 MTP 还能在同等效率下再降延迟。那是算法层减搬运；本篇是硬件层减搬运。两者叠加时，不要把 InferenceX 上 STP 的每千瓦倍数，解释成已经包含 MTP。

边界与工程取舍 ​

切片与显式通信提高了编程难度：错误的布局会让所有流量打到通用 NoC，芯片退化成「很贵的带宽很差的 GPU」。没有 CUDA 式隐式缓存来救拙劣内核。公开 bring-up 三个模型，不能外推到任意动态图。不要编造 NoC 拓扑（mesh 还是 crossbar）、不要填写未公开的片上 SRAM 每核容量。HBM4 的 216 GiB 是封装容量，决定能放下的权重+KV；切多少模型并行，仍受这张容量表约束。

若工作负载是极大 batch 的离线 prefill，统一内存 + 通用 GPU 可能更省事：算术强度高，\(T_{\mathrm{stall}}\) 被计算盖住。Jalapeño 的搬运故事主要针对交互式、阶段混合、KV 不能乱搬家的服务。

出处：Hot Chips 2026 现场报道中关于 memory-sliced、本地 HBM 视图、集合网络与通用 NoC、带宽天花板 vs 真实 token 率的幻灯叙述。规格数字同场：15.4 TB/s、216 GiB、128/2048 域。

小结 ​

  • 公开诊断：空等来自远数据、争用内存与全局栅栏，使利用率离开峰值。
  • 对策是切片本地视图、规则通信走专用集合网、其余走 NoC，KV 不在异构机群间搬。
  • 峰值 HBM 带宽用来证明「真实系统不在带宽屋顶上」，规划要用有效带宽。
  • 编译器显式放置是利用率的一部分，不是可选优化。
  • EP 的全局带宽更低，过宽的逐步 All-to-All 仍会打满网络。
  • 出处：Hot Chips 2026 Jalapeño 架构报道。
