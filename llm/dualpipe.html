DualPipe ​

两套微批沿相反方向走同一组设备，正向与反向的通信与计算互相遮挡，流水线两端不再是注定的空闲段。

—— DeepSeek-V3 技术报告中的 DualPipe 调度

上一课在单向流水上拆 \(B/W\)。设备排成一条线时，第 1 段与第 \(P\) 段在预热和冲刷里仍然更闲，通信方向也单一。DeepSeek-V3 用 DualPipe：把流水看成可以同时跑正向批次与反向批次的双向管道。本课不重讲 \(B/W\) 拆分。缺口是双向日历如何与已经学过的 1F1B / ZB 区分，以及它要求的实现前提（两份在飞状态、通信反向）。重叠课会把同一思想用到 TP；本课只谈流水这条轴。

问题 ​

单向 PP 的气泡即使在稳态被 ZB 压掉，pipeline 的两端在 batch 边界仍要等。长窗口、小 \(M\) 时，边界空拍占比重新变大。双向调度让一组微批从阶段 1 走向 \(P\)，另一组从 \(P\) 走向 1，一台设备在「给正向做 \(F\)」的同时可以用另一套缓冲给反向做 \(B\)。这要求激活与梯度的缓冲翻倍，并要求网络同时打两个方向而不互相排队。

DeepSeek 的报告把它写成与 MoE、FP8 一起的系统选择。本课只抽取调度语义，不把专家并行写进来当主角——MoE All-to-All 在后课。

与交错虚阶段的差别 ​

交错是同一方向上多层映射到一卡。DualPipe 是两个方向的流量共享卡。两者都能填洞，内存账不同：交错加虚阶段激活；双向加第二套在飞微批。不要在配置里用同一个 pp_schedule 字符串表示两件事。

双向不意味着数学上变成非因果。两条流仍是各自的因果前向与对应反向，只是设备日历交织。

方法 ​

维护两套微批队列。偶数全局步以 1→\(P\) 为主方向，奇数步对开，或在同一全局 batch 内同时注入两端（实现依赖框架）。每阶段的内核顺序写成：计算当前方向的 \(F\) 或 \(B\)，把通信 post 到反向流量的流上。DeepSeek-V3 强调计算与跨阶段通信重叠；若 NCCL 无法双向充分并行，日历会退化为「看起来双向、实际仍排队」。

对拍实验：相同 FLOPs 与数据，DualPipe 与 1F1B 的损失应对齐；吞吐差应能用气泡公式解释，而不是静默改了 batch 语义。梯度累积步数要对两套队列对称，否则优化器看到的 token 数抖动。

内存与重计算 ​

缓冲翻倍迫使更激进的重计算或更小微批。微批太小会打不满 张量并行 的 GEMM，又把收益吐给 TP。应先定 TP 度与微批下限，再开 DualPipe，而不是先开双向再发现矩阵乘变碎。

检查点必须记录两套在飞状态或保证边界上没有在飞，否则故障恢复会从错误的微批重放。后课异步检查点要知道这一点。

机制 ​

流水气泡本质是依赖方向单一。引入反向流量后，关键路径上的等待被另一条独立依赖链的计算填满。利用率提高，来自并发度而不是减少工作量。通信体积仍按激活形状 × 两套流增加，InfiniBand 过载时 DualPipe 会先于 1F1B 饱和。拓扑感知放置课会要求这两条流走的链路不要挤在同一条胖树的过订阅切面上。

边界 ​

DualPipe 实现成本高，小 \(P\) 时收益不如加 \(M\)。它不替代 ZB：有的系统两者叠加，有的只选其一。不要与数据并行的双向 All-Reduce 术语混淆。下一课把「通信躲进计算」从流水边界推广到 TP/DP 的集合通信，成为所有并行轴共用的手法。

小结 ​

  • 本课不重讲 \(B/W\)；只补双向微批流共享设备日历。
  • 第二套在飞状态换两端气泡；网络必须真能双向并行。
  • 损失应对拍 1F1B；微批下限受 TP GEMM 约束。
  • 检查点要知道双流状态。
  • 出处：DeepSeek-AI, DeepSeek-V3 Technical Report；对照 Narayanan 等 Megatron 流水与 Qi 等零气泡。
