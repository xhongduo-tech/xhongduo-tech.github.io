Artificial Analysis Intelligence Index ​

指数是加权合成：在同一提示、同一温度与同一抽取规则下跑完一组评测，再按智能体、编码、科学推理与通用能力的权重加总。

—— Artificial Analysis，Intelligence Benchmarking 方法论文档与 Index v4.2 公告

实验室各自报 MMLU、GPQA、自研内部集，公众很难判断「这个数能不能和那个数比」。Artificial Analysis 把多家模型放进同一套英语文本评测，产出 Intelligence Index 以及并列的每任务成本、输出 token 效率。它不是能力的充分统计量——图像、语音、多语言另表——但作为跨实验室的公开合成，引用密度很高。2026 年 9 月的 v4.2 把私有留出集权重加倍，并换上更重的知识工作智能体题。本篇写合成合同与版本漂移，不把某一天的榜首写成科学事实。

问题 ​

单项基准会饱和、会被针对性训练、也难以代表「上班会碰到的活」。合成指数用权重承认这一点：把智能体任务、终端编码、科学开放题与知识/幻觉分开，再合成一个 0–100 量级的数。Artificial Analysis 自称相对任何单一分数更有用，同时列出限制：主套件是英文文本；视觉与多语言走独立指数；个体评测的置信区间可以宽于指数整体的约 ±1%。

第二个问题是应试。公开题一旦进入训练语料，指数就变成记忆比赛。v4.2 把私有、留出测试集的权重提到 40%（v4.1 的两倍），包括 AA-Briefcase、AA-Omniscience 与 CritPt 的答案；并预告 v5 还会再提高。这是方法上的对抗，不是道德指责：指数若要继续当比较尺，必须让实验室难以对答案过拟合。

合成不是平均所有能找到的题 ​

方法页把 v4.1.1 写成四类加权：Agents 34%、Coding 24%、Scientific Reasoning 24%、General 18%，强调智能体。表里曾包括 GDPval-AA v2、τ³-Banking、Terminal-Bench v2.1、SciCode、AA-LCR、AA-Omniscience、Humanity's Last Exam、GPQA Diamond、CritPt。v4.2 作为过渡版本加入 AA-Briefcase 与 Surge AI 的 GDP.pdf，并因饱和去掉 GPQA Diamond。引用「Index 分数」必须绑定版本号：同一模型在 v4.1.1 与 v4.2 上不可直接减。

原则四条：标准化（同一条件）、不偏罚合法变体、零样本指令（不给 few-shot 示范）、公开方法。温度：非推理模型 0，推理模型 0.6（除非实验室另有推荐）。pass@1：第一次就必须对；多次重复时对所有尝试聚合。

方法 ​

所有模型在相同提示策略与抽取规则下跑。非推理模型最大输出 16384 token（或模型上限）；推理模型用实验室披露的最大输出。API 失败最多自动重试 30 次，仍失败则人工看；若专有接口系统性拦截某题，分数可能被拉低。指数用的 token 计数优先取供应商标称，以便报真实成本；性能基准另用客户端 o200k_base 统一计数——两套 token 不要混着算美元。

智能体题走开源 harness Stirrup：E2B 沙箱、网页抓取、搜索、看图、代码执行、结束与放弃任务。GDPval-AA v2 基于 OpenAI GDPval 公开金标，覆盖美国 GDP 主要部门的 44 类职业；提交文件后由三个前沿实验室的评判模型做盲成对比较，Bradley-Terry 拟合 Elo，人类专家交付锚定在 1000。写入指数时 Elo 被冻结并按 clamp((Elo-500)/2000) 归一。τ³-Banking 用双控智能体–用户模拟与后端数据库状态打分。编码侧 Terminal-Bench 看测试套件；SciCode 看子题单测，v4.2 还修了沙箱，避免「代码是对的但跑得慢」被判失败。

v4.2 往真实工作再迈一步 ​

AA-Briefcase 是实验室自研、带私有留出集的知识工作智能体评测：多周项目、大量相互依赖的子任务、数千个输入源文件，rubric 与成对比较同时打可验证完成、分析质量与呈现质量。GDP.pdf（Surge AI）是单轮专业文档推理：100 份 PDF、十个领域、4592 页，证据散落在正文、表、图、脚注与排除项里；1275 条专家原子标准，标题量 All-pass Rate 要求一条任务的全部标准都满足。AA-LCR 升到 v1.1，补了评分系统提示并修正答案键。GDPval-AA 与 Briefcase 的 Elo 重新锚定，避免每加一个模型就把旧分冲乱。

公告里的当时快照：Anthropic 的 Claude Fable 5.1 领跑指数，OpenAI GPT-6 Astra 第二（相对 GPT-5.6 Sol 约 +4 分）；成本帕累托上 Anthropic、OpenAI、Meta 与 Z.AI 都有点。这些数字是 2026-09-04 的截面，本篇只用来说明指数在产出什么比较，不滚动追榜。

机制 ​

加权平均把「哪类错误更伤使用」写进标量。智能体权重大，是因为失败发生在多工具轨迹而不是单选题。pass@1 拒绝「采样 100 次取最好」的实验室叙事，更接近用户只付一次生成的体验。Elo 成对比较处理开放交付物：没有唯一正确答案的职业文档，用相对人类专家的位置来打。留出集机制是承认训练会吞公开题——把一部分质量放在实验室看不到的标签上，指数才继续对「泛化」敏感。

Cost per Task 用与指数相同的分项权重，把输入、缓存、输出单价乘上真实消耗再除以任务数。于是「更聪明但更啰嗦」会在成本轴上显形：推理 token 多的模型即使单价不高，每任务美元也可能更贵。输出 token 前沿是另一张图：同一智力带上，谁用更少生成 token 换到相近指数。机制上这是把能力与计费拆开，避免只报正确率。

缓存命中率用该模型典型命中，而不是评测当日的一次测量，以免偶然冷缓存扭曲成本。供应商标称 token 与性能基准的客户端 token 分属两套账，引用成本必须说清来源。

与 METR 视界、Vending-Bench 不是同一尺 ​

指数是横切面的加权正确率/Elo，适合比较「现在谁更通」。METR 视界是纵切面的人类工期，适合谈自主时长。Vending-Bench 是单一超长经营的钱。一个模型可以指数很高、视界中等、售货机破产。Artificial Analysis 另有 Coding Agents 等分指数；不要把 Intelligence Index 当成智能体专项。GDPval 原数据集来自 OpenAI 论文（arXiv:2510.04374），AA 的实现是 Stirrup 上的复现与改沙箱，分数也不等于 OpenAI 原文表。

边界与工程取舍 ​

v4.2 自称把 v5 的零件提前上车，因为前沿动得太快、他们又刻意让 v4 稳定了约八个月。过渡版本的代价是：权重与题集同时变，历史曲线要分段。GPQA Diamond 退出后，科学推理桶的含义变了；Briefcase 与 GDP.pdf 进入后，指数更吃长文档与多文件项目，对「只会做竞赛题」的模型更狠。

个体评测重复次数不同（有的 1 次，有的 5 次），分项 CI 可以宽。工具使用列在表里：有的题允许工具，有的不允许——混用工具条件的外部复现不可比。指数整体 CI 约 ±1% 来自对部分模型、全部数据集超过十次的重复实验，不是对一切未来题集的保证。多语言走 Global-MMLU-Lite 的独立 Multilingual Index；把英语指数当全球能力会偏。

出处：Artificial Analysis，Language Model Benchmarking Methodology 与 Intelligence Benchmarking（artificialanalysis.ai/methodology）；Announcing Artificial Analysis Intelligence Index v4.2，2026-09-04。GDPval 原数据 OpenAI；GDP.pdf 为 Surge AI。引用写 Index 版本、是否含工具、以及成本是否用供应商标称 token。

小结 ​

  • Intelligence Index 是英文文本评测的加权合成，强调智能体任务；视觉与多语言另表。
  • 默认 pass@1、零样本、统一温度；智能体题多用 Stirrup + 沙箱工具。
  • v4.2 加入 AA-Briefcase 与 GDP.pdf，去掉已饱和的 GPQA Diamond，留出集约 40% 以防应试。
  • Cost per Task 用真实消耗按同一权重计费，把啰嗦的推理显式记成美元。
  • 分数绑定版本与日期；不要与 METR 视界或 Vending-Bench 余额平均。
  • 出处：Artificial Analysis 方法论文档与 v4.2 公告。
