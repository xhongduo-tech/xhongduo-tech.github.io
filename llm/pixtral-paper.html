Pixtral 报告 ​

可变分辨率的相对位置应写进视觉自注意力：RoPE-2D 让内积只依赖 $\Delta h,\Delta w$；评测则必须先把提示写死、再讨论宽松解析，否则开源对照表比的是格式而不是看图。

—— Agrawal 等，Pixtral 12B，arXiv:2410.07073

Mistral 的产品博文与 Pixtral 专文已经交代 12B、Apache 2.0、Nemo 解码器与 128K。本篇只写 arXiv:2410.07073 作为技术报告多出来的三块：Pixtral-ViT 相对 CLIP 的四处改动与 RoPE-2D 的相对性；MM-MT-Bench 的构造；以及「显式提示 / 灵活解析」如何改写开源对照叙事。不把 Pixtral Large 的层数写进表 1，也不把博客 52.5% 与论文主表 52.0% 混成一个 MMMU。

问题 ​

开源 MLLM 的论文数字经常不可比：默认提示不规定「Final answer:」还是「The answer is」，精确字符串匹配把「6.0」判错，闭源数字又来自另一套协议。报告认为这会让「谁更强」变成「谁更会猜评测脚本」。第二个问题是视觉编码器：固定 224 的 CLIPA 一类骨干，高分辨率只能切成许多独立窗口，位置表还要插值；文档长宽比一变，同一面积、不同网格在序列里无法区分。

产品目标（原生分辨率、多图、文本不掉点）在专文里写过。报告要回答的方法问题是：RoPE-2D 是否真有相对性；打破 token 是否必要；在同一显式提示下，12B 相对 Qwen2-VL 7B、Llama-3.2 11B 还剩多少；MM-MT-Bench 能否代理真实助手，而不是再一张选择题。

表 1 是报告的规格锚 ​

解码器：\(d=5120\)，40 层，head_dim 128，32 头，8 KV 头，上下文 131072，词表 131072。编码器：\(d=1024\)，24 层，head_dim 64，16 头，FFN 4096，patch 16，编码器序列上限 4096。视觉经两层全连接（中间同宽、GELU）进解码器，之后与文本一样走一维 RoPE 与因果注意。这是早融合交错，不是交叉注意力适配器。

编码器序列 4096 限制单张极高分辨率；超过要先缩小。128K 是解码器窗口，不是「两张 4K 图免费」。引用架构时用表 1，不要从 Nemo 博客另抄一套再假装是视觉论文。

方法 ​

Pixtral-ViT 四处改动：（1）行间 [IMAGE BREAK]、图末 [IMAGE END]，区分等面积不同长宽比；（2）FFN 门控；（3）序列打包加块对角掩码，批内多图互不注意；（4）RoPE-2D 替代可学习绝对位置。对出现在 \((i,j)\) 的 \(d\) 维特征 \(x^{(i,j)}\)，

\[\mathrm{RoPE\text{-}2D}(x^{(i,j)},\Theta)=M^{(i,j)}_\Theta x^{(i,j)}. \]

附录证明内积只依赖相对高差与宽差，从而网格变大不必插值位置表。用户按延迟选低分辨率、按细粒度选高分辨率，token 数随面积变。消融用同一 Nemo 12B 指令骨干，短程视觉指令微调：CLIPA 固定 224 或 25 窗拼到 \(1120^2\)，对照 Pixtral-ViT 可变分辨率、最长边约 1024。文档 / 图表任务上自训编码器明显更好，自然图 VQAv2 大致持平。

MM-MT-Bench 与解析协议 ​

MM-MT-Bench：92 段对话，图类为图表 21、表 19、PDF 页 24、示意图 20、杂项 8；69 单轮，其余多轮最多 4 轮。并行查询每一轮，历史用参考答案填充；GPT-4o 当裁判打 1–10，看正确与完整。论文称与 LMSys Vision Elo 皮尔逊相关约 0.91。主表 CoT：MathVista 58.3、MMMU 52.0、ChartQA 81.8、DocVQA 90.7。另报显式提示下部分开源模型分数塌掉、宽松解析后回升；Pixtral 对解析松紧不敏感——用来支持「指令跟随」而不是「更会看图」这一条。评测代码在 mistral-evals。

机制 ​

绝对位置在 224 上训、到 1024 要插值，等于换了一种几何；RoPE-2D 把「左邻右舍」做成旋转，外推的是相对结构。Break token 解决的是离散化后的歧义：32×32 与 16×64 长度可以接近，版面完全不同。块对角打包让训练吞吐接近文本 packing，不把两张图的 patch 混成一张——这是实现，不是新的注意力公式。

评测机制更刺耳：精确匹配把格式误差记成感知误差。显式提示把格式写入题目，本应降低这种混淆；若模型仍只在宽松解析下回升，说明它没听从格式指令。Pixtral 主表在显式提示下填，再展示宽松解析几乎不给自己加分，是为了把「听话」从「看清」里拆出来。MM-MT-Bench 用长回答与多轮，避免选择题偶然；92 场与 GPT-4o 裁判是方差与偏置来源，论文用与 Arena 相关来辩护，不能当成唯一上线门禁。

和切格派、和本站产品文 ​

InternVL2 切 448 格再像素重排；AnyRes 同类。Pixtral 把可变网格放进自训 ViT，解码器不再看见「格」这一层语言。产品文强调 drop-in Nemo；报告用 MATH / HumanEval 与显式提示表支撑「文本不牺牲」。不要只抄 MMMU 一句来比较两派。

灵活解析第三档论文标明「仅作说明，会把错答判对」。引用「宽松后某某追上」必须停在他们发布的合法档，不要用第三档改写排序。

边界与工程取舍 ​

Apache 2.0 覆盖 12B 权重，不覆盖 GPT-4o 裁判与训练数据。博客日期 2024-09-17，预印本 2410.07073，MMMU 两处 52.5 / 52.0，引用钉来源。MM-MT-Bench 92 场，适合协议讨论。编码器消融是短程指令微调，不是完整 12B 预训练复现。不要声称「原生分辨率无损」——patch 16 仍是下采样。

服务要把分辨率当调用方旋钮：缩略图聊天低分辨率，发票 OCR 拉高。多图模板固定 BREAK / END 顺序。回归必须同时跑纯文本 IFEval / 数学与带图 VQA。复现对照必须走 mistral-evals 的显式提示，否则是另一张榜。裁判模型若从 GPT-4o 换成别家，MM-MT-Bench 的绝对分会动，只适合在固定裁判下做相对排序。文档类题目对 break token 更敏感：行被拆错时，模型会把两列表格读成一行，表现为「看得清字、算错栏」。这不是 RoPE-2D 失效，而是序列化版面的标签丢了。

出处：Agrawal 等，Pixtral 12B，arXiv:2410.07073。产品叙事与 2409 权重见站内 Pixtral 专文。RoPE-2D 相对性证明在附录 B，不要只复述「用了二维 RoPE」而不写内积依赖相对位移。

小结 ​

  • 报告贡献是自训 Pixtral-ViT（RoPE-2D、break token、打包）与可复现评测协议，而不只是一张 12B 权重卡。
  • RoPE-2D 使视觉自注意力的内积依赖相对高宽；绝对位置插值不是同一几何。
  • MM-MT-Bench（92 场）代理多轮助手，与 Vision Elo 相关约 0.91。
  • 开源对照必须声明显式提示与解析松紧；格式误差不是感知误差。
  • 出处：Agrawal 等，arXiv:2410.07073。
