Chisel：粗几何定结构、文本定风格 ​

粗三维场景决定世界的结构，文本提示控制整体风格；二者可按任意比例混合。

—— World Labs，Marble: A Multimodal World Model 中对 Chisel 的说明

文本能描述「斯堪的纳维亚客房」，却很难规定床离窗 1.2 米、走道宽 90 厘米。单图能钉死一张明信片，却很难保证房间进深。Chisel 把这两件事拆开：用户在三维里用盒子、平面、墙，或导入已有资产，摆出粗结构；再写一段话（或参考外观）决定材质、时代与装饰。Marble 把粗布局和文本合成细致世界。结构听几何，风格听文字——公开叙述把它比作网页里结构与样式的分工。本篇只写这种解耦，不写区域扩展、Composer 或导出格式。

问题 ​

生成式三维的主控通道若只有自然语言，空间量就变成形容词：「宽敞」可能是 30 平方米也可能是 80，「一张长桌」可能挡住本应存在的门。创作者心里往往先有体块：哪是承重墙、哪是中庭、展柜靠哪一侧。把体块写成提示词，模型会当成风格暗示去「看起来像有墙」，而不是去遵守墙的坐标。反过来，若只有体块没有风格通道，输出停在灰盒子，达不到「现代美术馆、木地板、彩色绘画」这类外观合同。

需要一种输入，其几何通道对尺度和邻接负责，其外观通道对纹理和物体类别负责，并且两条通道冲突时有默认裁决：搬墙应改盒子，换木头应改句子。Chisel 被写成面向进阶用户的实验性三维雕刻模式，正是为了把「我看见的心里那个布局」直接摆进世界坐标，而不是翻译成一段容易被 recaption 改掉的英文。

粗，不是施工图 ​

粗几何的粒度是盒子、平面、墙段、简单导入件。它用来挡空间、定开口、标出家具占位，不是 BIM、不是精确 CAD。边角可以不齐，曲面可以用多段盒近似。生成器的工作是在这些占据约束上长出合理的建筑构件与装饰，而不是逐顶点拟合用户的盒子。若用户把 Chisel 当雕刻软件去抠圆雕，会与「粗结构」的合同相反：模型仍会按体块理解，细节会被风格通道重写。

导入 GLB / FBX 等资产是结构通道的一部分：物体先占位，再按文本被重新风格化，以便和房间共一套外观。导入件不是「原样网格穿过生成」的保证；要原样，应走后期替换，而不是指望 Chisel 当网格查看器。

方法 ​

先摆占据，再写风格 ​

工作顺序是：在视口里用墙工具、拉伸、基本体搭出 \(G\)（粗几何），可选导入资产并变换；然后给出文本 \(c\)。生成

\[W=\mathcal{G}(G, c), \]

其中 \(\mathcal{G}\) 应近似满足占据约束 \(\mathrm{occ}(W)\approx\mathrm{occ}(G)\)，同时外观服从 \(c\)。同一 \(G\) 换不同 \(c\)，应得到结构可辨认、风格迥异的一组世界——博文用同一客房体块配不同句子来展示这一点。同一 \(c\) 改 \(G\)（挪墙、加夹层），风格家族应还在，平面图应跟着盒子走。

公开例子把粗场景写成美术馆体块，文本写成木地板、彩色画与曲线雕塑。检验时看两件事：走道宽度是否仍由盒子决定；木头与艺术品是否由句子决定。若句子里写了「拆掉中庭」而中庭还在，说明结构通道赢了，符合解耦；若用户本想拆中庭，正确操作是改盒子，不是把「拆掉」写进形容词。

结构与风格的混合比 ​

解耦不是绝对正交。文本可以提到「一张圆形柜台」，几何里没有圆台时，生成器可能发明一件符合句子的物体——这是风格通道对结构的轻微入侵，有时有用（添道具），有时有害（堵住你留的门）。混合比由用户控制：几何越密、越贴齐，入侵空间越小；几何越疏，文本越会「帮你填家具」。工程直觉是：要锁死的用盒子，愿意被发明的留空，再在句子里描述留空处应有的气氛而不是精确件数。

TechCrunch 转述的类比是 HTML 管结构、CSS 管颜色。类比的限度：HTML 不会在你写 CSS 时偷偷加一扇门；生成模型可能会。解耦是产品意图，不是数学保证。锁门用几何，不要用否定句去「禁止」模型长门。

机制 ​

几何通道提供的是世界坐标里的条件场：这里应实、那里应空、这一段应是竖直分隔。生成过程把精细表面吸附到这些场的附近，类似粗网格约束下的细节合成。风格通道提供的是外观与语义先验：什么材质合法、什么装饰密度、什么时代。两者在损失上应分开：几何项惩罚墙被搬走、房间被缩小；风格项惩罚「明明写了木地板却铺了镜面金属」。

若把 \(G\) 先渲染成一张深度图再当单图提示，结构会退化成「看起来像这些方块的照片」，相机一偏，进深就丢。Chisel 的意义是条件在三维：约束不随某一张预览图的视锥消失。这也解释了为何要在 3D 视口里摆，而不是在二维画布上涂色块冒充平面图——平面图缺高度与层高，夹层和中空会被压扁。

文本里不要重复已经摆好的墙 ​

提示应写风格与几何里没有的元素：光线、材质、展品类型、窗外冰川。重复「左边有一堵墙」会把结构又送进语言通道，recaption 或模型可能按句子重新发明一堵位置略偏的墙，与盒子重影。机制上，语言通道对「墙」这类高先验词非常敏感；能用 \(G\) 说清的，不要再用 \(c\) 说一遍。

Chisel 场景界面提供墙、拉伸、全景相机与模板导入等。这些是搭 \(G\) 的工具，不是第二套世界模型。生成按钮才调用 Marble；之前的操作应理解为在编辑条件场。

边界与工程取舍 ​

Chisel 被标明实验性、面向进阶用户。体块精度、布尔是否可靠、曲线如何近似，都以产品当时行为为准，不要写成已发表的几何论文。它不替代多图测量：真实场所的墙应以照片或扫描为合同，而不是凭记忆摆盒子。它也不替代后期 DCC：导出后仍要在专业软件里改的，不应在粗盒子阶段抠。

风格重写导入资产时，功能件可能被美化坏：栏杆变成雕花却丢了间隔，碰撞会在后续双网格流程里出问题。需要保留功能轮廓的，盒子要比看起来「更好看」更保守。文本改结构的入侵无法完全关掉时，减少句子里的空间动词（扩大、拆掉、加一层），把那些动词变成对 \(G\) 的操作。

与纯文本模式相比，Chisel 增加了摆块成本，换来可重复的平面图。两次生成若 \(G\) 不变，结构应可辨认——这是相对文本骰子的工程收益。若发现同 \(G\) 两次平面图乱跳，那是当前生成器的方差边界，不是用户没把形容词写好。此时应加密几何或接受方差，而不是把整段小说写进提示。

本篇不讨论在已生成世界上用自然语言做局部编辑；那是另一套「改已经存在的 \(W\)」。Chisel 的主路径是条件生成：先有 \(G\) 与 \(c\)，再得到 \(W\)。

小结 ​

  • Chisel 用粗几何 \(G\) 定结构，用文本 \(c\) 定风格，再合成细致世界。
  • 要锁的尺度与邻接放进盒子和墙；要锁的材质与时代放进句子。
  • 同一 \(G\) 换 \(c\) 应换装不换房；改房应改 \(G\)。
  • 导入资产先占位再被风格化；不要默认网格原样穿过。
  • 解耦是产品意图，语言仍可能轻微改结构，故空间动词应落在几何操作上。
