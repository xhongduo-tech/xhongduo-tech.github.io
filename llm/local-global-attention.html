Local-Global Hybrid Attention ​

大多数标记只看邻域就够了；再留出少数能看见全序列、也被全序列看见的全局标记，长程捷径就有了落点。

—— Iz Beltagy 等, Longformer, 2020

纯 滑窗 把远边全部剪掉，远距离只能靠层叠隐状态有损传递。纯全注意力又把二次代价加回每一层。局部–全局混合在这两极之间：默认边是局部的，再加一类「全局」通道——可以是少数特殊 token，也可以是少数层仍用满注意力。Longformer 把全局权给分类符与任务标记；较新的解码器则常在层间交替滑窗与全局，例如 Google DeepMind 2024 年 Gemma 2 的做法。本篇讲这种混合设计，不展开 Longformer / BigBird 的完整稀疏图，那张图见 稀疏模式。

问题 ​

语言模型里同时存在两种依赖。一种是局部的：词序、括号、最近指代。一种是全局的：文档主题、系统提示里的硬约束、远距离的定义。滑窗服务第一种几乎不掉点，服务第二种会在约束滑出窗口后失效。反过来，每一层都做全局，prefill 的 \(\Theta(n^2)\) 在长上下文上不可接受，decode 的 KV 也无法钉死。

混合要回答的不是「要不要长程」，而是「长程通道的配额给谁」。配额可以按 token：只有 CLS、指令头、少数记忆槽走全局。也可以按层：偶数层窗口、奇数层全图。还可以按头：少数头全局、其余头局部。三种配额都会打破平移不变的带状图，引入实现复杂度，但使信息不必经过 \(n/w\) 跳才能从文首走到文末。

方法 ​

全局 token 与全局层 ​

Longformer 的全局 token 定义为：它可以与所有位置做注意力，所有位置也可以注意它。于是它成为星形的中枢。分类任务把 CLS 设成全局，等于强制存在一个可读写的全文摘要槽。编码器里这很自然；因果解码器里「被所有未来看见」与掩码冲突，全局通道通常改成：当前 token 仍只能看过去，但可以看一组常驻的全局键（提示前缀、汇点、记忆槽），并且这些槽自己对过去做较宽甚至满注意力。

解码器里的「全局」几乎总是单向的：未来仍不可见。真正双向的全局 token 属于编码器或前缀语言模型。把 Longformer 论文里的双向星形图直接贴到因果 LLM 上，会漏看掩码，评测也会虚高。

全局层更简单：选定若干层用满因果注意力，其余层滑窗。Gemma 2 用局部层与全局层交替，局部窗口固定。信息每两层可以做一次任意远的点对点对齐，中间层则便宜地做局部精炼。配额按层数百分比计，比按 token 更容易与现有内核兼容——全局层就是标准注意力，局部层就是带状掩码。

信息如何跨窗口传播 ​

三种典型路径。路径一：局部层把邻域写进隐状态，全局层用一次满注意力把远处键读进来。路径二：全局 token 在每一层收集全图，再被局部 token 当作窗口里的普通键来读——即使局部层看不到远处原文，也能看到中枢里的压缩。路径三：膨胀或稀疏随机边，见下一篇；本篇不依赖随机边。路径一保留任意 query–key 对准，适合针测；路径二把全文挤进少数槽，适合指令与主题。产品若只做了路径二却用针测验收，会误判混合失败。先写清全局通道要承担哪一种长程，再决定按层还是按 token 开口。

\[h_t^{\mathrm{(hyb)}}=\mathrm{Att}_{\mathrm{loc}}(q_t,K_{\mathcal{N}(t)},V_{\mathcal{N}(t)})+\mathrm{Att}_{\mathrm{glb}}(q_t,K_{\mathcal{G}},V_{\mathcal{G}}) \]

上式把局部邻域 \(\mathcal{N}(t)\) 与全局集合 \(\mathcal{G}\) 写成两项之和，也可以先拼接键再做一次 softmax。分开归一化还是合并归一化是关键细节：分开等于两个分布再混合，全局通道不会被窗口内的近邻完全压掉；合并则让全局键与近邻直接竞争，近邻往往赢，全局通道可能名存实亡。

和纯滑窗、纯稀疏的差别 ​

纯滑窗没有 \(\mathcal{G}\)，远距离只有隐状态接力。纯稀疏模式（Longformer 全图、BigBird）在 token 图上同时画窗、膨胀、随机与全局，一层之内就已经近似连通。混合注意力常更粗：要么整层全局，要么少数槽全局，实现接近现有 Flash 内核，不必写随机稀疏收集。质量上，一层之内的连通性不如 BigBird 细，但训练稳定、内核成熟，更常出现在当代解码器里。

与 Attention Sink 的关系：汇点是推理时被迫保留的「伪全局」前缀。混合架构若在训练期就设置全局槽，汇点可以变成显式记忆，而不只是 softmax 的病理锚。两者不要混名。

机制 ​

全局通道能工作，是因为它把 \(O(n)\) 的远距离查询压缩进 \(|\mathcal{G}|\) 或少数层的 \(O(n^2)\) 预算。星形图的中枢容量有限：一个 CLS 要代表整篇文档，必然丢失细节。所以全局 token 适合主题与指令，不适合「第 317 行那个变量名」。全局层没有这种压缩，任意 query 仍可对准任意过去 key，细节保留更好，但那一层的代价回到二次，必须把全局层数压低。

归一化机制决定通道是否真的开着。合并 softmax 时，若局部键的 logit 普遍更大，全局键的权重接近 0，混合退化为滑窗。对策包括：全局键单独一组头、全局项加温度或门控、或对全局分数加偏置。Longformer 对全局与局部用不同投影，本质上是让模型学会何时走中枢。

边界与工程取舍 ​

按层交替实现成本最低，但全局层的 KV 仍随 \(n\) 增长。若只有 1/2 的层是全局，缓存大约减半，不是减到窗口大小。要常数显存，必须让全局通道的键集合也有上界：固定前缀、固定记忆槽、或对历史做压缩。否则「混合」只加速 prefill，不解 decode 的显存墙。

按 token 全局要对齐训练目标。聊天模板里把系统提示标成全局，模型才知道这些键永远可及。若训练未标、推理突然把提示当全局，属于改图。另一边界是批次里序列长度不一，全局层的满注意力要对齐填充掩码，否则短序列会看见填充。

取舍：需要指令永不遗忘，用显式全局前缀；需要任意针测，必须有真正的全局层或可学习选择，不能指望一两个 CLS。预算上先加少量全局层，再考虑复杂稀疏图。混合的失败模式常常是全局通道没打开：图上画了星形，softmax 里权重接近零。查问题时先看全局键的平均注意力质量，再去加层或加窗。

小结 ​

  • 局部负责近邻，全局负责捷径；混合的本质是给长程通道限额，而不是取消稀疏。
  • 配额可按 token、按层、按头；解码器里全局必须仍是因果的。
  • 分开归一化才能防止近邻把全局键挤没；合并 softmax 可能让混合名存实亡。
  • 按层交替实现简单，但全局层 KV 仍随长度涨；常数显存需要有界的全局键集。
  • 中枢 token 适合主题与指令，不适合精确远距离检索。
  • 与固定稀疏图相比，混合更粗、更好实现，是当代 LLM 更常见的折中。
  • 出处：Beltagy et al., Longformer, 2020；Zaheer et al., BigBird, 2020；Google DeepMind, Gemma 2, 2024；Mistral 7B, 2023。
