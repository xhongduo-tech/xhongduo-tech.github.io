视频时序融合 ​

时间采样决定看见哪些帧；时序融合决定这些帧在进语言模型之前，要不要先在时间维上合并成更短的运动符号。

—— 对照 Qwen2-VL / Qwen2.5-VL 的动态 FPS 与时间 RoPE；以及视频理解里的时间池化 / 时序注意力

上一课 已经把视频写成「抽多少帧、每帧多少 patch、时间 ID 按绝对秒还是按帧号」。本课不重讲抽帧。缺口是抽完之后的 融合：相邻帧是简单平均、是 3D 卷积式局部混合，还是把时间完全交给 LLM 自注意力。早融合课里的「在哪一层跨模态」这里变成「在哪一层跨时间」。后课交错训练默认视频块已经是一条时间上有序、长度可控的 token 流。

问题 ​

只做均匀抽帧、每帧当独立图像送进 ViT，运动必须由 LLM 在 \(T\times N\) 个 token 上自己发现。相邻帧高度冗余时，自注意力先把容量花在近重复 patch 上，动作的差分反而弱。若在编码器里做时间池化——例如每 \(m\) 帧合成一个时间单元——\(T\) 下降，冗余下降，但短于 \(m\) 帧的事件被抹掉。视频理解的经典张力是：融合太晚则序列爆、融合太早则运动糊。

这与 视觉 token 压缩 不同。空间压缩可以每帧独立做；时序融合显式跨帧，梯度会把「哪几帧该并在一起」和「并完的符号表示什么运动」绑在同一段参数上。抽帧是不可微的预处理（或最多用可学习采样），融合常常是可训练的。

池化假设时间局部性 ​

平均池化、max 池化、把 \(m\) 帧的 CLS 再过一层小 Transformer，都假设相关运动发生在窗口 \(m\) 内。镜头切换、闪回、多画面，窗口会把两个无关场景合成一个鬼影 token。因此融合模块需要镜头边界，或至少需要能被注意力跳过的门。把「视频 = 局部平滑时间」写进架构，对电影和幻灯片式课件都会错。音频 codec 的帧是均匀且局部的；视频镜头不是。把 RVQ 那套均匀时间格子直接套到视频 token 上，会在切镜处制造假运动。时序融合要能在边界上断开。

方法 ​

晚、早、分级三条路径 ​

三条常用路径：

  • 晚时序：每帧独立编码，只在 LLM 里靠时间 RoPE / MRoPE 融合。实现简单，长度税全付在 LLM。Qwen2-VL 一类接近这条，再用动态 FPS 控制 \(T\)。
  • 早时序：3D patch（空间 \(P\times P\)、时间 \(\tau\)）在编码器入口融合。运动进入 ViT 第一层，LLM 看见的已是时空管。短事件与切镜要靠 \(\tau=1\) 的退化或自适应 \(\tau\)。
  • 分级：底层局部时间注意力或池化，顶层再进 LLM。类似视频 Swin 的局部窗，再接到连接器。

位置编码必须与融合一致。若 \(m\) 帧已经合成一个 token，该 token 的时间 ID 应取窗口中心的绝对时间，而不是「第几个融合块」的序号——否则不同 FPS、不同 \(m\) 的同一秒会对不齐，上一课的警告在融合之后仍然成立。

机制 ​

时间池化是低通滤波：高频闪烁、快速手势被衰减。对「谁进了房间」够用，对「唇形 / 计数快速事件」不够。可学习融合（小型时间注意力）能保留部分高频，但窗口外仍看不见。LLM 自注意力理论上是全局的，可以跨分钟绑定，代价是 \(T N\) 的二次项。工程上往往 早侧低通减 \(T\)，晚侧全局绑定：编码器负责「这一秒在干什么」，LLM 负责「这一秒和三分钟前那句旁白的关系」。

多模态对齐上，音画要用同一时间刻度。若视频融合把 4 帧并成 1 个 token、音频仍是 50 Hz codec 符号，交错时两种符号的「一秒」长度不同，模型会学到错误的口型同步。Qwen2.5-Omni 的 TM-RoPE 把这件事写成共享时间分量；本课只要记住：融合改变符号率，必须同步改时间 ID 的步长，而不是只改 token 个数。

评测动作理解（Something-Something、短视频问答）对早融合更敏感；长视频叙事、多镜头推理对晚侧全局注意力更敏感。只用一种基准会选出错误的融合深度，与早/晚模态融合课里「指标绑错接口」是同一个坑。

动态 FPS 与融合窗口如何一起动 ​

动态 FPS 在运动剧烈处提高采样率。若融合窗口 \(m\) 固定按「帧数」计，剧烈处窗口覆盖的绝对时间变短，平静处变长——滤波的时间常数随内容变，可能是好事（自适应），也可能让位置编码难以解释。更干净的是窗口按绝对毫秒切，帧数随 FPS 变。实现更烦，时间几何与 video-tokens 的绝对时间 ID 一致。

边界与工程取舍 ​

生成式视频（要重建每一帧）不能在理解编码器里做不可逆池化；理解式 VLM 可以。同一套视觉塔若既做理解又做生成，融合必须可逆或跳过。训练 packing 把多段视频拼进一条序列时，融合窗口不得跨样本、不得跨镜头标注边界，否则会出现「两个用户的视频在时间上求平均」的幽灵运动。

计算上，3D 卷积 / 时间注意力在编码器侧的 FLOPs 随 \(\tau\) 涨，但通常仍远小于 LLM 对 \(TN\) 的二次项。优化器应优先减 \(T\)，而不是舍不得编码器里那点时空混合。反过来，\(T\) 已经很小（每秒 1 帧）时再池化，只会毁运动，省不下什么。

「Temporal pool」容易被实现成对时间维做自适应平均池化（GAP）。全局时间平均把整段视频压成一条向量，晚融合到极点，绑定能力为零。本课的池化默认是局部的、仍保留时间轴。全局平均属于检索塔，不属于对话 VLM。

小结 ​

  • 抽帧选哪些时刻；时序融合决定跨帧是否在进 LLM 之前混合。
  • 太晚融合则近重复占满注意力；太早池化则短事件与切镜被抹掉。
  • 融合改变符号率，时间 ID 必须按绝对时间重标，并与音频帧率对齐。
  • 理解与生成对可逆性要求不同；packing 不得跨段融合。
  • 动作基准与长叙事基准会选出不同融合深度，不要混用。
  • 出处：Qwen2-VL / Qwen2.5-VL 的时间位置编码与动态 FPS；视频 Transformer 的局部时序窗。
