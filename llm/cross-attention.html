Cross-Attention ​

查询来自当前要写的序列，键和值来自另一段已算好的记忆；注意力在两条长度可以不同的序列之间做内容寻址。

—— Vaswani et al., Attention Is All You Need, NeurIPS 2017

上一课的查询、键、值来自同一条序列，并用因果掩码挡住未来。本课不重讲 SDPA，也不重讲掩码。缺口是：两条长度可以不同的序列之间，如何做内容寻址。当 \(Q\) 从 \(X\) 投影、\(K,V\) 从 \(Y\) 投影时，这个运算叫交叉注意力（cross-attention）。翻译、视觉语言、检索增强都是同一套代数。下一课才把它放进编码器-解码器的固定槽位。

问题 ​

因果自注意力只能在一条序列内部路由。一旦任务有两个来源——源语言与目标语言、图像与文本、记忆库与当前查询——内部路由看不见另一侧。早期 seq2seq 用编码器的最终隐状态做一个向量，解码器全程只看这个向量，容量在长句上迅速成为瓶颈。交叉注意力把「一个向量」换成「一组按内容寻址的键值」，解码端每个位置都可以重新选择读源端的哪一部分。

「内容寻址」就是按『内容像不像』而不是按『排在第几号』来找：每个查询带着自己的问题，去记忆里匹配最相关的条目，类似按关键词搜书，而不是翻固定页码；同一页对不同问题的重要度也不同。

两侧长度通常不相等。令查询长度 \(n\)、记忆长度 \(m\)，分数矩阵是 \(n\times m\)，不是 \(n\times n\)。输出长度跟查询走：每个查询位置得到一条与 \(d_v\) 同宽的混合结果，记忆序列本身不被改写。这与自注意力「改写自己」不同——交叉注意力是只读地查询外部记忆。

条件来源与被写序列必须分开 ​

若把 \(X\) 与 \(Y\) 简单拼成一条再做自注意力，也能形成跨段读取，但可见性、位置编码和因果约束会缠在一起：生成侧往往需要因果，记忆侧往往需要双向，拼串后要用块状掩码去模拟。交叉注意力把两种约束拆开：记忆侧的 \(K,V\) 预先算完，查询侧按自己的掩码（常是因果）去读。代价是多一套投影，以及必须决定何时、在哪一层去读。

交叉注意力没有内置的「记忆是否可信」机制。softmax 会在 \(m\) 个键上分满 100% 的质量，即使 \(Y\) 与当前查询无关。检索空结果、图像与问题不匹配时，模型仍会读点什么。这是算子的归一化性质，不是任务设计的失误；要留退路需要额外的门、空记忆 token，或把「不读」学进分数。

方法 ​

记 \(X\in\mathbb{R}^{n\times d}\)，\(Y\in\mathbb{R}^{m\times d}\)。

\[Q=XW^Q,\qquad K=YW^K,\qquad V=YW^V, \]\[\mathrm{CrossAttn}(X,Y)=\mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V. \]

\(W^Q\) 只作用于被写序列，\(W^K,W^V\) 只作用于记忆。多头时与 MHA 相同：分头打分、拼接、乘 \(W^O\)。查询侧若是自回归的，对 \(X\) 内部仍用带掩码的自注意力；交叉注意力对记忆一般不施因果掩码——源句的未来词在翻译里通常允许看见，因为源句在编码时已完整存在。

长度不同时的形状与掩码 ​

\(QK^\top\) 的形状是 \(n\times m\)。源端 padding 必须沿键维屏蔽，否则填充位置会吸入权重。目标端 padding 沿查询维屏蔽，避免无意义位置的损失或梯度。两侧的 padding 掩码来源不同，不能复用同一张 \(n\times n\) 因果模板。记忆若来自多幅图、多条检索，常先把它们沿长度维拼接，再共享一套 \(K,V\)；查询仍然是当前文本位置。

代个形状：源句 20 个词（\(m=20\)）、已译出 5 个词（\(n=5\)），分数矩阵就是 \(5\times 20\) 共 100 个注意力权重；若错套自注意力的 \(n\times n\) 模板，形状根本对不上——这正是实现里最常见的第一处报错。

机制 ​

交叉注意力的梯度分两边走。对 \(X\) 的更新来自「我该问什么」：\(W^Q\) 与 \(X\) 被分数与值共同塑造。对 \(Y\) 的更新来自「我该被怎样检索」：被频繁点到的记忆位置会收到更大的值侧与键侧梯度。编码器-解码器训练里，这正是编码器获得生成端误差信号的主要通路之一。若冻结 \(Y\)（预训练视觉编码器、离线检索向量），梯度只更新查询侧与输出投影，记忆变成常数表。

复杂度是 \(O(nmd_k)\)，在 \(n\approx m\) 时与自注意力同阶；若 \(m\gg n\)，例如长文档、高分辨率图像 token，瓶颈在记忆长度。此时工程上会压缩 \(Y\)（池化、Perceiver 式潜向量、token 合并），而不是改 softmax 公式。KV 缓存在交叉注意力里往往指记忆侧：源端 \(K,V\) 在一次编码后可固定，解码多步反复用——这与自注意力里「随生成增长的缓存」不同，记忆缓存长度是 \(m\) 而不是当前已生成长度。

RoPE 一类相对位置编码默认假设查询与键是同一条序列上的下标。交叉注意力两侧下标空间不同，直接共用一套旋转位置会把「源语言第 3 词」和「目标第 3 词」错误地当成相对位置零。常见做法是记忆侧用独立的位置几何，或对交叉注意力关闭相对位置、只保留内容点积。这是实现时最容易 silently 出错的点。

只读记忆与残差写入 ​

交叉注意力的输出加回 \(X\) 的残差，不写回 \(Y\)。信息流是单向读取。若任务需要两侧互相改写（某些跨模态融合、对偶注意力），要再放一层角色对调的交叉注意力，那是两份本算子，而不是一份算子的隐藏模式。单向读取使缓存简单：记忆算一次即可。

边界 ​

交叉注意力增加一层同步：必须先准备好 \(Y\)，再算 \(X\) 的这一子层。流式源端（边听边译）时记忆在增长，需要增量编码并更新 \(K,V\)，语义仍是交叉，工程变成在线。多模态里图像 token 数常远大于文本，\(m\) 主导显存；把交叉注意力放到浅层或对视觉先做池化，是在减 \(m\)，不是在改公式。

与「把所有模态拼进一条自注意力」相比，交叉注意力的归纳偏置更强：查询侧不能被记忆侧的因果结构污染，记忆侧也不被查询侧的生成顺序打乱。代价是表达力受限于「读」而不是「与记忆共同演化」。当需要深层融合时，人们会在自注意力拼串与交叉注意力之间折中，例如早期层交叉读图、后期层文本自注意。那是系统装配，算子本身仍是 \(Q\) 来自 \(X\)、\(KV\) 来自 \(Y\)。

直觉类比：交叉注意力像开卷考试——每道题（查询）去翻参考书（记忆）里最相关的段落抄进答题卡；书不会被改写，而且同一本书可以考很多场（记忆侧 KV 只算一次）。自注意力则更像考生在自己草稿上边写边回看。

解码器里若同时存在掩码自注意力和交叉注意力，二者的 KV 缓存布局不同：前者每步追加一个 token 的 KV，后者在源端固定时缓存一次性写满。推理框架把它们当成两种注意力类型分别调度。把源端 KV 误塞进自注意力缓存，会出现长度错位和位置编码错位。

小结 ​

  • 交叉注意力令 \(Q\) 来自序列 \(X\)、\(K\) 与 \(V\) 来自序列 \(Y\)，输出长度与查询一致，记忆只读。
  • 分数矩阵形状是 \(n\times m\)，两侧 padding 掩码必须分开构造；对完整记忆通常不加因果掩码。
  • 它解决的是跨来源内容寻址，而不是单序列内部的自回归约束；后者仍由查询侧的自注意力负责。
  • 复杂度随 \(nm\) 增长；记忆很长时优先压缩 \(Y\)，而不是改 softmax。
  • 相对位置编码不能默认跨序列共用下标，否则会把两侧「第 \(i\) 个位置」错误对齐。
  • 编码器-解码器层、视觉-语言读取、检索记忆，都是这一算子的实例，槽位不同、公式相同。
  • 出处：Vaswani et al., Attention Is All You Need, NeurIPS 2017。
