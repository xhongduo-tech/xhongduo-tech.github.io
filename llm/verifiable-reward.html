可验证奖励 ​

最终答案能被程序判定对错时，强化学习不必先训练一个会撒谎的偏好模型；奖励就是校验器的 0/1 或测试通过率。

—— 对照 GSM8K / MATH 的答案核对、竞赛编程的单测；DeepSeek-R1 把可验证信号作为推理 RL 的主奖励

Long CoT SFT 教会写长链，但不告诉模型「哪种与教师不同的链更好」。本课把奖励改成可验证环境：数学填空、代码单测、形式化证明检查、带断言的工具结果。偏好模型、过程模型可以后加；这里先把结果奖励写成确定性函数 \(R(x,y)\in\{0,1\}\) 或 \([0,1]\)。缺口是从模仿走到探索，且探索的信用来自环境而不是另一个 LLM 的口味。后课长度预算与闭环都假设 \(R\) 已存在且可批量调用。

问题 ​

RLHF 的奖励模型会在长链上投机：更长、更客气、更像证明的错误过程可能得高分。可验证任务允许绕开这条噪声：抽取最终答案（或程序输出），与标准答案或测试集比较。GSM8K、MATH、HumanEval、竞赛题、部分代理环境（单元测试、棋局终态）属于此类。自然语言开放问答、风格、安全，多数不可验证，本课不覆盖。

SFT 之后做 RL 的原因：教师覆盖有限，校验器可以对新采样的 \(z\) 给真值，策略可以离开教师邻域。没有校验器，采样再多也只能做 Best-of-N 蒸馏，仍是模仿。问题立刻变成抽取与误判：链写对了但盒子格式错，\(R=0\)，模型被教去优化格式而不是数学；抽取过宽，把中间计算当答案，\(R\) 假阳性。

抽取器是奖励函数的一部分 ​

\(R\) 的真实定义是 \(\mathrm{check}(\mathrm{extract}(z,y), y^\star)\)。extract 与训练 / 评测必须同一套。正则、boxed、JSON 字段、最后一行数字，选一种锁死。SFT 阶段就应教这一种。代码任务的 \(R\) 是测试通过率，还要锁时间、内存、是否允许网络——这与后课沙箱是同一边界，本课先要求：奖励通道上没有不可复现的副作用。「可验证」不等于「无噪声」。单测覆盖不足会把错误实现标成对；数学等价形式（\(1/2\) vs \(0.5\)）会把对的标成错。噪声来自规范，不是来自神经网络。规范要版本化，像代码一样 diff。

方法 ​

群体采样与抽取失败怎么计 ​

采样：对每题抽 \(G\) 条长链（R1 / GRPO 式群体）。算 \(R_i\)。优势用群体均值基线或 critic-free，不必上价值网。更新用 PPO 截断或 GRPO / REINFORCE 变体，只在可解析样本上计梯度——抽取出失败可赋 \(R=0\) 或直接 mask，二者对格式学习的压力不同：0 分会教格式，mask 把格式留给 SFT。

混合任务时，不可验证题不要假装 \(R=0.5\)；应排除出这套 RL，或走单独的偏好通道。把 Arena 口味塞进同一标量，会污染校验器的 0/1 几何。

机制 ​

0/1 结果奖励在长链上极稀疏：一百步里一步算错则整条零，与 PRM 搜索课开头的方差问题相同，但现在方差进了梯度。群体内相对基线把「这题大家都错」变成零优势，避免惩罚不可能的题；「这题有人对」则只抬对的链。这比学一个全局 critic 更稳，前提是 \(G\) 够大且温度够，否则全 0 或全 1，没有优势。

探索与格式冲突：提高温度能出新算法，也更能破坏 boxed。通常先低温度巩固抽取，再升温。奖励里加很小的格式项（正则通过 +0.1）会很快饱和，应尽早去掉，否则模型靠格式刷分。

可验证 RL 会过拟合校验器的洞。数学竞赛若只核最终整数，过程胡写也能碰对；代码若只核公开测例，会硬编码输出。保留隐藏测例与过程抽查（人工或 PRM）是防黑客，不是否定可验证原则。

与 SFT 教师的关系 ​

RL 可以负迁移：为了过校验器，链变得更长、更丑、丢掉对用户友好的解释。产品若需要可读 CoT，要在 \(R\) 之外另加长度或风格约束——下一课。若只追求准确率，可读性不是本课目标。SFT 教师若来自不可验证的偏好，与本课 \(R\) 会打架：有时教师链在校验器下是 0，应在进 RL 前丢掉或改写。

边界与工程取舍 ​

校验器吞吐决定 RL 墙钟。代码沙箱比数学正则贵几个数量级，batch 结构要按环境分组，避免数学 step 等代码超时。非确定性评测（浮点、并发）会让同一条 \(y\) 的 \(R\) 抖动，梯度变噪声；应钉种子、钉实现。

不可把「用 GPT-4 当判官」叫做可验证奖励。那是 LLM-as-judge，方差与偏好偏见回到场内。本课的动词是 程序判定。代理任务里若判定器本身是 LLM，应放到评测协议课，不要冒充 \(R\)。

DeepSeek-R1 把数学、代码、逻辑谜题等可验证数据作为推理 RL 的主场，开放域走另外的对齐。复现时不要把全部指令数据灌进 0/1 校验器；没有 checker 的样本不属于本课。

小结 ​

  • 可验证奖励用程序判定最终答案或测试，替代长链上不可靠的奖励模型。
  • 抽取器与运行规范是 \(R\) 的一部分，必须与 SFT 格式锁死。
  • 稀疏 0/1 靠群体相对基线降方差；全 0 / 全 1 的题没有梯度。
  • 防校验器黑客要用隐藏测例；不要把 LLM 评委叫做可验证。
  • 吞吐与确定性约束 RL 的环境设计，为沙箱课留接口。
  • 出处：MATH / GSM8K / 竞赛编程的核对传统；R1 类推理 RL 的主奖励设计。
