大模型 · 2026-09-03

Kaplan 扩展律 ​

在足够宽的范围内，语言模型的交叉熵随参数量、数据量和计算量呈可预测的幂律下降——直到某一项成为瓶颈。

—— Kaplan et al., Scaling Laws for Neural Language Models, 2020

2020 年 Kaplan 等人把「更大的模型更好」收成一组可拟合的曲线。他们在 Transformer 语言模型上系统扫参数量 \(N\)、数据集大小 \(D\) 和训练计算 \(C\)，发现测试损失在很大范围内服从幂律，并且当另外两项足够充裕时，损失由最紧的那一项主导。这件事改变了预训练的规划方式：与其只报某一个最大模型的分数，不如先问，以现有的 FLOPs 预算，应该把参数和 token 分到什么比例。后续 Chinchilla 修正了他们给出的计算最优比例，但并没有推翻「损失可沿尺度外推」这一观察。本篇只讲 Kaplan 当时写下的形式、他们建议的计算分配，以及这条曲线后来被发现的适用边界。

问题 ​

预训练之前，模型大小往往凭经验或单次消融来选。深度、宽度、训练步数纠缠在一起，很难回答「若把计算加倍，应该加宽模型还是多看数据」。Kaplan 等人要的是可外推的标度：固定架构家族（Decoder-only Transformer），改变 \(N\)、\(D\)、\(C\)，看语言建模损失如何变。若标度稳定，就可以在小模型上拟合，再决定大模型该长多大。

计算与 \(N\)、\(D\) 不是独立的。Transformer 训练的 FLOPs 近似 \(C\approx 6ND\)（前向约 \(2ND\)，反向约两倍）。给定 \(C\)，选更大的 \(N\) 意味着更少的 token，反之亦然。扩展律必须同时描述三条轴，以及它们互相卡住时的形状。

三项瓶颈 ​

他们把损失写成接近

\[L(N,D)=\left[\left(\frac{N_c}{N}\right)^{\frac{\alpha_N}{\alpha_D}}+\frac{D_c}{D}\right]^{\alpha_D} \]

这类可分形式：当 \(D\) 极大，\(L\) 随 \(N\) 幂律下降；当 \(N\) 极大，\(L\) 随 \(D\) 幂律下降。单独对计算拟合时，又有 \(L(C)\propto C^{-\alpha_C}\)。早期小模型、短训练很容易落在「三项都不饱和」的中间区，曲线看起来很光滑；真正做大时，总会撞上其中一堵墙。幂律说的是在对数坐标里近似直线，不是在任何尺度上都永不弯曲。数据重复、优化失败、上下文长度变化、tokenizer 改变，都会让直线折弯。Kaplan 的贡献是指出存在一段可规划的直线，不是宣称损失可以无限按同一指数降下去。

方法 ​

实验上，他们训练一系列不同大小的 Transformer，扫训练步数与数据量，用测试集交叉熵作为标度对象——不是下游准确率。下游任务当时已有随损失改善的迹象，但拟合仍落在语言建模损失上，因为后者噪声更小、跨模型更可比。参数量按非嵌入参数计，以避免词表大小扭曲小模型的 \(N\)。

在给定计算预算下，他们用拟合出的指数去推「最优」的 \(N\) 与 \(D\)。得到的图像是：计算变大时，模型应该涨得比数据更快，\(N\) 大约随 \(C\) 的 \(0.73\) 次幂涨，\(D\) 大约随 \(0.27\) 次幂涨。按这条建议，很大的模型只看相对较少的 token 就是「计算最优」。这一条后来被 Hoffmann 等人证明是过度偏向大模型了，原因包括学习率余弦日程与训练长度耦合、以及大模型往往没有训到充分的 token。但 Kaplan 的测量协议——用损失对 \(N,D,C\) 做幂律拟合——被保留下来。

样本效率随宽度上升 ​

曲线的另一个直接推论是：更大的模型达到同一损失所需的 token 更少。这与「大模型更数据饥渴」的直觉相反，却与训练动态一致——容量高的网络能从同一批数据里抽更多可泛化的结构。于是出现一种规划语言：若数据是瓶颈，把计算用于更大的 \(N\)；若计算是瓶颈且数据充裕，再权衡 \(N\) 与 \(D\)。Kaplan 当时认为计算最优落在偏大模型一侧；Chinchilla 把同一句话改成两者近似等比例涨。两种说法共享「先看损失标度、再分配预算」的方法。

机制 ​

幂律从哪里来，论文本身没有给出从第一性原理推出的指数。经验上，过参数化网络在平滑损失面上的优化，常表现为对容量与样本量的幂次误差下降，视觉和语言里都见过类似形状。Kaplan 的指数应被当成对那一架构、那一数据分布、那一优化器的描述统计。换 tokenizer、换 MoE、换训练长度相对余弦周期的比例，指数会动。

\(C\approx 6ND\) 这一会计也很关键。它假设稠密 Transformer、几乎全部 FLOPs 花在线性层上，序列长度进入 \(D\) 的计数方式保持一致。激活重计算会改变墙上时间，但不改变这套 FLOPs 会计；混合精度改变的是吞吐，也不是 \(6ND\) 的系数来源。用 Kaplan 曲线做规划时，必须声明 \(N\) 是否含嵌入、\(D\) 是否计重复、 \(C\) 是理论 FLOPs 还是 GPU-hours。把下游分数直接拿去拟合幂律，噪声通常大于损失。同一损失对应的下游提升还随任务饱和而变。Kaplan 把标度对象定在交叉熵上，是为了让外推稳定；从损失再到任务，需要另一次校准，不能把 2020 年的指数套到某一项榜单上。

为什么计算最优会被写偏 ​

余弦学习率把「预定训练步数」编进日程：提早停，等于没走完退火；为了把大模型塞进预算，实验往往给大 \(N\) 更少的步数，日程也按更短的寿命来排。于是大模型看起来「用更少数据就很好」，一部分其实是小模型被训得更充分、大模型欠训。这不影响「损失随 \(N,D\) 下降」的定性结论，但影响给定 \(C\) 时 \(N\) 与 \(D\) 的最优分割。读 Kaplan 应用这条分割去定训练配方时，要把这一偏差记在旁边。

边界与工程取舍 ​

Kaplan 扫的是稠密自回归 Transformer 与当时的网络文本。稀疏 MoE、状态空间模型、多模态、以及重度重复的数据约束设定，都需要自己的拟合，不能直接套 2020 年的 \(\alpha\)。上下文长度变化会改变每个 token 的有效计算与激活显存，严格来说 \(C\) 的会计也要重写。

扩展律还假设优化成功。梯度爆炸、学习率过大、数据污染，会让点掉到曲线下方或上方，拟合会被少数失败 run 拽偏。小规模拟合再外推两个数量级，必须留误差带，而不是只给一个点估计。工业上后来用 Chinchilla 比例当计算最优的起点，再用过度训练把小模型推过计算最优点，以换推理成本——那是对 Kaplan 规划语言的续写，不是否定损失仍随尺度下降。「符合 Kaplan」有时被用来形容任何随对数参数下降的曲线。更精确的用法是：三项可分的幂律、计算会计约 \(6ND\)、以及他们那次拟合给出的偏大模型分配。后两项尤其不可未经说明就沿用。

小结 ​

  • Kaplan 等人 2020 年表明，语言模型损失随参数、数据、计算在很宽范围内呈幂律下降。
  • 三项中最紧的一项主导损失；给定计算时 \(N\) 与 \(D\) 互相挤占。
  • 他们建议的计算最优偏向前更大的模型、相对更少的 token，这一分割后来被 Chinchilla 修正。
  • 标度对象是语言建模交叉熵，不是下游任务本身。
  • 指数属于特定架构与数据，换 MoE、换重复数据或换日程都会动。
  • 学习率日程与训练长度耦合，是大模型显得更「样本高效」的原因之一。
  • 出处：Kaplan et al., Scaling Laws for Neural Language Models, 2020。
