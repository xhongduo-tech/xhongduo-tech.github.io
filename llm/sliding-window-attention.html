Sliding Window Attention ​

不必让每个标记看完整段历史；看最近一个固定窗口，再靠层叠把感受野撑开，长序列也能训、也能跑。

—— Mistral AI, Mistral 7B, 2023

Softmax 注意力的代价随长度二次膨胀，见 二次复杂度。滑动窗口把每个位置的可见集裁成最近 \(w\) 个标记，把一层的计算与 KV 缓存都变成与 \(w\) 成正比。Mistral 7B 把这一选择写进解码器主路径，窗口 4096，并用环形缓冲把推理缓存钉死在窗口大小上。Longformer 更早把滑窗当作稀疏图的局部底盘，但还叠加全局标记；本篇只讲「每层都是因果滑窗」这条主路径。膨胀步长见 Dilated Attention，局部加全局见 Local-Global Hybrid Attention，推理时切窗导致的汇点崩坏见 Attention Sink。

问题 ​

全注意力里，位置 \(t\) 看见 \(\{1,\ldots,t\}\)，一层就是 \(\Theta(t)\) 次点积，整段序列是 \(\Theta(n^2)\)。预训练 \(n\) 到 4K 尚可，到 32K、128K 时，激活与注意力分数都按平方涨，数据还没喂完先爆显存。更现实的观察是：多数 token 的有效依赖其实落在近邻——局部句法、最近实体、刚写出的公式。把远距离全部展开，大量权重接近零，却仍要占带宽。

服务端还有第二笔账。Decode 的 KV 随生成变长，即使用了 GQA，\(n\) 到数万时缓存仍可能大于权重。若架构保证每层只读最近 \(w\) 个键值，缓存上界就是 \(w\)，与生成了多长无关。这正是流式对话想要的常数显存。问题于是变成：裁掉窗口外的边之后，远距离信息还能否在层与层之间接力传递，以及窗口边界会不会切断关键证据。

方法 ​

窗口长度与感受野 ​

因果滑窗规定，位置 \(t\) 只与 \(j\in[t-w+1,t]\) 做注意力（左边界截断到 1）。一层的复杂度是 \(\Theta(n w)\)。单层确实看不见 \(t-w\) 之前的标记，但下一层的 \(t\) 会读到已经混合过更早信息的隐状态。与卷积相同，堆 \(L\) 层后理论感受野约为 \(L\cdot w\)。感受野是「理论上碰得到」，不是「无损传到」。每过一层都经过 softmax 与残差，远距离信号会被近邻淹没。Mistral 用 32 层乘 4096，纸面可达约 13 万标记，真实长依赖仍明显弱于全注意力。

\(w\) 的选取是质量与算力的直接旋钮。太小，一层内的指代都够不着；太大，又走回二次代价。Mistral 选 4096，与当时主流预训练长度同阶，等于「层内按短上下文工作，层间再拼长程」。训练必须用同样的掩码，不能全注意力预训练再在推理改窗——分布不一致会直接掉点。

滚动 KV 缓冲 ​

推理时不必保存 \(n\) 个键值。环形缓冲开 \(w\) 槽，位置 \(t\) 写入槽 \(t \bmod w\)。当 \(t>w\)，最老的键被覆盖。注意力只扫这 \(w\) 槽，decode 的带宽与显存都与生成长度脱钩。实现上还要保存位置编码所用的绝对或旋转相位，覆盖槽位不等于覆盖「逻辑位置」：\(t\) 与 \(t-w\) 占用同一槽，但 RoPE 的 \(\theta t\) 必须按逻辑 \(t\) 算，否则旋转错位。

环形缓冲与「保留整段 KV、只掩码窗口」等价于同一注意力图，但后者显存仍随 \(n\) 涨，失去滑窗的部署意义。工程上应把缓存大小当成架构承诺，而不是可选优化。掩码窗口只改可见集，不改存储。服务日志里若仍看到 KV 随对话变长，说明实现还是稠密缓存加带状掩码，滑窗的吞吐承诺没有兑现。

与因果掩码的关系 ​

滑窗是在因果下三角里再切一条带。掩码可以写成

\[M_{tj}=\begin{cases} 0 & t-w<j\le t\\ -\infty & \text{otherwise} \end{cases} \]

FlashAttention 一类内核支持带状掩码，不必物化 \(n\times n\) 矩阵。需要注意：预训练若用完整下三角，推理改带状，等于突然丢掉教师从未掩掉的远边，比「一开始就带状」伤得更重。反过来，窗口训练、推理改全注意力，多出来的边没有经过学习，也帮不上忙。滑窗是训练–推理必须对齐的结构选择，不是解码器插件。

机制 ​

局部 softmax 把质量重新归一化在窗口内。窗口外的键不仅是「看不见」，而是从未进入分母。于是出现与全注意力不同的校准：同样一个近邻 token，在全注意力里可能被远处的高分键压下去，在滑窗里会拿到更大权重。这解释了为何滑窗模型的短上下文语言建模可以很强，而「文档开头的约束」容易忘——开头早已滑出所有层的窗口，只能指望隐状态里还残留压缩后的痕迹。

层叠接力依赖残差。第 \(\ell\) 层的隐状态 \(h^{(\ell)}_t\) 含有对 \(h^{(\ell-1)}_{t-w:t}\) 的混合，因而间接含有更早位置。信号路径长度是 \(O(n/w)\) 跳，类似深层 CNN。跳数一多，梯度与信息都衰减。这与状态空间模型用线性递归传长程是不同机制：滑窗仍是选择式注意力，只是选择集被硬裁切。

边界与工程取舍 ​

滑窗最怕的任务是「答案在很早以前、且中间没有反复提及」。针测、法规条款引用、超长仓库里的单次定义，都会在窗口滚过之后丢失精确键。补救不是把 \(w\) 加到与 \(n\) 相等——那就取消了滑窗——而是混合全局层、全局 token，或改用 Native Sparse Attention 这类训练期就学选择的结构。

另一边界是注意力汇点。若推理用环形缓冲丢掉序列开头，softmax 会失去常驻高权重的锚，窗口内分布失真。StreamingLLM 用保留汇点 token 修补，见 Attention Sink。架构若在训练期就滑窗，汇点问题轻一些，但仍可能出现。

取舍：对话与代码补全这类局部性强的负载，滑窗几乎是免费的吞吐；需要整本书精确检索时，滑窗只能当局部底盘，必须加全局捷径。窗口大小应在目标硬件上按 prefill 显存与 decode 带宽联合选，而不是只看论文默认的 4096。环形 KV 把显存钉死之后，并发可以从「随对话变长而掉」变成平稳。代价是产品必须接受：用户把关键约束写在很早以前、中间从未回顾，模型可能已经看不见那句话。

小结 ​

  • 因果滑窗把一层注意力从 \(\Theta(n^2)\) 降到 \(\Theta(nw)\)，KV 缓存可钉在 \(w\)。
  • \(L\) 层纸面感受野约 \(L\cdot w\)，但是有损接力，不是全注意力的任意远边。
  • 训练掩码与推理环形缓冲必须是同一张图，事后改窗会分布偏移。
  • 短程语言建模往往几乎不掉点；精确远距离检索是主要失败模式。
  • 丢掉开头会诱发汇点问题，不能和「窗口淘汰」混成一件事。
  • 需要长程时，应走向局部–全局混合或原生稀疏，而不是无限加大 \(w\)。
  • 出处：Mistral AI, Mistral 7B, 2023；Beltagy et al., Longformer, 2020（滑窗作为局部底盘）；Child et al., Sparse Transformer, 2019。
