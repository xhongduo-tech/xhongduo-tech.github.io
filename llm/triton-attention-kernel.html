Triton 写注意力核 ​

用 Python 写出分块循环，编译器负责把块映射到 GPU 的并行层次与共享存储；注意力核因此可以在几天内对齐 FlashAttention 的 IO 结构。

—— Tillet, Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations, MAPL 2019

手写 CUDA 注意力要同时管正确性（在线 softmax）与硬件细节（warp、bank、MMA 布局）。Tillet 的 Triton 把并行模型收成：每个程序实例处理一块数据，tl.load / tl.store 带掩码，编译器插入共享存储与向量化。OpenAI 随后用它把 FlashAttention 写成可阅读的 Python，成为教学与研究里最常见的「可改的注意力核」。本篇写这条路径：Triton 的编程模型如何承载分块 SDPA，以及它相对 CUTLASS / 手写 CUDA 的边界。公式仍是 缩放点积，算法仍是 FlashAttention 的 IO 感知分块。

问题 ​

注意力的朴素 PyTorch 实现物化 \(S=QK^\top/\sqrt{d_k}\) 再 softmax，长度一长就炸显存。融合核必须在片上完成打分与加权，于是出现三重循环：batch/头、query 块、key 块。CUDA 里这三重循环要手工绑定到 grid、CTA、warp，还要处理半精度溢出、因果掩码、变长 padding。研究实验往往只想改一件事——窗口大小、额外偏置、不同的缩放——却被迫 fork 几千行生产核。

Triton 要降低的是「从伪代码到可跑核」的成本。它不声称自动推出最优注意力：块大小、循环顺序、是否把 \(K\) 转置成对 MMA 友好的布局，仍是作者的选择。它声称的是：这些选择可以用 Python 写出来，用 autotune 扫一组 BLOCK_M, BLOCK_N, BLOCK_D，编译器去管指针对齐与共享存储分配。问题从「会不会写 CUDA」变成「分块数学有没有写对」。

程序实例与掩码加载 ​

一个 Triton 程序实例通常对应注意力里的一个 query 块（再加 batch、头的索引）。tl.program_id 给出这块在网格中的坐标。加载 \(Q\) 的一块是矩形；加载 \(K,V\) 的一块时，序列尾部可能越界，必须用掩码把越界元素变成 0 或 \(-\infty\)，否则既读脏数据，也会把 softmax 污染。因果掩码是第二张掩码：query 下标小于 key 下标的位置在 softmax 前设为很大的负数。两张掩码写错，核会「能跑、数值 silently 错」——这是 Triton 注意力最常见的调试税。

Tillet 的贡献是编译栈与语言，不是 2022 年那篇 FlashAttention 论文。把 Triton 写成「OpenAI 的注意力算法」会张冠李戴。算法来自 Dao 等人的分块与在线 softmax；Triton 提供把该算法写短、并能在 Ampere 上较快落地的载体。

方法 ​

典型前向核的结构与 FlashAttention 伪代码对齐。对每个 query 块，在 SRAM（由编译器安排）或寄存器累加器里维护行最大值 \(m\)、指数和 \(\ell\) 与输出块 \(O\)。内循环每次加载一块 \(K,V\)：计算块分数 \(S_{ij}=Q_i K_j^\top \cdot s\)，按掩码改写，更新 \(m\)，把旧的 \(O\) 与 \(\ell\) 按 \(\mathrm{e}^{m_{\mathrm{old}}-m}\) 缩放，累加 \(\mathrm{softmax}\) 局部贡献。扫完 key 后归一化 \(O\)，写回 HBM。反向核要么保存中间，要么像 FlashAttention 那样重算块；教学实现常先写前向。

缩放 \(s=1/\sqrt{d_k}\) 乘在分数上。半精度路径里，块分数与 softmax 用 FP32 累加，避免 exp 溢出——这与 SDPA 的数值卫生相同，只是发生在 Triton 的 tl.exp 与 float32 累加器上。autotune 装饰器列出若干块大小与 num_warps；运行时按输入形状选一份最快的。变长序列用 seqlen 张量加掩码，而不是先 pad 再靠掩码浪费 MMA。

能写到哪一步、写不到哪一步 ​

Ampere 上，Triton 注意力可以接近当时的 FlashAttention 实现，因为瓶颈主要是 HBM 与较规整的 MMA，编译器足够好。Hopper 上，手写核开始用 TMA、WGMMA、warp specialization 把流水排满；Triton 的程序模型当时并不能把这些集体指令暴露成一等公民，于是出现「同一算法，CUDA 特化更快」的代差。这不是 Triton 写错了 softmax，而是并行层次的控制权仍有一部分留在编译器里。后来的语言扩展在补这条缝，但写核的人必须知道：Triton 注意力首先是可维护的 IO 感知实现，其次才是冲榜工具。

机制 ​

Triton 把每个程序实例看成 SPMD 的一块工人。编译器分析 tl.load 的范围，决定是否经过共享存储、如何向量化、如何插入同步。作者看到的是 NumPy 风格的块运算；GPU 看到的是 CTA 内的协同。注意力能融合，是因为内循环不把 \(S\) 写回全局内存：分数张量的生命周期被限制在这一实例里。这正是 FlashAttention 的 IO 命题，用语言约束而不是用手工 shared 声明来保证。

在线 softmax 的递推必须写在 Python 循环里，编译器不会从「我对整行做 softmax」推出分块算法。若有人在 Triton 里先对每个 key 块做局部 softmax 再相加，结果是错的。语言降低的是存储层次的样板，不降低对算法不变量的要求。tl.dot 映射到 Tensor Core（形状允许时），块大小选错会掉到较慢的路径，这就是 autotune 存在的理由。

调试 Triton 注意力，优先对齐数值而不是对齐 TFLOPS。用小尺寸、FP32、关掉因果，和 PyTorch 的 softmax(QK^T)V 逐元素比；再开因果、再降精度。占用率问题放在数值正确之后。静默的掩码错误会被「差不多快」掩盖。

与服务核、教学核的关系 ​

教学与研究：改缩放、加 ALiBi 偏置、改成滑动窗口，Triton 是最快的实验床。训练框架里的 SDPA 后端有时也会调用 Triton 或编译器生成的同类核。服务侧的分页、级联、ragged 调度，Triton 也能写，但页表间接引用与极端特化通常仍由 FlashInfer 一类 CUDA 库承担。合理分工是：新注意力变体先在 Triton 里证明质量与大致速度，再决定是否下沉到 CUTLASS 或手写。

边界与工程取舍 ​

Triton 核的启动仍有 Python / 运行时开销；极小张量上不如融合好的 cuDNN。编译缓存冷启动会卡第一次调用。错误信息有时停在编译器中间层，不如 CUDA 的行号直观。多 CTA 协同、持久化核、精细的生产者-消费者流水，表达力弱于 C++。许可证与运行时版本要与 PyTorch 绑定对齐，否则「本机可以、集群不行」。

不要把 Triton 当成与硬件无关的规范。同一份核在不同 GPU 世代上的块大小必须重 tune；把 autotune 表写死在 A100 上，到 H100 可能变慢。文档与教程里的注意力核默认连续布局、固定头维，接到真实训练还要处理 GQA、dropout、变长、以及反向与梯度检查点的交互。

Triton 的成功容易让人以为「所有核都该用 Python 写」。GEMM 主路径、卷积、以及要对齐 NVIDIA 集体指令的生产注意力，CUTLASS 与汇编级特化仍然在。Tillet 降低的是tiled 算法的实现门槛，不是取消存储层次。

小结 ​

  • Triton 用 SPMD 块程序与带掩码的 load/store，让 FlashAttention 式分块注意力可以写成短 Python。
  • 语言管共享存储与向量化；在线 softmax、因果掩码、缩放与精度仍由作者写对。
  • autotune 扫块大小与 warp 数，不代替算法正确性检查。
  • Ampere 上常接近手写 IO 结构；Hopper 集体指令上曾落后于 CUDA 特化，这是控制力边界，不是 softmax 边界。
  • 适合研究变体与教学；分页服务热路径往往再下沉到专用库。
  • 数值对齐应先于冲榜；掩码错误是静默的。
  • 出处：Tillet et al., Triton: An Intermediate Language and Compiler for Tiled Neural Network Computations, MAPL 2019；分块算法见 Dao et al., FlashAttention。
