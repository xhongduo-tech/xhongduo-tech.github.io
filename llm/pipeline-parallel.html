流水线并行 ​

把层按深度切开，微批在阶段之间流动；气泡、激活内存和权重版本，是三条一起要付的账。

—— Huang 等，GPipe；Narayanan 等，PipeDream；1F1B 调度

流水线并行（PP）把 Transformer 的层堆切成 \(P\) 段，每段放在不同设备上：第 1 段算前几层，把激活发给第 2 段，直到最后一段算出损失再反向传梯度。它切的是深度，不是隐藏宽，也不是 batch。单层仍然完整，因此与张量并行正交。朴素实现里同一时刻只有一段在忙，其余空转，利用率是 \(1/P\)。GPipe 用微批填满管道；PipeDream 用异步 1F1B 一类调度减气泡、并引出权重版本问题；Megatron 采用的 1F1B（one-forward-one-backward，亦称 PipeDream-Flush）在稳定段交替前向与反向，把激活内存从「所有微批」压到「约流水线深度」。本篇把这三种图像对齐，公式只保留工程上用的气泡与内存关系。

问题 ​

深度 \(L\) 很大时，即使 TP 已经把宽度切开，一层叠一层的权重仍可能单机放不下，且跨节点 NVLink 不够用、不能把 TP 组拉到很大。沿深度切开，阶段之间只传递边界激活，体积是 \(b\times s\times d\)，不是整层权重。这很适合节点间的 InfiniBand：通信次数少、每次是一块激活。

空转（气泡）来自依赖：阶段 \(p\) 必须等阶段 \(p-1\) 的前向激活，反向必须等 \(p+1\) 的梯度。\(P\) 段、只有 1 个 batch 时，前向填满要 \(P\) 拍，其中大量设备在等。微批数 \(M\) 把一个全局 batch 切成 \(M\) 份，让管道里同时有多份数据。\(M\) 太小，气泡比例大；\(M\) 太大，GPipe 式「先全部前向再全部反向」要把 \(M\) 份激活都存到反向开始，显存爆炸。问题是调度：如何在填满管道、限制激活内存、以及「反向用的权重是否仍是前向那一版」之间取点。

GPipe 的微批与气泡 ​

GPipe（Huang 等）把 batch 切成 \(M\) 个微批，每个阶段按 \(1..M\) 做完所有前向，再按 \(M..1\) 做完所有反向。管道填满后，前向阶段的气泡比例约为 \((P-1)/M\) 量级（精确写法随是否计反向、是否对称而略有出入，数量级如此）。\(M\gg P\) 时利用率接近 1。代价：每个阶段要缓存该阶段上 \(M\) 份前向激活供反向用，激活内存 \(\propto M\)。大模型的激活往往已经是显存主角，\(M\) 不能按「消除气泡」无限开。重计算可以丢掉中间激活、反向时重做前向，用算力换 \(M\) 的内存，是 GPipe 实践里的配套，不是调度本身。

微批切的是数据并行意义上的 batch 维，不是序列维。PP 不缩短上下文。有人用「pipeline batch」称呼 \(M\)，写配置时应区分 global batch、microbatch、以及梯度累积步数——三者乘起来才是优化器看到的 batch。

方法 ​

PipeDream（Narayanan 等）不再等所有前向前完。稳定工作时，每个阶段尽快做完一个微批的前向，立刻做另一个微批的反向——1F1B 的雏形。管道更满，气泡更小。异步带来权重版本：阶段 1 可能已经用新权重做了下一个微批的前向，而阶段 \(P\) 的反向梯度仍对应旧权重的前向。PipeDream 用权重暂存（weight stashing）让反向对上当时的前向版本，或接受滞后更新（类似异步 SGD）。前者内存换正确性，后者吞吐换收敛噪声。预训练大模型通常不能接受未加约束的异步噪声。

1F1B / PipeDream-Flush：引入周期，每个全局 batch 仍然同步更新一次权重。调度在预热填满之后，每个阶段交替「一个前向、一个反向」，最后冲刷管道。反向用的权重与该微批前向一致（同一版本），没有跨 batch 的异步。激活内存大约只需为「正在飞的 \(P\) 个微批」保留，而不是 GPipe 的 \(M\) 个——当 \(M>P\) 时这是实质节省。气泡仍约 \((P-1)/(M+P-1)\) 一类，靠 \(M\) 相对 \(P\) 足够大来压。

1F1B 如何压激活内存 ​

GPipe：阶段 1 在最后一个微批前向结束前，一直握着微批 1 到 \(M\) 的激活。1F1B：阶段 1 对微批 \(k\) 做完前向后，很快就能等到微批 \(k\) 的反向（在稳定段），激活可以释放。握着的份数与管道里未完成反向的微批数相当，约 \(O(P)\)。\(M\) 仍应大于 \(P\) 以填气泡，但内存不再随 \(M\) 线性涨（在理想实现下）。梯度累积与 1F1B 的边界：累积多个全局 batch 才更新时，权重版本仍然单一，只是优化器步更稀；不要和 PipeDream 的跨版本更新混为一谈。

交错流水（interleaved / virtual stages）：每张卡持有多层的不连续块，例如卡 0 既有层 1–2 又有层 9–10。逻辑阶段数大于物理卡数，气泡公式里的 \(P\) 变成更大的虚阶段数，填满更快。代价是阶段间通信次数增加、实现更绕。Megatron 用它在给定 \(M\) 下再挤一点利用率。

机制 ​

阶段边界传递的张量是激活（前向）与激活梯度（反向）。体积 \(2\times b_{\mathrm{micro}}\times s\times d\) 字节量级（含一来一回），每微批、每边界一次。总通信 \(\propto (P-1)\times M \times b_{\mathrm{micro}} s d\)。对比 TP 的每层 All-Reduce，PP 的次数少、每次可以很大，更耐跨节点延迟，怕的是气泡而不是单次带宽。\(P\) 过大时，即使 \(M\) 很大，边界次数和负载不均（最后一段含损失与输出头，往往更重）会让 step time 由最慢阶段决定。切段时应按 FLOPs 均衡，而不是按层数均分——输出嵌入、连接词表的头，常常值得单独算一笔账。

流水线的负载不均不能靠 All-Reduce 平均掉。DP 可以把慢卡的梯度等齐；PP 里慢阶段就是墙。MoE 层、超宽 FFN 应尽量均分到各段，而不是堆在同一阶段。

交错流水与气泡公式 ​

气泡占用的时间步，粗算前向预热 \(P-1\)、反向冲刷 \(P-1\)。总有用微批步约 \(M\)（前向）+\(M\)（反向）。比例 \((P-1)/M\) 是报告里最常见的近似。交错后用虚阶段 \(P_{\mathrm{v}}=vP\) 代入，\(v\) 为每卡虚阶段数，气泡相对变小，通信次数乘 \(v\)。当 \(M\) 已经很大，交错的收益变薄，只剩实现复杂度。小 \(M\)（显存不允许更多微批）时交错更值得。

数值：PP 不改变一层内部的求和顺序，比改 TP 度更接近比特可复现——前提是微批划分相同。微批大小改变会改 BatchNorm 一类统计（解码器预训练几乎不用 BN）以及 Dropout 噪声的粒度，损失曲线仍会漂。比较 GPipe 与 1F1B 的收敛，应固定 \(M\) 与全局 batch。

边界与工程取舍 ​

PP 不替代 TP：单层矩阵过大时，阶段内部仍要 TP。也不替代 DP：全局 batch 仍要靠 DP 或更大的 \(M\) 来凑。\(P\) 受层数整除约束；余下层要有明确归属。检查点按阶段存，扩缩 \(P\) 需要重切层到卡的映射。

PipeDream 式真正异步在 LLM 预训练里少见，因为收敛噪声与复现成本。若见到「无 flush 的 1F1B」，要问权重是否 stashing。不要把调度名字当成已经保证了同步 SGD。

激活重计算与 PP 强绑定：1F1B 已经压了 \(M\)，重计算再压层内中间激活。二者都加时，step 的 FLOPs 上升，通信掩盖关系会变——原本计算刚好盖住边界传输，重计算后可能又露出通信。调 \(P\)、\(M\)、重计算应看成同一组旋钮。

梯度裁剪的全局范数跨 PP 阶段：必须把各阶段局部范数平方求和再开方。只在最后一段裁剪，前面的层等于没裁。ZeRO 再叠上来时，归约网络是「PP 阶段 × DP 组」的乘积，漏一条边就会让 \(c\) 失效。

推理生成是逐步 decode，管道里没有 \(M\) 个微批可填，气泡接近 \(P-1\)，PP 对单请求延迟不友好。服务期常用张量并行或复制，流水线更多出现在离线批处理。训练期的 \(P\) 不能照搬到在线推理。

小结 ​

  • 流水线并行按深度切层，阶段间传激活；适合节点间带宽，怕气泡与阶段负载不均。
  • GPipe 用大 \(M\) 填管道，激活内存 \(\propto M\)；常配重计算。
  • PipeDream 用异步 1F1B 减气泡，但引入权重版本；预训练多用同步的 1F1B / Flush。
  • 1F1B 稳定段交替前向与反向，激活内存约 \(O(P)\)；交错虚阶段进一步压气泡、加通信次数。
  • \(P\) 与 TP、DP、重计算一起选；全局范数与检查点必须跨阶段定义清楚。
  • 出处：Huang 等，GPipe；Narayanan 等，PipeDream；Megatron 的 1F1B / interleaved 调度。
