InternLM3 ​

只用 4T 高质量 token 训 8B 指令模型，官方称相对同尺度常见 18T 级配方节省七成以上训练代价；同一检查点用系统提示在普通对话与长链深度思考之间切换。

—— 上海人工智能实验室，InternLM3-8B-Instruct 模型卡与 GitHub（2025-01-15）；无与 InternLM2 对等的综合 arXiv

InternLM3 是书生·浦语 2025 年 1 月 15 日开源的一代，目前公开权重是 InternLM3-8B-Instruct，面向通用对话与高阶推理。官方主张：在推理与知识密集型任务上超过 Llama 3.1-8B 与 Qwen2.5-7B 同档开源；预训练只用 4T 高质量 token，相对「同尺度常见配方」节省 75% 以上训练成本。第二个卖点是 双模式：长思维链深度思考 + 流畅短答，靠改 system prompt 切换，而不是两套权重。本篇以模型卡、OpenCompass 表和 Hugging Face config.json 为准；不要把 InternLM2 的 COOL RLHF 或 2.5 的 1M 窗口写成 3 的论文贡献——3 没有 2403.17297 那种总报告。

问题 ​

同尺度开源在 2024 年末已经卷到十兆 token 量级。再堆数据的边际 IQPT（每个 token 买到的智力）下降，上海 AI Lab 把叙事改成 数据效率：4T 精料打到别人 18T 的点（官方对比口径）。同时，推理模型（长 CoT）与助手模型（短延迟）在社区里常分成两个检查点，部署与路由都贵。InternLM3 要在一个 8B Instruct 里切两种行为。

工程上，8B 要能在消费卡量化跑（模型卡：4bit 约 8GB），又要在 RULER 4K–128K 平均分上能看。config.json 写 max_position_embeddings=32768，评测却报 RULER 到 128K——实现者必须同时读配置与评测协议，不能只看一个数字。

没有综合技术报告就不能编 COOL 的续集 ​

InternLM 仓库的 Technical Report 链接仍指向 InternLM2 的 2403.17297。3 的过滤规则、是否沿用 COOL、RL 算法、合成 CoT 比例均未成文。写 3 只能引用模型卡句子与可下载配置。

思考模式的评测表里 MATH-500、AIME2024 带星号，注明用 Thinking Mode。把带星的数学分去对 Qwen2.5-7B 的非思考分，不是同一协议。

方法 ​

公开方法很薄，能写实的只有这几层。数据：4T 高质量 token，官方称改进数据框架、提高 IQPT；具体去重、配比、合成比例 未公布。开源物是 Instruct 而不是 Base——社区看不到纯预训练检查点，无法把 4T 的损失曲线画出来。

结构以 config.json 为准（不要用 configuration 文件里的默认 32 层）：hidden_size=4096，num_hidden_layers=48，num_attention_heads=32，num_key_value_heads=2（极瘦 GQA），head_dim=128，intermediate_size=10240，hidden_act=silu，无偏置，词表 128512，rms_norm_eps=1e-5。RoPE：rope_theta=5e7，rope_scaling 为 dynamic、factor 6.0，max_position_embeddings=32768。这是可复现的实现约束，不是论文里的消融。

双模式：改系统提示，不改权重 ​

对话模式用书生·浦语身份的系统提示。思考模式换一段「竞赛数学专家、逐步严格推理、[[8192]] token 内作答、\boxed{}」类提示（文档示例）。同一 InternLM3ForCausalLM，行为差来自条件前缀。官方称之为开源里较早把「普通对话 + 深度思考」打进 一个通用检查点的做法。推理推荐 transformers ≥ 4.48，部署指向 LMDeploy / vLLM / SGLang，与 2.5 一样走实验室工具链。

OpenCompass 表只描述这一个 8B ​

模型卡表（节选，0-shot 除非注明）：CMMLU 83.1、MMLU 76.6、MMLU-Pro 57.6、GPQA-Diamond 37.4、MATH-500 83.0*、AIME2024 20.0*、LiveCodeBench 17.8、IFEval Prompt-Strict 79.3、RULER 4–128K 平均 87.9、AlpacaEval 2.0 LC 51.1。对比列是 Qwen2.5-7B-Instruct、Llama3.1-8B-Instruct、GPT-4o-mini。数字以 OpenCompass 当时配置为准，版本迭代会改分。

机制 ​

4T 相对 18T 的故事是 提高每个 token 的信息密度，机制上可能是更狠的过滤、更多合成推理、或两者都有——官方没拆开，不能写成已证明的定律。双模式的机制是 提示条件化策略：思考提示把解码推进长 CoT 区域，短提示把同一先验用在聊天分布。这与后来混合推理 MoE（思考/不思考作为模式开关）同类，但 InternLM3 是稠密 8B，没有专家分流。

GQA 2 个 KV 头对 32 个查询头，是非常省 KV 的设置；decode 带宽友好，表达力是否够靠 48 层和 10240 中间维补。相对 InternLM2 全系列较温和的 GQA，3 把 KV 头收到极瘦，这是 8B 单卡服务长评测时的不对称交易：省的是缓存，可能丢的是头间多样性。dynamic RoPE factor 6 与 \(5\times 10^{7}\) 基频是长窗外推的实现线索，RULER 报到 128K 说明他们在评测协议里做过超 32K 的压力测试，但 默认安全窗仍应以 32768 配置为准，除非模型卡另给 128K 权重文件。实验室同时强调「通专融合」：把通用对话数据与深度推理数据在训练里混起来，而不是先训助手再单独蒸馏推理模型；系统提示只是把已经学到的两种条件分布切出来。

仓库引用文献仍是 InternLM2 报告。论文号不能改写成 InternLM3。2 的 1.8B/7B/20B 与 3 的单一 8B Instruct 不是同一发布矩阵。

边界与工程取舍 ​

未开源 Base、未开源数据卡、未开源 RL 配方。不要把 MindSearch「搜一百页」或 7B-Chat-1M 安到 3 上。思考模式延迟和 token 账单会上去，产品若默认开思考会伤闲聊；文档示例还把思考预算写成约 8192 新 token，短答模式不应套这套 max_new_tokens。安全免责与 2 系相同：仍可能出偏激内容。许可以当时 Apache / 仓库 LICENSE 为准。官方 IQPT 叙事若成立，意义是「过滤与配比可以替代盲目堆 token」，但没有开放配比表，外部无法画同一条效率曲线，只能把 4T 当作发布约束而不是可复现实验。OpenCompass 五维（学科、语言、知识、推理、理解）是实验室惯用切分，与 Arena Elo 不是同一把尺。推荐推理栈仍是 LMDeploy 优先、transformers 作对照，与 2.5 的 1M 权重推荐同一工具链，但 3 并没有放出对应的 1M 检查点。

第三方若把 configuration 默认 32 层当成实物，会算错层数——必须以检查点旁的 config.json 为准（48 层、2 KV 头）。

「节省 75% 训练成本」是相对官方所指的同尺度常见 token 预算，不是相对你本地的某次 4T 复现。没有数据配方，成本数字不可审计。

小结 ​

  • InternLM3 公开核心是 8B-Instruct：4T 高质量 token、双模式系统提示、OpenCompass 对比 Llama3.1-8B 与 Qwen2.5-7B。
  • 可核对结构：48 层、GQA 32/2、词表 128512、配置窗 32K；RULER 评测到 128K。
  • 无综合 arXiv；过滤、对齐、合成比例均不可臆造。
  • 出处：上海 AI Lab，InternLM3-8B-Instruct 模型卡与 GitHub，2025-01-15；config.json。InternLM2 报告仍为 arXiv:2403.17297。
