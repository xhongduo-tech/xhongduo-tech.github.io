RMT Recurrent Memory ​

不必改 Transformer 内部：把记忆写成特殊 token，段尾写、段首读，梯度沿记忆向量跨段回传，有效上下文就不再被层数乘缓存长度卡住。

—— Bulatov, Kuratov, Burtsev，Recurrent Memory Transformer，NeurIPS 2022

Transformer-XL 把上一段各层激活整段缓存下来当记忆，容量随层数线性涨，有效跨段距离仍受「停梯度 + 层间阶梯」限制。压缩记忆 再加压实槽，对象仍是激活缓存。Bulatov、Kuratov 与 Burtsev 的 Recurrent Memory Transformer（RMT）换了一条更省的路：记忆不是层内 KV，而是加在输入两端的一组特殊 token；段与段之间只传递这组写记忆的输出表示。骨干可以是未改动的 Transformer，记忆读写完全落在序列的接口上。本篇钉 2022 年原文：token 记忆、段级循环、BPTT，以及它和 XL 缓存在容量与深度上的差别。后续把同一机制外推到百万 token 的工作只作为边界提及。

问题 ​

自注意力把全局与局部信息写进同一个位置表示。序列一长，主题、指针、算法状态被摊到所有 token 上，全局特征容易糊；同时分数矩阵随长度二次涨，实现上只能切段。切段之后，段与段之间若没有任何状态，复制、反转、联想检索这类必须看见「整段输入」的任务立刻失败。XL 的回答是缓存上一截激活：每层存 \(m\) 个向量，总记忆是 \(m\times N\) 量级，且查询只看见上一层的过去，有效上下文近似「层数 × 缓存长度」，不是无限磁带。

需要一种容量与层数解耦、又能跨段写全局状态的接口。外部记忆网络（NTM、Memory Networks）有读写头，但要改控制器；Memory Transformer 已经证明可以在输入里加全局 token，却在因果解码器上卡住——记忆若只放段首，写不进当前段；只放段尾，当前段读不到。问题因此是：在不改注意力核的前提下，让同一组记忆向量既被当前段写入、又被下一段读出，并且训练信号能穿过段边界。

因果掩码下的读写冲突 ​

解码器的下三角掩码禁止位置 \(i\) 看见 \(j\gt i\)。把记忆 token 放在段首，它们在本段里几乎只能看见自己和更早的记忆，收集不到本段内容；放在段尾，本段词可以写进记忆，但本段词自己读不到这份刚写完的记忆。单段里无法同时满足「读旧记忆、写新记忆」。RMT 把冲突拆到时间上：本段段首的读记忆来自上一段的写记忆，本段段尾的写记忆看完整当前段，再交给下一段当读记忆。

RMT 的记忆不是检索器，也没有离散地址。每个记忆 token 是 \(d\) 维连续向量，读写都经过标准自注意力。容量由记忆条数 \(m\) 和表示维度决定，不是由文档长度决定；文档再长，跨段状态仍是 \(m\) 个向量。

方法 ​

输入序列切成段。第 \(\tau\) 段的词嵌入记为 \(H_\tau^0\)。将同一组记忆表示 \(H_\tau^{\mathrm{mem}}\) 拼在段首与段尾：

\[\tilde H_\tau^0=\bigl[H_\tau^{\mathrm{mem}}\,\circ\,H_\tau^0\,\circ\,H_\tau^{\mathrm{mem}}\bigr]. \]

整段送进未修改的 Transformer，输出按同样切分

\[\bar H_\tau^N=\mathrm{Transformer}(\tilde H_\tau^0)=\bigl[H_\tau^{\mathrm{read}}\,\circ\,H_\tau^N\,\circ\,H_\tau^{\mathrm{write}}\bigr]. \]

下一段令 \(H_{\tau+1}^{\mathrm{mem}}:=H_\tau^{\mathrm{write}}\)，再做同样的首尾拼接。段内词与词之间仍用因果掩码；读/写记忆块内部允许互相看见，写记忆可以看全段。这样，段首记忆向当前词提供「上一段摘要」，段尾记忆把当前段压进固定槽。

只改输入输出的段级循环 ​

与 XL 对比：XL 每层缓存 \(m\) 个停梯度的过去激活，查询来自当前层、键值来自「缓存 ∘ 当前」；RMT 每段只存 \(m\) 个记忆向量，这些向量会再走一遍全部 \(N\) 层。记忆因此在段与段之间被反复编码，等效深度约为「段数 × 层数」，而不是 XL 那种「沿深度爬一层、沿时间走一段」的阶梯。实现上作者把 RMT 接在 Transformer-XL 代码之上，也可以把 XL 缓存当短时记忆、RMT token 当长时记忆，两者拼接。

训练用沿时间反向传播。与 XL 在段边界停梯度不同，RMT 让记忆上的梯度流入更早的段。展开步数是超参，原文扫 0 到 4 段；更深则显存涨，可用检查点缓解。展开为 0 时，记忆仍能前向传递，但写记忆学不到「怎样为下一段服务」。

算法任务上的分段协议 ​

复制、反转、联想检索被故意切成多段：答案在后段，证据在前段，模型必须把内容写进 \(m\) 个槽而不是指望当前窗口。损失只加在目标段，与解码器「先读后写」一致。二次方程式任务把题目、解答、答案切段，只评最后一段答案是否完全正确。这些设定强迫记忆成为唯一的跨段信道；没有记忆的基线在段数大于 1 时崩掉，用来标定「循环是否真的在工作」。

机制 ​

记忆 token 提供一块不对应任何输入词的表示容量，全局状态不必再糊在每个位置上。注意力可视化里，原文观察到可解释的读/写模式：写记忆在段尾集中看关键证据，读记忆在下一段被需要该证据的位置点名。这与「把 XL 缓存当作另一截普通上下文」不同——缓存是过去词的未压缩激活，记忆是模型自己维护的工作磁带。

为何更小的记忆能追上更大的 XL 缓存 ​

WikiText-103 上，记忆大小 10 或 25 的 RMT 可达到缓存 75 的 XL 附近的困惑度；段长缩到 50、循环步数增多时，1 个记忆向量的 RMT 可接近缓存 10 的 XL。XL 的「记忆大小 10」其实是每层 10 个向量、十六层就是 160 个状态；RMT 的 1 个记忆是穿过所有层、并经 BPTT 为未来段塑形的。压缩来自训练目标：语言模型必须靠这几个向量降低下一段损失，而不是靠把过去原样贴上。enwik8 上大小 5 的 RMT 与缓存 40 的 XL 接近，方向相同。

BPTT 是机制的一部分。只前向传记忆、不回传，等于让写记忆当常数，模型会退化成「略看一点边界」。原文图里，加深展开会降低困惑度，也带来训练不稳与显存墙。记忆条数从 1 加到 5 收益大，再加到 50 变钝：任务所需的工作记忆有饱和点，多出来的槽不一定被用上。

不要把 RMT 的 \(m\) 与 XL 的缓存长度用同一个数字对比。一个是跨层共享的 \(m\) 个 token，一个是每层一份的激活片段。比的应是「可见过去有多少、梯度能走多远」，而不是超参表上的整数。

边界与工程取舍 ​

RMT 理论上下文可以任意长，实践上限是记忆容量与读写是否学得会。复制任务上，固定记忆、加长序列，XL 先垮，RMT 更晚才降；但总长度到数百 token 之后仍会劣化，说明有损压缩不是无损日志。语言建模里，RMT 用更少槽追平 XL，并不自动等于「长文档问答更好」——WikiText 的局部 n-gram 统计仍占主导，算法任务才真正检验跨段指针。

把记忆插进已预训练的 BERT/RoBERTa/T5，在 Hyperpartisan 长新闻分类上，10 个记忆、多段微调可以超过许多 4096 窗口的稀疏注意力基线。这证明接口可以事后加上去，但分类任务的「多段编码」与生成任务的因果读写不是同一评测；不能把分类 F1 抄成生成记忆的定理。

2023 年后续工作把同一 token 记忆外推到百万 token 量级的合成依赖（复制、bAbI 一类），训练长度仍远短于测试长度。那是外推实验，不是把预训练语料真的做成百万窗口。与 Infini-Attention 的固定大小矩阵记忆也不同：Infini 用线性注意力累加，RMT 用 softmax 注意力写少数槽。

段内二次复杂度没有消失。RMT 省的是跨段状态，不是把 \(n\) 开到文档长度再做满注意力。部署时仍按段长 \(n\) 付 \(n^2\)，外加 \(2m\) 个记忆 token 的线性项。

何时不必上 RMT ​

窗口已经覆盖任务依赖、没有跨段指针，普通 Transformer 即可。需要无损回看最近若干词，XL 或滑动 KV 更直。需要把整篇压成可缓存的软提示并在检索语料上复用，那是 AutoCompressors 的累积摘要，不是每段只传一组覆盖写的记忆。需要改注意力核、从零训长程架构，RMT 的「不改骨干」优势用不上。

小结 ​

  • RMT 用段首读记忆、段尾写记忆的特殊 token 做段级循环，骨干 Transformer 可以不改。
  • 跨段只传 \(m\) 个向量；训练用 BPTT 让写记忆为后续段服务，有效深度随段数累积。
  • 算法任务上，段数增多时优于同等槽数的 XL 缓存；语言建模上更小的记忆可追平更大缓存。
  • 可与 XL 短时缓存并用；也可插到已预训练编码器上做长文分类。
  • 容量有界、段内仍二次；百万 token 外推是后续论文，不是 2022 年主实验。
  • 出处：Bulatov, Kuratov, Burtsev，Recurrent Memory Transformer，NeurIPS 2022，arXiv:2207.06881。
