# 博文方法

博文用于沉淀理解、实验和判断。先明确一个问题与先修知识，再把机制、代码与证据连起来；没有完成的实验保留为计划。

## 三层内容

**专题地图**组织概念、依赖和待解决的问题；**博文**回答一个边界清楚的问题；**项目报告**连接多篇博文与实际实现。专题提纲和任务书不进入已发表文章列表。

## 每篇文章的结构

1. 问题与先修：这篇要解释哪个缺口？
2. 机制：计算流程、必要公式、正确性条件与代价。
3. 源码：仓库、commit、入口和调用路径。
4. 实验：假设、基线、变量、环境、原始结果与复现步骤。
5. 结论：证据支持到哪里，失败、反例和未覆盖范围是什么。
6. 资料：靠近具体主张标注第一方论文或官方代码。

## 写作与发布

草稿放在仓库drafts目录，逐步补证据；主题入口放在专题页。只有经过核对、明确标记published的article进入文章列表。发布前运行内容检查与构建，再通过source分支的原有Pages流程发布。
