## 为什么从 UI/UX 设计讲起

上一节的「数字媒体与交互设计」是总纲，这一节落到今天最热门的细分职业：**UI/UX 设计**——互联网产品（App、网站、软件）的界面设计与体验设计。

从 2007 年 iPhone 重新定义「触屏」开始，UI/UX 设计在近二十年里成为设计行业最大的就业池：几乎每个互联网公司都有「UI 设计师」「UX 设计师」「交互设计师」。

理解 UI/UX，既是理解设计学的「当代核心」，也是通往产品经理、创业的一条现实路径。

## 1 UI 与 UX：两个常被混淆的概念

**UI（User Interface，用户界面）**：产品的视觉与交互呈现——按钮长什么样、页面怎么排、动效怎么走。UI 是「皮」：用户看得见、摸得着的部分。

**UX（User Experience，用户体验）**：用户使用产品全过程的整体感受——从「发现这个产品」到「完成目标」到「事后评价」。UX 是「骨+魂」：它决定产品「为什么这样设计、是否真的对用户有价值」。

<span class="marginnote">UI 与 UX 的关系常被比喻成「装修与房子」：UI 是装修（好看、精致），UX 是房子本身（格局、动线、采光是否合理）。一个「装修极美但格局糟糕」的房子，住进去很难受——这就是「UI 很美但 UX 很差」的产品：打开 App 惊艳，用起来处处别扭。反过来，格局好但装修差（UX 好 UI 差）也能住，但不够吸引人。<strong>成熟的产品「先 UX 后 UI」：先想清楚用户要什么，再设计它长什么样。</strong></span>

UI 与 UX 的分工在团队里体现为：UX 设计师负责「用户研究、信息架构、流程图、原型」——解决「做什么、为什么」；UI 设计师负责「视觉设计、设计规范、组件库」——解决「长什么样」。

小团队里常是一人身兼两职，但思维要分清。

## 2 从 UX 到 UI：设计流程的拆解

一个典型的 UI/UX 项目，流程是从「骨」到「皮」逐层落地：

**第一步：UX 研究**。用户是谁、要解决什么问题、竞品怎么做——用第三篇的方法（用户研究、需求分析）把「方向」定清楚。

**第二步：信息架构（IA）与流程图**。产品有哪些页面、信息怎么组织、用户怎么从一个页面走到另一个页面——画出「站点头图」（sitemap）与「流程图」（flow），这是产品的「骨架」。

**第三步：线框图（wireframe）**。用最简单的线条块面画出「每一页有什么」——不考虑颜色和字体，只确定「信息层级与布局」。线框图是「结构图」，让团队先确认「逻辑对不对」，再谈「好不好看」。

<span class="marginnote">「先线框、后视觉」是 UI/UX 的铁律，也是最容易违反的纪律：新手常一上来就「画得美美的」，结果评审时大家只讨论「好不好看」，没人看「逻辑对不对」。线框图的价值正在于「剥掉美观的外衣，让逻辑赤裸相见」——先用最丑的图确认结构，再花力气做视觉，才是高效路径。</span>

**第四步：交互原型（prototype）**。把线框图做成「可点击的假产品」——用 Figma、Axure 等工具，让用户「试玩」，验证流程是否顺畅。原型测试发现的问题，在写代码前修正（成本最低）。

**第五步：视觉设计（UI）**。确定风格、色彩、字体、组件——从「结构图」变成「视觉稿」。这里使用前面学的全部视觉语言：层级、对齐、留白、网格、色彩。

**第六步：设计系统与交付**。把视觉稿整理成「设计系统」——组件库（按钮、输入框、卡片）、颜色规范、字体规范，交给开发者实现。**设计系统是 UI 设计的「工业标准件」**：让多个页面、多个开发者产出「看起来像同一套设计」。

## 3 UI 设计的基本功：组件与规范

UI 设计看似自由，实则有一套「约定俗成的语法」。掌握这些基本功，是入门 UI 的第一步：

**核心组件（components）**：按钮、输入框、导航栏、标签页、卡片、弹窗、表单——每个组件都有「规范」：按钮有主/次/危险三种状态，输入框有「正常/聚焦/错误」三种状态，弹窗要交代「关闭方式与遮罩行为」。UI 设计师先「会做组件」，再「会做页面」。

**状态设计（states）**：一个元素不只是「静态一张图」，还有多种状态——正常态、悬停态（hover）、按下态、禁用态、加载态、空态（没有数据时显示什么）、错误态。**「状态完备」是好 UI 的分水岭**：新手只画「正常态」，老手把「所有状态」都设计清楚。

<span class="marginnote">「空态」是 UI 设计最容易被忽略却最重要的状态：一个新用户打开你的 App，首页「空空如也」——如果空态只是「一片空白」，用户会以为产品坏了；好的空态要「解释+引导」：「这里还没有内容」+「点击这里开始」。空态、加载态、错误态合称「三态」——把三态设计好的产品，才是「经过认真设计」的产品。</span>

**响应式与多端适配**：同一产品要适配手机、平板、桌面、不同屏幕尺寸——UI 设计要建立「栅格系统」（grid）与「断点」（breakpoint），让布局随屏幕「流动」。

还有**设计规范一致性**：一像素的对齐、统一的圆角半径、固定的间距系统（8pt 网格）——「细节的一致性」让产品显得「专业」。

## 4 核心辨析：UI 与 UX 的完整分工

| 维度 | UX 设计 | UI 设计 |
| --- | --- | --- |
| 对象 | 用户的整体体验 | 界面的视觉呈现 |
| 核心问题 | 用户要什么、怎么用 | 用户看到什么、怎么好看 |
| 产出物 | 研究、流程图、线框、原型 | 视觉稿、组件、设计系统 |
| 成功标准 | 任务完成、体验愉悦 | 视觉美观、识别清晰 |
| 时间定位 | 先（骨） | 后（皮） |

**辨析｜易错点：** 最经典的两个误区：一是「UI=UX」——把「做界面」当成「做体验」，做完视觉稿就以为「体验设计完成了」。事实上体验设计贯穿「研究—架构—原型—视觉—上线—迭代」全程，UI 只是其中一个环节。

二是「UX 很虚、UI 才是硬功夫」——认为「研究、流程」是虚的，「画得美」才是真的。事实上**对产品成败影响最大的恰恰是「虚」的 UX**：一个流程不顺、需求搞错的产品，UI 再美也救不回来；而「流程顺畅但不够美」的产品至少可用。

**UI 决定「第一印象」，UX 决定「长期使用」**——两者都重要，但权重不同。成熟的团队一定「UX 优先」，因为「结构错了，装修白做」。

<span class="marginnote">AI 时代 UI/UX 的分工正在被重写：AI 可以生成界面（文生 UI）、生成文案、甚至根据数据自动调整布局——「画 UI」的执行门槛骤降。但「判断 UX」的能力（研究用户、定义问题、评估方案）依然稀缺。这预示着 UI/UX 职业的重心将从「UI 的执行」向「UX 的判断」迁移——设计师更像「产品经理+体验架构师」，而「画图」越来越多由 AI 代劳。这与第四篇《设计与商业》《设计管理》的趋势完全一致。</span>

## 5 UI/UX 的评估与迭代

UI/UX 设计没有「一次到位」，它的生命在「迭代」：

**可用性测试**：让真实用户试用原型/成品，记录卡点（前面《设计心理学》讲过「5 用户测试」）。用数据发现「哪里卡住」。
**数据分析**：通过埋点看「用户在哪里流失」——注册转化率、跳出率、停留时长。数据指出「哪里有问题」。
**A/B 测试**：同一页面出两个版本（A 版按钮大、B 版按钮小），随机分给用户，看哪个转化高。**用「实验」代替「争论」**——「我觉得」不如「数据显示」。

<span class="marginnote">A/B 测试让 UI/UX 从「艺术判断」走向「科学实验」：两个设计方案的争论，不再靠「谁口才好」，而是靠「数据说话」。这与第四级《机器学习》的「评估驱动」、第九级《数据科学》的「假设检验」完全同构——设计的「经验主义」正在被「实验主义」取代。但要注意：A/B 测试能优化「指标」，却不能定义「方向」——「这个产品该不该做」仍是 UX 研究的判断，不是 A/B 能回答的。</span>

**延伸：给 UI/UX 新手的「入门路径」。** 想入门 UI/UX，有一条被验证过的「学习路径」可以参照：

- **第一步：学会「看」**——大量拆解优秀产品（App 的每个页面为什么这样排、按钮为什么在这、动效为什么这样走），用「分析」代替「观赏」。
- **第二步：学会「画」**——从「临摹」到「线框」：先把优秀界面「复刻」一遍（练手与眼），再画「自己的线框图」（练结构与逻辑）。
- **第三步：学会「做」**——用 Figma 等工具做「可点击原型」，请朋友「试玩」，观察他们的操作与困惑——「原型+测试」是入门最快的学习闭环。
- **第四步：学会「改」**——根据「测试反馈」迭代你的原型，一轮、两轮、三轮……「迭代」才是 UI/UX 的日常。
- **第五步：学会「想」**——回头看：为什么这个方案好？用户要什么？数据怎么说？从「会做」走向「会想」，是「初级」与「高级」的分水岭。

这条路径的本质是：**UI/UX 是「做中学」的学科**——看、画、做、改、想，五步循环，越走越深。

**回到本课的中心问题。** UI/UX 设计回答了「数字产品如何被设计」：不是「画界面」，而是「设计体验的完整链路」。

从研究到架构、从线框到视觉、从组件到设计系统，UI/UX 的每一步都在回答「用户怎么用、用了舒不舒服」——UI 决定「第一印象」，UX 决定「长期使用」。

它最核心的方法论，是「先 UX 后 UI」：**先想清楚「用户要什么」，再设计「它长什么样」**——结构错了，装修白做。

它也是最「实验主义」的设计门类：可用性测试、数据分析、A/B 测试——**让「数据」而不是「意见」来裁决设计**，这是 UI/UX 的现代性所在。

在 AI 可以「生成界面」的今天，UI/UX 设计的重心正从「画」转向「判断」——**会研究、会定义、会评估的「体验架构师」，将比「画图的 UI」更有未来**，这也是 UI/UX 在新时代的方向。

## 6 小结

- **UI** 是界面的视觉呈现（皮），**UX** 是使用的整体体验（骨+魂）；先 UX 后 UI。
- 流程：**UX 研究 → 信息架构 → 线框图 → 交互原型 → 视觉设计 → 设计系统**。
- UI 基本功：**组件、状态（含三态）、栅格与响应式、一致性**。
- UI 决定第一印象，UX 决定长期使用；「结构错了，装修白做」。
- 评估迭代：**可用性测试、数据分析、A/B 测试**——设计从经验主义走向实验主义。
