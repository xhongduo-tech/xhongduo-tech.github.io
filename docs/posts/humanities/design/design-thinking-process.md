## 为什么从「思维与流程」讲起

前面几节解决了「设计是什么、由什么构成」，但这还只是静态的解剖。

这一节要转入动态过程：设计师面对一个模糊的问题，如何一步步把它变成一件可用的产品？

20 世纪以来，设计界逐渐总结出一套可教的通用流程——**设计思维（design thinking）**。

它之所以重要，是因为它把设计从「天才的灵光一现」变成了「普通人也能训练的方法」，并因此在硅谷与商学院被广泛借用。

理解这条流程，等于拿到一张设计学的地图。

## 1 设计思维的提出与两种模式

**设计思维（design thinking）**：一种以用户为中心、通过迭代式探索来求解复杂问题的创新方法，由斯坦福大学 d.school 与设计咨询公司 IDEO 在 21 世纪初系统化推广。

<span class="marginnote">有趣的是，设计思维的思想源头远比它时髦的外表古老：20 世纪 60 年代赫伯特 · 西蒙（Herbert Simon）在《人工科学》里就把设计定义为「把现状改变为理想状况的智力活动」，并把设计学视为「关于人造物的科学」。d.school 不过是把西蒙的洞见流程化了。</span>

在谈流程之前，先分清两种截然不同的思维模式——它们对应大脑的两种工作方式：

- **收敛思维（convergent thinking）**：面对多个候选，逐步筛选、聚焦，得到唯一最优解。这是「缩小选项」的思维，评估、测试都属于此。
- **发散思维（divergent thinking）**：从一点向外生成大量可能性，暂不判断好坏。这是「放大选项」的思维，头脑风暴、生成概念都属于此。

**设计流程的本质，就是发散与收敛的交替节律**：先宽后窄、再宽再窄，如同呼吸。

许多失败的「设计」不是没有好点子，而是节奏错了——过早收敛，或发散过久无法落地。

## 2 经典流程：双钻模型

最流行的流程框架是英国设计委员会提出的**双钻模型（Double Diamond）**，它把一次设计展开为四个阶段：

```
  问题探索            定义          方案开发            交付
 ┌────────┐        ┌──────┐      ┌────────┐        ┌────────┐
 │  发散   │ ────▶ │ 收敛  │ ───▶ │  发散   │ ────▶ │ 收敛   │
 │ 发现问题 │        │ 定义问题│      │ 生成方案 │        │ 测试落地 │
 └────────┘        └──────┘      └────────┘        └────────┘
```

- **第一钻：发现（Discover）**。带着开放心态进入问题领域，做用户研究、田野调查、竞品分析，尽可能多地收集信息与洞察。目标不是答案，而是理解。

<span class="marginnote">这一阶段最容易犯的错误是「把解决方案当成问题」：用户说「我要一个更大的垃圾桶」，真正的问题可能是「我的垃圾没有方便的投放路径」。双钻模型强迫你先回到问题层，而不是一头扎进方案层。</span>

- **第一钻收口：定义（Define）**。从海量信息中提炼核心问题，写成一句清晰的问题陈述（problem statement）或「用户画像 + 需求 + 洞察」的组合。收敛的质量决定后续方向是否正确。
- **第二钻：开发（Develop）**。围绕定义好的问题疯狂生成方案——头脑风暴、草图、原型、多方案对比。这一钻要的是数量与多样性，先别急着否定。
- **第二钻收口：交付（Deliver）**。收敛到少数方案，做高保真原型、用户测试、迭代打磨，直至可上线/量产。

双钻模型的价值在于它显式地把**问题定义**与**方案解决**分成两个钻——大多数新手都在第二钻拼命，却忽略了第一钻：

**把问题问对，比把方案做对更值钱。**

## 3 流程中的三个关键活动

流程不是空壳，它由一组具体活动支撑。有三个活动尤其重要：

**活动一：用户研究。** 流程的第一步往往是观察与访谈。设计师要用移情能力理解用户真实处境，而不是预设用户想要什么。常见误区是把问卷数据当真相、把「用户说的」当「用户要的」——用户未必能准确表达自己的需求，观察行为往往比听信说辞更可靠。详见第三篇《用户研究》。

**活动二：原型与测试。** 设计是「尽早失败、快速迭代」的学问。原型（prototype）从纸面草图到可点击高保真不等，其目的不是「做一个接近成品的样品」，而是**用最便宜的方式验证一个关键假设**。

<span class="marginnote">这正是设计方法与软件工程的敏捷迭代、以及大模型领域「快速试错实验」共享的认识论：在真实反馈面前修正假设，比在脑中推演全局更高效。第四级《软件工程》的螺旋模型与双钻模型几乎是孪生兄弟。</span>

**活动三：决策与取舍。** 设计最终是一连串取舍：在功能、成本、时间、品牌之间反复权衡。好的设计师不是「全都要」，而是明确什么不可妥协、什么可以让步。

## 4 核心辨析：设计流程不是流水线

| 视角 | 理解 | 正确姿势 |
| --- | --- | --- |
| 线性流水线 | 做完一步再做下一步，不可回退 | 流程可回跳：测试发现问题就回到发现/定义 |
| 完美主义 | 一次把方案做完美再拿出来 | 早点让用户看到半成品，早反馈早修正 |
| 流程万能 | 走完流程就必然成功 | 流程是脚手架，质量仍取决于洞察与判断 |
| 用户原教旨 | 用户说的都是对的 | 用户研究要交叉验证，用户需要被引导而非盲从 |

**辨析｜易错点：** 双钻图容易让人误以为流程是「严格顺序的四步」。

实际上：**设计流程是迭代的、并行的、可回跳的**。

一次真实的项目里，你往往在「发现」时顺手做了「原型」，在「测试」时又发现了新的「定义」问题。

把流程当流水线，是初学者最常见的失败模式。

## 5 设计思维为何从设计界出圈

设计思维如今早已溢出设计界，进入管理、教育、政策制定领域。

它被追捧的原因可以归纳为三点：

1. **它提供了「处理模糊问题」的路径**。传统的工程与商业方法擅长优化已知问题，却不擅长界定模糊问题；设计思维恰好补上这一环——先发散探索、再收敛定义。
2. **它以人为中心**。在技术主导的组织里，设计思维提供了一种把「人的体验」放进决策方程的方法，与第三篇《人机工程学》《设计心理学》一脉相承。
3. **它强调行动而非空谈**。原型与测试让团队「用手思考」，用具体的物推进抽象的讨论。

但也要冷静：**设计思维不是万灵药**。

它对「问题模糊、用户可及、快速迭代」的场景有效；对高风险的物理工程、对需要长周期验证的科研，直接套用会显得轻率。

认识工具的适用边界，本身就是设计的成熟。

<span class="marginnote">这也提醒我们：设计学与第九级「系统科学」天然亲近——设计思维处理的正是复杂适应系统的「涌现式求解」；而它「先原型后完善」的路径，又与认知科学中「基于模型推理」的研究互为镜像。</span>

## 6 小结

- **设计思维**是以用户为中心、迭代求解复杂问题的方法论，源头可溯至西蒙的《人工科学》。
- 流程的本质是**发散与收敛的交替**；过早收敛是最常见的错误。
- **双钻模型** = 发现 → 定义 → 开发 → 交付，前两阶段专门用于「把问题问对」。
- 关键活动有三：**用户研究、原型测试、决策取舍**。
- 流程是**迭代可回跳**的脚手架，不是严格顺序的流水线。
- 设计思维对「模糊问题」有效，但不是万能方法。
