## 为什么从小型机开始

上一篇的 System/360 把计算机变成了「组织的基础设施」——但它的用户仍然只是「隔着玻璃窗」看机器运转的普通人。一个根本性的问题悬而未决：**计算机能不能属于一个人？** 1960 年代中后期，一场「反叛」开始了：DEC 等公司造出便宜得多、小得多、能让人坐在旁边交互使用的**小型机（minicomputer）**；与此同时，麻省理工等机构发明了**分时系统（time-sharing）**，让许多人同时共享一台机器、各自「独占」它的交互体验；而在这一切的余波里，贝尔实验室诞生了**UNIX**——一个至今仍在统治服务器的操作系统。<span class="marginnote">Ceruzzi 的第8章标题就叫「The Minicomputer」。他把小型机称作「向大型机的集中统治发起的第一次真正的反叛」——它的武器不是更强的算力，而是更低的门槛与更近的距离。</span>

这一篇的三条线索——小型机（硬件）、分时（软件）、UNIX（操作系统）——其实是同一个故事的不同侧面：**把「算力」从「组织的资源」变成「个人的能力」**。读懂这段历史，就理解了为什么今天的程序员可以在一台笔记本上编写、编译、运行一切。

## 1 DEC 与小型机的诞生：肯·奥尔森的「反 IBM」

肯·奥尔森（Ken Olsen）与哈兰·安德森（Harlan Anderson）1957 年在波士顿创立了**数字设备公司（DEC，Digital Equipment Corporation）**。奥尔森本是 MIT 林肯实验室的工程师，参与过 TX-0 晶体管实验机的研制——这段经历让他笃信：**计算机不必是大得吓人的神殿，它可以是一台「你愿意坐在它旁边」的机器**。<span class="marginnote">奥尔森后来有一句著名的「名言」：「没有理由让任何人想在家里放一台电脑。」——他后来为此懊悔不已，因为这句话成了 PC 时代最大的打脸现场。但它也从侧面说明：即使是小型机的先驱，也没能预见到「个人计算机」能走多远。</span>

1960 年，DEC 推出 **PDP-1**：售价约 12 万美元，只有一台大冰箱大小，配有键盘与阴极射线管（CRT）显示器——用户可以坐在它面前，敲击键盘、看着屏幕、即时看到程序运行的结果。这台机器上运行着最早的电子游戏之一《太空大战》（Spacewar!，1962），也孕育了后来「交互式计算」的文化雏形。

PDP-1 的价值不在性能，而在**「亲近感」**：它是第一台「让用户直接面对自己程序」的计算机。这听起来像常识，但当时的 IBM 大型机用户从未拥有过这种体验——他们只能把打孔卡交给操作员，然后等结果。<span class="marginnote">「交互」（interactive）与「批处理」（batch）是两种截然不同的文化：批处理里，人与机器隔着一层「排队」；交互里，人直接「对话」机器。DEC 押注交互，押中了整整一个时代。</span>

有趣的是，PDP-1 诞生于一个被《连线》杂志后来称为「计算机界文艺复兴」的实验室氛围：MIT 的年轻黑客们把它当玩具——在上面编游戏、写编辑器、试验各种「没用但好玩」的想法。**「玩」孕育了「用」**：从这些实验中走出了字符编辑器、文本处理、甚至早期的「互联网」雏形。DEC 的机器让「计算机可以被玩」，这个「可以被玩」的属性，日后成了个人计算机最强大的驱动力。

## 2 PDP-8 与 PDP-11：把「计算机」卖给单个用户

如果说 PDP-1 是小型的「原型」，那么 1965 年的 **PDP-8** 才是小型机的「爆款」：售价约 18,000 美元——比大型机便宜两个数量级——体积只有洗衣机大小，被当时的媒体称为「计算机界的甲壳虫汽车」。<span class="marginnote">PDP-8 的成功靠的是「砍配置」：指令集极简、内存很小、外设很少——但「够用」。这个「够用主义」后来被苹果、任天堂等无数公司反复证明：用户买的不是「最强」，而是「正好够 + 负担得起」。</span>

1970 年，DEC 推出 **PDP-11**，它拥有一个优雅的通用寄存器指令集，成为大学、实验室与工业企业最常用的小型机，也是 C 语言与 UNIX 最初的宿主平台。PDP 系列的累计销量以万计——对「一台大型机要卖给一个组织」的时代而言，这是天翻地覆。

DEC 与 IBM 的战略差异也值得品味：IBM 卖「完整解决方案」（机器 + 软件 + 服务 + 大客户经理），DEC 卖「便宜好用的机器 + 开放的接口」，把「怎么用」留给用户自己。<span class="marginnote">这个差异后来被总结成「开放生态 vs 垂直整合」之争——DEC 的开放，让大学与黑客可以自由摆弄机器，反而孵化出无数创新；而 IBM 的封闭虽稳，却在大客户之外失去了「草根创新」的土壤。这种张力在 PC 时代又重演了一遍。</span>

小型机带来的不仅是「便宜」，还有「新用户」：以前只有大公司与军方用得起计算机，现在实验室的研究员、大学的学生、医院的医生、甚至小企业的老板都能拥有。**「谁可以用计算机」的人群急剧扩张——这既是技术事件，也是社会事件**。它直接为下一篇的微处理器与个人计算机革命铺平了道路。

## 3 分时系统：把一台机器「分」给许多人

小型机把「近距离」给了少数人，而**分时系统（time-sharing）**想把「交互体验」给许多人——哪怕他们共享一台昂贵的机器。核心想法朴素：机器以极快速度轮流处理每个用户的程序，每个用户仿佛「独占」了整台机器。1959 年，MIT 的约翰·麦卡锡（John McCarthy）提出「计算机可以像电话一样按需使用」；1961 年，费尔南多·科巴托（Fernando Corbató）在 MIT 实现了第一个分时系统 **CTSS**。<span class="marginnote">科巴托后来说：分时系统把「机器时间」从「稀缺的特权」变成了「按需的自来水」。这个「计算即公用事业」的比喻，比云计算的宣传早了整整半个世纪——今天你在云端 `ssh` 到一台机器，本质仍是分时系统的精神后裔。</span>

分时的意义远不止「多人共用」：它改变了「人与程序的关系」。在批处理时代，用户写完程序要等几小时到几天；在分时时代，用户在终端上敲入命令，几秒钟内就能看到反馈——**「程序员的循环」从「提交—等待」变成了「输入—反馈」**，这个循环是现代软件开发方法的生理基础。没有它，就不会有「调试」「重构」这些如今理所当然的工作方式。

分时还有一个容易被忽略的附带发明：**终端（terminal）**。为了让远处的人也能交互，人们把「显示器 + 键盘」从主机上拆下来，用线连到各人的桌上——于是「远程使用计算机」成为可能。今天你在浏览器里登录一个网页后台、在手机上遥控家里的电脑，技术上都是「终端」思想的远亲。**分时把「人机交互」从「机房特权」变成了「桌面日常」。**

分时系统的极致尝试是 **Multics**（1965 年启动，MIT/GE/贝尔实验室三方合作）：它想把分时、共享、安全、数据库全部塞进一个宏大的操作系统。结果它庞大、缓慢、迟迟无法交付——但正是在 Multics 的废墟上，贝尔实验室的工程师们悟出了一个相反的哲学：**小的、简单的、能立刻跑起来的系统，远胜于宏大但永远完不成的系统。**

## 4 核心对比表：大型机、小型机与分时终端

把这一篇的三条线索放在一张表里，「谁在用、怎么用」的变迁一目了然：

| 维度 | 大型机（System/360） | 小型机（PDP-8） | 分时终端 |
| --- | --- | --- | --- |
| 典型价格 | 数百万美元 | 约 1.8 万美元 | 终端便宜、主机共享 |
| 用户 | 组织（大公司/军方） | 实验室、大学、小企业 | 大量终端用户 |
| 使用方式 | 批处理（排队） | 交互（坐机前） | 交互（终端共享） |
| 机器的所有权 | 组织拥有 | 个人/团队拥有 | 组织拥有、个人使用 |
| 代表性的「拥有感」 | 隔着玻璃窗 | 就在手边 | 独享虚拟机的错觉 |

这张表最发人深省的是最后一行：**「拥有感」不一定要靠「物理独占」——分时用「瞬间反馈」制造了「这台机器是我的」的错觉**。这个「体验上的独占」，正是后来云端时代「按需租用算力」的心理原型。

## 5 公式解析：分时轮转的响应时间

分时系统的核心机制叫**时间片轮转（round-robin）**：系统把时间切成固定长度的小片（quantum，通常几十毫秒），让每个用户按顺序轮流用一小片。若系统同时服务 $n$ 个用户、每片时长为 $q$，则一个用户两次获得 CPU 的间隔约为：

$$T_{\text{resp}} \approx n \times q$$

- **第一步，理解 $q$（时间片）**：它是每个用户一次最多能连续使用 CPU 的时间。$q$ 太小，则频繁切换、系统开销大；$q$ 太大，则用户等得久、交互感差——选择 $q$ 是「切换开销」与「响应延迟」的权衡。
- **第二步，理解 $n$（并发用户数）**：排队等待的用户越多，每个用户轮到一次就要等得越久。$n=10$、$q=50\text{ms}$ 时，用户最长要等约 $0.5$ 秒才能再轮到——这个量级恰好能被人类感知为「流畅」。
- **第三步，看为什么是「≈」**：真实系统还有进程切换（context switch）的额外开销、I/O 等待与优先级调度，所以响应时间是近似式，但数量级判断已经足够。

这个公式解释了分时系统为什么能「骗过」人脑：只要把轮转周期压到几百毫秒以内，人的操作与机器反馈之间就没有「等待感」——**「即时」不是真的快，而是「快过了人脑的感知阈值」**。这个「感知阈值」的思想，后来延伸到 60Hz 显示器、触屏响应与网络延迟设计里。<span class="marginnote">顺带一提，分时系统还发明了「多任务」的概念本身：一台机器同时「看起来」在跑多个程序。今天操作系统的进程调度、云计算的多租户隔离，都是分时思想的规模化与安全化。</span>

## 6 UNIX 的诞生：贝尔实验室的「反叛之作」

Multics 于 1969 年终止后，贝尔实验室的肯·汤普森（Ken Thompson）用一台闲置的 PDP-7 写了一个简化版的操作系统——最初只有「一个文件系统 + 一个进程模型」，小得可怜。丹尼斯·里奇（Dennis Ritchie）加入后，两人把它移植到 PDP-11，并起名 **UNIX**——谐音「Multics 的仇敌」（发音相近，故意反着来）。<span class="marginnote">UNIX 的名字本身就是个冷笑话：Multics 意为「多路、复杂」，UNIX 则暗示「单、简」。但历史证明：简单的那条路，笑到了最后。</span>

UNIX 的哲学，后来被道格·麦克罗伊（Doug McIlroy）概括成一句话：**「每个程序只做好一件事，程序之间用文本流协作。」** 于是有了「管道」（pipe）——把一条命令的输出直接接给另一条命令的输入，如 `cat file | grep xxx | sort`。这个「小工具 + 组合」的设计，让 UNIX 既简单又无比强大，也深刻塑造了今天 shell、命令行与「Unix 哲学」的传统。<span class="marginnote">今天你在终端里随手打的 `grep`、`sort`、`find`、`awk`，都是 1970 年代贝尔实验室「每个工具做一件事」哲学的直系后裔。这条「小而专」的设计线，一路延伸到 Kubernetes 的「每个容器只跑一个进程」。</span>

1972 年，里奇在 Thompson 的 B 语言基础上设计了 **C 语言**；1973 年，两人用 C 重写了整个 UNIX——**这是操作系统史上第一次用高级语言书写，让操作系统从此「可移植」**。UNIX 因此不再绑定某一种机器，而能编译到任何有 C 编译器的平台。这个「可移植性」的突破，为 UNIX 后来的横扫一切奠定了技术基础。

把 UNIX 诞生前五年的历程收拢成一张表：

| 年份 | 事件 |
| --- | --- |
| 1965 | Multics 项目启动（MIT/GE/贝尔实验室） |
| 1969 | Multics 终止；Thompson 在 PDP-7 上写出初版 UNIX |
| 1970 | UNIX 移植到 PDP-11，命名定稿 |
| 1971 | 贝尔实验室专利部用 UNIX 做文本处理，首份用户 |
| 1972 | Ritchie 设计 C 语言 |
| 1973 | 用 C 重写 UNIX，实现可移植 |

这张表最值得玩味的是 1971 年那一行：UNIX 的第一个「客户」，是贝尔实验室的专利与法律部门——他们要处理大量文本与排版。**一台为「程序员好玩」而生的操作系统，靠「处理文档」获得第一笔预算**——技术与商业的相遇，常常就是这样阴差阳错。

## 7 UNIX 的遗产：开源、BSD 与 Linux

由于贝尔实验室早期以近乎免费的方式向大学提供 UNIX 源码，UNIX 在学术界迅速传播，培养了一代计算机科学家。1970 年代末，加州大学伯克利分校在源码基础上发展出 **BSD**（Berkeley Software Distribution）；1983 年，理查德·斯托曼（Richard Stallman）发起 **GNU** 计划，打出「自由软件」旗号；1991 年，林纳斯·托瓦兹（Linus Torvalds）发布 **Linux** 内核——一个受 UNIX 启发、但完全独立实现的开源操作系统。<span class="marginnote">今天的服务器、云计算、超级计算机，绝大多数运行着 Linux——而 Linux 是 UNIX 精神的「开源版」：多任务、多用户、文本流、管道、一切皆文件。你手上这台「从极限到大模型」网站背后的服务器，很可能就跑在 Linux 上——你正踩在 1969 年贝尔实验室那个「小到可怜」的操作系统的肩上。</span>

UNIX 还留下了另一笔隐形财富——**程序员文化**：协作者通过邮件与补丁沟通、软件以「对他人有用」为荣、工具链公开共享。这些价值观后来演化为开源运动与整个 GitHub 时代。**从 PDP-7 上那个废弃的操作系统，到今天统治互联网的操作系统内核，UNIX 只做了一件事：把「简单」坚持到底。**

**辨析｜易错点：UNIX 不是「一个人一天写出来的」。** 流行的故事常渲染「Thompson 一周写出 UNIX」，但这只是「内核雏形」——完整的 UNIX（文件系统、进程、shell、工具链）是 Thompson、Ritchie 与贝尔实验室整个团队用数年时间迭代打磨的成果。「一周写出 UNIX」的神话，和「牛顿被苹果砸出万有引力」一样，把「灵感」与「工程」混为一谈。读懂技术史的第一课，就是把「发现时刻」与「长久的建造」分开看。

## 8 小结

- **小型机**（DEC PDP-1/PDP-8/PDP-11）把价格降到原来的百分之一，让「计算机可以属于个人/小团队」成为现实。
- **分时系统**（CTSS/Multics）用极快轮转制造「独占感」，把「提交—等待」的批处理变成「输入—反馈」的交互——现代开发方法的生理基础。
- **Multics 的失败**教会行业「简单胜于宏大」，直接催生了 UNIX。
- **UNIX**（1969）以「小工具 + 文本流 + 管道」的哲学，用 C 重写而获得可移植性，成为操作系统的「原典」。
- UNIX 的开放传播孕育了 **BSD、GNU 与 Linux**，并把「自由共享」变成程序员文化。
- 这一篇的主题是「算力从组织走向个人」——下一篇，这个趋势将推进到极致：一颗芯片装下整个计算机。
- 分时系统用「感知阈值」制造「独占」错觉，这个思想延续到显示器刷新率、触屏与云计算的延迟设计。
- UNIX 的「简单哲学」与开源文化，直接孕育了 GNU、Linux 与今天的整个开源生态。
- DEC 的「开放生态」与 IBM 的「垂直整合」之争，在小型机时代就预演了 PC 时代的格局。

在下一节，我们将看到「一台计算机」如何缩小到「一块芯片」——Intel 4004 微处理器、苹果与 IBM 的个人计算机革命，也就是《微处理器与个人计算机革命》。
