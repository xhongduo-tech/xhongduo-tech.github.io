## 为什么从冯·诺依曼报告开始

上一篇讲到，ENIAC 的程序是接线板上的插线，换一道题就要重插几天；EDVAC 与冯·诺依曼报告提出了**存储程序**原则——把程序当作数据，与数据一起存放在内存里。这一篇要做的，是把这个「原则」拆成一台机器的骨架：**冯·诺依曼体系结构**。它是此后七十多年几乎所有通用计算机的设计蓝图——从 1950 年代的 UNIVAC，到你口袋里的手机，再到云端训练大模型的 GPU 集群，都在某种意义上遵循这张 1945 年的图纸。<span class="marginnote">说「某种意义上」，是因为今天的计算机在细节上早已面目全非——缓存、流水线、多核、GPU 并行——但「程序与数据同存于内存、CPU 依序取指令执行」这一核心约定，仍然支配着绝大多数机器的基本运行方式。理解它，等于拿到了阅读任何一台现代计算机的总纲。</span>

冯·诺依曼报告并不是一本「教科书」，而是一份 101 页的工作草案；它被后人称作「第一份描述存储程序计算机的完整文献」。它的影响之所以如此之大，不在于每一个想法都是首创，而在于它**把零散的思想整合成了一份清晰、可执行的蓝图**。这一篇，我们细读这份蓝图。

## 1 冯·诺依曼：从布达佩斯到普林斯顿的跨界数学家

约翰·冯·诺依曼（1903—1957）生于布达佩斯的一个犹太银行家家庭，自幼展现惊人的数学天赋。他曾与爱因斯坦、哥德尔在普林斯顿高等研究院共事，30 岁出头就已是世界级数学家：他与奥斯卡·摩根斯坦合著的《博弈论与经济行为》（1944）开创了博弈论；他在量子力学的数学基础、遍历理论、算子代数上都有奠基性贡献；他还参与了曼哈顿计划，为原子弹的爆炸力学做了大量数值计算。<span class="marginnote">对计算机史而言，冯·诺依曼最特别的能力是「跨界消化」：他不只是数学家，还擅长把物理、工程与经济问题翻译成数学。他参与 EDVAC 项目时，对这种「数学 + 工程 + 战争」的交叉场景如鱼得水——这正是他能写出那份报告的原因。</span>

冯·诺依曼不是计算机的「发明者」，但他是把计算机「变成一门学科」的关键人物。他参与曼哈顿计划时，深切体会到手算与机电计算的极限，因此对「自动计算」有着比纯数学家更现实的需求。1944 年夏，他在火车站偶遇格尔斯坦中尉，得知摩尔学院的电子计算项目后立刻投身其中——这个「偶遇」被后世认为是计算机史最重要的巧合之一。

他还为战后的计算机写下了「程序」与「数值方法」的接口：他在报告中强调，机器不仅要会算，还要能运行**可自主决定下一步**的程序——即把「决策」也交给程序。这一条后来演化为「分支与循环」，成为一切编程语言的基本构件。可以说，冯·诺依曼不只是给了计算机一个「结构」，还给了它一个「灵魂」：让机器自己决定下一步做什么。

## 2 存储程序：把「程序」当成「数据」

冯·诺依曼报告最核心的命题只有一句话：**程序与数据以同样的方式，存储在同一个内存里**。这听起来平淡，却蕴含三个层层递进的革命性后果。

第一，**换程序不再需要改硬件**。ENIAC 换题要重插接线；而在存储程序机器里，换一段程序只需把新的二进制写进内存——「软件」由此成为独立于「硬件」的存在，也第一次成为一个可以被单独设计、销售、纠错的行业对象。<span class="marginnote">「软件」这个词要到 1950 年代末才由约翰·图基（John Tukey）正式造出，但它的「物理前提」在 1945 年就已成立：<strong>只要程序是内存里的数据，程序就可以被买卖、被复制、被演化</strong>。</span>

第二，**程序可以读取程序**。既然程序是数据，一段程序就可以把另一段程序当作输入来处理——这听起来像绕口令，却是编译器的原理所在：编译器就是一个「读入程序、输出另一段程序」的程序。而「自我修改的程序」也由此成为可能，虽然现代工程中它被视为危险行为，但它在理论上的存在，正是「程序」这个概念开放性的根源。

这一条还有更日常的一面：**文件、文本、数据与程序在内存里「长得一模一样」**——都是内存里的字节。这正是现代操作系统里「一切皆文件」、以及「任何二进制都能被任何程序解读」的底气所在。今天我们把一个 JSON 传给另一个 API，本质上与「一段程序读取另一段程序」是同一件事：**内存不区分「代码」与「数据」，是程序员得以灵活调度的根本自由，也是安全漏洞的根源。** 这个「不区分」的双刃剑属性，从 1945 年就注定了。

第三，**程序是可计算的对象**。既然程序是数据，那么「程序」本身就可以作为另一台通用机器的输入——这直接通向图灵机：一台通用图灵机可以模拟任何其他机器，因为它能把「描述其他机器的程序」当作数据读入。**存储程序原则与图灵机「通用性」之间的关系，是计算机科学史上最深刻的呼应之一。** 这一呼应也解释了为什么「可计算性」理论（见本博客第七级《可计算性理论》）与「实际计算机」能共享同一个词汇表——因为它们共享同一个本体论前提：程序即数据。

## 3 冯·诺依曼体系结构：五大部件与取指—执行循环

冯·诺依曼报告把一台存储程序计算机拆成五大部件，这个清单至今仍是计算机组成教科书的标准框架：

- **运算器（ALU）**：执行加、减、乘、除等算术与逻辑运算。
- **控制器（Control Unit）**：解读指令、指挥其他部件协同工作。
- **存储器（Memory）**：同时存放程序与数据，按地址读写。
- **输入设备**：把外部信息送进机器（卡片读入机、键盘等）。
- **输出设备**：把结果送出来（打印、显示等）。

五大部件靠两条通路连接：**数据通路**传送数值，**控制通路**传送指令与地址。CPU（控制器 + 运算器）与内存之间只有一条共享总线——这既是它的简洁之处，也是它的瓶颈所在。

一台存储程序机器的运行，可以概括为**取指—执行循环（fetch–execute cycle）**：控制器从内存取出下一条指令，译码，执行，再取下一条……周而复始。<span class="marginnote">这个循环的关键在于「程序计数器」（PC）：它保存「下一条指令在内存里的地址」，普通指令执行完就 PC+1 指向下一条，遇到跳转指令则把 PC 改成指定地址。现代 CPU 里仍保留着 PC 寄存器——它是「程序的顺序性」在硬件上的唯一化身。</span>

取指—执行循环看似简单，却隐含一个深刻的哲学事实：**程序是「时间上依次发生的动作序列」，而内存是「空间上并列存放的字节集合」**——取指循环就是「时间」与「空间」之间的翻译器。CPU 每秒钟做几十亿次这样的翻译，把「摆在那里的数据」变成「按部就班的动作」。现代计算机所谓「运行一段程序」，本质就是让这个翻译循环转得足够快。

这个「顺序执行」的朴素模型还定义了「图灵完备性」的底线：只要机器能取指、能执行有限条基本指令、能在内存里读写，它就能模拟任何算法。**冯·诺依曼机器因此在理论上等价于图灵机**——这正是「冯·诺依曼体系结构足以支撑通用计算」的数学依据。从巴贝奇的分析机到今天的 CPU，这条「取指—执行」的底线从未被突破。

值得注意的是，这个「取指—执行」结构本身并不复杂——复杂的是指令的编码、内存的层次与流水线的调度。**冯·诺依曼报告的智慧，恰恰在于把复杂度留给了「怎么做」，而把「做什么」收敛到了一个极简的框架里。** 这使它既能被 1949 年的 EDSAC 造出来，也能被 2026 年的芯片继续沿用。

## 4 核心对比表：分析机、ENIAC 与冯·诺依曼机

把三代「通用计算」的设想并列，冯·诺依曼报告的独特之处就一目了然：

| 特征 | 巴贝奇分析机 | ENIAC | 冯·诺依曼机 |
| --- | --- | --- | --- |
| 存储 | 仓库（卡片读数） | 电子管寄存器 | 统一内存 |
| 程序载体 | 穿孔卡片（外部） | 接线板插线 | 内存中的数据 |
| 换题方式 | 换卡片 | 重插接线（数天） | 写入内存（秒级） |
| 条件分支 | 有（卡片跳转） | 无（纯顺序） | 有（跳转指令） |
| 数制 | 十进制 | 十进制 | 二进制 |
| 建成年代 | 未建成 | 1945 | 1949 起（EDSAC 等） |

这张表最扎眼的对照在「换题方式」一行：**从「数天」到「秒级」的跃迁，不靠任何物理速度的提升，而只靠一个结构决定——程序住进内存**。这也是为什么冯·诺依曼体系结构被称为「计算机的宪法」：它改变的不是速度，而是「可能性的空间」。

## 5 冯·诺依曼瓶颈：共享总线的代价

「程序与数据共用一个内存」这一设计，也带来了一个著名的代价——**冯·诺依曼瓶颈（von Neumann bottleneck）**：由于 CPU 与内存之间只有一条总线，取指令、取数据、写结果都必须排队通过同一条路，内存带宽常常成为整机的短板。

这个瓶颈在 1950 年代并不显眼——那时 CPU 和内存一样慢。但摩尔定律让 CPU 越来越快，内存相对越来越慢，「内存墙」逐渐成为性能的主要天花板。计算机工程师为此发明了层层对策：**缓存（cache）**把常用数据搬到 CPU 旁边，**流水线（pipeline）**让取指与执行重叠，**多核**让多个 CPU 并行工作，**GPU** 用上千个线程同时喂饱一个巨型计算单元。<span class="marginnote">有意思的是，「并行处理」的一大动机正是绕开冯·诺依曼瓶颈：与其让一个 CPU 等待内存，不如让很多 CPU 一起忙。今天训练大模型的并行策略，本质仍是「对抗内存带宽不足」的延续。详见本博客第四级《并行计算》与《GPU 编程》专题。</span>

有人据此主张「冯·诺依曼体系结构已经过时」，但更准确的判断是：**它从未被推翻，只是被各种技术「绕过」**。你手机里的 ARM 芯片、云端的数据中心，都还在执行取指—执行循环；所谓「非冯·诺依曼」的神经网络芯片，也大多仍靠内存与计算单元的数据搬运工作。**理解瓶颈，比空谈推翻它更有用。**

## 6 谁「发明」了存储程序：一场史学公案

存储程序思想并非冯·诺依曼一人的独创——这大概是计算史上最著名的一场归属争论。摩尔学院的埃克特与莫奇利在 1944—45 年已经提出过类似想法；英国数学家图灵在 1945 年给国家物理实验室的「ACE」报告中，也已包含程序作为数据存储的设计；甚至 ENIAC 早期也有过「把函数表当程序用」的萌芽。

史学界对此的态度，大致可以概括为三句话：**图灵与埃克特/莫奇利各自孕育了类似思想；冯·诺依曼以最清晰的形式把它系统化并写成了广为流传的报告；而报告以冯·诺依曼个人署名、未列团队名单，是这场争论的直接导火索**。<span class="marginnote">这场争论至今没有「标准答案」，但它留给技术史的启示很实在：<strong>重要的往往不是「谁第一个想到」，而是「谁让思想成为可建造、可传播、可执行的蓝图」</strong>——这正是「从极限到大模型」里反复强调的「想法 × 实现 = 变革」。</span>

不管归属如何，结果是明确的：1949 年英国剑桥的 **EDSAC** 成为第一台投入实际服务的存储程序计算机（威尔克斯团队，直接借鉴了冯·诺依曼报告）；此后美国洛斯阿拉莫斯的 **IAS 机**、雷明顿-兰德的 **UNIVAC**、IBM 的 **701** 相继问世。**从 1945 年的「报告」到 1952 年的「产业」，存储程序只用了七年就完成了从思想到现实的转变。**

用一张时间表把「从报告到产业」的七年后半段收拢：

| 年份 | 里程碑 |
| --- | --- |
| 1945 | 冯·诺依曼《EDVAC 报告草案》（6 月） |
| 1946 | 摩尔学院暑期班宣讲存储程序思想 |
| 1947 | IAS 机立项（冯·诺依曼主持） |
| 1948 | 曼彻斯特「宝贝」机试运行（小规模存储程序） |
| 1949 | 剑桥 EDSAC 投入服务 |
| 1951 | UNIVAC I 交付，第一台商用存储程序机 |
| 1952 | IBM 701 交付，正式踏入电子计算业 |

这张表还透出一个容易被忽略的细节：**「存储程序」从纸面到硅片只用了七年，而它从概念到被公众理解，用了更长的时间**。1947 年，美国《大众机械》杂志还在问「为什么需要计算机」——技术超前于理解，是计算机史上反复上演的节奏。

## 7 小结

- **存储程序原则**：程序与数据同存于内存——「软件」由此成为独立于「硬件」的存在。
- 存储程序使「程序读取程序」成为可能，这是**编译器**的原理，也通向图灵机的**通用性**。
- 冯·诺依曼体系结构 = **运算器 + 控制器 + 存储器 + 输入 + 输出**，靠**取指—执行循环**运转。
- **冯·诺依曼瓶颈**（共享总线）塑造了缓存、流水线、多核与 GPU 的演进方向，但框架本身从未被推翻。
- 存储程序思想的归属是**多方孕育、一人整合**的史学公案，但 EDSAC/UNIVAC/IAS 用七年把它变成现实。
- 冯·诺依曼报告是「第一份完整的存储程序计算机蓝图」——它是现代计算机的「宪法」。
- 内存「不区分代码与数据」是一把双刃剑：既赋予程序员调度自由，也是安全漏洞的根源。
- 「程序即数据」使可计算性理论与实际计算机共享同一本体论，这正是图灵机与真实机器的连接点。
- 冯·诺依曼机器在理论上等价于图灵机——「取指—执行」是通用计算的最简底线。
- 「程序与数据在内存里长得一模一样」让「一切皆文件」成为可能，也埋下了安全问题的种子。

在下一节，我们将看到冯·诺依曼机器的物理实现如何从「一只电子管」走向「一颗芯片」——晶体管、集成电路与 IBM System/360，也就是《晶体管、集成电路与 IBM System/360》。
