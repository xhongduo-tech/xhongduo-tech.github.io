## 为什么从医疗数据分析讲起

EHR 累积了海量数据，第4篇前面的 NLP 让文本变结构化，CDSS 与循证给了「决策的骨架」——这一章把这些汇成「用数据建模预测」。**医疗数据分析与机器学习**回答：如何从历史数据中学出「谁有风险、什么方案有效、何时该预警」，并把它部署进临床。它与第1篇《概率推理》一脉相承（预测模型本质是估计后验概率），又是第4篇《转化生物信息学》《临床研究信息学》的方法底座。但医疗 ML 有它独特的难题——数据是「为临床记的」、人群高度异质、错误代价极高。<span class="marginnote">对「从极限到大模型」主线：这一章是「机器学习在医学的落地学」——模型、指标、偏倚、部署，每个环节都被医学语境重新校准，是 ML 通用技能在生命健康领域的专业翻译。</span>

## 1 医疗数据的特点与建模挑战

医疗 ML 与「干净的数据竞赛」不同，它的原料有四个先天特点：

**数据为临床而记，非为研究而采**：字段缺失、记录不完整、采样偏倚（病情重的人检查多）——「数据产生机制」本身带有系统性偏差。

**纵向与时序性**：患者数据是多次就诊的纵向序列，单次快照会丢失病情演变信息；但「时间轴正确建模」（哪些是历史、哪些是结果）很容易出错。

**事件稀疏与类不平衡**：罕见病、罕见事件（院内死亡、某种并发症）正样本稀少；「预测罕见事件」需要专门处理类不平衡。

**高维异构**：诊断、用药、化验、影像、文本、时序混合——特征维度高、类型杂、缺失多。<span class="marginnote">这些特点共同决定了医疗 ML 的「气质」：<strong>不做「调参竞赛」，做「因果意识」</strong>——建模前先问「这个特征与结局的相关性会不会是混杂造成的」，模型之外要配套数据治理（呼应第3篇）。</span>

**数据代表性（data representativeness）** 是另一个前置问题：用某三甲医院的数据训练，模型能推广到基层医院、其他地区、其他人种吗？**样本与目标人群的偏移**是医疗 ML 最常见的失效根源。

## 2 公式解析：逻辑回归——医疗预测的常青模型

医疗预测模型（再入院、脓毒症、死亡风险）使用最广的基础模型是**逻辑回归（logistic regression）**。设患者特征向量为 $\mathbf{x} = (x_1, \dots, x_p)$，模型预测结局 $y \in \{0,1\}$ 的概率：

$$
P(y=1 \mid \mathbf{x}) = \sigma(\beta_0 + \beta_1 x_1 + \cdots + \beta_p x_p) = \frac{1}{1 + e^{-(\beta_0 + \beta^\mathsf{T}\mathbf{x})}}
$$

- **第一步，理解线性部分 $\beta_0 + \beta^\mathsf{T}\mathbf{x}$**：特征的加权和——每个特征 $x_i$ 乘一个系数 $\beta_i$，加上截距 $\beta_0$。它把「多因素」压成一个实数。
- **第二步，理解 Sigmoid 函数 $\sigma(z) = 1/(1+e^{-z})$**：把任意实数 $z$ 映射到 $(0,1)$ 区间——压缩成概率。$z$ 越大，概率越接近 1。
- **第三步，理解系数 $\beta_i$ 的含义**：$\beta_i$ 的符号与大小反映「特征 $x_i$ 对结局的正/负影响」——这在医学里尤其宝贵：**逻辑回归天然可解释**，医生能看到「年龄每增 10 岁，风险系数多大」。
- **第四步，理解「log-odds 线性」**：对式子变形得 $\ln\frac{P}{1-P} = \beta_0 + \beta^\mathsf{T}\mathbf{x}$——**对数优势是特征的线性函数**。这正是逻辑回归「回归」二字的由来，也让它与第1篇《概率推理》的「先验优势 × 似然比」在数学上同源。<span class="marginnote">逻辑回归与优势比（OR）天然衔接：系数 $\beta_i$ 取指数 $e^{\beta_i}$ 就是该特征的优势比——「吸烟 vs 不吸烟的患病优势是 2.1 倍」。这种「模型输出直接对应临床语言」的特性，让逻辑回归至今仍是临床风险评分的首选骨架。</span>

**重点：** 现代医疗预测常用更强的模型（随机森林、梯度提升、深度网络），但逻辑回归的三点遗产永远适用：**可解释、可校准、可验证的基线与参照**。新模型首先要「跑赢逻辑回归」，再谈复杂度。

## 3 模型评估：区分度、校准与临床效用

医疗 ML 的评价比「准确率」深得多，三组概念必须分清：

**区分度（discrimination）**：模型能否把「会出事的」与「不会出事的」分开。核心指标是 **AUC（ROC 曲线下面积）**——0.5 是随机，1 是完美；医学模型 AUC 0.7–0.9 属常见水平。<span class="marginnote">ROC 曲线是「以假阳性率为横轴、真阳性率为纵轴」画出的曲线，AUC 是曲线下面积——它不依赖阈值，衡量的是「排序能力」：随机抽一对正负样本，模型把正样本排前面的概率。AUC 高只代表「排得对」，不代表「概率报得准」。</span>

**校准（calibration）**：模型报的「风险 30%」的人群，真实事件率是否接近 30%？校准差的模型会把人群错误分层——**这是医疗 ML 与通用 ML 的最大差别**：给「真实风险 5%」的人报「40%」，可能驱动过度治疗。

**临床效用（clinical utility）**：模型提升了决策质量吗？要在**特定阈值 + 特定决策点**下评估净获益（如「每拦截 100 例非必要入院，漏掉多少真需要入院的」）——用**决策曲线分析（DCA）** 等工具。<span class="marginnote">决策曲线分析把「模型的净获益」画成阈值的函数，并与「全部治疗」「全部不治疗」两个基线比较——它回答「模型在什么阈值下真的值得用」，是连接「指标好看」与「临床有用」的桥梁。</span>

**辨析｜易错点：** **AUC 高 ≠ 临床有用**。AUC 忽略阈值与代价，一个「排序很对但概率偏斜」的模型可能临床无效。评价医疗 ML 的完整证据链是「区分度 + 校准 + 临床效用」三件套。

## 4 医疗 ML 的偏倚与公平性

模型从数据学，也学进数据的偏倚：

**数据偏倚（data bias）**：训练数据若对某人群欠采样，模型对该人群预测不准——「代表性不足」的人群（少数族裔、老年、语言障碍者）风险最大。

**标签偏倚（label bias）**：结局标签本身的定义与获取方式有偏（用「入院作为结局」可能只反映「谁更易被收治」而非「谁更病重」）。

**决策偏倚与反馈回路**：模型若被用于决策，其预测会改变后续数据（医生看到高风险预测更积极干预，结局改善，反过来「证明」模型准）——这类循环偏倚极难察觉。<span class="marginnote">经典的反馈回路案例：模型预测「哪些患者该加强监护」→ 高风险的被重点照顾 → 结局改善 → 模型误以为「高风险者结局好」→ 下次把他们都当低风险。医疗 ML 的部署必须监测这种「预测影响现实」的反身性。</span>

**公平性治理**：模型上线前应做**亚组表现审计**（按年龄/性别/民族/保险分层的区分度与校准对比），识别并缓解系统性偏差。公平性不是「事后慈善」，而是医疗 ML 的工程要求——因为它直接关系「医疗资源是否被公平分配」。

## 5 从模型到临床：部署的最后一公里

「离线指标好」到「临床真的用」，隔着最后一公里的工程挑战：

**实时数据管道**：模型要消费 EHR 实时数据（当前生命体征、最新化验），数据接口的稳定性与延迟决定模型能否「在决策点及时给出预测」。

**告警整合与工作流嵌入**：预测结果要以「不打断、可理解」的方式呈现（分级提醒、仪表盘、风险分层队列），嵌入临床工作流（呼应 CDSS 的干预分级）。

**持续监测与再训练**：人群与流程会变，模型要定期做**漂移监测**（输入分布漂移、校准漂移）并再训练——「模型上线」是持续运维的开始，不是结束。<span class="marginnote">这与「从极限到大模型」主线的 MLOps 完全同构：数据监控、模型版本、回滚机制、A/B 测试——医疗只是把这些通用实践加上「患者安全与合规」的硬约束。</span>

**前瞻性验证**：模型在回顾性数据上有效，必须经过**前瞻性验证**（在真实临床环境按设计方式运行，测量实际效用）才能确认价值——这是医疗 ML 与循证医学（上一章）对齐的环节：模型也是一种「干预」，要按证据标准评价。

## 6 从预测到干预：因果与可解释

「预测风险」之后，医疗 ML 的两大前沿是**因果推断**与**可解释性**——它们共同回答「医生凭什么信你、该拿模型怎么办」。

**从预测到因果**：预测模型回答「谁会出事」，因果模型回答「干预会不会改变结果」。医疗决策真正需要的是后者——「给这个高风险患者做 X 干预，能降低多少风险？」。观察数据中的「高风险」可能是「病更重」的标记而非「可干预」的靶点。因此前沿方法（因果推断、目标试验模拟、反事实推理）正在把医疗 ML 从「预测层」推向「决策层」。<span class="marginnote">「预测 vs 因果」的经典警示：模型发现「去 ICU 的患者死亡风险高」——但这是「病重才进 ICU」的混杂，不是「进 ICU 导致死亡」。若把预测当因果，会得出「少送 ICU」的荒谬建议。医疗 ML 部署前必须问：<strong>这个预测特征是可干预的因，还是疾病的标记？</strong></span>

**可解释性（explainability）**：医生与监管都要求「为什么给这个建议」。方法分两路——**事后解释**（SHAP、LIME 对任意黑箱模型解释单次预测：哪些特征把风险推高/拉低）与**本质可解释**（逻辑回归、决策树、规则，模型本身透明）。<span class="marginnote">SHAP 是当前最流行的特征归因方法：它把「模型的预测」分解成「每个特征的贡献」，回答「这位患者风险高，主要是肾功能差和年龄大贡献的」。但 SHAP 是「模型层面的解释」，不等于「医学因果的解释」——两者要分清。</span>

**解释的限度**：可解释不是「理解一切」，而是「足够临床信任与问责」——医生要能判断「建议是否合理、何时该质疑、出了错谁负责」。这呼应第4篇《临床决策支持》的「可解释可问责」原则。

**辨析｜易错点：** 「模型可解释」≠「模型正确」。一个解释清晰的错误模型，比黑箱更危险——因为它看起来可信。可解释性是「信任的前提」而非「正确的保证」；医疗 ML 的完整证据链仍是「区分度 + 校准 + 效用 + 前瞻验证」，可解释性服务的是信任与调试，不替代验证。

### 常见疑问

**问：医疗预测为什么不直接全部用深度学习？**
答：因为医疗问题的核心约束不是「模型容量」而是「数据与验证」。医疗数据量相对小、噪音大、标签贵，深度模型的优势发挥不出来；而**可解释、可校准、可验证**的需求让简单模型（逻辑回归、梯度提升）常更实用。深度学习在影像、文本等「高维信号」场景优势明显，在「结构化表格 + 稀疏事件」场景未必跑赢基线。**先定问题与验证，再选模型**，而不是反着来。

**问：模型上线后谁负责监测与再训练？**
答：需要明确的「模型运营」责任——理想是「数据科学家 + 临床 + 信息科」三方的联合：数据科学家做漂移监测与再训练，临床代表评估「建议是否还合理」，信息科管部署与回滚。没有责任人的模型，会在环境变化后「静默失效」——这是医疗 AI 部署最常见的事故模式。模型不是「上线即完事」，而是「上线即开始运维」。

**关联阅读**：模型的概率基础见《临床决策中的概率推理与证据》，模型的落地系统见《临床决策支持系统》，模型的数据原料见《信息治理数据质量与编码体系》。

### 关键术语速查

- **区分度**：模型把「出事」与「不出事」分开的能力，用 AUC 衡量。
- **AUC**：ROC 曲线下面积，衡量排序能力，不依赖阈值。
- **校准**：预测概率与真实事件率的一致性。
- **临床效用**：在特定阈值与决策点下的净获益（DCA 衡量）。
- **决策曲线分析（DCA）**：把模型净获益画成阈值函数的工具。
- **数据漂移**：人群/流程/编码变化导致模型失效。
- **前瞻性验证**：在真实临床环境按设计方式运行并测量效果。
- **亚组表现审计**：按人群分层检查模型表现的公平性手段。

## 7 小结

- 医疗数据四特点：**为临床而记、纵向时序、事件稀疏、高维异构**；代表性偏移是失效主因。
- **逻辑回归**是常青基线：$P = 1/(1+e^{-(\beta_0+\beta^\mathsf{T}x)})$
