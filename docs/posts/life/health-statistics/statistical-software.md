## 为什么从统计软件开始

前面 12 篇，我们学了从描述统计到生存分析的一整套方法。但这些方法的**落地**依赖一台「计算的机器」——统计软件。没有软件，卡方 9.23、F 44.9、t 3.66 这些数字要手算到天荒地老，而且必然出错。

统计软件的本质是「**方法的中介**」：它把「我在心里想的检验」翻译成「机器执行的算法」，再把结果翻译回「人能读的表」。

<span class="marginnote">这层翻译恰恰是危险的来源：软件是忠实的执行者，却不是聪明的顾问——它不会告诉你「这个数据该用 Fisher 精确检验」，只会照你的指令输出。统计判断永远在软件之外。</span>

这也与「从极限到大模型」的工程观相通：训练脚本、评估脚本、版本控制，追求的是一件事——**可复现**。统计分析的同一追求叫「可复现分析」。

## 1 R：自由、脚本、生态

**R** 是开源的统计语言，卫生统计学事实上的「世界语」。

入门最小集：

数据结构：向量 `c(1,2,3)`、数据框 `data.frame`。
- 读数据：`read.csv("data.csv")`。
- 描述：`summary(dat)`、`mean`、`sd`、`table`。
- 假设检验与回归：`t.test`、`aov`、`lm`、`glm`、`chisq.test`。

一个完整的最小分析：

```r
dat <- data.frame(bp = c(120,125,118,122,130,135,128,132),
                  grp = factor(rep(c("A","B"), each = 4)))
t.test(bp ~ grp, data = dat, var.equal = TRUE)
```

输出（简化）：

```
	Two Sample t-test
data:  bp by grp
t = -4.0472, df = 6, p-value = 0.00676
alternative hypothesis: true difference in means is not equal to 0
95 percent confidence interval:
 -17.41554  -4.58446
```

读这张表的三步：先看 `p-value`（0.0068 < 0.05 拒绝）、再看置信区间（不含 0，与检验一致）、最后看统计量本身（t = −4.05，负号只是方向）。

**检验、区间、效应量三者呼应**——这正是本专题反复强调的统一视角。

## 2 SAS：严谨、工业、药品监管

**SAS** 是制药业与监管申报（FDA）的标准语言，以严谨著称。

- 分两步走：`DATA` 步建数据，`PROC` 步跑分析。
- 经典过程：`PROC MEANS`（描述）、`PROC TTEST`、`PROC GLM`（方差分析）、`PROC LOGISTIC`、`PROC LIFETEST`（生存）。
- 优势：过程稳健、文档完备、监管审计友好；代价：商业授权昂贵、语言语法比 R 繁琐。

## 3 SPSS：点选、入门、教学友好

**SPSS** 以菜单点选为主，是医学院教学与护理研究的常用工具。

- 无需编程即可跑出 t 检验、卡方、回归的结果表。
- 「分析 → 比较均值 → 独立样本 T 检验」这类路径就是它的语法。
- 优势：上手快、结果排版美观；代价：脚本化与可复现性弱、高级模型支持滞后。

## 4 三种工具对照

| 维度 | R | SAS | SPSS |
| --- | --- | --- | --- |
| 价格 | 免费开源 | 商业授权 | 商业授权 |
| 使用方式 | 脚本（编程） | DATA/PROC 两步 | 菜单点选 |
| 可复现性 | 强（脚本即证据） | 强（日志完整） | 弱（点选难追溯） |
| 卫生统计生态 | 最全（survival、lme4、survminer） | 监管级稳健 | 教学友好 |
| 典型场景 | 学术研究、数据科学 | 药品申报、大型机构 | 教学、临床科室 |
| 学习曲线 | 陡 | 中 | 缓 |

**重点：三者统计结果应当一致，方法本身不因软件而异。** 若同一数据在 R 和 SPSS 里得出不同 p 值，先怀疑「是否用了不同的检验选项」（如方差假设不同、是否校正），而不是「软件出错了」。软件是载体，方法是灵魂。

## 5 可复现性：脚本、R Markdown 与版本控制

**可复现分析（reproducible analysis）** 的黄金标准是：**一份脚本，从头跑到尾，别人拿到同一数据能复现全部结果**。

三条纪律：

- **脚本先行**：一切操作写进脚本，不靠手动点选；点选的操作日志无法证明「当时做了什么」。
- **R Markdown / Quarto**：把叙述文字、代码、结果、图混排成一份「会讲故事的文档」——这也是本博客一贯的「边写边算」风格。
- **版本控制（git）**：代码与数据都进版本库，改一处能追溯历史——这正是「从极限到大模型」项目本身的工程习惯。

<span class="marginnote">R 生态里 `tidyverse`（数据整理）、`survival`（生存分析）、`lme4`（混合模型）、`ggplot2`（绘图）是卫生统计四大金刚；掌握它们等于掌握了本专题每一章在 R 里的落点。</span>

**数据与代码的分离**：脚本里写死路径、在代码里手动改数，是可复现性的大敌。规范做法是「数据只读、代码只算」：原始数据单独存放且不改动，分析脚本通过参数读取——这与大模型实验里「数据集快照 + 训练脚本」的分工完全同构。

## 6 易错辨析

- **软件不思考**：软件会忠实地跑出「错误的数据用错了方法」的结果。方法选择是人的职责——回看第一篇的「数据尺度决定方法」。
- **默认选项要读文档**：`var.equal` 的默认值、卡方是否做连续性校正，都会改变结果。跑代码前先问「这个函数的默认假设是什么」。
- **数据导入的编码与因子**：中文列名、`factor` 的参考水平会影响输出；分类变量一定要确认被识别为因子。
- **复制粘贴的陷阱**：从软件拷贝结果到论文时，数字格式（小数点位数、科学计数）可能失真，务必以原始输出为准。
- **结果≠结论**：软件输出的是统计量，论文结论是「统计量 + 临床判断」——显著性到临床意义的最后一步，永远是人类。

## 7 小结

- 软件是**方法的中介**：忠实执行，不负责判断；方法选择在软件之外。
- R 自由脚本、SAS 监管严谨、SPSS 点选友好；**同一方法三工具结果一致**。
- 最小分析五件套：`t.test`、`aov`、`lm`、`glm`、`chisq.test`。
- **可复现 = 脚本 + 叙事混排 + 版本控制**；R Markdown / Quarto 是黄金标准。
- 易错集中在：默认选项、因子识别、结果复制、以及「把输出当结论」。

在下一节，我们将回答：随访数据里有些患者到研究结束还没出事、甚至失访了，怎么用这些「没完成」的数据——这就是**生存分析**。
