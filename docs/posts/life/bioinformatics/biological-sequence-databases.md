## 为什么从序列数据库开始

上一篇勾勒了生物信息学的全景：所有分析都从**序列数据**出发。可这些数据存在哪、长什么样、怎么检索？这就是数据库的职责。<span class="marginnote">序列数据库是整个学科的「公共图书馆」：任何人的比对、注释、进化分析，都先回到这里查「已知的序列」。你之前学的数据库、倒排索引、事务——生物数据库同样是数据系统，只是数据变成长度不一的字符串。</span>理解数据库，你才看得懂后文所有工具（BLAST、基因组浏览器、变异数据库）的数据从何而来。

## 1 从原始数据到知识：三级体系

生物序列数据并非一个巨大的扁平仓库，而是按「加工程度」分层的：

| 层级 | 名称 | 内容 | 例子 |
| --- | --- | --- | --- |
| 一级 | 原始序列数据库 | 提交者直接上传的核酸/蛋白质序列 | GenBank、ENA、DDBJ |
| 二级 | 派生/知识库 | 对原始序列**人工或自动加工**后的结果 | UniProt、RefSeq、PDB |
| 三级 | 综合资源 | 整合多源数据、附加功能注释 | NCBI、Ensembl、KEGG |

<span class="marginnote">这个分层与图书馆体系对应：一级是「出版社原稿」，二级是「编辑审校后的版本」，三级是「检索系统」。分析时优先用二级/三级数据，因为它们做了质量控制和统一命名。</span>

**一级数据库的黄金法则**：研究者测出新序列，须在论文发表前提交到公共数据库，获得一个**登录号（accession number）**——登录号是序列的身份证，论文里引用它即可。全球三个一级核酸数据库——美国的 GenBank、欧洲的 ENA、日本的 DDBJ——每天交换数据，保证内容一致，合称 **INSDC（国际核酸序列数据库联盟）**。

## 2 GenBank 与 INSDC 三兄弟

**GenBank** 由美国国立生物技术信息中心（NCBI）维护，是全世界最常用的核酸序列数据库。它的三条关键事实：

**数据来源**：研究者直接提交 + 从专利局、期刊、其他数据库同步；
**记录规模**：截至近年已积累超过数亿条序列、数万亿碱基，且仍在指数增长；
**增长动力**：高通量测序让数据库容量每隔约 18 个月翻一番，超过摩尔定律。

GenBank 的姊妹库——ENA（欧洲）与 DDBJ（日本）——在内容上与 GenBank **每日互换**，所以你任选其一查询，得到的结果基本一致。差异在界面与附加服务，不在数据本身。

<span class="marginnote">为什么要有三个而不是一个？历史原因：三个机构分别随区域性的测序项目兴起。为避免重复劳动，1987 年它们约定互相同步，形成 INSDC。这像互联网的根域名服务器——冗余、同步、统一对外。</span>

## 3 读一条记录：FASTA 与 flatfile

序列数据最常见的两种文本格式，是所有生物信息学工具的「世界语」。

**FASTA 格式**——最简形式，两条规则：

```
>sp|P69905|HBA_HUMAN Hemoglobin subunit alpha
MVLSPADKTNVKAAWGKVGAHAGEYGAEALERMFLSFPTTKTYFPHF...
```

以 `>` 开头的行是**头行**，存放标识与描述；
其后是**序列行**，纯字母（核酸 A/T/C/G/U 或蛋白质字母），可换行。

**GenBank flatfile 格式**——带完整注释的结构化记录，核心字段包括：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| LOCUS | 名称与长度 | LOCUS AB000123 1000 bp |
| ACCESSION | 登录号 | ACCESSION AB000123 |
| ORGANISM | 物种 | Homo sapiens |
| FEATURES | 功能注释（CDS、gene、exon 等） | gene=HBA1 |
| ORIGIN | 序列本体 | ORIGIN 1 atggtg... |

<span class="marginnote">FEATURES 表是 flatfile 的灵魂：它用坐标区间把「序列」和「生物学含义」绑在一起——第 100 到 450 位是一个 CDS（编码区），第 12 到 50 位是一个信号肽。后文「基因注释」就是把这种区间标注自动化。</span>

## 4 UniProt：审查过的与自动注释的

核酸序列翻译成蛋白质后，进入 **UniProt**（Universal Protein Resource）。它的核心是 UniProtKB，分两个层次：

**Swiss-Prot（审查过的）**：由**人工**逐条审校，注释丰富、可信度高，但数量有限（约几十万条）；
**TrEMBL（未审查的）**：由**计算程序**自动从核酸数据翻译、自动注释，规模大（数千万条）但质量参差。

一条蛋白质记录的「审查与否」会直接写进标识：Swiss-Prot 条目的第二字段以 `P`/`Q`/`O` 开头，TrEMBL 以 `A0A` 开头，如上节 FASTA 例子中的 `P69905`。**检索时优先看 Swiss-Prot**——人工注释告诉你「这可能是信号肽」「这个残基是活性位点」，而 TrEMBL 通常只有推断结果。

<span class="marginnote">Swiss-Prot 的「人工」不是逐字校对，而是<strong>专家根据文献证据逐条加注释</strong>：哪篇论文证明了这个磷酸化位点？序列从哪个生物来的？这种「证据驱动的注释」是二级数据库的核心价值。</span>

除 UniProt 外，蛋白质结构数据存于 **PDB**（RCSB Protein Data Bank），基因序列的权威参考集是 **RefSeq**——它去除了冗余、逐条评审，是比对和注释时的「黄金参考」。

## 5 公式解析：序列空间有多大

「为什么需要数据库？」的深层答案是：**序列空间大得超乎想象**。一段长度为 $n$ 的 DNA 序列，每个位置有 4 种碱基可选，可能序列总数是

$$
N = 4^n
$$

三步拆解：

- **第一步，理解底数 4**：DNA 的四个字母 A、T、G、C，每位置四选一；
- **第二步，理解指数 $n$**：长度每增加一位，总数乘 4——这是**指数爆炸**；
- **第三步，代入数量级**：一个基因平均约 1000 碱基，$4^{1000} \approx 10^{602}$，远超宇宙原子总数（约 $10^{80}$）。因此**几乎任何一条真实序列都是独一无二的**，你看到的人类基因，理论上从未在宇宙中出现过第二条完全相同的序列。

这带来一个深刻推论：序列数据库里的条目不是「重复的内容」，而是**进化的抽样**——自然界在指数空间里只实现了极少一部分。比对、搜索、聚类的全部意义，就是在这片几乎空白的指数空间里寻找「相近的邻居」。

## 6 数据库检索的实战要点

理论讲完，落到「怎么查」。生物信息学 90% 的日常是「检索 + 判断」，有四个可迁移的实战要点：

**按登录号而非名字检索**：登录号（如 `P69905`、`NM_000518`）是全球唯一的，而「血红蛋白 α」这种名字在不同数据库写法各异。论文里引用序列一律给登录号，就是这个原因。

**区分「版本」与「视图」**：同一基因在 RefSeq 里有 `NM_`（mRNA）、`NP_`（蛋白）、`NC_`（染色体）三种视图；序列坐标可能随基因组版本（hg19 vs hg38）改变。分析时先明确用的是哪个版本——跨版本比对是初学者最常见的坐标灾难。

**善用跨库链接**：NCBI 的每条记录底部都链到 UniProt、Ensembl、PDB 等；从 `Gene` 页（而非序列页）出发，能看到「这个基因的蛋白结构」「这个基因的疾病关联」等整合信息。

**下载用 API / FTP 而非浏览器**：NCBI 的 `efetch`、Ensembl 的 REST API、UniProt 的 `SPARQL` 都可以脚本化批量下载——这正是你在第三级《脚本编程》里学的「自动化」在数据采集上的直接应用。

<span class="marginnote">一个小提醒：公共数据库不是「免费云盘」——每次大规模下载请遵守使用政策（NCBI 对高频访问会限流）。论文「补充数据」区常直接给下载链接，优先从那里拿，比抓整个库可靠。</span>

## 7 小结

- 序列数据库分**三级**：原始序列库（GenBank/ENA/DDBJ）→ 知识库（UniProt/RefSeq/PDB）→ 综合资源（NCBI/Ensembl）。
- **GenBank** 由 NCBI 维护，与 ENA、DDBJ 组成 **INSDC**，每日互换数据。
- 格式两件套：**FASTA**（简洁）与 **GenBank flatfile**（带 FEATURES 区间注释）。
- **UniProtKB** 分 Swiss-Prot（人工审校）与 TrEMBL（自动注释）；`P`/`Q`/`O` 开头的登录号标识即人工审校。
- 序列空间按 $4^n$ 指数膨胀，真实序列是自然界的稀疏抽样——这是所有检索与比对的意义所在。
