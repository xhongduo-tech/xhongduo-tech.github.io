## 为什么管理问题长在「网」上

城市之间有路、电路之间有网、供应商与工厂之间有合同关系、任务之间有先后顺序。管理系统的骨架，几乎都是**网络**：节点代表实体，边代表关系或通道。

**图与网络分析**就是用图论的数学语言，去回答网络上最典型的四类问题——**连成一片要花多少钱、两点之间怎么走最近、整个网络最多能输送多少、怎样才能最省钱地输送**。


这四个问题对应四种经典算法：**最小生成树、最短路、最大流、最小费用流**。它们是物流规划、通信网络、电网调度、项目管理的共同地基，也是后面网络计划技术（CPM/PERT）的直接前置。

<span class="marginnote">图论在计算机科学里是第三级《数据结构》与《算法设计》的主场；在管理科学与工程里，它把「图上抽象」翻译成「网络的资金、容量、时限」。</span>

同一棵最小生成树，工程师叫它 MST，管理者叫它「最便宜的互联方案」。


## 1 图的词汇表

先建立一套共用词汇：


**图（graph）** $G = (V, E)$：节点集合 $V$ 与边集合 $E$。

边无方向的叫**无向图**，有方向的叫**有向图**（此时边叫弧，记作 $(u, v)$ 表示从 $u$ 到 $v$）。


**链 / 路（path）**：由边首尾相接的序列。**回路（cycle）**：起点与终点重合的路。<span class="marginnote">有向图里「路」必须沿弧的方向走；</span>

无向图里则没有方向约束。很多管理问题的本质就是「在有向图上找一条满足某种约束的路」——最短路、关键路径都是。


**树（tree）**：连通且无回路的无向图。它有两个等价特征：$n$ 个节点的树恰有 $n-1$ 条边；树中任意两节点之间恰有一条路。**生成树（spanning tree）**：

包含所有节点的树。


**赋权图（weighted graph）**：每条边带一个权值（距离、成本、容量、时间），图上的优化问题几乎都在赋权图上进行。


## 2 最小生成树：Kruskal 与 Prim

**问题**：给 $n$ 个节点（城市、厂站）架设线路，使它们全部连通，且总造价最小。答案就是一棵**最小生成树（Minimum Spanning Tree, MST）**。


**Kruskal 算法**：把所有边按权从小到大排序，依次考察，只要这条边**不形成回路**就选它，直到选出 $n-1$ 条边。


**Prim 算法**：从一个节点出发，每次在当前已连通的部分与外部之间选权最小的边，把新节点拉进来，直到全部纳入。


两个算法殊途同归，都基于**切割性质**：对任何把节点集切成两半的切割，跨切割的权最小的边一定属于某棵 MST。

<span class="marginnote">切割性质是贪心算法在这类问题上「只管眼前也对」的理论保证——跨切割的最小边若不在 MST 里，把它加进去就会与树中某条跨切割边形成回路、</span>

替换后总权更小，矛盾。贪心之所以正确，是因为最优性有局部结构可循。


## 3 最短路：Dijkstra 与 Floyd

**问题**：在赋权图上求从起点到终点的最短路径（时间、距离或成本最小）。


**Dijkstra 算法**：适用于**所有边权非负**的单源最短路。

维护一个已确定最短距离的集合，每次从未确定节点里选「当前估计距离最小」的节点，用它的邻居「松弛」估计值，重复直到终点确定。复杂度 $O(n^2)$（堆优化 $O(m\log n)$）。

<span class="marginnote">Dijkstra 的正确性依赖边权非负：正因为路径长度只增不减，第一次从待定集合里取出「距离最小」的节点，它的距离就是最终值。</span>

一旦出现负权边，这个「先取出即定死」的推理崩塌，必须换 Bellman-Ford 或 SPFA。


**Floyd-Warshall 算法**：动态规划求**所有点对**最短路。

设 $d_{ij}^{(k)}$ 为「只允许经过编号前 $k$ 个节点作中转」时 $i$ 到 $j$ 的最短距离，递推：


$$d_{ij}^{(k)} = \min\left\{ d_{ij}^{(k-1)},\ d_{ik}^{(k-1)} + d_{kj}^{(k-1)} \right\}$$

三重循环 $O(n^3)$，一次算出整个距离矩阵。注意它也是第7章动态规划的直接应用——把「允许中转的节点集合」当作阶段，状态就是「用不用第 $k$ 个节点做中转」。

## 4 公式解析：最大流与最小割定理

**问题**：给一个有向网络，每条弧有容量 $c_{ij}$，求从源点 $s$ 到汇点 $t$ 能输送的最大流量。

**增广路径算法（Ford-Fulkerson）**：从零流开始，反复找一条从 $s$ 到 $t$ 的**增广路**（沿途弧的剩余容量都为正），沿它压入尽可能多的流，直到找不到增广路为止。剩余容量为 0 的反向弧（残余网络）允许「撤销流量」，这让算法可以修正之前的错误选择。

**最大流最小割定理**：网络的最大流值，等于把节点集分成含 $s$ 的部分与含 $t$ 的部分时，所有割中**最小割容量**：

$$\max \ \text{flow} = \min \ \text{cut capacity} = \min_{(U, \bar{U}):\, s\in U, t\notin U} \sum_{u\in U, v\notin U} c_{uv}$$

- **第一步，认割**：一个**割**就是把节点劈成两半、$s$ 在一半、$t$ 在另一半；割容量是「从 $s$ 侧指向 $t$ 侧」所有弧的容量之和。
- **第二步，认方向**：任何流都不能超过任意割的容量（流要从 $s$ 侧流到 $t$ 侧，跨割净流量 ≤ 割容量），所以 $\max \text{flow} \le \min \text{cut}$。
- **第三步，看相等**：Ford-Fulkerson 终止时，$s$ 可达的节点集 $U$ 形成的一个割，其容量恰好等于当前流量——两边同时达到，等号成立。<span class="marginnote">最小割的工程含义比最大流还重要：它告诉你<strong>哪几条弧是真正的咽喉</strong>。网络扩容改哪里？先找到最小割，改的正是割上的弧——这在电网、交通、供应链的瓶颈分析里是直接可用的结论。</span>

## 5 最小费用流

现实中运货不只问「能不能运过去」，更问「怎么运最省运费」。**最小费用流问题**：

每条弧带容量 $c_{ij}$ 与单位运输费用 $w_{ij}$，需求是把 $F$ 单位货从 $s$ 送到 $t$，且总运费最小。


它的标准解法是**逐次最短增广路**：每次都沿着「单位费用最小的增广路」送流（用最短路算法在费用网络上找），直到送满 $F$。

每送一批就更新残余网络（含反向费用），保证后续流可以「绕开」之前不经济的决策。<span class="marginnote">最小费用流把图论与线性规划连起来了：</span>

它本质是一个网络结构下的 LP，约束矩阵还是全幺模的，所以 LP 解自动整数。运输问题（第3章）是它无容量上限的特例，指派问题也可化为它——一张网串起全书。


## 6 易错点与辨析

**辨析｜易错点：Dijkstra 不能处理负权边。** 负权会让「先取出即定死」失效——一个节点可能通过一条负权边被后来的节点抄近路。

遇到负权用 Bellman-Ford（可检测负环）或 SPFA。


**辨析｜易错点：增广路要沿「残余网络」找，不是原网络。** 残余网络里的反向弧是实现流量修正的关键：

没有反向弧，Ford-Fulkerson 可能因为一次贪心的错误选择而永远达不到最大流。把反向弧忘掉是最大流实现的头号错误。


## 7 数值算例：Dijkstra 完整走一遍

设 5 个节点 1~5，起点 1，各边权（正数）如下：1-2: 2，1-3: 4，2-3: 1，2-4: 7，3-4: 3，3-5: 5，4-5: 2。求 1 到 5 的最短路。


**初始化**：$d(1) = 0$，其余 $d = \infty$；已确定集合 $S = \varnothing$。


**第一轮**：未确定节点中距离最小的是 1（$d = 0$），把它定死。松弛其邻居：$d(2) = 0 + 2 = 2$，$d(3) = 0 + 4 = 4$。


**第二轮**：未确定最小的是 2（$d = 2$），定死。松弛：$d(3) = \min(4, 2+1) = 3$（更新），$d(4) = 2 + 7 = 9$。


**第三轮**：最小的是 3（$d = 3$），定死。松弛：$d(4) = \min(9, 3+3) = 6$（更新），$d(5) = 3 + 5 = 8$。


**第四轮**：最小的是 4（$d = 6$），定死。松弛：$d(5) = \min(8, 6+2) = 8$（不变）。


**第五轮**：最小的是 5（$d = 8$），定死，终止。1 到 5 的最短距离 8，路径由「定死时记录的前驱」回溯：

$d(5) = 8$ 来自节点 3（$3 + 5$），$d(3) = 3$ 来自节点 2（$2 + 1$），$d(2) = 2$ 来自节点 1。

路径 1 → 2 → 3 → 5，总长 $2 + 1 + 5 = 8$。


注意第三轮 $d(4)$ 从 9 更新到 6 时，走的是「经节点 3」——这说明最短路可以绕远路反而更近。

**每轮定死的节点，其距离永不再改**，这正是 Dijkstra「先取最小即定死」的贪心保证；若出现负权边，这个保证失效，前面的更新顺序可能就错了。



**补充：网络问题的算法复杂度地图。** 最小生成树、最短路（非负权）、

最大流等经典网络问题都有**多项式时间**算法（$O(m\log n)$ 或 $O(n^3)$ 量级），规模到几十万节点也能算——这是它们成为工程标配的根本原因。

但要注意几个「看似网络、实则难」的问题：**旅行商问题（TSP）**求访问所有节点的最短回路是 NP-hard，**车辆路径问题（VRP）**、**设施选址**同样难。判别的经验法则：

**「点对点」网络问题往往容易，「整体覆盖/回路/选址」网络问题往往难**。管理实践中，把 NP-hard 问题近似求解（启发式、元启发式如遗传算法、

模拟退火）是常态——精确解只在规模足够小时才可行。这一层认知，决定了你面对一个网络问题时是「直接建模求解」还是「先估规模、再选求解策略」。


## 8 小结

- 图论词汇：**节点、边/弧、路、回路、树、生成树、赋权图**。
- **最小生成树**（Kruskal/Prim）解「连通最省钱」，靠**切割性质**保证贪心正确。
- **最短路**：Dijkstra 单源（非负权）、Floyd-Warshall 全点对（DP，$O(n^3)$
