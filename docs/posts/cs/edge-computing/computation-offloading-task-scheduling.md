## 为什么从卸载与调度开始

边缘系统的资源不是无限的：终端算力小、边缘节点负载会抖、云端链路带宽有限。于是每个任务都面临同一个三岔路口——**本地算、卸载给边缘算、还是扔给云端算**。这就是**计算卸载（computation offloading）**；而当一群任务同时涌向同一个边缘节点，谁先跑、谁让路，就是**任务调度（task scheduling）**。这两个问题合起来，构成边缘系统「资源管理」的心脏，也是本专题里数学含量最高的一篇。它会用到你学过的概率、排队论，以及后续强化学习课程里的 DRL 方法。<span class="marginnote">卸载问题的本质是一个「两难中的优化」：本地算省传输但费时间费电，卸载算省时省电但要付带宽与排队成本——而这一切还在动态变化中。这类「在约束下做决策」的骨架，与你在《最优化》与《强化学习》里遇到的模型同构。</span>

## 1 为什么要卸载：本地算力撑不住

终端（手机、传感器、车载盒）受体积、散热、电池约束，算力天花板远低于云端与边缘服务器。当任务的计算量（所需 CPU 周期数）超出终端能力时，把任务送去更强的节点执行可以：**缩短执行时间**（更快的处理器）、**节省终端能耗**（任务少占本地 CPU）、**访问更大数据与模型**。但卸载不是免费的——传输数据要花时间与带宽，远程执行还引入排队与网络延迟。**什么时候卸载划算，是卸载决策（offloading decision）研究的核心。**

## 2 卸载模型：二进制 vs 部分卸载

卸载策略分两大类：

- **二进制卸载（binary offloading）**：任务不可拆分，要么整体本地执行，要么整体卸载执行。适合原子性强、任务粒度小的场景（如一次图像识别请求）。
- **部分卸载（partial offloading）**：任务可分割，一部分留在本地、一部分卸载。适合可并行的计算图（如视频帧的部分预处理本地做、特征提取远端做）。

两类模型都要求我们把「卸载的成本账」算清楚——这引出本节的核心公式。

## 3 公式解析：卸载到底划不划算

设一个任务 $n$ 的计算量为 $C_n$（CPU 周期数），本地 CPU 频率为 $f_l$，边缘侧执行频率为 $f_s$，数据量为 $D$，上行带宽为 $R$，结果返回量为 $D_{\text{res}}$。

**本地执行时间**：

$$
T_{\text{local}} = \frac{C_n}{f_l}
$$

**卸载执行时间**（上传 + 远端执行 + 结果返回）：

$$
T_{\text{offload}} = \frac{D}{R} + \frac{C_n}{f_s} + \frac{D_{\text{res}}}{R}
$$

**卸载判据**：当 $T_{\text{offload}} < T_{\text{local}}$ 时卸载在时间上划算；若以能耗为目标，则比较 $E_{\text{local}} = k f_l^2 C_n$（CMOS 动态功耗 $P = k f^3$ 乘时间）与 $E_{\text{offload}} = P_{\text{tx}} \cdot \frac{D}{R} + E_{\text{remote_idle}}$。

逐项拆解这个不等式，能读出三条直觉：

- **$C_n$（计算量）越大，卸载越划算**：本地频率 $f_l$ 低，算大任务要等很久；远端 $f_s$ 高，时间上占优。
- **$D/R$（传输时间）越大，卸载越不划算**：大文件搬上传链路，光传输就吃掉优势——这正是「算力跟数据走」优于「数据跟算力走」的数学证据。
- **$f_s \to f_l$ 或带宽紧张时，卸载优势消失**：边缘忙时 $f_s$ 实际退化（排队），卸载可能反而更慢——所以决策必须用**实时测量**而不是静态标称值。<span class="marginnote">这一不等式的三个变量对应三类优化手段：降数据量（压缩、缓存、本地预处理）、提远端效率（调度与负载均衡）、选对决策时机（动态估计带宽与队列长度）。工程上离线决策在 5% 的误差内就足够，而动态环境必须走向下一节的智能调度。</span>

## 4 任务调度：谁来排队、谁先跑

卸载决策解决「派不派」，任务调度解决「派给谁、何时跑」。边缘节点面对一组任务（每个带计算量、截止时间、优先级），常见调度策略：

- **先到先服务（FCFS）**：简单公平，但对紧急任务不友好。
- **最短剩余时间优先（SRPT）**：优先处理剩余量小的任务，可降低平均等待时间——排队论里经典的最优性结论。
- **截止时间优先（EDF）**：按绝对截止时间排序，满足实时约束，但负载过高时会「雪崩」。
- **负载均衡调度**：把任务摊到多个边缘节点，避免单点过载，配合移动性（用户跨基站切换时任务迁移）。
- **联合优化卸载 + 调度**：把「决策 × 资源分配」写成联合优化问题，用启发式（贪心、遗传）求解。

## 5 动态环境下的智能调度

真实边缘系统是动态的：带宽波动、节点负载波动、任务随机到达、终端移动。静态公式算不准，于是近年主流转向**深度强化学习（DRL）** 的求解范式：

- **状态（state）**：当前任务队列、各节点负载、带宽估计、任务参数。
- **动作（action）**：每个任务选「本地 / 边缘 A / 边缘 B / 云」，以及分配多少资源。
- **奖励（reward）**：负延迟加权 + 负能耗加权 + 截止时间违约惩罚，构成多目标帕累托权衡。

DRL 的价值在于**在线自适应**：不需要精确模型，靠与环境交互学到「在当下状态下该派给谁」。多个边缘节点各自做决策时，问题升级为**多智能体强化学习（MARL）**——这是边缘资源管理当前的研究前沿，也直接通向第三级《强化学习》课程。

**辨析｜易错点：** 卸载 ≠ 「远程执行」的简单代名词。有两个高频误解：其一，**卸载需要「可携带的上下文」**——任务引用的数据、模型、状态必须能序列化随任务迁移，否则只能「移动计算，不能移动任务」；其二，**卸载省时间不代表省能耗**——如果远端空闲时终端仍要满功率发送数据，发射功耗可能吞掉省下的执行能耗。是否卸载、以什么目标卸载，必须在「时间 / 能耗 / 带宽」的权衡面上先讲清楚你要优化哪个。

### 延伸：一个算例——把卸载判据算一遍

纸上得来终觉浅，代入数字看一次。设某任务计算量 $C_n = 10^9$ 个 CPU 周期，本地频率 $f_l = 1$ GHz，边缘执行频率 $f_s = 5$ GHz，上传数据 $D = 1$ MB（即 $8 \times 10^6$ bit），带宽 $R = 100$ Mbps，结果返回量很小可忽略。

- **本地执行**：$T_{\text{local}} = C_n / f_l = 10^9 / 10^9 = 1.0$ 秒。
- **上传耗时**：$D / R = 8 \times 10^6 / 10^8 = 0.08$ 秒。
- **边缘执行**：$C_n / f_s = 10^9 / (5 \times 10^9) = 0.2$ 秒。
- **卸载总耗时**：$T_{\text{offload}} = 0.08 + 0.2 = 0.28$ 秒 < 1.0 秒 → **卸载划算**。

现在把带宽降到 $R = 10$ Mbps 再算一遍：$D/R = 8 \times 10^6 / 10^7 = 0.8$ 秒，$T_{\text{offload}} = 0.8 + 0.2 = 1.0$ 秒——刚好打平，几乎没有收益。再把带宽降到 5 Mbps：上传要 1.6 秒，卸载反而比本地还慢，此时**本地执行更优**。

这个算例把公式变成了工程直觉：**卸载是否划算，取决于「算力差距」能否跑赢「传输代价」**——带宽 100 Mbps 时边缘 5 倍算力明显划算，带宽降到 5 Mbps 时传输吃掉全部优势。真实的卸载决策系统就是动态测量这两个量（节点算力状态与带宽），实时套用这个不等式。这也解释了为什么离线做「永远卸载」或「永远本地」的静态配置都是次优的——**决策必须跟随环境参数在线变化**。

再补一层移动性视角：用户跨基站移动时，任务可能要从边缘节点 A 迁移到 B（任务迁移）。迁移本身要支付「状态序列化 + 传输」的成本，所以迁移决策也要算一笔账——这比「卸载一次」复杂一个维度，也是调度系统在车联网、移动终端场景下的硬骨头，我们会在《车联网与工业边缘应用》里再见。

### 延伸：调度策略怎么选——一张对照表

不同调度策略没有绝对优劣，只有「适不适合当下」。把常见策略放在同一张表里对照：

| 策略 | 优化目标 | 优点 | 短板 | 适用场景 |
| --- | --- | --- | --- | --- |
| FCFS 先到先服务 | 公平性 | 实现简单、无饥饿 | 平均等待长、紧急任务吃亏 | 任务性质均匀的后台 |
| SRPT 最短剩余优先 | 平均延迟 | 平均等待时间最优 | 大任务可能被饿死 | 任务大小差异大 |
| EDF 截止时间优先 | 实时性 | 满足截止时间（负载不过载时） | 过载时整体雪崩 | 有硬截止时间的实时任务 |
| 加权轮询 / 权重公平 | 资源公平 | 可控的服务质量 | 需调参 | 多租户共享节点 |
| DRL 智能调度 | 综合（延迟+能耗+违约） | 在线自适应、无需建模 | 训练成本高、难解释 | 动态复杂环境 |
| 优先级队列 | 服务质量 | 高优先级先跑、低优先级让路 | 低优先级可能饥饿 | 有等级差别的业务 |

选型的直觉：**目标决定策略**——要公平选 FCFS/轮询，要平均延迟选 SRPT，要硬实时选 EDF，要在动态环境里长期优化选 DRL。边缘系统的现实是任务类型混合，所以主流做法是「分层混合调度」：先按类型（实时/尽力而为）分流，再在各队列内部用对应策略。这与操作系统课程里「多级反馈队列」的思想一脉相承——你在《操作系统》里学的调度哲学，在边缘维度上原样重演，只是被调度的对象从「进程」变成了「任务 + 网络 + 迁移」。

## 6 小结

- 卸载的两类模型：**二进制卸载**（整体决策）与**部分卸载**（可分割）。
- 核心判据：$T_{\text{offload}} = \frac{D}{R} + \frac{C_n}{f_s} + \frac{D_{\text{res}}}{R}$ 与 $T_{\text{local}} = \frac{C_n}{f_l}$ 比较，$C_n$ 大、$D/R$ 小则卸载划算。
- 调度策略谱系：FCFS → SRPT → EDF → 负载均衡 → 联合优化，随需求升级。
- 动态环境走向 **DRL/MARL** 在线决策，连接强化学习课程。
- 两个易错点：卸载要**上下文可迁移**；省时间 ≠ 省能耗。
- 卸载与调度是一枚硬币的两面：**卸载决定「派不派」，调度决定「派给谁、何时跑」**，真实系统两者联合决策，脱离任何一个谈优化都是不完整的。
- 选策略先看目标：**要公平选 FCFS/轮询，要平均延迟选 SRPT，要硬实时选 EDF，要动态优化选 DRL**——目标决定策略，而非反过来。

在下一节，我们回到数据本身——**边缘存储与缓存：把热数据留在离用户最近的地方**。如果说卸载解决「任务去哪算」，缓存解决的就是更底层的问题：「数据能不能先在本地准备好」——没有数据的本地化，卸载省下的执行时间会被取数时间重新吃掉。
