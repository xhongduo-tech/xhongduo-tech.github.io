## 为什么从 5G 说起

MEC 给边缘装了「平台」，但它要真正兑现低延迟，还得靠一张「跑得动的网」。4G 的端到端时延约 30–50 ms，够刷视频，不够自动驾驶；而 5G 把空口时延压到 1 ms、端到端低至 5–10 ms，并引入两项革命性机制：**服务化架构（SBA）** 与 **网络切片**。这两者恰恰是边缘计算在电信侧的「落地点」。本节回答三个问题：5G 凭什么快？网络切片切的是什么？MEC 与切片如何协同？<span class="marginnote">「切片 + 边缘」是 5G 产业叙事里绑定最紧的组合：切片负责「网络资源隔离」，边缘负责「应用就近」，合起来才构成完整的行业数字化底座。</span>如果你已经学完《计算机网络》那篇关于 OSI 七层与路由的知识，会更容易理解：切片是控制平面与数据平面上的「软性切割」，而边缘是数据平面上的「物理就近」。

## 1 5G 的三大场景：一张网吃不下所有需求

IMT-2020（5G 的目标愿景）定义了三大应用场景，它们对网络的需求几乎互相矛盾：

| 场景 | 全称 | 关键指标 | 代表业务 |
| --- | --- | --- | --- |
| eMBB | 增强移动宽带 | 峰值 20 Gbps 下行 | 超高清视频、XR |
| URLLC | 超高可靠低时延通信 | 空口 1 ms、可靠性 99.999% | 自动驾驶、工业控制 |
| mMTC | 海量机器类通信 | 每平方公里百万级连接 | 智慧城市、传感网络 |

注意这里的矛盾：eMBB 想要「极大带宽」，URLLC 想要「极低时延」，mMTC 想要「极多连接」——同一张物理网络如果按同一种配置跑，根本无法同时满足三者。**5G 的答案是：不造三张网，而是把一张物理网切成多个逻辑网。**

## 2 网络切片：把物理网络切成逻辑网络

**网络切片（network slicing）**：在共享的物理基础设施上，通过 SDN/NFV 技术构建多个**相互隔离的端到端逻辑网络**，每个逻辑网络（切片）针对特定业务定制——独立的带宽、时延、可靠性、安全策略与资源配额。

类比：一条高速公路（物理网络）被划分出专用车道、公交车道、应急车道（多个切片），每类车辆只在自己的车道上跑，互不干扰、各享资源。

关键技术支撑来自云原生与虚拟化：**NFV（网络功能虚拟化）** 把基站、核心网功能拆成软件（如 vRAN、vUPF），**SDN（软件定义网络）** 提供可编程转发路径，切片再叠加切片选择与编排器（NSSF、NSMF）统一管理。一个切片就是一条「虚拟网络实例」。

**切片与 MEC 的绑定**：切片管「网络路径与资源」，MEC 管「应用放置」。以 URLLC 切片为例——该切片把 UPF（用户面功能）下沉到基站旁的 MEC 节点，数据在边缘就地终结；同时切片为它预留专用带宽与低时延转发路径。于是「切片的低时延保证」与「MEC 的就近计算」在数据平面会师。

## 3 5G 服务化架构：UPF 下沉与 NEF 开放

5G 核心网采用服务化架构（SBA），把传统网元拆成一个个可以按需调用的「网络功能（NF）」。与边缘相关的是两个关键角色：

**UPF（用户面功能）**：数据面唯一的转发枢纽，对应 4G 的 SGW/PGW。它的部署位置决定「用户数据在哪里终结」——**UPF 可以下沉到基站旁、与 MEC 节点同址部署**，用户流量不再绕行核心网，这是 5G 边缘计算最核心的物理机制。
- **NEF（网络能力开放功能）**：把网络能力（位置、切片信息、QoS 策略）以 API 形式开放给第三方应用与 MEC 平台，让边缘应用能感知并驱动网络。

于是「5G 给 MEC 的两份礼物」齐了：**UPF 下沉 = 数据面就地的物理基础；NEF 开放 = 控制面能力的软件接口。** 边缘应用的流量在本地终结，同时还能按需申请网络资源，两件事在标准层面被打通。<span class="marginnote">在 3GPP 规范里，边缘计算场景要求「对数据面的本地路由 + 对应用和移动性管理的协同」，这正是 UPF 与 MEC 编排器之间的标准接口（如 N4、N6 参考点）要做的事。</span>

## 4 公式解析：一毫秒的预算怎么花

URLLC 的「空口 1 ms」听起来炫目，但要兑现端到端低延迟，必须把毫秒预算拆开、逐段规划。一次工业闭环控制的端到端延迟可分解为：

$$
T_{\text{e2e}} = T_{\text{air}} + T_{\text{TTI}} + T_{\text{upf}} + T_{\text{edge}} + T_{\text{down}}
$$

- **$T_{\text{air}}$**：空口传输时延，即信号在基站与终端间的电磁波传播与调度等待，5G 通过更短的子载波间隔（numerology）与免调度传输把它压到亚毫秒。
- **$T_{\text{TTI}}$**：传输时间间隔，即一次调度的最小时间粒度，5G 用「迷你时隙（mini-slot）」把 4G 的 1 ms TTI 砍到数十至数百微秒。
- **$T_{\text{upf}}$**：用户面在 UPF 上的转发时延，UPF 越靠近基站，这一项越小。
- **$T_{\text{edge}}$**：边缘节点的应用处理时延，即上一节端到端公式里的 $T_{\text{process}}$，由 MEC 平台承担。
- **$T_{\text{down}}$**：下行返回时延。

**逐段压榨的逻辑**：空口与 TTI 由 5G 物理层解决，UPF 转发由下沉部署解决，应用处理由 MEC 解决——**「毫秒预算」是被 5G 与边缘联合承包的，任何一段超预算都会拖垮整体。** 这正是工业界用「延迟预算倒推架构」的实操范式，也解释了为什么只有「5G + 边缘」组合才能支撑远程手术、云端驾驶这类业务。<span class="marginnote">把 $T_{\text{e2e}}$ 的每一项列成一份「预算表」并给出测量方法，是边缘系统工程设计的日常：先定业务 SLA，再倒推各段的预算与余量，再决定 UPF 放哪、边缘节点买多大算力。</span>

## 5 切片 + 边缘的落地形态

把两块拼起来，典型方案是这样的组合拳：

**行业定制切片**：为智慧工厂申请一个 URLLC 切片（低时延、高可靠、专用带宽），为视频监控申请一个 eMBB 切片（大带宽）；**边缘就近部署**：两个切片各自把 UPF 下沉到各自的 MEC 节点，工厂控制流量走「工厂本地 MEC」，视频流量走「园区边缘 MEC」；**统一编排**：切片的生命周期与 MEC 应用的生命周期由统一的编排层（跨域编排器）协调，业务上线时「切片 + 应用」一起部署、一起回收。

这个形态在智慧工厂、智慧港口、车联网中已经批量落地。它的本质是把上一节讲的三层架构再细化一层：**「云 - 边 - 端」之上叠加了「切片」这层逻辑网络维度**——算力按延迟放哪层，流量按业务走哪条切片，两件事协同决定。

**辨析｜易错点：** 不要把「网络切片」与「VPN」混为一谈。VPN 只是加密隧道的逻辑隔离，物理资源仍共享、无法保证 QoS 隔离；切片通过虚拟化在**资源层面**预留带宽与低时延转发，可以承诺 SLA。切片是「按资源切」，VPN 是「按路由穿」，前者能背书「一毫秒」的承诺，后者不能。

### 延伸：切片的纵向分层——一条切片横跨三段网络

「端到端切片」里的「端到端」不是口号，一条切片在物理上横跨**三段网络**，每一段都要切：

| 网络段 | 切片化手段 | 关键角色 |
| --- | --- | --- |
| 接入网（RAN） | 无线资源按切片划分（不同 numerology、资源块隔离） | gNB、CU/DU |
| 承载网（transport） | 网络资源预留（FlexE、Segment Routing 按切片隔离带宽） | 传输网设备 |
| 核心网（5GC） | 按切片实例化独立的 AMF/SMF/UPF 实例 | NSSF、NSMF、NSSAAF |

三个细节值得记：

- **切片选择**：终端接入时携带切片标识（S-NSSAI），网络根据签约与业务类型把请求路由到对应切片实例；一个终端可同时关联多个切片（手机既看视频又连车联网）。
- **编排层级**：跨域协调由 **NSMF（网络切片管理功能）** 负责，它把一条端到端切片「翻译」成对接入网、承载网、核心网各段子切片管理器的指令——这与「边缘平台与编排」篇里跨域编排的思路完全同构。
- **切片 + MEC 的联合编排**：切片的创建要「顺带」把 MEC 应用实例一起拉起（应用随切片部署），这样业务上线时网络与计算同时就位。

所以当你听到「为自动驾驶切一条 URLLC 切片」，它的完整含义是：接入网留资源、承载网留带宽、核心网独立实例化 UPF 且 UPF 下沉到路边 MEC——**三段网络 + 一层边缘，合起来才是一条端到端切片**。这也是理解运营商「行业专网」方案的最短路径：行业专网 = 专用切片 + 本地边缘 + 统一编排。

### 延伸：一个算例——毫秒预算怎么摊

把公式代入一个智慧工厂的闭环控制场景。设一次「机器人收到指令并回报状态」的端到端延迟预算为 10 ms，按公式逐段分配（示意值）：

| 预算项 | 分配（ms） | 由谁保证 |
| --- | --- | --- |
| $T_{\text{air}}$ 空口 | 1.0 | 5G 短帧 + 免调度传输 |
| $T_{\text{TTI}}$ 调度粒度 | 0.5 | mini-slot |
| $T_{\text{upf}}$ 用户面转发 | 0.8 | UPF 下沉到车间边缘 |
| $T_{\text{edge}}$ 边缘应用处理 | 3.0 | 车间 MEC 节点 |
| $T_{\text{down}}$ 下行返回 | 1.2 | 空口下行 + 本地转发 |
| 抖动余量 | 3.5 | 给调度与处理留的缓冲 |

合计 10 ms，且留出 35% 的抖动余量——工业闭环的工程铁律是**预算表必须留余量**，因为排队与无线信道天然抖动，不留余量的系统会在峰值延迟下超时。这张表的读法是：**每一段都要「可测量、可监控、可告警」**，一旦某段实测逼近预算上限，就要立即调优（加大边缘算力、调整调度优先级、或收紧无线参数）。把「毫秒预算」当成一份活的性能合同来管理，而不是一次性的设计假设——这正是「5G + 边缘」能从演示走向规模商用的工程分水岭。

## 6 小结

- 5G 三大场景 **eMBB / URLLC / mMTC** 需求互相矛盾，催生**网络切片**：在一张物理网上切出多个隔离的逻辑网络。
- 切片依赖 **NFV + SDN + 切片编排**，与 MEC 绑定后形成「网络资源隔离 + 应用就近」的组合。
- 5G 给边缘的两份礼物：**UPF 下沉**（数据面就地终结）与 **NEF 开放**（能力 API 化）。
- 端到端延迟公式 $T = T_{\text{air}} + T_{\text{TTI}} + T_{\text{upf}} + T_{\text{edge}} + T_{\text{down}}$，由 5G 物理层、UPF 部署与 MEC 联合承包。
- 切片 ≠ VPN：切片在资源层面承诺 QoS 与 SLA。
- 毫秒预算是**一份活的性能合同**：每一段都要可测量、可监控、可告警，工程上必须留抖动余量。

在下一节，我们走出网络，把目光转向边缘上最火的应用——**边缘 AI：模型如何在云里训练、被搬到边缘部署**。这也是本专题从「网络」转向「应用」的枢纽：前面讲的切片与 MEC，最终都是为了给边缘上的智能腾出位置——网络负责把算力与流量送到对的地方，应用负责在那里兑现价值。
