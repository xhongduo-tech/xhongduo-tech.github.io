## 为什么从文本、链接与图像开始

上一节我们把文档的**外壳**搭好了：`<!DOCTYPE html>`、`<head>`、`<body>`。外壳之内，`<body>` 里的内容才是用户真正读的东西。而 `<body>` 里最基础的三类元素，恰好对应网页对人类的三种表达：**用文字说话、用链接走路、用图像展示**。学完这一节，你就能写出第一个「真正可点、可看」的多页面网站。

这三类元素也是后续一切内容的模板：列表、表格、表单、媒体，本质上都是「文本 + 结构」的变体；而链接与图像又都有各自的**属性系统**（`href`、`src`），理解属性如何工作，是理解整个 HTML 的关键钥匙。<span class="marginnote">HTML 的知识点是「标签名 + 属性 + 内容模型」三件套。这一节把三件套讲透，后面学列表、表格、表单时就只剩「换名字」了。</span>

## 1 文本元素：段落、标题与强调

网页上的文字不是一坨，而是被结构化成**段落（paragraph）**与**标题（heading）**。

**段落**用 `<p>` 表示。一个关键常识：**HTML 会折叠空白**——你在源代码里连写十个空格、按三下回车，渲染时都合并成一个空格。所以想要换行，必须用换行元素 `<br/>`（`<br>` 的 XHTML 写法），而不是在编辑器里敲回车。<span class="marginnote">空白折叠（whitespace collapsing）继承自排版传统：在纸媒里，连续空格和硬换行并不产生新段落。若忘了这点，你会发现「我明明换行了，浏览器却不换」。</span>

**标题**有六级：`<h1>` 到 `<h6>`，`<h1>` 最重要、字号最大，`<h6>` 最次要。它们不是「调大字号的工具」，而是**文档大纲的层级**——搜索引擎和屏幕阅读器靠标题层级理解文章的骨架。

**强调（emphasis）**有两种力度：

`<em>`：语气强调，默认斜体。屏幕阅读器会用不同语调读出。
`<strong>`：重要性强调，默认加粗。表示「这段内容格外重要」。

**辨析｜易错点：** `<b>` 和 `<i>` 只提供**视觉效果**（加粗、斜体），不含语义；`<strong>` 和 `<em>` 则携带**语义**。选哪个取决于目的：纯粹装饰用 `<b>`/`<i>`，要告诉机器「这里重要」用 `<strong>`/`<em>`。语义化是现代 HTML 的核心价值观，详见第5篇的《语义化与可访问性 ARIA》。

文本里还有一批「行内语义元素」，各自承担一种角色：`<code>` 标记程序代码、`<kbd>` 标记键盘按键、`<sup>`/`<sub>` 表示上/下标（公式、脚注）、`<mark>` 高亮文字、`<time>` 标记时间（配 `datetime` 属性供机器读取）、`<abbr>` 标记缩写（配 `title` 给出全称）。它们与 `<em>`/`<strong>` 同属「给文字贴语义标签」的家族——用得越准确，机器对内容的理解就越好。

文本里还有一批「字符实体」：`&nbsp;` 表示不换行空格（中文排版常用它防止「5 元」在行尾被拆成两行）、`&amp;` 显示 `&`、`&lt;`/`&gt;` 显示尖括号。它们让「在 HTML 里有特殊含义的字符」也能安全地显示为字面量——想真正打出 `<` 时，你写的必须是 `&lt;`。

文本里还有两个常用元素：`<span>` 是无语义的行内容器，常被 CSS/JavaScript 选中作为钩子；`<a>` 是链接，见下一节。

## 2 链接：锚元素与统一资源定位符

**链接（link）**是超文本的心脏，用锚元素 `<a>` 表示：

```html
<a href="https://example.com" target="_blank" rel="noopener">访问示例站</a>
```

它的核心属性是 **`href`（Hypertext Reference，超文本引用）**，指向前往的地址。地址有四种写法：

| 写法 | 示例 | 含义 |
| --- | --- | --- |
| 绝对 URL | `href="https://example.com/a.html"` | 完整的「协议 + 域名 + 路径」，可跨站 |
| 相对 URL | `href="about.html"` | 相对当前文档路径解析，站内跳转首选 |
| 锚点 | `href="#section2"` | 跳到当前页 id 为 `section2` 的元素 |
| 协议相对 | `href="//cdn.example.com/x.js"` | 跟随当前页面协议，http/https 自适应 |

`target="_blank"` 表示新标签页打开，但**必须配上 `rel="noopener"`**——否则新页面可以通过 `window.opener` 反向操纵你的页面，形成 **reverse tabnabbing** 安全漏洞。<span class="marginnote">现代浏览器已默认给 `<a target="_blank">` 隐式添加 `noopener` 行为，但手动写出来既是防御纵深，也让代码意图更清晰。安全细节在第5篇《前端安全基础》展开。</span>

**辨析｜易错点：** `href` 与 `src` 是两个最常混淆的属性——**`href` 是「跳转去」，`src` 是「嵌进来」**。链接不会把目标内容搬进当前页；而 `<img src>`、`<script src>` 会把资源下载并插入当前文档。这个差别决定了各自的使用场景：`<a>` 只能配 `href`，`<img>` 只能配 `src`。

链接的地址除了网页 URL，还有几类「特殊协议」：`mailto:hello@example.com` 打开邮件客户端、`tel:+8613800000000` 唤起拨号（移动端尤其好用）、`<a download="文件名">` 强制触发下载而非导航。这些协议让链接从「跳网页」扩展到「调起系统能力」——一个 `tel:` 链接，就是手机上一个可点击的号码。

链接的**可访问性**有专门要求：链接文字应「自解释」——「点击这里」是反模式，因为读屏用户会把一串链接文字连起来听成「点击这里点击这里……」；纯图标链接必须配 `aria-label`（第5篇 ARIA 的主角）；用 `target="_blank"` 新开窗口时要让用户「知道要新开」。

`title` 属性可以给链接加悬停提示，但它的局限在于**依赖鼠标**——触屏设备根本没有 hover，读屏用户也常忽略它。链接的名称应该写在可见文字里，`title` 只做锦上添花的补充，不做唯一的信息载体。

## 3 图像：src、alt 与可访问性

**图像元素** `<img>` 是**空元素**（没有内容、没有结束标签），一切信息都写在属性里：

```html
<img src="photo.jpg" alt="一只在窗台上打盹的橘猫" width="600" height="400">
```

三个属性各司其职：

**`src`（source，来源）**：图像地址，必填。地址写错则图像加载失败。
**`alt`（alternative，替代文本）**：图像加载失败时显示的文字，也是屏幕阅读器朗读的内容。它**不是可选项**——即使图像纯装饰，也要写 `alt=""` 表示「装饰，请忽略」。
- **`width`/`height`**：声明渲染尺寸。写它们有两个意义：避免图像加载时页面上下跳动（布局偏移）；当尺寸与图片真实比例不符时，`alt` 场景下也保持占位稳定。<span class="marginnote">布局偏移（layout shift）是 Web 性能指标 CLS 的核心度量——图片、广告等「后到的大块」会把已经渲染的文字挤到别处，读者正读着就跳行了。预先声明宽高是最简单的修复。</span>

图像格式的常识：**JPEG** 适合照片（有损压缩，不支持透明），**PNG** 适合图标与需要透明的图（无损，体积大），**GIF** 适合简单动图（256 色），**SVG** 是矢量图，放大不失真，适合 Logo 与图表，**WebP/AVIF** 是新一代格式，体积更小、浏览器支持已成熟。

此外，`<figure>` 与 `<figcaption>` 是「图 + 题注」的语义容器：把 `<img>` 与说明文字包在一起，图注与图片的关联在语义层面被钉死——屏幕阅读器能读出「图：一只打盹的猫」，搜索引擎也能把题注当图片上下文。它比「图片下面随便放段小字」严谨得多，也是第5篇语义化的标准做法。

**辨析｜易错点：** 不要把图片当文字用。把「营业执照」四个字做成 `photo.png`，搜索引擎和屏幕阅读器都读不到。真正的做法是普通文本 + 样式控制，或者至少把文字写进 `alt`。

图像的**加载性能**同样是属性系统的职责：`loading="lazy"` 让视口外的图片延迟加载（滚动到附近才请求），`decoding="async"` 让解码不阻塞渲染，`srcset`/`sizes` 让浏览器按设备分辨率选图。这些属性不改变「图是什么」，却决定「图加载得顺不顺」——第28篇《Web 性能优化基础》会系统展开。

## 4 公式解析：相对 URL 的解析规则

这一节「有公式」吗？有一个隐藏的**解析公式**——浏览器把相对 URL 解析成绝对 URL 的规则。把它写出来，从此再不会困惑 `href="../css/style.css"` 到底指哪：

$$
\text{resolved} = \text{base\_dir} \; \oslash \; \text{relative\_path}
$$
