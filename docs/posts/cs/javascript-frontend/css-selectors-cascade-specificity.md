## 为什么从选择器与层叠开始

HTML 解决了「页面里有什么」，CSS（Cascading Style Sheets，层叠样式表）回答「这些东西长什么样」。而 CSS 的机制核心，全在它的全名里：**Cascading，层叠**——当多条规则同时作用于一个元素时，它们如何叠出最终结果。

这一步是整个前端最重要的思维转换：**HTML 是一次性的声明，CSS 是一个冲突仲裁系统**。你的样式表越大、参与方越多（外部框架、组件库、内联样式），「谁说了算」就越关键。不理解层叠规则，就会写出「明明写了样式却不生效」的玄学 bug，然后靠 `!important` 暴力解决，把优先级秩序搅得更乱。<span class="marginnote">层叠（cascade）一词借自「瀑布」的意象：上游的水一层层叠下来，每层的贡献都算数，但底层决定最终流向。CSS 里，同一属性的多条声明按规则「叠」起来，只有一个胜出。</span>

## 1 CSS 语法与三种引入方式

一条 CSS 规则由**选择器（selector）**与**声明块（declaration block）**组成：

```css
p {                /* 选择器：选谁 */
  color: red;      /* 声明：属性: 值 */
  font-size: 16px; /* 每条声明以分号结尾 */
}
```

引入样式有三种方式：

**外部样式表**：`<link rel="stylesheet" href="style.css">`——推荐，可缓存、可复用、关注点分离。
**内嵌样式块**：`<style>…</style>` 写在 `<head>`，适合单页小站。
- **内联样式**：`style="color: red"` 写在标签属性里——优先级极高，几乎无法被外部覆盖，一般只用于动态插入。

选择器家族按能力分级，从弱到强：

| 选择器 | 写法 | 选中什么 | 特异性 |
| --- | --- | --- | --- |
| 类型 | `p` | 所有 `<p>` 元素 | 最弱 |
| 类 | `.card` | `class="card"` 的元素 | 中 |
| ID | `#app` | `id="app"` 的元素 | 强 |
| 属性 | `[type="email"]` | 带该属性的元素 | 中 |
| 伪类 | `:hover`、`:first-child` | 状态/位置 | 按对应种类计 |
| 伪元素 | `::before`、`::first-line` | 元素的某部分 | 弱 |

**组合器（combinator）**把选择器连成「路径」：`div p` 后代、`div > p` 直接子代、`h1 + p` 相邻兄弟、`h1 ~ p` 一般兄弟。<span class="marginnote">后代组合器（空格）是最常用的「任意深度」选择；直接子代 `>` 更精确，能避免样式漏到不该去的嵌套深处——选择器越精确，越不容易误伤。</span>

## 2 层叠的三道关卡

当多条规则都想给同一元素的同一属性赋值，浏览器按**三道关卡**逐层裁决，只有闯过全部关卡才胜出：

1. **来源与重要性**：谁「更有资格」定义。
2. **特异性（specificity）**：谁选得「更精确」。
3. **源码顺序**：谁写得更靠后。

**关卡一：来源与 `!important`。** 声明按来源分三层：**浏览器默认样式**（user agent）→ **用户样式**（罕见）→ **作者样式**（我们写的）。作者样式默认赢过浏览器默认——这就是为什么 `<h1>` 默认很大，但你能改小。而 `!important` 是「核按钮」：`color: red !important` 把这条声明的权重翻到所有普通声明之上。它是合法的，但滥用它会毁掉优先级秩序——**永远优先考虑用特异性解决问题**，`!important` 留给「必须覆盖外部库」的场合。<span class="marginnote">`!important` 的正确使用场景：覆盖第三方组件库的样式、或实现可访问性相关的强制配色。日常开发中用它是「优先级失控」的信号——通常意味着某个选择器特异性设计得有问题。</span>

**关卡二：特异性（specificity）。** 这是 CSS 最需要精确理解的规则，见下一节的公式解析。

**关卡三：源码顺序。** 特异性打平后，**写在后面的声明获胜**。这也是为什么组件库要「最后引入」——它想赢过业务代码里特异性相同的规则。CSS Modules、Tailwind 等现代方案都在刻意管理这层顺序。
