## 为什么从选择器与层叠开始

HTML 解决了「页面里有什么」，CSS（Cascading Style Sheets，层叠样式表）回答「这些东西长什么样」。而 CSS 的机制核心，全在它的全名里：**Cascading，层叠**——当多条规则同时作用于一个元素时，它们如何叠出最终结果。

这一步是整个前端最重要的思维转换：**HTML 是一次性的声明，CSS 是一个冲突仲裁系统**。你的样式表越大、参与方越多（外部框架、组件库、内联样式），「谁说了算」就越关键。不理解层叠规则，就会写出「明明写了样式却不生效」的玄学 bug，然后靠 `!important` 暴力解决，把优先级秩序搅得更乱。<span class="marginnote">层叠（cascade）一词借自「瀑布」的意象：上游的水一层层叠下来，每层的贡献都算数，但底层决定最终流向。CSS 里，同一属性的多条声明按规则「叠」起来，只有一个胜出。</span>

## 1 CSS 语法与三种引入方式

一条 CSS 规则由**选择器（selector）**与**声明块（declaration block）**组成：

```css
p {                /* 选择器：选谁 */
  color: red;      /* 声明：属性: 值 */
  font-size: 16px; /* 每条声明以分号结尾 */
}
```

引入样式有三种方式：

**外部样式表**：`<link rel="stylesheet" href="style.css">`——推荐，可缓存、可复用、关注点分离。
**内嵌样式块**：`<style>…</style>` 写在 `<head>`，适合单页小站。
- **内联样式**：`style="color: red"` 写在标签属性里——优先级极高，几乎无法被外部覆盖，一般只用于动态插入。

选择器家族按能力分级，从弱到强：

| 选择器 | 写法 | 选中什么 | 特异性 |
| --- | --- | --- | --- |
| 类型 | `p` | 所有 `<p>` 元素 | 最弱 |
| 类 | `.card` | `class="card"` 的元素 | 中 |
| ID | `#app` | `id="app"` 的元素 | 强 |
| 属性 | `[type="email"]` | 带该属性的元素 | 中 |
| 伪类 | `:hover`、`:first-child` | 状态/位置 | 按对应种类计 |
| 伪元素 | `::before`、`::first-line` | 元素的某部分 | 弱 |

**组合器（combinator）**把选择器连成「路径」：`div p` 后代、`div > p` 直接子代、`h1 + p` 相邻兄弟、`h1 ~ p` 一般兄弟。<span class="marginnote">后代组合器（空格）是最常用的「任意深度」选择；直接子代 `>` 更精确，能避免样式漏到不该去的嵌套深处——选择器越精确，越不容易误伤。</span>

## 2 层叠的三道关卡

当多条规则都想给同一元素的同一属性赋值，浏览器按**三道关卡**逐层裁决，只有闯过全部关卡才胜出：

1. **来源与重要性**：谁「更有资格」定义。
2. **特异性（specificity）**：谁选得「更精确」。
3. **源码顺序**：谁写得更靠后。

**关卡一：来源与 `!important`。** 声明按来源分三层：**浏览器默认样式**（user agent）→ **用户样式**（罕见）→ **作者样式**（我们写的）。作者样式默认赢过浏览器默认——这就是为什么 `<h1>` 默认很大，但你能改小。而 `!important` 是「核按钮」：`color: red !important` 把这条声明的权重翻到所有普通声明之上。它是合法的，但滥用它会毁掉优先级秩序——**永远优先考虑用特异性解决问题**，`!important` 留给「必须覆盖外部库」的场合。<span class="marginnote">`!important` 的正确使用场景：覆盖第三方组件库的样式、或实现可访问性相关的强制配色。日常开发中用它是「优先级失控」的信号——通常意味着某个选择器特异性设计得有问题。</span>

**关卡二：特异性（specificity）。** 这是 CSS 最需要精确理解的规则，见下一节的公式解析。

**关卡三：源码顺序。** 特异性打平后，**写在后面的声明获胜**。这也是为什么组件库要「最后引入」——它想赢过业务代码里特异性相同的规则。CSS Modules、Tailwind 等现代方案都在刻意管理这层顺序。

## 3 公式解析：特异性怎么算

特异性可以写成一条**计分公式**。对每条选择器，把它拆成四类计数器：

$$
S = (a, b, c, d)
$$

四个计数器从高到低依次是：

- **$a$：内联样式**。写在 `style="…"` 属性里的声明，计 `a = 1`——它压过一切外部选择器。
- **$b$：ID 选择器个数**。`#app`、`#nav` 每出现一次加 1。
- **$c$：类、属性、伪类个数**。`.card`、`[type="email"]`、`:hover`、`:nth-child(2)` 都计入这一级。
- **$d$：类型选择器与伪元素个数**。`p`、`div`、`::before`、`::first-line` 计入这一级。

比较规则：**先比 $a$，平手再比 $b$，再比 $c$，最后比 $d$**——高位优先，像比较多位数一样从左到右。例如 `#app .card p` 的计数是 $(0, 1, 1, 1)$，`body .box:hover` 是 $(0, 0, 2, 1)$，前者胜出，因为 $b=1 > 0$ 一票决定，后面的位数都不用看了。

**辨析｜易错点：** 特异性的直觉陷阱是「10 个类能否打赢 1 个 ID」——**不能**。三个计数器是独立的位，不是十进制数字；`(0, 0, 10, 0)` 与 `(0, 1, 0, 0)` 相比，仍是后者赢。这也是为什么「每多一层嵌套，特异性就升高一档，越写越难覆盖」——控制选择器深度，就是控制你的样式可维护性。

## 4 实战：层叠规则怎么用

**避免 `!important` 的「军备竞赛」。** 当项目里到处是 `!important`，特异性彻底失去意义，改一处样式要带出十处。正确姿势：让每个组件的特异性都停在「一层类选择器」的低位，冲突交给源码顺序裁决。

**约定优于特异性**：CSS Modules、BEM（块/元素/修饰符）都刻意把选择器压成「单类」，让特异性恒为 $(0,0,1,0)$——于是「后写的赢」成为唯一裁决依据，规则变得可预测。BEM 的典型写法：`.card__title--large` 把「块、元素、修饰」都编码进一个类名。

**内联样式 vs 选择器**：JS 动态改样式用 `style` 属性（`el.style.color`）时，它落在 $a$ 这一档，压过所有外部选择器——这正是「JS 改样式总能生效」的底层原因。<span class="marginnote">所以「用 JS 改样式」与「用 CSS 类切换」是两种模式：前者走内联（$a$ 档），后者走类（$c$ 档）。框架里「状态改类名」之所以被推崇，是因为它把样式决策留在 CSS 内部，可维护性远高于满屏内联。</span>

**`@layer` 是层叠秩序的重构**（CSS 2022 年成为基线特性）：把 `@layer reset, base, components, utilities` 排好序，后声明的层天然压过前一层，让「组件库覆盖 reset」「工具类压过组件」不再靠特异性搏斗。<span class="marginnote">CSS 层（`@layer`）把「源码顺序」升级成「层间顺序」：先声明层名，再往各层里放规则。同层内仍按特异性与顺序裁决，但层与层之间直接按声明顺序压——特异性被关进层内，秩序由你定义。</span>

## 5 现代选择器：:is、:where 与 :has

近几年的 CSS 给选择器补了三件利器，它们与特异性直接相关：

**`:is(…)`**：把一组选择器合并，取**其中特异性最高者**。`.card :is(h1, h2, h3)` 等价于写了三条规则，但特异性按 `h1/h2/h3` 中最高者计——写起来省，行为不偷懒。

**`:where(…)`**：同样合并选择器，但**特异性恒为 0**。`h1:where(.dark) { color: #fff }` 里 `.dark` 完全不贡献特异性，因此这条规则永远输给任何带类的普通规则——适合「期望被任意组件覆盖的兜底样式」。

**`:has(…)`**：按「是否包含某子元素」反向选择父元素，被誉为「父选择器」。`.card:has(.badge) { border-color: red }` 选中「内含徽标」的卡片。它的特异性等于括号里参数的特异性，功能极强，让很多原本要 JS 参与的「状态判定」回到了 CSS。

```css
/* 一个列表头：统一样式，但 h1 规则不被 h1 的默认特异性带偏 */
nav :where(a) { color: inherit; }
/* 含标题的卡片加边框——旧 CSS 做不到的「父选择」 */
article:has(> h2) { border-top: 2px solid #1f6f8b; }
```

**辨析｜易错点：** 这三个伪类的支持度 2023 年前后在主流浏览器已齐整，但旧项目要注意基线。它们的价值不在于「能少写几行」，而在于**把特异性显式地握在手里**——`:where` 归零、`:is` 取高，让「这一层我根本不打算赢」与「这一层我必须赢」都能说清楚。

## 6 小结

- 一条规则由**选择器 + 声明块**构成；引入方式三种：外部样式表、`<style>` 块、内联样式。
- 层叠裁决三道关卡：**来源与重要性 → 特异性 → 源码顺序**；`!important` 是核按钮，滥用毁秩序。
- 特异性计分 $(a, b, c, d)$：内联 > ID > 类/属性/伪类 > 类型/伪元素；**高位优先，不是十进制相加**。
- 现代实践用 BEM、CSS Modules 压低特异性、让「后写赢」，用 `@layer` 定义层间秩序。
- 写样式先想「谁能赢」，而不是「我写了就该生效」——玄学 bug 大半是层叠没算清。
