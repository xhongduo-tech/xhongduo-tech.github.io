## 为什么从语句与流程控制开始

上一节有了数据（变量、类型、运算符），这一节让数据**动起来**。程序 = 数据 + 算法，而算法的骨架是**流程控制**：判断（if/switch）、循环（for/while）。没有它们，代码只是一行行顺序执行；有了它们，代码才能「看情况行事」「反复处理直到完成」。

这一节还要立住一个贯穿 JS 全程的**核心概念：表达式（expression）与语句（statement）的区分**。不理解这个区分，后面读箭头函数、模板字符串、React 的 JSX 时都会发懵——因为「能当值用」和「只能执行」是两回事。它是 JS 函数式风格（第15篇）的理论前提。<span class="marginnote">Zakas 第4章是「变量、作用域与内存」（实际是 V8 中 vars 与 scope），而「语句与流程控制」对应第3章后半的「语句」（Statements）小节。本章重新编排：先立「表达式 vs 语句」的认知框架，再逐个过条件与循环结构。</span>

## 1 表达式与语句：JS 的第一组二元对立

**表达式（expression）**：产生一个**值**的东西。`1 + 2`、`user.name`、`fn()`、`` `${x}` ``——它们都能被求值，都能放进任何「需要值」的地方。

**语句（statement）**：执行一个**动作**的东西。`let x = 1;`、`if (…) {…}`、`for (…) {…}`——它们不「产生值」，只是改变状态。

**关键区分**：

**赋值是表达式，声明是语句**：`x = 1` 是表达式（它的值是 1，可继续参与运算：`y = (x = 1)`）；`let x` 是语句。
**条件是三元的表达式版**：`condition ? a : b` 是表达式，**有值**；`if/else` 是语句，**无值**。

```js
// 三元是表达式，可直接赋给变量
const status = score >= 60 ? "及格" : "不及格";

// if/else 是语句，只能执行，不能「赋值」
let status;
if (score >= 60) { status = "及格"; } else { status = "不及格"; }
```

**直觉是什么？** 表达式像「名词」，语句像「动词」。函数式编程（JS 深受其影响）偏爱「表达式风格」——因为表达式可以组合、可以传值、没有副作用，天然更可预测。<span class="marginnote">这个区分是理解 React 的关键：JSX 里只能放表达式，不能放 if 语句——所以条件渲染用 `{cond && \lt 组件/>}`（表达式）而不用 `{if …}`。你现在打下的认知，到第4篇、以及将来学前端框架时都会反复用到。</span>

## 2 条件分支：if、else if 与 switch

**`if/else if/else`** 是最基本的条件结构：

```js
if (score >= 90) {
  grade = "A";
} else if (score >= 60) {
  grade = "B";
} else {
  grade = "C";
}
```

规则与易错点：

条件按顺序求值，**命中一个就短路**，后续 else if 不再看——所以分支顺序从「最严」到「最松」排列。
条件表达式的结果会被转成布尔（真值/假值，见上节）——`if ([])` 恒真、`if (arr.length)` 是「非空数组」的惯用法。
- 单语句分支可省略花括号，但**永远不省略**——后续加一行就踩「悬空 else」坑，统一加 `{}` 是工程铁律。

**`switch`** 用于「一值多分支」的场合：

```js
switch (command) {
  case "start":
    startEngine();
    break;
  case "stop":
    stopEngine();
    break;
  default:
    log("未知命令");
}
```

**`break` 不可或缺**：没有 `break` 会**穿透（fall through）**到下一个 case 继续执行——这既是陷阱也是特性。刻意让多个 case 共享一段代码时（如 `case 1:` `case 2:` 共用逻辑），穿透是合法的；否则每个 `case` 都要 `break`。<span class="marginnote">`switch` 用 `===` 比较——所以 `switch ("1")` 不会命中 `case 1`，类型不同直接不匹配。另外 `default` 位置不必在最后，但惯例放在末尾更可读。</span>

## 3 循环：for、while 与 do-while

三种循环各有适用场景：

```js
// for：知道次数
for (let i = 0; i \lt  10; i++) {
  console.log(i);
}

// while：先判断后执行，可能一次都不执行
let n = 0;
while (n \lt  5) { n++; }

// do-while：先执行后判断，至少执行一次
let m = 0;
do { m++; } while (m \lt  0);   // m 变成 1 才退出
```

**`for` 三段式**：初始化（`let i = 0`）、条件（`i \lt  10`）、更新（`i++`）。用 `let` 声明循环变量——它每次迭代创建新绑定，这在闭包场景（第15篇）里至关重要。
**`while`** 适合「不知道要循环几次，只知道什么时候停」——如轮询直到某状态达成。
- **`do-while`** 适合「先做一次再判断」——如至少让用户输一次。

`break` 立即跳出循环，`continue` 跳过本轮进入下一轮。**`break` 只跳出最内层循环**——多层循环想一次跳出，需要**标签（label）**：

```js
outer: for (let i = 0; i \lt  3; i++) {
  for (let j = 0; j \lt  3; j++) {
    if (i * j === 4) break outer;   // 直接跳出两层
  }
}
```

标签语句是 JS 里少有人用、但关键时刻唯一解法的结构。<span class="marginnote">死循环（infinite loop）的常见来源：忘记更新循环变量（`while` 里忘了 `n++`）、条件恒真（`while (true)` 却没 break）。浏览器里死循环会卡死标签页，调试时先怀疑这三处。</span>

## 4 数组与对象的循环：for...of 与 for...in

对集合的遍历，ES6 给了两个专用循环：

```js
for (const item of items) {        // 遍历值（数组、字符串、Map、Set…）
  console.log(item);
}
for (const key in obj) {           // 遍历键（对象、数组下标…）
  console.log(key, obj[key]);
}
```

**`for...of`**：遍历**可迭代对象的值**，配合 `const` 声明，是遍历数组、字符串、`Map`/`Set`（第17篇）的标准方式。
**`for...in`**：遍历**可枚举属性名**，主要用于普通对象。

**辨析｜易错点：** 两者极易用错——

- 用 `for...in` 遍历数组：拿到的是**下标字符串**（`"0"`、`"1"`），还会带上原型链上可枚举的属性，顺序也不保证——**数组遍历永远用 `for...of`**。
- 用 `for...of` 遍历对象：对象默认**不可迭代**，直接抛 `TypeError: obj is not iterable`——对象遍历用 `for...in` 或 `Object.keys()`。

一条经验法则：**数组/类数组值 → `for...of`；普通对象的键 → `for...in` 或 `Object.keys/entries`**。<span class="marginnote">`for...of` 的底层是<strong>迭代器协议</strong>（`Symbol.iterator`）——这正是第18篇《迭代器与生成器》的主角。现在记住「能 for...of 的都是可迭代的」，到第18篇你会拿到它的完整引擎。</span>

## 5 公式解析：条件表达式嵌套与真值短路

流程控制里有一族「表达式型分支」，值得用公式理清——它们都基于「表达式有值」这一性质：

$$
\text{result} = c_1 \,?\, v_1 : (c_2 \,?\, v_2 : v_3)
$$

**逐步拆解（嵌套三元）：**

- **第一步，判 `c_1`**：若 `c_1` 为真，整体值就是 `v_1`，后面全部忽略。
- **第二步，判 `c_2`**：否则看 `c_2`——为真取 `v_2`，为假取兜底 `v_3`。
- **第三步，注意右结合**：三元运算符是**右结合**的——`a ? b : c ? d : e` 被解析为 `a ? b : (c ? d : e)`。虽然 JS 语法允许，但**嵌套三元超过一层就不易读**，工程上推荐拆成 `if` 或用「早期返回」的函数。

再看**逻辑短路**的另一种「表达式分支」：

$$
\text{result} = A \;\&\&\; B
$$

- 若 `A` 为假值，直接返回 `A`（B 根本不求值——**短路**）。
- 若 `A` 为真值，返回 `B` 的值。

**直觉是什么？** `&&` 是「如果 A 成立，就执行/取 B」的压缩写法；`||` 是「如果 A 不成立，就用 B 兜底」。React 里的 `{isLoggedIn && <Welcome/>}` 就是这条公式的日常形态——**条件渲染 = 表达式短路**。<span class="marginnote">短路求值还有个副作用副作用防线：`A && B` 中若 `A` 为假，`B` 的<strong>一切副作用都不发生</strong>——所以「先判断再调用」可以写得极简：`user && user.logout()`。这也是第13篇真值表的实战延伸。</span>

## 6 小结

- **表达式**有值、可组合、可传参；**语句**执行动作、无值。三元的「表达式版 if」是函数式风格的地基。
- `if/else if` 按序短路，条件按真值/假值判断；单语句分支也要写 `{}` 防悬空 else。
- `switch` 用 `===` 比较，漏写 `break` 会穿透；`default` 兜底。
- `for` 知次数、`while` 先判后行、`do-while` 先行后判；`break`/`continue` 控流，标签可跳多层。
- **数组遍历用 `for...of`（取值），对象遍历用 `for...in` 或 `Object.keys`**——用错会拿下标或抛错。
- 嵌套三元与 `&&`/`||` 短路都是「表达式分支」，理解其求值顺序才能用好。

在下一节，我们接触 JS 最重要的成员——**函数、作用域与闭包**。函数是 JS 的一等公民，闭包则是最令人敬畏、也最实用的机制，理解了它们，才算真正跨进 JS 的大门。
