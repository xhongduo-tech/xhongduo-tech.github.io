## 为什么从列表、表格与表单开始

上一节我们处理了「单个元素」——文本、链接、图像。但真实网页的内容是**成组**的：一列要点、一张数据表、一个登录框。HTML 为这三类「群体结构」各备了一组专用元素，它们共同撑起页面一半以上的内容组织工作。

更重要的是，这三类元素是**从「展示」走向「交互」的转折点**：列表与表格仍在「把信息摆整齐」，表单则第一次让用户**向网站输入数据**——这是后面 JavaScript 一切交互（第4篇的验证、第5篇的请求）的物理载体。学完这一节，你就凑齐了「网页从静态到动态」的第一块跳板。

## 1 列表：无序、有序与描述列表

HTML 有三种列表，对应三种「排列语义」：

**无序列表（unordered list）**：顺序无关紧要的并列项，用 `<ul>` + `<li>`，默认圆点符号。

```html
<ul>
  <li>牛奶</li>
  <li>鸡蛋</li>
  <li>面包</li>
</ul>
```

**有序列表（ordered list）**：顺序有意义（步骤、排名），用 `<ol>` + `<li>`，默认数字序号。它的魅力在属性：

- `type="1"` / `"A"` / `"a"` / `"I"` / `"i"`：数字、大写/小写字母、罗马数字。
- `start="3"`：从 3 开始编号，不必从 1 起。
- `reversed`：倒序编号，做「倒计时清单」天然合适。

**描述列表（description list）**：「术语 — 定义」的配对，用 `<dl>` 包裹，`<dt>` 是术语、`<dd>` 是定义。它最适合做词汇表、FAQ、属性说明：

```html
<dl>
  <dt>HTML</dt>
  <dd>超文本标记语言，网页的结构。</dd>
  <dt>CSS</dt>
  <dd>层叠样式表，网页的外观。</dd>
</dl>
```

**辨析｜易错点：** 三个列表不能混用语义——「导航菜单」本质是并列项，用 `<ul>`；「菜谱步骤」有先后，用 `<ol>`；「这个符号是什么意思」用 `<dl>`。判断方法：**顺序换掉会不会改变含义？** 会，用 `<ol>`；不会，用 `<ul>`；是「名词—解释」的配对，用 `<dl>`。列表可以**嵌套**（一个 `<li>` 里再放一个 `<ul>`），做多级目录。<span class="marginnote">把 `list-style-type: none` 加上 `padding: 0`，`<ul>` 的圆点与缩进就消失——现代导航栏几乎都是用「无样式的 `<ul>`」做的。去掉装饰后，列表元素剩下一份「条目的语义骨架」，这正是语义化的价值。</span>

## 2 表格：行列与语义分区

**表格（table）**把数据摆成「行 × 列」的二维网格。最基础的骨架：

```html
<table>
  <tr>
    <th>水果</th>
    <th>单价</th>
  </tr>
  <tr>
    <td>苹果</td>
    <td>5 元/斤</td>
  </tr>
</table>
```

**`<tr>`** 是行，**`<th>`** 是表头单元格（默认加粗居中），**`<td>`** 是数据单元格。横向合并用 `colspan="2"`，纵向合并用 `rowspan="2"`——这两者是把表盘出「不规则形状」的手段。

**表格的语义分区**是它区别于「随便画个网格」的地方：用 `<thead>`、`<tbody>`、`<tfoot>` 把表头、表体、表尾分组。现代规范还要求用 **`scope` 属性**声明表头管的是行还是列——`<th scope="col">` 表示「这是列的表头」：

```html
<table>
  <thead>
    <tr><th scope="col">季度</th><th scope="col">营收</th></tr>
  </thead>
  <tbody>
    <tr><td>Q1</td><td>120 万</td></tr>
    <tr><td>Q2</td><td>150 万</td></tr>
  </tbody>
  <tfoot>
    <tr><td>合计</td><td>270 万</td></tr>
  </tfoot>
</table>
```

`scope` 与 `thead/tbody/tfoot` 的价值，在于让**屏幕阅读器**把「表头」与「数据」正确配对——读屏用户听到 Q2 时能知道「它的表头是季度」而不是一串裸数字。表格是读屏体验最难做好的元素，语义分区是全部基础。<span class="marginnote">表格在手机上的适配是个老大难：宽表必然溢出。第11篇《响应式设计与媒体查询》会给三种解法——横向滚动容器、折叠成卡片、砍次要列。语义结构完整，这三种方案才有实施前提。</span>

## 3 表单：控件与交互

**表单（form）**是网页里「让用户输入数据」的容器。最精简的例子：

```html
<form action="/search" method="get">
  <label for="q">搜索</label>
  <input type="text" id="q" name="q">
  <button type="submit">提交</button>
</form>
```

**`action`**：数据送到哪；**`method`**：用 `get`（数据在 URL 里，适合搜索）还是 `post`（数据在请求体里，适合提交内容）。`<input>` 的 **`type`** 决定控件长什么样、键盘怎么弹、浏览器怎么校验——从最简单的 `text` 到 `email`、`number`、`date`、`checkbox`、`radio` 等。

**`<label>` 必须与控件绑定**：用 `for` 指向控件的 `id`。绑定后，点击标签文字等于点击控件（手机党福音），屏幕阅读器也能正确读出「这个输入框是干嘛的」。**`name` 属性是数据的名字**——提交时浏览器发送的是「名字 = 值」的键值对，没有 `name` 的控件不会随表单提交。

**`<select>`** 下拉框与 **`<textarea>`** 多行文本框是 `<input>` 的补充：`select` 用 `<option>` 给出选项、`multiple` 可多选；`textarea` 用 `rows`/`cols` 定初始尺寸，可自由拉伸。<span class="marginnote">`placeholder` 属性显示的「提示文字」不是提交值，也<strong>不应替代 `<label>`</strong>——提示会在输入时消失，读屏也读不到。标签与提示是两回事：标签回答「这是什么」，提示回答「怎么填」。</span>

## 4 核心对比表：input 常用类型

`<input>` 的 `type` 是表单世界里最值得背的一张表。同一段代码，换 `type` 就换一套交互：

| type | 外观/交互 | 浏览器内置校验 | 典型用途 |
| --- | --- | --- | --- |
| `text` | 单行文本框 | 无 | 姓名、昵称 |
| `email` | 文本框 + 邮件键盘 | 检查含 `@` | 邮箱 |
| `password` | 遮罩显示 | 无 | 密码 |
| `number` | 数字微调器 | 必须可解析为数字 | 数量、价格 |
| `date` / `time` | 日期/时间选择器 | 格式校验 | 预约、生日 |
| `checkbox` | 复选框 | 无 | 多选、勾选协议 |
| `radio` | 单选框（同 `name` 互斥） | 无 | 二选一/多选一 |
| `range` | 滑块 | 无 | 音量、筛选区间 |
| `file` | 文件选择器 | 无 | 上传头像 |
| `submit` / `button` | 提交/普通按钮 | 无 | 触发动作 |

**辨析｜易错点：** 使用 `type="email"`、`type="number"` 时，浏览器会做**轻量客户端校验**——这省事，但它只是第一道防线。真正的数据合法性要在服务端复验，因为任何人都能绕过浏览器直接发请求（这是第5篇《前端安全基础》的核心议题之一）。客户端校验的职责是「即时反馈、少一次无效往返」，不是「安全」。

## 5 表单的组织：fieldset、required 与提交

表单一大，就需要组织与约束手段：

**`<fieldset>`** + **`<legend>`**：把相关控件圈成一组并给组命名——「个人信息」「配送地址」各一组，读屏用户能理解分组逻辑。

**`required`**：必填标记。配 `type="email"` 等即可让浏览器拦截空提交并给出提示。

**`pattern`**：正则校验，`pattern="[0-9]{11}"` 强制 11 位数字——它是「复杂格式校验」的入口，第4篇《表单验证与客户端交互》会把它与 JS 配合讲透。

**`disabled`**：禁用控件，不参与提交、不可编辑；配合 JS 做「同意条款后才能提交」的动态开关。

**提交的归宿**：点击 `submit` 按钮，浏览器把**所有带 `name` 的控件**打包成「名 = 值」对，按 `method` 与 `action` 发往服务器。这套「表单即数据包」的心智模型，直接衔接第4篇《Fetch 与网络请求》——那里我们会看到，现代前端更常用 JavaScript 拦截这次提交、用 `fetch` 异步发送，让页面不刷新也能完成交互。

## 6 小结

- 三种列表对应三种语义：`<ul>` 并列、`<ol>` 有序（`type`/`start`/`reversed`）、`<dl>` 术语定义。
- 表格用 `<tr>`/`<th>`/`<td>` 排布，`colspan`/`rowspan` 合并，`<thead>`/`<tbody>`/`<tfoot>` + `scope` 提供读屏语义。
- 表单的核心契约：**`action` + `method` + 控件的 `name`**——浏览器把「名 = 值」对发给服务器。
- `<input type>` 决定控件形态与内置校验；`<label for>` 必须绑定控件；`placeholder` 不是标签的替代品。
- 客户端校验只是第一道防线，服务端复验是安全底线；`fieldset`/`required`/`pattern`/`disabled` 是组织与约束工具。
- 现代提交路径：JS 拦截 + `fetch` 异步发送——第4篇的主角。
