## 为什么从响应式开始

2010 年前后，手机浏览网页还要经历「缩小再放大」的痛苦：桌面版网页在手机上被等比缩成邮票大小。伊桑 · 马科特 2010 年提出**响应式设计（responsive web design）**，给出解决方案：**一套 HTML，随屏幕环境自适应**，而不是为每类设备写一套页面。

响应式是前面所有布局知识的验收场：**流式网格**（第9、10节的 `fr`、百分比）、**弹性图像**（第2节的 `max-width: 100%`）、**媒体查询**（本节核心），三者合一才是完整方案。它还与第28篇《Web 性能优化》直接相关——移动端流量与网速约束，让「响应式 + 性能」成为一对必须同时解决的问题。<span class="marginnote">响应式三要素是马科特原书的核心框架：流式网格（fluid grid）让布局按比例流动、弹性图像（flexible images）让图片随容器缩放、媒体查询（media queries）按视口切换样式。现代实践又加了第四条：`clamp()` 等比例函数让「流动」更精细。</span>

## 1 流式网格：让布局随宽度流动

「响应式」的第一步，是让布局**根本不用断点也能自适应**。手段就是前面学的相对单位：

**宽度用百分比或 `fr`**：`grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))`——列数随容器宽度自动增减。
**字号用 `rem`**：根字号统一，改一处全站缩放。
- **间距用 `gap`**：不写死 margin，靠弹性容器分配。

流式网格的目标是「**大部分情况下，页面自己就能长好**」；媒体查询只负责「少数关键的形态切换」。好的响应式设计，断点越少越好——靠流式布局吸收连续变化，靠媒体查询处理离散转折。

**辨析｜易错点：** 「流式」不等于「无限拉伸」。超宽屏上正文行若拉成整屏宽，读起来会累——这正是 `max-width: 60ch`（约 60 个字符宽）这类「阅读宽度上限」的用途。流式布局 + 内容上限，才是舒适的可读性。

## 2 弹性图像与媒体

图像是响应式布局最容易撑爆的成员。三条铁律：

```css
img, video {
  max-width: 100%;   /* 永不超出容器 */
  height: auto;      /* 保持宽高比 */
}
```

`max-width: 100%` 让媒体随容器收缩而不是溢出；`height: auto` 保证收缩时不变形。配上第1篇《媒体元素与嵌入内容》的 `srcset`/`sizes`，就得到「**容器自适应 + 分辨率自适应**」的完整图像方案。

表格也是响应式难点：宽表格在小屏必然溢出。三种常用策略——容器 `overflow-x: auto` 让表格可横向滚动；或在小屏用媒体查询把表格「折叠」成卡片式堆叠；或砍掉次要列。没有银弹，取决于数据的重要程度。<span class="marginnote">「表格折叠成卡片」的实现思路：在小屏媒体查询里，把 `<tr>` 变 `display: block`、`<td>` 前用 `::before` 注入表头文字——数据从「行列」重排成「条目」，是纯 CSS 的经典技巧。</span>

## 3 媒体查询：按环境切换样式

**媒体查询（media query）** 根据设备特征有条件地应用样式：

```css
@media (max-width: 768px) {
  .sidebar { display: none; }   /* 窄屏隐藏侧栏 */
  .nav { flex-direction: column; }
}
```

语法拆解：`@media` 后跟**媒体类型**（可选，`screen` 屏幕、`print` 打印）与**特性查询**。最常用的特性：

| 特性 | 示例 | 含义 |
| --- | --- | --- |
| 宽度 | `(min-width: 768px)` | 视口宽 ≥ 768px |
| 宽度 | `(max-width: 768px)` | 视口宽 ≤ 768px |
| 方向 | `(orientation: portrait)` | 竖屏（宽 < 高） |
| 偏好配色 | `(prefers-color-scheme: dark)` | 系统处于深色模式 |
| 减弱动效 | `(prefers-reduced-motion: reduce)` | 用户请求减少动画 |

**`min-width` 与 `max-width` 决定响应式策略方向**：用 `min-width`（从小到大）是**移动优先**，用 `max-width`（从大到小）是**桌面优先**——见下节。`prefers-color-scheme` 是「深色模式」的原生开关；`prefers-reduced-motion` 是**可访问性**硬需求——对晕动症用户，动画必须可关闭（呼应第1篇的可访问性主线）。<span class="marginnote">`prefers-reduced-motion` 是 WCAG 2.1 明确要求的可访问性特性。尊重它的做法：`@media (prefers-reduced-motion: reduce) { * { animation: none; transition: none; } }`——一条规则，为易眩晕的用户关掉一切动效。</span>

## 4 移动优先与桌面优先

响应式的两种写法方向相反，默认样式与断点语义完全不同：

| 策略 | 默认样式 | 断点写法 | 覆盖方向 |
| --- | --- | --- | --- |
| 移动优先 | 手机样式 | `@media (min-width: …)` | 越宽越「升级」 |
| 桌面优先 | 桌面样式 | `@media (max-width: …)` | 越窄越「降级」 |

**移动优先**是当前主流：

```css
/* 默认：手机布局 */
.nav { flex-direction: column; }

/* ≥ 768px：横向导航 */
@media (min-width: 768px) {
  .nav { flex-direction: row; }
}
```

为什么推荐移动优先？三个理由：

1. **强制聚焦核心**：先写手机版，逼你只保留最重要的内容与功能。
2. **渐进增强**：基础样式覆盖所有设备，大屏只是在上面「增强」——桌面浏览器、老浏览器都能得到可用版本。
3. **性能**：手机端默认加载最少样式，大屏才追加（现代构建工具还会配合懒加载）。

**辨析｜易错点：** 断点值不要「拍脑袋」。常见约定是 576 / 768 / 992 / 1200（源自 Bootstrap 栅格），但**断点应跟着内容走**：当布局在某宽度「开始变难看了」，那才该加断点。先内容后断点，而不是先断点后迁就内容。<span class="marginnote">「内容驱动断点」的操作方法：在 DevTools 里拖拽视口宽度，观察布局何时崩坏，记下那个宽度做断点。这样断点数量最少、每个都有存在理由，而不是机械地套四档栅格。</span>

## 5 公式解析：clamp() 让尺寸自动流动

现代 CSS 用 **`clamp(MIN, VAL, MAX)`** 在区间内自动取值，是「响应式字号/间距」的终极写法：

$$
\text{clamp}(m, v, x) = \max(m, \min(v, x))
$$

三步拆解：

- **第一步，内层 $\min(v, x)$**：在「首选值 $v$」与「上限 $x$」之间取较小者——值再大也不能超过上限。
- **第二步，外层 $\max(m, \cdots)$**：再把结果与「下限 $m$」比较取较大者——值再小也不能低于下限。
- **第三步，整体效果**：$v$ 落在 $[m, x]$ 区间内时原样生效，超出则被上下限夹住。把 $v$ 写成随视口变化的单位（如 `vw`），就得到「随屏缩放、但永不小于/大于某个尺寸」的自适应值。

典型用法：

```css
h1 { font-size: clamp(1.5rem, 1rem + 2vw, 3rem); }
```

桌面大屏时字号接近 3rem，手机上逼近 1.5rem，中间连续过渡——**一个属性替代了原本需要写两三个媒体查询断点的活**。`clamp()` 同样适用于 `width`、`padding` 与 `gap`，是「断点越少越好」理念的极佳工具。注意 `clamp` 的参数顺序必须是 MIN、VAL、MAX，写反了区间就会被上下限锁死成错误的固定值。

## 6 视口单位：vw/vh/vmin/vmax

媒体查询是「按断点切换」，而视口单位让尺寸**直接跟着视口走**，两者是响应式的两个维度。

| 单位 | 含义 |
| --- | --- |
| `vw` | 视口宽的 1%，`100vw` = 整屏宽 |
| `vh` | 视口高的 1%，`100vh` = 整屏高 |
| `vmin` | 视口宽、高中较小者的 1% |
| `vmax` | 视口宽、高中较大者的 1% |

典型场景：全屏首屏 `height: 100vh`；与 `clamp()` 配合做随屏缩放的标题；`vmin` 做「横竖屏都不溢出的方形容器」。**辨析｜易错点：** `100vh` 在移动端地址栏伸缩时会「超出一屏」，让页脚被顶出可视区——移动端常改用 `100dvh`（动态视口高度）或 `min-height: 100vh` 配合 `100dvh` 回退来规避。

## 7 小结

- 响应式三要素：**流式网格、弹性图像、媒体查询**；先靠相对单位吸收连续变化，再靠断点处理离散转折。
- 弹性图像铁律：`max-width: 100%` + `height: auto`；宽表格用滚动容器或折叠策略兜底。
- 媒体查询用 `min-width`（移动优先，渐进增强）还是 `max-width`（桌面优先，渐进降级）决定了整套写法的方向。
- `clamp(m, v, x) = max(m, min(v, x))` 一个函数替代多条断点；视口单位 `vw/vh/vmin/vmax` 让尺寸直接跟随视口。
- 尊重 `prefers-color-scheme` 与 `prefers-reduced-motion`，可访问性不是加分项而是底线。

在下一节，我们将让页面真正「动」起来：**变换、过渡与动画**——响应式解决了布局的弹性，动画解决的是状态的表达。
