## 为什么从排版与颜色开始

页面 90% 的内容是文字。文字好不好读、层级清不清晰，直接决定读者愿不愿意看下去。这一节把 CSS 的三个「观感开关」讲透：**字体**决定文字的骨架，**文本排版**决定文字的血肉（间距、对齐、大小写），**颜色**决定文字的情绪。

排版还有一个隐藏价值：它是**可读性（readability）与可访问性**的战场。字号太小、对比度太低，视觉受损的读者就无法阅读——第1篇《语义化与可访问性 ARIA》埋下的可访问性线，在这里进入实操。而 `em`/`rem` 的相对单位，则与响应式设计（第11篇）直接挂钩：排版单位选对了，整个页面的缩放就有了根基。<span class="marginnote">字号单位的选择是「绝对 vs 相对」的哲学：px 是绝对单位，字体放大设置对页面无感；em/rem 相对根字号，用户一改浏览器字号，整站文字跟着变——这是可访问性的硬需求，也是响应式排版的第一步。</span>

## 1 字体：font-family 与字体栈

**`font-family`** 指定字体，关键在「**栈（stack）**」——列出多个备选，浏览器按顺序取第一个可用的：

```css
body {
  font-family: "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
}
```

栈的最后一个 `sans-serif` 是**通用字体族**：`serif`（衬线）、`sans-serif`（无衬线）、`monospace`（等宽）、`cursive`（手写）、`fantasy`（装饰）。它保证「永远有字体可用」。中文网页栈的惯例：先列本机中文字体（PingFang/苹方、微软雅黑），再列西文字体兜底——因为中文字体体积巨大，通常靠系统自带，**除非是少量标题或图标，否则不要用 Web Font 加载整份中文字体**。

**Web 字体**让网页用上系统没有的字体，两种途径：

**`@font-face`**：自托管字体文件，`src` 指明 woff2/woff 格式与路径。
**Google Fonts / 字体 CDN**：一行 `<link>` 引入。

**辨析｜易错点：** 中文字体是「体积地雷」。一份简体中文字体包含数千个字形，动辄几 MB；而西文只需几十 KB。所以**正文不要整段用 Web 中文字体**，标题、Logo 少量使用才划算——这是性能（第28篇）与排版体验的经典权衡。<span class="marginnote">「字重」（font-weight）是字体的另一维度：`100`–`900`，`normal`=400、`bold`=700。注意：声明 `font-weight: 600` 但该字体没有 600 的字形时，浏览器会<strong>合成加粗</strong>（faux bold）或用最近的可用字重，效果往往不够精致。</span>

## 2 字号单位：px、em 与 rem

字号有三种常见单位，代表三种「参照系」：

| 单位 | 参照物 | 特点 |
| --- | --- | --- |
| `px` | 设备像素 | 绝对，不随环境缩放 |
| `em` | **父元素**字号 | 相对，层层继承会累积 |
| `rem` | **根元素**（`<html>`）字号 | 相对，但只认根，不累积 |

```css
html { font-size: 16px; }   /* 根字号 */
.box { font-size: 1.5rem; } /* = 24px，无论嵌多深 */
.box span { font-size: 0.5em; } /* = 12px，基于父 .box 的 24px */
```

**为什么 `em` 会累积？** 因为 `em` 是「基于父元素字号」的相对单位：父是 24px，子 `0.5em` 是 12px；若孙再 `0.5em`，基于子，变 6px——层层相乘，越嵌越小，这在嵌套组件里极易失控。<span class="marginnote">`em` 的「失控」并非全是缺点：padding、margin 用 `em` 会随自身字号等比缩放，做「字号越大内边距越大」的自适应按钮很自然。规矩是——<strong>字号用 rem，间距可 em，px 留给边框与固定元素</strong>。</span>

`rem` 修复了累积问题：永远基于 `<html>` 的根字号，与嵌套深度无关。这也是为什么现代框架普遍 `html { font-size: 16px }` 然后用 `rem` 定字号——改一处根字号，全站缩放。

## 3 文本排版：行高、对齐与装饰

字体选好，文本的「版式」由一组属性打磨：

**`line-height`**：行高，文本行之间的垂直间距。推荐写法是无单位数值（如 `1.5`），表示「字号 × 1.5」——它会随字号自动缩放，是最稳的用法。<span class="marginnote">行高是中文长文的生命线：过小则行与行粘连、阅读时串行；过大则段间松散。正文一般 1.5–1.8，标题可收紧到 1.2 左右。</span>
**`text-align`**：水平对齐，`left`/`center`/`right`/`justify`。`justify` 两端对齐，但**中文正文慎用**——它靠拉伸词间空格实现，中文可能挤出难看的大空隙。
**`text-decoration`**：装饰线，`underline` 下划线、`line-through` 删除线、`none` 去线（常用于去掉链接下划线）。
- **`text-transform`**：大小写变换，`uppercase`/`lowercase`/`capitalize`——只对西文有效，是「展示层」操作，不改动原始文本。
- **`letter-spacing`** / `word-spacing`：字距与词距，标题常用 `letter-spacing` 加一点间距显得更疏朗。
- **`white-space`**：空白处理，`nowrap` 禁换行（配合省略号）、`pre` 保留空格换行。

**单行文本省略号**是三件套连用的经典配方：

```css
.ellipsis {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;  /* 溢出显示 … */
}
```

## 4 核心对比表：颜色的五种写法

颜色在 CSS 里有多种记法，本质都是「把颜色编码成数字」：

| 写法 | 示例 | 通道 | 适用 |
| --- | --- | --- | --- |
| 关键字 | `red`、`transparent` | 预定义 | 原型/调试 |
| 十六进制 | `#c0392b` | RGB 各 2 位十六进制 | 最常用 |
| `rgb()` | `rgb(192, 57, 43)` | 十进制 RGB | 需要计算时 |
| `rgba()` | `rgba(0,0,0,0.5)` | RGB + 透明度 | 半透明遮罩 |
| `hsl()` | `hsl(7, 70%, 46%)` | 色相/饱和度/亮度 | 调色板设计 |

**`hsl()` 为什么值得学？** 它把「颜色」拆成人更容易直觉操作的三个量：**色相**（0–360 度色环上的角度）、**饱和度**（0–100%）、**亮度**（0–100%）。想调「同色系更浅一点」？只动亮度即可；想找「互补色」？色相加 180 度。设计系统里的调色板几乎都用 HSL 思维生成。<span class="marginnote">色相环 0° 是红、120° 是绿、240° 是蓝，180° 互补。CSS 的 `hsl()` 与现代的 `oklch()` 都属这一类「知觉色彩空间」，比 RGB 的「三个数字」更贴近人怎么想颜色。</span>

**透明度**用 `opacity`（整个元素包括子元素一起变透明）与 `rgba`/`hsla`（只变当前层的颜色通道）区分——前者是「整层淡出」，后者是「颜色本身带 alpha 通道」。

## 5 公式解析：em 与 rem 的换算

排版单位的关系可以写成两条**换算公式**，把「相对值」翻译成像素：

$$
\text{px}_{\text{em}} = \text{font-size}_{\text{parent}} \times \text{em}
$$

$$
\text{px}_{\text{rem}} = \text{font-size}_{\text{root}} \times \text{rem}
$$

两条式子都在做同一件事：把相对单位还原成像素。逐项拆解：

- **$em$ 的换算链**：$em$ 是「乘法链」。根字号 16px，父元素 `1.5em` = 24px；子元素 `0.5em` 基于父的 24px，= 12px；再下一层 `0.5em` 又基于 12px，= 6px。每一层都要**回头看父元素**，这就是它「越嵌越小、层层累积」的原因。
- **$rem$ 的换算链**：$rem$ 只看根。无论嵌套多深，`1.5rem` 永远是 $16 \times 1.5 = 24px$。锚点只有一个，链条不累积——这是它适合做「全局字号」的根本原因。
- **直觉对比**：$em$ 是「跟着父走」的相对性，适合间距随字号缩放的按钮；$rem$ 是「跟着根走」的全局性，适合定字号。两者共用一套换算逻辑，差别只在「参照物是谁」。

一个真实换算：根字号 16px，`.note { font-size: 0.875em }` 直接嵌在 body 下，则 0.875em = 14px——这就是「14px 小字」在相对体系里的写法。而 `.note { font-size: 0.875rem }` 写在哪里都是 14px。

**辨析｜易错点：** 中英文混排时，行高 `line-height` 建议用无单位数值（如 `1.6`），它等于「1.6 × 当前字号」，随字号自动缩放；写成 `line-height: 24px` 则在大字号下反而拥挤。`px`、`em`、`rem` 三者没有「谁绝对正确」，规则是：**字号用 rem，间距可 em，边框与固定结构用 px**。

## 6 小结

- **font-family** 用字体栈兜底，通用字体族保证「永远有字体」；中文正文慎用 Web 字体（体积地雷）。
- 字号单位三参照系：`px` 绝对、`em` 看父、`rem` 看根；`em` 的换算链会累积，`rem` 只认根。
- 文本排版六件套：`line-height`（无单位数值最稳）、`text-align`、`text-decoration`、`text-transform`、`letter-spacing`、`white-space`。
- 颜色五写法（关键字/hex/`rgb()`/`rgba()`/`hsl()`）本质都是「把颜色编码成数字」；`hsl()` 贴近人的直觉，调色板首选。
- 换算是纯数学：$\text{px} = \text{font-size}_{\text{参照}} \times \text{相对值}$；选对参照系，全站缩放就有了根基。
