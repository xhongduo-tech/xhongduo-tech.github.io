## 为什么从语义化与可访问性开始

HTML 第1篇的结尾，我们谈「语义」；这一篇则把它推到前台。**语义化（semantics）**是指：HTML 标签不仅决定「长什么样」，更声明「这是什么」——`<h1>` 不只是大号字，它宣告「这里是页面主标题」；`<nav>` 不只是横条，它宣告「这里是一组导航链接」。

为什么重要？因为**网页的消费者不只有人眼**：搜索引擎机器人逐段理解页面结构，屏幕阅读器按文档大纲逐级朗读，盲人、低视力、认知障碍用户依赖这些语义导航页面。据世界卫生组织估算，全球有超过 10 亿人存在某种残疾——语义化与可访问性（accessibility，常简称 a11y）不是加分项，而是让网页「对所有人可用」的基础工程。这也是后续一切「样式与交互」都必须遵守的前提。

## 1 语义化元素：给结构贴标签

HTML5 引入了一组「分区语义元素」，把以前清一色的 `<div>` 升级成有意义的区块：

| 元素 | 语义 | 典型位置 |
| --- | --- | --- |
| `<header>` | 页头/区块头 | 站点标题、Logo、导航 |
| `<nav>` | 导航链接组 | 主导航、面包屑 |
| `<main>` | 页面主内容（全页唯一） | 正文区 |
| `<article>` | 可独立分发的内容单元 | 博客正文、新闻、评论 |
| `<section>` | 主题相关的分区 | 章节、分组 |
| `<aside>` | 与主内容间接相关 | 侧栏、附注、广告 |
| `<footer>` | 页脚/区块尾 | 版权、联系方式 |

```html
<header>
  <h1>我的博客</h1>
  <nav>
    <a href="/">首页</a> <a href="/about">关于</a>
  </nav>
</header>
<main>
  <article>
    <h2>HTML 语义化入门</h2>
    <p>正文……</p>
  </article>
</main>
<footer>© 2026 从极限到大模型</footer>
```

**语义元素与 `<div>` 的关系**：`<div>` 是「无语义的通用容器」——当没有合适的语义元素时才用它，它是最后的退路而不是默认选择。判断口诀：**先问「这个区块是什么」，有对应语义元素就用它，没有才用 `<div>`**。

**为什么这不只是「换个名字」**：屏幕阅读器把 `<nav>` 读出为「导航地标」，用户可以一键跳到导航；搜索引擎把 `<article>` 视为可独立索引的内容单元；浏览器插件、浏览器内置的「阅读模式」也靠这些语义重建排版。**语义是给机器和辅助技术的「接口」**，它和 CSS 一样影响使用体验——只是用户「看不见」。

## 2 文档大纲：标题层级是导航

**标题层级（heading hierarchy）**是页面最基础的「地图」：`<h1>` 一个、往下 `h2 → h3 → h4` 逐级嵌套，构成大纲树。

**辨析｜易错点：** 两个高频错误——**跳级**（从 `<h2>` 直接到 `<h4>`，大纲出现断层）与**用标题做样式**（为了「字大」用 `<h3>` 装小段落）。标题是「结构」，字号是「样式」，二者分离正是 CSS 的职责：结构该用 `<h2>` 就用 `<h2>`，想让它小一点用样式改，而不是降级用 `<h4>`。屏幕阅读器用户最依赖这个大纲「扫读」长文——跳级会让大纲读起来像电梯缺了楼层。<span class="marginnote">大纲是读屏用户扫读长文的主要手段：他们可以调出「标题列表」快速定位。一份「一个 `<h1>`、层级规整」的大纲，效果相当于给页面做了一份目录。跳级、缺级都会让这份目录缺页。</span>

**视觉顺序与文档顺序**：读屏按**文档源码顺序**朗读，而不是视觉位置。CSS 把某个元素视觉上移到顶部（如 `position: fixed` 的导航），读屏仍按源码顺序读。因此**源码顺序应当反映内容的逻辑顺序**——「先主内容后侧栏」是通用准则。

## 3 ARIA：给自定义组件配音

HTML 原生元素自带语义，但复杂的自定义组件（下拉菜单、对话框、滑块）没有对应标签。**ARIA（Accessible Rich Internet Applications，无障碍富互联网应用）**提供一组属性，为这些组件「补配语义」。

三个核心概念：

**ARIA 角色（role）**：声明「这个自定义元素是什么」，如 `role="dialog"`、`role="tab"`、`role="slider"`。

**ARIA 状态与属性（state & property）**：声明「它现在怎样」，如 `aria-expanded`（是否展开）、`aria-hidden`（是否对辅助技术隐藏）、`aria-label`（无可见文字时给它一句名字）。

```html
<button aria-expanded="false" aria-controls="menu">菜单</button>
<div id="menu" hidden>
  <a href="/a">选项 A</a>
</div>
```

`aria-expanded="false"` 告诉读屏「这个按钮控制的面板当前收着」，用户点了之后 JavaScript 把它改成 `true` 并去掉 `hidden`——读屏用户因此知道「菜单现在开了」。

**第一条规则：优先用原生元素。** ARIA 有一条根本原则——**「无 ARIA 胜过劣质 ARIA」**。能用 `<button>` 就别用 `<div role="button">`：原生元素自带键盘交互、焦点管理、读屏语义，ARIA 只负责「补」，不负责「替」。只有当原生标签确实表达不了时（如自定义滑块、对话框、选项卡），才动用 ARIA，且必须同时补足键盘支持。

**ARIA 的「第一规则」还有半句**：别在原生元素上重复声明——`<button role="button">` 是冗余的废话。<span class="marginnote">ARIA 最著名的口号是「ARIA 的第一个规则是不要使用 ARIA」——能原生表达就用原生。每加一层 `role`，都意味着你要亲手负责一层键盘与读屏行为，那是原生标签免费赠送的。</span>

## 4 可访问性的三项实操

除语义外，可访问性有几个「检验尺子」式的指标：

**焦点（focus）**：键盘用户（含读屏用户）用 Tab 键在可交互元素间移动。三条铁律：所有可交互元素必须能获得焦点（原生 `<button>`/`<a>`/`<input>` 自带，自定义组件要加 `tabindex="0"`）；焦点移动要有**可见指示**（默认的外框 outline，别一删了之）；弹窗打开时焦点要**移进弹窗**、关闭后**归还触发它的按钮**——这是第4篇《DOM 树结构与节点操作》与事件篇的实操话题。

**对比度（contrast）**：前景文字与背景的明暗差要足够。WCAG（Web 内容可访问性指南）规定正文最低 **4.5:1**、大号文字 **3:1**。灰色字配浅灰底常只有 2:1 左右，视觉正常的人看着都费劲——这是「设计感」与「可读性」最常见的冲突点，DevTools 里直接能测。

**`alt` 与标签**：图片 `alt`（第2篇）、表单 `<label>`（第3篇）——前几篇反复强调的细节，在可访问性这里汇成同一条底线：**所有非文字内容都必须有文字替身**。

**优先增强可用性**：`prefers-reduced-motion`（第11篇讲过）、深色模式、放大排版——这些现代 CSS 特性让「可访问性」从「硬性规范」变成「顺手的体验提升」。

## 5 核心对比表：语义元素与无障碍对照

语义化的目标读者是「机器 + 辅助技术」。把常见区块与其语义、读屏效果对照：

| 你写的 | 语义含义 | 读屏用户听到 | 不用它时 |
| --- | --- | --- | --- |
| `<h1>`–`<h6>` | 文档大纲层级 | 「标题，第2级，正文标题」 | 层级信息丢失 |
| `<nav>` | 导航地标 | 「导航地标」可一键跳到 | 找不到导航入口 |
| `<main>` | 主内容地标 | 「主内容地标」一键跳正文 | 每次都要听完整个页头 |
| `<button>` | 可点击按钮 | 「按钮」，可空格激活 | 键盘不可操作 |
| `<label for>` | 输入框的名字 | 「搜索，编辑框」 | 读屏只读「编辑框」 |
| `aria-label` | 无文字元素的名字 | 「关闭」 | 图标按钮成「按钮」 |
| `alt` | 图片的文字替身 | 朗读图片描述 | 图变成「图像」或无信息 |

**辨析｜易错点：** 语义化与 ARIA 最容易混淆的点——**语义元素是「用对的标签」、ARIA 是「给标签补语义」**。前者用原生 `<nav>`、`<button>` 就已经把语义写进结构；后者在原生表达不了时加 `role`/`aria-*` 属性。能原生就原生，是贯穿两者的唯一准则。

## 6 小结

- 语义化：标签声明「这是什么」而不只是「长什么样」；`<header>/<nav>/<main>/<article>/<footer>` 让结构有意义，`<div>` 是最后的退路。
- 标题层级是文档大纲：一个 `<h1>`、逐级嵌套；别跳级、别拿标题当样式工具。
- 读屏按**源码顺序**朗读；视觉顺序由 CSS 控制，逻辑顺序由 HTML 保证。
- ARIA 三件套：`role`（是什么）、状态属性（现在怎样）、`aria-label`（叫什么）；**第一规则是「优先用原生元素，无 ARIA 胜过劣质 ARIA」**。
- 三项检验：焦点可见且可达、正文对比度 ≥ 4.5:1、所有非文字内容都有文字替身（`alt`/`label`）。
- 语义化与可访问性贯穿全专题：第2篇 `alt`、第3篇 `label`、第11篇 `prefers-reduced-motion` 都是它的落点。
