## 为什么从变量与类型开始

HTML/CSS 把页面「画」了出来，但画出的页面是**死的**。要让页面「活」起来——响应用户点击、抓取数据、动态更新内容——需要一门能**存储数据、执行逻辑**的语言：JavaScript。这一节是 JS 的第一课：**数据在内存里怎么存、有哪些种类、用什么运算符加工**。

JS 常被戏称为「披着 C 外衣的 Lisp」：语法看起来像 C（分号、花括号），灵魂却完全不同——**动态类型、函数一等公民、基于原型**。这一节先立住最根本的两件事：**变量声明**（`let`/`const` 时代）与**数据类型**（原始类型 + 对象）。它们是后面一切 JS 知识——函数、对象、数组、异步——的共同地基。<span class="marginnote">Zakas 的《JavaScript高级程序设计》第3章是「语言基础」（Language Basics），涵盖语法、数据类型、运算符、语句四块。这里我们按「变量→类型→运算符→易错」的顺序重排，更贴合「先理解再练习」的学习曲线。</span>

## 1 变量声明：var、let 与 const

JS 有三种声明变量的关键字，理解差异是**第一道门槛**：

```js
var legacy = "老派声明";
let score = 42;      // 可重新赋值
const PI = 3.14;     // 常量，不可重新赋值
```

| 关键字 | 可重新赋值 | 作用域 | 变量提升 | 推荐 |
| --- | --- | --- | --- | --- |
| `var` | 是 | 函数作用域 | 提升且可重复声明 | 不用 |
| `let` | 是 | 块作用域 | 提升但存在「暂时性死区」 | 变量用 |
| `const` | 否 | 块作用域 | 同上 | 默认用 |

**块作用域**：`let`/`const` 只在最近的 `{ }` 内有效；`var` 只在函数内有效，`for` 循环里用 `var` 声明的变量，循环外也能访问——这是「闭包陷阱」（第15篇）的经典伏笔。
**暂时性死区（TDZ）**：`let`/`const` 虽「提升」到块顶，但声明之前访问会抛 `ReferenceError`，不像 `var` 静默得到 `undefined`。
- **`const` 的本质**：禁止**重新绑定**，不冻结对象内容。`const obj = { a: 1 }; obj.a = 2;` 合法；`obj = {}` 抛错。

**约定**：能用 `const` 就用 `const`——它表达「这个绑定不该变」，让代码的意图更清楚，也避免误改。确实需要重新赋值才用 `let`。<span class="marginnote">历史上 `var` 的函数作用域导致过无数 bug：循环里的 `var` 变量在回调里读到同一个最终值。ES6 引入 `let`/`const` 后，规范明确「新代码一律不用 `var`」。老代码里见到 `var`，理解它是「函数作用域」即可。</span>

## 2 原始类型：七个基本单元

JS 有**七种原始类型（primitive types）**，除 `object` 外的一切值都属于它们：

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| `number` | 数字，一律 IEEE 754 双精度浮点 | `42`、`3.14`、`1e3` |
| `string` | 字符串，三种引号 | `"a"`、`'b'`、`` `c` `` |
| `boolean` | 布尔 | `true` / `false` |
| `undefined` | 已声明未赋值 | `let x;` 的值 |
| `null` | 显式「空值」 | `null` |
| `symbol` | 唯一标识符 | `Symbol("id")` |
| `bigint` | 任意精度整数 | `9007199254740993n` |

**原始类型是「值」本身**：赋值时拷贝值，比较时比值。而**对象（object）是引用**：赋值时拷贝引用，两个变量可能指向同一块内存——这个「值 vs 引用」的差别，是 JS 后续所有数据行为的底层规律。

**`null` 与 `undefined` 的辨析**是新手第一坑：

`undefined` 是「**系统层面**的未定义」——变量声明了但没给值，访问不存在的属性，都得到它。
`null` 是「**程序员显式表示**的空」——我要清空一个引用、占个位，写 `null`。

语义上：**`undefined` 是「还没」，`null` 是「我设为空」**。但它们还有一个历史包袱——`typeof null === "object"`，这是语言诞生时无法修复的 bug，如今成为约定俗成。<span class="marginnote">为什么 `typeof null` 返回 `"object"`？因为 JS 的类型标签存储在值的最低几位里，`null` 的标签恰好是 0（object 的标签），修正它可能破坏无数现存代码，于是官方将其固化为「已知 bug」。理解它比吐槽它有用。</span>

## 3 数字与字符串：两个常用类型

**数字**只有一个类型 `number`，不管整数小数都按 64 位浮点（IEEE 754）存储。这带来两个经典后果：

**精度陷阱**：`0.1 + 0.2 !== 0.3`（约等于 `0.30000000000000004`），因为二进制无法精确表示 0.1。
**特殊值**：`NaN`（非数，`NaN !== NaN`）、`Infinity`（无穷）、`-0`（负零）。

**`NaN` 的诡异**：它自己不等于自己——判断一个值是不是 NaN 只能用 `Number.isNaN(x)`，不能用 `x === NaN`。任何含 `NaN` 的算术结果都是 `NaN`，且 `NaN` 会像传染病一样在运算链里扩散。<span class="marginnote">IEEE 754 是国际浮点标准：64 位里 1 位符号、11 位指数、52 位尾数。它能表示约 15–17 位十进制有效数字，超大整数（> 2^53）会丢失精度——这正是 `bigint` 类型存在的理由。</span>

**字符串**用三种引号：

单引号/双引号：等价的传统写法，内部可转义（`\n` 换行、`\'` 单引号）。
**模板字符串**（反引号）：支持**插值**与**多行**：

```js
const name = "前端";
const msg = `欢迎来到${name}专题，共${5 + 25}篇`;
```

`${}` 内可放任意表达式——字符串拼接从 `+` 升级为插值，是现代 JS 写字符串的默认选择。

## 4 运算符：算术、比较与逻辑

**算术**：`+ - * / % **`（加、减、乘、除、取余、幂）。注意 `/` 是浮点除，没有整数除法：`7 / 2 === 3.5`；取余 `%` 对正负数有符号规则：`-7 % 3 === -1`。

**比较**：`\lt  > \lt = >=` 与相等比较。相等比较有**双等与三等之分**——这是 JS 最大的坑之一，见下节公式解析。

**逻辑**：`&&`（与）、`||`（或）、`!`（非）。JS 的逻辑运算**返回的不是布尔，而是操作数本身**：

```js
const name = user.name || "匿名";   // name 为空则取默认值
const ok = isReady && doAction();   // isReady 为真才执行 doAction
```

`||` 取「第一个真值」，`&&` 取「第一个假值」——这就是「短路求值」的日常用法，也是现代代码里省略 if 的惯用手法。

**真值与假值**是逻辑的基石：在布尔上下文里，`false`、`0`、`""`（空串）、`null`、`undefined`、`NaN` 是**假值（falsy）**，其余都是**真值（truthy）**——包括空数组 `[]`、空对象 `{}`。这是初学者最容易踩的：`if ([])` 恒为真。<span class="marginnote">假值清单（6 个）背下来：`false`、`0`、`-0`、`""`、`null`、`undefined`、`NaN`。注意 `"0"`（字符串零）和 `" "`（空格串）都是真值——字符串非空即真。</span>

## 5 公式解析：== 与 === 的隐藏转换

双等与三等的差别，是 JS 里最值得用公式拆解的规则。**三等 `===` 不做任何转换**，类型不同直接 false；**双等 `==` 会做隐式类型转换（coercion）**后再比。它的转换规则可以概括为一张决策表：

$$
a == b \;\Rightarrow\; \begin{cases} a = \text{Number}(a),\ b = \text{Number}(b) & \text{if } a \text{ 或 } b \text{ 是 number} \\ a = \text{String}(a),\ b = \text{String}(b) & \text{if } \text{都是 string} \\ a = \text{Boolean}(a) \rightarrow \text{Number} & \text{if } \text{涉及 boolean} \\ false & \text{否则（null 与 undefined 除外）} \end{cases}
$$

逐步拆解三条最常见的结果：

- **`1 == "1"` → `true`**：数字与字符串比，字符串被 `Number()` 转成 1，`1 === 1` 成立。
- **`0 == false` → `true`**：涉及布尔，`false` 先转 `0`，`0 == 0` 成立。
- **`null == undefined` → `true`，但 `null == 0` → `false`**：规范把 `null`/`undefined` 单独豁免，它们只彼此相等。

**直觉是什么？** `==` 的转换规则是历史上为「方便」设计的，但副作用是产生了 `" " == 0 === true`、`[] == false === true` 这类反直觉结果。**工程共识：永远用 `===`，不用 `==`**——除非你明确想用 `x == null` 同时判断「x 是 null 或 undefined」这一种例外。<span class="marginnote">`x == null` 是 `==` 唯一被广泛推荐的用法：它等价于 `x === null || x === undefined`。TypeScript 的宽松空检查也是这么写的。除此之外，一律 `===`。</span>

## 6 小结

- 变量声明三关键字：`var`（函数作用域，废弃）、`let`（块作用域，可重赋值）、`const`（块作用域，不可重绑定）；**默认 `const`**。
- 七种原始类型：`number`、`string`、`boolean`、`undefined`、`null`、`symbol`、`bigint`；原始类型按值拷贝，对象按引用。
- `undefined` 是「还没」，`null` 是「我设为空」；`typeof null === "object"` 是历史 bug。
- `number` 是 IEEE 754 双精度：`0.1 + 0.2` 有精度坑，`NaN !== NaN` 只能用 `Number.isNaN` 判断。
- 逻辑运算返回操作数本身，`||` 取第一个真值、`&&` 取第一个假值；六/七个假值要背熟。
- **相等一律用 `===`**，`==` 的隐式转换（`"1"==1`、`0==false`）是无数 bug 的源头。

在下一节，我们把「表达式」编排成「语句」——**语句、表达式与流程控制**。数据有了，逻辑就要有骨架：if、for、while、switch，让代码按条件与循环运行。
