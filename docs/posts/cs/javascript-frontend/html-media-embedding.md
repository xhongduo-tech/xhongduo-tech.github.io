## 为什么从媒体与嵌入开始

1993 年，`<img>` 标签让网页第一次「看得见图」——Mosaic 浏览器正是凭此引爆了万维网的大众化。三十多年过去，网页早已不只是文字与静态图：它承载**视频、音频、可交互的地图、第三方小工具**。这一节处理的就是「网页如何拥抱多媒体与外部内容」。

它也是**性能与可用性的分水岭**：媒体是页面体积的大头，一张未压缩的照片可以比整份 HTML 大几十倍。怎么在「要媒体」与「不拖垮页面」之间取舍，是第5篇《Web 性能优化基础》反复出现的主题——本节先给出媒体元素的语言，性能篇给出它们的策略。

## 1 图像的现代进阶：picture 与 srcset

第2篇讲过 `<img>` 的基础：`src`、`alt`、`width`/`height`。这里补上「同一张图，按设备给不同版本」的现代机制。

**`srcset` 与 `sizes`**：让浏览器按设备屏幕宽度挑图。`srcset` 列出「图片地址 描述符」对，`sizes` 告诉浏览器这张图在页面上实际占多宽：

```html
<img
  src="hero-800.jpg"
  srcset="hero-400.jpg 400w, hero-800.jpg 800w, hero-1600.jpg 1600w"
  sizes="(min-width: 900px) 50vw, 100vw"
  alt="城市夜景">
```

`400w` 是「该图适合 400 像素宽的视口」，浏览器结合 `sizes` 的「图占 50vw」与自身屏幕密度，选一张最合适的——**把决定权交给浏览器，而不是你写死**。<span class="marginnote">`srcset` 解决的是「分辨率自适应」：高密度屏（Retina）该拿到更清晰的图。它与 `sizes` 配合，是响应式图像的官方方案，比 JS 判断屏幕宽度再换图更可靠——不用等脚本、不阻塞渲染、不挑浏览器。</span>

**`<picture>` 元素**是更粗的开关——按条件整体换图，常用于「WebP 支持则用 WebP，否则退回 JPEG」：

```html
<picture>
  <source srcset="hero.webp" type="image/webp">
  <source srcset="hero.jpg" type="image/jpeg">
  <img src="hero.jpg" alt="风景">
</picture>
```

浏览器自上而下找第一个支持的格式；都不支持时兜底到最内层 `<img>`——注意 `<img>` 必须存在，它还承担 `alt` 与可访问性的全部职责。`type` 的现代选择：WebP/AVIF 体积小、支持已成熟，JPEG/PNG 做兜底。

## 2 视频与音频：video、audio 与控件

`<video>` 与 `<audio>` 把媒体播放器原生化——不用再靠 Flash 插件（它 2020 年底已被 Adobe 正式停更，是 Web 史上最著名的淘汰事件）。

```html
<video controls width="640" poster="cover.jpg">
  <source src="movie.mp4" type="video/mp4">
  <source src="movie.webm" type="video/webm">
  <p>你的浏览器不支持视频，请升级。</p>
</video>
```

要点拆解：

- **`controls`**：显示播放控件（播放/暂停/进度条）。不加它，视频就是一片「静默的黑」，什么都不能操作——所以要么给 `controls`，要么用 JavaScript 自建控件。
- **多 `<source>` 格式兜底**：浏览器按顺序试，第一个能播的生效；容器（`<video>`）里的文本只有全部失败才显示——这是「渐进增强」的经典形态。
- **`poster`**：播放前的封面图。
- **`autoplay`、`loop`、`muted`**：自动播放、循环、静音。注意：主流浏览器**禁止有声自动播放**（`autoplay` 但没 `muted` 会被拦），这是防骚扰的行业底线。

**`<audio>`** 与 `<video>` 几乎同构，只是没有画面：`controls`、多 `<source>`、`loop` 一应俱全，常见于播客、背景音、提示音。

**辨析｜易错点：** 媒体不是「放上去就行」。视频与音频是**体积与带宽的黑洞**：一段 5 分钟 1080p 视频动辄几百 MB，直接塞进页面会拖垮加载。正规做法是**预渲染**（服务端转码、压缩、切片），页面只引用 URL——`<video>` 标签只是「播放器壳」，生产环境几乎不会拿它直接播原始文件。这是性能篇与后端协作的接缝处。

## 3 嵌入：iframe 与第三方内容

**`<iframe>`（内联框架）**在当前页面里嵌另一个文档——地图、视频播放器、评论区、第三方小工具，全走它。

```html
<iframe
  src="https://example.com/widget"
  width="100%" height="400"
  title="示例小部件" loading="lazy"></iframe>
```

现代 `<iframe>` 的要点：

- **`title` 必须有**：给读屏用户一个「这是什么内嵌内容」的交代，否则他们只会听到一团空泛的「内嵌框架」。
- **`loading="lazy"`**：滚动到附近才加载，节约流量。
- **`sandbox`**：给内嵌内容戴「安全脚镣」，`sandbox="allow-scripts"` 允许脚本但禁表单提交、弹窗等——嵌入不信任的第三方内容时是安全底线。

**`<embed>` 与 `<object>`** 是更老的嵌入元素（用于插件、PDF、SVG），如今大部分场景已被 `<video>`、`<iframe>`、`<picture>` 取代，理解其存在即可，不要作为首选。<span class="marginnote">嵌入第三方内容的安全警钟：`<iframe>` 引入的是<strong>另一个文档</strong>，它自己的脚本在它的上下文里跑。默认情况下，被嵌页面可以通过 `window.parent` 试探父页面——这就是第5篇《前端安全基础》里 clickjacking、XSS 的一部分战场。`sandbox` + 尽量选可信来源，是两条基本纪律。</span>

## 4 核心对比表：图像与媒体的决策路径

「我要放一个媒体，该用哪个元素？」答案取决于它的**形态与来源**：

| 内容形态 | 首选元素 | 关键属性 | 一句话理由 |
| --- | --- | --- | --- |
| 照片/图标（静态图） | `<img>` | `src` + `alt` | 最简单可靠 |
| 同图多分辨率 | `<img>` + `srcset`/`sizes` | `400w` 描述符 | 让浏览器挑 |
| 同图多格式 | `<picture>` | `<source type>` | 格式协商 |
| 视频文件 | `<video>` | `controls` + 多 `<source>` | 原生播放器 |
| 音频文件 | `<audio>` | `controls` | 原生播放器 |
| 外部页面/地图/小工具 | `<iframe>` | `title` + `sandbox` | 嵌另一个文档 |
| 图 + 题注 | `<figure>` + `<figcaption>` | — | 钉死图文关联 |

**辨析｜易错点：** 一句话决策——**文件形态自己掌控、要响应式，用 `<img>`/`<picture>`；有播放语义（动、有声音），用 `<video>`/`<audio>`；内容在别人服务器上、要靠别人渲染，用 `<iframe>`**。三个家族边界清晰，别把视频塞进 `<img>`，也别把地图贴成截图。

## 5 媒体的可访问性与性能

媒体元素把「图、声、动」带给视觉/听觉受损用户时，必须留好后门：

**图片**：`alt` 是语义替换——装饰图写 `alt=""`、信息图写具体描述、数据图（图表）尽量把数据写进正文或 `longdesc`。

**视频**：提供**字幕**——`<track kind="subtitles" src="subs.vtt">` 挂 WebVTT 字幕文件，不仅服务听障用户，也服务「地铁里不能开声音」的普通用户。自动生成的文本轨还是搜索引擎理解视频内容的唯一通道。

**音频**：播客类提供文字稿（transcript）；纯装饰性音效允许隐藏，但别用自动播放音效骚扰用户。

**性能底线**：一切媒体都要问「这真的需要原分辨率吗」。图片选对格式与尺寸、视频走服务端转码切片、第三方嵌入用 `loading="lazy"`——**媒体是页面体积的 80%**，对媒体吝啬，就是对用户流量和耐心负责。这些策略会在《Web 性能优化基础》集中展开。

## 6 小结

- 响应式图像双件套：**`srcset`/`sizes` 按分辨率挑图**、**`<picture>` 按格式协商**；`<img>` 的 `alt` 始终不可省。
- 视频/音频用原生 `<video>`/`<audio>`：`controls` 必给、多 `<source>` 兜底、`muted` 才能 `autoplay`。
- `<iframe>` 嵌外部内容：`title` 必须、`sandbox` 兜安全、`loading="lazy"` 省流量。
- 决策一句话：自己控制的文件用 `<img>`/`<video>`，别人服务器上的内容用 `<iframe>`。
- 可访问性：图片 `alt`、视频 `<track>` 字幕、音频文字稿；性能上「媒体体积 = 页面体积的 80%」。

在下一节，我们给结构装上「意义」：**语义化与可访问性 ARIA**——从「用什么标签」上升到「这些标签对机器与人分别意味着什么」。
