## 为什么从存储与外设开始

处理器负责「算」，但算的原料和结果都住在**存储**里，与外界打交道则靠**外设**。一片发动机 ECU 的程序可能只有几百 KB，却要在一个 20 年寿命内稳定工作——嵌入式的存储设计因此充满了「够用就好」的取舍。上一篇我们讲了流水线与指令执行，这一篇回答三个问题：**数据存在哪、怎么读最快、怎么和外部世界对话**。它同时为后面的实时调度（中断与任务切换）、功耗设计（存储的漏电流占比）埋下伏笔。放到课程谱系里，这是第三级《计算机组成》的「存储层次」与「I/O」两章在嵌入式场景下的具体化。

## 1 存储层次：从寄存器到 Flash

处理器能访问的存储，按「越快越贵、越近越小」排成一条**存储层次（memory hierarchy）**：

**寄存器堆（最快，最小）→ 缓存 / 片内 SRAM → 主存（DRAM）→ 非易失 Flash（最慢，断电不丢）**

这条层次能成立，靠的是**局部性原理（locality）**：程序在时间上倾向于反复访问刚用过的数据（时间局部性），在空间上倾向于访问相邻的数据（空间局部性）。于是只需把最常用的少量数据放在最快的地方，就能以「接近快的速度」服务「接近大的容量」。

嵌入式场景下还有两个特别的分类维度：

- **易失 vs 非易失**：SRAM、DRAM 一断电就丢，属于易失；Flash、EEPROM、NOR 断电不丢，属于非易失。程序与常量必须放在非易失存储里，运行时数据放在易失存储里。
- **统一编址 vs 哈佛结构**：程序存储与数据存储共用一片地址空间叫冯·诺依曼 / 统一编址；分开编址叫哈佛结构。<span class="marginnote">手机里「手机内存」与「手机存储」两个词，正是「易失的 DRAM」与「非易失的 Flash」的通俗叫法。工程上「RAM 不丢数据」是一句常见的口语误解——RAM 恰恰是最容易丢的。</span>

## 2 SRAM 与 DRAM：一个快而贵，一个慢而省

**SRAM（静态随机存储器）**：每个存储单元约 6 个晶体管构成锁存结构，上电后状态**保持稳定，无需刷新**，速度快，但面积大、价格贵。用于缓存、片内 RAM 和寄存器堆。

**DRAM（动态随机存储器）**：每个单元是「1 个晶体管 + 1 个电容」，靠电容上的电荷表示 0/1，电荷会漏，因此必须**周期性刷新（refresh）**——通常每几十毫秒把所有行重写一遍。容量大、便宜，但慢，且刷新本身要占用总线时间。

| 特性 | SRAM | DRAM |
| --- | --- | --- |
| 单元结构 | ~6 管 | 1 管 + 1 电容 |
| 是否刷新 | 否 | 是（几十毫秒一次） |
| 速度 | 快 | 慢 |
| 成本 / 容量 | 贵 / 小 | 便宜 / 大 |
| 典型用途 | 缓存、片内 RAM | 主存 |

**易错辨析：** 名字里的「静态 / 动态」不是指「要不要供电」，而是指「会不会自发的状态变化」。SRAM 的「静态」指无刷新也稳定；DRAM 的「动态」指电荷在不断泄漏、必须持续救火。

## 3 Flash：断电不丢的存储器

**Flash 存储器**是现代嵌入式系统的「硬盘」，断电后数据长存。按组织方式分两类：

**NOR Flash**：可按字节随机读，速度较快，可以**原地执行（XIP, execute-in-place）**——CPU 直接从 Flash 取指令运行，无需先拷贝到 RAM。常用于存放启动代码。
- **NAND Flash**：按「页」读写、按「块」擦除，密度高、成本低，适合大容量存放文件系统与固件。不能随机读字节。

**辨析｜易错点：** Flash 有一个反直觉的物理约束——**写之前必须先擦除，且擦除的最小单位是块（block），不是字节**。所以「往 Flash 里原地改一个字节」在硬件上是不成立的，必须「读整块→改→擦整块→写回」。这个约束直接决定了文件系统（如 JFFS2、UBIFS）为什么做得那么复杂。

此外 Flash 有**擦写寿命**（典型 $10^4 \sim 10^5$ 次），于是诞生了**磨损均衡（wear leveling）**：把写操作尽量均匀地摊到所有块上，避免个别块先死。

## 4 外设与 I/O：处理器如何与外界对话

处理器与外界的数据交换靠**外设（peripheral）**完成。嵌入式系统里最常见的几位常客：

- **GPIO**：通用的数字输入输出脚，最简单也最万能。
- **UART / SPI / I2C**：串行通信接口，详见本专题《嵌入式通信总线》。
- **定时器（timer）**：按计数器产生时间基准与定时中断。<span class="marginnote">定时器是嵌入式世界「隐形的主角」：一切「过一段时间再干」的实时行为都靠它提供时间基准，几乎所有 RTOS 的 tick、一切 PWM 波形，都源于定时器。</span>
**看门狗（watchdog）**：一个「定时炸弹」——软件必须在期限内喂它，否则系统复位。它专门对付「程序跑飞」的失控现场。
- **PWM**：脉冲宽度调制，用于调亮度、调速、产生模拟量。
- **ADC / DAC**：模拟与数字的转换桥。

I/O 有三种工作模式，一个比一个「省 CPU」：

1. **轮询（polling）**：CPU 反复查询设备状态，简单但浪费。
2. **中断（interrupt）**：设备有事件时主动通知 CPU，CPU 平时去干别的。
3. **DMA（直接存储器访问）**：专用控制器直接搬运数据到内存，搬运完再中断 CPU。<span class="marginnote">DMA 是「外包搬运工」：批量数据（比如 ADC 采样的几千个点、以太网的一个帧）让 DMA 搬，CPU 全程零拷贝开销，只在「搬完了」那一声才被叫醒。</span>

中断的硬件骨架是**中断向量表**：每种中断对应一个入口地址，中断到来时 CPU 查表跳转。现代 MCU 还有统一的中断控制器（Cortex-M 上是 NVIC）负责优先级仲裁与嵌套。

## 5 公式解析：平均访存时间

缓存的终极问题是「没命中怎么办」。用一个公式把代价量化——**平均访存时间（AMAT）**：

$$
\text{AMAT} = t_{\text{hit}} + \text{miss\_rate} \times t_{\text{miss}}
$$

- **$t_{\text{hit}}$**：命中时访问缓存所需时间，通常 1–3 个时钟周期。
- **$\text{miss\_rate}$**：未命中率，即「每次访问有多大概率没在缓存里」。
- **$t_{\text{miss}}$**：未命中的惩罚——要把数据从下一层（主存甚至 Flash）取上来，动辄几十到上百个周期。

举个具体例子：命中 1 周期、未命中率 2%、未命中惩罚 50 周期，则：

$$
\text{AMAT} = 1 + 0.02 \times 50 = 2 \ \text{周期}
$$

把式子变形能看出关键——**当惩罚很大时，命中率差几个百分点，平均访存时间就翻倍**。缓存优化（容量、块大小、关联度、预取）的本质都是**压低 miss rate**。而局部性差的程序（随机跳转、大矩阵遍历）即使缓存很大，命中率也可能难看——这就是「缓存失效是难事」的出处。

## 6 存储器映射与启动：谁住在哪个地址

嵌入式系统复位后的第一条指令从哪来？答案是**存储器映射（memory map）**——芯片设计者把各类存储与外设安排进固定的地址区间，CPU 复位后从映射表指定的地址取第一条指令：

| 地址区间（典型） | 内容 | 访问方式 |
| --- | --- | --- |
| 低位地址（0x0000 0000 起） | Flash / Boot ROM | 启动时原地执行（XIP） |
| 片内 SRAM | 运行时数据、栈 | CPU 直接访问 |
| 外设寄存器区 | GPIO、UART、TIM 等控制字 | 统一编址，用指针读写 |
| 外部存储器控制器 | 大容量 SDRAM / Flash | 经内存控制器间接访问 |

**Cortex-M 的启动另有一套「复位向量」约定**：向量表的第一个字是栈顶指针 MSP，第二个字是复位后第一条指令的地址——硬件复位后自动从这两个地址装载，然后才执行第一条代码。<span class="marginnote">「统一编址」意味着外设寄存器与内存共用一套地址空间，C 里直接 `*(volatile uint32_t *)0x40000000 = x;` 就能操作外设——这也是嵌入式 C 到处是 `volatile` 指针的原因：不让编译器把这行「看似没用」的写操作优化掉。volatile 的语义会在《嵌入式程序设计》一篇再展开。</span>

看懂 memory map 是读一切 MCU 数据手册的钥匙：手册里的内存映射图决定了程序能放哪、栈放哪、外设寄存器在哪、以及上电后第一条指令从哪取。它把上一篇的存储层次「翻译」成了具体的地址，也让「XIP 启动」「位带操作」「寄存器映射」这些嵌入式黑话有了坐标。

## 7 小结

- 存储层次靠**局部性原理**运转：寄存器→SRAM→DRAM→Flash，越快越贵越近。
- **SRAM 快贵不刷新，DRAM 慢廉要刷新，Flash 断电不丢但必须「先擦后写」且寿命有限**。
- I/O 三种模式：**轮询、中断、DMA**，按 CPU 占用率从高到低排列。
- **AMAT = 命中时间 + 未命中率 × 未命中惩罚**，惩罚越大越要在意命中率。

在下一节，我们离开「硬件怎么连」的世界，进入「软件怎么跑」的世界：**实时操作系统与调度**——让多个任务在同一个 CPU 上准时地交替运行。
