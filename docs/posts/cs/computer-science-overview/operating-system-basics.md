## 为什么从操作系统开始

上一节的裸机有 CPU、内存、磁盘，却几乎不可用：程序要自己记住每个硬件的细节、自己协调资源，一次只能跑一个，任何一个程序出错都可能搞垮整台机器。**操作系统（operating system，OS）**就是夹在硬件与应用之间的一层软件，它的全部工作可以概括成两件事：**管理资源**（谁用 CPU、谁占内存、谁读写磁盘）与**提供抽象**（让程序看到一个干净、假想的机器）。

几乎所有后续知识都站在它肩上：进程与并发是《并发编程》的起点，虚拟内存是《计算机组成原理》存储层次的延伸，文件系统是《数据库》存储引擎的前身。<span class="marginnote">操作系统的思想也是大模型时代的公共常识：云上「一台 GPU 服务器」往往不是一台物理机，而是一个被操作系统虚拟化出来的资源视图——「抽象出干净假象」这个思路一以贯之。</span>本节只做导论，深入体系（调度算法、死锁、内存管理细节）在第三级《操作系统》专题展开。读完本节，你应该能回答三件事：**进程是什么、内存如何被保护、文件从哪来**——这三件事构成了「程序在一个现代系统里到底怎么活」的完整图景。

## 1 操作系统的角色：管家与翻译

操作系统同时扮演两个角色。

**作为资源管理者**：CPU、内存、磁盘、各种外设都是稀缺资源，OS 按策略把它们分配给一个个程序，并保证互不侵犯。它像一个管家，统筹几桌客人（程序）怎么分灶（CPU）与住房（内存）。

**作为抽象提供者**：OS 把粗糙的硬件包装成好用的接口——不让你直接操作磁盘扇区，而是给你「文件」；不让你直接切换 CPU 状态，而是给你「进程」。这套接口叫**系统调用（system call）**，例如创建进程、读写文件、分配内存。<span class="marginnote">系统调用是用户程序进入内核的唯一正门。我们平时写代码调用 `open()`、`read()`，最终都落到一次系统调用，而这需要从用户态切到内核态——一次跨越特权边界的「出国」。细节见第三级《操作系统》与《汇编语言》。</span>

**辨析｜易错点：** 操作系统不是「你在屏幕上看到的桌面」。桌面环境（GUI）只是运行在 OS 之上的一个或多个应用；OS 本体是内核，负责最底层的中断、调度、内存管理。杀毒软件、浏览器、终端都「跑在 OS 上」，但都不是 OS。

**用户态与内核态**：CPU 有特权级别，内核态（kernel mode）能执行全部指令、直接访问硬件，用户态（user mode）只能做受限操作。程序平时在用户态跑，只有发起系统调用时才短暂进入内核态完成服务再返回。这个隔离机制是「一个应用崩溃不至于弄死整个系统」的保障。

**一段简史**：操作系统的形态是跟着硬件与需求演化的。早期是**批处理（batch）**——一次只能跑一个程序，排队执行，慢且交互差；60 年代出现**分时系统（time-sharing）**，用时间片轮转让多人同时用一台机器，交互成为可能；70 年代 UNIX 把多用户、多进程、文件系统这些设计定型并延续至今；再到个人电脑时代，Windows、macOS、Linux 各自繁荣。理解这条线，你就能明白「为什么操作系统会有这些概念」——几乎每个机制都是被某个现实痛点逼出来的。

## 2 进程与调度：让多个程序「同时」跑

**进程（process）**：一个正在执行的程序的实例——它不仅包括代码，还包括它的数据、寄存器现场与打开的文件等「运行上下文」。同一份代码可以被多个进程执行，各自互不干扰。

**辨析｜易错点：** 程序（program）是磁盘上的静态文件；进程是内存里动态执行的活动。程序是菜谱，进程是照着菜谱正在做的菜——同一份菜谱可以同时开好几锅。<span class="marginnote">「程序 vs 进程」是操作系统里第一对要分清的概念。还有一个相关概念是「线程」（进程内的执行流），本节先不展开，第三级《并发与并行编程》会专门处理。</span>

**调度（scheduling）**：CPU 通常只有一个（或少数几个），却要服务很多进程。OS 的**调度器**决定「下一个把 CPU 交给谁」。最朴素也最重要的策略是**时间片轮转（round-robin）**：把 CPU 时间切成小片，每个进程轮流用一片，用完了就换下一个。

**并发与并行**：时间片轮转让多个进程「看起来同时跑」，这叫**并发（concurrency）**——它们在宏观上重叠、微观上轮流；只有多个 CPU 核心真正同时执行，才叫**并行（parallelism）**。手机一边放歌一边回消息，多半是并发——单个核在飞快切换。

调度设计要平衡两个指标：**吞吐量**（单位时间完成多少任务）与**响应时间**（一个任务从提交到开始执行等多久）。时间片越长，吞吐越高但响应越迟钝；越短，交互越流畅但切换开销越大。操作系统课程里大量调度算法（先来先服务、短作业优先、多级反馈队列）都是在这两个目标之间找平衡。

**上下文切换（context switch）**：进程切换时，OS 要把当前进程的寄存器、PC 等现场保存下来，再恢复下一个进程的现场。这个「换人」操作有开销，切换太频繁反而浪费 CPU——所以时间片长短是个需要权衡的设计参数。

**进程三态**：一个进程的一生，多数时间在三个状态间辗转：
**就绪（ready）**：万事俱备，只等 CPU；
**运行（running）**：正占用 CPU 执行；
**阻塞（blocked / waiting）**：在等某个事件（如磁盘读完数据、用户按下一个键），事件未到就先让出 CPU。

调度器从就绪队列里挑一个去运行；运行中的进程若发起需要等待的系统调用，就被挂到阻塞状态，事件到达后再转回就绪。这三态的转换模型是理解一切并发程序的基础，也是后续《操作系统》课程一开篇就画的图。<span class="marginnote">「阻塞 ≠ 空闲」：阻塞的进程虽然不用 CPU，但还占着内存和打开的文件等资源，操作系统要照样管理它们。这也解释了为什么「进程数很多」不等于「CPU 很忙」。</span>

## 3 存储管理：虚拟内存与分页

内存是另一个被争抢的资源。早期系统里程序直接使用物理地址，一个 bug 就能写坏别人的数据。现代 OS 用**虚拟内存（virtual memory）**解决这个问题：**每个进程看到的是一个从 0 开始的、私有的地址空间，仿佛独占了整台机器**；OS 负责把这些虚拟地址映射到真正的物理内存。

映射的最小单位是**页（page）**：虚拟内存与物理内存都被切成固定大小的页（常见 4 KB），进程的每一页通过**页表（page table）**查到对应的物理页帧。进程访问一个地址时，硬件查页表完成换算；若该页不在物理内存而在磁盘上，就发生**缺页（page fault）**，OS 从磁盘读入并可能换出别的页。<span class="marginnote">「内存不够用了就去磁盘借」——这是虚拟内存最浪漫也最朴素的想法。磁盘上的这份后备空间叫交换区（swap）；而「换出哪一页」由页面置换算法决定，最著名的 LRU（最近最少使用）背后就是存储层次里的局部性原理，上一节刚讲过。</span>

**内存保护**：页表不仅做映射，还登记每页的权限（可读、可写、可执行）。进程 A 访问进程 B 的地址空间，会在页表层被拦截——虚拟内存因此同时实现了「隔离」与「保护」。<span class="marginnote">大模型训练里常说的「显存不够、把参数换出到 CPU 内存」，本质就是这种换页思想的现代变体——只不过由框架（而非 OS）在 GPU 的显存与主存之间做分页式的调度。</span>

地址转换靠硬件加速：CPU 里的**内存管理单元（MMU）**在每次访存时自动查页表、算物理地址，几乎不增加软件负担；查得慢则再用 TLB 这个小缓存顶在前面。于是每次「访问一个虚拟地址」，在硬件里可能已经悄悄走了「TLB → 页表 → 物理内存」三层。<span class="marginnote">「虚拟地址 → 物理地址」的翻译每秒发生几十亿次，绝不能靠软件慢慢查，必须用硬件流水线化——这也是为什么「CPU 有多复杂、就有多少隐藏的硬件机制」这句话成立。</span>

## 4 公式解析：虚拟地址如何拆成「页号 + 偏移」

分页的关键换算，是把一个虚拟地址拆成两部分：高位是**页号**，低位是**页内偏移**。

$$
\text{虚拟地址} = \underbrace{\text{页号 (page number)}}_{\text{高位}} \ \underbrace{\text{页内偏移 (offset)}}_{\text{低位}}
$$

以 4 KB 页、32 位虚拟地址为例拆解：
- **第一步，算偏移位数**：页大小 $4\ \text{KB} = 2^{12}$ 字节，所以低 12 位是页内偏移（范围 0~4095）。
- **第二步，算页号位数**：总地址 32 位减去偏移 12 位，高 20 位是页号，可表示 $2^{20}=1048576$ 个页。
- **第三步，换算示例**：虚拟地址 `0x1000`（二进制低 12 位为 0）意味着页号 `0x1`、偏移 `0x0`；而 `0x10FF` 是页号 `0x1`、偏移 `0x0FF`——同页内相邻地址只差偏移，页号不变。

**辨析｜易错点：** 页的大小必须设计得当：页太小，页表条目过多、换页频繁；页太大，内部碎片（一个页用不满）浪费增多。4 KB 是长期演化的经验值，但超大内存场景也会用 2 MB 甚至 1 GB 的「大页」来降低页表开销——这是数据库与 HPC 调优里常出现的词。

页表本身也要占内存，这个账值得算一笔：32 位地址空间、4 KB 页，共 $2^{32}/2^{12} = 2^{20}$ 个页；若每个页表项记 4 字节，一个进程的页表就要 $4\ \text{MB}$
