## 为什么从呈现数据开始

脚本的「输出」不是铁板一块——Linux 把它们分成了两条独立的管道：**标准输出（stdout）** 装正常结果，**标准错误（stderr）** 装报错信息。这个看似多余的区分，实际是运维的救命设计：`2>/dev/null` 把报错扔掉、`>> log 2>&1` 把全部输出追进日志、`grep 正常输出` 时不会被错误刷屏。而这一切的底层是**文件描述符（file descriptor）**——三个编号 `0/1/2` 构成的输入输出抽象。本章把 echo 与 printf 的输出手段、三种重定向、以及文件描述符的底层模型一次讲透。

## 1 echo 与 printf：两条输出路径

**`echo`** 是脚本里最常用的输出命令，简单但选项受限：

```bash
echo "Hello"               # 输出并换行
echo -n "不换行"           # -n 不换行
echo -e "a\tb"             # -e 解释转义符 \t \n
echo "路径是: $HOME"       # 变量展开
```

**`printf`** 提供格式化输出，写法更接近 C 语言，适合对齐表格：

```bash
printf "%-10s %6s\n" "名称" "大小"
printf "%-10s %6s\n" "app.log" 123456
```

`%s` 字符串、`%d` 整数、`%f` 浮点；`-10` 左对齐占 10 位、`6` 右对齐占 6 位。<span class="marginnote">`printf` 的格式串<strong>不自动换行</strong>——必须显式写 `\n`。而 `echo` 是否解释转义取决于版本（bash 内建默认解释 `\n`）。跨 shell 可移植性要求高时用 `printf`，它行为一致。</span>

**易错点**：`echo "$var"` 与 `echo $var` 不同——加引号保留变量里的空格与换行，不加引号会被**分词与通配符展开**。输出含 `*`、空格、换行的内容时，永远加引号。

## 2 公式解析：文件描述符与重定向

**文件描述符（file descriptor，FD）** 是内核给每个打开的「流」分配的编号。每个进程启动时自动拥有三个：

$$
\underbrace{0}_{\text{stdin 标准输入}} \qquad \underbrace{1}_{\text{stdout 标准输出}} \qquad \underbrace{2}_{\text{stderr 标准错误}}
$$

重定向符号就是在**改这些编号指向的落点**：

| 符号 | 含义 |
| --- | --- |
| `>` | 标准输出写入文件（覆盖） |
| `>>` | 标准输出追加到文件 |
| `\lt ` | 用文件作为标准输入 |
| `2>` | 标准错误写入文件 |
| `2>&1` | 标准错误**并到**标准输出 |
| `&>` | 标准输出与错误都写入文件 |

拆解最经典的一条 `2>&1`：

- **第一步**：`>> file` 把 FD 1（stdout）追加到 file。
- **第二步**：`2>&1` 把 FD 2（stderr）重定向到 FD 1 **当前指向的位置**——也就是 file。
- **第三步**：于是正常输出与报错都进同一个文件，顺序清晰。
- **第四步**：`2>&1` 必须写在重定向之后：`cmd >> log 2>&1` 正确，`cmd 2>&1 >> log` 会把错误送到终端、只有正常输出进文件——顺序错了结果全错。

**易错点**：`2>&1` 与 `2>1` 完全不同——`2>1` 是「把错误写入名为 1 的文件」！要「合并到标准输出」必须写 `2>&1`。<span class="marginnote">`&>` 是 `> file 2>&1` 的简写，但 `>> file 2>&1` 没有对应的 `&>>` 简写（旧 bash 不支持）。`/dev/null` 是「黑洞」设备：`2>/dev/null` 把报错丢弃、`1>/dev/null` 丢弃正常输出，是「只想看其中一路」的标准手法。</span>

## 3 在脚本里创建自己的 FD

除了 0/1/2，脚本可以**打开更多的文件描述符**，让数据流更清晰。bash 语法：

```bash
exec 3> output.log        # 打开 FD 3 指向文件
echo "这是一条正式输出" >&3   # 写到 FD 3
exec 3>&-                 # 关闭 FD 3
```

用 FD 3 打开日志、FD 4 打开结果文件，主输出仍走 1——脚本里「不同类数据去不同地方」就不必反复 `>>` 指定路径。<span class="marginnote">`exec 3>file` 里 `exec` 不做别的，只是<strong>在当前 shell 里永久设置</strong>这次重定向。读完记得 `exec 3>&-` 关闭——FD 数量有限（默认 1024），脚本长时间跑还不关，可能耗尽。</span>

**易错点**：`exec 3> file` 若省略 `exec`（`3> file` 单独一行），在**交互 shell**里这行会被当命令执行、容易出错；在脚本里两种都能用，但 `exec` 语义更明确。另外打开 FD 时用 `>` 会立即清空目标文件，不想清空用 `>>`。

## 4 高级重定向：Here Document 与 tee

**Here Document（heredoc）** 把一段多行文本直接嵌进命令，作为输入传入：

```bash
cat \lt \lt  EOF > /etc/myapp.conf
server_name example.com;
listen 80;
EOF
```

`\lt \lt  EOF` 表示「从这里到下一个 EOF 都是输入」，`> file` 再把这整段输入重定向写进文件——脚本里批量生成配置文件、邮件正文、SQL 的标准姿势。<span class="marginnote">`\lt \lt -` 会忽略每行开头的 Tab（方便在缩进代码里嵌文档）；heredoc 内默认做变量展开，要禁用写在定界符加引号：`\lt \lt  'EOF'`。定界符用 `EOF` 只是惯例，任何字符串都行。</span>

**`tee`** 把数据「一分为二」：一份继续输出到标准输出，一份写入文件：

```bash
date | tee log.txt          # 屏幕上看到，同时写进文件
date | tee -a log.txt       # -a 追加
```

管道里夹一个 `tee`，既能在日志文件里留底、又能让数据继续流给下游命令。

**易错点**：heredoc 的定界符 **EOF 必须顶格写**——行首有任何空格或 Tab（除非用 `\lt \lt -`）都不会被识别为结束符，命令会一直等输入，最后报错。这是 heredoc 最常见的坑。<span class="marginnote">`tee` 默认<strong>覆盖</strong>文件（`-a` 追加）。想要「屏幕 + 文件」双写，`cmd 2>&1 | tee -a log` 是既看过程又留日志的完整姿势——错误也一并 tee 进去。</span>

## 5 小结

- **FD 0/1/2 = 输入/输出/错误**：内核为每个进程预装三个流，重定向就是改它们的落点。
- **`>` 覆盖、`>>` 追加、`2>` 错误**：`2>&1` 合并错误到输出，顺序敏感、`2>1` 是写文件不是合并。
- **`&>` 简写合并**：`cmd > log 2>&1` 的标准写法记得住就够，`/dev/null` 是丢弃专用。
- **`exec` 打开自定义 FD**：`exec 3>file` 开、`exec 3>&-` 关，用完必关。
- **heredoc 与 tee**：`\lt \lt  EOF` 批量生成文件、`tee` 一分为二；EOF 必须顶格写。
