## 为什么从结构化命令开始

上一章的脚本是「一路直下」的：从头跑到尾。但真实自动化永远需要**判断**：磁盘超过 90% 就告警、文件存在才处理、服务没跑起来才重启。这一切的根基是 shell 的一个朴素机制——**每条命令结束都会返回一个退出状态码**，而 `if` 就是在问「这条命令，你是成功（0）还是失败（非 0）？」。本章围绕这个机制展开：`if-then` 做分支、`test` 与 `[[ ]]` 做条件比较、`case` 做多路匹配。它们是脚本获得「智能」的第一块拼图。

## 1 退出状态：if 的判断依据

在 shell 里，**每条命令的结局都有一个数字**：0 表示成功，非 0 表示失败。这个数字叫**退出状态（exit status）**，存在变量 `$?` 里：

```bash
grep "error" app.log
echo $?            # 0 = 找到了；1 = 没找到；2 = 出错
```

**公式解析：if 的语义**

$$
\text{if} \; \underbrace{\text{命令}}_{\text{执行并检查退出状态}} \; ; \; \text{then} \; \text{分支A} \; ; \; \text{else} \; \text{分支B} \; ; \; \text{fi}
$$

$$
\text{命令退出状态} = 0 \;\Rightarrow\; \text{执行 then 分支}; \qquad \neq 0 \;\Rightarrow\; \text{执行 else 分支}
$$

拆解：

- **第一步**：`if` 后面跟的**不是条件表达式，而是一条普通命令**。
- **第二步**：bash 执行这条命令，读取它的退出状态。
- **第三步**：状态为 0 走 `then`，非 0 走 `else`（可省略）。
- **第四步**：`fi`（if 倒过来写）结束整个结构。

这个设计让 if 天然理解「命令是否成功」：`if grep -q error log` 直接判断「日志里有没有 error」，无需任何比较运算符。<span class="marginnote">`-q` 让 grep 静默：它只返回退出状态、不输出匹配行。用 `if grep -q ...` 这种「命令本身当条件」的写法，比 `if [ $(grep ...) ]` 更干净高效。`exit N` 可以显式设置脚本自身的退出状态。</span>

**易错点**：`if [ ... ]` 里的 `[` **是一个命令**（等价于 `test`），所以它左右必须有空格：`[ $a = 1 ]` 而非 `[$a=1]`——后者会被当成命令名 `[$a=1]`，直接报 `command not found`。

## 2 test 命令：数字、字符串、文件三种比较

`if` 只会判断「命令是否成功」，而**条件**要由 `test`（或等价写法 `[ ]`）来构造。`test` 支持的比较分三类：

**数值比较**：

| 表达式 | 含义 |
| --- | --- |
| `n1 -eq n2` | 相等 |
| `n1 -ne n2` | 不等 |
| `n1 -gt n2` | 大于 |
| `n1 -ge n2` | 大于等于 |
| `n1 -lt n2` | 小于 |
| `n1 -le n2` | 小于等于 |

**字符串比较**：`=` 相等、`!=` 不等、`-z` 空串、`-n` 非空。

**文件比较**：

| 表达式 | 含义 |
| --- | --- |
| `-e file` | 文件存在 |
| `-d file` | 是目录 |
| `-f file` | 是普通文件 |
| `-r` / `-w` / `-x` | 可读 / 可写 / 可执行 |
| `-s file` | 文件非空 |
| `nt` / `ot` | 新于 / 旧于 |

实际写法（`[ ]` 是 `test` 的别名）：

```bash
if [ "$total" -gt 90 ]; then
    echo "磁盘超过 90%，请清理"
fi

if [ -f "$log" ]; then
    echo "日志文件存在"
fi

if [ -z "$name" ]; then
    echo "name 为空"
fi
```

**易错点**：数值比较用 `-gt`/`-lt`，**不能**用 `>`/`<`——那会被当作重定向符号。字符串比较用 `=`，数值用 `-eq`，混用会得到错误结果。比较变量时**加引号** `[ "$var" = "x" ]`，否则变量为空或含空格时表达式会语法错误。

## 3 高级比较：[[ ]] 与 (( ))

bash 提供 `test` 的增强版：**双括号 `[[ ]]`**（字符串与文件）与 **`(( ))`**（数值）。它们更宽容也更强大：

```bash
if [[ $name == h* ]]; then     # 支持通配符模式匹配
    echo "name 以 h 开头"
fi

if [[ $file == *.log && -f $file ]]; then   # 逻辑与 && 
    echo "是 .log 且存在"
fi

if (( total > 90 )); then      # 数值直接写，无需 -gt
    echo "磁盘超过 90%"
fi
```

**核心对比表：`[ ]`、`[[ ]]`、`(( ))`**

| 写法 | 适用 | 特点 |
| --- | --- | --- |
| `test` / `[ ]` | POSIX 通用 | 最可移植，但符号啰嗦 |
| `[[ ]]` | bash 增强 | 支持 `==` 模式匹配、`&&`、`\|\|`、不用引号也安全 |
| `(( ))` | bash 数值 | 直接写 `>`、`<`、算术，无需 `-gt` |

`[[ ]]` 里**变量不加引号也安全**——bash 不会做分词，`[[ $var = "" ]]` 在 var 为空时不会报错。这比 `[ ]` 省心得多，脚本明确用 bash 时优先 `[[ ]]`。<span class="marginnote">`[[ ]]` 与 `(( ))` 是 bash 专属，`sh` 不认。想写最大可移植的 POSIX 脚本就用 `[ ]`；自己机器上的运维脚本，`[[ ]]` 更舒适。`-a`（与）`-o`（或）是 `[ ]` 里的旧写法，`[[ ]]` 里用 `&&`/`||`。</span>

## 4 case：多路匹配的优雅写法

一连串 `if-elif` 判断同一个变量时，代码会迅速变长。**`case`** 是更紧凑的多路分支：

```bash
case "$1" in
    start)  echo "启动服务..." ;;
    stop)   echo "停止服务..." ;;
    restart|reload) echo "重启服务..." ;;
    *)      echo "用法: $0 {start|stop|restart}" ;;
esac
```

语法要点：`case 变量 in` 开头，每个分支用 `)` 结尾、`;;` 结束，`*` 是默认分支，`esac`（case 倒写）收尾。分支模式支持通配符与 `|` 多值。

**易错点**：`;;` 不能丢——少了它 bash 会把下一个分支也执行（穿透）。而 `*)` 默认分支一定要放在最后，它兜住所有未匹配的情况，是脚本「对未知输入的反应」的最后一层防线。<span class="marginnote">`case` 的价值在可读性：把「同一个变量的多值判断」扁平化成一列，比一串 elif 清爽得多。这也是 init 脚本处理 `start|stop|restart` 参数的标准写法。</span>

## 5 小结

- **退出状态决定 if 走向**：0 成功走 then、非 0 走 else；`$?` 可随时读取。
- **`if` 后跟命令而非表达式**：`if grep -q ...` 直接用命令成败做分支。
- **`test`/`[ ]` 三类比较**：数值用 `-eq/-gt/-lt`、字符串用 `=`、文件用 `-e/-f/-d/-r/-w/-x`。
- **`[[ ]]` 与 `(( ))` 是 bash 增强**：模式匹配、`&&`/`||`、直接写 `>`；POSIX 兼容性要求高时才退回 `[ ]`。
- **`case` 是多路分支**：`;;` 收尾、`*` 兜底，处理 `start|stop` 这类参数最优雅。
