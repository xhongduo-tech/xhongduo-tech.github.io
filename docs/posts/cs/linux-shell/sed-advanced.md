## 为什么从 sed 进阶开始

初识 sed 时我们只用了单行命令 `s`、`d`、`p`。但真实需求很快会越界：想「把空行后紧跟的行合并」、想「从某模式出现开始连续处理 N 行」、想「把配置文件里一大段块替换掉」——这些都涉及**跨行状态**。sed 的进阶武器库由此展开：**多命令与脚本文件**、**模式空间与保持空间**（两个缓冲区的协同）、**多行命令**（`N`、`D`、`P`）、以及**替换的高级选项**（`&`、`\1`、`\U`、`i` 修饰符）。学完这章，sed 从「行内小刀」升级为「块级文本手术刀」。

## 1 多命令与脚本文件

sed 支持一条命令里串多个子命令，也支持把整份逻辑写进脚本文件：

```bash
# 一行内多条命令，用分号分隔
sed 's/foo/bar/; s/FOO/BAR/g' file.txt

# -e 多次指定
sed -e 's/foo/bar/' -e '/^#/d' file.txt

# 脚本文件（大逻辑更好维护）
sed -f fix.sed file.txt
```

脚本文件里**每行一条命令**，可读性远胜一长串分号：

```
# fix.sed
s/colour/color/g
/^debug/d
s/[[:space:]]\+$//    # 去掉行尾空白
```

**易错点**：分号串命令时注意寻址范围——`1,5s/a/b/; 10,20s/c/d/` 两段各有自己的地址，写在一个 `s` 里或位置放错会改变语义。多行脚本里行尾的反斜杠表示续行，别把续行与多命令搞混。

## 2 核心对比表：模式空间与保持空间

sed 处理每行时在内存里维护**两个缓冲区**，这是理解 sed 一切进阶命令的钥匙：

| 缓冲区 | 含义 | 默认生命周期 |
| --- | --- | --- |
| **模式空间（pattern space）** | 当前正在处理的行 | 读完下一行就被覆盖 |
| **保持空间（hold space）** | 临时寄存区 | 跨行一直保留 |

操作两个空间的命令：

| 命令 | 作用 |
| --- | --- |
| `h` / `H` | 把模式空间**复制/追加**到保持空间 |
| `g` / `G` | 把保持空间**复制/追加**回模式空间 |
| `x` | 交换两个空间的内容 |
| `n` / `N` | 读下一行 / 把下一行**追加**进模式空间 |

**易错点**：`h` 与 `H`、`g` 与 `G` 的差别是**覆盖 vs 追加**——小写覆盖、大写追加。`x` 交换是最容易引起混乱的：它让「正在处理的行」与「寄存的行」对调，时序一错结果全反。建议先用 `h` + `g` 掌握「寄存—取回」模型，再碰 `x`。

## 3 公式解析：多行处理 N/D/P

单行命令一次只见一行；**多行命令**让 sed 能「看两行甚至更多」。核心是三对大写字母：

$$
\underbrace{n}_{\text{读下一行覆盖}} \quad \underbrace{N}_{\text{读下一行追加}} \qquad
\underbrace{p}_{\text{打印模式空间}} \quad \underbrace{P}_{\text{只打印第一行}} \qquad
\underbrace{d}_{\text{删除模式空间}} \quad \underbrace{D}_{\text{删除第一行并重新处理}}
$$

拆解一个「把空行之后的行与前一行合并」的例子：

```bash
sed '/^$/ { N; s/\n//; }' file.txt
```

- **第一步**：`/^$/` 寻址命中空行，进入 `{ }` 命令块。
- **第二步**：`N` 把**下一行追加**进模式空间——此时模式空间是「空行 + \n + 下一行」。
- **第三步**：`s/\n//` 把换行符删掉，两行合成一行。
- **第四步**：输出合并后的行。`D` 则用于「删掉模式空间第一行、重新处理剩余部分」——适合多行条件下的循环处理。

**易错点**：`N` 遇到**最后一行**时若无更多行可读，会**直接结束 sed 且不输出**——多行处理的边界条件最容易丢尾行。处理大文件的多行逻辑，`P`/`D` 组合能形成循环，但要仔细数清楚每个分支「谁被消费了」。<span class="marginnote">`sed -n '1p; N; P; D'` 是一个有名的「滑动窗口」技巧：每次读一行、打印第一行、删除第一行——相当于一次只推进一行地流式处理，内存占用恒定，适合超大文件。</span>

## 4 替换的高级用法

`s` 命令的替换端不是死板字符串，支持多种动态能力：

```bash
sed 's/.*/& &/' file.txt              # & 代表整个匹配内容（翻倍）
sed 's/\(foo\)/\U\1/' file.txt        # \U 把分组 1 转大写
sed -i 's/old/new/i' file.txt         # i 修饰符：忽略大小写匹配
sed -n 's/error/&/p' file.txt         # 只打印发生替换的行
```

**公式解析：替换端的特殊记号**

$$
s / \text{模式} / \underbrace{\&}_{\text{整个匹配}} \;\text{或}\; \underbrace{\backslash 1}_{\text{第 1 分组}} \;\text{或}\; \underbrace{\backslash U\backslash 1}_{\text{分组转大写}} / \;\text{修饰符}
$$

- **第一步**：`&` 在替换端代表「模式匹配到的整段文本」——`s/\w+/[&]/` 给每个词加方括号。
- **第二步**：`\1` 引用分组；`\L` 转小写、`\U` 转大写，`\U\1` 是「把分组 1 大写」。
- **第三步**：修饰符 `i`（忽略大小写）、`g`（全局）、`p`（打印发生替换的行）跟在末位。
- **第四步**：`-n` + `s///p` 组合是「只看发生替换的行」——批量修改前先这样干跑一遍确认范围。

**易错点**：`&` 在替换端是元字符，想输出**字面量 `&`** 要写 `\&`。同理 `\1` 想输出字面量需 `\\1`。替换端含反斜杠或 `&` 时最容易「结果比预期多/少」，先干跑（不带 `-i`）确认再落地。<span class="marginnote">sed 的 `i` 修饰符只对替换生效，与 `-i`（原地修改）字母相同但位置不同——一个是替换标志、一个是命令行选项，别在文档里看花眼。</span>

## 5 实战：批量改配置的稳妥流程

把本章能力组装成「批量修改配置」的规范流程：

```bash
# 1. 先备份
cp nginx.conf nginx.conf.bak

# 2. 干跑：只看会改成什么（不落地）
sed 's/listen 80/listen 8080/g; s/server_name example.com;/server_name api.example.com;/' nginx.conf | diff nginx.conf -

# 3. 确认无误后原地修改
sed -i 's/listen 80/listen 8080/g; s/server_name example.com;/server_name api.example.com;/' nginx.conf

# 4. 语法校验 + 重载
nginx -t && systemctl reload nginx
```

关键三步：**备份 → 干跑 diff → 落地 + 校验**。`sed ... | diff nginx.conf -` 用 diff 逐行对比「改前 vs 改后」，一眼看清所有差异，比盲改盲看安全得多。<span class="marginnote">`diff nginx.conf -` 的 `-` 表示「把标准输入当另一份文件」。批量改系统配置的黄金法则是「改之前先让 diff 给你看一遍」，这条习惯能挡住九成配置事故。</span>

## 6 小结

- **多命令与脚本文件**：分号串命令、`-f script.sed` 存逻辑，脚本文件更可维护。
- **双缓冲区模型**：模式空间装当前行、保持空间跨行寄存；`h`/`g` 覆盖、`H`/`G` 追加、`x` 交换。
- **多行命令 N/P/D**：`N` 追加下一行、`P` 只打印首行、`D` 删首行重处理——滑动窗口处理大文件。
- **替换端动态记号**：`&` 整个匹配、`\1` 分组、`\U` 转大写、`i` 忽略大小写、`p` 只打替换行。
- **批量改配置三步走**：备份 → `sed | diff -` 干跑 → `-i` 落地 + 语法校验。
