## 为什么从正则表达式开始

`grep "error"` 只能匹配死板的子串，可现实里的日志长这样：`2026-08-07 09:41:02 ERROR worker-7 task failed after 3 retries`。你要的是「所有 ERROR 级别、且以 `task failed` 结尾的行」——这需要一套能表达模式的**语言**，它就是**正则表达式（regular expression，regex）**。它是 grep、sed、vim、awk 以及几乎所有脚本语言的共同语法；把正则学透，等于一次性给几十个工具开了外挂。本章先立住正则的核心构件，再补上 `cut`、`tr`、`diff` 这几个「文件格式化」工具。

## 1 字符类与量词：匹配「一类字符」与「出现的次数」

正则的核心是两个概念：**匹配什么** 与 **匹配几次**。

**字符类（character class）** 用方括号表达「这一位可以是这几个字符中的任意一个」：

| 写法 | 含义 | 例 |
| --- | --- | --- |
| `[abc]` | a、b、c 中任意一个 | `gr[ae]y` 匹配 gray/grey |
| `[a-z]` | 小写字母 | `[0-9]` 匹配一位数字 |
| `[^abc]` | 除 a、b、c 外任意字符 | `[^0-9]` 匹配非数字 |
| `.` | 任意一个字符 | `a.c` 匹配 abc/a2c |
| `\d` | 一个数字（部分工具支持） | 等价 `[0-9]` |

**量词（quantifier）** 跟在字符类后，表达它出现多少次：

| 写法 | 含义 |
| --- | --- |
| `*` | 前一项出现 0 次或多次 |
| `+` | 前一项出现 1 次或多次 |
| `?` | 前一项出现 0 次或 1 次 |
| `{n}` | 恰好 n 次 |
| `{n,m}` | n 到 m 次 |

**公式解析：拆一个真实模式**

$$
\underbrace{[0-9]}_{\text{一位数字}} \;\{2\}\;\underbrace{\text{-}}_{\text{字面量}} \;\underbrace{[0-9]}_{\text{一位数字}}\;\{2\}\;\underbrace{\text{-}}_{\text{字面量}}\;\underbrace{[0-9]}_{\text{一位数字}}\;\{4\}
$$

这条模式匹配 `MM-DD-YYYY` 形式的日期（如 `08-07-2026`）。逐项拆解：

- **第一步**：`[0-9]` 匹配任意一位数字，`{2}` 要求恰好出现两次，于是前两位是 `08`。
- **第二步**：`-` 没有加方括号，匹配字面量连字符本身。
- **第三步**：重复同样的结构得到 `MM-DD`。
- **第四步**：末尾 `[0-9]{4}` 匹配四位年份。

整个模式 `[0-9]{2}-[0-9]{2}-[0-9]{4}` 就是「日期」的机器翻译。注意这与「随便两个数字中间夹连字符」的区别——它把结构写死了。

## 2 锚点与分组：定位与复用

**锚点（anchor）** 把匹配「钉」在特定位置：

| 锚点 | 含义 |
| --- | --- |
| `^` | 行首 |
| `$` | 行尾 |
| `\b` | 单词边界 |

`^Error` 匹配行首的 Error，`failed$` 匹配行尾的 failed，`\bcat\b` 匹配独立的单词 cat 而不碰 concatenate。三个锚点合起来，就实现了上一节 grep 里「整词匹配」的精确版。

**分组（group）** 用括号 `( )` 把一段模式打包，用途有二：**整体应用量词** 与 **捕获复用**。

```text
(ab)+        匹配 ab、abab、ababab……
(192\.168\.1)\.\d+    匹配 192.168.1 开头的网段
```

捕获的内容用 `\1`、`\2` 引用——sed 与 vim 替换里 `\1` 是第一个分组，后文第 4 篇的 sed 进阶会大量用到。<span class="marginnote">在 `grep` 里 `.` 若不转义会匹配任意字符，`192.168.1` 会误匹配 `192x168x1`。要匹配字面点号，写 `\.`。这个「元字符 vs 字面量」的转义之争，是所有正则新手的第一道坑。</span>

**易错点**：`^` 在方括号内是「取反」，在方括号外是「行首」——同一个符号两种语义，看它出现在哪。`[^0-9]` 是「非数字」，`^[0-9]` 是「以数字开头」。

## 3 grep 实战：正则第一次落地

有了构件，回到 grep 把正则用起来。grep 默认用**基本正则（BRE）**，`-E` 切换**扩展正则（ERE）**——主要差别是 `+`、`?`、`{`、`|`、`( )` 这些元字符在 BRE 里需要反斜杠转义才生效，ERE 里直接生效。

```bash
grep -E "^[0-9]{2}:" app.log        # 以两位数字加冒号开头的行
grep -E "error|fatal|panic" app.log # 三个级别任一
grep -E "\.(php|js)$" file          # 以 .php 或 .js 结尾
grep -E "\[(WARN|ERROR)\]" app.log  # 匹配 [WARN] 或 [ERROR]
```

**易错点**：`grep error|fatal` 不带括号时，`|` 的优先级会把命令拆成「grep error」和「fatal」两部分——`fatal` 会被当成文件名。务必用 `grep -E "error|fatal"`，把整个模式放进引号里。

## 4 文件格式化：cut、tr、diff

正则负责「挑」，格式化工具负责「改」。鸟哥这一章的配套工具里最常用的三个：

**`cut`** 按字段或字符切出文件的列——处理 `:` 分隔的 `/etc/passwd` 是经典场景：

```bash
cut -d: -f1 /etc/passwd        # 按冒号分隔，取第 1 列（用户名）
cut -d: -f1,7 /etc/passwd      # 取第 1 和第 7 列
cut -c1-10 file.txt            # 按字符位置取前 10 个字符
```

**`tr`** 做单字符的替换与删除，常常用来清洗文本：

```bash
tr 'a-z' 'A-Z' \lt  file.txt       # 全部转大写
tr -d '\r' \lt  win.txt            # 删除 Windows 行尾的 ^M
tr -s ' ' \lt  file.txt            # 把连续多个空格压成 1 个
```

**核心对比表：格式化工具速查**

| 工具 | 定位 | 最典型用法 |
| --- | --- | --- |
| `cut` | 按列切 | `cut -d: -f1 /etc/passwd` |
| `tr` | 单字符替换/删除 | `tr -d '\r'` 去 Windows 行尾 |
| `wc` | 统计 | `wc -l` 行数 |
| `diff` | 逐行对比 | `diff -u a.txt b.txt` 统一格式差异 |
| `sort` | 排序 | `sort -t: -k3 -n` 按第三列数值排 |
| `uniq` | 相邻去重 | `uniq -c` 计数 |

**`diff`** 是排障利器：`diff old.conf new.conf` 逐行对比两份配置，`-u` 给出带上下文的统一格式，是代码 review 与配置回滚时「到底改了什么」的标准答案。<span class="marginnote">`diff -u` 输出的 `+` 行是新增、`-` 行是删除。把 `diff` 与「补丁」联系起来的是 `patch` 命令：`diff -u old new > p.diff` 之后 `patch \lt  p.diff` 就能把改动应用到另一份拷贝上。</span>
