## 为什么从 BRE 与 ERE 开始

第 1 篇讲正则时我们用了 `grep -E`——当时说「扩展正则更省心」。但 `-E` 到底扩展了什么？为什么 `grep` 默认的 `+`、`?` 不生效、而 `sed` 的 `*` 又完全正常？答案在 POSIX 把正则分成的**两种方言**里：**BRE（基本正则）** 与 **ERE（扩展正则）**。这是把正则从「能套模板」推向「能设计模式」的一章：你会理解 `\+` 与 `+`、`\) \)` 与 `( )` 的转义之争，会掌握分组、反引用、区间量词这些「写一个模式解决一类问题」的高级构件，还会看清它们在不同命令里的默认方言。

## 1 BRE 与 ERE：一场反斜杠的战争

POSIX 定义了两套正则语法，差别集中在**哪些元字符需要转义才生效**：

**核心对比表：BRE 与 ERE 的元字符**

| 元字符 | BRE 中的写法 | ERE 中的写法 |
| --- | --- | --- |
| 一个或多个 | `\+` | `+` |
| 零个或一个 | `\?` | `?` |
| 分组 | `\) \)` | `( )` |
| 区间量词 | `\{n,m\}` | `{n,m}` |
| 或 | `\|` | `\|` 或 `\|`（grep 里需 `\|`） |
| 引用分组 | `\1` | `\1` |

**公式解析：转义规则的本质**

$$
\text{BRE：} \;\; \backslash \text{元字符} \Rightarrow \text{激活} \qquad
\text{ERE：} \;\; \backslash \text{元字符} \Rightarrow \text{字面量}
$$

拆解这条「反直觉」的规则：

- **第一步**：BRE 里 `+` 默认是**字面量加号**，要加反斜杠 `\+` 才是「一个或多个」。
- **第二步**：ERE 里 `+` 默认就是元字符，加反斜杠 `\+` 反而变成字面量加号。
- **第三步**：所以同一模式在两种方言里**差一个反斜杠**：BRE 的 `a\+` = ERE 的 `a+`。
- **第四步**：`*` 与 `.` 是少数两边一致的元字符——它们太古老、两套语法都默认激活。

**易错点**：别试图用一套记忆硬套所有工具。`grep` 默认 BRE、`grep -E` 切 ERE；`sed` 默认 BRE、`sed -E` 切 ERE；`awk` 默认 ERE。**写模式前先确认当前命令的方言**——`grep 'a\+b'` 与 `grep -E 'a+b'` 是同一个意思，写错方言就匹配不上。<span class="marginnote">`grep` 的 `-E` 与 `egrep` 等价，`-F`（fgrep）是纯字面量匹配、连正则都不解释——搜含大量特殊字符的字符串时 `-F` 最稳。`sed -E` 与 `gawk` 的 ERE 在细节上也有出入（如 `\w` 支持度），跨工具验证是职业习惯。</span>

## 2 分组与反引用：捕获的威力

**分组 `( )`** 不只能打包应用量词，还能**捕获**匹配到的内容，供后面**反引用（backreference）** 使用。反引用用 `\1`、`\2` 引用第 1、2 个分组：

```bash
# 找出重复的相邻单词：the the
grep -E '(\b\w+\b) \1' file.txt

# sed 交换两列的顺序：把 "first last" 换成 "last, first"
sed -E 's/(\w+) (\w+)/\2, \1/' names.txt
```

**公式解析：反引用的引用链**

$$
\text{模式} \;(\underbrace{\text{group 1}}_{\text{捕获}})\; \text{分隔符} \;\underbrace{\backslash 1}_{\text{引用 group 1 捕获的内容}}
$$

拆解 `(\b\w+\b) \1`：

- **第一步**：`\b\w+\b` 匹配一个完整的单词，外层括号把它捕获为 group 1。
- **第二步**：后面的 ` \1` 要求「一个空格 + 与 group 1 **完全相同**的内容」。
- **第三步**：于是整条模式只匹配「相同单词连写两次」——`the the` 命中、`the cat` 不命中。
- **第四步**：在 sed 替换里，`\2, \1` 把第二分组排到第一分组前面——**重排字段**最简洁的手段。

**易错点**：分组是从 `(` 出现顺序编号的，**嵌套括号从外到内编号**。反引用必须在**同一正则表达式的后半部分**引用——跨表达式无法引用（不同命令的变量另说）。分组过多时语义易混，超过两个分组就考虑拆成两步处理。

## 3 高级构件：区间、或、词边界

把进阶构件集中过一次：

| 构件 | 写法（ERE） | 含义 |
| --- | --- | --- |
| 区间量词 | `{2,5}` | 前项出现 2 到 5 次 |
| 或 | `a\|b` | 匹配 a 或 b |
| 词边界 | `\bword\b` | 独立单词 |
| 非捕获组 | `(?:...)` | 分组但不捕获（部分工具） |
| 预定义类 | `\d` `\w` `\s` | 数字、单词字符、空白（部分工具） |

一个「匹配 IP 地址」的完整模式：

```bash
grep -E '^([0-9]{1,3}\.){3}[0-9]{1,3}$' access.log
```

拆解：`[0-9]{1,3}` 是 1–3 位数字，`\.` 是字面点号，`(...){3}` 让「数字点」整体重复 3 次，最后再一个数字段——整条匹配「四段点分数字」。**注意它只校验格式，不校验数值**（`999.999` 也会过），严格的 IP 校验需要把每段限制在 0–255，那是另一层逻辑。<span class="marginnote">ERE 的 `|` 优先级极低：`a|bc` 是「a 或 bc」，想表达「ab 或 ac」要写 `a(b|c)`。`[0-9]` 与 `\d` 在 ERE 里不总是等价——grep -E 的 `\d` 未必被支持，用 `[0-9]` 最保险。</span>

**易错点**：`.` 在正则里匹配「任意字符」，**匹配字面点号必须转义 `\.`**。`grep '192.168.1.1'` 会误匹配 `192x168x1x1`——处理 IP、域名这类含点文本时，逐点转义是基本功。

## 4 贪婪与懒惰：匹配多少的哲学

量词默认**贪婪（greedy）**：尽可能多匹配。看这个例子：

```bash
echo '<b>bold</b> and <b>more</b>' | grep -oE '<b>.*</b>'
# 输出一整段：<b>bold</b> and <b>more</b>
```

`.*` 贪婪地吞掉了两个 `<b>...</b>` 之间的所有内容。想让匹配**最短**，用懒惰量词 `*?`（部分工具支持）：

```bash
grep -oE '<b>.*?</b>' 文件
# 只匹配第一个：<b>bold</b>
```

**易错点**：贪婪匹配是正则「结果比预期长」的头号原因。日志里取 `from=...` 到 `to=...` 之间的内容，若中间还出现过 `from`，贪婪会一路吞到最后一个——先画清楚「从哪个边界到哪个边界」再选量词。<span class="marginnote">`.*` 的贪婪也可以反过来利用：`<.*>.*</.*>` 配整段 HTML 标签。`sed` 与 `grep -E` 对懒惰量词支持不一，需要最短匹配时，用 `[^>]*` 这类「排除法」代替 `.*?` 更可移植。</span>

## 5 小结

- **BRE 元字符要反斜杠激活、ERE 直接生效**：`a\+` = `a+`，写模式前先确认命令方言。
- **分组捕获 + 反引用 `\1`**：`(\w+) \1` 查重复词，`s/(\w+) (\w+)/\2 \1/` 交换字段。
- **区间 `{n,m}`、或 `\|`、词边界 `\b`**：`([0-9]{1,3}\.){3}...` 这类模式是「一类问题」的模板。
- **贪婪默认、懒惰可选**：`.*` 吞到底，`.*?` 或 `[^>]*` 取最短。
- **跨工具验证**：grep 默认 BRE、`-E` 切 ERE，sed 用 `-E`，awk 默认 ERE——模式搬家前先跑一遍。
