## 为什么从磁盘与文件系统开始

前三篇我们在「文件」的层面工作，但文件不是凭空存在的——它最终要落在**磁盘**上，而磁盘上必须先有**分区**、被格式化成**文件系统**、再**挂载**进目录树，文件才有家。运维里最经典的一幕是「磁盘告警」：`df -h` 一看根分区 100% 爆满，但你不知道是哪个目录吃的，这时需要 `du` 逐层下钻。本章把这条链讲透：**块设备 → 分区 → 文件系统 → 挂载点 → 目录树**，并掌握日常最常用的两个观测命令 `df` 与 `du`。

## 1 从硬盘到分区：设备命名

Linux 把一切硬件都当作文件，磁盘也不例外。一块 SATA 硬盘在系统中表现为 `/dev/sda`、`/dev/sdb`……其中的 `sd` 表示 SCSI 磁盘设备，`a` 是设备序号；NVMe 固态则是 `/dev/nvme0n1` 这种命名。<span class="marginnote">设备文件只是「入口」：`/dev/sda` 本身不存数据，它是对整块磁盘的访问通道。在 `/dev/sda` 上分区后得到 `/dev/sda1`、`/dev/sda2`，后缀是分区号。用 `lsblk` 可以树状列出所有磁盘与分区。</span>

**分区（partition）** 是把一块物理磁盘划分成若干逻辑段。分区表有两种主流格式：**MBR**（传统，最多 4 个主分区，单盘上限约 2TB）与 **GPT**（现代，理论支持 128 个分区、大容量，是新装系统的默认选择）。<span class="marginnote">为什么 MBR 单盘上限约 2TB？因为 MBR 用 32 位来记录扇区地址，每个扇区 512 字节，$2^{32} \times 512$ 字节约等于 2TB。GPT 改用 64 位逻辑块地址，这个限制就消失了——GPT 正是为此而生。</span>

**核心对比表：MBR 与 GPT**

| 维度 | MBR | GPT |
| --- | --- | --- |
| 分区数量 | 最多 4 个主分区 | 默认 128 个 |
| 单盘容量 | 约 2TB 上限 | 巨大（EB 级） |
| 备份 | 分区表在磁盘首部，无备份 | 首尾各存一份，可自愈 |
| 兼容性 | 极老系统也能认 | 需 UEFI（或加保护 MBR） |

## 2 文件系统与挂载

**文件系统（filesystem）** 是磁盘分区上组织数据的「图书编目法」：它决定数据块怎么分、文件名怎么存、权限元数据放哪。Linux 常见的文件系统：`ext4`（传统 Linux 主力）、`xfs`（大文件与高并发友好，RHEL 默认）、`btrfs`（快照与压缩）、`tmpfs`（纯内存）。<span class="marginnote">上一章提到的 inode 就是文件系统的一部分：ext4 格式化时预留了一部分空间专门放 inode 表。`df -i` 可以看 inode 用量——有时候磁盘没满却创建不了文件，就是 inode 用尽了。</span>

**挂载（mount）** 是把一个文件系统「接」到目录树的某个目录上，这个目录叫**挂载点（mount point）**：

```bash
mount /dev/sdb1 /mnt/data      # 把 sdb1 挂到 /mnt/data
umount /mnt/data               # 卸载
mount                          # 不带参数，列出当前所有挂载
df -h                          # 查看文件系统用量
```

挂载之后，`/mnt/data` 目录就「变成」了那块分区——你在该目录读写，数据落在 `sdb1` 上。<span class="marginnote">关键直觉：目录本身在根文件系统上，挂载只是把根文件系统的一个目录「指向」另一块文件系统。卸载后目录还在，只是里面的内容消失了——这解释了为什么 `umount` 前要先确认没有进程占用（`lsof` 可查）。</span>

**易错点**：在挂载点目录里还残留着挂载前的内容时，挂载会把这些内容**暂时隐藏**，卸载后才重现。所以挂载点最好用空目录。

## 3 自动挂载：/etc/fstab

重启后手动 `mount` 就消失了，想要开机自动挂载，得写进 **`/etc/fstab`**。一行一个文件系统，六个字段以空白分隔：

```
/dev/sdb1  /mnt/data  ext4  defaults  0  2
```

| 字段 | 含义 |
| --- | --- |
| 设备 | `/dev/sdb1`，或用 UUID 更稳 |
| 挂载点 | `/mnt/data` |
| 文件系统类型 | `ext4` |
| 挂载选项 | `defaults`（含 rw、suid、exec 等） |
| dump 备份标记 | 0 表示不备份 |
| fsck 检查顺序 | 根分区 1，其他 2，0 表示不检查 |

**易错点**：fstab 写错会导致**开机卡在维护模式**。两个防线：一是用 `blkid` 查 UUID 而非设备名，设备名重启后可能变化；二是改动后用 `mount -a` 验证——它按 fstab 重新挂载所有项，能立即暴露语法错误，不用重启试错。<span class="marginnote">`defaults` 实际展开为 `rw,suid,dev,exec,auto,nouser,async` 一组默认选项。日常最常用的自定义选项是 `noatime`（关闭访问时间记录，减少写入）与 `nodev,nosuid`（安全加固，挂载点不需要设备文件与 setuid 时用）。</span>

## 4 新建磁盘的完整流程

把一块新盘接进系统，完整的命令序列通常是五步：

```bash
lsblk                      # 1. 确认新设备名（如 /dev/sdc）
fdisk /dev/sdc             # 2. 交互式分区：n 新建、p 主分区、w 写入
mkfs.ext4 /dev/sdc1        # 3. 在分区上格式化出文件系统
mkdir -p /mnt/data         # 4. 准备挂载点目录
mount /dev/sdc1 /mnt/data  # 5. 挂载，之后可读写
```

**易错点**：第三步的 `mkfs.ext4` 会**摧毁目标分区上的全部数据**——命令本身不确认，回车即执行。`fdisk` 的交互里 `p` 打印分区表、`n` 新建、`w` 写入，**只要不按 `w`，改动都只存在于内存**，`q` 退出即丢弃。先把 `p` 看清楚再按 `w`，是分区操作的安全底线。

格式化时还可以预先规划 inode 密度与块大小：`mkfs.ext4 -I 256 -b 4096 /dev/sdc1`。默认值对绝大多数场景足够，但「小文件海量、大文件稀少」这类特殊负载，值得查一次 `mkfs.ext4` 的手册再决定。

## 5 公式解析：df 与 du 的差别

**`df`（disk free）** 看整个文件系统的用量，**`du`（disk usage）** 统计目录树的占用。两者答案不一致是常态，因为 df 站在文件系统层、du 站在目录层：

$$
\text{df 报告的占用} = \text{文件系统已用块} - \text{保留块}
$$

$$
\text{du 统计的占用} = \sum_{\text{每个文件}} \text{逻辑大小（向上取整到块）}
$$
