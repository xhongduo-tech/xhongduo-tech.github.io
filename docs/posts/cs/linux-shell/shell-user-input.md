## 为什么从用户输入开始

目前我们写的脚本都是「自说自话」：跑起来就用写死的值。但真实工具必须**与人对话**——`backup.sh /home/data /backup/dir` 里的源目录与目标目录该由调用者给，`-v`、`-f` 这类选项也要能解析。本章讲三条输入通道：**位置参数**（命令行的 `$1 $2`）、**`read`**（运行时交互读入）、**`getopts`**（规范解析 `-a -b` 这类选项）。学完你写出的脚本会「长出手脚」：能被参数驱动、能交互询问、能像正规命令一样带选项。

## 1 位置参数：命令行直接传入

脚本运行时，命令行上的参数依次进入特殊变量：

```bash
#!/bin/bash
# 用法: ./greet.sh alice bob
echo "第 1 个参数: $1"
echo "第 2 个参数: $2"
echo "脚本名: $0"
echo "参数个数: $#"
```

**位置参数（positional parameters）** 是 `$1`、`$2`……`$9`；超过 9 个要写 `${10}`。`$0` 是脚本名，`$#` 是参数个数。<span class="marginnote">`$0` 里是<strong>调用时写的名字</strong>：`./greet.sh` 就给 `./greet.sh`，`bash greet.sh` 就给 `bash`（此时 `$0` 是 greet.sh）。用 `$0` 在脚本里显示用法信息时，把可能出现的 `./` 用 `basename "$0"` 去掉更友好。</span>

**校验参数个数**是脚本健壮性的第一课：

```bash
if [ "$#" -ne 2 ]; then
    echo "用法: $0 <源目录> <目标目录>"
    exit 1
fi
```

**易错点**：`$1` 未传时是空串而非报错——所以「参数没给全」不会崩溃，只会悄悄用空值。显式 `if [ $# -lt 2 ]` 校验，比指望用户按说明书来可靠得多。

## 2 公式解析：$* 与 $@ 的差别

`$*` 与 `$@` 都表示「全部位置参数」，但**展开方式不同**——这是本章最经典也最隐晦的辨析：

$$
\$* = \text{"\$1 \$2 \$3"} \quad (\text{全部参数作为}\textit{一个}\text{字符串})
$$

$$
\$@ = \text{"\$1" "\$2" "\$3"} \quad (\text{每个参数作为}\textit{独立}\text{字符串})
$$

拆解：

- **第一步**：`"$*"` 把所有参数拼成一个字符串，用第一个字符（IFS，默认空格）连接。
- **第二步**：`"$@"` 把每个参数当作独立的带引号单元。
- **第三步**：`for x in "$@"` 逐个处理每个参数；`for x in "$*"` 只循环一次、拿到一整串。
- **第四步**：当参数本身含空格时差别致命——`"$@"` 保持参数完整，`"$*"` 会把它拆散。

**规则**：遍历参数一律用 `"$@"`（加引号）。`$@` 不带引号等价 `$*` 不带引号，都会做分词，但既然要可靠，就记住「**`"$@"` 是唯一正确姿势**」。<span class="marginnote">`shift` 命令把参数左移：`shift` 后 `$2` 变 `$1`、`$3` 变 `$2`、`$#` 减一。`shift 2` 一次移两个。配合 `while [ $# -gt 0 ]`，是「逐个消费参数」的标准循环写法。</span>

## 3 read：运行时交互输入

**`read`** 在脚本执行到一半时停下来，从标准输入读一行：

```bash
read -p "请输入目标目录: " target
echo "将备份到: $target"

read -s -p "密码: " pass      # -s 静默输入（不回显）
read -t 5 -p "5 秒内确认(y/n): " ans   # -t 超时
```

常用选项：

| 选项 | 含义 |
| --- | --- |
| `-p` | 先打印提示符 |
| `-s` | 静默（不回显），适合密码 |
| `-t` | 超时秒数，超时返回非 0 |
| `-n 1` | 只读一个字符（按键即返回） |
| `-a` | 读入数组 |

**易错点**：`read` 交互需要人盯着屏幕，**不适合无人值守的 cron 任务**——排程里脚本只能「自己决定」，不能用 `read` 等待。`read` 读管道输入（如 `while read` 读文件）才是它在自动化里的主战场。<span class="marginnote">`read` 支持一次读多个变量：`read a b c` 把一行按空白切成三份，多余部分全给最后一个变量。读文件时 `while IFS= read -r line` 的三件套（IFS=、-r、重定向）上一章已见，是处理含空格行的标准解法。</span>

## 4 getopts：规范解析命令行选项

手写 `-v`、`-f file` 这类选项解析很痛苦，**`getopts`** 是 bash 内建的标准解法：

```bash
#!/bin/bash
while getopts "vf:" opt; do
    case "$opt" in
        v) verbose=1 ;;
        f) file="$OPTARG" ;;
        ?) echo "用法: $0 [-v] [-f 文件]"; exit 1 ;;
    esac
done
shift $((OPTIND - 1))    # 跳过已解析的选项，剩余的是位置参数
```

`getopts "vf:"` 声明「接受 `-v` 与 `-f`，`f` 后面跟一个参数」。`OPTARG` 存 `-f` 的值，`OPTIND` 是下一个待解析参数的索引。<span class="marginnote">`getopts` 与老命令 `getopt` 不是一回事：`getopts` 是 bash 内建、跨平台一致、支持 `-vf` 合并写法；`getopt` 是外部程序、能处理长选项但各发行版行为不一。脚本里优先 `getopts`。</span>

**易错点**：`getopts` 选项串里冒号表示「该选项需要一个参数」——`f:` 是「-f 必须带值」，没写冒号的 `v` 是「开关型」。`?` 分支捕获非法选项；`:` 分支捕获「缺参数」的情况。写完先用 `./script -h` 试一把，确认非法输入能被兜住。

## 5 小结

- **位置参数 `$1 $2 … $#`**：命令行直接传参，`${10}` 超过 9 个要加花括号，先 `$#` 校验再干活。
- **`"$@"` 遍历参数**：每个参数保持独立；`"$*"` 拼成一个串——遍历一律用 `"$@"`。
- **`read` 交互读入**：`-p` 提示、`-s` 静默、`-t` 超时；无人值守脚本别依赖交互。
- **`getopts` 解析选项**：`"vf:"` 声明、`OPTARG` 取值、`shift $((OPTIND-1))` 清理。
- **`shift` 左移参数**：配合 `while [ $# -gt 0 ]` 逐个消费。
