## 为什么从文件与目录管理开始

这是整条命令行学习路径的入口。后面的一切——权限位、查找过滤、压缩归档、Shell 脚本、服务管理——都建立在「文件与目录」这棵树上。上一级学编程时，我们操作的对象是变量与函数；到了 Linux 命令行，**文件和目录成为最基本的操作对象**，而 `ls`、`cd`、`cp`、`mv`、`rm` 就是针对它们的五个最高频命令。<span class="marginnote">「一切皆文件」让 Linux 能用同一套<strong>打开、读写、关闭</strong>的接口对待键盘、磁盘、网络 socket 与普通文件。这个统一的抽象是理解后面重定向与文件描述符的伏笔。</span>五个命令本身不复杂，但背后压着 Unix 的两个根本设计——**路径**把一棵树的位置说清楚，**inode** 让「文件内容」与「文件名」可以分离。把这两点吃透，后面的学习都会更顺。

## 1 路径：绝对与相对

**路径（path）** 是指向某个文件或目录的位置描述。Linux 只有一种书写方式：用 `/` 分隔的目录链。路径分两种：

- **绝对路径（absolute path）**：从根目录 `/` 写起，任何时刻都指同一个位置。例如 `/etc/ssh/sshd_config`。
- **相对路径（relative path）**：从当前所在目录写起，跟随你「现在在哪」而变化。例如 `../logs/app.log` 表示「上一级目录里的 logs 目录下的 app.log」。

几个路径记号要牢记：`.` 是当前目录、`..` 是上一级目录、`~` 是当前用户的家目录、`~user` 是某用户的家目录。

**重点**：相对路径的两条简化规则——**`. /` 表示「从当前目录进入」，`.. /` 表示「退回上一级」**。`cd ..` 与 `cd ../..` 是命令行里用得最多的两条命令。<span class="marginnote">「当前在哪」由每个 shell 进程各自的 `PWD` 环境变量记录，`pwd` 命令把它打出来。两个终端窗口可能处于不同目录——路径的相对性正是「每个进程一个工作目录」的体现，这在后面的 Shell 脚本里会再次遇见。</span>

**易错点**：`cd` 到一个不存在的目录会报错且**停留在原地**；而 `cd ..` 在根目录 `/` 下执行等于没动——`/` 的上一级还是它自己。判断路径写没写对，先想清楚「我此刻在哪」。

## 2 ls：认识文件的清单

**`ls`（list）** 列出目录内容，是使用率第一的命令。它本身的选项极多，日常记住下面几个就够：

```bash
ls              # 列出当前目录
ls -l           # 长格式：权限、属主、大小、时间
ls -a           # 包含隐藏文件（以 . 开头的文件）
ls -lh          # -h 让人读的大小（K/M/G）
ls -l /etc      # 指定目录
ls -lt          # 按修改时间排序（最新在前）
ls -R           # 递归列出子目录
```

`ls -l` 的第一列那 10 个字符是**权限位**——它长什么样、每个字符什么意思，是下一节《文件权限与目录配置》的主题。<span class="marginnote">隐藏文件只是「文件名以 `.` 开头」，Linux 并不真正「隐藏」它们，只是 `ls` 默认不显示。`.bashrc`、`.gitignore`、`.ssh/` 这些配置文件就这样安静地住在每个用户的家目录里。</span>

**易错点**：`ls` 与 `dir` 在 Linux 下几乎等价，但 `ls -l` 输出的总大小是「块数 × 块大小」，不是字节——真正统计目录占用要用 `du`，那是第2篇《磁盘与文件系统管理》的事。

## 3 cd/cp/mv/rm：移动与操作

**`cd`（change directory）** 切换工作目录：`cd /var/log`、`cd ~`、`cd -` 回到**上一次**所在的目录（记忆神器）。<span class="marginnote">`cd -` 在两个目录间往返极好用——在配置目录与日志目录之间来回切换，一条 `cd -` 就能跳回上一站。</span>

**`cp`（copy）** 复制，**`mv`（move）** 移动，**`rm`（remove）** 删除。三个命令的核心选项：

```bash
cp file.txt /tmp/            # 复制到目录
cp -r dir /tmp/              # -r 递归复制目录
cp -p file.txt /tmp/         # -p 保留权限、时间戳（备份常用）
mv file.txt /tmp/            # 移动
mv old.txt new.txt           # 同目录 mv = 重命名
rm file.txt                  # 删除文件
rm -r dir                    # 递归删除目录
rm -f file.txt               # -f 不询问直接删
```

**重点**：`mv` 在同一目录内就是**重命名**——对文件系统而言，「重命名」与「移动到另一个目录」本质都是「改目录项」，这又回到了 inode 的概念。<span class="marginnote">`cp -r` 复制目录内容与结构；若目标目录已存在，源目录会作为其子目录放进去；若不存在，会创建出同名目录。`cp` 的 `-a` 等价于 `-drp`，是整目录备份的最稳写法。</span>

**核心对比表：cp 与 mv 的区别**

| 维度 | cp | mv |
| --- | --- | --- |
| 结果 | 源文件保留 | 源文件消失 |
| 本质 | 复制数据，新建 inode | 移动目录项，inode 不变 |
| 目录复制 | 需 `-r` | 直接可用 |
| 改名能力 | 无 | 同目录内即改名 |
| 跨文件系统 | 任意 | 跨文件系统时退化为「复制+删除」 |

**易错点**：`rm -rf /` 是著名的事故命令——`-rf` 加上对根目录的误操作会删掉整个系统。习惯性把危险路径写全（`rm -rf /home/me/tmp/`）而不是依赖相对路径，并在删除前先 `ls` 确认。

## 4 ln：硬链接与符号链接

**`ln`（link）** 建立「指向文件」的新名字，是文件与目录管理里最容易被低估的命令。它有两种链接，行为迥异：

**核心对比表：硬链接与符号链接**

| 维度 | 硬链接 | 符号链接（软链接） |
| --- | --- | --- |
| 指向对象 | 同一个 inode | 另一个**路径名** |
| 是否新建文件 | 否，新增一个目录项 | 是，新建一个小文件存目标路径 |
| 跨文件系统 | 不能 | 可以 |
| 指向目录 | 不能 | 可以 |
| 源文件被删 | 硬链接仍有效 | 变成「悬空链接」，目标丢失 |
| `ls -l` 显示 | 正常文件 | `l` 开头，`->` 指向目标 |

**符号链接**是日常最常用的：`ln -s /opt/app /home/user/app` 建一个快捷方式，`ls -l` 下显示为 `app -> /opt/app`。<span class="marginnote">符号链接在 `.ssh/config`、`/etc/alternatives`、Python 虚拟环境里到处都是。注意：对符号链接执行 `rm` 删的是链接本身，不会动目标文件；`cp` 默认复制的是链接指向的<strong>内容</strong>而非链接。</span>

**公式解析：硬链接的 link count**

```
硬链接数 = 指向同一个 inode 的目录项（名字）的个数
```

拆解这条「公式」：

- **第一步**：文件内容存在 inode 里，而 inode 有一个计数器叫 **link count**，记录「有几个名字指向我」。
- **第二步**：`ln a.txt b.txt` 让 `b.txt` 也指向 `a.txt` 的 inode，于是 link count 从 1 变为 2——两个名字、一份内容。
- **第三步**：`rm a.txt` 只是删掉一个名字，link count 减为 1，内容仍在，`b.txt` 依旧能读到全部数据。
- **第四步**：只有 link count 归零且没有进程正在打开该文件时，inode 与数据块才被真正释放——**删除文件 = 减少链接数，而不是立即抹掉数据**。这也是为什么被误删的文件有时还能用数据恢复工具抢救。

## 5 小结

- **路径两种**：绝对路径从 `/` 写起恒指一处；相对路径从「当前目录」写起，`..` 回退、`~` 指家目录。
- **`ls -l` 看权限**：第一列 10 字符是权限位，是下一节的主线；`-a` 看隐藏文件、`-h` 让人读大小。
- **`cp`/`mv`/`rm` 三兄弟**：`mv` 同目录即改名、`cp -r` 复制目录、`rm -rf` 是危险命令需谨慎。
- **硬链接 vs 符号链接**：硬链接共用 inode、不能跨文件系统；符号链接存的是路径、可指向目录。
- **删除的本质**：`rm` 减 link count，归零才释放数据；目录默认 link count ≥ 2（自身与 `..`）。
