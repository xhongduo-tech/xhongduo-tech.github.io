## 为什么从网络安全开始

前面几篇的安全都发生在「一台机器内部」——认证、访问控制、加固、内存防护。但计算机几乎从不孤立存在：**数据要在网络上传输，而网络恰恰是攻击者最便利的战场**——攻击者不需要进入你的机房，只要在网络上截获、篡改、伪造流量，就能实施攻击。<span class="marginnote">Stallings 第13章开启第3篇《网络安全》——它从网络协议栈的视角重新审视安全：<strong>每一层协议都有自己的威胁与防护</strong>。理解网络安全，是理解 TLS、IPsec、无线安全、防火墙等后续各篇的共同基础：它们都是在「协议栈的某个高度」上补上安全。</span>本篇建立三件事：网络攻击的分类、协议栈各层的威胁、以及常见的网络攻击技术。

## 1 网络安全的攻防视角

网络安全的基本矛盾：**协议栈的设计假设「信道可信」，而现实信道不可信**。攻击者可以：

**窃听（passive eavesdropping）**：在链路上截获流量——不改变数据，但读取内容。**篡改（modification）**：修改在途数据。**伪造（fabrication）**：冒充合法主机发送数据。**中断（interruption）**：阻断通信（DoS）。<span class="marginnote">这四类网络威胁与概述篇的「被动/主动攻击」一一对应：<strong>窃听是典型的被动攻击（靠加密防），篡改/伪造/中断是主动攻击（靠完整性校验与检测防）</strong>——网络安全不过是「把网络协议放进安全框架」的具体化。这一节值得反复记住的一句话：<strong>「网络层的每一跳都是不可信的中转」</strong>，数据离开你的机器，就不再受你控制。</span>

**重点：网络安全的防护逻辑与单机安全完全一致——防窃听靠加密，防篡改靠完整性校验，防伪造靠认证。** 只是实施的位置在协议栈的不同层，后续各篇（TLS、IPsec、邮件安全）就是这些防护在各层的具体化。

## 2 协议栈各层的安全：从链路到应用

用 OSI/TCP/IP 协议栈逐层看「每层有什么威胁、谁来防护」：

| 层 | 典型协议 | 主要威胁 | 安全机制 |
| --- | --- | --- | --- |
| 链路层 | 以太网、Wi-Fi | 窃听、ARP 欺骗 | 链路加密、802.1X |
| 网络层 | IP、ICMP | IP 欺骗、路由劫持、Smurf | IPsec、过滤器 |
| 传输层 | TCP、UDP | SYN Flood、端口扫描、会话劫持 | TLS、SYN Cookie |
| 应用层 | HTTP、DNS、邮件 | SQL 注入、DNS 劫持、钓鱼 | 应用级防护、WAF |

<span class="marginnote">这张表是「<strong>分层安全</strong>」的地图：每一层都可能有漏洞，每一层都需要防护。但也正因如此，攻击者可以在「防护最弱的层」下手——所以现代安全强调「全栈纵深」，而不是「某一层固若金汤」。下面几篇将逐层深入：<strong>TLS 管传输层，IPsec 管网终层，无线安全管链路层，邮件安全管应用层</strong>。</span>

**重点：本专题的网络安全各篇，本质上都是「在这张表的某一层上补安全」**——网络安全的框架性认识（本篇）是它们的前提。

## 3 常见网络攻击：从扫描到劫持

几个贯穿协议栈的高频攻击技术：

**端口扫描（port scanning）**：攻击者用 `nmap` 等工具探测「哪些端口开放、跑什么服务」，为后续攻击做侦察——它是几乎所有网络攻击的「第一步」。<span class="marginnote">端口扫描本身不造成伤害，但它是「<strong>踩点</strong>」：攻击者先扫描出目标开放的服务与版本，再针对性利用已知漏洞。防御不是「禁止扫描」（无法完全禁止），而是「<strong>最小暴露</strong>」——少开端口、隐藏非必要服务，让扫描结果「没有可利用的信息」。</span>

**ARP 欺骗（ARP spoofing）**：链路层攻击——攻击者伪造 ARP 应答，让受害者的流量被重定向到攻击者机器（中间人），随后窃听或篡改。<span class="marginnote"><strong>ARP 欺骗</strong>是局域网内最经典的中间人手法：ARP 协议本身无认证，攻击者广播「网关的 IP 是我的 MAC」，受害者的包就都流向攻击者。防护靠「静态 ARP 表」「端口安全」或「DHCP Snooping + DAI」等交换机特性——但最彻底的还是「<strong>上层加密</strong>」（TLS/IPsec），让被重定向的流量也读不懂。</span>

**IP 欺骗（IP spoofing）**：伪造源 IP 地址——用于隐藏真实身份、绕过访问控制、实施反射型攻击（DoS 一篇的放大攻击）。

**中间人攻击（MITM）**：攻击者插入通信双方之间，同时扮演两边的「对方」——窃听、篡改、重放。TLS 的证书验证（PKI 一篇）正是为防 MITM 而设计。

## 4 公式解析：Smurf 攻击的放大原理

Smurf 是经典的 ICMP 放大攻击，它揭示了「网络放大」的基本数学——也是后面 DDoS 放大攻击的鼻祖：

$$
\text{攻击流量} = \text{伪造源地址的 ping} \times \text{广播网内主机数}
$$

- **伪造源地址**：攻击者发送 ICMP Echo 请求，**源地址伪装成受害者的 IP**。
- **定向广播**：把请求发往一个网络的广播地址——该网络内**每台主机都会响应**，把响应发向「源地址」（即受害者）。
- **放大因子**：一次攻击包，换来网络内 N 台主机的响应——放大 N 倍，受害者瞬间被响应淹没。

**重点：放大攻击的根源是「协议回应的不对称」——一个小的请求换来大的（或多的）响应。** Smurf 已被现代网络的广播配置禁用（默认不回应定向广播），但它奠定了「放大攻击」的范式：DNS 放大、NTP 放大、Memcached 放大都是同一逻辑的变体（详见《拒绝服务攻击与防护》）。

## 5 会话劫持与 DNS 攻击

**会话劫持（session hijacking）**：攻击者窃取或预测合法的会话凭证（cookie、序列号），接管已建立的连接——受害者被踢下线，攻击者以受害者身份继续通信。**TCP 会话劫持**依赖预测 TCP 序列号（早期很可行，现代随机化后变难）；**应用层会话劫持**则常靠窃取 cookie（XSS 攻击的载荷之一）。

**DNS 攻击**：DNS 是「互联网的电话簿」，攻击它等于劫持「地址解析」：

**DNS 缓存投毒（cache poisoning）**：向 DNS 服务器注入伪造的解析记录，让用户访问到攻击者的服务器（钓鱼）。**DNS 劫持**：篡改域名解析。**DNS 隧道**：把数据藏在 DNS 查询里偷偷外传（绕过防火墙）。<span class="marginnote"><strong>DNS 缓存投毒</strong>的经典案例是 2008 年的 Kaminsky 漏洞——它让「一次投毒可污染整个域名」成为现实，直接推动了 <strong>DNSSEC</strong>（DNS 安全扩展，对解析记录做数字签名）的推广。理解 DNS 攻击，还牵出「信任链」的脆弱：用户信任 DNS，DNS 却被投毒——本专题《邮件安全》里的邮件伪造也利用了类似的信任缺口。</span>

## 6 网络侦察：攻击的序幕

大多数网络攻击不是「直接打」，而是先**侦察（reconnaissance）**——了解目标网络的拓扑、开放端口、操作系统版本、存在的服务。侦察阶段包括：

**被动侦察（passive）**：不接触目标——通过搜索引擎、whois、DNS 记录、公开泄露的数据库了解目标。**主动侦察（active）**：直接探测——ping 扫描（探测存活主机）、端口扫描（探测开放服务）、操作系统指纹（`nmap -O` 判断 OS）、服务版本探测。<span class="marginnote">「<strong>侦察难防</strong>」是网络安全的现实：ping 扫描、端口探测这类行为很难与正常流量区分，也很难被完全禁止。所以网络防御的思路不是「阻止侦察」（做不到），而是「<strong>让侦察结果无用</strong>」——少开端口、隐藏版本号、把服务放在非标准配置下，让攻击者「踩了点点不出有价值的信息」。</span>

**威胁情报（threat intelligence）**：防守方也用侦察——收集攻击者的 IP、域名、攻击手法（IoC），提前封堵。**攻防双方的「侦察」是同一套技术，方向相反**——这正是网络安全的对称性。

## 7 网络访问控制与分段

防御网络攻击的架构手段，核心是「控制谁能在网络上接触谁」：

**网络分段（network segmentation）**：把网络按信任级别分成多个段（DMZ、内网、数据库区），段与段之间用防火墙/ACL 控制——**攻击者即使突破一个段，也难以横向移动到核心区**。<span class="marginnote"><strong>网络分段是「防横向移动」的关键</strong>：现实中的入侵很少一次到位，而是「先打外围，再横向跳到内网，最后摸到数据库」。分段让每一跳都要跨防火墙——攻击者的每一步都被拦一道。<strong>微隔离（micro-segmentation）</strong>进一步把分段细到工作负载级别（每台服务器独立策略），是云与零信任时代的网络隔离主流。</span>

**网络访问控制（NAC）**：接入网络前的「准入检查」——设备是否合规（有杀毒、有补丁）、用户是否认证，不合规就隔离。**DMZ（非军事区）**：对外服务的服务器放在 DMZ，即使被攻破，也难以直接接触内网核心。

## 8 网络监控与入侵检测

**网络监控**：对进出流量做持续观察与分析——它是「发现入侵进行中」的眼睛：

**流量基线**：建立「正常流量什么样」的基线，偏离基线的异常（突增的外联、异常的协议、可疑的目的 IP）触发告警。**NetFlow/IPFIX**：流级别的元数据（谁连谁、多大流量、什么协议）——比抓包轻量，适合长期监控。<span class="marginnote">网络监控要回答三个问题：<strong>谁在连谁（流向）、连了多少（流量）、像不像正常（异常检测）</strong>。它不做「拦截」，只做「发现」——发现可疑活动后，交给入侵检测/防御系统（《IDS/IPS》一篇）与事件响应处理。监控与检测的分工是：<strong>监控是「眼」，检测是「哨兵」，响应是「行动」</strong>。</span>

**入侵检测（IDS）/入侵防御（IPS）**：网络层的检测与自动阻断——基于签名（已知攻击特征）与基于异常（行为偏离基线）。这是《入侵检测与防御 IDS/IPS》一篇的主题，本篇先立位置。

## 9 传输层与网络层的典型攻击细化

把传输层与网络层的代表性攻击再拆开看，理解「攻击者如何玩弄协议」：

**SYN Flood**：发送海量 TCP 握手第一步（SYN）而不回 ACK，让服务器连接表被半开连接占满（详见《拒绝服务》一篇的公式解析）。**TCP 序列号攻击**：预测或窃取 TCP 序列号，向已建立的连接注入伪造数据——早期实现可预测序列号，让「会话注入」成为可能。<span class="marginnote"><strong>TCP 序列号攻击</strong>是「<strong>协议实现不可靠</strong>」的早期经典：1990 年代许多系统用可预测的初始序列号（ISN），攻击者可冒充可信主机向连接注入数据。现代系统用随机 ISN（RFC 6528 的随机化建议），让这类攻击几乎失效——又一次「协议设计修复」胜过「堆补丁」的例子。</span>

**RST 攻击**：伪造 TCP 重置包，强行断开合法连接——一种低成本 DoS。**ICMP 重定向**：发送伪造的 ICMP 重定向消息，让受害者把流量发往攻击者指定的路由——篡改路由表实现中间人。

**重点：这些攻击的共同模式是「<strong>伪造协议控制消息</strong>」**——TCP/IP 协议的许多消息本是为「协作」设计（重置、重定向、序列号），却被攻击者用来「破坏」。防护的方向要么是「认证这些消息」（如 IPsec、BGP 的 RPKI），要么是「随机化让伪造难以成功」（如随机 ISN）。

## 10 小结

- **网络安全的基本矛盾**：协议假设信道可信，现实信道不可信；四类威胁（窃听/篡改/伪造/中断）对应被动与主动攻击。
- **分层安全**：链路/网络/传输/应用每层都有威胁与防护——「全栈纵深」是网络安全的必然要求。
- **常见攻击**：端口扫描（踩点）、ARP 欺骗（局域网 MITM）、IP 欺骗、中间人攻击。
- **Smurf 放大**：一次小请求 × N 台主机 = N 倍攻击流量——放大攻击范式的鼻祖，与 DoS 篇的 DNS/NTP 放大同源。
- **会话劫持**：窃取凭证接管连接；**DNS 缓存投毒**劫持地址解析，催生了 DNSSEC。
- **后续各篇**：TLS（传输层）、IPsec（网络层）、无线安全（链路层）、邮件安全（应用层）——都是在协议栈特定层上补安全。
- **网络侦察难防**：主动/被动侦察让「最小暴露」成为关键——少开端口、隐藏版本，让侦察结果无用。
- **网络分段与 NAC**：防横向移动的核心架构手段；监控是「眼」、检测是「哨兵」、响应是「行动」。
- **分层的攻防地图**：链路/网络/传输/应用四层的威胁与防护——「全栈纵深」是网络安全的必然要求。
- **DNSSEC 的启示**：DNS 缓存投毒暴露了「信任链的脆弱」——用户信任 DNS，DNS 却可能被投毒，信任必须有签名与验证兜底。
- **加密是网络安全的万灵底色**：无论哪一层被劫持、被重定向，只要数据加密了，窃听者读不懂、篡改者会被发现——加密让「信道不可信」变得无关紧要。

在下一节，我们从「传输层之上」开始逐层补安全——**传输层安全与 TLS**：最常用的应用（HTTPS）最需要保护，而 TLS 正是那层「保护连接」的安全。
