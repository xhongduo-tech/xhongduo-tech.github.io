## 为什么从入侵检测开始

本专题一路讲的都是「防」——认证、访问控制、加固、加密。但安全的基本现实是：**没有绝对防得住的系统**。攻击者总会找到漏网之鱼。于是安全体系必须回答下一个问题：**如果入侵正在发生（或已经发生），我们能发现吗？**<span class="marginnote">入侵检测的定位，是概述篇「被动靠防、主动靠测」里「测」的核心载体：<strong>防是「不让它发生」，测是「它发生了要知道」</strong>。Stallings 第19章专章讲入侵检测与防御——它是「发现入侵进行中」的眼睛，也是事件响应（《事件响应》一篇）的前置哨兵：先发现，才谈得上响应。</span>本篇建立三件事：入侵检测的工作原理、IDS 与 IPS 的差别、以及检测方法的取舍。

## 1 入侵检测的基本思想

**入侵检测（intrusion detection）**：监控系统与网络活动，识别「未经授权或恶意」的行为。**入侵检测系统（IDS）** 是执行这一任务的系统，它回答两个问题：**什么是「异常」？如何判定「异常」？**

**IDS 的工作流程**：**数据采集**（流量、日志、系统调用）→ **特征提取**（连接特征、行为序列）→ **分析判定**（是否入侵）→ **告警响应**（通知安全团队）。<span class="marginnote">IDS 与防火墙的差别值得先分清：<strong>防火墙是「门卫」（在网络边界拦「看起来不对」的流量），IDS 是「监控探头」（观察内部行为是否异常）</strong>。防火墙是预防层（防），IDS 是检测层（测）——两者互补，不是替代。攻击者突破了防火墙，IDS 仍要能发现。</span>

**关键指标——误报与漏报**：**误报（false positive）**——正常行为被误判为入侵；**漏报（false negative）**——真正的入侵未被发现。**两者此消彼长**：阈值调严，漏报降低但误报飙升（安全团队被告警淹没）；阈值调松，误报减少但漏报上升（真攻击被放过）。<span class="marginnote">「<strong>告警疲劳</strong>」是 IDS 部署的现实痛点：高误报率让安全分析师对海量告警麻木，真正的攻击反而被淹没。现代安全运营（SOC）的告警调优，本质是在「多告警多打扰」与「少告警漏真凶」之间找平衡——这也是为什么「告警质量」比「告警数量」更受重视。</span>

## 2 IDS 的两大检测方法

IDS 判定「异常」的方法，分两大流派：

**基于特征/签名的检测（signature-based）**：把已知攻击的特征（流量模式、恶意载荷、攻击序列）做成「签名库」，流量与签名匹配即告警。<span class="marginnote">签名检测的优点是<strong>准确（低误报）</strong>、直接（能指出具体攻击）；缺点是<strong>只能检测已知攻击</strong>——新攻击、变种攻击（多态、变形）不匹配任何签名就被漏过。它与杀毒软件的特征码检测同源：都是「比对已知指纹」的逻辑，都受「滞后于新样本」的限制。</span>

**基于异常的检测（anomaly-based）**：先学习「正常行为」的基线（流量特征、用户行为、系统调用序列），偏离基线即告警。<span class="marginnote">异常检测的优点是能发现<strong>未知攻击与「伪装成正常」的异常</strong>（0-day 也可能偏离基线）；缺点是<strong>误报率高</strong>（正常行为也可能偶尔偏离基线）且需要「干净的训练数据」来建立基线。签名是「知道坏人长什么样」，异常是「知道好人长什么样」——一用「已知恶意」，一用「已知正常」。</span>

**实践中的组合**：主流 IDS 几乎都是「签名为主 + 异常为辅」——签名保证低误报覆盖已知，异常补漏未知。

## 3 HIDS 与 NIDS：检测的两个位置

按「监控哪里」，IDS 分两类：

**网络型 IDS（NIDS）**：部署在网络的汇聚点（交换机镜像端口、网关），**旁路监听**全部流量，分析是否包含攻击特征。<span class="marginnote">NIDS 的关键设计是「<strong>旁路（out-of-band）</strong>」——它挂在一个「流量镜像口」上观察，不串在流量路径中间（串中间会引入延迟与单点故障）。NIDS 能发现「网络层面的攻击」（扫描、DoS、溢出载荷），但看不到「加密流量内部」——TLS 加密后，NIDS 只能看到密文。</span>

**主机型 IDS（HIDS）**：安装在**单台主机**上，监控该主机的系统活动——日志、文件完整性、系统调用、进程行为、注册表/配置文件变化。<span class="marginnote">HIDS 能发现「主机层面的异常」：Web 服务器被挂马改文件、系统二进制被替换、可疑进程、异常登录。它能看到 NIDS 看不到的「加密后的应用层行为」与「主机本地活动」。现代 EDR（端点检测与响应，见《恶意软件》一篇）就是 HIDS 的进化形态——检测能力 + 云端情报 + 远程处置。</span>

**两种互补**：NIDS 看「网络」，HIDS 看「主机」——真实部署通常两者都要，各补对方盲区。

## 4 IPS：从「发现」到「阻断」

**入侵防御系统（IPS）** 是 IDS 的「主动版」：不仅检测，还**自动阻断**——它**串联**在网络路径上，检测到攻击即刻丢弃/阻断流量。<span class="marginnote">IDS 与 IPS 的核心差别在<strong>部署方式</strong>：<strong>IDS 旁路监听（只报不动），IPS 串联阻断（自动拦截）</strong>。IPS 的优点是「即时止损」——攻击流量在到达目标前就被丢弃；代价是「误报=误伤」——正常流量被误判拦截，等于自我 DoS。所以 IPS 通常配合「先旁路观察调优、再串联启用」的部署节奏。</span>

**IPS 与防火墙的关系**：传统防火墙按「五元组」（源/目的 IP、端口、协议）做粗粒度拦截；IPS 深入「载荷内容」做细粒度检测（这个 HTTP 请求是否含注入载荷）。现代统一威胁管理（UTM）/下一代防火墙（NGFW）把两者融合——先按规则拦，再按内容检测。

## 5 公式解析：检测能力的评估指标

如何评估一个 IDS 好不好？用「四格表」与派生指标：

$$
\text{TPR（检出率/召回率）} = \frac{TP}{TP + FN}, \qquad \text{FPR（误报率）} = \frac{FP}{FP + TN}
$$

- **TP（真阳）**：攻击被正确检出。**FN（漏报）**：攻击被放过。**FP（误报）**：正常被误判为攻击。**TN（真阴）**：正常被正确放行。
- **TPR = TP/(TP+FN)**：所有攻击里被检出的比例——**越高越好**（少漏报）。
- **FPR = FP/(FP+TN)**：所有正常行为里被误判的比例——**越低越好**（少误报）。

**重点：理想是「TPR 高 + FPR 低」，但现实是「鱼与熊掌」**——ROC 曲线就是「在 TPR 与 FPR 之间权衡」的可视化：调阈值让曲线往左上角走（高 TPR 低 FPR）就是好系统。<span class="marginnote">「<strong>没有完美检测器</strong>」可以用指标证明：任何检测器都要在 TPR/FPR 间做取舍（ROC 曲线下的面积 AUC 衡量整体能力）。评估一个 IDS 不是问「能不能检测」，而是问「在可接受的误报下，能检出多少」——这是安全运营里「用数字说话」的典型。</span>

## 6 IDS 的数据来源与告警流程

IDS 的「眼睛」能看多远，取决于数据喂得多好。主流数据来源：

**网络流量**：NetFlow/IPFIX 元数据、完整数据包（深度包检测 DPI）。**主机日志**：系统日志（`syslog`/`journald`）、认证日志、应用日志。**系统活动**：文件完整性（Tripwire/AIDE）、进程行为、系统调用序列。<span class="marginnote">「<strong>数据质量决定检测质量</strong>」是 IDS 的铁律：日志不完整、流量不镜像、主机不装代理，IDS 就「看不见」。所以好的安全运营先做「<strong>日志与流量的全覆盖</strong>」（SIEM 集中日志、交换机镜像端口），再谈检测算法——<strong>检测的上限由「能看见多少」决定，不由算法决定</strong>。</span>

**告警的生命周期**：检测到异常 → 生成告警（含威胁情报关联）→ 分析师研判（是真攻击还是误报）→ 升级响应（事件响应流程）→ 反馈调优（减少误报）。**SIEM（安全信息与事件管理）** 把多个数据源（IDS、防火墙、主机、云）的日志集中、关联分析、统一告警——它是现代安全运营（SOC）的「大脑」，IDS 是它的「眼睛」。

## 7 入侵检测的对抗：攻击者的反制

攻击者也在进化——他们学习如何「绕过 IDS」：

**加密流量**：用 TLS 加密攻击载荷，NIDS 看不到内容——对策是 TLS 解密后检测（需合法证书）或只做「元数据层」检测。**分片与混淆**：把攻击载荷拆成多个碎片、加随机填充，绕过「单包匹配」的签名。**慢速与低流量攻击**：把攻击流量压到「低于阈值」的速率，绕过基于流量的异常检测。<span class="marginnote">「<strong>绕过 IDS 的每一条路，都反过来推动 IDS 的进化</strong>」：加密催生了「解密+检测」，分片催生了「流重组检测」，慢速催生了「长期行为分析」。这与内存防护的「攻防升级螺旋」同构——检测与反检测是同一场永不停歇的军备竞赛。</span>

**攻击者探测 IDS 的存在**：主动扫描触发告警、观察响应判断是否被监控，然后调整手法。**对策**：IDS 的「蜜罐（honeypot）」——部署一台「故意暴露的诱饵主机」，吸引攻击者攻击，既能延迟攻击、又能收集攻击手法。

## 8 现代检测：从规则到机器学习

传统 IDS 依赖人工编写规则，现代检测在向「自动化 + 机器学习」演进：

**威胁情报（threat intelligence）**：把外部情报（恶意 IP、恶意域名、攻击特征）自动喂给 IDS——「别人被攻击的教训，成为我检测的规则」。**机器学习检测**：用分类模型（决策树、随机森林、深度模型）从大量「正常 + 异常」样本中学习「攻击长什么样」，自动发现新型攻击。<span class="marginnote"><strong>ML 检测的核心张力</strong>是「<strong>误报与可解释性</strong>」：深度学习模型检测率高，但「为什么判定为攻击」难以解释，安全分析师不信任「黑盒告警」；规则检测可解释但僵化。2026 年的实践走向「<strong>ML 初筛 + 规则/人工复核</strong>」——ML 负责「在海量流量里挑可疑的」，规则与分析师负责「确认到底是不是」。</span>

**重点：检测技术一直在进化，但「检测的本质」不变——把「已知正常」或「已知恶意」的判定逻辑，应用于持续的数据流。** 签名→异常→ML 的演进，只是「判定逻辑」的自动化程度越来越高，检测与误报的基本权衡始终存在。

## 9 IDS/IPS 的部署位置与架构

检测系统的价值，一半取决于「部署在哪里」。典型位置：

**边界部署**：网络出口的 NIDS/IPS——监视「进出网络的流量」，拦截来自外部的攻击。**关键网段部署**：在 DMZ、数据库区、核心服务器区部署 NIDS——监视「内部的横向移动」。**主机部署**：对关键服务器（Web、数据库、域控）部署 HIDS——监视「单机的活动」。<span class="marginnote">部署位置决定检测能力：<strong>只在外围部署 NIDS，内部的横向移动就看不见；只在主机部署 HIDS，全网规模的攻击就看不见</strong>。成熟的架构是「<strong>边界 NIDS + 关键网段 NIDS + 关键主机 HIDS + SIEM 集中</strong>」——每一层放一个「探针」，把数据汇到 SIEM 统一研判。</span>

**分流与性能**：IDS 不能成为瓶颈——旁路 NIDS 用「流量镜像」不串路径，IPS 串联要评估延迟与吞吐。**云环境**：虚拟化与云原生环境下，传统「旁路监听」难以实施，转向「云原生日志采集 + 行为分析 + 代理检测」——检测从「网络旁路」走向「数据与行为驱动」。

**重点：检测系统的架构设计，本质是「在哪里放眼睛」的决策**——要与资产价值（保护什么）、威胁模型（怕什么）对齐，而不是「设备堆得越多越好」。检测架构是风险管理的延伸：**把检测资源优先部署在「价值高、风险大」的位置**。

## 10 小结

- **入侵检测定位**：防是「不让发生」，测是「发生要知道」——IDS 是安全体系的「眼睛」。
- **两大方法**：签名检测（准确但只认已知）vs 异常检测（能抓未知但误报高）——实践以签名为主、异常为辅。
- **NIDS vs HIDS**：网络旁路监听 vs 主机本地监控——NIDS 看不到加密流量，HIDS 看主机活动，两者互补。
- **IDS vs IPS**：旁路只报 vs 串联阻断——IPS 即时止损但误报即误伤，需先旁路调优再串联启用。
- **评估指标**：TPR（少漏报）与 FPR（少误报）此消彼长——ROC/AUC 量化检测能力，「没有完美检测器」。
- **IDS 是「发现入侵」的哨兵**：它把「已发生的入侵」变成「可被看见的事件」，是事件响应（下一篇）的前置。
- **数据质量决定检测质量**：SIEM 集中日志、交换机镜像端口——检测的上限由「能看见多少」决定。
- **检测对抗是军备竞赛**：加密、分片、慢速绕过推动检测进化；蜜罐收集攻击手法，ML 初筛 + 规则/人工复核是 2026 年的实践走向。
- **检测架构是「在哪里放眼睛」**：边界 NIDS + 关键网段 NIDS + 关键主机 HIDS + SIEM 集中——检测资源优先部署在高价值高风险位置。
- **IDS 的前提是「看到了」**：数据覆盖（日志/流量/主机）决定检测上限；告警要经过「研判→响应→调优」的闭环才有价值。
- **IDS 是响应体系的输入**：检测到的告警是事件响应（《事件响应》一篇）的触发源——「发现」与「处置」必须衔接。
- **检测没有终点**：攻击者在进化、数据在变化、业务在扩展——IDS 的规则与基线需要持续调优，检测体系是「活」的。
- **告警质量 > 告警数量**：高误报导致的告警疲劳会让真攻击被淹没——调优的目标是「在可接受误报下检出尽量多」。
- **防火墙 + IDS/IPS 的分工**：防火墙是边界「门卫」（防），IDS/IPS 是内部「哨兵 + 拦截」（测与防）——两者叠加才是「防得住 + 看得见」的完整纵深。
- **检测的价值在闭环**：告警不处置等于没有检测——IDS 必须与事件响应、威胁情报、规则调优形成持续循环。

在下一节，我们从「发现入侵」走向「守住边界」——**防火墙与网络边界防护**：IDS 是「内部的监控」，防火墙是「边界的大门」。IDS 让入侵「可见」，防火墙让入侵「难进」——两者一测一防，构成边界与内部的完整纵深。
