## 为什么从哈希讲起

上一篇的加密解决「内容保密」，但保密不等于可信：**密文在传输途中被篡改、或发送方事后否认发过，加密都无能为力**。完整性、认证与不可否认性需要另一族密码原语——哈希、消息认证码（MAC）与数字签名。<span class="marginnote">你可以把三者看成一个递进：哈希回答「内容变了吗」（对所有人），MAC 回答「内容变了吗 + 是不是持有密钥的对方发的」（对称认证），数字签名回答「内容变了吗 + 是不是某个特定主体发的 + 无法抵赖」（非对称认证）。</span>这一篇是上一篇的自然延续：同样的数学工具，目标从机密性转向完整性与真实性。

## 1 密码哈希函数：内容指纹

**密码哈希函数（cryptographic hash function）**：把任意长度的输入压缩为固定长度输出（摘要，digest）的函数 $H$，满足三个安全性质：

**抗原像（preimage resistance）**：给定 $y$，找不到 $x$ 使 $H(x) = y$——摘要不可逆推原文。**抗第二原像（second preimage resistance）**：给定 $x_1$，找不到 $x_2 \neq x_1$ 使 $H(x_1) = H(x_2)$。**抗碰撞（collision resistance）**：找不到任意一对 $x_1 \neq x_2$ 使 $H(x_1) = H(x_2)$。<span class="marginnote">三个性质强度递增：抗碰撞蕴含抗第二原像，抗第二原像蕴含抗原像。现实中还要求「雪崩效应」——输入改 1 位，输出约一半位翻转，使摘要与输入之间看不出任何统计关联。</span>

**散列的特性就是「指纹」**：文件内容完全一致 → 摘要完全一致；内容任何一比特变化 → 摘要面目全非。典型算法：**SHA-2 家族**（SHA-256、SHA-512，2026 年仍安全）与 **SHA-3**（Keccak）；已废弃的 MD5、SHA-1 因碰撞攻击（如 2017 年 SHA-1 的 SHAttered 碰撞）不得再用于安全场景。

哈希的用途远不止完整性：口令存储（上一篇）、区块链的工作量证明、去重、Git 的对象寻址——**一切「给内容贴指纹」的地方**都是哈希的舞台。<span class="marginnote">Git 用 SHA-1 给每个提交生成对象 ID，就是把哈希当「内容寻址」用——内容变则 ID 变，天然防篡改。虽然 SHA-1 已被攻破，但 Git 的哈希碰撞攻击需要精心构造对象，现实威胁有限。</span>

## 2 消息认证码：带密钥的完整性

哈希能证明「内容没变」，但**证明不了「内容没被调包」**——攻击者可以同时替换消息和它的摘要。**消息认证码（MAC, Message Authentication Code）** 解决这个问题：MAC 是**带密钥的哈希**，只有持有密钥的双方才能计算与验证。

$$
\text{MAC} = C_K(M)
$$

典型构造：**HMAC（基于哈希的 MAC）**，写作 $\text{HMAC}(K, M) = H\big((K' \oplus \text{opad}) \,\|\, H((K' \oplus \text{ipad}) \,\|\, M)\big)$。<span class="marginnote">HMAC 用两个不同的填充常量（ipad/opad）对密钥做两次哈希混合，使得即使底层哈希有轻微弱点，HMAC 仍保持安全。RFC 2104 定义 HMAC，TLS 的密钥派生、JWT 的 HS256 签名都基于它。</span>

**MAC 的语义**：完整性 + 数据源认证（发送方也持有密钥）。但它是**对称**的——接收方与发送方共享密钥，接收方无法向第三方证明「这消息确实是发送方发的」（因为接收方自己也能伪造）。这就是 MAC 与数字签名的根本差别。

## 3 数字签名：完整性的非对称升级

**数字签名（digital signature）**：用**发送方私钥**对消息（或其摘要）进行运算，任何持有对应**公钥**的人都能验证，但只有私钥持有者能产生。它把 MAC 的「对称认证」升级为「非对称认证 + 不可否认」：

$$
\sigma = \text{Sign}_{K_{priv}}(H(M)), \qquad \text{Verify}_{K_{pub}}(M, \sigma) = \text{true/false}
$$

三步解析：

- **签名**：发送方计算消息摘要 $H(M)$，用自己的私钥对摘要签名，得到签名值 $\sigma$，把 $(M, \sigma)$ 一起发送。
- **验证**：接收方用发送方的公钥验证 $\sigma$ 是否是对 $H(M)$ 的合法签名——不需要共享任何秘密，只需要对方公开的公钥。
- **不可否认（non-repudiation）**：因为只有发送方持有私钥，任何人都能向第三方证明「这个签名必然出自发送方」——这是数字签名区别于 MAC 的根本能力，也是电子合同、审计记录、软件发布签名的法律与信任基础。

**为什么签名的是摘要而非整个消息**：消息可能很长，RSA 等算法对输入长度有上限且运算昂贵；先哈希压缩成 256 位摘要，再对摘要签名，效率与安全性兼得。只要哈希安全，对摘要的签名就等价于对整条消息的签名——这就是「哈希 + 签名」组合（如 ECDSA、EdDSA）的标准形态。<span class="marginnote">现代签名算法家族：<strong>RSA-PSS</strong>（概率签名方案）、<strong>ECDSA</strong>（基于椭圆曲线）、<strong>EdDSA/Ed25519</strong>（Edwards 曲线，速度快、实现更不易出错，2026 年 SSH 与 TLS 的推荐选择）。Ed25519 把「恒定时间实现」作为设计目标，规避了一类侧信道问题。</span>

**辨析｜易错点：** 「用私钥加密 = 签名」是流传甚广的误导。RSA 里「私钥运算」在数学形式上看似加密，但语义完全不同：签名不是把消息「藏起来」，而是给摘要「盖私章」；任何人验证时都能读到消息本身。机密性、完整性、认证、不可否认是四个独立目标，分别由加密、哈希/MAC、认证、签名承担——混用是安全设计的常见事故源。

## 4 核心对比：哈希、MAC 与数字签名

三者容易混淆，用一张表把边界划清：

| 维度 | 哈希 | MAC | 数字签名 |
| --- | --- | --- | --- |
| 是否带密钥 | 否 | 对称密钥 | 私钥/公钥 |
| 谁可验证 | 任何人 | 共享密钥双方 | 任何持有公钥者 |
| 证明完整性 | 是 | 是 | 是 |
| 数据源认证 | 否 | 是（对称） | 是（非对称） |
| 不可否认 | 否 | 否（接收方可伪造） | 是 |
| 典型算法 | SHA-256 | HMAC、CMAC | RSA-PSS、ECDSA、Ed25519 |

**重点：三者的关系是「层层加码」——哈希是裸的完整性，MAC 加上对称密钥换来「可信的完整性」，签名再换成非对称密钥，换来「可对第三方证明的完整性」。** 选型取决于威胁模型：单纯检测偶然损坏用哈希；双方共享秘密、防第三方篡改用 MAC；需要法律效力或公开验证用签名。

## 5 公式解析：HMAC 的双层哈希结构

HMAC 是 MAC 最广泛的构造，它的设计意图值得拆开看：

$$
\text{HMAC}(K, M) = H\Big((K' \oplus \text{opad}) \,\|\, H\big((K' \oplus \text{ipad}) \,\|\, M\big)\Big)
$$

- **$K'$**：密钥 $K$ 经补齐/哈希后得到的标准长度密钥。
- **$\text{ipad}$ 与 $\text{opad}$**：两个不同的固定填充常量（内、外填充），分别与 $K'$ 异或，把密钥「揉进」内外两层哈希。
- **内外两层结构**：内层 $H((K' \oplus \text{ipad}) \,\|\, M)$ 把密钥与消息一起哈希，外层再套一次 $H((K' \oplus \text{opad}) \,\|\, \text{inner})$。

**为什么设计成两层**：如果直接用 $H(K \,\|\, M)$，底层哈希一旦有长度扩展弱点（如 MD5/SHA-1 的 Merkle–Damgård 结构），攻击者可以在不知道 $K$ 的情况下拼接延长消息、伪造新 MAC。双层 + 异或填充把密钥从哈希的「输入前缀」变成「结构的一部分」，有效封堵了长度扩展攻击——这是「协议设计」胜过「堆砌原语」的经典一课。

## 6 从原语到系统：三条应用主线

哈希、MAC、签名不是孤立技术，它们撑起了现代安全的三大基础设施：

**软件供应链**：**软件签名**——厂商用私钥对安装包签名，系统校验签名后才执行。一旦签名体系被绕过（如 2015 年 XcodeGhost、各类白签名服务），恶意应用就能披着「正版」外衣。<span class="marginnote">这正是「<strong>校验和 vs 签名</strong>」的现实差别：校验和（哈希）只防「下错文件」，签名才防「下载源本身被劫持」。现代包管理器（npm、pip、apt）与操作系统更新都已强制签名验证。</span>

**区块链与证明**：比特币的「挖矿」就是暴力寻找满足 $H(\text{block}) < \text{target}$ 的 nonce；区块哈希把整条链焊死——改一个交易，其后所有哈希全变。UTXO 的「花费」用 ECDSA 签名证明所有权。

**登录与证书**：口令存储的加盐哈希（上一篇）、TLS 握手的证书签名（后续《PKI》《TLS》两篇）、JWT 的签名（HS256 用 HMAC，RS256 用 RSA 签名）——**每一条安全链路里，哈希、MAC、签名至少出现一次**。

## 7 哈希的安全强度：生日攻击与输出长度

「抗碰撞」不是免费的，它的代价可以用概率算清楚。给定一个输出 $n$ 位的哈希函数，要找一对碰撞，理论上需要尝试多少次？

$$
\text{碰撞所需尝试次数} \approx \sqrt{2^n} = 2^{n/2}
$$

- **$n$**：摘要的位数。SHA-256 的 $n = 256$，SHA-512 的 $n = 512$。
- **$2^{n/2}$**：这就是**生日悖论**——找「任意一对相同」远比找「一个特定目标」便宜。固定目标要找抗原像需 $2^n$ 次，而碰撞只需 $2^{n/2}$ 次。
- **推论**：SHA-256 的抗碰撞强度是 128 位（$2^{128}$），与 AES-128 同级——这也是「256 位哈希 + 128 位对称密钥」在安全强度上匹配的原因。

**重点：哈希的输出长度决定了它的安全层级。** MD5 输出 128 位，碰撞只需 $2^{64}$ 次——2004 年王教授给出实质碰撞，2008 年已能构造恶意证书，从此 MD5 退出安全舞台；SHA-1 输出 160 位，$2^{80}$ 的理论强度也在 2017 年 SHAttered 碰撞中被击穿。**「够长」是哈希选择的第一原则，SHA-256 及以上是 2026 年的底线。**

## 8 小结

- **哈希**：任意长度输入 → 固定长度摘要；三个性质（抗原像、抗第二原像、抗碰撞）；SHA-256/SHA-3 可用，MD5/SHA-1 已破。
- **MAC**：带密钥的完整性 + 对称数据源认证；HMAC 用双层哈希结构封堵长度扩展攻击。
- **数字签名**：私钥签名、公钥验证，提供完整性、认证与**不可否认**；先哈希再签名是标准形态。
- **区别**：哈希裸完整性，MAC 加密钥，签名换非对称密钥 + 可对第三方证明。
- **应用**：软件供应链签名、区块链、口令存储、TLS 证书、JWT——三者贯穿现代安全体系。

在下一节，我们将回答一个悬而未决的问题：签名验证需要「对方的公钥」，但公钥本身怎么可信地属于那个人？这就是**公钥基础设施 PKI 与数字证书**——把密码学原语变成可以信赖的身份体系。
