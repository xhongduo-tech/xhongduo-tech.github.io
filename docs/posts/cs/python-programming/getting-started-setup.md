## 为什么从搭建环境开始

从极限到大模型，这条主线从数学一直延伸到当代 AI，而几乎所有数据工作都绕不开一门「胶水语言」——**Python**。它不追求最快，而追求**可读**：让想法能快速写成、让代码能被别人读懂。本专题将以《Python编程：从入门到实践》（第3版）为主线、以官方 Python 文档为准绳，从环境搭建起步，一路走到面向对象与工程实践。

万事开头难在「开」：先把解释器装好、把第一个程序跑起来，之后的每一节才有可运行的载体。这一节不学语法，只解决三件事——Python 是什么、如何安装与运行、以及用什么工具写代码。

需要提前说明的是：Python 的生态远超语言本身。今天装好的这套环境，将来会被 NumPy 处理矩阵、被 Django 支撑网站、被 PyTorch 训练模型——标准库与第三方包都在同一套解释器上运行。把地基打正，后续所有依赖的安装才不会出错。

## 1 Python 是什么：解释型、多范式的通用语言

**Python（派森）**：1991 年由荷兰人吉多 · 范罗苏姆（Guido van Rossum）发布的一门通用编程语言，名字取自英国喜剧团体 Monty Python，与蛇无关。<span class="marginnote">吉多 1989 年圣诞节期间开始设计 Python，想补足 ABC 语言的缺憾。1994 年发布 1.0，2000 年 2.0，2008 年 3.0 做出不向后兼容的大改动——今天代码里的 `print(...)` 括号、`input` 返回字符串，都是 3.0 的遗产。</span>

Python 是**解释型语言**：程序由解释器（interpreter）一行一行翻译执行，而不是像 C 那样先整体编译成机器码再运行。代价是运行稍慢，收益是开发极快、免去烦琐的编译步骤。

它还是**多范式**的：既支持面向过程，也支持面向对象与函数式；加上一个庞大而统一的**标准库**，因此有「batteries included（自带电池）」的说法。这三者叠加，让 Python 成为**数据科学、Web 后端与自动化脚本**的共同选择，也让它与后续专题里的数值计算、机器学习直接相连。

## 2 安装解释器与验证环境

不同操作系统安装方式不同，但万变不离其宗：装一个 Python 3.x 的官方解释器，并在终端里能敲出版本号。

在终端验证安装：

```bash
python --version    # Python 3.12.4（或更高）
python3 --version   # macOS / Linux 上可能要用 python3
```

**重点：先分清两个词。** `python` 是**解释器**，负责执行 `.py` 文件；代码编辑器或 IDE 只是编辑工具，与解释器是两个东西。<span class="marginnote">macOS 新版已不再自带 `python`；Linux 发行版常同时存在 `python` 与 `python3`。拿不准时用 `python3 --version` 最保险。Windows 用户在安装时应勾选「Add python.exe to PATH」。</span>

若机器上同时存在多个版本，用 `python -m 模块名` 可确保调用当前解释器——这个写法在后面的「虚拟环境与包管理」一节还会反复出现。

## 3 第一个程序：hello_world.py

按《Python编程》第 1 章的流程，新建一个工作目录，在其中新建 `hello_world.py`，写入一行：

```python
print("Hello, Python!")
```

在终端运行：

```bash
python hello_world.py
# Hello, Python!
```

**`print()` 函数**：把括号里的内容输出到终端的内置函数，是 Python 中最常用、也是第一个要记住的名字。<span class="marginnote">《Python编程》第 1 章从 `hello_world.py` 讲起，是要让读者第一分钟就体会到「代码—运行—输出」的闭环。先把这条最短链路跑通，后面排查任何语法错误才有所依托。</span>

除了运行脚本，还可以进入**交互式解释器（REPL）**：在终端敲 `python`，出现 `>>>` 提示符后逐行输入、立即得到结果，适合做小实验与查语法。

```python
>>> 3 + 4
7
>>> "py" * 3
'pypypy'
>>> print("hello")
hello
```

《Python编程》第 1 章还介绍了 **IDLE**——随 Python 一起安装的极简 IDE，自带一个编辑器窗口与交互窗口，零配置即可「打开即写」。刚起步时用它练习绰绰有余；等需要调试、版本管理时再切到 VSCode 或 PyCharm 也不迟——工具的更替不会改变语法本身。

## 4 核心对比表：解释器与编译器的差别

「Python 是解释型语言」这句话值得拆开看。下表把两种执行模型的一次讲清：

| 维度 | 解释型（Python） | 编译型（C 等） |
| --- | --- | --- |
| 执行方式 | 边翻译边执行 | 先整体编译成机器码再执行 |
| 运行产物 | 直接运行 `.py` | 先产出 `.exe`/`.o` 等中间文件 |
| 开发速度 | 快，改一行即可重跑 | 较慢，每次改动需重新编译 |
| 运行速度 | 较慢（有解释开销） | 快 |
| 跨平台 | 装有解释器即可运行 | 通常需按平台分别编译 |

**辨析｜易错点：** 「解释型」只是教学简化。现代 CPython 先把源码编译成字节码（`.pyc`），再由虚拟机执行，类似 Java。这条细节对日常编程无碍，却解释了「为何第二次导入同一模块比第一次快」——字节码被缓存了。

## 5 编辑器选择与 PEP 8

环境搭好后，还要选一个「趁手的工具」。三种选择由简到繁：

**代码编辑器**：VSCode 加 Python 扩展，语法高亮、补全、调试一应俱全，是入门到中级的平衡之选。**集成开发环境（IDE）**：PyCharm，功能全但偏重。**终端文本编辑器**：Vim，灵活但学习曲线陡。<span class="marginnote">选择标准不是「哪个最强」，而是「哪个能让我立刻开始写」。VSCode 或 PyCharm 社区版二选一即可。</span>

无论用哪个工具，风格都要向 **PEP 8** 看齐——Python 官方编码规范，核心约定：缩进用 4 个空格、变量名用小写加下划线、每行不超过 79 字符。风格统一，代码才真正「可读」。

## 6 排查技巧：读懂第一份报错

环境搭建阶段最常见的挫折不是语法，而是「敲了命令没反应 / 报错看不懂」。把高频问题集中解决一次：

| 报错信息 | 含义 | 对策 |
| --- | --- | --- |
| `command not found: python` | 解释器不在 PATH | 改用 `python3`，或重装并勾选 PATH |
| `SyntaxError: invalid syntax` | 语法写错 | 检查冒号、括号、缩进是否齐全 |
| `IndentationError` | 缩进不一致 | 统一用 4 空格，勿混用 Tab |
| `ModuleNotFoundError: pip` | 环境缺 pip | 运行 `python -m ensurepip --upgrade` |

**重点：把报错信息原样搜索，是最快的解法。** 环境问题十有八九是「版本、路径、PATH」三件事之一。用三连查定位：

```bash
python3 --version       # 解释器版本对不对
which python3           # 解释器在哪、是不是预期的那个
echo $PATH              # 命令搜索路径里有没有解释器目录
```

这三条命令能回答「解释器装没装、装在哪、能不能找到」——环境问题到此基本水落石出。剩下的，交给搜索引擎与官方文档（docs.python.org）即可。

## 7 小结

- Python 是**解释型、多范式**的通用语言，1991 年由吉多发布，以可读性为设计目标。
- 先装好 Python 3.x 解释器，用 `python --version` 验证；macOS/Linux 常需 `python3`。
- `print()` 输出内容，`python 文件.py` 运行脚本，REPL 适合做小实验。
- 解释型与编译型在**开发速度与运行速度**之间取舍，Python 选择前者。
- 代码风格遵循 **PEP 8**：4 空格缩进、小写下划线命名、行宽 79。
