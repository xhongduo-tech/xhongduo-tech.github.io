## 为什么从并发构造开始

单核时代，程序「想快」只能靠更快的时钟；多核时代，时钟到头了——赫伯 · 苏特 2005 年那句「免费午餐结束了」宣告：**想快，就得并行**。可并行引入了一个串行世界没有的维度：多个计算同时推进、互相交错、共享数据。程序设计语言必须为此提供构造，这就是 Scott《程序设计语言原理》§12.4 的**并发语言构造（concurrency constructs）**：线程与进程、锁与信号量、管程与条件变量、消息传递与 Actor、事务内存与 async/await。本课是《操作系统》并发章的语言侧镜像，也是大模型时代分布式系统正确性的底层直觉。

## 1 并发与并行：先分清两个词

**并发（concurrency）**：多个计算**在时间上交错推进**——可以只有一个核，靠调度轮流执行；**并行（parallelism）**：多个计算**在同一瞬间同时执行**——需要多个核。并发是「程序结构」问题（如何组织多个活动），并行是「硬件利用」问题（如何让多核同时忙）。一个并发的程序可能跑在单核上，一个并行的系统背后必定需要并发结构。

**辨析｜易错点：** 并发 ≠ 更快。并发解决的是**结构**问题（响应性、I/O 等待期间干别的活），并行才直接买速度；把一段代码「拆成多线程」不保证变快——若线程都在抢同一把锁，反而更慢。**优化者常问的「我这是并发还是并行、瓶颈在锁还是核」就是这个区分的应用。**

## 2 线程与进程：并发的执行单元

**进程（process）**：独立的地址空间、独立的资源，进程间不能直接读对方内存；**线程（thread）**：同一进程内的执行流，**共享**地址空间与堆数据，各自保有程序计数器与栈。语言层面的并发几乎都是线程级（Java `Thread`、Python `threading`、Go `goroutine` 是更轻量的用户态线程）。共享内存让线程间通信廉价，也埋下了**数据竞争（data race）**的雷：两个线程无同步地读-写同一个变量。<span class="marginnote"><strong>GIL（全局解释器锁）</strong>是 Python 的著名特例：CPython 用一把大锁串行化字节码执行，导致 Python 线程无法真并行（计算密集场景），只能靠多进程或协程。语言运行时「线程是不是真并发」，取决于调度模型——这正是《运行时系统》一课的延伸。</span>

## 3 共享内存与同步：锁、信号量、管程

线程共享内存，就必须控制「谁在何时能碰数据」。经典工具族：

**锁 / 互斥量（mutex）**：同一时刻只允许一个线程进入临界区；`lock()` 拿不到就阻塞。原子操作（CAS）是现代锁的底料。
- **信号量（semaphore）**：一个可计数的资源许可；`P` 减一（不够则等）、`V` 加一。互斥量是计数为 1 的特例。
- **管程（monitor）**：把「锁 + 共享数据 + 操作数据的过程」打包成语言构造——Java 的 `synchronized` 方法即管程；配合**条件变量（condition variable）**解决「等某个条件成立」的等待问题（`wait`/`notify`）。

两个经典失败模式必须分清：**死锁（deadlock）**——所有线程都在等别人释放，谁也走不了；**活锁 / 饿死（livelock/starvation）**——有线程一直得不到资源。死锁的四个必要条件（互斥、持有并等待、不可抢占、循环等待）来自《操作系统》，语言层面通过**加锁顺序**、`tryLock` 超时等手段打破它们。<span class="marginnote">「持锁越久、临界区越大，并发越低」是锁编程的基本矛盾：锁保护数据完整，锁本身却成了串行化点。因此现代语言用更细的并发粒度——不可变数据（函数式范式的馈赠）天然无需加锁。</span>

## 4 消息传递：不共享，就不竞争

另一条路线是**不共享内存**：并发单元之间只靠**消息传递**通信。Scott 总结了三种主流形态：

| 机制 | 同步方式 | 代表 |
| --- | --- | --- |
| CSP / 通道 | 发送与接收会合（rendezvous），可缓冲 | Go `chan`、Erlang 邮件 |
| Actor 模型 | 异步投递 + 邮箱，无共享状态 | Erlang/Elixir、Akka |
| 远程过程调用 | 同步请求-应答，跨进程/机器 | gRPC、分布式系统 |

**重点：** 消息传递的卖点是把「共享可变状态」整个拿掉——**没有共享就没有数据竞争**，这正呼应《函数式语言范式》的「状态越少越安全」。Go 的 `goroutine + channel` 让「不要通过共享内存来通信，要通过通信来共享内存」成为一句口号；Erlang 的 Actor 把「进程」做成轻量、可崩溃重启的单元，支撑了电信级的高可用系统。<span class="marginnote">大模型时代的分布式训练与推理（数据并行、张量并行）本质上也是「消息传递」：各卡持有模型分片、靠通信协议交换梯度。理解「同步点在哪、带宽花在哪」的能力，源头就是本课讲的会合与通道语义。</span>

## 5 现代抽象：事务、future 与 async/await

锁与通道之上，语言又长出了一层更舒服的抽象：

- **事务内存（transactional memory, STM）**：把「对共享数据的若干操作」声明为事务，提交时若发生冲突则自动回滚重试——「锁」被替换成「乐观并发控制」，如 Clojure、Haskell 的 STM。
- **future / promise**：一个「尚未计算出来、将来会有的值」——`future` 让耗时计算异步进行，调用方在需要时 `get`。
- **async/await**：把「异步 + 回调」重写成像同步一样的顺序代码——`await` 暂停当前协程而不阻塞线程。Rust、JS、Python、C# 全面采纳，是 I/O 密集型应用（包括 LLM 服务的请求调度）的标配。

这些抽象的共同方向：**把「并发」从程序员手写的调度细节，收编进语言与运行时的类型与语义**——正如类型系统把错误提前到编译期，async/await 把「谁等谁」的表达力交给语言。

## 6 公式解析：竞态条件的一次时间线

并发没有数值公式，却有一条必须解剖的「时序公式」——经典的计数器竞态。设两个线程对共享 `x = 0` 各执行一次 `x = x + 1`，期望结果 $2$：

$$
\begin{aligned}
\text{线程 1}:\;& \text{load } x\;(0) \quad \text{add } 1 \quad \text{store } x\;(1) \\
\text{线程 2}:\;& \text{load } x\;(0) \quad \text{add } 1 \quad \text{store } x\;(1) \\
\text{交错}:\;& \text{load}_1\;(0) \quad \text{load}_2\;(0) \quad \text{store}_1\;(1) \quad \text{store}_2\;(1) \quad \Rightarrow x = 1
\end{aligned}
$$

- **三个原子动作**：`x = x + 1` 在机器层面拆成 load、add、store——**高级语言的一行不是原子的**。
- **期望值 $2$ 的前提**：两次操作必须**串行**——一次完整做完再做下一次。
- **交错导致丢更新**：两个线程都 load 到 0，各自算出 1，先后 store，最终只有 1——**一次更新被悄悄覆盖**，这就是竞态条件（race condition）的最小样本。
- **解药在「原子性」**：把 load-add-store 包进同一临界区（锁）或原子指令（`fetch_add`），交错便不再发生。**竞态的本质不是「并发」，而是「并发下的非原子读-改-写」**——这也是后续一切同步工具要解决的问题。

## 7 小结

- **并发**是结构（交错推进），**并行**是硬件利用（同时执行），二者别混。
- **进程**隔离地址空间，**线程**共享内存；共享内存带来廉价通信，也带来**数据竞争**。
- 同步工具有**锁、信号量、管程、条件变量**；失败模式有**死锁、活锁、饿死**。
- **消息传递**（CSP/Actor/通道）以「不共享」换取「无竞争」，是大规模并发的正统路线。
- 现代抽象（**STM、future、async/await**）把并发细节收编进语言语义，呼应类型系统「把错误前移」的精神。
- 竞态的最小模型是「非原子的读-改-写被交错」，解药是原子性。
