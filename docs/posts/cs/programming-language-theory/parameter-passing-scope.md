## 为什么从参数与作用域开始

类型系统管「项怎么归类」，语义管「项怎么求值」——可真实程序大量活动围绕一个主题：**名字**。变量名、函数名、参数名在哪里有效、绑定到什么、何时释放，直接决定了程序的行为。本课讲 Scott《程序设计语言原理》§3.4 的核心：**作用域（scope）**——一个名字在程序文本的哪些区域有定义；**绑定（binding）**——名字到实体（值/位置/函数）的关联；以及**参数传递**——实参以什么方式进入被调函数。这四块决定了函数调用的全部语义，也是理解闭包、运行时栈（《运行时系统》一课）的前提。

## 1 作用域：静态还是动态

**静态作用域（static/lexical scoping）**：一个名字的绑定，由**程序文本的嵌套结构**决定——函数定义在哪里，它就能看到哪里的外层变量。C、Java、Python、几乎所有主流语言都如此。**动态作用域（dynamic scoping）**：绑定由**调用链**决定——调用者当时的环境就是被调者看到的环境。

```text
x = 1
def f(): return x        # 静态：此处 x 是模块层，值为 1
def g():
    x = 2
    return f()           # 动态作用域下，f 里会看到这个 x，返回 2
```

静态作用域下 $g()$ 返回 1；动态作用域下返回 2。<span class="marginnote">早期 Lisp（1960 年代的原始 Lisp）用动态作用域，调试极其混乱——一个函数的行为取决于「谁调用了它」，同一函数换个调用方结果不同。Scheme、Common Lisp 后来都转向词法作用域。今天的动态作用域几乎只存在于旧语言、shell 的某些变量与异常处理器的隐式环境里。</span>**静态作用域胜出的根本原因：可预测性**——函数行为只由文本决定，因而可以读代码推断、可以做类型检查、可以编译期优化。**辨析｜易错点：** 不要混淆「动态作用域」与「运行时绑定」：多态里 `virtual` 方法的实现在运行时按对象类型选择，但方法的\*名字解析\*仍是静态的；动态作用域改变的是「$x$ 指哪个 $x$」，而不是「调用哪个方法」。

## 2 环境与存储：绑定发生在哪里

绑定要落到机器上，需要两个概念分开：

**环境（environment）**：名字 → 值的映射，随作用域嵌套而变化。
- **存储（store / memory）**：内存单元的集合，随程序运行而变化。

环境是「看见什么」的编译期概念，存储是「存着什么」的运行时概念；两者通过**引用（reference / 地址）**相连——名字绑定到一个引用，引用指向存储中的单元<span class="marginnote">这解释了 Python 的一个经典困惑：`a = []`；`b = a`；`b.append(1)` 后 `a` 也变了——因为 `a`、`b` 这两个名字绑定到同一个引用。可变对象通过引用共享，是「环境-存储分离」的日常体现。</span>。**绑定时间（binding time）**则是另一把尺：语言设计时、编译时、链接时、加载时、运行时逐层发生——「什么时候确定 $T$ 的类型、$T$ 的地址」，每一层的决定都会固化一部分灵活性。

## 3 参数传递的七种模式

参数传递规定实参如何「交」给形参。主要模式如下（Scott 称之为 parameter passing modes）：

| 模式 | 传什么 | 效果 | 代表语言 |
| --- | --- | --- | --- |
| 传值 by-value | 实参的值拷入形参 | 形参是副本，改形参不影响实参 | C、Java（基本类型） |
| 传引用 by-reference | 实参的地址 | 形参即实参的别名，修改立即回传 | C++ `&`、Fortran |
| 传结果 by-result | 形参副本，返回时拷回实参 | 仅在返回时回写 | Ada `out` |
| 传值-结果 by-value-result | 拷入 + 返回时拷回 | 调用期内无别名效应 | Ada `in out` 的旧实现 |
| 传常量 by-constant | 传值但禁止修改 | 防篡改 + 可共享大对象 | C++ `const &` |
| 传名 by-name | 未求值的实参表达式（按需重算） | 惰性、可能多次求值或零次 | Algol 60 |
| 传需求 by-need | 未求值但缓存结果 | 惰性且至多一次 | Haskell 纯函数 |

**传名（call-by-name）**是最有意思的一种：实参表达式原样传入，**每次用到形参都重新求值**，若形参从未被用则实参一次也不求值——这正是上一课「按名调用」的实参版本，也孕育了 Haskell 的惰性求值。**传值-结果与传引用**的区别很微妙：传引用下，若实参是某全局数组的一个下标元素且函数内改了下标，别名效应会改变被写的单元；传值-结果则固定写回「进入时记住的那个单元」。<span class="marginnote">1970 年代关于 Fortran 是否该用传引用的争论催生了 Wirth 与众多语言设计者对别名（aliasing）的警惕：两个形参指向同一对象时，先后赋值会出现「最后写者获胜」等反直觉行为。传值-结果正是为了削减这种别名灾难。</span>

## 4 公式解析：参数传递没有公式，但有严格规则

本课主题是语义性的，没有数值公式，却有一条「判定一条语言规则对不对」的准则——**别名测试（alias test）**。设函数修改形参 $x$ 并读取形参 $y$，判断下述程序段的行为：

$$\text{call } g(\texttt{a[i]},\, \texttt{a[j]}) \text{ 且 } g \text{ 内执行 } x := x + 1 \text{ 并读 } y$$

- **传值**：$x$ 是 `a[i]` 的副本，写 $x$ 不影响 `a`；再读 $y$ 读到的是进入时 `a[j]` 的副本——**先读后写，互相独立**。
- **传引用**：$x$ 与 `a[i]` 是同一个存储单元。若 $i = j$，则 `a[i]` 与 `a[j]` 是同一单元，写 $x$ 后再读 $y$ 读到的是**改写后的新值**——结果随 $i, j$ 是否相等而变。
- **传值-结果**：$x$ 是副本，返回时把副本写回进入时的单元；若 $i = j$，最终写回的是「最后一次拷贝」，中间读 $y$ 仍是副本——**别名效应被局部化到返回时刻**。

这条测试揭示了教材用「是否允许别名、别名何时生效」来刻画传递模式的道理：**模式的差异，本质上是对「实参与形参是否共享存储、共享多久」的承诺差异**。

## 5 闭包：作用域的运行时化身

静态作用域在运行时需要可执行的支持：函数返回后，它的自由变量可能仍被引用。**闭包（closure）**= 函数代码 + 定义它的环境（对自由变量的捕获）。现代语言里 `lambda`、Python 内嵌函数、JS 箭头函数返回的都是闭包。实现上，嵌套函数访问外层变量常用**静态链（static link / access link）**——每个活动记录里存一个指向「词法外一层活动记录」的指针，或用一个**显示表（display）**数组按词法深度索引<span class="marginnote">静态链按词法嵌套深度一层层找外层变量，显示表则直接按深度数组索引、更快但复制更贵。二者都是编译原理中活动记录（activation record）布局的经典内容，也是《编译原理》专题会详细展开的实现细节。</span>。闭包是「作用域是可计算对象」的证明：既然环境可以被捕获、被传递、被闭包永久持有，名字解析就不再只是编译期的事——它在运行时获得了实体。

## 6 小结

- **作用域**决定名字在哪些文本区域有效：静态作用域看嵌套结构（主流），动态作用域看调用链（旧 Lisp）。
- **环境**（名字→值）与**存储**（内存单元）分离；引用把两者接起来，也是别名与 Python 共享语义的根源。
- 参数传递模式众多：**传值、传引用、传结果、传值-结果、传常量、传名、传需求**，差异在于别名承诺与求值时机。
- **别名测试**是判定模式行为的标准方法：同一函数在不同模式下对同一实参结果不同。
- **闭包** = 函数 + 捕获的环境，是静态作用域的运行时实体，由静态链/显示表实现。
