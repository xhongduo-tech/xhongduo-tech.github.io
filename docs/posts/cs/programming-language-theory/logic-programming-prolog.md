## 为什么从逻辑编程开始

函数式把「计算 = 求值」推到极致，逻辑编程则把「计算」整个换掉：**计算 = 逻辑推导**。你不再写「怎么做」（算法），只写「什么是真的」（逻辑），剩下交给系统去推理。这个范式的代表是 **Prolog**（Programming in Logic），科瓦尔斯基用一句话总结它的哲学——**算法 = 逻辑 + 控制**：逻辑部分描述问题的知识，控制部分（搜索顺序）由解释器决定。Scott《程序设计语言原理》§11 讲它的核心：**事实、规则、查询，加上统一化与回溯**。它一度是自然语言处理、专家系统、定理证明的主流工具，也是今天「声明式」思想（SQL、逻辑求解器）的理论源头。

## 1 程序 = 事实 + 规则 + 查询

Prolog 程序是**子句（clause）**的集合，子句只有三类角色：

- **事实（fact）**：无条件成立的断言，如 `parent(zhang, ming).`（张是明的父母）。
- **规则（rule）**：带条件的断言，形如「头 :- 体」，如 `ancestor(X, Z) :- parent(X, Z).` 与 `ancestor(X, Z) :- parent(X, Y), ancestor(Y, Z).`——读作「如果……那么……」，其中 `X`、`Z` 是大写开头的**变量**，小写的是**常量**。
- **查询（query）**：问系统「什么成立」，如 `?- ancestor(zhang, Z).`，系统回答「Z = ming」。

**重点：** 程序不再描述「如何做」，而是描述「哪些关系成立」——执行就是问「这些关系在什么取值下成立」。规则里的「,」是逻辑与（conjunction），同一条规则的所有体子目标必须都满足；不同子句之间是「或」——多个 clause 是备选方案，这正是回溯的根源。<span class="marginnote">Prolog 的子句全是 <strong>Horn 子句</strong>（至多一个肯定文字的子句）：要么是事实（纯肯定），要么是「结论 ← 一组前提」。Horn 子句是逻辑编程能高效搜索的关键限制——它让推导规则可以机械执行，代价是表达能力受限（不能写任意一阶公式，否定尤其麻烦，见 §4）。</span>

## 2 统一化与回溯：计算的引擎

Prolog 的执行机制只有两个动作：

**统一化（unification）**：让查询目标与某个子句的头部**匹配**——就是《类型推导》里那个统一化算法的运行时版本。若匹配失败就试下一条子句；若成功则把子句体加入待证目标。
- **回溯（backtracking）**：按**深度优先、从左到右**的顺序搜索；某条路径失败时，回到最近一个「还有别选项」的分叉点，试下一条。

以查询 `?- ancestor(zhang, ming).` 为例：第一条规则直接问 `parent(zhang, ming)`——事实匹配成功，答案 `true`。若问 `?- ancestor(zhang, sun)`，第一条规则失败，回溯到第二条：先证 `parent(zhang, Y)`，匹配到 `parent(zhang, ming)` 得 `Y = ming`；再证 `ancestor(ming, sun)`，递归下去。**重点：** 每一次 `Y` 的取值绑定都来自统一化，搜索树上的「分支」来自「或」——**回溯就是在这个或树上做深度优先遍历**。<span class="marginnote">现代 Prolog 编译器（如 SWI-Prolog）用「<strong>last-call optimization</strong>」把尾位置的递归改写成迭代，使深度优先搜索不爆栈；但 <strong>left-recursion 会死循环</strong>——`ancestor(X,Z) :- ancestor(X,Y), parent(Y,Z).` 放在第一条会无限展开自己。程序员的「控制」知识（子句顺序、目标顺序）在此刻决定成败，这正是「逻辑 + 控制」中控制的分量。</span>

## 3 列表与递归：Prolog 的数据库结构

Prolog 的列表写作 `[1, 2, 3]`，可拆成头尾 `[H | T]`。递归处理列表是 Prolog 的标准姿势，例如「判断 X 是否属于列表」：

```prolog
member(X, [X | _]).
member(X, [_ | T]) :- member(X, T).
```

**关键洞察：** `member` 不需要「返回布尔」——它靠**变量绑定**给出答案。查询 `?- member(2, [1, 2, 3]).` 得 `true`；查询 `?- member(X, [1, 2, 3]).` 系统会依次回答 `X = 1`、`X = 2`、`X = 3`——**同一个谓词既当「测试」又当「生成器」**，方向完全由查询决定。这是逻辑编程最迷人的特性：程序描述关系，而关系的每个参数都可进可出，一个定义服务多种用途。列表拼接 `append` 同理：`append(X, Y, [1, 2])` 会让系统枚举出所有拆法，包括「X = [], Y = [1,2]」等三种——这是 Prolog 教程里最著名的「倒过来用」范例。<span class="marginnote">「一个谓词多种用途」源于纯逻辑的对称性——关系 $R(x,y)$ 本是双向的。它让 Prolog 程序格外适合「规格即实现」：声明了关系，就自动得到正向求值、反向生成、约束求解等全套用法。这也是逻辑编程在搜索、规划、语法分析（DCG）等场景难以被替代的原因。</span>

## 4 cut 与否定即失败：逻辑的裂缝

Prolog 里有两样东西**打破了纯逻辑**，理解它们是入门到进阶的分水岭：

**cut（`!`）**：割断搜索树——一旦执行到 `!`，就**提交**当前选择、放弃其它分支。它能让搜索更快，但**非逻辑**：同样的知识，加 `!` 前后行为不同，声明式读法被破坏。<span class="marginnote">`!` 是「控制」凌驾「逻辑」的典型：纯逻辑无法表达「别搜了」，工程上却非要这种剪枝。因此 Prolog 的谓词常写成「逻辑版本 + 加了剪枝的效率版本」，把「知识与策略」分开维护。</span>
- **否定即失败（negation as failure）**：`not(P)` 意味着「P 推导不出来」——在**封闭世界假设**（没被证明为真的就是假的）下成立。但它**不是经典逻辑的否定**：若知识库不完整，`not(P)` 可能误判。`\+ member(apple, fruits)` 在 `fruits` 没列出苹果时返回 `true`，哪怕世界上确实有苹果——系统只能说「我推不出来」，却声称「不成立」。

**辨析｜易错点：** 忘记 **occur check** 是 Prolog 初学者的经典陷阱：`?- X = f(X).` 多数 Prolog 直接成功（把 X 绑成无穷项），而逻辑上它应失败；标准 Prolog 为速度默认省略 occur check，只有显式 `unify_with_occurs_check/2` 才检查——这和《类型推导》里统一化必须防无穷类型恰好互为镜像：类型系统防的是「类型无限展开」，Prolog 防的是「项无限嵌套」，机制同源、取舍相反。

## 5 公式解析：SLD 归结的一步

归结（resolution）是 Prolog 的证明规则。设当前要证的子目标列表是 $(G_1, \dots, G_k)$，程序里有一条头部能与之统一的子句 $H \leftarrow B_1, \dots, B_m$，且统一化给出置换 $\theta$，那么一步 SLD 归结为：

$$
\frac{(G_1, \dots, G_i, \dots, G_k) \quad (H \leftarrow B_1, \dots, B_m) \quad \text{mgu}(G_i, H) = \theta}{(G_1, \dots, B_1, \dots, B_m, \dots, G_k)\,\theta}
$$

- **分子左半 $(G_1, \dots, G_i, \dots, G_k)$**：当前待证明目标列，选一个 $G_i$ 来攻击（Prolog 选最左边的）。
- **分子右半 $H \leftarrow B_1, \dots, B_m$**：程序里挑一条头部与 $G_i$ 统一的规则（或事实，$m = 0$）。
- **统一化 $\theta$**：$G_i$ 与 $H$ 的最一般合一子——名字、结构全部对齐后的置换，它把答案的变量绑定起来。
- **结论**：$G_i$ 被**替换**成该规则的前提 $B_1, \dots, B_m$，且整个目标列套上 $\theta$。目标列为空时，当前 $\theta$ 的所有变量绑定就是查询的答案。
- **直觉**：SLD 归结就是「要证 $G_i$，找一个能推出它的规则，把前提换成新的子目标」——**不断把目标替换成更基本的目标，直到全部落在事实里**，这条证明路径反过来就是求解路径。

## 6 小结

- 逻辑编程把**计算 = 逻辑推导**：程序 = 事实 + 规则（Horn 子句）+ 查询，执行即回答「哪些取值使查询成立」。
- 执行引擎 = **统一化 + 深度优先回溯**；回溯在「或」分支上遍历，变量绑定即答案。
- 列表与递归让同一谓词**可测可生成**，`append` 的三种用法是「关系双向性」的招牌。
- **cut**（剪枝）与**否定即失败**（封闭世界假设）是非逻辑扩展，使用时必须清楚其语义。
- 逻辑编程是声明式的极致——「逻辑 + 控制」的分工，也是 SQL、约束求解等现代声明式技术的理论源头。
