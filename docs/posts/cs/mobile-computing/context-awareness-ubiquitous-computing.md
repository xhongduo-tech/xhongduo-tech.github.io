## 为什么从上下文感知讲起

前面几篇解决的是「移动设备怎么连上网、传数据、断线续命」——这些是移动计算的**底层能力**。但移动计算的最终价值不在通信，而在**应用如何变得更聪明**：手机知道你正在开车就自动切换免打扰，音乐 App 知道你在健身房就自动放节奏感强的歌，地图知道你进了商场就自动切换到室内楼层。<span class="marginnote">这些体验的共同点，是系统利用了「上下文」——设备状态之外、关于使用者与环境的动态信息。从「你输入什么我做什么」到「我感知你的处境并主动服务」，是移动计算从工具走向智能体的关键一跃，也是今天大模型 Agent 与「环境感知」思想的直接前身。注意，这种「主动」必须克制：系统的每一次主动行为，都在消耗用户的信任，误判一次推送就可能让用户永久关闭通知权限。</span>这一篇讲清上下文感知的理论骨架与普适计算的整体愿景。

## 1 普适计算：技术从视野中消失

1991 年，施乐 PARC 的马克·维瑟发表了划时代的论文《The Computer for the 21st Century》，提出**普适计算（ubiquitous / pervasive computing）**的愿景：计算机不再是桌面上的一个盒子，而是**嵌入环境、无处不在、彼此协作**——你与之交互时甚至意识不到它们的存在。<span class="marginnote">维瑟用「消失（disappear）」来描述终极形态：技术好用到底，就退到注意力之外——就像你写字时不会去注意笔。这个「消失」的标准，是衡量普适计算成熟度的最高标尺。</span>

普适计算对应三条技术主线：

**设备微型化与嵌入**：传感器、可穿戴、智能家居把算力撒进环境。
**网络无处不在**：无线连接让这些设备随时协作——前几篇的所有无线技术都是它的「血管」。
**感知与自适应**：设备感知环境并主动调整——这就是**上下文感知（context awareness）**。

维瑟还在论文里预见了三种设备形态：**tab**（英寸级，随身携带，如今天的手环）、**pad**（平板级，随手可取，如平板）、**board**（米级，共享墙面，如智能白板）。三十多年后回看，智能手机正是「tab 的加强版」，平板、智能音箱、智能家居面板分别对应后两者——**普适计算的硬件预言几乎全部应验，缺的只是软件层的智能协作**。

一句话：**普适计算是愿景，上下文感知是让愿景落地的核心机制**。

## 2 什么是「上下文」

**上下文（context）**的经典定义来自 Schilit 与 Theimer（1994）：**任何可用于刻画一个实体（人、地点或对象）处境的信息**。更实用的说法是：上下文回答四类问题——**我在哪、和谁在一起、现在有什么资源、附近正在发生什么**。

按来源与稳定性，上下文可分类为：

| 上下文类型 | 例子 | 变化速度 |
| --- | --- | --- |
| 位置上下文 | GPS 坐标、楼层、室内外 | 快 |
| 时间上下文 | 时刻、星期几、节假日 | 慢 |
| 身份上下文 | 用户身份、设备 ID、关系 | 极慢 |
| 活动上下文 | 走路、开车、开会、睡眠 | 中 |
| 环境上下文 | 温度、光照、噪声、网络带宽 | 中快 |

**辨析｜易错点：** 位置是最常见、最容易被误认为「唯一」的上下文。但只有位置的上下文系统是「傻定位」——**真正有用的上下文要组合**：位置 + 时间 + 活动，才能推断「用户在通勤路上」并主动推送通勤信息。单一维度上下文，价值十分有限。<span class="marginnote">上下文是「低层数据」的合成品：GPS 坐标只是原始数据，经推断（结合地图、速度、历史）才成为「在开车」这个上下文。区分「原始传感器数据」与「派生的上下文」，是理解上下文系统的第一课。</span>

## 3 上下文感知的计算模型

**上下文感知（context-aware）**指系统能**获取上下文、据此调整行为、并把结果反馈给用户**。Dey 提出了经典的三层模型：

**表示层（representation）**：用什么数据结构表达上下文——通常是「类型-值-时间戳-置信度」的四元组。
**获取层（acquisition）**：从传感器、系统日志、用户输入、网络信息中采集原始数据。
**应用层（application）**：把上下文映射为行为——触发规则、调整界面、调度资源。

三个层次之间还需要一层**上下文解释（interpretation）**：把原始数据加工成语义上下文。例如「GPS 坐标序列 + 速度 > 5 m/s」→「正在移动」，再加「时间 = 早高峰」→「在通勤」。<span class="marginnote">这套「数据 → 解释 → 语义 → 行为」的流水线，与感知机、今天多模态大模型里「信号 → 特征 → 语义」的处理链条高度同构。上下文系统做的是轻量级的「机器理解」，只是没有学习海量参数而已。</span>

在应用层，上下文驱动的行为常用**ECA 规则（事件-条件-动作）**表达：**当「事件」发生且「条件」满足时，执行「动作」**。例如：事件=检测到驾车，条件=当前时间在工作日早高峰，动作=自动开启勿扰并朗读消息。ECA 规则把「上下文 → 行为」映射变成可配置、可审计的声明式逻辑，是上下文系统最常用的行为模型——它也是「规则引擎」这一软件思想在移动端的直接应用。

## 4 上下文获取：传感器与推理

获取上下文的手段五花八门，按「直接程度」可分为：

**物理传感器**：GPS、加速度计、陀螺仪、光线/温度/湿度传感器——直接测物理量，数据最原始。
**虚拟传感器**：从软件状态提取——日历里有没有会、蓝牙连了哪个设备、Wi-Fi 在哪个 AP、当前 App 是什么。
**逻辑传感器**：多个源融合推理——例如用「Wi-Fi 指纹 + 蓝牙信标 + 气压计」共同推断室内位置。

多源融合常面临矛盾：两个传感器给出冲突的结论怎么办？工程上常用**加权投票或加权平均**，用置信度分配权重——这正好是一条值得拆解的式子。<span class="marginnote">传感器的选择还受<strong>能耗</strong>约束：GPS 每秒一次功耗极高，加速度计则便宜得多。所以真实系统用「低功耗传感器触发、高功耗传感器确认」的级联策略——先检测到「在移动」再开 GPS。省电设计又一次决定架构。</span>

另一个实用原则是**分层触发**：先用电荷最小的传感器（加速度计、Wi-Fi 扫描）做粗判断，只有粗判断命中才唤醒昂贵的传感器（GPS、麦克风）。这套「从便宜到昂贵、从粗到细」的探测顺序，既省电又省算力，是上下文系统在真实设备上能长期运行的关键。

## 5 公式解析：多源上下文的加权融合

当多个来源给出对同一上下文的判断时，最简单有效的合并方式是**置信度加权平均**：

$$\hat{c} = \frac{\sum_{i=1}^{n} w_i \cdot c_i}{\sum_{i=1}^{n} w_i}$$

- **第一步，认清符号**：$c_i$ 是第 $i$ 个来源给出的上下文取值（如「温度 = 25℃」「置信度 = 0.8」），$w_i$ 是第 $i$ 个来源的权重，$\hat{c}$ 是融合后的估计值。
- **第二步，权重从哪来**：权重 $w_i$ 通常取该来源的**历史准确度**或**实时置信度**——GPS 在开阔地权重高、在地下室权重低；加速度计检测「移动」可靠时权重高。
- **第三步，看极端情形**：若某个来源权重为 0（该传感器失效），融合结果自动忽略它；若所有来源一致，$\hat{c}$ 就是公共值——**加权平均天然具备「容错」与「向高可信源倾斜」两种能力**。
- **第四步，直觉**：这条式子本质是**证据的民主表决，但每票按质量加权**——它与集成学习里「加权多数投票」、贝叶斯估计里「按精度加权」是同一个思想在上下文系统的落地。**多源融合的价值，不在算法多深，而在「如何设计权重」**。

**辨析｜易错点：** 加权平均对**系统性偏差**无能为力——如果 GPS 在某个区域整体偏北 50 米，权重再高也纠正不了偏移。因此融合算法之上通常还要叠加**校准（calibration）**与**异常检测**，先清洗单个源的系统误差，再做加权。

## 6 上下文感知应用与隐私困境

上下文感知的典型应用已经深入日常生活：

- **场景自适应**：手机按「驾车/会议/睡眠」自动切换勿扰、音量与亮屏策略。
- **主动通知**：天气变化、航班延误、到站提醒——系统「知道你在哪、要干嘛」才推送。
- **资源自适应**：根据「正在播放视频」自动提高屏幕亮度与网络优先级，根据「低电量+离线」自动降级画质。
- **智能家居**：回家前自动开空调，依据的是「位置 + 通勤时间 + 室温」的联合上下文。<span class="marginnote">这些应用的本质是把「用户意图」从行为数据里推断出来。推断得越准，服务越好；但推断需要的数据越多，隐私风险越大——<strong>上下文感知的每一分智能，都建立在多一分数据暴露之上</strong>，这是它的原罪。</span>

**隐私是上下文感知的阿喀琉斯之踵**：系统知道你何时离家、去过哪里、见过谁、几点睡——这既是便利的来源，也是监视的温床。工程上的缓解手段包括：**上下文本地化处理**（不上云）、**最小化采集**（只取必要维度）、**差分隐私**与**用户可撤销授权**。技术能解决「能不能知道」，但「该不该知道」需要制度与伦理共同回答。

一个完整的上下文感知系统，把以上各环节串成一条链：**传感器采集 → 数据清洗 → 上下文推理 → 规则匹配 → 行为执行 → 反馈与学习**。链路任一环出错（传感器故障、推理误判、规则过期），最终体验都会打折——所以真实系统非常看重**置信度度量**：每条上下文都带着「我有多确信」的分数，行为执行时低于阈值的推断宁可不触发。**宁可少做，不可错做**，是上下文系统工程的第一原则。

## 7 易错辨析：上下文感知理解的三个误区

**辨析｜易错点：** 集中澄清三个高频误解。

- **「上下文感知 = 基于位置的推送」**：位置只是最常用的一种上下文。真正的上下文系统要组合位置、时间、活动、环境与身份，做**语义推断**，而不是简单「到了某地发个广告」。
- **「上下文越多越好」**：不是。上下文质量取决于**相关性、时效性与准确性**，而不是数量。采集一堆过期、冲突、无关的数据，只会增加噪声与隐私风险。
- **「普适计算已经实现」**：雏形遍地（智能家居、可穿戴），但「技术从视野中消失」的终极形态远未达成——今天的智能设备依然要求人主动学习、主动配置，维瑟的理想仍是持续逼近的目标而非现实。

## 8 小结

- 普适计算是「技术嵌入环境、从视野中消失」的愿景；上下文感知是它落地的核心机制。
- 维瑟预见的 tab/pad/board 三种设备形态已被智能手机、平板与智能家居逐一印证。
- 上下文是「可刻画实体处境的信息」，要回答我在哪、和谁在一起、有何资源、发生何事。
- Dey 三层模型：表示、获取、应用；外加一层「原始数据 → 语义」的解释流水线。
- 上下文驱动行为常用 ECA 规则（事件-条件-动作）表达，可配置、可审计。
- 传感器分物理/虚拟/逻辑三类；多源融合用置信度加权平均 $\hat{c} = \frac{\sum w_i c_i}{\sum w_i}$
