## 为什么从移动 IP 讲起

蜂窝网络解决了「无线电怎么连」，蓝牙解决了「个人设备怎么连」，但都还没解决一个更抽象的问题：**一台设备在移动中换了网络，互联网怎么还能找到它？** 有线互联网里，IP 地址既是「你是谁」（身份），又是「你在哪」（位置）——两个语义绑在一起。人一动，位置变了，可 TCP 连接和所有指向这台设备的流量都还认着旧地址。<span class="marginnote">这正是「身份与位置分离」问题的由来：它不只是移动 IP 的出发点，也是今天 SDN、标识网络、6G 网络架构都在反复求解的问题。移动 IP 是这个问题第一个被广泛接受的工程答案。</span>这一篇从 IP 寻址的固有缺陷讲起，把移动 IP 的机制、代价与演进讲透。

## 1 IP 寻址的移动困境

在标准 TCP/IP 里，IP 地址的双重语义带来了移动性的根本障碍：

**身份语义**：地址是主机在网络中的唯一标识，TCP 连接、路由表、防火墙规则都依赖它。
**位置语义**：地址同时也编码了「这个主机挂在哪个网络」——前缀相同的地址在同一个网段内。

主机一旦移动到新网络，它的地址前缀与位置不再匹配，路由将无法送达。<span class="marginnote">换个角度理解：如果强行让移动主机保留旧地址，那么它所在的新网络必须「假装」旧网络存在——要么全网路由表为它更新（路由爆炸），要么有中间人代为转发。移动 IP 选了后者。</span>这个问题在链路层无解，因为 IP 层的「可路由性」要求地址前缀与拓扑一致；在移动的环境里，唯一的出路是**让地址的「身份」与「位置」解耦**。

## 2 移动 IP 的基本架构

移动 IP（Mobile IP，RFC 5944 等）用三组角色实现「身份与位置分离」：

**移动节点（MN）**：正在移动的主机，拥有一个固定的**家乡地址（HoA）**——这是它的「身份」，永远不变。
**家乡代理（HA）**：位于移动节点家乡网络的路由器，负责在移动节点离开时「代收」发往它家乡地址的数据包，再转发出去。
**外部代理（FA）**：位于移动节点当前所在外地网络的路由器，负责向移动节点分配**转交地址（CoA）**并接收家乡代理转来的隧道包。<span class="marginnote">转交地址 CoA 是移动节点在「外地」临时获得的可路由地址——它代表「位置」，可以随时变化。于是地址拆成了两层：家乡地址答「你是谁」，转交地址答「你现在在哪」。这个二元的层次结构，是整篇的灵魂。</span>

核心思想一句话：**家乡地址永远不变，移动节点每到一处用 CoA 向家乡代理登记当前位置；家乡代理把发给 HoA 的包用隧道转发到 CoA。**

CoA 有两种存在形式，值得分清：

**外部代理 CoA（FA-CoA）**：CoA 是外部代理自己的地址，隧道终点是 FA，由 FA 再通过链路层转给移动节点——移动节点不额外占一个 IP，适合大规模共享。
**共址 CoA（co-located CoA）**：移动节点自己从外地网络申请一个临时 IP 作为 CoA，隧道直接打到自己——无需外部代理，但要求移动节点拥有完整 IP 栈与移动 IP 实现。

**两种 CoA 的取舍是「少占地址、多依赖网络」还是「多占地址、少依赖网络」**，也是移动 IP 部署时的第一个分叉口。

## 3 工作流程：发现、注册、隧道

移动 IP 的数据流分四个阶段：

1. **代理发现（Agent Discovery）**：移动节点通过 ICMP 路由通告判断自己是否离开了家乡网络。在本地，直接走正常 IP 路由；在外地，得到外部代理的 CoA。
2. **注册（Registration）**：移动节点把「家乡地址 + 当前 CoA」的绑定发给家乡代理，家乡代理记录到绑定表。这相当于向家乡「报个平安，告诉它我搬到哪里了」。
3. **隧道转发（Tunneling）**：通信对端（CN）把数据包发往家乡地址；家乡代理截获后，用 **IP-in-IP 隧道**把原包封装进新包，目的地写 CoA，送到移动节点。
4. **解封装（Decapsulation）**：移动节点（或外部代理）剥掉外层包头，还原原始数据包。

**移动节点发出的数据**则走普通 IP 路由直达通信对端——因为数据包从当前网络发出，源地址用 CoA，接收方直接回给这个地址即可。<span class="marginnote">注意这个不对称：<strong>发出去走直路，收进来绕家乡</strong>。正是这种不对称造成了下一节要讲的「三角路由」问题——而发送方向也可以用反向隧道统一走家乡，代价是更大的延迟。</span>

注册是移动 IP 的「心跳」：注册消息里携带家乡地址、CoA 与**生存期（lifetime）**，家乡代理每次收到都刷新绑定表；生存期耗尽而未续约，绑定即失效。这套「定时续约」机制让绑定状态有明确的生命周期，异常掉线时状态会自动过期回收——与 ARP 缓存、DHCP 租约是同一种「软状态（soft state）」思想：**与其精确检测故障，不如让状态自己过期**。

注册的安全性同样不可忽略：绑定表一旦被伪造，攻击者就能把「发给受害者 HoA 的流量」全部重定向到自己手里——这是**流量劫持**。为此注册消息必须携带**移动节点与家乡代理共享的密钥**做消息鉴权（RFC 5944 定义了缺省的鉴权扩展），任何未鉴权的注册请求都应被丢弃。一个细节值得记住：**移动 IP 的漏洞几乎都出在「信任假设」上**——假设注册消息可信、假设家乡代理诚实、假设 CoA 分配正确，而现实中这些假设都需要逐一加固。

## 4 公式解析：IP-in-IP 封装的代价

隧道转发不是免费的，它给每个数据包增加了额外开销。IP-in-IP 封装的基本形式是：

$$L_{\text{total}} = L_{\text{payload}} + 20\ \text{B（内层 IP 头）} + 20\ \text{B（外层 IP 头）}$$

- **第一步，看封装的本质**：外层 IP 头的目的地是 CoA（给路由看），内层 IP 头的目的地是 HoA（给应用看）。一个数据包被套上了两层 IP 头，载荷不变，包头翻倍。
- **第二步，算开销占比**：若原包载荷为 $L_{\text{payload}} = 1460\ \text{B}$（典型 TCP 段），则 $L_{\text{total}} = 1500\ \text{B}$——恰好顶着以太网 MTU 上限，外层 20 字节头对大数据包约 1.4% 的开销可以接受；但若再叠加 IPsec 或 GRE 隧道头，总长就会超过 MTU，触发 IP 分片，反而更慢。
- **第三步，小包才是痛点**：对语音、控制这类几十字节的小包，20 字节外层头占比高达 30% 以上——所以移动 IP 的隧道通常只在**数据面**启用，控制信令仍走普通 IP。
- **第四步，读出设计权衡**：隧道让「网络层换位置」成为可能，代价是每个包多一层包头；而更深的代价是**路径被拉长**——数据要先绕回家乡代理，这正是下一节的三角路由问题。

## 5 三角路由与反向隧道

移动 IP 的默认数据路径是不对称的：**发往移动节点的包「先绕家乡」**（CN → HA → MN），**移动节点发出的包「直走」**（MN → CN）。两条路径合起来像一个三角形，因此得名**三角路由（triangle routing）**。<span class="marginnote">三角路由的代价很直观：数据包绕道家乡网络，端到端时延被拉长，家乡链路的带宽成为瓶颈；而且 HA 一旦故障，所有入站流量都会中断——家乡代理成了「单点」。这也是移动 IP 在真实网络里没有大规模取代蜂窝移动性管理的原因之一。</span>

缓解手段是**反向隧道（reverse tunneling）**：让 MN 发出的包也先送回 HA，再经 HA 转发给 CN——收发路径统一走家乡，路径变直了（CN 看到的一直是家乡地址，不再出现「从陌生地址来的连接」）。反向隧道还解决了三类应用问题：**入站过滤**（一些网络拒绝源地址不属于本网的数据包，反向隧道让源地址永远是 HoA）、**固定源地址**（需要固定源地址的 TCP 会话与防火墙规则）、**组播**（由家乡网络代理转发）。代价是更大的时延——它把「不对称的省路」换成了「对称的绕路」。

**辨析｜易错点：** 三角路由不是「bug」，而是「身份与位置分离」这个设计目标的直接产物——要让通信对端永远只认家乡地址，入站数据就必然要经过家乡代理。改进不是取消绕路，而是**缩短绕路**：让 HA 尽量靠近 MN 的当前位置（网络侧移动锚点），或把移动性管理从终端搬到网络侧。

## 6 移动 IPv6 与代理移动 IP

移动 IP 的后续演进沿两条路推进，其方向高度一致——**把复杂性从终端向网络迁移**。

**移动 IPv6（MIPv6，RFC 6275）**：IPv6 的原生移动方案，两处关键改进。其一，不再需要外部代理——MN 直接用 IPv6 的**路由器通告**发现转交地址，用**路由头（routing header）**替代 IP-in-IP 封装，开销更小；其二，内建**返回路由可达性检验（return routability）**——CN 在建立绑定前验证「MN 确实同时拥有 HoA 和 CoA 的往返路径」，防止攻击者伪装 MN 劫持流量。这两点让 MIPv6 在安全与开销上都优于 MIPv4。

**代理移动 IPv6（PMIPv6，RFC 5213）**：把移动性管理从「终端」搬到「网络」——MN 完全无感，由网络侧的**移动接入网关（MAG）**与**本地移动锚点（LMA）**替终端完成注册与隧道。手机用户因此**不装任何移动 IP 软件**就能获得「换网不换地址」的体验，运营商也更容易集中管理与计费。<span class="marginnote">从 MIP 到 PMIP 的演进，与 5G 核心网「控制面集中、用户面下沉」是同一个方向：终端越「笨」，网络越「勤」。今天蜂窝网里的「换基站不掉会话」，本质上就是一套网络侧移动性管理的成品——MEC 的 UPF 下沉也复用同一思想。</span>

**从 MIPv4 到 MIPv6 再到 PMIPv6，演进的主线清晰可见：移动性管理从「终端自觉」走向「网络代办」**——这与云计算里「从物理机到虚拟机的迁移」同构：谁能提供更透明的移动性，谁就更能被大规模采用。

## 8 易错辨析：移动 IP 理解的三个误区

**辨析｜易错点：** 集中澄清三个高频误解。

- **「移动 IP 改变 IP 地址」**：恰恰相反，移动 IP 的核心是**让家乡地址永不改变**——改变的是转交地址，而通信对端感知不到这个变化。这才是「身份与位置分离」的意义。
- **「移动 IP 已经解决了所有移动问题」**：它只解决「IP 层的可达性」。断线续传、低功耗、丢包优化仍是《无线环境下的 TCP》与《断接操作》的课题——移动 IP 只是让「包能到」，不负责「到了之后体验好」。
- **「没有移动 IP，手机就不能换基站」**：蜂窝网的移动性管理（位置区更新、切换）在链路层与网络层做了自己的一套，并不依赖移动 IP。移动 IP 解决的是「接入互联网后跨 IP 子网的漫游」，两者分工不同。

## 9 小结

- 移动性的根子是「IP 地址既表身份又表位置」的双重语义，解法是身份与位置解耦。
- 移动 IP 三要素：家乡地址（身份）、转交地址（位置）、家乡代理（代收转发）。
- 数据流四步：发现、注册、隧道、解封装；注册用生存期软状态自动过期。
- IP-in-IP 隧道每包多 20 字节头，小包占比大，隧道只服务数据面。
- 三角路由是「身份与位置分离」的必然代价，反向隧道用时延换对称。
- MIPv6 去掉外部代理、PMIPv6 把移动性搬进网络，主线是「复杂性向网络迁移」。
- 注册须带共享密钥鉴权，移动 IP 的安全漏洞几乎都出在「信任假设」上。

在下一节，我们把「包能送到」升级为「包能送好」：无线信道的随机丢包会让 TCP 把噪声当拥塞、把变慢当丢失——这就是**无线环境下的 TCP 与传输层优化**。
