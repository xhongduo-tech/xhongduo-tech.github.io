## 为什么从任务模型开始

上一节我们用「逻辑正确 + 时间正确 + 可预测上界」定义了实时系统，也认识了任务的四个参数（释放时间、执行时间、截止期、周期）。但「四个参数」只是零件，还差一套**组装规则**：任务什么时候来、来多少次、能不能被抢占、要不要共享资源。这套规则就是**任务模型**。没有模型，一切分析都是空谈——你无法证明一个连「负载长什么样」都没说清的系统能否在期限内完成任务。<span class="marginnote">想想反例：如果任务到达毫无规律、执行时间没有上界，任何调度算法都无法给出保证。任务模型把「混沌负载」改写成「可分析负载」，这是实时工程与普通工程的分水岭。</span>本章把任务模型与「可调度性」这两个贯穿全专题的概念正式立起来。

## 1 任务模型的三根支柱

任务模型从三个维度刻画负载：

**到达模式（arrival pattern）**：任务实例按什么规律释放？据此分三类：

**周期任务（periodic task）**：每隔固定周期 $P_i$ 释放一次，无限延续。这是实时系统最基本、最常用的模型——传感器采样、控制回路迭代都是周期任务。相对截止期通常取 $d_i \leq P_i$。
**偶发任务（sporadic task）**：两次释放之间有**最小到达间隔** $T_i$，但具体何时到达不确定。每次到达后，下一次必须至少等 $T_i$ 才到。<span class="marginnote">偶发任务给分析留下的抓手，正是这个「最小间隔」：调度器可以按最坏情形假设「每次都按最小间隔密集到达」来做悲观分析。</span>事件触发的报警任务属于此类。
**非周期任务（aperiodic task）**：到达没有任何间隔保证，纯随机。软实时系统里的交互请求属于此类，硬实时系统通常不允许它存在（或必须用偶发模型近似它）。

**执行约束（execution constraint）**：

**抢占式（preemptive）**：高优先级任务可以打断低优先级任务，被抢占的任务稍后从断点继续。绝大多数实时调度分析基于抢占式模型。
**非抢占式（non-preemptive）**：任务一旦开始执行就运行到结束，中途不可打断。模型更简单，适合执行时间很短的临界区或硬件协议。

**实例关系（instance relation）**：

- **单实例任务**：只在系统生命周期内执行一次，如启动自检。
- **多实例任务**：反复释放，每个实例称为一个 **job**。周期任务天然是多实例的。

## 2 可调度性的正式定义

有了任务模型，「能不能在期限内完成」就有了精确的数学形式。

**任务集（task set）**：系统里所有任务的集合 $\mathcal{T} = \{T_1, T_2, \dots, T_n\}$，每个任务有各自的 $(C_i, D_i, P_i)$。

**可调度（schedulable）**：存在**某个**调度算法，使得在任务集所有可能到达模式下，每个任务的所有实例都能在截止期前完成。若一个任务集**对给定的调度算法 $A$** 可调度，称它 **$A$-可调度**。

**可调度性分析（schedulability analysis）**：在运行之前、用数学方法判断任务集是否可调度的过程。

**核心要点：可调度性分析回答「可能吗」，调度算法回答「怎么做」。** 一个任务集在处理器上「时间够不够」是它的固有属性，与分析算法无关；而一个具体算法能否兑现这份「够」，是另一回事。下一节的 RM 与 EDF 就是在回答「怎么把够变成够」。

辨析｜易错点：**「可调度」与「CPU 不忙」不是一回事。** 利用率 $U \leq 1$ 只说明总工作量不超过容量，但调度不当仍可能让某高优先级任务挨饿。可调度是强得多的性质：它要求**每个**任务、**每个**实例的截止期都被满足，是一个逐任务、逐实例的全局保证。

## 3 可调度性的必要条件

不管用什么算法，任何可调度任务集都必须满足几个**必要条件**——违反任何一条都直接不可调度：

**条件一（利用率条件）**：$U = \sum_{i=1}^{n} \frac{C_i}{P_i} \leq 1$。总执行需求不能超过总处理容量。

**条件二（单任务条件）**：对每个任务 $T_i$，$C_i \leq D_i$（或 $C_i \leq P_i$）。任务的执行时间不能超过它自己的期限，否则连独占处理器都来不及。

**条件三（峰值条件，非抢占式特例）**：非抢占式调度里，任意时刻正在执行的任务不能被中断，因此**任意两个任务执行时间之和也不能超过较小截止期**。这是非抢占模型比抢占模型更苛刻的根源。

这些条件统称**必要但不充分**：满足它们只说明「有希望」，真正拍板需要针对性分析。以两个周期任务为例：$T_1 = (C=1, P=3)$、$T_2 = (C=1, P=3)$，$U = 2/3 \leq 1$，必要条件全过；但若让 $T_1$ 抢占地每次跑满 1 个时间单位、$T_2$ 排在后面，只要调度顺序得当二者都能按期完成——而一旦调度不当（比如同周期内先跑完 $T_1$ 的 2 个实例），$T_2$ 就会超期。<span class="marginnote">这个例子说明：必要条件相当于「体检指标正常」，可调度性分析才是「体检报告结论」。</span>

## 4 公式解析：利用率为什么是半把尺子

把利用率条件再往深挖一层，它是后续几乎所有可调度性定理的骨架。考虑 $n$ 个周期任务，相对截止期等于周期（$D_i = P_i$），总利用率：

$$
U = \sum_{i=1}^{n} \frac{C_i}{P_i}
$$

对它做三步解剖：

- **第一步，理解单位**：$C_i/P_i$ 是任务 $T_i$ 在单位时间内平均消耗的处理器份额，无量纲。$U = 0.8$ 意味着处理器平均有 80% 的时间在执行这些任务。
- **第二步，理解 $U = 1$ 的含义**：$U = 1$ 是「刚好饱和」的临界点。$U > 1$ 时，平均需求超过容量，必然有任务超期——所以 $U \leq 1$ 是必要条件的本质。
- **第三步，理解 $U \leq 1$ 为何不充分**：可调度性还要求时间上的**排布**。即使平均不超载，若高优先级任务扎堆到达、或共享资源导致阻塞，某个低优先级任务仍可能错过截止期。调度算法的任务，就是把「平均够」兑现为「每个时刻都够」。

这条公式的深刻之处在于：**它把时间约束翻译成了空间（容量）约束**。实时分析里的大量工作——RM 的利用率界、EDF 的最优性——都是在这一翻译之后展开的。

## 5 可调度性分析的三类方法

实际工程中，判断任务集是否可调度有三条路线，精度与成本递增：

**充分必要条件（exact test）**：直接模拟最坏到达模式或迭代计算每个任务的最坏响应时间，给出「是/否」的精确答案。成本最高，但结论最强。响应时间分析（RTA）是典型代表，我们在 WCET 与 RTOS 两篇会再次遇到它。

**充分条件（sufficient test）**：给出一个保守的界，条件成立则必可调度，但条件不成立时**未必**不可调度。RM 的 Liu–Layland 界 $U \leq n(2^{1/n} - 1)$ 就是充分条件——它是「容易算，但可能误杀」的典型。<span class="marginnote">充分条件的「误杀」是设计选择：宁可拒绝一个其实可调度的系统，也不冒超期的风险。这与软实时里「接受某些超期」的取向正相反。</span>

**仿真（simulation）**：按模型随机生成负载跑一段时间，观察是否超期。工程上最有说服力，但只能证明「测过的场景可行」，无法覆盖全部最坏情形——所以硬实时系统必须以前两种数学方法为准。

## 6 可调度性判定实战流程与术语速查

把本章工具串成一个可操作的三步流程，任何任务集都能走一遍：

**第一步，收集参数**：列出每个任务的 $(r_i, C_i, D_i, P_i)$，确认到达模式。参数不全的任务集无法分析——「WCET 没估、周期没定」是工程上最常见的分析前置失败。

**第二步，过必要条件**：先算总利用率 $U = \sum C_i/P_i$，检查 $U \leq 1$；再逐任务检查 $C_i \leq D_i$。必要条件不过，直接判不可调度，无需继续。

**第三步，做针对性充分性判定**：按调度算法选判定工具——RM 用 Liu–Layland 界，EDF 用 $U \leq 1$ 充要条件，复杂任务集用响应时间分析（RTA）。工具结论分三种：可调度、不可调度、不确定（充分条件失效）。后两者都要回到设计去调整参数。

一个例子走完三步。任务集 $T_1 = (C=1, P=3)$、$T_2 = (C=1, P=4)$、$T_3 = (C=2, P=6)$：

- **第一步**：三任务的 $(C, P)$ 齐全，均为周期任务，可直接分析。
- **第二步**：$U = 1/3 + 1/4 + 2/6 = 0.917 \leq 1$，通过；逐任务 $C_i \leq P_i$ 全过。
- **第三步**：RM 界 $3(2^{1/3}-1) \approx 0.780$，而 $U = 0.917 > 0.780$，充分条件失效——需换 RTA 或 EDF 再判定。由此看到「必要条件过、充分条件失效」时的不确定性区间。

术语速查表：

| 术语 | 含义 | 备注 |
| --- | --- | --- |
| 周期任务 | 每隔 $P$ 释放一次 | 可调度性分析的主对象 |
| 偶发任务 | 两次释放至少隔 $T$ | 按最坏密集到达分析 |
| 非周期任务 | 无任何间隔保证 | 只给统计性承诺 |
| 抢占式调度 | 高优先级可打断低优先级 | 分析模型的主流 |
| 可调度 | 存在某算法使全部实例按期完成 | 与具体算法区分开 |
| 充分条件 | 成立则必可调度 | 可能「误杀」 |
| 充要条件 | 成立当且仅当可调度 | 结论最强 |

## 7 小结

- **任务模型**从到达模式（周期/偶发/非周期）、执行约束（抢占/非抢占）、实例关系三个维度刻画负载。
- **可调度**是「存在某算法使所有实例都按期完成」；可调度性分析在运行前完成判断。
- 可调度性的**必要条件**有利用率条件 $U \leq 1$、单任务条件、非抢占峰值条件；满足必要条件不保证可调度。
- 利用率 $U = \sum C_i/P_i$
