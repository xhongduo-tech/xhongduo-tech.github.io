## 为什么从冒险开始

上一篇我们得到了理想的五级流水线：每周期一条指令，CPI = 1。但理想只存在于指令互不相干的世界里——真实程序的指令彼此依赖，上一条的结果常常是下一条的输入。

**冒险（hazard）**：流水线中某条指令需要的结果，还没被前面指令产生出来，于是无法按理想节奏执行的情况。它把 CPI 从 1 拉回 1 以上，是流水线性能的第一道现实约束。

本专题从第 3 篇起讨论分支预测、超标量、乱序执行——它们处理的都是「如何让流水线在冒险存在时仍高速运转」。因此先把冒险与它的两条对策讲透：**forwarding（旁路/转发）** 用硬件绕过停滞，**停顿（stall）** 用时间换正确。

另一个视角是「谁来解决」：**结构冒险靠硬件**（加资源），**数据冒险软硬并举**（转发 + 调度），**控制冒险主要靠预测**（下一篇主角）。分清这三者的责任主体，是理解后续所有技术的钥匙。

## 1 三类冒险：结构、数据、控制

冒险按来源分三类：

- **结构冒险（structural hazard）**：硬件资源不够，两条指令同时想用同一部件。例如单一存储器既取指又访存，lw 与下一条指令在同一周期争夺端口。
- **数据冒险（data hazard）**：指令间存在数据依赖，后一条需要前一条尚未算出的值。最常见的是 **RAW（读后写）**——`add` 的结果被下一条 `sub` 立刻使用。
- **控制冒险（control hazard）**：分支/跳转指令尚未判定方向，后续指令不知道取哪条。流水线越深，这个「不知道」持续得越久。

现代处理器通过**分离指令缓存与数据缓存**消解大部分结构冒险，因而重点落在数据与控制冒险上。<span class="marginnote">哈佛结构（指令、数据分路存取）正是为此而生；RISC-V 的五级教学流水线采用分离缓存，把结构冒险几乎清零，让教材把火力集中在 RAW 与分支上。分立缓存的具体组织见本专题第 7 篇《存储层次》。</span>

## 2 数据冒险与 forwarding

**转发（forwarding），也叫旁路（bypass）**：ALU 的结果在 EX 级末尾就已算好，与其等它写完寄存器堆再读，不如直接把结果「插队」到需要它的那条指令的输入。

以 RISC-V 序列为例：

$$ \text{add } x1,\ x2,\ x3 \qquad \text{sub } x4,\ x1,\ x5 $$

`sub` 需要 `x1`，而 `x1` 由 `add` 在 EX 级产生。若不做处理，`sub` 必须停两个周期；有了 forwarding，`add` 的 EX/MEM 寄存器里的结果直接旁路给 `sub` 的 ALU 输入，**冒险被完全消除，CPI 保持 1**。

**判定条件**：当 ID 级读出的源寄存器与 EX/MEM 或 MEM/WB 段的目标寄存器相同，且该段指令确实会写寄存器（排除 `x0` 与 `sw`），就启动转发。硬件是一组比较器加多路选择器（MUX），这正是「流水线控制」的核心逻辑之一。<span class="marginnote">寄存器文件读到「旧值」而转发的是「新值」，靠的是时序：写回发生在 WB 级的前半拍，读发生在 ID 级——同一周期内先写后读，配合转发选择器，五级流水线的 RAW 冒险即可在多数情况下不发一个停顿周期。</span>

转发按数据来源细分：**ALU-ALU 转发**（结果还在 EX/MEM 段）、**MEM-ALU 转发**（结果刚从缓存读回，在 MEM/WB 段）。距离越远，需要的转发路径越长，这也是流水线变深后旁路网络变复杂、延迟变大的原因之一。

**load-use 冒险**是 forwarding 治不了的：`lw` 在 MEM 级末才拿到数据，而紧邻的指令在下一周期就要用。此时必须**停顿一拍 + 转发**：

$$ \text{lw } x1,\ 0(x2) \qquad \text{add } x3,\ x1,\ x4 $$

编译器也会出手：把 `lw` 与使用它的指令之间插入一条无关指令（**指令调度**），让硬件免于停顿。这是「软硬件协同」的第一课。

在超标量处理器里（本专题第 4 篇），转发网络还要覆盖多个执行单元与更长流水线；load-use 冒险变成更精细的「就绪检测」。但本质不变：**能转发的转发，不能转发的停**，停顿是最后手段。

## 3 控制冒险与分支惩罚

分支指令在 ID 级才算出方向（比较寄存器），而目标地址到 EX 级才算好。若分支实际跳转，流水线里已经取入的错误指令全部作废（flush），白白消耗周期。

**分支惩罚（branch penalty）**：每次跳转分支造成浪费的周期数。五级流水线未优化时惩罚高达 3 拍；若在 ID 级就并行算出方向与目标（**尽早比较、提前跳转**），惩罚可降到 1 拍。

处理控制冒险的朴素策略：

- **冻结（freeze）**：检测到分支就停发新指令，等方向确定再继续——最简单，也最贵。
- **预测不跳（predict-not-taken）**：假定不跳，出错时冲刷流水线。
- **预测跳（predict-taken）**：假定跳转，配合延迟槽（delay slot）由编译器填有用指令。

**分支目标缓冲区（BTB，branch target buffer）** 是更进一步的机制：在 IF 级就用 PC 查一个小缓存，命中时直接给出预测目标地址，连「取哪条指令」都不用等译码。BTB 是现代分支预测器与取指端的接口，下一篇《分支预测》会把它讲透。

RISC-V 与 MIPS 的一个关键取舍是：RISC-V 取消延迟槽，把控制冒险的包袱完全交给预测器与编译器；而传统 MIPS 用延迟槽让一条「注定执行的指令」填补惩罚——两种哲学各有利弊，但趋势是前者。

分支惩罚的直接后果是：**分支越频繁、惩罚越大，性能越差**。所以现代处理器把「把分支猜对」当作头等大事——这正是下一篇《分支预测》的动机。<span class="marginnote">SPEC 基准里的整数程序每 5–6 条指令就有一条分支；若分支惩罚 3 拍且全猜错，CPI 会从 1 飙到 1.5–1.6，把流水线的收益吃掉近一半。猜对率从 50%（猜错一半）提到 97%，是把「性能翻倍」的实现细节。</span>

## 4 公式解析：停顿如何进入 CPI

设分支在总指令中占比例 $p$，每条分支平均惩罚 $b$ 拍，其余数据冒险造成的平均停顿为 $s$ 拍/条，则实际 CPI 为：

$$ \text{CPI} = 1 + s + p \cdot b $$

- **第一步**：理想 CPI = 1，这是流水线的天花板。
- **第二步**：数据冒险平均每指令增加 $s$ 拍；分支惩罚按占比 $p$ 折算进总和，得 $p \cdot b$。
- **第三步**：若 $p = 0.2$、$b = 3$、$s = 0.1$，则 $\text{CPI} = 1 + 0.1 + 0.6 = 1.7$——**性能只剩理想的约 59%**。

这条公式是后面所有动态调度、分支预测技术要优化的目标函数：Tomasulo 把 $s$ 压低，分支预测把 $b$ 摊薄。看懂它，就理解了为什么处理器要在冒险上砸那么多晶体管。

**数值算例**：把分支惩罚从 3 拍降到 1 拍（提前比较），CPI 从 1.7 降到 $1 + 0.1 + 0.2 = 1.3$，提速约 31%；再把预测准确率做到 97%（$b \approx 0.03$），CPI 约 1.1——**预测的每一分准确率都直接兑换成性能**。

真实的「猜错率」不是常数：循环尾巴的分支几乎必猜错，函数返回难预测，间接跳转（`jr ra`）目标不可预知。这也解释了为什么预测器要按地址分开记录（**分路**），并引入历史信息——预测不是一个计数器，而是一门统计推断学问。

## 5 流水线控制：谁来决定转发与停顿

流水线控制逻辑在 ID 级集中判决：比较各段的目标寄存器与源寄存器，产生 `ForwardA`、`ForwardB` 信号（选择转发源）与 `StallF`、`StallD` 信号（是否停顿）。

| 信号 | 作用 |
| --- | --- |
| `ForwardA` / `ForwardB` | 选择 ALU 第一/第二操作数来自 EX/MEM、MEM/WB 还是寄存器堆 |
| `Flush` | 分支错误预测或异常时，清空作废的指令 |
| `StallF` / `StallD` | load-use 冒险时冻结取指与译码段 |

这套机制在《计算机组成原理》的 CPU 章节与《数字逻辑》的时序电路中都有底层的触发器实现；本篇关心的是它的**判决逻辑**——一组比较器与优先规则。当多个转发源同时可用时，取最新（距离最近）的那个，保证读到的是最新值。

**硬件代价**需要清醒认识：每对 5 位寄存器比较 + 32 位数据选择，转发 MUX 在关键路径上，级数越深、代价越大；停顿时冻结流水寄存器还要额外的门控时钟。正因如此，设计者宁可在「软件可重排、硬件可转发」之间寻找平衡点——这也是《编译原理》中指令调度的价值所在。

从「正确性」与「性能」两个角度看：**冒险处理的第一原则是正确性**——宁可停顿也不能读到错误的值；在正确的前提下，再谈用转发、预测把停顿减到最少。这一原则会贯穿本专题的乱序执行与推测执行各篇。

## 6 小结

- 冒险分**结构、数据、控制**三类；分离指令/数据缓存消解大部分结构冒险。
- **RAW** 是数据冒险的主角；**forwarding** 从 EX/MEM、MEM/WB 旁路结果，多数 RAW 零停顿消除。
- **load-use** 必须停顿一拍再转发；编译器用指令调度填补空隙。
- 控制冒险靠**尽早比较、预测方向、冲刷错误指令**处理，分支惩罚决定其代价。
- BTB 在取指级缓存分支目标，把「猜分支」提前到 IF 级。
- 实际 CPI = $1 + s + p\cdot b$：数据停顿与分支惩罚是两个独立优化轴。
- 流水线控制用比较器 + MUX 判决转发与停顿，是现代处理器「微操作控制」的原型。
- 「能转发就转发、不能转发才停」是贯穿所有动态调度技术的黄金准则。

在下一节，我们将把「猜分支」从朴素策略升级为科学——**两位饱和计数器、TAGE 与感知机预测器**，看硬件如何把猜对率推到 97% 以上。
