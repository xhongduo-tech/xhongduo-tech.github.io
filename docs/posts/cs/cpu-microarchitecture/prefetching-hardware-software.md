## 为什么从预取开始

上一篇的 AMAT 公式里，未命中代价高达 200 周期。缓存的全部努力都在**缩小未命中率**，但强制未命中（第一次访问）是任何缓存都躲不掉的——除非「第一次访问还没发生，数据就已经在缓存里了」。

**预取（prefetching）**：在数据被真正需要之前，把它提前搬进缓存。它不是「减少未命中」，而是**把未命中的时间提前到不影响执行**——用「空闲的访存带宽」换「关键路径上的零等待」。

这一章分两半：**硬件预取器**靠观察历史自动发现规律（顺序、步长、相关），**软件预取**靠编译器的 `prefetch` 指令显式安排。两者回答同一个问题：**哪些数据「很可能马上用」，且「提前取不会污染缓存」**。

## 1 为什么预取有效：局部性定理的第二推论

上一篇我们靠「时间 + 空间局部性」让缓存命中。预取进一步利用同一规律：**能预测访问序列，就能提前取**。

- **顺序/流式（sequential/stream）**：数组遍历——取 N 就预告 N+1、N+2……这是最常见也最有效的形态。
- **步长（stride）**：`for (i=0;i<n;i+=4) a[i]`——按固定步长跳着取。
- **相关（correlating）**：`A` 之后总跟着 `B`——记录「前驱 → 后继」对，遇到 `A` 就取 `B`。

一条被反复验证的规律是：**顺序预取能消除 SPEC 等基准里一半以上的强制未命中**。代价极低（一个加计数器），收益巨大，因此每一颗现代核心的 L2 都带「下一行/步长预取器」。<span class="marginnote">硬件预取器的思想可以一路追溯到 1978 年 IBM 370/168 的「顺序预取」——半个世纪过去，最朴素的「取下一行」仍是收益/成本比最高的预取器。现代 Intel L2 预取器可追踪多达几十个独立的流，AMD 与 ARM 也各有专属预取算法。</span>

**一个判断「值得预取吗」的直觉**：如果程序以「近似顺序」扫描一个数组，预取几乎必赚；如果程序跳转依赖指针链、访问完全不可预测，预取大概率白费甚至有害。**预取的价值 = 可预测性 × 未命中代价**——这条直觉也是硬件预取器「激进度控制」的依据。

## 2 硬件预取器：观察历史、预测未来

硬件预取器的标准范式是**标记表（tagged table，McFarling 1988）**：缓存未命中时，在表中记录「这个块被访问过」并发出一次「下一块」预取；下一次预取命中，再发出再下一块——**每命中一次预取，就滚雪球式地推进预取流**。

标记表的关键细节是「只有**被真实访问**的预取块才会触发下一次预取」。这样设计有双重好处：其一，避免「为预取而预取」的雪崩；其二，自动让预取流**跟随真实访问节奏**，程序停下预取也停下。这个「用真实访问校准预取」的反馈，是硬件预取器可靠性的基石。

| 预取器 | 规律 | 硬件 | 典型命中率提升 |
| --- | --- | --- | --- |
| 下一行（next-line） | 顺序 | 极低 | 中 |
| 步长（stride） | 固定间隔 | 低 | 高（数组负载） |
| 流/流缓冲（stream buffer） | 多条顺序流 | 中 | 高 |
| 相关（correlating） | 前驱→后继 | 高 | 中 |
| 神经（如 AMD 的深层学习预取器） | 复杂混合 | 很高 | 在特定负载显著 |

现代处理器常同时挂多个预取器，各管一类规律；每个预取器还有**「受控激进」**机制——预取太凶会污染缓存，所以命中率/带宽允许时才扩张，浪费时自动回缩。这又是一个「用饱和计数器当裁判」的实例。<span class="marginnote">预取的「度」极其微妙：取太远可能取到用不到的数据（污染）、占掉带宽；取太近又来不及掩盖未命中代价。现代预取器都带「及时性（timeliness）」与「有用性（usefulness）」统计，靠历史决定预取距离与深度——与第 3 篇 TAGE 的「自适应表分配」是同一套自适应哲学。</span>

另一个工程选择是**预取到哪一级**：预取到 L1 收益最快，但污染最重；预取到 L2 把污染「隔层」，等真实访问到 L2 命中后再自然落入 L1。因此硬件预取器普遍面向 L2，软件预取则常用「两级模式」先 L2 后 L1。**「预取进哪一层」与「预取多远」是两个可独立调节的旋钮**，共同决定预取的净收益。

## 3 软件预取：编译器明说「请提前取」

**软件预取（software prefetching）**：编译器在循环里插入显式预取指令，如 x86 的 `prefetcht0 [addr]` 或 RISC-V 的 `prefetch`。它把「何时取、取多远」的决定权交给编译器——因为编译器能看到循环结构，能算出「这次迭代预取下一次迭代的数据」。

一个典型的循环预取模式：

```c
for (i = 0; i < n; i += BLOCK) {
    __builtin_prefetch(&a[i + PREFETCH_DIST]);  // 提前 PREFETCH_DIST 个元素
    process(a[i]);
}
```

**预取距离（prefetch distance）** 是关键参数：提前取的「够不够早」要能覆盖未命中延迟。若一次访存代价 200 周期、每次迭代 4 周期，则距离应 ≈ 50 次迭代——太近不够早，太远污染缓存且可能还没轮到就被替换。编译器常用「首次失效距离」模型推算最优距离，这也是《编译原理》循环优化的经典考题。<span class="marginnote">软件预取对「步长不规律、依赖指针链」的负载几乎无能为力——因为编译器不知道运行时地址；此时硬件预取器反而更可靠。两者互补：<strong>编译器看见结构，硬件看见行为</strong>。</span>

**软件预取的实际收益**受硬件支持制约：x86 的 `prefetch*` 指令是一族「提示（hint）」——处理器可以无视、可以提前、也可以压后，不保证语义。这给了硬件「受控激进」的空间，也让预取指令**零开销可测**：即使预取无益，也几乎不伤害正确性。这正是预取指令能放心进生产代码的原因。

## 4 公式解析：预取距离怎么定

设预取指令到使用之间的迭代步数为 $D$，每次迭代耗时 $T_\text{iter}$，未命中代价为 $T_\text{miss}$，则「恰好掩盖」的距离为：

$$ D = \left\lceil \dfrac{T_\text{miss}}{T_\text{iter}} \right\rceil $$

- **第一步**：预取必须在访问前 $T_\text{miss}$ 周期发起，否则掩盖不住。
- **第二步**：每步迭代推进 $T_\text{iter}$ 周期，故需要提前 $\dfrac{T_\text{miss}}{T_\text{iter}}$ 步。
- **第三步**：代入 $T_\text{miss} = 200$、$T_\text{iter} = 4$，得 $D = 50$——**恰好提前 50 次迭代**。

**数值算例**：若 $D$ 取 25（太近），则每 25 步有一次未命中暴露，约浪费 $200 - 25\times4 = 100$ 周期/次；若 $D$ 取 200（太远），预取数据还没轮到就被替换，等于白取。**最优距离把未命中代价从 200 压到 0，差的距离让一半的预取「白干」**——这就是「预取不是越多越好」的数学版。

## 5 预取与乱序执行、多核的配合

预取与前面几篇的机制环环相扣：

- **与乱序执行配合**：乱序窗口里的访存指令可以「越过」未就绪的指令提前执行，这本身就是一种隐式预取；显式预取再往前一步，把取数提前到「还没发射访存」。
- **与 TLB 配合**：预取会触发页表遍历，把 TLB 条目也提前填好——预取「连地址翻译一起预热」。
- **与多核配合**：预取的数据可能是脏块或共享块，会触发缓存一致性的无效/获取操作；预取器必须「意识到」多核的共享状态，避免把已被其他核独占的块乱取。

**预取器设计的黄金法则**：它必须「看到真实访问才推进」，且「预测必须足够保守」——宁可少取，不可乱取。这条法则在乱序、多核、安全的夹缝里，决定了现代预取器全部的自适应机制。

## 6 预取的风险：污染与带宽

预取不是免费午餐，它有三个代价：

- **缓存污染（pollution）**：预取的数据挤掉真正有用的行。解决：预取到 L2 而非 L1（L2 污染成本更低），或只填充不命中预取的块。
- **带宽消耗**：预取占据访存带宽，可能挤掉真实访问。解决：受控激进——带宽吃紧时自动降低预取强度。
- **无用预取**：预测错了，取来的数据没人用。解决：有用性统计，命中率低的预取流被「降级」。

**辨析｜易错点**：预取的收益不是「把未命中率降为零」，而是「把未命中从关键路径挪走」。若程序本身就内存带宽受限，预取只会加重拥堵——**预取对「延迟敏感、带宽富余」的负载最有效**。<span class="marginnote">预取与侧信道还共享同一个微观机制：预取会改变缓存状态，理论上可被计时探测。Spectre 之后的「推测性预取」甚至要求预取不得跨越安全边界——预取又一次被安全约束绑住了手脚。</span>

**一个直观的验收标准**：打开预取前后对比运行时间。若命中率上升而时间几乎不变，说明瓶颈在带宽而非延迟——预取救不了带宽瓶颈；若时间显著下降，说明预取把延迟成功藏住了。**预取的收益永远要放在「延迟 vs 带宽」的框架里判断**，这也是下一篇性能模型的预演。

## 7 小结

- **预取**把强制未命中从关键路径挪走，是「时间局部性的主动版」。
- 硬件预取器（下一行/步长/流/相关/神经）观察历史自动预测；现代 L2 常挂多个并行预取器。
- 软件预取靠编译器的 `prefetch` 指令显式安排，用预取距离 $D = \lceil T_\text{miss}/T_\text{iter}\rceil$ 定参数。
- 编译器看见结构、硬件看见行为，两者互补而非替代。
- 预取的三大代价：污染、带宽、无用预取——受控激进是通用解。
- 预取对「延迟敏感、带宽富余」的负载最有效，对带宽受限负载可能适得其反。
- 预取与乱序、TLB、多核一致性互相纠缠，现代预取器必须「看真实访问才推进」。
- 预取是「提示」而非「命令」，硬件可无视，因此零正确性风险。
- 预取目标层（L1 还是 L2）与距离是两个独立旋钮，共同决定净收益。
- 预取器的黄金法则：看见真实访问才推进，预测保守优先。
- 预取的收益要用「延迟 vs 带宽」框架判断，带宽受限时预取可能有害。
