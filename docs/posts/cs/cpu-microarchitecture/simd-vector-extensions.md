## 为什么从向量化开始

前几篇的乱序、分支、缓存，都在「榨取一条指令的并行度」；但有一类并行是**数据本身带来的**——图像、音频、矩阵、神经网络，成千上万个数据元素被**同一条运算**处理。

**数据级并行（DLP，data-level parallelism）** 用一条指令操作多个数据：**SIMD（单指令多数据）**。它不增加发射宽度、不增加核数，只让「一条指令」同时处理 4、8、16 个数据——**这是通用核上最后一片「免费午餐」**，也是从视频解码到 AI 推理，性能翻倍的主要来源。

这一篇讲清四代扩展的脉络：x86 的 SSE → AVX → AVX-512，ARM 的 NEON/SVE，RISC-V 的向量扩展 RVV。它们回答同一个问题：**如何让「一条指令做很多事」既高效又可控**。

## 1 从标量到向量：一条指令,多份数据

标量指令一次处理一个数据；SIMD 指令一次处理一个**向量**（打包的多个数据）。以浮点加法为例：

$$ \text{标量：} a + b \quad \longrightarrow \quad \text{向量：} \vec{a} + \vec{b} = (a_0+b_0,\ a_1+b_1,\ \dots) $$

**关键点**：向量的每个元素都是「独立加、独立存」——没有跨元素的依赖，因此天然可并行。这与第 4 篇的指令级并行不同：ILP 需要硬件去「发现」并行，DLP 是**数据形态自带的并行**，编译器只需「认出」即可。

**SIMD 的软件前提**：循环必须是「可向量化的」——无循环进位依赖、无指针别名（aliasing）。编译器在《编译原理》里做循环向量化，无法证明别名时只能保守放弃，或靠 `restrict` 关键字向编译器保证。**向量化是「编译器证明 + 硬件执行」的经典配合**。<span class="marginnote">一个著名的坑：`a[i] = b[i] + c[i]` 循环能否向量化，取决于 `b` 与 `c` 是否可能指向同一块内存。C99 的 `restrict` 正是为此而生——它告诉编译器「放心，这些指针不重叠」。忘写 `restrict`，SIMD 收益直接打对折。</span>

## 2 x86 的扩张之路：SSE → AVX → AVX-512

x86 的 SIMD 扩展是一部「寄存器越来越宽」的历史：

- **SSE（1999，Pentium III）**：128 位寄存器 `xmm0–xmm15`，一次 4 个单精度浮点。
- **AVX（2011，Sandy Bridge）**：256 位寄存器 `ymm0–ymm15`，一次 8 个单精度；引入三操作数（FMA，融合乘加）。
- **AVX-512（2017，Skylake-X）**：512 位寄存器 `zmm`，一次 16 个单精度；带来掩码寄存器与嵌入式广播。

| 扩展 | 宽度 | 单精度元素数 | 引入年代 |
| --- | --- | --- | --- |
| SSE | 128 位 | 4 | 1999 |
| AVX | 256 位 | 8 | 2011 |
| AVX-512 | 512 位 | 16 | 2017 |

**两条伴随约束**：其一，**频率权衡**——宽向量单元耗电大，Intel 在 AVX-512 上引入「AVX 频率降频」：跑宽向量时自动降频保护散热；其二，**发射/译码**——向量指令要穿过第 4 篇的乱序调度器，向量寄存器也要纳入重命名，这给微架构的物理寄存器文件平添面积。<span class="marginnote">「AVX 降频」是功耗墙的活例子：宽向量把峰值 FLOPS 推高，但功耗同步飙升，实际吞吐未必等比上涨。这提醒我们：<strong>峰值 FLOPS 是纸面数字，能持续维持的「稳态 FLOPS」才是真实性能</strong>——这直接通向下下篇的 Roofline 模型。</span>

**一个真实的向量化收益例子**：把一段 `for` 循环的 `c[i]=a[i]+b[i]` 从标量改为 AVX-512（16 路），循环次数直接除以 16——**同样的缓存流量，指令数只剩 1/16**，乱序调度器的负担也相应减轻。这解释了为什么「SIMD 收益」经常比「多核收益」更稳：它不依赖负载的多线程可扩展性，只依赖数据形态。

从微架构视角，向量单元还带来**专门的硬件**：宽加载/存储、元素重排（shuffle）、融合乘加（FMA）单元。这些单元的**延迟与吞吐**成为向量程序的性能天花板，也是《性能建模》那篇微基准测试要测的对象。

## 3 ARM 的可扩展向量：NEON → SVE

ARM 走了另一条路——**向量长度无关（VL agnostic）**：

- **NEON**：128 位定长向量，类似 SSE。
- **SVE（Scalable Vector Extension）**：向量长度**由实现决定**（128–2048 位），软件按「当前长度」编写，同一二进制可在不同硬件的不同长度上运行。

**SVE 的核心思想**：把「向量有多宽」从软件契约中抽走。软件用谓词（predicate）控制「哪些元素参与运算」，硬件在运行时决定实际宽度。这样**软件只需写一次，硬件演进即可自动变宽**——这正是富士通 A64FX（超算富岳）选择 SVE 的理由，也是 ARM 走向「可扩展」的哲学。<span class="marginnote">对比鲜明：x86 靠「加宽指令集」演进（每个新宽度都是新指令），ARM 靠「运行时长度」演进（同一套指令，硬件变宽即可）。前者是「指令集版本号推动」，后者是「实现参数推动」——RISC-V 的 RVV 与 SVE 一脉相承。</span>

SVE 的谓词化还有一个隐藏收益：**它把「条件执行」也向量化了**。传统 SIMD 遇到 `if (a[i] > 0) b[i] = ...` 只能拆分支；SVE/RVV 的掩码让「整条向量带条件执行」成为可能，循环里的分支不再打断向量流。这让可向量化的代码范围大幅拓宽——从「纯数组运算」扩展到「带条件的数组运算」，也是神经网络中大量 `ReLU` 这类「逐元素条件函数」能被向量化的关键。

## 4 RISC-V 向量扩展 RVV：把「宽」变成配置项

**RVV（RISC-V Vector Extension）** 把向量化的「自由」推向极致：它定义了**向量寄存器组 v0–v31** 与一套与长度无关的指令，通过 CSR（如 `vsetvli`）在运行时设置「每个向量寄存器的元素个数与类型」。

RVV 的关键特性：

- **长度无关**：软件查询 `vsetvli` 返回的「每寄存器元素数」，按它循环；换硬件自动适配。
- **谓词（mask）**：每条向量指令可选掩码，实现「条件向量化」——把 if 语句也向量化。
- **元素类型灵活**：8/16/32/64 位整数与浮点，一条指令按类型选择。

**一段 RVV 风格的「长度无关」循环**（伪代码）最能说明问题：

```
while (i < n) {
    vl = vsetvli(n - i, f32);      // 问硬件：这一轮能处理几个？
    vload v1, a[i];                 // 加载 vl 个元素
    vload v2, b[i];
    vadd  v3, v1, v2;               // 向量加
    vstore c[i], v3;
    i += vl;                        // 按实际处理的个数推进
}
```

同样的代码，在 128 位 RVV 硬件上每次处理 4 个，在 512 位硬件上每次处理 16 个——**软件不用改，性能自动翻四倍**。这就是「长度无关」的最大价值：它把「向量宽度」从软件契约变成硬件参数，让代码库只写一次。

RVV 把「向量宽度」从「硬件特性」变成「运行时配置」，让同一套软件跑在嵌入式（128 位）到超算（数千位）上。它与 SVE 共享「长度无关」哲学，但把粒度与灵活性做得更细。<span class="marginnote">向量扩展与《高性能计算》的联系极深：无论哪种向量机，「每周期处理元素数 × 频率」就是理论峰值。学向量扩展时，请始终把「这会给峰值 FLOPS 贡献多少」记在心里——这正是下一篇性能模型的核心输入。</span>

## 5 公式解析：峰值 FLOPS 的组成

一台处理器**理论峰值浮点性能**的公式：

$$ \text{峰值 FLOPS} = \text{核数} \times \text{频率} \times \text{SIMD 宽度} \times 2 \ (\text{FMA}) $$

- **第一步，拆项**：每个核每周期能完成「SIMD 宽度」个浮点乘加。
- **第二步**：FMA（融合乘加）一条指令同时算「乘」与「加」，故乘 2。
- **第三步**：乘上核数与频率，即整机每秒浮点运算次数。

**数值算例**：8 核、3.5 GHz、AVX-512（16 个单精度）、FMA 融合：$8 \times 3.5\times10^9 \times 16 \times 2 = 896$ GFLOP/s。**纸面峰值近 900 GFLOP/s**；实际因访存与降频往往只能到三成左右——这个「峰值 vs 实际」的落差，正是 Roofline 模型（下一篇）要量化的。

再看「加宽 vs 加核」的经济账：把 SIMD 宽度从 128 加到 512 位，指令数与循环开销几乎不变，面积只加在向量单元上；而多加一个核，整套前端、缓存、调度器都要复制。**这就是为什么「数据能向量化时，优先向量化」**——它是通用核上「每瓦特性能」最高的一类并行。

## 6 小结

- **数据级并行（DLP）** 是数据形态自带的并行，编译器认出、硬件执行。
- x86 沿「加宽指令」演进：SSE 128 → AVX 256 → AVX-512 512 位。
- ARM（SVE）与 RISC-V（RVV）沿「长度无关」演进：软件写一次，硬件变宽即提速。
- 向量化前提是循环可证明无依赖、无别名；`restrict` 是编译器信任状。
- 峰值 FLOPS = 核数 × 频率 × SIMD 宽度 × 2（FMA），但实际受功耗与访存制约。
- 「峰值是纸面、稳态才是真实」——这是通向 Roofline 的桥梁。
- 掩码/谓词把「条件执行」也向量化，`ReLU` 这类逐元素条件函数受益最大。
- 向量寄存器也要进重命名与物理寄存器文件，给乱序核心平添面积。
- 向量化收益比多核收益更稳：不依赖线程可扩展性，只依赖数据形态。
- 峰值 FLOPS 公式是「核数 × 频率 × 宽度 × 2」，每个因子都是独立优化轴。
