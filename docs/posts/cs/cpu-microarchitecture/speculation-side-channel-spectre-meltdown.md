## 为什么从推测执行讲安全

前几篇我们全力拥抱推测执行：分支预测让取指越过边界，乱序执行让指令越过依赖。它们合起来带来巨大的性能，却埋下一个隐患——**处理器在执行时做了「不该做的事」**，只是事后擦掉了可见状态。

2018 年 1 月，这个隐患被三组研究者（Kocher 等人、Lipp 等人、Google Project Zero）同时引爆：**Spectre** 与 **Meltdown**。它们不是软件漏洞，而是**微架构漏洞**——乱序与推测执行把「不存在的执行」变成了「可观察的计时差异」。

本篇回答三件事：推测执行如何泄露信息、两条攻击分别利用了什么、缓解为什么这么贵。

## 1 侧信道：从「看得见」到「偷得出」

**侧信道（side channel）**：不直接读取目标数据，而是通过数据在系统中留下的「物理痕迹」推断它。CPU 侧信道之王是**缓存计时（cache timing）**——访问命中（几十周期）与未命中（几百周期）的时间差，就像一把「尺子」，量出目标数据是否在缓存里。

**Flush+Reload** 是经典手法：攻击者把目标内存从缓存中清掉（flush），等受害者运行，再计时访问它（reload）。若受害者访问过它，reload 快；否则慢。由此读出「受害者是否访问了某个地址」——一个布尔信息，串联起来就是数据。

**关键洞察**：微架构把「结果」擦掉，但把「过程」留在缓存与 TLB 里。**推测执行改变缓存状态的那一刻，就是泄露开始的那一刻**。<span class="marginnote">这不是第一个利用计时的攻击（2005 年的密码学时序攻击早已存在），但 Spectre/Meltdown 的恐怖在于：它不需要任何程序漏洞，CPU 的「优化行为」本身就是漏洞载体——连沙箱、虚拟机、浏览器隔离都挡不住。</span>

## 2 Spectre：训练分支预测器

Spectre 一族最核心的是 **Variant 1：边界检查绕过（bounds check bypass）**。它利用处理器「先推测、后验证」的时序漏洞：

```c
if (x < array1_size) {          // 边界检查
    index = array1[x] * 4096;   // 越界读，推测执行发生
    temp &= array2[index];      // 把「是否命中」写进缓存
}
```

攻击者反复制造 `x` 合法，训练分支预测器「预测不跳」；再忽然传入越界 `x`。处理器**在检查完成前就推测执行了越界读**，并把结果通过 `array2[index]` 的缓存状态「带」到可见世界。检查完成后虽被回滚，但缓存痕迹留下——用 Flush+Reload 即可把秘密字节一位位测出来。<span class="marginnote">Variant 2（分支目标注入 / BTB poisoning）则是污染 BTB：让受害者在「被预测会跳」的地址上执行攻击者选择的目标，把受害者的推测执行引到攻击者代码上。Variant 3/4（Meltdown、边界检查绕过-存储）共享同一根：推测窗口内执行了本不该执行的指令。</span>

Spectre 的可怕之处是**不需要任何代码漏洞**——正常程序越界读本来会出错，但推测执行让「错」发生在「被验证之前」。修复的代价因此高昂：必须在「检查通过」前不让推测读真的发生。

把攻击拆成五步，就能看清它为什么「防不胜防」：

- **第 1 步，训练**：反复用合法 `x` 执行边界检查，让预测器学到「不跳」。
- **第 2 步，触发**：忽然传入越界 `x`，处理器在检查完成前推测执行越界读。
- **第 3 步，编码**：把读到的秘密字节用作 `array2` 的偏移，让秘密值决定哪块缓存被加载。
- **第 4 步，回滚**：检查发现越界，推测指令被丢弃，寄存器状态复原。
- **第 5 步，测量**：用 Flush+Reload 找出哪块 `array2` 缓存变热，反推出秘密字节。

**攻击者唯一需要的是「能运行代码」**——浏览器里的 JavaScript、云上的租户、甚至旁路进程，都可以发起。这也是为什么 2018 年它在浏览器沙箱与云计算场景引爆。

## 3 Meltdown：穿透特权边界

**Meltdown** 针对 Intel（当时）的乱序核心：它利用「**权限检查（page permission）在乱序窗口里被延迟**」这一微架构特性。

攻击思路是：访问一个本应「特权拒绝」的内核地址（如 `kernel[offset]`），处理器在**判定权限错误之前**就推测性地把它读入，随后把值通过 `probe[secret * 4096]` 的缓存状态编码出来。权限错误最终引发异常，但缓存痕迹已留下——用 Flush+Reload 测量，就能读出内核内存。

这等于说：**用户态程序可以读取内核地址空间的内容**。2018 年它在几乎所有 Intel 乱序 CPU 上有效（对当时未打补丁的系统可读任意内核内存），杀伤力远超 Spectre。<span class="marginnote">Meltdown 与 Spectre 的本质差异：Spectre 是「训练处理器猜错」，Meltdown 是「处理器无视权限直接猜」——Meltdown 根植于乱序执行的权限检查延迟，Intel 后来在微码与硬件里加了序列化屏障，AMD 因权限检查更早而基本免疫。</span>

Meltdown 的技术前提有二：其一，乱序执行在**权限判定之前**就发起了内存访问（越权推测）；其二，权限异常（页故障）在流水线**退休阶段**才被识别，给推测留出了「窗口」。这两个前提在当年的 Intel 微架构里恰好成立——把「优化」变成「漏洞」，只隔了一个微架构细节。

Meltdown 的修复路径也因此非常「物理」：**让权限检查提前到访存发起之前**（硬件微码补丁），或干脆**让内核地址不出现在用户态的页表**（KPTI）。前者损失吞吐，后者损失切换速度——两个方向都在跟「延迟权限检查」这个微架构选择博弈。

## 4 核心对比表：两个家族的四大变体

| 变体 | 名称 | 利用的机制 | 攻击对象 |
| --- | --- | --- | --- |
| Variant 1 | 边界检查绕过（Spectre v1） | 分支预测越界读 | 任何推测处理器 |
| Variant 2 | 分支目标注入（Spectre v2） | BTB 污染 | 多数乱序处理器 |
| Variant 3 | Meltdown | 乱序权限检查延迟 | Intel 乱序核心 |
| Variant 4 | 存储绕过（Spectre v1.1/v4） | 推测存储转发 | 多数乱序处理器 |

共同分母只有一个：**推测执行让「本不该发生的读写」先发生，缓存是它的留声机**。这张表是理解所有缓解的索引。

## 5 缓解：为什么每个方案都肉疼

因为漏洞在「优化行为」本身，缓解只能「挡住优化」或「遮住痕迹」，两头都在烧性能：

- **lfence / 序列化指令**：在敏感边界插入，禁止推测越过（Spectre v1 的直接解药，但一次 `lfence` 可吞 20+ 周期）。
- **retpoline**：用「返回指令的延迟推测」替代间接跳转预测，堵住 BTB 污染（Spectre v2 的软件缓兵之计，编译器可透明生成）。
- **IBRS / STIBP**：硬件层面隔离不同特权级/超线程间的分支预测器状态。
- **KPTI（内核页表隔离）**：让用户态根本映射不到内核页表，Meltdown 无从读取（性能代价最高可达两位数百分比）。
- **RSB stuffing**：填充返回地址栈，防「返回地址被污染」。

**一张「性能税」账单**：KPTI 让系统调用慢 10–50%，retpoline 让间接调用慢几个百分点，序列化屏障拖累整数流水线——**堵漏洞的每一针，都是打在性能上的**。这正是 2018 年后「安全成为第一级设计约束」的由来。<span class="marginnote">更彻底的硬件修复直到新一代核心才到来：Intel 的「序列化前端」、ARM 的推测阻断指令、AMD 的「显式推测隔离」，都是在微架构层重建「不能越过权限边界推测」的保证。安全不再是软件补丁，而是硅片设计的一部分。</span>

缓解的选择背后是清晰的权衡逻辑：

- **Spectre v1 靠「挡」**：在可疑的边界检查前后插 `lfence`，牺牲的是该处流水线吞吐。
- **Spectre v2 靠「换」**：retpoline 用「返回指令的不可预测性」替代「可污染的间接跳转」，把攻击面从「可训练的 BTB」移走。
- **Meltdown 靠「藏」**：KPTI 让攻击者「看不见」目标，从根上断了越权读的路径。
- **纵深防御**：现代操作系统同时启用上述全部，配合硬件的推测隔离指令，形成多层防线。

安全领域的同行还可参看《计算机安全》专题的侧信道章节——那里的攻击者视角，与这里的处理器视角互为镜像。

## 6 公式解析：缓存计时如何变成信息

Flush+Reload 的判读是一个统计假设检验。设命中延迟均值 $\mu_h$、未命中均值 $\mu_m$，一次测量 $T$ 判定「命中」的标准是：

$$ \text{判定命中} \iff T < \dfrac{\mu_h + \mu_m}{2} $$

- **第一步**：$\mu_h \approx 40$ 周期（L1 命中），$\mu_m \approx 200$ 周期（回主存），间隔远大于测量噪声。
- **第二步**：阈值取两者的中点，单次测量的误判率已极低；再重复数千次取中位数，可把噪声压到忽略。
- **第三步**：每个秘密字节经 256 次探测（`array2` 的 256 块），命中位置即字节值——**一次攻击约几十万次计时，总耗时毫秒级**。

公式背后的直觉值得记住：**只要两个「状态」的时间差足够大、且测量可重复，任何微架构痕迹都能变成信道**。这是侧信道不可消除的根源。

## 7 小结

- **推测执行 + 缓存计时 = 侧信道**：处理器擦掉结果，却留下缓存痕迹。
- **Spectre v1/v2**：训练分支预测器/BTB 让推测越过边界或目标；**Meltdown**：乱序权限检查延迟让越权读取发生。
- 四大变体共享「缓存是留声机」的共同分母。
- 缓解要么**挡优化**（lfence、retpoline、IBRS、RSB stuffing），要么**遮痕迹**（KPTI）。
- 性能税真实：KPTI 数十个百分点、retpoline 数个百分点——安全从此进入硅片设计。
- 硬件级修复（序列化前端、推测隔离）在新一代核心才真正落地。
