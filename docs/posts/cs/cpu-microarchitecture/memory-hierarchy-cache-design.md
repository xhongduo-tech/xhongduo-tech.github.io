## 为什么从存储层次开始

前面六篇解决「如何把指令跑得并行」，接下来两篇解决「如何把数据喂得及时」。事实是：**访存延迟早已成为性能的第一瓶颈**。一次 L1 命中约 4–5 个周期，一次主存访问约 200 周期——差两个数量级。

**存储层次（memory hierarchy）**：把不同速度、容量、价格的存储器件组织成金字塔，让「热数据」在顶层、「冷数据」在底层。它存在的依据只有一个：**局部性（locality）**。时间局部性（刚用过的还会再用）与空间局部性（刚用过的附近也会被用）让「只缓存一小块、却命中绝大多数访问」成为可能。

上一篇《推测执行》告诉我们缓存也是侧信道的载体；这一篇我们正面看清它：缓存如何组织、数据如何放置、放不下时如何取舍、写回如何保证一致。这是《预取》与《一致性》两篇的地基。

## 1 局部性：存储层次的物理依据

**局部性（locality）**：程序在一段时间内倾向于访问一小部分地址区域。

- **时间局部性**：循环、栈、近期变量——访问过的地址很快再被访问。
- **空间局部性**：数组遍历、结构体、指令顺序执行——访问过的地址附近也会被访问。

99% 的命中率不是玄学，而是局部性定理的必然：Denning 的**工作集（working set）** 理论证明，程序的活跃页集合通常远小于其全部内存。缓存只要装下工作集，就抓住了绝大多数访问。<span class="marginnote">缓存命中的收益远大于未命中的代价：即便命中率 95%、未命中代价 200 周期、命中代价 5 周期，平均访问时间也只是 $5 + 0.05\times200 = 15$ 周期——比全部直访主存快一个数量级。这个「95/5」账，正是所有缓存都值得做的数学依据。</span>

未命中按其成因可分三类，优化方向各不相同：

- **强制未命中（compulsory / cold）**：第一次访问该块，任何缓存都躲不掉——只能靠**预取**（下一篇）或**更大的块**减少首次次数。
- **容量未命中（capacity）**：工作集超过缓存容量——只能靠**更大的缓存**。
- **冲突未命中（conflict）**：该块能放的位置被「别的块」占满——靠**提高相联度**。

**辨析｜易错点**：冲突未命中是「相联度不够」的症状，把它误当容量问题去加缓存容量，治标不治本。判断依据很简单：同样的访问序列换到全相联就不见了，是冲突；全相联还丢，是容量。

## 2 缓存组织：三种映射方式

**缓存（cache）**：处理器与主存之间的小而快的存储，按行（块，block/line）组织，每行存若干字节（通常 64 字节）。一个地址被拆成三部分：**标签（tag）**、**索引（index）**、**块内偏移（offset）**。

按「一个地址能放在缓存里的几个位置」分三类：

- **直接映射（direct-mapped）**：每个块只能放一个位置（`索引 = 地址中间位`）。硬件最简、查得最快，但冲突未命中（thrashing）严重。
- **组相联（set-associative）**：缓存分成若干组，每块可放组内任意位置。**n 路组相联 = 每组 n 个位置**。硬件代价中等，冲突大幅缓解。
- **全相联（fully associative）**：任何块可放任意位置。最灵活，但要全表比较，硬件最贵。

| 组织 | 一个地址的位置数 | 硬件代价 | 冲突未命中 |
| --- | --- | --- | --- |
| 直接映射 | 1 | 最低 | 最严重 |
| 组相联（4/8 路） | n | 中 | 明显缓解 |
| 全相联 | 全部 | 最高 | 几乎为零 |

**命中判定**：处理器把地址的「索引」部分查表，再用「标签」部分与缓存行里存的标签逐一比较，全部相等才算命中。**路数越高，需要同时比较的标签越多**——这也是组相联「查得慢一点点」的物理原因：标签比较器与多路选择器都上了关键路径。设计者常用「先查索引、后比标签」的流水化来隐藏这个延迟。

现代 L1 数据缓存普遍 8 路组相联，L2/L3 更高路数甚至动态分路——**「路数」是命中率与速度、面积、功耗之间的旋钮**。<span class="marginnote">地址的「索引」取中间位而非低位，正是为了避免「连续数组 + 低位索引」造成的系统性冲突——取中间位相当于给地址做了一次散列，把相邻块散到不同组。这与《数据结构》里散列函数的设计是同一思路。</span>

**块大小（block size）是另一个关键旋钮**：块越大，空间局部性利用越好（一次取更多），但冲突与污染也更重——一次 128 字节的取块可能把有用的行挤出去。现代设计把 L1 块定为 64 字节，是「空间局部性收益」与「污染代价」的折衷结果。块太大还意味着**未命中代价更重**（传输时间随块大小线性增长），所以「大块」要配合「流水化的缓存填充」才能不失控。

## 3 替换策略：放不下时踢谁

组内位置满时，新块必须**替换**某个旧块。策略决定「踢谁」：

- **LRU（最近最少使用）**：踢最久没被访问的。命中率最佳，但需要每路记录「新旧顺序」。
- **伪 LRU（pseudo-LRU）**：用一棵二叉树近似 LRU，省去满顺序记录——现代大缓存（L2/L3）的实际选择。
- **随机（random）**：任意踢一个。硬件几乎为零，命中率略低于 LRU，但对「循环访问」反而更稳。
- **FIFO**：先进先出，实现简单但容易误踢热点。

**直觉**：命中率排序约 LRU ≥ 伪 LRU > 随机 > FIFO；硬件代价则相反。在路数多的缓存里，「真 LRU」的代价过高，所以伪 LRU 与随机更常见。<span class="marginnote">替换策略与《操作系统》的页面置换（LRU、FIFO、时钟算法）一一对应——缓存与虚拟内存是同一套「替换哲学」在不同层的实现。唯一差别是硬件缓存无法承担 LRU 的逐路时间戳，只能用近似。</span>

近年研究还发现「**单一替换策略对所有程序都不最优**」：某些负载偏爱「保护流式数据」，某些偏爱「保护复用数据」。于是出现了**自适应替换（如 RDP、DRRIP）**——用饱和计数器在多种策略间切换，按「谁的未命中率低」选策略。这与第 3 篇锦标赛分支预测器的「选择器」哲学完全同构：**硬件里一切「策略选择」，都爱用饱和计数器当裁判**。

## 4 写策略：写回何时可见

读未命中要「取」，写未命中与写命中则要回答「什么时候写回主存」：

- **写直达（write-through）**：写命中时立即写主存（或写缓冲）。简单、一致性好，但带宽浪费。
- **写回（write-back）**：写命中只改缓存并标记「脏」（dirty），块被替换时才写回主存。省带宽，但要处理「脏块逐出」。
- **写分配（write-allocate）**：写未命中时先把块取进缓存再写——通常配合写回。
- **非写分配（no-write-allocate）**：写未命中直接写主存，不进缓存——通常配合写直达。

现代处理器 L1 数据缓存多用**写回 + 写分配**：把「写」也变成缓存内部的事，把主存带宽省给更值得的访问。<span class="marginnote">写回策略埋下的「脏块」是下一篇《缓存一致性》的导火索：多核时，两个核各自的缓存里可能有同一地址的「不同版本」。写直达让一致性简单、写回让一致性复杂——多核时代的一致性协议，本质上就是在给「写回 + 写分配」收拾残局。</span>

还有一个必须提的配套结构：**写缓冲（write buffer）**。写直达时处理器不必等主存写完成，把写请求放进写缓冲就继续跑；写回时脏块逐出也先入缓冲。**写缓冲让「写」不必立即阻塞流水线**，但缓冲满时仍会停顿——这也是乱序处理器「访存指令排队」的现实来源。它与第 5 篇的 ROB 一起，构成了「访存如何在乱序窗口里保持有序」的底层机制。

## 5 公式解析：平均访存时间（AMAT）

**平均访存时间（AMAT，Average Memory Access Time）** 是缓存性能的度量：

$$ \text{AMAT} = \text{命中时间} + \text{未命中率} \times \text{未命中代价} $$

- **第一步，读符号**：命中时间（hit time）是 L1 命中耗时（约 4–5 周期）；未命中率（miss rate）是未命中占比；未命中代价（miss penalty）是「从 L1 未命中到把数据取回」的全过程。
- **第二步，代入**：命中 5 周期、未命中率 5%、代价 200 周期，得 $\text{AMAT} = 5 + 0.05 \times 200 = 15$ 周期。
- **第三步，读结论**：**未命中率每下降一个百分点，AMAT 改善 2 周期**——缓存优化的所有努力（更大、更相联、更好替换）都是在压这个线性项。

这就是为什么「缓存越大、路数越多、替换越好」永远是存储层次的进化方向——它们在公式里是同一个线性减号。

**再进一步——多级缓存**：现代处理器把「未命中代价」拆成几级，L1 未命中找 L2、L2 未命中找 L3、最后才去主存。每一级只承担「上一级的未命中代价」的一小部分，配合**非包含/包含策略**与**逐级替换**，把 AMAT 从「一跳 200 周期」摊成「多跳渐进」。**存储层次的金字塔，在硅片里就是 L1/L2/L3/主存的阶梯**——下一节《预取》将在这个阶梯上再进一步：不等未命中发生，先把数据请进门。

## 6 小结

- **存储层次靠局部性**：时间 + 空间局部性让「小缓存、高命中」成为可能。
- 三种映射：直接 / 组相联 / 全相联——命中率与硬件代价互换。
- 替换策略：LRU / 伪 LRU / 随机 / FIFO——现代大缓存用伪 LRU 或随机。
- 写策略：写直达 vs 写回，写分配 vs 非写分配——现代 L1 用写回 + 写分配。
- AMAT = 命中时间 + 未命中率 × 未命中代价，是缓存优化的总账。
- 未命中分强制/容量/冲突三类，优化方向各自不同；块大小与路数是两个主旋钮。
- 写缓冲让「写」不必立即阻塞流水线，是乱序访存的地基。
- 自适应替换用饱和计数器当裁判，与分支预测的「选择器」一脉相承。
- 多级缓存把未命中代价摊成渐进阶梯，是金字塔的硅片形态。
- 写回埋下的「脏块」，正是下一节缓存一致性要收拾的局面。
- 标签比较器与多路选择器决定相联度的硬件成本，命中判定在关键路径上。
- 写缓冲衔接「写」与流水线，缓冲满时仍会停顿，是访存队列的现实来源。
- 直接映射的「颠簸」是经典反面教材，也是组相联存在的理由。
