## 为什么从固件开始

从「从极限到大模型」的主线看，我们已经在第三级读过操作系统、计算机组成原理与体系结构。操作系统课程的开篇通常假设「一台已经能跑的机器」：有可用的内存、有挂起的磁盘、有能输出的串口。可只要追问一句「这台机器是怎么变成能跑的」，就立刻触到了操作系统课程刻意绕开的那层代码——**固件（firmware）**。<span class="marginnote">本书第三章讲操作系统与虚拟机，第四章讲体系结构；固件是比它们都更深的一层，是 OS 程序真正看到的「冷启动现场」。</span>

固件这个词来自 1967 年一位普林斯顿工程师 Opler 的提议，本意是「既不像硬件那样焊死、又不像软件那样易变」的中间态。今天它的含义稳定下来了：**固件是直接与硬件交互、负责把平台从「上电复位」推进到「操作系统接管」的那部分代码**。它既不按普通软件的形态运行，也不完全等同于硬件逻辑，而是两者之间那张薄薄的、几乎不可见的分界面。

## 1 固件在整机中的位置

一台 x86 计算机的逻辑层次大致是这样叠起来的：

- **应用层**：浏览器、数据库、大模型推理框架；
- **操作系统内核**：进程调度、虚拟内存、文件系统；
- **固件层**：开机自检（POST）、初始化内存、枚举 PCIe 设备、准备 ACPI 表；
- **硬件层**：CPU、内存控制器、芯片组（PCH/SoC）、外设控制器。

<span class="marginnote">固件工程师常用「plumbing（管道）」自嘲：没人注意它，直到它漏水。可一旦固件漏水，漏水点往往在内存初始化与电源管理这些最底层的部位。</span>

操作系统程序员看固件，是透过 ACPI 表与 UEFI Runtime 服务；硬件工程师看固件，是透过芯片手册里的寄存器位域。两种视角都成立，合起来才是固件的全貌——它向下把芯片的手册翻译成「对 OS 可见的规范接口」，向上把 OS 的要求翻译回「对芯片的寄存器操作」。

**固件的本质是一次翻译**：一端是芯片厂商的私有编程指南，另一端是操作系统共同遵守的公开规范。

正因为夹在中间，固件工程师的日常与操作系统或应用工程师都不同：他们不写「算法」，而是反复对照**寄存器手册**、操作**时序**、处理**厂商私有二进制**。一次内存初始化、一次 PCIe 枚举，背后都是「把芯片手册的语言翻译成平台可见的行为」——这个翻译的成败，决定了 OS 之上的所有代码能站多稳。<span class="marginnote">这正是《Embedded Firmware Solutions》全书的方法论：固件工程师的日常，就是在一堆芯片手册（programming guides）与一套公开接口（UEFI/PI）之间来回搬运。</span>

## 2 上电复位：固件存在的第一个理由

「从零开始」在计算机里是个物理事实。按下电源键的瞬间：

1. 电源的 Power Good 信号稳定下来，复位控制器释放 RESET#；
2. x86 CPU 的复位向量（reset vector）指向 `0xFFFFFFF0`，也就是 4 GB 地址空间顶端以下 16 字节处；
3. 那里放着的不是操作系统，甚至不是 BIOS 主程序，而是一条无条件跳转指令；
4. 从这条跳转开始，之后所有代码都属于固件。

**固件要解决的核心矛盾是鸡与蛋**：初始化内存需要代码执行，而代码又需要内存才能运行。<span class="marginnote">这个矛盾贯穿整个启动链：SEC 阶段用 CPU 缓存当作临时内存（Cache-as-RAM，CAR），先跑起来一小段信任锚代码，再逐步把真正的 DRAM 点亮。</span>

如果固件在任何一个环节失败，系统就停在死寂的黑屏 POST code 上——没有操作系统什么事，因为操作系统根本还轮不到出场。

这段「从复位到 OS 的过渡期」在历史上被统称为 **POST（Power-On Self Test，开机自检）**。在传统 BIOS 时代，POST 是一连串顺序执行的检查——内存读写、键盘控制器、串并口、显卡；在 UEFI 时代，POST 被拆进 SEC/PEI/DXE/BDS 各阶段，不再是「一个测试程序」，而是一套**逐步构建运行环境**的过程。术语换了，但「固件负责在 OS 之前把平台准备好」这个职责始终没变。

## 3 固件放在哪里：从 ROM 到 SPI Flash

固件的存放介质决定了它的更新方式与安全边界。历史上依次出现过：

- **掩膜 ROM / PROM**：出厂焊死，想升级只能换芯片，IBM PC 初期的 BIOS 就是如此；
- **EPROM / EEPROM**：可擦写，但要在紫外线灯下照半小时（EPROM），或经并行接口逐字节编程；
- **NOR Flash**：今天的主流。SPI 接口把固件芯片挂在芯片组上，典型容量 8–32 MB，可按扇区擦写。

NOR Flash 之所以能当固件介质，是因为它支持**字节/短地址随机读**——CPU 复位向量取指令时，可以直接「按地址读内存」一样地读 Flash。它的容量演进也反映固件本身的膨胀：早期 286 时代 BIOS 只要 64 KB，今天一套完整的 UEFI 固件动辄 16–32 MB——安全启动密钥、驱动模型、固件诊断、甚至 mini 内核都被装了进去。这与 NAND Flash 完全不同：NAND 只能按页读、按块擦，必须在内存里先放一段搬移代码才能引导，所以手机与嵌入式设备要额外依赖 BootROM。

补充一个容易混淆的点：**固件区（Flash）与「内存盘」「U 盘」不是一回事**。固件 Flash 被芯片组当作「可执行区域」直接映射进 CPU 地址空间；而普通的存储设备（SSD、U 盘）只是「数据」，要读它们必须先有驱动。**「固件能被执行」与「数据能被读取」是两种截然不同的能力**——这是理解整个启动链的一把钥匙：BootROM 之所以特殊，正因为它在任何驱动存在之前就「能执行」。

### Flash 布局：固件芯片里装的不只是 BIOS

现代 x86 主板的 SPI Flash 并非「一个 ROM」这么简单，它通常按区域划分，最典型的是 Intel 平台的三段式：

- **Descriptor Region（描述符区）**：描述 Flash 的分区结构、访问权限与模式（是 Intel 的私有权衡区域，固件开发者常说的 `-a 0` 就是为它解锁）；
- **BIOS Region（BIOS 区）**：存放实际固件，也是我们整条启动链的载体；
- **ME Region（ME 区）**：存放 Intel ME 的固件镜像（见本专题《固件安全》）。

这三段各有独立的读/写/执行权限位，芯片组会强制执行。这带来一个工程含义：**「刷 BIOS」往往只刷 BIOS 区，而描述符与 ME 区一旦损坏，主板上电后可能连 BIOS 区都访问不到**——这也解释了为什么有的「刷砖」需要专用烧录器从芯片外部重写整个 Flash。

## 4 固件的现代谱系

「BIOS」是大众最熟悉的固件词，但它只是固件家族里的一支。今天平台固件大致分成四派：

| 流派 | 代表实现 | 典型载体 | 哲学 |
| --- | --- | --- | --- |
| 传统 BIOS | AMI/Insyde 的 Legacy BIOS | x86 台式机、工控 | 实模式、中断表、约定俗成 |
| UEFI | TianoCore/EDK II、AMI Aptio | 主流 PC、服务器、ARM 服务器 | 规范驱动、C 语言模块化、协议总线 |
| coreboot | coreboot + 各种 payload | Chromebook、服务器 | 极简、快、开源优先 |
| 引导加载程序 | U-Boot、TF-A、GRUB | 嵌入式、ARM SoC | 小而快，常与内核紧耦合 |

这张表还提醒我们：**固件的「级别」并不由容量或复杂度决定，而由「信任与启动顺序」决定**。GRUB 只有几十 KB，但它运行在 OS 之前、承担系统入口——它具备固件的角色属性；而一个 32 MB 的 UEFI 驱动包在 OS 之后运行时，反而退化为普通软件。

这四派并不互斥：coreboot 可以把 EDK II 当作 payload 加载，U-Boot 也可以作为 UEFI 下的 OS Loader。**把「固件」理解为单一程序，是外行的直觉；把它理解为一串可组合的引导层，才是工程师的心智模型。**

一个常被忽略的事实是：**「BIOS」这个词本身就是 1975 年 CP/M 时代发明的品牌术语**，它先于 IBM PC 存在；今天的工程师说起「刷 BIOS」，实际刷的很可能是一套 UEFI 固件。词在变、技术在变，但「第一段代码」的角色没变——这正是本专题整条线的起点。

## 5 核心对比表：固件与软件、硬件的边界

纯概念主题，本节用核心对比表代替公式解析。**判别「一段东西是不是固件」的标准，比名称重要得多**：

| 维度 | 硬件 | 固件 | 软件 |
| --- | --- | --- | --- |
| 存在形态 | 逻辑门、寄存器 | ROM 里的机器码 | 磁盘上的文件 |
| 谁启动谁 | 固件由硬件复位启动 | OS 由固件启动 | 应用由 OS 启动 |
| 变更手段 | 重新流片 | 在系统内擦写 Flash | 普通文件替换 |
| 故障后果 | 硬件 RMA | 变砖 / 需恢复 | 蓝屏 / 重启即可 |
| 更新权限 | 无 | 需签名的 capsule / 烧录器 | 任意用户 |
| 失效保护 | 不适用 | 双备份 / A/B 分区 | 重装系统 |

从这张表还能看出固件的另一个身份：**它既是「最需要被保护」的软件，也是「最难被保护」的软件**——它常驻 ROM、运行在最高特权、且在 OS 的防御体系之外。平台信任的起点（Secure Boot、TPM 度量）恰恰要从这一层开始，这也埋下了本专题后面几篇的伏笔。

一个常见的辨析点是：**引导加载程序（bootloader）算不算固件？** 严格说，GRUB 这类 OS Loader 属于「临时系统加载」阶段，运行在内存里、也常从文件系统读取——它更接近软件；而固件专指「持久驻留、在 OS 之前、直接操作硬件」的那层。<span class="marginnote">UEFI 规范的术语把这层边界定得很细：SEC/PEI/DXE/BDS 属于固件，TSL（OS Loader）与 RT（运行时）是 OS 世界的事务。我们在下一篇 x86 启动链里会把这几个阶段全部走一遍。</span>

## 6 小结

- 固件是**硬件与操作系统之间的那层代码**，负责把平台从上电复位推进到 OS 接管。
- 它要解决的根本矛盾是**鸡与蛋**：初始化内存需要代码，执行代码又需要内存——SEC 阶段用 Cache-as-RAM 先行一步。
- 固件存放在**SPI NOR Flash** 中，按地址随机读、按扇区擦写，这决定了它可原地升级。
- 现代固件有**四派谱系**：传统 BIOS、UEFI、coreboot 与嵌入式引导加载程序，彼此可组合。
- 判别固件的标准不是名字，而是**是否持久驻留、是否在 OS 之前、是否直接操作硬件**。
- 固件研究有一条清晰的纵深线：**操作系统课讲「OS 假设平台已就绪」，固件课回答「平台怎么才就绪」**——两者合起来，才是「从极限到大模型」第三级计算机系统知识的完整闭环。
