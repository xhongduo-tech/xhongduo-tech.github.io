## 为什么从传统 BIOS 开始

UEFI 再先进，也必须面对一个物理现实：**1981 年 IBM PC 定义的那套引导约定，四十多年来一直没彻底消失**。今天的服务器固件里，CSM（Compatibility Support Module）仍在为网卡 PXE、老显卡 ROM、旧版 Windows 提供一条返祖路径。理解传统 BIOS，不只是考古，而是理解「为什么现代固件里会残留着 16 位代码」。

传统 BIOS 的遗产集中在三个词上：**实模式**、**中断表**、**约定地址**。它们共同构成了一套「无规范，只有习惯」的接口——这正是 UEFI 要替换、又不得不兼容的东西。<span class="marginnote">《Embedded Firmware Solutions》第2章把 Legacy BIOS 与 UEFI/RTOS 并列比较，正是想说明：选择固件栈不是「新旧二选一」，而是理解各自约束后的权衡。</span>

## 1 实模式与 1 MB 的世界

8086 的地址总线只有 20 位，于是程序员被迫用「段 + 偏移」两段式表达地址。**段地址与物理地址的换算**是理解实模式的第一条公式：

$$
\text{物理地址} = \text{段} \times 16 + \text{偏移}, \qquad 0 \le \text{物理地址} < 2^{20}
$$

对这个公式做三步拆解：

- **第一步，为什么乘 16**：段寄存器是 16 位，物理地址是 20 位。把 16 位段值左移 4 位（乘 16）得到 20 位基址，再叠加 16 位偏移，就得到完整的 20 位物理地址。
- **第二步，`0xFFFF` 陷阱**：`段 = 0xFFFF, 偏移 = 0xFFFF` 时，`0xFFFF0 + 0xFFFF = 0x10FFEF` 超过 20 位。8086 会**回绕**到 `0x0FFEF`。A20 地址线的诞生（通过键盘控制器 8042 的第 2 脚控制第 21 根地址线）正是为了在 286 时代解决这个回绕问题。
- **第三步，由此得到的布局**：实模式下 BIOS 把内存低端规划成约定区域——中断向量表在 `0x00000`，BIOS 数据区在 `0x00400`，EBDA 扩展数据区在 `0x9FC00` 附近，BIOS ROM 映射到 `0xF0000`–`0xFFFFF`。**任何一段地址都是「约定」，不是「规范」**。

对初学者而言，最容易的误区是把「实模式」理解成「过时」。其实**实模式至今仍是 x86 上电后的初始状态**：所有 UEFI 固件的启动早期（SEC）都从实模式起步，再切进保护模式。读得懂实模式 = 读得懂启动的第一毫秒。

### 低端内存布局：一段被约定框死的 1 MB

把实模式的内存地图完整画出来，是理解 legacy 世界的捷径：

| 地址范围 | 内容 |
| --- | --- |
| `0x00000`–`0x003FF` | 中断向量表（IVT），1024 个中断向量 |
| `0x00400`–`0x004FF` | BIOS 数据区（BDA），放串口地址、键盘状态等 |
| `0x00500`–`0x9FBFF` | 常规内存（约 640 KB，DOS 的「领地」） |
| `0x9FC00`–`0x9FFFF` | EBDA（扩展 BIOS 数据区） |
| `0xA0000`–`0xBFFFF` | 显存窗口（VGA） |
| `0xC0000`–`0xDFFFF` | 可选 ROM（显卡、网卡、SCSI 卡） |
| `0xE0000`–`0xEFFFF` | 保留 / 系统 ROM 上部 |
| `0xF0000`–`0xFFFFF` | 系统 BIOS ROM |

这套布局的残酷之处在于：**可用的常规内存只有 640 KB**。DOS 程序、常驻内存（TSR）、驱动全挤在 `0x00500`–`0x9FBFF` 里——「640K 是不是对每个人来说都够了？」正是盖茨在 1981 年说过的那句著名（且被断章取义）的话。它解释了为什么 x86 上「高端内存」「EMS/XMS」这类奇技淫巧层出不穷：**内存不够，是实模式的第一性约束**。

## 2 BIOS 服务的接口：中断而非 API

BIOS 给上层程序的服务是**中断**，其中最著名的是软中断 `INT 10h`（视频）与 `INT 13h`（磁盘）。调用方把功能号放进寄存器 `AH`，把参数放进其他寄存器，然后执行 `INT`，BIOS 的向量表里对应的例程完成工作后返回。

这段历史的遗产今天依然可见：**MBR 分区表**、**引导扇区 512 字节**、**FAT12/16/32**、**INT 13h 扩展**（LBA 寻址）——现代存储与启动工具链全部建立在这套约定上。

### MBR：512 字节里的政治

**MBR（Master Boot Record）** 是传统 BIOS 引导的锚点，它的布局本身就是一段历史：

- **前 446 字节**：主引导代码——把「哪个分区是激活的」找出来，再加载它的引导扇区到 `0x7C00`；
- **分区表（Partition Table）**：4 条 16 字节的条目（这就是「主分区最多 4 个」的来历）；
- **结尾魔数 `0x55AA`**：引导代码的自检标志，很多老工具「按字节找 `55 AA`」判断是不是引导盘。

这 512 字节让「引导」变得极度脆弱：**任何一个字节被破坏，机器就停在「请插入系统盘」**。UEFI 用「从 EFI 系统分区加载 `.efi` 文件」取代了这套 512 字节魔法——文件系统天然健壮、可签名、可扩展。<span class="marginnote">传统 BIOS 的引导流程是：POST → 按 CMOS 里的启动顺序逐个试引导设备 → 读 MBR 的 512 字节到 `0x7C00` → 跳到那里。MBR 里的引导代码再继续加载分区引导扇区与内核。UEFI 则改为「从 EFI 系统分区的 `\EFI\BOOT\` 直接加载 `.efi` 文件」，绕开了 512 字节的全部限制。</span>

值得留意的是 `0x7C00` 这个「魔法地址」：为什么引导扇区要放在这里？因为**它要给后续的引导代码让出足够的空间**——`0x7C00` 之上到 640 KB 之间有约 635 KB 给第二级引导与内核映像。这个数字同样来自 1981 年的约定，今天 U-Boot、GRUB 的早期代码仍会沿用类似的「固定加载地址」思路，只不过把它们写进自己的头文件而不是中断表。

**易错点｜辨析：** 很多人以为「BIOS 升级」「刷 BIOS」刷的是整个 ROM。实际上传统 BIOS 由 POST 程序、设备 ROM（Option ROM，网卡/显卡自带）与 Setup 程序组成；系统 BIOS 在 Flash 高地址段，Option ROM 在 `0xC0000`–`0xEFFFF` 的保留区，两者通过 `INT` 与共享数据结构协作。刷 BIOS 只是替换其中一部分，其余约定区域原封不动。

## 3 CSM：UEFI 里的返祖通道

**CSM（Compatibility Support Module，兼容支持模块）** 是 UEFI 固件中可选的一段代码，负责在 UEFI 环境里重新提供传统 BIOS 的接口。它的存在让以下老世界仍然可用：

- 从传统 MBR 磁盘引导旧版 Windows（Windows 7 及更早）；
- 加载无 UEFI 驱动的显卡/网卡 Option ROM；
- 为操作系统提供 `INT 10h`/`INT 13h` 等传统调用入口。

历史上 INT 13h 的接口还推动过一场「容量竞赛」：最早的 CHS 寻址只认到 8.4 GB，后来规范在 `0x41` 检测「INT 13h 扩展」，支持 LBA 寻址后一路突破 137 GB 等里程碑。**每突破一个容量上限，都是 BIOS 接口被扩展一次**——这就是「约定式接口」的宿命：永远在被容量追着跑。

CSM 由 UEFI 规范附录 A 定义（最初源自 Intel 与 Microsoft 联合开发的 Compatibility Support Module 规范），结构上分 Boot Support 与 Runtime Support 两大块。Boot Support 负责「UEFI 环境里模拟传统引导」（提供 legacy Option ROM 环境、MBR 引导路径），Runtime Support 负责「OS 运行期仍提供传统中断」（老驱动在 Windows 里还能用 INT 13h 访问硬盘）。

这里有一个工程上的死结值得体会：**CSM 必须让「传统引导路径」与「UEFI 安全模型」共存，而两者在根本上互斥**。传统 Option ROM 的代码无法被签名验证（它是 16 位裸汇编），Secure Boot 无法度量它；于是几乎所有固件在开启 Secure Boot 时强制关闭 CSM，反之亦然。**「你要老兼容，就不能要强安全」——这是 CSM 无法两全的宿命**。<span class="marginnote">CSM 的实现相当微妙：它要「在 UEFI 的现代世界里重现 16 位环境」，于是固件必须能在保护模式与实模式之间反复切换。这就解释了为什么很多主板在开启 CSM 后 UEFI Secure Boot 就自动变灰——安全签名链与 16 位中断调用在哲学上互斥。</span>

## 4 遗产为什么消失得这么慢

用「对比 + 归因」来看这段历史，比单纯记年代更有价值：

| 遗产 | 还在哪里 | 为什么没消失 |
| --- | --- | --- |
| MBR 分区 | 老磁盘、部分兼容设备 | 工具链与旧系统依赖 |
| 512 字节引导扇区 | 引导流程默认 | BIOS 时代遗留约定 |
| `INT 13h` 扩展 | PXE、部分 RAID 卡 | Option ROM 老驱动 |
| A20 线 | 所有 x86 启动早期 | 实模式回绕的历史修补 |
| CMOS/RTC | 所有主板 | 廉价、久经考验 |

原因概括起来是三个「不想」：**旧硬件不想被遗弃**（很多工控设备还在用 2000 年代的主板）、**旧 OS 不想被淘汰**（Windows 7 在特定行业仍是硬需求）、**旧工具链不想被重写**（厂商的 Option ROM 代码常年没人维护）。

另一个隐藏推手是**引导扇区的病毒史**：从 1990 年代的 Stoned、Michelangelo，到后来的引导区蠕虫，恶意代码长期寄生在 MBR 与引导扇区里——它们在实模式下直接获得最高权限，杀毒软件在 OS 里根本看不见它们。**MBR 是传统 BIOS 信任模型的阿喀琉斯之踵**：无法签名、无法度量、OS 无法察觉。这正是 UEFI Secure Boot 与 TPM 度量启动（见本专题相关各节）要根除的核心问题。

不过趋势是明确的：Intel 已在部分平台固件里**默认禁用甚至移除 CSM**；2020 年后新出的主板普遍以 UEFI-only 引导为默认，CSM 从「开箱即用」退化为「兼容开关」。

回望这段历史，BIOS 生态本身的公司史也很有意思：**Phoenix 成立最早（1979 年）**，几乎定义了「兼容 BIOS」这门生意；**AMI（1985 年）与 Award（1983 年）**随后入场，Award 后来被 Phoenix 收购，AMI 至今仍是服务器/主板 BIOS 与 UEFI 固件的主力供应商。<span class="marginnote">「BIOS 是每家主板都差不多的黑盒」的直觉，正是这几家厂商「逆向 1981 年 IBM PC 的 POST 流程、做成兼容实现」塑造的。今天它们都已转向 UEFI，但品牌与代码资产仍在——读主板固件时，`AMI Aptio` 这类字样就是它们的痕迹。</span>**遗产的价值在于它解释了现在，而不在于它定义了未来。** 对学习而言，研究 legacy 的意义不是「回去写 16 位代码」，而是**获得一把解释当代的钥匙**：为什么 UEFI 要设计成那样、为什么引导扇区是 512 字节、为什么很多老工具还在用 `0x7C00` 与 `55 AA`。先有这些「为什么」，后面读 UEFI 规范才会处处有来处。

## 5 小结

- 传统 BIOS 建立在**实模式**上：地址用「段 × 16 + 偏移」计算，20 位地址空间下一切靠**约定区域**。
- BIOS 的服务是**中断**（`INT 10h`/`INT 13h`），MBR 512 字节引导扇区与 FAT 文件系统都是这套约定的产物。
- **CSM** 是 UEFI 固件里的兼容层，为老 Option ROM 与旧版 Windows 保留传统接口。
- 遗产消失慢的原因：**旧硬件、旧 OS、旧工具链**三方惯性互相锁定。
- 趋势是 UEFI-only：CSM 逐步默认关闭，安全启动要求更是加速了这一进程。
- 传统 BIOS 的信任模型（无法签名、无法度量的 MBR/引导扇区）是它被取代的深层原因——病毒史与 rootkit 史共同证明了这一点。
- 学习 legacy 的价值在「解释现在」：512 字节引导扇区、`0x7C00`、`55 AA`、MBR 四主分区等约定，至今仍潜伏在工具链与文档里。

在下一节，我们从「兼容」转向「信任」：安全启动的签名链、TPM 度量启动与平台信任根——这是固件从「让机器跑起来」升级为「让机器可信地跑起来」的关键一跃。它要根治的，正是本节反复出现的 legacy 遗产：**无法签名、无法度量的引导路径**。
