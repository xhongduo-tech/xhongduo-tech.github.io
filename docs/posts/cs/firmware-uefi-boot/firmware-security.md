## 为什么从固件安全开始

我们已经反复强调固件是「第一段代码」——而安全世界的第一法则就是：**先于一切运行的程序，决定一切程序的命运**。固件若被攻破，重装操作系统、重刷驱动、杀毒软件全都无效，因为攻击者藏在所有 OS 防御之下。这一节直面三件事：固件为什么是最高价值目标、真实存在的 BIOS rootkit、以及独立安全处理器（Intel ME/AMD PSP）引发的争议。

对《Embedded Firmware Solutions》读者，这是第8章「Putting It All Together」里把工程问题升维到安全问题的部分——当你在第3、4章构建固件时，每一行代码都在为平台信任基线负责。<span class="marginnote">一个反直觉的事实：<strong>重装系统杀不掉固件木马</strong>。系统重装只覆盖磁盘，而固件驻留在 SPI Flash 里，OS 的磁盘工具根本够不到它——这正是「固件安全的攻击面 > OS 攻击面」的根源。</span>

## 1 攻击面：固件在哪一层被攻击

固件攻击的入口大致有四类：

- **OS 提权后写 Flash**：攻击者拿到内核/驱动权限后，通过 SPI 接口直接改写固件区——不需要任何硬件操作；

**固件攻击的门槛其实不高**：许多研究已经证明，只要拿到内核权限，配合芯片组文档里公开的 SPI 编程接口，写一个「改写固件」的工具并不比写一个 rootkit 难多少。真正的门槛在**能不能躲过检测**（写坏会被发现、写脏会被固件自检拒绝）——所以固件攻击者真正追求的，是「改得隐蔽、且能跨重启存活」：这正是 LoJax 这类 rootkit 的生存逻辑。
- **固件更新通道被劫持**：如果更新链的签名/版本校验有漏洞（见《固件更新机制》），恶意镜像可冒充合法更新；
- **SMM 漏洞**：SMM（System Management Mode）运行在最高特权环，驻留内存且对 OS 不可见；SMM 代码一旦被溢出利用，就是永久的隐形后门；
- **供应链投毒**：固件在出厂/更新环节被植入——这正好呼应开源固件运动（见《开源固件》）对供应链透明化的追求。

供应链风险在现实中一再上演：**2018 年的「ShadowHammer」**事件中，攻击者一度劫持了华硕官方固件更新服务器的签名推送渠道，把后门装进「官方」更新的固件里。**「有签名的更新」不等于「可信的更新」**——如果签名私钥失守，信任链就反向服务于攻击者。这也解释了为什么「签名 + 版本 + 供应源 + 审计」必须同时在线。

**辨析｜易错点：** 很多人以为「BIOS 安全 = Secure Boot 开了就行」。Secure Boot 只验证引导镜像，**防不了已经运行中的 OS 提权后直接改 Flash，更防不了 SMM 内的漏洞**。Secure Boot 是信任链的**第一环**，不是唯一环。

## 2 真实案例：LoJax 与 SMM rootkit

固件 rootkit 不再是理论。最著名的实例是 **LoJax**（2018 年被 ESET 披露，属 Sednit/APT28 组织）：

- 它利用合法的 **LoJack（反盗版软件）固件模块**机制：LoJack 本身就把一个小模块烧进 UEFI ROM，用于「笔记本被盗后仍能定位」——这给了恶意软件一条现成的「写固件 + 每次启动自愈」的通道；
- 攻击者把恶意模块替换进去，于是**即使重装磁盘，恶意代码也随每次开机复活**；
- 检测它需要比对固件 ROM 的哈希——而多数用户的固件镜像根本没有基线存档。

检测固件 rootkit 也因此成了「基线问题」：`fwupd`/厂商工具能导出当前 ROM 的哈希，但「没有原始基线」就无法判断是否被改。**企业安全团队的固件策略，往往从「建立并保存每台机器固件的出厂基线」开始**——没有基线，检测就是空谈；这也是本专题《固件更新机制》里「固件基线监测」一说的延续。

SMM 方向更隐蔽。SMM 代码驻留在 **SMRAM**，这段内存对操作系统完全不可见；如果平台固件里的 SMM 驱动存在缓冲区溢出，攻击者可通过 `SMI` 中断注入代码，拿到**比内核更高的执行特权**且无法被 OS 察觉。SMM 攻击不是纯理论：2011 年的 **Duqu** 木马就借用了 SMM 侧的路径潜伏；多年来各厂商在 SMM 驱动里被反复报出可被利用的越界读写（这些常以 **CVE + SMM 相关编号**公开）。**「SMM 是比内核更深的隐藏层」既是它的价值，也是它的风险**。<span class="marginnote">防御思路是「把 SMRAM 锁死」：平台在 DXE 阶段对 SMRAM 做「锁定（locking）」，令其在运行期不可被配置/映射。EDK II 里有专门的 SMM access validation 与 SMRAM lock 代码路径，值得读源码的读者重点看。</span>

## 3 独立安全处理器：Intel ME 与 AMD PSP

现代 x86 平台都内置一个**与主 CPU 无关的独立协处理器**，它有自己独立的固件、独立的内存、独立的网络栈：

- **Intel ME（Management Engine）**：一个跑在 PCH 上的小型 x86 核心，运行 Minix 系统，支持 AMT 远程管理。它的固件大部分闭源；
- **AMD PSP（Platform Security Processor）**：一颗 ARM 核心，负责安全启动、密钥管理与平台信任根；
- 服务器另有 **BMC（基板管理控制器）**，负责带外管理（IPMI/Redfish）。

这些协处理器的**带外能力**是双刃剑：ME 的 AMT 与 BMC 的专用网口意味着「机器关机/系统崩溃时仍能远程管理」——这在运维上是救命稻草，在安全上则是「不受 OS 控制的第一跳」。历史上针对 BMC/IPMI 的漏洞研究（如无认证 RCE）屡见不鲜，**「带外」的每一分便利，都对应「带外」的每一分暴露**。

这些处理器的争议在于 **「必要的信任」与「不可审计的黑盒」之间的张力**：

- 支持者说：它们提供了**独立于 OS 的信任根**，Secure Boot、密钥管理、远程修复都依赖它；
- 批评者说：闭源固件 + 网络接入 = 无法审计的超特权后门。历史上一度出现 **INTEL-SA** 系列 ME 漏洞（如 CVE-2017-5689，可导致 ME 被攻破后**无法恢复**），而 ME 固件即使重刷也常在主板深处残留。

**核心对比表**（纯概念主题，以表代替公式）：三种平台级安全协处理器的边界：

| 维度 | Intel ME | AMD PSP | BMC |
| --- | --- | --- | --- |
| 内核 | 微型 x86 | ARM | ARM/自研 |
| 主要用途 | 远程管理、信任根 | 信任根、密钥 | 带外管理 |
| 独立网络 | 有（AMT） | 无 | 有（专用网口） |
| 固件开源度 | 极低 | 较低 | 厂商各异 |
| 争议焦点 | 闭源 + 网络 | 闭源 | 带外后门 |

<span class="marginnote">一个看待 ME/PSP 的务实角度：它们既不是「必然的后门」，也不是「无代价的守护神」，而是<strong>平台厂商在「远程可管理性」「可信根」「审计透明度」三者间的取舍</strong>。真正的安全评估，应该看固件能否被审计、能否被更新、能否被隔离——而非只看「有没有一个独立处理器」。</span>

**易错点｜辨析：** 这些协处理器**不是「后门」的同义词**。它们的信任边界是平台设计者的选择：有网络栈的 ME/BMC 暴露面更大，纯本地信任根的 PSP 更收敛。**判断标准永远是谁能读它的固件、谁能改它的配置、它能否独立触网**。

## 4 固件安全怎么做：纵深防御清单

把前面的机制串起来，现代平台固件安全的基本盘是：

1. **Secure Boot + 度量启动**：管执行、留审计（见《安全启动》）；
2. **SMRAM 锁定与 SMM 加固**：堵住最高特权环的入口；
3. **安全更新链**：签名、防回滚、A/B 双槽（见《固件更新机制》）；
4. **固件基线监测**：保存出厂/最新 ROM 哈希，定期比对，捕捉 LoJax 式替换；

这条「基线监测」在实践里有成熟工具：Intel 开源的 **CHIPSEC** 能扫描固件配置、检查 SMRAM 锁与 SPI 保护位；`chipsec_main` 一跑，平台「该锁的有没有锁、该关的有没有关」一目了然。**「让固件可被检查」是防御的第一步**——检查不了的黑盒，就是攻击者的后花园。
5. **平台信任根**：让 ME/PSP 承担密钥与启动验证，同时用固件安全审计压减闭包面积。

还有一个 2018 年后人人皆知的连接：**Spectre/Meltdown 类 CPU 漏洞的缓解，很大一部分经微码更新发布，而微码由固件加载**。于是「更新 BIOS」成了「修 CPU 漏洞」的常规途径——**固件安全与 CPU 安全在微码这一层合流**，也让「BIOS 更新」从冷门操作变成了安全运维的日常动作。

<span class="marginnote">安全界的经典结论在此同样成立：<strong>没有银弹</strong>。Secure Boot、SMRAM 锁、签名更新各堵住一段，合起来才构成「从 Flash 到 OS 的纵深」。固件安全不是开关，而是和《固件更新机制》一样，是一个持续的过程。</span>

## 5 平台信任的工程进展

固件安全的「基本盘」之外，平台级信任还在往更深处演进：

- **Intel TXT（可信执行技术）**：在启动早期「测量并验证」主板、BIOS、OS 引导器，用「密封（seal）」机制把密钥只交给「已验证干净」的环境——这是 Measured Boot 在芯片层的强化；
- **SGX（软件保护扩展）**：把应用放进「飞地（Enclave）」加密内存，即使内核被攻破也读不到飞地内容；
- **TDX（可信域扩展）**：把整台虚拟机放进硬件隔离的可信域，配合远程证明让「云端租户信任物理机」——它正是本专题《安全启动》里「远程证明」在云场景的落地。

<span class="marginnote">这三者的共同底座，都依赖本节讲的「启动信任链 + TPM 度量」：没有可信的启动，TXT/SGX/TDX 的「信任承诺」就没有立足点。<strong>固件安全不是某个特性，而是所有上层可信机制的基石</strong>。</span>

## 6 小结

- 固件是「第一段代码」，**重装系统杀不掉固件木马**——这是固件攻击面高于 OS 的根本原因。
- 真实威胁分四类：**OS 提权写 Flash、更新链劫持、SMM 漏洞、供应链投毒**。
- 攻击门槛其实不高：内核权限 + 公开的 SPI 文档就能写固件，真正的壁垒在「隐蔽 + 跨重启存活」。
- **LoJax** 借 LoJack 固件通道复活；**SMM rootkit** 藏在 OS 不可见的 SMRAM 里。
- **Intel ME / AMD PSP / BMC** 是独立的平台协处理器，争议核心是「必要信任 vs 不可审计」。
- **带外能力**（ME 的 AMT、BMC 的专用网口）每多一分便利，就多一分不受 OS 控制的暴露面。
- **ShadowHammer** 警示：签名私钥失守会让「官方更新」反向成为后门通道——「有签名」≠「可信」。
- **CHIPSEC** 等工具让「固件锁没锁好」可被检查——「让固件可被审计」是固件防御的第一步。
- 防护是纵深：Secure Boot + 度量启动 + SMRAM 锁 + 安全更新链 + 固件基线监测。
- **SMM 是比内核更深的隐藏层**：Duqu 与历年的 SMM CVE 证明「OS 防御够不到它」，SMRAM 锁定是必要防线。
- **TXT/SGX/TDX** 等平台信任技术的可信底座，全部建立在「可信启动 + TPM 度量」之上。
- 务实视角：ME/PSP 不是「必然的后门」也不是「无代价的守护神」，安全评估看的是固件能否被审计、被更新、被隔离。
