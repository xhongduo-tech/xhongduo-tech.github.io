## 为什么从变量、类型与函数开始

上一课的猜数游戏里，我们已经见过 `let`、`u32`、`fn main()` 这些语法零件。这一章把它们拧成系统：**变量**是数据命名的机制，**类型**是数据在内存中的形状约定，**函数**是把操作封装成可复用单元的手段。这三者几乎是所有编程语言的公共底座——Rust 的特别之处在于，它在这三层里塞满了「默认安全」的立场：变量默认不可变、整数溢出在调试模式默认 panic、类型在编译期精确到字节。<span class="marginnote">把「默认不可变」「默认安全」读进骨髓，是理解 Rust 一切设计的钥匙。相比之下，C 的 `int` 在不同平台宽度不定、Python 的整数无限增长——Rust 在这两者之间选择「显式、精确、可预测」。</span>

## 1 变量与可变性

### 不可变是默认

`let` 声明变量，默认**不可变（immutable）**。尝试给不可变变量重新赋值，编译器直接报错 `cannot assign twice to immutable variable`：

```rust
let x = 5;
x = 6; // 编译错误：x 不可变
```

这不是对开发者的说教，而是**并发安全的基石**：如果数据不可能被修改，就不存在「两个线程同时写」的数据竞争。Rust 把「能否被修改」提升为编译期可检查的属性，而非运行期的纪律。<span class="marginnote">这与 Java 的 `final`、C++ 的 `const` 神似但更彻底：Rust 的不可变是编译期强制的默认值，可变需要显式 `mut`。在第三级《并发与并行编程》中我们会看到，这个默认值如何让数据竞争在编译期绝迹。</span>

需要可变时用 `mut` 声明：

```rust
let mut y = 5;
y = 6; // 合法
```

### 常量：编译期就固定

与不可变变量不同，**常量（const）**用 `const` 声明，值必须在编译期确定，且必须标注类型：

```rust
const MAX_POINTS: u32 = 100_000;
```

常量与不可变变量的本质差别在于：常量是「编译期就写死在代码里的字面值」，可以出现在任意作用域（包括全局）；不可变变量是「运行期绑定一次就不可改的盒子」。下划线 `100_000` 只是字面量的视觉分隔，不改变数值。

### 遮蔽：同名新绑定

`let` 可以用同名声明**遮蔽（shadow）**之前的绑定，新绑定接管名字：

```rust
let x = 5;
let x = x + 1;
let x = x * 2;
```

每一步都产生新的不可变绑定，旧值不可达。遮蔽与 `mut` 的区别很微妙但关键：`mut` 是**原地修改**同一个绑定；遮蔽是**创建新绑定**，类型都可以改变。猜数游戏里把字符串 `guess` 遮蔽为数字 `guess`，用的正是这条特性。

## 2 标量类型与复合类型

Rust 是**静态强类型**语言：每个变量在编译期都有确定的类型。类型分两类——**标量（scalar）**代表单个值，**复合（compound）**把多个值组合在一起。

### 整数类型

Rust 的整数类型按「位数 × 符号」两维展开：

| 位数 | 有符号 | 无符号 | 取值范围（有符号） |
| --- | --- | --- | --- |
| 8 | `i8` | `u8` | $-2^7$ 到 $2^7-1$ |
| 16 | `i16` | `u16` | $-2^{15}$ 到 $2^{15}-1$ |
| 32 | `i32` | `u32` | $-2^{31}$ 到 $2^{31}-1$ |
| 64 | `i64` | `u64` | $-2^{63}$ 到 $2^{63}-1$ |
| 128 | `i128` | `u128` | $-2^{127}$ 到 $2^{127}-1$ |
| 机器字 | `isize` | `usize` | 随平台（64 位机即 64 位） |

**`i32` 是整数默认类型**，`usize` 是数组索引与内存大小的专用类型。位数的选择不是随意的：`u8` 恰好装 0–255（适合字节），`usize` 与指针同宽（适合地址）。<span class="marginnote">这套精确到位的整数体系与 C 语言几乎一致，但 Rust 强制你在「溢出」问题上表态：调试模式溢出会 panic，发布模式按补码回绕——除非显式用 `wrapping_add` 等方法声明「我就是要回绕」。这避免了 C 里无数由静默溢出引发的安全漏洞。</span>

### 浮点与布尔

浮点有两种：**`f32`** 与 **`f64`**（默认），分别对应 IEEE 754 单精度与双精度。布尔是 **`bool`**，取 `true`/`false`；字符是 **`char`**，用单引号，**大小为 4 字节**，能表示 Unicode 标量值——这比 C 的 `char`（1 字节）与 C++ 的 `char16_t` 都要统一，代价是字符串的内存布局需要单独设计（见第8篇《常用集合》）。

### 元组与数组

**元组（tuple）**是把不同类型组合在一起的定长复合类型：

```rust
let tup: (i32, f64, u8) = (500, 6.4, 1);
let (a, b, c) = tup;        // 解构（destructuring）
let first = tup.0;          // 索引访问
```

**数组（array）**是**同类型、定长、栈上连续**的复合类型：

```rust
let arr: [i32; 5] = [1, 2, 3, 4, 5];
let zeroes = [0; 10];       // 10 个 0
let first = arr[0];
```

数组与切片（slice）的边界检查是编译期 + 运行期双层保证的：越界索引在运行期 panic，而不是像 C 那样读越界内存——这直接消灭了一整类缓冲区溢出漏洞。

## 3 函数：参数、返回与表达式

### 函数声明与参数

函数用 `fn` 声明，参数必须标注类型：

```rust
fn print_sum(a: i32, b: i32) {
    println!("sum = {}", a + b);
}
```

**每个参数都标类型**是 Rust 的强制性约定，与 C 一致；类型标注让编译器在函数签名处就完成大部分检查，也让阅读者无需猜测。

### 表达式与语句

这是 Rust 函数里最重要的一个区分，也是最容易混淆的：

**语句（statement）**：执行动作、不产生值，以分号结尾，如 `let x = 5;`。
**表达式（expression）**：计算并产生值，**不以分号结尾**，如 `a + b`、`x * 2`、甚至整个 `if` 块与 `match` 块。

**函数的最后一个表达式就是返回值**，无需 `return`；`return` 关键字用于提前返回：

```rust
fn add_one(x: i32) -> i32 {
    x + 1        // 无分号：这是返回值
}

fn early(x: i32) -> i32 {
    if x < 0 {
        return 0;   // 提前返回
    }
    x * 2
}
```

把 `x + 1` 误加分号是新手最常见的错误——编译器会报 `mismatched types`，因为语句 `x + 1;` 的类型是 `()` 而不是 `i32`。<span class="marginnote">这个「表达式即值」的模型来自函数式语言（ML 家族、Lisp），Rust 继承了它却保持命令式外观。到第13篇《闭包与迭代器》、第15篇《智能指针》时，你会发现几乎所有控制结构都能当表达式用，这正是 Rust 表达力的一部分。</span>

### 显式返回值类型

函数签名用 `-> 类型` 声明返回类型。返回类型不只是文档，还参与类型检查——**函数返回什么、调用处如何使用，编译器都会核对**。

## 4 公式解析：整数范围与类型选择

把整数的范围写成集合，一切边界都清楚了：

$$
i8 \text{ 的值域} = \{ n \in \mathbb{Z} \mid -128 \le n \le 127 \}
$$

拆解三步：

- **第一步，为什么是 $-2^{7}$ 到 $2^{7}-1$**：8 位二进制有 $2^8 = 256$ 种组合。补码表示下，最高位为符号位，非负部分 $0$ 到 $2^7 - 1$ 共 128 个，负数部分 $-1$ 到 $-2^7$ 也共 128 个，于是总范围是 $[-2^7, 2^7-1] = [-128, 127]$。
- **第二步，无符号就是没有符号位**：`u8` 的 256 种组合全部用于非负，范围 $[0, 2^8-1] = [0, 255]$。同一个 8 位模式 `0b1111_1111`，作为 `i8` 是 $-1$，作为 `u8` 是 $255$——**解释方式由类型决定**。
- **第三步，如何选**：数值不可能是负数选无符号；可能为负选有符号；不确定时 `i32` 是安全默认。计数、索引、长度这类「非负且可能很大」的量，优先 `usize`——它与指针同宽，保证「数组长度放得下」。
