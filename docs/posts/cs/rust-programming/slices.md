## 为什么从切片开始

上一课我们学会了 `&` 与 `&mut`，但「借用一整块数据」仍然太粗。实际问题常常是「只想看一段」：取字符串的前 5 个字符、读数组的第 2 到第 4 个元素。**切片（slice）**就是「引用一个连续序列中的一段」的引用形式——它不拥有数据，只记录「从哪开始、多长」两个信息。切片的意义不在于语法花哨，而在于它让「引用数组/字符串的一部分」这件事变得**类型安全**：切片类型直接编码了「这是只读的一段」，越界问题在编译期与运行期都被兜住。

## 1 字符串切片：`&str` 的完整含义

### 切出子串

字符串切片就是对 `String` 的一段引用：

```rust
let s = String::from("hello world");

let hello = &s[0..5];   // "hello"
let world = &s[6..11];  // "world"
```

`&s[0..5]` 读作「借用 `s` 的第 0 到第 4 个字符」。区间 `[0..5]` 是半开区间：**含 0，不含 5**，取 5 个字节。`&s[6..11]` 取 6 到 10，也是 5 个字节。

切片的内部表示极简：**一个起始指针 + 一个长度**。`hello` 知道「从 `s` 的地址 + 0 开始，共 5 字节」，`world` 知道「从 `s` 的地址 + 6 开始，共 5 字节」。它不复制任何字符——只是「看着」`s` 里的一段。

### 省略写法

区间可以省略边界，让编译器推断：

```rust
let s = String::from("hello world");

let len = s.len();          // 11
let first = &s[..5];        // &s[0..5]，从开头
let last  = &s[6..];        // &s[6..len]，到结尾
let whole = &s[..];         // &s[0..len]，整段
```

**`&s[..]` 就是「借用整个字符串」**，它与 `&s` 等价。`&str` 这个类型之所以处处出现，正因为切片如此自然——任何对字符串的「看一眼」操作，返回的都是 `&str`。

### 字节边界：中文切片的坑

字符串切片按**字节**索引，不是按字符。一个 `char` 在 UTF-8 编码下可能占 1–4 字节，中文字符占 3 字节。如果在字符边界中间切开，程序会 panic：

```rust
let s = String::from("你好世界");
let bad = &s[0..1];   // panic：切在 "你" 的字节中间
```

`"你好世界"` 每个字 3 字节，总长 12 字节。`&s[0..1]` 只取到「你」的 3 字节中的 1 字节，不是合法 UTF-8，Rust 在运行期直接 panic 而不是返回乱码。<span class="marginnote">这正是 Rust「要么不做、要做就做对」的立场：C 语言会静默返回半个字符的乱码字节，Python 的字符串直接按字符索引所以没有这个问题。Rust 选择「字节索引 + 运行期边界检查」，把「切错了」变成可发现的 panic，而不是静默的损坏。</span>

安全的做法是用 `chars()` 遍历字符或按字符边界找位置：

```rust
let s = String::from("你好世界");
let first_two: String = s.chars().take(2).collect();  // "你好"
```

## 2 其他切片：数组与 Vec

切片不止适用于字符串，任何连续序列都能切。**数组切片**是 `&[T]`：

```rust
let a = [1, 2, 3, 4, 5];

let slice = &a[1..3];      // &[i32]，内容是 [2, 3]
```

`slice` 的类型是 `&[i32]`——对数组一段的只读引用。数组切片同样记录「指针 + 长度」，不复制元素。`Vec` 也可以切：`&vec[..]` 得到 `&[T]`，这正是「把拥有的动态数组降级为借用的切片视图」的惯用操作。<span class="marginnote">`String` ↔ `&str`、`Vec<T>` ↔ `&[T]` 是两对平行的「拥有/借用」关系。函数参数用切片视图（`&str`/`&[T]`）而非拥有类型（`String`/`Vec<T>`）是最佳实践：调用者传什么都行，函数不需要所有权。</span>

统一的心智是：**切片是一段连续内存的只读窗口**。不管是字符串、数组还是 `Vec`，切片都只认「起始 + 长度」两个数字。

## 3 切片作为函数参数

切片最常见的用途是作为函数参数——让函数能处理「任意来源的一段文本」：

```rust
fn first_word(s: &str) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    &s[..]
}

fn main() {
    let s = String::from("hello world");
    let word = first_word(&s);   // "hello"
}
```

这个函数返回「第一个单词」。它接收 `&str`，意味着调用时传 `&s`（`String` 的引用可自动转为 `&str`）或字面量 `"hello"` 都可以。

注意返回类型 `-> &str`：**返回的切片借用了参数的数据**。Rust 的借用检查器保证：`word` 存在期间，`s` 不能被修改——因为 `word` 是 `s` 的一部分的引用。这就是「引用必须始终有效」在切片上的体现：切片是借用，借用的数据必须先活着。<span class="marginnote">把 `first_word(&s)` 换成返回 `String`（拷贝一份单词）也可以，但代价是堆分配。返回 `&str` 则零拷贝——这是 Rust 高性能代码的常态：能借用就借用，需要拥有时才分配。</span>

如果用旧的索引式写法（返回 `usize` 结束位置），会留下悬空的隐患：索引被保存，但字符串可能被修改导致索引失效。切片类型把「这段数据 + 它属于谁」绑定在一起，让编译器替你保证一致性。

## 4 核心对比：切片与拥有的数据类型

| 维度 | `String` | `&str` | `Vec<T>` | `&[T]` |
| --- | --- | --- | --- | --- |
| 所有权 | 拥有 | 借用 | 拥有 | 借用 |
| 内存 | 堆上字符 + 栈上元数据 | 指针 + 长度 | 堆上元素 + 栈上元数据 | 指针 + 长度 |
| 可变性 | 可增删改 | 只读 | 可增删改 | 只读 |
| 典型用途 | 拼接、修改文本 | 读取、参数、字面量 | 动态数组 | 只读序列参数 |
| 是否可复制 | 否（移动） | 是（`&str` 是 `Copy`） | 否（移动） | 是（`&[T]` 是 `Copy`） |

有趣的是最后一行：**引用（包括切片）本身是 `Copy` 的**。因为引用不拥有数据，复制一个引用只是多一张「地图」，不涉及堆内存的复制。所以 `&str`、`&[T]`、`&T` 都实现 `Copy`，传值等于传引用，零成本。而 `String`、`Vec<T>` 拥有数据，不能 `Copy`，只能移动。

## 5 公式解析：切片的长度与字节偏移

切片的一切都归结为两个数——起始字节偏移与长度。设 `s` 是某字符串，切片 `&s[a..b]`：

$$
\text{切片} = (\text{ptr} + a, \ b - a)
$$

拆解：

- **第一步，起始偏移 $a$**：切片从 `s` 的字节地址加 $a$ 处开始。`&s[0..5]` 的起始偏移是 0。
- **第二步，长度 $b - a$**：半开区间 `[a, b)` 的元素个数恒为 $b-a$。`&s[0..5]` 的长度是 5，`&s[6..11]` 的长度是 5。
