## 为什么从所有权开始

Rust 最著名的广告词是「**没有垃圾回收器的内存安全**」。垃圾回收（GC）语言靠运行期扫描回收内存，付出暂停与不确定性的代价；C/C++ 靠程序员手动 `free`/`delete`，获得性能却把内存错误的风险全部压在人身上。Rust 走了第三条路：把「谁拥有这块内存、何时释放」编成一套**编译期检查的规则**——这就是**所有权（ownership）**。<span class="marginnote">所有权是 Rust 区别于一切主流语言的独创设计。理解了它，你就理解了为什么 Rust 编译器的报错总在纠结「move」「borrow」「lifetime」——那不是编译器的脾气，而是它在你写代码时就把内存安全检查做完了。</span>

这门课要回答三个问题：内存是如何被分配与释放的、所有权三条规则是什么、所有权如何移动。

## 1 内存模型：栈与堆

任何程序的数据都住在两种内存区域里：**栈（stack）**与**堆（heap）**。

**栈**是后进先出的内存区域，数据按声明顺序压入、按逆序弹出。栈上的数据大小在编译期已知，分配就是移动栈指针——极快。函数调用的局部变量、函数参数都在栈上。

**堆**是更自由的内存区域：你请求分配一块大小未知或动态变化的空间，拿到一个**指针**，用完后需要释放。堆的分配比栈慢，因为要寻找空闲块；但堆能容纳动态大小的数据——比如运行时才确定长度的字符串。

Rust 与 C 的分界点在这里出现：

| 语言 | 栈上数据 | 堆上数据 | 堆释放时机 |
| --- | --- | --- | --- |
| C | 局部变量 | `malloc` | 手动 `free`（易漏易错） |
| C++ | 局部变量 | `new` | `delete` 或 RAII 析构 |
| Java | 引用 | `new` 对象 | GC 不定时回收 |
| Python | 引用 | 对象 | 引用计数 + GC |
| **Rust** | **值** | **`Box`/`String`/`Vec` 等** | **所有权结束（drop）** |

Rust 的独特之处在于最后一行：**堆内存的释放时机由所有权规则自动决定，且是确定性的**——值离开作用域时立即调用析构（drop），既不像 C 那样要手动、也不像 GC 那样有延迟。<span class="marginnote">「确定性析构」意味着 Rust 在获得近似 C 的性能的同时，把资源（内存、文件句柄、锁）的释放写进了语言规则：作用域一结束，资源自动归还。这与 C++ 的 RAII 思想同源，但 Rust 把它与所有权绑定得更彻底。</span>

以 `String` 为例：

```rust
{
    let s = String::from("hello"); // 在堆上分配空间
    // 使用 s ...
} // 作用域结束，s 的所有权结束，堆内存被自动释放
```

`String` 是「栈上的元数据（指针 + 长度 + 容量）+ 堆上的字符数据」的组合体。作用域结束时，Rust 自动调用 `drop` 释放堆内存——没有手动 `free`，也没有等待 GC。

## 2 所有权三规则

Rust 的所有权由三条规则定义，它们覆盖了所有变量的生命周期：

**规则一：Rust 中每一个值都有一个所有者（owner）变量**。

**规则二：一个值在任一时刻只能有一个所有者**。

**规则三：当所有者离开作用域时，这个值将被丢弃（drop）**。

这三条规则的精髓是「**一个值只有一个主人**」。主人负责释放它；要转手，必须显式转移所有权。这就杜绝了两类经典内存错误：

**悬空指针（dangling pointer）**：如果一块内存被释放后仍有指针指向它，就是悬空。规则三保证「所有者离开作用域 → 内存释放」总是同步发生，没有残留的引用。
**双重释放（double free）**：如果两块代码各自释放同一块内存，就是双重释放。规则二保证「只有一个所有者」，因此只有一处会负责释放。

**这也是为什么 Rust 不需要垃圾回收**：GC 存在的意义是「避免双重释放与悬空」，而所有权把这两个问题在编译期就排除了。

## 3 Move：所有权如何转移

### 移动而非复制

看这段代码：

```rust
let s1 = String::from("hello");
let s2 = s1;               // 所有权从 s1 移动到 s2

println!("{s1}");          // 编译错误：s1 已被移动
```

在 C 里，`s2 = s1` 是**浅拷贝**：两个指针指向同一块堆内存，双重重叠，析构时双重释放。在 Rust 里，`let s2 = s1` 被定义为**移动（move）**：`s1` 的栈上元数据复制给 `s2`，但 `s1` 立即失效，所有权归 `s2`。之后访问 `s1` 是编译错误，因为它的值已经不在它那里了。

可以把移动理解成「**所有权的搬家**」：数据没有复制，只是地址卡片换了主人。Rust 编译器甚至会追踪一个值是否已被移动，被移动后的变量不再可用。

### 与 Copy 类型的区别

并不是所有赋值都是移动。**完全存在于栈上的标量类型**实现 `Copy` trait，赋值是真正的复制，两个变量都有效：

```rust
let x = 5;
let y = x;       // x 仍可用：整数是 Copy
println!("{x} {y}");

let s = String::from("hi");
let t = s;       // s 被移动：String 不是 Copy
```

`Copy` 意味着「复制一份廉价的位拷贝，两个值都独立」。整数、浮点、布尔、`char`、以及只含 `Copy` 元素的元组都是 `Copy`。而 `String`、`Vec`、`Box` 等涉及堆指针的类型**不是** `Copy`——浅拷贝它们会制造两个指向同一堆块的指针，这正是 C 双重释放的源头。<span class="marginnote">判定一个类型是否 `Copy` 的直觉：它离开作用域时，需不需要执行清理动作（释放堆内存、关闭句柄）？需要，就不能 `Copy`；只是普通位拷贝的，可以是 `Copy`。Rust 的类型系统让你为自定义类型显式选择是否实现 `Copy`。</span>

### 函数调用中的所有权

所有权随函数调用转移——传参即移交，返回即回传：

```rust
fn takes_ownership(s: String) {
    println!("{s}");
} // 这里 s 被 drop

fn main() {
    let s = String::from("hello");
    takes_ownership(s);   // s 的所有权被移交进函数
    // println!("{s}");   // 错误：s 已被移动
}
```

返回值也会转移所有权：

```rust
fn gives_back(s: String) -> String {
    s
}

let s2 = gives_back(s);   // 所有权被 return 回传
```

这种「传来传去」很快就显得笨拙——`takes_ownership` 只是想读一下字符串，却把调用者的数据吞掉了。Rust 的解法不是放松所有权，而是引入**引用与借用**：让函数「借」数据而不是「拿」数据。那是下一课的主题。

## 4 公式解析：Move 前后栈与堆的状态

把移动过程画成内存状态变化，是最清楚的理解方式。

**移动前**，`s1` 的栈槽里存着三个字段：

$$
s1 = (\text{ptr} \to \text{堆上字符}, \ \text{len} = 5, \ \text{capacity} = 5)
$$

**执行 `let s2 = s1;` 之后**：

$$
s2 = (\text{ptr} \to \text{同一块堆内存}, \ \text{len} = 5, \ \text{capacity} = 5)
$$

$$
s1 = \text{已失效（被移动）}
$$
