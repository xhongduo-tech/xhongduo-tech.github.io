## 为什么从这个专题收尾

前九篇给了你「阅读」汇编的全部语法，这一篇练习「书写」——把零散的指令、寻址、调用约定拼成完整程序。我们选三个最有工程价值的方向：**数组**（一切数据结构的底层形态）、**字符串**（一切 I/O 与文本处理的载体）、**宏**（消除重复的汇编写法）。

这三个主题恰好也是把全专题收拢的结点：数组动用寻址模式，字符串动用 `rep` 前缀的块指令，宏动用汇编器的「预处理」能力。<span class="marginnote">对标 Hyde《The Art of Assembly Language》第 8~12 章的选题：底层数据结构的机械实现。今天没人手写大规模汇编，但 JIT、编译器后端、引导代码、性能热路径仍然天天在用这套手艺。</span>tokenizer 把文本切成 token、大模型的采样循环把 token 拼成句子——机器层全是字符串/数组在动。

## 1 数组：下标就是「基址 + 偏移」

一维数组在内存里是**连续**的一串元素。设数组首地址为 $x_A$、元素大小为 $L$，则第 $i$ 个元素的地址：

$$
A[i] \iff x_A + i \times L
$$

编译器把这条公式直接换成寻址模式。C 的

```c
long a[10];        // 首地址在 %rdi
a[i] = a[i] * 2;   // i 在 %rsi
```

翻译成：

```
  movq  (%rdi,%rsi,8), %rax    # 读 a[i]，比例因子 8 = sizeof(long)
  addq  %rax, %rax             # ×2
  movq  %rax, (%rdi,%rsi,8)    # 写回 a[i]
```

**指针算术**在汇编层更赤裸：`&A[i] - &A[j]` 的地址差是 $(i-j)\times L$ 字节，再除以 $L$ 得元素个数差——C 早已帮你做完除法。<span class="marginnote">把 `a` 换成结构体数组，$L$ 变成 `sizeof(struct)`；访问 `a[i].field` 就是 $x_A + iL + \text{fieldOffset}$，两次偏移一次寻址。数组到对象布局的桥梁就在这条式子里。</span>

## 2 公式解析：二维数组的行优先寻址

二维数组 `A[R][C]` 在 C 里按**行优先（row-major）**存储：整行挨着整行。设首地址 $x_A$、元素大小 $L$，则：

$$
A[i][j] \iff x_A + i \times (C \times L) + j \times L
$$

拆三步：

- **第一步**：第 $i$ 行的起始位置在 $x_A + i \times C \times L$——先跳 $i$ 行，每行 $C$ 个元素；
- **第二步**：行内第 $j$ 列再加 $j \times L$；
- **第三步**：合起来就是一条寻址指令 `(%rdi,%rsi,8)` 的推广——基址是行首，比例因子 $L$，中间夹一个「行内已乘好」的行偏移。

若维度在运行时可变（变长数组 `int a[n][m]`），行偏移 $i \times m$ 就要先算乘法再寻址，编译器会在帧里额外存 `m`——所以变长数组的开销比固定数组高。**缓存局部性**也与布局同源：行优先下按行遍历 `A[i][j]` 连续命中同一缓存行，按列遍历则每条跳一次——读《计算机组成原理》的缓存时，你会再见到这同一幅图景。<span class="marginnote">深度学习里「行优先」的转置/内存布局之争（NCHW vs NHWC）、`torch` 里 `contiguous()` 的用途，底层全是这一条寻址公式。</span>

## 3 字符串：rep 前缀的块指令

字符串处理在 x86 有专门指令，配合 **`rep` 前缀**整块搬运：

```
movsq / rep movsq     # 搬 8 字节 / 重复搬到 %rcx 为 0
stosq / rep stosq     # 把 %rax 填到 ES:...（现代：指向串的目标地址）
lodsb / lodsq         # 从源串载入累加器
cmpsb / scasb         # 比较 / 扫描
cld / std             # 清/置方向标志 DF（决定地址递增还是递减）
```

一个典型的字符串复制循环：

```
; 把 rsi 指向的串复制到 rdi，长度在 rcx
    cld                 # 方向：地址递增
    rep movsb           # 逐字节复制 rcx 次
```

`rep` 的语义是「重复执行直到 `%rcx == 0`，每步 `%rcx--`」。`rep stosq` 配合 `movq $-1,%rax` 就能把整块内存填成 0xFF（“填充”算法）。方向标志 DF 控制地址**递增（cld）还是递减（std）**，忘记 `cld` 是最隐蔽的 bug 之一——中断处理程序会留下 DF=1，导致后续串指令倒着走。<span class="marginnote">glibc 的 `memcpy`、`strlen` 之所以快到反直觉，是向量化 + 无分支 + 宽字（一次搬 32 字节）+ 先对齐的特技叠加。现代处理器上 `rep movsb` 本身也有<strong>快速串</strong>微码路径（ERMS），搬大块内存时比逐条指令还快。</span>

## 4 宏：在汇编里消灭重复

汇编没有函数级抽象，重复代码就靠**宏**。三种常见宏机制：

**GAS 的 `.macro`**：

```
.macro PUSH2 r1, r2
    pushq \r1
    pushq \r2
.endm
PUSH2 %rbx, %rbp          # 展开成两条 push
```

- **NASM 的 `%macro`**：`%macro name 2` … `%endmacro`，功能更强（支持标签唯一化 `%%`）；
- **C 预处理器的 `#define`**：gas 也能直接用，把宏写在 `-D` 或 `.h` 里。<span class="marginnote">宏是<strong>编译期文本替换</strong>，不是运行时调用——它不占栈、没有调用开销，代价是每展开一次复制一份代码（代码膨胀）。「用宏还是用函数」的取舍，是所有汇编程序员的日常权衡。</span>宏还能带参数做「模板化」：一个「遍历数组累加」的宏，能按元素类型生成 `movq`/`movl` 两个版本，汇编级的泛型。

## 5 组装：把知识拼成一个程序

综合本专题，一个「把整数数组求和并返回」的完整程序（Linux + gas）：

```
    .globl  sum_array
sum_array:
    # %rdi = 数组首地址, %rsi = 长度
    movq  $0, %rax          # 累加器
    testq %rsi, %rsi        # 空数组？
    jle   .Ldone
.Lloop:
    addq  (%rdi), %rax      # 累加
    leaq  8(%rdi), %rdi     # 指针前进（数组）——寻址模式
    decq  %rsi
    jne   .Lloop            # ——控制流
.Ldone:
    ret                     # ——过程调用
```

这一小段里：寻址模式（`(%rdi)`、`8(%rdi)`）、算术（`addq`）、控制流（`jle/jne`）、调用约定（参数在 `%rdi/%rsi`、返回 `%rax`）全部到齐——汇编语言这门课，在这里真正闭环。<span class="marginnote">优化视角：这段循环如果改成「每次 `addq (%rdi,%rsi,8), %rax` 再递减下标」，就能省掉 `leaq` 那步指针更新——编译器做循环优化时正是这样来回权衡的。读得懂这条循环，你就读得懂 `-O2` 的一半招式。</span>

## 6 小结

- **数组**：$A[i] = x_A + iL$，一条寻址指令搞定；二维行优先 $= x_A + iCL + jL$。
- **变长数组**要现场算行偏移，比固定数组贵；布局决定缓存局部性。
- **字符串**：`rep movs/stos/lods/cmps` 块指令，`cld/std` 控制方向，DF 是经典坑。
- **宏**：`.macro`/`%macro`/`#define` 三种机制，编译期展开，可做「汇编级泛型」。
- **易错点｜忘记 `cld`、宏参数标签冲突、`rep` 依赖 `%rcx` 初值，是三大现场事故**。
- 一篇文章内收齐寻址、算术、控制流、调用约定，汇编语言专题正式闭环。

至此，汇编语言专题全部收尾：从机器级表示与寄存器，到寻址、算术、过程调用、ABI、控制流、指令编码、C 互操作、浮点与 SIMD、中断与系统调用，最后落到数组、字符串与宏的工程实践。在下一级，我们将带着「机器在做什么」的清晰图景，进入**操作系统**与**计算机组成原理**——调度、虚拟内存、缓存与流水线会在这张图上逐层展开。
