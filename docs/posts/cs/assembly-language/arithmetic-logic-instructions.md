## 为什么从算术与逻辑指令开始

有了寻址模式做「取数语言」，接下来要学的就是运算本身：加法、减法、乘除、按位与或、移位。它们是 CPU 里所有「计算」的最小积木——大模型里的矩阵乘法，最终被拆成一长串这样的标量或向量算术；`count = count + 1` 这个最普通的语句，底层就是 `addq $1, %rax`。

这一节覆盖 CS:APP §3.5。学完之后，你能完整读懂任意一段「从内存取数 → 运算 → 存回」的汇编，也第一次直面机器算术里最反直觉的一个事实：**有符号数与无符号数共享同一套加减指令，溢出是算出来的，不是报出来的**。<span class="marginnote">上一节我们学了寻址模式，这一节的指令几乎全部允许「寄存器/立即数/存储器」三种来源组合，但一条指令里最多只有一个是内存操作数——x86 不允许「内存搬内存」。</span>

## 1 数据搬运：mov 家族

**mov** 把字节序列从源复制到目的，源与目的不能同时是内存。带后缀定宽度：

```
movq (%rdi), %rax      # 8 字节：从内存读入
movl $1, %eax          # 4 字节立即数写寄存器
movb %al, (%rdi)       # 1 字节：写回内存
```

真正容易出错的是**改变宽度**的搬运。把窄值搬进宽寄存器必须决定高位填什么：

**movz** 家族：零扩展，高位填 0。`movzbq %al, %rax`、`movzbl %al, %eax`。
- **movs** 家族：符号扩展，高位填符号位。`movsbq %al, %rax`、`movslq %eax, %rax`。
- **cltq**：`%eax` → `%rax` 的符号扩展专用指令，等价于 `movslq %eax, %rax`。<span class="marginnote">C 里把 `char` 赋值给 `int` 会发生符号扩展；如果那个 `char` 恰好是 0xFF 表示 -1，忘记扩展就会得到 255 而不是 -1。这个「扩展方向」错误是 C 数组/字符处理的经典 bug 来源。</span>

记住口诀：**w 代表 width（宽度），s 代表 sign（符号）**。

## 2 算术指令：加、减、乘、除

最常用的算术指令几乎全部带后缀：

| 指令 | 含义 | 例 |
| --- | --- | --- |
| `leaq S, D` | D = S 的地址（不访存） | `leaq 4(%rax), %rbx` |
| `incq D` / `decq D` | D = D ± 1（不影响 CF） | `incq %rax` |
| `negq D` / `notq D` | D = -D / ~D | `negq %rax` |
| `addq S, D` / `subq S, D` | D = D ± S | `addq %rcx, %rax` |
| `imulq S, D` | D = D × S（低 64 位） | `imulq %rcx, %rax` |
| `xorq` / `orq` / `andq` | 按位异或 / 或 / 与 | `xorq %rcx, %rax` |

乘法有两个版本。**双操作数 `imulq`** 取乘积的低 64 位；**单操作数 `imulq S`** 才是「完整乘法」：把 `%rax` 与 S 相乘，128 位结果放入 `%rdx:%rax`（高 64 位在 `%rdx`）。除法只有单操作数形式：`idivq S` 以 `%rdx:%rax` 为被除数，商进 `%rax`，余数进 `%rdx`。<span class="marginnote">除法前必须先用 `cqto`（或 32 位下的 `cltd`）把 `%rax` 符号扩展到 `%rdx:%rax`——忘了这一步，高位残留垃圾会让商和余数彻底错乱，这是除法汇编最容易漏的一步。</span>

## 3 移位与逻辑

移位指令把操作数按位搬移，空出的位补 0（左移/逻辑右移）或补符号位（算术右移）：

```
salq $4, %rax    # 左移：乘 2^4
sarq $1, %rax    # 算术右移：符号扩展除法，结果向负无穷取整
shrq $2, %rax    # 逻辑右移：填 0
```

移位量只能来自**立即数**或寄存器 `%cl`。左移一位 = 乘 2，算术右移一位 = 除以 2（向负无穷方向），这个恒等式是编译器把「乘常量」换成移位+加法的依据——`x * 15` 可能被编译成 `x<<4 - x`。

## 4 公式解析：补码溢出到底意味着什么

机器算术里 `addq` 执行的就是**模 $2^{64}$ 的补码加法**。设结果实际算出的 64 位值为 $R$，则：

$$
R \equiv (x + y) \bmod 2^{64}, \qquad R = x + y - 2^{64}\cdot \text{CF}'
$$

其中进位位的逻辑我们先用直觉版本理解。拆三步：

- **第一步，区分「运算器结果」与「程序意图」**：`addq` 老老实实做模 $2^{64}$ 加法，它不知道你当 $x,y$ 是有符号还是无符号。
- **第二步，什么时候溢出**：两个正数相加结果为负（对符号数），或两个负数相加结果为正——符号位错误翻转，此时 `OF` 标志被置 1。
- **第三步，谁看 OF，谁看 CF**：有符号运算读 `OF`（溢出），无符号运算读 `CF`（进位/借位）。`incq` 唯一不更新的就是 `CF`，因为加 1 不可能进位到第 65 位（除非初始就是全 1，此时结果回到 0，但 `OF` 会置位）。

于是一个惊人的事实浮现：**`addq` 本身不区分符号，区分符号的是读取 `OF` 还是 `CF` 的那条条件指令**。这就是为什么第二章《控制流与跳转》里，同样的 `cmpq` 后面既可以有符号比较 `jl` 也可以有无符号比较 `jb`。

## 5 用 leaq 与移位做「免费算术」

编译器爱用两种「零成本」算术：

- `leaq (%rdi,%rdi,8), %rax` 得 $9x$，`leaq 7(%rdi,%rdi,4), %rax` 得 $5x+7$——乘法、加法一次完成且不碰条件码。
- 乘以 2 的幂用 `salq`：`x << 3` 即 $x \times 8$。<span class="marginnote">但注意：除以 2 的幂不能用 `sarq` 直接替代 C 的整数除法——因为 C 的 `/` 向零取整，而 `sar` 向负无穷取整，-3/2 在 C 是 -1，`sarq` 得到 -2。编译器会额外插入修正指令。这是个很能区分「懂汇编」与否的细节。</span>

## 6 编译器眼中的常量乘法

理解了 leaq 与移位，就能读懂编译器对「乘常量」的重写。`x * 15` 不开 `imulq`，而拆成移位与 leaq 的组合（15 = 3 × 5）：

```
  movq  %rdi, %rax             # x
  leaq  (%rax,%rax,4), %rax    # 5x
  leaq  (%rax,%rax,2), %rax    # 5x + 2·5x = 15x
```

`x * 12`（12 = 3 × 4）：

```
  leaq  (%rdi,%rdi,2), %rax    # 3x
  salq  $2, %rax               # 3x << 2 = 12x
```

为什么绕这么一圈？`imulq` 是若干周期的慢指令，而 leaq/移位是 1 周期快指令且不进乘法单元——编译器宁可多两条指令，也不愿用一次慢乘法。<span class="marginnote">这条「快指令代替慢指令」的恒等变换思路，正是《计算机组成原理》流水线章节「指令代价不对称」的现实注脚；现代 CPU 乘法延迟虽已压到 3~4 周期，重写依旧普遍存在。</span>读反汇编时看到一串 leaq/salq 而没看到 imulq，别奇怪——这正是编译器在替你做优化。

## 7 小结

先补一句被 `mov` 家族掩盖的细节：**凡是能搬进寄存器或立即数的值，都不要直接搬进内存**——`movq %rax, (%rdi)` 这类「寄存器到内存」要占内存带宽，而紧凑循环里的临时量编译器会尽量留在寄存器里。这条「寄存器优先」的原则，正是汇编与《计算机组成原理》里「寄存器是离 ALU 最近的存储」在工程上的体现。

- **mov** 搬运数据，**movz/movs** 负责零/符号扩展，`cltq` 是 `%eax→%rax` 的符号扩展专用指令。
- 算术四则：`addq/subq/imulq/negq`，除法 `idivq` 前必须先 `cqto` 扩展被除数。
- **单操作数乘法**得到 128 位结果存 `%rdx:%rax`；双操作数 `imulq` 只保留低 64 位。
- 移位量来自**立即数或 `%cl`**；左移=乘 2、算术右移=除以 2（向负无穷）。
- **易错点｜add 不区分符号数，`OF` 管有符号溢出、`CF` 管无符号进位**。
- `leaq` 是编译器的免费算术：加乘一条指令。
