## 为什么需要互操作

写汇编从来不是目的。绝大多数时候我们写 C，只是偶尔需要「掀开盖子」：确认编译器到底生成了什么、手动优化某段热代码、或者调用一段别人写的汇编。**汇编与 C 的互操作**就是这些场景的实操手册——不是学新指令，而是把前几篇的知识变成真正的日常工具。

这条技能树有三层：**向外看**（让编译器把 C 翻译成汇编给我们读）、**向里嵌**（在 C 里直接写汇编片段）、**向旁接**（把独立的汇编模块链接进 C 程序）。掌握它们，等于给自己的调试与分析工具箱配上了「机器级放大镜」。<span class="marginnote">深度学习框架的算子库（如 FlashAttention、oneDNN）就是「C/C++ 骨架 + 关键热路径手写 SIMD 汇编/内联汇编」的典型结构——互操作不是考古手艺，是当代性能工程的日常。大模型推理的每一个 token 延迟，都有一部分由这些热路径决定。</span>

## 1 看：让编译器吐出汇编

最快理解编译器行为的方式是直接问它：

```
$ gcc -Og -S code.c      # 生成 code.s
$ gcc -O2 -S code.c      # 优化版本
$ objdump -d code.o      # 反汇编目标文件
$ objdump -d a.out       # 反汇编可执行文件
```

要点：

`-S` 只生成汇编，不继续汇编链接；汇编文本里 `%` 寄存器、`$` 立即数的 AT&T 风格一目了然。
- `-Og` 生成的汇编与源代码**逐行对应**，是学习与对照的黄金组合；`-O2` 则是「真实世界」的汇编。
- `objdump -d` 把 `.o` 的字节反汇编出来，与 `-S` 结合（`objdump -d -S`）可以看到**汇编与 C 源码逐行交错**。<span class="marginnote">想看清符号对应关系可以用 `objdump -dr`（显示重定位信息）。`.o` 文件里的函数地址还没定，反汇编会显示占位，链接后才填上——重定位机制本身是《链接》章的主题。</span>

一个实践习惯：怀疑某段 C 有性能问题时，先 `gcc -Og -S` 看看它被翻译成了几条指令、用了几次内存访问，往往比凭空猜测快得多。

## 2 嵌：内联汇编

在 C 函数体里直接写汇编片段，GCC 提供 `asm` 关键字（写 `__asm__` 可避开 C 标准名冲突）：

```
__asm__ volatile("cli");              // 基本形式：禁中断
```

**扩展形式**才真正有用，它声明了汇编与 C 变量的交换接口：

```
long add3(long x, long y) {
  long r;
  __asm__("addq %1, %0"
          : "=r"(r)          // 输出操作数：%0
          : "r"(x), "0"(y)   // 输入操作数：%1、%2（%0 兼作输入）
          : "cc");           // 破坏列表：条件码被改
  return r;
}
```

写法是 `asm("模板" : 输出 : 输入 : 破坏列表)`，模板里 `%0、%1、%2…` 按输出、输入顺序编号，`"r"` 表示让编译器随便选一个寄存器，`"=r"` 表示只写不读。**破坏列表**（`"memory"`、`"cc"`）必须如实声明汇编动了哪些东西，否则编译器会基于错误假设做优化。<span class="marginnote">GCC 还有 `__asm__("" ::: "memory")` 这种空模板：不产生任何指令，只作为<strong>编译器屏障</strong>，阻止编译器把内存读写跨过它重排——内核、并发无锁编程里的老朋友。</span>

## 3 接：独立的汇编模块

把汇编写进单独文件，再从 C 调用，是更「干净」的互操作方式。核心是**符号的可见性**：

汇编端用 `.globl`（或 `.global`）声明函数为全局符号，让链接器看得见；
- C 端用 `extern` 声明原型，按 ABI 规则调用。

```
# sum.s
    .text
    .globl  sum                # C 里 extern long sum(long, long);
sum:
    leaq (%rdi, %rsi), %rax    # 参数在 %rdi、%rsi
    ret

# main.c
extern long sum(long, long);
int main(void) { return sum(1, 2); }
```

```
$ gcc main.c sum.s -o prog
```

按 System V ABI，前 6 个整数参数自动出现在 `%rdi,%rsi,%rdx,%rcx,%r8,%r9`，返回值进 `%rax`——上一节学的调用约定在这里**直接兑现**。<span class="marginnote">反过来，C 也可以被汇编调用：用 `extern` 或 `weak` 声明，遵守 callee-saved 纪律即可。注意 C 编译器的命名修饰（mangling）：C 函数名一般原样导出，C++ 的符号会被修饰成 `_Z…`——所以汇编调用 C++ 通常要包一层 `extern "C"`。</span>

## 4 调试：反汇编与 gdb

`gdb` 提供机器级调试：

```
(gdb) disassemble main         # 反汇编 main
(gdb) info registers           # 看全部寄存器
(gdb) stepi                    # 单步执行一条汇编指令
(gdb) x/8gx $rsp               # 查看栈顶 8 个 8 字节单元
(gdb) break *0x401000          # 在地址处打断点
```

把 C 源码、汇编、寄存器状态并排观察，是「亲眼确认汇编在做什么」的最强武器——尤其是定位段错误、寄存器错位这类 ABI 问题，`info registers` 配合 `x $rsp` 往往一击即中。<span class="marginnote">`perf`、`valgrind` 这类剖析工具也报告到「函数 + 汇编行」粒度，能读懂汇编才能把热点的字节级信息落地。</span>

## 5 互操作的常见事故

**辨析｜易错点：**

- **忘了 `.globl`**：汇编函数对 C 不可见，链接报 `undefined reference`；
- **破坏 callee-saved 寄存器**：在汇编里改 `%rbx` 等却没保存/恢复，C 调用方拿到被踩的变量，bug 飘忽不定；
- **扩展 asm 漏写破坏列表**：汇编悄悄改掉 `%rcx` 却不声明，编译器按原值复用，结果随优化级别不同而时好时坏；
- **AT&T/Intel 混写**：`asm` 模板默认 AT&T，非要在里面写 Intel 语法就得加 `.intel_syntax` 前缀，混写必乱。

## 6 小结

- `gcc -Og -S` 看汇编、`objdump -d` 反汇编、`-S` 与 `-d` 结合看源码交错。
- **内联汇编**：`asm("模板" : 输出 : 输入 : 破坏列表)`，`%0、%1…` 编号、`"r"/"=r"` 约束、破坏列表必须诚实。
- **独立模块**：`.globl` 导出符号 + C 端 `extern` 声明 + 遵守 ABI，即可互相调用。
- `gdb` 的 `disassemble`、`stepi`、`info registers` 是机器级调试三板斧。
- **易错点｜破坏列表漏写、callee-saved 未保存、`.globl` 忘记声明，是互操作三大事故**。
