## 为什么从中断与系统调用开始

前面九篇的主角都是「指令」——但程序不是孤岛。它要读文件、写终端、分配内存、发起网络请求，而这些操作**不属于你的程序**，属于操作系统。问题是：**你的程序凭什么能碰到内核？** 答案是中断与系统调用这条「特权通道」。

这是汇编学习里最大的一次视野升级：从「CPU 内部」跳进「CPU × 操作系统」的边界。你将看到机器层如何实现「用户态不能碰硬件、但能小心翼翼地请内核代劳」——这是《操作系统》那门课一切并发、调度、设备管理的前提。<span class="marginnote">本专题对标 Patterson & Hennessy 的 RISC-V 视角：RISC-V 把这种机制做得干净、可教学，x86-64 则是一套更古老的、兼容包袱更重的版本。两种都值得看，它们回答的是同一个问题。</span>

## 1 异常与中断：同步与异步

CPU 随时可能被两类「不速之客」打断：

**异常（exception）**：**同步**，由**当前正在执行的指令**引发——除零、缺页、非法指令、以及你主动发起的 `ecall`/`syscall`。
- **中断（interrupt）**：**异步**，由**外部事件**引发——定时器到点、网卡收到包、键盘按键，CPU 不知道它什么时候来。

两者都走同一条「**陷入（trap）**」流水线：暂停当前程序、跳转内核处理程序、处理完再回来。

常见的异常类型及其在 RISC-V 上的 mcause 编号：

| 异常 | mcause（S 模式） | 触发情形 |
| --- | --- | --- |
| 指令地址未对齐 | 0 | 跳转到非对齐地址 |
| 非法指令 | 2 | 解码出未定义的指令 |
| 断点 | 3 | `ebreak`（调试器用） |
| 访存缺页 | 12 / 13 | 访问未映射或越权的页 |
| ecall 系统调用 | 8 / 9 / 11 | U/S/M 模式发起的系统调用 |
| 定时器/外部中断 | 5 / 9（中断位） | 设备或定时器打断<span class="marginnote">异常与中断共享机制但语义不同：异常是「你这条指令出事了」，中断是「外面有事叫你」。Linux 里 `irq` 专指中断、`fault/trap` 专指异常，这个用词差别对应着完全不同的处理逻辑。</span>系统调用是异常的一种：程序**主动**制造一次 trap 来请求内核服务。

## 2 特权级别：谁碰得动硬件

为什么程序不能直接读磁盘？因为硬件只把特权交给**内核**。RISC-V 定义三个特权模式：

$$\text{U（用户，User）} \le \text{S（监管，Supervisor）} \le \text{M（机器，Machine）}$$

- **U 模式**：运行应用程序，大部分指令不可用（不能写特权 CSR、不能直接访问设备寄存器）；
- **S 模式**：运行操作系统内核，管理进程、虚拟内存；
- **M 模式**：最高权限，运行固件/引导/可信执行环境，RISC-V 处理器一上电就在 M 模式。

x86-64 的对应物是**四个特权环（ring）**：ring 0（内核）~ ring 3（用户），兼容历史包袱。普通程序永远待在 ring 3 / U 模式，想升权只有一个入口：**陷入内核**。<span class="marginnote">「用户态能不能碰这条指令/这个寄存器」是硬件写死的检查：任何越权尝试都触发异常。这就是为什么一次 `mov` 到一个特权寄存器，不产生「权限错误」而是一条硬异常——机制永远先于「报错」。</span>

## 3 陷入的完整流程：RISC-V 的 ecall

RISC-V 用一条 `ecall` 指令发起系统调用，整个陷入流程由硬件与内核配合完成：

```
用户程序（U 模式）                   处理器（硬件）
───────────────                     ─────────────
ecall  ──────────────────────────→ 1. 保存 mepc = 当前 PC
                                    2. mcause = 原因（ecall = 11）
                                    3. 跳转到 mtvec 指向的处理程序
                                    4. 切到 M/S 模式

处理程序（内核）                      恢复现场
───────────────                     ─────────────
保存现场（通用寄存器）                mret ──────→ 1. 恢复 PC = mepc
读 mcause 判断原因                               2. 恢复模式/状态
分发到对应处理函数                                3. 用户程序继续
```

关键角色是**控制状态寄存器（CSR）**：

**mepc（Machine Exception PC）**：保存陷入时的 PC，`mret` 用它返回；
- **mcause**：记录原因（异常类型/中断编号）；
- **mtvec**：处理程序入口地址；
- **mstatus**：保存/恢复处理器的状态位。

处理器做的只是「**保存最少信息 + 跳到固定入口**」，其余全靠软件。<span class="marginnote">S 模式还有一套 `stvec/sepc/scause`，让操作系统也能处理「更轻」的异常；RISC-V 的设计哲学是「硬件只给机制，语义归软件」——同一个 `ecall`，机器模式处理程序与监管模式处理程序看到的风景不同。mret 前必须把 mepc 加 4 跳过 `ecall` 本身，否则会死循环陷入。</span>

## 4 公式解析：syscall 指令的三个现场

x86-64 的机制类似，但「现场」藏在寄存器里。Linux 系统调用约定：

$$
\text{功能号} \to \%\text{rax}, \quad \text{参数} \to \%\text{rdi},\%\text{rsi},\%\text{rdx},\%\text{r10},\%\text{r8},\%\text{r9}
$$

与函数调用（ABI）不同：第 4 个参数用 `%r10` 而非 `%rcx`——因为 `syscall` 指令本身会把返回地址放进 `%rcx`。一个向终端写字符串的完整系统调用：

```
    movq  $1, %rax        # 功能号 1 = write
    movq  $1, %rdi        # fd = 1（标准输出）
    leaq  msg(%rip), %rsi # 缓冲区地址
    movq  $5, %rdx        # 长度 5
    syscall               # 陷入内核；返回时 %rax = 写入字节数
```

拆三步：

- **第一步**：`syscall` 让 CPU 从 ring 3 跳到 ring 0，目标地址由 MSR `IA32_LSTAR` 指定，返回地址存 `%rcx`、旧标志存 `%r11`；
- **第二步**：内核按 `%rax` 查系统调用表，找到 `sys_write` 处理，把结果写回 `%rax`；
- **第三步**：`sysret` 用 `%rcx` 恢复用户态 PC，回到 `syscall` 的下一条指令。

一次 `printf("hello")`，机器层就是 `printf` → glibc 包装 → 数条 `mov` + 一条 `syscall`。<span class="marginnote">函数调用与系统调用的关键区别：函数调用是「同特权级跳转」，系统调用是「跨特权级陷入」——后者要保存/恢复整套特权状态，所以 `syscall` 慢得多。这也是「一次系统调用 ≈ 几百纳秒、一次函数调用 ≈ 几纳秒」的数量级差距来源，缓存/无锁编程都建立在这种差距上。</span>

## 5 中断：外部的「不速之客」

定时器中断每若干毫秒把 CPU 从用户程序拽进内核，操作系统借此完成**进程调度**——这正是「操作系统」之所以是操作系统的地方。过程与异常几乎相同，只有一个方向不同：中断不知何时来，所以硬件要负责**保存中断现场**（寄存器、PC），`mret`/`iretq` 再整体恢复。中断还带**优先级与屏蔽**：处理低优先级中断时可以先关中断（`cli`），防止更急的中断插队破坏现场。<span class="marginnote">网络包到达、磁盘数据就绪，驱动通过中断唤醒阻塞的进程——这一切在《操作系统》的「中断处理」「下半部 softirq」等主题里会展开。这里只需要立住一句：<strong>中断是硬件主动找软件，系统调用是软件主动找内核</strong>，两者共用陷入机制。</span>

## 6 小结

- **异常**（同步，指令引发）与**中断**（异步，外部事件）共用**陷入**机制。
- 特权模式：RISC-V 的 **U/S/M**、x86 的 ring 0~3；普通程序在 U/ring3。
- RISC-V：`ecall` 触发陷入，**mepc/mcause/mtvec/mstatus** 四个 CSR 记录现场与入口。
- x86-64：`syscall` 用 **%rax 功能号 + %r10 传第 4 参数**，返回地址在 %rcx。
- **易错点｜syscall 第 4 参数是 %r10 而非 %rcx；mret 前需把 mepc 加 4 跳过 ecall**。
- 中断让 OS 得以抢占 CPU 做调度，系统调用让用户程序安全地借用内核能力。
