## 为什么从控制流开始

到目前为止，我们看到的指令都是一条条顺序执行——但程序的生命力恰恰来自「**该往哪走**」：`if` 走哪条路、`while` 何时退出、`switch` 跳到哪个分支。机器层没有 `if`，只有**条件码**加**跳转**：一条算术指令留下几个标志位，后面的跳转指令根据标志决定是否改写 `%rip`。

这一节把「编程语言的控制结构」和「机器的跳转指令」对上号，你会看到 C 的 `if/while/for/switch` 是如何被编译器翻译成一段段「比较 + 条件跳转」的。这与大模型的推理循环、乃至 transformer 里的逐 token 判断（如 stop 条件）在机器层毫无二致：**一切分支最后都是对几个标志位的查问**。<span class="marginnote">现代 CPU 的分支预测器会猜测 `jne` 往哪跳、提前取指——猜错就冲刷流水线。你在《计算机组成原理》里会学到，正是这段「猜」，让 `if (a > b)` 判断分支的顺序（哪个分支放前面）能改变程序速度。</span>

## 1 条件码：算术留下的副产物

四条核心条件码：

**CF（Carry）**：无符号运算的最高位进位/借位；
- **ZF（Zero）**：结果是否为 0；
- **SF（Sign）**：结果的符号位（最高位）；
- **OF（Overflow）**：有符号运算是否溢出（符号位是否「错位」）。

`addq`、`subq` 等绝大多数算术指令**在存结果的同时顺带设置**这些标志。有两对指令**只设标志、不写结果**：

```
cmpq S2, S1     # 计算 S1 - S2，丢弃结果，只置标志
testq S2, S1    # 计算 S1 & S2，丢弃结果，只置标志
```

`testq %rax, %rax` 是汇编里最常用的「测零」写法——`S1 & S1` 恰在 `%rax == 0` 时置 `ZF`。<span class="marginnote">`cmp` 的减法是「S1 − S2」（AT&T 里被减数在前）。看 `cmpq %rcx, %rax` 是「%rax 减 %rcx」，与 `subq %rcx, %rax` 的语义一致，只是不存结果。方向记反，条件判断全体反转。</span>

## 2 跳转指令家族

无条件跳转 `jmp Label` 直接改写 `%rip`。条件跳转以 `j` 开头，根据标志组合跳转，配对齐全：

| 有符号 | 无符号 | 含义（条件） |
| --- | --- | --- |
| `jge` / `jg` / `jle` / `jl` | `jae` / `ja` / `jbe` / `jb` | ≥ / > / ≤ / < |
| `je` / `jne` | 同左 | = / ≠（都看 ZF） |
| `js` / `jns` | 同左 | 负数 / 非负 |
| `jo` / `jno` | 同左 | 溢出 / 不溢出 |

同一个 `cmp` 之后既能接有符号跳转也能接无符号跳转——**差别只在读哪几个标志**。还有配套的 `set*` 指令：`sete %al` 按条件把 8 位寄存器写成 0 或 1，`cmov*` 指令按条件搬运，常被编译器用来消除分支。

## 3 公式解析：有符号比较为什么是 SF^OF

有符号数 `<` 的判断没那么直白，因为**减法可能溢出**。设 S1 − S2 的实际结果（截断后）为 $R$，则「S1 < S2」的条件是：

$$
\text{S1} < \text{S2} \iff \text{SF} \oplus \text{OF} = 1
$$

拆三步：

- **第一步**：当结果没有溢出（OF=0）时，`R` 的符号位 SF 就代表结果正负——S1 < S2 当且仅当 SF=1。
- **第二步**：当发生溢出（OF=1）时，符号位被「反转」——比如两个负数相减得正（S1 < S2 但 R > 0），此时 SF=0 却该判断为「小于」。于是需要把 SF 取反。
- **第三步**：把「不溢出时看 SF、溢出时看 SF 的反」合起来，恰是**异或**：SF ⊕ OF。

这就是 `jl`（有符号小于）的判定；`jl` 记为 $\text{SF}\neq\text{OF}$。而**无符号**的 `jb` 只看 CF=1（借位）——因为无符号减法的下溢恰好表现为借位，一个标志就够。<span class="marginnote">`jg`（有符号大于）= !ZF && !(SF^OF)：既要排除相等，又要排除「小于」。这类标志组合在《计算机组成原理》的 ALU 设计课上是真金白银的硬件逻辑。</span>

## 4 编译 if 与 while

`if (cond) then-body else-body` 的典型翻译：先算条件，反写跳转跳过 then 块；else 块末尾跳去结尾。

```
  cmpq $0, %rdi        # cond: n == 0 ?
  jne  .Lfalse         # 不成立则跳 else
  ...then-body...
  jmp  .Ldone
.Lfalse:
  ...else-body...
.Ldone:
```

**循环**是这节的重头戏。`do-while` 最简单：条件判断在**循环体之后**，天然一次循环体至少执行一次，直接落成「体 + 底部条件跳转」：

```
.Lloop:
  ...循环体...
  cmpq $0, %rax        # 底部判断
  jne  .Lloop          # 条件成立则回跳
```

而 `while`（先判断后执行）的经典翻译是 **jump-to-middle（跳到中间）**：先无条件跳到末尾的条件测试处，条件成立才进入循环体。这样既保证「零次进入」的语义，又避免把测试复制两份：

```
  jmp  .Ltest
.Lbody:
  ...循环体...
.Ltest:
  cmpq $0, %rax
  jne  .Lbody          # 条件成立继续
```

`for` 循环则把「初始化、条件、更新」三段拆开，本质就是套了壳的 `while`。

## 5 switch 与跳转表

当 `switch` 的分支值是**密集的整数区间**时，编译器不再生成一串 `cmp/jne`，而是建一张**跳转表（jump table）**：一张放满分支地址的表，运行时按「case 值 − 最小 case」为下标**查表跳转**。

```
  leaq  .JTab(%rip), %rax   # 表基址
  movslq .Lidx(%rax,%rdi,4) # 按 index*4 取表项
  jmp   *%rax               # 间接跳转
```

查表跳转把「多次比较」摊平成「一次索引 + 一次间接跳转」，case 越多收益越大。<span class="marginnote">间接跳转 `jmp *%rax` 是跳转家族里的「函数指针」——C 里函数指针、C++ 虚函数、Go 的 interface dispatch，机器层全是这种查表 + 间接跳转。跳转表还是《算法》里状态机、词法分析器的高效实现。</span>注意 case 太稀疏（如 1、1000、2000）时编译器会放弃跳转表退回比较链——跳转表的空间开销不划算。

## 6 小结

- 算术指令**顺带设置**条件码 CF/ZF/SF/OF；`cmp`/`test` 只设标志不写结果。
- 条件跳转以 `j` 开头，`je/jne` 看 ZF，无符号看 CF，有符号看 **SF⊕OF**。
- `set*` 把条件写成字节，`cmov*` 消除分支。
- `do-while` 体先于判断；`while`/`for` 用 **jump-to-middle** 翻译。
- **易错点｜`cmpq S2, S1` 是 S1 − S2，方向写反则所有分支反转**。
- `switch` 密集 case 用**跳转表** + 间接跳转，稀疏 case 退回比较链。
