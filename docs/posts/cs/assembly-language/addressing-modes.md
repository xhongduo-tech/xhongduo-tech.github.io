## 为什么从寻址模式开始

上一节我们认识了寄存器和数据格式，但指令真正「干活」时，操作数大多藏在**内存**里——数组、结构体、指针指向的对象全在内存。CPU 怎么把「我想访问第 i 个元素」这句话翻译成一个具体的**地址**？答案就是**寻址模式（addressing modes）**：指令里写下地址的「配方」，CPU 按配方算出最终地址。这一节学完，你将拥有读懂 `(%rdi,%rsi,4)` 这类玄学括号的全部能力。

寻址模式也是汇编与 C 的**接缝**：C 的数组下标、指针加减、结构体成员访问，落到机器码里几乎全部变成「算地址」。理解它，等于理解了 C 中 $a[i]$ 为什么是一个地址表达式而不是别的。<span class="marginnote">到本章第 5 篇《汇编程序设计专题》，我们会看到二维数组 `A[i][j]` 的寻址公式如何从这一节的通式直接推出来。大模型里的张量下标运算同样建立在「基地址 + 偏移」之上。</span>

## 1 三种操作数

所有指令的操作数只有三种来源：

- **立即数（immediate）**：常量本身，写在指令里，记作 $\$C$。取值就是 $C$。
- **寄存器（register）**：读写某个寄存器，记作 $R_a$。取值就是 $R[R_a]$。
- **存储器（memory）**：按某个地址访问内存，记作 $M[A]$，其中 $A$ 是**有效地址（effective address）**。

一张对照表（CS:APP 图 3-3）：

| 类型 | AT&T 写法 | 取值 |
| --- | --- | --- |
| 立即数 | `$0x1F` | $31$ |
| 寄存器 | `%rax` | $R[\text{rax}]$ |
| 直接寻址 | `0x100` | $M[0x100]$ |
| 间接寻址 | `(%rax)` | $M[R[\text{rax}]]$ |
| 基址+偏移 | `4(%rax)` | $M[4 + R[\text{rax}]]$ |
| 变址+基址 | `(%rax,%rcx)` | $M[R[\text{rax}] + R[\text{rcx}]]$ |
| 完整形式 | `8(%rax,%rcx,4)` | $M[8 + R[\text{rax}] + 4\cdot R[\text{rcx}]]$ |

## 2 寻址模式的家族树

上面的表是一个递进家族，从简单到完整，由四条「配料」自由组合：

**位移 Imm**、**基址寄存器 Rb**、**变址寄存器 Ri**、**比例因子 s**（只能取 1、2、4、8），任意取子集。于是有效地址的统一公式是：

$$
\text{有效地址} = \text{Imm} + R[\text{Rb}] + R[\text{Ri}] \cdot s
$$

<span class="marginnote">Intel 处理器发明这套寻址是为了一条指令完成「基址+下标+步长」的数组访问：一维数组第 i 个元素 = 数组首地址 + i×元素大小，正好落在 `(Rb,Ri,s)` 三种模式上。</span>常见特例：`(, %rcx, 4)` 表示 $4 \cdot R[\text{rcx}]$——基址、位移都省略；`%rax` 单独出现时表示寄存器而非内存，这是新手最容易搞混的地方：**同一个名字，写进括号是内存，写在外面是寄存器**。

## 3 公式解析：有效地址怎么算

公式 $\text{Imm} + R[\text{Rb}] + R[\text{Ri}] \cdot s$ 是本章最重要的一条算术，拆成三步：

- **第一步，取基址**：读基址寄存器 `%rax` 的值，这是「落脚点」，常是数组首地址或结构体基址。
- **第二步，加权变址**：读变址寄存器 `%rcx` 的值，乘以比例因子 $s$。$s$ 只能是 1、2、4、8，因为它们是 int、指针等常见类型的字节数——乘以 $s$ 就是「按元素大小跳到第 i 个元素」。
- **第三步，加位移**：Imm 是个常量偏移，用于跳过结构体头部或访问成员字段。

一个具体例子：设 `%rax = 0x1000`，`%rcx = 3`，则

$$
8(\text{rax},\text{rcx},4) \Rightarrow 8 + 0x1000 + 4 \times 3 = 0x101C
$$

于是 `movq 8(%rax,%rcx,4), %rdx` 把内存地址 `0x101C` 处的 8 字节读入 `%rdx`——这不正是「一个 int 数组，从第 3 个元素再往后挪 1 个元素」吗？寻址模式把「下标运算」直接做进了硬件。

## 4 leaq：不访问内存的「算地址」指令

特殊的成员是 **`leaq`（load effective address）**：它把有效地址**算出来放进寄存器，但不碰内存**。`leaq 8(%rax,%rcx,4), %rdx` 把上面的 `0x101C` 放入 `%rdx`，而不是去读那个地址的内容。

正因为不访存，`leaq` 常被编译器当**廉价算术**用：

```
leaq 7(%rdi, %rdi, 4), %rax   # %rax = 5 * %rdi + 7
leaq (%rdi, %rdi, 8), %rax    # %rax = 9 * %rdi
```

乘以 5、乘以 9、加 7，一条指令完成——不用乘法指令、不碰条件码。<span class="marginnote">`leaq` 会把 32 位操作数零扩展到 64 位，且不设置条件码标志，所以编译器放心用它做纯算术而不怕破坏后续判断。</span>在《算术与逻辑指令》篇里它还会再次登场。

## 5 从 C 表达式到寻址模式

把 C 翻译成寻址模式是本章的「阅读理解题」：

`p` 是指针变量（存在 `%rax`）：`*p` → `(%rax)`；
- `p + 1`（`p` 指向 8 字节类型）：→ `8(%rax)`——注意 C 指针算术已经帮你乘了元素大小；
- `a[i]`（`a` 存 `%rdi`，`i` 存 `%rcx`，int 数组）：→ `(%rdi,%rcx,4)`；
- `s.field`（`s` 存 `%rax`，`field` 偏移 8）：→ `8(%rax)`。

指针算术的**单位是元素大小**这件事，在汇编层看得清清楚楚：`(%rdi,%rcx,4)` 里的 4 就是 `sizeof(int)`。<span class="marginnote">反方向也成立：若某编译器翻译 `p++` 时没乘元素大小，那个 bug 在汇编层一眼就能看出「比例因子写错」。懂汇编，是给 C 程序纠错的一双 x 光眼。</span>

## 6 一个完整的取数翻译练习

把寻址公式变成眼睛，最快的办法是练翻译。给定：

```c
struct Point { double x, y; };      // 16 字节
struct Point *p;                    // 存 %rdi
p[2].y = p[2].y + 1.0;
```

翻译：

```
  leaq  32(%rdi), %rax       # &p[2]：16*2 = 32
  movsd 8(%rax), %xmm0       # p[2].y：+8 跳过 x 字段
  addsd .LC0(%rip), %xmm0    # +1.0（常量放在只读区）
  movsd %xmm0, 8(%rax)
```

结构体数组把「元素大小」换成 `sizeof(struct)`，成员偏移按字段排布逐段累加——一条指令内「基址 + 下标×大小 + 成员偏移」三层都齐了。练熟这类翻译，再读 `objdump` 输出时就只剩「秒懂」一个选项。<span class="marginnote">注意结构体的字段偏移受对齐规则影响：编译器可能在成员之间插入填充字节（padding），于是「偏移 = 字段大小累加」只在最简单时成立。对齐与填充是《Heterogeneous Data Structures》（异构数据结构）章节的主题，这里先埋个伏笔。</span>

## 7 易错辨析与小结

**辨析｜易错点：** 一是「括号内 = 内存」：`%rax` 是寄存器值，`(%rax)` 才是内存；二是比例因子只有 1/2/4/8 四档，想乘 3 只能拆成 `leaq`；三是 `leaq` 算地址不读内存，`movq` 才真正访存；四是 AT&T 里位移永远在括号外左边。

- 三种操作数：**立即数、寄存器、存储器**；存储器的取值是 $M[\text{有效地址}]$。
- 寻址模式统一公式 $\text{Imm} + R[\text{Rb}] + R[\text{Ri}]\cdot s$，$s\in\{1,2,4,8\}$。
- 同一寄存器名**括号内是内存、括号外是寄存器**。
- `leaq` 只算地址不访存，可当**加乘混合算术**用。
- C 的指针算术在汇编层就是**基址 + 下标 × 元素大小**。
