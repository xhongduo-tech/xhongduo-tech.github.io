## 为什么从机器级表示开始

你已经用 C 语言写过程序，Python 也大概摸过几回。无论是 `a = b + 1` 还是 `x = tensor.matmul(w)`，最终落到 CPU 里执行的都不是这些句子，而是**机器码**——一串字节。这中间隔着一层编译器和一层面向微架构的映射，而「翻译链」上最近的一层文本形态，就是**汇编语言（assembly language）**。

学习汇编并不是为了回去手写它，而是为了获得一门**精确读懂机器在干什么**的母语：编译器为何这样翻译循环、为何数组下标快、为何递归不免费、深度学习算子库为何长成那样——这些问题的答案都写在汇编里。<span class="marginnote">大模型推理框架（如 llama.cpp、vLLM）里的矩阵乘 kernel，最终都要经过编译优化变成特定的机器指令；读懂汇编，就是读懂「优化」这层魔法的说明书。</span>本专题对标 CS:APP 第 3 章，从最底层的信息表示（寄存器与数据格式）起步，一路走到过程调用、控制流与浮点指令。

## 1 一条汇编指令长什么样

我们采用 AT&T 语法（GNU 汇编器 GAS 的默认风格），一条指令的骨架是：

$$
\text{操作码}\quad \text{源操作数},\ \text{目的操作数}
$$

例如 `movq %rax, %rbx`，把 `%rax` 寄存器里的 8 字节值**复制**到 `%rbx`。操作数有三大类：

- **立即数（immediate）**：写在 $ 之后，如 `$4`，是直接写进指令里的常量；
- **寄存器（register）**：写在 % 之后，如 `%rax`，是 CPU 内部的存储单元；
- **存储器（memory）**：如 `(%rdi)`，表示以 `%rdi` 的值为地址、去内存取数。

<span class="marginnote">Intel 语法是另一种口味（`mov rbx, rax`，源在前），Windows 工具链与 MASM 常用。本专题以 AT&T 为准，看懂一种、知道另一种存在即可。两者源/目的顺序相反，混读是最常见的入门事故。</span>

## 2 从 C 到机器代码的翻译链

gcc 把 `code.c` 变成可执行文件要经过四步：**预处理 → 编译 → 汇编 → 链接**。我们想看的「汇编」就诞生在编译与汇编之间：

```
$ gcc -Og -S code.c     # 生成 code.s（汇编文本）
$ gcc -Og -c code.c     # 生成 code.o（机器码目标文件）
$ objdump -d code.o     # 反汇编，把机器码译回汇编
```

`-Og` 让编译器生成「与源代码保持对应关系」的汇编，适合人类阅读；`-O2` 之后代码会被揉得面目全非但跑得更快。<span class="marginnote">反汇编之所以可行，是因为机器码到汇编是「一对一可逆」的文本化——机器码是汇编的二进制编码，汇编是机器码的人类可读名。本章第 7 篇《x86-64 指令编码》讲的就是这层编码规则。</span>结论先立住：**汇编不是另一种编程语言，而是机器码的文本形式**，每条汇编指令严格对应一段机器码字节。

## 3 数据格式：b / w / l / q

x86-64 的指令用后缀标明操作数的宽度，后缀字母来自历史名词：

| 后缀 | 大小 | C 类型 | 例 |
| --- | --- | --- | --- |
| `b` | 1 字节 | char | `movb` |
| `w` | 2 字节 | short | `movw` |
| `l` | 4 字节 | int、unsigned int、float | `movl` |
| `q` | 8 字节 | long、char\*、指针 | `movq` |

在 x86-64 上，C 的整数类型大小是确定的：char=1、short=2、int=4、long=8、指针=8，double=8。<span class="marginnote">`l` 里的「l」来自 long，是 32 位时代的遗留：那时的 long 是 32 位，所以 4 字节后缀叫 l。到了 64 位时代，4 字节变成 int、8 字节叫 q（quad，四字）。知道这段历史，后缀就不会记反。</span>后缀写错（比如 64 位值用 `movl`）是汇编里最常见的一类 bug。

## 4 寄存器组：十六个通用寄存器

x86-64 给程序员提供了 16 个**通用寄存器（general-purpose registers，GPR）**。它们的名字是历史的拼贴：8086 时代只有 `%ax~%dx` 这类 16 位寄存器，后来一层层加宽，加宽部分用 r/e 前缀标记。同一个物理寄存器有多种宽度的「别名」：

| 64 位 | 32 位 | 16 位 | 8 位（低字节） | 用途（System V ABI） |
| --- | --- | --- | --- | --- |
| `%rax` | `%eax` | `%ax` | `%al` | 返回值、函数调用方保存 |
| `%rbx` | `%ebx` | `%bx` | `%bl` | 被调用方保存 |
| `%rcx` | `%ecx` | `%cx` | `%cl` | 第 4 个整数参数 |
| `%rdx` | `%edx` | `%dx` | `%dl` | 第 3 个整数参数 |
| `%rsi` | `%esi` | `%si` | `%sil` | 第 2 个整数参数 |
| `%rdi` | `%edi` | `%di` | `%dil` | 第 1 个整数参数 |
| `%rbp` | `%ebp` | `%bp` | `%bpl` | 被调用方保存（帧指针） |
| `%rsp` | `%esp` | `%sp` | `%spl` | 栈指针（专用） |
| `%r8` | `%r8d` | `%r8w` | `%r8b` | 第 5 个整数参数 |
| `%r9` | `%r9d` | `%r9w` | `%r9b` | 第 6 个整数参数 |
| `%r10~%r11` | `%r10d`~ | `%r10w`~ | `%r10b`~ | 函数调用方保存 |
| `%r12~%r15` | `%r12d`~ | `%r12w`~ | `%r12b`~ | 被调用方保存 |

**寄存器是 CPU 里速度最快的存储**，比访问内存快一个数量级以上；编译器的核心工作之一，就是把变量尽量塞进寄存器而不是内存。<span class="marginnote">`%r8~%r15` 是 x86-64 新增的，只有低 8 位寄存器名（`%r8b`），没有「高 8 位」别名。`%ah/%bh/%ch/%dh` 是 `%ax` 家族的高字节别名，只存在于前四个寄存器。</span>「调用方保存 / 被调用方保存」是《x86-64 调用约定与 ABI》篇的主角，这里先留个眼熟。

## 5 特殊寄存器：%rsp、%rip 与条件码

通用寄存器之外，有三个「身份特殊」的寄存器，后续每篇都会跟它们打交道：

**`%rsp`（栈指针）**：永远指向栈顶，由 `pushq`/`popq`/`callq` 维护，程序员不直接改它——这是《过程调用与栈帧》篇的地基。
- **`%rip`（指令指针）**：指向下一条要执行的指令地址，相当于程序计数器 PC。分支、跳转的本质就是改 `%rip`。
- **条件码（condition codes）**：`CF`（进位）、`ZF`（零）、`SF`（符号）、`OF`（溢出）四个标志位，由算术指令作为副产品设置，供后续的条件跳转读取。<span class="marginnote">注意条件码不是寄存器数据，没有名字可读写；你只能通过 `set*`、`cmov*`、`j*` 这些指令间接消费它们。这层「旁路」设计是《控制流与跳转》篇的钥匙。</span>

## 6 公式解析：寄存器的宽度与类型映射

把「寄存器-后缀-C 类型」三者钉在一起，关键公式是一条**写回规则**：

$$
\text{mov}\{\text{b,w,l,q}\}\ \text{src},\ \text{dst}
\;\Rightarrow\;
\text{写入 dst 的字节数} = 1,2,4,8
$$

对 `%r` 家族而言，写 32 位（`movl`）会**同时把高 32 位清零**；写 8 位或 16 位则**不清零**其余位。拆解三步：

- **第一步，看后缀定宽度**：`movq` 搬运 8 字节，`movl` 搬运 4 字节，依此类推。汇编指令的宽度完全由后缀决定，与 C 的隐式转换无关。
- **第二步，看目标寄存器**：`%rax` 全 64 位、`%eax` 是低 32 位、`%al` 是最低字节。
- **第三步，应用清零规则**：`movl $1, %eax` 之后，`%rax` 的完整值一定是 `0x00000001`——高 32 位被自动清零。这个「白送的清零」常被编译器拿来省掉一步显式零扩展。

这条规则是 64 位时代为了简化处理器实现引入的（32 位写不依赖旧值），却成了汇编新手最容易踩的坑：以为 `movl` 只动了低 32 位，实则整个 `%rax` 都被重置。

## 7 小结

- 汇编是**机器码的文本形式**，由操作码加操作数构成；本专题采用 **AT&T 语法**（目的在右）。
- C 到机器码经过**编译与汇编**两步，`gcc -S` 与 `objdump -d` 是观察汇编的两把扳手。
- 指令后缀 `b/w/l/q` 标明 1/2/4/8 字节宽度，与 C 类型一一对应。
- x86-64 提供 **16 个通用寄存器**，一个物理寄存器有 64/32/16/8 位多种别名。
- `%rsp` 管栈、`%rip` 管指令流、四个**条件码**标志是分支判断的来源。
- **易错点｜写入 32 位寄存器会清零高 32 位，写入 8/16 位则不清**。

在下一节，我们将回答「如何用一条指令从内存里取数」——这就是**数据寻址模式**：立即数、寄存器、存储器三种操作数与寻址模式的完整家族。
