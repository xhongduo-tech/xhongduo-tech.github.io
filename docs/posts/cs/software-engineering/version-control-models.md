## 为什么从版本控制模型开始

上一节讲了 SCM 的框架，这一节深入其核心工具——**版本控制系统（VCS）**。版本控制经历过两次范式跃迁：**集中式（CVCS）**与**分布式（DVCS）**。理解两者的差异，不仅是为了选工具，更是为了理解 Git 的**设计哲学**——为什么 Git 如此强大、又为何让新手困惑。

## 1 版本控制的核心概念

**版本控制（version control）**：系统化地记录文件的**每次变化**，支持回溯历史、多人协作、分支合并。

核心概念：

- **提交（commit）**：一次变更的**原子快照**——记录"这次改了哪些文件、谁、何时、为何"。
- **工作区 / 暂存区 / 仓库**：Git 的三区模型——工作区（你编辑的地方）、暂存区（准备提交的变更）、仓库（提交的历史）。
- **分支（branch）**：独立的开发线——多条开发线并行互不干扰。
- **合并（merge）**：把一条开发线的变更并入另一条。

**辨析｜易错点：** 版本控制 ≠ 备份。备份是"复制文件"，版本控制是"**记录变更历史**"——能回答"这个文件为什么变成这样""这个 bug 是哪个提交引入的"（git bisect）。**历史（history）才是版本控制的核心资产**，文件只是历史的快照。

## 2 集中式版本控制（CVCS）

**集中式（Centralized VCS）**：一个**中央仓库**保存所有版本，客户端从中央仓库**检出（checkout）**文件到本地，修改后**提交（commit）**回中央仓库。

代表：CVS、SVN。

- **优点**：**权限管理简单**（中央统一控制）、**历史单一**（只有一个权威版本）、简单直观。
- **缺点**：**单点故障**（中央仓库挂了，全组瘫痪）、**离线无法工作**（提交必须连服务器）、**分支成本高**（分支在服务器上，操作慢）。

**辨析｜易错点：** 集中式的"单仓库"是它的双刃剑——**简单但脆弱**。提交必须联网、仓库必须有人维护、历史只有一个备份点。对小型团队与入门场景，集中式够用；但它的"集中"也意味着**单点依赖**，这与现代分布式协作（远程团队、离线开发）格格不入。

## 3 分布式版本控制（DVCS）

**分布式（Distributed VCS）**：每个开发者的本地都有一份**完整的仓库副本**（含全部历史），提交在**本地**完成，通过**推送（push）/拉取（pull）**与远程仓库同步。

代表：Git、Mercurial。

- **优点**：**离线可提交**（本地就有完整历史）、**多备份**（每个克隆都是完整仓库，没有单点故障）、**分支廉价**（本地分支秒级创建）、**灵活的工作流**（本地提交、再推送）。
- **缺点**：**概念复杂**（本地/远程、暂存区、多个 remote）、**历史可能分叉**（需要合并纪律）、对新手陡峭。

**辨析｜易错点：** Git 的"本地完整副本"是它与集中式的**本质区别**——**集中式里"提交"是"上传"，分布式里"提交"是"本地记录，推送才是上传"**。这个区别解释了 Git 新手最常见的困惑：**"为什么我提交了，远程仓库却没有？"**——因为提交在本地，要 `git push` 才到远程。<span class="marginnote">Git 的"分布式"还有一个深度含义：<strong>没有"唯一的权威仓库"</strong>。所谓远程（origin）只是"大家约定的公共交换点"，不是"唯一的真相源"。这带来了 Git 工作流（下一节）的多样性——Git Flow、GitHub Flow 本质都是"团队约定如何用 Git 的分布式能力"。理解"仓库平等、约定造权威"，是理解一切 Git 工作流的前提。</span>

## 4 两种模型的对比

| 维度 | 集中式（SVN） | 分布式（Git） |
| --- | --- | --- |
| 仓库 | 唯一中央仓库 | 每个克隆都是完整仓库 |
| 提交 | 必须联网上传 | 本地记录，推送才同步 |
| 离线 | 无法提交 | 可完整工作 |
| 分支 | 重、在服务器 | 轻、在本地 |
| 单点故障 | 有 | 无 |
| 学习曲线 | 平缓 | 陡峭 |
| 历史 | 单一线性 | 可分叉、需合并纪律 |

**关键判断：** 现代软件工程几乎全面采用 Git（DVCS），原因是**分布式天然适合远程协作、离线开发、并行分支**。但"用 Git"不等于"用好 Git"——**Git 的价值取决于分支策略与协作纪律**，这正是下一节的内容。<span class="marginnote">值得注意：Git 的"陡峭"是工具层的陡峭，不是概念层的陡峭——Git 只有"提交、分支、合并、推送"四个核心概念，其余都是变体。一旦理解了"本地完整副本 + 提交与推送分离"，Git 的多数困惑会迎刃而解。学习 Git 的正确路径不是背命令，而是<strong>先理解模型（分布式、三区、快照），再学命令</strong>——命令是模型的操作化。</span>

## 5 小结

- **版本控制**记录每次变更历史，历史是核心资产，备份只是复制。
- **集中式（SVN）**：唯一中央仓库，简单但单点故障、离线受限、分支重。
- **分布式（Git）**：本地完整副本，离线可提交、多备份、分支廉价。
- 核心区别：**提交在本地、推送才同步**——解释了大量 Git 新手困惑。
- 分布式没有"唯一真相源"，工作流靠团队约定（下一节）。
- 学 Git 的正确路径：**先理解模型（分布式、三区、快照），再学命令**。
