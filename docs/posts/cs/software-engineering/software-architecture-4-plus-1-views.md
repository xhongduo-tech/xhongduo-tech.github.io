## 为什么从体系结构开始

前一章讲完构件级设计，这一章把镜头拉远到**系统级**：**软件体系结构（software architecture）**。它是最早做出、最难更改、影响最深远的决策。这一节先回答三个问题：体系结构到底"作用"在哪，它该如何**描述**（4+1 视图模型），以及描述语言是什么。

## 1 体系结构的作用：非功能性需求的承载者

**软件体系结构**：系统的整体结构——**构件**（component，计算与存储单元）、**连接件**（connector，构件间的交互机制）、**约束**（constraint，规则）与**属性**（attribute，质量特征）。

体系结构的作用可以归结为一句话：**它决定系统的非功能性属性**。<span class="marginnote">功能（"做什么"）换种实现依然成立，但性能、安全、可用性、可修改性几乎完全由结构决定。把日志模块直接写在每个业务类里，系统就"不可维护"；把数据库访问散布在 UI 层，系统就"不可移植"。结构决定命运，这正是架构决策昂贵的原因。</span>

具体而言，体系结构影响：

**性能**：数据在哪、复制几份、同步还是异步。
**安全性**：信任边界在哪、敏感数据走哪条路径。
**可用性**：冗余如何部署、故障如何隔离。
**可维护性与可演化性**：模块边界是否匹配业务变化方向。

## 2 4+1 视图模型：同一座建筑的五张图纸

一个复杂的软件系统不可能用一张图说清。Philippe Kruchten 提出 **4+1 视图模型（4+1 View Model）**：用五个互补视图描述体系结构。

| 视图 | 回答的问题 | 面向的读者 |
| --- | --- | --- |
| 逻辑视图（Logical） | 系统由哪些类/模块组成、职责如何分配 | 设计人员、领域专家 |
| 过程视图（Process） | 并发与同步：进程/线程、时序、同步机制 | 系统集成者、性能工程师 |
| 开发视图（Development） | 代码如何组织成包/层/子系统 | 程序员、构建管理者 |
| 物理视图（Physical） | 构件如何部署到硬件节点 | 部署工程师、运维 |
| 场景视图（Scenarios，+1） | 关键用例如何贯穿四个视图 | 所有人——串起其他四者 |

**辨析｜易错点：** "4+1" 的 "1"（场景视图）不是第五个并列视图，而是**粘合剂**：它用一个关键用例（如"借书"）沿着逻辑→过程→开发→物理四个视图走一遍，验证四者是否一致。没有场景视图，四个视图可能各画各的、互相对不上。<span class="marginnote">4+1 的核心洞见：<strong>架构文档不需要一张"总图"，而需要一组"互补的图"</strong>。这与第 3 章分析阶段"场景/类/行为/数据多模型互补"是同一方法论在架构层级的复现——多视角是理解复杂系统的唯一方式。</span>

## 3 视图的载体：UML 图

每个视图用 UML 图承载：

**逻辑视图**：类图、对象图。
**过程视图**：顺序图、活动图、状态图。
**开发视图**：组件图、包图。
**物理视图**：部署图。
**场景视图**：用例图。

**辨析｜易错点：** 画架构图最常见的错误是**"用一张组件图冒充全部视图"**——只在组件图上堆几十个框，却不画部署、不画进程、不画关键用例的时序。评审时的第一问应该是：**这张图回答的是哪个视图的问题？** 回答不出，就是图没画对。

## 4 描述体系结构的三种表述

描述体系结构有三种粒度递增的表述：

**体系结构风格（architectural style）**：宏观的组织模式（数据流、调用-返回、层次、事件驱动……），是"大词汇表"——后面三节逐一展开。
**设计模式（design pattern）**：构件内的局部方案（第 6 章）。
**参考体系结构（reference architecture）**：特定领域的标准结构（如 E-commerce 参考架构、分层 Web 架构）。<span class="marginnote">参考架构是"领域教材"：它凝聚了一个领域的成熟实践，新项目照它裁剪即可。例如大多数 Web 应用的参考架构是"浏览器→负载均衡→应用服务器→数据库+缓存"。先有参考架构，再做定制，是架构实践的高效路径。</span>

## 5 小结

- **软件体系结构** = 构件 + 连接件 + 约束 + 属性，是**非功能性需求的承载者**。
- 体系结构是最早、最难改、影响最深的决策。
- **4+1 视图**：逻辑 / 过程 / 开发 / 物理 + 场景，五个互补视图描述同一系统。
- 场景视图是**粘合剂**，用关键用例验证四个视图的一致性。
- 描述体系结构的三级词汇：**风格 → 模式 → 参考体系结构**。
