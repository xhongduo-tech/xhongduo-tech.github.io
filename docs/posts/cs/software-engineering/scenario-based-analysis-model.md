## 为什么从场景开始

上一节的用户故事与用例，已经引入了"场景"这个关键词。这一节把它放大成一种**完整的分析视角**：**基于场景的分析模型（scenario-based model）**。它回答一个朴素的追问——"系统到底怎么被用起来？"——并由此派生出系统行为、类结构、数据流的分析起点。在 Pressman 的体系里，场景模型是四类分析模型（场景、类、行为、数据）之首，因为它最贴近人脑的叙事本能。

## 1 场景：需求分析的第一语言

**场景（scenario）**是对系统在特定环境下与特定参与者交互的一段**具体叙事**。它与用例的区别在于：

- **场景是具体的**：「读者小明在周五晚上用手机检索《三体》，点击预约，收到确认短信」——有具体的人、时间、对象。
- **用例是抽象的**：把具体场景抽象成「参与者检索并预约资源」的通用步骤。

**起点场景（initial scenario）**与**正常场景（normal scenario）**是最先写的；随后补充**例外场景**（资源已借出）、**替代场景**（无借书证）、**取消场景**等。<span class="marginnote">Pressman 建议每个关键场景附一个<strong>场景描述表</strong>：场景 ID、发起者、前置条件、步骤序列、后置条件、涉及数据与对象、异常分支。表格式的场景让分析模型的完整度可以检查：每个前置条件都应有步骤覆盖，每个步骤都应有后置结果。</span>

## 2 从场景到用例的规范化

场景写多了会显得散乱，于是要做**规范化（normalization）**：把相似场景合并、提炼出通用步骤。规范化的产物就是用例。步骤如下：

1. 收集全部场景（主场景 + 所有变体）。
2. 提取共同步骤序列 → 主成功场景。
3. 把变体映射为备选流与扩展点。
4. 检查覆盖：每个用户目标至少有一个场景；每个异常至少有一个备选流。

**辨析｜易错点：** 场景规范化的陷阱是"过度抽象"：把两个**行为不同**的场景硬合并成一个用例，导致用例文本里到处是"如果……否则……"，可读性与可测性双输。判断标准：合并后主流程还能否用一句"参与者做 X 系统做 Y"讲清楚？讲不清就拆开。

## 3 场景模板与"基本事件流"

业界流传多种场景模板，其内核一致。Pressman 的场景模型通常包含：

| 要素 | 内容 | 示例 |
| --- | --- | --- |
| 场景名 | 动词短语 | 预约图书 |
| 参与者 | 发起与协作角色 | 读者、图书管理员、支付网关 |
| 前置条件 | 开始时的系统状态 | 读者已注册、馆藏有该书 |
| 事件流 | 主/备选步骤序列 | 见下 |
| 异常处理 | 失败路径与对策 | 库存不足 → 提示可预订 |
| 后置条件 | 结束时的系统状态 | 预约记录生成、配额占用 |
| 涉及对象 | 场景操作的数据实体 | Book、Reservation |

其中**事件流（event flow）**是心脏，写作风格是显式的交替：

1. 读者提交检索请求 → 2. 系统返回书目列表 → 3. 读者选择图书并发起预约 → 4. 系统校验馆藏并生成预约记录 → 5. 系统发送确认短信。

每个"读者做"对应一个"系统应"，这正是需求与测试一一对应的根基。<span class="marginnote">注意事件流的两种视角：<strong>叙述式</strong>（自然语言段落）适合与人沟通，<strong>结构化</strong>（编号步骤）适合驱动设计与测试。成熟团队常两者都写：结构化为主、叙述式解释歧义点。</span>

## 4 从场景模型到其他分析模型

场景模型不是孤立产物，它是分析模型的"入口"，向下游辐射：

**场景 → 行为模型**：事件流里的"系统响应"正是状态转换的触发条件，直接喂给状态图（见《行为建模》）。
**场景 → 类模型**：事件流里的名词（读者、书目、预约记录）正是候选类，直接喂给 CRC 建模。
**场景 → 数据模型**：事件流里被创建、修改、读取的数据实体，正是数据模型的实体来源。<span class="marginnote">这是一个重要的"需求方法学"观点：<strong>名词 → 类，动词 → 方法，状态变化 → 状态机，数据流动 → DFD</strong>。场景模型把四种分析统一起来，是你从零开始建模时的最佳起点。</span>

## 5 小结

- **场景**是具体叙事，**用例**是抽象模板；场景是用例的原料。
- 起点场景、正常场景、例外场景、替代场景共同覆盖一个用户目标。
- **规范化**把相似场景提炼成用例的主流程与备选流，注意避免过度抽象。
- 场景模板的核心是**事件流**——"参与者做 X，系统做 Y"的交替序列。
- 场景模型是分析模型的**入口**：名词喂给类模型、状态变化喂给行为模型、数据流动喂给数据模型。
