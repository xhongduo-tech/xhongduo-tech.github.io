## 为什么从界面设计开始

前面的章节都在讲"系统内部"——模块、架构、模式。这一章转向用户直接触摸的**用户界面（UI）**。界面是系统的门面：内部再优雅，界面反人类，用户就认为系统烂。这一节先立住界面设计的**三条黄金规则**（Theo Mandel 提出，Pressman 沿用），它们是后面所有界面工作的总纲。

## 1 黄金规则一：让用户掌控系统

**"让用户掌控系统（Place the user in control）"**——用户应该感觉自己在开车，而不是被系统推着走。它的反面是"系统替用户做决定"。

落实这条规则的实践：

- **避免强制模式（modal）**：除非必须（危险操作），否则不要用弹窗把用户困在某一模式里。
- **提供撤销（undo）**：允许用户反悔——"误操作可逆"是掌控感的核心。
- **让交互可定制**：允许用户调整界面（布局、快捷键、默认值）。
- **不要替用户下结论**：系统可以建议，但要给用户最终决定权。

**辨析｜易错点：** "让用户掌控" ≠ "把所有选项都扔给用户"。掌控感来自"**用户能做主**"，而不是"用户要处理更多选择"——选项过载同样是失去掌控。好的设计是"默认值合理 + 高级选项可展开"，而非"平铺所有开关"。

## 2 黄金规则二：减少用户的记忆负担

**"减少用户的记忆负担（Reduce the user's memory load）"**——系统应替用户记住信息，用户不需要在页面之间搬运记忆。

落实手段：

- **识别优于回忆（recognition over recall）**：让用户"认出来"而不是"想起来"——下拉菜单优于让用户敲命令，图标配文字标签。
- **保持一致**：同一操作在同一位置、同一颜色、同一说法——用户学会一次，处处适用。
- **提供上下文**：页面标题、当前位置、表单提示——让用户随时知道"我在哪、我在干什么"。
- **默认值与联想输入**：记住上次的选择，自动补全。<span class="marginnote">心理学里有个"<strong>7±2 原则</strong>"（米勒定律）：工作记忆能同时保持的信息约 7±2 个组块。界面设计把它翻译成"不要把太多信息一次性砸给用户"——分步引导（向导）、渐进披露（progressive disclosure）、分页，都是在给用户的记忆"减负"。</span>

**辨析｜易错点：** 减少记忆负担 ≠ "界面越简单越好"。它是"**把该记住的交给系统**"，而不是"把功能藏起来"。把高级功能藏在不可发现的角落里，同样增加认知负担——只是从"记"变成"找"。

## 3 黄金规则三：保持界面一致

**"保持界面一致（Keep the interface consistent）"**——相同的信息用相同的表示，相同的操作触发相同的结果，同类场景用同类交互。

一致性分三个层次：

- **内部一致**：同一应用内——所有"删除"都是同一个按钮样式、同一套确认流程。
- **外部一致**：与平台惯例一致——Mac 与 Windows 的快捷键、滚动方向遵循平台规范。
- **隐喻一致**：与现实世界的类比一致——"垃圾桶"表示删除、"放大镜"表示搜索。

不一致的代价是**学习成本**：用户每遇到一个"似曾相识却又不完全一样"的控件，都要停下来重新判断。<span class="marginnote">一致性不是"完全不变"。真正专业的做法是<strong>"有原则地一致"</strong>：统一遵循一套设计规范（design system），在规范内允许有意义的差异化——"危险操作用红色"是一致，"不同业务模块配色略有区分"也是建立在规范之上的合理差异。一致性管"规则"，不是管"完全相同"。</span>

**辨析｜易错点：** 一致性 ≠ 呆板统一。过度一致会抹掉必要的语义差异（所有按钮一个样，用户分不清"提交"与"删除"）。一致性要的是"**相同的信息行为相同、不同的信息行为不同**"——语义差异本身也是一种一致。

## 4 三条规则的落点

| 黄金规则 | 核心问题 | 典型反例 | 典型正例 |
| --- | --- | --- | --- |
| 用户掌控 | 谁在做主？ | 强制弹窗、无法撤销 | 撤销/重做、可定制布局 |
| 减少记忆负担 | 谁在记？ | 让用户记编号、记步骤 | 下拉选择、自动补全 |
| 保持一致 | 是否可预测？ | 删除按钮样式不一 | 统一设计规范 |

三条规则最终服务于一个目标：**让用户把认知资源花在任务上，而不是花在界面上**。<span class="marginnote">这三条"黄金规则"与第 3 章的需求工程相连：界面需求（非功能性需求的一部分）应在需求阶段就写清楚"一致性、可控性、低认知负担"的目标，让设计、实现、测试有据可依。好的界面不是美学问题，而是<strong>需求、设计、测试共同保证的工程产物</strong>。</span>

## 5 小结

- **让用户掌控系统**：可撤销、少强制模式、可定制、不替用户下结论。
- **减少记忆负担**：识别优于回忆、保持一致、提供上下文、善用默认值。
- **保持界面一致**：内部一致、外部一致（平台惯例）、隐喻一致（现实类比）。
- 一致性是有原则地统一，不是呆板地完全相同。
- 三条规则服务同一目标：**让用户把认知资源花在任务上**。
- 界面质量是需求、设计、测试共同保证的工程产物，不只是美学。
