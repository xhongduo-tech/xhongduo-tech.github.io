## 为什么从遗留系统开始

可维护性差的软件还活着，就成了**遗留系统（legacy system）**。现实残酷而清醒：**大量关键业务系统是遗留系统**——银行核心、航空订座、政府系统，跑了十几年甚至几十年，又老又关键。这一节讲遗留系统的困境、它的几种演化策略，以及**再工程（reengineering）**为什么是"第三条路"。

## 1 遗留系统的两面

**遗留系统（legacy system）**：仍在使用、但基于过时技术/结构、难以维护的旧系统。

它的"两面"让它陷入两难：

- **为什么不能直接扔**：承载关键业务逻辑、积累了数十年领域知识、替换风险极高、停机不可接受。
- **为什么不能放着不管**：技术过时（老语言、老平台）、人才难找、难以扩展、与新技术（云、移动、AI）难集成。

**辨析｜易错点：** 对遗留系统最危险的态度有两个极端——"**全盘重写**"（烧钱又冒险，业务逻辑重写必然遗漏，New Hampshire 效应）与"**死也不动**"（系统越来越僵死）。现实中绝大多数的"重写计划"都以失败告终：**重写丢失了隐性业务知识**。遗留系统的正确姿势，是在"重写"与"不动"之间寻找中间路线。

## 2 遗留系统的演化策略谱系

处理遗留系统，有一组从"不动"到"重写"的策略谱系：

| 策略 | 做法 | 风险/成本 | 适用 |
| --- | --- | --- | --- |
| 维持现状 | 只做必要维护 | 低/低 | 系统接近退役 |
| 包装（wrapping） | 用接口包装旧系统 | 低/中 | 需要给旧系统新接口 |
| 迁移（migration） | 迁到新平台/新语言 | 中/高 | 平台过时但逻辑仍有效 |
| 再工程（reengineering） | 重构+逆向+正向结合 | 中/中 | 结构恶化但价值仍高 |
| 完全重写 | 从头开发 | 高/极高 | 系统已无价值或需求全变 |

**辨析｜易错点：** 策略选择的核心判断是"**旧系统的价值 vs 它的质量**"：价值高且质量差 → 再工程；价值低且质量差 → 考虑重写或退役；价值高且质量尚可 → 包装或迁移。**"重写"是最后手段而非首选**——先问"这堆业务逻辑你写得出来吗"，写不出来就乖乖走再工程。

## 3 再工程：不重写但翻新

**再工程（reengineering）**：**对现有软件进行审视与改造，以新的形式重新实现它，而不改变其功能**。它不是重写（不推倒重来），也不是纯维护（不只是小修小补），而是**"逆向理解 + 正向重建"的结合**。

再工程的活动循环：

1. **库存分析（inventory analysis）**：盘点系统现状，确定哪些值得再工程。
2. **逆向工程（reverse engineering）**：从现有代码提取设计信息（下一节详述）。
3. **重构（restructuring）**：在保持行为的前提下改善结构（第 14 章）。
4. **正向工程（forward engineering）**：用改进后的设计重新实现。
5. **经济性评估**：随时评估"再工程的成本 vs 收益"。

<span class="marginnote">再工程与重写的关键区别：<strong>重写面向"重新开始"，再工程面向"重建于旧基础之上"</strong>。再工程保留了"逆向获得的业务知识"（哪些逻辑是核心、哪些是历史包袱），这是重写最容易丢掉的东西。业界常说的"现代数字化改造"，大部分是再工程而非重写——用新架构承载旧业务，而不是把旧业务抹掉重来。</span>

## 4 再工程的经济性：什么时候值得

再工程不是免费的，需要**成本-收益分析**。关键指标：

**再工程成本**：逆向 + 重构 + 正向的人力与风险。
**维持现状成本**：继续维护旧系统的未来成本（会随结构退化上升）。
**业务机会成本**：旧系统挡住的业务创新。

**再工程值得做的判据**：再工程成本 < 维持现状的未来成本 + 业务机会损失，且系统价值仍高。<span class="marginnote">再工程的黄金法则与预防性维护一致：<strong>越早做越便宜</strong>。系统刚出现结构退化迹象时再工程，成本远低于退化到"没人敢碰"之后。这再次说明"预防性维护/再工程"不是奢侈品——<strong>它是"避免最贵选项（重写或僵死）"的投资</strong>。评估再工程的工具包括第 10 章的估算方法与第 15 章的度量——数据支撑"值不值得动"的决策。</span>

## 5 小结

- **遗留系统**过时但仍承载关键业务，陷入"不能扔也放不下"的两难。
- 处理策略谱系：**维持 → 包装 → 迁移 → 再工程 → 重写**，风险逐级升高。
- "全盘重写"多失败于**丢失隐性业务知识**——重写是最后手段。
- **再工程** = 逆向理解 + 正向重建，不改变功能而改善结构，保留业务知识。
- 再工程的循环：库存分析 → 逆向 → 重构 → 正向 → 经济性评估。
- 判据：再工程成本 < 维持现状成本 + 机会损失，且**越早做越便宜**。
