# 测试覆盖率：语句、分支、路径与条件覆盖

<div class="epigraph">

## 为什么从测试覆盖率开始

"测试充分了吗？"不能靠感觉回答。**测试覆盖率（test coverage）**给出量化答案：已执行的代码占全部代码的多少。但"覆盖率"不是一个指标，而是一族指标——语句、分支、路径、条件，各有各的"盲区视角"。这一节讲清这四种覆盖率、它们的关系与陷阱。

## 1 四种覆盖率

以这段代码为例（前面白盒测试用过的例子）：

```c
cin >> a >> b;
if (a > 1 && b < 0)
    x = a * b;      // 语句 1：真分支
else
    x = a - b;      // 语句 2：假分支
y = x + 1;          // 语句 3
```

- **语句覆盖（statement coverage）**：每个**可执行语句**至少执行一次。测试 `a=5, b=-1` 执行语句1、3，语句2 没执行——语句覆盖不要求覆盖假（else）分支。
- **分支覆盖（branch coverage）**：每个**判定分支**（真/假）至少走一次。需测**真分支（条件成立）**与**假分支（条件不成立）**两条，覆盖真/假两支。
- **条件覆盖（condition coverage）**：每个**条件的每个取值**至少一次。对 `a > 1 && b < 0`，要让 `a > 1` 真/假各一次、`b < 0` 真/假各一次。
- **路径覆盖（path coverage）**：每条**独立路径**至少走一次——最严格，也是基本路径测试的目标。

**辨析｜易错点：** 分支覆盖 ≠ 条件覆盖。分支覆盖看"整个判定的结果"（真/假），条件覆盖看"每个子条件的取值"。对 `a > 1 && b < 0`，分支覆盖只要“整体真一次、整体假一次”；条件覆盖要求 `a > 1` 与 `b < 0` 各自的真假都被验证——**条件覆盖比分支覆盖更细，但两者都不自动包含对方**。

## 2 覆盖率的强弱关系

四种覆盖率构成**强度阶梯**：

$$
\text{语句覆盖} \le \text{分支覆盖} \le \text{路径覆盖}
$$

**辨析｜易错点：** 更严格的覆盖**通常但未必**包含更宽松的覆盖——路径覆盖一定满足语句覆盖，但**分支覆盖与条件覆盖互不包含**（要同时满足两者需要专门设计）。工程师常犯的错误是**"把语句覆盖当充分标准"**——语句覆盖是最弱的标准，它甚至不要求覆盖所有判定分支，覆盖率 100% 的语句覆盖也测不出“分支逻辑错误”。

## 3 覆盖率与质量的关系

- **覆盖率低 ≠ 质量差，覆盖率高 ≠ 质量好**。覆盖率只是"测到了多少结构"，不保证"测对行为"——测了一条语句但断言错了，覆盖率照计。
- **覆盖率是"必要非充分"**：低覆盖率肯定有盲区；高覆盖率只是"盲区少了"，不含"缺陷没了"。
- **覆盖率的工程用法**：团队定**覆盖率门槛**（如语句覆盖 ≥ 80%、分支覆盖 ≥ 70%），作为 CI 的守门指标——低于门槛的提交不允许合并。<span class="marginnote">覆盖率门槛要有<strong>"目标化"的智慧</strong>：对高风险模块（支付、权限）要求高覆盖，对低风险模块（工具函数、样板代码）放低要求——<strong>按风险分配覆盖目标</strong>，而不是一刀切 "100%"。盲目追求 100% 覆盖，会诱导写"凑行数的假测试"，反而稀释测试质量。覆盖率是仪表盘，不是方向盘。</span>

## 4 覆盖率的测量工具

现代工具自动插桩统计覆盖率：

**C/C++**：gcov、lcov。
**Java**：JaCoCo、Cobertura。
**Python**：coverage.py。
**JavaScript**：Istanbul / nyc。

这些工具给出**结构级覆盖**（语句/分支/条件），配合 **CI**（第 13 章）在每次提交后生成覆盖率报告、按门槛拦截。<span class="marginnote">除了"结构覆盖"，还有一类"行为覆盖"：需求覆盖（每条需求有测试对应，对应第 3 章的追踪矩阵）与缺陷覆盖（每个历史 bug 有回归用例）。完整的测试充分性判断 = <strong>结构覆盖 + 需求覆盖 + 缺陷覆盖</strong> 三个维度，结构覆盖率只是最容易量化的那一项。</span>

## 5 小结

- **语句覆盖**最弱（每条语句一次），**分支覆盖**（每分支一次）、**条件覆盖**（每条件取值一次）、**路径覆盖**最严（每条独立路径一次）。
- 覆盖率强度阶梯：语句 ≤ 分支 ≤ 路径；分支与条件**互不包含**。
- 覆盖率是"必要非充分"：低覆盖必有盲区，高覆盖不代表无缺陷。
- 工程用法：**按风险设定覆盖门槛**，由 CI 守门，而非盲目 100%。
- 完整充分性 = 结构覆盖 + 需求覆盖（追踪矩阵）+ 缺陷覆盖（回归集）。
- 覆盖率是仪表盘，不是方向盘——它指出盲区，不保证正确。
