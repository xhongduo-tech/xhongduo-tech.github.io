# 项目进度计划：WBS、甘特图与关键路径

## 为什么从进度计划开始

估算给出了"要多少人月"，这一节把它排成"**时间表**"——什么任务、什么顺序、什么时候做完。进度计划的三大工具：**WBS**（把项目拆成可管理的任务）、**甘特图**（把任务画到时间轴上）、**关键路径**（找出决定工期的命脉）。它们从"拆"到"画"到"算"，是项目调度的完整链条。

## 1 WBS：把项目拆成可管理的工作包

**工作分解结构（Work Breakdown Structure, WBS）**：把项目**自顶向下逐层分解**成更小、可管理、可估算、可分配的工作包。

WBS 的分解原则：

- **100% 原则**：子任务之和必须**完整覆盖**父任务（不多不少）。
- **可管理粒度**：工作包小到"一人能在一段时间内完成"。
- **可验证结果**：每个工作包有明确的交付物/完成标准。

以"开发网上书店"为例的 WBS 片段：

| 层级 | 工作包 |
| --- | --- |
| 1 | 网上书店 |
| 1.1 | 订单模块 |
| 1.1.1 | 购物车 |
| 1.1.2 | 结算 |
| 1.2 | 支付模块 |
| 1.2.1 | 对接支付网关 |
| 1.2.2 | 退款处理 |
| 1.3 | 库存模块 |
| 1.3.1 | 库存扣减 |
| 1.3.2 | 入库管理 |

**辨析｜易错点：** WBS 分解的常见错误是"**按组织结构拆**"（前端组/后端组）而不是"**按交付物拆**"（订单模块/支付模块）。WBS 的粒度单位是**可交付成果**，不是部门。判断标准：**每个叶子工作包能不能说清"完成时交付什么"？** 说不清的分解是假分解。

## 2 甘特图：把任务画到时间轴

**甘特图（Gantt chart）**用**横向条形图**展示任务的时间安排：

- **横轴**：时间（天/周）。
- **纵轴**：任务列表。
- **条形**：任务的开始与结束时间。
- **依赖线**：箭头表示任务先后关系。
- **里程碑**：菱形标记关键节点。

甘特图的价值是**直观**：一眼看到"现在该做什么""谁在忙什么""哪个任务要等哪个任务"。它的局限是**静态**——复杂依赖关系难以在甘特图上精确表达，任务一多就显得拥挤。

**辨析｜易错点：** 甘特图 ≠ 进度管理。**画了甘特图只是计划，跟踪进度（实际 vs 计划）才是管理**。甘特图的常见死法是"画完就没人更新"——计划与实际脱节，图表沦为摆设。让甘特图活起来的关键：**定期更新实际进度线，对比计划线，暴露偏差**。

## 3 关键路径：决定工期的命脉

**关键路径法（Critical Path Method, CPM）**用**网络图**（节点=任务、边=依赖）计算项目的最短工期与关键任务。

核心概念：

- **最早开始时间（ES）**：任务最早何时能开始（正推）。
- **最晚开始时间（LS）**：任务最晚何时开始而不延误工期（逆推）。
- **浮动时间（slack / float）**：$LS - ES$——任务能拖延多久而不影响总工期。
- **关键路径**：浮动时间为零的任务组成的路径——**决定项目总工期**。

**公式解析**：对任务 $i$，浮动时间 $Slack_i = LS_i - ES_i$。**关键路径上的任务浮动时间为 0**——它们任何一天的延误都直接延长项目总工期；非关键任务有正浮动，可在浮动范围内调度资源。<span class="marginnote">关键路径的工程含义：<strong>只有压缩关键路径上的任务才能缩短总工期</strong>。加资源压"非关键任务"毫无意义——它本来就有富余。反过来，关键路径任务的任何延误都不可容忍，所以要<strong>优先保障关键路径上的资源与监控</strong>。一个项目的总工期，就是它关键路径的长度——这条判断决定了"该往哪里用力"。</span>

## 4 三者配合：从拆到画到算

| 工具 | 回答的问题 | 产物 |
| --- | --- | --- |
| WBS | 项目由哪些任务组成 | 任务层级清单 |
| 甘特图 | 任务何时做、谁做 | 时间轴条形图 |
| 关键路径 | 哪个任务决定工期 | 网络图 + 浮动时间 |

配合流程：**用 WBS 拆任务 → 用网络图建依赖 → 用 CPM 算关键路径 → 用甘特图呈现时间表**。

**辨析｜易错点：** 资源冲突是排期的隐藏杀手——WBS 拆出任务、算出关键路径后，还要检查**资源是否超载**（同一个人被同时安排两个关键任务）。出现冲突时，利用**非关键任务的浮动时间**重新调度，让资源向关键路径倾斜。**排期不仅是排时间，更是排资源**——忽略资源约束的甘特图，只是纸上谈兵。

## 5 小结

- **WBS** 自顶向下拆项目，遵循 100% 原则，按**交付物**分解。
- **甘特图**用条形图展示任务时间与依赖，直观但需持续更新实际进度。
- **关键路径法**用 ES/LS/浮动时间找"零浮动"的关键任务链，它决定总工期。
- **只有压缩关键路径**才能缩短工期；关键路径任务要优先保障资源。
- 三者配合：WBS 拆 → CPM 算 → 甘特图画。
- 排期要**同时排资源**，用非关键任务的浮动消化资源冲突。
