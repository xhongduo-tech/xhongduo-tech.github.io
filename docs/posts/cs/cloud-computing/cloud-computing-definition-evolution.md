## 为什么从定义与演进开始

在第三级计算机基础里，你已经学过操作系统、计算机网络与分布式系统——云计算正是这三者在一门学科里的交汇点<span class="marginnote">云计算 = 分布式计算 + 虚拟化 + 网络服务化。它把操作系统的资源管理、网络的分层协议与分布式的容错机制，统一收敛成「按需租用」的商业模型。可回看第三级《分布式系统》的总体框架。</span>。要理解后续的虚拟化、容器、对象存储与无服务器，首先得回答两个看似朴素的问题：**云计算到底是什么？它又是从哪条历史脉络里长出来的？** 这一篇先把坐标立起来。

一个提醒：**不要用「云 = 远程服务器」来理解云**——那是 20 世纪的主机时代。云的核心不是「远程」，而是「按需、弹性、计量」这三个词。本专题的全部内容，都是这三个词在不同层面的展开。先把「远程」这个旧印象放下，这篇的定义会自然立住。

## 1 云计算的定义：把「计算」变成「水电气」

学术界与产业界引用最广的定义来自美国国家标准与技术研究院（NIST）SP 800-145 文档。**云计算（cloud computing）**：一种让用户通过互联网，按需获取一个**可配置计算资源池**（网络、服务器、存储、应用与服务），并能够快速供给与释放、只需极少管理开销或与服务商交互的模式。

拆开这一定义，有三个关键词构成了云的本质：

- **资源池（pooling）**：底层资源被多租户共享，物理边界被虚拟化抹平，用户看到的是一大片「可随时取用」的算力与存储。
- **按需自助（on-demand self-service）**：用户自行开通、配置、释放资源，不需要人工介入——就像拧开水龙头不需要给自来水公司打电话。
- **计量付费（metered service）**：用量被精确计量，按使用量计费（如按小时、按 GB、按请求数），把 IT 从「买资产」变成「买服务」。

<span class="marginnote">NIST SP 800-145 定义的五条核心特征（按需自助、广泛网络接入、资源池化、快速弹性、可计量服务）是考试与面试的「标准答案」，也是下一篇《云计算的核心特征》逐条展开的骨架。</span>云计算的英文词源同样说明问题：早期架构图里习惯用「一朵云」来画互联网，云代表「你不用关心里面长什么样」——**用户只关心接口，不关心实现**。

## 2 演进：从巨型机到公用计算

云计算不是横空出世，而是计算产业对「如何共享昂贵算力」这一老问题的一次次回答。整条演进线可以概括为四步：

- **巨型机时代（1960s—1970s）**：一台主机、多个哑终端。算力集中在主机上，终端只负责输入输出。IBM System/360 是这一代的代表，其分时操作系统（TSS）已经具备「多人共享 CPU」的雏形。
- **客户-服务器时代（1980s—1990s）**：微型计算机（PC）普及，算力下沉到桌面。局域网把 PC 与服务器连起来，但每台机器仍是相对孤立的资产，闲置率高、管理成本高。
- **网格计算与效用计算（1990s—2000s）**：网格计算（grid computing）把地理上分散的异构计算机组织起来，协同求解科学计算问题（SETI@home 是公众熟知的例子）。效用计算（utility computing）主张「按用量付费」，把计算当作公共服务来卖——这是云的商业思想先驱，但还缺少「按需弹性」与「资源池化」的工程实现。
- **云计算（2006 起）**：AWS 于 2006 年推出 S3 与 EC2，第一次把「按需租用虚拟机与对象存储」做成了普惠的线上商品。此后 Azure、Google Cloud、阿里云相继跟进，云成为新算力底座。<span class="marginnote">2006 年被普遍视为云计算元年：AWS 的 EC2（弹性计算云）与 S3（简单存储服务）同年上线，标志着「可计量的虚拟计算」首次以标准化 API 形式向公众出售。此前的公用计算更多停留在实验与内部部署。</span>

## 3 核心要点对比：云计算 vs 传统 IT vs 网格计算

纯概念主题用一张对比表把差异钉死，比冗长的叙述更有效：

| 维度 | 传统自建 IT | 网格计算 | 云计算 |
| --- | --- | --- | --- |
| 供给方式 | 采购硬件，提前规划 | 组织既有闲置算力 | 按需自助、即时供给 |
| 计费模式 | 一次性资本开支 | 多为科研共享 | 按用量计量付费 |
| 弹性 | 扩容需数月 | 弱 | 分钟级伸缩 |
| 资源池化 | 无（物理隔离） | 松散聚合 | 多租户共享池 |
| 用户界面 | 现场管理 | 作业提交 | Web/API 自助 |
| 抽象层次 | 物理机 | 任务级 | 基础设施/平台/软件 |

**辨析｜易错点：** 云计算常被误认为是网格计算的「换皮」。关键区别在于：网格计算面向**特定任务**、把闲置资源捐给科研计算，弹性与计费都弱；云计算面向**通用负载**、以资源池与 API 为产品，把「供给-计费-释放」做成闭环。<span class="marginnote">另一个高频误区是把「虚拟化」与「云计算」划等号。虚拟化是云的技术手段之一，但云还包含自服务、计量、弹性这些虚拟化本身不具备的商业化能力——后面第二篇《服务器虚拟化原理》会专门展开。</span>

## 4 为什么说「云」是一层新的抽象

从计算机组成原理的角度看，云的本质是**把硬件差异向上掩盖，向下汇聚**。操作系统向上层进程提供「进程、文件、socket」这组抽象；云则向用户提供「虚拟机、对象桶、负载均衡」这组抽象——它们都是**接口即承诺**：接口稳定，实现可换。底层可以是一台物理机，也可以是一万台；对你（用户）而言没有区别。这正呼应了你已经学过的分层思想：每一层只对上一层暴露受控接口，内部变化被吞没在抽象边界之内。<span class="marginnote">「抽象与接口」是贯穿整个计算机基础课程的主线：指令集抽象硬件、系统调用抽象内核、HTTP 抽象 Web 服务。云只是把这条线的终点再往上推了一层——把「数据中心」本身也抽象成了 API。</span>

## 5 判定框架：如何识别一朵「真云」

定义讲完，落到判断力上：**凭什么说某个系统是云，而另一个只是「远程机房」？** 用一篇《核心特征》的标准做一次「体检」，五问即可：

1. **按需自助吗？** 用户能不经过人工审批，自己开通、释放资源吗？
2. **广泛接入吗？** 通过标准网络协议、从任意设备可访问吗？
3. **资源池化吗？** 多租户共享一个资源池，靠逻辑隔离而非物理隔离吗？
4. **快速弹性吗？** 资源能在分钟级扩缩，而非提前数月规划吗？
5. **可计量吗？** 用量被精确测量、按量计费吗？

拿这三家做对比：

| 系统 | 按需 | 接入 | 池化 | 弹性 | 计量 | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| 阿里云 ECS | ✅ | ✅ | ✅ | ✅ | ✅ | 真云 |
| 传统虚拟化集群 | ❌ | ❌ | ✅ | ❌ | ❌ | 不是云 |
| 公司内部 PaaS | ✅ | ✅ | ✅ | 部分 | 部分 | 准云 |

**辨析｜易错点：** 判定时最容易「误伤」的是「**看着像云、其实不是**」的系统：某个团队说「我们上了私有云」，一问——开通虚拟机要提工单、用多少资源不计量、扩容要买新服务器。**它只是虚拟化 + 自动化的产物，缺了自助与计量这两条，就不满足 NIST 定义**。反过来，也别把「不是云」当成「不好」——自建虚拟化集群在安全与可控上自有价值，只是它不该叫「云」。

## 6 云的行业影响：从初创公司到大模型

定义、演进、判定都讲清了，最后看一眼云**改变了什么**——这决定你为什么要学它。

**对创业公司的改变：零固定资产起步**。20 年前的互联网创业要先买服务器、租机房，烧完一轮融资才把产品跑起来；今天用云，信用卡一刷，几分钟内就有生产级环境。「按用量付费」把**启动成本从百万级降到千元级**，失败成本也随之下沉——这是过去二十年创业门槛骤降的技术底色。

**对成熟企业的改变：弹性从口号变成日常**。电商大促、春节抢票、热点事件——流量可以在几分钟内暴涨十倍。自建机房要提前数月扩容，云让你「平时省钱、峰值够用」，把「为峰值买单」变成「为实际买单」（见《云计算的核心特征》）。

**对 AI 行业的改变：算力成了可租用的水电气**。今天的大模型训练与推理，动辄需要几千张 GPU 跑数月——没有任何创业公司能自建这种算力。**云让 AI 的入场券从「拥有超算」变成「租用超算」**，GPU 集群像自来水一样按量供应。这也是本博客「从极限到大模型」主线里，云计算作为「底座」的直接意义。<span class="marginnote">你正在读的这个网站、用到的各类在线服务，几乎都运行在云上。云不是「另一个行业」，而是「所有行业的地基」——<strong>理解了云，就理解了当代软件被构建、交付、运行的基本方式</strong>。这正是本专题在整个课程体系里的位置：它不是孤立的第三级课程，而是连接操作系统/网络/分布式与 AI 部署的枢纽。</span>

**辨析｜易错点：** 云的行业影响也有「阴影面」——**供应商集中**：全球算力高度集中于少数几家云厂商，一旦某家故障或断供，大量业务同时受影响；**数据出境与合规**：数据放在谁的云上，受谁的法律管辖。这些是《多云与混合云策略》《云安全与合规》要正面回答的问题。**技术中立，但选择有立场**——这是学完云计算后应该有的清醒。

## 7 一句话理解云：三个视角的合流

走到篇末，用三个视角把「云计算」浓缩成一句话，方便你在任何场合讲清楚它：

- **技术视角**：云 = **虚拟化 + 分布式 + 网络服务化**——把一台台物理机变成可切分、可调度、可通过网络按需供给的资源池（对应《虚拟化技术》整篇）。
- **商业视角**：云 = **IT 从「买资产」变「买服务」**——资本支出转运营支出，按用量付费（对应《云计算的核心特征》的计量）。
- **交付视角**：云 = **责任链的分段承包**——IaaS/PaaS/SaaS 切到哪层，你管到哪层（对应《云服务模型》）。

三个视角合起来：**云是把「算力」变成像水电气一样可按需购买的基础设施**——技术上是虚拟化与分布式的产物，商业上是按量计费的公共服务，交付上是责任的分层外包。

**辨析｜易错点：** 只从一个视角看云会失真——纯技术视角会忽略「计量付费」这个商业内核；纯商业视角会忽略「弹性」背后的虚拟化工程。**「三视角合流」才是对云的完整理解**，也是后续每一篇展开的坐标系：虚拟化篇回答「怎么切」，服务模型篇回答「切到哪」，核心特征篇回答「凭什么按量卖」。<span class="marginnote">如果只允许记住一句话，请记住：<strong>云不是一种技术，而是一种「算力即服务」的供给模式，虚拟化只是让它成为可能的手段</strong>。这个区分决定了你学云的方式——学的是「服务设计」（按需、弹性、计量、责任分界），而不是某个产品的按钮。本专题全部 33 篇，都是这句「服务化」在不同层面的展开。</span>

## 8 小结

- 云计算的 **NIST 定义**：通过网络按需获取可配置计算资源池，快速供给释放、低管理开销。
- 三个关键词：**资源池、按需自助、计量付费**。
- 演进脉络：**巨型机 → 客户-服务器 → 网格/效用计算 → 云计算**，云是「算力共享」老问题的当代答案。
- 与网格计算的差异：云面向通用负载、以 API 与计费为产品，网格面向特定任务、弱弹性。
- 云的本质：一层**新的抽象**，把数据中心抽象成 API。

- 定义篇的收官提醒：**定义不是「背下来」，而是「拿来判断」**——遇到任何一个「号称云」的系统，用这五条与判定框架过一遍，就能识破包装。

- 核心记忆点：**云不是技术，而是「算力即服务」的供给模式**——虚拟化只是实现手段。
- 判定框架速记：**按需 + 计量 + 弹性，缺一不叫云**——用这三问检验任何「号称云」的系统。
- 与后续的衔接：定义与演进是「坐标」，下一篇的五条特征是在坐标上画出的「能力边界」。
