## 为什么从 VPC 开始

第二篇的《网络虚拟化》讲了 VLAN 与 Overlay 的技术基础，这一篇把它们落地成云上的产品：**VPC**。在云上建一个应用，第一件事往往是「创建一个 VPC、划分子网、配安全组」——这套动作相当于**租户在云里自建一个私有局域网**。理解 VPC 的三件套（VPC、子网、安全组），你就掌握了云上所有网络配置的主干。

## 1 VPC：云上的私有网络

**VPC（Virtual Private Cloud，虚拟私有云）**：在云厂商的网络里，为单个租户划出的一个**逻辑隔离的私有网络**。创建 VPC 时你指定一个 IP 网段（CIDR，如 `10.0.0.0/16`），这个网段归你独占——别的租户不会占用它。这就是网络虚拟化篇里 Overlay 的成果：**物理网络共享，逻辑网络隔离**。<span class="marginnote">VPC 的核心承诺是「像自建机房一样自由」：你可以任意划分网段、搭建拓扑、控制进出。而这一切在物理上共享同一张云网络——多租户的隔离靠 VXLAN 的 VNI、靠路由隔离实现。你在《网络虚拟化》里学到的 VNI 概念，此刻成了 VPC 的底层身份标识。</span>

VPC 有几个关键的配套概念：

- **子网（subnet）**：把 VPC 的 IP 网段再切成小段（如 `10.0.1.0/24`），用于**组织与隔离**——比如「Web 子网」「数据库子网」。
- **路由表（route table）**：定义子网内的流量去向——发往 `10.0.0.0/8` 的走内网，发往 `0.0.0.0/0` 的走公网网关。
- **Internet 网关（IGW）**：把子网与互联网接通的「大门」。

## 2 公有子网与私有子网

按能否直接访问互联网，子网分为两类，这是最常用的规划模型：

| 子网类型 | 访问互联网 | 典型用途 | 安全策略 |
| --- | --- | --- | --- |
| 公有子网 | 是（经 IGW） | Web 服务器、负载均衡 | 只开放 80/443 入站 |
| 私有子网 | 否（需 NAT 网关） | 数据库、应用后端 | 只接受来自公有子网的访问 |

**核心思想：公网入口尽量少、攻击面尽量小**——只有必须对外的机器才放公有子网，数据库永远躲在私有子网里。对外访问互联网（如拉软件包），通过 **NAT 网关**统一出去，进一步收敛暴露面。<span class="marginnote">「公有子网 + 私有子网」是云架构教科书式的分层：<strong>Web 层暴露、应用层半暴露、数据层不暴露</strong>。这与第三级《计算机网络》的分层思想一脉相承——每层只信任它的直接上层，最小暴露原则贯穿整个网络设计。</span>

## 3 安全组与网络 ACL：两道防火墙

云上控制网络流量靠两类「过滤器」，它们的区别很关键：

- **安全组（security group）**：挂在**实例（ENI）**上的虚拟防火墙，**默认全拒**，只放行你显式允许的流量。它是**有状态（stateful）**的——允许了入站，自动允许对应出站响应。典型配置：Web 实例的安全组「入站只允许 80/443，源为 `0.0.0.0/0`」。
- **网络 ACL（Network ACL）**：挂在**子网**边界上的无状态过滤器，**默认全放**（除非显式拒绝）。它是**无状态（stateless）**的——入站出站要分别配置。

**辨析｜易错点：** 安全组管「哪台实例能进出」，网络 ACL 管「哪个子网能进出」；安全组有状态、默认拒绝，网络 ACL 无状态、默认允许。两者叠加时规则都生效（先过子网 ACL，再过实例安全组）。最稳妥的实践是：**ACL 做粗粒度子网边界，安全组做细粒度实例防护**。<span class="marginnote">安全组的「有状态」是初学者的高频混淆点：你在安全组里放行了「入站 80」，不用再配「出站回包」——系统自动允许。而网络 ACL 则必须「入站规则 + 出站规则」成对配置，少一条回包就丢。理解有状态/无状态，就理解了这两种防火墙的本质差异。</span>

## 4 核心要点对比：VPC 三件套的职责

| 对象 | 作用范围 | 管什么 | 关键属性 |
| --- | --- | --- | --- |
| VPC | 整个租户网络 | IP 网段、隔离边界 | CIDR、region |
| 子网 | VPC 内一段 | 网络分区、路由 | 可用区、路由表 |
| 安全组 | 单台实例 | 实例级入出站 | 有状态、默认拒绝 |
| 网络 ACL | 单个子网 | 子网级入出站 | 无状态、默认放行 |

**一句话总结这套架构**：VPC 给租户一张私有网，子网把它切成不同的安全区，路由表决定流量怎么走，安全组与 ACL 两层过滤决定谁能进出。<span class="marginnote">VPC 是云网络一切产品的地基：负载均衡、NAT 网关、VPN/专线、托管数据库，都长在某个 VPC 里。下一篇《负载均衡》会看到，LB 本身就是一个「放在公有子网、接进 VPC」的转发设备。</span>

## 5 打通世界：NAT、VPN 与专线

VPC 是「围起来的花园」，但花园总要对外联系。三类「通道」各管一段：

- **NAT 网关**：让**私有子网**的实例**主动访问互联网**（拉软件包、调外部 API），但外部**无法反向访问**它们。单向、安全、收敛暴露面。
- **VPN / 专线（Direct Connect）**：把**企业自建机房**与 VPC 安全打通。VPN 走公网加密隧道（便宜、靠 IPsec），专线走物理专线（贵、低延迟、稳定）——专线是金融、制造等对网络质量要求高的企业的标准选择。
- **VPC 对等连接（peering）**：把两个 VPC 直接打通，让不同业务线/不同账号的 VPC 互相通信，不经过公网。

| 通道 | 连接谁 | 安全性 | 成本 |
| --- | --- | --- | --- |
| NAT 网关 | 私有子网 → 公网 | 单向出站 | 低 |
| VPN | 机房 ↔ VPC | 加密隧道 | 中 |
| 专线 | 机房 ↔ VPC | 物理隔离 | 高 |
| 对等连接 | VPC ↔ VPC | 内网互通 | 低 |

**辨析｜易错点：** 分清**出站**与**入站**的方向。NAT 只解决「出去」；要让外部**进来**访问你的服务，得靠负载均衡 + 公网 IP（Ingress 层），而不是 NAT。「有了 NAT 就能被外网访问」是把方向搞反的常见误区。<span class="marginnote">「机房 ↔ 云」的打通，是混合云（《多云与混合云策略》）落地的网络基础：专线把私有云与公有云连成一张网，数据与应用才能自由迁移。你会看到，<strong>混合云的「打通」，首先打通的永远是网络</strong>——专线、VPN、对等连接，缺哪条，混合云就缺哪块。</span>

## 6 网络架构实战：经典三层 Web 架构

把 VPC 三件套组合起来，一个教科书式的云网络架构就诞生了——**三层 Web 架构**：

```
                    ┌───────────────────────────────┐
   用户 ──► CDN ──► │  公有子网 · Web 层              │
                    │  LB ─► Web 实例(安全组:80/443) │
                    └──────────────┬────────────────┘
                                   │ (内网，经安全组)
                    ┌──────────────▼────────────────┐
                    │  私有子网 · 应用层             │
                    │  应用实例(仅接受 Web 层访问)   │
                    └──────────────┬────────────────┘
                                   │ (内网)
                    ┌──────────────▼────────────────┐
                    │  私有子网 · 数据层             │
                    │  数据库(仅接受应用层访问)      │
                    └───────────────────────────────┘
```

三层的访问规则逐步收紧：

| 层 | 子网 | 谁能访问 | 安全组策略 |
| --- | --- | --- | --- |
| Web | 公有子网 | 所有人（经 LB） | 入站仅 80/443 |
| 应用 | 私有子网 | 仅 Web 层 | 入站仅来自 Web 安全组 |
| 数据 | 私有子网 | 仅应用层 | 入站仅来自应用安全组 |

**这条架构的精髓：攻击面逐层收敛**——能直接触达公网的只有 Web 层；应用与数据藏在私有子网，攻击者连路由都看不到。<span class="marginnote">安全组可以「引用另一个安全组」作为源——「只允许 Web 安全组的实例访问数据库」就是这么写的，比「允许某个 IP 段」更语义化、更安全（实例 IP 变了也不影响）。这是云上「<strong>按角色而非按 IP 做防火墙</strong>」的关键技巧，也是安全组有别于传统防火墙的最大优势。</span>

**辨析｜易错点：** 三层架构不是「三台机器」，而是「**三层逻辑**」——每层都可以水平扩展（Web 层多台实例、应用层多台实例），层与层之间只通过受控接口通信。这是「松耦合分层」思想（你在《计算机网络》的分层里见过）在网络架构上的落地——**分层让每层可独立伸缩与替换**。

## 7 小结

- **VPC**：租户逻辑隔离的私有网络，通过 CIDR 划网段。
- **子网**：VPC 的细分与安全分区；**公有子网**对外、**私有子网**隔离。
- **安全组**：实例级防火墙，**有状态、默认拒绝**。
- **网络 ACL**：子网级过滤器，**无状态、默认放行**。
- 规划口诀：最小暴露——Web 在公有子网，数据库永远在私有子网。
