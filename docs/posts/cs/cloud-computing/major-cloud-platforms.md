## 为什么从主流云平台开始

前五篇建立了云的完整理论框架。这一篇落地到**具体的厂商**：AWS、Azure、阿里云、华为云。同一套架构，为什么各家产品命名千差万别、却又一一对应？看懂一张「命名对照表」，你就能在任意云平台上快速定位自己需要的能力——这也是云从业者的核心迁移技能。

一个值得先建立的认知：**云平台不是「四家互不相干的公司」，而是「同一套工程规律的四种实现」**——因为虚拟化、存储、网络、数据库的底层规律是通的，所以各家产品必然一一对应。理解这点，「迁移到新平台」就从「从零学起」变成了「翻译术语」。

## 1 全球云市场的基本盘

按市场份额，全球公有云 IaaS 市场常年被三家把持：**AWS**（约三成）、**Microsoft Azure**（约两成多）、**Google Cloud**（约一成）。在中国市场，格局则明显不同：**阿里云**长期领跑，华为云、腾讯云紧随其后。<span class="marginnote">云市场份额数据来自 Synergy Research、Canalys 等机构的季度报告，各口径略有差异但前三名稳定。份额是「窗口」，真正的差异在各家的产品纵深与生态——读这份概览时请记住：<strong>平台选型看的不只是名气，而是你需要的那几项能力是否够强</strong>。</span>

## 2 AWS：云的发明者

**AWS（Amazon Web Services）** 于 2006 年上线，是公有云的鼻祖。它的产品线以「服务名缩写」著称，几乎成了云术语的标准词：**EC2**（弹性计算）、**S3**（对象存储）、**RDS**（关系型数据库）、**Lambda**（函数计算）、**DynamoDB**（NoSQL）、**VPC**（虚拟网络）。AWS 的优势是**起步最早、功能最全、生态最成熟**——很多云原生概念（对象存储模型、无服务器）都先在 AWS 上被定义，再被其他厂商跟随。<span class="marginnote">S3 的命名（Simple Storage Service）开创了「对象存储」这一产品类别；EC2 的「按小时租虚拟机」开启了 IaaS 时代。因此学云计算时，AWS 的产品名几乎就是行业「方言」——AWS 文档也是各云平台里质量最高的学习材料之一。</span>

## 3 Azure：微软的云

**Microsoft Azure** 是微软 2010 年发布的公有云，产品线深度绑定 Windows 生态与企业 IT：**Azure Virtual Machines**（对标 EC2）、**Azure Blob Storage**（对标 S3）、**Azure Functions**（对标 Lambda）、**Azure SQL**（托管数据库）。Azure 的独特优势在于**混合云**：微软的 Azure Stack 可以把云技术栈部署到客户自建机房，与本地 Active Directory 无缝打通——这对重度使用微软产品的企业极具吸引力。<span class="marginnote">Azure 与「开发者工具」的绑定也很深：GitHub（微软收购）、Visual Studio、.NET 生态让开发者能「从 IDE 直达云端」。若你的团队已经在用微软全家桶，Azure 是迁移成本最低的选择。</span>

## 4 阿里云与华为云：中国力量

**阿里云（Alibaba Cloud）** 成立于 2009 年，是中国云市场的领跑者。核心产品：**ECS**（弹性计算，对标 EC2）、**OSS**（对象存储，对标 S3）、**RDS**（云数据库）、**PolarDB**（自研云原生数据库）、**函数计算 FC**。阿里云的技术特色是「双十一」级的高并发实战锤炼——每年双十一的峰值流量成为其系统能力的练兵场。<span class="marginnote">阿里云的双 11 压力测试是云行业著名的「炼狱」：数亿人在同一分钟涌入，峰值每秒数十万笔交易。扛过这种负载的系统，其弹性与容错设计很难在普通场景下复制——这也是为什么阿里云的弹性伸缩、高可用方案在电商与金融行业口碑突出。</span>

**华为云（Huawei Cloud）** 是华为 2017 年全面发力云计算后的成果，主打政企市场与**全栈自主**。核心产品：**ECS**、**OBS**（对象存储）、**GaussDB**（数据库）、**FunctionGraph**（函数计算）。华为云的特点是「硬件出身」——背靠华为的服务器、网络设备与昇腾 AI 芯片，在强调**国产化与信创**的政企市场拥有独特位置。

## 5 核心要点对比：四大平台产品对照

| 能力 | AWS | Azure | 阿里云 | 华为云 |
| --- | --- | --- | --- | --- |
| 虚拟机 | EC2 | Virtual Machines | ECS | ECS |
| 对象存储 | S3 | Blob Storage | OSS | OBS |
| 函数计算 | Lambda | Functions | 函数计算 FC | FunctionGraph |
| 托管数据库 | RDS | Azure SQL | RDS / PolarDB | GaussDB |
| 虚拟网络 | VPC | VNet | VPC | VPC |
| 容器服务 | EKS | AKS | ACK | CCE |

**辨析｜易错点：** 别被命名差异吓到——上表每一行都是**同一类能力的换名**。真正的差异不在「有没有」，而在「强不强、贵不贵、合不合规」。迁移时最需要警惕的不是改名，而是**厂商专属服务**（如 AWS 的 DynamoDB 在某些场景不可替代），这才是锁定的真正来源。<span class="marginnote">读这份对照表还有一个实操用途：<strong>面试与求职</strong>。云厂商认证（AWS 解决方案架构师、阿里云 ACA/ACP）几乎都围绕「用自家产品名回答问题」展开，能熟练做这张对照表的翻译，就掌握了任意一家云的基础语言。</span>

## 6 如何选云：一张决策清单

了解了四家平台的差异，落地到「我该选哪家」时，用一张清单逐项打分，比凭名气拍脑袋可靠得多：

| 决策维度 | 要问的问题 | 典型权重 |
| --- | --- | --- |
| **合规与地域** | 数据必须放在哪些区域？有无行业监管要求？ | 最高（不满足则出局） |
| **存量技术栈** | 团队用的是微软栈、Java、还是开源？ | 高 |
| **目标产品能力** | 你需要的核心服务（AI、数据库、容器）哪家最强？ | 高 |
| **定价与成本** | 按你的负载算总账单，谁更便宜？ | 中 |
| **生态与支持** | 文档、社区、认证、技术支持是否到位？ | 中 |
| **锁定风险** | 是否重度使用某家专属服务？ | 低-中 |

**一个务实结论**：绝大多数团队的选择不是「哪家最先进」，而是「**哪家满足合规、与现有技术栈最契合**」。国内企业普遍选阿里云/华为云（合规与地域优势），微软重度用户倾向 Azure，AI 与数据团队偏爱 Google Cloud，全球出海业务则绕不开 AWS。<span class="marginnote">选云还有个「反直觉」的维度——<strong>人才可得性</strong>：团队里谁会哪家云的技能，直接影响上手成本。所以简历上写「熟悉 AWS」和「熟悉阿里云」，在就业市场对应的是两套不同的岗位池。云技能是可迁移的，但第一朵云的选择确实有路径依赖。</span>

**辨析｜易错点：** 别用「功能数量」做唯一标准。四家平台的功能广度已高度趋同，真正的差异在**特定能力的深度**（如某家的某数据库更强）、**价格**与**合规资质**。选云是选「长期合作的基础设施」，值得花一个月做 PoC（概念验证），而不是看一份功能对照表就定。

## 7 云认证与云从业者的学习路径

看完四大平台，落地到「我怎么学、怎么证明」——云认证是云技能最主流的「通行证」。

**主流认证体系**：

| 厂商 | 入门级 | 进阶级 | 专家级 |
| --- | --- | --- | --- |
| AWS | Cloud Practitioner | Solutions Architect Associate | Solutions Architect Professional |
| Azure | Fundamentals（AZ-900） | Administrator / Developer | Architect Expert |
| 阿里云 | ACA（助理） | ACP（专业） | ACE（高级） |

**认证的价值**：一是**系统化梳理知识**——认证大纲本质是一份「云技能地图」，按它学习不会遗漏核心概念；二是**求职与议价**——云岗位招聘普遍认认证。但认证**不等于能力**：考试考的是「记住产品」，工程要的是「在真实系统里做出取舍」。

**学习路径建议（与本书体系呼应）**：

1. **先把「云基础四件套」打牢**：定义/特征/服务模型/部署模型（对应第一篇）——任何云认证都考这些。
2. **虚拟化与容器**：Hypervisor、Docker、K8s 是云的中枢（对应第二篇）——也是面试高频。
3. **存储、网络、数据库**：三件套能力对应第三篇——考「选型」题（这个场景该用块还是对象存储）的题库来源。
4. **安全与成本**：共享责任模型、IAM、FinOps——高级认证的区分题，也是真实工作的常驻话题。

**辨析｜易错点：** 别「只刷题、不实践」。认证是「地图」，实践才是「走过的路」。**最好的学习组合是「认证大纲当清单 + 免费试用额度当沙盒」**——每个云厂商都提供免费额度，亲手建一个 VPC、跑一个容器、部署一个函数，概念就活了。<span class="marginnote">另一个常被忽略的路径：<strong>开源工具是「跨云通用」的资产</strong>。Terraform、Kubernetes、Prometheus 这些工具在每家云上通用——精通它们，比只懂某一家云更「保值」。这呼应了《多云与混合云策略》：<strong>标准抽象层让技能可迁移，也让你的职业路不被单家绑定</strong>。</span>

## 8 一个务实的问题：先学哪家云

看完四家平台、认证与路径，回到最实际的问题——**「我应该先学哪家？」** 给三条建议：

1. **按就业市场走**：看你想去的公司/岗位用哪家云。国内互联网多用阿里云，政企/信创多用华为云，外企/出海多用 AWS/Azure——**跟着目标岗位的招聘 JD 选**，学习才有就业回报。
2. **按生态学习便利走**：AWS 文档最全、社区最大、免费额度也够用，是**学习云计算概念的绝佳沙盒**——大部分技术书与课程都以 AWS 为例。先拿 AWS 建立概念，再迁移到其他家（命名对照表在这里派上用场）。
3. **按公司存量走**：如果你已经在某家公司，**它用哪朵云就学哪朵**——先解决当前工作问题，再扩展广度。

**一条普适的学习路线**：**用 AWS（或任意一家）建立完整概念 → 用「命名对照表」翻译到第二家 → 用开源工具（Terraform/K8s/Prometheus）做跨云通用技能**。这三步走完，你就不是「会某家云」，而是「懂云计算」——后者才是真正的职业资产。<span class="marginnote">最后一点提醒：<strong>云技能是「道」与「术」两层</strong>——「术」是某家产品的操作（会变、会过期），「道」是共享责任模型、弹性、声明式、高可用这些原则（不变、可迁移）。花 70% 精力学「道」，30% 学「术」，你的技能就不会被任何一家厂商的迭代淘汰。<strong>这正呼应本专题的编排：先原理、后产品、再实践。</strong></span>

## 9 小结

- 全球市场：**AWS 领跑、Azure 追赶、Google Cloud 第三**；中国市场**阿里云领先、华为云/腾讯云跟进**。
- **AWS**：云的发明者，EC2/S3/Lambda 定义了行业标准命名。
- **Azure**：深度绑定 Windows 与微软生态，混合云（Azure Stack）是特色。
- **阿里云**：双十一高并发实战，PolarDB 自研数据库；**华为云**：全栈自主，政企与信创市场。
- 四大平台产品一一对应，真正差异在**生态、定价与合规**，厂商专属服务才是锁定之源。

- 平台概览的学习定位：**这六篇建立的是「云的坐标」**——定义（在哪）、特征（是什么）、模型（卖什么）、部署（放哪）、架构（怎么组织）、平台（谁在卖）。第二篇起，进入「云内部怎么运转」。

- 核心记忆点：**四家平台的产品一一对应，差异在「深度、价格、合规」**——厂商专属服务才是锁定之源。
- 面试常见问法：「**AWS EC2 对应阿里云哪个产品**」——答「ECS」并顺势展开「S3↔OSS、Lambda↔FC」对照即显功力。
- 与后续的衔接：平台概览是「认门牌」，第二篇起进入「看内部」——记住这张对照表，迁移时直接翻译。
- 自查练习：**不翻资料，默写 AWS/Azure/阿里云三家的「虚拟机、对象存储、函数计算」对照**——能写全，平台基础就扎实了。
- 一句总结：**平台会迭代、厂商会涨跌，唯有「按需、弹性、计量」的原理不变**——学「道」重于学「术」。

至此，云计算基础第一篇的六篇全部完成。接下来进入第二篇——**虚拟化技术**，从云的「心脏」讲起：Hypervisor 如何让一台物理机分身成几十台虚拟机。平台概览让你「认识云」，虚拟化则带你「拆开云」——**从看产品，走向看引擎**。
