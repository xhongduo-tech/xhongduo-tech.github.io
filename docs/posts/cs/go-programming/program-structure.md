## 为什么从程序结构开始

写任何一门语言，第一道门槛不是「写对一行代码」，而是「看懂一个文件为什么长这样」。Go 程序的骨架由**包（package）**、**声明（declaration）**与**变量赋值**三块构成：`package main` 决定编译产物，`import` 决定依赖，`var`/`const`/`func` 声明名字与类型，`=` 与 `:=` 决定值如何流动。<span class="marginnote">对标《Go语言圣经》第2章：这一章把「程序结构」单独拎出来，是因为 Go 的包机制与作用域规则直接决定了后面所有章节的写法。读懂结构，语法细节才有落点。</span>

这一章在课程里的位置很特殊：它既是**第三级《Go 语言编程》的第一块砖**，又与第一级《基础数学》的「从集合到函数」一脉相承——Go 用**类型（type）**约束变量能装什么、能做什么运算，正如数学用集合约束对象。把「变量有类型、函数有签名」这个观念立稳，后面读 goroutine、channel 时才不会迷失。

## 1 包：命名的边界

**包（package）** 是 Go 组织源码的基本单位：一组相关文件放在同一目录、声明同一个 `package` 名，就构成一个包。<span class="marginnote">对照 Java 的 `package` 与 C 的「头文件+链接」：Go 的包是「目录即包」——一个目录下所有 `.go` 文件属于同一个包，目录路径同时是导入路径。</span>

包的三种角色：

- **可执行包**：`package main`，编译后产生可运行文件，必须有 `func main()`。
- **库包**：如 `fmt`、`strings`，供其它程序导入复用。
- **内部包**：`internal/` 目录下的包只允许同根目录内导入，是「包内私有」的加强版。

导入（import）语句把其它包的名字引入当前文件：

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	fmt.Println(strings.ToUpper("hello"))
}
```

**重点：** 只有**首字母大写**的标识符才会被导出（export）——`fmt.Println` 能访问，`fmt.println` 则不行。这是 Go「用大小写代替 `public`/`private` 关键字」的极简设计，也意味着包边界本身就是信息边界。

## 2 声明：名字与类型

**声明（declaration）** 把名字绑定到类型。Go 有四种声明：`var`（变量）、`const`（常量）、`type`（类型）、`func`（函数）。

```go
package main

import "fmt"

const boilingF = 212.0  // 常量：编译期确定

var version = "1.0"     // 包级变量

func main() {
	var f = boilingF            // 局部变量，类型由初始化式推断
	var c = (f - 32) * 5 / 9    // 摄氏温度换算
	fmt.Printf("boiling point = %g°F or %g°C\n", f, c)
}
```

**变量声明的三种形态：**

| 写法 | 含义 | 类型来源 |
| --- | --- | --- |
| `var x int` | 声明变量，零值 | 显式指定 |
| `var x = 5` | 声明并初始化 | 由初始化式推断 |
| `x := 5` | 短变量声明 | 由初始化式推断 |

**短变量声明 `:=`** 是 Go 的特色：声明的同时赋值，且**左侧必须至少有一个新变量**——若全是已存在的变量，则报编译错误。它只能用在函数内部，包级变量不能用 `:=`。

**辨析｜易错点：** `x := 5` 与 `x = 6` 完全不同：前者在**当前作用域声明新变量**，后者**给已有变量赋值**。若在同一个函数内重复 `x := 5`，只要左侧没有新名字，编译器会报「no new variables on left side of :="。

## 3 变量生命周期与作用域

**作用域（scope）** 是编译期概念：标识符在源码中可见的范围；**生命周期（lifetime）** 是运行期概念：变量实际存活的时间段。两者容易混淆。<span class="marginnote">对照第一级《基础数学》的函数定义域：作用域之于名字，恰如定义域之于自变量——超出范围，名字就不「存在」了。</span>

Go 的作用域规则：**块（block）** 是作用域的基本单位。`{}` 花括号围出块，`if`、`for`、`switch` 也各自构成块。内层块可以遮蔽（shadow）外层块的同名变量。

```go
var x = "outer"

func main() {
	x := "inner"   // 遮蔽包级 x
	fmt.Println(x) // inner
	{
		x := "deep" // 再遮蔽一层
		fmt.Println(x)
	}
	fmt.Println(x) // inner
}
```

**生命周期**由编译器通过**逃逸分析（escape analysis）**决定：若局部变量的地址被返回或存入堆，它会逃逸到堆上，存活时间超过函数返回。这对性能有直接影响——逃逸到堆的变量触发垃圾回收开销，这在《go 工具链》与《基准测试与 pprof》中会实测。

## 4 赋值与多重赋值

**赋值**把值写入变量：`x = 5`。Go 支持**多重赋值**，同一时刻给多个变量赋值：

```go
i, j = j, i       // 交换两个变量，无需临时变量

a, b, c = 1, 2, 3
```

多重赋值的真正威力在于**函数返回多个值**：

```go
n, err := fmt.Println("hello")
// n 是写入的字节数，err 是可能的错误
```

这一行同时完成「声明两个变量」「接收两个返回值」——错误处理就是从这里开始的。**Go 没有异常（exception）**，错误以值的形式显式返回，这是后面《错误处理与 errors 包》篇的总纲。

**辨析｜易错点：** 多重赋值要求右侧先全部求值，再依次赋值。`i, j = j, i` 之所以能交换，正是因为右侧先取旧值，左侧再写入。若写成两条 `i = j; j = i`，则两个变量都会变成同一个旧 `j`。

## 5 零值与类型

Go 的一个极简设计：**每个变量声明后立即有零值（zero value）**，不需要显式初始化：

| 类型 | 零值 |
| --- | --- |
| 数值类型 | `0` |
| 布尔 | `false` |
| 字符串 | `""`（空串） |
| 接口 | `nil` |
| 指针 / 切片 / map / 函数 | `nil` |

<span class="marginnote">零值让 Go 的代码「声明即安全」：`var s string` 可以直接 `s += "a"`，不会像 C 那样读到未初始化的垃圾值。这是内存安全的细节体现，也是 Go 与 C 最根本的差异之一。</span>

**核心对比：Go 与 C、Java 的类型态度**

| 维度 | Go | C | Java |
| --- | --- | --- | --- |
| 未初始化变量 | 自动零值 | 未定义（垃圾值） | 局部变量须显式初始化 |
| 隐式类型转换 | 禁止 | 常见（int→float 等） | 窄化禁止、拓宽允许 |
| 错误处理 | 返回值 | 错误码 | 异常 |

Go 选择「没有隐式转换」：`int` 与 `int64` 是不同的类型，必须显式 `int64(x)` 转换。这让代码更啰嗦，但消除了「隐式转换引入的 bug」这一类错误——与第1篇《Hello World 与语言设计理念》讲的「显式优于隐式」完全一致。

## 6 小结

- 包是 Go 的源码组织单位：`package main` 是可执行程序，库包供导入复用。
- 四种声明：`var`、`const`、`type`、`func`；首字母大写才导出。
- `:=` 短变量声明必须引入至少一个新变量，且只能用于函数内。
- 作用域是编译期概念（块），生命周期是运行期概念（逃逸分析决定栈/堆）。
- 多重赋值让交换与多返回值成为可能；**Go 用返回值表达错误，没有异常**。
- 零值机制让「声明即安全」：数值 `0`、布尔 `false`、字符串 `""`、引用 `nil`。

在下一节，我们将深入数据的类型体系：**基础数据类型——整数、浮点、复数与字符串**，把「机器的数」与「数学的数」逐一对照。
