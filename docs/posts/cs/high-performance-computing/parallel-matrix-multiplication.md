## 为什么从并行矩阵乘法开始

矩阵乘法 $\mathbf{C} = \mathbf{A}\mathbf{B}$ 是数值计算的基石：

线性方程组、特征值、机器学习、有限元——全都建立在它之上。

Top500 的 LINPACK 基准测的就是它。

并行矩阵乘法是「数据布局」与「通信优化」的完美案例：

同样的计算，数据摆法不同，性能差出一个数量级。

<span class="marginnote">矩阵乘法还有一层现代意义：深度学习里的矩阵乘法（GEMM）占了训练算力的绝大部分；NVIDIA cuBLAS 里手写优化的 GEMM 内核，正是并行矩阵乘法在 GPU 上的极致形态。</span>

本节讲清三件事：数据怎么摆、算法怎么算、通信怎么省。

## 1 矩阵乘法与数据布局

$\mathbf{C} = \mathbf{A}\mathbf{B}$，其中 $\mathbf{A}$ 是 $m \times k$、$\mathbf{B}$ 是 $k \times n$、$\mathbf{C}$ 是 $m \times n$。

最直接的并行方式：

**按输出矩阵 $\mathbf{C}$ 分块**——每个处理器负责 $\mathbf{C}$ 的一个子块。

计算 $C_{ij}$ 需要：

$\mathbf{A}$ 的第 $i$ 行分块；
$\mathbf{B}$ 的第 $j$ 列分块。

所以关键在于：

**每个处理器能不能「不太贵地」拿到自己需要的 $\mathbf{A}$ 行块与 $\mathbf{B}$ 列块？**

这引出了两种经典布局：

**按行/按列分**：一维剖分，通信简单但扩展受限；
**二维块分布**：把 $\mathbf{C}$ 切成 $\sqrt p \times \sqrt p$ 的网格，通信量最优。

**核心直觉：** 矩阵乘法并行化的胜负手不在计算（计算量是固定的 $O(n^3)$），而在**数据移动**。

## 2 块分布与 2D 网格

现代并行矩阵库采用**二维块分布（2D block distribution）**：

把矩阵 $\mathbf{C}$ 想象成铺在 $p$ 个处理器网格上——一个 $\sqrt p \times \sqrt p$ 的棋盘。

每个处理器持有 $\mathbf{C}$ 的一个子块，同时也持有 $\mathbf{A}$、$\mathbf{B}$ 的对应子块。

更精细的做法是**块循环分布（block-cyclic）**：

小块循环发放，让「每一轮负载」都均衡。

这正是 **ScaLAPACK**（可扩展线性代数库）的默认布局。

<span class="marginnote">ScaLAPACK 是并行版的 LAPACK，靠块循环布局 + 二维网格处理稠密线性代数。LINPACK 基准跑的就是它这一套。</span>

**辨析｜易错点：** 一维分（按行分给 $p$ 个处理器）简单，但每个处理器需要**整列 B**——通信量随 $n$ 线性增长。

二维分布把通信量压到 $O(n/\sqrt p)$ 量级，是质的差别。

## 3 Cannon 算法

**Cannon 算法**（1969）是最早的经典二维并行矩阵乘法。

它的核心是**循环移位（rotation）**：

1. 把 $\mathbf{A}$ 的第 $i$ 行块**左移 $i$ 位**、$\mathbf{B}$ 的第 $j$ 列块**上移 $j$ 位**，让每个处理器对齐到初始位置；
2. 每个处理器**本地做一次小块乘法**并累加；
3. $\mathbf{A}$ 块整体左移一格、$\mathbf{B}$ 块整体上移一格；
4. 重复 $\sqrt p$ 次，累加完成全部乘积。

Cannon 的优点：

每轮通信是**邻居间一次交换**，开销小；
总共 $\sqrt p$ 轮，通信总量 $O(n^2/\sqrt p)$。

Cannon 的缺点：

只适合**方阵**且 $p$ 是平方数的规则情况；
块循环等更灵活的布局它处理不了。

## 4 SUMMA：可扩展通用矩阵乘法

**SUMMA（Scalable Universal Matrix Multiplication Algorithm，可扩展通用矩阵乘法）**是现代并行 GEMM 的工业标准。

思想极其简洁——**把矩阵乘法拆成「面板乘法」**：

对每个列索引 $k$（或块 $k$）：

1. **广播**：所有持有 $\mathbf{A}$ 第 $k$ 列块的处理器，把该列块广播给需要它的行；
2. **广播**：所有持有 $\mathbf{B}$ 第 $k$ 行块的处理器，把该行块广播给需要它的列；
3. **本地累乘**：每个处理器用收到的 $\mathbf{A}_k$ 与 $\mathbf{B}_k$ 做一次面板乘积，累加到 $\mathbf{C}$。

SUMMA 的优势：

不要求方阵、不要求 $p$ 是平方数——**任意矩形网格都行**；
广播用**树状**或**流水线**优化，通信高效；
与块循环布局无缝配合。

<span class="marginnote">SUMMA 的广播可以做成「流水线行广播」：数据沿处理器行传递，边传边算，把通信延迟藏进计算——这是「通信计算重叠」在 GEMM 里的标准打法。</span>

## 5 公式解析：通信量与扩展

对比两种算法的**每处理器通信量**（数据搬运总量）：

Cannon：

$$M_{\text{Cannon}} = O\!\left(\frac{n^2}{\sqrt p}\right)$$

SUMMA（每个面板广播一次）：

$$M_{\text{SUMMA}} = O\!\left(\frac{n^2}{\sqrt p}\right)$$

两者的通信量**渐近相同**，都是 $O(n^2/\sqrt p)$：

- **第一步，看分子 $n^2$**：矩阵是 $n^2$ 个元素，数据规模天然是 $n^2$ 量级；
- **第二步，看分母 $\sqrt p$**：二维网格的边是 $\sqrt p$，每条数据只沿一个方向流动，所以通信被 $\sqrt p$ 摊薄；
- **第三步，对比计算量 $O(n^3/p)$**：当 $n$ 远大于 $\sqrt p$（大矩阵、处理器不多），计算占主导，通信相对小——**这解释了 LINPACK 为什么总能跑到很高效率**。

**工程结论：** 矩阵乘法是「通信友好」的——计算密度高、数据局部性好，所以它是 HPC 里最容易优化的算法，也正因如此被选作 Top500 的度量尺。

## 6 核心对比：Cannon 与 SUMMA

| 维度 | Cannon | SUMMA |
| --- | --- | --- |
| 核心操作 | 循环移位 | 面板广播 |
| 矩阵形状 | 仅方阵 | 任意矩形 |
| 处理器网格 | $p$ 为平方数 | 任意 |
| 与块循环兼容 | 差 | 好 |
| 现代库采用 | 少 | 是（ScaLAPACK 等） |
| 通信量 | $O(n^2/\sqrt p)$ | $O(n^2/\sqrt p)$ |

**核心结论：** 两者通信量同阶，但 SUMMA 灵活得多，所以成为工业标准。

Cannon 的价值在于它把「数据布局如何决定通信」这个道理讲得最直观。

## 7 小结

- 并行矩阵乘法**胜负在数据移动**，不在计算。
- **二维块分布**与**块循环布局**把通信压到 $O(n^2/\sqrt p)$。
- **Cannon 算法**：循环移位 + 邻居交换，适合方阵。
- **SUMMA**：面板广播 + 本地累乘，任意形状、工业标准。
- 矩阵乘法**计算密度高、通信友好**，是 LINPACK 与深度学习 GEMM 的共同基础。
- 铁律：**布局决定通信，通信决定扩展。**
