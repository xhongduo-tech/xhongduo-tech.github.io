## 为什么从并行线性方程组开始

有限元、流体、电网、神经网络训练——它们最后都问同一个问题：

给定 $\mathbf{A}\mathbf{x} = \mathbf{b}$，求 $\mathbf{x}$。

求解线性方程组有两大流派：

- **直接法**：有限步内精确求解，如 LU 分解；
- **迭代法**：逐步逼近，如共轭梯度。

并行化这两派，策略完全不同：

直接法的瓶颈是**同步的分解步骤**，迭代法的瓶颈是**每步的全局归约与稀疏访存**。

<span class="marginnote">大模型的优化器（如 Adam）里那些求逆、求范数的操作，底层也依赖 BLAS/LAPACK 的线性代数内核——线性方程组求解是现代数值世界的供水系统。</span>

本节把两派各自的并行策略讲清楚。

## 1 直接法：并行 LU 分解

**LU 分解**把 $\mathbf{A}$ 拆成下三角 $\mathbf{L}$ 与上三角 $\mathbf{U}$：

$$\mathbf{A} = \mathbf{L}\mathbf{U}$$

解方程变成两步回代：

$$\mathbf{L}\mathbf{y} = \mathbf{b}, \qquad \mathbf{U}\mathbf{x} = \mathbf{y}$$

串行 LU 的消元是**从左到右逐列**推进的——天然串行依赖。

并行化的关键思想是**面板分解（panel factorization）**：

- 把矩阵按**列块（panel）**分给处理器；
- 对某个 panel，先由**一个处理器**做局部消元；
- 消元产生的更新因子**广播**给其他处理器，让它们并行更新自己的面板；
- 如此逐面板推进。

这种「串行小步 + 并行大步」的模式叫**流水线分解**：

每一步串行的 panel 很小，大部分计算都在并行的更新阶段。

<span class="marginnote">ScaLAPACK 的 `pdgetrf` 就是这种模式：panel 内局部 LU + panel 外并行更新。它把「串行依赖」压缩到极小的一段，让大规模 LU 也能跑到高并行效率。</span>

**辨析｜易错点：** 消元要**选主元（pivoting）**保证数值稳定。

主元选取需要跨列交换行——这带来**额外通信**。并行 LU 要把选主元的范围尽量限制在 panel 内，减少跨处理器交换。

## 2 迭代法：从 Jacobi 到共轭梯度

直接法对大稀疏矩阵很吃力（填充过多），迭代法于是登场。

最朴素的 **Jacobi 迭代**：

$$\mathbf{x}^{(k+1)}_i = \frac{1}{a_{ii}}\left(b_i - \sum_{j \neq i} a_{ij} x^{(k)}_j\right)$$

**新值只用旧值**——这使 Jacobi **天生可并行**：

每个处理器更新自己那一块分量，只需读取邻居的旧值。

**Gauss-Seidel 迭代**用「最新的」值，收敛快一倍，但破坏并行性（严格的 Gauss-Seidel 串行）。

折中是 **SOR / 红黑着色**：把网格染成红黑两色，同色节点互不依赖，一次并行更新一色。

**共轭梯度法（CG）**是正定对称问题的明星迭代法：

每步只有**稀疏矩阵乘向量（SpMV）**与**两个全局内积**。

SpMV 局部可并行，内积则是一次全局归约——CG 的并行瓶颈全在两个内积上。

## 3 公式解析：并行迭代法的一步

以 CG 的一步为例，代价由两部分组成：

$$T_{\text{step}} = T_{\text{SpMV}} + T_{\text{dot}}$$

- **第一步，看 $T_{\text{SpMV}}$**：$\mathbf{A}\mathbf{v}$ 的计算，每个处理器只碰自己的行——完全局部，代价 $O(nnz/p)$；
- **第二步，看 $T_{\text{dot}}$**：内积 $\mathbf{p}^T \mathbf{q}$ 需要**先局部算、再全局求和**——一次 all-reduce，代价随 $p$ 增长（对数级）；
- **第三步，相加**：当处理器变多，$T_{\text{SpMV}}$ 缩小而 $T_{\text{dot}}$ 不缩——**内积的归约成为 CG 扩展的天花板**。

工程对策：

- 把多次归约**合并**成一次（一次 all-reduce 返回多个结果）；
- 用非阻塞归约，让它在 SpMV 计算期间后台进行。

**核心直觉：** 迭代法的并行优化，一大半是在「省归约次数」。

## 4 稀疏问题：SpMV 与 halo 交换

稀疏矩阵的并行还多一层难题——**怎么存、怎么访存**。

**稀疏矩阵向量乘（SpMV）**：$\mathbf{y} = \mathbf{A}\mathbf{x}$。

每个输出 $y_i$ 是 $\mathbf{A}$ 第 $i$ 行与 $\mathbf{x}$ 的非零元素乘积之和。

并行化：

- 按行分块：每个处理器持有若干行；
- 需要的 $\mathbf{x}$ 分量 = 这些行的非零列——**通常来自邻居的分量**；
- 每轮迭代前，处理器要**从邻居取这些分量**——这叫 **halo 交换（halo exchange）**或**ghost cell 更新**。

<span class="marginnote">halo 交换是稀疏迭代并行化的标准动作：每个处理器维护一小圈「影子数据」，每轮迭代开始时与邻居交换更新一次。通信量与剖分的割边成正比——图剖分（上一节）在这里再次登场。</span>

稀疏矩阵的存储格式（CSR、ELL 等）决定访存模式：

好的格式让非零元访问相对连续，差的格式让每个非零元都成为一次缓存缺失。

## 5 核心对比：直接法与迭代法

| 维度 | 直接法（LU） | 迭代法（CG） |
| --- | --- | --- |
| 精度 | 精确（机器精度） | 近似（收敛容差） |
| 适用矩阵 | 稠密/中小规模 | 大稀疏 |
| 主要瓶颈 | 串行 panel + 选主元 | 全局归约 + halo 交换 |
| 并行效率 | 高（LINPACK） | 中（受通信拖累） |
| 填充问题 | 有（稀疏变稠密） | 无 |
| 预处理 | 不需要 | 通常需要 |

**工程结论：** 稠密小矩阵用直接法，稀疏大矩阵用迭代法加预处理。

现代求解器（如 PETSc、Hypre）把两派都包起来，按矩阵性质自动选择。

## 6 小结

- **直接法**并行靠**面板分解**：串行小步消元 + 并行大步更新。
- **迭代法**的 Jacobi 天生并行，CG 的瓶颈在**全局内积归约**。
- SpMV 的并行需要 **halo 交换**，成本与图剖分质量挂钩。
- 迭代法一步成本：$T = T_{\text{SpMV}} + T_{\text{dot}}$，**省归约就是省时间**。
- 铁律：**稠密用直接法，大稀疏用迭代法；先预处理，再并行。**
