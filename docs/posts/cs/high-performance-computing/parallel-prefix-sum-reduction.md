# 并行前缀和与归约

## 为什么从前缀和开始

先看一个看似平凡的问题：

给定数组 $x$，输出 $y$，其中 $y_i = x_0 + x_1 + \cdots + x_i$。

这就是**前缀和（prefix sum）**，也叫**扫描（scan）**。

串行做法是 $O(n)$ 一次循环。

但它是**天生顺序依赖**的：第 $i$ 项要用第 $i-1$ 项的结果。

怎么并行？这是并行算法设计里最有启发性的问题之一。

**归约（reduction）**则是它的「兄弟」：只求 $y_n$（总和），不求所有中间项。

<span class="marginnote">前缀和的串行公式 y[i] = y[i-1] + x[i] 是「递推依赖」的典型，而递推在并行世界里必须靠「重新排列计算顺序」来打破——这是本节最核心的思维转变。</span>

## 1 前缀和的定义

设输入 $x_0, x_1, \ldots, x_{n-1}$，定义**前缀和（prefix sum）**：

$$y_i = \sum_{k=0}^{i} x_k$$

即 $y$ 的第 $i$ 项是 $x$ 前 $i+1$ 项的和。

两个变体：

- **inclusive scan**：$y_i$ 含 $x_i$（上式就是）；
- **exclusive scan**：$y_i$ 不含 $x_i$，即前 $i$ 项的和，$y_0 = 0$。

运算不必是加法，任何**满足结合律**的二元运算都行：

求前缀最大值、前缀乘法、前缀异或——全都适用。

**辨析｜易错点：** 前缀和看似是「递推」，但它可以并行，关键在结合律。

加法的结合律让我们可以**换一种顺序**求和，而不改变结果。

## 2 Hillis-Steele 扫描

最直观的并行扫描叫 **Hillis-Steele 扫描**（1986）：

- 第 $k$ 轮，每个元素把「相距 $2^k$」的前面元素加到自己身上；
- $\log n$ 轮后，所有元素都累积了正确的前缀和。

具体地，第 $k$ 轮：

$$y_i^{(k)} = y_i^{(k-1)} + y_{i - 2^k}^{(k-1)}$$

只看一轮：所有 $y_i$ 的更新**互不依赖**，可以完全并行。

- 每轮是 $O(n)$ 个操作并行执行；
- 共 $\log n$ 轮。

所以并行时间 $O(\log n)$，但**总工作量**是 $O(n \log n)$——比串行的 $O(n)$ 多。

<span class="marginnote">Hillis-Steele 的直觉像「信息传播」：每个元素每轮翻倍「视野」，两轮后能看到 4 个元素、三轮后 8 个……$\log n$ 轮后看到整个数组。</span>

**辨析｜易错点：** 并行时间短 ≠ 算法好。

Hillis-Steele 快在**时间**，但浪费在**工作量**——$n \log n$ 比 $n$ 多出的那部分，在核少或数据大时是实打实的浪费。

## 3 归约与扫描的关系

**归约（reduction）**只求一个结果：

$$s = x_0 \oplus x_1 \oplus \cdots \oplus x_{n-1}$$

其中 $\oplus$ 是结合运算（求和、求最大等）。

归约是最容易并行的操作之一：

- 把数组两两配对并行相加；
- 每轮元素减半，$\log n$ 轮后得到一个总和；
- 这就是**树状归约（tree reduction）**。

归约与扫描的关系：

**扫描 = 归约的「全过程快照」**。

扫描给出所有前缀（即所有「归约到一半」的结果），归约只是扫描的最后一个元素。

反过来，**归约能用来构造扫描**——Blelloch 的 work-efficient 扫描正是这么做的。

**工程直觉：** 归约是并行度最饱满的原语，几乎所有并行库（MPI_Allreduce、CUDA 的 reduce）都把它做到接近硬件上限。

## 4 公式解析：两种扫描的复杂度

把两种扫描的成本对比钉死：

**Hillis-Steele：**

$$T_{\text{time}} = O(\log n), \qquad W_{\text{work}} = O(n \log n)$$

**Blelloch（work-efficient）扫描：**

$$T_{\text{time}} = O(\log n), \qquad W_{\text{work}} = O(n)$$

为什么 Blelloch 能省工作量？它分两趟：

- **第一趟（up-sweep，向上归约）**：树状归约算出每段的和，存下来；
- **第二趟（down-sweep，向下分发）**：用存下的段和，把前缀和「发」到每个位置。

拆三步理解复杂度：

- **第一步，看两趟的步数**：每趟都沿树走 $\log n$ 层，所以时间仍是 $O(\log n)$；
- **第二步，看每层的工作**：树状归约每层 $n/2$ 个操作、向下分发每层也约 $n/2$ 个——两层加起来每层 $O(n)$；
- **第三步，相加**：$\log n$ 层 × $O(n)$ 每层 = $O(n)$ 总工作量——**追平了串行，还多了并行**。

这就是 work-efficient 的含义：

**并行版本不比串行多做总操作，却把时间压缩到 $O(\log n)$。**

## 5 应用：流压缩与更多

前缀和为什么是「瑞士军刀」？几个经典应用：

**流压缩（stream compaction）：**

从数组中挑出满足条件的元素，压缩成新数组。

每个元素先算「我该排在新数组第几位」——这正是**exclusive scan**：

- 条件为真的元素位置 = 它前面为真的个数；
- 一次扫描得到所有位置，各元素并行写入。

**基数排序（radix sort）：**

按位排序时，需要知道「这一位是 0 的排在哪些位置」——又是一次扫描。

**分段的累积（segmented scan）：**

把数组分成若干段，段内各自扫描——图像处理、稀疏矩阵里无处不在。

<span class="marginnote">流压缩是 GPU 上「过滤 + 紧凑存储」的标准动作：粒子系统里删掉死掉的粒子、物理引擎里收集碰撞事件，都靠一次扫描。CUDA 的 `CUB` 库把 scan/reduce 封装成一行调用。</span>

## 6 小结

- **前缀和**：$y_i = \sum_{k\le i} x_k$，任何结合运算都能扫描。
- **Hillis-Steele**：时间 $O(\log n)$，但工作量 $O(n \log n)$。
- **Blelloch work-efficient 扫描**：两趟树状过程，工作量 $O(n)$、时间 $O(\log n)$。
- **归约是扫描的特例**，扫描是归约的全程快照。
- 应用：**流压缩、基数排序、分段扫描**——GPU 数据结构的公共底座。
- 铁律：**递推依赖不可怕，结合律给了你重排计算顺序的自由。**
