## 为什么从并行排序开始

排序是「数据密集型并行」的微缩世界：

数据要分解、要比较、要交换、要归并——并行算法的所有环节它都占了。

而且排序是无数并行程序的内层循环：外排序、数据库、计算几何都靠它。

学习并行排序，等于把前七节的分解、通信、同步思想**实战演练**一遍。

<span class="marginnote">MapReduce 的核心 shuffle 阶段，本质就是一个跨机器的并行排序——理解并行排序，就理解了大数据框架的半边天。</span>

本节的四位主角：

并行归并排序、奇偶转置排序、双调排序、样例排序。

## 1 排序问题与串行下界

排序问题：

给定 $n$ 个元素，按升序（或降序）重排。

串行比较排序的下界是：

$$\Omega(n \log n)$$

任何基于比较的串行排序算法都不可能更快——这是算法课程里的经典结论。

并行的目标就是**突破**这个下界的时间：

让 $p$ 个处理器把 $n$ 个元素排好，理想时间约为：

$$T(n, p) = O\left(\frac{n \log n}{p}\right)$$

- 每个处理器分摊 $\approx n/p$ 个元素；
- 若每个处理器内部还能并行或流水，总时间近似串行复杂度除以 $p$。

**工程前提：** 数据要**先分布**在 $p$ 个处理器上——并行排序通常假设输入已经分片，输出也要求分片有序。

**辨析｜易错点：** 并行排序的目标不是「每个处理器局部有序」，而是**全局有序且分片正确**。

只把每个分片排好然后交给进程 0 拼起来，是错的——那一步的归并会成为瓶颈。

## 2 并行归并排序

**并行归并排序（parallel merge sort）**把串行归并排序的「分治」直接并行化：

1. **分解**：把 $n$ 个元素分成 $p$ 个分片，每个处理器拿到 $n/p$ 个；
2. **局部排序**：每个处理器串行排好自己的分片，各用快排或归并；
3. **并行归并**：把 $p$ 个已排序分片**两两归并**，$\log p$ 轮后得到一个全局有序序列。

归并本身也可以并行：

两个有序数组的归并，可以**二分定位**每个元素的插入位置，让多个处理器同时填输出数组。

时间分析（见第 6 节公式解析）：

$$T(n, p) = O\left(\frac{n}{p}\log n + n\right)$$

后半项的 $n$ 来自**归并阶段的数据移动**——这是并行归并排序的固有代价。

## 3 奇偶转置排序

**奇偶转置排序（odd-even transposition sort）**是冒泡排序的并行翻版，专为「处理器排成一条线」设计：

重复执行两个阶段，直到有序：

- **奇相位（odd phase）**：每个奇数下标处理器与自己右边的邻居比较交换；
- **偶相位（even phase）**：每个偶数下标处理器与自己右边的邻居比较交换。

每次比较交换都是**相邻处理器**间的本地操作，只涉及点对点通信，非常适合网格/线性拓扑。

最多需要 $n$ 轮奇偶交替就能保证有序——**与冒泡排序同数量级**，但每一轮所有处理器同时干。

<span class="marginnote">奇偶转置排序的正确性直觉：每一轮奇偶交替，就像冒泡排序的「一轮冒泡」——最大元素每两轮必然向右推进一个位置，$n$ 轮后整体有序。</span>

它适合**处理器少、通信昂贵**的场景：实现极简单，通信只发生在邻居之间。

## 4 双调排序

**双调排序（bitonic sort）**是**比较器网络（sorting network）**的经典代表。

它建立在**双调序列（bitonic sequence）**的定义上：

先单调递增、后单调递减（或反之）的序列。

**双调归并（bitonic merge）**：把一个双调序列用 $\log n$ 轮比较交换排成有序序列。

整个算法：

1. 把 $n$ 个元素看成若干段；
2. 每段先排成双调序列（一半升一半降）；
3. 双调归并逐层合并，$\log n$ 层后全局有序。

比较器网络的好处：

**比较结构完全固定**，与数据无关——所有比较可以同时发生，极其适合硬件与 GPU 实现。

时间：

$$T(n) = O\left(\log^2 n\right)$$

用 $n$ 个处理器时，双调排序的并行时间只有 $O(\log^2 n)$，是理论最优级别的排序网络。

<span class="marginnote">双调排序的规律之美在于「比较次序是写死的」：GPU 与 FPGA 上几乎不分支、不索引跳跃，是 SIMT 的完美匹配。</span>

## 5 样例排序

**样例排序（sample sort）**是快排/桶排序的并行版本，工业界最常用：

1. **采样**：每个处理器从自己的分片里抽样若干元素；
2. **选枢轴**：把样本汇总，选出 $p-1$ 个**枢轴（pivots）**，把值域切成 $p$ 个桶；
3. **分配**：每个处理器把自己所有元素按值域**归入对应桶**；
4. **全局桶交换**：用全对全通信（all-to-all）把每个桶发给它「该去」的处理器；
5. **局部排序**：每个处理器把收到的桶排序，全局即有序。

样例排序的复杂度接近最优：

$$T(n, p) = O\left(\frac{n}{p}\log n + n\right)$$

但常数项比归并排序友好，而且**负载均衡**由枢轴选择质量决定。

**辨析｜易错点：** 枢轴选得不好（全挤在几个桶里），负载失衡，退化成串行。

工程上常用**双采样+排序后再选枢轴**保证均衡——这是「采样质量决定性能」的典型。

## 6 公式解析：并行归并排序复杂度

把并行归并排序的总时间拆开：

$$T(n, p) = \underbrace{O\!\left(\frac{n}{p}\log\frac{n}{p}\right)}_{\text{局部排序}} + \underbrace{O(n)}_{\text{并行归并}}$$

- **第一步，看局部排序**：每个处理器对 $n/p$ 个元素串行排序，快排等是 $(n/p)\log(n/p)$；
- **第二步，看归并**：最终拼成一个有序数组，至少要移动 $n$ 个数据——这个 $n$ 与 $p$ 无关；
- **第三步，总时间**：当 $p$ 很大，$n/p$ 项缩小，但 $O(n)$ 项不动——**数据移动成为扩展的天花板**。

这揭示了并行算法的一个普遍规律：

**计算可以并行，数据移动难以并行。**

排序、矩阵、FFT 全都受这条「移动定律」支配。

## 7 小结

- 串行排序下界 $\Omega(n \log n)$，并行目标是把它摊到 $p$ 个处理器上。
- **并行归并排序**：分片局部排 + $\log p$ 轮并行归并。
- **奇偶转置排序**：相邻处理器比较交换，实现简单、通信局部。
- **双调排序**：比较器网络，结构固定，$O(\log^2 n)$，GPU 友好。
- **样例排序**：采样选枢轴 + 全局桶交换，工业最常用。
- 铁律：**数据移动 $O(n)$ 是并行排序的扩展天花板。**

在下一节，我们把「归并」这个操作做到极致：学习**并行前缀和与归约**——看似平凡却无处不在的并行原语。
