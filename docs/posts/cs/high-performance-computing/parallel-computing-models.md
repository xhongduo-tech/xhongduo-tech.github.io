## 为什么从模型开始

上一节的加速比是「事后度量」，这一节我们要「事前预测」。

写一个并行算法之前，得先有个抽象的机器让你分析它。

这个抽象机器就是**并行计算模型（parallel computation model）**。

它把五花八门的真实硬件（总线、缓存、网络拓扑）简化成几条清晰的规则，让你能在纸上算复杂度。

就像顺序算法有随机访问机（RAM）模型，并行算法需要自己的「RAM」。

本节的两位主角是：

- **PRAM**：最理想、最干净的共享内存模型；
- **BSP**：最接近真实分布式机的一步。

<span class="marginnote">并行计算模型是「算法设计」与「硬件实现」之间的合同：算法写给模型，模型再映射到机器。合同越干净，算法越好写；合同越真实，算法越能用。</span>

## 1 并行计算模型是什么

一个并行计算模型至少要回答三件事：

- **并行度怎么来**：有多少处理器？各自能独立做什么？
- **通信怎么发生**：处理器之间怎么共享数据？代价多少？
- **同步怎么做**：什么时候必须「停下来等齐」？

不同的答案，构成不同的模型。

模型决定了你在算法里敢不敢假设「读别人的数据是免费的」——这在共享内存上是真的，在分布式内存上则是一场灾难。

## 2 PRAM：理想共享内存

**PRAM（Parallel Random Access Machine，并行随机访问机）**由福琼与怀尔在 1978 年提出。

它是共享内存的完美抽象：

- $p$ 个处理器 + 一个无限大的共享内存；
- 每条指令要么算、要么读写内存，耗时都是单位时间；
- 处理器之间通过共享单元直接通信，**通信免费**。

PRAM 内部还要区分**并发读/写**的许可：

| 变体 | 含义 |
| --- | --- |
| EREW | 互斥读、互斥写（最严） |
| CREW | 允许并发读、互斥写 |
| CRCW | 允许并发读、并发写（最宽，写冲突要定规则） |

**辨析｜易错点：** CRCW 里多个处理器同时写同一单元，结果由规则决定——「取最小值」「任意一个」等。

同一份数据在不同规则下可能算出不同的结果，分析时必须说明用了哪种 CRCW 变体。

PRAM 的价值在理论：它让算法设计者摆脱通信细节，专注并行思想。

代价是太理想：现实中每台机器都有通信延迟，而且共享内存读写**不是免费的**。

于是有了更务实的 BSP。

## 3 BSP：务实的一步

**BSP（Bulk Synchronous Parallel，整体同步并行）**由莱斯利 · 瓦朗（Leslie Valiant）在 1990 年提出。

它把并行计算组织成一个个**超步（superstep）**：

1. **本地计算**：每个处理器只算自己手里的数据；
2. **全局通信**：处理器之间交换消息；
3. **全局同步**：所有处理器等齐，才开始下一个超步。

BSP 模型由三个参数刻画：

- $p$：处理器个数；
- $L$：同步的代价（一个超步里同步操作的时间）；
- $g$：通信带宽的倒数——单位消息交换的代价，$g$ 越小带宽越大。

## 4 公式解析：BSP 的超步成本

设一个超步里：

- $w_i$：第 $i$ 个处理器本地计算的时间；
- $h$：该超步中**最大的消息收发量**（每个处理器发 + 收的最大包数）。

那么这一个超步的成本是：

$$T_{\text{superstep}} = \max_i w_i + g \cdot h + L$$

拆成三步理解：

- **第一步，$\max_i w_i$**：本地计算时间取**所有处理器中的最大值**——同步意味着大家都等最慢的那个，这是负载均衡问题的数学化身。
- **第二步，$g \cdot h$**：通信时间 = 带宽倒数 × 最大消息量。$h$ 是「通信缺口（h-relation）」，是并行算法最该压低的量。
- **第三步，$+L$**：每次同步都有固定开销 $L$，与数据量无关。

整个 BSP 程序的成本就是所有超步相加：

$$T = \sum_{\text{supersteps}} \big(\max_i w_i + g \cdot h + L\big)$$

<span class="marginnote">BSP 的一个著名应用是 Google 的 Pregel（图计算系统）：把图算法拆成超步，每个超步里节点交换消息再同步，正是 BSP 思想的工业落地。</span>

这个公式给出三条优化直觉：

**减少超步数、压低最大负载、压缩 h-relation。**

## 5 LogP 与其他模型

1990 年代，卡伦（Culler）等人觉得 BSP 的 $g$ 还不够细，提出 **LogP 模型**，用四个参数刻画分布式机：

| 参数 | 含义 |
| --- | --- |
| $L$ | 消息在网络上的延迟（latency） |
| $o$ | 处理器发送/接收一条消息的开销（overhead） |
| $g$ | 消息之间的最小间隔（带宽相关） |
| $P$ | 处理器/进程个数 |

LogP 的精度换来了分析的繁琐。

工程上，现代 HPC 分析常常直接在**真实机参数**（延迟、带宽、每核浮点峰值）上建粗略模型，LogP 则作为理论基石被继承下来。

<span class="marginnote">还有一个常被提的模型叫 APRAM（异步 PRAM）：允许处理器各自独立推进、用显式同步语句协调，是对 PRAM 的一种务实修正。</span>

## 6 核心对比：PRAM 与 BSP

| 维度 | PRAM | BSP |
| --- | --- | --- |
| 内存视角 | 全局共享、通信免费 | 显式消息传递 |
| 同步 | 隐含在指令级 | 超步末尾强制同步 |
| 通信代价 | 忽略 | $g \cdot h$ 显式计入 |
| 同步代价 | 忽略 | $L$ 显式计入 |
| 可分析性 | 最强 | 中等 |
| 与硬件贴近度 | 低 | 高 |

**核心结论：** PRAM 适合推导理论下界，BSP 适合预测真实机器上的性能。

现代并行算法教科书几乎都以「先 PRAM 想思路、再 BSP/LogP 估代价」的方式组织内容。

## 7 小结

- **并行计算模型**是算法与硬件之间的抽象合同，回答并行度、通信、同步三件事。
- **PRAM** 假设共享内存、通信免费，分 EREW/CREW/CRCW 三档并发规则。
- **BSP** 用「超步」组织计算，成本 $T = \max_i w_i + g \cdot h + L$。
- **LogP** 用 $L/o/g/P$ 四个参数刻画分布式通信。
- BSP 公式给出三条铁律：**减少超步、压低最大负载、压缩 h-relation**。

在下一节，我们开始动手设计并行算法：讨论怎么把一个大任务**分解**成小块、再**映射**到处理器上——这是并行算法的第一步。
