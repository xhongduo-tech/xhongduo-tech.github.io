## 为什么从信号量开始

上一课我们止步于「朴素加锁必挂」，问题在于互斥必须由某个原子机制落地。代克斯特拉 1965 年提出的**信号量（semaphore）**，是第一个既优雅又通用的答案：它既当互斥锁，又能做「等一个条件」的阻塞同步——生产者-消费者问题由此成为并发课程的经典标本。搞懂信号量的 `P/V` 两个操作、搞懂有界缓冲区里三个信号量如何各司其职，你就掌握了后续锁、条件变量、管程所围绕的全部主题骨架。

## 1 信号量：一个带计数器的门卫

**信号量（semaphore）**：一个非负整数 $s$，配有两个原子操作：

- **P（Proberen / wait）**：若 $s > 0$ 则 $s \leftarrow s - 1$；否则阻塞等待，直到 $s$ 变为正数再减一。<span class="marginnote">P 与 V 都取荷兰语：Proberen（测试）与 Verhogen（增加）。代克斯特拉用母语命名，这两个缩写从此写进所有操作系统的教科书。P 就是「申请资源」，V 就是「归还资源」。</span>
**V（Verhogen / signal）**：$s \leftarrow s + 1$，若此时有线程因 P 阻塞，则唤醒其中一个。

两个操作必须**原子**执行——这正是硬件需要原子指令的地方。按计数方式，信号量分两类：

- **二元信号量（binary semaphore）**：取值仅 0 或 1，等价于一把锁，用于互斥。
- **计数信号量（counting semaphore）**：取任意非负整数，用于管理「一定数量」的资源。

关键直觉：**信号量守护的是「资源存量」**。$s$ 表示当前可用资源个数；P 是「拿走一个资源」，V 是「归还一个资源」。把「资源」理解为空位或物品，生产者-消费者就有了天然的建模语言。

## 2 互斥锁模式：信号量当锁用

把信号量当互斥锁，只需让计数器只取 0/1：

```c
sem_t mutex;
sem_init(&mutex, 0, 1);      /* 初值 1 */

P(&mutex);                    /* 申请锁：s 从 1 变 0 */
/* …… 临界区 …… */
V(&mutex);                    /* 释放锁：s 从 0 变 1 */
```

这是二分互斥的标准写法。但信号量的真正威力在下一步：它不只是锁，还能表达「等一个事件」——比如「等到缓冲区里有物品」。锁只能保证互斥，不能表达「队列里有数据」这种计数条件；信号量的计数器把这个条件直接编码了。

## 3 生产者-消费者：三个信号量各司其职

经典场景：**生产者（producer）**线程不断 `put` 物品进缓冲区，**消费者（consumer）**线程不断 `get` 取走。约束有三：任意时刻最多一个线程碰缓冲区结构（**互斥**）；缓冲区满时生产者必须等待（**满则停**）；缓冲区空时消费者必须等待（**空则等**）。

设缓冲区容量为 $n$，引入三个信号量：`mutex`（互斥）、`slots`（空位数，初值 $n$）、`items`（物品数，初值 0）。<span class="marginnote">命名传达语义：`slots` 就是「缓冲区还能放几个」，`items` 就是「缓冲区里已有几个」。两个计数信号量合起来恰好覆盖满/空两个方向，互斥锁则守护缓冲区的物理结构（数组下标、链表指针）。</span>

```c
void producer(){                                   void consumer(){
    while(1){                                          while(1){
        item = produce();                                 P(&items);      /* 有物品才取 */
        P(&slots);    /* 有空位才放 */                    P(&mutex);      /* 进临界区 */
        P(&mutex);     /* 进临界区 */                     item = buf[out];
        buf[in] = item;                                  out = (out+1) % n;
        in = (in+1) % n;                                 V(&mutex);      /* 出临界区 */
        V(&mutex);     /* 出临界区 */                     consume(item);
        V(&items);    /* 物品多一个 */                 }
    }                                              }
}
```

**这就是教科书级的「先申请资源，再进临界区」范式**：`slots`/`items` 这两个计数信号量在互斥锁**之前**被 P——先确定「这件事能做成」（有空位/有物品），再进去动手。次序颠倒则会引入死锁，这是本课最经典的易错点（详见第 5 节）。

## 4 公式解析：缓冲区的守恒不变量

生产者-消费者程序的正确性由一条**守恒律**保证：

$$
\underbrace{slots}_{\text{空位数}} + \underbrace{items}_{\text{物品数}} + \underbrace{mutex}_{\text{0 或 1}} \;=\; n \quad\text{（始终成立）}
$$

拆解这条不变量：

- **第一步，数守恒**：缓冲区每放入一个物品，`slots` 减 1、`items` 加 1，两者之和不变；`mutex` 在临界区外是 1、在临界区内是 0，正好补偿「锁住期间没人进出」的那一步差额。
- **第二步，证安全**：因为 $slots + items \le n$ 始终成立，缓冲区里的物品数 `items ≤ n` 不会越界写；`items ≥ 0` 则保证消费者不会空读。
- **第三步，证活性**：生产者 P(`slots`) 在满时阻塞，但消费者取走物品后 V(`slots`) 必会唤醒它，故不饥饿；对称地，消费者也不会永久等待。<span class="marginnote">这是「不变量 + 逐步论证」的完整示范：安全性质用不变量证，活性性质用「谁 V 谁唤醒」证。Herlihy 全书的方法论，在这三行代码里已经成型。</span>

## 5 辨析｜易错点：P 的顺序不能颠倒

把生产者写成先 P(`mutex`) 再 P(`slots`) 会发生什么？

```c
P(&mutex);      /* 先拿锁 */
P(&slots);      /* 再等空位 —— 若缓冲区满则在此阻塞 */
```

缓冲区满时：生产者拿着锁、阻塞在 `slots` 上。消费者想取物品必须 P(`mutex`)，拿不到锁，阻塞——而能让 `slots` 变大的正是消费者。于是两边互等，**死锁**。结论一句话：**先申请计数信号量（资源），后申请互斥信号量（锁）**；释放顺序反过来。<span class="marginnote">这个「资源先于锁」的顺序，是几乎所有并发经典考题的考点；到《死锁检测与预防》一篇，我们会把这种「循环等待」上升为死锁的四个必要条件。</span>

## 6 小结

- **信号量**：非负计数器 + 原子 P/V；P 申请、V 归还，语义是「管理资源存量」。
- 二元信号量 = 互斥锁；计数信号量 = 资源管理。
- 生产者-消费者用**三个信号量**分工：`mutex` 护结构、`slots` 管满、`items` 管空。
- 守恒不变量 $slots + items + mutex = n$ 一锤定音地证明安全；唤醒关系证明活性。
- **P 顺序**：先资源（slots/items）后锁（mutex），颠倒必死锁。
