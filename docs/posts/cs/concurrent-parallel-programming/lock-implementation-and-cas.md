## 为什么从锁的实现开始

前面我们反复强调「朴素加锁必挂」，也反复预告「要靠硬件原子原语」。这一课兑现承诺：把 `test-and-set`、`fetch-and-add`、`compare-and-set`（CAS）这些**硬件原子原语**逐个解剖，再从它们出发实现三把递进的锁——朴素自旋锁、票据锁、队列锁。这条演进线串起了 Herlihy §7 的全部精华：从「正确」到「公平」到「可扩展」，锁的设计史就是多核性能的进化史。

## 1 三个硬件原语：原子性的最小单位

**硬件原子原语**：由处理器保证「读-改-写」在一条指令内完成、对其它核心不可分割的操作。三个主角：

- **test-and-set（TAS）**：读取 `word` 的旧值，同时把它置为 1，返回旧值。**语义：看一眼并同时把它抢走。**
- **fetch-and-add（FAA）**：读取旧值，同时把 `word` 增加 `d`，返回旧值。**语义：原子地加一，并告诉我之前是多少。**
- **compare-and-set（CAS）**：若 `word` 等于 `expected`，则把它置为 `new`，返回成功；否则不改动。**语义：只有在我预期的前提下才交换。**

```c
bool CAS(int *word, int expected, int new){
    if (*word == expected){ *word = new; return true; }
    return false;
}
```

**辨析｜易错点：** CAS 与比较-交换在 x86 里对应 `cmpxchg`，但现代写法常用 **`compare-and-swap`** 返回旧值（ABA 问题由此而来）；在 Arm 上则用 **`load-linked/store-conditional`（LL/SC）** 代替，两者都拥有共识数 ∞，能力等价。<span class="marginnote">上一课《并发对象与同步原语相对能力》已经证明：只有共识数 ≥ 2 的原语才可能实现互斥，而 CAS/LL/SC 是共识数 ∞ 的唯一现实代表——所以每一个多核架构都咬着牙把这条指令做进硅片。</span>

## 2 朴素自旋锁：正确但会输在扩展性

用 TAS 实现一把锁：`state` 为 0 表示空闲、1 表示占用。

```c
void lock(){ while (TAS(&state) == 1) ; }   /* 忙等轮询 */
void unlock(){ state = 0; }
```

它**正确**（TAS 保证了抢占的原子性），却有两个大毛病：

1. **自旋争用**：多个线程同时自旋在同一个缓存行上，每次状态翻转都要触发缓存一致性广播——临界区越短、线程越多，缓存一致性总线越拥塞，性能崩得越难看。
2. **不公平**：释放锁时谁抢到看运气，存在**饥饿**可能。

于是有了第一个改进——把「抢锁」与「等待」分开：先 TAS 探测，抢不到就阻塞睡眠而不是空转。这就是 **test-and-test-and-set（TTAS）** 的思路，它先读状态、只在看到「可能解锁」时才 TAS，把不必要的写广播挡在门外。

## 3 票据锁：先来后到的公平

**票据锁（ticket lock）**：把锁变成两家计数器，一个 `next`（发号）一个 `owner`（叫号）。每个线程拿票即排队：

```c
void lock(){
    int my_ticket = FAA(&next, 1);      /* 原子取号 */
    while (owner != my_ticket) ;        /* 等叫到自己 */
}
void unlock(){ owner = owner + 1; }     /* 叫下一位 */
```

**关键：谁先 FAA 取号，谁的 ticket 小，谁就先获锁——公平性由发号顺序硬性保证，不存在饥饿。** 代价是每个线程解锁都写 `owner`，仍然共享缓存行；且拿票之后若临界区很长，后到的线程无法插队，吞吐不如「尽力而为」的锁。<span class="marginnote">票据锁是 Linux 内核传统自旋锁的前身（`arch_spinlock_t` 曾用 ticket 结构）；它的思想被广泛复用——任何「先到先得」的资源队列，都可以用「发号-叫号」建模。</span>

## 4 队列锁：把自旋点拆开

争用的根源是大家都在同一个地址上自旋。**队列锁（queue lock）** 的思路：让每个等待者各自在一个**私有的**标志位上自旋，锁的传递变成一条明确的链表，谁来唤醒谁一目了然。Herlihy 的 **CLH 锁**与 **MCS 锁**是代表。

**CLH（Craig-Landin-Hagersten）**：每个线程自旋在前驱节点的 `locked` 标志上；解锁时把自己的 `locked` 置假，后驱自动被唤醒。自旋访问的是**别人的节点**，天然错开缓存行。
- **MCS（Mellor-Crummey-Scott）**：每个线程自旋在自己的节点上，解锁时**显式**唤醒后继。适合 NUMA，因为释放锁的成本只落在本地。

CLH/MCS 的共同点是把「谁自旋、谁唤醒」显式编码进数据结构，**从而同时获得公平、可扩展与低缓存争用**——这是自旋锁的工程巅峰。<span class="marginnote">到《并发数据结构：链表/队列/栈》一课你会看到，MCS 锁的「队列」思想还能反过来用于构造真正的并发队列：用原子操作把节点链起来，正是 Michael-Scott 队列的骨架。</span>

## 5 公式解析：CAS 的条件更新语义

CAS 的核心价值在于它把「读 + 判 + 写」压缩成一步。用公式把它写清楚：设 `word` 旧值为 $w$，期望值 $e$，新值 $n$，则

$$
\text{CAS}(\text{word}, e, n):\quad
\begin{cases}
\text{word} \leftarrow n, & \text{若 } \text{word} = e \text{（成功）}\\
\text{不改动}, & \text{否则（失败，可重试）}
\end{cases}
$$

- **第一步，读条件**：只有「当前值恰好是预期的 $e$」时交换才生效——这使 CAS 能表达「别人没动过，我才动手」。
- **第二步，用场景**：自旋锁的解锁就是 `CAS(&state, 1, 0)`，只有锁确实在自己手里才释放；无锁数据结构的插入则是 `CAS(&next, NULL, newNode)`，只有确实「后面没人」才接上新节点。
- **第三步，看局限**：CAS 保证的是「值没变」，不是「状态没变」。若某值从 $A$ 变 $B$ 又变回 $A$，CAS 会误判为「没人动过」——这就是**ABA 问题**，它的解法（版本号、`LL/SC`）在《并发数据结构》一篇正面展开。<span class="marginnote">ABA 问题值得记住一句话：<strong>CAS 只能发现「值变了」，发现不了「值变过又变回来」。</strong> 无锁算法的历史 bug 里，ABA 是最常见、最难查的一类。</span>

## 6 小结

- 三大硬件原语：**TAS**（读且置 1）、**FAA**（原子加一）、**CAS**（条件交换）；共识数 ∞ 的原语家族。
- **朴素 TAS 锁**正确但争用缓存行、可能饥饿；**TTAS** 先读后写，挡住写广播。
- **票据锁**用发号-叫号实现严格先来后到，杜绝饥饿，但共享 `owner` 缓存行。
- **CLH/MCS 队列锁**让每个线程在私有标志上自旋，公平 + 可扩展 + 低争用三丰收。
- CAS 语义是「值没变才交换」，因此**发现不了 ABA**，需要版本号或 LL/SC 兜底。

在下一节，我们跳出「锁」去看另一种同步结构：**条件变量与管程**，并用它解决经典的**读者-写者**问题——锁保护数据，条件变量等待条件，两者合起来才构成完整的同步工具箱。
