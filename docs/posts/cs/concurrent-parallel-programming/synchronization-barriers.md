# 同步屏障 Barrier

<div class="epigraph">
<p>许多并行程序的结构可以浓缩成一句口令：一轮又一轮，每次都在屏障前集合，集合齐了再出发。</p>

## 为什么从屏障开始

工作窃取解决「负载不均」，但很多并行计算要求**每一轮所有线程都完成，才能进入下一轮**——比如数值迭代（热传导、PageRank 的迭代收敛）、物理仿真（每一时间步的粒子更新）。这种「集体集合点」就是**屏障（barrier）**。Herlihy §16 从最朴素的计数屏障讲到树形屏障、广播屏障，每一代都针对同一组硬件烦恼：**核数一多，单一计数器就会成为争用与可扩展性的瓶颈**。这一课我们要回答：为什么简单的屏障会卡？树形、广播屏障如何救场？

## 1 屏障问题：等齐了再走

**屏障（barrier）**：一种同步结构，要求一组线程全部到达某个点之后，才允许它们各自继续。典型形态：

```c
// 每轮计算后：
compute_round();      /* 各线程算自己那份 */
barrier_wait();       /* 等所有人算完 */
next_round();         /* 才能安全进入下一轮 */
```

为什么必须等齐？因为第 $k+1$ 轮的任何线程都可能读到第 $k$ 轮**别人**写的数据——不等齐就读，是上一课我们反复讲的竞态。屏障就是「集体互斥的汇合点」：它不保护单个临界区，而是保护**轮次之间的边界**。<span class="marginnote">屏障与锁的最大区别：锁是「一人进、别人等」；屏障是「要等就一起等，等齐一起走」。数值计算、GPU 的 `__syncthreads()`、分布式训练里的 all-reduce，本质都是屏障。</span>

## 2 朴素屏障：一个计数器的问题

最简单的实现：一个计数器 `count`，每个线程到达就 `count++`，最后一个到达的人发现 `count == n`，唤醒所有人。

```c
barrier_wait(){
    lock();  count++;
    if (count == n) { count = 0; unlocked = true; cv.notify_all(); }
    else { while (!unlocked) cv.wait(); }
    unlock();
}
```

正确性没问题，可扩展性却糟：所有线程**轰击同一个计数器与同一个缓存行**。$n$ 个线程同时到达，等于把计数器当成了自旋锁的锁变量——争用随 $n$ 线性恶化，128 核时性能惨不忍睹。更糟的是它还有**复用陷阱**：如果第一个离开屏障的线程立刻再来一轮，可能把 `count` 提前清零，第二轮的线程就凑不满 $n$。

注意「同一个缓存行」这个措辞：CPU 缓存行通常 64 字节，计数器 `count` 与周围状态挤在同一行。$n$ 个线程同时 `count++`，就是 $n$ 个核同时读改写同一行——缓存一致性协议被迫在核间反复广播行失效，一次广播就能吞掉几百个时钟周期。**这个现象叫缓存行乒乓（cache-line ping-pong）**，它是「单计数器屏障」可扩展性差的物理根源：瓶颈在缓存，不在锁，所以加读写锁也救不回来。

也因此，工程实现里常见一招**填充（padding）**：把每个线程要用的计数、状态各自放进独立的缓存行（对齐到 64 字节的倍数），让线程们各打各的行、互不干扰——「物理上隔离争用」往往比「逻辑上减少争用」更便宜。这也是为什么高性能库总在结构体里塞 `char pad[64]` 之类的占位。

## 3 感知反转屏障：把复用问题干掉

**感知反转屏障（sense-reversing barrier）**用一招解决复用：每个线程维护一个本地布尔 `sense`，交替取反（true / false），屏障只关心「大家本轮是不是同一种感知」：

```c
barrier_wait(){
    local_sense = !local_sense;          /* 每轮感知取反 */
    lock();  count++;
    if (count == n) { count = 0; unlocked = local_sense; cv.notify_all(); }
    else { while (unlocked != local_sense) cv.wait(); }
    unlock();
}
```

**核心要点：** 靠「感知取反」代替「计数器清零」，彻底免除了「第二轮把第一轮的计数器清零」的误判——每轮用的感知值不同，上一轮的信号不会再误导这一轮。它仍是单计数器，争用问题还在，但复用正确性被一举解决。<span class="marginnote">感知反转是「用状态位的交替代替清零」的经典例子，同一思想在读写锁的偏向、以及轮询优化的 epoch 机制里反复出现——记住「清零有竞态，取反没有」。</span>

## 4 树形屏障与广播屏障：把争用摊开

单计数器的争用根源是「所有人打一个点」。两大改进各自摊开争用：

**树形屏障（combining tree barrier）**：把 $n$ 个线程组织成树，每个内部节点统计「子树内到达数」。叶子线程先向父节点汇报，父节点等齐子树再向祖父汇报，根节点齐了再沿树逐层广播「出发」。**每次汇报只跟父节点打交道，争用从 O(n) 降到 O(log n)。**
- **广播屏障（dissemination barrier）**：干脆不要计数——每轮每个线程向固定对子发送「我已到达」，并等待固定对子的消息；对子的配对每轮不同，$\lceil \log_2 n \rceil$ 轮后所有人都互相确认过。**它用 log 轮信息传播代替计数，NUMA 友好，且天然可复用。**

| 屏障 | 争用 | 轮数 / 深度 | 适合场景 |
| --- | --- | --- | --- |
| 计数屏障 | O(n) 单点 | O(1) | 线程少、简单 |
| 感知反转 | O(n) 单点 | O(1) | 复用正确优先 |
| 树形屏障 | O(log n) | O(log n) | 中大规模、NUMA |
| 广播屏障 | O(n) 但分散 | O(log n) | 大规模、NUMA 友好 |

**辨析｜易错点：** 树形屏障胜在「汇报更少」，广播屏障胜在「无中心、天然可复用」——但广播屏障每轮要对特定对子说话，若某线程掉线，整轮停摆；树形屏障某个子树出问题，也只影响该子树以上的传播。<span class="marginnote">GPU 上 `__syncthreads()` 就是硬件化的屏障；分布式深度学习里每次 all-reduce 前的「等梯度齐」也是屏障——树形与广播的思想在 NCCL 等框架的 ring / tree 算法里继续活着。</span>

**辨析｜易错点：屏障不适合流水线。** 屏障强制「整组齐步走」，而流水线风格的算法（生产者推进一段、消费者消化一段）天生错峰，强塞屏障只会把整条线的吞吐压到最慢的那一档。错峰场景的正确工具是有界队列或 channel，而不是屏障——判断标准只有一句：**所有线程必须同时到达某个轮次边界吗？** 数值迭代、物理仿真答「是」，生产者-消费者答「否」。

## 5 公式解析：广播屏障需要多少轮

广播屏障的正确性来自「信息传播代数」：每个线程每轮把「我到了」的消息传给一个固定对子，同时从对子收到消息；对子配对每轮变化。设 $n = 2^k$ 个线程，需要的轮数满足

$$
\text{轮数} \;=\; \lceil \log_2 n \rceil
$$

- **第一步，理解一轮**：每一轮，线程 $i$ 与线程 $j$（$j = i \oplus 2^{r-1}$，$r$ 是轮号）交换到达消息。
- **第二步，追消息**：第 1 轮后，每个线程知道了「与自己只差一位二进制」的线程；第 2 轮后差两位……第 $r$ 轮后，知道了「二进制位差 ≤ r 位」的所有线程。
- **第三步，数轮数**：最多需要覆盖 $\log_2 n$ 位，所以 $\lceil \log_2 n \rceil$ 轮后，任意线程都收到了其他所有线程的到达消息——**信息传播的「直径」就是 log n**。<span class="marginnote">这个推导与 gossip / 传染病传播协议同构：广播屏障本质是一个同步的 gossip 协议——「每一轮交换 + 轮数 = 网络直径」。信息在稠密图上的扩散，永远由直径决定速度。</span>

**把 $n = 8$（$k=3$）的配对摊开看**：线程编号 0–7（二进制 000–111），第 $r$ 轮与编号相差 $2^{r-1}$ 的线程交换消息：

| 轮次 $r$ | 配对距离 $2^{r-1}$ | 线程 0 与谁交换 | 线程 3 与谁交换 |
| --- | --- | --- | --- |
| 1 | 1 | 1（001） | 2（010） |
| 2 | 2 | 2（010） | 1（001） |
| 3 | 4 | 4（100） | 7（111） |

三张表合起来：线程 0 依次收到 1、2、4 的「到达」，线程 3 依次收到 2、1、7……每一轮，每个线程对「另一台线程是否到达」的信息掌握量翻倍，到第 3 轮末所有人都互相确认过——**这正是指数级信息传播最直观的一张表**，也顺带解释了为什么轮数就是 $\lceil \log_2 n \rceil$。

**选型经验**：核数少（< 8）用计数屏障即可；核数多、跨 NUMA 节点时优先广播屏障（对子通信大多落在同一节点，跨节点流量少）；需要「出错能定位到子树」时选树形屏障。多数并行库默认给你一个「树形 + 感知反转」的组合，先跑通，再按实测决定要不要换。

### 术语速查

**屏障（barrier）**：等齐一组线程再放行的集体同步点；**轮次（round）**：两次屏障之间的计算段；**感知反转（sense reversing）**：用布尔取反代替计数器清零来解决复用；**缓存行乒乓（cache-line ping-pong）**：多核反复读改写同一缓存行引发的协议广播开销；**广播屏障（dissemination barrier）**：用 $\lceil \log_2 n \rceil$ 轮两两交换代替计数的无中心屏障。

## 6 小结

- **屏障**：等齐一组线程再放行，保护「轮次边界」，与锁的「一人进」语义相反。
- **朴素计数屏障**正确但单点争用 O(n)，且有复用清零竞态。
- **感知反转**用布尔取反替代清零，解决复用正确性，争用未变。
- **树形屏障**把汇报组织成树，争用降到 O(log n)；**广播屏障**用 log n 轮两两交换，无中心、NUMA 友好。
- 广播屏障轮数 $=\lceil \log_2 n \rceil$，本质是同步 gossip，信息扩散由网络直径决定。

在下一节，我们把「原子性」从锁推向更高层：**事务内存**——让一串操作像数据库事务一样「要么全成、要么全败」，程序员不再手写锁，而是声明「这段要原子执行」。那是《事务内存 TM》。
