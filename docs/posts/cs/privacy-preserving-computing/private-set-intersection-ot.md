## 为什么从隐私求交开始

上一课介绍了安全多方计算的两种范式，但真实的隐私计算需求往往不是「算任意函数」，而是一个极高频的特定问题：**两家机构各持一组数据，想找出共同的部分，又不肯把各自的集合泄露给对方。** 银行们查共同客户、广告商对转化归因、医院匹配共患病历——这全是**隐私求交（private set intersection, PSI）**。PSI 是安全多方计算在工业界落地最广的场景之一，而它最底层的积木，是一条只有两个参与者、看似简单到多余的协议——**不经意传输**。

读这一课的收获会同时服务两件事：一方面 PSI 本身是高频刚需，另一方面 OT 是理解本专题此前所有 SMPC 构造的钥匙。把它当成「隐私计算的最小电路」来学，后面看任何协议都不会再觉得神秘。

## 1 不经意传输：一次选择，一方知晓

**不经意传输（oblivious transfer, OT）**：发送方 S 持有两个消息 $m_0, m_1$；接收方 R 选择比特 $b$。协议结束后，R 恰好学到 $m_b$，对 $m_{1-b}$ 一无所知；而 S 完全不知道 R 选了哪个。

把 OT 想象成「不可见的自助取件柜」：柜子里有 0 号和 1 号两个格子，取件人投一枚硬币决定开哪个门，取完就走；柜子（发送方）记录不下他开了哪扇门，只知道自己投递了两个格子。它保证的是「取件人的选择对外不可见」——这是所有「接收方输入保密」类协议的最小公分母。<span class="marginnote">OT 的「不经意」三个字，指的是 S 对 R 的选择<strong>盲目</strong>。它像一个不可见的自动售货机：投币选货，机器不知道自己卖出了哪一件。这个性质是「接收方输入保密」的最小原子。</span>

OT 的威力远超它的简单外表。1988 年基利安证明了一个惊人定理：**OT 是完备原语**——给定一个安全的 OT，可以构造任意函数的安全多方计算。上一课混淆电路里 Bob 悄悄拿输入标签，靠的就是 OT；秘密分享方案里交换秘密片段，也能归约为 OT。可以说，**OT 是 SMPC 世界的「种子」**。

完备性还有一个方向相反的推论：**如果 OT 不安全，SMPC 就不可能安全**。几乎所有多方计算协议——混淆电路、秘密分享的乘法、PSI——都能归约到 OT；反过来 OT 可以由更基础的原语（如带陷门的公钥加密）构造。所以研究 OT 的安全性假设，就是研究整个隐私计算的地基。

现实中一次协议要跑大量 OT，直接执行每个都贵。**OT 扩展（OT extension, Ishai et al. 2003）**用少量「种子 OT」加对称密码，批量衍生出成千上万个 OT，成本从「每个 OT 一次公钥运算」降到「每个 OT 一次哈希」。工程上的 PSI 都建立在 OT 扩展之上。

### 一种直观的 OT 构造（RSA 风格）

发送方选两个随机消息 $m_0, m_1$ 与一个 RSA 私钥指数 $d$，把 $m_0, m_1$ 连同公钥 $e$ 发给接收方；
接收方选比特 $b$ 与随机数 $k$，发送 $v = k^e + m_b \bmod N$；
发送方对 $v$ 用私钥解密得到 $k'_0 = (v - m_0)^d$、$k'_1 = (v - m_1)^d$，把 $(k'_0 - m_0, k'_1 - m_1)$ 发回；
- 接收方用自己的 $k$ 校验，恰好一个匹配，得到 $m_b$；发送方看不出 $b$——因为 $v$ 对两个候选「雨露均沾」。

这个构造只是教学直觉，真实 OT 用更强的数学保证安全性，但它揭示了 OT 的全部要素：**接收方用一次盲化隐藏选择，发送方用一次解密同时服务两种可能。**

## 2 直觉方案：哈希求交为何不够

最朴素的想法：双方各自把集合元素做哈希，交换哈希集合，求交集。若 $x = y$，则 $H(x) = H(y)$，交集自然浮现。这个方案的问题是**字典攻击**：集合元素的取值空间往往很小（手机号、身份证、IP 地址），攻击者枚举整个空间、逐个哈希，就能从对方的哈希集合反推出元素。

设元素空间大小为 $N$（比如 10 亿个手机号），哈希集合泄露后，一次离线枚举即可重建对方集合。**哈希是单向的，但单向只在输入高熵时成立；手机号这类低熵输入，单向形同虚设。**

用数字看多可怕：假设对方集合里有 1 万个手机号，哈希集合泄露后，攻击者枚举全部 10 亿个候选手机号、逐个哈希并与 1 万个哈希比对——现代 GPU 上一分钟就能跑完，等于把对方的完整通讯录拿到手。哈希只保护「计算上难」，而枚举根本不需要破解哈希。<span class="marginnote">这是隐私计算里反复出现的一课：<strong>密码学原语保护的是高熵秘密</strong>。低熵数据必须先被「抬高熵」——通常用带密钥的哈希（PRF）把密钥藏进运算里，让攻击者无法离线枚举。这正是下一节 DH-PSI 的动机。</span>

所以真正安全的 PSI 不能只靠公开哈希，必须引入**密钥**，让每一方都无法独立验证「某个元素在不在对方集合里」。

引入密钥之后，攻击者就算枚举出候选元素 $v$，也无从验证 $H(v)^a$ 是否等于对方集合里的某个值——因为缺少盲化密钥 $a$。**密钥把「可离线验证」变成了「必须在线协作」**，字典攻击的窗口被彻底关上。

## 3 DH-PSI：用双盲化挡住字典攻击

**基于 Diffie-Hellman 的 PSI（DH-PSI）**是经典构造，也是理解 PSI 的入口。设双方各持集合 $X$（Alice）、$Y$（Bob），协议如下：

Alice 生成私钥 $a$，把集合盲化为 $X' = \{H(x)^a \mid x \in X\}$，发给 Bob；
Bob 生成私钥 $b$，把集合盲化为 $Y' = \{H(y)^b \mid y \in Y\}$，发给 Alice；
双方各自对收到的集合再做一次自己的指数：Alice 算 $Z_X = \{H(x)^{ab} \mid x \in X\}$，Bob 算 $Z_Y = \{H(y)^{ab} \mid y \in Y\}$；
- 双方把 $Z$ 集合（或其哈希）交换比对，相等的元素即交集。

为什么安全？Alice 收到 $H(y)^b$ 后，想反推 $H(y)$ 必须解离散对数；在 CDH 假设下这不可行。<span class="marginnote">关键在「双盲」：$H(x)^a$ 对 Bob 是一次盲化，Bob 再指数成 $H(x)^{ab}$，Alice 自己也认不出 $H(x)$——因为解开外层指数 $a$ 需要离散对数。双方都在「看不见对方原始元素」的前提下，把元素推到了一个可比的公共编码空间。</span>同时私钥 $a$、$b$ 的参与让字典攻击失效：攻击者没有 $a$ 或 $b$，枚举出来的 $H(v)^a$ 根本对不上号。

DH-PSI 的通信量是两趟全集交换：$O(|X| + |Y|)$。双方各要把盲化后的整个集合发给对方。对百万级集合，这意味着一笔不小的网络传输与两轮指数运算。正因如此，工业界更常用 **OPRF 基的 PSI**：用一次 OPRF 让双方把元素映射到共同伪随机值，再靠布谷鸟哈希把通信压到接近下界。**DH-PSI 是教学主线，OPRF-PSI 是工程主力。**

### 正确性与安全性的分工

DH-PSI 的正确性来自哈希的抗碰撞性（两个不同元素几乎不会哈希到同一点），安全性来自 CDH 假设（给定 $H(x)^a$ 无法反推 $H(x)$）。这两条性质各自独立：哪怕哈希被攻破，攻击者也只能制造「伪交集」，恢复不出原始元素；哪怕 CDH 被攻破，协议也只是泄露元素、不会算错交集。**分工越清晰，协议越容易审计。**

## 4 公式解析：DH-PSI 的编码等价

PSI 正确性的全部秘密，浓缩在一条等式里：

$$
x \in X \cap Y \iff H(x)^{ab} = H(y)^{ab}
$$

- **第一步，读左侧**：$x$ 属于双方交集，当且仅当 Alice 集合里有 $x$、Bob 集合里有同一个 $x$（记作 $y = x$）。
- **第二步，读中间**：把 $H(x)$ 看作一个可求幂的群元素（椭圆曲线点）。Alice 的盲化指数是 $a$，Bob 的盲化指数是 $b$，双方各做一次后得到 $H(x)^{ab}$——**指数先后次序无关**：$H(x)^{ab} = (H(x)^a)^b = (H(x)^b)^a$。
- **第三步，读右侧**：因为哈希是确定的，$x = y \Rightarrow H(x) = H(y) \Rightarrow H(x)^{ab} = H(y)^{ab}$；反过来，若两条盲化值相等，由哈希的抗碰撞性可知原元素几乎必然相等。**交集判定的本质，是「两边各自算出一个共同盲化值再比较」。**

安全性侧，攻击者面对 $H(x)^a$ 想恢复 $H(x)$，等价于在给定 $g^a$ 时求 $g$——计算 Diffie-Hellman 假设下不可行。**正确性来自哈希的抗碰撞，安全性来自离散对数的困难性**，两条性质各司其职。

还有一个常被忽略的工程细节：**哈希 $H$ 必须映射到群上，而不是先哈希成普通整数再求幂**。若 $H(x)$ 是普通整数、随后映射到曲线点，攻击者可能利用「非群元素」的代数结构做区分攻击。正确做法是让 $H$ 直接输出群元素（如椭圆曲线点的哈希），保证盲化后的值始终落在「离散对数困难」的群内。这个细节选错，整个协议的安全证明就作废了。

## 5 PSI 的变体、应用与工程权衡

PSI 不是单一协议，而是一个家族。按泄露量从少到多排列：

- **纯 PSI**：双方只知道交集元素。
- **PSI-CA（交集基数）**：只输出 $|X \cap Y|$，不输出元素——适合「统计共有多少客户」。
- **PSI-SUM / 标记 PSI（labeled PSI）**：交集元素附带一份属性求和或标签——广告归因里「共同用户贡献了多少转化金额」。

这四类变体的安全级别依次递增，实现成本也依次升高：纯 PSI 只要「等值比较」，PSI-SUM 需要「等值比较 + 密文求和」，复杂度自然上一个台阶。**需求上能少泄露就少泄露，方案上能简单就简单**——这是 PSI 工程选型的第一原则。
- **PSI 与 OT、OPRF**：现代高性能 PSI 常把 DH 盲化替换为**不透明 PRF（OPRF）**或 **OT 扩展**，通信与计算都更优。<span class="marginnote">工程选型的三个旋钮：<strong>通信量、计算量、泄露量</strong>。DH-PSI 逻辑清晰但通信按集合大小线性增长；OT 扩展方案用更密的数学换来更高吞吐。数据量上亿的场景，方案选择几乎决定能不能跑起来。</span>

选型口诀可以这样记：**集合小、逻辑清晰，选 DH-PSI；集合大、要吞吐，选 OPRF/OT 扩展；只要结果不想暴露元素，选 PSI-CA；要附带属性计算，选 PSI-SUM 或 labeled PSI。** 泄露量越少的变体通常代价越高——「只要一个数字」比「要全部交集」便宜得多。

应用早已进入生产：通讯录联系人匹配（双方不泄露完整通讯录）、广告转化归因（平台与广告主共享交集金额）、跨机构反欺诈（银行间匹配可疑账户）、基因组数据匹配（研究机构比对共有变异）。PSI 与同态加密、秘密分享的组合也在联邦学习的垂直领域广泛出现。

| 场景 | 双方输入 | PSI 变体 | 为什么必须 PSI |
| --- | --- | --- | --- |
| 通讯录匹配 | 双方联系人的哈希 | 纯 PSI | 不能把完整通讯录交给对方 |
| 广告归因 | 平台曝光 / 广告主转化 | PSI-SUM | 只共享交集转化金额 |
| 跨行反欺诈 | 各自可疑账户集合 | PSI-CA | 只想知道共同客户数量 |
| 医疗协作 | 各院病历 ID 集合 | 纯 PSI / labeled | 病历 ID 本身即敏感信息 |

## 6 小结

- **不经意传输**：接收方恰好获得 $m_b$、发送方不知 $b$；OT 是 SMPC 的完备原语，靠 **OT 扩展**批量廉价生成。
- 裸哈希求交会被**字典攻击**击穿——低熵输入必须用密钥盲化抬高熵。
- **DH-PSI** 用双盲指数把元素映射到共同编码空间：$x \in X \cap Y \iff H(x)^{ab} = H(y)^{ab}$
