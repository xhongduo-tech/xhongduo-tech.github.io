# 签名的不可伪造性：EUF-CMA 安全模型

<div class="epigraph">

## 为什么从 EUF-CMA 开始

前几节的每个签名方案（RSA-PSS、DSA、ECDSA、EdDSA）都声称「EUF-CMA 安全」。这一节把这个术语拆开：它到底在说什么、为什么是这个定义、攻击者拥有什么能力。EUF-CMA 是现代签名安全证明的**通用靶子**——读懂它，等于读懂「一个签名方案凭什么被信任」的全部论证结构。<span class="marginnote">EUF-CMA 的名字就是它的内容：<strong>EUF = 存在性不可伪造（Existence UnForgeability），CMA = 选择消息攻击（Chosen-Message Attack）</strong>。它描述「什么样的攻击者、什么样的成功」算攻破——这是所有密码安全定义的通用语法。</span>

## 1 攻击者的能力：预言机模型

安全模型先要回答「攻击者能做什么」。EUF-CMA 给攻击者两台机器：

**签名预言机**：攻击者提交任意消息，得到该消息的合法签名——模拟「系统会为任意输入签名」的现实（如签名服务器、认证服务）。
**验证预言机**（部分模型）：攻击者提交「消息-签名对」，得到「合法/非法」——模拟系统对签名的验证反馈。

攻击者还拥有：

**公钥** $pk$（公开）。
**任意计算能力**（多项式时间）。
可以**自适应**地选择要签名的消息——先看以前的签名，再决定下一次要什么。

**这是攻击者能有的最大能力**——除「私钥本身」外的一切。EUF-CMA 假设攻击者就是这个水平，然后问：他还能伪造吗？<span class="marginnote">为什么给攻击者签名预言机？因为现实中攻击者总能诱使系统为他签名（发起合法交易、请求 token）。<strong>一个「只在攻击者看不到签名时安全」的方案毫无用处——签名方案必须在他能随便要签名时依然安全</strong>。这是 CMA 的残酷之处，也是真实安全的前提。</span>

## 2 攻击成功的定义：存在性伪造

**EUF（存在性不可伪造）** 定义「什么样算攻击成功」：攻击者输出一对 $(m', \sigma')$，满足

$\text{Verify}(m', \sigma') = \text{接受}$；
且 $m'$ **从未**被签名预言机签名过。

任何「能造出一条从未被签过的消息的合法签名」的攻击都算成功。注意**存在性**的含义：攻击者不需要伪造「特定目标消息」的签名——哪怕伪造出的是毫无意义的垃圾消息，也算攻破。这是**最宽松的成功标准**，所以对应的「不可伪造」是最强的保证。

若一个方案连「伪造一条新消息」都做不到，那更别说「伪造指定消息」了——EUF 安全是底线。<span class="marginnote">对照更强的变体：<strong>SUF-CMA（强不可伪造）</strong> 要求攻击者连「对已签名消息产生不同签名」都做不到。EUF-CMA 是标准底线，SUF-CMA 用于需要「签名不可重写」的场景（如区块链）。理解两者的差异，是阅读安全证明的前提。</span>

## 3 安全证明的框架：规约

有了定义，怎么「证明」方案安全？答案是**规约（reduction）**：

**定理形态**：若困难问题 $P$（如 RSA 分解、ECDLP）难解，则方案 $\Pi$ 是 EUF-CMA 安全的。

**证明结构（反证）**：

1. 假设存在攻击者 $\mathcal{A}$ 能攻破 $\Pi$（以不可忽略概率伪造）。
2. 构造一个「挑战者」$\mathcal{B}$，把 $\mathcal{A}$ 当子程序调用：$\mathcal{B}$ 把自己的困难问题实例（如一个 ECDLP 实例 $Q = dG$）伪装成 $\Pi$ 的公钥与签名预言机喂给 $\mathcal{A}$。
3. 若 $\mathcal{A}$ 成功伪造，$\mathcal{B}$ 从伪造中**提取出困难问题的解**——于是 $\mathcal{A}$ 的存在 ⟹ $P$ 可解。
4. 但 $P$ 假设不可解——矛盾。所以 $\mathcal{A}$ 不存在，$\Pi$ 安全。

**「$\mathcal{B}$ 模拟签名预言机」是证明的核心难点**：$\mathcal{B}$ 不知道私钥，却要给 $\mathcal{A}$ 提供合法签名——它必须用「随机预言模型」或特殊代数技巧做到这一点。<span class="marginnote">规约是密码学证明的通用语言：<strong>「攻击者成功 ⟹ 我能解困难问题」</strong>。它把「方案安全」归约到「假设成立」。这也解释了为什么假设（分解难、DLP 难）是公钥密码的命脉——证明没有假设就无从谈起。</span>

## 4 公式解析：规约的不等式

$$
\Pr[\mathcal{A} \text{ 伪造成功}] \le \Pr[\mathcal{B} \text{ 解出 } P] \le \mathsf{negl}
$$

三步拆解这条「证明主不等式」：

- **第一步，左边是攻击成功**：$\mathcal{A}$ 伪造出新消息合法签名的概率。EUF-CMA 要求它可忽略。
- **第二步，中间是规约**：$\mathcal{B}$ 用 $\mathcal{A}$ 的伪造提取困难问题解。$\mathcal{A}$ 成功 ⟹ $\mathcal{B}$ 成功，所以「$\mathcal{A}$ 成功概率 ≤ $\mathcal{B}$ 成功概率」。
- **第三步，右边是假设**：困难问题 $P$ 被解出的概率可忽略（这是假设）。于是左边 ≤ 可忽略——$\mathcal{A}$ 的伪造概率可忽略，方案安全。

## 5 从证明到实践：安全模型的意义

EUF-CMA 不只是教科书概念，它直接指导工程：

- **填充方案的选择**：RSA-PSS、OAEP 因为有「随机预言模型下的 EUF-CMA 证明」才被信任；裸 RSA 签名没有。
- **哈希要求**：签名方案证明里假设哈希抗碰撞——所以哈希选型（SHA-256）是签名安全的一部分。
- **随机数要求**：DSA/ECDSA 的证明要求 $k$ 随机；确定性 $k$（RFC 6979）在证明里等价（把 $k$ 当作私钥派生的伪随机数）。
- **协议的组合**：TLS 用签名的 EUF-CMA 保证「服务器身份不可冒充」——握手安全的前提。

**一句话**：EUF-CMA 是「签名安全」的验收标准——没有这个模型，方案就停留在「看起来安全」的层面。<span class="marginnote">一个现实的提醒：<strong>EUF-CMA 安全不等于「实际不可能被攻击」</strong>——证明假设了随机预言模型、理想哈希、正确的实现。现实攻击（侧信道、RNG 缺陷、实现 bug）都在模型之外。所以「可证明安全」是「必要不充分」：没有证明一定不安全，有证明也可能在工程上翻车。</span>

## 6 小结

- **EUF-CMA**：攻击者有签名预言机 + 公钥，不能为「未签名过的新消息」伪造合法签名。
- **EUF** 是最宽松的成功标准，所以是最强的保证；**CMA** 给攻击者最大能力。
- **规约证明**：攻击者成功 ⟹ 可解困难问题 ⟹ 与假设矛盾 ⟹ 方案安全。
- 证明主不等式：$\Pr[\text{伪造}] \le \Pr[\text{解困难问题}] \le \mathsf{negl}$。
- 从证明到工程：填充、哈希、随机数、协议组合——安全模型指导一切签名实践。
