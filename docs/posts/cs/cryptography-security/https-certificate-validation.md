## 为什么从 HTTPS 开始

HTTPS（HTTP over TLS）是互联网上最广泛的安全应用——每一次网购、登录、银行操作都建立在它之上。它把 HTTP 的请求-响应放入 TLS 记录层加密传输，并在握手时完成身份认证。这一节把前几篇的 TLS 知识组装成一个完整的 HTTPS 连接：从 URL 输入到页面加载，浏览器到底做了什么证书校验。理解 HTTPS 的完整链路，等于理解「一把地址栏的小锁背后有多少道防线」。<span class="marginnote">一个澄清：HTTPS 不是新协议，而是「HTTP 跑在 TLS 之上」——<strong>HTTP 语义完全不变，只是传输层换成 TLS（默认 443 端口）</strong>。URL 从 `http://` 变 `https://`，请求-响应照旧，但底层有了加密与认证。</span>

## 1 HTTPS 连接：从握手到传输

一次完整的 HTTPS 请求（简化）：

1. **DNS 解析**：把域名解析成 IP。
2. **TCP 握手**：三次握手建立连接（1-RTT）。
3. **TLS 握手**：协商版本与套件、认证服务器、协商密钥（1-RTT）。
4. **HTTP 请求**：浏览器用会话密钥加密发送 HTTP 请求（TLS 记录层）。
5. **HTTP 响应**：服务器加密返回响应。
6. **连接管理**：长连接复用 TLS 会话（会话恢复 0-RTT）。

**浏览器在 TLS 握手期间做证书校验**——如果证书不合法，浏览器在步骤 3 就拦截，显示「连接不安全」警告，绝不发送任何应用数据。**证书校验是 HTTPS 的第一道、也是最关键的门禁**。<span class="marginnote">一个安全铁律：<strong>证书校验失败时，浏览器绝不「继续但降级」</strong>——直接中止连接。这正是 HTTPS 比「加密的 HTTP」强的核心：它把「跟谁说话」变成硬性校验，而不是可选提示。</span>

**辨析｜易错点：** HTTPS 的「延迟」常被归咎于「加密开销」，其实主要来自多出的网络往返：DNS + TCP（1-RTT）+ TLS 握手（1-RTT）比明文 HTTP 多一次 TLS 往返，再叠加证书链下载、OCSP 查询。现代优化（HTTP/2 多路复用、TLS 1.3 0-RTT、会话恢复）正是为了把这些往返压下去——**安全与性能的权衡，本质是「多几次往返」与「少几次被攻击」的权衡**。

## 2 证书校验的四步：链、期、域、吊销

浏览器校验服务器证书，执行四个检查：

**① 信任链（Chain）**：从服务器证书向上，逐级验签直到预装的根 CA——中间任何一级签名不匹配，链断裂。

**② 有效期（Validity）**：当前时间在证书的 `notBefore`–`notAfter` 之间（并考虑少量时钟偏差）。

**③ 域名（Domain）**：服务器证书的 **SAN（Subject Alternative Name）** 包含用户访问的域名——防止 A 域的证书被用于 B 域。

**④ 吊销（Revocation）**：用 OCSP/CRL 检查证书是否已被吊销（浏览器的策略有所取舍）。

**只有四项全部通过，浏览器才显示绿色锁**。任何一项失败都会触发「证书错误」页面。<span class="marginnote">域名校验是「钓鱼防护」的关键：<strong>攻击者可以申请一张「长得像」的证书（如 `example.com.evil.net`），但无法为 `example.com` 拿到合法证书</strong>——除非 CA 审核疏漏或被攻破。这就是证书校验防钓鱼的机制所在。</span>

用「访问 `https://www.example.com` 时证书被换」的三种场景，把「链、期、域、吊销」各抓一次：

| 攻击者伪造的方式 | 被哪一步拦截 | 为什么拦得住 |
| --- | --- | --- |
| 自签一张「www.example.com」证书 | 信任链 | 不指向任何预装根 CA |
| 给他人合法证书改名再用 | 信任链 + 域 | 证书被签发给别人，验签失败 |
| 给「www.example.com」申请一张合法证书 | 无法伪造 | 攻击者不是域名所有者，CA 不签发 |

**关键认知**：前两种伪造都被「信任链 + 域名」双重拦截——攻击者要么伪造不了签名（链断），要么拿不到目标域名的合法证书（域不匹配）。这正是证书校验能防住绝大多数中间人的数学基础。

## 3 证书错误与用户决策

浏览器遇到证书错误时的典型情况：

**自签证书**：证书不指向任何预装根——常见于内网、开发环境。用户看到「您的连接不是私密连接」。
**域名不匹配**：证书是 A 域名的，访问的是 B 域名——常见于共享 IP 配置错误。
**证书过期**：有效期已过——常见于忘记续期。
**信任链断裂**：中间 CA 缺失——服务器配置错误。

**用户的正确反应**：除非**明确知道**为什么（内网自签、测试环境），否则应**中止访问**——忽略证书错误等于把 HTTPS 的认证能力扔掉，让位于中间人攻击。这正是证书校验流程的「最后一公里」在用户端完成。<span class="marginnote">「点击通过证书警告」是安全研究里反复强调的用户风险：<strong>一次「知道是假的但点了继续」，就可能让攻击者的钓鱼证书得逞</strong>。Chrome 从 2018 年起对证书警告使用「全屏拦截」而非「可点击继续」，就是为了减少这种「被教育点击」的行为。</span>

**辨析｜易错点：** 「证书过期」与「证书被吊销」是不同的错误——过期是「时间到了」，吊销是「被提前作废」。浏览器会分别提示，但**两者都意味着「不能信任」**。一个常见的运维误区是「证书快过期了先不管，反正还能用」——错，过期证书在过期瞬间就失效，服务会直接中断，这正是 ACME 自动续期要消灭的场景。

## 4 公式解析：HTTPS 的 URL 语义

$$
\text{https://} \langle \text{host} \rangle [:\text{443}] / \langle \text{path} \rangle
$$

三步拆解这条「HTTPS URL」：

- **第一步，scheme**：`https` 告诉浏览器「用 TLS 连接、默认 443 端口、必须校验证书」。
- **第二步，host**：域名进入证书校验——SAN 必须匹配它。
- **第三步，path**：应用路径——在 TLS 握手完成后，加密地发送给服务器。

**注意**：URL 里的路径、查询参数、Host 头在 HTTP 请求里，都是**加密后**传输的——但**域名本身不加密**（DNS 查询与 TLS SNI 都暴露域名）。这是 HTTPS 的隐私边界：防内容、不防「你在访问哪个站」。为此现代方案用 **ECH（加密的 ClientHello）** 把 SNI 也藏进 ECDHE 公钥里——让「访问了哪个站」都不再可见。

## 5 从 HTTPS 到现代 Web 安全

HTTPS 之上还叠加了一层 Web 安全生态：

- **HSTS**：服务器声明「之后一律 HTTPS」，浏览器记住并拒绝明文 HTTP——防降级。
- **证书透明度（CT）**：所有证书进公共日志——浏览器要求 CT 证据，防恶意签发。
- **自动续期（ACME/Let's Encrypt）**：免费证书 + 自动续期，让 HTTPS 普及到长尾站点。
- **混内容拦截**：HTTPS 页面里的 HTTP 资源会被浏览器拦截——防降级注入。
- **加密 DNS（DoH/DoT）**：把 DNS 查询也加密，让「解析哪个域名」不再被中间人看到——与 ECH 一起补齐 HTTPS 的域名级隐私。

现代 Web 安全 = HTTPS（加密认证）+ HSTS（强制）+ CT（审计）+ 证书自动化（普及）。<span class="marginnote">一个生态观察：<strong>HTTPS 从「付费可选」变成「免费默认」，是 Let's Encrypt 与 ACME 的功劳</strong>——90 天免费证书 + 自动续期，让「证书过期」从普遍现象变成罕见事故。安全的普及，往往靠「降低采用成本」而非「提高安全意识」。</span>

把四层防线按「解决什么问题」归纳成一张表，就能看清 HTTPS 生态的分工：

| 机制 | 解决的问题 | 本质 |
| --- | --- | --- |
| TLS 证书校验 | 跟谁说话 | 认证 + 加密 |
| HSTS | 被降级回明文 HTTP | 强制策略 |
| 证书透明度 CT | CA 恶意/错误签发 | 公开审计 |
| ACME 自动续期 | 证书过期、成本 | 自动化 |

**设计洞察**：这四层恰好对应密码学的「信任、强制、审计、普及」四个维度——每一层都补上了前一层的短板，合起来才是「默认安全的 Web」。

## 6 小结

- **HTTPS** = HTTP over TLS：默认 443、握手后加密传输、证书校验是门禁。
- **证书校验四步**：信任链 → 有效期 → 域名（SAN）→ 吊销——全过才显示绿锁。
- **证书错误**：自签、域不匹配、过期、链断裂——用户应中止而非忽略。
- **四步拦截模型**：信任链防「签名伪造」、有效期防「时间失效」、域名防「跨域冒用」、吊销防「提前作废」。
- **隐私边界**：内容加密、域名可见（DNS/SNI）——HTTPS 防内容不防访问记录。
- 现代生态：HSTS 防降级、CT 审计、ACME 自动化——HTTPS 已成 Web 安全的地基。
- 一句话总结：**地址栏那把锁，背后是「加密 + 认证 + 强制 + 审计 + 自动化」五层协作**——它让「我在跟 example.com 说话」从一句口号变成可验证的事实。
