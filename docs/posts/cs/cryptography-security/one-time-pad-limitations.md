# 一次一密的工程局限与唯密文攻击的意义

<div class="epigraph">

## 为什么从一次一密的局限开始

上一节证明了一次一密在数学上完美无缺。但完美的代价是三个工程噩梦：密钥要和消息一样长、密钥要用一次就丢、密钥要事先安全地送到对方手里。这三个问题合起来，让一次一密在绝大多数现实场景里「理论完美、工程不可用」。本节直面这些局限，并顺带厘清一个常被误读的结论——**一次一密在唯密文攻击下不可破，不代表它在所有攻击模型下都不可破**。攻击模型的升级，正是后面所有密码学对抗的根源。<span class="marginnote">注意「唯密文攻击」只是五种经典攻击模型里最弱的一种。一次一密只对<strong>唯密文攻击</strong>保证完善保密；面对已知明文攻击、选择明文攻击时，它连「一次性」的要求都保护不了。</span>

## 1 三大工程局限：长度、一次性、分发

一次一密无法普及，根子在三个环环相扣的约束上：

**密钥与消息等长**：加密 1 MB 文件就要先安全传递 1 MB 密钥。带宽翻倍、存储翻倍，在无线电、电话、互联网时代都无法接受。用数字算一算就更直观：要加密一份 10 MB 的软件安装包，先要安全地传递 10 MB 密钥；一条 1 Gbps 的加密链路，要求密钥流生成速率也是 1 Gbps——这意味着「密钥传送」本身就得占用一整条同等带宽的安全信道。<span class="marginnote">等长约束可以用吞吐量来量化：设链路速率为 $R$，则密钥供给速率必须至少为 $R$。没有任何一台密钥分发服务器能长期、实时地为全网所有会话供密钥。</span>

**密钥严格一次性**：密钥不能复用，否则 $C_1 \oplus C_2 = M_1 \oplus M_2$ 立即泄露两条明文的差异（上一节的 Venona 案例）。这意味着通信双方要持续不断生成「永不重复」的随机密钥，同步成本极高。密钥本一旦被部分泄露或复用，全部历史通信都可能被连坐。

**密钥分发（key distribution）**：密钥必须**先于**通信、通过安全信道送达。可问题是：如果已经有一条安全信道能送密钥，为什么不能用它直接送消息？这个「先有鸡还是先有蛋」的困境，直到公钥密码出现才被真正绕开。<span class="marginnote">密钥分发问题是密码学的原问题：对称密码的一切麻烦都源于「双方必须先共享一个秘密」。Diffie 与 Hellman 在 1976 年解决的就是这个问题，见第六篇《Diffie-Hellman 密钥交换协议》。</span>

三个局限不是孤立的，而是互为因果：正因为密钥要等长且一次性，才必须持续不断地安全运送——运送又恰恰是最难保证的环节。

## 2 密钥分发的「鸡生蛋」困境

把「分发」单独拎出来，因为它是最反直觉的一环。设想 Alice 要给 Bob 发一份绝密文件：

1. 若已有安全信道能运送密钥，为何不直接用这条信道送文件本体？
2. 若没有安全信道，那么送密钥的信道也不安全，密钥在途中就可能被窃取。
3. 于是陷入循环：**保密通信的前提是已经存在保密通信**。

破解这个循环有两条路。一是**物理护送**：二战间谍把密钥印在丝巾、歌词、微缩胶片上，靠人肉携带过境——代价高、慢、不可扩展。二是**让「交换」本身不需要保密信道**：这正是公钥密码（Diffie-Hellman、RSA）的核心贡献，也是它被称为「公钥革命」的原因。

**重点：密钥分发问题的存在，是公钥密码登上历史舞台的根本动机。** 没有一次一密的局限，就没有对公钥密码的迫切需求。

## 3 唯密文攻击：一次一密真正防御的敌人

为什么香农的证明只谈唯密文攻击？因为在香农 1949 年的模型里，攻击者 Eve 的「武器库」只有一样东西：**截获的密文**。她看不到明文-密文对，不能主动选择要加密的消息，只能被动监听。这个攻击模型叫**唯密文攻击（ciphertext-only attack）**，是最弱、也最符合「被动窃听」直觉的模型。

香农证明的准确表述是：**在唯密文攻击下，一次一密是完善保密的**。这句话经常被简化成「一次一密不可破」，但省略了前提。一旦攻击模型升级，一次一密的表现就完全不同——这正是下一节要展开的。<span class="marginnote">五种经典攻击模型按攻击者能力从弱到强排列：唯密文 < 已知明文 < 选择明文 < 选择密文 < 自适应变体。现代密码体制要求在最强者下安全；一次一密只在最弱者下安全。</span>

| 攻击模型 | 攻击者知道 | 一次一密的表现 |
| --- | --- | --- |
| 唯密文 | 仅截获密文 | 完善保密，不可破 |
| 已知明文 | 若干明文-密文对 | 密钥可被直接还原 |
| 选择明文 | 可主动指定明文并得到密文 | 密钥立即暴露 |
| 选择密文 | 可主动指定密文并得到明文 | 密钥立即暴露 |

这张表说明一个关键事实：**完善保密不是「绝对不可破」，而是「只在特定前提下的不可破」。** 前提一破，一次一密毫无抵抗力。

## 4 已知明文攻击：一次一密也守不住

设想一个被监听、但攻击者已经知道一段明文-密文对 $(m_0, c_0)$ 的场景——比如消息是固定格式的报文头，Eve 猜得到。那么：

$$
K = m_0 \oplus c_0
$$

**一个明文-密文对就把密钥完全还原了**。这不是攻击者的「破解」，而是数学上的必然：异或是可逆的，已知两个量就能解出第三个。一旦密钥被还原，且 Eve 知道该密钥被重用的范围，之前和之后用同一密钥加密的所有消息全部沦陷。

这在工程上意味着：**通信双方哪怕只泄露一个「明文-密文对」（例如一份被公开的旧报文头），整个密钥流的历史与未来都完了。** 相比之下，现代分组密码的「密钥泄露」通常只影响单次会话——这背后是「混淆与扩散」的设计哲学，见第三篇《分组密码》。

## 5 公式解析：C₁ ⊕ C₂ = M₁ ⊕ M₂ 泄露了什么

密钥复用为什么如此致命？把两条用同一密钥 $K$ 加密的密文相异或：

$$
C_1 \oplus C_2 = (M_1 \oplus K) \oplus (M_2 \oplus K) = M_1 \oplus M_2
$$

逐项拆解这条式子：

- **第一步，看异或的自反性**：$K \oplus K = 0$，密钥在异或相消中彻底消失，剩下的只有 $M_1 \oplus M_2$。
- **第二步，看剩余量的意义**：$M_1 \oplus M_2$ 不再是密文，而是两条明文的**差异掩码**。若两条明文是自然语言，这个掩码会暴露出明显的字母分布规律，配合语言统计即可还原明文。
- **第三步，看攻击的代价**：攻击者不需要知道密钥，只需要拿到两段用同一密钥加密的密文——这正是 Venona 计划（美国破译苏联一次性密钥本复用）的实际攻击路径。<span class="marginnote">Venona 计划在 1943—1980 年间破译了数千份苏联外交电报，根因正是密钥本被局部复用。它证明了「理论完美」的密码在工程失误面前不堪一击。</span>

**重点：密钥复用是密码体制的「结构事故」，再强的算法也救不回来。** 一次一密的安全完全押在「密钥绝对保密且绝不泄露」上。它不提供任何「即使泄露一点、损失也有限」的韧性——密钥是唯一的防线，防线一破，全盘皆输。<span class="marginnote">对比现代密码的「密钥泄露有分级损失」设计：AES 单密钥泄露只影响该会话；一次一密密钥泄露影响该密钥覆盖的<strong>全部</strong>通信。完美安全的设计没有冗余，也因此没有韧性。</span>

## 6 从「一次一密」到「密钥流生成器」：妥协的开始

一次一密的三个局限指向同一条出路：**能不能用很短的种子，派生出看起来很随机的长密钥流？** 如果派生出来的密钥流足够接近随机、且绝不重复，那么用它的密码体制就「计算上接近」一次一密——但不再是无条件安全，因为密钥流由短种子决定，理论上存在有限算力可以穷举的弱点。

这个思路就是流密码的雏形：**密钥流生成器（keystream generator）** 用短密钥播种，持续产出伪随机比特流，再与明文异或。<span class="marginnote">严格说，伪随机密钥流让体制退化为<strong>计算安全</strong>：攻击者若能区分「伪随机流」与「真随机流」，就攻破了体制；若伪随机生成器足够好，攻击者就和无条件安全时一样无能为力。退化与否取决于生成器的质量。</span> 我们将在第四篇《流密码》系统学习这套工程妥协。

| 特性 | 一次一密 | 流密码（RC4/ChaCha20） |
| --- | --- | --- |
| 密钥流来源 | 真随机、与消息等长 | 短种子伪随机派生 |
| 安全性 | 无条件安全 | 计算安全 |
| 密钥管理 | 等长、一次性、难分发 | 短密钥、可复用会话 |
| 工程可行性 | 极低 | 高 |

## 7 工程上的「伪一次一密」：哪些系统真的在用

尽管一次一密不能普及，它仍然在一些**极端安全场景**里服役，因为它们能承担代价：

- **政府热线**：美俄元首间的「红色电话」历史上用过一次性密钥本，密钥由特使手提箱物理运送。
- **卫星与深空通信**：信道窄、消息短，逐条会话密钥可以近似「一次一密」。
- **量子密钥分发（QKD）的落地形态**：QKD 协商出的随机密钥流短、且一次性，恰好与一次一密互补。

这些场景的共同点：**消息量小、带宽不是瓶颈、物理手段可以安全运密钥**。反过来，只要其中一个条件不满足——比如普通互联网通信——一次一密就退场。

## 8 小结

- 一次一密的三大工程局限：**密钥与消息等长、密钥一次性、密钥分发难**。
- **密钥分发困境**是公钥密码诞生的根本动机：保密通信的前提不能是「已有保密通信」。
- 完善保密只针对**唯密文攻击**；攻击模型一旦升级（如已知明文），密钥可被直接解出。
- 已知明文攻击下 $K = m_0 \oplus c_0$，密钥完全暴露——完美设计无冗余、无韧性。
- 密钥复用导致 $C_1 \oplus C_2 = M_1 \oplus M_2$，明文差异直接泄露，Venona 是真实战例。
- 出路是**伪随机密钥流生成器**：用短种子模拟一次一密，从无条件安全降级为计算安全。
- 一次一密仍活在政府热线、卫星通信、QKD 等「能承担代价」的极端场景。
