## 为什么从 ECDSA 开始

ECDSA（Elliptic Curve Digital Signature Algorithm）是 DSA 在椭圆曲线群上的移植：把「模 $p$ 子群」换成「椭圆曲线点群」，把「$g^k$」换成「$kG$」。它继承了 DSA 的全部结构，却因为 ECDLP 没有亚指数攻击，密钥从 3072 位缩到 256 位。ECDSA 是比特币/以太坊交易签名、TLS 证书签名、现代 HTTPS 的事实标准。这一节把它与 DSA 逐行对照，并点出 ECDSA 独有的实现陷阱。<span class="marginnote">一个「移植的胜利」：<strong>DSA 与 ECDSA 的数学骨架完全相同，只是「群」换了</strong>——从「$\mathbb{Z}_p^*$ 的 $q$ 阶子群」换成「阶 $q$ 的椭圆曲线群」。读懂 DSA 就能读懂 ECDSA，这就是「群论抽象」的工程红利。</span>

## 1 从 DSA 到 ECDSA：逐行对照

**公共参数**：椭圆曲线 $E$、基点 $G$（阶为 $q$）。私钥 $d$，公钥 $Q = dG$。

**签名**（对哈希 $z = H(m)$ 的 $q$ 位截断）：

| DSA | ECDSA |
| --- | --- |
| $r = (g^k \bmod p) \bmod q$ | $r = (kG)_x \bmod q$（$kG$ 点的 $x$ 坐标取模 $q$） |
| $s = k^{-1}(z + xr) \bmod q$ | $s = k^{-1}(z + dr) \bmod q$ |
| 签名 $(r, s)$ | 签名 $(r, s)$ |

**验证**：

$$
w = s^{-1}, \quad u_1 = zw, \quad u_2 = rw, \quad \text{点 } X = u_1 G + u_2 Q, \quad \text{接受当且仅当 } X_x \bmod q = r
$$

结构完全平行：DSA 的「两次幂」变成 ECDSA 的「标量乘法 + 点加」；验证方程从 $g^{u_1}y^{u_2}$ 变成点 $u_1G + u_2Q$。<span class="marginnote">验证的几何直觉：<strong>验证者重新计算「承诺点」$X = u_1 G + u_2 Q$，检查它的 $x$ 坐标是否等于签名里的 $r$</strong>。$r$ 是「$kG$ 的 x 坐标」，而 $X$ 恰好就是 $kG$（当签名合法时）——验证就是「重走承诺」。</span>

一个容易忽略的细节是「$z$ 是哈希的 $q$ 位截断」：如果直接用完整哈希而哈希输出（如 SHA-256 的 256 位）超过 $q$（如 P-256 的 256 位刚好相等，但 secp256k1 的 $q$ 略小于 $2^{256}$），就需要左截断。截断的规则必须**两端一致**，否则签名与验证在 $z$ 上产生分歧，合法的签名会被拒绝——这看似微小，却是「正确实现 vs 细节翻车」的分水岭。

## 2 公式解析：ECDSA 验证的闭环

$$
X = u_1 G + u_2 Q, \qquad X_x \equiv r \pmod q, \qquad u_1 = zs^{-1}, \; u_2 = rs^{-1}
$$

三步拆解这条「点群验证方程」：

- **第一步，解开 $s$**：$w = s^{-1}$ 抵消 $k^{-1}$；$u_1 = z/s$，$u_2 = r/s$。
- **第二步，点运算合并**：$X = (z/s)G + (r/s)Q = (z/s)G + (rd/s)G = ((z + rd)/s)G$。而 $s = (z + rd)/k$，所以 $X = kG$。
- **第三步，比对承诺**：$X = kG$ 的 $x$ 坐标正是签名时的 $r$。$X_x \bmod q = r$ ⟺ 签名合法。

**辨析｜易错点：** 验证方程里的 $Q$ 是签名者的**公钥**，不是验证者自己的密钥——验证者用「签名者的公钥 + 消息 + 签名」重算承诺。若验证者误用另一个人的公钥，或攻击者替换公钥，验证结果必然错误。所以 ECDSA 验证的安全性依赖「公钥确实属于签名者」——这正是公钥基础设施（第九篇）存在的理由。

## 3 为什么 ECDSA 更好：密钥与性能

ECDSA 相对 DSA/RSA 的三个优势：

- **密钥短**：256 位曲线 ≈ 128 位安全强度，而 DSA/RSA 要 3072 位——证书、签名、交易数据都小 12 倍。
- **验证快**：点乘运算在无专用硬件时也比 3072 位模幂快。
- **生态成熟**：比特币、以太坊、TLS、SSH 全面采用。

**代价**：实现更精细——点的验证、标量乘法的恒定时间、随机数管理，每一处都藏雷。ECDSA 是「数学简单、工程难」的典型。**辨析｜易错点：** 注意「密钥短」不等于「签名过程简单」——签名仍需一次标量乘（$kG$）与一次求逆，验证需两次标量乘与一次点加。密钥与签名小是「数据尺寸」的优势，运算本身并不比 RSA 简单。

把「同安全强度下」的密钥与签名大小并排，就能直观理解「12 倍」的来源：

| 安全强度 | ECDSA 密钥 | RSA/DSA 密钥 | 签名大小 |
| --- | --- | --- | --- |
| 80 位 | 160 位（secp160r1） | 1024 位 | ECDSA 320 位 |
| 112 位 | 224 位 | 2048 位 | ECDSA 448 位 |
| 128 位 | 256 位（P-256） | 3072 位 | ECDSA 512 位 |
| 192 位 | 384 位（P-384） | 7680 位 | ECDSA 768 位 |

对区块链来说这很关键：**每笔交易都要带上签名**，签名从 768 字节（RSA-3072）缩到 64 字节（P-256 ECDSA），交易费与区块空间立刻省下一个数量级。这正是比特币选择 ECDSA 的工程理由。

## 4 ECDSA 的坑：从 k 到 RNG 到侧信道

ECDSA 的实现陷阱比 DSA 更尖锐，几条都是「血泪史」：

- **$k$ 泄露/重用/可预测**：与 DSA 同源，但后果更惨——**区块链签名的 $k$ 泄露 = 钱包私钥被盗**。Sony PS3（2010，固定 $k$）、Android Bitcoin 钱包（2013，RNG 熵不足）都是著名事故。
- **nonce 偏差**：$k$ 的低位有偏差也能被格攻击利用（2013 年），要求 RNG 足够随机或确定性派生。
- **无效点攻击**：验证时若不检查 $Q$ 是否在曲线上，攻击者可提交低阶点让签名验证「偶然通过」。
- **侧信道**：标量乘法若按 $d$ 的比特分支执行，计时/功耗泄露私钥。<span class="marginnote">ECDSA 的「k 敏感度」是签名家族里最苛刻的：<strong>只要 $k$ 有任意可预测的偏差（哪怕几个比特），格攻击就能在收集一定量签名后恢复私钥</strong>。所以 RFC 6979（确定性 $k$）对 ECDSA 不是「推荐」而是「必需」。</span>

**为什么 $k$ 重用会直接泄露私钥**——用一条代数式子就说明白。若两个签名用了同一个 $k$：

$$s_1 = k^{-1}(z_1 + dr), \qquad s_2 = k^{-1}(z_2 + dr)$$

两式相减：$s_1 - s_2 = k^{-1}(z_1 - z_2)$，于是 $k = (z_1 - z_2)/(s_1 - s_2) \bmod q$——**$k$ 被直接算出来**。再把 $k$ 代回任意一式，$d = (sk - z) r^{-1}$ 也直接可得。这就是为什么「同样的 $k$ 签两次」等于「把私钥公之于众」，也是 Sony PS3 2010 年事故的完整数学。

## 5 使用 ECDSA 的现代姿势

现代实践总结成几条铁律：

**用标准曲线**：P-256、secp256k1（比特币）、Curve25519 相关（但 EdDSA 更优）。
**确定性 $k$（RFC 6979）**：从私钥+消息 HMAC 派生，杜绝 RNG 依赖。
**恒定时间实现**：标量乘法用蒙哥马利阶梯或查表+统一公式，防侧信道。
**验证点有效性**：验签前确认 $Q$ 在曲线上、阶为大素数。
**哈希与截断**：$z$ 必须是哈希的 $q$ 位截断，且哈希要抗碰撞。<span class="marginnote">一个选型建议：<strong>新系统优先考虑 EdDSA（Ed25519）而非 ECDSA</strong>——EdDSA 用确定性 $k$、Edwards 曲线、固定基点，从结构上免除了 ECDSA 的多数陷阱。ECDSA 是「必须兼容」时的选择（区块链、老协议），EdDSA 是「新设计」的选择。</span>

用「签名一次小额转账」的玩具数值把 ECDSA 的签名过程走一遍（取小曲线，仅演示结构）：设私钥 $d = 3$，基点阶 $q = 11$，消息哈希截断 $z = 5$，随机 $k = 4$：

1. 计算 $R = kG$，取 $r = x_R \bmod q$——假设 $r = 7$。
2. 计算 $s = k^{-1}(z + dr) \bmod q = 4^{-1}(5 + 3 \times 7) \bmod 11$。$4^{-1} \equiv 3 \pmod{11}$（因为 $4 \times 3 = 12 \equiv 1$），于是 $s = 3 \times (5 + 21) \bmod 11 = 3 \times 26 \bmod 11 = 78 \bmod 11 = 1$。
3. 签名 $(r, s) = (7, 1)$ 随交易广播。

验证者用 $Q = dG$ 重算 $X = zs^{-1}G + rs^{-1}Q$，若 $X$ 的 $x$ 坐标 $\bmod q = 7 = r$ 则接受。注意 $s$ 依赖 $k$、$z$、$d$ 三者的组合——**任何一个被篡改，$X \ne R$，验证即失败**。真实 ECDSA 只是把这里的 11 换成 256 位的大素数。

## 6 小结

- **ECDSA** = DSA 在椭圆曲线群上的移植：$r = (kG)_x$，$s = k^{-1}(z + dr) \bmod q$。
- **验证**：$X = zs^{-1}G + rs^{-1}Q$，$X_x \bmod q = r$——重走承诺。
- 优势：**密钥 12 倍短、生态成熟**（比特币、TLS、SSH）。
- 代价：实现陷阱多——**$k$ 是命门**（PS3/Android 事故）、无效点、侧信道。
- 铁律：标准曲线 + RFC 6979 确定性 $k$ + 恒定时间 + 点有效性验证；新系统选 EdDSA。
- 一句话总结：**ECDSA 用「更小的群」换来了更小的密钥，也换来了更尖锐的实现陷阱**——数学简单，工程必须小心。
