## 为什么从攻击模型开始

上一节《密码学的基本概念》建立了全套基础词汇：明文、密文、密钥、五元组 $(P, C, K, E, D)$，以及四个安全目标——机密性、完整性、认证、不可否认性。但「保护」这个词永远欠着一个前置问题：**到底在防谁？** 同一个系统，防得住一个只会偷听的学生，未必防得住一个能往信道上写数据的对手；能挡住单次入侵，未必顶得住被反复试探。把「敌人是谁、他能做什么、他拿到了什么」说清楚，就是**攻击模型（attack model）**<span class="marginnote">「攻击模型」与「威胁模型」（threat model）常被混用：威胁模型侧重枚举威胁主体与路径，攻击模型侧重刻画攻击者能力，本系列按 Stallings 的用法把两者放在同一节讨论。</span>。它是整门密码学的坐标系——后面每一个算法、每一套协议，都必须先声明「我在什么攻击模型下是安全的」，这句话不写清楚，安全声明就是空话。

这条思路在「从极限到大模型」的主线上同样成立：大模型的对抗样本、数据投毒、提示注入，本质上都是先定义「攻击者能碰什么、不能碰什么」，再谈防御。安全的第一步永远是**把对手画进图纸里**。

## 1 威胁、攻击与脆弱性：三个别混的术语

要谈攻击，先要立住三个容易混淆的术语。Stallings 在 §1.1 里把它们严格区分开：

**威胁（threat）**：可能造成安全损害的一种潜在可能——一个「如果……就会……」。例如「如果数据库口令哈希泄露，账户就被接管」——这只是一种隐患，尚未发生。
**脆弱性（vulnerability）**：系统中可被威胁利用的薄弱点。口令库明文存储、补丁没打、密码设成 `123456`，都是脆弱性。
**攻击（attack）**：由某个智能的威胁主体（攻击者）对系统发起的真实冲击——威胁与脆弱性在现实中**交汇**的那一瞬间。

**重点：攻击是动词，威胁是名词，脆弱性是形容词。** 用一句话串起来：攻击者利用**脆弱性**，把**威胁**兑现成一次**攻击**。一个没有脆弱性的系统，威胁只是「天气预报」；一旦出现脆弱性，天气预报就随时可能变成「真的下雨」。

**辨析｜易错点：** 新手常把「有威胁」误当「已经出事」。威胁管理（threat modeling）的价值恰恰是在出事之前就把「如果——就会——」的链条枚举出来，这正是后面第五篇《公钥密码的数论基础》里所有安全假设的思考方式：我们从不假设攻击者不会来，只假设他做不到某些事。

## 2 被动攻击：窃听与流量分析

**被动攻击（passive attack）**：攻击者只「听」不「动」——窃听或监视信道上的传输，目的是获取正在传输的信息。它有两个决定性的特征：**不改动任何数据**，因此极难被检测到；应对思路只能是「防」，也就是加密，而不是「察」。<span class="marginnote">为什么被动攻击难检测？因为它不留下任何痕迹：线路上跑的数据和平时一模一样，发送方与接收方都无从察觉有人多读了一份。这就是「防患于未然」在安全里的字面含义。</span>

被动攻击主要有两种：

**泄露消息内容（release of message contents）**：电话录音、电子邮件、文件内容被直接读走。这是普通人理解的「窃听」。
**流量分析（traffic analysis）**：即使消息内容被加密得严严实实，**谁在和谁通信、通信多频繁、消息多长、什么时间**——这些「关于通信的通信」仍可能泄露。攻击者无需读懂内容，光是流量模式就能推断出不少秘密。

**重点：加密保护内容，保护不了元数据。** 你给老板发三封加密邮件，内容滴水不漏，但攻击者看流量就知道「你在给老板发邮件」——这本身就是信息。流量分析是许多真实系统里最难缠的被动攻击，也是后面第十一篇 TLS 讨论「流量指纹」时的伏笔。

## 3 主动攻击：伪装、重放、篡改与拒绝服务

**主动攻击（active attack）**：攻击者真的动手——修改数据流，或制造假数据流。与被动攻击相反，主动攻击会改变数据，因此**原则上是可以被检测的**；应对思路是「察」——用完整性校验与认证去发现篡改，并在被攻破后恢复。

Stallings 把主动攻击分成四类：

**伪装（masquerade）**：一个实体冒充另一个实体。攻击者假装是 Alice 给 Bob 发消息，Bob 以为在和 Alice 说话。
**重放（replay）**：截获一份合法的数据单元，稍后再原样重发一次，以产生未经授权的效果。攻击者不做任何破解，只是「复制粘贴」——被重放的正是货真价实的合法消息。
**消息篡改（modification of messages）**：对消息做部分改动、延迟或重排。比如把「转账 100 元」改成「转账 10000 元」。
**拒绝服务（denial of service, DoS）**：阻止或抑制对系统设施的正常使用。可以针对特定实体（如持续向某人洪泛消息），也可以针对整条网络。<span class="marginnote">拒绝服务攻击威胁的是「可用性」（availability）——它不偷也不改，只是让你用不了。可用性虽不在四个密码学目标之列，却是网络安全的基本要求，第十二篇《网络安全》会专门展开 DoS/DDoS。</span>

**辨析｜易错点：** 被动攻击与主动攻击的分界线不是「是否偷看」，而是「是否改动数据」。偷看是被动，偷看之后把截获的消息**重放**出去，就从被动跨进了主动——同一个攻击者，两阶段动作，分属两个类别。这条边界在密码学里非常重要：一次一密能防住唯密文的被动窃听，却防不住一个会重放的主动对手。

## 4 公式解析：攻击者能力的单调链

如果说被动/主动是「攻击的形态」，那么还有一个更精细的维度：**攻击者手里有什么**。密码学界按「攻击者掌握的材料多少」把攻击模型排成一条经典的能力链：

$$
\text{CO} \;\subset\; \text{KP} \;\subset\; \text{CPA} \;\subset\; \text{CCA}
$$

逐项拆解这条链：

- **第一步，看最弱端 $\text{CO}$（ciphertext-only，唯密文攻击）**：攻击者只拿到了一批密文 $C_1, C_2, \dots, C_n$，除此之外什么也没有。这是最接近现实的模型——攻击者守在信道上，只能被动记录密文。
- **第二步，看 $\text{KP}$（known-plaintext，已知明文攻击）**：攻击者除了密文，还掌握了若干**明文—密文对** $(P_i, C_i)$。这些对是「白捡」的——比如一封公开的例行公事邮件恰好也被加密传输，攻击者两边都拿到了。<span class="marginnote">第二次世界大战里布莱切利园破译 Enigma，靠的正是「已知明文」：德国人每天固定发「天气报告」这类内容可预测的明文，盟军拿到密文就能凑出明文—密文对。</span>
**第三步，看 $\text{CPA}$（chosen-plaintext，选择明文攻击）**：攻击者不仅能读，还能**主动挑选明文**，让系统帮他加密、观察对应的密文 $C_i = E_k(P_i)$。攻击者等于获得了一台「免费加密机」。
**第四步，看最强端 $\text{CCA}$（chosen-ciphertext，选择密文攻击）**：攻击者在选择明文的基础上，还能**挑选密文让系统解密**，观察对应的明文。攻击者又获得了一台「免费解密机」。这几乎是密码学家能想象的最强对手——除了不知道密钥，他什么都能问。

**为什么「子集」箭头成立？** 这条链的含义是：一个 $\text{CCA}$ 攻击者**天然具备** $\text{CO}$、$\text{KP}$、$\text{CPA}$ 攻击者的一切能力——他可以选择性地把问题退化成更弱的模型。因此反过来成立一个贯穿全书的重要结论：

**若一个密码方案在更强的模型（如 $\text{CCA}$）下安全，则它在所有更弱的模型下也自动安全。** 反之则不然——在 $\text{CO}$ 下安全、在 $\text{KP}$ 下一击即溃的方案比比皆是（古典密码就是典型，下一节就会看到）。所以现代密码学总是把安全声明尽量做在**最强**的模型上，一次到位的证明，自动覆盖所有弱模型。

## 5 攻击模型如何决定安全设计

有了攻击模型这把尺子，安全设计就有了取舍的依据。把前面两节的分类并起来，正好对应四个安全目标：

| 攻击 | 类别 | 主要威胁目标 | 主力防御工具 |
| --- | --- | --- | --- |
| 泄露消息内容 | 被动 | 机密性 | 加密 |
| 流量分析 | 被动 | 机密性（元数据） | 填充、流量整形 |
| 伪装 / 重放 / 篡改 | 主动 | 完整性、认证 | 消息认证码、数字签名 |
| 拒绝服务 | 主动 | 可用性 | 网络层过滤、限流 |

这张表与《密码学的基本概念》中的四目标表是同一条线索的两面：**威胁按形态分被动/主动，防御按目标分机密/完整/认证/可用**。真实系统的安全工程，就是「枚举攻击模型 → 映射到目标 → 选择工具」的反复循环，这被称为**威胁建模（threat modeling）**，也是「纵深防御」的第一步——不止防一种攻击，而是让每一层防线各自面对一类威胁。

用一小段 Python 演示「被动截获 → 主动重放」的跨越。这里攻击者不解密、不破解，只是把偷听到的合法凭证原样再发一次：

```python
# 被动截获：Eve 在信道上记下 Alice 的合法请求
request = sniff_request()               # 窃听，不改动任何数据
token = request.headers["Authorization"]  # "Bearer <Alice 的合法令牌>"

# 主动重放：原样再发一次，不解密、不伪造、不破解
def replay():
    forged = build_request(headers={"Authorization": token})
    send(forged)                        # 服务器验证签名通过，照常执行
```

这段代码的讽刺之处在于：Eve 从头到尾**没有破解任何东西**——token 是合法的，验证逻辑是对的，问题只出在服务器没有检查「这条凭证是不是太旧了」。这正是重放攻击的本质：**合法消息被复用，就变成了攻击**。防重放的经典手段是时间戳新鲜度、随机数与序列号，我们会在第十篇《认证协议》系统处理。<span class="marginnote">真实系统中的重放攻击远比这复杂：TLS 用随机 nonce 防止握手重放，OAuth 用一次性 code，Kerberos 用时间戳窗口。共同点都是在凭证里绑定「只能用一次或只能用于特定时刻」的信息。</span>

## 6 小结

- 三个术语要分清：**威胁**是潜在隐患，**脆弱性**是可被利用的薄弱点，**攻击**是威胁被兑现。
- **被动攻击**只窃听不改动数据：**泄露消息内容**与**流量分析**；极难检测，只能靠加密「防」。
- **主动攻击**会修改或制造数据流：**伪装、重放、消息篡改、拒绝服务**；可被检测，靠认证与完整性校验「察」。
- 攻击者能力按手中材料排成单调链 **$\text{CO} \subset \text{KP} \subset \text{CPA} \subset \text{CCA}$**：在强模型下安全，自动覆盖所有弱模型。
- 攻击形态 × 安全目标共同决定防御工具的选择，这正是**威胁建模**的日常工作。

在下一节，我们将回答一个让所有密码设计者夜不能寐的问题：**假设攻击者连我们的算法都一清二楚，系统还安全吗？** 这正是科克霍夫原则（Kerckhoffs's Principle）的由来。
