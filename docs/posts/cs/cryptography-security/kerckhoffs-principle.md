## 为什么从科克霍夫原则开始

上一节我们看清了攻击者：他可能被动窃听，也可能主动重放、篡改。但所有这些攻击模型都默认了一个更基本的假设——**攻击者知道我们用的算法**。为什么敢这么假设？为什么不把算法藏起来，让敌人连用什么密码都不知道？

直觉上，「藏算法」似乎更安全：敌人不知道规则，破解无从下手。可密码学的全部现代史证明：**这条直觉是错的。** 今天我们把「算法公开、密钥保密」当作天经地义的默认值，它的思想源头就是 1883 年一位荷兰密码学家提出的**科克霍夫原则（Kerckhoffs's Principle）**。这一节讲清楚它为什么正确、它把安全的重心压到了哪，以及由此引出的一个贯穿全书的核心命题：**安全性的全部重量，都压在密钥上。**

这与《攻击模型与威胁分类》直接衔接——攻击者知道系统，是我们在 §4 那条能力链里默认的起点；而这条默认，正是科克霍夫原则给的。

## 1 1883 年的一篇军事论文：科克霍夫斯的六条准则

奥古斯特 · 科克霍夫（1835—1903）是荷兰裔语言学家，长期在巴黎高等商学院执教，兼修密码学。<span class="marginnote">他更广为人知的身份其实是世界语运动的先驱之一——科克霍夫同时活跃在「通用语言」与「保密语言」两个方向上，算是那个时代的独特巧合。</span> 1883 年，他在《军事科学杂志》（*Journal des sciences militaires*）发表了两期长文《军事密码学》，针对军用密码体系提出六条设计准则。后世常提的「科克霍夫原则」，只是其中第二条：

1. 系统在实用上（若非数学上）不可破；
2. **系统不应要求保密，即便落入敌人手中也不应带来损失**；
3. 密钥应易于沟通与记忆；
4. 系统应易于操作与更换；
5. 系统应适用于各种通信场合；
6. 系统应易用，不要求使用者背下一长串规则。

六条里有五条在谈「好用」——战场上的密码员不能背太重的规则，密钥要能随时换。真正影响深远的，是那条看似不起眼的第二条：**把「保密」从算法身上剥离，全部押给密钥。**

**重点：科克霍夫从未说过「算法必须公开」，他说的是「算法不应是安全的唯一依托」。** 军事密码更注重「密钥可换」：前线战败、密码本被缴获，只要密钥能换，系统还能继续用；若安全全靠算法保密，算法一旦泄露，整个系统就永久报废了。

## 2 原则的精确表述：安全性只依赖密钥

把科克霍夫的话翻译成现代密码学的语言：

**科克霍夫原则（Kerckhoffs's Principle）：一个密码系统的安全性，必须只依赖于密钥的保密，而不得依赖于算法的保密。**

换句话说：把算法手册、伪代码、实现源码全部交给攻击者，系统依然必须是安全的——只要他不知道密钥。<span class="marginnote">香农在 1949 年的奠基论文《保密系统的通信理论》中把这一点收编为一句常被引用的格言：「敌人知道系统」（The enemy knows the system）。香农的意思是：设计时必须假设对手完全掌握我们的密码体制，唯一的未知量只有密钥。</span>

这条原则之所以成为现代密码学的第一公理，有三个层层递进的理由：

- **密钥是唯一可「管理」的秘密**：算法一旦公开就永远公开，收不回来；密钥却可以定期更换、按需分发、随时销毁。把安全压在唯一能旋转的旋钮上，安全才是一个可操作的过程。
- **公开算法经得起公众检验**：越多人审视，弱点暴露得越快。闭门设计的算法往往在多年后才被发现是纸糊的；公开的算法则在全世界攻击者的锤打下越敲越硬。
- **可替换性（replaceability）**：算法泄密不等于系统崩溃——换一个算法（或换一种密钥用法）即可，损失是局部的。

**辨析｜易错点：** 科克霍夫原则**不是**「算法公开就一定安全」，而是「算法必须经得起公开」。历史上有大量系统因为信奉「敌人不知道我们怎么加密」而垮台——这种把安全寄托在隐瞒实现细节上的做法，有个专门的贬称：**隐蔽式安全（security by obscurity）**。隐蔽式安全不是不能用（它偶尔能拖延攻击者），但**绝不能作为安全性的依据**——安全必须建立在可验证的基础上，而不是建立在「没人想到」上。

## 3 为什么公开算法反而更安全

反直觉之处就在这里：把底牌摊开，怎么会更安全？答案藏在**验证**与**博弈**两个词里。

先看验证。一个密码算法是好是坏，靠自吹没有用，要靠全世界最聪明的一批攻击者持续挑战。公开算法等于把「质量检验」外包给全球社区：AES 是公开征集、公开评审、公开攻击多年后才成为标准的；RSA 的数学假设在论文里躺了四十多年，至今未被攻破。相比之下，专有算法往往只经过内部审查，出错概率被成倍放大。

再看博弈。假设一个专有算法真的比公开算法安全——攻击者不知道算法，确实多了一层障碍。但这层障碍有多大？攻击者一旦通过反汇编、侧信道、内部泄密拿到算法，这层障碍就**一次性永久消失**；而系统设计者若把安全押在这层障碍上，等于把宝押在「敌人永远拿不到算法」这一件不可控的事上。**安全工程讲究「不要把宝押在不可控的事情上」**——算法保密恰恰是世界上最不可控的事。

**重点：公开设计把「保密面」收敛成一条线。** 隐蔽式安全面前，攻击者要猜的东西有一大团：算法、参数、密钥、实现细节……任何一环漏了就全盘皆输。科克霍夫原则把保密面压缩到只剩密钥一项，其余全部公开。攻击面变小，防御才可能变强。这正是「从极限到大模型」里反复出现的同一种思维：**把复杂度从不可验证的地方，挪到可验证的地方。**

## 4 公式解析：密钥空间与暴力搜索的工作量

把「安全性只依赖密钥」量化，第一个问题就是：**密钥到底要多大，才扛得住最笨的穷举攻击？** 设密钥是 $k$ 比特的二进制串，密钥空间的大小是

$$
|K| = 2^k
$$

攻击者不知道密钥，只能逐个试。若密钥均匀随机选取，攻击者按任意顺序试探，找到正确密钥时已试的次数平均为

$$
\mathbb{E}[\text{试验次数}] = \frac{|K|}{2} = 2^{k-1}
$$

逐项拆解：

- **第一步，看 $|K| = 2^k$**：$k$ 比特密钥能表示 $2^k$ 种不同的取值。这是「密钥长度决定安全上界」的根源——密钥每增加 1 比特，攻击者要穷举的空间就翻一倍。
- **第二步，看期望值 $\frac{|K|}{2}$**：正确的密钥在 $2^k$ 个候选中位置是随机的，平均落在正中间。注意是**平均**，个别运气好的攻击者可能第一次就试中，但平均工作量是指数级的。<span class="marginnote">对暴力搜索而言，唯一的「指数」变量是比特数 $k$：$2^{40} \approx 10^{12}$ 还可用并行机扫，$2^{64} \approx 1.8\times 10^{19}$ 已超出单机现实，$2^{128} \approx 3.4\times 10^{38}$ 在可预见的物理定律下都不可能穷举。</span>
- **第三步，把科克霍夫原则套进来**：暴力搜索的前提恰恰是「算法公开、只差密钥」——攻击者不需要知道算法内部任何秘密，只要会调用加密函数就能试密钥。若算法本身保密，攻击者连从何试起都不知道，但那不叫「安全」，叫「暂时的迷茫」。
- **第四步，看密钥长度的一票否决权**：一个加密算法无论设计多精巧，只要密钥空间太小，就必被穷举击穿。DES 用 56 比特密钥，$2^{56} \approx 7.2\times 10^{16}$，在 1990 年代末已被专用硬件在几天内扫空——**算法没有错，是密钥不够长**。这就是为什么科克霍夫原则下「密钥」成为整个安全体系的承重墙。

用一小段 Python 把「期望试验次数 $2^{k-1}$」验证一下：在很小的密钥空间上模拟穷举，比较理论均值与模拟均值：

```python
import random

def brute_force_expect(k: int, trials: int = 20000) -> float:
    """在 2^k 的密钥空间上随机放正确密钥，模拟穷举所需试探次数。"""
    n = 2 ** k
    total = 0
    for _ in range(trials):
        secret = random.randrange(n)
        # 按 0..n-1 顺序试探，找到 secret 要试 secret+1 次
        total += secret + 1
    return total / trials

for k in (8, 12, 16):
    sim = brute_force_expect(k)
    theory = 2 ** (k - 1)
    print(f"k={k:2d}  模拟均值 {sim:9.1f}  理论 2^(k-1) = {theory:9.0f}")
```

输出的模拟均值会贴着理论值 $2^{k-1}$ 波动——穷举攻击的工作量不是玄学，是一条可预测的指数曲线。理解这条曲线，就理解了为什么现代密码的密钥长度动辄 128、256 比特：**科克霍夫原则把全部安全性压到密钥上，密钥就必须大得让穷举变成物理上不可能。**

## 5 从「算法保密」到「密钥保密」：现代设计的延伸

科克霍夫原则发表至今一百四十多年，它的精神不仅没过时，反而被现代密码学推到了更激进的位置。

- **开放设计与标准化**：今天的密码算法（AES、SHA-2、RSA、椭圆曲线）全部是公开标准，经过公开评审（NIST 公开征集、全世界密码学家攻击）。这正是科克霍夫原则的现代制度化：**算法公开是标准，不是例外。**
- **公钥密码的极端情形**：在非对称密码里，连「密钥保密」都被推向极限——加密用的**公钥本身就公开**，任何人都能用它加密；安全只靠配套的**私钥**保密。这是科克霍夫原则的下一个台阶：不仅算法公开，连加密密钥都公开，唯一保密的是解密私钥。<span class="marginnote">公钥密码之前我们学的所有体制都要求「加密方和解密方共享同一个秘密密钥」。公钥密码打破了这个前提：密钥分裂成公开的加密钥与保密的解密钥，第五、六篇会完整展开。</span>
- **密码敏捷性（crypto-agility）**：既然算法可能在未来某天被攻破（量子计算对 RSA 的威胁就是眼前例子），现代系统把「算法」做成可随时更换的插槽，密钥与算法分离管理——这正是科克霍夫原则里「可替换性」的工程化，第十六篇《后量子密码》会详细讨论迁移问题。

**辨析｜易错点：** 科克霍夫原则管的是**密码算法**，不是所有安全机制。口令、令牌、生物特征这类「认证秘密」仍然必须保密——原则说的是「算法的保密不构成安全性的依据」，而不是「所有秘密都该公开」。把两者混为一谈，是对科克霍夫最经典的误读。

## 6 小结

- **科克霍夫原则**：密码系统的安全性必须只依赖密钥的保密，不得依赖算法的保密。
- 它在科克霍夫 1883 年六条军用密码准则中只是第二条，核心动机是「密钥可换、算法难换」。
- 香农把同一思想凝练为「**敌人知道系统**」，成为现代密码设计的第一假设。
- 公开设计更安全，因为：可验证、抗泄密、可替换；而隐蔽式安全把宝押在不可控的事情上。
- 量化的承重墙是密钥空间：$|K| = 2^k$，暴力搜索期望 $2^{k-1}$ 次试验——密钥长度一票否决整个体制。
- 现代延伸：算法公开标准化、公钥密码连加密钥都公开、密码敏捷性成为系统刚需。

在下一节，我们将亲手实现第一个真正意义上的密码体制——**单表替换密码**：从凯撒密码到仿射密码再到任意单表替换。别忘了，科克霍夫原则说算法可以公开，那我们就从「公开算法、只藏密钥」的古典密码开始，看看它们扛不扛得住。
