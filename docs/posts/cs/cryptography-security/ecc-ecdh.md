## 为什么从 ECDH 开始

上一节我们建立了椭圆曲线群，这一节把它装进 DH 框架——**ECDH（Elliptic Curve Diffie-Hellman）**：把 DH 的「模乘法群上的指数」换成「椭圆曲线群上的标量乘法」。语法完全平行，但密钥长度从 2048 位缩到 256 位。现代互联网的 TLS 1.3 握手、比特币与以太坊的签名、WhatsApp 的端到端加密，全都站在 ECDH（及其家族）上。理解 ECDH 是理解现代密码基础设施的最后一公里。<span class="marginnote">ECDH 的两个主角曲线：<strong>NIST P-256（美国标准）与 Curve25519（伯恩斯坦设计，TLS 1.3 默认）</strong>。它们都是「256 位基域、阶为大素数」的曲线，但实现哲学不同：P-256 历史悠久，Curve25519 以「恒定时间实现简单、防侧信道」著称。</span>

## 1 ECDH 协议：与 DH 逐行平行

ECDH 与 DH 的流程一一对应，只是把「$g^x \bmod p$」换成「$xP$」（标量乘法）：

**公共参数**：一条椭圆曲线 $E$、基点 $G$（一个生成点，阶为大素数 $n$）。

1. Alice 随机选私钥 $a$（$1 \le a \le n-1$），算公钥 $A = aG$，发给 Bob。
2. Bob 随机选私钥 $b$，算公钥 $B = bG$，发给 Alice。
3. Alice 算共享密钥 $S = aB = a(bG) = abG$。
4. Bob 算共享密钥 $S = bA = b(aG) = abG$。

**关键**：$abG$ 两边相等（标量乘法可交换）；窃听者只有 $A = aG$、$B = bG$，算 $abG$ 需要解 **ECDLP**——不可行。之后双方把 $S$ 的坐标喂给哈希函数，派生出对称加密的会话密钥。

## 2 公式解析：ECDH 的可交换性

$$
S = a(bG) = b(aG) = abG
$$

三步拆解这条「共享密钥公式」：

- **第一步，看 Alice**：$S = aB = a(bG)$。标量乘法满足结合律与交换律，$a(bG) = (ab)G$。
- **第二步，看 Bob**：$S = bA = b(aG) = (ba)G$。$ab = ba$——普通整数乘法可交换。
- **第三步，看安全**：窃听者知道 $G, aG, bG$，但算不出 $abG$（ECDLP）。双方共享同一个「点」，再哈希成对称密钥。

## 3 从 ECDH 到完整密钥协商：KDF 与 HKDF

ECDH 算出的 $abG$ 是一个椭圆曲线点，不能直接当密钥用——因为它的坐标比特可能偏斜、且只有曲线阶的熵。协议要做**密钥派生（KDF）**：

$$
\text{session key} = \text{HKDF}(abG, \text{盐}, \text{上下文})
$$

现代 TLS 用 **HKDF**（HMAC-based KDF）：先用 ECDH 的共享秘密作为「输入密钥材料」，再经「提取-扩展」两阶段派生出多个会话密钥（加密密钥、认证密钥、IV 等）。这个过程保证：即使共享点相同，不同上下文也得到不同密钥。<span class="marginnote">ECDH 只给「共享秘密」，不给「密钥」——<strong>秘密到密钥之间必须经过 KDF</strong>。跳过 KDF 直接用共享点坐标是常见实现错误：坐标有结构偏差、且无法与上下文绑定，可能被相关密钥攻击利用。TLS 1.3 全程用 HKDF 派生，正是为此。</span>

## 4 ECDH 的两种模式与安全性

**静态 ECDH**：双方长期公钥固定，共享密钥长期不变——密钥管理简单，但无前向保密，且长期共享秘密泄露风险大。
**临时 ECDH（ECDHE）**：每次会话生成新的临时密钥对，会话结束即弃——**前向保密**，TLS 1.3 默认。E 代表 ephemeral。

ECDH 的安全性假设是 **ECCDH 假设**（椭圆曲线 CDH）：给定 $G, aG, bG$，算 $abG$ 不可行——它是 ECDLP 的「计算版」。攻击者若解出 $a$（ECDLP），一切沦陷；所以曲线阶必须够大（P-256 与 Curve25519 的阶都约 $2^{255}$，$O(\sqrt{n}) \approx 2^{128}$ 次攻击不可行）。<span class="marginnote">对照记忆：<strong>DH 的难题是「模乘法群 DLP」，ECDH 的难题是「椭圆曲线群 ECDLP」</strong>。两者结构平行，但 ECDLP 无亚指数攻击——这就是 ECDH 用 256 位、DH 要 2048 位的全部原因。</span>

## 5 实现注意：为什么 ECC 实现容易翻车

ECC 的性能与安全高度依赖实现细节，几个反复出事的点：

**侧信道**：标量乘法若按 $k$ 的比特做「跳过加点」，计时会泄露 $k$。**防御**：恒定时间双倍-加（每个位都做双倍+加点，用蒙哥马利阶梯）或统一公式。
**无效曲线攻击**：接收方若不验证对方公钥是否在正确曲线上，攻击者可用低阶点迫使共享密钥退化。**防御**：验证点落在曲线上、验证阶。
**随机数质量**：ECDSA 的 $k$ 若泄露或复用，私钥直接还原（索尼 PS3 事件）。Curve25519 的设计（x-only 坐标、固定基点）从结构上降低了这些风险。<span class="marginnote">为什么 Curve25519 更「工程友好」：它只用 $x$ 坐标（省一半字节）、把基点固定、用蒙哥马利阶梯恒定时间计算、内部就处理了无效曲线——<strong>「简单实现也安全」是它的设计目标</strong>。这代表了 ECC 从「数学正确」到「工程健壮」的演进。</span>

## 6 小结

- **ECDH**：$S = aB = bA = abG$；与 DH 逐行平行，只是把模幂换成标量乘法。
- 公共参数：曲线 + 基点 $G$；私钥 $a$、公钥 $aG$。
- 共享秘密要经 **HKDF/KDF** 派生成会话密钥——「秘密 ≠ 密钥」。
- 模式：**ECDHE**（临时）提供前向保密，TLS 1.3 默认。
- 安全靠 **ECCDH/ECDLP**；实现要防侧信道、无效曲线、随机数泄漏——用 Curve25519 类曲线最省心。
