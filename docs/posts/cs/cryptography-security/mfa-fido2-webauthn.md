## 为什么从 MFA 与 FIDO2 开始

单因子认证注定被某一种攻击击穿——口令被钓鱼、令牌被劫持。**多因子认证（MFA）**把不同种类的因子组合起来，让攻击者必须同时攻破多条独立的防线。而**FIDO2/WebAuthn**把 MFA 推向「无口令」的终极形态：用安全钥（或设备内置的密钥）做基于公钥的认证，从根上消灭钓鱼与撞库。这一节把第十篇的认证知识收束成现代认证的完整图景。<span class="marginnote">MFA 的数学直觉：<strong>若单因子的攻破概率是 $p_1$、$p_2$，且攻击路径独立，则双因子同时被攻破约 $p_1 p_2$</strong>——非线性下降。但「路径独立」是关键：短信验证码与口令都被钓鱼骗走，就不算真独立。这就是为什么「防钓鱼的 FIDO2」比「短信码 MFA」强得多。</span>

## 1 从两步到多因子：概念辨析

先澄清术语：

**两步验证（2-Step）**：两个「同类」步骤（口令 + 安全问题的答案）——因子种类没变，安全性提升有限。
**多因子（MFA）**：至少两个**不同种类**的因子——知识（口令）+ 占有（令牌/手机）+ 固有（生物特征）。**因子种类不同，攻击路径才独立**。

常见的 MFA 组合：

| 组合 | 因子种类 | 抗攻击力 |
| --- | --- | --- |
| 口令 + 安全问题 | 知识 + 知识 | 弱（同类） |
| 口令 + 短信码 | 知识 + 占有 | 中（短信可被 SIM 劫持） |
| 口令 + TOTP 应用 | 知识 + 占有 | 中强（抗 SIM，仍可钓鱼） |
| 口令 + 硬件安全钥 | 知识 + 占有 | 强（抗钓鱼） |
| 硬件安全钥（FIDO2） | 占有 + 生物 | 最强（无口令可钓） |

**核心**：因子种类越多、攻击路径越独立、安全性越高。<span class="marginnote">一个反直觉事实：<strong>「口令 + 短信码」常被钓鱼一锅端</strong>——攻击者同时伪造登录页和短信验证码输入框，用户两个都交出去。所以 MFA 的强弱不看「有几步」，而看「因子是否独立于攻击者的掌控」。FIDO2 的防钓鱼能力来自「密钥绑定域名」——钓鱼网站的挑战根本无法用真域的密钥签名。</span>

## 2 FIDO2/WebAuthn：无口令的公钥认证

**FIDO2** 是 FIDO Alliance 的标准套件，**WebAuthn** 是它的 Web API 部分（W3C 标准）。核心流程用**公钥密码**替代「口令 + 服务器存储的秘密」：

**注册（绑定设备）**：

1. 用户在网站发起注册，网站发一个**挑战**。
2. 设备（安全钥/手机/电脑）生成一对密钥：**私钥留在设备内**，公钥发给网站。
3. 设备用私钥对挑战签名，返回公钥与签名。

**登录（认证）**：

1. 网站发**新挑战**。
2. 设备用私钥对挑战签名，返回签名（并解锁：PIN 或生物特征）。
3. 网站用存的公钥验签——通过即认证成功。

**为什么强**：

**无口令可钓**：认证基于私钥签名，不涉及口令——钓鱼网站拿不到私钥。
**防中间人**：签名绑定**域名（origin）**——钓鱼域的挑战无法用真域的密钥应答。
**防撞库**：没有口令可重用，服务器不存秘密。
**本地生物解锁**：私钥被 PIN/指纹保护——「占有 + 固有」双因子合一。<span class="marginnote">FIDO2 的安全本质：<strong>私钥永远不出设备，服务器只存公钥</strong>——这是「服务器被拖库也无秘密可拖」的极致形态。私钥与域名绑定，让「钓鱼站拿挑战」也签不出合法响应。这正是挑战-响应 + 公钥认证的完美结合。</span>

## 3 公式解析：WebAuthn 的认证签名

$$
\sigma = \text{Sign}_{sk}(c \| \text{origin} \| \text{rpId}), \qquad \text{Verify}_{pk}(c \| \text{origin} \| \text{rpId}, \sigma) = \text{接受}
$$

三步拆解这条「WebAuthn 认证」：

- **第一步，签什么**：设备签名的是「挑战 $c$ + 网站来源 origin + 依赖方标识 rpId」——**挑战防重放、origin/rpId 防钓鱼**。
- **第二步，怎么签**：私钥 $sk$ 在安全硬件内（TPM/安全芯片），用前要 PIN 或生物解锁。
- **第三步，验什么**：网站用存的公钥验签——通过则「持有私钥的人在现场且确实在访问本域」。

## 4 Passkey：从「登录」到「免密」的落地

**Passkey（通行密钥）** 是 FIDO2 的消费级产品化：浏览器/系统把密钥**同步到云**（如 iCloud 钥匙串、Google 密码管理器），用户在所有设备间无缝使用。

- **主因子**：私钥（设备内/云端）。
- **解锁**：本地面容/指纹/PIN。
- **优势**：无口令、跨设备、防钓鱼、服务器零秘密。

**Passkey 的取舍**：云端同步的密钥面临「云账户被攻破」的新风险（密钥在云端可被导出）；纯设备内的密钥则面临「换设备麻烦」。业界在「可同步」与「防导出」之间权衡——这正是 MFA/FIDO2 生态正在激烈演化的前沿。<span class="marginnote">一个冷静的观察：<strong>Passkey 把「口令」换成了「云密钥 + 生物特征」——它消灭了撞库与钓鱼，但把信任移给了平台（苹果/谷歌）</strong>。云密钥被导出 = 另一种「拖库」。认证的未来不是「更聪明的口令」，而是「重新分配信任」——平台责任、硬件保护、用户可迁移性三者之间的平衡。</span>

## 5 现代认证体系的完整图景

把第十篇串成一张图：

**因子层**：知识（口令）、占有（令牌）、固有（生物）——MFA 组合。
**协议层**：挑战-响应（防重放）、加盐慢哈希（口令存储）、AKE（防中间人）。
**标准层**：SCRAM、Kerberos、TLS、WebAuthn——把协议工程化。
**趋势层**：无口令（Passkey/FIDO2）、可迁移凭证、平台信任模型。

**选型建议**：新系统优先 **FIDO2/Passkey**；兼容旧场景保留「口令 + TOTP」；银行等高安全场景加硬件安全钥。认证的终极目标——**让「证明你是谁」既安全又无感**——正在被 FIDO2 一步步实现。<span class="marginnote">一个收束全书的观点：<strong>认证的演进是「秘密」形态的演进</strong>——从「共享秘密」（口令）到「持有秘密」（令牌）到「可证明的秘密」（私钥）。FIDO2 把「秘密」从服务器与网络里彻底移除，只留在用户设备内——这是「秘密最小化」原则在认证领域的极致应用。</span>

## 6 小结

- **MFA**：组合不同种类因子，攻击路径独立、成本非线性叠加——真正的安全来自「种类不同」。
- **FIDO2/WebAuthn**：公钥认证——私钥留设备、服务器只存公钥、签名绑定域名防钓鱼。
- **Passkey**：FIDO2 的云端同步产品化——无口令、跨设备，但信任向平台转移。
- 强于口令/TOTP 之处：**无口令可钓、防中间人、无撞库、服务器零秘密**。
- 趋势：从「更聪明的口令」到「重新分配信任」——无口令是认证的终局方向。
