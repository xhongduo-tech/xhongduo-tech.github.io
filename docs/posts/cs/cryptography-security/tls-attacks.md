## 为什么从 TLS 著名攻击开始

TLS 是史上被攻击最多的协议——这不是它的耻辱，而是它「值得被攻击」的证明。BEAST、POODLE、Heartbleed、降级攻击……这些名字背后是四种完全不同的攻击类型：协议缺陷、实现 bug、侧信道、配置失误。理解这四类攻击，等于掌握「安全协议如何被攻破」的完整分类学，也才能真正读懂 TLS 1.3 为什么那么设计。<span class="marginnote">一个分类框架：<strong>BEAST 打「协议设计」，POODLE 打「降级兼容」，Heartbleed 打「实现 bug」，降级攻击打「协商逻辑」</strong>——四类攻击的修复方式完全不同：改协议、删旧版、修代码、改配置。把它们分清，是安全工程师的基本功。</span>

## 1 BEAST（2011）：CBC 的可预测 IV

**BEAST（Browser Exploit Against SSL/TLS）** 针对 TLS 1.0 的 CBC 模式：

- **漏洞**：TLS 1.0 的 CBC 加密用**可预测的 IV**（部分 IV 由上一块密文推导），攻击者能构造「选择明文攻击」场景，逐块猜出明文。
- **场景**：攻击者用 JavaScript 注入请求、配合网络嗅探，可在 HTTPS 会话里恢复敏感数据（如认证 Cookie）。
- **修复**：TLS 1.1 引入显式随机 IV；TLS 1.3 彻底弃用 CBC，只留 AEAD。

**教训**：CBC 模式的「IV 随机性」在协议实现里被偷工减料——**密码学模式的安全前提（IV 不可预测）必须由协议显式保证**。<span class="marginnote">BEAST 的更深教训：<strong>「实现上的小简化」（IV 用上个密文块）可能摧毁整个模式的安全证明</strong>。TLS 1.0 的 IV 推导方式让 CBC 的 CPA 安全性失效——协议层的细节，就是密码学与工程之间的缝隙。</span>

## 2 POODLE（2014）：强制降级到 SSL 3.0

**POODLE（Padding Oracle On Downgraded Legacy Encryption）** 是「降级 + 填充预言」的组合攻击：

- **漏洞**：攻击者**诱导客户端降级到 SSL 3.0**（通过阻断 TLS 握手消息），而 SSL 3.0 的 CBC 填充校验几乎不检查填充内容——攻击者用「填充预言」逐字节猜出明文。
- **场景**：中间人阻断 TLS 连接，让浏览器回退到 SSL 3.0，然后逐字节解密 Cookie。
- **修复**：**彻底弃用 SSL 3.0**（2014 年 RFC 7568 宣布 SSL 3.0 死亡），浏览器禁用它。

**教训**：**降级兼容是安全协议最危险的敌人**——为了「兼容老系统」保留的旧版本，成了攻击者的后门。<span class="marginnote">POODLE 的「降级」套路被反复使用：攻击者不需要破解新协议，只要让双方退到「能破解的旧协议」。这也是 TLS 1.3 用「降级标记 + 转录签名」把版本协商钉死的根本原因——<strong>不让你降级，才没有 POODLE</strong>。</span>

## 3 Heartbleed（2014）：内存越界读

**Heartbleed** 不是协议漏洞，而是 **OpenSSL 的 TLS 心跳扩展（Heartbeat）实现 bug**：

- **漏洞**：Heartbeat 请求携带「负载长度」，但 OpenSSL 没有检查该长度与真实数据是否匹配——攻击者可越界读取内存，**每次最多 64KB**。
- **后果**：攻击者反复请求，可读取服务器的**私钥、会话密钥、用户凭证**等内存数据——数百万 HTTPS 服务器受影响两年之久。
- **修复**：OpenSSL 补丁（检查长度边界）；TLS 1.3 移除心跳的旧实现。

**教训**：**密码学安全不等于实现安全**——一个内存越界读，能让全部密码学防线归零。安全协议必须有内存安全的实现（Rust、内存检查、模糊测试）。<span class="marginnote">Heartbleed 的影响是深远的：它是「开源基础设施单点风险」的警钟——<strong>全世界一半 HTTPS 服务器用同一份 OpenSSL，一个 bug 就是全球灾难</strong>。它直接推动了内存安全语言（Rust）在系统软件里的采用。</span>

## 4 降级攻击家族：从 SSL 3.0 到更弱套件

降级攻击是一个**家族**，共同目标是「让双方用弱算法」：

- **版本降级**：诱导用 SSL 3.0（POODLE 的铺垫）。
- **套件降级**：诱导用弱密码套件（CBC、RC4、弱 RSA）——**FREAK**（2015）诱导用 512 位出口级 RSA，**Logjam**（2015）诱导用弱 DH。
- **协议混淆**：诱导服务器/客户端理解不同的安全配置。

**现代防御（TLS 1.3）**：

- 密码套件不可协商到弱档（只有 AEAD）。
- 版本协商有降级标记 + 转录签名。
- 弱算法（RC4、SHA-1、CBC、出口级 RSA）全部移除。

**降级攻击的哲学**：攻击者不打「新协议的锁」，而是把「锁」换回旧型号——**安全性必须「向前看」：每个旧版本都是潜在的后门**。<span class="marginnote">Logjam 的细节值得记住：<strong>512 位 DH 是 1990 年代「出口管制」时代的遗留物</strong>——为合规而设的弱算法，几十年后成为攻击后门。这揭示了「为政治合规保留的弱项」最终都会变成安全漏洞。</span>

## 5 公式解析：降级攻击的统一逻辑

$$
\text{攻击者迫使双方协商 } (V_{\text{low}}, \text{suite}_{\text{weak}}) \quad \Rightarrow \quad \text{用已知弱点解密}
$$

三步拆解这条「降级攻击」的通用模式：

- **第一步，阻断**：攻击者阻断高版本的握手消息（TCP 层丢弃或篡改），迫使双方「无法协商到高版本」。
- **第二步，回退**：协议「向下兼容」逻辑让双方回退到旧版本/弱套件——这是协议为兼容性而设的正常路径。
- **第三步，利用**：旧版本的已知弱点（CBC 填充、RC4 偏差、512 位 RSA）被利用，解密流量。

## 6 小结

- **BEAST（2011）**：TLS 1.0 CBC 可预测 IV → 逐块猜明文；修复：显式 IV + 弃用 CBC。
- **POODLE（2014）**：强制降级 SSL 3.0 + 填充预言 → 逐字节解密；修复：SSL 3.0 彻底死亡。
- **Heartbleed（2014）**：OpenSSL 心跳越界读 → 泄露私钥；修复：内存边界检查 + 内存安全语言。
- **降级攻击家族**：版本/套件降级（FREAK、Logjam）→ 诱导弱算法；修复：TLS 1.3 移除弱算法 + 转录签名。
- **总教训**：协议设计、降级兼容、实现安全、配置纪律——四类攻击对应四道防线。
