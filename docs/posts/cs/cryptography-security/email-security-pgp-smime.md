## 为什么从电子邮件安全开始

电子邮件（SMTP）默认**明文传输**——邮件经过的每一台服务器都能读到内容。要保护邮件，需要**端到端加密**：发件人加密、收件人解密，中间的服务器只看到密文。两条标准路线：**PGP**（基于「信任网」）与 **S/MIME**（基于 CA 证书）。它们都回答同一个问题：**怎么把「加密 + 签名」安全地套在邮件上**——而这正是前面所有密码学知识（混合加密、数字签名、证书）的一次综合应用。<span class="marginnote">一个定位：电子邮件安全要解决两件事——<strong>机密性（内容不被中转站读）</strong>与<strong>认证（确认是谁发的、没被改）</strong>。PGP 与 S/MIME 都同时做这两件事：先签名（防伪）+ 再加密（保密），或加密签名组合。</span>

## 1 邮件的威胁模型

邮件在传输链路上面临的威胁：

**窃听**：邮件在 SMTP 服务器之间明文转发——任何中间节点可读。
**篡改**：中间人改邮件内容、附件。
**伪造**：冒充他人发邮件（钓鱼、诈骗）。
**重放**：截获合法邮件后重新发送。

**TLS 只能保护「一跳」**：SMTP-over-TLS 保护「客户端→服务器」「服务器→服务器」的传输段，但服务器内部仍是明文。**端到端加密（PGP/S/MIME）** 保护「发件人→收件人」全程——这是唯一能让「服务器的管理员也读不到」的方案。<span class="marginnote">关键区分：<strong>传输层加密（TLS）防窃听但服务器可见明文；端到端加密（PGP）防一切中间节点</strong>。企业邮件通常两样都做：传输用 TLS、关键内容用 PGP——「跳间加密」与「端到端加密」不是替代而是叠加。</span>

## 2 PGP：混合加密 + 信任网

**PGP（Pretty Good Privacy，1991，Phil Zimmermann）** 是最著名的邮件加密方案，核心设计是**混合加密**：

1. **压缩**：邮件先压缩（减少冗余、增强加密强度）。
2. **加密**：生成一次性会话密钥，用对称加密（AES）加密邮件。
3. **密钥封装**：用收件人公钥（RSA/ECC）加密会话密钥。
4. **签名**：用自己的私钥对「邮件哈希」签名。
5. **编码**：Base64 编码成 ASCII（适应邮件协议）。

收件人反向操作：用自己的私钥解开会话密钥 → 解密邮件 → 用发件人公钥验签。

**PGP 的信任模型——信任网（Web of Trust）**：PGP 没有中心 CA，而是**用户互相签名担保公钥**——你信任的朋友签署的公钥，你部分信任；足够多的独立签名构建信任链。这是对 CA 中心化模型的一种「去中心化」替代。<span class="marginnote">信任网的哲学：<strong>「信任从你开始，沿你信任的人扩展」</strong>——你的公钥被 20 个朋友签名，别人就更有理由信「这个公钥真是你的」。它牺牲了 CA 的「开箱即信」，换来了无中心、无单点的自主。今天 PGP 也支持「密钥服务器」辅助分发，但信任仍是网状的。</span>

## 3 S/MIME：把邮件放进 PKI

**S/MIME（Secure/Multipurpose Internet Mail Extensions）** 是 IETF 标准，采用**层级信任模型**：

**证书**：每个用户有一张 X.509 证书（由 CA 签发），证书把「邮箱地址 ↔ 公钥」绑定。
**加密与签名**：与 PGP 同框架（混合加密 + 数字签名），但用标准化的 CMS（Cryptographic Message Syntax）。
**信任**：验证证书链到预装的根 CA——与 HTTPS 的信任模型完全一致。

**S/MIME 与 PGP 的对比**：

| 维度 | PGP | S/MIME |
| --- | --- | --- |
| 信任模型 | 信任网（无中心） | CA 证书链（层级） |
| 证书 | 自管理公钥 + 互签 | X.509（CA 签发） |
| 标准 | OpenPGP（RFC 4880） | CMS（RFC 5652） |
| 生态 | 技术圈、自由软件 | 企业、商业邮件 |

**选型**：企业（有现成 CA/PKI）用 S/MIME；注重去中心与自主的用户用 PGP。<span class="marginnote">一个现实讽刺：<strong>PGP 与 S/MIME 技术成熟，但普及率长期低迷</strong>——因为它们把「密钥管理」的复杂度压给了用户（要装证书、管理密钥、理解信任）。直到 2014 年 Snowden 事件后，「邮件加密」才重新被关注，但也主要是「加密传输」而非「端到端」。</span>

## 4 公式解析：PGP 的混合加密

$$
\text{邮件密文} = E_{\text{sym}}(K_{\text{ses}}, \text{compressed}(m)), \qquad K_{\text{ses}} \text{ 用 } E_{\text{pub}}(pk_{B}) \text{ 封装}
$$

三步拆解这条「PGP 混合加密」：

- **第一步，对称加密正文**：邮件用 AES 会话密钥 $K_{\text{ses}}$ 加密——对称加密快，适合长文本。
- **第二步，公钥封装密钥**：$K_{\text{ses}}$ 用收件人公钥加密——只有收件人私钥能解，解决「密钥分发」。
- **第三步，两全其美**：对称加密的快 + 公钥加密的密钥安全——这正是 TLS 混合加密的同款设计，只是用在邮件上。

## 5 数值骨架：一次 PGP 会话的密钥流

用 RSA 玩具数字（承接《RSA 算法》一节的 $p=61, q=53, n=3233, e=17, d=2753$）把混合加密的「密钥流」走一遍：

**发件人 Alice**：

1. 随机生成对称会话密钥 $K_{\text{ses}} = 65$（真实中是 128/256 位随机数）。
2. 用 $K_{\text{ses}}$ 加密邮件正文：$c = \text{AES}_{65}(\text{邮件})$。
3. 用收件人 Bob 的公钥 $(17, 3233)$ 封装 $K_{\text{ses}}$：$c_K = 65^{17} \bmod 3233 = 2790$。

**Bob 收件**：

4. 用私钥 $(2753, 3233)$ 解封：$K_{\text{ses}} = 2790^{2753} \bmod 3233 = 65$。
5. 用 $K_{\text{ses}} = 65$ 解出邮件正文。

**为什么这样分层**：正文用对称加密（快、能处理长文本），会话密钥用公钥加密（慢但只处理 128 位密钥）。攻击者截获的密文只有 $c$ 与 $c_K$——没有 Bob 私钥，既解不开 $c_K$ 也解不开 $c$。<span class="marginnote">对照后文 TLS 的握手：<strong>TLS 1.3 的 ECDHE + AES-GCM，和 PGP 的 RSA + AES，是同一个「对称加密正文 + 公钥交换密钥」模板</strong>。混合加密是这个时代所有安全协议的公共骨架——学会一个，其余都是换群换参数。</span>

## 6 PGP 与 S/MIME 的局限：前向保密与密钥失窃

**局限 1：无前向保密（No Forward Secrecy）**。PGP/S/MIME 用长期密钥（数月到数年不变）。一旦收件人私钥泄露或失窃，**过去所有被该密钥加密的邮件全部可解密**——「今天的失窃，解封昨天的邮件」。对比 Signal/TLS 1.3：每次会话用临时密钥，旧会话密钥用完即焚，失窃只影响当前会话。

**局限 2：密钥管理是单点**。PGP 私钥存在用户设备上，丢设备 = 丢密钥（除非有恢复口令）；S/MIME 依赖 CA 与证书吊销，吊销延迟可能让已失效证书继续「看起来有效」。

**局限 3：加密不防钓鱼**。PGP 能把内容加密，但「骗子用伪造公钥加密邮件发给你」仍然成立——端到端加密解决不了「信任这个公钥」之外的欺骗。

**现实结论**：对「长期归档」的邮件，PGP/S/MIME 是最实用方案；对「即时通信」，现代 IM 用「默认端到端 + 前向保密」碾压了邮件加密的 UX——这是后文《安全协议》要展开的对比。<span class="marginnote">一个连接主线的观察：<strong>前向保密是「密钥失窃」时代的必修课</strong>——TLS 1.3 强制 ECDHE、Signal 用双棘轮，都是为了让「一钥失窃」不扩散成「全部失窃」。邮件加密的历史包袱就在「长期密钥 + 归档需求」的冲突上。</span>

## 7 邮件安全的现实：加密与钓鱼的拉锯

邮件安全不只是「加密算法」：

- **钓鱼邮件**：伪造发件人、仿冒品牌——加密解决不了「用户被骗」，需要 DKIM/SPF/DMARC（发件人认证）与用户教育。
- **DKIM/SPF/DMARC**：邮件域名的身份验证——防伪造域名的标准机制（与端到端加密互补：它们防「伪造」而非「窃听」）。
- **加密的 UX 困境**：端到端加密的密钥管理复杂，导致用户「知道要加密但不用」——Signal 等 IM 的「默认加密」恰恰是 PGP 式加密在 UX 上的胜利。

**技术结论**：邮件端到端加密（PGP/S/MIME）成熟可靠，但「防钓鱼 + 防伪造」靠的是**发件人认证（DKIM/SPF/DMARC）+ 用户判断**——加密只解决保密与真实，不解决「人被骗」。<span class="marginnote">一个观念扩展：<strong>安全 = 密码学（防窃听、防篡改）+ 身份验证（防伪造）+ 人的决策（防被骗）</strong>。邮件是这三层都需要的典型场景：PGP 管前两层，DKIM/SPF 管伪造，反钓鱼靠意识。技术的极限在于「加密解决不了信任问题」。</span>

## 8 小结

- **邮件威胁**：窃听、篡改、伪造、重放——传输层 TLS 只护一跳，端到端加密护全程。
- **PGP**：混合加密 + 数字签名 + 信任网——去中心、自主、OpenPGP 标准。
- **S/MIME**：CMS + X.509 证书链——层级信任，与企业 PKI 无缝。
- **混合加密**：对称加密正文 + 公钥封装会话密钥——快与安全的组合；玩具算例 $K=65 \leftrightarrow c_K=2790$。
- **局限**：无前向保密（长期密钥）、密钥管理单点、加密不防钓鱼。
- 现实：端到端加密成熟但 UX 难；DKIM/SPF/DMARC 防伪造；人不能被加密保护。
