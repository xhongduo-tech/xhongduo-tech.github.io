# 无条件安全与计算安全的分野

## 为什么从两种安全的分野开始

前两节我们把一次一密的「完美」推到极限，又看到了它的工程绝境。密码学由此走到一个岔路口：一边是**无条件安全**——不假设攻击者算力，但代价高昂；一边是**计算安全**——允许短密钥，但把安全性建立在「问题难解」的计算假设上。现代密码学几乎全部站在计算安全这一侧：RSA、AES、哈希函数、数字签名，无一例外。理解这个分野，等于理解了「现代密码学在证明什么」这个总问题的骨架。<span class="marginnote">这是信息安全学科的范式分界：<strong>无条件安全问「信息是否泄露」，计算安全问「泄露要花多少时间</strong>」。前者是数学命题，后者是工程命题——这也是为什么现代密码学论文里全是「规约」「优势」「不可区分性」这类概率-复杂性语言。</span>

## 1 无条件安全：不假设算力的安全

**无条件安全（unconditional security）**：即使攻击者拥有无限的算力与时间，也无法从密文获得任何关于明文的信息。它也叫**信息论安全（information-theoretic security）**，因为安全性来自信息论，不依赖任何计算复杂度假设。

它的代表是上一节的完善保密性：一次一密就是无条件安全的。但请注意，无条件安全**不等于**完善保密——它是更大的概念家族，还包括**秘密共享**（若干份额合起来才恢复秘密，任何少于门槛的份额集合不泄露信息）、**安全多方计算**的信息论变体等。<span class="marginnote">无条件安全的共同语法是「信息完全不泄露」，而非「泄露一点但难利用」。秘密共享里，$n$ 份份额中的任意 $t-1$ 份关于秘密的熵为 0——这是信息论意义上的绝对不泄露，见第十五篇《安全多方计算与秘密共享》。</span>

无条件安全的代价也一目了然：要么密钥与消息等长（一次一密），要么通信方之间需要共享大量随机性（秘密共享的份额），总之「安全要用足够的随机性去换」。

## 2 计算安全：把安全建立在困难问题上

**计算安全（computational security）**：攻击者算力有限，破解密码所需的计算量超出其能力范围，因而在**实际可行**的意义上安全。它不承诺「信息不泄露」，只承诺「泄露的信息难以利用」。

计算安全的两个要素缺一不可：

**困难问题**：体制背后要有一个被广泛相信「难解」的计算问题，如大整数分解（RSA）、离散对数（ElGamal、DH）、格问题（后量子密码）。
**可忽略的成功概率**：攻击者的成功概率要么小到可以忽略，要么所需工作量指数级增长。<span class="marginnote">「可忽略」在密码学里有严格定义：随安全参数 $n$ 增长，成功概率 $< n^{-c}$ 对任意常数 $c$ 都最终成立，即比任何多项式倒数都小。AES-256 的穷举 $2^{256}$ 次就是「实际不可行」的直观表达。</span>

关键在「被广泛相信」四个字：计算安全是**假设性的**。今天难解的问题，明天可能被算法进展或量子计算机攻破——这正是第十六篇后量子密码的由来。

## 3 公式解析：不可区分性的两种表述

$$
\Pr[\mathcal{A}(\text{挑战}) = b] \le \frac{1}{2} + \mathsf{negl}(n)
$$

这是计算安全的**标准语言**——「游戏」框架。以区分两个密文为例，拆三步：

- **第一步，读懂符号**：攻击者 $\mathcal{A}$ 面对一个「挑战」：系统随机选明文 $m_0$ 或 $m_1$（概率各半）加密成 $c$ 交给 $\mathcal{A}$。$\mathcal{A}$ 猜它加密的是哪一个，$b$ 是真实答案，$\mathcal{A}$ 猜对的概率记作 $\Pr[\mathcal{A}=b]$。
- **第二步，理解基准**：瞎猜的概率是 $1/2$。所以「$\le 1/2 + \mathsf{negl}(n)$」的意思是：攻击者最多比瞎猜好一个**可忽略**的量。
- **第三步，读出直觉**：攻击者即使花大量算力，也只能比「抛硬币」多得到微不足道的优势。这就是「计算上不可区分」——两个密文在计算上看起来一样。

对比无条件安全的表述 $P(M=m \mid C=c) = P(M=m)$：那里是**精确相等**，这里是**近似相等**（差可忽略）。一字之差，就是两条安全路线的全部差别。

## 4 辨析｜易错点：计算安全不是「难一点点」

初学者最常见的误解，是把计算安全理解成「破解需要很多年」。这个理解方向对，但必须精确化：

- **差一个常数没关系**：破解需 $2^{100}$ 次与需 $2^{200}$ 次，都算计算安全——攻击者连 $2^{80}$ 次都做不完。
- **差一个多项式就有关系**：若破解时间从 $2^{100}$ 降到 $n^2$，体制立即不安全。计算安全要求攻击优势随安全参数**指数级**下降或工作量指数级上升，多项式级别的提升是致命的。
- **参数要留余量**：AES-128 的 $2^{128}$ 在今天足够，但摩尔定律与量子计算不断侵蚀余量，所以业界在往 AES-256、更长的密钥迁移。<span class="marginnote">安全参数的「保质期」问题：1980 年代 56 位密钥（DES）被认为是安全的，今天几小时就能暴力破解。计算安全永远是「相对于当前算力」的安全，需要持续评估。</span>

## 5 一条光谱：从绝对到相对

把两种安全放在一条光谱上，能看清现代密码学的位置：

| 维度 | 无条件安全 | 计算安全 |
| --- | --- | --- |
| 攻击者算力 | 无限 | 有限（多项式时间） |
| 安全基础 | 信息论 | 困难问题假设 |
| 典型结论 | $P(M \mid C)=P(M)$ | 优势 $\le \mathsf{negl}(n)$ |
| 代表体制 | 一次一密、秘密共享 | AES、RSA、DH、椭圆曲线 |
| 密钥长度 | ≥ 消息长度 | 短（128/256 位） |
| 被攻破风险 | 无（数学保证） | 有（算法或量子威胁） |

现代密码学几乎全部落在右列：短密钥带来的工程可行性，是以「假设性安全」为代价换来的。整条密码学发展史——从 DES 到 AES、从 RSA 到椭圆曲线、再到后量子密码——都可以看成在右列内部不断更换、加固「困难问题假设」的旅程。<span class="marginnote">一个耐人寻味的细节：公钥密码（RSA 等）只能做到计算安全，因为公开密钥本身就是把「验证信息」公之于众；而对称密码理论上可以做到无条件安全。这也是为什么真正的绝密通信仍然向往一次一密。</span>

## 6 小结

- **无条件安全**：不假设算力，信息绝对不泄露；代表是一次一密与秘密共享，代价高。
- **计算安全**：假设攻击者算力有限，把安全建立在**困难问题假设**上；代表是 AES、RSA 等几乎所有现代体制。
- 计算安全的标准语言是**可忽略优势**：$\Pr[\mathcal{A}=b] \le \tfrac12 + \mathsf{negl}(n)$。
- 计算安全是**相对且假设性**的，需随算力进步持续升级参数——这是后量子密码的动因。
