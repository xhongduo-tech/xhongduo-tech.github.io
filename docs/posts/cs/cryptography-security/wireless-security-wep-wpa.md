## 为什么从无线安全开始

有线网络可以物理隔离，而 Wi-Fi 是**广播介质**——信号穿过墙壁，任何在范围内的人都能「收听到」数据包。无线安全必须用加密把广播变成「只听自己人的频道」。Wi-Fi 安全的演进是一部「密码学失败史」：WEP 被系统性攻破、WPA 被补丁、WPA2 成为标准、WPA3 修复 WPA2 的 KRACK。理解这段历史，等于看到「加密算法、密钥管理、协议设计」三者如何共同决定一个安全体系。<span class="marginnote">一个全局视角：<strong>Wi-Fi 安全 = 加密（数据保密）+ 认证（谁允许连）+ 密钥管理（密钥怎么安全分发）</strong>——WEP 恰恰三样都错：加密弱、认证弱、密钥复用。三代标准（WEP→WPA2→WPA3）就是这三样逐渐做对的过程。</span>

## 1 WEP：从头错到尾的加密

**WEP（Wired Equivalent Privacy，1999）** 号称「等效有线」，实际上脆弱到几分钟可破。它的核心问题：

**RC4 流密码 + 24 位 IV**：IV 太短（仅 2^24），流量稍大就**重用**——一次一密重用的灾难（$C_1 \oplus C_2 = M_1 \oplus M_2$）。
**IV 直接拼进密钥**：WEP 用 $K = \mathrm{IV} \parallel k$（IV 拼在密钥前面）作为 RC4 密钥——IV 是公开的，恰好触发 RC4 的**弱密钥偏差**（Fluhrer-Mantin-Shamir，2001）。
**CRC-32 完整性**：CRC 是线性校验，攻击者可**翻转密文位并重算 CRC**——完整性形同虚设。
**无认证**：共享密钥认证可被截获重放。

**2001 年 FMS 攻击**：只需收集 500 万～几百万个数据包，几分钟内即可恢复 WEP 密钥。**WEP 是「密码学错误示范大全」**——每个设计决策都踩在错误的位置上。<span class="marginnote">WEP 的教训浓缩成一句话：<strong>「短 IV + 公开密钥输入 + 弱流密码 + 线性校验」——四重错误叠加</strong>。它还证明了一个通则：任何「把可预测/公开数据拼进密钥」的设计都危险。现代 WPA3 的 SAE 握手专门避免「密码直接参与会话密钥」。</span>

用一条代数式子说明「IV 重用 = 灾难」。WEP 用 RC4 生成密钥流 $K$，加密是 $C = M \oplus K$。若两个包重用了同一个 $(IV, K)$：

$$C_1 \oplus C_2 = (M_1 \oplus K) \oplus (M_2 \oplus K) = M_1 \oplus M_2$$

**密钥流被消掉了**——攻击者得到的是两条明文的异或。明文有大量可预测结构（IP 头、TCP 头），这一异或足以恢复大量明文；再配合 WEP 的 ICV（CRC）线性性质，还能改写数据。**24 位 IV 在繁忙 Wi-Fi 上几小时就会重用**，这正是 WEP「几分钟可破」的直接根源。反观现代 AEAD（如 AES-GCM），nonce 一旦重用就直接报废会话——设计者用「一次性 nonce」的硬约束，从根上杜绝了「IV 重用悄悄发生」的可能。

## 2 WPA/WPA2：修补与标准

**WPA（2003）** 是对 WEP 的紧急修补：

用 **TKIP**（临时密钥完整性协议）：仍用 RC4，但每次包都用不同密钥（每包重钥）+ 更强的完整性（MIC）+ IV 管理改进。
引入 **802.1X/EAP** 认证（企业模式）或 **PSK**（家庭模式）。

**WPA2（2004）** 是彻底重写：

用 **AES-CCMP**（CCM 模式）替代 RC4——现代 AEAD。
**四次握手（4-way handshake）**：基于 PSK 派生会话密钥，每会话新密钥。
成为 Wi-Fi 认证的长期标准（2004–至今）。

**WPA2-PSK 的四次握手**：接入点与客户端用「口令派生的 PMK」做四次消息交换，派生每会话的 PTK（成对临时密钥），并相互证明「双方都知道口令」。

**WPA2 的弱点**：口令猜测（PSK 弱则字典攻击）、无前向保密、以及 **KRACK**。<span class="marginnote">四次握手的精髓：<strong>用「口令派生的主密钥（PMK）」协商出「每会话的临时密钥（PTK）」</strong>——即使口令长期不变，会话密钥也每次不同（接近前向保密）。这跟 TLS 的「长期身份 + 临时会话」是同一个模式。KRACK 攻击恰恰打在握手的「重传」逻辑上——见下文。</span>

把四次握手拆成消息级流程，理解它为什么能「双方都证明知道口令」：

1. **AP → 客户端**：AP 发送随机数 `ANonce` 与自身 MAC。
2. **客户端 → AP**：客户端发送随机数 `SNonce` 与自身 MAC（客户端此时已能算 PTK）。
3. **AP → 客户端**：AP 发送 `MIC`（用 PTK 对握手消息算的消息完整性码）——**证明 AP 知道 PMK**（不知道口令就算不出 PTK、给不出正确 MIC）。
4. **客户端 → AP**：客户端回 MIC 确认——**证明客户端也知道 PMK**，握手完成，双方开始用 PTK 加密数据。

关键在消息 3 与 4 的 MIC：**每一方都通过「算得出正确的 MIC」来证明自己知道口令派生的 PMK**，而口令本身从未出现在任何消息里。这就是「用密钥证明知识，而非传输知识」的标准范式。

## 3 KRACK：WPA2 的握手重放漏洞

**KRACK（Key Reinstallation Attack，2017）** 由 Vanhoef 发现，针对 WPA2 四步握手的实现逻辑：

**漏洞**：攻击者**重放**握手的第 3 条消息，迫使客户端**重新安装**已经用过的密钥——重置 nonce/序列号计数器。
**后果**：nonce 重用 → 同一密钥加密重复 → 攻击者可重放/解密部分流量；还能注入明文包。
**影响**：所有 WPA2 设备（因实现遵循握手的重传逻辑），包括 Linux/Android 尤甚。

**修复**：协议实现补丁（重传时不重新安装密钥）；WPA3 从协议层修复。KRACK 的教训：**握手协议的「重传容错」逻辑也是攻击面**——看似无害的「再发一次确认」，能让整个密钥体系失效。<span class="marginnote">KRACK 的深层教训：<strong>「密钥安装」必须是一次性事件</strong>——重新安装已用过的密钥 = nonce 重置 = 加密重复。协议设计者要仔细回答「什么操作是幂等的、什么操作绝不能重做」。这与 TLS 记录层的「序列号不重置」是同一个原则的不同实现。</span>

一个值得记住的细节：KRACK 影响面极大，是因为 **WPA2 规范要求客户端「收到消息 3 的重传就重新安装密钥」**——这是为了容错（消息丢失时重发），却被攻击者利用。它提醒我们：**协议的「容错重试」一旦处理不当，会把「重放」从 bug 变成漏洞**。安全协议设计要在「容忍丢包」与「拒绝重放」之间做精细的权衡。

## 4 WPA3：下一代标准

**WPA3（2018）** 针对 WPA2 的弱点做系统升级：

**SAE 握手**（Simultaneous Authentication of Equals）：基于 Dragonfly（PAKE）——**口令不参与网络传输**，即使被离线抓包也无法字典攻击；天然防 KRACK。
**前向保密**：SAE 每次握手都用临时密钥，历史流量不可被未来密钥解密。
**192 位模式**：企业用更高安全强度。
**开放网络增强**：对无密码的热点，用 OWE（Opportunistic Wireless Encryption）做「免密加密」。

**WPA3 的落地**：WPA3-Personal（家庭）、WPA3-Enterprise（企业）。兼容性上常以「WPA2/WPA3 混合模式」过渡——但混合模式会降级到 WPA2 弱点。<span class="marginnote">SAE（PAKE）的意义：<strong>传统 WPA2-PSK 的握手会「公开口令派生的值」——攻击者可离线字典攻击弱口令；SAE 让口令只参与「双方同时验证」的计算，网络里没有任何可离线攻击的值</strong>。这是「口令认证密钥交换（PAKE）」思想在 Wi-Fi 的落地——与 FIDO2 的「密码不参与网络」是同一个哲学方向。</span>

把三代标准的「加密、认证、密钥管理」并排对比，历史脉络立刻清晰：

| 标准 | 加密 | 认证/握手 | 密钥管理 | 已知问题 |
| --- | --- | --- | --- | --- |
| WEP | RC4 + 短 IV | 共享密钥 | IV 拼密钥，重用小 | 全方面被攻破 |
| WPA | RC4 + TKIP | 802.1X / PSK | 每包重钥 | 中间补丁 |
| WPA2 | AES-CCMP | 四次握手 | 每会话 PTK | KRACK、口令猜测 |
| WPA3 | AES-GCMP | SAE（PAKE） | 临时密钥 + 前向保密 | 落地覆盖不全 |

每一代都修上一代的「最痛处」：WPA 补 IV 重用、WPA2 换掉 RC4、WPA3 修掉「口令可离线攻击」与「无前向保密」。这条演进史本身就是「安全标准如何随攻击迭代」的活教材。

## 5 无线安全的实践清单

普通用户与管理员应遵循的实践：

**用 WPA2/WPA3，绝不回退 WEP**（WEP 已是历史）。
**口令要强**：PSK 至少 12+ 字符随机串——弱口令是 WPA2/WPA3-Personal 的最大弱点。
**开启 WPA3（设备支持时）**：SAE 握手防字典攻击与前向保密。
**企业环境**：用 WPA3-Enterprise + 证书认证（802.1X/EAP-TLS），不用共享口令。
**访客网络**：独立 SSID + 隔离，避免访客接触内网。
**及时更新固件**：路由器的 WPS/KRACK/远程漏洞补丁都靠固件下发——旧固件是攻击者最爱的突破口。
**监控**：检测异常设备、禁用 WPS（存在 PIN 暴力漏洞）。<span class="marginnote">一个现实提醒：<strong>WPA2 在「强口令」下仍然相当安全</strong>——KRACK 需要攻击者在物理范围内、且大多数设备已打补丁。WPA3 是「更安全的默认」，但 WPA2 + 强口令仍是可接受的最低标准。无线安全与有线一样：协议之外的「口令强度 + 补丁 + 监控」同样重要。</span>

再补一条常被忽略的无线风险：**恶意接入点（Rogue AP）与 Evil Twin**。攻击者架一个同名的假热点，诱导设备连上来做中间人。防护手段包括：**802.1X 企业认证**（每台设备唯一证书，假 AP 无法通过）、**WPA3 的「欺诈检测」提示**、以及客户端侧的「首次连接指纹」提醒。无线安全不止是「加密」，还包括「这个热点是不是真的」——这也是为什么企业环境几乎必须上 EAP-TLS。它和「口令是否够强」一起，构成了 Wi-Fi 安全「算法、密钥、身份」三角的最后一角。

## 6 小结

- **WEP**：短 IV 重用 + RC4 弱密钥 + 线性 CRC——四重错误，2001 年 FMS 攻击几分钟破。
- **WPA2**：AES-CCMP + 四次握手——现代标准，但有口令猜测与 KRACK 弱点。
- **KRACK（2017）**：握手重传导致密钥重装、nonce 重置——协议实现逻辑的攻击面。
- **WPA3**：SAE 握手（PAKE）——口令不出网、防字典、前向保密、防 KRACK。
- 实践：WPA2/WPA3 + 强口令 + 补丁 + 监控；企业用证书认证（EAP-TLS）。
