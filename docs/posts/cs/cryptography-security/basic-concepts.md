## 为什么从密码学开始

你每次在浏览器地址栏看见那把小小的锁，每次用微信聊天、用网银转账、用 SSH 登录服务器，背后都有一台「看不见的加密引擎」在工作。**密码学（cryptography）**就是这整套引擎的数学根基——它回答一个非常朴素的问题：**在一条任何人都能窃听的信道上，怎样让只有你与对方能读懂消息，而第三者即使截获全部数据也一无所获？**

这个问题的答案，从 2000 多年前的凯撒大帝到今天的大模型训练数据保护，骨架从未变过。它由几个极简的概念构成：**明文、密文、密钥，以及把它们组织起来的密码体制五元组**。这一节是全专题的第一块基石——后面所有内容，从古典密码到 AES，从 RSA 到后量子密码，都是在这组概念上盖楼。我们先把地基的每块砖看清楚。

## 1 明文、密文与密钥：三个最朴素的角色

**明文（plaintext）**：需要保护的消息原始形式，记作 $P$。它可以是二进制的文件、UTF-8 的文本、一段语音采样，数学上我们把它看成**明文空间**里的一个元素。

**密文（ciphertext）**：明文经过变换后的「看不懂」的形式，记作 $C$。密文同样属于一个**密文空间**。判断密码好坏的第一直觉就是看密文是否「毫无规律」。

**密钥（key）**：控制加密/解密变换的可变参数，记作 $k$。同一份明文，用不同的密钥加密，得到不同的密文；反之，同一份密文，用不同的密钥解密，还原出的是不同的「明文」。<span class="marginnote">密钥与密码（cipher）的区别：密码是固定的变换规则，密钥是这条规则里可以换的旋钮。类比一把锁：锁的结构是密码，钥匙是密钥。换了钥匙不换锁，还是同一把锁。</span>

用一个具体的例子固定直觉。凯撒密码把每个字母向后平移 $3$ 位：`HELLO` → `KHOOR`。这里明文是 `HELLO`，密文是 `KHOOR`，密钥就是「平移 3」。把 3 换成 5，密文立刻变成 `MJQQT`——**规则没变，只是旋钮转了一下**。

**核心概念：密码体制（cipher）**：一套完整的、明文空间到密文空间的变换规则，连同它的密钥空间、加密与解密算法。

## 2 密码体制五元组 (P, C, K, E, D)

Stallings 沿用香农 1949 年那篇奠基论文《保密系统的通信理论》的框架，把一套密码体制形式化为**五个集合（或变换）构成的元组**，记作：

$$
(P, C, K, E, D)
$$

逐项拆开：<span class="marginnote">香农把保密系统抽象成五元组，第一次让「保密」成为可以严格讨论的数学对象。这与第一级《基础数学》中「集合」的语言一脉相承——五元组里的每一项都先是集合，再谈其上的运算。</span>

- **$P$，明文空间**：所有可能明文的集合。
- **$C$，密文空间**：所有可能密文的集合。
- **$K$，密钥空间**：所有可能密钥的集合。$K$ 里每个元素 $k$ 称为一个**密钥**。
- **$E$，加密变换的集合**：对每个密钥 $k$，存在一个加密变换 $E_k: P \rightarrow C$。
- **$D$，解密变换的集合**：对每个密钥 $k$，存在一个解密变换 $D_k: C \rightarrow P$。

五个成员里，**$P, C, K$ 是集合，$E, D$ 是一族映射**——这正是第一级《基础数学》集合论与函数概念在密码学里的第一次正式登场。$(P, C, K, E, D)$ 这个写法本身就是一个「元组」，与我们在第二级《离散数学》里遇到的有序对、笛卡尔积是同一套语言。

一个密码体制要能工作，加密与解密必须互为逆运算。这引出了下面这个贯穿全部密码学的核心等式。

## 3 公式解析：C = E_k(P) 与 P = D_k(C)

$$
C = E_k(P), \qquad P = D_k(C)
$$

这两行看起来平淡，却是整门学科的**公理级关系**。逐项拆解：

- **第一步，看下标 $k$**：$E_k$ 不是「一个」函数，而是「一把钥匙一个函数」的一族函数。密钥 $k$ 从密钥空间 $K$ 中选出，$E_k$ 随之确定。这解释了为什么换一个密钥，同样的明文会变成完全不同的密文。
- **第二步，看第一个式子 $C = E_k(P)$**：加密是把明文 $P$ 送进加密变换 $E_k$，输出密文 $C$。箭头方向是 $P \rightarrow C$。
- **第三步，看第二个式子 $P = D_k(C)$**：解密是反向走——把密文 $C$ 送进解密变换 $D_k$，还原出明文 $P$。
- **第四步，把两式合起来**：把第一式代入第二式，得到

$$
P = D_k(E_k(P))
$$

这条链式等式是密码体制的**可正确性条件（correctness）**：先加密再解密，必须原样回到出发点。它翻译成集合论的话就是：$D_k$ 是 $E_k$ 的左逆映射，或者说 $E_k$ 必须是**单射**——不同的明文不得加密成同一份密文，否则解密时就无法区分。<span class="marginnote">把 $E_k$ 看成单射，这正是第一级《基础数学》里函数性质与第二级《离散数学》集合论中「单射/满射/双射」的实战。多数现代密码还要求 $E_k$ 是双射，这样密文空间与明文空间一样大。</span>

**重点：$D_k$ 是 $E_k$ 的逆变换**。加密与解密不是两套独立规则，而是一枚硬币的两面。这个「逆」的概念将反复出现：在分组密码里它是可逆的轮函数，在公钥密码里它就是那个神秘的「陷门」。

## 4 柯克霍夫原则：安全性只依赖密钥

那么，一套密码的安全性应该建立在什么之上？1883 年，荷兰密码学家奥古斯特·柯克霍夫（Auguste Kerckhoffs）在其军事密码学著作中提出了一条后来影响深远的原则，今天称为**柯克霍夫原则（Kerckhoffs's Principle）**：

**密码系统的安全性必须仅依赖密钥的保密，而不得依赖算法本身的保密。**

换句话说：**让敌人知道你用的是什么算法，甚至把算法源码公开给他，系统仍然必须是安全的**——只要他不知道密钥。真正的安全不靠「藏算法」，而靠「藏钥匙」。

这条原则与直觉相反，却极其深刻。它把「保密」的对象从**一大团说不清的规则**压缩成了**一个可管理的密钥**：密钥可以定期更换、可以分发、可以销毁，而算法一旦公开就再也无法保密。更重要的是，公开算法接受全世界攻击者的检验，反而能暴露弱点——这被称作**公开设计原则**。

**辨析｜易错点：** 柯克霍夫原则不等于「算法公开就一定安全」，而是「算法必须经得起公开」。历史上因为「相信算法没人知道」而垮掉的系统数不胜数——这正是安全界常说的「隐蔽式安全」（security by obscurity）的陷阱。现代密码学默认算法公开，安全性完全由密钥承载。

## 5 对称密码与非对称密码：两条技术路线

五元组 (P, C, K, E, D) 是抽象骨架，落到工程上有两种截然不同的「密钥安排」，它们在后面的章节会各自展开成一座大厦。

**对称密码（symmetric cipher）**：加密与解密**使用同一个密钥** $k$。今天聊天软件、HTTPS 里传输数据的加密，绝大多数是这类——代表是 AES、ChaCha20。它的优点是快，缺点是必须先安全地把同一把密钥送到对方手里（这叫**密钥分发问题**）。

**非对称密码（asymmetric cipher，又称公钥密码）**：每个用户有一对密钥——**公钥（public key）**公开、**私钥（private key）**保密。用公钥加密，只有配对的私钥能解密。这解决了对称密码的密钥分发难题，代表是 RSA 与椭圆曲线密码。代价是慢，所以真实系统里两者常结合：**用非对称密码安全地交换对称密钥，再用对称密码加密海量数据**——这几乎是所有现代协议（TLS、SSH）的通用套路。

可以用一小段 Python 代码把「加密是函数、解密是反函数」的骨架看得更清楚（仅为教学示意，真实密码远比这复杂）：

```python
def xor_cipher(data: bytes, key: int) -> bytes:
    """用单字节异或演示对称加密：加密与解密是同一个操作。"""
    return bytes(b ^ key for b in data)

key = 0x5A
plaintext = b"HELLO"
ciphertext = xor_cipher(plaintext, key)   # C = E_k(P)
recovered  = xor_cipher(ciphertext, key)  # P = D_k(C)
assert recovered == plaintext
print("C =", ciphertext.hex())
print("P =", recovered)
```

注意这里 `xor_cipher` 既当 $E_k$ 又当 $D_k$，因为异或的自反性 $a \oplus b \oplus b = a$ 恰好满足 $D_k(E_k(P)) = P$。现代对称密码（AES 等）加密与解密是**不同的**函数，但它们的核心关系依然是「互为逆」——这正是第三节那个等式的意义。

## 6 四个安全目标：密码学到底在保护什么

密码学不只是「把消息弄乱」。站在安全的角度，它服务于四个基本目标，Stallings 在 §1.1 中将其作为贯穿全书的线索：

| 安全目标 | 含义 | 反面对应 |
| --- | --- | --- |
| **机密性（confidentiality）** | 只有授权者能读懂内容 | 被窃听 / 泄露 |
| **完整性（integrity）** | 消息在传输中未被篡改 | 被伪造 / 被改写 |
| **认证（authentication）** | 消息确实来自声称的发送者 | 身份冒充 |
| **不可否认性（non-repudiation）** | 发送者无法否认发过这条消息 | 事后抵赖 |

**重点：四个目标对应四种不同的攻击，也因此对应不同的密码学工具。** 机密性靠**加密**；完整性靠**哈希函数与消息认证码**；认证靠**数字签名与认证协议**；不可否认性靠**数字签名**（尤其是公钥体制下的签名，私钥只有本人持有）。<span class="marginnote">注意「认证」与「机密性」是两回事：一条消息可以完全不加密（全世界都能读），但必须保证它确实来自声称的发送者——签名就是干这个的。这也是为什么 HTTPS 既加密又签名。</span>

这四项就是我们后面整本专题的「任务清单」：每一类密码算法，最终都要回答「它在保护哪个目标」。「从极限到大模型」的读者请留意：大模型的训练数据保护、模型权重的防篡改、API 调用的认证，底层全是这四个目标在不同场景的重述。

## 7 小结

- 密码学三大基本角色：**明文 $P$**、**密文 $C$**、**密钥 $k$**。
- 密码体制形式化为**五元组 $(P, C, K, E, D)$**：明文空间、密文空间、密钥空间、加密变换族、解密变换族。
- 核心等式 $C = E_k(P)$ 与 $P = D_k(C)$，合并得到**可正确性条件** $D_k(E_k(P)) = P$——解密是加密的逆变换。
- **柯克霍夫原则**：安全性只依赖密钥的保密，算法必须经得起公开。
- 两种技术路线：**对称密码**（同一密钥，快）与**非对称密码**（公钥/私钥，慢但解决密钥分发）；实际系统常两者结合。
- 四个安全目标：**机密性、完整性、认证、不可否认性**，构成全书主线。

在下一节，我们将进入密码学的「威胁面」：攻击者到底能做什么——**被动攻击与主动攻击的分类**。这决定了我们设计的密码到底要防住谁。
