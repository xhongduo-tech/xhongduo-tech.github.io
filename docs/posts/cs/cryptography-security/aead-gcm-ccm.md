# 认证加密模式：GCM 与 CCM

## 为什么从认证加密开始

前两节的模式都只解决**机密性**：加密。但现实攻击者往往是「主动的」——他拦截、篡改、重放密文。如果只加密不认证，攻击者翻转一个密文位，解密后就是一位被篡改的明文（CTR/OFB 甚至能做到精确翻转），而系统浑然不知。**认证加密（Authenticated Encryption, AE / AEAD）**同时提供机密性 + 完整性 + 真实性：解密时先验证「消息确实是对方加密的、没有被改动过」，验证失败就拒绝。现代协议的标配 GCM 与 CCM，正是这类模式的代表。<span class="marginnote">AEAD 里的 AD 指<strong>关联数据（Associated Data）</strong>：一段「不加密但必须认证」的元数据——比如 IP 头、HTTP 头、包序号。它们不需要保密，但必须保证没人能偷偷改动，否则整个协议会被注入伪造消息。</span>

## 1 为什么「加密 + MAC」不够：顺序陷阱

认证加密不是「加密后再加一个 MAC」这么简单——**顺序错了会出致命漏洞**。历史上主流的三种组合方式：

**Encrypt-and-MAC**：先加密，MAC 算在**明文**上，明文与密文一起传。缺陷：MAC 泄露明文的模式，破坏机密性。
**MAC-then-Encrypt**：先对明文算 MAC，再把「明文+MAC」一起加密。缺陷：解密时先解出明文才能验 MAC，验 MAC 失败时把「解密结果」泄露给攻击者——**填充预言攻击**正是打这个顺序（见下一节）。
**Encrypt-then-MAC**：先加密，MAC 算在**密文**上，密文与 MAC 一起传。**唯一推荐顺序**：验 MAC 时不需要解密，失败就丢弃，不泄露任何明文信息。

GCM 与 CCM 都属于 Encrypt-then-MAC 的思想，但把 MAC 集成进加密流程，实现「一次遍历完成加密与认证」，比「加密+MAC」更快。<span class="marginnote">一句话记顺序：<strong>先加密，再对密文做认证</strong>。任何先认证后加密、或只加密不认证的方案，都站在这条铁律的错误一侧。</span>

## 2 GCM：CTR 加密 + GHASH 认证

**伽罗瓦计数器模式（Galois/Counter Mode, GCM）** 由两部分组成：

- **加密部分 = CTR**：用计数器生成密钥流，与明文异或得到密文——继承 CTR 的全部优点（可并行、可随机访问）。
- **认证部分 = GHASH**：在 $\mathrm{GF}(2^{128})$ 上，把密文与关联数据按位乘一个固定的哈希密钥 $H = E_K(0^{128})$，用**多项式哈希**累积出一个认证标签 $T$。

GHASH 的计算是一个 Horner 式的多项式求值：

$$
T = \text{最后一块 } X_n, \qquad X_i = (X_{i-1} \oplus \text{块}_i) \cdot H
$$

GHASH 是**几乎线性**的（每个块一次 GF 乘法），配合 AES 的硬件指令（AES-NI + PCLMULQDQ），GCM 在 CPU 上可以极快地同时完成加密与认证——这是它成为 TLS 1.2/1.3 与 VPN 首选的原因。<span class="marginnote">GHASH 的脆弱面：它是<strong>线性哈希</strong>（不像 SHA-2 那样的密码学哈希），安全性完全押在 $H$ 保密与 nonce 不重复上。若 nonce 重复，攻击者能恢复 $H$ 并伪造任意标签——GCM 对 nonce 复用几乎零容忍。</span>

## 3 CCM：CBC-MAC 与 CTR 的组合

**计数器模式 + CBC-MAC（CCM）** 是另一种标准 AEAD（用于 IEEE 802.11 Wi-Fi、蓝牙、Zigbee 等）：

**认证部分 = CBC-MAC**：用 AES 做 CBC 链（把密文与关联数据链接起来），取最后一个分组作为 MAC——本质上是不含密钥流、只做链式累计的「CBC」。
**加密部分 = CTR**：生成密钥流加密明文。

CCM 与 GCM 的取舍：

| 维度 | GCM | CCM |
| --- | --- | --- |
| 认证机制 | GHASH（GF 多项式哈希） | CBC-MAC |
| 加密机制 | CTR | CTR |
| 并行性 | 全并行 | **认证部分串行** |
| 硬件加速 | AES-NI + PCLMULQDQ | 仅 AES-NI |
| 主要用途 | TLS、VPN、IPsec | Wi-Fi、蓝牙、传感器网络 |

CCM 的优势是**只用 AES**（不依赖 GF 乘法指令），在无 AES-NI 的廉价芯片上实现简单；代价是认证部分串行、速度慢。GCM 在现代 PC 与服务器上全面胜出，CCM 活在嵌入式与无线协议里。<span class="marginnote">IEEE 802.11（Wi-Fi）从 WEP 到 WPA2 一直用 CCM 的变体（CCMP）；GCM 则出现在 TLS 1.2 的 GCM-SHA256 套件与 TLS 1.3 的默认套件里。一个协议选哪个 AEAD，往往取决于它的硬件平台。</span>

## 4 公式解析：GCM 的认证标签如何生成

$$
T = \mathrm{GHASH}_H(\mathrm{Nonce} \| A \| C) \oplus E_K(\mathrm{Nonce} \| 1)
$$

三步拆解这条「认证标签」公式：

- **第一步，哈希累积**：GHASH 以 $H = E_K(0^{128})$ 为密钥，把 Nonce、关联数据 $A$、密文 $C$（含长度信息）按序喂给多项式哈希，得到一个 128 位中间值。
- **第二步，掩码**：$E_K(\mathrm{Nonce}\|1)$ 是对「计数器=1」的加密——它把 GHASH 的线性结果「掩码」掉，防止攻击者从标签反推 $H$。
- **第三步，整体**：$T$ 取异或结果的低 96 位（或 64/128 位，可配置）。验证时接收方重算 $T$ 并与收到的标签比较——不等则拒绝整个消息。

## 5 使用 AEAD 的安全清单

认证加密是现代密码工程的默认要求，但它的安全前提依然苛刻：

- **Nonce 必须唯一**：GCM/CCM 的 nonce 复用是灾难级的——GCM 复用会泄露 $H$，攻击者从此可伪造任意认证标签。TLS 用「每连接随机 nonce」、磁盘用「每扇区计数器」，都是工程化的唯一性保障。
- **密钥不能重复**：同一密钥加密太多消息（约 $2^{32}$ 条），nonce 空间被耗尽，安全性下降——大数据量场景要定期换密钥。
- **先验标签，再处理**：解密流程必须「验标签通过才输出明文」，失败直接丢弃——任何「先给明文再验标签」的实现都打开了认证绕过的大门。<span class="marginnote">最后一条是 AEAD 实现里最常见的 bug：<strong>把「验签失败」与「验签通过但内容坏」区分开</strong>。正确的 AEAD 只有两种结果：完整输出或拒绝。任何第三种结果（如部分明文+错误码）都可能被侧信道利用。</span>

## 6 小结

- **认证加密（AEAD）**：机密性 + 完整性 + 真实性；解密先验标签，失败即拒绝。
- 组合顺序铁律：**Encrypt-then-MAC**（先加密、再认证密文）；其余顺序都有历史漏洞。
- **GCM** = CTR 加密 + GHASH 认证，全并行、可硬件加速，TLS/VPN 首选。
- **CCM** = CTR 加密 + CBC-MAC 认证，只用 AES、实现简单，无线/嵌入式标准。
- 共同前提：**nonce 唯一、密钥不超量复用、先验签后输出**。
