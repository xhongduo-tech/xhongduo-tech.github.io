## 为什么从 VPN 与 IPSec 开始

远程办公、分支机构互联、公共 Wi-Fi 保护——都依赖 **VPN（虚拟专用网）**：在公网上建立一条加密隧道，让远程设备像「插进内网」一样安全。IPSec（IP Security）是 IP 层的 VPN 标准，也是企业 VPN 的经典主力。理解 VPN 原理，等于理解「如何在不可信网络上建立可信通道」——这正是前面所有密码学知识的网络层应用。<span class="marginnote">一个澄清：VPN 不是一种加密算法，而是一种「隧道架构」——<strong>把 IP 包装进加密隧道再穿越公网</strong>。加密用什么（AES-GCM）、密钥怎么来（IKE）、包怎么封装（ESP）才是具体技术。IPSec 是其中最经典的一套。</span>

## 1 VPN 的核心思想：隧道封装

VPN 的隧道模型：

1. 主机 A 要发给主机 B 一个 IP 包。
2. VPN 网关把原始 IP 包**加密**，再**封装进一个新的外层 IP 包**（外层源/目的是两个 VPN 网关）。
3. 外层包穿越公网（公网只看到两个网关在通信），到达对端网关。
4. 对端网关解密、拆封、还原原始 IP 包，转交给真正的主机 B。

**关键**：公网上的攻击者只能看到「两个网关之间的加密流量」——看不到内网的 IP、端口、内容。这就是「虚拟专用网」：物理上在公网，逻辑上是专用网。

## 2 IPSec 的两个协议：AH 与 ESP

IPSec 用两个协议保护 IP 包：

**AH（认证头）**：提供完整性 + 源认证，**不加密**。它认证 IP 头与载荷（防篡改、防伪造），但内容透明。

**ESP（封装安全载荷）**：提供**加密 + 完整性 + 源认证**。它把载荷加密，并加认证标签。ESP 是实际主力——现代 IPSec 几乎只用 ESP。

**ESP 的两种模式**：

- **传输模式**：只加密 IP 包的**载荷**（原 IP 头保留）——用于主机到主机的端到端。
- **隧道模式**：加密**整个 IP 包**并加新 IP 头——用于网关到网关（VPN 的标准形态）。

## 3 IKE：IPSec 的密钥协商

IPSec 需要密钥——由 **IKE（Internet Key Exchange）** 协议负责：

1. **IKE SA 协商**（阶段一）：双方认证身份（预共享密钥或证书）、协商保护套件、建立 IKE 通道。
2. **IPsec SA 协商**（阶段二）：在 IKE 通道内，为具体的数据流协商 ESP 密钥与参数。

**IKEv2**（RFC 7296）是现代标准：用 DH 交换密钥、用证书/PSK 认证、支持 NAT 穿透与移动性。IKE 本质上是「TLS 握手」在 IPSec 里的对应物——协商、认证、派生密钥三位一体。<span class="marginnote">IKE 与 TLS 的对照：<strong>TLS 保护「连接」（在 TCP 之上），IPSec/IKE 保护「包」（在 IP 层）</strong>。TLS 对应用透明（浏览器直接用），IPSec 对<strong>上层全部</strong>透明（任何 TCP/UDP 应用都不用改）。IPSec 的「包级保护」让它能加密 ICMP、路由协议等 TLS 覆盖不到的流量。</span>

## 4 公式解析：ESP 隧道模式的包结构

$$
\text{外层 IP} \| \text{ESP 头} \| \text{加密}(\text{原 IP} \| \text{载荷}) \| \text{认证标签}
$$

三步拆解这条「ESP 隧道封装」：

- **第一步，加密**：原始 IP 包（含内层地址）整体加密——公网看不到内网拓扑。
- **第二步，认证**：ESP 头与加密载荷一起进认证标签——篡改任何字节都被检出。
- **第三步，封装**：加外层 IP 头（两个网关地址）与 ESP 头（含 SPI 标识「用哪个 SA」）——公网路由器正常转发，不知内情。

## 5 IPSec 的部署形态与局限

**部署形态**：

- **站点到站点（site-to-site）**：两个企业网关之间的 IPSec 隧道（分支机构互联）。
- **远程访问（remote access）**：个人设备连企业网关（常配合证书认证）。

**IPSec 的强项**：包级保护、协议无关、支持所有 IP 流量。

**局限**：

- **配置复杂**：IKE 参数、证书、NAT 穿透——上手门槛高。
- **NAT 兼容**：ESP 是 IP 层协议，NAT 改写地址会破坏认证——需 NAT-T（UDP 封装）。
- **性能**：包级加密对每个包都有开销。

这些局限推动了许多组织转向 **TLS VPN**（OpenVPN、WireGuard），下一节对比。<span class="marginnote">一个选型判断：<strong>IPSec 适合「站点到站点」的长期固定隧道；TLS VPN 适合「远程访问」与穿越 NAT</strong>。IPSec 在 IP 层、什么都加密，TLS VPN 在应用层、更容易穿透防火墙。两者不是替代关系，而是分工。</span>

## 6 小结

- **VPN 核心**：隧道封装——加密原包 + 外层新头穿越公网。
- **AH vs ESP**：AH 只认证不加密；**ESP** 加密 + 认证，是主力。
- **传输 vs 隧道模式**：传输模式只保护载荷，隧道模式保护整个包（VPN 标准）。
- **IKE**：阶段一认证 + 协商、阶段二派生 ESP 密钥——IPSec 的「握手」。
- 强项：包级保护、协议无关；局限：配置复杂、NAT 兼容难。
