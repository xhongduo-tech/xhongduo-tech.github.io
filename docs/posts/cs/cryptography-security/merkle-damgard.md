# 迭代式哈希结构：Merkle-Damgård 构造

<div class="epigraph">
<p>一个只能处理固定长度输入的函数，如何安全地压缩任意长度的消息？答案是：一块一块地咀嚼，并让每一口都改变状态。</p>

## 为什么从 Merkle-Damgård 开始

哈希函数要处理任意长度的输入，但内部的核心部件——**压缩函数**——只能处理固定长度。怎么把「固定长度的压缩」升级成「任意长度的哈希」？1979 年 Merkle 与 Damgård 独立给出了答案：**Merkle-Damgård 构造**。它把消息切成小块，逐块压缩，让每块都通过「状态链」影响后续。SHA-1、SHA-2 全系、MD5 都基于这个结构。理解它是理解 SHA 家族（及长度扩展攻击）的前提。<span class="marginnote">Merkle-Damgård 的意义超越了哈希本身：它证明了<strong>「压缩函数安全 ⇒ 整体哈希安全」</strong>——只要内部压缩函数满足碰撞安全，整个迭代结构就是碰撞安全的。这种「从部件到整体」的归约论证，是现代密码设计的标准范式。</span>

## 1 结构：填充、分块、链式压缩

Merkle-Damgård 构造分三步：

**第一步，填充**：把消息补到分组长度的整数倍。填充必须**包含消息长度**（Merkle-Damgård 加固），否则长度扩展攻击会钻空子。MD 填充通常是「补 1 + 补 0 + 64 位长度」。

**第二步，分块**：填充后的消息分成 $m_1, m_2, \ldots, m_k$，每块 $b$ 位。

**第三步，链式压缩**：用一个压缩函数 $f$，从初始向量 $IV$ 出发逐块更新状态：

$$
h_0 = IV, \qquad h_i = f(h_{i-1}, m_i), \qquad \text{输出 } H(m) = h_k
$$

最终状态 $h_k$ 就是摘要。**每一块都参与更新状态**，前一块的影响通过 $h_{i-1}$ 传播到后一块——这是「迭代」的含义。<span class="marginnote">直觉：哈希像一条「状态链」——<strong>每块消息都「搅拌」当前状态，最后的状态就是摘要</strong>。压缩函数 $f$ 像一台小型「密码机器」，链式结构把任意长度的输入喂给它。SHA-256 的 $f$ 内部是一组轮函数（类 AES 的 SP 结构，但只加密状态的一半）。</span>

把「填充」用一个小例子讲清楚。SHA-256 的分块是 512 位（64 字节），要哈希的消息是 `abc`（3 字节）：

1. 先在消息末尾补一个 `1` 位（`0x80`），使总长 `3 + 1 = 4` 字节。
2. 继续补 `0` 位，直到长度与「64 位长度域」之间只剩 8 字节空间：即补到 $64 - 8 = 56$ 字节。
3. 最后 8 字节写入原始消息长度（按比特计，`abc` = 24 位 = `0x0000000000000018`）。

于是填充后的块 = `abc` + `0x80` + 52 个 `0x00` + `0x0000000000000018`——**恰好 64 字节**。注意长度域是关键：它让「`abc`」与「`abc` 后跟若干个 0 再补长度」在数学上可区分，这是 Merkle-Damgård 加固的一部分，也是防碰撞证明成立的前提。

## 2 为什么这样构造是安全的：归约证明

Merkle-Damgård 最漂亮的性质是可证明性：

**定理**：若压缩函数 $f$ 是抗碰撞的，则整个 Merkle-Damgård 哈希 $H$ 是抗碰撞的。

**证明（反证）**：假设攻击者找到 $H$ 的两个碰撞输入 $x \neq x'$（$H(x) = H(x')$）。顺着两条链比对各步状态：

若中间某一步状态不同但 $f$ 输出相同——直接得到 $f$ 的一个碰撞。
若直到最后一步状态都不同——最后 $f(h_{k-1}, m_k) = f(h'_{k'-1}, m'_{k'})$ 是 $f$ 的碰撞（注意长度编码使 $k \neq k'$ 时也不会同步）。

**无论哪种情况，都能从 $H$ 的碰撞推出 $f$ 的碰撞**。所以「$f$ 抗碰撞」⇒「$H$ 抗碰撞」。设计者只需把 $f$ 做到抗碰撞，迭代结构「免费」继承安全性。<span class="marginnote">这个证明的哲学：<strong>安全不是「整体难」而是「部件难 + 结构不拖后腿」</strong>。设计者把「难」集中在压缩函数上，迭代结构只是忠实地把难度传播出去——这大大简化了哈希设计的安全性分析。</span>

**辨析｜易错点：** 这里的归约方向容易记反。正确的方向是「$H$ 有碰撞 ⇒ $f$ 有碰撞」——所以「$f$ 抗碰撞」才能推出「$H$ 抗碰撞」。反过来，「$f$ 有碰撞」并不直接意味着「$H$ 有碰撞」：一个坏的压缩函数可能恰好在链式拼接下被「掩盖」。归约证明的价值恰恰在于它给出了「要做多少安全工作」的下限。

## 3 压缩函数：SHA-256 的心脏

SHA-256 的压缩函数 $f(h, m)$ 接收 256 位状态 $h$ 与 512 位消息块 $m$，输出新 256 位状态。内部结构类似一个「64 轮的迷你分组密码」：

**消息扩展**：把 512 位消息块扩展成 64 个 32 位字 $W_0, \ldots, W_{63}$（类似 AES 的密钥扩展）。
**轮迭代**：64 轮，每轮用 $W_t$ 与一组轮常数 $K_t$ 更新 8 个 32 位工作变量。
**加常量**：轮末把输入状态加回（feed-forward），保证压缩函数不可逆。

轮函数只用**位运算**（异或、右移、循环右移）与**加法**——无查表，所以 SHA-256 在无专门指令的 CPU 上也能稳定实现，且有 SHA-NI 指令集加速。<span class="marginnote">SHA-256 的「可逆性」设计：压缩函数若可逆，攻击者可反推中间状态；<strong>「加回输入」的 feed-forward 让它不可逆</strong>。这与 ChaCha20 的 feed-forward 是同一个思路——「输出前把输入加回来」在流密码与哈希里反复出现。</span>

这里可以顺手比较 SHA-256 与 MD5/SHA-1 的「同构性」：三者都是 Merkle-Damgård + 各自的压缩函数。MD5 是 4 轮 64 步、128 位状态；SHA-1 是 5 轮 80 步、160 位状态；SHA-256 是 64 步、256 位状态。**结构骨架完全一样，只有压缩函数与状态宽度不同**——这也解释了为什么 MD5/SHA-1 一被攻破，就「连累」人们对整个 MD 结构重新审视。

## 4 公式解析：链式状态的更新

$$
h_i = f(h_{i-1}, m_i), \qquad H(m) = h_k
$$

三步拆解这条「迭代主方程」：

- **第一步，看输入**：第 $i$ 块的压缩输入有两个——上一状态 $h_{i-1}$ 与当前块 $m_i$。$h_{i-1}$ 携带了之前所有块的「历史」，所以每块都影响最终摘要。
- **第二步，看状态**：$h_i$ 是新状态，成为下一块输入的「历史」。链式传递由此形成。
- **第三步，看输出**：最后一块压缩完的 $h_k$ 直接作为摘要。整个消息的每个比特都通过链影响了 $h_k$——这就是「任意长度 → 固定长度」的完成。

用一个「玩具压缩函数」把链式过程走一遍，不用关心真实 SHA-256 的细节。设压缩函数为 $f(h, m) = (h + m) \bmod 16$（纯演示，非安全设计），$IV = 0$，消息分两块 $m_1 = 5, m_2 = 7$：

- 第一块：$h_1 = f(0, 5) = 5$。
- 第二块：$h_2 = f(5, 7) = 12$。
- 摘要为 $H(m) = 12$。

现在把 $m_2$ 换成 $m_2' = 7$ 之外的任何值，$h_2$ 都会变；反过来，任何一块消息的改变都会沿着链传到最终状态。真实 SHA-256 只是把这里的「模 16 加法」换成 64 轮复杂压缩，但「**每块都改状态、状态逐块传播**」的结构完全一致。

## 5 Merkle-Damgård 的弱点：结构本身的软肋

Merkle-Damgård 结构自身有两个已知弱点，催生了后来 SHA-3 的海绵结构：

- **长度扩展攻击**：因为状态直接复用，给定 $H(m)$ 与长度，攻击者能构造 $H(m \| \text{pad} \| \text{extra})$ 而不需要知道 $m$——这对「用哈希当 MAC」是致命的（后文详述）。
- **多碰撞与 Herding**：迭代结构存在「拼接两个消息块形成同摘要」的代数技巧，让攻击者在特定场景下比 $2^{n/2}$ 更快地制造多碰撞。

这些弱点不破坏「抗碰撞」本身，但削弱了哈希在**其他安全角色**（如密钥化、承诺）里的适用性——所以现代设计转向了海绵结构。<span class="marginnote">一个工程教训：<strong>「抗碰撞」的哈希未必适合所有用途</strong>。Merkle-Damgård 哈希做 MAC 会被长度扩展攻击、做随机预言会有 Herding——安全属性与安全角色要一一匹配。这正是 SHA-3 重新设计结构的原因之一。</span>

把 Merkle-Damgård 与 SHA-3 的海绵结构并排对比，能看清「为什么换结构」：

| 维度 | Merkle-Damgård（SHA-1/SHA-2） | 海绵结构（SHA-3/Keccak） |
| --- | --- | --- |
| 消息处理 | 单向链式压缩 | 吸收-挤出（双向混合） |
| 长度扩展 | 存在 | 不存在（状态被挤出后不可再延伸） |
| 输出 | 固定状态直接作摘要 | 可调输出长度（可当 PRF/流密码） |
| 抗多碰撞 | 较弱 | 较强 |

关键差异一句话：**海绵结构把「长度扩展」从根上消灭**——吸收阶段结束后状态被「挤出」，攻击者无法在不知道消息的情况下继续延伸摘要。这也让 SHA-3 直接可当 MAC/PRF 用，弥补了 SHA-2 的短板。

## 6 小结

- **Merkle-Damgård**：填充（含长度）→ 分块 → 链式压缩 $h_i = f(h_{i-1}, m_i)$，输出 $h_k$。
- **归约安全**：$f$ 抗碰撞 ⇒ $H$ 抗碰撞——「部件难、结构不拖后腿」。
- SHA-256 的 $f$：消息扩展 + 64 轮位运算 + feed-forward，无查表、可硬件加速。
- **结构弱点**：长度扩展攻击、Herding/多碰撞——催生了 SHA-3 的海绵结构。
- 认识：MD 构造是 SHA-1/SHA-2 的骨架，理解它是读懂现代哈希演进的第一课。
