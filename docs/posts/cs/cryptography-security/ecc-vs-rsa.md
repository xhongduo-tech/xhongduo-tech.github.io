## 为什么从 ECC 与 RSA 的对比开始

RSA 统治了公钥密码近半个世纪，但 ECC 在 2000 年代后全面崛起。两者的分水岭不在「算法谁更安全」，而在**同一个安全强度下，ECC 的密钥短得多**。这个「密钥长度差」带来一串连锁好处：更小的证书、更快的握手、更省的带宽。这一节把两套体制放在天平上，讲清「安全强度」这个统一的度量，以及 ECC 的代价与适用边界。<span class="marginnote">一个关键认知：<strong>「密钥长度」不是安全强度，只是它的代理</strong>。RSA-2048 与 ECC-256 的「位数」差了 8 倍，但安全强度（抗攻击的等价格）都是约 112–128 位。比较两个体制，要看安全强度，不能看比特数。</span>

## 1 安全强度：统一的比较单位

**安全强度（security strength）**：攻击者破解该体制所需的运算量，用「等价于破解多少位对称密钥」来表示。NIST 给出了标准换算：

| 对称强度 | RSA 模数 | ECC 曲线 | DH 模数 |
| --- | --- | --- | --- |
| 80 位 | 1024 位 | 160 位 | 1024 位 |
| 112 位 | 2048 位 | 224 位 | 2048 位 |
| 128 位 | 3072 位 | 256 位 | 3072 位 |
| 192 位 | 7680 位 | 384 位 | 7680 位 |
| 256 位 | 15360 位 | 512 位 | 15360 位 |

看 128 位这一行：RSA 要 3072 位，ECC 只要 256 位——**差 12 倍**。这个差距的来源，正是上一节说的：RSA 的分解攻击有亚指数算法（数域筛），ECC 的 ECDLP 只有 $O(\sqrt{n})$ 的通用算法。<span class="marginnote">直觉锚点：<strong>攻击者每「多花一位对称强度」需要翻倍算力；RSA 要靠位数线性增长撑住，ECC 靠平方根增长天然省</strong>。位数的立方复杂度让 RSA 的密钥增长特别「昂贵」，这是 ECC 占优的结构性原因。</span>

**辨析｜易错点：** 「ECC 比 RSA 安全」是个含混的说法。准确的说法是：**在相同安全强度下，ECC 密钥更短**。若都取「256 位强度」，ECC 用 512 位、RSA 要用 15360 位——两者「同样安全」，但 ECC 短 30 倍。说「ECC 更安全」只在你用「同样位数的 RSA 与 ECC」比较时才成立，而现实中没人这么比。

## 2 为什么密钥短有连锁好处

ECC 的 256 位 vs RSA 的 3072 位，不是「省点存储」这么简单，而是全链路的改善：

**证书更小**：HTTPS 握手时证书要传输，ECC 证书比 RSA 小一个数量级——弱网下的握手更快。
**握手更快**：密钥协商的运算量小，TLS 握手的 CPU 占用更低，服务器可支撑更多并发。
**功耗更低**：物联网芯片、智能卡、区块链节点——短密钥意味着更省电、更省内存。
**随机数要求更低**：短密钥生成需要的熵与计算更少。

在移动端与 IoT 场景，这些差异是「能不能落地」的差别。<span class="marginnote">一个容易被忽视的点：<strong>密钥生成速度</strong>。RSA 生成 3072 位密钥要测很多候选素数，通常秒级；ECC 生成 256 位密钥只需一次随机标量乘法——毫秒级。这在「频繁生成短期证书」的场景（如 ACME 自动续期）里是实打实的优势。</span>

| 场景 | RSA 的代价 | ECC 的收益 |
| --- | --- | --- |
| HTTPS 证书 | 大、握手慢 | 小、握手快 |
| IoT/智能卡 | 功耗高 | 省电省内存 |
| ACME 自动续期 | 密钥生成秒级 | 毫秒级 |
| 弱网移动端 | 传输慢 | 明显更快 |

## 3 ECC 的代价与弱点

ECC 并非免费午餐，它有自己的代价与攻击面：

**实现更难**：标量乘法、点验证、曲线参数——每一处都可能出错，出错就出漏洞。RSA 的模幂实现相对简单。
**信任问题**：NIST 曲线的参数来源曾受质疑（怀疑 NSA 埋后门——至今无证据，但信任被削弱）。Curve25519 的透明设计部分回应了这种不信任。
**侧信道与故障注入**：ECC 的标量乘法天然吃侧信道；RSA 有 CRT 故障注入，ECC 有「无效曲线」「阶退化」等特殊攻击面。
**专利历史**：ECC 早期有 Certicom 的专利争议（已过期），阻碍过早期采用。<span class="marginnote">一个值得记住的「信任教训」：<strong>参数来源不透明的算法，无论数学多安全，都难以获得生态信任</strong>。NIST 曲线的争议让「可解释的参数来源」成了新一代密码（Ed25519、后量子）的设计要求——这是 RSA/ECC 时代留下的遗产。</span>

**重点：ECC 的「短密钥优势」与「实现复杂度」是硬币的两面。** 数学上更优越的体制，往往在工程上更难做对。这也是为什么 Curve25519 / Ed25519 类「简单实现也安全」的曲线成为现代首选——它们把「实现的坑」尽量填平。

## 4 公式解析：安全强度的换算逻辑

$$
\text{ECC 攻击复杂度} = O(\sqrt{n}) \approx 2^{128}, \quad \text{RSA 攻击复杂度} = L_n[1/3, 1.92]
$$

三步拆解「为什么长度差这么多」：

- **第一步，看 ECC**：群的阶 $n \approx 2^{256}$，最佳通用攻击 Pollard's rho 是 $O(\sqrt{n}) = 2^{128}$ 步——**阶减半就是强度**，所以 256 位曲线给 128 位强度。
- **第二步，看 RSA**：分解 3072 位 $n$ 的数域筛（GNFS）复杂度 $L_n[1/3, 1.92]$ 是**亚指数**——它比 ECC 的平方根算法「更会利用结构」，所以同样 128 位强度要 3072 位。
- **第三步，读出结论**：ECC 的强度「线性」地随密钥增长（每多 2 位阶 = 多 1 位强度），RSA 的强度「亚线性」地随位数增长（位数翻倍强度只涨一点）——这决定了长期密钥规划里 ECC 的绝对优势。

**重点：强度增长的「效率」是本质区别。** ECC 是「每 2 位阶换 1 位强度」（高效率），RSA 是「位数增长但强度涨得慢」（低效率）。到了 256 位强度这一档，RSA 的 15360 位已经笨重到失去实用性，而 ECC 的 512 位依然轻巧——这就是为什么后量子时代到来前，ECC 是公钥密码的效率天花板。

## 5 实际选择：谁在什么场景用谁

现实中两套体制不是二选一，而是共存分工：

- **TLS 1.3**：默认 ECDHE（P-256 / X25519）+ 签名（ECDSA 或 EdDSA）；RSA 签名仍被支持但逐步退场。
- **证书**：新一代证书用 ECDSA 或 Ed25519 签名，比 RSA 证书小、验证快。
- **SSH**：默认 Ed25519（ECC 签名），RSA 老密钥仍可登录。
- **PGP/邮件**：RSA 传统深厚，ECC 逐步渗透。
- **后量子过渡**：混合方案（如 X25519Kyber768）把 ECC 与格密码并排用——ECC 不会被立刻取代，而是先与格共存。

一句话：**新协议选 ECC，老系统过渡期兼容 RSA**。<span class="marginnote">密码敏捷性（crypto-agility）的实践：<strong>不要「赌」单一算法，而是设计成可随时切换</strong>。TLS 1.3 的密码套件、SSH 的多算法协商、后量子混合方案，都是「让算法可替换」的工程机制——这是应对量子威胁与算法风险的第一道防线。</span>

## 6 术语速查

| 术语 | 含义 |
| --- | --- |
| 安全强度 | 破解所需运算量，等价于对称密钥位数 |
| Pollard's rho | 解 ECDLP 的最佳通用算法，$O(\sqrt{n})$ |
| 数域筛（GNFS） | 分解大整数的最佳算法，亚指数 |
| 亚指数攻击 | 比多项式快、比指数慢的攻击——RSA 被其拖累 |
| ECDH / ECDSA | ECC 上的密钥交换与签名 |
| Ed25519 | 基于 Curve25519 的现代签名，实现友好 |

## 7 小结

- **安全强度**是统一度量：128 位强度 → RSA 3072 位、ECC 256 位、DH 3072 位。
- **密钥短的连锁好处**：证书小、握手快、功耗低、生成快——移动/IoT 场景的落地优势。
- **ECC 的代价**：实现复杂、NIST 曲线信任争议、特殊的侧信道/无效曲线攻击面。
- 换算逻辑：ECC 平方根攻击（强度随阶线性涨）vs RSA 亚指数攻击（强度涨得慢）。
- **分工现状**：新协议选 ECC（TLS 1.3、SSH、证书），老系统兼容 RSA；后量子时代走混合过渡。
- 强度增长效率：ECC「每 2 位阶换 1 位强度」高效，RSA「位数涨强度涨得慢」低效——256 位强度档 RSA 已笨重。
- 一句记忆：比较两套体制看「安全强度」，不看「比特数」——ECC 用更短的钥匙换同样的强度。
- 实现提示：若你选 ECC，优先 Curve25519/Ed25519 类「简单实现也安全」的曲线，别自造曲线参数。
- 一个工程判断：证书/握手体积敏感的 HTTPS 与 IoT 场景，ECC 是默认；遗留 RSA 只作兼容层保留。

- 一个换算自检：128 位强度时，RSA=3072 位、ECC=256 位、DH=3072 位——三者「等价安全」却「长度悬殊」。
- 一句话收尾：ECC 赢在「效率天花板」，RSA 赢在「历史与兼容」——后量子时代两者都将让位于格，但今天 ECC 是主角。

- 最后的提醒：无论选 RSA 还是 ECC，都要给「迁移」留接口——密码敏捷性比任何单算法都更值钱。
