## 为什么从缓冲区溢出开始

前面十五篇讲「通信安全」，从这一节起进入「软件安全」：**漏洞如何产生、如何利用、如何防御**。**缓冲区溢出（buffer overflow）** 是软件安全的第一课——它是最经典的漏洞类型，源于一个朴素的错误：**程序写入了比分配空间更多的数据**。栈溢出利用尤其致命：攻击者覆盖函数返回地址，把程序的控制流劫持到自己的代码。1996 年 Aleph One 的经典论文让它成为黑客的入门必修，至今仍是内存安全问题的总代表。<span class="marginnote">一个数据背景：<strong>缓冲区溢出曾是 1990–2000 年代的头号漏洞（蠕虫、远程入侵的常客）</strong>——Morris 蠕虫（1988）就利用 `fingerd` 的缓冲区溢出。现代防御（金丝雀、ASLR、内存安全语言）大大压低了它的可利用性，但「内存越界」作为一类问题仍是 C/C++ 系统软件的顽疾。</span>

## 1 内存布局：程序在内存里怎么排

理解栈溢出，先理解进程的内存布局（x86-64 简化）：

- **代码段**：程序的机器指令（只读）。
- **数据段/堆**：全局变量与动态分配（malloc）的内存。
- **栈**：函数调用时分配的局部空间，**从高地址向低地址增长**。

**栈帧**：每次函数调用压入一个栈帧，包含：

- 函数参数。
- **返回地址**（调用方继续执行的地址）。
- 保存的帧指针（RBP）。
- 局部变量。

**关键**：返回地址在栈帧的高地址侧，局部变量在低地址侧。**如果局部变量数组溢出向上覆盖，就能一路写到返回地址**——这就是栈溢出的几何基础。<span class="marginnote">栈「向下增长」与溢出「向上覆盖」的反直觉：<strong>栈向低地址长，但数组索引向高地址走</strong>——所以数组越界写「恰好」能碰到更早压栈的返回地址。这个方向性是栈溢出独有的「地利」。</span>

## 2 栈溢出的机制：覆盖返回地址

一个经典的脆弱代码：

```c
void vulnerable(char *input) {
    char buf[64];          // 64 字节局部数组
    strcpy(buf, input);    // 不检查长度地拷贝！
}
```

如果 `input` 超过 64 字节，`strcpy` 会**继续往上写**，覆盖：

1. 保存的 RBP（8 字节）。
2. **返回地址**（8 字节）。
3. 调用方栈帧里的其他数据……

**利用目标**：把返回地址改成攻击者想要的值（通常是攻击者注入的 shellcode 的地址），函数返回时 `ret` 指令就跳转到 shellcode——程序执行了攻击者的代码。

## 3 公式解析：溢出的偏移计算

$$
\text{返回地址偏移} = \text{buf 大小} + \text{填充} + 8(\text{RBP})
$$

三步拆解这条「定位返回地址」：

- **第一步，量出偏移**：攻击者先填入大量填充字符（如 `A`×N），用调试器/崩溃地址观察「返回地址被改成多少」——从而精确知道覆盖返回地址所需的偏移（对 64 字节 buf：`64 + 8 = 72` 字节处就是返回地址）。
- **第二步，放 payload**：在偏移之前放 shellcode（注入的可执行代码），偏移处填 shellcode 的地址。
- **第三步，触发**：函数返回时 `ret` 弹出「被篡改的返回地址」，CPU 跳进 shellcode，攻击者代码执行。

## 4 攻击的演变：从 shellcode 到 ROP

经典栈溢出直接注入并跳转 shellcode，但现代防御（栈不可执行）让它失效。攻击也随之演变：

- **Shellcode**：直接注入可执行代码（老办法）。
- **Return-to-libc**：不注入代码，把返回地址改为系统库函数（如 `system`）——绕过「栈不可执行」。
- **ROP（Return-Oriented Programming）**：把返回地址链成一段段「以 ret 结尾的指令片段（gadget）」，拼出任意行为——绕过 NX + ASLR（配合泄漏）。
- **堆溢出**：不碰栈，改写堆上的元数据或函数指针。

**攻击的进化史 = 防御的进化史**：每加一道防御，攻击者就发明一种绕过。<span class="marginnote">ROP 的核心洞察：<strong>「程序里已经存在所有需要的指令片段」——攻击者不注入新代码，只把现有代码「拼图」</strong>。返回地址链 = 一段段 gadget 的调用序列。这让「栈不可执行」彻底失效，也解释了为什么 ASLR（随机化地址）如此重要——它让攻击者「猜不到 gadget 在哪」。</span>

## 5 真实的缓冲区溢出：从理论到 CVE

缓冲区溢出不是教科书玩具，它一直是真实世界的高危漏洞：

- **Morris 蠕虫（1988）**：利用 `fingerd` 缓冲区溢出——史上第一个大规模蠕虫。
- **IIS/Web 服务器**：2000 年代大量 Web 服务被溢出攻击。
- **Heartbleed（2014）**：本质是**越界读**（缓冲区溢出的兄弟：读越界而非写越界）。
- **现代 C/C++ 系统**：浏览器内核、操作系统、网络协议栈仍在不断发现越界漏洞。

**根因**：C/C++ 不检查数组边界——「信任程序员」。现代缓解：内存安全语言（Rust）、编译器检查、运行时防护（下一节）。<span class="marginnote">一个时代判断：<strong>缓冲区溢出正在从「头号漏洞」退为「遗留系统漏洞」</strong>——Rust 等内存安全语言把「越界」变成编译期错误。但 C/C++ 存量巨大（Linux 内核、浏览器、旧系统），「内存安全」的迁移仍是最重要的安全工程课题之一。</span>

## 6 小结

- **缓冲区溢出**：写入超过分配空间——C/C++ 不检查边界的代价。
- **栈布局**：返回地址在栈帧高地址侧——数组越界上写可覆盖它。
- **利用**：`strcpy` 越界 → 覆盖返回地址 → `ret` 跳转 → 执行攻击者代码。
- **演变**：shellcode → return-to-libc → **ROP** → 堆溢出——每道防御催生一种绕过。
- 真实世界：Morris 蠕虫、Web 服务器、Heartbleed——内存越界是 C/C++ 系统的顽疾。
