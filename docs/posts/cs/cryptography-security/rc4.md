# RC4 算法及其偏差攻击

## 为什么从 RC4 开始

RC4 是历史上最传奇、也最波折的流密码：由 Ron Rivest 在 1987 年为 RSA 公司设计，多年作为商业秘密，1994 年匿名泄露到互联网。因为极其简单（约 20 行代码）、软件实现飞快，它统治了 SSL/TLS 与 Wi-Fi 的 WEP 协议近二十年。但 RC4 的密钥流存在**统计偏差**——某些输出字节比随机更常出现——这些偏差被一步步放大成完整攻击，最终让它被 TLS 1.3 与 WPA3 彻底清除。RC4 的兴衰是「实现简单 vs 密码学安全」这对矛盾的经典案例。<span class="marginnote">RC4 泄露事件本身就是密码学史的一课：它通过 Cypherpunks 邮件列表匿名发布，没有论文、没有同行评审，却因「够简单」被大规模采用。<strong>简单与可用，替代不了公开分析与形式化证明</strong>。</span>

## 1 算法：一个字节状态的排列

RC4 的核心是一个 256 字节的状态数组 $S[0..255]$，保存 0–255 的一个排列。算法分两个阶段：

**密钥调度（KSA）**：用密钥 $K$ 打乱 $S$ 的初始排列。

$$
j = (j + S[i] + K[i \bmod \text{len}(K)]) \bmod 256, \qquad \text{交换 } S[i], S[j]
$$

对 $i = 0$ 到 255 重复上式，完成初始化。

**伪随机生成（PRGA）**：每输出一个密钥流字节 $z$，更新两个索引并交换：

$$
i = (i+1) \bmod 256, \quad j = (j + S[i]) \bmod 256, \quad \text{交换 } S[i], S[j], \quad z = S[(S[i]+S[j]) \bmod 256]
$$

输出 $z$ 与明文异或即完成加密。RC4 的状态是 256 字节排列，内部熵约 $\log_2(256!) \approx 1684$ 比特——理论状态空间巨大，这正是它曾被认为安全的资本。<span class="marginnote">RC4 的优雅：<strong>整个密码就是一次交换和一个查表</strong>，没有任何乘法、无查复杂表，硬件/软件都极快。这也是它被 WEP、SSL 选中而非更安全的算法（当时）的原因——简单就是生产力，直到简单变成突破口。</span>

用一个「缩减版」例子（状态只有 4 个字节 $S[0..3]$）把交换逻辑走一遍，避免被 256 的大数字吓住：

1. 初始 $S = [0,1,2,3]$，设密钥字为 $K[0]=1, K[1]=0$。
2. KSA 第一轮：$i=0$，$j = (0 + S[0] + K[0]) \bmod 4 = 1$，交换 $S[0]$ 与 $S[1]$ → $S=[1,0,2,3]$。
3. KSA 第二轮：$i=1$，$j = (1 + S[1] + K[1]) \bmod 4 = (1+0+0)=1$，交换 $S[1]$ 与 $S[1]$（自交换，无变化）。
4. PRGA 第一字节：$i=1$，$j=(0+S[1]) \bmod 4 = 0$，交换 $S[1]$ 与 $S[0]$ → $S=[0,1,2,3]$，输出 $z = S[(S[1]+S[0]) \bmod 4] = S[1] = 1$。

可以看到：**整个流程里只有加、取模、交换、查表四种操作**，没有复杂结构——这正是 RC4 能塞进几百行汇编、在 1990 年代的硬件上飞快的原因。也正因如此，一旦密钥流出现偏差，攻击者不需要理解「算法的深意」，只要统计就够了。

## 2 密钥流偏差：随机性里藏着常数

RC4 的密钥流并非均匀随机，存在系统性偏差。最著名的两条：

**第二条字节偏差**：密钥流的第二个字节 $z_1$ 等于 0 的概率是 $2/256$ 而非 $1/256$（翻倍）。根源是 KSA 结束后 $S[1]$ 与 $S[S[1]]$ 的结构——这在 RC4 的早期输出里留下了「指纹」。
**弱密钥偏差（Fluhrer-Mantin-Shamir, 2001）**：当密钥 $K$ 满足特定形式（$K[0]+K[1] = 0$ 等）时，密钥流的前几个字节与密钥强相关。**WEP 的 IV 恰好把这种弱密钥直接喂给了 RC4**——这就是 WEP 被彻底攻破的数学根源。

这些偏差起初看似微不足道（概率翻倍也只是 $2/256$），但密码分析的精髓正在于此：**把微小偏差放大成全局攻击**。<span class="marginnote">2001 年的 FMS 攻击让 WEP 在几分钟内可破；2015 年，TLS 上针对 RC4 的偏差攻击（AlFardan et al.）用约 $2^{30}$ 个会话即可恢复部分明文。<strong>偏差从「理论存在」到「实战利用」的距离，取决于有多少样本可以收集</strong>——网络协议动辄上亿会话，给了偏差放大足够的土壤。</span>

把二十年间积累的主要偏差与攻击整理成一张「偏差谱系表」，能看清「研究如何一步一步逼近」：

| 年份 | 偏差 / 攻击 | 内容 | 实战影响 |
| --- | --- | --- | --- |
| 1996 | Roos 偏差 | 前 256 字节的密钥流与密钥字节相关性 | 分析起点 |
| 2001 | FMS 攻击 | 特定 IV 形式（弱密钥）泄露密钥字节 | WEP 几分钟可破 |
| 2007 | Klein 攻击 | 利用 KSA 状态泄露逐字节恢复 WEP 密钥 | WEP 完全失守 |
| 2013 | RC4 偏差统计 | 密钥流各位置的系统性偏向被大规模量化 | 宣告 RC4 不再安全 |
| 2015 | AlFardan 偏差攻击 | $2^{30}$ 会话可恢复 TLS 会话部分明文 | 促成 RFC 7465 禁用 |

这条谱系说明了一个方法论：**流密码的失败往往不是「一次性破解」，而是「偏差—放大—利用」的渐进过程**——每代研究者在前人发现的偏差上多走一步，直到攻击复杂度跌进实战范围。

## 3 攻击如何放大偏差：从字节概率到明文恢复

以 TLS 上的 RC4 偏差攻击为例，看「放大」的机制：

- **收集偏差表**：攻击者先离线测量 RC4 在大量随机密钥下每个输出位置的字节分布，得到「第 $r$ 个密钥流字节偏向哪个值」的统计表。
- **截获海量会话**：在真实网络里截获大量 TLS 会话的密文。每个会话的 RC4 密钥流都在**相同位置**有相同偏差。
- **统计重叠**：把同一明文字节位置上的密文字节按「猜测的密钥流字节」分类投票。因为真实密钥流在某位置偏向某值，投票结果会凸显——**出现频率最高的猜测就是正确的明文字节**。

攻击把「每次加密一个密钥流字节有一点偏差」累积成「上百万次加密后的显著投票优势」。这是典型的**统计密码分析**：不依赖算法被「破解」，只依赖分布不均匀被「累积」。

## 4 公式解析：第二条字节偏差的由来

$$
\Pr[z_1 = 0] = \frac{2}{256}
$$

三步拆解这条「看似不可思议」的结论：

- **第一步，理解 $z_1$ 的来源**：$z_1$ 是 PRGA 第二个输出。PRGA 先 $i=1$、更新 $j$、交换，然后输出 $S[(S[1]+S[j])\bmod 256]$。
- **第二步，找结构**：KSA 之后，若 $S[1] = 1$ 且 $j$ 恰好停在使 $S[1]+S[j] \equiv 0$ 的位置，则 $z_1 = S[0]$。这些条件在随机密钥下以高于 $1/256$ 的概率同时成立，导致 $z_1=0$ 的概率翻倍。
- **第三步，读出后果**：单个位置的 $2/256$ 偏差看似小，但若协议在每个会话的**同一位置**都使用密钥流的第二个字节（如 TLS 的固定位置），攻击者跨会话统计就能确认「这里偏向 0」——偏差从算法层面泄露到协议层面。

## 5 为什么 RC4 被判死刑：三连击

RC4 的败亡是三个层面合力：

- **理论层面**：密钥流非均匀，偏差可被统计放大；存在特定弱密钥。
- **协议层面**：WEP 用 IV 拼接密钥（弱密钥直接被触发）、TLS 的 RC4 套件把偏差暴露给跨会话统计。
- **生态层面**：TLS 1.3（2018）彻底移除 RC4；WPA3（2018）用 AES-GCM 替代 WEP/WPA 的 RC4 内核；浏览器与服务器在 2015–2016 年集体弃用 RC4。<span class="marginnote">2015 年，RFC 7465 正式宣布<strong>「RC4 不得再用于 TLS」</strong>。从 1987 年诞生到 2015 年退休，RC4 用了近三十年走完「简单→普及→偏差→攻破→淘汰」的完整生命周期——这是研究「如何评判一个密码」最好的标本。</span>

RC4 曾经的「应用版图」本身也是教科书素材——同样的算法，在不同协议里结局不同：

| 应用 | 使用方式 | 结局 |
| --- | --- | --- |
| WEP（1997） | IV + 秘密密钥直接作 RC4 密钥 | 弱密钥被 FMS/Klein 利用，彻底攻破 |
| SSL/TLS（~1996 起） | RC4 套件用于流式加密 | 偏差攻击恢复明文，2015 后禁用 |
| 微软 Office、PDF | 内部加密流 | 随实现迁移陆续弃用 |
| WPA/WPA2（部分） | RC4 用于 TKIP 的 MIC 保护 | 设计上有补丁，仍被优先淘汰 |

**一个密码的命运，一半由算法本身、一半由使用方式决定**——WEP 把 IV 直接拼进密钥，等于亲手把弱密钥喂给 RC4；而同样偏斜的 RC4，若不是 TLS 的会话数量足够大，偏差也未必能被放大成明文恢复。这提醒我们：选算法要选「容错」的，部署更要避免「把弱点直接暴露给统计」。

## 6 小结

- **RC4**：KSA 初始化 + PRGA 输出；256 字节状态排列，每字节输出一次交换+查表。
- **偏差**：$z_1 = 0$ 概率 $2/256$；FMS 弱密钥偏差（2001）直接击穿 WEP。
- **放大机制**：统计密码分析——离线建偏差表 + 跨会话投票，把微小偏差累积成明文恢复。
- 败亡三连：理论偏差 + 协议滥用（WEP/TLS）+ 生态清除（RFC 7465、TLS 1.3、WPA3）。
- 教训：**「简单好用」不能替代「公开分析」**；统计均匀是安全的必要非充分条件。

在下一节，我们看 RC4 的现代继任者——**ChaCha20**，它用 ARX 结构从设计上规避了统计偏差，成为 TLS 1.3 与移动时代的默认流密码。
