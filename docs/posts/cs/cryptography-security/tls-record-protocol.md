## 为什么从 TLS 记录协议开始

握手完成、密钥就位后，真正的数据传输由**记录协议（record protocol）**承载。它把应用数据切成分片、用 AEAD 加密、加记录头、逐条发送；接收方逐条解密、验证、重组。记录协议是「数据面」，握手的全部成果（密钥、算法、会话状态）最终都在这里兑现。理解记录协议，等于理解「HTTPS 的每一字节如何被保护」。<span class="marginnote">一个分层视角：<strong>握手层是「控制面」（谈条件），记录层是「数据面」（干活）</strong>——这个「控制面/数据面」分离的模式，在网络协议里反复出现（TCP 的握手 vs 数据、IPsec 的 IKE vs ESP）。</span>

## 1 记录层的处理流水线

TLS 发送一条应用数据（如 HTTP 响应），记录层做四步：

1. **分片（Fragmentation）**：把数据切成 ≤ 16KB 的记录（TLSPlaintext）。
2. **压缩（可选）**：TLS 1.3 已移除压缩（曾引致 CRIME 攻击）。
3. **加密与认证**：用 AEAD（AES-GCM 或 ChaCha20-Poly1305）加密并生成认证标签——**机密性 + 完整性一次完成**。
4. **装帧（Record Header）**：加 5 字节记录头（类型、版本、长度），组成 TLSCiphertext 发送。

接收方反向处理：验头 → 解密 → 验标签 → 重组 → 交给上层。

**记录头**：`content_type`（应用数据/握手/告警）+ `version`（TLS 1.2/1.3）+ `length`。类型字段让同一连接能承载不同协议内容。

## 2 每条记录的 nonce 与序列号

AEAD 需要**不重复的 nonce**。TLS 记录层为每条记录生成唯一 nonce：

- TLS 1.3：nonce = **隐式序列号**（每方向每连接递增）与 IV 的异或。序列号从 0 开始，每条记录 +1——**不可能重复**（除非记录数超过 $2^{64}$）。
- 序列号还是**防重放**的关键：接收方只接受「下一个序号」的记录，旧记录重放立即被拒。

**为什么隐式**：序列号不必出现在线路上（双方各自计数），省了带宽、也无从被篡改——它直接参与 nonce 派生与认证标签计算。

## 3 告警协议与关闭

记录层的旁边还有**告警协议（alert protocol）**，用于传递错误与关闭：

- **告警类型**：`close_notify`（正常关闭）、`bad_record_mac`（认证失败）、`handshake_failure`、`unexpected_message` 等。
- **严重级别**：`warning`（可继续）与 `fatal`（立即断开）。

**告警是安全信号**：`bad_record_mac` 表示「记录被篡改或密钥错误」——攻击者听到这个信号就知道「我的篡改被检测到了」。这既是防御（检测攻击）也是信息泄漏（反馈给攻击者）——所以 TLS 要求**告警处理本身不泄露过多细节**。

## 4 公式解析：AEAD 加密的一条记录

$$
\text{nonce} = \text{IV} \oplus \text{seq\_num}, \qquad \text{ciphertext} = \text{AEAD-Encrypt}_K(\text{nonce}, \text{plaintext}, \text{header})
$$

三步拆解这条「记录加密」：

- **第一步，nonce 派生**：每条记录的 nonce 是「固定 IV ⊕ 递增序列号」——唯一且不可预测。
- **第二步，AEAD 加密**：用会话密钥 $K$、nonce 加密明文；关联数据（associated data）是**记录头**——头被认证，改头即失败。
- **第三步，完整记录**：`TLSCiphertext = header || ciphertext || tag`。接收方验 tag → 解密 → 检查序列号——三重防护：机密性、完整性、防重放。

## 5 记录层的安全边界与历史教训

记录协议看似简单，历史上有多个因它而起的著名攻击：

- **BEAST（2011）**：针对 TLS 1.0 CBC 的可预测 IV——攻击者能逐块猜出明文。**修复**：TLS 1.1+ 显式 IV、TLS 1.3 彻底弃用 CBC。
- **CRIME/BREACH（2012/2013）**：压缩 + 记录长度泄漏——攻击者用「密文长度变化」推断明文内容。**修复**：TLS 1.3 移除压缩、HTTP 层禁用压缩响应。
- **Padding Oracle 系列（2014）**：CBC 填充校验的错误反馈——Lucky13 计时攻击。**修复**：AEAD 让填充校验彻底消失。
- **Heartbleed（2014）**：OpenSSL 的心跳扩展越界读——**泄露内存中的私钥**。**修复**：OpenSSL 补丁 + TLS 1.3 移除心跳旧实现。

**共同教训**：记录层的每个「可观测差异」（长度、错误、时间）都可能成为侧信道。<span class="marginnote">Heartbleed 是最特殊的记录层事故：它不是密码被攻破，而是<strong>实现 bug 把内存里的私钥泄露出去</strong>——影响两年间大多数 HTTPS 服务器，数百万私钥被认为可能泄露。它证明了：密码学安全 ≠ 实现安全，一个内存越界读就能让全部密码学归零。</span>

## 6 小结

- **记录流水线**：分片 → 加密（AEAD）→ 装帧（5 字节头）——接收反向处理。
- **nonce**：IV ⊕ 序列号；序列号双向递增、防重放、参与认证。
- **告警协议**：错误与关闭信号；`bad_record_mac` 是篡改检测信号。
- **AEAD 记录**：加密 + 认证 + 头绑定——机密性、完整性、防重放一体。
- 历史教训：BEAST/CRIME/POODLE/Heartbleed——记录层的每个可观测差异都是侧信道。
