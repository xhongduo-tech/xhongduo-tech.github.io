## 为什么支配关系无处不在

上一节的 SSA 需要支配边界，这一节把支配本身讲透。支配关系是 CFG 上的一种「必经」关系，它像一个坐标系统，把程序的结构性信息组织成树。一个优化器里，支配树被用于：SSA 构造、循环识别、冗余消除的合法性判断、代码布局的优化……说它是「程序的结构骨架」毫不夸张。<span class="marginnote">支配关系是图论与程序分析的一个典型交叉点：它本身是纯图概念（任何有向图都有支配者），但程序分析把它变成了优化器的常规武器。它在第三级《编译原理》与《算法设计与分析》里都会再次出现。</span>

**支配（dominance）**：在 CFG 上，基本块 $d$ 支配 $n$（记 $d\ \mathrm{dom}\ n$），若从入口（entry）出发的每一条到达 $n$ 的路径都经过 $d$。**直接支配者（immediate dominator）**：$d$ 是 $n$ 的直接支配者（记 $\mathrm{idom}(n)$），若 $d$ 严格支配 $n$，且 $d$ 不支配任何其他也严格支配 $n$ 的节点——即「$n$ 的支配者里最接近 $n$ 的那一个」。

## 1 支配的性质：从定义出发的三条推论

支配关系有若干直接推论，它们是后续算法的支点：

**自反性**：每个节点支配自己（$n\ \mathrm{dom}\ n$）。**传递性**：若 $a\ \mathrm{dom}\ b$ 且 $b\ \mathrm{dom}\ c$，则 $a\ \mathrm{dom}\ c$。**反对称性**：若 $a\ \mathrm{dom}\ b$ 且 $b\ \mathrm{dom}\ a$，则 $a = b$。

由此，**支配关系是入口节点上的一个偏序**，且每个节点（除入口外）有唯一的直接支配者。这两件事合起来，使支配关系可以画成一棵树。

**节点间的比较规则**：设 $a, b$ 是两个节点，则要么 $a$ 支配 $b$，要么 $b$ 支配 $a$，要么互不支配。注意「要么支配要么被支配」只在**祖先-后代**之间成立，平级节点互不支配——支配不是全序，而是「支配树」这个偏序。

### 一个 idom 判定的小例子

把「谁是直接支配者」在一条带分支的程序上走一遍。设 CFG 有节点：入口 E、A（`if`）、B（真分支）、C（假分支）、X（汇合）、Y（出口）。各节点的支配者集合：

$\mathrm{Dom}(E) = \{E\}$（入口只支配自己）。
$\mathrm{Dom}(A) = \{E, A\}$（到 A 必经 E）。
- $\mathrm{Dom}(B) = \{E, A, B\}$（到 B 必经 E 与 A）。
- $\mathrm{Dom}(C) = \{E, A, C\}$。
- $\mathrm{Dom}(X) = \{E, A, X\}$（到 X 必经 E 与 A，B 与 C 都不是必经）。
- $\mathrm{Dom}(Y) = \{E, A, X, Y\}$。

由「严格支配者中最近的那个」：$\mathrm{idom}(A) = E$，$\mathrm{idom}(B) = A$，$\mathrm{idom}(C) = A$，$\mathrm{idom}(X) = A$，$\mathrm{idom}(Y) = X$。

**支配树**：E 是根，A 是 E 的子，B、C、X 都是 A 的子，Y 是 X 的子。注意 B 与 C 是 A 的**平级子节点**——它们互不支配，正如「if 的两个分支互不支配」。而 X 也是 A 的子（不是 B/C 的子），因为到达 X 不经过 B 或 C——**「文本顺序上 X 在 B、C 之后」不影响支配关系**，支配只看路径必经。

两个常用性质值得记住：

- **支配的并合**：若 $d$ 支配 $n$，且 $d$ 支配 $m$，则 $d$ 支配「所有从入口到 $n$ 或 $m$ 的路径上的任意节点」——支配者是「路径必经点」，天然满足这种并合。
- **严格支配**：$d$ 严格支配 $n$（$d\ \mathrm{sdom}\ n$）当且仅当 $d\ \mathrm{dom}\ n$ 且 $d \ne n$。直接支配者就是在严格支配者中「最靠近」的一个。

## 2 支配树：把支配关系画成树

因为每个节点（除入口）有唯一直接支配者，把所有「$\mathrm{idom}$ 关系」画成一条边 $d \to n$（$d = \mathrm{idom}(n)$），得到的就是**支配树（dominator tree）**：

- 树的根是入口节点（entry）。
- 每个节点的直接支配者是它在树上的**父节点**。
- 节点 $d$ 支配 $n$，当且仅当 $d$ 在支配树上是 $n$ 的**祖先**。

这三条性质把「支配」这种全局路径性质，压缩成了树上的「祖先-后代」局部关系——查询「$d$ 支配 $n$ 吗」从「检查所有路径」变成「检查树上的祖先关系」，可以 O(1) 回答（配合 DFS 序的时间戳）。

**支配边界（dominance frontier, DF）**：节点 $n$ 的支配边界 $\mathrm{DF}(n)$ 是满足下面条件的节点 $x$ 的集合：$n$ 支配 $x$ 的某个前驱，但 $n$ 不支配 $x$。即「$n$ 的影响范围（$n$ 支配的区域）首次被打破的边界」。<span class="marginnote">支配边界的直觉：$n$ 支配了一片「$n$ 说了算」的区域；在区域的边界上，别的路径开始渗入，$n$ 不再说了算。SSA 的 $\phi$ 就插在这些边界上——因为那里才可能同时见到「来自 $n$ 的值」和「来自区域外的值」。</span>

### 支配的四种典型用途

支配关系在优化器里处处出没，先集中列四种最典型的用法，后面各节会反复遇到：

**SSA 构造**（上一节）：$\phi$ 插在定义点的支配边界上——这是支配边界最直接的应用。

**循环识别**（下一节）：回边 $a \to b$ 的定义就是「$b$ 支配 $a$」；自然循环的判定、循环头（header）的确认，全靠支配查询。

**代码外提的合法性**（下一节）：循环不变量外提要求「指令所在块支配所有循环出口」——「支配所有出口」正是支配关系做合法性判断的标准句式。这类「操作必须在所有出口之前执行」的证明，抽象出来都是支配查询。

**冗余消除与死代码**：若一条指令支配它的所有使用点，删除它不需要担心「某条使用路径上它没执行过」——这类「安全删除」的判据也回到支配。

**易错点：** 支配是「路径必经」，与「顺序在前」不是一回事。`if` 的两个分支里，分支 A 的代码在文本顺序上先于分支 B，但 A 不支配 B——它们互不支配（存在不经过 A 到达 B 的路径）。**支配是结构关系，不是文本顺序关系。**

## 3 计算支配者：Lengauer-Tarjan 算法

朴素的支配者计算是迭代的：从「全节点集」出发，反复收紧，直到不动点。设 $\mathrm{Dom}(n)$ 是支配 $n$ 的节点集合：

$$
\mathrm{Dom}(n) = \{n\} \cup \bigcap_{p \in \mathrm{pred}(n)} \mathrm{Dom}(p)
$$

入口处 $\mathrm{Dom}(\mathrm{entry}) = \{\mathrm{entry}\}$。直观：$n$ 的支配者 = $n$ 自己 + 「所有前驱都共同拥有」的支配者。这个式子直接、正确，但每轮要交所有前驱的集合，复杂度高。

实际工程里几乎都用 **Lengauer–Tarjan 算法**（1979）：它把支配者计算转化为「最近公共祖先」问题，在 DFS 树与半支配者（semi-dominator）的基础上一步到位，近乎线性 $O(E \cdot \alpha)$。算法骨架分三段：

1. **DFS 编号**：从入口做深度优先遍历，给节点标 DFS 号，得到 DFS 树。
2. **逆序计算半支配者**：按 DFS 号的逆序，对每个节点用「跨过回边到达的祖先」收紧它的半支配者候选。
3. **解析支配者**：由半支配者与已求出的支配者，直接确定 $\mathrm{idom}$。

**易错点：** 迭代式 $\mathrm{Dom}$ 公式的交运算，要求「$\cap$ 分配进前驱集」——它正确，但每轮都要重新交一遍所有前驱。初学者常误以为这个迭代式是「够用的实现」，在大图上它慢到不可接受。**工程标准是 Lengauer-Tarjan，迭代式只适合教学与超小函数。**

## 4 公式解析：直接支配者的迭代判定

把「谁是 $n$ 的直接支配者」写成可计算的判定。$\mathrm{idom}(n)$ 是满足两个条件的唯一节点 $d$：

$$
d\ \mathrm{dom}\ n,\ d \ne n,\ \text{且}\ \forall d' \ne d:\ \big(d'\ \mathrm{dom}\ n \implies d\ \mathrm{dom}\ d'\big)
$$

对这条式子做三步拆解：

- **第一步，看前两条**：$d$ 必须严格支配 $n$——这是候选资格的门槛。
- **第二步，看第三条**：对任何其他支配 $n$ 的 $d'$，$d$ 都要支配 $d'$——这说「$d$ 是所有支配者中最小/最靠下的那个」。这正是「直接」的含义：所有其他支配者都排在 $d$ 之上。
- **第三步，理解唯一性**：由支配的反对称性，同时满足这两条的 $d$ 至多一个；又由「非空支配集 + 偏序」保证至少一个。于是 $\mathrm{idom}(n)$ 良定义，支配树可以唯一构造。

## 5 小结

- **支配**是「所有路径必经」关系，满足自反、传递、反对称，是入口节点上的偏序。
- **支配树**以 $\mathrm{idom}$ 为边，把支配压缩成祖先-后代关系；「$d$ 支配 $n$」 = 「$d$ 是 $n$ 的祖先」。
- **支配边界**是 $n$ 的影响区边界，是 SSA $\phi$ 的安放处。
- 工程上支配者用 **Lengauer-Tarjan** 算法近线性求解；迭代式只适合入门。
- $\mathrm{idom}(n)$ 是「严格支配 $n$
