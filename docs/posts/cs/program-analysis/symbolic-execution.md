## 为什么符号执行是「路径敏感」之王

数据流分析回答「所有执行的平均性质」，抽象解释回答「安全超集」。**符号执行（symbolic execution）** 换了一个更直接的问题：**对每条具体路径，构造它的输入条件，并反解出真实输入。** 它把程序输入当作**符号**而非具体值，沿每条路径累积约束，最后用 SMT 求解器问「什么输入能走到这里」。它在测试生成、漏洞挖掘、程序验证里是现代工具链的核心（KLEE、angr、SymCC 等）。<span class="marginnote">符号执行的奠基：金（James King）1976 年的论文《Symbolic Execution and Program Testing》首次把「符号状态 + 路径条件」系统化；四十年后它成为安全领域最火的程序分析技术之一，KLEE 在 2013 年获得 ACM SOSP 时间检验奖。这是「理论老了半世纪，工程还正年轻」的典型。</span>

**符号执行（symbolic execution）**：用符号值代替具体输入执行程序，沿每条执行路径维护一个**符号状态**（变量到符号表达式的映射）与一个**路径条件**（该路径可达所需满足的输入约束），并用约束求解器判定路径可达性与生成测试输入。

## 1 符号状态：变量是「表达式」而不是「值」

普通执行里，变量绑定到一个具体值：执行 `x = y + 1`，若 $y = 5$，则 $x = 6$。符号执行里，输入 $y$ 用一个**符号** $\alpha$ 表示（未赋值的符号常量），执行 `x = y + 1` 后：

$$
x \mapsto \alpha + 1
$$

$x$ 绑定到一个**符号表达式**。符号状态 $\sigma: \mathrm{Var} \to \mathrm{SymExpr}$ 把每个变量映射到「当前已知的表达式」——它描述的是「程序到这个点，$x$ 如何由输入表达」这一族性质，而不是单个值。

**符号化的执行规则**与操作语义几乎一样，只是求值从「算数值」变成「构造表达式」：

- 赋值 `x := e`：$\sigma[x \mapsto \llbracket e \rrbracket_\sigma]$——$e$ 在符号状态下的求值是符号表达式。
- 分支 `if b`：**不选一边**，而是**分裂**——两边都探索，各加一条约束。
- 循环：符号执行**不执行无限循环**——它按路径展开，或对循环次数设上限。

**易错点：** 符号状态与抽象解释的抽象状态不同。抽象状态用**抽象值**（区间、多面体）覆盖一族具体值，是「粗化」；符号状态用**符号表达式**精确记录「关于输入的关系」，是「精确但可能无限」。符号表达式可以无限增长（循环里不断复合），所以符号执行需要**超时/上限**来保证终止——它不像抽象解释那样天然收敛。

## 2 路径条件：一条路径的「入场券」

**路径条件（path condition, PC）** 是到达当前程序点所需满足的输入约束的合取：

$$
PC = \bigwedge_{\text{沿途每个分支}} (\text{该分支的条件})
$$

程序在 `if (x > 0)` 处走真分支，PC 里加入 $x > 0$；后面在 `if (x < 10)` 走假分支，PC 里再加入 $\neg(x \lt  10)$。走到任意程序点，当前 PC 刻画了「哪些输入能走到这里」。

PC 是符号执行与 SMT 求解器的接口：

- **可满足性判定**：`SMT_solve(PC)` 可满足 ⟺ 该路径被某个真实输入走到。
- **测试输入生成**：求解器不仅说可满足，还给出一个模型——一个具体输入，直接就是一条测试用例。
- **死路径剪枝**：PC 不可满足，说明该路径不可达，不再展开。

**易错点：** PC 的不可满足 ≠ 程序有 bug。PC 不可满足只说明「这条路径没有输入能走到」——它可能是合理的（防御性分支、前置条件保证的路径）。**符号执行真正要抓的是「PC 可满足但路径走到错误点」**：构造「走到错误点且 PC 可满足」的公式，若可满足，就得到触发 bug 的输入。

## 3 引擎中的三大难题

符号执行的工程落地有三座大山：

**路径爆炸（path explosion）**：分支指数增长——每个 `if` 分裂两条路径，$n$ 个分支 $2^n$ 条路径。对策：**启发式优先级**（先探「更可能出错」的路径）、**合并（path merging）**（两条路径的 PC 求并后合并探索）、**bounded 深度**（限制展开深度）。<span class="marginnote">路径爆炸是符号执行的第一敌人。工业实践的标准组合：按覆盖/危险度启发式排序 + 循环深度上限 + 运行超时。完全消除爆炸不可行，控制它是有价值的工程艺术。</span>

**约束求解开销**：每条路径都要调 SMT 求解器，求解占整个符号执行 90%+ 的时间。对策：**增量求解**（路径间共享子问题）、**缓存**（复用已解的约束）、**简化 PC**（约束求值后化简，去掉已被蕴含的子式）。

**外部世界（environment）**：程序要与外部交互——文件、网络、系统调用。符号执行很难符号化整个操作系统。对策：**模型化**（把 read/write 建模成符号数组）、**具体化（concretization）**（外部调用返回具体值，牺牲精度保可行）。<span class="marginnote">KLEE 处理符号文件系统的方式：把文件内容建模成符号字节数组，read/write 操作符化成约束，这样「读文件」也变成路径条件的一部分。这是「符号化一切可能符号化的东西」的实践。</span>

### 符号执行与抽象解释的对比

初学者常把符号执行与抽象解释（第三篇）混淆，其实它们处在精度轴的互补两端。对比一张表：

| 维度 | 抽象解释 | 符号执行 |
| --- | --- | --- |
| 分析对象 | 抽象值（区间、多面体） | 符号表达式（含输入变量） |
| 路径敏感性 | 路径不敏感（合并路径） | 路径敏感（逐路径） |
| 循环处理 | 加宽强制收敛 | 有界展开（深度上限） |
| 可证明什么 | 全称性质（「所有执行安全」） | 存在性质（「存在输入触发 bug」） |
| 典型输出 | 程序点的不变量 | 路径条件 + 测试输入 |
| 终止性 | 天然保证（加宽） | 需人工上限 |

读这张表的三步：

- **第一步，看循环的差别**：抽象解释用加宽「一次收敛」，覆盖所有迭代；符号执行用有界展开「切一段」，只覆盖有限步。**抽象解释回答「整个循环」，符号执行回答「前 k 步循环」**。
- **第二步，看性质的差别**：抽象解释证「全称」——区间分析证「所有执行都不越界」；符号执行找「存在」——「存在一条路径到达错误点」。**验证用抽象解释，测试生成用符号执行**，各得其所。
- **第三步，看互补**：现代工具常两两结合——用抽象解释做「不可能路径」的粗剪枝，用符号执行做「可疑路径」的深挖。**一个保底、一个攻坚。**

### 一个符号执行的小例子：从 PC 到测试输入

把「PC → 测试输入」走一遍。设函数：

```c
int check(int x, int y) {
    if (x > 0) {
        if (y > x) return 1;
    }
    return 0;
}
```

符号执行从入口出发，$x, y$ 为符号 $X, Y$：

- 分支 1 `x > 0`：真分支 PC = $X > 0$，假分支 PC = $X \le 0$。两条都探索。
- 真分支下分支 2 `y > x`：真 PC = $X > 0 \land Y > X$，假 PC = $X > 0 \land Y \le X$。
- 三片叶子（返回 1、返回 0、返回 0）各带 PC。

对「返回 1」的 PC = $X > 0 \land Y > X$，SMT 求解：可满足，给一个模型如 $X = 1, Y = 2$。**这就是触发「返回 1」路径的测试用例。** 对另外两条 PC 各求一次，得到覆盖所有路径的三个测试用例。

**要点**：符号执行天然生成「覆盖全部可达路径」的测试集——比随机测试的覆盖率高得多。**代价**：路径数指数增长，小函数三五个分支就几十条路径；这就是路径爆炸的现实压力。

## 4 公式解析：分支分裂规则

符号执行最核心的规则是分支分裂。设当前符号状态 $\sigma$、路径条件 $PC$，执行 `if b` 时分裂为两个后继：

$$
\begin{aligned}
\text{真分支: } & (\sigma,\ PC \land \llbracket b \rrbracket_\sigma) \\
\text{假分支: } & (\sigma,\ PC \land \neg \llbracket b \rrbracket_\sigma)
\end{aligned}
$$

对这条式子做三步拆解：

- **第一步，看真分支**：走真分支，PC 追加 $\llbracket b \rrbracket_\sigma$——$b$ 在符号状态下的求值表达式。若 $b$ 依赖符号输入，这就是一条新的输入约束。
