## 为什么先做「传播」

「传播（propagation）」在编译器里指：把一个地方知道的信息，沿程序结构「送」到使用它的地方。**常量传播**送的是「此变量恒为某常量」这个事实，**复写传播**送的是「此变量等于彼变量」这个等式。它们本身不消除任何东西，但它们是几乎所有后续优化的**放大镜**——把冗余照出来，让死代码消除、强度削减等优化看到下手点。<span class="marginnote">在 SSA 形式下这两个传播尤其简单，因为它们的信息是「沿版本号直读」的：一个 SSA 变量要么已知常量，要么已知复写，要么未知。本节先讲 SSA 版本（现代默认），再对照普通形式的迭代版本。</span>

**常量传播（constant propagation）**：若某变量在所有到达的路径上都被赋以同一个常量，则把该变量的所有使用点替换成该常量。**复写传播（copy propagation）**：若某变量的值恒等于另一变量（经由复写语句 $x := y$），则把 $x$ 的使用点替换成 $y$。

## 1 常量传播：SSA 上的「直读」

在 SSA 形式里，每个变量只有一处定义。因此「$x_3$ 是不是常量」只取决于它的定义：若 $x_3$ 的定义是常量赋值 $x_3 = 5$，则处处可用 5 替换 $x_3$；若 $x_3 = \phi(x_1, x_2)$，则要看 $x_1, x_2$ 是否都是常量。这就成了**沿 SSA 依赖图做一次遍历**的问题，而不是整个函数的数据流迭代。

SSA 常量传播的算法（Wegman & Zadeck，1991）维护一个**格值**，每个变量取三种状态之一：

**未定（undefined / $\bot$）**：还没发现它的值，也尚未证明它非恒定。
**常量（constant / $c$）**：已确定恒为常量 $c$。
- **非常量（not-a-constant / $\top$）**：已证明不可能恒为常量。

**易错点：** 三值格的初值不是「未知」而是「未定」，两者有别。「未定」表示「暂时不知道但可能很快知道」；「非常量」才是「确认没戏」。从 $\bot$ 出发按常量规则逐条收束，遇到「两个常量不同」就升到 $\top$——一旦升到 $\top$，永远不能再降回常量。这正是单调性的体现：**信息只会越变越精确，不会反复**。

### 分支条件下的常量传播

常量传播的一个难点在于**分支条件的反馈**。经典例子：

```
x = 10
if (x < 5) {
    y = x      // 走不到：x=10 恒大于 5
} else {
    y = x + 1  // y = 11
}
```

若常量传播只在「定义—使用」间传播，`y = x` 与 `y = x + 1` 都会用「$x$ 是常量 10」来算：$y$ 的两路分别得到 10 与 11，$\phi$ 合并后 $y$ 非常量——**丢失了「第一个分支不可达」这个事实**。

**条件分支下的精确传播**：在分支 `if (x < 5)` 处，若 $x$ 已知常量 10，则条件可**折叠**——真分支恒不执行。折叠后整段变成 `y = 11`。这个「用常量把条件算出来」的优化叫**条件分支折叠 / 常量条件求值**，它与常量传播通常合并成一个遍：传播时遇到 `if (c)` 且 $c$ 可求值，就把分支替换为无条件跳转。

**为什么这重要**：它把「死代码」的判据从「值没用」扩展到了「路径不可达」——配合 DCE（下一节），`if (x < 5)` 真分支整块删除。常量传播、分支折叠、死代码消除三者的边界在此交汇。

**易错点：** 折叠 `if` 要小心**副作用**。`if (c) f(x) else g(y)` 若 $c$ 折叠为真，`g(y)` 不可达可删，但 `f(x)` 的调用必须保留——**折叠删的是「不可达分支」，不是「未使用代码」**；有副作用的调用在可达分支里绝不能删。

### 传播优化的局限：何时它会失效

看到这里，你可能会问：传播这么好，为什么不是「唯一的优化」？因为它有三条硬边界：

**非常量运算**：`x = y * 2` 若 $y$ 是输入（非常量），常量传播无能为力——它只能传播「已知的常量」，不能发明新常量。这类「代数性质」（如 `y*2` 与 `y<<1` 等价）要靠强度削减等其他优化。

**精度天花板**：$\phi$ 规则「全同才常量」意味着只要有一条路径带来不同值，结果就非常量。`if (c) x = 1 else x = 2` 之后 `x` 恒非常量——即使 $c$ 在程序里永远是真。**传播不追踪「路径不可达」时，遇到分支就丢精度**（除非与分支折叠联动）。

**格值爆炸**：传播依赖三值格的单调收敛。若程序的变量依赖链很长（几十层定义），格值要沿整条链传播，工作表会推很久。**传播的代价是「链长 × 变量数」**，链极长时也非免费。

**这三条边界共同说明**：传播是优化流水线里的一环，不是全部。它负责「把已知事实送出去」，而「发现新事实」（代数、路径、全局）由其他分析承担——**优化的分工，和程序分析的分工一样，是各司其职的协作。**

规则逐条如下，对每一条 SSA 指令：

- 常量赋值 $x = c$：$x$ 得常量 $c$。
- 运算 $x = y \ \mathrm{op}\ z$：若 $y,z$ 均为常量，则 $x$ 得 $\mathrm{op}$ 的结果；否则 $x$ 得非常量。
- 复写 $x = y$：$x$ 继承 $y$ 的格值（若 $y$ 尚未定，先记下待定，等 $y$ 定了再更新）。
- $\phi$ 函数 $x = \phi(x^{(1)}, \dots, x^{(k)})$：若所有参数同为常量 $c$，则 $x = c$；若存在两个不同的常量，或任一参数为非常量，则 $x$ 为非常量；否则先未定，随参数更新。<span class="marginnote">$\phi$ 的规则精妙在「全同才常量」：只要有一条路径带来不同的值，$x$ 就非常量——这正对应 $\phi$ 的「按路径取值」语义。SSA 把「到达定值分析」压缩进了这一条 $\phi$ 规则。</span>

算法用工作表驱动：格值更新的变量入表，重算依赖它的使用点，直到工作表为空。

## 2 复写传播：替换等式

复写传播针对的是这类语句：$x := y$（或 $x_3 := x_1$ 的 SSA 版本）。它把「$x$ 现在等于 $y$」这条信息沿 SSA 图送出去：所有用到 $x$ 的地方，若 $y$ 在那一点可用且不被重定义，就用 $y$ 替换。

**SSA 版本尤其干净**：因为每个变量只定义一次，$y$ 的值在 $x$ 的定义之后、任何 $x$ 的使用点都不变——不存在「$y$ 被重定义」的干扰。于是复写传播变成：遇到 $x = y$，把所有 $x$ 的使用点替换成 $y$，然后删除这条复写语句。若替换后 $y$ 的用途链只剩这个复写，$y$ 的定义也可能变死。

**为什么复写传播有用**：它把「中间变量的别名」剥掉，让后续分析看到本质。典型场景：`t = a + b; x = t;` 经复写传播变 `t = a + b; x = a + b;`，公共子表达式消除再认出 `t` 与 `x` 用的是同一个 `a + b`。**复写传播本身不优化，它替别的优化「拆包装」。**<span class="marginnote">这也解释了为什么编译器手册里复写传播常与「合并（coalescing）」并列：删复写后，$x$ 与 $y$ 可以共享同一个物理寄存器（在 SSA 消去阶段）。SSA 的 $\phi$ 参数常伴随复写，把它们合并掉是寄存器分配的前置。</span>

## 3 两个传播如何协同：一个完整例子

看一个浓缩的例子，体会传播的「放大镜」作用。设 SSA 代码：

```
x_1 = 3
t_1 = x_1 * 4
y_1 = t_1
z_1 = y_1 + 1
return z_1
```

逐步作用：

- **第一步，常量传播**：$x_1 = 3$ 是常量；$t_1 = x_1 * 4$ 的输入是常量，算出 $t_1 = 12$；$z_1 = y_1 + 1$ 待定（$y_1$ 还未定）。
- **第二步，复写传播**：$y_1 = t_1$ 是复写，$y_1$ 的使用点替换为 $t_1$，删掉 $y_1 = t_1$。现在 $z_1 = t_1 + 1$。
- **第三步，常量传播再收束**：$t_1$ 已定 $12$，$z_1 = 13$；$return\ z_1$ 变成 $return\ 13$。
- **第四步，死代码消除接力**（下一节）：$x_1, t_1, y_1$ 的定义全部无用了，整段代码塌缩成 `return 13`。

这个例子说明传播的协同模式：**常量传播产生常量，复写传播拆别名，死代码消除收割冗余**。它们按固定顺序跑，一轮接一轮，直到不动点——编译器优化器的「遍」就是这样排队的。

## 4 公式解析：常量传播的格值规则

把三值格的偏序与运算规则写成精确形式。设变量 $v$ 的格值 $Val(v) \in \{\bot\} \cup \mathbb{Z} \cup \{\top\}$，偏序 $\bot \sqsubseteq c \sqsubseteq \top$。复写规则与 $\phi$ 规则的统一形式用 meet：

$$
Val(x) = \bigsqcap_{i} Val(x^{(i)}) \qquad (\text{对复写与 }\phi\text{ 的每个参数})
$$

对这条式子做三步拆解：

- **第一步，看 meet 的方向**：$\bot \sqsubseteq c \sqsubseteq \top$ 意味着 meet（取最大下界）给出「已知信息里最具体的一个」。两个常量 $5 \sqcap 5 = 5$；常量与非常量 $5 \sqcap \top = 5$——非常量「不贡献具体信息」，meet 保留常量。
- **第二步，看冲突**：$5 \sqcap 7$——两个不同常量，它们的最大下界是什么？格上不存在比它们都小的非常量，只有 $\bot$；但 $\bot$ 表示「未定」，冲突意味着「确定非常量」= $\top$。于是约定 $5 \sqcap 7 = \top$。**meet 在这儿把「矛盾」编码为「非常量」。**
- **第三步，看规则统一**：复写 $x = y$ 就是单参数 meet，$Val(x) = Val(y)$；$\phi$ 就是多参数 meet。三值格配 meet，一条公式同时覆盖复写与 $\phi$——这正是「一个框架多种实例」在传播优化里的回响。

## 5 小结

- **常量传播**：SSA 上沿依赖图直读，三值格（$\bot$ / 常量 / $\top$）单调收束，$\phi$ 用「全同才常量」。
- **复写传播**：把 $x = y$ 的等式送到使用点，剥掉中间变量别名，为其他优化拆包装。
- 两者用**工作表**驱动，格值更新即重算依赖点。
- 传播不优化，它是**放大镜**；与死代码消除等接力，多遍迭代到不动点。
