## 为什么指针分析决定一切

绝大多数现代语言都有指针或引用（C/C++、Java、JavaScript）。指针让「一条写语句到底改了哪块内存」变得需要分析才能知道。**指针分析（pointer analysis）** 回答「指针可能指向哪些对象」；**别名分析（alias analysis）** 回答「两个表达式是否可能指向同一对象」。它们的答案决定了几乎所有其他分析的可用性：常量传播要知道 `*p = 5` 改不改 `x`，死代码消除要知道 `*p` 有没有副作用，并行化要知道两个循环迭代是否冲突。<span class="marginnote">业界有句大实话：指针分析是静态分析的「瓶颈中的瓶颈」——它慢，其他分析跟着慢；它粗，其他分析跟着粗。因此指针分析的精度-代价权衡，是整个静态分析工程最有价值的设计决策之一。</span>

**指针分析（pointer analysis）**：计算每个指针变量的**指向集（points-to set）**，即它可能指向的分配点（`malloc`、`new`、栈上变量）集合。**别名分析（alias analysis）**：判断两个表达式 $e_1, e_2$ 是否可能指向同一个对象——通常由指针分析的指向集派生：$e_1$ 与 $e_2$ 可能别名，若它们的指向集相交。

## 1 指向集：指针分析的核心对象

把「指针可能指向哪里」形式化。一个指针变量 $p$ 的**指向集**：

$$
\mathrm{pts}(p) = \{ o \mid p \text{ 可能指向对象 } o \}
$$

其中 $o$ 是程序中的**分配点**（abstract location）——`x = malloc()`、`p = new C()`、栈变量地址等。指向集里的每个对象，代表「内存里的一块抽象区域」。

从指向集派生别名关系：**$p$ 与 $q$ 可能别名，当且仅当 $\mathrm{pts}(p) \cap \mathrm{pts}(q) \ne \emptyset$**。交集非空，说明存在一块内存两个指针都可能指到。

**易错点：** 指向集是「可能」不是「必然」。$\mathrm{pts}(p)$ 里的对象是 $p$ **可能**指向的；分析是保守的——宁可多装，不可漏装。**别名关系同理：可能别名 ≠ 必然别名**。优化器利用的是「不可能别名」的结论：若 $\mathrm{pts}(p) \cap \mathrm{pts}(q) = \emptyset$，则 $p,q$ 永不别名，相关优化可以放心做。

## 2 精度-代价光谱：流不敏感到流敏感

指针分析的精度谱系，沿两把尺子展开：

**流不敏感（flow-insensitive）**：不分程序点，整个函数的指向集是一个全局关系。快（接近线性），但精度差——循环里的赋值和循环后的赋值混在一起，一个指针的指向集被「全程序」污染。Andersen 与 Steensgaard 都属于流不敏感，区别在合并策略。

**流敏感（flow-sensitive）**：每个程序点各自维护指向集，赋值按执行顺序传播。精确得多，但代价是「程序点 × 指向集」的内存与迭代开销，一般只在关键函数上用。

**上下文敏感（context-sensitive）**：区分不同调用点的分析（上一节）。指针分析 + 上下文敏感是黄金组合：虚函数调用解析、跨函数别名都靠它，但代价指数增长。<span class="marginnote">LLVM 提供了一族内建指针分析（basic、globals、steensgaard、dsa），精度与代价各不同；Clang 静态分析器对关键路径用流敏感 + 路径敏感的指针建模。选择哪一档，是「要分析的置信度」与「能接受的编译时间」之间的工程判断。</span>

**易错点：** 流不敏感 ≠ 错误，流敏感 ≠ 一定好。对「只关心会不会别名」的许多优化，流不敏感的不可能别名结论已够用；流敏感的优势在「局部精确到每个程序点」。**选精度档位，要看被分析的优化到底需要多细的信息。**

### 别名分析如何驱动优化决策

别名分析本身不产生优化，它是优化的「守门员」——一个优化的合法性常归结为「这两个表达式可能别名吗」。看三张决策表：

**公共子表达式消除（CSE）**：

| 条件 | 结论 |
| --- | --- |
| `*p` 与 `*q` 不可能别名，且期间无写入 | 可做 CSE（`*p` 与 `*q` 值相等可复用） |
| 可能别名 | 不可 CSE（`*q` 可能被 `*p` 的写入改变） |

**循环外提的合法性**：

| 条件 | 结论 |
| --- | --- |
| 外提指令写的内存与循环内其他写/读不别名 | 可外提 |
| 可能别名 | 不可外提（指令在循环内执行时机敏感） |

**并行化的可行性**：

| 条件 | 结论 |
| --- | --- |
| 第 $i$ 次迭代写的内存与第 $i+1$ 次迭代读写的内存不别名 | 可并行 |
| 可能别名 | 有数据竞争，不可并行 |

三张表共享同一个模式：**优化器问「可能别名吗」，别名分析答「不可能」时，优化才敢做**。反过来，「可能别名」的答案直接否决优化。所以别名分析的最优价值不是「精确地知道别名」，而是**「可靠地排除别名」**——能证明「不别名」的地方，就是优化的安全区。

**易错点：** 别名分析的「可能」语义常被误读为「概率」。$\mathrm{pts}(p) \cap \mathrm{pts}(q) \ne \emptyset$ 不代表「$p,q$ 通常别名」，只代表「存在一条路径/一个对象使它们别名」。**静态分析的结论是「存在性」，不是「频率」**——优化器必须按「可能存在」来保守决策。

### 别名分析的经典案例：type-based alias analysis

C 语言的 **TBAA（type-based alias analysis, 基于类型的别名分析）** 是最著名的轻量别名分析。它利用 C 的类型系统：**两个不同类型的左值通常不指向同一对象**。

规则：`int` 与 `char` 类型的对象不可能别名；`struct A*` 与 `struct B*` 的对象不可能别名。于是：

```c
float f;
int *p = (int *)&f;   // 未定义行为，TBAA 判定不别名
```

编译器据此敢做优化：`float` 的写入不会影响 `int` 的读取，可以重排。**TBAA 快（无分析、纯类型推导）但激进**——它依赖程序员遵守 C 的类型别名规则（strict aliasing rule），一旦程序有未定义行为（如用 `char*` 穿越类型读写），TBAA 可能给出错误结论。<span class="marginnote">TBAA 的激进引来了著名争议：Linux 内核曾依赖类型穿越（type punning）技巧，与 GCC 的 TBAA 优化冲突。为此 GCC 提供了 `-fno-strict-aliasing` 来关闭激进推断。这个案例说明：别名分析的「快」与「正确」之间的张力，在真实大型 C 代码里每天都在被考验。</span>

## 3 结构别名：字段与容器

真实指针很少只指「一个对象」，常指「对象的某个字段」或「容器的某个元素」。于是分析粒度又分两档：

**字段不敏感（field-insensitive）**：不区分 `p.f` 与 `p.g`，整个对象一个指向集。快，但两个字段被混为一谈——`p.f = x; q = p.g;` 会被误判为 $q$ 可能指向 $x$。

**字段敏感（field-sensitive）**：每个字段单独记指向集（如 `pts(p, f)`）。精确，但指向集数量随字段数增长。

**容器**（数组、`HashMap`）是更难的层次：数组 `a[i]` 与 `a[j]` 通常被当作「同一块抽象区域」（索引不敏感）——除非分析区分索引区间，而那往往贵得不可行。**工业界的默认是：字段敏感、容器不敏感**——字段是热点，容器建模到「粗粒度」即可。<span class="marginnote">对象不敏感（object-insensitive）与对象敏感（object-sensitive）是 Java 世界的经典分法：对象敏感按「分配点」区分对象，字段敏感按「字段」区分位置。现代 Java 静态分析（如 Soot、WALA）的组合策略通常是「分配点对象 + 字段」双敏感，这在精度与规模之间取得了被广泛接受的平衡。</span>

## 4 公式解析：Andersen 的约束规则

把 Andersen 流不敏感指针分析写全。设 $o$ 是分配点，$pts$ 是全局指向关系，约束规则归纳如下：

$$
\begin{aligned}
x = \mathrm{new}() &\Rightarrow \mathrm{new} \in pts(x) \\
x = y &\Rightarrow pts(x) \supseteq pts(y) \\
x = y.f &\Rightarrow pts(x) \supseteq \bigcup_{o \in pts(y)} pts(o.f) \\
x.f = y &\Rightarrow pts(x.f) \supseteq pts(y),\ \forall o \in pts(x) \\
\end{aligned}
$$

对这条式子做三步拆解：

- **第一步，看前两条**：分配与复制规则直接建立指向集的下界——复制把 $y$ 的整个指向集并入 $x$。这是约束系统（第 17 节）的实例化。
- **第二步，看字段读写**：读字段 $x = y.f$ 把「$y$ 可能指向的每个对象的 $f$ 字段」的指向集并入 $x$；写字段 $x.f = y$ 把 $y$ 的指向集并入「$x$ 可能指向的每个对象的 $f$ 字段」。**字段读写按「可能指向的对象集」逐个展开**——对象集越大，展开越粗。
- **第三步，看求解**：全部规则是「⊇ 下界」约束，最小解 = 最小闭包，用位向量 + 工作表迭代求解。**Andersen 精度高但 $O(n^3)$ 级；Steensgaard 把复制合并成图并查集、近线性但精度低——同题两解，光谱两端。**

## 5 小结

- **指针分析**计算指向集 $\mathrm{pts}(p)$，**别名分析**由指向集相交派生：$\mathrm{pts}(p) \cap \mathrm{pts}(q) \ne \emptyset$。
- 指向集是「可能」不是「必然」；优化器利用的是**不可能别名**。
- 精度谱系：流不敏感（快粗）→ 流敏感（准贵）→ 上下文敏感（最准最贵）。
- 粒度档位：字段敏感 / 容器不敏感是工业默认；对象敏感是 Java 世界的主流。
- **Andersen** 约束精确、$O(n^3)$
