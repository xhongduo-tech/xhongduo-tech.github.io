## 为什么是三件套

上一节我们识别出循环不变量与归纳变量，这一节把这两类发现变现。**循环不变量外提（loop-invariant code motion, LICM）** 把「每次迭代结果都一样」的计算搬到循环前；**强度削减（strength reduction）** 把乘法换成加法；**归纳变量消除（induction variable elimination）** 删掉多余的循环计数器。三件套共享同一个前提——上一节的自然循环识别，也共享同一个目标：**减少循环体内的指令数**。<span class="marginnote">循环体每少一条指令，收益要乘上迭代次数。所以「循环里的一条指令」不是一，而是「迭代次数」；这解释了为什么优化器对循环内指令如此斤斤计较。这也是编译器与深度学习里「bottleneck 分析」的同构思想。</span>

**循环不变量外提（LICM）**：把循环中「值在整个循环期间不变」的指令移到循环入口之前（preheader）。**强度削减（strength reduction）**：把循环内开销大的运算（乘法、除法）替换为等价的、逐迭代累加的低成本运算（加法、减法）。**归纳变量消除（IV elimination）**：当多个归纳变量步长相同、用途可替代时，删掉多余的那个，只保留一个并调整使用点。

## 1 外提：把不变的计算移出去

**循环不变量**的定义上一节已给：操作数要么是常量、要么定值在循环外、要么也是不变量。满足条件的指令，其值每次迭代都一样，完全可以只算一次。

**外提的条件**（漏一条就可能改语义）：

1. **指令是循环不变量**——值在循环期间不变。
2. **指令的出口块支配循环的所有出口**——或者等价地，指令所在块支配所有「可能离开循环」的边。保证这条指令在循环退出时已执行。
3. **循环内没有其他语句给指令的操作数赋值**——保证不变量判断不过时。
4. **循环内没有该指令的副作用**——外提不能把有副作用的调用搬走。

为什么第 2 条必要？因为若指令只在部分迭代执行（例如在 `if` 分支里），把它搬到循环前就可能在**一次也不该执行**的情况下执行了——改变了可观察行为。<span class="marginnote">更精确的判据是「dominates all exits」：外提的指令必须在任何出口路径上都已经执行过。若循环有多个出口，指令所在块要支配每一个出口边。这正是支配关系在优化里的又一次应用。</span>

外提的目标位置是上一节人工添加的 **preheader**——循环头之前的空块。指令搬进去，语义不变（preheader 恰好执行一次），还给了优化器一个干净的操作点。

**易错点：** 「不变量」是静态性质，「每次迭代值相同」是运行时事实。一条 `a = b * c` 若 $b,c$ 都在循环外定义，是静态不变量；但若循环里有 `print(b)` 之类可能改变内存的操作，$b$ 的真实值仍可能变——因此多数编译器对外提采取保守策略：**只有操作数定值在循环外、且循环内无可能修改它们的调用时，才外提**。

## 2 强度削减：乘法变加法

强度削减针对归纳变量的**线性函数**。设 $i$ 是归纳变量（每次迭代 $i \leftarrow i + 1$），循环内有：

```
j = 4 * i
a[j] = ...
```

每轮迭代都重新算 `4 * i`。强度削减把它变成：维护一个新的归纳变量 $j'$，初值 $4 \times i_0$，每轮迭代 $j' \leftarrow j' + 4$，然后 `a[j'] = ...`。

为什么划算？**乘法比加法贵得多**：在多数架构上整数乘法几个周期，加法一个周期，地址计算里尤其明显。把「每轮一次乘法」换成「每轮一次加法 + 循环外一次乘法」，收益与迭代次数成正比。

**算法要点**：

1. 识别基本归纳变量 $i$ 与派生归纳变量 $j = c_1 \cdot i + c_2$。
2. 在 preheader 初始化 $j' = c_1 \cdot i_0 + c_2$。
3. 在 $i$ 每次更新处，同步 $j' \leftarrow j' + c_1 \cdot step_i$。
4. 把所有 $j$ 的使用点替换为 $j'$，删除 $j$ 的定义。

**易错点：** 派生归纳变量的更新要与 $i$ 的更新**同步同处**，否则在「$i$ 已更新而 $j'$ 未更新」的中间程序点，$j'$ 与 $j$ 会脱节。若 $i$ 在多个地方更新（如循环体内有 `if` 分支改 $i$），每个更新点都要配上 $j'$ 的同步更新。

### 循环展开与软件流水：三件套之外的循环优化

外提、强度削减、归纳变量消除是循环优化的「老三样」，但现代编译器还有两个高频使用的兄弟：

**循环展开（loop unrolling）**：把循环体复制 $k$ 份，每轮迭代处理 $k$ 个原迭代。如：

```
for (i = 0; i < n; i++) a[i] = b[i] * c[i];
```

展开成「每轮处理 4 个 i」的形式，并补上尾部剩余（`n % 4` 次）。**收益**：减少循环控制开销（比较、跳转、计数器更新）在总执行中的占比；给指令级并行（ILP）更大空间——4 次独立的乘法可以并行发射。**代价**：代码膨胀、指令缓存压力增大。展开因子（unroll factor）按「代价模型」选取。

**软件流水（software pipelining）**：把循环迭代的各个阶段错开重叠——像流水线一样，让第 $i$ 次迭代的「读取」与第 $i+1$ 次迭代的「计算」同时进行。**收益**：隐藏访存延迟，充分利用多发射。**代价**：需要处理循环的 prologue（前奏）与 epilogue（尾声），代码生成复杂得多。<span class="marginnote">这两种优化的前提都是「循环体无跨迭代依赖」或「依赖已知」——再次回到程序分析：能否展开、能否流水，由循环迭代间的数据依赖决定。这正是第四篇《程序切片与依赖分析》里「循环并行化判定」的同款依赖分析。</span>

**易错点：** 展开与强度削减的交互要当心。展开后归纳变量多了 $k$ 份更新，若强度削减没有同步更新所有副本，会导致版本错乱。现代编译器把「展开」「削减」「变量消除」作为一个复合遍统一调度，而不是各自为战。

### 三件套之外的判断：什么循环值得优化

循环优化不是「对所有循环无脑做」。工程上每个优化都要先过「值不值得」的判断：

**收益的度量**：优化收益 = 每条指令节省的代价 × 循环迭代次数 × 执行频率。**外层循环的高频调用，比内层循环的低频执行更值得优化**——「哪层优化」要用频率计数（profile）而非结构决定。

**成本的度量**：代码膨胀（展开）、寄存器压力（多归纳变量）、可读性。**优化是「用空间换时间」的交易，膨胀到损害缓存就没赚到。**

**安全性的再确认**：外提、强度削减都假设「循环结构稳定」。一旦后续优化（如循环分裂、反转）改变了结构，前面的结论要重算——**优化遍之间是流水线，后一遍必须在前一遍的结论仍成立的前提下运行。**

**这三条判断共同说明**：循环优化的最终形态不是「套三件套」，而是「按代价模型决策、按安全性验证」的工程流水线——分析给「能」，代价模型决定「值」，正确性验证保证「没错」。

## 3 归纳变量消除：删掉多余的计数器

强度削减常常制造出**多个平行的归纳变量**：它们步长不同但功能重复。例如：

```
for (i = 0, j = 0; i < n; i++, j += 2) { ... }
```

$i$ 与 $j$ 都是归纳变量，步长分别是 1 与 2。若 $j$ 只被用来「数到 $2n$」、或与 $i$ 满足 $j = 2i$，则其中一个可以消去——所有 $j$ 的使用换成 $i$ 的表达式 $2i$（或反过来），再删掉 $j$ 的更新与终止测试。

**消除的价值**：每次迭代少一次比较、少一个寄存器的维护；寄存器分配的压力也减小——多一个归纳变量就多占一个物理寄存器。**归纳变量消除是强度削减的自然续篇**：强度削减把乘法变加法，归纳变量消除把平行的加法收敛成一个。

**算法要点**：

1. 对每个基本归纳变量，收集与之相关的派生归纳变量与终止条件。
2. 若两个归纳变量成比例（$j = c \cdot i$ 或 $j = c \cdot i + d$），且 $j$ 的用途可全部改写，则消去 $j$。
3. 改写终止测试：`while (j < limit)` 改成 `while (i < (limit - d) / c)`，注意除法的舍入语义——这一步最容易出错。<span class="marginnote">终止条件的改写是归纳变量消除的「险区」：`j = 2*i, j < limit` 改写为 `i < limit/2` 时，整数除法的向下取整可能改变循环执行次数。稳妥做法是保持原有测试基于「保留下来的那个变量」，或用无溢出语义的精确换算。</span>

## 4 公式解析：强度削减的替换恒等式

强度削减的正确性建立在一条算术恒等式上。设 $i$ 是步长为 $s$ 的基本归纳变量，$j$ 是派生归纳变量 $j = c \cdot i + d$。在迭代 $k$（$i_k = i_0 + k s$）：

$$
j_k = c \cdot i_k + d = c \cdot (i_0 + k s) + d = j_{k-1} + c \cdot s
$$

对这条式子做三步拆解：

- **第一步，看展开**：$j_k = c \cdot i_k + d$ 是派生定义；代入 $i_k = i_0 + k s$ 得到第二式——$j_k$ 关于 $k$ 是线性的。
- **第二步，看差分**：由线性性，$j_k - j_{k-1} = c \cdot s$——**相邻两轮迭代 $j$ 的增量恒定**。这就是「把 $j$ 变成每次加 $c s$ 的新归纳变量」的数学依据。
- **第三步，看收益**：原来的「每轮算 $c \cdot i + d$」是一轮乘法加加法；替换后的「每轮加 $c s$」只是一轮加法。**乘法被挤出循环体，只在 preheader 算一次初值 $j_0 = c \cdot i_0 + d$。** 这就是强度削减的全部秘密。

## 5 小结

- **LICM**：把循环不变量移到 preheader，条件是不变 + 支配所有出口 + 无副作用；preheader 是专门的外提锚点。
- **强度削减**：把派生归纳变量 $j = ci + d$ 换成每轮加 $cs$
