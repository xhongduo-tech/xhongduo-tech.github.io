## 为什么「i 不回退」是对的

KMP 敢让主串指针 `i` 永不回退，必须给出证明：**`i` 回退可能错过「更早的匹配起点」吗？** 答案藏在 next 数组的性质里——**失配时，从「原起点 + 1」到「当前 `i`」之间的任何位置都不可能是新的匹配起点**，因为模式串已经匹配过的部分（$T[1..j-1]$）足以排除它们。本节用**不变量**严格证明 KMP 的正确性，并用**摊还分析**证明它的 $O(n+m)$ 复杂度——这两块是「KMP 为什么成立」的完整答案。

## 1 KMP 的核心不变量

匹配过程中维护如下不变量：

**不变量：在每一步，$T[1..j-1]$ 与 $S[i-j+1..i-1]$ 恰好匹配，且 $j$ 是最小的「使上述成立且能继续」的候选位置。**

更实用地表述：**当前已确认「$S$ 中以 $i-1$ 结尾、长度为 $j-1$ 的子串 = $T[1..j-1]$」**——即模式串前 $j-1$ 位与主串当前窗口匹配。

**重点：KMP 的正确性 = 不变量「已匹配长度 $j-1$」的维护**——匹配则 `i++, j++` 保持不变量；失配则 `j = next[j]` 把不变量调整为「更短的已匹配前缀」——**这个调整不漏掉任何可能的起点**。<span class="marginnote">「<strong>不变量 = 算法正确性的锚</strong>」：<strong>每一步都保持「$T$ 的前 $j-1$ 位匹配 $S$ 的某窗口」</strong>。<strong>证明 KMP 正确 = 证明「匹配/失配两个分支都维持这个锚」</strong>——<strong>不变量方法论是算法证明的通用语言</strong>。</span>

## 2 失配时为什么可以「跳到 next[j]」

失配于 $S[i] \ne T[j]$，此时 $T[1..j-1] = S[i-j+1..i-1]$。要回答：**是否存在一个「更早的匹配起点」 $p < i-j+1$，使得从 $p$ 开始能匹配上？**

- 若存在这样的 $p$，则 $S[p..i-1]$ 与 $T[1..i-p]$ 匹配；
- 而 $S[p..i-1]$ 是 $S[i-j+1..i-1]$ 的后缀（因为 $p < i-j+1$）；
- 所以 $T[1..i-p]$ = 这个后缀 = $T$ 的某个真后缀——即「$T$ 的某真后缀 = $T$ 的前缀」。

**结论：任何「更早的匹配起点」都对应「$T[1..j-1]$ 的一个前缀=后缀重合」**——而 `next[j]` 正是「最长」的那个重合长度 + 1。跳到 `next[j]` 不会跳过「最长可复用」的位置，更早的位置（重合更短）在匹配继续时会被自然排除。<span class="marginnote">「<strong>更早的起点 ⇔ 更短的前后缀重合</strong>」是 KMP 正确性的核心观察：<strong>所有「可能的新起点」都藏在「$T[1..j-1]$ 的前缀=后缀」里</strong>。<strong>`next[j]` 取最长，等于「从最省力的起点继续」——更短的起点若可行，会在后续被逐步发现</strong>。</span>

## 3 公式解析：匹配的复杂度 O(n+m)

匹配阶段，`i` 每次循环要么 `i++` 要么不动（只 `j` 变）。如何保证 $O(n)$？

**摊还分析**：把 `i` 看作「前进的游标」，`j` 看作「窗口长度」：

$$
\text{匹配总代价} = O(n) \quad \text{（$i$ 最多前进 $n$ 次，$j$ 的回退由前进补偿）}
$$

- **第一步，读「i 单调」**：`i` 只增不减，至多前进 $n$ 次——主串扫描是线性的。
- **第二步，读「j 的账」**：`j` 每次回退到 `next[j]`，**回退的总量被前进的总量上界约束**——每前进一次至多「还」一点，总回退 ≤ 总前进。
- **第三步，读「求 next 同理」**：求 `next` 的循环里，`j` 单调前驱、`k` 沿 next 回退——**同样是摊还线性，$O(m)$**。总 $O(n+m)$。<span class="marginnote">「<strong>摊还：回退的总量 ≤ 前进的总量</strong>」是 KMP 线性的关键：<strong>看起来 `j` 可能来回跳，但「前进的步数」限制了「回退的步数」</strong>——<strong>像记账：每次回退都要「有余额」（前进过）才能发生</strong>。摊还分析的这一招，也用于并查集、栈的单调性分析。</span>

## 4 求 next 的复杂度分析

求 `next` 的循环：

```c
j = 1; k = 0; next[1] = 0;
while (j < m) {
    if (k == 0 || T[j] == T[k]) { j++; k++; next[j] = k; }
    else k = next[k];
}
```

- **`j` 单调**：每次 `j++`，最多 $m$ 次；
- **`k` 沿 next 回退**：回退总量被「`j` 前进时 `k` 的增量」上界约束；
- **总代价 $O(m)$**：与匹配阶段同构的摊还论证。

**重点：求 next 的复杂度和匹配完全平行——都是「一个单调游标 + 一个沿 next 回退的游标」，都摊还线性。** 这也是「求 next 是自己跟自己 KMP」在复杂度上的体现。<span class="marginnote">「<strong>求 next 与匹配是同构的摊还</strong>」：<strong>匹配里是 (i, j)，求 next 里是 (j, k)——结构一模一样</strong>。<strong>看懂一个的复杂度，另一个自动成立</strong>——「同构」让证明只需做一次。</span>

## 5 KMP 的复杂度总账与地位

| 阶段 | 复杂度 | 说明 |
| --- | --- | --- |
| 求 next | $O(m)$ | 自匹配，摊还线性 |
| 匹配 | $O(n)$ | 主串只扫一遍 |
| 总计 | $O(n+m)$ | 最优（必须读完全部输入） |

**重点：KMP 的 $O(n+m)$ 是「最优中的最优」——任何匹配算法至少要读一遍主串和模式串。** 它把朴素匹配的 $O(nm)$ 一举压到线性，是「用预处理换匹配速度」的经典。<span class="marginnote">「<strong>$O(n+m)$ = 理论的底线</strong>」：<strong>读一遍 $S$、读一遍 $T$，是最低必要成本——KMP 达到了它</strong>。<strong>「先花 $O(m)$ 预处理，再花 $O(n)$ 匹配」是字符串匹配的标准节奏</strong>——KMP、Boyer-Moore、Z 算法都遵循这个「预处理换速度」的范式。</span>

## 6 小结

- 不变量：每步保持「$T[1..j-1]$ 匹配 $S$ 的当前窗口」。
- 失配跳 next 不漏起点：更早起点 ⇔ 更短前后缀重合，next 取最长不跳过。
- 匹配复杂度：`i` 单调前进 $O(n)$，`j` 回退被前进补偿——摊还线性。
- 求 next 复杂度 $O(m)$：与匹配同构的摊还论证。
- 总复杂度 $O(n+m)$——理论最优。
- KMP 是「预处理换匹配速度」的范式代表。
