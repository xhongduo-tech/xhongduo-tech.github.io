## 为什么查找可以「免比较」

顺序查找 $O(n)$、折半 $O(\log n)$、B 树 $O(\log_m n)$——都靠「比较」缩小范围。**哈希表（hash table）**给出终极答案：**用哈希函数把关键字直接映射成存储地址**，查找变成一次计算——平均 $O(1)$。$O(n)$，「找」字都可以省掉。代价有两笔：一是**哈希冲突**（不同关键字映射到同一地址）需要解决（下节）；二是哈希函数本身要精心构造，让冲突尽量少。本节先立起哈希表的概念、装填因子这把「压力计」，以及几种经典哈希函数的构造方法。

## 1 哈希表与哈希函数

**哈希表（hash table）**：根据关键字直接计算存储位置的表。**哈希函数（hash function）**：把关键字 $key$ 映射为地址的函数 $H(key)$。

$$address = H(key)$$

**哈希地址**：$H(key)$ 的值。理想情况下，$H$ 把每个关键字映射到不同地址，查找、插入、删除都是 $O(1)$。

**重点：哈希的本质是「以空间换时间」+「以函数换比较」。** 它放弃「有序性」（不能范围查询），换来「平均 $O(1)$ 的定位」。

**「以空间换时间」具体换在哪**：表长 $m$ 通常远大于元素个数 $n$——装填因子 $\alpha = n/m$ 只有 0.5~0.75，意味着哈希表**空着一大截**。这些空位就是「为减少冲突预留的余量」：$\alpha$ 越低，冲突越少、查找越快，但空间浪费越多。**哈希表不是「装满」的表，而是「故意留空」的表**——留空是为了让「算地址 → 直接命中」的概率更高。理解了这个「空间换时间」的实质，就不会惊讶「哈希表为什么只有一半满还叫高效」了。<span class="marginnote">哈希与数组的关系：<strong>数组按下标 $O(1)$ 访问，哈希表把「任意关键字」变成「下标」</strong>。哈希 = 一把把任意键翻译成数组下标的钥匙。这一「翻译」让哈希表成为所有语言里 $O(1)$ 查找的底层。</span>

## 2 冲突与装填因子

**冲突（collision）**：两个不同关键字 $key_1 \neq key_2$，但 $H(key_1) = H(key_2)$。

**装填因子（load factor）**：

$$
\alpha = \frac{\text{表中已有元素个数 } n}{\text{表长 } m}
$$

- $\alpha$ 是哈希表「满」的程度——**$\alpha$ 越大，冲突概率越高，查找越慢**；
- 工程经验：链地址法 $\alpha$ 控制在 0.75 左右，开放定址法控制在 0.5~0.7 以下。

**装填因子的「双刃」**：$\alpha$ 小 → 冲突少、查找快，但空间利用率低（多数槽空着）；$\alpha$ 大 → 空间省，但冲突多、查找慢，甚至（开放定址）探测序列爆炸。**「0.75」正是这条曲线的甜点**：再低省不了多少时间、多浪费空间；再高时间开始明显变差。工程哈希表的「扩容阈值」就是在「空间成本」与「时间成本」之间做的最小化——**哈希表的健康管理，本质是装填因子的动态调控**。<span class="marginnote">装填因子是哈希表唯一最重要的「健康指标」：<strong>它直接决定冲突率与期望查找长度</strong>。当 $\alpha$ 超过阈值，就要「扩容 + 重新哈希」——专题篇《哈希表工程实现》会详细算这笔账。记住 <strong>$\alpha=0.75$ 是工程界的经典默认值</strong>（Java HashMap）。</span>

## 3 哈希函数的构造方法

一个好的哈希函数要「**计算快 + 分布均匀**」。经典构造法有四种：

**直接定址法**：$H(key) = a \cdot key + b$。线性映射，无冲突，但要求关键字分布已知且连续。
**除留余数法**：$H(key) = key \bmod p$，$p$ 取不大于表长的**素数**（或与 8 的倍数无关的数）。最通用。
**数字分析法**：分析关键字各位数字的分布，取分布均匀的若干位作地址。适合关键字已知、位数长的场景。
**平方取中法**：把 $key$ 平方，取中间几位。中间几位受所有位数影响，分布好。
**折叠法**：把关键字分成几段再叠加求和。

**重点：除留余数法是最通用、最常用的构造法——$p$ 的选择（素数）直接影响分布。** 选 $p$ 的直觉：避开「常见因子的倍数」，让地址尽可能均匀。<span class="marginnote">为什么 $p$ 常取素数？因为若 $p$ 是合数，而关键字恰以 $p$ 的因子为步长分布（如按 2、4 递增），$key \bmod p$ 会出现系统性聚集——<strong>素数让「间隔规律」被打破</strong>。这一细节在工程哈希表里被反复验证。</span>

## 4 公式解析：除留余数法的设计

$$
H(key) = key \bmod p, \qquad p \text{ 为不超过表长 } m \text{ 的素数}
$$

- **第一步，读「取模」**：地址落在 $[0, p-1]$，$p$ 应接近表长 $m$，避免「表大地址小」浪费。

**几种构造法的适用场景速记**：**直接定址法**——关键字本身是连续整数（如学号段连续），线性映射零冲突，但不连续就浪费；**数字分析法**——关键字已知且位长（如身份证号），挑分布均匀的几位；**平方取中法**——关键字位数不多、分布未知，平方后中间位融合了各位信息；**折叠法**——关键字位数很长，分段折叠。**实际工程里九成用「除留余数法」**，因为它是「任意类型关键字 → 0..m-1 地址」的通用翻译器；其余方法只在「关键字形态特殊」时才显身手。**先掌握除留余数法，再按需了解其他几种**，是哈希函数学习的正确次序。
- **第二步，读「素数」**：避免关键字间隔与 $p$ 的因子共振，使分布均匀。
- **第三步，读「关键字类型」**：对字符串关键字，常见做法是「加权累加」：$H(s) = \sum s_i \times 31^{i} \bmod p$（31 是经验值）——把字符串变成一个大整数再取模。<span class="marginnote">「31」这个系数并非偶然：<strong>31 是素数、乘起来快（$31x = 32x - x$），且避开了许多常见碰撞模式</strong>。Java 的 $H(s) = \sum s_i \times 31^{i} \bmod p$ 正是这个「$H = s_0 \cdot 31^{n-1} + \cdots + s_{n-1}$」的模板——教科书公式直接进了 JDK。</span>

## 5 哈希查找的「平均 O(1)」从哪来

理想哈希下：

$$
T_{\text{查找}} = O(1) \quad \text{（一次哈希计算 + 一次地址访问）}
$$

- **第一步，读理想情况**：无冲突时，$H(key)$ 一次算出地址，直接访问——比任何比较都少。
- **第二步，读现实情况**：冲突存在，查找要「算地址 + 冲突处理」——平均代价取决于装填因子 $\alpha$ 与冲突解法（下节）。
- **第三步，读「平均」的含义**：哈希的 $O(1)$ 是**平均意义**的（依赖哈希函数均匀），最坏（全部冲突到一处）仍是 $O(n)$——**这与 BST 的「最坏 $\log$、平均 $\log$」形成对比**。

**一个「免比较但非万能」的清醒认识**：哈希表放弃了**有序性**——它不支持范围查询、顺序遍历、找前驱后继；这些都要回到 BST/B+树。工程里最常见的决策是「**等值查找用哈希，范围/排序用树**」：数据库里 `=` 查询走哈希索引、`BETWEEN` 查询走 B+树索引。**哈希的 $O(1)$ 只买「精确定位」这一种服务**——想清楚「你要的是定位还是有序」，才知道该用哈希还是树。这不是哈希的缺点，而是它的「服务边界」。<span class="marginnote">「哈希平均 $O(1)$、最坏 $O(n)$；BST 最坏也 $\log$」——两种结构对「恶意输入」的耐受力不同。<strong>对抗哈希攻击（全部键撞到同一桶）需要随机化哈希或平衡桶</strong>，这是现代哈希表（Java 的树化桶、SipHash）在做的加固。</span>

## 6 数值算例：哈希函数质量差会怎样

空谈「分布均匀」不如对比两种哈希函数。表长 $m=10$，关键字为 12、22、32、42、52、62（都是「个位 2、十位递增」的等差数列，公差 10）。

**坏的哈希**：$H_1(key) = key \bmod 10$——六个键全部映射到地址 2！冲突率 100%，查找退化成链表式扫描。**根源**：$p=10$ 是合数，关键字以 10 为步长递增，恰好与 $p$ 的因子 10 共振，全部撞车。

**好的哈希**：$H_2(key) = key \bmod 7$（7 是素数）——12→5、22→1、32→4、42→0、52→3、62→6，六个地址全不同，零冲突。**根源**：素数 7 与关键字步长 10 互质，等差数列取模后均匀散布。<span class="marginnote">这个例子把「为什么取素数」讲透了：<strong>合数 $p$ 的因子会与「等差数列的步长」共振，导致系统性聚集；素数则与任意步长互质，打破聚集</strong>。<strong>「素数的意义在打破周期」</strong>——同样的道理也适用于随机数生成、哈希表扩容（$2^m$ 是哈希杀手）。</span>

## 7 术语速查表：哈希基础概念

| 术语 | 含义 | 要点 |
| --- | --- | --- |
| 哈希函数 | $H(key)$ 映射地址 | 计算快 + 分布均匀 |
| 哈希地址 | $H(key)$ 的值 | 一次计算定位 |
| 冲突 | 不同键同地址 | 需下节处理 |
| 装填因子 | $\alpha = n/m$ | 越高越慢 |
| 除留余数法 | $key \bmod p$ | $p$ 取素数最通用 |
| 直接定址法 | $a\cdot key + b$ | 无冲突但要求连续 |

**三句收束**：第一，**哈希 = 以空间换时间 + 以函数换比较**——用「放弃有序性」换「平均 $O(1)$ 定位」。第二，**哈希函数的黄金标准是「计算快 + 分布均匀」**——除留余数法 $key \bmod p$ 最通用，$p$ 取素数打破周期聚集。第三，**装填因子 $\alpha$ 是哈希表的压力计**——超过阈值（约 0.75）就该扩容，这是下节冲突处理与专题篇工程实现的共同前提。<span class="marginnote">「<strong>素数打破周期</strong>」是本节的隐藏主角：<strong>它让等差数列、常见步长在取模后不再聚集</strong>。<strong>哈希函数选得好不好，不是看「算得快」，而是看「在常见输入上是否分布均匀」</strong>——这需要一点数论的直觉，也是哈希从「会用」到「会设计」的分水岭。</span>

## 8 小结

- 哈希表：用哈希函数把关键字映射为地址，查找 = 一次计算，平均 $O(1)$。
- 冲突：不同键同地址；装填因子 $\alpha = n/m$ 决定冲突率与性能。
- 构造法九成场景用除留余数法，其余按关键字形态按需选。
- 构造法：直接定址、除留余数、数字分析、平方取中、折叠。
- 除留余数法最通用：$H(key) = key \bmod p$，$p$ 取素数。
- 字符串哈希常用「加权累加 + 31」。
- 哈希表是「故意留空」的表：空位是留给低冲突的余量。
- 哈希平均 $O(1)$、最坏 $O(n)$；放弃有序性换速度。
- 数值对比：$H_1 = key \bmod 10$ 六键全撞、$H_2 = key \bmod 7$ 零冲突——素数打破周期。
- 服务边界：等值查找用哈希、范围/排序用树。
