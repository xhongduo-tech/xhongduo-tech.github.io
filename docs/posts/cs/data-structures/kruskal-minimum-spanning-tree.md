## 为什么 Kruskal 与 Prim 互补

Prim 是「点扩展」，每次把**离集合最近的点**拉进来；**Kruskal 是「边扫描」**，把**全部边按权排序，从小到大一条条挑**——只要这条边不把已选边「织成环」。Kruskal 的独特之处在于它第一次动用**并查集（Union-Find）**：判断「加这条边会不会成环」= 判断两端点是否已在同一连通块。Kruskal 的复杂度 $O(e\log e)$，**稀疏图（$e \sim n$）时完胜 Prim**，是「边少图」的默认 MST 算法。

## 1 Kruskal 的思想

1. 把所有边按权值**升序排序**；
2. 初始化：每个顶点自成一个连通块（并查集）；
3. 从小到大遍历边 $e = (u, v)$：若 $u, v$ 不在同一连通块，选入 $e$ 并合并两块；否则跳过（会成环）；
4. 直到选出 $n-1$ 条边，即得 MST。

```c
typedef struct { int u, v, w; } Edge;   /* 边：端点 u、v，权值 w */

int Find(int parent[], int x) {         /* 并查集查找（含路径压缩） */
    return parent[x] == x ? x : (parent[x] = Find(parent, parent[x]));
}

int cmp(const void *a, const void *b) {
    return ((Edge *)a)->w - ((Edge *)b)->w;
}

void Kruskal(Edge e[], int n, int m) {
    int parent[MAXV], i, cnt = 0, ru, rv;
    for (i = 0; i < n; i++) parent[i] = i;          /* 每个顶点自成一个连通块 */
    qsort(e, m, sizeof(Edge), cmp);                 /* 按权值升序排序 */
    for (i = 0; i < m && cnt < n - 1; i++) {
        ru = Find(parent, e[i].u);
        rv = Find(parent, e[i].v);
        if (ru != rv) {                             /* 不成环才选入 */
            parent[ru] = rv;                        /* 合并两个连通块 */
            cnt++;                                  /* 选入一条边 */
        }
    }
}
```

**重点：并查集在此承担「判环」这一职责——$O(e\log e)$ 即 u、v 已连通，再加边必成环。** 这是并查集在算法中的第一次「正式出场」，也预告了专题篇《并查集经典应用》。<span class="marginnote">并查集判环为什么快？每次合并/查找近似 $O(\alpha(n))$（反阿克曼函数，接近常数），所以 Kruskal 的总代价由<strong>排序主导</strong>：$O(e\log e)$。没有并查集，判环要维护「已选边的连通块」，代价会显著变差。</span>

## 2 公式解析：Kruskal 的复杂度

$$
T_{\text{Kruskal}} = O(e \log e)
$$

- **第一步，读排序**：$e$ 条边排序，最优比较排序是 $O(e\log e)$——这是 Kruskal 的主要开销。
- **第二步，读判环**：每条边做两次 Find + 至多一次 Union，近似常数——不改变复杂度主导项。
- **第三步，与 Prim 对比选型**：稀疏图 $e \sim n$ 时，$O(n\log n)$ 优于 Prim 朴素 $O(n^2)$；稠密图 $e \sim n^2$ 时，$O(n^2\log n)$ 反而不如 Prim 朴素 $O(n^2)$。**稀疏图选 Kruskal，稠密图选 Prim。**<span class="marginnote">「排序主导」意味着 Kruskal 的常数很小——现代排序（快排/堆排）极快，加上并查集近似常数，工程里 <strong>稀疏图 Kruskal 通常比 Prim 更实用</strong>。这也解释了为什么「Kruskal + 并查集」是竞赛与面试的标配组合。</span>

## 3 正确性：切割性质的另一种用法

Kruskal 的正确性同样靠切割性质。考察算法选边时：若选 $e = (u, v)$ 不成环，则 $u$、$v$ 当前在不同连通块。取 $S$ = 「$u$ 所在连通块」，则 $e$ 是跨切割 $S/V-S$ 的边。因为边按权升序扫描，**$e$ 是当前跨该切割权最小且「最先被遇到」的边**——而比它轻的跨切割边若存在，要么已选、要么会成环。结合切割性质，$e$ 可进入某棵 MST。<span class="marginnote">Kruskal 的证明是「<strong>扫描顺序 + 切割性质</strong>」的合奏：升序保证「当前边就是未决边中最轻的」，「不成环」保证它跨一个真实切割。<strong>贪心正确性 = 一种「顺序保证」+ 一条「局部最优性质」</strong>，这个配方在赫夫曼、Dijkstra、Prim 里反复出现。</span>

## 4 辨析｜易错点：为什么「不成环」就够了

**为什么不成环的边一定「连通两块」？** 并查集里 $v$ 意味着 $u$、$v$ 分属不同连通块，选这条边就合并两块——**选的边数加 1、连通块数减 1**。
**为什么最终一定连通？** 若最后不连通，说明仍有跨切割边未选；但升序扫描会挑到最轻那条（不成环则必选），矛盾。故 Kruskal 结束时必连通且边数 $n-1$，恰是一棵生成树。
**会成环的边为何必跳？** 选了它就在连通块内部多出环，环上必有更早选入的边——**「成环边」等价于「已经连通的两点之间的边」，选了必冗余**。<span class="marginnote">「<strong>环 = 冗余 = 可以拒绝</strong>」是 Kruskal 的直觉核心。这也可理解为：MST 是「$n$ 个连通块合并成一个」的过程，每选一条合法边，连通块数减 1，恰好需要 $n-1$ 次合并——与并查集的「Union 次数」精确对应。</span>

## 5 Kruskal 的应用

**稀疏图的 MST**：如路网、通信网（边数远小于 $n^2$）；
**并查集的实战舞台**：判环、动态连通性、按秩合并与路径压缩（专题篇）；
**聚类分析**：单链接聚类（single-linkage）本质就是「按最轻边不断合并」——Kruskal 每步合并的边权就是合并距离；
**最小生成森林**：图不连通时，Kruskal 自然输出每块的 MST，合称最小生成森林。

**重点：Kruskal 是「边权升序 + 并查集判环」的模板**——这类「从小到大挑不冲突的元素」的贪心，在聚类、区间选点、最大不相交区间里反复出现。<span class="marginnote">单链接聚类与 Kruskal 的等价是个漂亮的桥：<strong>聚类合并的最小距离树，正是图上的 MST</strong>。你会在《机器学习》的层次聚类里再次见到它——数据结构的概念，一转身就进了机器学习的课堂。</span>

**一个具体的算例。** 图有 4 个顶点 $A,B,C,D$ 与 5 条边：$AB(1)$、$AC(3)$、$AD(4)$、$BC(2)$、$CD(5)$。按权排序：$AB(1)$、$BC(2)$、$AC(3)$、$AD(4)$、$CD(5)$。

1. 选 $AB(1)$，合并 $\{A,B\}$；
2. 选 $BC(2)$，$B$ 在块 $\{A,B\}$、$C$ 单独，不成环，合并为 $\{A,B,C\}$；
3. 看 $AC(3)$：$A,C$ 已在同一块，成环，跳过；
4. 选 $AD(4)$，$D$ 单独，不成环，合并 $\{A,B,C,D\}$，已选 3 条 = $n-1$ 条，停止。

MST 总权 $1+2+4=7$。注意第 3 步的 $AC(3)$ 虽然比 $AD(4)$ 轻，却必须跳过——**这正是「成环即弃」的贪心在起作用**。<span class="marginnote">这个例子说明 Kruskal 不是「无脑取轻」：<strong>轻的边若成环一样被弃</strong>。真正决定选边的不是单边权值，而是「是否连通两块」。也正因如此，Kruskal 需要并查集实时维护「两块是否已连通」。</span>

**核心对比表：Prim vs Kruskal**

| 维度 | Prim | Kruskal |
| --- | --- | --- |
| 视角 | 点扩展 | 边扫描 |
| 数据结构 | 最小堆 / 标记数组 | 并查集 |
| 复杂度 | 朴素 $O(n^2)$ / 堆 $O((n+e)\log n)$ | $O(e\log e)$ |
| 适用 | 稠密图 | 稀疏图 |
| 判环手段 | 点的「已连集合」标记 | 并查集 Find |

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 生成树 | 连通 $n$ 顶点的 $n-1$ 条无环边 |
| MST | 总权最小的生成树 |
| 切割性质 | 跨某割的最轻边必在某棵 MST 中 |
| 单链接聚类 | 按最轻边不断合并 = Kruskal |

## 6 小结

- Kruskal：边按权升序，逐条选「不成环」的边，直到 $n-1$ 条。
- 判环用**并查集**：`Find(u) != Find(v)` 即不成环，选入后 `Union(u, v)` 合并两块。
- 复杂度 $O(e\log e)$，排序主导；稀疏图完胜 Prim。
- 正确性：升序扫描 + 切割性质；「不成环」= 跨真实切割。
- 每选一条边连通块减 1，共 $n-1$ 次合并。
- 应用：稀疏图 MST、单链接聚类、最小生成森林。
