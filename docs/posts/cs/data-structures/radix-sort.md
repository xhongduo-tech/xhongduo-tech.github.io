## 为什么排序可以「不比大小」

前面所有排序都靠「比较关键字」——而「比较排序」有个铁律：**下限 $\Omega(n\log n)$**。**基数排序（radix sort）**绕开比较：**把关键字拆成若干位（digit），按位「分配」到桶里，再按桶序「收集」**——全程不比较关键字，只做「按位归类」。它的复杂度是 $O(d(n+r))$，其中 $d$ 是位数、$r$ 是基数——当 $d$ 小（如三位数）时，**突破 $n\log n$ 的下限**。基数排序是「分配思想」的代表，也是「稳定的桶排序」在多关键字上的组合应用。

## 1 基数排序的基本思想

以「三位十进制数」为例，排序 `[329, 457, 657, 839, 436, 720, 355]`：

- **基数 r = 10**：十进制，10 个桶（0–9）；
- **位数 d = 3**：百位、十位、个位；
- **LSD（Least Significant Digit first，最低位优先）**：先按个位分桶收集，再按十位，再按百位。

每趟「分配 + 收集」：把元素按当前位放到对应桶（**队列**，保持桶内稳定），再按桶 0→9 依序收回数组。

```c
/* LSD 基数排序：按位分配 + 收集，桶用队列保持稳定 */
void radixSort(int a[], int n, int d, int r) {
    for (int k = 1, div = 1; k <= d; k++, div *= r) {
        for (int i = 0; i < n; i++)              /* 分配：按当前位入桶 */
            enqueue(bucket[(a[i] / div) % r], a[i]);
        int idx = 0;
        for (int b = 0; b < r; b++)              /* 收集：按桶序收回数组 */
            while (!empty(bucket[b]))
                a[idx++] = dequeue(bucket[b]);
    }
}
```

**重点：LSD 必须保证「每趟桶内稳定」——先按低位排好，高位相同的元素其低位顺序得以保留。** 这正是一次「多关键字排序」：把关键字拆成 d 个「次关键字」，从最次要到最主要逐次排序，靠稳定性叠加。<span class="marginnote">「LSD + 稳定桶」的魔力：<strong>若桶内不稳定，后一趟高位排序会破坏低位已经排好的顺序</strong>。稳定性在这里不是「锦上添花」，而是「正确性前提」——这也是《排序概述与稳定性》里「稳定支持多关键字叠加」的实战例证。</span>

## 2 公式解析：基数排序的复杂度

设 $n$ 个关键字、基数 $r$、每个关键字 $d$ 位：

$$
T_{\text{基数排序}} = O(d \cdot (n + r))
$$

- **第一步，读每趟代价**：分配扫 $n$ 个元素入桶（$O(n)$）+ 收集从 $r$ 个桶合并（$O(n+r)$）——每趟 $O(n+r)$。
- **第二步，读总代价**：$d$ 趟，总 $O(d(n+r))$。
- **第三步，与比较排序对比**：$n=10^6$、$d=3$、$r=10$：约 $3\times10^6$ 次操作，而快排约 $n\log n \approx 2\times10^7$ 次比较——**当 $d$ 小、$r$ 适中时，基数排序在常数上超过快排**。<span class="marginnote">「$d$ 小则赢」是基数排序的命门：<strong>关键字越短（$d$ 越小），越有优势；若 $d$ 很大（如长字符串、128 位哈希），$O(d(n+r))$ 反而不如比较排序</strong>。基数排序是「<strong>用关键字的位数，换排序的线性时间</strong>」。</span>

## 3 空间与稳定性

**空间**：$O(n + r)$——$r$ 个桶（队列），总共装 $n$ 个元素。
**稳定性**：**稳定**。桶内用队列（FIFO）、收集按桶序——等值元素保持相对顺序。

**辨析｜易错点：基数排序的「位」与「进制」要配套。** 基数 $r$ 决定桶数（$r$ 个桶）与「位」的划分。按位取数字的公式是 $r=2$。若把十进制数当二进制处理，$r=2$、$d$ 变长，桶只有 2 个——复杂度换成 $O(d(n+2))$，$d$ 涨到约 3.3 倍。<span class="marginnote">「基数与位数的权衡」：<strong>$r$ 大则桶多（空间大）、$d$ 小（趟数少）；$r$ 小则桶少（空间小）、$d$ 大（趟数多）</strong>。2 进制 32 趟 vs 10 进制 10 趟 vs 256 进制 4 趟——工程上常选 256（字节）做基数，用空间换趟数。</span>

## 4 MSD 与 LSD

基数排序有两个方向：

**LSD（最低位优先）**：从个位到最高位，靠**稳定**叠加，实现简单，是默认选择；
**MSD（最高位优先）**：从最高位开始，按最高位分成若干子序列，**递归**排序各子序列——需要「桶内再递归」，实现复杂，但适合「字典序」（如字符串排序）。

**重点：LSD 靠「稳定」作弊，MSD 靠「递归」分治——方向不同，原理都是「按位分类」。**<span class="marginnote">「LSD vs MSD」与「BFS vs DFS」神似：<strong>LSD 自底向上、按层（位）推进、靠稳定合并；MSD 自顶向下、递归深入、逐桶分治</strong>。字典序字符串排序多用 MSD（配合 Trie 更自然），数值排序用 LSD（实现更省）。</span>

## 5 基数排序的应用与地位

**整数与定长字符串排序**：ID、学号、日期、IP 地址——位数固定的场景是它的甜区；
**后缀数组构造的基数部分**：字符串算法里对「排序子串」用基数排序；
**计数排序/桶排序**：基数排序的「单趟」就是计数排序或桶排序——**基数排序 = 对每一位做一次桶排序**。

**重点：基数排序证明「突破比较下限是可能的」——前提是不比较。** 它把「排序」从「比较决策」变成「按位分配」，是算法设计「换一种基本操作」的典范。<span class="marginnote">「突破下限的唯一办法，是绕过下限的前提」——<strong>比较排序的下限建立在「只能比较」之上，基数排序用「分配」绕开它</strong>。这个「换操作」的思路极具迁移性：字符串排序用 Trie、网络路由用前缀匹配，都是「不用比较、用结构」的同类智慧。</span>

## 6 小结

- 基数排序：按位分配（桶）+ 收集，全程不比较关键字。
- LSD：从最低位到最高位，靠**稳定桶**叠加，$O(d(n+r))$。
- 复杂度 $O(d(n+r))$：$d$ 小、$r$ 适中时超越快排，突破 $n\log n$。
- 稳定 + 空间 $O(n+r)$；基数与位数此消彼长。
- MSD：从最高位递归分桶，适合字典序字符串。
- 基数排序 = 每趟一次桶排序（计数/桶排序）的组合。
