## 为什么要把「空闲」组织起来

动态存储管理的第一步，是给「空闲区」建一张**可利用空间表（available space list）**——所有空闲块串成一张链表，分配时从表里摘块、回收时把块插回去。这张表有两种组织方式：**按地址排序**（有利于相邻块合并）与**按大小排序**（有利于最佳适应）。本节实现三种分配方法（首次、最佳、最坏适应）在这张表上的具体操作，并处理分配与回收中的核心难点——**相邻空闲块的合并**。

## 1 可利用空间表的两种组织

- **按地址排序的空闲表**：块按起始地址从小到大排。回收时易于「前后相邻块合并」，但「找大小合适」需顺序扫描。
- **按大小排序的空闲表**：块按大小排序。最佳/最坏适应可以直接从表头/表尾下手，但「回收后地址相邻的块」未必在表中相邻，合并要查找。

**重点：地址序利于合并、大小序利于适应，二者只能选一个作为主组织**——这是存储管理里第一个结构权衡。<span class="marginnote">地址序/大小序的分野，与前文「数组 vs 链表」「稠密 vs 稀疏」是同一类权衡：<strong>把哪个字段当成「排序键」，就优先支持哪类操作</strong>。选地址序 = 优先「回收合并」，选大小序 = 优先「分配选择」。</span>

## 2 分配：FF / BF / WF 的实现

设空闲表按地址排序，三种分配方法的操作：

**首次适应 FF**：从表头开始，顺序找第一块**够大**（$size \ge n$）的空闲块。若大小恰为 $n$，整块摘下；若 $size > n$，把块切成两块——前 $n$ 字节分出，剩余 $size - n$ 字节留在表中。
**最佳适应 BF**：遍历整表，记下「够大且最小」的块，分配给它的剩余碎片最小。
**最坏适应 WF**：取整表最大块（地址序表则需遍历找最大），分给它的剩余空间最大。

```c
// 首次适应 FF：从表头找第一块 size ≥ n 的空闲块
Block* firstFit(Block *head, int n) {
    Block *p = head;
    while (p && p->size < n) p = p->next;   // 顺序扫描
    if (!p) return NULL;                    // 找不到：分配失败
    split(p, n);                            // 切块：前 n 字节分出，剩余留表
    return p;
}

// 最佳适应 BF：找「够大且最小」的空闲块
Block* bestFit(Block *head, int n) {
    Block *best = NULL;
    for (Block *p = head; p; p = p->next)
        if (p->size >= n && (!best || p->size < best->size))
            best = p;                       // 记录最小够大的
    if (!best) return NULL;
    split(best, n);
    return best;
}

// 最坏适应 WF：取最大块（地址序表需遍历找最大）
Block* worstFit(Block *head, int n) {
    Block *max = NULL;
    for (Block *p = head; p; p = p->next)
        if (!max || p->size > max->size)
            max = p;                        // 记录最大块
    if (!max || max->size < n) return NULL;
    split(max, n);
    return max;
}
```

**重点：切块时「剩余部分留在空闲表里、地址后移」——块的物理地址随分配推进，这是「移动分配」的雏形。** 分配后块变小、地址后移，空闲表随之变化。<span class="marginnote">「切块」把一次分配变成「摘块 + 分裂」两步。<strong>分裂制造了碎片之源</strong>——每次分配在空闲块中间切一刀，剩余部分越来越小。这也是为什么后续要「合并」与「紧缩」。</span>

## 3 回收：合并相邻空闲块

回收一块被释放的空闲块 $B$（地址 $addr_B$、大小 $size_B$）时，把它插回空闲表。若表中已有与它**地址相邻**的空闲块，应**合并**成一块（地址序表中，相邻块就在前驱/后继位置）：

1. 找 $B$ 在地址序中的插入位置（前驱 $p$、后继 $q$）；
2. 若 $p$ 的末尾恰接 $B$ 的首（$addr_p + size_p = addr_B$），合并；
3. 若 $B$ 的末尾恰接 $q$ 的首（$addr_B + size_B = addr_q$），合并；
4. 两个相邻都合并时，三块并一块。

**辨析｜易错点：合并不是「把两块拼起来」这么简单，必须按地址精确判断相邻。** 两块地址相邻（前一块地址 + 大小 = 后一块地址）才能合并；中间隔哪怕一个字节都不可合并。合并后要**更新大小、删除被并掉的结点**。<span class="marginnote">「地址相邻才可合并」这条规则，在地址序表里只需检查前驱与后继——<strong>这正是选地址序的回报</strong>。若用大小序表，找相邻块要全表查，合并的代价就上来了。</span>

## 4 公式解析：分配与回收的复杂度

设空闲表长度为 $m$：

$$
\begin{aligned}
T_{\text{FF 分配}} &= O(m) \ \text{（最坏全表扫描）}, \quad \text{通常很快（早停）} \\
T_{\text{BF/WF 分配}} &= O(m) \ \text{（必须全表扫描）} \\
T_{\text{回收}} &= O(m) \ \text{（地址序：定位前驱后继）}
\end{aligned}
$$

- **第一步，读 FF 的「平均快」**：FF 常在前几个块就命中，平均 $O(1)$ 到 $O(\text{小块数})$——但最坏仍是 $O(m)$。
- **第二步，读 BF/WF 的「必然全扫」**：要知道「最小够大的」或「最大的」，必须看完整表——代价固定 $O(m)$。
- **第三步，读回收**：地址序表里「找插入位置」是顺序扫描 $O(m)$，但合并本身 $O(1)$。<span class="marginnote">「FF 平均快、BF/WF 稳定慢」是分配方法的第一课。<strong>真实 malloc 多用 FF 的变体（size class 分桶后近似 FF）</strong>——把「一次全表扫描」摊到「多桶各扫一小段」，兼顾速度与碎片。</span>

## 5 从空闲表到现代内存分配器

本节的「空闲表」是动态存储管理的抽象骨架，现代分配器在其上叠加了大量优化：

**分离适配（segregated fit）**：按大小分成若干链表（size class），请求落在对应桶——首次适应（FF）的经典实现；
**slab 分配**：内核里按对象大小预建 slab，对象级复用，避免反复切块；
**伙伴系统（下一节）**：按 2 的幂分块，合并规则最规整。

**重点：所有现代分配器的核心动作仍是「分配选块 + 回收合并」**——本节的 FF/BF/WF 与合并规则，是理解它们的最小模型。<span class="marginnote">「分离适配 + slab」用「预分类」降低在线决策的代价——<strong>把「运行时全表搜索」换成「按类别的快速查找」</strong>。这与数据库索引、哈希分桶、缓存的「分片」是同一哲学：分类，是为了少搜索。</span>

**辨析｜易错点：分配后「剩余碎片」的处理。** FF/BF 切块后，剩余部分必须**保留在空闲表中**（重新写大小），而不是丢弃——否则内存越分越少。而「恰好相等」时不切块、整块摘下。

**一句话**：「能切则切、恰等则整摘」，是分配的两分支。

## 6 小结

- 可利用空间表组织方式：**地址序**（利于合并）或**大小序**（利于适应）。
- FF：第一块够大的，平均快；BF：最小够大的，外碎小；WF：最大块，保大块。
- 分配 = 摘块 + 切块；回收 = 插表 + 相邻合并。
- 合并条件：**地址精确相邻**（前一块地址 + 大小 = 后一块地址）；地址序表只需检查前驱后继。
- 复杂度：FF 平均快、BF/WF 必全扫；回收 $O(m)$ 定位。
- 现代分配器（分离适配、slab、伙伴系统）是这些规则的工程化。
