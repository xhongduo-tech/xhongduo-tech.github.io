## 为什么滑动窗口最值要「双端队列」

滑动窗口最大值朴素做法 $O(nk)$（每窗口扫一遍）。**单调队列（monotonic queue）**用**双端队列（deque）**维护一个「从队头到队尾单调递减」的候选队列，把复杂度压到 $O(n)$。它的两个动作各司其职：**队尾负责「淘汰弱者」**（新元素来了，弹出队尾比它小的——它们永远不可能是最大值了）；**队头负责「淘汰过期」**（窗口滑出，队头若在窗外则弹出）。于是**队头永远是当前窗口的最大值**。单调队列是「单调栈 + 过期淘汰」的队列版，也是「动态规划优化」的预备知识。

## 1 单调队列的结构与两个动作

维护一个**队头到队尾单调递减**的双端队列，存「候选下标」：

- **入队新元素**（窗口右端进入）：从队尾弹出所有「比新元素小/等」的——它们失去候选资格；再把新元素从队尾入队；
- **淘汰过期**（窗口左端滑出）：若队头下标 < 窗口左界，从队头弹出；
- **取最大值**：队头元素即当前窗口最大值。

```cpp
deque<int> q;                       // 存候选下标，队头到队尾单调递减
for (int i = 0; i < n; i++) {
    while (!q.empty() && a[q.back()] <= a[i]) q.pop_back();  // 队尾实力淘汰
    q.push_back(i);
    if (q.front() < i - k + 1) q.pop_front();                // 队头时间淘汰
    if (i >= k - 1) ans.push_back(a[q.front()]);             // 队头即窗口最大值
}
```

**重点：队尾管「实力淘汰」、队头管「时间淘汰」——两端分工，队头就是答案。**<span class="marginnote">「<strong>队尾比实力、队头比时间</strong>」是单调队列的两句口诀：<strong>队尾弹掉「又老又弱」的（比新元素小），队头弹掉「过期」的（滑出窗口）</strong>。<strong>双端队列的「两端可操作」恰好服务这两个需求</strong>——这正是它选 deque 而非普通队列的原因。</span>

## 2 为什么队尾的「弱者淘汰」是对的

新元素 $a[i]$ 进入窗口，队尾那些 $a[t] \le a[i]$ 的元素：

它们**比 $a[i]$ 小/等**——若 $a[i]$ 在窗口中，最大值永远轮不到它们；
它们**比 $a[i]$ 更早过期**——$a[i]$ 晚来、活得更久；
所以它们**永远不会是未来任何窗口的最大值**——安全弹出。

**重点：单调队列的淘汰判据是「比你弱 + 比你早过期」——双弱必淘汰。** 这个「又弱又早」的判据，是单调队列正确性的核心。<span class="marginnote">「<strong>强者恒强，弱者早亡</strong>」：<strong>一个元素还能不能当最大值，看两件事——值够不够大（实力）、活得够不够久（时间）</strong>。<strong>两项都输给新元素 → 永无出头之日 → 弹出</strong>。<strong>「双弱淘汰」让队列里只剩「有希望」的候选</strong>。</span>

## 3 公式解析：复杂度 O(n)

设 $n$ 个元素、窗口 $k$：

$$
T_{\text{单调队列}} = O(n) \quad \text{（每个元素入队一次、出队一次）}
$$

- **第一步，读「两次」**：每个元素恰好被 push 一次、pop 至多一次——总 $O(n)$ 次操作。
- **第二步，读「窗口维护」**：每次滑动只做「队尾淘汰 + 队尾入队 + 队头淘汰」三个动作，各 $O(1)$ 摊还。
- **第三步，与朴素对比**：朴素每窗口扫 $k$ 个，$O(nk)$；单调队列 $O(n)$——**当 $k$ 接近 $n$ 时，差距是 $O(n)$ vs $O(n^2)$**。<span class="marginnote">「<strong>每元素进出一次 = $O(n)$</strong>」是单调队列的复杂度铁律：<strong>不管窗口多大，每个元素只被处理常数次</strong>。<strong>「窗口是滑动参数，但总代价与窗口大小无关」</strong>——这是单调队列最反直觉也最值钱的结论。</span>

## 4 单调队列 vs 单调栈

| 维度 | 单调栈 | 单调队列 |
| --- | --- | --- |
| 结构 | 栈（一端操作） | 双端队列（两端操作） |
| 淘汰方向 | 只在栈顶 | 队尾实力淘汰 + 队头时间淘汰 |
| 场景 | 「下一个更大/更小」 | 「滑动窗口最值」 |
| 过期概念 | 无 | 有（窗口滑出） |
| 典型题 | 柱状图矩形 | 滑动窗口最大值 |

**重点：单调队列 = 单调栈 + 「过期淘汰」**——栈没有「时间维度」，队列的窗口给了它「生命周期」概念。理解单调栈后，单调队列只是「多了一个队头淘汰」的动作。<span class="marginnote">「<strong>单调队列是带生命周期的单调栈</strong>」：<strong>单调栈只淘汰「实力弱」，单调队列还要淘汰「时间到」</strong>。<strong>多了一个维度（窗口），就多一个淘汰条件</strong>——<strong>「单调」的灵魂不变，「淘汰」的维度变宽</strong>。</span>

## 5 单调队列的应用预览

**滑动窗口最值**：经典，$O(n)$；
**维护区间最值**：任意「连续区间最值」问题；
**DP 优化（下节）**：形如 $dp[i] = \max_{j \in [i-k, i-1]}(dp[j]) + cost$ 的转移——内层 max 就是「滑动窗口最值」，用单调队列从 $O(nk)$ 优化到 $O(n)$。

**重点：凡「一段连续区间的最值」反复被查，单调队列就能用**——它把「每窗口重算」变成「窗口滑动、最值递推」。<span class="marginnote">「<strong>区间最值递推化</strong>」是单调队列的通用价值：<strong>窗口滑动时，最值不是重算，而是「删一个 + 加一个 + 取队头」</strong>。<strong>这个「增量维护最值」的能力，直接喂给动态规划做状态转移加速</strong>——下一节的 DP 优化就是它的最大舞台。</span>

## 6 小结

- 单调队列：双端队列存候选下标，队头到队尾单调递减。
- 队尾「实力淘汰」：弹掉比新元素小/等的——双弱必淘汰。
- 队头「时间淘汰」：弹掉滑出窗口的过期下标。
- 复杂度 $O(n)$：每元素入队一次、出队一次，与窗口大小无关。
- 单调队列 = 单调栈 + 过期淘汰。
- 应用：滑动窗口最值、区间最值、DP 转移优化（下节）。
