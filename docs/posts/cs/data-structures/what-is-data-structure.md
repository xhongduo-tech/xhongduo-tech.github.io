## 为什么从「数据结构」开始

「从极限到大模型」这条路上，我们已经用集合、函数、数列预习了数学的语言。但数学只负责描述「是什么」，真正要让程序跑起来，还得回答另一组问题：数据在计算机里**怎么摆、按什么关系组织、用什么方式取用**。这门学问就是**数据结构（data structure）**。

举一个眼前的例子。大模型之所以「大」，是因为有数以千亿计的参数；这些参数被组织成张量（tensor），张量的形状、内存排布、批量运算，背后全是数据结构的功夫。再退回到一个普通的「通讯录」程序：它也要回答，记录在内存里怎么存放，按姓名查找快还是按号码查找快。数据结构，就是这套「怎么存放、怎么组织、怎么取用」的系统学问。

我们上一站刚在《集合的概念》里学完**确定性、互异性、无序性**<span class="marginnote">见第一级《基础数学》的《集合的概念》：集合的元素不讲顺序、不许重复、归属明确。数据结构恰恰从「无序」出发，研究给元素加上顺序、层次、网状关系之后，能换来怎样的计算能力。</span>。数据结构可以看作对「无序」的解放：**给元素之间加上关系**，正是数据结构全部的起点。

## 1 数据、数据元素与数据项

严蔚敏《数据结构》绪论的第一件事，是把几个容易混的基本术语钉死。它们构成了一个层层包含的阶梯：

- **数据（data）**：能输入到计算机中、并被计算机程序处理的**符号的集合**。它是信息的载体，可以是数值、文字、图像、声音，凡能输入机器处理的都算。
- **数据元素（data element）**：数据的**基本单位**，在程序中通常作为一个整体进行考虑和处理。它在不同场景有不同的别名——记录（record）、结点（node）、顶点（vertex），叫法随场合变，指的东西是同一个。
- **数据项（data item）**：构成数据元素的、**不可分割的最小单位**。一个数据元素可以由若干个数据项组成。
- **数据对象（data object）**：**性质相同**的数据元素的集合，是数据的一个子集。

用一个「学生档案表」把它们串起来：整张表是**数据**；表中一行（一名学生）是一个**数据元素**，也常叫一条**记录**；一行里的「学号、姓名、性别、成绩」是不可再分的**数据项**；「全体学生记录」这个集合，就是**数据对象**。<span class="marginnote">数据项还能再细分为「初等项」与「组合项」——例如「成绩」可拆成「平时成绩」与「期末成绩」。拆到什么粒度，取决于问题需要的精细度，这正是下一步「数据结构设计」的取舍。</span>

这里有个值得记住的对应：**数据对象是集合，数据元素是元素**——它与第一级数学里的集合语言完全同构，只是把「性质相同」换成了更具体的业务含义。

## 2 数据结构的三要素

有了基本术语，就可以给「数据结构」下定义了。严蔚敏给出的是描述性定义：

**数据结构（data structure）**：相互之间存在一种或多种**特定关系**的数据元素的集合。

这个定义里真正关键的是「关系」。于是研究数据结构，本质上是研究三件事，合称**数据结构的三要素**：

1. **逻辑结构（logical structure）**：数据元素之间**逻辑上的关系**，与计算机硬件无关。它描述的是「数据在数学模型里长什么样」。
2. **存储结构（storage structure）**：逻辑结构在计算机存储器中的**映像**，也称物理结构（physical structure）。它回答「逻辑关系在内存里怎么落实」。
3. **数据运算（data operation）**：施加在该数据结构上的**操作及其规定**，例如插入、删除、查找、排序。

**逻辑结构是「关系」，存储结构是「实现」，数据运算体现「用途」**——同一份逻辑结构可以用不同方式存储，同一份存储也能支撑不同运算，三者分工明确、互相支撑。<span class="marginnote">打个比方：逻辑结构是「乐谱」上标注的音符关系，存储结构是「乐器」怎么发声，数据运算是「怎么演奏」。同一首曲子，钢琴、吉他都能弹，音色不同，代价不同。</span>本章第三节《线性表的类型定义》会第一次完整地体会这种「先定义逻辑结构，再分别实现」的写法。

## 3 逻辑结构：四种关系模型

逻辑结构只关心元素之间的**关系**，而关系只有四种可能，于是逻辑结构被划分为四类。

### 集合结构

**集合结构（set structure）**：数据元素之间**除了「同属一个集合」之外别无其他关系**。<span class="marginnote">注意「没有关系」本身也是一种关系——它规定所有元素彼此独立。这与第一级数学里的朴素集合完全一致：元素只问「在不在」，不问「在谁旁边」。</span>

典型的例子是一张不讲究顺序的花名册：你只关心某个人是否在册，不关心他在册中的第几行。

### 线性结构

**线性结构（linear structure）**：数据元素之间存在**一对一**的线性关系——除首元素与尾元素外，每个元素有且仅有一个直接前驱和一个直接后继。

生活中的队列、书本目录、按时间排序的交易流水，都是线性的。线性结构的核心特征是「有头有尾、先后分明」。

### 树形结构

**树形结构（tree structure）**：数据元素之间存在**一对多**的层次关系。存在唯一的「根」元素，每个元素可以有多个直接后继，却只有一个直接前驱。

家谱、公司组织架构、文件系统的目录树，都是树形。「一对多」让它天然适合表达「分层」与「归属」。

### 图状结构

**图状结构（graph structure）**：数据元素之间存在**多对多**的任意关系。任何两个元素之间都可能直接相关，没有「根」，也没有层级。

地铁线路图、社交网络的好友关系、网页之间的超链接，都是图状。它是最一般、也最复杂的关系模型。

## 4 核心对比表：四种逻辑结构

四种逻辑结构，关系从「无」到「多对多」，一个比一个「稠密」。把它们并排放在一起，差异一目了然：

| 逻辑结构 | 元素间关系 | 数学抽象 | 生活实例 | 典型数据结构 |
| --- | --- | --- | --- | --- |
| 集合结构 | 无关系，仅同属一集 | 无序集合 | 花名册 | 哈希表（只判成员） |
| 线性结构 | 一对一（前驱—后继） | 有序序列 | 排队、流水 | 数组、链表、栈、队列 |
| 树形结构 | 一对多（分层归属） | 树 | 家谱、目录 | 二叉树、堆、B 树 |
| 图状结构 | 多对多（任意相连） | 图 | 地铁网、社交网 | 邻接表、邻接矩阵 |

从表中可以读出几条规律。第一，**关系越稀疏，结构越简单，运算代价越低**；集合的「查成员」近乎常数时间，而图的「查连通」则需要整图搜索。第二，**前一种结构往往可以看成后一种的退化**：线性是树的退化（每层只有一个孩子），树是图的退化（没有环的连通图）。第三，**这些结构不是孤立的**——第三级《算法设计与分析》（以 CLRS 为纲）中的 Dijkstra 最短路，正是「图状结构 + 堆（树形结构）」的组合。

## 5 存储结构：四种物理表示

逻辑结构是「关系」的蓝图，蓝图要落地，就需要存储结构。同一张蓝图可以有四种画法，对应四种存储结构：

**顺序存储结构（sequential storage structure）**：把逻辑上相邻的元素存放在**物理地址也相邻**的存储单元里，用元素在内存中的相对位置表示逻辑关系。数组是它的化身：第 $i$ 个元素的下标就是 $i$，逻辑相邻即物理相邻。

**链式存储结构（linked storage structure）**：元素存放在**任意的存储单元**里，逻辑上相邻的元素物理上可以相隔很远，靠一组「指针」显式地把顺序穿起来。逻辑相邻 ≠ 物理相邻，这是它与顺序存储最根本的差别。

用一小段 C 语言对比这两种画法：

```c
/* 顺序存储：一排连号的格子，第 i 个元素就存在下标 i 处 */
int a[10];                  /* 逻辑相邻 == 物理相邻 */

/* 链式存储：格子散落在各处，用指针把逻辑顺序穿起来 */
typedef struct Node {
    int data;               /* 元素本身 */
    struct Node *next;      /* 指向下一个元素的指针 */
} Node;                     /* 逻辑上的「下一个」，由 next 显式指出 */
```

**索引存储结构（index storage structure）**：在存储元素信息的同时，另外建立一张**索引表**，索引项形如（关键字，地址），通过「关键字 → 地址」的映射定位元素。图书的目录、数据库的索引文件都是这种思路。

**散列存储结构（hash storage structure）**：根据元素的关键字**直接计算出**它的存储地址：

$$
地址 = H(关键字)
$$

其中 $H$ 是哈希函数。它把「查找」变成一次计算，是常数时间查找的基石。<span class="marginnote">索引与散列都会在后面的《查找》篇和《专题篇 · 哈希》中系统展开：哈希函数怎么构造、冲突怎么解决、装载因子怎么控制，是独立于本课的一大块内容。</span>

注意顺序：**先有逻辑结构，再谈存储结构**。同一个「线性表」的逻辑结构，既可以用顺序存储（数组）实现，也可以用链式存储（单链表）实现——这正对应严蔚敏教材第二篇《线性表》里要分别展开的两条实现路线。

## 6 数据运算：运算「定义」在逻辑结构上

三要素的第三项是**数据运算**。常用运算大致有：插入（insert）、删除（delete）、修改（modify）、查找（search）、排序（sort）、遍历（traverse）。

关于运算，有一句贯穿全教材的话要记住：**运算定义在逻辑结构上，实现于存储结构之中**。同一个「插入」运算，在线性表上语义是「在第 $i$ 个位置放入一个元素」；但用顺序存储实现时，它意味着把后面的元素整体后移，代价与元素个数成正比；用链式存储实现时，它只意味着改两处指针，代价是常数——**逻辑语义相同，物理代价不同**。

这正是数据结构这门课与「写代码」的分界：**先问清楚一个运算在逻辑上「要做什么」，再去不同存储结构里比较它「怎么做更省」**。而「怎么算更省」，就需要第三级《算法设计与分析》的复杂度度量工具（渐进记号、最坏情况分析）来精确回答。<span class="marginnote">在本专题下一篇《算法和算法分析》里，我们会引入时间复杂度的 $O$ 记号；届时「顺序存储插入要移动 $O(n)$ 个元素」这类结论，就会从直觉变成严格的公式。</span>

## 7 公式解析：程序 = 数据结构 + 算法

1976 年，尼克劳斯 · 维尔特用一本书的名字给出了一个「公式」，它成了整个计算机科学流传最广的一句话：

$$
程序 = 数据结构 + 算法
$$

严格说这不是数学等式，而是一句**关于程序构成的三段论**。对它做三步拆解：

- **第一步，读懂「数据结构」这一项**：它回答「数据以什么关系、什么形式组织」，决定了一个程序的**骨架**。数据摆得不好，后面一切运算都事倍功半。
- **第二步，读懂「算法」这一项**：它回答「对这份组织好的数据，按什么步骤解决一个问题」，决定了一个程序的**灵魂**。同一种数据，算法好坏可以相差千百倍。
- **第三步，读懂那个「+」**：这不是机械相加，而是**相互匹配**。一种数据结构往往催生一类算法——有序表催生折半查找，堆催生堆排序，图催生最短路算法；反过来，一类算法也往往要求一种数据结构——Dijkstra 最短路要求「图 + 优先队列」，而优先队列的经典实现正是二叉堆。

把话翻译得直白些：**数据结构和算法是一枚硬币的两面**。没有结构，算法无处施展；没有算法，结构只是一堆摆设。这也是为什么本专题（数据结构）与《算法设计与分析》（CLRS）必须互为参照地学习。

## 8 抽象数据类型（ADT）：把「怎么做」藏起来

有了三要素与四结构，严蔚敏在绪论里给出了最后一个、也是最具前瞻性的概念：**抽象数据类型（Abstract Data Type，ADT）**。

**抽象数据类型（ADT）**：一个**数学模型**以及定义在该模型上的一组**操作**。它把「数据对象」「数据关系」「基本操作」三者打包成一个整体，向使用者只暴露「**能做什么**」，隐藏「**怎么做**」。

教材绪论用「复数」做了第一个完整的 ADT 示范。复数在数学里是数集的一类元素，把它抽象成数据类型，规格说明长这样：

```text
ADT Complex {
    数据对象：D = { e1, e2 | e1, e2 ∈ float }
    数据关系：R = { <e1, e2> | e1 是实部，e2 是虚部 }
    基本操作：
        Create(&C, x, y)    /* 构造复数 C = x + yi */
        Add(C1, C2)         /* 返回 C1 与 C2 之和 */
        Mul(C1, C2)         /* 返回 C1 与 C2 之积 */
        GetReal(C)          /* 取复数 C 的实部 */
} ADT Complex
```

这份规格说明里没有一行「怎么实现加法和乘法」的代码——它只声明**接口**，把实现留到后面。使用者只要知道 `Add` 能算两个复数的和，完全不必关心加法是用普通运算、查表还是别的办法完成的。<span class="marginnote">这就是「信息隐藏」：把变化封在实现里，让接口保持稳定。ADT 是面向对象「封装」思想的前身——C 语言没有 class，但 ADT 已经把「接口与实现分离」的雏形给出来了。到后面学栈、队列、二叉树，你会发现每个数据结构都可以写成一个 ADT 规格说明。</span>

**ADT 的意义在于分工**：它允许「使用者」与「实现者」各司其职——使用者在接口层面写程序，实现者在不破坏接口的前提下优化内部结构。这一层抽象，让大规模软件工程成为可能。

## 9 小结

- **术语阶梯**：数据是符号的集合，数据元素是基本单位，数据项是不可分的最小单位，数据对象是性质相同元素的集合。
- **数据结构三要素**：逻辑结构（关系）、存储结构（实现）、数据运算（用途）。
- **逻辑结构四种**：集合、线性（一对一）、树形（一对多）、图状（多对多）；关系由稀疏到稠密，代价由低到高。
- **存储结构四种**：顺序、链式、索引、散列；同一逻辑结构可有多种物理表示。
- **程序 = 数据结构 + 算法**：二者互相匹配、互为表里，本专题与《算法设计与分析》需对照学习。
- **抽象数据类型 ADT**：数据对象 + 数据关系 + 基本操作，暴露接口、隐藏实现，是封装思想的前身。

在下一节《基本概念和术语》中，我们会把「数据结构、存储结构、数据类型、抽象数据类型」这些概念逐个钉得更死，并引入第一个能动手实现的数据结构——线性表的类型定义。
