## 为什么跳表能「跳过一半」

链表查找是 $O(n)$——因为只能一格一格走。**跳表（skip list）**的妙想：**给链表加「快速通道」**——每一层都是一条「跳跃的链表」，高层跳过更多结点。查找时从最高层开始，**能跳就跳、不能跳就降层**——把 $O(n)$ 拉到**期望 $O(\log n)$**。而「每层有哪些结点」不由插入顺序决定，而由**随机抛硬币**决定：每个结点有 $1/2$ 概率升到上一层。这个「随机层数」让跳表**期望平衡**——不需要旋转、不需要颜色，用概率换简单。跳表是「以随机替代显式平衡」的完美标本，也是 Redis 有序集合的底层。

## 1 跳表的结构：多层有序链表

跳表是「**多层链表**」的叠加：

- **第 0 层（最底层）**：包含全部元素的有序链表；
- **第 1 层**：约一半元素（每 2 个取 1 个）的「快链」；
- **第 2 层**：约 1/4 元素……
- 顶层可能只有几个元素——「高速公路」。

每个结点有**若干个前向指针**（一个结点可能出现在多层）。查找时从**最高层的头**出发，向右找「不大于目标的最后一个结点」，再降一层继续，直到第 0 层。

**重点：跳表 = 有序链表 + 多级「跳跃指针」——高层让查找「一步跨过多个结点」。**<span class="marginnote">「<strong>跳表是给链表装电梯</strong>」：<strong>第 0 层是楼梯（一步步走），高层是电梯（一层层跳）</strong>。查找时「电梯能到就到，到不了就下一层楼梯」——<strong>每层最多走几个结点就降层，总步数期望 $O(\log n)$</strong>。多级指针 + 逐层下降，就是跳表的全部。</span>

## 2 随机层数：抛硬币决定高度

新结点插入时，**随机决定它的层数**：

1. 新结点至少在第 0 层；
2. 抛硬币：正面就**再升一层**，反面停——**层数 = 连续正面的次数 + 1**。

```cpp
// 随机层数：抛硬币，正面升层、反面停止（每层 1/2 概率）
int randomLevel() {
    int level = 1;                                // 至少在第 0 层
    while (rand() % 2 == 1 && level < MAX_LEVEL)  // 正面(1)再升一层
        level++;
    return level;
}
```

**重点：层数服从「几何分布」——$P(\text{层数} \ge k) = 2^{-k}$，期望层数 2。** 于是各层的结点数自然呈「每层减半」——高层结点少、但跳得远，正是跳表「期望平衡」的来源。<span class="marginnote">「<strong>硬币决定高度，高度决定跳过多少</strong>」：<strong>层数期望 2、高层结点指数衰减</strong>——这个分布恰好让「每层减半」的结构以概率方式自动实现。<strong>随机化的妙处：不需要任何「平衡维护」，插入就自动维持「期望平衡」</strong>。</span>

## 3 公式解析：期望层数与空间

设 $n$ 个结点：

$$
\mathbb{E}[\text{层数}] = \sum_{k\ge1} P(\text{层数} \ge k) = \sum_{k\ge1} 2^{-k} = 1 \ (\text{第0层}) + \text{期望额外} \ 1 = O(1) \text{ 额外指针/结点}
$$

- **第一步，读「每结点期望 2 个指针」**：期望层数 2 = 每个结点平均 2 个前向指针——**空间 $O(n)$，常数略大于单链表**。
- **第二步，读「与 BST 对比」**：BST 每结点 2 个指针；跳表期望也是 2 个——**空间同阶**。
- **第三步，读「顶层高度」**：最顶层有 $O(\log n)$ 层的概率极高（$n$ 个结点、层数 $\log n$ 的期望），**查找路径期望 $O(\log n)$**。<span class="marginnote">「<strong>期望层数 2 = 空间与 BST 同阶</strong>」是跳表「免费」的证据：<strong>它没比 BST 多用空间，却用「随机」替代了「旋转/染色」的复杂维护</strong>。<strong>「空间不涨、复杂度不涨、实现大降」</strong>——这就是跳表的设计红利。</span>

## 4 查找、插入、删除的流程

**查找**：从最高层头开始，向右走到「不大于目标的最大结点」，降层，重复，直到第 0 层——目标若存在必在附近。
**插入**：查找插入位置；抛硬币定层数；把新结点插入到所有「它该出现的层」的对应位置。
**删除**：查找目标，从最高层到第 0 层逐层摘除。

```cpp
// 查找 key：从最高层头出发，能跳就跳、不能跳就降层
bool search(int key) {
    Node* p = head;
    for (int k = level; k >= 0; --k) {            // 从最高层逐层下降
        while (p->forward[k] && p->forward[k]->key < key)
            p = p->forward[k];                    // 同层向右跳到不大于 key 的最大结点
    }
    p = p->forward[0];                            // 降到最后，第 0 层再走一步
    return p && p->key == key;                    // 目标若存在，必在附近
}
```

**重点：查找的黄金规则是「能跳就跳、不能跳就降层」**——每层做「向右跳到不大于目标」，然后降层，循环到第 0 层。<span class="marginnote">「<strong>跳 + 降</strong>」二重奏是跳表查找的全部动作：<strong>同一层尽量向右跳（省步数），跳不动就降一层（换更细的粒）</strong>。<strong>这套「贪心向右 + 逐步降层」恰好命中目标</strong>——它本质是「二分查找的链表化」。</span>

## 5 跳表 vs 平衡树：随机 vs 确定

| 维度 | 跳表 | 平衡树（AVL/红黑） |
| --- | --- | --- |
| 平衡机制 | 随机层数（期望） | 旋转/染色（确定） |
| 复杂度 | 期望 $O(\log n)$ | 最坏 $O(\log n)$ |
| 实现难度 | 低 | 高 |
| 并发友好 | 好（层内无锁） | 较差（重平衡需锁子树） |
| 最坏情况 | 概率极低退化 | 绝无退化 |

**重点：跳表用「期望」换「简单」**——它没有确定的最坏保证，但退化概率指数级小；而它换来的是**实现短一大截、并发更容易**。工程里「确定性要求不高、要简单可维护」的场景，跳表胜出。<span class="marginnote">「<strong>随机 vs 确定，是复杂度哲学的两种极致</strong>」：<strong>跳表赌「大概率好」（退化概率 $2^{-n}$），平衡树保「绝对好」（最坏有界）</strong>。<strong>「工程上『几乎一定好』常常够用」</strong>——这就是 Redis 敢用跳表、内核却用红黑树的原因：<strong>应用场景对「最坏」的容忍度不同</strong>。</span>

## 6 小结

- 跳表 = 多层有序链表，高层跳过更多结点。
- 查找：从高层开始「能跳就跳、不能跳就降层」，期望 $O(\log n)$。
- 随机层数：抛硬币升层，几何分布，每结点期望 2 个指针、空间 $O(n)$。
- 插入：查位 + 定层 + 多层插入；删除：逐层摘除。
- 期望平衡、无旋转、无染色——实现远简于平衡树。
- 选型：要确定性最坏选平衡树，要简单可维护选跳表（Redis）。
