## 为什么初始有序段可以「超过内存」

外部排序的第一阶段把数据切段、段内排序。朴素做法是「每装满内存就排一段」——段长 ≤ 内存。**置换-选择排序（replacement-selection sort）**打破这个限制：**利用「输入不断到来 + 内存中的最小者不断输出」的流水线，生成的段可以比内存更长**。它的机制像一台「置换流水线」：内存里维护一个小根堆（或胜者树），读入一个新元素就输出一个当前最小——只要新元素比刚输出的元素大，它就能留在本段。段长因此不再受内存限制，初始段数减少，归并趟数随之减少。

## 1 置换-选择排序的思想

设内存能装 $M$ 个元素，用小根堆维护。生成一个有序段的过程：

1. 从输入读 $M$ 个元素，建小根堆；
2. 输出堆顶（当前最小），写入当前有序段；设刚输出的值为 `last`；
3. 读入一个新元素：
   - 若新元素 ≥ `last`，它属于当前段——入堆；
   - 若新元素 < `last`，它属于下一段——**暂存**到「下一段缓冲区」；
4. 堆空（都小于 `last`）→ 当前段结束，开始下一段。

```c
while (还有输入) {
    x = 读入一个元素;
    if (x >= last) { push(heap, x); }      /* 属于当前段，入堆 */
    else { 暂存 x 到下一段缓冲区; }          /* 属于下一段 */
    if (heap 非空) {
        last = pop(heap);                   /* 输出当前段最小 */
        写 last 到当前段;
    } else {
        当前段结束; 下一段缓冲区的内容成为新堆; last = -∞;
    }
}
```

**重点：只要新读入的元素比「刚输出的元素」大，它就能留在当前段——段可以无限长下去。** 这正是「置换」二字的含义：读一个、换出一个，段内始终保持「输出序列有序」。<span class="marginnote">「新元素 ≥ last 就归本段」的判断非常优雅：<strong>它保证段内输出序列非降，而无需关心整个段先验有序</strong>——有序性由「每次输出都 ≥ 上一个」的动态约束逐点保证。这是一台真正的「流水线排序」：<strong>输入在流，输出在流，内存只当「缓冲 + 仲裁」</strong>。</span>

## 2 公式解析：置换-选择排序的平均段长

设内存容量 $M$、输入随机，置换-选择排序生成的**平均段长**：

$$
\text{平均段长} \approx 2M
$$

- **第一步，读「为什么是 2M」**：堆里 $M$ 个元素，输入随机时，新元素「大于当前堆顶」的概率约 1/2（堆顶接近当前输出的最小值），故平均每读两个新元素才「淘汰」一个——段长约为内存的 2 倍。
- **第二步，读「相比朴素切段」**：朴素切段每段 $M$、段数 $n/M$；置换-选择平均段长 $2M$、段数约 $n/(2M)$——**段数减半**。
- **第三步，读「归并趟数的收益」**：趟数 = $\lceil \log_k m \rceil$，$m$ 减半 → 趟数可能减 1——**省一整遍读写全文件的 I/O**。<span class="marginnote">「平均段长 2M」是随机输入下的理论值，数据越有序，段长越长——<strong>输入天然有序时，置换-选择能生成「超长段」，甚至一次通过</strong>。这个「吃数据有序性红利」的性质，让它在「数据部分有序」的实际场景中特别有效。</span>

## 3 置换-选择 vs 朴素切段

| 维度 | 朴素切段 | 置换-选择 |
| --- | --- | --- |
| 段长 | ≤ 内存 $M$ | 平均 $2M$，可更长 |
| 段数 | $n/M$ | 约 $n/(2M)$ |
| 归并趟数 | $\lceil\log_k(n/M)\rceil$ | $\lceil\log_k(n/(2M))\rceil$ |
| 实现 | 简单 | 需堆 + 双缓冲 |
| 数据有序时 | 无红利 | **段长暴涨** |

**重点：置换-选择用「堆 + 双缓冲」的实现复杂度，换「段数减半」的 I/O 收益**——当数据量大、I/O 是瓶颈时，这笔交易非常划算。<span class="marginnote">「置换-选择」是「<strong>用内存里的堆，榨取输入流的有序性</strong>」的典范。<strong>它把「切段」从「离线批次」变成「在线流水」</strong>——在线处理常常能利用「数据到达顺序」里的信息，这是离线算法做不到的。</span>

## 4 与内部排序的关系

置换-选择排序的内部是「小根堆」——它本质是**「堆排序的在线版」**：一边读入、一边输出最小。联系到 §10.7 堆排序：

- 堆排序：把全部数据先建堆、再依次取顶——离线；
- 置换-选择：数据流式到来，读一个、堆维护、输出一个——在线；
- 两者共用「堆 = 动态维护最小值」这一核心能力。

**辨析｜易错点：置换-选择不是「每读一个就输出一个」那么简单。** 关键在「分段的判据」——`x >= last` 归本段、`x < last` 归下段。若判据写反，段内输出会乱序，整个外部排序崩坏。<span class="marginnote">「<strong>段边界 = 输入与输出之间的相对大小</strong>」是置换-选择最精妙的点：<strong>段与段的边界不是「内存满了」，而是「输入比当前段的最小输出还小」</strong>。这天然把「有序段」与「输入流」对齐——<strong>边界由数据决定，不由容量决定</strong>。</span>

## 5 置换-选择排序的意义

- **初始段优化**：外部排序第一阶段的核心优化——减少初始段数、减少归并趟数；
- **在线处理思想**：边读边排、边排边写——是「流式处理」的雏形；
- **与败者树配合**：置换-选择内部可用败者树代替堆，支持「内存装多段」的更复杂分配。

**重点：置换-选择排序教会我们「流水线的力量」**——排序不一定要「先收齐再排」，可以「边到边排」。这一思想在数据库的流式排序、MapReduce 的 map 端排序、大模型推理的流式输出里都有回响。<span class="marginnote">「<strong>在线 + 流水</strong>」是处理大数据的基本姿势：<strong>不等全部数据到齐，边到边处理，让内存只存「窗口」而非「全体」</strong>。置换-选择、流式聚合、滑动窗口，全是同一哲学——<strong>「窗口 + 增量」替代「全量 + 批量」</strong>。</span>

## 6 小结

- 置换-选择：读一个、换一个，段内输出非降，段长可超内存。
- 判据：新元素 ≥ `last` 归本段，否则归下段。
- 平均段长 ≈ $2M$；段数减半 → 归并趟数减一 → 省一遍 I/O。
- 内部是「小根堆 = 堆排序的在线版」。
- 数据有序时段长暴涨——吃「输入有序性」红利。
- 思想：在线流水处理，边到边排，内存只存窗口。
