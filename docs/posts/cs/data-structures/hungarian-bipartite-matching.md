## 什么是「最好的配对」

**二分图（bipartite graph）**：顶点分成左右两组，边只连左右。**匹配（matching）**：一组「两两不相交」的边（每个顶点至多匹配一次）。**最大匹配**：边数最多的匹配。现实里到处是它：**任务分配**（工人 × 任务）、**配对问题**（约会、宿舍）、**棋盘覆盖**。**匈牙利算法（Hungarian algorithm）**求二分图最大匹配，核心是**增广路（augmenting path）**——一条「从未匹配顶点出发、交替走未匹配/已匹配边、结束于另一未匹配顶点」的路径，把它「取反」就能让匹配数 +1。反复找增广路，直到没有，即最大匹配。朴素版 $O(VE)$。

## 1 匹配与增广路

设当前匹配为 $M$：

- **已匹配边**：$M$ 中的边；**未匹配边**：$E - M$；
- **增广路**：一条路径，起点和终点都是**未匹配顶点**，且边「未匹配、已匹配、未匹配、已匹配、……、未匹配」交替；
- **增广操作**：把增广路上的边「取反」（未匹配变已匹配、已匹配变未匹配）——**匹配数 +1**（因为增广路的未匹配边比已匹配边多 1 条）。

**重点：匹配数能 +1 ⇔ 存在增广路。最大匹配 ⇔ 不存在增广路。** 这是匹配理论的「增广路定理」，匈牙利算法就是「反复找增广路直到没有」的实现。<span class="marginnote">「<strong>增广路 = 加一条匹配的路</strong>」：<strong>路的起点终点都「自由」，沿路取反，匹配边数净增 1</strong>。<strong>「有没有增广路」是判断「还能不能更大」的唯一标尺</strong>——<strong>这个定理把「求最大匹配」变成「反复找增广路」</strong>。</span>

## 2 匈牙利算法的思想

对左侧每个未匹配顶点，尝试找增广路（DFS）：

```cpp
bool dfs(int u) {
    for (int v : adj[u]) {                    // 枚举 u 的每个候选右点
        if (vis[v]) continue;                 // 本轮已访问过，跳过
        vis[v] = true;
        if (match[v] == 0 || dfs(match[v])) { // v 空闲，或让 v 的现任另找下家
            match[v] = u;                     // 配对成功
            return true;
        }
    }
    return false;
}

int hungarian() {
    int res = 0;
    for (int u = 1; u <= n; ++u) {            // 对每个左点尝试一次增广
        memset(vis, 0, sizeof(vis));
        if (dfs(u)) res++;
    }
    return res;
}
```

**重点：`dfs(u)` 的递归是「让位链」——若 v 已被占，就尝试让 v 的现任匹配者 `match[v]` 另找下家**。这正是一条增广路的构造。<span class="marginnote">「<strong>递归让位 = 找增广路</strong>」：<strong>u 想要 v，但 v 已配给 w——就递归问 w「你能不能换一个」</strong>。<strong>这条「让位链」的终点若是一个自由右点，沿链取反就完成增广</strong>——<strong>匈牙利算法的全部，就是这个递归让位</strong>。</span>

## 3 公式解析：复杂度

设左部 $|L|$ 个顶点、右部 $|R|$、边 $e$：

$$
T_{\text{匈牙利}} = O(|L| \cdot e) = O(VE)
$$

- **第一步，读「对每个左点跑一次」**：最多对 $|L|$ 个左点各尝试一次增广。
- **第二步，读「每次 DFS 扫边」**：每次 `dfs(u)` 沿边搜索，最坏 $O(e)$。
- **第三步，读「改进版」**：用 Hopcroft-Karp（分层 + 多路增广）可到 $O(\sqrt{V}E)$——匈牙利已足够对付多数题目。<span class="marginnote">「<strong>匈牙利 $O(VE)$、Hopcroft-Karp $O(\sqrt{V}E)$</strong>」：<strong>匈牙利实现简单、够用；图很大时换 Hopcroft-Karp（BFS 分层 + DFS 多路增广）</strong>。<strong>「先上简单的，不够再优化」</strong>——匈牙利是竞赛匹配题的默认起手式。</span>

## 4 二分图的判定与建模

**怎么判断是不是二分图？** 染色法：BFS/DFS 给顶点染两色，相邻不同色——冲突则非二分图（含奇环）。

**把问题建成二分图匹配**：

**任务分配**：左 = 工人、右 = 任务、边 = 能胜任；
**棋盘/网格覆盖**：相邻格子黑白染色，左黑右白，边 = 可一起覆盖；
**最小路径覆盖 / 最大独立集**：由二分图匹配的性质推导（柯尼希定理）。

**辨析｜易错点：最大匹配 ≠ 完美匹配。** 完美匹配要求「每个顶点都被匹配」（左右等大且全匹配上）；最大匹配是「边数最多」，可能不是完美匹配（某侧有顶点落单）。<span class="marginnote">「<strong>最大 ≠ 完美</strong>」：<strong>完美匹配 = 所有顶点都匹配上（必要条件：左右顶点数相等）；最大匹配 = 边数最大（允许落单）</strong>。<strong>「完美」是「最大」的特例</strong>——<strong>很多题先问「能不能完美匹配」，就是问「最大匹配是否覆盖全部顶点」</strong>。</span>

## 5 二分图匹配的性质与应用

**柯尼希定理**：最大匹配 = 最小点覆盖（覆盖所有边的最少顶点数）；
**最大独立集** = 顶点数 - 最小点覆盖；
**应用**：任务分配、棋盘覆盖、课程安排、配对问题、图像分割（二分图割）。

**重点：二分图匹配不只是「配对」——它是一系列「覆盖/独立/路径覆盖」问题的计算引擎**，靠柯尼希定理把「匹配数」翻译成「覆盖数」。<span class="marginnote">「<strong>匹配是图论的中心枢纽</strong>」：<strong>最大匹配、最小点覆盖、最大独立集、最小路径覆盖——四个看似无关的极值，被柯尼希定理串成一个数值</strong>。<strong>「算一个，得四个」</strong>——这是二分图理论最优雅的地方。</span>

## 6 小结

- 二分图：左右两组、边只连左右；染色法判定（相邻异色）。
- 匹配：不相交边集；增广路 = 交替未匹配/已匹配、两端自由的路径。
- 增广路定理：匹配数能 +1 ⇔ 存在增广路；最大匹配 ⇔ 无增广路。
- 匈牙利算法：递归让位找增广路，$O(VE)$；Hopcroft-Karp 可优化到 $O(\sqrt{V}E)$。
- 最大 ≠ 完美：完美要求全匹配、最大只求边数。
- 柯尼希定理：最大匹配 = 最小点覆盖——匹配问题通向覆盖/独立集问题。
