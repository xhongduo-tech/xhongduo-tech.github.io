## 为什么从线性表开始

上一站《什么是数据结构》我们立起了**三要素**：逻辑结构、存储结构、数据运算。这一站开始落地。为什么第一站选线性表？因为它是**最简单、却包含一切「顺序」思想的结构**。

回顾第一级《集合的概念》里集合的三个特征：确定性、互异性、**无序性**。集合不讲顺序——$\{a,b\}$ 与 $\{b,a\}$ 是同一个集合。而线性表做的第一件事，就是**把「顺序」重新请回来**：我们规定元素 $a_1$ 必须在 $a_2$ 前面。这个看似微不足道的动作，是通往数组、链表、栈、队列、字符串、树的起点。<span class="marginnote">老子说「道生一，一生二，二生三，三生万物」：线性表就是那根「一」。给元素加上线性顺序得到线性表，把「一对多」加进去得到树，把「多对多」加进去得到图——后面的所有结构，都是从这一维「线」上长出来的。</span>

学完这一节，你将掌握：线性表的**形式化定义**（逻辑结构怎么用数学语言写清楚）、它区别于「存储结构」的**抽象性质**，以及第一份完整的数据结构规格说明 **ADT List**。这是全书「先定义逻辑结构，再分别实现」节奏的第一拍。

## 1 线性表的定义

严蔚敏《数据结构》给出的定义是这样的：

**线性表（linear list）**：由 $n(n \ge 0)$ 个**数据元素** $a_1, a_2, \dots, a_n$ 组成的**有限序列**。记作

$$L = (a_1, a_2, \dots, a_{i-1}, a_i, a_{i+1}, \dots, a_n)$$

其中 $n$ 称为表的**长度（length）**；当 $n = 0$ 时称为**空表（empty list）**。

这个定义里有三根柱子，缺一根都不成立：

- **有限性**：$n$ 必须是有限的整数。无限的数列（比如全体正整数）不构成线性表——计算机内存不可能装下一个无穷序列。<span class="marginnote">「有限序列」这四个字是计算机版与数学版的重要差别。数学里你可以谈论「所有自然数排成的序列」，但那是无限的；线性表要求有限，因为它最终要被放进有限的内存里。这个「现实约束」是数据结构区别于纯数学的地方。</span>
- **有序性**：$a_1$ 是第一个元素，$a_n$ 是最后一个元素；$a_i$ 是第 $i$ 个元素。$i$ 称为 $a_i$ 在表中的**位序（position）**。顺序是线性表最本质的属性。
- **同型性**：在同一个线性表中，数据元素的类型相同——要么都是整数，要么都是学生记录，不能混装。<span class="marginnote">「同型」意味着每个元素占用同样大小的存储空间，这是后文「顺序表能用乘法定位元素地址」的前提。C 语言的数组要求元素类型一致，正是这条性质在语言层面的体现。</span>

把「集合」和「线性表」并排放一眼：集合只看「在不在」，线性表还看「第几个」。这个差别，正是从第一级的数学语言走向第三级计算机世界的第一个台阶。

## 2 线性表：先于「存储」存在的逻辑结构

线性表是一个**逻辑结构**，而不是存储结构。这一点必须一开始就钉死：**「线性表」回答的是「元素之间是什么关系」，不回答「在内存里怎么摆」**。

同一张线性表的逻辑关系，可以用两种完全不同的方式在内存里落实：

- **顺序存储**：用一组地址连续的存储单元，让第 $i$ 个元素紧挨着第 $i-1$ 个元素存放。逻辑相邻 = 物理相邻。这是下一节《线性表的顺序表示和实现》。
- **链式存储**：元素放在任意位置，用指针把逻辑顺序「穿」起来。逻辑相邻 ≠ 物理相邻。这是再下一节《线性表的链式表示和实现》。

所以教材的编排是：**2.1 先给「逻辑定义」，2.2 和 2.3 再给「两种物理实现」**。这正呼应绪论里那句话——运算定义在逻辑结构上，实现于存储结构之中。

**辨析｜易错点：**「线性表」经常被误当成「顺序表」的同义词。其实顺序表只是线性表的一种实现。把「逻辑结构」和「存储结构」混为一谈，是本章最普遍的思维误区；后面学二叉树时，你会看到同一棵树的「双亲表示法、孩子表示法、二叉链表」三种存法——同一个道理。

## 3 ADT List：第一份完整的数据结构规格说明

绪论里我们看过 ADT Complex 的示范。现在轮到线性表本人——这是全书写得最完整的一份规格说明，它把「数据对象、数据关系、基本操作」三件套完整列出：

```text
ADT List {
    数据对象：D = { ai | ai ∈ ElemSet, i = 1, 2, …, n, n ≥ 0 }
    数据关系：R = { <a_{i-1}, ai> | ai-1, ai ∈ D, i = 2, …, n }
    基本操作：
        InitList(&L)            /* 构造一个空的线性表 L */
        ListEmpty(L)            /* 若 L 为空表，返回 TRUE，否则 FALSE */
        ListLength(L)           /* 返回 L 中数据元素的个数 */
        GetElem(L, i, &e)       /* 用 e 返回 L 中第 i 个元素的值 */
        LocateElem(L, e)        /* 返回 L 中第一个值与 e 相等元素的位序 */
        ListInsert(&L, i, e)    /* 在 L 中第 i 个位置之前插入新元素 e */
        ListDelete(&L, i, &e)   /* 删除 L 的第 i 个元素，并用 e 返回其值 */
} ADT List
```

这份规格说明有三点值得停下来品：

- **数据对象用集合语言写**：$D = \{ a_i \mid a_i \in \text{ElemSet},\ i=1,\dots,n,\ n\ge0 \}$——竖线、元素类型、个数范围，全是我们第一级学过的描述法。
- **数据关系用有序对写**：$R = \{ \langle a_{i-1}, a_i \rangle \mid \dots \}$——「$a_{i-1}$ 是 $a_i$ 的前驱」被写成有序对，这是集合论里「关系即有序对集合」的直接移植。<span class="marginnote">这是线性表与集合最深刻的联系：集合是第一级的基础，而「关系」正是第二级《离散数学》里的核心对象。一个线性表 = 一个元素集合 + 一条「前后相继」的二元关系。前驱/后继、第 $i$ 个，这些词在离散数学里都有严格定义。</span>
- **基本操作只有接口没有实现**：`ListInsert` 只声明「在第 $i$ 个位置之前插入 e」，至于顺序表怎么搬移元素、链表怎么改指针，这里一概不关心——那是 2.2、2.3 的事。

**这几个操作不是随便列的。** 它们构成了「存取、查询、增删」的完整工具箱，后面的顺序表、链表要实现的就是这同一份接口。这正是 ADT 的意义：**使用者只面对这份接口，实现者可以在不破坏接口的前提下换底层的存储方式**——哪怕将来从顺序表换成链表，调用 `ListInsert(&L, i, e)` 的代码一行都不用改。

## 4 公式解析：从「位序」到「下标」的翻译

线性表里最容易被忽略、却最实用的一条「公式」，是**位序与下标的关系**。数学里的序列从 1 数起，而 C 语言的数组从 0 数起。设元素 $a_i$ 存放在数组下标 $\text{idx}$ 处，则有：

$$\text{idx} = i - 1, \qquad i = \text{idx} + 1$$

对这个「笨公式」做三步拆解，你会看到它其实藏着整个顺序表的核心逻辑：

- **第一步，认清两个起点**：位序 $i$ 从 1 开始（第一个元素是 $a_1$）；下标从 0 开始（第一个元素是 `L.elem[0]`）。差值为 1，不多不少。
- **第二步，理解方向**：给位序求下标，减 1；给下标求位序，加 1。所有「第 $i$ 个位置」都要先翻译成 `i-1` 才能碰数组。这是全章 off-by-one 错误的根源。
- **第三步，看到背后的跳跃**：一旦第 1 个元素的地址确定了，第 $i$ 个元素的地址就可以**用乘法一步算出来**：

$$LOC(a_i) = LOC(a_1) + (i-1) \times \text{sizeof(ElemType)}$$

这条式子里的 $(i-1)$ 正是刚才的位序翻译。**因为能直接算出地址，顺序表才能「随机存取」：找第 1 个元素和第 1 万个元素一样快，都是常数时间。** 这一点是链式存储给不了的，下一节我们会在《顺序表》里重点展开这条公式。

## 5 从线性表到栈、队列、串：一份逻辑蓝图的三种变形

学完 ADT List，你已经握住了一把钥匙——**很多看似全新的数据结构，其实只是给这份基本操作加上了「使用规则」**。

- **栈（stack）**：只允许在表的一端（栈顶）插入和删除的线性表。逻辑结构不变，只是把 `ListInsert` 和 `ListDelete` 限制在表尾。于是「后进先出」（LIFO）这个新性质就长出来了。
- **队列（queue）**：只允许在表的一端插入、在另一端删除的线性表。同样共享线性结构，只是操作位置被钉死成「先进先出」（FIFO）。
- **串（string）**：数据元素限定为字符的线性表。任何一门语言里字符串的拼接、子串查找，底层都是一张「字符线性表」。

所以严蔚敏教材把「线性表、栈、队列、串」列为连续的四篇，不是随意排列——**它们共享同一份逻辑蓝图**。<span class="marginnote">这是理解全书的捷径：栈、队列、串都是「线性表 + 操作约束」。后面你还会看到，栈的递归实现、队列的广度优先遍历、串的 KMP 匹配，全都在吃这份「线性」的红利。先牢牢立住线性表，等于给后面三篇一次性打好地基。</span>

这也再次印证 ADT 的力量：**「是什么」与「怎么用」可以分离。** 线性表定义了完整的工具箱，栈和队列只是把「允许碰哪几个格子」的规则收紧——同样的底层顺序表或链表，改一行使用约定，就变成了完全不同的数据结构。这种「复用结构、改变约束」的思维，正是软件工程里组合优于继承的雏形。

## 6 小结

- 线性表是 $n(n\ge0)$ 个同型元素组成的**有限序列**，记为 $L = (a_1, a_2, \dots, a_n)$；$n$ 是表长，$n=0$ 为空表。
- 三根柱子：**有限性、有序性、同型性**；与集合相比，线性表多了「顺序」，位序 $i$ 是它的核心概念。
- 线性表是**逻辑结构**，顺序存储与链式存储是它的两种实现，二者不可混为一谈。
- **ADT List** 用集合语言（数据对象）、有序对（数据关系）和接口清单（基本操作）完成了第一份完整规格说明，体现「运算定义在逻辑结构上」。
- **位序与下标**差 1：$i \leftrightarrow i-1$；由此可得第 $i$ 个元素地址的乘法公式，这是顺序表随机存取能力的来源。
- **线性表的延伸**：栈、队列、串都是「线性表 + 操作约束」，同一份逻辑蓝图经约束变形即得新结构。

在下一节《线性表的顺序表示和实现》中，我们把这份 ADT 落到数组上，亲手写出顺序表的插入与删除，并算清楚它们为什么是 $O(n)$——以及那笔「移动元素」的代价到底值不值。
