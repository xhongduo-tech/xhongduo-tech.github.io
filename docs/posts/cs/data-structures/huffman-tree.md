## 为什么需要赫夫曼树

给 $n$ 个带权结点（如字符及其出现频率）造一棵二叉树，使**带权路径长度最小**——这就是**赫夫曼树（Huffman tree）**，也叫最优二叉树。它回答一个普遍问题：**权重高的对象，应该离根近（路径短），权重低的离根远。** 从哈夫曼编码（数据压缩）到最优判定树（分类）到数据库索引的某些变体，都是这一思想的产物。它的构造算法——「每次合并两个最小权值」——是**贪心算法**的第一次系统登场，也是后续《算法》课程里贪心证明的范本。

## 1 路径、路径长度与带权路径长度

三个概念层层递进：

- **路径与路径长度**：从树中一个结点到另一个结点之间的分支构成路径，路径上的分支数称为路径长度。
- **结点的带权路径长度**：从根到该结点的路径长度与该结点**权值**的乘积。
- **树的带权路径长度（WPL）**：树中**所有叶子**的带权路径长度之和。

$$
WPL = \sum_{i=1}^{n} w_i \cdot l_i
$$

其中 $w_i$ 是第 $i$ 个叶子的权值，$l_i$ 是根到它的路径长度。**WPL 越小，表示「高权对象走得越短」**——这是压缩、判定场景下的目标函数。<span class="marginnote">注意 WPL 只累加<strong>叶子</strong>：赫夫曼树关心的是「被查找/被编码的对象」的路径成本，内部结点是构造出来的、不直接计费。</span>

## 2 赫夫曼树的定义

**赫夫曼树（Huffman tree）**：由 $n$ 个带权叶子结点构造出的、**WPL 最小**的二叉树。它不唯一——权值相同的不同形态可能 WPL 相等，但**最小 WPL 值是唯一的**。

**重点：WPL 最小 ⇔ 大权叶子尽量靠近根。** 直觉上，把权值最大的叶子放在路径最短（深度最小）的位置，把权值最小的放最深，整体代价最小——这正是构造算法的贪心依据。<span class="marginnote">最坏情况的对比：把 $n$ 个叶子摆成一条斜链（每层一个），WPL 是 $O(n^2)$；赫夫曼树把它降到 $O(n \log n)$ 量级——因为高度从 $O(n)$ 压到 $O(\log n)$。对编码来说，这就是压缩比的天壤之别。</span>

## 3 赫夫曼树的构造算法

给定 $n$ 个权值 $w_1, w_2, \cdots, w_n$，构造赫夫曼树：

1. 把 $n$ 个权值看成 $n$ 棵**只有根的二叉树**，构成森林 $F$；
2. 从 $F$ 中**选出两棵根权值最小**的树，作为左右子树合成一棵新树，新根权值 = 两权值之和；
3. 从 $F$ 中删除这两棵树，把新树加入 $F$；
4. 重复步骤 2、3，直到 $F$ 只剩一棵树——它就是赫夫曼树。

```c
typedef struct {
    unsigned weight;             /* 权值 */
    int parent, lchild, rchild;  /* 双亲与左右孩子下标，-1 表示空 */
} HTNode;

/* 在 ht[1..k] 中选出两个权值最小且双亲为空的结点 */
void Select(HTNode ht[], int k, int *s1, int *s2) {
    int i, min1 = 0, min2 = 0;
    for (i = 1; i <= k; i++)
        if (ht[i].parent == -1) { min1 = i; break; }
    for (i = 1; i <= k; i++)
        if (ht[i].parent == -1 && ht[i].weight < ht[min1].weight) min1 = i;
    for (i = 1; i <= k; i++)
        if (ht[i].parent == -1 && i != min1) { min2 = i; break; }
    for (i = 1; i <= k; i++)
        if (ht[i].parent == -1 && i != min1 && ht[i].weight < ht[min2].weight) min2 = i;
    *s1 = min1; *s2 = min2;
}

/* 用 n 个权值 w[1..n] 构造赫夫曼树，存于 ht[1..2n-1] */
void HuffmanTree(HTNode ht[], int w[], int n) {
    int i, m = 2 * n - 1, s1, s2;
    for (i = 1; i <= m; i++) ht[i].parent = ht[i].lchild = ht[i].rchild = -1;
    for (i = 1; i <= n; i++) ht[i].weight = w[i];
    for (i = n + 1; i <= m; i++) {              /* 合并 n-1 次 */
        Select(ht, i - 1, &s1, &s2);            /* 取两个最小根 */
        ht[s1].parent = ht[s2].parent = i;
        ht[i].lchild = s1;  ht[i].rchild = s2;
        ht[i].weight = ht[s1].weight + ht[s2].weight;
    }
}
```

**重点：算法共执行 $n-1$ 次合并，得到 $2n-1$ 个结点的赫夫曼树**——$n$ 个叶子 + $n-1$ 个内部结点。<span class="marginnote">「每次取两个最小」是贪心选择：局部最优（合并当前最小的两个）导向全局最优（WPL 最小）。这个「贪心正确」需要用<strong>交换论证</strong>证明——把任意最优树里的非最小叶子与最小叶子对换，WPL 不会增大。这是贪心算法证明的标准模板。</span>

## 4 公式解析：赫夫曼树的规模

设叶子数为 $n$，则赫夫曼树的总结点数为：

$$
\text{结点总数} = n + (n - 1) = 2n - 1
$$

- **第一步，读叶子的贡献**：$n$ 个叶子是给定的对象本身。
- **第二步，读内部结点的来源**：每次合并产生 1 个新内部结点，共合并 $n-1$ 次，产生 $n-1$ 个内部结点。
- **第三步，验证「无度为 1 的结点」**：赫夫曼树中每个内部结点恰好两个孩子（合并产生），所以 $n_1 = 0$。由二叉树性质 3（$n_0 = n_2 + 1$）验证：$n_2 = n_0 - 1 = n - 1$，与合并次数一致。<span class="marginnote">「$2n-1$」这个数与二叉链表空指针数「$n+1$」呼应：<strong>赫夫曼树是「满」的（无单子结点），形态完全由叶子权值决定</strong>。存储时用一个 $2n-1$ 的数组即可装下全部结点。</span>

## 5 赫夫曼树的应用一：最优判定树

分类问题里，判定树每个叶子是一个结论，内部结点是一次比较。**不同判定顺序的代价不同**——把「出现频率高」的类别放在浅层，能减少平均比较次数，这正是赫夫曼树：

把每个类别及其概率（作为权值）构造成赫夫曼树；
从根到叶子的路径就是判定过程；
**平均判定代价 $= WPL / \text{总概率}$，被赫夫曼树最小化**。<span class="marginnote">经典的例子是「按成绩划分优/良/中/差」：若优秀率 5%、良好率 15%、中等 60%、不及格 20%，用赫夫曼树排判定顺序，先判「是否中等」能最快排除大多数。赫夫曼树把「最常走的分支」放最浅，平均判 2 次即得结论，而非顺序判定平均 3 次。</span>

## 6 小结

- 带权路径长度 $WPL = \sum w_i l_i$，只计叶子。
- 赫夫曼树 = WPL 最小的二叉树；大权叶子靠近根、小权叶子远离根。
- 构造算法：每次合并两个最小权值，共 $n-1$ 次，$2n-1$ 个结点。
- 贪心选择「合并两个最小」→ 全局最优，用交换论证证明。
- 赫夫曼树无度为 1 的结点（$n_1 = 0$）。
- 应用一：**最优判定树**——把高概率类别放浅层，最小化平均判定代价。
