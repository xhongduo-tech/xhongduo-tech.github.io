## 为什么归并排序是「分治」的模范

快速排序「分而不管合」，**归并排序（merge sort）**则把分治的每一半都做标准：**分解**——把序列对半拆；**求解**——递归排序两半；**合并**——把两个有序子序列归并成一个有序序列。它的复杂度稳定 $O(n\log n)$、且**稳定**，是「稳定性 + 确定性」的双料冠军。代价是**需要 $O(n)$ 的辅助空间**（合并时的临时数组）。归并排序还是外部排序的基石——磁盘上的大规模排序，正靠「归并」把多个有序段合成一个。

## 1 二路归并的思想

**二路归并（2-way merge）**：把两个**已有序**的序列合并成一个有序序列——就是第二篇《一元多项式的相加》里那个「双指针一趟归并」：

```c
void Merge(int a[], int low, int mid, int high) {
    int b[MAX];                              /* 辅助数组 */
    for (k = low; k <= high; k++) b[k] = a[k];  /* 复制到辅助 */
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high)            /* 双指针归并 */
        a[k++] = (b[i] <= b[j]) ? b[i++] : b[j++];
    while (i <= mid) a[k++] = b[i++];        /* 左半余下 */
    while (j <= high) a[k++] = b[j++];       /* 右半余下 */
}
```

**重点：归并的正确性依赖「两个子序列各自有序」——而递归保证了这个前提。** `Merge` 里的 `<=` 是稳定性的关键：相等时先取左边的，等值元素保持原序。<span class="marginnote">「归并」在本书已第三次出现：<strong>一元多项式相加、稀疏矩阵加法、归并排序</strong>——全是「两个有序序列线性合并」。这是「有序 + 有序 = 有序」这条最强大的结构性质的集中体现，也是外部排序（第十一篇）的全部基础。</span>

## 2 归并排序的递归框架

```c
void MergeSort(int a[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MergeSort(a, low, mid);              /* 排序左半 */
        MergeSort(a, mid + 1, high);         /* 排序右半 */
        Merge(a, low, mid, high);            /* 合并两半 */
    }
}
```

**重点：归并排序是「按位置对半切」的稳定分治——切法固定，与数据无关，因此复杂度与输入无关（无最坏退化）。** 这正是它与快排的分水岭：快排按「值」划分（受输入影响），归并按「位置」划分（输入无关）。<span class="marginnote">「<strong>位置分治 = 输入无关，值分治 = 输入敏感</strong>」是一条重要的判据：归并按位置对半，永远完美平衡；快排按值划分，平衡度取决于枢轴。这也是归并「最坏也 $O(n\log n)$」而快排「最坏 $O(n^2)$」的根源。</span>

## 3 公式解析：归并排序的复杂度

$$
\begin{aligned}
T_{\text{归并}} &= O(n\log n) \quad \text{（递归 } \log n \text{ 层，每层归并总代价 } O(n) \text{）} \\
S_{\text{辅助空间}} &= O(n) \quad \text{（合并需要临时数组）}
\end{aligned}
$$

- **第一步，读递推**：$T(n) = 2T(n/2) + O(n)$，解出 $T(n) = O(n\log n)$——主定理的第一种情形。
- **第二步，读每层代价**：第 $k$ 层有 $2^k$ 个子序列、每个合并 $O(n/2^k)$，整层合计 $O(n)$；共 $\log n$ 层。
- **第三步，读「稳定 + 最坏有保证」**：归并同时具备「稳定」与「最坏 $O(n\log n)$」——**这是快排和堆排都给不了的组合**（快排不稳且最坏 $O(n^2)$，堆排不稳）。<span class="marginnote">归并是「<strong>三好学生</strong>」：稳定 + 最坏 $O(n\log n)$ + 顺序访问（对链表友好）。它的唯一短板是 $O(n)$ 辅助空间——对内存敏感的场景（嵌入式）不划算，但对稳定排序刚需的场景（多关键字排序、外部排序）无可替代。</span>

## 4 稳定性与链式归并

- **稳定性**：稳定。`Merge` 用 `<=`，相等时取左半元素，等值元素保持原序。
- **链式归并**：链表上的归并排序**不需要辅助数组**——链表合并只改指针。因此归并排序是「链表排序」的默认选择（`std::list::sort` 就是归并）。

**辨析｜易错点：归并排序的 $O(n)$ 空间不是必须的，但「原地归并」极难。** 严格原地归并（$O(1)$ 空间）存在但实现复杂且常数巨大。实践中要么接受 $O(n)$ 辅助（数组归并），要么用链表（零辅助）。**「要稳定又要省空间」在归并里只能二选一。**<span class="marginnote">「稳定 + 省空间」的不可兼得，是排序领域长期无解的问题（原地稳定归并一直是个难题）。工程上的折中：<strong>链表用归并（免辅助空间），数组用 introsort（不稳但快）</strong>——按「数据形态 + 稳定性需求」分工。</span>

## 5 归并排序的工程形态

- **自底向上的归并（迭代版）**：从「长度 1 的段」开始，两两归并成长度 2、4、8……——不用递归，适合外部排序；
- **Timsort**：Python 与 Java 的默认排序——检测「天然有序段」（run），把 run 按规则归并，结合插入排序收尾。它利用「现实数据常有有序段」的规律，达到「近乎有序时 $O(n)$」；
- **外部归并**：磁盘上的数据先切成有序段，再多路归并（第十一篇）。

**重点：Timsort 说明「归并思想 + 利用数据规律」能造出工业级排序**——Python 的 `sorted()` 之所以默认 Timsort，正是看中它对「现实数据」的平均性能与稳定性。<span class="marginnote">「<strong>检测天然有序段，再归并</strong>」是 Timsort 对归并的改造：<strong>现实数据（数据库查询结果、日志）往往自带有序段，直接用归并吃掉它们，比从头排序快得多</strong>。这是「算法适配数据规律」的完美案例——也是我们学数据结构时应有的视角：<strong>好算法是「贴着数据形状」设计的</strong>。</span>

## 6 小结

- 归并排序 = 位置对半分治 + 双指针合并，递归完成。
- $T(n) = 2T(n/2) + O(n)$，解出 $O(n\log n)$，输入无关、最坏也有保证。
- **稳定**（`Merge` 用 `<=`）+ 最坏 $O(n\log n)$——快排/堆排给不了的组合。
- 辅助空间 $O(n)$；链表归并可免辅助空间。
- 迭代版（自底向上）是外部排序的骨架。
- Timsort：检测有序段 + 归并 + 插入，Python/Java 默认排序。
