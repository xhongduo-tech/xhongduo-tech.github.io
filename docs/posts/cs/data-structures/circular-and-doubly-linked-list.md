## 为什么还要改链表

单链表已经解决了「插入不用搬元素」，但留下两个隐痛。其一，**从尾部走回头部**要走一整圈——表尾结点是 `NULL`，你想再从表尾绕回表头，得从表头重新来过。其二，**找前驱要 $O(n)$**——单链表只有 `next` 一根指针，想知道「上一个」只能从头再走一遍。老子说「反者道之动」：道总是在返回中运动。这一节的两处改造，正是让链表学会「返回」——**循环链表**让尾部自动绕回头部，**双向链表**让每个结点都能向前走。

这两个结构不是学术摆设：循环链表是约瑟夫问题（Josephus problem）与进程调度轮转（round-robin）的天然载体；双向链表是 LRU 缓存、编辑器文本缓冲、`std::list`、Linux 内核链表的基础。学完这一节，线性表的链式家族就齐了，我们也攒够了去实现《一元多项式的表示及相加》的全部零件。

## 1 循环链表：把 NULL 换成头指针

**循环链表（circular linked list）**：把单链表中最后一个结点的指针域由空（`NULL`）改为**指向头结点（或头指针）**，使整个链表形成一个环。

对带头结点的循环单链表，判断条件随之改变：

- 单链表判空：`L->next == NULL`；
- **循环链表判空：`L->next == L`**——头结点的 next 又指回自己。

```c
/* 循环链表的判空 */
int ListEmpty(LinkList L) {          /* L 是头指针，指向头结点 */
    return L->next == L ? TRUE : FALSE;
}
```

**辨析｜易错点：** 循环链表的遍历结束条件从「遇到 `NULL` 停」变成「回到头结点停」。若还用旧的 `while (p != NULL)` 来遍历，循环链表会**永远循环下去**——这是初学循环链表最经典的死循环来源。遍历的写法要改成：

```c
p = L->next;                          /* p 指向第一个元素结点 */
while (p != L) {                      /* 回到头结点即遍历完毕 */
    visit(p->data);
    p = p->next;
}
```

循环链表最大的好处是**对称性**：从表中**任意**一个结点出发，都能走遍全表。对单链表，访问表尾后要回头只能从头走，循环链表则天然绕回来了。<span class="marginnote">这个「从任意结点可到达任意结点」的性质，正是图论里「强连通」概念在链表上的雏形。循环链表是一个最简单的一维「环」，而第三级《算法设计与分析》里的环检测（Floyd 判圈）正是基于这类环形结构。</span>

## 2 约瑟夫问题：循环链表的经典战场

循环链表最著名的应用是**约瑟夫问题**：$n$ 个人围成一圈，从第 1 个人开始报数，报到 $m$ 的人出列，然后从下一个人重新报数，问出列顺序。这个「一圈人不断出列」的模型，用循环链表实现几乎不需要思考——删除一个结点后自然停在下一结点，继续报数即可。

```c
/* 用带头结点的循环链表求解约瑟夫问题（n 个人，报数到 m 出列） */
void Josephus(int n, int m) {
    LinkList L = CreateCircList(n);      /* 建一个含 n 个元素的循环链表 */
    LNode *p = L->next, *prev = L;       /* p 指向第 1 人，prev 记前驱 */
    while (p->next != p) {               /* 圈里只剩一人时结束 */
        for (int k = 1; k < m; ++k) {    /* 报数到 m：前移 m-1 步 */
            prev = p;
            p = p->next;
        }
        printf("%d ", p->data);          /* 报到 m 的人出列 */
        prev->next = p->next;            /* 断链删除该结点 */
        free(p);
        p = prev->next;                  /* 从下一个人重新开始报数 */
    }
    printf("%d\n", p->data);             /* 最后剩下的人 */
}
```

这个实现的精妙在于：**删除结点后 `p` 自动落在下一个人身上，不需要额外「前进」一步**——这正是环结构的天然馈赠。约瑟夫问题还有一个著名的数学闭式解（当 $m=2$ 时答案与 $n$ 的二进制表示有关），但它只回答「最后剩下谁」，而循环链表能直接给出**完整的出列顺序**——「要一个序列还是要一个数」，决定了用模拟还是用数学。

## 3 双向链表：补上「前驱」这根指针

**双向链表（doubly linked list）**：在单链表的每个结点中，再增加一个指向**直接前驱**的指针域 `prior`。这样每个结点都有两根指针：`prior` 指向前一个，`next` 指向后一个。

```c
typedef struct DuLNode {
    ElemType         data;      /* 数据域 */
    struct DuLNode  *prior;     /* 前驱指针：指向直接前驱 */
    struct DuLNode  *next;      /* 后继指针：指向直接后继 */
} DuLNode, *DuLinkList;
```

双向链表对称而优雅：**已知结点 `p`，它的前驱是 `p->prior`，后继是 `p->next`**。这意味着单链表里「找前驱要 $O(n)$」的短板被补上了——给定任意结点，向前向后都只要一步。

代价也很清楚：**每个结点多存一个指针**。空间从「一个数据 + 一个指针」变成「一个数据 + 两个指针」。这就是「用空间换时间」的第二次应用：多花一份指针空间，把「向前走」从 $O(n)$ 降到 $O(1)$。

## 4 双向链表的插入与删除：对称的四步与两步

双向链表插入/删除的特点是**两对指针都要改**。在结点 `p` 之后插入新结点 `s`，需要四步：

```c
s->prior = p;            /* ① s 的前驱 = p */
s->next = p->next;       /* ② s 的后继 = p 的后继 */
p->next->prior = s;      /* ③ 原后继的前驱改为 s */
p->next = s;             /* ④ p 的后继改为 s */
```

删除结点 `p` 本身（而不是它的后继），因为有了 `prior`，**不需要找前驱**，两步即可：

```c
p->prior->next = p->next;      /* 让前驱的 next 跨过 p，指向 p 的后继 */
p->next->prior = p->prior;     /* 让后继的 prior 跨过 p，指回 p 的前驱 */
free(p);                       /* 释放 p */
```

**辨析｜易错点：** 双向链表删除自己只要 $O(1)$——这正是它相对单链表的重大升级。单链表想删除结点 `p` 本人，必须从头找到它的前驱（$O(n)$）；双向链表直接 `p->prior` 就拿到前驱了。但也正因如此，**前驱/后继指针必须成对维护**：插入的四个赋值、删除的两个赋值，任何一步漏掉，链表就「裂」成两截——这是双向链表最容易出 bug 的地方。写完后务必检查：**每个结点被它的前驱和后继同时指到**。

## 5 循环双向链表：把两处改造合起来

把循环与双向合在一起，得到最「满配」的线性链表结构——**循环双向链表**：头结点的 `prior` 指向表尾，表尾的 `next` 指向头结点，两头接成一个环。

- 判空：`L->prior == L` 且 `L->next == L`；
- 从任意结点出发，可沿两个方向走遍全表；
- 插入删除在任意位置都是 $O(1)$，且不需要特判边界。

这个结构就是 C++ 标准库 `std::list` 的底层模型，也是 Linux 内核 `list_head` 双向循环链表的设计蓝本。<span class="marginnote">内核把链表做成「链表结构内嵌进数据结点」的形态，让同一套插入删除代码服务于所有类型的数据——这是「把操作从具体数据中剥离」的教科书级抽象。工程细节在第三级《操作系统》的进程管理、文件系统缓存里会反复遇到。</span>

**辨析｜易错点：** 循环链表的「头结点」现在既是头也是尾——头结点 `next` 指向第一个元素、`prior` 指向最后一个元素。遍历方向不同，结束条件也不同：沿 `next` 走回到 `L` 停，沿 `prior` 走也回到 `L` 停。**「回到头结点」就是循环结构统一的结束条件**，记住这一句，循环链表的遍历就不会绕晕。

## 6 公式解析：三种链表在「删除结点 p 本身」上的对比

三种链表的差别，用一条对比最能看清。设要删除**已知指针 `p` 指向的结点**，三种结构的复杂度：

$$
T_{删除}(p) = \begin{cases}
O(n), & \text{单链表（需从头找 } p \text{ 的前驱）} \\[2pt]
O(1), & \text{双向链表（} p\text{-}\text{>prior 直接可取）} \\[2pt]
O(1), & \text{循环单链表（若已知表尾指针）}
\end{cases}
$$

三步拆解：

- **第一步，单链表为何 $O(n)$**：单链表没有前驱指针，要删 `p` 必须先找到 `p` 的前驱才能改它的 `next`。而找前驱只能从头遍历，最坏要走 $n$ 步。
- **第二步，双向链表为何 $O(1)$**：`p->prior` 一步拿到前驱，改 `p->prior->next` 与 `p->next->prior` 两个赋值即完成，不随 $n$ 变化。
- **第三步，循环单链表的特殊情况**：若只维护一个**表尾指针 `rear`**，则表尾结点的后继就是表头——删除表尾本人可以借 `rear->prior` 走一圈定位，这类「已知表尾即可绕行」的便利，正是循环结构对称性的价值。

这条对比讲透了本章的技术路线：**顺序表用「位置」换「搬运」，单链表用「指针」换「遍历」，双向链表再用「双指针」换「回退」。** 每一步都在补前一步的短板，每一步都付出相应的空间或常数代价——数据结构的发展史，就是一份「取舍」的账本。

## 7 小结

- **循环链表**：表尾 `next` 指回头结点，判空条件变为 `L->next == L`，遍历结束条件是「回到头结点」而非 `NULL`。
- **循环的价值**：从任意结点可走遍全表，天然适配约瑟夫问题与轮转调度等「围成一圈」的场景。
- **双向链表**：每个结点增加 `prior` 前驱指针，找前驱从 $O(n)$ 降到 $O(1)$；插入要改四根指针、删除改两根，必须成对维护。
- **循环双向链表**：两头相接，插入删除任意位置都是 $O(1)$，是 `std::list` 与 Linux 内核链表的结构原型。
- 三者的取舍主线：**用空间换时间、用指针补短板**——没有全能结构，只有匹配需求的结构。
