## 为什么有序性能换速度

顺序查找「逐个比较」的浪费在于：比较第 3 个元素后，前两个的信息被丢掉。若表**有序**，则可用**折半查找（binary search）**：取中间元素比较，一次排除一半——「每次比较都在告诉你答案在哪半边」。$n=10^6$ 时顺序查找平均 50 万次，折半查找最多 20 次。这 $\log_2 n$ 的差距，是计算机科学最经典的「用有序性换时间」。折半查找还是**判定树**的首次登场——所有比较过程可以被画成一棵二叉树，这棵树决定了它的平均代价。

## 1 折半查找的思想

设表按关键字升序，区间 $[low, high]$ 初始为 $[1, n]$：

1. 取中点 $mid = \lfloor (low+high)/2 \rfloor$；
2. 若 $a[mid] = key$ 找到；若 $a[mid] > key$ 查左半 $[low, mid-1]$；若 $a[mid] < key$ 查右半 $[mid+1, high]$；
3. 重复直到找到或区间为空（失败）。

```c
int BinarySearch(int a[], int n, int key) {
    int low = 1, high = n, mid;
    while (low <= high) {                       /* 闭区间 */
        mid = (low + high) / 2;
        if (a[mid] == key) return mid;          /* 找到 */
        else if (a[mid] > key) high = mid - 1;  /* 查左半 */
        else low = mid + 1;                     /* 查右半 */
    }
    return 0;                                   /* 失败 */
}
```

**重点：循环条件 $low \le high$ 与区间收缩 $mid\pm1$ 必须配套。** 若写 $low < high$ 或收缩成 $mid$，可能漏查或死循环——这是折半查找最经典的边界陷阱。<span class="marginnote">边界条件为何如此容易错？因为「<strong>区间是闭区间还是半开区间</strong>」决定收缩方式。<strong>闭区间 $[low, high]$ 配 $mid\pm1$，半开区间 $[low, high)$ 配 $mid$ 与 $mid+1$</strong>——先定区间约定，再写收缩，就稳了。</span>

## 2 判定树：折半查找的「路线图」

整个折半查找的比较过程，可以画成一棵**判定树（decision tree）**：树根是第一次比较的**中间元素**（即 $\lfloor (1+n)/2 \rfloor$），左子树是查左半的过程，右子树是查右半的过程。

**重点：$n$ 个元素的有序表，其折半判定树是一棵「近似完全二叉树」。** 每个结点对应一个「可能被比较的元素」，从根到该结点的路径长度 = 比较次数。<span class="marginnote">判定树把「算法过程」变成「树结构」，是分析查找算法最有力的工具：<strong>查找成功的比较次数 = 结点深度，查找失败落在叶子的空孩子上</strong>。第六篇二叉树的所有性质（深度、叶子数、完全二叉树编号），在这里直接变成「最多比较几次」的答案。</span>

## 3 公式解析：折半查找的 ASL

设 $n$ 个元素，判定树深度为 $h = \lfloor \log_2 n \rfloor + 1$。查找成功的平均比较次数：

$$
ASL_{\text{成功}} = \frac{1}{n}\sum_{i=1}^{n} (\text{第 } i \text{ 个结点的层数})
$$

若 $n = 2^h - 1$（满二叉树），第 $k$ 层有 $2^{k-1}$ 个结点、比较 $k$ 次：

$$
ASL_{\text{成功}} = \frac{1}{n}\sum_{k=1}^{h} k \cdot 2^{k-1} \approx \log_2(n+1) - 1
$$

- **第一步，读层数求和**：判定树的每层结点数 × 层数，除以总结点数——与二叉树的层统计完全一致。
- **第二步，读近似**：满树时精确值为 $\frac{n+1}{n}\log_2(n+1) - 1$，$n$ 大时趋向 $\log_2(n+1) - 1$。
- **第三步，与顺序查找对比**：$n = 10^6$，折半 ≈ 19 次，顺序 ≈ 50 万次——**有序性换来了约 2.6 万倍的提速**。<span class="marginnote">「$\log_2(n+1)-1$」里的 $-1$ 来自判定树「最底层不满」的修正。更本质的读法：<strong>折半查找的 ASL 就是「完全二叉树的平均深度」</strong>——查找复杂度问题的答案，藏在二叉树性质里，这是「数据结构和算法互相翻译」的绝佳例子。</span>

## 4 公式解析：查找失败的代价

查找失败时，比较会一直进行到判定树的**外部结点**（叶子的空孩子）。失败比较次数不超过树高 $h$，失败查找的 ASL 约为：

$$
ASL_{\text{失败}} \approx h = \lfloor \log_2 n \rfloor + 1
$$

**重点：失败与成功的代价同阶（都是 $O(\log n)$），但失败要多走到「树的底层」。** 判定树的外部结点数 $= n+1$（叶子 + 空孩子），这也是「$n$ 个内部结点必配 $n+1$ 个外部结点」的二叉树性质在查找里的回响。<span class="marginnote">「外部结点」是判定树分析里的隐形角色：<strong>内部结点=查找成功，外部结点=查找失败</strong>。外部结点数恒为 $n+1$——与二叉链表「$n+1$ 个空指针」是同一个定理的两副面孔。</span>

## 5 折半查找的前提与局限

**前提：表必须有序 + 必须能随机存取（数组）。**

链表不能折半：取中点要 $O(n)$ 遍历，「每次排除一半」的优势荡然无存；
频繁插入删除的表不适合：维持有序性的代价高于查找收益——这时要动态结构（二叉排序树，§9.4）；
静态表 + 有序 + 数组 = 折半查找的理想舞台。

**辨析｜易错点：折半查找 ≠ 二叉排序树上的查找。** 折半查找的判定树是**静态**的、完美平衡的；二叉排序树是**动态**的、形状由插入顺序决定（可能退化）。「静态有序用折半、动态有序用 BST」是两条不同的路。<span class="marginnote">折半查找的判定树之所以完美平衡，是因为它<strong>预知了表长 $n$、一次性把区间对半切</strong>；二叉排序树每插一个元素只影响一条链，无法保证全局平衡——这才有后面的「平衡二叉树」（§9.5）做修正。<strong>静态的确定性与动态的自由度，是查找结构的永恒对偶</strong>。</span>

## 6 小结

- 折半查找：取中点比较，每次排除一半，区间收缩一半。
- 边界纪律：闭区间配 $low \le high$、$mid\pm1$；先定区间约定再写收缩。
- 判定树：折半过程 = 近似完全二叉树，比较次数 = 结点深度。
- ASL（成功）≈ $\log_2(n+1) - 1$；失败 ≈ 树高 $\lfloor\log_2 n\rfloor + 1$。
- 前提：**有序 + 随机存取**；链表与频繁增删场景不适用。
- 静态有序用折半，动态有序用 BST（§9.4）。
