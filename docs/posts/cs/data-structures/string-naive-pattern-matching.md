## 为什么先学朴素匹配

在文本里找一个单词、在代码里找一个函数名、在基因序列里找一个片段——这些都是同一个问题：**模式匹配（pattern matching）**，即从主串 $S$ 中找出子串 $T$（模式）第一次出现的位置。最直接的解法是**朴素匹配**：把模式串从主串的每个可能起点逐一比对。它实现简单、容易证明正确，但最坏情况是 $O(nm)$。先学会朴素算法，是为了看清它的浪费在哪里——而 KMP 的每一个改进，都是在回答「如何不浪费已经比过的信息」。

## 1 朴素匹配的思想

设主串 $S$ 长度为 $n$，模式串 $T$ 长度为 $m$。朴素匹配从 $S$ 的第 1 个字符开始，把 $T$ 逐位对齐比较；若某位失配，就把 $T$ 整体右移一位，从 $S$ 的下一个字符重新对齐比较：

```c
int NaiveIndex(SString S, SString T) {
    int i = 1, j = 1;                 /* i 扫主串，j 扫模式串 */
    while (i <= S.length && j <= T.length) {
        if (S[i] == T[j]) { i++; j++; }        /* 匹配：双双前进 */
        else { i = i - j + 2; j = 1; }         /* 失配：i 回退到本趟起点 + 1，j 复位 */
    }
    if (j > T.length) return i - T.length;     /* 匹配成功，返回起始位置 */
    return 0;                                  /* 匹配失败 */
}
```

**重点：失配时的两条指针操作是朴素匹配的灵魂——$j$ 复位到 1，$i$ 回退到「本趟起点 + 1」。** 整个算法的代价来自这种「白白回退」。

**为什么「回退」是必要的（也是浪费的）**：朴素匹配不知道模式串内部的结构，失配时它唯一能确认的是「本趟起点不行」，于是只能把模式整体右移一位、重新从主串的下一个字符开始。**必要性**——它保证不跳位、不漏检；**浪费**——它把上一趟已经比对成功的 $j-1$ 个字符扔掉，下趟又从头比。**「必要但浪费」正是朴素匹配的全部矛盾**，KMP 解开这个矛盾的办法是：利用模式串的「前缀 = 后缀」结构，让 $j$ 回退到「已经比对成功的前缀」的结尾，而不必回到 1。

## 2 公式解析：为什么朴素匹配最坏是 $O(nm)$

设比较次数为 $C$。最好的情形，第一趟就匹配成功或第一趟首字符就失配：$C = O(m)$。最坏情形，每趟都在最后一位才失配（或匹配到 $S$ 末尾才失败）：

$$
C_{\max} = (n - m + 1) \cdot m = O(nm)
$$

- **第一步，读懂系数**：最多有 $n - m + 1$ 个对齐位置，每个位置最多比较 $m$ 次。
- **第二步，找一个真实的坏例子**：$S = "aaaaaaaaaaaab"$、$T = "aaab"$。每一趟都「前 $m-1$ 个字符匹配成功、最后一位失配」，于是每趟比较 4 次、还要回退——总比较次数逼近 $(n-m+1)\cdot m$。
- **第三步，看浪费在哪**：失配时 $i$ 回退、$j$ 复位，意味着**已经比过的字符会被重复比较**。上一趟确认了 $S$ 的一部分与 $T$ 的前缀相同，这趟又从头比较——信息被白白丢掉。

**用数字感受一下重复比较的规模**：取 $n = 10^6$、$m = 10^4$，最坏主串全是 `a`、模式是 `aaa…ab`。朴素匹配要比较 $(n-m+1) \times m \approx 10^{10}$ 次——百亿次字符比较，在普通机器上要跑几十秒。而 KMP 只比较 $O(n) = 10^6$ 次，毫秒级完成。**「把已比过的信息扔掉」与「把已比过的信息留住」，差的是 $10^4$ 倍的运行时间**——这就是为什么模式匹配要专门研究高效算法。<span class="marginnote">「<strong>已经知道的信息被丢弃</strong>」是朴素算法的病灶。KMP 的全部聪明之处，就是让 $j$ 回退到合适位置而不复位到 1，从而把比较过的信息保留下来——这正是下一节要展开的 $next$ 数组。</span>

## 3 朴素匹配的正确性

朴素匹配的正确性依赖一个简单的观察：**对每个对齐位置 $k$，若 $T$ 与 $S[k..k+m-1]$ 完全相等，算法必然在检查到位置 $k$ 时发现它。** 因为算法逐一尝试 $k = 1, 2, 3, \cdots$，不跳过任何位置，且每个位置上的比较穷尽了 $T$ 的全部 $m$ 个字符。不存在「漏检」的可能。

**用「不变量」把正确性说得更严格**：朴素匹配维护这样一个循环不变量——「**当前已经检查过所有起点 $< i_0$ 的对齐位置，它们都匹配失败**」，其中 $i_0$ 是当前趟的起点。每趟结束时，若失败，$i_0$ 前进 1，不变量继续成立；若成功，直接返回。归纳可证：**算法要么在某个起点找到匹配，要么检查完全部 $n-m+1$ 个起点后宣告失败**——没有第三种可能。**「逐位穷举 + 不跳位」让它永远正确，这是优化算法（KMP、BM）都必须以它为正确性基准的原因。**

**辨析｜易错点：$i$ 回退公式为什么是 $i - j + 2$。** 失配前 $j-1$ 个字符已匹配，本趟起点是 $i - (j-1)$。下一趟起点 = 本趟起点 + 1 = $i - j + 2$。

**一个常被问的变体**：如果主串和模式串的下标都从 0 开始（C 语言习惯），公式会变成 `i = i - j + 1`，`j = 0`——本质完全一样，只是下标起点整体平移了 1。**面试里「下标从 0 起还是 1 起」决定公式长什么样，但「失配回退」的语义不变**。建议写代码时固定一种约定，并先想清楚「本趟起点」的表达式，再推回退公式——直接背形如 `i - j + 2` 的公式，最容易在变体里出错。<span class="marginnote">初学者最容易在这一行出错：$i - j + 2$ 会让指针停在原地死循环，$j-1$ 会跳过一个位置。把它推一遍——失配前走了 $j-1$ 步，起点是 $i-(j-1)$，加 1 得 $i-j+2$——就能永远记住。</span>

## 4 辨析：朴素匹配在什么时候「其实不差」

$O(nm)$ 是最坏情况，但朴素匹配在真实数据上往往不差：

字符集越大、文本越随机，失配越早发生——**平均情况接近 $O(n+m)$**。
模式串越长，首字符匹配成功的概率越低，实际比较次数越少。
对 ASCII 文本找英文单词，朴素匹配通常足够快；真正需要 KMP 的场景，是**字符集极小、模式存在大量长前缀**（如 DNA 序列的 ACGT 四字符）或**重复模式**。<span class="marginnote">「最坏情况 vs 平均情况」是算法分析的经典二分。第三级《算法设计与分析》里，随机输入下的期望复杂度与最坏复杂度会分开讨论。朴素匹配恰好是「最坏吓人、平均还行」的代表。</span>

## 5 从朴素匹配到更快的算法

朴素匹配的教训是「信息被丢弃」。三种改进路线由此而来：

- **KMP**：利用模式串自身的「前缀 = 后缀」结构，让 $j$ 回退而非复位——下一篇展开。
- **Boyer-Moore**：从模式串**末尾**开始匹配，失配时按「坏字符」与「好后缀」规则大步跳过，平均更快。
- **Rabin-Karp / 字符串哈希**：把子串哈希成整数，比较哈希而非逐字符——见专题篇《字符串哈希与 Rabin-Karp》。

三者不互相排斥：KMP 保证最坏 $O(n+m)$，Boyer-Moore 平均更快，哈希法支持多模式同时匹配。**「利用已比信息」是它们共同的思想内核。**

**工程里的真实选择**：绝大多数编程语言的内置字符串查找（如 C 的 `strstr`、Java 的 `indexOf`）在短模式、常规文本上用的正是**优化的朴素匹配**（如 Two-Way 算法，结合了朴素与 KMP 思想）；只有当模式很长或字符集极小时才体现出 KMP/BM 的差距。**朴素算法不是「该被淘汰的旧物」，而是「在特定输入下已经足够好、且实现最不易错」的基准**——优化的意义不是否定它，而是知道何时不必用它。

## 6 数值算例：亲手走一遍最坏例子

用最坏例子 $S = $ `aaaaaaaab`（8 个 a 加一个 b）、$T = $ `aaab`，从头逐趟走一遍朴素匹配：

- **第 1 趟**：`aaab` 对齐 $S[1..4]$，前 3 个 a 匹配，第 4 位 `S[4]=a` vs `T[4]=b` 失配，比较 4 次；
- **第 2 趟**：对齐 $S[2..5]$，同样前 3 个 a 匹配、第 4 位失配，比较 4 次；
- **……依次到第 $n-m+1$ 趟**：主串长 $n=9$、模式长 $m=4$，共 $9-4+1=6$ 趟，每趟 4 次比较。

总比较次数 $6 \times 4 = 24$，与公式 $(n-m+1)m = 6 \times 4 = 24$ 完全吻合——**这就是最坏 $O(nm)$ 的实景**。真正可怕的不是数字本身，而是「**前 3 个字符的匹配结果每趟都被重新验证一遍**」——$S$ 的 `aaaaaaa` 那段被反复比对，信息白白丢弃。<span class="marginnote">「<strong>把坏例子亲手走一遍，比背公式有用一百倍</strong>」：<strong>你会亲眼看见 $i$ 怎么回退、$j$ 怎么复位、同一批字符怎么被反复比对</strong>——KMP 的全部动机就藏在这份「重复劳动」里。看懂了浪费，才读得懂改进。</span>

## 7 术语速查表：模式匹配关键概念

| 术语 | 含义 | 要点 |
| --- | --- | --- |
| 主串 $S$ | 被搜索的长串 | 长度 $n$ |
| 模式串 $T$ | 要寻找的子串 | 长度 $m$ |
| 对齐位置 | $T$ 与 $S$ 的可能起点 | 共 $n-m+1$ 个 |
| 朴素匹配 | 逐位对齐、失配右移一位 | 最坏 $O(nm)$ |
| 前缀 = 后缀 | KMP 利用的自相似结构 | 让 $j$ 回退而非复位 |

**三句收束**：第一，**朴素匹配的正确性来自「不跳位」**——它逐一尝试每个对齐位置，绝不漏检，这是它永远可用的底气。第二，**它的低效来自「信息被丢弃」**——$j$ 复位到 1、$i$ 回退，把上一趟已经比对的字符重新比一遍，最坏 $O(nm)$。第三，**三种改进路线（KMP 回退、Boyer-Moore 大步跳、Rabin-Karp 哈希）共同的思想内核，就是「利用已比信息」**。<span class="marginnote">「<strong>先学朴素，再谈优化</strong>」是算法学习的通用次序：<strong>朴素算法提供「正确的底线」，优化算法提供「聪明的飞跃」</strong>——没有底线，飞跃无从谈起。<strong>评价任何优化，先问它比朴素快多少、代价又是什么</strong>。</span>

## 8 小结

- 朴素匹配：把模式串从主串每个起点逐一对齐比较，正确且简单。
- 变体提醒：下标从 0 起公式变 `i-j+1`，语义不变。
- 双指针推进：匹配则 `i++`、`j++`；失配则 `i = i - j + 2`、`j = 1`。
- 最坏 $O(nm)$，坏例子是「每趟最后一位才失配」的重复字符主串。
- 浪费根源：**已比过的信息被丢弃**，$j$ 复位导致重复比较。
- 平均情况接近 $O(n+m)$，字符集大时朴素算法常够用。
- 数字对比：$n=10^6$、$m=10^4$ 最坏约 $10^{10}$ 次比较，KMP 仅 $O(n)$ 次。
- 内置 `strstr`/`indexOf` 多用优化朴素（Two-Way），朴素不是废物而是基准。
- 改进路线：KMP（$j$ 回退）、Boyer-Moore（末尾匹配大步跳）、Rabin-Karp（哈希）。
- 正确性基准：逐位穷举 + 不跳位，永远不漏检。

在下一节，我们把串的运算放进一个真实场景——**串操作应用举例（文本编辑）**，看行表结构如何支撑光标的插入、删除与查找。带着「朴素匹配=正确基准」的眼光看下去，你会更珍惜每一个高效算法背后的信息复用思想。
