## 为什么先学朴素匹配

在文本里找一个单词、在代码里找一个函数名、在基因序列里找一个片段——这些都是同一个问题：**模式匹配（pattern matching）**，即从主串 $S$ 中找出子串 $T$（模式）第一次出现的位置。最直接的解法是**朴素匹配**：把模式串从主串的每个可能起点逐一比对。它实现简单、容易证明正确，但最坏情况是 $O(nm)$。先学会朴素算法，是为了看清它的浪费在哪里——而 KMP 的每一个改进，都是在回答「如何不浪费已经比过的信息」。

## 1 朴素匹配的思想

设主串 $S$ 长度为 $n$，模式串 $T$ 长度为 $m$。朴素匹配从 $S$ 的第 1 个字符开始，把 $T$ 逐位对齐比较；若某位失配，就把 $T$ 整体右移一位，从 $S$ 的下一个字符重新对齐比较：

```c
int Index(SString S, SString T, int pos) {
    /* 返回子串 T 在主串 S 中第 pos 个字符之后第一次出现的位置 */
    int i = pos, j = 1;
    while (i <= S[0] && j <= T[0]) {      /* 双指针都未越界 */
        if (S[i] == T[j]) { i++; j++; }   /* 匹配：两指针同步前进 */
        else { i = i - j + 2; j = 1; }    /* 失配：i 回退，j 回到 1 */
    }
    if (j > T[0]) return i - T[0];        /* T 全部匹配，返回起点 */
    else return 0;                        /* 未找到 */
}
```

**重点：失配时的两条指针操作是朴素匹配的灵魂——`j` 复位到 1，`i` 回退到「本趟起点 + 1」。** 整个算法的代价来自这种「白白回退」。

## 2 公式解析：为什么朴素匹配最坏是 $O(nm)$

设比较次数为 $C$。最好的情形，第一趟就匹配成功或第一趟首字符就失配：$C = O(m)$。最坏情形，每趟都在最后一位才失配（或匹配到 $S$ 末尾才失败）：

$$
C_{\max} = (n - m + 1) \cdot m = O(nm)
$$

- **第一步，读懂系数**：最多有 $n - m + 1$ 个对齐位置，每个位置最多比较 $m$ 次。
- **第二步，找一个真实的坏例子**：$S = "aaaaaaaaaaaab"$、$T = "aaab"$。每一趟都「前 $m-1$ 个字符匹配成功、最后一位失配」，于是每趟比较 4 次、还要回退——总比较次数逼近 $(n-m+1)\cdot m$。
- **第三步，看浪费在哪**：失配时 `i` 回退、`j` 复位，意味着**已经比过的字符会被重复比较**。上一趟确认了 $S$ 的一部分与 $T$ 的前缀相同，这趟又从头比较——信息被白白丢掉。<span class="marginnote">「<strong>已经知道的信息被丢弃</strong>」是朴素算法的病灶。KMP 的全部聪明之处，就是让 `j` 回退到合适位置而不复位到 1，从而把比较过的信息保留下来——这正是下一节要展开的 $next$ 数组。</span>

## 3 朴素匹配的正确性

朴素匹配的正确性依赖一个简单的观察：**对每个对齐位置 $k$，若 $T$ 与 $S[k..k+m-1]$ 完全相等，算法必然在检查到位置 $k$ 时发现它。** 因为算法逐一尝试 $k = 1, 2, 3, \cdots$，不跳过任何位置，且每个位置上的比较穷尽了 $T$ 的全部 $m$ 个字符。不存在「漏检」的可能。

**辨析｜易错点：`i` 回退公式为什么是 `i - j + 2`。** 失配前 $j-1$ 个字符已匹配，本趟起点是 $i - (j-1)$。下一趟起点 = 本趟起点 + 1 = $i - j + 2$。<span class="marginnote">初学者最容易在这一行出错：`i - j + 1` 会让指针停在原地死循环，`i - j + 3` 会跳过一个位置。把它推一遍——失配前走了 $j-1$ 步，起点是 $i-(j-1)$，加 1 得 $i-j+2$——就能永远记住。</span>

## 4 辨析：朴素匹配在什么时候「其实不差」

$O(nm)$ 是最坏情况，但朴素匹配在真实数据上往往不差：

- 字符集越大、文本越随机，失配越早发生——**平均情况接近 $O(n+m)$**。
- 模式串越长，首字符匹配成功的概率越低，实际比较次数越少。
- 对 ASCII 文本找英文单词，朴素匹配通常足够快；真正需要 KMP 的场景，是**字符集极小、模式存在大量长前缀**（如 DNA 序列的 `ACGT` 四字符）或**重复模式**。<span class="marginnote">「最坏情况 vs 平均情况」是算法分析的经典二分。第三级《算法设计与分析》里，随机输入下的期望复杂度与最坏复杂度会分开讨论。朴素匹配恰好是「最坏吓人、平均还行」的代表。</span>

## 5 从朴素匹配到更快的算法

朴素匹配的教训是「信息被丢弃」。三种改进路线由此而来：

- **KMP**：利用模式串自身的「前缀 = 后缀」结构，让 `j` 回退而非复位——下一篇展开。
- **Boyer-Moore**：从模式串**末尾**开始匹配，失配时按「坏字符」与「好后缀」规则大步跳过，平均更快。
- **Rabin-Karp / 字符串哈希**：把子串哈希成整数，比较哈希而非逐字符——见专题篇《字符串哈希与 Rabin-Karp》。

三者不互相排斥：KMP 保证最坏 $O(n+m)$，Boyer-Moore 平均更快，哈希法支持多模式同时匹配。**「利用已比信息」是它们共同的思想内核。**

## 6 小结

- 朴素匹配：把模式串从主串每个起点逐一对齐比较，正确且简单。
- 双指针推进：匹配则 `i++、j++`；失配则 `i = i-j+2`、`j = 1`。
- 最坏 $O(nm)$，坏例子是「每趟最后一位才失配」的重复字符主串。
- 浪费根源：**已比过的信息被丢弃**，`j` 复位导致重复比较。
- 平均情况接近 $O(n+m)$，字符集大时朴素算法常够用。
- 改进路线：KMP（$j$ 回退）、Boyer-Moore（末尾匹配大步跳）、Rabin-Karp（哈希）。
