## 为什么表达式求值需要栈

计算机执行 `1 + 2 * 3` 时，必须回答一个问题：先算加法还是先算乘法？我们靠「运算符优先级」和「括号」确定顺序，但一台顺序执行的机器，如何把这种「越界的规则」翻译成线性的一步步操作？答案是**栈**。表达式求值是栈最经典的应用：一个栈存操作数，一个栈存运算符，按优先级规则协同工作，就能把中缀表达式算出来。理解它的关键是**算符优先关系表**——把「优先级与结合性」翻译成机器可查的表。

## 1 三种表达式记号

把运算符放在操作数之间的叫**中缀（infix）**，如 $a + b$。还有两种更「机器友好」的记法：

- **后缀（postfix）**，也叫逆波兰式（RPN）：$a\ b\ +$，运算符跟在两个操作数之后；
- **前缀（prefix）**：$+ \ a\ b$，运算符在两个操作数之前。

**重点：后缀表达式不需要括号，也不需要优先级——从左到右扫一遍，遇操作数压栈、遇运算符取两个操作数算完压回，结果唯一确定。** 中缀的 `1 + 2 * 3` 写成后缀是 `1 2 3 * +`，而 `(1 + 2) * 3` 写成后缀是 `1 2 + 3 *`——同一个中缀串的两种加括号方式，对应两个完全不同的后缀串。<span class="marginnote">后缀表达式为什么天然免括号？因为「先算谁」的信息被编码进了<strong>顺序</strong>里：运算符出现得越晚，优先级越高。机器只认顺序，不认嵌套——这正是后缀记号存在的全部理由。</span>

## 2 后缀表达式的求值

后缀表达式求值只需要**一个操作数栈**：

```c
/* 输入：后缀表达式 3 4 2 * + */
double evalPostfix(char *s) {
    Stack st;                    /* 操作数栈 */
    while (扫描 s) {
        if (是操作数) push(st, 值);            /* 数字压栈 */
        else {                                 /* 运算符 */
            b = pop(st);  a = pop(st);         /* 注意：先弹出的是右操作数 */
            push(st, apply(a, 运算符, b));
        }
    }
    return pop(st);              /* 栈底（顶）即结果 */
}
```

**辨析｜易错点：弹出顺序与操作数顺序相反。** 减法与除法不满足交换律，`a - b` 不能写成 `b - a`。由于栈是 LIFO，先弹出的 `b` 是后压入的右操作数，后弹出的 `a` 才是左操作数——`a op b` 的顺序必须保持。这是后缀求值里最容易踩的坑，也是面试高频考点。

## 3 公式解析：中缀转后缀的算符优先法

中缀表达式求值有两种路线：先转后缀再求值，或用「算符优先法」两栈直接算。严蔚敏教材用后者：一个**运算符栈** + 一个**操作数栈**，核心是一张**算符优先关系表**。

设 $op_1$ 是栈顶运算符，$op_2$ 是当前读到的运算符，比较关系只有三种：

$$
\begin{aligned}
op_1 < op_2 &\Rightarrow op_2\ \text{压栈（栈顶优先级低，先处理新的）} \\
op_1 = op_2 &\Rightarrow \text{配对：弹出栈顶（括号消解）或同优先级弹出} \\
op_1 > op_2 &\Rightarrow \text{弹出并执行 } op_1\ \text{（栈顶优先级高，先算它）}
\end{aligned}
$$

- **第一步，读懂「<」**：如 `1 + 2 * 3`，读到 `*` 时栈顶是 `+`，因 `+ < *`，`*` 压栈。于是 `*` 先被弹出执行——这正实现了「乘法先于加法」。
- **第二步，读懂「>」**：`1 * 2 + 3`，读到 `+` 时栈顶是 `*`，因 `* > +`，先弹出 `*` 算出 `1*2`，再压入 `+`。优先级高的先算，靠「>」触发。
- **第三步，读懂「=」**：遇到右括号 `)` 时与栈内 `(` 配对，弹出 `(` 消解括号；同级运算符（如两个 `+`）也可用 `=` 表示「先算栈顶、新者再入」——这就实现了左结合。<span class="marginnote">算符优先表是「<strong>把规则变成数据</strong>」的典范：优先级和结合性不再是散落在代码里的 if-else，而是一张可以在程序外维护的二维表。规则变更只改表，不改代码。</span>

## 4 算法主流程：两栈协同

中缀求值的主循环：

```c
while (读入符号 c) {
    if (c 是操作数) push(OPND, c);
    else switch (precede(栈顶运算符, c)) {
        case '<':  push(OPTR, c); break;               /* 新运算符压栈 */
        case '=':  pop(OPTR); break;                   /* 括号配对，弹出左括号 */
        case '>':  op = pop(OPTR);
                   b = pop(OPND); a = pop(OPND);
                   push(OPND, calculate(a, op, b));    /* 先算栈顶 */
                   /* 不读下一字符，重新比较新的栈顶 */
    }
}
```

每一步都遵守一条不变量：**运算符栈里的运算符，优先级从栈底到栈顶严格递增**。这条不变量一旦被破坏（栈顶比新运算符优先级低），就要先执行栈顶，把栈恢复成递增序——这正是「>」分支的职责。

## 5 边界与细节：负号、括号、除零

真实求值还要处理几处细节：

- **一元负号**：`-3 + 2` 里的 `-` 是一元运算符。常见做法是预处理：把「跟在运算符或左括号后面的 `-`」视为取负号并入操作数，或定义一元的优先级。
- **括号必须配对**：`(` 压栈后遇到 `)` 才配对弹出；若扫描完栈内还残留 `(`，说明括号不匹配。
- **除零与类型**：`a / 0` 在算符优先法里是运行时错误，需在 `calculate` 里显式检查；浮点参与时还需考虑精度。<span class="marginnote">表达式求值是「<strong>编译器词法 + 语法分析</strong>」的迷你版：运算符栈对应符号表，优先关系表对应语法优先级。到第三级《编译原理》学表达式文法（EBNF）与递归下降分析时，你会再次遇到「如何确定先算谁」这个老问题。</span>

## 6 小结

- 中缀、后缀、前缀三种记号；**后缀不需要括号与优先级**，机器可线性求值。
- 后缀求值：**一个操作数栈**；弹出顺序与操作数相反，`a-b` 不可写成 `b-a`。
- 中缀求值：**算符优先法**，运算符栈 + 操作数栈，核心是优先关系表。
- 优先关系三态：`<` 新运算符压栈、`>` 先执行栈顶、`=` 括号配对或同级左结合。
- 不变量：**运算符栈优先级栈底到栈顶严格递增**。
- 边界细节：一元负号、括号配对、除零检查。

在下一节，我们从「后进先出」换到「先进先出」——**队列的顺序表示与循环队列**，并解决顺序队列「假溢出」这个经典工程问题。
