## 为什么 Dinic 是「竞赛标配」

Edmonds-Karp 每次找一条增广路，$O(VE^2)$——还是有点慢。**Dinic 算法**大幅加速：它用 **BFS 分层图**（每个顶点标记到源点的距离层），再在分层图上 **DFS 一次推尽可能多的流（多路增广）**。因为分层图保证「增广路都按层前进、最短」，且一次 DFS 能同时推多条路——**Dinic 的复杂度 $O(V^2E)$，对单位容量图（如二分图匹配）甚至 $O(E\sqrt{V})$**。它是竞赛里最大流的默认算法，也是理解「分层 + 多路」两个加速思想的范例。

## 1 Dinic 的两阶段

**阶段一（BFS 分层）**：从源点 BFS，给每个顶点标 **level（层号）** = 到源点的最短边数。只保留「从层 $k$ 到层 $k+1$」的边（即 level 递增的边）——这些边构成**分层图**。

**阶段二（DFS 多路增广）**：在分层图上，从源点出发 DFS 到汇点，**一次 DFS 沿途推流、且回溯时继续尝试其他分支**（多路增广），直到当前分层图没有从源到汇的路，回到阶段一。

```cpp
int Dinic(int s, int t) {
    int flow = 0;
    while (BFS(s, t)) {                       /* 阶段一：BFS 分层，无增广路则结束 */
        for (int i = 1; i <= n; i++) cur[i] = head[i];   /* 当前弧初始化 */
        while (int f = DFS(s, t, INF))        /* 阶段二：DFS 多路增广 */
            flow += f;
    }
    return flow;
}
```

**重点：BFS 分层保证「每次增广都走最短路径」，DFS 多路增广把「一条条推」变成「一趟推完当前层的所有可能」。** 两个加速合起来，让增广轮数从 $O(VE)$ 降到 $O(V)$。<span class="marginnote">「<strong>BFS 管层、DFS 管量</strong>」：<strong>BFS 把图按距离分层，DFS 在层间一口气推多条路</strong>——<strong>「每轮推进一层」+「每层推进多路」= 轮数 $O(V)$</strong>。<strong>「分层」与「多路」是 Dinic 的两板斧</strong>。</span>

## 2 公式解析：Dinic 的复杂度

$$
\begin{aligned}
T_{\text{Dinic 一般图}} &= O(V^2 E) \\
T_{\text{Dinic 单位容量图}} &= O(E \sqrt{V}) \quad \text{（每条边容量 1，如二分图匹配）}
\end{aligned}
$$

- **第一步，读「轮数 $O(V)$」**：每轮 BFS 分层后，最短增广路长度至少 +1——最多 $O(V)$ 轮。
- **第二步，读「每轮 $O(VE)$」**：每轮 DFS 多路增广，总代价 $O(VE)$。
- **第三步，读「单位容量的加速」**：容量全为 1 时，每轮推进的「层数」与「流量」有更强上界——$O(E\sqrt{V})$，二分图匹配用它尤其快。<span class="marginnote">「<strong>分层让轮数有界，多路让每轮高效</strong>」：<strong>最短增广路长度单调递增 → 轮数 ≤ $V$</strong>；<strong>DFS 多路增广一次扫完当前层的所有路 → 每轮 $O(VE)$</strong>。<strong>「单位容量图 $O(E\sqrt{V})$」是 Dinic 送给二分图匹配的礼物</strong>。</span>

## 3 当前弧优化

**当前弧优化（current arc）**：每个顶点记录「上次 DFS 推进到哪条出边」，下次从那里继续——**已试过且满载的边不再重试**。

```cpp
int DFS(int u, int t, int f) {                       /* 多路增广 + 当前弧优化 */
    if (u == t) return f;
    for (int &i = cur[u]; i != -1; i = nxt[i]) {     /* cur[u] 记录推进到的出边 */
        int v = to[i], w = cap[i];
        if (level[v] == level[u] + 1 && w > 0) {
            int d = DFS(v, t, min(f, w));
            if (d > 0) { cap[i] -= d; cap[i ^ 1] += d; return d; }
        }
    }
    return 0;
}
```

**重点：当前弧优化把「每轮 DFS 的重复尝试」省掉**——满载的边、层级不对的边只试一次。它是 Dinic 工程实现的标配，没有它 Dinic 会慢不少。<span class="marginnote">「<strong>满载的边，一次试过就不再试</strong>」：<strong>当前弧指针记住「哪条出边还没试过」，DFS 从那里继续</strong>——<strong>把「反复碰壁」变成「一次定位」</strong>。<strong>这是 Dinic 里最「划算」的优化：几行代码，常数大降</strong>。</span>

## 4 最小割：最大流的镜像问题

**最小割（min-cut）**：把顶点分成「含源点的集合 $S$」与「含汇点的集合 $T$」，割的容量 = 从 $S$ 到 $T$ 的边的容量和。**最小割 = 最大流**（上节定理）。

**求最小割方案**：跑完 Dinic 后，从源点在残余网络中做 BFS，能到达的顶点属于 $S$，其余属于 $T$——**$S$ 到 $T$ 的「满载边」就是最小割的边**。

**重点：Dinic 跑完顺带得到最小割——「跑一遍流，答案和割一起出来」。** 这让网络流能解「最便宜切断」类问题：哪些边要删、哪些点要分到哪边。<span class="marginnote">「<strong>最大流跑完，最小割就在残余图里</strong>」：<strong>源点 BFS 能到的 = $S$ 侧，到不了的 = $T$ 侧</strong>——<strong>跨越两组的满载边即最小割</strong>。<strong>「求流」与「求割」一次完成</strong>——这是网络流最实用的「买一送一」。</span>

## 5 最小割的建模应用

**图像分割**：像素连前景/背景，边容量 = 分割代价——最小割 = 最优分割；
**项目选择**：收益与依赖约束 → 最小割 = 最大收益方案；
**二分图匹配**：单位容量流 = 最大匹配，顺带得最小点覆盖；
**密铺 / 约束满足**：割模型统一解决。

**重点：最小割是「二分类」问题的万能模型**——把「每个元素分到哪边、以及分隔的代价」建成割，最小割即最优方案。图像分割、项目决策、社区划分全在这个框架里。<span class="marginnote">「<strong>最小割 = 最优二分类</strong>」：<strong>每个顶点选边（$S$ 或 $T$），边容量是「分错的代价」，最小割即最省钱的分法</strong>。<strong>图像分割、市场划分、社交分群</strong>——<strong>「把数据分成两类且代价最小」的问题，都是最小割的建模</strong>。</span>

## 6 小结

- Dinic：BFS 分层 + DFS 多路增广，反复直到无增广路。
- 复杂度：一般图 $O(V^2E)$，单位容量图 $O(E\sqrt{V})$。
- 当前弧优化：跳过满载/层级不对的边，每轮 DFS 只试一次。
- 最小割 = 最大流；Dinic 跑完，残余图上 BFS 即得割方案。
- 最小割建模：把「二分类代价」建成割——图像分割、项目选择。
- Dinic 是竞赛最大流默认算法，也是「分层 + 多路」思想的代表。
