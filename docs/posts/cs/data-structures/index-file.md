## 为什么「数据乱、索引齐」能加快查找

顺序文件的毛病是「记录必须有序才快，而维持有序要重写」。**索引文件（indexed file）**把两个约束解开：**记录数据可以无序存放（甚至堆叠在物理块里），另建一张「索引表」——按关键字有序地记录「关键字 → 物理地址」**。查找时先在**有序的索引表**上折半定位（快），再按地址取记录（一次 I/O）。数据不用动，索引维护即可。这就像字典的「部首表」：正文可以乱序，查字先查表。索引文件是数据库索引、文件系统 inode 的直接祖先——「索引 + 数据分离」从此成为存储系统的标准架构。

## 1 索引文件的结构

- **数据区（主文件）**：记录可以按任意顺序（或按插入顺序）存放；
- **索引区（索引表）**：若干索引项（关键字，地址），**按关键字有序**。

```c
/* 数据区中的记录 */
typedef struct {
    KeyType key;         /* 关键字 */
    InfoType info;       /* 记录的其它字段 */
} Record;

/* 索引项：关键字 → 物理地址 */
typedef struct {
    KeyType key;         /* 关键字 */
    long addr;           /* 记录在数据区中的物理地址（块号 + 位移） */
} IndexItem;

IndexItem index[MAXSIZE];   /* 索引表：按关键字有序 */
```

查找：在索引表上折半（索引表有序）找到关键字，得到地址，一次 I/O 读记录。<span class="marginnote">「<strong>索引 = 关键字的有序投影</strong>」是索引文件的核心抽象：<strong>索引表只存「键 + 地址」，体积远小于数据区</strong>，所以能整体放内存或少量块——折半在索引上进行，数据只需一次随机读。<strong>「把查找集中在小表上」</strong>是索引的全部秘密。</span>

## 2 索引文件 vs 分块查找

索引文件与《索引顺序表（分块查找）》是近亲，但有一处关键差异：

**分块查找**：数据区块间有序，索引项记「每块的最大关键字 + 块地址」——块内还要顺序找；
**索引文件**：数据区**无序**，索引项记「每条记录的关键字 + 地址」——查到即定位，块内无需再找。

**重点：索引文件用「更细的索引」换「定位一步到位」**——代价是索引表更大（每条记录一项），收益是查找只需「索引折半 + 一次 I/O」。<span class="marginnote">「块级索引 vs 记录级索引」是索引粒度的分水岭：<strong>块级索引省空间但块内要扫，记录级索引一步到位但表大</strong>。数据库里两者都有——<strong>主索引常记录级（B+树叶子挂记录），辅助索引也记录级</strong>；而「多级索引」（ISAM，下节）则用「索引的索引」解决索引表太大的问题。</span>

## 3 公式解析：索引文件的查找代价

设 $n$ 条记录、索引表 $m$ 项（$m = n$ 记录级），索引表能整体放入内存：

$$
T_{\text{查找}} = \underbrace{O(\log m)}_{\text{索引折半（内存）}} + \underbrace{O(1)}_{\text{一次磁盘 I/O 取记录}}
$$

- **第一步，读「索引在内存」**：索引表小，可装入内存，折半查找是内存速度——$O(\log n)$ 次比较，毫秒级以下。
- **第二步，读「数据一次 I/O」**：找到地址后，一次磁盘读取出记录——这是唯一的磁盘代价。
- **第三步，读「折半 + 一次 I/O」的组合**：总代价 ≈ 一次磁盘访问 + 极快的内存折半——**比顺序文件的 $O(\log n)$ 次磁盘访问快了一个量级**。<span class="marginnote">「把磁盘访问压到 1 次」是索引设计的北极星：<strong>内存折半再快也不值钱，磁盘 I/O 一次都贵</strong>。索引文件做到了「1 次 I/O 完成查找」——这正是它比顺序文件（$\log n$ 次 I/O）快的本质：<strong>把「多次磁盘」换成「内存折半 + 1 次磁盘」</strong>。</span>

## 4 索引文件的更新

**插入**：数据区直接追加记录（数据无序，插哪都行）；索引表插入一项（保持有序，可批量重排）；
**删除**：数据区标记删除；索引表删除项；
**修改**：关键字不变，改数据；关键字变，删旧插新。

**辨析｜易错点：索引文件的插入「数据快、索引慢」。** 数据区插入是 $O(1)$（追加），但索引表是**有序表**，插入要 $O(m)$ 移位——**瓶颈从数据区转移到了索引区**。工程解法：索引表也留空位/用树（B 树索引），或「定期重建索引」。<span class="marginnote">「<strong>数据乱、索引齐，瓶颈在索引</strong>」是索引文件的平衡点：<strong>数据操作省了，索引操作贵了</strong>。要根治索引的插入慢，就得让索引本身也「动态平衡」——这正是 B+树索引（专题篇）登场的原因：<strong>B+树让索引的插入删除也是 $O(\log n)$，而不用整表移位</strong>。</span>

## 5 从索引文件到现代索引

索引文件是「索引体系」的第一课，它的思想层层升级：

1. **单级索引**：索引表可能太大放不进内存；
2. **多级索引**：给索引表再建索引（索引的索引）——ISAM 文件（下节）；
3. **树形索引**：用 B 树/B+树做索引——动态平衡、天然多级——数据库的最终形态。

**重点：索引文件的「索引 = 键的有序表」思想，一路演化成 B+树**——区别只在「索引用什么结构存」。数据与索引分离、查找集中在索引上，这两个原则从头到尾没变。<span class="marginnote">「<strong>数据与索引分离</strong>」是现代存储的第一原则：<strong>数据库的表（堆文件）+ 索引（B+树）、文件系统的数据 + inode、搜索引擎的文档 + 倒排</strong>，全是「数据 + 元数据」的分离。<strong>索引文件是这条演化链的第一环</strong>。</span>

## 6 小结

- 索引文件：数据区无序 + 索引表（键→地址）按关键字有序。
- 查找：索引折半（内存）+ 一次 I/O 取记录——磁盘访问压到 1 次。
- 与分块查找差异：记录级索引，定位一步到位。
- 插入数据 $O(1)$、索引 $O(m)$——瓶颈在索引表移位。
- 升级路线：单级 → 多级（ISAM）→ B 树/B+树索引。
- 「数据与索引分离、查找集中在索引」是现代存储的第一原则。
