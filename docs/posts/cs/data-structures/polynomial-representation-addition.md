## 为什么从一元多项式开始

线性表前几节分别用顺序存储与链式存储实现了「表」本身。但表终究只是容器，本节要让容器真正干活：用它装下一个**一元多项式**，并完成两个多项式的**相加**。为什么偏偏选多项式？因为它是一类**「稀疏」却有规律**的数据——次数可能很高，非零项却很少。用数组硬扛，浪费惊人；用线性表按「指数升序」只存非零项，多项式就变成一个有序表，而**有序表的归并**正是后面归并排序、多路归并的雏形。本节是「用数据结构解决具体数学问题」的第一次完整示范，也第一次尝到「表示方式决定算法代价」的甜头。

## 1 多项式与线性表的对应

一元多项式是形如 $P_n(x) = p_n x^n + p_{n-1} x^{n-1} + \cdots + p_1 x + p_0$ 的式子。最直觉的存法是**稠密表示**：用数组 $p[0..n]$，按下标存系数，第 $i$ 项就是 $p[i]\,x^i$。

但现实中的多项式常常稀疏：$P(x) = 3x^{100} + 2$。用稠密数组存，要开 101 个格子，其中 99 个是 0。于是改用**按指数升序排列的（系数, 指数）序偶表**：

$$
P(x) = \sum_{i=0}^{m} p_i x^{e_i}, \qquad e_0 < e_1 < \cdots < e_m
$$

表里每个元素是一个序偶 $(p_i, e_i)$，指数严格递增。这样 $3x^{100} + 2$ 只需两个元素，存储量从 101 降到 2。<span class="marginnote">这是「<strong>数据组织方式决定存储成本</strong>」的第一次尝鲜：同一份数学对象，稠密与稀疏两种表示，空间开销可以差几十倍。第五篇《稀疏矩阵的压缩存储》会是同一主题的第二次登场。</span>

## 2 链式表示的结点设计

用线性链表表示多项式时，每个结点包含三个域：**系数域（coef）**、**指数域（expn）**、**指针域（link）**。

```c
typedef struct PolyNode {    /* 多项式链表结点 */
    float coef;              /* 系数域 */
    int   expn;              /* 指数域 */
    struct PolyNode *link;   /* 指针域 */
} PolyNode, *Polynomial;
```

指数按升序排好，链表就有了「有序表」的全部性质。这个有序性不是白给的——它让下面的加法变成一趟线性归并。注意，这里用的是「带头结点」的链表还是「不带头结点」的链表都可行，关键在于**首元结点必须是指数最小的一项**，这样归并从表头出发才有意义。

## 3 公式解析：多项式相加即有序表归并

两个多项式相加，本质是「指数相同的项系数相加，其余项原样保留」。用线性表语言说：**两个按指数升序排列的表，合成一个新表，新表仍按指数升序**。设 $A$、$B$ 是两个指针，分别扫过两个多项式，比较所指项的指数，只有三种情形：

$$
\begin{aligned}
e_A = e_B &\Rightarrow \text{系数相加后插入结果表} \\
e_A < e_B &\Rightarrow \text{$A$ 的当前项整个移入结果表} \\
e_A > e_B &\Rightarrow \text{$B$ 的当前项整个移入结果表}
\end{aligned}
$$

- **第一步，读懂三种情形**：指数相等才需要「真正的加法」；指数不等时，较小的那项直接落位，因为它不可能再遇到同指数的项了——这是归并正确性的核心。
- **第二步，体会「移动 vs 复制」**：链式表示下，把一项移入结果表只需改指针（常数时间）；若用顺序表，则要复制整个数组，代价 $O(n)$。这正是本节标题「表示及相加」里，表示方式先于相加算法的原因。
- **第三步，读复杂度**：两个表各扫一遍，时间 $O(m+n)$，其中 $m,n$ 是两多项式的非零项个数，与最高次数无关。**稀疏表示把多项式运算的代价绑定在非零项数目上**，这是它最大的价值。

## 4 算法主流程：一趟归并

加法算法的骨架是「三个指针、一趟扫描」：

```c
Polynomial AddPolyn(Polynomial A, Polynomial B) {
    Polynomial C = NULL, *tail = &C;     /* 结果表，尾指针插入 */
    while (A && B) {
        if (A->expn == B->expn) {              /* 指数相等：系数相加 */
            float s = A->coef + B->coef;
            if (s != 0) attach(tail, s, A->expn);  /* 和为零则丢弃 */
            A = A->link; B = B->link;
        } else if (A->expn < B->expn) {        /* A 指数小：A 当前项落位 */
            attach(tail, A->coef, A->expn); A = A->link;
        } else {                               /* B 指数小：B 当前项落位 */
            attach(tail, B->coef, B->expn); B = B->link;
        }
    }
    while (A) { attach(tail, A->coef, A->expn); A = A->link; }  /* 收尾 */
    while (B) { attach(tail, B->coef, B->expn); B = B->link; }
    return C;
}
```

这个流程有两个细节值得指出：

- **系数和为零的项被丢弃**：数学上 $p_i x^{e_i} + (-p_i)x^{e_i} = 0$，若不丢弃，表里会出现「系数为 0」的幽灵结点，破坏稀疏表示的前提。
- **每轮只推进一个（或两个）指针**：每个结点至多被处理一次，这是 $O(m+n)$ 的来源。

## 5 辨析｜易错点：指数升序为什么不能乱

最常犯的错误，是把多项式随意存成不排序的表。一旦指数无序，上述归并就失效——你无法确定「当前指数是否还会出现同指数的项」，只能对每个项做全表扫描，复杂度退化到 $O(mn)$。

- **有序性是稀疏表示的生命线**：它把「多项式相加」从两两比较的 $O(mn)$ 降到一趟归并的 $O(m+n)$。
- **归并是信息不丢失的压缩**：两个有序表做一趟归并就能得到有序结果，这正是《内部排序·归并排序》与《外部排序·多路归并》里反复出现的核心模式。<span class="marginnote">把「相加」看成「归并」的实例，是本节最重要的认知升级。到第十篇学归并排序、第十一篇学多路平衡归并时，你会看到一模一样的指针推进骨架。</span>

## 6 从多项式到更广的抽象

多项式的链表表示还能往两个方向推广。一是**稀疏矩阵**：把「两个指数维」展开，每个非零元用（行, 列, 值）三元组表示，矩阵加法就成了对两组三元组的归并——这直接通向第五篇《数组和广义表》。二是**广义表**：当多项式有多个变量（如 $x^2y + xy^2$）时，可把 $y$ 看成「系数里的变量」，得到「多项式中的多项式」，这正是广义表与 $m$ 元多项式递归表示的入口。

**辨析｜易错点：系数和为零必须丢弃该项。** 加法中 $p_i x^{e_i} + (-p_i)x^{e_i} = 0$，若不丢弃，结果表里会出现系数 0 的「幽灵项」——它既破坏稀疏表示（只存非零项的承诺），又可能在后续运算里制造麻烦（0 项参与归并）。代码里用 `if (s != 0)` 判定后插入，正是这个数学事实的工程化。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 序偶（coef, expn） | 系数 + 指数 |
| 稠密 / 稀疏表示 | 数组全存 / 链表只存非零项 |
| 有序表归并 | 三个指针一趟扫描 |
| 幽灵项 | 系数为 0 的项（应丢弃） |
| 尾指针插入 | attach(tail, ...) 常数时间 |

## 7 小结

- 一元多项式用**按指数升序排列的（系数, 指数）序偶链表**表示，存储量正比于非零项个数。
- 多项式相加 = **有序表归并**：一趟扫描，时间 $O(m+n)$。
- 三种情形：指数相等则系数相加（和为零则丢弃），否则较小指数项直接落位。
- 有序性不可乱：失去有序，归并退化为 $O(mn)$ 的两两比较。
- 多项式的链表表示是**稀疏矩阵、广义表**的共同原型。
