## 为什么需要十字链表

三元组顺序表把稀疏矩阵压成了一张有序表，但它的短板在「按列访问」：要找到第 $j$ 列的所有非零元，只能整表扫描。而矩阵加法、乘法、转置都需要频繁按列操作。**十字链表（orthogonal linked list）**给每个非零元装上**两个方向的指针**——向右指向同行下一个非零元，向下指向同列下一个非零元。行与列两套链表十字交叉，按行访问、按列访问都变成从链头出发的线性扫描。它还天然支持**动态插入删除非零元**——矩阵的稀疏模式变化时，无需整体搬家。这正是它在稀疏矩阵运算库（如 MATLAB 的稀疏格式雏形）里受青睐的原因。

## 1 十字链表的结点结构

每个非零元结点包含五个域：

```c
// 十字链表的结点结构：行列坐标 + 值 + 行指针 + 列指针
typedef struct OLNode {
    int row, col;                // 非零元的行号、列号
    ElemType value;              // 非零元的值
    struct OLNode *right;        // 指向同行下一个非零元
    struct OLNode *down;         // 指向同列下一个非零元
} OLNode, *OLink;
```

所有非零元结点被组织成两组链表：**每一行一条链表**（靠 `right` 穿起来，行内按列号递增），**每一列一条链表**（靠 `down` 穿起来，列内按行号递增）。每个结点同时挂在「所在行链」与「所在列链」上——这就是「十字」的含义。

<span class="marginnote">与三元组顺序表对比：三元组表是「<strong>一份数据、两种视角靠扫描</strong>」，十字链表是「<strong>一份数据、两种视角各一条链</strong>」。用「冗余的指针」换「双向的访问」，是链式结构一贯的交易。</span>

## 2 行头结点与列头结点

行链与列链各需要一个头：通常用**一个头结点数组** `rhead` 与 `chead` 分别指向每一行的首非零元与每一列的首非零元：

```c
// 十字链表的头结构：行头数组 + 列头数组 + 规模信息
typedef struct {
    OLink rhead[MAX_ROW];        // 行头指针数组：rhead[i] 指向第 i 行第一个非零元
    OLink chead[MAX_COL];        // 列头指针数组：chead[j] 指向第 j 列第一个非零元
    int m, n, t;                 // 行数、列数、非零元个数
} CrossList;
```

**重点：空行的链表头指针为 `NULL`，空列同理。** 插入一个新非零元时，先按行号找它在行链中的位置（行内按列号递增），再按列号找它在列链中的位置（列内按行号递增），两个方向分别插入——插入本身是 $O(\text{行链长度} + \text{列链长度})$。

## 3 插入非零元的算法

插入 $A[i][j] = e$（$e \neq 0$）的基本步骤：

```c
// 插入非零元 A[i][j] = e：同时维护行链与列链，保持「行列一致」
void Insert(CrossList *M, int i, int j, ElemType e) {
    OLNode *p = newOLNode(i, j, e);
    // 行链插入：行内按列号递增，先找插入位置
    OLink *q = &M->rhead[i];
    while (*q && (*q)->col < j) q = &(*q)->right;
    p->right = *q;
    *q = p;                                    // 挂入行链
    // 列链插入：列内按行号递增，先找插入位置
    q = &M->chead[j];
    while (*q && (*q)->row < i) q = &(*q)->down;
    p->down = *q;
    *q = p;                                    // 挂入列链
}
```

**辨析｜易错点：插入要同时维护两条链，漏掉任何一条都会让矩阵「行列不一致」。** 行链插入成功而列链未插入，按列扫描时就找不到该元素——矩阵的两种视角分裂了。<span class="marginnote">十字链表的「<strong>双链一致性</strong>」是它的复杂度来源：任何修改都必须同时反映到行链与列链。这与数据库里「冗余索引的一致性」、双向链表的「前后指针必须同步」是同一类纪律——<strong>每多一个视角，就多一份必须同步的约束</strong>。</span>

## 4 公式解析：十字链表 vs 三元组表的代价

两种稀疏矩阵表示的取舍，用公式化的对比看清：

$$
\begin{aligned}
T_{\text{按行访问}} &: \ \text{三元组表 } O(1)\ \text{起点} \to O(tu) \ \text{全表扫描}, \quad \text{十字链表 } O(1)\ \text{行头} \to O(\text{该行非零元数}) \\
T_{\text{按列访问}} &: \ \text{三元组表 } O(tu) \ \text{（无列索引）}, \quad \text{十字链表 } O(1)\ \text{列头} \to O(\text{该列非零元数}) \\
T_{\text{插入删除}} &: \ \text{三元组表 } O(tu) \ \text{（顺序表整体搬移）}, \quad \text{十字链表 } O(\text{行链长} + \text{列链长})
\end{aligned}
$$

- **第一步，读按列访问**：三元组表没有列索引，找第 $j$ 列只能全表扫 $O(tu)$；十字链表有 `chead`（列头指针），直接进列链。
- **第二步，读插入删除**：三元组表是顺序表，中间插入要把后续元素整体后移 $O(tu)$；十字链表改指针即可。
- **第三步，读空间代价**：十字链表每个结点多两个指针域（`right`、`down`），还有行头、列头数组——空间开销明显高于三元组表。**空间换时间、换灵活性，是十字链表的基本账。**<span class="marginnote">选型规律：矩阵规模固定、运算以「整体变换」（如转置、两趟法）为主 → 三元组表；矩阵需要<strong>动态增删非零元</strong>、运算需频繁按列访问 → 十字链表。这也是「静态 vs 动态」之选在矩阵上的投影。</span>

## 5 从十字链表到稀疏矩阵运算

十字链表最著名的应用是**稀疏矩阵乘法**的经典实现：$C = A \times B$。实现时，把 $B$ 的每一行也组织成链表，对 $A$ 的每个非零元，沿 $B$ 的对应行做累加——十字链表的「行链」让每个非零元都能快速找到 $B$ 中与之相乘的一整行。<span class="marginnote">稀疏矩阵乘法是「<strong>数据结构的选型决定算法复杂度</strong>」的教科书案例：同样的数学定义，在十字链表下能组织成 $O(\text{涉及的非零元对})$ 的实现，三元组表下则频繁整表扫描。结构的自由度，就是算法的可能性。</span>

**辨析｜易错点：十字链表的「按行扫描」不等于「遍历矩阵」。** 从 `rhead[0]` 沿 `right` 走只扫第 0 行的非零元；要遍历整个矩阵，得对每一行各走一遍行链（或每一列各走一遍列链）。**两种遍历视角各有各的链**——这正是十字链表「十字」的代价：同一份数据，两套链都要维护。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 十字链表 | 行链 + 列链交叉的非零元表示 |
| right / down | 同行下一个 / 同列下一个 |
| rhead / chead | 行头 / 列头指针数组 |
| 双链一致性 | 修改必须同时反映到行链与列链 |
| 三元组表 | 静态有序表（无列索引） |

**辨析｜易错点：十字链表的插入「同时维护行链与列链」，顺序无妨但都不能漏。** 先插行链再插列链（或反之）都行，漏任何一条都会让矩阵「行列分裂」——按行能找到、按列找不到。双链一致性是正确性的底线。

**一句话**：十字链表用「每结点两个方向指针」，让按行、按列访问都从链头 $O(1)$ 起步。

## 6 小结

- 十字链表：每个非零元带 `right`（同行下一个）与 `down`（同列下一个），行链 + 列链十字交叉。
- 行内按列号递增，列内按行号递增；`rhead`、`chead` 作各链头。
- 插入须**同时维护行链与列链**，漏维护即「行列分裂」。
- 按列访问与动态插入删除，十字链表远优于三元组表；代价是双指针域空间。
- 静态整体变换用三元组表，动态增删、频繁按列访问用十字链表。
- 稀疏矩阵乘法是十字链表「行链加速」的经典应用。
