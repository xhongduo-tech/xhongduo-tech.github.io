## 为什么回溯需要树的遍历

许多问题的解不是一条确定的路径，而是一个**搜索空间**——要在所有候选里找满足约束的解。把这些候选组织成一棵**解空间树**，求解就变成「在这棵树上找可行结点」，而遍历这棵树的方法，就是**回溯法（backtracking）**：沿一条分支深入，走不通就**回溯**到最近的岔路口换一条。**八皇后问题**——在 $8 \times 8$ 棋盘上放 8 个皇后使互不攻击——是回溯的经典标本。它的解空间树是一棵「排列树」，回溯 + 剪枝让搜索从 $8^{64}$ 的荒谬降到几万次试探。

## 1 解空间树：把搜索组织成树

八皇后的解是「8 个皇后的列位置」的排列。逐行放置，每行选一列：第一行有 8 种选择，第二行又 8 种……解空间就是一棵**深度为 8、每层 8 叉**的树，叶结点数是 $8^8 \approx 1.68 \times 10^7$——这还只是「逐行放」的版本，已远小于 $8^{64}$。

**重点：回溯法 = 在这棵解空间树上做「带剪枝的深度优先遍历」。** 深搜自然用栈（递归），而「剪枝」在走到一个结点时就判断它是否可能导出解——不可能就直接放弃整个子树。<span class="marginnote">八皇后可以推广到「$n$ 皇后」：$n \times n$ 棋盘放 $n$ 个皇后。随着 $n$ 增大，解空间爆炸，但剪枝让实际搜索量远小于 $n^n$——<strong>回溯法的效率不取决于解空间大小，而取决于剪枝力度</strong>。</span>

## 2 八皇后的约束与剪枝

皇后互不攻击的约束有两条：

**同行/同列**：由于逐行放置，同行自动满足；同列判断列号是否已被占用；
**同对角线**：主对角线「行-列」为常数，副对角线「行+列」为常数——与已有皇后的 `row - col` 或 `row + col` 相同则冲突。

回溯算法骨架：

```cpp
bool ok(int row, int col, int n) {            /* 判断 (row, col) 是否与已放皇后冲突 */
    for (int i = 1; i < row; i++) {
        if (pos[i] == col) return false;                     /* 同列 */
        if (row - i == abs(col - pos[i])) return false;      /* 同对角线 */
    }
    return true;
}

void backtrack(int row, int n) {
    if (row > n) { /* 找到一个解，输出 pos[1..n] */ return; }
    for (int col = 1; col <= n; col++) {      /* 逐列尝试 */
        if (ok(row, col, n)) {
            pos[row] = col;                   /* 放置皇后 */
            backtrack(row + 1, n);            /* 深入下一行 */
            /* 返回后无需显式撤销：下一轮循环会覆盖 pos[row] */
        }
    }
}
```

**重点：回溯 = 递归深入 + 返回后继续尝试下一个候选。** 「撤销」在这里是隐式的：`for` 循环自动尝试下一列，`pos[row]` 被覆盖。<span class="marginnote">若候选带「占用标记」（如列、对角线是否被占），返回时必须<strong>显式撤销</strong>占用标记——否则下次尝试会误判冲突。「隐式撤销（覆盖） vs 显式撤销（还原标记）」是回溯实现的两大流派，按状态是否需要还原来选择。</span>

## 3 公式解析：n 皇后的解空间规模

n 皇后逐行放置的搜索树，结点总数（含剪枝前的全展开）为：

$$
N(n) = 1 + n + n^2 + \cdots + n^n = \frac{n^{n+1} - 1}{n - 1}
$$

- **第一步，读等比求和**：第 $k$ 层有 $n^k$ 个候选结点，从第 0 层（根）到第 $n$ 层（叶子）求和。
- **第二步，代入 $n=8$**：$N(8) \approx 1.9 \times 10^7$——约两千万次试探。对计算机是可接受量级，但纯暴力枚举 $8^{64}$ 则完全不可行。
- **第三步，读剪枝的威力**：实际带冲突剪枝后，八皇后只需约 **1.5 万次**试探——剪枝砍掉了 99.9% 的搜索。<span class="marginnote">「$n^n$ 指数 vs 剪枝后的多项式」是回溯的力量来源。<strong>解空间树的大小决定了「暴力有多暴力」，剪枝决定了「实际走多远」</strong>。这一对概念，在第三级《算法》的 NP 完备与回溯章节会反复辨析。</span>

## 4 从八皇后到通用的回溯模板

八皇后只是回溯的「hello world」。回溯能解决的是一大类问题，它们的共同结构是「**候选集 + 约束 + 目标**」：

| 问题 | 解空间树 | 约束 |
| --- | --- | --- |
| 八皇后 | 排列树（$n$ 层 $n$ 叉） | 列、对角线不冲突 |
| 子集和/背包 | 子集树（每层两叉：选/不选） | 容量与和 |
| 全排列/组合 | 排列树 | 已选元素去重 |
| 图的哈密顿回路 | 排列树 | 邻接与回到起点 |
| 数独 | 每格候选 1–9 | 行、列、宫不重复 |

**辨析｜易错点：子集树与排列树要分清。** 子集问题（选/不选）每层两叉，解空间 $2^n$；排列问题（排顺序）每层递减一叉，解空间 $n!$。回溯模板相同，但「下一层的候选集合」不同——选错树形，剪枝条件就全错。<span class="marginnote">回溯与《离散数学》的「生成排列/组合」、《算法》的「分支限界」一脉相承：分支限界是回溯的「带下界估计」版本，用于优化问题。<strong>回溯找「满足约束」，分支限界找「最优」</strong>——一个判可行，一个评优劣。</span>

## 5 回溯与「树遍历」的连接

回到本篇主题：回溯本质就是树的遍历，只是多了「剪枝」。把皇后问题对应到遍历语言：

**递归深入** = 先序遍历的一路向下；
**返回后换分支** = 遍历中访问完一棵子树后转向下一棵；
**剪枝** = 在访问某结点前判断「该子树不可能含解」，直接跳过。

**重点：会树的先序遍历，就会回溯的骨架；回溯只是「先序 + 剪枝」。** 这个连接让回溯从「神秘技巧」变成「树的遍历的应用」——也解释了为什么它出现在《树和二叉树》这一篇里。<span class="marginnote">这种「旧结构 + 新策略 = 新算法」的模式贯穿全书：队列 + 访问 = BFS，栈 + 状态 = 非递归 DFS，树 + 剪枝 = 回溯。<strong>算法的发明，多是结构复用的结果</strong>。</span>

**一个 4 皇后的完整回溯轨迹。** $n=4$ 比 8 更能看清流程：

- 第 1 行放列 1：`pos=[1]`；
- 第 2 行试列 1（同列冲突）、列 2（同对角线冲突）、列 3（合法）：`pos=[1,3]`；
- 第 3 行试列 1（冲突）、列 2（对角冲突）、列 3（同列）、列 4（对角冲突）——**全失败，回溯**；
- 返回第 2 行：换列 4：`pos=[1,4]`；第 3 行列 2 合法：`pos=[1,4,2]`；第 4 行列 3 合法：`pos=[1,4,2,3]`——**找到第一个解**。

注意「第 3 行全失败 → 返回第 2 行换列」就是**回溯**：放弃整棵「第 3 行的子树」，回到最近的岔路口。<span class="marginnote">「回溯 = 撤销当前层的选择、回到上一层继续」：<strong>当一层所有候选都被剪枝，就说明「这一层以上某个选择不对」</strong>——<strong>回溯往上走，直到某层还有未试的候选</strong>。<strong>4 皇后有 2 个解、8 皇后有 92 个解</strong>——解的数目远比搜索树小，这正是剪枝的功绩。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 解空间树 | 所有候选排列成的树 |
| 回溯 | 走不通返回最近的岔路口 |
| 剪枝 | 判定子树无解直接跳过 |
| 子集树 / 排列树 | 两叉选/不选 / 递减叉排顺序 |
| 隐式撤销 | 覆盖 pos[row]，无需还原标记 |

## 6 小结

- 回溯法 = 在**解空间树**上做带剪枝的深度优先遍历。
- 八皇后：逐行放置、逐列尝试，剪枝条件是列冲突与对角线冲突。
- 解空间规模 $N(n) = (n^{n+1}-1)/(n-1)$；剪枝把八皇后搜索降到约 1.5 万次。
- 子集树（两叉）与排列树（递减叉）是两类基本解空间。
- 隐式撤销（覆盖）与显式撤销（还原占用标记）是回溯实现的两派。
- 回溯 = 树的先序遍历 + 剪枝，是结构复用的典范。
