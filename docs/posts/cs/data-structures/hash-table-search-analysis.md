## 为什么哈希还要「分析」

哈希查找的流程一句话：**算地址 → 冲突就按解法找**。但「平均多少步」取决于装填因子 $\alpha$、冲突解法与哈希函数质量——这不是凭感觉能估的。本节把哈希查找的**完整流程**、**成功与失败的 ASL**、以及**各因素如何影响性能**系统分析一遍。结论会澄清一个常被误解的事实：**哈希表的 $O(1)$ 不是免费的，它在 $\alpha$ 低时成立；$\alpha$ 升高，一切按公式恶化**。理解这套分析，才算真正「会用」哈希表。

## 1 哈希查找的完整流程

查找关键字 $key$：

1. 计算地址 $addr = H(key)$；
2. 看 $addr$ 处：若为空 → 不存在；若关键字相等 → 找到；否则 → **冲突处理**；
3. 开放定址法：按探测序列继续找（线性/二次/伪随机）；链地址法：沿该桶链表逐个比；
4. 找到空位/链尾 → 查找失败。

**重点：哈希查找的「比较次数」= 探测/链表扫描的次数，由冲突决定。** 无冲突时 1 次，冲突越多越接近顺序查找。<span class="marginnote">「哈希查找 = 哈希计算 + 冲突消解」两步。<strong>哈希计算是常数，冲突消解是变量</strong>——所以哈希表性能分析的全部焦点，都落在「冲突消解要花多少步」上。这正是上一节两种冲突解法被反复对比的原因。</span>

## 2 公式解析：成功与失败的平均查找长度

设装填因子 $\alpha = n/m$，哈希函数均匀。两种冲突解法下的 ASL：

$$
\begin{aligned}
\text{链地址法} &: \quad ASL_{\text{成功}} \approx 1 + \frac{\alpha}{2}, \qquad ASL_{\text{失败}} \approx \alpha \\
\text{线性探测} &: \quad ASL_{\text{成功}} \approx \frac{1}{2}\left(1 + \frac{1}{1-\alpha}\right), \qquad ASL_{\text{失败}} \approx \frac{1}{2}\left(1 + \frac{1}{(1-\alpha)^2}\right)
\end{aligned}
$$

- **第一步，读「与 $\alpha$ 的关联方式」**：链地址是**线性**关联（$1+\alpha/2$），线性探测是**双曲**关联（分母 $1-\alpha$）。
- **第二步，代入 $\alpha = 0.5$**：链地址成功 1.25，线性探测成功 1.5——两者都「接近 1」。
- **第三步，代入 $\alpha = 0.9$**：链地址成功 1.45，线性探测成功 ≈ 5.5、失败 ≈ 50——**线性探测在 $\alpha=0.9$ 时已经不可用**。<span class="marginnote">「线性增长 vs 爆炸增长」的差异，是选冲突解法的决定性依据：<strong>若装填因子可能升高，链地址法安全得多</strong>。这也解释了为什么 Java 的 HashMap 把 $\alpha$ 定在 0.75、到 0.75 就扩容——<strong>在爆点之前扩容，是哈希表的养生之道</strong>。</span>

## 3 影响哈希查找性能的三个因素

1. **哈希函数的质量**：分布越均匀，冲突越少。除留余数法选好 $p$，字符串加权取好系数，都是「均匀化」手段；
2. **装填因子 $\alpha$**：越高越挤、越慢——是最可控的旋钮；
3. **冲突解决的方法**：链地址稳、开放定址敏。

**重点：三个因素中，$\alpha$ 是「最可操作」的**——哈希函数写好后难改，冲突解法建表前定死，唯有装填因子能通过「扩容」动态调控。工程哈希表的核心机制（扩容 + 重新哈希）就是围绕 $\alpha$ 展开的。<span class="marginnote">「扩容 + 重哈希」是哈希表工程实现的心脏：<strong>$\alpha$ 超阈值 → 表长翻倍 → 所有元素重新插入</strong>。重哈希 $O(n)$，但均摊到每次插入是 $O(1)$——这正是哈希表「均摊 $O(1)$」的数学基础。专题篇《哈希表工程实现》会完整算这笔均摊账。</span>

## 4 辨析｜易错点：哈希查找的几个常见误区

- **误区一：「哈希表查找恒为 $O(1)$」**：错。平均 $O(1)$ 依赖 $\alpha$ 与函数均匀；最坏（全部冲突）是 $O(n)$。
- **误区二：「装填因子可以接近 1」**：开放定址法不行（探测爆炸），链地址法勉强可以，但链太长仍慢。
- **误区三：「哈希表可以有序遍历」**：错。哈希地址无序，哈希表不支持范围查询——有序需求要回到 BST/B 树。
- **误区四：「哈希函数越复杂越好」**：错。计算快 + 分布均匀才是目标；过度复杂反而拖慢常数。<span class="marginnote">「平均 $O(1)$、最坏 $O(n)$、无法有序」三条边界，是哈希表的完整画像。<strong>要有序 → 别用哈希；怕最坏输入 → 随机化哈希或控制 $\alpha$</strong>。认清边界，哈希表才能用在刀刃上。</span>

## 5 从哈希分析到工程实践

- **语言内置哈希表**：Python `dict`、Java `HashMap`、C++ `unordered_map`——都是「哈希 + 链地址（或树化桶）+ 动态扩容」；
- **数据库哈希索引**：等值查询用哈希索引最快，但范围查询用 B+树；
- **分布式哈希**：一致性哈希（专题篇）解决「结点增删时最小化重映射」。

**重点：本节的分析框架——$\alpha$、冲突、ASL——直接迁移到工程哈希表。** 看懂这些公式，就能理解为什么 `HashMap` 要扩容、为什么某些负载会让哈希表变慢。<span class="marginnote">哈希分析是「<strong>从平均到工程</strong>」的模板：<strong>一个平均指标（ASL）背后藏着负载因子、冲突策略、最坏边界三件事</strong>。学会这套分析，你拿到任何「XX 表」都能问出关键问题——装多满？冲突怎么办？最坏多糟？</span>

## 6 小结

- 哈希查找 = 算地址 + 冲突消解；比较次数由冲突决定。
- 链地址 ASL：成功 $1+\alpha/2$、失败 $\alpha$——线性关联。
- 线性探测 ASL：成功 $\frac12(1+\frac1{1-\alpha})$、失败 $\frac12(1+\frac1{(1-\alpha)^2})$——双曲关联。
- $\alpha$ 是哈希性能最可操作的旋钮；扩容重哈希使其均摊 $O(1)$。
- 边界：平均 $O(1)$、最坏 $O(n)$、不支持有序。
- 工程哈希表（dict/HashMap/unordered_map）都遵循本节的分析框架。
