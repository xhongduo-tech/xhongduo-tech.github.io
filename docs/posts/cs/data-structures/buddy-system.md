## 为什么按 2 的幂管理

边界标识法的空闲表里，块大小五花八门，合并要逐个判断相邻。**伙伴系统（buddy system）**换一条思路：**把空闲块的大小限制为 2 的幂**，并按大小分成若干「档位」的链表。请求 $n$ 字节时，把它**向上取整到 2 的幂**，从对应档位找；没有就向上借（分裂），回收时反向合并。因为合并规则被「2 的幂」约束成「**与自己的伙伴合并**」，合并判断变得极其规整——这正是 Linux buddy allocator、诸多内存池的底层机制。

## 1 伙伴系统的组织

设整个堆大小为 $2^m$。空闲块按大小 $2^k$（$k = 0, 1, \cdots, m$）分成 $m+1$ 条链表：

- `free_list[k]`：大小为 $2^k$ 的空闲块链表；
- 分配请求 $n$ 向上取整为 $2^k$（$2^{k-1} < n \le 2^k$），从 `free_list[k]` 找。

**伙伴（buddy）**：一块大小为 $2^k$、起始地址为 $a$ 的块，若 $a$ 是 $2^{k+1}$ 的倍数，则它的伙伴是「地址 $a + 2^k$ 的那块」；否则伙伴是「地址 $a - 2^k$ 的那块」。**伙伴与它自己，合起来正好是一块大小为 $2^{k+1}$ 的块。**<span class="marginnote">伙伴的数学刻画很干净：设块大小为 $2^k$，起始地址右移 $k$ 位再异或 1，再左移 $k$ 位，就得到伙伴地址。用位运算表达：`buddy(a) = a ^ (1 << k)`——<strong>伙伴就是「地址的第 $k$ 位翻转」</strong>。这个简洁正是伙伴系统能用位运算快速实现的原因。</span>

## 2 分配：向上取整 + 分裂

请求 $n$ 字节：

1. 求 $k$：使 $2^{k-1} < n \le 2^k$，目标块大小 $2^k$；
2. 若 `free_list[k]` 非空，取一块返回；
3. 否则向上找第一个非空的 `free_list[j]`（$j > k$），取出一块 $2^j$，**反复分裂**：每次一分为二，左半留下、右半（或左半）放回下一档空闲表，直到得到 $2^k$ 的块返回。

```c
Block *BuddyAlloc(int n) {
    k = ceil_log2(n);                     /* 请求向上取整到 2^k */
    if (free_list[k] 非空) return Pop(free_list[k]);
    int j = k;
    while (++j <= m && free_list[j] 为空);   /* 向上找可分裂档 */
    if (j > m) return NULL;               /* 无块 */
    Block *b = Pop(free_list[j]);
    while (j > k) {                        /* 反复分裂 */
        j--;
        Block *half = b + (1 << j);        /* 后半块放回下一档 */
        Push(free_list[j], half);
    }
    return b;
}
```

**重点：分裂只发生在「向上借档」时，且每次一分为二、剩下一半回表。** 分裂产生的块大小全是 2 的幂，结构永远规整。<span class="marginnote">分裂是「<strong>借大还小</strong>」：借一块 $2^j$ 的，分到目标 $2^k$ 后，多出来的 $2^k, 2^{k+1}, \cdots$ 都回表。这一过程保证任何档位都不缺块（若有更大的空闲块）。</span>

## 3 回收：与伙伴合并

回收一块 $2^k$ 的块 `b`：

1. 查它的**伙伴** `buddy(b)`；
2. 若伙伴也空闲（在 `free_list[k]` 中），**从表中摘出伙伴**，合并成 $2^{k+1}$ 的块，继续向上检查；
3. 若伙伴不空闲，把 `b` 直接插入 `free_list[k]`。

**辨析｜易错点：伙伴必须「同档且地址按 2 的幂对齐」才能合并。** 不是任意两个相邻块都能合并——必须是**恰好同一档位**（大小同为 $2^k$）且「合起来恰好 $2^{k+1}$」的伙伴关系。`free_list[k]` 里有两个相邻块不代表它们是伙伴，它们的伙伴是「由地址位运算唯一确定的另一块」。<span class="marginnote">「只跟伙伴合并」是伙伴系统与边界标识法的根本区别：<strong>边界标识法按物理相邻合并（无档位约束），伙伴系统按地址位翻转合并（有幂次约束）</strong>。后者的合并树是「满二叉树」——每次分裂对应「分叉」，合并对应「剪枝」，天然无碎片合并失败。</span>

## 4 公式解析：伙伴系统的复杂度与碎片

设档位数为 $m+1$：

$$
\begin{aligned}
T_{\text{分配}} &= O(\log m) \ \text{（向上找档 + 分裂）} \\
T_{\text{回收}} &= O(\log m) \ \text{（沿伙伴链向上合并）} \\
S_{\text{内碎片}} &\le n - 2^{k-1} \ \text{（请求与分配块的大小差，最多近一倍）}
\end{aligned}
$$

- **第一步，读分配**：向上找非空档最坏 $O(m)$，分裂 $O(m)$——用档位数组 + 位图找「第一个非空档」可加速到 $O(\log m)$。
- **第二步，读回收**：合并可能沿伙伴链一路向上，最坏 $O(m)$ 档——但每档只一次。
- **第三步，读内碎片**：请求 $2^{k-1}+1$ 时分配到 $2^k$，浪费近一半——**伙伴系统的内碎片上限接近 100%**，这是「2 的幂对齐」的代价。<span class="marginnote">伙伴系统的账要算两笔：外碎片几乎消除（块总可合并）、内碎片最多近一倍。<strong>用内碎换外碎</strong>，是「规整管理」的典型交换——Linux 物理内存分配、jemalloc 的部分场景都吃下了这份内碎，换取分配/合并的极简与高效。</span>

## 5 伙伴系统的应用

- **Linux 内核物理内存分配**：页分配器（buddy allocator）按 2 的幂页数分配物理页，配合 slab 缓存做对象级复用；
- **jemalloc / 内存池**：按 size class 分档的分配器，思想与伙伴系统同源；
- **等幂分裂的数学结构**：伙伴系统本质是「满二叉树的先序分裂」，合并是后序还原——**它与二叉堆、完全二叉树共享同一棵编号树**。

**重点：伙伴系统把「内存分配」变成「二叉树上的分裂与合并」**——这是数据结构在系统软件里最优雅的落地之一。<span class="marginnote">「分裂 = 二叉树下行，合并 = 二叉树上行」——伙伴系统就是<strong>一棵完全二叉树（或满二叉树）的内存版</strong>。学完第六篇二叉树再回来读这一段，会有「原来如此」的感觉：<strong>数据结构的形态，决定了分配策略的形态</strong>。</span>

## 6 小结

- 伙伴系统：空闲块大小限定为 **2 的幂**，按档位 $m+1$ 条链表组织。
- 伙伴：大小 $2^k$ 块的伙伴 = 地址第 $k$ 位翻转（`a ^ (1<<k)`），合起来恰为 $2^{k+1}$ 块。
- 分配：向上取整 2 的幂 + 向上借档 + 反复分裂。
- 回收：只与**伙伴**合并（不与他人合并），沿链向上。
- 复杂度：分配/回收 $O(\log m)$；内碎片最多近一倍，外碎片几乎消除。
- 应用：Linux buddy allocator、jemalloc、内存池；本质是二叉树分裂合并。
