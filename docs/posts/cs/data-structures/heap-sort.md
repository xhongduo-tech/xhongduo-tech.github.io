## 为什么选择排序要配一棵树

简单选择排序每趟扫全表找最小，$O(n)$ 一趟、$O(n^2)$ 全程。能不能**把上一趟的比较结果记住**，让下一趟只补少量比较？**树形选择排序（锦标赛排序）**做到了：用一棵「锦标赛树」记录两两比较的胜者，每趟取冠军 $O(1)$，重赛只需沿冠军路径 $O(\log n)$。**堆排序**则是它的内存友好版：用**二叉堆**（完全二叉树的数组实现）替代锦标赛树，建堆 $O(n)$、每趟取极值 $O(\log n)$，全程 $O(n\log n)$ 且原地。堆排序是「选择思想」的终极形态，也是「优先队列」这头巨兽的基石。

## 1 树形选择排序（锦标赛排序）

**树形选择排序**：把 $n$ 个元素看成锦标赛的选手，两两比较建一棵「败者被淘汰」的树，树根就是全局最小（冠军）：

- 建树：叶子是元素，逐层两两比，胜者向上——$O(n)$ 次比较；
- 取冠军：树根即最小，$O(1)$；
- 重赛：把冠军位置置为 $\infty$（淘汰），沿它的路径向上重新比较——只需 $O(\log n)$ 次；
- 重复 $n$ 次取冠军，总 $O(n\log n)$。

**重点：锦标赛树的核心价值是「记录历史比较结果」——重赛时只重比冠军路径上的 $\log n$ 个结点，而非全表。**<span class="marginnote">「<strong>记住比较结果，别重复比较</strong>」是锦标赛排序的灵魂：上一趟比过的大小关系被固化在树里，下一趟只需修补被淘汰者的路径。<strong>「用空间（树）记历史，换时间（少比较）」</strong>——这正是从 $O(n^2)$ 到 $O(n\log n)$ 的通用套路。</span>

## 2 堆排序：锦标赛树的数组版

锦标赛树要建一棵真二叉树，空间 $O(n)$ 且不原地。**堆排序**把它塞进数组：**二叉堆 = 完全二叉树的数组表示**，父结点 $i$ 的孩子是 $2i$、$2i+1$（第六篇性质 5）。

**大根堆**：每个结点 ≥ 它的孩子 → 堆顶是最大元素；
**小根堆**：每个结点 ≤ 它的孩子 → 堆顶是最小元素。

堆排序（升序用大根堆）三步：

1. **建堆**：把数组调整成大根堆，$O(n)$；
2. **取最大**：堆顶与末尾交换，堆顶最大元素就位；堆规模 -1；
3. **下沉（sift down）**：新堆顶向下调整恢复大根堆性质，$O(\log n)$；重复到堆空。

```c
void SiftDown(int a[], int n, int i) {  /* 大根堆 */
    int tmp = a[i], child;
    while (i * 2 <= n) {
        child = i * 2;
        if (child < n && a[child + 1] > a[child]) child++;  /* 选较大的孩子 */
        if (tmp >= a[child]) break;
        a[i] = a[child];                /* 孩子上移 */
        i = child;
    }
    a[i] = tmp;
}

void HeapSort(int a[], int n) {         /* 升序，下标从 1 起 */
    int i, tmp;
    for (i = n / 2; i >= 1; i--)        /* 建堆：自底向上下沉 */
        SiftDown(a, n, i);
    for (i = n; i > 1; i--) {
        tmp = a[1]; a[1] = a[i]; a[i] = tmp;   /* 堆顶与末尾交换 */
        SiftDown(a, i - 1, 1);                 /* 新堆顶下沉 */
    }
}
```

**重点：建堆从「最后一个非叶结点」开始，自底向上下沉——每个结点下沉一次，总代价 $O(n)$。**<span class="marginnote">「从 $n/2$ 开始自底向上」是建堆的奥妙：<strong>叶子不用下沉，从倒数第二层开始，每层结点下沉高度有限，累加仍是 $O(n)$</strong>。若从根「自顶向下逐个插入」，反而要 $O(n\log n)$——<strong>建堆的方向（自底向上）决定了建堆的复杂度</strong>。</span>

## 3 公式解析：堆排序的复杂度

$$
\begin{aligned}
T_{\text{建堆}} &= O(n) \qquad \text{（自底向上下沉，总代价线性）} \\
T_{\text{排序}} &= O(n\log n) \qquad \text{（$n$ 趟，每趟下沉 } O(\log n) \text{）} \\
S &= O(1) \qquad \text{（原地，仅数组）}
\end{aligned}
$$

- **第一步，读建堆 $O(n)$**：第 $k$ 层有 $2^{k-1}$ 个结点、每个下沉至多 $h-k$ 层，累加求和得 $O(n)$——「直觉 $O(n\log n)$、精算 $O(n)$」。
- **第二步，读排序 $O(n\log n)$**：$n-1$ 趟，每趟一次交换 + 一次 $O(\log n)$ 下沉。
- **第三步，读「最优之一」**：堆排序的 $O(n\log n)$ 是**最坏保证**（不像快排平均才 $O(n\log n)$）、且原地 $O(1)$——**这是快排做不到的组合**（快排最坏 $O(n^2)$、空间 $O(\log n)$）。<span class="marginnote">堆排序是「<strong>三优合一</strong>」的排序：最坏 $O(n\log n)$ + 原地 $O(1)$ + 无需递归。它输给快排的只有「常数因子」（堆操作的缓存不友好）——所以工程排序主流仍是快排，但「<strong>需要最坏保证 + 原地</strong>」时（嵌入式、实时系统），堆排序是首选。</span>

## 4 稳定性与辨析

**稳定性**：**不稳定**。堆的交换会破坏相等元素的相对顺序。
**辨析一：堆排序 vs 简单选择排序**——堆排序就是「选择排序 + 堆加速」，把「挑最小」从 $O(n)$ 降到 $O(\log n)$；
**辨析二：堆排序 vs 快排**——堆最坏 $O(n\log n)$、原地、不稳定但常数大；快排平均快、常数小、最坏 $O(n^2)$。<span class="marginnote">「快排常数小、堆排保证强」是工程选型的分水岭：<strong>要平均最快选快排（C 库 qsort），要最坏有保证选堆排（实时系统）</strong>。$O(n^2)$ 用 introsort——快排 + 堆排兜底，正是「两者都要」的组合。</span>

## 5 从堆排序到优先队列

堆排序把「堆」这个结构用到了极致，而堆本身是**优先队列（priority queue）**的经典实现：

**插入**：新元素放堆尾，上浮 $O(\log n)$；
**取极值**：堆顶 $O(1)$，删除后下沉 $O(\log n)$。

**重点：堆 = 支持「插入 + 取极值」都 $O(\log n)$ 的数据结构。** Dijkstra、Prim、Top-K、合并 K 个有序链表——凡需要「动态维护极值」的算法，都离不开堆。堆排序只是堆的一个应用。<span class="marginnote">「堆排序是堆的顺带产物」——<strong>堆本身是为了「优先队列」而生的，排序只是它的一个用途</strong>。到专题篇《二叉堆的上浮与下沉》《优先队列的典型应用》，我们会把「上浮/下沉」两个原语与堆的全部应用系统展开——<strong>本节先让堆完成排序使命，下篇再让它当优先队列</strong>。</span>

**辨析｜易错点：建堆是「自底向上」，排序的「取顶」是「自上而下」。** 建堆从最后一个非叶结点开始，逐个向下沉——每个结点只处理一次，总 $O(n)$。而排序阶段每次把堆顶与末尾交换后，只对「新堆顶」下沉——每趟 $O(\log n)$。两个方向、两种代价，别混为一谈。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 大根堆 / 小根堆 | 父 ≥ 子 / 父 ≤ 子 |
| 建堆 | 自底向上下沉，$O(n)$ |
| 取顶 | 堆顶与末尾交换 + 下沉 |
| 锦标赛树 | 堆排序的树形前身 |
| 优先队列 | 堆作为「插入 + 取极值」结构 |

## 6 小结

- 树形选择排序：锦标赛树记比较结果，重赛只沿冠军路径 $O(\log n)$。
- 堆排序 = 锦标赛树的数组版：大根堆 + 建堆 + 取顶 + 下沉。
- 建堆自底向上，$O(n)$；排序 $n$ 趟 $O(\log n)$，总 $O(n\log n)$。
- **原地 $O(1)$ + 最坏 $O(n\log n)$ + 不稳定**——快排没有的组合。
- 与快排对比：快排常数小、堆排最坏有保证。
- 堆 = 优先队列：插入、取极值均 $O(\log n)$，是 Dijkstra/Prim/Top-K 的地基。
