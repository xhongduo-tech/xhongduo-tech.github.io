## 为什么图的存储是两个世界

树有孩子个数上限，图的边却「任意分布」——于是图的存储分化成两个世界：**邻接矩阵（数组表示法）**用 $n \times n$ 二维数组穷举所有「点对」，空间 $\Theta(n^2)$、查边 $O(1)$；**邻接表**只存「存在的边」，空间 $O(n+e)$、查边 $O(\text{度})$。选谁，取决于图是**稠密**（$e \sim n^2$）还是**稀疏**（$e \sim n$）。本节把两种结构及其变体讲透，并明确「查边 / 遍历邻居」两种运算在两种结构下的真实代价——这直接决定后面 DFS、Dijkstra 等算法的复杂度。

## 1 邻接矩阵：数组表示法

**邻接矩阵（adjacency matrix）**：用二维数组 $A[n][n]$ 表示图。无向图中：

$$
A[i][j] = \begin{cases} 1 & (v_i, v_j) \in E \\ 0 & \text{否则} \end{cases}
$$

有权图把 1 换成权值，无连边处用 $\infty$。`$$<span class="marginnote">两个直觉事实：<strong>无向图的邻接矩阵一定对称</strong>（$(u,v)$ 与 $(v,u)$ 同一条边），对角线上常为 0；第 $i$ 行的 1 的个数就是 $v_i$ 的度（无向）或出度（有向）。矩阵的对称性在有向图里消失——一眼就能区分存储的是有向还是无向图。</span>

**重点：邻接矩阵的「查边」是 $O(1)$**——`A[i][j]` 一次寻址。这让它在「频繁判断两点是否相邻」的场景不可替代。

## 2 邻接表：只存存在的边

**邻接表（adjacency list）**：为每个顶点开一条链表，链表里存「与该顶点相邻的所有顶点」。结构上是一个**顶点表数组 + 边链表**：

```c
typedef struct ArcNode {          /* 边（弧）结点 */
    int adjvex;                   /* 该弧指向的顶点位置 */
    struct ArcNode *next;         /* 下一条弧 */
    InfoType info;                /* 权值等信息 */
} ArcNode;
typedef struct VNode {            /* 顶点结点 */
    VertexType data;
    ArcNode *firstarc;            /* 指向第一条弧 */
} VNode;
typedef struct { VNode adjlist[MAXV]; int n, e; } ALGraph;
```

**重点：邻接表的空间是 $O(n+e)$**——顶点 $n$ 个 + 边（弧）$e$ 条。稀疏图下它远小于邻接矩阵的 $\Theta(n^2)$。<span class="marginnote">无向图的邻接表里，每条边出现<strong>两次</strong>（$(u,v)$ 同时挂在 $u$ 和 $v$ 的链上），所以边链表总长 $2e$。这个「边存两份」是邻接表处理无向图的一个小代价，也催生了「邻接多重表」这种边只存一份的变体（下一节）。</span>

## 3 公式解析：两种存储的代价对比

两种结构在关键运算上的复杂度并排：

$$
\begin{aligned}
S_{\text{空间}} &: \ \text{邻接矩阵 } \Theta(n^2), \quad \text{邻接表 } O(n+e) \\
T_{\text{查边}} &: \ \text{邻接矩阵 } O(1), \quad \text{邻接表 } O(\text{度}(v)) \\
T_{\text{遍历邻居}} &: \ \text{邻接矩阵 } O(n), \quad \text{邻接表 } O(\text{度}(v))
\end{aligned}
$$

- **第一步，读空间**：矩阵固定 $\Theta(n^2)$，与边数无关；邻接表按边数线性增长。$n=10^5$ 的稀疏图，矩阵要 $10^{10}$ 单元，邻接表只要 $O(n+e)$。
- **第二步，读查边**：矩阵 $O(\text{度})$ 直取；邻接表要沿 $v_i$ 的链表找 $j$，$O(\text{度})$。
- **第三步，读遍历邻居**：矩阵要扫整行 $O(n)$ 才知道「有哪些邻居」；邻接表直接给出邻居链表 $O(\text{度})$。**DFS/BFS 的总复杂度由此而来**：邻接表版 $O(n+e)$，矩阵版 $O(n^2)$。<span class="marginnote">「<strong>遍历邻居</strong>」是图算法的最频繁操作——DFS、BFS、Dijkstra 都要反复访问邻居。邻接表让它的总代价从 $O(n^2)$ 降到 $O(n+e)$，这正是稀疏大图上<strong>邻接表统治级优势</strong>的来源。</span>

## 4 辨析｜易错点：两个容易混淆的点

**「行=出度、列=入度」只对有向图成立**：有向图邻接矩阵第 $i$ 行 1 的个数是出度，第 $j$ 列 1 的个数是入度；无向图行与列都等于度。
**「逆邻接表」**：为快速求入度，可另建一张「入边表」（每个顶点存指向它的弧）。邻接表给出度方便、逆邻接表给入度方便——这催生了「十字链表」：把两者合一（下一节）。<span class="marginnote">邻接表给出度、逆邻接表给入度，各有半张图的信息。<strong>十字链表把出弧链表与入弧链表合进同一张表</strong>，让有向图的入度、出度都能 $O(1)$ 起步访问——这是「省一半还是全都要」的又一权衡。</span>

## 5 两种结构怎么选

选型口诀一句话：**稠密用矩阵，稀疏用邻接表。**

**稠密图**（$e$ 接近 $n^2$，如完全图、小规模竞赛图）：邻接矩阵的空间 $\Theta(n^2)$ 与邻接表相当，但查边 $O(1)$ 更优——矩阵胜。
**稀疏图**（$e \sim n$，如路网、社交网络、大图）：邻接表空间 $O(n+e)$ 完胜，遍历邻居 $O(n+e)$ 完胜——邻接表胜。
**需要快速判断「两点是否相邻」**：矩阵 $O(1)$ 无条件优于邻接表。

现代工程里的大图几乎都是稀疏的（社交网络、Web 图），所以**邻接表是默认选择**，邻接矩阵常见于小规模、密集、需要 $O(1)$ 查边的场景。<span class="marginnote">注意「稠密/稀疏」没有绝对阈值，经验上以 $e$ 与 $n^2$ 的比值粗略划分。工程里还常用邻接表的「数组版」（CSR, Compressed Sparse Row）——把边链表压进连续数组，缓存友好且省指针，是 <strong>GraphBLAS、图神经网络框架的底层格式</strong>。</span>

## 6 小结

- 邻接矩阵：$\Theta(n^2)$ 空间，查边 $O(1)$，无向图对称、有向图不对称。
- 邻接表：$O(n+e)$ 空间，只存存在的边，遍历邻居 $O(\text{度})$。
- 无向图邻接表每条边出现两次（$2e$ 个弧结点）。
- DFS/BFS 总复杂度：邻接表 $O(n+e)$，邻接矩阵 $O(n^2)$。
- 选型：稠密图选矩阵、稀疏图选邻接表；工程大图默认邻接表（CSR）。

在下一节，我们补齐两种「进阶」存储——**十字链表与邻接多重表**，它们分别优化有向图与无向图。
