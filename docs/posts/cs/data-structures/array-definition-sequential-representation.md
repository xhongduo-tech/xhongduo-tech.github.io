## 为什么把数组单列一篇

前面所有顺序结构都建立在「数组」上，但那时数组只是工具。现在反过来问：**数组本身是什么数据结构？** 它是 $n$ 维的**固定结构**——一旦声明，各维大小不可改变。与线性表的「动态增删」不同，数组只提供「按下标存取」一种运算，且这个运算必须 $O(1)$。让数组 $O(1)$ 存取的，是一套**地址计算公式**：把逻辑下标翻译成物理偏移。本节把二维、三维直到 $n$ 维的地址公式一次讲透，并解释行优先与列优先两种排布的区别——这是后续矩阵压缩存储、稀疏矩阵、以及张量（大模型的地基）内存布局的共同前提。

## 1 数组的定义

**数组（array）**：由一组**类型相同**的数据元素构成，每个元素受 $n$ 个**线性关系**约束，称为 $n$ 维数组。每个关系确定一个下标范围，元素由下标序偶唯一确定。

一维数组就是定长线性表；二维数组可看成「元素为线性表」的线性表——**数组是线性表的推广**，或者说，$n$ 维数组是「线性表的线性表的……线性表」。这个递归视角在求地址时很有用。

数组的基本运算只有两种：**给定下标，取该元素**（Value 取值）与**给定下标，改该元素**（Assign 赋值）。它没有插入删除——结构固定，这正是「数组 vs 线性表」的分界线。<span class="marginnote">数组是「<strong>按下标直接定位</strong>」的结构，线性表是「<strong>按逻辑顺序增删</strong>」的结构。一个重随机访问、一个重动态变化。判断用谁，就问一句：数据规模在运行期会不会变？</span>

## 2 顺序存储：把多维拍成一维

内存是一维的，多维数组必须**按某种顺序拍平**。只有两种本质不同的拍法：

- **行优先（row-major）**：先放满第一行，再放第二行……C/C++ 采用行优先。
- **列优先（column-major）**：先放满第一列，再放第二列……FORTRAN 采用列优先。

以 $m \times n$ 的二维数组为例，行优先下元素 $A[i][j]$ 前面有 $i$ 个完整行、每行 $n$ 个元素，再加本行的 $j$ 个：

**一图看清两种排法**：对 $3\times4$ 的数组，行优先的存储顺序是
$A[0][0], A[0][1], A[0][2], A[0][3], A[1][0], A[1][1], \cdots$；
列优先则是 $A[0][0], A[1][0], A[2][0], A[0][1], A[1][1], A[2][1], \cdots$。
同一个「逻辑矩阵」，两种物理布局，前者第一行紧挨，后者第一列紧挨——**布局选择决定哪个「方向」的访问是连续的**，也就决定了缓存命中率。

$$
LOC(i,j) = LOC(0,0) + (i \times n + j) \times L
$$

其中 $LOC(0,0)$ 是数组起始地址，$L$ 是每个元素占的字节数。<span class="marginnote">行优先与列优先没有优劣，只有「谁更契合访问模式」：C 里 <strong>访问同一行的元素（连续下标）</strong>时缓存命中最好，因为它们在内存里相邻；而 FORTRAN 的矩阵乘法惯例则让列相邻。现代向量化库（如 NumPy）的「按内存布局选择算法」，本质就是在利用行/列优先的局部性。</span>

两种排法的细节差异值得一张对照表收住：

| 维度 | 行优先（row-major） | 列优先（column-major） |
| --- | --- | --- |
| $A[i][j]$ 的偏移 | $i \times n + j$ | $j \times m + i$ |
| 连续访问的是 | 同一行的元素 | 同一列的元素 |
| 代表语言 | C/C++、Python、Java | FORTRAN、MATLAB（列优先存储） |
| 地址公式的第一项 | 先跳 $i$ 个整行 | 先跳 $j$ 个整列 |

**面试高频追问**：在行优先语言里遍历二维数组，为什么「外层按行、内层按列」比反过来快一个数量级？答案是局部性——内存按行排布，逐行走一遍恰好是顺序读；按列走一遍则每次跨过一整行，缓存连续失效。**这道题考的正是本节的行优先布局。**

## 3 公式解析：$n$ 维数组的地址

设 $n$ 维数组各维下标上限为 $b_1, b_2, \cdots, b_n$（下标从 0 起，每维有 $b_i$ 个元素）。对下标 $(j_1, j_2, \cdots, j_n)$，其地址为：

$$
LOC(j_1, \cdots, j_n) = LOC(0, \cdots, 0) + \left(\sum_{k=1}^{n} j_k \prod_{i=k+1}^{n} b_i \right) \times L
$$

- **第一步，读懂内层 $\prod_{i=k+1}^{n} b_i$**：它表示「第 $k$ 维下标每增加 1，跳过多少个元素」。第 $n$ 维（最后一维）的乘积是空积 = 1——最后一维相邻元素地址连续。
- **第二步，读懂求和**：从第 1 维到第 $n$ 维，把每维贡献的偏移量累加。这是「行优先」的 $n$ 维推广：越靠前的维，每个单位跳过越多元素。
- **第三步，用二维验证**：$n=2$ 时 $\prod_{i=3}^{2} = 1$，$\prod_{i=2}^{2} = b_2 = n$，于是 $LOC = LOC(0,0) + (j_1 \times n + j_2) \times L$——与上一节的行优先公式完全一致。<span class="marginnote">这套公式是<strong>编译器的活教材</strong>：C 语言里 $\prod_{i=2}^{2} = b_2 = n$ 的寻址，编译阶段就由编译器按行优先展开成 $LOC = LOC(0,0) + (j_1 \times n + j_2) \times L$。<strong>地址公式不是「数据结构理论」，而是每次数组访问都在执行的真实计算</strong>。</span>

## 4 三种视图：数组、矩阵、张量

数组与数学对象的关系值得理清：

**二维数组 ↔ 矩阵**：行优先的二维数组就是矩阵的内存形态。矩阵的转置、乘法，在行优先下都变成「如何调整下标访问顺序」的问题。
**三维数组 ↔ 图像/张量**：一张 $H \times W \times 3$ 的彩色图像，是三维数组；神经网络的权重与激活是更高维张量。大模型里的批量矩阵乘法，全部运行在「多维数组的连续内存」上。<span class="marginnote">大模型训练为何偏爱 GPU？一个重要原因是张量运算可以<strong>按块搬到显存、整块并行计算</strong>——而这一切的前提，是张量在内存里是连续的行优先排布。数组的地址公式，是大模型性能的下限。</span>

## 5 辨析｜易错点：下标从 0 还是从 1

C/C++/Python：下标从 **0** 开始，地址公式为 $i \times n + j$，无偏移。
数学与部分教材（严蔚敏的矩阵讨论）：常从 **1** 开始，公式为 $(i-1)\times n + (j-1)$，或把每行预留长度。
混用会直接算错地址——**写地址公式前，先明确下标的起点**。<span class="marginnote">「下标从 0 起还是 1 起」看似琐碎，实则是<strong>边界约定</strong>问题的缩影：从 0 起时「$n$ 个元素 = 下标 $0..n-1$」，从 1 起时「= $1..n$」。二分查找、循环边界、地址公式，处处都受这个约定的影响。</span>

## 6 数值算例：手算一个三维数组的地址

公式不能只背不练。设数组 $A$ 声明为 $A[3][4][5]$（下标从 0 起，共 $3\times4\times5=60$ 个元素），每个元素占 $L=4$ 字节，起始地址 $LOC(0,0,0)=1000$。求 $A[2][3][1]$ 的地址。

代入 $n$ 维公式，各维大小 $b_1=4$（第二维）、$b_2=5$（第三维），下标 $(j_1,j_2,j_3)=(2,3,1)$：

$$
LOC = 1000 + \big( 2\times(4\times5) + 3\times5 + 1 \big)\times 4 = 1000 + (40 + 15 + 1)\times 4 = 1224
$$

- **第一步，算每维的「步长」**：第 1 维每走 1 个单位跨过 $4\times5=20$ 个元素；第 2 维每走 1 个单位跨过 5 个元素；第 3 维每走 1 个单位跨过 1 个元素。步长从大到小，正是行优先的特征。
- **第二步，乘下标并累加**：$2\times20 + 3\times5 + 1\times1 = 40+15+1=56$，这是 $A[2][3][1]$ 前面共有 56 个元素。
- **第三步，乘字节并加基址**：$56\times4=224$ 字节，$1000+224=1224$。

**验证**：$A[2][0][0]$ 的地址应为 $1000 + 2\times(4\times5)\times4 = 1000+160=1160$，恰好是第三组 20 个元素的起点；$A[0][0][4]$ 的地址应为 $1000+4\times4=1016$，是第二层第一个元素的最后一位。**地址连续、层层衔接，这就是「顺序存储」四个字的全部含义。**<span class="marginnote">面试手写多维数组寻址时，先画一张「步长表」：从最后一维开始，步长 1、$b_n$、$b_{n-1}b_n$……再从前到后乘下标。画完表再算，几乎不会错。</span>

## 7 易错辨析：四组最容易混的概念

**一维数组的地址**：$LOC(i) = LOC(0) + i\times L$，下标即偏移量——无乘除弯绕，但很多人会忘记乘 $L$。
**行优先 vs 列优先的互换**：同一逻辑元素 $A[i][j]$，行优先偏移 $i\times n + j$，列优先偏移 $j\times m + i$——把 $m$、$n$ 对调再互换 $i$、$j$ 即得。
**「元素个数」 vs 「最大下标」**：$A[0..m-1][0..n-1]$ 有 $m\times n$ 个元素，但最大下标是 $m-1$、$n-1$——差一个 1，地址公式错一位。
**基址是否是首元素地址**：$LOC(0,0)$ 是数组首元素的地址；若题目给「首行首元素地址」，与 $LOC(0,0)$ 同义；若给「数组名地址」，在多数语言里也等于 $LOC(0,0)$，但在某些数组下标从 1 起的教材语境里要小心整体偏移。

`<center>`—— 行优先下「先变行、后变列」的顺序，与 C 里 `a[i][j]` 的访问顺序完全一致 ——`</center>`

## 8 小结

- 数组是 **$n$ 维固定结构**，只按下标存取，$O(1)$；没有插入删除。
- 数组是**线性表的推广**（$n$ 维 = 线性表的线性表的……）。
- 二维内存排布两种：**行优先**（C/C++）与**列优先**（FORTRAN）。
- 地址公式 $LOC(i,j) = LOC(0,0) + (i\times n + j)\times L$，$n$ 维推广为加权和公式。
- 越靠前的维，每个单位跳过的元素越多（行优先）。
- 数组 ↔ 矩阵 ↔ 张量，是数值计算与大模型的内存地基。
- 步长自最后一维起算（1、$b_n$、$b_{n-1}b_n$、……），行优先下「前维大步、后维小步」。
- 缓存局部性决定遍历顺序：行优先语言按行访问远快于按列。
- 四组易错点：忘乘 $L$、行列优先互换、个数与最大下标差一、基址语义。

在下一节，我们让数组「减肥」——**矩阵的压缩存储（特殊矩阵）**，对对称、三角、对角矩阵只存一半。压缩存储的思想正是本节的地址公式：**只存非冗余部分，再用公式把逻辑下标映射到压缩后的物理下标**——地址公式在压缩矩阵里依然是主角。
