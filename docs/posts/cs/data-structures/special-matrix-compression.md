## 为什么矩阵需要压缩

上一节讲了数组的行优先/列优先存储——二维数组存矩阵，$n \times n$ 就占 $n^2$ 个单元。但很多矩阵的 $n^2$ 个元素里**大量重复或全为零**：对称矩阵有 $n(n-1)/2$ 个元素是「镜像重复」，三角矩阵有 $n(n-1)/2$ 个元素恒为零，三对角矩阵更是只有约 $3n$ 个非零元素。把重复的和为零的都存下来，是对内存的浪费。**压缩存储**的思路是：只存「不重复、非零」的那部分，并用一套**下标映射公式**在「逻辑下标 (i,j)」与「物理位置 k」之间来回换算。本节以对称、三角、对角三类特殊矩阵为例。

## 1 对称矩阵的压缩

**对称矩阵（symmetric matrix）**：$A[i][j] = A[j][i]$ 对一切 $i, j$ 成立。因此只需存**下三角（含对角线）**，即 $i \ge j$ 的部分。

下三角的元素个数是 $n(n+1)/2$，把它压进一维数组 $SA[0..n(n+1)/2 - 1]$。存法按行优先：第 1 行存 1 个、第 2 行存 2 个、……第 $i$ 行存 $i$ 个。于是元素 $A[i][j]$（约定下标从 1 起，$i \ge j$）在一维数组中的位置为：

$$
k = \frac{i(i-1)}{2} + (j-1)
$$

其中 $i(i-1)/2$ 是前 $i-1$ 行元素总数（$1 + 2 + \cdots + (i-1)$），$j-1$ 是本行内 $A[i][j]$ 前面的元素个数。<span class="marginnote">下标从 1 起时用 $\frac{i(i-1)}{2}$，从 0 起时用 $\frac{i(i+1)}{2}$——<strong>起点的选择改变公式，公式必须与起点配套</strong>。这也是上一节「下标从 0 还是 1」的延续。</span>

若需要 $A[i][j]$ 而 $i < j$，则利用对称性交换：$A[i][j]$ 与 $i < j$ 同值，用 $n^2$ 访问。<span class="marginnote">对称矩阵只存一半，存储量从 $n^2$ 降到 $n(n+1)/2$——接近省一半。这张「<strong>用公式换空间</strong>」的账，是压缩存储的通用模型：<strong>牺牲一次乘法运算，换来接近减半的内存</strong>。</span>

## 2 三角矩阵的压缩

**三角矩阵**分两种：**下三角矩阵**（$i < j$ 处恒为零）与**上三角矩阵**（$i > j$ 处恒为零）。它们的非零元素都只有 $n(n+1)/2$ 个。

以下三角矩阵为例，只存下三角（含对角线），再加**一个单元**存常数（上三角的零部分全由这个常数代表）。一维数组长为 $n(n+1)/2 + 1$。访问 $A[i][j]$：

$i \ge j$：$k = \frac{i(i-1)}{2} + (j-1)$（同对称矩阵）；
$i < j$：直接返回常数（如 0）。

上三角矩阵对称地处理：以「行优先」存上三角时，$A[i][j]$（$i \le j$）位置为 $k = \frac{(i-1)(2n - i + 2)}{2} + (j - i)$——前 $i-1$ 行的元素总数是第 $1$ 行的 $n$ 个、第 $2$ 行的 $n-1$ 个……求和 $n + (n-1) + \cdots + (n-i+2) = \frac{(i-1)(2n - i + 2)}{2}$。<span class="marginnote">上三角的行优先求和，是一个标准的<strong>等差数列部分和</strong>：第 $r$ 行有 $n-r+1$ 个元素。把公式退回去想一遍（先想 $n=3$ 的小矩阵），比死记公式可靠。</span>

## 3 对角矩阵（带状矩阵）的压缩

**对角矩阵（diagonal matrix）**：非零元素只出现在主对角线及其两侧的有限条斜带上。最典型的是**三对角矩阵（tridiagonal matrix）**：非零元素仅在主对角线、主对角线上方一条、下方一条上，共约 $3n - 2$ 个。

三对角矩阵的压缩存储：按行把三条对角线上的元素依次存入一维数组 $B$。元素 $A[i][j]$ 非零当且仅当 $|i - j| \le 1$。行优先存储下：

$$
k = 2i + j - 3 \qquad (1 \le i, j \le n, \ |i-j| \le 1)
$$

- **第一步，核对第一行**：$A[1][1]$ 在第 1 行第 1 个 → $k = 2+1-3 = 0$；$A[1][2]$ → $k = 2+2-3 = 1$。正确。
- **第二步，核对每行的三个**：第 $i$ 行有 3 个元素（除首尾行有 2 个），位置 $k = 3(i-1)$ 起。代入 $A[i][i-1]$：$2i + (i-1) - 3 = 3i - 4$；$A[i][i]$：$3i - 3$；$A[i][i+1]$：$3i - 2$。三者连续。
- **第三步，体会常数时间换算**：任意合法下标都能 $O(1)$ 定位，因为三条对角线在数组里是连续排布的。<span class="marginnote">三对角矩阵是<strong>带状矩阵</strong>的特例。有限差分求解偏微分方程时，离散化会天然产生带状矩阵——数值线性代数里著名的 Thomas 算法（追赶法）正是基于三对角结构，只需 $O(n)$ 时间求解方程组。</span>

## 4 核心对比表：三类特殊矩阵

三类矩阵的压缩要点并排：

| 矩阵类型 | 非零/不重复元素数 | 压缩存储内容 | 访问 $A[i][j]$ 的处理 |
| --- | --- | --- | --- |
| 对称 | $n(n+1)/2$ | 只存下三角 | $i<j$ 时交换下标 |
| 下三角 | $n(n+1)/2$ | 下三角 + 常数单元 | $i<j$ 返回常数 |
| 上三角 | $n(n+1)/2$ | 上三角 + 常数单元 | $i>j$ 返回常数 |
| 三对角 | 约 $3n-2$ | 三条对角线 | $|i-j|>1$ 返回 0 |

三条规律：第一，**压缩的前提是结构规则**——对称、三角、带状都有精确的「哪些元素有值、哪些恒为零」的判定规则，公式才能成立。第二，**压缩换来的是空间、付出的是计算**：每次访问都要算一次映射公式，牺牲运算换内存。第三，**当矩阵不再规则（稀疏但零元素散布各处）时，本节的方法失效**——那就要用下一节的三元组表示。

## 5 辨析｜易错点：矩阵压缩 vs 稀疏矩阵

初学者常把「特殊矩阵压缩」与「稀疏矩阵」混为一谈。区别在于：

**特殊矩阵**：元素分布有**确定规律**（对称、三角、带状），压缩后仍可用**公式** $O(1)$ 定位。
**稀疏矩阵**：非零元**少但分布无规律**，无法用公式定位，必须显式记录每个非零元的（行, 列, 值）——即三元组表。
**判断标准**：能否用「行、列」的简单函数算出存储位置。能 → 特殊矩阵；不能 → 稀疏矩阵。<span class="marginnote">这个二分本质上问的是「<strong>数据的规律性能否用公式捕获</strong>」。捕获得了，用压缩数组；捕获不了，用索引表。文件系统、数据库索引的设计也遵循同一逻辑：能用公式映射的，绝不建表。</span>

## 6 数值算例：把三个公式算到具体数上

用一个 $n = 4$ 的矩阵把三条公式各自验一遍。

**对称矩阵**：$n = 4$，下三角共 $n(n+1)/2 = 10$ 个元素。求 $A[3][2]$ 的位置：$k = \frac{3 \times 2}{2} + (2-1) = 3 + 1 = 4$。核对行优先排布：第 1 行 1 个、第 2 行 2 个、第 3 行 3 个，$A[3][2]$ 是第 3 行的第 2 个，前面共 $1 + 2 + 1 = 4$ 个——吻合。若问 $A[2][3]$（$i < j$），交换下标后用 $A[3][2]$ 的位置 4。

**上三角矩阵**：$n = 4$，求 $A[2][3]$（$i \le j$）：$k = \frac{(2-1)(8-2+2)}{2} + (3-2) = \frac{8}{2} + 1 = 5$。核对：第 1 行存 4 个、第 2 行存 3 个，$A[2][3]$ 是第 2 行的第 2 个，前面共 $4 + 1 = 5$ 个——吻合。

**三对角矩阵**：$n = 4$，求 $A[3][4]$（$|i-j| = 1$，合法）：$k = 2 \times 3 + 4 - 3 = 7$。核对行优先：第 1 行 2 个、第 2 行 3 个、第 3 行 3 个，$A[3][4]$ 是第 3 行的第 3 个，前面共 $2 + 3 + 2 = 7$ 个——吻合。

**重点：公式的每一次核对都在做同一件事——「先数前面的行，再数本行内的位置」。** 只要记住这条原始语义，任何公式都能自己推导、自己验证，而不必死背。<span class="marginnote">「<strong>先数前面的行、再数本行内的位置</strong>」是压缩存储公式的万能钥匙：<strong>对称、三角、三对角的公式全部由此生成</strong>——面试或考试现场推一遍，比背公式更稳，也顺带检验了下标起点（从 0 还是 1）是否配套。</span>

**辨析｜易错点：公式与下标起点「绑定」，别混用。** 对称矩阵的 $k = i(i-1)/2 + (j-1)$ 假设下标从 1 起；若代码里数组下标从 0 起，公式要整体平移成 $k = i(i+1)/2 + j$（$i \ge j$）。「先想清楚第 $i$ 行前面有几行、每行几个」，再写公式，起点怎么变都能推对。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 对称矩阵 | $A[i][j] = A[j][i]$ |
| 三角矩阵 | 一半恒为零，加常数单元存储 |
| 三对角矩阵 | 非零仅在 $|i-j| \le 1$ |
| 下标映射公式 | 逻辑 $(i,j)$ ↔ 物理 $k$ |
| 带状矩阵 | 非零限在有限条斜带内 |
| 稀疏矩阵 | 非零少但无规律，需三元组表 |

**延伸对照**：压缩存储的「公式换空间」与哈希表的「函数换定位」同源——都试图用「可计算的函数」替代「显式的存储结构」，区别只在函数是从下标推位置、还是从键推位置。

**辨析｜易错点：压缩存储的公式「先数前面的行、再数本行内的位置」是唯一心法。** 对称、三角、三对角的公式全部由此生成——现场推一遍，比背公式可靠，还能顺带检验下标起点（从 0 还是 1）。

**一句话**：压缩存储 = 只存不重复、非零的部分 + 一套下标映射公式——用乘法换空间。

## 7 小结

- 压缩存储 = 只存「不重复/非零」部分 + 一套**下标映射公式**。
- 对称矩阵：存下三角 $n(n+1)/2$ 个，$k = i(i-1)/2 + (j-1)$（下标从 1 起）。
- 三角矩阵：存半三角 + 一个常数单元，零区返回常数。
- 三对角矩阵：存三条对角线约 $3n-2$ 个，$k = 2i + j - 3$。
- 压缩公式必须与**下标起点**配套（从 0 起还是从 1 起）。
- 特殊矩阵用公式定位；分布无规律的非零元要用**稀疏矩阵**的三元组表。
