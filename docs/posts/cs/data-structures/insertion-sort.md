## 为什么插入排序是「最直觉」的排序

打牌时我们天然用插入排序：手里牌已有序，新摸一张，找到位置插进去。**直接插入排序（straight insertion sort）**把这个直觉程序化：把序列分成「已排序前缀」与「未排序后缀」，每次把后缀第一个元素插到前缀的正确位置。它简单、稳定、对「近乎有序」的数据极快（$O(n)$），是许多高级排序（希尔、Timsort）的底层零件。**折半插入排序**则把「找插入位置」从顺序比较换成折半查找——比较次数降一半，但移动次数不变。

## 1 直接插入排序的算法

```c
void InsertSort(int a[], int n) {
    int i, j;
    for (i = 2; i <= n; i++) {          /* a[1..n]，a[0] 作哨兵 */
        a[0] = a[i];                    /* 待插元素暂存哨兵 */
        j = i - 1;
        while (a[0] < a[j]) {           /* 从后往前找插入位置 */
            a[j + 1] = a[j];            /* 后移腾位 */
            j--;
        }
        a[j + 1] = a[0];                /* 插入 */
    }
}
```

**重点：每一趟做两件事——「找位置」（比较）与「腾位」（移动）。** 待插元素暂存到 `a[0]` 哨兵，后移时不必每次都判断 `j >= 1`。<span class="marginnote">哨兵在插入排序里的妙用与顺序查找一致：`<strong>`a[0]` 存放待插值，后移循环遇到它自然停下，省掉「j 越界」判断。这个「哨兵 + 少一次判断」的微优化，在《算法和算法分析》里是常数优化的经典例题。</span>

## 2 公式解析：直接插入的复杂度

设 $n$ 个记录。三态复杂度：

$$
\begin{aligned}
T_{\text{最好}} &= O(n) \qquad \text{（序列已有序：每趟只比较 1 次、不移动）} \\
T_{\text{最坏}} &= O(n^2) \qquad \text{（逆序：第 } i \text{ 趟比较 } i \text{ 次、移动 } i \text{ 次）} \\
T_{\text{平均}} &= O(n^2) \qquad \text{（每趟约一半的比较与移动）}
\end{aligned}
$$

- **第一步，读最好 $O(n)$**：已有序时，每趟只做一次**比较**判断就跳过——$n-1$ 次比较、0 移动。
- **第二步，读最坏 $O(n^2)$**：逆序时第 $i$ 趟要比较 $i$ 次、移动 $i$ 次，累加 $\sum i = n(n-1)/2$。
- **第三步，读「对有序敏感」**：插入排序是「输入敏感」的——**数据越有序越快**。这个性质让它在「近乎有序」的场景（如 Timsort 检测到有序段）里大放异彩。<span class="marginnote">「输入敏感」是插入排序的招牌：<strong>越有序越快，最好 $O(n)$</strong>。与之对比，选择排序「输入不敏感」（无论有序与否都 $O(n^2)$）。判断一个算法「会不会占已有序性的便宜」，是选算法时的关键问题。</span>

## 3 稳定性与空间

**稳定性**：稳定。后移元素时不改变相等元素的相对顺序，插入位置在相等元素之后——等值元素保持原序。
**空间**：$O(1)$（只用一个哨兵 `a[0]`），**原地排序**。

**重点：直接插入是「稳定 + 原地 + 对有序敏感」三合一**——这三个性质让它成为高级排序的理想「底件」：$O(n\log n)$ 排序在小规模或近乎有序时，会切换到插入排序收尾（introsort、Timsort 都这么做）。<span class="marginnote">「插入排序当底件」是工业排序的共识：<strong>$n$ 小（< 16）或近乎有序时，插入排序的常数远小于快排递归</strong>。C++ `std::sort`、Python 的 Timsort 都在递归到底层时切到插入排序——<strong>高级算法负责大局面，插入负责收尾</strong>。</span>

## 4 折半插入排序

**折半插入排序**改进「找位置」这一步：前缀 $a[1..i-1]$ 是有序的，用**折半查找**定位插入点，比较次数从 $O(i)$ 降到 $O(\log i)$：

```c
void BInsertSort(int a[], int n) {
    int i, j, low, high, mid;
    for (i = 2; i <= n; i++) {
        a[0] = a[i];                          /* 暂存待插元素 */
        low = 1; high = i - 1;
        while (low <= high) {                 /* 折半找插入位置 */
            mid = (low + high) / 2;
            if (a[0] < a[mid]) high = mid - 1;
            else low = mid + 1;
        }
        for (j = i - 1; j >= low; j--)        /* 腾位：整体后移 */
            a[j + 1] = a[j];
        a[low] = a[0];                        /* 插入 */
    }
}
```

**辨析｜易错点：折半插入的「比较减半、移动不变」。** 找位置从 $O(i)$ 降到 $O(\log i)$，但**腾位仍要移动 $O(i)$ 个元素**——所以时间复杂度仍是 $O(n^2)$，只是**比较次数**少了。总代价由移动主导时，提速有限。<span class="marginnote">「优化了比较、没优化移动」是折半插入的局限：<strong>排序的代价是「比较 + 移动」，只减一项，另一项仍占主导</strong>。这也是为什么后续算法要同时攻击两项——希尔排序正是靠「大步移动」来压缩移动总量。</span>

## 5 公式解析：折半插入的复杂度

$$
T_{\text{折半插入}} = O(n^2), \qquad C_{\text{比较}} = O(n\log n), \qquad M_{\text{移动}} = O(n^2)
$$

- **第一步，读比较**：每趟折半 $O(\log i)$，总比较 $\sum \log i = O(n\log n)$——优于直接插入的 $O(n^2)$ 比较。
- **第二步，读移动**：移动次数与直接插入相同 $O(n^2)$——**这才是总代价的主导**。
- **第三步，读结论**：总时间仍 $O(n^2)$，常数略优于直接插入。<span class="marginnote">「折半插入给我们的启示」：<strong>当「移动」是瓶颈时，优化「比较」收效甚微</strong>。后续的希尔排序改「移动」、归并改「分治移动」、堆排序改「选择+交换」——<strong>每个突破都发生在「移动」或「组织方式」上，而不是比较上</strong>。</span>

**一个插入的算例。** 序列 `[3, 1, 4, 2]`（下标从 1 起，`a[0]` 哨兵）：

- $i=2$：`a[0]=1`，与 `a[1]=3` 比较，3 后移，插入 → `[1, 3, 4, 2]`；
- $i=3$：`a[0]=4`，与 3 比较，4 已比 3 大，原地插入 → 不动；
- $i=4$：`a[0]=2`，与 4 比较后移、与 3 比较后移、与 1 比较停，插入 → `[1, 2, 3, 4]`。

第 3 趟只做一次比较就跳过——这正是「有序时 $O(n)$」的来源：每个元素只需确认「已在前缀末尾」即可。<span class="marginnote">「$i=3$ 的这次几乎不做事」是插入排序输入敏感的缩影：<strong>已就位的元素只付一次比较的代价</strong>。<strong>数据越有序，这样的「便宜趟」越多</strong>——这就是它「吃有序红利」的机制。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 已排序前缀 | 前 $i-1$ 个已有序的元素 |
| 哨兵 a[0] | 暂存待插值，省越界判断 |
| 后移腾位 | 比待插值大的元素依次后移 |
| 折半插入 | 折半找位置，比较降半、移动不变 |
| 输入敏感 | 数据越有序越快 |

## 6 小结

- 直接插入：已排序前缀 + 逐元素插入，哨兵 `a[0]` 暂存待插值。
- 复杂度：最好 $O(n)$（有序）、最坏/平均 $O(n^2)$；稳定、原地、输入敏感。
- 直接插入是「对有序敏感」的算法——高级排序的收尾底件。
- 折半插入：折半找位置，比较 $O(n\log n)$，但移动仍 $O(n^2)$，总时间 $O(n^2)$。
- 启示：优化「比较」不如优化「移动」；希尔排序走上后者。
