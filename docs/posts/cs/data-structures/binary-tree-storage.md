## 为什么二叉树存储值得单独一节

二叉树有两种性格截然不同的存法：**顺序存储**用数组、靠完全二叉树的编号性质定位；**链式存储**用指针、每个结点带左右孩子指针。选错存法，代价立现——用数组存一棵「歪脖子树」，空间浪费一半以上；用链表存一棵完全二叉树，又放弃了数组的紧凑。理解两者的适用边界，是设计二叉树算法（堆、二叉排序树、线索树）的前提。本节把两种存储结构讲透，并给出「三叉链表」这个为「找双亲」而生的变体。

## 1 顺序存储：数组装完全二叉树

完全二叉树的「连续编号」性质让它可以顺序存储：**编号 $i$ 的结点存于数组下标 $i$**（下标从 1 起，0 号留空），其双亲、左右孩子的编号由性质 5 直接算出：

$$
\text{parent}(i) = \lfloor i/2 \rfloor, \qquad \text{left}(i) = 2i, \qquad \text{right}(i) = 2i+1
$$

例如一棵 7 个结点的完全二叉树：

```
            1:A
          /     \
       2:B        3:C
      /   \      /   \
   4:D    5:E  6:F    7:G

顺序存储（下标从 1 起，0 号留空）：
下标  0  1  2  3  4  5  6  7
数据  -  A  B  C  D  E  F  G
```

**重点：顺序存储只对完全二叉树「不浪费」。** 对普通二叉树，中间有空位，编号不连续，数组里就会出现空洞——深度为 $k$ 的斜二叉树要开 $2^k - 1$ 个单元，实际只装 $k$ 个结点，浪费率接近 100%。<span class="marginnote">判断该不该用顺序存储，就看「结点编号是否连续」：完全二叉树连续、适合数组；普通二叉树稀疏、适合链表。这正是《特殊矩阵压缩》里「<strong>规律 → 公式定位</strong>」的思路——完全二叉树的规律就是「编号公式」。</span>

## 2 链式存储：二叉链表

二叉链表每个结点三个域：数据 + 左孩子指针 + 右孩子指针。

```c
typedef struct BiTNode {
    ElemType data;              /* 数据域 */
    struct BiTNode *lchild;     /* 左孩子指针 */
    struct BiTNode *rchild;     /* 右孩子指针 */
} BiTNode, *BiTree;
```

**重点：$n$ 个结点的二叉链表有 $n+1$ 个空指针域。** 为什么？总指针域 $2n$ 个，真正被用上的（指向非空孩子）恰有 $n-1$ 个（除根外每个结点被一个指针指到），故空指针域 $= 2n - (n-1) = n+1$。这一半左右的「空指针」不是浪费——下一节**线索二叉树**正是要把它们利用起来。<span class="marginnote">「$n+1$ 个空指针域」这个数会在三处出现：二叉链表的空指针数、<strong>线索二叉树的线索数</strong>、以及二叉树叶子与度为 2 结点关系的验证。记住它，线索化时你就知道「到底有多少线索可用」。</span>

## 3 三叉链表：为「找双亲」而生的变体

很多算法需要从子结点**回到双亲**（如查找结点的祖先、某些回溯）。二叉链表只能从根往下走，没有向上的指针。**三叉链表**在每个结点增加一个 `parent`（双亲）指针：

```c
typedef struct TriTNode {
    ElemType data;              /* 数据域 */
    struct TriTNode *lchild;    /* 左孩子指针 */
    struct TriTNode *rchild;    /* 右孩子指针 */
    struct TriTNode *parent;    /* 双亲指针 */
} TriTNode, *TriTree;
```

代价是每个结点多一个指针域（空间 $+50\%$），换来从任意结点 $O(1)$ 找到双亲。**三叉链表是「以空间换向上导航」的典型**——在需要「自底向上」遍历的场景（如某些树形 DP、区间树）中不可替代。

## 4 公式解析：空指针域为什么是 $n+1$

二叉链表空指针域的个数可以严格推出：

$$
\text{空指针数} = 2n - (n - 1) = n + 1
$$

- **第一步，数总指针域**：$n$ 个结点，每个有两个指针域，共 $2n$ 个。
- **第二步，数被占用的指针域**：非空指针恰指向一个孩子；除根外每个结点恰好被一个非空指针指向，故占用 $n-1$ 个。
- **第三步，相减**：$2n - (n-1) = n + 1$。这个结论与树的形态无关——任何二叉树都成立。<span class="marginnote">用「每个结点的入度都是 1（除根）」来理解更直观：<strong>孩子指针总数 = 结点总数 - 1</strong>。这条「入度守恒」在证明树的性质时反复使用——性质 3 的证明也用了同一思想。</span>

## 5 核心对比表：顺序 vs 链式存储二叉树

两种存储并排，各自的代价一目了然：

| 维度 | 顺序存储 | 二叉链表 | 三叉链表 |
| --- | --- | --- | --- |
| 空间 | 完全二叉树紧凑，普通树浪费大 | 每结点 2 指针，空指针 $n+1$ 个 | 每结点 3 指针 |
| 随机访问 | $O(1)$（按下标） | $O(\text{深度})$（沿链） | $O(\text{深度})$ |
| 找双亲 | 由编号公式 $O(1)$ | 需遍历 | $O(1)$ |
| 插入删除 | 困难（定长） | 灵活 | 灵活 |
| 适用 | 堆、完全二叉树 | 一般二叉树 | 需自底向上访问 |

三条规律：第一，**顺序存储适合「形态已知、静态、完全」的树**——二叉堆、某些外部排序的败者树；第二，**二叉链表是默认选择**——空间适中、操作灵活，绝大多数二叉树算法都基于它；第三，**三叉链表是「向上导航」的特需品**——需要 $O(1)$ 找双亲时才值得多付一个指针域。

## 6 小结

- 顺序存储：数组按编号装结点，双亲孩子由公式定位；**只对完全二叉树不浪费**。
- 二叉链表：每个结点带左右孩子指针，空间适中，$n$ 个结点有 **$n+1$ 个空指针域**。
- 三叉链表：加 `parent` 指针，$O(1)$ 找双亲，空间 $+50\%$。
- 空指针数 $= 2n - (n-1) = n+1$，任何形态都成立。
- 选型：静态完全 → 顺序；一般二叉树 → 二叉链表；需向上导航 → 三叉链表。
- 「$n+1$ 个空指针」是线索二叉树的基础。
