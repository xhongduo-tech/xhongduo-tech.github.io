## 为什么要在块的「两端」做标记

上一节的空闲表靠「前驱后继」找相邻块——可回收时要知道「物理上相邻的那块是不是空闲、多大」，得从空闲表里查。**边界标识法（boundary tag method）**给出一个更直接的方案：**在每一块（不管空闲还是占用）的头与尾都存一个「边界标记」**，记录块的标志（空闲/占用）、大小，以及**指向前后相邻块的指针**。于是回收时，只需看「物理前邻块」与「物理后邻块」的标记，就能 $O(1)$ 判断能否合并——不需要在全表里找邻居。它是「用冗余信息换局部操作」的经典，也是现代 `glibc malloc` 合并逻辑的直系祖先。

## 1 边界标识的块结构

每个存储块（无论空闲或占用）都带两个「边界标识」，位于块的首尾：

```c
/* 块首（位于块起始处） */
typedef struct Word {
    HeaderTag tag;        /* 空闲(0) / 占用(1) */
    int size;             /* 本块大小（含首尾标识） */
    struct Word *llink;   /* 指向前一空闲块（仅空闲块有链指针） */
    struct Word *rlink;   /* 指向后一空闲块 */
} Header;

/* 块尾（位于块末尾） */
typedef struct { HeaderTag tag; } Footer;   /* 仅存标志位，与块首呼应 */
```

**重点：块尾只需一个 `tag` 标志。** 因为回收时要知道「物理后邻块」是不是空闲——查它的尾部标志即可；若空闲，还需知道它的大小与前一空闲块指针，这些信息从它的**块首**取（块首在物理上紧随本块尾部，可由大小算出地址）。<span class="marginnote">「块尾只存标志、块首存全部信息」的精妙之处：<strong>尾部标志让「向前看邻居」变 $O(1)$，块首则保证「空闲块的完整信息只存一份」</strong>。地址 = 前块首地址 + 前块大小，物理布局自然衔接。</span>

## 2 分配：基于空闲链的 FF

边界标识法通常把空闲块用**双向链表**串起来（`llink`/`rlink`），并配首尾哨兵。分配时用**首次适应**：沿空闲链找第一个大小够的块：

- 若 `size == n`：整块摘下，更新块首/块尾标志为「占用」；
- 若 `size > n`：切块——前 $n$ 字节给请求，剩余 `size - n` 字节仍空闲（重写其首尾标识与大小）。

```c
Block *BoundaryFF(Block *head, int n) {
    Block *p = head->rlink;                     /* 沿空闲链找 */
    while (p != head && p->size < n) p = p->rlink;
    if (p == head) return NULL;                 /* 无足够空闲块 */
    if (p->size == n) {
        RemoveFromFreeList(p);                  /* 摘链 */
        p->tag = ALLOCATED;  (p 尾) ->tag = ALLOCATED;
        return p;
    }
    /* 切块：p 的剩余部分留作空闲 */
    Block *used = p;  used->size = n;  used->tag = ALLOCATED;
    /* 更新剩余块 p' 的块首（紧跟 used 之后）与块尾 */
    ...
    return used;
}
```

**重点：切块后要「修两个块的边界标记」**——被分出的块标记为占用，剩余块更新大小与标志。边界标识法的一切操作都在「改写首尾标志」上进行。<span class="marginnote">「<strong>改标志代替移数据</strong>」是边界标识法的灵魂：分配不搬任何数据，只改标志与链指针。这与链表删除「摘链即删除」、哈希「标记删除」是同一思想——<strong>用元信息管理，而非搬运内容</strong>。</span>

## 3 回收：$O(1)$ 判断相邻合并

回收一块已占用的块 `r` 时，边界标识法的优势全面爆发——**直接看物理前后邻居的尾/首标志**：

1. **前邻块 `r_prev`**（在 `r` 之前，地址 = `r` 的地址减去它的块首大小）：查**前邻的块尾标志**，若为空闲则与前邻合并；
2. **后邻块 `r_next`**（紧跟 `r` 之后，地址 = `r->addr + r->size`）：查**后邻的块首标志**，若为空闲则与后邻合并；
3. 合并后重写合并块的首、尾标志与大小；若前后都空闲，三块并一块。

**辨析｜易错点：块尾标志是「物理向后看」的关键。** 若前邻空闲，要拿到它的**完整空闲信息**（大小、链指针），须从前邻的**块首**取——而前邻块首地址 = `r` 地址 - 前邻大小。前邻大小又存在哪？就在前邻的块首里，可从 `r` 的块首的 `llink` 等找到，或由边界布局推算。<span class="marginnote">「<strong>由物理位置推地址、由地址读标志</strong>」是边界标识法的操作范式——它不依赖「空闲表里查邻居」，只依赖「内存布局的算术」。这正是一个「<strong>用空间冗余换时间复杂度</strong>」的教科书案例：每块多存一个尾标志，换回 $O(1)$ 的合并判断。</span>

## 4 公式解析：边界标识法的代价

设空闲块个数为 $f$：

$$
\begin{aligned}
T_{\text{分配}} &= O(f) \quad \text{（沿空闲链 FF 扫描）} \\
T_{\text{回收}} &= O(1) \quad \text{（只看物理邻块的边界标记）}
\end{aligned}
$$

- **第一步，读分配**：沿空闲链找合适块，最坏 $O(f)$——与普通空闲表相同。
- **第二步，读回收**：无论前邻是否空闲、是否合并，都只需读一两个标志 + 改指针——常数时间，**与空闲块总数无关**。
- **第三步，读「不对称」的启示**：回收比分配便宜，因为合并所需信息**已预先存在块的边界上**——这是「预置信息」策略的胜利。<span class="marginnote">「回收 $O(1)$、分配 $O(f)$」的不对称，让边界标识法特别适合「<strong>分配少、释放频繁</strong>」的工作负载（如动态数据结构反复申请/释放结点）。<strong>把最频繁的操作做成 $O(1)$，是结构设计的普遍目标</strong>。</span>

## 5 边界标识法的现代回响

- **glibc malloc**：空闲块的 chunk 结构存 `prev_size` 与 `size`（含标志位），正是边界标识法的工程形态；free 时向后合并、向前合并，靠的就是相邻 chunk 的边界标志。
- **碎片与内存安全**：边界标识还能用于**越界检测**——块尾标志被改写说明发生了 buffer overflow，这是很多堆检查器（如 `-fsanitize`）的原理雏形。

**重点：边界标识法是「教科书算法直接长成生产代码」的罕见例子。** 理解它的首尾标志与相邻合并，等于理解了一半 glibc 的 free() 逻辑。<span class="marginnote">从「块尾标志」到「越界检测」只有一步之遥：<strong>数据结构的冗余信息，常被安全机制捡去复用</strong>。堆检查器、内存池、竞技场（arena）分配器，都在这套「边界 + 标志」的地基上盖楼。</span>

## 6 小结

- 边界标识法：每块**首尾都存边界标志**（空闲/占用、大小），空闲块串成双向链。
- 分配 = 沿空闲链 FF + 切块 + 改写首尾标志，$O(f)$。
- 回收 = 看物理前后邻块的标志，$O(1)$ 判断合并。
- 合并只依赖「地址算术 + 标志读取」，不查全表。
- 以「每块一个尾标志」的空间冗余，换回收的常数时间。
- 现代回响：glibc malloc 的 chunk 合并、越界检测。
