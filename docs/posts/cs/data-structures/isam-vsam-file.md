## 为什么索引也要分层

单级索引在记录数巨大时，索引表本身大到放不进内存——折半查找索引也要多次磁盘 I/O。**ISAM（Indexed Sequential Access Method）**给出「索引的索引」：**多级索引**，像一本书的「章-节-段」目录，先查总目录、再查分目录、最后定位记录。它结合「索引查找」与「顺序扫描」：既能按关键字随机查（走索引），又能按物理顺序整表扫。**VSAM（Virtual Storage Access Method）**则是它的现代改良：用「B+ 树」替代固定多级索引，让索引结构动态平衡、可伸缩。ISAM/VSAM 是数据库「B 树索引」之前的经典文件组织，也是理解 B+树为何能统治数据库的桥梁。

## 1 ISAM：多级索引 + 顺序数据

**ISAM 文件**由三部分构成：

1. **多级索引**：柱面索引 → 磁道索引 → （数据磁道）——一级索引指向二级索引，像书的「目录的目录」；
2. **数据区**：记录按关键字顺序存放，分块（磁道）排列；
3. **溢出区**：插入的记录放不下时，链到溢出区。

查找路径：**先查柱面索引 → 得磁道索引 → 得数据磁道 → 块内/磁道内顺序找**——多级折半定位，最后一段顺序扫描。

**重点：ISAM 的索引是「静态多级」的——结构固定，记录移动（插入溢出）只进溢出区。** 它快在查找（多级索引折半），痛在溢出区链越长越慢。<span class="marginnote">「<strong>静态多级索引 + 溢出链</strong>」是 ISAM 的性格：<strong>查询路径固定、实现简单，但长期插入后溢出区膨胀，性能劣化</strong>。它适合「建好就不怎么变」的静态数据集（如老式银行账目、编译后的查找表）。</span>

## 2 ISAM 的查找与插入

- **查找**：沿「柱面索引 → 磁道索引 → 磁道」三级折半定位，磁道内顺序找；
- **插入**：先定位记录应在的磁道；磁道有空位则插；满则插入溢出区，用链指针从原位置指向它；
- **删除**：标记删除即可，空间不立即回收。

**辨析｜易错点：溢出区是 ISAM 的「阿喀琉斯之踵」。** 插入频繁时，溢出链越来越长，查找要沿链多走几步——性能随「修改历史」劣化，而不是随「记录数」劣化。**ISAM 适合「多查少改」，不适合「频繁插入」。**<span class="marginnote">「溢出区劣化」是「静态结构 + 动态操作」矛盾的必然：<strong>静态索引设计时假设数据固定，动态插入必然破坏它</strong>。这引出了 VSAM 的改进思路——<strong>让索引结构本身可动态调整，而不是靠溢出区兜底</strong>。</span>

## 3 VSAM：B+ 树的文件形态

**VSAM 文件**用 **B+ 树**作为索引结构，替代 ISAM 的固定多级索引：

- **索引集（index set）**：B+树的内部结点——分隔键，动态分裂合并；
- **顺序集（sequence set）**：B+树的叶子——记录数据，叶子间用指针串成有序链；
- **溢出处理**：B+树的叶子分裂天然处理插入，无需独立溢出区。

**重点：VSAM = B+树 = 「动态多级索引 + 叶子顺序链」。** 它把 ISAM 的两大问题同时解决：索引结构动态平衡（B+树分裂/合并），叶子链保持顺序扫描能力。<span class="marginnote">「<strong>VSAM 就是 B+树</strong>」是本节最简洁的结论：<strong>索引集 = B+树内部结点，顺序集 = B+树叶子</strong>。<strong>ISAM 的「固定多级」在 VSAM 里变成「动态平衡」</strong>——这就是 B 树篇（§9.6）与文件组织的交汇点。</span>

## 4 公式解析：ISAM/VSAM 的查找代价

设记录 $n$ 条、数据分 $b$ 块，两级索引（柱面 + 磁道），块容量 $c$：

$$
T_{\text{ISAM 查找}} = O(\log b) \ \text{索引访问} + O(1) \ \text{数据块访问} + O(\text{溢出链长度})
$$

$$
T_{\text{VSAM 查找}} = O(\log_{m} n) \quad \text{（B+树高度，$m$ 为路数）}
$$

- **第一步，读 ISAM**：多级索引把「索引折半」摊到 $O(\log b)$ 次块访问；数据块 1 次；溢出链另计。
- **第二步，读 VSAM**：B+树高度 $\log_m n$——$n=10^9$、$m=200$ 时约 4 层，4 次 I/O。
- **第三步，读「为什么 VSAM 胜」**：ISAM 的溢出区让代价随修改劣化；VSAM 的 B+树恒定 $O(\log_m n)$，且 $m$ 大时树极矮。<span class="marginnote">「VSAM 用 B+树把 I/O 钉死在 $O(\log_m n)$」是它的历史贡献：<strong>从 ISAM 的「静态 + 溢出」到 VSAM 的「动态 + 平衡」，文件索引完成了从「工程凑合」到「理论优雅」的跃迁</strong>。今天我们数据库里的 InnoDB，正是 VSAM 这条线的直系后裔。</span>

## 5 核心对比表：ISAM vs VSAM

| 维度 | ISAM | VSAM |
| --- | --- | --- |
| 索引结构 | 固定多级索引 | B+树（动态平衡） |
| 插入 | 溢出区 + 链 | 叶子分裂 |
| 性能随修改 | 劣化（溢出链长） | 恒定 $O(\log_m n)$ |
| 顺序扫描 | 支持（数据磁道顺序） | 支持（叶子链） |
| 复杂度 | 简单 | 较复杂 |
| 历史地位 | 经典 | 现代数据库索引前身 |

**重点：ISAM → VSAM 的演化，就是「索引从静态到动态」的完整故事**——而 VSAM 的 B+树，正是《B-树和B+树》与《B+树与数据库索引》之间的关键桥梁。现代 MySQL InnoDB 的主键索引，就是「VSAM 思想的 B+树落地」。<span class="marginnote">「<strong>静态 vs 动态</strong>」这个母题再次出现：<strong>静态结构（数组、ISAM、固定索引）省事但怕变化；动态结构（链表、B+树）灵活但有维护成本</strong>。文件索引的演化，是整个数据结构「静态 → 动态」主线的缩影。</span>

## 6 小结

- ISAM：多级静态索引 + 顺序数据 + 溢出区。
- ISAM 查找：柱面索引 → 磁道索引 → 数据磁道 → 顺序找。
- ISAM 的劣化：频繁插入让溢出链变长、查询变慢——适合「多查少改」。
- VSAM：用 B+树做索引，索引集 + 顺序集（叶子链）。
- VSAM 查找恒定 $O(\log_m n)$，插入靠叶子分裂、无需溢出区。
- ISAM → VSAM 是「索引从静态到动态」的演化，VSAM 是现代数据库索引的前身。
