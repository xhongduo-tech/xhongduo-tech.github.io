## 为什么稀疏矩阵要用三元组

上一节的特殊矩阵靠「规律」压缩。可现实中大量矩阵**没有规律**：一个 $1000 \times 1000$ 的矩阵可能只有几百个非零元，散布各处。存全矩阵是 10⁶ 个单元，实际信息只有几百条。**稀疏矩阵（sparse matrix）**的压缩思路是：不按「位置」存，而按「有哪些非零元」存——每个非零元记作一个**三元组（行, 列, 值）**，全体三元组按行序（行号小的在前，同行按列号小的在前）排成一张表。这样存储量从 $O(n^2)$ 降到 $O(\text{非零元个数})$。本节实现它的顺序存储（三元组顺序表），并以**转置**为例展示「按行序的三元组表」如何高效变换。

## 1 三元组顺序表的结构

稀疏矩阵 $M$ 用一个三元组表 `T` 存所有非零元，再记录矩阵的行数、列数与非零元个数：

```c
#define MAXSIZE 12500            /* 三元组表的最大长度 */
typedef struct {
    int i, j;                    /* 非零元的行下标、列下标 */
    ElemType e;                  /* 非零元的值 */
} Triple;

typedef struct {
    Triple data[MAXSIZE + 1];    /* 三元组表，data[0] 未用 */
    int mu, nu, tu;              /* 矩阵行数、列数、非零元个数 */
} TSMatrix;
```

**重点：`T` 中的三元组按「行优先」有序——行号小的在前，同行列号小的在前。** 这个有序性不是摆设，它让「按行扫描」类运算（如加法、乘法、转置）可以线性完成。<span class="marginnote">三元组表与第二篇《一元多项式的表示及相加》的序偶表同构：多项式是「（指数, 系数）」的有序表，稀疏矩阵是「（行, 列, 值）」的有序表。两者都是「<strong>只存稀疏信息 + 保持有序</strong>」的同一策略。</span>

## 2 简单转置：按列扫描、逐行搬运

**转置（transpose）**：把 $M$ 的行列互换，$M[i][j] \to M^T[j][i]$。若 $M$ 的三元组按行有序，则 $M^T$ 也按行有序的要求，等价于「$M$ 中**按列**从小到大依次取出三元组，交换 i、j 后追加」。最简单的做法是三层循环：

```c
/* 简单转置：按列扫描，每列扫一遍整个三元组表 */
Status TransposeSMatrix(TSMatrix M, TSMatrix &T) {
    T.mu = M.nu;  T.nu = M.mu;  T.tu = M.tu;
    if (T.tu == 0) return OK;
    int q = 1;                                   /* T 的写入游标 */
    for (int col = 1; col <= M.nu; col++)        /* 按 M 的列（T 的行）扫描 */
        for (int p = 1; p <= M.tu; p++)
            if (M.data[p].j == col) {            /* 该三元组属于本列 */
                T.data[q].i = M.data[p].j;       /* 行、列互换 */
                T.data[q].j = M.data[p].i;
                T.data[q].e = M.data[p].e;
                q++;
            }
    return OK;
}
```

复杂度为 $O(\text{nu} \times \text{tu})$——每列要扫一遍整个三元组表。当非零元多、列数多时，这个双重扫描很浪费。

## 3 公式解析：快速转置的核心——每列起始位置

**快速转置**把上面 $O(nu \times tu)$ 降到 $O(nu + tu)$。它的诀窍是**预知每一列在结果表中的起始位置**。

设 $M$ 的列数为 $n$，先扫一遍统计出**每列的非零元个数** $\text{num}[col]$，再递推算出**每列第一个三元组在转置结果表 $T$ 中的位置** $\text{cpot}[col]$：

$$
\text{cpot}[1] = 1, \qquad \text{cpot}[col] = \text{cpot}[col-1] + \text{num}[col-1]
$$

- **第一步，读递推式的含义**：第 $col$ 列的第一个元素，必然紧跟在第 $col-1$ 列的全部元素之后——所以在第 $col-1$ 列的起点上，加上第 $col-1$ 列的元素个数。
- **第二步，读懂「按列填表」**：扫一遍 $M$ 的三元组，遇到第 $col$ 列的，就放到 `cpot[col]` 处，然后 `cpot[col]++`——下一个同列元素自动落在后面。
- **第三步，复杂度**：统计列数 $O(nu)$，算起点 $O(nu)$，填表 $O(tu)$，合计 $O(nu + tu)$，线性。相比简单转置的 $O(nu \cdot tu)$，当 $tu$ 大时差距悬殊。<span class="marginnote">快速转置的思想是「<strong>先统计、再定位</strong>」——一次扫描统计分布，二次扫描按分布直接落位。这个「两趟法」是计数排序、桶排序、基数排序的同一内核，在《内部排序·基数排序》里会再次相遇。</span>

## 4 快速转置的代码

```c
/* 快速转置：先统计每列个数 num[]，再递推起点 cpot[]，一趟填表 */
Status FastTransposeSMatrix(TSMatrix M, TSMatrix &T) {
    T.mu = M.nu;  T.nu = M.mu;  T.tu = M.tu;
    if (T.tu == 0) return OK;
    int num[M.nu + 1], cpot[M.nu + 1];
    for (int col = 1; col <= M.nu; col++) num[col] = 0;
    for (int p = 1; p <= M.tu; p++)  num[M.data[p].j]++;      /* 统计每列个数 */
    cpot[1] = 1;
    for (int col = 2; col <= M.nu; col++)                      /* 递推每列起点 */
        cpot[col] = cpot[col - 1] + num[col - 1];
    for (int p = 1; p <= M.tu; p++) {
        int col = M.data[p].j;
        int q = cpot[col];                                     /* 落点：该列当前起点 */
        T.data[q].i = M.data[p].j;                             /* 行、列互换 */
        T.data[q].j = M.data[p].i;
        T.data[q].e = M.data[p].e;
        cpot[col]++;                                           /* 起点后移，同列元素自动落在后面 */
    }
    return OK;
}
```

**重点：`cpot[col]++` 让「下一个同列元素」自动进入下一格**——这是把「顺序填表」与「起点递推」结合的关键一行。注意 `num`、`cpot` 数组的 1 到 `nu` 下标对应矩阵的列号。

**辨析｜易错点：为什么一定要先统计再转置？** 因为结果表要求「按行有序」——而 $M$ 的「列」正是 $T$ 的「行」。若不知道每列有多少元素，就无法预知每列元素在结果表中的落点，只能像简单转置那样反复扫描。<span class="marginnote">「<strong>输出有序 ⇒ 需要预知每组的落点 ⇒ 先统计</strong>」这条因果链，是很多「看似魔法」的线性算法的真正来源。理解这条链，比记住 $\text{cpot}$ 递推公式更有迁移价值。</span>

## 5 从转置到更广的稀疏矩阵运算

转置只是热身，稀疏矩阵的**加法**与**乘法**同样基于三元组表：

**加法**：两个按行有序的表做一趟**归并**（同下标相加、异下标保留），正是第二篇多项式相加的推广——代价 $O(tu_1 + tu_2)$。
**乘法**：矩阵乘法 $C = A \times B$ 的三元组实现，需要在 $B$ 上「按行定位」非零元，常配合「每行起始位置」的辅助数组（$rpos$），把一个元素乘一整行的操作组织成可控的累加。

这些运算的共同点：**把「稀疏性」转化为「只碰非零元」的时间节省**。三元组顺序表在非零元规模可控时高效；但若运算中需要频繁按「列」访问（如转置的逆运算、乘法按列累加），顺序表就要反复扫描——这引出了下一节的**十字链表**。<span class="marginnote">三元组顺序表的短板是「<strong>按列访问要全表扫描</strong>」。十字链表用「行链表 + 列链表」双链，把按行、按列访问都变成 $O(1)$ 起点——这就是下一节的主角，也是稀疏矩阵运算进入「动态增删」时代的关键。</span>

## 6 小结

- 稀疏矩阵 = 只存**非零元三元组**（行, 列, 值），按行序排列成表。
- 三元组表 `T` + 矩阵规模（$mu$、$nu$、$tu$）；有序性让线性运算成为可能。
- 简单转置按列扫描，$O(nu \times tu)$。
- **快速转置**：先统计每列元素个数 `num[]`，递推起点 `cpot[]`，一趟填表，$O(nu + tu)$。
- 「先统计、再落位」的两趟法，是计数排序等线性排序的共同内核。
- 稀疏矩阵加法是多项式相加的推广；按列访问频繁时应改用十字链表。
