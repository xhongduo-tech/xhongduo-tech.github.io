## 为什么优先队列是「算法百搭」

上一节我们把堆的两个原语打磨透了。本节看它的实战价值：**优先队列（priority queue）**在算法里的出场频率，仅次于数组与哈希。三个经典应用——**Top K**（海量数据取最大 K 个）、**合并 K 个有序链表**、以及**动态取极值**（Dijkstra、Prim、任务调度）——全部建立在同一个能力上：「**动态维护一组数，随时取最大/最小，插入与取顶都 $O(\log n)$**」。本节用这三个例子，示范「识别出『需要动态取极值』→ 上优先队列」的思维模式。

## 1 应用一：Top K —— 用 K 个元素的小堆

**问题**：$n$ 个元素中取最大的 K 个（$K \ll n$），$n$ 可能大到放不进内存。

**思路**：维护一个**大小为 K 的小根堆**，堆顶是当前「第 K 大的候选」：

1. 前 K 个元素直接入堆；
2. 对后续每个元素：若大于堆顶，则**替换堆顶并下沉**（淘汰最小的候选）；
3. 结束后堆里就是最大的 K 个。

```c
for (x : 全部元素) {
    if (heap.size() < K) push(heap, x);
    else if (x > heap.top()) {          /* 比第 K 大还大，值得入选 */
        pop(heap);
        push(heap, x);
    }
}
```

**公式解析：Top K 的复杂度**

$$
T_{\text{Top K}} = O(n \log K)
$$

- **第一步，读「堆只装 K 个」**：堆大小恒为 K，每次插入/替换 $O(\log K)$。
- **第二步，读「与排序对比」**：全排序 $O(n\log n)$；Top K 只需 $O(n\log K)$——**K 远小于 n 时优势巨大**。
- **第三步，读「内存友好」**：堆只占 $O(K)$ 内存，海量数据**流式处理**（边读边筛），无需全部装入。<span class="marginnote">「<strong>大小为 K 的堆 = 在线筛 Top K</strong>」：<strong>堆顶是「入选线」，比线高的进、比线低的弃</strong>。这个「小根堆存最大 K 个」的用法极其经典——反向的「大根堆存最小 K 个」同理。<strong>「堆的大小 = 你要留几个」</strong>，一眼可记。</span>

## 2 应用二：合并 K 个有序链表

**问题**：$K$ 个**各自有序**的链表，合并成一个大有序链表。

**思路**：用一个小根堆装「K 个链表的当前头结点」：

1. 把 K 个头结点入堆；
2. 弹出堆顶（全局最小），接入结果链；
3. 该链表后移一个结点，新头结点入堆；
4. 直到堆空。

```c
ListNode *MergeKLists(vector<ListNode*> lists) {
    priority_queue<ListNode*, ..., 小根堆> pq;
    for (head : lists) if (head) pq.push(head);   /* K 个头入堆 */
    ListNode *dummy = new ListNode(0), *cur = dummy;
    while (!pq.empty()) {
        ListNode *node = pq.top(); pq.pop();
        cur->next = node; cur = cur->next;         /* 接最小 */
        if (node->next) pq.push(node->next);       /* 补上该链下一个 */
    }
    return dummy->next;
}
```

**公式解析：合并 K 个链表的复杂度**

$$
T = O(N \log K) \quad \text{（$N$ 为总结点数，每次取/插 $O(\log K)$）}
$$

- **第一步，读「堆永远装 K 个」**：堆里始终是最多 K 个「各链当前最小候选」。
- **第二步，读「为什么对」**：全局最小一定在「K 个链的当前头」中——堆顶即全局最小。
- **第三步，对比二路归并**：两两归并 $O(N\log K)$ 同阶，但**优先队列版实现更直接、且天然支持 K 路动态**。<span class="marginnote">「<strong>K 路归并 = 优先队列</strong>」是外部排序《多路平衡归并》的直接落地：<strong>败者树是「专用版」优先队列，这里用「通用版」堆</strong>。K 路归并、多路归并、合并 K 个排序流，本质都是「K 个候选 + 每次取最小 + 补新候选」——<strong>一个模板，无数场景</strong>。</span>

## 3 应用三：动态取极值 —— Dijkstra 与 Prim

Dijkstra（§7.6）与 Prim（§7.4）都需要「从未确定的顶点中取最小」：

- 朴素版每次扫全部候选，$O(n)$ 一趟；
- **堆优化版**：把候选的「当前值」放入小根堆，取最小 $O(\log n)$、更新 $O(\log n)$——总 $O((n+e)\log n)$。

**重点：优先队列是「图算法」与「调度算法」的通用电池**——凡「动态维护一组候选、反复取最优」的算法，堆都能直接插入。Dijkstra、Prim、A*、霍夫曼编码（取两个最小）、任务调度，全是它。<span class="marginnote">「<strong>看到『反复取最值』就想到堆</strong>」是算法直觉的一条快线：<strong>Dijkstra 取最短 dist、Prim 取最轻边、霍夫曼取两个最小权、Top K 取第 K 大</strong>——全是「动态集合 + 取极值」，全是堆。<strong>优先队列是这些算法的「时间银行」</strong>。</span>

## 4 公式解析：为什么「取极值」要 O(log n)

朴素「取最小」要 $O(n)$ 扫一遍；堆把「取最小」降到 $O(\log n)$，代价是「插入/更新」也要 $O(\log n)$：

$$
\text{朴素}:\quad T_{\text{取最小}} = O(n), \quad T_{\text{更新}} = O(1) \\
\text{堆}:\quad T_{\text{取最小}} = O(\log n), \quad T_{\text{更新}} = O(\log n)
$$

- **第一步，读「交易的实质」**：堆把「取最小」从 $O(n)$ 降到 $O(\log n)$，但「更新」从 $O(1)$ 涨到 $O(\log n)$——**用更新的小涨，换取最小的大跌**。
- **第二步，读「何时划算」**：若「取最小」次数远多于「更新」次数，堆大赚；反之朴素可能更好。
- **第三步，读「Dijkstra 的账」**：$n$ 次取最小 + $e$ 次更新——堆化后 $(n+e)\log n$ 完胜朴素 $n^2$（稀疏图）。<span class="marginnote">「<strong>交易的胜负看次数比</strong>」是优先队列选型的核心：<strong>取极值多、更新少 → 堆；取极值少、更新多 → 朴素数组</strong>。这个「操作次数比」的视角，能帮你决定任何「动态极值」场景要不要堆——<strong>不是堆永远好，而是「看账本」</strong>。</span>

## 5 优先队列应用的识别清单

遇到下面这些信号，优先队列就该出场：

- 「**Top K / 第 K 大/小**」——大小为 K 的堆；
- 「**K 个有序序列合并**」——K 个头的堆；
- 「**反复取最小/最大**」——Dijkstra、Prim、A*、霍夫曼；
- 「**动态维护有序集合的极值**」——滑动窗口、任务调度、事件模拟。

**重点：优先队列的核心识别词是「动态 + 极值」**——数据在变、又总要最值，堆就是答案。<span class="marginnote">「<strong>动态取极值 → 优先队列</strong>」是一条几乎万能的识别链：<strong>只要问题同时出现「元素会增删」与「每次要最大/最小」，优先队列就大概率是最优解</strong>。从 Top K 到调度器，从图算法到事件仿真，<strong>「堆」是那台无处不在的极值发动机</strong>。</span>

## 6 小结

- Top K：大小为 K 的小根堆，堆顶是入选线，$O(n\log K)$、流式省内存。
- 合并 K 个有序链表：K 个头入堆，弹出最小再补新头，$O(N\log K)$。
- Dijkstra/Prim 堆优化：取最小 $O(\log n)$，总 $O((n+e)\log n)$。
- 堆的账：取最小 $O(n)\to O(\log n)$、更新 $O(1)\to O(\log n)$——看次数比选型。
- 识别词：「动态 + 极值」→ 优先队列。
- 优先队列是图算法、调度、归并、Top K 的通用时间银行。
