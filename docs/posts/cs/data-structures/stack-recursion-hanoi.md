## 为什么从汉诺塔看递归

递归是程序设计中第一个「反直觉」的工具：函数调用自己，看起来像在兜圈子，却能干净地解决分而治之的问题。它的底层机制是什么？答案是**栈**。每一次函数调用，系统都会把「返回地址 + 局部变量」压入一张隐藏的调用栈；递归返回时，再从栈里弹出继续。汉诺塔（Tower of Hanoi）是理解这整套机制的最佳案例：问题自身呈现鲜明的递归结构——「把上面的 $n-1$ 个盘子搬走」，而这又是个规模更小的汉诺塔。本节以汉诺塔为载体，讲清递归与栈的等价关系。

## 1 递归的两个条件

一个递归过程要成立，必须同时满足两条：

- **递归出口（base case）**：存在一个不再递归、直接可解的情形，例如汉诺塔的「只有一个盘子」。
- **递归体（recursive case）**：把原问题化为规模更小、形式相同的子问题，且每次递归都向出口逼近。

**重点：没有出口的递归是死循环，出口太远则是栈溢出（stack overflow）**——因为每次递归都消耗一层调用栈。<span class="marginnote">递归深度受限的根本原因正在于此：调用栈的大小是有限的。深度 1 万层的递归可能把栈耗尽，而把递归改写成显式栈或循环，就能把「栈」搬到堆上，避开系统栈的限制——这是把递归改迭代的第一动力。</span>

## 2 汉诺塔问题的递归解

汉诺塔：三根柱子 $A,B,C$，$A$ 上有 $n$ 个大小递增的盘子，一次只能搬一个，大盘不能压小盘，目标是把全部盘子从 $A$ 移到 $C$。递归解就两句话：

```c
void hanoi(int n, char A, char B, char C) {
    /* 把 n 个盘子从 A 借助 B 移到 C */
    if (n == 1) {
        move(A, C);              /* 递归出口：直接搬这一个盘子 */
    } else {
        hanoi(n - 1, A, C, B);   /* 1. 上面 n-1 个盘子：A → B（借助 C） */
        move(A, C);              /* 2. 最大盘：A → C */
        hanoi(n - 1, B, A, C);   /* 3. n-1 个盘子：B → C（借助 A） */
    }
}
```

注意参数名的「换位」：递归调用里，柱子角色的互换不是魔法，而是「借助柱」与「目标柱」的轮换。读懂这条递归，要抓住一个不变式：**每次调用都保证「借助第三根柱子，把 $n$ 个盘子从第一根移到第二根」**。

## 3 公式解析：移动次数为什么是 $2^n-1$

设 $T(n)$ 为移动 $n$ 个盘子所需的次数。递归体的三步结构直接给出递推式：

$$
T(1) = 1, \qquad T(n) = 2\,T(n-1) + 1
$$

- **第一步，读递推式的来源**：搬 $n$ 个盘子 = 先搬 $n-1$ 个（$T(n-1)$）+ 搬最大盘 1 次（$+1$）+ 再搬 $n-1$ 个（$T(n-1)$）。
- **第二步，解这个递推**：反复代入 $T(n) = 2T(n-1)+1 = 2(2T(n-2)+1)+1 = \cdots$，得通项：

$$
T(n) = 2^n - 1
$$

- **第三步，体会指数爆炸**：$n=64$ 时 $T(64)=2^{64}-1 \approx 1.8\times 10^{19}$ 次。传说中梵天庙宇要移完 64 片金盘，以每秒一次的极限也要约 5800 亿年。**递归让程序极短，但复杂度是问题本身的**——优化程序救不了指数级的问题规模。<span class="marginnote">汉诺塔的 $2^n-1$ 与《数学分析》里的几何级数同源：$1+2+4+\cdots+2^{n-1}=2^n-1$。指数增长的三种典型面孔——<strong>子集、汉诺塔、二分搜索的补</strong>——在此已出现一个。</span>

## 4 递归与栈的等价：系统栈 vs 显式栈

每次递归调用发生时，系统做了三件事：

1. 把返回地址（调用点下一行）压栈；
2. 把参数（实参值）与局部变量压栈；
3. 跳转到函数体执行；返回时出栈恢复现场。

因此递归调用天然就是「后调用、先返回」——与栈的 LIFO 完全一致。<span class="marginnote">反过来看，任何递归都能改写成「显式栈 + 循环」：手动把一个「任务」压栈，循环里出栈执行。区别只在于：<strong>系统栈自动维护现场，显式栈把现场（参数、状态）交到你手里</strong>。树的先序非递归遍历、后续的深度优先搜索，都是这种改写的实战。</span>

**辨析｜易错点：递归不是「函数自己调用自己」这么简单。** 初学者常以为递归调用在内部「重演」整个函数，于是把问题想复杂。正确的心智模型是：**递归调用是「在栈上挂起当前任务，转而执行一个更小的任务」**。每一层调用都是独立的「帧」，互不干扰；返回时从栈里取出上一帧继续。画一张调用栈图，比空想「递归」二字有用得多。

## 5 从汉诺塔到更广的递归应用

汉诺塔暴露的「递归 = 分治 + 栈」模式，会反复出现在本书后面的章节：树的遍历（先序、中序、后序）是同一模式，快速排序与归并排序是「数组上的分治」，深度优先搜索是「图上的递归」。「栈与递归」这一节是理解它们的通用钥匙——每当遇到递归，先问三句话：出口在哪？如何缩小规模？系统栈在做什么？<span class="marginnote">到第六篇《遍历二叉树》时，你会看到三种遍历如何分别对应「先处理根 / 中间处理根 / 后处理根」；其非递归版本正是<strong>显式栈模拟系统栈</strong>。本节是那一切的伏笔。</span>

## 6 小结

- 递归的两条铁律：**有出口**、**每次递归向出口逼近**；缺一即死循环或栈溢出。
- 汉诺塔递归解：三句——搬 $n-1$ 个到辅助柱、搬最大盘、再搬 $n-1$ 个到目标柱。
- 移动次数 $T(n) = 2T(n-1)+1 = 2^n - 1$，指数增长，与问题规模强相关。
- 递归的底层是**系统调用栈**：压入返回地址与现场，后调用先返回。
- 任何递归都可改写为**显式栈 + 循环**，从而绕开系统栈深度限制。

在下一节，我们让栈直接上场干活——**表达式求值**。中缀表达式如何转后缀、两个栈如何协同完成四则运算，是栈作为「计算器核心」的经典应用。
