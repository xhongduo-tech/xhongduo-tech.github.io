## 为什么多路归并需要「败者树」

$k$ 路归并每选出一个最小元素，要从 $k$ 个当前元素里找最小——若直接扫描是 $O(k)$。当 $k$ 很大（如 32、128 路），$O(k)$ 的选择代价会主导整个归并。**败者树（loser tree）**把「$k$ 选 1」从 $O(k)$ 降到 $O(\log k)$：它是一棵特殊的锦标赛树——**叶子是 $k$ 个候选，内部结点记录「这一组的败者」（而非胜者）**。每次选出冠军后，只需沿冠军的路径重赛 $\log k$ 次。它是外部排序「多路平衡归并」的核心数据结构，也是「树形选择」思想在磁盘场景的实战。

## 1 为什么用败者树而不是胜者树

锦标赛树（胜者树）里，内部结点记录胜者；而**败者树**记录败者：

- 记录胜者：重赛时要从「新胜者的位置」向上与兄弟比较，途中还需「知道兄弟的胜者」——实现上要重建路径；
- 记录败者：新冠军只需沿路径与「记录在内部结点的败者」比较——**比较对象固定，路径天然可用**，且根上多放一个「总冠军」。

**重点：败者树让「替换冠军后重赛」只需沿一条路径比较 $\log k$ 次，且代码更规整。** 这是它在多路归并里胜过胜者树的原因。<span class="marginnote">「败者树 vs 胜者树」的差异看似细节，实则工程性很强：<strong>胜者树重赛要「知道兄弟子树当前的胜者」，路径信息不完整；败者树把「败者」固化在内部结点，新元素只需逐个与败者比</strong>。多路归并里元素持续替换，败者树的「路径直接可用」优势被放大。</span>

## 2 败者树的结构

$k$ 个有序段（路）各有一个当前元素，败者树组织如下：

```c
int ls[k];       /* ls[0] 是总冠军（最小值）；ls[1..k-1] 是内部结点，存败者下标 */
int b[k];        /* b[0..k-1] 是 k 路各自的当前元素（叶子对应的值） */
```

- **叶子（概念上）**：$k$ 路各自的当前元素 `b[0..k-1]`；
- **内部结点**：`ls[i]` 存「该子树中的败者」的**路号**；
- **根**：`ls[0]` 存**总冠军**（最小值所在的路号）。

调整（重赛）函数：从某一路 `s` 出发，沿路径与 `ls` 中的败者比较，胜者向上、败者落位：

```c
void Adjust(int s) {                    /* s 是新补充元素所在的路 */
    for (t = (s + k) / 2; t > 0; t /= 2) {   /* 沿路径到根 */
        if (b[s] > b[ls[t]]) {         /* 若 s 比结点记录的败者大 */
            swap(s, ls[t]);            /* s 成为新败者，原败者（较小）继续向上 */
        }
    }
    ls[0] = s;                          /* 根存总冠军 */
}
```

**重点：`Adjust` 就是「从叶子到根，逐层决出胜者」——每次比较 $O(1)$、路径 $O(\log k)$，替换一个元素的总代价 $O(\log k)$。**<span class="marginnote">「败者落位、胜者向上」让调整只需一行 `if (b[s] > b[ls[t]]) swap(s, ls[t])`——<strong>代码的简洁，来自「内部结点只存败者」的巧妙设计</strong>。数据结构选对了，算法自然短。这也是为什么败者树成为多路归并的事实标准。</span>

## 3 公式解析：败者树加速后的归并代价

设 $k$ 路归并、总记录 $n$、每块 $b$ 条：

$$
T_{\text{归并}} = O(n \log k) \quad \text{（每元素 $O(\log k)$ 选最小）} \quad \longrightarrow \quad \text{I/O} = O\left(\frac{n}{b} \log_k m\right)
$$

- **第一步，读「选最小」的加速**：直接扫描 $k$ 选 1 是 $O(k)$，败者树降到 $O(\log k)$——$k=128$ 时是 128 次 vs 7 次，差近 20 倍。
- **第二步，读「I/O 主导」**：尽管选最小从 $O(k)$ 优化到 $O(\log k)$，外部排序的总成本仍由 I/O（读写趟数）主导——**败者树优化的是「内存里的选择」，不改变趟数**。
- **第三步，读「优化的边界」**：当 $k$ 大到内存放不下 $k$ 路缓冲时，路数受「内存 ÷ 缓冲大小」限制——败者树在「给定 $k$」的前提下做选择优化。<span class="marginnote">「败者树优化内存选择、不优化磁盘趟数」提醒我们：<strong>先定结构（路数 $k$），再定选择算法</strong>。<strong>磁盘 I/O 是主导项，内存选择是次要项</strong>——但 $k$ 大时次要项也可能反超，所以两处都要优化。</span>

## 4 多路平衡归并的完整流程

「平衡」指：**每一趟归并把所有有序段均匀地合并**，不偏袒任何路。流程：

1. **准备**：$k$ 个有序段各分配一块输入缓冲，取各自首块读入内存，建败者树；
2. **选最小**：根给出全局最小元素所在路，输出到输出缓冲；
3. **补充**：该路缓冲耗尽则读下一块；新元素进入，`Adjust` 重赛；
4. **写回**：输出缓冲满，顺序写回磁盘；
5. 某路段读完，用「无穷大」补位；全部读完则归并完成，得到新有序段。

**重点：全程「顺序读各段 + 顺序写新段」——每趟归并 I/O 恰好读写全文件一遍，没有任何随机寻道。**<span class="marginnote">「<strong>缓冲 + 顺序化</strong>」是外部归并的工程骨架：<strong>读缓冲吸收「段内的顺序流」，输出缓冲把「逐条写」聚成「整块写」</strong>。没有缓冲，逐条写盘会退化成随机寻道——缓冲的存在，就是「把随机逐条变成顺序整块」。</span>

## 5 多路归并选型的总原则

- **路数 $k$ 增加**：趟数 $\log_k$ 降，但内存缓冲需求与选择代价（即使有败者树）升；
- **段长增加**：初始段数 $m$ 降，趟数降——这是 §11.4 置换-选择排序的目标；
- **块大小增加**：单趟 I/O 次数降，但缓冲能装的路数降。

**重点：外部排序是「内存、路数、块大小、段长」四变量的联合调优**——没有一个变量能独立最优，全部受「内存总量」这一硬约束耦合。<span class="marginnote">「四变量受内存耦合」是外部排序与内部排序的最大不同：<strong>内部排序的优化是「算法内」的，外部排序的优化是「资源分配」的</strong>——把有限内存分给「段长、路数、块大小」三处，是一个系统层面的分配问题，与操作系统的「页面置换」异曲同工。</span>

## 6 小结

- $k$ 路归并选最小：直接扫描 $O(k)$，败者树 $O(\log k)$。
- 败者树：内部结点存「败者」，根存总冠军；替换后沿路径 `Adjust`。
- `Adjust` 一行 `if` 决出胜负——「只存败者」让路径直接可用。
- 败者树优化「内存选择」，不改变磁盘趟数。
- 平衡归并：均匀合并所有段，全程顺序读写，每趟 I/O = 读写一遍文件。
- 外部排序是「内存、路数、块、段长」四变量在内存约束下的联合调优。
