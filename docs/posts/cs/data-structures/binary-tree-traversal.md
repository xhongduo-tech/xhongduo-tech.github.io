## 为什么遍历是树的「第一运算」

树的一切操作——查找、删除、序列化、复制——都从**遍历（traversal）**开始：按某种次序把每个结点恰好访问一次。二叉树有四种经典遍历：**先序、中序、后序、层序**。前三者是「深度优先」（沿路径走到底再回头），由「何时访问根」区分；层序是「广度优先」（逐层推进），靠队列实现。掌握遍历等于掌握二叉树的「语法」——后续的线索化、表达式求值、二叉排序树、赫夫曼编码，全是某种遍历的变体。

## 1 三种递归遍历

若把对树的处理抽象成「访问根（visit）」与「递归遍历左、右子树」两个动作，三种遍历只是「访问根」的时机不同：

- **先序（preorder）**：访问根 → 先序遍历左子树 → 先序遍历右子树。
- **中序（inorder）**：中序遍历左子树 → 访问根 → 中序遍历右子树。
- **后序（postorder）**：后序遍历左子树 → 后序遍历右子树 → 访问根。

代码是同一模板的三次填空：

```c
void PreOrder(BiTree T) {
    if (T) {                       /* 空树：什么都不做（递归出口） */
        visit(T->data);            /* 先序：先访问根 */
        PreOrder(T->lchild);
        PreOrder(T->rchild);
    }
}
/* InOrder / PostOrder：仅调整三行代码的顺序 */
```

**重点：三种遍历共享同一递归框架，差异只有「访问根」的位置。** 空树返回是递归出口，保证递归必然终止。<span class="marginnote">记忆口诀：<strong>先序「根左右」、中序「左根右」、后序「左右根」</strong>。名字里的「先/中/后」指的就是根的位置。对表达式树，先序是前缀式、中序是中缀式、后序是后缀式——表达式求值那一节的三种记号，在这里与遍历一一对应。</span>

## 2 公式解析：遍历序列的递归刻画

中序遍历可递归地写成「序列的拼接」。设 $L$ 为左子树的中序序列，$R$ 为右子树的中序序列，则整棵树的中序序列为：

$$
\text{Inorder}(T) = \text{Inorder}(L) + [\text{root}] + \text{Inorder}(R)
$$

- **第一步，读「$+$」**：遍历序列是字符串拼接——左子树序列、根、右子树序列依次排开。
- **第二步，读递归下降**：$\text{Inorder}(L)$ 本身又展开为「$L$ 的左子树 + $L$ 的根 + $L$ 的右子树」，直到叶子（叶子是「左右子树为空」的树，其序列就是 $[\text{leaf}]$）。
- **第三步，体会「分治」**：遍历序列的构造是完美的分治——**「左、中、右」三段各自独立递归**。这也是「由遍历序列恢复二叉树」能行的原因：中序序列里，根的左边必是左子树全体、右边必是右子树全体。<span class="marginnote">分治在遍历里的体现，与快速排序「选枢轴分两半」完全同构：<strong>根是枢轴，中序序列按根切两半</strong>。所以「先序 + 中序恢复二叉树」的算法，本质上就是「已知枢轴位置的递归重建」。</span>

## 3 层序遍历：用队列逐层推进

层序（level order）遍历按「从根开始、逐层从左到右」访问。它与深度优先不同，是**广度优先**，自然要用队列：

```c
void LevelOrder(BiTree T) {
    InitQueue(Q);
    if (T) EnQueue(Q, T);
    while (!QueueEmpty(Q)) {
        DeQueue(Q, p);            /* 出队一个结点 */
        visit(p->data);           /* 访问它 */
        if (p->lchild) EnQueue(Q, p->lchild);   /* 左孩子入队 */
        if (p->rchild) EnQueue(Q, p->rchild);   /* 右孩子入队 */
    }
}
```

**重点：入队顺序「先左后右」，出队顺序恰好是层序。** 因为队列 FIFO——同一层的结点先入队、先出队，出完一层才轮到下一层。<span class="marginnote">层序与《链队列》里预演的 BFS 是同一台机器：树的层序遍历就是 BFS 的特例。到第七篇《图的遍历（广度优先搜索）》，你会看到完全相同的「队列 + 访问 + 邻接点入队」骨架——<strong>只是把「左右孩子」换成「所有邻接点」</strong>。</span>

## 4 由遍历序列恢复二叉树

知道一棵二叉树的遍历序列，能否反推出它的形状？

- **先序 + 中序**：能唯一确定。先序的第一个是根；用根把中序切成左、右两半；递归重建两棵子树。
- **中序 + 后序**：也能唯一确定。后序的最后一个（或先序逆序的根）是根，同样切中序。
- **只有先序 + 后序**：**不能**唯一确定——只知根和「左右子树整体」，不知左右如何划分。

**辨析｜易错点：为什么「先序 + 后序」不够？** 因为一棵只有左孩子的树与只有右孩子的树，先序都是「根、孩子」，后序都是「孩子、根」，二者不可区分。**中序序列是「左右分界」的关键信息**——它唯一地告诉你根的左右各是什么。<span class="marginnote">「中序提供分界、先/后序提供根」——这条配合是二叉树恢复问题的核心。它也与「<strong>已知根序 + 中序 → 重建</strong>」的经典面试题完全一致，递归实现只需 20 行。</span>

## 5 遍历的非递归实现

递归遍历虽优雅，但深度大时可能栈溢出。非递归实现用**显式栈模拟系统调用栈**：

- **先序非递归**：根入栈；循环出栈访问，再依次把右、左孩子入栈（先右后左，保证左孩子先被访问）。
- **中序非递归**：沿左链一路压栈到底，再逐一出栈访问，访问后转向右子树——「先走到最左，再回头」。
- **后序非递归**：最麻烦，需要记录「右子树是否已访问」，常用双栈或标记法。

<span class="marginnote">非递归遍历是「<strong>显式栈替换系统栈</strong>」的实践课——与《栈与递归（汉诺塔）》一节讲的「递归改写迭代」直接呼应。理解了系统栈在递归里做什么，非递归版本就是你「手动重演」系统栈。</span>

## 6 小结

- 先序「根左右」、中序「左根右」、后序「左右根」——递归模板相同，仅根的访问时机不同。
- 遍历序列 = 左右子序列 + 根的拼接，是分治的典型。
- 层序遍历用**队列**，是 BFS 的特例。
- **先序 + 中序**（或中序 + 后序）可唯一恢复二叉树；先序 + 后序不够。
- 非递归遍历用显式栈模拟系统栈，避免递归栈溢出。
