## 为什么 DAG 值得专门研究

现实中的「先后依赖」——课程先修、工程工序、编译依赖、任务调度——都能用**有向图**表达：边 $u \to v$ 表示「$u$ 必须先于 $v$」。但若图里有环，依赖就陷入死循环（A 依赖 B、B 又依赖 A），调度不可能完成。**有向无环图（DAG, Directed Acyclic Graph）**正是「无矛盾依赖」的数学模型。**拓扑排序（topological sort）**把 DAG 的所有顶点排成一个线性序列，使得每条边 $u \to v$ 都满足「$u$ 在 $v$ 之前」。它是课程安排、编译顺序、Spark 计算图、Makefile 依赖树的统一解法。

## 1 DAG 与拓扑排序的定义

**有向无环图（DAG）**：不存在任何有向回路的有向图。

**拓扑排序**：对 DAG 的顶点排成序列 $v_1, v_2, \cdots, v_n$，使对每条边 $v_i \to v_j$ 都有 $i < j$。

**重点：拓扑排序存在的充要条件是该有向图是 DAG。** 有环则必然存在「环上的顶点互为依赖」，无法排序；无环则一定可以排。而且**一个 DAG 的拓扑序通常不唯一**。<span class="marginnote">「有环必无拓扑序」可以用反证：若环上顶点能排成线性序，沿环走一圈要求 $v_{i_1} < v_{i_2} < \cdots < v_{i_k} < v_{i_1}$，自相矛盾。<strong>拓扑排序的副产品就是「检测是否有环」</strong>——排不出来的图必有环。</span>

## 2 拓扑排序的算法（Kahn 算法）

**Kahn 算法**基于「剥洋葱」：反复删除「当前入度为 0 的顶点」（它没有先决条件，可以先行）：

1. 统计每个顶点的入度；
2. 把所有入度为 0 的顶点入队（或入栈）；
3. 出队一个顶点 $v$，加入拓扑序列；对 $v$ 的每个后继 $w$，入度减 1，若变为 0 则入队；
4. 重复直到队列空。

```text
// Kahn 算法：反复剥「入度为 0」的洋葱
for (每个顶点 v) indeg[v] = 统计入度;
for (每个顶点 v) if (indeg[v] == 0) 入队 v;      // 就绪判据：入度为零
count = 0;
while (队列不空) {
    v = 出队; 输出 v;  count++;
    for (v 的每个后继 w) {
        indeg[w]--;
        if (indeg[w] == 0) 入队 w;               // 先决条件已满足
    }
}
if (count < n) 该图有环;                          // 排不满 = 存在环
```

**重点：算法结束时若输出的顶点数少于 $n$，说明有环**——那些顶点永远无法入度为 0。这是拓扑排序自带环检测的原因。<span class="marginnote">用队列还是栈，只影响「并列就绪顶点」的输出顺序，不影响正确性。<strong>入度为零 = 所有先决条件已满足</strong>，是拓扑排序的「就绪判据」。它也是多线程调度、构建系统里「依赖就绪即执行」的同一判据。</span>

**一个具体的算例。** 设五门课程 $A, B, C, D, E$，先修关系为 $A \to C$、$A \to D$、$B \to C$、$B \to E$、$C \to E$（边 $u \to v$ 表示「须先修 $u$ 再修 $v$」）。统计入度：$A=0, B=0, C=2, D=1, E=2$。算法执行：

1. 队列初始含入度为 0 的 $A, B$；出队 $A$，输出 $A$，$C$ 减为 1、$D$ 减为 0，$D$ 入队；
2. 出队 $B$，输出 $B$，$C$ 减为 0、$E$ 减为 1，$C$ 入队；
3. 出队 $D$，输出 $D$；出队 $C$，输出 $C$，$E$ 减为 0，$E$ 入队；
4. 出队 $E$，输出 $E$。得到拓扑序 $A, B, D, C, E$。

注意队列里 $A$ 与 $B$、$D$ 与 $C$ 的相对顺序都可以交换，会得到不同的合法拓扑序——**拓扑序不唯一，是 DAG 的常态而非例外**。<span class="marginnote">把「并列就绪」的顶点按不同顺序调度，就得到不同的拓扑序。<strong>多数系统只要「任一合法拓扑序」，但有的场景（如优先安排关键工序）会给顶点加优先级</strong>——此时把队列换成优先队列，Kahn 算法立即升级成「字典序最小」的拓扑序。</span>

**核心对比表：Kahn 算法 vs DFS 拓扑序**

| 维度 | Kahn 算法 | DFS 完成序 |
| --- | --- | --- |
| 出发点 | 入度为零的顶点（剥洋葱） | 任意顶点（先钻到底） |
| 数据结构 | 队列 / 栈 | 递归栈 |
| 环检测 | 输出顶点数 < $n$ | 遍历中遇到回边 |
| 输出顺序 | 从「就绪」到「后继」 | 完成序的逆序 |
| 实现代价 | 需额外入度数组 | 仅需访问标记 |

两种写法复杂度同为 $O(n+e)$，选哪种取决于手头的数据形态——若要顺带判环，Kahn 的「输出数不足」更直白。

## 3 公式解析：Kahn 算法的复杂度

设图有 $n$ 个顶点、$e$ 条边：

$$
T_{\text{拓扑排序}} = O(n + e) \qquad (\text{邻接表})
$$

- **第一步，读统计入度**：遍历所有弧一次，$O(e)$。
- **第二步，读主循环**：每个顶点入队/出队一次（$O(n)$），每条边被「入度减 1」处理一次（$O(e)$）。
- **第三步，读线性性**：总代价 $O(n+e)$，与 DFS 同级——拓扑排序是「线性时间」算法。**任何顶点/边都只处理常数次**，这是「剥洋葱」结构的保证。<span class="marginnote">$O(n+e)$ 的线性性来自「<strong>每个顶点每条边恰好处理一次</strong>」。注意邻接矩阵版会是 $O(n^2)$——又要「扫整行找后继」。线性与二次的差距，在 $n=10^5$ 时是 $10^{10}$ vs $10^5$，悬殊四个量级。</span>

## 4 拓扑排序 vs DFS 拓扑序

Kahn 算法是「入度视角」；DFS 也能给出拓扑序：

**DFS 完成序（finishing order）**：DFS 中「一个顶点的所有邻接点都访问完、即将回溯」的时刻叫完成。**DFS 完成的逆序就是拓扑序**。
原理：边 $u \to v$ 意味着 $v$ 是 $u$ 的后代或后访问，DFS 中 $v$ 先完成、$u$ 后完成；逆序后 $u$ 在前。

**辨析｜易错点：DFS 拓扑序是「完成序的逆序」，不是「访问序」。** 直接把 DFS 访问顺序当拓扑序是错的——先访问的不一定先完成。必须用「后根顺序」（类似树的后序遍历）再反转。<span class="marginnote">「完成序逆序」与《树与森林遍历》的「后根遍历」异曲同工：都是「<strong>先处理完所有孩子再处理自己</strong>」，再逆序。这一「后序 + 反转」模板，在专题篇的 Tarjan 强连通分量里还会原样出现。</span>

## 5 DAG 的应用：从编译到计算图

**课程先修安排**：顶点 = 课程，边 = 先修，拓扑序 = 可行的选课顺序；
**工程关键路径（下一节）**：拓扑序给出「最早开始时间」的计算顺序；
**编译/构建系统**：Make、Maven、pip 的依赖解析——依赖是 DAG，构建顺序是拓扑序；
**Spark/计算图**：DAG 调度器按拓扑序安排 Stage 执行；
**符号推导**：表达式依赖图（算符 DAG）求值。<span class="marginnote">大模型推理里，计算图（TensorFlow/PyTorch 的图）本身就是 DAG：张量是顶点、算子是边（或反之），<strong>拓扑序就是「先算哪个张量」的求值顺序</strong>。自动微分（反向传播）在 DAG 上反向走一遍——「前向按拓扑序、反向按逆拓扑序」，这条规则全图通用。</span>

**辨析｜易错点：拓扑序不唯一，也不是「完全排序」。** 拓扑序只约束「有边相连的两顶点」的前后关系；对无直接依赖的顶点，相对顺序完全任意。因此拓扑序通常不唯一，也不等于字典序——若题目要求字典序最小，把普通队列换成优先队列即可，Kahn 的框架原封不动。

**辨析｜易错点：别把「入度为零」记成「出度为零」。** 入度为零 = 没有前置依赖 = 可以先行，是 Kahn 的就绪判据；出度为零 = 没有后继，属于 DFS 完成序的视角。两者方向相反，写代码时务必分清。

**延伸对照**：本节两个辨析与《树与森林遍历》的「后根遍历」、专题篇《Tarjan 求强连通分量》的「完成序」一脉相承——**「入度视角」与「完成序视角」是 DAG 上的两种互补心智模型**，遇到「依赖调度」类题目，先问自己用的是哪一个。

## 6 小结

- DAG = 无有向回路的有向图；拓扑序存在 ⇔ 图是 DAG。
- Kahn 算法：剥「入度为零」的洋葱，队列 + 入度计数，$O(n+e)$。
- 输出顶点数 < $n$ ⇒ 有环（拓扑排序自带环检测）。
- DFS 拓扑序 = 完成序的逆序；注意与访问序区分。
- 应用：课程安排、构建系统、Spark 计算图、算符 DAG。
- 计算图求值「按拓扑序、反向传播按逆拓扑序」。
