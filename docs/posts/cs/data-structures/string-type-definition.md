## 为什么把「串」单独列一篇

整数、实数、字符是计算机处理的基本单元，但真实世界的文本是由**字符序列**构成的——一份合同、一段代码、一篇文章，本质上都是「串」。串不是普通的线性表：它的元素只有字符，元素数量却可以成千上万，而且人们关心的运算不是「在第 $i$ 位插入一个字符」，而是**串的整体比较、拼接、求子串、查找子串**。于是串值得拥有一套自己的抽象数据类型。更重要的是，串的模式匹配（在本篇 §4.3 与专题篇的 KMP 中展开）是搜索引擎、文本编辑器、生物信息学序列比对的共同地基。

## 1 串的基本术语

**串（string）**：由零个或多个字符组成的**有限序列**，记作 $S = "a_1 a_2 \cdots a_n"$，其中 $n$ 称为串的**长度**。

几个必须钉死的术语：

- **空串（null string）**：长度为零的串，记作 `""`（空引号对），不含任何字符。
- **空白串**：只含空格字符的串，如 `" "`（由空格组成），长度不为零——**空串 ≠ 空白串**。
- **子串（substring）**：串中**任意个连续字符**组成的子序列。如 `"cd"` 是 `"abcd"` 的子串。
- **主串（main string）**：包含子串的串。
- **位置（position）**：字符在串中的序号。子串在主串中**第一次出现**时其首字符在主串中的序号，称为子串在主串中的**位置**。

<span class="marginnote">串与线性表的关系：串是一种<strong>内容受限</strong>的线性表——元素只能是字符。但运算模型变了：线性表重「定位插入删除」，串重「整体求值」。这一「内容受限 → 运算转向」的模式，在矩阵、树、图上还会反复出现。</span>

## 2 串相等与串比较

两个串**相等**，当且仅当**长度相同且对应位置字符都相同**。

串的比较按**字典序（lexicographic order）**进行：从第一个字符开始比较，若某位字符不同，则 ASCII/Unicode 码小的串小；若前面的字符全相同，则**短的串小**（空串最小）。<span class="marginnote">字典序与数学里「字典」的排序完全一致，也与人教版高中《集合》里「实数大小」的比较习惯同源——只是把「比大小」的定义搬到了字符序列上。程序里 `strcmp` 返回负/零/正，就是字典序三态的实现。</span>

**辨析｜易错点：「空串是任何串的子串」。** 按「任意个连续字符」的定义，空串也是子串——通常约定它位于主串开头，位置记 1（或 0，取决于约定）。相应地，**任何串都是自身的子串**（取全部连续字符），但通常讨论「真子串」时不包含自身。

## 3 串的抽象数据类型

严蔚敏教材把串定义为一个 ADT，基本操作有：

```text
ADT String {
    数据对象：D = { a1 a2 ... an | ai ∈ CharacterSet, n ≥ 0 }
    数据关系：R = { <a(i-1), ai> | i = 2, ..., n }   /* 相邻字符的线性关系 */
    基本操作：
        StrAssign(&T, chars)       初始条件：chars 是字符串常量
                                   操作结果：生成一个值等于 chars 的串 T
        StrCompare(S, T)           操作结果：按字典序比较 S 与 T
        SubString(&Sub, S, pos, len)  操作结果：用 Sub 返回 S 中第 pos 个字符起长 len 的子串
        Index(S, T, pos)           操作结果：求 T 在 S 中从 pos 起首次出现的位置
} ADT String
```

**重点：`Index`（模式匹配）是串的「灵魂操作」**——它的实现效率决定文本处理的上限。朴素匹配是 $O(nm)$，改进的 KMP 是 $O(n+m)$。这一差异，是本章后续所有内容的伏笔。<span class="marginnote">注意 ADT 规格只声明「<strong>做什么</strong>」不声明「怎么做」：`Index` 用朴素算法还是 KMP，使用者无感。这正是绪论《抽象数据类型的表示与实现》里「接口与实现分离」在串上的落地。</span>

## 4 核心对比表：串与线性表

串与线性表同源而不同用，并排对比最清楚：

| 维度 | 线性表 | 串 |
| --- | --- | --- |
| 元素类型 | 任意 | 仅字符 |
| 长度单位 | 元素个数 | 字符个数 |
| 核心运算 | 定位、插入、删除 | 比较、连接、求子串、模式匹配 |
| 存储粒度 | 元素 | 字符（可能压缩、可能按块） |
| 比较语义 | 通常按元素 | 按字典序 |
| 典型应用 | 通用容器 | 文本编辑、搜索、编译 |

从表中读出三条规律。第一，**「内容受限」直接改写了运算重心**：串几乎不关心「在第 $i$ 个位置插入一个字符」，而关心「一段连续字符整体出现了没有、出现在哪」。第二，**求子串是串特有的操作**——线性表没有「子表」概念，因为它不强调连续片段。第三，**模式匹配（Index）是串独有的性能战场**：从朴素匹配到 KMP，再到专题篇的 Trie 与字符串哈希，性能每上一个台阶，都对应一种新的「利用已知信息」的策略。

## 5 串与「从极限到大模型」主线的连接

串不是孤立的文本细节，它是整条主线的交汇点：

**编译原理**：词法分析把源码读成 token，正则表达式本身就是「串的模式」；
**搜索引擎**：倒排索引的键是词项（串），查询匹配本质是串运算；
**生物信息学**：DNA/蛋白质序列比对是「允许缺口的模式匹配」；
**大模型**：Tokenizer 把文本切成 token 子串，注意力机制在 token 序列上做匹配——「串」是所有语言处理的第一形态。<span class="marginnote">大模型的输入从「字符流」变成「token 流」，但串的三个基本问题（怎么存、怎么比、怎么找子串）一个都没消失——只是规模放大到十亿 token。数据结构的功夫在这里从「基本功」变成「瓶颈」。</span>

**一个字典序比较的算例。** 设 $S_1 = "apple"$、$S_2 = "apply"$、$S_3 = "ap"$、$S_4 = "banana"$。

- $S_1$ 与 $S_2$：前四位 `appl` 相同，第五位 `e`（101）< `y`（121），故 $S_1 < S_2$；
- $S_1$ 与 $S_3$：$S_3$ 是 $S_1$ 的前缀且更短，故 $S_3 < S_1$——「短的串小」；
- $S_2$ 与 $S_4$：首位 `a`（97）< `b`（98），故 $S_2 < S_4$。

这正是 `strcmp` 的判定逻辑：一位位比码值，前缀相同则比长度。<span class="marginnote">「前缀相同比长度」这条规则在排序里很重要：<strong>任何字典序排序中，前缀串一定排在其扩展串之前</strong>。你在「字符串排序」「Trie 前缀遍历」里会再次遇到它。</span>

**辨析｜易错点：「空格」与「空字符」不同。** 空白串由空格（ASCII 32）组成，长度不为零；空串长度为 0、不含任何字符。比较时空格按 ASCII 32 参与排序——空格串大于空串，但小于 `!`（33）之后的字符。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 串（string） | 字符的有限序列 |
| 空串 | 长度 0，记 `""` |
| 空白串 | 只含空格的串，长度非 0 |
| 子串 | 任意个连续字符组成的子序列 |
| 字典序 | 逐字符比码值、前缀同则比长度 |
| 位置 | 子串首字符在主串中的序号 |

**辨析｜易错点：串的「长度」与「存储容量」是两回事。** 逻辑长度 = 字符个数；物理容量 = 分配的空间大小。定长存储里两者可能不等（容量固定、长度可变）；堆分配里长度与容量独立管理。别把「容量」当「长度」，也别把「长度」当「容量」。

**一句话**：串是「字符有限序列」，其灵魂操作是模式匹配——从朴素到 KMP，是本章的主线。

**补充**：串与集合（第一级）的对比值得留意：集合无序去重，串有序可重——前者管「在不在」，后者管「怎么排、怎么比」。

## 6 小结

- 串是**字符组成的有限序列**，空串长度为 0，空白串只含空格——两者不同。
- 子串是**任意个连续字符**；子串位置 = 其首字符在主串中的序号。
- 串相等：**长度相同且逐字符相同**；串比较按**字典序**。
- 串的 ADT 核心操作：比较、连接、求子串、**模式匹配 Index**、替换、插入删除。
- 串 vs 线性表：内容受限 → 运算重心从「定位插入」转向「整体求值与匹配」。
- Index 的效率（朴素 $O(nm)$ vs KMP $O(n+m)$）是本章主线。
