## 为什么用链式实现栈

上一节的顺序栈把栈顶钉在数组末尾，简单高效。但它的短板也很现实：空间必须**预分配**，装满了就得扩容；而很多时候我们根本不知道栈最多会有多深——嵌套的括号、递归的调用、深度优先搜索，栈的深度随输入剧烈变化。链式表示（链栈）把每个元素做成一个结点，用指针串起来，**栈要多深就建多深，用完即释放**。链栈是「链表」这一存储结构的第一个应用场，也让我们第一次直面「指针操作」的细节与陷阱。

## 1 链栈的结构

链栈是单链表的特例：**栈顶是链表头，栈底是链表尾**。为什么栈顶要放在头端？因为单链表在头端插入、删除都是 $O(1)$，而在尾端需要遍历到倒数第二个结点。把「只能在一端操作」的栈顶对齐到「天然支持头部操作」的链表头，两个约束一拍即合。

```c
typedef struct StackNode {
    ElemType data;              /* 数据域 */
    struct StackNode *next;     /* 指针域 */
} StackNode, *LinkStack;        /* 栈顶就是链表头 */
```

**重点：链栈不需要独立的 top 指针变量——栈顶就是链表头指针。** top 指针本身既代表整个栈，又直接指向栈顶结点。<span class="marginnote">这里有个值得品味的对应：顺序栈用「<strong>top 整数</strong>」记录栈顶下标，链栈用「<strong>top 指针</strong>」记录栈顶结点。同一个「栈顶」概念，在两种存储结构里分别落成「下标」与「地址」——这正是绪论「逻辑结构到存储结构的映像」的活例子。</span>

## 2 链栈的入栈：头插法

入栈（push）就是把新结点插到链表头部：

```c
Status Push(LinkStack &S, ElemType e) {
    StackNode *p = (StackNode *)malloc(sizeof(StackNode));
    p->data = e;
    p->next = S;          /* ① 先：新结点指向旧栈顶 */
    S = p;                /* ② 后：更新栈顶指针 */
    return OK;
}
```

步骤只有三行，但要分清顺序：**先让新结点的 `next` 指向旧栈顶，再把栈顶指针更新为新结点**。若顺序写反（先更新栈顶指针、再连 `next`），新结点会指向自己，链表环化——这类「指针自指」错误最难排查。<span class="marginnote">头插法只在头部操作，时间 $O(1)$。它就是单链表「插在表头」的封装：把插入位置固定为头，这一步正是把线性表改造成栈的那一下。</span>

## 3 链栈的出栈：释放结点

出栈（pop）取走栈顶元素，并**释放**该结点：

```c
Status Pop(LinkStack &S, ElemType &e) {
    if (S == NULL) return ERROR;        /* 判空：链栈只有下溢 */
    StackNode *p = S;
    e = p->data;          /* ① 先：暂存栈顶元素 */
    S = p->next;          /* ② 再：移动栈顶指针 */
    free(p);              /* ③ 最后：释放原栈顶结点 */
    return OK;
}
```

出栈的关键在于**「先暂存，再移动，最后释放」**。若先释放再访问，就是 use-after-free；若先移动再释放，则丢失了指向原栈顶的指针，造成内存泄漏。

**辨析｜易错点：链栈只有下溢，没有上溢。** 顺序栈有「栈满」要判溢出；链栈的结点逐个从堆上分配，只要内存足够就不存在「满」，唯一需要检查的是「空」——出栈（pop）之前必须先判空栈。这体现了链式存储「按需分配」的本质：以 malloc/free 的开销换空间弹性。

## 4 公式解析：两种实现的代价对比

顺序栈与链栈是「数组 vs 链表」在栈上的决斗。把两种代价并排写出来：

$$
\begin{aligned}
T_{\text{push/pop}} &: \ \text{顺序栈 } O(1) \ \text{（不移动元素）}, \quad \text{链栈 } O(1) \ \text{（只动指针）} \\
S_{\text{空间}} &: \ \text{顺序栈 } O(n) \ \text{（预分配，可能浪费）}, \quad \text{链栈 } O(n) \ \text{（按需，但每结点多一个指针域）}
\end{aligned}
$$

- **第一步，读时间**：两种实现 push/pop 都是常数时间——这是「栈顶固定」带来的红利。但常数的系数不同：顺序栈是一次数组读写，链栈多一次 malloc/free，栈深大、操作频繁时，分配开销不可忽视。
- **第二步，读空间**：顺序栈有预分配浪费，链栈有指针域开销。若元素恰好 4 字节、指针恰好 8 字节，链栈的指针开销可达顺序栈的 2 倍。
- **第三步，真正的分水岭是「深度是否可知」**：栈的最大深度可估计（如括号匹配最多 $n$ 层），用顺序栈；深度不可知（如递归 DFS、内存里飞涨的调用栈），用链栈。<span class="marginnote">这个权衡会贯穿全书：顺序结构「<strong>快但死板</strong>」，链式结构「<strong>活但略贵</strong>」。到《链队列》《稀疏矩阵的十字链表》时，同样的二选一还会反复出现。</span>

## 5 数值算例：头插头删的指针三步

用一个 2 元素的链栈演示入栈、出栈的指针变化。设栈当前为 `top → N2(20) → N1(10) → NULL`。

**入栈 30**：申请新结点 `p(30)`——第一步 `p->next = top`（$p$ 指向 N2）；第二步 `top = p`（top 指向 $p$）。两笔之后：`top → N3(30) → N2(20) → N1(10) → NULL`。注意**两步的顺序**：若先执行 `top = p`，则 `p->next` 用的是「更新后的 top」——`p->next = p`，新结点自指成环。

**出栈**：先 `e = top->data`（暂存 30）；再 `top = top->next`（top 移到 N2）；最后 `free(N3)`。三步之后：`top → N2(20) → N1(10) → NULL`，`e = 30` 已返回。

**重点：链栈的每次操作都是「先连后断」或「先取后断」——顺序错一位，要么自指成环、要么内存泄漏。**<span class="marginnote">这些「一步之错」在真实代码里极难排查，因为只在特定内存布局下触发。<strong>画指针图 + 按序口述每一步</strong>，是调试链表问题的黄金方法——<strong>先画后写，胜过写完再猜</strong>。</span>

这段「顺序敏感」不只在链栈：链队列、单链表插入、双向链表，全都依赖「先接新链、再断旧链」的顺序——**指针操作的第一课就是记住顺序**。

**一个应用对比的算例：括号匹配的栈深估计。** 对「$n$ 对括号的合法序列」，栈的最大深度恰好 $n$（最坏 `((((...))))` 全部压栈），所以深度**已知**——教科书用顺序栈。而 DFS 的递归栈深度等于图的深度，最坏可达 $n$ 且无法预知——**深度不可知，用链栈**。这两类场景的分界，就是选型的一句话口诀。

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 链栈 | 单链表的头部操作栈 |
| 栈顶 = 链表头 | 头插头删，操作 $O(1)$ |
| 先连后断 | push 先 `p->next=top` 再 `top=p` |
| 下溢 | 空栈出栈，链栈唯一需要判的错 |
| 指针自指 | 顺序写反导致新结点指向自己 |

**辨析｜易错点：链栈的「判空」是出栈的唯一前置检查。** 链栈没有「栈满」，只有「栈空」——出栈前必须 `if (S == NULL)` 判空，否则访问空指针。入栈则几乎不用判（除非 malloc 失败）。「只有下溢、没有上溢」是链栈与顺序栈最直观的差别。

**一句话**：链栈 = 单链表 + 「只在头部操作」的约束——栈顶就是链表头，头插头删 $O(1)$。

**补充**：链栈适合「深度不可预估」的场景（递归 DFS、嵌套表达式），因为它按需分配、用完即释放，空间永不预支。

## 6 小结

- 链栈是单链表特例：**栈顶 = 链表头**，头插头删，操作 $O(1)$。
- 入栈三步：申请结点 → 新结点指向旧栈顶 → 更新栈顶指针，顺序不可反。
- 出栈三步：暂存元素 → 移动栈顶 → 释放结点，顺序也不可反。
- 链栈**只有下溢没有上溢**：只需判空，无需判满。
- 链栈 vs 顺序栈：时间同为 $O(1)$，链栈多指针域与 malloc 开销、换来空间弹性；栈深不可知时选链栈。

在下一节，栈要真正「用起来」了——**栈与递归（汉诺塔）**。我们会看到，函数调用的「现场保存、返回恢复」本质就是一台隐藏的栈，而把递归改写成显式栈，是理解二者的共同捷径。
