## 为什么最短路径如此重要

导航找路、网络路由、地图服务、游戏寻路——「从 A 到 B 的最短路径」是最普遍的图问题。**Dijkstra 算法**解决**单源最短路径**：给定源点，求它到所有其他顶点的最短路（**边权非负**）。它的思想是贪心 + 松弛：维护一个「已确定最短路的顶点集合」，每次从未确定顶点中挑一个「当前距离最小」的加入，然后用它去更新（松弛）它的邻居。配上优先队列（堆），Dijkstra 是 $O((n+e)\log n)$——这也是「堆」这座结构第一次真正挑大梁。

## 1 Dijkstra 的思想：贪心选点 + 松弛

设源点为 $s$。维护数组 $dist[v]$ = 当前已知的 $s$ 到 $v$ 的最短距离，以及集合 $S$ = 已确定最短路的顶点。

1. 初始化 $dist[s] = 0$，其余 $dist[v] = \infty$，$S$ 为空；
2. **选点**：从不在 $S$ 的顶点中，选 $dist$ 最小的 $u$，加入 $S$；
3. **松弛**：对 $u$ 的每个邻居 $v$，若 $dist[u] + w(u,v) < dist[v]$，则更新 $dist[v]$；
4. 重复 2、3，直到 $S$ 包含全部顶点。

```c
// Dijkstra（邻接矩阵版）：贪心选点 + 松弛，朴素 O(n^2)
// 用最小堆优化「选点」，可得 O((n+e) log n)
void Dijkstra(MGraph G, int s, int dist[], int pre[]) {
    int S[MAXN] = {0};                 // S[v] = 1 表示 v 已确定最短路
    for (int v = 0; v < G.n; v++) { dist[v] = G.arcs[s][v]; pre[v] = s; }
    dist[s] = 0;  S[s] = 1;
    for (int i = 1; i < G.n; i++) {
        int u = -1, minD = INF;
        for (int v = 0; v < G.n; v++)          // 选点：S 外 dist 最小的 u
            if (!S[v] && dist[v] < minD) { minD = dist[v]; u = v; }
        S[u] = 1;                              // u 加入 S，dist 永不再变
        for (int v = 0; v < G.n; v++)          // 松弛：用 u 更新它的邻居
            if (!S[v] && dist[u] + G.arcs[u][v] < dist[v]) {
                dist[v] = dist[u] + G.arcs[u][v];
                pre[v] = u;                    // 前驱同步更新
            }
    }
}
```

**重点：Dijkstra 的两个关键动作——「选最小」与「松弛」。** 选出的 $u$ 一旦加入 $S$，它的 $dist$ 就**永不再变小**（这正是非负权保证的）；松弛则保证「经过 $u$ 的路径被考虑过」。<span class="marginnote">「选出的最小不会再变小」是 Dijkstra 正确性的核心不变量：<strong>非负权下，任何绕远路都不可能比当前直达更短</strong>——因为绕路至少要加一条非负边。若有负权边，这个不变量立刻破裂，Dijkstra 失效（那时要 Bellman-Ford，专题篇）。</span>

## 2 公式解析：松弛操作与复杂度

**松弛（relaxation）**的定义：

$$
dist[v] \leftarrow \min\{ dist[v],\ dist[u] + w(u,v) \}
$$

- **第一步，读「尝试缩短」**：$dist[u] + w(u,v)$ 是「先到 $u$ 再到 $v$」的候选长度，与当前 $dist[v]$ 取小者。
- **第二步，读「为什么要沿所有边做」**：最终的最短路径一定由若干次松弛逐步逼近；每个顶点的 $dist$ 是「当前已知最好」，被反复刷新。
- **第三步，读复杂度**：朴素版「选最小」每次 $O(n)$，共 $n$ 次，总 $O(n^2)$；用**最小堆**存「未确定顶点的 $dist$」，选最小 $O(\log n)$、松弛更新 $O(\log n)$，总 $O((n+e)\log n)$。<span class="marginnote">「$O(n^2)$ vs $O((n+e)\log n)$」正是稠密图与稀疏图的又一次对决：<strong>稠密图 $e \sim n^2$，朴素 $O(n^2)$ 反而更好；稀疏图 $e \sim n$，堆优化 $O(n\log n)$ 完胜</strong>。Dijkstra 的实现选择，依然服从「存储/数据结构适配图形态」的总原则。</span>

## 3 Dijkstra 正确性的直觉证明

为什么「每次选最小」不会出错？

**不变量**：加入 $S$ 的每个顶点的 $dist$ 都是最终最短路。
**归纳步骤**：假设 $S$ 内正确。取 $S$ 外 $dist$ 最小的 $u$。若存在更短的 $s \to u$ 路径，它必然第一次离开 $S$ 的边是 $<x, y>$，$x \in S$、$y \notin S$。则 $dist[u]$ 更短 ⇒ $dist[y] \le dist[u]$ 更短，与「$u$ 是 $S$ 外最小」矛盾（非负权保证 $dist[y] \ge \dots$）。故 $u$ 正确。

**辨析｜易错点：负权边会让 Dijkstra 出错。** 例子：$s \to a$ 权 1，$s \to b$ 权 2，$b \to a$ 权 -3。Dijkstra 先确定 $a$（dist=1），但真正最短路是 $s \to b \to a$ 权 -1——$a$ 的 dist 被过早「锁定」。**负权图必须用 Bellman-Ford（专题篇）或 SPFA。**<span class="marginnote">这个反例值得亲手画一遍：<strong>「先选出的最小」假设了「绕路只会更贵」</strong>，负权边把绕路变成「更便宜」，假设崩塌。Dijkstra 与 Bellman-Ford 的分界，就是「边权是否非负」这一条线。</span>

## 4 记录路径：前驱数组

光有 $dist$ 只知道「多长」，还要知道「怎么走」。加一个前驱数组 $s$ 记录「$s$ 到 $v$ 最短路上的前驱顶点」：松弛成功时，$v$。最后从目标点沿 `pre` 前驱指针一路回溯到源点，逆序即得路径。

**重点：前驱数组 `pre` 在松弛时同步更新——最短路是「决策」的累积，不是事后推算。** 这与 DFS 的生成树、并查集的父指针是同一类「记录来源」的技法。<span class="marginnote">「松弛 + 前驱」这个组合在几乎所有最短路算法里通用（Dijkstra、Bellman-Ford、Floyd 的 path 矩阵）。<strong>只要更新了最优值，就同步记录「从哪来的」</strong>——这是路径重建的标准模板。</span>

## 5 Dijkstra 的应用

**GPS 导航**：道路网（稀疏、权为正的里程），堆优化 Dijkstra 是主流，工程上加 A\* 启发式加速；
**网络路由**：OSPF 等链路状态协议用 Dijkstra 计算路由表；
**加权图分层**：找出到各点的最短路，作为后续算法的输入；
**游戏寻路**：带权网格上的 Dijkstra/A\*。

**重点：Dijkstra 是「非负单源最短路」的黄金标准**——几乎所有现代实现都是「邻接表 + 最小堆」。理解它，就理解了大模型推理里「Beam Search 打分路径」的贪心框架与它同源的「贪心扩展」逻辑。<span class="marginnote">「贪心 + 松弛 + 前驱」三件套是单源最短路问题的标准答案。<strong>Dijkstra 与 A\* 的区别只在「选点标准」</strong>：Dijkstra 用 $dist$，A\* 用 $dist + heuristic$（预估剩余距离）。加一个启发式，就换来大幅加速——但启发式必须「可采纳」（不高估），正确性才保住。</span>

**一个手算的算例。** 设图有顶点 $s, a, b, t$，边为 $s \to a(2)$、$s \to b(6)$、$a \to b(1)$、$a \to t(7)$、$b \to t(2)$。

1. 初始化 $dist = [s:0, a:2, b:6, t:\infty]$；
2. 选最小 $s$（0）入 $S$；松弛 $a$（2）、$b$（6）；
3. 选最小 $a$（2）入 $S$；松弛 $b$：$2+1=3 < 6$，$dist[b] \to 3$；松弛 $t$：$2+7=9$；
4. 选最小 $b$（3）入 $S$；松弛 $t$：$3+2=5 < 9$，$dist[t] \to 5$；
5. 选最小 $t$（5）入 $S$，结束。

$s \to t$ 的最短路长 5，路径为 $s \to a \to b \to t$——注意第 3 步「经 $a$ 绕到 $b$」反而比直达 $s \to b(6)$ 更短，正是松弛在起作用。<span class="marginnote">「绕路反而更短」正是松弛存在的意义：<strong>直接边不是最短，经中间点的组合才是</strong>。Dijkstra 每确定一个顶点，就把它当「跳板」去刷新邻居——<strong>贪心选点保证每个被确定的 $dist$ 都是最终值</strong>。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 单源最短路 | 一个源点到所有顶点的最短路 |
| 松弛（relax） | 用 $dist[u]+w(u,v)$ 尝试缩短 $dist[v]$ |
| 已确定集合 $S$ | $dist$ 已是最终值的顶点 |
| 前驱数组 pre | 记录最短路「从哪来」 |
| 堆优化 | 用最小堆选「$S$ 外最小 $dist$」 |

**辨析｜易错点：Dijkstra 的「贪心选点」只在非负权下成立。** 负权边可能让「已确定」的点被后续更短的绕路推翻。所以 Dijkstra 的前提是边权非负；有负权，请用 Bellman-Ford（专题篇）。

**一句话**：Dijkstra = 贪心选最小 + 松弛 + 前驱记录——非负单源最短路的标准答案。

## 6 小结

- Dijkstra 解决**非负权单源最短路**：贪心选最小 + 松弛。
- 不变量：加入 $S$ 的顶点 $dist$ 永不再变（依赖非负权）。
- 复杂度：朴素 $O(n^2)$，堆优化 $O((n+e)\log n)$。
- 负权图失效——改用 Bellman-Ford/SPFA。
- 前驱数组 `pre` 记录路径，松弛时同步更新。
- 应用：导航、OSPF 路由、寻路；A\* 是加启发式的变体。
