## 为什么需要广义表

线性表要求所有元素同型。但真实世界的数据常是**异质嵌套**的：一份成绩单的元素可以是「学生的姓名」「学生的各科成绩表」；一本书的目录项可以是「标题」或「下一级目录」。把这些装进同一个表，就得到**广义表（generalized list）**——它的元素既可以是一个**原子（atom）**，也可以是一个**子表（sublist）**。广义表是线性表在「元素类型」上的彻底解放，也是「递归数据结构」的第一次正式亮相：一个广义表可以包含自身吗？可以——它因此成为 LISP 语言数据模型、以及一切嵌套结构（XML、JSON、表达式树）的抽象原型。

## 1 广义表的定义

**广义表（generalized list）**：记作

$$
LS = (a_1, a_2, \cdots, a_n)
$$

其中 $n$ 是表的**长度**，每个 $a_i$ 可以是**单个元素（原子）**，也可以是**一个广义表（子表）**。当 $a_i$ 是子表时用小写字母记表名、用括号括内容，例如：

$$
A = () \qquad B = (e) \qquad C = (a, (b, c)) \qquad D = (B, C) \qquad E = (a, E)
$$

几个要点：

- **空表**：长度为 0 的广义表，如 $A = ()$，它既不是原子也不是子表。
- **长度**：外层括号内直接包含的元素（原子或子表）个数。$C$ 的长度是 2（$a$ 与子表 $(b,c)$）。
- **深度**：广义表括号的**最大嵌套层数**。原子的深度为 0，空表深度为 1，$C$ 的深度为 2，$D$ 的深度为 3。

<span class="marginnote">广义表的「递归性」在于它的定义用到了自身：表由元素组成，元素又可以是表。这是数据结构中第一次明确出现<strong>递归定义</strong>——而递归定义自然导向递归的存储结构与递归的算法，本节与后续两节将一路贯彻。</span>

## 2 表头与表尾

对非空的广义表 $LS = (a_1, a_2, \cdots, a_n)$，定义两个基本运算：

**表头（head）**：第一个元素 $a_1$；
**表尾（tail）**：去掉第一个元素后剩下的**表** $(a_2, \cdots, a_n)$。

注意两个细节：**表头可以是原子也可以是子表**；**表尾一定是表**（哪怕只有一个元素，也用括号括成表）。

**重点：表尾的定义是「递归分治」的钥匙。** 任意广义表都能写成 $\text{head}(LS)$ 与 $\text{tail}(LS)$ 的复合，于是对表的遍历、求深度、求复制，都可以用「处理表头 + 递归处理表尾」来表达。<span class="marginnote">例如对 $B = (e)$：$\text{head}(B) = e$，$\text{tail}(B) = ()$。对 $C = (a, (b,c))$：$\text{head}(C) = a$，$\text{tail}(C) = ((b,c))$——注意表尾是「含一个子表的表」。这是初学者最容易绕晕的地方。</span>

## 3 广义表的递归性与共享性

广义表最奇特的性质来自「元素可以是表」这条规则：

**递归表**：表可以包含自身。如 $E = (a, E)$——一个无限展开的表。它能定义「无限序列」，如 LISP 里的无穷流。
**共享表**：同一子表可以被多个表引用。如 $D = (B, C)$ 中，$B$ 作为子表出现一次，但若另有 $F = (B, B)$，$B$ 被引用两次——**广义表是 DAG（有向无环图）而非严格的树**，因为一个子表可以有多个父表。<span class="marginnote">「<strong>共享</strong>」让广义表不能用「物理复制」来保存：存两份 $B$ 既浪费又破坏语义（递归表更是无法有限复制）。于是存储上必须用「<strong>引用/指针</strong>」，这是下一节广义表存储结构的出发点。</span>

## 4 核心对比表：线性表、数组与广义表

三种「表」结构的定位并排：

| 维度 | 线性表 | 数组 | 广义表 |
| --- | --- | --- | --- |
| 元素类型 | 同型 | 同型 | **原子或子表**（可异质嵌套） |
| 元素个数 | 固定/动态 | 固定 | 动态 |
| 是否递归 | 否 | 否 | **是（表可含表）** |
| 结构形态 | 线性序列 | 多维矩形 | **树 / DAG / 递归** |
| 典型用途 | 通用容器 | 数值计算 | 符号表达式、LISP、JSON |

三条规律：第一，**线性表与数组是「平面」结构，广义表把平面卷曲成了「嵌套」**——复杂度从一维升到任意维。第二，**广义表是线性表在元素类型上的推广**，但一旦允许嵌套，结构就从「序列」变为「树或 DAG」，问题域完全改变。第三，**广义表是 LISP/JSON/XML 的数学抽象**——现代数据结构课里大量「嵌套结构」，都是广义表的工程化身。

## 5 广义表与「从极限到大模型」主线的连接

广义表看起来抽象，却埋伏在整条主线上：

**LISP 与函数式编程**：LISP 程序本身就是广义表，`head` 就是取表头，`tail` 取表尾——`head`/`tail` 的命名直接来自 LISP 的 `car`/`cdr`。
**XML/JSON**：嵌套的元素树就是广义表；「递归下降解析器」就是在遍历一张广义表。
**编译器**：语法树是嵌套结构，表达式 `a + b * c` 的树形表示就是广义表思想的具象化。
**机器学习**：神经网络的「层套层」、大模型的「模块树」，本质都是嵌套结构。<span class="marginnote">「<strong>嵌套</strong>」是现代数据结构的第一关键词：树的递归定义、JSON 的递归 schema、文件系统的目录树，全是广义表的不同方言。学会「用递归的眼光看嵌套」，你就拿到了解读一大半数据结构的地图。</span>

## 6 小结

- 广义表 = 元素可以是**原子或子表**的序列；长度是直接元素个数，深度是最大嵌套层数。
- 空表深度为 1、长度为 0；原子深度为 0。
- **表头**是首元素，**表尾**是去掉首元素后的表（一定是表）。
- 广义表支持**递归表**（含自身）与**共享表**（一子表多父表），结构是树或 DAG。
- 线性表、数组、广义表：平面 → 嵌套，是「元素类型」的逐步解放。
- 广义表是 LISP、JSON、XML、语法树的共同抽象。

在下一节，我们解决广义表「怎么存」——**广义表的存储结构**，用「表头指针 + 表尾指针」的递归结点把嵌套结构装进内存。
