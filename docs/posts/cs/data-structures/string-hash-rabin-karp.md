## 为什么「哈希字符串」是万能加速器

比较两个字符串是否相等是 $O(L)$；但若把字符串**哈希成一个整数**，比较就变成「比两个整数」——$O(1)$。**字符串哈希（string hashing）**把「串的相等性」转成「整数的相等性」：给定 $S$ 与一个基 $B$，定义 $H(S) = (S_0 B^{L-1} + S_1 B^{L-2} + \cdots + S_{L-1}) \bmod M$。于是**任意子串的哈希都能由前缀哈希 $O(1)$ 推出**——这成就了 **Rabin-Karp 算法**（滚动哈希匹配）与无数字符串问题（判等、最长公共子串、回文）。代价是**哈希碰撞**——所以工程里常用「双哈希」把碰撞概率压到可忽略。

## 1 字符串哈希的定义

设字符串 $S = s_0 s_1 \cdots s_{L-1}$、基数 $B$、模 $M$：

$$
H(S) = \left( \sum_{i=0}^{L-1} s_i \cdot B^{L-1-i} \right) \bmod M
$$

把每个字符当成「数字」，串就是一个「$B$ 进制的大整数」对 $M$ 取模。**基 $B$ 要大于字符集大小**（如字母 26 用 131、13331 等经验素数），模 $M$ 常取大素数（如 $10^9+7$）。

**重点：字符串哈希 = 「把字符串编码成 $B$ 进制整数再取模」**——它是「数值哈希」的字符串版，而「$B$ 进制」让子串哈希可以 $O(1)$ 推导。<span class="marginnote">「<strong>$B$ 进制编码 = 可拆分的哈希</strong>」：<strong>因为「$B$ 进制数」的子串就是「整数的高低位切片」，能用乘除 $B^k$ 还原</strong>。<strong>这比普通哈希（如取模多项式）多了一个「子串可推导」的性质</strong>——是 Rabin-Karp 的数学地基。</span>

## 2 公式解析：子串哈希 O(1) 推导

设前缀哈希 $h[i] = H(S[0..i])$，且预处理 $B$ 的幂 $B$（$B^k \bmod M$）。则子串 $S[l..r]$ 的哈希：

$$
H(S[l..r]) = (h[r] - h[l-1] \cdot B^{r-l+1}) \bmod M
$$

- **第一步，读「高位对齐」**：$h[l-1]$ 是「前 $l$ 个字符的编码」，要把它「挪到和 $h[r]$ 对齐」——乘以 $B^{r-l+1}$（子串长度），因为高位的「位权」不同。
- **第二步，读「相减」**：$h[r] - h[l-1] \cdot B^{r-l+1}$ 恰好剩下「$S[l..r]$ 的编码」——整数减法。
- **第三步，读「$O(1)$」**：前缀哈希数组 $O(len)$ 预处理 $O(L)$，之后任何子串哈希 $O(1)$——**这是字符串哈希最值钱的性质**。<span class="marginnote">「<strong>子串哈希 $O(1)$ = 区间问题秒解</strong>」：<strong>判「$S[l1..r1]$ 是否等于 $S[l2..r2]$」从 $O(len)$ 降到 $O(1)$</strong>。<strong>回文、最长公共子串、重复子串——凡是「比子串相等」的问题，字符串哈希都能把内层比较变成 $O(1)$</strong>。</span>

## 3 Rabin-Karp 算法：滚动哈希匹配

**Rabin-Karp** 用「滚动哈希」做模式匹配：

1. 预处理模式串哈希 $H(P)$ 与主串前缀哈希；
2. 滑动窗口：对每个可能的起点 $i$，$O(1)$ 算主串子串 $S[i..i+m-1]$ 的哈希；
3. 若哈希等于 $H(P)$，再**逐字符确认**（防碰撞）。

```c
// Rabin-Karp：滚动哈希匹配，返回首次匹配位置（-1 表示未找到）
int rabinKarp(string S, string P) {
    int n = S.length(), m = P.length();
    if (m > n) return -1;
    long hp = 0, hs = 0, pow = 1;
    for (int i = 0; i < m; i++) {              // 预处理模式串哈希与 B^m
        hp = (hp * B + P[i]) % M;
        hs = (hs * B + S[i]) % M;
        pow = pow * B % M;
    }
    for (int i = 0; i + m <= n; i++) {
        if (hs == hp && S.substr(i, m) == P)   // 哈希相等再逐字符确认
            return i;
        if (i + m < n)                         // 滚动：去掉最高位，加上新字符
            hs = ((hs * B - S[i] * pow + S[i + m]) % M + M) % M;
    }
    return -1;
}
```

**公式解析：Rabin-Karp 的复杂度**

$$
T_{\text{平均}} = O(n + m), \qquad T_{\text{最坏}} = O(nm) \quad \text{（碰撞极多时）}
$$

- **第一步，读「$O(n+m)$」**：预处理 $O(m)$、滑动窗口 $n-m+1$ 个窗口、每个 $O(1)$ 哈希——$O(n)$。
- **第二步，读「碰撞」**：哈希相等但串不等，要逐字符确认——若哈希差（碰撞多），最坏退化成朴素 $O(nm)$。
- **第三步，读「为什么平均仍好」**：好的哈希函数下碰撞概率低，确认次数少——平均线性。<span class="marginnote">「<strong>Rabin-Karp = 哈希筛 + 逐字符确认</strong>」：<strong>哈希先「过滤」掉绝大多数不匹配位置，命中的少数再做精确比较</strong>。<strong>「粗筛 + 精验」是哈希算法的通用模式</strong>——布隆过滤器、Rabin-Karp 都是这个两步走。</span>

## 4 碰撞与双哈希

字符串哈希的碰撞风险：两个不同串可能同哈希。对抗手段：

**双哈希（double hash）**：用两组不同的**基与模数**（如 $(B_1, M_1)$、$(B_2, M_2)$）算两个哈希，都相等才判同——**碰撞概率从 $1/M$ 降到 $1/M^2$**；
**大模数**：$M$ 取 $10^9+7$ 或 $10^9+9$（大素数），单哈希碰撞概率已经 $10^{-9}$ 量级；
**自然溢出**：用 64 位无符号整数自然溢出当模 $2^{64}$——快，但可能被构造碰撞（对抗场景慎用）。

**辨析｜易错点：哈希相等是「必要不充分」**——哈希相等只能说明「很可能相等」，不能证明。**竞赛/工程默认「双哈希 + 大模数」把概率压到可忽略**；要「绝对正确」则回到 KMP 或后缀自动机。<span class="marginnote">「<strong>哈希判等是概率性的</strong>」：<strong>双哈希的碰撞概率 $10^{-18}$ 比硬件故障还低，工程可当「确定」用</strong>。<strong>但面试/出题若禁止「概率算法」，就要用 KMP 等确定性算法</strong>——「概率正确 vs 绝对正确」是哈希系算法的永恒标签。</span>

## 5 字符串哈希的应用全景

**字符串判等 / 去重**：把串哈希成整数，哈希表/集合秒判；
**回文判断**：正反两向哈希，$O(1)$ 判任意子串回文；
**最长公共子串 / 重复子串**：哈希 + 二分答案；
**Rabin-Karp 匹配**：多模式串时尤其高效（多个模式串一起哈希匹配）；
**字典序比较**：哈希 + 二分定位第一个不同字符位。

**重点：字符串哈希把「字符串比较」从 $O(L)$ 变成 $O(1)$**——凡是要「反复比较子串」的问题，先哈希再比较，复杂度立刻降一个量级。<span class="marginnote">「<strong>先哈希，后比较</strong>」是字符串题的通用起手式：<strong>把「比较」预处理成 $O(1)$，剩下的算法骨架就能跑得飞快</strong>。<strong>回文、LCP、重复子串——哈希一上，内层循环全是 $O(1)$</strong>。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 字符串哈希 | $B$ 进制编码取模 |
| 前缀哈希 | 前缀的哈希数组 |
| 子串哈希 | 由前缀哈希 $O(1)$ 推导 |
| 滚动哈希 | 滑动窗口的 $O(1)$ 更新 |
| 双哈希 | 两组基与模数，碰撞概率平方级下降 |

**延伸对照**：字符串哈希的「$B$ 进制编码」与《哈希表》的「除留余数法」同族——都是「大整数 → 桶号」。而「子串可 $O(1)$ 推导」这一性质，让它在「区间比相等」的问题上，扮演了线段树 / 树状数组在「区间和」问题上的角色——都是「预处理 + $O(1)$ 查询」。

## 6 小结

- 字符串哈希 = $B$ 进制编码取模；**子串哈希可由前缀哈希 $O(1)$ 推出**。
- 子串哈希 $O(1)$：$H(S[l..r]) = h[r] - h[l-1] \cdot B^{r-l+1} \pmod M$。
- Rabin-Karp：滚动哈希匹配，平均 $O(n+m)$、最坏 $O(nm)$（碰撞多）。
- 碰撞处理：双哈希、大素数模、自然溢出（慎用于对抗场景）。
- 哈希判等是概率性的——绝对正确需 KMP 等确定性算法。
- 应用：判等、回文、LCP、重复子串、多模式匹配——比较先哈希。
