# 按秩合并与复杂度分析

## 为什么光有路径压缩还不够

路径压缩能「压扁」查询过的路径，但 `Union` 本身仍可能把**高树挂到矮树下**——下一次 `Find` 又要走很长的链。**按秩合并（union by rank）**给每个根记一个「秩（rank）」（≈树高），`Union` 时**把矮树的根挂到高树的根下**，避免树「长高」。两个优化合璧，并查集的复杂度降到**反阿克曼函数 $O(m\alpha(n))$**——这个「实际是常数」的结论，是数据结构课最漂亮的复杂度分析之一。本节讲清按秩合并、两种优化的相互作用，以及那个著名复杂度定理的直觉证明。

## 1 按秩合并：让树长不高的 Union

每个根维护一个「秩」——树的**高度上界**。`Union` 时按秩决定谁挂谁：

```c
int rank[N];                     /* 秩：树高上界 */
void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx == ry) return;
    if (rank[rx] < rank[ry]) parent[rx] = ry;   /* 矮挂高 */
    else if (rank[rx] > rank[ry]) parent[ry] = rx;
    else { parent[rx] = ry; rank[ry]++; }       /* 等高：高度 +1 */
}
```

**重点：按秩合并保证「树高 ≤ $\log_2 n$」**——因为每棵树的结点数随高度指数增长，高度被钉在对数量级。这是 `Find` 均摊 $O(\log n)$（仅按秩、无路径压缩）的保证。<span class="marginnote">「<strong>树高 ≤ $\log_2 n$</strong>」的证明很直观：<strong>一棵高度 $h$ 的树至少有 $2^h$ 个结点</strong>（每次长高，结点数至少翻倍）。所以 $2^h \le n$，$h \le \log_2 n$。<strong>「树高对数」是并查集性能的第一道保险</strong>——即使不做路径压缩，按秩合并已经给出 $O(\log n)$ 的 $Find$。</span>

## 2 两个优化：一个管「找」，一个管「挂」

| 优化 | 作用 | 改变什么 |
| --- | --- | --- |
| 路径压缩 | 把走过的路径压扁 | 降低**未来** `Find` 的代价 |
| 按秩合并 | 矮挂高、树不长高 | 限制**整体**树高的增长 |

**重点：路径压缩「治标」（查一次扁一段），按秩合并「治本」（树长不高）。** 两者独立有效、合体更强——这正是并查集设计的精妙：**两个微小的局部策略，合起来达成近乎常数的全局性能。**<span class="marginnote">「<strong>治标 + 治本 = 最优</strong>」是优化设计的通用模式：<strong>路径压缩处理「已经发生的坏形状」，按秩合并预防「未来产生坏形状」</strong>。类似地，缓存治「慢查」、预取治「慢载」——<strong>一个修过去，一个防未来</strong>。</span>

## 3 公式解析：并查集的复杂度定理

设 $m$ 次操作（Find/Union）、$n$ 个元素，两个优化都用：

$$
T = O(m \, \alpha(n)) \qquad \alpha(n) \text{ 是反阿克曼函数}
$$

- **第一步，读「$\alpha(n)$」**：阿克曼函数 $A(n)$ 增长极快（$A(4)$ 已是天文数字），其反函数 $\alpha(n)$ 增长极慢——**$\alpha(n) \le 4$ 对 $n \le 2^{65536}$ 成立**。
- **第二步，读「为什么几乎线性」**：$O(m\alpha(n))$ 对一切实际输入就是 $O(m)$——**线性时间**。
- **第三步，读「证明的难度」**：这个结论要证明「$m$ 次操作的总复杂度以 $\alpha$ 为界」，用「秩分档 + 势能分析」——是算法分析里公认的硬核。<span class="marginnote">「反阿克曼函数」的存在本身就够震撼：<strong>一个对「可想象的输入」恒小于 5 的函数</strong>。它说明并查集「实际常数」不是经验之谈，而是<strong>严格定理</strong>。想深入这个证明，可以到第二级《计算复杂性》或《算法》的「摊还分析」章节——<strong>「几乎常数」背后站着「极慢增长函数」这座理论山峰</strong>。</span>

## 4 摊销分析的直觉：势能

为什么两个优化合体能到 $\alpha$？直觉是**「树的高度被双重压制」**：

- **势能视角**：把「森林里所有非根结点的父链长度之和」看成势能。路径压缩每次把一段链压扁，势能大幅下降；按秩合并保证势能不会重新长高到 $O(n)$；
- **结论**：$m$ 次操作中，「被压扁的总步数」被势能上界限制，平均到每次操作是 $\alpha$ 级。

**辨析｜易错点：不要把「$O(\alpha)$ 均摊」理解成「每次都是常数」。** 单次 `Find` 最坏可以是 $O(\log n)$（刚 Union 完还没压扁的高树），但**摊到 $m$ 次上**平均是 $\alpha$。**均摊 ≠ 每次**——这是理解摊销分析的关键。<span class="marginnote">「均摊常数 ≠ 每次常数」是摊销分析的常见误区：<strong>单次可以慢（$O(\log n)$），但「慢」的次数被总量限制，摊到每次近常数</strong>。这就像「修路」：修路那天很慢，但之后很多年都快。<strong>摊销分析的数学就是「把修路的成本摊到通行的次数上」</strong>。</span>

## 5 并查集复杂度分析的地位

- **数据结构复杂度谱系的顶端**：并查集是「几乎线性 + 严格证明」的经典，与「比较排序下界」「斐波那契堆」并列算法分析的里程碑；
- **反阿克曼的惊艳**：它的复杂度是 $O(\alpha(n))$，而 $\alpha$ 增长之慢让它成为「比常数还接近常数」的存在；
- **竞赛与工程的双料宠儿**：实现 30 行、性能近乎 $O(1)$，是竞赛图算法（Kruskal、动态连通）与工程（网络、数据库）的标准工具。

**重点：并查集是「少即是多」的完美示范——两个两行的优化，把一个朴素数据结构推到算法分析的天花板。** 它告诉我们：**数据结构的性能上限，常常藏在几个「不起眼的工程细节」里。**<span class="marginnote">「两行优化 × 理论皇冠」是并查集的传奇：<strong>路径压缩一行、按秩合并三行，换来 $O(m\alpha(n))$ 的严格最优</strong>。这是「小改动大收益」的极致案例——也是我们学数据结构最该记住的教训：<strong>优化的价值不在代码量，在它触动的结构本质</strong>。</span>

## 6 小结

- 按秩合并：矮挂高，树高 ≤ $\log_2 n$——`Find` 均摊 $O(\log n)$。
- 路径压缩治「找」，按秩合并治「挂」——两个优化互补。
- 双优化合体：$T = O(m\alpha(n))$，$\alpha(n) \le 5$ 对实际 $n$——近乎线性。
- 摊销 ≠ 每次：单次可 $O(\log n)$，平均近常数。
- 证明用「秩分档 + 势能分析」，是算法分析的硬核经典。
- 30 行实现、近乎 $O(1)$——竞赛与工程的标配。
