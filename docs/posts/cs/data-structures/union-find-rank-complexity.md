## 为什么光有路径压缩还不够

路径压缩能「压扁」查询过的路径，但朴素 union 本身仍可能把**高树挂到矮树下**——下一次 find 又要走很长的链。**按秩合并（union by rank）**给每个根记一个「秩（rank）」（≈树高），union 时**把矮树的根挂到高树的根下**，避免树「长高」。两个优化合璧，并查集的复杂度降到**反阿克曼函数 $O(m\alpha(n))$**——这个「实际是常数」的结论，是数据结构课最漂亮的复杂度分析之一。本节讲清按秩合并、两种优化的相互作用，以及那个著名复杂度定理的直觉证明。

## 1 按秩合并：让树长不高的 Union

每个根维护一个「秩」——树的**高度上界**。union 时按秩决定谁挂谁：

```c
void Union(int x, int y) {
    x = Find(x);  y = Find(y);
    if (x == y) return;
    if (rank[x] < rank[y]) parent[x] = y;          /* 矮树挂到高树下 */
    else if (rank[x] > rank[y]) parent[y] = x;
    else { parent[y] = x; rank[x]++; }             /* 等高时任意挂，秩加 1 */
}
```

**重点：按秩合并保证「树高 ≤ $\log_2 n$」**——因为每棵树的结点数随高度指数增长，高度被钉在对数量级。这是 $2^h \le n$ 均摊 $O(\log n)$（仅按秩、无路径压缩）的保证。

**为什么「秩」记录的是「上界」而非精确高度**：路径压缩会让树的实际高度变小，但被压缩树的根秩仍保留原值——秩只是「这棵树曾经达到过的高度上限」。这个「不精确但单调」的设计是刻意的：**秩只需「只增不减」就能撑起树高对数的证明**，无需实时维护精确高度（那会多花时间）。**「用单调上界代替精确值」是算法设计里的常见取舍**——并查集的秩、B 树的阶、均摊分析里的势能，都是同一个思路：不追求精确，只要求「能证明上界」。<span class="marginnote">「<strong>树高 ≤ $\log_2 n$</strong>」的证明很直观：<strong>一棵高度 $h$ 的树至少有 $2^h$ 个结点</strong>（每次长高，结点数至少翻倍）。所以 $2^h \le n$，$h \le \log_2 n$。<strong>「树高对数」是并查集性能的第一道保险</strong>——即使不做路径压缩，按秩合并已经给出 $O(\log n)$ 的 $Find$。</span>

## 2 两个优化：一个管「找」，一个管「挂」

| 优化 | 作用 | 改变什么 |
| --- | --- | --- |
| 路径压缩 | 把走过的路径压扁 | 降低**未来** find 的代价 |
| 按秩合并 | 矮挂高、树不长高 | 限制**整体**树高的增长 |

**重点：路径压缩「治标」（查一次扁一段），按秩合并「治本」（树长不高）。** 两者独立有效、合体更强——这正是并查集设计的精妙：**两个微小的局部策略，合起来达成近乎常数的全局性能。**

**两者缺一会怎样？** 只有路径压缩、没有按秩合并：极端顺序插入会先长出一条 $n$ 长的链，第一次 find 全链压扁要 $O(n)$；此后虽然快了，但那一次已经爆表。只有按秩合并、没有路径压缩：find 始终 $O(\log n)$，稳稳的但不惊艳。**两者都缺**：退化到 $O(n)$ 的 find——$n$ 次操作 $O(n^2)$。**分别看，两个优化各自只解决了半边；合起来，才共同逼近 $\alpha$ 级**——这就是「治标 + 治本」缺一不可的定量意义。<span class="marginnote">「<strong>治标 + 治本 = 最优</strong>」是优化设计的通用模式：<strong>路径压缩处理「已经发生的坏形状」，按秩合并预防「未来产生坏形状」</strong>。类似地，缓存治「慢查」、预取治「慢载」——<strong>一个修过去，一个防未来</strong>。</span>

## 3 公式解析：并查集的复杂度定理

设 $m$ 次操作（Find/Union）、$n$ 个元素，两个优化都用：

$$
T = O(m \, \alpha(n)) \qquad \alpha(n) \text{ 是反阿克曼函数}
$$

- **第一步，读「$\alpha(n)$」**：阿克曼函数 $A(n)$ 增长极快（$A(4)$ 已是天文数字），其反函数 $\alpha(n)$ 增长极慢——**$\alpha(n) \le 4$ 对 $n \le 2^{65536}$ 成立**。
- **第二步，读「为什么几乎线性」**：$O(m\alpha(n))$ 对一切实际输入就是 $O(m)$——**线性时间**。
- **第三步，读「证明的难度」**：这个结论要证明「$m$ 次操作的总复杂度以 $\alpha$ 为界」，用「秩分档 + 势能分析」——是算法分析里公认的硬核。

**感受一下 $\alpha$ 有多慢**：阿克曼函数 $A(1)=2$、$A(2)=4$、$A(3)=16$、$A(4)=65536$、$A(5)=2^{65536}$——增长快得离谱。反函数 $\alpha(n)$ 是「需要 $n \le A(k)$ 才达到 $k$」的那个最小 $k$。要 $\alpha(n)=5$，得 $n > 2^{65536}$，这个数比可见宇宙的原子数还大。**对一切实际存在的输入，$\alpha(n) \le 4$——「$O(m\alpha(n))$」在工程里就是「线性」**。这就是为什么并查集可以放心当「近似 $O(1)$」用。<span class="marginnote">「反阿克曼函数」的存在本身就够震撼：<strong>一个对「可想象的输入」恒小于 5 的函数</strong>。它说明并查集「实际常数」不是经验之谈，而是<strong>严格定理</strong>。想深入这个证明，可以到第二级《计算复杂性》或《算法》的「摊还分析」章节——<strong>「几乎常数」背后站着「极慢增长函数」这座理论山峰</strong>。</span>

## 4 摊销分析的直觉：势能

为什么两个优化合体能到 $\alpha$？直觉是**「树的高度被双重压制」**：

**势能视角**：把「森林里所有非根结点的父链长度之和」看成势能。路径压缩每次把一段链压扁，势能大幅下降；按秩合并保证势能不会重新长高到 $O(n)$；
**结论**：$m$ 次操作中，「被压扁的总步数」被势能上界限制，平均到每次操作是 $\alpha$ 级。

**辨析｜易错点：不要把「$O(\alpha)$ 均摊」理解成「每次都是常数」。** 单次 find 最坏可以是 $O(\log n)$（刚 Union 完还没压扁的高树），但**摊到 $m$ 次上**平均是 $\alpha$。**均摊 ≠ 每次**——这是理解摊销分析的关键。<span class="marginnote">「均摊常数 ≠ 每次常数」是摊销分析的常见误区：<strong>单次可以慢（$O(\log n)$），但「慢」的次数被总量限制，摊到每次近常数</strong>。这就像「修路」：修路那天很慢，但之后很多年都快。<strong>摊销分析的数学就是「把修路的成本摊到通行的次数上」</strong>。</span>

## 5 并查集复杂度分析的地位

**数据结构复杂度谱系的顶端**：并查集是「几乎线性 + 严格证明」的经典，与「比较排序下界」「斐波那契堆」并列算法分析的里程碑；
**反阿克曼的惊艳**：它的复杂度是 $O(\alpha(n))$，而 $\alpha$ 增长之慢让它成为「比常数还接近常数」的存在；
**竞赛与工程的双料宠儿**：实现 30 行、性能近乎 $O(1)$，是竞赛图算法（Kruskal、动态连通）与工程（网络、数据库）的标准工具。

**重点：并查集是「少即是多」的完美示范——两个两行的优化，把一个朴素数据结构推到算法分析的天花板。** 它告诉我们：**数据结构的性能上限，常常藏在几个「不起眼的工程细节」里。**<span class="marginnote">「两行优化 × 理论皇冠」是并查集的传奇：<strong>路径压缩一行、按秩合并三行，换来 $O(m\alpha(n))$ 的严格最优</strong>。这是「小改动大收益」的极致案例——也是我们学数据结构最该记住的教训：<strong>优化的价值不在代码量，在它触动的结构本质</strong>。</span>

## 6 数值算例：八棵树的并查集长成什么样

空讲「树高 ≤ log n」不如亲手推一遍。对 8 个元素做一组 Union，全程用按秩合并，看树高怎么被钉住。

1. `Union(1,2)`：等高，`parent[2]=1`，`rank[1]=1`；
2. `Union(3,4)`：等高，`parent[4]=3`，`rank[3]=1`；
3. `Union(1,3)`：`rank[1]=rank[3]=1` 等高，`parent[3]=1`，`rank[1]=2`——根 1 的树含 1,2,3,4；
4. `Union(5,6)`、`Union(7,8)`：各自成高 1 的树；
5. `Union(5,7)`：等高，`parent[7]=5`，`rank[5]=2`；
6. `Union(1,5)`：`rank[1]=2`、`rank[5]=2` 等高，`parent[5]=1`，`rank[1]=3`——最终所有元素挂在根 1 下。

**关键观察**：$n=8$，最终根 1 的秩为 3，树高至多 3 = $\log_2 8$。注意「秩」是树高**上界**而非精确高度——当秩 1 的树（实际高度可能 1）挂到秩 1 的根下，父秩变 2，但该路径实际高度不会超过 2。**「秩只增不减、且每增一次结点数至少翻倍」**，所以高度被严格钉在 $\log_2 n$ 内——这就是按秩合并的定量保证。<span class="marginnote">亲手推一遍这 8 个 Union，你会看见「<strong>矮树挂高树、等高才长高</strong>」的全部逻辑：<strong>每棵树的秩从 0 开始，被挂的树秩不变，只有当两棵同秩树合并时父秩才 +1</strong>。<strong>秩就是「树的体重计」</strong>——它只反映「这棵树经历过多少次『等高合并』」。</span>

## 7 术语速查表：并查集复杂度关键概念

| 术语 | 含义 | 要点 |
| --- | --- | --- |
| 秩（rank） | 树高的上界 | 只增不减，随等高合并 +1 |
| 按秩合并 | 矮树挂到高树下 | 树高 ≤ $\log_2 n$ |
| 路径压缩 | 查询时压扁路径 | 降低未来 find 代价 |
| 反阿克曼 $\alpha(n)$ | 阿克曼函数的反函数 | 实际输入下 ≤ 5 |
| 势能分析 | 用势能上界限总代价 | 摊还分析的硬核工具 |
| 均摊 | 总代价 ÷ 操作次数 | 单次可慢、平均近常数 |

**三句收束**：第一，**按秩合并单独使用就给出 $O(\log n)$ 的 find**——「树高对数」是第一道保险。第二，**两个优化合体到 $O(m\alpha(n))$**——路径压缩治「找」、按秩合并治「挂」，互补才到几乎线性。第三，**均摊 ≠ 每次**——单次 find 可以慢，但慢的次数被总量限制。<span class="marginnote">「<strong>两行优化 × 反阿克曼</strong>」是并查集最迷人的地方：<strong>30 行实现，撑起一个「几乎常数、严格可证」的复杂度</strong>。它是「简单结构 + 精妙分析」的教科书——学完这一节，你对「优化」与「摊还分析」都有了直观的坐标。</span>

## 8 小结

- 按秩合并：矮挂高，树高 ≤ $\log_2 n$——find 均摊 $O(\log n)$。
- 仅按秩就 $O(\log n)$，加路径压缩才到 $\alpha$——两者互补。
- 路径压缩治「找」，按秩合并治「挂」——两个优化互补。
- 双优化合体：$T = O(m\alpha(n))$，$\alpha(n) \le 5$ 对实际 $n$——近乎线性。
- 摊销 ≠ 每次：单次可 $O(\log n)$，平均近常数。
- 证明用「秩分档 + 势能分析」，是算法分析的硬核经典。
- 30 行实现、近乎 $O(1)$——竞赛与工程的标配。
- 缺一不可：只有压缩会「首次爆表」，只有按秩是「稳而不惊艳」。
- 数值推演：8 元素 6 次 Union，根秩 3 = $\log_2 8$——树高被钉死。
- 秩是「单调上界」而非精确高度——只增不减即可撑起证明。
