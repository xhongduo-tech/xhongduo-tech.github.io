## 为什么冲突解决决定哈希表的命运

哈希函数再精心，冲突也**不可避免**（鸽子笼原理：表长有限、键域无限）。于是「冲突了怎么办」成了哈希表最核心的工程决策。两大类解法：**开放定址法**——冲突就在表内另找空位；**链地址法**——冲突就在桶下挂链表。前者表内搬家、表满为止，后者无限扩容、代价是额外指针。选错解法，哈希表在装填因子上升时性能会断崖式下跌。本节讲清两种方法的机制、探针序列与装填因子临界点——这是「工程哈希表」的全部关键。

## 1 开放定址法：冲突了就在表里找空位

**开放定址法（open addressing）**：所有元素都存在表内。$H(key)$ 冲突时，按某种**探测序列**在表里继续找空位：

$$
address_i = (H(key) + d_i) \bmod m
$$

按 $d_i$ 的不同，有三种经典探测：

- **线性探测（linear probing）**：$d_i = 1, 2, 3, \cdots$——顺序往后找，可能「堆积」（cluster）；
- **二次探测（quadratic probing）**：$d_i = 1^2, -1^2, 2^2, -2^2, \cdots$——向两侧跳，缓解堆积；
- **伪随机探测**：$d_i$ 取伪随机序列。

**重点：探测序列决定「找空位的顺序」——它是开放定址法的灵魂。**<span class="marginnote">线性探测的「堆积」问题：<strong>连续占用的区域越长，新插入越容易落在区尾，区越长、堆得越凶</strong>——像排队时后来者都挤在队尾。二次探测用「平方跳跃」打散落点，缓解但不根除。</span>

## 2 公式解析：开放定址法的查找与装填因子

线性探测下，查找成功的平均探测次数（设装填因子 $\alpha$）：

$$
ASL_{\text{成功}} \approx \frac{1}{2}\left(1 + \frac{1}{1-\alpha}\right), \qquad
ASL_{\text{失败}} \approx \frac{1}{2}\left(1 + \frac{1}{(1-\alpha)^2}\right)
$$

- **第一步，读 $\alpha \to 0$**：表空时 $ASL_{\text{成功}} \approx 1$——一次命中，理想哈希。
- **第二步，读 $\alpha \to 1$**：$\alpha$ 接近 1 时，分母 $\to 0$，探测次数**爆炸式增长**——表快满时线性探测几乎不可用。
- **第三步，读临界点**：$\alpha = 0.5$ 时成功约 1.5 次、失败约 2.5 次；$\alpha = 0.8$ 时成功约 2.5、失败约 13 次。<strong>开放定址法必须把 $\alpha$ 压在 0.7 以下</strong>。<span class="marginnote">「$\alpha \to 1$ 探测爆炸」是开放定址法的宿命：<strong>表内没有「额外的家」，空位越少、找空位越久</strong>。这迫使开放定址法必须<strong>提前扩容</strong>（$\alpha$ 到 0.7 就翻倍扩容），否则性能雪崩——专题篇《哈希表工程实现》会算扩容这笔账。</span>

## 3 链地址法：冲突了就在桶下挂链表

**链地址法（chaining）**：把同地址的关键字都挂在同一个**桶（bucket）**的链表上：

```c
#define HASHSIZE 100
typedef struct Node {        /* 桶内链表结点 */
    KeyType key;
    struct Node *next;
} Node;

Node *hashtable[HASHSIZE];   /* 表头数组：每个桶是一条链表，初始全空 */

/* 插入：算地址 → 头插到对应桶链表（O(1)） */
void Insert(KeyType key) {
    int addr = Hash(key);
    Node *p = (Node *)malloc(sizeof(Node));
    p->key = key;
    p->next = hashtable[addr];   /* 头插法 */
    hashtable[addr] = p;
}

/* 查找：算地址 → 沿该桶链表线性扫描 */
Node *Search(KeyType key) {
    Node *p = hashtable[Hash(key)];
    while (p && p->key != key) p = p->next;
    return p;
}
```

插入：算地址，链到对应桶的链表头（头插 $O(1)$）；
查找：算地址，沿该桶链表找——桶内线性扫描。

**重点：链地址法没有「表满」概念——冲突越多、链表越长，性能平滑退化。** 装填因子 $\alpha$ 等于平均链长；$\alpha=1$ 时每条链平均 1 个结点，性能几乎最优。<span class="marginnote">链地址法与开放定址法的哲学差异：<strong>开放定址「一个萝卜一个坑，坑满就换坑」，链地址「一个坑装一筐萝卜，筐里排队</strong>」。链地址的链表天然动态，能承受更高的 $\alpha$——工程默认 0.75，就是给链地址法定的。</span>

## 4 公式解析：链地址法的 ASL

设装填因子 $\alpha$（= 平均链长），查找成功/失败的平均比较次数：

$$
ASL_{\text{成功}} \approx 1 + \frac{\alpha}{2}, \qquad
ASL_{\text{失败}} \approx \alpha
$$

- **第一步，读成功**：平均链长 $\alpha$，链内顺序找，平均 $\alpha/2$ 次比较，加一次哈希定位——$1 + \alpha/2$。
- **第二步，读失败**：找不到时扫完整条链，平均 $\alpha$ 次。
- **第三步，与开放定址对比**：$\alpha = 0.75$ 时链地址成功约 1.375 次——**比开放定址同 $\alpha$ 下更稳**，且 $\alpha$ 可以容忍更高。<span class="marginnote">「链地址法的 ASL 与 $\alpha$ 线性相关，开放定址与 $\alpha$ 双曲相关」——这就是<strong>链地址法能扛高装填因子</strong>的数学根源：线性增长 vs 爆炸增长。<strong>工程里默认链地址法</strong>，正是看中它对 $\alpha$ 的宽容。</span>

## 5 辨析｜易错点：两种方法的对比与删除陷阱

| 维度 | 开放定址法 | 链地址法 |
| --- | --- | --- |
| 额外空间 | 无需指针 | 每条链需指针域 |
| 表满 | 有（需扩容） | 无（链可无限） |
| 冲突聚集 | 有（线性探测堆积） | 无（分散各链） |
| 删除 | **麻烦**（不能直接删，需标记） | 容易（链上摘结点） |
| 适用 | 表长可知、$\alpha$ 低的静态场景 | 动态、高装填因子 |

**删除陷阱：开放定址法删除一个元素，不能直接「清空」那个槽。** 因为后续元素的探测路径可能经过它，清空会导致「探测链断裂」，查不到本可查到的元素——必须用「删除标记」占位或重新哈希受影响段。**链地址法则无此问题，链上摘结点即可。**<span class="marginnote">「开放定址删除要打标记」是哈希表最反直觉的坑：<strong>一个槽被清空，所有依赖它做跳板的探测都失效</strong>。这也是为什么动态哈希表（会删）几乎都选链地址法——<strong>删除的便利，是链地址法的隐藏优势</strong>。</span>

**一句话**：冲突解决法的选型口诀——会删除、要动态用链地址法；表长固定、$\alpha$ 低用开放定址。

## 6 小结

- 冲突不可避免（鸽子笼原理），解决法两大类。
- 开放定址法：表内找空位，线性/二次/伪随机探测；$\alpha$ 高则探测爆炸。
- 链地址法：桶下挂链表，平均链长 = $\alpha$，可扛高装填因子。
- 开放定址 ASL（成功）≈ $\frac12(1 + \frac1{1-\alpha})$，链地址 ≈ $1 + \alpha/2$。
- 开放定址删除需标记占位；链地址删除直接摘链。
- 工程默认链地址法；开放定址适合低 $\alpha$ 静态场景。
