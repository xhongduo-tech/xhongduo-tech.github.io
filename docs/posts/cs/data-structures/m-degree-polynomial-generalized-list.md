## 为什么用 m 元多项式收尾本篇

第二篇我们用线性表表示一元多项式，第五篇前几节处理矩阵与广义表。现在把三者拧成一股：**m 元多项式**——如 $P(x, y, z) = x^{10}y^3z^2 + 2x^6y^3z + 3x^5y^2z^2 + \cdots$——的表示。关键思想是**降维嵌套**：把 $x$ 看作主变元，$y, z$ 藏进「系数」里，则 $P$ 是「关于 $x$ 的一元多项式」，而它的每个「系数」又是一个关于 $y, z$ 的 m-1 元多项式。如此递归，m 元多项式被化成**变元链 + 指数序偶表**的嵌套结构——正好就是广义表。本节用它收尾，展示「递归定义 → 递归存储 → 递归算法」的完整闭环。

## 1 降维：m 元多项式看成「多项式中的多项式」

设 $P(x_1, x_2, \cdots, x_m)$ 是 m 元多项式，按主变元 $x_1$ 的幂次展开：

$$
P = \sum_{i=1}^{k} P_i(x_2, \cdots, x_m)\, x_1^{e_i}, \qquad e_1 < e_2 < \cdots < e_k
$$

其中 $P_i$ 是 m-1 元多项式（$x_1$ 的「系数」）。这个结构可以递归：$P_i$ 再按 $x_2$ 展开，直到一元多项式——而一元多项式的「系数」是常数（原子）。

**重点：m 元多项式 = 变元 + 指数 + 子多项式 的三元递归结构。** 这个结构与广义表严丝合缝：每个「系数」是子表，最终的常数是原子。<span class="marginnote">这正如第二篇的序偶表：一元多项式是「（指数, 系数）」序偶表，m 元多项式则是「（变元, 指数, 子多项式）」的嵌套序偶表。<strong>每一层降维，都是同一张「指数→系数」映射</strong>——递归把 m 维问题变成 m 个一维问题的嵌套。</span>

## 2 广义表表示

每个结点表示一个变元的一次幂项，含三个信息：**变元名**、**指数**、**指向系数（子多项式）的指针**。整张广义表由一串「变元-指数」结点组成，末端的系数要么是常数（原子）要么是更低元的子多项式（子表）。

```c
typedef struct MPolyNode {
    char  var;                  /* 变元名，如 'x' */
    int   exp;                  /* 指数 */
    struct MPolyNode *next;     /* 同层下一个幂项 */
    struct {                    /* 系数 */
        int  tag;               /* 0=原子常数，1=子多项式 */
        union {
            float atom;         /* 常数系数 */
            struct MPolyNode *sub;   /* 指向子多项式（子表表头） */
        } u;
    } coef;
} MPolyNode;
```

举例，二元多项式 $P(x,y) = x^2 y + 3 x y^2 + 5$ 可表示为：按 $x$ 展开得 $(x^2, \text{「y 的子多项式」}), (x^1, \text{「y 的子多项式」}), (x^0, \text{常数 } 5)$；其中「y 的子多项式」又是按 $y$ 展开的序偶链。<span class="marginnote">注意这里的结点复用上一节「<strong>扩展线性链表</strong>」的画法：$(x^2, \text{「y 的子多项式」}), (x^1, \text{「y 的子多项式」}), (x^0, \text{常数 } 5)$ 串同层、$y$ 进子层。变元-指数链横向展开，系数子树向下生长——一张表同时表达「多项式的幂次结构」与「变元的嵌套关系」。</span>

## 3 公式解析：m 元多项式的递归求值

对 m 元多项式 $P$ 在给定变元值下求值，递归定义：

$$
P(x_1, \cdots, x_m) = \sum_{i=1}^{k} P_i(x_2, \cdots, x_m)\, x_1^{e_i}
$$

- **第一步，读递归出口**：当某支系数是常数（原子）时，返回该常数值；当变元值代入完毕，只剩常数时求和。
- **第二步，读递推**：对每个「变元-指数」结点，先**递归求值**它的系数子多项式 $P_i$，再乘以 $x_1^{e_i}$，最后对同层所有幂项求和。
- **第三步，体会结构即算法**：求值代码的递归结构，与存储结构的嵌套形态一一对应——**遍历一张广义表，就等于算一个 m 元多项式**。<span class="marginnote">这正是 LISP「<strong>代码即数据、数据即代码</strong>」的雏形：广义表既是多项式的存储，又隐含求值过程。符号计算（Mathematica、SymPy）的求导、合并同类项，本质上都是在这张嵌套表上做递归变换。</span>

## 4 递归算法：按变元求导

对 m 元多项式关于变元 $x_j$ 求偏导，同样递归：沿「变元-指数」链找到 $x_j$ 所在层，对该层的每个结点应用一元求导法则（指数降 1、系数乘指数），其他变元照旧。算法的骨架：

```text
Diff(P, var):
    if P == NULL: return
    if P.var == var:                  # 命中目标变元层
        if P.exp > 0:                 # 一元求导法则：指数降 1、系数乘指数
            产生新幂项 (var, exp-1, 系数 × exp)
        else:                         # 常数项：导数为 0，丢弃
            丢弃该幂项
    else:                             # 其他变元层：穿透进入系数子表
        Diff(P.coef.sub, var)         # 递归求导子多项式
    Diff(P.next, var)                 # 继续处理同层下一个幂项
```

**辨析｜易错点：递归必须「每一层都降维」。** 求 $x_j$ 的偏导时，$x_j$ 只在它对应的那一层出现；其他层的变元-指数结点不能被误动，只能「穿透」进入它们的系数继续找。若在某层误把系数当常数截断，就会漏掉更深层里的 $x_j$——**降维不彻底，求导就错**。<span class="marginnote">这个「穿透」动作在符号计算里叫<strong>沿路径匹配变元</strong>：递归搜索时只改命中的那一层、其余层原样传递。它与文件系统里「沿路径找文件」、XML 里「沿节点路径查找」是同一种递归遍历模式。</span>

## 5 从 m 元多项式看递归的普适性

本节是第五篇的收官，也是「递归思想」的检阅：

第二篇的一元多项式 → 线性表上的归并；
本节的 m 元多项式 → 广义表上的递归分解；
两类问题共享同一句口号：**「把系数看成子问题」**——一元时系数是常数，m 元时系数是子多项式，递归让「系数」这个位置永远可以换成一个新的问题。<span class="marginnote">递归的迁移力就在于此：<strong>把一个结构（多项式、表、树）上的问题，翻译成「该结构某个部位上的更小同类问题」</strong>。掌握了这种翻译，面对任何嵌套结构你都有现成的武器——第六篇的树，正是这个武器最大的靶场。</span>

**一个具体展开的算例。** 三元多项式 $P(x,y,z) = 2x^2 y z + 3x y^2$：

按 $x$ 展开：$(x^2, \text{子多项式 } Q_1), (x^1, \text{子多项式 } Q_2)$；
其中 $Q_1 = 2yz$ 按 $y$ 展开为 $(y^1, \text{子多项式 } 2z)$，再按 $z$ 展开为 $(z^1, \text{常数 } 2)$；
$Q_2 = 3y^2$ 按 $y$ 展开为 $(y^2, \text{常数 } 3)$。

于是整张广义表的形态是：`x^2 → (y^1 → (z^1 → 2))` 与 `x^1 → (y^2 → 3)`——变元逐层嵌套，常数落在叶子。<span class="marginnote">「每一层只处理一个变元」是降维的纪律：<strong>$x$ 层只按 $x$ 的幂次分项，$y$ 藏进系数里；到 $y$ 层再按 $y$ 分项</strong>。<strong>「逐变元、逐层展开」把 m 维问题拆成 m 个一维问题</strong>——与树的多层嵌套结构完全同构。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 主变元 | 当前展开层的变元 |
| 降维 | 把 m 元化成「系数是 m-1 元」 |
| 变元-指数结点 | 一层一个变元一次幂 |
| 穿透递归 | 只改命中层、其余层下钻 |
| 结构即算法 | 存储的递归形态决定算法 |

## 6 小结

- m 元多项式**按主变元递归展开**：系数是 m-1 元子多项式，常数是原子。
- 广义表表示：**变元 + 指数 + 系数（原子或子表）**的三元递归结构。
- 结点复用扩展线性链表：`next` 串同层幂项，`sub` 进系数子层。
- 递归求值：系数先递归求值再乘幂次求和；**结构即算法**。
- 按变元求导：只改命中层、其余层穿透递归，降维要彻底。
- 一元 → m 元，「系数看成子问题」的思想一以贯之，是递归的普适模板。
