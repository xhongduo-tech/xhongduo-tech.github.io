## 为什么堆是「数组里的树」

堆（heap）是优先队列最经典的实现，也是《堆排序》那节的基础。它的全部魔法建立在两个前提上：**堆是一棵完全二叉树**（因此能装进数组、用下标定位父子），**且满足堆序**（父 ≤ 子或父 ≥ 子）。维护堆序只需两个原语：**上浮（sift up）**——插入或变小后向上调整；**下沉（sift down）**——取顶或变大后向下调整。本节把这两个原语讲到骨子里：为什么 `i` 的孩子是 `2i` 和 `2i+1`、上浮下沉各自的步骤、以及它们如何组合出「插入 $O(\log n)$ + 取顶 $O(\log n)$」。

## 1 数组里的完全二叉树

堆用数组存储，靠**下标算术**定位家族关系（下标从 1 起，0 号留空或用哨兵）：

$$
\text{left}(i) = 2i, \qquad \text{right}(i) = 2i+1, \qquad \text{parent}(i) = \lfloor i/2 \rfloor
$$

**重点：堆是「物理上连续、逻辑上成树」——数组下标就是树的编号，不需要任何指针。** 这是完全二叉树性质 5 的直接应用（第六篇），也是堆「空间 $O(1)$、缓存友好」的根源。<span class="marginnote">「<strong>数组即树</strong>」是堆最优雅的地方：<strong>没有指针、没有结点结构，只有 `a[i]` 与 `2i`、`2i+1` 的下标运算</strong>。这和「并查集的 parent 数组」「二叉树的顺序存储」是同一哲学——<strong>用「位置约定」替代「显式指针」</strong>。</span>

## 2 上浮（sift up / bubble up）

**上浮**用于「插入新元素」或「某元素值变小」。以**小根堆**（父 ≤ 子）为例：

1. 新元素先放到数组**末尾**（满足完全二叉树，但不一定满足堆序）；
2. 与父结点比较：若比父小，**与父交换**；
3. 继续向上，直到「不小于父」或到达根。

```c
void SiftUp(int a[], int k) {          /* a[k] 上浮，k 是刚插入/变小的位置 */
    while (k > 1 && a[k] < a[k/2]) {   /* 比父小则交换 */
        swap(a[k], a[k/2]);
        k /= 2;                         /* 上移到父的位置 */
    }
}
```

**重点：上浮是「自底向上、逐层换位」**——每层 $O(1)$，最多 $\log n$ 层，总 $O(\log n)$。插入 = 放末尾 + 上浮。<span class="marginnote">「上浮像气泡」：<strong>小元素一路向上「顶」开大的父结点</strong>。上浮只影响「一条祖先链」——所以插入的成本严格 $O(\log n)$，与其他元素无关。这是「局部调整」思想的体现：<strong>堆序被破坏的地方只有新元素那一条链，修好它即可</strong>。</span>

## 3 下沉（sift down）

**下沉**用于「取出堆顶」或「某元素值变大」。小根堆取顶的过程：

1. 堆顶与**最后一个元素**交换（堆顶出列），堆规模 -1；
2. 新的堆顶可能比孩子大——**与较小的孩子比较**，若大于它则交换；
3. 继续向下，直到「不大于两个孩子」或到达叶子。

```c
void SiftDown(int a[], int k, int n) {   /* a[k] 下沉，堆规模 n */
    while (2*k <= n) {                   /* 有左孩子 */
        int j = 2*k;
        if (j < n && a[j] > a[j+1]) j++; /* 选较小的孩子 */
        if (a[k] <= a[j]) break;         /* 已满足堆序 */
        swap(a[k], a[j]);
        k = j;
    }
}
```

**重点：下沉的关键是「与较小的孩子比较」**——若与较大的孩子换，换上来还是比另一个孩子大，堆序仍被破坏。<span class="marginnote">「<strong>选较小的孩子</strong>」是下沉的唯一陷阱：<strong>大根堆选较大的孩子，小根堆选较小的孩子</strong>。选错方向，交换后堆序依然破坏，而且可能「来回震荡」。判断方向的一句口诀：<strong>「父的相反方向」——小根堆选小、大根堆选大</strong>。</span>

## 4 公式解析：插入与取顶的复杂度

设堆有 $n$ 个元素（树高 $h = \lfloor\log_2 n\rfloor$）：

$$
\begin{aligned}
T_{\text{插入（Push）}} &= O(\log n) \quad \text{（放末尾 + 上浮，最多 } h \text{ 层）} \\
T_{\text{取顶（Pop）}} &= O(\log n) \quad \text{（换顶 + 下沉，最多 } h \text{ 层）} \\
T_{\text{查顶（Peek）}} &= O(1) \quad \text{（就是 a[1]）}
\end{aligned}
$$

- **第一步，读「上浮/下沉都是 $O(\log n)$」**：完全二叉树高 $\log_2 n$，一次调整至多走完一条路径。
- **第二步，读「查顶 $O(1)$」**：堆顶就是数组首位——优先队列「看最小」不花钱，只有「取走」才 $O(\log n)$。
- **第三步，读「均摊与最坏同阶」**：堆操作没有「摊销优化」——每次都是稳定的 $O(\log n)$，最坏与平均相同。<span class="marginnote">「堆的 $O(\log n)$ 是『<strong>铁打的</strong>』」：<strong>不像哈希表平均 $O(1)$ 最坏 $O(n)$，堆的最坏就是 $O(\log n)$</strong>。这给「需要确定性延迟」的场景（实时调度、Dijkstra）以强保证——<strong>稳定可预测的复杂度，是堆不可替代的价值</strong>。</span>

## 5 上浮与下沉的配合使用

两个原语覆盖堆的全部操作：

| 操作 | 动作 | 原语 |
| --- | --- | --- |
| 插入 | 放末尾 + 上浮 | SiftUp |
| 取顶 | 换顶 + 下沉 | SiftDown |
| 删任意元素 | 换到末尾 + 上浮或下沉 | SiftUp/SiftDown |
| 改值（变小时） | 上浮 | SiftUp |
| 改值（变大时） | 下沉 | SiftDown |

**重点：上浮与下沉是堆的「万能修补剂」**——任何「堆序被局部破坏」的情况，判断「往哪走」（变小上浮、变大下沉），调对应原语即可。<span class="marginnote">「<strong>变小上浮、变大下沉</strong>」是堆维护的总口诀：<strong>上浮管「向上找位置」，下沉管「向下找位置」</strong>。掌握了这两个原语，堆的一切操作（插入、删除、改值、建堆）都是它们的排列组合——<strong>堆的全部，就是两板斧</strong>。</span>

## 6 小结

- 堆 = 完全二叉树装进数组：`2i`、`2i+1`、`⌊i/2⌋` 定位家族。
- 上浮：插入/变小时自底向上换位，$O(\log n)$。
- 下沉：取顶/变大时「与较小的孩子」向下换位，$O(\log n)$。
- 查顶 $O(1)$；插入、取顶均 $O(\log n)$ 且最坏同阶。
- 「变小上浮、变大下沉」覆盖全部堆操作。
- 堆是优先队列的经典实现，两板斧撑起整个结构。
