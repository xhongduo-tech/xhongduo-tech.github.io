## 为什么折中：块间有序、块内无序

折半查找快，但要求整表有序——而整表有序的代价是插入删除极贵。顺序查找随便，但 $O(n)$ 太慢。**分块查找（block search）**取两者之长：把表分成若干块，**块与块之间有序**（前一块的最大值 < 后一块的最小值），**块内可以无序**。查的时候先在一块**索引表**里折半（或顺序）定位「在哪一块」，再在块内顺序查找。它的代价介于两者之间，却**允许块内自由增删**——这是数据库索引、文件系统分块的思想雏形。

## 1 分块查找的结构

- **主表**：分成 $b$ 块，每块 $s$ 个元素；块间按关键字有序，块内任意。
- **索引表**：每块对应一个索引项 `(最大关键字, 块的起始地址)`，索引表按最大关键字有序。

```c
typedef struct {
    KeyType maxkey;      /* 本块的最大关键字 */
    int addr;            /* 本块的起始地址 */
} IndexItem;             /* 索引表项 */
```

查找流程两步走：先在索引表中定位「目标可能所在的块」（用折半或顺序），再在块内顺序查找。<span class="marginnote">分块查找是「<strong>两级定位</strong>」：索引表回答「大概在哪一区」，块内扫描回答「具体在哪」。这与图书的「目录→页码」、字典的「部首→条目」、数据库的「索引→行」是同一结构——<strong>一切索引，都是「先缩范围，再细找」</strong>。</span>

## 2 查找过程与复杂度

设 $b$ 块、每块 $s$ 个元素，$n = b \cdot s$：

1. **索引表定位**：索引表长度 $b$，用折半查找（索引表有序），代价 $O(\log b)$；
2. **块内查找**：块内 $s$ 个元素，用顺序查找，代价 $O(s)$。

**重点：分块查找的代价 = 索引查找 + 块内查找，两块相加。** 它不追求任一步最优，而是让两步的总和「够小」。<span class="marginnote">「两步相加」意味着有个「最优分块」问题：<strong>块太小，索引表长（$\log b$ 大）；块太大，块内扫描长（$s$ 大）</strong>。微积分能求出最优块大小在 $\sqrt{n}$ 附近——这正是「数据分块」的通用甜点。</span>

## 3 公式解析：分块查找的 ASL

设块内等概率、索引表用折半查找。查找成功的平均查找长度：

$$
ASL = ASL_{\text{索引}} + ASL_{\text{块内}} \approx \log_2(b+1) - 1 + \frac{s+1}{2}
$$

若索引表用顺序查找，则：

$$
ASL = \frac{b+1}{2} + \frac{s+1}{2} \quad (\text{等概率，索引表顺序找})
$$

- **第一步，读「索引折半 + 块内顺序」**：折半在索引表（$b$ 项）上，$O(\log b)$；顺序在块内（$s$ 项），$(s+1)/2$。
- **第二步，读「最优分块」**：令 $b \approx s \approx \sqrt{n}$（顺序索引时），$ASL \approx \sqrt{n} + 1$——**比分块前的 $n/2$ 快了一个量级**。
- **第三步，读「介于两者之间」**：$O(\sqrt{n})$ 恰在 $O(n)$ 与 $O(\log n)$ 之间——分块查找是「简单性」与「速度」的折中，代价比折半高，灵活性比折半强。<span class="marginnote">「$\sqrt{n}$」这个量级值得记住：<strong>把问题分成 $\sqrt{n}$ 组、每组 $\sqrt{n}$ 个，是最朴素的两级结构</strong>。哈希表的「桶 + 链」、数据库的「页 + 目录」、布隆过滤器的「分段」，都在 $\sqrt{n}$ 附近找平衡点。</span>

## 4 分块查找的动态优势

分块查找真正的卖点不在速度，而在**增删的自由度**：

- **插入**：在目标块内直接插入（块内无序，插哪都行），只更新该块的索引项「最大关键字」——**不需要像整表有序那样大搬家**；
- **删除**：块内删除，同样只改索引。

**辨析｜易错点：插入后块的「最大关键字」可能变，索引项必须同步更新。** 若插入的值大于本块原最大值，索引表的 `maxkey` 要改写；若导致块间顺序破坏（新值超过下一块的最小值），更要多块调整。**「块间有序」是分块查找的生命线，插入时必须守护它。**<span class="marginnote">分块查找的「维护成本」藏在索引更新里：<strong>插入 $O(s)$（块内）+ 索引修正 $O(b)$</strong>。相比「整表有序」的 $O(n)$ 插入，已经省了一个量级——「放宽有序性」的本质，就是把「全局维护」降成「局部维护」。</span>

## 5 分块思想的现代化身

分块查找的「块 + 索引」结构，是现代存储系统的通用骨架：

- **数据库的 B 树 / B+ 树**：页（块）内有序，页间有索引——分块查找的树形升级版（§9.6、专题篇 B 树）；
- **文件系统**：索引块记录文件的数据块位置；
- **哈希的桶**：桶内顺序、桶间哈希定位。

**重点：分块查找是「索引」这一概念的最小模型。** 学会它，「索引到底是什么」就有了直观答案：**一张小表，记着大表的「块」的概要，让查找先缩范围。**<span class="marginnote">B+ 树、倒排索引、LSM 树，全是在回答同一个问题：「<strong>如何用一小块元数据，快速缩小查找范围</strong>」。分块查找是这一切的种子——先缩范围，再细找，永不过时。</span>

## 6 小结

- 分块查找：**块间有序、块内无序**，配索引表（最大关键字 + 起始地址）。
- 查找两步：索引表定位（可折半）+ 块内顺序查找。
- ASL ≈ $\log_2(b+1)-1 + (s+1)/2$（索引折半）或 $(b+s)/2+1$（索引顺序）。
- 最优分块在 $\sqrt{n}$ 附近，$ASL \approx \sqrt{n}$ 量级。
- 插入删除只需局部维护，比整表有序便宜。
- 分块 + 索引是 B 树、哈希桶、文件系统的共同原型。
