## 为什么一般树要「变」成二叉树

二叉树有完整的遍历、线索、性质体系，而一般树（孩子个数不限）没有。好消息是：**任何一般树都能用「孩子兄弟表示法」唯一转换成二叉树，森林也能转换成二叉树**——于是二叉树的全部算法（遍历、线索、查找）都能套用到任何树上。反过来，二叉树也能还原成树或森林。这一「转换」不是花架子：文件系统的目录、家谱、语法分析树，全是「以二叉树形式存储的一般树」。本节讲清三种存储结构，并给出树、森林与二叉树转换的完整规则。

## 1 树的三种存储结构

一般树的孩子个数不定，存储比二叉树麻烦。三种经典方案：

**双亲表示法**：每个结点只存「数据 + 双亲的下标」。找双亲 $O(1)$，找孩子要遍历全表。

```c
// 双亲表示法：结点 = 数据 + 双亲下标
#define MAX_TREE_SIZE 100
typedef struct {
    ElemType data;
    int parent;                    // 双亲位置下标，根为 -1
} PTNode;
typedef struct {
    PTNode nodes[MAX_TREE_SIZE];   // 结点数组
    int n;                         // 结点个数
} PTree;
```

**孩子表示法**：每个结点的孩子用一个链表串起来（单链表存孩子下标）。找孩子快，找双亲要遍历。<span class="marginnote">双亲表示法重「向上」、孩子表示法重「向下」——<strong>存储结构的侧重，直接决定常用运算的快慢</strong>。这与二叉链表/三叉链表的选择逻辑一致。</span>

**孩子兄弟表示法**：每个结点两个指针——`firstChild`（长子）与 `nextSibling`（下一兄弟）：

```c
// 孩子兄弟表示法（二叉链表）：左指针指长子，右指针指下一兄弟
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstChild;     // 指向长子
    struct CSNode *nextSibling;    // 指向下一兄弟
} CSNode, *CSTree;
```

**重点：孩子兄弟表示法让「一般树」长成了「二叉树」的形态。** 每个结点恰好两个指针，整棵树就是一棵二叉树——这就是「树转二叉树」的结构基础。<span class="marginnote">孩子兄弟表示法也叫「左孩子右兄弟」表示法。它的巧妙在于：<strong>把「任意多个孩子」压成「长子 + 兄弟链」两个维度</strong>——第一个孩子往下走，其余孩子往右走，树的层次被压成二叉的左右结构。</span>

## 2 树 → 二叉树的转换规则

把一般树转换为二叉树，就三句话：

1. 在所有**兄弟之间**加一条连线（兄弟互连）；
2. 对每个结点，**只保留它与长子的连线**，删去与其他孩子的连线；
3. 以根为轴，把树**顺时针旋转 45°**，让层次变成左右结构。

转换的实质：**二叉树的「左孩子」= 原树的第一个孩子，「右孩子」= 原树的下一兄弟。** 一个结点在二叉树里的右子树，是原树里它的兄弟及其子孙。

**辨析｜易错点：树转成的二叉树没有右子树？不——根的右子树是森林里的下一棵树。** 对一棵树单独转换，根没有兄弟，所以根的右子树为空；而**森林**转换成二叉树时，把第二棵树作为第一棵树的根的右子树接上，以此类推——森林就成了一棵「根无左、右链极长」的二叉树。<span class="marginnote">「<strong>左子树装孩子、右子树装兄弟/邻居</strong>」是这套转换的密码。反过来，二叉树转回森林时：沿根一直往右走，每一条「右链」断开，就是一个棵独立的树。</span>

## 3 森林 ↔ 二叉树的转换

**森林 → 二叉树**：

1. 每棵树各自转换成二叉树；
2. 把第二棵二叉树作为第一棵的**右子树**、第三棵作为第二棵的右子树……依次拼接。

**二叉树 → 森林**：若根有右子树，沿右链把二叉树「拆断」，每段转成一棵树，直到右子树为空——得到森林。

**重点：转换是「一对一、可逆」的**。树 ↔ 二叉树、森林 ↔ 二叉树都是双射：转换后还能转回去，信息零丢失。<span class="marginnote">「可逆的双射」保证了转换不会改变语义——这在数据交换（JSON/XML 转内存树）、序列化传输里至关重要。<strong>一套存储既能表达树又能表达森林</strong>，正是「结构归约」的价值：把无穷形态归约到一种形态。</span>

## 4 公式解析：三种存储的运算代价

把三种存储结构的核心运算代价并排：

$$
\begin{aligned}
T_{\text{找双亲}} &: \ \text{双亲表示法 } O(1), \quad \text{孩子表示法 } O(n), \quad \text{孩子兄弟 } O(\text{深度}) \\
T_{\text{找孩子}} &: \ \text{双亲表示法 } O(n), \quad \text{孩子表示法 } O(\text{孩子数}), \quad \text{孩子兄弟 } O(\text{长子数}) \\
S_{\text{空间}} &: \ \text{双亲表示法 } O(n), \quad \text{孩子表示法 } O(n + \text{孩子指针}), \quad \text{孩子兄弟 } O(2n)
\end{aligned}
$$

- **第一步，读「双亲」列**：双亲表示法天生为「找双亲」优化——存的就是双亲下标；孩子表示法反着来，找双亲要遍历。
- **第二步，读「孩子兄弟」列**：两个指针域，空间 $O(2n)$；找双亲需沿树往上走 $O(\text{深度})$。
- **第三步，读选型**：静态树、常按双亲回溯 → 双亲表示法；频繁枚举孩子 → 孩子表示法；要享受二叉树算法、树形态会变 → 孩子兄弟表示法。<span class="marginnote">大多数「把树当二叉树用」的场合（并查集的树形表示、红黑树的外层包装、文件系统的 inode 目录项）都选孩子兄弟法——<strong>因为只有它能让一般树直接复用二叉树的成熟算法</strong>。</span>

**一个转换的算例。** 一棵树：根 R，孩子 A、B，A 的孩子 C。转换规则：兄弟互连（A—B）、保留长子（R—A、A—C）、删去其他（R—B）、旋转 45°。结果二叉树：R 的左孩子是 A，A 的右孩子是 B（兄弟），A 的左孩子是 C。

若再加一棵树（根 S），森林 {树1, 树2} 转换：树1 转的二叉树作左，树2 转的二叉树作为树1 根的**右子树**接上——根 R 的右孩子是 S。反过来，从这棵二叉树还原森林：根的右链（R—S）断开，就得两棵树。<span class="marginnote">「<strong>左孩子 = 长子，右孩子 = 兄弟/邻居</strong>」是这套转换的全部密码。<strong>森林的二叉树「根无左、右链长」</strong>——根把每棵树的首结点串在右链上。<strong>转换可逆、信息零丢失</strong>，所以二叉树算法能直接用于一般树。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 双亲表示法 | 存数据 + 双亲下标 |
| 孩子表示法 | 孩子链表 |
| 孩子兄弟表示法 | 长子 + 兄弟，二叉形态 |
| 左孩子 = 长子 | 转换的密码 |
| 右孩子 = 兄弟 | 转换的密码 |

**辨析｜易错点：树转二叉树的「旋转 45°」是示意图，不是实际运算。** 真正的转换是「兄弟互连 + 保留长子 + 删其余」三步，旋转只是帮助可视化「左孩子=长子、右孩子=兄弟」的结果。别把「旋转」当成真实的树操作——它只是把层次压成左右结构的图形化说法。

**一句话**：孩子兄弟表示法让一般树「长成」二叉树，从而复用二叉树的全部算法——结构归约的经典范例。

**补充**：转换可逆、信息零丢失，是「一套存储表达多种结构」的价值所在，序列化与数据交换依赖这个性质。

## 5 小结

- 树的三种存储：**双亲表示法**（找双亲 $O(1)$）、**孩子表示法**（找孩子快）、**孩子兄弟表示法**（两指针、即二叉树形态）。
- 孩子兄弟表示法：`firstChild` 长子 + `nextSibling` 右兄弟，一般树「压」成二叉树。
- 树 → 二叉树：兄弟互连、保留长子、旋转 45°；左孩子 = 长子，右孩子 = 兄弟。
- 森林 → 二叉树：各树转二叉后，依次接为右子树；转换**可逆**。
- 选型：按运算侧重选存储；要复用二叉树算法就选孩子兄弟法。
