## 为什么从「复杂度计算」开始

上一篇我们留下了工具的原型：统计语句频度得到 $T(n)$，再提取量级得到 $O(n)$。这一节把它做成一件趁手的武器——学会**数循环、数递归、数空间**，并背下从 $O(1)$ 到 $O(n!)$ 的量级阶梯。从今往后，每一个数据结构章节的结尾都会甩来一句「插入 $O(n)$、查找 $O(\log n)$」，不理解这套计数法，那些结论就只是一堆记不住的符号。

这套工具还直接通向大模型工程的最前线：Transformer 的自注意力对序列长度 $n$ 是 $O(n^2)$ 的，正是这条复杂度，逼出了 FlashAttention、线性注意力等一大批优化——**复杂度不是纸上谈兵，它直接决定一个系统能不能在真实规模上跑起来**。

## 1 从频度到渐进复杂度：大 O 记号

把语句频度求和，得到关于输入规模 $n$ 的函数 $T(n)$，这一步我们上一篇已经做过。但 $T(n) = 2n + 3$ 这种精确式子太细碎：换台机器、换种写法，系数就变。我们真正关心的是**当 $n$ 趋于无穷时，$T(n)$ 增长的速度有多快**。为此引入**渐进时间复杂度（asymptotic time complexity）**：

**渐进时间复杂度**：如果存在正常数 $c$ 和 $n_0$，使得当 $n \geq n_0$ 时，恒有 $T(n) \leq c \cdot f(n)$，则记 $T(n) = O(f(n))$，称 $f(n)$ 是 $T(n)$ 的渐进上界。

读作「$T(n)$ 的量级不超过 $f(n)$」。它回答的问题是：**$n$ 越来越大时，这个算法的时间至少不会比某个标准函数增长得更快。**

## 2 公式解析：把大 O 的定义拆成三行

大 O 记号是教材里第一个「看起来很吓人」的公式，其实它是一句很朴素的话。把定义拆开看：

$$
\exists\, c > 0,\ n_0 > 0 \quad \text{使得} \quad \forall\, n \geq n_0 : \ T(n) \leq c \cdot f(n)
$$

- **第一步，读懂 $\exists\, c > 0$**：存在一个正的常数 $c$。它允许我们把 $T(n)$ 放大若干倍——因为「倍率」不改变增长趋势，$2n$ 和 $100n$ 都是线性增长。
- **第二步，读懂 $n_0$**：存在一个门槛。只在 $n \geq n_0$ 时要求不等式成立——小规模输入下谁快谁慢没有意义，我们只关心**足够大之后**的长期行为。这吸收了「频度」里那些常数项与低阶项。
- **第三步，读懂 $T(n) \leq c \cdot f(n)$**：$f(n)$ 是 $T(n)$ 的**上界**。它意味着「$T(n)$ 增长得不会比 $f(n)$ 快」。当 $T(n) = 2n + 3$ 时，取 $f(n) = n$，找到 $c = 3$、$n_0 = 1$ 即可验证：$3n \geq 2n + 3$ 对 $n \geq 3$ 恒成立，于是 $T(n) = O(n)$。<span class="marginnote">这一定义是「放缩」思维的第一次露面：把复杂式子放大成简单的标准函数，再比较两者量级。后学《算法设计与分析》里的 $\Theta$、$\Omega$ 记号，都是同一个「存在常数 + 门槛」框架的变体。</span>

一句话直觉：**$O(f(n))$ 是给 $T(n)$ 画的一条「不会被超过」的增长曲线**。

## 3 常见复杂度的量级阶梯

把「标准函数」按增长速度排成一架梯子，越高越慢（规模翻倍时越吃力）：

| 记号 | 名称 | 规模翻倍的代价 | 典型例子 |
| --- | --- | --- | --- |
| $O(1)$ | 常数时间 | 代价不变 | 数组按下标访问 `a[i]`、哈希查成员 |
| $O(\log n)$ | 对数时间 | 只多一步 | 二分查找、二叉树查找 |
| $O(n)$ | 线性时间 | 代价翻倍 | 顺序查找、求前 $n$ 项和 |
| $O(n \log n)$ | 线性对数 | 略多于翻倍 | 归并排序、快排平均、堆排序 |
| $O(n^2)$ | 平方时间 | 代价变四倍 | 双层嵌套循环、冒泡排序 |
| $O(2^n)$ | 指数时间 | 代价平方 | 朴素递归斐波那契、子集枚举 |
| $O(n!)$ | 阶乘时间 | 代价爆炸 | 全排列穷举 |

这条阶梯是数据结构的「估价表」：看到 $O(n^2)$ 与 $O(n \log n)$ 的差距，就明白为什么「会排序」如此重要——把 $10^6$ 个数排好序，$O(n \log n)$ 只要约 $2 \times 10^7$ 次基本操作，$O(n^2)$ 却要 $10^{12}$ 次，差着五个数量级。<span class="marginnote">阶梯值得背下来，因为全教材的复杂度结论都要挂到它上面：顺序表插入 $O(n)$、折半查找 $O(\log n)$、哈希查找平均 $O(1)$、Dijkstra 最短路用堆可到 $O((n+m)\log n)$……知道每个算法「站在哪一级」，才能做跨结构的取舍。</span>

## 4 典型例题：循环的频度拆解

复杂度计算的大部分实战是「数循环」。四个经典套路，一个一个拆。

**套路一：单层循环，线性时间。** 求前 $n$ 项和，循环体执行 $n$ 次，$T(n) = 2n + 3 = O(n)$。上一篇已算过。

**套路二：双层嵌套，平方时间。**

```c
for (i = 0; i < n; i++)          /* 外层循环 n 次 */
    for (j = 0; j < n; j++)      /* 内层循环 n 次 */
        x++;                     /* 内层循环体，共执行 n^2 次 */
```

内层循环体执行次数是 $\sum_{i=0}^{n-1} n = n^2$，于是 $T(n) = O(n^2)$。

**套路三：循环变量折半，对数时间。**

```c
for (i = 1; i <= n; i *= 2)      /* i 每次翻倍：1, 2, 4, 8, ... */
    x++;                         /* 执行约 log2(n)+1 次 */
```

$i$ 依次取 $1, 2, 4, 8, \dots, 2^k$，在第 $k$ 步 $i = 2^k$。循环停止条件是 $2^k > n$，即 $k > \log_2 n$，所以循环约执行 $\lfloor \log_2 n \rfloor + 1$ 次，$T(n) = O(\log n)$。**把 $n$ 翻倍，循环只多跑一步**——这是对数时间最反直觉、也最值钱的地方。

**套路四：每轮规模减半，线性对数。** 归并排序、快速排序这类「每次把一个规模 $n$ 的问题拆成两个规模 $n/2$ 的问题」的算法，递归树共有 $\log_2 n$ 层、每层总工作量 $O(n)$，于是 $T(n) = O(n \log n)$。这个结论在《内部排序》篇会给出严格推导，这里先记住形状：**分而治之把 $O(n^2)$ 压成 $O(n \log n)$**。<span class="marginnote">判断这类问题有个捷径：写出递归式 $T(n) = 2T(n/2) + O(n)$，它解出 $O(n \log n)$；$T(n) = 2T(n/2) + O(1)$ 解出 $O(n)$。主定理（Master Theorem）是《算法设计与分析》里的标准工具，届时会系统学习。</span>

## 5 空间复杂度与递归的代价

**空间复杂度（space complexity）** 记为 $S(n)$，是算法运行所需存储空间随输入规模 $n$ 变化的量级，定义与大 O 同构：$S(n) = O(f(n))$。通常只统计**随 $n$ 增长的额外空间**，不统计输入数据本身占用的空间。

- **原地算法**：只使用常数个辅助变量，$S(n) = O(1)$。交换两个数、冒泡排序都属于这一类。
- **线性辅助空间**：复制一个长度为 $n$ 的数组，需要另一个长度 $n$ 的空间，$S(n) = O(n)$。
- **递归的隐藏空间**：这是最容易漏算的一项。每次递归调用都要在内存中开辟一个**栈帧**，保存返回地址与局部变量；递归结束后栈帧才释放。因此递归算法的空间复杂度由**递归深度**决定，而不是调用总次数。

**辨析｜易错点：** 递归空间是初学者最大的坑。求 $n$ 的阶乘：

$$
f(n) = f(n-1) + 1, \qquad f(1) = 1
$$

每次调用压入一个栈帧，最深时同时存在 $n$ 个栈帧，所以 $S(n) = O(n)$，$T(n) = O(n)$。而朴素递归求斐波那契数 $F(n) = F(n-1) + F(n-2)$，调用**总次数**约为 $2^n$ 量级（时间 $O(2^n)$），但**递归深度**只有 $n$，所以空间仍是 $O(n)$。<span class="marginnote">把「时间看调用总数、空间看调用深度」这两句话钉进脑子，递归复杂度就再也不会算错。斐波那契的时间 $O(2^n)$ 正是第三节阶梯里指数时间的来源。</span>

**辨析｜易错点：** 三个关于复杂度的通用误区。其一，**默认说的是最坏情况**。以顺序查找为例，三种情形差异很大：

| 情形 | 命中位置 | 比较次数 | 复杂度 |
| --- | --- | --- | --- |
| 最好 | 第一个元素 | $1$ | $O(1)$ |
| 平均 | 平均位置 | $\frac{n+1}{2}$ | $O(n)$ |
| 最坏 | 最后一个 / 不存在 | $n$ | $O(n)$ |

不特别说明时，「时间复杂度」指**最坏情况**——它给出的是「不管运气多差，都不会慢过这个量级」的保证，正因如此它最常被引用。其二，**量级吞噬常数**：$O(1000n)$ 与 $O(n)$ 是同一量级，但工程上常数差一千倍照样致命；量级分析回答「规模趋势」，常数优化回答「绝对快慢」，两者都重要、别混用。其三，**别把量级符号当精确值**：$O(n^2)$ 不是「恰好 $n^2$ 次」，而是「上界不超过 $n^2$ 量级」。

## 6 小结

- **大 O 记号**：$T(n) = O(f(n))$ 表示存在 $c, n_0$，使 $n \geq n_0$ 时 $T(n) \leq c \cdot f(n)$——$f(n)$ 是 $T(n)$ 的渐进上界。
- **量级阶梯**：$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)$。
- **数循环四套路**：单层 $O(n)$、双层 $O(n^2)$、折半 $O(\log n)$、分治 $O(n \log n)$。
- **空间复杂度**：原地 $O(1)$、复制 $O(n)$；**递归空间看深度、递归时间看调用总数**。
- **默认最坏情况**，量级吞噬常数，$O$ 是上界而非精确值。
