## 为什么关心「最长路径」

工程的「完工时间」不是所有工序耗时之和，而是**最长的依赖链**——这条链上任何一道工序延误，整个工程都要延误。**关键路径（critical path）**就是 AOE 网（活动在边上的有向无环图）中「源点到汇点的最长路径」。它与最短路径看似对立，但解法同源：在 DAG 上按**拓扑序**递推，一次求出每道工序的「最早开始」与「最晚开始」，两者之差为零的工序就是关键工序。项目管理的 PERT 图、芯片设计的时序分析，都在算这条路径。

## 1 AOE 网与两个关键数组

**AOE 网（Activity On Edge network）**：边表示活动（带权值=耗时），顶点表示事件（活动的完成时刻）。只有一条源点（入度为 0）与一条汇点（出度为 0）。

求关键路径需要两个数组：

- **$ve[i]$（事件最早发生时间）**：从源点沿最长路到达顶点 $i$ 的最早时刻。按**拓扑序**递推：$ve[j] = \max_k (ve[k] + w(k, j))$。
- **$vl[i]$（事件最迟发生时间）**：不影响总工期时，事件 $i$ 最晚发生的时刻。按**逆拓扑序**递推：$vl[k] = \min_j (vl[j] - w(k, j))$。

**重点：$ve$ 用「取 max」，$vl$ 用「取 min」**——早到取最长链、迟走留最宽裕。<span class="marginnote">为什么 $ve$ 取 max？因为事件 $j$ 要等<strong>所有</strong>入边活动都完成才发生，最慢的那个决定它。为什么 $vl$ 取 min？因为事件 $k$ 最迟不能拖到让<strong>任何一个</strong>后继事件 $j$ 延误——最早的 deadline 决定它。<strong>max 是「等所有」、min 是「赶最早」</strong>。</span>

## 2 公式解析：最早与最迟时间

设活动 $a = <k, j>$，持续 $w$。四个量：$ve[j]$、$vl[k]$、活动最早开始 $e(a) = ve[k]$、活动最迟开始 $l(a) = vl[j] - w$。

$$
ve[j] = \max_{k: <k,j> \in E} \{ ve[k] + w(k,j) \}, \qquad
vl[k] = \min_{j: <k,j> \in E} \{ vl[j] - w(k,j) \}
$$

- **第一步，读 $ve$ 递推**：事件 $j$ 的最早时刻 = 所有前驱事件的最早时刻 + 边权，取最大——「等所有人到齐」。
- **第二步，读 $vl$ 递推**：事件 $k$ 的最迟时刻 = 所有后继事件的最迟时刻 - 边权，取最小——「不能耽误任何后继」。
- **第三步，读「余量」**：活动 $a$ 的**时间余量（slack）** $= l(a) - e(a)$。余量为 0 的活动是**关键活动**；关键路径 = 全部由关键活动组成的路径。工期 = $ve[\text{汇点}]$。<span class="marginnote">「余量为零 = 关键」：余量是「这条活动最多能拖多久而不影响总工期」。<strong>关键活动的任何延误都直接延长工期</strong>——这就是项目经理盯住关键路径不放的原因。余量>0 的活动有「缓冲」，可用来调配资源。</span>

## 3 算法流程：两趟递推 + 一挑

关键路径算法三步：

1. **拓扑序求 $ve$**：从源点沿拓扑序，$ve[j] = \max(ve[k] + w)$；
2. **逆拓扑序求 $vl$**：从汇点沿逆拓扑序，$vl[k] = \min(vl[j] - w)$；
3. **逐活动判余量**：$l(a) - e(a) = 0$ 的活动全部挑出来，连成关键路径。

```text
// 关键路径：两趟递推 + 一挑
// 1. 拓扑序求 ve（最早发生时间）
ve[源点] = 0;
for (顶点 v 按拓扑序) for (v 的每条出边 a = <v, j>)
    ve[j] = max(ve[j], ve[v] + w(v, j));

// 2. 逆拓扑序求 vl（最迟发生时间）
vl[汇点] = ve[汇点];
for (顶点 k 按逆拓扑序) for (k 的每条出边 a = <k, j>)
    vl[k] = min(vl[k], vl[j] - w(k, j));

// 3. 逐活动判余量，挑出关键活动
for (每条活动 a = <k, j>)
    if (vl[j] - w(k, j) == ve[k])   // l(a) == e(a)，余量为 0
        标记 a 为关键活动;
```

**重点：$ve$ 和 $vl$ 的依赖方向相反，必须一前一后两趟**——先沿拓扑序（正方向）算最早，再沿逆拓扑序（反方向）算最迟。<span class="marginnote">「正一趟、反一趟」的双向递推，是 DAG 上很多问题的标准结构：求「最早」沿拓扑序、求「最晚」沿逆拓扑序。<strong>关键路径、差分约束的最远/最近可达、概率图的前向后向算法，全是这个两趟模板</strong>。</span>

## 4 公式解析：关键路径的复杂度

$$
T_{\text{关键路径}} = O(n + e) \qquad (\text{邻接表，含拓扑排序})
$$

- **第一步，读拓扑排序**：$O(n+e)$（上一节）。
- **第二步，读两趟递推**：$ve$ 沿拓扑序遍历每条边一次、$vl$ 沿逆拓扑序再遍历每条边一次，均 $O(e)$。
- **第三步，读总代价**：三部分相加 $O(n+e)$——关键路径是线性算法。<span class="marginnote">「关键路径只要 $O(n+e)$」常让人意外——找「最长路径」一般不便宜，但<strong>在 DAG 上最长路径是多项式可解的</strong>（一般图的最长路径是 NP-hard）。「无环」这个约束把指数问题变成线性问题，这就是 DAG 结构红利。</span>

## 5 辨析｜易错点：关键路径 vs 最短路径、最长路径

**关键路径 = DAG 上的最长路径**，不是最短——它求「最慢链」；
但算法与「DAG 单源最短路」同框架：$ve$ 用 max 就是「最长」，用 min 就是「最短路」——**同一趟拓扑递推，改一个运算符就换一个问题**；
**关键路径不要求「汇点唯一」时**：把多个汇点虚拟接到一个超汇点即可统一。

**重点：DAG 上「最长」与「最短」是同一算法的两个运算符。** 拓扑序保证递推顺序合法，max 求最长、min 求最短，复杂度都是 $O(n+e)$。<span class="marginnote">「改一个运算符换一个算法」在 DAG 动态规划里处处可见：最长路、最短路、路径计数（加法）、概率路径（乘法）——<strong>同一拓扑序上的 DP，只是「合并运算符」不同</strong>。到第二级《算法》学 DAG 动态规划时，你会看到这套思想的完整版。</span>

## 6 小结

- AOE 网：边 = 活动、点 = 事件；源点、汇点各一。
- $ve$（最早）沿拓扑序取 max；$vl$（最迟）沿逆拓扑序取 min。
- 活动余量 $= l(a) - e(a)$；余量为 0 即关键活动。
- 关键路径 = 最长依赖链，工期 = $ve[\text{汇点}]$。
- 复杂度 $O(n+e)$；DAG 最长路径是线性可解的。
- 与最短路同框架：「max 求最长、min 求最短」。
