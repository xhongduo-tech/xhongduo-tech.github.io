## 为什么删除是红黑树的「最难关卡」

插入的麻烦是「红红冲突」（局部、好修）；删除的麻烦是「**黑高被破坏**」（全局、难补）。删除一个黑结点，会减少一条路径上的黑结点数——性质 5（黑高一致）被破坏，而修复它需要「**从兄弟那里借黑色**」的整套策略。红黑树删除因此有**四种兄弟情形**，比插入的三类更绕。但回报是明确的：**删除至多 3 次旋转**——比 AVL 删除的 $O(\log n)$ 次旋转划算得多。本节把「删除 = 摘结点 + 双黑修复」拆开，逐一过四类兄弟情形。

## 1 删除的两个阶段

**阶段一（摘结点）**：按 BST 删除。若被删结点有双子，用后继顶替（§9.4 的技巧），实际摘除的是「后继」（至多一个孩子）。**关键是记住「被摘的结点是什么颜色」**：

- 删**红结点**：性质 4、5 都不破坏，**直接结束**——红结点无黑高影响；
- 删**黑结点**：该路径黑高 -1，**需要修复**。

**重点：只有删黑结点才要修复**——这是删除比插入复杂的原因：红结点是「自由的」，黑结点是「神圣的」。<span class="marginnote">「<strong>红删无痕、黑删要补</strong>」是删除的第一判据：<strong>红结点不影响黑高也不引入红红（若两子都黑），删了啥事没有；黑结点一删，它所在路径的黑高立刻少 1</strong>。所以红黑树删除的大半篇幅，全在「补这个被删的黑」。</span>

## 2 双黑：删除修复的「记账」

删黑结点后，用**「双黑（double black）」**记账：把「这个位置欠一个黑」记在顶替它的孩子上（若孩子存在），或记在「空的 NIL 处」。修复的目标是**通过旋转/变色/借色，把双黑「还清」**——让所有路径黑高恢复一致。

**双黑修复的核心思路：向兄弟借黑色。** 设双黑结点为 `x`，兄弟为 `w`。按**兄弟 `w` 的颜色与孩子颜色**分四种情形。

**重点：修复的「记账法」让问题可递推——补不了就把双黑「上移」，直到能补。** 这与插入的「变色上移」异曲同工，只是从「红红」换成了「双黑」。<span class="marginnote">「<strong>双黑 = 一张可以上移的欠条</strong>」：<strong>局部补不了黑，就把「欠黑」记到父结点上（父变双黑），向上找能借的地方</strong>。<strong>「记账 + 上移」是删除修复的通用机制</strong>——它让「补黑」变成「沿路径找到一个能补的兄弟」。</span>

## 3 删除的四种兄弟情形

设双黑 `x` 的兄弟为 `w`（`x` 在左，镜像对称处理）：

- **情形一：兄弟是红色**——`w` 变黑、父变红、对父旋转——**把「红兄弟」变成「黑兄弟」**，转入情形二/三/四；
- **情形二：兄弟是黑色，且兄弟的两个孩子都黑**——**兄弟变红、双黑上移到父**（父若红则变黑结束，父若黑则父成双黑继续）；
- **情形三：兄弟是黑色，兄弟的左孩子红、右孩子黑**——对 `w` 旋转并变色——**把「折线」变成「直线」**，转入情形四；
- **情形四：兄弟是黑色，兄弟的右孩子红**——对父旋转、`w` 继承父色、父与 `w` 的右孩子变黑——**双黑还清，结束**。

**重点：四类情形的路线是「一 → 二 或 三 → 四」**——情形一先变出黑兄弟，情形三先拉直，情形二上移，情形四终结。删除至多 3 次旋转。<span class="marginnote">「<strong>删除四情形，最终都汇到四</strong>」：<strong>情形一造黑兄弟、情形二上移欠条、情形三拉直线、情形四终结</strong>。<strong>比插入多一步「上移」的可能（情形二），但旋转总数仍封顶 3 次</strong>——这就是红黑树删除「最坏也有界」的保证。</span>

## 4 公式解析：删除的复杂度

$$
T_{\text{删除}} = O(\log n) \quad \text{（BST 定位 + 摘除）} + O(\log n) \text{（情形二沿路上移）} + O(1) \text{（至多 3 次旋转）}
$$

- **第一步，读「变色可沿路上移」**：情形二不断把双黑上移，最坏到根——$O(\log n)$ 次变色。
- **第二步，读「旋转封顶 3 次」**：情形一、三各 1 次、情形四 1 次——合计至多 3 次，且「上移」不新增旋转。
- **第三步，与 AVL 对比**：AVL 删除最坏要沿路径多次旋转（$O(\log n)$ 次）；红黑树旋转封顶——**这是红黑树在「增删频繁」场景胜出的又一证据**。<span class="marginnote">「<strong>变色不限次、旋转限次</strong>」是红黑树删除的复杂度真相：<strong>变色便宜可以随便用（$O(\log n)$），旋转贵必须封顶（3 次）</strong>。<strong>这个「便宜操作不限、贵操作限量」的模式，是红黑树设计的一贯思路</strong>。</span>

## 5 辨析｜易错点：插入与删除的对照记忆

| 维度 | 插入 | 删除 |
| --- | --- | --- |
| 要修的冲突 | 红红（局部） | 黑高（全局） |
| 看谁 | 叔叔 | 兄弟 |
| 变色的动作 | 叔红则父叔变色上移 | 兄弟双黑则兄弟变红上移 |
| 旋转封顶 | 2 次 | 3 次 |
| 谁终结 | 情形三（旋转变色） | 情形四（旋转借色） |

**重点：插入看「叔叔」、删除看「兄弟」**——这是两套调整最硬的记忆锚点。插入从「红红冲突」出发、删除从「黑高缺口」出发，触发源不同，观察对象自然不同。<span class="marginnote">「<strong>插看叔、删看兄弟</strong>」一句口诀区分两套调整：<strong>插入冲突在「父与叔」之间（看叔叔的脸色），删除缺口在「结点与兄弟」之间（看兄弟的脸色）</strong>。<strong>抓住「看谁」，红黑树的调整就少了一半的混乱</strong>。</span>

## 6 小结

- 删除两阶段：BST 摘结点 + 双黑修复；只有删黑结点才要修。
- 双黑 = 欠黑记账，可上移；修复 = 向兄弟借黑色。
- 四类情形：红兄弟变黑、黑兄弟双黑上移、折线拉直、直线旋转终结。
- 变色可 $O(\log n)$ 次、旋转封顶 3 次。
- 与 AVL 对比：红黑删除旋转少，增删场景更划算。
- 记忆锚点：插入看叔叔、删除看兄弟。
