## 为什么删除是红黑树的「最难关卡」

插入的麻烦是「红红冲突」（局部、好修）；删除的麻烦是「**黑高被破坏**」（全局、难补）。删除一个黑结点，会减少一条路径上的黑结点数——性质 5（黑高一致）被破坏，而修复它需要「**从兄弟那里借黑色**」的整套策略。红黑树删除因此有**四种兄弟情形**，比插入的三类更绕。但回报是明确的：**删除至多 3 次旋转**——比 AVL 删除的 $O(\log n)$ 次旋转划算得多。本节把「删除 = 摘结点 + 双黑修复」拆开，逐一过四类兄弟情形。

## 1 删除的两个阶段

**阶段一（摘结点）**：按 BST 删除。若被删结点有双子，用后继顶替（§9.4 的技巧），实际摘除的是「后继」（至多一个孩子）。**关键是记住「被摘的结点是什么颜色」**：

- 删**红结点**：性质 4、5 都不破坏，**直接结束**——红结点无黑高影响；
- 删**黑结点**：该路径黑高 -1，**需要修复**。

**重点：只有删黑结点才要修复**——这是删除比插入复杂的原因：红结点是「自由的」，黑结点是「神圣的」。

把「红删无痕、黑删要补」再拆细一点：**删红结点要求它的两个孩子都是黑**（否则红红冲突），此时删掉它不影响任何路径的黑高，直接收工；而黑结点的孩子可以是任意颜色——正因为黑结点的「牺牲」会牵动整条路径，修复才不得不看兄弟的脸色。**想清「红自由、黑神圣」，删除流程的第一步就不会走错**——先判颜色，再决定进不进入修复循环。<span class="marginnote">「<strong>红删无痕、黑删要补</strong>」是删除的第一判据：<strong>红结点不影响黑高也不引入红红（若两子都黑），删了啥事没有；黑结点一删，它所在路径的黑高立刻少 1</strong>。所以红黑树删除的大半篇幅，全在「补这个被删的黑」。</span>

## 2 双黑：删除修复的「记账」

删黑结点后，用**「双黑（double black）」**记账：把「这个位置欠一个黑」记在顶替它的孩子上（若孩子存在），或记在「空的 NIL 处」。修复的目标是**通过旋转/变色/借色，把双黑「还清」**——让所有路径黑高恢复一致。

**双黑修复的核心思路：向兄弟借黑色。** 设双黑结点为 x，兄弟为 s。按**兄弟 s 的颜色与孩子颜色**分四种情形。

**重点：修复的「记账法」让问题可递推——补不了就把双黑「上移」，直到能补。** 这与插入的「变色上移」异曲同工，只是从「红红」换成了「双黑」。

**为什么「双黑」能上移而不破坏黑高？** 双黑结点的本质是「该位置应该有两个黑」。把它上移到父结点，等价于把「父结点记成双黑」——整条路径的黑高仍然是「正确的」，只是欠账换了个地方。**记账的妙处在于：欠账可以在路径上自由移动而不改变黑高总量**，直到找到一个「红结点」或「能借色的兄弟」把它一次还清。这正是删除修复「有界」（旋转 ≤ 3 次）的深层原因——变色只是记账移动，不花旋转预算。<span class="marginnote">「<strong>双黑 = 一张可以上移的欠条</strong>」：<strong>局部补不了黑，就把「欠黑」记到父结点上（父变双黑），向上找能借的地方</strong>。<strong>「记账 + 上移」是删除修复的通用机制</strong>——它让「补黑」变成「沿路径找到一个能补的兄弟」。</span>

## 3 删除的四种兄弟情形

设双黑 x 的兄弟为 s（x 在左，镜像对称处理）：

**情形一：兄弟是红色**——s 变黑、父变红、对父旋转——**把「红兄弟」变成「黑兄弟」**，转入情形二/三/四；
**情形二：兄弟是黑色，且兄弟的两个孩子都黑**——**兄弟变红、双黑上移到父**（父若红则变黑结束，父若黑则父成双黑继续）；
**情形三：兄弟是黑色，兄弟的左孩子红、右孩子黑**——对 s 旋转并变色——**把「折线」变成「直线」**，转入情形四；
**情形四：兄弟是黑色，兄弟的右孩子红**——对父旋转、s 继承父色、父与 s 的右孩子变黑——**双黑还清，结束**。

**重点：四类情形的路线是「一 → 二 或 三 → 四」**——情形一先变出黑兄弟，情形三先拉直，情形二上移，情形四终结。删除至多 3 次旋转。<span class="marginnote">「<strong>删除四情形，最终都汇到四</strong>」：<strong>情形一造黑兄弟、情形二上移欠条、情形三拉直线、情形四终结</strong>。<strong>比插入多一步「上移」的可能（情形二），但旋转总数仍封顶 3 次</strong>——这就是红黑树删除「最坏也有界」的保证。</span>

## 4 公式解析：删除的复杂度

$$
T_{\text{删除}} = O(\log n) \quad \text{（BST 定位 + 摘除）} + O(\log n) \text{（情形二沿路上移）} + O(1) \text{（至多 3 次旋转）}
$$

- **第一步，读「变色可沿路上移」**：情形二不断把双黑上移，最坏到根——$O(\log n)$ 次变色。
- **第二步，读「旋转封顶 3 次」**：情形一、三各 1 次、情形四 1 次——合计至多 3 次，且「上移」不新增旋转。
- **第三步，与 AVL 对比**：AVL 删除最坏要沿路径多次旋转（$O(\log n)$ 次）；红黑树旋转封顶——**这是红黑树在「增删频繁」场景胜出的又一证据**。

**工程意义再放大**：Linux 内核、Java `TreeMap`、C++ `std::map` 之所以偏爱红黑树而非 AVL，正是因为它「**写操作旋转封顶**」——在写多读少的场景（进程调度、缓存淘汰、日志索引）里，删除/插入的旋转次数直接决定吞吐。AVL 读更快（更矮更平衡），红黑写更快（旋转有界）——**选择平衡树，先问自己的负载是读多还是写多**。<span class="marginnote">「<strong>变色不限次、旋转限次</strong>」是红黑树删除的复杂度真相：<strong>变色便宜可以随便用（$O(\log n)$），旋转贵必须封顶（3 次）</strong>。<strong>这个「便宜操作不限、贵操作限量」的模式，是红黑树设计的一贯思路</strong>。</span>

## 5 辨析｜易错点：插入与删除的对照记忆

| 维度 | 插入 | 删除 |
| --- | --- | --- |
| 要修的冲突 | 红红（局部） | 黑高（全局） |
| 看谁 | 叔叔 | 兄弟 |
| 变色的动作 | 叔红则父叔变色上移 | 兄弟双黑则兄弟变红上移 |
| 旋转封顶 | 2 次 | 3 次 |
| 谁终结 | 情形三（旋转变色） | 情形四（旋转借色） |

**重点：插入看「叔叔」、删除看「兄弟」**——这是两套调整最硬的记忆锚点。插入从「红红冲突」出发、删除从「黑高缺口」出发，触发源不同，观察对象自然不同。<span class="marginnote">「<strong>插看叔、删看兄弟</strong>」一句口诀区分两套调整：<strong>插入冲突在「父与叔」之间（看叔叔的脸色），删除缺口在「结点与兄弟」之间（看兄弟的脸色）</strong>。<strong>抓住「看谁」，红黑树的调整就少了一半的混乱</strong>。</span>

## 6 数值算例：亲手走一遍「情形二」

空谈四种情形，不如一棵具体的树。设红黑树如下（下标 B=黑、R=红）：根 50B，左孩子 30R（它的两个孩子 20B、40B），右孩子 70R（它的两个孩子 60B、80B），叶子均为黑色 NIL。检查黑高：从根到任一 NIL 都是「50B → 30R → 20B/40B → NIL」共 2 个黑结点，合法。

**删除 20（黑色叶结点）**：

1. **摘结点**：20 被删，其位置由 NIL 顶替；20 是黑 → 该路径黑高减 1，产生**双黑**。设双黑位置为 $x$，其兄弟是 40（黑色）。
2. **判定情形**：兄弟 40 是黑色，且 40 的两个孩子都是黑色 NIL → **情形二**。
3. **执行情形二**：兄弟 40 变红，双黑**上移**到父结点 30。
4. **看 30**：30 本是红色 → 红结点被标记为双黑时，直接**变黑**即可还清双黑，过程结束。

最终树：50B、30B（由红变黑）、40R（由黑变红）、20 消失、70R/60B/80B 不变。**验证黑高**：左路「50B → 30B → NIL」2 个黑；「50B → 30B → 40R → NIL」2 个黑；右路「50B → 70R → 60B → NIL」2 个黑。完全一致——**双黑在红父处一步还清，零旋转**。<span class="marginnote">这个例子演示了删除最温柔的情形二：<strong>黑兄弟 + 双黑孩子 + 红父 → 兄弟变红、父变黑，一步收工</strong>。若父是黑，双黑就要继续上移，可能一路到根——<strong>「最坏沿路径变色、旋转至多 3 次」正是从这类例子里归纳出来的</strong>。</span>

**再做一次「情形四」收尾的速记**：若兄弟 40 的右孩子是红（情形四），则对 30 做一次左旋、40 继承父色、30 与 40 的右孩子变黑——双黑立刻还清且旋转恰好 1 次。**情形一（红兄弟）先转成黑兄弟，情形三（折线）先拉成直线，两者最终都汇入情形四**。

## 7 术语速查表：红黑树删除关键概念

| 术语 | 含义 | 归属 |
| --- | --- | --- |
| 双黑 | 删除黑结点后「欠一个黑」的记账 | 修复的起点 |
| 情形一 | 兄弟为红 → 转黑兄弟 | 过渡 |
| 情形二 | 兄弟黑且双孩子黑 → 兄弟变红、双黑上移 | 可递推 |
| 情形三 | 兄弟黑、近侄红 → 拉直成直线 | 过渡 |
| 情形四 | 兄弟黑、远侄红 → 旋转终结 | 终结 |
| 旋转 | 左旋/右旋，删除至多 3 次 | 与 AVL 的对比点 |

**三句收束**：第一，**「红删无痕、黑删要补」**是删除的第一判据，只有删黑结点才进修复流程。第二，**修复本质是「借色 + 上移」**——借得到就旋转终结，借不到就把双黑上移一层继续。第三，**变色不限次、旋转封顶 3 次**，这是红黑树删除优于 AVL 删除的结构性原因。<span class="marginnote">把「<strong>借色上移</strong>」与插入的「<strong>变色上移</strong>」并列，你会发现红黑树的两种修复其实是同一种旋律：<strong>局部修不好就向上层找后援</strong>。理解这个共性，红黑树的两套调整就变成了一套思想。</span>

## 8 小结

- 删除两阶段：BST 摘结点 + 双黑修复；只有删黑结点才要修。
- 读多选 AVL、写多选红黑树——旋转有界是红黑树的核心卖点。
- 双黑 = 欠黑记账，可上移；修复 = 向兄弟借黑色。
- 四类情形：红兄弟变黑、黑兄弟双黑上移、折线拉直、直线旋转终结。
- 变色可 $O(\log n)$ 次、旋转封顶 3 次。
- 与 AVL 对比：红黑删除旋转少，增删场景更划算。
- 记忆锚点：插入看叔叔、删除看兄弟。
- 数值验证法：手画一棵 6 结点红黑树删一个黑叶，按「判定 → 情形 → 验证黑高」三步走。
- 情形一/三只做「转黑兄弟 / 拉直」的过渡，最终都汇入情形四终结。
- 双黑可沿路径上移到根；根变双黑时直接改黑即可（根无兄弟）。
- 删除后必查三性质：根黑、红红不邻、各路径黑高一致。
- 情形二在红父处一步还清、零旋转；黑父则双黑上移继续。
