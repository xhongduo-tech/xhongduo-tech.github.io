## 为什么归并的顺序也要优化

$k$ 路归并中，若各初始有序段的长度**不相等**，归并的先后顺序会影响总 I/O。例如三段长为 1、2、3：先并 1 和 2（读 3 写 3），再并 3 和 3（读 6 写 6），共读写 18 单元；先并 2 和 3（读 5 写 5）再并 1 和 5（读 6 写 6），共读写 22。**短段先并更省**。把归并过程画成树——叶子是有序段、内部结点是归并——则**总 I/O 次数 = 带权路径长度（WPL）**。于是「最省归并顺序」等价于「WPL 最小」，而 WPL 最小的 $k$ 叉树正是**赫夫曼树**。**最佳归并树（optimal merge tree）= 赫夫曼树在外部排序里的重演**。

## 1 归并树与带权路径长度

把归并过程画成一棵树：**叶子 = 初始有序段（权 = 段长），内部结点 = 归并产生的段（权 = 两子树段长之和），根 = 最终大段**。

**归并树的总 I/O 代价 = 每个叶子被「读 + 写」的次数 × 它的长度。** 叶子在树中的深度 = 它参与归并的趟数（每趟读写一次），于是：

$$
\text{总 I/O} = \sum_{i} (\text{叶子 } i \text{ 的段长} \times \text{叶子 } i \text{ 的深度}) = WPL
$$

**重点：归并树的 WPL 就是外部排序的 I/O 总量——要省 I/O，就求最小 WPL。** 这和《赫夫曼树》的结论完全同构：段长长的（权大）应放在浅层（少归并几趟）。<span class="marginnote">「<strong>归并树的 WPL = I/O 总量</strong>」把外部排序的代价翻译成了树的性质——这是「数据结构=代价模型」的绝佳例子。<strong>我们曾在《赫夫曼树》里求 WPL 最小，如今同一个问题以「归并顺序」的面貌再现</strong>——学了赫夫曼树，最佳归并树几乎不费新力。</span>

## 2 赫夫曼树：最短的归并顺序

**最佳归并树**：用赫夫曼算法构造——**每次把权值最小的 $k$ 棵树合并成一棵**，得到 $k$ 叉赫夫曼树，其 WPL 最小，即 I/O 最少。

对二路归并：每次并两个最短段，与赫夫曼树完全一致。

**辨析｜易错点：$k$ 叉赫夫曼树需要「补 0」使叶子数满足条件。** $k$ 叉赫夫曼树的叶子数 $n$ 必须满足「$n - 1$ 能被 $k - 1$ 整除」（每个内部结点有 $k$ 个孩子，$n$ 个叶子 ⇒ $n = (k-1) \times \text{内部结点数} + 1$）。若不满足，**补若干权为 0 的虚段**，凑齐条件——0 权虚段不增加 I/O，只是让树结构合法。<span class="marginnote">「补 0 虚段」是 $k$ 叉赫夫曼树的经典细节：<strong>$k$ 叉树每加一个内部结点，叶子净增 $k-1$ 个，所以叶子数必须 ≡ 1 (mod $k-1$)</strong>。不够就补 0——0 权段在归并里不产生读写，只是「占位」。这个细节在专题篇《最佳归并树》的变体题里是考点。</span>

## 3 公式解析：二路最佳归并树的总代价

设初始段长为 $l_1, l_2, \cdots, l_n$，二路归并。赫夫曼树给出的最小 I/O：

$$
\text{最小 I/O} = WPL_{\min} = \sum_{i} l_i \times depth(\text{叶子 } i)
$$

- **第一步，读「权大浅放」**：段长长的叶子放浅层（少归并）、段长短的放深层——与赫夫曼树「大权近根」同一原则。
- **第二步，算例子**：段长 1、2、3、4：先并 1+2=3，再并 3+3=6，再并 6+4=10，总 I/O = 读 + 写 = 2 × (3+6+10) = 38（每趟读写两遍），而 WPL = 1×3 + 2×3 + 3×2 + 4×1 = 19，总 I/O = 2 × WPL = 38——吻合。
- **第三步，读「为什么 I/O = 2×WPL」**：每次归并读一遍、写一遍，WPL 统计的是「读写一遍」的代价，所以总 I/O = 2 × WPL。<span class="marginnote">「总 I/O = 2 × WPL」这个「×2」来自「归并要读 + 写」。<strong>看代价时先分清「算 WPL 还是算 I/O」</strong>——差一个因子 2，但优化方向（WPL 最小）不变。<strong>优化指标差常数倍不改变决策</strong>，这也是算法分析里「常数无关」的一个注脚。</span>

## 4 归并树与赫夫曼树：同一棵树的两种身份

| 维度 | 赫夫曼树（§6.7） | 最佳归并树 |
| --- | --- | --- |
| 叶子权 | 字符频度 | 有序段长度 |
| 内部结点 | 两权之和 | 两段归并后的长度 |
| 优化目标 | WPL 最小（编码最短） | WPL 最小（I/O 最少） |
| 构造算法 | 每次合并两个最小权 | 每次合并 k 个最小段 |
| 应用 | 赫夫曼编码 | 外部排序归并顺序 |

**重点：最佳归并树与赫夫曼树是同一个算法、两个应用——「每次合并最小的」这个贪心，同时最小化编码长度与归并 I/O。** 学会赫夫曼树，最佳归并树只是「换个权值含义」。<span class="marginnote">「同一个数学结构，服务多个问题」是数据结构最迷人的地方：<strong>卡特兰数串起二叉树与出栈序列，赫夫曼树串起编码与归并</strong>。<strong>识别「这是同一个结构」比记住两个孤立算法更有价值</strong>——这也是为什么我们要在教材之外反复做「结构复用」的连接。</span>

## 5 外部排序总优化的闭环

回顾整篇外部排序，五个优化点环环相扣：

1. **§11.2**：增加路数 $k$ → 趟数 $\log_k m$ 降；
2. **§11.3**：败者树 → 多路选最小 $O(\log k)$；
3. **§11.4**：置换-选择 → 初始段变长、段数减半；
4. **§11.5**：最佳归并树 → 段长不等时选最优归并顺序；
5. **块大小 / 缓冲**：I/O 次数与内存的平衡。

**重点：外部排序的全部优化，最终都指向同一目标——「减少磁盘读写」。** 趟数、段长、路数、归并顺序，四管齐下把 I/O 压到最低。<span class="marginnote">「<strong>系统优化是多变量的合力</strong>」是本节给我们的总启示：<strong>没有单点魔法，只有环环相扣</strong>。外部排序的五步优化，和「数据库查询优化」「大模型推理优化」一样，都是在「资源约束下做多维度的联合调优」——<strong>学数据结构，学的其实是系统思维</strong>。</span>

## 6 小结

- 归并树：叶子 = 初始段，内部结点 = 归并结果；总 I/O = WPL。
- 最佳归并树 = 赫夫曼树：每次合并最小段，WPL 最小、I/O 最少。
- $k$ 叉赫夫曼树需「补 0 虚段」满足叶子数条件。
- 总 I/O = 2 × WPL（读一遍 + 写一遍）。
- 最佳归并树与赫夫曼树是同一算法、两个应用。
- 外部排序五优化环环相扣，目标统一：减少磁盘读写。
