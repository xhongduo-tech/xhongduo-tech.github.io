## 为什么从「钉死术语」开始

上一篇《什么是数据结构》给了我们一套直觉：数据结构 = 元素 + 关系 + 运算，逻辑结构分四类，存储结构分四种。直觉让我们「看得懂」，但计算机科学要求「说得准」——一个概念含糊，写出来的程序就会在边界处出错。这一节的任务，是把术语钉成砖石：用集合论的语言重新定义数据结构，再厘清「数据结构」「数据类型」「抽象数据类型」这三个最容易被混为一谈的词。

这恰好呼应第一级《集合的概念》的路径：康托尔先给描述性定义，后人再把它公理化。数据结构也一样——先描述，再形式化。

## 1 数据结构的形式化定义：二元组 (D, S)

严蔚敏用集合论把「数据结构」钉成一个**二元组**：

**数据结构形式化地定义为一个二元组 $(D, S)$**，其中 $D$ 是数据元素的有限集，$S$ 是 $D$ 上关系的有限集。

用学生档案表举例：$D$ 就是「全体学生记录」这个集合，$S$ 就是「按学号从小到大排成一行」这个线性关系。$S$ 中的每一个关系，描述 $D$ 中元素之间的一种联系方式。<span class="marginnote">关系是集合论的标准概念：集合 $D$ 上的一个二元关系，是 $D \times D$ 的一个子集。集合结构对应「$S$ 为空」的情形，线性结构对应「一个使元素前后有序的关系」，树、图则各有更复杂的关系——四种逻辑结构只是 $S$ 的四种典型取法。</span>

用一个具体的线性表把二元组落到纸面。设学生表 $D = \{s_1, s_2, s_3\}$，线性关系

$$
R = \{ \langle s_1, s_2 \rangle, \langle s_2, s_3 \rangle \}
$$

其中有序对 $\langle s_1, s_2 \rangle$ 表示「$s_1$ 紧排在 $s_2$ 之前」。于是 $(D, R)$ 精确刻画了「按学号排成一行」这个逻辑结构——不多不少，正是一对一的前驱后继关系。若把 $R$ 换成父子关系就成了树，换成任意两两相连的边就成了图。

这个二元组里**没有存储**：$(D, S)$ 只描述逻辑结构。把逻辑结构翻译进内存，关系只有两种映象方式——**顺序映象**（用存储位置的相邻表示逻辑相邻，对应顺序存储结构）与**链式映象**（用指针等附加信息显式指出逻辑相邻，对应链式存储结构）。**先有 $(D, S)$ 的关系蓝图，再谈内存怎么摆**——这是本章反复出现的节奏。

**辨析｜易错点：逻辑结构不是存储结构。** 初学者最常犯的错，是把「存储方式」当成「结构本身」：看到数组就说线性表，看到链表就说线性结构。实际上，同一个线性表逻辑结构，既可以用数组实现（顺序映象），也可以用链表实现（链式映象）；反过来，同一个数组存储既可以装线性表，也可以当图的邻接矩阵。**判定逻辑结构只看关系，不看内存**——$(D, S)$ 里没有内存，存储是另一层的选择。

## 2 数据运算：加工型与引用型

定义在数据结构上的运算，按是否改变结构本身，可分成两类：

- **加工型运算（processing operation）**：会改变数据结构的「值」，如插入（insert）、删除（delete）、修改（modify）。
- **引用型运算（retrieval operation）**：不改变结构，只读取信息并返回，如查找（search）、读取（access）、遍历（traverse）。

这个分类的意义在工程上。引用型运算常常是加工型运算的**子过程**：删除一个结点，往往先「查找」到它再删；修改一条记录，也是先「定位」再改。于是设计数据结构时，通常先保证引用型运算高效，再让加工型运算复用它们。<span class="marginnote">很多教材也把加工型运算叫「改变型」、引用型运算叫「只读型」。这个分类不是考试重点，却是一把实用的尺子：遇到一个运算，先问「它改不改变结构」，再决定用哪类分析去衡量它的代价。</span>

## 3 数据类型：值集 + 操作集

从数据结构往下走一层，是程序设计语言里的概念——**数据类型（data type）**：

**数据类型是一个值的集合和定义在这个值集上的一组操作的总称。**

C 语言里的 `int` 就是一个数据类型：它的值是 $\{ \dots, -2, -1, 0, 1, 2, \dots \}$ 的一个子区间，它上的操作有加、减、乘、除、取模、比较等。按值能否再分解，数据类型分两类：

**原子类型（atomic type）**：值不可再分解的类型，如 `int`、`float`、`char`、`double`。
**结构类型（structure type）**：值由若干成分按某种结构组成，且可以分解的类型，如 C 的数组、结构体、共同体。

还有一个反直觉的点值得停下来想：**C 语言里的 `int` 也是「抽象」的**。硬件并不认识整数——内存里只有高低电平。是语言规定「这 4 个字节按补码解读、按整数运算」，类型才被制造出来。所谓数据类型，本质是语言层替我们钉死的一组「值集 + 操作集」约定。<span class="marginnote">这正是「抽象」最朴素的样子：把「如何用二进制表示数、如何用加法器相加」全部藏进 `int` 的壳里，我们只消费「整数 + 加减乘除」这个干净接口。语言设计者做的，就是造一个又一个这样的壳。</span>

用一段 C 语言把「原子 vs 结构」落到实处：

```c
/* 原子类型：int、float——值「整块」，不可再分解 */
int id = 2024001;
float score = 95.5f;

/* 结构类型：结构体——值可分解为学号、姓名、成绩 */
typedef struct {
    int id;          /* 学号：原子 */
    char name[20];   /* 姓名：字符数组，可分解 */
    float score;     /* 成绩：原子 */
} Student;

Student s = {2024001, "张三", 95.5f};   /* s 是可分解的结构类型 */
```

`int`、`float` 的值是「整块」的，语言不允许把 `int` 拆成两半；而 `Student` 的值可以分解出学号、姓名、成绩，每个成分又各是原子或结构。**「能不能再分解」是原子与结构的判据**，与它的大小无关：`double` 占 8 字节仍是原子类型，因为它不能被拆成两个更有意义的值。<span class="marginnote">结构类型的「成分 + 结构」三件套（学号、姓名、成绩 + 它们被组织成一条记录），正是二元组 $(D, S)$ 在语言层的投影——数据元素内部的结构关系，与数据元素之间的结构关系，用的是同一套「值 + 关系」语言。</span>

## 4 数据类型、数据结构、抽象数据类型：三者辨析

三个词都以「数据」开头，最容易混淆。并排看最清楚：

| 概念 | 形式定义 | 关心的核心 | 归属 |
| --- | --- | --- | --- |
| 数据结构 | 二元组 $(D, S)$ | 元素之间的**关系** | 一门课程 / 一种建模方式 |
| 数据类型 | 值集 + 操作集 | 值长什么样、能做什么操作 | 程序设计语言的既有设施 |
| 抽象数据类型 ADT | 三元组 $(D, S, P)$ | 接口：暴露什么操作、隐藏什么实现 | 一种设计纪律 |

三者的关系可以这样记：**数据类型是程序设计语言里「已经实现好」的数据结构**；而 ADT 把数据结构的 $(D, S)$ 再补上操作集 $P$，并强调「只谈接口、不谈实现」。同一个线性表逻辑结构，顺序表（顺序存储）与链表（链式存储）都能实现，但使用者看到的是同一个 ADT 接口——这正是下一节要展开的内容。<span class="marginnote">一句话浓缩：数据结构重「关系」，数据类型重「值与操作」，ADT 重「接口与实现的分离」。考试爱考的是拿具体例子判断「这是哪个概念」，用学生表反复套这三栏即可。</span>

**辨析｜易错点：** 数据结构与数据类型不是同一个东西。数据结构强调**关系**——它回答「元素之间怎么连」；数据类型强调**值集与操作集**——它回答「一个值属于哪类、能被哪些运算处理」。把「数组是一种数据类型」和「线性表是一种数据结构」放在一起看，立刻能体会差别：数组是语言造好的数据类型，线性表是我们用数组或链表去实现的一种结构。

## 5 公式解析：$D$ 上的关系为什么有 $2^{n^2}$ 个

「$S$ 是 $D$ 上关系的有限集」这句话很轻，背后却藏着一个惊人的规模。设 $D$ 有 $n$ 个元素，问：$D$ 上可能的二元关系有多少个？答案是

$$
2^{\,n^2}
$$

三步拆解这个式子：

- **第一步，数有序对**：$D$ 上任意两个元素 $x, y$ 都能组成有序对 $(x, y)$。有序对的数量是 $n \times n = n^2$ 个，因为 $x$ 有 $n$ 种取法、$y$ 也有 $n$ 种取法，两者独立。
- **第二步，把关系看成子集**：一个二元关系就是 $D \times D$ 的一个子集。于是「选关系」变成「从这 $n^2$ 个有序对里，逐个决定要不要它」。
- **第三步，逐个做选择**：每个有序对有「要 / 不要」两种选择，$n^2$ 个有序对互不干扰，总取法就是

$$
\underbrace{2 \times 2 \times \cdots \times 2}_{n^2 \text{ 个}} = 2^{n^2}
$$

直觉落在哪里？四种逻辑结构（集合、线性、树、图）是无穷多种关系里被我们挑中的**四种典型**——它们抓住了「无关系 / 一对一 / 一对多 / 多对多」这四档核心语义。剩下的海量关系要么无序可循，要么冗余重复，工程上不采用。<span class="marginnote">顺带一个现实感：$n=10$ 时 $2^{100} \approx 1.27 \times 10^{30}$，远多于可见宇宙的原子数。所以「关系」不是稀缺品，稀缺的是<strong>有意义、可高效实现</strong>的关系——这正是数据结构这门课精选四种逻辑结构的理由。</span>

## 6 小结

- 数据结构形式化定义是**二元组 $(D, S)$**：$D$ 为数据元素有限集，$S$ 为 $D$ 上关系有限集；它只描述逻辑结构，不含存储。
- 运算分**加工型**（插入、删除、修改）与**引用型**（查找、读取、遍历），引用型常作加工型的子过程。
- **数据类型** = 值集 + 操作集；分原子类型与结构类型；语言内置的数据类型本质也是抽象。
- **数据结构重关系，数据类型重值与操作，ADT 重接口与实现的分离**，三者不可混谈。
- $D$ 上二元关系总数是 $2^{n^2}$，四种逻辑结构是其中四种典型取法。

在下一节《抽象数据类型的表示与实现》中，我们将把这套术语落成一份能写进代码的规格说明——看 ADT 如何用「数据对象 + 数据关系 + 基本操作」的格式被描述，再用 C 语言真正实现它。
