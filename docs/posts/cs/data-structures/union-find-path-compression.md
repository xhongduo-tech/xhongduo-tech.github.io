## 为什么需要并查集

很多问题只关心「**两个元素是否在同一集合**」与「**把两个集合合并**」——连通性判定、朋友圈合并、Kruskal 判环、图片连通域。**并查集（Union-Find / Disjoint Set）**就是为这两个操作而生的数据结构：**`Find(x)`**（x 属于哪个集合）与 **`Union(x, y)`**（合并 x、y 所在集合）。它的经典实现用**森林**：每个集合是一棵树，根是集合的代表；`Find` 沿父指针找根，`Union` 把一个根挂到另一个根下。朴素版最坏 $O(n)$，但加上两个微小的优化——**路径压缩**与**按秩合并**——就变成近乎 $O(1)$（反阿克曼函数）。并查集是「用树结构 + 两个优化达成几乎常数」的奇迹，也是《Kruskal 最小生成树》里判环的幕后功臣。

## 1 并查集的表示：森林

并查集用**森林**表示若干不相交集合：

- 每个集合 = 一棵树，**根**是集合的代表元；
- 每个结点存一个 `parent`（父指针），根指向自己；
- `Find(x)`：沿父指针一路向上，直到根——返回根（代表元）；
- `Union(x, y)`：找到 x、y 的根，把其中一个根挂到另一个根下。

```c
int parent[N];
void Init() {
    for (i = 0; i < N; i++) parent[i] = i;   /* 每个元素自成集合，指向自己 */
}
int Find(int x) {
    while (parent[x] != x) x = parent[x];    /* 沿父链找根 */
    return x;
}
void Union(int x, int y) {
    int rx = Find(x), ry = Find(y);
    if (rx != ry) parent[rx] = ry;           /* 把 rx 的根挂到 ry 下 */
}
```

**重点：`parent[i] == i` 表示「$i$ 是根」——根指向自己是森林的终止条件。** 这套表示极其省空间：一个数组装下全部集合。<span class="marginnote">「<strong>根指向自己</strong>」是并查集最精巧的约定：<strong>用「自指」代替「空指针」作为树的终止标记</strong>，让 `Find` 的循环条件简洁到一行。这个「哨兵自指」的思想，在链表的头结点、循环链表里都能看到影子。</span>

## 2 路径压缩：让树变扁

朴素 `Find` 最坏要走到链的顶端——链状树让 `Find` 退化成 $O(n)$。**路径压缩（path compression）**：`Find` 找到根后，把**沿途所有结点**的父指针直接指向根——一次遍历，让整条链「扁平化」：

```c
int Find(int x) {                    /* 递归版路径压缩 */
    if (parent[x] != x)
        parent[x] = Find(parent[x]); /* 沿路把父指针都指向根 */
    return parent[x];
}
```

**重点：路径压缩让「以后对这条路径上任何结点的 Find」都只需一步**——这次查询花 $O(\text{原深度})$，但把整条路径「压扁」，未来的查询全部受益。<span class="marginnote">「<strong>一次压扁，全路径受益</strong>」是路径压缩的「摊销」逻辑：<strong>这次多走几步，换来这条路径上未来所有查询变成 $O(1)$</strong>。它像「道路拓宽」——第一次走要花时间修路，之后所有车都提速。这也是并查集「近乎常数」的第一个来源。</span>

## 3 公式解析：路径压缩的复杂度

只做路径压缩、不做按秩合并，$m$ 次操作、$n$ 个元素的最坏复杂度：

$$
T_{\text{仅路径压缩}} = O(m \log n) \qquad \text{（$m$ 次 Find/Union）}
$$

- **第一步，读「路径压缩不够」**：仅压缩，树的「高度」在最坏情况下仍可能退化（Union 把高树挂到矮树下），$Find$ 均摊 $O(\log n)$。
- **第二步，读「为什么已经很好」**：$O(\log n)$ 均摊已远好于朴素的 $O(n)$，绝大多数场景够用。
- **第三步，读「真正的近乎常数」**：路径压缩 **+** 按秩合并（下节），复杂度降到反阿克曼函数 $O(m\alpha(n))$，$\alpha(n)$ 对一切实际 $n$ 都 $\le 5$——**实际就是常数**。<span class="marginnote">「$\alpha(n) \le 5$ for $n \le 2^{65536}$」——反阿克曼函数增长慢到「<strong>对一切能想象的 $n$ 都小于 5</strong>」。这意味着并查集在实践里就是 $O(1)$，而理论证明极深（Ackermann 逆函数的摊销分析是算法分析的皇冠之一）。<strong>「工程常数 + 理论优雅」让并查集成面试与竞赛的宠儿</strong>。</span>

## 4 辨析｜易错点：并查集的几个要点

- **`Union` 要「先 Find 后合并」**：直接 `parent[x]=y` 而不先找根，会把 x 整棵子树挂到 y 下，破坏「根代表集合」的性质；
- **`Find` 的递归版可能栈溢出**：深链时递归深度大，可写循环版；
- **路径压缩只影响 `Find`**：`Union` 本身不改树的形状（除非按秩合并）。

**重点：并查集的两个操作 `Find`/`Union` 都围绕「根」展开——理解「根是代表元、父链到根」这一模型，一切实现变体都一目了然。**<span class="marginnote">「并查集的正确性 = 始终以根为准」：<strong>`Find` 返回根、`Union` 合并根、判同集合 = 根相同</strong>。<strong>路径压缩只是「加速找根」的缓存，不改变集合的划分</strong>——它改的是「树高」，不是「集合」。</span>

## 5 并查集的应用预览

- **连通性判定**：动态加边时，判断两点是否连通（$Find$ 相等）；
- **Kruskal 判环**：$Find(u) != Find(v)$ 才选边（§7.4 的幕后功臣）；
- **朋友圈 / 团伙**：合并已知关系，统计连通块数；
- **网格连通域**：图片处理、岛屿计数。

**重点：并查集是「动态连通性」的标准答案**——内存里比 DFS/BFS 更快地处理「不断加边、随时问连通」。<span class="marginnote">「DFS 离线判连通、并查集在线判连通」：<strong>DFS 扫一遍给「静态图」的连通分量；并查集在「边不断到来」时实时回答</strong>。动态场景（网络链路变化、社交关系增长）正是并查集的用武之地——这也是它在图算法、数据库、网络领域高频出现的原因。</span>

## 6 小结

- 并查集：森林表示集合，`Find` 找根（代表元）、`Union` 合并根。
- `parent[i] == i` 是根的标记；一个数组装下全部集合。
- 路径压缩：`Find` 沿途把父指针指向根——一次压扁、全路径受益。
- 仅路径压缩 $O(m\log n)$；加按秩合并 → $O(m\alpha(n))$ 近乎常数。
- 要点：`Union` 先 `Find`；路径压缩不改集合划分。
- 应用：连通性判定、Kruskal 判环、朋友圈、网格连通域。
