## 为什么还需要链队列

循环队列用「取模绕圈」解决了假溢出，但数组大小仍是先定的——队满就得扩容或报错。链队列换一条路：用带头结点的单链表实现队列，**要多少结点就申请多少**，彻底告别「队满」这个概念。入队改在链表尾、出队改在链表头，配合两个指针 `front`、`rear`，入队出队都是 $O(1)$。链队列是「栈的链式表示」的孪生兄弟，但比链栈多一个关键部件——**队尾指针**，因为链表的尾端插入天然需要它。

## 1 链队列的结构

链队列用带头结点的单链表。两个指针各司其职：

```c
typedef struct QNode {
    QElemType data;
    struct QNode *next;
} QNode, *QueuePtr;

typedef struct {
    QueuePtr front;   /* 队头指针：指向头结点 */
    QueuePtr rear;    /* 队尾指针：指向队尾结点 */
} LinkQueue;
```

**重点：`front` 指向头结点，`rear` 指向队尾结点。** 头结点（不存数据的哨兵）让「删除队头」时总能改 `front` 而无需特判表空——空队时 `front == rear` 都指向头结点。<span class="marginnote">带头结点有两个好处：空队与「恰好一个元素」的删除逻辑统一；且 `front` 指针本身永远指向头结点，出队后新队头由 `head->next` 决定，代码少一条分支。这与《循环链表与双向链表》里对头结点的讨论一脉相承。</span>

## 2 链队列的入队：尾插法

入队只需在队尾接一个结点，并更新 `rear`：

```c
Status EnQueue(LinkQueue *Q, QElemType e) {
    QNode *p = (QNode *)malloc(sizeof(QNode));
    if (!p) return ERROR;              /* 内存不足 */
    p->data = e;
    p->next = NULL;
    Q->rear->next = p;                 /* 接到旧队尾之后 */
    Q->rear = p;                       /* 新结点成为队尾 */
    return OK;
}
```

尾插法的时间是 $O(1)$——这是「队尾指针」存在的意义：没有 `rear`，尾插要遍历整个链表找尾，退化到 $O(n)$。**引入一个指针，把尾插从 $O(n)$ 降到 $O(1)$**，这是「以指针换时间」的典型。

## 3 链队列的出队：删除头结点之后的结点

出队删除的是头结点后面的那个结点：

```c
Status DeQueue(LinkQueue *Q, QElemType *e) {
    if (Q->front == Q->rear) return ERROR;   /* 队空 */
    QNode *p = Q->front->next;               /* p 指向待删的队头结点 */
    *e = p->data;
    Q->front->next = p->next;                /* 摘链 */
    if (Q->rear == p) Q->rear = Q->front;    /* 特殊：删的是最后一个结点 */
    free(p);
    return OK;
}
```

**辨析｜易错点：删空后必须修正 `rear`。** 当队里只有一个结点时，`p` 既是队头又是队尾。摘掉它之后，`rear` 还指向已释放的 `p`，变成悬空指针。所以必须先判断 `Q->rear == p`，把 `rear` 拉回头结点。这一行「特判」是链队列最容易漏的地方。<span class="marginnote">悬空指针（dangling pointer）是链式结构的内存隐患之王：指向已释放内存的指针一旦被解引用，读到的是随机数据或触发崩溃。`free` 之后把指针置 `NULL`、或在删除后同步修正相关指针，是两条基本纪律。</span>

## 4 公式解析：循环队列 vs 链队列的代价

两种队列实现各有代价，把关键差异并排写出来：

$$
\begin{aligned}
T_{\text{入队/出队}} &: \ \text{循环队列 } O(1), \quad \text{链队列 } O(1) \ \text{（含一次 malloc/free）} \\
S_{\text{空间}} &: \ \text{循环队列 } O(n) \ \text{（预分配）}, \quad \text{链队列 } O(n) \ \text{（按需，每结点多一指针域）} \\
\text{满/空} &: \ \text{循环队列} \ \text{有满有空}, \quad \text{链队列} \ \text{只有空（无队满）}
\end{aligned}
$$

- **第一步，读时间**：两者都是 $O(1)$。但链队列的常数更大——每次入队多一次 malloc、出队多一次 free。
- **第二步，读空间**：循环队列预分配 $O(n)$ 固定块；链队列结点按需分配，却每个结点多一个指针域（64 位下 8 字节），批量小元素时开销占比可观。
- **第三步，读决策依据**：元素大小固定、深度可预估、对性能敏感 → 循环队列；深度不可知、频繁进出但总量浮动、元素较大 → 链队列。<span class="marginnote">这个取舍与前文顺序栈/链栈、顺序表/链表一脉相承：<strong>顺序结构快而固定，链式结构活而略贵</strong>。到《外部排序》与《文件》篇时，这一对矛盾会以「内存 vs 外存」的形态再次出现。</span>

## 5 链队列在「广度优先」中的应用预览

链队列最著名的应用是**广度优先搜索（BFS）**：先把起点入队，每出队一个结点，就把它的所有未访问邻居入队。因为队列是 FIFO，「先发现、先扩展」，BFS 才能按「距离起点由近及远」的层次逐层推进。这与树的层序遍历是同一套机器，将在第六篇《树的遍历》与第七篇《图的遍历（广度优先搜索）》里正式登场。<span class="marginnote">为什么 BFS 必须用队列而不能用栈？用栈就是深度优先——后发现的结点先扩展，层次立刻被打乱。数据结构的选择，直接决定遍历顺序。这一条会在图算法篇反复被印证。</span>

## 6 小结

- 链队列 = 带头结点的单链表 + `front`（头结点）+ `rear`（队尾结点）两个指针。
- 入队**尾插法**：`rear->next = p; rear = p`，$O(1)$。
- 出队删头结点之后的结点；**删空时须特判 `Q->rear == p` 并修正 `rear`**。
- 链队列**无队满、只有队空**，空间按需分配。
- 循环队列快而固定、链队列活而略贵，深度不可知时选链队列。
- 链队列是 BFS 与树层序遍历的底层容器。
