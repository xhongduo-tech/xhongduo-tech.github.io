## 为什么外部排序要「先学外存」

内部排序假定数据全在内存；当数据大到内存装不下，就得用**外存（磁盘）**。但外存与内存的「成本结构」完全不同：内存访问是纳秒级，磁盘寻道是毫秒级——**相差 6 个数量级**。于是「外部排序」的优化目标从「少比较」变成「少读写」。要理解外部排序，先要懂外存的物理特性：**磁道、扇区、块（页）**以及**为什么「按块读写」比「按字节读写」划算几个量级**。本节立起外存存取的概念，为后面的多路归并、置换-选择排序铺路。

## 1 外存的基本物理结构

机械硬盘（磁盘）的三层结构：

- **磁道（track）**：盘面上一个个同心圆；
- **扇区（sector）**：磁道被分成的最小物理存储单位（512B~4KB）；
- **块（block）/页（page）**：操作系统与文件系统组织 I/O 的逻辑单位（4KB~16KB），由若干扇区组成。

**重点：外存 I/O 以「块」为最小单位**——哪怕只读一个字节，也要把整个块读入内存。这是外部排序一切设计的出发点。<span class="marginnote">「读一个字节 = 读一个块」的「块效应」是外存最反直觉的性质：<strong>按字节随机读 1MB，可能要 1000 次寻道（慢）；按块顺序读 1MB，可能只要几十次（快）</strong>。顺序读写 vs 随机读写的差距可达百倍——<strong>外部排序的全部智慧，就是「把随机访问变成顺序访问」</strong>。</span>

## 2 磁盘存取的时间构成

一次磁盘读（写）的时间：

$$
T_{\text{I/O}} = t_{\text{寻道}} + t_{\text{旋转}} + t_{\text{传输}}
$$

- **寻道（seek）**：磁头移到目标磁道——最贵，毫秒级；
- **旋转延迟（rotation）**：等待目标扇区转到磁头下——半圈旋转时间；
- **传输（transfer）**：数据从盘面读出——相对便宜。

**重点：一次 I/O 的「大头」是寻道 + 旋转（机械运动），传输只占小头。** 这决定了「一次读得越多越划算」——把 I/O 次数压到最少，比单次读多读少更重要。

**一个量级直觉**：假设一次 I/O 共 10 ms，其中寻道约 4 ms、旋转约 3 ms、传输约 3 ms——**传输只占三成**。即使把传输速度提高一倍，总时间也只降 15%；而「少一次寻道」能直接省 4 ms。这就是为什么磁盘算法从不追求「单次读得快」，而追求「次数少 + 顺序化」——**优化磁盘 I/O，先优化次数与顺序，再谈速度**。这个优先级在 SSD 上有所缓和（无机械寻道），但「次数与顺序优先」的原则依然成立，因为每次 I/O 都有固定开销。<span class="marginnote">「<strong>寻道是机械运动，机械运动以毫秒计</strong>」——这是外存排序性能的全部症结。SSD 没有寻道，但「随机读 vs 顺序读」仍有数量级差距（NAND 的读改写惩罚）。所以「<strong>让 I/O 顺序化</strong>」的优化原则，机械盘与 SSD 都适用。</span>

## 3 顺序存取与随机存取

外存上的数据组织决定访问代价：

**顺序存取（sequential access）**：按物理顺序连续读写——磁头几乎不移动，$T \approx \text{传输}$；
**随机存取（random access）**：跳着读写——每次都要寻道 + 旋转，$T$ 放大百倍。

**重点：外部排序的设计目标 =「把随机存取转化为顺序存取」。** 归并时的有序段、缓冲区、多路读写，都是为了「让磁盘尽量顺序工作」。

**顺序化的三种经典手法**：其一，**缓冲（buffer）**——一次读入多个块到内存，边用边续，把多次小随机读合并成一次大顺序读；其二，**预读（prefetch）**——用着当前块时，后台提前读下一批块，隐藏 I/O 延迟；其三，**紧凑排布（cluster）**——把逻辑上相邻的记录在物理上也放得近，让顺序读覆盖尽量多的逻辑数据。**这三个手法不仅属于外部排序，也属于数据库的页缓存、大模型训练的数据加载器**——「把随机变成顺序 + 用缓冲隐藏延迟」，是存储优化的通用工具箱。<span class="marginnote">「顺序化」是外存算法的黄金法则，也渗透到内存算法：<strong>数组访问（顺序）比链表访问（随机跳指针）快，就是因为 CPU 缓存只按顺序预取</strong>。外存与缓存的原理完全同构——「<strong>离 CPU 越远的存储，越要求顺序访问</strong>」。</span>

## 4 公式解析：块大小的选择

设记录长 $l$、块大小 $B$，则一块能装 $b = \lfloor B/l \rfloor$ 条记录。处理 $n$ 条记录需要的 I/O 次数与块大小的关系：

$$
\text{I/O 次数} \approx \frac{n}{b} = \frac{n \cdot l}{B}
$$

- **第一步，读「块越大、I/O 越少」**：$B$ 翻倍，I/O 次数减半——这就是「按块读」的价值。
- **第二步，读「块过大的代价」**：块太大，内存缓冲区装不了几块，多路归并的「路数」受限。
- **第三步，读折中**：块大小要在「I/O 次数」与「内存缓冲」之间平衡——工程上按「内存大小 ÷ 归并路数」确定块大小。

**块大小的现代视角**：SSD 时代块（页）大小普遍取 4 KB–16 KB，与 NAND 的物理页对齐；数据库页（InnoDB 16 KB）与文件系统块（4 KB）往往错层设计，各有各的粒度。**「块大小」本质是「一次 I/O 搬运多少数据」的决策**——它决定 I/O 次数、内存占用、以及随机访问的「浪费比」。理解了「粒度权衡」，你在任何存储系统里看到「为什么是 4 KB / 16 KB」，都能自己推一遍：<strong>粒度粗则 I/O 次数少但浪费多，粒度细则浪费少但 I/O 次数多</strong>。<span class="marginnote">「块大小」是外部排序的旋钮：<strong>块大 → I/O 少但路数少；块小 → 路数多但 I/O 多</strong>。这与内部排序「块大小权衡」（《串的表示》的块链、B 树的结点大小）是同一个「<strong>粒度权衡</strong>」：粒度粗省 I/O、粒度细省内存。</span>

## 5 从外存存取出发看外部排序

理解了「块 + 顺序化」，外部排序的整体策略就呼之欲出：

1. **切段（run）**：把大文件切成能装进内存的段，每段内部排序——产生若干有序段；
2. **多路归并**：把多个有序段「顺序读」进内存缓冲，归并成一个更大的有序段，写回——**读与写都尽量顺序**；
3. **层层归并**：直到只剩一个有序段。

**重点：外部排序的每一趟，都是「顺序读 + 顺序写 + 内存归并」——让昂贵的寻道次数降到最少。** 这就是「外存信息的存取」这节存在的意义：先懂外存的物理，才懂外部排序为何长这样。

**「切段 + 归并」的趟数怎么估计**：设内存能装 $M$ 个记录，文件有 $n$ 个记录。切段产生 $\lceil n/M \rceil$ 个有序段；每趟归并把这些段合并，若路数为 $k$，则每趟把段数除以 $k$，总趟数约 $\lceil \log_k (n/M) \rceil$。$n = 10^8$、$M = 10^5$、$k = 10$ 时：初始 1000 段，趟数 $\lceil \log_{10} 1000 \rceil = 3$ 趟——每趟读一遍写一遍，共 6 遍全文件 I/O。**「趟数 = 遍数 × 2」是外部排序成本的骨架**，后面的多路归并、置换-选择排序，全在优化这两件事：减少段数、减少趟数。<span class="marginnote">「先切段、再归并」也是很多「内存装不下」问题的通用解法：<strong>数据库的排序、MapReduce 的 shuffle、大文件的去重，全是「分块处理 + 归并汇总」</strong>。外部排序是「<strong>分而治之在磁盘上</strong>」的模板。</span>

## 6 数值算例：顺序读和随机读差多少

用具体数字感受「顺序化」的价值。设一个 100 MB 的文件，每条记录 100 字节，块大小 4 KB（一块装 $\lfloor 4096/100 \rfloor = 40$ 条记录），磁盘每块 I/O 约 5 ms。

- **顺序读整个文件**：$100\text{MB} / 4\text{KB} = 25000$ 次块 I/O，约 $25000 \times 5\text{ms} = 125$ 秒。看似久，但这是「一次寻道读一大段」的代价。
- **随机读 1000 条记录**：每条记录在随机位置，每次都要寻道 + 读块——$1000$ 次 I/O，约 $1000 \times 5\text{ms} = 5$ 秒。
- **顺序读同样的 1000 条**：它们若连在一起，只需 $\lceil 1000/40 \rceil = 25$ 次块 I/O，约 $25 \times 5\text{ms} = 0.125$ 秒。

**同样的 1000 条记录，随机读 5 秒、顺序读 0.125 秒——相差 40 倍。** 这就是「把随机访问变成顺序访问」的全部动力：**外部排序的每一趟归并，都在把「随机跳着读写」翻译成「顺序读入 + 顺序写回」**，从而把几小时压到几分钟。<span class="marginnote">这个 40 倍的差距值得背下来：<strong>顺序 I/O 比随机 I/O 快一到两个数量级</strong>。<strong>判断任何磁盘算法的好坏，先问「它让磁盘顺序工作了吗」</strong>——数据量越大，这个问题越致命。</span>

## 7 术语速查表：外存存取关键概念

| 术语 | 含义 | 与内部排序的对应 |
| --- | --- | --- |
| 磁道 | 盘面同心圆 | — |
| 扇区 | 最小物理存储单位 | — |
| 块 / 页 | I/O 的逻辑单位 | 数组的「一段」 |
| 寻道 | 磁头移动 | 最贵的机械运动 |
| 旋转延迟 | 等扇区转到磁头下 | 半圈时间 |
| 顺序存取 | 物理顺序连续读 | 数组遍历 |
| 随机存取 | 跳着读写 | 链表式访问 |

**三句收束**：第一，**外存 I/O 以块为单位，寻道/旋转是大头**——「读一个字节 = 读一个块」是最反直觉也最重要的事实。第二，**顺序存取比随机存取快一到两个数量级**——外部排序的黄金法则是「把随机变成顺序」。第三，**块大小是「I/O 次数 × 内存缓冲」的旋钮**——块大 I/O 少但缓冲受限，块小反之，工程上按「内存 ÷ 路数」折中。<span class="marginnote">「<strong>离 CPU 越远、越要求顺序访问</strong>」的原则贯穿存储金字塔：<strong>寄存器无需顺序、缓存讲究局部性、内存要连续、磁盘必须顺序</strong>。理解这条分层法则，你就同时理解了缓存优化与外部排序——<strong>它们是同一件事在不同距离上的回声</strong>。</span>

## 8 小结

- 外存以**块**为单位 I/O；读一个字节也要读整个块。
- 一次 I/O ≈ 寻道 + 旋转 + 传输；寻道/旋转（机械运动）是大头。
- 顺序存取 vs 随机存取可差百倍——**外部排序的目标是「顺序化」**。
- 块越大 I/O 越少，但受内存缓冲限制——块大小要折中。
- 外部排序总策略：**切有序段 + 多路归并**，读写尽量顺序。
- 原则「离 CPU 越远越要求顺序」贯穿缓存与外存。
- 数值对比：1000 条记录随机读 5 秒、顺序读 0.125 秒——差 40 倍。
- 读一个字节 = 读一个块，「块效应」是外存最反直觉的性质。
