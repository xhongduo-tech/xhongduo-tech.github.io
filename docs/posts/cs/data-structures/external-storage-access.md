## 为什么外部排序要「先学外存」

内部排序假定数据全在内存；当数据大到内存装不下，就得用**外存（磁盘）**。但外存与内存的「成本结构」完全不同：内存访问是纳秒级，磁盘寻道是毫秒级——**相差 6 个数量级**。于是「外部排序」的优化目标从「少比较」变成「少读写」。要理解外部排序，先要懂外存的物理特性：**磁道、扇区、块（页）**以及**为什么「按块读写」比「按字节读写」划算几个量级**。本节立起外存存取的概念，为后面的多路归并、置换-选择排序铺路。

## 1 外存的基本物理结构

机械硬盘（磁盘）的三层结构：

- **磁道（track）**：盘面上一个个同心圆；
- **扇区（sector）**：磁道被分成的最小物理存储单位（512B~4KB）；
- **块（block）/页（page）**：操作系统与文件系统组织 I/O 的逻辑单位（4KB~16KB），由若干扇区组成。

**重点：外存 I/O 以「块」为最小单位**——哪怕只读一个字节，也要把整个块读入内存。这是外部排序一切设计的出发点。<span class="marginnote">「读一个字节 = 读一个块」的「块效应」是外存最反直觉的性质：<strong>按字节随机读 1MB，可能要 1000 次寻道（慢）；按块顺序读 1MB，可能只要几十次（快）</strong>。顺序读写 vs 随机读写的差距可达百倍——<strong>外部排序的全部智慧，就是「把随机访问变成顺序访问」</strong>。</span>

## 2 磁盘存取的时间构成

一次磁盘读（写）的时间：

$$
T_{\text{I/O}} = t_{\text{寻道}} + t_{\text{旋转}} + t_{\text{传输}}
$$

- **寻道（seek）**：磁头移到目标磁道——最贵，毫秒级；
- **旋转延迟（rotation）**：等待目标扇区转到磁头下——半圈旋转时间；
- **传输（transfer）**：数据从盘面读出——相对便宜。

**重点：一次 I/O 的「大头」是寻道 + 旋转（机械运动），传输只占小头。** 这决定了「一次读得越多越划算」——把 I/O 次数压到最少，比单次读多读少更重要。<span class="marginnote">「<strong>寻道是机械运动，机械运动以毫秒计</strong>」——这是外存排序性能的全部症结。SSD 没有寻道，但「随机读 vs 顺序读」仍有数量级差距（NAND 的读改写惩罚）。所以「<strong>让 I/O 顺序化</strong>」的优化原则，机械盘与 SSD 都适用。</span>

## 3 顺序存取与随机存取

外存上的数据组织决定访问代价：

**顺序存取（sequential access）**：按物理顺序连续读写——磁头几乎不移动，$T \approx \text{传输}$；
**随机存取（random access）**：跳着读写——每次都要寻道 + 旋转，$T$ 放大百倍。

**重点：外部排序的设计目标 =「把随机存取转化为顺序存取」。** 归并时的有序段、缓冲区、多路读写，都是为了「让磁盘尽量顺序工作」。<span class="marginnote">「顺序化」是外存算法的黄金法则，也渗透到内存算法：<strong>数组访问（顺序）比链表访问（随机跳指针）快，就是因为 CPU 缓存只按顺序预取</strong>。外存与缓存的原理完全同构——「<strong>离 CPU 越远的存储，越要求顺序访问</strong>」。</span>

## 4 公式解析：块大小的选择

设记录长 $l$、块大小 $B$，则一块能装 $b = \lfloor B/l \rfloor$ 条记录。处理 $n$ 条记录需要的 I/O 次数与块大小的关系：

$$
\text{I/O 次数} \approx \frac{n}{b} = \frac{n \cdot l}{B}
$$

- **第一步，读「块越大、I/O 越少」**：$B$ 翻倍，I/O 次数减半——这就是「按块读」的价值。
- **第二步，读「块过大的代价」**：块太大，内存缓冲区装不了几块，多路归并的「路数」受限。
- **第三步，读折中**：块大小要在「I/O 次数」与「内存缓冲」之间平衡——工程上按「内存大小 ÷ 归并路数」确定块大小。<span class="marginnote">「块大小」是外部排序的旋钮：<strong>块大 → I/O 少但路数少；块小 → 路数多但 I/O 多</strong>。这与内部排序「块大小权衡」（《串的表示》的块链、B 树的结点大小）是同一个「<strong>粒度权衡</strong>」：粒度粗省 I/O、粒度细省内存。</span>

## 5 从外存存取出发看外部排序

理解了「块 + 顺序化」，外部排序的整体策略就呼之欲出：

1. **切段（run）**：把大文件切成能装进内存的段，每段内部排序——产生若干有序段；
2. **多路归并**：把多个有序段「顺序读」进内存缓冲，归并成一个更大的有序段，写回——**读与写都尽量顺序**；
3. **层层归并**：直到只剩一个有序段。

**重点：外部排序的每一趟，都是「顺序读 + 顺序写 + 内存归并」——让昂贵的寻道次数降到最少。** 这就是「外存信息的存取」这节存在的意义：先懂外存的物理，才懂外部排序为何长这样。<span class="marginnote">「先切段、再归并」也是很多「内存装不下」问题的通用解法：<strong>数据库的排序、MapReduce 的 shuffle、大文件的去重，全是「分块处理 + 归并汇总」</strong>。外部排序是「<strong>分而治之在磁盘上</strong>」的模板。</span>

## 6 小结

- 外存以**块**为单位 I/O；读一个字节也要读整个块。
- 一次 I/O ≈ 寻道 + 旋转 + 传输；寻道/旋转（机械运动）是大头。
- 顺序存取 vs 随机存取可差百倍——**外部排序的目标是「顺序化」**。
- 块越大 I/O 越少，但受内存缓冲限制——块大小要折中。
- 外部排序总策略：**切有序段 + 多路归并**，读写尽量顺序。
- 原则「离 CPU 越远越要求顺序」贯穿缓存与外存。
