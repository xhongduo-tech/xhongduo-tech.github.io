## 为什么从顺序存储开始

上一节我们把线性表定义成了逻辑结构。现在要问：**它在内存里到底怎么摆？** 答案是顺序存储——把逻辑上相邻的元素放到**物理地址也相邻**的存储单元里。这个选择背后的「支点」是阿基米德式的：**只要知道第一个元素的地址，就能算出任何元素的地址**。这份「一算就得」的随机存取能力，是顺序表（sequential list）最宝贵的资产，也是它与链表最根本的差异。

本节我们用 C 语言把上一节的 ADT List 完整实现一遍：定义存储结构、写出取元素、插入、删除、定位四个核心操作，再用复杂度分析算出每笔操作的代价。学完你会理解那句贯穿全书的话：**逻辑上同样一句「插入」，在顺序表里要搬动整段元素——这就是「逻辑语义相同，物理代价不同」的第一个实证。**

## 1 顺序表的存储结构

**线性表的顺序存储结构（sequential storage structure）**：用一组**地址连续**的存储单元依次存放线性表的数据元素。

C 语言里，天然的载体是数组。严蔚敏教材用两个变量描述一块「动态的数组」：

```c
// 顺序表的动态存储结构
#define LIST_INIT_SIZE 100      // 存储空间初始分配量
#define LISTINCREMENT  10       // 存储空间分配增量
typedef struct {
    ElemType *elem;             // 存储空间基址（指向一块动态数组）
    int length;                 // 当前表长（实际元素个数）
    int listsize;               // 当前容量（最多能装多少个）
} SqList;
```

这里有一个贯穿全书的重要区分，**务必看仔细**：

- **length（表长）**：当前实际存储的元素个数。`length` 是多少，表就有多大。
- **listsize（容量）**：分配给这块空间的最大承载量，是初始分配值或动态扩充后的值。

**辨析｜易错点：** 表长是「现在有几个」，容量是「最多能装几个」。表长永远不超过容量（`length ≤ listsize`）。当表已满（`length == listsize`）还想插入时，就「溢出」了——顺序表需要先扩容（动态存储管理），这也是很多初学者写崩的根源：把 `length` 当成了数组末尾哨兵，忘了检查边界。

## 2 随机存取：一条乘法公式的威力

顺序表最强的能力叫**随机存取（random access）**。逻辑上第 $i$ 个元素 $a_i$，存放在以基址 `elem`（即 $LOC(a_1)$）起、第 $i-1$ 个单元处。第 $i$ 个元素的地址是：

$$LOC(a_i) = LOC(a_1) + (i-1) \times \text{sizeof(ElemType)}$$

**因为已知 $LOC(a_1)$ 和元素大小，地址是一步乘法算出来的，与 $i$ 的大小无关**——找第 1 个元素和找第 10000 个元素花的时间一样多。用算法分析的术语说，**随机存取**的时间复杂度是：

$$T(n) = O(1)$$

这就是「阿基米德支点」：**顺序表只要一个基点，就能撬起任意位置。** 而下一节的链表恰恰相反——它没有这根杠杆，找第 $i$ 个元素只能从表头一步步走过去，代价是 $O(n)$。<span class="marginnote">这里第一次出现 $O$ 记号。它的严格定义（渐进上界、最坏情况）在绪论《时间与空间复杂度》和第三级《算法设计与分析》里展开；现在你只需要直觉：$O(1)$ 是「常数时间」，$O(n)$ 是「随规模线性增长」。</span>

## 3 顺序表的插入：为什么是 O(n)

插入是顺序表最典型的操作。**逻辑定义**是上一节的 ADT：`ListInsert(L, i, e)` 在**位序 $i$** 处插入元素 e。但**物理实现**得动真格：为了保持「逻辑相邻 = 物理相邻」，必须先把从 $i$ 到末尾的所有元素**整体后移一格**，把位序 $i$ 的位置空出来，再把 e 放进去，最后 `length++`。

```c
// 在顺序表 L 的位序 i 处插入元素 e（1 ≤ i ≤ length+1）
Status ListInsert(SqList *L, int i, ElemType e) {
    if (i < 1 || i > L->length + 1) return ERROR;   // i 不合法
    if (L->length >= L->listsize) {                 // 表满：先扩容
        L->elem = realloc(L->elem,
            (L->listsize + LISTINCREMENT) * sizeof(ElemType));
        L->listsize += LISTINCREMENT;
    }
    for (int j = L->length - 1; j >= i - 1; j--)    // 从尾往头整体后移
        L->elem[j + 1] = L->elem[j];
    L->elem[i - 1] = e;                             // 空位放 e
    L->length++;                                    // 表长 +1
    return OK;
}
```

把代价算清楚。设表长为 $n$，在**位序 $i$** 插入时要移动的元素个数是 $n - i + 1$。移动次数随 $i$ 变化：

- 插在表尾（$i = n+1$）：移动 0 个，最划算；
- 插在表头（$i = 1$）：移动 $n$ 个，最贵；
- 平均而言，假设插入位置等概率落在 $1 \sim n+1$，平均移动次数是：

$$\bar{E}_{ins} = \sum_{i=1}^{n+1} \frac{1}{n+1}(n - i + 1) = \frac{n}{2}$$

平均要移动**一半**的元素，所以插入的时间复杂度是 $O(n)$。<span class="marginnote">这个「平均移动 n/2 个」的结论，是顺序表最深刻的性格：它赢在「读」（随机存取 $O(1)$），输在「写」（中间插入/删除 $O(n)$）。后面的链表正好是镜像：写快、读慢。数据结构没有免费的午餐，全是取舍。</span>

**辨析｜易错点：** 两个经典的坑。其一，循环搬移（`for (j = length - 1; j >= i - 1; j--) A[j+1] = A[j]`）必须**从尾往头**搬，若从头往尾搬会把后一个元素覆盖掉。其二，`elem`（基址）指针的比较依赖指针指向同一数组（C 标准里同数组内指针比较才合法），所以插入/删除的指针运算都限定在这段连续空间内进行。

## 4 顺序表的删除：对称的代价

删除 `ListDelete(L, i, &e)` 与插入互为镜像：把第 $i$ 个元素取出来，然后把 $i+1$ 到末尾的元素**整体前移一格**，补上空位，最后 `length--`。

```c
// 删除顺序表 L 的位序 i 的元素，用 e 返回（1 ≤ i ≤ length）
Status ListDelete(SqList *L, int i, ElemType *e) {
    if (i < 1 || i > L->length) return ERROR;   // i 不合法或表空
    *e = L->elem[i - 1];                        // 取出被删元素
    for (int j = i; j < L->length; j++)         // 前移补位
        L->elem[j - 1] = L->elem[j];
    L->length--;                                // 表长 -1
    return OK;
}
```

删除位序 $i$ 的元素需要移动 $n - i$ 个元素。等概率下平均移动：

$$\bar{E}_{del} = \sum_{i=1}^{n} \frac{1}{n}(n - i) = \frac{n-1}{2}$$

同样是 $O(n)$。把插入与删除放在一起，你会看见顺序表的完整画像：**两头快、中间慢**。在表尾追加（`append`，即 `ListInsert(L, length+1, e)`）是 $O(1)$ 的，所以「动态数组」作为最常用的容器，总把新元素往末尾塞；而任何「插中间」的暴力操作，都要付出搬家的代价。这也是为什么语言标准库（C++ 的 `std::vector`、Python 的 `list`）都把「末尾操作」优化成常数时间——它们的底层正是顺序表。

## 5 公式解析：平均移动次数怎么来的

上面两个平均移动公式长得像，背后是一套统一的推导。以删除为例，把 $\bar{E}_{del}$ 拆成三步：

- **第一步，列出全部可能**：位序 $i$ 可以取 $1, 2, \dots, n$，共 $n$ 种等可能的位置，每种概率 $\dfrac{1}{n}$。
- **第二步，写出每种情况的代价**：删除位序 $i$ 要移动 $n - i$ 个元素。比如删表头（$i=1$）要动 $n-1$ 个，删表尾（$i=n$）要动 0 个。
- **第三步，求期望**：把「概率 × 代价」对全部位置求和：

$$\bar{E}_{del} = \frac{1}{n}\sum_{i=1}^{n}(n - i) = \frac{1}{n}\left[(n-1) + (n-2) + \cdots + 0\right] = \frac{n-1}{2}$$

这套「枚举所有情况 → 写出每种的代价 → 加权平均」的三步法，就是**平均时间复杂度**的标准算法。它和第一级《概率》里的数学期望完全同构：把「位置」当作随机变量，「移动次数」当作它的取值，期望就是加权平均。<span class="marginnote">这里第一次真正用上数学期望：数据结构教材里大量「平均移动 n/2 个」「平均查找 n/2 次」的结论，全是这么算出来的。这也呼应了为什么博客从概率一路铺到数据结构——期望与复杂度共用同一套数学语言。</span>

## 6 小结

- **顺序存储结构**：用地址连续的数组承载线性表，逻辑相邻 = 物理相邻；用 `length`（表长）与 `listsize`（容量）两个量区分「现在有几个」与「最多能装几个」。
- **随机存取**：$LOC(a_i) = LOC(a_1) + (i-1) \times \text{sizeof}$，取元素 $O(1)$——这是顺序表最大的优势。
- **插入/删除**：需要整体搬移元素，平均移动约 $n/2$ 个，复杂度 $O(n)$——这是顺序表最大的代价。
- **平均复杂度** = 对全部等可能位置「概率 × 代价」求和，与第一级数学期望同构。
- 顺序表性格：**读快写慢、两头快中间慢**；语言标准库的 `std::vector`/`list` 底层正是它。
