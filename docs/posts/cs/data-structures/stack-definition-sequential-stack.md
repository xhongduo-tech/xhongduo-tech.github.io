## 为什么从栈开始

线性表允许在任意位置插入、删除，这是「自由」；但许多实际问题里，运算被严格限制在一端——浏览器后退、函数调用、括号匹配、撤销操作，全是「后来者先被处理」。把「只在一端插入删除」这条约束立起来，就得到**栈（stack）**。它是线性表家族里最简单的一种受限结构，却因为「后进先出」这一个特征，成为递归、表达式求值、深度优先搜索的幕后英雄。本节先用顺序存储把它实现出来，为后面所有栈的应用打地基。

## 1 栈的定义

**栈（stack）**：只允许在表的一端进行插入和删除运算的线性表。允许插入和删除的一端称为**栈顶（top）**，另一端称为**栈底（bottom）**；不含任何元素的栈称为**空栈（empty stack）**。

栈的基本操作只有四类：

- **入栈（push）**：在栈顶插入一个元素；
- **出栈（pop）**：删除栈顶元素并返回其值；
- **读栈顶（gettop）**：只读栈顶元素，不删除；
- **判空 / 取长度**。

由于插入和删除都发生在同一端，**后进栈的元素必然先出栈**，这一特征被称为**后进先出（LIFO, Last In First Out）**。<span class="marginnote">栈与队列的对比是数据结构的经典母题：栈是<strong>后进先出</strong>，队列是<strong>先进先出</strong>。同一个线性表，开放「哪一端」，就得到两种行为完全不同的结构。下一节学完链栈、再到《队列》一篇，这个对比就补全了。</span>

## 2 顺序栈：数组 + 栈顶指针

栈的顺序存储（顺序栈）用一块连续的数组存放元素，另设一个整数 `top` 记录栈顶位置。

```c
#define MAXSIZE 100                 /* 栈的最大容量 */
typedef struct {
    SElemType data[MAXSIZE];        /* 存放栈元素的数组 */
    int top;                        /* 栈顶指针：top 指向栈顶元素 */
} SqStack;
```

关于 `top` 有两种习惯约定。严蔚敏教材采用「**top 指向栈顶元素**」：

初始化时 `top = -1`，表示空栈；
元素 `e` 入栈：`S.data[++S.top] = e`（先移动指针，再写入）；
出栈：`e = S.data[S.top--]`（先取走，再移动指针）。

另一种常见约定是「top 指向栈顶元素的下一个空位」（`top = 0` 表示空栈）。两种约定只要自洽都行，但**混用必出 bug**——这是初学者的经典陷阱。<span class="marginnote">记住一条检验准则：<strong>空栈时 top 的取值，与入栈时 top 的移动方向，必须与你「top 指谁」的约定匹配</strong>。把约定写进注释，比背代码可靠。</span>

## 3 公式解析：栈满与栈空的条件

顺序栈的两个边界条件可以用一对简单式子钉死：

$$
\text{空栈}:\ top = -1 \qquad\qquad \text{栈满}:\ top = MAXSIZE - 1
$$

- **第一步，读空栈条件**：`top = -1` 表示「没有任何元素」，此时连 `data[0]` 都未被占用。
- **第二步，读栈满条件**：数组下标从 0 到 `MAXSIZE-1`，`top` 顶到最后一个下标即满。此时再入栈，就是**上溢（overflow）**。
- **第三步，体会「上溢」与「下溢」的不对称**：栈满再 push 叫上溢，属结构性错误（空间不够），靠扩容数组解决；栈空再 pop 叫下溢，属程序逻辑错误（取出不存在的元素），必须由「先判空再出栈」规避。两者性质不同，处理方法也不同。

## 4 顺序栈的入栈与出栈

入栈三步、出栈两步，各写一个函数：

```c
/* 入栈：先动指针再放值 */
Status Push(SqStack &S, SElemType e) {
    if (S.top == MAXSIZE - 1) return ERROR;   /* 栈满，上溢 */
    S.data[++S.top] = e;                      /* 先移动指针，再写入 */
    return OK;
}

/* 出栈：先取值再动指针 */
Status Pop(SqStack &S, SElemType &e) {
    if (S.top == -1) return ERROR;            /* 栈空，下溢 */
    e = S.data[S.top--];                      /* 先取走，再移动指针 */
    return OK;
}
```

**重点：入栈是「先动指针再放值」，出栈是「先取值再动指针」。** 两段代码互为镜像，任何一次顺序颠倒，都会让栈顶元素错位。这也是面试常考「手写栈」的原因——它考查的不是难，而是对边界的精确。

## 5 辨析｜易错点：出栈是「逻辑删除」

出栈时，`data[top]` 里的旧值其实还在数组中——我们只是把 `top` 往下移了一位。这带来两条推论：

- **出栈不释放空间，但也不该依赖旧值**：后续入栈会直接覆盖该位置，这是顺序栈省时的原因；但若代码误读 `top` 以上的「残留值」，就引入了难以察觉的错误。
- **扩容只需一次搬家**：顺序栈满时，可重新分配一块更大的数组并复制旧元素，代价 $O(n)$。因为栈顶固定在数组尾部，复制后无需移动任何元素的位置，这与顺序表在头部插入要整体后移完全不同。<span class="marginnote">栈顶固定在数组末端，使顺序栈的插入删除都发生在末尾：均摊 $O(1)$，且不搬动已有元素。这是「<strong>限制一端</strong>」换来的效率红利，也是「约束简化实现」的又一例证。</span>

## 6 从顺序栈到链栈

顺序栈简单高效，但有两个软肋：栈满需要扩容，且数组大小必须在创建时确定。这两个问题，用链式存储即可化解——每个元素一个结点，靠指针串成栈，栈顶就是链头。这就是下一节《栈的链式表示》的内容。顺序栈与链栈的取舍，本质是「数组 vs 链表」之争在栈上的重演：顺序栈快但需预分配，链栈灵活但多存指针、多花 malloc/free 的代价。

**一个顺序栈的操作算例。** 设 `MAXSIZE = 5`，初始 `top = -1`：

- push 10：`data[0]=10, top=0`；push 20：`data[1]=20, top=1`；push 30：`top=2`；
- pop：`e=data[2]=30, top=1`——**后进先出**，后入栈的 30 先出栈；
- gettop：读 `data[1]=20`，top 不动；
- 继续 pop 两次：top 回 -1，此时再 pop 判 `top == -1` 得下溢错误。

这个轨迹把「后进先出」「栈顶指针移动」「上溢/下溢判定」一次演全。<span class="marginnote">注意 pop 后 `data[2]=30` 的旧值还在数组里，只是 top 不再指向它——<strong>「逻辑删除」让顺序栈的 pop 是 $O(1)$ 且不搬元素</strong>。若下次 push 40，`data[2]` 直接被覆盖，无需任何清理。</span>

**术语速查表**

| 术语 | 含义 |
| --- | --- |
| 栈顶 top | 指向栈顶元素的指针（教材版） |
| 后进先出 LIFO | 后入栈者先出栈 |
| 上溢 / 下溢 | 栈满再入 / 栈空再出 |
| 逻辑删除 | pop 只移 top，旧值仍在数组 |
| 顺序栈 vs 链栈 | 数组预分配 vs 指针按需 |

## 7 小结

- 栈是**只允许在一端插入删除**的线性表，特征为**后进先出（LIFO）**。
- 顺序栈 = 数组 + 栈顶指针 `top`；「top 指向栈顶元素」约定下，空栈 `top = -1`，栈满 `top = MAXSIZE - 1`。
- 入栈 `data[++top] = e`，出栈 `e = data[top--]`，两条互为镜像。
- 栈满再入栈是**上溢**（扩容解决），栈空再出栈是**下溢**（先判空规避）。
- 出栈是**逻辑删除**：旧值仍在数组中，靠移动 top 完成。
