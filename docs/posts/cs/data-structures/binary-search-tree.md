## 为什么动态查找需要树

折半查找要求整表有序 + 随机存取，插入删除要整体搬家。**二叉排序树（BST, Binary Search Tree）**把「有序」装进树结构：每个结点的左子树都小于它、右子树都大于它。查找时沿树下行，每走一步排除一整棵子树；插入、删除只影响局部，不搬家。它是「动态有序表」的开山之作——AVL 树、数据库索引、许多查找结构都以 BST 为起点。不过 BST 有一个著名软肋：形状由插入顺序决定，最坏会退化成链表——这正是下一节「平衡二叉树」要解决的。

## 1 BST 的定义与性质

**二叉排序树（BST）**：一棵空树，或满足如下性质的二叉树：

1. 若左子树非空，则**左子树上所有结点**的关键字都**小于**根的关键字；
2. 若右子树非空，则**右子树上所有结点**的关键字都**大于**根的关键字；
3. 左、右子树本身也都是 BST。

**重点：BST 的中序遍历结果是「升序序列」。** 这条性质是 BST 的身份证——左根右的遍历顺序恰好把树「压平」成有序表。<span class="marginnote">「<strong>中序 = 升序</strong>」把树与有序表连起来：BST 是「<strong>能动态增删的有序表</strong>」，而折半查找的判定树是「静态有序表」。中序遍历一次 BST 即得有序序列，这让 BST 还能当「动态排序器」用。</span>

## 2 BST 的查找

查找过程与折半查找神似：从根出发，key 小往左、大往右，相等即命中：

```c
/* 查找关键字等于 key 的结点，返回结点指针；找不到返回 NULL */
BSTNode *BST_Search(BSTNode *T, int key) {
    while (T != NULL && key != T->key) {
        if (key < T->key)  T = T->lchild;   /* key 小，往左 */
        else               T = T->rchild;   /* key 大，往右 */
    }
    return T;                               /* 命中返回该结点，否则返回 NULL */
}
```

**重点：BST 查找的过程，就是「沿一条路径下行」——比较次数 = 路径长度 = 结点深度 + 1。** 树越矮，查找越快。<span class="marginnote">BST 查找的复杂度取决于树高：<strong>理想树高 $O(\log n)$，退化链高 $O(n)$</strong>。因此 BST 的一切问题都归结为「如何让树保持矮」——这是后面 AVL、红黑树、B 树的共同动机。</span>

## 3 BST 的插入

插入规则：从根出发按查找路径下行，**直到找到一个空位置，把新结点放进去**——新结点总是作为叶子插入：

```c
/* 插入关键字为 key 的新结点，新结点总是作为叶子插入 */
BSTNode *BST_Insert(BSTNode *T, int key) {
    if (T == NULL) {                        /* 找到空位置 */
        T = (BSTNode *)malloc(sizeof(BSTNode));
        T->key = key;
        T->lchild = T->rchild = NULL;
        return T;
    }
    if (key < T->key)      T->lchild = BST_Insert(T->lchild, key);
    else if (key > T->key) T->rchild = BST_Insert(T->rchild, key);
    return T;                               /* key 已存在则什么都不做 */
}
```

**辨析｜易错点：BST 的插入顺序决定树的形状。** 按升序 **`1, 2, 3, …, n`** 依次插入，得到一条右斜链（查找退化为 $O(n)$）；按 **`5, 3, 7, 2, 4, 6, 8`** 插入，得到一棵平衡的树。**同样的数据、不同的插入顺序，树的形态天差地别。**<span class="marginnote">「插入顺序决定形状」是 BST 的宿命：<strong>有序输入 → 退化链</strong>，这被称为「最坏输入」。对抗它有三种思路：<strong>随机化（随机 BST）、平衡化（AVL/红黑树）、多叉化（B 树）</strong>——后续各节逐一登场。</span>

## 4 BST 的删除

删除一个结点分三种情形（最麻烦的操作）：

**叶子**：直接删除，改双亲指针为空；
**只有一棵子树**：用子树顶替被删结点；
**有两棵子树**：用**中序前驱**（左子树最大）或**中序后继**（右子树最小）顶替，然后递归删除那个前驱/后继（它至多有一棵子树）。

**重点：删除的核心是「用谁顶替」——两子树结点选「中序前驱或后继」顶替，保持中序升序不变。**<span class="marginnote">为什么选中序前驱/后继？因为<strong>中序序列里它紧挨着被删结点，用它顶替不破坏「中序 = 升序」</strong>。这个「用相邻元素顶替」的技巧，在堆、B 树、红黑树的删除里都会以各种形态重现。</span>

## 5 公式解析：BST 查找的 ASL 与退化

设树高为 $h$，查找成功的平均比较次数（路径长度均值）：

$$
ASL = \frac{1}{n}\sum_{i=1}^{n} (\text{结点 } i \text{ 的深度} + 1)
$$

- **第一步，读「深度 + 1」**：从根到结点的路径上要比较「深度 + 1」次。
- **第二步，读理想情况**：形状理想（接近完全二叉树）时 $h = O(\log n)$，$ASL = O(\log n)$。
- **第三步，读退化情况**：按升序插入得右斜链，$h = n$，$ASL = (n+1)/2$——**退化成顺序查找**。BST 的性能「最好对数、最坏线性」，全看形状。<span class="marginnote">「最好 $\log$、最坏 $n$」说明 BST 是「<strong>形状敏感</strong>」的结构。与之对比，哈希表对输入不敏感（平均 $O(1)$），但失去了有序性。要「<strong>既有序又不退化</strong>」，只能强制平衡——下一节的 AVL 树正是为此而生。</span>

## 6 BST 的应用与展望

**动态有序表**：需要有序遍历 + 动态增删的场景；
**AVL 树 / 红黑树**：标准库的红黑树正是「平衡的 BST」（专题篇红黑树）；
**表达式的二叉判定**：BST 是许多高级结构（AVL、红黑、B 树）的基础。

**重点：BST 是「平衡树家族」的起点**——AVL 加「平衡因子」、红黑树加「颜色与旋转」、B 树加「多路」，全部是在 BST 的查找骨架上打补丁，目标是**同一件事：把树高压到 $O(\log n)$**。<span class="marginnote">「一切平衡树的初心，都是让 BST 不退化。」记住这句，AVL 的旋转、红黑树的颜色、B 树的多路，就都有了统一的目标函数——<strong>树高 $O(\log n)$</strong>。下一节 AVL 第一个登场。</span>

## 7 小结

- BST：左小右大的二叉树；**中序遍历 = 升序序列**。
- 查找/插入沿路径下行，比较次数 = 结点深度 + 1。
- 插入总是作为叶子；删除分三种情形，双子结点用中序前驱/后继顶替。
- 插入顺序决定形状：有序输入退化成链，查找 $O(n)$。
- ASL：理想 $O(\log n)$，退化 $(n+1)/2$——形状敏感。
- BST 是 AVL、红黑树、B 树的基础；一切平衡树都为压树高。
