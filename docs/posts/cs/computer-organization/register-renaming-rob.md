## 为什么「乱序的账」要按序算

Tomasulo 用保留站 + 重命名解决了乱序执行的依赖问题，但它**乱序写寄存器堆**——异常发生时无法精确回溯。现代方案加一层保险：**重排序缓冲（ROB, Reorder Buffer）**——指令乱序执行，但**按程序顺序提交**（commit）。本课讲 ROB 的工作原理、与 Tomasulo 保留站的分工，以及**寄存器重命名**在现代 CPU 中的具体形态。<span class="marginnote">「乱序执行 + 按序提交」是现代 CPU 的统一公式：执行可以乱（挖 ILP），提交必须按序（保精确）。ROB 就是那个「按序提交」的执行者——它同时解决了精确异常、精确中断、分支预测错误的撤销。</span>

## 1 ROB 的结构与角色**ROB（重排序缓冲）**：一个按程序顺序排列的环形缓冲，每条指令分配一个 ROB 项：

| ROB 项 | 内容 |
| --- | --- |
| 指令 | 操作码、目标寄存器 |
| 状态 | 已发射 / 已执行 / 已提交 |
| 结果 | 执行完的数值（暂存，不写寄存器堆） |

**生命周期**：

1. **发射**：指令进入 ROB，分配一个项（按程序顺序）。
2. **执行**：乱序执行，结果写回 ROB 项（**不写寄存器堆**）。
3. **提交**：ROB 头部的指令——若已执行完且无异常——把结果写进寄存器堆，然后移出 ROB。

**核心概念：提交（commit）是「副作用生效」的唯一时刻**——寄存器堆/内存只在提交时更新。<span class="marginnote">ROB 让「执行」与「提交」分离：执行快慢无关紧要，提交严格按程序顺序。异常发生在某条指令时，它之前的已提交（保留）、之后的未提交（作废）——精确异常自动满足。分支预测错也一样：错误路径的指令在 ROB 里未提交，直接作废即可。</span>

## 2 ROB 与保留站的分工现代 CPU 同时有**保留站（调度执行）**与 **ROB（按序提交）**，职责不同：

| 结构 | 负责 | 谁用 |
| --- | --- | --- |
| 保留站 | 等操作数、调度执行 | 执行前 |
| ROB | 存结果、按序提交、异常/分支回滚 | 执行后 |

**核心概念：执行用 Tomasulo（保留站），提交用 ROB——两套机制各管一段**。<span class="marginnote">历史沿革：IBM Power 与 Intel P6 用「ROB 替代保留站做重命名」（ROB 同时当重命名表），简化硬件但限制发射。现代 Intel（P6 之后）重新分离「物理寄存器堆 + 重命名映射表」，发射宽度更大——这是微架构设计的演进细节。</span>

## 3 寄存器重命名的现代形态现代 CPU 的寄存器重命名不是「给逻辑寄存器换名」这么简单，而是**物理寄存器堆（PRF）**：

- **架构寄存器（逻辑，如 `%rax`、`%rbx`）** 程序员看到的名称。
- **物理寄存器**：硬件里实际存值的寄存器，数量多于架构寄存器（如 32 个逻辑 → 192 个物理）。
- **重命名映射表（RAT）**：记录「每个逻辑寄存器当前对应哪个物理寄存器」。

$$\%rax \xrightarrow{\text{RAT}} \text{物理寄存器 } P_{137}$$

**写入时分配新物理寄存器**：每次写入都分配一个新的物理寄存器写进去，同时更新 RAT——旧值仍在旧物理寄存器里（供之前已发射的指令读取）。<span class="marginnote">这就是 WAR/WAW 被消除的硬件细节：每次写寄存器都「另开新账本」，两条写同一逻辑寄存器的指令写到不同物理寄存器，互不等待——假冒险在物理层面消失。「旧值保留」也让分支预测错误回滚变得简单（RAT 快照恢复）。</span>

## 4 公式解析：物理寄存器数怎么定设逻辑寄存器 $n$ 个、乱序窗口（在途指令数）$W$，则物理寄存器数量：

$$P \approx n + W$$

逐项拆解：

- **第一步，基线**：至少 $n$ 个物理寄存器对应 $n$ 个逻辑寄存器。
- **第二步，乱序窗口**：每条在途指令最多占一个新物理寄存器（写目标时分配），共需 $W$ 个。
- **第三步，合计**：物理寄存器 ≈ 逻辑 + 窗口大小。

例：32 个逻辑寄存器、乱序窗口 200 → 物理寄存器约 232（实际取 2 的幂，如 256）。<span class="marginnote">物理寄存器堆是现代 CPU 最大的结构之一（256 个 64 位寄存器 + 端口）。「乱序窗口越大，物理寄存器越多」是硬件面积与 ILP 的又一权衡——这也是「发射宽度不能无限加」的物理约束之一。</span>

## 5 辨析｜易错点：ROB 与重命名**辨析｜易错点：**

- **ROB ≠ 保留站**：保留站管「执行前的调度」，ROB 管「执行后的提交」——一前一后，别混。
- **ROB 提交 ≠ 写寄存器堆的时刻不同**：执行完先写 ROB，提交才写寄存器堆——中间隔着「等前面指令提交」的时间。
- **寄存器重命名消除的是 WAR/WAW，不消除 RAW**：真依赖（RAW）仍需保留站等值 + 前递。
- **分支预测错误靠 ROB 回滚**：错误路径指令未提交，作废即可；RAT 快照恢复——这是「预测安全」的硬件保障。

## 6 拓展：ROB 与物理寄存器堆的现代分工现代 CPU 的「寄存器重命名」有两种组织方式：- **ROB 兼作重命名表（老式）**：结果只写 ROB，提交时才写寄存器堆——简单但发射宽度受限（ROB 端口有限）。
- **物理寄存器堆 PRF（现代）**：执行完直接写 PRF 的物理寄存器，ROB 只记录「按序提交」——发射宽、乱序深，是主流。

**核心概念：现代方案是「执行写 PRF、提交靠 ROB」**——ROB 不再存结果，只管「按程序顺序确认」。这解耦了「执行深度」与「提交深度」。

**辨析｜易错点：**ROB 满时**必须停止发射**——因为新指令没有 ROB 项可分配（无法保证按序提交）。「ROB 满停发」是乱序 CPU 的常见停顿原因，也是「乱序窗口大小」=「ROB 大小」说法的来源。

## 7 拓展：ROB 与物理寄存器堆现代方案：执行写 PRF（物理寄存器堆），ROB 只管「按序提交」——执行与提交深度解耦。

重命名映射表 RAT：逻辑寄存器 → 物理寄存器，每次写分配新物理寄存器，旧值保留供旧指令读。

**五条必记**：
- 物理寄存器 ≈ 逻辑 + 乱序窗口（如 32+200 ≈ 232）。
- 提交 = 副作用生效的唯一时刻，异常可精确切割。
- 分支预测错误靠 ROB 作废未提交指令 + RAT 快照恢复。
- 保留站管执行前、ROB 管执行后——一前一后分工。
- 重命名消除 WAR/WAW，不消除 RAW（RAW 靠保留站等值+前递）。

**辨析｜易错点**：ROB 满必须停发射——新指令没 ROB 项无法保证按序提交。「乱序窗口大小 = ROB 大小」。

## 8 核心要点
- 执行乱序、提交按序（ROB）。
- 物理寄存器 ≈ 逻辑 + 乱序窗口。
- 重命名消除 WAR/WAW，保留站解决 RAW。
- 分支回滚靠 ROB 作废 + RAT 快照。
- 提交是副作用生效的唯一时刻。

## 9 小结- **ROB**：按程序顺序的提交缓冲，执行乱序、提交按序。
- 生命周期：发射进 ROB → 乱序执行写回 ROB → 按序提交写寄存器堆。
- 分工：**保留站管执行、ROB 管提交**——Tomasulo + ROB 是现代组合。
- **寄存器重命名**：RAT 映射逻辑→物理寄存器，每次写分配新物理寄存器，消 WAR/WAW。
- 物理寄存器 ≈ 逻辑 + 乱序窗口；ROB 保证精确异常与分支回滚。
