## 为什么浮点运算器要用流水线

定点加法一个周期完成，浮点加法却要对阶、求和、规格化、舍入四步——每一步都是独立的硬件阶段。如果每步各占一个时钟周期、串行执行，一次浮点加法要 4 周期。**流水线（pipeline）**的思路是：把这 4 个阶段变成 4 级独立电路，让不同的数「错峰」通过——第一级正在对阶第 5 个数时，第四级正在舍入第 2 个数。这样**吞吐率翻 4 倍**，虽然单条延迟不变。这一课讲浮点运算器的部件结构与流水线化设计，是第六篇流水线专题的第一次预习。<span class="marginnote">「延迟（latency）不变、吞吐（throughput）提升」是流水线的核心 trade-off：单个运算没有变快，但单位时间完成的运算数变多了。这正是 GPU 与神经网络加速器碾压 CPU 的秘密。</span>

## 1 浮点运算器的组成一个典型的浮点运算单元（FPU）由三大部分组成：

**阶码运算部件**：负责阶码比较、加减、bias 修正，核心是一个小加法器与比较器。
**尾数运算部件**：负责尾数对齐移位、加减、乘除，核心是定点加法器/乘法器阵列与桶形移位器。
**规格化与舍入部件**：负责左规/右规、判断阶码溢出、执行舍入（就近取偶等）。

它们之间的连接按「四步流程」串联，天然适合流水线划分。<span class="marginnote">x86 的 x87 浮点单元与 SSE 的向量浮点单元是 FPU 的两个历史形态；现代 CPU 的 FPU 与整数 ALU 并行布置，分别服务浮点与整数组件——这个「双轨」结构到《超标量流水线》一课会展开。</span>

## 2 浮点加法流水线的四级划分以浮点加法为例，把四步各分一级：

| 流水级 | 功能 | 关键部件 |
| --- | --- | --- |
| E1 | 对阶（比较阶码、尾数右移） | 阶码比较器、桶形移位器 |
| E2 | 尾数求和 | 定点加法器 |
| E3 | 规格化（左规/右规） | 前导零检测 + 移位器 |
| E4 | 舍入 | 舍入逻辑、加法器 |

每级之间用**锁存器（latch）**隔离，一个时钟周期后把结果交给下一级。4 级流水线让 4 个浮点加法「同时在途」。

**重点：流水线理想吞吐 = 每周期完成一个结果**，尽管单个加法的延迟仍是 4 周期。<span class="marginnote">「流水线深度」与「单级延迟」要平衡：级数越多，理论吞吐越高，但级间锁存器开销越大，且任何一级的等待都会造成气泡。真实 FPU 的浮点加法流水线通常 3–5 级。</span>

## 3 浮点乘法与加法的流水线组合浮点乘法单元（FMUL）通常是独立的流水线：尾数乘法（阵列乘法器）占多级，阶码相加一级，规格化舍入一级。

现代 CPU 常把 FMUL 与 FADD 做成**两条并行流水线**：

FADD 流水线：对阶 → 求和 → 规格化 → 舍入。
FMUL 流水线：尾数相乘 → 规格化 → 舍入。

因为乘加运算（fused multiply-add, FMA）太常见，后来干脆合并成 **FMA 单元**：一次完成 $a \times b + c$，中间乘积**不单独舍入**——这比「先乘后加各舍入一次」精度更高，还省一条指令。<span class="marginnote">FMA 是近二十年浮点硬件最重要的改进：深度学习里的矩阵乘、卷积全用它。Tensor Core 本质就是高吞吐的 FMA 阵列——一条 FMA 同时省一次舍入、一次读写，精度和速度双赢。通往第四级《大模型部署》的矩阵乘优化。</span>

## 4 公式解析：流水线加速比设浮点加法 4 级流水，每级 1 周期，连续执行 $n$ 次加法：

$$T_{\text{流水}} = 4 + (n - 1) \quad\text{周期}$$

$$S = \frac{T_{\text{串行}}}{T_{\text{流水}}} = \frac{4n}{n + 3}$$

逐项拆解：

- **第一步，首条延迟**：第一条加法要 4 周期才能走出流水线（填充阶段）。
- **第二步，稳态**：此后每周期出一条结果，共 $n-1$ 条。
- **第三步，加速比**：$n$ 很大时 $S \to 4$，即「流水深度倍」；$n=4$ 时 $S = 16/7 \approx 2.29$，说明流水线在短序列下收益有限。

**核心结论：流水线在「长序列、无依赖」时吞吐最大；短序列或频繁依赖（冒险）会打折扣**——后者是第六篇流水线冒险专题的主角。<span class="marginnote">这个加速比公式与《阿姆达尔定律》一脉相承：流水线只改进了「执行阶段」这一部分，固定开销（填充/排空）是那个 $1-f$。</span>

## 5 辨析｜易错点：延迟 vs 吞吐| 指标 | 定义 | 流水线影响 |

| --- | --- | --- |
| 延迟（latency） | 单条指令从进到出 | 不变（仍 4 周期） |
| 吞吐率（throughput） | 每周期完成的指令数 | 提升到 1 |
| 流水线填充时间 | 首条指令出流水线的等待 | 序列越长占比越低 |

**辨析｜易错点：**（1）流水线**不缩短单条延迟**，只提升吞吐——「加了流水线单次加法变快」是错误说法；（2）浮点流水线与定点流水线对依赖处理不同：浮点加法器内部各阶段的「对阶移位量」随数据变化，导致某些级延迟可变，设计更复杂；（3）分支、异常、除法等「长尾操作」会打断流水线，需要停顿与重定向机制。

## 6 拓展：Tensor Core 与 FMA 的算力账「FMA 一次完成 $a \times b + c$」如何撑起 AI 算力？以 NVIDIA Tensor Core 为例：

- 一个 Tensor Core 每周期做 4×4×4 的矩阵乘加 = 64 次 FMA（128 次浮点运算）。
- 一个 GPU SM 含多个 Tensor Core，整卡几千个——浮点算力达到 PFLOPS（每秒千万亿次）级。

**核心概念：AI 算力的公式 = FMA 单元数 × 频率 × 每 FMA 的运算次数**——深流水线 + 海量 FMA 单元 + 高并行，是 GPU 碾压 CPU 的三板斧。

**辨析｜易错点：**FMA 的「不单独舍入」既是优点也是语义差异：FMA 的结果与「先乘后加（分开舍入）」的结果可能差一个 ulp——依赖 FMA 行为的代码要在「精确 vs 可移植」间权衡。编译器开 `-ffp-contract=fast`（GCC/Clang）会把普通乘加换成 FMA，结果不同但更快。

## 7 考点速记：浮点运算器与流水线**组成**：阶码部件（比较/加减/bias 修正）+ 尾数部件（加法器/乘法器阵列/桶形移位器）+ 规格化舍入部件。

**浮点加法流水线**：对阶 → 求和 → 规格化 → 舍入，4 级。

**五条必记**：
- 流水线延迟不变、吞吐提升——单条浮点加仍 4 周期。
- 加速比 S = 4n/(n+3)，长序列趋近 4。
- FMA 一次完成 a×b+c，中间不单独舍入——精度速度双赢。
- Tensor Core = 高吞吐 FMA 阵列，AI 算力的秘密。
- FMUL 与 FADD 两条独立流水线，现代合并 FMA。

**辨析｜易错点**：流水线不缩短单条延迟——「加流水线单次变快」是错的，它只提吞吐。

- 流水线延迟不变、吞吐提升。

## 9 小结- FPU 组成：**阶码部件、尾数部件、规格化舍入部件**，按四步流程串联。
- 浮点加法流水线：对阶 → 求和 → 规格化 → 舍入，4 级。
- **FMA（乘加融合）**：一次完成 $a\times b+c$，中间不单独舍入，精度速度双赢，是深度学习硬件的基石。
- 流水线加速比 $\to$ 级数倍，但**延迟不变**，短序列收益有限。
- GPU/TPU 的算力秘密：海量 FMA 单元 + 深流水线 + 高并行。
