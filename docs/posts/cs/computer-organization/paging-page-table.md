## 为什么页表是虚拟内存的「神经中枢」

虚拟内存说「把 VA 翻译成 PA」，翻译的依据就是**页表（page table）**——一张记录「每个虚拟页 → 哪个物理页（或磁盘）」的表。本课把页式存储的地址划分、页表项（PTE）的结构、缺页处理与地址翻译流程讲透。页表是理解虚拟内存一切细节的钥匙：多级页表、TLB、存储保护、缺页中断，全部围绕它展开。<span class="marginnote">「页表是一张映射表」——它把庞大的虚拟页号空间映射到较小的物理页号空间。这个映射的存储与查找效率，决定了虚拟内存能否实用，也催生了 TLB 与多级页表两大工程发明。</span>

## 1 分页的地址划分**分页（paging）**：虚拟地址与物理地址都被切成**固定大小的页**，页大小 $P$（通常 4KB）。

$$\text{虚拟地址} = \underbrace{\text{虚拟页号（VPN）}}_{\text{高位}} \parallel \underbrace{\text{页内偏移（VPO）}}_{\text{低位}}$$

$$\text{物理地址} = \underbrace{\text{物理页号（PPN）}}_{\text{高位}} \parallel \underbrace{\text{页内偏移（PPO）}}_{\text{低位}}$$

**关键性质**：虚拟页偏移与物理页偏移**位数相同**（页大小相同），地址翻译只需把 VPN 换成 PPN，偏移部分**原样保留**。<span class="marginnote">「偏移不翻译」是分页的美妙之处：页内的 12 位（4KB 页）从虚拟到物理不变，MMU 只换高位的页号。这保证了「同一虚拟页内的连续地址仍映射到同一物理页内的连续地址」。</span>

## 2 页表项（PTE）的结构**页表（page table）** 是一个**数组**：虚拟页号 VPN 是下标，页表项 PTE 是内容。PTE 关键字段：

**有效位（valid）**：该虚拟页是否已分配。
**物理页号（PPN）**：映射到哪个物理页。
**访问权限位**：读/写/执行（见《存储保护》）。
**脏位 / 引用位**：是否被写过/访问过（供替换与写回用）。

一个典型 PTE（32 位示例）：

| 有效 | 权限 | 脏/引用 | PPN（20 位） |

**重点：PTE 同时承担「缓存副本定位」与「保护决策」双重职责**——它既是 Cache 式地址翻译的依据，又是权限检查的依据。<span class="marginnote">PTE 的权限位让「一个页」成为内存保护的最小单元：代码页只读可执行、数据页可读可写、某些页连读都不行。这些位由操作系统在加载程序时设置，硬件 MMU 负责检查。</span>

## 3 地址翻译流程与缺页一次完整的翻译流程：

1. MMU 把虚拟地址拆成 VPN + VPO。
2. 用 VPN 查页表（先查 TLB 快表，见下一课）。
3. **有效位 = 1**：取出 PPN，拼上 VPO 得物理地址，访问内存。
4. **有效位 = 0**：该页不在内存 → **缺页（page fault）**：
MMU 触发异常，操作系统接管。
OS 从磁盘读入该页到某个空闲物理页。
更新页表项（有效位置 1、填 PPN），重新执行被中断的指令。

**核心概念：缺页中断（page fault）**——它不是错误，而是「数据在磁盘、需要调入」的正常流程。操作系统把「读磁盘 + 更新页表 + 重执行」一气呵成。<span class="marginnote">缺页的处理要「重新执行指令」：指令取数时缺页，等页调入后，CPU 从头再执行这条指令。这要求 CPU 支持「异常后精确重执行」，与《流水线的中断处理》一课的精确异常直接相关。</span>

## 4 公式解析：页表大小页表占多少内存，是分页设计的核心账。设虚拟地址 $n$ 位、页大小 $P=2^p$ 字节、每个 PTE $e$ 字节：

$$\text{页表项数} = 2^{n-p}, \qquad \text{页表大小} = 2^{n-p} \times e$$

例：32 位地址、4KB 页、PTE 4 字节：

$$\text{页表大小} = 2^{32-12} \times 4 = 2^{20}\times4 = 4\,\text{MB}$$

逐项拆解：

- **第一步，页表项数**：$2^{20}$ 个（每个虚拟页一项）。
- **第二步，单表大小**：每个进程一张 4MB 页表——100 个进程就要 400MB。
- **第三步，问题的根源**：页表要**连续存放**且随时可查，4MB 连续分配不现实；更糟的是 64 位下这个数字是天文数字。

**结论：单级页表「一次建全」不可行，必须多级页表按需建立**——这是下一课的主题。<span class="marginnote">「页表本身也占内存」常被初学者忽略。4GB 虚拟空间、4KB 页的进程，即使只用一点点内存，单级页表也要预留 4MB。多级页表按需分配解决了「大而不全」的浪费。</span>

## 5 辨析｜易错点：分页常见错误**辨析｜易错点：**

- **VPN 是页表下标，不是地址**：翻译时先把虚拟地址右移 12 位得到 VPN，再索引页表，别把「页号」当「字节地址」。
- **偏移不翻译**：VPO = PPO，虚拟与物理页内偏移相同。
- **缺页是「慢的正常」，段错误是「坏的错误」**：有效位为 0 且地址合法 → 缺页（正常调入）；地址非法（如越界）→ 段错误（进程崩溃）。
- **页表属于每个进程**：每个进程一张独立页表，进程切换时要切换页表（CR3 寄存器）——这就是「上下文切换」的一部分。

## 6 拓展：PTE 的权限位如何保护页一个典型 64 位 PTE 的字段不止「有效位 + PPN」：| 位 | 含义 |
| --- | --- |
| Present | 页是否在内存（有效位） |
| R/W | 是否可写 |
| U/S | 用户态是否可访问 |
| A/D | 是否被访问/修改（供替换算法用） |
| PPN | 物理页号 |

**核心概念：PTE 是「保护的最小单元」**——代码页设 R+X、数据页设 R+W、栈页 R+W 且不可执行，MMU 每次访问检查这些位。NX（不可执行）就是 PTE 的「X 位」为 0。

**辨析｜易错点：**「有效位为 0 = 页不存在」与「缺页」的关系：有效位为 0 且地址合法（虚拟页已分配、数据在磁盘）→ 缺页调入；有效位为 0 且地址非法（未分配的虚拟地址）→ 段错误。同一个 PTE 位，两种语义由「地址是否在合法区间」区分。

## 7 补充：分页速记- 分页：虚拟与物理按固定页切分，VPN→PPN 翻译、偏移原样保留。
- 页表：以 VPN 为下标的数组，PTE 含有效位、PPN、权限、脏/引用位。
- 翻译：查页表（先 TLB）→ 有效位判断 → 命中/缺页。
- 缺页是「数据在磁盘」的正常流程，OS 调页并重执行。
- 单级页表大小 = 2^(n-p)×e，64 位不可行 → 多级页表。

## 8 一句话回顾- 分页 = VPN→PPN 翻译，偏移原样保留。
- 页表以 VPN 为下标，PTE 管有效/权限/脏位。
- 缺页是正常调入流程，不是错误。

## 9 核心公式
- 页表项数 = 2^(n-p)。
- 页表大小 = 2^(n-p) × e。
- VPN 查表、VPO=PPO 不翻译。
- 缺页 = 有效位 0 且数据在磁盘。

## 10 小结- 分页：虚拟与物理都按固定页切分，**VPN→PPN 翻译、偏移原样保留**。
- **页表**是以 VPN 为下标的数组，PTE 含有效位、PPN、权限位、脏/引用位。
- 翻译流程：查页表（先 TLB）→ 有效位判断 → 命中访问 / 缺页调页。
- **缺页**是「数据在磁盘」的正常流程，由 OS 调页并重执行指令。
- 单级页表大小 = $2^{n-p}\times e$，64 位下不可行 → 多级页表。
