## 为什么写比读复杂得多

读 Cache 只要「找到数据」；写 Cache 却要回答一个折磨人的问题：**改了 Cache，主存怎么办？** 立即写回主存（写直达）简单但慢；先攒着、被换出时再写（写回）快但有「数据不一致」风险。再加上「写未命中时先取块还是直接改」（写分配 vs 写不分配），Cache 的写策略是一组互相牵连的设计决策。本课把它们逐一讲清，并引出**写缓冲（write buffer）**这个把「写直达」变快的工程技巧。<span class="marginnote">写策略的深层问题是「一致性」：主存与 Cache 是同一数据的两个副本，写操作让它们分叉。Cache 写策略、多核缓存一致性（MESI）、数据库脏页，处理的是同一个「副本一致」难题的不同层面。</span>

## 1 两大写策略：写直达与写回### 写直达（write-through）

**写直达**：每次写 Cache 命中时，**同时**把数据写入主存。

- 优点：主存始终与 Cache 一致，实现简单；无需脏位。
- 缺点：每次写都要访问慢速主存，**写操作的延迟被主存拖累**。

### 写回（write-back）

**写回**：写 Cache 命中时**只写 Cache**，并给该行置**脏位（dirty bit）**；只有当该行被替换（逐出 Cache）时，才把整行写回主存。

- 优点：写操作只碰快 Cache，快；主存写次数大幅减少。
- 缺点：主存与 Cache 可能长期不一致（数据「脏」在 Cache 里）；被替换时需要额外写回，驱逐变慢；需要脏位硬件。<span class="marginnote">写回策略的代价藏在「逐出」：一个脏行被替换时要先写回主存才能腾出槽位——这使未命中的处理延迟变长。现代 CPU 用「写回 + 脏位 + 写回缓冲」的组合，把写回延迟藏起来。</span>

## 2 写未命中：写分配与写不分配写操作发现目标块不在 Cache 中（写未命中），有两种应对：

- **写分配（write-allocate）**：先把主存块调入 Cache，再修改 Cache——像读未命中一样先取块。配合写回策略常用（因为后续可能反复写）。
- **写不分配（no-write-allocate）**：不调入 Cache，**直接写主存**（或写旁路缓冲）。配合写直达常用——既然每次都写主存，何必调块进来。

**典型组合**：写直达 + 写不分配（写少读多场景）；写回 + 写分配（写密集场景）。这两种搭配是教材默认的「合理配对」，但并非强制。<span class="marginnote">直觉：写回策略下「写分配」才有意义——块调进来后写操作都在 Cache 里进行，脏了再整体写回；写直达下「写分配」反而多此一举，每次都写主存，调块进来纯属浪费。记住「写回+分配、写直达+不分配」的配对逻辑，比背结论更可靠。</span>

## 3 公式解析：写直达的代价与写缓冲写直达的最大痛点是「每次写都访问主存」。设写命中率 $h_w$，Cache 命中写时间 $t_c$，主存写时间 $t_m$，写操作的平均时间：

$$T_w = h_w \cdot t_c + (1 - h_w) \cdot (t_c + t_m) \approx t_c + (1-h_w)\cdot t_m$$

**写缓冲（write buffer）**的救场思路：写直达时，把写主存的动作「异步化」——

1. 写 Cache 的同时，把数据放进一个**写缓冲（FIFO）**，CPU 立即继续执行。
2. 后台电路在空闲周期慢慢把缓冲里的数据写入主存。

逐项拆解：

- **第一步，同步写**：没有写缓冲时，CPU 等主存写完才继续，写延迟 $= t_m$。
- **第二步，缓冲写**：写缓冲把 CPU 与主存解耦，CPU 只需等缓冲入队（几个周期）。
- **第三步，风险**：写缓冲满时 CPU 仍要等待；且**后续读操作若指向缓冲里尚未写主存的数据，必须先查写缓冲**（否则读到旧值）。

**结论：写缓冲把「写直达」的可见延迟从主存级降到缓存级**，代价是额外的查询逻辑与缓冲满时的回退。<span class="marginnote">写缓冲本质上是一个「异步写队列」——它与第八篇《DMA》的异步思想同源：让慢设备不阻塞快设备。现代 CPU 有几十个条目的写缓冲，配合写合并（write combining）还能批量提交相邻写。</span>

## 4 辨析｜易错点：写策略对照表| 维度 | 写直达 | 写回 |

| --- | --- | --- |
| 写命中时 | 同时写主存 | 只写 Cache，置脏位 |
| 主存一致性 | 始终一致 | 可能不一致 |
| 脏位 | 不需要 | 需要 |
| 写延迟 | 高（被主存拖累） | 低（只碰 Cache） |
| 主存写次数 | 多 | 少 |
| 典型搭配 | 写不分配 | 写分配 |

**辨析｜易错点：**（1）「写直达」不是「直接改主存不改 Cache」——它**先写 Cache 同时写主存**，Cache 里照样有最新值；（2）脏位的语义是「本行比主存新」，不是「本行无效」；（3）写回策略下「逐出脏行」要先写回，所以「逐出代价」因脏位而异；（4）读未命中与写未命中的调块策略可以不同，题目要看清是读还是写。

## 5 写策略的一致性视角写策略其实在回答「副本一致」的两个子问题：

- **Cache 与主存的一致性**：写直达保证强一致（每写必同步），写回保证最终一致（逐出时同步）。
- **多核 Cache 间的一致性**：当两个核各有一个 Cache 时，写回策略会带来「核 A 改了、核 B 还拿着旧值」的问题——这需要缓存一致性协议（MESI）来解决，是第六篇的专课。

**核心要点**（本课主题偏策略选择，用表格总结决策依赖）：

| 决策点 | 选项 | 适用场景 |
| --- | --- | --- |
| 写命中 | 写直达 / 写回 | 一致性要求 vs 性能 |
| 写未命中 | 写分配 / 写不分配 | 是否预取块 |
| 写延迟 | 同步 / 写缓冲 | 延迟敏感 vs 复杂度 |

## 6 考点速记：Cache 写策略| 决策 | 选项 | 要点 || --- | --- | --- |
| 写命中 | 写直达 | 同时写主存，简单一致但慢 |
| 写命中 | 写回 | 只写 Cache + 脏位，逐出时写回 |
| 写未命中 | 写分配 | 先调块再改（配写回） |
| 写未命中 | 写不分配 | 直接写主存（配写直达） |

**五条必记**：

- 写直达：Cache 与主存始终一致，但每次写都访问慢主存。
- 写回：脏位标记「Cache 比主存新」，逐出脏行要先写回。
- 典型配对：「写回+写分配」「写直达+写不分配」。
- **写缓冲**：把写主存异步化，CPU 不等待——但读要查缓冲、满了要回退。
- 写策略是多核一致性（MESI）的前置：先有写回才有一致性问题。

**辨析｜易错点：**「写直达 = 直接改主存不改 Cache」是错的——写直达**先写 Cache 同时写主存**，Cache 里有最新值。脏位是「本行比主存新」，不是「本行无效」。

## 7 一句话回顾- 写直达同步写主存、写回置脏位逐出写。
- 写分配配写回、写不分配配写直达。
- 写缓冲异步化写主存。

## 8 小结- **写直达**：命中即同步写主存，简单一致，但写延迟被主存拖累。
- **写回**：命中只写 Cache 并置脏位，逐出时整体写回，快但需一致性管理。
- **写分配 / 写不分配**决定写未命中是否调块；典型配对「写回+分配、写直达+不分配」。
- **写缓冲**异步化写主存，把可见写延迟降到缓存级，满时需回退且读要查缓冲。
- 写策略是多核一致性（MESI）的起点：先有 Cache 写回，才有一致性问题。

- 写直达同步写主存、写回置脏位逐出写
- 写分配配写回、写不分配配写直达
- 写缓冲异步化写主存
- 脏位是「比主存新」
- 逐出脏行要先写回
- 写策略是一致性的前置
- 读缺失与写缺失策略可不同
- 副本一致是写策略的本质问题
