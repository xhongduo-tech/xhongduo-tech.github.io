## 为什么「机械」决定了磁盘的一切

磁盘是唯一仍在高速运转的机械部件：盘片旋转、磁头移动，一切性能都由物理运动决定。本课讲磁盘的物理结构（磁道、扇区、柱面）、性能三指标（寻道、旋转、传输）与**磁盘调度算法**（先来先服务、最短寻道、电梯算法等）——这些算法优化「磁头怎么走」，是操作系统存储子系统的经典内容。<span class="marginnote">机械硬盘的访问时间是「毫秒级」，比内存（ns）慢 6 个数量级——因为磁头要物理移动。磁盘调度的全部意义：<strong>把随机访问变成有序访问，减少磁头来回跑的机械开销</strong>。SSD 没有寻道，磁盘调度也由此式微。</span>

## 1 磁盘的物理结构- **盘片（platter）**：圆盘，两面都记录数据。
- **磁道（track）**：盘片上的同心圆。
- **扇区（sector）**：磁道的一段，通常 512B/4KB——**最小读写单位**。
- **柱面（cylinder）**：所有盘面上同一半径的磁道集合。
- **磁头（head）**：读写数据，由机械臂带动在磁道间移动。

$$\text{磁盘容量} = \text{盘面数} \times \text{每面磁道数} \times \text{每道扇区数} \times \text{扇区大小}$$

**核心概念：扇区是最小读写单位**——即使只读 1 字节，也要读整个扇区（512B 或 4KB）。这就是文件系统「按块读写」的原因。<span class="marginnote">「扇区大小」与文件系统的「块」有关联：文件系统块（4KB）通常是扇区（512B）的整数倍。SSD 的「页/块」、文件系统的「块」、磁盘的「扇区」是三层不同大小的「块」——理解磁盘先分清这三层。</span>

## 2 磁盘的性能指标一次磁盘访问的时间 = 三个部分：

$$T_{\text{access}} = T_{\text{seek}} + T_{\text{rotate}} + T_{\text{transfer}}$$

- **寻道时间 $T_{\text{seek}}$**：磁头移动到目标磁道的时间——**占比最大**（几毫秒）。
- **旋转延迟 $T_{\text{rotate}}$**：目标扇区转到磁头下的时间——平均半圈（如 7200rpm 下约 4.2ms）。
- **传输时间 $T_{\text{transfer}}$**：数据从盘面读出的时间——通常最短。

**核心概念：磁盘访问的瓶颈是「机械移动」（寻道+旋转）**，数据传输本身反而快。<span class="marginnote">量化：7200rpm 磁盘平均旋转延迟 = 60/7200/2 ≈ 4.17ms，寻道平均约 4–10ms，而传输 4KB 只要 0.1ms 左右——一次访问 90% 以上时间在「等磁头到位」。这就是为什么「顺序读比随机读快百倍」：顺序读只需一次寻道，随机读每次都要找。</span>

## 3 磁盘调度算法多个 I/O 请求排队时，**调度算法**决定磁头先去哪个磁道——目标是「少跑路」。

| 算法 | 策略 | 特点 |
| --- | --- | --- |
| FCFS（先来先服务） | 按请求顺序 | 简单，但磁头乱跑 |
| SSTF（最短寻道优先） | 先服务最近的磁道 | 平均好，但远端可能饿死 |
| SCAN（电梯算法） | 磁头单向扫到头再回头 | 公平，避免饿死 |
| C-SCAN（循环扫描） | 单向扫，到头瞬间跳回起点 | 等待时间更均匀 |
| LOOK / C-LOOK | 只扫到最远请求处 | 优化 SCAN 的空跑 |

**核心概念：SCAN 像电梯**——磁头沿一个方向服务所有请求，到头再反向。它避免 SSTF 的「饥饿」问题，是现代磁盘调度的经典方案。<span class="marginnote">「电梯算法」的名字很贴切：电梯不会因为 2 楼有人就丢下 10 楼的人，而是沿一个方向服务完再回头。SCAN 保证了「每个请求最多等一圈」——公平性有界。LOOK 的改进是不扫到物理边界，只到最远请求处就回头，省空跑时间。</span>

## 4 公式解析：磁盘平均访问时间设寻道平均 $T_s$、旋转延迟平均 $T_r$、传输 $T_t$：

$$T_{\text{avg}} = T_s + T_r + T_t$$

例：7200rpm 磁盘、$T_s=8$ms、$T_r=4.2$ms、传 4KB $T_t=0.1$ms：

$$T_{\text{avg}} = 8 + 4.2 + 0.1 = 12.3\ \text{ms}$$

逐项拆解：

- **第一步，寻道**：磁头移动，机械最慢。
- **第二步，旋转**：平均半圈等扇区。
- **第三步，传输**：数据读出，最快。
- **第四步，比例**：机械时间占 99%——**这就是磁盘调度价值所在**。

**核心结论：磁盘访问时间的 99% 是机械时间——任何减少寻道/旋转的优化（调度、预读、缓存）都是巨幅收益**。<span class="marginnote">「顺序 vs 随机」的量化：顺序读（一次寻道后连续读 1MB）≈ 寻道 8ms + 传输几十 ms；随机读 1MB（256 个 4KB 扇区）≈ 256 × 12ms ≈ 3 秒——差 100 倍。数据库为什么用 B+ 树？它把随机插入变成有序叶子遍历，把随机 I/O 转顺序 I/O——磁盘物理决定数据结构设计。</span>

## 5 辨析｜易错点：磁盘概念**辨析｜易错点：**

- **寻道时间 ≠ 旋转延迟**：寻道是「磁头横移」，旋转是「盘片等扇区」——两个不同机械运动，别混。
- **SSTF 不是最优**：SSTF 贪心局部最近，全局未必最优（可能错过「路径上更顺的请求」）；且会饿死远端。
- **磁盘容量算错单位**：厂商用十进制（1GB=10⁹），系统用二进制（1GiB=2³⁰）——「500GB 只有 465GiB」的原因。
- **扇区是硬件单位、块是文件系统单位**：扇区由磁盘物理决定，块由文件系统逻辑决定——两层概念。

## 6 拓展：磁盘访问时间的完整算例一块 7200rpm 磁盘，平均寻道 8ms，传输速率 100MB/s。计算读一个 4KB 扇区的平均时间：

- 平均旋转延迟 = 60/7200/2 ≈ 4.17ms。
- 传输时间 = 4KB / 100MB/s = 0.04ms。
- 平均访问 = 8 + 4.17 + 0.04 ≈ 12.2ms。

再算顺序读 1MB（256 个扇区连续）：一次寻道 + 旋转 + 256×0.04ms 传输 ≈ 8 + 4.17 + 10.2 ≈ 22.4ms。

对比随机读 1MB：256 次独立访问 ≈ 256 × 12.2ms ≈ 3.1 秒——**顺序比随机快 140 倍**。

**核心结论：磁盘调度的全部意义就是「把随机访问变成顺序访问」**——电梯算法、预读、缓存都是这个目标。

**辨析｜易错点：**「寻道时间」是磁头横移，「旋转延迟」是等扇区转过来——两个独立机械动作。有些题把两者合并叫「定位时间」，注意区分。
