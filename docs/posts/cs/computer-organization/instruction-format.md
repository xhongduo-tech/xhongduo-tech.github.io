## 为什么指令是「操作码 + 地址码」的二元结构

程序最终要变成一串二进制指令，而每条指令必须回答两个问题：**做什么**（加、减、跳转、读内存）与**对谁做**（操作数在哪）。前者是**操作码（opcode）**，后者是**地址码（address code）**。本课从指令的二元结构出发，讲清三地址、二地址、一地址、零地址指令的格式与语义，为后面指令寻址、操作码扩展做铺垫。理解了指令格式，你就看懂了「一条指令占几个字节」从何而来。<span class="marginnote">指令格式是 ISA（指令集体系结构）的最直接体现：RISC 的定长 32 位指令与 CISC 的变长指令，差别首先就写在格式里。本专题《RISC 与 CISC》一课会回到这个对比。</span>

## 1 指令的基本结构**核心概念：机器指令（machine instruction）**：由**操作码**与**地址码**两部分组成。

$$\text{指令} = \underbrace{\text{操作码 OP}}_{\text{做什么}} \parallel \underbrace{\text{地址码 A}}_{\text{对谁做}}$$

- **操作码（opcode）**：指出该指令执行何种操作——加、减、传送、跳转等。操作码的位数决定能表示的操作种类：$n$ 位操作码最多 $2^n$ 种操作。
- **地址码（address code）**：指出操作数所在的位置——可以是操作数本身、寄存器号、内存地址或地址的计算线索。

**操作码与地址码的位数之和 = 指令字长**。在固定指令字长下，两者此消彼长：操作码多一位，地址码就少一位。<span class="marginnote">「指令字长」与「机器字长」的关系是常考概念：指令字长可以等于、大于或小于机器字长。变长指令系统里一条指令可能跨多个字——这影响取指的复杂程度，下一课专讲。</span>

## 2 地址码的数量：零到三地址按地址码的个数，指令分为四类：

| 类型 | 格式 | 语义示例 | 特点 |
| --- | --- | --- | --- |
| 三地址 | OP A1 A2 A3 | $(A1) \text{ OP } (A2) \to A3$ | 直观，指令长 |
| 二地址 | OP A1 A2 | $(A1) \text{ OP } (A2) \to A1$ | 结果覆盖一个源，最常用 |
| 一地址 | OP A1 | $(A1) \text{ OP } (ACC) \to ACC$ | 依赖累加器 |
| 零地址 | OP | 操作数在栈顶 | 栈式机器（JVM） |

**重点：二地址指令的「结果覆盖源」语义**——`ADD R1, R2` 表示第一个地址码既作源又作目的，结果覆盖源操作数。这节省地址码位数，但改变了源操作数，需要程序员/编译器注意。<span class="marginnote">零地址指令（栈式）里操作数隐式在栈顶，指令只需操作码——JVM 字节码就是栈式指令集。三地址指令最接近高级语言的表达式（`a = b + c`），RISC 指令多用三地址形式。</span>

## 3 一地址指令与累加器**一地址指令**：只有一个显式地址码，另一个操作数隐含在**累加器（ACC）**中。

$$\text{OP } A: \quad ACC \leftarrow (ACC) \text{ OP } (A)$$

例如一地址指令 `ADD A` 表示 `ACC ← ACC + M[A]`。

**历史地位**：早期 CPU（如 8080、6502）资源少，用累加器省指令长度。代价是**每次运算都经过 ACC**，限制了并行度，且代码表达要绕着 ACC 转。<span class="marginnote">累加器机器的局限：一次运算只有一个操作数来自内存，另一个锁死在 ACC 里——写复杂表达式要多条指令。现代 CPU 已用「通用寄存器 + 三地址」取代，但累加器思想活在 SIMD 指令与某些 DSP 里。</span>

## 4 公式解析：操作码与操作种类的上限设操作码占 $m$ 位，指令字长 $L$ 位，地址码共 $n$ 位：

$$\text{操作种类上限} = 2^{m} = 2^{L - n}$$

逐项拆解：

- **第一步，位数守恒**：$m + n = L$（忽略扩展技术），操作码位数 = 指令字长 - 地址码位数。
- **第二步，编码空间**：$m$ 位二进制有 $2^m$ 个组合，对应 $2^m$ 种不同操作。
- **第三步，权衡**：地址码越多（三地址），操作码越少，操作种类越受限——这就是**操作码扩展技术**（把部分地址码位借给操作码）要解决的矛盾。

例：指令字长 16 位、二地址（每地址 6 位）：操作码占 4 位，最多 16 种操作——太少，所以现代 ISA 用定长 32 位指令或变长格式。<span class="marginnote">这个「位数守恒」是理解指令格式设计的总纲：操作码与地址码的位数分配，决定了指令系统的「能力边界」。RISC 选定长 32 位、三地址，牺牲指令数密度换解码简单——后文《RISC 与 CISC》详述。</span>

## 5 辨析｜易错点：指令格式的常见误区**辨析｜易错点：**

- **地址码存的是「操作数的位置信息」，不一定是操作数本身**：它可能是立即数、寄存器号、内存地址、或地址的计算线索——下一课《数据寻址方式》会展开这些变化。
- **指令字长 ≠ 机器字长**：指令可以是半字、一字、双字；变长指令集的取指流程复杂。
- **三地址指令的结果可以覆盖源，也可以独立目标**：`SUB R3, R1, R2`（R3=R1−R2）与 `SUB R1, R1, R2`（R1=R1−R2）语义不同，别混。
- **零地址指令不是「没有操作数」**：它的操作数在栈顶，是隐式寻址，不是真的没有。

## 6 拓展：指令格式设计的现实坐标指令格式不只是教科书概念，它直接决定一条指令占几个字节、译码器多复杂：

- **RISC-V**：定长 32 位，操作码 7 位 + funct 字段 3/7 位 + 寄存器与立即数字段——所有指令同宽，译码器简单，字段位置固定。
- **ARM（Thumb）**：16 位精简指令，密度高但译码复杂，用「前缀切换」在 16/32 位间切换。
- **x86**：变长 1–15 字节，操作码 + ModRM + SIB + 位移 + 立即数——灵活但译码是现代 CPU 的前端瓶颈。

**核心概念：指令格式是「表达能力」与「解码简单性」的折中**——RISC 押注定长简单，x86 押注变长灵活，两派在市场上并存了几十年。

**辨析｜易错点：**「地址码」的位数不一定等于「能寻址的位数」——地址码可以是寄存器号（3–5 位）、立即数、或内存地址的一部分，它存的是「定位操作数的信息」，解读方式由寻址方式决定。

## 7 考点速记：指令格式五要点**要点一**：指令 = 操作码（做什么）+ 地址码（对谁做），位数之和 = 指令字长。

**要点二**：按地址码数量分零/一/二/三地址——二地址最常用（结果覆盖源），零地址是栈式。

**要点三**：一地址指令依赖累加器 ACC——操作数一个在指令里、一个隐含在 ACC。

**要点四**：操作码位数决定操作种类上限 $2^m$——与地址码此消彼长。

**要点五**：指令字长 ≠ 机器字长——指令可半字、一字、双字或变长。

**五条必记**：

- 二地址 `ADD R1, R2` 语义：R1 = R1 + R2（结果覆盖源）。
- 零地址指令操作数在栈顶（JVM 字节码）。
- 三地址最接近高级语言 `a = b + c`。
- 操作码扩展把地址码位借给操作码，增加指令种类。
- RISC 定长 32 位三地址，x86 变长。

**辨析｜易错点：**地址码存的是「操作数的位置信息」，不一定是操作数本身——可能是立即数、寄存器号、内存地址或寻址线索。

## 8 核心公式
- 指令 = 操作码 OP ∥ 地址码 A，位数之和 = 指令字长。
- 操作种类上限 $2^m$（m 位操作码）。
- 二地址：$(A1) \text{ OP } (A2) \to A1$。
- 一地址：$(A1) \text{ OP } (ACC) \to ACC$。
- 零地址：操作数在栈顶（栈式机器）。

## 9 小结- 指令 = **操作码 + 地址码**：操作码管「做什么」，地址码管「对谁做」。
- 按地址码数量分**零/一/二/三地址**，二地址最常用，零地址是栈式机器。
- 一地址指令依赖累加器 ACC，结果常写回 ACC。
- 操作码位数 = 指令字长 - 地址码位数，$2^m$ 决定操作种类上限。
- 指令字长与机器字长是两回事，变长指令系统取指更复杂。
