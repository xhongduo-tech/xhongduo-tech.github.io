## 为什么「执行一条指令」要拆成几个周期

上一课看到一条指令要经过取指、译码、执行——但严格说，CPU 的工作节拍更细致：**指令周期（instruction cycle）** 由若干**子周期**组成：**取指周期（Fetch）、间址周期（Indirect）、执行周期（Execute）、中断周期（Interrupt）**。不是每条指令都走完四个子周期——是否走「间址」取决于寻址方式，是否走「中断」取决于有无中断请求。本课把「一条指令的一生」完整展开，这是理解 CPU 时序与控制器设计的核心地图。<span class="marginnote">「指令周期」在唐朔飞教材里是第五章的主线：它定义了 CPU 的最小工作循环。流水线篇的「每个周期一条指令」其实是「指令周期重叠」——先理解单条串行周期，再理解多条并行。</span>

## 1 指令周期的四个子周期一条指令从取到执行完，可能经历：

| 子周期 | 做什么 | 谁触发 | 必走吗 |
| --- | --- | --- | --- |
| 取指周期 F | 从内存取指令 → IR，PC+1 | 每条指令 | 必走 |
| 间址周期 I | 若间接寻址，取操作数地址 | 指令含间接寻址 | 可选 |
| 执行周期 E | 执行操作码规定的操作 | 每条指令 | 必走 |
| 中断周期 INT | 响应中断：保存现场、转中断程序 | 有中断请求且被允许 | 可选 |

**核心概念：指令周期的组成 = F + (I) + E + (INT)**——括号表示可选。

**重点：不是所有指令都有间址周期**——只有寻址方式是「间接」的指令才需要额外一次访存取地址；普通指令（寄存器寻址、立即寻址）没有间址周期。<span class="marginnote">为什么间址要单独成「周期」？因为它多一次访存（取地址），访存时间远长于 CPU 内部操作，值得作为一个独立阶段对待。这也再次说明：间接寻址「慢」的根因就是多一个访存周期。</span>

## 2 各类指令的周期组成不同指令的「四季」长短不同：

- **非访存指令**（如 ADD R1, R2）：取指 + 执行，2 个子周期。
- **直接访存指令**（如 LOAD R1, [addr]）：取指 + 执行（执行内含访存），2 个。
- **间接访存指令**（如 LOAD R1, [[addr]]）：取指 + **间址** + 执行，3 个。
- **转移指令**（如 JMP addr）：取指 + 执行（执行内改 PC）。
- **含中断时**：任意指令的末尾加一个中断周期。

$$T_{\text{指令周期}} = T_F + (T_I) + T_E + (T_{INT})$$

<span class="marginnote">唐朔飞教材里经典的周期对比：非访存 2 周期、直接访存 2 周期、间接访存 3 周期。考试常问「间接寻址比直接寻址多几个周期？」——答案是一个间址周期。这个「周期数统计」是历年高频题。</span>

## 3 中断周期：保存现场的插曲**中断周期（interrupt cycle）** 出现在指令执行结束后、下一条取指前：

1. **保存返回地址**：把当前 PC（下一条指令地址）压栈。
2. **关中断（可选）**：置 IF=0，防止被更高优先级中断打断（见《多重中断》）。
3. **转入中断服务程序**：把中断服务程序入口地址装入 PC。

$$\text{返回地址} \to \text{栈}, \qquad \text{PC} \leftarrow \text{中断服务程序入口}$$

**核心概念：中断周期与取指周期的对称性**——中断周期本质是「特殊的一步：保存现场并跳转」，它让程序流「插入」一段服务程序，服务完再由返回地址恢复。<span class="marginnote">中断周期只在「有中断请求且中断被允许」时出现——CPU 在每个指令周期的末尾检查中断信号。检查点固定、响应时机确定，这就是「中断响应在指令边界」的硬件约定，也是《程序中断方式》一课的预备。</span>

## 4 公式解析：指令周期与 CPU 主频的关系设 CPU 时钟周期为 $T_c$，一条指令需 $n$ 个子周期、每子周期 $m_i$ 个时钟周期：

$$T_{\text{指令}} = \sum_{i=1}^{n} m_i \cdot T_c$$

$$\text{CPU 执行时间} = \sum_{\text{所有指令}} T_{\text{指令}} = IC \times \overline{T_{\text{指令}}}$$

逐项拆解：

- **第一步，单条时间**：指令周期 = 各子周期时钟数之和 × 时钟周期。
- **第二步，平均**：不同指令的周期数不同（2–4 个子周期），程序总时间 = 指令数 × 平均指令时间。
- **第三步，联系 CPI**：平均每条指令的周期数就是 **CPI**（cycles per instruction）——见《性能评价》一课的指标。

**核心结论：指令周期的时间 = 子周期数 × 每子周期时钟数 × 时钟周期**——其中「每子周期几个时钟」由控制方式（同步/异步）决定，见《控制方式》一课。<span class="marginnote">「一条指令要几个时钟周期」是现代 CPU 的 CPI 概念的前身：CISC 的复杂指令 CPI 可达 10+（多个子周期、微程序解释），RISC 简单指令 CPI≈1。指令周期分析是「为什么 RISC 快」的时钟级解释。</span>

## 5 辨析｜易错点：周期概念的层次**辨析｜易错点：** 时钟周期、机器周期、指令周期三个概念必须分清：

| 概念 | 定义 | 关系 |
| --- | --- | --- |
| 时钟周期 | CPU 最小时间单位（1 个脉冲） | 最小 |
| 机器周期 | 完成一个基本操作（如取指） | 含若干时钟周期 |
| 指令周期 | 完成一条指令 | 含若干机器周期 |

**辨析｜易错点：**（1）**指令周期 ≥ 机器周期 ≥ 时钟周期**，层层包含；（2）「取指周期」是一个机器周期还是几个机器周期取决于教材约定——唐朔飞常把「取指」作为一个机器周期，内含多个节拍；（3）间址、中断周期同样是「机器周期」级别——它们是「机器周期的种类」，不是「时钟周期」。三层嵌套是组成原理的必考分层。

## 6 拓展：周期数与 CPI 的关系「一条指令要几个子周期」直接决定 CPI：- 非访存指令（寄存器运算）：取指 + 执行 = 2 个子周期。
- 直接访存指令（LOAD/STORE）：取指 + 执行 = 2 个（执行内含访存）。
- 间接访存指令：取指 + 间址 + 执行 = 3 个。
- 含中断时：再加 1 个中断周期。

**核心概念：指令周期的子周期数 = 指令「工作量」的粗略度量**——间接寻址多一个间址周期（多一次访存），这正是它慢的原因。程序的平均指令周期数 ≈ CPI。

**辨析｜易错点：**指令周期、机器周期、时钟周期三层嵌套：时钟周期最小（一个脉冲）、机器周期是基本操作（含若干时钟周期）、指令周期完成一条指令（含若干机器周期）。「指令周期 ≥ 机器周期 ≥ 时钟周期」——别倒挂。

- 自测 2：中断周期在什么时候插入？
- 自测 3：三层周期嵌套的顺序？

## 7 补充：指令周期速记- 指令周期 = 取指（必）+ 间址（可选）+ 执行（必）+ 中断（可选）。
- 非访存/直接访存 2 个子周期，间接访存 3 个。
- 中断周期：保存返回地址 → 关中断 → 转服务程序。
- 指令时间 = 子周期数 × 每子周期时钟 × 时钟周期。
- 三层嵌套：时钟周期 < 机器周期 < 指令周期。

## 8 一句话回顾- 指令周期 = 取指 + (间址) + 执行 + (中断)。
- 间接寻址多一个间址周期（多一次访存）。
- 时钟 < 机器 < 指令三层嵌套。

## 9 核心公式
- 指令周期 = 取指 + (间址) + 执行 + (中断)。
- 间接寻址 3 个子周期。
- 时钟 < 机器 < 指令三层嵌套。

## 10 小结- 指令周期 = **取指（必） + 间址（可选） + 执行（必） + 中断（可选）**。
- 周期组成统计：非访存/直接访存 2 个子周期、间接访存 3 个、加中断再多一个。
- **中断周期**：保存返回地址 → 关中断 → 转入服务程序，在指令边界插入。
- 指令时间 = 子周期数 × 每子周期时钟数 × 时钟周期；平均即 CPI。
- 三层嵌套：**时钟周期 < 机器周期 < 指令周期**。

- 指令周期 = 取指+(间址)+执行+(中断)
- 间接寻址多一个间址周期
- 中断周期保存返回地址
- 时钟<机器<指令三层嵌套
- 周期数决定 CPI
- 非访存 2 周期、间接 3 周期
- 中断在指令边界检查
- 周期统计是高频考点
