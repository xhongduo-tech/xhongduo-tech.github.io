## 为什么「等依赖」是最蠢的等待

顺序流水线里，一条指令因依赖停顿，后面的全堵着。**乱序执行（out-of-order execution）**的思路：让「准备好」的指令先执行，没准备好的绕开——只要最终结果按程序顺序提交，程序语义不变。本课讲乱序执行的两大经典算法：**记分牌（scoreboard）** 与 **Tomasulo**。前者是开端，后者用「保留站 + 寄存器重命名 + 数据前递」解决了记分牌的根本缺陷，是现代 CPU 的基础。<span class="marginnote">记分牌是 CDC 6600（1964）的调度器，Tomasulo 是 IBM 360/91（1967）的浮点单元算法。半个世纪过去，Tomasulo 及其变体仍是 Intel/AMD 乱序执行的核心——因为它同时解决了 WAR/WAW 假冒险与数据前递。</span>

## 1 记分牌算法：集中式调度**记分牌（scoreboard）**：一个集中式的状态表，跟踪每条指令的执行状态与功能单元占用，按「数据就绪」原则发射指令。

状态跟踪三张表：
- **指令状态表**：每条指令到哪一步了（发射/读操作数/执行/写回）。
- **功能单元状态表**：每个功能单元是否空闲、在算什么。
- **寄存器结果状态表**：哪个功能单元将写哪个寄存器。

**优点**：简单，是乱序执行的启蒙。**致命缺陷**：
1. **结构冒险阻塞**：功能单元忙，后到指令（即使无数据依赖）也要等——浪费 ILP。
2. **无数据前递**：结果要等写回寄存器堆才能被读取。
3. **WAR/WAW 会导致停顿**：记分牌不做寄存器重命名，假冒险真实发生。

<span class="marginnote">记分牌的「WAR 停顿」例子：`r1 = r2 + r3; r2 = r4 + r5`——第二条要写 r2，第一条要读 r2。乱序下第二条可能先写完 r2，第一条就读到新值——记分牌只能停住第二条等第一条读完。Tomasulo 用寄存器重命名直接消灭这种假冒险。</span>

## 2 Tomasulo 算法：保留站 + 重命名 + 前递**Tomasulo 算法**的三件武器：

### 保留站（reservation station）

每个功能单元前配一个「保留站」队列，指令发射进保留站后，**等源操作数就绪**再执行——不是等「写回寄存器」而是等「数值就绪」。

### 寄存器重命名（register renaming）

指令的目标寄存器不再直接写寄存器堆，而是**映射到一个保留站**——后续指令读该寄存器时，去读「产生它的保留站」，而不是寄存器堆。

$$\text{读 } r_i \Rightarrow \text{读「将产生 } r_i \text{ 的那个保留站」}$$

这消除了 WAR/WAW——因为每个「逻辑寄存器」的每次写入都被重命名到独立位置。

### 数据前递（bypassing）

结果一旦算出，**立即前递**给等待它的保留站——不用等写回寄存器堆。

**核心结论：Tomasulo = 记分牌 + 寄存器重命名 + 数据前递**——它同时解决 WAR/WAW（重命名）、RAW 等待（前递）、结构阻塞（保留站缓冲）。<span class="marginnote">Tomasulo 的关键洞察：<strong>依赖跟踪从「寄存器名」变成「数值流」</strong>。一条指令等待的是「值」，不是「寄存器名」——保留站记录「我在等哪个操作的结果」，结果一到就前递。寄存器重命名让「名字冲突」消失，剩下的只有真依赖 RAW。</span>

## 3 公式解析：记分牌 vs Tomasulo 的停顿对比设程序含 $f$ 比例的真依赖（RAW）、$g$ 比例的假依赖（WAR/WAW）：

$$\text{记分牌停顿} \propto f + g \quad(\text{真假都停})$$

$$\text{Tomasulo 停顿} \propto f \quad(\text{重命名消除假依赖})$$

逐项拆解：

- **第一步，记分牌**：真依赖要等（数据没到），假依赖也要等（名字冲突）——两类都付代价。
- **第二步，Tomasulo**：假依赖被重命名消除，只有真依赖（RAW）需要等待前递。
- **第三步，前递收益**：RAW 也被「算完即送」大幅缓解，只留「LOAD-use」等少数停顿。

**核心结论：Tomasulo 把停顿从「真+假」压缩到「仅真依赖」**——这是它比记分牌性能高出一截的根本原因。<span class="marginnote">实测里假依赖在程序中占比可观（寄存器复用普遍），记分牌因此损失大量 ILP。Tomasulo 的「重命名」让程序员的寄存器复用变得「免费」——这也是为什么现代编译器敢大胆复用寄存器。</span>

## 4 Tomasulo 的执行流程一条指令在 Tomasulo 里的完整生命周期：

1. **发射（issue）**：从指令队列取出，若保留站有空位则进入；目标寄存器重命名到该保留站。
2. **等待操作数（wait）**：源操作数未就绪则监听 CDB（公共数据总线），就绪则取值。
3. **执行（execute）**：操作数齐了，功能单元执行。
4. **写结果（write result）**：结果上 **CDB（Common Data Bus）**，同时广播给所有等待它的保留站与寄存器堆——一步完成「写回 + 前递」。

**核心概念：CDB 广播是 Tomasulo 的「数据快递」**——一个结果同时送到所有需要它的地方，不需要逐点询问。<span class="marginnote">CDB 广播让「写回」与「前递」合一：结果上总线，所有保留站自动捕获。代价是 CDB 带宽有限——多结果同时完成要排队。现代 CPU 用多条 CDB（如 4 条）缓解这个瓶颈。</span>

## 5 辨析｜易错点：两大算法对照| 维度 | 记分牌 | Tomasulo |

| --- | --- | --- |
| 调度 | 集中记分牌 | 分布式保留站 |
| 假依赖（WAR/WAW） | 停顿 | 重命名消除 |
| 数据前递 | 无 | CDB 广播 |
| 结构阻塞 | 直接停 | 保留站缓冲缓解 |
| 硬件 | 简单 | 复杂 |
| 现代使用 | 历史 | 现代乱序核心 |

**辨析｜易错点：**（1）记分牌的「WAR 停顿」不是数据错误，而是**名字冲突**——Tomasulo 重命名解决的是「名字」，不是「数据」；（2）保留站是「等值」，不是「等寄存器名」——这是 Tomasulo 的灵魂，答题要强调；（3）Tomasulo 仍有乱序完成，但精确异常要靠下一课的 **ROB** 保证——「乱序执行 + 按序提交」是现代组合。

## 6 拓展：Tomasulo 的 CDB 与执行流程Tomasulo 的写结果靠 **CDB（公共数据总线）广播**：一个结果上总线，所有等待它的保留站同时捕获——「写回」与「前递」合一。

执行四步：发射（进保留站+重命名）→ 等操作数（监听 CDB）→ 执行 → 写结果（上 CDB 广播）。

**五条必记**：
- 保留站「等值」不「等寄存器名」——Tomasulo 的灵魂。
- 重命名消除 WAR/WAW 假冒险，前递加速 RAW 真冒险。
- 记分牌三表：指令状态表、功能单元状态表、寄存器结果状态表。
- 记分牌无前递、有 WAR 停顿；Tomasulo 两者都解决。
- CDB 带宽有限，多结果同时完成要排队——现代用多条 CDB。

**辨析｜易错点**：记分牌的 WAR 停顿是「名字冲突」不是「数据错误」——Tomasulo 重命名解决的是名字问题。

## 7 核心要点
- 保留站等值不等待寄存器名。
- 重命名消除假冒险、CDB 前递加速真冒险。
- 记分牌三表、无前递、WAR 停顿。
- 执行四步：发射→等→执行→写结果。
- CDB 广播写回+前递合一。

## 8 小结- **记分牌**：集中式状态表调度，简单但假依赖停顿、无前递。
- **Tomasulo**：保留站（等值）+ 寄存器重命名（消假依赖）+ CDB 前递（算完即送）。
- 停顿对比：记分牌「真+假」，Tomasulo「仅真」。
- 执行四步：**发射 → 等操作数 → 执行 → CDB 写结果**。
- Tomasulo 是现代乱序执行的基础，精确异常由 ROB 兜底（下一课）。
