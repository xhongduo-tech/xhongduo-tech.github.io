## 为什么控制流「不总是顺序的」

前几课的程序流是「顺序 + 跳转 + 调用」。但系统里还有一类更根本的打断：**异常（exception）**——除零、缺页、系统调用、外部中断。它们由**处理器内部或外部事件**触发，把控制流强制转到操作系统处理程序。本课把异常的分类（**陷阱、故障、终止**）与处理流程讲清，并解释「上下文切换」如何让被打断的程序无缝恢复。这是理解中断、系统调用与进程调度的共同地基。<span class="marginnote">「异常控制流（ECF）」是 CS:APP 第八章的主题：操作系统的一切（进程、信号、虚存、I/O）都建立在异常控制流之上。本课是进入操作系统专题前的硬件侧准备。</span>

## 1 异常的分类按「发生时机与能否恢复」，异常分三类：

| 类别 | 触发 | 返回行为 | 典型例子 |
| --- | --- | --- | --- |
| 陷阱（trap） | **有意**的指令 | 返回下一条指令 | 系统调用（syscall） |
| 故障（fault） | **意外**的、可恢复 | 重新执行当前指令 | 缺页、除零 |
| 终止（abort） | 不可恢复的错误 | 进程终止 | 硬件错误、校验失败 |

**核心概念**：

**陷阱（trap）**：程序员**故意**触发，如 syscall 指令进内核做系统调用——「请求服务」。
**故障（fault）**：意外发生但**可修复**——缺页时调入页面后**重新执行**触发指令。
**终止（abort）**：致命错误，程序无法继续——**不回原程序**。

<span class="marginnote">区分三类异常的记忆锚点：陷阱是「我要进内核办事」（主动），故障是「刚出错但能补救」（被动可救），终止是「没救了」（被动不可救）。返回行为分别是：下一条、当前、永不。</span>

## 2 异常处理机制：异常表与处理程序异常处理由硬件 + 操作系统协作：

1. **异常表（exception table）**：操作系统初始化时建好，记录每个异常号对应的处理程序入口地址（存于「异常表基址寄存器」）。
2. **触发**：处理器检测到异常事件，查表得到入口地址。
3. **切换**：保存现场（当前程序状态），跳转处理程序。
4. **返回**：按异常类型决定返回「下一条」「当前」或「不返回」。

```c
int a = 10, b = 0;
printf("%d\n", a / b);   // 整数除零 → 故障（fault），进程收到 SIGFPE
```

**核心概念：异常让处理器从用户态切换到内核态（特权级提升）**——因为处理程序属于操作系统。<span class="marginnote">异常处理的核心开销是「特权级切换 + 现场保存」：用户态→内核态要换栈、换页表、保存寄存器。现代 CPU 用「快速系统调用」（syscall/sysret 指令）把切换压到几十周期——这是系统调用的性能关键。</span>

## 3 系统调用：异常的最高频用途**系统调用（system call）**是「陷阱」的典型应用：用户程序要读文件、分配内存、发网络包，都必须进内核——但不能随便跳进去，只能通过 syscall 指令**故意触发陷阱**。

```asm
# Linux x86-64：write(1, "hi\n", 3) 触发系统调用
movq $1, %rax         # 系统调用号 1 = write
movq $1, %rdi         # 参数 1：stdout 文件描述符
leaq msg(%rip), %rsi  # 参数 2：要写出的缓冲区
movq $3, %rdx         # 参数 3：写 3 个字节
syscall               # 触发陷阱，CPU 切到内核态
```

**重点：系统调用号是「内核服务的编号」**——syscall 指令用寄存器传参数与编号，内核据此分发到具体服务。用户程序永远无法直接执行内核代码，只能「申请」。<span class="marginnote">「系统调用 vs 函数调用」的对比：函数调用在同一特权级、跳转到用户代码；系统调用跨特权级、跳转到内核代码。所以系统调用更贵（要切换特权级），编译器会尽量少用——printf 内部会触发 write 系统调用，但缓冲机制让它不至于每次输出都进内核。</span>

## 4 公式解析：异常处理的开销设异常处理需要「保存现场 + 切换特权级 + 处理 + 恢复」，总时间：

$$T_{\text{异常}} = T_{\text{保存}} + T_{\text{切换}} + T_{\text{处理}} + T_{\text{恢复}}$$

例：系统调用约几百周期（现代快速路径），缺页则要读磁盘（几十万周期）：

$$T_{\text{缺页}} \approx 10^7\ \text{周期} \gg T_{\text{系统调用}} \approx 10^2\ \text{周期}$$

逐项拆解：

- **第一步，保存现场**：压栈寄存器、保存 PC 与状态字。
- **第二步，特权切换**：换到内核栈、内核页表。
- **第三步，处理**：执行处理程序（缺页要读磁盘，最贵）。
- **第四步，恢复**：弹栈、切回用户态、跳回原程序。

**核心结论：异常的代价由「最贵的一步」主导**——系统调用贵在切换、缺页贵在读磁盘。这也是为什么 OS 要用缓冲、预读等机制减少异常次数。<span class="marginnote">上下文切换（进程切换）是异常控制流的另一大应用：定时器中断触发「进程调度」，OS 保存当前进程的全部上下文、载入另一进程。每次上下文切换约几千周期——所以线程太多反而慢，这是并发编程的性能边界。</span>

## 5 辨析｜易错点：异常与控制流**辨析｜易错点：**

- **中断（interrupt）vs 异常（exception）**：CS:APP 里「异常」包含三类；唐朔飞教材把「中断」单列（外部 I/O 中断），「异常」指内部事件。术语体系不同，考试按教材口径。
- **故障 vs 终止**：故障可修复、重新执行当前指令（缺页）；终止不可修复、程序死亡。判错类型会导致「能不能恢复」答反。
- **陷阱的返回地址是下一条**：因为系统调用是「有意为之」，执行完 syscall 当然要继续下一条；故障要重执行「当前」指令。
- **异常是「同步 vs 异步」的另一层**：陷阱/故障/终止由**处理器当前指令**引发（同步）；外部中断由**外部设备**引发（异步）——时机完全不同。

## 6 拓展：异常控制的现实形态**五条必记**：
- 陷阱（有意，返回下一条）、故障（可恢复，重执行当前）、终止（不可恢复）。
- 异常表查入口 → 保存现场 → 内核态处理 → 按类型返回。
- 系统调用 = 陷阱典型，syscall 指令 + 寄存器传参。
- 缺页最贵（读磁盘 10^7 周期），系统调用约 10^2 周期。
- 上下文切换是异常控制流的大应用，每次约几千周期。

**辨析｜易错点**：中断（外部异步）vs 异常（内部同步）——时机与来源不同，术语按教材口径。

## 7 一句话回顾- 陷阱（有意返下一条）、故障（可恢复重执行）、终止（不可恢复）。
- 系统调用 = 陷阱典型应用。
- 缺页最贵、上下文切换约几千周期。

> 一句话：陷阱返下一条、故障重执行当前、终止不返回。
> 一句话：系统调用 = 陷阱的典型应用。

## 8 小结- 异常三类：**陷阱**（有意、返回下一条）、**故障**（可恢复、重执行当前）、**终止**（不可恢复、进程死）。
- 处理机制：**异常表**查入口 → 保存现场 → 内核态处理 → 按类型返回。
- **系统调用** = 陷阱的典型应用，syscall 指令 + 寄存器传参。
- 异常开销：保存 + 切换 + 处理 + 恢复；缺页最贵（读磁盘）。
- **上下文切换**是异常控制流的大应用，每次约几千周期。

- 上下文切换几千周期
