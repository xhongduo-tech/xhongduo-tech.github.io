## 为什么用 C 语言检验机器数理论

前几课学的原码、补码、浮点编码，都是抽象概念；C 语言让它们**变成可运行的程序**。C 贴近硬件，几乎直接暴露机器数的运算规则——这正是 CS:APP 用 C 讲数据表示的原因。本课把三类经典问题串起来：**类型转换**（有符号/无符号/浮点的相互转换）、**整数溢出**（无符号回绕与有符号未定义）、**浮点数陷阱**（比较、舍入、类型提升）。学完本课，你手里的「机器数知识」就变成了「能调试 bug 的能力」。<span class="marginnote">为什么不用 Python 验证？Python 的 `int` 是任意精度，`bigint` 隐藏了表示细节——它帮你把机器数的复杂性「抽象掉了」。C 语言把这些细节暴露给你，是组成原理的最佳实验场。</span>

## 1 整数之间的类型转换：位型不变，解读可变回顾《无符号数与有符号数》：同一个位型，按无符号读和按有符号读是两套数。C 的类型转换**不改变位模式，只改变解读方式**（截断除外）。

```c
int x = -1;                 // 位型：0xFFFFFFFF
unsigned u = (unsigned)x;   // 强制转换，位型不变
printf("%u\n", u);          // 4294967295（按无符号解读）
printf("%d\n", (int)u);     // -1（按有符号解读，位型还原）
```

**转换规则**：有符号转无符号时，负数按模 $2^w$ 加上去（$w$ 为位宽）；无符号转有符号同理。公式：

$$T2U_w(x) = \begin{cases} x, & x \ge 0 \\ x + 2^w, & x < 0 \end{cases} \qquad U2T_w(u) = \begin{cases} u, & u \le 2^{w-1}-1 \\ u - 2^w, & u \ge 2^{w-1} \end{cases}$$

例如 `-1` 转成 `unsigned` 得 $4294967295$，再转回 `int` 仍是 `-1`——位型一个比特都没变。<span class="marginnote">「符号位反转」技巧：`unsigned` 转 `int` 再转回 `unsigned` 位型不变，但数值可能已变（若原为负）。C 标准保证可表示范围内位型保持一致，这就是为什么位型不变是可靠前提。</span>

## 2 整数溢出：无符号回绕与有符号未定义### 无符号回绕

无符号加法在溢出时**按模 $2^w$ 回绕**（wrap around），这是定义好的行为：

```c
unsigned u = UINT_MAX;   // 2^32 - 1
u = u + 1;               // 回绕：按模 2^32 变为 0
printf("%u\n", u);       // 0（定义行为）
```

### 有符号溢出是未定义行为

C 标准说有符号溢出是**未定义行为（undefined behavior）**——编译器可以随意处理，可能回绕、可能饱和、可能做任何优化假设。这是 bug 的温床：

```c
int x = INT_MAX;
int y = x + 1;   // 有符号溢出：未定义行为（undefined behavior）
```

**重点：编译器利用「未定义」做优化**。例如 `x + 1 > x` 对 `有符号 int` 恒真（因为溢出未定义，编译器假定不发生），于是可能被优化为 `1`（真）。这解释了很多「看似正确却诡异的 bug」。<span class="marginnote">检测整数溢出的安全写法：`x == INT_MAX` 而非 `x + 1 < x`——后者自身就溢出了。C 安全编码（CERT 规则）专门处理这类问题。</span>

## 3 浮点与整数的转换陷阱浮点转整数和整数转浮点都有坑：

```c
int i = (int)1e20;      // 超出 int 范围 → 未定义行为
float f = 16777217;     // 需 25 位有效位 → 舍入为 16777216.0f
printf("%d\n", i);      // 各平台结果不同
```

**int → float**：float 只有 24 位有效位，超过 $2^{24}$ 的整数会被舍入。
**float → int**：若浮点值超出 int 范围或不是有限数，转换是未定义行为（不同平台结果不同）。
**隐式提升**：`char`、`short` 参与运算时提升为 `int`；`float` 提升为 `double`——了解「通常算术转换」规则可避免许多类型错误。<span class="marginnote">经典问题：`printf("%d", 3.14)` 为什么输出垃圾？因为 `printf` 按 `int` 解读栈上 `double` 的位型——这与「位型不变，解读可变」是同一个道理。</span>

## 4 公式解析：为什么 2^24 是 float 精确整数的分水岭

float 尾数 23 位 + 隐藏位共 24 位有效位，所以能精确表示的最大连续整数是 $2^{24}$：

$$2^{24} = 16\,777\,216$$

逐项拆解：

- **第一步，连续整数**：$0 \sim 2^{24}$ 之间的整数都能用 24 位有效位精确表示（$2^{24}$ 需要 25 位，但它恰好是 $1.0\times2^{24}$，隐藏位恰好覆盖）。
- **第二步，再往大**：$2^{24}+1$ 需要 25 位有效位，float 装不下，只能舍入到 $2^{24}$ 或 $2^{24}+2$。
- **第三步，结论**：`x + 1.0f == x` 对 $x \ge 2^{24}$ 恒真——这就是《浮点数表示》一课「大数加小数被吃掉」的量化边界。

**辨析｜易错点：**double 的分水岭是 $2^{53}$（53 位有效位）。判断「这个整数能不能精确放进 float」就看它是否 $\le 2^{24}$——这是面试与数值代码的常用经验值。

## 4 浮点比较与常见陷阱汇总| 陷阱 | 现象 | 对策 |

| --- | --- | --- |
| 浮点数直接比较 | 舍入误差导致不相等 | 阈值比较 `fabs(a - b) < eps` |
| 与 0 比较 | 微小非零值被判为零 | 用相对阈值 |
| 与 NaN 比较 | NaN 与自身不相等 | `isnan()` 检测 |
| 循环变量用 float | 步进舍入导致死循环 | 用整数循环或阈值 |
| 大数吃小数 | $16777216+1$ 不变 | 先加小再加大，或用 double |

**核心要点**（本课主题是「实践」，用表格替代公式总结 C 与机器数的对应）：

| C 语言事实 | 机器数原理 |
| --- | --- |
| 有符号溢出未定义 | 补码回绕，标准留给编译器裁量 |
| 无符号溢出回绕 | 模 $2^w$ 运算定义明确 |
| 有符号/无符号混合转无符号 | T2U 公式 $x+2^w$ |

| 0.1 + 0.2 ≠ 0.3 | 二进制无限小数 + 舍入 |

## 5 补充：C 语言速记- 类型转换不改位型只改解读：T2U 负值加 2^w。
- 无符号溢出按模回绕（定义行为），有符号溢出未定义。
- int↔float 各有舍入/未定义陷阱，2^24 是 float 分水岭。
- 浮点比较用阈值，NaN 用 isnan，循环别用 float 步进。
- C 是机器数理论的活教材——每个陷阱背后一条编码规则。

## 6 小结- **类型转换不改位型，只改解读**：T2U 对有符号负值加 $2^w$。
- **无符号溢出按模回绕**（定义行为）；**有符号溢出未定义**（编译器可自由优化）。
- **int ↔ float** 各有舍入/未定义陷阱，$2^{24}$ 是 float 连续整数的分水岭。
- **浮点比较**用阈值，NaN 用 `isnan()`，循环别用 float 做精确步进。
- C 是机器数理论的「活教材」——每个陷阱背后都是一条编码规则。
