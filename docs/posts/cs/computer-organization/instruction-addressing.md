## 为什么「找下一条指令」也要专门学

指令存放在内存里，CPU 取指的关键是**回答「下一条指令在哪」**。两种基本方式：**顺序寻址**（顺着往下）与**跳跃寻址**（跳到别处）。别看简单，它决定了程序计数器 PC 的行为、循环与分支的实现、以及流水线里最头疼的分支预测问题。本课先把这两种寻址讲透——它们是「程序控制流」的机器级基础。<span class="marginnote">「指令寻址」的「寻址」对象是<strong>指令本身</strong>；「数据寻址」的「寻址」对象是<strong>操作数</strong>。两个寻址是不同的问题，别混——本课讲前者，下一课讲后者。</span>

## 1 顺序寻址**顺序寻址（sequential addressing）**：指令在内存中按地址连续存放，执行时 PC 依次加一（按字寻址）或加指令长度（按字节寻址）。

$$\text{PC}_{\text{new}} = \text{PC}_{\text{old}} + L \quad(L = \text{指令长度})$$

**顺序寻址是默认状态**：除非遇到跳转指令，程序就一条条往下执行。它依赖指令在内存中的**连续存放**——这由链接器保证（代码段合并成连续区域）。

**重点：顺序执行与指令的空间局部性**——指令连续存放，取指天然是顺序访问，I-Cache 命中率极高。这是《局部性》一课的又一例证。<span class="marginnote">「PC 加 L」的 L 可以是固定（定长指令）或动态（变长指令）。定长指令下 PC 步长恒定，取指器可以「流水线式」预取下一批；变长指令下 PC 步长要解码后才知道——这是变长指令取指慢的原因之一。</span>

## 2 跳跃寻址**跳跃寻址（jump addressing）**：指令的执行顺序不再按地址顺序，而是**转移到指定地址**。

$$\text{PC}_{\text{new}} = \text{目标地址}$$

跳跃由**转移指令**触发：

- **无条件转移**：`JMP`，必定跳转。
- **条件转移**：`Jcc`（如 `JE`、`JG`、`JA`），满足条件才跳，否则顺序执行。
- **过程调用**：`CALL/RET`，跳转的同时保存/恢复返回地址。

**跳跃寻址的意义**：它让「循环」「分支」「函数调用」成为可能——没有它，程序只能是一条直线。

**核心概念：跳转目标地址的来源**——可以是绝对地址（指令里直接给出）、相对偏移（PC + offset）、或寄存器/内存中的地址（函数指针）。<span class="marginnote">「顺序寻址与跳跃寻址」从更高视角看就是「指令流中 PC 的两种更新方式」。现代 CPU 为此设计了分支预测、分支目标缓冲（BTB）——因为跳转打破顺序流的局部性，是流水线的最大敌人。通往第六篇《分支预测》。</span>

## 3 公式解析：相对跳转的地址计算现代 ISA 的分支指令多用**相对寻址**：目标地址 = PC + 偏移。

$$PC_{\text{new}} = PC_{\text{old}} + \text{offset} \quad(\text{offset 为有符号数})$$

例：指令位于地址 `0x1000`，偏移 `0x20`（x86 约定偏移相对下一条指令）：

$$PC_{\text{new}} = 0x1004 + 0x20 = 0x1024$$

逐项拆解：

- **第一步，基准**：x86 里 PC 指「下一条指令地址」（当前指令地址 + 指令长度）。
- **第二步，偏移**：offset 是有符号数，负数向回跳（循环体）。
- **第三步，为什么用相对**：代码整体搬移（重定位）后相对关系不变；且 offset 通常比绝对地址短，省指令位。

**辨析｜易错点：相对偏移的「基准」因 ISA 而异**——x86 相对**下一条指令**，有些 RISC 相对**当前指令**。算错基准是汇编题经典失分点。<span class="marginnote">循环的机器级样子：循环体末尾一条条件跳转「往回跳」到循环头；`for` 循环翻译后就是「初始化 → 条件判断 → 循环体 → 更新 → 回跳」。看汇编能一眼认出循环，就是从这种「往回跳」的模式判断的。</span>

## 4 顺序与跳跃的切换：标志寄存器条件转移依赖**标志寄存器（PSW/FLAGS）**：ALU 运算的结果会更新标志，条件转移指令读取标志决定是否跳转。

| 标志 | 含义 | 典型条件指令 |
| --- | --- | --- |
| ZF | 结果为零 | `JE`/`JNE`（相等跳转） |
| SF | 结果符号 | `JS`/`JNS`（符号跳转） |
| CF | 无符号进位/借位 | `JA`/`JB`（无符号比较） |
| OF | 有符号溢出 | `JO`/`JNO`（溢出跳转） |
| SF^OF | 有符号小于 | `JL`/`JGE`（有符号比较） |

**重点：条件跳转的本质是「读标志 + 决定 PC」**——`CMP` 先算 `减法` 更新标志但不写结果，随后 `Jcc` 根据 `标志位` 决定跳转。<span class="marginnote">这与《ALU 的标志位生成》直接衔接：标志是 ALU 送给控制流的「暗号」。两条指令（比较 + 跳转）的配合让「if/while」变成机器级事实——也解释了为什么编译器会做「标志位复用」的优化（一条算术指令的结果和标志一起被下一条跳转使用）。</span>

## 5 辨析｜易错点：指令寻址高频错误**辨析｜易错点：**

- **「指令寻址」≠「数据寻址」**：前者找「下一条指令」，后者找「操作数」，是两个不同章节的概念。
- **顺序寻址不是「每次 PC+1」**：按字节寻址 + 4 字节指令时 PC+4；只有按字寻址 + 单字指令才是 +1。
- **无条件跳转与条件跳转的区别**：无条件必跳，条件看标志——两者都是「跳跃寻址」，但触发条件不同。
- **CALL 比 JMP 多一个动作**：CALL 要把返回地址压栈（为 RET 铺路），JMP 不保存任何东西。

## 6 拓展：循环的机器级样子看一个 `for` 循环如何被「顺序 + 跳跃」组合实现：

```asm
; for (i = 0; i < n; i++) { 循环体 }
        movq $0, %rax        # 初始化 i = 0
.L1:    <循环体>              # 循环体
        addq $1, %rax        # 更新 i++
        cmpq %rsi, %rax      # 条件判断：i < n ?
        jl   .L1             # 满足条件则回跳循环头，否则顺序退出
```

- **顺序寻址**：循环体一条条往下执行。
- **跳跃寻址**：`JL` 是条件跳跃——满足条件则 PC 跳回 `.L1`，否则顺序退出循环。

**核心概念：高级语言的一切控制结构（if/for/while/函数）最终都翻译成「顺序执行 + 条件/无条件跳跃」**——机器只有这两种控制流原语。

**辨析｜易错点：**`CALL` 与 `JMP` 的区别常考：`CALL` 在跳转前把返回地址压栈（为 `RET` 铺路），`JMP` 只跳不保存——所以函数调用用 `CALL`，普通跳转用 `JMP`。「CALL 是带记忆的跳转」。

## 7 补充：指令寻址速记- 顺序寻址：PC 依次加指令长度，靠指令连续存放。
- 跳跃寻址：PC 跳转，由转移指令触发。
- 相对跳转：PC_new = PC + offset，可重定位、省位。
- 条件转移读标志寄存器（ZF/SF/CF/OF）。
- CALL 压返回地址、JMP 不保存——「带记忆的跳转」。

> 记住：相对跳转基准因 ISA 而异（x86 取下一条）。

## 8 核心公式
- 顺序：PC ← PC + L。
- 跳跃：PC ← 目标地址。
- 相对：PC ← PC + offset。
- CALL 压返回地址、JMP 不压。

## 9 小结- **顺序寻址**：PC 依次加指令长度，靠指令连续存放，取指天然局部性好。
- **跳跃寻址**：PC 跳转到目标地址，由转移指令触发，支持分支/循环/函数调用。
- 转移指令：无条件（JMP）、条件（Jcc 读标志）、调用（CALL/RET 压栈）。
- 相对跳转：$PC_{\text{new}} = PC + offset$，可重定位、省位，但基准因 ISA 而异。
- 条件转移依赖标志寄存器（ZF/SF/CF/OF），「CMP + Jcc」是 if/while 的机器级形态。

- 顺序寻址 PC+步长、跳跃寻址改 PC
- 相对跳转基准因 ISA 而异
- 条件转移读标志寄存器
- CALL 压返回地址、JMP 不压
- 循环=往回跳的条件分支
- 代码重定位靠相对寻址
- 转移指令三类：无条件/条件/调用
- 标志位 CMP+Jcc 配合
