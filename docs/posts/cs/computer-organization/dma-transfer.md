## DMA 传输的四步曲

上一课认识了 DMAC，本课把一次 DMA 传输的完整过程走一遍——从 CPU 配置到设备就绪、从总线搬运到中断收尾。DMA 的**传送方式**（三种）与**传送过程**（四步）是考试的经典大题，也是理解「为什么 DMA 快」的完整画面。<span class="marginnote">DMA 传送的完整画面：CPU 布置任务（配置寄存器）→ 设备就绪 → DMAC 接管总线搬数据 → 计数归零 → 中断通知 CPU。CPU 从头到尾只出现两次——开头和结尾。</span>

## 1 DMA 的传送方式### 方式一：停止 CPU 访问主存

DMAC 请求总线，CPU 让出总线控制权，DMA 连续传输完整个数据块，再把总线还给 CPU。

- **优点**：一次性搬完，简单。
- **缺点**：传输期间 CPU 不能访存——**长块传输时 CPU 被「冻住」**。

### 方式二：周期挪用

DMAC 每次只挪用一小段总线周期（通常传一个字），然后释放总线；下次再申请、再挪用。

- **优点**：CPU 几乎不受影响（只损失被挪用的周期）。
- **缺点**：传输被分割成碎片，总时间变长；DMAC 每次都要重新申请总线（仲裁开销）。

### 方式三：DMA 与 CPU 交替访问（透明）

CPU 在每个机器周期内用一半时间访问内存（如前半拍），DMA 用另一半（如后半拍）——两者**分时共享总线**，互不等待。

- **优点**：对 CPU 完全透明，无等待。
- **缺点**：要求总线能「分时」，且 DMA 只能拿到「半拍」带宽；硬件复杂。

**核心概念：三种方式 = 总线使用权如何分配**——「全让」「挪用」「分时」三档。<span class="marginnote">现实中块设备多用「突发 + 周期挪用混合」：大块用突发连续搬，小块/多设备用周期挪用轮转。「透明传输」理论上最美，但要求 CPU 与 DMA 时钟同步分时，工程上难做——所以教材提、实用少。</span>

## 2 DMA 的传送过程（四步）以「磁盘读一块到内存」为例：

**第一步：CPU 配置 DMAC**

CPU 写 DMAC 的寄存器：
- 内存地址寄存器 AR ← 目标内存地址。
- 字计数寄存器 WC ← 要传的块大小。
- 控制寄存器 ← 传输方向（设备→内存）、启动命令。

**第二步：DMAC 请求/设备就绪**

DMAC 向设备发「读请求」，设备准备数据；DMAC 同时向总线控制器申请总线使用权。

**第三步：数据传送**

DMAC 获得总线，开始搬运：
- 每传一个数据：`设备 → DMAC 缓冲 → 内存`，同时 AR+1、WC−1。
- 直到 WC=0（块传完）。

**第四步：中断通知 CPU**

DMAC 发中断给 CPU，报告「传输完成」。CPU 读取 DMAC 状态寄存器，确认结果（成功/错误）。

$$\text{CPU 写 AR/WC/控制} \Rightarrow \text{DMAC 接管搬数据} \Rightarrow \text{WC 归零发中断}$$

<span class="marginnote">「DMA 的四步」是考试经典流程题：配置、请求、传送、中断。关键记忆点——<strong>CPU 只做第一步与第四步</strong>，中间的数据搬运是 DMAC 的活。说「DMA 过程 = CPU 管两头、DMA 管中间」一句话就能记住。</span>

## 3 公式解析：DMA 传输的地址推进DMAC 每传一个字，三个寄存器同步更新：

$$\text{AR} \leftarrow \text{AR} + 1, \qquad \text{WC} \leftarrow \text{WC} - 1$$

$$\text{传输结束条件：} \text{WC} = 0$$

逐项拆解：

- **第一步，地址递增**：内存地址寄存器每次 +1（或按字长加），保证数据连续落到内存。
- **第二步，计数递减**：字计数每次 −1，跟踪还剩多少。
- **第三步，结束判定**：WC 减到 0，传输完成——这是「不用 CPU 参与就知道何时完成」的硬件机制。

**核心概念：AR 与 WC 是 DMAC 的「自动驾驶」**——地址与计数自动推进，DMAC 不需要 CPU 干预就知道「传了多少、传到哪」。<span class="marginnote">现代 DMA 用「描述符（descriptor）链」替代单个 AR/WC：描述符里写「源地址、目标地址、长度」，DMAC 自动逐个描述符处理——这就是 scatter-gather（分散聚集）I/O。一次配置可以传多个不连续的内存块，正是文件系统的缓冲（多个分散页）所需。</span>

## 4 辨析｜易错点：DMA 传送**辨析｜易错点：**

- **DMA 传输方向由控制寄存器设置**：内存→设备（写盘）与设备→内存（读盘）方向相反，配置不能错。
- **「WC 归零发中断」是结束信号**：不是每字中断——DMA 只在中途出错或全部完成时通知 CPU。
- **周期挪用的「挪用」是借总线周期**：不是借 CPU 时间——DMA 不占 CPU，只占总线。
- **DMA 期间的 Cache 一致性问题**：DMA 写内存而 CPU 缓存里有旧副本 → 需要缓存失效/同步（现代用 IOMMU/缓存一致性互连处理）——高级话题，但要意识到。

## 5 拓展：DMA 传送速记**五条必记**：
- 四步：配置 DMAC → 设备就绪/申请总线 → 搬运（AR+/WC−）→ 中断。
- 三种模式：停止 CPU（突发）、周期挪用、透明分时。
- AR/WC 自动推进，WC=0 即完成——DMAC 自动驾驶。
- 方向由控制寄存器设置，配置不能错。
- 现代 DMA 用描述符链实现 scatter-gather。

**辨析｜易错点**：DMA 只在中途出错或全部完成时中断，不是每字中断。

## 7 小结- 三种传送方式：**停止 CPU（突发）、周期挪用、透明分时**——总线使用权分配的三档。
- 四步过程：**配置 DMAC → 设备就绪/申请总线 → 数据搬运（AR+/WC−）→ 中断通知 CPU**。
- AR/WC 自动推进，WC=0 即完成——DMAC 的「自动驾驶」。
- 现代 DMA 用描述符链实现 scatter-gather，一次配置传多块。
- CPU 只管「开头配置、结尾验收」，中间全部交给 DMAC。

- 四步：配置→申请总线→搬运→中断
- AR/WC 自动推进、WC=0 完成
- 三种模式：突发/挪用/透明
- 方向由控制寄存器设置
- 描述符链实现 scatter-gather
- 周期挪用借总线周期
- 透明传输对 CPU 无感
- DMA 只在中途/结束中断
