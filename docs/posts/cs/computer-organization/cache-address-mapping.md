## 为什么主存块不能「随便放」

Cache 容量远小于主存，一个主存块到底能放进 Cache 的哪个槽，需要规则。规则有三套：**直接映射**（一个主存块只能进固定一个槽）、**全相联映射**（可进任意槽）、**组相联映射**（可进固定一组的任意槽）。它们构成「灵活性 vs 硬件复杂度」的三角光谱：越灵活越难找，越固定越容易冲突。本课把三种映射的地址划分、判定流程与命中率特性讲透，这是 Cache 设计最核心的一课。<span class="marginnote">「相联」（associative）的意思是「通过内容找到位置」——全相联 Cache 找块时要把所有 Tag 同时比较，类似《存储器分类》里按内容存取的 CAM。相联度越高，找起来越像「全城搜索」，硬件越贵。</span>

## 1 直接映射**直接映射（direct-mapped）**：主存块号与 Cache 槽号的对应关系固定——主存第 $i$ 块只能进 Cache 第 $i \bmod S$ 个槽。

$$\text{槽号} = \text{块号} \bmod S$$

地址划分：Tag + Index + Offset，其中 Index 直接由主存地址的中间位给出，无需计算。

**访问判定**：

1. 用 Index 定位唯一的槽。
2. 比较该槽 Tag 与地址 Tag：相同则命中。
3. 不同则未命中——**没有任何其他选择**，直接替换这个槽。

**优点**：硬件最简单——一次比较、无替换算法（替换目标唯一）。**缺点**：冲突严重——两个经常交替访问的块若映射到同一槽，会互相驱逐，命中率崩坏。<span class="marginnote">直接映射的经典反例：数组步长恰好等于 Cache 槽数时，所有访问都映射到同一槽——「抖动（thrashing）」，命中率接近 0。这就是为什么现代 CPU 很少用纯直接映射，至少也要 2 路组相联。</span>

## 2 全相联映射**全相联映射（fully associative）**：主存任何一块都可以放进 Cache 的**任意**槽。

地址划分：Tag + Offset——没有 Index，因为不需要定位固定槽。

**访问判定**：

1. 把地址 Tag 与**所有**槽的 Tag 同时比较。
2. 任一匹配且有效 → 命中。
3. 全不匹配 → 未命中，按替换算法（LRU/FIFO）选一个槽淘汰。

**优点**：最灵活，无冲突（只有容量不足才会未命中），命中率理论最高。**缺点**：Tag 比较是「全并行」——需要多路比较器，硬件成本随槽数线性上升，所以只能用于小容量 Cache（如 TLB）。<span class="marginnote">全相联为什么只能小容量：n 个槽就要 n 路并行比较器，面积和功耗巨大。TLB 只有几十上百个条目，用全相联尚可接受；L1/L2 有几千行，全相联会烧掉整块芯片。</span>

## 3 组相联映射：折中的主流**组相联映射（set-associative）**：把 Cache 分成 $G$ 组，每组 $E$ 个槽（$E$ 叫**相联度**）。主存块只能进固定的一组（组号 = 块号 mod G），但组内可自由选择任意槽。

$$G = \frac{S}{E}, \qquad \text{组号} = \text{块号} \bmod G$$

地址划分：Tag + Set + Offset——Set Index 定位组，组内用 Tag 并行比较 E 个槽。

**相联度 E 的两种退化**：

- $E = 1$：每组只有 1 槽 → 退化为**直接映射**。
- $E = G$（只有一组）：→ 退化为**全相联**。

**组相联是「冲突与成本的连续旋钮」**：E 越大，冲突越少、命中率越高，但比较器越多、硬件越贵。现代 CPU 的 L1 常用 8 路，L2/L3 用 8–16 路。<span class="marginnote">「8 路组相联」的意思：一个组里有 8 个槽，找块时把 Tag 与组内 8 个 Tag 并行比较。路数（ways）= 相联度 E。买 CPU 看「L2 12MB, 16-way」就是指路数 16。</span>

## 4 公式解析：组相联的地址划分计算设主存地址 32 位，Cache 共 1024 槽、4 路组相联、块大小 64B，求各字段位数。

$$S = 1024, \quad E = 4, \quad G = \frac{S}{E} = 256$$

$$\text{Offset} = \log_2 64 = 6, \qquad \text{Set} = \log_2 256 = 8, \qquad \text{Tag} = 32 - 6 - 8 = 18$$

逐项拆解：

- **第一步，组数**：槽数 ÷ 路数 = 组数，256 组。
- **第二步，Offset**：块内偏移 = $\log_2$(块大小) = 6 位。
- **第三步，Set**：组索引 = $\log_2$(组数) = 8 位。
- **第四步，Tag**：总位数 - Offset - Set = 18 位。

**结论：Tag 位数随路数增加而减少**——同样容量下，路数越多，每组越小，Set 位数越少，Tag 越大。<span class="marginnote">常考换算：32 位地址、64KB Cache、16B 块、8 路组相联 → 槽数 = 64K/16 = 4096，组数 = 4096/8 = 512，Set=9，Offset=4，Tag = 32-9-4 = 19。每步都是「容量→槽数→组数→位宽」的链。</span>

## 5 辨析｜易错点：三种映射对照| 维度 | 直接映射 | 全相联 | 组相联 |

| --- | --- | --- | --- |
| 可进槽 | 固定 1 个 | 任意 | 固定组的任意槽 |
| 地址字段 | Tag+Index+Offset | Tag+Offset | Tag+Set+Offset |
| 替换算法 | 不需要 | 需要 | 需要（组内） |
| 冲突 | 最严重 | 无 | 适中 |
| 硬件 | 最简 | 最贵 | 折中 |
| 用途 | 教科书/小型 | TLB | 现代 CPU 全用 |

**辨析｜易错点：**（1）直接映射「不需要替换算法」常被误答——因为替换目标是唯一的；（2）全相联没有 Index 字段，不是「Index 全为 0」，而是根本没有这一位；（3）组相联的替换只在**组内**选（比如 4 路就是 4 选 1），不跨组；（4）判定命中必须 Tag 相同**且有效位为 1**，两者缺一不可。

## 6 考点速记：Cache 映射三兄弟**直接映射**：块号 mod 槽数，固定槽、无替换、冲突最大、硬件最简。

**全相联**：任意槽、Tag 全并行比较、无冲突、硬件最贵（TLB 用）。

**组相联**：块号 mod 组数 + 组内自由，E=1 退化直接、E=G 退化全相联。

**五条必记**：
- 地址三段：Tag + Index/Set + Offset，三段位长之和 = 地址宽度。
- 组相联字段计算：组数=槽数/路数，Set=log₂组数，Tag=总位-Off-Set。
- 直接映射不需要替换算法（目标唯一）。
- 命中判定 = Tag 相同 ∧ 有效位为 1，缺一不可。
- 路数（ways）= 相联度，L1 常用 8 路。

**辨析｜易错点**：全相联没有 Index 字段——不是「Index 全 0」，是根本没这一位。

## 7 核心公式
- 槽号 = 块号 mod 槽数（直接映射）。
- 组号 = 块号 mod 组数（组相联）。
- Offset = log2 块大小、Set = log2 组数、Tag = 总位 - Off - Set。
- 命中 = Tag 相同 ∧ 有效位为 1。

## 8 小结- **直接映射**：块号 mod 槽数，固定槽、无替换算法、冲突最大、硬件最简。
- **全相联**：任意槽、Tag 全并行比较、无冲突、硬件最贵，适合 TLB。
- **组相联**：块号 mod 组数 + 组内自由，E=1 退化为直接、E=G 退化为全相联，现代 CPU 主流。
- 地址字段计算链：容量→槽数→组数→Offset/Set/Tag 位宽。
- 路数（ways）是相联度，越大越贵越好，L1 常用 8 路。
