## 为什么函数能「进去再出来」

高级语言的函数调用——传参、执行、返回、恢复现场——在机器级全靠**栈（stack）**：调用者把参数和返回地址压栈，被调用者建栈帧存放局部变量，返回时弹栈恢复。这一课把过程调用的完整机器级机制讲透：**栈帧结构、参数传递约定、返回地址的保存与恢复**。这是理解递归、理解调用约定（ABI）、理解栈溢出攻击的基石。<span class="marginnote">「函数调用是栈数据结构在程序世界的化身」：嵌套调用是后进先出，天然匹配栈的语义。递归之所以能工作，正是因为每次调用都有独立的栈帧——局部变量互不干扰。</span>

## 1 调用机制：CALL 与 RET- **`CALL addr`**：把**返回地址**（下一条指令地址）压栈，然后跳转到 addr。

- **`RET`**：从栈顶弹出返回地址，跳回调用点。

$$\text{CALL: } \text{SP} \to \text{SP} - 8; \ M[\text{SP}] \leftarrow \text{返回地址}; \ \text{PC} \leftarrow \text{addr}$$

$$\text{RET: } \text{返回地址} \leftarrow M[\text{SP}]; \ \text{SP} \to \text{SP} + 8; \ \text{PC} \leftarrow \text{返回地址}$$

**核心概念：返回地址 = 调用点下一条指令的地址**——CALL 压栈、RET 弹栈，一压一弹正好回到调用点继续。<span class="marginnote">为什么返回地址要压栈而不是存寄存器？因为嵌套调用：A 调 B、B 调 C，三个返回地址都要保存，栈的 LIFO 恰好按「先进后出」的顺序恢复。用固定寄存器只能保存一层——这就是栈调用模型的由来。</span>

## 2 栈帧结构被调用函数运行时，在栈顶占据一块区域——**栈帧（stack frame）**：

```text
        高地址
      ┌───────────────┐
      │   调用者的栈帧   │
      ├───────────────┤
      │   参数（>6 个） │  ← 调用者压栈
      ├───────────────┤
      │   返回地址     │  ← CALL 压入
      ├───────────────┤
      │  保存的 %rbp  │  ← push %rbp
      ├───────────────┤
      │   局部变量     │  ← %rbp - 偏移
      │   被保存寄存器  │
      ├───────────────┤
      │   参数（溢出区）│
      │   调用者的局部  │
      └───────────────┘
        低地址    %rsp → 栈顶
```

**帧指针 %rbp**：指向当前帧底部，用于索引参数与局部变量（`%rbp` 负偏移是局部、`%rbp` 正偏移是参数）。
**栈指针 %rsp**：始终指向栈顶，随 push/pop 移动。

**重点：栈向下增长**——地址递减方向；帧指针固定、栈指针浮动，帧指针让「参数与局部变量的位置」在函数内不随 push/pop 变化。<span class="marginnote">现代编译器常用「省略帧指针」优化：用 %rsp 直接索引（需要额外跟踪偏移）。帧指针是调试与回溯（backtrace）的依靠，`-fomit-frame-pointer`（省略帧指针）优化会牺牲部分调试能力。</span>

## 3 参数传递与调用约定x86-64（System V ABI）的参数传递规则：

**前 6 个整数/指针参数**：依次放在 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`。
**超过 6 个参数**：压栈传递。
**返回值**：`%rax`。
**被调用者保存 vs 调用者保存**：`%rbx/%rbp/%r12-%r15` 由被调用者保存（callee-saved）；`%rax/%rcx/%rdx/%rsi/%rdi/%r8-%r11` 调用者保存（caller-saved）。

**核心概念：调用约定（ABI）是「谁负责保存哪个寄存器」的契约**——被调用者保存的寄存器，被调用函数必须「用前保存、用完恢复」；调用者保存的，调用者自己要负责。<span class="marginnote">为什么要分「调用者/被调用者保存」？为了效率：高频寄存器（返回值、参数）由调用者管理，低频寄存器（%rbx 等）由被调用者统一压栈保存一次。这个分工是编译器生成高效代码的基础，也是逆向工程判断「谁保存了谁」的依据。</span>

## 4 公式解析：一次完整调用的汇编全景以 `add` 函数为例，看看机器级的一进一出：

```asm
# 调用者视角：传两个参数并调用
movl  $1, %edi           # 第一个参数 a = 1
movl  $2, %esi           # 第二个参数 b = 2
call  add                # CALL：压返回地址 + 跳转

# add 函数内部
add:
    pushq %rbp           # 建帧：保存调用者帧指针
    movq  %rsp, %rbp     # rbp 指向新帧
    movl  %edi, -4(%rbp) # 参数 a 存到栈上局部
    movl  %esi, -8(%rbp) # 参数 b 存到栈上局部
    movl  -4(%rbp), %eax # 取 a → %eax
    addl  -8(%rbp), %eax # a + b → %eax
    popq  %rbp           # 拆帧：恢复调用者帧指针
    ret                  # RET：弹返回地址跳回
```

逐项拆解：

**第一步，建帧**：`pushq %rbp` 保存调用者帧指针，`movq %rsp, %rbp` 让 rbp 指向新帧。
**第二步，参数**：参数在 `%edi`（第一个参数寄存器），存到栈上局部。
**第三步，计算**：`%eax` 载入 a、`addl` 加上 b 放进返回值寄存器 `%eax`。
**第四步，拆帧**：`popq %rbp` 恢复调用者帧指针，`ret` 弹返回地址跳回。

**核心结论：函数调用的机器级 = 建帧（push rbp）→ 计算 → 拆帧（pop rbp）→ ret**——整个「现场保存与恢复」全靠栈。<span class="marginnote">递归怎么靠这套机制工作？每次递归调用都新建一个栈帧、保存各自的 %rbp 与局部变量——深度递归只受栈空间限制。栈溢出（stack overflow）就是递归太深把栈耗尽——与《虚拟内存》的栈段上限直接相关。</span>

## 5 辨析｜易错点：栈帧与调用约定**辨析｜易错点：**

- **返回地址在参数之前压栈**：`CALL` 先压返回地址，函数入口的 `push %rbp` 在其上——所以参数在返回地址之上（更高地址）。读栈帧布局时别搞反。
- **%rsp 与 %rbp 的职责**：%rsp 随时变（随 push/pop），%rbp 帧内不变——用 %rbp 索引局部变量/参数才稳定。
- **x86-64 参数寄存器顺序**：`%rdi → %rsi → %rdx → %rcx → %r8 → %r9`——这个顺序是 ABI 铁律，写内联汇编或读汇编时必考。
- **调用者保存 ≠ 被调用者不用管**：调用者保存的寄存器，被调用函数可以直接覆盖（因为调用者已经保存了自己的副本）——「谁用谁保存」是理解的关键。

## 6 考点速记：过程调用五件事**一**：CALL 压返回地址 + 跳转；RET 弹返回地址 + 跳回。

**二**：栈帧 = 返回地址 + 保存的 rbp + 局部变量 + 被保存寄存器，栈向下增长。

**三**：x86-64 前 6 个整数参数在 rdi/rsi/rdx/rcx/r8/r9，返回值在 rax。

**四**：callee-saved（rbx/rbp/r12-15）被调用者保存；caller-saved 调用者保存。

**五**：函数机器级 = 建帧（push rbp）→ 计算 → 拆帧（pop rbp）→ ret。

**五条必记**：
- 返回地址在参数之前压栈——读栈帧布局别搞反。
- rsp 随时变、rbp 帧内不变——用 rbp 索引稳定。
- 递归靠独立栈帧，深度受栈空间限制（栈溢出）。
- 调用约定（ABI）是「谁保存谁」的契约。
- 现代编译器可省略帧指针（用 rsp + 偏移）。

**辨析｜易错点**：参数寄存器顺序 rdi→rsi→rdx→rcx→r8→r9 是 ABI 铁律。

## 7 小结- **CALL** 压返回地址 + 跳转；**RET** 弹返回地址 + 跳回。
- **栈帧**：返回地址、保存的 %rbp、局部变量、被保存寄存器——栈向下增长。
- **参数传递**：前 6 个整数参数在 `%rdi/%rsi/%rdx/%rcx/%r8/%r9`，更多压栈；返回值在 `%rax`。
- **调用约定**：callee-saved 与 caller-saved 寄存器的分工契约。
- 函数调用机器级 = 建帧 → 计算 → 拆帧 → ret；递归靠独立栈帧工作。
