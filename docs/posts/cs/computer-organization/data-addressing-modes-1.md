## 为什么寻址方式是指令系统的「语言」

一条指令里的地址码只是一个「线索」，真正的操作数可能在指令里、在寄存器里、在内存的某个地址里、甚至在那地址的地址里。**寻址方式（addressing mode）**定义了「线索 → 操作数」的解释规则。本课讲五种基础方式：**立即、直接、间接、寄存器、寄存器间接**。它们构成了寻址方式的骨架，理解它们，你就看懂了「一条指令怎么找到它要的数据」——这是汇编阅读与指令设计的地基。<span class="marginnote">寻址方式是 ISA 最个性化的部分之一：x86 有十几种寻址，RISC-V 只有几种。寻址方式越多，指令表达越灵活，但解码越复杂——这是「能力 vs 复杂度」的另一处权衡。</span>

## 1 立即寻址**立即寻址（immediate addressing）**：地址码字段**直接存放操作数本身**（称为立即数）。

```
指令:  OP | 立即数(操作数)
```

- 例：`ADD R1, #5` —— 立即数 5 直接参与运算。
- 特点：**取指即得数**，无需访存，最快；但立即数位数受限（在指令里），且是常量、不能修改。
- 用途：常量、初值、偏移。

**重点：立即数在指令里，指令在内存里——「取立即数」就是取指的一部分**，没有额外访存。<span class="marginnote">立即数与后面「直接寻址」一字之差：立即数是「数值就在指令里」，直接寻址是「地址在指令里、数值在内存里」。考试最喜欢在「立即 vs 直接」上设陷阱。</span>

## 2 直接寻址**直接寻址（direct addressing）**：地址码字段存放**操作数的内存地址**。

```
指令:  OP | 内存地址 EA
操作数 = M[EA]
```

- 例：`LOAD R1, [0x2000]` —— 从内存地址 `0x2000` 读数据到 R1。
- 特点：**一次访存**得操作数；寻址空间受地址码位数限制（地址码只有这么多位）。
- 缺点：地址在指令里是「绝对地址」，代码重定位困难；地址范围窄。

**核心概念：有效地址（effective address, EA）**——寻址方式计算出的、真正去访存的地址。<span class="marginnote">直接寻址的地址码就是 EA，最简单；间接寻址则是「先读出一个地址再用它访存」。有效地址是理解一切寻址方式的统一概念：所有寻址方式都在回答「EA 怎么算」。</span>

## 3 间接寻址**间接寻址（indirect addressing）**：地址码字段存放的**不是操作数地址，而是存放操作数地址的地址**。

```
指令:  OP | 地址的地址
EA = M[指令中的地址]   （第一次访存得到地址）
操作数 = M[EA]          （第二次访存得到操作数）
```

- 例：`LOAD R1, [[0x2000]]` —— 先读 `M[0x2000]` 得地址，再用它读数据。
- 特点：**两次访存**，慢；但地址位数等于字长（不受地址码限制），且支持「指针」语义——一个地址可以被多处引用、动态修改。
- 用途：指针、链表遍历、函数指针。

**辨析｜易错点：间接寻址访存两次**，第一次取地址、第二次取数——这是它和直接寻址的本质区别。<span class="marginnote">间接寻址是「C 语言指针」的机器级祖先：`int *p; *p = 5;` 中 `p` 存的是地址，`*p` 要先去内存读 `p` 的地址再访存——和间接寻址的两级访存一一对应。</span>

## 4 寄存器寻址与寄存器间接寻址### 寄存器寻址

**寄存器寻址（register addressing）**：操作数在**寄存器**中，地址码字段是寄存器号。

```
指令:  OP | 寄存器号 Ri
操作数 = Ri
```

- 特点：**零访存**（寄存器在 CPU 内），最快；但寄存器数量少（32/64 个），寄存器号只需几位。
- 用途：算术指令的大多数操作数。

### 寄存器间接寻址

**寄存器间接寻址（register indirect addressing）**：寄存器的内容作为**操作数的内存地址**。

```
指令:  OP | 寄存器号 Ri
EA = Ri 的内容
操作数 = M[EA]
```

- 例：`LOAD R1, (R2)` —— 从「R2 里的地址」指向的内存读数据。
- 特点：**一次访存**；地址长度 = 寄存器长度（= 机器字长），寻址范围最大；改 R2 就改了访问目标——天然支持数组遍历与指针移动。
- 用途：遍历数组（每次递增 R2）、链表、栈操作（SP 就是寄存器间接寻址）。

<span class="marginnote">寄存器间接寻址是现代 CPU 最重要的寻址方式：`*(p++)`、数组 `a[i]` 的机器级实现全靠它。RISC 的访存指令（LD/ST）几乎都是寄存器间接/基址寻址——它是「Load/Store 架构」的支撑。</span>

## 5 公式解析：五种寻址方式的访存次数| 寻址方式 | 地址码含义 | 有效地址 EA | 访存次数 |

| --- | --- | --- | --- |
| 立即 | 操作数本身 | 无需 EA | 0 |
| 直接 | 操作数地址 | EA = A | 1 |
| 间接 | 地址的地址 | EA = M[A] | 2 |
| 寄存器 | 寄存器号 | 操作数 = Ri | 0 |
| 寄存器间接 | 地址在寄存器 | EA = Ri | 1 |

逐项拆解（核心记忆法）：

- **访存 0 次**：立即（数在指令里）、寄存器（数在寄存器里）——最快。
- **访存 1 次**：直接（地址在指令）、寄存器间接（地址在寄存器）——地址来源不同，访存次数相同。
- **访存 2 次**：间接——先读地址再读数，最慢。

**核心结论：寻址方式的「速度排序」几乎就是访存次数排序**——寄存器/立即 > 直接/寄存器间接 > 间接。<span class="marginnote">为什么间接寻址已不多见？两次访存太慢，且现代编译器可以用「寄存器间接 + 偏移」模拟出指针语义。间接寻址是历史遗产，但理解它有助于读懂老代码与体系结构演进。</span>

## 6 一句话回顾- 立即 0 访存、直接 1 访存、间接 2 访存。
- 寄存器 0 访存、寄存器间接 1 访存。
- 速度排序 ≈ 访存次数排序。

## 7 小结- **立即寻址**：数在指令里，0 访存，最快，限于常量。
- **直接寻址**：地址在指令里，1 访存，寻址范围受地址码限制。
- **间接寻址**：地址的地址在指令里，2 访存，支持指针语义。
- **寄存器寻址**：数在寄存器里，0 访存。
- **寄存器间接寻址**：地址在寄存器里，1 访存，支持数组/指针/栈。
- 统一框架：**有效地址 EA** 的计算方式区分了各寻址方式。

- 立即 0 访存、直接 1 访存、间接 2 访存
- 寄存器 0 访存、寄存器间接 1 访存
- 速度排序 ≈ 访存次数排序
- 间接寻址支持指针语义
- 寄存器间接支持数组遍历
- EA 是统一框架
- 立即数是常量不能改
- 直接寻址绝对地址难重定位
