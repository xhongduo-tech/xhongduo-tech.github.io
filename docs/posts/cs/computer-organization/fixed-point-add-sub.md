## 为什么加减运算是整个算术的地基

上一课我们提到「补码让减法消失」，本课把这句话变成硬件。计算机里没有独立的减法器——减法指令执行的是「取减数的相反数再相加」。这意味着：**只要造出一个好加法器，加减法就全部解决了**，而乘法、除法又都可以化归为加减与移位。因此理解定点加减的运算规则、硬件流程与溢出判断，是理解整个 ALU 的第一块基石。<span class="marginnote">ALU 里那个加法器，在后文《加法器设计》一课会从晶体管逻辑一路设计到先行进位。今天的定点加减，是它的软件视角。</span>

## 1 补码加减的运算规则**核心概念：补码加减运算规则**——按二进制运算规则，符号位与数值位一起参与运算，结果的符号位由运算自然得出。

$$[x + y]_{\text{补}} = [x]_{\text{补}} + [y]_{\text{补}} \pmod{2^n}$$

$$[x - y]_{\text{补}} = [x]_{\text{补}} + [-y]_{\text{补}} = [x]_{\text{补}} + \left(\overline{[y]_{\text{补}}} + 1\right)$$

第二式是关键：减法被改写为「被减数加（减数各位取反加一）」。取反加一就是「求负」，硬件上一组反相器 + 一个加 1 信号即可完成。<span class="marginnote">一个 1 位控制信号 `Sub` 就能让同一套电路既做加法又做减法：`Sub=0` 时正常相加，`Sub=1` 时把减数取反并把进位置 1（相当于加一）。这是教科书上经典的「加减共用一个加法器」设计。</span>

### 例 1：同号相加

$[+25]_{\text{补}} + [+13]_{\text{补}} = 0001\ 1001 + 0000\ 1101 = 0010\ 0110 = +38$

### 例 2：异号相减（转加法）

$[+25]_{\text{补}} - [+13]_{\text{补}} = 0001\ 1001 + (1111\ 0010 + 1) = 0001\ 1001 + 1111\ 0011 = 1\ 0000\ 1100 \to +12$

最高位进位 1 自然丢弃，结果正确。**符号位参与了运算**，这正是补码的灵魂。

## 2 溢出的概念**溢出（overflow）**：运算结果超出了机器数所能表示的范围，产生了「正确的二进制结果，但错误的真值」。

例如 8 位补码，$+100 + +50$：

$$0110\ 0100 + 0011\ 0010 = 1001\ 0110$$

二进制相加没错（模 256 下），但 `1001 0110` 读作 $-106$，而不是 $+150$——**结果正负号都翻了**，这就是溢出。

**辨析｜易错点：**进位与溢出是两回事：

- **进位（carry）**：最高位产生了进位/借位，只说明「超出字长」，无符号数视角下它正常（无符号运算丢弃进位得到正确结果）。
- **溢出（overflow）**：有符号数视角下结果超出表示范围，真值错误。
- 同一个运算，从无符号看是进位、从有符号看是溢出——**进位与溢出永远不要混为一谈**。<span class="marginnote">硬件把两者分开记录：标志寄存器里 `CF` 记进位、`OF` 记溢出。程序员选对标志位，是汇编编程的基本功。</span>

## 3 公式解析：溢出的三种判断方法**溢出只可能发生在「两个同号数相加」或「两个异号数相减」时**——异号相加、同号相减（异号相加等价）永不溢出。判断方法有三种：

### 方法一：单符号位法

直接看结果符号位与操作数符号位是否一致。若两个操作数符号相同，而结果符号与之不同，则溢出。

$$+100 + +50 = -106 \quad(\text{符号 } 0,0 \to 1 \Rightarrow \text{溢出})$$

### 方法二：双符号位法（变形补码）

用两个符号位（如 `00` 表正、`11` 表负），运算后看两个符号位：

- `00` 或 `11`：无溢出（两符号位相同）。
- `01`：正溢出（结果为正但超出范围）。
- `10`：负溢出（结果为负但超出范围）。

**结果的正确符号位是最高位符号位（第一个）**，次高位符号位可用于判断。硬件只需比较两个符号位是否相等。<span class="marginnote">双符号位法也叫「模 4 补码」，因为它以 4 为模运算。它比单符号位法更适合硬件：异或两个符号位即可得溢出信号。现代 ALU 正是这样实现的。</span>

### 方法三：最高位进位与次高位进位异或

设 $C_n$ 为最高位的进位，$C_{n-1}$ 为次高位的进位，则：

$$\text{overflow} = C_n \oplus C_{n-1}$$

**直觉**：最高位进位说明「符号位被改变了」，次高位进位说明「数值位溢进了符号位」。两者不同时发生才是真溢出。<span class="marginnote">异或法的硬件实现就是两个进位信号过一个 XOR 门，速度快、面积小，是所有教科书推荐的工程方案。</span>

## 4 定点小数的加减定点小数（模 2）的加减规则与整数完全一致，只是范围解释不同：

$$x + y \pmod{2}, \qquad x - y = x + (-y) \pmod{2}$$

例如 $0.75 + 0.5$（8 位定点小数）：$0110\ 0000 + 0100\ 0000 = 1010\ 0000$，读作 $-0.75$——而正确结果 $+1.25$ 超出 $-1\sim1$ 范围，是正溢出。**同样的位模式，换一种定点约定，溢出判断也换一套**。

## 5 加减运算的工程流程一次完整的定点加减在 CPU 中大致走这样的流程：

1. **取数**：从寄存器或存储器取出两个操作数。
2. **选数**：根据指令是加还是减，决定是否对第二个操作数取反加一。
3. **相加**：送入加法器，得结果与进位。
4. **判溢**：用方法二或方法三生成溢出标志，写入标志寄存器。
5. **写回**：结果存入目标寄存器；若溢出，依据指令策略触发异常或静默截断。

<span class="marginnote">C 语言里 `int` 溢出是「未定义行为」，编译器假定它不会发生并据此优化；而在硬件层面溢出标志一直存在。理解这层差异，是《C 语言中的整数与浮点数》一课的重要伏笔。</span>

## 6 补充：定点加减速记- 补码加减统一为加法：[x-y]补 = [x]补 + [-y]补。
- 符号位参与运算，模 2^n 丢弃进位。
- 溢出 ≠ 进位：CF 管进位、OF 管溢出。
- 判溢三法：单符号位、双符号位、最高/次高位进位异或。
- 双符号位法硬件最友好，现代 ALU 用异或法。

## 7 一句话回顾- 补码加减统一为加法，符号位参与运算。
- 溢出 ≠ 进位：CF 与 OF 各管一摊。
- 判溢三法殊途同归，硬件用异或法。

> 记住：进位与溢出是两回事（CF vs OF）。

## 8 核心公式
- $[x+y]_{补} = [x]_{补} + [y]_{补} \pmod{2^n}$。
- $[x-y]_{补} = [x]_{补} + [-y]_{补} = [x]_{补} + (\bar{y} + 1)$。
- 溢出 = $C_n \oplus C_{n-1}$（最高位进位与次高位进位异或）。
- 双符号位：`01` 正溢出、`10` 负溢出、`00/11` 正常。
- 减法复用加法器：取反加一 + 进位信号 1。

## 9 小结- 补码加减统一为**加法**：$[x-y]_{\text{补}} = [x]_{\text{补}} + [-y]_{\text{补}}$，取反加一即求负。
- **符号位参与运算**，模 $2^n$ 丢弃进位。
- **溢出 ≠ 进位**：`CF` 管进位，`OF` 管溢出，有符号溢出才是真错误。
- 溢出判断三法：**单符号位法**、**双符号位法**、**最高位与次高位进位异或**。
- 双符号位法硬件最友好，现代 ALU 采用异或法。
