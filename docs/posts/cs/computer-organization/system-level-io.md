## 为什么「I/O 的终极抽象」是文件

前几课的查询、中断、DMA 是 I/O 的「硬件方式」；本课看「软件方式」——操作系统如何把这些硬件封装成程序员的接口。**Unix I/O** 用「文件」统一一切设备，用**文件描述符**统一访问方式，用**三个表**管理共享与偏移。这是 CS:APP 第十章的内容，也是从组成原理过渡到操作系统的桥梁。<span class="marginnote">「万物皆文件」是 Unix 的设计哲学：设备、管道、socket 都暴露为文件描述符，用统一的 `read`/`write` 操作。硬件千差万别，文件抽象把它们统一——这是《I/O 系统概述》「设备无关性」的具体实现。</span>

## 1 Unix I/O 的基本操作Unix I/O 的四大系统调用：

**`open`**：打开文件，返回**文件描述符（fd）**。
**`read`**：从 fd 读 n 字节到 buf。
**`write`**：写 buf 的 n 字节到 fd。
**`close`**：关闭文件。

```c
int fd = open("hello.txt", O_RDONLY);  // 打开文件，返回 fd
char buf[1024];
ssize_t n = read(fd, buf, sizeof(buf)); // 读 n 字节到 buf
write(STDOUT_FILENO, buf, n);           // 写 buf 到标准输出
close(fd);                              // 关闭文件
```

**核心概念：文件描述符（fd）是内核维护的「打开的文件的编号」**——程序不直接碰文件，只碰整数 fd，内核用 fd 索引真正的文件状态。<span class="marginnote">标准三件套：fd 0=标准输入、fd 1=标准输出、fd 2=标准错误——由 shell 在启动时自动打开。`printf` 最终调用 `write`，`scanf` 调用 `read`——一切高级 I/O 都建立在 `open`/`read`/`write`/`close` 之上。</span>

## 2 内核的三个表：文件如何被共享内核用三张表管理每个打开的文件：

| 表 | 内容 | 作用 |
| --- | --- | --- |
| 描述符表 | fd → 打开文件表项 | 每个进程一张 |
| 打开文件表 | 文件偏移、访问模式 | 全局共享 |
| v-node 表 | 文件类型、大小、inode | 全局，每个文件一项 |

**重点：进程的描述符表是私有的，但打开文件表与 v-node 表是全局共享的**——这是「文件共享」的机制基础。

**共享的方式**：

**父子进程共享**：`fork` 后子进程复制父进程的描述符表，指向**同一个**打开文件表项——共享文件偏移（读写互相影响）。
**独立打开**：两个进程各自 `open` 同一文件 → 各自独立的打开文件表项 → 独立偏移。<span class="marginnote">「偏移是否共享」是文件共享的核心：`fork` 后的子进程与父进程共享偏移（同一打开文件表项），所以一个读文件另一个会「接着读」；而两次独立 `open` 则各读各的。这个细节决定了多进程协作读写文件的行为。</span>

## 3 标准 I/O 与系统调用的关系**标准 I/O 库（stdio）** 是 `open`/`read`/`write`/`close` 之上的缓冲层：

**全缓冲**：数据先攒在用户缓冲里，满了才 `write`（文件）。
**行缓冲**：遇到换行才刷新（终端）。
**无缓冲**：立即写（错误输出 stderr）。

```c
printf("hello");         // 全缓冲：先攒在 stdio 缓冲区
fgets(buf, 100, stdin);  // 行缓冲：遇到换行才刷新
fprintf(stderr, "oops"); // 无缓冲：立即输出
fflush(stdout);          // 强制刷新到内核
```

**核心概念：stdio 的缓冲是为了「少调用系统调用」**——系统调用有开销（进入内核、特权切换），攒一批写一次能大幅提效。<span class="marginnote">「缓冲省系统调用」的数量级：每次 `write` 是进内核（约百纳秒到微秒），攒 4KB 写一次 vs 逐字节写 4096 次——差几千倍。但缓冲也有坑：`fork` 后没 `fflush` 就 `exit`，缓冲内容会被复制两份——经典 bug。</span>

## 4 公式解析：I/O 的完整链路一次 `printf` 到底经历了什么？从应用到硬件：

$$\text{printf} \to \text{stdio 缓冲} \to \text{write 系统调用} \to \text{内核文件系统} \to \text{磁盘/SSD} \to \text{DMA 传输}$$

逐项拆解：

- **第一步，用户库**：stdio 格式化 + 缓冲。
- **第二步，系统调用**：`write` 进内核（特权切换）。
- **第三步，内核**：文件系统定位、页缓存（page cache）命中或缺失。
- **第四步，硬件**：页缓存缺失 → 发块设备 I/O → **DMA** 把数据从磁盘搬进页缓存。
- **第五步，返回**：数据从页缓存拷到用户缓冲，`read` 返回。

**核心结论：一次文件写可能经过「缓冲 → 系统调用 → 页缓存 → DMA → 磁盘」五层**——每一层都在「减少下层调用次数」。<span class="marginnote">「页缓存（page cache）」是关键中间层：读过的文件页留在内存，重复读直接命中——这就是为什么「第二次读同一文件快得多」。页缓存本质是「文件系统层的 Cache」，与《Cache》一课的思想完全同构：局部性 + 按块缓存 + 替换。整个存储层次（寄存器→缓存→内存→页缓存→磁盘）在这一刻连成一体。</span>

## 5 辨析｜易错点：系统级 I/O**辨析｜易错点：**

- **系统调用 ≠ 标准库函数**：`write` 是系统调用（进内核），`printf` 是库函数（带缓冲）——「printf 直接写设备」是错的。
- **fd 是整数，不是文件指针**：`FILE *` 是 stdio 的封装（含缓冲），fd 是内核编号——两者转换用 `fileno`/`fdopen`。
- **`read` 可能读不满**：读文件可能返回「读了多少算多少」（如读到 EOF、信号中断）——不能假设一次 `read` 读满 n 字节，要循环读。这是 CS:APP 反复强调的「short count」问题。
- **关闭 fd 才释放资源**：不 `close` 会泄漏描述符（打开文件数有限制）。

## 6 考点速记：系统级 I/O 五件事**一**：Unix I/O 四大调用 open/read/write/close，fd 统一访问一切设备。

**二**：三张表——描述符表（进程私有）、打开文件表（共享偏移）、v-node 表（共享文件）。

**三**：fork 共享偏移（同一打开文件表项），独立 open 独立偏移。

**四**：stdio 缓冲（全/行/无）减少系统调用，`fflush` 强制刷新。

**五**：完整链路 printf → 缓冲 → write 系统调用 → 页缓存 → DMA → 磁盘。

**五条必记**：
- fd 0/1/2 = 标准输入/输出/错误。
- `read` 可能读不满（short count），要循环读。
- 系统调用（进内核）≠ 库函数（用户层缓冲）。
- 页缓存是「文件系统层的 Cache」，第二次读快。
- `close` 不及时会泄漏描述符。

**辨析｜易错点**：printf 后不 fflush 就 fork——缓冲内容被复制两份，经典 bug。

## 7 小结- **Unix I/O**：`open`/`read`/`write`/`close` 四大调用，fd 统一访问一切设备。
- 三张表：**描述符表（私有）→ 打开文件表（共享偏移）→ v-node 表（共享文件）**。
- **fork 共享偏移，独立 open 独立偏移**——文件共享的机制基础。
- stdio 缓冲：全缓冲/行缓冲/无缓冲，少调系统调用换性能。
- 完整链路：printf → 缓冲 → 系统调用 → 页缓存 → DMA → 磁盘——存储层次的全景。

- open/read/write/close 四大调用
- fd 0/1/2 标准输入输出错误
- 三张表：描述符/打开文件/v-node
- fork 共享偏移、独立 open 独立
- stdio 缓冲减少系统调用
- read 可能读不满要循环
- 页缓存是文件系统层 Cache
- close 不及时泄漏描述符
