## 为什么「主动打招呼」优于「被动等待」

程序查询让 CPU 干等设备，效率太低。**程序中断方式（interrupt-driven I/O）** 反转角色：**设备就绪时主动向 CPU 发中断请求**，CPU 暂停当前程序、处理设备、再恢复。CPU 不用再轮询，可以安心做别的。本课是中断方式的开篇，讲中断的基本概念、中断的分类与中断处理的总流程——后面几课展开细节。<span class="marginnote">「中断（interrupt）」是操作系统的心脏机制之一：I/O 完成、定时器到点、错误发生都靠中断通知 CPU。中断让 CPU 从「被动等待」变为「主动干别的事、被设备打断时再响应」——这是现代系统并发的硬件基础。</span>

## 1 中断的基本概念**核心概念：中断（interrupt）**——CPU 执行程序过程中，因**外部事件或内部异常**暂停当前程序，转去执行**中断服务程序**，处理完再返回原程序继续。

```text
主程序 ──执行──► 中断请求 ──► 保存现场 ──► 服务程序 ──► 恢复现场 ──► 继续
```

**中断与调用的区别**：

- 调用是**程序主动**请求（`call`），中断是**设备/事件被动**触发。
- 调用的目标地址在代码里写死；中断的目标地址由**中断向量表**给出。
- 调用的时机由程序控制；中断的时机**不确定**（随时可能来）。<span class="marginnote">「中断是不确定的」是它的本质特征：CPU 不知道设备何时就绪，所以必须在每条指令边界检查中断请求。这个「指令边界检查」是中断响应的硬件约定，也是《指令周期》里「中断周期」的来源。</span>

## 2 中断的分类按来源分：

- **外部中断（硬件中断）**：I/O 设备请求、定时器——来自 CPU 外部。
- **内部异常**：除零、缺页、非法指令——来自 CPU 内部（见《异常与控制流》）。

按可屏蔽性分：

- **可屏蔽中断（maskable）**：受中断允许标志（IF）控制，可被软件关闭。
- **不可屏蔽中断（NMI）**：不受 IF 控制，必须响应（电源故障、内存校验错误）。

按优先级分：

- **多重中断**：高优先级中断可打断低优先级中断的服务程序。

**核心概念：可屏蔽 vs 不可屏蔽是「CPU 能不能拒绝」**——I/O 中断可屏蔽（IF=0 时忽略），NMI 不可屏蔽（重大事件必须响应）。<span class="marginnote">x86 的 `cli`（关中断）/`sti`（开中断）指令控制 IF 位。临界区（共享资源保护）里要关中断防止被打断——但关中断太久会延迟响应真实 I/O，所以临界区要尽量短。「关中断的代价」是实时系统设计的重要权衡。</span>

## 3 中断的完整流程中断处理分五个阶段：

1. **中断请求（INTR）**：设备发请求信号。
2. **中断判优**：多个请求时选最高优先级（见《中断请求、中断判优与中断响应》）。
3. **中断响应**：CPU 确认响应：关中断、保存现场、取中断向量、转服务程序。
4. **中断服务**：执行设备处理程序（读数据、写命令）。
5. **中断返回（IRET）**：恢复现场、开中断、返回原程序。

**核心概念：中断响应是「硬件自动完成的部分」**——保存现场（PC、PSW 压栈）与取向量由硬件在几条指令内完成，服务程序才是软件。<span class="marginnote">「保存现场」保存什么：PC（返回地址）与 PSW（状态字）由硬件压栈，其他寄存器（通用寄存器）由中断服务程序开头自己保存。为什么分开？硬件只保「马上要用」的最小现场，其余交给软件按需保存——这是硬件/软件分工的典型。</span>

## 4 公式解析：中断与查询的效率对比设设备就绪平均周期 $T_d$，中断响应与处理开销 $T_{int}$：

- 查询：CPU 空转 ≈ $T_d$（每传输）。
- 中断：CPU 花 $T_{int}$ 处理，其余时间干正事。

$$\text{查询 CPU 占用} \approx r \cdot c \quad(\text{见上节})$$

$$\text{中断 CPU 占用} \approx r \cdot T_{int} \quad(\text{只付处理开销})$$

逐项拆解：

- **第一步，查询**：等设备期间 CPU 一直空转轮询——占用与等待成正比。
- **第二步，中断**：等待期间 CPU 干正事，就绪后才被打断处理——占用只算处理时间。
- **第三步，对比**：只要 $T_{int} \ll T_d$（处理远快于等待），中断就远优于查询。

**核心结论：中断把 CPU 从「等待」中解放——等待期干别的，只付处理开销**。<span class="marginnote">这正是「中断」统治现代系统的原因：CPU 等待键盘/磁盘时可以去跑其他进程。而「等待期干别的」正是操作系统的并发模型——中断让单 CPU 也能「同时」管理多设备、多进程。</span>

## 5 辨析｜易错点：中断基本概念**辨析｜易错点：**

- **中断（I/O 设备）vs 异常（内部事件）**：唐朔飞教材常把中断特指外部硬件中断，内部事件叫异常——术语按教材口径。
- **可屏蔽中断 ≠ 低优先级**：屏蔽是「软件能关」，优先级是「多个请求谁先」——两个维度。
- **中断服务程序运行在什么上下文**：它打断当前程序，运行在「被打断者的上下文」里——所以必须保存现场、快速返回。
- **中断返回指令是 `iret`**，不是普通 `ret`——它同时恢复 PC 与 PSW。

## 6 考点速记：中断基本概念**中断定义**：设备/事件主动请求，CPU 暂停当前程序、转去服务、再恢复——与程序主动的「调用」相反。

**分类**：外部中断（I/O、定时器）vs 内部异常（除零、缺页）；可屏蔽（IF 控制）vs 不可屏蔽（NMI）。

**流程五步**：请求 → 判优 → 响应（关中断+保存现场+取向量）→ 服务 → 返回。

**五条必记**：

- 中断时机不确定 → CPU 在指令边界检查中断请求。
- 硬件保存 PC+PSW，通用寄存器由服务程序自己保存。
- `cli/sti`（x86）控制 IF——临界区要关中断，但关太久延迟真实中断。
- 中断返回用 `iret`（同时恢复 PC 与 PSW），不是普通 `ret`。
- 中断让 CPU「等待期干别的」——并发模型的基础。

**辨析｜易错点：**可屏蔽 ≠ 低优先级——屏蔽是「软件能关」，优先级是「多个请求谁先」，两个维度。

## 7 一句话回顾- 中断 = 设备主动请求，CPU 暂停服务再恢复。
- 可屏蔽受 IF 控制，NMI 必须响应。
- 响应：关中断 + 保存 PC/PSW + 取向量。

## 8 核心要点
- 中断 = 设备主动、调用 = 程序主动。
- 可屏蔽受 IF 控制、NMI 必须响应。
- 响应：关中断+保存 PC/PSW+取向量。
- 硬件存 PC/PSW、软件存通用寄存器。

## 9 小结- **中断**：设备主动请求，CPU 暂停当前程序、服务设备、恢复执行。
- 分类：外部中断/内部异常，可屏蔽/不可屏蔽（NMI）。
- 流程：请求 → 判优 → 响应（保存现场+取向量）→ 服务 → 返回。
- 硬件保存 PC+PSW，软件保存其余寄存器——软硬分工。
- 中断让 CPU 从「等待」解放：占用只算处理开销，查询则全耗在等待。

- 中断 = 设备主动、调用 = 程序主动
- 可屏蔽受 IF 控制、NMI 必须响应
- 响应：关中断+保存 PC/PSW+取向量
- 硬件存 PC/PSW、软件存通用寄存器
- 指令边界检查中断
- cli/sti 控制 IF
- iret 恢复 PC+PSW
- 中断等待期干别的=并发基础
