## 为什么从「hello, world」到机器指令的旅程开始

我们写下的 C 语言源码（如 hello.c）是一串人类可读的字符，而 CPU 只认二进制机器码。中间隔着一条漫长的流水线：**预处理 → 编译 → 汇编 → 链接 → 装载**。这条路每个程序员每天都在走，但大多数人不清楚每一站发生了什么。理解了这条「翻译链」，你才能真正读懂 `语法错误`、`undefined reference` 与 `段错误` 这类报错到底在说哪一环出了问题。<span class="marginnote">这条链与第一篇《计算机的层次结构》一一对应：C 是高级语言机器级，汇编是汇编语言机器级，机器码是机器语言级。每向下走一级，离硬件就近一步。</span>

## 1 从源代码到目标文件：编译与汇编### 预处理

以 C 为例，第一阶段是预处理，处理以 `#` 开头的指令。`#include` 把头文件内容原样插入，`#define` 做文本替换，`#ifdef` 做条件编译。预处理的产物仍是文本，只是「展开」后的 C 源文件。

### 编译

编译阶段把 C 源码翻译成**汇编语言**。这是整个链条中语义最重的环节：编译器要做词法分析、语法分析、语义分析、中间代码生成与优化，最终输出 `.s` 汇编文件。例如：

```c
int add(int a, int b) {
    return a + b;
}
```

经编译后大致得到：

```asm
add:
    leal (%rdi, %rsi), %eax   # rdi = a, rsi = b，一条指令算完 a+b
    ret
```

这里 `leal (%rdi, %rsi), %eax` 一条指令就完成了加法——编译器聪明地把「取地址再相加」的语义用在了整数加法上。<span class="marginnote">注意编译输出的是「可移植的汇编文本」，它还没有被固定到具体内存地址，里面的函数名、全局变量名都以符号（symbol）形式存在。</span>

### 汇编

汇编阶段把汇编文本翻译成**机器码**，输出**可重定位目标文件（relocatable object file）**，Unix 下扩展名是 `.o`，Windows 下是 `.obj`。汇编器做的是近乎「一一对应」的翻译：每条汇编指令对应一条（或几条）机器指令，同时生成**符号表（symbol table）**，记录本文件定义与引用了哪些全局符号。

## 2 链接：把碎片拼成整体一个程序很少只有一个目标文件。main.o 调用 libc 里的 printf，两者分别编译，**链接器（linker）**负责把它们拼成一个可执行文件。

链接要解决两个核心问题：

**符号解析（symbol resolution）**：把每一处对符号的引用，与符号表里的定义对上。如果找不到定义，就报 `undefined reference` 链接错误。
**重定位（relocation）**：把各目标文件中的代码和数据段合并，为每个符号分配最终的**虚拟地址**，然后修改所有引用这些符号的指令，把「占位地址」替换成真实地址。<span class="marginnote">这也是目标文件叫「可重定位」的原因：它里面的地址都是相对本文件的偏移，等着链接阶段被「重新定位」到最终地址。</span>

### 静态链接与动态链接

**静态链接**把库的代码直接复制进可执行文件，缺点是文件大、库更新要重新链接。**动态链接**则只在可执行文件里留下一个「引用」，运行时由动态链接器（如 Linux 的 ld.so）在装载时把共享库映射进进程地址空间。这就是为什么你的程序能共享系统里的 libc——内存里只放一份库代码。

## 3 装载：让程序跑起来链接完的可执行文件还躺在磁盘上。**装载（loading）**由操作系统完成：把可执行文件中的代码段、数据段读入内存，建立栈与堆，把入口地址装入 PC（程序计数器），然后把控制权交给程序。在现代操作系统里，这个动作对应 execve 系统调用，并且大量依赖**虚拟内存**的按需调页——程序还没用到的部分先不读入，用到时再缺页调入。<span class="marginnote">「装载即映射」是现代系统的关键观念：可执行文件不是被整体拷贝进内存，而是被<strong>映射</strong>进虚拟地址空间。这背后是第三篇《虚拟存储器》的页表机制，也是理解 mmap 的钥匙。</span>

## 4 公式解析：可执行文件的逻辑组成一个典型的可执行文件（ELF 格式）按段组织，其逻辑结构可写作：

$$\text{ELF} = \text{ELF 头} + \left[ \begin{array}{c} .text \\ .data \\ .bss \end{array} \right]_{\text{段}} + \text{节头表} + \ldots$$

逐项拆解：

- **ELF 头**：固定结构，记录文件类型、入口点、节头表位置等元数据，装载器读它决定「文件长什么样」。
- **`.text` 段**：只读的机器代码，装载后标记为「可执行不可写」——这是防止代码被篡改的第一道防线。
- **`.data` 段**：已初始化的全局变量和静态变量，有初值，装载时从文件拷贝到内存。
- **`.bss` 段**：未初始化的全局/静态变量，文件里不占空间，装载时由内核清零——因为「未初始化」的 C 语义就是「初值为 0」。<span class="marginnote">`.bss` 不占磁盘空间这个事实意味着：声明一个 `char buf[1 << 30]` 的全局数组，可执行文件并不会因此变大 1GB——这常常让初学者惊讶。</span>

## 5 辨析｜易错点：编译、汇编、链接、装载分别做了什么| 阶段 | 输入 | 输出 | 关键产物/动作 | 典型报错 |

| --- | --- | --- | --- | --- |
| 预处理 | `.c` | `.i`（展开文本） | `#include`/`#define` 展开 | 找不到头文件 |
| 编译 | `.i` | `.s`（汇编文本） | 语法/语义分析、优化 | 语法错误 |
| 汇编 | `.s` | `.o`（目标文件） | 符号表、可重定位机器码 | 汇编指令写错 |
| 链接 | 多个 `.o` | 可执行文件/共享库 | 符号解析、重定位 | undefined reference |
| 装载 | 可执行文件 | 内存中的进程 | 段映射、栈堆建立、跳转入口 | 段错误 |

**辨析｜易错点：**「编译」在中文口语里常被泛指整条链，但在组成原理语境下它特指「高级语言 → 汇编」这一段。考试与面试里，「把 `.c` 变成可执行文件经历了哪些阶段，各自输出什么」是出现频率极高的基础题，务必把上表每一行记牢。

## 6 考点速记：五阶段编译链| 阶段 | 输入 | 输出 | 关键动作 || --- | --- | --- | --- |
| 预处理 | .c | .i | #include/#define 展开 |
| 编译 | .i | .s | 语法语义分析、优化 |
| 汇编 | .s | .o | 符号表、机器码 |
| 链接 | 多个 .o | 可执行文件 | 符号解析、重定位 |
| 装载 | 可执行文件 | 内存进程 | 段映射、跳转入口 |

**五条必记**：

- 静态链接把库复制进可执行文件；动态链接留引用、运行时加载共享库。
- ELF 逻辑组成：.text（代码）、.data（已初始化）、.bss（未初始化、不占磁盘）。
- 符号解析失败 → undefined reference；重定位把占位地址换成真实地址。
- 装载靠虚拟内存的按需调页，不是整体拷贝。
- 「编译」在中文口语常泛指整条链，严格特指「高级语言→汇编」。

**辨析｜易错点：**`.bss` 不占磁盘——声明 `char buf[1 << 30]` 全局数组不会让可执行文件变大 1GB。

## 7 一句话回顾- 预处理→编译→汇编→链接→装载，五阶段。
- 链接做符号解析 + 重定位。
- 装载靠虚拟内存按需调页。

> 一句话：链接做符号解析 + 重定位。

## 8 小结- 完整链路：**预处理 → 编译 → 汇编 → 链接 → 装载**，每一级都有明确的输入输出。
- 编译输出汇编文本，汇编输出**可重定位目标文件**，链接完成**符号解析**与**重定位**。
- 链接分**静态**与**动态**两种；动态链接让共享库在内存中只存一份。
- 装载由操作系统完成，核心是现代系统的**虚拟内存映射**，而非整体拷贝。
- ELF 逻辑组成：`.text`（代码）、`.data`（已初始化数据）、`.bss`（未初始化数据）。

- 预处理→编译→汇编→链接→装载
- 链接做符号解析+重定位
- .bss 不占磁盘空间
- 动态链接运行时加载共享库
- 装载靠虚拟内存按需调页
- undefined reference 是链接错误
- 装载即映射非拷贝
- ELF：.text/.data/.bss
