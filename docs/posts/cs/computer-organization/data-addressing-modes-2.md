## 为什么需要「地址 + 位移」

上一课的五种寻址都是「一个地址搞定」，但真实程序还要求：**代码重定位**（程序移到哪都能跑）、**数组遍历**（地址要动态变）、**结构体访问**（基址 + 字段偏移）。这些需求的统一解法是「**地址 + 位移**」：用一个寄存器当基准，加上一个偏移量得到有效地址。本课讲四种经典形式：**相对、基址、变址、堆栈**寻址，并辨析最容易混淆的「基址 vs 变址」。<span class="marginnote">「基址 + 偏移」是现代 CPU 寻址的绝对主流：x86 的 `[base + index*scale + disp]`、RISC-V 的 `ld rd, offset(rs1)` 都是这个家族。这一课是阅读任何汇编的必备技能。</span>

## 1 相对寻址**相对寻址（relative addressing）**：有效地址 = **PC 内容 + 位移量**。

$$\text{EA} = \text{PC} + \text{offset}$$

- 例：`JZ +4`、`LOAD R1, +8(PC)`。
- 特点：**以 PC 为基准**，程序整体搬移后相对关系不变——代码可重定位。
- 主要用途：**分支指令**的目标地址（见《指令寻址》的相对跳转），也可用于读取「紧跟指令的常量」。

**重点：相对寻址的基准是 PC**，而基址寻址的基准是任意寄存器——一字之差，用途完全不同。<span class="marginnote">相对寻址是分支指令的标准实现：`JMP offset` 在汇编器眼里就是「PC + offset」。程序加载到任何地址都能跑，全靠相对寻址的「随遇而安」——这是《链接与装载》里位置无关代码（PIC）的核心。</span>

## 2 基址寻址**基址寻址（base addressing）**：有效地址 = **基址寄存器内容 + 位移量**。

$$\text{EA} = \text{(基址寄存器)} + \text{offset}$$

- 例：`LOAD R1, 8(R2)` —— R2 是基址寄存器，8 是位移。
- 特点：**基准是程序员/系统指定的基址寄存器**，用于把「程序/数据在内存中的起点」固定下来。
- 用途：**程序重定位**——把整个程序的数据区基点装入基址寄存器，所有访问都相对基点，搬动程序只需改基址寄存器；也可用于访问栈帧（帧指针 + 偏移）。

**核心概念：基址寻址解决「程序搬到哪」**——基址寄存器保存程序/模块的起点，偏移量在链接时确定，运行时只需改基址。<span class="marginnote">基址寻址的经典应用是「重定位」：一个程序从磁盘加载到不同物理地址，操作系统把基址装入基址寄存器，所有地址自动跟着变——这是分段虚拟内存的原始形态（《分段》一课的段基址就是基址寄存器）。</span>

## 3 变址寻址**变址寻址（indexed addressing）**：有效地址 = **指令中的地址 + 变址寄存器内容**。

$$\text{EA} = \text{地址（指令内）} + \text{(变址寄存器)}$$

- 例：`LOAD R1, array(R3)` —— array 是数组基地址（指令里），R3 是变址（数组下标）。
- 特点：**基准在指令里（固定），变化量在变址寄存器里（动态）**——与基址寻址正好相反！
- 用途：**数组/表遍历**——每循环一次把变址寄存器加元素大小，地址自动推进。

**辨析｜易错点：基址 vs 变址**——这是本课最高频考点：

| 维度 | 基址寻址 | 变址寻址 |
| --- | --- | --- |
| 基准在哪 | 寄存器（可变的基点） | 指令内（固定的基地址） |
| 变化量在哪 | 指令内（固定偏移） | 寄存器（可变的变址） |
| 典型用途 | 程序/数据重定位 | 数组遍历、查表 |

一句话记：**基址寻址「基点可变、偏移固定」；变址寻址「基点固定、变址可变」**。两者公式相同（寄存器 + 偏移），但基准与变化量的角色互换。<span class="marginnote">记忆锚点：变址寻址里「变址寄存器」之所以叫变址（index），因为它就是 C 里 `a[i]` 的 `i`——下标在变。基址寻址的寄存器叫基址（base），因为它是「基地」的起点。i 是变址，base 是基址。</span>

## 4 堆栈寻址**堆栈寻址（stack addressing）**：操作数**隐式**在栈顶，由**栈指针（SP）**指明。

$$\text{操作数} = \text{M[SP]}, \qquad \text{SP 自动增减}$$

- **压栈 PUSH**：`SP ← SP - 1; M[SP] ← 操作数`（栈向下增长）。
- **出栈 POP**：`操作数 ← M[SP]; SP ← SP + 1`。
- 特点：**无显式地址码**（零地址指令），操作数在栈顶，硬件自动管理 SP。
- 用途：函数调用的参数、返回地址、局部变量（栈帧）；逆波兰表达式求值；JVM 虚拟机。

**核心概念：栈是「隐式寻址」的典型**——指令里没有地址码，但数据的位置由 SP 这个隐式指针决定。<span class="marginnote">函数调用为什么用栈？因为嵌套调用是「后进先出」：`f` 调 `g`，`g` 返回后 `f` 的局部数据必须原样恢复——栈的 LIFO 语义完美匹配。这就是《过程调用的机器级实现》一课的核心。</span>

## 5 公式解析：四种寻址的统一形式四种寻址可以统一写成「寄存器/PC + 位移」的框架：

$$\text{EA} = R_{\text{基准}} + \text{disp}$$

| 寻址方式 | 基准 $R_{\text{基准}}$ | 位移来源 | 典型指令 |
| --- | --- | --- | --- |
| 相对 | PC | 指令内 disp | 分支 |
| 基址 | 基址寄存器 | 指令内 disp | 重定位访问 |
| 变址 | 指令内地址（固定） | 变址寄存器 | 数组访问 |
| 堆栈 | SP | 0（隐式） | PUSH/POP |

逐项拆解：

- **第一步，统一**：大多数寻址都是「某个寄存器 + 某个位移」。
- **第二步，角色分工**：谁固定、谁可变，决定了它是基址还是变址。
- **第三步，隐式特例**：堆栈的基准是 SP、位移为 0，且地址码都不需要。

**核心结论：理解寻址方式的关键是分清「哪个是可变的、哪个是固定的」**——比背公式重要得多。<span class="marginnote">现代 ISA 把「基址 + 变址 × 比例 + 位移」融合进一条寻址（x86 的 `[base + index*scale + disp]`）——一个地址码字段同时提供基址寄存器、变址寄存器、比例、位移四个自由度。理解本课的单自由度版本，多自由度只是叠加。</span>

## 6 拓展：带偏移寻址速记**五条必记**：
- 相对：EA = PC + disp，可重定位，用于分支。
- 基址：EA = 基址寄存器 + disp，基点可变偏移固定，用于重定位。
- 变址：EA = 指令内地址 + 变址寄存器，基点固定变址可变，用于数组。
- 基址 vs 变址：谁可变谁固定互换——最高频考点。
- 堆栈：操作数在栈顶，SP 隐式管理，零地址。

**辨析｜易错点**：基址「基点可变、偏移固定」；变址「基点固定、变址可变」——记反就错。

## 7 一句话回顾- 相对看 PC、基址基点可变、变址变址可变。
- 基址 vs 变址：谁可变谁固定互换。
- 堆栈寻址隐式靠 SP。

## 8 小结- **相对寻址**：EA = PC + disp，代码可重定位，用于分支。
- **基址寻址**：EA = 基址寄存器 + disp，基点可变、偏移固定，用于重定位。
- **变址寻址**：EA = 指令内地址 + 变址寄存器，基点固定、变址可变，用于数组遍历。
- **基址 vs 变址**：谁可变谁固定互换——最高频考点。
- **堆栈寻址**：操作数在栈顶，SP 隐式管理，零地址指令。
- 统一框架：EA = 寄存器 + 位移，分清可变/固定即理解全部。
