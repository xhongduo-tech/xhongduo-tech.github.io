## 为什么从分类开始

「计算机」三个字盖住了太多长相完全不同的机器。口袋里那台每秒做几十亿次运算、几乎不发热的手机，机房里占满一整间屋子的超级计算机，汽车引擎盖下负责控制喷油的单片机，还有云端替你转存照片的服务器——它们都叫「计算机」，彼此的差别却比鲸鱼与海豚还大。<span class="marginnote">鲸鱼和海豚都是哺乳动物、都生活在海里，却走了完全不同的演化路线。计算机的分类也类似：同一个「冯·诺依曼内核」，在不同约束下长出了截然不同的形态。</span>

学组成原理为什么要先分一分类？因为**分类的本质，是「历史演化的横截面」**。上一篇讲过，每一代器件都在改变速度、体积、功耗、成本四种约束；而每一类计算机，恰是某一种约束组合下被「压」出来的最优解：超级计算机追求绝对性能，嵌入式芯片追求极低功耗，服务器追求长时间不停机。先认清这些约束，后面学存储器、学总线、学输入输出时，你才能理解「为什么这里要这样设计」。

## 1 两种主分类视角对计算机分类，教材通常给出两个坐标轴：一条看「用什么信号」，一条看「多大、多贵、干什么用」。

**按处理信号分类**：**模拟计算机（analog computer）**用连续物理量（电压、电流、转角）直接表示数值，运算在物理电路里瞬时发生；**数字计算机（digital computer）**用离散的符号（二进制位）表示数值；**数模混合计算机**两者兼用，只在个别特殊场合出现。

**按规模与用途分类**：从大到小大致有**巨型机（超级计算机）、大型机、小型机、微型机（个人计算机）、嵌入式系统**五档。「规模」在这里不单指体积，而是一个复合指标——运算速度、存储容量、可连接的外部设备数量、造价与可靠性要求。<span class="marginnote">「规模」是性能、价位、应用场景的综合体：一台大型机的体积可能还不如一台小型机大，但它的输入输出吞吐与可靠性远超后者，两者服务的对象完全不同。</span>

## 2 按规模与用途：从超级计算机到嵌入式| 类别 | 性能画像 | 典型应用 | 代表例子 |

| --- | --- | --- | --- |
| 巨型机 / 超级计算机 | 每秒百亿亿次浮点运算，造价数亿元，占地数十个机柜 | 气象预报、核物理模拟、密码破译、大模型训练 | 美国 Frontier、中国神威·太湖之光 |
| 大型机 | 极高的 I/O 吞吐与可靠性，支持海量并发事务 | 银行核心账务、航空订票、证券交易 | IBM z 系列 |
| 小型机 | 中端性能，面向部门级应用，曾盛极一时 | 企业部门计算、早期网络服务器 | DEC VAX、PDP-11 |
| 微型机 | 单用户、低功耗、普及率最高 | 个人办公、娱乐、软件开发 | PC、苹果 Mac、工作站 |
| 嵌入式系统 | 以应用为中心，软硬件可裁剪，专用，数量极其庞大 | 手机、路由器、家电、汽车 ECU、医疗设备 | ARM 芯片、单片机 |

这张表里还漏了两个常挂在嘴边的词：**服务器（server）**与**工作站（workstation）**。服务器本质是「为他人服务的高端主机」——常常不配显示器，7×24 小时运转，强调可靠性、多处理器与大存储；工作站则是面向专业图形与工程计算的高配微型机。它们不是独立的大类，而是「以用途命名的变体」，这点要心里有数。

读这张表，最有价值的不是背下每一档，而是看清一个规律：**从上到下，「通用性」递减，「专用性」与「出货量」递增**。超级计算机一台只解决一类重大问题；嵌入式芯片则藏身于我们身边几乎每一件电器里，人类每年消耗的处理器绝大多数属于它。<span class="marginnote">一台现代汽车里嵌着数十个甚至上百个单片机/微控制器，它们各自只干一件事：控制车窗、控制喷油、计算安全气囊触发的时机。这就是「嵌入式」——软件与硬件被牢牢绑定，几乎没有用户可改的余地。</span>

**辨析｜易错点：**分类的绝对指标会随时间「漂移」。今天一部手机的性能，已经超过 1990 年代的许多超级计算机；所谓「微型机」「大型机」的分界线，二三十年后早已改判。**分类的坐标会变，但「不同约束塑造不同机器」的思想不变**——学组成原理，学的是后者，不是那张会过时的分档表。

## 3 按处理信号：为什么「数字」赢了

模拟计算机的诱惑很实在：电压相加天然就是数值相加，电路直接把物理量「算」出来，速度快、不需要译码。可它有一个致命伤——**精度由元件决定**。电阻有误差、温度会漂移，模拟运算做到千分之一精度都很难，更不要说抗干扰；而且它很难通用编程，改一道题往往要改电路。

数字计算机则相反：数值被编码成一串 0 和 1，电路只需要可靠地区分「高电平 / 低电平」两个状态，剩下的精度全部交给**位数**去堆。<span class="marginnote">这就是数字化的本质：把「需要绝对精确的模拟量」翻译成「只需要二态判别的离散量」。抗噪声、可复制、可编程，三样占全，模拟计算机因此几乎绝迹于通用计算领域。</span>

**辨析｜易错点：**「数字计算机精度高」不是因为它不会出错，而是因为它**只犯二态错误，且错误可被检测与重算**。一位的判别只要可靠，再多位也只是「重复同一种可靠」；而模拟系统里每一位精度，都要靠昂贵的元件去「买」。

一个直觉例子：老工程师用过的**计算尺**就是一台微型模拟机——两段刻着对数刻度的尺子相错一推，「乘除」就被算了出来，快得惊人，可精度只能到两三位有效数字；而小学生用的数字计算器，答案精确到十位，代价只是按几个键。<span class="marginnote">计算尺靠「位移量」这种连续量做工，属于模拟计算；计算器把每个数字编成二进制再逐步相加，属于数字计算。速度与精度之争，从二战一直延续到今天。</span>数字方案之所以胜出，正是因为它把「贵在元件」换成了「贵在位数」，而后者的成本可以由半导体工艺不断摊薄。

数字计算机内部用**二进制**表示一切，这部分细节我们在第二篇《进位计数制及其相互转换》《无符号数与有符号数的机器表示》再系统展开；今天只需记住结论：**二态可靠，多态拼精度**。

## 3 发展趋势：四个方向与一条功耗墙把上一篇的四代历史与今天的分类叠在一起看，计算机的未来沿着几条主线推进：

**巨型化**：超级计算机的算力持续冲顶。从千万亿次（petaflops，$10^{15}$ 次浮点运算/秒）迈向百亿亿次（exaflops，$10^{18}$），支撑大模型训练、蛋白质结构预测这类「算力黑洞」。衡量浮点性能的单位逐级跳三位：

| 前缀 | 全称 | 每秒浮点运算次数 |
| --- | --- | --- |
| K | Kilo | $10^{3}$ |
| M | Mega | $10^{6}$ |
| G | Giga | $10^{9}$ |
| T | Tera | $10^{12}$ |
| P | Peta | $10^{15}$ |
| E | Exa | $10^{18}$ |
**微型化与嵌入式**：芯片越做越小、越做越省电，嵌入到每一个物体里——「物联网」的物理前提。
**网络化**：单机演变为「端—云」协同，算力在数据中心，终端只做采集与交互。<span class="marginnote">「从极限到大模型」里那些大模型的推理，今天大多跑在云端 GPU 集群上而不是你的手机里——网络化是这一切的地理前提。</span>
- **智能化**：通用 CPU 之外长出专用加速器——GPU、NPU、TPU，为神经网络运算定制数据通路。这将是《计算机体系结构》专题「领域专用架构」的主角。
- **多媒体化**：图形、音视频的实时处理从「能不能」变为「必然要」，反过来倒逼总线的带宽设计（第七篇《总线》）。

再往远处看，**量子计算、光计算、生物计算**也在实验室里缓慢生长。它们若成真，改变的将不只是「更快」，而是计算的基本模型本身——那是《计算机体系结构》专题最后要展望的地平线。但在它们成熟之前，一切仍以冯·诺依曼框架为圆心展开，这也是我们本专题的立足点。

但所有这些趋势，都撞在同一堵墙上——**功耗墙（power wall）**。它解释了为什么过去二十年我们不再单纯把 CPU 主频从 3 GHz 提到 30 GHz，而是改走「多核」路线。这正是下一节的公式要讲清的故事。

## 5 公式解析：$P = \alpha C V^2 f$，频率为什么撞上了墙

数字芯片的**动态功耗（dynamic power）**有一个教科书公式：

$$
P = \alpha C V^2 f
$$

拆成三步来读：

- **第一步，一次开关消耗多少能量**：CMOS 电路里，一个门每完成一次 0→1 或 1→0 的翻转，都要对负载电容 $C$ 充电或放电。电容储能公式是 $\tfrac{1}{2}CV^2$，一次完整翻转（充一次、放一次）合计消耗约 $C V^2$ 的能量。所以**每次翻转的能量与电压的平方成正比**——$V$ 从 1.2 V 降到 0.9 V，单次翻转的能量立刻省下约 $(1.2/0.9)^2 \approx 1.78$ 倍。
- **第二步，每秒翻转多少次**：时钟频率 $f$ 决定每秒的翻转次数；但并非每个晶体管每个周期都翻转，真正翻转的比例记作 $\alpha$（**活动因子 / 翻转因子，activity factor**）。于是「每次翻转的能量 × 每秒翻转的次数」就是
  $$
  P = \alpha \cdot (C V^2) \cdot f
  $$
- **第三步，直觉与推论**：提高频率 $f$ 只换来功耗的**线性**增长，而降低电压 $V$ 是**平方级**的收益——所以过去几十年工艺路线一直是「降电压 + 提频率」。但电压不能无限降（降到阈值附近晶体管就关不死了），于是频率也撞上了天花板：主频自 2004 年前后的 3–4 GHz 之后几乎不再上涨。<span class="marginnote">芯片功耗涨到一定程度，散热跟不上、温度失控，这就是「功耗墙」。频率撞墙后，性能增长只好「横向」展开——多核、多线程、异构并行，成为《计算机体系结构》专题一整章的起点。</span>

用一小段代码感受「降电压」的巨大收益——电压从 1.2 V 降到 0.9 V（主频不变），动态功耗几乎砍半：

```python
alpha, C, f = 0.5, 1e-9, 2e9       # α、C、f 取一组常数（功耗看相对变化）
p_12 = alpha * C * 1.2**2 * f      # V = 1.2 V 时的动态功耗
p_09 = alpha * C * 0.9**2 * f      # V = 0.9 V 时的动态功耗
print(f"{p_12:.3f} W")             # 1.440 W
print(f"{p_09:.3f} W")             # 0.810 W
print(f"{(0.9 / 1.2) ** 2:.3f}")   # 0.562，约降一半
```

运行结果是 `1.440 W`、`0.810 W`、`0.562`——电压每降 25%，功耗约降一半，这就是半导体工艺拼了命「降压」的原因；而功耗能降，频率才能稳，性能才敢继续往上推。

**辨析｜易错点：**$P = \alpha C V^2 f$ 只是**动态功耗**，不是全部功耗。漏电（静态功耗）在工艺缩小时同样急剧上升，两者合起来才构成一颗芯片真实的热负荷。只记公式、忽略漏电，会误以为「功耗只跟频率和电压有关」。

## 4 一句话回顾- 按规模/能力：巨型、大型、中型、小型、微型。
- 按用途：通用 vs 专用。
- 现代趋势：微型化、网络化、智能化、高性能并行。

## 5 小结- 计算机有两个主分类坐标：**按处理信号**（模拟 / 数字 / 混合）与**按规模用途**（超级计算机 → 大型机 → 小型机 → 微型机 → 嵌入式）。
- 分类的绝对指标会随时间漂移，但**「不同约束塑造不同机器」**的思想稳定不变。
- **数字计算机**以二态判别换精度，把误差从「模拟量的昂贵精确」换成「离散位的可靠重复」。
- 发展趋势可概括为**巨型化、微型化、网络化、智能化、多媒体化**，共同的技术瓶颈是**功耗墙**。
- 动态功耗 $P = \alpha C V^2 f$：频率只线性推高功耗，电压却是平方级杠杆；电压触底后频率撞墙，于是多核成为必然。

- 按规模：巨型到微型
- 按用途：通用/专用
- 发展趋势：微型化/网络化/智能化
- 功耗墙限制单核
- 基准程序区分性能
- 分类维度看信号与规模
- 多核并行是趋势
- 嵌入式专用化
