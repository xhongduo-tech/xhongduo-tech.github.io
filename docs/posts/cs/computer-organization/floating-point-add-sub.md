## 为什么浮点加法要走四步

定点加减一个加法器搞定，浮点加减却要经历完整的四步：**对阶 → 尾数求和 → 规格化 → 舍入**。原因是浮点数的尾数与阶码是「打包」在一起的，两个阶码不同的数不能直接相加——就像 $\times10^2$ 与 $\times10^5$ 的两个数，必须先化成同阶再对尾数相加。这一课把四步拆开，每一步都藏着经典错误。<span class="marginnote">浮点加法是数值计算里最频繁的操作，也是误差的主要来源之一。理解了这四步，你就看懂了为什么 `0.1+0.2` 会等于 `0.30000000000000004`。</span>

## 1 第一步：对阶**对阶（alignment）**：把两个操作数的阶码变成相同，规则是「**小阶向大阶看齐**」。

- 比较两个数的阶码，取较大的阶码为共同阶码。
- 阶码小的数，尾数右移「阶差」位，每右移一位相当于阶码加一，保持数值不变。

例：$1.5 \times 2^2 + 1.25 \times 2^5$，阶差 3，前者尾数右移 3 位：

$$1.5 \times 2^2 \;\to\; 0.1875 \times 2^5$$

**为什么是小阶向大阶**：小阶数尾数右移会丢低位（损失精度），而大阶数尾数若左移会溢出（灾难性）。两害相权，右移丢低位是可控的。<span class="marginnote">「小阶向大阶看齐」是铁律。若反过来把大阶往小阶对齐，尾数左移会直接溢出——这是对阶步骤里最典型的错误。</span>

## 2 第二步：尾数求和与第三步：规格化尾数按补码/原码相加后，结果可能不满足规格化条件，需要**规格化（normalization）**：

- **左规**：尾数最高位为 0（如 `0.01...`），则尾数左移、阶码减 1，直到最高位为 1。可能多次左移。
- **右规**：尾数溢出到符号位（两个同号数相加产生 `10.xxx` 或 `01.xxx`），则尾数右移一位、阶码加 1，最多右规一次。

例：$1.25 \times 2^2 + 1.5 \times 2^2 = 2.75 \times 2^2 = 1.375 \times 2^3$——尾数 $2.75$ 超出 $[1,2)$，右规一次得 $1.375 \times 2^3$。<span class="marginnote">右规只可能发生一次，因为两个同号规格化尾数相加最大接近 2（刚好溢出到 2 倍）；左规则可能连续多次（如 $0.03125\times2^k$ 要左规 5 次）。</span>

## 3 第四步：舍入规格化后尾数可能超出可用的位数，多出的低位必须处理——这就是**舍入（rounding）**。IEEE 754 定义了四种舍入模式：

| 舍入模式 | 规则 | 特点 |
| --- | --- | --- |
| 就近舍入（默认） | 舍入到最近的可表示数，恰在中间时取偶 | 误差有界且对称 |
| 向 +∞ | 总是向上取 | 有偏 |
| 向 -∞ | 总是向下取 | 有偏 |
| 向 0（截断） | 直接丢弃低位 | 最简单，误差最大 |

**就近舍入的「中间取偶」**：当被丢弃的位正好是一半（如二进制 `...1000`），取能使末位为偶数的那个候选——这避免了「总是向上」带来的系统性正偏。<span class="marginnote">「中间取偶」也叫银行家舍入。十进制里 $1.5$ 舍入到 $2$，$2.5$ 舍入到 $2$（因为 2 是偶数）。这比「四舍五入」在统计上更公平，但初学时常被忽略，是考试区分点。</span>

## 4 公式解析：0.1 + 0.2 为什么是 0.30000000000000004

这是最著名的浮点例子，用双精度逐步看：

$$0.1 + 0.2 = 0.30000000000000004$$

逐项拆解：

- **第一步，表示误差**：$0.1$ 与 $0.2$ 都是无限二进制小数（见《进位计数制》一课的 $0.6$ 例子），双精度把它们各自舍入到 53 位有效数字，各有约 $10^{-17}$ 的表示误差。
- **第二步，相加**：两个含误差的数相加，误差叠加。对阶时 $0.1$ 与 $0.2$ 阶码相同（都是 $2^{-4}$ 附近），无需大移位。
- **第三步，舍入放大**：和 $0.30000000000000004...$ 又经过一次就近舍入，恰好多出一个最低位的 1，于是打印出来就是那个著名的 `04`。

**结论**：这不是 bug，而是「有限精度表示 + 每次运算舍入」的必然。程序里比较浮点应该用阈值：`fabs(a-b) < 1e-9`。<span class="marginnote">为什么金融计算不能用浮点？因为 $0.1$ 的误差会在千万笔交易上累积。金融用十进制定点（BCD/`Decimal`），牺牲速度换精确。这与第二篇《字符与字符串的表示》的 BCD 码直接相关。</span>

## 4 浮点加减的溢出与下溢- **上溢（overflow）**：阶码超出最大真值指数，结果变为 $\pm\infty$。规格化后要检查阶码是否全 1。
- **下溢（underflow）**：结果小于最小规格化数，进入非规格化范围（逐渐下溢），进一步缩小则归零。
- **阶码下溢**：左规次数太多导致阶码减到全 0，需要特殊处理（下溢到非规格化或 0）。

**辨析｜易错点：**浮点的上溢/下溢与定点的溢出不同：浮点溢出是「阶码越界」，表现为变成 $\infty$ 或 0，不产生异常（除非显式开启陷阱）；定点溢出是「数值位越界」，表现为符号翻转。两者的「溢出」是两套机制。

## 5 拓展：浮点加法的一个完整算例把四步流程走一遍。用 8 位浮点格式（1 符号 + 4 阶码 + 3 尾数，偏置 7）计算 $1.5 + 0.75$。

- 表示：$1.5 = 1.1_2 \times 2^0$，阶码真值 0 → 编码 `0111`，尾数 `100`；$0.75 = 1.1_2 \times 2^{-1}$，阶码真值 -1 → 编码 `0110`。
- **对阶**：小阶向大阶，$0.75$ 尾数右移一位：$1.1 \times 2^{-1} \to 0.11 \times 2^0$，3 位尾数变为 `011`（低位 `1` 被丢弃）。
- **求和**：$1.100 + 0.011 = 1.111$，在 $[1,2)$ 内，无需右规。
- **结果**：$1.111_2 \times 2^0 = 1.875$——而精确值是 $2.25$，误差来自对阶时 $0.75$ 丢掉的低位。

这个例子揭示：**对阶的右移是精度损失的主要来源**——尾数位越多、阶差越大，损失越可控。这也是为什么「先加小再加大」能把误差控制住（小阶差触发少右移）。

**辨析｜易错点：**「小阶向大阶看齐」为什么不能反过来？因为大阶数尾数左移会**溢出**到符号位，直接灾难；右移只丢低位，可控。

## 6 考点速记：浮点加减四步歌**对阶**（小阶向大阶）→ **求和**（尾数相加）→ **规格化**（左规/右规）→ **舍入**（就近取偶）。

**五条必记**：
- 对阶丢低位可控，反向对阶会溢出——铁律。
- 右规最多一次（同号相加最大 <2），左规可能多次。
- 就近舍入 ties-to-even：恰在中间取偶，统计无偏。
- 0.1+0.2 的 04 来自「表示误差 + 运算舍入」累积，非 bug。
- 浮点溢出 = 阶码越界（变 ∞/0），定点溢出 = 数值位越界（符号翻转）——两套机制。

**辨析｜易错点**：舍入发生在规格化之后——先规格化（定阶）再舍入（定尾数），顺序别反。

## 7 一句话回顾- 对阶 → 求和 → 规格化 → 舍入，四步缺一不可。
- 对阶丢低位可控、反向会溢出。
- 0.1+0.2 的误差是表示+舍入的累积，非 bug。

> 记住：对阶丢低位可控，反向对阶会溢出。

## 8 小结- 浮点加减四步：**对阶（小阶向大阶）→ 尾数求和 → 规格化（左规/右规）→ 舍入**。
- **对阶**丢低位是可控损失；反方向对阶会溢出。
- **右规**最多一次，**左规**可能多次。
- IEEE 754 舍入四模式，默认**就近舍入（中间取偶）**。
- `0.1+0.2` 的误差来自表示误差 + 运算舍入的累积，是浮点的本质而非 bug。
