## 为什么汇编与机器码是「同一种东西」

机器指令是二进制，人没法读；汇编指令是助记符，人能读——**两者一一对应**。汇编器做的是「查表翻译」：助记符 → 某个操作码、寄存器名 → 某个寄存器号。理解这种对应，你就能用 objdump 读任意二进制、理解反汇编、看懂 ELF 文件里的字节码。本课讲汇编指令与机器码的映射关系、指令编码的字段、以及如何阅读一条指令的机器码。<span class="marginnote">这条「对应」的链条：C 源码 → 编译器 → 汇编（.s）→ 汇编器 → 机器码（.o）。汇编是人类与机器码之间最后的「友好界面」——再往下就是纯比特了。回顾《编译、汇编、链接与装载》一课。</span>

## 1 汇编指令的结构一条汇编指令的典型形式：

```asm
loop_start:      ; 标号（label）
    addl %ebx, %eax   ; 助记符 + 操作数
```

**标号（label）**：符号地址，汇编时换算成地址。
**助记符（mnemonic）**：如 addl、movl，对应操作码。
**操作数**：寄存器（%eax）、立即数（$8）、内存（(%ebx)）。
**注释**：以 ; 或 # 开头，汇编器忽略。

**核心概念：汇编指令 = 机器指令的「可读形式」**——每条汇编指令对应一条（或一簇）机器指令，汇编器负责翻译。<span class="marginnote">为什么用汇编而不是直接写机器码？助记符让指令意图可读、操作数写法统一、标号让地址管理自动化——汇编器承担了「编号、算偏移、查操作码」的琐碎工作。这是「符号化」的第一次胜利。</span>

## 2 机器指令的编码：字段与格式机器指令的二进制由几个字段组成：

$$\text{机器指令} = \text{操作码} \parallel \text{寻址方式/寄存器} \parallel \text{立即数/偏移}$$

以 x86 的 `addl %ebx, %eax` 为例，机器码可能是：

```
01 D8
```

- 操作码 01 表示「add 寄存器到寄存器」。
- 后一个字节 D8 拆成 ModRM 字段：11（寄存器寻址）、011（%ebx）、000（%eax）。<span class="marginnote">x86 的机器码格式：前缀（可选）+ 操作码 + ModRM（寻址）+ SIB（可选）+ 位移 + 立即数。ModRM 字节是 x86 解码的核心：3 位 reg + 3 位 rm + 2 位 mod 组合出操作数与寻址方式。读懂 ModRM，是反汇编 x86 的关键。</span>

## 3 从汇编到机器码：汇编器的工作汇编器把汇编翻译成机器码，主要做四件事：

1. **查操作码表**：助记符 → 操作码。
2. **编码操作数**：寄存器号、立即数、寻址方式 → 字段位。
3. **解析标号**：把符号地址换算成偏移（相对寻址的 disp）。
4. **生成目标文件**：机器码 + 符号表 + 重定位信息（见《编译汇编链接装载》）。

```
addl %ebx, %eax      →  01 D8           ; 寄存器寻址，2 字节
addl $0x100, %eax    →  05 00 01 00 00  ; 32 位立即数，5 字节
```

**重点：一条汇编指令翻译后的字节数取决于操作数与寻址方式**——立即数 32 位占 4 字节、寄存器寻址占 2 字节……这是 x86 变长指令的微观来源。<span class="marginnote">RISC 的汇编翻译更「规整」：每条指令固定 4 字节，字段位置固定（opcode、rs、rt、rd、imm 各占固定位）。对照 x86 的 ModRM 灵活编码，正是一课《RISC 与 CISC》的微观体现。</span>

## 4 公式解析：相对偏移的编码分支指令的目标地址用相对偏移编码：

$$\text{disp} = \text{目标地址} - (\text{当前指令地址} + \text{指令长度})$$

例：jmp 指令在地址 0x1000，占 2 字节，目标是 0x1010：

$$\text{disp} = 0x1010 - (0x1000 + 2) = 0xE$$

机器码：EB 0E（EB 是短跳转操作码，0E 是位移）。

逐项拆解：

- **第一步，基准**：偏移相对「下一条指令地址」（x86 约定），即当前地址 + 指令长度。
- **第二步，求差**：目标减基准得位移。
- **第三步，编码**：位移写入指令的偏移字段（有符号）。

**核心结论：汇编里的标号在机器码里是「操作码 + 偏移」**——标号最终被换算成一个有符号位移，这就是链接器与汇编器处理的「重定位」内容。<span class="marginnote">用 objdump 看反汇编时，你会看到 jmp 旁边的机器码 eb 0e——汇编器把「目标地址」显示出来，但机器码里只有「相对偏移」。理解这一点，你才真正读懂反汇编输出。</span>

## 5 辨析｜易错点：汇编与机器码的对应**辨析｜易错点：**

- **汇编 ≠ 机器码**：汇编是文本、可移植性差但可读；机器码是二进制、不可移植。汇编器做翻译。
- **一条汇编可能对应多条机器指令**：宏指令（如 MASM 的 INVOKE）会展开成多条机器指令。
- **机器码不可移植**：同一汇编在不同 ISA 上是不同机器码；同一 ISA 也可能因指令版本不同编码不同。
- **「反汇编」不一定能还原原汇编**：同一机器码可能对应多种写法（如 nop 与 xchg %eax, %eax 效果相同），反汇编只给一种——信息有损。

## 6 考点速记：汇编与机器码对应**一**：汇编 = 标号 + 助记符 + 操作数，与机器指令一一对应。

**二**：机器指令字段 = 操作码 + 寻址/寄存器 + 立即数/偏移。

**三**：汇编器四件事——查操作码、编码操作数、解析标号、生成目标文件。

**四**：相对偏移 disp = 目标 - (当前地址 + 指令长度)。

**五**：反汇编有损——同一机器码可能对应多种汇编写法。

**五条必记**：
- x86 的 ModRM 字节（mod/reg/rm）是解码核心。
- jmp 机器码里存的是相对偏移 eb 0e，不是目标地址。
- RISC 定长 4 字节规整编码 vs x86 变长 ModRM。
- 标号在汇编时换算成偏移——链接器的重定位内容。
- 宏指令可能展开成多条机器指令。

**辨析｜易错点**：一条汇编可能对应多条机器指令；机器码不可移植。

- 自测 1：objdump 显示的目标地址为什么是算出来的？
- 自测 2：ModRM 管什么？
- 自测 3：为什么反汇编不能完全还原源码？

> 一句话：汇编与机器码一一对应，汇编器查表翻译。

## 7 小结- 汇编指令 = 标号 + 助记符 + 操作数 + 注释，与机器指令一一对应。
- 机器指令字段：操作码 + 寻址/寄存器（如 x86 ModRM）+ 立即数/偏移。
- 汇编器四件事：查操作码、编码操作数、解析标号、生成目标文件。
- 相对偏移：disp = 目标 − (当前地址 + 指令长度)。
- RISC 定长 4 字节规整编码 vs x86 变长 ModRM 灵活编码。

- 汇编与机器码一一对应
- 操作码+ModRM+位移+立即数
- 汇编器查表翻译
- 标号换算成偏移
- 反汇编有损
- RISC 定长规整、x86 变长 ModRM
- jmp 机器码存相对偏移
- 宏指令展开多条
