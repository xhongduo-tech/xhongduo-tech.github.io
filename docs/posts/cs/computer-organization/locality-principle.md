## 为什么「局部性」是缓存一切的理由

上一课说层次结构靠「命中率」活着，但命中率凭什么高？答案是**局部性（locality）**：程序在时间上只反复访问一小部分数据，在空间上只访问一小片地址。这不是巧合，而是人类编写程序的必然——循环、函数、顺序执行、数组遍历塑造了局部性。本课把局部性拆成时间与空间两半，用具体的代码例子说明「写缓存友好的程序」，并量化「糟糕的局部性能让程序慢 10 倍」的代价。<span class="marginnote">局部性是「计算机性能的第一定律」：一切缓存、预取、TLB、流水线优化的有效性都建立在它之上。理解了局部性，你就理解了为什么「同样的算法，不同的数据布局」性能天差地别。</span>

## 1 两种局部性**核心概念：时间局部性（temporal locality）**：刚被访问的存储单元，很可能在不久的将来被再次访问。

循环体反复执行 → 循环体指令、循环变量被反复访问。
变量在短时间窗口内被反复读写。

**核心概念：空间局部性（spatial locality）**：刚被访问的存储单元附近的单元，很可能在不久的将来被访问。

顺序执行的指令在内存里相邻。
数组元素按顺序遍历，访问 a[0] 后紧接 a[1]。

举例对比：

```c
// 空间局部性好：顺序访问，一个缓存行（64B，约 16 个 int）被用满
int s1 = 0;
for (int i = 0; i < n; i++)
    s1 += a[i];

// 空间局部性差：隔一个取一个（第 0、2、4…个元素），每行只用一半
int s2 = 0;
for (int i = 0; i < n; i += 2)
    s2 += a[i];
```
<span class="marginnote">访问一个数组元素时，Cache 通常一次取「一整行」（如 64 字节，含 16 个 int）。如果代码只跳着取第 0、2、4 个元素，每个缓存行只用一半——空间局部性差，命中率降一半。</span>

## 2 为什么指令也有局部性

局部性不只作用于数据，**指令同样有**：

顺序执行：指令按地址顺序取指 → 空间局部性。
循环与函数调用：一小段指令被反复执行 → 时间局部性。
**分支（if/switch）**：程序流跳转打破空间局部性，但分支两端的指令块各自保持局部性。

**重点：指令与数据是两套访问流，局部性各有各的来源**。这直接解释了为什么 CPU 要分开「指令 Cache」与「数据 Cache」——它们的局部性模式不同，分开缓存命中率更高（本专题有专课）。<span class="marginnote">指令流的局部性如此之强，以至于「循环」可以完全驻留在 L1 指令缓存里；而数据流则取决于数据结构布局。性能优化里「让热循环贴在一起、别插太多不相关代码」正是为了指令局部性。</span>

## 2 局部性如何被层次结构利用局部性在层次结构的每一层都被「翻译」成机制：

| 局部性 | 利用机制 | 效果 |
| --- | --- | --- |
| 时间局部性 | Cache 保留近期访问的块（替换算法倾向保留） | 反复访问命中 |
| 空间局部性 | 一次取一整块（缓存行/页） | 相邻访问命中 |
| 空间局部性 | 硬件预取器提前取后续块 | 隐藏缺失延迟 |
| 时间局部性 | 虚拟内存的常驻集管理 | 减少缺页 |

**Cache 用「块（block）/行（line）」为单位搬运数据**：一次取 64 字节，就是为空间局部性「押注」——赌相邻数据很快会被用上。<span class="marginnote">「按块搬运」是层次结构的通用策略：Cache 按行取主存、主存按页取磁盘、磁盘按扇区取。块的大小是「空间局部性的赌注大小」——太大浪费带宽、太小浪费局部性。</span>

## 3 公式解析：二维数组的两种遍历局部性最经典的考题是二维数组的两种遍历顺序。设二维数组 $A[M][N]$ 按行主序存储：

```c
// 方式一：行主序，内层 j 连续 —— 空间局部性好
for (int i = 0; i < M; i++)
    for (int j = 0; j < N; j++)
        sum += A[i][j];          // 地址连续递增，整行命中缓存

// 方式二：列主序，内层 i 跨行 —— 空间局部性差
for (int j = 0; j < N; j++)
    for (int i = 0; i < M; i++)
        sum += A[i][j];          // 每次跨一整行，缓存行只用 1 个元素
```

逐项拆解：

**第一步，内存布局**：C 的二维数组按行主序，$A[i][j]$ 与 $A[i][j+1]$ 在内存里相邻。
**第二步，方式一**：内层循环 j 递增，访问的地址连续递增——每个缓存行取来后 16 个元素依次命中，空间局部性满分。
**第三步，方式二**：内层循环 i 递增，跨行跳着访问——每个缓存行只用 1 个元素，其余 15 个浪费，空间局部性崩坏。
**第四步，量化**：若缓存行 64 字节（16 个 int），方式二的有效带宽只有方式一的 $1/16$。

**结论：同样是 $M\times N$ 次求和，方式一比方式二快近一个数量级**。这就是「数据布局决定性能」的最经典演示。<span class="marginnote">NumPy/PyTorch 里张量默认行主序（row-major），深度学习写自定义算子时必须按行主序访问张量，否则访存带宽直接崩盘。这条经验在《高性能计算》专题里被反复强调。</span>

## 4 辨析｜易错点：如何写「局部性友好」的程序**辨析｜易错点：**

**别把所有优化都归因局部性**：编译器优化（循环展开、分块）很多是为了增强局部性，但有些是并行——区分开，别混。
**「局部性差」不等于「错」**：矩阵转置、稀疏数据天然局部性差，需要用「分块（blocking/tiling）」技术改善。
**分块技术**：把大循环切成小方块，让每个小块的数据在 Cache 里被完全用掉再换下一块——这是数值计算与深度学习的核心优化。<span class="marginnote">循环分块（loop tiling）是 GEMM（通用矩阵乘）优化的第一步：把大矩阵切成 8×8 或 16×16 的小块，让每个小块能驻留 L1 Cache，反复重用。没有分块的 GEMM 会因为「每次都要从内存取」而慢 10 倍。通往第四级《AI 基础设施》的矩阵乘优化。</span>

## 5 补充：局部性速记- 时间局部性：刚访问的很快再访问（循环、变量重用）。
- 空间局部性：附近的数据很快被访问（数组连续、顺序执行）。
- 指令也有局部性：顺序执行 + 循环。
- 二维数组按列遍历比按行慢近一个数量级——布局即性能。
- 分块（tiling）技术改善差局部性，是 GEMM 优化第一步。

## 6 一句话回顾- 局部性 = 程序访问集中在「一小段时间的一小片地址」。
- 时间局部性靠循环、空间局部性靠连续布局。
- 数据布局即性能——按列遍历二维数组慢近一个数量级。

## 7 一句话回顾- 时间局部性靠循环、空间局部性靠连续布局。
- 数据布局即性能。
- 分块技术改善差局部性。

## 8 小结- **时间局部性**：刚访问的数据很快再访问——靠循环、变量重用。
- **空间局部性**：附近的数据很快被访问——靠顺序执行、数组连续布局。
- 指令也有局部性：顺序执行与循环让取指高度局部化。
- 层次结构用「按块搬运」利用空间局部性，用「保留近期块」利用时间局部性。
- 二维数组按列遍历比按行遍历慢近一个数量级——数据布局即性能。

- 时间局部性靠循环、空间局部性靠连续布局

- 工作集决定上层容量需求
- 局部性是缓存的根基
