## 为什么从「存储程序」开始

上一篇把计算机分成了好几类，但它们其实共享同一个内核。这个内核由冯·诺依曼在 1945 年的《EDVAC 报告草案》里定型：**把程序像数据一样存进存储器，机器按地址自动取指令、执行**。到今天，几乎一切通用计算机——从超级计算机到手机里的处理器——都仍在这个框架里。

为什么这个思想如此之重？因为它回答了计算机史上最根本的问题：**一台机器怎样才能「通用」？** ENIAC 解一道题要重新接线，改程序是物理劳动；而一旦程序可以像数据一样被存起来、被读出来、被执行，「换程序」就退化成「换存储内容」——一台硬件不变的机器，可以完成无限多种任务。这正是「通用图灵机」的工程实现，也是第一篇《计算机的产生与发展》里「程序 = 数据」那句话的落点。

冯·诺依曼本人是 20 世纪罕见的通才——他 8 岁学会微积分，在博弈论、量子力学、计算机科学多个领域留下名字。1944 年他偶然得知 ENIAC 计划，立刻意识到「外插程序」路线的天花板，随即在 EDVAC 报告中把图灵的理论蓝图落成可制造的工程结构。今天我们纪念的，与其说是某台具体的机器，不如说是「通用可编程」这个思想本身。

## 1 存储程序：把程序变成数据**存储程序（stored-program）思想**：计算机工作时，把预先编制好的程序与数据一起存放进存储器；运行时，控制器按地址顺序取出每一条指令，译码并执行。<span class="marginnote">「程序 = 数据」是现代计算最深刻的元假设：正因为程序是数据，程序才能被别的程序处理——编译器、解释器、操作系统乃至今天的 AI 写代码，全都建立在这个假设之上。</span>

要体会它的分量，可以和「外插程序」的机器对比：ENIAC 用插接板和开关把程序「接」进机器，改一次程序要数小时到数天；而存储程序的机器改程序，只是把存储器里的内容换掉，再按一下启动。**差别不在速度，而在「程序能否被机器当作数据来读写」**——后者让「改程序」从体力活变成了换数据。

举例：同一台存储程序机器，今天存储体里放着一套记账程序，明天换上一套游戏程序，硬件纹丝不动，只是存储单元里的二进制内容变了。这种「**硬件固定、软件可换**」的优雅，正是通用计算机的定义；而「软件可换」之所以可能，前提就是程序以数据的形式存放在存储器里。

## 2 冯·诺依曼结构的五大特点教材把冯·诺依曼结构概括为以下几个基本特点（不同教材列法略有出入，精神一致）：1. 计算机由**运算器、控制器、存储器、输入设备、输出设备**五大部件组成；
2. **指令和数据以同等地位存放于存储器中**，并可按地址寻访；
3. 指令和数据均用**二进制**表示；
4. 指令由**操作码（opcode）**与**地址码（address）**两部分组成；
5. **存储程序控制**：机器自动逐条取指、译码、执行，无需人工干预。

前四条是「结构」，第五条是「行为」——它们合起来回答了一件事：**一台由开关电路搭成的机器，凭什么能自己「跑」完一段程序。**<span class="marginnote">这五条里，第 1 条与第 5 条常被当作「存储程序」的近义词。严格说，第 1 条是结构骨架，第 5 条才是「存储程序控制」的行为内核——正如上一篇《计算机的产生与发展》末尾所辨析的，思想与结构是两个层次。</span>

拿一台 8 位字长的假想机举例，一条指令可能长这样：`0001 0110`。前四位 `0001` 是**操作码**（代表 LDA，取数），后四位 `0110` 是**地址码**（代表 6 号单元）。机器一读到它，就知道「把 6 号单元里的数取到累加器」。操作码与地址码各占几位，直接决定了这台机器最多能支持几种指令、能编到多大的地址空间——这正是第四篇《操作码扩展技术与指令格式设计》的伏笔。

从这里也能提前看到一条规律：**操作码的种类数上限是 $2^{op}$（$op$ 为操作码位数）**——4 位操作码最多表达 16 种操作，8 位就是 256 种。所以指令设计的第一步，往往是先数清「这台机器到底需要多少种操作」，再去定操作码的宽度。这个「位数换种类」的权衡，会贯穿整个第四篇。

## 3 五大部件：一张结构图把五大部件画在一张图里，是理解冯·诺依曼结构最快的方式：![冯·诺依曼结构：五大部件与连接](/images/computer-organization/von-neumann-1.svg)

图上要点：**运算器**负责算术与逻辑运算；**控制器**是发号施令的指挥官；**存储器**存放程序与数据；**输入设备**把外部信息送进机器；**输出设备**把结果交还人类。其中运算器与控制器合称 **CPU（中央处理器，Central Processing Unit）**，CPU 与主存合称**主机**，输入输出设备统称**外部设备（外设）**。<span class="marginnote">「主机 = CPU + 主存」这个划分在教材里几乎固定出现：外设通过 I/O 接口与主机打交道，I/O 接口是我们到第八篇《I/O 接口的功能、组成与类型》才展开的桥。</span>

图里两条通路要分清：**青色的箭头是数据 / 指令通路**（信息在哪两个部件之间流动），**红色的箭头是控制信号**（控制器指挥谁、谁必须在什么时候做什么）。计算机的全部运行，就是这两类信号在五大部件之间的往复。

把五大部件各自的一句话职责放进一张表，就是这篇内容的最短笔记：

| 部件 | 一句话职责 |
| --- | --- |
| 运算器 | 算：做算术与逻辑运算 |
| 控制器 | 指挥：取指令、发控制信号 |
| 存储器 | 记：存放程序与数据 |
| 输入设备 | 送：把外部信息送进机器 |
| 输出设备 | 交：把结果交还外部世界 |

这张表还可以进一步压缩成六个字：**算、指挥、记、送、交**。后文每一篇解剖某个部件的文章，本质上都是把这六个字展开成具体的电路与数据通路——这是全专题的总纲。<span class="marginnote">复习时可以从这六个字反推：每个字背后藏着哪些寄存器、哪些通路、哪些控制信号。</span>

还需要特别强调一对概念：**控制流**与**数据流**。**控制流**是控制器发出的「何时、谁、做什么」的命令，像乐队的指挥棒；**数据流**是数据本身在部件之间的搬移，像流动的音符。两者沿不同路径传播、由不同信号承载——分清它们，是读懂一切组成原理图的第一步。我们会在第五篇《指令周期的数据流分析》里反复用到这对词。

最后留一个悬念：五大部件加上存储程序，只定义了「机器长什么样」，还没回答「机器听得懂哪几种话」——后者是**指令系统（第四篇）**的主题。而指令系统恰恰是硬件与软件的接口：操作系统与编译器都只认到指令集这一层。从下一篇起，我们先看硬件怎么组成，再看指令怎么设计。

## 4 冯·诺依曼瓶颈：通用性的代价存储程序让机器通用，但也埋下一个隐患：**指令和数据共用同一条存储器通路**——同一时刻，存储器要么给指令用，要么给数据用，不能同时。这就是著名的**冯·诺依曼瓶颈（von Neumann bottleneck）**：CPU 速度再快，也常要停下来等存储器「喂」指令和数据，访存成为吞吐的咽喉。<span class="marginnote">今天「存储器」早已不是单一的一块：寄存器、Cache、主存、辅存构成层次结构，正是为了在「靠近 CPU 的高速小容量」与「远离 CPU 的慢速大容量」之间取平衡。这段我们到第三篇《存储器层次结构》系统展开。</span>

**辨析｜易错点：**「冯·诺依曼结构」与「哈佛结构」是两条对立路线。哈佛结构把**指令存储与数据存储分开**，各用各的通路，CPU 可以同时取指令与取数据，从而缓解瓶颈——数字信号处理器（DSP）与许多单片机采用它；代价是结构更复杂、存储资源无法灵活调配。现代芯片常是「混合体」：指令 Cache 与数据 Cache 分离（属于哈佛思想），底层主存统一编址（仍属冯·诺依曼）。**记住：冯·诺依曼结构是「一条通路、统一存储」的典型，哈佛结构是「两路并行、分离存储」的改良。**对比如下：

| 维度 | 冯·诺依曼结构 | 哈佛结构 |
| --- | --- | --- |
| 指令与数据的存储 | 统一存放 | 分离存放 |
| 访存通路 | 一条（共享） | 两条（并行） |
| 能否同时取指令与取数 | 不能 | 能 |
| 典型应用 | 通用计算机 | DSP、部分单片机 |

<span class="marginnote">哈佛结构也并非铁板一块：DSP 内部常有多条并行总线，具体细节因芯片而异，这里只取「分离 vs 统一」这条主干。</span>

回到现实：现代 CPU 缓解冯·诺依曼瓶颈的手段，除了「指令 Cache 与数据 Cache 分离」这一结构上的哈佛化，还有时间上的**指令流水线**——让取指、译码、执行像工厂流水线一样重叠进行。流水线是第六篇《指令流水线的基本概念与流水段划分》的主角；届时你会发现，瓶颈并没有消失，只是被「叠起来」利用了。

## 5 公式解析：$N = 2^n$，地址线决定存储器能编多少个单元「指令和数据按地址寻访」这句话里藏着一个极有用的公式。设存储器的**地址线有 $n$ 根**，每根地址线可传输一位二进制地址，则共能编码 $2^n$ 种地址，即可寻址的存储单元个数为：

$$
N = 2^n
$$

拆成三步：

- **第一步，一根地址线能区分几件事**：一根地址线只有 0 / 1 两种取值，所以只能「指认」2 个存储单元。若 $n = 1$，可寻址 $2^1 = 2$ 个单元。
- **第二步，n 根线排列组合**：每根线各取 0 或 1，$n$ 根线共有 $2 \times 2 \times \cdots \times 2 = 2^n$ 种组合，每种组合对应一个地址。所以地址线每加 1 根，可寻址空间**翻一倍**。
- **第三步，直觉**：地址位数与寻址空间是指数关系——16 根地址线可寻址 64 KB，20 根是 1 MB，32 根是 4 GB。<span class="marginnote">今天的 64 位机器理论上可寻址 $2^{64}$ 字节，约 180 亿 GB，物理上远用不完；地址位数与「字长」的关系、为何不干脆全部用作地址，是《计算机体系结构》里地址空间与内存管理的起点。</span>

以 Intel 8086 为例：它有 20 根地址线，可寻址 $2^{20} = 1\ \text{MB}$——这就是「8086 只能访问 1 MB 内存」这句老话的来历；后来的 80386 把地址线加到 32 根，一下子跳到 4 GB。**每一代 CPU 的「内存天花板」，本质都是地址线根数决定的 $2^n$。**

再提醒一句衔接：$N = 2^n$ 给出的是**可寻址的单元个数**；若每个单元只存 1 字节，地址空间就是 $2^n$ 字节。而主存的实际容量还取决于每个单元的位数——下一篇《计算机的基本组成》会把两者合并成完整的容量公式 $C = 2^m \times w$。

这个公式在下一篇讲主存组成时会以更完整的面貌出现（存储容量 = 存储单元个数 × 存储字长），这里先抓住最核心的那条指数关系。

## 6 补充：冯·诺依曼速记- 五大部件：运算器、控制器、存储器、输入、输出。
- 存储程序思想：程序与数据同存，指令顺序执行。
- 工作方式：取指-译码-执行的存储程序循环。
- 瓶颈：取指与取数共用一条总线（冯·诺依曼瓶颈）。
- 现代 CPU 用 I/D 分离、多级缓存缓解瓶颈。

## 7 核心要点
- 五大部件：运算器、控制器、存储器、输入、输出。
- 存储程序 + 程序控制。
- 指令与数据同存，顺序执行。
- 瓶颈：取指取数共用总线。

## 8 小结- **存储程序思想**：程序与数据同存于存储器，机器按地址自动取指执行；「程序 = 数据」使机器获得通用性。
- 冯·诺依曼结构五大特点：**五大部件、指令与数据同存且按地址寻访、二进制表示、指令 = 操作码 + 地址码、存储程序控制**。
- 五大部件中，**运算器 + 控制器 = CPU**，CPU + 主存 = 主机，输入输出 = 外设；CPU 内部 PC、IR、MAR、MDR 的细节将在第五篇《CPU 中的主要寄存器》展开。
- **冯·诺依曼瓶颈**：指令与数据共用一条访存通路；哈佛结构以指令 / 数据分离存储来缓解，现代芯片是二者的混合。
- 地址线位数 $n$ 与可寻址空间满足 **$N = 2^n$**，每加一根地址线，空间翻倍。

- 五大部件：运算器/控制器/存储器/输入/输出
- 存储程序+程序控制
- 程序与数据同存
- 瓶颈：取指取数共用总线
- I/D 分离缓解瓶颈
- 层次结构应对存储墙
- 指令顺序执行
- 程序=数据是元假设
