## 为什么替换算法决定 Cache 的「宿命」

组相联和全相联 Cache 未命中时，槽可能已满，必须**驱逐**一个旧块为新块腾地方。驱逐谁？答案直接影响命中率。四种经典算法——**随机（RAND）、先进先出（FIFO）、LRU、LFU**——代表了「简单」「公平」「预测未来」「统计频率」四种哲学。这一课讲清它们的机制、优劣与工程折中，并给出一个反直觉的结论：**在真实程序里，最聪明的算法未必比最简单的快多少**。<span class="marginnote">「理想算法 OPT（最优替换）」预知未来，驱逐未来最久才用到的块，命中率最高——但它需要预知未来，无法实现，只作理论下界。所有现实算法都是在逼近它。</span>

## 1 四种经典算法### 随机（RAND）

从候选槽中**随机**选一个驱逐。

优点：实现极简（一个伪随机数生成器），无状态。
缺点：可能驱逐「马上要用的块」，命中率随性。

### 先进先出（FIFO）

驱逐**最早进入** Cache 的块（按调入时间排队）。

优点：实现简单（一个循环队列指针）。
缺点：**不管块是否还在被用**——一个常驻热块可能因为「来得早」被误杀，导致命中率低于随机。<span class="marginnote">FIFO 有个著名现象叫「Belady 异常」：在 FIFO 下，增大 Cache 容量反而可能降低命中率（因为最早进来的热块被更早驱逐）。LRU 则没有这种异常——这是 LRU 理论上的优势。</span>

### LRU（Least Recently Used）

驱逐**最近最少使用**的块——把「很久没用」当作「以后也不常用」。

实现：维护一个「最近使用顺序」，每次命中把块移到队首，队尾即 LRU。
优点：利用时间局部性，命中率在现实中最好。
缺点：需要记录访问顺序，硬件成本随相联度上升（组内 n 路需要 $\log_2 n!$ 位状态，4 路约 5 位）。

**LRU 是理论与实践的最佳平衡点**，现代 CPU 的 L1/L2 普遍采用近似 LRU（pseudo-LRU）。

### LFU（Least Frequently Used）

驱逐**使用频率最低**的块——用「计数」代替「时间」。

实现：每个块一个计数器，命中加一，驱逐时找计数最小者。
优点：能识别「高频率但低局部性」的热块。
缺点：**历史包袱**——一个曾经的超热块即使不再被用，计数仍高，赖着不走；且计数器会溢出。<span class="marginnote">LFU 的「老热块赖着不走」是它的致命伤。工程改良版 LFU（如 Caffeine 缓存库用 TinyLFU）会做「频率衰减」或「滑动窗口」。这套替换思想在操作系统页面置换（Clock 算法）里也有一脉。</span>

## 2 公式解析：用「未来」量化算法优劣以理想 OPT 为基准，定义缺失率比较。设访问序列长度为 $N$，某算法的缺失次数为 $M_{\text{alg}}$：

$$\text{缺失率} = \frac{M_{\text{alg}}}{N}, \qquad \text{最优} = \frac{M_{\text{OPT}}}{N}$$

**关键不等式（栈算法的单调性）**：

- LRU 属于**栈算法（stack algorithm）**：Cache 容量从 $C$ 增到 $C+1$ 时，LRU 的命中集是原命中集的超集——**容量增大不降低命中率**。
- FIFO **不是**栈算法：容量增大可能降低命中率（Belady 异常）。

逐项拆解：

- **第一步，栈算法定义**：若容量为 $k$ 时缓存中的内容集合总是「容量 $k+1$ 时内容集合」的子集，则增大容量不会挤掉任何「小容量下也会保留」的块。
- **第二步，LRU 满足**：LRU 保留的是「最近 $k$ 个不同的块」，增大到 $k+1$ 只是多留一个，旧集合不变。
- **第三步，FIFO 不满足**：FIFO 保留的是「最早进入的 $k$ 个」，容量变化改变驱逐目标，可能赶走本可保留的热块。

**结论：LRU 在理论上有「单调性」保证，这是它优于 FIFO 的结构性原因。**<span class="marginnote">栈算法的意义：可以「扫一遍访问序列」同时算出所有容量下的缺失率（Mattson 算法），用于设计阶段的容量选择——这是 LRU 被理论界偏爱、被工程界长期使用的深层原因。</span>

## 3 实现代价：从理论到硬件| 算法 | 硬件状态 | 实现代价 | 命中率（平均） |

| --- | --- | --- | --- |
| RAND | 无 | 最低 | 最低~中 |
| FIFO | 指针 | 低 | 中 |
| LRU | 每行访问顺序 | 中高（4 路约 5 位/组） | 高 |
| LFU | 每行计数器 | 中（计数器需防溢出） | 中高（看场景） |
| OPT | 需预知未来 | 不可实现 | 上界 |

**重点：LRU 的硬件代价随相联度爆炸**——8 路需要 $\log_2 8! \approx 16$ 位状态、16 个比较器。因此现代 CPU 用**伪 LRU（Pseudo-LRU）**：用树形位记录「哪一侧更旧」，只需 $E-1$ 位（8 路只要 7 位），性能损失约 1%。<span class="marginnote">伪 LRU 用一棵二叉树：每个内部节点 1 位，指向「上次未命中的一侧」。更新 O(1)，驱逐 O(1)，硬件省一个量级——这是「用近似换成本」的经典工程妥协，在缓存、TLB、分支预测器里到处可见。</span>

## 4 辨析｜易错点：算法选择误区**辨析｜易错点：**

**LRU ≠ LFU**：LRU 看「多久没碰」（时间），LFU 看「总共碰几次」（频率）。「最近最少使用」与「最不经常使用」一字之差，机制完全不同，考概念题必出。
**FIFO 有 Belady 异常，LRU 没有**：这是两者最常被对比的性质。
**替换算法只在相联/全相联 Cache 需要**：直接映射替换目标唯一，谈不上算法。
**算法优劣要看访问模式**：顺序流（数组遍历）下 FIFO 与 LRU 都很好；循环流下 LRU 好；突发性访问下 RAND 可能反超——没有「万能算法」。

## 5 替换算法的现实坐标- **L1/L2 Cache**：伪 LRU，兼顾命中率与硬件。
**TLB**：LRU 或随机（因为 TLB 项数少、替换频率低）。
**操作系统页面置换**：Clock（二次机会）算法——LRU 的近似，用一位「使用位」降低成本。
**数据库/Redis 缓存**：近似 LRU（Redis）、LFU 变体（TinyLFU）、LFU-LRU 混合。<span class="marginnote">替换算法在 Cache 里是「纯硬件、纳秒级」，在数据库里是「软件、毫秒级」——同一个思想，两个世界。Redis 的 maxmemory-policy 让你在 volatile-lru、allkeys-lfu 之间选，正是本课算法的工程投影。</span>

## 6 拓展：替换算法速记**五条必记**：
- RAND（随机）、FIFO（先进先出，有 Belady 异常）、LRU（最近最少用，栈算法）、LFU（最不经常用）。
- LRU 现实最好且无 Belady 异常——栈算法单调性。
- FIFO 简单但有 Belady 异常。
- LFU 有「老热块赖着不走」问题。
- 工程用伪 LRU（树形位）降硬件成本。

**辨析｜易错点**：LRU 看时间、LFU 看频率——一字之差。

- 自测 1：LRU 为什么无 Belady 异常？
- 自测 2：伪 LRU 省什么？
- 自测 3：直接映射需替换算法吗？

> 记住：LRU 看时间、LFU 看频率。

## 7 小结- 四种算法：**RAND（随机）、FIFO（先进先出）、LRU（最近最少用）、LFU（最不经常用）**。
- **LRU 利用时间局部性，现实中命中率最好，且是栈算法（无 Belady 异常）**。
- FIFO 简单但有 Belady 异常；LFU 有「老热块赖着不走」的问题。
- OPT 需预知未来，是理论下界。
- 工程用**伪 LRU**（树形位）降硬件成本；替换算法思想贯通 Cache 与操作系统。

- RAND/FIFO/LRU/LFU 四算法
- LRU 无 Belady 异常、FIFO 有
- 伪 LRU 树形位省硬件
- LFU 计数防溢出
- 替换思想贯通 Cache 与 OS
- OPT 是理论下界
- 直接映射无需替换算法
- 算法优劣看访问模式
