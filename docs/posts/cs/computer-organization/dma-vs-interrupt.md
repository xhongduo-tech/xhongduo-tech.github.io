## 中断和 DMA 都是「省 CPU」，省法不同

中断与 DMA 都让 CPU 不干等设备，但分工不同：**中断**是「设备就绪喊一声，CPU 来搬一个字节」；**DMA** 是「设备成块直接搬内存，搬完喊一声」。本课把它们放在天平两端系统比较，并给出「什么时候用哪个」的选型准则。这是 I/O 方式专题的总结性一课。<span class="marginnote">I/O 方式的光谱回顾：程序查询（CPU 傻等）→ 中断（CPU 等通知，逐字节搬）→ DMA（CPU 不搬，成块直传）→ 通道（专门的 I/O 处理器，彻底解放）。中断与 DMA 是其中最常用的两档，比较它们就抓住了 I/O 设计的核心权衡。</span>

## 1 全面对比| 维度 | 程序中断 | DMA |

| --- | --- | --- |
| 数据传送 | 每字节中断 + CPU 搬运 | 成块直接搬，CPU 不参与 |
| 响应单位 | 字节/字 | 数据块 |
| CPU 干预 | 每次传输都参与 | 开始/结束各一次 |
| 中断次数 | 与数据量成正比 | 每块一次 |
| 适用设备 | 低速字符设备 | 高速块设备 |
| 硬件 | 接口含中断逻辑 | 额外 DMA 控制器 |
| 数据路径 | 设备→CPU→内存 | 设备→DMAC→内存 |
| 错误处理 | 每字节可查 | 块级检查 |

**核心概念：中断「每字节打扰一次」，DMA「每块打扰一次」**——打扰频率差了几个数量级，这是两者性能差距的根源。<span class="marginnote">量化：串口 115200bps（≈14.4KB/s）每字节中断，CPU 3GHz 每字节 2000 周期，占用约 1%；而 1GB/s 网卡用中断会 100% 占用。同一中断机制，设备从「Kbps」到「Gbps」就不可用了——速率翻 6 个数量级，中断频率跟不上了，必须 DMA。</span>

## 2 什么时候用中断、什么时候用 DMA**用中断**：

低速设备（键盘、鼠标、串口、打印机）。
数据量小、频率低——中断开销可忽略。
设备需要「逐个字符处理」（交互式输入）。

**用 DMA**：

高速块设备（磁盘、SSD、网卡、显卡）。
数据量大、成块连续——一次搬完，减少打扰。
数据无需 CPU 处理（直接从设备进内存缓冲）。

**核心结论：选型准则 = 数据率与块性**——**低速逐字节用中断，高速成块用 DMA**。<span class="marginnote">「块性」是另一个维度：键盘是逐字符语义（每按一键要处理），磁盘是整块语义（4KB 一起读）。即使键盘速率不高，它的「逐字符」特性也决定了用中断比 DMA 合适——DMA 的「块」模型对键盘无意义。</span>

## 3 公式解析：两种方式的 CPU 开销对比设设备速率 $r$ 字节/s、每字节中断处理 $T_{int}$、块大小 $B$、每块 DMA 配置+中断 $T_{dma}$：

$$\text{中断 CPU 占用} = r \times T_{int}$$

$$\text{DMA CPU 占用} = \frac{r}{B} \times T_{dma}$$

逐项拆解：

- **第一步，中断**：每字节一次处理，占用 = 速率 × 每字节开销。
- **第二步，DMA**：每块一次处理，占用 = (速率/块大小) × 每块开销。
- **第三步，对比**：若 $T_{dma} \approx B \times T_{int}$（DMA 配置开销≈搬一块的中断开销），两者相当；但 $T_{dma}$ 通常远小于 $B \times T_{int}$——DMA 省。

例：$r=100$MB/s、$B=4$KB、每字节中断 1μs、每块 DMA 10μs：

$$\text{中断占用} = 100\% \quad(\text{CPU 全在中断})$$

$$\text{DMA 占用} = 25600 \times 10\mu s / 1s \approx 25\%$$

**核心结论：高速设备下中断方式直接饱和，DMA 是唯一选择**。<span class="marginnote">DMA 的「每块开销」包括：配置 DMAC（写几个寄存器）、块结束中断、CPU 验证状态。对比中断的「每字节开销」（保存现场、服务、恢复、返回），DMA 把每字节的成本摊销到整块——摊销是 DMA 省 CPU 的数学本质。</span>

## 4 辨析｜易错点：中断 vs DMA**辨析｜易错点：**

- **DMA 也要用中断**：DMA 结束时发中断通知 CPU——「DMA 不用中断」是错误说法，DMA 只是把中断频率从每字节降到每块。
- **中断方式也可以搬大量数据**：只是 CPU 参与度高、效率低——不是「不能」，是「不划算」。
- **DMA 需要总线仲裁与 DMAC 硬件**：代价是硬件复杂度；中断只需接口加中断逻辑。
- **「中断方式 CPU 数据经过 CPU」vs「DMA 数据不经过 CPU」**：数据路径不同是本质差异——中断路径 CPU 是中间站，DMA 路径 CPU 被旁路。

## 5 拓展：中断与 DMA 的「混合实践」现实系统不是「非中断即 DMA」，而是混合：

- **网卡**：数据包经 DMA 直接进内存环形缓冲，收到一批后发**一次中断**通知 CPU——「DMA 搬运 + 中断通知」的组合。
- **中断合并（coalescing）**：网卡攒若干包再中断一次，防止「中断风暴」。
- **NAPI（Linux）**：流量高时切换为轮询收包（中断关闭），流量低时恢复中断——中断与轮询的动态平衡。

**核心概念：现代 I/O 是「DMA + 合并中断 + 动态轮询」的组合拳**——单看某一种方式已经过时，组合才是工程答案。

**辨析｜易错点：**「DMA 方式不要中断」是错的——DMA 结束恰恰靠中断通知 CPU。正确说法是：DMA 把中断频率从「每字节」降到「每块」。

## 6 拓展：中断与 DMA 的选型**五条必记**：
- 中断：每字节打扰、CPU 搬运、低速字符设备。
- DMA：每块打扰、DMAC 直搬、高速块设备。
- 选型：低速逐字节用中断，高速成块用 DMA。
- 开销公式：中断 r×T_int vs DMA (r/B)×T_dma——摊销是本质。
- DMA 结束也中断，只是频率从每字节降到每块。

**辨析｜易错点**：「DMA 不用中断」是错的——DMA 完成靠中断通知 CPU。

## 7 一句话回顾- 中断每字节打扰、DMA 每块打扰。
- 低速逐字节用中断、高速成块用 DMA。
- DMA 结束也中断，只是频率低。

> 一句话：低速逐字节用中断、高速成块用 DMA。

## 8 小结- 中断：**每字节打扰、CPU 搬运、低速字符设备**。
- DMA：**每块打扰、DMAC 直搬、高速块设备**。
- 选型准则：**低速逐字节用中断，高速成块用 DMA**。
- 开销公式：中断 $r×T_{int}$ vs DMA $(r/B)×T_{dma}$——DMA 靠「摊销」省 CPU。
- DMA 结束也发中断，只是频率从每字节降到每块。

- 中断每字节打扰、DMA 每块打扰
- 低速逐字节用中断、高速成块用 DMA
- DMA 结束也中断
- 摊销是 DMA 省 CPU 的本质
- 网卡 = DMA+合并中断+NAPI
- 数据路径：中断过 CPU、DMA 旁路
- 块性决定选型
- 高速设备中断会饱和
