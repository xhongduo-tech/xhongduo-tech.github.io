## 为什么现代 CPU 全靠流水线

前几课的单指令周期里，一条指令要「取指 → 译码 → 执行 → 访存 → 写回」串行完成，取指部件大部分时间在空转。**指令流水线（instruction pipeline）** 把这些阶段拆开，让多条指令像工厂流水线一样错峰通过——取指第 5 条时，第 4 条在译码、第 3 条在执行……**单条延迟不变，吞吐提升数倍**。这一课是第六篇的开篇，讲清流水线的核心概念、五级划分与时空图，为后面的冒险、分支预测、乱序执行铺路。<span class="marginnote">「流水线」的思想来自汽车工厂的装配线，1950s 用于计算机。现代 CPU 的流水线深度 14–20 级（如 Intel 的 19 级），深度越深，单级越短、主频越高——但冒险代价也越大。</span>

## 1 五级流水线：经典划分把一条指令的执行拆成五个阶段：

| 阶段 | 英文 | 做什么 | 主要部件 |
| --- | --- | --- | --- |
| IF | Fetch | 取指令 | PC、I-Cache |
| ID | Decode | 译码、读寄存器 | 译码器、寄存器堆 |
| EX | Execute | 运算/算地址 | ALU |
| MEM | Memory | 访存 | 数据 Cache |
| WB | Write Back | 写回寄存器 | 寄存器堆 |

$$\text{指令} = \text{IF} \to \text{ID} \to \text{EX} \to \text{MEM} \to \text{WB}$$

每级之间用**流水线寄存器**（如 IF/ID、ID/EX）隔离，保存该级的中间结果，时钟沿到来时传给下一级。<span class="marginnote">五级是 MIPS 的经典划分（也是 CS:APP 的 Y86-64 的划分）。现代处理器把 EX 再拆成多级（乘法、浮点、访存地址计算各占一级），深度因此翻倍。级数越多，每级逻辑越短，主频可以越高。</span>

## 2 时空图：流水线怎么「错峰」5 条指令在 5 级流水线上执行，用时空图看：

| 周期 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| I1 | IF | ID | EX | MEM | WB | | | | |
| I2 | | IF | ID | EX | MEM | WB | | | |
| I3 | | | IF | ID | EX | MEM | WB | | |
| I4 | | | | IF | ID | EX | MEM | WB | |
| I5 | | | | | IF | ID | EX | MEM | WB |

**关键观察**：

第 1 条指令花 5 个周期完成（延迟 5）。
从第 2 条起，**每周期完成一条**（吞吐 1）。
5 条指令共 9 周期，串行要 25 周期——**吞吐提升 2.8 倍**。

**核心概念：延迟（latency）vs 吞吐（throughput）**——流水线不缩短单条延迟（还是 5 周期），但把吞吐从「5 周期/条」提升到「1 周期/条」。<span class="marginnote">「流水线的稳态」：填充阶段（前 4 周期）吞吐未达峰值；排空阶段（后 4 周期）亦然。长序列下填充/排空占比可忽略，吞吐趋近 1 条/周期——这就是为什么流水线对「大循环」收益最大。</span>

## 3 流水线的理想条件流水线要高效，需要满足：

**阶段均衡**：五级耗时大致相等——最慢一级决定节拍，其他级被迫等待。
**指令独立**：各指令之间无依赖——有依赖则要停顿（数据冒险，见后文）。
**无分支打扰**：分支打破取指连续性——有分支则可能清空流水线（控制冒险）。

**核心概念：流水线的节拍由「最慢阶段」决定**——若 MEM 级耗时是其他级的 2 倍，整个流水线按 MEM 的节奏走，吞吐只有理想值的一半。<span class="marginnote">这就是「流水线分级要均衡」的原因：把大而慢的级拆成两半（如把访存拆成地址计算 + 数据存取），让每级耗时接近，吞吐才能最大化。现代 CPU 拆深流水线，一半是为主频、一半是为均衡。</span>

## 4 公式解析：流水线的加速比设流水线 $k$ 级、每级 1 周期，执行 $n$ 条指令：

$$T_{\text{串行}} = n \times k, \qquad T_{\text{流水}} = k + (n-1)$$

$$S = \frac{nk}{k + n - 1}$$

逐项拆解：

- **第一步，串行时间**：每条 5 周期，n 条共 5n。
- **第二步，流水时间**：第 1 条 5 周期，之后每周期出一条，共 $5 + (n-1)$。
- **第三步，极限**：$n \to \infty$ 时 $S \to k = 5$——加速比极限 = 流水线级数。

例：$n=100, k=5$：$S = 500/104 \approx 4.8$，接近极限 5。

**核心结论：流水线加速比趋近「级数」，但受 n 与冒险限制**——短序列、频繁冒险时实际加速比远低于理论极限。<span class="marginnote">这个加速比公式与《阿姆达尔定律》呼应：流水线只优化了「执行」这一部分，填充/排空与冒险就是那个「不可改进的部分」。工程上，指令级并行（ILP）的追求极限就是「每周期一条 + 冒险最小化」。</span>

## 5 辨析｜易错点：流水线概念**辨析｜易错点：**

- **流水线不缩短单条指令延迟**——「加了流水线单条变快」是错误说法，它只提吞吐。
- **流水线级数 ≠ 性能倍数**：级数决定理论极限，实际受冒险、阶段不均衡、填充排空限制。
- **流水线寄存器是必需的**：每级之间要有寄存器暂存，否则下一级上一级互相干扰——它不是「额外开销」而是「必要部件」。
- **五级流水线不是唯一标准**：不同 ISA/微架构的级数划分不同（3 级到 20 级都有），五级只是教学基准。

## 6 考点速记：流水线五问**问一：五级是什么？** IF（取指）→ ID（译码）→ EX（执行）→ MEM（访存）→ WB（写回）。

**问二：延迟与吞吐？** 延迟不变（首条仍 k 周期），吞吐提升到每周期一条。

**问三：加速比？** $S = nk/(k+n-1)$，极限 = 级数 k。

**问四：理想条件？** 阶段均衡、指令独立、无分支打扰。

**问五：节拍谁定？** 最慢阶段——分级不均衡则按最慢走。

**五条必记**：

- 级间要**流水线寄存器**隔离，否则各级互相干扰。
- 填充/排空阶段吞吐未达峰值，长序列才接近理想。
- 级数越深主频越高，但级间开销与冒险代价越大。
- 流水线用「空间（重复部件）换时间（吞吐）」。
- 时空图：第 1 条 k 周期，此后每周期出一条。

**辨析｜易错点：**「流水线让单条指令变快」是错的——它只提吞吐，单条延迟不变甚至略增（级间开销）。

## 7 核心公式
- 五级：IF→ID→EX→MEM→WB。
- 流水时间：$T = k + (n-1)$。
- 加速比：$S = nk/(k+n-1)$。
- 节拍由最慢阶段决定。

## 8 小结- 五级流水线：**IF → ID → EX → MEM → WB**，级间用流水线寄存器隔离。
- 时空图：第 1 条延迟 k 周期，此后每周期出一条。
- **延迟不变、吞吐提升**：加速比趋近级数 k。
- 理想条件：阶段均衡、指令独立、无分支打扰。
- 节拍由最慢阶段决定，级数由「主频 × 均衡」共同决定。
