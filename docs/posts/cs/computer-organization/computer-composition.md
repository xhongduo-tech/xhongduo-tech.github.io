## 为什么把机器拆成五个部件

上一篇把冯·诺依曼结构画成了五大部件，但那张图只是骨架。今天我们要做一次「解剖」：每个部件内部由什么构成，各自负责哪一段工作，相互之间怎么配合。学完这一节，你会拥有一个「拆机视角」——以后再看到「CPU」「内存」「显卡」这些词，脑子里出现的不是神秘盒子，而是一张分工明确的分工表。

现代计算机的硬件系统，按功能划分为**运算器、控制器、存储器、输入设备、输出设备**五大部件；再往上归并：**运算器与控制器合称 CPU，CPU 与主存合称主机，输入输出设备合称外部设备**。<span class="marginnote">这套「五部件 → 主机 / 外设」的层级，是组成原理里最稳定的框架：无论器件怎么换代，这个功能划分几乎不变——上一节那张结构图，正是这张分工表的图形化。</span>

## 1 运算器：数据的加工厂**运算器（arithmetic unit）**是计算机的**执行部件**，负责对数据进行**算术运算**（加、减、乘、除）与**逻辑运算**（与、或、非、异或、比较）。

它的核心是**算术逻辑单元（ALU, Arithmetic Logic Unit）**，此外还有若干寄存器作为「工作台」：**累加器（ACC）**用来暂存一个操作数与运算结果，**乘商寄存器（MQ）**在乘除法中暂存乘数或商，**操作数寄存器（X）**暂存另一个操作数。<span class="marginnote">ALU 的电路实现——如何用与门、或门、加法器搭出加减乘除——是第三级《数字逻辑》与第二篇《算术逻辑单元 ALU 的基本结构》《加法器设计》的内容。今天先记住它的功能定位。</span><span class="marginnote">ALU 的「逻辑运算」与布尔代数一一对应：《数字逻辑》里与门、或门、异或门的真值表，就是这里「与、或、非、异或」的电路依据。</span>

一句话记忆：**运算器 = ALU + 几个暂存数据的寄存器**。它没有「决策权」，只会「算」。

用加法走一遍：要算 $3 + 4$，控制器先把 3 送进 ACC、把 4 送进操作数寄存器 X；然后 ALU 把 ACC 与 X 相加，结果 7 写回 ACC。整个过程里，运算器只负责「算」，至于「谁先谁后、结果存哪」，全由控制器说了算——这就是「加工厂」与「指挥官」的分工。

## 2 控制器：发号施令的指挥官**控制器（control unit, CU）**是整个机器的**指挥中心**。它逐条取出指令、翻译指令，再据此向其余部件发出**控制信号（control signals）**，命令谁在什么时候做什么。

控制器内部有两个关键寄存器：

**程序计数器（PC, Program Counter）**：存放下一条要执行的指令的地址。程序顺序执行时，取完一条指令 PC 自动加 1，指向下一条。
**指令寄存器（IR, Instruction Register）**：存放当前正在执行的这条指令本身（操作码 + 地址码），供控制器译码。

此外还有负责解释指令的**指令译码器（ID）**，以及按节拍发出信号的**时序控制**部件。<span class="marginnote">控制器的实现有两条路线：<strong>硬布线控制</strong>（用逻辑门电路直接搭出控制逻辑，快但改不动）与<strong>微程序控制</strong>（把控制信号写成「微程序」存进控制存储器，灵活）——这是第五篇《硬布线控制器的设计原理》《微程序控制的基本思想》两节的主角。</span><span class="marginnote">PC 与 IR 是最容易混淆的一对：PC 存「下一条在哪」，IR 存「这一条是什么」——一个是地址，一个是指令本身。</span>

一句话记忆：**控制器 = 决定「下一步做什么」的大脑；运算器 = 执行「怎么算」的手。**

由此看到整台机器的权力结构：**运算器出力，控制器出主意，存储器出记忆，输入输出出沟通**。下一节，我们让这四个角色围绕一条指令真正转起来。

## 3 存储器：记忆的仓库**存储器（memory）**是计算机的**记忆部件**，用来存放程序与数据。组成原理里首先关心的是**主存（主存储器，即内存）**，它的内部结构是理解一切访存操作的地基。

主存由三部分构成：

**存储体（memory array）**：真正存放信息的地方，由成千上万个**存储单元**组成，每个单元存放一个**存储字（word）**（或一个字节）。

再说清两个名词：**存储单元（cell）**是存储体的最小编址单位，每个单元有一个唯一编号（即地址）；**存储字（word）**是每个单元里存放的二进制位串，其位数叫**存储字长**。存储字长与机器字长并不总相等，二者的关系我们到第四篇《指令字长与机器字长的关系》再细说。
**存储地址寄存器（MAR, Memory Address Register）**：存放本次要访问的存储单元的地址，它的位数决定主存可寻址的单元个数。
**存储数据寄存器（MDR, Memory Data Register）**：存放刚读出或即将写入的数据，它的位数一般等于存储字长。

一次**读操作**的过程是：CPU 把地址送入 MAR → 译码器按地址找到对应单元 → 把该单元内容读出到 MDR → 交给 CPU。**写操作**则反向：地址入 MAR、数据入 MDR → 写入指定单元。<span class="marginnote">「地址走 MAR，数据走 MDR」这套分工贯穿主存与 CPU 的所有交互——第五篇《CPU 中的主要寄存器：PC、IR、MAR、MDR、PSW》会把这五个寄存器放在同一张表里比较。</span>

用具体的数走一遍：假设 MAR 是 4 位、MDR 是 8 位。要读 6 号单元，CPU 先让 MAR ← 0110；主存按地址译码，找到 6 号单元，把其中 8 位内容读出到 MDR；MDR 再把这 8 位交给 CPU。「**MAR 定位置、MDR 定数据**」这套口诀，后面会用很多次。

主存中，**地址唯一标识一个单元，数据可以被反复读出而不改变**（破坏性读出是动态存储器 DRAM 的细节，第三篇《DRAM 的结构、读写原理与刷新方式》再讲）。

## 4 输入输出设备：计算机的手眼口**输入设备**把外部世界的信息送进计算机：键盘、鼠标、扫描仪、麦克风、摄像头、传感器。**输出设备**把结果交还给外部世界：显示器、打印机、音箱。I/O 设备的种类五花八门，速度差异极大（键盘每秒几个字节，显卡每秒数 GB），这决定了它们不能直接挂到 CPU 总线上，而要通过**I/O 接口（interface）**中转。<span class="marginnote">输入输出是组成原理里「最像系统工程」的部分：如何让速度相差十万八千里的设备与 CPU 协调工作，正是第八篇《输入输出系统》要解决的核心矛盾。</span>

**辨析｜易错点：**「输入输出设备」是**外部设备（外设）**，不属于主机。**存储器**（主存）属于主机，但**外存**（磁盘、SSD）通常也被归入外设——「内存」与「外存」一字之差，地位完全不同。判断口诀：**CPU 直接通过总线访问的属于主机；需要通过接口、以文件形式打交道的是外设。**

五大部件并不是各自为政，它们之间的连接靠**总线（bus）**——一组按功能分组的共享导线：传输地址的**地址线**、传输数据的**数据线**、传输控制信号的**控制线**。CPU 想访问主存，就把地址送上地址总线、把数据放上数据总线，再靠控制总线协调方向与时序。总线的完整体系我们到第七篇《总线的基本概念与特性》再展开，今天先记住一句话：**部件之间靠总线握手。**

## 5 公式解析：主存容量 $C = 2^m \times w$把上一篇的 $N = 2^n$ 与今天的 MAR / MDR 结合起来，就得到主存容量的完整公式。设 MAR 的位数为 $m$，MDR 的位数为 $w$，则：

$$
C = 2^m \times w \quad (\text{位 bit})
$$

逐步拆解：

- **第一步，单元个数看 MAR**：MAR 有 $m$ 位，可编出 $2^m$ 个不同地址，因此主存有 $2^m$ 个存储单元。
- **第二步，每单元容量看 MDR**：每个存储单元存放一个存储字，MDR 的位数 $w$ 就是这个字的位数。
- **第三步，相乘**：总容量 = 单元个数 × 每个单元的位数 = $2^m \times w$ 位。换算成字节要除以 8，例如 $m = 20,\ w = 32$ 时，$2^{20} \times 32 = 32\ \text{Mb} = 4\ \text{MB}$。<span class="marginnote">这是容量换算的第一次实战：位（bit）→ 字节（Byte）→ KB → MB → GB，每一级是 1024 倍（$2^{10}$），不是 1000 倍——这个「程序员都懂的 1024」，我们会在第二篇《进位计数制及其相互转换》里追根溯源。</span>

用代码验证一遍这条公式的换算：

```python
m, w = 20, 32                      # MAR=20 位，MDR=32 位
bits = (1 << m) * w                # 总容量：2^20 个单元 × 每单元 32 位
print(bits, "bit")                 # 33554432 bit
print(bits // 8, "B")              # 4194304 B
print(bits // 8 // 1024 // 1024, "MB")   # 4 MB
```

运行结果：`33554432 bit`、`4194304 B`、`4 MB`——与手算完全一致。这条「**位 → 字节 → KB → MB**」的换算，是后面读存储器参数时天天要用的基本功。<span class="marginnote">内存条上「8 GB」的标签，对应的就是这条公式换算后的字节数；现代主存普遍按字节编址，字长往往就是 8 位。</span>

**辨析｜易错点：**MAR 的位数决定的是**可寻址单元个数**，不是容量本身；容量还要乘上每个单元的字长（MDR 位数）。两个寄存器一个管「能编多少个地址」，一个管「每个地址装多少数据」，缺一不可。

顺带把本课出现的寄存器放进一张表，算是第五篇的预习：

| 寄存器 | 归属部件 | 职责 |
| --- | --- | --- |
| ACC | 运算器 | 暂存操作数与运算结果 |
| PC | 控制器 | 下一条指令的地址 |
| IR | 控制器 | 当前指令本身 |
| MAR | 主存 | 本次访问的存储单元地址 |
| MDR | 主存 | 读入 / 写出的数据 |

## 6 补充：基本组成速记- 运算器：算术逻辑运算。
- 控制器：取指令、发控制信号。
- 存储器：存程序与数据。
- 输入输出：信息交换。
- 总线：连接各部件。存储程序 + 程序控制是核心。

## 7 核心要点
- 运算器算、控制器指挥、存储器存、I/O 交换。
- 总线连接各部件。
- 存储程序 + 程序控制是核心。

## 8 小结- 五大部件各司其职：**运算器**加工数据，**控制器**发号施令，**存储器**存放程序与数据，**输入 / 输出设备**完成人机交互。
- 归并关系：**运算器 + 控制器 = CPU；CPU + 主存 = 主机；输入输出 = 外设**。
- 控制器内部的关键是 **PC（下一条指令地址）与 IR（当前指令）**；运算器内部的关键是 **ALU 与 ACC 等寄存器**。
- 主存 = **存储体 + MAR + MDR**：地址走 MAR，数据走 MDR；一次读操作是「送地址 → 译码 → 读出到 MDR」。
- 主存容量 $C = 2^m \times w$（MAR 位数 $m$，MDR 位数 $w$）——地址线定个数，字长定每个单元的容量。
- 外设通过 **I/O 接口**与主机交互；内存与外存、主机与外设的界限，是高频易错点。

- 五大部件分工明确
- 存储程序+程序控制
- 总线连接各部件
- 运算器算、控制器指挥
- 主存存程序与数据
- I/O 换能器
- 冯·诺依曼五大部件
- 取指译码执行循环
