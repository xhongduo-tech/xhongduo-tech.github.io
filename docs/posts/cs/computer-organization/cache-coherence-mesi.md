## 为什么多核的 Cache 会「打架」

单核里 Cache 与主存的不一致用写策略解决；多核里问题升级：**核 A 与核 B 的 L1 都缓存了同一块内存**，A 修改后 B 还读旧值——程序就错了。**缓存一致性（cache coherence）** 协议规定「各核缓存对同一地址必须看到一致的值」。本课讲一致性问题的成因、写失效协议的基本思路，以及现代主流 **MESI 协议**的四状态。<span class="marginnote">缓存一致性是《Cache 的写策略》在多核的延伸：写回策略下，脏数据只在 Cache 里，多核必须有机制让「谁改了、通知谁」。MESI 就是这套「通知协议」——它由 Intel Pentium Pro 时代推广，至今是所有主流 CPU 的基石。</span>

## 1 一致性问题的成因多核下出现不一致的三个条件：

1. **多份副本**：同一内存块被多个核的 Cache 缓存。
2. **写回策略**：修改只写自己的 Cache，不立即写主存（脏块）。
3. **并行执行**：各核独立读写，无统一调度。

经典冲突场景：

核 A 与核 B 的 L1 同时缓存了变量 X（初始值 0）；核 A 执行 X = 1（写回策略下只更新自己的 Cache，副本转 M），核 B 仍读到 0——两个核对同一地址看到两个不同的值。

**核心概念：缓存一致性协议要保证——任一时刻，所有核看到同一地址的值是一致的**（对写回 Cache 而言，即「写者对最新值负责，读者要么读新值要么等」）。<span class="marginnote">一致性的严格定义（write serialization）：对同一地址的写操作必须「全局有序」，且每个核看到的读结果与该顺序一致。实现上就是「写操作要广播/失效其他副本」——一个写者、大家同步。</span>

## 2 一致性协议的两大流派- **写更新（write-update）**：A 写时把新值**广播**给所有副本，大家同时更新。
优点：读总是最新的。缺点：广播带宽开销巨大。
**写失效（write-invalidate）**：A 写时广播**失效通知**，其他核的副本作废；它们要读时重新取。
优点：带宽省（只发失效信号）。缺点：失效后重取有延迟。

**现代 CPU 几乎全用写失效**——因为失效信号比数据本身小得多，带宽效率高。MESI 就是写失效协议的经典实现。<span class="marginnote">「写失效 vs 写更新」的取舍是带宽 vs 读延迟：失效省带宽但让其他核「miss 后重取」，更新免重取但每次写都广播数据。现代高速互连下失效协议胜出——这也是为什么 MESI 统治了市场。</span>

## 3 MESI 协议的四种状态每个缓存行带两位状态标记：

| 状态 | 含义 | 该核 | 其他核 |
| --- | --- | --- | --- |
| M（Modified） | 已修改 | 唯一最新副本，脏 | 无副本 |
| E（Exclusive） | 独占 | 唯一副本，干净 | 无副本 |
| S（Shared） | 共享 | 干净副本 | 可能有副本 |
| I（Invalid） | 失效 | 无效 | — |

**状态转移的核心逻辑**：

**读**：本地命中 M/E/S → 直接读；I 或 miss → 向总线发「读请求」，若其他核有 M 则写回主存并转 S，自己进 S 或 E。
**写**：命中 M → 直接写；命中 E → 进 M 写；命中 S → **广播失效**，使其他副本失效，进 M；miss → 取块 + 失效其他，进 M。

**核心概念：写操作的目标状态是 M**——写者独占最新值，其他副本全部失效。这就是写失效 + 独占修改的组合。<span class="marginnote">状态机的记忆锚点：M = 我改了（脏、独占）、E = 我独占但干净、S = 大家共享（干净）、I = 无效。转移核心是「写要独占、失效广播」。考试常画状态转移图，记住「写→M，失效→I」的主线即可。</span>

## 4 公式解析：总线嗅探与一致性流量**总线嗅探（bus snooping）**：每个核的 Cache 控制器**监听总线**上的所有一致性请求（读、失效），据此更新自己的状态。

例：核 A 要写地址 X（自己的副本是 S），广播失效：

$$\text{A 广播 invalidation}(X) \Rightarrow \text{B 收到后 } S \to I, \quad \text{A 的 } S \to M$$

逐项拆解：

- **第一步，写者动作**：A 广播失效信号，然后本地写、状态转 M。
- **第二步，他者动作**：B 监听到失效，把自己的副本标 I（作废）。
- **第三步，后续读**：B 再读 X → miss → 重新从总线取（A 的 M 副本写回主存/转发）。

**核心结论：一致性流量 = 「失效广播 + 重取」的带宽成本**——写共享数据越频繁，总线流量越大。<span class="marginnote">「伪共享（false sharing）」是 MESI 的著名性能陷阱：两个核分别改同一个缓存行里的不同变量——虽然逻辑无关，但写让整行失效，两核互相「踢」对方出局，总线流量爆炸。解法是「变量对齐到不同缓存行」——这是多核性能优化的经典技巧。</span>

### 数值算例：一段 MESI 状态转移追踪

设核 A、B 最初都没有地址 X 的副本，按时间顺序推演各核状态：

1. A 读 X → miss，向总线发读请求 → 主存提供数据，A 进入 **E**（独占、干净）。
2. B 读 X → miss，发读请求 → 总线嗅探发现 A 持有 X → A 转 **S**，B 进入 **S**（两核共享）。
3. A 写 X → 命中 S 需独占 → 广播失效 → B 的副本 **S→I**，A 进入 **M**（脏、独占）。
4. B 再读 X → 自己的副本已 I → miss → 发读请求 → A 嗅探到，把自己的 **M** 数据写回主存（或直接转发），A 转 **S**，B 进入 **S**。

**关键：整条链上，总线上只有「读请求、失效、写回/转发」三类一致性事务**——MESI 的每一条转移都对应一个总线事件，这正是《总线》一篇里「总线嗅探」的现实意义，也是「一致性流量 = 失效广播 + 重取」的具体落地。

## 5 辨析｜易错点：一致性 vs 写策略**辨析｜易错点：**

- **一致性协议 ≠ 写策略**：写直达/写回解决「Cache 与主存」，一致性解决「Cache 与 Cache」——单核用写策略，多核加一致性。
- **MESI 不保证「内存序」**：它管「单个地址的副本一致」，多个地址的读写顺序（内存一致性）要靠内存屏障——两者是不同层次。
- **E 与 M 都是独占，区别在「脏不脏」**：E 干净（主存同步），M 脏（主存旧、以 Cache 为准）。写 E 只需本地转 M，写 S 才要广播失效。
- **一致性协议是硬件透明的**：程序员不需要知道 MESI——但它的性能代价（伪共享、总线流量）程序员必须懂。

## 6 拓展：伪共享的完整例子伪共享（false sharing）是 MESI 的经典性能陷阱：

线程 1 频繁写变量 a、线程 2 频繁写变量 b，而 a 与 b 恰好落在同一个 64B 缓存行内：

- 核 1 写 a → 缓存行进入 M，向核 2 广播失效。
- 核 2 写 b → 也要独占该行 → 失效核 1 的副本。
- 两核互相「踢」对方——虽然 a 与 b 逻辑无关，但同一缓存行让它们「伪共享」，总线流量爆炸。

**核心概念：一致性协议以「缓存行」为粒度，不是以变量为粒度**——同一行的不同变量被不同核写，就产生伪共享。

**辨析｜易错点：**「伪共享」不是「数据竞争」——数据竞争是逻辑错误（同一变量无同步读写），伪共享是性能问题（不同变量同缓存行互相踢）。修复伪共享是「对齐/填充到不同缓存行」，修复数据竞争是「加同步」——两类问题、两类解法。

## 7 补充：MESI 速记- 不一致三条件：多副本 + 写回 + 并行。
- 写更新（广播数据）vs 写失效（广播失效信号），现代用失效。
- 四状态：M（脏独占）、E（干净独占）、S（干净共享）、I（无效）。
- 写操作目标 M：命中 S 要广播失效。
- 总线嗅探监听一致性请求；伪共享是性能陷阱。

> 记住：写操作目标状态是 M。

> 一句话：写操作目标状态是 M，命中 S 要广播失效。

## 8 小结- 不一致三条件：**多副本 + 写回 + 并行**。
- 写更新（广播数据）vs **写失效（广播失效信号）**，现代用写失效。
- **MESI 四状态**：Modified（脏独占）、Exclusive（干净独占）、Shared（干净共享）、Invalid（无效）。
- 写操作目标 M：命中 S 要广播失效，其他核 S→I。
- **总线嗅探**监听一致性请求；伪共享是 MESI 的性能陷阱。
