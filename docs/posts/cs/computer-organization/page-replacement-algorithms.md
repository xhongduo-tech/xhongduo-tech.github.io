## 为什么页面替换比 Cache 替换更「重」

虚拟内存的「页」比 Cache 的「行」大得多（4KB vs 64B），缺页代价高得多（读磁盘 vs 读主存），所以页面替换算法更讲究。Cache 里用伪 LRU 就够，虚拟内存里却是 **OPT、FIFO、LRU、Clock** 四大家的舞台——尤其是 **Clock 算法**，它在「LRU 的命中率」与「极简硬件」之间找到了操作系统能接受的平衡点。本课讲清四家算法、Belady 异常与「抖动（thrashing）」现象。<span class="marginnote">页面替换与 Cache 替换是同一思想在两个层次上的实现，但工程约束截然不同：Cache 替换要纳秒级硬件决策、只看几位状态；页面替换可以花几千指令跑软件算法、用完整页表信息。所以 OS 用更聪明的近似算法。</span>

## 1 四个算法### OPT（Optimal，最优）

**OPT**：驱逐**未来最长时间不再使用**的页。需要预知未来，**不可实现**，只作理论下界，用来衡量其他算法的优劣。

### FIFO

**FIFO**：驱逐**最早调入**的页。实现简单（环形队列），但可能驱逐「常驻热页」，且有 **Belady 异常**——增加物理页数反而使缺页增多。

### LRU

**LRU**：驱逐**最近最少使用**的页。利用时间局部性，命中率最好，是栈算法（无 Belady 异常）。但完全 LRU 需要维护每个页的「最近使用时间」，硬件成本高，操作系统里**难以精确实现**。

### Clock（时钟/二次机会）

**Clock**：LRU 的近似——给每页一个**使用位（reference bit）**，所有物理页排成环形；缺页时沿环扫描：

1. 使用位为 0 → 驱逐该页。
2. 使用位为 1 → 置 0（给一次「二次机会」），继续扫下一个。

```text
                 ┌──────────────────────────┐
                 │      物理页环形队列         │
                 │  页0 ─► 页1 ─► 页2 ─► …   │
                 │    ▲                 │    │
                 │    └───── 手(hand) ◄──┘    │
                 │                          │
                 │  使用位=1 → 置 0 继续扫描   │
                 │  使用位=0 → 驱逐该页        │
                 └──────────────────────────┘
```

**核心思想**：把「LRU 的精确排序」降级为「一比特的『最近用过没』」，用环形扫描近似 LRU。<span class="marginnote">Clock 为什么叫「二次机会」？每个页第一次被扫描到且有使用位时会得到一次「赦免」（置 0 不驱逐），第二次再被扫到若仍为 0 才驱逐——相当于给「刚用过的页」两次生命。它牺牲了 LRU 的精确性，换来 O(1) 决策与一位硬件。</span>

## 2 公式解析：缺页率的理论界用引用串（reference string）评估替换算法。设物理页数 $m$、引用串长度 $N$，某算法的缺页次数为 $F$：

$$\text{缺页率} = \frac{F}{N}$$

**OPT 是最优的**，对任意引用串：

$$F_{\text{OPT}} \le F_{\text{LRU}} \le F_{\text{FIFO}} \quad(\text{通常})$$

逐项拆解：

- **第一步，理论下界**：OPT 预知未来，缺页次数最少，是其他算法的下界。
- **第二步，经验排序**：现实中 LRU 通常优于 FIFO，FIFO 优于随机——但这不是定理（某些串下 FIFO 可能胜过 LRU）。
- **第三步，异常**：FIFO 有 Belady 异常（增大 m 可能增缺页），LRU/OPT 是栈算法、单调不增——所以「加内存」对 LRU 保证有效，对 FIFO 不保证。

**结论：替换算法的优劣是「平均意义上的」，不是逐串保证的**；LRU 的栈性质让它成为理论上最可靠的选择。<span class="marginnote">这个「增大容量不保证更好」的 Belady 异常，是操作系统课最反直觉的考点之一。它在 Cache 里同样存在（FIFO Cache），所以现代 Cache 也不用 FIFO 而用近似 LRU。</span>

## 3 抖动（Thrashing）**抖动（thrashing）**：物理页数过少，活跃页集装不下，导致「频繁缺页、频繁换入换出」，CPU 大部分时间在等磁盘 I/O，系统吞吐崩溃。

现象：CPU 利用率骤降，但磁盘 I/O 率飙升。
本质：每个进程需要的「活跃页集合（working set）」超过了分配给它的物理页数。
对策：**工作集模型**——操作系统按进程的活跃页集分配物理页，宁可让部分进程换出也不让所有进程一起抖；或使用局部替换（只替换自己的页）防止互相干扰。<span class="marginnote">工作集模型由 Denning 提出：进程在一段时间内实际访问的页集就是工作集，其大小 W(t,Δ) 随窗口 Δ 变化。OS 若保证「每进程物理页 ≥ 工作集」，就不会抖——这是内存过载管理的核心思想。</span>

## 4 辨析｜易错点：Cache 替换 vs 页面替换| 维度 | Cache 替换 | 页面替换 |

| --- | --- | --- |
| 单元 | 缓存行（64B） | 页（4KB） |
| 缺页/缺失代价 | ~100 周期 | ~10^7 周期 |
| 实现者 | 硬件 | 操作系统 |
| 常见算法 | 伪 LRU | LRU 近似（Clock）、LFU 等 |
| 能否 OPT | 不能（预知未来） | 不能 |
| 关键威胁 | 抖动（Cache thrash） | 抖动（working set 超载） |

**辨析｜易错点：**（1）「LRU 用时间、LFU 用频率」——页面替换讨论的主角是 LRU 与 Clock，LFU 在 Cache 与数据库缓存更常见；（2）Clock 的「使用位」是硬件在每次访问时自动置 1（MMU 更新页表项），不是软件手动置的；（3）「缺页率」不是越小越好——为了极小缺页率无限加大物理内存会挤占其他进程，OS 的目标是「够用而不过量」。

## 5 页面替换的现实坐标- Linux 的页面回收器：**近似 LRU**（两个双向链表：活跃链表 + 非活跃链表，通过「页面在非活跃列表的驻留时间」近似 LRU），替代传统 Clock。
数据库缓冲池：LRU-K、Clock 变体，考虑访问频率与代价。
现代 OS 还会做「预读」（检测顺序访问提前调页）与「脏页异步写回」——在替换之前就优化，减少缺页处理成本。<span class="marginnote">Linux 的「双链 LRU」思想与 Clock 一脉相承：活跃链表装「近期访问的页」，非活跃链表装「候补」；页面从非活跃链表底部被回收。它比单比特 Clock 更接近真实 LRU，且实现仍是 O(1)。</span>

## 6 考点速记：页面替换四算法| 算法 | 策略 | 特点 |
| --- | --- | --- |
| OPT | 驱逐未来最久不用的 | 理论下界，不可实现 |
| FIFO | 驱逐最早进入的 | 简单，有 Belady 异常 |
| LRU | 驱逐最近最少用的 | 栈算法，现实中最好 |
| Clock | 环形扫描 + 使用位 | LRU 的一比特近似 |

**五条必记**：
- Belady 异常：FIFO 增大容量反而缺页增多；LRU/OPT 无此问题（栈算法）。
- Clock 的「二次机会」：使用位为 1 置 0 放行，为 0 才驱逐。
- 抖动（thrashing）：工作集超载，频繁缺页、吞吐崩溃——靠工作集模型治理。
- 缺页率 = 缺页次数 / 引用串长度；替换算法优劣是平均意义。
- 现代 Linux 用「活跃/非活跃双链表」近似 LRU，思想源自 Clock。

**辨析｜易错点**：LRU 看「多久没碰」（时间），LFU 看「总共碰几次」（频率）——「最近最少使用」与「最不经常使用」一字之差。

## 7 小结- **OPT**（理论下界，不可实现）、**FIFO**（简单、有 Belady 异常）、**LRU**（最优实践、栈算法、成本高）、**Clock**（LRU 的一比特近似，环形扫描 + 二次机会）。
- **Belady 异常**：FIFO 下增大容量反而缺页更多；LRU/OPT 无此问题。
- **抖动**：活跃页集超载导致频繁缺页、吞吐崩溃；靠工作集模型与局部替换治理。
- 缺页率公式：$F/N$；替换算法优劣是平均意义，不是逐串保证。
- 现代 OS（Linux）用双链表近似 LRU，思想源自 Clock。

- OPT 理论下界、不可实现
- FIFO 有 Belady 异常
- LRU 栈算法、现实中最好
- Clock 二次机会近似 LRU
- 抖动 = 工作集超载
- Linux 双链表近似 LRU
- LFU 老热块赖着不走
- 缺页率 = 缺页/引用串
