## 从 DMA 到通道：一次「委托」的升级

DMA 每次传输都要 CPU 配置，传大文件时 CPU 要反复「布置任务」。**通道（channel）** 更进一步：通道是**专门负责 I/O 的处理器**，CPU 只需下发一条「I/O 指令」（读文件、写块），通道自己执行**通道程序**管理一组设备完成传输。本课讲通道的概念、三种通道类型与通道的工作过程——它是 I/O 方式的收官之课。<span class="marginnote">「通道」在大型机（IBM 360/370）里是标配：一台大型机有多个通道，每个通道管理一群设备，CPU 只发「命令」、通道执行「程序」。DMA 是「一次传输的委托」，通道是「一组 I/O 的委托」——委托粒度升级，CPU 进一步解放。</span>

## 1 通道的基本概念**核心概念：通道（channel）**——具有执行 I/O 指令能力的**专用处理器**，负责控制一台或多台外部设备与主存交换数据。

- **CPU 与通道的关系**：CPU 发「I/O 指令」（启动通道），通道执行「通道程序」（通道自己会读的一段指令序列），完成后中断 CPU。
- **通道程序**：存在主存里，由通道指令组成（如「读 N 个字节到地址 A」「从设备 X 读到内存 Y」）。

$$\text{CPU：发 I/O 指令（启动）} \to \text{通道：执行通道程序} \to \text{中断通知 CPU（完成）}$$

**核心概念：通道是一台「会跑 I/O 程序的小电脑」**——它有自己的指令集（通道指令）、自己的程序（通道程序）、自己的执行器。<span class="marginnote">通道与 DMA 的本质区别：DMA 是「一个可配置的搬运器」（每次传输重新配置），通道是「一个能执行程序的处理器」（用通道程序描述一组传输）。通道能自动处理「读多个不连续块、错误重试」等复杂逻辑，DMA 要 CPU 反复配置才能做到。</span>

## 2 通道的三种类型按「通道与设备的关系」分三种：

| 类型 | 特点 | 适用 |
| --- | --- | --- |
| 字节多路通道 | 以字节为单位、分时共享，同时管理多台慢速设备 | 字符设备（终端、打印机） |
| 数组选择通道 | 一次连接一台高速设备，成块连续传输 | 磁盘等高速设备 |
| 数组多路通道 | 分时传输数据块，可同时管理多台高速设备 | 多磁盘系统 |

- **字节多路通道**：慢速设备轮流用，每次传一个字节就换下一个设备——多路复用。
- **数组选择通道**：一次只服务一台高速设备，传完一整块才换——「独占式」。
- **数组多路通道**：以「块」为单位分时复用——兼顾高速与多设备。

<span class="marginnote">「多路」= 一个通道管理多台设备（分时复用）。字节多路以字节分时（慢设备轮流），数组多路以块分时（快设备轮流）。选择通道最「笨」但最简单——一次只管一个快设备。大型机的通道架构就是这三种的组合配置。</span>

## 3 通道的工作过程一次完整的通道 I/O：

1. **CPU 下发 I/O 指令**：CPU 执行「启动 I/O」指令，通知通道开始。
2. **通道取通道程序**：通道从主存读取通道程序的第一条指令。
3. **通道执行通道程序**：逐条执行（读/写/跳转/测试），控制设备与主存交换数据。
4. **传输完成/出错**：通道向 CPU 发中断，报告结果。
5. **CPU 处理中断**：检查结果，继续后续工作。

$$\text{启动 I/O} \to \text{取通道程序} \to \text{执行通道程序} \to \text{中断（完成/出错）}$$

**核心概念：CPU 只在「启动」与「收尾」出现**——中间的通道程序执行完全由通道自己完成，CPU 彻底解放去算别的。<span class="marginnote">「通道程序」的存在让 CPU 与通道的交互频率降到「每次 I/O 任务一次」——比如读一个文件（可能涉及几十次磁盘访问），CPU 只发一次「读文件」指令，通道自己调度几十次磁盘传输。这就是大型机能支撑海量 I/O 的秘密。</span>

## 4 公式解析：通道方式的 CPU 占用设通道执行通道程序（含设备传输）耗时 $T_{ch}$、每次 I/O 任务 CPU 发指令 + 收中断 $T_{cpu}$：

$$\text{CPU 占用} = \frac{T_{cpu}}{T_{ch}}$$

逐项拆解：

- **第一步，CPU 参与时间**：启动指令 + 完成中断处理，固定且很小。
- **第二步，通道工作时间**：整个通道程序的执行，CPU 完全不参与。
- **第三步，占比**：CPU 占用 = CPU 参与 / 通道总时间——**通道程序越长，CPU 占用越低**。

例：读文件 $T_{ch}=10$ms、CPU 参与 $20\mu s$：占用 = 0.2%——CPU 几乎零负担。

**核心结论：通道把 CPU 占用压到「每次 I/O 任务」级别**——CPU 与 I/O 的耦合被降到最低。<span class="marginnote">对比：程序查询 100% 占用、中断约每字节一次、DMA 每块一次、通道每次任务一次。CPU 与设备的「打扰频率」逐级降低——这就是 I/O 方式演进的主线（从查询到通道，CPU 越来越解放）。</span>

## 5 辨析｜易错点：通道概念**辨析｜易错点：**

- **通道是处理器，不是接口**：通道有自己的指令与执行逻辑；接口是通道与设备之间的适配层。
- **通道程序存在主存**：不是存在通道内部——通道像 CPU 一样从主存取指令执行。
- **通道方式 = DMA 的推广**：DMA 是「一次传输」，通道是「一组传输（通道程序）」——通道可以管理多次 DMA 式传输。
- **现代 PC 没有独立通道硬件**：通道思想被「智能 DMA 引擎 + 中断控制器 + CPU 里的设备驱动」取代——大型机的通道理念活在现代 I/O 栈里。

## 6 拓展：通道与 DMA 的「委托粒度」通道与 DMA 都是「CPU 少参与」，区别在委托粒度：

- **DMA**：一次传输——CPU 配置 AR/WC，DMAC 搬一块，中断完事。
- **通道**：一组传输——CPU 发一条「I/O 指令」，通道执行通道程序，程序里可能包含「读块 A、跳转、读块 B、校验」等多步。

**核心概念：DMA 是「一次搬运的委托」，通道是「一组 I/O 的委托」**——通道程序让「多步 I/O」也能脱离 CPU 执行，这是大型机能支撑海量外设的原因。

**辨析｜易错点：**「通道程序存在哪？」——存在**主存**里，通道像 CPU 一样从主存取指令执行。不是存在通道内部。「通道有自己的指令集」——通道指令（读、写、控制、转移）与 CPU 指令完全不同。

## 7 拓展：通道速记**五条必记**：
- 通道 = 执行通道程序的专用 I/O 处理器，CPU 只发启动指令。
- 三种类型：字节多路（慢速分时）、数组选择（高速独占）、数组多路（高速分时）。
- 流程：启动 I/O → 取通道程序 → 执行 → 中断完成。
- 通道程序存在主存，通道像 CPU 一样取指令。
- CPU 占用 = CPU 参与/通道时间，接近零负担。

**辨析｜易错点**：DMA 是「一次传输委托」，通道是「一组 I/O 委托」——委托粒度不同。

## 9 小结- **通道**：执行通道程序的专用 I/O 处理器，CPU 只发启动指令、收完成中断。
- 三种类型：**字节多路**（慢速分时）、**数组选择**（高速独占）、**数组多路**（高速分时）。
- 工作过程：启动 I/O → 取通道程序 → 执行 → 中断完成。
- CPU 占用 = CPU 参与/通道时间——每次任务一次，接近零负担。
- 通道是 I/O 演进的终点：查询 → 中断 → DMA → 通道，CPU 逐级解放。
