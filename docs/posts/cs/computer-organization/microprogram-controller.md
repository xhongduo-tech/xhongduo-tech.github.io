## 为什么微程序控制器需要「自己的 PC」

上一课认识了微指令与微程序；本课把它们装进一台完整的机器——**微程序控制器**。它包含控制存储器（存微指令）、微指令地址寄存器（μPC/CMAR，存下一条微指令地址）、微指令寄存器（μIR/CMDR，存当前微指令）等部件。它几乎是一台微缩版 CPU：**有「内存」（控制存储器）、有「PC」（μPC）、有「IR」（μIR）**。理解这台「机器中的机器」，就掌握了微程序控制的全部工作机理。<span class="marginnote">对照上一课：硬布线控制器是「组合逻辑算信号」，微程序控制器是「存储程序查信号」。微程序控制器的结构就是「用冯·诺依曼机器的部件，重新实现了一遍控制逻辑」——递归之美。</span>

## 1 微程序控制器的组成微程序控制器的核心部件：

| 部件 | 作用 | 类比 |
| --- | --- | --- |
| 控制存储器 CS | 存全部微程序（微指令） | 主存 |
| 微指令地址寄存器 μPC（CMAR） | 存下一条微指令地址 | PC |
| 微指令寄存器 μIR（CMDR） | 存当前微指令 | IR |
| 微地址形成逻辑 | 由操作码/标志生成下一条微指令地址 | 控制器 |

**核心概念：一次「机器指令执行」的宏观流程**——操作码 → 微地址形成逻辑 → μPC → 读 CS → μIR → 执行微操作 → 更新 μPC → 下一条微指令。

<span class="marginnote">「μ」是 micro 的缩写，读作「缪」。教材里 μPC、μIR、CMAR、CMDR 几个记号并存，考试认准一个体系即可——核心是「微指令地址寄存器」与「微指令寄存器」这两个角色。</span>

## 2 工作原理：一条机器指令的微程序之旅以执行一条 `ADD` 指令为例：

1. **取指微程序**（所有指令共用）：按 PC 从主存取出指令送 IR，PC 加 1 指向下一条。
2. **映射**：微地址形成逻辑根据 IR 操作码，算出 `ADD` 指令微程序的首地址。
3. **执行微程序**：逐条把 μPC 所指的微指令读入 μIR，译出控制信号，控制数据通路完成加法并把结果写回目的寄存器。
4. **返回**：微程序末位给出「取指微程序首地址」，回到第 1 步。

```asm
; 取指微程序（所有指令共享）
Fetch: MAR ← PC                ; 送主存地址
       MDR ← M[MAR]            ; 取指令
       IR ← MDR; PC ← PC + 1   ; 送 IR，PC 指向下一条
       μPC ← Map(IR)           ; 按操作码分叉到指令微程序

; ADD 指令微程序
Add:   ALU ← R[rs1] + R[rs2]   ; 执行加法
       R[rd] ← ALU             ; 结果写回目的寄存器
       μPC ← FetchAddr         ; 返回取指微程序首地址
```

**重点：取指微程序是所有指令共享的**——它不因指令而异，执行完取指后根据操作码「分叉」到各自微程序。<span class="marginnote">这就是微程序控制的核心巧思：<strong>公共微程序（取指、间址、中断）共享，指令特异的微程序分叉</strong>。它让控制存储器的容量大大节省——几百条指令共享几段公共微程序。</span>

## 3 公式解析：控制存储器的地址组织设控制存储器容量 $N$ 字，微指令地址寄存器 $\mu PC$ 宽 $k$ 位：

$$k = \lceil \log_2 N \rceil$$

微程序在控制存储器中的组织：

- **取指微程序**：固定在某段地址（如 `0` 号单元起始）。
- **各指令微程序**：由操作码映射到各自的起始地址。
- **微程序内**：顺序执行（μPC+1）或条件转移（微分支）。

逐项拆解：

- **第一步，容量→地址位**：$N=256$ 字则 $\mu PC$ 8 位。
- **第二步，布局**：公共微程序放低地址段，指令微程序按操作码映射。
- **第三步，取指循环**：每条微程序最后一条微指令把「取指微程序首地址」写入 μPC——回到循环起点。

**核心结论：微程序控制器的运行 = μPC 在控制存储器里的「游历」**——从取指微程序出发，分叉到指令微程序，执行完再回到取指。<span class="marginnote">「微程序如何结束」是个设计细节：常用「微指令末尾的下地址字段直接给出下一条微指令地址」，或专门设一条「转回取指」的微指令。这也引出下一课《微指令的编码方式》——下地址怎么表达。</span>

## 4 与硬布线控制器的分工微程序控制器与硬布线并非水火不容，现实系统常混合：

**简单高频指令**（MOV、ADD）：硬布线快速路径。
**复杂低频指令**（字符串操作、浮点特殊处理）：微程序慢速路径。

**核心概念：现代 CPU 的「微码 + 硬布线混合」**——x86 用硬布线处理常见指令，用微码（microcode）处理复杂指令；微码还能被更新（microcode patch）修复 bug——这是硬布线做不到的灵活性。<span class="marginnote">现代 CPU 的「微码」是活的：Intel/AMD 会通过 BIOS 更新发布微码补丁修复 CPU 硬件 bug（如 2018 年的 Meltdown/Spectre 缓解）。「控制逻辑可升级」是微程序控制留给世界的遗产。</span>

## 5 辨析｜易错点：微程序控制器组成要点**辨析｜易错点：**

- **μPC 与 PC 是两回事**：PC 指向主存里的机器指令，μPC 指向控制存储器里的微指令——两个「程序计数器」，管两套存储。
- **控制存储器可写吗**：多数是只读（ROM），但现代 CPU 允许「微码更新」——所以在出厂后仍可写（特殊机制）。
- **微指令的执行也有周期**：取微指令 + 执行微指令，可重叠（流水线）。
- **微程序控制比硬布线慢的根源**：每次执行微操作都要「读控制存储器」——一次访存比门电路慢。

## 6 拓展：微程序与硬布线的「混合分工」现代 CPU 不是纯微程序或纯硬布线，而是按指令频率分工：- **高频简单指令**（MOV、ADD、JMP）：硬布线快速路径——解码快、执行快。
- **低频复杂指令**（字符串、浮点特殊处理、特权指令）：微码路径——靠微程序组合实现。

**核心概念：按「二八定律」分工**——80% 的执行时间跑在 20% 的简单指令上，给它们硬布线速度；20% 的复杂指令用微码保证「能实现且可维护」。

**辨析｜易错点：**「微程序 = 软件实现指令」的说法不准确——微程序是**硬件里的存储逻辑**（控制存储器 + 执行器），不是运行在 CPU 上的软件程序。它比硬布线慢，但仍是硬件机制。「微码可更新」让它兼具软件的灵活性，但本质是硬件。
