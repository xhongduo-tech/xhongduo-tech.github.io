## 为什么要把存储器堆成金字塔

没有任何一种存储技术能同时做到「快、大、便宜」。但程序运行需要的是「又快又大又便宜」的存储——于是硬件工程师想出一个折中：**把多种存储器按速度与容量排列成层次**，快的做小、慢的做大，数据在层间流动，让 CPU 大部分时间都命中最快的那层。这就是**存储器层次结构（memory hierarchy）**，它是本专题最重要的框架之一，也是后文 Cache 与虚拟内存的总纲。<span class="marginnote">「层次结构是计算机性能的秘密」——Hennessy 与 Patterson 在《计算机体系结构》里称它为「无可争议的至尊设计思想」。现代 CPU 性能远超主存速度，全靠这层金字塔撑着。</span>

## 1 层次结构的分层从 CPU 往外，典型的层次（越快越贵越小，越慢越便宜越大）：

| 层次 | 典型技术 | 容量 | 访问时间（约） | 管理方式 |
| --- | --- | --- | --- | --- |
| 寄存器 | SRAM | < 1 KB | < 1 ns | 编译器显式管理 |
| Cache | SRAM | KB–MB | 1–10 ns | 硬件自动管理 |
| 主存 | DRAM | GB | 50–100 ns | 操作系统（虚拟内存） |
| 本地辅存 | SSD/磁盘 | TB | 0.1–10 ms | 操作系统文件系统 |
| 远程存储 | 网络/云 | PB | 数十 ms | 网络协议 |

每往下一层，访问时间大约增大一个数量级，容量增大两个数量级。<span class="marginnote">「快 10 倍、大 100 倍」是层次结构的经验比例（H&P 的观察）。从寄存器到远程存储，总跨度达 7–10 个数量级——这是计算机体系结构里最大的数量级跨度。</span>

## 2 两个层次之间的服务关系层次结构的基本工作模式是「缓存」：**上层是下层的缓存，下层是上层的后备**。

- CPU 要数据，先找寄存器 → Cache → 主存 → 辅存，逐层向上「请求」。
- 每层的职责是：**命中**（数据在本层）就直接返回；**缺失**（不在本层）就向下一层取，同时在本层留一份副本，供下次命中。

**核心概念：命中（hit）与缺失（miss）**：

- 命中率 $h$ = 命中的访问次数 / 总访问次数。
- 缺失率 $1-h$ 越接近 0，整体性能越接近「最上层 + 次层」的速度。

这套「缺失时取数并留副本」的机制在 Cache（硬件）与虚拟内存（操作系统）里是同一个抽象——**下一层永远是上一层的「更慢更大的备份」**。<span class="marginnote">把层次结构想成「图书馆查书」：书桌（寄存器）放常用的书，书架（Cache）放常借的，总馆（主存）是主库，远程书库（辅存）是后备。借不到就往下一级找，找到后也顺手带一份到书桌。</span>

## 3 公式解析：平均访问时间设两级存储器，上层访问时间 $t_1$，下层 $t_2$，命中率 $h$，则**平均访问时间**：

$$T_{\text{avg}} = h \cdot t_1 + (1-h) \cdot (t_1 + t_2)$$

$$T_{\text{avg}} = t_1 + (1-h) \cdot t_2$$

逐项拆解：

- **第一步，命中路径**：命中的访问时间是 $t_1$（只需访问上层）。
- **第二步，缺失路径**：缺失要先访问上层确认缺失（花 $t_1$，但通常忽略），再访问下层（花 $t_2$）。
- **第三步，加权**：命中概率 $h$ 乘命中时间，缺失概率 $(1-h)$ 乘缺失时间。
- **第四步，化简**：$T_{\text{avg}} = t_1 + (1-h)t_2$——直观解读：**每个访问都要付上层时间，只有缺失才额外付下层时间**。

例：$t_1 = 1\text{ns}$，$t_2 = 100\text{ns}$，$h = 0.98$：$T_{\text{avg}} = 1 + 0.02\times100 = 3\text{ns}$——平均访问比主存快 33 倍！<span class="marginnote">这个公式揭示了命中的威力：98% 的命中率就把「100ns 的主存」伪装成「3ns 的平均访问」。而命中率从 98% 降到 90%，平均时间变成 11ns——<strong>缓存性能对命中率极度敏感</strong>，这就是为什么局部性如此重要。</span>

## 4 三个关键数量级事实层次结构之所以有效，靠三个「程序行为的经验法则」：

- **局部性**：程序在某一小段时间内只访问一小块地址空间（下一课专讲）。
- **时间局部性**：刚访问的数据很快会被再访问（循环变量、热门项）。
- **空间局部性**：被访问数据附近的数据很快会被访问（数组、顺序代码）。

**重点：层次结构把「程序倾向访问一小块」与「上层只存得下一小块」完美对接**——只要上层能装下程序的活跃子集，命中率就很高。这解释了为什么「无限大的缓存做不到，99% 命中的缓存却做得到」。<span class="marginnote">机器学习的训练循环是局部性的极好例证：权重矩阵反复被遍历（时间局部性），一个 batch 按连续内存布局读取（空间局部性）——所以 GPU 的缓存层次 + 显存带宽能撑起深度学习。通往第四级《AI 基础设施》的访存优化。</span>

## 5 辨析｜易错点：层次结构认知误区**辨析｜易错点：**

- **层次结构不是「每个程序自己选层」**：寄存器由编译器分配，Cache 由硬件自动管理，主存由操作系统（虚拟内存）管理——各层管理方不同。
- **「辅存存的是主存的副本」与「主存存辅存的副本」是同一个关系**：层次结构是双向的「缓存」关系，上层是下层的副本（Cache 是主存的副本、主存是磁盘的副本）。
- **容量从上往下单调递增，速度单调递减**：不能出现「上层比下层慢」或「上层比下层大」的倒挂。
- **层次越多，平均访问时间越接近最快层，但管理开销越大**：现代 CPU 有 2–3 级 Cache + TLB + 虚拟内存，层次深度是工程权衡。

## 6 拓展：层级命中率的「两个事实」关于存储器层次结构，两个反直觉但重要的事实：**事实一：容量每降一级，命中率收益巨大。** 程序的工作集（活跃数据）通常只有几 MB——64KB 的 L1 可能只有 80% 命中，1MB 的 L2 达到 95%，32MB 的 L3 超过 99%。每层「接住」上一层的漏网之鱼。

**事实二：缺失代价决定了层级该多深。** 现代 CPU 的 L3 缺失要访问主存（100 周期）、主存缺失要访问磁盘（千万周期）——每往下一层，代价数量级上升，所以每一层都要尽量把命中率做到「够高」。

**核心概念：层次结构的设计公式是「层级数 × 各级容量」要匹配程序的工作集分布**——工作集大（大数据库）则 L3 要大，工作集小（嵌入式循环）则 L1 够用。

**辨析｜易错点：**「多级 Cache = 容量相加」是片面的——各级 Cache 是「不同速度层」而非「同池容量」；L2 是 L1 缺失的后备，不是 L1 的补充。

## 9 小结- **存储器层次结构**：寄存器 → Cache → 主存 → 辅存 → 远程，速度递减、容量递增。
- 上层是下层的**缓存**：命中直接返回，缺失向下一层取并留副本。
- **平均访问时间** $T_{\text{avg}} = t_1 + (1-h)t_2$，命中率是性能杠杆。
- 层次结构依赖**局部性**：程序活跃子集小，上层装得下，命中率高。
- 各层管理方不同：编译器（寄存器）、硬件（Cache）、操作系统（主存/虚拟内存）。
