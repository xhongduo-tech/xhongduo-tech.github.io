## 为什么「数据往哪走」比「做什么」更接近硬件

上一课知道指令周期分取指、间址、执行、中断四个子周期；本课回答更细的问题：**每个子周期里，数据具体经过哪些部件、以什么顺序流动？** 这就是**数据流分析**。画数据流图、写「寄存器传送」（register transfer）是组成原理的看家本领——它把「一条指令」翻译成「一系列微操作」，是理解数据通路与微程序控制器的桥梁。<span class="marginnote">「数据流分析」的产物是寄存器传送级（RTL）描述：如 `MAR←PC; IR←M(MAR); PC←PC+1`。它介于「指令级」与「电路级」之间，是数字系统设计（Verilog 描述）与控制器设计的共同语言。</span>

## 1 取指周期的数据流取指周期把指令从内存搬到 IR，数据流如下：

$$\text{PC} \to \text{MAR} \to \text{地址总线} \to \text{主存}$$

$$\text{主存} \to \text{数据总线} \to \text{MDR} \to \text{IR}$$

$$\text{PC} \leftarrow \text{PC} + 1 \ (\text{或} +L)$$

**关键动作**（RTL 写法）：

1. **送地址（PC → MAR）**：PC 内容送 MAR，地址送上地址总线。
2. **读指令（M(MAR) → MDR → IR）**：主存按 MAR 寻址，经 MDR 把指令送进 IR。
3. **PC 自增（PC + 1 → PC）**：PC 自增，指向下一条。

**核心概念：寄存器传送（register transfer）**——`A ← B` 表示「把 B 的内容送到 A」，是描述数据流的最小动作。控制器就是按节拍逐个触发这些传送。<span class="marginnote">取指周期结束后，指令已在 IR 中「待命」，PC 已指向下一条——这个「取指即推进 PC」的顺序保证执行期间 PC 不再变化，中断保存的返回地址也正确。数据流分析的价值，就是把这种「先后顺序」说得明明白白。</span>

## 2 间址周期的数据流间址周期取「操作数地址」：

$$\text{IR 地址码} \to \text{MAR} \to \text{主存} \to \text{MDR} \to \text{有效地址寄存器/送回 IR 地址码区}$$

RTL：

1. **送间接地址（IR(地址码) → MAR）**：把指令里的「地址的地址」送 MAR。
2. **读有效地址（M(MAR) → MDR → 有效地址）**：读主存，得到真正的操作数地址。
3. **有效地址送寄存器** 或写回：有效地址送入地址寄存器（或暂存）。

**重点：间址周期是「用地址去取地址」**——它多的一次访存，正是间接寻址慢的原因。<span class="marginnote">间址周期结束后，有效地址已经就位，执行周期直接用这个地址访存取操作数。注意：间址周期与执行周期共享「访存」硬件，所以它们不能重叠——这也解释了为什么间接寻址指令周期数更多。</span>

## 3 执行周期与中断周期的数据流### 执行周期

执行周期的数据流**因指令而异**。以 **ADD X（一地址，累加器）** 为例：

$$\text{MAR} \leftarrow \text{有效地址}, \quad \text{MDR} \leftarrow M(\text{MAR})$$

$$\text{ALU} \leftarrow (\text{ACC}) + (\text{MDR}), \quad \text{ACC} \leftarrow \text{ALU 结果}$$

RTL 链：访存取操作数 → 送 ALU → 与 ACC 相加 → 结果写回 ACC。

### 中断周期

$$\text{栈指针 SP} \to \text{MAR}, \quad \text{MDR} \leftarrow \text{PC}, \quad M(\text{SP}) \leftarrow \text{MDR}$$

$$\text{PC} \leftarrow \text{中断入口地址}$$

RTL 链：PC 压栈（保存返回地址）→ 置中断允许位 → 改 PC 为服务程序入口。<span class="marginnote">「执行周期的数据流因指令而异」是控制器复杂度的来源：不同指令要触发不同的传送序列。硬布线控制器用状态机逐个节拍触发；微程序控制器则把每个传送序列存成一条「微程序」——这是第五篇后半的核心。</span>

## 4 公式解析：数据流分析的通用框架把任意子周期数据流统一成「源 → 通路 → 目的」三步：

$$\text{目的寄存器} \leftarrow f(\text{源寄存器}_1, \text{源寄存器}_2, \ldots)$$

例：取指周期 = $\text{IR} \leftarrow f(\text{MAR}, \text{主存})$；执行周期 = $\text{ACC} \leftarrow g(\text{ACC}, \text{MDR})$。

逐项拆解：

- **第一步，识别源**：数据从哪些部件出来（PC、IR、MDR、ACC、主存）。
- **第二步，识别通路**：经过什么总线/部件（ALU、数据总线、地址总线）。
- **第三步，识别目的**：写到哪个寄存器。
- **第四步，写 RTL**：目的 ← f(源)，一条数据流一条 RTL。

**核心结论：数据流分析 = 用 RTL 语言重写指令周期的每个子周期**——它把「指令」分解成可硬件实现的微操作序列。<span class="marginnote">这个「指令 → RTL → 微操作 → 控制信号」的逐级分解，正是微程序控制器的设计路线。反过来，读硬布线控制器的状态图，也是从 RTL 反推。掌握 RTL，第五篇后半的控制器设计就有了语言。</span>

## 5 辨析｜易错点：数据流分析易错点**辨析｜易错点：**

- **读操作的中间寄存器**：读主存是「MDR ← M(MAR)」，写主存是「M(MAR) ← MDR」——方向别写反。
- **PC 自增的时机**：取指周期内完成 PC ← PC + 1，不要等到执行周期——否则中断保存的返回地址会错。
- **间址周期的地址来源**：来自 **IR 的地址码字段**，不是来自 PC。
- **不要混淆「地址」与「数据」**：MAR 装地址、MDR 装数据，两条通路别画串。

## 6 拓展：RTL 数据流速记**五条必记**：
- 取指：MAR←PC → IR←M(MAR) → PC←PC+L。
- 间址：MAR←IR(地址码) → 有效地址←M(MAR)。
- 执行：因指令而异，如 ACC←ALU(ACC, MDR)。
- 中断：PC 压栈 → PC←服务程序入口。
- 读主存是 MDR←M(MAR)，写是 M(MAR)←MDR——方向别反。

**辨析｜易错点**：PC 自增在取指周期内完成，不要拖到执行——否则中断保存的返回地址会错。

## 7 一句话回顾- 取指：MAR←PC → IR←M(MAR) → PC+L。
- 间址：MAR←IR(地址码)。
- 读 MDR←M(MAR)、写 M(MAR)←MDR。

## 8 核心公式
- 取指：MAR←PC → IR←M(MAR) → PC←PC+L。
- 间址：MAR←IR(地址码) → 有效地址←M(MAR)。
- 执行：ACC←ALU(ACC, MDR)（一地址 ADD）。
- 中断：PC 压栈 → PC←入口。

## 9 小结- 数据流分析的产物是 **RTL（寄存器传送）** 描述：如 `MAR←PC; IR←M(MAR); PC←PC+1`。
- **取指**：MAR←PC → IR←M(MAR) → PC←PC+L。
- **间址**：MAR←IR(地址码) → 有效地址 ← M(MAR)。
- **执行**：因指令而异，如 ACC←ALU(ACC, MDR)。
- **中断**：PC 压栈 → 改 PC 为服务程序入口。
- RTL 是把「指令」翻译成「微操作序列」的桥梁，也是控制器设计的语言。
