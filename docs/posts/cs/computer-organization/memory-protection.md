## 为什么「程序可以任意访问内存」是危险的

如果没有存储保护，任何程序都能读写整个物理内存——读走别的进程的密码、把自己的数据写进内核、甚至篡改另一进程的代码。现代系统的防线由硬件（MMU/页表）与操作系统（权限设置）共同构筑：**每个进程都活在虚拟地址空间的结界里**，越界与越权访问会被硬件当场拦下并触发异常。本课讲两类保护——**越界保护**（地址是否合法）与**访问权限保护**（操作是否被允许），以及它们在现代安全中的角色。<span class="marginnote">存储保护是「进程隔离」的物理实现，也是「沙箱」「虚拟机」等一切隔离技术的地基。没有它，一个 bug 就能让整个系统崩溃或被攻破——WannaCry 等蠕虫正是利用了内存保护被绕过（ROP 攻击）才得以传播。</span>

## 1 越界保护：地址合法性**越界保护（bounds checking）**：检查程序要访问的地址是否落在**允许的范围内**。

两种实现思路：

**基址-限长（base-limit）**：寄存器保存「段的基址」与「段的限长」，访问地址必须在 $[\text{base}, \text{base}+\text{limit})$ 内。分段结构天然支持。
**分页的越界检查**：页表项的有效位已经隐含了「这个虚拟页是否分配」。访问未分配的页（PTE 无效）→ 段错误/无效访问。

**核心概念：无效访问（invalid access）**：虚拟页未分配或地址越界，MMU 拦截并触发异常（x86 的页面错误 / 段错误）。<span class="marginnote">「越界」是分页与分段都有的检查：分段靠 limit 比较，分页靠 PTE 有效位。C 语言的野指针（dangling pointer，指向已释放或未分配内存）最终都会撞上这道硬件防线——只不过撞上时程序已经出错了，越界保护只是「让它崩溃得干脆」。</span>

## 2 访问权限保护：操作合法性即使地址合法，操作本身也可能不被允许。**访问权限（permission）**由页表项/段表项的权限位控制：

**读权限（R）**：可否读该页。
**写权限（W）**：可否写该页。
**执行权限（X）**：可否取指执行该页内容。

典型设置：代码段 R+X、数据段 R+W、堆栈 R+W（且通常禁止执行）。

**重点：权限检查在每次访问时由 MMU 完成**——取指时查 X 位，读时查 R 位，写时查 W 位。违反即触发**保护异常（protection fault）**。

**现代安全意义**：
**NX（No-eXecute）/DEP**：禁止数据页可执行，阻止「在栈上注入代码并执行」的经典攻击。
**ASLR（地址空间随机化）**：随机化进程地址布局，让攻击者难以预测目标地址——配合 NX，构成现代内存安全的两道防线。<span class="marginnote">NX 把「数据不可执行」变成硬件强制：即使攻击者把 shellcode 写进缓冲区，CPU 取指时也会因 X 位为 0 直接拒绝。这是 x86 的 NX 与 ARM 的 XN，今天所有主流 OS 默认开启。</span>

## 3 特权级与内核/用户隔离存储保护还有一个维度：**特权级（privilege level）**。

**内核模式（ring 0 / supervisor）**：可访问全部内存与特权指令。
**用户模式（ring 3 / user）**：只能访问自己的地址空间，访问内核区或执行特权指令 → 异常。

**核心概念：内核地址空间与用户地址空间分离**——现代 OS 把虚拟地址空间高位留给内核（如 Linux 的 `0x0000800000000000`（2⁴⁷ 分界）以上），用户态访问该区域触发保护异常。这就是「为什么应用程序崩溃不会拖垮操作系统」的根基。<span class="marginnote">x86 有 4 个特权环（ring 0–3），OS 实际只用 0（内核）与 3（用户）。特权切换（用户→内核）必须通过<strong>系统调用（syscall）</strong>，它既是功能的入口，也是权限的闸门——用户态永远无法直接碰内核的数据结构。</span>

## 4 公式解析：保护的实现层次存储保护由「硬件检查 + 软件设置」双层完成，可概括为：

$$\text{访问合法} \iff \text{地址在范围内} \wedge \text{操作符合权限} \wedge \text{特权级足够}$$

逐项拆解：

- **第一步，地址检查**：虚拟页是否分配（有效位）/ 偏移是否越段（limit）——越界保护。
- **第二步，权限检查**：读/写/执行是否被 PTE 权限位允许——访问权限保护。
- **第三步，特权检查**：当前 CPU 特权级是否足够（内核区只有 ring 0 可进）。
- **第四步，任一失败** → 触发异常 → 操作系统接管 → 通常是「终止进程」（段错误）。

**核心结论：一次访存要过三道检查**，三道都过才真正访问物理内存。<span class="marginnote">这套「三道检查」全部在 MMU 的地址翻译路径上完成，不额外耗时——保护是「免费」的，因为它焊在翻译硬件里。这就是为什么虚拟内存既提供隔离又几乎不拖慢访问。</span>

## 5 辨析｜易错点：保护相关概念**辨析｜易错点：**

- **越界 ≠ 越权**：越界是「地址不对」（未分配/超限），越权是「操作不对」（只读页被写）。一个管空间，一个管行为。
- **段错误（segmentation fault）是「结果」不是「机制」**：它是越界/越权被拦截后操作系统的处理结果（终止进程）。机制是 MMU 异常。
- **NX 防的是「执行」，不是「写」**：缓冲区溢出攻击写数据页没问题，但执行被 NX 拦下——所以现代攻击转向 ROP（重用已有代码），这又引出了新的缓解（ASLR、CFI）。
- **用户态程序「看不到」内核**：不是「碰不到」，是「碰到就异常」。内核数据在用户虚拟地址空间里根本不存在映射。

## 6 拓展：一个「三道检查」的完整例子
设某进程要读虚拟地址 `0x400000`（代码段第一页内），逐道检查：
- **第一道，地址检查**：页表查该虚拟页——有效位为 1（已分配），地址合法。
- **第二道，权限检查**：该页权限位是「R+X」（代码页）——读允许，写则拒绝。
- **第三道，特权检查**：当前是用户态（ring 3），而该页在用户空间——允许访问。
- 三道全过 → MMU 翻译出物理地址，读取成功。

若同一进程要**写** `0x400000`：第二道失败（代码页只读）→ 触发保护异常 → 操作系统终止进程（分段错误）。

**核心结论：一次访存的三道检查全在地址翻译路径上完成，零额外耗时**——保护是「免费」的，这是虚拟内存设计最优雅之处。

**辨析｜易错点：**段错误（segfault）是「结果」不是「机制」——机制是 MMU 的越界/越权异常，结果是操作系统杀掉进程。用户态「看不到」内核不只是「权限不够」，更是「内核虚拟页根本没有映射进用户地址空间」。

## 7 拓展：保护的三道检查一次访存过三道：地址检查（有效位/限长）→ 权限检查（R/W/X）→ 特权检查（ring 0/3）。

**五条必记**：
- 越界 ≠ 越权：地址不对 vs 操作不对。
- 段错误是「结果」，机制是 MMU 异常。
- NX 防「执行」不防「写」——攻击转向 ROP。
- 用户态「看不到」内核 = 内核页根本没映射进用户空间。
- 保护免费——焊在地址翻译路径上，零额外耗时。

**辨析｜易错点**：读（R+X 页）合法、写非法——同一地址不同操作结果不同。

- NX 防执行不防写。

## 9 小结- **越界保护**：基址-限长（分段）或 PTE 有效位（分页），管地址合法性。
- **访问权限保护**：PTE 的 R/W/X 位，管操作合法性；NX/DEP 阻止数据页执行。
- **特权级隔离**：内核/用户空间分离，系统调用是唯一的跨界入口。
- 一次访问过三道检查：**地址、权限、特权**，全在 MMU 翻译路径上完成。
- 保护是「免费的」——焊在翻译硬件里，为进程隔离与系统安全奠基。
