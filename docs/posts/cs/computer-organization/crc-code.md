## 为什么 CRC 是网络与存储的「事实标准」

海明码适合短数据的单错纠正，但以太网、Wi-Fi、硬盘、ZIP 压缩包需要检测的是**突发错误**——一个噪声脉冲可能连续翻转多位。**CRC（Cyclic Redundancy Check，循环冗余校验）**专治突发错误：它把一个数据块当做一个**二进制多项式**，用多项式除法求余数作为校验码，检错能力强、硬件实现只要移位寄存器和异或门，因此成为所有网络协议与存储介质的事实标准。<span class="marginnote">CRC 的检错能力与「生成多项式」直接相关：选得好，能检测所有奇数个错、所有长度 ≤ 生成多项式次数的突发错、以及 99.99…% 的其他错误模式。以太网用 32 位 CRC（CRC-32）。</span>

## 1 二进制多项式：数据的另一个身份**核心概念：二进制多项式（binary polynomial）**：把数据位看作多项式的系数，最高位对应最高次项。

$$110101 \;\longleftrightarrow\; x^5 + x^4 + x^2 + 1$$

**模 2 运算**：加法和减法都用异或（无进位、无借位），即 $x^a + x^a = 0$。这正是二进制多项式与普通算术多项式最大的不同——系数只取 0/1，加法即异或。<span class="marginnote">模 2 多项式运算里「减法 = 加法」：$x^5 - x^2 = x^5 + x^2$。这个性质让 CRC 的除法电路只需要异或门和移位寄存器，不需要借位逻辑——硬件极其简单。</span>

## 2 CRC 的编码过程设数据多项式 $M(x)$（数据位）、生成多项式 $G(x)$（次方为 $r$，即 $r+1$ 位，首尾为 1）：

1. **左移**：数据左移 $r$ 位（末尾补 $r$ 个 0），得到 $M(x) \cdot x^r$。
2. **相除**：计算 $M(x)\cdot x^r$ 除以 $G(x)$ 的**余数** $R(x)$（模 2 多项式除法）。
3. **拼接**：发送码字 $T(x) = M(x)\cdot x^r + R(x)$。

**关键性质**：$T(x)$ 恰好能被 $G(x)$ 整除（余数为 0）——因为 $M(x)x^r$ 的余数是 $R(x)$，加上 $R(x)$ 后整除。

接收方验证：把收到的码字除以同一个 $G(x)$，余数为 0 则无错，非 0 则有错。

### 例：$M = 110101$（6 位），$G = 1001$（$r=3$）

左移：$M \cdot x^3 = 110101000$（末尾补 3 个 0）。
模 2 除以 $G = 1001$：逐位异或长除。
余数：$R = 011$（3 位）。
发送：$T = 110101\;011$。<span class="marginnote">手算 CRC 容易错在「模 2 除法的对齐」：每次异或只从当前剩余的最高位开始，且商只在最高位为 1 时记 1——与普通长除法一致，只是减法换成异或。多练一遍比背步骤可靠。</span>

## 3 公式解析：CRC 校验为什么能检突发错误

CRC 能检测所有长度不超过 $r$ 的突发错误，原因是**错误多项式**的结构。设错误模式为 $E(x)$，接收方收到 $T(x) + E(x)$，校验等价于问「$E(x)$ 能否被 $G(x)$ 整除」。

$$E(x) = x^j (x^{l-1} + \cdots + 1)$$

逐项拆解：

- **第一步，建模**：长度 $l$ 的突发错误 = 连续 $l$ 位翻转，可写成某个低次多项式乘以 $x^j$（$x^j$ 表示突发发生在第 $j$ 位起）。
- **第二步，检错条件**：若 $E(x)$ 不能被 $G(x)$ 整除，则错误被检出。
- **第三步，分析长度**：当 $l \le r$ 时，$E(x)$ 的次数 $< r$，一个低次多项式不可能被高次（次数 $r$）的 $G(x)$ 整除——**所有长度 ≤ r 的突发错误必被检出**。
- **第四步，更长突发**：长度 $> r$ 的突发可能整除（漏检），但概率约为 $2^{-r}$（若 $G(x)$ 含因子 $x+1$ 还可多检奇数个错）。

**结论**：$r=32$ 的 CRC-32 能保证检测所有 ≤ 32 位的突发错误，更长的错误漏检概率仅约 $2^{-32}$。<span class="marginnote">对比奇偶校验「检不出偶数个错」的脆弱，CRC 的检错覆盖近乎完备，这正是它在网络/存储中不可替代的原因。常见生成多项式：CRC-16 0x8005、CRC-32 0x04C11DB7。</span>

## 3 生成多项式的选取原则$G(x)$ 的选择直接决定检错能力，经验法则：

**必须首尾为 1**：保证余数不会是「简单退化」。
**含因子 $(x+1)$**：能检出所有奇数个错误。
**不可约 / 本原多项式**：最大化检错覆盖。
工程常用：CRC-8（0x07）、CRC-16（0x8005）、CRC-32（0x04C11DB7，以太网、ZIP、PNG）。<span class="marginnote">「本原多项式」与《离散数学》里的有限域理论相关：本原多项式对应的 LFSR 周期最长。CRC 与 LFSR（线性反馈移位寄存器）在硬件上是同一回事——一节 CRC 电路本质上就是一个带反馈的移位寄存器。</span>

## 4 辨析｜易错点：CRC 与海明码、奇偶校验的对照| 维度 | 奇偶校验 | 海明码 | CRC |

| --- | --- | --- | --- |
| 冗余位 | 1 位 | 约 $\log_2 n$ 位 | 8/16/32 位 |
| 检错 | 奇数个错 | 1 位错 | 突发错 ≤ r 位 |
| 纠错 | 不能 | 能（单错） | 通常不纠错 |
| 硬件 | 异或树 | 组合逻辑 | LFSR 移位寄存器 |
| 适用 | 简单串行 | ECC 内存 | 网络帧、磁盘扇区 |

**辨析｜易错点：**（1）CRC **重在检错而非纠错**：发现错误就丢弃重传（网络）或报错（磁盘），不试图纠正——纠错成本太高；（2）CRC 的「循环」二字指编码的循环性质（任何循环移位仍满足某些性质），不是「循环执行」的意思；（3）模 2 除法**不是普通除法**，商不反映数值，只反映「异或消位」过程——别把商当有效信息。

## 5 拓展：CRC 与 LFSR 的硬件实现
CRC 的模 2 除法在硬件上用一个 **LFSR（线性反馈移位寄存器）** 实现——它让 CRC 的速度达到「每时钟周期处理一位」：
- 一个移位寄存器，某些级之间插入异或门，异或的「接法」由生成多项式决定。
- 数据逐位移入，经过 $r$ 次移位后，寄存器里的值就是余数（CRC 校验码）。

**核心概念：LFSR 把「多项式除法」变成「移位 + 异或」的流水操作**——这正是 CRC 能用于千兆级网络的原因：简单、快、且是纯硬件。

**辨析｜易错点：**CRC 与 LFSR 的对应：生成多项式 $x^3 + x + 1$ 对应「第 3 级和第 0 级反馈」。别把「多项式次数」与「寄存器级数」搞混——次数 r 对应 r 级 LFSR。

## 6 拓展：CRC 硬件与检错能力**五条必记**：
- LFSR 把多项式除法变成移位+异或，每周期一位。
- 检错：所有长度 ≤ r 的突发错误必检，更长漏检率约 2^-r。
- 生成多项式要求：首尾 1、含因子 (x+1)（检奇数个错）、不可约。
- CRC-32（0x04C11DB7）用于以太网/ZIP/PNG。
- CRC 重在检错不纠错，发现错误丢弃重传。

**辨析｜易错点**：CRC 的「循环」指编码的循环性质，不是「循环执行」；模 2 除法不是普通除法。

## 8 小结- CRC 把数据当**模 2 多项式**，用多项式除法求余作校验位。
- 编码：数据左移 $r$ 位 → 除 $G(x)$ 取余 → 拼接发送；接收端整除验证。
- 检错能力：**所有长度 ≤ r 的突发错误必检**，更长错误漏检概率约 $2^{-r}$。
- 生成多项式选法：首尾 1、含 $(x+1)$、不可约，工程用 CRC-8/16/32。
- CRC 检错不纠错，硬件是 LFSR，是网络与存储的事实标准。
