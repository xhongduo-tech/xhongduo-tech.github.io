## 为什么操作数有「类型」

同样一条指令，能加整数、浮点、地址、字符——但硬件对不同类型的数据做的是不同的事：整数加法要补码规则，浮点加法要对阶舍入，地址相加没有进位。所以**操作数类型（data type）决定了解释方式与运算规则**，**操作类型（operation type）决定了动作本身**。本课把操作数的常见类型与指令的操作分类讲清，让你对「指令系统有哪些牌」有完整地图。<span class="marginnote">「类型是解释层的约定」——同样的 32 位 0x3F800000，当整数是 1065353216，当 float 是 1.0。指令里没有类型标记，类型由操作码决定：ADD 与 FADD 暗示操作数分别是整数与浮点。这是「位型不变、解读可变」在指令层的体现。</span>

## 1 操作数类型机器能操作的基本数据类型：

| 类型 | 说明 | 典型长度 |
| --- | --- | --- |
| 无符号整数 | 地址、下标、位掩码 | 8/16/32/64 位 |
| 有符号整数（补码） | 普通算术 | 同上 |
| 浮点数 | IEEE 754 单/双精度 | 32/64 位 |
| 字符 | ASCII/Unicode | 8/16/32 位 |
| 布尔 | 位、位向量 | 1 位/寄存器宽 |
| 指针/地址 | 内存地址 | 字长 |

**重点：指令必须「知道」操作数类型**——这不是运行时动态判断，而是由**操作码静态决定**。IMUL（有符号乘）与 MUL（无符号乘）是两条不同的指令，同一串位按哪种解读由指令说了算。<span class="marginnote">编译器负责把高级语言的类型翻译成正确的指令：C 里有符号 int 的乘法用 imulq，无符号 unsigned 的乘法用 mulq。类型系统的很大一部分工作，就是在编译期选出「解读正确」的指令。</span>

## 2 操作类型：六大类指令按「做什么」分成六大类：

### 1. 数据传送
MOV、LOAD、STORE、PUSH/POP——在寄存器、内存、栈之间搬数据。**不改变数值，只改变位置**。

### 2. 算术逻辑
ADD/SUB（算术）、AND/OR/XOR（逻辑）、SHL/SHR（移位）——核心计算指令。

### 3. 移位与循环
逻辑移位、算术移位、循环移位——见《补码的移位运算》。

### 4. 控制转移
JMP（无条件跳转）、Jcc（条件跳转）、CALL（过程调用）、INT（软中断）——**改变程序计数器 PC**，是流程控制的基石。

### 5. 输入输出
IN/OUT——专用 I/O 指令（x86 的独立编址），或通过访存指令统一编址。

### 6. 其他
特权指令（仅在核心态可执行）、状态标志操作、系统调用等。<span class="marginnote">六大类里，「控制转移」最特殊：它改变的不是数据而是「下一句在哪」。所有高级语言的控制结构（if/for/while/函数调用）最终都翻译成控制转移指令——这是《指令寻址》与流水线分支预测的核心对象。</span>

## 3 数据传送指令的细节数据传送是最常见也最容易忽略的指令，有几个关键点：

**MOV 不改变源操作数**：MOV R1, R2 复制 R2 到 R1，R2 保持原值。
**Load/Store 架构**：RISC 用 LD/ST 显式访存，只有这两类指令能碰内存，算术只能在寄存器间做。
**Push/Pop**：栈操作隐含更新栈指针 SP。

**重点：RISC 的「访存必须走 LD/ST」限制**是理解 RISC 的关键——算术指令不进内存，寄存器才是指令的主舞台。<span class="marginnote">「Load/Store 架构」让 RISC 的指令格式高度规整：算术指令全是「寄存器三地址」，访存指令单独两类。CISC（x86）则允许 ADD 直接在内存上算——灵活，但解码复杂。</span>

## 4 公式解析：控制转移的地址计算控制转移指令的核心是**计算目标地址**。无条件跳转：

$$\text{PC}_{\text{new}} = \text{PC} + \text{offset}$$

$$\text{条件跳转：若条件成立，则 } \text{PC}_{\text{new}} = \text{PC} + \text{offset，否则继续}$$

逐项拆解：

- **第一步，相对跳转**：大多数分支用「相对偏移」，目标是 PC + offset（offset 有符号）。
- **第二步，为什么用相对**：代码无论装载到哪，分支关系不变——可重定位；且 offset 通常短，指令省位。
- **第三步，绝对跳转**：绝对跳转（JMP 到绝对地址）用于跨区跳转（函数指针、表驱动），需要寄存器/内存操作数。

**核心结论：控制转移的本质是「修改 PC」**，相对寻址让代码可重定位（与《链接与装载》的地址重定位思想一致）。<span class="marginnote">分支目标地址的取 PC 还是「当前指令地址」有细微差别：x86 的 PC 是「下一条指令地址」，所以偏移量（offset）实际是加在「本条指令地址 + 指令长度」之上的。不同 ISA 约定不同，汇编写偏移时要小心。</span>

## 5 辨析｜易错点：操作数与操作类型**辨析｜易错点：**

- **「指令类型」与「操作数类型」是两个维度**：加法指令（操作类型）可以对整数、浮点、地址（操作数类型）操作——类型决定解读，指令决定动作。
- **MOV 的「复制」语义**：MOV 不移动（源仍保留），英文 move 名不副实。
- **条件跳转不改变数据**：Jcc 只读标志寄存器决定跳不跳，不修改任何操作数。
- **逻辑运算（AND/OR/XOR）与算术运算（ADD/SUB）都作用于位**，但语义不同：逻辑按位独立，算术有进位/借位关联——指令译码会分别选通不同电路。

## 6 考点速记：操作数与操作类型**操作数类型**：整数（无符号/补码）、浮点、字符、布尔、地址——类型由**操作码静态决定**解读方式。

**六大操作类型**：

1. 数据传送（MOV/LOAD/STORE/PUSH/POP）——只搬不改值。
2. 算术逻辑（ADD/SUB/MUL/AND/OR/XOR）——核心计算。
3. 移位（逻辑/算术/循环）——乘除的原子操作。
4. 控制转移（JMP/Jcc/CALL/RET）——改 PC。
5. 输入输出（IN/OUT 或访存指令）。
6. 特权/系统（仅核心态、状态操作）。

**五条必记**：

- 同一串位，unsigned（无符号）与 signed（有符号）解读不同。
- RISC 是 Load/Store 架构：只有 LD/ST 访存，算术只在寄存器。
- MOV 不改变源操作数（move 名不副实）。
- 控制转移的本质是「修改 PC」；相对寻址让代码可重定位。
- 类型与操作是两个维度：指令管「做什么」，类型管「怎么解读」。

**辨析｜易错点：**「指令类型」与「操作数类型」别混——加法指令可以对整数、浮点、地址操作，类型决定解读，指令决定动作。

## 7 核心要点
- 类型由操作码静态决定解读。
- 六大类：传送、算术逻辑、移位、控制、I/O、特权。
- RISC Load/Store：只有 LD/ST 访存。
- MOV 只搬不改值。
- 控制转移本质是改 PC。

## 8 小结- **操作数类型**：整数、浮点、字符、布尔、地址，类型由操作码静态决定解读方式。
- **六大操作类型**：数据传送、算术逻辑、移位、控制转移、输入输出、特权。
- 数据传送不改变数值，只搬位置；RISC 是 **Load/Store 架构**，只有 LD/ST 访存。
- 控制转移的本质是**修改 PC**；相对寻址让代码可重定位。
- 类型与操作是两个维度：指令管「做什么」，类型管「怎么解读」。
