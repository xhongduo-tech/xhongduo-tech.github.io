## 为什么高速设备「一次一个字节」会要命

中断方式里每个字节都要「中断一次 + 服务程序搬一下」——对磁盘（KB 级块）、网卡（GB/s 级流量）来说，中断频率会压垮 CPU（见《中断服务程序》的占用率公式）。**DMA（Direct Memory Access，直接存储器访问）** 让**设备与主存直接交换数据，全程不经过 CPU**——CPU 只在开始配置、结束时收一个中断。本课讲 DMA 的基本概念与 DMA 接口（DMA 控制器）的组成。<span class="marginnote">「DMA」直译「直接内存访问」：数据不走「设备→CPU→内存」的绕路，而是「设备→DMA控制器→内存」直达。CPU 的角色从「搬运工」变成「包工头」——布置任务、验收结果，中间不干活。这就是高速 I/O 的秘诀。</span>

## 1 DMA 与中断的本质区别| 维度 | 程序中断 | DMA |

| --- | --- | --- |
| 数据传输 | 每字节中断一次，CPU 搬运 | 成块传输，CPU 不参与 |
| CPU 参与度 | 高（每次传输都服务） | 低（只开始/结束时参与） |
| 触发时机 | 每字节就绪 | 整块传输完成 |
| 适用设备 | 低速字符设备 | 高速块设备 |
| 响应方式 | 中断 | 中断（仅完成时一次） |

**核心概念：DMA 把「每字节一次中断」变成「每块一次中断」**——中断频率从「设备速率」降到「块速率」，CPU 负载骤降。<span class="marginnote">对比数据：串口 115200bps 用中断没问题（每字节中断），但磁盘 500MB/s、每块 4KB——用中断要 12 万次/秒，CPU 直接瘫痪。DMA 让整块直接搬，一次中断搞定——这是「块设备必须 DMA」的根本原因。</span>

## 2 DMA 控制器（DMAC）的组成DMA 传输由 **DMA 控制器（DMAC）** 执行，它本质上是一个「能接管总线的小处理器」：

| 部件 | 作用 |
| --- | --- |
| 内存地址寄存器（AR） | 主存目标地址（递增） |
| 字计数寄存器（WC） | 剩余要传的字数（递减） |
| 控制寄存器 | 传输方向、模式、启动 |
| 数据缓冲寄存器 | 数据暂存 |
| 状态寄存器 | 传输状态、完成标志 |

**核心概念：DMAC 是「懂内存地址的设备代理」**——它知道「往内存哪里写、写多少」，接管总线完成传输，最后发中断报告 CPU。<span class="marginnote">现代 DMA 引擎比教材的简单模型复杂得多：支持多通道、描述符链（scatter-gather 列表）、环缓冲。网卡/SSD 的 DMA 引擎会自己从「描述符表」读「数据在哪、写到哪」，CPU 只需设置描述符——CPU 与设备的「交互频率」进一步降低。</span>

## 3 DMA 的三种传输模式（CPU 与总线的关系）DMA 传输要占用总线，与 CPU 抢总线的方式有三种：

1. **停止 CPU 访问主存（周期挪用/突发）**：DMAC 接管总线，连续传完一块，再还给 CPU。
2. **周期挪用（cycle stealing）**：DMAC 每次只挪用一小段总线周期（传一个字节/字），然后释放——CPU 与 DMA 交替用总线。
3. **透明传输**：只在 CPU 不用总线的周期（如 CPU 内部运算时）传输——对 CPU 完全透明。

**重点：周期挪用是常见折中**——CPU 几乎不受影响，DMA 也能持续推进。<span class="marginnote">「周期挪用」让 CPU 每 N 个周期被插一个 DMA 周期，像「被打断的节拍」。对 CPU 而言吞吐略降，但对慢速到中速设备足够。突发模式适合大块传输（磁盘读整块），透明传输最理想但要求「DMA 恰好赶上 CPU 空闲」——硬件上难保证。</span>

## 4 公式解析：DMA 的 CPU 占用设 DMA 块大小 $B$、设备速率 $r$，每块传输占总线 $T_{bus}$：

$$\text{CPU 因 DMA 的吞吐损失} = \frac{T_{bus}}{B/r} = \frac{r \cdot T_{bus}}{B}$$

逐项拆解：

- **第一步，每块周期**：块大小 ÷ 设备速率 = 每块传输的「墙钟时间」。
- **第二步，总线占用**：每块占用总线 $T_{bus}$。
- **第三步，损失比例**：占用 ÷ 总时间 = 吞吐损失。

例：磁盘 500MB/s、块 4KB，每块 DMA 占 4μs：每块墙钟时间 8μs，DMA 占 50%——大块传输时 DMA 本身也吃总线。

**核心结论：DMA 省的是 CPU 的「搬运时间」，但总线带宽是共享资源——DMA 与 CPU 都访存，总线是瓶颈**。<span class="marginnote">「DMA 也要吃总线带宽」是常被忽略的事实：CPU 取指也要访问内存，DMA 与 CPU 抢带宽。所以现代系统用「多级缓存 + 独立的内存控制器通道」缓解——CPU 大量命中 Cache 时不太用内存总线，DMA 就能畅行。这就是为什么「DMA 性能」要看系统整体访存负载。</span>

## 5 辨析｜易错点：DMA 基本概念**辨析｜易错点：**

- **DMA 不是「设备直接访问内存」的字面意思**：是「DMA 控制器代表设备访问内存」——DMAC 是中间执行者。
- **DMA 传输结束才中断一次**：不是每字节中断——「DMA 结束中断」是唯一的 CPU 通知。
- **DMAC 接管总线需要总线仲裁**：DMAC 也是总线主设备，要申请总线使用权（见《总线仲裁》）。
- **DMA 不经过 CPU，但 CPU 要配置**：开始前 CPU 写 AR/WC/控制寄存器，结束后 CPU 读状态——「配置 + 验收」两步。

## 6 拓展：DMA 与现代 I/O 栈现代系统的 DMA 比教材模型更「自动化」：

- **描述符环（descriptor ring）**：网卡/SSD 的 DMA 引擎从内存中的「描述符表」读「数据从哪来、写到哪」，CPU 只需把描述符写进环——交互频率再降一个量级。
- **IOMMU**：DMA 也要地址翻译与保护——IOMMU（I/O 内存管理单元）把设备可见的「I/O 地址」映射到物理地址，并限制设备能访问的内存范围（防止恶意/错误设备读走系统内存）。
- **Cache 一致性**：DMA 写内存时，CPU 缓存里可能有旧副本——需要缓存失效/同步机制（现代互连用「一致性 DMA」或软件刷新）。

**核心概念：DMA 让设备「直接访问内存」，但也带来「安全与一致」的新问题**——IOMMU 与一致性协议就是答案。

**辨析｜易错点：**「DMA 不经过 CPU」指数据路径不经过 CPU，但 CPU 要做「配置与验收」——「DMA 全程无需 CPU」是错的。另外 DMA 要占用总线，与 CPU 共享内存带宽，不是「免费」的。

## 7 考点速记：DMA 五要点**一**：DMA = 设备与主存直接交换，CPU 只在开始配置、结束收中断。

**二**：DMAC 组成——内存地址寄存器 AR（递增）、字计数寄存器 WC（递减）、控制/状态寄存器。

**三**：三种模式——突发（停 CPU）、周期挪用（借周期）、透明（分时）。

**四**：DMA 结束才中断一次，不是每字节。

**五**：DMA 也要吃总线带宽——与 CPU 共享内存带宽。

**五条必记**：
- DMAC 是「懂地址的设备代理」，接管总线完成传输。
- 周期挪用是常见折中：CPU 几乎不受影响。
- 现代 DMA 用描述符环 + IOMMU，交互频率更低、更安全。
- DMA 数据路径绕过 CPU，但配置/验收仍要 CPU。
- 高速块设备（磁盘/SSD/网卡）必须 DMA。

**辨析｜易错点**：「DMA 全程无需 CPU」是错的——配置与验收两步 CPU 必参与。

## 8 小结- **DMA**：设备与主存直接交换，CPU 只在开始配置、结束收中断。
- **DMAC 组成**：内存地址寄存器、字计数寄存器、控制/状态寄存器。
- 三种传输模式：**突发（stop CPU）、周期挪用、透明传输**——周期挪用是折中。
- CPU 占用：省了搬运时间，但 DMA 与 CPU 共享总线带宽。
- 适用：高速块设备（磁盘、SSD、网卡）；低速字符设备用中断即可。

- DMA = 设备与主存直接交换

- DMAC 有 AR/WC/控制/状态寄存器
- 三种模式：突发/挪用/透明
- DMA 也吃总线带宽
- 描述符环+IOMMU 现代形态
- 周期挪用是折中
- 块设备必须 DMA
