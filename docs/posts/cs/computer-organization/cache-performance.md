## 为什么 Cache 性能有「公式」而不是「玄学」

前几课学了 Cache 的映射、替换、写策略——它们最终都要落到一个可计算的性能指标上。这一课把**命中率、缺失率、平均访问时间、CPU 时间**串成公式，并回答一个现代 CPU 每天都在做的事：**为什么要有 L1/L2/L3 三级 Cache，而不是一个大 Cache？** 你会看到，「多级 Cache」不是性能叠加的运气，而是有明确数学依据的结构设计。<span class="marginnote">「性能分析」是组成原理从「知道原理」到「会算账」的转折点。考试里 Cache 的大题几乎都是「给出容量/块大小/命中率，求平均访问时间或 CPU 时间」——公式就是武器。</span>

## 1 命中率与缺失率**核心概念**：

- **命中率（hit rate）** $h$：访问命中 Cache 的比例。
- **缺失率（miss rate）** $1-h$：未命中的比例。

$$h = \frac{N_{\text{hit}}}{N_{\text{total}}}, \qquad \text{缺失率} = \frac{N_{\text{miss}}}{N_{\text{total}}}$$

**CPU 时间分解**：把「访存」与「执行」拆开：

$$T_{\text{CPU}} = (\text{执行周期} + \text{访存停顿周期}) \times \text{时钟周期}$$

$$T_{\text{CPU}} = \left( \text{CPI}_{\text{执行}} + \frac{\text{缺失次数}}{\text{指令数}} \times \text{缺失代价} \right) \times T_{\text{clock}}$$

其中「缺失代价（miss penalty）」是未命中时访问下层多花的周期数。<span class="marginnote">这个公式把 Cache 性能翻译成 CPI 的一部分：访存停顿（memory stall）直接加在每条指令的周期数上。CPI 越大，性能越差——Cache 的作用就是压低 CPI。</span>

## 2 公式解析：平均访问时间（多级）**单级 Cache 平均访问时间**：

$$T_{\text{avg}} = T_{\text{hit}} + \text{缺失率} \times \text{缺失代价}$$

**两级 Cache（L1 + L2）**：

$$T_{\text{avg}} = T_{\text{L1 命中}} + \text{L1 缺失率} \times \left( T_{\text{L2 命中}} + \text{L2 缺失率} \times T_{\text{主存}} \right)$$

逐项拆解：

- **第一步，一级近似**：每次访问先付 L1 命中时间；L1 缺失才去 L2。
- **第二步，二级展开**：L1 缺失后，L2 命中的付 L2 命中时间，L2 也缺失才付主存代价。
- **第三步，直觉**：平均访问时间 = 「每层命中时间」+「每层缺失时向下层的额外代价」逐层嵌套。

例：L1 命中 1 周期、L2 命中 10 周期、主存 100 周期，L1 缺失率 5%、L2 缺失率 20%：

$$T_{\text{avg}} = 1 + 0.05 \times (10 + 0.2 \times 100) = 1 + 0.05 \times 30 = 2.5 \ \text{周期}$$

**重点：多级 Cache 的「局部缺失率」远低于单级**——L1 挡掉 95%，剩下的 5% 里 L2 又挡掉 80%，真正打到主存的只有 1%。<span class="marginnote">「缺失率有全局（global）与局部（local）之分」是考试常考点：L1 的局部缺失率 5%，但全局缺失率（相对所有访问）就是 5%；L2 的全局缺失率 = 0.05×0.20 = 1%。性能公式用的是「每层相对上一层的局部缺失率」。</span>

## 3 为什么多级 Cache 优于一个大 Cache

直觉上「32MB 的 L3 不如 32MB 的单个 L1」——为什么？因为**速度与容量的矛盾只能分层化解**：

**快**要求小：L1 只有几十 KB，访问 1–2 周期，才能跟 CPU 同步。
**大**要求慢：SRAM 越大，访问延迟越高（信号传输距离、译码深度）。
**分级**：L1 快小挡大头，L2 中速挡次大头，L3 大而慢兜底，主存殿后——每一层都只服务「上一层的漏网之鱼」。

**核心结论：多级 Cache 让「90% 以上的访问停在最快的 L1」**，这是单个大 Cache 做不到的——单个大 Cache 会让所有访问都变慢。<span class="marginnote">缓存层级的选择遵循「平均访问时间最优化」：L2 的容量是「L1 缺失流量 × 局部性窗口」的折中，L3 容量更大是因为它的「客户」是多个核。现代服务器 CPU 的 L3 可达几十 MB，共享给所有核心。</span>

## 3 Cache 性能的工程杠杆影响 Cache 性能的设计参数与收益：

| 参数 | 增大方向 | 影响 |
| --- | --- | --- |
| 容量 | 增大 | 缺失率下降，但延迟上升 |
| 块大小 | 增大 | 空间局部性收益，但浪费带宽、行数变少 |
| 相联度 | 增大 | 冲突减少，但比较器与替换成本上升 |
| 级数 | 增多 | 平均访问下降，但复杂度与面积上升 |

**关键 trade-off**：命中率与命中时间是**对立的**——牺牲命中时间换命中率（更大的 Cache 更慢），或反之。设计者的任务是在「命中率的收益」与「命中时间的代价」之间找平衡点。<span class="marginnote">这就是为什么现代 CPU 的 L1 命中延迟只有 4 周期而 L3 高达 40 周期：L1 宁可用较小的容量和直接映射/8 路来保速度，把容量赌在 L2/L3。性能调试时「减小 L1 缺失率」比「换更大的 L3」更常见，因为 L1 缺失要付出穿越 L2 的 40 周期代价。</span>

## 4 辨析｜易错点：Cache 性能计算陷阱**辨析｜易错点：**

- **缺失代价单位混乱**：缺失代价必须换算成周期，且要分清「从 L2 取块」还是「从主存取块」。
- **写缺失的代价不同**：写直达+写不分配时，写缺失直接写主存，缺失代价接近主存写时间；写回+写分配时，写缺失要先取块。
- **「平均访问时间」vs「CPU 时间」**：前者是「一次访问的平均时间」，后者还要乘上指令数与 CPI。
- **别忘掉访存频率**：CPU 时间公式里「缺失次数/指令数」= 每条指令平均缺失次数，不是缺失率本身（还要乘每指令访存次数）。

## 5 考点速记：Cache 性能公式**核心公式**（两级）：`$$`T_{avg} = T_{L1命中} + \text{L1缺失率} \times (T_{L2命中} + \text{L2缺失率} \times T_{主存})$$

**CPU 时间**：

$$T_{CPU} = (\text{CPI}_{执行} + \text{缺失次数/指令} \times \text{缺失代价}) \times T_{时钟}$$

**五条必记**：

- 局部缺失率 vs 全局缺失率：L2 全局缺失率 = L1 缺失率 × L2 缺失率。
- 多级 Cache 优于单大 Cache：快需要小、大需要慢，分层化解。
- 缺失代价单位要统一（周期），写缺失与读缺失代价不同。
- 设计杠杆：容量、块大小、相联度、级数——命中率与命中时间此消彼长。
- 访存停顿 = 缺失率 × 缺失代价，直接加进 CPI。

**辨析｜易错点：**「平均访问时间」是「一次访问平均」，CPU 时间还要乘指令数与每指令访存次数——别把缺失率当缺失次数。

## 6 核心公式
- 单级：$T_{avg} = T_{hit} + \text{缺失率} \times \text{缺失代价}$。
- 两级：$T_{avg} = T_{L1} + m_1(T_{L2} + m_2 T_{主存})$。
- CPU 时间 = (CPI_执行 + 缺失次数/指令 × 缺失代价) × T_clock。
- L2 全局缺失率 = L1 缺失率 × L2 缺失率。

## 7 核心公式
- 单级：$T = T_{hit} + m \times \text{代价}$。
- 两级：$T = T_{L1} + m_1(T_{L2} + m_2 T_{主存})$。
- CPU 时间 = (CPI + 缺失/指令×代价)×T_clock。
- L2 全局缺失率 = m1 × m2。

## 8 小结- **命中率 / 缺失率**定义访问命中的比例；缺失代价是未命中的额外周期。
- CPU 时间 = (执行 CPI + 访存停顿 CPI) × 时钟周期。
- **多级 Cache 平均访问时间**逐层嵌套：$T_{\text{avg}} = T_{\text{L1 命中}} + \text{L1 缺失率} \times (\ldots)$。
- **局部缺失率 vs 全局缺失率**：L2 的全局缺失率 = L1 缺失率 × L2 缺失率。
- 多级优于单大 Cache：**快需要小、大需要慢，分层化解矛盾**。
- 设计杠杆：容量、块大小、相联度、级数，命中率与命中时间此消彼长。
