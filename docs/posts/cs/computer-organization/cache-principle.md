## 为什么 Cache 是「硬件的魔法」

主存要 50–100ns，CPU 一个周期只要 1ns——没有 Cache，CPU 会 99% 的时间都在等内存。**Cache（高速缓冲存储器）**用 SRAM 存主存中活跃数据的副本，把「访问主存」变成「绝大多数时候访问 Cache」。它的精妙在于：**完全由硬件自动管理**，程序无感知。本课讲 Cache 的工作原理、基本结构与读写流程，为后面的地址映射、替换算法、写策略铺路。<span class="marginnote">Cache 的出现源于 1967 年 Maurice Wilkes 提出的「slave memory」思想，直到 1980 年代 Intel 80386 才把 Cache 放进芯片。今天 CPU 的 Cache 占据芯片一半以上的面积，是性能的隐形支柱。</span>

## 1 Cache 的基本原理：主存副本**核心概念：Cache 的工作基础**——把主存划分成固定大小的**块（block）/行（line）**，Cache 也按同样大小的「槽（slot）」组织，每个槽存一个主存块的副本，并记录这个块的地址信息。

```
CPU ──► Cache（快，SRAM，存主存块副本）
            │ 未命中时从主存取块
            ▼
        主存（慢，DRAM）
```

访问流程：

1. CPU 给出地址，Cache 控制器判断该地址对应的主存块**是否在 Cache 中**（命中/未命中）。
2. **命中**：直接返回 Cache 中的数据，几个周期完成。
3. **未命中**：从主存把整个块调入 Cache（若有槽位），或先按替换算法淘汰一个旧块再调入，然后返回数据。

**关键：Cache 以「块」为单位与主存交换**——一次未命中不是只取一个字节，而是取一整个块（如 64B）。这是利用空间局部性的核心设计。<span class="marginnote">「按块搬运」的深层理由：未命中的代价（几十个周期）远大于多传几个字节的代价，所以一次尽量多取，赌接下来的访问会落在同一块里。块太大浪费带宽，块太小利用不了空间局部性——64B 是现代 CPU 的经验值。</span>

## 2 Cache 的基本结构一个 Cache 由三大部分组成：

- **存储体（data array）**：存主存块的副本，每个槽容量 = 块大小。
- **标记（tag）**：每个槽记录它存的是「主存哪一块」——通常是地址的高位部分。
- **有效位（valid bit）**：标记该槽是否有有效数据（初始为 0，调入数据后置 1）。

Cache 行（line）的组织：

| Tag | Valid | Data（块内容） |

**重点：Tag 是「这个槽里放的是主存哪一块」的身份证**；地址的低位是「块内偏移」（找块里的具体字节），中间位是「槽索引」（找哪个槽），高位是 Tag（确认这个槽里是不是我们要的那块）。<span class="marginnote">这个「地址三段论」（Tag + Index + Offset）是 Cache 一切后续知识的地基：直接映射、组相联、替换算法都在这三段的划分上展开。先记住三段，后面的课才有抓手。</span>

## 3 公式解析：Cache 的容量与参数设 Cache 有 $S$ 个槽，每槽存 $B$ 字节（块大小），则：

$$C_{\text{cache}} = S \times B \quad \text{字节}$$

$$B = 2^{b}, \qquad S = 2^{s}, \qquad \text{主存地址位数} = t + s + b$$

其中 $b$ 是块内偏移位数，$s$ 是槽索引位数，$t$ 是标记位数。

逐项拆解：

- **第一步，容量**：Cache 总字节数 = 槽数 × 每槽字节数。
- **第二步，地址划分**：地址最低 $b$ 位选块内字节（块内偏移），接着 $s$ 位选槽（槽索引），剩下的 $t$ 位是 Tag。
- **第三步，校验**：$t + s + b$ 必须等于主存地址总位数——三段的长度和就是地址宽度。

例：主存地址 32 位，Cache 槽数 1024（$s=10$），块大小 64B（$b=6$），则 $t = 32-10-6 = 16$ 位 Tag。<span class="marginnote">「Tag 越大，Cache 能区分的块越多，但 Tag 本身占空间」。实际 Cache 还要算上 Tag 与有效位开销，所以「Cache 容量 64KB」通常指数据容量，不算 Tag 区。</span>

## 4 Cache 的读写流程### 读流程

1. 用地址的 Index 位定位槽。
2. 检查 Valid 位：无效 → 未命中；有效 → 比较 Tag。
3. Tag 匹配 → **命中**，用 Offset 位取数据。
4. Tag 不匹配 → **未命中**，从主存取块，调入该槽（必要时先替换）。

### 写流程

写比读多一个「何时把数据写回主存」的问题——这是下一课《Cache 的写策略》的内容。基本分两种：

- **写直达（write-through）**：每次写 Cache 同时写主存。
- **写回（write-back）**：只写 Cache，标记脏位，被替换时才写回主存。

**核心要点**（Cache 的基本结构与访问决策用表格总结）：

| 阶段 | 动作 | 依据 |
| --- | --- | --- |
| 定位 | 用 Index 选槽 | 地址中位 |
| 验证 | 查 Valid + 比 Tag | 地址高位 + 有效位 |
| 取数 | 用 Offset 选字节 | 地址低位 |
| 未命中 | 调块 + 替换 | 替换算法 |

## 5 辨析｜易错点：Cache 概念误区**辨析｜易错点：**

- **Cache 是「副本」不是「第二份数据」**：Cache 里的块与主存对应块是同一逻辑数据的两处物理存放，必须保持一致（写策略解决）。
- **Cache 对程序透明**：程序员看不到 Cache、不能直接操作 Cache——这与寄存器（编译器管理）不同。
- **「Cache 命中率」与「局部性」的因果**：局部性好 → 命中率高 → 平均访问快，是单向的因果链，别把命中率当局部性本身。
- **Cache 大小 vs 块大小**：Cache 容量 = 槽数 × 块大小；「加大块大小」既可能提高空间局部性收益，也可能因浪费带宽而降低命中率——不是越大越好。

## 6 补充：Cache 原理速记- Cache 存主存块副本，以块为单位交换，完全硬件管理。
- 结构：存储体 + Tag + 有效位；地址分 Tag+Index+Offset 三段。
- 读流程：定位（Index）→ 验证（Tag/Valid）→ 取数（Offset）。
- 写流程关键在何时写回主存（写直达 vs 写回）。
- 命中率由局部性决定，平均访问时间对命中率极度敏感。

## 7 一句话回顾- Cache = 主存块副本，完全硬件管理。
- 地址三段：Tag + Index + Offset。
- 命中率对性能极度敏感。
