## 为什么虚拟内存是「一个机制，三种身份」

前几课讲虚拟内存的机制，本课讲它的**运用**。同一个「虚拟页 ↔ 物理页」的映射机制，现代系统用它做了三件事：**当缓存**（主存缓存磁盘文件）、**当内存管理工具**（堆分配、栈、共享库）、**当保护工具**（进程隔离）。这一课聚焦前两种的实际形态：**mmap 文件映射、malloc 动态分配、垃圾回收**——它们是你在 C/Python/Java 里每天打交道的东西，底子全是虚拟内存。<span class="marginnote">「所有的大程序都是虚拟内存的客户」：打开一个 1GB 的文件不需要 1GB 内存，写一块 `1GB` 的缓冲区不需要立即分配物理页——懒惰与映射，是虚拟内存送给程序的礼物。</span>

## 1 虚拟内存作为缓存：文件映射（mmap）**核心概念：mmap（memory-mapped file）**：把磁盘文件的一部分直接**映射到进程的虚拟地址空间**，程序读写这块地址就像读写内存，缺页时操作系统自动从文件调入。

```c
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>

int fd = open("data.bin", O_RDONLY);
char *p = mmap(NULL, 4096, PROT_READ, MAP_PRIVATE, fd, 0);
// p 指向文件前 4KB；首次读 p[0] 缺页时，内核自动从文件调入
```

**机制**：mmap 创建虚拟页，PTE 指向「文件中的块」而非「物理页」；第一次访问某页时缺页，OS 从文件读入物理页并建立映射。

**优势**：省内存（只调常用页）、省拷贝（不用 read 系统调用复制到用户缓冲）、共享文件天然支持（多个进程映射同一文件）。<span class="marginnote">对比 read 系统调用：它把文件内容拷贝到用户缓冲区，需要一次系统调用 + 一次拷贝；mmap 让文件内容「看起来就在地址空间里」，缺页时内核直接填充页。这就是为什么数据库、加载器、IPC 都用 mmap 而非 read。</span>

## 2 动态内存分配：malloc 的内部机制

**malloc / free** 不是「向内存要一块」这么简单，它背后是**堆管理器**在虚拟内存里做「地块分配」：

**堆（heap）**：位于数据段之上、向上增长的区域。
**malloc** 从堆里找一块空闲区返回；**free** 把块归还。
堆耗尽时，堆管理器用 **sbrk / mmap** 向内核申请更多虚拟地址空间——但**物理页要到真正写入时才分配**（按需调页）。

**分配器策略**：空闲链表（free list）管理空闲块，选择策略有 first-fit、best-fit、next-fit 等；碎片问题（内部/外部碎片）要靠合并与分裂缓解。<span class="marginnote">「malloc 返回的地址几乎不碰物理内存」是反直觉真相：一个程序 malloc 1GB 只触达前几 KB，物理内存占用只有几 KB——其余页尚未被触达。这正是按需调页（demand paging）的懒惰之美。</span>

## 3 垃圾回收：回收不再使用的堆块C 用 malloc/free 手动管理；Java/Python/Go 用**垃圾回收（garbage collection, GC）**自动回收。GC 与虚拟内存的关系在于：**它回收的是虚拟地址空间中的堆块，靠的是「可达性分析」而非引用计数**。

主流 GC 算法：

**标记-清除（mark-sweep）**：从根（全局变量、栈）出发标记所有可达对象，再清除不可达者。
**标记-整理（mark-compact）**：清除后把存活对象压缩到一起，消除碎片。
**复制收集（copying）**：把堆分成两半，存活对象拷到另一半——快但空间翻倍。
**分代收集（generational）**：对象按存活时间分代，年轻代频繁回收、老年代少回收（基于「大多数对象很快死」的经验）。<span class="marginnote">GC 的「根」包括栈上的指针——所以 JVM 需要知道「栈里哪些字是指针」。这就是为什么 JVM 用「保守式」还是「精确式」GC 有讲究：精确式需要编译器提供类型信息（OopMap），现代 JVM/Go 都做到了。</span>

## 4 公式解析：按需调页的懒惰账设程序映射了 $V$ 字节虚拟内存，实际访问了 $U$ 字节，物理页大小 $P$：

$$\text{实际物理占用} \approx \left\lceil \frac{U}{P} \right\rceil \times P$$

$$\text{节省} = V - \left\lceil \frac{U}{P} \right\rceil \times P$$

逐项拆解：

- **第一步，惰性分配**：虚拟页建立映射时**不分配**物理页，只有访问（缺页）才分配。
- **第二步，实际占用**：物理页数 = 「真正被触达的页数」× 页大小。
- **第三步，收益**：当 $U \ll V$（映射大文件只用小部分），物理占用远小于文件大小。

例：mmap 一个 8GB 文件，只读前 4MB：物理占用约 4MB，而非 8GB——**节省了 2000 倍内存**。<span class="marginnote">这个「懒惰账」支撑了大数据处理的基本形态：Spark 读一个大文件用 mmap，几千个 task 各读自己那一段，物理内存只装活跃段。虚拟内存的映射机制让「假装拥有大文件」成为可能。</span>

## 5 辨析｜易错点：虚拟内存三身份的统一视角| 身份 | 面对的问题 | 手段 |

| --- | --- | --- |
| 缓存 | 主存太小装不下文件 | mmap + 按需调页 + 页面替换 |
| 内存管理 | 堆/栈/共享库怎么组织 | 地址空间布局 + malloc/GC |
| 保护 | 进程互相干扰 | PTE 权限 + 地址空间隔离 |

**辨析｜易错点：**（1）**malloc 分配的是虚拟地址，不是物理页**——「malloc 后立即看内存占用」会发现 RSS 没涨，因为页还没被触达；（2）mmap 的 MAP_PRIVATE 标志是「写时复制（copy-on-write）」：多个进程共享只读页，谁先写谁获得私有副本——这是共享库与 fork 的底层机制；（3）GC 回收的是「堆里的虚拟块」，与「物理页回收」是两层——JVM 的 GC 在虚拟层，OS 的页面回收在物理层。

## 6 拓展：用一个小实验体会「惰性分配」写一段 C 程序：`malloc(1GB)` 后立刻看进程的内存占用（`top` 或 `ps` 的 RES），会发现 RSS 几乎没涨——因为物理页还没被触达。再**逐页写入**每页的首字节，RSS 才随触达的页数增长。

这个实验揭示了按需调页的三个事实：

- **malloc 分配的是虚拟地址，不是物理页**——「分配 1GB」只是「地址空间留了 1GB」。
- **物理页在首次写入时才分配**——缺页处理程序完成「分配物理页 + 建立映射」。
- **内存「使用量」的真相**：常看 RSS（物理驻留）而非 VIRT（虚拟大小）。

**辨析｜易错点：**mmap 的 MAP_PRIVATE 标志是「写时复制（COW）」：多个进程映射同一文件时共享只读页，谁先写谁获得私有副本。fork 的子进程因此能「假装」拥有父进程的全部内存——只有写时才真正复制，这是「廉价进程复制」的机制。

## 7 考点速记：虚拟内存三角色**缓存**：mmap 把文件映射进虚拟空间，按需调页——主存是磁盘的缓存。

**内存管理**：malloc 分配虚拟地址，物理页延迟分配；堆耗尽用 sbrk/mmap 扩展。

**保护**：每进程独立虚拟空间，PTE 权限隔离——进程 A 碰不到进程 B。

**五条必记**：
- malloc 1GB 后 RSS 不涨——物理页在触达时才分配。
- mmap 省系统调用与拷贝，MAP_PRIVATE = 写时复制。
- GC 回收堆里的虚拟块（可达性分析），与物理页回收是两层。
- 惰性账：mmap 大文件只占活跃页的物理内存。
- 页缓存让「第二次读同一文件快」。

**辨析｜易错点**：「malloc 后内存占用立刻涨」是误解——分配的是虚拟地址，物理页要写入才分配。

## 8 核心要点
- malloc 分配虚拟地址，物理页延迟分配。
- mmap 按需调页，省拷贝省内存。
- MAP_PRIVATE = 写时复制。
- GC 回收堆虚拟块，与物理页回收两层。
- 页缓存让二次读快。

## 9 小结- 虚拟内存三身份：**缓存（mmap）、内存管理（malloc/GC）、保护（权限隔离）**。
- **mmap** 把文件映射进虚拟空间，按需调页，省内存省拷贝。
- **malloc** 在堆里做地块分配，物理页延迟分配；free 归还虚拟块。
- **GC** 用可达性分析回收堆块：标记-清除/整理、复制、分代。
- 按需调页的懒惰账：映射大文件只占活跃页的物理内存。
- 写时复制（COW）让共享库与 fork 既省内存又保隔离。

- malloc 分配虚拟地址、物理页延迟分配
- mmap 按需调页省拷贝
- COW 共享只读页
- GC 回收堆虚拟块
- 页缓存二次读快
- RSS 才是物理占用
- sbrk/mmap 扩展堆
- 惰性账：mmap 大文件占少量内存
