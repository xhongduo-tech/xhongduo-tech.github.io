## 为什么从模型监控开始

部署模式（上一节）把模型送上了线，但上线只是监控的开始。**传统软件上线后行为不变，模型却会随着世界的变化悄悄退化**：用户偏好变了、季节性到了、上游数据口径改了、甚至只是某个事件让输入分布整体移动——模型对「旧世界」学到的规律，不再适用于「新世界」。模型监控要做两件事：**早发现**（在业务受损前嗅到退化信号）与**可归因**（分清是数据变了还是模型不行）。它是「闭环」的收口：监控信号反过来触发再训练，生命周期才真正转起来。<span class="marginnote">「温水煮青蛙」在 ML 里尤其贴切：模型效果通常是每天掉零点几个百分点，单日不构成告警，累计一个月就崩了。所以监控不只盯「是否已坏」，更要盯「趋势是否在变坏」。</span>

模型监控还承担着另一重使命：**为「是否该重训」提供证据**。没有监控时，团队重训靠「感觉效果变差了」或「领导要求了」，既不可靠也不可审计。有了漂移指标，重训决策就变成一条显式规则——「特征 PSI 超过 0.25 就触发再训练」。这让「重训」从拍脑袋变成数据驱动，也正是在为上一节 CI/CD 的「持续训练（CT）」提供扳机信号。监控与 CI/CD 在这里汇成闭环：监控负责「发现」，流水线负责「处置」。

## 1 三类漂移：先分清「谁」变了

漂移不是一种病，而是三种，混淆它们会导致错误的处置。先看一张图：

![三类漂移示意图：左为特征分布漂移（协变量漂移），中为标签分布漂移，右为概念漂移](/images/mlops-llmops/model-monitoring-drift-1.svg)

**特征分布漂移（covariate shift，协变量漂移）**：输入的分布 $P(x)$ 变了，但「输入 → 标签」的关系 $P(y \mid x)$ 没变。典型例子：训练期用户年龄集中在 20–35 岁，上线两年后 40 岁以上用户占比大增。处置手段是**用新数据重训**，模型仍可复用。

**标签分布漂移（label shift / prior probability shift）**：标签的边缘分布 $P(y)$ 变了，但 $P(x \mid y)$ 相对稳定。典型例子：某类欺诈案件突然翻倍，导致正样本比例升高。处置手段同样是重训，但要**重点重采样**让类别均衡。

**概念漂移（concept drift）**：$P(y \mid x)$ 本身变了——同一份输入，现在对应不同的正确输出。典型例子：疫情期间「出门次数」这个特征对「消费金额」的预测关系彻底翻转。处置手段**不只是重训**，可能要改特征、换模型结构，因为「规律」本身已经过时。<span class="marginnote">一句话记忆：协变量漂移是「问的问题（输入）变了」，标签漂移是「答案的整体分布变了」，概念漂移是「题目与答案的对应规则变了」。只有概念漂移意味着模型学到的「因果规律」失效，需要更重的干预。</span>

**辨析｜易错点：** 三个概念最常被混为一谈的是协变量漂移与概念漂移。判据只有一条：**在给定输入 $x$ 时，正确的标签 $y$ 是否还一样？** 一样 → 协变量漂移（重训即可）；不一样 → 概念漂移（要重新建模）。而「数据漂移」是协变量漂移的通俗叫法，不是独立概念。

## 2 公式解析：PSI——量化「分布变了多少」

「变了」不能靠肉眼，要有一个数。业界最常用的分布漂移度量是 **PSI（Population Stability Index，群体稳定性指数）**：

$$
\text{PSI} = \sum_{i=1}^{k} (p_i - q_i) \cdot \ln \left( \frac{p_i}{q_i} \right)
$$

逐项拆解：

- **第一步，理解 $p_i$ 与 $q_i$**：把特征取值分成 $k$ 个区间（分箱）。$p_i$ 是**训练期**落在第 $i$ 箱的样本比例，$q_i$ 是**当前线上**落在第 $i$ 箱的样本比例。
- **第二步，看懂差与比**：$(p_i - q_i)$ 度量两个分布在第 $i$ 箱的**绝对差**；$\ln(p_i/q_i)$ 度量**相对差**。两者相乘，等于「差异越大，加权越重」——一个箱子漂移 20 个百分点，远比二十个箱子各漂 1 个百分点评分高。
- **第三步，体会分箱的作用**：PSI 把连续的分布比较离散成 $k$ 个箱子的比较，避免了「用分布函数距离」的复杂计算，工业界因此极爱用它。
- **第四步，记住经验阈值**：业界通行判读——$\text{PSI} \lt  0.1$ 视为无明显漂移，$0.1 \le \text{PSI} \lt  0.25$ 视为轻度漂移（需关注），$\text{PSI} \ge 0.25$ 视为显著漂移（应告警并触发再训练）。<span class="marginnote">PSI 还有两个近亲：KL 散度 $D_{KL}(q \| p) = \sum q_i \ln(q_i/p_i)$ 与 JS 散度。PSI 与 KL 结构相似但分子分母方向不同，所以 PSI 不是对称的——用哪个指标不重要，重要的是<strong>全团队固定同一个指标和阈值</strong>，否则监控口径一乱，告警就失去意义。</span>

**PSI 的局限也值得知道**：它度量「分布变了多少」，却不告诉你「变在哪、为什么」。PSI 只对**分箱后的离散化**敏感，分箱数目与箱边界的选择会影响结果；它也不区分「均值平移」与「方差扩大」两类漂移的方向。所以 PSI 是「哨兵」而不是「诊断书」——它负责报警，定位要交给下一层的特征级剖析（逐特征画分布对比图、看分位数变化）。监控体系里，**指标负责「发现」、工具负责「归因」**，两者搭配才算完整。

## 3 监控的三层观测：模型、特征、业务

只盯一个信号会漏判。成熟的监控体系从三个层面交叉观察：

**模型输出层（model output）**：预测分数的分布、正样本率、各类别占比。若「模型预测的 A 类比例」突然从 30% 跳到 60%，即使没有标签可对，也能嗅到异常。

**特征层（feature input）**：对每个关键特征算 PSI/统计量，覆盖缺失率、均值、方差、分位数。特征漂移是**最早的预警信号**——它通常先于模型指标恶化数周出现。

**业务结果层（business outcome）**：有真值反馈的任务（如 CTR 点击、风控违约）直接测「模型效果是否下滑」；没有即时真值的任务，用代理指标（人工抽检、延迟指标）。<span class="marginnote">为什么三层要并行？因为「真值滞后」。风控模型要等 90 天才能确认某笔贷款是否违约，若只盯业务结果，坏模型已经跑了三个月。特征漂移信号往往提前数周到达，是「早发现」的关键。</span>

这三层信号通常被汇总进监控面板，配三套告警：**特征漂移告警（触发再训练）、性能劣化告警（触发回滚）、业务异常告警（触发人工介入）**。

三个层面的信号并不是等权的。工程经验通常建议：**特征层看漂移、输出层看分布、业务层看效果**，三者组合成一个「先怀疑、再确认、后处置」的决策序列。例如：特征 PSI 上升先触发「疑似」，若同时模型输出分布异常则升级为「确诊」，再结合业务指标确认是否立即回滚或重训。这样层层递进，既不错过早期信号，也不被单点噪声牵着走——监控的成熟度，恰恰体现在这套「递进式确认」的流程设计上。

监控还要回答一个容易被忽略的问题：**监控哪些特征、监控多久一次**。不是每个特征都值得上漂移指标——工程实践会为特征按「对模型影响度」分级：高影响特征（模型入模的核心特征）逐特征监控 PSI 与缺失率；中低影响特征只做统计摘要与周期性抽查。频率上，特征漂移通常**按天或小时**聚合（新一批数据到达即计算），业务指标则随真值就绪周期（如 T+1、T+90）更新。监控频率与特征量级要平衡：特征太多、算太勤，指标计算本身就成了新的性能负担。

## 4 告警到行动：从「发现」到「处置」的闭环

监控不是为了发告警，而是为了驱动决策。告警之后必须回答三个问题：

**第一，告警是真是假？** 数据分布季节性波动（如双十一流量）可能触发假阳性。所以告警要设**静默窗口**与**多信号确认**——单一信号触发只算「疑似」，多个信号同时触发才算「确诊」。

**第二，处置手段是什么？** 按漂移类型选择：协变量/标签漂移 → 触发**再训练流水线**（CI/CD for ML 的 CT 环节在此闭环）；概念漂移 → 冻结模型、人工分析特征是否失效；模型性能劣化且无法快速修复 → **回滚到上一版本**。

**第三，处置后如何验证？** 再训练后的新模型要走完完整的质量门禁（评估、漂移检查、金丝雀）才能转正——**监控与 CI/CD 在此汇合**，形成「监控发现 → 自动重训 → 门禁校验 → 金丝雀上线 → 继续监控」的完整飞轮。

**辨析｜易错点：** 最常见的问题是「有告警无行动」——监控面板摆了一堆红色，却没人定义处置 SOP。成熟团队会给每条告警写**运行手册（runbook）**：什么信号、什么阈值、找谁、第一步做什么、何时升级。监控的价值不在面板，在面板之后的决策链路。

## 5 监控基础设施：数据怎么从线上流到告警

监控不是「在面板上画几个数」就完事，它背后是一条数据管线：**线上请求 → 特征/预测日志 → 聚合 → 指标存储 → 告警引擎 → 通知**。四个环节各有工程细节：

**第一，在线日志**：推理服务把每次请求的输入特征、预测分数、业务结果（若有）落成结构化日志。这是监控的「原材料」——没有日志，一切指标都无从谈起。日志要采样还是全量，取决于成本与诊断需求。

**第二，指标计算与存储**：用流处理或周期批处理，从日志算出特征 PSI、预测分数分布、正确率等指标，写入时序数据库（如 Prometheus、InfluxDB）。指标的定义要与训练侧口径一致——「PSI 的分箱方式」在离线和在线必须相同，否则告警会失真。

**第三，告警引擎**：对每个指标配置「阈值 + 持续时间 + 静默窗口」。单点尖刺不告警，持续恶化才告警——用「窗口内连续 N 次超阈值」代替「单次超阈值」，可大幅降低误报。<span class="marginnote">告警的「静默窗口」也很关键：业务大促、季节性高峰期间指标天然异常，提前设定静默期可以避免告警风暴把运维团队「炸麻木」——人一旦习惯了满屏红色，真正的危险信号反而无人响应。</span>

**第四，通知与升级**：告警按级别路由到不同渠道与责任人，超时未处理自动升级。通知的价值是「让人知道」，所以每条告警都要带上下文：哪个模型、哪个特征、PSI 多少、可能的原因。

**辨析｜易错点：** 监控最怕「指标口径漂移」——离线算 PSI 用 A 分箱，在线用 B 分箱，两边数字永远对不上。正确做法是把「指标定义」当作一份共享配置，离线和在线从同一份定义计算。这也解释了为什么上一节讲「实验与监控同源」——指标只有一处定义，才谈得上可比。

另一个反复出现的误区是「把监控当运维的终点」：告警响了、重训跑了，但**没有人复盘「这次为什么漂移」**。漂移背后可能是季节规律（双十一）、产品改版（推荐位变了）、上游数据口径调整（特征定义改了）——把每次告警的根因沉淀进「漂移档案」，下一次同类漂移就能提前预判。监控的长期价值，恰恰在于它积累起来的这份「世界怎么变」的知识库，它让团队从「被动救火」走向「预判式运营」。

## 6 术语速查表

| 术语 | 一句话含义 | 关键词 |
| --- | --- | --- |
| 协变量漂移 | 输入分布 $P(x)$ 变、$P(y \mid x)$ 不变 | 重训即可 |
| 标签漂移 | 标签分布 $P(y)$ 变 | 重点采样重训 |
| 概念漂移 | 对应规则 $P(y \mid x)$ 本身变了 | 需重新建模 |
| PSI | 分箱度量分布差异的指数 | 0.1 / 0.25 分界 |
| 三层观测 | 模型输出、特征输入、业务结果 | 特征最早预警 |
| 告警管线 | 日志 → 指标 → 告警 → 通知升级 | 离在线同口径 |

## 7 小结

- 三类漂移要分清：**协变量漂移**（输入变了）、**标签漂移**（答案分布变了）、**概念漂移**（对应规则变了）；只有后者需要重新建模。
- **PSI** 用分箱后的 $p_i$ 与 $q_i$ 量化分布差异：$\text{PSI} < 0.1$ 无明显漂移，$0.1 \le \text{PSI} < 0.25$ 需关注，$\ge 0.25$ 告警并触发再训练。
- 监控要**三层并行**：模型输出看分布、特征输入看漂移（最早预警）、业务结果看效果，形成「先怀疑、再确认、后处置」的递进式确认。
- 告警价值不在面板，在**面板之后的决策链路**：每条告警配 runbook，写清信号、阈值、责任人、第一步做什么；有告警无行动等于没监控。
- **指标口径一旦定义，离线和在线必须同源计算**——PSI 的分箱方式不一致，告警就会失真。
- **PSI 是「哨兵」不是「诊断书」**：它负责报警，定位要交给特征级剖析（逐特征画分布对比图、看分位数变化）。
- 每次告警都要**复盘根因、沉淀「漂移档案」**（季节、改版、上游口径），让团队从被动救火走向预判式运营。
- 监控频率与特征量级要平衡：**高影响特征逐特征盯 PSI，中低影响特征只做摘要与周期性抽查**。
- 监控与 CI/CD 在此闭环：漂移告警 → 自动重训 → 门禁校验 → 金丝雀上线 → 继续监控，构成「发现—处置—验证」的完整飞轮。

在下一节，我们把 MLOps 的整套纪律搬到大模型时代：**LLMOps**——提示管理、评估体系与安全护栏。当「不训练模型、只使用与约束模型」成为常态，监控的重心也从「盯漂移」转向「盯幻觉、越狱与隐私泄露」，评估则成了没有真值时的第一工程。届时你会发现，「没有真值怎么办」这个问题，正是 LLMOps 相对传统 MLOps 最大的方法论跃迁。
