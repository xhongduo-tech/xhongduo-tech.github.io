## 为什么从快速排序开始

快速排序是最早、也是最著名的随机算法案例：确定性快排在已排序输入上退化到 $O(n^2)$，而**随机化快速排序（randomized quicksort）**——每次随机选主元——对所有输入的期望比较次数都是 $O(n\log n)$。它完美示范了本专题的核心理念：**随机化把「最坏情形输入」变成「几乎不可能事件」**。更妙的是，它的期望分析只用到上一篇学过的**期望线性 + 指示变量**，是「把复杂量拆成指示变量之和」这门手艺的教科书级示范。

## 1 算法：随机主元打破输入诅咒

确定性快排的病灶在于：如果输入恰好有序，而主元总取第一个元素，则每次划分都是「1 个对 $n-1$ 个」的失衡，递归树退化成链，总代价 $\Theta(n^2)$。

**随机化快速排序**：每次划分时，从当前子数组中**均匀随机**选择一个元素作为主元。于是「输入恰好有序」不再致命——主元等概率是任意元素，即使输入有序，划分也是随机的。<span class="marginnote">注意这里的随机性<strong>只来自算法内部抛硬币</strong>，输入可以是任何最坏情形（包括对抗性输入）。随机化的意义在于：不再依赖「输入是平均情形」的假设，而是把平均化放进算法自身。</span>

期望分析的目标：设 $T(n)$ 为排序 $n$ 个元素的随机比较次数，证明 $\mathbb{E}[T(n)] = O(n \log n)$。

## 2 指示变量分析法：比较发生与否

直接的递归分析要处理随机主元的位置分布，稍显繁琐。更优雅的是用**指示变量**逐对统计比较次数。

**观察**：一次比较发生在两个元素之间，且任何一对元素至多被比较一次——一旦某个主元把它们划到两侧，之后它们再也不会相互比较。设输入排序后为 $z_1 \lt  z_2 \lt  \dots \lt  z_n$，对任意 $1 \leq i \lt  j \leq n$ 定义指示变量

$$X_{ij} = \begin{cases} 1 & z_i \text{ 与 } z_j \text{ 被比较过} \\ 0 & \text{否则} \end{cases}$$

于是总比较次数 $C = \sum_{i<j} X_{ij}$。<span class="marginnote">这个「$z_1,\dots,z_n$ 用排序后下标重新编号」的技巧是理解整段分析的关键：我们讨论的是<strong>值的大小关系</strong>，与它们的物理位置无关。所有下标 $i<j$ 都指「第 $i$ 小与第 $j$ 小的元素」。</span>

下一步关键：在集合 $S_{ij} = \{z_i, z_{i+1}, \dots, z_j\}$ 中，$z_i$ 与 $z_j$ 被比较，**当且仅当** $z_i$ 或 $z_j$ 是 $S_{ij}$ 中第一个被选为主元的元素。因为只要 $S_{ij}$ 中有一个内部元素先被选为主元，它就会把 $z_i$ 和 $z_j$ 划分到两侧，从此永不相见。

由于主元在 $S_{ij}$ 中均匀随机选择，$z_i$ 与 $z_j$ 是 $S_{ij}$ 的边界元素，被选中的概率各为 $1/|S_{ij}|$：

$$\Pr[X_{ij} = 1] = \frac{2}{j - i + 1}$$

## 3 期望比较次数：双和与调和级数

由期望线性，总和期望等于逐项期望之和（**无需独立性**，这正是核心优势）：

$$\mathbb{E}[C] = \sum_{1 \le i \lt  j \le n} \Pr[X_{ij} = 1] = \sum_{1 \le i \lt  j \le n} \frac{2}{j - i + 1}$$

固定 $k = j - i + 1$（即区间长度），对每个 $k \in \{2, \dots, n\}$，有 $n - k + 1$ 对满足条件的 $(i,j)$，于是

$$\mathbb{E}[C] = \sum_{k=2}^{n} \frac{2(n - k + 1)}{k} \lt  2n \sum_{k=1}^{n} \frac{1}{k} = 2n\,H_n = O(n \log n)$$

其中 $H_n = \sum_{k=1}^n 1/k \approx \ln n$ 是调和级数。<span class="marginnote">这个 $2n H_n \approx 2n\ln n$ 的常数 2 是<strong>紧</strong>的：随机化快速排序的平均比较次数约 $1.39 n\log_2 n$，只比最优信息论下界 $\log_2(n!)$ 大约 39%，相当优秀。</span>

## 4 公式解析：$\Pr[X_{ij}=1] = \frac{2}{j-i+1}$ 的来龙去脉

$$
\Pr[X_{ij} = 1] = \Pr[z_i \text{ 或 } z_j \text{ 是 } S_{ij} \text{ 中第一个主元}] = \frac{2}{j - i + 1}
$$

- **第一步，界定关键集合**：$S_{ij} = \{z_i, z_{i+1}, \dots, z_j\}$，共 $j-i+1$ 个元素。$z_i, z_j$ 是它的最小、最大元素。
- **第二步，刻画比较条件**：$z_i, z_j$ 被比较 $\iff$ 在 $S_{ij}$ 中，$z_i$ 或 $z_j$ **先于所有内部元素**被选为主元。因为首个被选的主元会把 $S_{ij}$ 一分为二；只有边界元素当主元时，$z_i, z_j$ 才留在同一边继续比。
- **第三步，均匀随机**：$S_{ij}$ 中每个元素成为「第一个主元」的概率相等，都是 $1/(j-i+1)$。事件「$z_i$ 或 $z_j$」是两个互斥事件的并，概率相加得 $2/(j-i+1)$。

**直觉**：区间越长，边界元素被优先选中的概率越小，这一对元素被比较的概率就越低。把「每对元素被比较的概率」求和，长区间贡献小、短区间贡献大，总和收敛到 $O(n\log n)$——随机化把最坏情形的 $O(n^2)$ 摊平成平均的 $O(n\log n)$。

## 5 尾概率：高概率界限

期望 $O(n\log n)$ 还不够，我们往往还要「运行时间超过 $c n\log n$ 的概率极小」。对随机快排，可以证明对任意常数 $c$，存在 $k$ 使

$$\Pr[C \geq k\,n \log n] \leq \frac{1}{n^{k/2}}$$

证明思路是分析**单层递归的失衡概率**：主元若落在区间中间 50%，则把问题至少切掉四分之一。用切尔诺夫界可证「连续 $\Omega(\log n)$ 层都没切好」的概率指数小，从而总比较次数的高概率上界成立。<span class="marginnote">这条尾界说明随机快排不仅平均好，而且「几乎总是好」：偏离 $k n\log n$ 的概率以 $n$ 的多项式倒数衰减。Las Vegas 算法的完整分析 = 期望分析 + 尾界分析，缺一不可。</span>

**辨析｜易错点：** 不要混淆「随机化快速排序」与「随机输入的确定性快排」。前者对**任意**输入成立（随机性在算法内），后者只对随机输入成立——前者是更强的保证。这也是为什么随机化在主元选择上至关重要。

## 6 工程实现：三路划分与随机性来源

教科书版的「随机主元」在实际实现里有两个常见调整：

**三路划分（three-way partitioning）**：当输入含大量重复元素，标准划分会把所有等于主元的值堆进一侧，退化到 $O(n^2)$。三路划分把数组分成「小于 / 等于 / 大于主元」三段，只递归小于与大于两段——重复元素越多，越能避免退化。<span class="marginnote">这是随机化与工程结合的典型案例：随机主元解决「输入有序」的退化，三路划分解决「输入大量重复」的退化。Java 的 `Arrays.sort` 对基本类型正是用了「双主元三路划分」的变体，两者叠加后，几乎所有真实输入都能以高概率保持 $O(n\log n)$。</span>

**随机性的实现**：真正的随机主元需要调用随机数发生器，在嵌入式或实时场景可能成为瓶颈。替代方案是「确定性伪随机选择」：用输入本身的哈希值（如对元素做随机化哈希）选主元，或用「三数取中」（左、中、右三个位置的中位数）。三数取中在对抗输入下仍有结构漏洞，但配合哈希化就非常稳健——这已经踩到第 29 节「伪随机发生器」的门口。

**尾递归优化**：快排的递归深度在随机化下期望 $O(\log n)$，但可先递归较小的一半、再迭代处理较大的一半，把栈深度压到 $O(\log n)$ 最坏。

## 7 随机化快速排序的谱系与位置

把快速排序的各个版本放进一张地图，看清随机化的独特位置：

| 版本 | 主元选择 | 最坏时间 | 期望时间 | 依赖 |
| --- | --- | --- | --- | --- |
| 确定性快排 | 固定（首/尾/中位） | $\Theta(n^2)$ | $O(n\log n)$ | 输入平均 |
| 随机化快排 | 均匀随机 | $\Theta(n^2)$（概率 $\lt 2^{-n}$） | $O(n\log n)$ | 无（任意输入） |
| 三数取中 | 左中右中位 | $O(n\log n)$ 期望 | $O(n\log n)$ | 近似 |
| Introsort | 随机 + 堆兜底 | $O(n\log n)$ | $O(n\log n)$ | 无 |

<span class="marginnote">最引人注目的是 Introsort（内省排序）：它先跑随机化快排，若递归深度超过 $O(\log n)$（说明运气极差），切换到堆排序保证最坏 $O(n\log n)$。这是「随机化 + 确定性兜底」的混合设计，C++ 标准库 `std::sort`、Go 的排序都采用它——随机化负责平均快，确定性兜底负责最坏不烂。</span>

**随机化的位置总结**：随机化快排不是「最好的排序」（它不如 Introsort 稳），但它是**理解随机算法的一切的完美案例**——指示变量、期望线性、尾界、主元随机化，四个核心工具全部登场。本专题选择它作为首个深度案例，正是因为它一篇文章装下了随机算法分析的全部招式。

**「平均情况」与「期望」的严格区分**：这是随机算法课程里最容易混淆的一对概念。确定性快排的「平均情况 $O(n\log n)$」是对**随机输入**取平均——对抗性输入可以摧毁它；随机化快排的「期望 $O(n\log n)$」是对**算法内部硬币**取平均——对任意（包括对抗性）输入都成立。后者是「随机化算法」的本质特征：随机性在算法内，输入可以是最坏情形。用一句话记：确定性算法怕坏输入，随机化算法不怕——因为坏运气只可能来自它自己抛的硬币，而硬币的坏运气可以按概率算清楚。

随机化快速排序之所以是随机算法课程的「第一课」，正因为它是全部核心技巧的最小完整示例：指示变量拆解、期望线性吃相关性、调和级数求期望、切尔诺夫拿高概率——一次示范，四件兵器全部亮相。之后的每个随机算法，都能在它身上找到影子。

**随机化的「近乎免费」属性**：随机主元的一次选择只花常数时间，收益却是「对抗输入免疫」与「平均与最坏解耦」——这个「便宜又强大」的组合，是随机化在工程里如此普遍的根本原因。

**与数学的衔接**：随机快排的期望分析只用期望线性 + 调和级数，不依赖任何分布假设；它也是后文「随机主方法与分治」的预告——随机化分治的期望复杂度，可以系统地用一把尺子量出来。

**一个反复出现的数字**：$2nH_n \approx 2n\ln n$——随机快排的期望比较次数，与最优信息论下界 $\log_2(n!)$ 只差约 39% 的常数，这是随机化分治「几乎最优」的典型代表。

## 8 小结

- 「期望」是对算法内部硬币取平均，对任意输入成立——区别于「平均情况」对随机输入取平均。
- 随机化快速排序每次均匀随机选主元，把「最坏输入」变成「几乎不可能事件」。
- 指示变量 $X_{ij}$ 刻画元素对是否被比较；$\Pr[X_{ij}=1] = 2/(j-i+1)$。
- 期望线性把期望比较次数化为双和：$\mathbb{E}[C] \leq 2nH_n = O(n\log n)$，无需独立性。
- 尾界：$\Pr[C \geq kn\log n] \leq 1/n^{k/2}$，由切尔诺夫界与分层失衡分析得到。
- 随机化把「输入平均」转为「算法内部平均」，对任意输入成立。
