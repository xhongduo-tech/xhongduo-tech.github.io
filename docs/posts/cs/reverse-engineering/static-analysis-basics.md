## 为什么从静态分析开始

拿到一个陌生样本，第一直觉是「跑一下看看」，但逆向工程的第一课恰恰相反：**先别运行，用眼睛读它。** 这倒不是因为谨慎能让人显得专业，而是因为在受控环境搭建好之前运行一个未知程序，等于把裁判权交给对手——你怎么知道它在你机器上干了什么、又留下了什么？<span class="marginnote">真正的恶意代码甚至会在运行前检测自己是否处于虚拟机里，见本专题《反调试与反虚拟机技术》。静态分析因此永远是第一道工序：它安全、可重复、不打草惊蛇。</span>

静态分析（static analysis）是指**不执行程序、仅凭程序本体（文件字节、结构、字符串、指令）推断其行为**的分析方式。它与我们之前在《操作系统》《编译原理》《汇编语言》里打下的基础直接对位：要读懂 PE/ELF 文件的骨架，需要 ELF 装载的知识；要读懂指令流，需要 x86 汇编；要判断字符串是否被加密，需要一点密码学直觉。这一篇就是把那些分散的知识第一次收拢到「一个未知文件」这个对象上。

## 1 情报侦察三步：哈希、文件类型、字符串

### 1.1 哈希：给文件发一张身份证

先做三件事，每件都不超过一条命令。第一件是哈希：对样本计算 MD5、SHA-1 或 SHA-256，得到一个固定长度的指纹。<span class="marginnote">哈希是单向函数：从摘要推不回原文，但相同文件必然得到相同摘要。2026 年的今天 MD5 已被证实可构造碰撞，安全领域不再用它做签名，但在「给文件命名、去重、查库」这种场景里它依然足够。</span>这个指纹有两大用途：一是拿到 VirusTotal 等在线服务里比对，看 60 多个杀毒引擎和历史样本库里有没有它的记录；二是作为这个样本的**全局唯一代号**——论文、报告、IOC 里说的「这个样本」，指的就是「这个 MD5」。

### 1.2 文件类型：先搞清楚它到底是什么

第二件是用 `file` 命令或直接看十六进制前几个字节，判断文件类型。Windows 可执行文件以 `MZ`（0x4D 0x5A，马克·茨比科夫斯基 Mark Zbikowski 的姓名缩写）开头，Linux 可执行文件以 `\x7FELF` 开头，PDF 以 `%PDF` 开头。**文件扩展名毫无意义，文件头才是身份**——恶意样本最常用的伪装就是把可执行文件改名成 `.jpg` 或 `.pdf`。<span class="marginnote">x86 平台 `MZ` 对应十六进制 `4D 5A`，正是 DOS 可执行文件头；PE 是 DOS 格式的继承者，所以现代 Windows 程序依然带着一个「DOS 头」。这段历史在后面《ELF/PE 文件格式解析》里还会展开。</span>

### 1.3 字符串：程序里露出的马脚

第三件是提取字符串。`strings` 命令把文件中连续的可打印字符序列（默认长度 ≥ 4）逐个挑出来，常常直接暴露程序的意图：一条 URL、一句中文错误提示、一个互斥量名字、一个「http://」或「cmd.exe」……<span class="marginnote">`strings` 有 `-a`（扫全文件而非只扫数据节）、`-n`（最小长度）、`-e l`（提取 UTF-16LE 编码的 Unicode 字符串，Windows 程序内部常用）等开关；只看默认输出会漏掉一半情报。</span>

但要警惕：**没有字符串 ≠ 没有恶意行为**。有经验的作者会把关键字符串编码、加密或分片存放，运行期再还原——所以字符串分析是「线索」而非「结论」，它更多告诉你「该往哪个方向继续挖」。

## 2 看穿 PE 的骨架

在 Windows 上，静态分析绕不开 PE（Portable Executable）格式。对照第三级《操作系统》里讲过的链接与装载，PE 的三个关键部位是：

**节区（sections）**：把程序的代码、数据按用途分块存放。常见节区名如 `.text`（代码）、`.data`（已初始化数据）、`.rdata`（只读数据）、`.rsrc`（资源）。<span class="marginnote">节区名只是约定，不是规范。UPX 加壳后节区改叫 `UPX0`、`UPX1`，恶意代码完全可以自造 `CODE`、`PAD` 之类的名字。名字给你提示，但不值得全信。</span>

**导入表（import table）**：程序运行时需要从哪些 DLL 引入哪些函数。这份名单是逆向的金矿——一个程序调用 `CreateProcess`、`VirtualAlloc`、`WriteProcessMemory`，即使你一行代码都没读，也能合理推测它想「创建新进程并往别的进程里写数据」。这就是典型的恶意行为。一个「正经程序」的导入表通常有几十上百个函数；如果导入表干净得反常，几乎只剩 `LoadLibraryA` 和 `GetProcAddress` 两个函数，那多半是**壳**的功劳——程序真正用到的 API 要到运行期才解析出来。<span class="marginnote">`LoadLibraryA` + `GetProcAddress` 组合是「动态解析 API」的标准姿势：先加载 DLL，再按名字查函数地址。壳、插件系统、恶意加载器都用这一招，让静态导入表失去情报价值。</span>

**资源（resources）**：图标、对话框、版本信息、内嵌的文件。恶意样本经常把载荷（payload）藏在资源节里，运行期再 `FindResource` 取出来释放到磁盘——这既是行为也是静态分析最容易忽略的一站。

### 2.2 节区权限与数字签名

PE 的每个节都带一组**节区权限标志**（`IMAGE_SCN_*`），其中最值得警惕的组合是 `MEM_EXECUTE | MEM_READ | MEM_WRITE`（可执行又可写）。正常编译器产生的 `.text` 是只读可执行，`.data` 是可写不可执行；一个「既能执行又能写」的节区，往往是**自修改代码**或**运行期解包**的舞台——加壳程序几乎必有一个这样的节。<span class="marginnote">节区权限也是运行时防御（DEP/ASLR）的审计对象：`MEM_EXECUTE_READWRITE` 节太多，直接拉高样本的嫌疑权重。静态分析阶段的「权限画像」能提前预告动态阶段会遇到什么。</span>

数字签名（Authenticode）则提供另一维度的信息：一个带合法签名（微软、Adobe 等）的程序，其代码完整性通常由签名背书；恶意样本要么无签名，要么**签名无效**（证书过期、被吊销），要么使用窃取的证书——`sigcheck` 一查便知。**但注意：有签名 ≠ 安全**，签名只证明「谁签的」，不证明「干了什么」，被签名的恶意程序（签牌泄漏）在历史上并不罕见。

## 3 加壳检测：静态分析的警报器

加壳（packing）是静态分析最大的敌人，也是后面《加壳、脱壳与混淆》一整篇的主角。静态阶段你只需要会**检测**它，三个信号通常同时出现：

- 节区名或节区结构异常（`UPX0`、`UPX1`、大量 `PAD` 节）；
- 文件熵值接近随机数据（见下一节公式解析）；
- 导入表异常精简，几乎只剩动态加载用的两个函数。

**加壳的本质是：把原始程序压缩或加密成一段「数据」，再在前面包一层很小的解包器；运行期由解包器在内存里还原原始代码再跳过去执行。** 所以你 `strings` 出来的是一堆乱码，`file` 看到的是个「正常程序」，而真正的逻辑要到运行期才在内存里现形——这正是静态分析的边界，也是逼着我们走进下一节《动态分析与沙箱》的原因。

## 4 公式解析：香农熵

判断一段字节是不是「随机数据」，标准做法是算它的信息熵（entropy）。加壳后的节区字节接近均匀分布，熵值通常 ≥ 7.0（满值 8），而正常代码节一般落在 5.0–6.5。香农熵的公式是：

$$
H = -\sum_{i=1}^{n} p_i \log_2 p_i
$$

分三步拆开读：

- **第一步，看 $p_i$**：把这段字节按 256 种取值（0x00–0xFF）统计频率，$p_i$ 是第 $i$ 种字节值出现的概率，$\sum p_i = 1$。
- **第二步，看 $-\log_2 p_i$**：这是「该字节值带来的信息量」。$p_i$ 越小、越罕见，信息量越大；$p_i = 1$（整段全是同一个字节）时信息量为 0。
- **第三步，加权求和**：$H$ 是每个字节值信息量的期望。全同字节的节 $H = 0$；均匀分布的节 $H = 8$；可读的 ASCII 文本受字符集限制，$H$ 明显低于 8。

直觉一句话：**熵度量的是「猜中下一个字节有多难」。** 明文代码有很强的统计结构，容易猜；加密或压缩后的字节像均匀噪声，猜不中——所以高熵节区是「这里藏着秘密」的最强静态信号。

## 5 静态分析的边界

静态分析能回答「这个文件声称自己是什么、结构上是什么、有没有藏东西」，但它回答不了四个关键问题：

- **运行时行为**：程序启动后改写了什么、连了哪个服务器、往注册表写了什么，静态阶段看不见；
- **解密后的真相**：加壳、加密、多态代码的「真身」只有运行期才出现；
- **执行与否**：某段代码是死代码还是关键路径，静态很难判断——这直接关系到《反汇编与控制流恢复》里「递归下降」要不要跟进某个分支；
- **环境交互**：程序与操作系统、网络的互动，是行为的范畴。

**辨析｜易错点：** 静态分析得出的结论永远是「推测」而非「事实」。看到导入表里有 `CreateProcess` 只能说明「程序具备了创建进程的能力」，不代表它一定那么干；看到高熵只能说明「有隐藏数据的强烈嫌疑」。把「疑似」当「实锤」写在报告里，是新手最常见的错误——动态分析的价值，正在于用事实检验这些推测。

## 6 一套可复用的静态分析流水线

把上面散落的工具组织成一条固定流程，就不会漏项。以拿到一个 Windows 样本为例，标准动作是：

1. `sha256sum sample.exe` 算哈希，把摘要提交到 VirusTotal，先看历史库与引擎判分——这一步往往已经能给出 80% 的方向；
2. `file` + 十六进制前几字节确认类型，警惕「改名成 .jpg 的可执行文件」；
3. `strings -a -n 6 -e l sample.exe` 提取 ASCII 与 UTF-16LE 两套字符串，把可疑的 URL、路径、互斥量名逐一记下并打上「来源地址」；
4. `pefile`（Python）读节区、导入表、资源、数字签名，重点核对节区权限与导入表精简度；
5. 对可疑节区算熵，把「高熵 + 精简导入表 + 异常节名」三个信号放在一起判断是否加壳。

这条流水线的产出是一张**疑点清单**，例如：

| 疑点 | 静态证据 | 待动态验证 |
| --- | --- | --- |
| 疑似加壳 | 熵 7.4、导入表只剩 `LoadLibraryA`/`GetProcAddress` | 运行后 OEP 落在哪、还原出的导入表是什么 |
| 疑似释放载荷 | `.rsrc` 里有一个未命名的大块资源 | 是否 `FindResource` 取出并写盘 |
| 疑似持久化 | 字符串里出现 `CurrentVersion\Run` | 注册表写操作是否真实发生 |

这张清单就是下一节《动态分析与沙箱》的输入——**静态分析的价值不止在于它自己回答了什么，更在于它为动态分析指明了「该盯着哪里看」**。

## 7 小结

- **静态分析 = 不执行程序的侦察**，顺序：哈希 → 文件类型 → 字符串 → PE 结构 → 加壳检测。
- **哈希**给出唯一指纹，可检索在线样本库；**文件头**而非扩展名才是身份。
- **导入表**是情报金矿：异常精简 ≈ 加壳或动态加载；`LoadLibraryA`/`GetProcAddress` 是动态解析的标准姿势。
- **加壳的静态信号**：异常节区名、高熵、导入表极简，三者常同时出现。
- **香农熵** $H = -\sum p_i \log_2 p_i$ 度量字节的可预测性，高熵 ≈ 加密或压缩。
- 静态结论都是推测，需要动态分析来证实或证伪。

在下一节，我们将把样本放进受控的虚拟机里真正运行它，用进程、文件、注册表与网络的蛛丝马迹验证静态猜测——这就是**动态分析与沙箱**。
