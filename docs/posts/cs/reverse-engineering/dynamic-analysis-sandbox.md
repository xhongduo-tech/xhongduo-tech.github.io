## 为什么从动态分析开始

上一节的静态分析给出一堆「疑似」——高熵节区疑似加壳、导入表里疑似要创建进程、资源里疑似藏着载荷。但这些全是推测。**动态分析（dynamic analysis）就是让样本真正跑起来，用它的行为验证静态猜想。** 静态分析回答「它是什么」，动态分析回答「它做了什么」——两者互为对方的试金石。

为什么这套流程在《逆向工程与二进制分析》里重要到单开一节？因为恶意代码设计的核心矛盾就是「藏住意图」。静态层面作者可以用加壳、加密、多态藏，但**程序一旦运行，必然要在文件系统、注册表、进程、网络四个舞台上做出动作**，这些动作就是洗不掉的行为指纹。动态分析的整个方法论，就是「把舞台搭好、把摄像头装好、然后让演员登场」。

## 1 安全前提：虚拟机与快照

动态分析的第一步不是装工具，而是**建立隔离环境**。标准做法是在宿主机上架一台虚拟机，把所有分析工具都装进虚拟系统，样本只在这个系统里跑。<span class="marginnote">快照（snapshot）是动态分析的第一原则：运行前拍快照，分析完回滚，每次都在「出厂状态」的系统里跑样本。一个样本反复运行几十次，系统却永远干净——这就是快照的魔法。</span>

隔离带来的另一个好处是**可观测性**。宿主机的杀软可能干扰样本，样本也可能觉察到分析工具而拒演（反调试、反虚拟机，见《反调试与反虚拟机技术》）；而快照能保证每次运行从同一起点出发，行为对比才有意义。

## 2 三大侦察工具：进程、注册表、文件系统

Windows 上动态分析的标准工具箱来自 Sysinternals，三个工具构成「行为三角」：

**Process Monitor（procmon）**：实时记录进程对文件、注册表、网络的每一次访问。<span class="marginnote">procmon 可以设置过滤器（只看某个进程、只看写入、只看失败），还可以勾选「Drop Filtered Events」让无关记录不积压。排障和恶意分析它都是第一神器。</span>

**Process Explorer（procexp）**：进程树的放大镜。比任务管理器强在：显示每个进程的命令行、父进程、加载的 DLL、句柄；还能对单个进程 `Restart`、`Suspend`、查看其属性。<span class="marginnote">关注两个细节：父进程是谁（恶意样本常常由一个看似无辜的进程创建）、加载了哪些可疑 DLL（DLL 注入的信号）。</span>

**Regshot / RegScanner**：对注册表拍前后快照并 diff。恶意代码最常见的持久化手段就藏在注册表里：`HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` 是开机自启动的老地方，服务键、IFEO（映像劫持）、AppInit_DLLs 也都是经典的藏身处。

**文件系统**：配合 procmon 的写入过滤，观察样本创建了哪些文件、释放了什么载荷。还要提前建好**诱饵**：在桌面放一个看似重要的 `.docx`，在浏览器目录留点「账号密码」痕迹——诱饵被碰说明样本在搜集敏感文件。

## 3 模拟网络：让样本以为自己在联网

网络是动态分析里最容易出彩也最容易失控的一环。真实联网的坏处是危险且不可控：样本可能下载真正的恶意载荷、向真实 C2 服务器回传数据。所以分析环境的铁律是**伪造一个假的互联网**。

标准做法：分析机的 DNS 指向本地伪造 DNS 服务器，所有域名解析全部指向 127.0.0.1；再在本机起一个监听端口 80 的假 Web 服务器（inetsim、FakeNet-NG 一类工具）。样本请求 `http://bad.com/drop.exe`，返回的是本地假服务器吐出的一个无害文件——但样本的**请求动作本身**被完整记录下来了。<span class="marginnote">网络行为的价值在于「意图」而非「结果」：样本要连哪个域名、发什么协议、回传什么数据，这些信息比它有没有连成功重要得多。</span>

**辨析｜易错点：** 别让分析机开着真实代理或 VPN，也别在快照里预存真实的浏览器登录态。任何「真实网络痕迹」都可能被样本利用，也可能让分析失败——伪造 DNS 是「所有解析都指向本地」，而 VPN 是「所有流量走真实出口」，两者天差地别。

## 4 沙箱：自动化与手动的边界

除了手工搭环境，还有现成的自动沙箱：Cuckoo、CAPE 等开源沙箱，以及 VirusTotal 背后的在线沙箱。自动沙箱把「运行 + 记录」打包成流水线：提交文件 → 在隔离环境里运行几十秒到几分钟 → 输出一份行为报告（网络请求、文件操作、注册表修改、进程树）。

沙箱省时省力，但有两道硬伤。**第一，时间是有限的**——样本可以用「休眠」对抗沙箱：先 `sleep` 几小时再发作，自动沙箱等不起；或者检测到自己运行时间太短就不执行恶意逻辑。<span class="marginnote">这是经典的「时间对抗」：`GetTickCount`/`rdtsc` 计时、`sleep` 拖延都是沙箱的克星，我们会在反虚拟机一节详细拆解。</span>**第二，行为是失真的**——沙箱环境太干净，样本会感知到「这不是真实用户」而拒绝行动（不弹窗、不联网、什么都不做）。

所以正确姿势是：**自动沙箱做初步筛查，手工环境做深度取证**。先用沙箱判断「这个样本值不值得深挖」，再用 procmon + 伪造网络的手工环境把行为钉死到证据级别。

### 4.1 判断「要不要手工深挖」的三个信号

沙箱报告出来后的第一件事不是写报告，而是**决定投入度**。三个信号帮你判断这单值不值得手工分析：

- **行为密度**：沙箱里样本是否真的做了事？访问了网络、写了注册表、创建了子进程？一个「什么都不做」的样本，要么是纯窃密型（行为全在内核层，沙箱看不见），要么是在反沙箱装干净（见《反调试与反虚拟机技术》）——两者都值得手工深挖；
- **独特性**：样本用了 DGA、进程注入、驱动加载这类「高级动作」吗？独特动作 = 高研究价值；
- **时效性**：样本是新型号还是老家族变种？威胁情报平台（VirusTotal 的历史样本、家族标签）能快速给出「新旧」判断——老样本查完家族资料即可收工，新样本才需要完整的动态取证。

## 5 从行为到指标：动态分析的产出

动态分析的最终产出不是「它跑了」，而是一组**可交付的行为指标（IOC，Indicators of Compromise）**：

- 文件的写入与释放（哪个目录、什么名字）；
- 注册表的读写（哪个键、自启动项）；
- 网络请求（域名、端口、协议、请求内容）；
- 进程行为（创建了谁、注入了谁、加载了谁）；
- 互斥量与命名管道（样本自己用来防止多实例的名称，是最独特的行为指纹之一）。

这些指标会直接进入后面的《恶意代码行为分析》与《恶意代码代码分析》——**行为分析给出「它做了什么」，代码分析回答「它怎么做到的」**，两者合起来才构成一份完整的分析报告。

## 6 小结

- **动态分析 = 让样本运行并观察其行为**，与静态分析互为验证；隔离是前提。
- **快照 + 回滚**保证每次运行从同一起点出发，系统永不污染。
- 三大侦察工具：**procmon**（文件/注册表/网络实时监控）、**procexp**（进程树）、**Regshot**（注册表 diff）。
- **网络必须伪造**：DNS 全部解析到本地 + 本地假服务器，记录「意图」而非「结果」。
- **自动沙箱做筛查、手工环境做取证**；沙箱怕休眠对抗、环境失真。
- 产出是**行为指标 IOC**：文件、注册表、网络、进程、互斥量五类证据。

在下一节，我们将从「看行为」深入「看内部」——把调试器挂到样本上，在指令级别观察它每一行代码的执行，这就是**调试器实战与动态调试**。
