## 为什么从完整性开始

前四篇都在回答「怎么把数据写对」：inode 怎么落、日志怎么记。但还有一个更阴险的问题：**磁盘没崩、系统没断电，数据却在某次读写中悄悄变了质**——这叫**静默损坏（silent data corruption）**。<span class="marginnote">研究显示，存储系统里很大一部分数据损坏从不抛出错误：磁盘内部校验抓不到固件 bug、地址错写这类故障。文件系统、RAID、数据库若不主动校验，就永远蒙在鼓里。</span>

ZFS、Btrfs 把「校验和」内建进文件系统，宣称「自我修复」；大模型训练动辄 PB 级数据，一份静默损坏的语料足以污染整个模型。理解校验和，是理解这一切防线的地基。

## 1 静默损坏：四种不打报告的故障

「检测到坏块就报错」是理想情况，现实中错误往往被悄悄吞掉。典型的故障模式有：

- **数据损坏（data corruption）**：读出的数据与写入时不同，且磁盘没报错。来源包括固件 bug、写路径上的位翻转、磁盘缓存策略缺陷。
- **地址错写（misdirected write）**：数据被写进了错误的块——块本身完好，内容却不对。
- **丢失写（lost write）**：系统以为写完了，数据其实根本没落盘。
- **介质退化**：磁道部分损坏，坏扇区开始返回伪数据而非报错。

**辨析｜易错点：** 「校验和能发现损坏」和「校验和能发现所有损坏」是两回事。对**丢失写**，普通每块校验和毫无办法——因为「该写的块」与「写成功的块」对不上号，需要额外机制（如 ZFS 的事务号）来察觉。

## 2 解法骨架：写时记、读时验

**校验和（checksum）**：一段与数据块绑定的、由数据计算出的短摘要。协议极简：

- **写路径**：对块 $B$ 计算校验和 $C = H(B)$，把 $B$ 与 $C$ 都写入磁盘。
- **读路径**：读出 $B'$ 与 $C$，计算 $H(B')$，与存储的 $C$ 比对。
- **不一致**：判定损坏，触发修复或向应用报错。

校验和要存哪？两种做法：独立的校验和数据区（与数据块分离，如 RAID 的做法），或与数据块相邻存放。ZFS 更进一步：**校验和只存在于父块的指针里**——父块自带孩子块的校验和，树形地层层校验。

## 3 公式解析：校验与验证的不变式

校验的核心是一个等式：

$$
C = H(B),\qquad \text{读时验证： } H(B') \stackrel{?}{=} C
$$

分三步拆解：

- **第一步，$H$ 是什么**：一个把任意长数据压成固定长度摘要的函数。好校验函数要求**雪崩效应**——任意一个比特翻转，摘要都剧烈变化。这样偶发的一位错、几位错都能被察觉。
- **第二步，为什么能检测**：只要 $B' \neq B$ 时 $H(B') \neq H(B) = C$ 以压倒性概率成立，损坏就会被发现。校验和并非数学上不可能碰撞，而是碰撞概率足够低（32 位 CRC 对随机损坏的漏检率约 $2^{-32}$），工程上可以接受。
- **第三步，CRC 的由来**：CRC 把块当作多项式 $B(x)$ 的系数，做**模 2 多项式除法**，余数即校验值：$C = (B(x) \cdot x^{32}) \bmod P(x)$。它用线性移位寄存器就能硬件实现，所以网络与存储界几十年都爱它——代价是它**抗随机错误不抗人为篡改**，防篡改需要 MD5/SHA 这类密码学散列。

**重点：** 检测到损坏只是第一步，恢复才是目的。恢复的手段有两条：**纠错**（若冗余信息足够，直接重建）与**复制**（从副本读）。这正是 RAID 与 ZFS 副本存在的意义——没有冗余，校验和只能让你「知道坏了」而不是「恢复数据」。

## 4 补齐缺口：write-back 与自我修复文件系统

只有校验和还不够，三类缺口要逐个补：

- **丢失写**：把「校验和 + 序号（或事务 id）」一起存储，读时发现「序号对不上」即察觉丢失写。
- **地址错写**：校验和里混入物理块地址，让「写到别处的数据」在校验时立刻现形。<span class="marginnote">把「位置」纳入校验输入，是防地址错写的标准招数：即使内容碰巧一致，位置不符也会触发报警。</span>
**写验证（write-verify）**：写完立刻读回比对。代价是写带宽减半，常用于高可靠场景。

**ZFS 与 Btrfs 的「自我修复」**：它们把「校验和 + 写时复制（copy-on-write）+ 多副本/RAID」组合：父块持有子块校验和，读时逐层验证，一旦发现坏块就从一个副本读出好数据，并**自动把好数据写回坏块**——这就是「self-healing」的字面含义。<span class="marginnote">写时复制（COW）在这里价值连城：数据从不在原地改写，旧版本永远留在原地等待校验，天然避免「先写后崩」的窗口。COW 同时是 LSM 树与数据库快照的亲戚。</span>

## 5 核心要点：三类故障与应对对照

| 故障 | 校验和能否发现 | 需要什么额外机制 |
| --- | --- | --- |
| 位翻转 / 数据损坏 | 能 | 仅校验和即可 |
| 地址错写 | 靠位置纳入校验输入 | 校验含块地址 |
| 丢失写 | 单独不行 | 校验含序号 / 事务号 |
| 人为篡改 | CRC 不行 | 密码学散列 |

## 6 小结

- **静默损坏**是不报错的变质，真实且常见，普通磁盘自检抓不住。
- 防线是**写时记校验、读时验校验**；校验函数要求雪崩效应，CRC 靠模 2 多项式除法实现。
- 校验和**只解决「检测」**，恢复要靠**冗余（RAID、副本）**——所以校验与冗余成对出现。
- 丢失写、地址错写需要**序号 / 地址纳入校验输入**补齐。
- **ZFS/Btrfs** 用「校验和 + COW + 冗余」实现自动修复，是现代存储完整性的标杆。
