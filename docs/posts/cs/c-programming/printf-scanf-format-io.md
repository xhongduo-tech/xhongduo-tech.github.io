## 为什么从 printf/scanf 讲起

程序不能永远活在真空里。它需要**输出**结果给用户、**输入**数据来处理——而 C 语言与终端打交道最常用的两个函数就是 `printf`（格式化输出）与 `scanf`（格式化输入）。<span class="marginnote">它们都定义在标准头文件 `stdio.h` 中，名字里的 `f` 是 format（格式）的意思：你可以规定输出的宽度、精度、对齐方式、进制，而不是像 Python 的 `print` 那样由系统自动决定。</span>搞懂 `printf` 的格式串，你就能精确控制程序说话的方式；搞懂 `scanf`，你就能安全地把用户的输入读进变量。这一节是后续所有需要交互的程序的通用工具。

## 1 printf 的核心：格式串与转换说明

`printf` 的第一个参数是**格式串（format string）**，后面的参数按顺序被替换进格式串里 `%` 开头的**转换说明（conversion specification）**：

```c
printf("名字：%s，年龄：%d，身高：%.1f 米\n", "小明", 18, 1.75);
/* 输出：名字：小明，年龄：18，身高：1.8 米 */
```

常用转换说明：

| 转换说明 | 含义 | 示例参数 | 输出 |
| --- | --- | --- | --- |
| `%d` / `%i` | 有符号十进制整数 | `42` | `42` |
| `%u` | 无符号十进制整数 | `42u` | `42` |
| `%o` | 八进制整数 | `8` | `10` |
| `%x` / `%X` | 十六进制整数（小/大写） | `255` | `ff` / `FF` |
| `%f` | 浮点数（十进制） | `3.14159` | `3.141590` |
| `%e` / `%E` | 科学计数法 | `3.14159` | `3.141590e+00` |
| `%g` | 按数值自动选 `%f` 或 `%e` | `3.14159` | `3.14159` |
| `%c` | 单个字符 | `'A'` | `A` |
| `%s` | 字符串（`char*`） | `"hi"` | `hi` |
| `%p` | 指针地址 | `&x` | `0x7ffee...` |
| `%%` | 输出一个 `%` | —— | `%` |

**`%s` 需要字符串的地址（`char*`）**，`%c` 需要字符的值；`%d` 需要 `int`，`%f` 需要 `double`（注意 `float` 在传给 `printf` 时会被自动提升为 `double`）。参数类型与转换说明不匹配属于**未定义行为**——`printf("%d", 3.14)` 不会报错，但会输出一个毫无意义的数字，因为函数按 `int` 去读一个 `double` 的字节。

## 2 修饰符：宽度、精度与标志

在 `%` 与转换字符之间可以插入**修饰符（modifier）**，它们控制输出的格式：

```c
printf("[%8d]\n", 42);      /* [      42]  宽度 8，右对齐 */
printf("[%-8d]\n", 42);     /* [42      ]  宽度 8，左对齐 */
printf("[%08d]\n", 42);     /* [00000042]  宽度 8，前导补 0 */
printf("[%.2f]\n", 3.14159);/* [3.14]      保留 2 位小数 */
printf("[%8.2f]\n", 3.14159);/* [    3.14]  宽度 8 且 2 位小数 */
```

**宽度（width）**：最小输出宽度。内容不够时用空格（或 `0`）补齐；内容超过宽度则正常扩展，不会截断。
**精度（precision）**：`.` 后跟数字。对浮点是小数点后的位数，对字符串是最大输出字符数：`%.5s` 只打印前 5 个字符。
- **标志（flag）**：`-` 左对齐、`0` 补零、`+` 显示正号、`#` 八进制/十六进制加前缀。<span class="marginnote">表格对齐是 `printf` 最实用的场景：`printf("%-20s %-10d\n", name, score);` 能把一列名字按宽度对齐，是命令行工具打印报表的标配写法。</span>

```c
printf("[%-10s]\n", "hi");   /* [hi        ]  字符串左对齐 */
printf("[%#x]\n", 255);      /* [0xff]         十六进制带前缀 */
```

## 3 scanf：把输入读进变量

`scanf` 与 `printf` 格式相似，但有一个**决定性的不同**：`scanf` 需要的是变量的**地址**，而不是变量的值。这就是 `&` 取地址运算符在 `scanf` 中出场的理由：

```c
int age;
double height;
printf("请输入年龄和身高：");
scanf("%d %lf", &age, &height);
printf("你输入了 %d 岁，%.2f 米\n", age, height);
```

注意两个易错点：

`scanf("%lf", &height)` 读 `double` 用 `%lf`，而 `printf` 打印 `double` 只用 `%f`——**`printf` 与 `scanf` 对浮点的转换说明不一样**，这是一个高频混淆点。<span class="marginnote">原因在于参数传递：`printf` 收到的是值（`float` 已提升为 `double`，所以 `%f` 就够）；`scanf` 收到的是指针，`%lf` 告诉它「你指向的是一个 `double`」，`%f` 则对应 `float*`。记法：scanf 里 `l` 修饰符表示长版本。</span>
**读字符串不用 `&`**：数组名本身就是地址，`scanf("%s", name)` 直接传 `name`，而不要写成 `&name`。

**scanf 的空白处理规则**：`%d`、`%f` 等会自动跳过输入中的空白（空格、换行、制表符）；`%c` 不跳过，会读入任意字符——所以 `scanf(" %c", &ch)` 前面加一个空格来跳过残留的换行。

## 4 输入缓冲与混用陷阱

终端输入是**行缓冲（line buffered）**的：你按回车后，整行内容才进入程序的输入流。于是 `scanf` 与 `getchar` 混用时，经常出现「吃掉了换行符」的经典事故：

```c
int n;
char ch;
scanf("%d", &n);      /* 输入 42 回车：42 被读走，换行符还留在缓冲里 */
scanf("%c", &ch);     /* %c 不跳过空白，ch 直接读到了那个 '\n' */
```

解决方式：在 `%c` 前加空格（`scanf(" %c", &ch)`），或者先用循环把缓冲里的残留清掉。<span class="marginnote">`%c` 的「不跳过空白」特性有时反而是想要的——比如逐字符处理时，你需要看到每个空格。规则本身不分对错，关键是你得知道它在什么场景下用。</span>

`scanf` 的**返回值**是成功读取的项数：`scanf("%d %d", &a, &b)` 返回 `2` 表示两项都读到了；返回 `0` 表示第一项就失败；返回 `EOF`（通常是 `-1`）表示输入结束。**检查返回值是写健壮输入的标准做法**：

```c
if (scanf("%d", &n) != 1) {
    printf("输入无效！\n");
    return 1;
}
```

## 5 核心对比表：printf 与 scanf

| 维度 | `printf` | `scanf` |
| --- | --- | --- |
| 作用 | 格式化输出到 stdout | 从 stdin 格式化读取 |
| 传参方式 | 传值 | 传**地址**（`&`） |
| 字符串参数 | `char*`（字符串首地址） | `char*`，数组名即地址，不用 `&` |
| 浮点转换 | `%f` 即可（读 `double` 值） | `%lf` 读 `double`，`%f` 读 `float` |
| 空白处理 | 无关 | 数值转换自动跳过空白；`%c` 不跳过 |
| 返回值 | 输出的字符数 | 成功读取的项数（`EOF` 表示结束） |

一张表点破两者最根本的对称关系：**一个把值「写」出去，一个把值「读」进来；输出传值，输入传址**。记不住别的，记住这一条，就能避开 90% 的输入输出错误。

## 6 公式解析：`printf("%8.2f", x)` 的逐段解读

\underbrace{\%}_{起始} \ \underbrace{8}_{宽度} \ \underbrace{.2}_{精度} \ \underbrace{f}_{转换}
