## 为什么从运算符讲起

上一节我们认识了数据的「容器」，这一节要让数据真正动起来：加减乘除、比较大小、逻辑判断、按位操作。运算符是构成**表达式（expression）** 的积木，而表达式是 C 程序的基本计算单元。<span class="marginnote">表达式与语句的区别：表达式有值（如 `3 + 5` 的值是 8），语句是动作（如 `x = 3 + 5;` 是赋值语句，末尾有分号）。几乎每条语句内部都由表达式构成。</span>本节的重头戏是 C 语言的**隐式类型转换（implicit conversion）** 规则——它决定了混合运算时「谁迁就谁」，也是无数隐蔽 bug 的策源地。

## 1 算术运算符

C 的算术运算符与数学高度重合：

| 运算符 | 含义 | 示例 | 结果 |
| --- | --- | --- | --- |
| `+` | 加法 | `7 + 3` | `10` |
| `-` | 减法 | `7 - 3` | `4` |
| `*` | 乘法 | `7 * 3` | `21` |
| `/` | 除法 | `7 / 3` | `2` |
| `%` | 取余 | `7 % 3` | `1` |
| `++` / `--` | 自增 / 自减 | `i++` | 使用后加一 |

两个容易翻车的点：

**整数除法会丢弃小数部分**：`7 / 3` 等于 `2` 而不是 `2.333`。若想要浮点结果，至少一个操作数必须是浮点：`7.0 / 3` 才是 `2.3333`。<span class="marginnote">这是「向零截断」：正数向下取整，负数向上取整。C99 起规定 `-7 / 3` 的结果是 `-2`（向零），而 Python 里 `-7 // 3` 是 `-3`（向下取整）——同一种除法，两种语言语义不同。</span>
**取余 `%` 只作用于整数**：`7.5 % 2` 是编译错误，浮点取余要用 `fmod()` 函数。
**除法注意除零**：整数除以 `0` 是未定义行为，通常导致程序崩溃（`SIGFPE`）。

**自增运算符**有前置与后置之分：`i++` 先使用 `i` 再自增，`++i` 先自增再使用。在同一个表达式中多次修改同一变量（如 `a = i++ + i++;`）属于未定义行为——**永远不要在一条语句里对一个变量自增两次**。

## 2 关系、逻辑与赋值运算符

**关系运算符**比较两个值，结果是整数 `1`（真）或 `0`（假）：

```c
int a = 5, b = 3;
printf("%d\n", a > b);   /* 1 */
printf("%d\n", a == b);  /* 0，注意是两个等号 */
```

**逻辑运算符**组合真值，支持**短路求值（short-circuit）**：

- `&&` 逻辑与：左边为假就不再求右边，整个为假。
- `||` 逻辑或：左边为真就不再求右边，整个为真。
- `!` 逻辑非。

```c
int x = 0;
if (x != 0 && 10 / x > 1)   /* 安全：x==0 时短路，10/x 不会执行 */
    printf("div\n");
```

短路求值让「先检查再使用」成为安全惯例：`if (p != NULL && p->value > 0)` 可以放心写，因为 `p` 为空时根本不会访问 `p->value`。<span class="marginnote">在 C 里「真」是任何非零值，`if (x)` 等价于 `if (x != 0)`。初学者常把 `=`（赋值）与 `==`（相等）写混——`if (x = 5)` 会把 5 赋给 x，然后因为 5 非零而恒为真，这是最经典的 C 陷阱之一。</span>

**赋值运算符**：`=` 是赋值，`+=`、`-=`、`*=`、`/=` 是复合赋值，`x += 2` 等价于 `x = x + 2`。赋值表达式本身也有值（就是赋进去的值），因此可以连续赋值：`a = b = c = 0;`。

## 3 位运算符

位运算直接操作整数的二进制位，是 C 相对高级语言的一大特权：

| 运算符 | 含义 | 示例（8 位） | 结果 |
| --- | --- | --- | --- |
| `&` | 按位与 | `0b1100 & 0b1010` | `0b1000` |
| `\|` | 按位或 | `0b1100 \| 0b1010` | `0b1110` |
| `^` | 按位异或 | `0b1100 ^ 0b1010` | `0b0110` |
| `~` | 按位取反 | `~0b1100` | `0b...0011` |
| `<<` | 左移 | `1 << 3` | `8` |
| `>>` | 右移 | `16 >> 2` | `4` |

位运算在嵌入式、位图、权限掩码、哈希散列中大量使用：

```c
/* 用位掩码管理一组开关 */
#define FLAG_A 0x01
#define FLAG_B 0x02
unsigned char flags = 0;
flags |= FLAG_A;          /* 打开 A */
flags &= ~FLAG_B;         /* 关闭 B */
if (flags & FLAG_A)       /* 判断 A 是否打开 */
    printf("A on\n");
```

`x << n` 相当于乘以 $2^n$，`x >> n` 相当于整除 $2^n$——但**右移有符号负数**时行为与实现相关（算术右移补符号位 / 逻辑右移补 0），跨平台代码要小心。位运算与位字段的完整实践见《位运算与位字段》一节。

## 4 类型转换：隐式与显式

不同类型混用时，C 会把它们转换为同一类型再运算，这套规则叫**通常算术转换（usual arithmetic conversions）**。转换方向遵循「小类型升级为大类型」：

```
char/short  →  int  →  unsigned int  →  long  →  unsigned long
    float   →  double  →  long double
```

核心原则：**值域小的向值域大的转换**，而 `float` 在整型运算中通常先提升为 `double`。`int` 与 `unsigned int` 混算时，`int` 被转成 `unsigned int`——这是最危险的转换，看这个例子：

```c
int a = -1;
unsigned int b = 1;
if (a < b)
    printf("a 更小\n");   /* 不会打印！-1 被转成 4294967295 */
```

`-1` 转成 `unsigned` 后变成巨大的正数，`a < b` 为假。<span class="marginnote">这是 C 世界里最著名的反直觉行为之一。在循环中比较 `int i` 与 `size_t`（无符号）长度时，`i` 一旦为负，条件立刻错乱——用 `size_t` 遍历时建议把下标也声明为 `size_t`。</span>

**显式转换**用强制类型转换（cast）运算符：`(double)x` 把 `x` 转成双精度。需要显式转换的典型场景：整数除法想要小数结果、把 `void*` 转回具体指针。

```c
int a = 7, b = 3;
double r = (double)a / b;   /* 先把 a 转成 double，再做除法 */
```

## 5 运算符优先级

表达式求值顺序由**优先级（precedence）** 与**结合性（associativity）** 决定。优先级从高到低的关键片段：

| 优先级 | 运算符 | 结合性 |
| --- | --- | --- |
| 最高 | `()` `[]` `.` `->` | 从左到右 |
| ↑ | `!` `~` `++` `--` `-`（一元）`*`（解引用）`&`（取址） | 从右到左 |
| ↑ | `*` `/` `%` | 从左到右 |
| ↑ | `+` `-` | 从左到右 |
| ↑ | `<<` `>>` | 从左到右 |
| ↑ | `<` `<=` `>` `>=` | 从左到右 |
| ↑ | `==` `!=` | 从左到右 |
| ↑ | `&` | 从左到右 |
| ↑ | `^` | 从左到右 |
| ↑ | `\|` | 从左到右 |
| ↑ | `&&` | 从左到右 |
| ↑ | `\|\|` | 从左到右 |
| ↑ | `?:` 三目 | 从右到左 |
| 最低 | `=` `+=` 等赋值 | 从右到左 |

一个必须背下的经典事实：**`*`（乘）高于 `+`（加），`==` 高于 `&`，而 `&` 高于 `&&`**。于是 `x & y == 0` 实际是 `x & (y == 0)`，而不是 `(x & y) == 0`——这类「想当然」的错位是位运算与比较混写时的高发事故。<span class="marginnote">经验法则：当你不确定优先级时，加括号。可读性优先于「我记住了优先级表」。几乎所有 C 风格指南都要求对复杂条件显式加括号。</span>

## 6 公式解析：`(a + b) / c` 的求值过程

把本节规则串起来，看一个具体的表达式求值：

$$
r = \frac{a + b}{c} \quad\Longrightarrow\quad r = (a + b) / c
$$

假设 `int a = 7, b = 3, c = 2;`，分步推演：

- **第一步，确定括号内先算**：`(a + b)` 最内层括号优先，`7 + 3 = 10`。
- **第二步，除法截断**：`10 / 2` 两个操作数都是 `int`，整数除法，结果是 `5`。
- **第三步，赋值转换**：把 `int` 值 `5` 赋给 `double` 类型的 `r`，隐式转换为 `5.0`。

若把式子改成 `r = a / (double)b + c`，则 `(double)b` 显式转成 `3.0`，`a / 3.0` 因 `double` 参与而变成浮点除法，`7 / 3.0 = 2.3333`。**同样的数字，不同的类型搭配，结果天差地别**——这条公式解析浓缩了本节全部要点：优先级决定顺序，类型决定除法语义。

## 7 核心对比表：`==` 与 `=`，`&` 与 `&&`

| 易混对 | 含义 | 常见误用 | 后果 |
| --- | --- | --- | --- |
| `=` | 赋值 | `if (x = 5)` | 恒为真，赋值被当成比较 |
| `==` | 相等比较 | `if (x == 5)` | 正确用法 |
| `&` | 按位与 | `x & 1 == 1` | 被解析成 `x & (1==1)` |
| `&&` | 逻辑与（短路） | `x > 0 && y > 0` | 正确用法 |
| `/` | 除法 | `7 / 3` | 整数除法得 `2`，非 `2.33` |
| `%` | 取余 | `7 % 3` | 得 `1`，仅限整数 |

这五组对比是 C 初学者与面试的高频陷阱：**一个字符之差，语义完全不同**。见到 `&` 先问「这是取地址、按位与、还是逻辑与的误拼」——写代码时多一点括号，少一点「我记得」。

## 8 小结

- 算术、关系、逻辑、位、赋值五类运算符构成表达式；表达式有值，语句是动作。
- 整数除法向零截断；取余 `%` 仅限整数；短路求值让 `&&`/`||` 可安全做「先检查后用」。
- 位运算直接操作二进制位，`<<`/`>>` 对应乘除 $2^n$
