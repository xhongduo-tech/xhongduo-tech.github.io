## 为什么从第一个程序开始

从极限到大模型这条路上，有无数层抽象：Python 解释器、Java 虚拟机、深度学习框架，乃至操作系统本身。剥开它们，最底下几乎都站着同一种语言——**C 语言**。<span class="marginnote">Linux 内核、Windows 内核、Python 的 CPython 解释器、NumPy 的底层扩展，全部用 C（或其近亲 C++）写成。学 C，是在学整个计算机世界的地基。</span>本专题从「第一个 C 程序」出发，先把程序如何变成机器能执行的东西讲清楚，再逐步进入变量、控制流、指针与内存。这一节的产出是一个最小却完整的程序，以及你亲手跑通它的那条路径。

## 1 程序的最小骨架

经典的第一课，是打印一句话：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}
```

把这段代码存成 `hello.c`，编译运行，屏幕上会出现：

```
Hello, world!
```

这个 6 行的程序包含了 C 程序**几乎全部的结构要素**，值得逐行拆开：

`#include <stdio.h>` 是**预处理指令（preprocessor directive）**：告诉编译器在编译前，把标准输入输出头文件 `stdio.h` 的内容「粘贴」进来，这样我们才能使用 `printf`。<span class="marginnote">以 `#` 开头的行是预处理指令，它们在真正的编译开始前就被处理掉。除了 `#include`，后面还会见到 `#define`、`#ifdef` 等，详见《预处理：宏、条件编译与 include》。</span>
`int main(void)` 定义了**主函数（main function）**：程序执行的入口点，操作系统从这里开始运行你的程序。`int` 是返回值类型，`(void)` 表示不接收参数。
花括号 `{ }` 围起的是**函数体**，函数的所有语句都写在这里。
- `printf("Hello, world!\n");` 是一条**函数调用语句**：`\n` 是**换行符（newline）**，表示输出后换到下一行。
- `return 0;` 把 `0` 返回给操作系统，**0 表示程序正常结束**。

**一切 C 程序都以 `main` 为入口，以 `return 0;` 宣告成功结束**——这个约定从 1972 年延续到今天。

## 2 编译流程：从源码到可执行文件

`hello.c` 是人类可读的文本，而 CPU 只认识机器指令。把前者变成后者，要经过**预处理 → 编译 → 汇编 → 链接**四个阶段。以 Linux/macOS 上的 GCC 为例：

```bash
$ gcc hello.c -o hello
$ ./hello
Hello, world!
```

一条 `gcc` 命令背后，是四道流水线工序：

- **预处理（preprocess）**：处理所有 `#` 开头的指令。`#include <stdio.h>` 会被替换成头文件的完整内容，`#define` 定义的宏会被文本替换。此阶段产出仍以 `.i` 结尾的纯文本。
- **编译（compile）**：把预处理后的 C 代码翻译成**汇编语言（assembly）**——贴近机器的低级语言，产出 `.s` 文件。这是真正「读懂你意图」的一步，语法错误大多在这里报出。
- **汇编（assemble）**：把汇编代码翻译成**机器指令（machine code）**，即 CPU 认识的二进制，产出 `.o` 目标文件（object file）。目标文件里的地址还是相对的，尚不能单独运行。
- **链接（link）**：把目标文件与所需的**库（library）**拼装起来，把 `printf` 的调用指向标准库中真正的实现，补齐所有地址，最终产出可执行文件 `hello`。<span class="marginnote">`printf` 的实现在 C 标准库（glibc / libc 等）里。链接阶段把「调用点」与「实现」接上，若漏了某个实现，你会看到 `undefined reference to ...` 这样的链接错误。</span>

![C 程序编译流水线：源码经预处理、编译、汇编、链接四阶段成为可执行文件](/images/c-programming/first-c-program-and-compilation-1.svg)

这四步对应了四类不同的错误：预处理阶段的文件缺失、编译阶段的语法错误、汇编阶段极少见、链接阶段的符号缺失。**学会从报错位置反推是哪个阶段出了问题，是排错的第一项基本功。**

### 常用编译选项

`gcc` 的选项让构建过程更可控，下面是最常用的一批：

| 选项 | 作用 |
| --- | --- |
| `-o 名字` | 指定输出文件名 |
| `-Wall -Wextra` | 开启常见警告 |
| `-g` | 生成调试信息（供 GDB 使用） |
| `-O2` | 开启优化（程序更快） |
| `-c` | 只编译不链接，产出 `.o` 目标文件 |
| `-E` / `-S` | 只做预处理 / 只做到汇编 |
| `-lm` | 链接数学库 |

`-Wall` 的警告是 C 工程师的「免费体检」：未使用变量、可疑的赋值、格式串不匹配，都能在编译期提前暴露。**工程习惯是把警告当错误看**——每消除一条警告，就少埋一个潜在的 bug。

## 3 与操作系统对话：main 与返回状态

`main` 不是普通的函数，它是程序与操作系统之间的**握手点**：

程序启动时，操作系统为进程准备环境，然后调用 `main`。
- `main` 返回的整数就是**退出状态（exit status）**。Shell 中紧跟着的 `$?` 会记录它：`0` 表示成功，非 0 表示某种失败。

```bash
$ ./hello
Hello, world!
$ echo $?
0
```

非零的退出码有约定俗成的含义：`1` 通常是「发生了一般性错误」，`2` 常表示「命令行用法错误」。脚本、持续集成工具（CI）正是靠检查进程的退出码来判断某一步是成功还是失败的——你写的每一个 C 程序，都在通过 `main` 的返回值与更大的自动化体系对话。<span class="marginnote">Linux 手册约定退出码 0–127 可供程序自行使用，128 以上由信号触发，如「段错误」常表现为 139（128 + 11，SIGSEGV）。这个约定贯穿整个 C 生态。</span>

**最容易误解的一点是：`main` 里的 `return 0;` 与普通函数的 `return 0;` 语义不同。** 对普通函数，`return` 只是把值交回调用者；对 `main`，这个值还会被操作系统读取并记录为进程的退出状态。这也是为什么 K&R 要求每个程序都以 `return 0;`（或 `exit(0);`）收尾——它是在向操作系统报告「任务完成」。

## 4 K&R 的第二个程序：温度转换表

第一个程序只会打印一句话，还不算「处理数据」。K&R 第1章紧接着给出的经典例子是**华氏—摄氏温度转换表**——它第一次引入变量、算术表达式与循环，是理解「程序 = 数据 + 运算」的最小模型：

```c
#include <stdio.h>

int main(void)
{
    int fahr;

    for (fahr = 0; fahr <= 300; fahr = fahr + 20)
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    return 0;
}
```

这个程序引入了三件新东西：

- **变量声明**：`int fahr;` 告诉编译器，我们要一个存放整数的「格子」，名叫 `fahr`。<span class="marginnote">`fahr` 是 Fahrenheit 的缩写，K&R 用它做变量名是为了让程序好读。变量名先声明后使用，是 C 的静态类型纪律的一部分，详见《基本数据类型与变量》。</span>
- **`for` 循环**：`fahr = 0` 是初始值，`fahr <= 300` 是继续循环的条件，`fahr = fahr + 20` 是每轮末尾的更新。循环体是紧跟其后的那条 `printf`。
- **算术表达式与浮点字面量**：`(5.0 / 9.0) * (fahr - 32)` 是华氏转摄氏的公式，其中 `5.0 / 9.0` 用了浮点除法。

## 5 公式解析：华氏转摄氏的陷阱

温度转换的核心是这条公式：

$$
C = \frac{5}{9}\,(F - 32)
$$

在 C 里，这条公式的写法有一个**著名的陷阱**——整数除法：

- **写错**：`5 / 9 * (fahr - 32)`。这里 `5 / 9` 是两个整数相除，结果为 `0`（C 的整数除法直接舍去小数部分），于是整个表达式恒等于 `0`。
- **写对**：`5.0 / 9.0 * (fahr - 32)`。只要操作数之一是浮点类型，除法就是浮点除法，`5.0 / 9.0 ≈ 0.5556`，结果正确。

再解释一下格式串 `"%3d %6.1f\n"`：`%3d` 把整数按宽度 3 右对齐打印，`%6.1f` 把浮点按总宽 6、保留 1 位小数打印。于是输出会排成整齐的一列：

```
  0   -17.8
 20    -6.7
 40     4.4
 ...
300   148.9
```

**这个例子第一次展示了「同样的公式，写法差一点、结果差千里」**——整数除法是 C 里最容易踩的坑之一，我们在《运算符、表达式与类型转换》还会再遇到它。

## 6 符号常量：让魔法数字消失

温度表里 `300`、`20` 是裸的数字，K&R 称它们为**魔法数字（magic numbers）**，并推荐用 `#define` 引入**符号常量（symbolic constants）**：

```c
#define LOWER 0
#define UPPER 300
#define STEP  20
```

把常数命名为 `LOWER`、`UPPER`、`STEP` 后，循环写成：

```c
for (fahr = LOWER; fahr <= UPPER; fahr = fahr + STEP)
    printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
```

`#define` 是**预处理指令**：在编译开始前，编译器会把代码里所有 `LOWER` 逐字替换成 `0`。它让程序变得更好读、更好改——改上限只需改一处。这是 C 程序员「命名魔法数字」的开端，完整的宏体系我们在《预处理：宏、条件编译与 include》展开。

## 7 小结

- C 程序以 `main` 为唯一入口，`return 0;` 向操作系统报告成功结束。
- 编译四阶段：预处理 → 编译 → 汇编 → 链接；`-Wall` 把警告当错误看。
- 退出状态 `$?` 是程序与 shell / CI 对话的契约，非 0 表示失败。
- 温度表程序引入变量、`for` 循环与浮点表达式；整数除法 `5 / 9` 得 0，是头号陷阱。
- 符号常量（`#define`）把魔法数字变成有名字的常量，是「让意图显式」的第一步。
