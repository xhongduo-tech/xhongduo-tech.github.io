## 为什么从第一个程序开始

从极限到大模型这条路上，有无数层抽象：Python 解释器、Java 虚拟机、深度学习框架，乃至操作系统本身。剥开它们，最底下几乎都站着同一种语言——**C 语言**。<span class="marginnote">Linux 内核、Windows 内核、Python 的 CPython 解释器、NumPy 的底层扩展，全部用 C（或其近亲 C++）写成。学 C，是在学整个计算机世界的地基。</span>本专题从「第一个 C 程序」出发，先把程序如何变成机器能执行的东西讲清楚，再逐步进入变量、控制流、指针与内存。这一节的产出是一个最小却完整的程序，以及你亲手跑通它的那条路径。

## 1 程序的最小骨架

经典的第一课，是打印一句话：

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}
```

把这段代码存成 `hello.c`，编译运行，屏幕上会出现：

```
Hello, world!
```

这个 6 行的程序包含了 C 程序**几乎全部的结构要素**，值得逐行拆开：

`#include <stdio.h>` 是**预处理指令（preprocessor directive）**：告诉编译器在编译前，把标准输入输出头文件 `stdio.h` 的内容「粘贴」进来，这样我们才能使用 `printf`。<span class="marginnote">以 `#` 开头的行是预处理指令，它们在真正的编译开始前就被处理掉。除了 `#include`，后面还会见到 `#define`、`#ifdef` 等，详见《预处理：宏、条件编译与 include》。</span>
`int main(void)` 定义了**主函数（main function）**：程序执行的入口点，操作系统从这里开始运行你的程序。`int` 是返回值类型，`(void)` 表示不接收参数。
花括号 `{ }` 围起的是**函数体**，函数的所有语句都写在这里。
- `printf("Hello, world!\n");` 是一条**函数调用语句**：`\n` 是**换行符（newline）**，表示输出后换到下一行。
- `return 0;` 把 `0` 返回给操作系统，**0 表示程序正常结束**。

**一切 C 程序都以 `main` 为入口，以 `return 0;` 宣告成功结束**——这个约定从 1972 年延续到今天。

## 2 编译流程：从源码到可执行文件

`hello.c` 是人类可读的文本，而 CPU 只认识机器指令。把前者变成后者，要经过**预处理 → 编译 → 汇编 → 链接**四个阶段。以 Linux/macOS 上的 GCC 为例：

```bash
$ gcc hello.c -o hello
$ ./hello
Hello, world!
```

一条 `gcc` 命令背后，是四道流水线工序：

- **预处理（preprocess）**：处理所有 `#` 开头的指令。`#include <stdio.h>` 会被替换成头文件的完整内容，`#define` 定义的宏会被文本替换。此阶段产出仍以 `.i` 结尾的纯文本。
- **编译（compile）**：把预处理后的 C 代码翻译成**汇编语言（assembly）**——贴近机器的低级语言，产出 `.s` 文件。这是真正「读懂你意图」的一步，语法错误大多在这里报出。
- **汇编（assemble）**：把汇编代码翻译成**机器指令（machine code）**，即 CPU 认识的二进制，产出 `.o` 目标文件（object file）。目标文件里的地址还是相对的，尚不能单独运行。
- **链接（link）**：把目标文件与所需的**库（library）**拼装起来，把 `printf` 的调用指向标准库中真正的实现，补齐所有地址，最终产出可执行文件 `hello`。<span class="marginnote">`printf` 的实现在 C 标准库（glibc / libc 等）里。链接阶段把「调用点」与「实现」接上，若漏了某个实现，你会看到 `undefined reference to ...` 这样的链接错误。</span>

![C 程序编译流水线：源码经预处理、编译、汇编、链接四阶段成为可执行文件](/images/c-programming/first-c-program-and-compilation-1.svg)

这四步对应了四类不同的错误：预处理阶段的文件缺失、编译阶段的语法错误、汇编阶段极少见、链接阶段的符号缺失。**学会从报错位置反推是哪个阶段出了问题，是排错的第一项基本功。**

### 常用编译选项

`gcc` 的选项让构建过程更可控，下面是最常用的一批：

| 选项 | 作用 |
| --- | --- |
| `-o 名字` | 指定输出文件名 |
| `-Wall -Wextra` | 开启常见警告 |
| `-g` | 生成调试信息（供 GDB 使用） |
| `-O2` | 开启优化（程序更快） |
| `-c` | 只编译不链接，产出 `.o` 目标文件 |
| `-E` / `-S` | 只做预处理 / 只做到汇编 |
| `-lm` | 链接数学库 |

`-Wall` 的警告是 C 工程师的「免费体检」：未使用变量、可疑的赋值、格式串不匹配，都能在编译期提前暴露。**工程习惯是把警告当错误看**——每消除一条警告，就少埋一个潜在的 bug。
