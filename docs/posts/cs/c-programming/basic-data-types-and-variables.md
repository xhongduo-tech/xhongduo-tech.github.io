## 为什么从数据类型开始

程序处理的本质，是**数据**——数字、字符、图像、模型参数。而在 C 语言里，每一个数据都必须先声明自己的「类型」：它占多大内存、按什么方式解释这些字节。<span class="marginnote">Python 里你随手写 `x = 3`，类型是解释器帮你定的；C 里类型是编译期就确定的静态属性，这也是 C 快而 Python 慢的根源之一——Python 运行时要去「猜」每个对象的类型。</span>学完这一节，你将理解整数、浮点数、字符在内存中的表示方式，也会第一次接触 C 语言的严格类型纪律——这正是它与动态语言最本质的分野。

## 1 基本数据类型全家福

C 语言提供四种**基本数据类型（basic data types）**，其余类型都由它们组合而来：

| 类型关键字 | 含义 | 典型长度 | 范围（示例） |
| --- | --- | --- | --- |
| `char` | 字符型 | 1 字节 | `-128` ~ `127` |
| `int` | 整型 | 4 字节 | 约 `-2.1e9` ~ `2.1e9` |
| `float` | 单精度浮点 | 4 字节 | 约 7 位有效数字 |
| `double` | 双精度浮点 | 8 字节 | 约 15 位有效数字 |

`int` 和 `float` 都可以用修饰符扩展：

**`short` / `long`**：缩短或加长整数。`long` 至少 4 字节，在 64 位系统上 `long` 是 8 字节，而 `long long` 保证至少 8 字节。<span class="marginnote">C 标准只规定「最短长度」，不规定精确长度：`int` 至少 2 字节、`long` 至少 4 字节。这意味着同一段代码在不同平台上行为可能不同——这是 C 可移植性的经典话题，到《内存模型、对齐与未定义行为》一节会深入。</span>
**`unsigned` / `signed`**：把整数解释为无符号或有符号。`unsigned int` 把所有位都用来表示非负数，范围从 `0` 到 `4294967295`。
**`double`** 的变体 `long double`：更高精度的浮点。

**char 是字节，不是「字符」**：在 C 里 `char` 就是一个能容纳 256 个值的小整数，字母、数字、标点都映射到它的编码值（通常是 ASCII）。'A' 在 ASCII 中等于整数 `65`，所以 `char` 与 `int` 可以互相转换——这在字符处理中极其常见。

## 2 变量：给内存位置起名字

**变量（variable）** 是「一个有名字、有类型、占一块内存」的对象。声明一个变量，就是告诉编译器：请给我一块足够大的内存，并让我用这个名字来引用它。

```c
int height;              /* 声明：分配 4 字节，但值未定义 */
int width = 100;         /* 声明并初始化：分配且赋初值 */
char first_letter = 'A';
double pi = 3.14159;
```

声明时**不给初值**的变量，其值是「未初始化的垃圾值」——内存里原本残留的位模式。<span class="marginnote">使用未初始化变量是 C 最常见的 bug 之一：程序看起来偶尔对、偶尔错。C 不像 Java，不会自动把整数初始化为 0。阅读《调试、断言与常见错误陷阱》一节时，这是头号嫌疑犯。</span>

**标识符（identifier）** 是变量、函数的名字，遵循三条规则：

1. 由字母、数字、下划线组成，**不能以数字开头**；
2. 不能与**关键字（keyword）** 冲突，如 `int`、`if`、`return`、`while`；
3. 区分大小写：`Height` 与 `height` 是两个不同的变量。

**常量（constant）** 是固定不变的值：`42` 是整型常量，`3.14` 是双精度常量，`'A'` 是字符常量，`"hi"` 是字符串字面量。用 `#define` 或 `const` 可以给常量起名：

```c
#define PI 3.14159     /* 预处理宏：编译前把 PI 替换成 3.14159 */
const int MAX = 100;   /* const 限定：运行期不可修改的变量 */
```

`#define` 与 `const` 有微妙差别：前者在预处理阶段做纯文本替换、不占类型；后者是真正的变量，只是被限定为只读。后面的《预处理》一节会详细辨析。

## 3 整数在内存里怎么存

一个 `int` 占 4 字节 = 32 位。**有符号整数**用**补码（two's complement）** 表示：最高位是符号位，其余位表示数值。补码的关键性质是：`-x` 等于 `~x + 1`（按位取反再加一）。

```
  十进制      二进制（32 位 int）
  0          0000 0000 0000 0000 0000 0000 0000 0000
  1          0000 0000 0000 0000 0000 0000 0000 0001
  2147483647 0111 1111 1111 1111 1111 1111 1111 1111
  -1         1111 1111 1111 1111 1111 1111 1111 1111
  -2147483648 1000 0000 0000 0000 0000 0000 0000 0000
```

几个直接推论：

- 最大的正数是 `0111...1`，即 $2^{31}-1$；最小的负数是 `1000...0`，即 $-2^{31}$。**正数比负数少一个**。
- **负数从 0 数下去会「绕回」**：`2147483647 + 1` 在 32 位里会变成 `-2147483648`，这叫**整数溢出（overflow）**，是无符号与有符号混合运算时最隐蔽的坑。
- `-1` 是全 `1`，这个性质让 `unsigned` 世界里 `-1` 等于 `4294967295`。

无符号整数则把 32 位全部当数值，范围 `0` ~ `4294967295`，且 `unsigned` 运算**永不溢出**——溢出就是模 $2^{32}$ 自动回绕，这在哈希、位运算里反而是有用特性。

## 4 浮点数：把小数塞进有限的位

浮点数用**科学计数法**的思路存储：$x = (-1)^s \times m \times 2^e$，其中 $s$ 是符号位，$m$ 是**尾数（mantissa）**，$e$ 是**指数（exponent）**。IEEE 754 标准把 `float` 的 32 位分成三段：

$$
\underbrace{1\ \text{位}}_{s} \quad \underbrace{8\ \text{位}}_{e} \quad \underbrace{23\ \text{位}}_{m}
$$

$$
\text{value} = (-1)^s \times (1.m)_2 \times 2^{e-127}
$$

对 `double`，则是 1 位符号 + 11 位指数 + 52 位尾数，指数偏移量是 `1023`。理解浮点，有三个必须接受的现实：

- **绝大多数小数无法精确表示**：像 `0.1` 这样的十进制小数，转成二进制是无限循环小数，只能近似存储。`0.1 + 0.2` 在计算机里并不精确等于 `0.3`。
- **有效数字有限**：`float` 约 7 位、`double` 约 15 位。`1e20 + 1` 对 `float` 来说等于 `1e20`，因为 `1` 落在精度之外。
- **比较浮点相等要小心**：判断两个浮点是否相等，通常不写 `a == b`，而是判断差值的绝对值小于某个很小的阈值，如 `fabs(a - b) < 1e-9`。

## 5 公式解析：整数的补码表示

补码是理解整数溢出与位运算的钥匙，值得单独拆解。核心式子是：

$$
-x \ \equiv\ \sim x + 1 \pmod{2^{32}}
$$

其中 `~x` 表示对 `x` 的 32 个位逐位取反。分三步理解：

- **第一步，为什么取反加一**：`x + (~x)` 每一位都是 `0` 与 `1` 相加，恰好得到全 `1`，即 `-1`（对 32 位补码而言 `-1` 就是全 1）。于是 `x + (~x + 1) = -1 + 1 = 0`，所以 `~x + 1` 正是 `0 - x` 的结果，也就是 `-x`。
- **第二步，符号位怎么工作**：最高位是 1 就表示负数。但补码的好处在于，**加减法不需要区分符号**：`5 + (-3)` 直接用二进制加法 `0101 + 1101 = 10010`，舍去溢出的最高位得 `0010 = 2`，结果正确。
- **第三步，溢出的边界**：加法结果超过 $2^{31}-1$ 或低于 $-2^{31}$ 时，会截断到 32 位。`2147483647 + 1` 得到 `-2147483648`，正是符号位被进位「翻脸」的结果——**有符号溢出在 C 里是未定义行为**，编译器可以做任何事，这是《内存模型、对齐与未定义行为》的重点内容。

## 6 核心对比表：有符号与无符号

| 属性 | `signed int` | `unsigned int` |
| --- | --- | --- |
| 取值范围 | $-2^{31}$ ~ $2^{31}-1$ | $0$ ~ $2^{32}-1$ |
| 表示方式 | 补码，最高位为符号位 | 纯二进制，全部位表示数值 |
| 溢出行为 | **未定义行为**（UB） | 定义良好：模 $2^{32}$
