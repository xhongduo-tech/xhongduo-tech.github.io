## 为什么从字符串讲起

程序处理的信息，最终大多要变成人类可读的**字符串**：用户名、文件路径、日志消息、网络报文。而 C 语言**没有独立的字符串类型**——字符串不过是「以空字符结尾的字符数组」。<span class="marginnote">C 的字符串约定是：用 `'\0'`（空字符，值为 0）标记结束。于是 `"hi"` 在内存里其实是 3 个字节：`'h' 'i' '\0'`。这个「约定」贯穿所有字符串函数——它们靠 `'\0'` 判断长度，而不是像 Python 那样记录一个长度字段。</span>这一节讲清字符串的表示、常见陷阱，以及 `string.h` 的整套函数库。

## 1 字符串：以 '\0' 结尾的字符数组

两种表示字符串的方式：

```c
char s1[] = "hi";          /* 字符数组：3 个字节 {'h','i','\0'} */
char *s2 = "hi";           /* 指针指向字符串字面量 */
```

两者有微妙但重要的差别：

**`char s1[] = "hi";`**：在栈上分配一个 3 字节数组，内容**可修改**：`s1[0] = 'H';` 合法。
**`char *s2 = "hi";`**：`s2` 指向**只读的字符串字面量**（通常在只读数据段）。修改 `s2[0]` 是**未定义行为**——多数平台直接段错误。

```c
char s1[] = "hi";
char *s2 = "hi";
s1[0] = 'H';      /* 合法：s1 是可变数组，变为 "Hi" */
/* s2[0] = 'H';  未定义行为：字符串字面量只读 */
```

**字符串字面量是 `const char*`**：`"hi"` 的类型是「指向只读字符的指针」。所以 `char *s2 = "hi";` 在严格模式（C++）下会报错，C 里它沿用旧式宽松规则，但**不要修改它**。

**字符串的长度**：`"hi"` 占 3 字节（含 `'\0'`），`strlen("hi")` 返回 `2`（不含 `'\0'`）。数组大小与 `strlen` 的差别是高频考点：`char s[100] = "hi";` 中 `strlen(s) == 2`，而 `sizeof(s) == 100`。

## 2 字符串的输入输出：scanf 与 fgets

`scanf("%s", buf)` 读取一个**不含空白**的词：

```c
char name[20];
scanf("%s", name);   /* 输入 "Alice Smith"，只读到 "Alice" */
```

`%s` 的问题：**不检查缓冲区大小**。输入超过 19 个字符时，`scanf` 会继续往 `name` 里写，**缓冲区溢出**——覆盖相邻内存，这是经典安全漏洞的根源。C Primer Plus 明确建议：**用 `fgets` 代替 `scanf("%s")`**：

```c
char line[100];
fgets(line, sizeof(line), stdin);   /* 最多读 sizeof(line)-1 个字符，安全 */
```

`fgets` 的三个参数：目标缓冲区、最大字符数、输入流（`stdin`）。它**保留换行符**：输入 `hi\n`，`line` 里是 `"hi\n"`，若想去掉换行：

```c
line[strcspn(line, "\n")] = '\0';   /* 把换行替换成 '\0' */
```

`strcspn(line, "\n")` 返回 `'\n'` 第一次出现的位置（没找到则返回长度），这是 C Primer Plus 推荐的惯用法。

## 3 string.h 核心函数

`string.h` 提供了整套字符串操作，全部以 `'\0'` 为长度依据：

| 函数 | 作用 | 注意 |
| --- | --- | --- |
| `strlen(s)` | 返回长度（不含 `'\0'`） | 结果类型 `size_t`（无符号） |
| `strcpy(dst, src)` | 把 `src` 复制到 `dst` | 不检查空间！ |
| `strncpy(dst, src, n)` | 复制最多 n 个字符 | 可能不补 `'\0'` |
| `strcat(dst, src)` | 把 `src` 追加到 `dst` 末尾 | 不检查空间！ |
| `strcmp(a, b)` | 比较两个字符串 | 返回 `<0`、`0`、`>0` |
| `strchr(s, c)` | 找字符 c 首次出现 | 返回指针或 `NULL` |
| `strstr(hay, needle)` | 找子串首次出现 | 返回指针或 `NULL` |

**`strcpy` 与 `strcat` 的危险性**：它们不检查目标缓冲区是否有足够空间。目标太小会溢出——安全替代是 `strncpy`/`strncat`，但 `strncpy` 有个坑：源字符串超过 n 时**不补 `'\0'`**，目标可能不是合法字符串。安全工程实践常直接手写或改用专用库。<span class="marginnote">`strcmp` 的返回值不是「布尔」，而是三态：负/零/正，对应 a`<b、a==b、a>`b。别写成 `if (strcmp(a,b))` 就认为「相等」——那是「不等」的意思。比较字典序时它按 ASCII 逐字符比。</span>

```c
char dst[10];
strcpy(dst, "hello");          /* 好：长度 5+1 <= 10 */
/* strcpy(dst, "hello world!");  溢出！需要 13 字节 */
```

## 4 字符串遍历与常用惯用法

**遍历字符串**：`for` 循环配合 `'\0'` 终止：

```c
void print_upper(const char *s)
{
    while (*s) {               /* *s 非 '\0' 就一直循环 */
        char c = *s;
        if (c >= 'a' && c <= 'z')
            c = c - 'a' + 'A';   /* 小写转大写 */
        putchar(c);
        s++;
    }
    putchar('\n');
}
```

`while (*s)` 是遍历字符串的经典写法——**以 `'\0'` 为哨兵（sentinel）**，不需要长度参数。`c - 'a' + 'A'` 利用 ASCII 码连续排列实现大小写转换。

**把字符串转换为数值**（`stdlib.h`）：`atoi("42")` 返回 `42`，`atof("3.14")` 返回 `3.14`。更安全的版本 `strtol`/`strtod` 能检测错误并报告结束位置。

**把数值转成字符串**：`sprintf(buf, "%d", n)`，但要小心缓冲区大小——用 `snprintf(buf, sizeof(buf), "%d", n)` 更安全。

## 5 公式解析：字符串的内存布局

字符串「字符数组 + `'\0'` 结尾」的内存布局，用 `strlen` 的视角来看：

$$
\text{strlen}(s) = \text{字符数}，\quad \text{存储空间} = \text{strlen}(s) + 1
$$

以 `char s[] = "hi";` 为例：

- **第一步，写出字节序列**：`s[0] = 'h'`（0x68），`s[1] = 'i'`（0x69），`s[2] = '\0'`（0x00）。
- **第二步，数有效字符**：从 `s[0]` 数到第一个 `'\0'` 之前，共 2 个——`strlen(s) = 2`。
- **第三步，算存储空间**：`'\0'` 本身也要占 1 字节，总空间 $2 + 1 = 3$
