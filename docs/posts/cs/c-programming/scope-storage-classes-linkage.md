## 为什么从作用域讲起

上一节我们看到函数内声明的变量默认是局部的：调用时出生、返回时消失。但这引出一连串问题：变量到底**活多久**（生命周期）、**能被谁看见**（作用域）、**多个文件之间如何共享名字**（链接）。<span class="marginnote">这三个问题分别由「存储类别说明符」（`auto`/`register`/`static`/`extern`）、「作用域规则」与「链接属性」回答。它们共同决定了一个名字在程序里的可见范围与存续时间——这是从「单文件小玩具」走向「多文件真实程序」的必经之路。</span>这一节把这些规则系统化，并澄清几个流传甚广的误解。

## 1 作用域：名字的可见范围

**作用域（scope）** 指一个名字在程序的哪些区域可以被引用。C 的作用域分几类：

**块作用域（block scope）**：在一对花括号内声明的变量，只在块内可见。函数体、`for` 循环体、`if` 块都是块。
**函数作用域**：仅 `goto` 标签拥有，整个函数内可见。
- **文件作用域（file scope）**：在所有函数之外声明的变量，从声明处到文件末尾都可见，也称**全局变量（global variable）**。
- **函数原型作用域**：原型声明里的参数名只在原型内有效。

```c
int global_var = 10;        /* 文件作用域：全文件可见 */

void f(void)
{
    int local = 1;          /* 块作用域：仅 f 内可见 */
    if (local > 0) {
        int inner = 2;      /* 更内层块：仅此块可见 */
        printf("%d %d\n", local, inner);
    }
    /* inner 在这里已不可见，local 仍可见 */
}
```

**内层块可以遮蔽（shadow）外层同名变量**：

```c
int x = 1;
void f(void)
{
    int x = 2;      /* 遮蔽文件作用域的 x */
    printf("%d\n", x);   /* 输出 2 */
}
```

遮蔽是合法的，但过度使用会让代码难以理解——编译器常给出 `-Wshadow` 警告。

## 2 存储类别：生命周期四兄弟

**存储类别（storage class）** 决定变量的生命周期（什么时候分配、什么时候销毁）与存放位置。四个关键字：

| 关键字 | 含义 | 典型位置 |
| --- | --- | --- |
| `auto` | 自动存储：块进入时分配、退出时销毁 | 栈 |
| `register` | 建议放入寄存器（现代编译器多忽略） | 寄存器/内存 |
| `static` | 静态存储：程序启动分配、结束才销毁 | 数据段 |
| `extern` | 声明「变量在其他地方定义」 | 引用外部定义 |

- **`auto` 是局部变量的默认类别**，几乎从不显式写出。它的生命周期被栈管理——上一节的调用栈就是它的舞台。
- **`register`** 只是「建议」把变量放在寄存器以加速访问，现代编译器会自动做寄存器分配，这个关键字更多是历史遗产。<span class="marginnote">C 还规定 `register` 变量不能取地址（`&x`），因为寄存器没有内存地址。现代优化编译器会自动把热点变量放寄存器，所以手写 `register` 基本无收益，反而限制了自己。</span>
**`static` 局部变量**：生命周期延长到整个程序，但**作用域仍是块级**——只有本函数能访问。它保留上一次调用的值，常用于计数器、缓存：

```c
void counter(void)
{
    static int n = 0;   /* 只初始化一次 */
    n++;
    printf("%d\n", n);
}
/* 连续调用三次：1、2、3，而不是每次都从 0 开始 */
```

**`extern`** 用于声明「这个变量在别的文件或本文件别处定义」，让当前文件可以引用它：

```c
/* file_a.c */
int shared = 42;        /* 定义 */

/* file_b.c */
extern int shared;      /* 声明：shared 定义在别处 */
void print_shared(void) { printf("%d\n", shared); }
```

## 3 文件作用域：static 与 extern 的两种角色

文件作用域的变量（全局变量）默认是**外部链接（external linkage）**：其他文件用 `extern` 可以访问。而加 `static` 的全局变量变成**内部链接（internal linkage）**：**仅限本文件可见**，其他文件即便写 `extern` 也访问不到。

```c
static int hidden = 1;    /* 内部链接：仅本文件可见 */
int visible = 2;          /* 外部链接：其他文件可 extern 访问 */
```

同理，**函数也有链接属性**：默认外部链接（跨文件可调用），`static` 函数是内部链接（仅本文件可用）。

```
static int helper(int x) { ... }   /* 本文件私有工具函数 */
int public_api(int x) { ... }      /* 对外暴露的接口 */
```

**工程惯例：全局变量与全局函数默认都应加 `static`**，除非确实需要跨文件共享。理由很简单：暴露得越少，意外冲突与误改的可能越小——这其实是「封装」在 C 里的雏形。<span class="marginnote">`static` 在函数内、在文件作用域、在局部变量三处含义不同：函数内 `static` 变量=延长生命周期；文件作用域 `static` 变量/函数=限制为本文件可见。一个关键字两种语义，是 C 里出了名的「一词多义」。</span>

## 4 常见误区辨析

**误区一：「`static` 变量整个程序都能访问」**。错。`static` 局部变量的**作用域仍是所在函数内**，只是生命周期变长了。「活多久」和「被谁看见」是两个独立维度，别混为一谈。

**误区二：「全局变量在声明时自动初始化」**。这条其实**正确**，但要加限定：文件作用域的变量（无论是否 `static`）会被**零初始化**——数值变量为 `0`、指针为 `NULL`。而**局部变量不会初始化**，是垃圾值。区别来自存储类别：静态存储自动清零，自动存储不负责。

```c
int g;                 /* 自动初始化为 0 */
static int h;          /* 自动初始化为 0 */
void f(void) {
    int i;             /* 垃圾值！必须手动初始化 */
    printf("%d\n", i); /* 未定义行为 */
}
```

**误区三：「`extern` 会创建一个变量」**。错。`extern` 只是**声明**，不分配内存；真正的定义只能有一个，否则链接阶段报「重定义」错误。

## 5 公式解析：`static` 与 `extern` 的对偶关系

用一张「生命周期 × 作用域」的坐标来总结：

$$
\text{local} \times \text{block scope} = \text{自动变量（auto）}
$$

$$
\text{local} \times \text{static} = \text{函数内静态变量}
$$

$$
\text{file} \times \text{static} = \text{本文件私有（内部链接）}
$$

$$
\text{file} \times \text{extern} = \text{跨文件共享（外部链接）}
$$
