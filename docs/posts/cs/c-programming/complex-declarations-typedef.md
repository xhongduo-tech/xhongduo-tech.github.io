## 为什么从复杂声明开始

学过指针、数组、函数之后，C 的声明会快速「长出牙齿」：`int (*fp)(int, int);` 到底指什么？`char *argv[]` 又是什么？K&R 第5章的经典主题——**复杂声明（complicated declarations）**——正是为解开这类谜题而生。它们不炫技：Unix 程序员的每个 `main` 签名、每个回调函数、每个命令行参数表，本质上都是复杂声明的实例。<span class="marginnote">你已经在《可变参数与函数指针》里见过 `qsort` 的比较函数，那里出现的就是函数指针。复杂声明把它推到极致：指针的指针、函数指针数组、返回指针的函数。</span>这一节教你**把声明读出来、写出来、用 `typedef` 驯服它们**。

## 1 声明的读法：从标识符开始，由内向外

C 的声明不是随意的符号堆砌，它有固定的**语法树**。读一条复杂声明，要遵循「**从标识符开始，由内向外，优先括号**」的规则。K&R 教给我们的读法是：

- 先看标识符（变量名），再看紧贴它的符号。
- `[]` 比 `*` 的绑定更紧，`()`（函数调用）同理。
- 遇到括号 `(...)` 先看括号内部，再向外扩展。

读 `int (*fp)(int, int)`：

- 标识符是 `fp`。
- `(*fp)`：括号让 `*` 先作用——`fp` 是一个**指针**。
- 后面 `(int, int)`：这个指针指向一个「接收两个 int、返回……」的函数。
- 最左边 `int`：返回值类型是 `int`。

于是读出：**`fp` 是指向函数的指针，该函数接收两个 `int`，返回 `int`**。一句话即可描述，但若没有方法，初学者会在三层符号里迷路。

## 2 复杂声明公式解析：三张类型卡

复杂声明看似无穷多，其实由三种「零件」拼成：`*`（指针）、`[]`（数组）、`()`（函数）。可以把任何声明当「公式」拆解——以 `char *argv[]` 为例：

$$
\text{argv} \xrightarrow{[]} \text{数组} \xrightarrow{*} \text{指针} \to \text{char}
$$

逐层解读：

- **第一层**：`argv` 紧贴 `[]`，优先绑定为「数组」。
- **第二层**：元素是 `char *`——指向 `char` 的指针。
- **合成**：`argv` 是「`char*` 的数组」。

这正是 K&R 第5章里 `main` 签名的来源——`char *argv[]` 是字符串指针数组，即「命令行参数表」。再看两个高频变体：

- `int *a[5]`：`a` 先绑定 `[]`，是**数组**，元素是 `int*`——「5 个指向 int 的指针」。
- `int (*a)[5]`：括号让 `*` 先绑定，`a` 是**指针**，指向「含 5 个 int 的数组」——「指向数组的指针」。

**两者一字之差，一个是数组、一个是指针。** 这就是为什么括号在复杂声明里重如泰山。<span class="marginnote">记忆口诀：「`*` 贴名是数组还是指针，看谁离标识符更近」。`[]` 比 `*` 更优先，除非括号强制改变优先级——这也是 K&R 反复强调的「声明模仿使用」原则。</span>

## 3 函数指针与函数指针数组

函数在 C 里没有名字以外的「值」，但它的**地址**可以存进指针。声明一个函数指针：

```c
int add(int a, int b) { return a + b; }
int (*fp)(int, int) = add;      /* fp 指向 add */
int result = fp(3, 4);          /* 调用，等价于 add(3,4) */
```

**函数指针让你把「函数」当「参数」传递**——这就是回调（callback）机制的基石，我们已在《回调函数与 qsort 应用》里尝过滋味。再进一步，把函数指针放进数组：

```c
int (*oper[])(int, int) = { add, sub, mul, div };
```

`oper` 是**函数指针数组**：`oper[0]` 是 `add`，`oper[1]` 是 `sub`…… 一个「根据下标选函数」的分派表（dispatch table）就此成型。状态机、命令解释器、表格驱动算法，全是这个模式。

## 4 typedef：给复杂类型一个名字

`typedef` 为已有类型引入**新名字（别名）**，它的语法与声明几乎一样，只是把「变量名」换成了「类型名」：

```c
typedef int (*operation)(int, int);   /* 类型名 operation */
operation op = add;                    /* 现在用起来像 int 一样自然 */
```

`typedef int (*operation)(int, int);` 与声明 `int (*fp)(int, int);` 结构完全相同——**`typedef` 是「把声明变成类型名」的语法糖**。一旦起名，那个吓人的 `int (*...)(int, int)` 就被装进 `operation` 这个名字里，函数指针数组的声明立刻变得清爽：

```c
operation oper[] = { add, sub, mul, div };
```

`typedef` 的另一大用途是**可移植类型**：`size_t`、`time_t` 都是标准库用 `typedef` 定义出来的，底层是 `unsigned long` 还是 `unsigned int`，随平台而定，程序其余部分不用改。这正是《计量学与 SI 单位制》里「抽象掉平台细节」思想的 C 版。

## 5 核心对比表：typedef 与 #define

`typedef` 常被误当成「高级 `#define`」，两者天差地别：

| 维度 | `typedef` | `#define` |
| --- | --- | --- |
| 处理时机 | 编译期，参与类型系统 | 预处理期，纯文本替换 |
| 作用对象 | 类型 | 任意文本 |
| 作用域 | 遵守块作用域 | 从定义处到文件尾 |
| 可读性 | 是类型，可声明新变量 | 只是文本，可破坏语法 |
| 例 | `typedef char *String;` | `#define String char*` |

一个经典反例：`#define String char*` 下写 `String a, b;`，展开成 `char* a, b;`——`b` 只是 `char`，不是 `char*`。而 `typedef char *String; String a, b;` 中 `a`、`b` 都是 `char*`。<span class="marginnote">这是「文本替换」与「类型系统」的本质差别：`#define` 不知道 C 语法，`typedef` 知道。凡是给类型起别名，一律用 `typedef` 而非 `#define`。</span>

## 6 读法实战：`char *argv[]` 的完整拆解

把第2节的「公式」用到真实的 `main` 签名上，检验你是否真的掌握了读法。K&R 的标准签名是：

```c
int main(int argc, char *argv[])
```

拆解 `char *argv[]`：

- 标识符是 `argv`，紧贴 `[]`——先读「数组」。
- 元素类型是 `char *`——「指向 `char` 的指针」，即字符串。
- 合成：`argv` 是**字符串指针数组**，数组里每个元素是一个 `char*`，指向一个命令行参数字符串。

再叠加一层：`argv` 作为函数参数时，数组会「退化为指针」，所以它等价于 `char **argv`——**指向「字符串指针」的指针**。<span class="marginnote">「数组参数退化」是 C 里一个著名的等价关系：形参里的 `char *argv[]` 与「指向字符指针的指针」等价。K&R 第5章用这个等价讲透了「数组与指针的亲密关系」，我们在《数组与指针的关系》中单独展开。</span>

于是 `argv` 就是一个「指向若干命令行字符串的指针的指针」，`argv[1]` 取第一个参数、`argv[0]` 是程序名。这条声明的每层括号都对应「指针—数组—字符串」中的一个维度——**读法练熟了，声明就不再是谜语，而是带层级的地图**。

## 7 小结

- 读复杂声明遵循「**从标识符开始，由内向外，优先括号**」；`[]` 和 `()` 的绑定优先于 `*`。
- `int *a[5]` 是数组的指针，`int (*a)[5]` 是指向数组的指针——一字之差、天壤之别。
- 函数指针把「函数」当数据传递，函数指针数组构成分派表，是回调与表格驱动的基础。
- `typedef` 给类型起别名，本质是「把声明变成类型名」，用于复杂类型与可移植类型。
- `typedef` 参与类型系统，`#define` 只是文本替换——给类型起名永远选 `typedef`。
