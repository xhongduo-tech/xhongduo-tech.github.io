## 为什么从递归讲起

函数能调用其他函数，自然也能**调用自己**——这种调用形态叫**递归（recursion）**。递归不是奇技淫巧，而是把「规模缩小、形式不变」的问题交给同一个函数去解的**通用策略**。<span class="marginnote">递归与数学归纳法互为镜像：归纳法靠「基础情形 + 归纳步」证明命题，递归靠「基本情况 + 递归步」计算问题。许多数据结构（树、链表）天然就是递归定义的，用递归处理它们几乎不需要额外的心智负担。</span>K&R 用递归实现快速排序、树遍历，把递归当作 C 的日常工具。这一节讲清递归的机制、写递归的三步法，以及它何时高效、何时该换成循环。

## 1 递归的两个部分

一个正确的递归函数，必须由两部分组成：

**基本情况（base case）**：不需要递归就能直接返回的情形，它终止递归。
**递归步（recursive step）**：把问题缩小到更小的规模，再用同一个函数求解。

看最经典的阶乘 $n!$：

```c
int factorial(int n)
{
    if (n <= 1)
        return 1;               /* 基本情况：0! = 1! = 1 */
    return n * factorial(n - 1); /* 递归步：n! = n * (n-1)! */
}
```

调用 `factorial(4)` 时，求值像一层层剥洋葱：

```
factorial(4)
= 4 * factorial(3)
= 4 * (3 * factorial(2))
= 4 * (3 * (2 * factorial(1)))
= 4 * (3 * (2 * 1))
= 24
```

**每一层递归都在「等待」下一层的返回值**。这些等待的现场就存在上一节的**调用栈**里：每次调用压入一层帧，最深时栈里堆了 4 层 `factorial` 的帧，然后逐层弹出。**递归的深度 = 调用栈的最大深度**——这是理解递归与栈溢出的关键。

## 2 三步法：把问题写成递归

写递归不靠灵感，靠套路。以「反转打印数组」为例：

**第一步，定义更小的问题**：把「打印 `a[0..n-1]` 的逆序」分解为「先打印 `a[1..n-1]` 的逆序，再打印 `a[0]`」。

```c
void print_reverse(int a[], int n)
{
    if (n <= 0)
        return;                  /* 基本情况：空数组无内容可打 */
    print_reverse(a + 1, n - 1); /* 递归步：先处理去掉首元素的后缀 */
    printf("%d ", a[0]);         /* 再打印首元素 */
}
```

**第二步，确认基本情况**：问题小到什么程度不用再递归？空数组（`n <= 0`）直接返回。

**第三步，相信递归（leap of faith）**：假设 `print_reverse(a+1, n-1)` 已经正确打印了后缀的逆序，那么整体逻辑自然成立。<span class="marginnote">「信任递归」是新手最难迈过的一步：不要试图在脑子里展开所有调用层，只验证「基本情形正确 + 递归步正确 + 规模确实在缩小」。三件事都对，函数就对——这就是数学归纳法在编程里的翻版。</span>

试跑 `print_reverse({1,2,3}, 3)`：递归层依次是 `[2,3]`、`[3]`、空，返回时依次打印 `3`、`2`、`1`。**「先递归、后处理」让打印顺序反转**——这是递归的精髓：后进先出，天然就是栈。

## 3 经典例子：汉诺塔与斐波那契

**汉诺塔（Tower of Hanoi）** 是递归最著名的代言：把 n 个盘子从 A 移到 C，一次只能动一个，大盘不能压小盘。

```c
void hanoi(int n, char from, char aux, char to)
{
    if (n == 0)
        return;
    hanoi(n - 1, from, to, aux);  /* 先把上面 n-1 个移到辅助柱 */
    printf("%c -> %c\n", from, to); /* 移动最底下一个 */
    hanoi(n - 1, aux, from, to);  /* 再把 n-1 个从辅助柱移到目标 */
}
```

3 个盘子输出 7 步、4 个盘子输出 15 步——移动次数是 $2^n - 1$。**汉诺塔漂亮地展示了递归的「规模分解」**：n 个盘子的问题被拆成两个 n-1 盘子的问题加一步移动。

**斐波那契（Fibonacci）** 则展示了递归的反面教材：

```c
int fib(int n)
{
    if (n <= 1)
        return n;
    return fib(n - 1) + fib(n - 2);   /* 慢！重复计算爆炸 */
}
```

`fib(40)` 要算约 3 亿次调用，因为 `fib(n-1)` 与 `fib(n-2)` 的子树**大量重叠**，同一子问题被反复求解。<span class="marginnote">`fib(n)` 的调用次数正是 $\text{Fib}(n)$ 量级——指数增长。这是「递归树」最直观的教训：重复子问题会让朴素递归不可用。解法是记忆化（memoization）或自底向上的迭代——这正是第三级《算法设计与分析》动态规划的入口。</span>换成迭代或记忆化后，`fib(40)` 瞬间完成。**递归的代价与收益要一起评估**：优雅不代表高效。

## 4 公式解析：汉诺塔移动次数

汉诺塔的总步数满足一个递归方程。设 $T(n)$ 为移动 n 个盘子所需步数：

$$
T(n) = 2T(n-1) + 1, \qquad T(1) = 1
$$

拆解这条递推式：

- **第一步，读懂递推**：移动 n 个盘子 = 「移走上面 n-1 个」（$T(n-1)$ 步）+「移动最底下一个」（1 步）+「把 n-1 个移回来」（$T(n-1)$ 步）。
- **第二步，展开前几项**：$T(1)=1$，$T(2)=2\times1+1=3$，$T(3)=2\times3+1=7$，$T(4)=15$——规律是 $T(n)=2^n-1$。
- **第三步，归纳验证**：若 $T(n-1)=2^{n-1}-1$，则 $T(n)=2(2^{n-1}-1)+1=2^n-1$。证毕。

$2^n$ 意味着什么？**每多一个盘子，步数翻倍**。64 个盘子的汉诺塔约需 $1.8\times10^{19}$ 步，哪怕每秒移动一次也要五千多亿年——这正是「指数爆炸」最直观的感受。递归把「指数问题」写得优雅，但优雅不等于可行。

## 5 递归 vs 迭代：何时用哪个

凡递归必可改写成迭代（用显式的栈），反之亦然。两者各有取舍：

| 维度 | 递归 | 迭代 |
| --- | --- | --- |
| 代码可读性 | 好，贴合数学定义 | 一般，需要手动管理栈 |
| 空间开销 | 每次调用压栈，深递归占大 | 常数或数组开销 |
| 栈溢出风险 | 深度过大时崩溃 | 无此风险 |
| 适用场景 | 树/链表遍历、分治、回溯 | 简单计数、线性遍历 |

判断依据：**问题本身是否递归定义**（树、链表、表达式求值）——是则递归更自然；**性能与深度是否关键**——是则优先迭代或「递归+记忆化」。K&R 的快速排序用递归，因为分治结构天然递归；而 `for` 循环数数，没人会写成递归。

**尾递归（tail recursion）** 值得一提：当递归调用是函数的**最后一步**（返回的就是递归调用的结果）时，某些编译器可优化为迭代，避免栈增长。上面的 `factorial` 不是尾递归（乘完才返回），改写成尾递归形式后，GCC 用 `-O2` 可将其消除——但这是优化层面的故事，初学不必纠结。

## 6 小结

- 递归 = 基本情况 + 递归步；「信任递归」要求两者都正确且规模在缩小。
- 递归的现场靠**调用栈**保存，递归深度就是栈深度，过深会栈溢出。
- 汉诺塔 $T(n)=2T(n-1)+1$ 得 $T(n)=2^n-1$
