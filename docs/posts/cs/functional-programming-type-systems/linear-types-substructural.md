## 为什么从线性类型开始

本专题最后一块拼图，要回答一个所有系统程序员都绕不开的问题：**内存谁来释放？** 手动 `free` 会悬垂指针，垃圾回收（GC）有停顿与开销，而过去十年的工业界给出了一台精妙的机器——Rust 的**所有权（ownership）与借用（borrow）**。它能在编译期消灭空悬引用、双重释放、数据竞争，却不需要 GC。这背后不是工程窍门，而是一条纯理论线索：**线性类型与子结构逻辑**。

值得注意的是：Rust 的设计者把理论挂在嘴边——其 2015 年 1.0 发布时的论文与演讲，反复引用线性逻辑与 Walker 的类型系统工作。**这是「从论文到生产」最成功的案例之一**，也是本专题「对标教材驱动」学习的绝佳示范：读懂了子结构逻辑，你就读懂了 Rust 的全部内存魔法。<span class="marginnote">子结构逻辑（substructural logic）的源头是吉拉德（Jean-Yves Girard）1987 年提出的<strong>线性逻辑（linear logic）</strong>——它让逻辑学家第一次认真对待「资源只能用一次」。类型系统的应用让「一次使用」从逻辑直觉变成了内存安全的工程现实。</span>

这一节在课程里的位置是收束性的：它把《效应系统》的「副作用可见」推进到「**资源可见**」——不只说你做了 I/O，还精确说你使用了哪些值、每个值用了几次。

放到「从极限到大模型」的主线看：大模型推理动辄几十 GB 显存，内存管理的效率直接决定部署成本；而「所有权」「借用」这类编译期资源调度，正是把「何时释放、谁可共享」从运行时偷懒（GC 停顿、OOM）搬回编译期的自觉。**类型系统越强，运行时越轻**——这条趋势在 Rust 身上达到极致。

## 1 子结构逻辑：当推理规则被削去

古典逻辑有一条「结构规则」：从前提 $A$ 可以推出 $A, A$（**收缩，contraction**，可以重复使用）——也可以干脆丢掉 $A$（**弱化，weakening**，可以不用）。这两条规则在「资源」视角下都是浪费：**现实世界里，一杯水喝掉就没有了，不能重复使用也不能凭空丢弃**。

把这两条规则从逻辑里删去（或部分删去），就得到一簇**子结构逻辑（substructural logic）**：

| 删除的规则 | 逻辑名称 | 资源约束 |
| --- | --- | --- |
| 收缩 + 弱化 | **线性逻辑** | 每个前提恰用一次 |
| 弱化（留收缩） | **相关逻辑** | 每个前提至少用一次 |
| 收缩（留弱化） | **仿射逻辑（affine）** | 每个前提至多用一次 |

「每个值至多用一次」的仿射逻辑，正是 Rust 的模型：**值用一次之后就被「消耗」，不许再用**。<span class="marginnote">Rust 实际采用的是「仿射 + 显式可变」：默认值可被移动（move）——移动后原绑定失效；要复制就显式 `Clone`。这就是「所有权转移」的逻辑学身份：一次使用 + 禁止重复。</span>

## 2 从逻辑到类型：线性类型

**线性类型（linear type）** 把「使用次数」写进类型规则。在普通类型系统里，变量可以反复使用；在线性类型系统里，**一个变量必须被使用且只能被使用一次**。于是「用一个值」变成了一种消耗性操作：

- 打开的文件是线性资源：用一次 `close` 就消耗掉，之后不可再用——**杜绝了重复关闭、也杜绝了忘记关闭**（忘记关闭意味着变量未用尽，类型检查报错）；
- 分配的内存是线性资源：`free` 消耗它——**杜绝了双重释放与悬垂指针**。

直觉：**线性类型把「资源生命周期」从运行时约定提升为编译期事实**。程序员再也不用「记得」释放——编译器逼你释放，且只放一次。<span class="marginnote">这个思想最早由 John Reynolds 1960 年代在语言设计里萌发（linearity 与别名），后在 Girard 线性逻辑中获得严格数学形式，再经 Walker、Ahmed 等人的语义工作变得成熟，最终在 Rust 里量产。</span>

「打开文件」的经典例子最直观：`open` 返回一个线性句柄，`close` 消耗它。若代码路径上忘了 `close`，类型检查器报「资源未用完」；若 `close` 两次，报「资源已消耗」。**在 C 里这是两个常见的运行时 bug；在线性类型里这是两个编译错误**——错误的性质没变，被发现的时间却提前了一个时代。

## 3 公式解析：一次使用如何在类型规则里强制

**「用一次」不是一个运行时标记，而是一条类型规则的语法效果。** 看线性逻辑的变量规则：

$$\frac{x : A \in \Gamma}{\Gamma \vdash x : A}\;(\text{var，恰好一次})$$

- **第一步，对照普通规则**：普通 λ 演算的 T-Var 允许变量在上下文里被任意使用；线性版本只允许「在 $\Gamma$ 中恰好出现一次」的变量被取用。
- **第二步，理解消耗**：当变量 $x$ 被用作实参传给一个消耗性函数（如 `free`），它在上下文 $\Gamma$ 里被**移除**——类型推导的每一步都在「用掉」资源。
- **第三步，看合成**：应用规则要求「函数用到的资源」与「实参用到的资源」**不重叠**——同一份资源不能同时喂给两个地方，这从结构上禁止了别名冲突。
- **第四步，直觉**：类型推导树本身就是「资源账本」，每一步都在做「借、还、销账」——**编译器通过检查推导树，就验证了每份资源恰好被消耗一次**。

一句话：**线性类型不是「检查你有没有 free」，而是把「每次使用」都登记进推导树，用完即销账**。

## 4 Rust：线性类型的大规模量产

Rust 把这套理论翻译成可用的工程语法。三个核心概念全都有逻辑学的影子：

- **所有权（ownership）**：每个值恰有一个 owner。赋给新变量 = **move**，原变量失效——正是「仿射 + 一次使用」；
- **借用（borrow）**：`&T` 共享借用（可多个、只读）、`&mut T` 独占借用（一个、可写）。**借用规则「不可同时存在可变借用与不可变借用」从字面上杜绝了数据竞争**；
- **生命周期（lifetime）**：`'a` 标注借用存活范围——保证借用不会比被借的值活得更久，杜绝悬垂引用。

经典错误信息最能说明「编译器在帮你做线性逻辑」：

```rust
let s = String::from("hi");
let t = s;          // s 被 move 给 t
println!("{}", s);  // 编译错误：borrow of moved value: `s`
```

编译器拒绝的正是「使用已消耗资源」。Rust 里没有 GC，安全代码也没有手动 free——**内存的分配与释放，由所有权系统在编译期排定**。<span class="marginnote">数据竞争（data race）在 Rust 里被类型系统直接消灭：共享可变状态在类型上就不可能同时被多线程访问——「不可变借用可并发，可变借用独占」。这比任何运行时锁都更早、更彻底。</span>

借用规则的「三定律」值得背下来，它们是借用检查器的全部依据：**① 任意时刻，一个值要么被一个可变借用引用，要么被任意多个不可变借用引用，不可并存；② 引用必须始终有效（不悬垂）；③ 借用存续期不超过所有者的生命周期。** 三条定律合起来，等于把「数据竞争」与「悬垂指针」在类型层面判了死刑。

把 Rust 的内存模型与另外两条路线摆在一起，三种哲学的高下立现：

| 方案 | 谁负责释放 | 空悬/双重释放 | 并发数据竞争 | 代表 |
| --- | --- | --- | --- | --- |
| 手动 | 程序员 | 常见 bug | 需锁 | C、C++ |
| GC | 运行时 | 几乎不可能 | 需锁 | Java、Go |
| 所有权 | 编译期 | 不可能 | 不可能 | Rust |

「在编译期就排除整类 bug」——这正是线性类型给工程界的最大承诺。

## 5 代价与权衡

线性类型不是没有成本。它的「每值一次使用」需要补充机制，Rust 的对应物是：

- **`Clone` / `Copy`**：显式复制让「多个所有者」合法化——代价是额外开销，程序员自己权衡；
- **`Rc` / `Arc`**：引用计数让「共享」合法化——这是「部分允许收缩」的运行时版本；
- **生命周期标注**：`'a`、`'static` 让借用系统的表达能力落地，但复杂的借用场景（自引用、迭代器嵌套）会逼程序员与借用检查器斗智。

「与借用检查器斗智」是 Rust 新手的必经之痛，但它其实有一个确定的出路：**借用检查器的规则是确定性的**——报错必有其理（某个值被 move、某个借用活得太久），看懂错误信息、用 `std::mem::take`、重构所有权边界，通常几轮迭代即可通过。这与「GC 语言里内存问题几乎不发生、发生时却无从下手」形成了有趣的对照：**编译期给你确定性，运行时给你神秘**。

**辨析｜易错点：**线性类型不等于「不许共享」。它精确地管理「共享的方式与次数」：要么显式复制、要么引用计数、要么借用——**共享没有消失，只是必须显式**。这与函数式「不可变 + 拷贝」哲学、与命令式「引用 + GC」哲学，构成对内存管理的三种完整答案。

## 6 小结

- **子结构逻辑**削去「收缩/弱化」规则，让逻辑第一次精确表达「资源用几次」。
- **线性类型**把「每值恰用一次」写进类型规则，推导树就是资源账本。
- **仿射逻辑**（至多用一次）正是 Rust 所有权的逻辑身份。
- 「忘记释放」与「释放两次」在线性类型里都是编译错误，而非运行时 bug。
- Rust 的**所有权 / 借用 / 生命周期**是线性类型的大规模工程化，编译期消灭空悬、双重释放与数据竞争。
- 代价：需要 `Clone`、`Rc/Arc`、生命周期标注等补丁机制，程序员付出显式性成本。
- 内存管理的三种完整答案：**函数式拷贝、命令式 GC、线性类型**——Rust 选了第三条路。
- 借用三定律（独占/共享互斥、引用有效、不超期）在编译期排除了数据竞争与悬垂指针。
- 「类型系统越强，运行时越轻」——大模型推理的显存管理同样受益于编译期资源调度。
- 借用检查器的规则确定而机械，报错必有其理，与 GC 的「运行时神秘」形成对照。
