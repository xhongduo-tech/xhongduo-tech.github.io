## 为什么从依赖类型开始

本专题一路走来，类型系统一直在「变强」：简单类型保证形状，多态保证复用，效应系统保证隔离。但所有这些都还守着一条底线——**类型由类型表达式构成，与「值」无关**。这一节要打破这条底线：**让类型可以依赖值**。类型 `Vec Int 3`（长度为 3 的整数向量）第一次把「长度」这个**数据**写进了「类型」本身。这就是**依赖类型（dependent types）**。<span class="marginnote">依赖类型的源头可以追溯到 Per Martin-Löf 1970 年代构造性类型论（Martin-Löf Type Theory）；而它今天最响亮的应用是 Agda、Idris、Lean、Coq——一门门「证明即编程」的证明助手语言。Harper 的 PFPL 第12–13章专门讲「类型与命题」（Curry-Howard）这一基础。</span>

这一节是《代数数据类型》里那句伏笔的兑现：积与和对应逻辑的且与或。一旦类型可以依赖值，整座「类型-逻辑」的桥梁就被彻底打通——**类型即命题，程序即证明**。这正是希尔伯特那句「我们必须知道」在计算世界的实现：让机器替我们验证「我们知道」。

历史谱系同样值得记住：1967 年 de Bruijn 的 AUTOMATH 率先用「命题=类型」做数学机器验证；1970 年代 Per Martin-Löf 的构造性类型论给出依赖类型的完整基础；1980 年代 Coq（法国）与 2000 年代的 Agda（瑞典）、Idris（英国）把它变成可用工具。**依赖类型从哲学直觉到实用工具，走了整整半个世纪**。

## 1 类型即命题：Curry-Howard 对应

**Curry-Howard 对应（Curry–Howard correspondence）**是类型理论里最著名的定理（实则是一个观察）：逻辑命题与类型一一对应，逻辑证明与程序一一对应。

| 逻辑 | 类型 |
| --- | --- |
| 命题 $P \to Q$（蕴含） | 函数类型 $P \to Q$ |
| 合取 $P \land Q$ | 积类型 $P \times Q$ |
| 析取 $P \lor Q$ | 和类型 $P + Q$ |
| 真 $\top$ | 单元类型（1 个元素） |
| 假 $\bot$ | 空类型（0 个元素） |

这条对应在 1930 年代的 Haskell Curry 与 1960 年代的 William Alvin Howard 手里逐渐成型，Philip Wadler 2015 年写下了权威综述《Propositions as Types》。它的意义是双向的：**逻辑学家从类型里学到计算的直觉，类型学家从逻辑里学到证明的结构**。<span class="marginnote">「命题 = 类型」不是比喻，而是精确的同构：`x : A` 读作「x 是 A 类型的程序」，也可以读作「x 是命题 A 的证明」。一段可执行代码，就是一个经过机器验证的证明——这就是证明助手的全部秘密。</span>

更重要的是，「证明 = 程序」给了数学一个全新的纪律：**证明变成可执行、可复用、可测试的对象**。一个「通过类型检查」的证明，不再依赖裁判（人）的审视，而是依赖机械规则（类型检查器）——希尔伯特当年追求的「绝对可靠」，在计算机里有了一个务实的版本：绝对可验证。这正是本节要反复强调的内核。

## 2 依赖类型：让类型提及值

普通类型系统里，「值」与「类型」是两个不相交的世界；依赖类型把它们缝起来。两个核心构造：

**依赖函数类型（dependent function type）** $\Pi(x : A).\; B(x)$：接受一个类型为 $A$ 的值 $x$，返回类型为 $B(x)$ 的值——**返回值类型依赖于输入值**。读作「对所有 $x : A$，$B(x)$」。当 $B$ 不依赖 $x$ 时，退化为普通函数类型 $A \to B$。

**依赖对类型（dependent pair type）** $\Sigma(x : A).\; B(x)$：一对「第一个分量 $x : A$，第二个分量类型依赖 $x$」——读作「存在 $x : A$ 使得 $B(x)$」。当 $B$ 不依赖 $x$ 时，退化为积类型 $A \times B$。<span class="marginnote">注意 $\Pi$ 与 $\forall$、$\Sigma$ 与 $\exists$ 的亲缘关系：在「类型即命题」的字典里，$\Pi$ 是「对所有」，$\Sigma$ 是「存在」。量词——一阶逻辑的招牌——第一次被完整地请进了类型系统。</span>

依赖类型让「类型携带证据」成为可能。经典例子：`Vec`（定长向量）与 `Fin`（有界自然数）：

```
Vec : Nat -> Type -> Type          -- 长度为 n 的 a 列表
Fin n = 0, 1, ..., n-1             -- 恰好 n 个元素的类型
```

`head : (n : Nat) -> Vec (n+1) a -> a` 把「非空」写进了签名：这个函数**不可能**对空向量调用——不是运行时检查，是编译期就不可能构造出「空向量」作为实参。<span class="marginnote">这正是依赖类型的革命性：大量「运行时才能发现」的错误——越界、除零、未处理分支——被翻译成「类型层面无法构造」的表达式。程序在编译期就删除了整类 bug。</span>

$\Sigma$ 依赖对同样实战价值巨大。想表示「存在一个数 $x$，使得 $x$ 是 100 的因子」，可以写成 $\Sigma(x : \mathrm{Nat}).\; \mathrm{Divides}\; x\; 100$——这个类型的元素是「一个具体的因子」加「它是因子的证明」。在依赖类型世界里，**「存在」不是一句断言，而是一个可以取出证人的数据结构**。<span class="marginnote">这也解释了为什么依赖类型与「程序抽取」（extraction）亲缘极深：从存在证明里抽出计算部分，就是可运行的程序；Coq 的 Extract 命令正做此事。</span>

## 3 公式解析：加法的结合律可以「证明」

**在依赖类型语言里，数学定理就是程序，证明就是让程序通过类型检查。** 以自然数加法的结合律为例，用 Agda 风格写：

$$\forall m\; n\; p : \mathrm{Nat}.\quad (m + n) + p = m + (n + p)$$

- **第一步，把命题变成类型**：结合律本身是一个类型——它的「元素」是「使等式成立的证明」。
- **第二步，归纳定义自然数**：$\mathrm{Nat} = \mathrm{zero} \mid \mathrm{suc}\; n$。加法 $0 + n = n$、$(m+1) + n = (m+n)+1$ 由结构递归定义。
- **第三步，对 m 归纳**：当 $m = 0$，两边都等于 $n + p$，证明是平凡的；当 $m = \mathrm{suc}\; m'$，用归纳假设把左边的 $m'+n$ 替换掉，等式两端同步化简。
- **第四步，机器验证**：这段「归纳证明」写成 Agda 程序，**类型检查器逐条核对每一步等式**——通过检查即证明完成。人写证明结构，机器验证每一步。

这个「归纳三步走」的套路（base case + inductive step + rewrite by IH）在证明助手里是**唯一不可省略的核心技能**——其余都是库与战术的锦上添花。它训练的是「把一个命题拆成可机械验证的小步」的思维方式，而这恰好也是写出健壮程序的思维方式：**分而治之，每步让机器兜底**。

于是希尔伯特的「我们必须知道」落到最实处：**不必再相信任何人的口头断言，证明可以被编译**。

## 4 依赖类型的代价：三座大山

依赖类型如此强大，为何主流语言不用？代价有三：

- **类型推断不可判定**：依赖类型里判断「两个类型是否相等」需要归约类型中的程序——而程序归约可以不停（停机问题）。Agda/Idris 靠「规范化」与交互式战术逼近，用户要写大量类型。
- **终止性检查**：类型里跑程序必须保证终止（否则类型检查不终止）。Agda 要求递归在**结构上递减**，写不动点、写非结构递归都要绕路——通用递归在依赖类型语言里被排除在外。
- **宇宙（universe）**：`Type : Type` 会导致 Girard 悖论，于是必须分层：`Type₀ : Type₁ : Type₂ : ...`，每个类型都有自己的「宇宙层级」，写起来多一维心智负担。<span class="marginnote">这三座大山解释了一个有趣的现象：依赖类型语言是小众的证明助手，不是大众编程语言；但 Idris、F* 等正在把「依赖类型的一小片」用于真实工程（如加密协议验证）。详见《现代语言实践》。</span>

第三座山（宇宙分层）尤其值得体会：它证明「把所有类型塞进一个类型」必然自相矛盾——**这套「不许自我指涉到崩塌」的规约，与《悖论》专题里罗素悖论、集合论公理化的逻辑完全同构**。类型系统的每一次「限制」，背后都有一个逻辑学理由。

**辨析｜易错点：**「依赖类型」不等于「泛型」。Rust 的 `Vec<T>` 中 `T` 是类型参数，但「长度 3」不是参数——`Vec<i32>` 仍是「任意长度」。真正的依赖类型如 `Vec i32 3` 连**长度**都进了类型，这是量变到质变的跳跃。

## 5 依赖类型的现代渗透

虽然「全依赖类型」未进主流，它的思想正在各处以「轻量」形态渗透：

- **长度索引列表**：Rust 的 `heapless`、类型级数（typenum）模拟 `Vec i32 3`；Haskell 的 `Data.Vector.Sized` 用类型标记长度；
- **协议验证**：Idris 的 `Type-driven development` 范式让网络协议、状态机的合法状态转换成为类型；F* 用依赖类型验证加密协议（HACL*，CryptoVerif 同门）达到商用级安全；
- **编译期检查**：TypeScript 的字面量类型与模板字符串类型，是「类型依赖值」在动态语言上的极轻量回声；
- **数学机械化**：Lean（被微软/数学界用于形式化现代数学）与 Coq（`CompCert` 编译器、`Coq` 版四色定理）是依赖类型的旗舰应用。

用一张表概括「依赖类型的渗透谱系」：

| 程度 | 代表 | 类型能说 |
| --- | --- | --- |
| 全依赖 | Agda、Idris、Lean、Coq | 任意命题、定理证明 |
| 半依赖 | F*、Dafny | 指针安全、协议性质 |
| 轻量 | Rust `typenum`、Haskell 类型级 | 长度、常量约束 |
| 近似 | TypeScript 字面量 | 固定取值集合 |

依赖类型是「类型系统能表达多少」的极限参照系——**理解它，就理解了现代语言每一项「类型增强」努力的方向**。

## 6 小结

- **Curry-Howard 对应**：命题=类型、证明=程序、化简=证明归一——类型与逻辑的精确同构。
- **依赖函数类型** $\Pi(x:A).B(x)$ 与**依赖对** $\Sigma(x:A).B(x)$ 让「类型依赖值」。
- 「存在」在依赖类型里是**可取出证人的数据结构**，不是一句空泛断言。
- 定长向量 `Vec`、有界自然数 `Fin` 让「非空」「不越界」成为编译期事实。
- 数学定理在 Agda/Idris 里就是程序，**类型检查通过 = 证明完成**。
- 三大代价：**推断不可判定、终止性检查、宇宙分层**——这是依赖类型未进主流的原因。
- 希尔伯特的「我们必须知道」，在证明助手里成为「机器替你验证」。
- 全依赖（Agda/Coq）到轻量（typenum、字面量类型）是依赖类型的完整渗透谱系。
