## 为什么从 λ 演算开始

1936 年，阿隆佐 · 丘奇（Alonzo Church）在普林斯顿写下一个只有三条语法规则的记号，本意是为「可计算函数」给出一个精确定义。九十年后，这个记号成了 Haskell、OCaml、Scala、JavaScript 闭包、Python 列表推导的共同祖先——它就是 **λ 演算（lambda calculus）**。在「从极限到大模型」这条主线上，λ 演算扮演的角色类似于微积分里的「极限」：它是全部函数式编程与类型理论的**出发点与最小公分母**。<span class="marginnote">丘奇与图灵在同一时期各自给出了「可计算」的等价定义，后称<strong>丘奇—图灵论题</strong>。图灵机是「带状态的计算」，λ 演算是「无状态的替换计算」，二者等价——详见第三级《计算理论》专题的图灵机章节。</span>

理解 λ 演算的价值不止于历史。函数式编程的每一项「先进特性」——不可变数据、高阶函数、递归、惰性求值——都能被翻译成 λ 演算里寥寥数行。换句话说，**学透 λ 演算，就等于拿到了读懂所有函数式语言的最小词汇表**。

从课程结构看，这是本专题的第一篇：后面所有主题（简单类型、System F、类型推断、单子、依赖类型）都是在这三条语法规则之上逐层加「约束」或加「结构」。先从**不带类型**的 λ 演算入手，正像微积分先讲极限、再讲微分——先把纯粹的计算讲清楚，再谈用什么纪律去约束它。

## 1 语法：只有三条规则

λ 演算的项（term）由三句话定义，一个比一个微妙：

- **变量**：$x$ 是一个项，比如 $x, y, z$；
- **抽象（abstraction）**：若 $x$ 是变量、$t$ 是项，则 $\lambda x. t$ 是一个项——读作「把 $t$ 里出现的 $x$ 绑定为参数」；
- **应用（application）**：若 $t_1, t_2$ 是项，则 $t_1\; t_2$ 是一个项——读作「把 $t_2$ 作为实参传给函数 $t_1$」。

仅此而已。没有算术、没有布尔、没有 `if`、没有循环。**应用是左结合的**：$t_1\; t_2\; t_3$ 意为 $(t_1\; t_2)\; t_3$；**抽象体向右尽量延伸**：$\lambda x. \lambda y. x$ 意为 $\lambda x. (\lambda y. x)$。

「绑定」与「出现」需要说得精确。在 $\lambda x. t$ 中，$t$ 内自由出现的 $x$ 被绑定（bound），其余变量仍保持自由（free）。<span class="marginnote">这与程序语言的<strong>作用域</strong>一一对应：$\lambda x$ 是声明，$t$ 内对 $x$ 的引用是引用。把「绑定变量」与「自由变量」区分开，是后续一切类型规则的前提。</span>两个只差变量名字、其余结构相同的项被视为同一项——比如 $\lambda x. x$ 与 $\lambda y. y$ 表示同一个函数——这种等价关系叫 **α-等价（alpha-equivalence）**。

举一个混合自由与绑定变量的例子：项 $\lambda x. \lambda y. x$ 中，$x$ 与 $y$ 都被各自最近的 λ 绑定，整体读作「接受 $x$，返回一个接受 $y$ 并忽略 $y$、恒返回 $x$ 的函数」——它就是投影函数 $\lambda x.\lambda y. x$，在丘奇编码里对应布尔值 $\mathrm{true}$。而 $\lambda x. y$ 中的 $y$ 是**自由**的：这个函数体依赖外界的 $y$，离开上下文无法独立求值。<span class="marginnote">这个区分在类型推导里至关重要——类型上下文（context）$\Gamma$ 记录的就是「哪些自由变量各是什么类型」，下一节与《Hindley-Milner 类型推断》都会反复用到 $\Gamma \vdash t : T$ 这个记号。</span>

## 2 丘奇编码：用函数表示一切

λ 演算里没有数字，但这难不倒丘奇。他把自然数 $n$ 编码为一个「接受两个参数 $f$ 和 $x$，把 $f$ 作用到 $x$ 上 $n$ 次」的函数，即 **丘奇数（Church numeral）**：

$$\overline{0} = \lambda f.\lambda x. x, \qquad \overline{n} = \lambda f.\lambda x. f(f(\cdots f(x)\cdots))$$

于是「数」就是**迭代**的抽象化身。后继函数、加法、乘法都只是对这个结构做组合：

$$\mathrm{SUCC} = \lambda n.\lambda f.\lambda x. f(n\; f\; x), \qquad \mathrm{ADD} = \lambda m.\lambda n.\lambda f.\lambda x. m\; f\;(n\; f\; x)$$

乘法更说明「组合」的威力：$\mathrm{MULT} = \lambda m.\lambda n.\lambda f. m\,(n\, f)$——把「应用 $n$ 次」重复 $m$ 次，得到的恰好是「应用 $mn$ 次」。减法（前驱 PRED）要借助有序对，编码稍复杂，但其存在本身就印证了一个事实：**只要图灵完备，任何可计算的东西都能硬挤进这三条语法**。

布尔值同样可以编码：$\mathrm{true} = \lambda x.\lambda y. x$（返回第一个参数），$\mathrm{false} = \lambda x.\lambda y. y$（返回第二个参数）。于是 `if-then-else` 不过是一次普通应用：`IF b then A else B` 即 $b\; A\; B$。<span class="marginnote">注意真值、自然数、选择结构全都归结为「函数」一种东西——这就是<strong>一切皆函数</strong>（everything is a function）的思想，也是后来闭包、一等函数的历史源头。</span>

有序对也可以编码：$\mathrm{PAIR} = \lambda x.\lambda y.\lambda b. b\; x\; y$，第一个分量是 $p\;\mathrm{true}$，第二个分量是 $p\;\mathrm{false}$。之所以这样编码，是因为在纯函数世界里没有「字段」，只有「选择」——**用什么来取，就定义了什么**。

把几种编码对照起来看，能一眼看出「数据 = 函数」的统一结构：

| 编码 | 定义 | 取用时 |
| --- | --- | --- |
| $\overline{n}$（丘奇数） | $\lambda f.\lambda x. f^n(x)$ | 应用 $n$ 次 $f$ |
| $\mathrm{true}$ | $\lambda x.\lambda y. x$ | 取第一个分支 |
| $\mathrm{false}$ | $\lambda x.\lambda y. y$ | 取第二个分支 |
| $\mathrm{PAIR}\;a\;b$ | $\lambda b. b\;a\;b$ | 传入选择子 `true`/`false` |

这张表里最耐人寻味的是：**同一个函数 $\lambda x.\lambda y. x$，既可以当布尔值 true，也可以当投影函数**。编码本无定论，一切取决于你约定如何用它。

## 3 归约策略：计算就是重写

若项 $( \lambda x. t_{12})\; t_2$ 是「把函数作用于实参」，它的计算结果就是把 $t_{12}$ 里自由出现的 $x$ 全部替换为 $t_2$，写作 $t_{12}[x \mapsto t_2]$。这一步替换叫 **β-归约（beta-reduction）**，形如 $\lambda x. t_{12}$ 的项叫 **β-可归约式（redex）**。

替换必须**避免变量捕获（capture-avoiding）**：若 $t_2$ 里含自由变量 $y$，而 $t_{12}$ 里有形如 $\lambda y. \cdots$ 的子项，直接替换会错误地把 $t_2$ 中的 $y$ 绑定起来。解决办法是先做 α-重命名，把冲突的内部 $\lambda y$ 改成新名字。这一细节在实现时极易出错，Pierce 第6章专门引入「有名表示」来绕开它。

来看一条完整的归约链。设 $\mathrm{id} = \lambda x. x$，则：

```
(λx. x) (λy. y) (λz. z)
  →  (λy. y) (λz. z)      （最左 redex：把 (λx.x) 应用到 (λy.y)）
  →  λz. z                （再把 (λy.y) 应用到 (λz.z)）
```

三步之内，一个看似复杂的项就归约到恒等函数——**计算没有副作用，只有重写**。注意这里最左归约先处理的是「把函数作用到实参」这一步，符合正则序的约定；若先归约内层实参则会走另一条路，但合流性保证殊途同归。

一个项里通常有多个 redex，先归约哪一个，就产生不同的**归约策略（reduction strategy）**：

- **正则序（normal order）**：总是先归约最左、最外层 redex——它保证在存在不可归约形式（范式，normal form）时一定找到它；
- **应用序（applicative order）**：先归约实参——这是大多数命令式语言的求值顺序，但在某些项上会陷入死循环。例如正则序下 $(\lambda x. y)\;\Omega$（其中 $\Omega = (\lambda x. x\,x)(\lambda x. x\,x)$）立刻得到 $y$，而应用序会先去归约 $\Omega$，永不停止。<span class="marginnote">Haskell 采用的正则序（配合按需共享）就是「惰性求值」，详见本专题《惰性求值》一篇。</span>

**辨析｜易错点：**「应用序先算实参」与命令式语言「先算子表达式再调用」的直觉一致，所以很多初学者默认它正确。但正是这个「先算完再用」的习惯，让那些根本用不到实参的程序（如 `if` 的未被选中分支）也付出计算代价——惰性求值革新的正是这一点。

## 4 公式解析：不动点组合子 Y

**没有循环语句，递归怎么写？** 这是 λ 演算必须回答的问题，答案是一个优雅得惊人的构造。

定义 **不动点组合子（fixed-point combinator）**：

$$Y = \lambda f. (\lambda x. f\,(x\,x))\;(\lambda x. f\,(x\,x))$$

逐步拆解它如何实现递归：

- **第一步，理解目标**：对任意函数 $f$，我们希望 $Y f$ 满足 $Y f = f\,(Y f)$——即 $Y f$ 是 $f$ 的**不动点**，而 $f\,(Y f)$ 正是「先展开一步再继续」的递归形态。
- **第二步，看内层**：$(\lambda x. f\,(x\,x))$ 接受 $x$，返回 $f\,(x\,x)$；把它作用到自身 $(\lambda x. f\,(x\,x))$ 上，得到 $f\,((\lambda x. f\,(x\,x))\,(\lambda x. f\,(x\,x)))$。
- **第三步，对等**：注意到括号内 $(\lambda x. f\,(x\,x))\,(\lambda x. f\,(x\,x))$ 恰等于 $Y f$，于是上式正是 $f\,(Y f)$。递归完成。
- **第四步，应用**：定义阶乘 $F = Y\,(\lambda f. \lambda n. \text{if } n = 0 \text{ then } 1 \text{ else } n \times f\,(n-1))$，每次调用都把 $f$ 替换成「再展开一步的自己」，从而在只含三条语法规则的语言里实现了任意递归。

不动点组合子表明：**递归不是原语，而是可以从 λ 演算推导出来的现象**。这也是类型系统研究里「递归类型」一章（TAPL 第20章）的伏笔。

## 5 范式与停机问题

如果一个项无法再归约，就称它处于 **范式（normal form）**。但并非每个项都能到达范式：$(\lambda x. x\;x)\;(\lambda x. x\;x)$ 每次归约都回到自身，陷入无限循环。事实上，**λ 演算与图灵机计算能力完全等价（丘奇—图灵论题）**，因此停机问题不可判定直接推出：不存在能判断任意项是否归约到范式的算法。<span class="marginnote">这个「不可判定」的结论带来一个重要的实用推论：任何全功能的类型系统都必须在「接受所有好程序」与「拒绝所有坏程序」之间取舍——这正是下一节《简单类型 λ 演算》的动机：给项加类型，用类型禁止掉那些会跑偏的项。</span>

范式不唯一的可能来自**η-等价**：$\lambda x. f\,x$ 与 $f$（当 $x$ 不在 $f$ 中自由出现）直觉上相同，这条规则（η-归约）并入后，归约系统仍具有合流性（confluence）。合流性保证：**若一个项能到达范式，则范式在 α-等价意义下唯一**。

这条「无类型语言既能表达一切、又会跑偏」的两面性，在今天有直接的现实投影。现代编程语言大多在「图灵完备」与「可判定检查」之间做取舍：Python 灵活但运行时才报错，Rust 严谨但要求程序员遵守借用规则。<span class="marginnote">同理，大模型时代的「推理不可判定」与「结果可验证」之争，也与这里「表达式力 vs 约束力」的古老张力同构。</span>类型系统，正是人类发明的、至今最成功的「用有限约束换取无限安全」的工程工具。

## 6 小结

- λ 演算只有**变量、抽象、应用**三条语法规则，却是图灵完备的通用计算模型。
- **丘奇编码**用函数表示自然数与布尔值，证明数据可以从计算中「长出来」。
- **β-归约**是唯一的计算步骤；替换必须**避免捕获**，靠 α-重命名兜底。
- 归约策略有**正则序**与**应用序**之分；正则序保证能找到范式，也是惰性求值的雏形。
- **不动点组合子 Y** 让递归成为推导物而非原语。
- 由于停机问题不可判定，**没有任何类型系统能同时接受所有好程序**——这是类型系统这门学问的第一推动力。

在下一节，我们将往 λ 演算里引入**类型**，用一套归纳定义的规则把「进展」（progress）与「保持」（preservation）两个性质钉死在语言里——这就是**简单类型 λ 演算**。
