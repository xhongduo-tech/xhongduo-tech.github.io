## 为什么从高阶抽象开始

前面五篇建立了一套「类型如何描述数据与函数」的体系。但真实程序还有另一类反复出现的结构：**「可能会失败」的计算、「可能为空」的计算、「带状态的」计算**。命令式语言用异常、`null`、全局变量分别应付；函数式语言则把它们都做成**类型**——`Maybe`、`Either`、`IO`——于是问题来了：**这些「装了东西的盒子」该如何统一地被操作？** 答案就是**函子、应用函子与单子**：一条从「对值操作」上升到「对结构操作」的抽象阶梯。<span class="marginnote">单子是 Haskell 社区的「入门分水岭」——有人称之为「单子墙」（monad tutorial 泛滥成灾）。但我们不从 `bind` 的语法切入，而从「结构保持的操作」这个更稳的直觉切入，你会发现单子不过是「结构操作」的最后一层。</span>

这一节也是本专题与范畴论（category theory）的第一次握手。**范畴论是「数学的数学」**：它把「对象 + 映射」这一最小骨架抽象出来，而函子、单子正是这个骨架在编程里的投射。

## 1 函子：结构保持的映射

**函子（functor）**是「能对内部值应用函数，同时保留外层结构」的容器。Haskell 里它是类型类：

```haskell
class Functor f where
    fmap :: (a -> b) -> f a -> f b
```

`fmap` 把一个「`a→b` 的函数」提升为「`f a→f b` 的函数」。`Maybe` 是函子：`fmap (+1) (Just 3) = Just 4`，`fmap (+1) Nothing = Nothing`——**结构（`Just`/`Nothing`）原封不动，只有内部值被改变**。<span class="marginnote">`List` 也是函子：`fmap` 就是 `map`；`Either e`、`IO`、`Tree` 都是函子。可以说「函子」是对「容器」这个朴素概念的公理化。</span>

函子必须满足两条**律（law）**：

$$fmap\; id = id, \qquad fmap\;(g \circ h) = fmap\; g \circ fmap\; h$$

第一条说「应用恒等函数不改结构」，第二条说「先组合函数再应用，等于分别应用再组合」。这两条律保证 `fmap` **不偷偷做任何事**——它是「结构保持」的映射，这正是「函子」与「随便一个遍历函数」的区别。

## 2 应用函子：把函数也装进盒子

函子能对「盒内的值」应用函数，但如果**函数本身也在盒子里**呢？**应用函子（applicative functor）**补上这一层：

```haskell
class Functor f => Applicative f where
    pure  :: a -> f a
    (<*>) :: f (a -> b) -> f a -> f b
```

`pure` 把一个普通值**抬升**进容器；`<*>`（读作「apply」）把「容器里的函数」应用到「容器里的值」。它们的组合让「多参数函数的柯里化调用」可以在容器内进行：`pure add <*> Just 1 <*> Just 2 = Just 3`。<span class="marginnote">`(<*>)` 与一元 `<*`、`*>` 让 Haskell 能优雅地写「并行但独立的效应」；而单子里的 `>>=` 处理的是「有依赖的效应」——依赖关系正是 applicative 与 monad 的分界。</span>关键在于 applicative 的运算**彼此独立**：`pure f <*> a <*> b` 里 `a`、`b` 的计算互不依赖，可以并行求值。

## 3 单子：让计算「串」起来

**单子（monad）**在 applicative 之上再迈一步：允许**后面的计算依赖前面的结果**。核心操作有两个：

```haskell
return :: a -> m a        -- 等价于 pure，抬升
(>>=)  :: m a -> (a -> m b) -> m b   -- bind：把前一个结果喂给下一个
```

`>>=` 读作「bind」——「把 `m a` 里的 `a` 取出来，交给 `a→m b`，得到 `m b`」。正是这一个操作让计算**串联**起来：每一步的输出成为下一步的输入，这就是 `IO`、`State`、`Maybe` 里「顺序执行」的抽象。<span class="marginnote">`Maybe` 作为单子时，`>>=` 一旦遇到 `Nothing` 就「短路」——整条链立刻结束。于是「可能失败的若干步骤」写成一行单子链，错误自动传播，这就是 Haskell 里没有异常还能优雅处理失败的原因。</span>

链条写多了会啰嗦，于是 Haskell 提供 **do 记法（do-notation）**——它只是 `>>=` 的语法糖：

```haskell
main = do
    line <- getLine          -- 取出一行
    if null line
      then return ()
      else putStrLn line >> main
```

把 `do` 里每一行看成「一次 bind」：`x <- e` 把 `e :: m a` 的 `a` 绑给 `x`，然后继续。**do 记法让「单子计算」读起来像命令式顺序语句**——这正是 IO 单子让 Haskell 能干「命令式」的活、同时保持类型安全的原因，详见《效应系统》。

## 4 公式解析：单子律——原来它是个幺半群

**「单子是自函子范畴上的幺半群」这句话到底在说什么？** 拆开它，不过是三条等式。

单子 $m$ 是一个函子，配上两个自然变换：**unit（return）** $\eta : \mathrm{Id} \to m$ 与 **multiplication（join）** $\mu : m\circ m \to m$。要求满足结合律与单位律，用 Haskell 的 `>>=` 重新写成程序员熟悉的三条**单子律**：

- **左单位律**：`return a >>= f` 与 `f a` 等价——「抬升之后立刻 bind」等于「直接用」；
- **右单位律**：`m >>= return` 与 `m` 等价——「bind 回 return」等于「没 bind」；
- **结合律**：`(m >>= f) >>= g` 与 `m >>= (\x -> f x >>= g)` 等价——「先后两步」等于「合成一步」。

把这三条与幺半群的定义对照：幺半群要求「有单位元、运算结合」；这里 `return` 是单位元、`>>=`（或者说 $\mu$）是结合运算——**所以单子确实是「（自函子）范畴上的幺半群」**。艾瑞那句玩笑话，拆到底就是这三条等式。<span class="marginnote">满足三条律的单子才是「真单子」，才能保证 `do` 语法的重排安全。GHC 提供 `-XTypeLaws` 这类工具辅助证明，但主流用法仍是「写出定律、相信正确性」。</span>

**直觉收束**：函子处理「一个盒子」，applicative 处理「独立的多盒子」，monad 处理「依赖的多盒子」。三者的名字各不相同，但共享同一句口诀——**把「在盒子里操作」这一主题逐层加深**。

再举一个让单子价值落地的真实例子：**State 单子**。它把「可变的全局状态」装进一个纯函数里：状态变换 $s \to (a, s)$ 本身就是值，`get`、`put` 读取与改写状态，`>>=` 负责把状态**串**下去。于是「计数器」「随机数生成器」这类「有状态」的程序，在纯函数世界里被表示成**显式传递状态**的单子——副作用被关进类型里，这正是《效应系统》一篇的核心思想的一次预演。

## 5 范畴论的最小核心：只要四个词

这一节只需掌握范畴论最外层的四个词，作为往后的门票：

- **范畴（category）**：对象 + 态射（morphism，对象之间的箭头）+ 恒等态射 + 结合律。
- **函子（functor）**：把一个范畴映到另一个范畴、且保持结构的映射。
- **自然变换（natural transformation）**：两个函子之间的「平行箭头」——`return` 与 `join` 正是自然变换。
- **单子**：函子 + 一对自然变换（$\eta, \mu$）满足结合律与单位律。

编程界不需要比这更多的范畴论，就能理解 Haskell 的类型类、Scala 的 `cats`、Rust 的 trait 组合背后的统一结构。<span class="marginnote">更深的范畴论（伴随、幺半范畴、n-category）在数学里恢宏壮阔，但做类型系统与语言设计只需这四词。别被「范畴论」三个字吓退——你在本节的收获已经够用。</span>

## 6 小结

把三者的「能力边界」用一张表钉死，是理解这条抽象阶梯最直接的方式：

| 抽象 | 核心操作 | 处理什么 | 依赖关系 |
| --- | --- | --- | --- |
| 函子 | `fmap` | 一个盒子的内部值 | 无 |
| 应用函子 | `pure`, `<*>` | 多个独立盒子 | 相互独立、可并行 |
| 单子 | `return`, `>>=` | 多个依赖盒子 | 后者依赖前者结果 |

一句话记忆：**函子处理值，applicative 处理独立的结构，monad 处理依赖的结构**。三者层层包含：每个单子都是应用函子，每个应用函子都是函子。

- **函子**：能 `fmap` 的容器，律保证它结构保持、不做多余的事。
- **应用函子**：`pure` + `<*>`，处理「独立的多盒子」，支持并行求值。
- **单子**：`return` + `>>=`，处理「依赖的多盒子」，让计算串联。
- **三条单子律**（左/右单位、结合）与幺半群定义完全对应——这就是艾瑞名句的真相。
- 范畴论只需四词门票：**范畴、函子、自然变换、单子**。
- `Maybe`/`List`/`IO` 都是单子实例，共享同一套 `do` 语法。

在下一节，我们把镜头从「抽象的形状」转向「计算的时机」：**惰性求值**——为什么 Haskell 可以拥有无限长的列表，以及「按需计算」给语言带来什么力量与代价。
