## 为什么从静态时序分析开始

布局布线把所有单元与连线都放好了，但「电路到底能不能按时工作」还没有答案。**静态时序分析（Static Timing Analysis，STA）**就是回答这个问题的第一把尺子——也是签核（signoff）的头号大关。

这一篇对标 Kahng、Lienig、Markov、Hu《VLSI Physical Design》第 8 章「Timing Closure」，并参考 Wang 等《Electronic Design Automation》第 6 章中的时序分析部分。核心直觉一句话：**每个触发器的数据必须在时钟沿前后保持稳定，STA 就是检查「所有路径都做到这一点」的数学方法。**

为什么叫「静态」？因为它**不跑仿真、不给输入向量**，而是枚举电路里所有可能的时序路径，用最坏情况检查每一段。仿真只能覆盖你喂进去的那几个输入，STA 覆盖的是全部路径——这正是它成为签核标准的根本原因。

STA 的计算复杂度也值得一提：一张百万门的时序图有几百万个节点、上千万条边，而最长路径的求法只是「拓扑排序 + 动态规划」——每个节点的 arrival time 由其所有前驱的最大值递推而来。这是《算法设计与分析》里「DAG 上的最长路径」在工业里的真实规模应用：O(V+E) 就能跑完全部关键路径。

<span class="marginnote">STA 与仿真的关系：仿真证明「在这些输入下没问题」，STA 证明「所有路径上都不会超时」。前者像抽样检查，后者像全量审计。芯片规模越大，全量审计越不可替代——这也是为什么 STA 是签核必须的环节。</span>

## 1 时序路径与时序图

STA 把电路建模成一张**时序图（timing graph）**：节点是引脚与端口，边是「信号从一个引脚传到另一个引脚」的延迟。电路里的所有信号路径都可以分为四类：

**寄存器到寄存器（reg-to-reg）**：一个触发器的输出，穿过组合逻辑，到达另一个触发器的输入——这是最常见、也最重要的一类。**输入到寄存器（input-to-reg）**：芯片输入引脚到第一个触发器。**寄存器到输出（reg-to-output）**：最后一个触发器到芯片输出引脚。**输入到输出（input-to-output）**：纯组合路径（绕过所有触发器）。

其中每个触发器的**数据引脚（D 端）**与**时钟引脚（CK 端）**是 STA 的「检查点」。一条路径的起点叫 **launch flip-flop**（发射触发器），终点叫 **capture flip-flop**（捕获触发器）。所有时序约束都围绕「发射、捕获、时钟」这三者的关系展开。

## 2 建立时间与保持时间

每个触发器都有两个固有参数，是时序设计的物理底线：

**建立时间（setup time，$T_{\text{setup}}$）**：数据必须在时钟沿**之前**就稳定，提前量至少是 $T_{\text{setup}}$——否则触发器可能采到「正在变化」的数据。**保持时间（hold time，$T_{\text{hold}}$）**：数据必须在时钟沿**之后**再保持稳定一段 $T_{\text{hold}}$——否则它可能采到「下一拍」的数据。

这两个约束分别对应两种违例：**建立时间违例（setup violation）**意味着「数据来得太晚」，会限制芯片的最高频率；**保持时间违例（hold violation）**意味着「数据变得太快」，与频率无关，是纯粹的竞争冒险问题。

两个约束的区别，用**核心对比表**一目了然：

| 项目 | 建立时间（setup） | 保持时间（hold） |
| --- | --- | --- |
| 检查的是 | 数据到达得太晚 | 数据变化得太快 |
| 用什么延迟 | 最慢角 / 最大延迟 | 最快角 / 最小延迟 |
| 影响什么 | 最高时钟频率 | 频率无关，纯竞争冒险 |
| 后果 | 芯片跑不到目标频率 | 芯片在任意频率都可能出错 |
| 修复手段 | 缩短组合逻辑 / 加大时钟周期 | 插入延迟缓冲器 / 修时钟偏斜 |
| 在时序图上 | 沿 launch→capture 正向路径 | 沿同样的路径但用最小延迟 |

「建立时间用最大延迟、保持时间用最小延迟」是 STA 里最重要的一条心法：查建立时间时担心数据太慢，所以取最坏；查保持时间时担心数据太快，所以取最好。**同一段电路，两种约束，两个世界。**

<span class="marginnote">建立时间与保持时间的通俗比喻：火车（数据）要在发车时刻（时钟沿）之前检票进站（setup），并且发车后不能立刻从车厢里消失（hold）。进站晚了会误车，出站太急会丢行李——两个都要管。</span>

## 3 公式解析：setup 约束与最大时钟频率

考虑最经典的「寄存器到寄存器」路径：发射触发器的时钟到输出延迟为 $T_{\text{cq}}$（clock-to-Q），组合逻辑延迟为 $T_{\text{comb}}$，时钟周期为 $T_{\text{clk}}$，时钟偏斜为 $T_{\text{skew}}$（捕获时钟比发射时钟晚到的量）。则建立时间约束为：

$$
T_{\text{cq}} + T_{\text{comb}} + T_{\text{setup}} \le T_{\text{clk}} + T_{\text{skew}}
$$

- **第一步，读左边（数据到达的时间）**：发射时钟沿一到，数据经过 $T_{\text{cq}}$ 离开触发器，再穿过组合逻辑花 $T_{\text{comb}}$，到达捕获触发器的 D 端。**$T_{\text{cq}} + T_{\text{comb}}$ 就是数据到达的时刻**。
- **第二步，读右边（数据最晚允许到达的时间）**：捕获时钟沿在 $T_{\text{clk}}$ 时刻到来，但数据必须在它之前 $T_{\text{setup}}$ 就稳定——且捕获时钟因为偏斜而晚到 $T_{\text{skew}}$，等于多给了 $T_{\text{skew}}$ 的余量。所以最晚到达时刻是 $T_{\text{clk}} + T_{\text{skew}} - T_{\text{setup}}$。
- **第三步，移项得到最大频率**：$T_{\text{clk}} \ge T_{\text{cq}} + T_{\text{comb}} + T_{\text{setup}} - T_{\text{skew}}$，于是最大时钟频率 $f_{\max} = 1/T_{\text{clk,min}}$。**想跑得更快，就要压短组合逻辑延迟 $T_{\text{comb}}$**——这正是综合与布局要优化关键路径的原因。
- **第四步，定义 slack（余量）**：$T_{\text{clk}} + T_{\text{skew}} - (T_{\text{cq}} + T_{\text{comb}} + T_{\text{setup}})$。slack 为正表示路径有余量，为负表示违例。**STA 报告的核心就是每一条路径的 slack**，负 slack 的路径就是「关键路径」，必须修复。

对应的**保持时间约束**为 $T_{\text{cq,min}} + T_{\text{comb,min}} \ge T_{\text{hold}} + T_{\text{skew}}$（要用最小时延估算，因为「数据变得太快」才是问题）。它不限制频率，但要求数据在时钟沿后别立刻变化——这通常靠插入延迟缓冲器修复。

到这里，STA 与前面几篇的线索也接上了：$T_{\text{comb}}$ 是综合阶段要压的（逻辑综合篇），时钟偏斜 $T_{\text{skew}}$ 是 CTS 要控制的（时钟树综合篇），线长延迟是布线要负责的（布线篇）。**STA 像一台「总账本」，把前面每个环节的贡献汇总成一张时序报表。**

## 4 RC 提取与片上变化

STA 的延迟计算依赖两样输入：**单元延迟**（从工艺库查表得到）与**互连延迟**（从布线几何计算得到）。互连延迟的第一步是 **RC 提取（RC extraction）**：从版图几何中算出每段金属的电阻 $R$ 与电容 $C$，再交给延迟计算器（如 Elmore 模型或更精确的仿真）求延迟。

但真实芯片有一个残酷的事实：**工艺不是完美的**。同一批芯片、同一块芯片的不同区域，晶体管的阈值电压、金属的电阻率都有随机差异——这就是**片上变化（on-chip variation，OCV）**。为了保守起见，STA 会**同时用最快与最慢两个角**分析：最快角（fast corner）查保持时间，最慢角（slow corner）查建立时间。

RC 提取还有一个细腻之处：**耦合电容**。两条平行的金属线之间存在耦合电容，邻近线翻转时会「串扰」过来，让信号的到达时刻提前或推迟。STA 用「最坏情况串扰」评估这种效应——为了跑赢串扰，布线时还要给关键信号留足间距，这又把 STA 与布线篇的「间距规则」接上了。

<span class="marginnote">从 OCV 到 <strong>AOCV（先进片上变化）</strong>，是精确度的一次升级：AOCV 认为「变化随路径长度递减」——路径越短，随机变化占比越大；路径越长，各种随机效应互相平均、占比越小。AOCV 用「深度相关的降额系数」把每条路径的变化算得更细，避免了「一刀切」的过度悲观。</span>

**时序角（timing corner）**则把电压、温度、工艺三个维度组合起来：最坏情况（slow/slow，低温高压）、最好情况（fast/fast，高温低压）……签核要在所有角下都通过，这使 STA 的运行次数成倍增长——也是并行计算在 EDA 里最典型的应用之一。

## 5 STA 在签核中的作用

STA 不是「最后才跑一次」的工具，而是贯穿全程的**指挥棒**：综合阶段用它指导优化，布局阶段用它挑选单元位置，CTS 之后用它检查时钟，布线之后用它做最终签核。每一次「优化 → STA → 再优化」的循环，都是把负 slack 的路径一条条修掉的过程。

因此现代 EDA 工具把 STA 引擎「内嵌」到综合与物理设计里，让每一步都「时序感知」：综合器对关键路径加权，布局器把关键单元摆近，布线器给关键线留宽裕。**STA 从一个「事后检查」的工具，变成了「事前指导」的引擎**——这是时序签核方法学在过去二十年最大的转变。

STA 的最终输出是一份**签核报告**：每条关键路径的延迟分解、slack 值、违例原因。设计师据此判断：是组合逻辑太长（改 RTL 或综合策略）、还是线太长（改布局约束）、还是时钟偏斜太大（改 CTS）。**STA 不只是「判定对错」，更是指出「该修哪里」。**

<span class="marginnote">STA 报告里有一个常见的陷阱：<strong>伪路径（false path）</strong>。有些路径在真实电路里永远不会被激活（比如两个互斥的使能信号），STA 却会照常检查。设计师必须用 SDC 约束把伪路径「豁免」掉，否则 STA 会报一堆「永远不发生的违例」，浪费整个团队的排查时间。<strong>让工具知道你的意图，是 STA 使用者的基本功。</strong></span>

## 6 时序修复：把负 slack 修成正

STA 报告的最终价值，是把负 slack 的路径一条条修成正。修复手段按「该动哪一层」分层：

**改 RTL**：在关键路径里插入流水寄存器，把一段长组合逻辑切成两段——延迟减半，但代价是数据晚一拍到达。**改综合策略**：让综合器给关键路径更激进的时序优化。**改布局**：把关键路径上的单元摆近，缩短线长。**改 CTS**：用有用偏斜给关键路径「借时间」。

这套「诊断 → 分层修复 → 再 STA」的循环，在物理设计里可能重复几十轮。每一次循环，关键路径的数量都在减少，直到全部路径的 slack 非负——这就是工程师口中的「**时序收敛（timing closure）**」，也是 Kahng 教材第 8 章的标题。

<span class="marginnote">时序收敛的残酷现实：越接近收敛，剩下的路径越「难啃」——它们往往纠结着复杂的约束组合（多周期路径、跨时钟域、set_case_analysis 等）。最后几条路径的修复，常常不是靠工具自动跑完，而是靠经验丰富的工程师「手工喂约束」。这也是为什么「时序工程师」是芯片团队里最难招的岗位之一。</span>

## 7 小结

- **STA** 枚举全部时序路径做最坏情况检查，比仿真更完整，是签核的标配。
- 时序路径分四类，核心是**寄存器到寄存器**；建立/保持时间是触发器的物理底线。
- 建立时间约束 $T_{\text{cq}} + T_{\text{comb}} + T_{\text{setup}} \le T_{\text{clk}} + T_{\text{skew}}$ 决定**最大频率**，保持时间约束决定**最小延迟**。
- **slack** 是路径余量，负 slack 即关键路径违例，是优化的唯一目标。
- **RC 提取 + Elmore 延迟**算互连延迟；**OCV/AOCV** 与多时序角保证签核保守可信。
- 伪路径要用 SDC 豁免，STA 报告指出的「该修哪里」驱动综合、布局、CTS 的迭代。
- 时序修复是「改 RTL / 改综合 / 改布局 / 改 CTS」的分层动作，直到全部 slack 非负即「时序收敛」。
- STA 引擎已内嵌到综合与物理设计各环节，「事后检查」变成「事前指导」。

在下一节，时序通过只代表「逻辑上会工作」，我们还要确认「版图上真的没问题」。下一站是**物理验证**——DRC、LVS、ERC 与天线效应，保证版图既合法又可制造。
