## 为什么从数组开始

在所有复合类型里，**数组（array）**是最古老也最基础的：它是一串**同类型元素**的连续存储，靠**下标**访问。数组的重要性在于它是「内存布局」与「抽象」的交汇点——一方面，数组直接映射到连续内存，编译器能算出任意元素的地址（这是第二级《计算机组成原理》里寻址方式的前提）；另一方面，数组又是大多数算法的数据结构底座。各语言在「下标从几开始、长度何时定、能否改变形状、能否切片」上的分歧，正是一部类型系统如何一步步变得既安全又灵活的历史。<span class="marginnote">数组是「内存连续 + 下标计算」的化身：`a[i]` 的地址 = 基址 + $i \times$ 元素大小，一条乘法加一条加法即可完成。这个 $O(1)$ 随机访问，是数组区别于链表的核心优势。</span>

## 1 数组的定义与四个维度

**数组（array）**：由**相同类型**的元素组成的**同质（homogeneous）**聚合，每个元素通过**下标**（index）区分。

Sebesta 指出设计数组要回答四个问题：

- **下标类型**：允许什么类型的下标？C 只允许整数；Fortran 允许任意有序类型；Python 的字典「下标」甚至可以是任意哈希对象。
- **下标范围**：下标从几到几？C 从 0 到 `n-1`；Pascal 可自定义 `array[1..10]`；Fortran 早期默认从 1 开始。
- **下标集何时绑定**：长度在**编译期**（静态数组）还是**运行期**（动态数组）确定？
- **存储何时分配**：分配在栈（函数内的局部数组）还是堆（运行时扩展）？

## 2 数组的下标：从 0 还是从 1

下标起点的选择是语言设计史上一桩著名公案：

- **从 0 开始**（C、Java、Python、Rust）：`a[i]` 的地址 = 基址 + $i \times$ 大小，天然与指针算术一致。<span class="marginnote">迪杰斯特拉在《Why numbering should start at zero》里从数学角度为 0 辩护：左闭右开区间 $[0, n)$ 的好处是「长度为 $b - a$、且空区间合法 $[a, a)$」——这成了 Python `range(n)` 与切片语法的理论依据。</span>
- **从 1 开始**（Fortran、MATLAB、Lua）：与数学下标、人类直觉一致，排序 `a[1]` 是第一个元素；缺点是空数组与子区间表达更绕。

**辨析｜易错点：** 从 0 开始的数组，长度为 $n$ 时**最大合法下标是 $n-1$**。遍历时 `for i in 0..=n`（包含 n）会越界——这是数组越界的第一大来源。而越界在 C 里是未定义行为（可能静默破坏内存），在 Java/Rust 里是运行时异常/panic。语言不同，代价不同。

## 3 静态数组与动态数组：绑定时间

按「长度何时确定」分两类：

**静态数组（static array）**：长度在编译期确定，存储随之固定。C 的 `int a[100];` 中 `100` 必须是编译期常量。优点是零运行时开销、可放栈上；缺点是长度写死。

**动态数组（dynamic array）**：长度在运行期由变量决定，且可能增长。Java 的 `new int[n]` 在运行期确定 `n`；Python 的 `list` 可随时 `append`。<span class="marginnote">Python `list` 的实现是「可增长的动态数组」：底层是一段连续指针数组，容量不足时重新分配更大块并拷贝——均摊后 `append` 是 $O(1)$。它仍是「数组」而非链表，只是会自己长个儿。</span>

**固定动态数组（fixed dynamic）**：长度运行时定但**不可变**——Java `int[n]` 创建后长度锁定。这是「灵活创建 + 长度稳定」的中间路线。

## 4 数组的初始化与切片

**初始化**：各语言差异巨大。

```c
int a[3] = {1, 2, 3};        /* C：编译期初始化 */
int[] b = {1, 2, 3};          /* Java：声明 + 初始化合并 */
let c = [1, 2, 3];            /* Rust：类型推导 + 字面量 */
[1, 2, 3]                     /* Python：列表字面量，动态 */
```

**多维数组**：C 的 `int m[3][4]` 是「数组的数组」，内存按**行优先**连续排布——`m[i][j]` 的地址 = 基址 + $(i \times 4 + j) \times$ 大小。<span class="marginnote">行优先意味着 `m[i]` 本身是「指向一行 4 个 int 的指针」。二维数组的「第一维下标」在 C 传参时必须给出除第一维外的全部维度——因为编译器要靠它算地址。这是 C 数组参数最容易出错的地方。</span>

**切片（slice）**：现代语言让「取数组的一段」成为一等操作。Python `a[1:4]`、Rust `&a[1..4]`、Go `a[1:4]` 都返回「视图」而非拷贝（Python 切片返回新列表，Rust/Go 返回视图——语义不同）。

## 5 公式解析：数组元素的地址计算

数组的 $O(1)$ 访问背后是一条地址公式。一维数组：

$$
\text{addr}(a[i]) = \text{base} + (i - \text{low}) \times \text{size}
$$

二维数组（行优先）$m$ 行 $n$ 列：

$$
\text{addr}(m[i][j]) = \text{base} + ((i - r_0) \times n + (j - c_0)) \times \text{size}
$$

三步拆解：

- **第一步，看偏移量**：$i - \text{low}$ 是从首下标起的元素个数。若 `low = 0`（C 系），偏移就是 $i$——公式退化为「基址 + $i \times$ 大小」。
- **第二步，看二维展开**：$(i - r_0) \times n$ 是「跳过前面 $i - r_0$ 整行」的元素数，$+(j - c_0)$ 是「行内再前进 $j - c_0$ 个」。行优先把二维映射成一维，编译器在**编译期**就固定了 $n$ 与 `size`，运行期只需乘法加法。
- **第三步，看越界检测**：若要安全，运行时须先验证 $\text{low} \le i \le \text{high}$ 再做计算——Java/Rust 做，C 不做。**越界检查是「安全数组」与「裸数组」的分界线**。

**辨析｜易错点：** 数组是**同质**的（所有元素同类型），这与「元组/记录」的**异质**（各字段类型可不同）相对。把数组当异质容器用（如「一个数组存名字和年龄」）是不懂类型设计的典型症状——那正是记录类型的用武之地，也是下一节的主角。

## 6 数组与「别的东西」的边界

数组类型在语言里常与几个相近概念混淆——厘清边界是避免错用的关键：

**数组 vs 链表**：数组连续存储、O(1) 随机访问；链表节点分散、O(n) 随机访问。**「数组快在访问，链表快在插入」**。

**数组 vs 切片（slice）**：切片是「数组的一段视图」——`&a[1..4]`（Rust）、`a[1:4]`（Go）不拷贝，指向原数组。**「切片 = 指针 + 长度」**，是「安全地共享数组的一部分」。

**数组 vs 元组/记录**：数组**同质**（元素同类型）、下标整数；元组/记录**异质**（字段类型可不同）、按位置/名字访问。**「同质用数组，异质用元组」**。

| 概念 | 同质/异质 | 访问方式 | 底层 |
| --- | --- | --- | --- |
| 数组 | 同质 | 整数下标 | 连续内存 |
| 切片 | 同质 | 整数下标（视图） | 指向数组 |
| 链表 | 同质 | 遍历 | 分散节点 |
| 元组 | 异质 | 位置 | 连续（打包） |

**辨析｜易错点：** **「切片是引用不是拷贝」**——`b = a[1:4]`（Go/Rust 切片）后改 `b` 会改到 `a` 的底层数组；Python 的 `a[1:4]` 则是**新列表**（拷贝）。**「同一个切片语法，不同语言语义不同」**——「切片是视图还是副本」必须先确认。「数组、切片、链表、元组」是四个不同工具，选错就是复杂度灾难。

## 7 小结

- 数组是**同质、连续存储、下标访问**的聚合；四个设计维度是下标类型、范围、绑定时间、存储分配。
- 下标从 0 开始由「左闭右开区间」的数学便利驱动，从 1 开始更贴近直觉。
- 长度绑定分**静态 / 固定动态 / 动态**三档，绑定时间决定灵活性与开销。
- 地址公式 $\text{base} + (i-\text{low}) \times \text{size}$ 是 $O(1)$ 访问的根源；**越界检查**是安全分界线。
