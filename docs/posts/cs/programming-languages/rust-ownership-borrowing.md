## 为什么从所有权开始

手动管理（C）有悬垂与泄漏，GC（Java）有停顿，引用计数（Swift）有循环引用——Rust 给出了第四条路：**所有权（ownership）系统**。它把「谁拥有这块内存、能活多久、谁能借用」全部编码进类型系统，由**借用检查器（borrow checker）**在**编译期**验证——既不手动释放、也无 GC，内存安全由「编译不过就重写」保证。这一节讲所有权模型的三条核心规则、移动语义、以及借用与生命周期——它们是 Rust「零成本抽象」和「无 GC 安全」的地基。<span class="marginnote">Rust 的野心：<strong>让内存安全错误在编译期消失</strong>。C 的「悬垂、越界、双重释放」在 Rust 里是编译错误而非运行时错误。代价是「借用检查器」的学习曲线——但它的规则其实只有几条，一旦内化，内存安全几乎免费。</span>

## 1 所有权的三条规则

**所有权（ownership）**：Rust 的每个值有且仅有一个**所有者（owner）**。三条规则：

1. **每个值有且仅有一个所有者**——即「每个变量拥有自己的值」。
2. **所有者离开作用域时，值被释放（drop）**——RAII（资源获取即初始化）。
3. **所有权可以转移（move）**，不能复制（除非实现 Copy trait）。

```rust
let s1 = String::from("hello");
let s2 = s1;           // 所有权从 s1 转移到 s2（move）
// println!("{}", s1); // 编译错误：s1 已被移动，无法再使用
println!("{}", s2);    // 正常输出
```

`s1` 的所有权被**移动**到 `s2`——`s1` 此后不可用。这是「移动语义」：避免双重释放（两个所有者都释放同一内存）的关键。<span class="marginnote">为什么不能「拷贝」？String 的内部结构（指针、长度、容量）若浅拷贝，两个变量指向同一堆内存，离开作用域都 drop——双重释放（use-after-free）。Rust 的答案：<strong>所有权转移</strong>（s1 失效），或显式 `clone()`（深拷贝）。「移动 = 转移所有权，不是复制」——这消灭了 C 里最危险的「双重释放」类。</span>

## 2 借用：不转移的访问

**借用（borrowing）**：不获取所有权地访问值——用**引用（reference）**。

```rust
fn len(s: &String) -> usize { s.len() }

let s = String::from("hello");
let n = len(&s);          // 借用 s（&s），不转移所有权
println!("{} {}", s, n);  // s 仍可用
```

两种借用：

**不可变借用 `&T`**：只读——可多个同时存在。
**可变借用 `&mut T`**：可写——**同一时刻只能有一个**。

**借用检查器的核心规则**：

```rust
let mut x = 5;
let r1 = &x;            // 不可变借用：OK
let r2 = &x;            // 多个不可变借用并存：OK
// let r3 = &mut x;     // 编译错误：已有不可变借用时不能再可变借用
let m = &mut x;         // 所有不可变借用失效后，可变借用才允许
*m += 1;
```

<span class="marginnote">「要么多个读、要么一个写」正是「读写锁」的编译期版本：多个读者可以并存，写者独占。Rust 把它从「运行时加锁」提前到「编译期检查」——这就是为什么 Rust 的并发数据竞争在编译期就被拒绝。没有 GC，没有运行时锁，安全靠类型系统。</span>

## 3 生命周期：引用能活多久

**生命周期（lifetime）**：引用有效的「时间区间」。Rust 用生命周期标注 `'a` 告诉编译器「这个引用和那个引用活得一样久」：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

`'a` 表示「输入引用与输出引用的共同寿命」——保证返回的引用不会比输入还短命。<span class="marginnote">生命周期标注大多可省略（生命周期省略规则：编译器自动推断），但「返回引用与哪个输入相关」必须显式。`'a` 的意思是「返回的引用活在 x 与 y 的公共寿命内」——编译器验证调用处这个关系成立。「生命周期 = 引用的保质期」，检查器保证「引用不越过被引用者的死亡」——悬垂引用在编译期消失。</span>

## 4 公式解析：借用检查的规则

借用规则可以形式化为「别名 + 可变性」的约束。设值 $v$，借用集合 $B$：

$$
\forall\ \text{时刻}: |\{b \in B : b \text{ 是 } \&mut v\}| \le 1
$$

$$
\forall\ \text{时刻}: (\exists\ b \in B,\ b \text{ 是 } \&mut v) \;\Rightarrow\; \nexists\ b' \in B,\ b' \text{ 是 } \&v
$$

三步拆解：

- **第一条，一个写者**：同一时刻最多一个 `&mut` 借用——防止「两个写者同时改」。
- **第二条，读写互斥**：有可变借用时，不能有不可变借用——防止「读的同时被改」（读到的数据已变化）。
- **第三条（生命周期）**：引用寿命 ⊆ 被引用值寿命——防止悬垂。**三条规则合起来：无数据竞争、无悬垂、无双重释放——全部编译期保证**。

**辨析｜易错点：** 借用检查的「限制」常常让新手困惑：可变借用（`&mut`）一次一个，意味着「先借用再修改」的模式要调整。解法：作用域细化（借用结束再借）、`clone()`、或重构数据流。**「借用检查器不是限制你，而是强迫你写出『无别名冲突』的代码」**——接受它，代码天然线程安全。

## 5 所有权模型的价值与代价

- **零成本安全**：内存安全无运行时开销（无 GC、无引用计数）——性能等同手动管理。
- **确定性释放**：drop 在作用域结束时发生——资源（文件、锁）自动关闭，无泄漏。
- **并发安全**：所有权 + 借用让「数据竞争」编译期消失——`Send`/`Sync` trait 标记线程安全。
- **代价**：学习曲线陡（借用检查器的思维）、某些共享模式要改（`Rc`/`Arc`/`RefCell` 用于共享所有权）。<span class="marginnote">Rust 的所有权模型是现代语言设计的「分水岭」：它证明了「零成本 + 内存安全 + 并发安全」可以兼得——只要你愿意让编译器管得更严。`Rc`（单线程引用计数）、`Arc`（原子计数）、`RefCell`（运行期借用检查）是「所有权模型的补充工具箱」——当纯所有权不够用时，显式选择「运行时管理」并付出对应代价。</span>

## 6 小结

- **所有权三规则**：一值一所有者、离开作用域即 drop、所有权可移动（move）——移动消灭双重释放。
- **借用**：`&T`（多读者）与 `&mut T`（单写者）——「要么多读、要么单写」编译期检查。
- **生命周期** `'a`：引用不超过被引用值寿命——悬垂引用编译期消失。
- 所有权模型 = 零成本内存安全 + 确定性释放 + 并发数据竞争编译期拒绝；代价是借用检查的学习曲线。
