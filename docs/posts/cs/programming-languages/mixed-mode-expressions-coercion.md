## 为什么从混合模式表达式开始

现实表达式的操作数常常「类型不一致」：`1 + 0.5`（`int + float`）、`count * price`（`int * float`）。**混合模式表达式（mixed-mode expression）**指操作数类型不同的表达式。要让它算出结果，语言必须引入**类型转换（type conversion）**。转换的两种形态——**隐式强制（coercion）**与**显式转换（cast/conversion）**——是类型安全光谱上的一道分界线：允许哪些隐式转换、以什么规则、牺牲多少精度，各语言给出了截然不同的设计。这一节把这套机制拆开，也把「提升」「窄化」「截断」这些经常把人绊倒的细节讲透。<span class="marginnote">混合模式的本质是「不同类型如何对齐到公共类型」。语言越「纵容」隐式转换，写起来越省事，但精度损失与类型错误越隐蔽；越「严苛」越安全，但要写更多显式转换。JavaScript 的 `"5" * 3` 与 Python 的 `"5" * 3`（字符串重复 3 遍！）是两种极端。</span>

## 1 强制转换：隐式的自动转换

**强制转换（coercion）**：编译器/运行期自动把一种类型转换成另一种，无需程序员书写。它在两种情况下发生：

- **算术强制**：`1 + 0.5` 把 `1` 提升为 `1.0`（`int → float`）。
- **赋值强制**：`float x; x = 3;` 把整数 `3` 转成 `3.0` 存入。

<span class="marginnote">「强制」的关键词是<strong>隐式</strong>——程序员没写转换代码，语言自作主张。强类型语言允许「安全」的强制（`int → float` 无损）而拒绝「危险」的（`float → int` 有损），弱类型语言则放行大部分转换。</span>

## 2 转换的方向：拓宽与窄化

按「信息是否损失」分类：

**拓宽转换（widening conversion）**：从「窄」类型到「宽」类型，信息不损失。`int → long → float → double` 是常见的拓宽链。<span class="marginnote">注意 `int → float` 其实可能损失精度：32 位 `int` 转成 32 位 `float` 时，大整数的低位可能被舍入——`16777217` 转 `float` 变成 `16777216`。C 把 `int → float` 算「合法隐式转换」，但这正是「拓宽 ≠ 无损」的暗例。</span>

**窄化转换（narrowing conversion）**：从宽到窄，可能损失信息甚至溢出。`double → int` 截断小数、`long → int` 高位溢出。<span class="marginnote">各语言对窄化的态度分化：C 静默截断（`(int)3.9` 得 `3`），Java 隐式窄化编译错误（必须显式 `(int)`），Python 的 `int(3.9)` 显式截断且不溢出（任意精度）。「窄化是否要显式」直接反映语言的强/弱立场。</span>

## 3 各类语言的转换策略

| 语言 | 隐式转换策略 | 典型表现 |
| --- | --- | --- |
| C/C++ | 宽松，遵循「通常算术转换」 | `1 + 0.5` → `double`；窄化静默 |
| Java | 仅允许拓宽；窄化必须显式 | `int` 赋给 `double` 合法，反之心须 `(int)` |
| Python | 极简；数值自动拓宽，字符串不自动转数值 | `1 + 0.5` → `1.5`；`"5" + 3` 抛 `TypeError` |
| Rust | 禁止隐式数值转换 | `1i32 + 0.5f64` 编译错误，必须 `as` |
| JavaScript | 极宽，甚至字符串参与算术 | `"5" * 3` → `15`；`"5" + 3` → `"53"` |
| Haskell | 几乎零隐式转换 | 需显式 `fromIntegral` |

**辨析｜易错点：** JavaScript 的 `+` 是「双面运算符」：若任一侧是字符串则做**字符串拼接**，否则做**数值加法**——`"5" + 3` 得 `"53"`。而 `*`、`-`、`/` 只做数值运算，字符串会被强制转数字——`"5" * 3` 得 `15`。**同一个语言里 `+` 与 `*` 对字符串的态度完全不同**，是 JS 最著名的坑之一。

## 4 公式解析：通常算术转换规则

C 语言的混合模式转换遵循「**通常算术转换（usual arithmetic conversions）**」——把两个操作数提升到「公共类型」。其规则（简化）：

$$
\text{common}(T_1, T_2) = \text{类型链 } \text{int} \to \text{long} \to \text{float} \to \text{double} \text{ 中较靠后的那个}
$$

例：

$$
\text{common}(\text{int}, \text{double}) = \text{double}, \qquad
\text{common}(\text{int}, \text{float}) = \text{float}
$$

三步拆解：

- **第一步，认类型链**：C 把数值类型排成一条「宽度」链，`int < long < float < double`（`long double` 更靠后）。隐式转换只允许「沿链向前」（拓宽）。
- **第二步，找公共类型**：两个操作数提升到链上「较靠后」的那个类型。`int + double` 时 `int` 被转成 `double`，结果也是 `double`。
- **第三步，看整数特例**：C 还有**整数提升（integer promotion）**——`char`/`short` 参与运算先提升为 `int`（`char + char` 是 `int` 运算）。这解释了为什么 `sizeof('a' + 'b')` 在 C 里是 `sizeof(int)`。

**辨析｜易错点：** 赋值时的转换规则**不同于**算术：`float x = 3;` 是赋值强制（`int → float` 拓宽），`int y = 3.9;` 是赋值窄化——C 允许（截断为 3），Java 编译错误。**「算术里的转换」与「赋值里的转换」是两套规则**，别混用。

## 5 显式转换：把决定权拿回手里

**显式转换（explicit conversion / cast）**：程序员书写转换代码，明确类型意图。

```c
int n = (int)3.9;        /* C 风格 cast：截断为 3 */
double d = (double)n;    /* 拓宽也显式写 */

let n = 3.9_f64 as i32;  /* Rust：as 转换，显式 */
int n = (int) 3.9;        /* Java：显式窄化 */
```

显式转换的价值：

- **明确意图**：读者一眼看到「这里故意转类型」。
- **安全边界**：窄化这类有损操作被显式标记，审阅者能看到风险。
- **跨域操作**：指针转整数、枚举转底层值，只有显式转换才能表达。

<span class="marginnote">现代语言对显式转换的语法也分风格：C 的 `(int)` 前缀式、Rust 的 `as` 关键字、Python 的构造器 `int(x)`/`float(x)`。Haskell 的 `fromIntegral`/`fromRational` 把转换写成<strong>有名字的函数</strong>——意图最明确，代价是冗长。</span>

## 6 类型转换的实践准则

混合模式表达式的「实战智慧」浓缩为几条准则——帮你在各语言里少踩坑：

**准则一：隐式转换只信任「拓宽」**——`int → float`、`int → double` 通常无损（除大整数精度）；`float → int`、`double → float` 有损，尽量显式。

**准则二：金额与精确计算不用浮点**——`0.1 + 0.2` 的误差在金钱上不可接受；用**十进制类型**（Python `Decimal`、Java `BigDecimal`、SQL `DECIMAL`）。

**准则三：跨语言注意转换差异**——`"5" + 3`：JS 得 `"53"`（拼接）、Python 报错、Rust 报错。**「同一种写法，三种命运」**。

**准则四：显式转换写清楚意图**——`int(3.9)`、`(int)3.9`、`3.9 as i32` 都「明说我在截断」——审阅者能看到风险。

| 情境 | 推荐做法 |
| --- | --- |
| 数值拓宽 | 隐式（安全） |
| 数值窄化 | 显式 + 确认 |
| 金额 | 十进制类型 |
| 跨语言移植 | 查转换表 |

**辨析｜易错点：** **「转换的『安全性』不是看方向，是看是否有损」**——`int → float` 是拓宽（方向）但大整数可能舍入（有损）——「拓宽」与「无损」不划等号。**「每次隐式转换都是一次静默的假设」**（「这个 int 一定够小能装进 float」）——假设成立没事，不成立就是隐蔽 bug。「显式转换是把假设说出口」——说出口的假设才可被审查。

## 7 小结

- **混合模式表达式**是操作数类型不同的表达式；**强制转换**是自动隐式转换。
- 转换分**拓宽**（信息不损失，但 `int→float` 可能舍入）与**窄化**（可能截断/溢出，通常需显式）。
- 语言策略光谱：C 宽松、Java 仅拓宽、Python 数值自动拓宽、Rust 禁止隐式数值转换、JS 极宽且 `+` 有字符串拼接歧义。
- 算术转换与赋值转换是**两套规则**；显式转换把意图写进代码，是现代语言的偏好。
