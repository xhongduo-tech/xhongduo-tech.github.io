## 为什么从迭代语句开始

选择结构决定「走哪条路」，**迭代语句（iterative statement）**决定「走多少遍」。循环是程序重复能力的形式化：三类主流形态——**计数循环**（`for`，按已知次数迭代）、**逻辑循环**（`while`/`do-while`，按条件迭代）、以及现代**迭代器**（`for x in collection`，对集合遍历）。迭代语句的设计里藏着语言的哲学：循环变量是语言专属还是用户定义、条件何时测（前测/后测）、迭代器是语法糖还是可组合的抽象。<span class="marginnote">「循环」与「递归」是重复的两种表达：循环靠迭代（命令式），递归靠调用自身（函数式）。Böhm-Jacopini 定理保证两者表达能力等价，但可读性与效率各异——第十二篇函数式编程会展开递归视角。</span>

## 1 计数循环：for 的经典形态

**计数循环（counter-controlled loop）**：由一个**循环变量**（counter）从初值迭代到终值，步长固定，迭代次数已知或可计算。

C 系的 `for` 是「最赤裸」的计数循环——循环变量、条件、步进全部显式：

```c
for (int i = 0; i < n; i++) {
    /* 循环体 */
}
```

Fortran/Pascal 的 `for` 更「封装」——只给初值、终值，步进由语言管理：

```pascal
for i := 1 to 10 do writeln(i);
```

**设计问题**：

- **循环变量的作用域**：C99 的 `for (int i...)` 把 `i` 关在循环内；旧 C 的 `i` 泄漏到循环外。
- **终值何时求**：C 的 `i < n` 每轮都重新求值（若 `n` 在循环内改变，迭代次数变化）；Fortran 的终值只在进入时求一次。<span class="marginnote">「条件每轮重测 vs 终值只测一次」是计数循环的核心语义分歧。C 重测（`n` 可变 → 循环次数动态）；Fortran 只测一次（循环次数固定）。重测更灵活但更难推理，只测一次更可预测。</span>

**辨析｜易错点：** C 的 `for (int i = 0; i < n; i++)` 中 `n` 每轮重读——若循环体内 `n` 被修改，迭代次数出乎意料。依赖「循环次数固定」的推理在 C 里不可靠，这是「计数循环」在 C 里其实是「逻辑循环加糖」的体现。

## 2 逻辑循环：while 与 do-while

**逻辑循环（logically controlled loop）**：以布尔条件控制循环，迭代次数不预知。条件**前测**还是**后测**决定「至少执行一次」与否。

**前测循环（pretest）**：先测条件，真则执行。`while`——条件为假时**一次都不执行**。

```c
while (n > 0) { sum += n; n--; }
```

**后测循环（posttest）**：先执行一次体，再测条件。`do-while`——**至少执行一次**。

```c
do { digit = getchar(); } while (digit != '\n');
```

**辨析｜易错点：** 前测与后测的「至少一次」差异是最经典的陷阱：`while` 对空输入直接跳过，`do-while` 对空输入也执行一次。把后测循环改写前测时，要显式补「先执行一次」的逻辑——反之亦然。**翻译循环形态时，「至少执行一次」的语义必须显式处理**。

## 3 迭代器与 for-each：遍历的现代形态

**迭代器（iterator）**：抽象「逐个访问集合元素」的机制，把「怎么遍历」从循环逻辑中分离。

现代语言普遍提供 **for-each 循环**：

```python
for x in items:       # Python：直接遍历可迭代对象
    process(x)

for item in &v {      // Rust：for 循环遍历迭代器
    println!("{}", item);
}
```

**迭代器协议**：Python 的 `__iter__`/`__next__`、Rust 的 `IntoIterator`、Java 的 `Iterator` 接口——让**用户自定义类型**也能被 `for` 遍历。

<span class="marginnote">迭代器的价值是<strong>分离「遍历策略」与「处理逻辑」</strong>：同样的 `for x in data` 可以换成惰性迭代、并行迭代、过滤迭代，循环体不用改。现代语言的迭代器普遍<strong>惰性</strong>——元素按需生成，支持无限流（`itertools.count()`）。</span>

## 4 公式解析：循环的语义模型

循环（以 `while` 为例）的语义可以递归定义——这正是「重复」的精确定义：

$$
\text{while}\ B\ \text{do}\ S \;\equiv\; \text{if}\ B\ \text{then}\ (S;\ \text{while}\ B\ \text{do}\ S) \;\text{else}\ \text{skip}
$$

三步拆解：

- **第一步，读等价**：`while B do S` 等价于「若 B 真，则执行 S 后再来一遍；否则什么都不做」。这是循环的**递归展开**——把「重复」翻译成「条件 + 递归」。
- **第二步，看终止**：递归展开会一直持续到 `B` 为假。若 `B` 永真，展开无限进行——对应**死循环**。循环终止 = 「经过有限次递归后 `B` 为假」。
- **第三步，连公理语义**：这条等价式正是公理语义里循环规则的基础——循环不变式 $I$ 满足 $\{I \land B\} S \{I\}$ 时，`while B do S` 保持 $I$ 且退出时 $\neg B$。**循环语义 = 条件 + 递归，这是三支语义都认可的公共结构**。

**辨析｜易错点：** `for` 循环与 `while` 循环的等价：`for (init; cond; step) body` 完全等价于 `init; while (cond) { body; step; }`——所以 C 的 for 是 while 的语法糖。但**循环体内 `continue` 的行为**不同：for 的 `continue` 仍会执行 `step`，而手写 while 里 `continue` 跳过 `step`。**翻译 for ↔ while 时，`continue` 的差异是隐蔽的坑**。

## 5 从循环到语言设计

- **Python**：`for` 只遍历可迭代对象，不提供 C 风格计数 for——计数靠 `range(n)`。**「for 只能遍历」的强制，让循环天然结构化**。
- **Rust**：`for x in iter` 内建迭代器协议；`..` 区间（`0..n`）生成范围。
- **Java**：传统 `for (i=0;...)` 与增强 `for (x : col)` 并存，迭代器模式可自定义。
- **Go**：`for` 一个关键字承担全部——`for {}`（无限）、`for cond {}`（while）、`for i := range`（迭代）。

<span class="marginnote">一个有趣的趋势：<strong>循环正在被「迭代」吸收</strong>。Python 的「列表推导」`[x*x for x in items]`、Rust 的「迭代器链」`items.iter().map(f).filter(g).collect()` 把「循环 + 条件 + 变换」压缩成声明式表达式——不再写循环变量，而是描述「对每个元素做什么」。这是控制结构「从语句走向表达式」的又一体现。</span>

## 6 小结

- **计数循环**（`for`）按已知次数迭代；C 的 for 是「条件重测」的裸形态，Fortran 的 for 是「终值固定」的封装形态。
- **逻辑循环**（`while`/`do-while`）按条件迭代；**前测**（可零次）与**后测**（至少一次）是最核心的语义差异。
- **迭代器与 for-each** 分离「遍历策略」与「处理逻辑」，支持用户自定义类型与惰性迭代。
- 循环语义 = 条件 + 递归展开；for ↔ while 翻译时 `continue` 行为是隐蔽坑。
