## 为什么从指针开始

数据类型的历程走到这里，遇到了一位特殊成员：**指针（pointer）**。它不直接装数据，而是装「数据所在的内存地址」——一个类型的值「指向」另一个类型的值。指针是 C 系语言高性能的根基（数组、字符串、链表、回调全依赖它），也是大量内存灾难（悬垂、越界、泄漏）的根源。理解指针，本质是理解「间接寻址」：值之外还有「值的位置」，而程序既可直接操作值，也可操作位置。<span class="marginnote">指针也是连接「类型系统」与「计算机组成原理」的桥：第二级《计算机组成原理》里的地址、寻址方式、存储器层次，在此升格为类型系统的一等公民。C 的 int * 不再只是「地址」，而是「指向 int 的指针」——类型把裸地址「语义化」了。</span>

## 1 指针的基本概念

**指针（pointer）**：一个变量，其值是一个**地址**，指向另一块存储中某个值。指针的类型指明「被指向值的类型」。

```c
int x = 42;
int *p = &x;   // p 是指针，存的是 x 的地址
*p = 43;       // 解引用：改的是 p 指向的那个值（即 x）
```

两个核心运算：

**取地址 &（address-of）**：&x 得到 x 的地址。
**解引用 *（dereference）**：*p 表示「p 指向的那个值」，可读可写。

**辨析｜易错点：** p 与 *p 是不同的东西：p 是地址（装在哪），*p 是值（指向什么）。写 *p 是对「被指者」操作，写 p 是对「指针本身」操作。把两者混淆，是一切指针 bug 的根源之一。

## 2 指针的两种语义：引用 vs 指针

现代语言把「间接寻址」分化成两种类型：

**指针（pointer）**：裸地址 + 显式算术，可空、可重指、可做算术运算。<span class="marginnote">C 指针算术 p + 1 不是「地址 +1」而是「地址 + sizeof(*p)」——指向下一个同类型元素。数组名退化为指针后，a[i] 与 *(a+i) 完全等价。这种「退化」让数组与指针在 C 里纠缠不清。</span>

**引用（reference）**：指称某对象的**别名**，语法上像普通变量，不可重指、通常不可空。C++ 引用 int& r = x; 使用后 r 就是 x 的另一个名字；Java 的对象变量、Python 的名字绑定都是「引用」语义。

| 语言 | 间接类型 | 可空 | 可重指 | 算术 |
| --- | --- | --- | --- | --- |
| C | 指针 | 是 | 是 | 是 |
| C++ | 指针 + 引用 | 指针可空 | 指针可 | 指针可 |
| Java | 引用 | 是（null） | 是 | 否 |
| Rust | 引用 & | 否（编译器保证） | 是 | 否 |
| Python | 引用（一切皆对象） | 是（None） | 是 | 否 |

## 3 指针的安全困境：悬垂与别名

指针强大的另一面是两类经典错误：

**悬垂指针（dangling pointer）**：指针指向的对象已被释放，指针仍在。解引用它读取的是已回收内存——结果未定义。

```c
int *p = malloc(sizeof(int));
free(p);       // 对象被释放，p 变成悬垂指针
*p = 10;       // 解引用已释放内存——未定义行为
```

**别名（aliasing）**：多个指针指向同一对象。通过一个指针修改，另一个指针「看见」的也被改——当优化器假设「不相交」时，就可能在编译器层面出错（违背别名规则 strict aliasing rule 即为此设）。<span class="marginnote">别名让「分析程序」变得困难：一个写操作可能影响任何与之别名的东西。这正是编译器优化与并行化最大的拦路虎，也是 Rust 所有权模型（每个值只有一个所有者）要根治的问题——第十五篇会展开。</span>

## 4 公式解析：指针与数组的等价

指针算术与数组下标在 C 中完全等价，这一事实是理解 C 内存模型的关键：

$$
a[i] \;\equiv\; *(a + i) \;\equiv\; *(i + a) \;\equiv\; i[a]
$$

三步拆解：

- **第一步，读等价**：a[i] 的编译结果就是 *(a+i)——先算地址（基址 + $i \times$ 元素大小），再解引用。四者写出来不同，机器码相同。
- **第二步，看为什么 i[a] 合法**：下标运算符本质是「加法 + 解引用」，加法可交换，故 a[i] 与 i[a] 等价——这是 C 语法的一个著名怪癖。
- **第三步，看出类型**：a + i 的加法是「指针 + 整数」，结果类型是「指向元素类型的指针」。元素大小被编译器编码进指针类型——**指针类型携带「步长」信息**，这正是 void\* 不能做算术的原因（没有步长）。

**辨析｜易错点：** 数组名退化（array decay）不是「数组就是指针」。a（整个数组）与 p（指针）不同；数组名 a 不能重新赋值而指针 p 可以。数组在大多数表达式中「退化」为指向首元素的指针，但声明 int a[10] 时它是一块真实存储。

## 5 从指针到安全语言

指针安全问题的现代解法谱系：

- **引用计数 / 垃圾回收**：Java、Python、Go 用 GC 消灭「手动释放」，从而消除悬垂指针（代价是回收延迟与开销）。
- **所有权 + 借用**：Rust 让每个堆对象只有一个所有者，借用的生命周期由编译器检查，悬垂在编译期被拒——零开销安全。<span class="marginnote">Rust 的所有权（ownership）、借用（borrowing）、生命周期（lifetime）是把「谁拥有、谁能改、能活多久」全部做进类型系统。它证明「无 GC 也无悬垂」并非乌托邦——代价是借用检查器的学习曲线。</span>
- **可空性标注**：Kotlin 的 String?、Swift 的 Optional 把「可空」从所有引用的默认状态收窄为显式标注。

## 6 指针与数据结构的经典搭配

指针的价值不在「地址」本身，而在它解锁的数据结构——C 里几乎所有动态结构都靠指针：

**链表**：每个节点存「下一个节点的地址」——next 指针。**「指针让『不连续的元素连成链』成为可能」**——数组要求连续内存，链表用指针自由连接。

**树与图**：二叉树节点含左右孩子指针——left 与 right。递归结构用递归指针定义。

**字符串与缓冲区**：C 字符串 = 字符数组 + '\0' 结尾——指针即字符串。

**函数指针**：存「函数的地址」——回调、命令分发（跳转表）。

| 结构 | 指针的角色 | 关键运算 |
| --- | --- | --- |
| 链表 | 连接节点 | next |
| 二叉树 | 连接左右孩子 | left、right |
| 字符串 | 指向字符序列 | *p、p++ |
| 函数指针 | 指向可调用代码 | (*fp)(arg) |

**辨析｜易错点：** **「指针是结构里的『胶水』，也是错误的『温床』」**——链表/树用指针连接，但「插入后忘更新指针」「释放后忘置空」让结构损坏。**「指针结构的正确性 = 每一步的指针更新都对」**——这也是为什么现代语言用「引用 + 所有权」（Rust）或「引用语义」（Java）让「连接」更安全。「看懂指针结构，就理解了 C 系数据结构的一半」——另一半是那些结构上的算法。

## 7 小结

- **指针**是存地址的变量，核心运算是取地址 & 与解引用 *；p（地址）与 *p（值）须分清。
- 指针与引用是「间接寻址」的两副面孔：指针可空、可重指、可算术；引用是别名，语法更安全。
- 指针的经典困境是**悬垂指针**与**别名**——前者因释放后仍使用，后者因多指同名。
- 现代语言的答案谱系：**GC**（消除手动释放）、**所有权 + 借用**（编译期保证）、**可空性标注**（收窄空值）。
