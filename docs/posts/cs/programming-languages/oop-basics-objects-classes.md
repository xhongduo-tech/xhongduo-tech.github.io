## 为什么从对象与类开始

第十一篇进入**面向对象程序设计（object-oriented programming, OOP）**——当代最主流（也最常被误解）的编程范式。OOP 建立在三个基本概念上：**对象**（状态 + 行为的封装单元）、**类**（对象的模板）、**消息传递**（对象间通过方法调用交互）。要理解 OOP，先得回到它的源头：1960 年代的 Simula（为仿真而设计）与 1970 年代的 Smalltalk（把它发展成完整哲学）。本文先把三个基本概念立稳——尤其「消息传递」这个常被忽略的 Smalltalk 视角，它是理解「动态绑定」的钥匙。<span class="marginnote">OOP 与 ADT 的关系：对象 = ADT + 继承 + 动态绑定。ADT 给了「封装」，OOP 在此基础上加了「类层次」与「运行时分派」。理解 OOP 前，把第十篇的 ADT 装进脑子——OOP 是它的面向对象扩展。</span>

## 1 对象：状态 + 行为

**对象（object）**：一个封装了**状态（state）**（数据/属性）与**行为（behavior）**（方法/操作）的实体。对象的状态通常私有，行为公开。

```python
class Counter:
    def __init__(self):
        self._count = 0          # 状态（私有惯例）
    def increment(self):          # 行为
        self._count += 1
    def value(self):
        return self._count
```

对象的两个本质特性：

- **同一性（identity）**：即使两个对象状态相同，它们仍是**不同**的对象（有各自的身份）。`c1 == c2` 比较的是身份还是状态，因语言而异。
- **封装**：状态对外隐藏，只能经方法访问——继承自 ADT 的核心承诺。<span class="marginnote">「同一性」是对象区别于「值」的关键：值（如整数 `5`）没有身份——两个 5 完全等价可互换；对象有身份——两个「计数器」即使计数相同也是两个独立实体（各自的状态会独立演化）。值语义 vs 引用语义的分野由此而来。</span>

## 2 类：对象的模板

**类（class）**：一组**同构对象**的模板/蓝图——定义对象的属性与方法的集合。对象是类的**实例（instance）**。

**类 vs 对象**：

- 类：定义「长什么样、能做什么」——编译期的类型。
- 对象：类的具体实例——运行期的实体（在堆上分配、经引用访问）。

```java
class Dog {                  /* 类：模板 */
    String name;
    void bark() { ... }
}
Dog d = new Dog();           /* 对象：实例 */
```

**辨析｜易错点：** 类是「类型」，对象是「值」——`Dog` 是类（定义了 `bark` 存在），`d` 是对象（真的会叫）。「类与对象混淆」是 OOP 入门第一错：类不是「一个狗」，而是「狗的定义」。**类描述集合，对象属于集合**——类比集合论里的「集合」与「元素」。

## 3 消息传递：方法调用的本质

**消息传递（message passing）**：对象之间通过「发送消息」交互——`receiver.method(args)` 就是「向 `receiver` 发送消息 `method`」。Smalltalk 的语法最直白：

```smalltalk
counter increment    "向 counter 发送 increment 消息"
```

消息传递的三个要点：

- **接收者决定响应**：消息被发送给谁，谁就决定如何响应——这引向「动态绑定」（下一节）。
- **接口即消息协议**：对象能响应哪些消息，构成它的接口。
- **封装在传递中保持**：消息的接收者内部如何实现，发送者不知道。<span class="marginnote">Smalltalk 的「一切皆对象、一切皆消息」是 OOP 的纯粹形态——连 `1 + 2` 都是「向对象 1 发送 + 消息、参数 2」。C++/Java 继承了这个思想但语法化为「方法调用」，消息传递被函数调用遮蔽——「消息」视角对理解动态绑定仍然关键：真正决定行为的是<strong>接收者</strong>。</span>

## 4 公式解析：对象的形式化

对象可以形式化为「状态 + 方法表 + 身份」的三元组：

$$
\text{obj} = \langle \text{state}, \ \text{methods}, \ \text{id} \rangle
$$

消息发送的语义：

$$
\text{send}(m, \text{obj}, a_1, \dots, a_k) = \text{apply}(\text{methods}(m, \text{obj}), \text{state}(\text{obj}), a_1, \dots, a_k)
$$

三步拆解：

- **第一步，认三元组**：对象 = 状态（私有数据）+ 方法表（可响应的操作）+ 身份（唯一标识）。
- **第二步，看分派**：发送消息 $m$ = 从对象的方法表里**查找 $m$ 对应的实现**（`methods(m, obj)`），再用「对象状态 + 实参」调用它。**方法表查找发生在运行时**——这正是「动态绑定」的形式化：实现由接收者的实际类型决定。
- **第三步，看封装**：调用方法时传入 `state(obj)`——方法可以读改状态；而外部代码**不能**直接碰 `state(obj)`（只能经方法）。**「消息 = 封装状态的唯一入口」是对象与普通记录的差别**。

**辨析｜易错点：** 「消息传递」与「函数调用」的区别：函数调用中，`f(x)` 的 `f` 是**静态已知**的名字；消息传递中，`obj.m()` 的 `m` 的实现由 `obj` 的**动态类型**决定。**「消息的响应者是谁，比消息本身更重要」**——这是 OOP 与过程式编程的根本分水岭，也是多态性的来源。

## 5 三个基本概念的关系

- **对象**：状态 + 行为 + 身份——程序运行时的实体。
- **类**：对象的模板——批量生产对象的依据，也是类型系统的载体。
- **消息传递**：对象间的交互协议——通过方法调用实现，动态绑定由此发生。

三者构成 OOP 的最小内核：**用类造对象，对象间传消息，消息触发行为**。后续所有 OOP 主题（继承、多态、接口）都是在这三个概念上生长。

<span class="marginnote">OOP 家族的三支源流：Simula（类 + 继承，为仿真建模）、Smalltalk（纯对象 + 消息，为交互设计）、以及后来 C++/Java 的「混合派」（类 + 值语义 + 函数库）。理解「对象/类/消息」这三个最小概念，再去看继承与多态，就不会被各语言的表面语法绕晕。</span>

## 6 小结

- **对象** = 状态 + 行为 + 身份；状态私有、行为公开，是 ADT 的面向对象形态。
- **类** = 对象的模板/蓝图；类描述集合、对象属于集合，「类 ≠ 对象」。
- **消息传递** = 对象间交互；响应者（接收者）决定行为——动态绑定的哲学基础。
- 对象形式化 = `⟨state, methods, id⟩`；消息分派在运行时查方法表，是 OOP 与过程式编程的分水岭。
