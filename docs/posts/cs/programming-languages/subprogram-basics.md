## 为什么从子程序开始

控制结构组织语句，**子程序（subprogram）**组织程序本身——它是「把一段代码封装成可复用单元」的最古老机制。函数、过程、方法、lambda，全都是子程序的不同形态。塞贝斯塔用一个抽象模型概括子程序的本质：**子程序是一段带「头」的代码，头说明参数与返回类型，调用时建立新的活动记录（activation record）**。理解子程序，就理解了「抽象、复用、调用栈、递归、参数传递」这一整串后续主题的地基。<span class="marginnote">「子程序」一词涵盖函数（有返回值）与过程（无返回值，C 里都是函数）。面向对象里「方法」是绑定到对象/类的子程序。现代语言里还有「一等函数」（可作为值传递的子程序，第九篇末的闭包将展开）。</span>

## 1 子程序的两个基本特性

塞贝斯塔指出，子程序区别于「一段代码」的核心是**控制抽象（control abstraction）**：

**每个子程序只有一个入口**（进入子程序只能从开头开始）；
**调用者暂停执行，被调子程序执行，完成后返回调用者**（并带回控制权与可能的返回值）。

这两条让子程序成为「可替换的黑盒」：调用者只关心「输入 → 输出」，不关心内部实现。<span class="marginnote">「一个入口」是子程序的纪律：C 允许 `goto` 跳进函数内部？不——C 禁止跨函数 goto（标签是函数局部的）。「从开头进入」保证子程序的状态初始化总是发生，这是正确性的基础。</span>

## 2 子程序的头与定义

**子程序头（subprogram header）**：声明名字、参数列表、返回类型——它是子程序的「接口」。

```c
int max(int a, int b);    // 头：返回类型 + 名字 + 参数列表
```

**子程序定义（definition）**：头 + 体（实现）。**子程序声明（declaration）**：只有头（告诉编译器「存在这么个东西」，实现在别处或之后）——C 的前向声明、头文件模式正是靠这个。

**辨析｜易错点：** 定义与声明的区别：**定义分配代码与存储**，**声明只声明接口**。C 里 `int max(int a, int b);` 是声明，`int max(int a, int b) { ... }` 是定义。链接时「声明了但没定义」→ 链接错误；「定义了两次」→ 重复定义错误。**「声明 ≠ 定义」是 C/C++ 新手第一道门槛**。

## 3 形参与实参：接口的通道

**形参（formal parameter）**：子程序定义中的参数名，占位符。**实参（actual parameter）**：调用时传入的具体值/引用。

```c
int max(int a, int b) {   // a、b 是形参
    return a > b ? a : b;
}

max(3, 7);                // 3、7 是实参
```

**参数协议（parameter protocol）**：调用时「实参 ↔ 形参」的对应规则——按位置、按名字、按默认值（下一节专文）。

子程序的调用机制（后续详讲）：调用建立**活动记录（activation record）**——存放实参、局部变量、返回地址的栈帧；返回时销毁。

## 4 公式解析：子程序调用的抽象模型

子程序调用可以用「栈帧」模型精确刻画。设子程序 $P$ 有形参 $f_1, \dots, f_k$ 与局部变量 $l_1, \dots, l_m$，调用 $P(a_1, \dots, a_k)$ 建立活动记录 $AR$：

$$
AR(P) = \langle \text{return addr}, \ f_1 \mapsto a_1, \dots, f_k \mapsto a_k, \ l_1, \dots, l_m \rangle
$$

三步拆解：

- **第一步，认活动记录**：一次调用生成一个活动记录——包含返回地址（调用结束后回哪）、实参到形参的映射、以及局部变量的槽位。
- **第二步，看栈的嵌套**：调用栈上，调用者的 AR 在下，被调者的 AR 在上；返回时被调者 AR 弹出——**LIFO 恰好对应「后调用先返回」**，这正是递归得以实现的结构基础。
- **第三步，看重入（reentrancy）**：递归调用时同一子程序有**多个活动记录**并存（各自独立的局部变量）——`fact(3)` 调用 `fact(2)` 时两帧并存。**「一次调用 = 一个 AR」让局部变量天然「每次调用独立」**。

**辨析｜易错点：** 形参的「占位」性质：形参是**定义时**的名字，实参是**调用时**的值——两者绑定发生在调用时刻。递归中形参的值在每一帧独立（`fact` 的 `n` 在每帧不同）。**「形参是局部的」**：每次调用，形参都重新绑定到新的实参，不影响外层帧的同名形参。

## 5 子程序的种类与语言形态

| 类别 | 特点 | 例子 |
| --- | --- | --- |
| 函数（function） | 有返回值，表达式里使用 | `int max(...)`（C） |
| 过程（procedure） | 无返回值，仅执行副作用 | `def f(): ...`（Python） |
| 方法（method） | 绑定到对象/类，隐式 `this` | `void push(int x)`（Java） |
| 运算符重载 | 运算符也是子程序 | `operator+`（C++ 运算符重载） |
| 泛型子程序 | 参数化类型 | `template<typename T>`（C++ 模板） |
| 一等函数 | 可作为值传递、返回 | `\x -> x + 1`（Haskell） |

<span class="marginnote">「过程 vs 函数」的分野正在消失：C 里 `void` 函数就是过程；Python 一切皆函数。但「函数」的纯度（无副作用）在函数式语言里重新变成设计核心（第十二篇）。「子程序」作为统一概念的价值，在于它把这些形态的共同骨架（头 + 体 + 调用 + 返回）一次讲清。</span>

## 6 递归：子程序的自我调用

子程序最深刻的能力是**递归（recursion）**——函数调用自身。它是「重复」的函数式表达（对比命令式循环）：

**递归的两个部分**：

```python
def fact(n):
    if n <= 1:                 # 基线（base case）：递归终止
        return 1
    return n * fact(n - 1)     # 递推（recursive case）：向基线逼近
```

- **基线（base case）**：递归终止的条件——不满足就无限递归（栈溢出）。
- **递推（recursive case）**：把问题缩小，向基线逼近。

**递归的机制**：每次递归调用**建立新的活动记录**（回顾本章 §4）——`fact(3)` 调用 `fact(2)`，两层帧并存，各帧的 `n` 独立。

**递归 vs 迭代**：

| 维度 | 递归 | 迭代 |
| --- | --- | --- |
| 表达 | 函数调用自身 | 循环 + 变量 |
| 栈 | 每层一帧（O(n)） | 常数栈 |
| 适合 | 分治、树、链表 | 简单计数 |
| 可读性 | 声明式（像数学定义） | 命令式 |

**辨析｜易错点：** **「递归不终止 = 栈溢出」**：基线缺失或递推不缩小问题，递归无限进行——栈溢出（stack overflow）。**「写递归先写基线」**是铁律。且深递归（> 几千层）可能爆栈——尾递归 + 尾调用优化（前面函数式篇讲过）可把递归变 O(1) 栈。**「递归是思想的工具，栈是它的物理约束」**——理解这两面，递归就从「魔法」变成「清晰」。

## 7 小结

- **子程序**是「头 + 体」的可复用代码单元，核心特性是**单入口 + 调用/返回**的控制抽象。
- **定义**（头 + 实现）与**声明**（仅接口）必须区分，链接时「缺定义」或「重定义」都是错误。
- **形参**是占位符，**实参**是调用时的值；两者绑定发生在调用时刻。
- 调用建立**活动记录**（栈帧），递归靠「一帧一局部」实现；子程序的种类覆盖函数/过程/方法/泛型/一等函数。
