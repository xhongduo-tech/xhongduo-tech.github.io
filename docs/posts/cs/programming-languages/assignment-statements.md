## 为什么从赋值语句开始

表达式求值产出值，而让值「留下来」靠**赋值语句（assignment statement）**——命令式语言的标志性构造。它把右侧表达式的值存入左侧变量（或其指向的存储）。看似平凡，赋值却有极深的设计纹理：`=` 作为赋值符的语法演进、`+=` 这类复合赋值是否引入「读-改-写」的歧义、赋值在表达式里能否当值用、以及「多重赋值」「交换赋值」等扩展形式。这一节把这些细节摊开——它们共同决定了一门命令式语言的「手感」。<span class="marginnote">赋值与「绑定」的分野要再强调一次：`let`（Rust/函数式）是<strong>声明绑定</strong>（引入新名字），`=`（C/Python 对已声明变量）是<strong>赋值</strong>（更新已有名字的值）。前者创建，后者更新——很多语言把两者用不同关键字区分（`let` vs `=`），正是为了划清这条线。</span>

## 1 赋值的基本形式

**赋值语句（assignment statement）**：**`target = expr;`**，把右侧表达式的值赋给左侧目标（变量、数组元素、字段等「可寻址」位置）。

```c
int x;
x = 5;               // 基本赋值：把字面量 5 存入 x
int arr[4];
arr[2] = x;          // 赋给数组元素
p.x = 10;            // 赋给字段
```

左侧必须是**左值（lvalue）**——有地址、可写的位置（第六篇讲过：左值 = 有地址，未必可写，如 `const` 变量不可作赋值目标）。

## 2 赋值符号的历史与语法分歧

**`=` 作为赋值符**是 C 系的传统，但它引发两个长期争论：

**与相等 `==` 的混淆**：**`if (x = 1)`** 在 C 里是「把 1 赋给 x，条件永真」——赋值误写为比较的经典 bug。现代编译器对「条件内的赋值」发出警告；有些语言直接禁止。
**非 C 系的选择**：Pascal 用 `:=`、Ada 用 `:=`、Python 用 `=` 而相等用 `==`、Go 用 `:=` 表示「声明 + 赋值」、Rust 用 `let` 声明、`=` 对可变变量赋值。

<span class="marginnote">Go 的 `:=`（短变量声明）与 `=`（赋值）的区分是设计巧思：`:=` 既声明又赋值（且类型推导），`=` 只更新。这解决了「声明与赋值要不要同一符号」的争论——答案可以是「两个符号、各司其职」。</span>

## 3 复合赋值：简洁与歧义的权衡

**复合赋值（compound assignment）**：把「取左值 → 运算 → 存回」压缩成一个运算符：**`x += 1`** 等价于 **`x = x + 1`**。

| 运算符 | 等价展开 | 说明 |
| --- | --- | --- |
| `+=` | `x = x + y` | 加法复合 |
| `-=` | `x = x - y` | 减法复合 |
| `*=` | `x = x * y` | 乘法复合 |
| `/=` | `x = x / y` | 除法复合 |
| `<<=` | `x = x << n` | 移位复合 |

**辨析｜易错点：** 复合赋值对**左值求值一次还是两次**，在 C 里存在语义分歧。**`a[i++] += 1`** 等价于 **`a[i++] = a[i++] + 1`**（i 自增两次）还是「i 只自增一次」？C 标准规定 **`+=`** 的左值**只求值一次**——所以 **`a[i++] += 1`** 中 **`i++`** 只发生一次，这与「机械展开为 **`a[i++] = a[i++] + 1`**」不同。**复合赋值不是简单的语法糖**，它有独立的求值语义。

## 4 赋值作为表达式：赋值表达式的命运

赋值语句「是否产生值、能否嵌入表达式」是另一个设计分歧：

**C/Java/C++**：赋值是**表达式**，产生「被赋的值」——**`x = y = 5`** 链式赋值合法；**`while ((c = getchar()) != EOF)`** 把赋值嵌进条件。
**Python**：赋值是**语句**，不产生值——**`a = b = c`** 仍是合法（链式是特例），但 **`if x = 1:`** 语法错误。
**Rust**：赋值表达式返回**单元类型 `()`**——**`let _ = (x = 5);`** 中 **`x = 5`** 是 **`()`**，刻意让「赋值当值用」变得无意义。

<span class="marginnote">Rust 的「赋值返回 `()`」是一种刻意设计：它让 `<strong>`if x = 5 这类错误在类型层即被拒绝（条件必须是 `bool`，而 `()` 不是）。「让危险写法在语法/类型层不可表达」，是现代语言对抗 C 系历史包袱的方式。</span>

## 5 公式解析：赋值的语义模型

赋值可以严格定义为「更新存储」：

$$
\sigma' = \sigma[\text{addr}(L) \mapsto \mathcal{E}(E)(\sigma)]
$$

复合赋值：

$$
\sigma' = \sigma[\text{addr}(L) \mapsto \text{op}\big(\sigma[\text{addr}(L)],\ \mathcal{E}(E)(\sigma)\big)]
$$

三步拆解：

- **第一步，基本赋值**：新存储 $\sigma'$ 是旧存储 $\sigma$ 在「**`addr(L)`** 的地址处」更新为「**`ℰ(E)(σ)`** 在旧存储下求的值」——先算右侧（读旧 $\sigma$），再写左侧。
- **第二步，复合赋值**：**`op`** 作用于「**`L`** 的当前值」（$\sigma[\text{addr}(L)]$）与「**`E`** 的值」，结果写回同一地址。**读旧值、算新值、写回**三步在一处完成。
- **第三步，看求值时机**：两条公式都强调右侧**在旧存储下**求值——**`ℰ(E)(σ)`** 读的是**赋值前**的存储。这保证了「先读后写」的顺序，是赋值语义的基石。

**辨析｜易错点：** 「多重赋值」**`a, b = b, a`**（Python 交换）看似神奇，实质是「**先整体求右侧元组**、再依次赋给左侧」——右侧在赋值前一次性求值，因此交换安全。若按「逐个赋值」理解 **`a, b = b, a`** 会得到错误结果（两次都取同一值）。

## 6 赋值与不可变性：语言哲学的分野

赋值语句的命运，映照出语言对「可变状态」的态度——这是命令式与函数式哲学的分水岭：

**命令式**（C/Java/Python）：赋值是主角——「程序 = 一系列赋值改变状态」。变量默认可变。

**不可变优先**（Rust/函数式）：赋值（绑定）创造值，变量默认不可变——**`let`**（Rust）、**`val`**/**`let`** 不可变绑定。**「默认不可变」**把「可变」变成需要显式声明的例外（Rust 的 **`mut`**）。

**赋值的代价**：每个可变变量都是「状态点」——并发下需要同步（竞态来源）、调试时要知道「最后一次赋值在哪」。**「可变状态越少，程序越容易推理」**——这是不可变性哲学的核心论据。

| 语言 | 变量默认 | 可变性 |
| --- | --- | --- |
| C/Java/Python | 可变 | 默认 |
| Rust | 不可变（`let`） | `mut` 显式 |
| Haskell | 不可变 | 无（纯函数） |
| Swift | 不可变（`let`） | `var` 显式 |

**辨析｜易错点：** **「不可变 ≠ 不能变」**——Rust 的 `mut`、Swift 的 `var` 都可变；「默认不可变」是「把可变性设为需要显式声明」。「默认不可变 + 显式可变」是现代语言对「赋值副作用」的驯化——**「让状态变更显式可见」**。赋值本身没有消失，只是从「默认」变成「显式」——这既保留命令式的表达力，又给推理与并发留出安全空间。

## 7 小结

- **赋值语句** `target = expr` 把右值存入左值；左侧必须是可寻址的**左值**。
- 赋值符的语法（`=`/`:=`/`let`+`=`）反映「声明与赋值是否分开」的设计哲学。
- **复合赋值** `+=` 是「读-改-写」的压缩；C 中左值只求值一次，不是纯语法糖。
- 赋值是否「作为表达式」因语言而异；Rust 用「返回 `()`」让危险写法不可表达。
- 语义模型：右侧在**旧存储**下求值、再更新左侧地址；多重赋值先整体求右侧。
