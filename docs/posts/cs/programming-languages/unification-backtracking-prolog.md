## 为什么从合一与回溯开始

前几节把 Prolog 的推理机制交代了大致轮廓；这一节深挖它的两个执行引擎：**合一（unification）**——让项「匹配并绑定」的算法，以及**回溯（backtracking）**——搜索失败时「回头换路」的机制。这两者让 Prolog 的程序「自动搜索解」；但它们也带来 Prolog 著名的缺陷：**不完备（可能死循环）、非逻辑特性（cut、否定）、以及低效**。理解优点与缺陷，才能真正驾驭 Prolog——它是一门「好用但需要知道何时会翻车」的语言。<span class="marginnote">Prolog 的执行可以一句话概括：<strong>合一找匹配，回溯找替代，深度优先搜遍解空间</strong>。这三者的组合让「声明式程序」可运行，也让「声明式语义」与「过程式行为」出现鸿沟——Prolog 的缺陷几乎都来自这道鸿沟。</span>

## 1 合一：项匹配与绑定

**合一（unification）**：求两个项的一个代换，使它们**完全相同**。

```prolog
?- X = alice.              % X 绑定为 alice
?- likes(alice, X) = likes(alice, music).   % X = music
?- f(X, b) = f(a, Y).      % X = a, Y = b
```

合一规则：

- 变量与任何项合一——绑定变量（`X = alice`）。
- 复合项须**函子相同、参数逐一合一**。
- 常量只与自身合一（`alice = bob` 失败）。

**合一 vs 赋值**：`X = alice` 不是赋值——是**约束**：X 被绑定为 alice，且此绑定参与后续全部求解（可逆、可传播）。<span class="marginnote">Prolog 的 `=` 是「合一」而非「赋值」——它建立「两边相同的约束」。`X = Y` 后 `X` 与 `Y` 共享绑定；`X = 5, X = 5` 成功，`X = 5, X = 6` 失败。「变量一旦绑定不可更改」是逻辑变量的核心——它让程序没有「可变状态」，只有「约束累积」。</span>

## 2 回溯：搜索失败后回头

**回溯（backtracking）**：当某个选择导致失败，Prolog **撤销最近的绑定**，回到上一个选择点，尝试下一条路。

```prolog
likes(alice, music).  likes(bob, sports).  likes(alice, books).

?- likes(alice, X).
X = music ;      % 用户输入 ; 要求更多解
X = books ;      % 回溯到第二个匹配
false.           % 没有更多
```

回溯的过程：匹配 `likes(alice, X)` 用第一条事实得 `X=music`；用户要求更多 → **撤销 `X=music`** → 尝试下一条 `likes(bob,sports)`（失败，`alice`≠`bob`）→ 再试 `likes(alice,books)` 得 `X=books`。**「深度优先 + 失败即回退」**是 Prolog 的搜索策略。<span class="marginnote">回溯 = 「系统性的试错」：它保证「若存在解，深度优先搜索能找到」（有终止条件时），且穷举所有解。代价是<strong>指数级搜索空间</strong>——组合爆炸问题（如旅行商）会让回溯跑到天荒地老。Prolog 程序员要用「剪枝（cut）」或改规则顺序来控制搜索成本。</span>

## 3 缺陷一：不完备与死循环

Prolog 深度优先搜索**可能不终止**——即使解存在。最典型的是**左递归**：

```prolog
ancestor(X, Z) :- ancestor(X, Y), parent(Y, Z).   % 左递归！
ancestor(X, Y) :- parent(X, Y).
parent(alice, bob).

?- ancestor(alice, X).   % 死循环！
```

第一条规则的第一个前提 `ancestor(X,Y)` 与规则头相同——无限递归展开，永不触底。<span class="marginnote">「左递归」是 Prolog 的头号陷阱：规则体<strong>第一个</strong>前提与规则头同谓词 → 深度优先永远先展开自己。逻辑上这些子句正确（声明式语义成立），但 Prolog 的过程式执行不完备。「把递归前提放后面」是常见的工程对策——`ancestor(X,Z) :- parent(X,Y), ancestor(Y,Z).`（右递归）可终止。</span>

**辨析｜易错点：** 不完备 ≠ 程序错。上述左递归程序**逻辑上正确**（能推出所有 ancestor 关系），但 Prolog 找不到——**「逻辑真」与「可计算真」在 Prolog 里分离**。这是「声明式理想」与「实现现实」的落差：Prolog 不是完整的定理证明器，只是一个「可实用的搜索器」。

## 4 缺陷二：cut 与否定——非逻辑的特性

**cut（`!`）**：Prolog 的「剪枝」操作符——**提交选择，禁止回溯**：

```prolog
max(X, Y, X) :- X >= Y, !.   % 一旦到这，不再尝试下一条
max(X, Y, Y).
```

`!` 的效果：跳过后续子句、锁定已做的绑定。它提升效率（避免无用回溯）、实现「否则」逻辑，但**破坏声明式语义**——程序的行为依赖执行顺序，不再是「纯逻辑」。

**否定（`\+`）**：Prolog 的否定是「**无法证明**」而非「为假」：

```prolog
\+ human(X)    % 问「无法证明 human(X)」——不是「X 不是人」！
```

这源自**封闭世界假设**——未证明即为假。它带来「否定即失败（negation as failure）」语义：`\+` 对含自由变量 X 的目标几乎总是失败或行为怪异。<span class="marginnote">`!` 与 `\+` 是 Prolog 的「过程性后门」——它们让程序员能控制搜索（效率、否则逻辑），代价是「声明式纯度」受损。理解它们的时机语义，是 Prolog 进阶的分水岭。「cut 让 Prolog 实用，也让 Prolog 不再是纯逻辑」。</span>

## 5 公式解析：回溯的实现模型

回溯可以用「搜索树 + 选择点」建模。Prolog 的执行 = 深度优先遍历**搜索树**，节点是「目标列表」，边是「合一某个子句」：

$$
\text{solve}(G) = \text{DFS over } \text{search-tree}(G), \quad \text{叶子 } = \text{空目标（成功）或死路（失败）}
$$

以 `?- likes(alice, X)` 为例：

```
目标: likes(alice, X)
├─ 与 fact1 合一 → X=music（成功，输出；回溯则撤销）
├─ 与 fact2 合一 → 失败（alice≠bob）
└─ 与 fact3 合一 → X=books（成功）
```

三步拆解：

- **第一步，选择点**：每个「多子句可合一」的节点是一个**选择点**——DFS 先走第一条，失败/回溯时走下一条。
- **第二步，回溯撤销**：回到选择点时，**撤销**进入该分支前做的全部绑定——`X=music` 被撤销，重新绑定。
- **第三步，穷尽**：DFS 遍历完整棵树 = 找到全部解；「无路可走」= 失败。**「回溯 = 搜索树上的深度优先 + 状态撤销」**——这是 Prolog 执行的完整图景。

**辨析｜易错点：** 回溯撤销的是**绑定**，不是「变量值」——逻辑变量没有「可变值」，只有「绑定状态」。`X=music` 后 X 被锁定；回溯 = 解锁 + 尝试另一绑定。**「逻辑变量不可修改，只可绑定与解绑」**——这与命令式「变量可改值」根本不同。

## 6 小结

- **合一** = 求使项相同的代换；`=` 是约束（可逆、传播、不可更改）而非赋值。
- **回溯** = 深度优先搜索 + 失败撤销绑定——穷举解空间，但可能指数爆炸。
- **缺陷一：不完备**——左递归等导致死循环；「逻辑真」与「可计算真」分离。
- **缺陷二：非逻辑特性**——`cut`（禁止回溯）与 `\+`（否定即失败）破坏声明式纯度，但让 Prolog 实用。
