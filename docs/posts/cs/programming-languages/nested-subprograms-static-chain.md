## 为什么从嵌套子程序开始

第六篇讲过词法作用域：内层函数可以访问外层函数的变量。这一节看它的**实现机制**：编译器如何让嵌套子程序访问到「外层函数里的局部变量」？答案是一张指针链——**静态链（static chain）**。理解静态链，就理解了「非局部变量访问」的成本、闭包的雏形、以及 Pascal/Ada 时代「嵌套函数」的实现智慧。虽然现代语言多用更复杂的「显示表（display）」或「环境闭包」，但静态链是理解这一切的起点。<span class="marginnote">问题的本质：外层函数的活动记录（栈帧）在内层函数运行时<strong>还活着</strong>（因为外层还没返回），但内层函数怎么找到它？静态链在每个帧里存一个「指向词法外层帧」的指针——顺着链走，就能到达任何词法祖先的帧。</span>

## 1 非局部变量的访问问题

**非局部变量（nonlocal variable）**：在子程序里使用、但声明在**词法外层**子程序中的变量。

```pascal
procedure Outer;
    var x : integer;
    procedure Inner;
    begin
        x := x + 1;      // 非局部变量：x 声明在 Outer 里
    end;
begin
    x := 0;
    Inner;
end;
```

`Inner` 的帧里没有 `x`——它必须找到 `Outer` 的帧。**问题**：当 `Inner` 运行时，`Outer` 的帧还压在调用栈的下方，怎么定位它？

普通局部变量在**自己的帧**里（通过帧基址 + 偏移）；非局部变量在**词法祖先的帧**里——需要一条「从当前帧到祖先帧」的路径。

## 2 静态链：指向词法外层的指针

**静态链（static chain）**：每个活动记录里存一个指针，指向**词法上直接包围它的子程序**的活动记录。

```
调用栈（自顶向下）              静态链
+------------------+       +------------------+
|  Inner 的活动记录 | -----> |  Outer 的活动记录 |
+------------------+       +------------------+
   x 不在此帧                     x 在此帧（按偏移取）
```

访问非局部变量 `x`：从当前帧沿静态链走**若干层**（层数 = 当前子程序到声明该变量子程序的词法距离），在目标帧里按偏移取变量。<span class="marginnote">词法距离是<strong>编译期常量</strong>——`Inner` 里访问 `Outer` 的变量，距离恒为 1 层。因此「走多少层链」在编译期就确定，运行期只需循环解指针。</span>

## 3 公式解析：静态链的寻址

设子程序 $S$ 的词法深度为 $d(S)$（main = 0），$S$ 访问声明于深度 $d'$ 的非局部变量 $v$。静态链寻址：

$$
\text{寻址}(S, v) = \text{从 } S \text{ 的帧沿链走 } (d(S) - d') \text{ 层，到达深度 } d' \text{ 的帧，再取偏移 } \text{offset}(v)
$$

三步拆解：

- **第一步，算层差**：$d(S) - d'$ 是「从当前深度到目标深度的层数差」——编译期可算（词法深度都是静态的）。
- **第二步，沿链走**：运行时从当前帧出发，沿静态链走 $d(S) - d'$ 步——每一步解引用一次指针。层差越大，访问越慢。
- **第三步，取偏移**：到达目标帧后，帧基址 + `offset(v)` 取出变量。**「层差 + 偏移」就是非局部访问的全部**——层差决定走几步链，偏移决定在帧内取哪。

**辨析｜易错点：** 静态链与**动态链**（call chain）的区别：静态链沿「词法嵌套」走，动态链沿「调用顺序」走。`Inner` 可以由 `Helper` 调用（动态链指向 helper），但它的静态链**仍指向 outer**（词法结构固定）。**「静态链看代码，动态链看调用」**——这是两条独立的链。

## 4 静态链的开销与替代方案

静态链的代价：

- **访问时间依赖深度**：非局部变量访问是 $O(d(S) - d')$，深度大时慢。
- **链维护**：每次调用要正确设置新帧的静态链（指向词法父帧）。

替代方案——**显示表（display）**：维护一个数组 `display`，第 $d$ 项指向「当前栈中该深度的最内层帧」。访问深度 $d'$ 的变量 = `display[d']`——**$O(1)$ 访问**，用空间换时间。<span class="marginnote">显示表把「沿链走的 $O(d)$ 步」换成「一次数组索引」——对深度大的程序（如 Pascal 深度嵌套）显著更快。Ada 的编译实现常用显示表。这是「查表 vs 遍历」的经典权衡：遍历省空间、查表省时间。</span>

## 5 从静态链到闭包

静态链思想在现代语言中的直接后裔是**闭包（closure）**：嵌套函数「捕获」外层变量，靠的正是「记住词法外层帧」的机制——闭包 = 函数 + 它沿静态链可达的环境。

```python
def make_counter():
    count = 0              # 被闭包捕获的外层变量
    def inc():
        nonlocal count     # 修改外层变量
        count += 1
        return count
    return inc             # 返回闭包：函数 inc + 环境 {count}
```

当 `inc` 被**返回**（逃出 `make_counter`），`make_counter` 的帧本应销毁——但闭包需要它。解决：把被捕获的环境**转移到堆上**（而非留在栈），闭包持有一个指向该环境的指针。<span class="marginnote">这正是「静态链」从栈迁移到堆的变体：函数式语言与 Python/Rust（闭包）都把「捕获环境」存到堆。静态链解决「运行中访问」，闭包机制解决「返回后仍访问」——后者是前者的延展。</span>

**辨析｜易错点：** 静态链 vs 闭包的环境：静态链是**指向栈上帧**的指针（帧销毁即失效），闭包的环境是**独立堆对象**（寿命由引用决定）。**「栈上的静态链」用于运行中的嵌套访问，「堆上的环境」用于逃逸的闭包**——前者生命周期嵌套、后者可任意流动。

## 6 现代语言对嵌套函数的处理

嵌套函数在现代语言里的支持程度各异——理解各语言的「能/不能」：

**支持嵌套**：Python（def 内 def）、JS（函数内函数）、Rust（闭包、fn 内 fn）、Pascal/Ada（完整嵌套）、Go（闭包）。这些语言里「函数内定义函数」是日常。

**不支持嵌套**：C（函数只能在文件顶层）、Java 8 前（用匿名类替代）。C 的「函数内函数」用「文件内 static 函数 + 全局变量传参」模拟——笨拙但可行。

**嵌套 + 非局部访问的差异**：即使支持嵌套，各语言对「内层访问外层变量」的支持也不同——Python 要 `nonlocal` 才能改外层变量（读无需）；JS 直接捕获；Rust 靠闭包捕获。

| 语言 | 嵌套函数 | 访问外层 | 改外层 |
| --- | --- | --- | --- |
| Python | ✅ | ✅（读） | `nonlocal` |
| JS | ✅ | ✅ | ✅（词法捕获） |
| Rust | ✅（闭包） | ✅（借用/move） | `FnMut`/`move` |
| C | ❌ | — | — |
| Java | 8+ 的 lambda | ✅（effectively final） | ❌ |

**辨析｜易错点：** **「嵌套函数的『捕获』各语言语义不同」**——Python 捕获变量（默认读、`nonlocal` 写）；Java lambda 只捕获 **effectively final**（不可改）；Rust 闭包按借用或 move。**「同是嵌套函数，『能捕获什么、能改吗』大不相同」**——写跨语言代码时，「内层能否修改外层变量」必须先确认。「嵌套函数 + 捕获」是现代语言的标配能力，但细节差异是移植的暗坑。

## 7 小结

- **嵌套子程序**让内层函数可访问词法外层的非局部变量。
- **静态链**：每个帧存指向词法父帧的指针；访问非局部变量 = 沿链走「层差」步 + 帧内偏移。
- 层差是**编译期常量**，运行期开销 $O(\text{深度})$；**显示表**用查表把访问降到 $O(1)$。
- 静态链是**闭包**的雏形：逃逸的嵌套函数把捕获环境搬到堆，形成「函数 + 环境」的闭包。
