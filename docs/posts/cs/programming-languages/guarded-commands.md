## 为什么从卫式命令开始

迪杰斯特拉在批判 goto 之后，没有停在「三种结构」的保守方案上，而是向前推进了一步：如果 `if/else` 要求条件「二选一」，能不能让语言表达「从所有满足条件的分支中选一个」？答案是**卫式命令（guarded command）**——每条分支带一个**卫（guard）**（布尔条件），求值后**所有满足卫的分支都可执行**，系统任选其一。这带来**非确定性（nondeterminism）**：同一程序多次运行，选择的分支可能不同，但所有选择都「正确」。这是并发编程、形式化验证、以及现代模式匹配「多模式可选」思想的先驱。<span class="marginnote">非确定性不是「随机」：它意味着「规范只约束『哪些结果可接受』，不规定『选哪个』」。这让程序规范更宽松、实现更自由——并发调度、分布式系统里「顺序不保证但结果保证」正是这种思想。</span>

## 1 卫式命令的基本形式

**卫式命令（guarded command）**：`guard -> command`，其中 `guard` 是布尔表达式，`command` 是语句。只有当 `guard` 为真时，`command` 才可执行。

迪杰斯特拉的**卫式命令语言（GCL）**有两个核心构造：

**卫式选择（guarded selection）**：

```
if
    B1 -> S1
    B2 -> S2
    ...
    Bn -> Sn
fi
```

语义：求值所有卫 $B_i$；**任意一个为真者**的分支可执行；若无任何卫为真，**程序失败/卡住**（与 C 的 switch 不同，不是静默跳过）。<span class="marginnote">GCL 的 `if` 比 C 的 `if` 严格得多：C 的 if-else 要求「必有 else」或默认跳过，GCL 的 if 在「无卫为真」时报错——因为它把「所有情况都被覆盖」当作正确性的前提。这是「把 bug 变错误」的设计哲学。</span>

**卫式循环（guarded repetition）**：

```
do
    B1 -> S1
    B2 -> S2
    ...
    Bn -> Sn
od
```

语义：反复执行「某个卫为真」的分支；当所有卫为假时循环结束。

## 2 非确定性：多分支可选

卫式命令的核心特征：**若有多个卫同时为真，选择哪一个？GCL 说不保证**——执行时任意选一个。

```python
# 非确定性选择两个递减分支之一（伪代码示意 GCL）
if
    x > 0 -> x = x - 1
    x > 0 -> x = x - 2
fi
```

`x` 初始为 5 时，两条卫都真——可能减 1 或减 2，结果不同但「都合法」。<span class="marginnote">非确定性给「程序正确性」带来了新的层次：不是「输出唯一确定」，而是「所有可能的输出都满足规范」。这在并发中尤为重要——两个线程交替执行的顺序不固定，但只要「任何交替都正确」，程序就是正确的。</span>

**辨析｜易错点：** 非确定性 ≠ 随机性。随机需要「概率分布」（抛硬币），非确定性只要求「任意选择都正确」。GCL 的非确定性是**自由选择**（specification-level），实现时可以任选策略；而随机是**概率选择**（implementation-level）。把「非确定」当「随机」是实现上的误区。

## 3 卫式命令与并发：Dijkstra 的深层动机

卫式命令语言的设计动机之一就是**并发正确性**。迪杰斯特拉发现：并发程序的「交错顺序」是天然非确定的——谁先谁后不由程序决定。与其假装顺序确定，不如把「任意顺序都正确」作为目标。

**守卫与并发同步的对应**：

- `B -> S` 中卫 `B` 相当于「当条件满足时才能执行 S」——这正是**条件同步（conditional synchronization）**的思想。
- 多个卫同时为真 = 多个线程同时可推进——调度器任选。
- 卫全假时卡住 = 并发死锁的规范表达。

<span class="marginnote">这一思想后来进入 <strong>CSP（通信顺序进程）</strong>与 <strong>Ada 的选择接受（selective accept）</strong>：Ada 的 `select ... when guard => accept ...` 正是卫式命令的并发实现——守卫控制「何时可以接受某消息」。第十四篇讲并发时会重逢。</span>

## 4 公式解析：卫式选择的语义

卫式选择可以用操作语义规则刻画。设分支 $B_i \to S_i$，卫式选择 $\text{if} \square_i (B_i \to S_i) \text{fi}$ 的转移：

$$
\frac{B_i(\sigma) = \text{true} \quad \langle S_i, \sigma \rangle \Rightarrow \sigma'}{\langle \text{if}\ \square_j (B_j \to S_j)\ \text{fi},\ \sigma \rangle \Rightarrow \sigma'}
$$

三步拆解：

- **第一步，读前提**：对**任意**满足 $B_i(\sigma)$ 为真的分支 $i$，该分支的语句 $S_i$ 都能执行——横线规则对每个「卫真」的分支都成立。
- **第二步，看非确定性来源**：多条规则同时可应用（多个 $i$ 卫真）时，**没有规则规定选哪条**——操作语义的「关系而非函数」在此显形：一个状态有多个可能的下一状态。
- **第三步，看失败条件**：若所有 $B_i$ 都为假，则没有规则可应用——**程序卡住**。GCL 把「无分支可走」当作错误（等价于断言失败），而不是像 C 那样静默继续。

**辨析｜易错点：** 卫式选择与 `switch` 的关键区别：switch 的匹配值**唯一确定**（一次取值比对），卫式选择的分支**可多个同时满足**（每个卫独立判断）。**「多选一但必须选对」与「精确二选一」是两种不同的选择语义**——卫式命令表达前者，条件语句表达后者。

## 5 卫式思想的现代遗产

- **并发语言**：Ada 的选择接受、CSP 的 `alt`、Go 的 `select`——「从多个可用通信中任选一个」直接继承卫式命令。
- **模式匹配的守卫**：Rust/Swift 的 `match` 支持**守卫（guard）**`match x { n if n > 0 => ... }`——在模式之上叠加布尔条件，是卫式思想的模式匹配形态。<span class="marginnote">Rust 的 `match` 守卫、Python 3.10 的 `match ... if` 让「条件 + 匹配」合一——现代语言把卫式命令的「多条件可选」能力嫁接到模式匹配上，是两种传统的最新交汇。</span>
- **形式化验证**：GCL 是证明并发程序正确性的理论工具（Dijkstra 的最弱前置条件演算正是定义在 GCL 上）。

## 6 小结

- **卫式命令** = `guard -> command`，只有卫为真才能执行该分支。
- **卫式选择/循环**：从所有满足卫的分支中任选其一；无卫为真时失败。
- **非确定性**是「任意选择都正确」，不是随机；它是并发「任意交错都正确」的规范基础。
- 卫式思想进入并发（Ada/CSP/Go 的 select）与模式匹配守卫，是现代「多分支可选」结构的共同祖先。
