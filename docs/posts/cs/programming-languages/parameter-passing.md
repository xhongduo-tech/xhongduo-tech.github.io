## 为什么从参数传递开始

参数协议解决了「实参怎么对应形参」，而**参数传递方式（parameter passing method）**解决更深的问题：**实参的值是如何进入形参的？** 是**传值（pass-by-value）**——拷贝一份值，子程序内的修改不影响调用者；还是**传引用（pass-by-reference）**——共享同一个存储，子程序内的修改直接影响调用者；抑或是**传结果（pass-by-result）**——子程序结束时才把形参的值拷回实参。三种方式对「子程序能否改变调用者的变量」给出截然不同的答案——这是函数副作用语义的基石，也是无数跨语言移植 bug 的根源。<span class="marginnote">一句话区分：<strong>传值看「拷贝」，传引用看「共享」，传结果看「回写」</strong>。C 默认传值，Java 一律「传值」（但对象引用也是值拷贝），Python 传「对象引用」（共享对象），C++ 可显式传引用——「同一段语义，四种表述」。</span>

## 1 传值：拷贝一份

**传值（pass-by-value）**：调用时，把实参的**值拷贝**一份给形参。形参是独立存储，子程序内对形参的任何修改**不影响**实参。

```c
void inc(int x) { x = x + 1; }   // 形参 x 是实参的拷贝

int a = 5;
inc(a);                          // a 仍是 5 —— 传值不影响实参
```

传值是 C、Java（基本类型）、Rust（默认）的方式。优点：子程序完全隔离，无副作用外泄；缺点：大对象拷贝开销高、无法通过参数「返回」多个值。<span class="marginnote">传值的语义直觉：「子程序拿到的是实参的影印件」——怎么涂改影印件都不影响原件。它是「最小权限」的参数方式：被调方无法意外破坏调用者的数据。</span>

## 2 传引用：共享同一份

**传引用（pass-by-reference）**：调用时，把实参的**地址**传给形参——形参是实参存储的**别名**。子程序内对形参的修改**直接影响**实参。

```cpp
void inc(int &x) { x = x + 1; }  // 形参 x 是实参的别名（&）

int a = 5;
inc(a);                          // a 变成 6 —— 修改直接写回实参
```

传引用的价值：

- **通过参数返回多个值**：`void divmod(int a, int b, int &q, int &r)`。
- **避免大对象拷贝**：传 `const &` 只读共享，零拷贝。
- **副作用直达**：修改直接写回实参。

**辨析｜易错点：** 传引用与传值的「陷阱对比」：传引用时子程序内对形参的修改悄悄改了调用者的变量；传值时没有这个效果。**阅读代码时必须知道「这个语言是传值还是传引用」**——C 默认传值，C++ 靠 `&` 显式传引用，Java 的对象「传引用值」——三者行为完全不同。

## 3 传结果与传值-结果

**传结果（pass-by-result）**：形参初始时**不拷贝**实参值（未初始化），子程序结束时把形参的**最终值拷回实参**。用于「输出参数」。

**传值-结果（pass-by-value-result）**：综合——进入时传值（拷贝进），退出时传结果（拷回）。语义上近似传引用，但有重要差异（尤其在别名时）。

```ada
procedure Inc (X : in out Integer) is   -- in out：进入拷贝进、退出拷回
begin
    X := X + 1;
end Inc;
```

**辨析｜易错点：** 传引用与传值-结果的经典差异（塞贝斯塔的著名例子）：若实参是数组元素 `a[i]` 且子程序内修改了 `a[i]`——传引用在整个调用期**绑定同一个位置**（`a[i]` 取「当前 i」）；传值-结果在**进入时定位置、退出时写回**（可能写到不同的 `i` 对应的位置）。**别名（两个实参指向同一位置）下，两者行为分歧**——这是考试与面试的经典题。

## 4 公式解析：三种方式的语义对比

用存储更新模型精确刻画。设实参 $a$ 位于地址 $\text{addr}(a)$，形参为 $p$，子程序体为 $S$：

**传值**：进入时拷贝，体内只改形参：

$$
\text{entry}: \sigma[\text{addr}(p) \mapsto \sigma[\text{addr}(a)]], \qquad
\text{exit}: \sigma \text{ 不变（实参未动）}
$$

**传引用**：形参就是实参的别名，体内改同一位置：

$$
\text{entry}: \text{addr}(p) = \text{addr}(a), \qquad
\text{exit}: \sigma[\text{addr}(a)] \text{ 已被 } S \text{ 修改}
$$

**传结果**：进入不拷贝，退出回写：

$$
\text{entry}: \text{addr}(p) \text{ 为新存储}, \qquad
\text{exit}: \sigma[\text{addr}(a) \mapsto \sigma[\text{addr}(p)]]
$$

三步拆解：

- **第一步，看进入**：传值**拷贝值**（$\sigma[\text{addr}(p) \mapsto \dots]$），传引用**共享地址**（$\text{addr}(p) = \text{addr}(a)$），传结果**不初始化**（只给新存储）。
- **第二步，看体内**：传值体内改的是「拷贝」，传引用体内改的是「实参」，传结果体内改的是「临时存储」。
- **第三步，看退出**：传值退出无事发生，传引用退出时改动已在实参上，传结果退出时**回写**（$\sigma[\text{addr}(a) \mapsto \dots]$）。**三条公式各自回答「进入拷贝 / 中途共享 / 退出回写」**。

**辨析｜易错点：** Java 的「传值」最容易让人困惑：`f(obj)` 中 `obj` 是实参引用的**值拷贝**——重新给形参赋值（`obj = new ...`）不影响调用者，但 `obj.method()` 会改变共享对象。**「传引用值」= 传值（引用本身是拷贝）+ 共享（对象是同一个）**——这是 Java 语义的准确表述。

## 5 各语言的选择与趋势

| 语言 | 默认方式 | 可显式选择 | 备注 |
| --- | --- | --- | --- |
| C | 传值 | 指针模拟引用 | 传指针 = 传引用的地址 |
| C++ | 传值 | `&`/`*` 引用与指针 | 最灵活的传递系统 |
| Java | 传值（含引用值） | 无 | 「万物皆传值」 |
| Python | 传对象引用 | 无 | 共享对象，赋值不传播 |
| Rust | 传值（移动语义） | `&`/`&mut` 借用 | 所有权决定传递 |
| C# | 传值 | `ref`/`out` 显式 | 类同 C++ |

<span class="marginnote">现代趋势是「显式性」：Rust 把「传值、传引用、传可变引用」的语义全部暴露在类型里（`T`、`&T`、`&mut T`），编译器强制区分。相比 C 的隐式、C++ 的繁琐，Rust 的「传递方式即类型」既清晰又安全——是参数传递设计的一个高点。</span>

## 6 小结

- **传值**：拷贝值，子程序内修改不影响实参——隔离但可能高开销。
- **传引用**：共享地址，子程序内修改直达实参——副作用强、可多返回。
- **传结果 / 传值-结果**：退出时回写；与传引用在**别名**下行为分歧。
- 语义公式：传值「进入拷贝」、传引用「中途共享」、传结果「退出回写」；Java 是「传引用值」= 传值 + 共享。
