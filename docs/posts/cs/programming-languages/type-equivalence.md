## 为什么从类型等价开始

类型检查器无时无刻不在回答一个隐秘的问题：**这个类型和那个类型，是不是同一个？** 赋值 `x = y` 要问「`y` 的类型是否等于/兼容 `x` 的类型」，传参、比较、返回都要做同样的判断。答案看似简单，实则是个设计抉择：两个「长得一模一样」的结构（如两个都含 `x` 和 `y` 的记录）到底算不算同一种类型？这里分出了两大阵营——**名字等价（name equivalence）**与**结构等价（structural equivalence）**。理解这场争论，就理解了「类型即抽象」的边界，以及为何有的语言里「长得像」不等于「是」。<span class="marginnote">这场争论的实质是「类型是什么」：名字等价派认为类型是<strong>声明出来的抽象单元</strong>，两个类型即使结构相同也是不同的抽象；结构等价派认为类型是<strong>值的集合</strong>，集合相同就是同一类型。两派对「安全」的定义也因此不同。</span>

## 1 名字等价：类型是声明出来的

**名字等价（name equivalence）**：两个类型相同，当且仅当它们**由同一个声明**定义（或名字直接相同）。即使两个记录结构一字不差，只要来自不同声明，就是不同类型。

Ada、Java（引用类型）、C++ 的类是名字等价的主要拥护者：

```cpp
struct Kilograms { int v; };     // 名字等价：两个类型互不相同
struct Pounds    { int v; };

Kilograms kg{50};
// Pounds lb = kg;               // 编译错误：类型不同，即使结构相同
Pounds lb{kg.v};                 // 必须显式转换
```

**`Kilograms`** 与 **`Pounds`** 结构都是整数，但名字等价使 **`lb = kg`** 直接编译错误——必须显式转换。这正是「抽象」的意图：**重量（kg）与磅（lb）在语义上不可混用，即使底层都是数字**。<span class="marginnote">名字等价把「语义不可混用」做进类型系统：两个表示「不同概念」的类型即使表示相同也不许混用。这比「靠程序员自律不混用」可靠得多——是「把错误消灭在编译期」的又一实例。</span>

**辨析｜易错点：** 名字等价有两种变体：**严格名字等价**（**`Kilograms` 与 `Pounds` 完全不同**）与**传递名字等价**（**别名链**中 **`B` 与 `A`** 名字不同、但 **`A`** 的变量赋给 **`B`** 的参数可能通过别名规则放行）。不要以为「名字等价 = 变量类型完全锁死」——大多数实现允许一定程度的子类型兼容。

## 2 结构等价：类型是值的集合

**结构等价（structural equivalence）**：两个类型相同，当且仅当它们的**结构**相同——相同的成分、相同的顺序、相同的类型。<span class="marginnote">结构等价看「形状」不看「名字」：两个都含 `a: int` + `b: int` 的记录，无论声明叫什么名字，都是同一类型。C 的 `struct` 之间、以及 C 的 `typedef`（仅为别名）大体按结构等价比较。</span>

结构等价的推论是：只要布局相同就能互赋。

```c
struct Point { int x; int y; };     // 两个声明不同的类型
struct Coordinate { int x; int y; };

struct Point p = {1, 2};
struct Coordinate c = p;            // 结构等价：布局相同即可互赋
```

**优点**：灵活——不需要「同一出处」，结构相同即可互通，适合处理外部数据（协议、文件格式）。**缺点**：破坏了抽象——**`kg` 与 `lb`** 在结构等价下无法区分，「重量」与「磅」被抹平，语义隔离失效。<span class="marginnote">结构等价的经典困境：C 的 `<strong>`typedef 只是别名，`<strong>`kg` 与 `lb 完全互通——你无法用类型系统阻止「把 kg 当 int 传给需要 lb 的函数」。要更强的抽象，C 得退到 `<strong>`struct（但结构等价又放行了不同 struct 的同构互赋）。</span>

## 3 两大阵营与语言实践

| 语言 | 引用类型 | 值类型（struct/record） |
| --- | --- | --- |
| Java | 名字等价 | （无值类型；数组按元素类型） |
| C++ | 类：名字等价 | `struct`：结构等价 |
| C | （无引用类型） | 结构等价 |
| Ada | 名字等价 | 名字等价 |
| Rust | 名字等价（`struct` 各不相同） | 名字等价 |
| Haskell/ML | **抽象类型**（经模块隐藏） | 结构等价（`data` 类型按构造器名） |

<span class="marginnote">注意 C 的双轨：类/结构在 C++ 里默认名字等价（`struct A` 与 `struct B` 布局相同也不是同一类型），而 C 的 `struct` 比较接近结构等价（布局相同即可互赋）。语言的「等价规则」并非一成不变——Java 的数组是结构等价（按元素类型判定），而类是名字等价。</span>

## 4 公式解析：等价的定义

两种等价可以写成精确的递归定义。结构等价 $T_1 \equiv_s T_2$：

$$
\frac{}{\text{int} \equiv_s \text{int}} \qquad
\frac{T_1 \equiv_s T_2 \quad T_1' \equiv_s T_2'}{\text{struct}\{a: T_1; b: T_1'\} \equiv_s \text{struct}\{a: T_2; b: T_2'\}}
$$

名字等价 $T_1 \equiv_n T_2$：

$$
T_1 \equiv_n T_2 \;\Longleftrightarrow\; T_1 \text{ 与 } T_2 \text{ 是同一个声明的名字}
$$

三步拆解：

- **第一步，结构等价是递归的**：基础情况（`int ≡ int`）加上复合情况（对应字段逐一等价）——结构等价看的是**无限展开后**的「形状」。两个声明名字不同但形状相同 → 等价。
- **第二步，名字等价是原子的**：一条规则即可判定——「是不是同一个声明」。不展开结构，不比较字段，只比「出身」。
- **第三步，看安全差异**：结构等价下「同构即互通」，命名抽象被绕过；名字等价下「不同声明即隔离」。从抽象保护角度，名字等价更严格；从互操作角度，结构等价更灵活。

**辨析｜易错点：** 结构等价有「递归结构」的坑——互递归类型（如链表结点 `Node`）的自引用不能无限展开。解决靠「递归类型视为一个整体」：遇到已展开的类型名字即判定等价。初学者写结构等价判定时最易陷入无限递归。

## 5 类型等价与类型安全

类型等价规则直接决定类型安全的「颗粒度」：

- 名字等价把「同构但不同概念」隔开——安全更细。
- 结构等价把「同构」全部打通——灵活优先。

现代语言更多采用**折中**：默认名字等价，但通过显式机制获得结构灵活性——Rust 的 `type` 别名（仅别名）、TypeScript 的**结构化类型系统**（类型按形状匹配，接近结构等价但用名义特性补充）。<span class="marginnote">TypeScript 的结构化类型（duck typing 的类型侧）让「长得像就能用」，配合名义化（brand）手法（如 `__brand` 字段）补上名义隔离。它说明两大阵营的界线不是固定的一刀切，而是可调旋钮。</span>

## 6 类型等价的实践意义

类型等价不是纯理论——它直接影响「哪些代码能编译」与「哪些错误能早发现」：

**防止单位混淆**：名字等价让「公斤」与「磅」不可混用——**`kg_value + lb_value`** 编译错误。物理量计算（NASA 火星气候轨道器因单位混用坠毁！）正是类型等价要防的灾难。**「名字等价 = 把『语义单位』变成编译期检查」**。

**接口演化的安全性**：结构等价下，两个「恰好同构」的类型自动互通——但若库 A 的 **`Point{x,y}`** 与库 B 的 **`Point{x,y}`** 语义不同（一个毫米、一个英寸），结构等价会**静默混用**。名字等价强制显式转换——**「宁可麻烦，不可静默错」**。

**调试的体验**：结构等价下，错误信息常显示「类型结构相同但不匹配」——难以定位；名字等价下类型名清晰（**`Point` 与 `Position`**）。

**辨析｜易错点：** **「结构等价的『灵活』与『危险』是同一枚硬币」**：灵活在于「长得像就能用」（处理外部数据方便）；危险在于「语义不同的同构类型被静默打通」。工程共识：**「库的公开 API 用名字等价（隔离语义），内部数据处理可放宽」**——「类型等价的选择 = 安全与灵活在类型层的平衡」。TypeScript 的结构化类型让「接口」灵活，但需要「名义化技巧」（brand/nominal）来补语义隔离——两种路线的折中。

## 7 小结

- **名字等价**：同一声明才相同；把「语义不可混用」做进类型系统，抽象保护强。
- **结构等价**：形状相同即相同；灵活、利于互操作，但抽象可被绕过。
- 语言实践常是混合：引用类型默认名字等价，值类型按结构；TypeScript 走结构化路线。
- 等价规则决定类型安全的颗粒度与互操作的灵活性，是「安全 vs 自由」权衡在类型层的投影。
