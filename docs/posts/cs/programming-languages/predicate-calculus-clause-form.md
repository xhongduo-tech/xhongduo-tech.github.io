## 为什么从谓词演算开始

命令式编程说「怎么做」，函数式编程说「函数是什么」，而**逻辑式编程（logic programming）**更进一步：**只说「什么为真」，让机器去推「怎么得到它」**。它的理论基础是**谓词演算（predicate calculus）**——数学里描述「对象与性质」的形式语言。Prolog 是逻辑式编程的代表：程序是一组**事实（facts）**与**规则（rules）**（合起来是「子句」），运行是**问查询**，求解是**归结（resolution）**（下一节）。这一节先打好地基：谓词演算的语法、霍恩子句、以及「为什么 Prolog 只接受子句形式」。<span class="marginnote">逻辑式编程的口号是「算法 = 逻辑 + 控制」（Kowalski）：程序员提供「逻辑」（声明什么为真），控制（怎么搜）由语言运行时负责。这是与命令式（程序员同时给逻辑和控制）的最大分野——也是最诱人的「声明式」理想。</span>

## 1 谓词演算：描述对象与关系

**谓词演算（predicate calculus）**：一种形式语言，用**项（term）**表示对象，用**谓词（predicate）**表示性质/关系，用**量词**（∀、∃）与**连接词**（∧、∨、¬）构成命题。

**项**：常量（**`socrates`**）、变量（**`X`**）、函数项（**`father(socrates)`**）。
**原子（atom）**：谓词作用于项——**`likes(alice, music)`**、「alice 喜欢音乐」。
**合式公式**：原子 + 逻辑连接词组合——**`∀X (human(X) → mortal(X))`**、「所有人都会死」。

Prolog 的谓词语法直接继承：

```prolog
% 项（term）：常量、变量、函数项
socrates               % 常量
X                      % 变量
father(socrates)       % 函数项

% 原子（atom）：谓词作用于项
human(socrates).       % 「苏格拉底是人」
likes(alice, music).   % 「alice 喜欢音乐」

% 合式公式：∀X (human(X) -> mortal(X))   「所有人都会死」
```

## 2 子句形式：把公式标准化

逻辑式编程不能处理**任意**谓词公式——只接受**子句形式（clause form）**：一个公式是「若干文字的析取」。通过三步转化，任意公式都能化成子句形式：

1. **消去蕴含**：**`P → Q`** 化为 **`¬P ∨ Q`**。
2. **否定深入**：**`¬(P ∧ Q)`** 化为 **`¬P ∨ ¬Q`**（德摩根 + 量词对偶）。
3. **消去存在量词**：引入 **Skolem 函数**——**`∃X P(X)`** 化为 **`P(a)`**（Skolem 常量）或 **`P(f(x))`**（含变量的 Skolem 函数），用「某个具体的（但未知的）对象」代替存在量词。

最终形式：**子句** = 文字的析取 **`¬A₁ ∨ ¬A₂ ∨ ... ∨ B`**，可改写为蕴含形式 **`A₁ ∧ A₂ ∧ ... → B`**。<span class="marginnote">Skolem 化的直觉：「存在一个 X 使得 P」——给它一个名字（Skolem 函数/常量），假想它已存在。`<strong>`∃X P(X) → `<strong>`P(a)。注意 Skolem 常量与普通常量的区别：它「存在但未知」，推导时不能随便实例化成别的值。</span>

## 3 霍恩子句：Prolog 接受的形式

**霍恩子句（Horn clause）**：最多含**一个正文字**（无否定）的子句。三种形态：

**事实（fact）**：一个正文字，无前提——**`human(socrates).`**
**规则（rule）**：一个结论 + 多个前提——**`mortal(X) :- human(X).`**（结论 **`mortal(X)`**，前提 **`human(X)`**）
**目标（goal）**：无正文字——**`?- mortal(socrates).`**（查询）

**为什么只要霍恩子句**？归结（resolution）在霍恩子句上**高效且确定**——每步只有一个选择点；任意子句的归结可能产生多个正文字（选择爆炸）。Prolog 的「程序 = 事实 + 规则，查询 = 目标」结构，正是霍恩子句的程序形态。<span class="marginnote">霍恩子句的限制：一个规则只能有一个结论——`<strong>`mortal(X) ∨ immortal(X)（两个正文字）无法表达。这牺牲了表达力，换来了<strong>高效、确定的归结</strong>。这是逻辑式编程「用受限于子句的表达换取自动求解」的核心权衡。工程上，霍恩子句足够表达绝大多数「if-then」规则。</span>

## 4 公式解析：子句形式的推导

用「所有人都会死」从自然语言到 Prolog 子句：

自然语言：所有人都是会死的。

**第一步，谓词公式**：

$$
\forall X\ (\text{human}(X) \to \text{mortal}(X))
$$

**第二步，消蕴含**：

$$
\forall X\ (\neg \text{human}(X) \lor \text{mortal}(X))
$$

**第三步，转 Prolog 子句**（全称量词省略，**`¬human(X) ∨ mortal(X)`** 写成蕴含形式）：

```prolog
% 谓词公式 ∀X (human(X) → mortal(X)) 经三步转化：
mortal(X) :- human(X).     % Prolog 规则：若 X 是人，则 X 必死
```

三步拆解：

- **第一步，符号化**：把自然语言翻成语料公式——量词 ∀ 覆盖所有 X，蕴含表达「若是人则会死」。
- **第二步，标准化**：蕴含转析取（**`¬human(X) ∨ mortal(X)`**），量词默认全称（自由变量即全称）。
- **第三步，翻 Prolog**：析取 **`¬human(X) ∨ mortal(X)`** 等价于蕴含 **`human(X) → mortal(X)`**，Prolog 写为 **`mortal(X) :- human(X).`**——「B 当 A 时成立」。**「Prolog 规则 = 蕴含 = 析取子句」**是三者贯通的钥匙。

**辨析｜易错点：** Prolog 的变量是**大写开头**（**`X`**），常量小写（**`socrates`**）；**`mortal(X) :- human(X).`** 的右侧是前提、左侧是结论。**「变量是『任何对象』，常量是『具体对象』」**——**`?- human(X).`** 问「X 是人吗（找所有人）」，**`human(socrates).`** 是「苏格拉底是人」的事实。大小写约定不是风格，是「变量/常量」的语法标记。

## 5 从谓词演算到逻辑式编程

- **声明式语义**：Prolog 程序 = 一组逻辑命题；「程序的含义」是这些命题的逻辑推论集合。
- **过程式语义**：Prolog 运行时按「深度优先 + 回溯」搜索证明——声明与过程两面共存（逻辑 + 控制）。
- **能力边界**：霍恩子句表达「if-then」规则绰绰有余，但表达「或」（多结论）、否定（**`\+`** 的特殊处理）、全称量词受限——逻辑式编程用「封闭世界假设」简化（未证明的真 = 假）。<span class="marginnote">「封闭世界假设（closed-world assumption）」：Prolog 里 `<strong>`\+ human(X)（negation as failure）表示「无法证明 human(X)」而非「确实不是人」。这是「数据库视角」的否定——未记录即假。它与经典逻辑的「排中律」不同，是逻辑式编程的一个微妙但重要的语义选择。</span>

## 6 小结

- **谓词演算**描述对象与关系：项 + 谓词 + 量词/连接词；逻辑式编程只说「什么为真」。
- **子句形式** = 文字的析取；经消蕴含、否定深入、Skolem 化把任意公式标准化。
- **霍恩子句** = 最多一个正文字：**事实 / 规则 / 目标**三种形态——Prolog 程序的全部结构。
- 霍恩子句限制表达力，换来**高效确定的归结**；声明式语义（逻辑）+ 过程式语义（深度优先搜索）两面共存。
