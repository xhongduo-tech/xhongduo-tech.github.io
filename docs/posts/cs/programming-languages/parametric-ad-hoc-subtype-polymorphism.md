## 为什么从多态开始

同一段逻辑要服务于不同数据类型，是编程里最普遍的需求：一个「求最大值」函数要对 `int`、`float`、字符串都可用；一个「容器」要能装任何类型。把「一个名字、多种类型」系统化，就是**多态（polymorphism）**。斯特雷奇在 1967 年把多态分成两大方向，后来学界细分为三类：**参数多态**（泛型）、**特设多态**（重载/强制）、**子类型多态**（面向对象的继承）。三者看似都「让一个名字有多种类型」，机制与用途却完全不同——混淆它们是类型系统学习中最常见的迷路点。<span class="marginnote">把三者和「数学」对应起来最好记：参数多态像「对任意类型通用的公式」，特设多态像「对不同类型分别定义的同一符号」，子类型多态像「父类位置可放子类对象」。同一个 `+` 或 `.toString()` 在不同机制下「多种实现」的来历各不相同。</span>

## 1 参数多态：对任意类型通用

**参数多态（parametric polymorphism）**：一个函数/类型对所有类型 T 都「同一段实现」，类型由参数化引入。<span class="marginnote">「参数化」指类型本身作为参数：`length :: [a] -> Int` 对任何元素类型 $a$ 的列表都成立，且实现只有一份——它不看元素长什么样，只看列表结构。这是「一次实现，处处可用」的纯粹形态。</span>

```haskell
length :: [a] -> Int        -- Haskell：对任意类型 a 的列表求长度
```

```rust
fn first<T>(v: &Vec<T>) -> Option<&T> { v.first() }   // Rust 泛型
```

参数多态的实现遵循**单一实现（uniform implementation）**原则：代码只写一遍，类型参数在编译期实例化（C++/Rust 模板/泛型会为每个类型生成专用代码，Java 用擦除共享一份）。它的核心价值是**通用性与安全性兼得**——不牺牲类型安全就能写通用算法。

## 2 特设多态：同一符号，分别定义

**特设多态（ad hoc polymorphism）**：同一个运算符/函数名对**不同类型**有**不同实现**。它与参数多态的本质区别：参数多态是「一份实现对所有类型」，特设多态是「一个名字绑定多份针对特定类型的实现」。

两类经典机制：

**重载（overloading）**：同一名字绑定多个同名的函数，靠参数类型区分。

```java
int  add(int a, int b)     { return a + b; }
double add(double a, double b) { return a + b; }
```

**强制（coercion）**：运算前把操作数自动转换成所需类型（如 `int` + `float` 先把 `int` 提升为 `float`）。<span class="marginnote">重载在编译期按「实参类型」选实现，强制在编译期按「可转换性」做类型调整。C++ 的重载解析是两者混合：既允许精确匹配也允许可转换匹配，形成复杂的优先级排序——这是 C++ 学习曲线陡峭的一角。</span>

现代语言用**类型类（type class）**（Haskell）与**trait**（Rust）给特设多态加了「纪律」：同一运算符对实现了 `Eq` 的类型都可重载，且声明与实现分离、可推导。

## 3 子类型多态：父类位置，子类对象

**子类型多态（subtype polymorphism）**：一个表达式「静态类型」是父类，运行时实际对象可以是任何子类；调用方法时**动态绑定**到实际类型的方法。<span class="marginnote">这是面向对象语言里「多态」最常指的意思：`Animal a = new Dog(); a.speak();` 实际调用 `Dog.speak()`。子类型多态的运行机制是虚表（vtable）或方法表——运行时查表找实际方法，这就是「动态分派」。</span>

```java
class Animal { void speak() {...} }
class Dog extends Animal { void speak() {...} }
Animal a = new Dog();
a.speak();   /* 运行时绑定到 Dog.speak() */
```

子类型多态是**面向对象的设计核心**（第十一篇详讲），它与前两者的关系：参数多态写「通用算法」，特设多态写「同名异实现」，子类型多态靠「继承 + 动态绑定」在运行时选择实现。

## 4 公式解析：三者的类型签名

用类型签名把三者的差异钉死。设 `f` 是要多态化的函数：

**参数多态**：

$$
f : \forall a.\ a \to a
$$

一份实现，对任何 $a$ 成立——同一函数体，类型全称量化。

**特设多态（重载）**：

$$
f : \text{Int} \to \text{Int}, \qquad f : \text{Float} \to \text{Float}
$$

同一个名字，绑定两份不同签名的实现——选择在编译期完成。

**子类型多态**：

$$
f : \text{Parent} \to \text{Parent}, \qquad \text{Dog} \leq \text{Parent}
$$

函数声明只认父类型，子类对象因其 $\text{Dog} \le \text{Parent}$ 的**子类型关系**也能传入——选择在运行时（动态绑定）完成。

三步拆解：

- **第一步，看量化词**：参数多态有 $\forall$（全称），一个签名管所有类型。
- **第二步，看签名数量**：特设多态有**多份签名**，靠名字共享；参数多态只有一份。
- **第三步，看何时选择**：参数多态不选（就一份），特设多态编译期选，子类型多态运行期选。**「三种多态 = 三种选择时机」**——这是最凝练的总结。

**辨析｜易错点：** 「重载」与「覆盖（override）」极易混淆。**重载**是同名字不同签名（编译期、静态解析）；**覆盖**是子类重写父类方法、签名相同（运行期、动态绑定）。重载是多态的**特设**形态，覆盖是**子类型**多态的载体——两者层次不同。

## 5 三者的配合：现代语言的综合运用

- **Rust**：`trait` 同时提供参数多态（`fn f<T: Trait>`）与特设多态（同一 trait 对不同类型有不同 impl）；子类型多态在 Rust 里极弱（无继承，靠 trait 对象 `dyn Trait` 近似）。
- **Java/C++**：泛型（参数多态）+ 重载（特设）+ 继承/接口（子类型）三者并存，构成完整工具箱。<span class="marginnote">Java 的 `List<T>` 是参数多态，`+` 对 `String` 的重载是特设，`List<Dog>` 赋给 `List<Animal>` 报错是「泛型不可协变」——三类多态在同一种语言里互相影响，牵一发动全身。</span>
- **Haskell**：参数多态为骨架，类型类实现「受约束的特设多态」，无子类型多态——纯粹的函数式路线。

## 6 小结

- **参数多态**：一份实现、全称量化（$\forall a$），对任意类型通用；选择不在运行时。
- **特设多态**：一个名字多份签名，靠**重载**与**强制**实现；编译期选择。
- **子类型多态**：父类位置放子类对象，靠**继承 + 动态绑定**；运行期选择。
- 三者区别可凝练为「签名数量 × 选择时机」；重载 vs 覆盖是必须厘清的辨析点。
