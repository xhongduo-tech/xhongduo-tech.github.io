## 为什么从 Scheme 开始

在函数式语言家族里，**Scheme** 是最适合「入门」的一个：它语法极简（一切皆括号表达式）、规则统一（代码与数据都是表）、又内建高阶函数、递归、闭包与宏。它源自 Lisp 家族，1980 年代成为 MIT 教材 SICP 的教学语言，培养了整整一代计算机科学家。这一节通过 Scheme 的三个核心——**函数、表（list）、递归**——展示函数式编程的最小但完整的图景。理解 Scheme，是理解 Lisp 家族「代码即数据」哲学、以及惰性/宏等高级主题的起点。<span class="marginnote">Scheme 的语法极简到令人惊讶：`(f a b)` 是「调用 f 于 a、b」，`(lambda (x) ...)` 是「匿名函数」。没有运算符优先级（前缀表示消除歧义）、没有语句/表达式之分（一切是表达式）——语法表少到可以一页写尽。这种极简让「语言本身」可以被清晰地思考。</span>

## 1 前缀表示：没有优先级的语法

Scheme 的一切计算都是**前缀表示（prefix notation）**——运算符在最前：

```scheme
(+ 1 2 3)      ; 加法：1 + 2 + 3 = 6
(* 2 3 4)      ; 乘法：2 * 3 * 4 = 24
(quotient 7 2) ; 整除：3
```

**没有优先级、没有结合性**——因为都是显式括号嵌套。`(+ 1 2 3 4 5)` 可以一次加多个参数（可变参数）。<span class="marginnote">前缀表示消除了「优先级歧义」这个命令式语言的心头大患（第二篇讲过）：`a + b * c` 在 Scheme 里必须写成 `(+ a (* b c))`——没有歧义空间。代价是手写较繁，但「机器可读性」极高——代码就是一棵语法树，解析毫不费力。</span>

## 2 函数定义与调用

**函数定义**用 `define`：

```scheme
(define (square x)
  (* x x))

(square 5)     ; 25
```

**匿名函数（lambda）**与高阶函数：

```scheme
((lambda (x) (* x x)) 5)     ; 匿名函数立即调用：25

(define (twice f x)
  (f (f x)))

(twice square 3)             ; 81 —— 函数作参数
```

Scheme 里函数是一等公民——`map`、`filter`、`foldl`（`apply`）都是标准函数。

## 3 表：函数式语言的数据结构

**表（list）**是 Scheme 的基本数据结构——由 `cons`（构造）、`car`（取头）、`cdr`（取尾）三个操作构建与分解：

```scheme
(cons 1 '(2 3))    ; (1 2 3) —— 构造
(car '(1 2 3))     ; 1 —— 取头
(cdr '(1 2 3))     ; (2 3) —— 取尾
```

**表 = 递归结构**：`(cons 1 '(2 3))` 是「1 加上 (2 3)」。这个「头 + 尾」的结构与递归函数天然匹配——处理表的函数几乎都是「处理头，再递归处理尾」。<span class="marginnote">`cons`/`car`/`cdr` 三个操作定义了整个表的世界：`cons` 建表、`car` 取头、`cdr` 取尾。表是「递归定义的容器」——它的结构就是递归程序的形状。这也是为什么函数式语言处理数据普遍用「递归 + 模式匹配」而非「索引循环」。</span>

## 4 公式解析：递归处理表

处理表的通用模式是「**递归分解**」——对表的递归定义直接翻译成递归函数。以「求表长」为例：

$$
\text{length}(l) = \begin{cases}
0 & l = \text{()} \quad (\text{空表}) \\
1 + \text{length}(\text{cdr}(l)) & \text{否则}
\end{cases}
$$

```scheme
(define (length lst)
  (if (null? lst)
      0
      (+ 1 (length (cdr lst)))))
```

三步拆解：

- **第一步，空表基线**：空表长度为 0——递归的终止条件，对应表的递归定义的「底」。
- **第二步，非空递推**：非空表 = 1（头）+ 尾的长度——`(+ 1 (length (cdr lst)))` 把「整表问题」化成「尾表问题」。
- **第三步，看通用性**：这个「基线 + 递推」的模式适用于所有表处理——`sum`、`map`、`filter` 都是同一结构。**「递归函数的形状 = 数据结构的形状」**是函数式编程的核心方法论。

**辨析｜易错点：** 递归的**深度**问题：`length` 对长表会深递归（调用栈深度 = 表长）。长表（如 100 万元素）可能栈溢出。**尾递归（tail recursion）**解决此问题——若递归调用是函数的**最后一个动作**，编译器可优化为循环（尾调用优化）。`(+ 1 (length (cdr lst)))` 的写法不是尾递归，需改为「带累积参数」的版本。

## 5 从 Scheme 到 Lisp 家族

- **代码即数据（homoiconicity）**：Scheme 的程序与数据都是表——`'(1 2 3)`（数据）与 `(+ 1 2)`（代码）结构相同。这让**宏**成为可能：写「操作代码的代码」。
- **Lisp 家族**：Common Lisp（实用）、Scheme（极简教育）、Clojure（JVM 现代版）、Racket（Scheme 的后继教学语言）。<span class="marginnote">「代码即数据」是 Lisp 最独特的气质：你可以写一个函数，它生成代码（表），再 `eval` 它——「程序生成程序」。这种元编程能力让 Lisp 的宏系统成为语言自定义的终极武器（第十六篇元编程会展开）。现代语言里，Julia 的宏、Rust 的宏、甚至 DSL 设计都继承了这一思想。</span>
- **SICP 遗产**：SICP 用 Scheme 教「程序构造与抽象」，其思想（数据抽象、过程抽象、元语言抽象）超越语言本身，影响了无数计算机科学教育。

## 7 小结

- **前缀表示**消除优先级歧义——代码即语法树，一切皆表达式。
- **函数**用 `define` 定义，lambda 提供匿名函数；函数是一等公民（可作参数/返回值）。
- **表**由 `cons`/`car`/`cdr` 构建与分解——递归结构，与递归程序天然匹配。
- 表处理的通用模式：**基线 + 递推**（递归函数形状 = 数据结构形状）；尾递归可优化为循环。
