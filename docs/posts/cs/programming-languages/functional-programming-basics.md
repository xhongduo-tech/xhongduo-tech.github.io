# 函数式编程的基本概念：数学函数与引用透明性

## 为什么从函数式编程开始

命令式语言（C/Java/Python 的主流写法）把程序看成「一系列修改状态的语句」；**函数式编程（functional programming）**换了一个视角：程序是一系列**函数求值**——输入进、输出出，函数间通过值连接，不通过共享状态。这个「程序即函数」的图景不是新鲜事——它正是数学里「函数」的定义：给定输入，唯一输出，无副作用。函数式编程的核心信条由此而来：**纯函数**与**引用透明性**。这一节把这两个基础概念立稳，它们是整个函数式世界的地基。<span class="marginnote">函数式编程不是「没有赋值」，而是「赋值不是主角」：程序的表达靠「值流动」（函数返回传给下一个函数），不靠「状态累积」（反复修改一个变量）。Java 8 的 Stream、Python 的 map/filter、JavaScript 的 Array.map 都是函数式思想在命令式语言里的渗透。</span>

## 1 数学函数 vs 程序函数

**数学函数（mathematical function）**：集合 A 到集合 B 的映射——对每个输入，**唯一确定**一个输出，且**无副作用**（不改变外部状态）。

$$f : A \to B, \qquad f(x) = y$$

**程序里的函数**却常常不是数学函数：C 的 rand() 每次返回不同值（依赖隐藏状态）；void log(msg) 无返回值但有副作用（写文件）。它们「是函数」但「不像数学函数」。

**纯函数（pure function）**：既是程序函数又像数学函数——① 相同输入必得相同输出；② 无副作用。<span class="marginnote">「纯函数」把数学函数的两个性质（确定性 + 无副作用）移植到程序里。add(1, 2) 是纯函数，rand() 不是，printf 不是。纯函数是函数式编程的原子——一切组合都建立在「纯」之上。</span>

## 2 引用透明性：可替换性

**引用透明性（referential transparency）**：表达式可以被它的值安全替换，而不改变程序行为。

$$E \equiv v \;\Longrightarrow\; \text{程序中所有 } E \text{ 可换成 } v，行为不变$$

例：3 + 5 是引用透明的——把它换成 8，程序行为不变。但 rand() + 5 不透明——换成它某次的值，行为就变了。

引用透明性的推论（威力所在）：

- **可缓存**：f(x) 的结果可记忆化（memoize），不用重算。
- **可重排**：a + b + c 的求值顺序无关紧要（无副作用依赖）。
- **可并行**：f(x) + g(y) 中每个子表达式独立——可放心并行。<span class="marginnote">引用透明性 = 「把表达式当值用」的能力。它是编译器优化（常量折叠、公共子表达式消除）的前提，也是并行计算安全的保证——没有共享状态，就没有数据竞争。「无副作用」让「可替换」成为可能，这是函数式语言利于推理、优化与并行的总根源。</span>

## 3 表达式 vs 语句：函数式的语法取向

函数式语言偏爱**表达式**（产生值）而贬抑**语句**（只执行动作）：

- 命令式：s = 0; for x in xs: s += x（三步语句）
- 函数式：sum(xs) 或直接 foldr (+) 0 xs（一个表达式）

Haskell 没有赋值语句；一切是表达式。if-then-else 是表达式（产生值）、循环用递归或高阶函数替代。

**辨析｜易错点：** 「函数式 = 不用循环」是常见误解。函数式**不用显式循环**（for/while），但用**高阶函数**（map/filter）与**递归**表达重复——循环的意图保留，只是形态改变。**「不是消除重复，而是把重复的『控制流』换成『数据转换』」**。

## 4 公式解析：纯函数的组合

函数式编程的构建单元是**函数组合（composition）**：

$$
(f \circ g)(x) = f(g(x))
$$

在程序里，组合用「管道」表达：

$$
\text{pipeline} = \text{map}(f) \circ \text{filter}(p) \circ \text{sort}
$$

三步拆解：

- **第一步，读组合**：$(f \circ g)(x)$ = 先算 $g(x)$，再对结果用 $f$。**函数式程序的骨架就是这种嵌套/管道的函数调用**。
- **第二步，看数据流**：map(f)/filter(p)/sort 都是「数据进、数据出」的纯函数——数据沿管道流动，每一步转换一次。**「程序 = 数据转换管道」是函数式的核心图景**。
- **第三步，看组合性保障**：组合之所以安全，正因为每个函数**纯**——管道中任何一环的输出只依赖输入，不依赖外部状态。**「纯函数 → 可组合 → 可预测」是函数式的方法论链条**。

**辨析｜易错点：** 纯函数不能「真的做任何事」（不能打印、不能写文件）——那怎么写出有用的程序？答案：**副作用被隔离到程序边界**（main、IO 层），核心逻辑保持纯函数。Haskell 用 IO 单子隔离（后面讲 Monad），命令式语言把纯逻辑放在函数深处、IO 放外层。「**纯核心 + 薄副作用外壳**」是函数式架构的经典形态。

## 5 函数式编程的价值与现代渗透

- **可测试性**：纯函数无需 mock——传参即测，输出即断言。
- **并发安全**：无共享状态 → 无数据竞争，天然可并行。
- **可推理性**：函数行为只由参数决定——调试无需追踪「谁改了这个全局变量」。
- **现代渗透**：Java Stream、Python 的 map/filter/reduce、JS 的 Array.map 方法、Rust 的迭代器、Spark 的 RDD——函数式思想已全面进入主流。<span class="marginnote">「大模型时代的函数式」：数据管线的声明式风格（Spark、SQL、Pandas 链式调用）与函数式「数据流」同构——「描述转换，而非描述步骤」。函数式的可组合与可并行，正好契合大规模数据处理的诉求。</span>

## 6 从命令式到函数式：一个改写实例

把一段命令式代码「翻译」成函数式风格，最能体会两者的差异。任务：对列表中的偶数求平方和。

**命令式**（Python）：

```python
total = 0
for x in numbers:
    if x % 2 == 0:
        total += x * x
print(total)
```

**函数式**（Python 风格）：

```python
total = sum(x * x for x in numbers if x % 2 == 0)
print(total)
```

两版对比：

| 维度 | 命令式 | 函数式 |
| --- | --- | --- |
| 状态 | total 逐步修改 | 无可变状态（一次算完） |
| 控制流 | for + if（语句） | 生成器 + 推导（表达式） |
| 思路 | 「怎么累加」 | 「选出什么、变换什么、求和」 |

函数式版本**没有变量被修改**——sum(...) 是一次算出的值，不是被反复赋值的累加器。**「命令式描述『如何一步步得到』，函数式描述『结果是什么』」**——这种「声明式」表述更接近数学（函数定义），也因此更易推理、可并行。

**辨析｜易错点：** 函数式改写不是「炫技」——它的价值在**可读性与可推理性**：没有中间变量就没有「状态在哪被改」的问题；sum(...) 一眼看出「求总和」。**「能用表达式描述的数据处理，优先表达式而非循环」**——这是函数式思想给命令式代码的实用建议（现代 Python/Java 都推崇）。

## 7 小结

- **纯函数** = 同输入同输出 + 无副作用——把数学函数的两个性质移植进程序。
- **引用透明性** = 表达式可被其值安全替换——带来可缓存、可重排、可并行。
- 函数式偏好**表达式**（产生值）而非语句；循环用高阶函数/递归替代。
- 函数组合 $f \circ g$ 是构建单元；「纯函数 → 可组合 → 可预测」是方法论链条；副作用隔离到边界。
