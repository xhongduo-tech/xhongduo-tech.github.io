## 为什么从栈与堆开始

第十五篇进入**内存管理（memory management）**——程序运行时内存如何分配与回收。两大区域奠定基础：**栈（stack）**——后进先出、随调用嵌套分配/释放；**堆（heap）**——任意生命周期、需显式或自动回收。栈是「结构性的」（由调用关系决定），堆是「内容性的」（由数据需要决定）。理解两者的分工与代价，是理解引用计数、垃圾回收、所有权系统（后续几节）的前提——它们都是「堆内存何时回收」这一问题的不同答案。<span class="marginnote">栈与堆的分工一句话：<strong>栈放「生命周期嵌套」的数据</strong>（局部变量、函数帧），<strong>堆放「生命周期自由」的数据</strong>（动态对象、共享数据）。栈靠「移动指针」分配（快），堆靠「找空闲块」分配（慢且有碎片）。「栈是自动的，堆是需要管理的」——所有内存管理的复杂度都来自堆。</span>

## 1 栈分配：随调用伸缩

**栈分配（stack allocation）**：内存从栈顶分配，进入函数时下移栈指针（分配帧），退出时上移（释放）。**后进先出（LIFO）**——先分配的帧后释放。

```c
void foo() {
    int x = 1;   // 进入 foo 时栈指针下移，x 分配在栈帧上
    int y = 2;   // 局部变量按声明顺序压栈
}                // 退出 foo 时栈指针上移，x、y 自动释放
```

栈分配的特点：

**极快**：分配 = 一条「栈指针减 N」指令，释放 = 一条加指令——无搜索、无碎片。
**自动**：进入/退出块自动分配/释放，无需手动管理。
**限制**：生命周期严格嵌套（后进先出）——无法让对象「活过」创建它的函数（除非拷贝或转堆）。<span class="marginnote">栈的 LIFO 决定了它的边界：一个对象<strong>不能</strong>在创建它的函数返回后继续存在——栈帧已销毁。所以「返回局部变量的指针」（C）是悬垂指针；「返回局部变量的值」（拷贝）是安全的。要「活过作用域」的对象必须去堆——这是栈与堆分工的根本界限。</span>

## 2 堆分配：自由的生命周期

**堆分配（heap allocation）**：内存从堆上分配，生命周期**不受调用嵌套限制**——可在任意时刻分配、任意时刻释放（只要还在使用）。

```c
int *p = malloc(sizeof(int));   // 堆上分配：返回空闲块地址
*p = 42;                        // 经指针访问
free(p);                        // 程序员手动释放，否则泄漏
```

堆分配的特点：

**灵活**：生命周期自由——可跨函数存活、可共享。
**昂贵**：分配需找空闲块（free list / 分配器），释放需回收并可能合并碎片——比栈慢几个数量级。
**需要管理**：谁负责释放？——手动（C）、引用计数（Swift）、GC（Java/Python）、所有权（Rust）——四种答案就是后续几节的主题。<span class="marginnote">堆的分配器像「内存管家」：维护空闲块列表，分配时找合适块（first-fit/best-fit），释放时回收并合并相邻空闲块（防碎片）。first-fit/best-fit 的性能与碎片控制是系统编程的经典课题——内存池、slab 分配器、tcmalloc/jemalloc 都是优化「堆分配」的工程成果。</span>

## 3 堆 vs 栈：用哪个

| 维度 | 栈 | 堆 |
| --- | --- | --- |
| 分配速度 | 极快（指针移动） | 较慢（搜索空闲块） |
| 生命周期 | 嵌套（LIFO） | 自由 |
| 大小限制 | 有限（栈空间，易溢出） | 大（受物理内存限制） |
| 管理方式 | 自动 | 手动/GC/所有权 |
| 典型用途 | 局部变量、函数帧 | 动态对象、大数组、共享数据 |

**经验法则**：能放栈就放栈（快、自动）；需要「跨作用域存活」或「大对象」才用堆。<span class="marginnote">「值类型 vs 引用类型」的讨论（C#、Swift、Rust 的 value/reference 语义）本质是「栈还是堆」的选择：值类型（struct）在栈上、拷贝语义；引用类型（class）在堆上、共享语义。现代语言让用户显式选择（C# 的 struct/class、Rust 的 struct/Box）——「栈堆选择」上升为语言特性。</span>

## 4 公式解析：栈与堆的分配开销

栈分配的开销可以用「常量时间」刻画——与已分配量无关：

$$
T_{\text{stack}}(n) = O(1) \quad \text{（一条指针加减指令，无论分配多少）}
$$

堆分配：

$$
T_{\text{heap}}(n) = O(\text{空闲块搜索}) + O(\text{碎片整理}) \quad \text{（可能 } O(\log n) \text{ 或更高）}
$$

三步拆解：

- **第一步，栈的 O(1)**：栈分配就是「把栈指针往下移 N 字节」——时间与 N、与已用空间都无关。这是栈最快的根源。
- **第二步，堆的代价**：堆分配要在空闲块里找「足够大的块」——free list 遍历（$O(n)$）、平衡树（$O(\log n)$）、或 tcmalloc 的缓存（接近 $O(1)$）。释放还涉及合并。
- **第三步，看取舍**：栈的 $O(1)$ 换来「生命周期受限」，堆的灵活换来「分配开销」。**「栈快但短命，堆慢但自由」**——这就是内存分配的基本矛盾，也是优化策略（对象池、栈上分配的 escape analysis）要解决的问题。

**辨析｜易错点：** 栈溢出（stack overflow）≠ 堆耗尽（out of memory）。栈溢出是**嵌套过深**（无限递归、超大局部数组）——栈空间固定（通常几 MB）；堆耗尽是整个程序的堆内存不够。**「递归爆栈是栈问题，泄漏耗尽是堆问题」**——两类错误、两种对策（改迭代/减少帧 vs 修泄漏）。

## 5 从分配策略到内存管理模型

- **C**：手动——malloc/free，全部由程序员负责（最强控制、最多错误）。
- **Java/Python**：GC——堆由垃圾回收器自动回收（下一节追踪式回收）。
- **Swift**：引用计数——ARC 自动计数（再下一节）。
- **Rust**：所有权——编译期决定何时释放（栈上 RAII，堆上 Box 随所有者作用域释放）。

<span class="marginnote">四种模型其实都在回答同一个问题：「堆对象何时释放？」——手动说「程序员决定」，GC 说「不可达时」，引用计数说「引用归零时」，所有权说「所有者离开作用域时」。四种答案的「时机确定性」与「开发负担」各异——这正是内存管理这片江湖的地图。</span>

## 6 小结

- **栈分配**：LIFO、指针移动即分配、极快、自动——但生命周期严格嵌套。
- **堆分配**：生命周期自由、需管理——分配慢、有碎片，是内存管理复杂度的来源。
- 栈 O(1) 分配换「短命」，堆灵活换「开销」；「值类型走栈、引用类型走堆」是现代语言的显式选择。
- 栈溢出（嵌套过深）≠ 堆耗尽（泄漏）；手动/GC/引用计数/所有权四种模型回答「堆何时释放」。
