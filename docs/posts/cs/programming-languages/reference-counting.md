## 为什么从引用计数开始

手动内存管理（`malloc`/`free`）太容易出错，垃圾回收（GC）有停顿——**引用计数（reference counting, RC）**走中间路线：**每个堆对象记录「被引用的次数」，次数归零时立即释放**。它直观、确定（释放时机可预测）、无需 GC 的暂停扫描；但也有致命的缺陷——**循环引用**：两个对象互相引用时，计数永不归零，内存泄漏。这一节把引用计数的机制、优势、以及循环引用的解法讲透——它是 Swift 的 ARC、Python 的引用计数、Rust 的 `Rc`/`Arc` 的共同基础。<span class="marginnote">引用计数的直觉：「对象活着 ⇔ 还有人指着它」。每次引用创建（赋值、传参）计数 +1，引用消失（离开作用域）计数 -1；计数为 0 = 没人用了 = 立即释放。它是「即时的确定性回收」——不像 GC 要等「某个时刻」扫描，引用消失的瞬间就回收。</span>

## 1 引用计数的机制

**引用计数（reference counting）**：每个堆对象头部存一个整数（引用数）。操作维护：

- **引用创建**（新指针指向对象）：计数 +1。
- **引用销毁**（指针离开作用域/重新赋值）：计数 -1。
- **计数归零**：立即释放对象（并递归递减其字段的计数）。

```python
a = [1, 2, 3]     # 引用计数 1
b = a             # 计数 2（b 也指向它）
del b             # 计数 1
del a             # 计数 0 → 立即释放
```

<span class="marginnote">Python 用引用计数做主要内存管理（配合分代 GC 清循环引用）：`sys.getrefcount(x)` 可以查看计数。每个对象的「引用计数 +1/-1」在字节码层面自动插入——这就是 Python 里「多一个引用就多一份计数」的开销来源。</span>

## 2 引用计数的优点

- **即时性**：计数归零即释放——内存不被「无人使用的对象」占用，回收时机确定（可预测、可测试）。
- **局部性**：不需要全局扫描——释放只涉及「计数归零的对象」及其字段，开销局部。
- **实现简单**：核心就是「+1/-1」两个操作。
- **确定性析构**：归零时立即执行析构函数——这对「持有文件句柄、锁」等资源很关键（Swift 的 ARC 保证资源随计数归零立即关闭）。<span class="marginnote">引用计数的「确定性」是它相对 GC 的核心优势：GC 的释放时机不确定（要看回收器何时跑），引用计数「引用没了就释放」——对需要精确管理资源（文件、锁、GPU 内存）的场景，确定性至关重要。Swift 选 ARC、Rust 选所有权，都是要「确定时机」。</span>

## 3 循环引用：计数的死穴

**循环引用（reference cycle）**：一组对象互相引用，形成环——每个对象的计数都 ≥1（被环内对象引用着），但整个环已「无人可达」（外部没有指针指向环）。计数永不归零，内存泄漏。

```python
class Node:
    def __init__(self): self.next = None

a = Node(); b = Node()
a.next = b; b.next = a     # 互相引用：形成环
del a; del b               # 但环仍在：计数都还是 1 → 泄漏！
```

**辨析｜易错点：** 循环引用的本质：**「有环」与「不可达」不一致**。引用计数只看到「每个对象被引用了几次」（局部信息），看不出「整个环是否还有人从外部用」（全局信息）。`a`、`b` 各自计数 1（互相引用），但从外部看它们已经没人用了。**「局部计数无法发现全局不可达」**——这是引用计数的结构性缺陷，不是实现 bug。

## 4 公式解析：循环引用的判定

循环引用可以用「可达性」精确说明。设对象集合 $O$，引用关系 $R$（$xRy$ = x 指向 y），外部根集 $G$：

$$
\text{可达}(o) \;\Longleftrightarrow\; \exists\ g \in G,\ \text{路径 } g \to o \text{（沿 } R \text{）}
$$

循环引用组 $C$：

$$
\forall\ o \in C : \text{refcount}(o) \ge 1 \ \text{（计数非零）} \quad \text{但} \quad \forall\ o \in C : \neg \text{可达}(o)
$$

三步拆解：

- **第一步，可达性**：从外部根（全局变量、栈）沿引用出发，能到达的对象是「活」的。
- **第二步，计数的盲区**：环内每个对象计数 ≥1（被环内引用），但环整体不可达——**计数看不出「环外是否还有人用」**。
- **第三步，矛盾**：计数说「有人用」（≥1），可达性说「没人用」（不可达）——引用计数的判定与真实需求冲突，泄漏。**「计数是局部度量，可达性是全局度量」**——引用计数牺牲全局视角换即时性，循环引用是这代价的体现。

**辨析｜易错点：** 循环引用不一定两个对象——三个以上互指同样泄漏（`A→B→C→A`）。**任何环**（长度 ≥2）都会让引用计数失效。而「自引用」（对象指向自身）也是环。**「检测环 ≠ 修环」**——解决要打破环（弱引用）或加周期回收器。

## 5 循环引用的解决方案

**方案一：弱引用（weak reference）**——不增加计数：

```python
class Node:
    def __init__(self):
        self.next = None
        self.parent = None   # 用弱引用打破环

a.next = b
b.parent = a     # 若 parent 是弱引用，b→a 不计数，环被打破
```

Swift 的 `weak`、Python 的 `weakref`、Rust 的 `Weak<T>` 都提供不计数引用。**「弱引用不参与计数——环里至少一条边不计数，环就断了」**。<span class="marginnote">弱引用的语义：指向对象但不「保住」它——对象可能在任何时刻因计数归零而消失。所以使用弱引用前要「升级」为强引用（Swift 的 `guard let x = weakRef else ...`）——「弱引用是观察者，不是保人」。这是打破循环引用的标准手法：<strong>环中一条边用弱引用，其余强引用</strong>。</span>

**方案二：周期回收器（cycle collector）**——GC 式扫描清环：

```python
# Python：gc 模块，分代收集
import gc
gc.collect()   # 手动触发周期回收，清掉循环引用
```

Python、Swift（不，Swift 靠弱引用）、以及带 RC 的 GC 语言用「追踪式回收」补充——从根集出发标记可达对象，把「不可达但计数非零」的环清掉。

## 6 小结

- **引用计数**：每个对象记引用数，归零即释放——即时、确定、局部。
- 优点：即时回收、无需全局扫描、确定性析构（资源管理友好）。
- **循环引用**：互相引用的环计数永不归零——「局部计数看不到全局不可达」，泄漏。
- 解法：**弱引用**打破环（标准手法）、**周期回收器**扫描清环（补充方案）；Swift ARC、Python RC、Rust `Rc`/`Arc` 都以引用计数为基。
