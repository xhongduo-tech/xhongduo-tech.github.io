## 为什么从记录类型开始

数组把「许多同类型值」聚成一个名字；但真实世界的数据几乎都是**异质**的——一个学生有姓名（字符串）、学号（整数）、绩点（浮点）、是否毕业（布尔）。**记录类型（record type）**把这个异质聚合变成类型系统的一等公民：一组**命名字段**，每个字段有自己的类型。它是数据库行、JSON 对象、面向对象「类」的结构雏形。而**元组（tuple）**是记录的匿名、无名字段变体。理解这两者，就理解了「用名字组织异质数据」这一贯穿所有现代语言的基本形态。<span class="marginnote">记录 = 字段名 + 字段类型的映射。学生记录 $\{\text{name}: \text{String}, \ \text{id}: \text{Int}, \ \text{gpa}: \text{Float}\}$ 正是「行的类型」——数据库的每一行、JSON 的每个对象，都是记录的实例。</span>

## 1 记录类型的基本形态

**记录类型（record type）**：由一组**命名字段（field）**组成，每个字段有名字与类型，字段可以是不同类型。

Pascal 是记录类型的鼻祖：

```pascal
type
  Student = record
    name: string;      // 字段：名字 + 类型
    id:   integer;
    gpa:  real;
    graduated: boolean;
  end;

var s: Student;
```

访问用**点记号**：s.name、s.id。字段名就是「下标」——只是它按名字而非位置寻址。<span class="marginnote">点记号 s.name 不是运算符而是「字段投影」的语法糖：把记录映射到它的某个成分。编译器据此知道 name 在记录内的偏移量，s.name 与数组下标 s[i] 一样是编译期可计算的地址。</span>

## 2 记录的三种访问方式

记录字段的访问可以按三种方式实现，体现了「名字寻址」的不同深度：

| 访问方式 | 做法 | 例子 |
| --- | --- | --- |
| 完全限定名 | 把名字逐层写全 | s.name |
| 引用（with/with 语句） | 把记录打开，字段可裸用 | Pascal with s do |
| 结构化引用 | 字段访问合并进表达式 | C s.id、Rust s.id |

**辨析｜易错点：** Pascal 的 with 语句会打开一条「名字隧道」，让 name 在块内裸指 s.name——但若同时存在局部变量 name，优先级容易混淆，被广泛批评为可读性陷阱。现代语言（Rust、Go、Python dataclass）普遍只用完全限定名 + 解构，放弃 with。

## 3 记录的内存布局与比较

**内存布局**：记录字段按声明顺序连续存放，但每个字段要**对齐（alignment）**到其自然边界（如 int 对齐到 4 字节），因此字段之间可能出现**填充（padding）**。<span class="marginnote">struct { char c; int i; } 在 32 位系统上通常占 8 字节而非 5——c 之后有 3 字节填充，让 i 对齐到 4 的倍数。字段重排（field reordering）可把同样结构压到 5 字节对齐到 8。这对网络协议、FFI 与内存敏感系统至关重要。</span>

**相等性比较**：记录能否用 == 比较，取决于语言是否内建「逐字段比较」语义。C 的 struct 不能直接用 ==（要逐字段手写）；Rust 只要字段都可比较，#[derive(PartialEq)] 自动生成逐字段比较；Python dataclass 默认生成。

## 4 元组：匿名记录

**元组（tuple）**：一组**异质值**的聚合，但**字段没有名字**，只按位置访问。它相当于「记录的名字被省去」——适合临时打包、多返回值、一次性数据传递。

```python
point = (3, 5)          # 元组：字段没有名字，按位置访问
x, y = point            # 解构：一次性拆开
```

元组的价值：

**多返回值**：Python 的函数其实「只能返回一个值」，但可以返回元组再解构——多返回值语法糖。
**轻量打包**：不需要为「一次性的两个值」定义一个具名记录。
**解构（destructuring）**：x, y = point 一次性拆开，是现代语言的可读性利器。<span class="marginnote">解构把「聚合」逆向操作：(3, 5) 创建元组，解构赋值 x, y = point 又把它按位置拆回。创建与解构是互逆的一对操作——这是「代数数据类型」精神的最小例子。</span>

**辨析｜易错点：** 元组**按位置**寻址，记录**按名字**寻址。(Int, Int) 与 (Int, String) 类型不同（位置对位置）；而记录 {x, y} 与 {y, x} 顺序无关紧要。可读性差的元组（如函数返回 (int, int, int)）是「魔法数字」式的坏味道——元组越长越该升级为记录/具名结构。

## 5 公式解析：记录的内存布局

记录字段偏移可以逐字段计算。设字段 $f_1, f_2, \dots, f_k$ 依次排列，各自的类型大小为 $s_i$、对齐要求为 $a_i$，则偏移递推：

$$
\text{offset}(f_1) = 0, \qquad \text{offset}(f_i) = \lceil \text{offset}(f_{i-1}) + s_{i-1} \rceil_{a_i}
$$

其中 $\lceil x \rceil_{a}$ 表示把 $x$ 向上对齐到 $a$ 的整数倍。

三步拆解：

- **第一步，第一个字段**：从偏移 0 开始。
- **第二步，递推**：后一个字段的起始位置 = 前一个字段末尾位置向上取整到后一字段的对齐要求。例如 char（大小 1、对齐 1）后跟 int（大小 4、对齐 4）：char 占偏移 0，int 从 $\lceil 0+1 \rceil_4 = 4$ 开始，中间 1–3 字节是填充。
- **第三步，整体对齐**：整个记录的大小须是**最严格对齐**的倍数，以便作为数组元素连续排布。

**辨析｜易错点：** 记录与数组的内存观正好相反——数组元素**同宽**，靠下标算地址；记录字段**异宽**，靠名字查偏移。理解「对齐填充」之后，你会发现网络报文结构体、二进制文件格式的「为什么多出字节」都迎刃而解。

## 6 记录与现代语言的形态

记录类型在现代语言里演化出多种形态——理解家族谱系，看到「同一个思想的不同实现」：

**C 的 struct**：最裸的记录——只有数据，无方法、无访问控制。

**Java 的 record（Java 16+）**：不可变记录——字段 + 构造器 + equals/hashCode/toString 自动生成。**「不可变 + 值语义」的记录**是现代趋势。

**Python 的 dataclass**：@dataclass 装饰器——自动生成 __init__/__repr__/__eq__。**「样板代码自动化的记录」**。

**Rust 的 struct**：可含方法（impl 块）、可派生 trait（#[derive(...)]）——「记录 + 行为」的现代形态。

**JSON 对象**：无类型记录——{"name": "Ada", "id": 1}，动态语言的记录。

| 语言形态 | 特征 |
| --- | --- |
| C struct | 裸数据 |
| Java record | 不可变 + 自动方法 |
| Python dataclass | 样板自动化 |
| Rust struct | 数据 + 行为（trait） |
| JSON | 动态无类型 |

**辨析｜易错点：** **「记录」vs「类」的边界**：记录默认「值语义」（拷贝/比较内容），类默认「引用语义」（共享/比较身份）。Java 的 record 是值语义（equals 比字段）、普通 class 是引用语义（== 比身份）。**「用 record 表达『数据』，用 class 表达『有身份的对象』」**——记录是「结构」，类是「实体」。选错语义，比较/拷贝行为全错。

## 7 小结

- **记录类型**：命名字段 + 各自类型，是数据库行与类结构的雏形，用点记号 s.name 访问。
- 记录字段按名字寻址、靠编译器计算的**偏移**定位；内存有**对齐填充**。
- **元组**是匿名记录，按位置访问，适合临时打包与多返回值；配合**解构**使用。
- 元组按位置、记录按名字；元组太长应升级为记录——可读性的分水岭。
