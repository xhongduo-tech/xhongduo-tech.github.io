## 为什么从块结构开始

词法作用域回答了「名字怎么找」；这一节看它的舞台——**块（block）**与**嵌套子程序（nested subprogram）**如何组织作用域的结构。块把「作用域的范围」精确到一对花括号：`{ int x; ... }` 里声明的 `x` 只活到 `}` 为止。嵌套子程序则让函数内部再定义函数，形成一层层嵌套的作用域。而由此引出一个微妙现象——**作用域空洞（scope hole）**：名字「被遮蔽」时，有一段代码既不能访问外层同名变量，也不能访问内层那个——它在空隙里悬空。<span class="marginnote">块结构是「最小权限」原则在作用域上的体现：<strong>变量应该只存在于它被需要的范围内</strong>。块越小，名字的可见面越窄，读代码的人要记住的上下文越少——这是可读性的物理基础。</span>

## 1 块结构：作用域的原子单位

**块（block）**：一段用括号定界的代码区段，其内部声明的变量只在该区段内可见。<span class="marginnote">C 系的 `{ ... }`、Ada 的 `declare ... begin ... end`、Python 的缩进块、Rust 的 `{ ... }` 都是块。块引入新作用域，内层块可访问外层块的名字。</span>

```c
int a = 1;
{
    int b = 2;      /* b 只在此块内可见 */
    printf("%d %d", a, b);   /* 访问外层 a 与内层 b */
}
/* b 在此处已不可见 */
```

块结构的好处：**临时变量不泄漏**——循环用的 `i`、交换用的 `tmp` 关进块内，不污染外层命名空间。

## 2 嵌套子程序与遮蔽

**嵌套子程序（nested subprogram）**：函数内部定义函数，内层函数可访问外层函数的变量。Pascal、Ada、Python、JS、Rust 都支持嵌套。

```python
def outer(a):
    def inner(b):
        return a + b      # inner 捕获 outer 的 a
    return inner(10)
outer(5)   # 15
```

**遮蔽（shadowing）**：内层声明与外层同名时，内层名字「遮住」外层——在作用域内，`x` 指向内层声明。

```python
x = "global"
def f():
    x = "local"    # 遮蔽全局 x
    return x       # → "local"
```

**辨析｜易错点：** 遮蔽只影响「名字解析」，不影响外层变量本身。遮蔽结束后（离开内层作用域），外层 `x` 恢复可见。Rust 甚至允许**同一块内的遮蔽**（`let x = 1; let x = x + 1;`）——新声明复用名字但生成新变量，这是 Rust 的惯用法（不可变重绑定），与「修改变量」语义不同。

## 3 作用域空洞：被遮蔽的悬空带

**作用域空洞（scope hole）**：当内层声明遮蔽外层同名变量时，内层声明**之前**的那一小段代码处于「空洞」——它想用外层 `x`，但名字已被内层 `x` 占据；想用内层 `x`，但它还没声明。于是 `x` 在此处**无法访问**。

```c
int x = 1;            /* 外层 x */
{
    int y = x;        /* 这里 x 指外层（=1）还是...？ */
    int x = 2;        /* 内层 x 遮蔽从此开始 */
    y = x;            /* 这里 x 指内层（=2） */
}
```

塞贝斯塔指出：在 C 中，`int y = x;`（内层声明前）的 `x` 指**外层** `x`——因为内层 `x` 的**作用域从声明处才开始**。但这一带正是「空洞」：读者和编译器都必须小心区分「声明前」与「声明后」的 `x` 各指谁。<span class="marginnote">多数语言规定「声明的效果从声明点开始」（这称为声明的<strong>可见性起点</strong>），从而避免「在一个作用域里，声明前的同名引用指向未来声明」的荒谬。空洞是这种规定的副产品：它让「遮蔽边界」附近出现一段需要格外留意的区域。</span>

## 4 公式解析：作用域与空洞的区间模型

作用域可以精确建模为「声明点之后、块的结束点之前」的区间。设块 $B$ 的区间为 $[\text{begin}_B, \text{end}_B]$，声明 $d$ 在块内位置 $p_d$，则 $d$ 的作用域：

$$
\text{scope}(d) = [p_d,\ \text{end}_B]
$$

且遮蔽规则：位置 $p$ 处的名字 $x$ 解析到「所有含 $p$ 的作用域中，起点 $p_d$ 最靠后的那个声明 $d$」。

三步拆解：

- **第一步，区间化**：每个声明贡献一个从「声明点」到「块尾」的可见区间——声明之前不可见。
- **第二步，遮蔽取最近**：解析 $p$ 处的 $x$ = 在所有「区间包含 $p$」的声明中取**起点最靠后**（最内层）的那个。这正是词法查找的区间版本。
- **第三步，空洞现身**：若外层 `x` 的区间是 $[p_{\text{outer}}, \text{end}]$，内层 `x` 的区间是 $[p_{\text{inner}}, \text{end}]$（$p_{\text{inner}} > p_{\text{outer}}$），则区间 $[p_{\text{outer}}, p_{\text{inner}})$ 里的 `x` 解析到外层——但这段代码「知道内层即将遮蔽」，阅读时最容易误判。**空洞 = 遮蔽开始前的外层可见带**。

**辨析｜易错点：** 空洞与「未声明」错误不同。空洞里 `x` **有**绑定（外层那个），只是语义微妙；未声明是根本没有绑定。许多语言（如 Python）在函数内出现 `x` 的赋值时，把整个函数体的 `x` 都当作局部——这消除了「空洞」却引入「赋值前引用局部」的 `UnboundLocalError`。**不同语言用不同规则处理「遮蔽边界」**，是移植代码的暗坑。

## 5 现代语言的块结构演化

- **Python**：`def` 引入作用域，但 `for`/`if` 块**不**引入新作用域——循环变量泄漏到函数级。
- **Rust**：任何 `{}` 都是块作用域；`let` 遮蔽成为惯用；块也是**表达式**（块的值 = 末尾表达式的值）。
- **JavaScript**：ES6 前 `var` 无块作用域（只有函数作用域），`let`/`const` 才引入块作用域——历史上著名的坑。
- **Kotlin/Swift**：块作用域 + 便捷的局部解构，遮蔽用得克制。

<span class="marginnote">JavaScript 的 `var` 提升（hoisting）是「无块作用域」时代的产物：`var x` 在函数内任何位置都「提升」到函数顶，声明前引用是 `undefined` 而非报错。ES6 的 `let` 修复了它——但「提升」一词保留下来描述 `let` 的「暂时性死区（TDZ）」。块结构的设计史，就是作用域语义从粗糙走向精确的历史。</span>

## 6 小结

- **块**是最小的作用域单位，把名字的可见范围关进括号；嵌套子程序形成多层作用域。
- **遮蔽**是内层声明遮住外层同名名字，影响解析但不影响外层变量。
- **作用域空洞**出现在「遮蔽开始前」——`x` 指外层但读者易误判，是遮蔽边界的微妙带。
- 作用域可建模为「声明点到块尾」的区间；不同语言对遮蔽边界的处理（提升、TDZ、泄漏）各异。
