## 为什么从名称、变量与值开始

第六篇的主题是「名称、绑定与作用域」，而它真正的起点是三个看似简单却极易混淆的概念：**名称（name）**、**变量（variable）**与**值（value）**。x = 5 这一行里，x 是名称，5 是值，而「变量」到底是哪个？多数初学者把三者当成一回事——这正是后续一切混淆（引用 vs 值、别名、作用域）的根源。塞贝斯塔用一句精辟的话点破：**变量是「名字、地址、类型、值」四位一体**。<span class="marginnote">把变量看成「名称 → 存储单元的映射」而非「值本身」，是理解赋值、传参、别名、作用域的统一钥匙。Python 的「名字绑定」、C 的「变量即地址」、Rust 的「移动语义」——全都是同一套概念的不同摆布。</span>

## 1 名称：一串受约束的字符

**名称（name）**：标识符——程序中用来引用实体（变量、函数、类型、标签）的符号串。

名称的设计问题：

**最大长度**：早期 Fortran 只认前 6 个字符，写 TOTAL_AMOUNT 与 TOTAL_AMOUNTS 可能撞车；现代语言几乎不限长。<span class="marginnote">Fortran 77 的 6 字符限制是历史上真实踩坑的地方——两个长变量名被截断成同一个，编译器却报「重复声明」。现代语言已基本移除长度限制，但「大小写是否敏感」（Count vs count）等规定仍因语言而异。</span>
**大小写敏感**：C/Java/Rust/Python 敏感（Count ≠ count）；Pascal/BASIC 早期不敏感。敏感提升表达力但增加拼写风险。
**特殊连接符**：C 系用下划线 total_amount；Java/Kotlin 用驼峰 totalAmount；Python 风格指南偏爱下划线。
**保留字（keyword）**：if、while 等被语言占用，用户不可用作名称。保留字的取舍影响语言的可扩展性——Ada 允许重定义部分关键字，而 C 把关键字锁死。

## 2 值：可观察的数据

**值（value）**：数据本身——数字、字符、对象、函数……它是「运行时内存里的可观察内容」。

值按**种类（category）**分左值（lvalue）与右值（rvalue）：

**左值（lvalue）**：有地址、可被赋值定位的值——如变量 x、数组元素 a[i]。
**右值（rvalue）**：只有值、没有稳定地址的临时量——如字面量 5、表达式结果 x + 1。<span class="marginnote">「左/右」来源于赋值语句左侧/右侧的位置：x = y + 1 中左侧 x 必须有地址（左值），右侧只需有值。C++11 把右值细分为 prvalue/xvalue，并引入右值引用与移动语义——「值种类」成了现代 C++ 性能的枢纽。</span>

**辨析｜易错点：** 常量与字面量：5 是字面量（右值），const int x = 5 中 x 是左值（有地址）但不可写。**「左值」不等于「可写」，只等于「有地址」**——把 const 变量当「没有地址」是常见误解。

## 3 变量：四属性的统一体

**变量（variable）**：一个抽象存储单元，由四个属性刻画：

| 属性 | 含义 | 绑定时间（下一节） |
| --- | --- | --- |
| **名称（name）** | 如何引用它 | 声明时 |
| **地址（address）** | 存储在哪 | 分配时 |
| **类型（type）** | 能存什么、怎么解释 | 声明/推导时 |
| **值（value）** | 此刻存了什么 | 赋值时 |

变量 = 名称 + 地址 + 类型 + 值。**同一变量在不同时刻值不同，但名称、地址、类型通常稳定**。<span class="marginnote">「变量的值」与「变量的地址」是两回事：x = x + 1 里，右侧读的是 x 的值，左侧写的是 x 的地址指向的存储。一条赋值语句同时用到了「值」与「地址」两面——能分清这一行，你就掌握了变量概念的八成。</span>

## 4 公式解析：变量与绑定的模型

变量可以用「环境 + 存储」的形式化模型精确刻画，这也接上了第三篇的操作语义：

$$
\text{Variable} \;\cong\; \langle \text{name}, \text{address}, \text{type}, \text{value} \rangle
$$

$$
\sigma[\text{addr}] = v \;\Longleftrightarrow\; \text{值 } v \text{ 存于地址 addr}
$$

三步拆解：

- **第一步，四元组**：变量不是一个「东西」而是一组属性。名称用于源码引用，地址用于运行定位，类型决定解释方式，值是当前内容。
- **第二步，存储函数**：存储 $\sigma$ 是「地址 → 值」的映射。读 x = 先查名称得地址，再查存储得值；写 x = 更新存储在该地址的映射。
- **第三步，分离名称与地址**：名称查地址是**绑定（binding）**问题（第六篇核心），地址查值是**存储**问题。两者分离后，「别名」（两个名称同一地址）、「悬垂」（名称对应已释放地址）都成了清晰可说的现象。

**辨析｜易错点：** 「引用（reference）」与「值」的混淆是重灾区。y = x 到底把 x 的**值**拷给 y，还是让 y **引用** x？C 的值语义（拷贝）、Java/Python 的引用语义（共享对象）、Rust 的移动语义（所有权转移）给出三种答案——**同一个 y = x，三种含义**。理解名称/变量/值三元组，是看懂这些差异的基础。

## 5 从概念到语言设计

- **值语义**（C、C++、Go 结构体）：变量直接持有值，赋值即拷贝。
- **引用语义**（Java、Python、JS）：变量持有「指向对象的引用」，赋值复制引用（对象共享）。
- **移动语义**（Rust）：值有唯一所有者，let y = x 默认移动（转移所有权）而非拷贝——由类型系统保证「谁拥有、能活多久」。<span class="marginnote">Rust 把「名称、地址、值」之外再加一个「所有权」属性，并用编译期规则管理。它证明：把变量模型想清楚，可以设计出既无 GC 也无悬垂的语言——这是变量概念在当代最深刻的运用。</span>

## 6 一个例子：别名与「变量的身份」

用「名称/地址/值」三件套重新解读两个经典现象：

**别名（aliasing）**：两个名称绑定到**同一个地址**。

```python
a = [1, 2]
b = a          # 别名：b 与 a 绑定到同一个列表对象
b.append(3)    # 改 b 就是改「那个对象」，a 也「看见」
```

用四元组看：a 与 b 的「名称、地址」不同，但「地址指向的存储」相同——所以改 b 就是改「那个地址」，a 也「看见」。**「别名 = 名称不同但地址相同」**——这是指针/引用语义下最常见的变量现象。

**左值右值的身份**：

```c
x = x + 1;   // 右侧 x 是右值（取值），左侧 x 是左值（定位）
```

**「同一条语句里，同一个名字 x 扮演两个角色」**——右侧是「取值」（右值），左侧是「定位」（左值）。区分名称的「值」与「地址」两面，这条语句就完全清晰了。

**辨析｜易错点：** 「变量与值混为一谈」的后果：b = a 后以为「拷贝了一份」，实际是「共享了地址」——这是 Python/Java 新手最常见的 bug 来源。「看语言语义：b = a 是拷贝（C 值语义）还是共享（Java/Python 引用语义）」——判断准了，别名行为就可预测。

## 7 小结

- **名称**是受约束的标识符，涉及长度、大小写、保留字等设计取舍。
- **值**按种类分**左值**（有地址）与**右值**（无地址）；左值 ≠ 可写。
- **变量**是「名称 + 地址 + 类型 + 值」的四元组；读是查地址取值，写是改地址指向的存储。
- 值语义、引用语义、移动语义是三种「=」的实现哲学；别名、悬垂都源于「名称与地址」的分离。
