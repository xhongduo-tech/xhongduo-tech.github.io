## 为什么从 Haskell 开始

如果说 Scheme 是函数式语言的「极简派」，**Haskell** 就是「学院派巅峰」：纯函数、惰性求值、强静态类型 + 类型推导（Hindley-Milner）、以及两个标志性机制——**类型类（type class）**与**模式匹配（pattern matching）**。Haskell 把函数式编程的原则推到极致：没有副作用（一切 IO 用 Monad）、没有循环（一切用递归/高阶函数）、类型推导到几乎不用写类型。理解 Haskell，就理解了「纯函数式 + 强类型」能走多远——它也是 Rust 的 trait、Swift 的协议等现代机制的思想源头。<span class="marginnote">Haskell 的名字致敬哈斯凯尔·柯里（Haskell Curry）——逻辑学家，柯里化（currying）以他命名。它是学术型语言，但「纯粹 + 强类型」的设计成为现代语言（Rust/Swift/Kotlin）吸收函数式特性的蓝本。</span>

## 1 纯函数与类型推导

Haskell 是**纯函数式**的：函数无副作用、表达式引用透明（前面几节已述）。它同时有**强大的类型推导**——几乎不用写类型注解：

```haskell
square x = x * x        -- 类型自动推导为 Num a => a -> a
factorial n = product [1..n]
```

`square` 的类型 `Num a => a -> a` 是「对任何数值类型 a 都成立」——**最一般的类型**（HM 主类型），由编译器推导而非手写。<span class="marginnote">Haskell 的类型推导让「无注解强类型」成为现实：你不需要写 `Int -> Int`，编译器从 `*` 的约束推出 `a` 必须是数值类型（`Num a`）。「少写类型 + 强类型检查」兼得，是 HM 系统（第五篇）的实践回报。</span>

## 2 类型类：受约束的多态

**类型类（type class）**：定义一组「操作」，声明「哪些类型实现了这些操作」。它是 Haskell 对「重载/接口」的解决方案——**受约束的参数多态**。

```haskell
class Eq a where
    (==) :: a -> a -> Bool      -- 类型类声明：任何实现 == 的类型

instance Eq Int where
    (==) = intEq                -- Int 实例

-- 受约束的泛型函数：只要求 a 可比较
member :: Eq a => a -> [a] -> Bool
```

`Eq a =>` 读作「对任何实现了 Eq 的类型 a」——函数既能泛型（对所有 Eq 类型通用）又能在函数体里用 `==`。<span class="marginnote">类型类解决 Haskell 的「重载」问题：`+` 对 `Int` 与 `Float` 都可用，靠 `Num` 类型类为两者各提供实例。这与 Rust trait（`T: Ord`）、Swift 协议几乎同构——Rust 的 `T: Trait` 正是 Haskell `TypeClass a =>` 的语法变体。「受约束多态」是「通用算法 + 能力约束」的完美结合。</span>

## 3 模式匹配：按形状取数据

**模式匹配（pattern matching）**：用「数据结构的样子」直接绑定变量、分派分支——取代「取字段 + 判条件」的命令式套路。

```haskell
factorial :: Integer -> Integer
factorial 0 = 1                -- 匹配「0」这个形状
factorial n = n * factorial (n-1)   -- 匹配「任意 n」

-- 列表模式
sumList :: [Int] -> Int
sumList []     = 0             -- 空表
sumList (x:xs) = x + sumList xs    -- 头 x、尾 xs 直接解构
```

模式匹配的价值：**定义即分派**——每个模式一行，逻辑清晰；且编译器检查**穷尽性**（漏模式报警告）。<span class="marginnote">模式匹配把「取头取尾 + 判断空表」压缩成一个 `(x:xs)` 模式——一次绑定 `x`、`xs` 并判定「非空」。它是 Scheme 里 `car`/`cdr`/`null?` 的声明式升级，也是 Rust `match`、Python `match` 的直接祖先。「按形状取数据」取代「按函数拆数据」。</span>

## 4 公式解析：类型类的判定

类型类约束在类型推导中的角色可以用 HM 扩展刻画。设类型类 $C$，实例关系 $T \;\text{inst}\ C$，则受约束的泛型函数：

$$
f : \forall a.\ C\ a \Rightarrow \tau
$$

含义：「对任何**满足约束 $C\ a$** 的类型 $a$，$f$ 具有类型 $\tau$」。调用 `f v` 时：

$$
\frac{\Gamma \vdash v : T \qquad T \;\text{inst}\ C}{\Gamma \vdash f\ v : \tau[T/a]}
$$

三步拆解：

- **第一步，约束引入**：`Eq a => ...` 中 `=>` 前是约束——`a` 必须是 `Eq` 的实例才能用 `==`。
- **第二步，调用检查**：用具体类型 $T$ 调用 `f` 时，编译器检查 $T$ 是否**实现了**类型类 $C$——`member 5 [1,2]` 要求 `Int` 实现 `Eq`（内建，通过）。
- **第三步，看多态**：约束让「多态」与「重载」合一——`f` 对所有满足约束的类型通用（多态），且能调用约束提供的操作（重载）。**「类型类 = 参数多态 + 受控的特设多态」**是 Haskell 对多态问题的最终答案。

**辨析｜易错点：** 类型类 ≠ 面向对象的类。类型类是**开放接口**（可对任何类型添加实例，包括你无法改动的类型），面向对象类是**封闭层级**（只能对子类）。**「实例与类型分离」是类型类的威力**：可以给 `Int` 实现自定义类型类——在 OO 语言里做不到（无法给 `int` 添加方法）。Rust 的 `impl Trait for Type` 继承了这一「孤儿规则」思想。

## 5 Haskell 的现代影响

- **Rust**：trait = 类型类 + 方法 + 关联类型；`T: Ord` 约束即 `Ord a =>`。
- **Swift/Kotlin**：协议/接口的默认实现接近类型类。
- **Scala**：implicit 参数 + type class 模式——直接移植。
- **类型驱动开发**：Haskell 的「先写类型签名，再填空实现」被广泛采纳为「类型先行」方法论。<span class="marginnote">Haskell 最重要的遗产不是语言本身，而是「<strong>类型即文档 + 编译即检查</strong>」的信念：一个能编译的类型正确的函数，比一百个「看起来对」的函数可靠。现代「类型驱动」开发、Rust 的「如果编译通过就没问题」文化，都从这里生长。</span>

## 6 小结

- Haskell = **纯函数 + 惰性 + 强静态类型**；类型推导让「少写类型 + 强检查」兼得。
- **类型类** = 受约束的多态（`Eq a => ...`），把「通用算法 + 能力约束」结合，是 Rust trait 的源头。
- **模式匹配**按形状取数据、定义即分派；编译器检查穷尽性。
- 类型类区别于 OO 类：开放接口（实例与类型分离）；Haskell 的「类型先行」文化深刻影响现代语言。
