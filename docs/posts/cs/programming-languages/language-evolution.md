## 为什么从演化史开始

上一节讲完三种实现方法，这一节把镜头拉远，看一部完整的历史。**语言不是凭空设计的，它们是一连串「问题—答案」的堆积**：每个时代有它的痛点，痛点催生语言，语言反过来固化那个时代对「好程序」的理解。读懂演化史，等于拿到了所有现代语言的「族谱」——你会发现 Python 的缩进、Java 的字节码、Rust 的所有权，各自都有一段可以追溯到几十年前的「血统」。

## 1 起点：Plankalkül（1945）

第一门被设计的**高级语言**不是 Fortran，而是德国工程师**楚泽（Konrad Zuse）**在 1945 年设计的 **Plankalkül**（德语「计划演算」）。从 1945 到 1957 年的这十二年，没有任何一门高级语言真正运行起来——这段「纸面时代」里，计算机只能靠机器码与汇编驱动。它在纸面上已经具备现代语言的特征：变量与类型、数组与嵌套数据结构、条件与循环、子程序。但它在当时**从未被实现**——计算机尚未造出来，更无人给它写编译器——直到 1998 年才有人为它实现了编译器。<span class="marginnote">Plankalkül 的「纸面先行」是个绝佳寓言：语言设计可以走在机器实现之前半个世纪。楚泽同时是通用计算机 Z3（1941）的发明者，一个人同时完成了「造机」与「造语言」两件事。</span>

楚泽并没有把自己限制在「翻译机器指令」上，而是直接思考「人怎样表达计算」——变量要有名字、数据要分类型、运算要能嵌套。这些想法在他那个时代过于超前：他 1945 年的手稿要等到 1972 年才正式发表，编译器则要等到 1998 年才出现。**Plankalkül 证明了「语言」与「机器」可以各自独立生长**——这也解释了为什么今天的我们仍在使用七十年前的设计词汇。

**辨析｜易错点：** 演化史不是「越新越好」的直线进步。Plankalkül 的一些数据结构思想甚至领先于它之后许多年的语言；而 1945—1957 年间的「语言真空期」，程序员只能用机器码与汇编。高级语言是「稀缺发明」，不是「必然涌现」。

## 2 1950 年代：科学计算与列表处理

**Fortran（1957，巴科斯 / IBM）**：第一个被**广泛使用**的高级语言。名字来自 Formula Translation（公式翻译），目标是把科学计算的公式直接写成程序。它引入了变量名、算术表达式、数组与循环，让程序员告别汇编——代价是早期版本控制流极其简陋，只有 **`DO`** 循环与 **`IF`** 语句。Fortran 至今仍是数值计算领域的主力，这本身就是语言生命力的写照。

**Lisp（1958，麦卡锡 / MIT）**：第一个**函数式**语言。名字来自 LISt Processing（表处理）。它的设计直接取材于 λ 演算：程序由「表达式」组成，数据是「表」，一切皆可递归。Lisp 还带来了**自动垃圾回收**——比 Java 早了三十年。如果说 Fortran 让机器服从「计算」，Lisp 让机器服从「思维」。

**COBOL（1960）**：面向**商业数据处理**。由葛丽丝 · 霍普团队的 FLOW-MATIC 演化而来，语法刻意贴近英文，记录（record）与字段（field）的数据结构成为商业编程的基石。<span class="marginnote">COBOL 是「设计给非程序员看的程序」的早期尝试——目标读者是经理而不是工程师。它至今仍在银行与保险的核心系统中运行，是「老而不死」的极端样本。</span>

五十年代的三大分支由此定型：**Fortran 代表科学计算、Lisp 代表符号处理与智能、COBOL 代表商业数据处理**。三条支流日后各自开枝散叶——Fortran 的血脉流入 C 与数值计算，Lisp 的血脉流入 Scheme、Haskell 与函数式编程，COBOL 的血脉流入记录、数据库与「数据结构」这门学科——直到今天仍能一一辨认。

## 3 1960 年代：ALGOL 60 与「语言的语法革命」

**ALGOL 60（1960）**是语言史上最被低估的里程碑。它由国际委员会设计，首次系统化了几项后来所有语言都离不开的机制：

**块结构（block structure）**：变量可以在任意嵌套的块中声明，作用域随之嵌套；
**递归（recursion）**：子程序可以调用自己；
**BNF 文法**：用巴科斯-诺尔范式精确描述语言语法——语言第一次有了「元语言」级别的自我描述。

ALGOL 60 本身几乎没有大规模商用，但它成了「语言的语言」：Pascal、C、Java 直到今天的无数语言，语法上都写着 ALGOL 60 的血统。<span class="marginnote">ALGOL 60 是「学术语言没有商业成功、却统治了所有后来者」的极端案例。它的 BNF 描述方式至今仍是《语法描述》篇的主线——本专题第二篇《语法描述》将从 BNF 讲起。</span>

同一时期还有两个重要角色：**APL（艾弗森）**把数组运算推向极致，一行 **`+/A`** 能表达一个完整矩阵求和；**PL/I** 试图「一个语言解决所有问题」，结果因为过于庞大而失败——「什么都想做」成了反面教材。

ALGOL 的后继者们也演示了两种相反的方向：**ALGOL 68** 追求语言理论的极致完备，设计报告晦涩难懂，结果被拒绝广泛采用；沃斯则反其道而行，从 ALGOL 里抽出最简的核，造出 **Pascal**。**「简洁才可传播」与「完备才可信」之间的拉扯，是此后每一次语言设计的暗线**——它甚至有了一个名字：复杂度的膨胀永远比语言的实际需求快半步。

ALGOL 60 还埋下了结构化编程的种子：它的块结构与 **`if`**/**`for`** 语句，正是迪科斯彻在《Go To Statement Considered Harmful》（1968）里倡导的「顺序、选择、循环」三结构的语法雏形——**方法学往往要落后于语法十年，才能把语法真正用起来**。

## 4 1970 年代：结构化、Pascal、C 与面向对象的种子

**Simula 67（1967，挪威）**：第一个**面向对象**语言。达尔与尼高为了仿真离散事件，发明了「类」与「继承」——今天 Java、C++ 的核心机制，来自一个仿真语言。Simula 的诞生颇具戏剧性：它起源自造船厂的仿真项目，为了模拟「一艘船的状态」，需要一种把「数据 + 行为」绑在一起的机制——**面向对象不是理论先行，而是被工程需求逼出来的设计**，这与 ALGOL 60 的「委员会式」诞生形成鲜明对照。
**Pascal（1971，沃斯）**：面向教学的结构化语言，把 ALGOL 的块结构翻译成清晰、严格的语法；**Modula-2、Oberon** 是沃斯「极简主义」的延续。
**C（1972，里奇 / 贝尔实验室）**：为写 Unix 而生。指针、位运算、几乎零运行时开销，让它成为系统编程的统治者。C 的成功说明：**当性能与可控性是硬需求时，「简单直接」胜过「安全周到」。**
**Prolog（1972，法国马赛）**：逻辑式程序设计的代表，程序由事实与规则构成，计算交给**归结推理**——它是第十三篇《逻辑式编程》的主角。

C 与 Unix 的组合是语言史上罕见的「语言与操作系统互相成就」：Unix 用 C 重写，C 借助 Unix 扩散。C 的设计哲学——信任程序员、提供最小抽象、让代价可见——至今仍是系统编程绕不开的参照系。Pascal 与 C 的对比则定格了 70 年代的另一场辩论：**教学语言追求正确性，系统语言追求直接性**，两条路线各有拥趸，一直延续到今天。

如果把 70 年代挑一句总结：**语言的多样性第一次全面展开——结构化、面向对象、逻辑式三条新路线同时发芽**，十年后它们各自长成参天大树。

## 5 1980—1990 年代：面向对象成熟、Web 与多范式爆发

这二十年是语言数量的大爆发：Smalltalk、Ada、C++、Python、Java、JavaScript、Ruby、Haskell 接连登场，几乎每两年就有一门改变格局的语言。它们不再执着于发明「新范式」，而是把已有范式**融合**进一门实用语言——多范式从此成为主流。

**Smalltalk（1980，艾伦 · 凯 / Xerox PARC）**：纯面向对象——「一切都是对象，一切皆可消息传递」，把 Simula 的类与继承推向哲学化。
**Ada（1983，美国国防部）**：为超高可靠性而生，引入强类型、异常处理、并发任务。它极其昂贵与庞大，却证明了「可靠是可以被设计进语言的」。
**C++（1983，斯特劳斯特鲁普）**：把面向对象「加」到 C 之上，同时保留指针与零成本抽象，成为高性能 OO 的代表。C++ 的多范式（过程式 + OO + 泛型）预告了 90 年代的趋势。
**Python（1991，范罗苏姆）**：多范式脚本语言——命令式、面向对象、函数式写法并存，缩进即语法块，可读性被当作第一设计目标。它刻意「少即是多」：没有 C 那样的多种整数宽度，没有强制类型声明，把「一种明显的方式」当作设计信条，最终成为胶水语言与 AI 时代的默认语言。
**Java（1995，高斯林 / Sun）**：面向对象 + 字节码 + 自动垃圾回收，实现「一次编写，到处运行」。它有意删掉 C++ 里危险的部分——多继承、运算符重载、指针——借着 Web 热潮成为企业级编程的标准。
**JavaScript（1995，艾希 / 网景）**：为浏览器而生，10 天设计完成，如今靠 V8 引擎与 JIT 成为最广泛部署的语言。<span class="marginnote">JavaScript 是「设计缺陷也能靠生态救活」的样本：它诞生 10 天、满是历史包袱，但 Web 的平台地位让它无可替代——2020 年代它仍是 GitHub 上最活跃的语言之一。</span>
- **Haskell（1990）**：纯函数式 + 惰性求值 + 类型类，把类型系统推向高阶；**Perl、Ruby** 同时期也各据一方。

## 6 21 世纪：并发与安全的新一轮

多核处理器普及让「并发」成为中心词，内存安全问题让「安全」重新成为卖点：

- **Go（2009，Google）**：由肯·汤普森、罗布·派克与格里塞默设计，语法刻意回到 1970 年代的极简，却用 goroutine 与 channel 让并发成为语言的一等公民——它是第十四篇《并发程序设计》中 CSP 模型的代表。
- **Rust（2015 稳定，Mozilla）**：**所有权系统**在编译期保证内存安全、无需垃圾回收，试图同时拿到 C 的性能与 Java 的安全——它从函数式语言借来模式匹配与代数数据类型，从 C++ 借来零成本抽象，从类型论借来生命周期，是「交叉授粉」时代最典型的混血儿。第十五篇《内存管理》将系统分析它。
- **TypeScript（2012，微软）**：给 JavaScript 加上**渐进类型**；**Kotlin、Swift** 则在新一代移动与服务端场景里重拾类型安全与表达力。

另一个正在发生的趋势是「渐进」：类型不再是「全有或全无」，而是可以一点点补上。TypeScript、Python 的 mypy、Ruby 的 Sorbet，都在证明**动态语言的灵活与静态语言的安全可以渐进调和**——这个主题在第五篇《类型系统深入》里会反复出现。

值得注意的是这一轮的**交叉授粉**：Rust 从 Haskell 借来类型推导，从 C++ 借来零成本抽象；TypeScript 把类型重新「织回」动态语言；Go 刻意回到 1970 年代的极简；Swift 把函数式的高阶函数放进命令式外壳。**语言不再各守山头，而是互相剽窃被验证的好主意**——「多范式融合」从例外变成了默认。语言设计者不再问「我是哪一派的」，而只问「这个特性对使用者是否有净收益」——功利主义取代了教条主义。

## 7 公式解析（本章以「核心对比表」替代）：演化史 = 设计问题的答案史

把七十多年压成一张表，每个时代一列：

| 时代 | 核心痛点 | 答案（语言） | 固化下来的语言特性 |
| --- | --- | --- | --- |
| 1945—1950s | 机器码难写 | Plankalkül、Fortran | 变量、表达式、数组 |
| 1950s | 科学计算 / 符号处理 | Lisp、COBOL | 递归、表、垃圾回收、记录 |
| 1960s | 语法混乱、无统一描述 | ALGOL 60 | 块结构、BNF、递归子程序 |
| 1970s | 控制流不可控 | Pascal、C、Simula 67 | 结构化语句、指针、类与继承 |
| 1980s | 可靠性与大规模 | Ada、C++、Smalltalk | 强类型、异常、面向对象、泛型 |
| 1990s | Web 与多范式 | Python、Java、JavaScript | 字节码、GC、脚本化、动态类型 |
| 2000s+ | 并发与内存安全 | Go、Rust、TypeScript | goroutine、所有权、渐进类型 |

三步读表：

- **第一步，读「核心痛点」列**：每个时代有一个「最痛的点」。1950s 是「从汇编解放」，1970s 是「控制流失控」，2000s 是「并发与内存安全」。语言是痛点的影子。
- **第二步，读「答案」与「特性」两列**：特性不是凭空发明，而是「把答案固化进语法」。结构化编程 → **`if`**/**`while`**；数据抽象 → 类；并发 → goroutine；安全 → 所有权。这条规律在《影响语言设计的因素》里已经反复出现。
- **第三步，读横向连续性**：每一行的特性都**继承**了上一行——Java 有 ALGOL 的块结构、Simula 的类、Smalltalk 的消息与 GC；Rust 有 C 的指针思维与 Haskell 的类型推导。**语言演化不是替换，而是叠加**：新语言吸收旧语言被证明有效的特性，再为新时代补上新答案。

把这张表再读一遍，你会注意到一件事：**没有任何一行是「凭空」出现的**——每门语言的说明书里都写着前人的名字。这就是为什么学习语言原理要从历史开始：历史不是背景板，而是**设计决策的数据库**。当你将来面对一门新语言，最先要问的不是「它有哪些新语法」，而是「它继承了谁、背叛了谁、为哪个痛点而生」。

所以，与其背下每一门语言的年份，不如记住那条唯一的轴：**每一个特性都是某个时代对某个痛点的回答，而这个回答会被下一代语言继承、改造或抛弃。** 记住这条轴，演化史就不再是年代列表，而是一部「问题如何流动」的历史。

## 8 小结

- 语言史是一部「**痛点—答案**」史：Plankalkül（1945）纸上先行，Fortran / Lisp / COBOL 奠定三大分支，ALGOL 60 带来语法革命。
- **Simula 67 → Smalltalk → C++ → Java → Kotlin** 是面向对象的一条血脉；**Lisp → Scheme → Haskell** 是函数式的另一条血脉。
- 演化不是线性进步而是**继承叠加**：现代多范式语言同时身兼命令式、面向对象、函数式三种血统。
- 21 世纪的新痛点是**并发与内存安全**，Go 与 Rust 是这一轮的代表答案。
