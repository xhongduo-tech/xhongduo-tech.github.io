## 为什么从模板元编程开始

宏是「语法层」的编译期代码生成，反射是「运行期」的元编程；**模板元编程（template metaprogramming, TMP）**是「类型层」的编译期计算——用**类型**作为「数据」、用**模板实例化**作为「计算」，在**编译期**完成计算与代码生成。它由 C++ 的模板系统意外发现（1990 年代模板图灵完备的发现），如今是 C++、Rust、D 语言「零成本抽象」的基石：`constexpr`、编译期哈希、类型级算法——把「运行期成本」降到零。这一节讲 TMP 的基本机制、编译期计算、以及它的价值与代价。<span class="marginnote">TMP 的发现是「意外之喜」：C++ 模板本意是泛型（`vector<int>`），但模板的特化与递归让它意外地<strong>图灵完备</strong>——能表达一切计算！「用模板写程序」成为可能：输入是类型，输出是类型，过程是递归模板实例化。</span>

## 1 模板的基本机制

**模板（template）**：参数化的类型/函数——用类型参数实例化出具体版本。

```cpp
template <typename T>   // 泛型函数
T max(T a, T b) { return a > b ? a : b; }

int x = max(3, 5);        // 实例化 max<int>
double y = max(3.0, 5.0); // 实例化 max<double>
```

**模板实例化**：每个具体类型生成一份专用代码（单态化，前面讲过）——编译期生成、运行期零开销。<span class="marginnote">模板实例化是「编译期生成代码」：`max<int>` 与 `max<double>` 是两份不同的机器码。这既是「零成本抽象」（与手写等价），也是「代码膨胀」的来源（每类型一份）。模板让「泛型」与「性能」兼得——Rust 泛型继承了这个设计。</span>

## 2 模板元编程：用类型做计算

**模板元编程（TMP）**：模板的特化 + 递归，让**编译期**完成「类型计算」——输入类型、输出类型。最经典例子：编译期计算阶乘。

```cpp
template <int N>
struct Factorial {
    static constexpr int value = N * Factorial<N-1>::value;  // 递归
};

template <>
struct Factorial<0> {
    static constexpr int value = 1;   // 基线
};

// 编译期就算出 5! = 120
static_assert(Factorial<5>::value == 120);
```

「计算」发生在**编译期**：`Factorial<5>::value` 在编译期递归展开（`5 * 4 * 3 * 2 * 1 * 1`）——运行期只是一个常量 120。<span class="marginnote">TMP 的「计算模型」：<strong>模板递归 ≈ 循环，模板特化 ≈ 条件分支，类型 ≈ 值</strong>。`Factorial<N>` 递归实例化到 `Factorial<0>` 停止——这是「函数式递归」在类型层的投影。「编译期算 vs 运行期算」——同样的逻辑，TMP 把它提前到编译期，运行期零成本。</span>

## 3 编译期计算：constexpr 与现代 C++

C++11 起，`constexpr` 让「普通函数也能编译期求值」——TMP 从「模板递归」扩展为「直接写编译期可算的函数」：

```cpp
constexpr int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n - 1);
}
constexpr int f5 = factorial(5);   // 编译期算好，运行期常量
```

现代编译期计算的生态：

- **`constexpr`**：编译期求值（C++14 起可含循环、可变）。
- **编译期哈希**：`constexpr` 计算哈希，作为模板参数。
- **类型特征（type traits）**：`std::is_integral<T>`——编译期判断类型性质，配合 SFINAE/`if constexpr` 选择实现。
- **`if constexpr`**（C++17）：编译期分支——按类型条件生成不同代码。<span class="marginnote">「编译期计算」的价值：<strong>把运行期成本移到编译期</strong>——哈希表在编译期构建、正则表达式在编译期编译、类型检查在编译期完成。代价是<strong>编译时间变长</strong>（编译器替你跑程序）。现代 C++ 用 `consteval`（必须编译期）、`consteval` 库（编译期容器）把这个能力进一步正规化。</span>

## 4 公式解析：TMP 的递归模型

TMP 可以形式化为「类型级函数」。设模板 $F$ 对参数 $N$ 递归计算值 $V(N)$：

$$
V(0) = 1 \quad \text{（特化基线）}
$$

$$
V(N) = N \times V(N-1) \quad \text{（递归实例化）}
$$

编译器在编译期展开：

$$
\text{Factorial<5>} \to 5 \times \text{Factorial<4>} \to \dots \to 5 \times 4 \times 3 \times 2 \times 1 \times \text{Factorial<0>} \to 120
$$

三步拆解：

- **第一步，基线特化**：`Factorial<0>` 专门特化为 1——递归的终止条件，对应函数式递归的「底」。
- **第二步，递归实例化**：`Factorial<N>` 触发 `Factorial<N-1>` 的实例化——**每次实例化是一次「编译期函数调用」**。
- **第三步，展开求值**：编译期把所有递归展开成常量表达式——最终 `Factorial<5>::value` 编译期就是 120。**「TMP = 编译期的函数式递归」**：模板实例化是调用、特化是分支、`::value` 是返回值。

**辨析｜易错点：** TMP 的「图灵完备」是理论上的——但**实例化深度有限**（编译器资源限制），写太深的递归模板会「模板实例化深度超出最大值」编译错误。**「编译期计算有资源上限」**——它不是无限的，深度、展开量都受编译器限制（现代 C++ 用 `constexpr` 更自然地表达编译期计算）。

## 5 模板元编程的现代形态

- **C++**：模板 + `constexpr` + `if constexpr` + 类型特征——现代 C++ 用「编译期函数」替代「模板黑魔法」，可读性大幅提升。
- **Rust**：`const fn`——编译期可调用的函数；泛型 + trait 实现「类型级编程」（关联类型、const 泛型 `[T; N]`）。
- **D**：`static if`、`static foreach`、CTFE（编译期函数执行）——内置的模板元编程。
- **依赖注入 / 框架代码生成**：编译期生成「样板代码」的替代方案（对应反射的「编译期」路线）。<span class="marginnote">TMP 的进化方向：<strong>从「类型级黑魔法」到「编译期普通代码」</strong>。C++ 从模板递归（难读）走向 `constexpr` 函数（像普通代码），Rust 用 `const fn` 让编译期计算「平凡化」。「编译期计算」本身的价值（零成本、提前验证）不变，表达方式越来越平易近人。</span>

## 6 小结

- **模板** = 参数化类型/函数，实例化生成专用代码——零成本抽象的基石。
- **TMP** = 用类型做编译期计算：模板递归（循环）+ 特化（分支）——图灵完备的「类型级程序」。
- **编译期计算**：`constexpr`/`const fn` 让普通函数编译期求值——运行期成本归零。
- TMP 是「编译期函数式递归」；代价是编译时间与实例化深度限制；现代方向是「编译期普通代码」（constexpr/const fn）。
