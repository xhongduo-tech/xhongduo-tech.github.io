## 为什么从原始数据类型开始

类型系统是一座金字塔，塔尖是各种复杂的复合类型与用户自定义类型，而塔基是**原始数据类型（primitive data type）**——语言直接内建、不可再按用户意志分解的那些类型。它们是编译器的第一等公民：寄存器、指令、字长都由它们定义。理解原始类型，本质是理解「计算机如何表示数、字符与真假」——这直接对应第二级《计算机组成原理》里数的机器表示，也是后续一切类型构造的地基。<span class="marginnote">原始类型的每一个选择都是「精度与性能」的权衡：更大的字长容纳更多数值但更占存储、更慢；更多位的浮点更精确但更昂贵。类型设计的历史就是一部权衡史。</span>

## 1 数值类型：整数

整数的核心是**字长**与**符号**，它们共同决定了取值范围：有 $n$ 位的二进制整数，无符号范围 $[0, 2^n - 1]$，补码有符号范围 $[-2^{n-1}, 2^{n-1}-1]$。<span class="marginnote">绝大多数现代语言用<strong>补码（two's complement）</strong>表示有符号整数：$n$ 位补码中最高位是符号位，运算可统一按无符号加法硬件完成。溢出后结果回绕——这是许多安全漏洞的根源。</span>

各语言的整数族系略有差异：

| 语言 | 整数类型 | 特点 |
| --- | --- | --- |
| C | `short`/`int`/`long` | 宽度依平台而定，最小保证 16/16/32 位 |
| Java | `byte`/`short`/`int`/`long` | 宽度**固定**（8/16/32/64 位），跨平台一致 |
| Python | `int` | 任意精度，自动扩位，无溢出 |
| Rust | `i8`/`u8`/`i32`/`u64` | 前缀 `i`/`u` 显式声明符号与位宽 |

Python 的任意精度是「溢出问题」的解法，代价是每个整数都是堆对象，性能远低于原生定宽整数——这正是 NumPy 用定宽 `int64` 数组提速的原因。<span class="marginnote">同一门语言里「数学整数」与「机器整数」是两种东西：Python 的 `int` 接近数学整数，C 的 `int` 是机器整数。理解自己在用哪种，是避免溢出 bug 的第一前提。</span>

## 2 数值类型：浮点数

浮点数用「符号 + 指数 + 尾数」表示 $v = (-1)^s \times 1.f \times 2^{e}$，现代语言普遍遵循 IEEE 754 标准：32 位单精度（float）、64 位双精度（double）。<span class="marginnote">IEEE 754 还定义了特殊的 `NaN`（非数）、`±Infinity`（无穷）与 `-0`。这些「值」不是实数——它们的存在让浮点运算总有一个结果，而不是崩溃。检查 `x == NaN` 永远为假，是新手第一个踩的坑。</span>

浮点数的三个性格：

- **不精确**：二进制无法精确表示 $0.1$，`0.1 + 0.2` 在多数语言里是 `0.30000000000000004`。<span class="marginnote">不是语言 bug，是「用二进制表示十进制小数」的必然。处理金钱要避免浮点，改用定点或十进制类型——这是领域知识的反哺。</span>
- **范围悬殊**：双精度能表示约 $[10^{-308}, 10^{308}]$，但相邻可表示数之间的间距随数量级增长——大数附近「密度」急剧下降。
- **运算不再结合**：$(a + b) + c \neq a + (b + c)$ 在浮点下常见，因为中间结果要舍入。

## 3 字符与布尔

**字符（character）**：早期语言用单字节存字符（ASCII，$0$–$127$），无法表达中文等。现代语言普遍采用 **Unicode**：Java 的 `char` 是 16 位 UTF-16 码元，Python 3 的 `str` 是 Unicode 码位序列，Rust 的 `char` 是 32 位码位。<span class="marginnote">字符、码位（code point）、码元（code unit）是三个不同概念：`'😀'` 是一个码位，但在 UTF-16 里占两个码元——Java 的 `char` 装不下它。这也是「字符长度」在跨语言时对不上的根源。</span>

**布尔（Boolean）**：只有 `true`/`false`。关键的设计分歧在于布尔与整数的关系：C 语言早期没有布尔类型，用 `0` 与**非零**充当真假，`if (x)` 的含义是「x 非零」；而 Java、Python、Rust 强制 `if` 的条件必须是布尔值，`if (x)` 在 Java 中直接编译错误。<span class="marginnote">「条件是否必须是布尔」是语言血统的分水岭：C 系（允许任意值）更灵活但易错——`if (x = 1)` 的赋值误写静默为真；强布尔系更安全但要求显式 `x != 0`。</span>

## 4 字符串

**字符串（string）**：字符的序列。设计问题集中在三个维度：

- **可变性**：C 的字符串是 `char[]` 可变；Java 的 `String` **不可变**（每次拼接产生新对象）；Python 的 `str` 不可变。
- **实现**：C 用 `'\0'` 结尾的字符数组（长度靠扫到结束符，`strlen` 是 $O(n)$）；Java/Python 用「长度前缀 + 数组」（`length()` 是 $O(1)$）。<span class="marginnote">`'\0'` 结尾是 C 缓冲区溢出漏洞的温床——写入越过 `'\0'` 位置就破坏了相邻内存。现代语言改走「显式长度」路线，是把安全内置进类型。</span>
- **字符编码**：串的字节解释取决于编码（ASCII、UTF-8、UTF-16）。UTF-8 是当今事实标准：ASCII 兼容、变长、自同步。

**辨析｜易错点：** 「字符串长度」在不同语言含义不同——Python 的 `len("中文")` 是码位数（2），Java 的 `"中文".length()` 是 UTF-16 码元数（2），而字节数 `utf-8 编码` 则是 6。判断长度、切片、遍历，务必先弄清你操作的是「码位、码元还是字节」。

## 5 公式解析：浮点数的位布局

IEEE 754 双精度用 64 位表示一个数：

$$
v = (-1)^s \times (1 + m) \times 2^{e - 1023}
$$

其中 $s$ 是符号位（1 位），$e$ 是指数（11 位，偏移 1023），$m$ 是尾数小数部分（52 位）。

三步拆解：

- **第一步，符号**：$(-1)^s$ 决定正负——$s=0$ 为正、$s=1$ 为负。符号位独立于大小，故浮点有 `-0` 与 `+0`。
- **第二步，指数**：$e - 1023$ 称为**偏置指数**。存的是 $e$，真实指数要减去 1023，从而能表示负次幂（小于 1 的数）。
- **第三步，尾数**：$1 + m$ 是**隐含前导 1**——规范化的浮点小数总以 1 开头，因此不必存储，等于白赚一位精度。$m$ 的 52 位给出约 15–17 位十进制有效数字。

**辨析｜易错点：** 浮点比较用 `==` 是危险操作。由于舍入，$0.1 \times 3$ 不一定等于 $0.3$。可靠做法是比较绝对差：`abs(a - b) < epsilon`，或改用十进制/定点类型。

## 6 大数：原始类型的边界之外

原始类型的「有限」边界，催生了**任意精度（arbitrary precision）**的解法——当内置类型不够用时：

**Python 的 `int`**：任意精度——`10**100` 直接算，自动扩位。代价：每个大整数都是堆对象，比原生 `int64` 慢得多。

**Java 的 `BigInteger`**：显式使用——`BigInteger.valueOf(2).pow(100)`。安全但冗长（不能直接用 `+`）。

**Rust 的 `num_bigint` / C++ 的 boost::multiprecision**：第三方库提供大数类型。

**数值溢出检查**：现代语言提供「检查式算术」——Rust 的 `checked_add`（溢出返回 `None`）、`wrapping_add`（回绕）、`saturating_add`（饱和）。Python 无溢出（自动扩位）；C 的溢出是未定义行为。

| 需求 | 语言 | 方案 |
| --- | --- | --- |
| 常规计数 | 全部 | 定宽 int（快） |
| 精确大数 | Python | 内建任意精度 |
| 大数 + 安全 | Java/Rust | BigInteger / bigint 库 |
| 溢出即报错 | Rust | `checked_add` |

**辨析｜易错点：** **「任意精度 ≠ 无代价」**——Python 大整数运算比 `int64` 慢一到两个数量级；且与 C 扩展（NumPy 的 `int64`）混用时可能静默丢失精度。**「定宽保性能，大数保正确」**——选型看需求：计数器用 `int`，加密/精确计算用大数。「类型的选择是需求的投影」——这句话在数值类型上体现得最直接。

## 7 小结

- 整数由**字长 + 符号**决定范围，多数语言用**补码**表示；溢出回绕是安全漏洞温床。
- 浮点遵循 **IEEE 754**，不精确、范围悬殊、运算不结合；比较要用容差而非 `==`。
- 字符走向 **Unicode**，要分清码位与码元；布尔与整数的关系是语言血统分水岭。
- 字符串在**可变性、实现、编码**三维度分叉；长度语义（码位/码元/字节）须先厘清。
