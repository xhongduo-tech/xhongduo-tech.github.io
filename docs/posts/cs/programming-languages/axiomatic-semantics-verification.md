## 为什么从公理语义开始

操作语义与指称语义都回答「程序意味着什么」；**公理语义（axiomatic semantics）**却问一个更务实的问题：**我们能否证明程序是正确的？** 它由弗洛伊德（Robert Floyd）与霍尔（C. A. R. Hoare）在 1960 年代末建立，核心产物是今天以霍尔命名的 **Hoare 逻辑**。公理语义不描述执行过程，只给出一套**推理规则**：从「执行前成立的前置条件」推导「执行后成立的后置条件」。它把「程序正确性」变成一种数学证明，是软件形式化验证、以及现代编程语言契约式设计（Design by Contract）的学术源头。<span class="marginnote">当一个语言内置了断言（assert）、前置条件与后置条件（如 Ada 的 pre/postcondition、Rust 的 debug_assert），它就在实践公理语义的思想——即使实现者从未提过 Hoare 逻辑。</span>

## 1 三元组：公理语义的句子

公理语义的基本命题是**霍尔三元组（Hoare triple）**：

$$
\{P\}\ S\ \{Q\}
$$

它断言：**若执行语句 $S$ 之前性质 $P$ 成立（前置条件，precondition），且 $S$ 的执行终止，则执行之后性质 $Q$ 成立（后置条件，postcondition）。**<span class="marginnote">注意「且 $S$ 的执行终止」——霍尔三元组关心的是「部分正确性」（partial correctness）：只在终止的前提下承诺结果。要证明「一定终止」需要单独的终止性证明。</span>

## 2 三条核心规则

公理语义只需少数规则即可覆盖全部语句结构。最核心的三条：

**赋值公理**：赋值之后，凡是关于新值成立的性质，执行前关于「旧表达式」必须成立。

$$
\{Q[E/x]\}\ x = E\ \{Q\}
$$

例如要证 $\{x = 5\}\ x = x + 1\ \{x > 0\}$：把 $Q = (x > 0)$ 中的 $x$ 替换成 $x+1$，得 $Q[(x+1)/x] = (x+1 > 0)$，化简为 $x > -1$——而 $x = 5$ 蕴含它，证明成立。<span class="marginnote">赋值公理是「逆向」的：想证「赋值后 $Q$」，只要证「赋值前 $Q$ 中把 $x$ 换成表达式后的结果」。这是 Hoare 逻辑里最容易写错的一条——方向反了就是常见错误。</span>

**顺序复合规则**：中间插一个断言 $R$，把两步串起来。

$$
\frac{\{P\}\ S_1\ \{R\} \qquad \{R\}\ S_2\ \{Q\}}{\{P\}\ S_1; S_2\ \{Q\}}
$$

**条件规则**：分支成立时带上前置条件 $B$，分支不成立时带上前置条件 $\neg B$。

$$
\frac{\{P \land B\}\ S_1\ \{Q\} \qquad \{P \land \neg B\}\ S_2\ \{Q\}}{\{P\}\ \text{if}\ B\ \text{then}\ S_1\ \text{else}\ S_2\ \{Q\}}
$$

## 3 循环不变式：最困难也最关键的一步

证明循环 $\{P\}\ \text{while}\ B\ \text{do}\ S\ \{Q\}$，需要找一个**循环不变式（loop invariant）$I$**：

$$
\frac{\{I \land B\}\ S\ \{I\}}{\{I\}\ \text{while}\ B\ \text{do}\ S\ \{I \land \neg B\}}
$$

$I$ 必须满足三件事：进入循环前成立（$P \Rightarrow I$）；循环体保持它（$\{I \land B\} S \{I\}$）；循环退出后能推出目标（$I \land \neg B \Rightarrow Q$）。<span class="marginnote">不变式是循环的「灵魂」：它描述循环在每次迭代前后都保持的核心性质。找不变式没有机械算法，是程序验证中最需要洞察力的一步——很多教科书练习就专练这一点。</span>

## 4 公式解析：证明求和循环

用公理语义证明「$x$ 累加 $1$ 到 $n$」的循环正确。程序为：

```
{s = 0; k = 0;}
while (k < n) { k = k + 1; s = s + k; }
```

要证的后置条件是 $Q \equiv s = n(n+1)/2$。选取不变式：

$$
I \equiv s = \frac{k(k+1)}{2} \land 0 \le k \le n
$$

三步拆解这个证明：

- **第一步，验证初始化**：循环前 $k=0, s=0$，代入 $I$ 得 $0 = 0$ 且 $0 \le 0 \le n$，成立。
- **第二步，验证保持性**：设执行前 $I \land (k < n)$ 成立，即 $s = k(k+1)/2$。循环体后 $k' = k+1$，$s' = s + k' = k(k+1)/2 + (k+1) = (k+1)(k+2)/2 = k'(k'+1)/2$——$I$ 以新值再次成立。
- **第三步，验证退出**：循环退出时 $k = n$（结合 $k \le n$），于是 $s = n(n+1)/2$——恰为 $Q$。$\blacksquare$

**辨析｜易错点：** 不变式必须**同时**覆盖「保持性」与「退出结论」。初学者常选一个太弱的不变式（如 $k \ge 0$），它虽在循环体保持，却推不出想要的 $Q$；或者选得太强而初始化不成立。验证一个不变式的合法性，永远要过三道关：初始成立、体保持、退出够用。

## 5 公理语义的工程回响

- **契约式设计**：Eiffel 语言把前置/后置条件与不变式做进语言本身，运行时可检查，这在今天的 Python（`assert`）、Rust（`debug_assert`）、及各类框架的验证注解中都能看到影子。
- **静态验证器**：现代工具（如微软的 Dafny、Frama-C）把 Hoare 逻辑机械化，自动搜索循环不变式并生成证明义务。<span class="marginnote">从「人写证明」到「机器帮证」，公理语义是这一整个验证工具链的理论核心——Dafny 的 `invariant` 关键字就是直接翻译了上述规则。</span>
- **类型系统**：类型规则与 Hoare 规则共享同一套「断言推理」的骨架——类型声明本质上也是一种前置条件。

**辨析｜易错点：** 公理语义不保证**终止**。证明「程序满足规格」通常分为两半：部分正确性（用 Hoare 规则）与终止性（通常用良基序数，证明每次迭代都让某个度量严格下降）。缺了后者，非终止程序也能通过前者——这违反直觉，却是验证的关键细节。

## 6 实战：用公理语义证明交换程序

把公理语义的规则组合起来，证明一个完整的程序。程序「交换 x 与 y」（借助临时变量 t）：

```
{t = 0}
t = x;
x = y;
y = t;
{x = old_y ∧ y = old_x}
```

用**最弱前置条件（weakest precondition）**从后往前推导——这是迪杰斯特拉风格的正确性验证：

- **从后往前第一步**：后置条件 $Q = (x = old\_y \land y = old\_x)$。对 `y = t` 用赋值公理：前置条件 $Q[y/t] = (x = old\_y \land t = old\_x)$。
- **第二步**：对 `x = y`：前置 $Q[y/t][x/y] = (y = old\_y \land t = old\_x)$。
- **第三步**：对 `t = x`：前置 $[x/y][y/x][t/x] = (y = old\_y \land x = old\_x)$。
- **第四步**：初始 `t = 0`（无关）——前置条件恒真，证明成立。$\blacksquare$

**辨析｜易错点：** 「从后往前」推导（最弱前置条件）比「从前往后」推导（最强后置条件）更机械、更适合程序验证——它把「要证的后置条件」一步步逆推成「需要的前置条件」，最后只需检查初始条件蕴含它。**「验证程序正确性 = 从目标逆推前置条件」**——这是公理语义在现代验证工具（Dafny、Frama-C）中的实际工作方式。

## 7 小结

- 公理语义的核心是**霍尔三元组** $\{P\} S \{Q\}$：前置条件、语句、后置条件的断言。
- 三条核心规则：**赋值公理**（替换方向）、**顺序复合**（中间断言）、**条件规则**（分支携带条件）。
- 循环证明依赖**循环不变式**，须过「初始成立、体保持、退出够用」三关。
- 公理语义只管**部分正确性**，终止性需要另证；它是契约式设计与程序验证工具的学术根基。
