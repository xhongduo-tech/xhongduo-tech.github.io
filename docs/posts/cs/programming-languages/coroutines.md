## 为什么从协同程序开始

普通子程序的调用是「严格嵌套」的：A 调 B，B 完成返回，A 继续。**协同程序（coroutine）**打破了这种嵌套——它可以在中途**挂起（suspend）**，把控制权交给另一个协程，之后**从挂起点恢复（resume）**。这模糊了「调用者与被调者」的等级关系：两个协程是**对等**的，轮流执行。这一概念由康威（Melvin Conway）在 1963 年提出，是现代生成器（generator）、async/await、以及许多并发框架的直接祖先。理解协程，就理解了「挂起/恢复」这种控制反转的本质。<span class="marginnote">协程 vs 子程序：子程序是「主从」关系（调用者永远支配被调者），协程是「对等」关系（两者平等地轮流推进）。协程 vs 线程：协程是<strong>协作式</strong>（自己让出），线程是<strong>抢占式</strong>（被调度器打断）。这三个对比是理解协程的坐标。</span>

## 1 协程的基本机制：挂起与恢复

**协同程序（coroutine）**：一种支持「挂起 → 恢复」循环的控制结构。协程在 `yield` 处挂起，把控制权交还；下次 `resume` 时**从挂起点的下一句继续**，且**局部变量保持**。

```python
def producer():
    for i in range(5):
        yield i          # 挂起，交回控制权
        # resume 后从这里继续

p = producer()
next(p)                  # → 0
next(p)                  # → 1（从 yield 后继续）
```

**关键特性**：协程有**自己的控制栈**（或「续延」），挂起时保存执行位置与局部状态，恢复时无缝继续。这与「每次从头执行」的普通子程序根本不同。<span class="marginnote">实现上，协程的「状态」包括：程序计数器（执行到哪一句）、局部变量、以及（语言相关）调用栈。生成器（generator）是协程的最简形态——只向调用者单向产出值；完整协程还能接收值（Python 的 `send`、Kotlin 的 Channel）。</span>

## 2 协程 vs 线程 vs 子程序

三者的本质区别在于「谁决定暂停、暂停后去谁那」：

| 维度 | 子程序 | 协程 | 线程 |
| --- | --- | --- | --- |
| 暂停方式 | 返回（结束） | 挂起（可恢复） | 被抢占 |
| 暂停由谁决定 | 自己 | 自己（协作式） | 调度器（抢占式） |
| 恢复方式 | 重新调用 | resume 从挂起点继续 | 调度器安排 |
| 并发粒度 | 无 | 协作式多任务 | 抢占式多任务 |
| 开销 | 极低 | 低（用户态切换） | 较高（内核/栈切换） |

**辨析｜易错点：** 协程不是线程：线程是**并行**（真并发，可同时在多核跑），协程是**并发**（单线程内协作式交替）。协程不解决「多核并行」，它解决「IO 等待时的让出」——这正是 async/await 高效的原因：等待 IO 时让出，不阻塞线程。

## 3 生成器：协程的最简形态

**生成器（generator）**：能产出**一系列值**的函数，每次 `yield` 产出一个值并挂起，下次恢复继续。

```python
def fib():
    a, b = 0, 1
    while True:
        yield a          # 产出当前项，无限生成
        a, b = b, a + b
```

生成器的价值：

- **惰性**：值按需生成，不一次性全部放入内存——适合无限序列、大文件逐行读。<span class="marginnote">惰性生成器把「数据流」变成「管线」：`fib()` 可以无限产出，消费方取多少算多少。相比「先生成整个列表」，惰性在内存与启动时间上都占优——这是「按需计算」思想的实践。</span>
- **状态保持**：生成器在 yield 之间保持局部状态，无需手动维护「当前进度」的外部变量。

## 4 公式解析：挂起/恢复的语义

协程的执行可以用「续延（continuation）」建模。设协程 $C$ 在挂起点 $y_i$ 处挂起，其「剩余计算」是一个续延 $\kappa_i$——「从 $y_i$ 之后继续，直到下一个挂起或结束」：

$$
\text{resume}(C) = \text{run}(\kappa_{\text{current}}), \qquad
\kappa_{\text{next}} = \text{suspend point captured during run}
$$

三步拆解：

- **第一步，认续延**：每次挂起，协程「记住」它接下来要做的事——这就是续延 $\kappa$：一段「待完成的剩余计算」。挂起 = 把 $\kappa$ 存起来。
- **第二步，看恢复**：`resume(C)` = 运行「当前续延」直到下一个挂起点或结束；运行中可能产生新的续延（下一个挂起点）。
- **第三步，看状态**：续延封装了「程序计数器 + 局部环境」——协程恢复时把这些状态装回去，就好像从未离开。**「挂起/恢复」= 「保存/装载续延」**，这是协程最精确的语义图景。

**辨析｜易错点：** 协程与「回调」的区别：回调是「把控制权交给别人，别人替你完成」，协程是「自己挂起、自己恢复」——协程把异步逻辑写成**顺序代码**（写起来像同步），避免「回调地狱」。**「用同步的外观表达异步的控制流」是协程的最大价值**，也是 async/await 的语法基础。

## 5 协程的现代形态：生成器到 async/await

- **Python**：生成器（`yield`）→ `yield from` → `async/await`——协程从「数据产出」进化到「异步控制流」。
- **Kotlin**：`suspend` 函数——挂起函数可被 `await`，编译成状态机。
- **Go**：goroutine 是「重量级协程 + 运行时调度」——协作式并发由运行时接管。<span class="marginnote">Go 的 goroutine 把协程的「协作式」与线程的「托管」结合：程序员写顺序代码，运行时负责在多个系统线程间调度海量 goroutine。「协程 + 调度器」是现代高并发服务（如 vLLM、Redis 事件循环）的普遍结构。</span>
- **Lua**：一等协程（`coroutine.create`/`resume`）——游戏引擎里常见。

## 6 协程的实现机制：栈式 vs 无栈

协程的实现方式决定了它们的灵活性与代价——两大流派：

**栈式协程（stackful coroutine）**：每个协程有**自己的调用栈**——可以嵌套调用函数、在深层函数里挂起。Lua 的协程、Go 的 goroutine（早期）、Boost.Coroutine 是代表。**「栈式 = 可以在任意深度挂起」**，灵活但每个协程占用栈内存。

**无栈协程（stackless coroutine）**：没有独立栈——协程被编译成**状态机**（把挂起点变成状态、局部变量变成结构体字段）。C++20 的 `co_await`、Rust 的 `async`、Python 的 `async/await` 是代表。**「无栈 = 轻量（无栈分配）」**，但只能在函数体内直接挂起（不能在被调函数深处挂起）。

| 维度 | 栈式 | 无栈 |
| --- | --- | --- |
| 独立栈 | 有 | 无（状态机） |
| 挂起深度 | 任意（嵌套） | 仅当前函数 |
| 内存 | 每协程一栈 | 极轻 |
| 代表 | Lua、goroutine | async/await |

**辨析｜易错点：** **「async/await 是无栈协程」**——它把 `await` 编译成状态机的挂起点，协程本身不占独立栈。「能不能在被调函数里挂起」是两者的关键差异：无栈协程的 `await` 必须出现在**自己的**函数体里（`await helper()` 可以，但 `helper()` 内部不能再挂起，除非 `helper` 也是 async）。**「理解栈式/无栈，就理解了协程的『能』与『不能』」**——为什么 Go 可以「在任意库函数里挂起」而 Python async 不行，根源在此。

## 7 小结

- **协程**支持「挂起 → 恢复」循环，打破子程序的严格嵌套，两个协程对等轮流执行。
- 与线程的区别：协程**协作式**（自己让出）、单线程内并发，线程**抢占式**、可多核并行。
- **生成器**是协程的最简形态：惰性产出值、状态在 yield 间保持。
- 语义模型：挂起/恢复 = **保存/装载续延**；协程用同步外观表达异步控制流，是 async/await 的祖先。
