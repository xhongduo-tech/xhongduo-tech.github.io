## 为什么从渗透测试方法论开始

本专题叫「网络攻防技术」，而整个攻防体系的第一块地基，不是某款工具，而是一套**怎么想、怎么排步骤**的方法论。**渗透测试（penetration testing）**：在获得授权的前提下，模拟攻击者的视角，系统性地探测目标系统并尝试突破其安全防御，以发现可被利用的漏洞。为什么先学方法论再学工具？

因为工具会过时，而流程是稳定的：一次成功的渗透测试，无论目标是一台 Web 服务器还是一个内网，都必须按「信息收集 → 漏洞分析 → 漏洞利用 → 后渗透 → 报告」的节奏推进。

Patrick Engebretson 的《渗透测试实践指南》（The Basics of Hacking and Penetration Testing）第 1 章正是用整整一章来讲这个「从哪里开始」的问题，并把它浓缩成五阶段模型。

<span class="marginnote">方法论的源头可以追溯到 1990 年代美国空军信息战中心的「渗透测试指南」，但真正让它成为行业标准的是 PTES（Penetration Testing Execution Standard）——一个由社区专家共同起草、如今被各大安全公司采纳的流程框架。它是本节对比的主轴。</span>

## 1 渗透测试的本质：授权下的模拟攻击

**渗透测试（penetration testing）**与「黑客攻击」在技术上几乎同源——用的是同一批工具、同一条攻击链路——唯一且决定性的区别是**授权**：渗透测试有书面授权、有范围边界、有停止条件，而恶意攻击没有。这个区别决定了渗透测试的一切工作方式。

**核心要点｜授权、范围与规则（Rules of Engagement）**：正式渗透测试开工前，双方必须签定授权书（Scope & Rules of Engagement），明确「测什么 IP、什么时间段、能不能用 DoS 手法、遇到敏感数据怎么办」。

这些规则不是形式，而是**法律与伦理的防火墙**——越界的行为即使技术上成功，也已构成犯罪。

这一点在中国网络安全法、等级保护条例以及各国法规里都是底线。

**辨析｜易错点：** 初学者最容易把「渗透测试」与「漏洞扫描」混为一谈。漏洞扫描（如 Nessus/OpenVAS）只是**自动化地发现已知漏洞**，输出一份「可能有问题」的清单；而渗透测试要**人工验证、尝试利用**，证明「这个漏洞真的能被攻破、影响有多大」。扫描是「体检」，渗透是「就诊」。

<span class="marginnote">渗透测试与 CTF 的差别也很关键：CTF 题目环境干净、目标明确（拿 flag）、没有授权问题；而真实渗透要面对生产系统、要负法律责任、要写报告。本专题后续的 CTF 篇（第20–25篇）与技术同源，但纪律完全不同——<strong>方法论的「授权意识」是从 CTF 走向实战的分水岭</strong>。</span>

## 2 五阶段方法论：渗透测试的标准流程

《渗透测试实践指南》第 1 章给出了渗透测试的经典流程，通常概括为**五个阶段**，与 PTES（渗透测试执行标准）的七个阶段大体对应：

**阶段一：侦察（Reconnaissance）**。尽可能多地收集目标信息——域名、IP、技术栈、员工信息。又分为**被动侦察**（不直接接触目标，搜 OSINT、查 WHOIS）与**主动侦察**（直接向目标发包，如端口扫描）。这一阶段回答「目标是谁、长什么样」。

**阶段二：扫描与枚举（Scanning & Enumeration）**。用 Nmap 等工具确认目标开放的端口与服务，再深入枚举服务的细节（版本、共享、目录）。这一阶段回答「攻击面在哪里」。

**阶段三：漏洞利用（Exploitation）**。针对发现的漏洞实施攻击——打 Metasploit 模块、注入 SQL、上传 WebShell，最终拿到目标主机的控制权（shell）。这一阶段回答「能攻进去吗」。

**阶段四：后渗透（Post-Exploitation）**。拿下 shell 之后的工作：**权限提升**（从普通用户提权到 root/Administrator）、**横向移动**（在内网里从一台跳到另一台）、**权限维持**（留后门）。这一阶段回答「能走多远、能待多久」。

**阶段五：报告（Reporting）**。把发现整理成报告：漏洞是什么、怎么复现、影响多大、怎么修复。**报告是渗透测试的最终交付物**——客户买的不是你的攻击，而是可行动的修复清单。

<span class="marginnote">五阶段里初学者最容易轻视「报告」：觉得「打下来就算完」。但真实世界的渗透测试合同中，报告撰写往往占工时的一半以上——<strong>「发现但说不清」与「没发现」同样失败</strong>。本专题最后一篇《安全评估报告与风险复测》会专门展开报告的写法。</span>

**核心要点｜五阶段对照表：**

| 阶段 | 回答的问题 | 代表工具/方法 | 对应 PTES 阶段 |
| --- | --- | --- | --- |
| 侦察 | 目标是谁 | Google Hacking、WHOIS、子域名枚举 | 情报收集 |
| 扫描枚举 | 攻击面在哪 | Nmap、Gobuster、enum4linux | 威胁建模、漏洞分析 |
| 漏洞利用 | 能攻进去吗 | Metasploit、Burp Suite、sqlmap | 主动渗透 |
| 后渗透 | 能走多远 | 提权脚本、C2、隧道 | 后渗透 |
| 报告 | 怎么修复 | 报告模板、CVSS 评分 | 报告 |

## 3 黑盒、白盒与灰盒：三个视角

按**对目标内部的了解程度**，渗透测试分为三类，这是方法论里必须搞清的第一组分类：

**黑盒测试（black-box）**：测试者对目标一无所知，完全从外部攻击者的视角出发。最贴近真实攻击，但效率低、覆盖面有限——就像蒙着眼找门。

**白盒测试（white-box）**：测试者掌握目标全部信息——源码、架构、账号权限、网络拓扑。覆盖面最全、效率最高，但无法完全模拟真实攻击者的「摸着石头过河」。常用于代码审计与合规测试。

**灰盒测试（gray-box）**：介于两者之间——测试者掌握部分信息（如一个低权限账号、部分文档），模拟「已经获得某种立足点的攻击者」。这是实际项目里最常见的选择：兼顾真实性与效率。

<span class="marginnote">为什么真实项目偏爱灰盒？因为纯粹的从零黑盒测试在有限工期内往往「测不透」，而白盒又不够真实。给一个普通用户权限的灰盒，既能测出水平越权、垂直提权这类「内鬼级」漏洞，又不至于在侦察阶段浪费太多时间。OWASP 测试指南对每一类测试都明确标注了应该从哪个视角做。</span>

**核心对比表｜三类测试的取舍：**

| 维度 | 黑盒 | 白盒 | 灰盒 |
| --- | --- | --- | --- |
| 信息掌握 | 无 | 全部 | 部分 |
| 真实性 | 最真实 | 最低 | 居中 |
| 覆盖面 | 有限 | 最全 | 较全 |
| 效率 | 低 | 高 | 中 |
| 典型场景 | 外部渗透、红队 | 代码审计、合规 | 大多数商业测试 |

## 4 从方法论到工具：本专题的路线图

方法论的价值在于它给出了一张**地图**——接下来的每一篇博文，都是这张地图上的一段路：

**第1篇（本篇）**定方法；**第2篇被动侦察 + 第3篇主动侦察**走完「侦察」；**第4篇服务枚举 + 第5篇漏洞扫描 + 第6篇流量分析**走完「扫描枚举」；**第7–14篇**聚焦 Web 应用渗透（对标《Web应用黑客手册》）；**第15–19篇**进入后渗透与内网（Metasploit、提权、横向、持久化）；**第20–25篇**是 CTF 六题型的实战化训练；**第26–30篇**站在攻防两端（红蓝对抗、蓝队、应急、取证、报告），完成从「进攻」到「防守」再到「交付」的闭环。

这套路线图还与本博客的课程体系相连：本专题依赖第三级《计算机网络》里 TCP/IP 与端口的概念、第二级《操作系统》里进程与权限的概念；而它的产出（漏洞报告、应急方法）又会成为第五级安全合规等更上层知识的素材。

<span class="marginnote">一个方法论层面的提醒：渗透测试的本质是<strong>「按流程做减法」</strong>——先广后深、先外后内、先低危后高危。记住这个节奏，比记住任何一条命令都重要。命令忘了可以查手册，节奏错了整个项目都会乱。</span>

## 5 渗透测试的工具箱：把方法论变成工具

方法论定了「做什么」，工具负责「怎么做」——本专题后续各篇都会详细介绍每类工具，这里先给一张总览图。

**Kali Linux**：渗透测试的旗舰发行版，预装 600+ 安全工具（Nmap、Metasploit、Burp、John、Wireshark 等），本专题绝大多数命令都在它上面跑。

**按阶段配工具**：侦察用 Nmap/子域名枚举工具；枚举用 Gobuster/enum4linux；利用用 Metasploit/Burp；后渗透用 Mimikatz/提权工具；报告用 Markdown/截图工具。

**职业化认证**：**CEH**（道德黑客认证）与 **OSCP**（Offensive Security 认证，含 24 小时实战考试）是行业认可的渗透测试能力证明——OSCP 强调「手工+实战」，与本书「必知必会的工具与方法」的定位高度契合。

**核心对比表｜五阶段与代表工具：**

| 阶段 | 代表工具 |
| --- | --- |
| 侦察 | Nmap、子域名枚举 |
| 扫描枚举 | OpenVAS、Gobuster |
| 利用 | Metasploit、Burp |
| 后渗透 | Mimikatz、提权脚本 |
| 报告 | 报告模板、CVSS |

<span class="marginnote">工具的哲学：<strong>工具是「螺丝刀」，方法论是「图纸」</strong>——没有图纸的螺丝刀只能乱拧，没有螺丝刀的图纸画不出房子。本专题正是「先图纸后工具」：每一篇都是「方法论 + 对应工具」的组合，学完一套，你就同时拥有了地图和装备。</span>

## 6 小结

- **渗透测试**是授权下的模拟攻击，与黑客攻击技术上同源、法律上殊途。
- 开工前必须签定**授权书与规则（Scope/ROE）**，明确范围与边界——这是法律底线。
- 经典流程是**五阶段**：侦察 → 扫描枚举 → 漏洞利用 → 后渗透 → 报告，与 PTES 标准大体对应。
- 按信息掌握程度分**黑盒、白盒、灰盒**，实际项目以灰盒最常见。
- **报告是最终交付物**，CVSS 评分让漏洞的影响「可量化、可排优先级」。
- 方法论的「授权意识」是从 CTF 走向真实渗透的分水岭。
