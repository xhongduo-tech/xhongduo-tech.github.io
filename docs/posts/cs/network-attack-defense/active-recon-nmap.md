## 为什么从主动侦察继续

上一节的被动侦察「零接触」，但被动情报有个天花板：你永远不知道目标上真正开着哪些端口、跑着什么服务。要回答「攻击面在哪里」，必须**主动向目标发送数据包**——这就是**主动侦察（active reconnaissance）**。

它的核心工具是 **Nmap**（Network Mapper），一个由 Gordon Lyon（笔名 Fyodor）从 1997 年开始维护的开源端口扫描器。主动侦察从此给目标留下了痕迹——防火墙日志、IDS 告警都可能记下你的扫描，但这是渗透测试进入实战的必经一步。

《渗透测试实践指南》第 3 章就是围绕 Nmap 展开的。本节的落点是：**用 Nmap 把「IP 地址」翻译成「端口 + 服务 + 版本 + 操作系统」的完整画像**。

<span class="marginnote">Nmap 的江湖地位：它是安全圈装机量最大的工具之一，随 Kali Linux 预装，也被《Black Hat Python》《Python 网络安全》等无数书籍当作第一课。它的作者 Fyodor 还撰写了著名的网络主机发现文章《The Art of Port Scanning》，Nmap 的许多理念都源自这篇文章。</span>

## 1 端口与协议：扫描的对象是什么

先复习一个前置概念（来自第三级《计算机网络》）：**端口（port）**是操作系统为每个网络服务分配的编号，范围 0–65535。一台主机对外暴露的服务，本质上就是「IP + 端口 + 协议」的三元组。**端口扫描**要做的，就是探测目标在哪些端口上接受连接，从而推断它在跑什么服务。

**核心要点｜常见端口与服务对照（必背基础）：**

| 端口 | 服务 | 协议 |
| --- | --- | --- |
| 21 | FTP | TCP |
| 22 | SSH | TCP |
| 23 | Telnet | TCP |
| 80 | HTTP | TCP |
| 443 | HTTPS | TCP |
| 445 | SMB | TCP |
| 3306 | MySQL | TCP |
| 3389 | RDP | TCP |

<span class="marginnote">记住端口与服务映射的意义：扫描结果 `22/tcp open` 立刻提示你「目标提供 SSH」——你可以试着探测版本、找弱口令、找历史 CVE。真实世界还有大量「非常规端口」：很多公司把 SSH 挪到 2222、把 Web 挪到 8080/8443 来「隐藏」，但<strong>隐藏不等于安全</strong>——Nmap 的版本探测（`-sV`）恰恰就是为穿透这种伪装设计的。</span>

## 2 Nmap 的扫描技术：三种核心模式

Nmap 支持多种扫描技术，它们对目标的影响、留下的痕迹、需要的权限各不相同。三种最常用的：

**TCP 连接扫描（`-sT`）**：完整走完 TCP 三次握手——连接成功说明端口开放。最准确、最不容易误报，但会在目标日志里留下完整的连接记录，也最「吵」。

**SYN 半开扫描（`-sS`）**：只发 SYN 包，收到 SYN/ACK 就判定「开放」并立即发 RST 断开——**不完成三次握手**，因此许多应用层服务不会记录这次「会话」。速度更快、痕迹更少，是默认推荐模式。需要 root 权限（要自己构造原始包）。

**UDP 扫描（`-sU`）**：UDP 无握手，判断开放与否靠「ICMP 端口不可达」回应。速度慢、误报多，但 DNS、SNMP、DHCP 这些关键服务都是 UDP 的——不可跳过。

<span class="marginnote">为什么 SYN 扫描「更隐蔽」仍不完美？因为防火墙和 IDS 依然能看到成批的 SYN 包——「SYN flood」这个特征本身就足以触发告警。隐蔽性是相对的，没有绝对隐形的扫描。理解这一点，就知道蓝队为什么能凭「异常高频的 SYN」发现侦察活动（对应本专题《蓝队防御》篇）。</span>

**核心对比表｜三种扫描技术：**

| 技术 | 握手 | 痕迹 | 速度 | 权限 |
| --- | --- | --- | --- | --- |
| `-sT` 连接扫描 | 完整 | 最重 | 慢 | 普通用户 |
| `-sS` SYN 扫描 | 半开 | 较轻 | 快 | root |
| `-sU` UDP 扫描 | 无 | 较轻 | 很慢 | root |

## 3 组合拳：一次标准的 Nmap 实战

实战中的 Nmap 很少单用一个参数，而是**组合**。一次典型的全画像扫描：

```bash
nmap -sS -sV -O -p- -T4 10.0.0.1
```
逐项拆解这条命令（这也是本节的「公式解析」——像拆数学式子一样拆命令）：

- **`-sS`**：SYN 半开扫描，快且相对隐蔽。
- **`-sV`**：**版本探测**——连接服务、读取 banner（如 `SSH-2.0-OpenSSH_7.4`），识别具体服务与版本。这是「指纹识别」的核心开关。
- **`-O`**：**操作系统探测**——根据 TCP 指纹（TTL、窗口大小、选项顺序）猜测目标 OS，输出 `Running: Linux 4.x` 之类的结果。
- **`-p-`**：扫描全部 65535 个端口（默认只扫前 1000 个常用端口）。
- **`-T4`**：时序模板 4 级（0–5），控制发包速度——扫描慢速网络时调低，避免丢包误报。

**为什么 `-sV` 让扫描从「发现了什么」升级为「用什么打」**：版本号是漏洞检索的钥匙。

扫出 `Apache/2.4.49`，就能去查这个版本有没有已知 CVE——Apache 2.4.49 恰好就存在著名的路径穿越 + 远程命令执行漏洞（CVE-2021-41773），配一条 curl 就能打穿。

**指纹识别把「端口开放」翻译成「可查 CVE 的具体软件」**，这正是枚举（下一篇）与利用（后几篇）之间的桥。

**核心要点｜Nmap 常用参数速查：**

| 参数 | 作用 |
| --- | --- |
| `-sS` / `-sT` / `-sU` | SYN / TCP / UDP 扫描 |
| `-sV` | 版本探测（指纹） |
| `-O` | 操作系统探测 |
| `-p-` / `-p 80,443` | 全端口 / 指定端口 |
| `-A` | 综合扫描（`-sV -O -sC` 加强） |
| `-oN/-oG/-oA` | 输出普通/可解析/全格式结果 |

## 4 指纹识别与脚本引擎：让 Nmap 替你干活

**指纹识别（fingerprinting）**在 `-sV` 之外还有一层：**服务指纹与操作系统指纹**。

服务指纹来自 banner 抓取与协议交互；操作系统指纹则利用不同系统在 TCP/IP 栈实现上的细微差异——TTL 初值、窗口大小、乱序行为——综合比对识别出 Linux/Windows/路由器固件。

**Nmap Scripting Engine（NSE，脚本引擎）**是 Nmap 的「插件系统」：`-sC`（或 `--script=default`）会跑一批默认脚本，自动做端口相关检查——如对 445 端口跑 SMB 用户枚举、对 80/443 跑 HTTP 信息收集。

`--script=vuln` 更是直接用 Nmap 内置的漏洞脚本去探测目标是否存在已知漏洞。

<span class="marginnote">NSE 让 Nmap 从「扫描器」变成「侦察平台」：`nmap --script=http-enum <目标>` 会枚举 Web 目录、`--script=smb-enum-shares` 会列出 SMB 共享。它把「扫描+枚举」两件事合并成一条命令，是效率利器——但也要记得，脚本跑得越多、目标留下的流量痕迹越重。</span>

**辨析｜易错点：** `-A` 不是「更高级扫描」的魔法开关，它只是 `-sV -O -sC --traceroute` 的打包。

另一个常见误解是把「全端口扫描出的所有 open 端口」都当成价值等同——实际上**高价值目标（445/3389/3306 等数据与远程控制端口）与低价值端口（如 135 的某些 RPC 服务）要区别对待**，攻击面要按「可达性 × 数据价值 × 漏洞可能」加权，而不是只看开没开。

## 5 小结

- **主动侦察**直接向目标发包，回答「攻击面在哪里」，代价是留下痕迹。
- **端口**是「IP+端口+协议」三元组里的服务标识，常用端口映射要背熟。
- Nmap 三大扫描模式：`-sT` 连接扫描、`-sS` SYN 半开扫描、`-sU` UDP 扫描，各有权衡。
- 一条标准命令 `nmap -sS -sV -O -p- -T4` 能同时拿到端口、服务版本与操作系统——**版本号是查 CVE 的钥匙**。
- NSE 脚本引擎把 Nmap 从扫描器升级为侦察平台（`-sC`/`--script=vuln`）。
- 扫描是「发现」，枚举才是「深挖」——两者配合才能画全攻击面。
