## 为什么从身份认证攻击继续

上一节我们绕过了「客户端」的纸糊防线，而 Web 应用真正意义上的第一道安全闸门是**身份认证（authentication）**——它回答「你是谁」。WAHH 第 6 章把认证攻击作为 Web 渗透的重头戏：因为**认证一旦被攻破，攻击者就获得了合法身份**，后续的越权、数据窃取都不再「非法」。

本节拆解身份认证的三大攻击面：**口令爆破**（穷举与字典）、**认证绕过**（逻辑缺陷）、**重放攻击**（截获即用）。理解这些攻击，也就能理解为何正确的口令策略（加盐哈希、限速、多因素）如此重要。

<span class="marginnote">认证与授权（access control）是两回事：<strong>认证</strong>验证「你是谁」（Authentication），<strong>授权</strong>决定「你能做什么」（Authorization）——常缩写为 AuthN 与 AuthZ。本节讲 AuthN 的攻击，下一节讲会话管理，再下一节讲 AuthZ 的越权。攻防里「先认证、后授权」的链路，是 Web 安全最基础的骨架。</span>

## 1 口令爆破：把字典烧到登录框上

**口令爆破（password cracking / brute force）**是身份认证攻击最直白的一类：不断尝试用户名与口令组合，直到试中。它不是「破解算法」，而是「猜答案」——成功率完全取决于**口令空间的薄弱程度**。

爆破分两种力度：**纯暴力（brute force）**穷举所有字符组合（如 8 位小写字母有 $26^8 \approx 2088$ 亿种，纯暴力极慢）；**字典攻击（dictionary attack）**用**口令字典**（常见弱口令、泄露过的口令）试——现实中大多数账户的密码都在字典里，所以字典攻击才是主流。

经典字典：`rockyou.txt`（来自 2009 年 RockYou 网站数据泄露，约 1430 万个真实口令，Kali 自带）、`SecLists` 的口令集合。

**公式解析｜破解一个口令的期望次数：**
$$
E[\text{尝试次数}] \approx \frac{\text{口令字典大小}}{2}
$$
直觉：如果口令均匀分布在字典里，平均试到一半就能命中。这个公式解释了为什么**只要口令进了常见字典，爆破就只是时间问题**——攻击者要的不是「穷举整个宇宙」，而是「覆盖最常见的那一小块口令空间」。

<span class="marginnote">口令强度的事实：8 位纯数字约 1 亿种组合，用显卡暴力破解（每秒数十亿次哈希）秒级可破；而 12 位以上大小写+数字+符号的口令，空间膨胀到天文数字，暴力几乎无望。这就是为什么密码策略要求「长度优先于复杂度」——<strong>每多一位字符，破解成本指数级上升</strong>（密码学见本专题 CTF Crypto 篇的哈希部分）。</span>

**核心要点｜爆破的完整链路：**

| 步骤 | 手段 | 工具 |
| --- | --- | --- |
| 用户枚举 | 登录错误提示差异 | 手工/Burp |
| 口令猜测 | 字典 + 规则变形 | Hydra、Burp Intruder |
| 组合爆破 | 用户名×口令 | Hydra |
| 哈希破解 | 离线破解泄露哈希 | hashcat、John |

## 2 认证绕过：不走正门的逻辑缺陷

口令爆破是「笨办法」，而**认证绕过（authentication bypass）**直接绕过认证流程——靠的是**认证逻辑的缺陷**，比爆破优雅得多，也更值得警惕。常见的绕过点：

**条件语句漏洞**。后端逻辑写成「如果认证通过就放行」，但攻击者通过操纵参数（如把 `authenticated=false` 改成 `true`）、删掉某个字段、注入逻辑条件，让服务器直接走「放行」分支。

这往往对应代码里「检查存在性」与「检查真值」的混淆——如 `if ($user)` 在 `$user` 为「空对象但存在」时误判。

**密码修改/找回流程缺陷**。找回密码用的「安全问题」「验证码」「重置链接」是经典薄弱点：重置链接的 token 可预测、验证码不校验服务端、安全问题答案在 OSINT 里找得到（呼应第2篇）。攻击者「重置」管理员密码即可登录。

**逻辑绕过（如多步骤流程）**。登录流程拆成多步（输账号→验码→改密），攻击者跳过中间的验证步骤，直接访问最终页面。

**辨析｜易错点：** 认证绕过常与「越权」混淆。区别：绕过是**根本没通过认证就进来**（AuthN 缺陷）；越权是**通过认证但访问了无权限资源**（AuthZ 缺陷）。前者在登录之前，后者在登录之后。下一节的会话管理、再下一节的访问控制，会把这条线彻底划清。

<span class="marginnote">认证绕过的本质是「<strong>信任了不该信任的判断</strong>」：服务器本应「认证通过才放行」，却因为参数可控、流程可跳、检查可误判而放行。WAHH 第6章反复强调：对认证的每一处判断，攻击者都会尝试「让它不走真分支」。防御的核心是——<strong>认证状态必须由服务器在会话中持久维护，绝不信任客户端提交的任何「已认证」标记</strong>。</span>

## 3 重放攻击：截获合法流量直接再用

**重放攻击（replay attack）**：攻击者**截获一段合法的认证流量**（如登录请求、认证令牌），然后**原样重放**它来冒充合法用户。它不破解任何密码，只是「录下来，放回去」。

**典型场景**：在无加密的 HTTP 下嗅探登录请求（呼应第6篇网络嗅探）——拿到 `POST /login` 里的口令或会话 Cookie，重放即可登录；或者截获一次性令牌（OTP、CSRF token 之外的认证凭据），在有效期窗口内重放。

**为什么有些系统防不住重放？** 重放攻击针对的是**「不可区分新旧」的流量**——如果认证凭据是「静态可复用的」（长期有效的 Cookie、未绑定的令牌），重放天然成功。

防御手段：给请求绑定**时间戳 + 随机数（nonce）**、令牌一次性使用、绑定来源 IP/设备、使用 HTTPS 防止截获。

**核心对比表｜三类身份认证攻击：**

| 攻击 | 原理 | 条件 | 防御 |
| --- | --- | --- | --- |
| 口令爆破 | 猜口令 | 弱口令 | 强口令策略+限速 |
| 认证绕过 | 利用逻辑缺陷 | 代码缺陷 | 服务端严格校验 |
| 重放攻击 | 截获重放 | 凭据可复用 | 一次性令牌+HTTPS |

<span class="marginnote">重放攻击在「认证与加密」的交叉处最值得注意：现代 API 常用的方案是给请求加 `timestamp` + `nonce` + 签名，服务器拒绝「过期」与「重复使用过 nonce」的请求——一次性 + 时效性，是防重放的两大支柱。本专题 CTF Crypto 篇的「随机数复用」也是同一思想的密码学版本。</span>

## 4 多因素认证与口令存储：正确的防线

理解了攻击，就理解了防御。身份认证的正确姿势有两个关键点：

**口令存储必须加盐哈希**。服务器**绝不明文存口令**：正确做法是 `加盐哈希`——`存储值 = hash(盐 + 口令)`，且每个用户盐值随机。加盐让两个相同口令的哈希不同，**彩虹表失效**；哈希让泄露的数据库不能直接反推出口令（只能靠离线爆破）。

反例：明文存储、MD5 不加盐——泄露即裸奔（呼应第20篇 CTF 数据泄露相关题型）。

**多因素认证（MFA）**。把认证从「你知道的（口令）」扩展到「你有的（手机 OTP/安全密钥）」或「你特有的（指纹/人脸）」——单点口令被攻破也不再致命。MFA 是当前对抗口令爆破、撞库、钓鱼的现实主力防线。

<span class="marginnote">口令策略的两个现实权衡：<strong>长度</strong>比复杂度更能抗暴力（每多一位指数级加难）；<strong>MFA</strong> 比改密更有效地抗撞库。安全运营者常说的「口令不是关键，关键是有没有第二因素」，正是这个道理。关于口令的具体强度数值与哈希算法，可对照第三级《应用密码学》的章节。</span>

## 5 认证攻击的实战流程

把认证攻击的各个手法串成一条实战链路——从「不知道用户名」到「登录成功」：

**第一步：用户枚举**。利用登录错误提示差异（「用户不存在」vs「口令错误」）、注册页报错、时间差（存在的用户响应更慢），确认有效用户名——这是后续所有攻击的前提。

**第二步：口令爆破**。对确认的用户名用字典攻击（Hydra 打 HTTP 表单、Burp Intruder 打登录接口），结合用户名规律（`admin`、`admin@域名`）缩小空间。配合**撞库**（已泄露的口令对批量试登录，呼应第2篇 OSINT 里的泄露痕迹）。

**第三步：认证绕过与重放**。爆破不成，转测逻辑绕过（参数操纵、找回流程）与重放（嗅探会话，呼应第6篇）。

**核心要点｜认证攻击工具速查：**

| 步骤 | 工具 | 说明 |
| --- | --- | --- |
| 用户枚举 | 手工/Burp | 观察错误差异 |
| 口令爆破 | Hydra、Burp Intruder | 字典攻击 |
| 撞库 | 泄露库 + 脚本 | 批量试口令 |
| 哈希破解 | hashcat、John | 离线破解 |

<span class="marginnote">认证攻击的「投入产出」思维：爆破是概率游戏——<strong>口令越弱、字典越好，命中越快</strong>；绕过是逻辑游戏——<strong>代码越糙、漏洞越多</strong>。实战中先试「低成本高回报」的弱口令与默认口令，再上字典，最后才考虑复杂绕过。把有限的测试时间花在命中率最高的地方，是认证测试的核心技巧。</span>

## 6 小结

- **身份认证（AuthN）**验证「你是谁」，是 Web 应用的第一道安全闸门，攻破它即获得合法身份。
- **口令爆破**分纯暴力与字典攻击，现实以字典为主——口令进了常用字典，破解只是时间问题。
- **认证绕过**利用认证逻辑缺陷（参数操纵、找回流程缺陷、多步骤流程跳过），比爆破更危险。
- **重放攻击**截获合法流量原样重放，靠「凭据可复用」得手；一次性令牌 + HTTPS 可防。
- 正确防线：口令**加盐哈希**存储（绝不明文）、**多因素认证**、登录限速与锁定。
- 认证与授权（AuthZ）是两条线——下一节先讲会话，再下一节讲越权。

在下一节，我们处理「登录之后如何保持身份」——**会话管理攻击**，看令牌弱点、会话固定与会话劫持如何偷走你的登录状态。
