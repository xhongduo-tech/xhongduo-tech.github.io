## 为什么从数字取证继续

应急响应里我们反复提到「先取证再隔离」「证据保全」——而**数字取证（digital forensics）**正是这门「从数字痕迹中重建事实」的科学。为什么要单独成篇？

因为取证与普通的「查日志」有本质区别：它要产出**经得起检验的证据**——不仅找到攻击者留下的痕迹，还要保证这些痕迹**完整、未污染、可复现**，能在后续追责、司法、复盘中被采信。取证是攻防的「真相层」：红队抹痕迹（第19篇），蓝队就是把这些被抹的痕迹**从磁盘、内存、网络的残留里挖回来**。

本节拆解取证的三大领域——**磁盘取证、内存取证、网络取证**，以及贯穿其中的核心纪律：**证据保全与哈希校验**。

<span class="marginnote">取证与第21篇 CTF Misc 取证题的关系：Misc 取证是「玩具版」，环境干净、flag 明确；真实取证是「战场版」，磁盘巨大、痕迹被刻意清除、结论要负责任。技能同源（文件系统、工具），但纪律的严谨度天差地别——<strong>真实取证的第一原则是「不污染证据」，这在 CTF 里几乎不存在</strong>。</span>

## 1 取证的铁律：证据保全

数字取证的整个方法论都建立在一条铁律上：**原始证据不可改变**。一旦证据被改动（哪怕读了一下），它的证明力就受损——「你怎么证明这个文件是你读之前就这样的？」

由此衍生出三个核心实践：

**镜像（imaging）**。不对原始磁盘直接分析，而是制作**只读镜像**（`dd` 复制整块磁盘、或 `FTK Imager`/`Guymager` 做司法镜像），所有分析都在副本上进行。原始磁盘封存。

**哈希校验（hashing）**。取证开始时与结束时对证据计算哈希（MD5/SHA256）——**哈希一致证明证据未被动过**。哈希是取证完整性的「数字指纹」。

**证据链（chain of custody）**。记录证据从采集、存储、分析到提交的全过程：谁、何时、何处、如何接触了证据。**证据链完整，证据才可采信**。

<span class="marginnote">「先哈希后分析」是取证的第一步：`sha256sum /dev/sdb > 原始哈希.txt` 记下采集时的哈希，分析结束再算一次——两次一致，证明整个过程证据未被改动。哈希校验把「我保证没改」变成「数学上可验证没改」，是取证从「技术活」升级为「司法证据」的关键一步。</span>

**核心要点｜取证铁律三件套：**

| 实践 | 作用 | 工具 |
| --- | --- | --- |
| 只读镜像 | 保护原始证据 | dd、Guymager |
| 哈希校验 | 证明完整性 | sha256sum、FTK |
| 证据链 | 证明可采信 | 记录文档 |

## 2 磁盘取证：从文件系统挖痕迹

**磁盘取证（disk forensics）**分析磁盘镜像，重建攻击者在文件系统上留下的痕迹。核心思路：**文件删除不等于消失**——删除只是把文件标记为「可覆盖」，数据仍留在磁盘上，直到被新数据覆盖。

磁盘取证的主要对象：

**已删除文件恢复**。用 `foremost`、`photorec`、`Autopsy` 按文件签名扫描磁盘「未分配空间」，恢复被删除的文件——攻击者删掉的工具、WebShell、压缩包，都可能被挖回来。

**文件时间线分析（timeline）**。文件系统的元数据（创建、修改、访问时间）构成时间线，用 `fls`、`Autopsy` 按时间排列，重建「攻击者在何时创建/修改/删除了什么」——**时间线是还原攻击顺序的核心工具**。

**文件系统特殊区域**。

`$MFT`（NTFS 主文件表）记录 NTFS 卷上每个文件的元数据与内容位置，是 Windows 磁盘取证的核心；`USN Journal`（变更日志）记录每次文件操作，可直接还原「哪个文件被创建/修改/删除」；**slack space（簇残留）**——文件末尾到簇边界之间的残留空间，常藏着被覆盖前的旧数据。这些区域是「正常用户看不到、攻击者不会清理」的证据富矿。

**核心要点｜磁盘取证的三大对象：**

| 对象 | 内容 | 工具 |
| --- | --- | --- |
| 已删除文件 | 未分配空间恢复 | foremost、photorec |
| 时间线 | 元数据 MAC 时间 | fls、Autopsy |
| 特殊区域 | $MFT、USN、slack | Autopsy、取证工具 |

## 3 内存取证：抓「正在发生的证据」

**内存取证（memory forensics）**分析**运行中主机的物理内存**（RAM）。为什么要看内存？因为**很多攻击只活在内存里**——无文件恶意代码（呼应第19篇）、解密后的口令、正在运行的进程、未落盘的数据，全部存在于内存而磁盘上看不到。

关机或重启，内存证据即消失——**内存取证必须在系统运行中（或冻结镜像后）第一时间进行**。

**内存取证的三大内容**：**进程列表**（哪些进程在跑，异常进程是恶意代码的直接线索）、**内存中的口令与哈希**（用 `mimikatz` 抓取，呼应第17篇）、**加载的模块与注入**（DLL 注入、shellcode 的落脚点）。

**工具与流程**：`Volatility`（开源内存取证框架）是绝对主力——先 `volatility imageinfo` 识别内存镜像的操作系统，再 `pslist`（进程）、`netscan`（网络连接）、`hashdump`（口令哈希）。

**核心要点｜内存取证的四步：镜像 → 识别系统 → 逐项分析 → 交叉验证**。

<span class="marginnote">内存取证对抗痕迹清理（第19篇）：红队清理磁盘日志、删除文件，但<strong>内存里的进程与数据在系统运行期间始终存在</strong>——只要在主机在线时抓下内存镜像（`dumpit`/`winpmem` 等工具），就能看到「正在发生的攻击」。这是「无文件攻击」时代取证的主战场。</span>

## 4 网络取证：从流量还原攻击过程

**网络取证（network forensics）**分析网络流量记录（pcap、防火墙/IDS 日志），还原攻击者的**网络行为**——这与本专题第6篇网络嗅探的流量分析同源，但目标从「找 flag」变成「还原攻击」。

**网络取证看什么**：**C2 通信**（外连的可疑 IP/域名，呼应第18篇）、**数据外带**（大量外发的数据，呼应 ATT&CK 的 Exfiltration 战术）、**扫描与横向**（对内网大量连接）、**时间线**（各设备的连接时间，还原攻击顺序）。

**核心要点｜网络取证的典型产物：**

| 产物 | 证明什么 |
| --- | --- |
| 攻击源 IP | 谁发起的 |
| C2 域名/IP | 和谁通信 |
| 外带流量 | 偷走了什么 |
| 连接时间线 | 攻击顺序 |

**辨析｜易错点：** 三大取证领域要协同而非孤立：磁盘取证回答「留下了什么文件」，内存取证回答「正在跑什么」，网络取证回答「和谁通信」。

单看一个领域都可能得出片面结论——**完整的取证要三者交叉印证**，例如磁盘里发现木马文件 + 内存里发现木马进程 + 网络日志里发现木马的外连记录，才算证据链闭合。

## 5 取证流程与证据链的闭环

把三大领域串成一次完整取证的标准流程——取证不是「东看一眼西看一眼」，而是按流程推进：

**标准流程**：**证据保全**（封存原始介质、记录证据链）→ **镜像与哈希**（制作只读镜像、记录初始哈希）→ **分析**（磁盘 → 内存 → 网络按需展开）→ **验证**（用多工具交叉印证结论）→ **出报告**（记录分析过程与结论，附证据链）。

**核心对比表｜一次取证的标准动作：**

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 保全 | 封存介质、记录链 | 证据链 |
| 镜像 | dd/Guymager | 只读镜像 |
| 哈希 | sha256sum | 完整性指纹 |
| 分析 | 磁盘/内存/网络 | 结论 |
| 报告 | 记录过程 | 可采信文档 |

<span class="marginnote">取证的「可采信」最终由三样东西支撑：<strong>原始证据未动（哈希）、过程完整（证据链）、结论可复现（工具与步骤记录）</strong>。这也是取证与普通「翻日志」的根本区别——普通翻日志回答「发生了什么」，取证要回答「凭什么相信你说的」。这份严谨，正是它在司法、追责、复盘中被采信的原因。</span>

## 6 小结

- **数字取证**从磁盘、内存、网络三处重建事实，核心纪律是**证据保全**：只读镜像、哈希校验、证据链。
- **磁盘取证**挖文件系统残留：已删除文件、MAC 时间线、`$MFT`/USN/slack 特殊区域。
- **内存取证**抓「正在发生」的证据——无文件攻击、内存口令、进程注入，必须在系统在线时进行。
- **网络取证**从 pcap 还原 C2 通信、数据外带与攻击时间线。
- 取证与第28篇应急响应深度融合：**先取证快照、再隔离处置**；与第19篇痕迹清理是攻防两端。
- 证据链完整，取证结论才可采信——三大领域交叉印证，才算闭合。
