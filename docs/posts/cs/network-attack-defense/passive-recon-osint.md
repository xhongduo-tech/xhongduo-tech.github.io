## 为什么从被动信息收集开始

上一节定下五阶段方法论，而五阶段的第一步「侦察」又分主动与被动。为什么从**被动**开始？

因为被动侦察有三个无可替代的优点：**零痕迹**——你不向目标发送任何流量，目标完全感知不到你在观察它；**低成本**——只需要浏览器、搜索引擎和免费的公共数据库；**信息量大**——企业注册、历史漏洞、员工社交账号，这些数据是目标自己「贴」到公共互联网上的。

《渗透测试实践指南》第 2 章把这一步称为「被动信息收集」，并强调它是整个渗透测试里**信息回报率最高**的一步——不碰目标一发炮弹，就能把它扒个底朝天。

<span class="marginnote">被动侦察与「OSINT（Open Source Intelligence，开源情报）」几乎是同义词。OSINT 不只是渗透测试的侦察手段，它还是网络舆论分析、商业尽调、甚至记者调查的通用技术。本博客第五级《情报学》与第六级《社会工程学》里，OSINT 都是核心方法论。</span>

## 1 OSINT：让目标自己交出情报

**OSINT（开源情报）**：仅从**公开可获取的渠道**收集与分析目标信息的技术体系。它的第一原则是「目标在公共互联网上留下的任何痕迹，都是情报」——而这些痕迹远比想象中多。

**被动侦察收集哪几类信息？** 大致四类：

**基础设施类**：域名、IP 段、DNS 记录、证书。回答「目标的网络长什么样」。

**组织人员类**：公司架构、员工邮箱、社交账号、技术博客。回答「谁在维护它、谁可能在点击钓鱼邮件」。

**技术指纹类**：网站用的 CMS、框架、历史版本。回答「用什么搭的，有哪些已知漏洞」。

**泄露痕迹类**：历史数据泄露、GitHub 上的源码、文档。回答「有没有已经暴露的秘密」。

**核心要点｜被动侦察信息清单：**

| 信息类别 | 典型内容 | 常用渠道 |
| --- | --- | --- |
| 基础设施 | 域名、IP、证书 | WHOIS、DNS、证书透明度 |
| 组织人员 | 邮箱、员工、组织架构 | 搜索引擎、LinkedIn |
| 技术指纹 | CMS、框架、版本 | 网站分析、Wappalyzer |
| 泄露痕迹 | 源码、凭证、历史数据 | GitHub、泄露数据库 |

<span class="marginnote">「被动」是相对「主动」而言的：被动不向目标发送流量，一切数据都来自第三方渠道。一个很好的自测标准——<strong>如果目标拉全量日志也看不到你，你做的就是被动侦察</strong>。一旦你开始用 Nmap 扫端口，就进入主动侦察（下一篇的内容），目标的防火墙与 IDS 就可能开始记录你了。</span>

## 2 Google Hacking：把搜索引擎当武器

**Google Hacking（谷歌黑客）**：利用搜索引擎的高级语法，精确检索目标泄露在互联网上的敏感信息。它不攻击任何系统，只是**把搜索引擎当成一台巨大的索引数据库来查询**。常用的语法：

`site:`：限定域名。`site:example.com` 列出该站被收录的全部页面。

`filetype:`：限定文件类型。`site:example.com filetype:sql` 找数据库备份、`filetype:env` 找配置文件。

`intitle:`/`inurl:`：限定标题/URL 关键词。`intitle:"index of"` 找开放目录。

`intext:`：限定正文关键词。`intext:"password" site:example.com` 找页面里暴露的口令。

组合使用威力更大：一条经典的 Google Hacking 查询 `intitle:"index of" "admin"` 能批量找出**开放目录**——服务器上没做访问控制的文件列表，往往直接暴露备份、源码甚至口令文件。

<span class="marginnote">Google Hacking 的力量在于「索引 = 情报」：搜索引擎已经替你爬了全网，你只需要会提问。信息安全从业者还维护了专门的 Google Hacking Database（GHDB）——一份按用途分类的高级查询清单，新手可以直接照着用。注意同样的语法在 Bing、DuckDuckGo 里略有差异，实战中常多引擎交叉查询。</span>

**核心要点｜Google Hacking 常用语法：**

| 语法 | 作用 | 例子 |
| --- | --- | --- |
| `site:` | 限定域名 | `site:example.com` |
| `filetype:` | 限定文件类型 | `filetype:env` |
| `intitle:` | 限定标题 | `intitle:"index of"` |
| `inurl:` | 限定 URL | `inurl:admin` |
| `intext:` | 限定正文 | `intext:"password"` |

**辨析｜易错点：** 新手常把 Google Hacking 的产出当成漏洞本身——查到一个 `index of` 目录就高呼「拿下了」。其实开放目录只是**信息暴露**，要判断它是不是漏洞，还得看里面有没有真正敏感的文件、能不能进一步利用。侦察的产物是「线索」，不是「战果」。

## 3 WHOIS、DNS 与证书透明度：扒出基础设施

域名与网络基础设施是渗透测试的第一手情报来源，三个渠道最重要：

**WHOIS**：查询域名注册信息的公开协议——注册人、注册商、注册/到期时间、DNS 服务器。老网站常留下**真实姓名、邮箱、电话**——这些信息既是社会工程学的靶子，也是猜测口令与安全问题的素材。工具：`whois example.com`。

**DNS 枚举**：域名系统本身就在公开作答。`dig` 查询 `A`（地址）、`MX`（邮件服务器）、`NS`（域名服务器）、`TXT`（文本记录，常含验证码或 SPF 配置）记录，能拼出目标的邮件与 CDN 架构。

一个细节：**有些企业只把子域名挂在公网 DNS 上**，从根域名的记录就能顺藤摸瓜。

**证书透明度（Certificate Transparency，CT）**：CA 签发的每一张 SSL 证书都会记入公开日志。

而**每签一张证书，就得公开域名与子域名**——于是攻击者可以扫描证书日志，找出那些**只对内部暴露、但曾在证书里出现**的子域名（如 `vpn.example.com`、`git.example.com`）。工具：`crt.sh` 在线查询，或 `certspotter`。

<span class="marginnote">证书透明度本来是 2013 年后为了防「证书被偷偷签发」而设计的公开审计机制，如今却成了侦察的宝库：<strong>证书日志 = 一张公开的子域名清单</strong>。真实渗透里，从 `crt.sh` 挖出一个不在任何页面链接上的内部 VPN 子域名，是经典的突破起点。</span>

**核心要点｜基础设施侦察三件套：**

| 渠道 | 拿到什么 | 工具 |
| --- | --- | --- |
| WHOIS | 注册人、邮箱、DNS | whois、Web 查询 |
| DNS | 记录、子域、架构 | dig、nslookup |
| 证书日志 | 全量子域名 | crt.sh、certspotter |

## 4 子域名枚举：扩大攻击面的关键一步

**子域名枚举（subdomain enumeration）**的目标：找出目标**所有**子域名，因为很多子域名部署着比主站薄弱得多的服务——旧测试系统、内部 Wiki、未加固的开发环境。子域名枚举有两种方式：

**基于字典**：用 `subfinder`、`amass`、`ffuf` 遍历常见子域名字典（`admin`、`test`、`dev`、`vpn`、`git`……），看哪些能解析出 `A` 记录。

**基于证书/搜索引擎**：上面说的证书日志（`crt.sh`）、DNS 历史记录（`SecurityTrails`）、搜索引擎收录，都是「被动」子域名枚举的主力——这也是本节把它放在被动侦察里的原因。

**实战思路｜子域名枚举之后**：枚举出子域名 ≠ 攻击面扩大，还要**解析成 IP、确认服务**。一个常见惊喜：某些子域名解析到**独立的 IP 段**，绕过父域名的 CDN/WAF——这时直接对源 IP 做后续扫描，往往能看到被 WAF 挡掉的真实服务。

<span class="marginnote">子域名枚举是「信息收集—扩大攻击面」这一思想的代表：<strong>主站固若金汤，但某个三年前遗留的 `dev.example.com` 可能跑着未打补丁的服务</strong>。OSINT 的价值不在于找到一个漏洞，而在于找到「哪一个口最软」——它决定了你接下来把 Nmap、Burp 的力气花在哪里。</span>

## 5 小结

- **被动侦察 / OSINT**：不向目标发包，从公开渠道收集情报，零痕迹、低成本、信息量大。
- 情报分**基础设施、组织人员、技术指纹、泄露痕迹**四类，各有渠道。
- **Google Hacking** 用 `site:/filetype:/intitle:` 等语法把搜索引擎变成检索工具。
- **WHOIS + DNS + 证书日志**三件套扒出基础设施与全量子域名。
- 子域名枚举常用**字典爆破 + 证书日志 + 搜索引擎**三路结合，找出被隐藏的薄弱服务。
- 侦察产出的是**线索**而非战果，它决定后续主动侦察的用力方向。
