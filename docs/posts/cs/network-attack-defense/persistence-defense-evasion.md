## 为什么从权限维持开始

内网渗透拿下目标、做完横向，攻击还差最后一环：**把胜利变成「长期存在」**。**权限维持（persistence）**：在目标系统上留下「后门」，让攻击者即使重启、即使原入口被堵，也能再次进入。

**痕迹清理（defense evasion / anti-forensics）**：抹掉入侵痕迹，让蓝队与取证人员「找不到、还原不了」。这两个动作是红队（攻击方）与蓝队（防守方）对抗最白热化的领域——《渗透测试实践指南》第 7 章在讲完后渗透后，专门交代「如何保住所攻下的成果」。

本节拆解权限维持的常见机制与痕迹清理的原则，并说明为什么蓝队视角（第27篇）恰恰从「发现后门、还原痕迹」反向工作。

<span class="marginnote">红队视角的持久化原则：<strong>「多条后门、彼此独立、互为备份」</strong>——删一条还有另一条；Web 后门（WebShell）与系统后门（服务/计划任务）配合，保证「入口被堵也不丢」。这与蓝队「纵深防御」思想是对称的：红队的纵深持久化 vs 蓝队的纵深检测，构成了攻防的核心张力。</span>

## 1 权限维持：让访问永久有效

**权限维持（persistence）**的手段按「驻留位置」分几大类：

**系统自启动项（AutoRun）**。把后门注册进系统启动流程——Linux 的 `cron`（计划任务）、`systemd` 服务、`/etc/rc.local`；Windows 的注册表 `Run` 键、启动文件夹、服务（`sc create`）。机器重启后后门自动复活。

**账户后门**。添加一个隐藏的高权限账户（Linux 直接改 `/etc/passwd` 加 UID 0 用户；Windows `net user` 加管理员），攻击者随时用这个账号登录。

**Web 后门（WebShell）**。在 Web 目录留一个 WebShell（呼应第16篇）——即使系统层面被清理，只要 Web 服务还在，入口就在。

**凭证持久化**。Windows 下用 `mimikatz` 留「黄金票据」（伪造长期有效的 Kerberos TGT）；Linux 下植入 SSH 公钥到 `~/.ssh/authorized_keys`——攻击者密钥随时 SSH 登录。

**核心要点｜常见持久化机制：**

| 平台 | 机制 | 复活时机 |
| --- | --- | --- |
| Linux | cron、systemd、rc.local | 定时/开机 |
| Linux | SSH 公钥、passwd 用户 | 随时登录 |
| Windows | 注册表 Run、服务 | 登录/开机 |
| Windows | 黄金票据 | 长期有效 |
| Web | WebShell | 随时访问 |

<span class="marginnote">持久化是攻防对抗的「长跑」：攻击者埋后门，蓝队用 EDR（端点检测响应）与基线监控去找异常启动项、异常账户、异常计划任务。经典的检测手法是<strong>「基线比对」</strong>——清点机器上「本不该存在」的持久化点（第27篇蓝队防御会展开）。红队的持久化越隐蔽（如藏在 DLL 劫持、WMI 事件订阅里），检测成本越高。</span>

## 2 痕迹清理：擦掉入侵的证据

**痕迹清理（anti-forensics）**的目标是让蓝队**无法确认入侵、无法还原过程、无法定位攻击者**。清理对象分三类：

**日志清理**。删除/篡改系统日志——Linux 的 `/var/log`（`auth.log`、`wtmp` 等）、Windows 的 `Event Log`（安全、系统、应用日志）。`attrib`/`wevtutil`（Windows）、`history`（bash 历史）都要处理。

但**现代日志会异地备份与转发**（SIEM，第27篇），本地删干净也没用——所以清理要与「知道蓝队在哪记录」结合。

**文件与进程清理**。删除上传的工具、临时文件、WebShell；结束可疑进程；清理 bash 历史（`history -c`）与临时文件。

**时间线抹除**。篡改文件时间戳（`touch -t`）、清理文件系统残留——对抗取证的时间线分析（第29篇数字取证）。

**核心要点｜痕迹清理的边界：**

| 目标 | 手段 | 反制 |
| --- | --- | --- |
| 日志 | 删除/截断 | SIEM 异地转发 |
| 文件 | 删除/覆盖 | 未分配空间取证 |
| 时间线 | 改时间戳 | MAC 时间分析 |
| 内存 | 留在内存的证据 | 内存取证 |

**辨析｜易错点：** 痕迹清理是**有取舍的**——删得太彻底反而暴露（「日志突然少了一段」本身就是告警信号）。专业红队的做法是**「定向删除」**：只删自己活动相关的那几条记录，而非清空整个日志。这个「手术式清理」与「炸平式清理」的区别，正是从入门到专业的门槛。

<span class="marginnote">痕迹清理与数字取证（第29篇）是硬币两面：取证的原则是「证据保全、不污染」，红队的原则是「能删则删、删不掉的改」。攻防在这里正面碰撞——攻击者覆盖文件的 <strong>slack space</strong>（未分配扇区残留）、伪造时间戳，取证人员则靠哈希比对、文件签名恢复、内存取证把这些「被清理的痕迹」挖回来。理解双方手法，才真正理解「痕迹」的本质。</span>

## 3 隐蔽通信：C2 与免杀

权限维持的配套是**隐蔽的通信通道**——攻击者需要与后门保持联系（接收指令、回传数据），这个通道叫 **C2（Command & Control，命令与控制）**：

**C2 协议伪装**。把命令与回传数据伪装成正常流量——HTTP/HTTPS 请求（长轮询、伪装 API）、DNS 查询（DNS 隧道）、ICMP、甚至放到合法云服务的 WebSocket 里。目标是「混在正常流量里，蓝队分不清」。

**免杀（AV evasion）**。让恶意文件绕过杀软与 EDR——payload 加密/混淆（PowerShell 编码执行）、shellcode 加载器（用合法进程装载恶意代码）、进程注入（把代码注入合法进程）。

Metasploit 的 `msfvenom` 编码、`Veil`、`Cobalt Strike` 的 Beacon 都是常见手段。

**核心对比表｜隐蔽通信的层次：**

| 层次 | 手段 | 隐蔽性 | 检测难度 |
| --- | --- | --- | --- |
| 明文 C2 | 直接回连 | 低 | 低 |
| 加密 C2 | HTTPS/TLS 伪装 | 中 | 中 |
| 协议隧道 | DNS/ICMP 隧道 | 高 | 高 |
| 驻留内存 | 无文件载荷 | 极高 | 极高 |

<span class="marginnote">「无文件攻击（fileless）」是当前威胁的主流：恶意代码不落盘（PowerShell 从内存执行、注册表里藏脚本、WMI 事件触发），传统杀软扫文件就抓不到——这是痕迹清理与免杀的「升级版」。蓝队对应思路是<strong>「行为检测」而非「特征检测」</strong>：不认文件、认行为（异常 PowerShell、异常父子进程关系）。攻防对抗从「特征」打到了「行为」，这也是第27篇蓝队防御与第28篇应急响应的核心议题。</span>

## 4 持久化对抗：检测与清理

攻击者埋后门，蓝队就要「找出来、清干净」——持久化对抗是红蓝长期博弈的主战场。

**检测方法**：**EDR 与基线监控**扫描异常的自启动项（计划任务、注册表 Run、systemd 服务）；**异常账户审计**（突然出现的管理员账户、SSH 新增公钥）；**Web 目录监测**（新增的可疑脚本文件，呼应第16篇 WebShell）；**日志关联**（后门创建时的事件）。

**清理方法**：清除后门必须「连根拔起」——删除持久化注册点（计划任务/服务/公钥）、删除 WebShell 文件、禁用异常账户、重设被篡改的凭证。**清理不彻底 = 复发**——这正对应第28篇应急响应的「清除」阶段。

**核心对比表｜持久化手法与检测：**

| 手法 | 检测点 |
| --- | --- |
| 计划任务/cron | 启动项审计 |
| 注册表 Run | EDR 基线 |
| SSH 公钥 | authorized_keys 审计 |
| WebShell | Web 目录监测 |
| 隐藏账户 | 账户列表比对 |

<span class="marginnote">「攻防对抗从特征打到行为」在这里再次应验：传统杀软按「特征」查文件，而持久化后门往往无文件（注册表脚本、WMI 事件）——所以蓝队必须按「<strong>行为</strong>」查：新启动项、新账户、新公钥、异常父子进程。这也就是为什么 EDR 与行为分析（第27篇）在当代安全里不可或缺。</span>

## 5 小结

- **权限维持**让攻击者在目标长期驻留：自启动项、账户后门、WebShell、SSH 公钥、黄金票据。
- 红队持久化原则：**多条后门、彼此独立**——纵深持久化对抗蓝队的纵深检测。
- **痕迹清理**删/改日志、文件、时间线；专业做法是**定向删除**而非清空（清空本身就是告警）。
- **C2 通信**把指令与回传伪装进正常流量（HTTPS/DNS 隧道），是后门与攻击者保持联系的通道。
- **免杀**让恶意文件绕过杀软：加密混淆、加载器、进程注入、无文件攻击。
- 攻防对抗已从「特征」打到「行为」——蓝队靠 SIEM、EDR 与行为检测反制（见第27–29篇）。
