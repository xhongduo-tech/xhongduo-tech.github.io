## 为什么从 CTF Reverse 继续

上一节的 Pwn 是「利用」，本节 **Reverse（逆向工程）**是「理解」——它不给程序源码，只给一个二进制文件（可执行程序、APK、固件），要求**分析出它的逻辑**，通常是还原出某种「算法」或「密钥」，从而拿到 flag。Reverse 题的典型形态：程序里有一个**校验函数**，输入 flag 才会输出正确结果——你的任务不是破解程序，而是**读懂程序在干什么**，倒推出正确的输入。Reverse 是安全从业者的核心基本功：恶意软件分析、漏洞研究、协议逆向、竞品分析，全靠「从二进制还原逻辑」的能力。它与《逆向工程与二进制分析》专题（cs-reverse-engineering）直接对接。本节拆解 Reverse 的两大分析路径——**静态分析**与**动态调试**，以及常见手法（加壳脱壳、算法识别）与解题流程。<span class="marginnote">Reverse 与 Pwn 的配合：Pwn 题要打程序，必须先 Reverse 读程序（找漏洞点）；Reverse 题到后期也常要写脚本暴力破解/求解算法。两者共享同一套底层技能——汇编、调试器、二进制格式。CTF 里「先 Reverse 后 Pwn」是常态，逆向是二进制安全的「眼睛」。</span>

## 1 静态分析：不运行就看懂程序

**静态分析（static analysis）**不执行程序，直接分析文件内容。它从「读文件」开始，逐层深入：

**文件识别与保护检测**。`file` 看文件类型（ELF/Mach-O/PE/APK）；`checksec` 看保护；`upx` 等检测是否加壳。

**字符串与资源提取**。`strings` 提取可读字符串——**flag 常藏在字符串里**，或通过字符串找到关键函数名/提示。程序里所有提示（"Wrong!"、"Correct!"）都是定位校验逻辑的路标。

**反汇编与反编译**。核心工具把机器码还原成可读形式：

**反汇编（disassembly）**：把二进制翻译成汇编指令，工具 `objdump`、IDA、Ghidra。
**反编译（decompilation）**：把汇编进一步还原成伪代码（C 风格），工具 **Ghidra**（免费开源）、IDA Pro（商业）的 Hex-Rays 插件。

Ghidra 的反编译输出把「读汇编」变成「读伪 C」，极大降低逆向门槛——校验函数的逻辑直接以 `if (input[i] != (key[i] ^ 0x5a))` 这样的形式呈现，倒推 flag 只需解方程。<span class="marginnote">Ghidra 是 NSA 开源的逆向套件，含反汇编器、反编译器、图形视图——`g` 跳地址、`F5` 反编译、`X` 查交叉引用，三个操作覆盖大部分逆向场景。它的反编译器把汇编还原成伪 C 代码，让「看逻辑」从「逐行读汇编」解放出来。入门 Reverse，从 Ghidra 开始是最平滑的路径。</span>

**核心要点｜静态分析的层次：**

| 层次 | 工具 | 产出 |
| --- | --- | --- |
| 文件识别 | `file`、`checksec` | 类型、保护、壳 |
| 字符串 | `strings` | 提示、flag、函数名 |
| 反汇编 | objdump、IDA | 汇编代码 |
| 反编译 | Ghidra、IDA | 伪 C 代码 |

## 2 动态调试：边运行边看

**动态调试（dynamic analysis）**运行程序，用调试器观察**运行时行为**——寄存器、内存、调用栈、分支走向。静态分析给出「程序的意图」，动态调试确认「实际发生了什么」，两者互补。

**调试器三件套**：`gdb`（Linux 标准调试器，配合 `pwndbg`/`gef` 插件体验大幅提升）、`OllyDbg`/`x64dbg`（Windows）、IDA 内置调试器。

**核心调试操作**：

**下断点（breakpoint）**：`break *0x401234` 在关键地址暂停——比如在校验函数入口、比较指令处。
**单步执行（step）**：`stepi`/`nexti` 逐指令走，观察分支与寄存器的变化。
- **查看寄存器与内存**：`info registers`、`x/20gx $rsp`——比较指令前的两个操作数，直接看出「正确答案」。
- **改运行时数据**：调试器可以**直接修改寄存器和内存**——把比较结果改成相等，绕过校验直接看正确分支。

**经典打法「动态爆破解法」**：在校验的 `cmp`/`jne` 指令处下断点，运行后**观察比较的是什么**——很多题目把 flag 逐字节和输入比较，运行时寄存器里就是明文的 flag 字符。改跳转条件直接拿到正确分支的 flag。<span class="marginnote">动态调试的最妙之处在于「程序自己告诉你答案」：比较指令 `cmp eax, ebx` 执行时，`eax`/`ebx` 里装着「当前输入」与「正确答案」，`info registers` 一眼即见。所以逆向的常见捷径是<strong>不逆向算法，直接动态看比较值</strong>——许多「加了密的算法题」其实经不起 gdb 单步观察。</span>

**核心要点｜动态调试三板斧：**

| 操作 | 命令 | 目的 |
| --- | --- | --- |
| 下断点 | `break *addr` | 关键位置暂停 |
| 单步 | `stepi` | 逐指令观察 |
| 看值 | `info registers` | 比较指令处取答案 |

## 3 常见手法：加壳、混淆与算法识别

Reverse 题为了加大难度，常用三类「防护手法」，对应三种破解思路：

**加壳（packing）**。用 UPX 等工具把程序压缩/加密，运行时先自解压再执行——原始代码被隐藏。**脱壳（unpacking）**的思路：让程序自己解压自己——用调试器跑到「解压完成、跳到原始入口（OEP）」的瞬间，dump 内存还原程序。`upx -d` 可直接脱 UPX 壳；手动脱壳靠「ESP 定律」等技巧。

**混淆（obfuscation）**。把代码变换得难以阅读：控制流平坦化、字符串加密、花指令。破解靠**耐心 + 工具**（`de4dot` 脱 .NET 混淆）+ 动态调试观察实际行为。

**算法识别**。程序里常集成标准算法（AES、MD5、RC4）——`FindCrypt` 插件、`hash` 匹配能自动识别出「这是 AES 加密、密钥是 X」。识别出算法后，直接用已知的密钥/初始向量解密数据即可，**不必逆向整个实现**。<span class="marginnote">「识别算法」是逆向的重要捷径：看到一堆轮转、异或、S 盒的模式，先用 `FindCrypt2`/`Detect It Easy` 扫一下——若是标准 AES/RC4，直接确认算法与参数，用现成库复现解密。逆向不追求「从零推导」，追求「最快理解逻辑」——复用已知知识是高手与新手的分水岭。</span>

**核心要点｜三种防护与破解：**

| 防护 | 原理 | 破解思路 |
| --- | --- | --- |
| 加壳 | 压缩隐藏代码 | 脱壳（OEP dump） |
| 混淆 | 变换难读 | 动态观察 + 工具 |
| 算法识别 | 内嵌标准算法 | FindCrypt 识别 + 复现 |

## 4 解题流程：从拿到文件到提交 flag

一道 Reverse 题的标准解题流程：

**第一步：识别**。`file` 看类型，`checksec` 看保护，`strings` 粗扫——先收集「这是什么、有什么提示」。

**第二步：静态粗看**。Ghidra 打开，找到 `main` 函数，看主逻辑——找校验函数、读输入的函数、比较的地方。`strings` 里的 "Correct!" / "Wrong!" 交叉引用（`X`）直达关键分支。

**第三步：深入算法**。校验逻辑若是简单比较/异或/移位——直接手动/脚本还原；若是标准加密——识别算法、找密钥、解密。

**第四步：动态确认**。对拿不准的地方用 gdb 断点验证——比较指令处看寄存器的「正确答案」。

**第五步：写脚本求解**。算法还原后，逆向写出**求解脚本**（Python）——从校验逻辑反推出合法输入（flag）。很多题的 flag 是「输入满足某条件即正确」，脚本就是「解这个条件」。<span class="marginnote">Reverse 的终点几乎都是「写脚本」：`z3`（约束求解器）是终极武器——把校验逻辑写成约束条件，让 z3 自动求解出满足条件的输入。对「输入经过一系列变换等于某固定值」的题目，用 z3 写约束直接求，比手工逆算法快得多。`pip install z3-solver`，几行代码解一道题。</span>

**核心要点｜Reverse 五步流程：**

1. **识别**：file/checksec/strings。
2. **静态粗看**：Ghidra 读 main 与校验逻辑。
3. **深入算法**：异或/加密/混淆逐层还原。
4. **动态确认**：gdb 断点看运行时值。
5. **脚本求解**：Python/z3 逆推合法输入。

**逆向的耐心与复盘。** Reverse 题是最考验耐心的题型——一个隐藏很深的校验逻辑可能要调试数小时。提升速度的关键是**「卡住就跳」与「WriteUp 复盘」**：卡住时先看别人 WriteUp 的突破口，再自己复现完整路径；每道题复盘「我卡在哪一步、用什么更快」，把经验沉淀成自己的解题套路。逆向能力的成长曲线，是由一道道题目的「卡点突破」累积出来的。

**工具链的组合拳。** 实际解题中静态与动态常交替使用：Ghidra 定位关键函数，gdb 在比较点确认值，脚本批量试错——三者配合才能高效逼近 flag。

## 5 小结

- **Reverse** 从二进制还原程序逻辑，目标常是倒推校验算法的合法输入（flag）。
- **静态分析**：`file`/`strings`/Ghidra 反编译，把汇编还原成伪 C 读逻辑。
- **动态调试**：gdb 断点单步，比较指令处直接看「正确答案」——动态看值常比逆向算法快。
- 三种防护：**加壳**（脱壳到 OEP dump）、**混淆**（工具+动态观察）、**算法识别**（FindCrypt 复用已知算法）。
- 解题五步：**识别 → 静态读 → 深算法 → 动态验 → 脚本求**（z3 约束求解是终极武器）。
