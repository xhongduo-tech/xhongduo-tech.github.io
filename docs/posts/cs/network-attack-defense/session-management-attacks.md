## 为什么从会话管理攻击继续

上一节讲「如何证明你是谁」——登录成功的一瞬间，身份认证完成。但 HTTP 是**无状态协议**：它不记得上一次请求是谁发的。所以应用要在认证之后给用户发一张「身份证」——**会话令牌（session token）**，后续每次请求都带上它，服务器据此识别「你是刚才登录的那个用户」。

**会话管理（session management）**就是这张「身份证」的签发、存储、校验与作废机制。WAHH 第 7 章指出：**会话令牌是认证的「延续」**——攻破了会话，等于在没有口令的情况下继承了用户的登录态。

本节拆解三大会话攻击：**令牌弱点**（可预测/泄露）、**会话固定**（强塞令牌）、**会话劫持**（偷走令牌）。

<span class="marginnote">把会话令牌想象成电影票根：入场时（登录）验票，之后每次进出都靠这张票根。如果票根容易被仿造（令牌可预测）、容易被抢（XSS 偷 Cookie）、或者被塞一张假票根（会话固定），别人就能冒充你自由出入。会话安全 = <strong>令牌不可预测 + 令牌传输与存储安全 + 登录后刷新令牌</strong>。</span>

## 1 会话令牌：登录状态的载体

**会话令牌（session token）**是服务器在登录成功后生成的随机字符串，通过 `Set-Cookie` 头发给浏览器；浏览器之后每次请求都通过 `Cookie` 头把它带回来，服务器查表确认「这个令牌对应哪个用户」。

**令牌的基本安全要求**：

**不可预测性**：令牌必须足够随机——长度足够、用密码学安全随机数生成器（CSPRNG）产生。若令牌可预测（如自增 ID、时间戳、固定前缀+递增），攻击者可以「猜出」别人的令牌。这正是 WAHH 第 7 章反复强调的第一条。

**绑定会话而非明文放敏感数据**：令牌只是一把「钥匙」，真正的用户数据应存在服务器端；不要把「用户 ID + 角色」直接编码进令牌且不做签名（否则攻击者改了角色字段就提权）。

**传输与存储安全**：Cookie 应打上 `Secure`（仅 HTTPS 传输）、`HttpOnly`（JS 不可读，防 XSS 窃取）、`SameSite`（防 CSRF 携带）属性。

**核心要点｜Cookie 的安全属性：**

| 属性 | 作用 | 防御对象 |
| --- | --- | --- |
| `Secure` | 仅 HTTPS 发送 | 明文嗅探 |
| `HttpOnly` | JS 读不到 | XSS 窃取 |
| `SameSite` | 跨站请求不带 | CSRF |
| `Path`/`Domain` | 限定作用范围 | 误用 |

<span class="marginnote">`HttpOnly` 是会话安全里最容易被忽略的一条：就算站内有 XSS（第14篇），只要会话 Cookie 打了 `HttpOnly`，攻击者的 JS 就读不到它——XSS 从「直接偷会话」降级为「还需别的配合」。防御是成体系的：令牌本身不可预测、传输加密、存储加锁，三层一起才有真正的会话安全。</span>

## 2 会话劫持：偷走别人的登录态

**会话劫持（session hijacking）**：攻击者**获得合法用户的会话令牌**，然后带着它访问应用，完全冒充该用户。令牌从哪里泄露？三条主要路径：

**网络嗅探**。未加密 HTTP 下，Cookie 随每个请求明文传输——中间人嗅探即可截获（呼应第6篇 ARP 欺骗）。这也是强制 HTTPS 的核心原因。

**XSS 窃取**。站内的存储型 XSS 让攻击者的 JS 在受害者浏览器里运行，用 `document.cookie` 读走 Cookie——除非打了 `HttpOnly`（呼应第14篇）。

**日志与引荐泄露**。令牌被拼进 URL（如 `?session=abc`）时，会出现在服务器日志、浏览器历史、`Referer` 头里——攻击者从日志或外站 Referer 间接获取。

**辨析｜易错点：** 会话劫持与重放攻击（上节）容易混淆。重放是**截获一段流量原样重放**（目标常是认证请求）；劫持是**拿到令牌本身并持续使用**（目标常是会话 Cookie）。现实中它们常一起出现——嗅探截获会话 Cookie 后重放，本质上就是一种劫持。

<span class="marginnote">会话劫持的经典示例：公共 Wi-Fi 下用 Wireshark 抓到目标访问某站点时的 `Cookie: session=...`，复制这个 Cookie 放进自己的浏览器即可登录。这个「Cookie 交换」手法是渗透测试的入门演示——也说明<strong>无加密网络的会话 = 拱手送人</strong>。防御：全站 HTTPS + Cookie 打 `Secure` + 登录设备绑定。</span>

## 3 会话固定：先塞票根，再等受害者用

**会话固定（session fixation）**是会话攻击里最「阴」的一种：攻击者不偷令牌，而是**先给受害者一个自己知道的令牌**，等受害者用这个令牌登录，攻击者就用同一令牌冒充登录后的身份。

**攻击流程**：攻击者访问目标站点，得到一个会话令牌 `S`；把这个令牌**塞给受害者**（通过 URL 参数、子域名 Cookie 注入、邮件里带链接）；受害者用令牌 `S` 登录；服务器把「登录态」绑定到 `S` 上；攻击者用自己手里的 `S` 直接以受害者身份访问——**因为登录发生在攻击者已知的会话里**。

**为什么有些系统防不住？** 如果应用**登录成功后不更换会话令牌**（沿用登录前的匿名令牌），攻击者就能「预先占座」。**正确做法**：**登录成功后必须重新生成会话令牌**（`session_regenerate_id`），使攻击者预先塞的令牌作废。

<span class="marginnote">会话固定的现实场景：钓鱼链接里带 `?PHPSESSID=abc123`，受害者点进去「登录」，攻击者同用 `abc123` 进后台。防御的核心动作只有一个——<strong>登录成功后轮换令牌</strong>。这个细节在很多框架里是默认行为，但在手写会话的老系统里常常被遗漏，是渗透测试的常考点。</span>

**核心对比表｜三类会话攻击：**

| 攻击 | 手段 | 关键前提 | 核心防御 |
| --- | --- | --- | --- |
| 会话劫持 | 偷走令牌 | 令牌泄露 | HTTPS、HttpOnly |
| 会话固定 | 预塞令牌 | 登录后不换令牌 | 登录后轮换令牌 |
| 令牌预测 | 猜出令牌 | 令牌弱随机 | CSPRNG、长令牌 |

## 4 会话生命周期：超时、登出与保护

会话安全的另一半是**生命周期管理**：

**超时（timeout）**。空闲超时（一段时间无操作自动登出）与绝对超时（登录总时长上限）双管齐下——避免令牌长期有效、放大泄露后果。

**登出（logout）**。登出必须**使服务器端会话失效**（不是只删浏览器 Cookie）——令牌作废，即使被截获也无法再用。

**并发与绑定**。限制同一账号的并发会话数、绑定设备/IP（可选，需权衡可用性）、异常登录提醒——把「令牌泄露」的窗口压到最小。

**核心要点｜会话安全的检查清单：** 令牌足够随机？Cookie 打齐 `Secure`/`HttpOnly`/`SameSite`？登录后轮换令牌？登出后服务端作废？有超时机制？全站 HTTPS？——每一条都能对应到本节讲的一种攻击。

<span class="marginnote">会话管理是「从极限到大模型」知识树里 Web 安全的承重墙：它与第三级《计算机网络》的 HTTP/Cookie 基础、与第四级《密码学》的随机数与哈希、与后端框架的会话中间件都直接相连。理解会话 = 理解「登录之后的一切安全」，这也是为什么它排在越权之前——<strong>先有会话，才有会话里的权限</strong>。</span>

## 5 会话安全测试清单

把会话知识变成可执行的测试项——渗透测试对会话的标准检查清单如下：

**令牌生成**：登录后取会话令牌，分析其**随机性与长度**——连续登录多次对比令牌是否可预测（自增、时间戳、固定前缀）。可预测 = 令牌预测漏洞。

**Cookie 属性**：用 Burp 检查 `Set-Cookie` 是否带全 `Secure`、`HttpOnly`、`SameSite`——缺 `Secure` 可被明文嗅探，缺 `HttpOnly` 可被 XSS 读取（呼应第14篇）。

**生命周期**：登录成功后令牌是否**重新生成**（防会话固定）；登出后服务端会话是否**真正作废**（重新用旧令牌访问应被拒）；是否有时效与空闲超时。

**核心对比表｜会话测试项：**

| 测试项 | 方法 | 通过标准 |
| --- | --- | --- |
| 令牌随机性 | 多次采样分析 | 不可预测 |
| Cookie 属性 | 检查 Set-Cookie | Secure/HttpOnly/SameSite |
| 登录轮换 | 登录前后对比 | 令牌已更换 |
| 登出作废 | 旧令牌重放 | 被拒绝 |
| 超时 | 等待后访问 | 会话失效 |

<span class="marginnote">这份清单在实战里就是「会话这一章的渗透测试报告」——每一项通过与否都能直接写成 findings。它也是蓝队加固的对照表：<strong>同一张清单，红队找漏洞，蓝队查加固</strong>。把「攻击手法」和「测试标准」放在一起记，是掌握 Web 安全最快的姿势。</span>

## 6 小结

- **会话令牌**是登录态的载体，HTTP 无状态，全靠它维持「你是谁」。
- 令牌三要素：**不可预测**（CSPRNG）、**绑定服务端**、**传输存储加锁**（`Secure`/`HttpOnly`/`SameSite`）。
- **会话劫持**靠偷令牌冒充用户，路径是嗅探、XSS、日志泄露——全站 HTTPS + HttpOnly 可挡。
- **会话固定**先塞已知令牌等受害者登录，**登录后轮换令牌**即可根治。
- **令牌预测**针对弱随机令牌，防御是密码学安全随机数 + 足够长度。
- 生命周期管理：**超时、登出即作废、并发限制**，把泄露窗口压到最小。
