## 为什么从 Web 应用防御机制开始

网络层的侦察（前六篇）让我们看见「服务器开在哪些端口」，但现代业务几乎都跑在 Web 上——**Web 应用才是攻击面最密集、最值钱的部分**。

《Web应用黑客手册》（The Web Application Hacker's Handbook，WAHH）是这一领域的权威教材，而它的第 2–4 章不是先讲漏洞，而是先讲**Web 应用由什么构成、有哪些防御机制、攻击面长什么样**。为什么倒过来学？

因为**漏洞是防御机制的「漏洞」**——不理解身份认证、会话管理、访问控制、输入处理这四道防线，就无法理解为什么 SQL 注入、越权、会话劫持能钻空子。本节目标是建立 Web 渗透的「地图感」：技术栈是什么、Burp Suite 怎么用、攻击面怎么映射。

<span class="marginnote">WAHH 第一版由 Dafydd Stuttard（PortSwigger 创始人、Burp Suite 作者）与 Marcus Pinto 合著，2007 年首版、2011 年第二版——直到今天它仍是 Web 渗透测试的「圣经」，其配套在线靶场 Web Security Academy（PortSwigger 免费提供）是练习 Web 漏洞的首选。本书的思路「先理解机制，再攻击机制」正是本节采用的结构。</span>

## 1 Web 应用技术栈：从浏览器到数据库

一个 Web 应用请求的完整路径，就是它的「纵深结构」：**浏览器 → 前端（HTML/CSS/JS）→ HTTP(S) → Web 服务器 → 应用逻辑 → 数据库/后端服务**。每一层都是攻击者可能下手的地方：

**前端层**：HTML 结构、CSS 样式、JavaScript 逻辑。攻击点：XSS、客户端校验绕过（下一篇）。

**传输层**：HTTP/HTTPS。攻击点：明文流量嗅探（上篇）、TLS 剥离。

**服务器层**：Nginx/Apache/IIS 等 Web 服务器。攻击点：配置错误、路径穿越、未打补丁的 CVE。

**应用逻辑层**：业务代码。攻击点：SQL 注入、越权、业务逻辑漏洞——**这是最丰富的攻击面**。

**数据层**：数据库、缓存、文件系统。攻击点：注入、存储型攻击、备份泄露。

**核心要点｜技术栈指纹与攻击面的关系：** 识别技术栈（用什么框架、什么版本）是攻击面映射的第一步。

工具如 **Wappalyzer**（浏览器插件）能从响应头、HTML 特征识别出 `Apache/2.4.49`、`PHP 7.4`、`Laravel 8`、`jQuery` 等——每个版本号都对应一串可查的 CVE。

<span class="marginnote">Web 技术栈在「从极限到大模型」的知识树里有自己的位置：前端（HTML/CSS/JS）见第三级《Web 前端开发》，后端框架与数据库见第三级《数据库原理》《Java 后端》等。理解技术栈不仅为了打 Web，也为了读懂一条请求在每个环节被如何处理——<strong>攻击面 = 技术栈每一层「未打补丁、配置不当、逻辑缺陷」的总和</strong>。</span>

## 2 核心防御机制：理解防线的四层

WAHH 第 3 章把 Web 应用的防御机制概括为四道防线，渗透测试的每一项攻击，本质上都是攻这四道防线：

**身份认证（Authentication）**：确认「你是谁」——用户名口令、多因素、证书。防线若弱，攻击者可以冒充合法用户（第9篇专门展开）。

**会话管理（Session Management）**：登录后怎么「保持你是谁」——通过会话令牌（session token）在多次请求间维持状态。令牌泄露或被预测，等于身份被劫持（第10篇）。

**访问控制（Access Control）**：决定「你能做什么」——授权模型、权限校验。校验缺失导致越权（第11篇）。

**输入处理（Input Handling）**：怎么对待用户的输入——过滤、转义、参数化。处理不当导致注入类漏洞（第12–14篇）。

**核心对比表｜四道防线与对应攻击：**

| 防线 | 回答的问题 | 攻破它的漏洞 |
| --- | --- | --- |
| 身份认证 | 你是谁 | 弱口令、认证绕过 |
| 会话管理 | 保持你是谁 | 会话劫持、固定 |
| 访问控制 | 你能做什么 | 越权、IDOR |
| 输入处理 | 输入怎么处理 | SQLi、XSS、命令注入 |

<span class="marginnote">WAHH 的洞见：<strong>许多应用把防御只做在一层（如仅前端校验），而每一层防线缺失都对应一类漏洞</strong>。学习时最好的框架是「防线 → 攻击」配对记忆：认证弱→撞库；会话弱→劫持；访问控制弱→越权；输入处理弱→注入。本节先把地图画出来，后面每一篇都在这张地图上定点。</span>

## 3 攻击面映射：把「所有输入点」列成清单

**攻击面（attack surface）**：应用暴露给攻击者的一切可交互入口的总和。**攻击面映射（mapping the attack surface）**是 WAHH 第 4 章的核心实践——渗透测试在攻击之前，先系统地枚举应用「在哪里接受输入」：

**枚举功能与页面**：爬取全站链接，列出每个 URL 与其参数。

**枚举输入点**：每个 URL 的查询参数、POST 表单、Cookie、HTTP 头、文件上传接口——每一个都是攻击试验的靶位。

**枚举状态与角色**：不同登录状态下（匿名/普通用户/管理员）可访问的页面集合。

**识别核心功能**：登录、注册、搜索、文件上传、支付——越「关键」的功能，越值得深挖。

**核心要点｜攻击面清单长什么样：**

| 输入点 | 位置 | 潜在攻击 |
| --- | --- | --- |
| URL 参数 | 查询字符串 | SQLi、越权 |
| POST 表单 | 请求体 | 注入、逻辑绕过 |
| Cookie | 请求头 | 会话攻击 |
| 文件上传 | multipart | WebShell |
| 请求头 | HTTP 头 | 注入、绕过 |

## 4 Burp Suite：Web 渗透的核心工具

Web 渗透测试的「瑞士军刀」是 **Burp Suite**（PortSwigger 出品，与 WAHH 同源）。它的核心能力是一个**拦截代理（intercepting proxy）**：

**代理抓包**：把浏览器流量导到 Burp，Burp 记录并允许你**修改每个请求再放行**——这是 Web 渗透与普通浏览的本质区别：你能看到、篡改浏览器与服务器之间的每一条 HTTP 消息。

**核心功能面板**：`Proxy`（拦截与历史）、`Repeater`（手工重放修改请求）、`Intruder`（自动化爆破/模糊测试）、`Decoder`（编解码）、`Comparer`（对比响应）。

<span class="marginnote">Burp 的核心心法：<strong>「信任但验证」一切客户端输入</strong>——浏览器发来的请求体可以随意改，服务器如果只信前端校验就会被打穿（这正是下一篇《绕过客户端控件》的原理）。Burp 让攻击者摆脱浏览器的约束，直接与服务器对话。</span>

**公式解析｜一次手工攻击试验的循环：**
$$
\text{观察请求} \rightarrow \text{猜测缺陷} \rightarrow \text{修改请求} \rightarrow \text{发送} \rightarrow \text{分析响应}
$$
这个循环就是 Repeater 的日常用法：把请求从 Proxy 历史里拖进 Repeater，改动某个参数（如 `id=1` 改 `id=2`），观察响应差异——越权、注入、逻辑漏洞全部从这个循环里发现。Intruder 则把这个循环自动化：对参数位置穷举字典，比较响应差异找「异常」。

**核心要点｜Burp 学习路径：**（1）学会在浏览器里配代理（127.0.0.1:8080）并装 CA 证书看 HTTPS 明文；（2）会用 Repeater 手工改包；（3）会用 Intruder 做简单爆破；（4）在 PortSwigger Web Security Academy 上靶场实操。

本专题后面各篇的 Web 攻击，全部围绕「Burp 里改请求」这一技能展开。

## 5 小结

- Web 应用技术栈是**浏览器→前端→HTTP→服务器→应用→数据**的纵深结构，每一层都是攻击面。
- WAHH 把防御归纳为**身份认证、会话管理、访问控制、输入处理**四道防线，漏洞就是防线的缺口。
- **攻击面映射**把应用的所有输入点（参数、表单、Cookie、头、上传）列成清单，是攻击前的地图。
- **Burp Suite** 是 Web 渗透的瑞士军刀，核心是拦截代理：能看到并修改每一条 HTTP 请求。
- 攻击试验的循环是「**观察→猜测→修改→发送→分析**」，Repeater 手工执行、Intruder 自动化执行。
- 攻防的起点都是「理解机制」——先懂防御，才懂漏洞。
