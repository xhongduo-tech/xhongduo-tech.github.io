## 为什么从 CTF Web 继续

本专题第2篇的八篇把 Web 渗透讲透了，而 **CTF Web 题**就是这些知识的「实战标本」：出题人把某一种真实漏洞人为保留、简化环境、加上 flag，让选手在限定范围内把它打出来。Web 题是 CTF 里**与真实工作最接近、入门性价比最高**的题型——它不像 Pwn 需要深厚的汇编功底，只要吃透 Web 漏洞原理就能解大部分题；而解一道 Web 题的过程，几乎就是一次浓缩版的 Web 渗透测试。本节把第2篇的知识「翻译」成 CTF 出题与解题视角，梳理 Web 题的高频考点、常见出题套路与解题思路。<span class="marginnote">Web 题与真实渗透的差异值得认清：CTF 题环境单一、漏洞明确、有 flag 提示，等于「告诉你有漏洞并给你打分」；真实渗透要自己发现漏洞、评估影响、遵守授权。<strong>CTF Web 练的是「手」，真实渗透练的是「眼」</strong>——前者训练利用技巧，后者训练发现与判断。</span>

## 1 Web 题的高频考点：第2篇知识的出题化

CTF Web 题的考点几乎全覆盖第2篇的漏洞类型，其中最高频的几类：

**SQL 注入**。考题的经典形态：登录绕过（`' OR '1'='1'`）、联合注入拖数据（flag 藏在数据库里）、盲注（时间/布尔）。**题目常给源码或注释提示**——`?id=` 参数、`sql` 相关文件名，直接定位注入点。工具 sqlmap 能自动化大部分，但**手工理解 payload**才能应对过滤。

**命令注入与 RCE**。考题常给一个「执行命令」的功能（ping、系统工具页面），注入分隔符拼接命令读取 flag：`;cat /flag`。过滤常见（空格、`/` 被拦），需要 `$IFS`、`${IFS}` 绕过空格、`base64` 编码绕过。

**文件上传**。上传 WebShell 拿 RCE：`.php` 被拦换 `.php5`、图片马、`.htaccess` 配置。CTF 题的环境通常给了 Web 目录与执行权限，上传成功即拿 flag。

**SSRF**。给一个「URL 请求」功能，让它访问内网服务或 `file://` 协议读文件。考点：协议限制绕过（`file://`、`gopher://`）。

**反序列化**。PHP/Java/Python 反序列化题目：利用魔术方法（`__wakeup`、`__destruct`）构造恶意对象链触发 RCE。**高难度题型**，常见于进阶赛。

**变量覆盖 / 弱类型**。PHP 特色：`$GET` 变量覆盖、`==` 宽松比较（`"admin"==0` 为真）、`md5` 碰撞（`0e...` 相等）。这类「语言特性漏洞」是 CTF 特有的出题角度。<span class="marginnote">PHP 弱类型是 CTF 特色考点：`==` 宽松比较时字符串与数字会隐式转换，`'0e12345'` 这类「科学计数法哈希」与 `0` 相等——`md5('QNKCDZO')` 与 `md5('s878926199a')` 都以 `0e` 开头，宽松比较直接相等。这类题在真实业务里极少见，却是 CTF 训练「语言边界思维」的经典素材。</span>

**核心要点｜CTF Web 高频考点：**

| 考点 | 典型题目形态 | 解题工具/思路 |
| --- | --- | --- |
| SQL 注入 | 登录绕过、注入点 | sqlmap / 手工 payload |
| 命令注入 | ping/系统功能 | 分隔符 + 空格绕过 |
| 文件上传 | WebShell 拿 RCE | 扩展名绕过、图片马 |
| SSRF | URL 请求功能 | 协议绕过、file:// |
| 反序列化 | 恶意对象链 | 构造 pop 链 |
| 弱类型 | `==` 比较绕过 | 0e 哈希、类型欺骗 |

## 2 Web 题的通用解题流程

面对一道 Web 题，遵循标准流程能避免漏掉关键信息：

**第一步：读题与看源码**。题目描述、附加的源码文件是最大的提示。CTF 题常直接给源码（或可下载的备份）——**源码审计是最强解题手段**，漏洞直接写在代码里。看 `robots.txt`、`.git` 泄露、注释里的提示。

**第二步：指纹识别与路径枚举**。访问站点看技术栈（PHP/Python/Java/Node），用 `dirsearch`/Gobuster 枚举隐藏路径——后台、`/admin`、备份文件 `www.zip`、`.git`。**隐藏文件常有源码或 flag**。

**第三步：定向测试**。根据指纹与源码确认漏洞类型，构造 payload：注入点 → 注入测试；上传点 → 上传绕过；登录 → 弱口令/绕过。用 Burp Suite 改包、Repeater 重放。

**第四步：拿 flag**。漏洞利用成功后，flag 通常在根目录（`/flag`）、数据库、Web 目录或管理员后台——读文件、查表、RCE 命令三选一。

**核心要点｜Web 题五步流程：**

1. **读题**：题面与源码是最大提示。
2. **看隐藏**：robots.txt、.git、备份文件。
3. **指纹**：技术栈决定攻击方向。
4. **定向打**：注入/上传/绕过，Burp 改包。
5. **取 flag**：文件/数据库/命令。

## 3 经典出题套路：几个必会模板

CTF Web 题有几套「模板化」出题套路，吃透它们等于拿到一半分数：

**套路一：`?file=` 文件包含（LFI/RFI）**。参数直接读文件：`?file=/flag`、`?file=php://filter/convert.base64-encode/resource=index.php`（用 php://filter 读源码）。**LFI 配日志注入/伪协议可升级 RCE**。

**套路二：`?url=` SSRF 与伪协议**。`?url=http://127.0.0.1/admin`（打内网）、`?url=file:///flag`（读文件）、`?url=gopher://`（构造任意请求）。

**套路三：`?cmd=` 命令注入/RCE**。把 flag 输出在页面：`?cmd=cat /flag`。过滤绕过是考点：空格→`$IFS`、`/`→`$(pwd)` 拼接、`cat`→`tac`/`more`、关键词→base64。

**套路四：源码泄露拿后台**。`/www.zip`、`/.git/`、`/backup` 泄露源码 → 审计出后台逻辑/管理员口令 → 登录后台 → 后台功能（上传/命令）→ RCE。

**套路五：PHP 特性综合**。变量覆盖、反序列化、弱类型组合——这类题源码审计是核心，`php://` 伪协议、PHP 函数特性（`extract`、`md5` 碰撞、`unserialize`）轮番上。<span class="marginnote">`php://filter/convert.base64-encode/resource=xxx` 是 PHP LFI 题的「万能钥匙」：直接读 PHP 源码且不执行，返回 Base64 编码的代码内容——解码即得完整源码。它绕过了「读 PHP 会被执行」的限制，让源码审计（而非黑盒猜）成为可能。熟练运用伪协议，LFI 题从「盲猜」变成「开卷」。</span>

**核心要点｜五套必会模板：**

| 模板 | 特征参数 | 快速打法 |
| --- | --- | --- |
| 文件包含 | `?file=` | php://filter 读源码 |
| SSRF | `?url=` | 伪协议 + 内网探测 |
| 命令执行 | `?cmd=` | 分隔符 + 绕过 |
| 源码泄露 | `/www.zip` | 下载审计后台 |
| PHP 特性 | 综合 | 源码审计为主 |

## 4 防御与工程视角：CTF 题的启示

CTF Web 题的价值不止于「会做题」，更在于它对防御的启示——**每一道题的漏洞原型，都是真实系统该修的缺陷**：

**源码审计 = 白盒测试**。CTF 题反复训练源码审计能力，这正是真实安全工作中白盒代码审计的核心技能——第7篇讲的「服务器信任客户端数据」「输入未校验」等缺陷，在源码里一目了然。

**框架与语言特性意识**。弱类型、伪协议、魔术方法——CTF 逼你理解语言的边界与陷阱，真实开发中这些特性正是安全 Bug 的温床。

**「默认不信任」的强化**。CTF 题的每道漏洞都在重述同一个原则：**用户输入一律不可信、安全校验必须在服务端、解析器默认关闭「输入即指令」**——第2篇反复强调的安全哲学，在 CTF 里被练成肌肉记忆。<span class="marginnote">不少企业安全团队把 CTF 作为工程师安全培训的手段：让开发人员亲手打一遍注入、XSS、上传题，比讲十遍 PPT 更深刻地理解「为什么不能拼接 SQL、为什么不能信任上传」。CTF 与工程安全的结合，正是「寓教于攻」的实践。</span>

**工具与手工的平衡。** Web 题可以用 sqlmap、Burp Scanner 等工具自动化，但**工具不是万能**：过滤注入点的 payload 需要手工调整、逻辑漏洞（越权、竞态）工具扫不出来。CTF Web 的进阶路径是「工具快速定位 + 手工精细突破」：

**核心要点｜自动化与手工的取舍：**

| 场景 | 首选 | 原因 |
| --- | --- | --- |
| 常规 SQL 注入 | sqlmap | 快且全 |
| 过滤后的注入 | 手工 | 需定制 payload |
| 逻辑漏洞 | 手工 | 工具不理解业务 |
| 上传绕过 | 手工+脚本 | 依环境定制 |

把工具当「加速器」而非「自动驾驶」，是 Web 题水平的分水岭。

## 5 小结

- **CTF Web 题**是第2篇 Web 知识的实战标本：注入、命令执行、上传、SSRF、反序列化、弱类型。
- 通用流程：**读题源码 → 看隐藏文件 → 指纹识别 → 定向测试 → 取 flag**。
- 五套必会模板：**文件包含、SSRF、命令注入、源码泄露、PHP 特性**。
- 伪协议（`php://filter`）与源码审计是 Web 题的破题双刃。
- Web 题同时训练**防御视角**：源码审计、语言特性意识、默认不信任原则。
