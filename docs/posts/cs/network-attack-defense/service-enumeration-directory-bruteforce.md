## 为什么从服务枚举继续

上一节我们用 Nmap 知道了「目标开了哪些端口、跑着什么服务」。但知道「有扇门」不等于知道「门里有什么」。**服务枚举（service enumeration）**要做的，就是把「端口开着」推进到「服务里藏着什么可用的入口」：SMB 共享里有哪个目录、SNMP 团体名是多少、Web 服务器上有哪些隐藏页面与后台路径。枚举是攻击面地图的最后一块拼图——它把「开放的服务」翻译成「可攻击的具体对象」。本节覆盖三类经典枚举：**Web 目录爆破**、**SMB 枚举**、**SNMP 枚举**，并介绍通用字典思想与工具 Gobuster、enum4linux、snmpwalk。<span class="marginnote">枚举与扫描的差别：扫描回答「开没开、是什么」，枚举回答「里面有什么、怎么进去」。同一个端口上，枚举往往比扫描多发现十倍的攻击线索——后台路径、共享目录、默认账号，全是后续利用的燃料。</span>

## 1 枚举的本质：猜名字

枚举技术千变万化，但底层逻辑高度统一——**在给定集合里遍历候选，观察哪些候选能得到「存在」的回应**。这个「遍历候选」的过程，专业术语叫**爆破（brute force）**或**暴力枚举**，而候选集来自**字典（wordlist）**。

**字典（wordlist）**：按特定主题整理出的候选字符串列表。目录爆破的字典就是「常见目录/文件名」的列表：`admin`、`backup`、`config.php`、`.git/`……质量决定枚举效果——**字典里没有的名字，爆破永远发现不了**。业界流传着几份经典字典：`SecLists`（Daniel Miessler 维护的合集）、`dirb`/`dirbuster` 自带字典、rockyou（口令字典，来自一次真实泄露）。

**核心要点｜枚举的三种回应逻辑：**

| 枚举对象 | 探测方式 | 「存在」的特征 |
| --- | --- | --- |
| HTTP 路径 | 发 `GET /<候选>` | 返回 200/301 而非 404 |
| SMB 共享 | 列出共享名 | 共享列表含该名字 |
| SNMP OID | `snmpwalk` 遍历 OID | 返回数据而非超时 |
| 子域名 | 解析 `DNS <候选>` | 返回 A 记录 |

**辨析｜易错点：** 不要把「目录爆破」理解成「一直撞到对为止」的蛮力。现实中的爆破是**定向字典 + 聪明过滤**：先确认目标框架（如 WordPress），再用其对应的字典（`wp-content` 等），并过滤 404 与重复内容，速度与准确率远高于无脑穷举。字典选择与过滤策略，往往比并发数更决定结果。

## 2 Web 目录爆破：Gobuster 实战

Web 应用的目录爆破，目标是找出**搜索引擎不收录、页面不链接**的隐藏路径：后台登录、备份文件、`.git` 泄露、配置文件、API 接口。经典工具是 **Gobuster**（Go 编写，速度快）与 **dirb/dirbuster**（老牌）。Gobuster 的基本用法：

```bash
gobuster dir -u http://example.com -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
```

参数含义：`dir` 表示目录模式，`-u` 指定目标 URL，`-w` 指定字典。Gobuster 会并发地向目标发送 `GET /<候选>` 请求，根据 HTTP 状态码判断路径是否存在。要让它更聪明，通常还会加：

`-x php,txt,bak`：对每个候选尝试多种扩展名（`config.php`、`config.txt`、`config.bak`）。
- `-k`：忽略 SSL 证书错误（目标证书自签名时）。
- `--status-codes` / `-b`：按状态码过滤，忽略 404。

**为什么状态码是核心信号？** Web 服务器对不存在路径返回 404；对存在路径返回 200（可访问）、301/302（重定向）、403（禁止访问——存在但被拦）。**403 尤其值得注意**：路径存在、但被访问控制拦截，本身就是一条攻击线索——后续可用绕过手段（改大小写、加路径穿越符、改请求方法）再试。

**核心要点｜HTTP 状态码在目录枚举中的含义：**

| 状态码 | 含义 | 枚举视角 |
| --- | --- | --- |
| 200 | 正常访问 | 路径存在且可读，高价值 |
| 301/302 | 重定向 | 存在，可能指向登录/后台 |
| 403 | 禁止访问 | 存在但被拦，需绕过 |
| 404 | 未找到 | 不存在，忽略 |
| 500 | 服务器错误 | 存在且可能出错，值得深挖 |

**辨析｜易错点：** 现代框架（如 Spring、Laravel）常把 404 统一返回 200，或用通配路由吞掉一切请求。这时「状态码判断」会失效——所有候选都返回 200。应对方案：**对比响应体长度与内容**（存在页面与 404 页面正文不同），或把已知存在的页面与不存在的响应做基线比对。工具如 `feroxbuster` 内置了响应大小/单词数的自动过滤，正是为此设计。

## 3 SMB 枚举：共享、用户与漏洞

**SMB（Server Message Block）**是 Windows 局域网共享文件/打印机的协议，通常监听 139/445 端口。SMB 服务是内网渗透的高价值目标——它可能暴露共享目录（含敏感文件）、可枚举出有效用户名（用于后续口令爆破）。Linux 下的经典枚举工具是 **enum4linux** 与 **smbclient**。

**SMB 枚举的三个重点：**

**共享枚举**。`enum4linux -S <ip>` 列出共享名，`smbclient -L //<ip>/` 交互式查看。攻击者重点找 `IPC$`、`ADMIN$`、`C$` 这类默认管理共享，以及业务共享（含文档、备份、脚本）。

**用户枚举**。SMB 协议在验证用户名是否存在时，返回信息有差异（如 NT_STATUS_LOGON_FAILURE 与 NT_STATUS_ACCOUNT_DISABLED 不同）。据此可以**批量确认哪些用户名有效**——有了有效用户名，口令爆破的命中率大幅提升。

**空会话（null session）**。老版本 Windows/Samba 在未配置安全策略时，允许**匿名登录**（空密码/空用户），直接读取共享列表与用户列表。这是 SMB 枚举最常见的高危配置。<span class="marginnote">空会话的经典利用：老式 Windows 域里 `net use \\target\ipc$</span>
