## 为什么从网络嗅探开始

渗透测试的信息收集阶段，我们一直「隔着网打探」目标；而**网络嗅探（network sniffing）**换了一个视角：**直接偷听网线上流过的数据**。攻击者一旦进入目标网络（或身处同网段），就可以把网卡调成「混杂模式」，捕获经过的每一个数据包，从中提取明文口令、敏感文件、协议细节。

流量分析则是它的另一半：拿到 `pcap` 抓包文件后，用 **Wireshark**/`tcpdump` 解析、过滤、还原，看出一段对话里藏着什么。嗅探是「内网渗透」与「网络取证」的共同基石——本专题第4篇的被动侦察、第29篇的数字取证、CTF 的流量分析题，全都建立在「会读包」这一技能上。

<span class="marginnote">嗅探的前提是「物理可达」：以太网交换机不会把别人的流量转发给你——所以在现代交换网络里，纯被动嗅探只能抓到「广播流量 + 发给自己 + 发往自己所在组的组播」。要嗅探别人的单播流量，需要 ARP 欺骗（本节第3节）这类主动手段。理解这个前提，就理解了为什么嗅探在「蜜罐/无线网/集线器网络」里尤其奏效。</span>

## 1 嗅探的原理：混杂模式与抓包

**抓包（packet capture）**的原理：正常情况下，网卡只处理「发给本机 MAC 地址」的数据帧；把网卡设置为**混杂模式（promiscuous mode）**后，网卡把**经过的所有帧**都交给上层处理——这就是「嗅探」的硬件基础。

**抓包工具两兄弟：**

**`tcpdump`**：命令行抓包器，轻量、适合服务器与脚本化。

基本用法：`sudo tcpdump -i eth0 -w capture.pcap`（抓 `eth0` 的流量写到文件）、`tcpdump -r capture.pcap`（读回文件）、`tcpdump port 80`（按端口过滤）。

**Wireshark**：图形化分析器，是 `tcpdump` 的「可视化大本营」——可以分层看每个包的以太网/IP/TCP/HTTP 结构、跟踪 TCP 流、统计协议分布。它的命令行版本 `tshark` 可脚本化。

**核心要点｜抓包三要素：** `-i` 指定网卡、`-w` 落盘保存、`filter` 指定过滤表达式（如 `host 10.0.0.1`、`tcp port 22`）。

<span class="marginnote">在 CTF 的流量取证题里，题目通常会给你一个 `capture.pcap` 文件，你的任务是还原其中隐藏的 flag——常见线索是：明文 HTTP 里的口令、DNS 隧道里的编码、图片文件传输、加密流量里的异常。Wireshark 的「Follow TCP Stream」是解这类题的第一板斧，本专题第21篇 CTF Misc 会专门训练。</span>

## 2 流量分析：从包里读故事

**流量分析（traffic analysis）**是从抓包文件中还原「发生了什么」的过程。Wireshark 打开 `pcap` 后的标准分析路径：

**看统计**。`Statistics → Protocol Hierarchy` 看协议分布——一眼看出这个流量主要是 HTTP 还是加密的 TLS。`Statistics → Endpoints`/`Conversations` 看哪些 IP 在频繁通信——异常的对端往往是攻击源或数据外带目标。

**过滤与跟踪**。`tcp.port==80`、`http.request.method=="POST"` 这类过滤器精准定位感兴趣流量；**Follow TCP Stream** 把一条完整对话拼出来——明文 HTTP 里就能直接读到用户名口令。

**还原文件**。Wireshark 能把流量里传输的文件（如图片、压缩包、二进制）导出（`File → Export Objects → HTTP`），直接还原下载内容。

**核心要点｜流量分析的典型目标：**

| 目标 | 现象 | 分析手段 |
| --- | --- | --- |
| 明文口令 | HTTP/FTP/Telnet 明文 | Follow Stream |
| 数据外带 | 大量 DNS/ICMP 异常流量 | 统计 + 深挖 |
| 恶意下载 | 传输可疑文件 | Export Objects |
| 协议异常 | 端口/协议不匹配 | 协议分层检查 |

**辨析｜易错点：** 新手抓包最常见的问题是**抓错网卡**——笔记本上好几个网卡（Wi-Fi、有线、虚拟网卡），没选对就什么都抓不到。

另一个高频误区是把**加密流量当明文**：现代 HTTPS 的载荷是密文，Wireshark 里只看到 `TLSv1.3 Application Data`，读不出内容——除非你有服务器私钥（`Edit → Preferences → RSA keys`）或用了中间人解密（对应第7篇 Burp Suite 抓 HTTPS 的思路）。

<span class="marginnote">流量分析也是<strong>网络取证的三大支柱之一</strong>（对应第29篇数字取证）：攻击者的 C2 通信、数据外带、横向移动都会在网络层面留下 pcap 痕迹。红队清痕迹要清流量日志，蓝队分析入侵要看流量日志——嗅探技能在攻防两端都是「透视眼」。</span>

## 3 ARP 欺骗：从被动偷听到主动截获

纯被动嗅探在交换网络里抓不到别人的单播流量，于是攻击者用**ARP 欺骗（ARP spoofing）**主动劫持。

先回忆 ARP（Address Resolution Protocol，地址解析协议）：主机要知道「某个 IP 的 MAC 地址」时，会广播 ARP 请求，收到 ARP 回复后缓存到 ARP 表。

**攻击原理**：攻击者向目标主机发送伪造的 ARP 回复，声称「网关 IP 的 MAC 是我」——目标主机更新 ARP 表后，发给网关的流量就会先送到攻击者网卡。攻击者嗅探后把数据转发给真实网关，完成**中间人（Man-in-the-Middle，MITM）**而不中断通信。

工具：`arpspoof`、`ettercap`、`bettercap`。

**公式解析｜中间人是否被察觉，取决于转发是否及时：**
$$
\text{漏包率} \approx \frac{\text{嗅探转发延迟}}{\text{网络正常延迟}}
$$
攻击者的网卡要先接收、复制、再转发每个包——如果转发慢于正常路径，目标会感到网络「卡顿」，暴露可能性上升。所以高效的 MITM 嗅探要求**低延迟转发 + 不中断连接**——这也是蓝队检测 ARP 欺骗的切入点（异常 ARP 告警）。

<span class="marginnote">ARP 欺骗的经典场景：公共 Wi-Fi 下嗅探同网段用户、内网里截获域管理员凭据、与 TLS 剥离（SSL strip）配合把 HTTPS 降级成 HTTP 再读明文。防御手段是 DHCP Snooping + 动态 ARP 检测（DAI）或静态 ARP 表——这也是蓝队加固的常规项目。</span>

**核心对比表｜被动嗅探 vs ARP 欺骗：**

| 维度 | 被动嗅探 | ARP 欺骗 |
| --- | --- | --- |
| 数据来源 | 广播/本机流量 | 劫持他人流量 |
| 目标感知 | 无 | 可能（卡顿/告警） |
| 前提 | 混杂模式 | 同网段 + 转发 |
| 隐蔽性 | 高 | 中 |
| 典型工具 | tcpdump | arpspoof/ettercap |

## 4 嗅探的防御：让偷听失效

嗅探的前提是「数据明文可达」——防御的核心就是让这两个条件失效：让数据不可读、让数据不可达。

**让数据不可读（加密）**：**全站 HTTPS/TLS** 让 HTTP 载荷加密，嗅探只能看到密文（呼应第7篇 Burp 抓 HTTPS 需装证书）；**Wi-Fi 用 WPA2/WPA3 加密**（WPA2 的 CCMP 加密让无线嗅探失效，WEP 则已可秒破——这正是 CTF 里「破解 WEP」题的原理）；远程访问用 **VPN** 建立加密隧道。

**让数据不可达（网络隔离）**：**交换机端口安全**（限制端口 MAC 数，防攻击者插入）与 **802.1X 认证**（终端接入先认证）；**DHCP Snooping + DAI（动态 ARP 检测）**拦截伪造的 DHCP 与 ARP 报文——ARP 欺骗（第3节）直接失效；网络分段把敏感网段与用户网段隔离。

**核心对比表｜嗅探攻击与防御：**

| 攻击 | 防御 | 原理 |
| --- | --- | --- |
| 明文嗅探 | 全站 HTTPS | 加密载荷 |
| 无线嗅探 | WPA2/WPA3 | 加密无线帧 |
| ARP 欺骗 | DAI | 校验 ARP 报文 |
| 端口接入 | 802.1X | 终端认证 |

<span class="marginnote">「加密 vs 隔离」是网络安全的两大母题：加密解决「被偷听」，隔离解决「被到达」。现实中两者要配合——<strong>即便加密，也不要把敏感网段暴露在不可信网段</strong>；即便隔离，明文协议（HTTP、Telnet）依然是嗅探的富矿。蓝队加固时，先改明文协议、再上加密、最后做隔离，逐层压缩嗅探的空间。</span>

## 5 小结

- **网络嗅探**靠混杂模式抓取网线上流过的数据包，**流量分析**用 Wireshark/tcpdump 从中还原事实。
- `tcpdump` 抓包三要素：`-i` 网卡、`-w` 落盘、filter 过滤；Wireshark 负责图形化深挖。
- 分析的标准路径：**统计 → 过滤 → Follow Stream → 还原文件**；明文协议（HTTP/FTP）是口令提取的富矿。
- 加密流量读不出明文，除非拥有私钥或做中间人解密——HTTPS 不是嗅探的盲区，而是「解密门槛」。
- **ARP 欺骗**通过伪造 ARP 回复完成中间人劫持，从被动偷听升级为主动截获。
- 嗅探技能贯穿内网渗透、CTF 取证、数字取证与蓝队分析，是攻防两端共同的透视眼。
