## 为什么从整条链路开始

搜索是「从极限到大模型」这条主线上最古老、也最完整的工程叙事之一：它把文本处理、数据结构、概率统计、机器学习、分布式系统、经济学与产品设计揉进同一条流水线。你在第三级《数据结构》里学的跳表、在第二级《概率论与数理统计》里学的贝叶斯、在第四级《机器学习》里学的排序模型，都会在这条链路上找到各自的工位。<span class="marginnote">本专题对标三本书：Manning 等《Introduction to Information Retrieval》（IR 基础）、Liu《Learning to Rank》（排序学习）、刘鹏《计算广告》（变现端）。三本合起来，正好覆盖「搜得到→排得准→赚得到」。</span>因此第一课不急着钻任何一个模块，而是先站在一万米高空，把整条链路画清楚——后面每一课都是这张图里的一个放大镜。

搜索引擎还是一条「教科书很成熟、工业界更凶悍」的战线。Manning 2008 年的教材里讲的是千万级文档的经典 IR，而今天的 Google 索引已经超过 4000 亿个网页。把教科书思想放大到这个规模，靠的不是灵光一闪，而是一套环环相扣的工程体系——这正是本专题真正想训练的东西：**给一块零件时你能造零件，给整条流水线时你能设计流水线。**

这十二课的路标也在这里：第1–7课走「检索与排序」这条 IR 主线，第8–12课转向「计算广告」这条变现主线。两条线共用同一种思维方式——**在约束下把相关度与收益同时优化**。搜索引擎是互联网的第一代「AI 产品」，而计算广告是互联网最大的商业模式；两套工程合起来，才是 Web 搜索引擎完整的样子。

## 1 一条查询背后站着多少系统

在搜索框里敲下一句「北京到上海的高铁时刻」，按下回车，这 0.2 秒里发生了不止一次查询，而是一整条**流水线（pipeline）**的分工。教科书把这条流水线拆成四个阶段：**爬取（crawling）**、**索引（indexing）**、**检索（retrieval）**、**排序（ranking）**。

其中前两个阶段是**离线（offline）**的：爬虫在查询发生之前就建好了 Web 图的副本，索引在查询发生之前就把文档组织成可查询的结构。后两个阶段是**在线（online）**的：每一次查询都要即时完成。<span class="marginnote">「离线多干活、在线少干活」是搜索引擎最根本的工程哲学。你把复杂度从用户等不起的地方，搬到系统有时间的地方。Manning 第1章把这一点讲得非常清楚：布尔检索之所以快，就是因为它把所有预处理都提前做完了。</span>理解这条「离线/在线」的分界线，比记住任何一个具体算法都重要——它是后面所有性能讨论的坐标系。

四个阶段还可以再压成一句顺口溜：**爬是为了有得搜，建索引是为了搜得快，检索是为了搜得到，排序是为了搜得准。**本专题第2课讲索引、第3课讲检索模型、第5课讲排序、第8课以后讲搜索如何变成生意。你现在记住这句话，就等于拿到了整张地图的图例。

值得强调，这四个阶段的工程量级完全不对称：爬取与索引是「万台机器跑几周的活」，检索与排序是「毫秒级的活」。理解这种不对称，你就能明白为什么搜索引擎公司真正的护城河往往在离线侧——**数据量与索引质量，比排序模型的精巧更值钱。**

## 2 离线链路：爬取与索引构建

**爬虫（web crawler / spider）** 从一组种子 URL 出发，下载网页、解析出超链接、把新链接加入待抓取队列，如此反复。Manning 第20章指出，一个能用的爬虫必须解决三件事：**礼貌（politeness）**——不要对同一站点造成过大的请求压力；**去重（deduplication）**——用 URL 规范化与内容指纹（如 shingles 或 hash）避免重复抓取；**新鲜度（freshness）**——页面会变，要按一定的重访策略保持索引不腐坏。Google 1998 年最初的原型就用 Python 写了最简单的爬虫，后来演化成成千上万台机器并行抓取、以比特为单位的增量更新。

抓下来的原始页面不能直接被查询。搜索引擎会做**标记化（tokenization）**、**去停用词（stop words）**、**词干化（stemming）**，然后构建**倒排索引（inverted index）**——这是下一课的绝对主角。一句话概括它的形态：**从「每个文档有哪些词」反转为「每个词出现在哪些文档」**，即一个词项（term）到其所在文档列表（postings list）的映射。<span class="marginnote">爬取之外的另一个离线大头是<strong>网页排名</strong>：PageRank、HITS 这类链接分析算法（Manning 第21章）也是离线算好的，在线排序时直接读取。搜索引擎的排序从来不是「临时起意」，而是「离线缓存好的知识 + 在线轻量计算」的混合体。</span>这一大段离线工程，决定了你敲下的每个查询能「找得到」哪些候选。

为什么要先做一堆**预处理（normalization）**再进索引？因为「Beijing」「beijing」「北京」在用户眼里是同一个意思。标记化决定词的粒度，停用词表决定哪些词不进词典，词干化把 runs / running / run 归并到同一条。这些决定看着琐碎，却直接决定索引大小、召回率和下面第三课讲的打分质量。Manning 第2章用一整章讲它们，就是这个道理——**检索的质量在建立索引那一刻就已注定一半。**

爬虫的「礼貌」有一个落地细节值得记住：站点通过 `robots.txt` 声明允许爬取哪些路径，合规爬虫必须遵守，抓取同一站点的请求频率也要受限。这不是道德问题，而是工程问题——不礼貌的爬虫会被站点直接封禁，反而破坏数据管道。到第8课讲广告系统工程时你会看到，这套「给对方留余量」的博弈思维在反作弊、流量控制里会以另一种面目反复出现。

## 3 在线链路：检索、打分与排序

查询到达时，**检索（retrieval）**阶段先在词典里找到查询词的倒排表，把它们求交/求并，得到一个**候选文档集合（candidate set）**。随后**打分（scoring）**阶段为每个候选算出一个相关度分数，**排序（ranking）**阶段按分数降序截取前 $k$ 条返回。这三步在教科书里对应一个统一的问题：**给定查询 $q$，为文档 $d$ 定义一个相关度函数 $\text{score}(q, d)$，再按它排序。**<span class="marginnote">打分函数是检索模型要回答的核心问题，第三课《检索模型》会把布尔模型、向量空间模型、BM25 一一展开。这里的要点是先立住框架：所有模型都只是在给「查询—文档相关度」找个数字。</span>

整条链路的**在线预算**是极其严苛的：主流搜索引擎的查询延迟预算大约在 100–300 毫秒。考虑到语料规模是百亿级网页，而任何一个查询命中倒排表后候选集都可能有成千上万篇文档，「每毫秒都要省」就成了排序阶段引入级联（cascade）、在前几轮只读摘要字段（anchor、title）而不是全文的原因。

在线与离线之间还有一层**缓存（cache）**。热门查询的结果可以直接复用，不必每毫秒都重新算一遍——Google 最热门的几千个查询占了总流量的相当比例，命中缓存的查询只需要几十毫秒。缓存是「拿空间换延迟」的最朴素形态，也是所有大型在线系统的第一课。

还应当注意，**排序结果的「展示层」也是产品层**：摘要（snippet）截自文档哪一段、关键词如何高亮、结果页上附哪些结构化信息（日期、评分、视频卡片），都会影响用户的点击与满意。搜索工程师常说「排名的结果就是产品的界面」，这提醒我们——这条链路最终通向的是人，而不是更漂亮的指标。

## 4 公式解析：响应时间预算

把在线查询时间写成四项之和，就能看清每一阶段的量级：

$$
T_{\text{query}} = T_{\text{dict}} + T_{\text{postings}} + T_{\text{score}} + T_{\text{rank}}
$$

逐项拆解：

- **$T_{\text{dict}}$**：在词典里定位查询词（哈希或字典树查找），毫秒级以下，几乎可忽略。
- **$T_{\text{postings}}$**：遍历倒排表求交。用跳表（skip pointers）可以让它做到与最短路程成正比，而不是与倒排表全长成正比。
- **$T_{\text{score}}$**：对候选集逐篇算相关度。它与候选规模 $|C|$ 成正比，是四者中增长最快的项——这就是为什么各大引擎都用「先粗排再精排」的两阶段结构，粗排用便宜的线性打分（如 BM25）把候选从数万砍到几百，精排再上昂贵的学习排序模型。
- **$T_{\text{rank}}$**：对精排后的少量候选做全排序，此时规模小，堆排序或归并即可。

于是「**粗排 = 便宜但粗略，精排 = 昂贵但精确**」的分工不是一个可选项，而是响应时间预算逼出来的必然结构。这个「级联式排序」的思想会一直贯穿到第五课的 LambdaMART 与第六课的向量召回。若把规模代入：$T_{\text{score}}$ 项随候选数 $|C|$ 线性增长，而 $|C|$ 在 Web 规模下可以轻易到达 $10^5$ 甚至 $10^6$，若不先粗排直接对全体精排，仅打分一项就会击穿 300 毫秒的预算。

再补一个直觉：**预算约束本身也是一种产品决策**。300 毫秒不是随便定的，眼动实验与用户行为数据都表明，响应时间超过约 1 秒，用户放弃或改用其他搜索的倾向显著上升。于是「快」与「准」被同一个数字绑在了一起——这也解释了为什么搜索引擎愿意花那么多工程力气去压缩索引、缓存结果、级联排序。快，是准的前提。

## 5 一次真实查询的端到端之旅

把上面的框架套进一个具体的查询，看它如何走完全程。假设用户输入「北京 高铁 时刻」：

**第一步，查询处理（在线）**。分词器把它切成三个词项：`北京`、`高铁`、`时刻`。此时系统可能顺手做**查询扩展**：查同义词词典，把 `高铁` 关联到 `动车`，扩大召回。这一块是第四课《查询理解与改写》的主题。

**第二步，检索候选（在线）**。三个词项各自指向一条倒排表：`北京` 有 2 亿篇文档，`高铁` 有 2000 万篇，`时刻` 有 8000 万篇。三表求交后，候选集缩到约 30 万篇——**求交的顺序和机制（跳表、自适应的 AND/OR）决定了这一步有多快**，第二课会给出精确的算法。

**第三步，粗排（在线）**。对 30 万篇候选用 BM25 打分，只读 title 与 anchor 字段，取前 1000 篇进精排。这一步几毫秒完成。

**第四步，精排（在线）**。对 1000 篇跑学习排序模型（第五课），综合相关度、时效性、权威度，最后选出前 10 条拼装结果页，附上摘要与高亮。

**第五步，商业层（在线）**。若这套搜索属于某个商业平台，结果页顶部会插广告位——广告的挑选与排序（第8课以后）和自然结果并行进行，但预算与计费规则完全不同。

把这个五步旅程记住，后面每一课都是其中某一步的深潜。教科书与工业界的差距也在这里显形：教科书通常只讲第二、三步的经典算法，而工业界的系统把这五步连同缓存、容灾、AB 实验一起焊进了同一个分布式架构。

**辨析｜易错点：** 初学常把「检索」与「排序」混为一谈。严格地说，检索负责「从全部文档中找出候选」，排序负责「把候选排个好次序」。两者的输入输出、目标函数、对错标准都不同：检索的好坏用召回率衡量，排序的好坏用排序质量（如 NDCG）衡量。这个区分在第5、7课会反复出现——把边界划清楚，后面才不会糊涂。

## 6 教科书里的总览：Manning 第1章与第19–20章

Manning、Raghavan 与 Schütze 的《Introduction to Information Retrieval》是本专题 IR 部分的地基，其结构本身就是一份「搜索引擎总览」：

| 链路环节 | 教科书章节 | 要解决的核心问题 |
| --- | --- | --- |
| 布尔检索 | 第1章 Boolean Retrieval | 倒排索引怎么支持 AND/OR/NOT |
| 词典与倒排表 | 第2章 Term Vocabulary and Postings | 标记化、跳表、位置信息 |
| 索引构建 | 第4章 Index Construction | 亿级文档怎么一次性建索引 |
| 索引压缩 | 第5章 Index Compression | 词典与倒排表如何瘦身 |
| 打分与排序 | 第6–7章 Scoring & Computing Scores | 向量空间模型、分块排序 |
| Web 搜索 | 第19–20章 Web Search Basics / Crawling | 爬虫、Web 规模、链接分析 |

第19章还专门讨论了 Web 搜索与教科书经典检索的差异：Web 规模大（数十亿文档）、是超文本（含锚文本与结构）、充满垃圾（spam）。这三条差异直接塑造了工业搜索的形态——规模逼出压缩与级联，超文本催生 PageRank，垃圾催生反作弊。本专题第8课以后进入的广告变现，正是附着在这套 Web 检索基础设施之上的商业层。

顺带一提，Manning 这本教材的电子版在斯坦福 NLP 组官网公开可读（nlp.stanford.edu/IR-book），章节号与印刷版几乎一致。本专题引用它的章节时，你随时可以翻开原文对照——这是「权威教材为准绳」最实在的落地方式。

## 7 小结

- 搜索引擎是一条**四阶段流水线**：爬取→索引→检索→排序；前两阶段离线完成，后两阶段在线完成。
- **离线/在线分工**是搜索引擎的第一工程哲学：把复杂度从查询路径上挪走，用户等不起的部分全部提前做。
- 在线响应时间预算约 100–300 毫秒，由 $T_{\text{dict}} + T_{\text{postings}} + T_{\text{score}} + T_{\text{rank}}$ 四部分构成，**$T_{\text{score}}$ 随候选规模增长最快**，于是级联排序成了必然。
- 一次真实查询要走**查询处理→候选检索→粗排→精排→商业层**五步，教科书多覆盖中间两步，工业界五步全焊。
- Web 搜索与经典 IR 的三大差异——规模、超文本、垃圾——塑造了压缩、PageRank、反作弊三大研究线。
- 本专题后续每篇都是本课这张图里一个模块的放大：第二课放大「索引」，第三课放大「打分」，第五课放大「排序」。
- 学习这张总图时给自己留一个追问习惯：**每一环是离线还是在线？慢在哪？瓶颈能不能用预处理消化？**——这套提问法会陪伴你走完整个专题。
- 搜索引擎的本质是一个**在时间预算内做最佳取舍**的系统工程：快、准、全、钱四者不可兼得，每一课都在教你在哪一步把哪一个指标让出去。

在下一节，我们将放大整条链路的枢纽——**倒排索引**，看它如何压缩词典、如何用跳表加速求交、以及如何被离线构建与在线更新。
