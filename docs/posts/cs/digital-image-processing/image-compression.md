## 为什么从图像压缩开始

回到第一篇的第一笔账：一张 $1920 \times 1080$ 的彩色照片约 6 MiB，一部电影超过 800 GiB。没有压缩，今天的一切数字影像服务都不存在。**图像压缩**研究的是「在尽量少损失的前提下，把图像数据量压下去」——它把信息论的抽象概念（熵、冗余、率失真）落到 JPEG、PNG、JPEG2000 这些每天都要打交道的格式上。学压缩，你收获的不只是几个编解码器的知识，而是「什么信息该留、什么信息可以扔」的判断力。这与语言模型里的「token 化 / 压缩」、数据库里的编码优化，都是同一族思想。

## 1 压缩的三重冗余

压缩的本质是**去除冗余（redundancy）**。图像里的冗余有三类，对应三种压缩手段：

**编码冗余**：灰度级被赋予的码字长度与它出现的概率不匹配。若 8 bit 均匀编码每个灰度级，但实际图像里「灰 128」出现概率 40%、「灰 0」只有 0.1%，就该给高概率灰度赋短码字——这就是**变长编码**（哈夫曼、算术编码）的思想。

**空间冗余**：相邻像素高度相关，天空一整片都是同一个灰度，逐像素存储是极大的浪费。**行程编码（RLE）**把「5555555」记成「7,5」；更通用的**预测编码**用邻近像素预测当前值，只存预测误差。

**心理视觉冗余**：人眼对不同信息的敏感度不同——对高频细节、对色彩（尤其是蓝色通道）不那么敏感。<span class="marginnote"><strong>辨析｜易错点：</strong> 前两类冗余的去除是<strong>无损</strong>的（可完全重建），心理视觉冗余的去除是<strong>有损</strong>的（扔掉的确实是人眼几乎感知不到的信息）。JPEG 是「无损编码（哈夫曼）+ 有损变换（DCT 量化）」的混合体；无损压缩与有损压缩的区别不是算法种类，而是「有没有扔掉不可逆的信息」。</span>

## 2 无损压缩：熵与变长编码

**信息量（自信息）**：事件 $e$ 出现的概率为 $P(e)$，则它携带的信息量是

$$I(e) = \log_2 \frac{1}{P(e)} = -\log_2 P(e) \quad \text{bit}$$

概率越小的事件越「出乎意料」，信息量越大。整幅图像的**熵**是所有灰度级的平均自信息：

$$H = -\sum_{k=0}^{L-1} p(r_k)\, \log_2 p(r_k)$$

熵是「每像素最少需要的比特数」的理论下界——任何无损编码的平均码长都不可能低于 $H$。**哈夫曼编码**构造一棵最优二叉树，给出最接近熵界的变长码：高概率灰度用短码，低概率用长码。<span class="marginnote"><strong>辨析｜易错点：</strong> 哈夫曼码是「最优前缀码」，但它是对<strong>单符号</strong>编码；若灰度级间还有相关（相邻像素像），单符号熵已经包含了这个信息，此时要再靠预测/变换把相关性拆掉，才能进一步逼近真熵。所以完整的压缩管线总是「先去相关，再熵编码」两步。</span>

## 3 有损压缩：变换 + 量化

有损压缩的核心是「把信息搬到更容易丢弃的表示里」。**变换编码**先把图像变换到能量集中的域，再做量化。

**DCT（离散余弦变换）**是 JPEG 的核心。与傅里叶变换不同，DCT 只取余弦基，对自然图像的能量集中性极好——大部分能量压进少数低频系数。<span class="marginnote">二维 DCT 与 DFT 的关系：DCT 可看成「先对图像做镜像对称延拓再取 DFT」的实部。因为镜像使边界连续，DCT 在图像块上的「边界效应」比 DFT 轻，能量更集中——这是 JPEG 选 DCT 而不是 DFT 的直接原因。</span>

**量化**是有损压缩真正的「损失发生处」：用一个量化表去除以变换系数并取整，高频系数大量变成零。量化步长越大，零越多、压缩率越高、损失越大——这就是 JPEG「质量参数」的物理含义。

## 4 公式解析：JPEG 的完整管线

JPEG 基线系统（baseline）对每张图像执行六个环节：

1. **分块**：把图像切成互不重叠的 $8 \times 8$ 像素块。
2. **中心化**：每个块整体减去 128，把灰度范围搬到以零为中心。
3. **DCT**：对每块做二维 DCT，得 64 个系数 $F(u,v)$。定义 $C(u) = 1/\sqrt{2}$（$u=0$）否则 $1$：

$$F(u,v) = \frac{1}{4} C(u)C(v) \sum_{x=0}^{7}\sum_{y=0}^{7} f(x,y)\cos\frac{(2x+1)u\pi}{16}\cos\frac{(2y+1)v\pi}{16}$$

4. **量化**：$F_q(u,v) = \operatorname{round}\!\left( \frac{F(u,v)}{Q(u,v)} \right)$，$Q$ 是 64 个量化步长构成的表。高频的 $Q$ 大，系数被压成零。
5. **之字形扫描（zig-zag）**：按「低频 → 高频」的之字形顺序把 64 个系数排成一维序列——因为量化后高频大都是零，这样排列把零集中成长串。
6. **熵编码**：直流系数用 DPCM 预测（存与前块的差），交流系数用 RLE 压缩零游程 + 哈夫曼编码。

逐项拆解：

- **$C(u)C(v)$**：正交性归一化因子，保证 DCT 是正交变换、能量守恒。
- **$\cos\frac{(2x+1)u\pi}{16}$**：第 $u$ 个余弦基在位置 $x$ 的取值——$u$ 越小基波越缓，$u = 0$ 是常数项（直流）。
- **除以 $Q(u,v)$ 取整**：唯一的有损步骤，量化的就是人眼不敏感的高频。
- **之字形 + RLE**：把二维稀疏矩阵转成一维零游程，是熵编码前的「去相关」整理。

解码是镜像流程：反量化（乘回 $Q$）→ 逆 DCT → 加重构误差。**辨析｜易错点：** 压缩的损耗全部发生在量化一步；「JPEG 有损」不等于「JPEG 必糊」——把 $Q$ 表整体缩小，损失可以压到肉眼不可辨，代价是文件变大。

## 5 JPEG2000 与小波压缩

JPEG 的高频分块带来了一个经典瑕疵：**块效应（blocking artifact）**——压缩率升高时，$8 \times 8$ 块的边界现出可辨的方格。**JPEG2000** 用上一节的小波变换替代 DCT 分块方案：<span class="marginnote">JPEG2000 的管线：整幅图像小波分解 → 嵌入式量化编码（EBCOT）→ 算术编码。小波基覆盖整幅图像，没有块边界，块效应从根上消失；编码器按重要性逐比特输出码流，支持<strong>渐进传输</strong>（先传概貌、越传越精细）与<strong>ROI 高保真</strong>（脸部等区域优先保质量）。</span> 代价是计算量大一个数量级，早期 JPEG2000 在软硬件上都没跑起来——技术优势不等于市场成功，这是工程史上的经典一课。

## 6 压缩格式速查与工程选型

不同的压缩格式站在「无损/有损」「通用/专用」两个维度的不同位置：

| 格式 | 类型 | 核心技术 | 典型场景 |
| --- | --- | --- | --- |
| PNG | 无损 | 预测 + 熵编码 | 截图、图标、程序资产 |
| GIF | 无损（调色板） | 调色板 + LZW | 简单动画、低色彩图 |
| JPEG | 有损 | DCT + 量化 + 哈夫曼 | 照片、自然图像 |
| JPEG2000 | 有损/无损 | 小波 + EBCOT | 医学影像、专业摄影 |
| WebP | 有损/无损 | 预测 + DCT/VP8 | 网页图片，体积更小 |
| HEIC/AVIF | 有损 | 块变换 + 帧内预测 | 手机照片、现代浏览器 |

**选择逻辑**：有细腻渐变与文字边缘的图（截图、UI）选 PNG——JPEG 的量化会在锐利边缘产生振铃；照片选 JPEG 或 AVIF——人眼对照片的轻微损失不敏感；需要透明通道选 PNG 或 WebP；需要专业保真选 JPEG2000。

**压缩率的两个经典数字**：JPEG 质量参数 75（常见默认）大约把照片压到原始的 1/10 到 1/20，肉眼几乎不可辨；质量降到 20 左右，块效应开始明显。无损压缩（PNG）对照片通常只能压到 1/2 到 1/3——自然图像的「熵」本身就这么高。

**为什么「先试无损」总是好习惯**：在不知道下游用途时，无损是无悔的选择——任何有损压缩的损失都是永久的。工程上常用的做法是「无损存档、有损分发」：原始数据存 PNG/无损 JPEG2000，线上服务用有损格式。

**压缩与信息论的收束**：香农告诉我们，任何无损压缩都压不过熵 $H$。有损压缩之所以能远低于 $H$，是因为它「主动扔掉」了人眼不需要的信息——这是率失真理论（rate-distortion）的核心，也是「压缩率 vs 质量」永远要权衡的本质原因。

**一个值得动手的小实验**：同一张照片分别用 JPEG（质量 90、50、10）保存，对比文件大小与放大后的画质。你会亲眼看到三条规律——质量越低文件越小、块效应先出现在天空这类平坦区、锐利边缘的振铃最先出现。这比任何描述都能建立「量化代价」的直觉。

**关于元数据**：现代压缩格式都允许携带 EXIF 等元数据，图片尺寸、拍摄参数、色彩配置都塞在里面。压缩时要注意「是否保留色彩配置（ICC 配置文件）」——丢了它，同一张图在不同设备上会呈现完全不同的颜色。

**一个估算记忆**：设原图 $b$ 字节，压缩率 $r$，则压缩后约 $b/r$ 字节。对 JPEG 取 $r \approx 10$，对 PNG 取 $r \approx 2.5$，对 AVIF 取 $r \approx 20$——三秒钟心算，就能判断「这张图该用什么格式传」。

**块效应 vs 振铃**：JPEG 的块效应是「分块 DCT」的直接后果；小波方案没有块，但过度量化会产生平滑区域的「水渍感」（振铃）。两类伪影都是「量化过狠」的信号，肉眼分辨它们，是压缩质检的基本功。

**有损压缩的「预览」陷阱**：在线图片服务常先生成多档尺寸的小图，再按需传原图。若小图压缩过狠，用户在大屏上放大时会看到「糊」——这不是原图的问题，而是预览档的量化太重。

**为什么要学压缩**：因为「存储 vs 质量」的权衡是图像工程的第一道选择题——它决定了你的系统是 6 MiB 一张图还是 0.5 MiB 一张图，决定了存储成本与加载体验。而选择的能力，来自对熵、量化和率失真的理解。

**有损压缩的无损「底」**：JPEG 无法完全无损，但 JPEG-LS（无损 JPEG 标准）与 PNG 可以——它们的共同点是只做预测 + 熵编码，不做 DCT 量化。需要「绝对无损存档」（法律文件、医学原片）时，用这些格式而不是常规 JPEG。

## 7 小结

- 压缩靠**去冗余**：编码冗余、空间冗余、心理视觉冗余，分别用变长编码、预测/变换、量化去除。
- **信息量与熵**：$I = -\log_2 P$，熵 $H = -\sum p \log_2 p$ 是任何无损编码的平均码长下界。
- **有损压缩管线**：去相关（预测/DCT/小波）→ 量化（唯一有损步骤）→ 熵编码（哈夫曼/算术）。
- **格式选型**：截图用 PNG、照片用 JPEG/AVIF、专业保真用 JPEG2000、网页用 WebP——「无损存档、有损分发」是工程惯例。
- **JPEG 六环节**：分块 → 中心化 → DCT → 量化 → 之字形扫描 → 熵编码；量化步长表是唯一「质量旋钮」。
