## 为什么从彩色图像处理开始

到目前为止，我们处理的都是单通道灰度图像。但真实世界是彩色的，传感器也天然采集三通道信息——RGB 每个通道各一张图。**彩色图像处理**要回答两个层面的问题：其一，颜色如何被建模（颜色模型），让「三个数」稳定地对应一种可复现的颜色；其二，灰度图像处理的技术如何在彩色上扩展——是逐通道独立处理，还是在某个颜色空间中整体处理。彩色分割、肤色检测、白平衡、图像检索里的颜色直方图，全部建立在这套模型之上；理解它，也是理解显示、打印、摄影后期（色彩管理）的底层逻辑。

## 1 颜色模型：颜色也要有坐标

颜色是三维的，需要三个分量表示。**颜色模型（color model / color space）**就是给颜色建立坐标系。

**RGB 模型**：用红、绿、蓝三个基色线性混合。它基于加色法——显示器在暗室里发光，三种荧光按比例叠加。<span class="marginnote"><strong>加色法 vs 减色法</strong>：显示器的 RGB 是加色（黑底加光），印刷的 CMY（青、品红、黄）是减色（白纸减光）。CMY 的互补性：青 = 白 − 红，品红 = 白 − 绿，黄 = 白 − 蓝。RGB 立方体与 CMY 立方体是对角的互补关系。</span>

**HSI 模型**：把颜色分解为**色调（hue，H，是什么色）**、**饱和度（saturation，S，有多浓）**、**亮度（intensity，I，有多亮）**三个知觉分量。HSI 的吸引力在于它贴近人眼认知：灰度处理只动 $I$，色调与饱和度保持，即可自然避免彩色失真。

## 2 公式解析：RGB 到 HSI 的转换

灰度技术想安全地搬到彩色上，最稳的做法是转到 HSI，只处理亮度分量 $I$。转换公式是分段的：

$$I = \frac{R + G + B}{3}$$

$$S = 1 - \frac{3}{R + G + B} \min(R, G, B)$$

$$H = \begin{cases} \theta & \text{若 } B \le G \\ 360^{\circ} - \theta & \text{若 } B > G \end{cases}, \qquad \theta = \cos^{-1}\left[ \frac{\frac{1}{2}\left[(R-G) + (R-B)\right]}{\sqrt{(R-G)^2 + (R-B)(G-B)}} \right]$$

逐项拆解：

- **$I$**：三分量的算术平均，就是灰度的自然推广——把彩色图像三个通道平均，正是「去饱和成灰度图」的标准做法。
- **$S$**：1 减去「最小分量占平均的比例」。$R = G = B$ 时（纯灰）$S = 0$；某个分量远小于其余时 $S$ 接近 1，颜色最浓。
- **$\theta$**：把 $(R,G,B)$ 视作三维空间中的点，$\theta$ 是该点在色环上相对红色轴的角度——它就是「颜色离红色转了多少度」。
- **$B \le G$ 分段**：余弦的反函数值域是 $[0, 180^{\circ}]$，而色环是 $360^{\circ}$，必须用 $B$ 与 $G$ 的大小关系判断角度落在上半环还是下半环。<span class="marginnote"><strong>辨析｜易错点：</strong> 反余弦只给半圆，漏掉分段条件会得到「一半颜色完全错位」的结果。工程实现里这类「反三角函数 + 象限判断」的模式极常见，是文档里最容易被照抄抄错的角落。</span>

反变换（HSI → RGB）按 $H$ 落在 $[0,120)$、$[120,240)$、$[240,360)$ 三个扇区分段，用矢量旋转公式回算——结构对称，此处从略。

## 3 伪彩色与全彩色处理

按处理对象，彩色处理分两大类：

**伪彩色（pseudo-color）处理**：输入是单通道灰度，输出是彩色——用一张查色表（LUT）把每个灰度级映射成一种颜色。最著名的例子是医学与遥感里的**热力图**：温度或海拔的灰度图按彩虹色带染色，人眼对颜色梯度的分辨力远高于灰度梯度，细节一目了然。<span class="marginnote">伪彩色不是「还原真实颜色」，而是「用颜色编码信息」——它能显著提升人眼的辨别能力，但颜色本身是人为约定的。<strong>辨析｜易错点：</strong> 伪彩色 ≠ 假彩色。伪彩色从灰度推颜色；假彩色（false color）是对真实多光谱数据的重新着色，比如植被在标准假彩色影像里显示为红色。</span>

**全彩色（full-color）处理**：输入就是彩色图像。有两种策略——**逐通道独立处理**（三个通道各做一次灰度算法，再合并）与**矢量处理**（把每个像素的三分量当作一个向量整体操作）。逐通道处理在「通道间不相关」的操作（如各通道直方图均衡化）里简单有效，但一旦操作会在通道间引入串扰（如旋转色相），就必须走矢量路线。

## 4 彩色变换与分割

**彩色变换**是灰度变换 $s = T(r)$ 的彩色推广：$s_i = T_i(r_1, r_2, r_3)$，$i = 1, 2, 3$。三类典型操作：

**彩色校正**：调整色调、饱和度或明度。把图像转 HSI 后对 $S$ 乘一个系数、对 $I$ 做伽马变换，再转回 RGB——这就是美颜软件里「饱和度」滑块的实现原理。

**彩色直方图均衡化**：对每个 RGB 通道独立做直方图均衡化，会同时改变颜色平衡（色调偏移）。更稳的做法是转 HSI 后只对 $I$ 做均衡化，色调与饱和度纹丝不动——这正是上一节「灰度技术迁到彩色」的最佳示范。

**彩色分割**：在颜色空间里做距离度量。设目标颜色的中心为 $\mathbf{a} = (a_1, a_2, a_3)$，像素 $\mathbf{z} = (z_1, z_2, z_3)$ 到中心的**欧氏距离**

$$D(\mathbf{z}, \mathbf{a}) = \sqrt{(z_1 - a_1)^2 + (z_2 - a_2)^2 + (z_3 - a_3)^2}$$

小于阈值 $D_0$ 的像素被判为「属于目标颜色」。肤色检测、绿幕抠像、遥感地物分类都是这个模式。<span class="marginnote"><strong>辨析｜易错点：</strong> 用 RGB 直接做距离，会把「亮度不同但色调相同」的像素误判为不同颜色——同一个人脸的受光面与背光面在 RGB 里相去甚远。改在 HSI 里只对 $H, S$ 算距离、放行整个 $I$ 范围，就鲁棒得多。这也是为什么分割任务几乎都先把图像转到知觉友好的颜色空间。</span>

## 5 颜色处理工程选型

颜色空间的选择是彩色处理的「第一决策」。用对照表固定下来：

| 任务 | 首选颜色空间 | 为什么 |
| --- | --- | --- |
| 灰度转换 | 亮度 $I$ 或 YUV 的 Y | 一个通道即完成，信息损失最小 |
| 色彩调整 | HSI/HSV | 色调、饱和度、明度独立控制 |
| 肤色检测 | HSI（对 $H,S$ 度量） | 对亮度鲁棒 |
| 压缩/传输 | YUV/YCbCr | 亮度与色度分离，可对色度降采样 |
| 打印 | CMY/CMYK | 减色法的物理匹配 |
| 深度视觉 | 常转 Lab | 知觉均匀，距离度量更有意义 |

**一个经典工程细节：色度降采样**。人眼对亮度分辨力高、对色度分辨力低——JPEG 把图像转 YCbCr 后，对 Cb/Cr 做 2:1 或 4:1 的降采样，几乎不损失观感却省下一半数据。这是「心理视觉冗余」在彩色领域最成功的工程化。

**白平衡的直觉**：同一张白纸在日光下与白炽灯下，RGB 值完全不同（色温不同）。白平衡就是估计并消除光源颜色——经典做法是「灰度世界假设」（场景平均应接近灰）与「白色区域假设」（场景最亮处应是白）。理解白平衡，就理解了为什么「同一个物体在不同光照下颜色不同」是物理事实而非传感器缺陷。

**色彩管理的三个环节**：采集（相机色彩空间）、处理（中间空间）、显示（显示器空间）各有一个「颜色档案」，三者不一致就会偏色。色彩管理（ICC 配置文件）就是让颜色在三个环节间可复现——摄影师、设计师都在这条链上工作。

**HSI 与 Lab 的分工**：HSI 由 RGB 非线性变换而来、简单直观，适合算法里的快速操作；Lab 基于人眼知觉实验设计、颜色距离更接近「视觉距离」，适合需要精确色彩度量的场景（如图像检索的色差排序）。两者互补而非替代。

**一个易混点再辨析**：RGB 三个通道不是「独立的灰度图」——它们共享同一个物理场景，通道间高度相关。因此「逐通道独立增强」常常带来色偏，而「先转知觉空间再增强」才是彩色处理的正路。这个原则值得反复强调。

**一张图记住 RGB/CMY 互补**：红色与青色互补（R + C = 白），绿色与品红互补，蓝色与黄色互补。在 RGB 立方体里，互补色是「对角相对」的顶点——这个几何直觉能帮你秒推各种颜色运算结果。

**彩色直方图的检索价值**：把图像按 H 分量（或颜色量化后的桶）统计直方图，两张颜色分布接近的图直方图距离也小——「颜色直方图检索」是最朴素的以图搜图，对「找同类场景」特别有效，但分不清「颜色相似、内容不同」的图（如红苹果与红球）。

**色域与「所见非所得」**：显示器（sRGB）能显示的颜色只是人眼可辨颜色的一部分，打印机（CMYK）的色域更小。把一张广色域图直接输出到窄色域设备，会「溢出」——色彩管理里的「色域映射」就是处理这类溢出。图像处理里的很多「偏色」，其实是色域不匹配而非算法错误。

**HSL 与 HSV 的微小差别**：两者都有 H 与 S，但 L（亮度）与 V（明度）的定义不同——V 取三分量最大值，L 取最大值与最小值的平均。同一个颜色在两个空间里的数值不同，混用会得到错误结果。这也是「颜色空间参数不可跨空间套用」的又一实例。

**彩色分割的一个完整例子**：要分割画面里的「橙色交通锥」。先转 HSI，取 H 在 15°–45°（橙色的色相范围）、S 高于 0.4 的像素为候选，再对候选做形态学清理与区域过滤——整个过程的核心是「在色相维度上做阈值」，这正是阈值分割在彩色空间的自然延伸。

**抗光照的颜色特征**：同一物体表面在不同光照下 RGB 变化很大，但「色相 H」相对稳定——所以肤色、交通标志、路标识别都优先用 H 或「色度比」这类对光照鲁棒的度量。这是「颜色特征设计要抗光照」的总原则。

**打印偏色的根源**：显示器用加色 RGB，印刷用减色 CMYK，而 CMYK 无法覆盖全部 RGB 色域——屏幕上的「荧光橙」印出来往往发暗。设计师「所见非所得」的抱怨，一半来自色域差，一半来自没有做色彩管理。

**色相环的工程记忆**：红橙黄绿青蓝紫按 0° 到 300° 均布在色相环上，互补色相隔 180°。「调节色相」就是沿环旋转，「提高饱和度」就是远离圆心——HSI 空间的几何，本质是色相环的极坐标展开。

## 6 小结

- **颜色模型**是颜色的坐标系：RGB（加色，显示）、CMY（减色，印刷）、HSI（色调/饱和度/亮度，贴近知觉）。
- **RGB → HSI**：$I$ 是三通道均值，$S$ 度量「浓淡」，$H$ 用反余弦 + 象限分段给出色相角。
- **伪彩色**用查色表给灰度编码颜色（热力图）；**假彩色**是对多光谱数据的重着色。
- **全彩色处理**分逐通道独立与矢量处理两种路线；涉及通道间关系时必须用矢量路线。
- **彩色分割**在颜色空间做距离判决；HSI 下对 $H,S$
