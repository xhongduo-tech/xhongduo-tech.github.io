## 为什么从架构开始

物联网（Internet of Things，IoT）不是一项技术，而是**一个由感知、传输、计算与存储共同编织的系统**。<span class="marginnote">凯文 · 阿什顿 1999 年在宝洁公司的供应链演讲中首次使用 "Internet of Things" 一词；这个名称真正被广泛传播是在 2005 年 ITU《互联网报告》之后。</span>要理解任何系统，先要有一张「地图」——**架构（architecture）**是系统的骨架，**参考模型（reference model）**是架构的坐标系。前者回答「我们的系统由哪些部分构成」，后者回答「业界公认这些部分应该如何分层、每一层干什么」。本篇先立骨架，后续每一篇（感知、通信、协议、平台、安全）都是在某一层上展开的施工。

## 1 三层架构：最朴素的第一张地图

几乎所有物联网教材的第一张图都是**三层架构**：

**感知层（Perception Layer）**：传感器、RFID、摄像头、执行器——负责「感知世界」与「执行动作」。它是物与数字世界之间唯一的物理接口。<span class="marginnote">感知层有时也叫「设备层」。它回答的是「数据从哪里来」这一根本问题，详见本专题《传感器与感知层》。</span>
**网络层（Network Layer）**：Wi-Fi、ZigBee、LoRa、NB-IoT、5G 等——负责把感知层的数据安全、可靠地传向互联网，也把指令传回设备。
- **应用层（Application Layer）**：智能家居、智慧城市、工业监控等具体业务——负责把数据变成价值。

三层模型的价值在于**一句话就能讲清 IoT 的分工**；它的缺陷也同样明显：现实系统里「网络层」内部还有接入网、核心网的分层，「应用层」下面还隔着数据处理与服务平台。于是出现了更细的模型。

## 2 五层模型：把中间层显式命名

为了把「网络」与「应用」之间那段灰区（数据处理、服务编排、业务逻辑）讲清楚，业界普遍采用**五层模型**：

| 层 | 别名 | 职责 |
| --- | --- | --- |
| 感知层 | 设备层 | 采集、执行 |
| 接入层 | 传输层 | 边缘侧接入：ZigBee、BLE、LoRa、NB-IoT |
| 网络层 | 互联网层 | IP 路由、承载：4G/5G、光纤 |
| 中间件层 | 平台层 | 数据汇聚、存储、服务封装 |
| 应用层 | 业务层 | 面向用户的业务逻辑 |

中间加出的这一层（中间件 / 平台层）是整个 IoT 数据价值链的核心——设备喷涌而出的原始字节在这里被清洗、存储、建模，再以 API 的形式供给应用。<span class="marginnote">「把中间层显式命名」是计算机系统设计的经典手法：TCP/IP 的出现、数据库从应用中独立、消息队列的诞生，本质上都是「往中间加一层」。</span>

## 3 参考模型不等于架构

**架构（architecture）**描述「这一个系统长什么样」，**参考模型（reference model）**描述「这类系统应该怎么想」。参考模型的价值是标准化的：它让不同厂商的产品能对号入座、能互相对话。

最具代表性的参考模型有三个：

**IoT 世界论坛参考模型（IoT World Forum Reference Model，2014）**：七层——物理设备、连接、边缘计算、数据积累、数据抽象、应用、协作与处理。它第一次把「边缘计算」作为独立层写进参考模型，把「数据积累」与「数据抽象」分开，强调数据是自下而上逐层增值的。<span class="marginnote">七层模型的头两条原则：一是「设备 + 连接」是硬件底座，一切能力都必须建立在它们之上；二是「数据流单向自底向上，指令流双向流动」。</span>
- **oneM2M 参考架构**：全球物联网标准组织 oneM2M 定义了横跨垂直行业的统一平台架构（应用层 CSE、设备层 AE、基础设施 NSCL 等），是「平台标准化」路线的代表。
- **IoT-A（物联网架构项目，EU FP7）**：提出了包含身份、安全、管理等功能垂直贯穿的服务层架构，强调「安全与隐私是跨层的关注点」——这一思想我们会在《物联网安全与隐私》中反复使用。

**易错点｜辨析：** 很多人把「参考模型」与「协议栈」混为一谈。参考模型回答「系统分几层、每层干什么」（概念层面），协议栈回答「每一层具体用哪个协议实现」（实现层面）。IoT 世界论坛七层模型对应到的现实实现，往往是「LoRaWAN + MQTT + 时序数据库 + 云 API」这样一组具体协议——模型与实现之间是一对多、多对一的关系。

## 4 公式解析：网络层的理论天花板——香农公式

无论分几层，网络层都绕不开一个物理极限：**一条信道到底能传多快**。这是克劳德 · 香农 1948 年给出的答案：

$$
C = B \cdot \log_2 (1 + \text{SNR})
$$

拆成三步看：

- **第一步，看 $B$（带宽）**：信道允许通过的频率范围，单位 Hz。带宽是「路的宽度」——路越宽，单位时间能过的车越多。
- **第二步，看 SNR（信噪比）**：信号功率与噪声功率之比。它决定「一车能装多少货」——信噪比越高，调制阶数越高，每个符号能携带的比特越多。
- **第三步，合起来读**：香农公式给出的是**信道的容量上限 $C$（bit/s）**，任何纠错编码与调制都无法突破它。对数结构意味着：想要把容量翻倍，带宽要翻倍，但信噪比只要「平方」即可——所以扩频（LoRa 用的正是扩频换取灵敏度）本质上是在带宽与信噪比之间做交易。

香农公式把「速率」与「距离/功耗」联系起来：传输距离远、发射功率受限，SNR 就低，容量就小——这正是 LoRa、NB-IoT 这类低功耗广域网「速率低」的根本原因，而不是工程上的懒惰。我们将在《无线通信协议》与《应用层协议》两篇中反复看到这个交易。

## 5 参考模型如何指导实际选型

拿到一张参考模型，不是用来背的，而是用来回答三个工程问题的：

1. **每一层有哪些现成选项？** 感知层选传感器与 MCU，接入层选 ZigBee 或 LoRa，应用层选 MQTT 或 CoAP——后文各篇逐一展开。
2. **数据在哪一层「增值」？** 原始数据在接入层只是字节流，在中间件层变成结构化记录，在应用层变成业务决策。增值点决定了整个平台的架构重心。
3. **安全与隐私在哪几层部署？** 参考模型提示你：安全必须横向贯穿所有层，而不是最后在应用层「打补丁」。

## 6 小结

- **三层架构**（感知 / 网络 / 应用）是理解 IoT 的第一张地图；**五层模型**显式补出了「中间件层」，对应现实中的数据平台。
- **参考模型 vs 架构 vs 协议栈**：概念坐标系、具体骨架、实现协议，三者不可混用。
- **IoT 世界论坛七层模型**首次把边缘计算与数据积累设为独立层，是当下最主流的思考框架；oneM2M 与 IoT-A 分别代表平台化与横切安全的路线。
- **香农公式 $C = B\log_2(1+\text{SNR})$** 给出速率上限，是「带宽—信噪比—速率」三者交易的理论根据，也是理解低功耗广域网速率为何低的钥匙。
