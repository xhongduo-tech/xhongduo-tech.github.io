## 为什么从防火墙开始

前面讲完了「检测」——但防御的第一步永远是**隔离**。防火墙（firewall）站在内网与公网的边界，是所有流量必须经过的咽喉，它的问题只有两个：**放谁进来、放谁出去。** 防火墙的思想极其古老（护城河、城门、检查站），却是整个网络安全的物理起点。<span class="marginnote">防火墙的完整产品谱系（包过滤、状态检测、代理、下一代 NGFW、Web 应用防火墙 WAF）在密码学专题 firewall 一篇有展开；本处聚焦「它的判断依据是什么」——从五元组到应用层，从规则到状态。</span>理解防火墙，本质是理解「网络边界的信任模型」。

## 1 防火墙的演进：从包过滤到状态检测

**第一代：静态包过滤（packet filtering）**。只看单个包的**五元组**——源/目的 IP、源/目的端口、协议。规则如「放行 22 端口出、阻断 80 端口入」。缺点一目了然：它**无状态**——不记得「这个回包是不是我上次发出的请求的应答」。一个经典的坑：外网回包若源端口恰好是 80，无状态防火墙可能误放行。

**第二代：状态检测（stateful inspection）**。维护**连接状态表**，记录每条 TCP 连接「谁发起、到哪、目前在哪一阶段」。放行不再看单个包，而是看它是否属于一条**合法的已建立连接**。攻击者回包必须「对得上」状态表里的某条会话——这层记忆让防火墙从「看门人」升级为「会话追踪者」。<span class="marginnote">状态表是防火墙性能的关键：连接数上千万时，查表就是瓶颈。<strong>「连接数上限」与「每秒新建连接」是两个独立指标</strong>——SYN Flood 打的正是后者，所以状态防火墙天然要配 SYN Cookie 与连接限速。</span>

**第三代：应用层代理与 NGFW**。前面两代都只懂「端口号」——而 HTTP 是 80 端口上的什么内容？**应用代理**替内网用户转发请求，让外网只看到代理，应用层协议完全被代理理解。**下一代防火墙（NGFW）**把 IDS/IPS、应用识别、用户身份识别、URL 过滤整合进一台设备，能识别「这是不是微信」「这个下载是不是恶意文件」。

三代防火墙的「判断依据」不断上移：

| 代际 | 判断依据 | 典型设备 | 核心局限 |
| --- | --- | --- | --- |
| 包过滤 | 五元组（IP/端口/协议） | 早期路由器 ACL | 无状态，认不出回包 |
| 状态检测 | 连接状态表 | 主流企业防火墙 | 只懂「端口」，不懂应用 |
| NGFW / 代理 | 应用、身份、内容 | Palo Alto、代理网关 | 解密成本、性能开销 |

**辨析｜易错点：** 防火墙「放行 443」不等于「放行 HTTPS 内容安全」——NGFW 要在 443 上做 **SSL 解密（SSL inspection）** 才能看清应用内容；解密既慢又涉及隐私合规，很多组织「只解密 BYOD 流量，不解密高合规业务」。**每一代防火墙都在「看得更细」与「性能/隐私」之间做取舍。**

## 2 堡垒区 DMZ：把服务放在火线之外

一个组织必须对外提供 Web 服务，但绝不能把内部数据库、内部 OA 暴露给公网。防火墙体系用**DMZ（demilitarized zone，非军事区）**来安置「对外但要隔离」的服务：

```
                    +------------------------------+
   Internet ──────► │  外部防火墙（规则：只放行 80/443 到 Web） │
                    +------------------------------+
                                │
              +─────────────────┼─────────────────+
              ▼                                   ▼
        +----------+                         +------------------+
        │   DMZ    │   Web 服务器、邮件中继        │  内部网络          │
        │  (对外)  │  承受公网流量                │  (对内)           │
        +----------+                         +------------------+
              ▲                                   ▲
              └────────── 内部防火墙（更严：禁止 DMZ → 内网） ─────┘
```

- **DMZ 里的服务**（Web、SMTP 中继、VPN 网关）暴露给公网，是**默认会被打的地方**。
- **DMZ 与内网之间还有一道防火墙**，且规则更严：DMZ 的服务器被攻破后，内网仍是第二道防线——这叫**纵深防御（defense in depth）**。
- **默认拒绝（default-deny）**是防火墙的灵魂规则：没有显式放行，就一律拒绝。所有「写白名单」比「拉黑名单」安全得多。

**重点：** 防火墙的价值不在「规则有多密」，而在**边界假设是否清晰**。你假设「内网可信、外网不可信」——可一旦内部人员钓鱼、笔记本带病毒回公司，这个假设就塌了。**零信任（Zero Trust）**正是对「边界可信」的反动：不再相信「在内网所以安全」，改为对每个访问请求都做身份与设备验证。

## 3 公式解析：状态防火墙的连接判定

状态检测的放行逻辑可以写成一条简洁的判定式。设 $T$ 为状态表，$\text{req}(p)$ 表示包 $p$ 属于一次新建连接请求，$\text{resp}(p)$ 表示它属于某条已建连接的回包：

$$
\text{allow}(p) =
\begin{cases}
\text{true}, & \text{若 } \text{req}(p) \wedge \text{rule allows}(p) \\
\text{true}, & \text{若 } \text{resp}(p) \wedge (p \text{ 的元组与状态表中某条连接匹配}) \\
\text{false}, & \text{其他}
\end{cases}
$$

- **第一步，看第一行**：新建连接（SYN 包）必须同时命中**显式放行规则**（如「允许内网访问 443」）才放行——这是「默认拒绝 + 白名单」的体现。
- **第二步，看第二行**：回包不查静态规则，只查**状态表**——它必须精确匹配某条已建连接的「四元组镜像」。这解决了包过滤「无状态」的致命伤。
- **第三步，看第三行**：既不是合法新建、又对不上任何会话的包，直接丢弃——畸形包、来源不明的回包、扫描探测在这里被沉默地拦下。
- **第四步，看整体**：规则是「方向性」的，状态是「会话性」的。方向决定谁能发起，状态决定应答是否可信。两者合起来，就是「状态防火墙比包过滤聪明的地方」。

## 4 防火墙的局限：它挡不住的

防火墙不是万能门神，它有四类结构性盲区：

- **加密流量**：防火墙看到的是 TLS 密文，除非做 **TLS 解密（SSL inspection）**——而解密又带来隐私与合规问题。
- **应用内攻击**：防火墙放行了 443 端口的 HTTPS，却无法判断这流量里是不是一次 SQL 注入——那是 **WAF（Web 应用防火墙）**与 Web 安全（见《Web 安全》一篇）的战场。
- **内部威胁与出站攻击**：防火墙默认「内网可信」，但钓鱼、内鬼、已被控端点都在内网侧。出站（egress）过滤常被忽视——其实出站过滤能阻断恶意回连、C2 通道与数据外泄。
- **零日与协议混淆**：攻击者可以把恶意流量伪装成正常应用流量，NGFW 的应用识别再强也追不上混淆的迭代速度。

**辨析｜易错点：** 别把「有防火墙」当作「有安全」。防火墙是**流量入口的第一道闸**，不是安全体系的全部——它与 IDS/IPS、沙箱、EDR、零信任构成纵深，任何一层被绕开，都要靠下一层兜底。

一个具体的边界示例能说明「规则怎么写才算对」：某公司只开放 22（SSH）、80/443（Web）、25（邮件出）。正确的规则应当**入站默认拒绝、出站按需放行**：

```text
# 入站：只放行 Web 与邮件（其余一律拒绝）
allow in  tcp 0.0.0.0/0 -> 10.0.0.10:80,443
allow in  tcp 0.0.0.0/0 -> 10.0.0.11:25
deny  in  any

# 出站：放行 DNS/Web/邮件，其余告警
allow out udp 10.0.0.0/8 -> 8.8.8.8:53
allow out tcp 10.0.0.0/8 -> any:80,443,25
deny  out any
```

**重点：** 注意「deny out any」——**出站过滤拦住的不只是员工乱访问，更是恶意软件的回连与数据外泄**。被控主机要连 C2 服务器、要外传数据，都得走出口流量；出站白名单等于给「内鬼」和「僵尸」都上了第二道锁。

## 5 小结

- 防火墙回答「**放谁进出**」，判断依据从**五元组**（包过滤）演进到**会话状态**（状态检测）再到**应用与身份**（NGFW）。
- **DMZ + 双层防火墙 + 默认拒绝**构成经典的边界纵深；零信任则质疑「边界可信」本身。
- 状态防火墙的聪明来自**状态表**：回包必须匹配已建会话，静态规则只管「谁可以发起」。
- 防火墙挡不住**加密流量、应用内攻击、内部威胁、零日混淆**——它只是纵深的第一层。
- 出站过滤与入站过滤同等重要：防「回连」与防「入侵」是同一件事的两面。

术语速查：

| 术语 | 含义 |
| --- | --- |
| 五元组 | 源/目的 IP、源/目的端口、协议 |
| 状态检测 | 维护连接状态表的防火墙 |
| DMZ | 对外暴露但要隔离的服务区 |
| 默认拒绝 | 无显式放行即拒绝 |
| NGFW | 应用感知的下一代防火墙 |
| WAF | Web 应用防火墙 |
| 零信任 | 不信任边界，逐个验证请求 |
