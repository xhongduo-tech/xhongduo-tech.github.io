# 拒绝服务攻击 DoS 与防护

<div class="epigraph">

## 为什么从 DoS 开始

前面的攻击都要「进入系统内部」——恶意代码、漏洞利用，门槛高、目标小。而 **DoS（Denial of Service，拒绝服务）**是唯一一种**不需要攻破任何防线**的攻击：它只是让你**服务不可用**。2000 年 2 月，一位网名 Mafiaboy 的少年用 SYN Flood 让 Yahoo、Amazon、eBay、CNN 集体宕机——他需要的只是大量「半开连接」。今天，僵尸网络驱动的 DDoS 可以打爆任何云，单次攻击流量动辄数百 Gbps、甚至超过 1 Tbps。<span class="marginnote">DoS 与 DDoS 的区别：DoS 单机发起，DDoS（分布式）由成百上千万僵尸主机同时发起——分散来源使其难以封锁。2016 年 Mirai 僵尸网络用被感染的路由器、摄像头等物联网设备发动攻击，峰值超 1 Tbps，是 DDoS 规模化的标志性事件。</span>

## 1 攻击的兵器谱：从资源耗尽到协议漏洞

按「消耗什么」，DoS 攻击分几路：

**带宽耗尽**：把链路塞满。UDP 洪泛（大量 UDP 包）、ICMP 洪泛（ping 风暴）都属此类。防护靠流量清洗与黑洞路由。

**资源耗尽**：让服务器的 CPU、内存、连接表、文件描述符见底。最典型的是 **SYN Flood**：攻击者只发 TCP 握手的第一段（SYN），不完成握手，让服务器把「半开连接」塞满 SYN 队列——后续合法连接全部被挤掉。<span class="marginnote">SYN Flood 的经典解法是 <strong>SYN Cookie</strong>（丹尼尔 · 伯恩斯坦，1996）：服务器不真的分配连接表项，而是把连接状态编码进序列号（种子的哈希），收到合法 ACK 时才重建——无状态应答让攻击者的半开连接根本不占资源。</span>

**协议逻辑滥用**：用协议本身的正常机制放大攻击。**HTTP Flood** 用大量合法请求打爆应用层；**Slowloris** 只发半个 HTTP 请求头并保持连接，占满连接数，把服务器「温柔地」饿死。

**放大攻击（amplification）**：这是效率最高的武器——用小请求换来大响应。**DNS 放大**、**NTP 放大**、**SSH 反射**都利用 UDP 的「无源验证」特性：攻击者伪造源地址（反射），让无辜的公开服务器把大响应砸向受害者。下一节量化「放大倍数」。

四类攻击的「战场」各不相同，对照如下：

| 攻击类型 | 消耗的资源 | 需要的带宽 | 典型缓解 |
| --- | --- | --- | --- |
| UDP / ICMP 洪泛 | 链路带宽 | 高 | 流量清洗、黑洞路由 |
| SYN Flood | 连接表 / SYN 队列 | 低 | SYN Cookie、连接限速 |
| HTTP Flood | 应用线程 / 连接 | 中 | 限速、验证码、CDN |
| Slowloris | 并发连接槽 | 极低 | 请求超时、限单 IP 并发 |
| DNS/NTP 放大 | 反射服务器响应 | 低（借力） | 关闭开放递归、限制 monlist |

**辨析｜易错点：** 别把「攻击流量大」当作 DDoS 的全部——SYN Flood、Slowloris 的流量很小，却专打「软资源」（连接表、线程、队列）。**评估 DoS 威胁要看「它消耗什么」，而不是「它发多少流量」。**

## 2 公式解析：放大攻击的倍数账

放大攻击的杀伤力可以精确算出来。设攻击者发一个字节为 $b_{req}$ 的伪造请求给一台无辜反射服务器，该服务器向受害目标回送字节数为 $b_{resp}$ 的响应，则**放大倍数（amplification factor）**为：

$$
A = \frac{b_{resp}}{b_{req}}
$$

- **第一步，看懂 A 的含义**：攻击者花 1 份带宽，能借反射服务器砸出 A 份流量。$A > 1$ 才有意义，越大越赚。
- **第二步，代入典型值**：普通 DNS 查询响应约 40–60 字节；若用 DNSSEC 或大 TXT 记录，响应可达 2000–4000 字节，$A \approx 50$。攻击者 2 Gbps 的带宽即可发动约 100 Gbps 的洪流。
- **第三步，看为什么 UDP 可行**：TCP 的三次握手要求源地址可回包，伪造源地址会失效；UDP 无连接、无源验证，反射服务器照单全收——**无验证的协议是放大攻击的土壤**。
- **第四步，看 NTP 的极端案例**：NTP 的 `monlist` 命令可返回数百个最近客户地址，响应可达 3000–4000 字节，放大倍数曾高到 500 倍以上，一度是最凶猛的放大器。后续版本已默认禁用该命令。

## 3 防护的层次：从入口到出口

DDoS 防护不是单一产品，而是**分层纵深**：

**边界与云端清洗**：在 ISP 或云厂商把流量牵引到**清洗中心（scrubbing center）**，用容量和规则过滤掉攻击流量，再把干净流量回注。这是应对「带宽耗尽」的主力手段，本质是用「更大的容量」和「流量整形」把洪流吸走。

**本地过滤**：防火墙与 IDS/IPS 设规则拦截明显异常——源地址欺骗（验证反向路由）、畸形包、高频 SYN。注意防火墙防不了「打满链路」型攻击，因为流量根本到不了防火墙。

**协议与应用加固**：SYN Cookie 抗 SYN Flood；反向代理与 CDN 抗 HTTP Flood；**速率限制（rate limiting）**对单 IP 限频；**验证码/CAPTCHA** 挡脚本洪泛；慢速攻击用超时与请求计数识别。<span class="marginnote">防护的本质矛盾：<strong>「区分合法用户与攻击者」在 DDoS 下做不到完美</strong>——攻击流量长得和正常流量一模一样。所以 DDoS 防护的最高境界是「让攻击者花钱比你花钱快」：CDN 分散、Anycast 分流、按量计费的云抗 DDoS，把成本压力推给攻击者。</span>

**增强自身的鲁棒性**：无状态设计（像 SYN Cookie 那样不占资源）、连接表限长、熔断与降级、多活冗余。**系统被攻击后的「优雅降级」与「快速恢复」本身就是一种防御。**

各层防御按「部署位置」对照：

| 防护手段 | 部署位置 | 主要防什么 |
| --- | --- | --- |
| 云端清洗 / DDoS 高防 | ISP 或云厂商 | 带宽耗尽 |
| 黑洞路由 | 入口路由器 | 被打爆目标直接弃疗 |
| 防火墙 / IDS-IPS | 边界 | 畸形包、异常流量 |
| SYN Cookie / 连接限速 | 服务器本身 | SYN Flood、连接耗尽 |
| 反向代理 / CDN | 源站前端 | HTTP Flood、慢速攻击 |
| 多活冗余 / 自动扩容 | 架构层面 | 整体不可用 |

**辨析｜易错点：** 云端清洗有「识别延迟」——高防设备需要几十秒才能把流量从「回源」切到「清洗」，攻击在窗口期内仍可能打到源站。**真正有效的 DDoS 防护，是在攻击发生之前就把「清洗路径」配好并持续演练**，而不是事发后再临时接线路。

## 4 应用层的慢速攻击：Slowloris 的机理

带宽洪泛要海量带宽，而 **Slowloris** 用极低的资源就瘫痪一台 Web 服务器，值得单独拆解：

1. 攻击者建立大量 TCP 连接。
2. 每条连接只发送 HTTP 请求的起始行，然后**每隔几十秒再发一行**，让服务器以为「请求还在路上」，永远不超时。
3. 服务器为每个「未完成的请求」保持一个工作线程/连接槽。
4. 当所有连接槽被占满，正常用户的新请求排不上队——服务「被饿死」。

**重点：** Slowloris 不消耗带宽，只消耗**并发连接数**——它攻击的是服务器的「同时服务上限」而非「吞吐量」。对策：限制单 IP 并发连接数、设置请求头超时、使用可处理大量空闲连接的异步服务器（如 Nginx 的事件驱动模型天然更抗慢速攻击）。<span class="marginnote">Slowloris 与 Slow POST、Slow Read 同属「慢速攻击」家族，专打「连接上限」这类软资源。<strong>攻击不一定要「快」，慢到极致反而是另一种高效</strong>——防御方不能只看流量大小。</span>

一个具体的数量感：假设某 Web 服务器默认最多维护 1024 个并发连接，攻击者用 2000 台肉鸡各发 1 条 Slowloris 连接，就稳稳占满全部连接槽；若每条连接每隔 30 秒才发一行「继续喂」，服务器永远等不到超时——**攻击方只需要维持连接，不需要任何真实流量**。这解释了为什么 Slowloris 的作者能靠一台笔记本就拖垮当时的流行服务器。

### 抵御慢速攻击的配置清单

- **单 IP 并发连接数上限**：`limit_conn` 直接掐死单点占坑。
- **请求头 / 请求体超时**：`client_header_timeout` 让「永远不说完」的连接被清理。
- **异步事件驱动架构**：Nginx/Node 用事件循环而非「一线程一连接」，空闲连接几乎零成本。
- **反向代理前置**：让 Slowloris 打在代理上而不是源站，源站连接数不受威胁。

## 5 小结

术语速查：

| 术语 | 含义 |
| --- | --- |
| DoS / DDoS | 拒绝服务 / 分布式拒绝服务 |
| SYN Flood | 用半开连接塞满 SYN 队列 |
| SYN Cookie | 无状态抗 SYN Flood 的机制 |
| 放大攻击 | 小请求换来大响应（DNS/NTP） |
| Slowloris | 慢速发请求占满连接槽 |
| 流量清洗 | 把攻击流量牵引走再回注干净流量 |
| 黑洞路由 | 把受害目标流量丢弃在入口 |

- **DoS 的目标是让服务不可用**，不需要攻破任何防线；**DDoS** 用分布式僵尸网络放大规模。
- 攻击谱系分**带宽耗尽**（UDP/ICMP）、**资源耗尽**（SYN Flood）、**协议滥用**（HTTP Flood、Slowloris）、**放大反射**（DNS/NTP）。
- **放大倍数 $A = b_{resp}/b_{req}$** 决定了攻击者的杠杆，UDP 的源地址可伪造是放大攻击的土壤。
- 防护是分层纵深：**云端清洗 + 本地过滤 + 协议加固 + 自身鲁棒性**，用「更贵地挡」让攻击者「更贵地打」。
- 慢速攻击提醒我们：**软资源（连接数、线程、超时）与带宽同样是要害**。

在下一节，防御将进入「看见攻击」的环节：**入侵检测与防御（IDS/IPS）**如何用签名与行为基线，在恶意流量到达目标之前把它拦下。
