## 为什么从通用编程规范开始

前几章讲的是「设计」，这一章回到「**日常**」——每天写局部变量、循环、字符串拼接、数值计算时，那些最不起眼却最容易错的地方。Effective Java 第 9 章是「编程常识的成文版」：局部变量作用域要小、循环用 for-each、**别用浮点数算钱**、优先使用基本类型、别用字符串冒充类型、字符串拼接用 `StringBuilder`、命名要清晰。这些规则单个看都「不高级」，但它们决定了一段代码是「能跑」还是「能维护、算得准、不被坑」。

## 1 最小化局部变量的作用域

**局部变量的作用域应该最小化**——在使用它的地方才声明，声明时就要初始化。这是 Effective Java 第 57 条，也是最容易被忽视的「代码卫生」：

- **在首次使用处声明**，不要提前到方法开头堆一摞变量——每提前一步，读者就要多记一个「这变量是干嘛的」直到它被用到。
- **声明时初始化**：`int count;` 这种「先声明、后赋值」的悬空变量，让读者无法确定「此刻它是未初始化还是有意为之」。
- **循环变量作用域收进循环**：`for (int i = 0; ...)` 的 `i` 只在循环内可见——这正是 `for` 比 `while` 干净的地方；用 `while` 时循环变量会泄漏到循环外。
- **优先用 `for-each` 而不是下标循环**（第 58 条）：`for (Employee e : staff)` 没有下标、没有越界风险、没有「手写迭代器」的样板代码。<span class="marginnote">什么时候必须用下标循环？需要同时访问多个集合的对应位置、需要跳过或倒序遍历、需要修改元素——这些场景才退回到传统 `for`。For-each 是默认，下标是特例。</span>

**辨析｜易错点：「一次声明，多处复用」是坏味道。** 一个变量被复用来装两种含义不同的东西，第一次读代码的人没法判断它的真实意图——这是「变量作用域过大」的典型症状，拆成两个小作用域的变量即可。

## 2 数值的真相：浮点数的精度陷阱

**重点结论：不要用 `float`/`double` 表示金钱或其他需要精确十进制的地方。** 看这条经典代码：

```java
System.out.println(1.0 - 0.9);   // 输出 0.09999999999999998，而不是 0.1
```

为什么？`double` 是**二进制浮点数**，它能精确表示的只是「二进制小数」，而 `0.1` 在二进制里是无限循环小数——就像 `1/3` 在十进制里写不尽。于是 `1.0 - 0.9` 落进一个最接近的二进制近似，误差就冒出来了。

**公式解析：浮点数为何「算不精确」**：

$$

0.1_{(10)} = 0.000110011001100\ldots_{(2)} \quad \text{（二进制无限循环小数）}

$$
