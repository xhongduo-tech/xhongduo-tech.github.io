## 为什么可满足性是形式化方法的"万能后端"

第 1 篇结尾我们埋了一个伏笔：验证「蕴含式恒真」可以归约为「合取式不可满足」。这里把这条线彻底打通——**SAT（布尔可满足性，Boolean satisfiability）判定**是整个形式化方法最底层的自动推理引擎。验证芯片等价、生成测试用例、软件符号执行、甚至规划与调度，全都编码成 SAT/SMT 问题，交给求解器解决。<span class="marginnote">SAT 是第一个被证明 NP 完全的问题（库克-列文定理，1971），但这不妨碍现代求解器每秒处理百万变量级的实例——理论最坏情况与工程实际之间的巨大鸿沟，正是 CDCL 算法二十多年演进的成果。2002 年以来的 SAT 竞赛（SAT Competition）是工业求解器迭代的擂台。</span>

本篇对标 Kroening & Strichman《Decision Procedures》的 SAT/SMT 部分。核心线索是：**DPLL 解决「搜索」，CDCL 解决「从失败中学」，DPLL(T) 解决「布尔结构之外的数学」**——三层层层升级，构成今天的 SMT 求解器。

SAT 求解器是「工业规模」的活证据：一台现代求解器每秒能处理数百万变量的实例，而它的核心算法不过五十行。更惊人的是，**几乎所有「看起来不是布尔」的问题——验证、规划、符号执行——最终都被编码成布尔公式丢给 SAT/SMT**。本篇要讲的，就是这台「万能后端」的内部引擎。

## 1 命题公式的 CNF 化

SAT 的输入约定为**合取范式（CNF）**：一组合取的子句，每个子句是文字的析取。任何命题公式都可以等价地转换成 CNF，但要避免指数爆炸，工程上用**Tseitin 变换**：给每个子公式引入新布尔变量作「别名」，得到关于新变量集合的 CNF，与原公式**同可满足**。<span class="marginnote">Tseitin 变换的代价是增加变量，但换来线性规模——这背后是「等价」与「同可满足」的差别：翻译不必保留原公式的全部结构，只须保留「有没有解」。这个思想在第 4 篇符号模型检测里也反复出现：能压缩真相的表示，不必忠实呈现真相。</span>于是求解器面对的核心对象是：

$$
(x_1 \lor \neg x_2) \;\land\; (\neg x_1 \lor x_3 \lor x_4) \;\land\; (x_2 \lor \neg x_4) \;\land\; \cdots
$$

**重点：SAT 的所有应用都建立在一条归约上——「验证 $\Phi \models \phi$」等价于「判定 $\Phi \land \neg\phi$ 不可满足」。** 判不满足，蕴含就成立；找一个赋值让 $\Phi \land \neg\phi$ 为真，就找到一条反例。第 3 篇的模型检测、第 6 篇的霍尔逻辑验证，最终都落到这道 SAT 问题上。

顺带澄清一个常见误解：**并非所有布尔公式都难**。2-CNF（每子句两个文字）的 SAT 是多项式可解的，因为它可归约为图上的强连通分量问题；真正难的是 3-CNF 及以上的一般情形。这正是 Tseitin 变换的价值——它把任意公式转成 3-CNF 规模近似的问题，而求解器要对付的正是这种「一般难」的输入。

## 2 DPLL：带单元传播的深度优先搜索

**DPLL 算法**（Davis-Putnam-Logemann-Loveland，1960-1962）在朴素真值表穷举之上加了三个关键加速：

1. **单元传播（unit propagation）**：子句里只剩一个未定文字时，其余皆假，则该文字被迫取真——可连锁推出大量必然结论，是搜索期间最锋利的剪枝刀；
2. **纯文字（pure literal）**：某变量在公式里只以一种符号出现时，直接赋值为使这些子句满足的值，不会伤及任何子句；
3. **回溯（backtracking）**：某个分支矛盾时，撤销最近的决策，改走另一分支。

单元传播的规则是「子句 + 已定文字 → 新子句」的推理：

$$
\frac{( \ell \lor C ) \quad \neg \ell}{(C)}
$$

读法：若某子句含有文字 $\ell$，而 $\ell$ 已被赋值为假（即 $\neg \ell$ 为真），则该子句的满足只剩靠 $C$——于是 $C$ 被「推导」出来。传播循环就反复应用这条规则，直到没有新结论。<span class="marginnote">注意这条规则形如第 1 篇的分离规则（modus ponens）——SAT 的传播推理本质就是命题逻辑里的那几条推理规则，只是变成了机器上毫秒级的循环。SAT 求解器把「逻辑推理」打磨成了「数据结构」：启发式顺序、两条文字监视（two-watched-literal）让单元传播均摊到常数时间。</span>

把 DPLL 在一条小 CNF 上完整跑一遍：$\Phi = (x_1 \lor x_2) \land (\neg x_1 \lor x_3) \land (\neg x_2 \lor \neg x_3)$。先决策 $x_1 = \mathrm{T}$：第一、二子句已被满足，第三子句剩 $\neg x_2 \lor \neg x_3$；继续决策 $x_2 = \mathrm{T}$，第三子句被逼出 $\neg x_3$，于是 $x_3 = \mathrm{F}$——三个子句全部满足，找到可满足赋值 $(1,1,0)$。若第一步决策 $x_1 = \mathrm{F}$：第一子句剩 $x_2$，被单元传播逼为真；第二子句剩 $x_3$，被逼为真；第三子句 $\neg x_2 \lor \neg x_3$ 两文字皆假，矛盾——回溯换 $x_1 = \mathrm{T}$。**这个例子展示了单元传播如何把「选变量」变成「连锁推导」，也展示了回溯如何把「走错路」变成「换条路」。**

## 3 CDCL：从冲突中学习

DPLL 在纯公式上效率不错，但对工业公式仍会陷入大规模回溯。2001 年前后成形的**冲突驱动子句学习（Conflict-Driven Clause Learning, CDCL）**把「回溯」升级为「回溯 + 学习」：

1. **冲突（conflict）**：单元传播推出一对矛盾文字（$x$ 与 $\neg x$ 都为真），当前分支必然失败；
2. **冲突分析**：沿着蕴含图（implication graph）回溯，找出导致冲突的**一组最小假设**（通常取第一个唯一蕴含点，First UIP）；
3. **子句学习**：把这组假设的否定写成一条新子句，加入公式——**下次任何分支一旦满足这些假设，立即被这条子句拦下**，不必再重走失败路径；
4. **回跳（backjumping）**：不是回到上一层决策，而是直接跳回学习子句能「复活」的那一层，跳过成批无望的分支。

加上**VSIDS 分支启发式**（最近活跃的变量优先决策）与**周期性重启（restart）**（放弃当前搜索树、保留所学子句重来），CDCL 使求解器具备了「越失败越聪明」的进化能力。<span class="marginnote">「学习子句 + 回跳」可以类比人类解题：第一次走进死胡同后，你把「这条路走不通」沉淀成一条经验，下次遇到同样的岔路直接绕开。现代 SAT 求解器解出上百万变量实例，靠的正是这种「失败驱动的结构记忆」——这与大模型在训练语料里学到「推理模式」在精神上同源，只是一个是显式子句、一个是隐式权重。</span>

**辨析｜易错点：学习与完备性并不冲突。** 学习者加的是原公式的**逻辑推论**（任何满足原公式的赋值都满足新子句），所以解集不变，求解器仍是完备的——学得再多，也不会把「有解」变成「无解」。判断所学子句「是否逻辑推论」的标准，正是它是否由冲突蕴含图推导而来。

CDCL 的完备性值得单独强调：**学习再多子句，解集也不会变**——因为每条学到的子句都是原公式的逻辑推论。于是 CDCL 要么找到满足赋值，要么传播推出空子句、输出「不可满足」。这个「输出 unsat 附带证明」的特性，让 SAT 求解器不仅能回答问题，还能为答案背书——这正是第 1 篇「$\vdash$ 与 $\models$」在算法里的重逢。

## 4 SMT：SAT 的理论引擎

纯布尔 SAT 表达不了「$x + y < 5$」这样的算术约束。**SMT（Satisfiability Modulo Theories，理论可满足性）**把 SAT 扩展到带理论背景的问题：公式由布尔结构 + 一阶理论原子（线性算术、位向量、数组、字符串、未解释函数）组成。主流引擎是 **DPLL(T)**：<span class="marginnote">DPLL(T) 的「T」代表 theory。它的历史根源在 1990 年代后期（Nelson-Oppen 组合决策过程、Harrison 等的工作），2008 年后的 SMT-LIB 标准与 SMT-COMP 竞赛推动了 Z3、CVC5 等引擎的迅猛发展。今天几乎每个程序验证工具背后都站着一个 SMT 求解器。</span>

1. **布尔抽象**：把每个理论原子（如 $x + y < 5$）当作一个布尔变量，先用 CDCL 在布尔层面搜索；
2. **理论求解器（theory solver）**：CDCL 找到的布尔赋值若同时给出一组理论原子「真/假」，就交给理论求解器检查这些理论约束**是否可满足**（如线性算术求联立解）；
3. **冲突反馈**：若理论约束矛盾，理论求解器向 CDCL 返回一条**理论冲突子句**（如 $x > 0 \land x < 0$ 的否定），CDCL 把它当普通学习子句继续搜索。

**重点：DPLL(T) 是「布尔引擎与理论引擎的对话」**——CDCL 负责布尔组合的爆炸，理论求解器负责每种数学的爆炸，两边互相喂「学到的结论」，直到判定整个公式的可满足性。Z3（微软）、CVC5（斯坦福/爱荷华）是当前最流行的实现。

一个具体的 DPLL(T) 场景：公式 $x + y < 5 \land (x > 3 \lor y > 3)$。布尔层面把 $x + y < 5$、$x > 3$、$y > 3$ 当作三个布尔变量 $A, B, C$，CDCL 先找满足 $A \land (B \lor C)$ 的布尔赋值（如 $A=\mathrm{T}, B=\mathrm{T}$）；随后线性算术求解器检查 $x + y < 5 \land x > 3$ 是否可满足——取 $x = 4, y = 0$ 即可，整个公式可满足。若布尔赋值是 $A=\mathrm{T}, C=\mathrm{T}$，理论求解器检查 $x + y < 5 \land y > 3$——同样可满足。**关键在最后一轮：当理论求解器说「这组理论约束无解」时，它会吐出一条理论冲突子句，CDCL 把它当普通学习子句继续搜索。**

DPLL(T) 让 SMT 求解器成为程序验证的标配后端：符号执行的路径条件、霍尔逻辑蕴含的自动检查、协议参数的反例查找，全都编码成 SMT 公式交给它。现代 Z3 在解决线性算术、位向量、数组、未解释函数上已非常成熟，**「把验证问题编码成 SMT」是形式化方法最常用的工程动作之一**——本专题第 6、10 篇的验证，最终都会落到这个引擎上。

## 5 公式解析：CDCL 的冲突学习怎么写

把「从冲突中学到一条子句」写成公式，它长这样：

$$
\frac{x_1 = \mathrm{F}, \quad x_2 = \mathrm{F} \;\Rightarrow\; \text{冲突 } x_3 \text{ 与 } \neg x_3}{(\neg x_1 \lor \neg x_2)}
$$

- **第一步，读前提**：在蕴含图中，假设 $x_1 = \mathrm{F}$ 与 $x_2 = \mathrm{F}$（两次决策）经单元传播同时推出 $x_3$ 与 $\neg x_3$——矛盾。注意「冲突」不是凭空出现，而是这组**特定决策**造成的。
- **第二步，读结论**：学习子句 $(\neg x_1 \lor \neg x_2)$ 说「$x_1$ 和 $x_2$ 不能同为假」。为什么正确？若同为假，就重现刚才的矛盾路径——而那条路径已被证明不可满足，所以这条子句是原公式的**逻辑推论**，加入后解集不变。
- **第三步，看它怎么加速**：以后任何分支只要赋 $x_1 = \mathrm{F}$，单元传播立刻逼出 $x_2 = \mathrm{T}$（由子句 $\neg x_1 \lor \neg x_2$），把「上次走死的岔路」在进入之前就封死——**学习把失败的记忆沉淀进公式本身**。
- **第四步，连回完备性**：CDCL 要么找到满足赋值、要么因传播矛盾而停止，此时传播推导出的空子句就是「不可满足」的证明。所以求解器输出的「unsat」本身就附带一份可独立核验的**证明**——这正是第 1 篇「$\vdash$ 与 $\models$」在工业算法里的重逢。

## 6 术语速查：把求解器的词汇表记牢

| 术语 | 英文 | 一句话定义 | 关键性质 |
| --- | --- | --- | --- |
| CNF | conjunctive normal form | 子句的合取，SAT 的标准输入 | 一般情形 NP 难 |
| Tseitin 变换 | Tseitin encoding | 引入别名变量保持同可满足 | 线性规模 |
| 单元传播 | unit propagation | 单文字子句被连锁逼值 | 最锋利的剪枝刀 |
| 冲突 | conflict | 传播推出矛盾文字 | 触发学习与回跳 |
| 冲突分析 | conflict analysis | 沿蕴含图找最小假设（1UIP） | 决定所学子句质量 |
| 子句学习 | clause learning | 把冲突假设的否定加入公式 | 解集不变、搜索变快 |

读这张表时抓住一条线索：**从 DPLL 到 CDCL 到 DPLL(T)，是「搜索 → 从失败中学 → 学别的数学」的三级升级**——每一次升级都没有改变问题的可判定性，却改变了工业上能解多大实例。

## 7 小结

- **SAT** 判定 CNF 的可满足性；「$\Phi \models \phi$」归约为「$\Phi \land \neg\phi$ 不可满足」；Tseitin 变换保持同可满足地做 CNF 化。
- **DPLL** 用单元传播 + 纯文字 + 回溯加速搜索；单元传播就是命题逻辑推理规则的机器化。
- **CDCL** 从冲突中**学习子句**、按蕴含图**回跳**、配 VSIDS 与重启，实现「失败驱动」的进化式搜索。
- **DPLL(T)** 把布尔引擎与**理论求解器**（算术、数组、位向量等）对接，冲突以理论子句反馈，构成 SMT 求解器（Z3/CVC5）。
- 一条 3 变量的 CNF 手算展示了「**决策 + 单元传播连锁推导 + 回溯**」的最小闭环；学习子句不改变解集、输出 unsat 附带证明。
- SAT/SMT 是验证、符号执行、测试生成的共同后端，与第 1 篇的语义蕴含和第 3 篇的模型检测全程互锁。

在下一节，我们将从「验证既有程序」转向「从规格出发推出程序」：**精化演算（refinement calculus）**用「最弱前置条件 + 规格语句」把「写程序」变成「对规格做逐步精化的数学推导」，让程序从规格中长出来。
