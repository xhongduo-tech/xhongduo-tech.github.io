## 为什么从插入与删除开始

B+ 树不是静态的：每秒都有成千上万条记录插入、删除。树必须在不失控的前提下保持平衡与有序——这就是**分裂（split）**与**合并（merge）**机制。这一节把 B+ 树的插入、删除算法完整走一遍，用「节点满则分裂、节点过空则借位或合并」这两条铁律贯穿。理解插入删除，你才真正理解 B+ 树为什么能「永远平衡」——也才能看懂并发场景下 B+ 树维护的复杂性。

## 1 插入：定位、塞入、必要时分裂

插入键值 $K$ 的算法：

1. **定位叶子**：从根走到应包含 $K$ 的叶子。
2. **塞入叶子**：把 $K$ 按序插入叶子；若叶子未满，直接结束。
3. **叶子分裂**：若叶子已满（$n$ 个键），分裂成两个各约 $n/2$ 键的叶子，把中间键上提到父节点。
4. **级联上提**：父节点也可能满，递归分裂；若根分裂，树高 +1（新根）。

**核心要点：插入代价是 $O(\log n)$ 次 I/O，但大部分插入不触发分裂。** 只有节点满才分裂，而分裂沿路径最多发生一次（从叶子向根最多一次级联）。B+ 树的平均写代价远低于最坏情况。

**辨析｜易错点：** 分裂时**上提的键在父节点保留一份、叶子也保留一份**——B+ 树允许键重复存在于内部节点与叶子。这与 B 树不同（B 树的键唯一），也是 B+ 树「叶子全量数据 + 内部路由」设计的一部分。笔试常考「分裂后中间键去哪」——答案是**同时留在叶子并复制到父节点**。

## 2 一个插入分裂的完整例子

设叶子最大容量 4 个键，插入序列：5, 8, 12, 15, 3。

- 插入 5, 8, 12：叶子未满，直接插入，无需分裂。
- 插入 15：叶子满 4 键——已达最大容量，再插入将触发分裂。
- 插入 3：叶子满，分裂。中间键 8：左叶 [3, 5]，右叶 [8, 12, 15]，上提 8 到父节点。

```text
插入 3 使叶子 [5, 8, 12, 15] 溢出（满 4 键）：
    插入后  →  [3, 5, 8, 12, 15]（5 个键，超出容量）
    分裂后  →  左叶 [3, 5]        右叶 [8, 12, 15]
    中间键 8 上提到父节点，树保持平衡、高度不变
```

**核心要点：分裂后左右叶子都保持「至少半满」，树始终平衡。** 分裂把「满」转成「两个半满」，为后续插入留出空间——这是 B+ 树能维持高占用率又不断生长的关键。

## 3 删除：删除、借位、合并

删除键值 $K$：

1. **定位并删除**：找到含 $K$ 的叶子，删除键。
2. **若叶子过空（低于最小容量 $\lceil n/2 \rceil$）**：
   - **从兄弟借**：向相邻兄弟节点借一个键（经父节点转手），调整父节点键。
   - **兄弟也过空则合并**：把两个叶子与父节点相应键合并成一个叶子，父节点少一个键。
3. **级联合并**：父节点过空则递归合并；若根变空，树高 -1。

**辨析｜易错点：** **借位与合并的分界**是「兄弟是否有多余键」。兄弟有富余 → 借（树不变）；兄弟也刚够最小 → 合并（树变矮）。合并比借位代价高（要改父节点、可能级联），所以算法优先借。

**公式解析：B+ 树插入/删除的 I/O 代价**

设树高 $h$，插入/删除的 I/O 代价界：

$$
T_{\text{insert}}, T_{\text{delete}} = O(h) \;\text{次 I/O}
$$

- **第一步，定位**：沿根到叶 $h$ 次读。
- **第二步，修改**：插入/删除后，若分裂或合并，需要**重写**受影响的节点——写回也按层计，至多 $h$ 次写。
- **第三步，摊销**：分裂/合并不是每次都有（概率与节点占用率相关），平均代价低于最坏 $O(h)$。
- **第四步，工程意义**：$h \approx 4$ 时，一次插入约 4-8 次 I/O——这就是为什么「每行插入都要维护索引」让写变慢，也让「批量插入 + 事后建索引」成为大量导入的最佳实践。

## 4 批量插入与索引维护

**核心要点：B+ 树逐条插入的代价，让「批量加载」成为专门的算法。** 一次性导入 1 亿行时，逐条走插入算法（每次 $O(h)$ I/O + 频繁分裂）太慢。数据库用**批量建树（bulk loading）**：

1. 数据先按搜索码排序。
2. 自底向上逐层构建：底层叶子按序填满，逐层建父节点。
3. 一次顺序 I/O 完成，远快于逐条插入。

**辨析｜易错点：** 批量建树后，后续插入仍走普通插入路径——所以「先批量灌数据、再提供在线写入」是数据仓库导入的标准流程（与堆文件 + 事后建索引同理）。

## 5 插入删除的数值算例与术语速查

**把删除的借位与合并分别走一遍。** 设叶子最小容量 2 个键（$n=4$ 的 B+ 树，最小 $\lceil 4/2 \rceil = 2$），叶子 L1 有 [3, 5]，兄弟 L2 有 [8, 12, 15]。

- **删除 3**：L1 剩 [5]——低于最小容量 2，需补救。
- **借位分支**：L2 有 3 个键（富余）——从 L2 借最小键 8，经父节点转手：L1 变成 [5, 8]，L2 变成 [12, 15]，父节点键更新为 12。
- **合并分支**：若 L2 只有 [8, 12]（刚好最小 2，无富余）——无法借，把 L1 与 L2 合并成 [5, 8, 12]，父节点少一个键（可能级联）。
- **规律**：**借位保持树高不变，合并使树变矮**——算法优先借位，合并是最后手段。

**数值算例：插入与删除的触发频率** 设 B+ 树节点平均占用率 75%，插入 1000 个随机键。

- 分裂概率约「节点满」的频率：约每 $n$ 次插入一次分裂，且多发生在叶子层。
- 1000 次插入预计触发约 $1000/4 = 250$ 次叶子分裂（$n=4$ 时），但**级联到父层的分裂少得多**（父节点占用率也 75%，分裂概率递减）。
- 工程含义：$n$ 越大（每块键越多），分裂越少——**大块 + 高分枝因子不仅让树矮，还减少维护开销**。

**辨析｜易错点：** 删除时「借位」是经父节点转手的——不是兄弟直接把键塞给叶子，而是「兄弟最小键上提到父节点、父节点原键下放到叶子」。这个「换手」保持了整棵树的有序性，漏掉父节点键的调整是删除算法最常见的笔误。

<span class="marginnote">把 B+ 树的插入删除与第 9 章缓冲池联系起来：<strong>分裂/合并会改写多个节点</strong>，如果这些节点不在内存，就要读盘再写回——一次分裂约 2-3 次额外 I/O。因此「热点键的频繁插入」会让对应叶子反复分裂，形成写热点——这也是为什么顺序插入（尾部分裂）比随机插入更高效的原因。</span>

### 术语速查

| 术语 | 含义 |
| --- | --- |
| 分裂 | 满节点一分为二，键上提 |
| 合并 | 过空节点与兄弟并成一个 |
| 借位 | 兄弟富余时经父节点转手 |
| 最小容量 | 叶子至少 ⌈n/2⌉ 个键 |
| 级联 | 分裂/合并沿路径向上传播 |
| 批量建树 | 排序后自底向上构建 |

## 6 小结

- 插入：**定位 → 塞入 → 满则分裂 → 中间键上提 → 级联**；键可同时存在于内部节点与叶子。
- 删除：**定位 → 删除 → 过空则借位 → 借不到则合并 → 级联**；根空则树高 -1。
- 分裂/合并保持「叶子至少半满」与全树平衡，代价 $O(h)$ I/O。
- 逐条插入贵（$O(h)$ 每次），大批量导入用**自底向上的批量建树**。
- B+ 树的平衡由分裂与合并两种操作维持——它们是树的「呼吸」。
