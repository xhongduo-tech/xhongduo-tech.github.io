## 为什么从共识开始

主从复制的故障切换有一个悬而未决的问题：**多个从节点「都以为自己该当新主」怎么办？** 这需要一个机制让所有节点**对「谁是主」达成一致**——这就是**共识（consensus）**。这一节先立住共识问题的精确定义（一致性、合法性、终止性），再讲分布式系统理论的奠基性结果——**FLP 不可能性定理**：在异步系统里，即使只有一个进程可能崩溃，也不存在「总能达成共识」的确定性算法。这个「不可能」塑造了所有共识算法的设计空间（Paxos/Raft 都在「弱化条件」后才可能）。

## 1 共识问题的定义

**共识（consensus）**：$n$ 个进程，每个提出一个值，要求所有进程就**同一个值**达成一致。三个性质：

- **一致性（agreement）**：所有**非故障**进程最终决定**同一个值**。
- **合法性（validity）**：决定的值必须是**某个进程提出的值**。
- **终止性（termination）**：所有非故障进程**最终**做出决定。

**核心要点：共识的三个性质缺一不可。** 一致性管「不分裂」，合法性管「不乱来」，终止性管「不停摆」。选主（谁是 leader）、原子广播（日志序）、分布式锁（谁获锁）——都能归约为共识。

## 2 同步与异步模型

**同步模型（synchronous）**：消息延迟有**已知上界**，进程执行速度有界。在这个模型里，可以用超时可靠地检测故障——**共识可解**。

**异步模型（asynchronous）**：**没有延迟上界**——一条消息可能「永远在路上」。无法区分「进程挂了」与「消息慢了」——**故障检测不可靠**。

**核心要点：异步性让「区分故障与慢」变成不可能。** 这是 FLP 定理的根源：在异步系统里，你无法确定「一个进程是死了，还是只是很慢」——而共识需要这种区分。

## 3 FLP 不可能性定理

**FLP 定理（Fischer, Lynch, Paterson, 1985）**：在**异步**消息传递系统里，只要有一个进程可能崩溃，就不存在**确定性算法**能同时保证一致性、合法性、终止性。

**公式解析：FLP 的核心论证**

定理的证明用「从可达到不可达」的构造：

$$
\text{假设存在算法 } A \Rightarrow \text{构造一个可允许的执行} \Rightarrow \text{终止性被违反}
$$

- **第一步，假设有算法 $A$**：假设存在总能终止的共识算法。
- **第二步，延迟消息**：构造一个执行，其中**关键消息被无限延迟**（异步模型允许）。
- **第三步，进程无法区分**：进程无法知道「消息没到」是「延迟」还是「发送者崩溃」——它不敢做决定（怕决定后收到矛盾消息）。
- **第四步，矛盾**：没有进程能安全决定 → 终止性被违反 → 假设错误。

**辨析｜易错点：** FLP 说的是**异步 + 至少一个进程可能崩溃 + 确定性算法**——三者缺一，定理不一定成立。**随机化算法、部分同步模型、或「零故障」假设**都能绕过 FLP。Paxos/Raft 正是靠「部分同步」（大多数时候同步，偶尔异步）绕过 FLP 的。

## 4 绕过 FLP：部分同步模型

**部分同步模型（partial synchrony）**：系统**大部分时间**同步（延迟有界），**偶尔**进入异步（延迟无界）。共识算法在「同步期」推进，在「异步期」等待——**FLP 不适用**（模型不是纯异步）。

**共识算法的共同结构**：**多数派（quorum）**。任何两个多数派必然相交——这个「交集」保证：即使某些节点慢/挂，只要多数派活着，信息就能传递、共识能推进。

**公式解析：多数派的交集性质**

设 $n$ 个节点、多数派大小 $q > n/2$：

$$
\forall\, Q_1, Q_2: |Q_1|, |Q_2| \ge q \Rightarrow Q_1 \cap Q_2 \ne \emptyset
$$

- **第一步，多数派交集非空**：两个超过半数的集合必有交集——鸽巢原理。
- **第二步，意义**：一个阶段（如选主）在多数派达成，下一阶段（如确认）的多数派必含上一阶段的某个节点——**信息不被丢失**。
- **第三步，容错**：最多容忍 $\lfloor (n-1)/2 \rfloor$ 个节点故障（3 节点容 1、5 节点容 2）。
- **第四步，代价**：需要多数派响应才能推进——少数派慢会拖慢共识。

## 5 从不可能到工程

**核心要点：FLP 不是「共识不可能」，而是「共识不总能保证终止」。** 工程上接受「偶尔不确定」：Paxos/Raft 在正常同步期快速推进，网络分区时暂停——**用「可能暂停」换「绝不分裂」**。

| 模型 | 共识可解？ | 代表 |
| --- | --- | --- |
| 同步 + 无故障 | 是（平凡） | 教科书 |
| 同步 + 有故障 | 是 | 超时 + 重试 |
| **异步 + 有故障** | **FLP：不可能** | — |
| **部分同步** | **是（用多数派）** | **Paxos、Raft** |

**连接点：** 下一节的 Paxos 与 Raft 就是「部分同步模型 + 多数派」的具体算法——它们如何用两阶段（或日志复制）在「能推进时推进、不能时暂停」——这正是 FLP 定理给出的设计边界。

## 6 共识的数值算例与术语速查

**用一个「选主」场景把共识的困难走一遍。** 设三节点 A、B、C，全部存活但网络延迟不定（异步模型），A 提议自己当主。

- **A 发提案**：向 B、C 广播「我当主」。若 B 回复、C 延迟——A 收到 1 票，加自己 1 票 = 2 票，多数派达成，A 当选。
- **C 的延迟**：C 不知道 A 当选，若 C 也想当主并发提案——两个多数派 {A,B} 与 {B,C} 相交于 B——**B 成为「事实仲裁者」**：B 先回谁，谁赢。
- **若 B 崩溃**：A 只剩自己，C 只剩自己——没有节点能凑多数派——**共识无法推进**（FLP 的体现：无法区分「B 死了」与「B 很慢」）。
- **部分同步**：若系统「大多时候同步」，超时后 A 可认定 B 挂了，走「新共识轮」——**同步期推进、异步期等待**。

**数值算例：多数派的容错上限** 设 $n$ 节点，多数派 $q = \lfloor n/2 \rfloor + 1$。

- $n=3$：$q=2$，容 1 个故障。
- $n=5$：$q=3$，容 2 个故障。
- $n=2$：$q=2$，容 0 个故障——两个节点无法构成「可容忍单故障的共识」。
- **结论**：多数派共识的容错上限是 $\lfloor (n-1)/2 \rfloor$——这是「用冗余换容错」的精确刻度，也是第 19 章分布式系统选节点数的依据。

**辨析｜易错点：** FLP 的「不可能」常被误读成「分布式共识在工程上不可行」——**错**。FLP 说的是「纯异步 + 确定性算法 + 任意一个进程可能崩溃」下不保证终止；工程上的 Paxos/Raft 用「部分同步 + 多数派 + 超时」绕过它，**牺牲「总能终止」换取「绝不分裂」**——这是「不可能」的正确打开方式。

<span class="marginnote">FLP 定理与第 18 章 CAP 是分布式理论的两座「不可能」之碑：<strong>FLP 说不保证终止，CAP 说分区时 C/A 二选一</strong>。两者共享「异步 + 不可靠通信」的假设——理解它们，就理解了分布式系统「为什么难」的根源。</span>

### 术语速查

| 术语 | 含义 |
| --- | --- |
| 共识 | n 进程对同一个值达成一致 |
| 一致性/合法性/终止性 | 共识的三个性质 |
| 同步模型 | 延迟有上界 |
| 异步模型 | 无延迟上界，故障不可检测 |
| FLP 定理 | 异步+故障下确定性共识不可能 |
| 部分同步 | 大多数同步偶尔异步 |
| 多数派 | 超过一半的节点集合 |

## 7 小结

- **共识**：一致性 + 合法性 + 终止性；选主、原子广播、分布式锁都可归约。
- 同步模型可解共识；**异步模型无法可靠检测故障**。
- **FLP**：异步 + 一进程可崩溃 → 无确定性共识算法保证终止。
- 绕过 FLP：**部分同步模型 + 多数派（quorum）**——交集保证信息不丢。
- Paxos/Raft 在部分同步下用多数派推进——**可暂停但绝不分裂**。
