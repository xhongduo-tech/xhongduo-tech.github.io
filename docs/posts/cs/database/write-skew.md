## 为什么从写偏斜开始

快照隔离是主流，但它有一个著名的盲区：**写偏斜（write skew）**——两个事务**各自读到的快照都不冲突**，各自写的也不是同一行，但合在一起却**违反了一条跨行约束**。它不是脏读、不是丢失更新，快照隔离的冲突检测完全看不见它。这一节把写偏斜讲透：经典案例（值班表）、为什么冲突检测防不住、以及数据库如何补救（可串行化快照隔离 SSI）。写偏斜是「为什么快照隔离≠可串行化」的活证据，也是 PostgreSQL 可串行化实现（SSI）要解决的核心问题。

## 1 写偏斜的经典案例

**医生值班表约束**：每名医生至少留一人值班。两个医生：

```
初始：D1 值班=true，D2 值班=true，约束「至少一人在岗」
T1: 读 D1=true, D2=true → 我（D1）可以下班 → 写 D1=false
T2: 读 D1=true, D2=true → 我（D2）可以下班 → 写 D2=false
```

**结果**：两个事务各自读到的快照都「有另一人在岗」，各自写**不同行**（D1 与 D2）——**快照隔离的写冲突检测只看「是否写了同一行」，两行不同 → 不冲突 → 都提交**。最终 D1=false 且 D2=false——**约束被破坏**。

**核心要点：写偏斜是「跨行/跨表约束」在快照隔离下的失效。** 快照隔离防得住「同一行的并发写」（丢失更新），防不住「各自写不同行、却共同依赖一个共享前提」的场景。

## 2 为什么冲突检测防不住

**快照隔离的写冲突检测（first-committer-wins）**只检测**写-写同一数据项**的冲突。写偏斜的特点是：

- T1 与 T2 写的**不是同一数据项**——检测器看不见。
- 但两者都**基于同一个快照前提**（D1 在岗、D2 在岗）做决策——前提被并发推翻。

**辨析｜易错点：** 写偏斜**不是**脏读（读的都是已提交数据）、**不是**丢失更新（两行都写了、都没丢）、**不是**不可重复读（各事务快照一致）。它是快照隔离特有的异常——**「读到的前提」与「写入的结果」之间的因果链被并发打破**。

## 3 公式解析：写偏斜的形式化

快照隔离下，事务 $T_1$ 写 $x$、$T_2$ 写 $y$（$x \ne y$），各事务读到的快照**不包含对方的写**。若存在约束 $C(x, y)$ 要求 $x$ 与 $y$ 满足某关系，则：

$$
\underbrace{T_1 \text{ 读 } (x_0, y_0)}_{\text{前提}} \Rightarrow T_1 \text{ 写 } x_1, \qquad
\underbrace{T_2 \text{ 读 } (x_0, y_0)}_{\text{同一前提}} \Rightarrow T_2 \text{ 写 } y_1
$$

- **第一步，两个事务读同一快照**：都读到「初始值班状态」。
- **第二步，各自写不同行**：$x_1 \ne x_0$、$y_1 \ne y_0$，写集不相交。
- **第三步，冲突检测漏网**：写-写同一行检测 → 两事务写集不相交 → 不中止。
- **第四步，结果违反约束**：$C(x_1, y_1)$ 不成立（无人值班）——**并发串行化视图里不存在这个结果**。

## 4 写偏斜的类型

写偏斜不只发生在「更新同一张表的不同行」：

- **不同表的交叉约束**：T1 改订单表、T2 改库存表，但「库存 ≥ 订单量」的约束被破。
- **插入与约束**：T1 与 T2 各插一行，合起来违反唯一约束（若唯一性不在同列）。
- **不可串行化的其他形态**：只读事务看到「不一致组合」（如看到新的订单但旧的库存）。

**核心要点：写偏斜的本质是「约束跨越了单个数据项」。** 只要业务约束是**跨行/跨表**的，快照隔离就可能在并发下破坏它。这也是为什么「要强约束就得上可串行化」。

## 5 对策：可串行化快照隔离（SSI）

PostgreSQL 用 **SSI（Serializable Snapshot Isolation）** 补救：在快照隔离之上加**冲突检测**。

- 跟踪「读依赖」：记录事务读过的数据。
- 检测「读-写反依赖环」：若事务 A 读到 B 将写的数据的旧版本，且 B 读到 A 将写的数据的旧版本——**形成危险结构，中止其一**。

**公式解析：SSI 的检测条件**

SSI 中止事务当检测到「写偏斜环」：

$$
\exists\, T_1, T_2: \; T_1 \text{ 读了 } T_2 \text{ 将写的数据的旧版本} \;\land\; T_2 \text{ 读了 } T_1 \text{ 将写的数据的旧版本}
$$

- **第一步，读旧版本**：$T_1$ 的读集与 $T_2$ 的写集有交集（读到旧版）。
- **第二步，双向反依赖**：另一方向也存在——形成**环**。
- **第三步，环 = 潜在写偏斜**：中止环中一个事务，破坏串行化违反。
- **第四步，代价**：SSI 比纯快照隔离多读集跟踪与环检测——**用开销换回可串行化**。它让「可串行化」在高并发下也可用（PostgreSQL 的 SERIALIZABLE 默认 SSI）。

## 6 小结

- **写偏斜**：两个事务各写不同行，基于同一共享前提，合起来违反跨行约束。
- 快照隔离的**写冲突检测只看同一行**——防不住写偏斜。
- 写偏斜不是脏读/丢失更新/不可重复读，是 SI 特有异常。
- 本质：**约束跨多个数据项**，快照隔离的「逐项冲突检测」看不见。
- **SSI**（可串行化快照隔离）用「读-写反依赖环检测」补救——PostgreSQL 可串行化的实现。
