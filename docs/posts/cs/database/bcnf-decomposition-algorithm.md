## 为什么从 BCNF 分解算法开始

上一节说 BCNF 分解「保无损、可能丢依赖」。这一节把算法本身写出来——**BCNF 分解算法**是一个反复寻找「坏依赖」、按它拆表的递归过程。它结构简单（判违反 → 拆 → 递归），却是整个规范化理论里最常考、最需要动手练的算法。理解它的关键：每一步都拆在一个违反 BCNF 的依赖上，而**按依赖拆天然保证无损**。这一节用「为什么无损」贯穿算法全过程。

## 1 BCNF 分解算法

输入：模式 $R$ 与依赖集 $F$。输出：满足 BCNF 的无损分解。

```text
result := { R }
done := false
while not done do
    if result 中存在模式 R_i 不满足 BCNF（有依赖 α → β 且 α 非超码）
        result := (result − R_i) ∪ (R_i − β) ∪ (αβ)
    else
        done := true
return result
```

每一步拆完，两个子模式都更小，且都有原模式的属性做公共部分——**递归终止是必然的**（属性数单调递减）。

**核心要点：算法只在「依赖左侧非超码」处下手。** 每个违反 BCNF 的依赖 $\alpha \to \beta$ 都提示「$\beta$ 的信息不该和 $\alpha$ 之外的东西同表」——拆开让 $\alpha$ 在子模式里成为超码。

## 2 为什么按依赖拆是无损的

拆 $R_i$ 成 $R_{i1} = \alpha\beta$ 与 $R_{i2} = R_i - \beta$，公共属性恰为 $\alpha\beta \cap (R_i - \beta) = \alpha$。

**公式解析：无损性的证明**

$$
R_i = R_{i1} \cup R_{i2}, \quad R_{i1} \cap R_{i2} = \alpha
$$

- **第一步，公共属性是 $\alpha$**：$R_{i1} = \alpha\beta$，$R_{i2} = R_i - \beta$，两者的公共属性正是 $\alpha$（$\alpha$ 在 $R_{i1}$ 里、不在被减掉的 $\beta$ 里、故也在 $R_{i2}$ 里）。
- **第二步，$\alpha \to \beta$ 蕴含 $\alpha \to \alpha\beta$**：由增广律（$F$ 里有 $\alpha \to \beta$）。
- **第三步，$\alpha$ 决定 $R_{i1}$ 全属性**：$\alpha \to \alpha\beta = R_{i1}$，所以 $\alpha$ 是 $R_{i1}$ 的超码。
- **第四步，套二元无损判据**：公共属性 $\alpha$ 决定 $R_{i1}$，满足「公共属性是某侧超码」，分解无损。

**辨析｜易错点：** 拆完后，**子模式上的依赖要重新投影**——只保留左右属性都在该子模式内的依赖。投影后的依赖集可能让某个子模式又违反 BCNF，这正是 while 循环继续的原因。容易漏的是：**原 $F$ 里左侧跨子模式的依赖在投影后消失**，别用消失的依赖判断子模式。

## 3 一个完整例子

**例 1**：$R = (A, B, C, D)$，$F = \{ A \to B, \; BC \to D \}$。

- 候选码：$A^+ = \{A, B\}$（用 $A\to B$），再加 BC→D 需要 B、C……先找候选码。$A$ 不能决定 C、D；试 $AC$：$(AC)^+$ 用 $A\to B$ 得 B，用 $BC\to D$ 得 D → 全属性。候选码 $AC$。
- 检查 BCNF：$A \to B$，$A^+ = \{A,B\} \ne R$ → 违反，按它拆：$R_1 = AB$，$R_2 = ACD$。
- 检查 $R_2 = ACD$：依赖投影只剩（$BC \to D$ 里 B 不在 $R_2$，丢弃）……$R_2$ 上无违反 BCNF 的依赖？$R_2$ 候选码 $AC$，无其他非平凡依赖 → 满足。
- 结果：$R_1(AB), R_2(ACD)$，无损。

**例 2（经典必考）**：$R = (s\_id, i\_id, dept\_id)$，$F = \{ i\_id \to dept\_id, \; (s\_id, dept\_id) \to i\_id \}$。

- $i\_id \to dept\_id$ 左侧 $i\_id^+ = \{i\_id, dept\_id\} \ne R$ → 违反，拆成 $R_1(s\_id, i\_id)$、$R_2(i\_id, dept\_id)$。
- 两个子模式各自满足 BCNF → 终止。如上一节所见：**无损但 $(s\_id, dept\_id) \to i\_id$ 不保持**。

<span class="marginnote">例 2 是「3NF 非 BCNF」的教科书案例，也是「BCNF 丢依赖」的完美演示——务必亲手推一遍。</span>

## 4 算法性质与边界

**BCNF 分解算法性质：**

- **总是无损**（每步按依赖拆，上文已证）。
- **可能不保持依赖**（例 2 已见）。
- **结果不唯一**：违反 BCNF 的依赖可能有多个，选择不同的依赖拆，得到不同的分解。
- **可能拆出不必要的表**：有时原模式已满足 BCNF，算法直接返回原模式。

**辨析｜易错点：** 判断「$R_i$ 是否满足 BCNF」要在**投影后的依赖集**上做，不是原 $F$。因为 $F$ 里有些依赖在子模式上根本不存在，用它判断会误判。每一步重新投影、重新找违反依赖，是算法的正确节奏。

## 5 BCNF 分解的数值算例与术语速查

**把第三个例子完整拆一遍，检验算法的手感。** 设 $R = (A, B, C, D, E)$，$F = \{ A \to BC, \; CD \to E, \; B \to D, \; E \to A \}$（与 3NF 合成例同款）。

- **候选码**：$CD$（$CD \to E$、$E \to A$、$A \to BC$ → 全属性）。
- **找违反依赖**：$A \to BC$——$A^+ = \{A,B,C\}$，$A$ 非超码 → 违反。
- **按 A→BC 拆**：$R_1 = ABC$，$R_2 = ACDE$。公共属性 A，$A^+$ 覆盖 $R_1$ 全属性 → 无损。
- **检查 $R_2 = ACDE$**：依赖投影——$CD \to E$（都在）、$E \to A$（都在）、$A \to BC$ 丢（B、C 不在）。$CD$ 是 $R_2$ 候选码；$E \to A$：$E^+ = \{E,A\}$ 非超码 → 违反。
- **再按 E→A 拆**：$R_{21} = EA$，$R_{22} = CDE$。$R_{22}$ 上 $CD \to E$ 满足（CD 是超码）。
- **结果**：$R_1(ABC), R_2(EA), R_3(CDE)$——无损，但依赖保持需检查（$B \to D$ 丢了：B 在 $R_1$、D 在 $R_3$，两侧被拆散）。

**辨析｜易错点：** 这个例子的教训是「投影后重新判断」——第一次拆完的 $R_2$ 看似没问题，投影后 $E \to A$ 仍违反，必须继续拆。**「判断 BCNF 要用投影后的依赖」不是一句口号，而是算法正确运行的保证**。

<span class="marginnote">把 BCNF 分解与 3NF 合成对照：同一例子，BCNF 拆成三张表还丢了 $B \to D$；3NF 合成得到四张表且保依赖。这就是「<strong>BCNF 更严但可能丢依赖，3NF 更宽但保依赖</strong>」的实证——也解释了为什么工程默认 3NF。</span>

### 术语速查

| 术语 | 含义 |
| --- | --- |
| 违反依赖 | 左侧非超码的依赖 |
| 分解 | 按 α→β 拆成 αβ 与 R−β |
| 无损 | 公共属性是某侧超码 |
| 依赖投影 | 只保留两侧都在子模式内的依赖 |
| 依赖保持 | 子模式依赖并集能推出原依赖 |
| 分解不唯一 | 选择不同违反依赖得不同结果 |

## 6 小结

- BCNF 分解：**找违反依赖 → 按 α→β 拆成 αβ 与 R−β → 递归直到全满足**。
- 按依赖拆**天然无损**：公共属性 α 决定 αβ，满足二元无损判据。
- 子模式的依赖要**重新投影**；判断 BCNF 用投影后的依赖。
- BCNF 分解**无损但不保证依赖保持**；结果可能不唯一。
- 例：$R(s\_id, i\_id, dept\_id)$ 拆成 $R_1(s\_id, i\_id)$ 与 $R_2(i\_id, dept\_id)$，丢失 $(s\_id, dept\_id) \to i\_id$。
- 分解终止性：每步属性数单调递减，必然收敛。
- 判断 BCNF 前先找候选码（闭包），再检查每个非平凡依赖的左侧是否超码。
