## 为什么从参与约束开始

映射基数回答了「一个能连几个」，但还没回答「**必须**连几个」——一个学生可以没选任何课吗？一个系必须至少有一个教师吗？**参与约束（participation constraint）**刻画「必须性」，它直接映射到关系模型里的**非空外键**与外键级联删除策略。而**弱实体集（weak entity set）**是参与约束最极端的形态：有些实体**离开宿主实体根本无法存在**——没有父母的子女、没有课程的教学大纲——它们的身份本身由宿主界定。这两者是 ER 模型里「约束」的核心。

## 1 参与约束：总量参与与部分参与

**参与约束**描述实体集在联系中的**必须程度**：

- **总量参与（total participation）**：每个实体**必须**参与该联系。例如「每个教师必须属于一个系」——教师实体对「属于」联系是总量参与。
- **部分参与（partial participation）**：有些实体可以不参与。例如「不是每个教师都必须授课」——教师对「授课」联系是部分参与。

**核心要点：参与约束是业务规则的强制声明。** 「必须」被数据库强制执行，就是 **非空（NOT NULL）外键**；「可以不必」就是可空外键。<span class="marginnote">ER 图里总量参与用<strong>双线</strong>连接实体与联系表示。总量参与还影响删除语义：若教师对「属于」总量参与，删掉系之前必须先处理系下教师——对应外键的 RESTRICT（限制删除）策略。</span>

## 2 参与约束与映射基数的组合

映射基数管「数量」，参与约束管「必须性」，两者正交组合出四种语义：

| 组合 | 含义 | DDL 对应 |
| --- | --- | --- |
| 1:n + 多侧总量参与 | 每个教师必属一系，每系有多个教师 | 教师表外键 `dept_id` 非空（NOT NULL） |
| 1:n + 多侧部分参与 | 教师可暂不分配系 | 教师表外键 `dept_id` 可空（NULL） |
| m:n + 两侧总量参与 | 每个学生必选课、每门课必有人选 | 连接表引用，两侧无空 |
| m:n + 部分参与 | 可选可不选 | 连接表只有实际发生的记录 |

**辨析｜易错点：** 初学者常把「1:n」与「总量参与」混为一谈。它们维度不同：1:n 说「一个系对应多个教师」，总量参与说「每个教师都必须有系」。一个 1:n 联系，既可能多侧总量参与（强制分配系），也可能部分参与（允许未分配）。

## 3 弱实体集：依赖宿主的实体

**弱实体集（weak entity set）**：**没有足够属性构成主码**的实体集。它的存在依赖另一个实体集——**标识实体集（identifying entity set）**——并通过**部分码（partial key / discriminator）**结合宿主的主码才能唯一标识。

经典例子：**教学大纲（syllabus）离开课程无法独立存在**。大纲有 `section_number`（同一门课的第几节），但没有全局唯一标识——两门不同课程的第一节大纲完全同构。要唯一标识一份大纲，需要 `(course_id, section_number)` 的组合。<span class="marginnote">弱实体集在 ER 图里用<strong>双矩形</strong>表示，标识联系用<strong>双菱形</strong>，部分码用<strong>虚线（波浪线）下划线</strong>。直觉理解：弱实体是宿主的「附属品」，离开宿主这个身份就不成立。</span>

**辨析｜易错点：** 弱实体集与普通实体集的区别不是「存在依赖」（很多强实体也依赖其他表），而是**没有自己的主码**。电话号码若单独成表、用 `phone_number` 做主码，它就是强实体；若只能靠 `(person_id, phone_number)`（宿主主码）标识，它就是弱实体。**有没有「独立可用的主码」是分水岭**。

## 4 公式解析：弱实体的标识依赖

弱实体集 $W$ 由标识实体集 $E$ 通过标识联系标识。$W$ 的每个实体，其主码是：

$$
\text{PrimaryKey}(W) = \text{PrimaryKey}(E) \cup \text{PartialKey}(W)
$$

- **第一步，部分码不足够**：$\text{PartialKey}(W)$（如大纲的 `section_number`）在 $W$ 内部不唯一——两个不同课程的第一节大纲 section_number 相同。
- **第二步，并入宿主主码**：加上 $\text{PrimaryKey}(E)$（如 `course_id`），组合后全局唯一。
- **第三步，标识联系必须是「对 E 一对一」**：一份大纲只属于一门课——标识联系里，$W$ 对 $E$ 是 m:1，且 $W$ 侧**总量参与**（每个弱实体都必须有宿主）。
- **第四步，落到关系模式**：弱实体转表时，宿主主码作为**外码**并入，并与部分码一起构成**组合主码**：`syllabus(course_id, section_number, content)`，主码 `(course_id, section_number)`，外码 `course_id` 引用课程表。删除课程时，其大纲**级联删除**。

## 5 参与约束、弱实体与级联删除

**核心要点：弱实体集与标识实体集之间存在隐式的级联删除（cascade delete）。** 宿主消失，附属实体失去存在意义，必须一并删除。这解释了关系模型中三种常见外键策略：

- **CASCADE（级联）**：删宿主，连带删弱实体/附属记录。
- **SET NULL（置空）**：宿主被删，外码置空（对应部分参与）。
- **RESTRICT（限制）**：有附属记录时禁止删宿主（对应总量参与）。

**辨析｜易错点：** 选择策略要看业务。对弱实体（大纲）用 **CASCADE**；对「订单明细」这种强依赖也用 **CASCADE**；但对「教师-系」这种总量参与，通常用 **RESTRICT**——先处理系下教师再删系，而不是静默删除。**无脑级联是设计事故的温床**。

## 6 弱实体的关系模式与删除策略对照

把「强实体 / 弱实体 / 普通附属」三类放到关系模式里，差异一目了然：

| 场景 | 主码 | 外键 | 删除策略 |
| --- | --- | --- | --- |
| 强实体（学生） | 自有主码 `sid` | 无 | 独立 |
| 普通附属（订单明细） | 自有主码 `detail_id` | 外键引用订单 | 常级联（CASCADE） |
| 弱实体（教学大纲） | 组合主码 `(course_id, section_number)` | 宿主主码并入 + 引用课程 | 隐式级联（宿主消失则消亡） |

**辨析｜易错点：** 弱实体的删除策略**不是自由选择**——它是语义强制的。大纲离开课程没有独立身份，删课程却保留大纲，就会留下「无法解释的大纲」。这与「订单明细」不同：明细虽常级联，但若业务允许「订单已删、明细留档审计」，明细就可以用 SET NULL 或软删除——**弱实体没有这个自由度**。

<span class="marginnote">把弱实体写成 SQL：`syllabus(course_id INT, section_number INT, content TEXT, PRIMARY KEY(course_id, section_number), FOREIGN KEY(course_id) REFERENCES course(cid) ON DELETE CASCADE)`。级联删除写死在 DDL 里，语义上才配得上「离开宿主便不存在」。</span>

### 数值算例：三种删除策略的差异

设系 dept 下有多位教师，学生选了课，课程有教学大纲。三种删除请求：

- **删除系 dept_1**：教师对「属于」是总量参与，数据库先拒绝（RESTRICT），直到所有教师改属他系或一并处理——**保护性删除**。
- **删除课程 c_101**：大纲（弱实体）自动级联删除；选课记录若设为 `ON DELETE CASCADE` 也会被连带清掉，若业务要求保留成绩审计，应改为先处理再删或软删除——**语义决定策略**。
- **删除学生 s_7**：若无外键依赖，直接删；若「选课」连接表外键为 `RESTRICT`，则需先退选——**约束与业务规则绑定**。

**核心要点：删除策略不是「选一个顺眼的」，而是「先问业务：宿主消失后，附属应该怎么办」。** 这个「先问业务」的习惯，正是第 7 章需求分析、第 13 章事务语义在建模层的共同底色。

<span class="marginnote">把「删除策略」想成「生命周期管理」更通用：CASCADE 是「同生共死」，SET NULL 是「脱离归属」，RESTRICT 是「先处理再放手」。到分布式系统（第 17 章 Saga 补偿）里，这个概念升级为「补偿事务」——删除/回滚的终极形式。</span>

### 术语速查

| 术语 | 含义 | 记号 / DDL |
| --- | --- | --- |
| 参与约束 | 实体在联系中的必须程度 | 总量双线 / 非空外键 |
| 总量参与 | 每个实体必须参与联系 | NOT NULL 外键 |
| 部分参与 | 允许不参与 | 可空外键 |
| 弱实体集 | 无主码，靠宿主 + 部分码 | 双矩形 / 双菱形 |
| 部分码 | 弱实体内部不唯一的判别属性 | 波浪线（虚线）下划线 |
| 标识联系 | 弱实体与宿主之间的联系 | 双菱形 |

**辨析｜易错点：** 「总量参与」与「弱实体」是两回事——总量参与说的是「必须参与联系」（外键非空），弱实体说的是「没有自己的主码」（组合主码）。一个强实体可以总量参与（教师必属一系），一个弱实体也可以部分参与（少见但允许）。把「必须性」与「身份独立性」分开看，就不容易混。

**连接点：** 弱实体的「宿主 + 部分码」组合主码，正是第 2 章「组合主码」、第 8 章「多值依赖」里「从属标识」思想的同构版本；而删除策略的选择，又与第 13 章事务的级联与约束语义绑定。

## 7 小结

- **参与约束**分总量/部分两种，决定外键**是否非空**与删除策略。
- 参与约束与映射基数**正交**：数量关系与必须性是两个维度。
- **弱实体集**没有自己的主码，靠「宿主主码 + 部分码」组合标识，用双矩形/双菱形/波浪下划线表示。
- 弱实体与宿主之间隐式**级联删除**；删除策略（CASCADE / SET NULL / RESTRICT）须按业务选。
