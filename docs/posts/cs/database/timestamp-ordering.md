## 为什么从时间戳排序开始

锁协议用「等待」解决冲突，代价是死锁。**时间戳排序协议（timestamp-ordering protocol）**走另一条路：**给每个事务一个全局时间戳，冲突时不等待、直接拒绝**——用「谁老谁优先」的规则保证调度等价于时间戳序的串行执行。它无死锁、无锁等待，代价是**事务可能被不必要地拒绝重启**。这一节讲时间戳分配、读/写规则、Thomas 写规则与变体。它是锁协议之外「无锁并发控制」的经典代表。

## 1 时间戳分配

**时间戳（timestamp）**：为每个事务 $T_i$ 分配一个唯一的、递增的标识 $TS(T_i)$。

- 分配方式：系统时钟、计数器、或两者的结合。
- **时间戳序 = 串行执行的等价顺序**：协议保证调度等价于按时间戳排序的串行调度。

**核心要点：时间戳是事务的「出生序号」。** 时间戳小的（老）事务先执行，时间戳大的（新）事务后执行——协议用「拒绝晚到的冲突」强制这个顺序。

## 2 读写规则

对每个数据项 $Q$，系统维护两个时间戳：

- $W\text{-timestamp}(Q)$：最后写 $Q$ 的事务的时间戳。
- $R\text{-timestamp}(Q)$：最后读 $Q$ 的事务的时间戳。

**读规则（事务 $T$ 读 $Q$）**：

- 若 $TS(T) < W\text{-timestamp}(Q)$：$Q$ 已被**更新的**事务写过——读它会读到「未来」的值，违反时间戳序 → **拒绝 $T$，重启**。
- 否则：允许读，更新 $R\text{-timestamp}(Q)$。

**写规则（事务 $T$ 写 $Q$）**：

- 若 $TS(T) < R\text{-timestamp}(Q)$：已有**更新的**事务读过 $Q$——$T$ 的写会被「更年轻」的读看到，违反顺序 → **拒绝 $T$，重启**。
- 若 $TS(T) < W\text{-timestamp}(Q)$：已有更新的事务写过——**Thomas 写规则**（见下）。
- 否则：允许写，更新 $W\text{-timestamp}(Q)$。

**核心要点：时间戳排序「拒绝晚到」**——老事务不许读被新事务写过的数据、不许写被新事务读过的数据。被拒事务重启后获得新时间戳（变成最新），重新执行。

## 3 公式解析：时间戳协议的保证

时间戳协议保证**冲突可串行化**，且等价于按时间戳排序的串行调度：

$$
S \text{ 冲突等价于 } T_1, T_2, \dots, T_n \text{（按时间戳升序串行）}
$$

- **第一步，读-写规则**：任何冲突的读写对，先发生的事务时间戳必然更小（晚到的被拒）。
- **第二步，写-写规则**：Thomas 规则下，旧的写被忽略（不被执行）——效果等价于新事务后写。
- **第三步，无环保证**：冲突对都「按时间戳序」发生，优先级图按时间戳序无环。
- **第四步，代价**：**非冲突事务也可能被误拒**——如 $T$ 读 $Q$ 时恰好有个更新事务先写了 $Q$（即使两者无实际依赖）。重启浪费工作。

**辨析｜易错点：** 时间戳排序**不会死锁**（无等待），但会**误拒**——被拒事务重做。若拒绝频繁，系统可能「活锁」（不断重启）。这也是它不如 MVCC 流行的原因：MVCC 用「版本」让读不冲突，时间戳用「拒绝」让冲突显式化。

## 4 Thomas 写规则

**Thomas 写规则（Thomas write rule）**：若 $TS(T) < W\text{-timestamp}(Q)$（有更新的写），**忽略 $T$ 的写**而不拒绝 $T$。

- 理由：$Q$ 最终值由最新写决定；$T$ 的旧写本来就会被覆盖——**跳过它不影响最终结果**。
- 效果：减少不必要的事务重启。

**但代价**：Thomas 规则**破坏了冲突可串行化**的严格定义（写-写冲突的处理不等价于串行）——它保证的是**视图等价**的串行化（比冲突串行化更宽）。**这是教科书里少见的「放宽冲突可串行化却仍正确」的例子**——因为跳过旧写不改变最终可见值。

## 5 时间戳协议与 MVCC/锁的对比

| 维度 | 锁（2PL） | 时间戳排序 | MVCC 快照 |
| --- | --- | --- | --- |
| 冲突处理 | 等待 | **拒绝重启** | 版本隔离 |
| 死锁 | 有 | 无 | 无 |
| 误拒 | 无 | 有 | 极少 |
| 读阻塞 | 有 | 无 | 无 |
| 写阻塞 | 有 | 无 | 无 |
| 实现 | 简单 | 简单 | 复杂 |
| 主流性 | 传统 | 教学/研究 | **现代主流** |

**核心要点：时间戳排序是「拒绝式」并发控制的思想源头。** 它无锁无死锁，但误拒代价高。**MVCC 用「版本」吸收了时间戳的思想（时间戳决定可见性）却避免了误拒**——所以现代数据库用 MVCC 而非纯时间戳。

## 6 小结

- 时间戳排序：给事务分配**全局时间戳**，冲突时**拒绝晚到的**、重启之。
- 读写规则：老事务读新写 / 写新读的数据 → 拒绝；否则允许并更新时间戳。
- 保证冲突可串行化，等价于时间戳序的串行调度；**无死锁**。
- **Thomas 写规则**忽略旧写，减少重启，保证视图等价串行化。
- 时间戳是「拒绝式」思想的代表；MVCC 吸收其时间戳思想却避免误拒。
