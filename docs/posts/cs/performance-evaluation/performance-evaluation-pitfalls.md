# 常见性能评估误区与陷阱

<div class="epigraph">
<p>性能评估中的每一个数字都来自一次测量，而每一次测量都可能是一个错误。</p>
<footer>—— 拉杰 · 贾因（Raj Jain），《The Art of Computer Systems Performance Analysis》第 3 章</footer>
</div>

## 为什么从误区开始

十篇学下来，工具都齐了：指标、测量、特征化、基准、实验设计、统计、模拟、排队论、MVA、容量规划。但**工具越多，误用的空间越大**。Jain 在教材第 3 章专门开列「常见错误清单」，因为他见过太多精心设计的实验被几个低级错误毁掉——而这些错误几乎不依赖专业知识，纯靠纪律就能避免。<span class="marginnote">把误区放在本专题最后讲，是刻意的：前十一篇提供的全部判断力，在这里化作「识破错误」的能力。<strong>会做实验只是合格，会看出别人实验的漏洞才是内行</strong>。</span>

这一篇把最常见的误区分成三类：数值陷阱、实验陷阱、认知陷阱，并给出每一类的对策。

## 1 没有明确目标的评估

最根本的误区是**先测量、后问为什么**。没有目标就没有正确答案：同一台机器，回答「够不够 5000 用户」与「能否撑住双十一峰值」需要完全不同的测量方案。没有目标的评估，产出的是「一堆数字」而非「一个结论」。<span class="marginnote">第 2 篇讲过测量目标四分类：比较、理解、调优、预测。<strong>先写下一句话目标</strong>：这句话决定测什么指标、用什么负载、做多少次实验、怎么分析——整条链都挂在这句话上。</span>

**对策**：动工前写清目标与交付物，例如「对比 A/B 两个版本在 1000 并发下的 p99 延迟，误差不超过 5%，置信度 95%」。目标里带数字，实验才有检验标准。

## 2 数值陷阱：平均值骗局

数值层面的误区最多，也最隐蔽：

**只报均值**：延迟长尾时均值被极端值拉高，p50 与 p99 分歧巨大。第 1 篇与第 6 篇反复强调：**报告均值必须配分位数与置信区间**。<span class="marginnote">「平均响应时间 200ms」这句报告，可能掩盖了 99% 的请求 50ms、1% 的请求 15s——把「大多数的好」包装成「全部的好」。</span>

**用错平均值算法**：用算术均值平均速率、用几何均值平均时间，结论系统性偏移。第 3 篇的三分法：时间取算术、比率取几何、速率取调和。

**忽略波动与置信区间**：两个系统均值差 3%，但噪声波动 ±5%——这个差异纯属运气。没有置信区间的比较，不能叫比较。

**只看相对值**：「新系统快 30%」——相对谁的 30%？基线配置、负载、环境是否一致？相对值脱离绝对值与上下文，就是数字游戏。

**辨析｜易错点：** 用「去掉异常值」来让数据变好看，是最恶劣的数值陷阱。性能数据里的异常值往往是真实缺陷（GC 停顿、磁盘抖动）——**删掉异常值，等于删掉问题本身**。正确的做法是保留并解释它们。

## 3 实验设计陷阱

实验环节的误区源于对「干净实验」的忽视：

**不消除干扰**：测 A 时后台在跑任务、测 B 时没有——差异来自环境而非系统。第 2 篇的规范：固定 CPU 频率、隔离环境、消除后台任务。

**不预热**：第一次运行带着冷缓存、JIT 未编译，测出的「冷启动」不是稳态性能。预热到稳定再计时。

**实验次数不足**：跑 3 次取平均，置信区间宽到没意义。第 6 篇样本量公式 $n \geq (ts/e)^2$ 给出理性预算。

**忽略实验顺序**：每次都先 A 后 B，系统温度、缓存状态系统性偏向后者——随机化实验顺序（第 5 篇）把干扰变成可平均的噪声。

**一次只变一个变量**：既浪费实验次数，又永远发现不了因子交互。2^k 因子设计（第 5 篇）一步到位。

## 4 认知陷阱与「应试教育」

最高级的误区藏在思维模式里：

**相关性当因果**：观察到「缓存越大延迟越低」，就断言扩容缓存能继续降低延迟——也许延迟瓶颈根本在磁盘。**相关性只是线索，实验才是证据**。

**过度拟合已知负载**：针对某条 trace 调优，系统在 trace 上飞快、在真实负载上打回原形——这是第 4 篇 Goodhart 定律的日常版。

**忽略成本**：只比性能不比成本，「快 5% 贵三倍」的方案可能毫无意义。TPC 的性价比指标（第 4 篇）提醒我们：**性能决策是资源决策，成本必须进场**。

**过早优化与过度相信数字**：一边是「不测就优化」的拍脑袋，一边是「测了就信」的迷信——两者都是对测量与实验的误用。<span class="marginnote">「从极限到大模型」的整条技术路线都建立在「测量驱动」之上：大模型的训练与推理优化，本质上是在海量的 profiling 与对比实验中迭代出来的。</span>

## 5 改写一份「坏报告」

把上面的误区集中演示一遍。假设收到这样一份报告：

「新缓存方案比旧方案快 30%，平均响应时间从 150ms 降到 105ms，强烈建议上线。」

这份报告至少踩了五个坑：没写负载、没写样本量、没写置信区间、没写环境、没写 p99。逐条追问：

**负载是什么？** 若只用了「平均请求」，长尾下的结论不成立——必须补 p50/p99 与请求大小分布。
**跑了多少次？** 单次测量只是随机样本，必须给均值与置信区间；没写样本量 = 没做过统计。
**环境一致吗？** 是否预热、是否固定 CPU 频率、是否隔离干扰？没写 = 无法复现 = 不可信。
- **p99 呢？** 均值降 30%，p99 可能反而恶化——缓存抖动往往拖慢最坏情况。

改写的正确姿势是把它变成：「在 2000 并发、真实 trace 回放、预热后各跑 30 次，新方案 p50 降低 28%（95% 置信区间 24%–32%）、p99 降低 12%，环境为 X 机型、Y 配置。」——每句话都能被复核，结论才配进决策会。<span class="marginnote">好报告与坏报告的差别不在字数，而在<strong>可复核性</strong>：负载、次数、环境、分位数、置信区间，五项齐全才是一份有立场的报告。</span>

## 6 核心对比表：误区与对策

本文为纯概念主题，用核心对比表替代公式解析：

| 误区 | 错误做法 | 正确做法 |
| --- | --- | --- |
| 无目标测量 | 先跑数据再想用途 | 动工前写下带数字的目标 |
| 只报均值 | 平均 200ms 就交差 | 配 p50/p99 与置信区间 |
| 均值算法用错 | 平均速率用算术均值 | 时间取算术、比率取几何、速率取调和 |
| 忽略噪声 | 差 3% 就说 A 快 | 先验证置信区间不重叠 |
| 删异常值 | 去掉慢样本再平均 | 保留并解释异常，那是缺陷线索 |
| 不预热 | 冷启动当稳态 | 预热到稳定再计时 |
| 样本不足 | 跑 3 次拍脑袋 | 用 $n \geq (ts/e)^2$ 定预算 |
| 忽略实验顺序 | 每次都先 A 后 B | 随机化顺序，干扰变可平均噪声 |
| 一次只变一个 | 逐个调参各跑一遍 | 2^k 因子设计一步到位 |
| 相关性当因果 | 观察「缓存大延迟低」就扩容 | 用受控实验验证因果 |
| 过度拟合负载 | 针对一条 trace 调优 | 用多组负载交叉验证 |
| 忽略成本 | 只比性能不比价格 | 引入性价比指标，成本进场 |
| 过早优化 | 不测就优化 | 先测量定位，再动手 |
| 迷信数字 | 测了就信 | 配置信区间，追问可复核性 |
| 不写报告 | 测完记在脑子里 | 立即沉淀可复核的书面结论 |

**辨析｜易错点：** 这张表不是「检查清单」，而是「思维习惯」：真正的内行不背口诀，而是每次看到数字都本能地追问「负载、次数、环境、分位数、置信区间」五件事。把这五问变成条件反射，比记住任何公式都值钱——前十一篇的全部技术，最终都要过这一关。

## 7 小结

- 误区分三类：**数值陷阱、实验陷阱、认知陷阱**，各自都有对应的纪律性对策。
- 最根本的误区是**没有目标的测量**——先写一句带数字的目标，整条链才有检验标准。
- 数值报告的铁律：**均值配分位数与置信区间**；删异常值等于删掉缺陷线索。
- 实验要**固定环境、预热、足量样本、随机化顺序**；一次只变一个变量既浪费又测不到交互。
- 认知层要提防**相关性当因果、过度拟合已知负载、忽略成本**三种高级陷阱。
- 好报告的判据是**可复核性**：负载、样本量、环境、分位数、置信区间五项齐全。
- 「不测就优化」与「测了就信」都是对测量的误用——测量驱动的前提是数字诚实。
- 十一个主题的工具在这里汇成同一条纪律：**测量驱动、数字诚实、结论可复现**。
- 「快 30%」这类相对值脱离基线配置与上下文就是数字游戏——相对值必须与绝对值、环境一起报。

回到第一篇的起点，本专题的全部纪律可以收成一句话：性能评估不是「跑几个数字」，而是「让数字说话，并让数字可信」。把这篇文章的误区清单当作每次实验前的自查表，你就能绕开绝大多数坑——这套纪律会一直陪伴你到第四级的《AI 基础设施》与《大模型部署》，那里的大规模训练与推理优化，正是本专题方法论的延续。
