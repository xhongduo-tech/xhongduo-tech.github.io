## 为什么从外部存储模型开始

前面所有算法都假设数据**全在内存**。当数据大到放不进内存（TB 级日志、数据库表），磁盘成为瓶颈——而磁盘访问的代价是内存访问的**十万倍量级**。**外部存储算法**在「数据在外存、内存是缓存」的模型下重新设计。<span class="marginnote">磁盘的物理现实：数据按<strong>块（block/page）</strong>读写，一次 I/O 读一整块（几 KB），而「寻道 + 旋转」的机械延迟约几毫秒——是内存（纳秒级）的百万倍。所以外部算法的目标不是「减少操作次数」，而是<strong>减少 I/O 次数</strong>——这是全新的复杂度衡量标准。</span>

这一课建立外部存储模型、定义 I/O 复杂度、以及「内存溢出」如何改变算法设计的直觉。

## 1 内存层次与外部模型

**存储层次**：寄存器 → 缓存 → 内存 → 磁盘（→ 磁带）。越往下越慢、越大、越便宜。

**外部存储模型（external memory model）**：两个层级——**主存（内存）**容量 $M$，**外存（磁盘）**容量无限。数据以**块**为单位移动，块大小 $B$。一次「读/写一块」计 1 次 **I/O**。内存最多容纳 $M/B$ 块。

**核心目标**：设计算法使 I/O 次数尽可能少——**I/O 复杂度**取代「普通时间复杂度」成为主要度量。<span class="marginnote">数量级直觉：内存 100ms 量级、磁盘 10ms 量级——一次磁盘 I/O 大约等于 10 万次内存访问。若算法把「每个元素」都当独立访问，$10^6$ 个元素就 100 万次 I/O ≈ 几小时；块式访问把 $10^6$ 元素装进 $10^4$ 个块（每块 100 元素），I/O 降到 $10^4$ 次 ≈ 秒级。<strong>「按块访问」是把算法从「不可行」拉回「可行」的唯一杠杆</strong>。</span>

**辨析｜易错点：** 不要以为「外部存储模型」只和数据库有关。现代 CPU 缓存、GPU 显存、云对象存储，处处是「两级存储 + 块传输」的结构。学会把问题翻译成「$M$ 多大、$B$ 多大、我要多少次 I/O」，这套思维可以复用到几乎所有存储体系上。

**为什么教材把它放在这里**：CLRS 把外部存储与 B 树放在树的章节里，正是为了强调「结构的选择由存储模型决定」——同一份数据，内存里用二叉搜索树，外存里要用 B 树，因为二者的「一次访问代价」差了一百万倍。学这一课的收获不是「会背外部模型定义」，而是「看懂存储模型如何重塑算法设计」。

**模型的简化与真实**：真实磁盘还有缓存、预读、SSD 等细节，但外部存储模型刻意只保留两个参数 $M, B$——它是最简可用模型。就像 RAM 模型假设「所有内存访问代价相同」一样，外部模型假设「所有块访问代价相同」；简化让理论分析成为可能，工程上再按实际硬件修正。理解「模型是为分析而简化的」，就能接受它的理想化。

## 2 内存 vs 外存的代价对比

| 指标 | 内存访问 | 磁盘 I/O |
| --- | --- | --- |
| 延迟 | ~100 ns | ~10 ms |
| 相对代价 | 1 | ~10⁵ |
| 访问单位 | 字节/字 | **块**（几 KB） |

**设计含义**：外部算法追求「**块局部性**」——让相关的数据落在同一个块、一次 I/O 处理整块。把「元素级」思维换成「块级」思维，是外部算法与普通算法的分水岭。<span class="marginnote">这个「块局部性」思想其实在普通算法里也有影子：快排的缓存友好、矩阵分块乘法（tiling）都是为了「一次取块、多次利用」。外部存储模型把这种「内隐的硬件直觉」变成「外显的分析框架」——它研究的正是「当块访问是瓶颈时，算法怎么设计」。</span>

**顺序与随机之差**：顺序读连续块几乎不花额外寻道时间，吞吐可达几百 MB/s；随机读一块（每次跳转）要「寻道 + 旋转」，每秒只能做几十到几百次。同样是 $10^9$ 次 I/O，顺序扫描几小时，随机跳转要几十天。外部算法设计的第一铁律因此是「把随机访问变成顺序访问」——这直接催生了 B 树「一个节点 = 一个块、一次读入」的结构。

## 3 公式解析：为什么「块式访问」是革命性的

设 $N$ 个元素、每块 $B$ 个元素。逐个访问 vs 块式访问的 I/O 次数：

$$I_{\text{逐个}} = \Theta(N), \qquad I_{\text{块式}} = \Theta\left(\frac{N}{B}\right)$$

- **第一步，逐个访问**：每个元素一次 I/O——$N$ 次。
- **第二步，块式访问**：一次 I/O 读 $B$ 个元素——$\lceil N/B \rceil$ 次。
- **第三步，对比**：$N/B$ 对 $N$——**差 $B$ 倍**（$B$ 通常数百到数千）。当 $N = 10^{12}$（TB 级）、$B = 10^3$，$N$ 次 I/O 要几年，$N/B$ 次只要几小时。

**要点**：**外部算法的目标是把 I/O 从「元素级」压到「块级」**——$N/B$ 是最理想的「扫一遍」代价。<span class="marginnote">「扫一遍」$O(N/B)$ 是外部算法的「线性时间」——它相当于内存算法里的 $O(N)$。任何「顺序扫描」的外部算法都以 $N/B$ 为基准；而「随机访问」是最贵的（每次跳转一个块）。所以外部算法偏爱「顺序化」——这也是外部归并排序与 B 树存在的根本原因。</span>

**辨析｜易错点：** I/O 复杂度与普通时间复杂度的换算不是「乘一个常数」——它们是**不同的量纲**。一个 $O(N)$ 时间但 $O(N)$ 次随机 I/O 的算法，可能比 $O(N\log N)$ 时间但 $O(N/B)$ 次顺序 I/O 的算法慢得多。**评估外部算法只看 I/O 次数**，CPU 时间在磁盘瓶颈下几乎免费。

**外部算法的下界直觉**：任何必须「看遍所有数据」的外部算法，至少 $\Omega(N/B)$ 次 I/O——每个数据至少要读进内存一次，而一次 I/O 最多带进 $B$ 个。这个下界告诉我们：外部归并排序的 $O\left(\frac{N}{B}\log_{M/B}\frac{N}{B}\right)$ 里，$N/B$ 那部分没法省，能优化的只有对数部分（靠提高归并路数）。「先知道下界，再知道自己离最优多远」是外部算法设计的第二原则。

**一个对比实验**：同一个排序任务，$N = 10^7$ 个整数（40 MB）——数据放内存，快排约 0.1 秒；数据在磁盘上却用「内存排序 + 随机读写」，会慢几个数量级；用外部归并排序（顺序 I/O）则稳定在秒级。「同样的逻辑，不同的存储位置，性能差几个数量级」——这就是外部算法存在的全部理由。

## 4 数值算例：TB 级数据扫一遍要多少 I/O

设 $N = 10^{12}$ 个 4 字节整数（共 4 TB），块大小 $B = 4096$ 字节 = 1024 个整数，内存 $M$ 可容约 $10^6$ 块。

- **逐个访问**：$10^{12}$ 次 I/O，每次约 10 ms，总耗时 $\approx 10^{12} \times 10^{-2}$ 秒 $\approx 317$ 年——不可行。
- **块式顺序扫描**：$N/B = 10^{12} / 1024 \approx 10^9$ 次 I/O；顺序读连续块时吞吐按 GB/s 计，总耗时约几小时——可行。
- **再放大块**：若用 $B' = 10^5$ 元素的大块，I/O 降到 $10^7$ 次，分钟级。

数字背后的规则：**每把「元素级访问」换成「块级访问」，就除以一个 $B$**；每把「随机访问」换成「顺序访问」，又省掉寻道延迟。两个杠杆叠加，就把「数学上可行但工程上不可行」变成现实可用。<span class="marginnote">算这个例子的意义不只是「记住几个数字」，而是建立「I/O 预算是关键约束」的直觉：外部算法设计的第一步永远是估算「理想情况下需要多少次 I/O」——如果理想值都不可接受，任何常数优化都白搭；如果理想值可行，再去设计「如何逼近理想」。这种「先算预算、再谈实现」的顺序，是外部算法区别于普通算法的工作方式。</span>

**内存 $M$ 的角色**：上面的预算假设我们只扫一遍。真实的外部算法还要考虑「内存装得下几个块」——$M/B$ 决定了「一次能同时打开几个输入流」。外部归并排序的归并路数、B 树节点能装多少子指针，都被 $M/B$ 卡着。$M$ 与 $B$ 一起，才构成外部模型的完整参数；只看 $B$ 不看 $M$，很多算法设计问题都答不对。

## 5 常见操作的 I/O 复杂度

| 操作 | 内存算法复杂度 | I/O 复杂度 |
| --- | --- | --- |
| 顺序扫描 N 元素 | $\Theta(N)$ | $\Theta(N/B)$ |
| 随机读 1 个元素 | $O(1)$ | $O(1)$（但每次跳块寻道昂贵） |
| 二叉搜索树查找 | $O(\log N)$ | $O(\log N)$ 次 I/O（每层一块） |
| B 树查找 | $O(\log N)$ | $O(\log_B N)$ 次 I/O |

**辨析｜易错点：** 表格最后两行的差异最值得记住——同样是 $O(\log N)$ 的查找，内存里是「时间」，外存里是「I/O 次数」；B 树用高扇出把 $\log_2 N$ 换成 $\log_B N$，$N = 10^{12}$ 时约 40 次对 4 次——这就是 B 树存在的全部理由。I/O 复杂度把「扇出」从实现细节提升为算法设计的第一公民。

**B 树的 I/O 算术**：设 $N = 10^9$、每块装 100 个关键字（$B \approx 100$）。二叉搜索树查找 $\log_2 10^9 \approx 30$ 次 I/O；B 树查找 $\log_{100} 10^9 \approx 4.5$ 次 I/O——差约 7 倍，且 $N$ 越大差距越大。若一次 I/O 10ms，30 次是 0.3 秒、4.5 次是 0.045 秒——这是用户能感知的区别，也是数据库宁可复杂也要 B 树的直接原因。

**一个直觉提醒**：普通算法书里的 $O(\log N)$ 查找、$O(N\log N)$ 排序，在外部模型下都要「翻译」成 I/O 次数再看。翻译的规则很简单：把「访问一个元素」换成「访问一块」，把「时间」换成「I/O」。掌握这条翻译规则，本专题前面所有算法都能在外部模型下重新评估——这就是「外部存储模型」作为独立一课的价值。

## 6 外部算法的设计原则

1. **顺序访问优先**：顺序读连续块比随机跳转快得多（磁盘连续读不用寻道）。
2. **大块批量**：尽量一次读一大块、处理完再写回，减少 I/O 次数。
3. **缓存重利用**：块读入内存后，让尽可能多的操作使用它。
4. **用数据结构换 I/O**：B 树用「高扇出」的树把树高压到「每层一次 I/O」以内。

这些原则的具体产物就是后面四课的主角：**外部归并排序**（顺序扫描 + 多路归并）与 **B 树**（高扇出树、磁盘友好）。<span class="marginnote">B 树「扇出大」的本质：每个节点装 $B$ 个关键字（一整块），树高 $O(\log_B N)$——从根到叶只要 $\log_B N$ 次 I/O。对比二叉搜索树（扇出 2，树高 $\log_2 N$）在外部模型下每层一次 I/O——$N = 10^{12}$ 时 $\log_2 N = 40$ 次 I/O 对 $\log_B N = 4$ 次——差 10 倍。<strong>扇出决定外部树的 I/O 深度</strong>。</span>

**写回同样按块算**：处理完一块、改动数据后再写回外存，同样要 1 次 I/O。所以很多外部算法把「读一块 → 处理 → 攒着 → 批量写回」打包成一个阶段，让「每块平均 1 次读 + 1 次写」。这是外部归并排序里「趟数」概念的雏形——一趟就是「整块读入、排序、整块写回」的一次往返，I/O 数 ≈ 块数 × 每块往返次数。

**外部归并排序的 I/O 轮廓**：先把外存数据分块读入内存，在内存里排成「归并段（run）」，再把归并段多路归并回外存——每一趟归并把段数除以归并路数 $M/B$。总 I/O 约 $O\left(\frac{N}{B}\log_{M/B}\frac{N}{B}\right)$。这里每个因子都有清晰的 I/O 含义：$N/B$ 是「扫一遍」，$\log_{M/B}(N/B)$ 是「归并趟数」。下一课会把这个式子一步步算出来。

**什么时候该用外部算法**：判断标准不是「数据有多大」，而是「内存装不装得下」——若 $N \times \text{elem\_size} \le M$，直接在内存排；刚超出时，可能「内存快排 + 一次归并」就够了；当 $N/B$ 大到需要多趟归并时，外部算法才是必需品。先做这个判断，避免「杀鸡用牛刀」——这也是工程与理论的分界：理论提供工具，工程决定何时使用。

## 7 小结

- **外部存储模型**：内存 $M$、外存无限、块大小 $B$；一次块读写 = 1 次 I/O。
- 磁盘 I/O 比内存慢约 $10^5$ 倍——**I/O 次数是外部算法的核心度量**。
- 逐个访问 $O(N)$ vs 块式访问 $O(N/B)$——块局部性是唯一杠杆。
- 数值上：4 TB 数据逐个访问要几百年，块式顺序扫描几小时。
- 设计原则：顺序优先、大块批量、缓存重用、高扇出结构。
- 内存容量 $M$ 与块大小 $B$ 共同决定可行性；$M/B$ 决定归并路数与节点扇出上限。
- B 树与外部归并排序是这两条原则的典范——后四课逐一展开。
- 使用时机：先估 I/O 预算，数据远超 $M$ 时才值得上外部结构。
