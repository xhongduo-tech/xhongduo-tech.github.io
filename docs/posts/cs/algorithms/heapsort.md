## 为什么从堆排序开始

有了二叉堆这把「数据结构的尺子」，排序就有了第三条路：归并排序 $O(n \log n)$ 但需要 $O(n)$ 额外空间；快速排序期望 $O(n \log n)$ 但最坏 $O(n^2)$；而**堆排序**原地完成、最坏 $O(n \log n)$——三个优势集于一身。<span class="marginnote">堆排序的价值不只是「又一种排序」：它展示了「数据结构驱动算法」的范式——先建一个支持取极值的结构，再反复取极值完成目标。优先队列的所有应用（调度、图算法）都是这个范式的变体。</span>

这一课有两大主题：**堆排序算法本身**（每次把堆顶搬到末尾），以及那个反直觉的复杂度结论——**BUILD-MAX-HEAP 只需 $O(n)$**，而不是直觉上的 $O(n \log n)$。

## 1 堆排序算法

堆排序分两阶段：

```text
HEAPSORT(A):
    BUILD-MAX-HEAP(A)                  // 阶段一：无序数组调整为最大堆
    for i = A.length downto 2:
        swap A[1] ↔ A[i]               // 堆顶（当前最大）落定到末尾
        A.heap-size = A.heap-size - 1  // 排除已落定的末尾元素
        MAX-HEAPIFY(A, 1)              // 把换上来的小元素下沉修复
```

**阶段一，建堆**：把无序数组调整成最大堆，让堆顶是全局最大元素。

**阶段二，反复提取**：把堆顶 $A[1]$（当前最大）与堆末尾 $A[i]$ 交换，此时最大值落定在最终位置；将堆的有效长度 $i$ 减一，把交换到堆顶的较小元素下沉修复——于是新堆顶又是剩余元素的最大值。重复直到堆只剩一个元素。<span class="marginnote">注意「排除末尾」的技巧：已落定的元素留在数组尾部，不参与后续堆操作。数组从 1 到 $i$ 是堆，从 $i+1$ 到 $n$ 是已排好的有序段——排序在同一个数组里完成，无需额外空间。</span>

每次提取需一次 MAX-HEAPIFY，$O(\log n)$；共 $n-1$ 次，故排序阶段 $O(n \log n)$。**堆排序的总时间由两阶段相加**：$O(n) + O(n \log n) = O(n \log n)$。

## 2 建堆：从下往上修复

最直观的建堆方式是自顶向下逐个插入——每个元素插入 $O(\log n)$，总 $O(n \log n)$。但 BUILD-MAX-HEAP 采用**从下往上**的策略：

```text
BUILD-MAX-HEAP(A):
    A.heap-size = A.length
    for i = ⌊A.length / 2⌋ downto 1:
        MAX-HEAPIFY(A, i)              // 从最后一个非叶节点向上修复
```

从 $\lfloor n/2 \rfloor$ 开始向前遍历——因为下标大于 $\lfloor n/2 \rfloor$ 的节点全是叶子，本身已满足堆序，无需处理。**叶子之上的节点逐一 MAX-HEAPIFY，让「子树的堆序」从下往上逐层建立**。

**辨析｜易错点：** 不能从上往下做（对根先 MAX-HEAPIFY 再对子树）——因为根修复时，其子树未必已满足堆序前提，MAX-HEAPIFY 的前提「孩子子树已经是堆」会被破坏。**只有从下往上的顺序才能保证每次调用 MAX-HEAPIFY 时前提成立**。这是「自底向上」最经典的教学案例。

## 3 公式解析：为什么建堆是 $O(n)$ 而非 $O(n \log n)$

直觉会说「$n$ 个节点每个花 $O(\log n)$，应该 $O(n \log n)$」。错在哪里？**不同节点的 MAX-HEAPIFY 代价不同**——越靠近根，路径越长；但越靠近根的节点越少。把工作量按「高度」分组：

- 高度为 $h$ 的节点至多有 $\lceil n/2^{h+1} \rceil$ 个；
- 高度 $h$ 的节点一次 MAX-HEAPIFY 至多 $O(h)$ 时间。

总代价

$$T(n) = \sum_{h=0}^{\lfloor \lg n \rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil O(h) = O\left(n \sum_{h=0}^{\infty} \frac{h}{2^h}\right)$$

而 $\sum_{h=0}^{\infty} \frac{h}{2^h} = 2$（几何级数求导技巧），于是

$$T(n) = O(n)$$

对这条式子做三步拆解：

- **第一步，算「高度 $h$ 的节点数」**：堆是近完全二叉树，最底层叶子占一半，上一层占四分之一，第 $h$ 层（从下往上数）占 $\approx n/2^{h+1}$。**越往上节点越少**。
- **第二步，配「单点代价」**：高度 $h$ 的节点下沉最多 $h$ 步，代价 $O(h)$。把「节点数 × 单点代价」配对，得 $\frac{n}{2^{h+1}} \cdot h$。
- **第三步，等比求和**：$\sum h/2^h = 2$ 是收敛的常数，不随 $n$ 增长——**大的工作量集中在底层那些「短路径」节点上，它们数量多但每步便宜**。<span class="marginnote">直觉校正：$n \log n$ 的错误估算假设「所有节点都花 $\log n$」。真相是绝大多数节点都很矮，真正花 $\log n$ 的只有根那一个。把账算到「按层分摊」，常数 $2$ 就出现了。</span>

**结论：BUILD-MAX-HEAP 是 $O(n)$。** 这是「看似 $n\log n$、实际 $n$」的教科书级案例。

## 4 堆排序的整体复杂度与性质

**最坏情况**：$O(n \log n)$——排序阶段每次提取都要走一遍路径。
**平均情况**：也是 $O(n \log n)$，常数比快排略大。
**原地**：只用了数组自身与常数辅助空间。
**不稳定**：堆排序**不是稳定排序**——交换堆顶与末尾会把相等元素的相对顺序打乱。<span class="marginnote">稳定性对「先按关键字 A 排，再按 B 排」的多关键字排序很重要（基数排序依赖稳定子排序，见第五篇）。堆排序的不稳定使它不适合直接作基数排序的子程序。</span>

**辨析｜易错点：** 堆排序与「选择排序」是近亲——都是「反复取极值」。区别在于堆用数据结构把「找最大」从 $O(n)$ 降到 $O(\log n)$，从而把选择排序的 $O(n^2)$ 改进到 $O(n \log n)$。**理解这层联系，比孤立记住堆排序的步骤更有价值。**

## 5 小结

- **堆排序** = 建堆（$O(n)$）+ 反复提取堆顶（$n$ 次 $\times O(\log n)$），总计 $O(n \log n)$。
- **BUILD-MAX-HEAP** 从 $\lfloor n/2 \rfloor$ 向前逐个 MAX-HEAPIFY，利用「叶子无需修复」的事实。
- 建堆 $O(n)$ 的证明靠**按高度分组**：高度 $h$ 的节点 $\approx n/2^{h+1}$ 个，单点 $O(h)$，总和 $\sum h/2^h = O(n)$。
- 堆排序**原地**、最坏 $O(n\log n)$，但**不稳定**。
- 堆排序与选择排序一脉相承，区别只在「取极值」被数据结构加速。

在下一课，我们把堆包装成真正的抽象——**优先队列**：支持 INSERT、EXTRACT-MAX、INCREASE-KEY 的数据结构，并延伸到 d 叉堆与最小堆。
