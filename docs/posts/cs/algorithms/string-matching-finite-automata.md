## 为什么从有限自动机开始

朴素算法的浪费是「失配后从头来」；**有限自动机（finite automaton）匹配**用一张**转移表**把「已匹配的前缀有多长」变成状态，每个字符只需 $O(1)$ 查表推进状态——匹配阶段**严格线性**。<span class="marginnote">有限自动机匹配是「把模式编译成自动机」的典范：预处理构造状态表（可能很贵），匹配阶段每个字符 $O(1)$。它的思想直接催生了 KMP（下一课）——KMP 只是用「前缀函数」把自动机的构造省下来。而自动机思路的推广（AC 自动机）支持多模式匹配。</span>

这一课定义状态与转移函数、给出构造方法，并分析「为什么匹配阶段是线性」。

## 1 状态 = 已匹配的最长前缀长度

**核心定义**：对模式 $P[1..m]$，状态 $q$（$0 \le q \le m$）表示「当前已匹配 $P$ 的前 $q$ 个字符」。状态 $m$ = 完全匹配。

**转移函数** $\delta(q, a)$ = 读到字符 $a$ 后，新的「最长可匹配前缀长度」。设 $P_q$ 是 $P[1..q]$（已匹配部分），$P_q + a$ 是「已匹配 + 新字符」构成的串，则 $\delta(q, a)$ 是 $P$ 的「最长前缀」且是 $P_q a$ 的「最长后缀」的长度：

$$\delta(q, a) = \max\{ k : P[1..k] \text{ 是 } P_q a \text{ 的后缀} \}$$

即「能继续接上的最长前缀长度」。<span class="marginnote">直觉：匹配到状态 $q$ 后读入 $a$，若 $a$ 恰好是 $P[q+1]$，则状态推进到 $q+1$；否则要「回退」——回退到「已读串 $P_q a$ 的最长后缀同时是 $P$ 的前缀」的那个长度。这个「回退」由最长前缀-后缀决定，正是 KMP 前缀函数的雏形。</span>

## 2 匹配阶段：逐字符查表

```text
FINITE-AUTOMATON-MATCHER(T, δ, m):
    n = T.length
    q = 0                                // 初始状态：未匹配任何前缀
    for i = 1 to n:
        q = δ(q, T[i])                   // 逐字符查表推进状态
        if q == m:                       // 达到完全匹配状态
            输出「模式在位移 i - m 处出现」
```

**每个字符 $O(1)$**（查表 $\delta(q, T[i])$），总 $O(n)$——**匹配阶段严格线性**，无回溯。<span class="marginnote">注意匹配阶段没有「失败」概念——自动机永远是确定性的：读入每个字符必然转移到某个状态。失配只是「转移到较小的状态」（回退），不是「停止」。这是自动机匹配与朴素匹配的本质区别：朴素失配后位移 +1 重新开始，自动机失配后状态回退但文本指针不动。</span>

## 3 转移表的构造

构造 $\delta$ 需要计算每个状态 $q$、每个字符 $a$ 的转移。**朴素构造**：

```text
COMPUTE-TRANSITION-FUNCTION(P, Σ):
    m = P.length
    for q = 0 to m:                      // 每个状态 q
        for each 字符 a ∈ Σ:
            k = min(m, q + 1)
            while k > 0 and P[1..k] 不是 (P[1..q] + a) 的后缀:
                k = k - 1
            δ(q, a) = k                 // 最长可继续匹配的前缀长度
    return δ
```

对每个 $(q, a)$ 从大到小试「$P$ 的前缀长度 $k$」，找第一个「是 $P_q a$ 后缀」的 $k$。**复杂度**：$O(m^3|\Sigma|)$（$m+1$ 个状态 × $|\Sigma|$ 字符 × 每次 $O(m)$ 后缀检查 × 试 $O(m)$ 次）。<span class="marginnote">$m^3|\Sigma|$ 是自动机构造的主要代价——它比匹配的 $O(n)$ 贵得多。这就是 KMP 出现的动机：KMP 用一个「前缀函数」在 $O(m)$ 内获得同样的「回退信息」，免去构造整张转移表。若 $|\Sigma|$ 很大（如 Unicode）或 $m$ 大，$m^3|\Sigma|$ 可能不可接受。</span>

**辨析｜易错点：** 转移表是 $(m+1) \times |\Sigma|$ 的——维度是「状态数 × 字符集大小」。字符集大（如 65536 个 Unicode 码点）时表会爆炸；这也是为什么实际更常用 KMP（无字符集维度）或后缀数组（后缀自动机）。

## 4 公式解析：为什么匹配阶段是 $O(n)$ 且正确

匹配阶段逐字符：

$$T_{\text{match}}(n) = \sum_{i=1}^{n} O(1) = O(n)$$

- **第一步，每字符一步**：每个 $T[i]$ 只触发一次查表 $\delta(q, T[i])$，$O(1)$。
- **第二步，总步数**：$n$ 个字符，$n$ 步——**无回溯、无重读**，文本指针单向推进。
- **第三步，正确性**：$\delta$ 的定义保证「状态 $q$ = 已读文本的最长后缀中匹配 $P$ 前缀的长度」；状态到 $m$ 即「某位移处完全匹配」。归纳可证每个匹配都被找到且不遗漏。

**要点**：自动机匹配把「匹配」与「预处理」彻底分离——匹配阶段的信息复杂度由状态表承担，文本只读一遍。<span class="marginnote">对比 Rabin-Karp：那里「哈希相等」还要朴素验证（期望线性）；这里「状态到 $m$」就是确凿匹配（严格线性），因为状态 $q=m$ 意味着「$P$ 确实是已读串的后缀」，不需要二次确认。自动机是「确定性」的：匹配由状态保证，无碰撞。</span>

## 5 延伸：AC 自动机与多模式

把「单模式的自动机」推广到「多模式」，就是 **Aho-Corasick 自动机**：把所有模式建成 Trie + 失配指针（fail link），一次文本扫描找出**所有**模式的所有出现——$O(n + \text{总匹配数} + \text{总模式长})$。<span class="marginnote">AC 自动机是「敏感词过滤、病毒特征扫描、多关键字检索」的工业标准。它的 fail link 正是「回退到最长可匹配前缀」思想的推广——单模式里这个「回退」是数字状态，多模式里变成 Trie 上的指针。理解了本课的 $\delta$，AC 自动机就只是「自动机思想的多模式版」。</span>

## 6 数值算例：P = aba 的整张转移表

对模式 $P = \text{aba}$（$m=3$）、字符集 $\Sigma = \{a,b\}$，逐格算转移：

| 状态 $q$ | $P_q$ | 读 $a$：最长可续前缀 | 读 $b$：最长可续前缀 |
| --- | --- | --- | --- |
| 0 | 空 | 1（$P_1 = a$） | 0（无前缀以 b 开头） |
| 1 | a | 1（$aa$ 的后缀 $a$） | 2（$ab$ = 前缀 $ab$） |
| 2 | ab | 3（$aba$ 全匹配） | 0（$abb$ 无前缀后缀） |
| 3 | aba | 1（$abaa$ 的后缀 $a$） | 2（$abab$ 的后缀 $ab$） |

以 $\delta(3, b)$ 为例：$P_q + a = \text{abab}$，找「$P$ 的前缀」中「$\text{abab}$ 的后缀」的最长者——$\text{ab}$ 是后缀 ✓，$\text{aba}$ 不是（后三位是 bab）→ $k = 2$。

**跑匹配**：文本 $T = \text{ababa}$。

| 字符 | 转移 | 状态 | 事件 |
| --- | --- | --- | --- |
| a | $\delta(0,a)=1$ | 1 | — |
| b | $\delta(1,b)=2$ | 2 | — |
| a | $\delta(2,a)=3$ | 3 | **匹配**（位移 0） |
| b | $\delta(3,b)=2$ | 2 | 回退到 2 |
| a | $\delta(2,a)=3$ | 3 | **匹配**（位移 2） |

文本 $\text{ababa}$ 中 $\text{aba}$ 出现在位置 1 与 3——两处都被状态到 3 精确捕获。<span class="marginnote">看 $T[4]=b$ 那一行：状态从 3 回退到 2，<strong>文本指针不倒退</strong>——这就是「无回溯」的含义。若用朴素算法，失配后位移 +1 重扫；自动机只是状态回退，文本继续往前。$T[5]=a$ 又把状态拉回 3，第二次匹配完成。5 个字符、5 次查表、零回退。</span>

**复杂度核对**：匹配阶段 $n=5$ 字符 × $O(1)$ = 5 步；构造阶段 $4 \times 2 = 8$ 格、每格 $O(m)$ 后缀检查 ≈ 常数。构造 $O(m^3|\Sigma|) = 3^3 \times 2 = 54$ 的上界在这里被小 $m$ 吞掉了——但当 $m$、$|\Sigma|$ 变大时，构造就会成为瓶颈。

## 7 小结

- **状态 $q$** = 已匹配模式前缀的最长长度；$m$ = 完全匹配。
- **转移** $\delta(q,a)$ = 使「$P$ 前缀」是「$P_q a$ 后缀」的最长 $k$。
- **匹配阶段**：逐字符查表，$O(n)$ 严格线性、无回溯。
- 数值算例：$P=aba$ 在 $\text{ababa}$ 中两次命中，状态 3→2 的回退不倒退文本指针。
- **构造复杂度** $O(m^3|\Sigma|)$——贵在表；字符集大时表爆炸。
- KMP 用前缀函数省去整张表；AC 自动机把思想推广到多模式。


**速查表**：

| 概念 | 含义 |
| --- | --- |
| 状态 $q$ | 已匹配模式前缀长度 |
| 转移 $\delta(q,a)$ | 读 $a$ 后的最长可续前缀长度 |
| 回退 | 失配时状态回退、文本指针不动 |
| 构造 $O(m^3|\Sigma|)$ | 预处理贵，匹配便宜 |

**辨析｜易错点：** 匹配阶段没有「失败」——自动机永远确定性：读入每个字符必然转移到某个状态，失配只是回退。这是自动机匹配与朴素匹配的本质区别。

**数值快照**：$P=\text{aba}$ 在 $\text{ababa}$ 中两次命中（位移 0 与 2），状态 3→2 的回退不倒退文本指针——5 个字符、5 次查表、零回退，$O(n)$ 严格线性。
