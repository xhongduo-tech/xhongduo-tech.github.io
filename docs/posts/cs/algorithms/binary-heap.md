## 为什么从二叉堆开始

堆排序的入口不是「排序」，而是一种数据结构：**二叉堆（binary heap）**。它把「在 $O(\log n)$ 内取最大/最小元素」这个需求，用数组里的完全二叉树优雅实现。<span class="marginnote">堆是优先队列（priority queue）的经典实现，而优先队列贯穿整个算法谱系：Dijkstra 最短路、Prim 最小生成树、Huffman 编码、任务调度——全都建立在「快速取极值」之上。学堆，是在给后面一大片图算法与贪心算法打地基。</span>

这一课聚焦堆的**结构与维护原语**：堆的性质、父子下标关系、MAX-HEAPIFY 的 $O(\log n)$ 修复。至于建堆、排序与优先队列，留给后续三课。

## 1 堆的两种性质

**二叉堆**是一个数组，可以看作一棵**近似完全二叉树**（除了最底层，每一层都填满；最底层从左到右填充）。它满足两条性质：

- **结构性质**：除最后一层外完全填满，最后一层靠左。
- **堆序性质**：对最大堆，任意节点不小于其孩子——**父节点值 ≥ 孩子值**。由此堆顶 $A[1]$ 一定是整个数组的最大值。

用数组 $A$ 存储时，下标关系是堆的全部秘密：

$$\text{PARENT}(i) = \lfloor i/2 \rfloor,\qquad \text{LEFT}(i) = 2i,\qquad \text{RIGHT}(i) = 2i+1$$

**辨析｜易错点：** 下标从 **1** 开始（CLRS 约定），LEFT = $2i$、RIGHT = $2i+1$、PARENT = $\lfloor i/2 \rfloor$。若语言里数组从 0 开始（如 C/Python），通常把下标平移：LEFT = $2i+1$，RIGHT = $2i+2$，PARENT = $\lfloor (i-1)/2 \rfloor$。<span class="marginnote">下标从 0 还是从 1 是堆实现里第一个坑：两套公式都能工作，但混用必然越界。做题或写代码前，先确认你的数组基准。</span>

## 2 堆的高度与基本度量

一个含 $n$ 个元素的堆对应一棵高度为 $\lfloor \lg n \rfloor$ 的完全二叉树。三个常用结论：

- **高度**：$\Theta(\log n)$，因为完全二叉树的高度是对数的。
- **叶子数量**：$\lceil n/2 \rceil$ 个叶子（从下标 $\lfloor n/2 \rfloor + 1$ 到 $n$）。<span class="marginnote">「后一半下标全是叶子」这个事实在建堆分析里至关重要——堆排序的 BUILD-MAX-HEAP 从下标 $\lfloor n/2 \rfloor$ 开始向前遍历，正是因为再往后的节点没有孩子，无需修复。</span>
- **子树规模**：以 $i$ 为根的子树最多有 $2n/3$ 个节点（当最后一层恰好半满时取到），这是 MAX-HEAPIFY 递归式里那个 $2n/3$ 的来源。

## 3 MAX-HEAPIFY：修复堆序性质

**MAX-HEAPIFY(A, i)** 的前提是：以 $i$ 的左、右孩子为根的子树**都已经满足最大堆性质**，只有 $A[i]$ 可能小于它的某个孩子。目标：让以 $i$ 为根的整棵子树重新满足堆序。

算法流程：

```
MAX-HEAPIFY(A, i)
  l = LEFT(i); r = RIGHT(i); largest = i
  if l <= A.heap-size and A[l] > A[i]
    largest = l
  if r <= A.heap-size and A[r] > A[largest]
    largest = r
  if largest != i
    exchange A[i] with A[largest]
    MAX-HEAPIFY(A, largest)
```

**思想**：找出 $A[i]$、左孩子、右孩子三者中最大者；若最大者不是 $A[i]$，把它与 $A[i]$ 交换，然后**沿着被交换下去的路径继续递归修复**——因为交换后，原来 $A[i]$ 的值下沉到孩子位置，可能又破坏了该孩子子树的堆序。<span class="marginnote">这种「逐级下沉」是堆维护的标准动作。它每次只修复一条从 $i$ 向下的路径，而非整棵子树——这正是它只有 $O(\log n)$ 而非 $O(n)$ 的原因。</span>

**辨析｜易错点：** MAX-HEAPIFY 的递归终止条件是「$A[i]$ 已经是三者中最大」；它**不检查孩子内部是否满足堆序**——那是前提，不是本函数的事。若把前提丢掉，正确性论证就会崩盘。另外注意 heap-size 与数组长度 `A.length` 的区别：heap-size 才是堆当前占用的有效长度。

## 4 公式解析：为什么 MAX-HEAPIFY 是 $O(\log n)$

以 $n$ 节点子树为根的 MAX-HEAPIFY，其运行时间满足递归式：

$$T(n) \le T\left(\frac{2n}{3}\right) + \Theta(1)$$

对这条式子做三步拆解：

- **第一步，看 $\Theta(1)$**：一次 MAX-HEAPIFY 除了递归调用外，只做常数次比较与至多一次交换——找三者的最大值只需 2 次比较。
- **第二步，看 $T(2n/3)$**：最坏情况下，被交换下去的孩子是较大的孩子，其子树规模是整棵子树规模的 $2/3$（当最后一层半满时）。于是递归规模是 $2n/3$ 而非 $n/2$。
- **第三步，解递归式**：每次规模乘以 $2/3$，需要 $\log_{3/2} n = O(\log n)$ 层，每层常数时间，故 $T(n) = O(\log n)$。

**要点**：堆的修复是「沿着一条从根到叶子的路径」，而路径长度就是树高 $\Theta(\log n)$。**任何「沿单条路径维护」的操作，在堆里都是 $O(\log n)$**——这个量级将贯穿堆排序、优先队列的所有操作。

## 5 变体：最小堆与迭代实现

把 MAX-HEAPIFY 中所有大小比较反转，就得到 **MIN-HEAPIFY** 与最小堆——堆顶是最小值，用于最小优先队列（Dijkstra、Huffman 的场景）。<span class="marginnote">实现层面，许多工程库用循环代替递归写 MAX-HEAPIFY，避免深递归的栈开销。逻辑完全等价：每次把「最大者」换到当前节点，游标下移，直到无需交换。</span>

堆的概念到这里就够用了。下一课我们就能用它完成两件事：建堆与排序。**一个重要预告**：从 $\lfloor n/2 \rfloor$ 往前对每个节点调用 MAX-HEAPIFY 来建堆，总代价是 $O(n)$ 而不是 $O(n \log n)$——那将是下一课最精彩的复杂度论证。

## 6 小结

- **二叉堆** = 完全二叉树 + 堆序性质；最大堆的根是全局最大元素。
- 数组下标编码树：LEFT $=2i$，RIGHT $=2i+1$，PARENT $=\lfloor i/2\rfloor$（从 1 开始）；从 0 开始时要平移。
- **MAX-HEAPIFY** 在「孩子已满足堆序」前提下，沿单条路径把违规节点下沉，$O(\log n)$。
- 递归式 $T(n) \le T(2n/3) + \Theta(1)$ 给出 $O(\log n)$；最坏子树规模可达 $2n/3$。
- 后 $\lceil n/2\rceil$ 个下标全是叶子——建堆与排序都会用到这个事实。

在下一课，我们用堆完成**堆排序**：先建堆，再反复把堆顶移到末尾并修复——并证明那反直觉的结论：建堆只要 $O(n)$。
