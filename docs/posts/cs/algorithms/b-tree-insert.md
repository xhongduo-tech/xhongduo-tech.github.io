## 为什么从 B 树插入开始

B 树的查找简单；**插入**则引入 B 树的招牌操作——**分裂（split）**：当节点满（$2t-1$ 个关键字）时，把它一分为二，中间关键字上抛给父节点。这个「满了就劈、劈了上抛」的机制保证树永远平衡。<span class="marginnote">分裂是 B 树「自我平衡」的发动机：插入只在叶子发生，叶子满了就分裂、父节点也跟着可能满、继续分裂——<strong>自底向上</strong>直到根。若根也满，根分裂成两层，树高 +1。这个「分裂上抛」与二叉平衡树（AVL/红黑）的旋转是不同哲学：旋转是「局部调整」，分裂是「整块对半」。</span>

这一课讲 B-TREE-SPLIT-CHILD、B-TREE-INSERT 的「先劈后下」策略、以及为什么是 $O(t\log_t n)$。

## 1 分裂：把满节点劈成两半

**SPLIT-CHILD(x, i)**：把「已满的左孩子 $y$（$2t-1$ 个关键字）」分裂成两个节点，中间关键字 $y.\text{key}[t]$ 上抛到 $x$：

```text
B-TREE-SPLIT-CHILD(x, i):
    y = x.c[i]                          // 满的左孩子
    z = 新节点                          // 新分配的右兄弟
    z.leaf = y.leaf
    z.n = t - 1
    for j = 1 to t - 1:                 // 拷贝右半关键字
        z.key[j] = y.key[j + t]
    if not y.leaf:
        for j = 1 to t:                 // 拷贝右半孩子指针
            z.c[j] = y.c[j + t]
    y.n = t - 1                         // y 保留左半
    for j = x.n + 1 downto i + 1:       // 在 x 中腾出孩子位
        x.c[j + 1] = x.c[j]
    x.c[i + 1] = z                      // z 挂到 x 上
    for j = x.n downto i:               // 腾出关键字位
        x.key[j + 1] = x.key[j]
    x.key[i] = y.key[t]                 // 中间关键字上抛
    x.n = x.n + 1
```

**效果**：$y$ 保留左 $t-1$ 个、$z$ 拿走右 $t-1$ 个、中间那个上抛——**两个节点各含 $t-1$ 个关键字（半满）**，为后续插入留出空间。<span class="marginnote">分裂把「满节点」变成「两个半满节点」，中间关键字上抛后父节点多一个关键字。这个「对半劈 + 上抛中间」让所有节点始终维持在「半满到全满」之间——B 树的「至少 $t-1$ 个关键字」不变量被维护，树的高度平衡因此保持。分裂代价 $O(t)$（拷贝 $t$ 个关键字与孩子）。</span>

## 2 插入：先劈后下

**B-TREE-INSERT** 的策略：**自顶向下，遇满先劈**——在下降过程中，只要当前节点满了就先分裂，保证「到达叶子时，父节点一定有空间接纳上抛的关键字」。这样**分裂不会回溯**（一次下行完成插入）。

```text
B-TREE-INSERT(T, k):
    r = T.root
    if r.n == 2t - 1:                   // 根满：先分裂出新根（树高 +1）
        s = 新节点
        T.root = s
        s.leaf = FALSE
        s.n = 0
        s.c[1] = r
        B-TREE-SPLIT-CHILD(s, 1)
        B-TREE-INSERT-NONFULL(s, k)
    else:
        B-TREE-INSERT-NONFULL(r, k)

B-TREE-INSERT-NONFULL(x, k):            // 前提：x 未满
    i = x.n
    if x.leaf:
        while i >= 1 and k < x.key[i]:  // 在叶子里定位并右移
            x.key[i + 1] = x.key[i];  i = i - 1
        x.key[i + 1] = k;  x.n = x.n + 1
    else:
        while i >= 1 and k < x.key[i]:  // 决定下降的孩子
            i = i - 1
        i = i + 1
        if x.c[i].n == 2t - 1:          // 孩子满，先劈再下
            B-TREE-SPLIT-CHILD(x, i)
            if k > x.key[i]:  i = i + 1
        B-TREE-INSERT-NONFULL(x.c[i], k)
```

<span class="marginnote">「先劈后下」的精妙：正常递归插入遇到满叶子会「上抛分裂、回溯父节点」——但 B-TREE-INSERT 在<strong>下降时</strong>就劈掉所有满节点，保证「要插入的叶子永远不满」，插入后无需任何回溯修正。这个「预分裂」让插入的 I/O = 树高（一趟下行），是 B 树插入高效的关键设计。</span>

## 3 公式解析：复杂度 $O(t\log_t n)$

**I/O 次数**：从根到叶的下降路径，每层一次 读/写：

$$I_{\text{insert}} = O(\log_t n) \text{ 次 I/O（= 树高）}, \qquad T_{\text{CPU}} = O(t \log_t n)$$

- **第一步，I/O**：下降 $O(\log_t n)$ 层，每层读写常数个块——$O(\log_t n)$ 次 I/O。
- **第二步，CPU**：每层节点内移动/拷贝 $O(t)$ 个关键字（分裂 $O(t)$、插入移位 $O(t)$），共 $O(t\log_t n)$。
- **第三步，磁盘瓶颈**：I/O 主导——**插入 ≈ 树高次磁盘访问**。$t=100$、$n=10^9$ 时约 5 次 I/O。

**要点**：B 树插入的 I/O 就是树高——**「先劈后下」保证一趟下行完成，无回溯**。这是 B 树能支撑数据库亿级数据写入的关键。<span class="marginnote">对比二叉搜索树插入（可能退化 $O(n)$ 高）与 AVL（每层旋转 $O(\log n)$）：B 树的「预分裂」使「最坏情况」与「平均情况」都是树高——稳定且矮。这也是为什么数据库敢用 B 树承接「写入吞吐」——插入代价可预测（树高次 I/O），不会突然退化。</span>

**辨析｜易错点：** 根满时**必须先给根分裂出一个新根**（树高 +1），再继续——否则「父节点没空间」的情况会破坏不变量。且分裂是「自底向上」的视觉但算法是「自顶向下预分裂」——**别把两者混了**：分裂发生在下降过程中，不是插入后的回溯修正。

## 4 分裂的连锁与树高增长

根满时分裂：新根只有 1 个关键字、2 个孩子——**树高增加 1**。此后每次「上抛导致父节点满」都会继续分裂——但因为是预分裂，父节点在插入前就已被劈开，所以**实际执行时不会出现「递归回溯」**。<span class="marginnote">树高增长只在「根满」时发生（分裂根）：新根诞生，高度 +1。这个「根分裂长高」是所有平衡树（红黑、B 树）的共性——增长只在顶端，叶子永不「往下长」。理解「树从根长高、从叶插入」的对称结构，B 树的平衡机制就完整了。</span>

## 5 小结

- **分裂（SPLIT-CHILD）**：满节点对半劈，中间关键字上抛，两个半满节点——维护「至少 $t-1$」不变量。
- **插入（先劈后下）**：下降路径上遇满先劈，保证叶子不满、一趟完成、无回溯。
- **根满**：先给根分裂（新根诞生、树高 +1）再插入。
- **复杂度**：$O(\log_t n)$ 次 I/O（= 树高）+ $O(t\log_t n)$ CPU。
- 插入代价可预测（树高次磁盘访问）——数据库写入吞吐的基石。
