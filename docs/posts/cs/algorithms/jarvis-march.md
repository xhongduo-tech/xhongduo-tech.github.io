# 凸包（Convex Hull）：Jarvis 步进法（礼品包装）

<div class="epigraph">

## 为什么从 Jarvis 步进开始

Graham 扫描先排序再扫描；**Jarvis 步进（gift wrapping）**完全不同的哲学：**不排序**，从最低点出发，每一步在剩余点里找「相对当前边转角最小的点」作为下一个凸包顶点——像绕礼物缠一圈彩带。<span class="marginnote">Jarvis 步进的复杂度是 $O(nh)$（$h$ = 凸包顶点数）——当 $h$ 很小时（凸包只含少数「最外圈」点），它比 Graham 的 $O(n\log n)$ 还快。这个「输出敏感（output-sensitive）」特性让它成为理解「算法复杂度可以依赖输出规模」的范例。</span>

这一课讲算法、「转角最小」的叉积实现、以及 $O(nh)$ 的分析。

## 1 算法：逐点「缠彩带」

**JARVIS-MARCH**：

```
JARVIS-MARCH(Q)
  let p0 be the point with minimum y (tie: min x)
  p = p0
  repeat
    output p
    q = some point in Q \ {p}          // 初始任意候选
    for each point r in Q \ {p, q}
      if DIRECTION(p, q, r) > 0        // r 相对 p→q 是左转（转角更小）
        q = r
    p = q
  until p == p0
```

**关键**：每一步固定当前点 $p$，在所有剩余点里找「$p$ 到该点的方向角最小」的点 $q$——即「从 $p$ 出发，右转到当前方向角度最小」的候选。用叉积判定：若 $\text{DIRECTION}(p, q, r) > 0$，说明 $r$ 在 $p \to q$ 的左侧，即「从 $p \to q$ 到 $p \to r$ 是左转」——$r$ 比 $q$ 更「左转」，转角更小，应替换 $q$。<span class="marginnote">「转角最小 = 最左转」的等价关系：沿凸包逆时针走，下一个顶点是「相对当前边向左转最多的点」。用 DIRECTION(p,q,r) > 0 判定「r 在 p→q 左侧」即「r 的转角更小」——一轮扫描找到转角最小者，它就是下一个凸包顶点。这个「贪心选最左转」与凸包的定义天然吻合。</span>

## 2 公式解析：为什么是 $O(nh)$

每次迭代找下一个顶点要扫描全部剩余点（$O(n)$），共 $h$ 个凸包顶点：

$$T(n) = h \cdot O(n) = O(nh)$$

- **第一步，每顶点**：从当前 $p$ 出发，扫描所有其他点找「最左转」的 $q$——$O(n)$。
- **第二步，顶点数**：凸包有 $h$ 个顶点，迭代 $h$ 次。
- **第三步，相乘**：$O(nh)$。当 $h = O(\log n)$（凸包很小）时优于 Graham；当 $h = O(n)$（多数点在凸包上）时退化为 $O(n^2)$。

**要点**：Jarvis 是**输出敏感**算法——复杂度依赖输出规模 $h$。**「输出敏感」是算法设计的一个重要维度**：有时解很小，不必为「解很大」买单。<span class="marginnote">选择建议：不确定 $h$ 大小时，Graham（$O(n\log n)$）更稳；$h$ 明显小（如点集近似凸、只有少数极端点）时 Jarvis 更快。实际上还有<strong>最优输出敏感算法</strong>（Chan 的算法，$O(n\log h)$）同时拿到两者优点——它「分块 + Jarvis + 二分」，是输出敏感技术的集大成。</span>

## 3 边界与正确性

**正确性**：每个「最左转」点都是下一个凸包顶点——因为凸包顶点的定义就是「从某顶点出发，下一个顶点是剩余点中转角最小的那个」。贪心选择与凸包结构一一对应，迭代 $h$ 次回到起点即闭合成凸包。

**共线处理**：若多点共线且都在凸包边上，策略同 Graham——「最左转但保留最远点」或「共线顶点全保留」视需求。<span class="marginnote">Jarvis 的共线分支要小心：当 DIRECTION = 0（多个候选同方向、共线），应选「最远的那个」（它在凸包边上，中途的点要么在边上要么被包住）。若不处理，可能陷入「来回弹跳」不闭合——这是 Jarvis 实现最常见的 bug。</span>

**辨析｜易错点：** 循环终止条件是「回到起点 $p_0$」——若起点选取不当或共线处理错，可能不收敛或绕回半途。**用「记录是否回到 $p_0$」而非「扫描次数」做终止条件**；同时初始化 $q$ 要选一个「确定不是 $p$」的点。

## 4 Jarvis vs Graham：怎么选

| 维度 | Graham 扫描 | Jarvis 步进 |
| --- | --- | --- |
| 思路 | 排序 + 单调栈 | 逐点最左转 |
| 时间 | $O(n\log n)$ | $O(nh)$ |
| 输出敏感 | 否 | 是 |
| $h$ 小时 | 较慢 | **更快** |
| 实现 | 稍复杂（排序比较器） | 简单（一轮扫描） |

**工程速查**：不确定 $h$ → Graham；$h$ 明显小 → Jarvis；追求最优 → Chan 算法（$O(n\log h)$）。<span class="marginnote">「$O(nh)$ vs $O(n\log n)$」的对比还有一个教学价值：它展示了「同一个问题可以有不同的复杂度刻画」。Graham 的复杂度只依赖 $n$，Jarvis 依赖 $n$ 与输出 $h$。理解「输出敏感」后，你会开始留意「输出规模是否可以作为复杂度的自变量」——这是高级算法分析的常用视角。</span>

## 5 小结

- **Jarvis 步进**：从最低点出发，每步找「最左转」点作为下一个凸包顶点，绕一圈闭合。
- **叉积判定**：DIRECTION(p,q,r) > 0 ⟹ r 比 q 转角更小，替换候选。
- **复杂度** $O(nh)$——输出敏感；$h$ 小时优于 Graham，$h$ 大时退化 $O(n^2)$。
- 共线处理（选最远点）避免不闭合；终止条件是「回到起点」。
- 对比：Graham 更稳、Jarvis 更快于小 $h$、Chan 的 $O(n\log h)$ 兼两者。
