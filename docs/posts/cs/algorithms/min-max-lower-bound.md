# 最小值与最大值：比较次数的精确下界

<div class="epigraph">

## 为什么从最值下界开始

顺序统计量问题的入口出奇地简单：**在 $n$ 个数里找最小值**。多数人的第一反应是「那就排个序」——但排序是 $O(n\log n)$，找最小值显然不该这么贵。逐个扫描一遍即可：$n-1$ 次比较。<span class="marginnote">这一课的价值不在「怎么找最小值」，而在「证明 $n-1$ 次比较是最优」——以及那个更精巧的结论：同时找最小和最大，不需要 $2(n-1)$ 次比较，只需要 $\lceil 3n/2 \rceil - 2$ 次。下界论证是这一课的主角。</span>

从简单问题里练出「证明最优性」的能力，是进入更复杂顺序统计量问题（期望线性选择、最坏线性选择）的必修课。

## 1 找最小值的 $n-1$ 下界

**上界**：顺序扫描，维护当前最小值，每扫一个元素至多一次比较，共 $n-1$ 次。

**下界（$n-1$ 次）**：为什么不可能更少？用**对抗论证（adversary argument）**：每次比较最多「淘汰」一个候选——被比较后更大的一方不可能再是最小值。为了确定最小值，除了全局最小者外的 **$n-1$ 个元素都必须在某次比较中「失败」**（即被证明不是最小值）。每次比较至多让一个元素失败，所以至少需要 $n-1$ 次比较。<span class="marginnote">对抗论证的要点：证明下界时，我们让「对手」每次只暴露最少的信息——一次比较只淘汰一个元素。任何声称更少比较就能完成的算法，都无法淘汰全部 $n-1$ 个非最小者，因此必然存在它无法判定的输入。</span>

**结论**：找最小值恰需 $n-1$ 次比较；找最大值同理，$n-1$ 次。**逐个比较的算法已经达到下界，无可再优化。**

## 2 同时找最小和最大：配对法

朴素做法是分别找，需要 $2n-2$ 次比较。但有一个更聪明的**配对法**把常数砍到 1.5：

```
MIN-MAX(A)
  if n is odd
    min = max = A[1]
  else
    if A[1] < A[2]  min=A[1], max=A[2]
    else            min=A[2], max=A[1]
  for i from (n odd ? 2 : 3) step 2 to n-1
    if A[i] < A[i+1]
      if A[i]   < min  min = A[i]
      if A[i+1] > max  max = A[i+1]
    else
      if A[i+1] < min  min = A[i+1]
      if A[i]   > max  max = A[i]
  return (min, max)
```

**思想**：先把元素**两两配对**，每对内部比较一次，分出「对内较小」与「对内较大」；然后只在「较小者集合」中找最小，在「较大者集合」中找最大。<span class="marginnote">关键洞察：真正的最小值只会出现在「每对中较小的那半个」里，真正的最大值只会出现在「每对中较大的那半个」里。把 $n$ 个元素分成两组各 $n/2$ 个「候选」，在各自组内找最值，避免了对每个元素都做两次比较。</span>

## 3 公式解析：为什么是 $\lceil 3n/2 \rceil - 2$ 次

数一数比较次数，分奇偶：

$$C(n) = \begin{cases} 3\left\lfloor \frac{n}{2} \right\rfloor, & n \text{ 为奇数} \\ \frac{3n}{2} - 2, & n \text{ 为偶数} \end{cases} = \left\lceil \frac{3n}{2} \right\rceil - 2$$

- **第一步，配对**：$\lfloor n/2 \rfloor$ 对元素，每对 1 次比较，共 $\lfloor n/2 \rfloor$ 次。
- **第二步，找最小**：在 $\lceil n/2 \rceil$ 个「对内较小者」中找最小，需 $\lceil n/2 \rceil - 1$ 次比较。
- **第三步，找最大**：在 $\lceil n/2 \rceil$ 个「对内较大者」中找最大，需 $\lceil n/2 \rceil - 1$ 次比较。

合计 $\lfloor n/2 \rfloor + 2(\lceil n/2 \rceil - 1) = \lceil 3n/2 \rceil - 2$。偶数 $n$ 时恰为 $3n/2 - 2$；奇数时（最左元素独立成组）为 $3\lfloor n/2\rfloor = 3(n-1)/2$。<span class="marginnote">对比朴素法 $2n-2$ 次：$n=10^6$ 时配对法省约 25% 的比较。虽然量级不变，但「最值」这类常数被反复调用的原语（如基数选择、分治选择）里，1.5 倍改善是实打实的。</span>

**结论**：配对法把同时求最小最大的比较次数从 $2n-2$ 降到 $\lceil 3n/2\rceil - 2$。

## 4 为什么这个下界是紧的：对抗论证升级

为什么不能低于 $\lceil 3n/2 \rceil - 2$？对抗论证给出精确理由。把每个元素的状态看成四种：「大于任何已知」$\to$ 只能当最大候选、「小于任何已知」$\to$ 只能当最小候选、「未决」、「已判定不可能是最值」。

- 为了确定最大值，除最大值外的 $n-1$ 个元素都必须在某次比较中「输掉」一次；
- 为了确定最小值，除最小值外的 $n-1$ 个元素都必须在某次比较中「赢过」一次（或输给更小的）。

关键：**除了「同时参与判定最大与最小」的比较**，一次比较最多贡献一条「输」或一条「赢」。对抗方总能安排：在 $n-1$ 条「输」与 $n-1$ 条「赢」中，至少 $n-2$ 条必须来自不同的比较——剩下至少 $\lceil n/2 \rceil$ 次比较专用于把「双候选」分成「单候选」。合计下界即 $\lceil 3n/2\rceil - 2$。<span class="marginnote">这个论证的严密版本在 CLRS 习题里展开，核心是「中位数元素」的计数：除最小与最大外的 $n-2$ 个元素，每个都必须输一次又赢一次。配对法恰好让每个中间元素在同一对内部「一输一赢」一次完成，所以它达到下界。</span>

**辨析｜易错点：** 配对法的「奇偶分叉」容易写错。$n$ 为奇数时，多出的那个元素要单独初始化 min/max，再从第 2 个开始配对；$n$ 为偶数时先比较前两个初始化。**边界处理错误会让结果正确但比较次数变多**——编程竞赛与面试里这是最常见的丢分点。

## 5 从最值到一般顺序统计量

找第 $k$ 小的元素（$1 < k < n$）比找最值复杂得多：不能只靠「淘汰一半」，因为中间的元素需要**同时证明比 $k-1$ 个大、比 $n-k$ 个小**。最小/最大问题的最优解是 $n-1$，而一般顺序统计量的比较次数下界是 $n + \min(k, n-k) - 2$，上界则是后面两课的主角：

- **期望线性选择**（RANDOMIZED-SELECT）：随机化 + 分治，期望 $O(n)$；
- **最坏线性选择**（SELECT）：中位数之中位数技巧，最坏 $O(n)$。<span class="marginnote">最值问题是「只淘汰一边」的特例，所以便宜；一般顺序统计量要「两边都淘汰一部分」，所以更贵但仍是线性。理解了最值下界，就理解了「淘汰」在顺序统计量里的中心地位。</span>

## 6 小结

- 找最小值（或最大值）恰需 **$n-1$ 次比较**，逐元素扫描已最优；下界靠对抗论证。
- **同时找最小与最大**用配对法：先两两比较分组，再分别找，**$\lceil 3n/2\rceil - 2$ 次**。
- 配对法的核心是「最小只藏在小半组、最大只藏在大半组」。
- 对抗论证升级版说明 $\lceil 3n/2\rceil - 2$ 是紧下界：除首尾外每个元素都要「一输一赢」。
- 一般第 $k$ 小元素更难——需要同时淘汰两边的候选，引出期望/最坏线性选择算法。

在下一课，我们解决一般化的顺序统计量——**RANDOMIZED-SELECT**：借鉴快速排序的划分，但只递归一边，期望 $O(n)$。
