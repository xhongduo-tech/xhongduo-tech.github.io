# 任意线段对相交检测：扫描线算法（Sweep Line）

<div class="epigraph">

## 为什么从扫描线开始

朴素做法对 $n$ 条线段两两判定相交，$O(n^2)$。**扫描线算法（sweep line）**用一条竖直「扫描线」从左到右扫过平面，只检查「当前与扫描线相邻」的线段对——把复杂度降到 $O((n+k)\log n)$（$k$ = 相交对数）。<span class="marginnote">扫描线是计算几何最重要的「范式」之一：把二维问题「降维」成「沿一维顺序的动态维护」。它的核心直觉是：<strong>两条线段相交前，必在某时刻于扫描线上「相邻」</strong>——所以只需检查相邻对，无需所有对。这个「只查相邻」的思想还用于最近点对、平面点集问题。</span>

这一课讲扫描线的机制、事件与状态、以及「只查相邻」为什么不漏相交。

## 1 机制：事件队列与状态结构

**扫描线（sweep line）**：竖直直线从 $x = -\infty$ 向右扫到 $+\infty$。维护两个结构：

**事件队列（event queue）**：所有线段的「左端点（插入）」与「右端点（删除）」按 $x$ 排序。
**状态结构（status）**：当前与扫描线相交的线段，按「与扫描线的交点 $y$ 坐标」**从上到下排序**——用平衡 BST（如红黑树）维护。

**算法**：

```
SWEEP-LINE(S)
1  把所有端点按 x 坐标排序作为事件队列       // 同 x 按 y、先删后插
2  初始化空的状态结构 T                       // 与扫描线交点按 y 排序的 BST
3  for each event in sorted order
4      if event 是线段 s 的左端点
5          把 s 插入 T
6          检查 s 与上下两个新邻居是否相交
7      else                                // event 是右端点
8          检查删除 s 后新成为邻居的那一对是否相交
9          从 T 中删除 s
10     if 某次检查发现相交
11         report 该交点（或直接停机）
```

<span class="marginnote">关键的两个「检查时机」：插入左端点时检查「新线段与上下邻居」；删除右端点时检查「删除后变成邻居的那一对」（它们可能本不相邻、因删除而相邻、且恰好相交）。<strong>相交线段必然在某时刻成为邻居</strong>——这是扫描线正确性的核心不变量。只输出「是否存在相交」时，一发现就停；要求「所有相交」则记录每一对。</span>

## 2 为什么「只查相邻」不漏相交

**不变量（关键引理）**：若两条线段相交，则存在某个时刻 $x$，在扫描线到达交点之前，它们**在状态结构中是相邻的**（上下紧邻）。

**论证**：设两线段 $s_1, s_2$ 交于 $x^*$。在 $x^*$ 之前，它们的 $y$-顺序在交点处「交叉」——即从「$s_1$ 在上」变成「$s_2$ 在上」。在这个交叉发生前，$s_1$ 与 $s_2$ 必然在某一时刻成为相邻线段（否则它们的相对顺序无法交换）。扫描线每次插入/删除都检查「新邻居对」，因此这个「相邻对」会被检查到——相交被发现。<span class="marginnote">这个「顺序交换必先相邻」的论证是扫描线正确性的灵魂：两条相交线段在交点处「穿越」彼此，而 y-顺序的交换必须经过「相邻」这个中间态。扫描线算法不是「碰运气」地查相邻——是<strong>数学上必然</strong>会在某个时刻遇到相交的那一对。</span>

## 3 公式解析：复杂度 $O((n+k)\log n)$

设 $n$ 条线段、$k$ 对相交。每个端点事件 $O(\log n)$（BST 插入/删除/查找邻居），共 $2n$ 个事件：

$$T(n) = 2n \cdot O(\log n) + k \cdot O(\log n) = O((n+k)\log n)$$

- **第一步，事件数**：$2n$ 个端点事件（每个线段一左一右）。
- **第二步，每事件**：BST 操作 $O(\log n)$；插入时检查两个邻居（常数次 DIRECTION）。
- **第三步，相交输出**：每发现一对相交，若需要「报告所有相交」还要额外维护（$O(\log n)$ 每对），$k$ 对贡献 $k \log n$。

**要点**：当相交很少（$k$ 小），复杂度接近 $O(n\log n)$；相交很多时，输出本身就要 $O(k)$。**对比朴素 $O(n^2)$，扫描线把「不必要的两两检查」全部省掉**。<span class="marginnote">数值细节：状态结构中「按 y 排序」的比较依赖「当前扫描线位置 $x$」——不同线段在扫描线上的交点 y 可能变化，需要「在当前 x 处比较交点 y」的动态比较器。实现上用「交叉计数」或「把比较延迟到事件处理时」处理；这是扫描线实现的常见难点（也是 $O(k)$ 自定义比较器的坑）。</span>

**辨析｜易错点：** 退化情形——**垂直线段**（在某个 $x$ 上与扫描线重合）、**重合线段**、**三线共点**——需要特殊的事件处理顺序（先删再插、或按 y 排序同 x 的事件）。CLRS 的简化版假设「无退化」，工程实现要补全这些分支。

## 4 扫描线范式的应用

扫描线「动态维护一维有序 + 只查相邻」的范式远超线段相交：

**平面点集的最近对**（Bentley-Ottmann 变体）。
**矩形并的面积/周长**：按 x 扫描，维护「当前被覆盖的 y 区间」。
**天空线问题（skyline）**：建筑轮廓线。
**Voronoi 图 / Delaunay 三角剖分**：Fortune 的扫描线算法。
**平面图嵌入**、点定位。<span class="marginnote">扫描线把「二维几何」翻译成「一维动态序列」，这个「降维」思路是计算几何的通用武器。下一课的「最近点对」也会用到「按坐标排序 + 邻域检查」的同类思想，只是维护方式不同。学透扫描线，等于掌握了一类「几何 + 数据结构」组合问题的钥匙。</span>

## 5 数值算例：四条水平线，只查该查的对

取四条互不相交的水平线段：$s_1$（y=4，x∈[1,7]）、$s_2$（y=2，x∈[2,8]）、$s_3$（y=3，x∈[3,6]）、$s_4$（y=1，x∈[4,9]）。事件按 x 排序：$L_1(1), L_2(2), L_3(3), L_4(4), R_3(6), R_1(7), R_2(8), R_4(9)$。

| 事件 | 状态结构（按 y 从上到下） | 检查的邻居对 | 结果 |
| --- | --- | --- | --- |
| $L_1$ | $\{s_1\}$ | 无 | — |
| $L_2$ | $\{s_1, s_2\}$ | $s_1$–$s_2$ | 不交 |
| $L_3$ | $\{s_1, s_3, s_2\}$ | $s_1$–$s_3$、$s_3$–$s_2$ | 均不交 |
| $L_4$ | $\{s_1, s_3, s_2, s_4\}$ | $s_2$–$s_4$ | 不交 |
| $R_3$ | $\{s_1, s_2, s_4\}$（删 s3） | $s_1$–$s_2$（新邻居） | 不交 |
| $R_1$ | $\{s_2, s_4\}$（删 s1） | $s_2$–$s_4$ | 不交 |
| $R_2$ | $\{s_4\}$ | 无 | — |

**统计**：朴素两两检查 $\binom{4}{2} = 6$ 对；扫描线只检查了 4 个不同的相邻对——且**所有可能相交的对都已覆盖**（本例无相交，正确输出「无」）。<span class="marginnote">注意 $R_3$ 那一步：删除 $s_3$ 后 $s_1$ 与 $s_2$ 变成新邻居，必须检查——因为「删除后新相邻」的这对在删除前不是邻居、却可能是相交对。这就是算法「插入查邻居、删除查新邻居」两个时机的必要性。本例四条线永不交叉，所以所有检查都返回「不交」，但每步检查都按不变量执行。</span>

**复杂度对照**（$n$ 条线段、$k$ 对相交）：

| $n$ | 朴素 $O(n^2)$ | 扫描线 $O((n+k)\log n)$，$k=O(n)$ |
| --- | --- | --- |
| $10^2$ | $10^4$ | ≈ 2×10²·7 ≈ 1.4×10³ |
| $10^4$ | $10^8$ | ≈ 2×10⁴·14 ≈ 2.8×10⁵ |
| $10^6$ | $10^{12}$ | ≈ 2×10⁶·20 ≈ 4×10⁷ |

$n$ 上万后差距以数量级拉开——扫描线把「看全部对」的平方代价压缩成「看相邻对」的拟线性代价，这正是它统治线段相交检测的原因。

## 6 小结

- **扫描线**：竖直扫描线从左到右扫过，事件 = 线段端点，状态 = 与扫描线交点的 y-序（BST）。
- **检查时机**：插入左端点查上下邻居；删除右端点查「新邻居对」。
- **核心引理**：相交线段必然在交点前成为相邻对——「只查相邻」不漏相交。
- **复杂度** $O((n+k)\log n)$，远优于朴素 $O(n^2)$。
- 数值算例：四条水平线只查 4 对（朴素 6 对），无相交时正确输出「无」。
- 退化情形（垂直线、共点）需特殊处理；扫描线范式广泛用于矩形并、skyline、Voronoi 等。


**速查表**：

| 概念 | 含义 |
| --- | --- |
| 事件队列 | 端点按 x 排序，插入（左端）与删除（右端） |
| 状态结构 | 与扫描线交点的 y 序（平衡 BST） |
| 新邻居检查 | 插入查上下邻居、删除查「新邻居对」 |
| 动态比较器 | 交点 y 依赖当前 x，需特殊处理 |

**辨析｜易错点：** 退化情形——垂直线段、重合线段、三线共点需要特殊的事件处理顺序（先删再插、同 x 按 y 排）。CLRS 简化版假设无退化，工程实现要补全这些分支。

**数值快照**：四条水平线朴素两两检查 6 对、扫描线只查 4 对且覆盖所有可能相交对；$n=10^6$ 时朴素 $10^{12}$ 对、扫描线约 $4\times10^7$ 次——「只查相邻」把平方代价压成拟线性。
