## 为什么从 NP 完全性开始

NP 里有很多问题，其中**最难的那一批**——只要其中一个有多项式算法，整个 NP 就都在 P 中——被称为 **NP 完全（NP-complete）**。这个「恰好最难」的刻画，把「P vs NP」浓缩成一个可验证的问题类。<span class="marginnote">「NP 完全」是难度阶梯的顶端：它在 NP 中（验证易），且所有 NP 问题都能归约到它（不比任何 NP 问题容易）。这意味着 NPC 是「NP 中最难的问题的集合」——它们之间两两同难度，一个被攻克全体解脱。</span>

这一课给出 NPC 的定义、它为何重要，以及那个石破天惊的 **Cook-Levin 定理**：SAT（可满足性）是第一个 NPC 问题。

## 1 NP 完全的定义

**语言 $L$ 是 NP 完全的（NP-complete）**，当且仅当：

1. $L \in NP$（验证容易）；
2. 对每个 $L' \in NP$，$L' \le_P L$（$L$ 不比任何 NP 问题容易）。

**NP 难（NP-hard）**：只要求条件 2（不一定在 NP 中）。NP-hard 可以超出 NP（如优化版 TSP、停机问题）——它们「至少和 NPC 一样难」，但可能连「验证」都做不到。<span class="marginnote">NP-complete 与 NP-hard 的区别常被混淆：NPC 必须在 NP 中（验证易），NP-hard 只要求「难」（所有 NP 归约到它）。所以 NPC ⊆ NP-hard。实际里优化问题（如「求最长路径的长度」）是 NP-hard 但不一定 NPC——因为输出不是「是/否」，验证定义对不上。</span>

**意义**：若任何 NPC 问题有多项式算法，则所有 NP 问题都有——**$P = NP$**。反之，证明某问题是 NPC，等于宣告「除非 $P=NP$，它没有多项式算法」。

## 2 证明 NPC 的范式

要证明新问题 $X$ 是 NPC，只需两步：

1. **证明 $X \in NP$**：给出多项式验证器（证书 + 检查）。
2. **证明某个已知 NPC 问题 $Y \le_P X$**：把 $Y$ 归约到 $X$。

第 2 步为什么够？由归约传递性：任何 $L' \in NP$ 都满足 $L' \le_P Y$（因为 $Y$ 是 NPC），而 $Y \le_P X$——传递得 $L' \le_P X$。于是 $X$ 满足 NPC 条件 2。<span class="marginnote">这个「两步范式」是 NPC 证明的通用模板：验证 + 归约。归约的源头是 Cook-Levin 定理给出的第一个 NPC（SAT），之后每个新 NPC 都从「已知 NPC」归约而来——像滚雪球一样滚出整个 NPC 家族。记熟这个模板，后面的顶点覆盖、哈密顿回路、子集和证明全是它的实例。</span>

## 3 Cook-Levin 定理：第一个 NPC

**定理（Cook-Levin, 1971）**：SAT（布尔公式可满足性）是 NP 完全的。

**定理的两部分**：

**SAT ∈ NP**：证书 = 一组变量赋值；验证器代入检查公式是否为真——多项式时间。
**每个 NP 问题 ≤ SAT**：任取 NP 问题，其多项式验证器 + 证书可编码成一个布尔公式 $\phi$，使「存在证书让验证器接受」⟺「$\phi$ 可满足」。

第二部分的构造：把「验证器在多项式步数内的运行」建模成一张**计算表格**（行 = 时间步、列 = 纸带格），每个格子/状态的「此时是什么」用布尔变量表示，约束条件写成合取范式——「合法计算」⟺「公式可满足」。<span class="marginnote">Cook-Levin 的构造是理论计算机科学最深刻的思想之一：它把「程序运行」编码成「布尔公式」，于是「是否存在某输入使程序接受」变成「公式是否可满足」。这个「计算表格」编码的思想，把抽象的「算法」拉进具体的「公式」世界——从此 NPC 家族有了第一个成员。</span>

**推论（第一个 NPC 变体）**：3-CNF-SAT（每个子句恰好 3 个文字的合取范式）也是 NP 完全的——通过对一般公式做「子句变形」归约。3-SAT 是最常用的归约源头，因为它的结构「规整」、好向图/数问题翻译。

## 4 公式解析：为什么「验证器 + 归约」能证明 NPC

用符号梳理 NPC 证明的第 2 步。设 $Y$ 已知 NPC，要证 $X$ NPC：

$$\forall L' \in NP:\; L' \le_P Y,\qquad Y \le_P X \;\Longrightarrow\; \forall L' \in NP:\; L' \le_P X$$

- **第一步，$Y$ 是 NPC**：每个 NP 问题都归约到 $Y$（$L' \le_P Y$）。
- **第二步，$X$ 不比 $Y$ 容易**：$Y \le_P X$。
- **第三步，传递性**：$L' \le_P Y \le_P X$ ⟹ $L' \le_P X$——$X$ 也「不比任何 NP 问题容易」。

**结论**：只要 $X \in NP$ 且「某个 NPC ≤ X」，$X$ 就是 NPC。**归约传递性把「所有 NP ≤ 一个 NPC」升级成「所有 NP ≤ X」**。<span class="marginnote">这就是「只需归约一个已知 NPC」的数学根据。它让 NPC 的版图可以「连锁扩张」：3-SAT → 顶点覆盖 → 哈密顿回路 → TSP → 子集和，每步只需一次归约。整个链条的根是 Cook-Levin 定理——没有它，第一块多米诺骨牌推不倒。</span>

## 5 NPC 的意义：实践与理论

**理论意义**：NPC 划定了「多项式算法不存在（除非 P=NP）」的问题集合——它回答「为什么这么努力都没找到多项式算法」。
**实践意义**：遇到 NPC 问题，不必死磕精确最优——转而用**近似算法**（第十二篇）、启发式、伪多项式算法（若参数小）、或分支限界。
**识别模式**：背包、图着色、调度、聚类、覆盖、路径……一大批实际问题都是 NPC，识别出来能省下无数「再想想」的时间。<span class="marginnote">CLRS 的忠告：<strong>「能证明 NPC，就别再找多项式算法」</strong>——把精力转向近似或特殊情形。但也要警惕「看着像 NPC 其实不是」（如最大流、二分匹配、最短路都是多项式）。识别「真难」与「假难」，是算法工程师的实战技能。</span>

## 6 NPC 的版图：归约链条一览

从 Cook-Levin 定理的 SAT 出发，NPC 家族靠归约像滚雪球一样扩大。记住这条主链，后面几课（顶点覆盖、哈密顿回路、TSP、子集和）的位置就清楚了：

| 问题 | 归约源头 | 一句话构造 |
| --- | --- | --- |
| 3-CNF-SAT | SAT | 把一般公式变形为每个子句恰 3 个文字的合取范式 |
| Clique / 独立集 | 3-SAT | 把「子句内真值分配」编码成互连顶点、成团成独立集 |
| Vertex Cover | Clique / 独立集 | 团 ↔ 独立集 ↔ 顶点覆盖三者对偶，一步换算 |
| Hamiltonian Cycle | Vertex Cover | 用「选择装置（gadget）」把覆盖方案映射成回路 |
| TSP | Hamiltonian Cycle | 边赋权 0/1，问是否存在代价 ≤ 0 的回路 |
| Subset-Sum | 3-SAT | 把文字与子句编码成十进制大数，配对凑和 |

每步归约都是多项式时间——于是 NPC 的全体成员共享同一个命运：**一个被攻克，全体解脱；一个被证在 P 中，则 P = NP**。<span class="marginnote">这张表也是后面课程的「路线图」：本专题随后几课逐一上演表中下半部分的证明。归约方向值得反复确认——永远是从「已知 NPC」归约到「待证问题」，方向错了整个证明就失效了。</span>

**辨析｜易错点一：**「NPC 问题无解」是错的。它们只是「没有已知多项式算法」（且除非 P=NP 不可能有）；**具体实例仍可解**——几十个城市的旅行商照样能算出最优回路，只是时间随规模指数增长。
**辨析｜易错点二：**「NPC 就是 NP 里最难」太模糊——NPC 是「彼此同难度、且 NP 内任何问题都归约到它们」的一族。NP 里还有「看着难但不知是否 NPC」的问题（如**图同构、整数分解**），它们不属于任何已证 NPC 类，难度与 NPC 的关系至今未知。<span class="marginnote">图同构与整数分解是「NP 中间地带」的著名候选：既没证多项式，也没证 NPC。2015 年图同构的拟多项式突破（Babai）引起轰动——它没把问题划入 P，却显示「卡在中间」的问题也能有深刻进展。若哪天有人证出某个 NPC 问题在 P 中，那将是整部理论计算机科学史的转折点。</span>

## 7 小结

- **NPC 定义**：$L \in NP$ + 所有 NP 问题归约到 $L$——「NP 中最难的一批」。
- **NP-hard**：只要求「所有 NP 归约到它」，不必在 NP 中；NPC ⊆ NP-hard。
- **两步范式**：证明 $X \in NP$（验证器）+ 证明某个 NPC ≤ $X$（归约）。
- **Cook-Levin 定理**：SAT 是第一个 NPC（计算表格编码）；3-SAT 是常用归约源头。
- NPC 家族靠归约连锁扩张：SAT → 3-SAT → 团/覆盖 → 哈密顿回路 → TSP → 子集和。
- NPC 的意义：除非 P=NP 无多项式算法；实践中转向近似/启发式。
- 误区提醒：NPC 问题「没有多项式算法」不等于「不可解」；图同构、整数分解仍是「中间地带」。


**速查表**：

| 概念 | 含义 |
| --- | --- |
| 验证器 | 多项式时间内用证书检查「是」实例的算法 |
| 多项式归约 $\le_P$ | 用一次归约把 $Y$ 的解翻译成 $X$ 的解 |
| 计算表格编码 | Cook-Levin 把程序运行编码成布尔公式 |
| NP 中间地带 | 图同构、整数分解：既未证 P 也未证 NPC |

**辨析｜易错点：** 归约方向永远是从「已知 NPC」到「待证问题」；写反方向整个证明失效。且「NPC 无多项式算法」是「除非 P=NP」的条件断言——不是「永远解不了」，具体实例（小规模）照样能解。

**数值快照**：NPC 家族靠归约连锁扩张：SAT → 3-SAT → 团/覆盖 → 哈密顿回路 → TSP → 子集和，每步只需一次归约；整个链条的根是 Cook-Levin 定理——没有它，第一块多米诺骨牌推不倒。


**延伸｜P vs NP 的实践态度**：面对 NPC 问题，正确反应不是「再想想多项式算法」，而是「识别并转向」——近似、启发式、伪多项式、参数化算法。CLRS 的忠告：**能证明 NPC，就别再找多项式算法**；识别「真难」与「假难」（最大流、二分匹配、最短路都是多项式）是算法工程师的实战技能。


- 记忆锚点：NPC 证明 = 验证器（在 NP）+ 一个已知 NPC 归约到它（不比它容易）。
