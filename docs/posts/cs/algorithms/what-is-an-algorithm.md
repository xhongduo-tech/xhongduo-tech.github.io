## 为什么从算法开始

这个网站叫「从极限到大模型」。极限是第一级数学里微积分的入口，大模型是高级专题中 AI 的前沿，而把数学送进机器、让机器产生「智能」的那层机制，正是**算法（algorithm）**。大模型的骨架全部由算法构成：注意力（attention）是一种计算步骤明确的算法，反向传播是一次又一次对梯度表达式的求值，训练用的 Adam 优化器、推理时的束搜索（beam search），无一例外。<span class="marginnote">「从极限到大模型」里的「大」，不只是参数量，更是「可计算性」与「效率」的尺度。算法分析回答的正是：这件事要花多久、到底能不能做完。</span>

在第三级的课程地图里，本专题《算法设计与分析》是最先出发的一条线：它讲的是「怎么把问题交给计算机，以及要为此付出什么代价」。紧随其后的《数据结构》讨论「用什么容器装数据」，而操作系统、计算机网络、编译原理，处处都在为「更好的算法」服务。今天这一篇是整个专题的第一课，目标朴素而根本：说清什么是算法、算法凭什么值得被当作一门技术来研究。

## 1 什么是算法：非形式定义

**算法（algorithm）**：一个**良定义的计算过程（well-defined computational procedure）**，它接收一个或一组值作为**输入（input）**，经过若干**计算步骤（computational steps）**，产生一个或一组值作为**输出（output）**——把输入变换成输出。<span class="marginnote">这是 CLRS 第 1.1 节给出的非形式定义。关键词是「良定义」与「计算步骤」：每一步都必须精确到可以让一台机器机械地执行，不含任何需要人类直觉补白的地方。</span>

拿一条家常食谱来对比：食谱也是「输入食材、经过步骤、得到菜肴」，但食谱充满歧义——「少许盐」「中火」「翻拌至断生」，每一步都要靠人的判断与经验补全。算法则不同，它的每一步都必须**无歧义**到可以被逐条机械执行。正是这种「去掉人的判断」的彻底性，让算法可以交给计算机，也让算法可以被**严格地分析**：我们能证明它对不对、能算出它要花多久。

这里有一个值得先立住的区分：**程序不一定是算法，算法也不一定是一条程序。** 一个永不终止的操作系统进程不符合「有限性」；而用纸笔演算欧几里得算法，虽然没有任何代码，却是一条货真价实的算法——这正是克努特那句话的意思：拿笔和纸亲手走一遍，是理解算法最好的方式。

## 2 五要素：把「良定义」落到实处

「良定义」三个字怎么落地？算法教材的通行做法（源自克努特《计算机程序设计艺术》，国内《数据结构》教材沿用了这套表述）是用**五个要素**来刻画：

**输入（input）**：有**零个或多个**外部提供的输入量。
**输出（output）**：**至少一个**输出量，与输入有确定的对应关系。
**确定性（definiteness）**：每一步都精确定义，无歧义，同一输入必然得到同一结果。
**有限性（finiteness）**：对合法输入，必须在**有限步**内结束。
**有效性（effectiveness）**：每一步都是**基本可执行**的操作——能用纸笔在有限时间内完成，而非「凭空猜一个解」之类的魔法。

五条里最容易在初学时丢掉的是**确定性**与**有效性**。确定性排除了「碰运气」：同一个输入跑两次，结果必须一致。这一点到后面学随机化算法时会得到一次漂亮的修正——随机化算法让「结果一致」松动为「以高概率一致」，但那是把随机性**显式地**请进算法，而不是依赖模糊步骤。<span class="marginnote">有效性提醒我们：算法必须建立在「可执行的基本操作」之上。「判定一个数是否素数」这句话本身并不构成算法——我们要的不是命题，而是可一步步执行的步骤，这正是后面素性测试那一章的主题。</span>

**「问题」与「实例」** 还要分清：一个**问题（problem）**是对「输入应当满足什么、输出应当是什么」的描述，例如「把 $n$ 个数排序」；而把具体的数填进去，比如「把 $\langle 5, 2, 4, 6, 1, 3 \rangle$ 排成 $\langle 1, 2, 3, 4, 5, 6 \rangle$」，才是问题的一个**实例（instance）**。算法针对问题设计，但真正跑起来时面对的永远是一个个具体的实例。

## 3 排序问题与插入排序

有了定义，立刻看一个贯穿全书的问题——**排序（sorting）**。

**排序问题（sorting problem）**：输入是 $n$ 个数的序列 $\langle a_1, a_2, \dots, a_n \rangle$；输出是这 $n$ 个数的一个重排 $\langle a_1', a_2', \dots, a_n' \rangle$，使得 $a_1' \le a_2' \le \dots \le a_n'$。<span class="marginnote">CLRS 把输入限定为「一个值的序列」——数学上这就是对集合的次序化，与第一级《集合》《集合的运算》里的语言同源。排序是最经典的算法问题：它足够简单，又能容纳几乎所有算法设计的核心思想。</span>

解决排序的第一个算法叫**插入排序（insertion sort）**，思路与打牌时整理手牌完全一致：手里的牌从左到右是从小到大排好的，新抓一张牌，就**从右往左**逐个比较，找到它该插入的位置插进去。

```
INSERTION-SORT(A)
1  for j = 2 to A.length
2      key = A[j]
3      // 把 A[j] 插入已排序的 A[1..j−1]
4      i = j − 1
5      while i > 0 and A[i] > key
6          A[i+1] = A[i]
7          i = i − 1
8      A[i+1] = key
```

这段伪代码是 CLRS 的经典写法，数组下标从 1 开始。用 Python 写出来，逻辑一模一样：

```python
def insertion_sort(A):
    for j in range(1, len(A)):        # Python 下标从 0 开始
        key = A[j]
        i = j - 1
        while i >= 0 and A[i] > key:  # 从右往左找插入点
            A[i + 1] = A[i]           # 大于 key 的元素右移一位
            i = i - 1
        A[i + 1] = key                # key 归位
    return A
```

手动走一遍 $\langle 5, 2, 4, 6, 1, 3 \rangle$：先看 $j=2$，key 是 2，把 5 往后挪、把 2 放到首位，得到 $\langle 2, 5, 4, 6, 1, 3 \rangle$；再看 $j=3$，key 是 4，把 5 挪开、4 插进中间……每一步之后，**前 $j$ 个位置已经是有序的**。这个不变性质叫**循环不变式（loop invariant）**，是证明算法正确性的关键工具，本专题的下一篇《插入排序：循环不变式与正确性证明》会把它讲透。

## 4 效率即技术：算法作为一门技术

定义说完，进入本章真正的题眼：**为什么把算法当作一门技术？**

因为**效率（efficiency）**。同一台机器上，两条算法可能差出几个数量级；而「量级」的差距，是任何硬件提速都无法抹平的。CLRS 第 1.2 节用插入排序与归并排序（后面分治那一篇要学的算法）做了一个著名对比：假设输入规模为 $n$ 时，插入排序运行 $8n^2$ 步，归并排序运行 $64\,n\lg n$ 步。

**临界点**：解 $8n^2 = 64\,n\lg n$，即 $n = 8\lg n$，解得 $n \approx 43$。当 $n \ge 44$ 时，归并排序更快。
**规模放大**：当 $n = 2^{20} \approx 10^6$（一百万个数）时，插入排序要跑约 $8 \times 2^{40} \approx 8.8\times 10^{12}$ 步，归并排序只需约 $64 \times 2^{20}\times 20 \approx 1.3\times 10^9$ 步——差了**六千多倍**。
**硬件救不回来**：就算给插入排序配一台**快 1024 倍**的机器，处理一百万个输入它仍要跑约 $8.8\times10^{12}/1024 \approx 8.6\times10^9$ 步，还是比慢机器上的归并排序多出约 6 倍。<span class="marginnote">这就是「算法作为技术」最反直觉也最核心的一点：当 $n$ 足够大，赢家由<strong>增长阶</strong>决定，而不是由机器的时钟频率决定。买更快的电脑，不如换更好的算法。</span>

**最坏 / 平均 / 最佳情况**的概念也在这里登场。同一个算法，面对不同的输入，代价可以天差地别：

**最佳情况**：输入已经有序，内层 while 每次都立即退出，插入排序只花线性时间 $\Theta(n)$。
**最坏情况**：输入逆序，每张新牌都要挪到底，代价是 $\Theta(n^2)$。
**平均情况**：随机输入，内层平均要走一半的距离，代价仍是 $\Theta(n^2)$，只是常数约为最坏情况的一半。

我们尤其关心**最坏情况**：它给出**保证**——无论输入多刁钻，运行时间都不会超过这个界；而平均情况需要概率的工具，那是第二级《概率》与《概率论与数理统计》反复训练的语言。

对今天的大模型而言，「效率即技术」不是修辞，而是账本：一次大模型训练动辄消耗成千上万 GPU 卡时，训练和推理算法哪怕只提升几个百分点，都是真金白银。<span class="marginnote">Transformer 的注意力对序列长度是平方复杂度，于是催生了线性注意力、状态空间模型（Mamba）等「换算法」的路线；FlashAttention 则在保持数学结果不变的前提下，把注意力的显存占用从 $O(n^2)$ 降到 $O(n)$。这些细节在大模型专题《注意力机制》一节展开。</span>

## 5 公式解析：插入排序最坏情况运行时间的求和

把「效率」从直觉变成公式。记 $t_j$ 为外层循环第 $j$ 轮（$2 \le j \le n$）里 **while 测试被执行的次数**。内层 while 每测试一次都要比较、并可能移动一个元素，所以运行时间的核心部分正比于 $\sum_{j=2}^{n} t_j$。

在最坏情况（输入逆序）下，第 $j$ 轮时前 $j-1$ 个元素全都比 key 大，while 一直跑到 $i=0$ 才停，故 $t_j = j$。于是：

$$
T(n) = \sum_{j=2}^{n} t_j = \sum_{j=2}^{n} j = \frac{n(n+1)}{2} - 1 = \frac{n^2 + n - 2}{2} = \frac{1}{2}n^2 + \frac{1}{2}n - 1
$$

对这条式子做四步拆解：

- **第一步，$t_j$ 是什么**：它是「第 $j$ 轮内层 while 的判断次数」，不是「移动次数」。判断次数比移动次数恰好多 1——最后一次判断发现条件不成立，也要先比较才知道停下来。
- **第二步，为什么最坏时 $t_j = j$**：逆序时第 $j$ 轮要跟前面全部 $j-1$ 个元素都比过、全部挪完，最后再把 key 放回 $A[1]$。$j-1$ 次「成功比较」加 1 次「失败比较」，合计 $j$ 次。
- **第三步，等差求和**：$\sum_{j=2}^{n} j = \left(\sum_{j=1}^{n} j\right) - 1$，而 $\sum_{j=1}^{n} j = \frac{n(n+1)}{2}$ 正是等差数列求和公式——高斯把 $1$ 到 $100$ 配成 50 对、每对和都是 101 的那个办法。这里又回到第一级数学的地基上来了。
- **第四步，看增长阶**：把 $T(n)$ 写成 $\frac{1}{2}n^2 + \frac{1}{2}n - 1$，当 $n$ 很大时，$\frac{1}{2}n^2$ 是主宰项，$\frac{1}{2}n$ 与 $-1$ 无足轻重。于是我们说 $T(n)$ 以 $n^2$ 的阶增长，记作 $T(n) = O(n^2)$——一个**渐进上界**：对足够大的 $n$，$T(n)$ 不超过 $n^2$ 的某个常数倍。

这一小步是全书最重要的观念跃迁：**把精确的式子 $\frac{1}{2}n^2 + \frac{1}{2}n - 1$ 简化成「增长阶」$n^2$**，抛弃常数与低阶项，换取对规模本质的把握。用什么记号严谨地表达「同一个增长阶」，正是下一节《渐进记号》的主题。

## 6 小结

- **算法**是良定义的计算过程：输入若干值，经过无歧义的计算步骤，输出若干值；五要素为**输入、输出、确定性、有限性、有效性**。
- **程序 ≠ 算法**：不终止的进程不是算法；纸笔演算的欧几里得算法没有代码，也是算法。
- **问题与实例**要分清：问题是「输入输出关系的描述」，实例是填进具体数据后的那一次运行。
- **排序问题**是贯穿全书的例舞台；**插入排序**用打牌的直觉完成排序，其正确性靠**循环不变式**保证（下一篇详述）。
- **效率即技术**：$8n^2$ 与 $64\,n\lg n$ 的对比说明，$n$ 足够大时增长阶决定胜负，快 1024 倍的硬件也救不回渐近更慢的算法。
- **最坏 / 平均 / 最佳情况**刻画算法在不同输入下的代价；最坏情况给出的是「无论如何都不超过」的保证。

在下一节，我们把「以 $n^2$ 的阶增长」这句话变成一门严格的语言——**渐进记号（asymptotic notation）**：$\Theta$、$O$、$\Omega$、$o$、$\omega$ 的精确含义，以及它们如何让「效率」可以被证明、被比较。
