## 为什么从并行矩阵乘法与归并开始

并行斐波那契是「并行无救」的反例；这一课看两个「值得并行」的算法——**并行矩阵乘法**与**并行归并**——它们的 work 不变、span 大幅下降，并行度可观。<span class="marginnote">并行的两条基本路线在这里同时出现：矩阵乘法是「<strong>数据并行</strong>」（每个输出元素独立可算，天然并行）；归并是「<strong>任务并行</strong>」（把问题切成两半，两半递归并行，合并也可能并行）。理解这两条路线，等于掌握了并行算法的两种基本构图。</span>

这一课算两个算法的 work 与 span，并对比「为什么一个简单、一个精巧」。

## 1 并行矩阵乘法：数据并行

朴素矩阵乘法 $C = A \cdot B$，$C[i][j] = \sum_k A[i][k]B[k][j]$。**每个输出元素独立**——可以直接 spawn 每个 $C[i][j]$ 的计算：

```text
P-MATRIX-MULTIPLY(A, B):
    n = A.rows
    令 C 为 n × n 矩阵
    parallel for i = 1 to n:             // 每个输出元素独立
        parallel for j = 1 to n:
            C[i][j] = 0
            for k = 1 to n:              // 内层 k 循环串行累加
                C[i][j] = C[i][j] + A[i][k] * B[k][j]
    return C
```

**work** $T_1 = \Theta(n^3)$（与串行相同——总工作量不变）。**span**：最内层 $k$ 循环串行 $O(n)$，两层 parallel for 的跨度是「最深的嵌套」$O(\log n)$ 每层？——不，parallel for 的 span 是 $O(\log n)$（分治展开），但内层 $k$ 循环是 $O(n)$：

$$T_\infty = O(n)$$

**并行度** $= \Theta(n^3/n) = \Theta(n^2)$——处理器数到 $n^2$ 都还能线性加速。<span class="marginnote">「数据并行」的威力：$n^2$ 个输出元素彼此独立，spawn 全部并行——只要内层 $k$ 循环不拆，span 就是 $O(n)$（每个元素串行算 $n$ 项）。若把内层也拆成并行归约（span $O(\log n)$），并行度升到 $\Theta(n^3/\log n)$——「拆得越细、并行度越高」。</span>

## 2 并行归并排序：任务并行 + 并行合并

**串行归并排序**：$T_1 = \Theta(n\log n)$。并行化分两步：

**（a）递归并行**：两半**递归**并行排序。span 递归 $T_\infty(n) = T_\infty(n/2) + O(\text{合并的 span})$。

**（b）并行合并（P-MERGE）**：合并两个有序数组时，选较长一半的中点作为「分割点」，在另一半里二分找它的位置，然后**两段并行合并**：

```text
P-MERGE(T, p1, r1, p2, r2, A, p3):
    n1 = r1 - p1 + 1;  n2 = r2 - p2 + 1
    if n1 < n2:                          // 保证 n1 ≥ n2
        交换两个子数组的边界参数
    if n1 == 0:
        return
    q1 = ⌊(p1 + r1) / 2⌋                // 长半的中点
    q2 = 在 T[p2..r2] 中二分定位 T[q1] 的插入位置
    q3 = p3 + (q1 - p1) + (q2 - p2)     // T[q1] 在输出中的位置
    A[q3] = T[q1]
    spawn P-MERGE(T, p1, q1-1, p2, q2-1, A, p3)
    P-MERGE(T, q1+1, r1, q2, r2, A, q3+1)
    sync
```

**并行合并的 span**：每层把规模减半，$T_\infty^{\text{merge}}(n) = O(\log^2 n)$。

**并行归并排序总 span**：

$$T_\infty(n) = T_\infty(n/2) + O(\log^2 n) = O(\log^3 n)$$

**work 不变** $= \Theta(n\log n)$。**并行度** $= \Theta(n\log n/\log^3 n) = \Theta(n/\log^2 n)$。<span class="marginnote">并行归并的巧妙在 P-MERGE：不「顺序扫描合并」，而是用「中点 + 二分定位」把合并拆成两个独立子合并——两个子合并规模都约减半，可并行。这个「二分定位 + 分治合并」让合并的 span 从 $O(n)$（串行合并）降到 $O(\log^2 n)$，是整个算法的点睛之笔。对比并行矩阵乘法的「直接数据并行」，这是「需要设计」的并行。</span>

## 3 公式解析：为什么并行归并的 span 是 $O(\log^3 n)$

把排序的 span 递归式展开：

$$T_\infty(n) = T_\infty\left(\frac{n}{2}\right) + O(\log^2 n) \quad\Longrightarrow\quad T_\infty(n) = \sum_{i=0}^{\log n} O(\log^2(n/2^i)) = O(\log^3 n)$$

- **第一步，排序 span 递归**：两半并行，span 只取一半（$\max$ = $T_\infty(n/2)$），再加合并的 span $O(\log^2 n)$。
- **第二步，展开**：$\log n$ 层，每层合并 span $O(\log^2 n)$——总和 $O(\log^3 n)$。
- **第三步，work 不变**：$T_1 = \Theta(n\log n)$（与串行归并相同）——并行不增加总工作量。

**要点**：$T_1$ 不变 + $T_\infty$ 从 $O(n)$ 降到 $O(\log^3 n)$——**并行归并排序的 span 比数据并行的矩阵乘法好得多**（对数 vs 线性）。<span class="marginnote">对比：串行归并排序的「关键路径」是 $O(n)$（合并必须串行扫）；并行归并把它压到 $O(\log^2 n)$ 每层。这就是「任务并行 + 精巧合并」对「数据并行」的优势——但矩阵乘法的 $O(n)$ span 也已足够好（并行度 $\Theta(n^2)$）。选择哪种并行取决于问题结构。</span>

**辨析｜易错点：** parallel for 的 span 是 $O(\log n)$（不是 $O(1)$）——它用分治展开成「$\log n$ 层的派生树」。算 span 时别把 parallel for 当常数。且 P-MERGE 的二分要求输入有序——**先排序再合并**的顺序不能乱。

## 4 两个算法的对比

| 算法 | Work $T_1$ | Span $T_\infty$ | 并行度 | 并行方式 |
| --- | --- | --- | --- | --- |
| 矩阵乘法 | $\Theta(n^3)$ | $O(n)$ | $\Theta(n^2)$ | 数据并行 |
| 归并排序 | $\Theta(n\log n)$ | $O(\log^3 n)$ | $\Theta(n/\log^2 n)$ | 任务并行 + 并行合并 |

矩阵乘法的并行度随 $n^2$ 增长（可大规模并行），归并排序并行度随 $n$ 增长（$n$ 大时也够用）——**两者都是「值得并行」的算法**（work 最优、span 短）。<span class="marginnote">「值得并行」的标准：work 尽量接近最优串行（$T_1 = \Theta(T_{\text{best}})$）且 span 尽量短（并行度高）。若 $T_1$ 已是指数（并行斐波那契），再高的并行度也无意义。这一课的两个算法是「work 优 + span 短」的正面教材——也是「数据并行 vs 任务并行」两条路线的对比样本。</span>

## 5 数值算例：P-MERGE 拆分一次

合并两个有序数组 $A = [1, 4, 7]$ 与 $B = [2, 3, 6]$（各 $n = 3$）。

**P-MERGE 第一步**：$n_1 = n_2 = 3$，取长半（A）中点 $q_1 = 2$（值 4）。在 $B = [2,3,6]$ 中二分定位 4 的插入位置——$4$ 应排在 3 之后、6 之前，故 $q_2 = 3$（B 中第 3 个位置，即值 3 之后）。输出位置 $q_3 = 1 + (2-1) + (3-1) = 4$，$A[4] = 4$。

**并行递归**：

| 子合并 | 输入 | 输出 |
| --- | --- | --- |
| 左：$A[1..1]=[1]$ 与 $B[1..2]=[2,3]$ | $[1]$、$[2,3]$ | $[1,2,3]$ |
| 右：$A[3..3]=[7]$ 与 $B[3..3]=[6]$ | $[7]$、$[6]$ | $[6,7]$ |

最终 $[1,2,3,4,6,7]$——**两个子合并规模都约减半且并行执行**。<span class="marginnote">看拆分的关键：4 落在输出第 4 位，左右两边各是「比 4 小的 $[1,2,3]$」与「比 4 大的 $[6,7]$」——两个子问题互不干扰，可 spawn 并行。若串行合并要按序扫 6 步（span $O(n)$），P-MERGE 的递归深度只有 $\log_2 3 \approx 2$ 层、每层二分 $O(\log n)$——总 span $O(\log^2 n)$。这就是「二分定位 + 分治合并」把合并关键路径从线性压到对数的原理。</span>

**规模对照**：$n = 10^6$ 时，串行合并 span $O(10^6)$；P-MERGE 递归约 $\log_2 10^6 \approx 20$ 层、每层二分约 20 次——span 约 $O(400)$，缩小两千五百倍。排序整体的 span 从 $O(n)$ 压到 $O(\log^3 n) \approx 8000$，并行度 $\approx n/\log^2 n \approx 2500$——「任务并行 + 精巧合并」的收益在规模上清晰可见。

## 6 小结

- **并行矩阵乘法**：数据并行（每输出独立），$T_1 = \Theta(n^3)$、$T_\infty = O(n)$，并行度 $\Theta(n^2)$。
- **并行归并排序**：任务并行（两半 spawn）+ P-MERGE（二分定位 + 并行合并），$T_\infty = O(\log^3 n)$。
- 数值算例：$[1,4,7]$ 与 $[2,3,6]$ 的 P-MERGE 一次拆分即得两个并行子合并。
- **P-MERGE 点睛**：中点 + 二分把合并拆成两个可并行子合并，span 从 $O(n)$ 降到 $O(\log^2 n)$。
- work 不变、span 缩短 = 并行度的来源；「值得并行」= work 优 + span 短。
- 数据并行（矩阵）vs 任务并行（归并）是并行算法的两种基本构图。
