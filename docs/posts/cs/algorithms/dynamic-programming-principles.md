# 动态规划原理：最优子结构与重叠子问题

<div class="epigraph">

## 为什么从动态规划原理开始

我们已经见过分治与贪心的影子，而**动态规划（dynamic programming）**是站在它们肩膀上的更系统范式。它处理的问题是：**可以拆成子问题，但子问题大量重叠**——同一子问题被反复求解。<span class="marginnote">「programming」在这里不是「编程」，而是贝尔曼时代的「规划/表格法」之意——把子问题的解填进表格，避免重复计算。这个名字常让人误解，但它的核心就是「记住算过的答案」。</span>

这一课先立起动态规划的两根支柱——**最优子结构**与**重叠子问题**——再给出一套四步法，把「能不能用 DP」和「怎么设计 DP」变成可操作的流程。后续所有 DP 问题（钢条切割、矩阵链、LCS、背包……）都套用这套骨架。

## 1 两个必要条件

**最优子结构（optimal substructure）**：问题的最优解**包含**子问题的最优解。即：一旦知道了子问题的最优解，就可以用它们构造出全局最优解。<span class="marginnote">最值下界那一课其实已悄悄用过最优子结构：最大子数组跨越中线时，「左最大后缀 + 右最大前缀」各自就是子问题的最优解。DP 把这种结构系统化，并配上「记忆化」消灭重叠。</span>

**重叠子问题（overlapping subproblems）**：递归求解时，同一个子问题被反复求解多次。若子问题是独立的（各自只出现一次），那是分治（归并排序）；若大量重复，才是动态规划的用武之地。

**辨析｜易错点：** 最优子结构 ≠ 「贪心适用」。贪心要求「贪心选择性质」（每次局部最优即全局最优）；DP 只要求「最优解由子问题最优解拼成」，允许需要探索多个选择。**凡是贪心能解的，往往有最优子结构；但反过来不成立**——这正是后面贪心课要讲的区分。

## 2 一个问题「是否 DP」：三个提问

拿到一个优化问题，按顺序自问：

1. **问题能拆成更小的同类问题吗？** 即是否存在「递归定义」——大问题的解由小问题的解组合而成。
2. **子问题重叠吗？** 画出递归树，若同一节点反复出现（如斐波那契的 $F(n-2)$ 被多个分支共享），则重叠。
3. **最优子结构成立吗？** 反证法检查：假设某个子问题取非最优解，能否导致全局更优？若能，则最优子结构成立。<span class="marginnote">第三问的严格工具是「剪贴论证（cut-and-paste）」：若全局最优解里含一个非最优子问题，把该子问题替换成它的最优解，全局不会变差——从而导出矛盾。这个论证在 CLRS 里反复出现，是证明最优子结构的标准动作。</span>

若三个回答都是「是」，DP 就是正确工具；若第一个回答「是」但第二个「否」，那是分治；若第一个回答「否」，那可能贪心或根本不适合拆解。

## 3 四步法：DP 设计骨架

CLRS 给出设计 DP 算法的四步，所有 DP 问题都是这套骨架的实例：

1. **刻画最优解的结构**——描述「最优解由哪些子问题的最优解组成」，即找出最优子结构。
2. **递归定义最优解的值**——写出状态与转移方程。设 $dp[\text{状态}]$ = 该状态的最优值，转移式把大状态写成小状态的函数。
3. **计算最优解的值**——自底向上填表（或自顶向下记忆化）。
4. **构造最优解**——除了最优值，还记录「决策」（做了哪个选择），回溯还原方案。

**状态设计**是第 2 步的灵魂：`dp[i]` 通常表示「前 $i$ 个元素 / 以 $i$ 结尾 / 区间 $[i,j]$」的最优值。**状态怎么定义，决定了转移怎么写**——这是 DP 里最需要经验的部分。<span class="marginnote">两条常见的心智捷径：一是「最后一步」——问自己「全局最优解的最后一步做了什么选择」，它往往就是状态转移的分支；二是「以 i 结尾」——把问题定义为「以第 $i$ 项结尾的最优值」，往往比「前 $i$ 项」更容易写转移。</span>

## 4 公式解析：递归树如何暴露重叠

以斐波那契 $F(n)$ 为例（它是理解重叠子问题的最小模型）：

$$F(n) = F(n-1) + F(n-2), \qquad F(0) = 0, \; F(1) = 1$$

- **第一步，展开递归树**：$F(5)$ 调用 $F(4), F(3)$；$F(4)$ 又调用 $F(3), F(2)$；$F(3)$ 出现**两次**。
- **第二步，数出现次数**：$F(2)$ 在递归树里出现 3 次，$F(3)$ 出现 2 次——同一子问题被反复求解。
- **第三步，算代价**：朴素递归 $T(n) = T(n-1) + T(n-2) + O(1)$ 解出 $T(n) = \Theta(\phi^n)$（$\phi$ 是黄金比例）；记忆化后每个状态只算一次，$O(n)$。

**要点**：重叠子问题让朴素递归呈**指数爆炸**；记忆化把每个子问题「只算一次」，爆炸变线性。<span class="marginnote">斐波那契展示了 DP 的第一重收益：不是「找到更聪明的解」，而是「不重复算同一个子问题」。后续的钢条切割、矩阵链都共享这个「记忆化消除指数」的结构，只是状态维度从 1 变 2。</span>

**辨析｜易错点：** 记忆化 ≠ 动态规划的全部。记忆化（自顶向下）只是计算次序的一种；自底向上填表同样消灭重叠，且**没有递归栈开销、更可控**。两者状态与转移相同，只是「什么时候算」不同。考试里常见误区是把「记忆化」与「DP」对立——它们是同一设计的两种实现。

## 5 动态规划 vs 分治 vs 贪心

| 维度 | 分治 | 动态规划 | 贪心 |
| --- | --- | --- | --- |
| 子问题关系 | 独立 | **重叠** | 独立（每次选完即固定） |
| 求解方向 | 自顶向下递归 | 自底向上/记忆化 | 逐次贪心选择 |
| 需要性质 | — | 最优子结构 + 重叠子问题 | 贪心选择性质 + 最优子结构 |
| 典型例子 | 归并排序 | 钢条切割、LCS | 活动选择、Huffman |

贪心是 DP 的**特例加速**：当「每次只需做一个选择」且该选择可证明最优时，不必探索所有子问题——DP 填满整张表，贪心只走一条路。<span class="marginnote">一条实用的经验：<strong>先用 DP 想通问题，再看能否加速成贪心</strong>。很多贪心算法（活动选择、分数背包）的正确性证明正是「证明 DP 的某种选择可以被贪心地固定」。反过来，DP 是贪心失效时的安全网。</span>

## 6 小结

- **最优子结构**：全局最优解由子问题最优解拼成——用剪贴论证验证。
- **重叠子问题**：递归树里同一子问题反复出现——这是 DP 与分治的分水岭。
- **四步法**：刻画结构 → 递归定义（状态 + 转移）→ 计算 → 回溯构造。
- 状态设计是 DP 的灵魂：「最后一步」与「以 i 结尾」是常用启发。
- 记忆化消除指数爆炸；自底向上更可控。DP 是贪心的超集，贪心是 DP 的特例加速。

在下一课，我们用第一个完整案例落地这套骨架——**钢条切割**：一根钢条怎么切收益最大？自顶向下备忘录与自底向上两种实现，对比各自的优劣。
