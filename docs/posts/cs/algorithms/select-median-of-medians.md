# 最坏情况线性时间选择：SELECT 与中位数的中位数（Median of Medians）

<div class="epigraph">
<p>要保证最坏也线性，就不能依赖运气——先保证每次划分都「足够好」，再递归。</p>
<footer>—— 曼努埃尔 · 布鲁姆 等（Manuel Blum, Robert W. Floyd, Vaughan Pratt, Ron Rivest, Robert Tarjan）</footer>
</div>

## 为什么从 SELECT 开始

RANDOMIZED-SELECT 期望线性，但最坏仍是 $O(n^2)$。1963 年，五位计算机科学家（Blum、Floyd、Pratt、Rivest、Tarjan）发明了一个**最坏情况也是 $O(n)$** 的选择算法——它不靠随机，靠一个巧妙的确定性保证：**每次划分都至少淘汰固定比例的元素**。<span class="marginnote">这个算法的核心是「中位数的中位数（median of medians）」：把元素分成 5 个一组，取各组中位数，再递归取中位数的中位数作为主元。它保证主元「不太小也不太大」——两侧各有至少 $3n/10$ 个元素，于是每次递归规模缩小固定比例，递归式解出线性。</span>

这一课的看点是：一个看似绕弯的「取中位数的中位数」步骤，如何换来确定性的线性上界。

## 1 算法：五步结构

```
SELECT(A, p, r, i)
  if p == r  return A[p]
  1. 把 n 个元素分成 ceil(n/5) 组，每组 ≤5 个（最后一组可能不足 5）
  2. 对每组排序（至多 5 个元素），取各组中位数，构成集合 M
  3. x = SELECT(M, 1, |M|, ceil(|M|/2))   // 递归：M 的中位数
  4. 用 x 作主元划分 A[p..r]，得到位置 q（x 是第 k 小）
  5. if i == k  return x
     else if i < k  return SELECT(A, p, q-1, i)
     else           return SELECT(A, q+1, r, i-k)
```

步骤 1–3 是「找主元」的强化版：不随机选，而是先分组取中位数、再递归取中位数的中位数。步骤 4–5 与 RANDOMIZED-SELECT 相同。<span class="marginnote">为什么组大小取 5？因为 5 是最小的奇数，使「每组中位数」的分组有意义，且让「大于主元的元素至少占 $3n/10$」的比例达到最优。取 3 也行但比例降为 $n/3$ 级、常数变大；取 7 或更大常数也更差。5 是工程与理论的甜蜜点。</span>

## 2 关键性质：主元两侧各有多少元素

设 $x$ 是中位数的中位数。要证明「$x$ 不是太小也不是太大」，先看**至少有 $3n/10$ 个元素 $> x$**：

- 把 $\lceil n/5 \rceil$ 组分成「中位数 $> x$ 的组」与「中位数 $< x$ 的组」。
- 因 $x$ 是「中位数集合 $M$」的中位数，$M$ 中至少一半元素 $> x$（即 $\lceil |M|/2\rceil$ 组的中位数 $> x$）。
- 每组 5 个元素里，中位数 $> x$ 意味着该组**至少 3 个元素 $> x$**（中位数自己、右两个）。

因此大于 $x$ 的元素至少 $\ge 3 \cdot \lfloor \lceil n/5\rceil / 2 \rfloor \ge 3n/10$。对称地，小于 $x$ 的元素也至少 $3n/10$。<span class="marginnote">这个「$3n/10$」是整场证明的支点：它保证无论目标在左在右，递归子问题规模都不超过 $7n/10$。回顾：随机化版本的子问题最坏是 $n-1$（依赖运气），这里最坏是 $7n/10$（结构性保证）——这就是「最坏线性」的来源。</span>

## 3 公式解析：递归式 $T(n) \le T(n/5) + T(7n/10) + O(n)$

SELECT 的时间由三部分组成：递归取中位数的中位数 $T(\lceil n/5\rceil)$、划分 $O(n)$、递归处理目标所在的一侧 $T(\le 7n/10)$：

$$T(n) \le T\left(\frac{n}{5}\right) + T\left(\frac{7n}{10}\right) + O(n)$$

- **第一步，$T(n/5)$**：步骤 3 对 $n/5$ 个中位数递归——这是「主元选择」本身的开销。
- **第二步，$T(7n/10)$**：步骤 5 只递归一侧，且该侧最多 $7n/10$ 个元素（因至少 $3n/10$ 被淘汰）。
- **第三步，相加**：$n/5 + 7n/10 = 9n/10 < n$——**每层的工作量严格收缩**，于是 $T(n) = cn + c(9n/10) + c(81n/100) + \cdots = cn \cdot \frac{1}{1-9/10} = 10cn = O(n)$。

**要点**：递归式能解出线性，是因为**两臂之和 $< 1$**。对照主定理：$T(n) = T(an) + T(bn) + cn$ 当 $a+b<1$ 时解为 $O(n)$；当 $a+b=1$ 时每层等重、解为 $O(n\log n)$。SELECT 的 $1/5 + 7/10 = 9/10$ 恰好落在 $<1$ 一侧。<span class="marginnote">这里不需要主定理——用「几何级数求和」直接解：$T(n) = cn(1 + 9/10 + (9/10)^2 + \cdots) = cn \cdot 10$。常数 10 说明 SELECT 虽线性，常数不小（$10cn$），实际常比 RANDOMIZED-SELECT 慢——这是「确定性保证」的代价。</span>

## 4 为什么 SELECT 不常出现在工程里

SELECT 理论上最坏线性，但工程上**几乎不用它**，原因是常数太大：步骤 1–3 的「分组、排序、递归中位数」每一步都是额外开销，常数因子高达 $10$ 以上。RANDOMIZED-SELECT 的期望线性常数更小、实现更简单，且随机化已足以应对实际输入。<span class="marginnote">SELECT 的价值更多是<strong>理论里程碑</strong>：它证明「最坏线性选择」在原理上可行，并示范了「确定性主元选择」这一技巧。这类技巧后来在 introselect（`std::nth_element` 的混合策略）、对抗性鲁棒算法里仍有影子。</span>

**辨析｜易错点：** 步骤 1 的「每组 5 个」与步骤 3 的「递归取中位数」缺一不可。若跳过步骤 3 直接取「各中位数的随便一个」，就没有 $3n/10$ 的保证，递归式退化到 $T(n) = T(n-1) + O(n) = O(n^2)$。**「中位数的中位数」这个看似多余的递归，正是保证「两臂之和 $<1$」的那一击**。

## 5 小结

- **SELECT**：五步结构 = 分组(5) → 各组排序取中位数 → 递归取中位数的中位数作主元 → 划分 → 递归单侧。
- **核心保证**：主元两侧各至少 $3n/10$ 个元素，递归子问题 $\le 7n/10$。
- **递归式** $T(n) \le T(n/5) + T(7n/10) + O(n)$，两臂之和 $9/10 < 1$，解得 $T(n) = O(n)$。
- 几何级数求和给出线性；常数约 $10c$，故工程上常被 RANDOMIZED-SELECT 取代。
- 它是「确定性主元选择」的理论典范，证明了最坏线性选择的可能性。
