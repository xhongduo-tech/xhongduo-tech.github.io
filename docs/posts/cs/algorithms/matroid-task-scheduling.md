# 拟阵视角下的任务调度问题：带截止时间单位任务的调度

<div class="epigraph">

## 为什么从任务调度开始

单处理器上有一批任务：每个任务耗时恰好 1 个单位时间，各有截止时间 $d_i$ 与逾期罚款 $w_i$。每个时刻只能做一个任务，**求一个执行顺序使总罚款最小**。<span class="marginnote">这个问题的古典形式（Moore-Hodgson 的变体）早就有贪心解，但 CLRS 把它放进拟阵框架——先证明「准时任务集」构成拟阵，再让拟阵贪心定理直接给出算法。这是「用抽象框架包具体问题」的教科书演示。</span>

这一课展示完整的「拟阵化」路径：把「最小化罚款」翻转成「最大化省下的罚款」，识别独立集，验证拟阵公理，最后跑拟阵贪心。

## 1 问题变形：从「罚最少」到「赚最多」

设任务集 $S$，任务 $i$ 有截止时间 $d_i$（正整数）与罚款 $w_i$。总罚款 = 所有逾期任务罚款之和。

**关键翻转**：总罚款 = $\sum w_i - \sum_{\text{准时}} w_i$。最小化总罚款 ⟺ **最大化准时任务的罚款和**。于是问题变成：选一个「可被准时安排」的任务子集 $A$，使 $\sum_{i \in A} w_i$ 最大。

**「可准时安排」**的定义：存在一个调度，使 $A$ 中每个任务都在其截止时间前完成。由于任务都是单位时间，$A$ 可被准时安排当且仅当……（下一节给出判定）。<span class="marginnote">把「最小化」翻成「最大化」是组合优化里的常用手法——把约束侧的「惩罚」移到目标侧变「收益」。这个翻转让问题落入「最大权独立集」的拟阵模板，贪心定理直接可用。</span>

## 2 独立集与拟阵验证

定义**独立集** = 可被准时安排的任务子集。先给判定条件：设 $A$ 中任务按截止时间排序为 $d_{i_1} \le d_{i_2} \le \cdots$，$A$ 可准时安排当且仅当对每个 $k$

$$\#\{i \in A : d_i \le k\} \le k, \qquad \forall k$$

即「截止时间 ≤ $k$ 的任务数不超过 $k$」——这是著名的 **Jackson 规则**（按截止时间排序就是最优调度）。<span class="marginnote">直觉：单位任务只能在离散时刻 1,2,3,… 执行；截止时间 ≤ $k$ 的任务必须赶在时刻 $k$ 前全部完成，一共只有 $k$ 个时刻可用。条件「数量 ≤ 可用的时刻数」是必要且充分的——按截止时间排序后逐个填入即可验证。</span>

**验证拟阵公理**：

- (M1) 空集显然可准时安排。
- (M2) 遗传性：$A$ 的子集满足更少的约束，仍可准时安排。
- (M3) 交换性：若 $A, B$ 都可准时安排且 $|A|<|B|$，需要证明能从 $B \setminus A$ 找一个任务加入 $A$ 而不破坏条件。CLRS 用「计数论证」：考察所有 $k$，$B$ 在「截止 ≤ $k$」的任务数……利用两个集合各自的约束，可证明存在这样的元素（若对任意 $x \in B\setminus A$ 加入 $A$ 都破坏条件，则 $A$ 的「容量」已满，推出 $|A| \ge |B|$，矛盾）。

因此「可准时安排子集」构成**拟阵**。<span class="marginnote">交换性的证明是这一课最绕的地方：它需要「若 $A$ 无法容纳 $B$ 的任何新元素，则 $A$ 的某些约束已饱和，从而 $|A| \ge |B|$」的计数反证。这个论证把「什么时候还能加」翻译成「容量是否已满」，是拟阵交换性证明的典型形态。</span>

## 3 算法：拟阵贪心

既然结构是拟阵，直接套拟阵贪心定理：**按罚款 $w_i$ 降序扫描任务，能准时安排就加入集合**。

```
SCHEDULE(S)
  sort tasks by w descending
  A = empty set
  for each task i in descending w order
    if A ∪ {i} is feasible (准时可安排)
      A = A ∪ {i}
  // 最终调度：A 内按截止时间排序执行；A 外逾期不执行（付罚款）
  return A
```

**正确性**：由拟阵贪心定理，$A$ 是最大权独立集——即「准时任务罚款和最大」，等价于「总罚款最小」。「能准时安排」的判定用第 2 节的 Jackson 条件（维护一个按截止时间排序的已选集合，插入时检查）。

**复杂度**：排序 $O(n\log n)$；每步可行性检查若用朴素扫描 $O(n)$，总 $O(n^2)$；用「并查集分配时刻」技巧可降到 $O(n \alpha(n))$。<span class="marginnote">实现层面的常见做法：已选任务存一个「按截止时间维护的时间表」，插入新任务时若时间冲突，就把「已选中最晚截止且罚款最小」的挤出去（或拒绝）。很多竞赛解法用「优先队列 + 按截止时间分批」，本质就是拟阵贪心的工程化。</span>

## 4 公式解析：Jackson 条件为什么充分必要

设 $A$ 的任务按截止时间升序为 $a_1, a_2, \dots$。**充分性**：若条件成立，按截止时间升序执行，第 $k$ 个任务的完成时刻恰为 $k$，而它的截止时间满足「$A$ 中截止 ≤ $d$ 的数量 ≤ $d$」——特别地第 $k$ 个任务的截止时间 ≥ $k$，故按时完成。**必要性**：若存在 $k$ 使「截止 ≤ $k$ 的任务数 $> k$」，这 $k$ 个时刻最多完成 $k$ 个任务，必有一个逾期——条件不满足则不可准时。

$$\underbrace{\#\{i \in A: d_i \le k\} \le k}_{\text{任何前缀时刻窗口}} \;\Longleftrightarrow\; A \text{ 可准时安排}$$

- **第一步，必要性**：$k$ 个时刻装不下 $> k$ 个截止在 $k$ 前的任务——鸽巢原理。
- **第二步，充分性**：按截止时间排序调度，第 $k$ 个任务完成于时刻 $k$，且其截止 ≥ $k$。
- **第三步，判定应用**：贪心加入任务 $i$ 时，只需检查「所有 $k \ge d_i$ 是否仍 ≤」——用区间计数数据结构高效维护。

**要点**：Jackson 条件把「存在一个调度」的可行性压缩成「一组可逐一检查的计数不等式」——这是「调度可行性判定」里最实用的定理之一。<span class="marginnote">这个条件在「最小化最大延迟」等调度变体里也会出现。注意它假设所有任务耗时都是 1——若任务耗时不同，条件变成「排序后前缀完成时间 ≤ 截止」的推广形式，但仍按最短处理时间或截止时间排序的策略。</span>

## 5 小结

- **任务调度问题**：单位时间任务 + 截止时间 + 罚款，求最小总罚款的调度。
- **翻转**：最小化罚款 ⟺ 最大化「准时任务的罚款和」。
- **独立集** = 可准时安排子集；Jackson 条件 $\#\{i \in A: d_i \le k\} \le k$ 判定可行性。
- **拟阵验证**：M1 空集、M2 遗传、M3 交换（计数反证）——因此是拟阵。
- **算法**：按罚款降序贪心「能加就加」，拟阵贪心定理保证最优；$O(n\log n)$ 排序主导。
