## 为什么从 Push-Relabel 开始

Ford-Fulkerson 家族都是「**增广路**」思路：找到整条 $s \to t$ 路径再统一增广。Push-Relabel 彻底换了一个思路：**不再找路径，而是让流「从源点一点一点推出去」**，允许中间节点**暂时超量**（积压），再通过局部操作慢慢推向汇点。<span class="marginnote">这个「局部推送」的视角在理论上带来更紧的复杂度（$O(V^2E)$，甚至 $O(V^3)$），在实践上也常优于增广路算法。它也是理解「预流（preflow）」概念的唯一入口——中间节点可以暂时「进大于出」，这在增广路框架里是不允许的。</span>

这一课建立 Push-Relabel 的核心概念：预流、溢出顶点、推送与重贴标签两个局部操作。

## 1 预流：放宽守恒约束

**预流（preflow）** 放宽流量守恒：除源点外，任何顶点的**净流入可以 ≥ 0**（可以「积压」流量），但不能有净流出超过进来的量。每个顶点 $u$ 的**溢出量（excess）**

$$e(u) = \sum_{v} f(v, u) - \sum_{v} f(u, v)$$

$e(u) > 0$ 表示 $u$ 有积压的流。**合法的预流**要求 $e(u) \ge 0$（$u \ne s$），汇点除外（$e(t)$ 可以任意）。<span class="marginnote">关键差别：合法<strong>流</strong>要求所有中间节点 $e(u) = 0$（完全守恒）；合法<strong>预流</strong>只要求 $e(u) \ge 0$（可积压）。Push-Relabel 从「把源点所有容量灌出去」的预流开始，不断把积压推走，最终得到一个 $e(u)=0$（除源汇）的合法最大流。</span>

**高度标签（height）**：每个顶点 $u$ 有一个非负整数 $h(u)$，直觉是「水往低处流」的海拔。初始 $h(s) = |V|$，其余 0。**合法条件**：对残量边 $(u,v)$，$h(u) \le h(v) + 1$。

## 2 两个局部操作

**推送（PUSH）**：若 $u$ 有溢出（$e(u) > 0$），且存在残量边 $(u,v)$ 使 $h(u) = h(v) + 1$（「u 比 v 高一格，水能流下去」），则沿 $(u,v)$ 推送 $\Delta = \min(e(u), c_f(u,v))$ 的流。

**重贴标签（RELABEL）**：若 $u$ 有溢出，但**没有**任何残量边 $(u,v)$ 满足 $h(u) = h(v)+1$（水推不动），则把 $h(u)$ 提高到「所有残量邻接点最小高度 + 1」：

$$h(u) = 1 + \min_{(u,v) \in E_f} h(v)$$

<span class="marginnote">两个操作的分工：能推就推（水往低处流），推不动就「抬高海拔」（重贴标签）直到能推。高度标签保证流「只会从高往低」，且每次 relabel 严格抬高——高度不超过 $2V-1$，这给出算法的复杂度上界。这个「能推就推、不行就抬」的模式，与物理里「连通器 + 抬高液面」的直觉相通。</span>

## 3 算法框架

```
GENERIC-PUSH-RELABEL(G, s, t)
  initialize preflow f:  s 的所有出边灌满，其余 0
  initialize heights:  h(s) = |V|, h(u) = 0 otherwise
  while there exists an overflowing vertex u (u ≠ s, t)
    if there is a pushable edge (u, v)   // h(u) = h(v)+1
      PUSH(u, v)
    else
      RELABEL(u)
  return f
```

**终止**：所有非源汇顶点溢出为 0 → 预流变成合法流。**正确性**：结束时无溢出顶点，且无「可改进」结构；由高度标签与最小割的论证，$f$ 是最大流。<span class="marginnote">算法正确性的两个支柱：<strong>终止性</strong>（高度有限、单调上升，relabel 至多 $2V-1$ 次每顶点）与<strong>最优性</strong>（结束时 $e(u)=0$ 全部清空，且由高度条件可证「割 $(S,T)$ 满流」——$|f| = c(S,T)$，由最大流最小割定理 $f$ 最优）。核心直觉：算法把「溢出」一步步推向汇点或推回源点。</span>

## 4 公式解析：复杂度 $O(V^2E)$ 从哪来

通用版的复杂度由三个计数构成：

$$T = O(VE) \cdot O(1) + O(V^2E) \cdot O(1) + O(V) \cdot O(V) = O(V^2E)$$

- **第一步，relabel 次数**：每顶点高度 ≤ $2V-1$，relabel 使高度严格上升，总 relabel ≤ $O(V^2)$。每次 relabel 扫描邻接边 $O(E)$，共 $O(V^2 E)$（可进一步摊到 $O(V^2)$，这里取上界）。
- **第二步，push 次数**：可分「饱和 push」（把边残量清 0）与「非饱和 push」。饱和 push 每边 ≤ $O(V)$ 次（高度单调），共 $O(VE)$；非饱和 push ≤ $O(V^2E)$（需势函数论证）。
- **第三步，相加**：总复杂度 $O(V^2E)$。用更聪明的调度（最高标号优先）可降到 $O(V^3)$。

**要点**：Push-Relabel 的复杂度上界来自「高度单调 + 计数饱和事件」——和 Edmonds-Karp 的「最短距离单调」是同一类论证。<span class="marginnote">工程上 Push-Relabel 常配<strong>最高标号优先</strong>调度（highest-label）：总是处理高度最高的溢出顶点，让流「尽快够到汇点」。这个实现达到 $O(V^3)$，且常数小、对大规模网络表现优异——是许多最大流库（如 HiPR）的默认引擎。</span>

**辨析｜易错点：** 初始化时**只灌源点的出边**，不是「每个顶点都灌」。且 $h(s)=|V|$ 让源点能推流向任何顶点（$h(s) \ge h(v)+1$ 恒成立）。若把高度初始化搞错，推送方向会乱。**「预流」与「流」的差别（可否积压）是理解本算法一切设计的起点。**

## 5 小结

- **预流**：放宽守恒，中间顶点可积压（$e(u) \ge 0$）；合法流是 $e=0$ 的特例。
- **高度标签**：水往低处流；合法条件 $h(u) \le h(v)+1$。
- **PUSH**：$h(u)=h(v)+1$ 且有残量时推送；**RELABEL**：推不动就抬高到「最小邻居高度 +1」。
- 通用版 $O(V^2E)$；最高标号优先调度可到 $O(V^3)$。
- 正确性 = 终止性（高度有限）+ 最优性（满流割）；与增广路思想完全不同的另一流派。
