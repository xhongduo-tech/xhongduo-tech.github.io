## 为什么从最长递增子序列开始

给定序列，找最长的严格递增子序列（元素按原顺序、不必连续）。它把钢条切割的「一维状态」与 LCS 的「子序列」概念结合，是经典中的经典。<span class="marginnote">LIS 的妙处在于它有两种解法：朴素的 $O(n^2)$ DP 直观易懂；而 $O(n\log n)$ 的「贪心 + 二分」优化展示了「用辅助数组维护下界」的设计模式。同一个问题，两种思路，是「先求正确、再求高效」的教学范例。</span>

它还有丰富的应用：最长不下降子序列的变体用于导弹拦截、骨架提取、以及「最小插入次数使序列有序」等经典题。

## 1 朴素 DP：以「结尾元素」为状态

设 $dp[i]$ = **以 $A[i]$ 结尾**的最长递增子序列长度。对每个 $i$，往前找所有 $j < i$ 且 $A[j] < A[i]$ 的位置，接在它们后面：

$$dp[i] = 1 + \max_{\substack{j < i \\ A[j] < A[i]}} dp[j], \qquad dp[i] \ge 1$$

答案 $\text{LIS} = \max_i dp[i]$。复杂度 $O(n^2)$：$n$ 个状态，每状态扫描 $O(n)$ 个前驱。

**状态选择「以 $i$ 结尾」而非「前 $i$ 个」**：因为「递增」要求知道上一个元素是谁——只有「以某个具体元素结尾」才能判断能否续接。<span class="marginnote">这是「以 i 结尾」状态的典型动机：转移条件（$A[j] < A[i]$）依赖上一个元素的值。若用「前 $i$ 个的 LIS 长度」做状态，无法知道最后一个元素多大、能否接新元素——状态信息不足。记住这条经验：<strong>转移需要知道「结尾是谁」，状态就以「结尾」定义</strong>。</span>

**辨析｜易错点：** $dp[i]$ 不是「前 $i$ 个元素的 LIS」。前者强制以 $A[i]$ 结尾（可能比全局 LIS 短），后者是全局长度。**必须取 $\max_i dp[i]$ 而非 $dp[n]$**——很多初学者误以为答案是最后一个状态。

## 2 贪心优化：维护「最小结尾」

$O(n^2)$ 的浪费在于：对每个 $i$ 都要重扫所有前驱。优化思路是**维护一个数组 $t[k]$ = 长度为 $k$ 的递增子序列的「最小可能结尾值」**：

$t$ 是**严格递增**的数组（长度越长，结尾至少越大）。
扫描 $A[i]$ 时，在 $t$ 里用**二分查找**找到第一个 $\ge A[i]$ 的位置 $pos$，把 $t[pos]$ 更新为 $A[i]$（「用更小的结尾替换，未来更容易续长」）。
$t$ 的长度就是 LIS 长度。

```text
t = []                          // t[k] = 长度为 k 的子序列的最小结尾
for x in A:
    pos = 第一个 ≥ x 的位置      // 二分查找（严格递增用 lower_bound）
    若 pos 存在: t[pos] = x     // 用更小的结尾替换，未来更容易续长
    否则: 把 x 追加到 t 末尾     // 形成更长的 LIS
return |t|                      // LIS 长度
```

每步二分 $O(\log n)$，共 $n$ 步，总时间 $O(n\log n)$。<span class="marginnote">直觉：$t[k]$ 是「长度为 $k$ 的子序列能有多小的结尾」。用小结尾替换大结尾不改变长度，但给未来留出更大余量——这本质是「贪心」在「子序列结尾」上的应用。注意 $t$ 数组本身<strong>不是</strong>一个 LIS（它是各长度的最优结尾），只有长度有意义。</span>

## 3 公式解析：为什么 $O(n^2)$ 能降到 $O(n\log n)$

朴素 DP：$T(n) = \sum_{i=1}^{n} O(i) = \Theta(n^2)$；优化后每步二分：

$$T(n) = \sum_{i=1}^{n} O(\log n) = O(n\log n)$$

- **第一步，朴素瓶颈**：每个 $dp[i]$ 要比较 $i$ 个前驱，平方级。
- **第二步，优化关键**：把「扫描前驱」换成「在单调数组 $t$ 里二分」——$t$ 的单调性（长度与结尾值同步增长）让二分可行。
- **第三步，正确性**：替换 $t[pos]$ 不影响长度与已建长度结构——贪心选择性质保证「越小的结尾越不劣」，故 $t$ 的长度即 LIS 长度。

**要点**：$O(n^2) \to O(n\log n)$ 的收益来自「**把线性扫描换成二分**」——前提是维护一个单调的辅助数组。这类「单调辅助 + 二分」技巧在 LIS、接雨水变体、以及后面图算法（Dijkstra 的优先队列）里反复出现。<span class="marginnote">若要输出 LIS 本身（而非长度），需额外记录「每个元素在 $t$ 中放置时，它接在哪个前驱之后」——用 $t$ 数组回溯。这与所有「只要长度 vs 要方案」的 DP 取舍一致；工程实现里 $t$ 数组只存下标、配合原数组恢复序列。</span>

## 4 变体与边界

**严格递增 vs 非递减**：严格递增要求「$A[j] < A[i]$」，二分用 $> x$（第一个 $\ge x$）；非递减允许相等，二分用 $\ge$（第一个 $> x$）。<span class="marginnote">一行二分的差别决定了「能否接相等元素」。题目「最长非递减子序列」（如导弹拦截的『不上升子序列』镜像）就是把这个 $\ge$ 改成 $>$ 的变体。</span>
- **还原 LIS**：存前驱（predecessor）链回溯；注意 $t$ 里被替换的值不影响已记录的链。
- **应用**：信封套娃（二维 LIS）、词链、以及「最少删多少个数使序列递增」（$n - \text{LIS}$）。

**辨析｜易错点：** `lower_bound` 与 `upper_bound` 的选择要跟上「严格/非严格」对齐。若题目是严格递增却用了 `upper_bound`，相等元素会被允许「续接」，得到非递减结果——**长度会偏大**。考试时先明确「递增」是否含相等。

## 5 小结

- **LIS 朴素 DP**：$dp[i]$ = 以 $A[i]$ 结尾的 LIS 长度，$O(n^2)$。
- **状态动机**：转移需要「结尾是谁」，故用「以 $i$ 结尾」而非「前 $i$ 个」。
- **$O(n\log n)$ 优化**：维护单调数组 $t[k]$ = 长度 $k$ 的最小结尾，二分更新。
- 严格/非递增对应 `lower_bound`/`upper_bound`；$t$ 的长度才是答案，$t$ 本身不是 LIS。
- 变体：还原 LIS 用前驱（predecessor）回溯；信封套娃、最少删除数等应用。
