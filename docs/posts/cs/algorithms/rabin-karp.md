# Rabin-Karp 算法：滚动哈希（Rolling Hash）

<div class="epigraph">
<p>把「两段字符串是否相等」翻译成「两个数是否相等」——哈希让比较从线性塌缩成常数。</p>

## 为什么从 Rabin-Karp 开始

朴素算法在每个位移都逐字符比对，$O(m)$；**Rabin-Karp** 把「字符串比较」换成「哈希值比较」，期望 $O(n+m)$。<span class="marginnote">核心思想：把长度为 $m$ 的子串映射成一个整数哈希（像 $d$ 进制数），比较哈希值代替比较字符。配合<strong>滚动哈希（rolling hash）</strong>——从 $T[s+1..s+m]$ 移到 $T[s+2..s+m+1]$ 时，哈希只需 $O(1)$ 更新，不必重算。这是哈希思想在字符串上的第一次大规模应用。</span>

这一课讲哈希映射、滚动更新的公式、以及「哈希碰撞」如何被处理（朴素验证兜底）。

## 1 哈希映射：子串即数字

设字符集大小为 $d$（如 ASCII 的 $d=256$），把子串 $T[s+1..s+m]$ 看成一个 $d$ 进制整数：

$$t_s = \left(T[s+1] \cdot d^{m-1} + T[s+2] \cdot d^{m-2} + \cdots + T[s+m]\right) \bmod q$$

$q$ 是取模素数。模式 $P$ 同理算 $p$。若 $t_s = p$，说明子串与模式**可能**相等（有碰撞风险）；再逐字符确认。<span class="marginnote">为什么取模 $q$？因为不取模的数太大（$d^m$ 天文数字）。取模后哈希值在 $[0, q)$ 内，滚动更新可精确计算。$q$ 取素数是经验之谈：素数模让哈希分布更均匀，碰撞更少。</span>

## 2 滚动哈希：$O(1)$ 平移

关键技巧——从 $t_s$ 更新到 $t_{s+1}$：

$$t_{s+1} = \left(d \cdot (t_s - T[s+1] \cdot d^{m-1}) + T[s+m+1]\right) \bmod q$$

即「去掉最左字符的贡献、整体左移一位、加上最右新字符」。其中最高位的权值 `h = d^{m-1} \bmod q` 可预处理一次。

**正确性**：$t_{s+1}$ 精确等于「新子串」的哈希——因为 $d$ 进制数的移位、加减在模 $q$ 下线性成立。每个新哈希 $O(1)$，总预处理 $O(n-m+1)$。

```
RABIN-KARP-MATCHER(T, P, d, q)
1  n = T.length
2  m = P.length
3  h = d^(m−1) mod q                // 最高位权值，预处理一次
4  p = 0
5  t₀ = 0
6  for i = 1 to m                   // 预处理：模式与文本首子串的哈希
7      p = (d·p + P[i]) mod q
8      t₀ = (d·t₀ + T[i]) mod q
9  for s = 0 to n−m                 // 滑动窗口
10     if p == tₛ                   // 哈希相等只是候选
11         if P[1..m] == T[s+1..s+m]    // 朴素验证兜底
12             print "Pattern occurs with shift" s
13     if s < n−m
14         t_{s+1} = (d·(tₛ − T[s+1]·h) + T[s+m+1]) mod q   // 滚动更新
```

<span class="marginnote">「哈希相等只是候选，朴素验证兜底」是 Rabin-Karp 的灵魂：哈希快但可能碰撞，所以哈希相等时才做真实的逐字符比较。哈希保证「大部分位移被 $O(1)$ 排除」，只有疑似匹配处才花 $O(m)$ 验证——期望时间因此接近线性。</span>

## 3 公式解析：滚动更新的正确性

证明 $t_{s+1}$ 是「新子串」的精确哈希。设旧子串 $S = T[s+1..s+m]$，新子串 $S' = T[s+2..s+m+1]$：

$$t_s = \left(\sum_{i=1}^{m} T[s+i]\, d^{m-i}\right) \bmod q$$

$$t_{s+1} = \left(d \cdot (t_s - T[s+1]\,d^{m-1}) + T[s+m+1]\right) \bmod q$$

- **第一步，去掉最左**：$t_s - T[s+1]d^{m-1}$ 删掉最高位贡献，剩下「$T[s+2..s+m]$ 的 $d$ 进制值」。
- **第二步，左移一位**：乘以 $d$，等价于「低位补一个 0」，即把中间 $m-1$ 个字符整体左移一格。
- **第三步，补最右**：加上 $T[s+m+1]$，填上新的最低位——恰好是 $S'$ 的 $d$ 进制值。

**要点**：滚动哈希的全部秘密是「$d$ 进制数的移位、加减在模 $q$ 下仍精确」。乘 $d$ 是左移、减高位是删字符、加低位是加字符——三个 $O(1)$ 操作完成一次平移。<span class="marginnote">$t_s - T[s+1]h$ 可能为负——实现时注意加 $q$ 再取模（模运算的负数处理）。这个「先减后乘再加」的细节是 Rabin-Karp 实现的常见 bug 来源。</span>

## 4 复杂度：期望与最坏

**期望时间**：$O(n+m)$——预处理 $O(m)$，滑动 $O(n-m+1)$ 次哈希比较（各 $O(1)$），碰撞验证的期望代价小。
**最坏时间**：$O((n-m+1)m)$——当哈希频繁碰撞（如所有子串哈希都相同，或构造「同哈希不同串」的坏输入），每个位移都要朴素验证。

**辨析｜易错点：** 最坏情形的存在使 Rabin-Karp **不是**严格的线性算法——它是「期望线性」。用**随机素数** $q$（而非固定素数）可以让「坏输入导致碰撞」的概率对任何输入都小——这是「随机化哈希」的思想：把碰撞概率摊到随机选择上，而不是赌输入不坏。<span class="marginnote">随机化版本的妙处：对手不知道我们用哪个 $q$，无法针对性地构造「全部碰撞」的输入——碰撞概率被压到 $O(1/q)$ 量级。这再次体现了「随机化消灭对手优势」的范式（对比随机化快排）。工程里 Rabin-Karp 常用于多模式匹配与重复检测。</span>

## 5 应用：不止单模式匹配

**多模式匹配**：多个模式同时查——对每个模式算哈希，一次滑动同时比对（朴素多模式是「每模式各跑一遍」）。
**抄袭/重复检测**：把文本切成固定长度块算哈希，找重复块。
**数据去重（chunking）**：滑动窗口哈希找「内容定义的断点」。
**字符串指纹**：Git 的内容寻址、数据库的大字段比对。<span class="marginnote">Rabin-Karp 的「滚动哈希」思想已远超字符串匹配：它是一切「滑动窗口 + 内容指纹」技术的祖先——从滚存去重、相似文档检测到安全领域的「模糊哈希」。学会滚动更新，等于掌握了一类「流式哈希」原语。</span>

## 6 小结

- **Rabin-Karp**：子串哈希 = $d$ 进制数取模；比较哈希代替逐字符比较。
- **滚动更新**：$t_{s+1} = (d(t_s - T[s+1]h) + T[s+m+1]) \bmod q$，$O(1)$ 平移。
- 哈希相等时**朴素验证兜底**处理碰撞；期望 $O(n+m)$、最坏 $O((n-m+1)m)$。
- 随机素数 $q$ 让碰撞概率对任意输入都小（随机化哈希）。
- 应用：多模式匹配、重复检测、数据去重、字符串指纹。
