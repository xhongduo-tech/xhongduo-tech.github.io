## 为什么从外部归并排序开始

排序是「数据太大」的经典场景：内存装不下，普通排序（快排/归并）直接崩溃。**外部归并排序（external merge sort）**分两阶段——**生成有序段**与**多路归并**——把「排不下」变成「分块处理 + 归并」。<span class="marginnote">外部排序是数据库与大数据系统的基石：SQL 的 `ORDER BY`、MapReduce 的 shuffle、Spark 的 sort 全都用外部归并排序。它的核心是两个「少 I/O」技巧：分块时每块尽量大（减少段数）、归并时多路并行（减少轮数）。这一课把 I/O 复杂度算给你看。</span>

这一课讲两阶段算法、I/O 复杂度的推导、以及「多路」为什么比「两路」好。

## 1 阶段一：生成有序段（run）

**目标**：把 $N$ 个元素切成若干个「能装进内存」的段，每段内部排好序、写回磁盘。

```text
// 阶段一：生成有序段（run）
while 磁盘上还有未读元素:
    读入一个能装满内存的块（约 M 个元素）
    在内存里排序（快排 / 归并）
    把有序块作为一段 run 写回磁盘
```

**段数**：$N/M$ 个 run（每个 run 约 $M$ 个元素）。I/O 代价：每段「读一次 + 写一次」，共 $2 \times (N/B)$ 次块 I/O。<span class="marginnote">「run 尽量大」直接减少归并阶段的工作：run 大小 = 内存大小 $M$ 时段数 = $N/M$。若用「替换选择（replacement selection）」技巧，run 平均可达 $2M$（利用堆的「提前输出」）——段数减半，归并更快。这是「外部算法靠小技巧省大 I/O」的例子。</span>

## 2 阶段二：多路归并

**目标**：把所有 run 归并成一个有序大文件。**多路归并（k-way merge）**：一次从 $k$ 个 run 各取一块进内存，用大小为 $k$ 的**败者树/最小堆**选出最小者输出。

```text
// 阶段二：多路归并
建大小为 k 的最小堆，从 k 个 run 各取一个元素入堆
while 堆非空:
    弹出堆顶（当前最小元素）写入输出文件
    从弹出元素所属的 run 读入下一个元素入堆   // 维持 k 个候选
```

若一次归并全部 $N/M$ 个 run 装不下内存，就分**多轮**：每轮把 $k$ 个 run 并成 1 个，$\log_k(N/M)$ 轮。

**轮数**：$\lceil \log_k(N/M) \rceil$。每轮「读一遍 + 写一遍」=$2N/B$ 次 I/O。

$$I_{\text{总}} = 2\frac{N}{B} + 2\frac{N}{B}\log_k\frac{N}{M} = O\left(\frac{N}{B}\log_k\frac{N}{M}\right)$$

<span class="marginnote">「多路」的价值在轮数：$k = 2$ 时 $\log_2(N/M)$ 轮；$k = 100$ 时 $\log_{100}(N/M)$ 轮——轮数大减。但 $k$ 受内存限制（$k$ 个 run 各要一块缓冲），所以「$k$ 与缓冲块大小」权衡：$k$ 大则每块缓冲小。工程上 $k$ 取「内存允许的最大值」。</span>

## 3 公式解析：I/O 复杂度 $O(\frac{N}{B}\log_k\frac{N}{M})$

**阶段一**：每块读一次、写一次——$2N/B$ 次 I/O。

**阶段二**：每轮把全部数据读一遍、写一遍——$2N/B$ 每轮，共 $\log_k(N/M)$ 轮：

$$I_{\text{阶段二}} = 2\frac{N}{B} \cdot \log_k \frac{N}{M}$$

- **第一步，读与写**：每轮归并把 $N$ 个元素（$N/B$ 块）读入、再写出——$2N/B$ 次 I/O。
- **第二步，轮数**：每轮把 $k$ 个 run 并成 1 个，run 数从 $N/M$ 降到 1，需要 $\log_k(N/M)$ 轮。
- **第三步，总 I/O**：阶段一 $2N/B$ + 阶段二 $2(N/B)\log_k(N/M)$——主导项是归并轮数。

**要点**：**轮数（$\log_k$ 项）决定外部归并的 I/O**。$k$ 越大、内存 $M$ 越大，轮数越少——这是外部排序调优的两个旋钮。<span class="marginnote">对比内存排序的 $O(N\log N)$：外部排序的 I/O 是「线性 × 轮数」，没有 $N\log N$ 那种元素级开销——因为内存里的排序（阶段一内、归并堆内）不计 I/O。外部排序的时间 ≈「I/O 时间（主导）+ 内存 CPU（几乎免费）」。</span>

**辨析｜易错点：** 归并轮数算的是「run 数变化」：从 $N/M$ 个 run 每轮除以 $k$，直到 1——$\log_k(N/M)$ 轮。**别把「元素数 $N$」直接套进 $\log$**——run 数才是归并的输入规模。且阶段一、阶段二的「读写各一遍」都要各算一次（读一次 + 写一次 = 2 次 I/O 每块）。

## 4 外部排序 vs 内存排序

| 维度 | 内存排序 | 外部归并排序 |
| --- | --- | --- |
| 假设 | 数据全在内存 | 数据在外存、内存是缓存 |
| 度量 | CPU 时间 | **I/O 次数** |
| 复杂度 | $O(N\log N)$ | $O(\frac{N}{B}\log_k\frac{N}{M})$ |
| 关键技巧 | 比较/分治 | 分块 + 多路归并 |

内存排序分析 CPU、外部排序分析 I/O——**同一个「排序」问题，两个模型给出两个量纲的答案**。<span class="marginnote">工程里的常见选择：数据能进内存（如 $N < M/2$）就用快排；进不了就用外部归并。数据库的 `查询优化器` 自动检测「是否内存可容纳」——这就是「外部 vs 内存」在工业界的分界线。理解了模型差异，就能理解为什么同样的算法在不同数据规模下「快慢迥异」。</span>

## 5 小结

- **外部归并排序**：阶段一生成有序段（run），阶段二 k 路归并。
- **run 生成**：内存大小的块排序后写盘，段数 $N/M$，I/O $2N/B$。
- **多路归并**：$k$ 个 run 用最小堆并行归并，轮数 $\log_k(N/M)$。
- **I/O 复杂度** $O(\frac{N}{B}\log_k\frac{N}{M})$——轮数主导。
- 调优旋钮：run 尽量大（替换选择）、$k$ 尽量大（内存允许）；外部与内存排序是不同的复杂度量纲。
