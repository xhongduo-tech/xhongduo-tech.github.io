## 为什么从并行算法开始

前面所有算法都是「单线程」思维。多核时代要求算法**显式并行**——而分析并行算法需要新的两个量：**工作（work）**与**跨度（span）**。<span class="marginnote">并行计算的新维度：单线程看「总操作数」，并行要看「总操作数」与「关键路径长度」两个数。CLRS 用<strong>动态多线程（dynamic multithreading）</strong>模型——用 `spawn`（派生）与 `sync`（同步）原语表达并行，分析则落在 work/span 上。这个模型是 Cilk、OpenMP 的理论基础。</span>

这一课建立模型、定义 work 与 span、以及三个核心性能度量：并行度、加速比与「时间 = 总工作量 / 处理器数 + 关键路径」。

## 1 动态多线程模型

**动态多线程**：程序像一棵「计算有向无环图（dag）」。基本原语：

- `spawn`：派生一个子任务与当前任务并行执行；
- `sync`：等待所有已派生的子任务完成；
- 普通代码串行执行。

**例（并行斐波那契）**：

```
P-FIB(n)
  if n <= 1:  return n
  x = spawn P-FIB(n-1)
  y = P-FIB(n-2)
  sync
  return x + y
```

`spawn P-FIB(n-1)` 让左分支与右分支并行。<span class="marginnote">计算 dag：每个顶点是一次串行执行段（strand），边是依赖关系。`spawn` 制造「分叉」，`sync` 制造「汇合」。分析并行算法就是分析这棵 dag 的「总工作量」与「关键路径」——两个数字一出来，加速比就清楚了。</span>

## 2 工作与跨度

对计算 dag $G$：

- **工作（work）** $T_1$ = 在**单处理器**上运行的总时间（= dag 中所有顶点的代价之和）。也叫「总工作量」。
- **跨度（span）** $T_\infty$ = 在**无穷多处理器**上的运行时间（= dag 中**最长路径**的长度）。也叫「关键路径」或「深度」。

**关键不等式**：

$$T_P \ge \max\left(\frac{T_1}{P},\; T_\infty\right)$$

$P$ 个处理器的时间不可能少于「总工作量除以 $P$」（每个处理器最多做一份），也不可能少于「关键路径」（依赖链必须串行）。<span class="marginnote">这两个下界一个「算术」、一个「深度」——它们像两条铁轨限定 $T_P$ 的可行域。所有并行分析的定理（贪心调度定理）都建立在「$T_P \ge \max(T_1/P, T_\infty)$」之上。直观：总工作量决定「有多少活」，关键路径决定「最快多快能开始干完最依赖的那串」。</span>

## 3 加速比与并行度

**并行度（parallelism）** = $T_1 / T_\infty$ = 能达到的**最大加速比上限**（用无穷多处理器时的理论加速）。实际加速比 $S_P = T_1 / T_P$。

**线性加速**：$S_P = \Theta(P)$（$T_P = \Theta(T_1/P)$）——理想但罕见。**次线性**：$S_P < P$——关键路径成为瓶颈。

**辨析｜易错点：** 「并行度 $T_1/T_\infty$」不是「处理器数」——它是**问题本身的固有并行潜力**。并行度 < 处理器数时，加更多处理器也白搭（关键路径瓶颈）；并行度 >> 处理器数时，加速比接近线性。<span class="marginnote">例：并行斐波那契的 $T_1 = \Theta(\phi^n)$（指数工作）、$T_\infty = \Theta(n)$（递归深度线性），并行度 $\approx \phi^n/n$——巨大。但实际并行斐波那契很浪费（指数工作量只为算斐波那契），这引向「并行要设计而非随便 spawn」。</span>

## 4 公式解析：$T_P \ge \max(T_1/P, T_\infty)$ 的两个下界

设 $P$ 个处理器，$T_P$ 是实际运行时间：

$$T_P \ge \frac{T_1}{P}, \qquad T_P \ge T_\infty$$

- **第一步，算术下界**：每个处理器单位时间至多完成 $T_1/P$ 的工作——$P$ 个处理器并行做，总吞吐上限是「总工作 / 处理器数」。
- **第二步，深度下界**：dag 中最长路径 $T_\infty$ 上的依赖必须串行——无论多少处理器，这条链的每段都要等前一段。
- **第三步，合取**：$T_P$ 同时受两个下界约束，取 $\max$——**「忙不过来的算术」与「快不过去的依赖」**共同决定时间下限。

**要点**：这两个下界是并行分析的罗盘。任何「$P$ 个处理器跑得比 $\max(T_1/P, T_\infty)$ 快」的声称都不可信——除非算法有「超线性」的神奇（不可能）。<span class="marginnote">「线性加速的充分条件」：当 $P \ll$ 并行度 $T_1/T_\infty$ 时，算术下界主导，贪心调度能接近 $T_1/P$——即「处理器远少于并行潜力」时接近线性。这给出实用指导：处理器数应远小于并行度，否则关键路径拖后腿。</span>

## 5 小结

- **动态多线程**：`spawn`/`sync` 表达并行；计算 dag 是分析对象。
- **工作** $T_1$ = 单处理器总时间；**跨度** $T_\infty$ = 无穷处理器的关键路径。
- **下界** $T_P \ge \max(T_1/P, T_\infty)$——算术与依赖两个瓶颈。
- **并行度** $T_1/T_\infty$ = 最大加速比上限；实际加速 $S_P = T_1/T_P$。
- 并行度远大于处理器数时接近线性加速；否则关键路径瓶颈。
