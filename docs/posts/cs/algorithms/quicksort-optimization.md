## 为什么从工程优化开始

前几课的快速排序在理论上优雅，但离「工业可用」还有距离：固定主元在有序输入上退化 $O(n^2)$、重复元素会堆到一侧、小数组的递归开销吞噬常数。<span class="marginnote">真实的标准库排序（C++ std::sort、Java Arrays.sort、Python TimSort）都叠加了多层优化。这一课把最经典的三板斧——随机/三数取中、三向划分、小数组插排——逐一拆解，理解它们各自解决什么问题、代价是什么。</span>

这是从「教材算法」到「工程算法」的第一次转变：**正确性之外，还有常数、鲁棒性、退化防护**。

## 1 随机化与三数取中：抵御有序输入

### 随机主元

把 PARTITION 的主元从「固定取 $A[r]$」改为「在 $[p,r]$ 内均匀随机选取」。上一课已证明期望 $O(n\log n)$。它的作用是**让最坏情况不再可被输入复现**——对手无法再构造「恰好让主元恒为极值」的输入。

### 三数取中（Median-of-Three）

随机数生成也有开销，且伪随机数未必均匀。**三数取中**从 $A[p]$、$A[\lfloor (p+r)/2\rfloor]$、$A[r]$ 中取中位数作主元：

```text
MEDIAN-OF-THREE(A, p, r):
    mid ← ⌊(p + r) / 2⌋
    if A[mid] < A[p]: 交换 A[p] 与 A[mid]
    if A[r]   < A[p]: 交换 A[p] 与 A[r]
    if A[r]   < A[mid]: 交换 A[mid] 与 A[r]
    此时 A[mid] 是三者中位数，把它交换到 A[r] 作为主元
```

它有两个好处：**对已有序输入给出近似完美的平衡划分**（三个采样点几乎覆盖端点与中点），且**不需随机数**——实现简单、行为可预测。<span class="marginnote">三数取中并非理论最优，但它在「工程确定性」与「理论随机性」之间取了折中：既不引入随机源，又能化解大多数病态输入。Sedgewick 在他的研究中发现它对随机数据也几乎不损失性能。</span>

**辨析｜易错点：** 三数取中不能完全替代随机化——存在专门构造的输入让三数取中依然失效（所谓 adversarial median-of-three killer）。理论严谨的应用（如避免恶意输入攻击的库）仍会叠加随机化；三数取中更多是「性价比」选择。

## 2 三向划分：对付重复元素

CLRS 的快排把相等元素散落两侧，朴素处理让重复元素堆积。当数组含大量重复元素时，划分可能严重失衡。**三向划分（3-way partition）**把数组分成三区：

$$A[p..lt-1] < x, \qquad A[lt..gt] = x, \qquad A[gt+1..r] > x$$

思路是用三个指针 `lt`（小于区右界）、`gt`（大于区左界）、`i`（扫描游标）：遇到 `A[i] < x` 时与 `A[lt]` 交换并前进；遇到 `A[i] > x` 时与 `A[gt]` 交换并**不前进**（换回来的元素未检查）；遇到 `A[i] = x` 直接前进。扫描结束后中间段全是主元，**递归只需处理左右两段**——等于值的元素不再参与递归。<span class="marginnote">对全等数组，一次三向划分就把所有元素归入中段，递归立即结束——时间 $O(n)$ 而非 $O(n^2)$。这是三向划分对抗重复数据的杀手锏。</span>

**辨析｜易错点：** 三向划分与 CLRS 版 PARTITION 的「三区域」不是一回事：CLRS 版的三区域是「$\le$ 主元 / $>$ 主元 / 未处理」，主元最后才归位；三向划分的「中间区」**整段都是等于主元的值**，扫描完成即可跳过。若把两者混用，重复元素又会被重新递归——优化失效。

## 3 小数组切换到插入排序

递归到规模很小时，函数调用与划分的固定开销占比过大。**对小数组（如 $n \le 10$）直接改用插入排序**：

```text
QUICKSORT(A, p, r):
    if r − p + 1 ≤ THRESHOLD:            // 小数组直接插入排序
        INSERTION-SORT(A, p, r)
    else:
        q ← PARTITION(A, p, r)           // 划分后递归处理两段
        QUICKSORT(A, p, q − 1)
        QUICKSORT(A, q + 1, r)
```

插入排序在近有序的小数组上几乎是线性的，且**无递归、常数极小**。阈值通常取 10–30。<span class="marginnote">这个「切换」思想在所有递归算法中通用：递归树越深，叶子越多，叶子处的固定开销越不可忽略。切到迭代/朴素算法处理叶子，是分治优化的标配。</span>

**辨析｜易错点：** 切换后整体复杂度仍是 $O(n\log n)$——插入排序只处理大小为常数的子问题，总代价仍是 $O(n \log n)$，只是常数变小。**不要把「小数组插排」误读成「把整个排序换成插入排序」**——它只作用于递归叶子。

## 4 公式解析：三数取中 vs 随机化的复杂度对比

三数取中并不能改变量级——它仍是 $O(n\log n)$ 期望/平均，最坏仍是 $O(n^2)$。真正值得解析的是「**随机化如何消灭 $n^2$ 的可复现性**」：

$$\Pr[\text{某次划分极端失衡}] \le \frac{2}{n}$$

- **第一步，看概率**：主元均匀随机时，落在「区间两端各 $n/2$ 外」的极端区域（使得划分比例 < 1/4）的概率有界。
- **第二步，看事件叠加**：连续 $k$ 次都极端失衡的概率按 $1/n$ 的幂次衰减，$n$ 越大越不可能。
- **第三步，看结论**：虽然最坏情况 $O(n^2)$ 在理论上仍存在，但**期望与高概率行为都是 $O(n\log n)$**——随机化把「必然退化」降级为「指数级不可能退化」。

**要点**：工程优化的目标不是「消除最坏」（那要更强的数据结构或算法），而是「让最坏在现实中不可达」。三数取中、随机化、三向划分各防一种病态，组合起来覆盖了有序、重复、恶意构造三类输入。<span class="marginnote">工业排序的集大成者是 C++ std::sort 的 <strong>introsort</strong>：快排为主，递归过深时切换到堆排序保证 $O(n\log n)$ 上界，小段用插入排序——三种算法各司其职。理解了这个组合逻辑，就读懂了一半的工业排序。</span>

## 5 小结

- **三数取中**：从三个采样点取中位数作主元，化解有序输入、免随机源，但不能完全防恶意构造。
- **三向划分**：把数组分成「$<$ / $=$ / $>$」三区，重复元素整段跳过，全等数组降至 $O(n)$。
- **小数组插排**：阈值以下切到插入排序，消灭递归叶子开销，常数大幅下降。
- **随机化**：让最坏情况「不可复现」而非「消失」；与三数取中互补。
- 工业实现（introsort）是快排 + 堆排 + 插排的组合，各层防一手。

在下一课，我们跳出比较排序的框架，问一个根本问题：**比较排序能快到什么程度？** 答案是 $\Omega(n\log n)$ 的下界——决策树模型将给出证明，然后引出计数排序、基数排序、桶排序这些「不靠比较」的线性时间排序。
