## 为什么从朴素匹配开始

在文本编辑器的查找、DNA 序列比对、日志检索里，核心原语是**字符串匹配**：在文本 $T$ 中找模式 $P$ 的所有出现位置。<span class="marginnote">朴素算法（naive）是每个初学者的第一直觉：从文本的每个位置出发，逐字符比对模式。它的平均表现尚可，但最坏情况——模式与文本大量「前面对上、最后错」——退化到 $O(nm)$。这一课把朴素算法的缺陷分析清楚，后面 Rabin-Karp、KMP、Boyer-Moore 全都是「针对这个缺陷的修补」。</span>

这一课定义问题、给出朴素算法、并解剖它为什么会退化——为后续所有高级算法立好靶子。

## 1 问题定义与朴素算法

**字符串匹配**：给定文本 $T[1..n]$ 与模式 $P[1..m]$（$m \le n$），找所有**有效位移（valid shift）** $s$，使 $P$ 与 $T[s+1..s+m]$ 完全匹配。目标：输出所有有效位移 $s$。

**朴素算法**：对每个位移 $s = 0..n-m$，从 $P$ 的第 1 位逐字符比对；一旦失配就放弃，移向下一个 $s$。

```text
NAIVE-STRING-MATCHER(T, P):
    n = T.length
    m = P.length
    for s = 0 to n - m:
        if P[1..m] == T[s+1..s+m]:       // 逐字符整体比对
            输出「模式在位移 s 处出现」
```

**复杂度**：最坏 $O((n-m+1) m)$。每个位移最坏比对 $m$ 个字符，共 $n-m+1$ 个位移。<span class="marginnote">朴素算法的时间常被低估：它的「平均」其实很好（随机文本下，$P$ 的第 1 位失配概率高，几乎每个位移只比 1 次就放弃，实际近 $O(n)$）。但「平均好」救不了「最坏坏」——理论分析看最坏，这才催生了 KMP 等线性算法。</span>

## 2 缺陷：信息被丢弃

朴素算法的核心浪费是：**失配后把已比对的字符信息全部丢弃**，下一个位移从头再来。

**最坏情况构造**：$T = aaaa\cdots a$（全 a），$P = aaa\cdots b$（$m-1$ 个 a 后一个 b）。每个位移都匹配前 $m-1$ 位、最后一位失败——每次比对 $m$ 次，$n-m+1$ 个位移，总 $O(nm)$。<span class="marginnote">这个「前缀全对、末位失配」的构造是朴素算法最坏的典型：位移 $s$ 已经知道「$T[s+1..s+m-1] = a^{m-1}$」，但位移 $s+1$ 完全不知道这件事，又重新比对这些 a。<strong>已获得的信息没有传递</strong>——这是所有高效匹配算法的共同出发点：把失配前的「部分匹配」信息保留下来。</span>

## 3 公式解析：为什么是 $O(nm)$

总比对次数 = 位移数 × 每位移最坏比对长度：

$$T(n,m) = \sum_{s=0}^{n-m} O(m) = O((n-m+1)\, m) = O(nm)$$

- **第一步，位移数**：$s$ 从 0 到 $n-m$，共 $n-m+1$ 个。
- **第二步，单位移最坏**：模式 $m$ 位全比对一次才失败，$O(m)$。
- **第三步，相乘**：$O(nm)$——当 $m \approx n/2$ 时约 $O(n^2)$。对长文本（$n = 10^6$）完全不可行。

**要点**：$nm$ 是「位移 × 模式长」的乘积。**只要每个位移都从头比对，$O(nm)$ 就不可避免**——除非利用「失配位置之前的信息」跳过一些位移或缩短一些比对。<span class="marginnote">后续算法的「先进」全部体现在「打破 $O(nm)$」：Rabin-Karp 用哈希把「整段比较」变成 $O(1)$ 期望；KMP 用前缀函数把「位移推进」变成「模式内回退」；Boyer-Moore 用「坏字符/好后缀」让模式「大步跳过」。朴素算法的 $O(nm)$ 是它们共同的敌人。</span>

## 4 朴素匹配的适用场景

虽然最坏 $O(nm)$，朴素算法并非一无是处：

**模式很短**（$m$ 小）或文本短时，常数小、实现简单。
**随机文本**下平均近 $O(n)$（首字符失配率 $1 - 1/|\Sigma|$）。
作为其他算法的基础结构（如自动机匹配的退化情形）。

**辨析｜易错点：** 「平均近 $O(n)$」依赖**均匀随机文本**假设。真实文本（自然语言、DNA、代码）常含大量重复子串，可能命中最坏情形。**别用「平均好」说服自己忽略最坏**——这正是 KMP 存在的原因。<span class="marginnote">工程速查：标准库的 `strstr` 常用「Two-Way 算法」（线性且常数小）；`grep` 用 Boyer-Moore 变体；DNA 比对用 KMP 或自动机。理解朴素算法是理解这些工程选择的前提——每个高级算法都在回答「朴素算法浪费在哪」。</span>

## 5 小结

- **字符串匹配**：找模式在文本中的所有位移；朴素算法逐位移逐字符比对。
- **最坏 $O(nm)$**：全 a 文本 + 「末位 b」模式，每个位移比 $m$ 次。
- **缺陷**：失配信息被丢弃，位移之间不共享「部分匹配」。
- 「平均近 $O(n)$」依赖随机假设，真实文本可能命中最坏。
- 后续算法（Rabin-Karp/KMP/Boyer-Moore）都是对「丢弃信息」这一缺陷的修复。
