## 为什么从朴素匹配开始

在文本编辑器的查找、DNA 序列比对、日志检索里，核心原语是**字符串匹配**：在文本 $T$ 中找模式 $P$ 的所有出现位置。<span class="marginnote">朴素算法（naive）是每个初学者的第一直觉：从文本的每个位置出发，逐字符比对模式。它的平均表现尚可，但最坏情况——模式与文本大量「前面对上、最后错」——退化到 $O(nm)$。这一课把朴素算法的缺陷分析清楚，后面 Rabin-Karp、KMP、Boyer-Moore 全都是「针对这个缺陷的修补」。</span>

这一课定义问题、给出朴素算法、并解剖它为什么会退化——为后续所有高级算法立好靶子。

## 1 问题定义与朴素算法

**字符串匹配**：给定文本 $T[1..n]$ 与模式 $P[1..m]$（$m \le n$），找所有**有效位移（valid shift）** $s$，使 $P$ 与 $T[s+1..s+m]$ 完全匹配。目标：输出所有有效位移 $s$。

**朴素算法**：对每个位移 $s = 0..n-m$，从 $P$ 的第 1 位逐字符比对；一旦失配就放弃，移向下一个 $s$。

```text
NAIVE-STRING-MATCHER(T, P):
    n = T.length
    m = P.length
    for s = 0 to n - m:
        if P[1..m] == T[s+1..s+m]:       // 逐字符整体比对
            输出「模式在位移 s 处出现」
```

**复杂度**：最坏 $O((n-m+1) m)$。每个位移最坏比对 $m$ 个字符，共 $n-m+1$ 个位移。<span class="marginnote">朴素算法的时间常被低估：它的「平均」其实很好（随机文本下，$P$ 的第 1 位失配概率高，几乎每个位移只比 1 次就放弃，实际近 $O(n)$）。但「平均好」救不了「最坏坏」——理论分析看最坏，这才催生了 KMP 等线性算法。</span>

## 2 缺陷：信息被丢弃

朴素算法的核心浪费是：**失配后把已比对的字符信息全部丢弃**，下一个位移从头再来。

**最坏情况构造**：$T = aaaa\cdots a$（全 a），$P = aaa\cdots b$（$m-1$ 个 a 后一个 b）。每个位移都匹配前 $m-1$ 位、最后一位失败——每次比对 $m$ 次，$n-m+1$ 个位移，总 $O(nm)$。<span class="marginnote">这个「前缀全对、末位失配」的构造是朴素算法最坏的典型：位移 $s$ 已经知道「$T[s+1..s+m-1] = a^{m-1}$」，但位移 $s+1$ 完全不知道这件事，又重新比对这些 a。<strong>已获得的信息没有传递</strong>——这是所有高效匹配算法的共同出发点：把失配前的「部分匹配」信息保留下来。</span>

**辨析｜易错点：** 朴素算法不需要任何预处理——这是它「简单」的代价：没有任何结构可以利用。反过来，KMP 的预处理（前缀函数）就是「把模式的自相似性先算好」，用它来「不回头地推进」。**预处理与在线开销的权衡**是字符串匹配算法设计的根本张力：先花时间学模式，还是每次现学现比。

**位移间的信息复用预览**：位移 $s$ 失配于位置 $j$（$P[j] \ne T[s+j]$），说明 $T[s+1..s+j-1] = P[1..j-1]$——这段「部分匹配」在位移 $s+1$ 里仍对应 $T[s+2..s+j]$。KMP 正是利用「$P[1..j-1]$ 的哪些后缀是它的前缀」来决定位移 $s+1$ 该从模式的哪一位继续比——把朴素算法「丢掉的」这部分信息找回来，换来线性时间。

## 3 数值算例：把 $O(nm)$ 数到具体数字

设文本 $n = 10^6$（百万字符的日志），模式 $m = 10^3$。

- **最坏**：$T$ 前 $m-1$ 位全是 `a`、末尾是 `b`，$P$ 是 `a`×999 + `b`。每个位移都比对 $10^3$ 次才失败，位移约 $10^6$ 个——总比对 $10^9$ 次。每比 1 个字符约 1ns，共约 1 秒——看似不快，但若 $n = 10^9$ 就变成 1000 秒，完全不可接受。
- **平均**：随机文本下，模式第 1 位与文本对应位相同的概率约 $1/|\Sigma|$（如 1/256），失配即放弃——每个位移平均比 1~2 次，总比对近 $O(n)$，毫秒级。

同一份输入、同一个算法，「最坏 1 秒 vs 平均毫秒」——差三个数量级。<span class="marginnote">这个对比说明「复杂度要看最坏」不只是理论洁癖：真实日志里大量重复子串（如全 a 的占位符、重复的标签）会把「平均很好」的假设击穿。工程上选匹配算法，先问「我的文本会不会有长重复段」——会，就老老实实上 KMP/自动机。</span>

## 4 公式解析：为什么是 $O(nm)$

总比对次数 = 位移数 × 每位移最坏比对长度：

$$T(n,m) = \sum_{s=0}^{n-m} O(m) = O((n-m+1)\, m) = O(nm)$$

- **第一步，位移数**：$s$ 从 0 到 $n-m$，共 $n-m+1$ 个。
- **第二步，单位移最坏**：模式 $m$ 位全比对一次才失败，$O(m)$。
- **第三步，相乘**：$O(nm)$——当 $m \approx n/2$ 时约 $O(n^2)$。对长文本（$n = 10^6$）完全不可行。

**要点**：$nm$ 是「位移 × 模式长」的乘积。**只要每个位移都从头比对，$O(nm)$ 就不可避免**——除非利用「失配位置之前的信息」跳过一些位移或缩短一些比对。<span class="marginnote">后续算法的「先进」全部体现在「打破 $O(nm)$」：Rabin-Karp 用哈希把「整段比较」变成 $O(1)$ 期望；KMP 用前缀函数把「位移推进」变成「模式内回退」；Boyer-Moore 用「坏字符/好后缀」让模式「大步跳过」。朴素算法的 $O(nm)$ 是它们共同的敌人。</span>

## 5 朴素匹配的适用场景

虽然最坏 $O(nm)$，朴素算法并非一无是处：

**模式很短**（$m$ 小）或文本短时，常数小、实现简单。
**随机文本**下平均近 $O(n)$（首字符失配率 $1 - 1/|\Sigma|$）。
作为其他算法的基础结构（如自动机匹配的退化情形）。

**辨析｜易错点：** 「平均近 $O(n)$」依赖**均匀随机文本**假设。真实文本（自然语言、DNA、代码）常含大量重复子串，可能命中最坏情形。**别用「平均好」说服自己忽略最坏**——这正是 KMP 存在的原因。<span class="marginnote">工程速查：标准库的 `strstr` 常用「Two-Way 算法」（线性且常数小）；`grep` 用 Boyer-Moore 变体；DNA 比对用 KMP 或自动机。理解朴素算法是理解这些工程选择的前提——每个高级算法都在回答「朴素算法浪费在哪」。</span>

## 6 术语速查与三算法前瞻

| 术语 | 含义 |
| --- | --- |
| 有效位移 | 模式与文本对齐且完全匹配的起始位置 |
| 朴素匹配 | 逐位移逐字符比对，最坏 $O(nm)$ |
| 前缀函数 | KMP 的预处理结构，编码模式的自相似性 |
| 滚动哈希 | Rabin-Karp 的 $O(1)$ 期望比较工具 |
| 坏字符/好后缀 | Boyer-Moore 的两条跳转规则 |

**辨析｜易错点：** 不要以为「朴素匹配没有预处理」等于「朴素匹配总比有预处理的慢」——对小模式（$m$ 很小），预处理开销反而可能超过匹配省下的时间。选型要看 $n$、$m$、字符集、重复模式出现频率：**没有「永远最好的匹配算法」，只有「对当前文本特征最合适的」**。

## 7 常见疑问快速答疑

**问：为什么不能把所有位移的比对结果「复用」？** 朴素算法的每个位移都从 $P$ 的第 1 位开始，位移 $s$ 比对的字符与位移 $s+1$ 比对的重叠很大，但朴素算法没有「记忆」。KMP 的核心正是「记住上一个位移已经匹配了多少」，用前缀函数避免重复比对——复用的就是这块被丢弃的信息。

**问：平均 $O(n)$ 是怎么算的？** 随机文本下，位移 $s$ 的第 1 次比对 $P[1]$ vs $T[s+1]$ 失配的概率约 $1 - 1/|\Sigma|$（字符集越大越可能失配），所以大多数位移只比 1 次就放弃。期望比对次数 $\approx n \cdot (1 + \text{小量})$，即 $O(n)$。但「概率」只在随机假设下成立。

**问：$m > n$ 怎么办？** 模式比文本还长，不可能匹配——直接返回空。朴素算法里 $s$ 从 0 到 $n-m$，当 $m > n$ 时这个范围为空，循环不执行。实现时可以先判 `m > n` 提前退出。

**问：一个文本多个模式怎么匹配？** 朴素算法逐位移比一个模式；若要同时找多个模式（如 DNS 查黑名单、词典分词），应改用 Aho-Corasick 自动机——它把多个模式合成一个自动机，一次扫描文本匹配所有模式。这属于「多模式匹配」的进阶话题。

**问：为什么 $O(nm)$ 里 n 和 m 是相乘而不是相加？** 因为每个位移独立地比对最多 $m$ 个字符，位移有 $n-m+1$ 个——「位移数 × 单位移工作」天然是乘积。只有「位移之间共享信息」才能把乘积降成和，这正是 KMP 等算法的目标：用前缀把 $O(nm)$ 换成 $O(n+m)$。

**问：朴素算法能检测重叠匹配吗？** 能——它把所有有效位移都输出。若重叠匹配也算（如 `aaa` 在 `aaaa` 中出现 2 次），朴素算法会正确报告两个重叠位移。KMP 同样支持重叠匹配，前缀函数正是为此设计。

**问：有没有比 KMP 更快的最坏线性算法？** 有——Two-Way 算法（线性且常数更小）是标准库 `strstr` 的常见实现。KMP 教学价值高，但工程实现常选 Two-Way。理解「线性 + 常数小」的取舍，是工程选型的必修课。

## 8 小结

- **字符串匹配**：找模式在文本中的所有位移；朴素算法逐位移逐字符比对。
- **最坏 $O(nm)$**：全 a 文本 + 「末位 b」模式，每个位移比 $m$ 次。
- **缺陷**：失配信息被丢弃，位移之间不共享「部分匹配」。
- 「平均近 $O(n)$」依赖随机假设，真实文本可能命中最坏。
- 选型看特征：小模式可直接朴素；长重复段必须上 KMP/自动机。
- 多模式匹配改用 Aho-Corasick；工程线性实现常用 Two-Way。
- KMP 复用「已匹配前缀的后缀-前缀关系」，把 $O(nm)$ 换成 $O(n+m)$。
- 后续算法（Rabin-Karp/KMP/Boyer-Moore）都是对「丢弃信息」这一缺陷的修复。

在下一课，我们给匹配装一个「哈希引擎」——**Rabin-Karp**：用滚动哈希把「整段比较」压成 $O(1)$ 期望时间。
