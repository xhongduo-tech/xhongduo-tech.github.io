## 为什么从空间优化开始

上一课的 $O(nW)$ 时间换来了 $O(nW)$ 空间——当 $n = 10^3$、$W = 10^5$ 时，$10^8$ 个整数就是数百 MB 内存，常常不可接受。这一课展示 DP 工程化的两个关键动作：**滚动数组把空间从 $O(nW)$ 压到 $O(W)$**，以及**如何在没有完整表格时仍能回溯出具体方案**。<span class="marginnote">这两招是「DP 实用化」的标配。前者利用「转移只依赖上一行」的结构，后者用一个额外的布尔表（或干脆保留二维）换取方案。它们不改变时间复杂度，但决定了一个 DP 能否跑在大数据上。</span>

## 1 为什么可以滚动：依赖结构

回顾 0-1 背包的转移：

$$dp[i][w] = \max\left(dp[i-1][w],\; dp[i-1][w-w_i] + v_i\right)$$

它只依赖**第 $i-1$ 行**的两个格——$dp[i][w]$ 与 $dp[i][w-w_i]$。也就是说，计算第 $i$ 行时，第 $i-2, i-3, \dots$ 行已经没用。于是可以只保留**一行** $dp[w]$，按 $i$ 逐件更新：

```text
for i = 1 to n                     // 逐件考虑
    for w = W downto w_i           // 容量从大到小，倒序遍历
        dp[w] = max(dp[w], dp[w - w_i] + v_i)
```

**关键细节：内层必须从 $W$ 倒序遍历到 $w_i$。**<span class="marginnote">为什么倒序？$dp[w]$ 更新时引用的 $dp[w-w_i]$ 若是「本行刚更新过的」，就等价于「同一件物品被拿了多次」——那是完全背包！倒序遍历保证 $dp[w-w_i]$ 仍是「上一行」（未处理本件）的值，0-1 语义才正确。这个「倒序 vs 正序」是背包 DP 最著名的实现分水岭。</span>

**辨析｜易错点：** 完全背包用正序（$w = w_i..W$，允许本行传递，即「可重复取」）；0-1 背包用倒序（$W..w_i$，阻止本行传递）。**把两者循环方向写反，是背包类 DP 的头号错误**——症状是结果偏大（0-1 写成正序 = 变成完全背包）或漏项。

## 2 一维 DP 的正确性：为什么没丢信息

倒序一维更新的正确性论证：处理第 $i$ 件前，$dp[w]$ 存的是 $dp[i-1][w]$。内层从 $W$ 往下走时，$dp[w-w_i]$（更小的 $w$）**尚未被本件更新**（因为正从大到小），所以它仍是 $dp[i-1][w-w_i]$。于是

$$dp[w] \gets \max(\underbrace{dp[i-1][w]}_{\text{当前值}}, \underbrace{dp[i-1][w-w_i]}_{\text{未更新的较小格}} + v_i)$$

与二维转移完全一致。<span class="marginnote">「倒序保证引用旧值」这个论证值得背下来：它是滚动数组正确性的通用范式。任何「转移依赖同行更小下标」的 DP，若要滚动压缩，都得想清楚访问顺序。</span>

## 3 方案回溯：没有二维表怎么办

滚动数组省了空间，也**丢了「每件物品在哪个状态被选中」的信息**。要输出「选了哪些物品」，两种方案：

**方案一：保留二维布尔表 $choice[i][w]$**（或直接保留完整二维 $dp$）。回溯时从 $choice[n][W]$ 出发：

```text
w = W
for i = n downto 1:
    if choice[i][w]:                 // 第 i 件被选中
        输出「选第 i 件」
        w = w - w_i                  // 腾出已占用的容量
    else:
        输出「不选第 i 件」
```

$choice[i][w] = \text{TRUE}$ 当且仅当「选第 $i$ 件使 $dp[i][w]$ 达到最优」。空间回到 $O(nW)$（存 choice 表），但时间不变。<span class="marginnote">「值表 + 选择表」与 LCS 课的 $b$（方向）表、最优 BST 的 $root$ 表是同一套路：要构造方案，就必须把「决策」记下来。空间优化的代价正是丢失决策——鱼与熊掌。</span>

**方案二：只存一维 dp，回溯时「重算」决策**。从 $dp[W]$（最终状态）开始，检查第 $i$ 件是否「值得拿」：

```text
w = W
for i = n downto 1:
    if w >= w_i and dp[w] == dp[w - w_i] + v_i:
        输出「选第 i 件」
        w = w - w_i
    else:
        输出「不选第 i 件」
```

需要再存一份完整的「每次更新前」的 dp？不行——一维 dp 已被覆盖。**方案二只在「能恢复历史 dp」时才成立**，通常需要存二维或存更新日志，所以工程上更常用方案一。

**辨析｜易错点：** 一维 dp 回溯时的判断 $dp[w] == dp[w - w_i] + v_i$ **可能误判**：因为一维数组在多次覆盖后，$dp[w-w_i]$ 不再代表「处理到第 $i-1$ 件」的值。**若要可靠回溯，请存二维**（或 choice 表）。这是「空间优化与方案回溯不可兼得」的诚实结论。

## 4 公式解析：空间复杂度对比

二维 DP：$S = O(nW)$；滚动数组：$S = O(W)$。

$$S_{\text{2D}} = n \times W,\qquad S_{\text{1D}} = W$$

- **第一步，二维表**：$n+1$ 行 × $W+1$ 列，存 dp 值或 choice 标志。
- **第二步，滚动**：每件物品只需一行 $W$，旧行覆盖新行。
- **第三步，比值**：$n$ 倍差距——$n = 10^4$ 时二维可能爆内存，一维轻松。

**要点**：滚动数组不改变**时间**复杂度（仍是 $O(nW)$），只省**空间**。当状态转移只依赖「上一层」，滚动总是可行；依赖「前两层」时保留两行；依赖「整层」时无法滚动——**「压缩到几行」由转移的依赖宽度决定**。<span class="marginnote">这个「依赖宽度决定可压缩度」的观点非常通用：LCS 可压到两行（依赖 $dp[i-1][*]$ 与 $dp[i][*-1]$），斐波那契压到两个变量，而最优 BST 的 $e[i][j]$ 依赖「跨区间的更短区间」、无法简单滚动。学会判断依赖结构，就知道 DP 能否省内存。</span>

## 5 数值算例：一维数组逐件滚动

四件物品（重量, 价值）$(2,3)、(3,4)、(4,5)、(5,6)$，容量 $W = 8$。一维数组 $dp[0..8]$ 逐件更新（每件从 $W$ 倒序到 $w_i$）：

| 处理 | $dp$ 数组（下标 0..8） |
| --- | --- |
| 初始 | 0 0 0 0 0 0 0 0 0 |
| 物品1 (2,3) | 0 0 3 3 3 3 3 3 3 |
| 物品2 (3,4) | 0 0 3 4 4 7 7 7 7 |
| 物品3 (4,5) | 0 0 3 4 5 7 8 9 9 |
| 物品4 (5,6) | 0 0 3 4 5 7 8 9 **10** |

$dp[8] = 10$——最优价值 10（选物品 2 与 4：$4 + 6 = 10$，重量 $3+5 = 8$）。<span class="marginnote">关键看「倒序」的作用：处理物品 2 时，$dp[8] = \max(dp[8], dp[5]+4)$ 引用的 $dp[5]$ 是「处理物品 1 后的旧值 3」（因为 5 < 8 尚未被本件更新）——得到 7。若正序遍历，$dp[5]$ 已被本件更新为 4，$dp[8]$ 会变成 $4+4=8$，等于「物品 2 拿了两次」（重量 6）——那就不该是 0-1 背包。本表所有值都能在二维表对应位置找到，证明滚动没丢信息。</span>

**空间对照**：二维表 $9 \times 9 = 81$ 格；滚动数组只要 9 格——9 倍节省。$n = 10^4$、$W = 10^5$ 时，二维 $10^9$ 格（约 4–8 GB）直接爆内存，一维 $10^5$ 格（约 0.4 MB）轻松跑——**这就是工程上滚动数组的意义**。

## 6 小结

- 0-1 背包转移只依赖上一行 → **滚动数组**压到 $O(W)$ 空间。
- **内层必须倒序遍历** $W..w_i$：保证引用上一行的旧值；正序等于完全背包。
- 数值算例：四件物品容量 8 逐件滚动得 $dp[8]=10$，倒序保证 0-1 语义、空间省 9 倍。
- 空间优化的代价是丢失决策信息——要回溯方案需存 choice 表（$O(nW)$）。
- 「值表 + 决策表」是 DP 构造方案的通用范式，贯穿 LCS、最优 BST、背包。
- 可压缩度由转移的依赖宽度决定：依赖上一层 → 压一行；依赖更宽 → 难压缩。


**速查表**：

| 概念 | 含义 |
| --- | --- |
| 滚动数组 | 每件只保留一行 $dp$，$O(W)$ 空间 |
| 倒序遍历 | $W$ 到 $w_i$，保证引用上一行旧值 |
| choice 表 | 记录每件每容量的选择，供回溯 |
| 依赖宽度 | 转移依赖几行 → 可压缩到几行 |

**辨析｜易错点：** 完全背包用正序（允许本行传递 = 可重复取），0-1 背包用倒序。把两者循环方向写反是背包 DP 头号错误——0-1 写成正序等于变成完全背包，结果偏大。

**数值快照**：四件物品容量 8 逐件滚动得 $dp[8]=10$（选物品 2 与 4）；二维表 $9\times9=81$ 格 vs 一维 9 格，$n=10^4$、$W=10^5$ 时二维 4–8GB 爆内存、一维 0.4MB 轻松跑。
