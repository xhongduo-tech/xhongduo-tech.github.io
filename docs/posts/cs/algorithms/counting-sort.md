# 计数排序（Counting Sort）：稳定性与适用条件

## 为什么从计数排序开始

上一课的下界 $\Omega(n\log n)$ 只约束「比较排序」。计数排序是第一把突破它的钥匙：**当 $n$ 个元素都是 $[0, k]$ 内的整数时，可以完全不比较，只用「统计每个值出现的次数」来排序**。<span class="marginnote">直觉：比较排序靠「大小关系」获取信息，每比一次最多拿到 1 比特，所以下限 $n\log n$；但计数排序直接看「元素的值」——值本身就是信息，拿到一个值就知道它该放哪里。值的取值域有限，这正是突破口。</span>

这一课拆解计数排序的算法、正确性，以及它最宝贵的性质——**稳定性**。稳定性不是可选项，而是计数排序作为基数排序子程序的命门。

## 1 算法：三次扫描

输入：$n$ 个 $[0, k]$ 内的整数。输出：排好序的数组 $B$。用辅助数组 $C[0..k]$ 统计频次。

```
COUNTING-SORT(A, B, k)
  let C[0..k] be a new array
  for i = 0 to k
    C[i] = 0
  for j = 1 to A.length        // 第一次扫描：统计频次
    C[A[j]] = C[A[j]] + 1
  for i = 1 to k               // 前缀和：C[i] = 值 ≤ i 的元素个数
    C[i] = C[i] + C[i-1]
  for j = A.length downto 1    // 第二次扫描：从后往前放置
    B[C[A[j]]] = A[j]
    C[A[j]] = C[A[j]] - 1
```

三步的关键：

- **频次统计**：$C[v]$ 记录「值恰好为 $v$」的元素个数。
- **前缀和**：$C[i]$ 变成「值 $\le i$」的元素总数——于是 $C[i]$ 就是「值 $i$ 应该放的最后一个位置」。
- **从后往前放置**：$B[C[A[j]]] = A[j]$ 把 $A[j]$ 放到它该在的位置，然后 $C[A[j]]$ 减一，让相等元素向前挪。<span class="marginnote">「从后往前」不是可有可无的细节：它保证相等的元素<strong>保持原相对顺序</strong>。若从前往后放，相等的元素会颠倒——稳定性就丢了。这是计数排序最容易写错的一行。</span>

## 2 正确性与稳定性

**正确性论证**：处理完前缀和后，$C[v]$ 表示「值 $\le v$ 的元素个数」，因此值 $v$ 的最后一个元素应落在下标 $C[v]$ 处。从后往前扫描时，每个元素被放到「当前该值剩余位置中最靠后的」，且放置后计数减一——归纳可知，扫描结束时 $B[1..n]$ 恰好是排序后的完整数组。

**稳定性（stability）**：**若两个元素值相等，它们在输出中的相对顺序与输入中的相对顺序一致**。计数排序的「从后往前放」保证了：值相同的元素中，输入中靠后者先被放置到较大的位置，靠前者随后被放到较小的位置——顺序保持。<span class="marginnote">稳定性为什么重要？因为基数排序需要「按低位先排，再按高位排」——如果子排序不稳定，高位的排序会破坏低位已经排好的相对顺序。稳定子排序 + 逐位排序 = 基数排序的整个正确性。</span>

**辨析｜易错点：** 稳定性不是「排序结果唯一」——结果都是同一个有序数组。稳定性是指**相等元素之间的次序**。检查一个实现是否稳定：输入 `[2a, 1, 2b]`（两个值相等但可区分），输出应为 `[1, 2a, 2b]`（保持 a 在 b 前）。若输出 `[1, 2b, 2a]`，则不稳定。

## 3 公式解析：为什么计数排序是 $O(n + k)$

计数排序的代价是四个循环的线性相加：

$$T(n,k) = \Theta(k) + \Theta(n) + \Theta(k) + \Theta(n) = \Theta(n + k)$$

- **第一步，$\Theta(k)$**：初始化数组 $C$ 与做前缀和，各扫一遍 $[0,k]$。
- **第二步，$\Theta(n)$**：统计频次与从后往前放置，各扫一遍输入数组。
- **第三步，合并**：$T = \Theta(n+k)$。当 $k = O(n)$ 时，$T = \Theta(n)$——**突破了比较排序的 $n\log n$ 下界**。

**要点**：计数排序是「空间换时间」的典型——用 $O(k)$ 的辅助空间换取线性时间。**它的代价与 $k$ 线性相关**：$k$ 远大于 $n$ 时（如值域 $[0, 10^9]$ 而只有 100 个元素），$O(k)$ 空间与时间都不可接受。<span class="marginnote">所以计数排序的适用条件是「$k$ 与 $n$ 同阶」。这个「值域不能太大」的约束，决定了它常常作为基数排序的原子步骤，而不是直接用于大值域。</span>

**辨析｜易错点：** $O(n+k)$ 里若 $k$ 以「指数级」形式出现（如 64 位整数的 $k = 2^{64}$），则比 $O(n\log n)$ 差得多——**不能因为「线性」就无条件用它**。「线性」是对 $n$ 说的，必须看 $k$ 的脸色。

## 4 与比较排序的关系与适用条件

计数排序的本质是**用「值的分布」替代「值的关系」**。适用条件总结：

- 元素必须是**小范围整数**（或可离散到小整数）；
- 值域 $k$ 与 $n$ 同阶才划算；
- 需要**稳定**输出（或作为基数排序子程序）。

作为对比：

| 维度 | 比较排序 | 计数排序 |
| --- | --- | --- |
| 信息获取 | 两两比较 | 直接读值 + 频次 |
| 时间 | $\Omega(n\log n)$ | $\Theta(n+k)$ |
| 空间 | 原地或 $O(n)$ | $O(k)$ 额外 |
| 对值域要求 | 任意可比较 | 整数、值域小 |
| 稳定性 | 看实现 | 天然稳定（从后往前放） |

<span class="marginnote">工程里计数排序最著名的应用场景是「桶」的索引：把浮点数按位拆成字节、把字符串按字典序逐位排——底层都靠计数排序的稳定性串联。理解了「用分布代替比较」，就理解了线性排序家族的设计哲学。</span>

## 5 小结

- **计数排序**：统计频次 → 前缀和 → 从后往前放置，$\Theta(n+k)$，突破比较排序下界。
- **稳定性**：从后往前放置保持相等元素的相对顺序——这是它作为基数排序子程序的关键。
- 正确性由「前缀和 = 每个值的落位区间」归纳证明。
- 适用条件：**小范围整数 + 值域与 $n$ 同阶**；值域过大时 $O(k)$ 空间不可接受。
- 稳定性检查法：构造 `[2a, 1, 2b]` 看输出是否保持 a 在 b 前。

在下一课，我们让计数排序「升维」——**基数排序**：把整数按位拆开、逐位稳定排序，用 $d$ 位数字把「每位 $O(n+k)$」叠加成 $O(d(n+k))$，且低位优先的正确性靠归纳证明。
