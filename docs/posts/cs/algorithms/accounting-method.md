# 核算法（Accounting Method）：二进制计数器的信用分配

## 为什么从核算法开始

聚合分析算出「总代价是 $O(n)$」，但它把话说到头就停了——**它不说「PUSH 摊还多少」「MULTIPOP 摊还多少」**。核算法给每个操作**单独分配一个摊还代价**，像记账一样解释「贵操作的钱从哪来」。<span class="marginnote">核算法的心智模型是「银行存款」：每个操作付一点「摊还费用」，其中一部分支付当前实际代价，多余的存在「信用」里；某个很贵的操作出现时，用之前攒的信用来付。只要「总存款 ≥ 总支出」（信用恒非负），摊还代价就是总代价的合法上界。</span>

这一课用**二进制计数器**演示核算法的完整记账过程——它比聚合分析更精细：每个「位」都有一本账。

## 1 核算法的一般框架

设第 $i$ 个操作的实际代价为 $c_i$，分配的**摊还代价**为 $\hat{c}_i$。累计信用定义为

$$\text{credit} = \sum_{i} \hat{c}_i - \sum_{i} c_i$$

**核心约束**：信用必须**始终非负**。则对任何 $n$ 次操作

$$\sum_{i=1}^{n} c_i \le \sum_{i=1}^{n} \hat{c}_i$$

即「总实际代价 ≤ 总摊还代价」——所以摊还代价给出总代价的上界。<span class="marginnote">「信用非负」是整个方法的命门：它要求我们<strong>不能透支</strong>。若某一步信用变负，说明摊还代价低估了实际代价，结论失效。设计摊还代价 = 找一个「始终够付」的预算分配方案。</span>

## 2 计数器记账：每个位存两元

回到 $k$ 位二进制计数器。给 INCREMENT 分配摊还代价 **2**（实际代价是翻转的位数，可能很大）。记账规则：**每次加 1，支付 2 元，其中 1 元付「把 0 变 1」的立即开销，另 1 元存进该位作为「未来把它变回 0」的信用**。

验证信用非负：一个位从 0 变 1 时，存入 1 元信用；之后某次加 1 把它从 1 变 0 时，恰好花掉这 1 元。**每位要么是 0（无信用，不需要），要么是 1（有 1 元信用）**——信用恰好等于「值为 1 的位数」，恒 ≥ 0。<span class="marginnote">这解释了聚合分析里「$\sum 1/2^i = 2$」的直觉：给每次加 1 付 2 元，一位付「置 1」、一位付「未来清 0」——几何级数里那个 2，正是这里每操作 2 元的摊还代价。两种方法算出同一个数，但核算法的解释「每笔钱有去处」更直观。</span>

## 3 公式解析：摊还代价 2 的记账平衡

用符号写清一笔账。设第 $i$ 次 INCREMENT 把 $t_i$ 个 1 翻成 0（并可能把 1 个 0 翻成 1）：

- 实际代价 $c_i = t_i + 1$（若最高位不溢出）——翻转的位数。
- 摊还代价 $\hat{c}_i = 2$。

验证：

$$\hat{c}_i - c_i = 2 - (t_i + 1) = 1 - t_i$$

- **第一步，看翻转结构**：加 1 总是「$t_i$ 个连续的 1 → 0，然后一个 0 → 1」。实际花 $t_i+1$ 元。
- **第二步，看信用变动**：被清成 0 的 $t_i$ 个位各取出 1 元信用（共 $t_i$ 元），置成 1 的那位存入 1 元。净信用变化 $= 1 - t_i$。
- **第三步，验非负**：信用总额 = 「值为 1 的位数」≥ 0。于是 $n$ 次总实际代价 ≤ $2n$——摊还 $O(1)$。

**要点**：摊还代价 2 的设计「恰好」让每一步的净信用变化与「清 0 位数」匹配。**找一个不负债的摊还代价，是核算法的全部艺术**。<span class="marginnote">若把摊还代价设成 1（「实际付 1」），则 0→1 那步没有预存，之后 1→0 时就透支——信用变负，上界失效。摊还代价必须是「当前代价 + 未来代价的摊销」的和，这是它要大于实际代价均值的原因。</span>

## 4 栈操作的核算法

同样的思想套到栈的 PUSH/POP/MULTIPOP 上：

**PUSH**：摊还代价 **2**——1 元付压栈本身，1 元存进该元素作为「未来被 POP 的预算」。
**POP**：摊还代价 **0**——用元素自带的 1 元信用支付。
**MULTIPOP(k)**：摊还代价 **0**——每弹一个元素花它那 1 元信用。

信用非负：栈里每个元素都有 1 元存款，弹出时正好花掉。于是 $n$ 次操作总摊还代价 = 只统计 PUSH 的 2 元，总 $\le 2n$，摊还 $O(1)$。<span class="marginnote">这里三种操作的摊还代价各不相同（2、0、0），这正是核算法相对聚合分析的增量价值：能区分「哪些操作贵」。聚合只给「平均每次 $O(1)$」，核算能精确到「PUSH 2、POP 0、MULTIPOP 0」。</span>

**辨析｜易错点：** 摊还代价可以是 0 甚至负数吗？**可以是 0**（如这里的 POP），但**不能是负数**——负数意味着「信用减少」，若长期为负就透支。设计时通常选「实际代价 + 为未来存的钱」，所以摊还 ≥ 实际代价 ≥ 0。

## 5 小结

- **核算法**：给每个操作分配摊还代价 $\hat{c}_i$，信用 $= \sum\hat c_i - \sum c_i$ 恒非负。
- **核心**：总实际代价 ≤ 总摊还代价；信用非负是合法性前提。
- **计数器**：INCREMENT 摊还 2（1 元置 1、1 元存信用清 0），信用 = 值为 1 的位数。
- **栈**：PUSH 摊还 2、POP/MULTIPOP 摊还 0——能区分操作类型的摊还代价。
- 摊还代价非负；「不负债」的预算分配是设计的核心。

在下一课，我们升级为**势能法**——不用「给单个元素存钱」，而是用一个全局「势能函数」跟踪结构的整体状态，动态表扩容分析是它的主舞台。
