# 随机化算法的基本概念：雇佣问题与指示器随机变量

<div class="epigraph">

## 为什么从雇佣问题开始

到目前为止，我们分析的都是**确定性算法**：给定输入，每一步都确定。真实世界并非如此——数据可能随机，算法内部也可以主动掷骰子。**随机化算法（randomized algorithm）**让算法在执行过程中使用随机数，换来「最坏情况不再被对手精确击中」或「期望时间优于最坏时间」的好处。<span class="marginnote">随机化算法与「平均情况分析」的区别：平均情况假设输入服从某分布；随机化算法是自己制造随机性，输入仍可任意。这个区别到第九篇《摊还分析》还会再辨析一次。</span>

雇佣问题（hiring problem）是 CLRS 用来引入随机化分析的第一个舞台。它足够简单，却足够展示**指示器随机变量（indicator random variable）**这个贯穿整本教材的概率工具——后续球与箱子、生日悖论、随机化快排，全都要靠它。

## 1 雇佣问题的设定

你是一家公司的人力主管，通过中介每天面试一位候选人。面试费用为 $c_i$，但候选人的**资质（quality）**在面试前未知；面试后你能立刻判断 ta 是否比现任秘书更好。若更好，就**雇佣** ta，付中介费 $c_h$（通常 $c_h \gg c_i$），同时辞退前任。问题：**总费用是多少？**

设共有 $n$ 位候选人，按面试顺序编号 1 到 $n$，第 $i$ 位资质为 $q_i$。若 $q_i$ 大于当前秘书资质就雇佣。用伪代码描述：

```text
HIRE-ASSISTANT(n)
    best = 0                            // 0 号是虚设的「最差」候选人
    for i = 1 to n
        interview candidate i           // 面试费用 c_i
        if candidate i is better than candidate best
            best = i
            hire candidate i            // 雇佣费用 c_h
```

面试总是 $n$ 次，费用 $n c_i$ 固定；**变化的只是雇佣次数 $H$**（即循环中执行 hire 的次数），总费用为 $n c_i + H c_h$。<span class="marginnote">极端情形：候选人资质严格递增，则每次都雇佣，$H = n$，费用 $n c_i + n c_h$；严格递减则只在第一天雇佣，$H = 1$。</span>于是问题转化为：**在什么意义下分析 $H$？**

## 2 最坏情况与期望：为什么要随机化

**最坏情况分析**：若面试顺序恰为资质递增，$H = n$。对手可以故意构造这种输入，让算法付出最高代价。**确定性算法在这类输入面前毫无还手之力**——因为它对每个输入都有固定行为。

**平均情况分析**：假设 $n$ 个候选人的资质是随机排列（每种排列等可能）。此时 $H$ 是随机变量，可以算它的期望。

**随机化的真正价值**：把「输入任意」与「内部随机」分开。我们不是祈祷输入恰好是随机排列，而是**主动把候选人顺序打乱**（用下一课的随机排列算法），然后再跑雇佣流程。此时无论原始输入长什么样，算法面对的都是均匀随机排列——**对手无法预测**。这就是「从平均情况到随机化」的范式转移：

$$\mathbb{E}[H] = \sum_{i=1}^{n} \frac{1}{i} = \ln n + O(1)$$

这一节的第一个目标，就是严格导出这个 $\ln n$。

## 3 指示器随机变量：把「事件」翻译成「0/1」

**指示器随机变量（indicator random variable）** 是概率论里最朴素的随机变量：对一个事件 $\mathcal{A}$，定义

$$I\{\mathcal{A}\} = \begin{cases} 1, & \text{若 } \mathcal{A} \text{ 发生} \\ 0, & \text{否则} \end{cases}$$

它的期望极其简单：

$$\mathbb{E}[I\{\mathcal{A}\}] = 1 \cdot \Pr[\mathcal{A}] + 0 \cdot \Pr[\neg \mathcal{A}] = \Pr[\mathcal{A}]$$

也就是说，**指示器的期望就是事件发生的概率**。这一行式子是整个随机分析的最强杠杆：想算「发生次数」的期望，就把发生次数写成若干指示器之和，再线性地取期望。

定义指示器 $X_i = I\{\text{候选人 } i \text{ 被雇佣}\}$。则总雇佣次数

$$H = X_1 + X_2 + \cdots + X_n$$

由期望的线性性（即使各 $X_i$ 不独立也成立）：

$$\mathbb{E}[H] = \mathbb{E}\left[\sum_{i=1}^n X_i\right] = \sum_{i=1}^n \mathbb{E}[X_i] = \sum_{i=1}^n \Pr[X_i = 1]$$

**关键的一步是算 $\Pr[X_i = 1]$**：候选人 $i$ 被雇佣，当且仅当 ta 是前 $i$ 位候选人中资质最高的。在均匀随机排列下，前 $i$ 位的最高者等可能地落在其中任何一位上，故

$$\Pr[X_i = 1] = \frac{1}{i}$$

于是得到调和级数 $\mathbb{E}[H] = \sum_{i=1}^{n} \frac{1}{i} = \ln n + O(1)$。

## 4 公式解析：为什么 $\mathbb{E}[X_i] = \Pr[X_i=1] = 1/i$

这是本课最需要吃透的式子，拆成三步：

- **第一步，$\mathbb{E}[X_i] = \Pr[X_i=1]$**：来自指示器的定义式 $\mathbb{E}[I\{\mathcal{A}\}] = \Pr[\mathcal{A}]$。把「是否被雇佣」编码成 1/0，期望自动退化为概率。
- **第二步，$\Pr[X_i=1] = 1/i$**：事件「$i$ 是前 $i$ 位中最好的」。随机排列下，前 $i$ 位中「最好」这个头衔均匀落在 $i$ 个位置之一，落在第 $i$ 位的概率自然是 $1/i$。<span class="marginnote">注意：它只依赖 $i$，不依赖其他候选人的具体资质——这正是「先随机排列，再分析」带来的干净性质。若顺序是任意的，这个 $1/i$ 就不成立。</span>
**第三步，求和得调和数**：$\sum_{i=1}^n 1/i = \ln n + \gamma + O(1/n)$，其中 $\gamma \approx 0.577$ 是欧拉常数。用积分近似即可验证：$\int_1^{n+1} \frac{dx}{x} \le \sum_{i=1}^n \frac1i \le 1 + \int_1^n \frac{dx}{x}$。

**辨析｜易错点：** 期望的线性性不需要独立性。很多初学者在算 $\mathbb{E}[H]$ 时试图先求 $H$ 的分布——那是自找麻烦。**指示器方法的精髓就是绕开分布，直接线性加和**；至于各 $X_i$ 之间是否独立，根本不用管。

## 5 随机化的两种口味：随机排列 vs 在线随机

CLRS 强调一个微妙但重要的区别：

**输入未知、候选逐个到达（在线）**：我们无法预先打乱顺序，只能接受输入顺序。此时 $1/i$ 的推导依赖「输入是均匀随机排列」这一假设——这属于**平均情况分析**，对手仍可能用坏顺序攻击我们。
**输入已知、可预先重排（离线）**：先用随机排列算法把候选人顺序打乱，再执行雇佣流程。此时即使输入是最坏情况，洗牌后也变成均匀随机排列，**期望雇佣次数恒为 $H_n$**——这是真正的随机化算法。

**随机化算法与 Las Vegas / Monte Carlo**：CLRS 这里的随机化是 **Las Vegas 型**——结果永远正确，只是运行时间（或代价）是随机变量。<span class="marginnote">与之相对的是 Monte Carlo 型：运行时间有界，但结果有小概率出错。素性测试里的 Miller-Rabin（第十五篇）就是典型的 Monte Carlo 算法。</span>理解这两类，是分析随机化算法的第一步。

## 6 数值算例：期望雇佣次数到底多大

把 $\mathbb{E}[H] = H_n = \ln n + \gamma + O(1/n)$ 算成具体数字，与最坏情况对照：

| 候选人数 $n$ | 期望雇佣次数 $H_n$ | 最坏情况 $H$ | 期望 / 最坏 |
| --- | --- | --- | --- |
| 10 | 2.93 | 10 | 29% |
| 100 | 5.19 | 100 | 5.2% |
| 1000 | 7.49 | 1000 | 0.75% |
| $10^6$ | 14.39 | $10^6$ | 0.0014% |

**看点**：$n$ 从 10 涨到一百万（$10^5$ 倍），期望雇佣次数只从 2.93 涨到 14.39——**对数增长的「钝感」在这里一览无余**。<span class="marginnote">直觉校准：第 $i$ 位候选被雇佣的概率 $1/i$，意味着「越靠后的候选人越难被雇佣」——第 100 位只有 1% 机会，第 $10^6$ 位只有百万分之一。总和是调和数，所以期望增长极慢。对照最坏情况（资质严格递增）$H = n$：随机化把「必然雇佣 $n$ 次」的灾难降成「期望雇佣 $\ln n$ 次」——对 $n=10^6$ 是从一百万次降到 14 次，<strong>四万倍的差距</strong>。这就是「随机排列 + 期望分析」能带来的真实收益。</span>

**费用对照**：设 $c_i = 1$、$c_h = 1000$、$n = 10^4$。期望总费用 $= 10^4 \times 1 + H_{10^4} \times 1000 \approx 10000 + 9.79 \times 1000 \approx 19790$；最坏（递增输入）为 $10000 + 10^4 \times 1000 = 10^7$——随机化把最坏代价压到约 1/500。

## 7 小结

- **雇佣问题**：费用 = $n c_i + H c_h$，核心是分析雇佣次数 $H$ 的期望。
- **指示器随机变量** $I\{\mathcal{A}\}$：把事件编码为 0/1，**期望恰为事件概率**。
- 总雇佣次数写成指示器和，用**期望线性性**（无需独立性）化简。
- 数值算例：$n=10^6$ 时期望 14.39 次 vs 最坏 $10^6$ 次——随机化收益约四万倍。
- 随机排列下 $\Pr[\text{第 } i \text{ 位被雇佣}] = 1/i$，故 $\mathbb{E}[H] = \sum 1/i = \ln n + O(1)$。
- **随机化 vs 平均情况**：随机化算法自己制造随机性，对手无法预测；Las Vegas 型结果正确、代价随机。
