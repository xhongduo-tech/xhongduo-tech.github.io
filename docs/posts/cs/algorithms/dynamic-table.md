## 为什么从动态表的删除开始

上一课分析了「只插不删」的动态表，摊还 $O(1)$。但真实容器（vector、ArrayList）都支持删除。一个 naive 的想法是「删到一半就缩容一半」——**这会带来灾难**：在「满」与「半」的边界反复插入删除，每次都会触发扩容或缩容，摊还代价退化为 $O(n)$。<span class="marginnote">这就是动态表删除分析的经典陷阱。解决办法是把扩容与缩容的<strong>阈值错开</strong>：例如扩容在「满」，缩容在「1/4 满」——两者之间隔着一个缓冲区间，避免「刚扩完就缩、刚缩完就扩」的震荡。</span>

这一课完整分析「插入 + 删除」的动态表，包括那个反直觉的「倍增 vs 半减」配对设计，以及势能法如何给出摊还 $O(1)$。

## 1 问题设定与负载因子

**动态表**：容量 $size$，元素数 $num$，**负载因子** $\alpha = num/size$。

操作：

**INSERT**：若 $\alpha = 1$（满），先扩容（倍增 $size$）再插入；否则直接插入。
**DELETE**：若 $\alpha$ 过低（阈值待定），先缩容再删除；否则直接删除。

**设计问题**：缩容阈值取多少？「删到一半缩一半」为什么不行？

**反例（$1/2$ 缩容陷阱）**：设 $size = 2^k$、$num = size$（刚满）。删除一个 → $num = size-1$，若「低于 1/2 就缩」这里不触发（$num = size-1 > size/2$）……实际上「删到 $< size/2$ 就缩到一半」的陷阱是：缩容后 $size' = size/2$、$num = size/2$（恰好满）。再插入 → 立即扩容回 $size$！**交替操作 $n$ 次触发 $n$ 次扩容+缩容，每次 $O(size)$，摊还 $O(n)$**。<span class="marginnote">关键在于「缩容到恰好满」：刚缩完的表是满的，下一次插入立刻扩容，下一次删除立刻缩容——扩缩在同一个边界上反复震荡。把缩容阈值降到「1/4 满」后，缩到半满（$num = size/4 \to size' = size/2$，$\alpha = 1/2$），距离满还有一半空间，需要 $size/4$ 次插入才扩容——震荡被缓冲。</span>

## 2 势能法建模：插入与删除

选择势能函数（CLRS 采用的两段式，处理插入与删除的对称性）：

$$\Phi(D) = \begin{cases} 2 \cdot num - size, & \alpha \ge 1/2 \\ size/2 - num, & \alpha < 1/2 \end{cases}$$

- **$\alpha \ge 1/2$ 时**（偏满）：势能随插入增长——和上一课相同，「满时攒势」给扩容用。
- **$\alpha < 1/2$ 时**（偏空）：势能随删除增长（$num$ 减小使 $size/2 - num$ 增大）——「太空时攒势」给缩容用。<span class="marginnote">两段式势能是动态表「插入删除都要分析」的关键：前半段管扩容、后半段管缩容，中间在 $\alpha = 1/2$ 处连续（$2num-size = size/2-num$ 当 $num=size/2$）。一个势能函数同时应付两种操作，是「对称设计」的范本。</span>

验证非负：$\alpha \ge 1/2$ 时 $2num \ge size$，$\Phi \ge 0$；$\alpha < 1/2$ 时 $size/2 > num$，$\Phi > 0$。始终非负。

## 3 摊还代价：四种情形逐一核对

**插入**（分扩容与否）：

不扩容：$c=1$，$\Delta\Phi = +2$，$\hat c = 3$。
扩容（$\alpha=1 \to num'=num+1=size'=2size$）：$c = num+1$，$\Delta\Phi = (2num'-size') - (2num-size) = (2\cdot2size - 2size) - (2size - size) = 2size - size = size$……这里需要重新算：扩容前 $\Phi = 2num - size = 2size - size = size$；扩容后 $\Phi = 2(num+1) - 2size = 2(size+1)-2size = 2$。$\Delta\Phi = 2 - size$。$\hat c = (num+1) + (2-size) = (size+1)+2-size = 3$。<span class="marginnote">注意这里与「只插不删」版本略有不同：扩到 $2size$ 后 $num+1 = size+1$，$\alpha = (size+1)/2size$ 略大于 $1/2$，仍走第一段势能。$\hat c$ 仍为 3——扩容的昂贵实际代价再次被势能吞掉。</span>

**删除**（分缩容与否）：

不缩容：$c=1$，$\Delta\Phi$：若 $\alpha \ge 1/2$ 则 $-2$，$\hat c = -1$；若 $\alpha<1/2$ 则 $+1$，$\hat c = 2$。取上界 $\hat c \le 2$。
缩容（$\alpha = 1/4$，缩到 $size' = size/2$）：$c = num$（拷贝 $num$ 个）+ 1（删除）；$\Delta\Phi = (size'/2 - num') - (size/2 - num)$。缩容前 $num = size/4$、$\Phi = size/2 - size/4 = size/4$；缩容后 $num' = size/4$、$size' = size/2$、$\Phi' = size'/2 - num' = size/4 - size/4 = 0$。$\Delta\Phi = -size/4 = -num$。$\hat c = (num+1) - num = 1$。

所有情形摊还代价均有常数上界，故 $n$ 次任意插入/删除序列摊还 $O(1)$。<span class="marginnote">四种情形的核对是这一课最繁琐的部分，但结论干净：插入摊还 3、删除摊还 ≤ 2、扩容/缩容那次摊还 1 或 3。核心是「势能精确匹配扩缩容的拷贝量」——每次扩缩容，势能跌掉的正好覆盖实际拷贝开销。</span>

## 4 公式解析：为什么「1/4 缩容」避免了震荡

关键设计：扩容阈值 $\alpha = 1$，缩容阈值 $\alpha = 1/4$。设缩容后 $num = size/2$（即 $size' = 2num$，$\alpha' = 1/2$）。从缩容完成到下次扩容，需要插入 $size/2$ 个元素——这段时间内不会再有扩/缩。

$$\text{缩容后容量 } = 2num \ge num + 1,\quad \text{需 } num \text{ 次插入才重新满}$$

- **第一步，缩到半满**：缩容后 $\alpha = 1/2$，不触发任何后续缩容（阈值 $1/4$）。
- **第二步，缓冲距离**：从半满到满需要 $num = size/4$ 次插入，期间无扩容。
- **第三步，对称性**：若缩到「恰好满」（阈值 $1/2$ 的错误设计），下一次插入立即扩容——缓冲为零，震荡形成。

**要点**：「倍增扩容 + 四分之一缩容」的错位阈值，让扩缩容之间隔着「半表」的缓冲——**任何操作序列都不会触发连续震荡**。这是动态表设计的工程智慧，也是势能法分析的直接结论。<span class="marginnote">工程语言里，这就是 C++ 标准库中 `std::vector` 的做法：capacity 倍增、缩容（`shrink_to_fit`）需要显式调用——正是为了避免「自动缩容」引发震荡。理解了这个阈值设计，就理解了现代容器的内存策略。</span>

## 5 小结

- **动态表删除**：naive「删到一半缩一半」会引发扩缩震荡，摊还退化 $O(n)$。
- **修正设计**：扩容阈值 $\alpha = 1$，缩容阈值 $\alpha = 1/4$，错开缓冲。
- **两段式势能** $\Phi$：$\alpha \ge 1/2$ 用 $2num-size$，$\alpha < 1/2$ 用 $size/2-num$，恒非负。
- 插入摊还 3、删除摊还 ≤ 2，扩容/缩容实际代价被势能精确吞掉——总摊还 $O(1)$。
- 「倍增 + 四分之一缩」是避免震荡的普适设计，现代容器（vector）即采用此策略。

在下一课，我们厘清一个关键区别——**摊还分析与平均情况分析**：两者都算「平均」，但一个是确定性上界、一个是概率期望，混用会出大错。
