## 为什么从势能法开始

核算法给「每个元素/每个位」存钱，但有些结构没法按元素分账——比如动态表的扩容。**势能法**用一个**全局函数** $\Phi$（势能）跟踪结构的整体状态，把「存储」变成「状态函数」：操作前势能高，操作后势能低，差值就是这笔操作的「预支」或「偿还」。<span class="marginnote">势能法比核算法更灵活：不需要设计「每个元素存多少钱」，只要找到一个「随状态自然变化」的函数 $\Phi$ 即可。它是摊还分析三种方法里最强大、最通用的一个，也是后面动态表、splay 树、并查集分析的标准工具。</span>

这一课讲势能法的一般框架，然后以**动态表**（vector）为主线——它同时是下一课「动态表」的前置。

## 1 势能法框架

设结构经历 $n$ 次操作，操作前状态为 $D_{i-1}$，操作后为 $D_i$。定义**势能函数** $\Phi(D)$（非负实数），第 $i$ 次操作的**摊还代价**为

$$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$$

即「摊还 = 实际代价 + 势能变化」。若 $\Phi(D_n) \ge \Phi(D_0)$（势能终态不降，或 $D_0$ 势能为 0 且终态非负），则

$$\sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0) \ge \sum_{i=1}^{n} c_i$$

总摊还 ≥ 总实际——摊还代价给出上界。<span class="marginnote">势能法的核心是选 $\Phi$：它不参与算法本身，只是一个「分析工具」。理想势能的特点是「贵操作前势能高、操作后势能低」，从而把贵操作的实际代价摊平到前面的便宜操作里。选错了 $\Phi$（如不满足非负/终态不降），上界就失效。</span>

**辨析｜易错点：** 势能函数的选择不是「唯一的」，也不是「算法的一部分」。同一个结构可以有很多合法的 $\Phi$，给出不同的（但都正确的）摊还上界。势能法是「分析工具」，不是「算法步骤」——不要在代码里实现 $\Phi$，它只在证明里存在。

## 2 数值算例：动态表连续插入的账本

用一个容量从 1 开始的动态表连续插入 8 个元素，逐次对账。容量 $size$、元素数 $num$、势能 $\Phi = 2num - size$。

- 插 1：$num=1, size=1$，扩容（$c = 1$）。$\Phi$ 从 0 到 0，$\hat c = 1$。
- 插 2：$num=2, size=2$，扩容（$c = 2$，拷 1 放 1）。$\Phi$ 从 0 到 $2\cdot2-2=2$？不——插 2 前 $num=1, size=1$，$\Phi=1$；扩容后 $num=2, size=2$，$\Phi = 0$。$\hat c = 2 + (0-1) = 1$。
- 插 3：$num=3, size=4$，不扩容（$c=1$）。$\Phi$ 从 0 到 $6-4=2$，$\hat c = 1+2 = 3$。
- 插 4：$num=4, size=4$，不扩容（$c=1$）。$\Phi$ 从 2 到 $8-4=4$，$\hat c = 1+2 = 3$。
- 插 5：$num=5, size=8$，扩容（$c = 5$）。$\Phi$ 从 4 到 $10-8=2$，$\hat c = 5 + (2-4) = 3$。
- 插 6、7、8：类似，扩容那次 $\hat c = 3$ 或 1。

**对账**：每次插入的摊还代价 ≤ 3（扩容那几次被势能抵消到 1 或 3），$n$ 次总摊还 $O(n)$，平均每次 $O(1)$。<span class="marginnote">注意插 5 那次：实际代价 5（拷 4 个旧元素 + 放新元素），但势能从 4 跌到 2，摊还只剩 3——「前面插 3、4 时多付的势能」在这里部分偿还。扩容越贵，之前攒的势能越多，抵消得越干净——势能法的「借贷」机制在这里表现得淋漓尽致。</span>

## 3 动态表：扩容问题

**动态表（dynamic table）**：数组在插入时若满则翻倍扩容（分配新数组、拷贝所有元素）。设当前容量 $size$、元素数 $num$，$num \le size$。

**只插不删**：插入的实际代价——不扩容 $c_i = 1$；扩容 $c_i = num + 1$（拷贝 $num$ 个旧元素 + 放新元素）。

**选势能函数**：$\Phi(D) = 2 \cdot num - size$。

表刚翻倍时：$num = size/2$，$\Phi = 2(size/2) - size = 0$。
表将满时：$num = size$，$\Phi = 2size - size = size$——**势能攒到最大，正好预支扩容的拷贝代价**。

**摊还代价**：设第 $i$ 次插入使 $num$ 从 $num_{i-1}$ 变 $num_i$。

**不扩容**：$c_i = 1$，$\Phi$ 增加 $2$（num 加 1），$\hat{c}_i = 1 + 2 = 3$。
**扩容**（$num_i = size_i = 2 size_{i-1}$，$num_{i-1} = size_{i-1}$）：$c_i = num_{i-1} + 1 = size_{i-1}+1$；$\Phi$ 从 $size_{i-1}$ 降到 $0$，变化 $= -size_{i-1}$。$\hat{c}_i = (size_{i-1}+1) - size_{i-1} = 1$。<span class="marginnote">妙处就在这里：<strong>扩容那次的实际代价虽高达 $O(size)$，但势能恰好跌去 $size$，摊还代价只剩 1</strong>——之前一次次插入时「多付的 2 元势能」在这里一次性偿还。这就是「势能法把贵操作摊平」的直观。</span>

两种情形摊还 ≤ 3，故 $n$ 次插入摊还 $O(n)$，平均每次 $O(1)$。

## 4 公式解析：$\hat{c}_i = c_i + \Delta\Phi$ 的两个例子

**不扩容**：$c_i = 1$，$\Delta\Phi = \Phi(D_i)-\Phi(D_{i-1}) = (2num_i - size) - (2num_{i-1}-size) = 2$，故 $\hat c_i = 3$。

**扩容**：$c_i = num_{i-1}+1$，$\Delta\Phi = 0 - (2 num_{i-1} - size_{i-1}) = 0 - size_{i-1}$（因 $num_{i-1}=size_{i-1}$），故 $\hat c_i = (num_{i-1}+1) - size_{i-1} = 1$。

**第一步，选势能**：$\Phi = 2num - size$ 的关键性质——「满时高、翻倍后低」，势能差精确抵消扩容的拷贝量。
**第二步，算变化**：普通插入 $\Delta\Phi = +2$；扩容 $\Delta\Phi = -size$。
**第三步，验证非负**：$num \ge size/2$（动态表保证负载 ≥ 1/2），故 $\Phi \ge 0$；终态势能 ≥ 初始 0。上界成立。

**要点**：势能函数的选择决定了分析质量。**「满时高、扩容后低」的势能，让扩容的实际代价被精确摊平**——摊还代价恒定（1 或 3），这就是动态表平均 $O(1)$ 的全部秘密。

**辨析｜易错点：** 别把「扩容」的摊还代价记成「等于实际代价」。扩容那次 $\hat c = 1$（几乎免费），因为势能替它付了账。**摊还代价可以远小于实际代价**——只要前面的操作攒够了势。这正是摊还分析「贵在整体而非单次」的体现。

## 5 势能法的另一个经典：栈操作

用势能法重看栈：设 $\Phi(D) = $ 栈中元素个数。PUSH：$\Delta\Phi = +1$，$\hat c = 1 + 1 = 2$；POP：$\Delta\Phi = -1$，$\hat c = 1 - 1 = 0$；MULTIPOP(k)：$\Delta\Phi = -\min(k, |\text{栈}|)$，$\hat c = \min(k,|\text{栈}|) - \min(k,|\text{栈}|) = 0$。势能非负（栈非空才操作），总摊还 $O(n)$。<span class="marginnote">对比核算法：同一个栈，核算法给「每个元素存 1 元」，势能法用「栈大小」当势能——结果完全一致（PUSH 2、POP/MULTIPOP 0）。两种方法给出相同答案，验证了「摊还界不依赖方法」。学会在三种方法间切换，是摊还分析熟手的标志。</span>

## 6 术语速查与三方法对照

| 术语 | 含义 |
| --- | --- |
| 势能函数 $\Phi$ | 描述结构状态的非负函数 |
| 摊还代价 $\hat c_i$ | $c_i + \Phi(D_i) - \Phi(D_{i-1})$ |
| 动态表 | 满则翻倍扩容的数组 |
| 负载因子 | $num/size$，动态表 ≥ 1/2 |
| 聚合分析 | 总代价合计 |
| 核算法 | 逐元素记账 |
| 势能法 | 全局状态函数 |

**辨析｜易错点：** 三种摊还方法不是「三个结论」，而是「同一个结论的三副眼镜」。聚合给总数、核算给逐元素、势能给全局函数——对同一问题它们算出相同的摊还界。做题时先试聚合（最简单），不行再核算/势能；不要把三者当成互斥的方法，而是「哪个直观用哪个」。

## 7 常见疑问快速答疑

**问：势能函数一定存在吗？** 不一定有「好」的——但总有一个平凡的：$\Phi \equiv 0$（所有操作 $\hat c = c$，摊还界退化成普通上界，没意义）。势能法的「好」在于选出能反映「贵操作规律」的 $\Phi$——大多数经典结构（栈、计数器、动态表、splay、并查集）都有自然势能可挖。

**问：$\hat c_i$ 会不会是负数？** 可能——若 $\Phi$ 急剧下降（如扩容那次的 $\Delta\Phi = -size$ 使 $\hat c = 1$，若 $c_i$ 很小则可能为负）。负的摊还代价没问题，只要「累计」非负（终态势能 ≥ 初始）。单步负摊还正是「偿还」的体现。

**问：动态表删除的势能怎么选？** 删除的扩缩容分析是下一课主题，提前剧透：若「删到一半就缩容」，插入与删除交替时可能「缩完又扩、扩完又缩」，势能法要设计「缩容阈值」避免这种振荡。$\Phi = 2num - size$ 只适用于「只插不删」。

**问：势能法和核算法到底哪个更好？** 没有绝对——核算法直观（逐元素记账），势能法通用（全局函数）。栈、计数器两者都容易；动态表、splay、并查集势能法更自然。判断标准：**哪个更容易验证「非负/终态不降」就用哪个**。

**问：摊还分析的结论能用于真实性能预测吗？** 能用于「最坏序列」的保证：任何 $n$ 次操作的总代价有上界，平均每次 $O(1)$。但它是「上界」，实际单次可能远小于摊还值（大多数插入只花 1）。**摊还是「最坏平均」的承诺，不是「典型」的估计**——别拿它当平均性能的预测器。

## 8 小结

- **势能法**：$\hat c_i = c_i + \Phi(D_i) - \Phi(D_{i-1})$；势能非负且终态不降时，总摊还 ≥ 总实际。
- **动态表扩容**：$\Phi = 2num - size$——满时势能最大、翻倍后归零。
- 普通插入摊还 3，扩容摊还 1——扩容的 $O(size)$ 实际代价被势能精确摊平。
- 栈操作：势能 = 栈大小，PUSH 摊还 2、POP/MULTIPOP 摊还 0，与核算法一致。
- 势能函数是「分析工具」不参与算法；选「满时高、贵操作后低」的势能是核心技巧。
- 三种方法（聚合/核算/势能）是同一摊还界的三副眼镜，哪个直观用哪个。
