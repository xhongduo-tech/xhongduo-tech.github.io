# Boyer-Moore 算法：坏字符规则与好后缀规则

## 为什么从 Boyer-Moore 开始

KMP 已经线性，但工程上最快的匹配算法常是 **Boyer-Moore（BM）**：它**从右往左**比对模式，且失配时能**一次跳过多个字符**——在真实文本（英文、代码）上常达到「次线性」表现。<span class="marginnote">BM 的反直觉之处：模式从右往左比，这让「坏字符规则」能把模式「大步滑过」文本——如果模式里根本没有文本中那个字符，整个模式可以直接跳过，$O(m)$ 的位移一步完成。grep、许多文本编辑器的查找，都基于 BM 或其变体（如 Horspool）。</span>

这一课讲 BM 的两条跳转规则：坏字符与好后缀，以及它们如何「取大者」合并。

## 1 从右往左比对

BM 的基本循环：对每个位移 $s$，**从模式右端 $P[m]$ 往左**逐字符比对 $T[s+m]$ 与 $P[m]$。失配时，用规则决定位移推进多少——目标是「跳得越多越好」。

**为什么从右往左**：失配通常发生得早——右侧字符的「信息量」能排除更多位移。若 $T[s+m]$ 是一个模式里根本不含的字符，那么「位移 $s$ 附近的所有位置都必然失配」（因为模式右端必须对上这个字符），可以**跳过整个模式长度**。<span class="marginnote">「从右往左」让 BM 在字符集大的文本（自然语言）上异常高效：命中「模式里没有的字符」的概率高，跳过多。而在字符集小的文本（DNA，4 字符）上效果变差——这是 BM 的一个适用性边界。</span>

**正确性直觉**：为什么「跳步」不会漏掉匹配？关键在于两条规则都不让模式「越过」一个可能的匹配位置。坏字符规则把失配字符对齐到它的最右出现位置——若某个中间位移 $s'$ 真能让 $T[s+j]=c$ 匹配上 $P[j']$，则 $c$ 必然在模式中该位置附近出现，而「最右出现」已经把这类位置排除掉了；好后缀规则同理保证「已匹配的后缀」不被跳过。两规则各自是「安全位移」的充分条件，**取大者依然安全**——这是 BM 从不漏报的理论保证。

**位移的范围**：每次失配至少推进 1 位、最多推进 $m$ 位。最坏情况（模式与文本高度重合、两条规则都算出小位移）会退化接近朴素；但好的实现会在「计算出的位移 ≤ 0」时强制推进一步，既保证终止，也不丢失匹配。

## 2 坏字符规则

**坏字符规则（bad-character rule）**：失配时，设文本字符 $c = T[s+j]$（模式中位置 $j$ 处失配）。若 $c$ 在模式中**最右侧**出现的位置是 $k$（$k < j$），则把模式右移，使 $c$ 对齐到 $k$：

$$\text{shift}_{\text{bc}} = j - k$$

若 $c$ 根本不在模式里（$k$ 不存在），则右移整个模式：$\text{shift}_{\text{bc}} = j$（把模式整个滑过 $c$）。<span class="marginnote">直觉：既然 $c$ 已经与 $P[j]$ 失配，就把 $c$ 与「模式里最近一次出现的 $c$」对齐——如果模式里没有 $c$，那 $c$ 不可能匹配任何位置，模式整体滑过去。这个规则只查「文本字符在模式中的最右位置」——预处理一个「最右出现表」，$O(|\Sigma|)$ 空间。</span>

**预处理**：对每个字符 $c$，记 $\text{last}[c]$ = $c$ 在 $P$ 中**最靠右**的下标（不在则为 0）。

**坏字符算例**：设 $P = \text{EXAMPLE}$（$m=7$）。失配发生在 $j=4$（$P[4]=\text{L}$ 对不上 $T[s+4]$），而 $T[s+4] = \text{P}$，$\text{last}[\text{P}] = 1$（P 在模式中最右出现在下标 1）。则 $\text{shift}_{\text{bc}} = 4 - 1 = 3$——模式右移 3 位，让失配的 P 对齐到 $P[1]$。若失配字符是模式里完全没有的（如 Z），则 $\text{shift}_{\text{bc}} = 4$，模式整体滑过那个字符。

**last 表怎么建**：扫描模式一遍，每遇到字符 $c$ 就更新 $\text{last}[c]$ = 当前下标——$O(m)$ 时间、$O(|\Sigma|)$ 空间。注意「最右出现」是扫描的自然产物：后出现的覆盖先出现的。对 ASCII 文本 $|\Sigma| = 256$，这张表就是一个 256 个整数的小数组，构建成本几乎可以忽略。

## 3 好后缀规则

**好后缀规则（good-suffix rule）**：失配时，已匹配的「好后缀」$P[j+1..m]$（模式右侧已与文本对齐的部分）。把模式右移，使「好后缀」在模式里更早的某个位置重新对齐——即找「$P$ 中在 $j$ 之前出现的、等于好后缀的片段」（或好后缀的真前缀是 $P$ 的后缀的情况）。

$$\text{shift}_{\text{gs}} = m - \max\{ k \le m : P[k+1..k + (m-j)] \text{ 是好后缀，或好后缀的后缀是 } P \text{ 的前缀} \}$$

规则较复杂，预处理基于「前缀函数」的变体计算「后缀匹配」表。<span class="marginnote">好后缀规则的直觉：失配处右边已经匹配的部分「不能浪费」——新位移必须让「已匹配后缀」仍能对齐。它利用「模式的内部结构」（后缀与子串的重叠），在坏字符跳不动时兜底。两条规则<strong>取较大者</strong>作为实际位移：$\text{shift} = \max(\text{shift}_{\text{bc}}, \text{shift}_{\text{gs}})$。</span>

**好后缀表怎么建**：需要每个失配位置 $j$ 的安全位移。经典做法先算「后缀数组」——对每个后缀求它与模式某个前缀的最大公共长度，再倒推出每个 $j$ 的位移。全程 $O(m)$ 时间、$O(m)$ 空间，但实现比 last 表复杂一个量级——这正是许多工程实现只用坏字符规则（Horspool 变体）的现实原因。

**辨析｜易错点：** 两条规则都要求「位移 > 0」——若计算出的位移 ≤ 0，至少推进一步，避免死循环。**「取大者」保证不丢匹配**：坏字符与好后缀各是「不跳过潜在匹配」的充分条件，取大者仍不越界。

**两条规则各管一摊**：坏字符管「文本字符不在模式里」——这是自然语言里最常见的情形，负责大跳跃；好后缀管「模式内部后缀重复」——当模式含重复后缀时，它能给出坏字符给不出的安全位移。只靠坏字符（Horspool）在多数文本上已足够快，但会丢掉「后缀重复」带来的最坏保护。

**好后缀算例**：$P = \text{ABABAB}$，失配在 $j=1$（$P[1]=\text{B}$ 对不上文本），已匹配后缀 $P[2..5]=\text{ABAB}$。它在模式中更早出现于 $P[0..3]=\text{ABAB}$，位移 $= j+1 - 0 = 2$——让模式开头的 ABAB 重新对齐文本里已匹配的 ABAB，重复模式得以继续利用。

## 4 完整算例：坏字符与好后缀的配合

在文本 $T = \text{GCAAGAGACG}$ 中查找模式 $P = \text{AAGAG}$（$m=5$）。预处理得 $\text{last}[\text{A}] = 3$、$\text{last}[\text{G}] = 4$。

- **位移 $s=0$**：对齐 `GCAAG`。从右往左：$T[4]=\text{G}$ 对 $P[4]=\text{G}$ 匹配；$T[3]=\text{A}$ 对 $P[3]=\text{A}$ 匹配；$T[2]=\text{A}$ 对 $P[2]=\text{G}$ **失配**，$j=2$。坏字符 $c=\text{A}$，$\text{last}[\text{A}]=3$，$\text{shift}_{\text{bc}} = 2 - 3 = -1 \le 0$——坏字符跳不动。交给好后缀：已匹配后缀 $P[3..4]=\text{AG}$，在模式中更早出现于 $P[1..2]$，位移 $\text{shift}_{\text{gs}} = 2$。取大者：$\text{shift} = 2$。
- **位移 $s=2$**：对齐 `AAGAG`。从右往左：$T[6]=\text{G}$ 对 $P[4]=\text{G}$、$T[5]=\text{A}$ 对 $P[3]=\text{A}$、$T[4]=\text{G}$ 对 $P[2]=\text{G}$、$T[3]=\text{A}$ 对 $P[1]=\text{A}$、$T[2]=\text{A}$ 对 $P[0]=\text{A}$——全部匹配，命中位置 2。<span class="marginnote">这个算例展示了 BM 的「分工」：坏字符在字符集大、模式不含该字符时跳得最狠；而当失配字符恰好是模式里有的字符（本例的 A）时，坏字符算出负位移，就得靠好后缀兜底。两条规则互相补位，正是 BM 设计「取大者」的原因。</span>

## 5 公式解析：最坏与期望复杂度

**期望**：在自然语言文本上，坏字符规则使平均位移远大于 1，匹配常**次线性**（平均 $O(n/m)$ 量级）。
**最坏**：$O(nm)$——构造「模式与文本大量重合、坏字符规则总跳不动」的输入（如 $T = a^n$、$P = a^m b$）。<span class="marginnote">BM 的「最坏 $O(nm)$」曾是其软肋；后来 Galil 的改进加上「好后缀 + 记忆化」可到 $O(n)$ 最坏。工程实现常用「Boyer-Moore-Horspool」变体（只用坏字符规则，常数更小），在多数文本上表现极佳但最坏无线性保证。</span>

$$\text{shift} = \max(\underbrace{j - \text{last}[T[s+j]]}_{\text{坏字符}}, \underbrace{\text{好后缀位移}}_{\text{好后缀}})$$

- **第一步，坏字符**：文本失配字符 $c$ 在模式最右位置 $\text{last}[c]$；$j - \text{last}[c]$ 是「让 $c$ 对齐」的位移。
- **第二步，好后缀**：用「已匹配后缀」在模式中的重出现位置计算位移。
- **第三步，取大者**：两条规则都保证「不跳过匹配」，取较大位移最大化跳过量。

**要点**：BM 的性能来自「每次失配尽量多跳」——坏字符管「字符不在模式」的大跳跃，好后缀管「后缀重复」的小调整，取大者兼顾两者。<span class="marginnote">对比 KMP：KMP 每次回退但文本指针永不回退，最坏线性；BM 每次位移大步跳，平均快但最坏可能退化。工程选择是「平均优先用 BM、最坏保证用 KMP（或 Two-Way）」。理解两者的权衡，是字符串匹配选型的核心。</span>

**数值感受**：设文本 $n = 10^6$、模式 $m = 10$、字符集 256。朴素匹配最坏约 $10^7$ 次字符比较；BM 在自然语言上平均每次位移跳过「$m$ 量级」，总比较次数常低于 $10^5$，比朴素快上百倍。「次线性」不是理论幻觉，而是文本匹配的真实经验——这正是 grep、编辑器把 BM 系算法当作默认选择的现实原因。

## 6 术语速查：字符串匹配算法三兄弟对照

| 算法 | 比对方向 | 失配时做什么 | 复杂度 |
| --- | --- | --- | --- |
| 朴素匹配 | 从左往右 | 位移 +1 | $O(nm)$ 最坏 |
| KMP | 从左往右 | 用前缀函数回退模式，文本指针不回退 | $O(n+m)$ 最坏线性 |
| Boyer-Moore | 从右往左 | 坏字符 / 好后缀取大者跳步 | 期望次线性，最坏 $O(nm)$ |

**辨析｜易错点：** 「BM 一定比 KMP 快」是常见误读。BM 的优势建立在「字符集大、模式不含的字符多」的自然语言文本上；在 DNA（4 字符）、二进制等小字符集上，坏字符规则频繁算出小位移甚至负位移，BM 的优势消失。选型要看文本特征，不是看算法名气。

**选型建议**：文本很大、模式较长、字符集较大，优先 BM；要求最坏线性保证，选 KMP；模式很短（1–3 个字符），朴素匹配的常数已经够小，直接朴素即可。工程上的「正确选择」常取决于文本特征，而不是算法名气。

## 7 术语速查

| 术语 | 含义 |
| --- | --- |
| 坏字符规则 | 失配字符对齐到它在模式中的最右出现位置 |
| 好后缀规则 | 已匹配后缀在模式中更早的位置重新对齐 |
| $\text{last}[c]$ | 字符 $c$ 在模式中的最右下标 |
| Horspool 变体 | 只用坏字符规则、常数更小的工程简化 |
| 次线性匹配 | 平均比较次数远小于文本长度 $n$ |
| Galil 改进 | 给好后缀加上记忆化，把最坏压回 $O(n)$ |

## 8 小结

- **BM**：从右往左比对模式；失配时用规则决定位移。
- **坏字符规则**：失配字符对齐到它在模式中的最右出现（不在则整模式滑过）——大跳跃主力。
- **好后缀规则**：已匹配后缀在模式中更早重对齐——兜底与微调。
- 位移 = $\max(\text{坏字符}, \text{好后缀})$；期望次线性、最坏 $O(nm)$（可改进）。
- 正确性来自「两条规则都安全、取大者仍安全」；负位移时强制推进一位。
- 工程上 grep/编辑器常用 BM-Horspool 变体；KMP 与 BM 是「最坏 vs 平均」的选型对照。
- 预处理成本很低：last 表 $O(m)$ 时间、$O(|\Sigma|)$ 空间；好后缀表 $O(m)$ 时间、$O(m)$ 空间，实现更复杂。
- 变体谱系：Horspool（只坏字符）、Galil 改进（最坏 $O(n)$）、Two-Way（最坏线性 + 常数小），按需取用。
- 正确性根基：两条规则都安全、取大者仍安全；位移 ≤ 0 时强制推进，保证终止。
