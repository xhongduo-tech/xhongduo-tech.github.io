# Boyer-Moore 算法：坏字符规则与好后缀规则

## 为什么从 Boyer-Moore 开始

KMP 已经线性，但工程上最快的匹配算法常是 **Boyer-Moore（BM）**：它**从右往左**比对模式，且失配时能**一次跳过多个字符**——在真实文本（英文、代码）上常达到「次线性」表现。<span class="marginnote">BM 的反直觉之处：模式从右往左比，这让「坏字符规则」能把模式「大步滑过」文本——如果模式里根本没有文本中那个字符，整个模式可以直接跳过，$O(m)$ 的位移一步完成。grep、许多文本编辑器的查找，都基于 BM 或其变体（如 Horspool）。</span>

这一课讲 BM 的两条跳转规则：坏字符与好后缀，以及它们如何「取大者」合并。

## 1 从右往左比对

BM 的基本循环：对每个位移 $s$，**从模式右端 $P[m]$ 往左**逐字符比对 $T[s+m]$ 与 $P[m]$。失配时，用规则决定位移推进多少——目标是「跳得越多越好」。

**为什么从右往左**：失配通常发生得早——右侧字符的「信息量」能排除更多位移。若 $T[s+m]$ 是一个模式里根本不含的字符，那么「位移 $s$ 附近的所有位置都必然失配」（因为模式右端必须对上这个字符），可以**跳过整个模式长度**。<span class="marginnote">「从右往左」让 BM 在字符集大的文本（自然语言）上异常高效：命中「模式里没有的字符」的概率高，跳过多。而在字符集小的文本（DNA，4 字符）上效果变差——这是 BM 的一个适用性边界。</span>

## 2 坏字符规则

**坏字符规则（bad-character rule）**：失配时，设文本字符 $c = T[s+j]$（模式中位置 $j$ 处失配）。若 $c$ 在模式中**最右侧**出现的位置是 $k$（$k < j$），则把模式右移，使 $c$ 对齐到 $k$：

$$\text{shift}_{\text{bc}} = j - k$$

若 $c$ 根本不在模式里（$k$ 不存在），则右移整个模式：$\text{shift}_{\text{bc}} = j$（把模式整个滑过 $c$）。<span class="marginnote">直觉：既然 $c$ 已经与 $P[j]$ 失配，就把 $c$ 与「模式里最近一次出现的 $c$」对齐——如果模式里没有 $c$，那 $c$ 不可能匹配任何位置，模式整体滑过去。这个规则只查「文本字符在模式中的最右位置」——预处理一个「最右出现表」，$O(|\Sigma|)$ 空间。</span>

**预处理**：对每个字符 $c$，记 $\text{last}[c]$ = $c$ 在 $P$ 中**最靠右**的下标（不在则为 0）。

## 3 好后缀规则

**好后缀规则（good-suffix rule）**：失配时，已匹配的「好后缀」$P[j+1..m]$（模式右侧已与文本对齐的部分）。把模式右移，使「好后缀」在模式里更早的某个位置重新对齐——即找「$P$ 中在 $j$ 之前出现的、等于好后缀的片段」（或好后缀的真前缀是 $P$ 的后缀的情况）。

$$\text{shift}_{\text{gs}} = m - \max\{ k \le m : P[k+1..k + (m-j)] \text{ 是好后缀，或好后缀的后缀是 } P \text{ 的前缀} \}$$

规则较复杂，预处理基于「前缀函数」的变体计算「后缀匹配」表。<span class="marginnote">好后缀规则的直觉：失配处右边已经匹配的部分「不能浪费」——新位移必须让「已匹配后缀」仍能对齐。它利用「模式的内部结构」（后缀与子串的重叠），在坏字符跳不动时兜底。两条规则<strong>取较大者</strong>作为实际位移：$\text{shift} = \max(\text{shift}_{\text{bc}}, \text{shift}_{\text{gs}})$。</span>

**辨析｜易错点：** 两条规则都要求「位移 > 0」——若计算出的位移 ≤ 0，至少推进一步，避免死循环。**「取大者」保证不丢匹配**：坏字符与好后缀各是「不跳过潜在匹配」的充分条件，取大者仍不越界。

## 4 公式解析：最坏与期望复杂度

**期望**：在自然语言文本上，坏字符规则使平均位移远大于 1，匹配常**次线性**（平均 $O(n/m)$ 量级）。
**最坏**：$O(nm)$——构造「模式与文本大量重合、坏字符规则总跳不动」的输入（如 $T = a^n$、$P = a^m b$）。<span class="marginnote">BM 的「最坏 $O(nm)$」曾是其软肋；后来 Galil 的改进加上「好后缀 + 记忆化」可到 $O(n)$ 最坏。工程实现常用「Boyer-Moore-Horspool」变体（只用坏字符规则，常数更小），在多数文本上表现极佳但最坏无线性保证。</span>

$$\text{shift} = \max(\underbrace{j - \text{last}[T[s+j]]}_{\text{坏字符}}, \underbrace{\text{好后缀位移}}_{\text{好后缀}})$$

- **第一步，坏字符**：文本失配字符 $c$ 在模式最右位置 $\text{last}[c]$；$j - \text{last}[c]$ 是「让 $c$ 对齐」的位移。
- **第二步，好后缀**：用「已匹配后缀」在模式中的重出现位置计算位移。
- **第三步，取大者**：两条规则都保证「不跳过匹配」，取较大位移最大化跳过量。

**要点**：BM 的性能来自「每次失配尽量多跳」——坏字符管「字符不在模式」的大跳跃，好后缀管「后缀重复」的小调整，取大者兼顾两者。<span class="marginnote">对比 KMP：KMP 每次回退但文本指针永不回退，最坏线性；BM 每次位移大步跳，平均快但最坏可能退化。工程选择是「平均优先用 BM、最坏保证用 KMP（或 Two-Way）」。理解两者的权衡，是字符串匹配选型的核心。</span>

## 5 小结

- **BM**：从右往左比对模式；失配时用规则决定位移。
- **坏字符规则**：失配字符对齐到它在模式中的最右出现（不在则整模式滑过）——大跳跃主力。
- **好后缀规则**：已匹配后缀在模式中更早重对齐——兜底与微调。
- 位移 = $\max(\text{坏字符}, \text{好后缀})$；期望次线性、最坏 $O(nm)$（可改进）。
- 工程上 grep/编辑器常用 BM-Horspool 变体；KMP 与 BM 是「最坏 vs 平均」的选型对照。
