## 为什么从哈夫曼编码开始

把「aaaaabbbccd」存成二进制，普通定长编码（如 ASCII 每字符 8 位）浪费空间——因为频率差异巨大。**哈夫曼编码**给高频字符短的码字、低频字符长的码字，使总编码长度最小。<span class="marginnote">它是数据压缩的基石：ZIP、PNG、JPEG、MP3 的熵编码阶段都用哈夫曼（或其变体）。它也是「贪心选择性质」的第二个标准案例，且这次贪心发生在<strong>构造树</strong>而非排序上——每步把两个最小频率的节点合成一个新节点，用优先队列实现。</span>

这一课讲清楚三件事：前缀码为什么必要、哈夫曼算法怎么构造、以及「合并两个最小频率」为何必然最优。

## 1 前缀码：无歧义解码的关键

**前缀码（prefix code）**：每个字符的码字都不是其他码字的前缀。这样解码无需分隔符——从左到右扫描二进制流，一旦匹配某码字就输出对应字符，永不歧义。

反例：若 `a` 的码字 = `0`、`b` 的码字 = `01`，则流「01」无法确定是「b」还是「a」+「1 开头的某码」。**前缀性质保证唯一解码**。<span class="marginnote">一棵<strong>满二叉树</strong>天然给出前缀码：每个叶子对应一个字符，路径上的「左0右1」就是码字；内部节点都不是码字，所以没有码字是另一个的前缀。把「找最优前缀码」翻译成「找最优满二叉树」，哈夫曼就有了树形舞台。</span>

给定字符集 $C$ 与频率 $f(c)$，一棵前缀码树 $T$ 的**总编码长度**为

$$B(T) = \sum_{c \in C} f(c) \cdot d_T(c)$$

其中 $d_T(c)$ 是 $c$ 在树中的深度（码字长度）。**目标**：构造满二叉树使 $B(T)$ 最小。

## 2 哈夫曼算法：自底向上合并

贪心策略：**每次把频率最小的两个字符/节点合并成新节点，其频率为两者之和，继续**。

```text
HUFFMAN(C):
    n = |C|
    Q = C                              // 按频率建最小堆
    for i = 1 to n - 1:
        新建节点 z
        x = EXTRACT-MIN(Q)             // 频率最小的两个
        y = EXTRACT-MIN(Q)
        z.left = x;  z.right = y
        z.freq = x.freq + y.freq
        INSERT(Q, z)                   // 合并结果放回堆
    return EXTRACT-MIN(Q)              // 唯一的根
```

以 $O(n)$ 为例：先合并 f+e=14，再合并 c+b=25，再 d+14=30，再 45 与 25 → 70，最后 30 与 70 → 100。最终 a 的码最短（1 位），f、e 的码最长（4 位）。<span class="marginnote">最小堆让每次「取两个最小的」只需 $O(\log n)$；$n-1$ 次合并总时间 $O(n\log n)$。若提前对频率排序，用两个队列可降到 $O(n)$——但 $O(n\log n)$ 的堆实现已足够清晰通用。</span>

## 3 正确性：两个引理

**引理 1（贪心选择性质）**：设 $x, y$ 是频率最小的两个字符，则存在一棵最优前缀码树中，$x$ 与 $y$ 是**兄弟叶子**（深度最大的一对）。<span class="marginnote">证明直觉：把任意最优树中最深的两片叶子 $a, b$ 与 $x, y$ 交换。因 $f(x), f(y) \le f(a), f(b)$ 且 $a, b$ 在更深位置，交换后总编码长度 $B$ 不增——于是存在「$x,y$ 在最深处且互为兄弟」的最优树。这是交换论证的又一次登场。</span>

**引理 2（最优子结构）**：把 $x, y$ 合并成新节点 $z$（频率 $f(x)+f(y)$），得到新字符集 $C'$。则 $C'$ 的最优树 $T'$ 对应 $C$ 的最优树 $T$——把 $T'$ 中叶子 $z$ 替换为「$z$ 的孩子 $x, y$」即得 $T$。<span class="marginnote">引理 2 的剪贴论证：若 $C$ 有比「$T'$ 替换 $z$」更好的树，则合并 $x,y$ 后对应一棵比 $T'$ 更好的 $C'$ 树，矛盾。两个引理合起来：贪心第一步（合并最小两字符合法）+ 剩余问题同构（递归贪心）——整棵哈夫曼树最优。</span>

## 4 公式解析：$B(T) = \sum f(c)d_T(c)$ 的极值结构

最优前缀码的代价函数是

$$B(T) = \sum_{c \in C} f(c) \cdot d_T(c) = \sum_{\text{内部节点 } u} f(\text{合并后叶子频率之和})$$

- **第一步，等价变形**：每一对「兄弟叶子合并」把频率累加到父节点；$B(T)$ 可以重写为「所有内部节点的合并频率之和」——因为每个叶子 $c$ 对 $B$ 的贡献 $f(c)d_T(c)$ 等于它在其每个祖先处的频率被计一次。
- **第二步，贪心对应**：哈夫曼每次合并两个最小频率，本质是「按合并代价从小到大累加」——与「让大频率的叶子尽量浅」等价。
- **第三步，最优性**：大频率字符浅（码短）、小频率字符深（码长），这正是 $B(T)$ 最小的树结构——由引理 1、2 保证。

**辨析｜易错点：** 哈夫曼树是**满二叉树**（每个内部节点恰有两个孩子），但不是**平衡树**。频率极不均匀时它可以长成一条链——这是正确的，因为高频字符就该在最浅处。**别用「平衡」去要求哈夫曼树**，它是「按频率定深浅」的树，不是「按层填满」的树。

## 5 应用与延伸

- **静态压缩**：两趟扫描（统计频率 → 建树编码），用于 ZIP、PNG。
- **自适应哈夫曼**：一遍扫描边统计边更新，用于实时传输。
- **哈夫曼 vs 最优 BST 的对照**：最优 BST 最小化「搜索代价」，哈夫曼最小化「编码长度」；前者叶子带概率、查询外部，后者所有字符都是叶子、编码内部节点。<span class="marginnote">哈夫曼编码与信息论的「熵」直接相连：当频率恰为 $2^{-k}$ 时，最优前缀码长度等于自信息 $-\log f(c)$，总长接近 $n \times H$（熵）。这解释了「压缩极限」——熵是数据压缩的理论下限，哈夫曼逼近它但不一定达到（需要算术编码才能精确达到）。</span>

**辨析｜易错点：** 哈夫曼要求**已知字符频率**。若频率未知或动态变化，静态哈夫曼要先传码表（额外开销）；工程上常与「自适应」或「算术编码」结合。<span class="marginnote">代码里最容易错的是「把频率当权重放错堆的方向」——最小堆存的是「最小频率优先合并」。若用最大堆，树会左右颠倒、编码失效。先想清楚「合并两个最小的」的语义，再写堆。</span>

## 6 小结

- **前缀码**：码字互不为前缀，解码唯一；满二叉树 = 前缀码。
- **哈夫曼算法**：最小堆反复合并两个最小频率节点，$O(n\log n)$。
- **正确性**：引理 1（贪心选择：最小两字符合并进最优树）+ 引理 2（最优子结构：合并后同构递归）。
- 代价 $B(T) = \sum f(c)d_T(c)$：高频浅、低频深；树是满二叉树但不必平衡。
- 应用：ZIP/PNG/MP3 的熵编码；逼近熵的压缩极限，算术编码可精确达到。

在下一课，我们把贪心理论升到最高抽象层——**拟阵（Matroid）**：一个统一「何时贪心正确」的代数框架，把很多看似无关的问题收进同一把伞下。
