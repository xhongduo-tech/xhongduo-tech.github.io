## 为什么从哈密顿回路开始

1859 年哈密顿提出的「环游世界」游戏：能否走遍每个顶点恰好一次并回到起点？这个有着近两百年历史的问题，1970 年代被证明是 **NP 完全**。<span class="marginnote">哈密顿回路（HAM-CYCLE）的 NPC 证明是归约构造的又一经典——但它和顶点覆盖不同：不再用「配额」，而是用<strong>子图构件（widget）</strong>。归约从 3-SAT 出发，把变量、子句翻译成精心设计的子图，迫使任何哈密顿回路必须「编码」一组满足赋值。</span>

这一课讲问题的复杂性地位、为什么「欧拉回路容易而哈密顿回路难」的对比，以及归约的思路（widget 构造的高层理解）。

## 1 问题与它的「近亲对比」

**哈密顿回路（HAM-CYCLE）**：给定无向图 $G$，是否存在经过每个顶点**恰好一次**并回到起点的简单回路？

- **欧拉回路**：经过每条**边**恰好一次——欧拉定理给出多项式判定（所有顶点度数为偶数）——**容易**。
- **哈密顿回路**：经过每个**顶点**恰好一次——**NPC**。

<span class="marginnote">欧拉 vs 哈密顿的对比是复杂性理论的经典开场：一个看「边」、一个看「顶点」，一个有多项式刻画、一个没有（除非 P=NP）。「只是换个对象看」就能从易变难——这就是组合问题的诡异性。</span>

**$\in NP$**：证书 = 顶点序列；验证器检查：长度 = $|V|$、无重复、相邻顶点有边、首尾相连——$O(V)$ 检查，多项式。

## 2 归约思路：从 3-SAT 用 widget

要证 HAM-CYCLE 是 NPC，构造 3-SAT $\le_P$ HAM-CYCLE。给定 3-CNF $\phi$，构造图 $G$：

**核心构件**：一个「widget」——小型的固定子图，其哈密顿路径只有有限种走法，用作「逻辑开关」。归约的关键步骤是设计「变量构件」与「子句构件」的 widget，并证明：$G$ 有哈密顿回路 ⟺ $\phi$ 可满足。<span class="marginnote">widget 构造的直觉：把「变量赋值」编码成 widget 的「左右两种走法」；把「子句满足」编码成「子句 widget 至少有一条边被『选中的走法』覆盖」。哈密顿回路必须「穿过」所有 widget——每种合法穿法对应一组赋值，而子句 widget 的约束确保至少一个文字为真。</span>

**不展开全部细节**（CLRS 的构造相当复杂），关键理解是：

- **变量 widget**：串联所有变量的「轨道」，每条轨道有「左走/右走」两种方式——对应 $x_i = true/false$。哈密顿回路必须逐段选择一种走法。
- **子句 widget**：3 个文字各接一个「触发口」；若变量走法使该文字为真，则对应的触发口「对齐」，子句 widget 能被回路覆盖。若三个文字都为假，子句 widget 无法被覆盖——回路不存在。<span class="marginnote">「真文字对齐触发口」是归约的翻译核心：把「子句至少一真」翻译成「子句 widget 至少一个触发口被覆盖」。这需要变量 widget 的走法与子句 widget 的拓扑精确咬合——归约构造的难点全在这里，也是 CLRS 花大篇幅画图的原因。</span>

## 3 公式解析：归约的「方向」与「等价性」检查

无论 widget 多复杂，归约证明的骨架不变：

$$\phi \text{ 可满足} \iff G \text{ 有哈密顿回路}$$

- **第一步，$(\Rightarrow)$**：给定满足赋值，按「真变量左走、假变量右走」的规则穿过变量 widget，并选择子句 widget 中「被真文字对齐」的路径——构造出一条完整哈密顿回路。
- **第二步，$(\Leftarrow)$**：给定哈密顿回路，读取出每个变量 widget 的走法 → 得到一组赋值；因为回路必然覆盖了所有子句 widget，每个子句至少一个触发口被对齐 → 每个子句至少一真 → 公式可满足。
- **第三步，多项式性**：图 $G$ 的规模是公式规模的常数倍（每个变量/子句对应常数个顶点边），构造可多项式时间完成——归约合法。

**要点**：等价性的两个方向 + 构造的多项式性，是任何归约证明的三件套。widget 只是把「逻辑」翻译成「图结构」的载体。<span class="marginnote">「等价性 + 多项式构造」这个骨架与顶点覆盖的证明完全同构——换的是构件，不变的是逻辑结构。学会识别「三件套」，任何 NPC 证明都能拆解成「验证、构造、双向论证」三步，不再被 widget 的复杂度吓住。</span>

## 4 哈密顿回路家族的 NPC 成员

- **有向哈密顿回路**：同样 NPC（无向可归约到有向，或反之）。
- **哈密顿路径**（不需回到起点）：NPC。
- **旅行商问题（TSP）**：找「总长度 ≤ 某值的哈密顿回路」——在下一课，从 HAM-CYCLE 归约。<span class="marginnote">哈密顿回路是 TSP 的「骨架」：TSP 就是在带权完全图上找「最短哈密顿回路」。所以「HAM-CYCLE ≤ TSP」的归约很自然——把 TSP 的判定版翻译成 HAM-CYCLE 的实例。理解了 HAM-CYCLE 的 NPC，TSP 的 NPC 就顺理成章。</span>

## 5 小结

- **哈密顿回路**：经过每顶点恰好一次的回路；证书验证 $O(V)$——$\in NP$。
- **欧拉回路容易、哈密顿回路难**：一个看边、一个看顶点，复杂性天差地别。
- **NPC 证明**：3-SAT $\le_P$ HAM-CYCLE，用 widget 构件把公式翻译成图。
- 归约三件套：等价性两个方向 + 构造多项式性——任何 NPC 证明的骨架。
- HAM-CYCLE 是 TSP 的骨架，TSP 的 NPC 由此归约而来。
