## 为什么从哈密顿回路开始

1859 年哈密顿提出的「环游世界」游戏：能否走遍每个顶点恰好一次并回到起点？这个有着近两百年历史的问题，1970 年代被证明是 **NP 完全**。<span class="marginnote">哈密顿回路（HAM-CYCLE）的 NPC 证明是归约构造的又一经典——但它和顶点覆盖不同：不再用「配额」，而是用<strong>子图构件（widget）</strong>。归约从 3-SAT 出发，把变量、子句翻译成精心设计的子图，迫使任何哈密顿回路必须「编码」一组满足赋值。</span>

这一课讲问题的复杂性地位、为什么「欧拉回路容易而哈密顿回路难」的对比，以及归约的思路（widget 构造的高层理解）。

## 1 问题与它的「近亲对比」

**哈密顿回路（HAM-CYCLE）**：给定无向图 $G$，是否存在经过每个顶点**恰好一次**并回到起点的简单回路？

**欧拉回路**：经过每条**边**恰好一次——欧拉定理给出多项式判定（所有顶点度数为偶数）——**容易**。
**哈密顿回路**：经过每个**顶点**恰好一次——**NPC**。

<span class="marginnote">欧拉 vs 哈密顿的对比是复杂性理论的经典开场：一个看「边」、一个看「顶点」，一个有多项式刻画、一个没有（除非 P=NP）。「只是换个对象看」就能从易变难——这就是组合问题的诡异性。</span>

**$\in NP$**：证书 = 顶点序列；验证器检查：长度 = $|V|$、无重复、相邻顶点有边、首尾相连——$O(V)$ 检查，多项式。<span class="marginnote">注意验证只检查「这是一条哈密顿回路」，不检查「是不是最优」——判定版问的是「存在不存在」。这和 TSP 的优化版（求最短）是两回事；把优化版转成判定版（是否存在长度 ≤ k 的回路）是 NPC 证明的标准手法，下一课讲 TSP 时会看到。</span>

**辨析｜易错点：** 「欧拉回路」与「哈密顿回路」的名字只差两个字，但判定难度天差地别。记忆锚点：**欧拉看边（Euler 的 e 联想到 edge），哈密顿看顶点（Hamiltonian 的 h 联想到 hop，一步一个顶点）**。做题时先确认题目在问「每边一次」还是「每点一次」，答案复杂度完全不同。

**一个立刻想到的尝试**：DFS 回溯能不能解决？朴素回溯是尝试所有排列，$O(n!)$ 指数级；加剪枝也只是常数改进，最坏依旧。贪心（每步走向最近的未访问顶点）能快速找到一条「尽量长」的路径，但不能保证走遍每个顶点、更不能保证回到起点——这正是旅行商最近邻近似（第十二篇）的来源。「看着能贪心，实际是 NPC」是哈密顿回路给我们的又一个提醒。

**判定版 vs 构造版**：本课问的是「是否存在」，这是判定版；「把回路实际找出来」是构造版。两者难度相同——NPC 证明通常先处理判定版，构造版可由判定版迭代推出（逐步固定边、重复判定）。「先证判定、再谈构造」的分工在复杂性理论里非常标准，近似算法课会再面对构造版。

## 2 归约思路：从 3-SAT 用 widget

要证 HAM-CYCLE 是 NPC，构造 3-SAT $\le_P$ HAM-CYCLE。给定 3-CNF $\phi$，构造图 $G$：

**核心构件**：一个「widget」——小型的固定子图，其哈密顿路径只有有限种走法，用作「逻辑开关」。归约的关键步骤是设计「变量构件」与「子句构件」的 widget，并证明：$G$ 有哈密顿回路 ⟺ $\phi$ 可满足。<span class="marginnote">widget 构造的直觉：把「变量赋值」编码成 widget 的「左右两种走法」；把「子句满足」编码成「子句 widget 至少有一条边被『选中的走法』覆盖」。哈密顿回路必须「穿过」所有 widget——每种合法穿法对应一组赋值，而子句 widget 的约束确保至少一个文字为真。</span>

**不展开全部细节**（CLRS 的构造相当复杂），关键理解是：

**变量 widget**：串联所有变量的「轨道」，每条轨道有「左走/右走」两种方式——对应 $x_i = true/false$。哈密顿回路必须逐段选择一种走法。
**子句 widget**：3 个文字各接一个「触发口」；若变量走法使该文字为真，则对应的触发口「对齐」，子句 widget 能被回路覆盖。若三个文字都为假，子句 widget 无法被覆盖——回路不存在。<span class="marginnote">「真文字对齐触发口」是归约的翻译核心：把「子句至少一真」翻译成「子句 widget 至少一个触发口被覆盖」。这需要变量 widget 的走法与子句 widget 的拓扑精确咬合——归约构造的难点全在这里，也是 CLRS 花大篇幅画图的原因。</span>

**为什么用 3-SAT 而不是 2-SAT**：2-SAT 是多项式的，不能用来证 NPC；3-SAT 是 NPC 的第一个成员（Cook-Levin 定理），所有后续 NPC 证明都从它出发。用 3-SAT 作为「已知难问题」是归约链的起点。<span class="marginnote">归约链的方向永远是从「已知 NPC」指向「待证 NPC」：3-SAT → HAM-CYCLE → TSP → 其他。方向反了就废了——若从 HAM-CYCLE 归约到 3-SAT，只能说明 3-SAT 不比 HAM-CYCLE 容易，得不出 HAM-CYCLE 是 NPC。</span>

**widget 为什么不直观**：CLRS 的正式构造里，变量 widget 是含多条内部路径的复杂子图，子句 widget 是几个节点和边的精巧组合——初学者第一次看常常完全懵住。建议的读法是：先记住「每个 widget 只有有限种合法走法」这个抽象，再回到图上逐一核对走法。「先抽象、后核对」比逐行啃图更有效，也更能抓住归约的意图。

## 3 归约的三件套检查

无论 widget 多复杂，归约证明的骨架不变：

$$\phi \text{ 可满足} \iff G \text{ 有哈密顿回路}$$

- **第一步，$(\Rightarrow)$**：给定满足赋值，按「真变量左走、假变量右走」的规则穿过变量 widget，并选择子句 widget 中「被真文字对齐」的路径——构造出一条完整哈密顿回路。
- **第二步，$(\Leftarrow)$**：给定哈密顿回路，读取出每个变量 widget 的走法 → 得到一组赋值；因为回路必然覆盖了所有子句 widget，每个子句至少一个触发口被对齐 → 每个子句至少一真 → 公式可满足。
- **第三步，多项式性**：图 $G$ 的规模是公式规模的常数倍（每个变量/子句对应常数个顶点边），构造可多项式时间完成——归约合法。

**要点**：等价性的两个方向 + 构造的多项式性，是任何归约证明的三件套。widget 只是把「逻辑」翻译成「图结构」的载体。<span class="marginnote">「等价性 + 多项式构造」这个骨架与顶点覆盖的证明完全同构——换的是构件，不变的是逻辑结构。学会识别「三件套」，任何 NPC 证明都能拆解成「验证、构造、双向论证」三步，不再被 widget 的复杂度吓住。</span>

**辨析｜易错点：** widget 归约里最容易犯的错是「只证了单向」。有的同学构造出 $G$ 后只说明「公式可满足 ⟹ 有回路」，却漏了反向——而反向恰恰是「回路编码了赋值」的保证。三件套缺一不可：单向成立只说明「难问题不比新问题难」，不能证明新问题是 NPC。

## 4 公式解析：等价性为什么必须双向

归约的等价性是一条「当且仅当」，它要求两个方向都成立。为什么不能只证一个方向？

- **$(\Rightarrow)$（可满足 ⟹ 有回路）**：保证「公式难 ⟹ 图也难」。若此方向成立，则「解图问题」的能力可以转化为「解公式」的能力——图问题至少与 3-SAT 一样难。
- **$(\Leftarrow)$（有回路 ⟹ 可满足）**：保证「图的解真的是公式的解」。若此方向不成立，可能构造出的「回路」根本不对应任何满足赋值——归约就把公式语义译错了。
- **合起来**：$G$ 有回路 ⟺ $\phi$ 可满足。于是「判定 HAM-CYCLE」的算法可以直接拿来「判定 3-SAT」——先构造 $G$，再跑算法。这就是多项式归约的定义：**若 3-SAT $\le_P$ HAM-CYCLE 且 3-SAT 是 NPC，则 HAM-CYCLE 是 NP 完全**。

**要点**：双向等价是把「两个问题一样难」焊死的螺丝。少一个方向，归约就松了一边。

## 5 哈密顿回路家族的 NPC 成员

**有向哈密顿回路**：同样 NPC（无向可归约到有向，或反之）。
**哈密顿路径**（不需回到起点）：NPC。
**旅行商问题（TSP）**：找「总长度 ≤ 某值的哈密顿回路」——在下一课，从 HAM-CYCLE 归约。<span class="marginnote">哈密顿回路是 TSP 的「骨架」：TSP 就是在带权完全图上找「最短哈密顿回路」。所以「HAM-CYCLE ≤ TSP」的归约很自然——把 TSP 的判定版翻译成 HAM-CYCLE 的实例。理解了 HAM-CYCLE 的 NPC，TSP 的 NPC 就顺理成章。</span>

**有向 vs 无向**：无向 HAM-CYCLE 可归约到有向版本（把每条无向边替换为一对反向有向边），反过来也可归约。两个方向都在多项式时间内完成，所以「有向哈密顿回路」同样是 NPC。这类「变体也是 NPC」的结论，靠的都是归约传递，不需要为每个变体重写一遍完整证明。

**NPC 的传染性**：一旦证明 HAM-CYCLE 是 NPC，凡是从它归约的问题都自动是 NP 困难。这张「NPC 家谱」不断扩展：3-SAT → HAM-CYCLE → TSP → 顶点覆盖 → 集合覆盖……归约就像传染病，从 3-SAT 这个「零号病人」沿着归约边扩散。「多认识几个 NPC 问题」因此非常有用——它们是归约的现成起点，遇到新问题可以先试着从最近的邻居归约。

| 问题 | 判定目标 | 复杂性 |
| --- | --- | --- |
| 欧拉回路 | 每边恰好一次的回路 | 多项式（顶点度数为偶数） |
| 欧拉路径 | 每边恰好一次的路径 | 多项式（恰 0 或 2 个奇数度顶点） |
| 哈密顿回路 | 每点恰好一次的回路 | NPC |
| 哈密顿路径 | 每点恰好一次的路径 | NPC |
| 旅行商（判定） | 长度 ≤ k 的哈密顿回路 | NPC |

## 6 术语速查：归约构造的构件库

| 术语 | 含义 | 顶点覆盖版 | 哈密顿回路版 |
| --- | --- | --- | --- |
| 变量构件 | 编码一个变量的真/假 | 一条边（二选一） | 一条轨道（左右走法） |
| 子句构件 | 编码「至少一真」 | 三角形（选 ≥2 顶点） | 触发口 widget |
| 连接边 | 绑定文字与赋值 | 文字顶点连到变量端点 | 文字连到触发口 |
| 配额 | 用「刚好用完」逼出精确解 | 紧配额 $k = n + 2m$ | 无配额，靠回路必须穿过所有 widget |

**辨析｜易错点：** 「配额型归约」（顶点覆盖）与「widget 型归约」（哈密顿回路）是 NPC 证明的两大流派。配额型用「数量刚好」逼约束；widget 型用「结构的走法有限」逼约束。识别「这个归约靠什么逼出解」——靠计数还是靠结构——是看懂任何 NPC 证明的第一把钥匙。

**本课的高层收获**：即使不背 CLRS 的 widget 细节，也要带走三样东西——哈密顿回路是 NPC、欧拉回路不是、归约的三件套骨架。考试或面试里遇到「哈密顿变体」，第一反应是「多半 NPC」，再用归约或近亲关系确认，而不是盲目尝试设计多项式算法。「先怀疑是 NPC，再验证」，是处理这类问题的正确姿势。

## 7 小结

- **哈密顿回路**：经过每顶点恰好一次的回路；证书验证 $O(V)$——$\in NP$。
- **欧拉回路容易、哈密顿回路难**：一个看边、一个看顶点，复杂性天差地别。
- **NPC 证明**：3-SAT $\le_P$ HAM-CYCLE，用 widget 构件把公式翻译成图。
- 归约三件套：等价性两个方向 + 构造多项式性——任何 NPC 证明的骨架。
- 两大归约流派：配额型（计数逼约束）与 widget 型（结构逼约束）。
- 变体（有向、哈密顿路径）都是 NPC，靠归约传递，不必重写证明。
- HAM-CYCLE 是 TSP 的骨架，TSP 的 NPC 由此归约而来。

在下一课，我们看最著名的 NPC 问题——**旅行商问题（TSP）**：为什么「最优旅行路线」如此难求，以及它的判定版如何从哈密顿回路归约。
