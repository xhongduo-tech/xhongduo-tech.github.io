## 为什么自动定理证明是这条线的终点

本专题从 SAT 出发，到 CDCL、到 SMT、到 Z3，一直在做一件事：**让机器自动判定「某条约束是否满足」**。而这条线的自然终点，是更高的野心——**让机器自动证明数学定理**。SAT 证明「$a=b$ 蕴含 $f(a)=f(b)$」时只是穷举布尔赋值；自动定理证明要处理的是带量词、带函数、带递归的一阶甚至高阶逻辑，那里不再有「有限赋值空间」可以穷举。<span class="marginnote">SAT/SMT 是「判定」，自动定理证明是「证明」：前者只需回答 yes/no，后者必须产出「为什么 yes」。正因如此，自动定理证明往往把 SAT/SMT 当子程序——一阶逻辑的命题部分可以交给 SMT 判定，量词部分才动用更强大的演算。</span>

自动定理证明分两大传统，对应两大流派：**自动的（automated）**——Superposition 演算支撑的 Vampire、E 等强力证明器；**交互的（interactive）**——Lean、Isabelle 等证明助手，人机协作，证明可达任意复杂数学。

## 1 一阶逻辑与不可判定性

先划定战场。**一阶逻辑（first-order logic）**在命题逻辑之上加了**量词**（$\forall$、$\exists$）、**函数符号**与**谓词符号**。例如：

$$
\forall x \forall y\; (f(x) = f(y) \rightarrow x = y)
$$

表达「$f$ 是单射」。一阶逻辑的判定问题是**不可判定的**（丘奇与图灵 1936 年证明）——不存在算法能在有限步内判定任意一阶公式是否永真。这让自动定理证明陷入两难：**完备性（能证明所有真定理）与终止性（总能停机）不可兼得**。<span class="marginnote">这是一个深刻的结果：一阶逻辑「半可判定」——若公式是永真的，终有算法能找到证明（完备的半判定过程存在）；但若不是永真的，算法可能永不终止。自动定理证明器靠「搜索空间剪枝 + 超时限制」在这个不可判定性下求实用。</span>

## 2 一阶归结与合一：机器「对得上」的关键

一阶归结与命题归结的关键差别，在于**合一（unification）**。命题归结只需看两个互补文字是否逐字相同；一阶归结却要处理带变量与函数的项，例如从「$P(f(x))$」与「$\neg P(y)$」能推出什么？答案取决于能否找到一个**替换（substitution）** $\sigma$，使 $f(x)$ 与 $y$ 变得相同——这里取 $y \mapsto f(x)$ 即可，于是两条子句的互补文字同时为真，推出空子句。

**合一**：给定两个项，找使它们相等的「最一般替换（most general unifier，MGU）」。Robinson 1965 年给出线性时间算法，它是一阶推理的引擎——没有合一，机器无法「把两段话对到一起」。这是自动定理证明与 SAT 的又一个分水岭：SAT 只有布尔文字，一阶逻辑的项结构让「匹配」本身成为一个需要计算的子问题。<span class="marginnote">合一算法至今仍是「逻辑编程（Prolog）」「类型推断（Hindley-Milner）」等许多系统的基石——本专题读者若在第三级《程序设计语言理论》学过类型推断，会发现那里用的正是同一套合一机器。这就是「一小撮核心算法反复出现」的例子。</span>

## 3 Superposition：归结的现代化身

自动定理证明的主流算法是 **Superposition 演算**——它是 Robinson 归结（1965）与 Knuth-Bendix 完备化（1970）联姻的产物，由 Bachmair、Ganzinger 等在 1990 年代发展成熟，Vampire、E、SPASS 等证明器都基于它。

Superposition 的两大支柱：

- **归结（resolution）**：从两条含互补文字的子句推出新子句——这与 SAT 里 Davis-Putnam 用过的归结同源，但在一阶逻辑里要处理量词、合一（unification）与替换。
- **有序重写（ordered rewriting / 完备化）**：用「定向等式」$t_1 \rightarrow t_2$（按项序把大项约成小项）不断化简，直至范式。等式推理正是靠这一支。

Superposition 把推理组织成「饱和（saturation）」过程：反复应用推理规则生成新子句，直到达到不动点或推出空子句。它的效率秘密在于**冗余消除**——大量子句被判定为「可从已有子句推出」而被删除，搜索空间得以聚焦。<span class="marginnote">SMT 里的 E-matching 与 Superposition 看似无关，实则同源：两者都在处理「如何从已有事实实例化量词」。Z3 的 MBQI 与证明器的 saturation loop 是同一棵家族树上的两支。</span>

一个容易忽略的点是「顺序」：Superposition 要求归结只作用于「最大项」，并用一个良基的项序来定向等式。这个看似技术性的约束，恰恰是它**完备且高效**的保证——Bachmair 与 Ganzinger 1994 年那篇奠基性论文证明，在恰当的冗余消除下，Superposition 是完备的（任何可证的定理最终都能被证明），同时又比无约束的归结小几个数量级地剪枝。

## 4 公式解析：一次一阶归结的完整链条

把一阶归结的每一步拆开看，体会「合一 + 归结 + 重写」如何协同。目标：从两条前提证明「$P(a)$」。前提为：

$$
\forall x\; (R(x) \rightarrow P(x)),\qquad R(a)
$$

**逐步拆解**：第一步，把蕴含写成子句形式：$(\neg R(x) \lor P(x))$ 与 $R(a)$。第二步，合一：要找 $x$ 的替换使 $R(x)$ 与 $R(a)$ 互补，取 $x \mapsto a$（MGU 恰好是这个常量替换）。第三步，归结：对 $(\neg R(a) \lor P(a))$ 与 $R(a)$ 做归结，消去互补文字 $R(a)$，得到 $P(a)$。第四步，饱和过程继续：$P(a)$ 与目标完全一致，证明完成——整个推导就是「合一确定匹配、归结消去互补、重写整理范式」三步循环的一次实例。

这个链条虽小，却展示了一阶自动证明的全部核心动作。而「要归结哪两条子句、要不要继续推导」，正是证明器的搜索策略在决策——也是它往往需要超时限制的原因：搜索空间在不可判定性下是开放的。

## 5 Lean 与 Isabelle：交互式证明

自动证明器适合「形式简单、推理机械」的定理；但对现代数学——群论、范畴论、分析——需要人机协作的**证明助手（proof assistant）**。

**Isabelle**（保尔森，1986）采用 LCF 风格：一个极小的可信内核接受少数推理规则，所有证明必须经过内核校验，从而把「系统出错」的风险降到最低。它支持 HOL（高阶逻辑），并有强大的自动化战术库 `auto`、`simp` 等——把大量例行程式化推理交给内嵌的自动化器。

**Lean**（德莫拉，2013）走得更远：它用**依值类型论（dependent type theory）**作为数学基础——「命题即类型，证明即程序」。一个数学断言被表达成一个类型，而构造该类型的项就是证明。Lean 的社区「数学库 mathlib」在 2020 年代迅速发展，2021 年完成了**完美图定理**的完全形式化——一个此前被认为「不可形式化」的现代组合数学里程碑。<span class="marginnote">Lean 的创始人正是 Z3 之父 de Moura——这绝非巧合：Z3 提供了「把自动化推理注入交互证明」的引擎，Lean 则把整个数学变成可编译、可校验的程序。工具谱系在此闭合：从 SAT 到 SMT 到定理证明，是同一群人追逐同一梦想的不同阶段。</span>

## 6 公式解析：命题即类型的证明

看 Lean 里一个最小定理如何被验证。在依值类型论里，声明「$\forall x,\; x = x$」并给出证明：

```lean
theorem refl_example (x : Nat) : x = x := by
  rfl
```

**逐步拆解**：第一步，`(x : Nat) : x = x` 声明了一个函数类型——输入自然数 $x$，输出命题 $x = x$。第二步，在类型论中，这个函数类型的「一个居民（项）」就是该命题的一个证明。第三步，`rfl`（reflexivity）是 Lean 内核内建的推理规则，它自动判定「两表达式定义上相等」——这里 $x$ 与 $x$ 定义上相同，故 `rfl` 立即完成证明。第四步，整个证明被内核逐条校验，结果是一棵可审计的证明树，任何一步不合规都会被拒绝。

这个例子虽小，却展示了交互证明的范式：**人是导演（写策略 `by ...`），内核是终极裁判（校验每个步骤）**，自动化器（`rfl`、`simp`、`omega`）承担例行推理。人类数学家与机器各自做最擅长的事。

## 7 两大传统的对比与分工

| 维度 | 自动证明（Vampire/E） | 交互证明（Lean/Isabelle） |
| --- | --- | --- |
| 逻辑 | 一阶逻辑 | 高阶逻辑 / 依值类型论 |
| 推理主体 | 机器全自动 | 人机协作 |
| 强度 | 例行数学、证明搜索 | 任意复杂现代数学 |
| 可信度 | 高（可输出证明） | 极高（内核逐条校验） |
| 经典用例 | 代数、几何证明搜索 | 数学定理形式化、程序验证 |

两者互补而非竞争：自动证明器常作为交互证明器的「自动化战术」被内嵌——Isabelle 的 `sledgehammer` 自动调用 Vampire/E 等外部证明器，把「能自动证的先自动证掉」，人的注意力只留给真正困难的核心步骤。这正是「从极限到大模型」这条线索上，自动化推理的完整图景。

## 8 一部简要的时间线：形式化如何走到今天

把自动与交互两条传统放进同一段历史，会看到一个清晰的脉络：

| 年份 | 里程碑 | 意义 |
| --- | --- | --- |
| 1931 | 哥德尔不完备定理 | 机器证明的理论边界 |
| 1936 | 丘奇-图灵定理 | 一阶逻辑不可判定 |
| 1965 | Robinson 归结 | 一阶自动证明的引擎 |
| 1970 | Knuth-Bendix | 等式重写与完备化 |
| 1986 | Isabelle | LCF 式交互证明助手 |
| 1990s | Vampire/E 出现 | 强力自动证明器 |
| 2013 | Lean 发布 | 依值类型论的现代证明助手 |
| 2021 | 完美图定理形式化 | Lean 证明现代组合数学 |

这张表浓缩了两条线的互动：理论上的不可判定性没有吓退工程，反而催生了「半判定搜索 + 超时限制」的实用证明器；而交互证明的内核校验思想，则让「机器证明」从研究玩具成长为可部署的工程工具。今天，Isabelle/HOL 已经用于操作系统与编译器的形式化验证（如 sel4、CompCert），Lean 的 mathlib 正把整座数学大厦逐块搬进机器——这条时间线还在延伸。

## 9 小结

- 自动定理证明处理带量词的一阶逻辑，而一阶逻辑判定**不可判定**（丘奇-图灵 1936），完备性与终止性不可兼得。
- **Superposition** = 归结 + 有序重写 + 饱和搜索，支撑 Vampire、E 等强力证明器。
- **Lean / Isabelle** 走交互证明路线：LCF 内核、依值类型论，「命题即类型，证明即程序」。
- **Isabelle 的 sledgehammer** 把自动证明器内嵌为战术，人机分工明确。
- 从 SAT 到 SMT 到定理证明，是同一自动化梦想的三个层次；Lean 与 Z3 同源（de Moura）即是明证。
