## 为什么从 DPLL 开始

上一篇我们认识了 SAT 问题与它的 NP 完全地位，也知道了「别指望多项式算法」这个工程判断。那么第一个真正能跑起来的算法是什么？答案是 1962 年的 **DPLL 过程**——由 Davis、Logemann、Loveland 提出，名字取自三人姓氏，而它的前身正是 Davis & Putnam 1960 年那篇用「归结」直接做的过程。<span class="marginnote">DPLL 中的三个字母常被误认为是对应 Davis-Putnam-Loveland，正确顺序是 Davis-Putnam-Logemann-Loveland：Putnam 在 1960 年的归结版中被替换掉了，1962 版把归结换成回溯搜索。今天 SAT 界说的「DPLL」一律指 1962 年的回溯版。</span>

DPLL 是一切现代完备 SAT 求解器的祖先：今天最先进的 CDCL 求解器，其核心仍然是「回溯搜索 + 单元传播」，只是加上了学习与启发式的翅膀。理解 DPLL，等于理解了求解器的骨架。

## 1 从穷举到回溯

最朴素的 SAT 算法是穷举：有 $n$ 个变量就试 $2^n$ 个赋值。DPLL 把穷举改造成**带剪枝的回溯搜索（backtracking search）**，核心是一个递归的二元分治：

1. **选变量**：从尚未赋值的变量中选一个 $x$。
2. **赋值与传播**：先试 $x = \text{true}$，用单元传播（见第 2 节）推导出必然的推论；若走到矛盾就撤销，改试 $x = \text{false}$。
3. **递归**：对分支后的公式递归求解；若两枝都矛盾，则当前公式不可满足。

这个框架下，搜索树每层对应一次「猜测」。关键洞察是：**单元传播让大部分变量不必猜测，而是被推论确定**——真实求解中猜测的变量往往只占少数，搜索树因此远小于 $2^n$。

## 2 单元传播与纯文字消除

DPLL 论文提出两条著名的简化规则，它们至今仍是每个求解器的看家本领：

**单元子句规则（unit clause rule）**：若公式中某个子句只剩下一个未赋值文字，则该子句要成立，这个文字必须为真——于是立即赋值并递归传播。<span class="marginnote">单元传播（unit propagation，简称 UP）在 DPLL 中通过反复扫描子句实现；现代 CDCL 用「监视文字（watched literals）」数据结构把它优化到近乎 O(1) 摊销，见第 4 篇。概念上两者完全一致。</span>

**纯文字规则（pure literal rule）**：若某个变量在公式中只以一种符号出现（只以 $x$ 出现而从不以 $\neg x$ 出现，反之亦然），则把它赋值为让它所在的每个子句都为真的符号，绝无风险——因为这只让子句更容易满足。

```
DPLL(F):
  F' = unit_propagate(F)          # 单元传播到不动点
  if F' 含空子句: return UNSAT
  if F' 为空:      return SAT
  F'' = pure_literal_assign(F')   # 纯文字消除
  x = pick_variable(F'')          # 选择分支变量
  if DPLL(F'' ∪ {x}) = SAT: return SAT
  return DPLL(F'' ∪ {¬x})
```

这段伪代码概括了 DPLL 的全貌：先传播、再消除、再猜测。注意 `unit_propagate` 必须迭代到不动点——一条单元子句赋值后可能制造新的单元子句，连锁反应正是搜索高效的关键。

## 3 为什么「回溯」而非「归结」

1960 年 Davis & Putnam 的过程用**归结（resolution）**：反复挑选两个含互补文字的子句，生成它们的归结子句，直到推出空子句或无法继续。这在理论上优美（归结是完备的），但实践上爆炸：归结子句会不断累积，内存与时间都撑不住。<span class="marginnote">归结的完备性本身是 Robinson 1965 年奠基的，它后来成为自动定理证明里 Superposition 演算的核心——那是本专题第 10 篇的舞台。但在命题层，回溯搜索比归结实用得多。</span>

DPLL 1962 版的关键决策，就是**放弃归结、回到搜索**：变量逐个赋值，冲突立即撤销。空间从「子句池」降到「搜索路径」，时间上配合单元传播也远优于归结。今天回头看，这是 SAT 求解史上第一次「用搜索换空间」的胜利，也是之后所有完备求解器的路线奠基。

## 4 公式解析：单元传播的连锁效应

单元传播为什么威力如此之大？看一个经典例子。假设公式含如下子句：

$$
(x_1) \land (\neg x_1 \lor x_2) \land (\neg x_2 \lor x_3) \land (\neg x_3 \lor \neg x_1)
$$

**逐步拆解**：第一步，$x_1$ 是单元子句，强制 $x_1 = \text{true}$。第二步，代入第二条子句 $(\neg x_1 \lor x_2)$，$\neg x_1$ 为假，故 $x_2$ 必须为真——又制造一条单元子句。第三步，代入 $(\neg x_2 \lor x_3)$，得 $x_3 = \text{true}$。第四步，检查 $(\neg x_3 \lor \neg x_1)$：$x_3$ 与 $x_1$ 都为真，子句为假，矛盾。

这个例子暴露了单元传播的本质：**它把「蕴含链」一次性全部推完**。$x_1$ 一个赋值，沿子句链条推出 $x_2$、$x_3$，最终撞出冲突。没有单元传播，求解器要在这条链条上逐一猜测 3 个变量（$2^3$ 个分支）；有了它，一次赋值即可走完，而这次「撞出的冲突」正是下一篇 CDCL 学习新子句的原料——**冲突分析**。

## 5 分支启发式：先猜哪个变量

回溯搜索要高效，还有一个隐蔽但致命的问题：**每次该选哪个变量去猜？** 不同的选择顺序，搜索树大小可以相差几个数量级——选得好的树可能只有几十个节点，选得差的可能上百亿。DPLL 时代的启发式大多基于**局部统计**：

- **出现次数（occurrence count）**：选在最多子句里出现的变量优先——直觉是「影响面越大，分支收益越大」。
- **Jeroslow-Wang 规则**：对每个文字按「所在子句长度与出现次数」加权，选权重最大的文字分支。它偏好「短子句里高频出现」的文字，因为短子句最容易被一个文字满足。
- **DLIS（Dynamic Largest Individual Sum）**：按「当前未满足子句中文字的出现次数」动态打分，随搜索状态更新。

这些启发式各有性格，但没有一个是通吃的——这正是 SAT 求解中「没有免费的午餐」的体现。值得注意，DPLL 的启发式只依赖**当前公式静态或局部的信息**，而 CDCL 的 VSIDS 之所以是革命的一部分，正在于它引入了「最近冲突相关的变量优先」这一**全局动态**信号。<span class="marginnote">一个有趣的实证观察：对同一个公式，把变量选择从「选出现次数最多」换成「随机选择」，求解时间可能从毫秒级膨胀到数小时。启发式不是锦上添花，而是决定生死——这也是为什么《Handbook》第 8 章专门用整章研究分支启发式，第 5 篇还会看到它如何与 CDCL 结合。</span>

## 6 公式解析：走一遍搜索树

把 DPLL 的完整动作走在一个小例子上，体会「传播—消除—猜测—回溯」的节奏。设公式：

$$
(x_1 \lor x_2) \land (\neg x_1 \lor x_3) \land (\neg x_2 \lor x_3) \land (\neg x_3)
$$

**逐步拆解**：第一步，`unit_propagate`：子句 $(\neg x_3)$ 是单元子句，强制 $x_3 = \text{false}$。第二步，传播：把 $x_3=\text{false}$ 代入 $(\neg x_1 \lor x_3)$ 与 $(\neg x_2 \lor x_3)$，两条子句的 $\neg x_3$ 文字满足，子句整体满足，不再产生新单元。第三步，`pure_literal_assign`：检查 $x_1$ 只以正形式出现（只在第一条子句），$x_2$ 亦然，于是可安全赋 $x_1=\text{true}, x_2=\text{true}$。第四步，代入第一条子句 $x_1 \lor x_2$ 已满足；四条子句全部满足，公式可满足，返回 SAT。

注意这个例子全程**没有一次猜测**：单元传播 + 纯文字消除就解完了。这正是 DPLL 的典型工作方式——真正的「猜测—回溯」只在启发式用尽后才发生。再看一个需要回溯的例子：

| 步骤 | 动作 | 结果 |
| --- | --- | --- |
| 1 | 决策 $x_1=\text{true}$ | 进入分支 |
| 2 | 单元传播 | 推出 $x_2=\text{true}$ |
| 3 | 单元传播 | 推出 $x_3=\text{true}$ |
| 4 | 发现 $(\neg x_3)$ 冲突 | 回溯到步骤 1 |
| 5 | 改试 $x_1=\text{false}$ | 新分支 |
| 6 | 传播到底 | 得解 SAT |

这张表浓缩了「回溯」的全部含义：冲突发生时撤销的是**最近一次决策**及其传播的全部推论，而**不是**全部搜索——这与 CDCL 的「非时序回溯」形成鲜明对比，后者一跳可以跳过多个决策层。

## 7 DPLL 的局限与遗产

DPLL 在实践中能解数千变量规模的问题，但对工业级百万变量实例仍力不从心。它的两大缺陷：

- **无记忆**：每次回溯都从头再来，同样的错误路径会反复撞上。
- **启发式粗糙**：变量选择（`pick_variable`）与子句排序高度依赖实现细节，早期只有简单的「出现次数最多」之类的策略。

但 DPLL 的遗产是奠基性的：**回溯搜索、单元传播、纯文字消除**这三个机制被原封不动保留进 CDCL；而「撞出冲突后学习」这一句补充，恰恰是把 DPLL 升级为 CDCL 的那一小步——这是下一篇「CDCL 革命」的主角。<span class="marginnote">如果你现在去读 MiniSat 源码，会发现它的主循环（`search` 函数）仍然是「传播—决策—冲突—回溯」的 DPLL 骨架；CDCL 只是在冲突时多做一件事：分析并添加学习子句。</span>

## 8 小结

- **DPLL** 是 1962 年 Davis-Logemann-Loveland 提出的回溯搜索过程，前身是 1960 年 Davis-Putnam 的归结版。
- 核心机制三件套：**回溯搜索、单元传播（unit propagation）、纯文字消除（pure literal rule）**。
- 单元传播把蕴含链一次性推完，让大多数变量由推论确定而非猜测，这是搜索高效的关键。
- **分支启发式**（出现次数、Jeroslow-Wang、DLIS）决定搜索树的大小，是求解器性能的隐形杠杆。
- **回溯优于归结**的关键在于空间可控、剪枝充分；归结的完备性则留给一阶逻辑的 Superposition。
- DPLL 是 CDCL 的骨架；「在冲突处学习新子句」这一步，把 DPLL 升级为现代求解器。

在下一节，我们将看到 DPLL 的致命弱点如何被一项发明彻底治愈——冲突驱动子句学习（CDCL）。「记录失败的教训」这七个字，把 SAT 求解从千级变量推向了百万级变量。
