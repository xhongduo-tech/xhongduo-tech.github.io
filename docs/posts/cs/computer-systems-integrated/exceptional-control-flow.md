## 为什么从异常控制流开始

到目前为止，我们假设程序「顺着指令一条条往下走」。但真实系统远非如此：键盘一敲，CPU 就得放下手里的活去处理中断；程序每跑几毫秒，操作系统就把它切走、换上另一个进程；你按 Ctrl-C，进程就收到信号被终止。**控制流从来不是连续的——它在中断、陷阱、故障、信号处不断被打断与转向**，这就是**异常控制流（Exceptional Control Flow，ECF）**。<span class="marginnote">ECF 是操作系统全部机制的载体：进程、信号、调度、系统调用、非本地跳转，都是 ECF 的具体形态。不理解 ECF，就读不懂 fork、读不懂僵尸进程、也读不懂「为什么程序会莫名被杀」。</span>

本章在全书中的位置很特殊：它是「程序员的 C 程序」与「操作系统的进程」之间的那座桥。上一章《链接与加载》把程序变成文件，本章把文件变成**活的、可以被切来切去的进程**；下一章《系统级 I/O》里的每个读写，都将跑在 ECF 提供的机制之上。它同时为《操作系统》专题打下了全部概念地基。

## 1 异常：控制流的四类急刹车

处理器执行指令时，遇到「必须立即处理」的事件，会暂停当前指令流，跳转到**异常处理程序（exception handler）**，处理完再决定是返回原指令、返回下一条、还是终止程序。异常按触发方式与返回行为分四类：

| 类型 | 触发 | 返回行为 | 典型例子 |
| --- | --- | --- | --- |
| **中断（interrupt）** | 外部 I/O 设备（异步） | 返回下一条指令 | 键盘输入、网卡包到达、时钟节拍 |
| **陷阱（trap）** | 程序主动执行 `syscall` | 返回下一条指令 | `read`、`fork`、`open` 等系统调用 |
| **故障（fault）** | 程序错误但可修复（同步） | 返回当前指令重试 | 缺页、除零、段错误 |
| **终止（abort）** | 不可恢复的错误 | 不返回，直接终止 | 硬件校验错误、非法指令 |

<span class="marginnote">这张表是本章的心法：把「谁触发」与「回不回来」分开记。中断与陷阱都「回来」，但中断是设备敲门（异步、硬件的），陷阱是程序自己举手（同步、软件的）。</span>

**辨析｜易错点：** 「异常」在系统世界里是中性词——它是机制，不是错误。断点、系统调用、缺页都走「异常」通道，但它们恰恰是系统正常工作的一部分。真正要小心的语义差别是：**故障**处理完成后**重试原指令**，若故障原因未消除（比如缺页缺在只读页上），就会升级成终止——段错误（segmentation fault）就是这么来的。<span class="marginnote">「缺页故障」是最好的例子：程序访问了尚未载入内存的页，处理器把控制交给内核，内核把页调入，然后<strong>重新执行那条访问指令</strong>——程序毫无察觉。这是虚拟内存能「按需调页」的机制基础，第九章会详细展开。</span>

## 2 系统调用：陷阱控制下的「合法特权跃迁」

陷阱类异常中最重要的是**系统调用（system call）**。用户程序想访问磁盘、网络、创建进程，都必须请操作系统代办，因为这些操作需要更高特权级。<span class="marginnote">x86 上用户态（ring 3）与内核态（ring 0）之间的跃迁，正是通过 `syscall`/`int $0x80` 这类陷阱指令实现的——它是最快的「特权切换电梯」。Linux 里每个系统调用有唯一编号，`syscall` 传参在寄存器里。</span>

**重点：** 系统调用的机制本身不复杂，但它确立了一个重要的分界：**用户代码不能直接碰硬件，一切敏感操作都要经内核代劳**。这正是下一章「系统级 I/O」里 `read`/`write` 比 `getchar` 更接近「内核」的原因，也是后续《操作系统》专题「内核态与用户态」讨论的起点。把几个最常见的系统调用记在手上，会很有用：

| 系统调用 | 功能 | 常见触发场景 |
| --- | --- | --- |
| `read` / `write` | 读/写一个描述符 | 键盘、文件、socket |
| `open` / `close` | 打开/关闭文件 | 任何文件访问 |
| `fork` | 创建子进程 | 派生子进程 |
| `execve` | 用新程序替换当前进程 | 加载并运行程序 |
| `mmap` | 映射内存或文件 | 共享库、`malloc` 大块 |
| `waitpid` | 等待子进程 | 回收子进程状态 |

## 3 进程：程序运行的一个实例

操作系统让每个程序「假装独占机器」的核心抽象是**进程（process）**：一个正在运行的程序实例，拥有自己独立的地址空间与执行状态。<span class="marginnote">进程的「独立」是操作系统制造的一场宏大幻觉：每个进程都以为自己独占全部 CPU 与内存，实际是内核在毫秒级地把它们换来换去。这份幻觉正是上一章链接的产物——独立虚拟地址空间，让每个进程的代码段都「从 0x400000 起头」而互不冲突。</span>

进程的三个关键属性：**独立的虚拟地址空间**（代码、数据、堆、共享库、栈各占一段）、**独立的控制流**（自己的寄存器、程序计数器、条件码）、以及**运行在用户态/内核态之间切换**。

**fork 的意义**：Unix 用 `fork` 创建进程——调用一次，返回两次：父进程得到子进程 PID，子进程返回 0。子进程是父进程的**完整副本**：虚拟地址空间、打开的文件描述符表，全被复制。<span class="marginnote">`fork` 的「复制整个地址空间」在今天听起来昂贵得离谱——但内核用「写时复制（COW，copy-on-write）」偷懒：先共享物理页，谁要写谁才复制。COW 是性能与安全高度耦合的设计，也横跨了虚拟内存章，第九章会正式展开。</span>

**exec 与 exit**：`execve` 用新程序替换当前进程的代码与数据（保持 PID）；`exit` 结束进程。一个完整的「跑一个程序」= `fork` 造一个新壳 + `execve` 把新程序装进去。

进程之间的关系构成一棵**进程树**：`init`（PID 1）是树根，每个进程都由一个父进程 fork 而来。父进程先于子进程死亡时，子进程会被 `init`「收养」；孤儿不会变成野进程，而是被统一接管——这是 fork 之外维护进程体系稳定的第二道保险。

**辨析｜易错点：** 子进程从 `fork` 的**返回点**继续执行，而不是从 `main` 重头再来——`fork` 之后的代码会被父、子各执行一遍，这就是「一次调用、两处执行」的机器语义。调试多进程程序时，在 `fork` 后各自打印 `getpid()`，就能亲眼看到两条独立控制流分道扬镳的路径；而 `execve` 成功后不会返回（新程序接管了控制），所以代码里 `execve` 之后的语句几乎都不会被执行到。

## 4 进程控制：wait 与僵尸

`fork` 之后，父进程常调用 `waitpid` 等待子进程结束。子进程退出后、父进程回收它之前，它处于**僵尸状态（zombie）**——进程已经死了，但它的退出状态还留在进程表里等父进程来收尸。<span class="marginnote">「僵尸进程」的名字再贴切不过：尸体在，魂没了。如果父进程从不 `wait`，僵尸就永远占用一个进程表条目——进程表耗尽，系统就再也无法 fork 出新进程。这也是「守护进程」要 `fork` 两次、让子进程被 init 收养的原因。</span>

**进程状态**：在内核眼里，进程通常处于三种状态之一——**运行**（正在用 CPU 或就绪排队）、**阻塞**（等待 I/O 或信号，不在就绪队列里）、**终止**（僵尸，等待被回收）。上下文切换只在「运行与就绪」之间发生；阻塞的进程既不占 CPU，也不参与调度。`ps` 输出里的 `R`/`S`/`D`/`Z` 就是这些状态的速写。

**辨析｜易错点：** 子进程与父进程是**两个完全独立的控制流**，`fork` 之后谁先运行由调度器决定——你无法保证顺序。`fork` 的返回值是唯一的同步信号：父进程拿到 PID，子进程拿到 0，二者据此分道扬镳。任何「依赖父先跑」的代码都是竞态——这是《并发编程》一章竞态问题的第一个预告。

## 5 信号：操作系统给进程的消息

**信号（signal）**是 ECF 的又一形态：它允许内核**异步地通知进程**某个事件发生了。常用信号：`SIGINT`（Ctrl-C）、`SIGSEGV`（段错误）、`SIGKILL`（强制杀，不可捕获）、`SIGCHLD`（子进程停止或终止）。<span class="marginnote">`SIGKILL` 与 `SIGSTOP` 是「不可捕获不可忽略」的两个信号——内核保留它们作为对失控进程的最终控制手段。其余信号都可以被进程「捕获」（自定义处理函数）或「忽略」。</span>

常用信号速查：

| 信号 | 触发 | 默认动作 | 能否捕获 |
| --- | --- | --- | --- |
| `SIGINT` | Ctrl-C | 终止进程 | 可 |
| `SIGTERM` | `kill` 默认信号 | 终止进程 | 可 |
| `SIGSEGV` | 段错误 | 终止并转储 | 可 |
| `SIGKILL` | `kill -9` | 终止 | 不可 |
| `SIGSTOP` | Ctrl-Z | 停止 | 不可 |
| `SIGCHLD` | 子进程退出 | 忽略 | 可 |

信号的默认行为五花八门：终止进程（`SIGINT`、`SIGSEGV`）、忽略（`SIGCHLD`）、停止/继续（`SIGTSTP`、`SIGCONT`）。进程可用 `signal` 或 `sigaction` 设置自定义处理函数。

**信号处理的两个硬约束：** 其一，信号处理函数只做**异步信号安全（async-signal-safe）**的操作——它们可能在任何一条指令处被打断，若再去调用 `printf`、`malloc` 这类非安全函数，可能造成死锁或数据损坏；其二，信号会**排队合并**——多次同类信号可能只交付一次，因此不能靠信号计数。<span class="marginnote">标准答案：信号处理函数里唯一「官方推荐」的万能做法，是<strong>设置一个 volatile 标志</strong>、或在处理函数里只做记录，把真正的逻辑留给主循环。`printf` 进信号处理函数，是教科书级别的「看起来没事、迟早出事」。</span>

**重点：** 信号是并发与异常的交汇点：`fork` 产生的 `SIGCHLD`、Ctrl-C 的 `SIGINT`、崩溃的 `SIGSEGV`——同一套机制，服务三类完全不同的场景。理解信号，是理解「异步」的第一课。

**辨析｜易错点：** 信号与「异常」不是一回事：异常由 CPU 在指令级同步产生（缺页、除零），信号是内核向进程异步发送的通知——同一个信号可能来自硬件（`SIGSEGV`）、键盘（`SIGINT`）或另一进程（`kill`）。另外，**「信号被阻塞」不等于「信号被丢弃」**：进程用 `sigprocmask` 屏蔽某类信号，屏蔽期间的同类信号只是挂起，解除后仍会交付——只有被忽略（`SIG_IGN`）的信号才真正消失。

## 6 上下文切换与调度

为了让多个进程「同时」前进，内核在每次时钟中断（通常是每毫秒一次）时决定是否切换进程：保存当前进程的**上下文（context）**——寄存器、程序计数器、栈指针——再恢复下一个进程的上下文，让它从上次离开的地方继续。<span class="marginnote">上下文切换不是玄学：它就是把一组寄存器的值「保存到 A 的 PCB，从 B 的 PCB 恢复」。切换本身有开销（缓存全部失效——想想上一章那些宝贵的局部性），所以内核不会切得太勤。</span>

**调度（scheduling）**就是「下一拍该让谁跑」的策略：时间片轮转、优先级、CFS（Linux 的完全公平调度）……它们的共同约束是：**进程不该被饿死，CPU 不该被闲置**。这一整套「抢时间」的戏剧，在《操作系统》专题会从设计角度再演一遍。<span class="marginnote">对普通进程而言，调度是透明的——你写 `while(1){}` 也占不满 CPU，内核会切走它。但实时系统、嵌入系统、以及并发编程里的「忙等」，都必须正视「进程可能在任何时刻被切走」这一现实。</span>

调度器的选择背后是一组互斥的诉求：**响应延迟**（交互程序别卡太久）、**吞吐量**（总任务尽量多）、**公平性**（谁也别饿死）、**亲和性**（进程尽量留在原 CPU 上，省缓存迁移开销）。Linux 的 CFS 用一个「虚拟运行时间」记账，把 CPU 按权重分配，且天然偏向「欠账多」的进程——它把「公平」定义成「运行时间按权重比例兑现」。

## 7 非本地跳转与并发的前奏

ECF 还有两种「程序员主动使用」的形态：**非本地跳转（nonlocal jump，`setjmp`/`longjmp`）** 允许程序在一个深层的函数调用栈里，直接跳回到早先保存的上下文——常用于异常恢复、长时间运行的守护程序里的「软重启」。<span class="marginnote">`longjmp` 直接绕过所有中间栈帧——它不调用析构、不释放资源，是 C 里最「暴力」的控制转移。用它的代码几乎都同时背负着「内存泄漏」的骂名；但某些场景（比如解释器的错误恢复）它又不可替代。</span>

到这里，ECF 的各类形态已经齐了：异常是硬件的急刹车，系统调用是程序举手的合法跃迁，进程是独立控制流的载体，信号是内核到进程的异步消息，调度是它们之间的调度者。把这些拼起来，你就拥有了理解《并发编程》《虚拟内存》与《系统级 I/O》所需要的全部操作系统概念。

## 8 小结

- **异常控制流** = 中断、陷阱、故障、终止四类急刹车；区分「谁触发」（设备/程序）与「回不回来」（重试/跳过/终止）。
- **系统调用**是陷阱类的代表：程序经 `syscall` 请求内核代办特权操作。
- **进程**是独立地址空间 + 独立控制流的抽象；`fork` 复制、`execve` 换装、`exit` 终止。
- 子进程退出后未回收前是**僵尸进程**；`waitpid` 负责收尸，否则进程表被僵尸占满。
- **信号**是内核给进程的异步消息；处理函数里只做异步信号安全的操作，信号会合并、不可靠计数。
- **上下文切换**与**调度**让多进程「同时」前进；`setjmp`/`longjmp` 是程序员主动的非本地跳转。
