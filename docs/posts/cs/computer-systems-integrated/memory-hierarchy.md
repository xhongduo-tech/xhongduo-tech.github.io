## 为什么从存储器层次结构开始

前几章我们一直在问「如何让 CPU 算得更快」；这一章要面对一个更扎心的数字：**CPU 算一次要 1 纳秒，读主存要 80 纳秒**——差了近两个数量级。如果每条指令都去访存，再聪明的流水线也白搭。<span class="marginnote">这不是「慢一点」的问题：DRAM 的访问延迟比 CPU 周期长几十倍，且这个「存储墙」随摩尔定律越拉越大。计算机系统的一切缓存设计，本质上都是在这场拉锯战里给 CPU「打掩护」。</span>

解药的名字叫**存储器层次结构（memory hierarchy）**：寄存器 → 多级缓存 → 主存 → 磁盘，一层比一层大、一层比一层慢、也一层比一层便宜。上一章的 CPE 优化、下一章的虚拟内存，都建立在这一层结构之上。<span class="marginnote">把层次结构看成「信息的供应体系」：寄存器是抽屉里随手拿的工具，缓存是办公桌上的常用文件，主存是书房的资料柜，磁盘是地窖的仓库。局部性原理说的是——人（程序）总是反复用那几样东西。</span>

## 1 局部性：一切缓存的物理基础

**局部性（locality）**是存储器层次结构能工作的唯一前提，分两种：

**时间局部性（temporal locality）**：刚访问过的位置，很可能马上再被访问——循环体、计数变量、热数据都是典型。<span class="marginnote">`sum += a[i]` 里的 `sum` 每轮都被读写——它是时间局部性的完美标本。正因为这样，编译器才敢把 `sum` 留在寄存器里，而不是每轮回内存。</span>

**空间局部性（spatial locality）**：刚访问过的位置附近的存储，很可能很快被访问——因为数组是连续存放的，遍历 `a[0], a[1], a[2]...` 就沿着内存地址顺路走下去。<span class="marginnote">行优先（row-major）的二维数组按行连续存放，于是 `a[i][j]` 的列循环（j 变化）走得快，行循环（i 变化）跳得远——「换循环次序」因此是矩阵运算最经典的缓存优化。这与《数值分析》里矩阵访存模式、以及《数据结构》里数组布局的讨论完全同构。</span>

**重点：** 局部性不是「程序员的个人品质」，而是**程序的物理属性**：一个数组的迭代顺序、一个 struct 的字段排列、一次冒泡排序的扫描方向，全都在跟硬件的缓存「商量」命中率。

## 2 SRAM 与 DRAM：两种记忆的价格战

层次结构里的「快端」与「慢端」，物理上是两种截然不同的存储元件：

**SRAM（静态随机存取存储器）**：用 6 个晶体管存一个比特，靠反馈保持状态，速度极快（接近 CPU），但贵、密度低。它是**缓存**的原料。<span class="marginnote">SRAM 的 6 管单元像一个微型跷跷板：两个反相器互相锁定，只要不断电状态就不掉。代价是面积——1MB 的 SRAM 能占一颗芯片不小的面积，这就是缓存容量「上不去」的物理原因。</span>

**DRAM（动态随机存取存储器）**：用 1 个晶体管 + 1 个电容存一个比特，电荷会泄漏，必须周期**刷新（refresh）**。容量大、便宜，但慢。它是**主存**的原料。<span class="marginnote">「动态」指的就是电容上的电荷会随时间漏光，必须每毫秒级刷新一次——刷新的行为，本质上就是 DRAM 每隔一段时间偷偷把自己的记忆重写一遍。</span>

**辨析｜易错点：** 通常所说的「内存条」是 DRAM，「处理器缓存」是 SRAM——两者名字都带 RAM，工艺、速度、成本天差地别。SSD（NAND 闪存）又是另一回事：它读比写快得多，还怕磨损，因此它的「缓存友好」策略与 SRAM/DRAM 完全不同。<span class="marginnote">磁盘/SSD 的访问延迟是毫秒级，比 DRAM 再慢三个数量级。正是这个「从 1ns 到 10ms 的 10^7 倍跨度」，逼出了几乎全部分层的设计。</span>

## 3 高速缓存：组、行、块

**高速缓存（cache）**位于 CPU 与主存之间，把主存划分成固定大小的**块（block）**，缓存以块为单位搬运数据。一个缓存由若干**组（set）**组成，每组容纳 $E$ 行（line），每行放一个块 + 有效位 + 标记（tag）。<span class="marginnote">缓存的世界里，最小单位不是字节而是块——一次访存未命中，会连块一起搬 64 字节。这 64 字节就是空间局部性被兑现的地方：你只要 `a[0]`，但连 `a[1]..a[15]`（int 数组）都捎带进来了。</span>

按「每组的行数 $E$」分三类：

**直接映射（direct mapped）**：$E=1$，每个地址只可能住进一个组——简单、但冲突频繁。<span class="marginnote">当两个常用变量的地址恰好映射到同一组，它们会互相把对方挤出去——「冲突缺失」随之而来。二维数组按列遍历正好踩中这个雷：列首元素们常映射到同一组，一行行地被冲掉。</span>
**组相联（set associative）**：$E > 1$，每个地址可以住进组内 $E$ 行之一——折中方案，也是现代缓存的常态（8 路组相联很常见）。<span class="marginnote">相联度（associativity）越高，冲突越少，但每组的比较逻辑越贵——「8 路」意味着一次访存要并行比较 8 个标记。容量、块大小、相联度，三者是缓存设计的一组互相拉扯的旋钮。</span>
- **全相联（fully associative）**：全缓存只有一组，地址可放任意一行——弹性最大，但比较成本高，只用于 TLB 这类小型缓存。

## 4 缓存地址的拆分

给定一个内存地址，缓存如何知道它该住进哪个组、以及是否命中？把地址从低位往高位拆成三段：

$$
\begin{aligned}
\text{块偏移（block offset）} &: b \text{ 位} \qquad 0 \le \text{偏移} < B \\
\text{组索引（set index）} &: s \text{ 位} \qquad 0 \le \text{组号} < S \\
\text{标记（tag）} &: t \text{ 位} \qquad m = t + s + b
\end{aligned}
$$

低 $b$ 位是块内偏移（确定块大小 $B = 2^b$ 字节），接着 $s$ 位是组索引（组数 $S = 2^s$），剩下的 $t$ 位是标记（区分同一组里的不同块）。命中判定 = 有效位为 1 且标记匹配。<span class="marginnote">标记为什么要高位？因为高位决定了「这个地址落在哪个大的区域」。两个地址若只有高位不同而低位相同，就会争抢同一组——这就是冲突缺失的数学来源。</span>

**重点：** 读取一个元素时，缓存先按组索引定位到组，再在组内逐行比对标记。命中，直接返回数据；缺失，从主存搬一个整块进来，若组已满，按**替换策略**（LRU、随机等）淘汰一行。

## 5 命中、缺失与三类缺失

**缓存命中（hit）**：数据已在缓存，无额外等待；**缓存缺失（miss）**：数据不在，需从下一层搬块，代价是一个「缺失惩罚」（通常几十到上百个周期）。缺失分三类：

**强制缺失（compulsory）**：第一次访问一个块，缓存里不可能有——无法避免，只能靠预取（prefetching）提前搬进来。<span class="marginnote">对磁盘而言，第一次读文件是强制缺失；SSD 的顺序预读，就是操作系统在替程序「抄近路」。</span>
**容量缺失（capacity）**：工作集大于缓存容量，块被挤出后又要回来——大缓存或换掉工作集才能缓解。
- **冲突缺失（conflict）**：明明容量够，但两个块争同一组——提高相联度或重新排数据布局（padding、换遍历顺序）可以缓解。<span class="marginnote">冲突缺失是「完全正确但很慢」的经典来源：算法没问题，只是两个热变量的地址撞了车。诊断它需要第六章的性能计数器；治好它常常只是加一个 `pad[7]` 或换一下循环方向。</span>

**辨析｜易错点：** 三种缺失的「治疗方案」完全不同——强制缺失靠预取，容量缺失靠换工作集，冲突缺失靠布局与相联度。把三者混为一谈，是缓存性能调优最常见的思路混乱。

## 6 把层次结构延伸：主存之外

层次结构并不止于主存：主存 → SSD/磁盘之间还有操作系统管理的**页面缓存（page cache）**，磁盘之上还有快照与备份——每一层都在用「局部性 + 更大的容量」为上一层「打掩护」。<span class="marginnote">你 `read` 一个文件时，数据先被内核读进页面缓存，进程再从缓存 copy 到用户空间——同一次 I/O 经过了至少两层「缓存」。这与第九章《虚拟内存》的页面表、按需调页直接相连。</span>

**重点：** 程序员能直接利用层次结构的三板斧：**把频繁访问的数据放进更小但更快的层**（寄存器变量、把热 struct 字段放前面）、**改善局部性**（按行访问矩阵、调整 struct 布局）、**预取**（顺序读取、`prefetch` 指令、批量处理）。这些手法在《数据结构》《数值分析》《数据库》专题里会以「缓存友好」的名义反复出现。

## 7 小结

- 存储器层次结构是一套**速度与容量**的梯度：寄存器 → SRAM 缓存 → DRAM 主存 → SSD/磁盘，每差一层约三个数量级。
- **局部性**（时间 + 空间）是缓存能生效的唯一前提，也是程序可被优化的物理属性。
- SRAM 快而贵（做缓存），DRAM 慢而便宜（做主存），两者都是「随机存取」但不是同一种工艺。
- 缓存按 **组 / 行 / 块** 组织，地址拆成 **标记 + 组索引 + 块偏移** 三段；直接映射、组相联、全相联是相联度的三个档位。
- 缺失分**强制、容量、冲突**三类，各自对症下药。
- 层次结构一直延伸到主存之外的页面缓存与磁盘——它是第九、十、十二章全部机制的舞台。
