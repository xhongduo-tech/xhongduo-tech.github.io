## 为什么从机器级表示开始

上一章我们学会了「位模式怎么解释成数据」，这一章要看「位模式怎么驱动行为」：一段 C 代码经过编译器变成**汇编语言**之后，机器到底在逐条做什么。

对应用开发者来说，汇编是「可移植性」的反面，平时没人手写；但它是最好的显微镜。**性能优化**、**缓冲区溢出**、**反编译**、**调试器**、**操作系统底层**——每一样都要透过这层玻璃才能看清。<span class="marginnote">这也是 CS:APP 贯穿三章（机器级表示、处理器体系结构、优化性能）的逻辑：汇编是「指令语义」的答案，流水线是「指令如何快跑」的答案，优化是「怎么利用这两者」的答案。</span>

需要说明的是，本专题全程使用 **x86-64** 指令集（即 Intel/AMD 的主流 64 位架构），并按 GCC 生成的 **AT&T 语法**来讲——这是 Linux 世界、也是 CS:APP 默认的表示法。<span class="marginnote">AT&T 语法最反直觉的一点：操作数顺序是「源，目的」，与 Intel 语法的「目的，源」相反；寄存器前加 `%`，立即数前加 `$`。同一行汇编在两种语法下互为镜像。</span>

## 1 寄存器与数据传送

x86-64 有 16 个 64 位通用寄存器：`%rax`、`%rbx`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%rbp`、`%rsp` 与 `%r8`~`%r15`。每个寄存器可按需取部分：`%rax` 的低 32 位叫 `%eax`，低 16 位叫 `%ax`，低 8 位叫 `%al`——一份存储，多种宽度视图。<span class="marginnote">寄存器是 CPU 内部最快的存储，一般十几个；编译器把它们当作「活变量」的暂存室，函数返回前把要存活的值搬回内存。寄存器分配的质量直接决定汇编行数与性能。</span>

**数据传送指令 `mov`**：`movq`（64 位）、`movl`（32 位）、`movw`（16 位）、`movb`（8 位），格式为 `mov 源, 目的`。操作数有三类：

**立即数（immediate）**：`$0x4` 这样的常量，直接写在指令里；
- **寄存器（register）**：`%rax`；
- **内存（memory）**：`Imm(%rb, %ri, s)` 形式，表示地址 `Imm + %rb + %ri × s`——这就是数组与指针的汇编根基。<span class="marginnote">例如 `movq (%rdi), %rax` 表示「把 `%rdi` 所指地址处的 8 字节读进 `%rax`」；`movq %rax, (%rdi)` 则反向把值写回内存。内存访问是 C 指针语义的唯一汇编通道。</span>

**重点：** `mov` 不改变源值，且**从不更新条件码**——这一点在与 `add` 等指令对比时会变得重要。

## 2 算术与逻辑：lea 与四则运算

算术指令以 `addq`、`subq`、`imulq`（有符号乘）、`negq`（取负）、`incq`、`decq` 为主，语义与 C 对应。其中最独特的是一条「看起来是内存访问、其实在算算术」的指令：

**`lea`（load effective address）**：`leaq S, D` 把「地址 S 的数值」放入寄存器 D，而不访问内存。`leaq 7(%rdx, %rdx, 4), %rax` 把 $5 \times \%rdx + 7$ 这个数本身放进 `%rax`。<span class="marginnote">`lea` 是编译器的手工表达式引擎：一次 `lea` 就能完成「乘 2/4/8 + 加寄存器 + 加常量」，比如计算 `i*12+5`、`p+8` 这类 C 表达式几乎都被编译成 `lea`，既快又不碰内存。</span>

**辨析｜易错点：** `leaq` 不读内存，`movq` 才读。`leaq (%rdi), %rax` 只是「把指针值拷进 `%rax`」，等价于取地址；而 `movq (%rdi), %rax` 才真正解引用。这两行长得像，语义差一个「*」。

## 3 控制流：条件码与跳转

CPU 没有「if」——它只有**条件码（condition codes）**：一组由算术指令自动更新的 1 位标志。最常用的四个：**ZF**（结果为零）、**SF**（结果为负）、**CF**（无符号溢出）、**OF**（补码溢出）。<span class="marginnote">条件码不用指令显式保存：`addq` 之后 `ZF` 反映「和是否为 0」，`OF` 反映「是否补码溢出」。所以上一章讲溢出时说的「两个正数相加得负数」，硬件正是用 OF 位记下来的。</span>

比较用 `cmpq 源, 目的`：它像减法但丢弃结果、只更新条件码；`testq 源, 目的` 像按位与，同样只更新标志——常用于判零：`testq %rax, %rax` 后 `ZF` 表示 `%rax == 0`。

跳转指令 `jmp`、`je`（等于跳）、`jne`、`jg`/`jl`（有符号大于/小于）、`ja`/`jb`（无符号大于/小于）根据条件码决定下一条指令的地址。<span class="marginnote">注意有符号与无符号比较用不同的跳转助记符：`jg` 看 SF 与 OF 的关系，`ja` 看 CF。上一章「转换只换解释」的教训在这里表现为「比较也分两套」。</span>

**重点：** 编译器把 `if`、`while`、`for` 全部翻译成**条件跳转 + 标签**的组合。例如 `for` 循环的典型骨架：先 `cmpq`，再 `jle` 跳回循环体开头；循环条件不满足时跳出。理解这条骨架，是后面优化章节讨论循环展开、预测失败的起点。

## 4 过程调用：栈与栈帧

过程调用（函数调用）的机器层机制是本章的枢纽，由三件事构成：

**调用栈（stack）**：一块从高地址向低地址增长的内存区，`%rsp` 永远指向栈顶（最低地址）。`pushq` 把 `%rsp` 减 8 后存入，`popq` 读出后把 `%rsp` 加 8。<span class="marginnote">栈向下增长、且 8 字节对齐（栈指针按 8 的倍数变化），是 x86-64 的硬约定。CS:APP 在第七章还会说明：调用前栈指针必须满足 16 字节对齐，否则某些库函数（SSE 指令）会崩溃。</span>

**调用指令**：`call 标签` 把返回地址（`call` 的下一条指令地址）压栈，再跳转到目标；`ret` 从栈顶弹出返回地址并跳回。这一压一弹，是「过程调用能正确回到调用点」的全部秘密。<span class="marginnote">栈为什么能无限嵌套？因为每次调用都开一段新空间（新栈帧），返回时销毁——「后进先出」天然匹配递归的「先进后出」结构。栈溢出（stack overflow）就是这段空间耗尽。</span>

**参数传递约定**：x86-64 用寄存器传前 6 个参数：`%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`，返回值放在 `%rax`；更多参数才用栈。被调用方保存（callee-saved）寄存器如 `%rbx`、`%rbp` 由被调函数负责还原，调用方保存（caller-saved）寄存器如 `%rax`、`%rcx`、`%rdx` 由调用方在必要时自己保护。<span class="marginnote">「谁负责保存」是编译器在函数间划分的君子协定：callee-saved 的寄存器，被调函数如果要用就得先压栈、返回前恢复，于是调用方可以放心地在调用前后继续使用它们。这份协定的遵守，构成了函数边界上不可见的信任网络。</span>

## 5 数组、结构与指针的机器模样

数组 `int A[10]` 在汇编里就是「一段连续内存」，`A[i]` 的地址是 `A 的基址 + i × 4`（`int` 占 4 字节）——这正好落进寻址模式 `基址 + 变址 × 缩放`：`movl (%rdi, %rcx, 4), %eax`。**数组越界在汇编层没有任何检查**，因为你访问的只是「另一块内存的地址」。<span class="marginnote">这正是 C 数组「免费但危险」的机器根源：`A[10]` 与 `A[3]` 在硬件眼中没有任何区别，都是地址计算。越界写可能恰好落在另一个变量上——下一节的缓冲区溢出就是靠这个原理展开的。</span>

**结构体（struct）**的成员在内存里按声明顺序连续排放，并遵循**对齐（alignment）**规则：成员地址必须是其大小的倍数。<span class="marginnote">对齐是为了让 CPU 单次访存就能拿到完整字段：4 字节字段若跨在 4 字节边界上，一次读会变成两次。编译器因此会在成员间插入填充字节（padding）——这也是为什么 `struct` 重排字段顺序可以省内存。这与信息表示章「位模式本身不含意义」是一对镜像：意义与布局都由编译器规则制造。</span>

## 6 缓冲区溢出：机器层的安全代价

`gets`、`strcpy` 这类函数不做边界检查，把超长输入写进栈上缓冲区时，会向上覆写**返回地址**——函数 `ret` 时跳进攻击者设定的地址，这就是**缓冲区溢出（buffer overflow）**。<span class="marginnote">1988 年的莫里斯蠕虫（Morris worm）就是利用 `fingerd` 的 `gets` 漏洞完成自我复制。缓冲区溢出是计算机安全史上最重要的单点技术成因。</span>

现代防御层层加码：**栈金丝雀（stack canary）**在返回地址前放一个随机数，返回前校验；**ASLR** 随机化代码与栈的基址，让攻击者猜不中目标地址；**NX（不可执行栈）**让栈上数据无法当代码执行。但防线总会漏——所以 CS:APP 反复强调：**只要会写 C，就必须知道这段机器层的历史**。<span class="marginnote">栈金丝雀名字的来源很妙：矿工下井时带一只金丝雀，瓦斯泄漏先毒死它；程序则在缓冲区与返回地址之间放一个「会先死」的哨兵值。防御的想象力往往就藏在一次命名里。</span>

## 7 公式解析：寻址模式的有效地址

x86-64 内存寻址统一写作 `Imm(%rb, %ri, s)`，其**有效地址（effective address）**为：

$$
EA = \mathrm{Imm} + R[r_b] + R[r_i] \cdot s, \qquad s \in \{1, 2, 4, 8\}
$$

分四步拆解：

- **第一步，看不变项 `Imm`**：一个编译期常量，如 `-8`、`0x40`。它常常是结构体字段的偏移量。
- **第二步，看基址寄存器 $r_b$**：$R[r_b]$ 是它的当前值，通常装着数组基地址或指针。
- **第三步，看变址与缩放 $r_i \cdot s$**：$R[r_i]$ 是索引，$s$ 必须是 1、2、4、8——恰好对应 `char`、`short`、`int`、`long` 的字节数。这就是「`A[i]` 自动乘以元素大小」的汇编真相。
- **第四步，合成**：$EA$ 就是 C 表达式里 `指针 + 偏移 + 下标×元素大小` 的一次性翻译。`leaq` 与 `movq` 的区别仅在于：取 `EA` 的值（lea）还是取 `EA` 处的内容（mov）。

## 8 小结

- x86-64 的 16 个寄存器与 `mov` 家族构成数据移动的基本设施；操作数分**立即数、寄存器、内存**三类。
- `lea` 是编译器免费的算术引擎，不读内存；算术指令自动更新**条件码** ZF/SF/CF/OF。
- 控制流 = 条件码 + 跳转：`cmp`/`test` 只改标志，`jX` 决定走向；有符号与无符号比较用不同的跳转。
- 过程调用靠**栈 + `call`/`ret`** 实现；寄存器传参、`%rax` 返回，caller-saved 与 callee-saved 的君子协定维持函数边界。
- 数组是连续内存加寻址公式，越界无检查；struct 依赖对齐与填充。
- **缓冲区溢出**是栈布局与不检查边界叠加的产物，金丝雀、ASLR、NX 是它的当代防线。
