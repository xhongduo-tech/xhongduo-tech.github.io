## 为什么从信息表示开始

一台计算机能认识的全部东西，是 0 和 1。**所谓编程，很大一部分工作是决定「这串 0 和 1 是什么意思」。** 同一个位模式 `0xFF`，按无符号数看是 255，按补码看是 −1，按浮点数看是 NaN，按 ASCII 看是 ÿ——机器自己并不知道它在处理什么，是程序的类型系统给了它解释。<span class="marginnote">这正是 CS:APP 开篇的核心论点：「机器对位模式的意义一无所知」——意义永远是由使用者（程序员、编译器、运行时）赋予的。想通这一句，后面的补码、IEEE 754、字节序全都不再神秘。</span>

这一章是全专题的地基：程序的一切「诡异行为」——溢出、截断、浮点误差、整型反转——都是表示规则的直接后果。它与第一级数学里的进制、离散数学里的布尔代数相衔接，也为下一章《程序的机器级表示》里的寄存器与指令铺路。甚至到大模型：token 的 vocabulary 本质上是一张「整数 → 嵌入向量」的映射表，而量化把 fp32 权重压成 int8 时发生的截断，正是本章要讲的精度与范围问题。<span class="marginnote">量化（quantization）就是把连续权重映射进有限位宽的格子——它遇到的溢出与舍入，与本章讲的整数回绕、浮点舍入是同一件事。到《机器学习》与《深度学习》专题我们还会回来。</span>

## 1 比特、字节与十六进制

计算机内部的最小信息单位是**比特（bit）**：一个取 0 或 1 的二值符号。把 8 个比特并在一起叫一个**字节（byte）**，它是机器寻址的最小单位。2 的幂次是编程者的第二语言：$2^{10}=1024=1\mathrm{K}$，$2^{20}=1\mathrm{M}$，$2^{30}=1\mathrm{G}$——所谓「1 GB 内存」实际是 $2^{30}=1073741824$ 字节，而不是 $10^9$ 字节。<span class="marginnote">二进制与十进制的 1K 之差：磁盘厂商爱用十进制 1000，内存容量用二进制 1024。同一块「500G」硬盘在两个标准下能差出几十 GB——这是信息表示第一次以真金白银的形式出现在生活里。</span>

字节内部是二进制，但人眼读二进制太长，**十六进制（hexadecimal）**成为标配：每 4 个比特对应一个十六进制位，`0000~1111` 对应 `0~F`，于是两个十六进制位正好描述一个字节。<span class="marginnote">十六进制是从字节到人眼的翻译器：`0x3F` 一眼能看出是 `0011 1111`；若写成十进制 63，反而要想半天。C 的 `0x` 前缀、汇编的 `0x`、Python 的 `0x`，都是同一个约定。</span>

**大小端（byte ordering）**：一个多字节数在内存里按什么顺序存放？x86 把最低有效字节放在最低地址，叫**小端（little-endian）**；网络协议用**大端（big-endian）**。<span class="marginnote">`int x = 0x01234567`，在小端机器的内存里看到的是 `67 45 23 01`。为什么小端能赢？因为从低位开始的加法可以「边读边算」，整数比较也不必等整个数读完——这是非常实际的硬件工程理由。</span>

**辨析｜易错点：** 大小端只影响「字节在内存里的排列」，不影响算术结果。`0x01234567` 作为整数永远是 `0x01234567`，无论怎么存放。只有当你用 `char` 指针逐字节去看、或者把数据写进文件、网络再异地读回时，大小端才变得性命攸关。

## 2 无符号编码与补码编码

整数用两种编码存储：**无符号数（unsigned）**与**二进制补码（two's complement）**。设字长为 $w$ 位、位向量 $\vec{x} = (x_{w-1}, x_{w-2}, \dots, x_0)$，则：

$$
B2U_w(\vec{x}) = \sum_{i=0}^{w-1} x_i \, 2^i
$$

$$
B2T_w(\vec{x}) = -x_{w-1}\, 2^{w-1} + \sum_{i=0}^{w-2} x_i \, 2^i
$$

无符号数把每一位都当正权重；补码把**最高位当作负权重** $-2^{w-1}$，其余照旧。这一改动换来两件大事：一是加减乘的硬件逻辑对有符号与无符号完全一致（本质是模 $2^w$ 的环运算），二是 0 只有一种表示（不像原码有 +0 与 −0 两种）。<span class="marginnote">「补码」名字的来源：$x$ 的相反数恰好是「按位取反再加一」，即 $-x \equiv \sim x + 1 \pmod{2^w}$。`-x == ~x + 1` 是这个编码最著名的恒等式，也是 `int` 类型一切诡异行为的源头。</span>

**重点：** 常用范围的边界要背下来。以 32 位为例：无符号数取值范围 $[0,\, 2^{32}-1]$，补码取值范围 $[-2^{31},\, 2^{31}-1]$，即 `TMin = -2147483648`、`TMax = 2147483647`。C 标准库里的 `INT_MIN`、`INT_MAX`、`UINT_MAX` 就是这三者的名字。

## 3 转换、符号扩展与截断

C 里 `int` 与 `unsigned` 混用时会发生隐式转换：**有符号被转成无符号，位模式不变，只换解释**。<span class="marginnote">这就是 CS:APP 那句名言「有符号与无符号之间的转换：位不变，意义变」。`-1` 与 `UINT_MAX` 是同一串 `0xFFFFFFFF` 的两种读法。</span>

**辨析｜易错点：** `unsigned` 的一切比较要格外小心。`if (i < sizeof(x))` 这种写法几乎必错——`sizeof` 返回无符号的 `size_t`，若 `i` 为负，`-1` 会被转成巨大的无符号数，比较结果为假，紧跟着的数组访问直接越界。CS:APP 用 `strlen` 与 `sizeof` 的经典组合演示了这个坑：`strlen(s) - strlen(t) > 0` 恒为真，因为它被转成了无符号减法。

**符号扩展（sign extension）**：把短的补码变长（如 `int8_t` → `int64_t`），在左边填充最高位（符号位）的副本，值不变；无符号数变长则填 0。**截断（truncation）**：把长数砍成短数，直接丢弃高位，值按模 $2^w$ 回绕。<span class="marginnote">截断规则：`x` 从 $w$ 位截成 $k$ 位，结果等于 $x \bmod 2^k$。`short s = (short) 65536;` 得到 0——因为 $65536 \equiv 0 \pmod{65536}$。</span>

## 4 整数运算：溢出与回绕

**溢出（overflow）不是错误，而是回绕（wrap-around）的数学结果。** 无符号加法溢出后，结果是 $x+y \bmod 2^w$；补码加法溢出后，结果相当于在环 $\mathbb{Z} / 2^w\mathbb{Z}$ 上求和，符号会突变。<span class="marginnote">补码加法的硬件就是无符号加法，溢出与否只取决于你如何解释结果——这也是为什么现代处理器里 `add` 指令只有一个版本。</span>

判断溢出的方法：两个正数相加得负数、或两个负数相加得正数，必溢出；无符号加法中结果小于任一加数，必溢出。<span class="marginnote">这个判据常被写进安全代码：`t = a + b; if (t < a) overflow;`——而开启优化后的编译器可能把这段「冗余」判断删掉，因为它合法地假设无符号加法不溢出。系统与安全的交界，见《系统安全》专题。</span>

另一个著名陷阱是 `-TMin`：$-\mathrm{TMin} = \mathrm{TMin}$。取反不改变边界，所以 `abs(INT_MIN)` 仍是负数。CS:APP 把这一系列规则统一为一句：**整数运算是模 $2^w$ 的环运算**——只要接受这一点，所有「怪象」都变得自然。

## 5 位运算、移位与掩码

位级运算 `&`、`|`、`~`、`^`（按位与、或、非、异或）对位向量逐位施加布尔代数，这正是离散数学里布尔代数的硬件落地。<span class="marginnote">异或 `^` 的三个妙用：与 1 异或即取反、与 0 异或保持不变（是「可控取反」开关）、自反性 `a ^ b ^ b == a`——曾用于不引入临时变量的交换。</span>

**移位**：左移 `<<` 一律补 0；右移 `>>` 分两种——无符号数**逻辑右移**补 0，有符号数**算术右移**补符号位（保留符号）。<span class="marginnote">算术右移让负数右移后仍为负数：`-8 >> 1 == -4`。所以右移不等于「整除 2」的机械翻译——整数除法向零取整，右移向负无穷取整，两者只在非负时一致。</span>

**掩码（mask）**是位运算最常见的工程模式：取低 8 位 `x & 0xFF`，判断奇偶 `x & 1`，把第 $k$ 位置 1 `x | 1<<k`，翻转某位 `x ^ (1<<k)`。<span class="marginnote">掩码思维将贯穿全书：虚拟地址的页内偏移就是 `addr & (P-1)`（$P$ 为 2 的幂），哈希桶索引用 `hash & (n-1)`——「用 2 的幂做模运算来免除法」是系统级编程的高级技艺。</span>

## 6 浮点数：IEEE 754

浮点数用**符号位 s、阶码（exponent）e、尾数（fraction）f** 三部分表示，规格化数的值约为 $(-1)^s \times 1.f \times 2^{e-bias}$——这是二进制的科学计数法。<span class="marginnote">阶码用偏移量（bias）存储：float 的 bias 是 127，double 是 1023。全 0 阶码表示次正规数与零，全 1 阶码表示无穷大与 NaN——IEEE 754 把位模式的一小部分「租」给了特殊值。</span>

**重点：** 规格化数、次正规数、无穷、NaN 四种形态，边界都在指数位模式上：阶码全 0 → 次正规数（弥补下溢台阶），阶码全 1 且尾数全 0 → $\pm\infty$，阶码全 1 且尾数非 0 → NaN。<span class="marginnote">NaN 是全章最容易翻车的值：IEEE 规定 `NaN != NaN` 永远成立，于是 `x == x` 在 `x` 为 NaN 时为假——这成了检测 NaN 的标准手法。</span>

浮点的「不精确」来自**舍入**：有限位尾数放不下 $1/10$ 的二进制展开（$0.1_{10}$ 在二进制里是无限循环小数），于是 `0.1 + 0.2 != 0.3`。这不是 bug，是表示的物理约束。**辨析｜易错点：** 永远不要用 `==` 直接比较浮点结果，请改用绝对误差或相对误差阈值。

## 7 公式解析：补码解码公式 B2T_w

$$
B2T_w(\vec{x}) = -x_{w-1}\, 2^{w-1} + \sum_{i=0}^{w-2} x_i \, 2^i
$$

对这条全章最重要的公式做四步拆解：

- **第一步，看最高位 $x_{w-1}$**：它是「符号位」，但权重是**负数** $-2^{w-1}$，而不是「符号加绝对值」里的那个负号。这个差别是理解补码的关键——最高位不只是告诉你正负，它真的参与数值。
- **第二步，看其余位**：$\sum_{i=0}^{w-2} x_i 2^i$ 中所有低位权重都是正的，与无符号编码完全一致。
- **第三步，算一个例子**：$w=4$，$\vec{x}=1111$。最高位贡献 $-2^3=-8$，低位贡献 $2^2+2^1+2^0=7$，合计 $-1$。所以 `0xF` 在 4 位补码里是 −1——这是最常被引用的结果。
- **第四步，理解设计动机**：因为 $-1$ 与 $2^4-1=15$ 的位模式相同，补码把「减法」变成「加上 −1 的位模式」，硬件只需一套加法器。所有溢出的「怪象」都源于此。

## 8 小结

- 一切信息是位模式，**意义由解释者赋予**；字节是最小寻址单位，十六进制是人眼与字节之间的翻译器。
- 整数两套编码：**无符号**全正权重，**补码**最高位为负权重；补码把整数运算统一为模 $2^w$ 的环运算。
- 转换只换解释不换位；**符号扩展补符号位、截断按模 $2^w$ 回绕**。
- 溢出是回绕而非错误，`-TMin == TMin` 这类边界行为要背熟。
- 位运算与掩码是系统编程的日常工具；右移分**逻辑右移**（补 0）与**算术右移**（补符号位）。
- 浮点数用**符号 / 阶码 / 尾数**三字段，舍入与特殊值（$\infty$、NaN）是 IEEE 754 的规定，浮点比较必须带误差。
