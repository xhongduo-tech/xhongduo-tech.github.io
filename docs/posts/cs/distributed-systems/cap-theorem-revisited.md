# CAP 定理及其正确解读

## 为什么从 CAP 定理开始

上一篇我们度量了性能、可用性与可扩展性。可当数据被复制到多台机器上，「同一份数据在不同机器上不一致」就成了日常。CAP 定理是被引用最多、也**被误解最多**的分布式定理。它说：网络分区不可避免，分区时你必须在一致性与可用性之间二选一。<span class="marginnote">在 6.824 与 DDIA 里，CAP 都只是开场白而非结论：它指出「你总得放弃点什么」，却没有告诉你放弃之后怎么活得更好——那正是后面所有复制、共识、最终一致性技术要做的事。</span>

## 1 三个字母的真实含义

CAP 三个字母分别指：

**C —— 一致性（Consistency）**：这里的定义是**线性一致性**，即读到的必须是最近一次写入的值，所有节点看起来像一台单机。
**A —— 可用性（Availability）**：**每个**收到的请求都必须得到响应，且响应必须是非错误结果——不能因为节点间联系不上就拒绝服务。
**P —— 分区容忍性（Partition Tolerance）**：网络分区（消息丢失、节点失联）发生时，系统仍能继续运行。

关键在 P 的性质：分区不是一种「选择」，而是物理现实——网络会丢包、会断、会慢，你无法禁止分区发生。**你只能决定分区发生时，系统表现得像一致的系统，还是像可用的系统。**<span class="marginnote"><strong>辨析｜易错点：</strong>很多文章把 CAP 说成「三选二」，仿佛可以在 C、A、P 中任选两个。但 P 不可弃——你不可能「不要分区容忍」，因为网络故障由物理世界决定。真正的选择永远是「分区时保 C 还是保 A」。</span>

## 2 为什么三者不可兼得

设想两个节点 $N_1$ 与 $N_2$，各自存着变量 $x$，初始值都是 $N_1$。现在客户端向 $N_1$ 写入 $N_2$，$N_1$ 成功响应；随后网络把 $N_1$ 与 $N_2$ 隔断（分区）。此时客户端向 $N_2$ 发起读 $x$ 的请求，只有两种可能：

**保一致性**：$N_2$ 知道自己的 $x$ 是过期的 $N_1$，于是拒绝响应（或阻塞等待 $N_1$ 恢复）——这违反了可用性（请求没得到非错误响应）。
**保可用性**：$N_2$ 返回自己看到的旧值——但这违反了线性一致性（读到了旧值）。

两条路都被堵死，所以**当分区发生时，C 与 A 无法同时满足**。这是一个物理性结论，不依赖任何实现细节。<span class="marginnote">1999 年 Brewer 在 PODC 提出该猜想，2002 年 Gilbert 与 Lynch 给出严格证明。证明的关键假设是「有限异步通信」——你无法确定对端到底是死了还是只是慢，这正是部分失败问题在 CAP 里的投影。</span>

## 3 CAP 的正确打开方式

把 CAP 简化成「P 不可选，分区时在 C 和 A 之间选」之后，正确的决策框架浮现出来：

**分区不存在时，系统可以同时是「一致且可用」的**——C 与 A 的冲突只在分区发生的窗口期出现。所以真正的工程问题是：**你的系统愿意在分区期间承受多少不一致，以换取多少可用性？**据此系统大致分为三类：

- **CP 系统**：分区时拒绝部分读写，优先保证一致性。典型如 ZooKeeper、etcd、Spanner（分区时牺牲可用性）。
- **AP 系统**：分区时继续接受读写，返回可能过期的数据，事后收敛。典型如 Dynamo、Cassandra、CouchDB。
- **CA 系统**：无分区的单机或少数派系统——严格说「CA」在分布式语境下几乎不存在，因为分区总会来。

**辨析｜易错点：**不要用 CAP 给系统贴永久标签。同一个系统在不同操作、不同时段可以是 CP 或 AP——例如 Cassandra 可调一致性，选 QUORUM 时偏 CP，选 ONE 时偏 AP。CAP 描述的是**某个操作在分区瞬间的行为**，不是系统的静态分类。

## 4 公式解析：从「2 选 1」到「P 恒成立」

把上面的二选一论证压缩成一条逻辑链：

$$
\underbrace{(C \land A)}_{\text{同时满足}} \Rightarrow \neg P \qquad \Longleftrightarrow \qquad P \Rightarrow \neg (C \land A)
$$

拆解这行式子：

- **第一行左边**：若系统同时满足一致性 C 与可用性 A——每个读都返回最新值、每个请求都有响应——那么分区不可能发生。因为一旦分区，上面的 $N_1$/$N_2$ 反例就会立即推翻 C 或 A。
- **第一行右边**：由逆否命题，**若分区会发生（P 为真），则 C 与 A 至少牺牲一个**。
- **工程读数**：$\neg (C \land A)$ 不是 $\neg C \lor \neg A$ 的二选一那么简单——它说的是**在分区的那个瞬间**二选一。分区结束后，系统可以（也应该）重新变得又一致又可用。

## 5 小结

- CAP 三个字母：**一致性**（线性）、**可用性**（每请求都有响应）、**分区容忍**（分区时继续运行）。
- **P 不可选**：分区是物理现实，只能决定分区时保 C 还是保 A。
- 二选一有严格证明：分区时存在一个节点持有过期数据，保 C 就拒绝服务（失 A），保 A 就返回旧值（失 C）。
- CAP 不是静态标签：同一系统可对不同操作提供不同保证；分区结束后 C 与 A 可以兼得。
- CAP 的价值是划定边界，不是给出答案——答案在后面的复制、共识与最终一致性技术里。
