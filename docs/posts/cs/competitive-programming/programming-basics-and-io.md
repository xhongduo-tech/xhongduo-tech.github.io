## 为什么从「读入与输出」开始

算法竞赛的第一课，不是数据结构，不是高深算法，而是**标准输入输出**。原因很朴素：任何程序都先要拿到数据，再吐出结果，中间才是算法施展的舞台。无论你将来要写 LeetCode 的题解，还是参加 ICPC、蓝桥杯，评测系统只看两样东西——你**从标准输入读进了什么**、你**向标准输出打印了什么**。读入写错，算法再漂亮也是零分。这一章，我们就从这门手艺的起点出发，把「输入—处理—输出」这条流水线彻底打通。

## 1 头文件与主函数：程序的骨架

C 语言程序的起点是一个**主函数（main function）**，操作系统加载程序后从它开始执行。加上头文件与返回值，一个最小但完整的程序长这样：

```c
#include <stdio.h>
int main() {
    printf("Hello, World!\n");
    return 0;
}
```

拆开看，有三个固定部件。**头文件（header file）** `#include <stdio.h>` 告诉编译器：我要用标准输入输出的函数，把它们的声明拿进来——`stdio` 是 *standard input/output\* 的缩写。<span class="marginnote">在 C++ 里常写 `#include <bits/stdc++.h>`，它一次性引入全部标准库头文件，竞赛中省事；但严谨工程里不推荐，因为编译时间与可读性都会变差。</span>**主函数** `int main()` 前的 `int` 表示它向操作系统返回一个整数，`return 0;` 表示「正常结束」。**函数体**用花括号 `{ }` 括起来，里面的语句用分号 `;` 结束。

**辨析｜易错点：** 主函数的名字必须是 `main`，一个程序也只能有一个。把 `main` 拼错成 `mian`，编译器不会报出「找不到主函数」这种亲切的提示，而是直接链接失败——这类错误在菜鸟阶段几乎人人都会撞上。

## 2 变量、常量与基本数据类型

程序要处理数据，就得先把数据**存起来**。在 C 语言里，每个数据都要有一个**类型（type）**，类型决定了它占用多少内存、能表示什么范围。

**变量（variable）** 是「有名字的存储空间」，先声明再使用：

```c
int n = 42;          // 整数
long long sum = 0;   // 更长的整数，竞赛中必用
double pi = 3.14159; // 浮点数
char c = 'A';        // 单个字符
```

竞赛中三个最容易踩的坑，都藏在类型里。<span class="marginnote">`int` 通常占 32 位，范围约 $-2^{31}$ 到 $2^{31}-1$，也就是 $-2147483648$ 到 $2147483647$——超过它就会「溢出」，行为不可预测。这是后续每一章都会反复强调的边界。</span>

**溢出（overflow）**：`int` 最大到约 $2.1\times10^9$。当求和、阶乘、$n^2$ 这类计算可能超过它时，一定要改用 `long long`。
**整数除法**：`7 / 2` 在 C 里等于 `3`，小数部分被直接丢弃，这是**向零取整**。
**浮点比较**：`0.1 + 0.2` 不一定精确等于 `0.3`，因为浮点数在计算机里是二进制近似存储的。

## 3 格式化输入输出：scanf 与 printf

输入输出的主力工具是 `printf`（打印输出）与 `scanf`（格式化读入）。它们的第一参数是**格式字符串（format string）**，里面的占位符决定了数据的读入与打印方式：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `%d` | 十进制整数 | `printf("%d", 42);` |
| `%lld` | `long long` 整数 | `printf("%lld", sum);` |
| `%f` | 单精度浮点 | `printf("%f", 3.14);` |
| `%.3f` | 保留 3 位小数的浮点 | `printf("%.3f", 3.14159);` |
| `%c` | 单个字符 | `printf("%c", 'A');` |
| `%s` | 字符串 | `printf("%s", s);` |

读入时有一个关键差别：**普通变量前要加取地址符 `&`**，因为 `scanf` 要把读到的值写进变量的地址，而不是变量本身。

```c
int n;
double x;
scanf("%d %lf", &n, &x);
```

**辨析｜易错点：** `double` 读入用 `%lf`，打印却可以用 `%f` 或 `%lf`——这是 C 标准的历史遗留，很多新手在这里栽跟头。更重要的是：`printf("%d", n)` 里的 `%d` 与后面变量类型不匹配时，编译器可能不报错，但打印出来的是垃圾值。

## 4 多组数据：竞赛读入的常见模式

算法竞赛的题目很少只读一组数据。最常见的三种模式是：

**模式一：读入 T，循环 T 组。** 第一行给出测试组数 `T`，之后每组数据分别读入：

```c
int T;
scanf("%d", &T);
while (T--) {
    // 读入并处理一组数据
}
```

**模式二：读到文件结束（EOF）。** 题目不说有多少组，读到输入结束为止。C 语言里用 `scanf` 的返回值判断：它返回成功读入的变量个数，读不到返回 `EOF`（值为 `-1`）。

```c
int a, b;
while (scanf("%d %d", &a, &b) == 2) {
    printf("%d\n", a + b);
}
```

**模式三：两个标记值结束。** 读到特定的终止数据（如 `0 0`）就停止。<span class="marginnote">`while (scanf(...) == 2)` 这种写法把「读入」和「是否继续」合并成一个条件，是竞赛代码里最经典的惯用法。循环体内不要再写一次 `scanf`，否则会漏读或错读。</span>

**辨析｜易错点：** 模式二里，`while (scanf("%d %d", &a, &b) == 2)` 千万不能写成 `while (scanf(...) != EOF)`——当读入到一半文件结束时，返回值是 `1` 而不是 `EOF`，条件仍为真，你会用未定义的变量继续算。

## 5 公式解析：% 运算符与取余的边界

`%` 是取余运算符，`a % b` 表示 $a$ 除以 $b$ 的余数。它在竞赛中无处不在：判奇偶、哈希散列、循环计数、大数拆分。

$$
a = q \cdot b + r, \qquad 0 \le r \lt  b
$$

- **第一步，除法**：$q = \lfloor a / b \rfloor$ 是商，整数除法下自动得到。
- **第二步，余数**：余数 $r = a - q \cdot b$，恒满足 $0 \le r \lt  b$。
- **第三步，符号**：C 里取余结果与被除数同号，`-7 % 3 == -1`；判断整除要用 `a % b == 0`。

**辨析｜易错点：取余的符号陷阱。** `a % b` 的符号在 C/C++ 里与 `a` 一致，`7 % 3 == 1`、`-7 % 3 == -1`。哈希散列、循环计数、循环队列里用取余定位时，先确认数据是否可能为负——负数取余方向不同，边界就错。

## 6 小结

- 程序骨架：头文件 + 主函数 + `return 0`；`main` 拼成 `mian` 是链接失败的经典坑。
- 类型决定范围：`int` 上限约 $2.1\times10^9$，可能溢出就换 `long long`。
- `scanf` 读入要取地址 `&`；`%d/%lld/%lf/%c/%s` 与变量类型严格对应。
- 多组数据三模式：先读 `T` 循环、读到 EOF（`== 2` 惯用法）、读到标记值。
- 取余结果与被除数同号；判断整除用 `a % b == 0`。

在下一节，我们将进入**分支与循环结构程序设计**——把「读到数据」的骨架接上「判断与重复」的血肉，程序才能真正处理海量数据。
