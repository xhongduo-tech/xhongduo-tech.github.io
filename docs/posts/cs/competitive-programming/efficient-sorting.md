## 为什么从高效排序与排序应用开始

上一章我们学会了归并、快排这两个 $O(n\log n)$ 的通用排序。但「通用」不是全部——当数据有特殊性质（整数、小范围、有界）时，可以做到比 $O(n\log n)$ 更快的**线性排序**；而当排序本身不是终点时，把它当**预处理手段**去解决下一层问题，才是竞赛里排序真正的价值。这一章我们补齐两块：非比较排序（计数排序、基数排序）的原理，以及「排序 + 处理」的经典应用（Top-K、合并区间、中位数、按自定义规则排序）。

## 1 比较排序的下界：为什么 O(n log n) 已经很好

在动手学更快的排序前，先知道一个结论：**基于比较的排序，平均与最坏下界是 $\Omega(n\log n)$**。为什么？排序必须能区分 $n!$ 种可能的排列，而每次比较最多产生两种结果：

$$
2^k \ge n! \implies k \ge \log_2(n!) = \Theta(n\log n)
$$

- **第一步，决策树**：每个比较把候选排列一分为二，整个排序过程是一棵决策树。
- **第二步，数叶子**：叶子必须覆盖 $n!$ 种排列，所以树高 $k$ 满足 $2^k \ge n!$。
- **第三步，斯特林公式**：$\log_2(n!) \approx n\log_2 n - 1.44n$，所以 $k = \Omega(n\log n)$。

**重点：想打破 $O(n\log n)$，必须离开「比较」这个信息源。** 归并、快排、堆排都是比较排序，已经到头；想更快，只能利用数据的**额外结构**——比如值域是有限整数。这就是计数排序的出发点。<span class="marginnote">这个下界是算法理论里少有的「铁律」：它不依赖任何具体算法，只依赖「比较」这个操作的抽象模型。想明白它，你就能一眼识破「声称 $O(n)$ 比较排序」的荒谬。</span>

## 2 计数排序：利用值域做线性排序

**计数排序（counting sort）** 适用于值域已知且不大的整数数组。思想极其朴素：数清每个值出现几次，再按值从小到大「倒出来」：

```cpp
vector<int> countingSort(vector<int>& a, int K) {
    vector<int> cnt(K + 1, 0);
    for (int x : a) cnt[x]++;
    vector<int> res;
    for (int v = 0; v <= K; v++)
        while (cnt[v]--) res.push_back(v);   // 按顺序倒出来
    return res;
}
```

**核心概念：计数排序不是比较排序。** 它完全没做元素间的比较，而是用「桶计数 + 值域顺序」直接定位每个元素的位置——这正是它突破 $O(n\log n)$ 下界的原因。**稳定性**的版本则需要前缀和定位每个元素的落点，保证相同值的元素相对顺序不变。

**辨析｜易错点：** 计数排序的空间是 $O(K)$，$K$ 是值域大小。当 $K$ 远大于 $n$（如值域 $10^9$ 但只有 $10^5$ 个数）时，开 $10^9$ 的数组是灾难——**值域是计数排序的命门**，值域小才划算。

## 3 公式解析：计数排序的时间复杂度

计数排序的复杂度分三步数清：

$$
T(n, K) = O(n) + O(K) + O(n + K) = O(n + K)
$$

- **第一步，统计频率**：一趟扫描数组，每个元素进对应桶，$O(n)$。
- **第二步，按序倒出**：扫描值域 $0..K$，把每个值出现次数个元素写进结果，$O(K + n)$。
- **第三步，合计**：$T = O(n + K)$。当 $K = O(n)$（值域与规模同阶）时，$T = O(n)$，达到线性。

**重点：$O(n+K)$ 的含义。** 它不是无条件线性——当 $K$ 很大时退化成 $O(K)$。竞赛中计数排序常被用来做**基数排序的一个轮次**或**哈希表桶的思想**。能用一个「数组桶」的，就不要用哈希表——这与《数组与哈希表基础》的结论一脉相承。

## 4 排序的工程应用：Top-K 与中位数

排序本身是工具，竞赛中真正常见的是「排序后」的操作。

**Top-K 问题（找第 K 大）**：朴素做法是排序后取第 $K$ 个，$O(n\log n)$；但「只想知道第 K 大」其实不需要全序。C++ 的 `nth_element` 用快速选择思想，平均 $O(n)$ 完成，且把数组分成「前 K 个 + 后面」两段：

```cpp
nth_element(a.begin(), a.begin() + k, a.end(), greater<int>());
int kth = a[k];   // a[0..k] 是前 k+1 大，a[k] 是第 k+1 大
```

<span class="marginnote">`nth_element` 不保证排序，只保证「第 K 个元素就位」且左边都不小于它、右边都不大于它——这正好是快排 partition 的性质。面试里被问「Top-K 有几种做法」，答案谱系是：排序 $O(n\log n)$、堆 $O(n\log k)$、快速选择 $O(n)$，按数据规模与是否需要在线选。</span>

**Top-K 的另一种工具：堆**。维护大小为 $K$ 的小顶堆，遍历时比堆顶大就替换——复杂度 $O(n\log k)$，优势是**不用一次性拿到全部数据**（在线处理）。「排序全量」vs「堆维护前 K」是 Top-K 的两条标准路线。

## 5 排序作为预处理：三类经典组合

**合并区间**：按起点排序后一趟扫描合并重叠区间——乱序时的区间重叠判断是 $O(n^2)$，排序后变成相邻比较，$O(n\log n)$。

**自定义键排序**：把「多关键字」组合成一个比较规则。比如按「频率降序、值升序」排序，C++ 用 lambda 同时表达两个维度。

**稳定性应用**：先按主键排，再按次键排，若第二趟排序稳定，第一趟顺序得以保留。<span class="marginnote">「排序的稳定性在实战中的意义」：比如先按总分排、再按学号排，希望总分相同者按学号有序——第二趟用稳定排序（归并）就能同时满足两个键，快排则做不到。STL 的 `std::stable_sort` 就是稳定版归并。</span>

**辨析｜易错点：** 自定义比较器必须满足**严格弱序**：任何元素都不应「小于自己」，且 `a < b` 与 `b < a` 不能同时成立。写「`a.x < b.x || (a.x == b.x && a.y < b.y)`」这类比较器时，任何一个不等号方向写反，都会让排序结果未定义。

### 基数排序：按位多次计数排序

**基数排序（radix sort）** 是计数排序的进阶形态：当值域很大（如 $10^9$ 的整数）但每一位的取值很小（0-9 或 0-255）时，从**最低位到最高位**逐位做稳定的计数排序。它的巧妙在于：每一位只排这一位的大小，但「稳定」保证了上一位已排好的顺序不被破坏——经过 $k$ 轮（$k$ 是位数），整体就排好了。

```cpp
void radixSort(vector<int>& a) {
    int maxv = *max_element(a.begin(), a.end());
    for (int exp = 1; maxv / exp > 0; exp *= 10) {
        // 按当前位（个位、十位、百位……）做稳定计数排序
        vector<int> cnt(10, 0);
        for (int x : a) cnt[x / exp % 10]++;
        for (int i = 1; i < 10; i++) cnt[i] += cnt[i-1];  // 前缀和定位
        vector<int> t(a.size());
        for (int i = a.size()-1; i >= 0; i--) {
            int d = a[i] / exp % 10;
            t[--cnt[d]] = a[i];         // 倒序放置保证稳定
        }
        a = t;
    }
}
```

**核心概念：稳定性是基数排序的引擎。** 每一轮都是计数排序，而计数排序稳定版本用「前缀和 + 倒序放置」实现——从后往前放，保证相等元素保持原相对顺序，于是上一轮的排序结果被完整保留。基数排序对整数（或可拆位的对象）复杂度是 $O(k \cdot (n + B))$，$k$ 是位数、$B$ 是进制（如 10），当 $k$ 是常数时就是线性。

**辨析｜易错点：** 基数排序的循环次数取决于**最大值的位数**，不是数组长度。负数需要特殊处理（先整体偏移或按符号分组）。另外，它不像计数排序那样需要「值域小的前提」，而是需要「位数少的前提」——适合大值域、固定字节宽的整数，工程上常用于对 64 位整数或字符串的排序。

**重点：非比较排序的适用画像。** 计数排序吃「值域小」，基数排序吃「位数少」，两者都是「用数据的特殊结构换线性时间」。判断用哪种，先看数据长什么样；而 `std::sort` 这类通用比较排序，则永远是最稳妥的默认选项。

## 6 小结

- 比较排序下界 $\Omega(n\log n)$：决策树 $2^k \ge n!$；想更快必须利用数据的额外结构。
- 计数排序靠值域桶，$O(n+K)$，值域小才划算，不是比较排序。
- Top-K 三路线：全量排序 $O(n\log n)$、堆 $O(n\log k)$、`nth_element` 平均 $O(n)$
