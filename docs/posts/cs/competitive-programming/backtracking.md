## 为什么从回溯法开始

上一章的暴力枚举把「一切可能」都试一遍，但很多问题的解空间是**一棵决策树**——每个节点是一次选择，根到叶子的路径就是一个候选解。**回溯法（backtracking）** 就是在这棵树上做深度优先搜索：沿着一条路往下走，走不通就**回头**换一条路。它比朴素枚举强在两点：一是**剪枝**排除不可能的分支，二是**增量构造**不需要先造好全部候选。全排列、N 皇后、数独、括号生成、组合总和……回溯是覆盖面试与竞赛最广的一类套路。这一章，我们把回溯的「选—递归—撤销」三拍子练成肌肉记忆。

## 1 回溯的本质：解空间树上的 DFS

几乎所有回溯题都能画成一棵**解空间树（solution space tree）**。以生成 $n$ 个元素的全排列为例：根节点是「空序列」，第一层选第一个元素，第二层选第二个……每个叶子就是一个完整排列。

```cpp
vector<vector<int>> ans;
vector<int> path;
bool used[10];

void dfs(vector<int>& a, int n) {
    if (path.size() == n) { ans.push_back(path); return; }  // 叶子：得到一个解
    for (int x : a) {
        if (used[x]) continue;        // 剪枝：已经用过的元素
        used[x] = true;
        path.push_back(x);            // 做选择
        dfs(a, n);                    // 递归深入
        path.pop_back();              // 撤销选择（回溯）
        used[x] = false;
    }
}
```

**核心概念：回溯三拍子。** 每一次递归调用里都藏着三个动作：**做选择**（把候选加入当前解）→ **递归**（深入下一层）→ **撤销选择**（把状态恢复到递归前的样子，好让兄弟分支复用）。<span class="marginnote">「撤销」是回溯与普通 DFS 的分水岭。普通 DFS 里 `vis` 标记一旦置位就不再清除；回溯里每次返回前必须还原——不然兄弟分支会看到「被污染」的状态，答案错得莫名其妙。想清楚「哪些状态属于这条路径，哪些属于整棵树」，就能决定要不要撤销。</span>

## 2 状态恢复：回溯最容易翻车的细节

**辨析｜易错点：状态恢复不彻底。** 回溯的正确性几乎全部系于「撤销」这一下。三个高频错误：

**漏恢复**：`used[x] = true;` 了却忘了在递归返回后 `used[x] = false;`，导致后面的分支以为该元素已用。
**恢复错了对象**：`path.pop_back()` 弹出的是最后加入的元素，如果代码里 push 和 pop 的位置不对称，栈就乱了。
**全局变量被兄弟分支共享**：如果「当前和」「当前路径」是全局变量，回溯后必须恢复原值。

一个可靠的纪律：**做选择和撤销选择严格成对**，紧挨着递归调用写。凡是「递归调用前后对称操作」的结构，都符合回溯的约定。

## 3 剪枝的艺术：让回溯从指数级变得可行

回溯的复杂度最坏仍是指数级，但**剪枝**能在大多数数据上让它跑到飞快。剪枝的思路是：在深入之前，就用局部信息判断「这条路还有没有希望」，没希望就提前回头。

**N 皇后**是剪枝的集大成者。逐行放皇后，放之前检查该列与两条对角线是否已被占用——三组布尔数组把检查从 $O(n)$ 降到 $O(1)$：

```cpp
bool col_[20], d1[40], d2[40];  // 列、主对角线、副对角线
void dfs(int r) {
    if (r == n) { ans++; return; }
    for (int c = 0; c < n; c++) {
        int a = r + c, b = r - c + n;          // 两条对角线的编号
        if (col_[c] || d1[a] || d2[b]) continue;  // 剪枝
        col_[c] = d1[a] = d2[b] = true;
        dfs(r + 1);
        col_[c] = d1[a] = d2[b] = false;      // 恢复
    }
}
```

**重点：把「检查」变成「查表」。** 对角线的巧妙之处在于：同一条主对角线（右上到左下）满足 $r + c$ 为定值，同一条副对角线满足 $r - c$ 为定值。<span class="marginnote">`r - c` 可能是负数，加个偏移 `+ n` 变成非负，就能当下标用。这种「把几何条件编码成数组下标」的手法，在回溯、DP、单调栈里到处可见——它是空间换时间的又一种形态。</span>

## 4 回溯的三个经典变体

把「选—递归—撤销」套在不同问题里，会演化出三个常用变体：

**组合总和（可重复选）**：选元素时可以重复使用同一个元素，靠「只向后选」避免顺序不同的重复解——递归时传入起点下标 `start`，下一次从 `start` 开始而不是从头。

**子集生成（选或不选）**：每个元素只有「要」与「不要」两种选择，递归深度 $n$，叶子数 $2^n$。这也是状态压缩枚举的递归版。

**括号生成**：在递归中维护已用的左右括号数，右括号数超过左括号数就剪枝——可行性剪枝的又一例。

**核心概念：去重。** 当输入含重复元素（如 `[1,1,2]`），直接回溯会生成重复的排列/子集。去重套路是**先排序，再在同层跳过「与前一个相同且前一个没用过」的元素**——这是「层内去重」的标准写法，也是面试高频考点。

### 回溯的优化方向：排序与去重先行

回溯题在动手递归前，往往要先「预处理」降低分支数。最常见的两个预处理：**先排序**，让剪枝条件更早触发——组合总和这类题，排好序后一旦当前元素已使和超限，后面更大的元素也不用试了，直接剪掉整段分支；**先去重**，把重复元素压缩成「计数」，避免同值元素在不同位置生成重复解。

**核心概念：剪枝的「前置」与「后置」。** 前置剪枝在递归进入前用排序、预计算提前排除不可能；后置剪枝在递归体内用「当前状态合法性」及时止损。两者目的相同——让解空间树的「坏分支」尽早被砍掉。

**辨析｜易错点：** 排序会破坏「下标语义」的题不能乱排。如果题目要求「按原顺序选」或答案依赖下标，排序会直接改变问题——排序只应在「值的相对大小决定一切」的题里使用。

**回溯与动态规划怎么选？** 回溯穷举「所有解」，动态规划通常求「最优解/方案数」。当子问题重叠严重、只需一个数值答案时，DP 用记忆化把指数降到多项式；当题目明确要求「输出所有方案」时，方案数本身是指数级，只能回溯枚举。判断口诀：**求最优、计数用 DP，求全部方案用回溯**。

N 皇后之外，**数独求解**是回溯的又一经典：每个空格枚举 1-9，用「行、列、宫」三组布尔数组 O(1) 检查冲突，填满即得解。它的剪枝强度在于「先行处理只有一种可能的空格」——这是「最约束优先」的剪枝思想，把分支数压到最低。

**回溯与状态压缩的合体。** 当「已使用集合」需要快速查询与撤销时，可以用位掩码 `used` 代替布尔数组——`(used >> i) & 1` 查、`used ^ (1 << i)` 切换。配合记忆化，指数级的回溯就能升级成状态压缩 DP，见《位运算与状态压缩》的 TSP 一例。

## 5 公式解析：全排列的数量与回溯的复杂度

回溯穷举的解空间大小，决定了它的最坏复杂度。全排列的解空间树，第一层有 $n$ 个分支，第二层每个分支 $n-1$ 个……叶子总数：

$$
P(n) = n \times (n-1) \times \cdots \times 1 = n!
$$

- **第一步，数分支**：解空间树的第 $k$ 层有 $n \cdot (n-1) \cdots (n-k+1)$ 个节点。
- **第二步，数叶子**：叶子在第 $n$ 层，总数恰为 $n!$。
- **第三步，算代价**：回溯每个叶子都要构造一次路径，总时间 $O(n \cdot n!)$。

**重点：$n!$ 增长极快，剪枝是唯一出路。** $10! = 3.6\times10^6$ 尚可，$13! \approx 6.2\times10^9$ 就已超时。所以回溯题的输入几乎都限制在 $n \le 10$ 上下——数据范围一给大，题目要的往往就不是纯回溯，而是**剪枝够狠的回溯**或彻底换思路。

## 6 小结

- 回溯 = 解空间树上的 DFS = 「做选择 → 递归 → 撤销选择」三拍子。
- 状态恢复是回溯的生死线：做选择与撤销严格成对，全局状态返回前必须还原。
- 剪枝让回溯从「指数级硬跑」变成「大多数数据飞快」；N 皇后用三组布尔数组 $O(1)$ 查冲突。
- 变体套路：组合总和向后选、子集生成选或不选、括号生成可行性剪枝。
- 含重复元素先排序再做「层内去重」。
- 全排列状态数 $n!$ 增长极快，回溯题 $n \le 10$
