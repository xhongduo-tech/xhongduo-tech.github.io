## 为什么从二分搜索开始

搜索一个有序数组里的元素，最朴素的是从头扫到尾，$O(n)$。但数组既然有序，就可以**每次看中间**：中间值比目标大，就只搜左半；比目标小，就只搜右半。每比较一次，搜索范围砍半——**二分搜索（binary search）** 把查找从 $O(n)$ 降到 $O(\log n)$。更妙的是，二分不只是「查找」：只要一个问题满足**单调性**——「答案是 X 时可行，答案是更大（或更小）时必然也可行」——就能对**答案本身**做二分，这叫**二分答案**。它是竞赛里解决「最大值最小 / 最小值的最大值」类问题的万能钥匙。

## 1 二分搜索的基本框架

在有序数组 `a` 中找目标 `target`。框架的精髓在**区间不变量**：维护一个区间，保证 `target`（若存在）一定在区间内，每次把区间砍半。

```cpp
int binarySearch(vector<int>& a, int target) {
    int l = 0, r = a.size() - 1;
    while (l <= r) {
        int mid = l + (r - l) / 2;   // 防溢出的写法
        if (a[mid] == target) return mid;
        else if (a[mid] < target) l = mid + 1;
        else r = mid - 1;
    }
    return -1;
}
```

**核心概念：`[l, r]` 闭区间语义。** 这里 `l` 与 `r` 都指向「仍可能是答案」的位置，所以循环条件是 `l <= r`；比较后 `l = mid+1` 或 `r = mid-1`，保证区间逐步收缩且不漏元素。<span class="marginnote">另一种常用写法是半开区间 `[l, r)`，此时循环条件是 `l < r`，收缩时 `r = mid` 而不是 `mid-1`。两种写法都正确，但要<strong>始终只用一种语义</strong>——闭区间与半开区间混用，是二分写错的头号原因。</span>

**辨析｜易错点：`mid = (l + r) / 2` 会溢出。** 当 `l + r` 超过 `int` 上限时，中间值计算错误。安全写法是 `l + (r - l) / 2`——这是面试官最爱让你「找 bug」的地方之一。

## 2 二分的变体：找第一个 / 最后一个满足条件的位置

实际题目很少只问「在不在」，更多是问**边界**：第一个大于等于 `x` 的位置、最后一个小于等于 `x` 的位置。这需要二分的一个变体——**把相等条件并入收缩方向**。

找「第一个大于等于 `target` 的位置」（即 C++ `lower_bound`）：

```cpp
int lowerBound(vector<int>& a, int target) {
    int l = 0, r = a.size();        // 半开区间 [l, r)
    while (l < r) {
        int mid = l + (r - l) / 2;
        if (a[mid] >= target) r = mid;   // 符合条件，向左收缩
        else l = mid + 1;                // 不符合，向右收缩
    }
    return l;   // l 指向第一个 >= target 的位置
}
```

**重点：边界二分的不变量是「左右夹出一个分界」**——左侧永远不满足条件，右侧永远满足条件，循环结束时 `l` 就是那个分界。记住「满足就 `r = mid`，不满足就 `l = mid + 1`」，第一个/最后一个、大于/大于等于，四个变体都是这同一句话的四种组合。

## 3 二分答案：对解空间做二分

真正的威力来自**二分答案（binary search on answer）**。当题目的解是一个「数值」，且存在一个**单调的判断函数**——`check(x)` 回答「答案能否达到 x」，并且 `check` 随 `x` 单调变化——就可以对答案的取值范围做二分。

经典例题：**分割数组的最大值最小化**（给定数组和分段数，求「各段和的最大值」的最小可能值）。判断函数是：给定上界 `x`，能否用不超过 `x` 的每段和把数组分成不超过 `m` 段：

```cpp
bool check(vector<int>& a, int m, long long x) {
    long long sum = 0; int cnt = 1;
    for (int v : a) {
        if (sum + v > x) { sum = v; cnt++; }   // 新开一段
        else sum += v;
        if (cnt > m) return false;
    }
    return true;
}

int splitArray(vector<int>& a, int m) {
    long long lo = *max_element(a.begin(), a.end());  // 下界：最大的单个元素
    long long hi = accumulate(a.begin(), a.end(), 0LL); // 上界：全部合成一段
    while (lo < hi) {
        long long mid = (lo + hi) / 2;
        if (check(a, m, mid)) hi = mid;   // 可行，尝试更小
        else lo = mid + 1;                // 不可行，必须更大
    }
    return lo;
}
```

**核心概念：单调性是二分答案的前提。** `check(x)` 必须满足「若 x 可行，则任何大于 x 的值也可行」——在本例中，上界越大越容易分。满足这个单调性，就能安全二分。找不到单调性，二分答案就无从谈起。

## 4 公式解析：二分次数与复杂度

每次比较把区间砍半，问多少次后区间缩到空？设区间长 $n$：

$$
2^k \ge n \iff k \ge \log_2 n
$$

- **第一步，砍半**：第 1 次后剩 $n/2$，第 2 次后剩 $n/4$，第 $k$ 次后剩 $n / 2^k$。
- **第二步，终止条件**：区间变空，即 $n / 2^k \lt  1$，也就是 $2^k > n$。
- **第三步，解出 k**：$k = \lceil \log_2 n \rceil$。所以二分一次的复杂度是 $O(\log n)$；二分答案时每次都要跑 $O(n)$ 的 `check`，总代价 $O(n \log n)$。

**重点：$O(\log n)$ 是「砍半」的红利。** $\log_2 10^6 \approx 20$，$\log_2 10^9 \approx 30$——即使解空间大到十亿，二分的次数也只有 30 次上下。这就是「数值再大也不怕」的原因。<span class="marginnote">实际实现中，二分次数常常写死成「循环 60 次」或「`while (lo < hi)` 配合整数二分」。浮点二分则固定迭代 60~100 次或当区间宽度足够小时停——浮点不能靠 `lo < hi` 判终止，因为精度永远达不到，这是浮点二分与整数二分的关键差异。</span>

## 5 二分的三个常见陷阱

**辨析｜易错点：**

**死循环**：当 `l` 与 `r` 相邻（`r = l + 1`）且 `mid = l` 时，若收缩走 `l = mid`，`l` 永远不动，死循环。对策：明确用哪种区间语义，收缩方向与 `mid` 取整方式配套（向下取整配 `l = mid+1` 或 `r = mid`）。
**下界上界选错**：二分答案的 `lo` 与 `hi` 必须覆盖**所有合法解**。`lo` 太小会让 `check` 永远为假，`hi` 太大会浪费次数，选错边界直接答案错误。
**check 写错方向**：`check` 返回「可行」，二分时「可行往小走还是往大走」取决于题目要最大值还是最小值——最小值（如本例）可行就往小，最大值可行就往大，方向写反全盘皆错。

## 6 小结

- 二分搜索：有序数组内找元素，每次砍半，$O(\log n)$。
- 边界二分（`lower_bound`）：满足就 `r = mid`、不满足 `l = mid + 1`，四个变体一句话。
- 二分答案：`check(x)` 必须单调，对答案取值做二分，总代价「二分次数 × check 代价」。
- 防溢出写 `mid = l + (r-l)/2`；浮点二分靠固定迭代次数终止。

在下一节，我们将进入**分治算法**——二分是「每步排除一半」的特例，而分治把它推广成「拆开解决、合并答案」的通用三拍子。
