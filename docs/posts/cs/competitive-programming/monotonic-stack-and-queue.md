## 为什么从单调栈与单调队列开始

有些问题问得刁钻：「每个元素右边第一个比它大的元素是谁？」「滑动窗口里的最大值是多少？」暴力做法分别是 $O(n^2)$ 与 $O(nk)$，而它们都有一个优雅的 $O(n)$ 解法——**保持栈/队列里的元素单调**。**单调栈（monotonic stack）** 与**单调队列（monotonic queue）** 是「栈」「队列」的进阶形态：存进去的元素按值单调排列，靠的是一条铁律——**新元素进来时，把破坏单调性的旧元素全部弹出**。每个元素入栈/入队一次、出栈/出队一次，所以总复杂度是线性。这一章，我们把这两件「看名字吓人、看代码很短」的武器彻底拿下。

## 1 单调栈：下一个更大元素

先看单调栈的名片题：**每日温度 / 下一个更大元素**——给定数组，求每个元素右边第一个比它大的元素（或距离）。

朴素做法对每个元素向右扫描，$O(n^2)$。单调栈的思路是**维护一个从栈底到栈顶单调递减的栈**，栈里存「还没找到答案的下标」：

```cpp
vector<int> nextGreater(vector<int>& a) {
    int n = a.size();
    vector<int> ans(n, -1);
    stack<int> st;                       // 存下标，栈底大、栈顶小（单调递减）
    for (int i = 0; i < n; i++) {
        while (!st.empty() && a[st.top()] < a[i]) {
            ans[st.top()] = a[i];        // a[i] 就是栈顶元素的「下一个更大」
            st.pop();
        }
        st.push(i);
    }
    return ans;
}
```

**核心概念：弹栈的时机就是答案诞生的时机。** 从左到右扫描，遇到一个新元素 `a[i]`，把所有「比它小、还在等答案」的栈顶元素弹掉——它们的答案就是 `a[i]`。弹完入栈，栈保持单调递减。<span class="marginnote">栈里存<strong>下标</strong>而不是值——因为答案要下标（或距离）。`while` 里的比较用 `a[st.top()]` 取值。想求「下一个更大或相等」「下一个更小」，只需改比较符号与方向——单调栈的一个模板，覆盖四类变体。</span>

**辨析｜易错点：** 循环结束后栈里还剩的元素，说明右侧没有更大的，答案保持 `-1`（或 0）。若把 `ans` 初始化为 `-1` 就能自动处理，不需要额外收尾。另外比较方向（`<` 还是 `<=`）决定「严格更大」还是「更大或相等」，题目要求不同，写法不同。

## 2 单调队列：滑动窗口最大值

**单调队列** 解决「滑动窗口内求最大/最小值」：窗口右移一位，进来一个、出去一个，要求快速知道当前窗口最大值。`priority_queue` 能做到 $O(\log n)$ 每次，单调队列更进一步——$O(1)$ 均摊。

**核心思想：窗口里「又老又小」的元素永远不可能成为最大值**——因为新进来的元素更大且更晚离开窗口，老元素注定被它压制。于是维护一个**从队头到队尾单调递减**的队列，队头永远是当前窗口最大值：

```cpp
vector<int> maxSlidingWindow(vector<int>& a, int k) {
    deque<int> dq;              // 存下标，队头是窗口最大值的下标
    vector<int> ans;
    for (int i = 0; i < a.size(); i++) {
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();  // 新元素更大，尾部小元素失去价值
        dq.push_back(i);
        while (!dq.empty() && dq.front() <= i - k) dq.pop_front();  // 出窗口的过期元素
        if (i >= k - 1) ans.push_back(a[dq.front()]);
    }
    return ans;
}
```

**核心概念：双端队列 `deque`。** 尾部弹出「被压制」的元素、头部弹出「过期」的元素、头部读最大值——`deque` 两头都能操作，是单调队列的天然载体。<span class="marginnote">三条纪律：<strong>进</strong>（新元素从尾部进，先把尾部小的弹出）、<strong>出</strong>（队头超出窗口的下标弹出）、<strong>读</strong>（队头就是窗口最大值）。顺序固定为「先清理尾部，再入队，再清理头部，最后读答案」。背住这个顺序，单调队列就不会乱。</span>

**辨析｜易错点：** 队头过期的判断是 `dq.front() <= i - k`——下标 `i-k` 是窗口左边界外的第一个。别写成 `< i-k`，那会让刚好在左边界的元素被误删。

## 3 公式解析：为什么总复杂度是 O(n)

单调栈与单调队列看似内层有 `while`，总复杂度却是线性。数一笔「出入账」：

$$
\text{总操作数} = \underbrace{n}_{\text{每个元素入栈/入队一次}} + \underbrace{n}_{\text{每个元素至多出栈/出队一次}} = O(n)
$$

- **第一步，入**：每个元素在扫描中被 push 恰好一次，$n$ 次。
- **第二步，出**：每个元素至多被 pop 一次——因为它一旦被弹出，就再也不会回来。栈/队列里的总弹出次数 ≤ 总入栈次数 = $n$。
- **第三步，相加**：入 $n$ 次 + 出至多 $n$ 次，总计 $O(n)$。

**重点：这就是摊还分析的威力。** 虽然某一次 `while` 可能连弹好多个，但这些「弹」的总量被「每个元素至多出一次」限死了——和滑动窗口、并查集路径压缩的复杂度论证是同一套语言。<span class="marginnote">「每个元素进一次、出一次」是单调结构复杂度论证的标准句式。它比「每步都 O(1)」更准确——整体线性，个别步骤可能有波动，但摊到每个元素上仍是常数。这是把「看着像 $O(n^2)$ 的双层循环」认定为 $O(n)$ 的底气。</span>

## 4 单调栈的进阶应用

单调栈的威力远不止「下一个更大元素」。三个高频变体：

**柱状图中最大矩形（largest rectangle）**：对每个柱子，找「左边第一个比它矮的」与「右边第一个比它矮的」——两个边界之间就是它能撑起的最大宽度。恰好两次单调栈（左一遍、右一遍）或一次扫描配合技巧。

**接雨水（trapping rain water）**：每个位置能接的水 = 左右两侧最高柱子的较小者减去当前高度。单调栈解法在弹栈时累计「凹槽」的水量，一次扫描完成。<span class="marginnote">接雨水有「双指针」「前后缀最大值」「单调栈」三种解法，复杂度都是 $O(n)$——单调栈是其中代码最紧凑的一种。它把「怎么判断左右有没有更高的墙」编码成弹栈时的局部比较，是「把几何直觉翻译成栈操作」的典范。</span>

**去除重复字母 / 字典序最小**：贪心 + 单调栈——在栈里维护「尽量小」的序列，遇到更小的字符时，若栈顶在后面还会出现，就弹出栈顶（让位给更小的）。

**核心概念：单调栈的通用形态。** 三种应用背后的模式统一为——**用单调栈维护「当前候选集」，新元素到来时弹出「注定被淘汰」的旧元素**。识别「谁会注定被淘汰」，是单调栈题的破题点。

## 5 单调栈 vs 单调队列

| 维度 | 单调栈 | 单调队列 |
| --- | --- | --- |
| 数据结构 | 栈（单端） | 双端队列 `deque` |
| 核心操作 | 尾部弹、尾部入 | 尾部弹、尾部入、头部出 |
| 典型问题 | 下一个更大元素、最大矩形 | 滑动窗口最值 |
| 答案时机 | 弹出时确定（找「右边」） | 实时读队头（窗口在动） |
| 复杂度 | $O(n)$ 摊还 | $O(n)$ 摊还 |

**辨析｜易错点：单调栈与单调队列别混淆。** 单调栈处理「每个元素向一侧找」，弹出的瞬间给旧元素定性；单调队列处理「滑动的固定区间」，队头持续提供当前答案。判据一句话：**题里是「向一侧找关系」用栈，「一个窗口在动」用队列**。

**补充：单调结构与「离线处理」的组合。** 单调栈、单调队列常与「离线」思维配合：先把所有查询按某种顺序排好，再用一个单调结构一趟扫完。典型如「滑动窗口最值」本身就是离线预知窗口移动轨迹；而「区间内第一个大于 x 的元素」类问题，可以按 x 从大到小排序，用单调栈边插入边回答。识别「查询能排序、扫描能复用」，就是单调结构的用武之地。

## 6 小结

- 单调栈：存下标、保持单调递减，弹栈时给旧元素定「下一个更大」。
- 单调队列：`deque` 三纪律——尾部清小、尾部入、头部清过期、读队头。
- 复杂度 $O(n)$：每个元素入栈/入队一次、至多出一次，摊还线性。
- 进阶应用：最大矩形、接雨水、去除重复字母，统一为「弹出注定被淘汰的旧元素」。
- 选型判据：向一侧找关系用栈，窗口在动用队列。

**延伸：单调结构与离线思维的组合。** 把「区间内第一个大于 x」的查询按 x 从大到小排序，边插入边用单调栈回答——查询能排序、扫描能复用，单调结构就与离线处理配成了好搭档。这与《前缀和、差分与离散化》里「离线批量修改」的思路一脉相承。
