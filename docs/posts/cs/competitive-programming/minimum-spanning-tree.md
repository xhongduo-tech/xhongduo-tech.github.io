## 为什么从最小生成树开始

很多工程问题可以抽象成一句话：在 $n$ 个点之间修路，让所有点连通，且总造价最小。这就是**最小生成树（minimum spanning tree, MST）**——用 $n-1$ 条边把所有点连成一棵树，使边权总和最小。它是贪心思想在图上最漂亮的落地，也是并查集与优先队列两大工具协同作战的舞台：**Kruskal** 用并查集判环，**Prim** 用优先队列取最值。这一章我们学会两种算法、理解它们共同的「切割性质」，并掌握 MST 的常见变体。

## 1 生成树与切割性质

**生成树（spanning tree）**：包含全部 $n$ 个顶点、恰好 $n-1$ 条边、且连通的子图——它是「覆盖所有点的一棵树」。**最小生成树**是所有生成树里总边权最小的那棵。<span class="marginnote">树的性质在这时派上大用场：$n$ 个顶点连通的必要条件是有至少 $n-1$ 条边；恰好 $n-1$ 条边且无环就自动连通。所以「选 $n-1$ 条边且不成环」等价于「构成生成树」——这是 Kruskal 能只盯着边的原因。</span>

**核心概念：切割性质（cut property）。** 把顶点集任意切成两半（一个「切割」），在所有**跨越切割**的边里，权值最小的那条一定属于某棵最小生成树。这个性质是两种算法的共同理论依据——每一步都「贪心地选中跨切割的最小边」，全局必然最优。

## 2 Kruskal：从小到大加边 + 并查集判环

**Kruskal 算法** 的思路直白：把边按权值从小到大排序，逐条尝试；若这条边两端的点**尚未连通**，就加入它（否则成环）；直到选了 $n-1$ 条边。

```cpp
struct Edge { int u, v, w; };
sort(edges.begin(), edges.end(), [](auto &a, auto &b){ return a.w < b.w; });

long long ans = 0, cnt = 0;
for (auto &e : edges) {
    if (find(e.u) != find(e.v)) {     // 两端不连通，不会成环
        unite(e.u, e.v);
        ans += e.w;
        if (++cnt == n - 1) break;    // 已构成生成树
    }
}
// cnt < n-1 说明图不连通，无生成树
```

**重点：为什么贪心成立。** 每次取「当前最小且不成环」的边，正是切割性质的应用——这条边横跨某个切割且是跨切割最小的，属于某棵 MST。<span class="marginnote">复杂度：排序 $O(m\log m)$，每条边一次 `find`（近 $O(1)$），总计 $O(m\log m)$。Kruskal 对边排序，所以<strong>稀疏图</strong>（$m$ 小）尤其划算——$m$ 甚至可以是 $n^2$ 量级的稠密图也能跑，只是排序代价上升。</span>

**辨析｜易错点：** 判断「是否成环」必须用并查集判**两端连通性**，而不是「边数够了没」。乱加边会成环，成环就不是树。另外，最后若 `cnt < n - 1`，说明原图不连通，MST 不存在——别漏了这个分支。

## 3 Prim：从点出发 + 优先队列取最小边

**Prim 算法** 换一个视角：从一个点出发，维护「已选点集」，每次从「连接已选点集与未选点集」的边里取权值最小的一条，把新点拉进来，直到所有点都进集合。

```cpp
vector<vector<pair<int,int>>> g(n);
priority_queue<tuple<int,int,int>, vector<...>, greater<...>> pq;  // (边权, u, v)
vector<int> vis(n, 0);
long long ans = 0; int cnt = 0;
vis[0] = 1;
for (auto &[v, w] : g[0]) pq.push({w, 0, v});
while (!pq.empty() && cnt < n - 1) {
    auto [w, u, v] = pq.top(); pq.pop();
    if (vis[v]) continue;              // 已入集合，跳过（可能是旧边）
    vis[v] = 1; ans += w; cnt++;
    for (auto &[x, ww] : g[v])
        if (!vis[x]) pq.push({ww, v, x});
}
```

**核心概念：Prim = 在「切割」上贪心。** 已选点集与未选点集之间的边，就是跨越切割的边；优先队列每次弹出最小的那条，正是切割性质。两种算法都在选「跨切割最小边」，只是扫描的顺序不同。<span class="marginnote">Prim 的复杂度 $O(m\log n)$（优先队列每次操作 $O(\log m)$）。用 `vis` 标记已入集合，堆里可能残留旧边，弹出时判断 `vis[v]` 跳过即可——这是 Dijkstra 与 Prim 共用的「惰性删除」惯用法。</span>

## 4 两种算法的对比

| 维度 | Kruskal | Prim |
| --- | --- | --- |
| 思路 | 对边贪心，从小到大加 | 对点扩展，每次拉最近点 |
| 工具 | 并查集（判环） | 优先队列（取最小边） |
| 复杂度 | $O(m\log m)$ | $O(m\log n)$ |
| 优势 | 稀疏图，实现直观 | 稠密图；与 Dijkstra 代码同构 |
| 边权为负 | 可以 | 可以（MST 与最短路不同） |

**重点：选哪套看图。** $m \approx n$（稀疏）用 Kruskal，$m \approx n^2$（稠密）用 Prim（朴素 $O(n^2)$ 实现甚至更好）。但实现难度上 Kruskal 更低，所以竞赛里很多选手默认 Kruskal。<span class="marginnote">注意 MST 允许负权边——负权不会破坏「切割性质」，算法照样正确。这与最短路（Dijkstra 怕负权）有本质区别，别把两个问题的直觉混在一起。</span>

## 5 公式解析：为什么生成树恰好 n-1 条边

树的一个重要性质是**边数 = 顶点数 - 1**。这个数字从哪来？对一棵树任取一个根，从根出发做一次 DFS：

$$
\text{边数} = \text{顶点数} - 1 \quad \Longleftrightarrow \quad m = n - 1
$$

- **第一步，观察结构**：树里每个非根顶点恰有一条「父边」（它在 DFS 树里被发现的边）。
- **第二步，数边**：$n$ 个顶点里 $n-1$ 个非根顶点，各对应一条父边，共 $n-1$ 条边。
- **第三步，验证**：根没有父边，所以总边数恰好是 $n-1$；多一条边必有环，少一条边必不连通。

**重点：$n-1$ 是 MST 的「停止条件」。** Kruskal 与 Prim 都靠「选了 $n-1$ 条边就停」来判断完成——这是树性质在算法里的直接体现。也解释了为什么「加边成环则跳过」：再加任何一条边都会破坏树结构。

## 6 最小生成树的应用与变体

**次小生成树**：删掉 MST 中的一条边、加入一条非树边，枚举「替换」找权值第二小——经典做法是预处理树上任意两点间路径的最大边权。

**最小瓶颈生成树**：让生成树里的最大边尽量小。结论很漂亮——**MST 就是一棵最小瓶颈生成树**，因为 Kruskal 的加边顺序天然保证最大边最小。

**多棵 MST / 计数**：边权相等时可能有多棵 MST。Kruskal 的「同权边」处理（按权分组、分别考虑）能用来计数。

**辨析｜易错点：** MST 是树，不是「最短路」。最短路让**两点间**距离最小，MST 让**全局连通**总代价最小——Dijkstra 求出的边集不一定构成 MST，两者目标不同，别混用。<span class="marginnote">「最大生成树」只需把边按权值降序排序，Kruskal 原样跑——同样靠切割性质的镜像版本。「最小生成树」的精神还能推广到拟阵理论（matroid），那是更深的数学背景，竞赛里先掌握两种算法即可。</span>

**补充：MST 与并查集、优先队列的关系复盘。** Kruskal 用并查集判环、Prim 用优先队列取最值——两大工具在 MST 里各司其职。理解「工具选型」的规律：凡是「不断取当前最小」的，优先队列；凡是「动态维护连通性、判环」的，并查集。这个「按需取工具」的直觉，会贯穿图论剩余的所有章节。

## 7 小结

- 生成树 = 连通 + $n-1$ 条边 + 无环；MST 是总权最小的生成树。
- 切割性质：跨切割最小边必属于某棵 MST——两种算法的共同依据。
- Kruskal：边排序 + 并查集判环，$O(m\log m)$，稀疏图友好。
- Prim：优先队列取跨切割最小边，$O(m\log n)$，稠密图友好。
- 树性质 $m = n-1$
