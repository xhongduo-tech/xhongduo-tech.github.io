## 为什么从函数与递归开始

前面几章，程序从头写到尾，是一大块平铺的代码。当问题变复杂，这种写法会迅速失控——一万行的 `main` 函数没人读得懂。**函数（function）** 把一段逻辑打包成可复用的单元，像搭积木一样组装程序；而**递归（recursion）** 更进一步，让函数调用它自己，用一种近乎数学归纳法的语言描述问题。这两者不仅是编程范式，更是算法思维的核心：分治、搜索、动态规划，全部建立在「把大问题拆成小问题」之上。

## 1 函数：定义、参数与返回值

函数有四个部分：**返回类型、函数名、参数列表、函数体**。

```c
// 返回两个整数的较大者
int max(int a, int b) {
    return a > b ? a : b;
}
```

调用函数时，实参的值被**拷贝**给形参——这是「**按值传递（pass by value）**」。函数内部对形参的修改不会影响调用者的变量：

```c
void swap_bad(int a, int b) {   // 没用！改的是拷贝
    int t = a; a = b; b = t;
}
```

要真正交换两个变量，得传**地址**（用指针）或之后学 C++ 的引用。<span class="marginnote">按值传递是 C 的默认行为，也是新手常踩的「为什么函数里改不动外面的变量」。想改外面，就要把「外面的变量的地址」传进去——指针第一课，也是 C++ 引用的由来。</span>

**辨析｜易错点：** 函数要先声明（或先定义）再使用。C 语言里把调用写在定义之前，需要前置声明；`void` 表示「不返回值」。`return` 一旦执行，函数立即结束，其后的代码不会运行。

## 2 作用域与变量的生命周期

每个变量都有它的**作用域（scope）**——「在哪些地方可见」。函数内的局部变量只在本函数内可见，参数也是局部变量；在函数外、所有函数之上声明的叫**全局变量**，处处可见。

**重点：全局变量默认初始化为 0**，而局部变量不初始化就是「上次那块内存留下的垃圾值」。竞赛里常见的习惯是：数组这类大存储开成全局，既免去 `memset` 的繁琐，又避开了「栈上分配大数组导致栈溢出」的隐患。

```c
int cnt[1000005];   // 全局，自动清零
int main() {
    cnt[100]++;      // 直接可用
    return 0;
}
```

<span class="marginnote">局部数组开在「调用栈」上，栈的空间一般只有几 MB；而全局数组放在静态区，容量可达几百 MB。竞赛里 `int a[1000000]` 这种规模开在局部可能直接爆栈，开全局则安全。</span>

## 3 递归：函数调用自己

**递归（recursion）** 是指函数直接或间接地调用自身。递归能成立，靠的是**把规模变小**：每次调用处理一个「更小但同构」的子问题，直到小到可以直接给出答案。

以阶乘 $n!$ 为例：

```c
long long fact(int n) {
    if (n <= 1) return 1;      // 基线条件
    return n * fact(n - 1);    // 递归步骤
}
```

**核心概念：递归两要素**——**基线条件（base case）**：规模最小时直接返回，不再调用自己；**递归步骤（recursive step）**：把当前问题拆成更小的同构问题。缺了基线，递归永远停不下来，最终栈溢出（stack overflow）崩溃。

**重点：每一次调用都是一份独立的拷贝**。`fact(3)` 会调用 `fact(2)`，后者再调用 `fact(1)`——每一层都有自己独立的参数和局部变量，逐层压入调用栈，返回时再逐层弹出。这个「栈」的直觉，是理解后续一切递归算法（DFS、分治）的基础。

## 4 递归实例：汉诺塔与 GCD

**汉诺塔（Tower of Hanoi）** 是递归的教科书例题：把 $n$ 个盘子从 A 柱移到 C 柱，每次只能移一个，大盘不能压小盘。递归拆法极其优雅——把上面 $n-1$ 个盘子看成一个整体：

```c
void hanoi(int n, char a, char b, char c) {
    if (n == 1) { printf("%c -> %c\n", a, c); return; }
    hanoi(n - 1, a, c, b);  // 把 n-1 个移到过渡柱 b
    printf("%c -> %c\n", a, c);  // 最底下一个直接到位
    hanoi(n - 1, b, a, c);  // 把 n-1 个从 b 移到 c
}
```

汉诺塔的移动次数满足 $T(n) = 2T(n-1) + 1$，解为 $T(n) = 2^n - 1$。<span class="marginnote">$n = 64$ 时移动次数约 $1.8\times10^{19}$，按每秒一次要 5800 亿年——传说里「世界毁灭时梵天完成 64 盘汉诺塔」的结局，从复杂度上看相当合理。</span>

**最大公约数（GCD）** 用**辗转相除法（欧几里得算法）** 递归实现，是数论与竞赛里最高频的小函数：

```c
int gcd(int a, int b) {
    return b == 0 ? a : gcd(b, a % b);
}
```

它的正确性依赖一个关键性质：$\gcd(a, b) = \gcd(b, a \bmod b)$——两个数辗转相除，余数会严格变小，所以递归必然终止。

## 5 公式解析：斐波那契的递归与灾难

斐波那契数列 $F(n) = F(n-1) + F(n-2)$ 是递归的招牌例子，也是「朴素递归会爆炸」的绝佳反面教材。

$$
F(n) = \begin{cases} 0 & n = 0 \\ 1 & n = 1 \\ F(n-1) + F(n-2) & n \ge 2 \end{cases}
$$

- **第一步，直接翻译**：把数学定义逐字写成递归函数，`return fib(n-1) + fib(n-2);`。
- **第二步，数调用次数**：设 $C(n)$ 为计算 $F(n)$ 需要的调用次数，$C(n) = C(n-1) + C(n-2) + 1$，解得 $C(n)$ 也是指数级，约 $\Theta(\phi^n)$（$\phi \approx 1.618$）。
- **第三步，发现灾难**：`fib(45)` 在普通机器上就要跑几十秒，因为 `fib(40)` 被重复计算了上千次。指数级的重复计算，正是朴素递归的最大陷阱。

**重点：重复子问题是递归的天敌**。解决办法是把算过的结果**存起来**——这就是《动态规划初步》里的**记忆化（memoization）**，空间换时间，把指数级降到 $O(n)$。递归思想的正确姿势是「用递归想清楚，用记忆化或 DP 去实现」。

## 6 小结

- 函数 = 返回类型 + 名字 + 参数 + 函数体；C 默认按值传递。
- 全局变量自动清零且容量大，大数组开全局；局部变量不初始化是垃圾值。
- 递归两要素：基线条件 + 递归步骤；缺基线会栈溢出。
- 汉诺塔、GCD 是递归的经典实例；$T(n) = 2^n - 1$
