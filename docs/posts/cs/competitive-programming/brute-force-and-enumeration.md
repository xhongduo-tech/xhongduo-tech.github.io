## 为什么从暴力求解法开始

很多初学者不屑于写暴力解，觉得「不够优雅」。恰恰相反——**暴力求解法是算法的及格线**：数据范围小的时候，暴力就是正解；数据范围大的时候，暴力是验证算法正确性的基准，也是「先跑通再优化」的开发策略。更重要的是，枚举是「搜索一切可能」的系统化训练：**枚举子集、枚举排列、枚举组合**是三类最基本的穷举结构，回溯法、状态压缩、剪枝都以它们为起点。这一章，我们先把「怎么把一切可能试一遍」练到条件反射，再学会「怎么聪明地少试」。

## 1 枚举的三个基本对象

暴力求解的核心是**穷举**。而「一切可能」不外乎三种结构：

**枚举子集（subset）**：$n$ 个元素的所有子集共 $2^n$ 个。每个元素「选或不选」，正好对应二进制的一位。

```cpp
for (int mask = 0; mask < (1 << n); mask++) {
    // mask 的第 i 位是 1 表示第 i 个元素入选
    for (int i = 0; i < n; i++)
        if (mask >> i & 1) // 处理元素 i
}
```

**枚举排列（permutation）**：$n$ 个元素的全排列共 $n!$ 个。C++ 里有现成的 `next_permutation`：

```cpp
vector<int> a = {1, 2, 3};
do {
    // 处理当前排列
} while (next_permutation(a.begin(), a.end()));
```

**枚举组合（combination）**：从 $n$ 个里选 $k$ 个，共 $\binom{n}{k}$ 个。可以用 DFS 按顺序选，避免重复。<span class="marginnote">`next_permutation` 默认按字典序生成下一个排列，而且它会<strong>原地修改</strong>数组；用之前最好先 `sort`，否则只会从当前排列开始往后走，漏掉前面的。这个函数每次调用 $O(n)$，枚举全部排列总代价 $O(n \cdot n!)$。</span>

## 2 枚举的复杂度预算：先算再写

写暴力前，第一件事是**算清状态数**。$n$ 决定了一切：

$$
\text{子集数} = 2^n, \qquad \text{排列数} = n!, \qquad \text{组合数} = \binom{n}{k}
$$

- **$n \le 20$**：$2^n$ 至多约 $10^6$，枚举子集稳稳可行——状态压缩 DP 的地盘。
- **$n \le 10$**：$10! = 3.6\times10^6$，枚举排列可行。
- **$n \le 10^5$**：任何指数级枚举都超时，必须上多项式算法。

**重点：状态数决定算法的天花板。** 看到数据范围，先在心里过一遍「穷举所有可能是 $2^n$ 还是 $n!$，是否在 $10^7$ 以内」。超了就改搜索剪枝或动态规划——复杂度预算是暴力与高效算法之间的切换开关。

## 3 剪枝：暴力到高效的过渡

**剪枝（pruning）** 是在搜索过程中提前排除不可能产生答案的分支。它不改变最坏复杂度，但在多数数据上能把运行时间砍掉几个数量级。

经典案例：**DFS 解 N 皇后**。逐行放皇后，每放一个就检查是否与已放的行、斜线冲突，冲突立即停止深入这条分支——这正是「排除不可能」的剪枝：

```cpp
int n, ans = 0;
int col[20];
void dfs(int r) {
    if (r == n) { ans++; return; }
    for (int c = 0; c < n; c++) {
        bool ok = true;
        for (int i = 0; i < r; i++)
            if (col[i] == c || abs(col[i] - c) == r - i) ok = false;
        if (!ok) continue;      // 剪枝：此列不可放
        col[r] = c;
        dfs(r + 1);
    }
}
```

**核心概念：可行性剪枝与最优性剪枝。** 可行性剪枝提前终止「不可能合法」的分支；最优性剪枝（常在贪心/搜索优化里）用「当前已得最优」截止「不可能更优」的分支。<span class="marginnote">N 皇后的检查里 `abs(col[i] - c) == r - i` 是「同对角线」的判定：行差等于列差，两点就在同一条斜线上。几何直觉在这里直接转化成了剪枝条件。</span>

## 4 枚举优化：换个视角，少试一半

很多时候「暴力」超时，不是因为要枚举的对象本身太多，而是枚举的**视角**错了。三个经典的优化套路：

**减少维度**：本来要枚举 $i$ 和 $j$（$O(n^2)$），如果把 `a[j]` 的某种信息预处理成数组，内层循环就变成 $O(1)$ 查表。比如「求每个位置左边最大元素」——前缀扫一遍记录即可，不必每对都重算。

**Meet in the Middle（折半搜索）**：当枚举子集 $2^n$ 超时但 $n$ 又不小（如 $n = 40$）时，把数组分成两半，各自枚举 $2^{20}$ 个状态，再合并。<span class="marginnote">折半搜索是「把指数劈成两半」的经典思想：$2^{40}$ 太大，但 $2^{20} \approx 10^6$ 可行。两半各自枚举后，用排序 + 双指针（或哈希）在合并时计数。它把 $2^n$ 的指数从 $n$ 降到 $n/2$，能救回很多「差一点就过」的题。</span>

**预处理 / 后缀信息**：把重复计算的结果先算好存起来。这类「空间换时间」的预处理，正是后续前缀和、差分、动态规划的共同思想。

### 枚举的对拍验证

暴力枚举还有一个关键用途——**当答案的「验证器」**。设计出高效算法后，写一个正确的暴力解，在小数据上随机生成输入，把暴力结果与高效算法结果逐一对拍，不一致就说明高效算法有 bug。这个「暴力对拍」的工程习惯贯穿整个竞赛生涯：贪心对不对、DP 转移有没有漏、新数据结构是否可靠，都靠对拍说话。它能把你「我觉得没错」的代码，变成「我验证过没错」的代码。

**核心概念：暴力是正确性的锚点。** 暴力慢，但它「错的可能性」远低于花哨算法——因为逻辑直白、贴近定义。留一个暴力解当锚，是竞赛选手效率最高的 debug 方式。

## 5 公式解析：二项式系数与枚举状态数

组合数 $\binom{n}{k}$ 是枚举组合的计数工具，也是最常用的公式之一：

$$
\binom{n}{k} = \frac{n!}{k!\,(n-k)!} = \binom{n}{n-k}
$$

- **第一步，计数原理**：从 $n$ 个里选 $k$ 个，选法数记为 $\binom{n}{k}$。
- **第二步，递推**：$\binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k}$（选或不选第 $n$ 个）——这正是「杨辉三角」的生成方式。
- **第三步，用途**：竞赛里用它算枚举状态数、概率期望的分布、以及后续组合数学专题的基础。

**重点：二项式系数在竞赛里既是「数数工具」也是「算法工具」。** 枚举题用它估算复杂度，概率题用它数「有多少种等可能结果」，DP 题里它的递推结构常被借来设计状态转移。

## 6 小结

- 暴力枚举三件套：枚举子集（$2^n$）、枚举排列（$n!$）、枚举组合（$\binom{n}{k}$）。
- 写暴力前先算状态数：$n \le 20$ 枚举子集，$n \le 10$ 枚举排列，超了改算法。
- 剪枝提前排除不可能分支：N 皇后是可行性剪枝的经典教材。
- 枚举优化三套路：减少维度、Meet in the Middle、预处理换空间。
- 折半搜索把 $2^n$ 的指数劈成 $n/2$，专治「差一点就过」的枚举题。
- 二项式系数 $\binom{n}{k}$
