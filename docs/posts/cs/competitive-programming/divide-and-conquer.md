## 为什么从分治算法开始

很多高效算法的骨架是同一个三拍子：**分解（divide）** 把大问题切成小问题，**递归（conquer）** 解决每个小问题，**合并（combine）** 把小问题的答案组装成大问题的答案。归并排序、快速排序、逆序对计数、最近点对……全是这个套路。**分治（divide and conquer）** 的魅力在于：它把「我不会做 $n$ 的问题」变成「我会做 $n/2$ 的问题」，而后者又变回前者——最终落在一个「小到直接能做」的基线上。这一章，我们用几个经典案例，把分治的「切、解、合」练成本能，并学会用主定理估复杂度。

## 1 分治的三拍子：切、解、合

分治算法的统一结构极其简单：

```cpp
solve(问题 P) {
    if (P 小到可以直接解) return 直接解;   // 基线
    把 P 切成几个更小的子问题;              // 分解
    递归解决每个子问题;                     // 递归
    把子问题的解合并成 P 的解;              // 合并
}
```

**核心概念：三种必须分清的「工作」**。基线条件保证递归终止；分解决定子问题的结构；合并是最容易出错的一步——很多分治题的难点不在「怎么切」，而在「两个子问题的答案如何跨越中线被组合进来」。<span class="marginnote">归并排序里我们已经见过这套结构：切到单元素就是基线，合并时用双指针把两个有序段合成一个。注意「切」几乎不花时间，「合」才是 $O(n)$ 的重头戏——分治的复杂度通常由合并步骤主导。</span>

**辨析｜易错点：** 递归子问题时，边界切错是分治的第一大坑。归并的 `[l, mid]` 与 `[mid+1, r]` 必须不相交且完整覆盖 `[l, r]`——多一个、少一个、重叠一个，都会导致元素丢失或重复。写分治前先在纸上划出区间，确认「并起来等于原区间」。

## 2 案例一：归并排序求逆序对

归并排序在合并时，顺带就能数出**逆序对（inversion）**——$i \lt  j$ 但 $a[i] > a[j]$ 的数对。合并两个有序段时，每当从左段取走一个元素，右段中「尚未取走的元素」都大于它，这些正好构成逆序对：

```cpp
long long cnt = 0;
void merge(int a[], int l, int m, int r) {
    vector<int> t;
    int i = l, j = m + 1;
    while (i <= m && j <= r) {
        if (a[i] <= a[j]) t.push_back(a[i++]);
        else { cnt += (m - i + 1); t.push_back(a[j++]); }  // 右段元素胜出，跨过 m-i+1 个左段元素
    }
    while (i <= m) t.push_back(a[i++]);
    while (j <= r)  t.push_back(a[j++]);
    for (int k = l; k <= r; k++) a[k] = t[k - l];
}
```

**重点：一次合并数清「跨中线的逆序对」。** 逆序对分三种：完全在左段、完全在右段、跨越中线。前两种由递归解决；合并时「右段元素提前出来」的次数，恰好等于跨越中线的逆序对数。<span class="marginnote">求逆序对是分治的经典应用，也是「分治能解决朴素做不了的事」的证明——暴力 $O(n^2)$，归并分治 $O(n\log n)$。同样的「跨中线计数」技巧还能推广到统计「满足某种偏序的数对」一类问题。</span>

## 3 案例二：最大子数组和（跨中线的最大值）

「求数组的最大连续子数组和」是分治的另一个经典——虽然它有个更简单的线性解法，但分治视角价值在于理解「跨中线」：

- **分解**：把数组从中间切开。
- **递归**：左右两半各自的最大子数组和。
- **合并**：答案 = max(左半答案, 右半答案, **跨越中线的最大子数组和**)。跨越中线的和 = 从中线向左延伸的最大后缀和 + 从中线向右延伸的最大前缀和，各用一次线性扫描求出。

**核心概念：答案的三个可能位置。** 分治题的合并步骤常常就是「枚举答案可能存在的区域」——全在左、全在右、跨中线。把三个候选都算出来取最优，合并就完成了。这个「三分候选」的框架，在最近点对等几何分治里还会再次出现。

## 4 主定理：分治复杂度的通用公式

分治的复杂度通常可以统一成一个递推式。若规模 $n$ 的问题被切成 $a$ 个规模 $n/b$ 的子问题，合并代价为 $O(n^d)$：

$$
T(n) = a\,T\left(\frac{n}{b}\right) + O(n^d)
$$

**主定理（master theorem）** 给出三情形解：

- **$a = b^d$**：$T(n) = O(n^d \log n)$——合并主导，每层同价，共 $\log n$ 层。归并排序 $a=2, b=2, d=1$，$2 = 2^1$，得 $O(n\log n)$。
- **$a \lt  b^d$**：$T(n) = O(n^d)$——合并代价主导。
- **$a > b^d$**：$T(n) = O(n^{\log_b a})$——子问题数量主导。

- **第一步，识参数**：数清一个分治切几个子问题（$a$）、每个多小（$n/b$）、合并多贵（$n^d$）。
- **第二步，比大小**：比较 $a$ 与 $b^d$，落进三情形之一。
- **第三步，套公式**：直接读出复杂度。

**重点：主定理是「递归树」的封装。** 它把《排序基础》里那棵递归树的层数 × 每层代价总结成三句话。<span class="marginnote">二分搜索是 $a=1, b=2, d=0$，$1 = 2^0$，得 $O(\log n)$；快排平均 $a=2,b=2,d=1$ 得 $O(n\log n)$。会认 $a,b,d$，绝大多数分治题一眼就能估出复杂度。</span>

## 5 公式解析：最大子数组的分治递推

把「最大子数组和」的分治复杂度写出来，是主定理的标准练习题。设 $T(n)$ 是规模 $n$ 的成本：

$$
T(n) = 2T\left(\frac{n}{2}\right) + O(n)
$$

- **第一步，分解**：切成两个 $n/2$ 的子问题，递归各花 $T(n/2)$。
- **第二步，合并**：计算跨中线的最大和，从中线向左一次扫描、向右一次扫描，$O(n)$。
- **第三步，套主定理**：$a=2, b=2, d=1$，$a = b^d$，落在第一情形，$T(n) = O(n\log n)$。

**重点：分治的答案不止一种正确。** 最大子数组和的线性解法（Kadane 算法）比 $O(n\log n)$ 的分治更好——但这不影响分治作为「通用思维训练」的价值：当问题没有线性解、只能靠分治时，这一套「切、解、合」就是你最后的手段。多掌握一种视角，多一条解题的路。

### 案例三：最近点对——分治的几何应用

**最近点对（closest pair of points）** 是分治在计算几何里的成名作：给平面上 $n$ 个点，求距离最近的两点。朴素两两枚举是 $O(n^2)$，分治把它压到 $O(n\log n)$：

- **分解**：按 x 坐标排序，从中间竖线切成左右两半。
- **递归**：分别求左半、右半内部的最短距离，取较小者记为 $\delta$。
- **合并**：最近对若跨过中线，两点必落在「中线左右各 $\delta$」的窄带里。把带内点按 y 排序，每个点只需与后面最多 6 个点比较——因为带内能放进边长为 $\delta$ 正方形的点有常数上界。

**核心概念：合并步的「常数上界」是效率关键。** 合并阶段如果对每个点都和带内全部点比较，仍是 $O(n^2)$；而「每个点只需比常数个」这个几何事实，把合并压回 $O(n)$。分治的复杂度，常常由「合并步能不能做到线性」决定——这正是主定理里 `d = 1` 的意义所在。最近点对是「跨中线」思想（与最大子数组、逆序对同源）在几何上的体现，值得反复咀嚼。

## 6 小结

- 分治三拍子：分解 → 递归 → 合并；基线条件保证终止，合并步骤最易出错。
- 递归子问题的边界必须「不相交且完整覆盖」原区间。
- 归并排序求逆序对：合并时「右段元素提前出来」的次数就是跨中线逆序对数。
- 最大子数组和的合并 = 左答案、右答案、跨中线答案三者取最大。
- 主定理 $T(n) = aT(n/b) + O(n^d)$：比 $a$ 与 $b^d$，三情形对应三种复杂度。
- 归并 $O(n\log n)$、二分 $O(\log n)$；最近点对靠「带内常数上界」把合并压回 $O(n)$。

在下一节，我们将进入**贪心算法**——分治用「合并答案」求最优，贪心用「局部选择」求最优，两种来源不同的最优策略，将在《高效排序》里再次以不同姿态登场。
