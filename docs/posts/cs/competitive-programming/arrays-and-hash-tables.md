## 为什么从数组与哈希表开始

从这一篇起，我们开始直面 LeetCode。前面的 C 与 C++ 给了你「会写程序」的能力，而 LeetCode 的数组与哈希表专题，是**从语法走向算法**的第一座桥：题目不难，但已经逼着你思考「如何用合适的数据结构把暴力优化掉」。数组是最简单的结构，哈希表则第一次展示了「用空间换时间」的威力——把查找从 $O(n)$ 降到均摊 $O(1)$。这一篇刷完，你会彻底明白为什么哈希表是算法世界的「瑞士军刀」。

## 1 数组的经典操作模式

LeetCode 的数组题，多数跑不出几个操作套路。先把它们练熟，遇到新题就知道该从哪里下手。

**双下标遍历**：用一个下标访问，处理「前缀」「相邻」类问题。比如「原地删除重复元素」，用两个指针一个读一个写，一次遍历完成：

```cpp
int removeDuplicates(vector<int>& nums) {
    int k = 0;  // 慢指针：已去重的数组长度
    for (int x : nums)
        if (k == 0 || x != nums[k-1])
            nums[k++] = x;  // 快指针读到新值就写入
    return k;
}
```

**就地修改（in-place）**：题目常要求「$O(1)$ 额外空间」，意思是只能动原数组，不能开副本。核心技巧是**覆盖**：把不想要的值用后面的值盖掉。

**辨析｜易错点：** 数组题最容易错的是**边界**。`nums[nums.size()-1]` 在数组为空时越界；`for (int i = 0; i + 1 < n; i++)` 和 `i < n` 差一位，就可能访问到 `nums[n]`。写循环前先问：这个下标最大会是多少？空数组能不能走这条路？

## 2 哈希表：空间换时间的第一课

**哈希表（hash table）** 又叫散列表，它维护「键到值」的映射，用一个**哈希函数**把键映射到数组下标，从而实现均摊 $O(1)$ 的插入与查找。C++ 里用 `unordered_map` / `unordered_set`。

<span class="marginnote">`unordered_map` 底层是<strong>哈希表</strong>，`map` 底层是<strong>红黑树</strong>。名字里带 `unordered` 的才是哈希表，均摊 $O(1)$；不带的是有序树，$O(\log n)$。竞赛与面试中，「只需要查找不关心顺序」就用 `unordered_*`。</span>

哈希表的威力在「**这个元素之前出现过吗**」这类查询。暴力做法对每个元素都回头扫描一遍，$O(n^2)$；哈希表把「查重」变成 $O(1)$，总代价直接降到 $O(n)$。

## 3 公式解析：两数之和

LeetCode 第 1 题「两数之和」是哈希表的名片：给定数组 `nums` 和目标 `target`，找两个下标使两数之和等于 `target`。

$$
\text{find } i, j \quad \text{s.t.} \quad nums[i] + nums[j] = target
$$

- **第一步，变形**：对当前元素 $x = nums[i]$，问题变成「在之前的元素里找 $target - x$ 是否出现过」。
- **第二步，边扫边存**：遍历数组，每看到一个 $x$，先在哈希表里查 $target - x$；查到了直接返回答案，查不到就把 $x$ 连同下标存进表里。
- **第三步，复杂度**：每个元素只查一次、存一次，哈希表操作均摊 $O(1)$，总时间 $O(n)$，额外空间 $O(n)$。

```cpp
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> pos;
    for (int i = 0; i < nums.size(); i++) {
        int need = target - nums[i];
        if (pos.count(need)) return {pos[need], i};
        pos[nums[i]] = i;
    }
    return {};
}
```

**重点：为什么是「边扫边存」而不是先全部存好？** 因为答案要求两个不同的下标，边扫边存天然保证「后面的下标不会匹配到自己」——这是两数之和最精妙的一笔。

## 4 哈希表的三大应用模式

刷完数组与哈希表专题，你会发现哈希表的用法高度可归纳：

**查重（去重）**：`unordered_set` 判断元素是否出现过。经典的「最长连续序列」就是用 set 建索引，再从每个连续段的起点开始数。

**计数（频率统计）**：`unordered_map<Key, int>` 统计出现次数。字母异位词分组的核心就是「排序后的字符串 → 原串列表」的映射：

```cpp
vector<vector<string>> groupAnagrams(vector<string>& strs) {
    unordered_map<string, vector<string>> mp;
    for (auto &s : strs) {
        string key = s;
        sort(key.begin(), key.end());  // 异位词排序后相同
        mp[key].push_back(s);
    }
    vector<vector<string>> res;
    for (auto &p : mp) res.push_back(p.second);
    return res;
}
```

**索引（记录位置）**：把「值 → 下标」存起来，两数之和就是这种模式。凡是需要「记住见过的值在哪」，就想到哈希表。

## 5 哈希表的代价：冲突与扩容

哈希表并非银弹，它有两个隐藏代价。**冲突（collision）** 是不同键映射到同一个桶，`unordered_map` 用链地址法处理，冲突多时单桶退化成链表，最坏 $O(n)$。**扩容（rehash）** 是负载因子过高时整体重建，偶尔一次 $O(n)$。<span class="marginnote">哈希表摊还 $O(1)$ 建立在「负载因子保持低」之上。竞赛里若遭遇精心构造的哈希碰撞攻击（卡 `unordered_map`），可以改用 `map` 或自定义哈希——这是高端选手的防御技能。</span>

**核心概念对比——数组与哈希表怎么选**：

| 维度 | 数组 | 哈希表 |
| --- | --- | --- |
| 下标含义 | 天然连续，语义固定 | 键可以是任意类型 |
| 查找 | $O(1)$，但必须知道下标 | 均摊 $O(1)$，按值查 |
| 顺序 | 保序 | 无序 |
| 空间 | 紧凑 | 有额外桶开销 |
| 适用 | 下标即语义（桶计数） | 任意键的映射/查重/计数 |

**重点：能用数组就用数组**。如果键恰好是「连续的小范围整数」（如 26 个字母、$n$ 以内的编号），数组的桶计数比哈希表更快、更省内存——这正是我们在《数组、字符串与字符处理》里用 `cnt[26]` 做的事。

## 6 小结

- 数组题三件套：双指针、就地修改、边界检查。
- 哈希表把「查重/计数/索引」从 $O(n)$ 降到均摊 $O(1)$
