## 为什么从区间 DP 与记忆化搜索开始

上一章的 LIS、背包都是「线性 DP」——状态沿数组下标单向推进。但有一类问题，子问题是**一段连续区间**，合并两段区间才能组成更大的区间：合并石子、矩阵连乘、回文串切割、戳气球……它们的共同结构是**在区间中间选一个分割点**。这类**区间 DP（interval DP）** 的状态是 `dp[l][r]`，转移靠枚举分割点 `k`。而**记忆化搜索**是写区间 DP 的另一种姿势——用递归 + 查表，让「分割点枚举」顺着直觉自然流淌。这一章，我们把区间 DP 的「长度从小到大」填表顺序和记忆化写法一次讲透。

## 1 区间 DP 的结构：分割点枚举

先看经典题：**合并石子**——一排石子，相邻的可以合并，合并代价是两堆重量之和，求把所有石子合并成一堆的最小总代价。

定义状态 `dp[l][r]` = **把第 l 到 r 堆合并成一堆的最小代价**。合并成一堆，必然存在最后一次合并：先合成左段 `[l, k]`、再合成右段 `[k+1, r]`、最后把两堆并起来。于是转移是「枚举分割点」：

$$
dp[l][r] = \min_{k = l}^{r-1}\big( dp[l][k] + dp[k+1][r] \big) + \text{sum}(l, r)
$$

```cpp
vector<vector<int>> dp(n, vector<int>(n, INF));
for (int i = 0; i < n; i++) dp[i][i] = 0;          // 单堆不需要合并
for (int len = 2; len <= n; len++)                  // 按长度从小到大
    for (int l = 0; l + len - 1 < n; l++) {
        int r = l + len - 1;
        for (int k = l; k < r; k++)
            dp[l][r] = min(dp[l][r], dp[l][k] + dp[k+1][r]);
        dp[l][r] += sum(l, r);                       // 最后一次合并的代价
    }
// 答案 dp[0][n-1]
```

**核心概念：填表顺序 = 依赖方向。** `dp[l][r]` 依赖更短的区间 `dp[l][k]` 与 `dp[k+1][r]`——所以必须**按区间长度从小到大填**。长度 1 的先算好，长度 2 依赖长度 1，长度 3 依赖长度 1、2……顺序反了，算到 `dp[l][r]` 时它依赖的还没算出来。<span class="marginnote">「先长度、后左端点、再枚举分割点」是区间 DP 的三重循环固定顺序：`len` 外层，`l` 中层，`k` 内层。背住这个结构，几乎所有区间 DP 的代码骨架都一样，差别只在转移的细节。</span>

## 2 记忆化搜索：自顶向下的区间 DP

区间 DP 用自底向上写，需要小心填表顺序；改用**记忆化搜索（memoized search）** 写，顺序完全不用管——递归自然会先算完依赖的小区间：

```cpp
int solve(int l, int r) {
    if (l == r) return 0;
    if (memo[l][r] != -1) return memo[l][r];   // 已算过，直接返回
    int best = INT_MAX;
    for (int k = l; k < r; k++)
        best = min(best, solve(l, k) + solve(k+1, r));
    return memo[l][r] = best + sum(l, r);      // 记下来再返回
}
```

**核心概念：记忆化 = 递归 + 缓存。** 与朴素递归的唯一区别是 `memo` 数组——算过的状态直接查表，不再重算。它把「同一个区间被反复求解」的指数级降成「每个区间只算一次」的 $O(n^2)$ 状态、$O(n)$ 转移。<span class="marginnote">记忆化搜索特别适合「转移方向不明显」的 DP：比如「戳气球」这类从中间往两边扩展的题，自底向上的填表顺序很难想，但递归的思维顺序却自然。竞赛里两者都要会，根据题目形态挑顺手的。</span>

**重点：memo 初值必须「不可能成为答案」。** `memo` 用 `-1` 或 `0` 做「未计算」标记时，要保证真实答案不可能等于这个值——否则会把「算过」误判成「没算」，逻辑错乱。这是记忆化最容易翻车的细节。

## 3 回文切割：区间 DP 的经典变体

**回文串切割**：把字符串切成若干段，每段都是回文串，求最少切几刀。这题的区间 DP 解法很典型——先用区间 DP 预处理「任意子串是否回文」，再线性 DP 求最少切割数。

**第一步，预处理回文**：`pal[l][r]` 表示 `s[l..r]` 是否回文，转移靠首尾相等 + 内部回文：

$$
pal[l][r] = (s[l] == s[r]) \ \text{and} \ (r - l \le 1 \ \text{or} \ pal[l+1][r-1])
$$

**第二步，最小切割**：`dp[i]` = 前缀 `s[0..i]` 的最少切割数，枚举最后一个回文段的起点 `j`：

$$
dp[i] = \min_{pal[j][i]} dp[j-1] + 1
$$

**核心概念：两个 DP 的接力。** 这题的优雅之处在于「预处理 DP 喂给主 DP」：回文性用区间 DP 算好，切割数用线性 DP 复用。这种「DP 套 DP」的组合在竞赛里很常见——先算好一个「判定表」，再把它当查询工具用。

## 4 公式解析：矩阵连乘的区间结构

**矩阵链乘法**是区间 DP 的教科书题：$n$ 个矩阵连乘，加括号的顺序决定乘法次数，求最少次数。设矩阵 $A_i$ 是 $p_{i-1} \times p_i$ 维，`dp[l][r]` 表示算完 $A_l \cdots A_r$ 的最少次数，分割点在 $k$：

$$
dp[l][r] = \min_{k=l}^{r-1} \big( dp[l][k] + dp[k+1][r] + p_{l-1}\,p_k\,p_r \big)
$$

- **第一步，看依赖**：`dp[l][r]` 依赖两个更短的区间，分割点是 $k$。
- **第二步，看合并代价**：左段结果矩阵是 $p_{l-1} \times p_k$，右段是 $p_k \times p_r$，两者相乘的代价是 $p_{l-1} p_k p_r$——这就是转移里最后一项的来源。
- **第三步，数复杂度**：状态 $O(n^2)$ 个，每个枚举 $O(n)$ 个分割点，总复杂度 $O(n^3)$。

**重点：$O(n^3)$ 是区间 DP 的常见代价。** 三重循环——长度、左端点、分割点——正好是 $n \times n \times n$。看到区间 DP 题，先估一下 $n$：$n \le 500$ 时 $O(n^3)$ 可行，$n$ 到 $10^4$ 就要另寻出路（如四边形不等式优化）。<span class="marginnote">合并石子的代价是「区间和」，矩阵连乘是「三个维度乘积」——两者转移的形态一样，只是「合并代价」函数不同。抓住「区间 DP = 枚举分割点 + 合并代价」这个骨架，具体题目只是换一层外衣。</span>

## 5 记忆化与区间 DP 的取舍

| 维度 | 自底向上（填表） | 自顶向下（记忆化） |
| --- | --- | --- |
| 实现 | 三重循环，需设计填表顺序 | 递归 + `memo` 数组 |
| 状态访问 | 可能算到用不上的状态 | 只算真正需要的状态 |
| 递归开销 | 无 | 有，深递归可能爆栈 |
| 顺序设计 | 依赖方向必须清晰 | 天然由递归保证 |
| 适用 | 顺序明显的经典模型 | 分割/扩展方向不直观的题 |

**辨析｜易错点：** 记忆化搜索虽然好写，但递归深度等于区间长度——$n = 10^5$ 时必然爆栈。竞赛里「大 $n$ 用自底向上，小 $n$ 且方向难用记忆化」是经验法则。另外，记忆化里 `memo[l][r] = best` 这句**必须**写在 return 前，漏掉就等于没缓存，退化成指数级。

**补充：区间 DP 的时间复杂度总览。** 三重循环的 $O(n^3)$ 里，往往可以通过「四边形不等式」或「取分割点的单调性」优化到 $O(n^2)$——这是进阶话题，但先记住：当 $n \le 500$ 时朴素 $O(n^3)$ 足够，$n$ 到 $10^3$ 以上才需要考虑优化。做题时先按数据范围选对写法，比盲目上优化重要得多。

## 6 小结

- 区间 DP 状态是 `dp[l][r]`，转移靠枚举分割点，填表按「长度从小到大」。
- 三重循环固定顺序：外层长度 → 中层左端点 → 内层分割点。
- 记忆化 = 递归 + `memo` 缓存，顺序交给递归，免去填表顺序设计。
- 合并石子、矩阵连乘共享同一骨架：「分割点 + 合并代价」。
- 回文切割展示「DP 套 DP」：先区间预处理回文表，再线性 DP 求切割数。
- 区间 DP 常见 $O(n^3)$
