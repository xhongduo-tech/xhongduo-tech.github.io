## 为什么从并查集开始

有些问题问的不是「两点之间怎么走」，而是「两点在不在同一个连通块里」：朋友圈里两个人是否间接认识、网络里两台机器是否连通、Kruskal 求最小生成树时边会不会成环。这类问题需要动态维护「一堆元素被分成若干集合」，并且支持两种操作：**合并**两个集合，**查询**两个元素是否在同一集合。这就是**并查集（union-find / disjoint set union）**——一个代码极短、却能在**近似常数时间**内完成合并与查询的数据结构。它是图论问题里出现频率最高的「工具型结构」，也是理解「数据结构用树组织、用数组实现」的又一例。

## 1 核心思想：森林与代表元

并查集把每个集合表示成**一棵树**，树的根节点是集合的**代表（representative）**。每个元素只存一个信息：它的「父节点」。元素通过不断找父节点，最终到达根——**根相同，就在同一集合**。<span class="marginnote">`fa[i] = i` 表示第 i 个元素是根（自环代表自己是代表元）。初始化时每个元素自成一棵树，`fa[i] = i` 全部置好。合并就是把一棵树的根挂到另一棵树的根下面——树变成森林，森林的每棵树就是一个集合。</span>

```cpp
vector<int> fa(n);
for (int i = 0; i < n; i++) fa[i] = i;

int find(int x) {               // 找 x 所在集合的代表（根）
    while (fa[x] != x) x = fa[x];
    return x;
}

void unite(int a, int b) {      // 合并 a、b 所在集合
    int ra = find(a), rb = find(b);
    if (ra != rb) fa[ra] = rb;  // 把 ra 的根挂到 rb 下
}
```

**核心概念：查询 = 找根，合并 = 改根。** 判断 `a`、`b` 是否同集合，就是 `find(a) == find(b)`；合并就是把一个根认成另一个的父节点。整个结构的正确性，全部建立在「根是集合的唯一代表」这一不变量上。

## 2 路径压缩：让树变得扁平

朴素并查集有一个隐患：合并方向不当时，树可能退化成一条链，`find` 退化为 $O(n)$。**路径压缩（path compression）** 一举解决——`find` 在找根的路上，顺手把沿途所有节点直接挂到根下面：

```cpp
int find(int x) {
    return fa[x] == x ? x : fa[x] = find(fa[x]);   // 递归版路径压缩
}
```

**核心概念：一次查找，整条路径变平。** 递归版把「找根」和「把路径上所有节点指向根」合并成一行——`fa[x] = find(fa[x])` 既返回根，又修改了沿途每个节点的父指针。<span class="marginnote">路径压缩后树的深度大幅下降：之后的 `find` 只要跳一两步就到根。递归版简洁，但深度极大时可能爆栈；迭代版写法稍长，却能扛住任意深度的链（配合按秩合并后深度其实很小，递归版一般够用）。</span>

## 3 按秩合并：控制树的高度

光有路径压缩，最坏情况仍是 $O(\log n)$ 量级；再加**按秩合并（union by rank）**，树的深度被严格控制在 $O(\log n)$ 内。**秩（rank）** 可以粗略理解为树的高度（或规模），合并时**把秩小的根挂到秩大的根下面**，避免树长高：

```cpp
vector<int> sz(n, 1);        // 用集合大小当秩
void unite(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return;
    if (sz[ra] < sz[rb]) swap(ra, rb);
    fa[rb] = ra;             // 大树当根，小树挂上去
    sz[ra] += sz[rb];
}
```

**重点：为什么按秩合并能让深度保持 $O(\log n)$。** 只有当两棵树的秩相同且合并时，新树秩才 +1；秩为 $k$ 的树至少有 $2^k$ 个节点，所以深度 $k \le \log_2 n$。路径压缩 + 按秩合并双管齐下后，单次操作的复杂度是**反阿克曼函数 $\alpha(n)$**——对所有实际规模都可视为常数。

## 4 公式解析：复杂度与「几乎常数」

并查集的复杂度是算法分析里的一个传奇。设 $n$ 个元素、$m$ 次操作，路径压缩 + 按秩合并的总代价：

$$
O(m\ \alpha(n)), \qquad \alpha(n) \le 4 \quad (\forall\ n \le 2^{2^{2^{65536}}})
$$

- **第一步，什么是 $\alpha$**：$\alpha(n)$ 是**反阿克曼函数（inverse Ackermann function）**，它增长慢到不可思议。
- **第二步，估量级**：$\alpha(10^{10^6})$ 也只有 4 左右——在宇宙内任何实际数据规模下，都可视为「常数」。
- **第三步，读结论**：每个操作平均 $O(\alpha(n))$ ≈ $O(1)$。这是「数据结构操作接近 O(1)」的典范。

**重点：两个优化缺一不可才达到这个界。** 只做路径压缩是 $O(m\log n)$，只做按秩合并是 $O(m\log n)$，两者都用才到 $\alpha(n)$。<span class="marginnote">这个复杂度上界由 Tarjan 等人在 1970 年代证明，是「摊还分析」与「复杂度层级」理论的经典产物。实用层面你只需要记住：并查集的操作在实际竞赛里就是 O(1) 级别，放心用。</span>

## 5 并查集的经典应用

**应用一：连通分量计数。** 初始每个点自成一个分量，每次成功合并 `--cnt`，最后 `cnt` 就是连通分量数。图的 DFS 也能数，但并查集**支持动态加边**——边一条条加进来，随时能回答「当前有几个连通块」。

**应用二：Kruskal 最小生成树。** 边按权重排序，从小到大尝试加入；加入前用并查集检查「这条边两端是否已连通」——已连通就跳过（否则成环），未连通就加入并合并。并查集在这里承担「判环」职责，是 Kruskal 的标配搭档（详见《最小生成树》）。

**应用三：离线处理「可撤销场景」的代替品。** 判断「去掉某些边后是否连通」等反向问题，常常反过来用并查集**离线倒序处理**：从全删的状态开始，把「删除」变成「添加」。<span class="marginnote">并查集变体很多：带权并查集（每个节点到根的偏移量，处理「种类/差值」关系）、可撤销并查集（记录操作栈，用于回溯）、按大小启发式合并的集合合并（配合 vector 维护集合内元素）。遇到「集合合并 + 查询归属」的题，先想并查集。</span>

**辨析｜易错点：** 合并时只改根的父指针，不要动集合内其他元素；`unite` 前先 `find` 拿到根再比较。一个常见错误是 `fa[a] = b` 而不是 `fa[find(a)] = find(b)`——这会让「树挂到元素上」而非「树挂到根上」，破坏森林结构，后续查找全错。

### 带权并查集：给「关系」也记一笔账

经典并查集只记录「在不在同一集合」，但很多题还要知道「集合内元素之间的相对关系」——谁在谁前面、谁大谁小、相差多少。**带权并查集（weighted union-find）** 在 `fa[i]` 之外，再维护一个**权值 `d[i]`**：表示「i 到它的父节点的偏移量」。`find` 时一边压缩路径，一边累加权值：

```cpp
vector<int> fa, d;   // d[i]: i 到根的距离
int find(int x) {
    if (fa[x] == x) return x;
    int root = find(fa[x]);   // 先递归找根
    d[x] += d[fa[x]];         // 累加：x 到新父（根）的偏移
    return fa[x] = root;      // 路径压缩
}
```

**核心概念：权值是「相对关系」的编码。** 如果 `d[i]` 表示「i 比根大 d[i]」，那么任意两个元素 `a`、`b` 的关系 = `d[a] - d[b]`。合并两个集合时，由「已知的 a、b 关系」反推两个根的相对偏移——这就是带权并查集的合并公式。经典应用是「种类」与「差值」关系：食物链（循环克制）、区间和的差值约束、棋盘染色的一致性判断。

**辨析｜易错点：** 带权并查集的 `find` 必须**先递归、后累加**——先拿到压缩后的新根，再沿递归返回时累加 `d`。顺序颠倒会累加到旧的、已被路径压缩破坏的父节点，权值全错。合并时偏移量的方向也极易写反：`a` 相对 `b` 的关系是「a → b」还是「b → a」，决定了公式里的加减号。

### 按大小启发式合并的集合维护

另一个高频变体：**「合并集合 + 查询集合内元素」**。维护每个集合的实际元素列表，合并时把**小集合的元素**逐个并入大集合——这就是「启发式合并」，总复杂度 $O(n\log n)$。每个元素每被并入更大的集合，所在集合大小至少翻倍，所以每个元素至多被移动 $O(\log n)$ 次。这个技巧配合 `vector` + 并查集根，能处理「合并两伙人后，问某人认识哪些人」一类问题。

## 6 小结

- 并查集维护动态集合：`find` 找根（集合代表），`unite` 合并两树。
- 路径压缩 `fa[x] = find(fa[x])` 把路径变平，一次查找多节点收益。
- 按秩合并把小树挂到大树下，深度严格 $O(\log n)$。
- 双优化后复杂度 $O(\alpha(n))$ ≈ $O(1)$
