## 为什么从拓扑排序开始

很多问题可以建模成「先后关系」：修课程要先修前置课、编译程序要先处理依赖库、做项目要按工序推进。这类关系用**有向图**表示——`u → v` 表示「u 必须先于 v」。而**拓扑排序（topological sort）** 就是给这张图排出一个合法的线性顺序：每条边 `u → v` 都满足 `u` 排在 `v` 前面。它在依赖解析、课程表、工程调度里无处不在，还顺带能检测「循环依赖」——也就是有向环。这一章我们掌握 Kahn 算法与 DFS 两种拓扑排序、环检测，以及它在**关键路径**（AOE 网）里的进阶应用。

## 1 拓扑排序的前提：DAG

**核心概念：有向无环图（DAG）是拓扑排序存在的前提。** 若图里有环——`A → B → C → A`——那么「A 必须先于 C、C 又必须先于 A」自相矛盾，任何线性顺序都不可能满足全部边。所以：**有向图能拓扑排序 ⟺ 它是 DAG**。<span class="marginnote">拓扑排序不唯一——只要满足「所有边从前到后」，就可能有多组合法顺序。DAG 拓扑排序的个数本身也是个可算的计数问题（DP 统计），但通常题目只要求任意一组。</span>

**重点：拓扑排序与「环」的关系。** 拓扑排序的第一个实用价值，就是**检测 DAG**：算法如果中途发现「还有节点没处理完，但已经没有任何零入度节点」，就说明有环。这个「排到一半排不下去」的判据，是环检测的最简单实现。

## 2 Kahn 算法：按入度剥洋葱

**Kahn 算法** 从入度入手：每一步选一个**入度为 0**（没有前驱）的节点输出，然后删掉它、把它后继的入度各减 1，重复直到没有节点剩下。

```cpp
vector<int> indeg(n, 0);
for (auto &[u, v] : edges) indeg[v]++;
queue<int> q;
for (int i = 0; i < n; i++) if (indeg[i] == 0) q.push(i);
vector<int> order;
while (!q.empty()) {
    int u = q.front(); q.pop();
    order.push_back(u);
    for (int v : g[u])
        if (--indeg[v] == 0) q.push(v);   // 前驱都排完了，v 可以出场
}
if (order.size() != n) {
    // 有环：还有节点从未入过队
} else {
    // order 是合法拓扑序
}
```

**核心概念：入度为 0 即「无未满足的前置」。** Kahn 的直觉是剥洋葱——先剥掉所有「不依赖别人」的节点，它们的前驱约束满足后，新的「零入度」节点又会浮出来。入度每次减到 0，代表「我的所有前置都已经排好」。<span class="marginnote">用队列还是优先队列，取决于题目要不要「字典序最小」的拓扑序——需要时换成优先队列即可，复杂度不变。`--indeg[v] == 0` 的写法把「减一 + 判断是否清零」合并成一步，是 Kahn 的标准惯用法。</span>

**辨析｜易错点：** 入度减 1 只对**出边指向的节点**做，不能全局乱减；且每个节点**只会**入队一次（入度一旦到 0 就入队，之后不会再变）。若忘记维护入度或重复入队，`order` 长度与环检测都会出错。

## 3 DFS 拓扑排序：后序的反转

拓扑排序还有一条路：**DFS 后序反转**。直觉是——先递归深入所有后继，等一个节点的后继全部「排完」再把它放入结果，得到的顺序再反转就是拓扑序。

```cpp
vector<int> order;
vector<int> state(n, 0);   // 0 未访问，1 在栈中，2 已完工
bool dfs(int u) {
    state[u] = 1;
    for (int v : g[u]) {
        if (state[v] == 1) return false;   // 回到栈中节点，有环
        if (state[v] == 0 && !dfs(v)) return false;
    }
    state[u] = 2;
    order.push_back(u);    // 后序：后继已排完，自己入列
    return true;
}
```

**核心概念：三色标记法。** `state` 用三色区分「未访问 / 在递归栈中 / 已完成」——在栈中再被访问就说明有环，这是 DFS 环检测的标准写法。<span class="marginnote">`order` 是「后序」：一个节点在它的所有后继之后入列。把 `order` 反转，每个节点的前驱（先被递归到）反而排在后继后面，反转后前驱在前的约束就满足了。DFS 拓扑排序的环检测与找拓扑序在同一趟完成，代码优雅但递归深度要小心。</span>

## 4 公式解析：Kahn 算法的复杂度与正确性

Kahn 算法的复杂度可以精确数清：

$$
T = O(\underbrace{n}_{\text{每个节点入队一次}} + \underbrace{m}_{\text{每条边扫一次}}) = O(n + m)
$$

- **第一步，数入队**：每个节点入度为 0 时入队，恰好一次，$O(n)$。
- **第二步，数出边**：每个节点出队时扫它的邻接表，所有节点出边合计 $m$ 条，$O(m)$。
- **第三步，相加**：$O(n+m)$——与 DFS/BFS 遍历同级，是图算法的黄金复杂度。

**重点：正确性的核心是「入度为 0 的节点必然可以排在当前位置」。** 若某节点入度不为 0，说明它还有前驱未排，排它就会违反「前驱在前」的约束；只有入度清零的节点，它的全部前驱都已经确定排在前面——所以 Kahn 每一步的选择都合法，最终要么排完（DAG）、要么剩环。

## 5 关键路径：给工序排工期

**关键路径（critical path）** 是拓扑排序在工程调度里的经典应用。一个项目由若干工序组成，工序间有先后依赖（AOE 网），求**项目完成的最短总工期**，以及哪些工序**拖延不得**（关键工序）。

算法分两步，都用拓扑序推进：

**第一步，算最早开始时间（earliest）**：按拓扑序从前向后，`earliest[v] = max(earliest[u] + w)`——工序 v 必须等它所有前驱完成。

**第二步，算最晚开始时间（latest）**：按拓扑逆序从后向前，`latest[u] = min(latest[v] - w)`——工序 u 最迟不能耽误后继开工。

**关键工序 = `earliest == latest` 的工序**，它们构成关键路径；关键路径的总长就是项目最短工期。<span class="marginnote">关键路径上的工序一旦延期，整个项目就延期——这就是「关键」的含义。`earliest` 用 max、`latest` 用 min，方向完全相反：一个被「最慢的前驱」卡住，一个被「最急的后继」约束。工程上 PERT/CPM 网络图就是这个模型的商业版本。</span>

**辨析｜易错点：** 关键路径**不唯一**——可能有多个工序都满足 `earliest == latest`，形成多条关键路径。求「项目最短工期」只需一步 `earliest` 全算完取最大值；求「哪条路径关键」才需要两步对比。

## 6 拓扑排序的应用谱系

**课程表 / 依赖解析**：LeetCode「课程表」系列直接就是拓扑排序 + 环检测——`u → v` 表示「先学 u 再学 v」，能排完就无环。

**DAG 上的 DP**：拓扑序是 DAG 上 DP 的**天然填表顺序**——按拓扑序从前向后转移，保证「算到某个节点时它的前驱都已算好」。最长路、方案计数、概率 DP 在 DAG 上都靠拓扑序。

**字典序最小拓扑序**：把 Kahn 的普通队列换成**优先队列**，每次取编号最小的零入度节点，得到的就是字典序最小的一组拓扑序。

**核心概念：拓扑序是 DAG 的「线性化」。** 把二维的依赖图摊平成一条线，让一切「从前向后」的遍历与 DP 都能进行——这是拓扑排序在算法里最深层的作用。

## 7 小结

- 有向图能拓扑排序 ⟺ 是 DAG；有环则无解。
- Kahn 算法：零入度入队、出队减后继入度，$O(n+m)$
