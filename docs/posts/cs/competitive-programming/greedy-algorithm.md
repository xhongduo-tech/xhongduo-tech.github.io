## 为什么从贪心算法开始

**贪心算法（greedy algorithm）** 是竞赛里「看着最不讲道理、实现却最简单」的一类算法：每一步都做**当前看起来最优**的选择，不做回头路，不考虑未来。多数时候这种「短视」会害了你——但有一类问题，短视恰恰就是最优策略。活动安排、哈夫曼编码、部分背包、跳跃游戏……它们都满足一个关键性质，让贪心成立。这一章我们学会三件事：怎么设计贪心策略，怎么**证明**贪心是对的，以及怎么识别「贪心会错、必须上 DP」的题。

## 1 贪心的直觉与风险

先看一个经典题：**活动安排（interval scheduling）**——给一堆带开始、结束时间的活动，选尽量多的互不重叠的活动。最自然的贪心是**按结束时间最早选**：先选最早结束的，腾出最多时间给后面。

```cpp
sort(acts.begin(), acts.end(), [](auto &x, auto &y){ return x.end < y.end; });
int ans = 0, last = -1;
for (auto &a : acts)
    if (a.start >= last) { ans++; last = a.end; }   // 选一个，更新最后结束时间
```

**辨析｜易错点：贪心不是「直觉对就对」。** 同一个活动问题，按开始时间最早选、按持续最短选，都可能不是最优。贪心策略看起来都合理，但对错的差别只在微妙之处——所以**每个贪心都必须证明**，这是它与暴力、分治最大的不同。<span class="marginnote">「按结束时间最早」为什么对？因为任何最优解里的第一个活动都能替换成「全局结束最早的活动」而不影响数量——这就是<strong>交换论证</strong>，贪心证明的两大武器之一。</span>

## 2 证明贪心正确：交换论证与领先论证

贪心不靠直觉担保，靠证明。两大标准证明手法：

**交换论证（exchange argument）**：假设存在一个最优解，它与贪心解的第一个不同选择出现在某处；证明「把最优解里那个选择换成贪心的选择，不会让解变差」。反复交换，最优解就变成了贪心解——于是贪心也是最优。

**领先论证（greedy stays ahead）**：证明贪心解在每一步都不比任何最优解「落后」。比如活动安排：贪心每次选结束最早的活动，所以贪心选的第 $k$ 个活动的结束时间，不晚于最优解选的第 $k$ 个——于是贪心能选的个数不少于最优。

**核心概念：贪心正确性的两种形态。** 交换论证证明「贪心解可以替代最优解」，领先论证证明「贪心解从不落后」——两者殊途同归，都在证明「局部最优的累积等于全局最优」。

## 3 贪心经典：哈夫曼编码与部分背包

**哈夫曼编码（Huffman coding）**：把出现频率高的字符用短编码，频率低的用长编码，总长度最短。贪心策略是**每次合并频率最小的两个节点**——这与《栈、队列与优先队列》里用优先队列取最值完美配合：

```cpp
priority_queue<long long, vector<long long>, greater<long long>> pq;
for (int x : freq) pq.push(x);
long long ans = 0;
while (pq.size() > 1) {
    long long a = pq.top(); pq.pop();
    long long b = pq.top(); pq.pop();
    ans += a + b;          // 合并代价计入答案
    pq.push(a + b);
}
```

**部分背包（fractional knapsack）**：物品可以切碎装袋，容量有限，求最大总价值。贪心按**单位重量价值**从高到低装，装满为止——因为可以切碎，不存在「装了装不下」的浪费，贪心严格最优。这与 0/1 背包形成鲜明对比：0/1 背包里物品不可分，「局部最优」会失败，必须用动态规划。<span class="marginnote">「能不能切碎」决定了问题的性质：能切碎 → 贪心；不能切碎 → 需要 DP。这个分水岭是理解贪心适用边界的绝佳例子——同一个「背包」名词，两种完全不同的算法。</span>

## 4 公式解析：哈夫曼编码的最优性

哈夫曼贪心「每次合并最小的两个」为什么总代价最小？设编码的带权路径长度（总代价）为：

$$
W = \sum_{i} f_i \cdot d_i
$$

其中 $f_i$ 是第 $i$ 个字符的频率，$d_i$ 是它的编码长度。

- **第一步，观察结构**：在最优编码树里，频率最小的两个字符必然处于**最深的两片叶子**，且它们是兄弟。
- **第二步，交换论证**：若某最优树里最小的两个字符不在最深处，把它们交换到最深且互为兄弟的位置，只会让 $W$ 变小或不变——因为越小的频率越应该走最长的路。
- **第三步，归纳**：合并这两个字符后，剩下的问题规模减一，仍是同一类「构造最优树」问题——递归地合并最小者，整体最优。

**重点：贪心证明的通用骨架。** 哈夫曼的证明是「贪心最优性」的标准模版：先证明「贪心的第一步选择可以被最优解接受」，再证明「剩余问题是同构的子问题」。两步合起来，归纳出贪心全程最优。

## 5 贪心与动态规划的边界

| 维度 | 贪心 | 动态规划 |
| --- | --- | --- |
| 决策方式 | 只看当前最优，不做回头 | 考虑所有选择，保留最优子结构 |
| 证明要求 | 必须证交换/领先 | 状态转移方程 + 正确性推导 |
| 适用条件 | 局部最优 = 全局最优 | 最优子结构 + 重叠子问题 |
| 复杂度 | 通常 $O(n\log n)$
