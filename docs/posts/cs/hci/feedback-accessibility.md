# 反馈与可访问性

## 为什么从反馈与可访问性开始

交互是一条回路，而**反馈（feedback）就是回路的另一半**：用户发出操作，系统必须告诉用户「我听到了，我正在这样处理，结果是这样」。没有反馈，用户就落在诺曼的评估鸿沟里——不知道发生了什么。而**可访问性（accessibility）**则问一个更根本的问题：这条反馈回路，对所有人（包括残障用户）都走得通吗？两者其实是同一个主题的两面——**反馈如何送达，取决于接收者的感知通道**。<span class="marginnote">把两者放在同一篇，是因为它们共享同一套方法：<strong>为不同的感知与操作通道设计冗余</strong>。给不了视觉反馈的用户提供听觉或触觉反馈，给不了键盘的用户提供开关控制——这不是「额外福利」，而是回路的完整性要求。</span>

## 1 反馈：交互的确认回路

诺曼把反馈列为设计的核心原则：**系统对每一次用户操作都要给出可见、即时的响应。** 反馈回答三个问题：

**已收到**：我的操作被系统接受了吗？（按钮按下有视觉凹陷/颜色变化）
**进行中**：系统现在在处理什么？（加载动画、进度条）
**已完成**：操作的结果是什么？（成功/失败提示、结果展示）

反馈要满足两个性质才有效：

**即时性**：反馈最好在 100ms 内出现——人的注意力保持在此量级。迟到的反馈（比如点了保存，5 秒后毫无动静）会让用户怀疑操作无效而重复点击。
**关联性**：反馈必须与操作直接对应。点「保存」却弹出一个无关的广告提示，是反馈与操作脱节的典型坏设计。

**辨析｜易错点：** 反馈 ≠ 通知轰炸。**每一个反馈都在占用用户的注意**，过度反馈（每个操作都弹窗确认）让用户养成「闭眼点确定」的机械习惯，反而使真正的警告失效——这就是「警示疲劳」：当系统什么都提醒，就相当于什么都不提醒。

## 2 反馈的模态与时机

反馈可以走多条感知通道，各有适配场景：

| 通道 | 优点 | 缺点 | 典型用例 |
| --- | --- | --- | --- |
| 视觉 | 信息量大、可回顾 | 占用视觉注意、可被遮挡 | 按钮状态、提示条、加载动画 |
| 听觉 | 无需视觉、可并行 | 环境噪音下失效、打扰他人 | 消息提示音、错误蜂鸣 |
| 触觉 | 私密、即时、不打扰 | 表达力弱 | 手机振动、Apple Watch 轻拍 |

Wickens 的**多重资源理论**解释了为什么多模态反馈更有效：视觉与听觉各自占用独立的认知资源，把「正在进行」的反馈放听觉、「详细结果」放视觉，两条通道可以并行工作而不互相干扰。

时机上，反馈要分**即时反馈**（每个操作，<100ms）与**延迟反馈**（长任务结束，如「邮件已发送」）。延迟反馈要配合「进行中」提示，否则用户无法判断系统是活着还是卡死了。

## 3 可访问性：WCAG 与 POUR

**可访问性（accessibility）**：让残障人士（视力、听力、肢体、认知障碍）也能独立使用产品。国际上通行的标准是 **WCAG（Web Content Accessibility Guidelines）**，其核心可浓缩为四条原则，缩写 **POUR**：

**可感知（Perceivable）**：信息能通过某种感知通道被接收到。对策：图片配替代文本（alt text）、视频配字幕、纯颜色不用作唯一信息载体。
**可操作（Operable）**：用户能操作界面。对策：全部功能键盘可达、操作有足够时间、避免诱发光敏癫痫的闪烁。
**可理解（Understandable）**：内容与操作能被理解。对策：语言清晰、行为可预测、输入有错误提示与纠正指引。
**健壮（Robust）**：能被辅助技术可靠解读。对策：正确的语义化 HTML 标签、符合标准、跨浏览器兼容。

WCAG 还给每项准则分级（A / AA / AAA），实践中大多数组织以 **AA 级**为合规目标。<span class="marginnote">「图片配 alt 文本」看似小事，却是屏幕阅读器用户「看见」图片的唯一通道。alt 文本要描述图片的<strong>信息内容</strong>而不是「这是一张照片」——后者对盲人用户毫无信息量。</span>

## 4 辅助技术与设计对策

可访问性设计的对象，是使用**辅助技术（assistive technology，AT）**的用户：

**屏幕阅读器（screen reader）**：把界面文字朗读出来。用户靠**键盘焦点**导航，靠语义标签理解结构。对策：用 `nav`、`main` 等**语义化标签**而不是裸 `div`、给表单控件配 `label`、设置正确的 heading 层级。
**开关控制（switch access）**：用单个开关（眨眼、呼气、下巴）扫描焦点选择目标。对策：焦点移动要有清晰高亮、扫描速度要可调。
**键盘导航**：全功能可用 Tab / Enter / 方向键完成。对策：保证可见焦点、逻辑 Tab 顺序、无键盘陷阱（焦点卡死在某元素）。
**放大与高对比**：低视力用户放大界面、提高对比度。对策：文本可缩放不破碎、正文对比度 ≥ 4.5:1。

**可访问性的一个核心思想是「不假设通道」**：不要假设用户能看见、能听见、能精确点击、能用双手操作。每个「假设」都把一部分用户关在门外。

## 5 核心对比表：反馈与可访问性的设计清单

| 反馈问题 | 常规设计 | 可访问设计 | 覆盖的残障用户 |
| --- | --- | --- | --- |
| 操作已收到 | 按钮颜色变化 | 颜色 + 语义状态 + 焦点样式 | 色觉障碍、低视力 |
| 错误提示 | 红色文字 | 红色 + 图标 + 文字 + aria 提示 | 色盲、认知障碍 |
| 进行中状态 | 转圈动画 | 动画 + 读屏可读的进度文本 | 盲人（读屏） |
| 交互方式 | 鼠标点击 | 键盘、开关、语音皆可达 | 肢体障碍 |
| 警告信息 | 弹窗 | 弹窗 + 声音 + 可暂停 | 注意力障碍、光敏人群 |

「反馈冗余 + 操作多路径」是同一件事的两面：**重要信息多通道送达，重要操作多通道可达。**

## 6 案例：一个完整的「删除」反馈设计

把反馈与可访问性的原则放进一个具体操作——「删除一条笔记」，看一套完整的反馈系统长什么样。

**操作前（约束 + 可撤销）**：删除不是「立即销毁」，而是先移到「最近删除」。这条约束让「删除」从不可逆变成可逆——用户敢删了，因为反悔有路。

**操作时（即时反馈）**：点删除的瞬间，列表项**立即淡出并伴随轻微位移**——不是等服务器响应了才动，而是先给「已收到」的即时反馈（<100ms 级别），后台异步处理。若网络失败，再恢复原状并提示。

**操作后（状态确认）**：屏幕底部出现一条轻提示：「笔记已移到最近删除」+ 一个「撤销」按钮。视觉 + 文字双通道确认结果，且给撤销的显式出口。

**可访问性版本**：读屏用户听到「已删除，可撤销」；色弱用户不依赖「变灰」判断状态，因为还有文字；键盘用户能直接 Tab 到「撤销」按钮。<span class="marginnote">这个例子的要点是「反馈是分层设计」：约束管操作前（可撤销），即时反馈管操作中（已收到），提示条管操作后（结果确认），每一层对应诺曼评估鸿沟的一个环节。单靠任何一层都不完整——少了操作后的「撤销」，用户删错了就只能后悔。</span>

**对照坏例子**：一个「删除即永久、点完没任何提示」的 App——操作后用户完全不知道发生了什么（评估鸿沟），更无法反悔（无约束）。同样是删除，差距不在功能，在反馈与约束的设计深度。

### 反馈的节奏：分清「每步确认」与「终态确认」

反馈不是越多越好，关键在**节奏**。把反馈按操作的生命周期分层，就能避免「过度确认」与「反馈缺失」两个极端：

- **连续操作（拖动、滚动、输入）**：给**持续反馈**——滑块位置、滚动进度、输入字数，让用户随时知道「正在发生什么」。不需要每一步都弹窗。
- **离散操作（点击、提交）**：给**瞬时确认**——按钮凹陷、转圈、提示条，告诉用户「收到了」。一次操作配一次确认。
- **高代价操作（删除、付款、发送）**：给**二次确认**——操作前确认（约束）+ 操作后结果提示（反馈），双保险。
- **长任务（上传、安装、训练）**：给**过程反馈**——进度条、剩余时间、阶段提示，并在完成时给**终态确认**。

**辨析｜易错点：** 最典型的节奏错误是「**该持续反馈的给了弹窗，该终态确认的给得含糊**」。拖一个滑块，每动一点都弹窗确认——用户被烦死；点一个「发送」，静默完成——用户不知道发没发出去。反馈的节奏要**匹配操作的代价与时长**，而不是统一「每步都弹」。

把反馈分层想清楚之后，再回头看《反馈与可访问性》的核心论点就完整了：**反馈在正确的时间、以正确的通道、给正确的对象**——这三条，就是反馈设计的全部。

把这一篇浓缩成一句：**反馈让用户知道系统在做什么，可访问性让所有用户都能收到这份通知**——两者是同一个「回路完整性」问题的两面。

## 7 小结

- 反馈回答「**已收到 / 进行中 / 已完成**」三个问题，要**即时（<100ms）且与操作关联**。
- 反馈过度会造成**警示疲劳**；多重资源理论支持用多模态并行反馈。
- 可访问性的核心标准 **WCAG/POUR**：可感知、可操作、可理解、健壮，实践以 AA 级为目标。
- 设计对策面向屏幕阅读器、开关控制、键盘、放大等**辅助技术**，核心是「不假设感知通道」。
- 反馈冗余与操作多路径是同一原则的两面：**重要信息多通道送达，重要操作多通道可达**。
