## 为什么一致性不够还要同步

[[cache-coherence-snooping]] 与 MESI 保证了「写会传播」。但并行程序还需要更强的保证：**两个线程不能同时改同一个计数器的值、不能让一个线程读到另一个线程「写了一半」的状态**。这需要**同步（synchronization）**——而同步的原子性，必须由**硬件指令**提供。<span class="marginnote">「读-改-写」三步（`counter++` 在机器层面是读、加、写三条指令）若没有硬件原子保证，两个线程会同时读到旧值、同时加 1、只写回一次——<strong>计数悄悄丢了一次</strong>。这就是必须原子操作的根因。</span>

## 1 原子操作：硬件保证的「不可分割」

**核心概念**：**原子操作（atomic operation）**：一组读-改-写在硬件上**不可中断**地完成——要么整组成功，要么整组不执行，期间没有其他核能插入。

经典原子原语：

| 原语 | 语义 | 用途 |
| --- | --- | --- |
| **test-and-set** | 读旧值、写 1、返回旧值 | 自旋锁 |
| **compare-and-swap（CAS）** | 若值==期望则换新值 | 无锁数据结构 |
| **fetch-and-add** | 读旧值、加增量、返回旧值 | 计数器、栅栏 |
| **atomic exchange** | 读旧值、写新值 | 锁、窃取工作 |

**RISC-V A 扩展**（[[riscv-overview]] 的原子扩展）提供两类：**AMO**（Atomic Memory Operation，如 `amoadd.w` 直接在内存上做原子加）与 **LR/SC**（`lr.w` 保留地址、`sc.w` 条件存储，失败则重试）——LR/SC 能组合出 CAS 等任何原子操作，是 RISC-V 的「万能原子」。

## 2 用原子操作实现锁：自旋锁

一个最简单的**自旋锁（spinlock）**：

```asm
# RISC-V：用 A 扩展的原子交换（test-and-set）实现
# a0 = 锁的地址，1 = 上锁，0 = 空闲
lock:
    li    t0, 1
1:  amoswap.w.aq  t1, t0, (a0)   # 原子地：读旧值 → 写 1 → 旧值放 t1
    bnez  t1, 1b                 # 旧值非 0 = 锁被占，跳回去继续试
    ret                          # 拿到锁，进入临界区
unlock:
    amoswap.w.rl  x0, x0, (a0)   # 原子地把 0 写进锁，释放
    ret
```

**自旋锁的代价**：拿不到锁的核在 `while` 循环**空转**——浪费 CPU 与一致性流量（每次试锁都产生总线事务）。优化：**测试-测试-设置（test-and-test-and-set）**先普通读一次，只有读到 0 才发原子操作；或者让等待者**休眠**（内核锁）而非自旋。

## 3 栅栏（Barrier）：全体会合

**核心概念**：**栅栏（barrier）**：所有参与线程**都到达**某个点后，才能一起继续——像「等到最后一个人到齐才开饭」。

集中式实现：一个计数器 + 一把锁。每个线程到达时原子地加 1，直到等于线程数 $P$ 时全体放行。经典细节是 **sense reversing**：每次栅栏翻转一个「预期值」，避免计数器清零时的竞争。

## 4 同步与内存序：acquire/release

锁只是「保证互斥」，还差最后一块：**拿到锁后，临界区里的读写必须发生在「抢锁成功」之后**；释放锁时，临界区的写必须**先于**解锁可见。这就是**acquire/release 语义**：

- **acquire（获取）**：其后的读/写都不能移到 acquire 之前。
- **release（释放）**：其前的读/写都不能移到 release 之后。

**辨析｜易错点：** 原子操作 ≠ 内存屏障。原子性保证「不可分割」，**但不保证顺序**（其他核看到的读写次序还要靠屏障/一致性模型）。写无锁代码时，CAS 原子正确 + 顺序错误是常见的「静默 bug」——**原子性与内存序是两个维度**，见 [[weak-release-consistency]]。

## 5 公式解析：集中式 vs 树形栅栏

$$
T_{\text{集中式}} = O(P), \qquad T_{\text{树形}} = O(\log P)
$$

- **第一步，看集中式**：$P$ 个线程挤在一个计数器上，每人都要争锁 + 原子加——串行瓶颈，$P$ 越大越慢。
- **第二步，看树形**：线程先两两会合，再四四会合……每次会合点独立、可并行——总深度只有 $\log P$ 层。
- **第三步，选型**：$P$ 小（几十）集中式够用；$P$ 大（数百核、GPU）必须树形/层次化，否则栅栏成为全局瓶颈。

## 6 数值算例：自旋锁的两种流量账

设 4 个核抢一把自旋锁，一个核持锁 1000 个周期的临界区，其余 3 个核空转等待：

- **朴素 test-and-set**：每次重试都发一次原子操作（总线事务）——**等待的 1000 周期里可能产生数千次总线事务**，直接压垮总线。
- **test-and-test-and-set**：先普通读锁（命中缓存、无总线流量），读到 0 才发原子操作——**1000 周期里总线事务只有少数几次**。

$$
\text{总线事务}:\quad \text{朴素} \approx O(\text{等待周期}),\qquad
\text{测试-测试-设置} \approx O(\text{锁释放次数})
$$

**要点**：同一个锁，实现差一点，一致性流量差两个数量级——**同步原语的实现质量，直接决定多核系统的可扩展性**。这也是为什么工业级锁有排队锁、MCS 锁等更精细的设计。

## 7 常见误区再辨析

- **「原子操作自带内存序」**：原子性只保证「不可分割」，**不保证顺序**；acquire/release 语义要显式标注。
- **「锁越多越好」**：锁粒度细了并发高，但原子操作与缓存一致性流量也上升——**粒度与开销要权衡**。
- **「栅栏只是锁的变体」**：栅栏是**全局会合**（所有人都到齐才继续），锁是**互斥**（同一时刻一人进）——语义不同。
- **「LR/SC 比 CAS 弱」**：LR/SC 能组合出 CAS 等一切原子操作，且免于「ABA 问题」——它更强，只是实现上要处理伪共享。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 原子操作 | 不可分割的读-改-写 |
| test-and-set | 读旧值、写 1、返回旧值 |
| CAS | 比较并交换 |
| fetch-and-add | 原子加并返回旧值 |
| LR/SC | 保留地址 + 条件存储 |
| 自旋锁 | 拿不到就空转等待的锁 |
| test-and-test-and-set | 先读后原子，减少流量 |
| 栅栏（barrier） | 全体到齐才继续的会合点 |
| acquire / release | 获取/释放时的顺序语义 |

## 9 小结

- **同步**让线程「按次序协作」，原子操作是它的硬件地基。
- 原子原语：**test-and-set、CAS、fetch-and-add、exchange**；RISC-V 用 **AMO + LR/SC** 提供。
- **自旋锁**用原子交换实现，拿不到就空转（浪费流量）——要测试-测试-设置优化。
- **栅栏**全体会合，集中式 $O(P)$、树形 $O(\log P)$。
- **原子 ≠ 屏障**：原子性管「不可分割」，内存序管「读写次序」——两者要一起用。

在下一节，我们系统化「读写的次序」问题——**一致性模型（Memory Consistency Model）：顺序一致性**。原子操作保证了「不可分割」，栅栏保证了「到齐」，而一致性模型规定「读写的次序到底怎么算」——三者合起来才是完整的并行语义。
