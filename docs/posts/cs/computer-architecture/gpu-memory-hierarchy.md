# GPU 存储层次：共享存储、寄存器堆与全局存储

## 为什么 GPU 的存储层次「要人管」

CPU 的缓存层次**硬件自动管理**（程序员看不见）。GPU 恰恰相反：它把最关键的一块——**共享内存（shared memory）**——交给**程序员显式管理**。这是 GPU 编程与 CPU 编程最大的不同：**性能不再只靠编译器与硬件，而是靠你把数据「搬」到对的地方**。<span class="marginnote">GPU 的哲学延续「[[gpu-architecture-overview]] 吞吐优先」：全局存储很慢没关系，<strong>用共享内存 + 大量 warp 把它藏起来</strong>。理解存储空间，就是理解 GPU 优化的 80%。</span>

## 1 GPU 的存储空间一览

| 空间 | 作用域 | 位置 | 延迟 | 管理 |
| --- | --- | --- | --- | --- |
| **寄存器** | 单线程 | 片上 | 极快 | 编译器 |
| **共享内存** | 块内 | 片上 | 快（~20 周期） | **程序员** |
| **全局内存** | 所有线程 | 显存 | 慢（数百周期） | 程序员+硬件 |
| **本地内存** | 单线程 | 显存（溢出用） | 慢 | 编译器 |
| **常量/纹理** | 只读广播/2D | 显存+缓存 | 中 | 硬件缓存 |

**核心概念**：寄存器与共享内存是「快」，全局内存是「慢」——GPU 优化的主线就是**把数据从全局搬到共享内存、用完后写回**。

## 2 共享内存：软件管理的「缓存」

**核心概念**：**共享内存（shared memory）**：每个 SM 上一块**片上 SRAM**（如 48–164 KB），供**同一个块的线程**协作使用——等价于一块「程序员手动填的 L1」。

典型用法（矩阵分块，对应 [[cache-optimization-compiler]] 的 tiling）：

```cuda
__shared__ float tile[BLOCK][BLOCK];
// 把全局内存的一块搬到共享内存
tile[tx][ty] = A[row][col];
__syncthreads();               // 块内同步：等大家搬完
// 然后从共享内存高速读取，反复重用
```

**为什么值得**：全局内存数百周期延迟 vs 共享内存 ~20 周期——**搬一次、用多次，分块越大越赚**。

## 3 内存合并（Coalescing）：一次事务装下整个 warp

**核心概念**：**内存合并（memory coalescing）**：一个 warp 的 32 个线程访问全局内存时，如果地址**连续**，硬件把它们合并成**一次（或几次）大的内存事务**；如果地址**乱跳**，就是 32 次独立事务——**带宽差 32 倍**。

```cuda
// 好：连续地址（合并）
c[i] = a[i] + b[i];          // 线程 i 访 a[i]，连续 → 一次事务

// 差：跨步地址（不合并）
c[i] = a[i * 4];             // 每隔 4 个元素取一个 → 大量浪费
```

**这是 GPU 性能最著名的陷阱**：代码逻辑一样，访存模式不同，带宽差一个数量级。优化规则只有一条：**让 warp 内的线程访问连续地址**。

## 4 Bank 冲突：共享内存的「伪并行」

共享内存按 **bank** 组织（如 32 个 bank，每个 bank 一个 32 位字宽），一个 warp 同时访问共享内存时：

- **无冲突**：32 个线程访问**不同 bank** → 一次搞定。
- **bank 冲突（conflict）**：多个线程访问**同一 bank 的不同地址** → 被串行化，慢 2–32 倍。<span class="marginnote">bank 冲突是 [[dram-internal-organization]] 的 bank 概念在共享内存上的重演：<strong>同一时刻同一 bank 只能服务一次访问</strong>。解法是「padding」——给数组每行多加一个元素，错开 bank 对齐。</span>

## 5 核心对比表：快存储与慢存储

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 寄存器 | 共享内存 | 全局内存 |
| --- | --- | --- | --- |
| 作用域 | 单线程 | 块内 | 全部 |
| 延迟 | 最快 | ~20 周期 | 数百周期 |
| 容量 | 每线程数十个 | 每 SM 数十 KB | GB 级 |
| 控制 | 编译器 | **程序员** | 程序员 |
| 冲突风险 | 无 | **bank 冲突** | 不合并 |

## 6 小结

- GPU 存储五空间：**寄存器、共享内存、全局内存、本地内存、常量/纹理**。
- **共享内存是程序员管理的缓存**：搬一次、用多次，是 GPU 优化的核心手法。
- **内存合并**：warp 线程访问连续地址 → 一次事务；乱跳 → 32 倍浪费。
- **bank 冲突**让共享内存访问串行化，用 padding 错开。
- GPU 优化主线 = **把数据搬进共享内存 + 访存连续化**。
