## 为什么互连也有「两大阵营」

把上千台服务器连起来做超算/AI 训练，用什么网络？**以太网**（便宜、通用、满世界都是）与 **InfiniBand**（贵、快、低延迟、专为集群设计）长期竞争。这个竞争的核心问题只有一个：**集群通信要「快到什么程度」，值不值得为它用专用网络**。<span class="marginnote">对照 [[wsc-architecture]] 的数据中心分级网络：互联网公司的「通用云」用以太网；超算与 AI 训练集群用 InfiniBand（或高性能以太网）。<strong>网络的选型 = 延迟/带宽需求 × 成本预算</strong>。</span>

## 1 以太网：通用之王，快得不够

以太网的优点与短板同样鲜明：

**优点**：生态无敌、成本低、即插即用、与互联网天然兼容。
**短板**：**有损（lossy）**——拥塞时**丢包**，靠 TCP 重传恢复；重传让**尾延迟爆炸**（[[tail-latency]] 的大敌）。且 TCP/IP 协议栈在内核里处理，**CPU 开销高**。

**核心概念**：以太网是为「尽力而为」设计的——它默认丢包可接受。但**集群计算（尤其 AI 训练）需要「不丢包 + 低延迟 + 低 CPU」**，这正是 InfiniBand 的切入点。

## 2 InfiniBand：为集群而生

**InfiniBand（IB）**是专为 HPC/集群设计的互连：

**RDMA 直通**：数据**直接从一个节点的内存拷到另一个节点的内存**，绕开内核与 TCP（见下）。
**无损失（lossless）**：用**基于信用的流控**——发送前先确认对方有缓冲，**不丢包**，延迟稳定。
**极高带宽**：单链路从 EDR 的 100 Gb/s 到 NDR 的 400 Gb/s，多链路聚合。
**低延迟**：亚微秒级，是 TCP 的几十分之一。

**RDMA 为什么快**：

```text
传统 TCP 一次发送，数据被拷贝多次、CPU 全程参与：
  应用缓冲 → 内核协议栈缓冲 → NIC 缓冲 → 网络

RDMA 一次发送，只有一次、由网卡硬件完成：
  应用缓冲 ─────────────────────────────→ 网络
        （对端网卡直接把数据 DMA 写进对端应用内存）
```

**核心概念**：**RDMA（Remote Direct Memory Access，远程直接内存访问）**让网卡硬件直接把数据搬进对端应用内存——**省掉内核拷贝与 CPU 中断**，延迟与 CPU 占用同时大降。

## 3 RoCE：以太网也想 RDMA

RDMA 不是 InfiniBand 专利。**RoCE（RDMA over Converged Ethernet）**把 RDMA 搬到以太网上：

**RoCE v2**：跑在标准以太网上，享受 RDMA 的低延迟，又用回廉价以太网设备。
**前提**：以太网要**无损失**——需要 **PFC（优先流控）** 等机制，把「有损」以太网改造成「无损」。
**代价**：PFC 配置复杂、容易「一个队列堵住全网」（反压问题）。

**辨析｜易错点：** RoCE 不是「免费获得 InfiniBand」——它需要**无损以太网**改造，而 PFC 的「全局反压」在规模大时反而引入新问题。**选 InfiniBand 还是 RoCE，是「专用可靠 vs 通用便宜」的取舍**。

## 4 竞争现状：超算 vs 云

| 场景 | 选择 | 理由 |
| --- | --- | --- |
| 超算（Top500） | **InfiniBand** 为主 | 极低延迟、无损、成熟 |
| AI 训练集群 | InfiniBand / RoCE 并进 | 带宽敏感、all-reduce 密集 |
| 通用云/互联网 | **以太网** | 生态、成本、兼容 |
| 企业网络 | 以太网 | 够用就好 |

**核心概念**：AI 训练把这场竞争推向白热化——大模型要**上千卡高速互连做 all-reduce**，网络带宽直接决定训练时间。**NVIDIA 的 NVLink/InfiniBand 生态、云厂商的 RoCE 网络**，是同一需求的两条路线。<span class="marginnote">有趣的是「拓扑 + 交换」的经典设计在两边通用：胖树（[[interconnection-topologies]]）是数据中心标准，无损流控（[[wormhole-virtual-channel]] 的 VC 思想）在无损以太网里同样出现。<strong>基础原理不变，变的是价格与生态</strong>。</span>

## 5 核心对比表：以太网 vs InfiniBand

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 以太网 | InfiniBand |
| --- | --- | --- |
| 设计目标 | 通用互联 | 集群高性能 |
| 丢包 | 有损（拥塞丢包） | **无损（信用流控）** |
| RDMA | RoCE 可选 | **原生** |
| CPU 开销 | 高（TCP 内核） | 低（网卡直通） |
| 延迟 | 数十~数百 μs | **亚微秒~数 μs** |
| 成本 | 低 | 高 |
| 场景 | 云、互联网 | 超算、AI 训练 |

## 6 小结

- 集群互连两大阵营：**以太网（通用便宜）vs InfiniBand（高速专用）**。
- 以太网有损 + TCP 高开销 → 延迟高；InfiniBand 无损 + RDMA → 延迟低。
- **RDMA** 让网卡直接把数据搬进对端内存，绕开内核，延迟与 CPU 双降。
- **RoCE** 把 RDMA 搬到以太网，但需要无损改造（PFC），有反压风险。
- AI 训练把互连带宽推成第一需求，超算用 IB、云用 RoCE/以太网。
