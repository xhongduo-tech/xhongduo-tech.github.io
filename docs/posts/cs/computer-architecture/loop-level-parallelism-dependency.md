## 为什么循环是并行的总开关

程序里 90% 的执行时间在循环里；而循环里的**每次迭代是否独立**，决定了它能不能被塞进多核（TLP）、SIMD（DLP）、GPU 线程——**依赖分析是这一切的总开关**。<span class="marginnote">[[data-level-parallelism-overview]] 说 DLP 是「一条指令多份数据」，[[simd-programming-autovectorization]] 说编译器要检查合法性——<strong>合法性检查的核心，就是本节要讲的依赖分析</strong>。</span>

## 1 循环级并行的三种出口

同一段循环，按并行方式可以走三条路：

```c
for (i = 0; i < n; i++)          // 迭代之间无依赖
    c[i] = a[i] + b[i];          // → 多核 / 向量化 / GPU 三条路都通
```

| 出口 | 手段 | 对应并行 | 载体 |
| --- | --- | --- | --- |
| **多核** | 迭代分给不同核 | TLP | CPU 多核 |
| **向量化** | 一组元素一起算 | DLP | SIMD/向量 |
| **GPU** | 一个元素一个线程 | DLP+TLP | GPU warp |

**核心概念**：**循环级并行（loop-level parallelism）**：把「迭代空间」切分后并行执行。切法有**循环分割**（前一半/后一半分给不同核）、**条带开采**（[[vector-isa-programming-model]] 的 strip-mining）、**循环分块**（[[cache-optimization-compiler]] 的 tiling）。

## 2 依赖分析：判断迭代是否独立

**核心概念**：**依赖分析（dependence analysis）**：编译器分析循环体，判断**不同迭代之间**是否存在数据依赖。两个访问 $a[f(i)]$ 与 $a[g(i)]$（不同迭代 $i_1 < i_2$）若指向同一内存位置，就构成**循环携带依赖（loop-carried dependence）**。

```c
for (i = 1; i < n; i++)
    a[i] = a[i-1] * 2 + c[i];    // a[i] 依赖上一次迭代写的 a[i-1]
                                 // → 循环携带依赖，迭代间不能直接并行
```

**辨析｜易错点：** 判断并行性的关键不是「循环体内部有没有依赖」（那叫循环内依赖，向量化内部处理），而是**迭代之间**有没有依赖。**循环携带依赖**跨迭代 → 不能并行；**无依赖**各迭代独立 → 随便并行。

## 3 依赖距离：量化「隔了几次迭代」

**核心概念**：**依赖距离（dependence distance）**$d$：迭代 $i_1$ 与 $i_2$ 的间隔 $i_2 - i_1$。

$d = 1$：每次迭代依赖前一次 → 完全串行链。
$d \ge 2$：迭代 $i$ 只依赖 $i-d$ → **可以按 $d$ 个「流」并行**（每个流内部串行）。

```c
for (i = d; i < n; i++)
    a[i] = a[i-d] + b[i];        // 依赖距离 d = 2：i 只依赖 i-2
                                 // → 按 i mod 2 分成 2 组并行
```

**依赖距离分析**（GCD 测试等）是编译器的经典算法：判断两个下标表达式是否可能指向同一位置，以及距离是多少。

## 4 三类「伪依赖」：可以绕过的障碍

不是所有跨迭代依赖都不可并行：

**归约（reduction）**：**累加求和**（如 `sum += a[i]`）——所有迭代写同一个 **变量**。看起来是冲突，但加法可交换——**分块部分和再合并（树形归约）**就能并行。
**私有变量（privatization）**：**如 `tmp = a[i] * b[i]`**——每个迭代自己的临时变量。**给每个线程一份私有副本**即可并行。
**归纳变量（induction variable）**：**如循环计数器 `i`**——可以用公式直接算，不必串行累加。

**核心概念**：这三类「伪依赖」的共性：**冲突发生在「名字/累加」而不是「真实数据流」**——用归约树、私有化、公式化就能消解。<span class="marginnote">这与 [[register-renaming]] 的「名字相关可消除」是同一哲学：<strong>先分清「真数据流」与「名字/累加撞车」，后者都能绕</strong>。</span>

## 5 公式解析：依赖距离与可并行度

$$
\text{可并行流数} = d \quad（依赖距离为 $d$ 时）
$$

- **第一步，看 $d=0$**：迭代内依赖（非跨迭代）——向量化时可合并处理，迭代间仍并行。
- **第二步，看 $d \ge 1$**：跨迭代依赖。距离 $d$ 意味着 $i$ 只等 $i-d$——**可以把迭代按 `i mod d`（迭代号对 $d$ 取余）分成 $d$ 组，每组内部串行、组间并行**。
- **第三步，看归约**：$d$ 概念的补充——归约的「依赖」是累加冲突，用**树形并行**（每块算部分和，再合并）把深度从 $O(n)$ 压到 $O(\log n)$。**归约是可并行化的「伪依赖」**。

## 6 数值算例：依赖距离与可并行度

设循环有 $n = 1000$ 次迭代，不同依赖距离：

- **$d = 0$（无跨迭代依赖）**：1000 次迭代全独立 → **1000 路并行**（多核/SIMD/GPU 全通）。
- **$d = 1$**：每次依赖前一次 → **1 条串行链**，无法并行。
- **$d = 4$**：$i$ 只依赖 $i-4$ → 按 `i mod 4` 分成 **4 条链**，每条 250 次迭代，链间并行。

$$
\text{并行度} = d,\qquad d=4 \Rightarrow 4\,\text{路并行}
$$

**要点**：依赖距离直接决定并行度的天花板——**$d=1$ 的循环是并行编译器的大敌**，而 $d \ge 2$ 的循环可以按 $d$ 路并行。归约则是特例：依赖距离看似 1，但加法可交换，**树形归约把深度从 $O(n)$ 压到 $O(\log n)$**——这就是「伪依赖可绕过」的威力。

## 7 常见误区再辨析

- **「循环体无依赖就能并行」**：关键看**迭代之间**；循环携带依赖（`a[i]=a[i-1]*2`）让迭代串行，体内部再干净也没用。
- **「归约不能并行」**：累加可交换——分块部分和 + 树形合并即可并行；浮点累加有舍入差，但可接受。
- **「依赖分析只对向量化有用」**：多核并行、GPU 分块同样要它——**它是所有并行的总开关**。
- **「私有变量是多余的」**：每个迭代的 `tmp` 若共享会串行化；**每个线程/迭代一份副本**就是私有化，必要且标准。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 循环级并行 | 切分迭代空间并行执行 |
| 依赖分析 | 判断迭代间是否独立 |
| 循环携带依赖 | 跨迭代的数据依赖 |
| 依赖距离 d | 迭代间隔 |
| GCD 测试 | 判断下标是否可能同址 |
| 归约（reduction） | 可交换的累加冲突 |
| 私有化 | 每线程一份临时变量副本 |
| 归纳变量 | 可用公式直接计算的计数器 |

## 9 小结

- **循环级并行**是 TLP/DLP 的总开关，三种出口：多核、SIMD、GPU。
- **依赖分析**判断迭代间是否独立：$a[f(i)]$ 与 $a[g(i)]$ 跨迭代 = 串行。
- **依赖距离 $d$** 决定并行度：距离 $d$ → $d$ 条独立链。
- **归约、私有变量、归纳变量**是可绕过的「伪依赖」。
- 归约用**树形合并**并行化，私有变量用**副本**，归纳变量用**公式**。
