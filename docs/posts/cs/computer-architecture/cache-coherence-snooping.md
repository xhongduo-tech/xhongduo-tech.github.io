## 为什么多核会「看见不同的世界」

单核 Cache 只管快；多核把 Cache 变成**一致性问题**的温床。设想最简单的场景：两个核都缓存了变量 `X` 的副本（值都是 0）。核 0 执行 `X = X + 1`，只改了自己 Cache 里的副本——核 1 还在读自己的旧副本，读到 0。<span class="marginnote">这就是「<strong>缓存不一致</strong>」：同一个地址，两个核看到两个值。在共享内存模型（[[thread-level-parallelism-overview]]）里这是不可接受的——程序语义直接崩坏。</span>

## 1 一致性问题的正式定义

**核心概念**：**Cache 一致性（cache coherence）**要求满足两个性质：

1. **写传播（write propagation）**：任何处理器对某地址的写，最终必须被其他处理器看到。
2. **写串行化（write serialization）**：所有处理器对同一地址的写，必须以**相同的顺序**被观察到——否则「谁最后写」都说不清。

第二条是隐蔽的：两个核同时写 X，一个顺序 A 先 B、一个 B 先 A——虽然都是「先读后写」，但没有全局一致的次序，程序结果就不确定。**一致性管「每个写的传播与全局次序」，不管「读写之间的任意顺序」**——后者是 [[memory-consistency-sequential]]（一致性模型）的事。

**辨析｜易错点：** 一致性（coherence）与一致性模型（consistency）不是一回事。**Coherence 管「单个地址」**（写的传播与串行化）；**Consistency 管「多个地址间的顺序」**（比如先写 A 再写 B，别人该看到什么次序）。先分清这两个词，多核内存模型就入门了。

## 2 监听协议：总线就是扩音器

**核心概念**：**监听协议（snooping protocol）**：在总线式 SMP 上，**每个 Cache 控制器都监听总线上的一切事务**，一旦发现别人在读写某个块，就更新自己的状态。

写时（写失效协议）的动作：

1. 核 0 写 X：缓存自己的副本，同时在**总线**上广播「我要写 X 这个地址」。
2. 所有其他核的控制器**监听**到这条广播，发现自己也缓存了 X → **把自己的副本置为无效（invalidate）**。
3. 此后别的核再读 X → 缺失 → 从核 0 取新值。

**总线在这里扮演双重角色**：传输数据 + **串行化事件顺序**——总线仲裁保证「谁先广播谁先写」，一致性所需的「全局次序」由总线天然提供。

## 3 写失效 vs 写更新

监听协议有两个流派：

| 协议 | 别核的动作 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **写失效（write-invalidate）** | 收到写广播 → 使自己的副本无效 | 总线流量少（只发失效信号） | 后续读要重新取 |
| **写更新（write-update）** | 收到写广播 → 更新自己的副本 | 副本永远新鲜 | 总线流量大（每次写都要广播新值） |

现代系统**清一色用写失效**：写通常跟着多次读，失效一次、重取一次，比每次写都广播新值省得多——**又是「以大概率事件为快」**。<span class="marginnote">写失效的直觉：写是「一次性」的，读是「反复」的；<strong>失效让「一次写」只付「一次广播 + 一次重取」</strong>，而写更新让「每次写」都付「全量广播」。</span>

## 4 监听协议的局限

监听协议建立在「**总线广播**」之上，因此：

- **不可扩展**：核一多，总线变瓶颈——每条写都要广播给所有核，流量随核数增长。
- **集中式仲裁**：总线的串行化点限制了并行度。
- 正是这些局限，催生了**目录协议**（[[directory-based-coherence]]）——用「点对点」替代「广播」，把一致性带到上千核。

## 5 核心对比表：一致性 vs 监听机制的搭配

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 写失效 | 写更新 |
| --- | --- | --- |
| 广播内容 | 失效信号 | 新数据 |
| 总线流量 | 低 | 高 |
| 别核副本 | 置无效 | 更新为新值 |
| 适用 | 读写比高 | 读多写少极端场景 |
| 现代选择 | **默认** | 罕见 |

## 6 小结

- **一致性问题**：多核缓存同一地址，写必须传播、写必须全局串行化。
- **coherence（单地址的写秩序）≠ consistency（多地址的顺序）**——别混。
- **监听协议**靠总线广播让每个核「知道别人的写」，总线仲裁提供全局次序。
- **写失效**是默认选择：一次失效 + 一次重取，比写更新省流量。
- 监听不可扩展 → 大系统转向**目录协议**。
