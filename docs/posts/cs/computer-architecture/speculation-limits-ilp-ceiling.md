# 推测的限制与 ILP 的天花板研究

<div class="epigraph">

## 为什么研究「天花板」

前面十几节都在「加机制」：预测、乱序、推测、多发射。但有一条根本问题悬而未决：**就算把硬件做到无限好，一个程序里到底有多少 ILP 可挖？** 回答这个问题的是 1990 年代的 ILP 上限研究——它们用「完美的预测、无限的窗口、无限的寄存器」做理想化模拟，量出 ILP 的物理上限，也一举解释了「为什么后来大家转去做多核与 SIMD」。<span class="marginnote">这段研究直接决定了体系结构的历史走向：既然单核 ILP 挖不动了，[[single-core-to-multicore]]（TLP）与 [[data-level-parallelism-overview]]（DLP）才成为主流。先有天花板，后有转向。</span>

## 1 数据流极限：程序自带的上限

即使资源无限、分支预测完美，ILP 也受**数据流**约束：每条指令必须等它的所有源操作数就绪。程序的执行可以画成一张**数据依赖图**，图中最长的一条链（**关键路径**）决定了程序最快的执行时间。

**核心概念**：程序的理论最小执行时间等于**关键路径长度**（把串行依赖链压缩到极限），因此

$$\text{ILP 上界} = \frac{\text{总指令数}}{\text{关键路径长度}}$$

如果一个程序 100 条指令、关键路径 25 步，那么**无论硬件多豪华，最快也只能 4 条/周期**——因为那 25 步必须一步一步走。<span class="marginnote">这解释了为什么浮点程序通常比整数程序 ILP 高：浮点代码往往是大而规则的基本块，依赖链短、并行支路多；整数程序充满指针追踪、分支和顺序比较，关键路径长。</span>

## 2 窗口、寄存器与访存歧义

理想化研究之外，真实的限制清单更长：

**窗口大小（window）**：ROB/发射队列只能容纳有限条在途指令（典型 100–600）。窗口小了，跨窗口的并行就挖不到。
**寄存器数量**：重命名需要的物理寄存器数量随窗口线性增长，寄存器堆是面积大户，无法无限给。
**访存歧义（memory disambiguation）**：一条 `load` 是否与更早的 `store` 访问同一地址，硬件通常不知道——只能保守地把访存串起来或靠预测。**这是 ILP 挖到深处最难缠的限制**。<span class="marginnote">访存依赖比寄存器依赖难处理得多：寄存器名字看得见（译码就知），地址要等地址算出来才知道。现代处理器用「Store-to-Load 转发预测」来赌，赌错再回滚——访存推测是推测执行最后的堡垒。</span>
- **取指带宽**：前端每周期取的指令数有限，喂不饱窗口。
- **分支精度**：预测器再准也有 1–2% 错误率，每次错误都是整段冲刷。

## 3 实测天花板：数字说话

经典研究（Wall, 1991；后续 Sohi 等）用理想化模拟 SPEC 程序得到的结论大致是：

| 条件 | 整数程序 | 浮点程序 |
| --- | --- | --- |
| 完美分支、无限窗口、无限寄存器 | 10–50（数据流极限） | 75–150 |
| 有限窗口（如 64） | 5–8 | 10–20 |
| 加真实分支预测与访存限制 | 3–4 | 4–6 |

**注意最后一行的现实意义**：今天最豪华的乱序处理器（窗口数百、发射 8+）平均 IPC 也就在 **3–5** 之间——**与 30 年前研究预测的「现实天花板」几乎一致**。加宽发射、加大窗口带来的收益早已被真实程序的依赖耗尽。

## 4 还能榨多少：值预测与更聪明的推测

天花板之下还有几个「补丁」试图再挤出一点：

- **值预测（value prediction）**：不只预测分支方向，还**预测指令产生的数据值**。猜对了等于把关键路径的等待直接跳过——理论上能把依赖链剪短。但准确率难以做高、验证与回滚复杂，至今只在部分研究芯片中出现。
- **访存推测（memory dependence prediction）**：预测 LOAD 与哪个 STORE 转发，消除访存串行化。
- **多路径执行**：同时执行分支的两个方向，赌错无需冲刷——代价是执行资源翻倍。

这些技术的共性是：**边际收益递减、复杂度爆炸**。它们证明了一个更深的判断——ILP 的天花板不是硬件题，而是**程序数据流的题**。

**辨析｜易错点：** 值预测 ≠ 分支预测。分支预测猜「控制流方向」，值预测猜「数据值」。看到「处理器可以推测指令产生的数值」指向的是值预测，它比分支预测激进得多，也难得多。

## 5 公式解析：关键路径上的 ILP 上界

$$
\text{ILP} \le \frac{N}{D}, \qquad N = \text{总指令数},\ D = \text{数据依赖图的关键路径长度}
$$

- **第一步，看分子 $N$**：总指令数越大，并行潜力越大——大基本块、展开的循环、规则代码贡献分子。
- **第二步，看分母 $D$**：关键路径上的指令必须**依次**执行，是最短的串行核心。指针追逐、顺序链贡献分母。
- **第三步，理解极限**：$N$ 增长而 $D$ 不增长的代码（如向量化循环）ILP 上界无限高——但这正是 **DLP** 的领域；依赖链处处都是的代码 ILP 上界很低——只能靠 **TLP**（多核并行不同的任务）。**ILP 的尽头，是 DLP 与 TLP 的起点。**

## 6 数值算例：理想与现实的天花板账

取一个典型整数程序，三种硬件条件下的 IPC（参照第三节表格的量级）：

- **数据流极限**（无限窗口 + 完美分支 + 无限寄存器）：IPC ≈ 20——**硬件做到无限也就这样**。
- **有限窗口（64）+ 完美分支**：IPC ≈ 6——窗口砍掉了一大半并行。
- **有限窗口 + 真实分支 + 访存串行**：IPC ≈ 3.5——这就是今天的真实处理器水平。

$$
\frac{\text{数据流极限}}{\text{现实 IPC}} = \frac{20}{3.5} \approx 5.7
$$

**要点**：从「理想」到「现实」损失约 5.7 倍，其中**窗口与访存歧义**占了大头——这解释了现代处理器把预算花在「更大的窗口」与「更好的访存预测」上，也解释了为什么继续加预算，收益已经到顶。

这也是「天花板研究」最有价值的地方：它告诉你**钱该往哪花**——花在窗口与访存预测上，比盲目加宽发射更有意义。

## 7 常见误区再辨析

- **「加大窗口 = 无限接近数据流极限」**：窗口翻倍后，访存歧义与分支错误成为新瓶颈——**限制是「水桶效应」，最短板决定水位**。
- **「完美分支预测就能到极限」**：数据流极限还要求无限寄存器与无限访存并行，现实中根本做不到。
- **「值预测很快会商用」**：准确率难以做高、验证与回滚代价大，几十年过去了仍是研究热点而非量产功能。
- **「ILP 天花板意味着单核性能到头」**：只是「单核内挖 ILP」到头；单核仍可通过 SIMD、更高频率、更深缓存继续前进——天花板封的是「乱序窗口」这条路。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 数据流极限（dataflow limit） | 仅由数据依赖决定的理论 ILP 上界 |
| 关键路径 | 数据依赖图中最长的一串指令 |
| 访存歧义（memory disambiguation） | 判断 load 与先前 store 是否同址 |
| 值预测（value prediction） | 预测指令产生的数据值本身 |
| 多路径执行 | 同时执行分支的两个方向 |
| 窗口（window） | 乱序引擎在途指令的数量上限 |
| Store-to-Load 转发预测 | 预测 load 从哪个 store 拿值 |
| 基本块（basic block） | 无分支、顺序执行的一段指令 |
| 依赖链（dependency chain） | 数据依赖串成的最长执行链 |
| 回滚（rollback） | 推测失败后恢复正确状态的过程 |

## 9 小结

- **数据流极限**：ILP 上界 = 总指令数 ÷ 关键路径长度，程序自带、硬件无法改变。
- 现实限制：**窗口、寄存器、访存歧义、取指带宽、分支精度**五重约束。
- 实测天花板：整数 IPC 3–4、浮点 4–6，**加宽发射收益早已耗尽**。
- 值预测、访存推测、多路径执行都是天花板边缘的补丁，复杂度高、收益递减。
- 结论：ILP 榨干了 → 转向 DLP（SIMD/GPU）与 TLP（多核），这是现代体系结构的分水岭。
