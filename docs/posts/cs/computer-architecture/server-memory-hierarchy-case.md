## 为什么用一台服务器收束第四篇

前面 16 节把存储层次的每个部件拆开讲过。现在把它们**装回一台真实的服务器**，看整棵层次树如何咬合、真实延迟到底是多少、多路服务器又添了什么新问题。<span class="marginnote">这台「典型服务器」的配置不必精确对应某一代产品（Intel Xeon / AMD EPYC 各有差异），但<strong>数量级与结构是稳定的</strong>——理解结构比背型号数字更重要。这也是 [[intel-core-arm-cortex-microrch]] 之后第二次「实例剖析」。</span>

## 1 一台现代服务器里有什么

| 层 | 典型容量 | 典型延迟 | 组织 |
| --- | --- | --- | --- |
| 寄存器 | KB 级 | < 1 ns | 每核私有 |
| L1 指令/数据 | 各 32–48 KB | ~1 ns（约 4 周期） | 每核私有，VIPT |
| L2 | 1–2 MB | ~4 ns（约 14 周期） | 每核私有 |
| L3 | 32–64 MB | ~12–20 ns | 多核共享 |
| DRAM（DDR4/5） | 数十–数百 GB | ~80–100 ns | 多通道 |
| NVMe SSD | 数百 GB–数 TB | ~10–100 μs | 走 PCIe |
| HDD | TB 级 | ~5–10 ms | 走 SAS/SATA |

**核心概念**：每一层比上一层大 **4–8 倍**、慢 **3–10 倍**——这是存储层次设计的经验法则：**容量比与延迟比匹配，任何一层「太跳」都会失衡**。

## 2 延迟阶梯：从寄存器到磁盘

把数字画成阶梯，跨度一目了然：

```text
延迟阶梯（数量级示意）：

寄存器     < 1 ns     ────────────────────────  最快
L1         ~1 ns      ×1
L2         ~4 ns      ×4
L3         ~15 ns     ×15
DRAM       ~90 ns     ×90
NVMe SSD   ~30 μs     ×30,000    ← 300 倍跳变，最宽鸿沟
HDD        ~5 ms      ×5,000,000
```

**从 L1 到磁盘差约 8 个数量级**。存储层次的全部意义，就是让绝大多数访问停在最左边几层——**命中率每提升一个数量级，平均访问时间都跟着掉一个数量级**。<span class="marginnote">注意 DRAM→NVMe 的「300 倍跳跃」：这是存储层次里最宽的鸿沟，也是 [[flash-emerging-nvm]] 的 SCM 想要填的坑——<strong>把它填到 10 倍左右，整个层次就「平」了</strong>。</span>

## 3 各层如何咬合：一次访存的旅程

一次**访存（读）**的完整旅程（假设全部缺失）：

1. 地址 **翻译**：查 TLB（L1 TLB 缺失 → L2 TLB → 页表遍历）。
2. **L1 缺失**：去 L2，同时**预取器**观察模式、发起预取。
3. **L2 缺失**：去 L3（共享，还要查**一致性协议**——其他核有没有这份数据）。
4. **L3 缺失**：请求进入**内存控制器**，按 bank 调度、行缓冲命中与否决定快慢。
5. **DRAM 返回**：按 MSHR 把数据广播给等它的所有访问，**关键字优先**送到处理器。
6. 若连 DRAM 都没有（缺页）→ 陷入内核，从 **NVMe** 取页。

**每一层都有独立的优化机制在跑**：TLB 预取、Cache 预取、调度器重排、一致性广播——这就是为什么优化是「全系统」的事。

## 4 NUMA：多路服务器的非均匀内存

多路（multi-socket）服务器里，每个 CPU 的 DRAM **离自己近、离别的 CPU 远**——访问远端内存要跨互连（如 Intel UPI、AMD Infinity Fabric），延迟高 1.5–2 倍。这就是 **NUMA（Non-Uniform Memory Access）**。

- 本地访问：~90 ns；远端访问：~150–180 ns。
- **NUMA 感知编程**：把内存分配在**正在执行的核所属的 socket**（first-touch 本地分配），避免跨 NUMA 访问。
- **NUMA 失衡**：共享数据被反复跨节点读写，性能可差 20–50%。

**辨析｜易错点：** NUMA 不是「设计缺陷」，而是**扩展的自然代价**——统一内存（UMA）在多路规模下带宽不够。接受「非均匀」，换来的是一台机器能插几百 GB 甚至 TB 内存。

## 5 核心对比表：本地 vs 远端

> 本节为纯概念主题，以核心对比表替代公式解析。

| 访问 | 位置 | 延迟 | 带宽 |
| --- | --- | --- | --- |
| L1 | 核内 | ~1 ns | 极高 |
| L3 | 片内共享 | ~15 ns | 高 |
| DRAM（本地） | 本 socket | ~90 ns | 中 |
| DRAM（远端） | 他 socket | ~170 ns | 低 |
| NVMe | 经 PCIe | ~30 μs | 中 |

## 6 数值算例：一次典型的层次账

设 $T_{L1}=1$、$M_{L1}=10\%$、$T_{L2}=4$、$M_{L2}=5\%$、$T_{L3}=15$、$M_{L3}=2\%$、$T_{\text{mem}}=90$ ns：

$$
\text{AMAT} = 1 + 0.1 \times (4 + 0.05 \times (15 + 0.02 \times 90)) = 1 + 0.1 \times 4.84 = 1.48\,\text{ns}
$$

- **如果不分层**：全部访问 DRAM → 平均 **90 ns**。
- **分层的效果**：平均 **1.48 ns**——**快约 60 倍**。

**要点**：这台「典型服务器」用 90% 的 L1 命中 + 逐层吸收，把平均访存从 90 ns 压到 1.5 ns。**层次的每一级都在「兜底」上一级的缺失**——这正是存储层次存在、且每一层优化都值得做的数学理由。

## 7 常见误区再辨析

- **「服务器只看 CPU 型号」**：现代服务器性能九成由存储层次决定——**NUMA、缓存、内存通道比核数更影响真实吞吐**。
- **「NUMA 是缺陷」**：是**扩展的自然代价**——统一内存（UMA）在多路规模下带宽不够；接受非均匀换容量。
- **「分层只对命中敏感负载重要」**：流式负载也要预取与带宽；随机负载更要命中率——**所有负载都吃层次**，只是吃的部分不同。
- **「远端内存只是慢一点」**：跨 NUMA 延迟高 1.5–2 倍、带宽更低，失衡可差 20–50%——**内存亲核是必须的软件优化**。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 延迟阶梯 | 各级延迟的数量级差 |
| AMAT | 平均访存时间 |
| NUMA | 非一致内存访问 |
| UMA | 统一内存访问 |
| 内存亲核 | 数据就近分配（first-touch） |
| 多路服务器 | 多 CPU socket |
| VIPT | 虚拟索引物理标签 |

## 9 小结

- 现代服务器层次：**寄存器 → L1 → L2 → L3 → DRAM → NVMe/HDD**，容量与延迟按 3–10 倍阶梯递进。
- **延迟阶梯跨 8 个数量级**，层次的使命是让大多数访问停在快端。
- 一次访存经过：**翻译（TLB）→ 各级缺失 → 内存调度 → 关键字优先返回**，各层机制独立咬合。
- **NUMA** 让远端内存更慢，多路服务器要靠软件「内存亲核」缓解。
- 存储层次是「全系统优化」：单独优化任何一层都不够，要看整棵树的咬合。

至此，第四篇「存储层次深入」全部收束。下一组进入**第五篇：线程级并行**——从多处理器体系结构概述开始。

而第四篇留给你一句话：**存储层次不是「一层层的缓存」，而是一个「由局部性驱动的、层层兜底的系统」**——它决定了一台机器的真实性能天花板，比任何单点优化都更根本。
