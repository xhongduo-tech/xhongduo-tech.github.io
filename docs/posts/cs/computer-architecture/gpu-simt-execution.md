## 为什么 GPU 不叫 SIMD

GPU 的线程像 SIMD 一样「同指令、多数据」，但实现方式完全不同：**SIMD 是「一条指令操作寄存器的多个槽位」，GPU 是「一批真正的线程，各自有寄存器与 PC，锁步执行同一条指令」**。NVIDIA 把这个模型命名为 **SIMT（Single Instruction, Multiple Thread）**。<span class="marginnote">关键区别：SIMD 的「线程」是硬件寄存器槽位，没有独立性；SIMT 的「线程」是真正的软件线程——<strong>可以各自分支（靠掩码）、各自有私有寄存器、可以独立地等待访存</strong>。这让 GPU 编程比 SIMD 更灵活。</span>

## 1 Warp：线程束作为调度单位

**核心概念**：**warp（线程束）**：NVIDIA 把 **32 个线程**绑成一个调度单位。一个 warp 里的 32 个线程**同时执行同一条指令**（锁步），由 SM 的**warp 调度器**统一取指、统一发射。

```text
线程 0   线程 1   线程 2  …  线程 31
  │        │        │          │
  └────────┴────────┴────┬─────┘
                         │ 锁步执行同一条指令（统一取指/发射）
                         ▼
                  warp 调度器（一次调度一个 warp）
```

AMD 的对应物叫 **wavefront**（64 线程）。**warp 是 GPU 的「指令级并行单位」**——GPU 的 IPC 用「每周期发几条 warp 指令」衡量。

## 2 锁步与「伪独立」

同一个 warp 的线程**锁步**：它们在同一条指令上同进同退。但每个线程又有**私有的寄存器与 PC**——所以它们不是 SIMD 槽位，而是真正的线程：

- **私有寄存器**：32 个线程各自有完整的寄存器文件空间——数据完全隔离。
- **独立访存**：一条 Load/Store 指令让 32 个线程各访存自己的地址（可以 gather 任意地址）。
- **分支**：遇到分支，用**掩码**让「该走 A 的走 A、该走 B 的走 B」，但执行时是「先让 A 部分跑、再让 B 部分跑」（见 [[gpu-branch-divergence]]）。

**辨析｜易错点：** 一个 warp 的线程**不是并行独立执行**的——它们被调度器当作**一个整体**推进。真正「并行」的是**多个 warp 之间**（SM 有多个调度器、多个 warp 同时驻留）。「线程并行」的正确理解是「warp 并行 + warp 内锁步」。

## 3 多 warp 驻留：GPU 的延迟隐藏引擎

GPU 不做乱序、不做深流水——它靠**大量驻留的 warp** 来隐藏延迟：

```text
时间 →

warp A：计算 ██  等待访存 ████████  计算 ██
warp B：        计算 ██████  等待 ███  计算 ████
warp C：            计算 ████████  等待 ██  计算
                  ↑ 调度器在 warp 等待时切换
→ 访存延迟被其他 warp 的运算掩盖
```

**核心概念**：当 warp A 在等内存时，调度器切到 warp B——**访存延迟被其他 warp 的运算完全掩盖**。这就是 [[gpu-architecture-overview]] 里「延迟隐藏」的具体机制：**不需要乱序硬件，只需要足够的「备胎 warp」**。

## 4 占用率（Occupancy）

**核心概念**：**占用率（occupancy）** = 驻留 warp 数 ÷ 最大可驻留 warp 数。占用率高 → 备胎多 → 延迟隐藏好。

限制占用率的资源：

- **寄存器**：每个 SM 寄存器堆有限，线程用太多寄存器 → 驻留 warp 数下降。
- **共享内存**：每个块要的共享内存过多 → 同时驻留的块变少。
- **块大小**：块太小浪费「半满」的 warp 槽位。

**辨析｜易错点：** 占用率**不是越高越好**。占用率 100% 但线程都在算同一个 ALU（无停顿），反而没意义；高占用率只在「有停顿要隐藏」时值钱。**优化目标不是最高占用率，而是「足够的备胎」**——经验上 50%+ 通常就够。

## 5 核心对比表：SIMT 与 SIMD 的机制差异

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | SIMD（CPU） | SIMT（GPU） |
| --- | --- | --- |
| 执行单位 | 寄存器槽位 | 真线程（warp 锁步） |
| 每个「通道」的状态 | 无（共享寄存器语义） | **私有寄存器 + PC** |
| 分支 | 需 mask/select | 掩码执行（[[gpu-branch-divergence]]） |
| 访存 | 连续为主 | 任意地址（gather） |
| 调度单位 | 指令 | **warp** |
| 隐藏延迟 | 乱序/流水 | **多 warp 切换** |

## 6 数值算例：需要多少「备胎」才藏得住

设访存延迟 400 周期、每个 warp 两次访存间约有 16 周期计算：

- **要完全隐藏**：至少需要 $400 / 16 = 25$ 个驻留 warp，才能让「一个在等、总有别的在算」。
- **只有 8 个**：等待时无 warp 可切——**利用率约 8/25 = 32%**，延迟无法隐藏。
- **64 个**：绰绰有余，但寄存器与共享内存被占满，占用率反而被资源限制。

$$
\text{所需 warp} \approx \frac{\text{访存延迟}}{\text{每 warp 计算量}}
$$

**要点**：备胎数量要**匹配访存延迟与计算量的比值**——太少藏不住、太多挤资源。GPU 设计者用「占用率」和「每线程资源预算」调这个平衡：**目标不是越多越好，而是刚好够遮住延迟**。

## 7 常见误区再辨析

- **「GPU 靠乱序隐藏延迟」**：GPU 不做乱序、不做深流水——它靠**大量驻留 warp 的切换**，这是完全不同（且便宜）的路线。
- **「warp 内线程并行独立」**：warp 内线程**锁步**同一条指令；真正并行的是**多个 warp**之间。
- **「占用率越高越好」**：占用率 100% 但都在算同一 ALU（无停顿）没意义；**「足够的备胎」**才是目标，50%+ 通常够。
- **「warp 大小越大越好」**：32 线程的 warp 让分歧代价可控；64（wavefront）分歧更贵——**宽度是权衡**。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| SIMT | 单指令多线程 |
| warp | 32 线程的锁步调度单位 |
| wavefront | AMD 的 64 线程对应物 |
| 锁步 | warp 内同指令同进退 |
| 私有寄存器 | 每线程独立的寄存器空间 |
| 占用率 | 驻留 warp ÷ 最大可驻留 |
| 延迟隐藏 | 用别的 warp 掩盖等待 |

## 9 小结

- **SIMT**：真正的线程锁步执行同一条指令，兼有 SIMD 的效率与线程的灵活。
- **warp** = 32 线程的调度单位（AMD wavefront=64），SM 每周期调度一个就绪 warp。
- warp 内线程有**私有寄存器与 PC**，可独立访存、可掩码分支。
- **多 warp 驻留**是 GPU 的延迟隐藏引擎：一个等内存、另一个干活。
- **占用率** = 驻留 warp 比例，决定「备胎够不够」；不是越高越好。

在下一节，我们细看 warp 遇到分支时怎么办——**GPU 分支分歧（Divergence）与掩码执行**。SIMT 的「锁步」在遇到分支时暴露软肋——同一 warp 里的线程走了不同路径，只能靠掩码让它们轮流走完。
