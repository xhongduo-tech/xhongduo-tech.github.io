## 为什么向量机值得重新认识

1976 年的 Cray-1 用**向量指令**统治了超算界：一条指令对整个数组做运算。三十年后的今天，向量思想以 **RISC-V V 扩展、ARM SVE** 的形式复活——因为它解决了一个 SIMD 至今没解决好的问题：**代码能不能不绑定具体的硬件向量宽度**。<span class="marginnote">这就是本节的中心词——<strong>向量长度无关（vector-length agnostic）</strong>编程模型：你写一次循环，硬件多宽它自己适配。这条特性把向量与 [[simd-instruction-evolution]] 的固定宽度 SIMD 划开了界限。</span>

## 1 向量机的基本盘：寄存器 + 深度流水

**核心概念**：**向量体系结构（vector architecture）**的核心是一组**向量寄存器**（如 64 个、每个 64 位 × 64 个元素）与**深度流水的向量功能单元**。一条向量加指令（如 Cray 的 `VADD`）让功能单元对两个向量寄存器的**所有元素**做加法，一个元素接一个元素地流过流水线——**一条指令 = 一整串运算**。

与标量机对比，向量指令省掉的不只是循环开销：

**无取指/译码/循环分支开销**：整段循环体被一条向量指令取代。
**深度流水吃饱**：向量单元把每个元素的操作流水化，吞吐极高。
**访存效率高**：向量装载指令 `VLOAD` 可以一次搬大量数据，充分利用带宽（Cray 用流水化访存 + 通道）。

## 2 向量长度无关：VL 寄存器与 strip-mining

向量寄存器的**物理宽度（$\text{VLEN}$，元素个数）由硬件决定**——不同芯片不同。软件要写的代码却必须「一套代码处处跑」。RISC-V 的解法：

每个向量指令的执行长度由 **VL（向量长度寄存器）** 在运行时指定，硬件可以截断到它支持的最大长度。
软件用 **strip-mining（条带开采）** 把大循环切成每块不超过硬件支持长度的若干段。

```c
// strip-mining：把 n 个元素切成「n/VL 块 + 1 个余数块」
for (i = 0; i < n; i += VL) {
    vl = min(VL, n - i);           // 最后一块可能不满
    向量执行 a[i .. i+vl-1] = ...; // 长度由运行时 VL 决定
}
```

**核心概念**：**strip-mining** 把「处理 $n$ 个元素」切成「$n / \text{VL}$ 块 + 1 个余数块」的循环；每块的向量长度由硬件在运行时给出。**代码只依赖「有一个 VL」，不依赖 VL 具体多大**——这就是长度无关的含义。

**辨析｜易错点：** 「向量长度寄存器（VL）」与「向量寄存器宽度」不是一回事。**VL 是「这次执行多长」的运行时可变量，寄存器宽度是「硬件最多支持多长」的常数**。前者让代码可移植，后者决定单条指令的吞吐上限。

## 3 经典例子：DAXPY

教材经典的 DAXPY（$Y = aX + Y$）向量版：

```asm
VLOAD   V1, X_addr    ; 装载 X 向量
VMULVS  V2, V1, F0    ; V2 = a · V1（标量 a 在浮点寄存器 F0）
VLOAD   V3, Y_addr    ; 装载 Y 向量
VADD    V4, V2, V3    ; V4 = V2 + V3 = aX + Y
VSTORE  V4, Y_addr    ; 存回 Y
```

四条向量指令替代了整个循环体——没有循环计数、没有分支、没有地址递增。<span class="marginnote">注意 MULVS 是「向量 × 标量」：标量值从浮点寄存器 F0 来。向量指令天然支持「一个标量与整个向量运算」这种并行模式，这也是向量代码简洁的来源。</span>

## 4 向量指令的多样性：不只是连续数组

向量体系结构把访存模式也向量化：

| 访存模式 | 指令 | 适用场景 |
| --- | --- | --- |
| 连续 | `VLOAD`/`VSTORE` | 稠密数组 |
| 固定步长 | `VLDS`/`VSTS` | 矩阵行/列、结构体字段 |
| 收集/散播 | `VGATHER`/`VSCATTER`（gather/scatter） | 稀疏数据、索引数组 |

`VGATHER`（索引装载）用另一个向量寄存器装**地址**，逐个取元素——把「乱序访存」也向量化，是稀疏计算的关键。

## 5 公式解析：strip-mining 的块数

$$
K = \left\lceil \frac{n}{\text{VL}} \right\rceil
$$

- **第一步，看 $n$**：总元素个数。
- **第二步，看 $\text{VL}$**：硬件支持的最大向量长度（运行时可查）。
- **第三步，取整**：块数 $K = \lceil n/\text{VL} \rceil$，前 $K-1$ 块满长、最后一块可能不满（余数）。**同样的代码，在不同硬件上 $K$ 自动变化**——这就是长度无关编程模型的全部量化含义。

## 6 数值算例：同样的代码，K 随硬件变

设处理 $n = 10000$ 个元素，同一段 strip-mined 代码：

- **硬件 VL = 256**：$K = \lceil 10000/256 \rceil = 40$ 块（39 块满 256 + 1 块余 16）。
- **硬件 VL = 1024**：$K = \lceil 10000/1024 \rceil = 10$ 块（9 块满 + 1 块余 784）。

$$
K = \left\lceil \frac{n}{\text{VL}} \right\rceil
$$

**要点**：**代码一个字都不改**，硬件越宽、块数自动越少——这就是「长度无关」的量化含义。程序员写一次，编译器与硬件在每种机器上各自算好 K。这也是向量模型对「宽度写死、换硬件要重编译」的 SIMD 的杀手锏。

## 7 常见误区再辨析

- **「VL 就是寄存器宽度」**：VL 是「这次执行多长」的**运行时变量**；寄存器宽度是「硬件上限」的常数——两个概念。
- **「向量只适合超算」**：RVV/SVE 正在进移动端、服务器——**长度无关让任何新 ISA 都能低成本拥抱向量**。
- **「向量代码会自动快」**：长度无关保证**可移植**，不保证**最优**——带宽受限时照样慢，仍需访存优化。
- **「向量取代标量」**：控制流、标量操作仍要标量核；向量是**加速数据并行段的引擎**，与标量共存。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 向量寄存器 | 存多个元素、硬件定宽的寄存器 |
| VL | 向量长度寄存器，运行时定 |
| VLEN | 硬件支持的向量宽度上限 |
| strip-mining | 把大循环切成 VL 块 |
| 长度无关 | 代码不绑定硬件宽度 |
| gather/scatter | 按索引收集/散开元素 |
| DAXPY | Y = aX + Y 的经典向量例 |

## 9 小结

- **向量体系结构** = 向量寄存器 + 深度流水向量单元，一条指令处理整个数组。
- 核心优势：省循环开销、流水吃满、访存高效。
- **向量长度无关**：代码只依赖运行时 VL，不依赖硬件宽度；strip-mining 适配任意长度。
- 访存模式向量化：连续、步长、gather/scatter 全覆盖。
- VL（执行长度）与 VLen（硬件宽度）是两个不同的概念，别混淆。
- 向量模型是 SIMD 的「可移植版」，为 [[riscv-vector-extension]] 铺路。

在下一节，我们把长度无关模型落地到 RISC-V——**RISC-V 向量扩展（RVV）：配置指令与掩码操作**。抽象讲清了「VL 与 strip-mining」，RVV 则给出具体指令：怎么设 VL、怎么用掩码处理条件与尾元素。
