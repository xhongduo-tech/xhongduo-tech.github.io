## 为什么盯住编码

指令集是「软件与硬件的合同」，而合同逐字写在**指令编码**里：每个 bit 归谁管、立即数怎么拼、寄存器号放哪。RISC-V 把「解码简单」当作第一优先——**所有格式中，寄存器字段的位置永远相同**，译码器几乎不用移位就能抽出 rs1/rs2/rd。<span class="marginnote">对比 [[risc-design-philosophy]] 的第三条原则「固定规整格式」：RISC-V 把这原则推到极致，连立即数的 bit 位置都刻意「打乱」以统一符号位。理解编码，才算真正理解 RISC-V 的魂。</span>

## 1 RV32I 的指令家族

RV32I（整数基础集）按功能分六类：

| 类型 | 格式 | 指令举例 | 作用 |
| --- | --- | --- | --- |
| 算术-逻辑 | R / I | ADD、SUB、AND、OR、XOR、SLT、SLTU、ADDI、ANDI | 寄存器/立即数运算 |
| 装载/存储 | I / S | LW、SW | 访存（load-store） |
| 分支 | B | BEQ、BNE、BLT、BGE | 条件跳转 |
| 跳转 | U / J | JAL、JALR | 无条件跳转 |
| 上位立即数 | U | LUI、AUIPC | 构造 32 位常数 |
| 系统 | I | ECALL、EBREAK、FENCE | 陷阱与同步 |

**核心概念**：RV32I 只含**整数运算**（不含乘除，那是 M 扩展）。它的每条指令都是**定长 32 位**，六种格式的字段位置高度统一——这是「解码快」的全部秘密。

## 2 六种指令格式

RISC-V 只用六种基本格式，每种格式的字段布局如下（`funct7`、`funct3` 是扩展操作码）：

| 格式 | 布局（从高到低 31→0） |
| --- | --- |
| **R** | funct7(7) \| rs2(5) \| rs1(5) \| funct3(3) \| rd(5) \| opcode(7) |
| **I** | imm\[11:0\](12) \| rs1(5) \| funct3(3) \| rd(5) \| opcode(7) |
| **S** | imm\[11:5\](7) \| rs2(5) \| rs1(5) \| funct3(3) \| imm\[4:0\](5) \| opcode(7) |
| **B** | imm\[12\|10:5\](7) \| rs2(5) \| rs1(5) \| funct3(3) \| imm\[4:1\|11\](5) \| opcode(7) |
| **U** | imm\[31:12\](20) \| rd(5) \| opcode(7) |
| **J** | imm\[20\|10:1\|11\|19:12\](20) \| rd(5) \| opcode(7) |

**注意观察**：在 R、I、S、B 四种格式里，`rs1` 永远占据 bits[19:15]、`rd` 永远占 bits[11:7]、`funct3` 永远占 bits[14:12]。译码器读出这三个字段**不需要知道格式**——乱序执行需要同时读多个指令的寄存器号时，这简直是恩赐。

## 3 立即数编码的怪癖

立即数的 bit 布局刻意「不合理」，目的却极合理：**立即数的第 31 位永远是符号位**，译码器可以无脑符号扩展，不管哪条指令。

**I 型**：`imm[11:0]` 直接平铺，12 位有符号。
**S 型**：`imm[11:5] | imm[4:0]` 分居两端——把 S 与 B 格式的立即数**错位共享**。
**B 型**：`imm[12|10:5] | imm[4:1|11]`——最低位固定 0（分支目标按 2 字节对齐），13 位有符号。
**U 型**：`imm[31:12]` 左移 12——高 20 位左移 12。
**J 型**：`imm[20|10:1|11|19:12]`，21 位有符号（最低位隐藏 0）。

**辨析｜易错点：** B 型和 J 型的立即数**最低位是隐藏的 0**（2 字节对齐），所以编码里没有 `bit0`。看到分支与 `jal` 的目标地址都是偶数，别惊讶——这是刻意为之，配合 [[riscv-compressed-instructions]] 的 16 位对齐。

## 4 语义要点：比较、分支与跳转

几个容易记混的语义：

**`slt`**：`rs1 < rs2` 时置 1，带符号比较；`sltu` 是无符号版。比较不跳转，先把结果放寄存器——这是 RISC 把「条件」拆成指令的风格。
**分支比较两操作数**：`beq`/`bne` 比较 `rs1` 与 `rs2`——**不是**「与 0 比较」。想与 0 比，先 `addi rd, x0, 0` / `sub rd, rd, rd` 造出一个 0。
**`jal`**：跳转并把**下一条指令地址**存入 `rd`（常为 `x1`/`ra`）；**`jalr`** 跳转到寄存器目标，是返回（RET = `jalr x0, 0(x1)`）与间接调用的基础。<span class="marginnote">`jal`/`jalr` 的返回地址语义配合 [[branch-target-buffer-ras]] 的 RAS 正好闭环：CALL 用 `jal` 压栈返回地址，RET 用 `jalr` 弹栈跳回。</span>

## 5 编码实例解析：一条 ADD 的完整旅程

以 `add x5, x6, x7` 为例，逐步拼出它的 32 位机器码：

| 字段 | 值 | 二进制 |
| --- | --- | --- |
| opcode | 0110011（OP） | bits[6:0] = 0110011 |
| rd | x5 | bits[11:7] = 00101 |
| funct3 | 000（ADD/SUB） | bits[14:12] = 000 |
| rs1 | x6 | bits[19:15] = 00110 |
| rs2 | x7 | bits[24:20] = 00111 |
| funct7 | 0000000（ADD） | bits[31:25] = 0000000 |

拼起来：`add x5, x6, x7` = **`0000000 00111 00110 000 00101 0110011`**。

- **第一步，认 opcode**：`0x33`（0110011）表示这是 OP（寄存器-寄存器整数运算）类。
- **第二步，认 funct**：`funct3`(000) + `funct7`(0000000) 共同确定是 `add`（若 funct7=0100000 则是 `sub`）。
- **第三步，读寄存器**：`rs1`（x6）、`rs2`（x7）、`rd`（x5）——字段位置固定，一次读出，无需移位。

## 6 构造 32 位常数：两条指令的编码

RISC-V 的单条立即数指令只有 20 位（U 型），构造任意 32 位常数要两条：

```asm
li    rd, X                 # 伪指令：把任意 32 位常数装入 rd
# 汇编器展开为两条真实指令：
lui   rd, (X >> 12)         # U 型：高 20 位，左移 12 进寄存器
addi  rd, rd, X & 0xFFF     # I 型：低 12 位，符号扩展
```

**辨析｜易错点：** `addi` 的 12 位立即数是**符号扩展**的——若低 12 位的符号位为 1，会「多减 1」：构造 32 位常数时，`lui` 的立即数要先 +1，再用 `addi` 的低 12 位补偿。这正是汇编器处理 `li` 伪指令时最易错的细节。**「拼常数」这种看似琐碎的事，正是编码里符号扩展语义的实战检验**。

## 7 小结

- RV32I 分六类指令，**定长 32 位**，六种格式（R/I/S/B/U/J）。
- **寄存器字段位置跨格式固定**（rs1 恒在 [19:15] 等），是解码极快的根源。
- 立即数布局刻意「打乱」：**符号位恒在 bit31**，译码无脑符号扩展；B/J 最低位隐藏 0。
- `slt` 把比较放进寄存器；分支比较两个操作数；`jal`/`jalr` 管理返回地址。
- 一条 `add` = `funct7 | rs2 | rs1 | funct3 | rd | opcode`，六字段一拼即成。
