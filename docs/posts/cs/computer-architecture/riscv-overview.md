## 为什么 RISC-V 值得单开一组

ARM 和 x86 的指令集都握在商业公司手里：要么交授权费、要么看它脸色。2010 年，加州大学伯克利分校的 Krste Asanović 团队发起 RISC-V——**一个开放、免费、模块化、可扩展的指令集**，把指令集从「商业许可」变成「公共标准」。到今天，RISC-V 已从学术玩具成长为芯片产业的第三条路线。<span class="marginnote">RISC-V 完美继承了 [[risc-design-philosophy]] 的哲学，并走得更远：它把「精简」推进到「<strong>基础集极简 + 扩展自由拼装</strong>」，让教学、嵌入式、高性能各自取用。</span>

## 1 模块化设计：最小内核 + 可选扩展

RISC-V 的第一设计原则是**模块化（modular）**：

**基础整数指令集（Base ISA）**：RV32I（32 位地址/寄存器）、RV64I（64 位）、RV128I（128 位，试验）。**I 是唯一必须存在的基础**，包含整数算术逻辑、分支、装载/存储、系统指令。
**标准扩展（standard extensions）**：按需加装：

| 扩展 | 含义 | 内容 |
| --- | --- | --- |
| M | 整数乘除 | MUL、DIV、REM |
| A | 原子操作 | LR（load-reserved）、SC（store-conditional）（第五篇同步的基础） |
| F | 单精度浮点 | 32 个浮点寄存器 + 浮点指令 |
| D | 双精度浮点 | RV64 上常用 |
| C | 压缩指令 | 16 位指令，代码密度 |
| V | 向量 | 定长/变长向量（[[riscv-vector-extension]]） |

**核心概念**：一个 RISC-V 处理器只需实现 RV32I，就能跑所有基本程序；需要乘除加 M、需要原子加 A。**扩展是正交的、可选的**——这让学生在 FPGA 上做一个「能跑全部 RV32I」的核成为可能，也让工业界按需裁剪。

## 2 命名规则：RV64IMAFDC 怎么读

配置名 = RV + 位数 + 基础 + 扩展字母（按字母序）。例如：

RV32I：32 位整数基础，最小可运行集。
RV32IMAC：整数 + 乘除 + 原子 + 压缩（典型的嵌入式/微控制器组合）。
RV64IMAFDC：64 位 + 乘除 + 原子 + 单/双精度浮点 + 压缩——**写作 RV64GC**（G = General，即 IMAFD 的组合）。<span class="marginnote">「RV64GC」里的 G 是「general-purpose」的缩写，等于 IMAFDC 五个扩展的打包记号。看到「RV64GC」就知道这是一台功能完整的 64 位 RISC-V，接近 ARM 的通用配置。</span>

**辨析｜易错点：** 扩展字母**必须按字母序排列**（如 RV32IMAC 不能写成 RV32IMCA），且 F 是 D 的前提（双精度需要单精度支持）。这是规范硬性规定的，考试与配置书写都要注意。

## 3 通用寄存器与 ABI 约定

RV32I/RV64I 提供 **32 个通用寄存器** x0–x31，其中 **x0 恒为 0**（写入忽略、读出为 0）——这是 RISC-V 的招牌设计，用它把「零寄存器」和「比较后丢弃结果」都表达成普通指令。软件层面再按 **ABI（应用二进制接口）**约定分工：

| 寄存器 | ABI 名 | 用途 |
| --- | --- | --- |
| x0 | zero | 恒 0 |
| x1 | ra | 返回地址（配合 [[branch-target-buffer-ras]] 的 RAS） |
| x2 | sp | 栈指针 |
| x8/x9 | s0/s1 | 保存寄存器（被调用者保护） |
| x10–x17 | a0–a7 | 参数/返回值 |
| x5–x7, x28–x31 | t0–t6 | 临时寄存器 |

**辨析｜易错点：** ABI 名（`sp`、`a0`）**不是硬件规定**，是软件调用约定的分工；硬件只认 `x` 编号（x2、x10）。`x0` 恒零才是硬件特性——区别要分清。

## 4 与 ARM 的对比：开源 vs 授权

RISC-V 与 ARM 在「开放度」上是天壤之别，这决定了它的生态形态：

| 维度 | RISC-V | ARM |
| --- | --- | --- |
| 授权模式 | 开源免费（可自由实现） | 商业授权（IP 许可费） |
| 可修改 | 允许自定义扩展 | 通常不允许/需协商 |
| 生态成熟度 | 快速增长中 | 极成熟 |
| 典型用途 | 教学、MCU、新兴 SoC、AI 加速器 | 手机/服务器主导 |
| 指令集稳定性 | 规范版本管理、向后兼容 | 商业主导 |

RISC-V 的**可扩展性**是其杀招：芯片厂商可以加**自定义扩展**（如 AI 指令），不必等上游批准——这正是它在 [[riscv-ecosystem]] 里重塑产业格局的底气。<span class="marginnote">开放不等于「乱」：RISC-V 有正式规范与兼容性测试（RISC-V Compliance）把关。自由扩展与标准兼容是设计者权衡的核心——扩展过头会破坏可移植性。</span>

## 5 小结

- **RISC-V** 是开放、免费、模块化的指令集，2010 年起源于伯克利。
- 基础集 RV32I 是唯一必选；**M/A/F/D/C/V 等扩展正交可选**。
- 配置名按规则拼写：RV + 位数 + 基础 + 扩展字母；字母须有序、F 先于 D。
- 32 个通用寄存器，**x0 恒零**；ABI 名（sp/ra/a0…）是软件约定。
- 与 ARM 的对比核心在**开放度与可扩展性**：开源免费 + 自定义扩展是 RISC-V 的护城河。
