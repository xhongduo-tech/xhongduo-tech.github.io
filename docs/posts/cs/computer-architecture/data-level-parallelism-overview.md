## 为什么 DLP 是「免费的并行」

ILP 要硬件挖、TLP 要线程写——**DLP 是三者里最「天然」的**：只要数据是数组、操作是「对每个元素各做一遍」，并行度就**写在数据里**。图像处理、音频编码、矩阵运算、AI 推理全是这种形态。于是有了三种实现：**固定宽 SIMD、向量、GPU 的 SIMT**。<span class="marginnote">对照 [[ilp-concepts-limits]] 的四种并行：DLP 是「数据里的并行」，粒度在元素级。它不需要程序员拆线程、也不需要硬件挖依赖——<strong>一条指令，一次操作，作用于很多元素</strong>。</span>

## 1 三种实现形态

| 形态 | 载体 | 并行方式 | 典型 |
| --- | --- | --- | --- |
| **SIMD 指令** | CPU 内定宽寄存器 | 一条指令操作 N 个固定宽元素 | SSE/AVX/NEON |
| **向量** | CPU 向量寄存器 | 长度运行时自适应 | RVV、SVE、Cray |
| **SIMT** | GPU 线程束 | 一批线程同时执行同一指令 | NVIDIA GPU |

三者共享核心思想：**「一条指令 + 多份数据」**，差别只在「宽度写死还是可变」「用寄存器还是用线程束」。第一、二种的本质对比已在 [[vector-vs-simd]] 讲过，本节把它们与 GPU 并列放进 DLP 的坐标里。

## 2 为什么数据并行无处不在

DLP 的适用判据很宽松：**对一个大数组/矩阵做同一种运算，且元素间相互独立**。这类负载是主流：

- **多媒体**：像素点、音频采样——「每个点各算一遍」。
- **科学与工程**：矩阵乘法、数值模拟——张量运算天然并行。
- **AI 推理**：神经网络就是大规模矩阵/张量运算——DLP 的最大金矿。
- **密码与压缩**：逐字节/逐块处理。

这类程序常被称为 **embarrassingly parallel（易并行）**：并行度无穷多、拆分零成本，性能只受**吞吐硬件**限制——**DLP 的瓶颈从来不是「有没有并行」，而是「硬件能不能喂饱」**。

## 3 DLP 与 ILP/TLP 的区别

| 维度 | ILP | TLP | DLP |
| --- | --- | --- | --- |
| 并行单位 | 指令 | 线程 | 数据元素 |
| 谁来挖 | 硬件/编译器 | 程序员/OS | 数据天然提供 |
| 控制流 | 单控制流 | 多控制流 | **单控制流（重要！）** |
| 典型硬件 | 乱序核 | 多核/SMT | SIMD/向量/GPU |

**核心概念**：DLP 的关键特征是**单一控制流**——所有数据元素走同一条指令序列（只是数据不同）。这决定了它的硬件可以**去掉「多控制流」的成本**（每个线程的 PC、分支预测），把晶体管全砸在「算得快」上。GPU 的 SIMT 之所以能堆几千个核，正是因为「控制流只有一份」。

## 4 从循环到数据并行：向量化的视角

大多数 DLP 代码从**循环**来——编译器做**自动向量化**：

```c
// 标量版本：每个元素一次加法
for (i = 0; i < N; i++)
    c[i] = a[i] + b[i];

// 向量化版本：一次处理 W 个元素（编译器自动生成）
for (i = 0; i < N; i += W)
    c[i..i+W-1] = a[i..i+W-1] + b[i..i+W-1];   // 一条 SIMD 指令
```

**能否向量化的判据**：循环体元素之间**无依赖**（无 [[loop-level-parallelism-dependency]] 的循环携带相关）、访存连续、无分支。编译器判定可行后，自动生成向量指令——**程序员不用写汇编，但写「可向量化」的循环是艺术**。

## 5 核心对比表：DLP 三条路线的硬件代价

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | SIMD 指令 | 向量 | GPU SIMT |
| --- | --- | --- | --- |
| 宽度 | 固定（128–512 bit） | 运行时可变 | 线程束（32/64 线程） |
| 控制流 | 单 | 单 | 单（带掩码） |
| 隐藏延迟方式 | 流水线 | 深度流水 | **线程切换**（TLP 补 DLP） |
| 典型延迟 | 低 | 中 | 高（靠并行掩盖） |
| 适用 | CPU 内少量并行 | 新 ISA、超算 | 海量并行、吞吐极致 |

**辨析｜易错点：** DLP 与 TLP 可以**叠加**：GPU 既是 DLP（一条指令对很多元素）又是 TLP（大量线程切换隐藏延迟）。「GPU 只是向量机」的说法不准确——GPU 的 SIMT 是**用线程级并行来实现数据级并行**，两条腿走路。

## 6 数值算例：从标量到 GPU 的加速账

设对 100 万个元素的数组做加法（`c[i] = a[i] + b[i]`）：

- **标量**：每周期 1 个元素——**约 100 万周期**。
- **SIMD-8（AVX2）**：每周期 8 个元素——**约 12.5 万周期**（8 倍）。
- **GPU（10 万线程）**：每线程处理 10 个元素，同时跑——**约几百到几千周期**（受访存限制，不是计算限制）。

$$
\frac{T_{\text{标量}}}{T_{\text{GPU}}} \sim 100\text{–}1000\ \text{倍}
$$

**要点**：DLP 的加速来自**数据天然并行**——从标量到 GPU 可差两个到三个数量级。但注意：**提速的上限是内存带宽**，不是计算单元——数据搬不进来，再多线程也白搭（[[simd-programming-autovectorization]] 的带宽受限观点）。

## 7 常见误区再辨析

- **「GPU 只是更大的 SIMD」**：GPU 的 SIMT 是**用线程切换隐藏延迟**（TLP 补 DLP），不是单条宽指令——机制不同。
- **「向量长度越长越好」**：定宽 SIMD 加宽要重编译、GPU 宽度要配线程数——**硬件宽度与程序规模要匹配**。
- **「DLP 不需要程序员」**：SIMD 要写可向量化循环、GPU 要写核函数与分块——**程序员决定并行能否被挖出**。
- **「易并行就一定快」**：易并行只是「并行度够」；**吞吐仍被带宽、访存模式、同步瓶颈限制**。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| DLP | 数据级并行，元素级并行 |
| SIMD | 单指令多数据，定宽寄存器 |
| 向量 | 长度运行时自适应的数据并行 |
| SIMT | 单指令多线程（GPU） |
| 易并行 | 并行度无穷、拆分零成本 |
| 单一控制流 | 所有元素走同一条指令序列 |
| 自动向量化 | 编译器把标量循环变向量指令 |

## 9 小结

- **DLP** 是「一条指令、多份数据」，并行写在数据里——最「天然」的并行。
- 三种形态：**SIMD 指令、向量、GPU SIMT**，共享单控制流思想。
- 多媒体、科学、AI 全是 DLP 主战场，通常「易并行」。
- 与 ILP/TLP 的区别：**单一控制流**，省掉多控制流成本。
- 自动向量化把标量循环变向量指令，判据是**元素独立 + 访存规则**。
