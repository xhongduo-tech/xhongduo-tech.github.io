## 为什么 WSC 的硬件「不追求单点最强」

[[warehouse-scale-computer]] 说 WSC 是同质商品硬件。本节拆解这台「大计算机」的三大部分：**服务器、存储、网络**——你会发现每个设计决策都以「规模化后的整体」为准绳，而不是单点。<span class="marginnote">对照单机体系结构：<strong>服务器的设计目标是「好养、便宜、够用」，不是「最快」</strong>。WSC 是「整体最优」哲学的极端案例。</span>

## 1 服务器：为规模设计

WSC 服务器的典型形态：

- **机架式**：1U/2U 标准机箱，数台到数十台一个机架。
- **组件**：2 路 CPU、数百 GB 内存、本地 SSD/HDD、双 NIC（网卡）。
- **无冗余电源/磁盘**：单机电源坏了就换整台——**冗余在机架层做**（机架配 N+1 电源与散热），不在单机里重复投资。

**核心概念**：**故障域（failure domain）**按机架组织：一个机架的电源/散热共享，整机架同时断电的单元是「一个故障域」。软件按故障域布局副本——**同一份数据的不同副本放在不同故障域**，单机架挂了也不丢。

## 2 存储组织：本地盘 + 分布式文件系统

WSC 存储分两层：

| 层 | 形态 | 用途 |
| --- | --- | --- |
| **本地盘** | 每台服务器的 SSD/HDD | 缓存、临时数据、本地日志 |
| **分布式文件系统** | GFS/HDFS 等 | 全局可靠存储（3 副本） |

**核心概念**：本地盘「快但不持久可靠」，分布式 FS「慢但可靠」。访问模式：

- 数据写 → 发给分布式 FS（3 副本跨机架）。
- 热数据 → 缓存到本地盘（数据局部性，避免跨网络读）。

**辨析｜易错点：** WSC 的「存储」不是一个大 SAN——它把**每台服务器自己的磁盘**聚合起来，用软件做成可靠存储（[[mapreduce-spark-cluster-computing]] 的地基）。「服务器无盘、全靠中心存储」是老式做法；**现代 WSC 走「本地盘 + 软件冗余」**。

## 3 网络组织：分级互连

WSC 网络是分级的，目标是把数万台服务器互连：

```text
                核心层（Core）——数十台，机架间高速互连
        ┌────────┼────────┬────────┬────────┐
    汇聚层    汇聚层    汇聚层    汇聚层    汇聚层   （Aggregation）
      │         │         │         │
   ┌──┴──┐   ┌──┴──┐   ┌──┴──┐   ┌──┴──┐
  ToR   ToR  ToR   ToR  ToR   ToR  ToR   ToR   （接入层，每机架一台）
   │││   │││   │││   │││   │││   │││   │││
  服务器  服务器  服务器  服务器  服务器  服务器  服务器  服务器
```

- **带宽超卖（over-subscription）**：ToR 上行带宽通常小于下行总带宽（如 1:3）——因为不是所有服务器同时满负荷。**超卖比是成本与性能的权衡**。
- **Clos / 胖树拓扑**：多级无阻塞互连（[[interconnection-topologies]]），让任意两台服务器都有多条等价路径。

**核心概念**：WSC 网络是「分级 + 超卖 + 多路径」——**不可能给每对服务器直连**（O(N²) 成本爆炸），而是用树状拓扑 + 流量统计超卖。

## 4 现代趋势：池化与加速

WSC 硬件正在变化：

- **存算分离**：把内存/存储从服务器里「抽出来」做成资源池，按需分配（CXL 内存池化，见 [[cxl-interconnect]]）。
- **DPU/IPU**：把网络、存储、安全从 CPU 卸到专用数据处理器上，CPU 专心算。
- **液冷**：AI 集群功耗暴涨，整机架液冷成为标配。

## 5 核心对比表：WSC 硬件的「反常」设计

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 传统单机 | WSC 服务器 |
| --- | --- | --- |
| 电源冗余 | 单机冗余电源 | **机架层冗余** |
| 磁盘 | 本地可靠 | 本地盘 + 分布式 FS 副本 |
| 网络 | 主板集成 | ToR + 分级 + 超卖 |
| 单点性能 | 追求最强 | **够用 + 好养 + 便宜** |
| 可靠性 | 硬件冗余 | **软件容错** |

## 6 数值算例：超卖比怎么算

设一个机架 40 台服务器、每台下行带宽 25 Gb/s，ToR 上行聚合带宽 100 Gb/s：

- **下行总带宽**：$40 \times 25 = 1000$ Gb/s。
- **上行带宽**：100 Gb/s。
- **超卖比**：$1000 / 100 = 10:1$——**机架内任意时刻最多只有 1/10 的流量能出机架**。

$$
\text{超卖比} = \frac{\text{下行总带宽}}{\text{上行带宽}} = \frac{1000}{100} = 10
$$

**要点**：10:1 意味着「同一时刻全部服务器满负荷外发」会拥塞——但现实中**统计上只有一小部分流量跨机架**，超卖以「小概率拥塞」换「10 倍成本节省」。**超卖比是 WSC 网络成本与性能的核心旋钮**：给 AI 训练就收紧（接近 1:1），给网页服务就放宽。

## 7 常见误区再辨析

- **「WSC 存储是中心 SAN」**：现代 WSC 走「**每台服务器本地盘 + 软件冗余**」——没有大 SAN 单点。
- **「服务器越强越好」**：WSC 追求「够用 + 好养 + 便宜」——**单点性能让位给规模化的整体成本与能效**。
- **「超卖 = 偷工减料」**：超卖是**统计复用的工程实现**——绝大多数负载跨机架流量小，超卖在成本/性能间取最优。
- **「故障域只是硬件概念」**：软件副本布局**按故障域**组织——「同一机架」是设计副本分布时必须避开的单位。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 故障域 | 一起失效的单元（如整机架） |
| 本地盘 | 服务器自带的 SSD/HDD |
| 分布式文件系统 | GFS/HDFS，3 副本可靠存储 |
| ToR | 机架顶部交换机（接入层） |
| 汇聚层 / 核心层 | 网络分级的上层 |
| 超卖比 | 下行总带宽 ÷ 上行带宽 |
| 存算分离 | 内存/存储抽成资源池 |
| DPU/IPU | 卸载网络与存储的数据处理器 |

## 9 小结

- WSC 服务器：**机架式、无单机冗余、够用就好**；冗余在机架层。
- 存储 = **本地盘（快）+ 分布式 FS（3 副本可靠）**，软件聚合。
- 网络 = **ToR → 汇聚 → 核心**分级，**超卖 + 多路径**控制成本。
- **故障域**按机架组织，副本跨故障域布局。
- 趋势：**存算分离、DPU、液冷**——为 AI 与更大规模重构。

在下一节，我们看 WSC 性能最反直觉的指标——**延迟与吞吐的权衡：在线服务的尾延迟（Tail Latency）**。硬件组织讲完了「WSC 长什么样」，下一节转向「它跑在线服务时用户到底快不快」——而答案常常是那个最慢的尾巴。
