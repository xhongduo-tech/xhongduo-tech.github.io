# 存算一体（Processing-in-Memory）：近数据计算的复兴

<div class="epigraph">

## 为什么「算」要挪到「存」旁边

[[memory-hierarchy-amat]] 说访存延迟几百周期；但更残酷的是**能耗**：一次 DRAM 访问的能耗是**一次浮点运算的 100–1000 倍**。传统架构把数据搬到 CPU 再算——**搬运本身烧掉了绝大多数能量**。**存算一体（Processing-in-Memory, PIM）** 的反向思路：**让计算发生在内存附近/内存内部**，省掉搬运。<span class="marginnote">PIM 是「[[memory-hierarchy-amat]] 内存墙」的终极应对：<strong>不把数据搬向计算，把计算搬向数据</strong>。它其实是个「老概念」——1990 年代的智能内存（IRAM）就试过，只是如今被大数据与 AI 重新点燃。</span>

## 1 数据搬运的能耗账

$$
E_{\text{总}} = N_{\text{计算}} \times E_{\text{算}} + N_{\text{搬运}} \times E_{\text{搬}}, \qquad E_{\text{搬}} \gg E_{\text{算}}
$$

- **第一步，看 $E_{\text{算}}$**：一次 MAC 的能耗（皮焦级）。
- **第二步，看 $E_{\text{搬}}$**：从 DRAM 搬一个字到 CPU 的能耗（纳焦级）——**大 2–3 个数量级**。
- **第三步，看比例**：矩阵运算里每次计算都要搬操作数——**搬运能耗常占总能耗 60–90%**。PIM 的赌注：**把搬运次数降下来，总能耗就能掉一个数量级**。

## 2 PIM 的两种形态

| 形态 | 计算在哪 | 代表 |
| --- | --- | --- |
| **近内存计算（Near-Memory）** | 内存堆叠的逻辑层 / 内存控制器旁 | HBM 3D 堆叠 + 逻辑 die、Samsung Aquabolt |
| **存内计算（In-Memory）** | 内存阵列内部（模拟/数字） | ReRAM、PCM 存算（[[reram-computing-in-memory]]） |

**核心概念**：**近内存（near-memory）**：在内存旁边加**逻辑层**（3D 堆叠、内存控制器的计算单元）——能做较复杂的运算，但仍是「数字计算」；**存内（in-memory）**：让**存储单元本身**参与计算（如用模拟电压/电流做乘加）——最彻底，但精度与灵活性受限。

## 3 为什么现在 PIM 复兴了

1990 年代 IRAM 失败于**工艺不匹配**：DRAM 工艺慢、逻辑弱，塞进去的逻辑单元又少又差。今天复兴的三个新理由：

- **大数据/ML 的带宽饥渴**：扫描数据库、神经网络推理要**读海量数据**——瓶颈在带宽，PIM 把「内存内部带宽」（极高）直接当计算带宽用。
- **3D 堆叠成熟**：HBM 把内存与逻辑堆在一颗封装里，**近内存逻辑成本大降**。
- **能耗压力**：[[wsc-energy-pue-tco]] 的能效焦虑让「省搬运」有了巨大的经济价值。<span class="marginnote">一句话：<strong>工艺问题被堆叠解决了，需求问题被 AI 引爆了，能耗问题被云放大了</strong>——PIM 的三个失败理由全部逆转。</span>

## 4 PIM 的挑战

- **逻辑能力受限**：内存里塞不了复杂核——只能做简单算子（扫描、聚合、乘加、比较）。
- **编程模型**：数据必须「恰好放在计算单元旁边」——要新编译器/运行时（类似 [[dsa-programming-model-software]] 的映射问题）。
- **虚拟内存的干扰**：[[tlb-optimization-multilevel-paging]] 的页表让「物理位置」对软件不透明——PIM 需要知道数据在哪，虚拟化让它难办。
- **内存做计算 = 内存被占用**：做计算时不能同时做存储，带宽与容量要权衡。

**辨析｜易错点：** PIM 不是「把 CPU 放进内存」。它是**把「少量简单运算」下沉到内存附近**——复杂控制流与浮点仍由 CPU/加速器做。**PIM 是「分忧」，不是「替代」**。

## 5 应用与现状

| 场景 | PIM 干的事 | 收益 |
| --- | --- | --- |
| 数据库扫描 | WHERE 过滤在内存内做 | 只搬符合条件的数据 |
| 图处理 | 邻接矩阵运算近内存 | 免去大量图遍历访存 |
| ML 推理 | 权重与激活在内存内乘加 | 带宽瓶颈消失 |
| memcpy/memset | 内存内部搬移 | 免经 CPU |

商业与学术现状：**Samsung 的 HBM-PIM、UPMEM 的 PIM 内存条、各类 ReRAM 存算芯片**——PIM 正从论文走向量产。

## 7 小结

- **内存墙**：搬运能耗是计算能耗的 100–1000 倍，PIM 省的就是搬运。
- 两种形态：**近内存（逻辑层）vs 存内（阵列内）**。
- 复兴三因：**AI 带宽饥渴 + 3D 堆叠成熟 + 能效压力**。
- 挑战：**逻辑受限、编程模型、虚拟内存干扰、容量权衡**。
- PIM 是「分忧」不是「替代」——复杂计算仍归 CPU/加速器。
