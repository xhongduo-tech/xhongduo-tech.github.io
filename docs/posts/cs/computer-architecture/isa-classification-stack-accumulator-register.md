# 指令集架构的分类：栈、累加器与寄存器型

## 为什么从「操作数放哪」讲起

进入指令集架构（ISA）进阶，第一件事是退回到原点：**一条算术指令从哪里拿操作数、把结果放哪？** 答案有三种历史形态——**栈、累加器、通用寄存器**。它们决定了指令的**长短、条数、硬件复杂度与编译器难度**，也决定了程序的**代码密度**。<span class="marginnote">先回顾「计算机组成原理」分类里的指令系统：寻址方式、操作码格式是那里的内容；本节用「操作数存储位置」这一把尺子，把整个 ISA 设计空间重新度量一遍。</span>

## 1 三种模型的本质差别

| 模型 | 操作数来源 | 指令条数（算 `a = b + c`） | 代表 |
| --- | --- | --- | --- |
| **栈式** | 隐式：栈顶 | 4 条 | JVM 字节码、Hewlett-Packard 计算器 |
| **累加器式** | 隐式：累加器 | 3 条 | 早期 8 位机（MOS 6502、Intel 8080） |
| **通用寄存器式** | 显式：寄存器 | 1–2 条 | x86、ARM、RISC-V、MIPS |

同一个表达式在不同模型下的指令序列，是最直观的对照：

```
栈式：       PUSH b ; PUSH c ; ADD ; POP a        （4 条，短指令）
累加器式：   LOAD b ; ADD c ; STORE a            （3 条）
寄存器式：   ADD a, b, c                         （1 条，长指令）
```

**核心概念**：**栈式机器（stack machine）**的操作数是**隐式的**——算术指令从栈顶取两个值、把结果压回栈顶。它不需要在指令里写操作数，指令极短、代码密度高，但同一表达式需要的指令条数最多。

## 2 栈式机器：隐式操作数的代价

栈式设计的优点与缺点同样突出：

- **优点**：指令短（操作码即可，如 `ADD`、`POP`）；硬件简单（一个栈）；程序紧凑；中间结果天然按嵌套表达式组织。
- **缺点**：栈顶频繁读写成为瓶颈；同一计算要更多指令（每条指令只做很少的事）；现代流水线与多发射很难在栈机上发挥（操作数依赖太密）。<span class="marginnote">JVM 字节码是栈式的，因为<strong>栈模型适合「可移植的虚拟执行环境」</strong>——解释器/JIT 容易实现、字节码紧凑。但 JIT 编译器会把字节码翻译成寄存器式机器码再执行——<strong>物理硬件早已不用纯栈，栈只活在虚拟层</strong>。</span>

## 3 累加器机器：半个隐式

**累加器式（accumulator machine）**只有一个隐式寄存器（累加器）：算术指令默认从它取一个操作数、结果写回它；另一个操作数在指令里给出（立即数或内存地址）。

- **优点**：指令短、硬件最简。
- **缺点**：累加器是唯一的数据通道，每次运算都要把它倒腾来倒腾去；编译器几乎无法并行。历史上 8 位微处理器多用此模型，如今只存在于嵌入式低端与教学。<span class="marginnote">累加器机的经典窘境：`LOAD b; ADD c; STORE a` 里，a 的旧值要先搬走、b 的值搬进来，一个寄存器忙死。这正是通用寄存器模型要解决的问题。</span>

## 4 通用寄存器机器：显式操作数

**通用寄存器（GPR）机器**在指令里**显式**写寄存器号（或内存地址）。按「寄存器+内存」的分工又分三类：

- **寄存器-存储器（register-memory）**：算术指令可从内存取一个操作数（x86 是典型）。指令条数少，但指令长度不一、操作数含内存地址。
- **寄存器-寄存器 / 装载-存储（load-store）**：只有 `LOAD`/`STORE` 能访问内存，算术全在寄存器间进行（ARM、MIPS、RISC-V 是典型）。指令格式规整、便于流水线与调度，但要额外执行装载/存储指令。
- **存储器-存储器（memory-memory）**：操作数全在内存（如早期的 VAX 部分模式），几乎不在现代设计里。

按地址数还分**三地址**（`ADD a,b,c`）、**二地址**（`ADD a,b` 即 `a+=b`）、**一地址**。<span class="marginnote">RISC 的 load-store 与 CISC 的 register-memory 之争，是 [[risc-design-philosophy]] 整篇的导火索：<strong>寄存器多、访存少、格式规整</strong>，换来的是更快更简单的流水线。</span>

**辨析｜易错点：** 「寄存器型」不等于「load-store」。x86 也是寄存器机器（有大量通用寄存器），但它允许算术指令直接操作内存（register-memory）；ARM/RISC-V 才是严格的 load-store。判断标准是：**算术指令能不能带内存操作数**。

## 5 核心对比表：三类模型的总评

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 栈式 | 累加器式 | 寄存器式（load-store） |
| --- | --- | --- | --- |
| 指令长度 | 最短 | 短 | 较长 |
| 指令条数 | 最多 | 中 | 最少 |
| 硬件复杂度 | 低 | 最低 | 较高（寄存器堆、端口） |
| 编译器难度 | 中 | 难（唯一数据通道） | 低（寄存器随便用） |
| 流水线/多发射 | 难发挥 | 难发挥 | 易发挥 |
| 现代用途 | 虚拟层（JVM/CLR） | 教学、低端 MCU | **所有现代高性能处理器** |

## 6 小结

- 分类的尺子：**操作数存在哪** → 栈、累加器、通用寄存器三族。
- 栈式：指令短、条数多、硬件简，活在 JVM 等虚拟层。
- 累加器式：单数据通道、最简硬件，属历史形态。
- 寄存器式：显式操作数、条数最少；**load-store** 是 RISC 的选择，**register-memory** 是 x86 的选择。
- 现代高性能处理器全部是寄存器式——**因为只有显式操作数才能支撑流水线与乱序执行**。
- 这个分类是理解「为什么 RISC-V 长这样」的前置知识。
