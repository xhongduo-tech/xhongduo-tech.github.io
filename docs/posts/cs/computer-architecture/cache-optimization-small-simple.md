# 高级 Cache 优化（一）：小而简单的第一级 Cache

<div class="epigraph">
<p>让 L1 足够小，小到它的命中时间不再拖慢时钟——这是很多优化里最便宜、最容易被忽略的一招。</p>

## 为什么「越小越好」反直觉

上一节 AMAT 告诉我们，缺失率越低越好——那 L1 越大不是缺失率越低吗？但这里有个陷阱：**L1 的命中时间在流水线的关键路径上**。每多花 1 个周期做命中判断，整个处理器的时钟周期就可能被拖长 1 个周期——**这 1 个周期的代价，要几百次命中才能补回来**。<span class="marginnote">回想 [[amdahls-law]] 的思路：如果命中占 98%，那么在命中上省 1 个周期，等于在 98% 的事件上加速；而在缺失上省 100 个周期，只影响 2% 的事件。<strong>高频路径上的小优化，往往比低频路径上的大优化更值钱</strong>。</span>

## 1 为什么 L1 命中时间在关键路径上

每次访存，处理器都要：

1. 用地址索引 Cache（查索引字段）。
2. 读出该组的数据与标签。
3. **比较标签**，判断命中。
4. 命中则把数据送进流水线。

第 3、4 步是**每周期都要走**的必经路径。L1 命中时间是「确定性」的常数延迟，如果它太大，要么时钟周期变长，要么流水线要为它多插一级——**两种都是全系统代价**。

## 2 小 Cache 为什么快：三个原因

- **索引更快**：Cache 小，索引位数少，地址解码路径短，延迟低。
- **标签比较更少**：相联度越低，需要并行比较的标签越少，比较器与选通逻辑越简单。
- **物理布线更短**：小 Cache 离 CPU 核心更近，片上走线延迟小——**在深亚微米工艺下，导线延迟往往超过门延迟**，面积直接折成延迟。

## 3 直接映射 vs 相联：命中的代价

- **直接映射（direct-mapped）**：每个地址只落在一个位置，只需**一次标签比较**，命中判断最快。
- **组相联（set-associative）**：N 路要**并行比较 N 个标签**，再多路选择——比较器多、MUX 深，命中时间变长。
- **全相联**：比较所有块，命中时间最长（通常只用于 TLB 这类小结构）。

**核心概念**：L1 的设计取向是「**宁可缺失率高一点，也要命中快**」——所以典型 L1 是 32–64 KB、4–8 路组相联，把命中控制在 1 个周期内；**容量与相联度的账，交给 L2/L3 去算**。<span class="marginnote">这就是「小而简单」的全部含义：L1 的任务是「<strong>最快地处理大多数访问</strong>」，不是「装下大多数数据」。装不下没关系，L2 兜底；慢了才致命。</span>

## 4 把容量让给 L2：层次的接力

L1 小，缺失率必然上升——但这笔账在层次里是划算的：

- L1 缺失后去 L2，L2 命中代价通常 4–10 周期，远小于 L1 多 1 个周期命中时间造成的**每访问**成本。
- 面积预算固定时，把晶体管给 L1 扩容 vs 给 L2 扩容，后者往往更能降总体缺失率（L2 承受更大容量压力）。

**辨析｜易错点：** 「L1 小导致缺失率升高」本身没错，但**缺失率不是孤立指标**。评判标准是 AMAT（含缺失代价），不是缺失率。大而慢的 L1 往往输给小而快的 L1 + 给力的 L2——**单看缺失率会做出错误设计**。

## 5 公式解析：小 vs 大的 AMAT 账

$$
\text{AMAT}_{\text{小}} = T_{\text{小}} + M_{\text{小}} \times T_{\text{L2}}, \qquad
\text{AMAT}_{\text{大}} = T_{\text{大}} + M_{\text{大}} \times T_{\text{L2}}
$$

- **第一步，定变量**：小的命中快（$T_{\text{小}} = 1$）、缺失率高（$M_{\text{小}} = 6\%$）；大的命中慢（$T_{\text{大}} = 2$）、缺失率低（$M_{\text{大}} = 3\%$）；设 $T_{\text{L2}} = 10$。
- **第二步，代入**：$\text{AMAT}_{\text{小}} = 1 + 0.06 \times 10 = 1.6$；$\text{AMAT}_{\text{大}} = 2 + 0.03 \times 10 = 2.3$。
- **第三步，看结论**：**小 Cache 反而快了 0.7 周期/访问**——前提是 L2 够快。若 L2 很慢（$T_{\text{L2}}=50$），小的 $\text{AMAT}=4$、大的 $=3.5$，大 Cache 才反超。**「小」是否最优，取决于下一层的速度**——这就是层次设计的动态平衡。

## 6 小结

- L1 命中时间在**流水线关键路径**上，慢 1 周期=时钟慢 1 周期，代价全局化。
- 小 Cache 快：**索引短、比较少、布线近**；相联度越高命中越慢。
- L1 的取向是「宁缺失率大、不失命中快」，容量交给 L2/L3。
- 评判标准是 **AMAT 而非缺失率**；单看缺失率会误导设计。
- 「小 vs 大」的胜负由**下一层速度**决定——层次设计是动态平衡。
