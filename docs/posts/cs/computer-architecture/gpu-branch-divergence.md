# GPU 分支分歧（Divergence）与掩码执行

<div class="epigraph">

## 为什么 GPU 的分支「贵」

[[gpu-simt-execution]] 说 warp 里的 32 个线程**锁步执行同一条指令**。但程序总有分支——一个 warp 里有些线程走 `if`、有些走 `else`，它们「各怀心思」。硬件不能真的让线程各走各的（那要 32 套控制流），于是**让两条路都执行一遍，每次只让「该走这条路」的线程干活**——这就是**分支分歧（divergence）**。<span class="marginnote">对比 [[memory-consistency-sequential]] 里 CPU 的分支预测：CPU 靠「猜」避免等待，GPU 不猜——它<strong>把两条路都走完</strong>，靠并行度来摊薄成本。两种思路各自在自己的世界成立。</span>

## 1 掩码执行：两条路都走

**核心概念**：GPU 用一个**活动掩码（active mask）**记录 warp 里「当前该执行」的线程。遇到分支：

```
if (tid % 2 == 0) {
    a[tid] = 1;      // 路径 A：只有偶数线程活动
} else {
    b[tid] = 1;      // 路径 B：只有奇数线程活动
}
```

硬件执行：

1. 掩码 = 偶数线程 → 执行路径 A（奇数线程挂起，不写）。
2. 掩码 = 奇数线程 → 执行路径 B（偶数线程挂起）。

**两条路径被串行执行**，不活动的线程「空转」。好在它们不写内存，不会造成错误——代价只是时间。

## 2 分歧的代价量化

$$
T_{\text{warp}} = T_A + T_B \quad（分歧时）
$$

- **第一步，看 $T_A + T_B$**：两条路径**累加**——即使只有 1 个线程走 B，整个 warp 也要把 B 完整走一遍。
- **第二步，对比理想**：若所有线程走同一条路，$T = \max(T_A, T_B)$，一次搞定。
- **第三步，感受损失**：路径 A 20 周期、B 20 周期 → 分歧时 40 周期 vs 一致时 20 周期——**慢 2 倍**。分支嵌套更深、路径更多，损失指数级放大。

**辨析｜易错点：** 分歧**不是「并行地两条路同时走」**——SM 的 ALU 只有一份，两条路径只能串行。GPU 能并行的前提是「warp 内指令一致」；**分歧把 warp 拆成了多个串行的「子 warp」**。

## 3 分歧的两种层级

| 层级 | 是否分歧 | 代价 |
| --- | --- | --- |
| **warp 内** | 分歧（lockstep 的受害者） | 路径串行化 |
| **warp 间 / 块间** | **无分歧** | 不同 warp 各走各的，互不影响 |

**核心概念**：**分歧只发生在 warp 内部**。不同 warp、不同块可以走完全不同的代码路径——它们由不同的调度器独立调度。所以 GPU 并行编程的正确姿势：**让「大粒度的不同」发生在块/线程束之间，让「warp 内的 32 个线程」尽可能同进退**。

## 4 避免分歧的编程策略

- **让分支条件与 warp 对齐**：把数据按「同一 warp 线程走同一路」来组织——如按 32 的倍数分段处理。
- **用算术替代分支**：`x = (cond) ? a : b` 可能被编译成 select 指令（无分支），比 `if` 更便宜。
- **把「分歧点」上移到块级**：让整个块的线程走同一条路，而不是 warp 内各走一半。
- **排序/重排数据**：把「要处理」与「不处理」的元素分到不同的块——经典的数据重排优化。

**辨析｜易错点：** 分支的**代价**不是「分支指令本身」，而是「warp 内路径不一致」。一个 `if` 里所有线程条件相同（如 `if (blockIdx.x == 0)`），零代价；条件随 `threadIdx` 变化，就可能贵。<span class="marginnote">所以判断 GPU 代码性能，先问：<strong>分支条件跟 `threadIdx`/`tid` 有关吗？</strong>跟线程索引有关 = 大概率分歧；跟块索引有关 = 几乎免费。</span>

## 5 分歧的成本到底多大：一个例子

设一个 warp 里 16 个线程走路径 A（10 周期）、16 个走路径 B（10 周期）：

- 无分歧：10 周期完成。
- 有分歧：**20 周期**（A、B 串行）——**浪费一半算力**。
- 若路径长短悬殊（A 100 周期、B 1 周期），串行代价更大，几乎等同于「所有线程都走长路径」。

工具侧：NVIDIA profiler 报告**分歧分支占比**；编译器会尝试**谓词化（predication）**——把短分支转成条件执行，用「全算 + 掩码」换「无分歧」。**写 GPU 代码时，把「是否按 threadIdx 分叉」当作第一性能检查项**。

## 6 小结

- **分支分歧**：warp 内线程走了不同路径，硬件被迫**串行执行所有路径**。
- **掩码执行**：活动掩码决定哪些线程干活，不活动的空转但不写。
- 分歧代价 $T = T_A + T_B$：**路径累加**，嵌套分歧指数级恶化。
- 分歧只发生在 **warp 内**；warp 间/块间天然并行。
- 避免策略：**按 warp 对齐分支、用 select 替 if、把分歧点上移到块级、数据重排**。
