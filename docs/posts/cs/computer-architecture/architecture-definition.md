# 计算机体系结构的定义：指令集、组成与实现的分工

<div class="epigraph">

## 为什么从定义开始

这个网站从「极限」走到「大模型」。极限是微积分的入口，大模型是当代 AI 的前沿，而把它们串起来的，是一个具体、可量化的机器世界：训练一个大模型的集群有上万块 GPU，每一块 GPU 都是一台规模惊人的计算机。它之所以能被设计、被比较、被优化，前提是先回答一个朴素的问题——**什么是一台计算机的「体系结构」？**

这个问题没有看上去那么直白。「体系结构」在中文里被同时用来指「芯片的内部设计」「一台电脑的整机形态」，甚至「软件架构」。在英文里它也有两义：窄义的 architecture 特指指令集体系结构，宽义的 computer architecture 则涵盖一台计算机的全部设计层次。这一篇要做的，就是把这两个含义拆开，理出一套**三层次分工**的框架。

这套框架直接承接第三级《计算机组成原理》[^1] 里的「计算机体系结构与计算机组成的区别」「CPU 执行时间与 CPI」——那里以「认识一台机器」为目标；本专题则改用 Hennessy & Patterson《量化研究方法》的眼光：一切设计决策都要拿测量数据说话。今天这篇，是全专题的第一块基石。

## 1 一个词，三种分工

1964 年，IBM 发布 System/360 家族，从低端 Model 30 到高端 Model 70，价格相差十倍以上，却要运行同一套软件。这在当时是激进的：此前每换一台机器，软件几乎要重写。IBM 的办法，是抽出一个**在所有型号上都保持不变的抽象层**，由安达尔、布劳与布鲁克斯在同年的论文里正式命名为 architecture——程序员所看到的系统属性，独立于内部组织与物理实现。<span class="marginnote">System/360 的「360」取自罗盘一周，寓意一个家族覆盖科学计算、事务处理等全部应用方向。安达尔（Gene Amdahl）正是阿姆达尔定律的提出者；布劳（Gerrit Blaauw）与布鲁克斯（Fred Brooks）是「architecture」一词最早在计算机上的厘清者。</span>

这次拆解定义了现代计算机体系结构的**三层次分工**：

- **体系结构 / 指令集体系结构（ISA, Instruction Set Architecture）**：程序员与编译器能看到、也必须遵守的全部约定——指令集、寄存器堆、寻址方式、数据类型与字长、异常与虚存模型。它是一份**契约**。
- **组成（organization，即微架构 microarchitecture）**：满足这份契约的内部设计——流水线深度、缓存容量与层次、指令级并行机制。契约不变，组成可以千变万化。
- **实现（implementation）**：把组成变成真实硬件的物理过程——门电路、晶体管、版图与工艺节点。组成不变，实现也可以随工艺进步不断更换。

**体系结构（ISA）决定软件能不能跑；组成决定跑得多快、多贵；实现决定同样的设计在物理上能落到什么程度。** 这是贯穿全篇的第一条主线。

## 2 指令集：软件与硬件的交界线

把「契约」两个字展开，ISA 具体规定了这些内容：

- **指令系统**：有哪些操作码、每条指令的格式与编码；
- **寄存器堆**：程序员可见的通用寄存器数量与位宽；
- **寻址方式**：如何从地址找到操作数（立即数、寄存器、内存、PC 相对等）；
- **数据类型与字长**：字是 32 位还是 64 位，支持哪些基本数据类型；
- **控制流**：分支、跳转、调用与返回如何表达；
- **异常与特权模型**：中断如何进入、内核态与用户态如何切换、虚存如何呈现给软件——现代 ISA 的必备部分。

**指令集是软件与硬件的交界线**：界线以上是编译器、操作系统与应用，界线以下是微架构与电路。软件只要面向某份 ISA 写好一次，就能在满足这份 ISA 的任何机器上运行——这正是 System/360「一个家族、一套软件」的承诺，也是今天所有计算生态的根基。<span class="marginnote">x86 家族四十余年向后兼容：今天的新程序仍能在只支持旧指令集的机器上跑。RISC-V 则把契约做成模块化、可裁剪的开源标准，任谁都能实现。两者用完全不同的商业路径，验证着同一条规律：契约一旦确立，软件生态就押在它上面。</span>

举例：ARM 把 ISA 授权给苹果、高通、三星等多家厂商，它们做出的芯片内部天差地别，但面向同一 ISA 的编译产物大体可以互换。苹果 2020 年把 Mac 从 x86 迁到自研 ARM 芯片时，必须靠 Rosetta 2 转译才能运行旧的 x86 程序——因为跨了 ISA，契约变了。**这一步转译的麻烦，恰好从反面说明：ISA 是程序员写软件时唯一的、也是最后的分界线。**

## 3 组成与实现：同一份契约，不同的机器

ISA 相同，机器仍可以完全不同。这些差别来自组成（微架构）与实现（硬件）两个层次。

**组成**回答「怎么把这套指令执行得快」：流水线分成多少级、每周期最多发射几条指令（超标量宽度）、乱序执行的窗口多大、缓存有几级、每级多大、分支预测器多聪明。这些是微架构师的决定。<span class="marginnote">Intel Core i3 与 i9 执行的是同一份 x86 ISA，但微架构不同（核心数、缓存、超线程、加速频率），跑同一程序的速度可以相差数倍——ISA 完全没变，变的只是「组成」。</span>

**实现**回答「把设计变成硅片」：用哪条工艺线、晶体管怎么布局、门电路怎么连、时钟频率能拉到多高。同一份微架构设计，换一个工艺节点（比如从 7 nm 换到 3 nm），功耗与频率立刻不同——这正是「新一代芯片每代都更快、更省电」的物理来源。

| 层次 | 决定的问题 | 可变程度 | 主要设计者 |
| --- | --- | --- | --- |
| 体系结构（ISA） | 软件能跑什么 | 一经确立几乎不变 | 指令集架构师、编译器与 OS |
| 组成（微架构） | 同一程序跑多快、多贵 | 同一 ISA 下自由变化 | 处理器微架构师 |
| 实现（硬件） | 落到硅片后多快、多省电 | 随工艺进步不断换代 | 电路与版图工程师 |

把三层次放在一起看，就能体会 H&P 反复强调的一句话：**性能不是某一个层次的事，而是三个层次共同作用的结果。** 这引出下一节的量化语言。

## 4 性能的量化语言：时钟周期、CPI 与 CPU 时间

量化方法的第一步，是给「快」一个可测的定义。我们不问「这台机器快不快」，而问：**执行某个程序要多少秒。** 这个「秒」，可以从三个因数逐层拼出来。

先定义三个量：

- **指令数（IC, instruction count）**：程序执行时处理器共处理了多少条指令。它主要取决于 ISA 与编译器——同样的程序，用不同的 ISA 或不同的编译选项，IC 会不同。<span class="marginnote">这正是「ISA 决定软件能跑什么、也决定程序有多啰嗦」的体现：指令语义越贴合程序、编译器越聪明，同一任务需要的指令数越少。RISC-V 靠精简指令 + 好编译器，常常能比复杂指令集拿到更小的 IC。</span>
- **CPI（cycles per instruction，每指令周期数）**：平均每条指令消耗多少个时钟周期。它主要由组成（微架构）决定——流水线越深、乱序发射越宽，CPI 通常越低，但可能更耗电。
- **时钟周期时间 $T_c$**：一个时钟周期持续多少秒，其倒数就是时钟频率 $f = 1/T_c$。它主要由实现（工艺、电路）决定。

于是：

$$T = \text{CPU 时间} = IC \times CPI \times T_c$$

三个因数，正好对应三个层次：**IC 由 ISA 与编译器决定，CPI 由组成决定，$T_c$ 由实现决定。** 第一节的定义框架，在这里变成了一个可以直接代数的公式——这是量化方法最漂亮的地方。

正因为性能是三个因数的乘积，只看频率就以为「3 GHz 比 2 GHz 快 50%」，就是最常见的陷阱<span class="marginnote">这正是本专题后文《性能度量：CPU 时间、CPI 与 MIPS 的陷阱》要拆穿的错误：频率只刻画 $T_c$ 这一个因数，完全不涉及 IC 与 CPI。</span>。下一节我们就动手推导这个公式，并用它引出本专题的第一条法则——Amdahl 定律。

## 5 公式解析：T = IC × CPI × Tc 与 Amdahl 定律

### 从执行时间到 T = IC × CPI × T_c

把 CPU 时间拆成三步：

- **第一步，数周期**：处理一条指令平均花 CPI 个时钟周期，共 IC 条指令，所以总时钟周期数为 $IC \times CPI$。
- **第二步，换秒**：每个时钟周期持续 $T_c$ 秒，所以 $\text{CPU 时间} = (IC \times CPI) \times T_c$。
- **第三步，验单位**：指令数（条）$\times$ 每指令周期数（周期/条）$\times$ 周期时间（秒/周期）$=$ 秒。单位链条闭合，公式成立。

代入一个具体数字：设某程序 $IC = 10^{10}$ 条指令，某微架构下 $CPI = 2.0$，运行在 3 GHz 机器上，则 $T_c = 1/(3 \times 10^9) \approx 0.333\ \mathrm{ns}$：

$$T = 10^{10} \times 2.0 \times \frac{1}{3 \times 10^9} \approx 6.67\ \text{秒}$$

把 $T_c = 1/f$ 代入，公式还有另一种写法：

$$T = \frac{IC \times CPI}{f}$$

两种写法等价，但后者清楚地表明：**频率翻倍只改善 $T_c$ 这一个因数**——若 IC 或 CPI 同时恶化，总时间未必下降。

### Amdahl 定律：加速比的量化边界

假设我们能优化程序里的某一部分，总时间能快多少？Amdahl 定律给出答案。设：

- $f$：在原执行时间里，被优化部分占的比例（$0 \le f \le 1$）；
- $p$：该部分被加速的倍数（优化后该部分时间变为原来的 $1/p$）。

把原时间归一化为 1，则优化后的总时间：

$$T' = (1 - f) + \frac{f}{p}$$

加速比（原时间 ÷ 新时间）即为：

$$S = \frac{1}{(1 - f) + \frac{f}{p}}$$

推导只有两步：**没动的部分照旧（$1-f$），动过的部分缩到 $f/p$，相加得新时间；新旧时间之比就是加速比。** 代入数字：若 $f = 0.6$、$p = 2$，则 $S = 1/(0.4 + 0.3) \approx 1.43$——只快 43%，远不是「优化了六成代码、提速一倍」所想象的 1.6 倍。<span class="marginnote">注意极端情形：当 $p \to \infty$ 时，$S \to 1/(1-f)$。即便把被优化部分做到无穷快，总加速比也被剩下的 $(1-f)$ 死死卡住——木桶最短的那块板决定总收益。这个极限与第二级数学里的极限直觉一脉相承。</span>

这条定律立刻导出量化方法的第一条设计原则——**以大概率事件为快（make the common case fast）**：动手前先测量，把力气花在 $f$ 最大的部分，而不是直觉以为「很贵」的部分。我们会在本专题的《Amdahl 定律：加速比的量化推导与应用》一章里把它用到更复杂的情形。

## 6 小结

- 计算机体系结构是**三层次分工**：**体系结构（ISA）**是程序员可见的契约，**组成（微架构）**是满足契约的内部设计，**实现**是物理落地。
- **软件兼容性由 ISA 保证**，性能与成本主要由组成、实现决定。
- 性能公式 $T = IC \times CPI \times T_c$ 把三个层次统一成一个代数式：IC 归 ISA 与编译器，CPI 归组成，$T_c$ 归实现。
- **Amdahl 定律** $S = 1/((1-f)+f/p)$ 给出加速比的量化上限：收益受不可改进部分 $(1-f)$ 的约束。
- 量化方法的起点是**测量**：以大概率事件为快，先把力气花在占比最大的部分。

在下一节，我们将回答「世界上有哪些种类的计算机」——**计算机的分类与 Flynn 分类法**，把三层次框架放到单核、向量机、多处理器与 GPU 的谱系中去。
