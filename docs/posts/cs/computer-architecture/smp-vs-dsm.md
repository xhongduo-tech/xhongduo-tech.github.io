# 对称多处理器（SMP）与分布式存储多处理器（DSM）

## 为什么内存布局决定多处理器的「性格」

上一节把多处理器按通信模型分了共享内存与消息传递。**共享内存**内部还有大分野：内存**物理上集中**（SMP）还是**物理上分散**（DSM）？这决定了机器能长多大、访问有多快、一致性怎么做。<span class="marginnote">一句话记忆：<strong>SMP 是「一个内存、一堆 CPU」，DSM 是「一堆内存、逻辑上还是一个」</strong>。两者都承诺「共享地址空间」，兑现方式天差地别。</span>

## 1 SMP：总线上的对称多处理器

**核心概念**：**SMP（Symmetric Multiprocessing）**：多个处理器通过**共享总线/交叉开关**连接到一个**统一的物理内存**，每个处理器看到相同的地址空间、访问时间**均一**（UMA）。

经典结构：

```text
    CPU0      CPU1      CPU2      CPU3
      │         │         │         │
      └─────────┴─────────┴─────────┘
                  │ 总线 / 交叉开关
                  ▼
          ┌────────────────┐
          │   共享物理内存   │  （UMA：访问时间均一）
          └───────┬────────┘
                  │
               I/O 设备
```

**对称**：所有处理器地位平等，都能访问全部内存与 I/O。
**一致性**：总线天然广播——每个核都能「看到」别人在读什么，所以**监听（snooping）协议**在总线上很自然（[[cache-coherence-snooping]]）。
**编程**：跟单机多线程一样，共享变量即可通信。

## 2 SMP 的扩展天花板：总线带宽

总线是 SMP 的命门：**所有一致性流量（读缺失、写失效、监听）都挤在同一条总线上**。核多了，总线饱和，加核不再提速。

粗略模型：总线带宽固定，每核缓存缺失率 × 核数 = 总线流量需求。核数翻倍，若缺失率不降，流量翻倍——**总线先到极限**。这就是为什么**总线式 SMP 通常只到 4–8 个核**，再往上要么换交叉开关、要么换分布式结构。

**辨析｜易错点：** SMP 的扩展瓶颈是**一致性流量**（监听+失效），不只是「读内存」的流量。即使程序没共享数据，**替换/失效广播**也会占总线——所以 SMP 扩展性问题比看起来更顽固。

## 3 DSM：物理分布、逻辑共享

**核心概念**：**DSM（Distributed Shared Memory）**：每个节点有**自己的本地内存**，节点间用**互连网络**相连；硬件+软件把各节点内存**伪装成一个共享地址空间**。

**本地访问**：快（走本地内存）。
**远端访问**：慢（走网络，延迟 100 倍+）。
**一致性**：节点间不共享总线，监听协议够不着，要用**目录协议**（[[directory-based-coherence]]）跟踪「谁有哪块数据的副本」。

**DSM 的代价**：远端访问延迟高、编程要小心数据放置（把热数据放本地）、假共享在网络带宽下更致命。

## 4 假共享：DSM 的隐形杀手

**核心概念**：**假共享（false sharing）**：两个核**各改各的变量**，但这两个变量**住在同一个 Cache 块/内存页**里。虽然逻辑上无关，但一致性协议把整块当作一个单位——**一方写，整块失效，另一方重取**。于是「互不相干」的写被硬生生串行化。

```c
// a、b 同住一个 Cache 块——假共享
struct { int a; int b; } shared;

线程 1：shared.a++;    // 写 a → 整块失效
线程 2：shared.b++;    // 写 b → 重新取块，又使整块失效
// → 互不相干的两笔写被串行化，每次都走一致性协议
```

对策：**填充（padding）**把变量分开到不同块，或让编译器安排数据布局——这与 [[cache-optimization-compiler]] 的「分块」是同一族思想。<span class="marginnote">假共享在 DSM 上比 SMP 更严重：远端失效要走网络，代价高一个数量级。<strong>「数据布局即性能」在多处理器上被放大成定律</strong>。</span>

## 5 核心对比表：SMP vs DSM

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | SMP（UMA） | DSM（NUMA） |
| --- | --- | --- |
| 内存物理位置 | 集中共享 | 分布式 |
| 访问时间 | 均一 | 本地快/远端慢 |
| 一致性协议 | 监听（总线广播） | 目录（点对点） |
| 扩展性 | 差（总线瓶颈，4–8 核） | 好（可到上千节点） |
| 编程难度 | 低 | 中（数据放置） |
| 假共享代价 | 中 | 高（走网络） |
| 现代形态 | 单颗多核 SoC | 多路服务器、机群 |

## 6 数值算例：总线先到极限

设每核每周期发 1 次访存、缺失率 2%、每次缺失产生 1 条总线事务：

- **4 核**：总线流量 $= 4 \times 0.02 = 0.08$ 事务/周期——**总线路有余量**。
- **16 核**：流量 $= 16 \times 0.02 = 0.32$ 事务/周期——**若总线只能承载 ~0.1，直接饱和**。

$$
\text{总线流量} = \text{核数} \times \text{每核缺失率}
$$

**要点**：SMP 的扩展性被**总线一致性流量**封顶——核数翻倍、流量翻倍，总线先到极限。这就是为什么总线式 SMP 止步于 4–8 核，也解释了「为什么多核 SoC 内部用交叉开关 + 目录而非单总线」。

## 7 常见误区再辨析

- **「SMP 瓶颈是读内存」**：主要是**一致性流量**（监听 + 失效广播）——即使没共享数据，替换/失效也占总线。
- **「SMP 和 DSM 是两种编程模型」**：两者都提供**共享内存模型**，差别在**内存物理布局**（集中 vs 分布）——不是编程接口的不同。
- **「假共享只在多核」**：假共享本质是「同块不同变量互相失效」——多路（NUMA）下走网络代价更高，**布局即性能**。
- **「DSM 一定比 SMP 快」**：DSM 能长大但远端访问慢一个数量级——**本地数据放置不好，DSM 可能比 SMP 更慢**。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| SMP | 对称多处理器，统一内存 |
| UMA | 统一内存访问，时间均一 |
| DSM | 分布式共享内存 |
| NUMA | 非一致内存访问 |
| 总线带宽 | SMP 的扩展天花板 |
| 假共享 | 同块无关变量互相失效 |
| 填充（padding） | 把变量分到不同块 |

## 9 小结

- **SMP**：共享总线 + 统一内存（UMA），访问均一、一致性靠**监听**，但**总线带宽**封顶扩展。
- **DSM**：分布式内存 + 逻辑共享，本地快远端慢，一致性靠**目录**，可扩展到上千节点。
- 扩展性 vs 编程友好是主线交易：**SMP 好写但长不大，DSM 能长大但要小心写**。
- **假共享**让无关变量互相失效，数据布局成为多处理器性能的关键。
- 现代系统两者混用：芯片内 SMP、跨芯片 NUMA/DSM。

在下一节，我们解决 SMP/DSM 的第一道硬问题——**Cache 一致性问题：监听协议（Snooping Protocol）**。共享内存承诺「一个地址空间」，但每个核的缓存各持一份副本——怎么保证它们永远一致，就是下一节的主题。
