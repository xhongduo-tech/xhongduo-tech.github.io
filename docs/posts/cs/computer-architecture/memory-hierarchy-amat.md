## 为什么存储层次要先「量化回顾」

第四篇是存储层次的深水区，起点必须先立住两件事：**为什么层次能成立**（局部性），以及**怎么量化它的好坏**（AMAT）。「计算机组成原理」里的 Cache 基础这里不再重复，本节用 H&P 的量化语言把整个层次重新度量一遍——**没有 AMAT，后面每一篇 Cache 优化都是无的放矢**。<span class="marginnote">局部性原理是第一篇 [[locality-principle]] 的内容：时间局部性（刚用过的还会用）与空间局部性（旁边的数据马上用）。存储层次是局部性在硬件上的「下注」——<strong>赌对了快百倍，赌错了罚百倍</strong>。</span>

## 1 存储层次为什么能成立

存储器按「快贵小」到「慢廉价大」排成金字塔：

| 层 | 典型容量 | 典型访问时间 | 管理方 |
| --- | --- | --- | --- |
| 寄存器 | KB 级 | < 1 ns | 编译器/硬件 |
| L1 Cache | 32–64 KB | ~1 ns | 硬件 |
| L2 Cache | 256 KB–1 MB | ~4–10 ns | 硬件 |
| L3 Cache | 几 MB–几十 MB | ~10–40 ns | 硬件 |
| DRAM | GB 级 | ~50–100 ns | 硬件 + OS |
| SSD/磁盘 | TB 级 | ~10⁴–10⁷ ns | OS/软件 |

相邻层的延迟差约 3–10 倍，但**从寄存器到磁盘差了九个数量级**。没有层次，CPU 只能按最慢的部件跑；有了层次，**大多数访存命中在最快层**，平均成本被局部性拉下来。

**核心概念**：存储层次存在的两个前提：**局部性**（程序访问集中在小块区域）+ **成本梯度**（越快的技术每字节越贵）。两者缺一，层次就没有存在的理由。

## 2 三个基本度量

- **命中时间（hit time）**：访问在某层命中所花的时间（含该层判断命中的开销）。
- **缺失率（miss rate）**：不在该层、需向下一层要数据的比例（缺失次数/访问总数）。
- **缺失代价（miss penalty）**：一次缺失额外付出的时间（把数据从下一层取来并放好）。

**辨析｜易错点：** 命中时间是**一次访问的时间**，缺失代价是**缺失时额外加的时间**（不是总时间）。写 AMAT 公式时，**公式里的缺失代价**是「额外部分」，不是「完整下一层时间」——除非特别说明包含了下层访问。

## 3 AMAT：平均访存时间

**核心概念**：**平均访存时间（Average Memory Access Time, AMAT）**把命中与缺失按概率加权：

$$
\text{AMAT} = \text{命中时间} + \text{缺失率} \times \text{缺失代价}
$$

这是单级 Cache 的核心公式。举例：命中 1 周期、缺失率 2%、缺失代价 100 周期，则 $\text{AMAT} = 1 + 0.02 \times 100 = 3$ 周期——**看似命中快，平均每访问要 3 周期**。把缺失代价换成 200，AMAT 变 5。可见**缺失代价对 AMAT 的杠杆极大**：缺失率降到 1%，AMAT 变 2。

## 4 多级层次的 AMAT 递归展开

现代处理器 2–3 级 Cache，AMAT 递归嵌套：

$$
\text{AMAT} = T_{L1} + M_{L1}\left(T_{L2} + M_{L2}(T_{L3} + M_{L3} \cdot T_{\text{mem}})\right)
$$

其中 $T_{L1}$ 是 L1 命中时间、$M_{L1}$ 是 L1 缺失率、$T_{L2}$ 是 L2 命中时间，依此类推。**每一层的「缺失代价」就是「下一层的 AMAT」**——这是整个存储层次设计最核心的递归结构。

算个典型值：$T_{L1}=1$、$M_{L1}=5\%$、$T_{L2}=8$、$M_{L2}=20\%$、$T_{L3}=30$、$M_{L3}=10\%$、$T_{\text{mem}}=100$：

$$
\text{AMAT} = 1 + 0.05 \times (8 + 0.2 \times (30 + 0.1 \times 100)) = 1 + 0.05 \times (8 + 0.2 \times 40) = 1 + 0.05 \times 16 = 1.8
$$

**每层都把上一层的缺失「吸收」掉一大截**，这就是多层次的意义。

## 5 公式解析：AMAT 的三步拆解

$$
\text{AMAT} = \text{命中时间} + \text{缺失率} \times \text{缺失代价}
$$

- **第一步，看命中时间**：无论命中缺失都要付的基础成本。想让它小：Cache 小、相联度低、命中判断快（见 [[cache-optimization-small-simple]]）。
- **第二步，看缺失率**：决定「多久赌输一次」。想让缺失率小：Cache 大、块大、相联度高、预取（见高级 Cache 优化系列）。
- **第三步，看缺失代价**：赌输了要赔多少。想让代价小：下一层更快、非阻塞、关键字优先（见 [[cache-optimization-critical-word]]）。

**三个杠杆互相牵扯**：把 Cache 做大降缺失率，但命中时间变长；把块变大降缺失率，但可能多搬无用数据、提高代价。**AMAT 就是这场三角权衡的记账本。**

## 6 数值算例：AMAT 的三个杠杆谁最狠

基线：命中 1 周期、缺失率 5%、缺失代价 100 → $\text{AMAT} = 1 + 0.05 \times 100 = 6$ 周期。逐一优化：

- **缺失率减半到 2.5%**：AMAT $= 1 + 0.025 \times 100 = 3.5$。
- **缺失代价减半到 50**：AMAT $= 1 + 0.05 \times 50 = 3.5$。
- **命中时间砍半到 0.5**：AMAT $= 0.5 + 0.05 \times 100 = 5.5$——**几乎没改善**。

$$
\text{AMAT} = \text{命中} + \text{缺失率} \times \text{代价}
$$

**要点**：在「缺失代价 ≫ 命中时间」的现实里，**优化缺失率与缺失代价的杠杆远大于优化命中时间**——这也是为什么高级 Cache 优化系列一大半在打缺失率与缺失代价，而「小而简单」只敢对命中时间动刀。

## 7 常见误区再辨析

- **「命中时间就是缺失代价」**：命中时间是**每次访问**都付的基础成本；缺失代价是**缺失时额外**的惩罚——两者量级常差一个数量级。
- **「缺失率低 = 性能好」**：小缺失率 × 大代价仍可能毁掉性能；要看 **AMAT** 这个合并指标。
- **「多级 Cache 每层都看命中时间」**：深层 Cache 命中时间更长，但因为上层已过滤，**深层缺失率才是关键**——设计重点随层变化。
- **「AMAT 只对读」**：写侧有写缓冲、写回等，AMAT 模型同样适用但更复杂——**读是主体，写是修正项**。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 命中时间 | 一次访问在该层命中的时间 |
| 缺失率 | 缺失访问占总数比例 |
| 缺失代价 | 缺失时额外付出的时间 |
| AMAT | 命中 + 缺失率 × 代价 |
| 时间局部性 | 刚用过的还会用 |
| 空间局部性 | 旁边的数据马上用 |
| 成本梯度 | 越快技术每字节越贵 |

## 9 小结

- 存储层次成立靠**局部性 + 成本梯度**，从寄存器到磁盘差九个数量级。
- 三度量：**命中时间、缺失率、缺失代价**。
- **AMAT = 命中时间 + 缺失率 × 缺失代价**；多级层次递归嵌套「下一层的 AMAT 是上一层的缺失代价」。
- 缺失代价杠杆最大：小缺失率 × 大代价仍可能毁掉性能。
- AMAT 的三个杠杆（命中时间/缺失率/缺失代价）相互牵扯，Cache 优化的本质是三角权衡。
