## 为什么 RVV 是长度无关模型的实现

上一节的「向量长度无关」是理想，**RVV（RISC-V V 扩展）**是把它落地的规范。2021 年定稿的 RVV 1.0 为任意硬件宽度（VLEN = 128/256/512 bit…）提供一套统一的向量指令，软件用一条 **`vsetvli`** 告诉硬件「我要多宽的元素、用几组寄存器」，硬件回答「这次实际能做多长」。<span class="marginnote">RVV 与 ARM SVE 是当代两大「可扩展向量」设计：都提供长度无关编程。区别在于 RVV 允许<strong>运行时</strong>通过 `vsetvli` 自由切换元素宽度与寄存器组数，灵活性更高——见 [[vector-vs-simd]] 的本质对比。</span>

## 1 RVV 的寄存器与配置：v0–v31 + vtype/vl

RVV 提供 **32 个向量寄存器 `v0`–`v31`**，每个宽度为硬件定义的 **VLEN** 位。另有两组核心 CSR：

| CSR | 作用 |
| --- | --- |
| `vtype` | 元素宽度（SEW）、寄存器组（LMUL）、掩码/尾元素策略 |
| `vl` | 当前向量长度（本次执行多少个元素） |
| `vstart` | 指令恢复执行的起点（用于中断/异常重放） |
| `vcsr` | 状态与控制位 |

**核心概念**：`vtype` 决定「每个元素多宽、一个向量寄存器能装几个元素」，`vl` 决定「这次实际执行几个」——**类型与长度分离**，这是 RVV 优雅的根基。

## 2 vtype：SEW 与 LMUL

`vtype` 里两个关键字段：

- **SEW（Selected Element Width）**：元素位宽，可取 8/16/32/64（V 扩展还支持 fp16/bf16 等）。SEW 越小，每个寄存器装的元素越多。
- **LMUL（vector register group Multiple）**：把 $m$ 个向量寄存器**拼成一组**当「一个更长的向量寄存器」用，$m \in \{1,2,4,8\}$（也有分数 $1/2,1/4,1/8$）。LMUL = 2 时，`v1` 实际占用 `v1`–`v2` 两个寄存器。<span class="marginnote">LMUL 的作用是「<strong>软件主动加长</strong>」：当 128 位 VLEN 装不下 64 位元素的浮点运算时，用 LMUL=2 让有效长度翻倍。代价是占用更多寄存器，编译器在可用性与长度之间权衡。</span>

有效向量长度 = $\frac{\text{VLEN} \times \text{LMUL}}{\text{SEW}}$（个元素）。

## 3 vsetvli：一条指令完成配置

```
vsetvli t0, a0, e32, m1
```

这条指令做三件事：设 SEW=32（`e32`）、LMUL=1（`m1`），**并根据 a0 请求的长度返回实际 `vl` 到 t0**——返回的 $vl = \min(a0,\ \text{硬件上限})$。典型循环：

```
loop:
    vsetvli t0, a0, e32, m1   ; t0 = 本次长度（≤ a0）
    vle32.v  v1, (a0)         ; 装载 t0 个 32 位元素
    vadd.vv  v2, v1, v1       ; 向量加
    vse32.v  v2, (a1)         ; 存回
    sub      a0, a0, t0       ; 还剩多少
    bnez     a0, loop         ; 没完就继续 → strip-mining 的汇编形态
```

循环每次按 `t0` 前进，块长随硬件自适应——**这就是长度无关代码长在汇编里的样子**。

## 4 掩码操作：条件执行的向量版

向量要处理 `if (x[i] > 0) y[i] = x[i]` 这类条件，靠**掩码（mask）**。RVV 用 **`v0` 兼任掩码寄存器**，每元素 1 位：

```
vsetvli t0, a0, e32, m1
vle32.v   v1, (a0)         ; 装载 x
vmsgt.vv  v0, v1, zero     ; v0 = (v1 > 0) 逐元素比较，生成掩码
vle32.v   v2, (a1)         ; 装载 y
vmerge.vvm v3, v2, v1, v0  ; 掩码位=1 取 v1，否则取 v2 → 完成 if 语义
vse32.v   v3, (a1)         ; 存回
```

**核心概念**：**掩码操作**让向量指令对**部分元素**生效——被掩码的元素要么保持不动、要么写「无关心」值。RVV 指令后缀 `.t`（如 `vadd.vv v1, v2, v3, v0.t`）表示「仅在 v0 掩码位为 1 的位置执行加法」。<span class="marginnote">掩码把「分支 + 执行」翻译成「计算掩码 + 按掩码执行」，消除了向量化时最难处理的<strong>控制流分歧</strong>。这与 GPU 里 [[gpu-branch-divergence]] 的掩码执行是同构思想。</span>

## 5 尾元素与「无关心」策略

循环末尾的**余数元素**（长度不足一块）和掩码为 0 的元素，是「不想要的元素」。RVV 用 `vtype` 里的两个位指定它们的处理：

- **`vta`（tail agnostic）**：尾元素写什么——`undisturbed`（保持原值）或 `agnostic`（无关心）。
- **`vma`（mask agnostic）**：掩码为 0 的位置写什么——同上。

选择 `agnostic` 让硬件**自由发挥**（可跳过、可写任意值），换来更高性能；选择 `undisturbed` 保证旧值保留，便于增量计算。**这是正确性与性能的显式权衡接口**，也是 RVV 相比固定 SIMD 的一个细腻之处。

## 6 核心对比表

> 本节为纯概念主题，以核心对比表替代公式解析。

| 概念 | 一句话 | 关键点 |
| --- | --- | --- |
| `vtype` | 元素宽度与寄存器组配置 | SEW + LMUL |
| `vl` | 本次实际执行长度 | 由硬件返回，≤ 请求值 |
| `vsetvli` | 运行时配置 + 返回 vl | 长度无关的开关 |
| `v0` | 掩码寄存器 | 每元素 1 位，兼任数据寄存器 |
| 掩码指令 `.t` | 条件执行 | 消除向量控制分歧 |
| `vta/vma` | 尾/掩码元素策略 | 正确性 vs 性能的接口 |

**辨析｜易错点：** 别把 `vl` 与 `vstart` 混为一谈。`vl` 是「这次执行多少」，`vstart` 是「中断/异常后从第几个元素恢复」——后者是 [[precise-exceptions-speculation-recovery]] 在向量上的应用：长向量指令被打断后，从 `vstart` 继续而非重头来。

## 7 小结

- **RVV**：32 个向量寄存器 + `vtype`/`vl` 配置，长度无关编程模型的规范实现。
- **vsetvli** 一条指令设置 SEW/LMUL 并返回实际 `vl`，是向量循环的「开关」。
- **LMUL** 把寄存器分组加长，灵活应对「寄存器装不下」。
- **掩码操作**（v0 + `.t` 后缀）把 if 语义向量化，消除控制分歧。
- **vta/vma** 显式管理尾元素与掩码元素的写策略。
- RVV 与 SVE 是「可扩展向量」双雄，与固定 SIMD 划出界限——见下节的本质对比。
