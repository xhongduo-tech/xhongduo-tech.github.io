## 为什么 RVV 是长度无关模型的实现

上一节的「向量长度无关」是理想，**RVV（RISC-V V 扩展）**是把它落地的规范。2021 年定稿的 RVV 1.0 为任意硬件宽度（VLEN = 128/256/512 bit…）提供一套统一的向量指令，软件用一条 **vsetvli** 告诉硬件「我要多宽的元素、用几组寄存器」，硬件回答「这次实际能做多长」。<span class="marginnote">RVV 与 ARM SVE 是当代两大「可扩展向量」设计：都提供长度无关编程。区别在于 RVV 允许<strong>运行时</strong>通过 vsetvli 自由切换元素宽度与寄存器组数，灵活性更高——见 [[vector-vs-simd]] 的本质对比。</span>

## 1 RVV 的寄存器与配置：v0–v31 + vtype/vl

RVV 提供 **32 个向量寄存器 v0–v31**，每个宽度为硬件定义的 **VLEN** 位。另有两组核心 CSR：

| CSR | 作用 |
| --- | --- |
| vtype | 元素宽度（SEW）、寄存器组（LMUL）、掩码/尾元素策略 |
| vl | 当前向量长度（本次执行多少个元素） |
| vstart | 指令恢复执行的起点（用于中断/异常重放） |
| vcsr | 状态与控制位（含舍入模式 vxrm、饱和标志 vxsat） |

**核心概念**：vtype 决定「每个元素多宽、一个向量寄存器能装几个元素」，vl 决定「这次实际执行几个」——**类型与长度分离**，这是 RVV 优雅的根基。

## 2 vtype：SEW 与 LMUL

vtype 里两个关键字段：

**SEW（Selected Element Width）**：元素位宽，可取 8/16/32/64（V 扩展还支持 fp16/bf16 等）。SEW 越小，每个寄存器装的元素越多。
**LMUL（vector register group Multiple）**：把 $m$ 个向量寄存器**拼成一组**当「一个更长的向量寄存器」用，$m \in \{1,2,4,8\}$（也有分数 $1/2,1/4,1/8$）。LMUL = 2 时，**向量寄存器组**实际占用 v0–v1（连续两个寄存器）。<span class="marginnote">LMUL 的作用是「<strong>软件主动加长</strong>」：当 128 位 VLEN 装不下 64 位元素的浮点运算时，用 LMUL=2 让有效长度翻倍。代价是占用更多寄存器，编译器在可用性与长度之间权衡。</span>

有效向量长度 = $\frac{\text{VLEN} \times \text{LMUL}}{\text{SEW}}$（个元素）。

代入数字感受一下。设 VLEN = 128、SEW = 64、LMUL = 1：有效长度 $= 128 \times 1 / 64 = 2$——一次只能算 2 个 64 位元素，效率惨淡；把 LMUL 升到 2，有效长度翻倍到 4。反过来 SEW = 8、LMUL = 1 时，一个寄存器能装 16 个字节，处理字节数组时 LMUL = 1 就够。**「元素越宽，越需要 LMUL 加长」**——这正是编译器向量化浮点代码时自动抬 LMUL 的原因。

## 3 vsetvli：一条指令完成配置

```asm
vsetvli t0, a0, e32, m1   # 请求长度 a0；SEW=32（e32）、LMUL=1（m1）
                          # 返回实际长度到 t0（t0 = vl ≤ a0）
```

这条指令做三件事：设 SEW=32（**e32**）、LMUL=1（**m1**），**并根据 a0 请求的长度返回实际 vl 到 t0**——返回的 $vl = \min(a0,\ \text{硬件上限})$。典型循环：

```asm
loop:
    vsetvli t0, a0, e32, m1   # 本次块长 t0 = min(a0, 硬件上限)
    vle32.v v1, (a1)          # 装载 vl 个 32 位元素
    vadd.vv v2, v1, v3        # 向量加：v2[i] = v1[i] + v3[i]
    vse32.v v2, (a2)          # 存回内存
    slli    t1, t0, 2         # 字节偏移 = vl × 4
    add     a1, a1, t1        # 源指针前进 vl 个元素
    add     a2, a2, t1        # 目的指针前进 vl 个元素
    sub     a0, a0, t0        # 剩余元素数减少 vl
    bnez    a0, loop          # 未完继续
```

循环每次按 **vl** 前进，块长随硬件自适应——**这就是长度无关代码长在汇编里的样子**。

注意 vsetvli 的返回值语义：若 `a0` 请求的长度超过硬件上限，返回的 `vl` 会**小于**请求值——代码必须按返回的 `vl`（而非请求值）前进指针。忽略这条，是手写向量汇编最常见的越界错误：缓冲区按错误的 `vl` 读长或写长，破坏相邻数据。

## 4 掩码操作：条件执行的向量版

向量要处理 **if-else 分支**这类条件，靠**掩码（mask）**。RVV 用 **v0 兼任掩码寄存器**，每元素 1 位：

```asm
vsetvli  t0, a0, e32, m1
vle32.v  v1, (a1)           # 装载数据
vmseq.vv v0, v1, v2         # 计算掩码：v1[i] == v2[i] 的位置置 1
vadd.vv  v3, v1, v4, v0.t   # 仅掩码位为 1 的元素执行加法
vse32.v  v3, (a2), v0.t     # 按掩码存回（掩码位为 0 的元素不写）
```

**核心概念**：**掩码操作**让向量指令对**部分元素**生效——被掩码的元素要么保持不动、要么写「无关心」值。RVV 指令后缀 **`.t`**（如 **`vadd.vv v3, v1, v4, v0.t`**）表示「仅在 v0 掩码位为 1 的位置执行加法」。<span class="marginnote">掩码把「分支 + 执行」翻译成「计算掩码 + 按掩码执行」，消除了向量化时最难处理的<strong>控制流分歧</strong>。这与 GPU 里 [[gpu-branch-divergence]] 的掩码执行是同构思想。</span>

掩码寄存器不只是「布尔开关」——RVV 允许把掩码当作**1 位元素的数据**参与向量比较与逻辑运算（如 `vmand`、`vmxor`、`vmset.m`），甚至用它做稀疏压缩（`vcompress.vm`）。**掩码本身是一种「窄向量」**，这层抽象让条件逻辑可以像数据一样被向量化、被组合，是 RVV 表达力强于传统 SIMD 掩码（如 AVX 的 `k` 寄存器）的地方。

## 5 尾元素与「无关心」策略

循环末尾的**余数元素**（长度不足一块）和掩码为 0 的元素，是「不想要的元素」。RVV 用 **vtype** 里的两个位指定它们的处理：

- **vta（tail agnostic）**：尾元素写什么——undisturbed（保持原值）或 agnostic（无关心）。
- **vma（mask agnostic）**：掩码为 0 的位置写什么——同上。

选择 **agnostic** 让硬件**自由发挥**（可跳过、可写任意值），换来更高性能；选择 **undisturbed** 保证旧值保留，便于增量计算。**这是正确性与性能的显式权衡接口**，也是 RVV 相比固定 SIMD 的一个细腻之处。

## 6 核心对比表

> 本节为纯概念主题，以核心对比表替代公式解析。

| 概念 | 一句话 | 关键点 |
| --- | --- | --- |
| vtype | 元素宽度与寄存器组配置 | SEW + LMUL |
| vl | 本次实际执行长度 | 由硬件返回，≤ 请求值 |
| vsetvli | 运行时配置 + 返回 vl | 长度无关的开关 |
| v0 | 掩码寄存器 | 每元素 1 位，兼任数据寄存器 |
| 掩码指令 `.t` 后缀 | 条件执行 | 消除向量控制分歧 |
| vta/vma | 尾/掩码元素策略 | 正确性 vs 性能的接口 |

**辨析｜易错点：** 别把 **vl** 与 **vstart** 混为一谈。**vl** 是「这次执行多少」，**vstart** 是「中断/异常后从第几个元素恢复」——后者是 [[precise-exceptions-speculation-recovery]] 在向量上的应用：长向量指令被打断后，从 **vstart** 继续而非重头来。

## 7 小结

- **RVV**：32 个向量寄存器 + vtype/vl 配置，长度无关编程模型的规范实现。
- **vsetvli** 一条指令设置 SEW/LMUL 并返回实际 vl，是向量循环的「开关」。
- **LMUL** 把寄存器分组加长，灵活应对「寄存器装不下」。
- **掩码操作**（v0 + `.t` 后缀）把 if 语义向量化，消除控制分歧。
- **vta/vma** 显式管理尾元素与掩码元素的写策略。
- RVV 与 SVE 是「可扩展向量」双雄，与固定 SIMD 划出界限——见下节的本质对比。
