## 为什么「最快的机制」成了「最大的漏洞」

2018 年 1 月，Spectre 与 Meltdown 同时曝光，几乎**所有现代乱序处理器**都中招。它们的共同根源惊人地朴素：**推测执行与乱序执行（第二篇的全部内容）在「回滚」时只恢复了架构状态（寄存器、内存），却留下了微架构痕迹（Cache 状态、时序）**——攻击者用这些痕迹反推出不该知道的数据。<span class="marginnote">这是对整个第二篇的「清算」：[[hardware-speculation-rob]] 的 ROB 保证「猜错回滚后程序结果正确」——<strong>但「结果正确」≠「没留下痕迹」</strong>。安全要求的是「无痕迹」，性能要求的是「猜」，两者在 2018 年正面相撞。</span>

## 1 侧信道：不通过「门」泄露

**核心概念**：**侧信道（side channel）**：信息不通过程序的**预期接口**（返回值、报错）泄露，而是通过**物理/时序副作用**——运行时间、功耗、Cache 命中与否。

最经典的载体是 **Cache 时序侧信道**：攻击者测量「访问某内存块的时间」——**如果快，说明目标把它读进了 Cache**；Cache 里有什么，就是目标「访问过什么」的间接证据。**「目标访问了哪块内存」本身就是机密**。

## 2 瞬态执行：回滚也留下痕迹

**核心概念**：**瞬态执行（transient execution）**：推测执行的指令在「确认猜错」前**暂时执行**、随后被回滚。回滚**撤销了架构效果**（寄存器不改、内存不写），但**不撤销微架构效果**（Cache 被填充、时序被改变）。

瞬态执行与「推测失败」的关系也常被误解：推测**成功**时不回滚，指令的效果就是合法的；只有推测**失败**才回滚。攻击利用的正是「失败的那部分」——**回滚撤销的是架构承诺，撤销不了的是物理痕迹**。这一句话，是整个微架构侧信道的全部原理。

```c
if (x < bound) {               /* 分支预测器已被训练成「猜真」 */
    secret = probe[x];         /* 瞬态：越界读出机密字节       */
    temp = array[secret * 64]; /* 瞬态：用机密做访存 → Cache 留痕 */
}
/* 确认猜错后回滚：寄存器/内存复原，但 array[...] 已留在 Cache 里 */
```

**攻击的关键链**：**瞬态读机密 → 用机密做访存 → Cache 留下位置痕迹 → 攻击者测量时序还原机密**。前两步是「越权」，第三步是「泄露」，第四步是「解码」。

## 3 Meltdown：越权读取内核内存

**Meltdown**（Meltdown，Intel 受影响最重）：

**漏洞**：乱序执行让「特权检查」晚于「实际使用数据」——用户程序发出的读内核内存指令**虽然最终被拒绝**，但在拒绝前，**数据已被乱序执行引擎拿去用了**。
**利用**：
  1. 发射一条访问**内核地址**的 Load（会触发异常）。
  2. 异常被**延迟**，乱序引擎继续，把读到的机密值用来索引一个探测数组。
  3. 探测数组的某块进入 Cache。
  4. 异常最终发生、指令回滚——但 Cache 痕迹已在。
  5. 攻击者测量探测数组各块的访问时间 → 还原机密字节。

**核心概念**：Meltdown 的本质是**「异常处理不够快」**——架构承诺「越权读会失败」，但微架构在失败前已经把数据用了。**「最终失败」不等于「过程中没泄露」**。

## 4 Spectre：训练分支预测器

**Spectre**（影响所有乱序处理器）：

**漏洞**：分支预测器**可被训练**（[[branch-prediction-1bit-2bit]]）——攻击者先用合法输入把某个分支训练成「猜跳」，再让它**越界**执行。
**利用（变体 1：越界检查绕过）**：
  1. 训练分支让预测器「猜真」。
  2. 传入越界下标，预测器仍「猜真」→ 推测执行体**访问越界地址**（含机密）。
  3. 机密值索引探测数组 → Cache 留下痕迹。
  4. 回滚后测量还原——**攻击者甚至不需要真正的越界权限**。

**Spectre 与 Meltdown 的区别**：Meltdown 是「读内核的越权数据」，Spectre 是「在受害者自己的内存里越界读，再把机密通过侧信道搬出来」——**Spectre 不需要内核漏洞，纯粹靠「猜错 + 侧信道」**。

**变体划分**：Spectre 家族常按编号记忆——**变体 1（Bounds Check Bypass，越界检查绕过）**是上面的分支训练；**变体 2（Branch Target Injection）**训练的是**间接跳转的目标**，让推测执行跳到攻击者选定的「gadget」上，再借同一套 Cache 侧信道搬数据。两者本质相同：**让推测执行访问攻击者控制的位置，再用时序还原**。

## 5 侧信道测量：Flush+Reload 与 Prime+Probe

攻击者如何「测量 Cache」？两大经典手法：

**Flush+Reload**：先用 `clflush` 把探测数组从 Cache 里**逐块清掉**，等受害者执行完，再逐一**重读**——读得快的那块，就是受害者碰过的（要求与受害者共享内存，如共享库）。
**Prime+Probe**：先用自己的数据**填满** Cache（Prime），受害者执行时把其中若干块顶出，事后逐块计时（Probe）——慢的块就是被受害者挤掉的。它不要求共享内存，适用范围更广，是现代攻击的主力。

两条路的共同点是**计时精度**：Cache 命中约几十周期、缺失约数百周期，单次测量噪声很大。攻击者通常**重复数千次取「最快时间」**，把调度、中断带来的噪声压下去，从统计里稳定地还原出每个字节。

时间差的量级具体可感：同一进程内两次对同一地址的 load，命中 L1 约 4 个周期、命中 L2 约 14 个周期、落到内存约 200 个周期。**把「4 vs 200」这个约 50 倍的窗口测准，就能以高置信度判定某块是否刚被访问过**。更精细的攻击还用 `rdtsc`/`rdpmc` 这类高精度计数器，把测量分辨率压到几个周期以内——计时越准，侧信道越锋利。

## 6 缓解措施

| 层 | 缓解 | 代价 |
| --- | --- | --- |
| 软件 | `lfence` 等序列化指令、retpoline（防分支注入） | 性能损失 |
| 操作系统 | **KPTI**（内核页表隔离，防 Meltdown） | 系统调用变慢 |
| 硬件 | 清除 Cache、序列化推测、限制越界推测 | 新一代 CPU 的微架构改动 |

**核心概念**：缓解的难处在于**性能与安全的根本冲突**——「推测执行」是性能的命根子，而「堵住瞬态泄露」需要**阻止或掩盖推测的副作用**。KPTI 当年让系统调用慢 5–30%，retpoline 让间接调用慢几个百分点——**安全的第一笔账单由性能支付**。

**辨析｜易错点：** 别把「防御」与「消除」混为一谈。补丁、固件、微码更新**降低**攻击成功的概率，但**只要推测执行还存在，泄露通道就还在**——后续的 MDS、ZombieLoad、TAA 等漏洞正是同一族问题的不同变体。**彻底的解法只能在下一代微架构里把「推测不留下可观测副作用」写进硬件**，而这恰恰是性能最难让步的地方。

泄漏通道后来被反复重开：**2019 年的 MDS/ZombieLoad** 从 CPU 的各类内部缓冲（行填充缓冲、store 缓冲）里掏出数据，**2020 年的 TAA** 让 TSX 事务在回滚时也留下痕迹——**每一次都印证「只要缓冲不隔离，侧信道就不会绝种」**。防御因此层层加码：从改微码、插 `lfence`，到新一代 CPU 在硬件里做「缓冲隔离」（如 Intel 的 `MD_CLEAR`），再到把访存计时指令的精度人为降级。**攻防双方在「CPU 内部到底藏着哪些临时状态」这个战场上周旋**，这已经超出了传统软件安全的射程。

**辨析｜易错点：** Spectre/Meltdown **不是软件 bug**——是**微架构的固有特性**。补丁只能「堵洞」，不能「除根」；根本解法是**重新设计推测执行**（下一代 CPU 在硬件里限制瞬态泄露）。<span class="marginnote">这给体系结构上了深刻一课：<strong>性能优化的每一个「偷偷摸摸」，都可能是未来的安全漏洞</strong>。安全必须从设计之初就与性能一同权衡，而不是事后打补丁。</span>

## 7 核心对比表：Spectre vs Meltdown

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | Meltdown | Spectre |
| --- | --- | --- |
| 利用机制 | 乱序执行先于特权检查 | **分支预测被训练** |
| 读什么 | 内核内存（越权） | 受害者进程内存（越界） |
| 谁受影响 | Intel 为主 | 所有乱序处理器 |
| 修复 | KPTI 等 | 软件+硬件，更顽固 |
| 变体 | 变体 3（Meltdown） | 变体 1 / 变体 2 |

## 8 小结

- **侧信道**：通过时序/Cache 状态等**非预期接口**泄露信息。
- **瞬态执行**：推测指令回滚后**架构状态复原、微架构痕迹残留**——泄露的根源。
- **Meltdown**：乱序先于特权检查，越权读内核数据。
- **Spectre**：训练分支预测器越界执行，把机密搬进 Cache。
- 缓解（**KPTI、retpoline、fence、硬件限制**）都要**用性能买单**。
- 体系结构的教训：**安全与性能必须一同设计**——推测执行是双刃剑。
