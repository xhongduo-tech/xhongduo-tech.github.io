## 为什么 chiplet 之间也要「协议」

[[chiplet-advanced-packaging]] 把大芯片拆成小片，但小片之间怎么通信？Intel 用自己的 Foveros/EMIB、AMD 用 Infinity Fabric、Apple 用自家接口——**彼此不兼容**。2022 年，Intel、AMD、ARM、TSMC、Samsung 等巨头联合推出 **UCIe（Universal Chiplet Interconnect Express）**，要成为 chiplet 互连的「USB 标准」。<span class="marginnote">对照 [[network-on-chip]]：NoC 是片内互连，UCIe 是「封装内 die 与 die 的互连」——<strong>把「片内网络」的思维扩展到「封装内网络」，并标准化</strong>。</span>

## 1 UCIe 是什么

**核心概念**：**UCIe** 定义 **die-to-die（裸片间）互连**的完整标准——物理层、协议层、软件层，让**不同厂商的 chiplet 能拼在一起即插即用**。

**物理层**：定义 die 之间的**高速串行接口**（最高 32 GT/s/引脚），支持 2.5D 中介层与有机封装两种形态。
**协议层**：复用 **PCIe/CXL** 协议栈——**软件生态直接继承**（见第 3 节）。
**愿景**：像 PC 装机一样**混搭** CPU/GPU/IO/加速 chiplet。

## 2 层次结构：从比特到软件

| 层 | 职责 | 类比 |
| --- | --- | --- |
| **PHY** | 电气信号、时钟、均衡 | USB 的物理口 |
| **Die-to-Die 适配层** | 链路管理、对齐、重传 | 数据链路层 |
| **协议层** | PCIe/CXL 语义 | 网络协议 |
| **软件/测试** | 系统软件、一致性 | 驱动 |

**核心概念**：UCIe 的高明之处在于**协议层直接借 PCIe/CXL**——操作系统、驱动、虚拟化**全部复用**，不需要为新接口重写软件栈。**标准化的对象主要是物理接口与封装形态，协议层是「拿来主义」**。

## 3 与 PCIe/CXL 的关系

**PCIe**：板卡级互连（主机到外设）。
**CXL**：基于 PCIe 的**缓存一致性、内存互连**协议（[[cxl-interconnect]]）。
**UCIe**：封装内 die 到 die 的互连——**它承载 CXL/PCIe 协议**，把「板卡级」的语义下沉到「封装级」。

```text
┌───────────────────────────────────────────────┐
│       软件层（驱动 / 虚拟化 / 系统软件）        │
├───────────────────────────────────────────────┤
│        协议层：PCIe / CXL 语义（直接复用）      │ ← UCIe 只重定义这段之下
├───────────────────────────────────────────────┤
│   Die-to-Die 适配层（对齐 / 重传 / 链路管理）  │
├───────────────────────────────────────────────┤
│        PHY：高速串行接口（最高 32 GT/s）       │
└───────────────────────────────────────────────┘
          ↑ 毫米级封装内布线（UCIe 负责这一段）
```

**辨析｜易错点：** UCIe 不是「封装版 PCIe」这么简单——它的物理层是为**超短距离、超高密度**优化的（毫米级布线、每毫米带宽远高于板卡）。**UCIe 定的是「最后一毫米」，PCIe 定的是「最后几厘米」**。

复用的回报是巨大的**软件红利**。PCIe 的驱动、地址翻译服务（ATS）、进程地址空间标识（PASID）、SR-IOV 虚拟化——这些在操作系统里耕耘了二十年的生态，UCIe 芯片**不用重写就能用**。对数据中心来说，这意味着往 CPU 旁加一颗加速 chiplet 时，hypervisor 与内核只需「认出这是 PCIe 设备」，芯片就自动可用。**生态继承，是 UCIe 比「从零定义一套新协议」聪明得多的地方**——这也是它背后站着 Intel、AMD、ARM、TSMC 的原因。

物理层还有一个常被忽略的细节：**UCIe 把封装形态标准化了**。2.5D 形态下 die 通过硅中介层（或有机基板）并排放置，凸点间距（bump pitch）只有 25–55 µm；UCIe 2.0 的 3D 形态更进一步，把 die **垂直堆叠**起来。**间距越密、距离越短，信号越干净**——这正是 die-to-die 接口敢跑到每引脚 32 GT/s、而板卡级 PCIe 长期只有 16 GT/s 的原因。走线再长一些就需要加 **retimer（重定时器）**恢复信号质量，这是 UCIe 在「超短距离优化」与「保留一定布线性」之间的折中。<span class="marginnote">对照 [[sdram-ddr-evolution]]：DDR 靠「更宽的接口 × 更高的频率」提升带宽，UCIe 靠「更密的引脚 × 更短的距离」——<strong>把带宽的物理账从板卡搬进了封装</strong>。</span>

正因为通道短、信号快，die-to-die 接口的**可靠性账**也和板卡不同：UCIe 在 Die-to-Die 适配层内置了**错误检测与重传（retry）**机制，类似「迷你链路层」——发现坏包就打回重发，而不像板卡级接口那样主要依赖协议层兜底。对数据中心来说，「芯片之间的链路也要可靠」是底线：一颗坏 flit 若悄悄溜进主存一致性协议，可能演变成整个系统的数据损坏。**UCIe 把「链路可靠」从板卡级下沉到了封装级**，这让异构 chiplet 的混搭不再以「碰运气」为前提。

## 4 为什么 UCIe 是行业大事

**破除私有围墙**：chiplet 不再只能买一家——**A 家的 CPU 配 B 家的 IO、C 家的加速器**成为可能。
**生态放大**：像 USB/PCIe 当年统一外设一样，UCIe 想让 chiplet 市场「PC 化」。
**成本分摊**：小公司不用做整片 SoC，做一颗「专业 chiplet」就能进生态。

良率账是 chiplet 背后被反复引用的动机，但真要算清楚并不简单。在独立的泊松缺陷模型下，一块 700 mm² 的大芯片（缺陷密度使良率约 50%）切成 4 块 175 mm² 的小片，单片良率升到约 84%，但「4 片全好」的概率仍是 $0.84^4 \approx 50\%$——**单看面积，分割并不直接提升整体良率**。分割真正的收益在别处：坏片可以被**单独降级或丢弃**（有冗余时系统照常可用）、不同功能片能用**不同成熟度的工艺**分开制造、以及突破单芯片的掩模版（reticle）尺寸上限。**把「大而全」换成「小而拼」，UCIe 是让这种拼法成本可接受的标准化前提**。

## 5 挑战与现状

| 挑战 | 内容 |
| --- | --- |
| 标准成熟度 | UCIe 1.0/2.0 刚发布，生态仍在建 |
| 测试与验证 | 混合 chiplet 的互操作测试复杂 |
| 供应链 | 「像买内存条一样买 chiplet」尚需时间 |
| 竞争 | 各家私有接口仍占主导 |

落地层面，厂商正分批上车：**AMD 的 Instinct MI300 系列、Intel 的 Max 系列（前 Ponte Vecchio）、Marvell 的自定义计算（custom compute）chiplet 都公开宣称采用 UCIe**。最先落地的往往是「自家 chiplet 先按 UCIe 互连」——先做内部标准化，再逐步开放给第三方。这条「先内后外」的路线，与当年 PCIe 先从服务器走量、再覆盖全市场的路径如出一辙。

**核心概念**：UCIe 是**愿景大于现状**的标准——它的价值在于确立方向：**把「封装内互连」变成开放接口，让异构集成（[[chiplet-advanced-packaging]]）从单厂专属走向全行业共享**。<span class="marginnote">回看历史：PCIe 统一板卡互连、以太网统一网络互连——<strong>UCIe 想统一的是「封装内互连」</strong>。标准成了，生态才会来。</span>

标准本身在快速演进：**UCIe 1.1** 补充管理/调试支持，**UCIe 2.0**（2024 年发布）引入 3D 堆叠（stacked die）互连与更高的每引脚速率，把目标从「2.5D 中介层」扩展到「垂直堆叠」——呼应 chiplet 向 3D 集成的整体趋势。**每一次发布，都是把「混搭」从口号往前推一步**。

## 7 数字与类比：UCIe 有多快

UCIe 1.0 的 die-to-die 接口每个引脚最高 **32 GT/s**；一个标准 chiplet 接口可以有**数千个引脚**——总带宽可达 **1 TB/s 以上**，远高于板卡级 PCIe 的几十 GB/s。为什么？因为布线距离从「厘米」缩到「毫米」，信号可以跑得更快、摆得更多根。

把带宽换算成可感的数字：一个 64 位宽的 UCIe 接口在 32 GT/s 下，每引脚单向 32 Gbps、64 引脚即约 2 Tbps ≈ 250 GB/s——而一块 NVMe SSD 的顺序读才约 7 GB/s，DDR5 一个通道约 50 GB/s。**die-to-die 接口的带宽不是「快」，是「极快」**——正因为布线距离以毫米计、每比特能耗以皮焦计，才敢堆这么多对差分线。

类比：**UCIe 之于 chiplet，就像 PCIe 之于扩展卡、以太网之于服务器**——它把「封装内互连」变成开放的接口标准。回到 [[chiplet-advanced-packaging]] 的问题：拆开容易，拼回来的「缝隙」就是 die-to-die 接口；UCIe 想让这条缝隙变成「标准尺寸的插槽」。

与 [[network-on-chip]] 的对照更清楚：NoC 处理的是毫米级片内网络、功耗预算以毫瓦计，UCIe 面对的是厘米级封装内网络、功耗预算以瓦计——**两者是同一套「互连思维」在不同尺度下的应用**。UCIe 把 NoC 里成熟的分层流控、信用机制与拓扑思想，移植到了 chiplet 与 chiplet 之间；反过来，下一代 NoC 也在吸收 UCIe 的物理层经验。**从片内到片间，「把网络装进封装」是同一件事的连续谱系**。

## 8 小结

- **UCIe** 是 chiplet 互连的开放标准：PHY + 协议 + 软件三层齐备。
- 协议层**复用 PCIe/CXL**，软件生态直接继承。
- UCIe 定「最后一毫米」，PCIe/CXL 定「最后几厘米」——互补。
- 愿景：**chiplet 市场 PC 化**，混搭不同厂商的小片。
- 现状：标准刚起步、生态在建——但方向已定：**封装内互连开放化**。
