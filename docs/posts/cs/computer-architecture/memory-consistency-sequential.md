# 一致性模型（Memory Consistency Model）：顺序一致性

<div class="epigraph">

## 为什么「读写次序」要单独立法

[[cache-coherence-snooping]] 解决「单个地址的写是否传播、是否串行化」。但并行程序还需要知道**跨地址**的次序：处理器 **P1** 先写 **A** 再写 **flag**，处理器 **P2** 看到 **flag** 变了，能保证看到 **A** 也变了吗？——这个问题一致性（coherence）回答不了，要由**一致性模型（consistency model）**来定义。<span class="marginnote">教科书式比喻：<strong>coherence 管「一个变量的账目」，consistency 管「多个变量的先后</strong>」。顺序一致性（SC）是最直觉、也最贵的那个模型——理解它，才理解现代处理器为什么「乱序」。</span>

## 1 顺序一致性（SC）的定义

**核心概念**：**顺序一致性（Sequential Consistency, SC）**（Lamport, 1979）：

1. **所有处理器的内存操作**（读、写）都按某个**全局顺序**执行；
2. **每个处理器自己的操作**，在这个全局顺序里保持**程序序**。

也就是说：存在一个所有处理器都认同的「时间线」，每个处理器在其上的操作顺序与它的程序一模一样。**任何执行结果，都等价于「把各处理器的操作按程序序交错成一个串行执行」**。

## 2 一个经典例子：flag 同步

```c
/* 处理器 P1 */                    /* 处理器 P2 */
A = 1;                          while (flag == 0);  /* 自旋等待 flag */
flag = 1;                       print(A);           /* SC 下必输出 1 */
```

**SC 下**：P2 的**自旋**循环看到 **flag** 时，**A** 的写必然已经完成（因为 P1 的程序序是 A 先、flag 后，全局顺序保持程序序）——**print 一定输出 1**。

**弱模型下**：P1 的两条写可能被硬件重排（store buffer、乱序执行、编译器优化），P2 看到 **flag** 时 **A** 可能还是旧值——**print 可能输出 0**。这就是为什么 SC 这么重要：它是程序员「显然正确」直觉的模型化。<span class="marginnote">真实世界残酷：<strong>现代 CPU 与编译器都默认重排</strong>，所以这段朴素代码在 x86 上也未必可靠——要靠栅栏/原子指令的 release 语义。这正是 [[synchronization-primitives]] 的 acquire/release 存在的原因。</span>

## 3 为什么 SC 很难做快

SC 要求「所有操作有全局顺序」——这恰好是高性能硬件的天敌：

- **乱序执行**（[[modern-superscalar-pipeline]]）主动重排指令，与「保持程序序」直接冲突。
- **写缓冲（store buffer）**：写操作先进缓冲、后进内存——读可能「越过」未完成的写。
- **缓存层次**：不同核的 Cache 让「何时可见」不统一。
- **编译器**：也会重排、消除看似无用的写。

严格实现 SC 意味着**每个内存操作都要全局同步**——性能灾难。于是出现了「放松」的模型（[[weak-release-consistency]]）：**允许重排，但提供屏障指令让程序员在需要时恢复顺序**。

## 4 DRF 模型：现代折中

**核心概念**：**数据竞争自由（Data-Race-Free, DRF）模型**——现代 CPU 的妥协方案：

- **规则**：如果程序没有**数据竞争**（两个线程访问同一位置、至少一个写、且没有同步），那么程序表现得像 **SC** 一样。
- **实现**：同步操作（锁、原子、栅栏）带 acquire/release 语义，其余操作可自由重排。
- **契约**：**写对同步的程序 = 简单；写错（有竞争）的程序 = 未定义**——硬件不替你兜底。

**辨析｜易错点：** DRF 不是「硬件支持 SC」，而是「对无竞争程序假装 SC」。它把「顺序保证」的负担从每次访存转移到同步点上——**多数时间快，同步时贵**。理解这一点，就理解了现代并发编程的全部规则。

## 5 核心对比表：SC vs 弱模型

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 顺序一致性（SC） | 弱/放松模型（含 DRF） |
| --- | --- | --- |
| 全局顺序 | 必须存在 | 不需要 |
| 程序序保持 | 强制 | 可重排 |
| 编程难度 | 低（直觉正确） | 高（要理解屏障） |
| 硬件/编译器 | 极贵 | 快 |
| 现代 CPU | 教学标准 | **实际使用** |
| 正确程序写法 | 任意 | 同步点 + 屏障 |

## 6 小结

- **一致性模型**定义「跨地址的读写次序」；coherence 只管单地址，consistency 管全局。
- **SC**：存在全局顺序、每处理器保持程序序——最直觉也最贵。
- **flag 同步**例子是 SC 的试金石：SC 下 **print** 必得 1，弱模型下可能得 0。
- **SC 慢**因为与乱序、写缓冲、缓存、编译器重排全部冲突。
- **DRF 模型**是折中：无竞争程序像 SC，有竞争未定义——现代 CPU 的现实契约。
