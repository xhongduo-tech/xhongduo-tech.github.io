## 为什么「做得出芯片」不如「喂得饱芯片」

[[dsa-rise-background]] 讲了专用硬件能快 10 倍，但**这 10 倍只是峰值**。真实性能取决于：**有没有编译器能把你的计算映射到那套专用结构上**。历史上 DSA 失败的案例，多数不是芯片不行，而是**软件栈没跟上**——程序员写不出、编译器映射不了，峰值永远只是峰值。<span class="marginnote">对照 [[vliw-epic]] 的 Itanium：VLIW 硬件很简单，但编译器写不好就白搭。<strong>DSA 把同样的赌注押得更大——专用到连指令集都不是通用的</strong>。</span>

## 1 DSA 软件栈的三层挑战

| 层 | 挑战 |
| --- | --- |
| **编程模型** | 程序员用什么写？通用语言、DSL、还是库？ |
| **映射** | 编译器怎么把算子放进脉动阵列/数据流？ |
| **可移植** | 换一代硬件，软件要不要重写？ |

**核心概念**：通用 CPU 的软件栈（C + 编译器 + OS）花了 40 年成熟；DSA 想快速落地，必须用**更聪明的编译器**把「高层算子 → 专用硬件」的鸿沟填上。

## 2 编程模型的谱系

| 模型 | 例子 | 抽象层次 | 适用 |
| --- | --- | --- | --- |
| **库** | cuDNN、oneDNN | 极高层（调函数） | 常见算子 |
| **DSL** | Halide、TVM、Triton | 声明式（写计算+调度） | 自定义算子 |
| **通用语言+编译** | CUDA、SYCL | 中层 | 灵活但难 |
| **编译器自动映射** | XLA、MLIR | 高层（图级） | 训练/推理框架 |

**辨析｜易错点：** DSA 编程不是「用专用语言写死」——主流趋势是**通用高层 API + 编译器映射**。你写 TensorFlow/JAX，XLA 编译到 TPU；你写 PyTorch，Triton/TVM 编译到加速器。**对大多数程序员，DSA 应当「透明」**。

## 3 编译器与中间表示：MLIR / TVM

**核心概念**：**MLIR（Multi-Level Intermediate Representation）**：一种可扩展的多级中间表示，让「高层框架 → 低层硬件」的每一级都有对应的 IR，编译器分阶段下降（lowering）——这正是 [[cs-compilers]] 分阶段思想的现代版。

- **高层 IR**：张量算子（像数学表达式）。
- **中层 IR**：循环结构、布局。
- **低层 IR**：脉动阵列的数据流、访存时序。

**TVM** 是另一条路：**端到端自动编译**——输入框架模型，输出针对指定 DSA 的机器码，中间的调度（loop tiling、数据流选择）由**自动调优搜索**决定。<span class="marginnote">DSA 编译器把 [[nn-dataflow-stationary]] 的数据流选择、[[cache-optimization-compiler]] 的循环变换、[[loop-level-parallelism-dependency]] 的依赖分析全部自动化——<strong>一次映射，三套功夫</strong>。</span>

## 4 自动调优：搜索调度

DSA 的调度空间巨大（分块、顺序、数据流、访存缓冲），手写优化不现实。**自动调优（auto-tuning）**让机器自己搜：

```
TVM/Ansor 流程：
  生成候选调度 → 在真硬件上跑 → 记录耗时 → 学习/进化 → 收敛到最优
```

**核心概念**：把「优化」从「专家经验」变成「搜索+测量」——这在 DSA 上尤其有效，因为**硬件结构千差万别，人类经验难以迁移，机器搜索却能每次重新找最优**。这也是「编译器即优化器」的现代形态。

## 5 软件硬件协同设计

最好的解法是**一开始就一起设计**：

- **硬件为编译器留口子**：可预测的时序、规整的数据通路、明确的调度接口。
- **编译器为硬件定约束**：把「必须这样映射」写进 IR，避免无效搜索。
- **共同验证**：编译器的「能映射率」作为硬件设计的验收指标。

**核心概念**：**软硬协同（co-design）**：DSA 的性能上限不是单靠硬件，而是「**硬件 × 编译器能映射多少**」的乘积。Itanium 的教训（硬件强、编译器弱）与 TPU 的成功（XLA 同步开发）一正一反地证明了这一点。

## 6 核心对比表：通用 vs DSA 软件栈

> 本节为纯概念主题，以核心对比表替代公式解析。

| 维度 | 通用 CPU | DSA |
| --- | --- | --- |
| 编程 | C/Python，编译器成熟 | 库/DSL/专用编译器 |
| 映射 | 指令选择 + 调度 | **算子 → 专用数据通路** |
| 可移植 | 二进制兼容 | 换代常要重编译 |
| 生态 | 极成熟 | 碎片化、快速演进 |
| 瓶颈 | 硬件 | **软件映射率** |

## 7 小结

- DSA 的真实性能 = **峰值 × 编译器映射率**——软件栈是真正的瓶颈。
- 编程模型谱系：**库 → DSL → 通用语言 → 自动编译**，趋势是高层透明。
- **MLIR/TVM** 用多级 IR 把「高层算子 → 专用硬件」分阶段映射。
- **自动调优**把优化从专家经验变成「搜索+测量」。
- **软硬协同设计**：硬件为编译器留口子、编译器为硬件定约束。
- Itanium 败于软件、TPU 成于软件——**DSA 的一半是编译器**。
