## 为什么从电子邮件安全开始

我们之前讨论的 TLS、IPSec 都是**连接型**安全：双方建立一条实时连接，握手、加密、收尾。但电子邮件是另一类动物——它是**异步存储转发**：邮件从你的客户端出发，经多个中继服务器，可能几个小时之后才被收件人打开。**没有「连接」可言，TLS 只能保护「客户端到服务器」这一小段，保护不了邮件躺在服务器上、以及服务器之间传递的全程。**

于是邮件安全必须做到**端到端**：在发件人那里就加密/签名，收件人那里解密/验签，中间任何服务器都只看到密文。实现端到端邮件安全的两大体系，就是 **PGP** 与 **S/MIME**。<span class="marginnote">连接安全（TLS）与端到端安全（PGP/S/MIME）是两种不同的威胁模型：前者假设「通道不可信」，后者假设「通道上的所有节点都不可信，只有收发两端可信」。电子邮件恰恰需要后者。</span>

还有一个实际的工程约束：邮件系统有**文本兼容性**问题。SMTP 协议最初只可靠传输 7 位 ASCII 文本，而加密后的密文是任意二进制——直接塞进邮件会损坏。于是 PGP 与 S/MIME 都用 **Base64（radix-64）编码**把二进制密文转成 ASCII，这也是「邮件加密」看起来总是一长串乱码字符的原因。

## 1 邮件的威胁模型

对一封邮件，攻击者可以做的坏事分两类。**被动攻击**：窃听——邮件在网络上明文传输，或从服务器上直接读取；**主动攻击**：冒充他人发信、篡改邮件内容、伪造发件地址、事后抵赖说「我没发过」。

一张表看清每类威胁对应哪种安全服务：

| 威胁 | 安全服务 | 实现工具 |
| --- | --- | --- |
| 窃听内容 | 机密性 | 对称加密（混合体制） |
| 内容被篡改 | 完整性 | 哈希 + MAC/签名 |
| 冒充发件人 | 数据源认证 | 数字签名 |
| 事后抵赖 | 不可否认性 | 数字签名 |

**重点：邮件安全的核心是「签名 + 加密」的组合**——签名解决「谁发的、改没改、赖不赖得掉」，加密解决「谁看得见」。两条路线（PGP 与 S/MIME）都提供这两样，区别在信任模型与生态。

还应区分「**邮件内容安全**」与「**邮件传输安全**」两个层面：传输安全用 TLS 保护「客户端—服务器、服务器—服务器」的每一段链路；内容安全用 PGP/S/MIME 保护「发件人到收件人」的端到端全程。两者不冲突、也不互相替代——**传输安全是「路不丢」，内容安全是「信不拆」**，现实的邮件安全是两者叠加。

还应注意**保护对象**的层次差别：邮件从发件人到收件人要经过发件服务器、多级中继、收件服务器，TLS 只保护「客户端—服务器」各段，而 PGP/S/MIME 从发件人客户端一路保护到收件人客户端。**服务器上的邮件、服务器间的转发，只有端到端方案能覆盖。**

## 2 PGP：密码学的「平民武器」

**PGP（Pretty Good Privacy）** 由菲利普 · 齐默尔曼（Phil Zimmermann）于 1991 年发布，初衷是给普通人一把够用的邮件加密工具。它的技术路线是**把本专题前几篇的零件全部组合起来**，提供五类服务：认证、机密性、压缩、电子邮件兼容（Base64 编码）、分片重组。

PGP 的加密是教科书级的混合体制：随机生成一把一次性**会话密钥** $K_s$，用 $K_s$ 加密邮件正文（对称，快），再用收件人的**公钥**加密 $K_s$（非对称，解决分发）。收件人先解出 $K_s$，再解正文。签名则照例是「哈希 → 私钥签名」。<span class="marginnote">PGP 的每封邮件都随机产生新的会话密钥——「一次一密」原则在邮件场景的落地。即使某封邮件的会话密钥泄露，也只损失这一封。</span>

PGP 用**密钥环（key ring）** 管理密钥：**私钥环**存放自己的私钥（用口令加密保护），**公钥环**存放收集来的他人公钥。加解密时按用户 ID 查环，签名验证时按发件人 ID 找公钥——密钥环是 PGP 的「本地信任数据库」。

PGP 最独特的是它的**信任之网（Web of Trust）**：不依赖中央 CA，而是**由熟人互相为对方的公钥签名背书**。你相信某把公钥，是因为你信任的张三签过它；张三又信任李四签过的公钥……信任沿人脉链传播。去中心化是它的自由，也是它的软肋——信任链长度与质量完全取决于你的社交圈。<span class="marginnote">「信任之网」的实用性长期存疑：对多数用户而言，可用的信任链往往又短又脆。它在密码学史上意义重大，但商业世界最终选择了 S/MIME 的中央权威路线。</span>

## 3 公式解析：PGP 的混合加密与签名链

把 PGP 的一次邮件加密 + 签名流水线拆成公式看。设发送者 A 的私钥 $PR_a$、收件人 B 的公钥 $PU_b$，随机会话密钥 $K_s$：

$$
C_1 = E_{K_s}(P), \qquad C_2 = E_{PU_b}(K_s), \qquad S = D_{PR_a}\big(H(P)\big)
$$

- **$C_1 = E_{K_s}(P)$**：正文 $P$ 用会话密钥 $K_s$ 对称加密——便宜、快，适合长正文。
- **$C_2 = E_{PU_b}(K_s)$**：$K_s$ 用 B 的公钥加密——只有 B 能解出 $K_s$，从而解 $C_1$。公钥只「护送」一把小密钥，开销可忽略。
- **$S = D_{PR_a}(H(P))$**：签名发生在摘要上——先把正文 $P$ 哈希成 $H(P)$，再用 A 的私钥对摘要签名。收件人验签时重算 $H(P)$ 与 $E_{PU_a}(S)$ 比对，一致则证明「消息没被改、且确系 A 所发」。

一句话总结这条流水线：**PGP 的加密管「机密性」，签名管「完整性与真实性」，Base64 管「兼容性」，压缩管「效率」**——四件事互不干扰地叠在同一封邮件上。这也正是本专题第一、二、三篇那些密码学零件被组合成实际产品的范本。

## 4 S/MIME：CA 体系下的邮件安全

如果说 PGP 是「平民路线」，**S/MIME（Secure/Multipurpose Internet Mail Extensions）** 就是「正规军路线」：它由 IETF 标准化，直接依赖 **X.509 证书与 CA 体系**——每一封加密/签名邮件都绑定一张由受信任 CA 签发的证书。你不需要像 PGP 那样经营「信任之网」，因为**信任已经由证书链替你背书**。<span class="marginnote">S/MIME 与 PGP 的分歧本质上是「信任模型」的分歧：S/MIME 用集中的 CA 体系（像 PKI 篇说的证书链回溯到根），PGP 用去中心的「信任之网」。企业的邮件网关、Outlook/Exchange 生态默认走 S/MIME，就是这个原因。</span>

S/MIME 的运作依托 MIME 标准扩展出来的几个安全类型：

**`application/pkcs7-mime`**：带信封的加密邮件——邮件正文被封装进 PKCS#7 加密结构中，收件人凭私钥解封；
**`application/pkcs7-signature`**：附带签名——正文以 `multipart/signed` 组织，签名块单独附上；
**`application/pkcs10`**：证书申请请求（CSR）——新用户向 CA 申请证书时的载体。

一封典型的 S/MIME 加密邮件走三步：**发送方用收件方的公钥加密会话密钥 → 会话密钥加密正文 → 封装成 PKCS#7 信封**。解密则反向：收件方用自己的私钥解出会话密钥，再解正文。

**重点：S/MIME 与 PGP 殊途同归——都是「对称加密正文 + 公钥护密钥 + 签名证身份」的组合**，差异只在信任模型与生态。理解这一点，就抓住了邮件安全两大体系的全部共性。

## 5 核心对比表：PGP vs S/MIME

> 本篇为纯概念主题，按编辑章程以核心对比表替代公式解析。

两条路线的差异浓缩成一张表：

| 维度 | PGP | S/MIME |
| --- | --- | --- |
| 标准化 | 事实标准（RFC 4880） | IETF 标准（RFC 5751） |
| 信任模型 | 去中心的信任之网 | 集中的 CA 证书链 |
| 证书来源 | 用户互相签名背书 | CA 签发 X.509 证书 |
| 应用生态 | 独立工具链（GnuPG） | 邮件客户端/企业网关 |
| 部署门槛 | 低，个人可用 | 需 CA 与证书管理 |
| 典型用户 | 个人、活动家、极客 | 企业、政府机构 |

**重点：选择哪条路线，本质是选择「信任从哪来」**。你信熟人链，用 PGP；你信 CA 层级，用 S/MIME。多数普通用户两者的信任模型都用不好——所以现实中端到端邮件加密始终是小众，绝大多数邮件仍靠「服务器之间的 TLS」保护一小段。

## 6 邮件安全的另一面：钓鱼与域名伪造

加密解决「内容被人看、被人改」，但电子邮件还有一个**不依赖加密**的重大威胁——**钓鱼（phishing）**与**域名伪造**。攻击者伪造发件地址、仿冒品牌页面，诱骗收件人交出凭据或转账。这类攻击**完全不碰密文**，加密体系对它毫无办法。

对抗伪造的现代武器是**邮件认证协议**，它们不加密内容，而是验证「这封邮件真的来自它声称的域名」：

**SPF（Sender Policy Framework）**：域名在 DNS 里公布「哪些服务器有权以我名义发信」的 TXT 记录，收件方据此校验发件 IP 是否合法；
**DKIM（DomainKeys Identified Mail）**：发件服务器用私钥对邮件摘要签名，公钥公布在 DNS 里，收件方验签确认邮件未被篡改、确系该域名所发；
**DMARC**：在 SPF/DKIM 之上，告诉收件方「验证失败时该拒绝、隔离还是仅标记」——它是前两者的策略层。<span class="marginnote">SPF/DKIM/DMARC 是「域名的防伪体系」：加密解决「内容」，这三大件解决「身份」。现代邮件安全是「内容加密（S/MIME/PGP） + 身份认证（SPF/DKIM/DMARC）」两条线的合力——缺了身份线，加密再强也挡不住钓鱼。</span>

**辨析｜易错点：** 邮件安全最深的误解是把「加密」当成「安全的全部」。**一封 S/MIME 加密邮件，也可能来自钓鱼者**——加密证明内容保密，SPF/DKIM 才证明发件人可信。现实中 99% 的邮件攻击走的是「伪造 + 诱骗」而非「破解加密」，这一事实决定了防御的重心分配。

另一层现实是**端到端加密的普及困境**：PGP/S/MIME 需要收发双方都部署密钥、都愿意用，而这在消费者市场几乎从未实现——普通人既不会自己管密钥，也不信任对方的密钥可信度。于是「邮件安全的日常」退而求其次：**点对点段用 TLS（SMTP STARTTLS）加密，端点靠 SPF/DKIM/DMARC 验身份，敏感数据另行加密通道传输**——这是现实工程对「理想端到端」的折中。

## 7 小结

- 邮件是**异步存储转发**，TLS 只能保护客户端到服务器的一小段，端到端必须靠 **PGP / S/MIME**。
- **PGP** 走「信任之网」，**S/MIME** 走 CA 证书链——差异是信任模型，共同点是「对称加密正文 + 公钥护密钥 + 签名证身份」。
- PGP 流水线是**混合加密 + 签名 + 压缩 + Base64** 的教科书组合，邮件安全是密码学零件的最佳装配场。
- 加密管「内容保密」，**SPF/DKIM/DMARC** 管「身份可信」——两条线缺一不可。
- 现实威胁重心在**钓鱼与伪造**而非密码破解，防御必须双线并重。

在下一节，我们把加密从「有线世界」带到「无线电波」——信道完全敞开、帧在空中广播的无线环境，安全机制将被逼到极限——**无线局域网安全：802.11i 与 WPA**。
