## 为什么从入侵检测技术开始

上一篇认识了 IDS 的「骨架」：三类入侵者、HIDS/NIDS 之分、纵深防御里的位置。但 IDS 真正的心脏是它的**检测引擎**——它到底凭什么把一条事件判为「入侵」？这就是本篇的主题，也是 IDS 设计里最富争议、最有深度的一块。

检测技术分成两条截然相反的哲学路线：**特征检测**问「这个行为像不像已知的坏人？」，**异常检测**问「这个行为像不像正常？」。前者认识敌人，后者认识家园。理解这两条路线，就能看懂为什么 IDS 永远在「误报」与「漏报」之间挣扎，也能看懂蜜罐这种「反向操作」为何是检测情报的宝藏。<span class="marginnote">上一篇讲了「检测在安全体系里的位置」，本篇讲「检测引擎内部怎么工作」；下一篇防火墙讲「在流量路径上如何拦截」。三篇合起来，就是「检测与边界防御」的完整骨架。</span>

## 1 特征检测：认识已知的坏人

**特征检测（signature detection / misuse detection）** 的思路是：把已知攻击的「指纹」事先写进规则库，进来的事件与规则逐条比对，命中即报警。它像病毒扫描——查的是「见过的病毒」。

一条典型的特征规则长这样：**「某个端口在 10 秒内收到超过 20 次 SYN 包」**——这是端口扫描的指纹；**「HTTP 请求里出现 `../../etc/passwd`」**——这是目录穿越攻击的指纹。Snort 等主流开源 IDS 的规则库就是成千上万条这样的模式。

**特征检测的优点与缺点同样突出**：

**优点**：误报率低（规则精确）、检测速度快、结果可解释（能明确说出「这是哪种攻击」）；
**缺点**：**只能发现已知攻击**，规则没写过的变体与零日攻击直接漏过；规则库需要持续更新，跟不上攻击者「改一个字节绕过特征」的速度。<span class="marginnote">特征绕过是攻防对抗的主战场：攻击者把载荷做一点变形（编码、拆分、加噪声），旧特征就失效了。这也是「基于特征」永远追不上「攻击变种」的原因——它在跟一个比你更快的敌人赛跑。</span>

**辨析｜易错点：** 「特征检测误报低」不等于「特征检测安全」。**误报低换来的代价是漏报高**——对未知攻击几乎零感知。很多企业的 IDS 只配特征检测，于是对「没见过的攻击」形同虚设。这正是异常检测存在的理由。

## 2 异常检测：认识正常的家园

**异常检测（anomaly detection）** 的思路完全相反：先为系统/用户建立**正常行为画像（profile）**，再把当前行为与画像比对，**偏离足够大即报警**。它不问「这像不像坏人」，只问「这和平时比，正常吗？」。

异常检测的画像建立在各种**度量指标**上：登录时间与频率、每次会话的时长、CPU 与内存用量、访问的文件集合、网络连接模式……每个指标都有其「正常范围」——通常是均值和方差——实时行为一旦越界，就触发告警。<span class="marginnote">一个经典场景：某员工每天 9 点到 18 点从公司 IP 登录，操作固定几台服务器。某天凌晨 3 点，同一账号从陌生 IP 登录并开始批量下载源码——没有命中任何攻击特征，但行为与画像严重偏离。这正是异常检测能抓住、特征检测会放过的案例。</span>

异常检测的**优点**是能发现**从未见过的攻击**（零日、变种、内部越权），因为它不需要预先知道攻击长什么样；**缺点**是误报率高——正常行为的波动（加班到深夜、出差登录）也可能被当成异常，而且画像的建立需要一段「干净基线」期，基线本身若已受污染，检测就跟着失效。

## 3 公式解析：统计异常分数

异常检测里最朴素的实现是**基于阈值的统计方法**。对每个度量指标，维护其正常行为的历史均值 $\mu$ 与标准差 $\sigma$，定义偏离程度：

$$
\text{score}(x) = \frac{|x - \mu|}{\sigma}
$$

逐项拆解：

- **$x$**：当前观测值，比如本次登录时长、本次会话的 CPU 用量；
- **$\mu$**：该指标的历史均值，代表「正常水平」；
- **$\sigma$**：历史标准差，代表「正常波动幅度」；
- **判据**：当 $\text{score}(x)$ 超过预设阈值（如 $3$），即判定为异常。

为什么用「除以 $\sigma$」而不是直接用「距均值多远」？因为**不同指标的波动尺度不同**——CPU 用量波动几个百分点很正常，而登录次数少一次就很不寻常。除以标准差把一切指标归一化到「距正常几个标准差」的同一把尺子上，阈值才可统一设置。<span class="marginnote">这条「标准化」思想在后面统计学习里无处不在：z-score、正态性检验、异常点检测都建立在这把尺子上。若假设正常数据近似正态分布，切比雪夫不等式还给出了理论担保：无论分布如何，$|x-\mu| \ge k\sigma$ 的概率不超过 $1/k^2$——这就是阈值法的安全下界。</span>

**辨析｜易错点：** 「阈值定多少」没有标准答案，它就是**误报与漏报的调节旋钮**。阈值调高，误报降但漏报升；调低则相反。工程实践通常先跑一段基线数据，用分位数（如 99 分位）自动选取阈值，而不是拍脑袋定一个数。

单指标阈值法还有一个天然局限：**单看一个指标，很多攻击并不显著越界**——比如攻击者用「半夜登录 + 下载少量文件」的组合，单独看每一项都在正常范围。进阶做法是**多维综合评分**：把多个指标的偏离度加权求和，或训练一个分类器学习「哪些组合才算异常」——这正是从「统计阈值」走向「机器学习检测」的过渡点。

## 4 核心对比表：特征检测 vs 异常检测

> 本篇为纯概念主题，按编辑章程以核心对比表替代公式解析。

两条路线的全部差异，浓缩成一张表：

| 维度 | 特征检测 | 异常检测 |
| --- | --- | --- |
| 判断依据 | 已知攻击的模式 | 正常行为的基线 |
| 检测对象 | 已知攻击 | 未知/变种/内部越权 |
| 误报率 | 低 | 高 |
| 漏报率 | 高（对未知） | 低（对未知） |
| 规则维护 | 需持续更新特征库 | 需持续更新画像 |
| 可解释性 | 强（能指出哪种攻击） | 弱（只报「异常」） |
| 典型实现 | Snort 规则、病毒特征 | 统计模型、机器学习 |

**重点：两条路线是「认识坏人」与「认识正常」的哲学对立，实践中必须互补**。成熟的检测体系几乎总是「特征检测打底 + 异常检测兜底」：特征检测负责快速、精准地抓住已知攻击；异常检测负责发现特征库还没写进去的新威胁。单独任何一条，都只是半边防线。<span class="marginnote">现代 EDR/XDR 的检测引擎，本质就是「特征 + 异常 + 行为关联」的复合体——把两条路线的优点揉在一起，用关联分析进一步压噪。</span>

## 5 蜜罐：把猎人变成猎物

**蜜罐（honeypot）** 是入侵检测里最「反直觉」的一招：**故意部署一台没有真实价值的诱饵系统，让攻击者来攻**。正常用户不会碰它，所以**任何访问蜜罐的流量，都可以直接判定为恶意**——蜜罐因此几乎零误报。

蜜罐分两类：

**低交互蜜罐**：模拟少量服务（如假 SSH、假 Web），攻击者只能做有限交互，安全、易部署、信息有限；
**高交互蜜罐**：运行真实系统与服务，攻击者可以深入操作，捕获的攻击技术更完整，但被攻破的风险也更大。

把多个蜜罐组成网络就叫**蜜网（honeynet）**。蜜罐的价值不止「发现入侵」，更在于**情报**：攻击者进蜜罐后的每一步——用的漏洞、敲的命令、下载的工具——都被记录下来，成为研究攻击手法的第一手资料。<span class="marginnote">蜜罐是「给攻击者设计的产品」：部署得越逼真，攻击者越愿意在里面多待一会儿，你能收集到的东西就越多。高交互蜜罐甚至要精心设计「诱饵数据」让攻击者以为偷到了真东西。</span>

**辨析｜易错点：** 蜜罐**不是「防御工具」**——它挡不住任何攻击。它是**检测与情报工具**：检测的价值在于「所有访问皆恶意」的低误报判断，情报的价值在于「记录攻击者的一举一动」。把蜜罐当防火墙用，是用错了它的设计目的。

蜜罐还有一个常被低估的作用——**拖延与消耗**。攻击者在蜜罐里越投入（敲命令、下载工具、横向探测），留给真正目标的时间与精力就越少；同时他暴露给防守方的手段就越多。一个部署得当的蜜罐，等于给攻击者准备了一间「装了摄像头的空房间」。

**辨析｜易错点：** 蜜罐并非没有代价。**它只吸引「会被诱饵吸引」的攻击者**——有经验的黑客能识别蜜罐的破绽（假服务的响应速度、版本的陈旧、数据过于整齐），转身就走；低交互蜜罐虽然安全，收集的信息也有限。蜜罐的价值依赖「逼真度」与「部署位置」的精心设计，是「用复杂度换情报」的工程，而非「放台假服务器」就能生效。

## 6 现代演进：分布式与机器学习

传统 IDS 是单点部署，面对现代网络力不从心，于是向两个方向演进：

**分布式 IDS**：在多个网络位置部署检测代理，通过**入侵检测消息交换格式（IDMEF）** 上报给中央分析器，协同检测跨越多个网段的攻击轨迹——攻击者的「跳跃式横向移动」单点看不全，分布式才能拼出全貌。<span class="marginnote">分布式检测的难点在「关联」：多台设备报上来的事件如何判定属于同一次攻击？这是现代 SIEM（安全信息与事件管理）的核心问题，也是把「告警」变成「案件」的关键一步。</span>

**机器学习检测**：异常检测的统计方法被深度学习方法大幅扩展——用神经网络学习流量与行为的复杂模式，检测更隐蔽的变体。但 ML 检测也带来了新的困境：**可解释性差**（模型判异常，却说不清为什么）、**对抗鲁棒性弱**（攻击者可以精心构造样本骗过模型）、**训练数据依赖**（基线数据不干净，模型就学歪）。<span class="marginnote">ML 检测与「大模型安全」形成有趣的呼应：大模型推理时也可能被对抗样本操纵，检测器本身的鲁棒性成为双刃剑——用 AI 防攻击，也要防攻击者攻击你的 AI。</span>

检测后的**处置**也在演进：从「人看告警、手动响应」走向**自动化编排（SOAR）**——把「告警」接进剧本化的响应流程，自动隔离主机、阻断外连、封禁账号，只有高置信度事件才升级到人。检测的价值被释放的关键，恰恰是「检测之后能多快地变成动作」——这与 IPS 篇「发现即处置」的思想一脉相承，只是把「处置」从网络设备扩展到了整个安全运营。

## 7 小结

- **特征检测**认识已知攻击：误报低、速度快、可解释，但**对未知攻击几乎零感知**。
- **异常检测**认识正常基线：能抓零日与内部越权，但误报高、需要干净基线。
- 统计异常分数 $|x-\mu|/\sigma$ 把一切指标归一化到「距正常几个标准差」的同一把尺子上，阈值是误报/漏报的调节旋钮。
- **蜜罐**用「诱饵系统」换取**零误报检测 + 一手攻击情报**，并顺带拖延与消耗攻击者。
- 现代演进方向是**分布式 IDS + 机器学习检测**，但可解释性差、对抗鲁棒性弱仍是硬伤。
- 单指标阈值有局限，**多维综合评分**与分类器是走向「机器学习检测」的过渡。

**核心一句话：检测技术没有银弹**——特征认已知、异常认偏差、蜜罐认「被碰就是恶意」，三者覆盖的攻击面互补。成熟的检测体系必然是三者的组合，而不是「选一条最厉害的」。

在下一节，我们把「检测」从被动拉回主动的边界——不再等攻击者进来再报警，而是把该挡的挡在门外，这是**防火墙与包过滤**。
