## 为什么从公钥密码开始

上一节我们反复碰到同一个死结：对称加密高效，但**收发双方必须共享同一把密钥**。如果双方此前从未见过面、又要通过不安全的网络协商密钥，怎么办？这正是「先有鸡还是先有蛋」式的困境——加密需要密钥，而传输密钥又需要加密。

1976 年，迪菲与赫尔曼（Diffie & Hellman）发表《密码学的新方向》，第一次提出**公钥密码**的思想，彻底解开这个死结：每人持有一对密钥，一个公开、一个私有，公开的不怕泄露，私有的永不出门。**公钥密码不仅解决了密钥分发，还顺带提供了数字签名这个对称密码完全无法提供的功能**——身份认证与不可否认性由此成为可能。<span class="marginnote">本专题第1篇《对称加密》留下的密钥分发问题，就是这一篇的主角；而数字签名与证书体系，将在下一篇《数字签名与 PKI》里展开。</span>

## 1 公钥密码的基本原理

公钥体制的核心是一个**陷门单向函数（trap-door one-way function）**：正向计算很容易，反向计算极难；但若掌握额外信息（陷门），反向也容易。<span class="marginnote">类比：揉进一个面团很容易，把揉进的面粉重新分离出来极难；但若你知道某处夹着的一颗蓝莓的位置（陷门），就能顺着它切开取回。公钥是公开的揉面机，私钥是那颗蓝莓。</span>

在公钥体制里，每个用户生成密钥对 $(PU, PR)$：

- **公钥（public key）$PU$** 公开分发，用于加密或验证签名；
- **私钥（private key）$PR$** 严格保密，用于解密或签名。

$$\text{加密：} C = E_{PU}(M), \qquad \text{解密：} M = D_{PR}(C)$$

**重点：从公钥推导私钥在计算上不可行**。这正是「公开」能够成立的前提——全世界都知道你的公钥，但只有你能解密。公钥体制还须满足四条性质：生成密钥对容易、加密解密容易、由 $PU$ 求 $PR$ 不可行、由 $PU$ 和 $C$ 恢复 $M$ 不可行。

## 2 RSA 算法

**RSA**（以三位发明者 Rivest、Shamir、Adleman 命名，1977）是历史最悠久、应用最广的公钥算法，安全性建立在**大整数分解的困难性**上。RSA 的密钥生成分四步：

1. 选择两个大素数 $p$、$q$，计算 $n = pq$；
2. 计算欧拉函数 $\phi(n) = (p-1)(q-1)$；
3. 选取公钥指数 $e$，满足 $1 \lt  e \lt  \phi(n)$ 且 $\gcd(e, \phi(n)) = 1$（通常取 $65537$）；
4. 计算私钥指数 $d \equiv e^{-1} \pmod{\phi(n)}$。

公钥是 $(e, n)$，私钥是 $d$。$p$、$q$、$\phi(n)$ 必须销毁或严格保密。

$$\text{加密：} C = M^e \bmod n, \qquad \text{解密：} M = C^d \bmod n$$

**辨析｜易错点：** 加密用**公钥**，解密用**私钥**，方向不能搞反。如果反过来「用私钥加密、公钥解密」，那不再提供机密性，而成了**数字签名**——这正好是下一篇的主题。同一个 RSA 数学，两种用途，靠「谁握有密钥」来区分。

## 3 公式解析：RSA 为什么能加解密互逆

RSA 的正确性，即 $D_{PR}(E_{PU}(M)) = M$，可以拆成三步看。

$$
M^{ed} \equiv M \pmod{n}, \qquad \text{其中 } ed \equiv 1 \pmod{\phi(n)}
$$

- **第一步，私钥的定义**：$d$ 是 $e$ 在模 $\phi(n)$ 下的乘法逆元，即 $ed = 1 + k\,\phi(n)$ 对某个整数 $k$ 成立。这是密钥生成第 4 步的实质。
- **第二步，加密再解密**：$C^d \equiv (M^e)^d = M^{ed} = M^{1 + k\phi(n)} \pmod{n}$。
- **第三步，欧拉定理收尾**：当 $\gcd(M, n) = 1$ 时，欧拉定理给出 $M^{\phi(n)} \equiv 1 \pmod{n}$，于是 $M^{1+k\phi(n)} \equiv M \cdot (M^{\phi(n)})^k \equiv M \pmod{n}$。当 $M$ 与 $n$ 不互素时，需要用费马小定理分别对 $p$、$q$ 论证，结论同样成立。

用一个微型例子走一遍（实际密钥远大于此）。取 $p = 17$、$q = 11$，则 $n = 187$、$\phi(n) = 160$；取 $e = 7$（与 160 互素），算 $d \equiv 7^{-1} \pmod{160} = 23$，因为 $7 \times 23 = 161 \equiv 1$。加密 $M = 88$：

$$C = 88^7 \bmod 187 = 11$$

解密验证：

$$M = 11^{23} \bmod 187 = 88$$

整数不大、步骤可手工验算，但结构完全真实：**公钥 $(7, 187)$ 人人可见，而只有握有 $d = 23$ 的人能还原 88**。现实里 $p$、$q$ 是数百位的素数，中间每一步都用快速幂在多项式时间内完成。

直觉层面记住一句话：**$e$ 和 $d$ 是模 $\phi(n)$ 下的互逆指数，乘在一起等于「先转一圈再转回来」**。攻击者若不知道 $\phi(n)$，就找不到 $d$；而想从 $n$ 算出 $\phi(n)$，本质上等于分解 $n$——这就是 RSA 安全的数学根基。<span class="marginnote">「分解 $n$ 难」目前只是计算复杂度上的经验事实，尚无严格证明。量子计算机若规模足够，Shor 算法能以多项式时间分解 $n$——届时 RSA 将全线崩溃，这也是后量子密码研究的动因。</span>

## 4 RSA 的安全性：不能只用数学

RSA 的安全性不止于「大数难分解」。教科书式 RSA（裸指数加密）有大量实现级陷阱：

**选择密文攻击与填充（padding）**：若 $M$ 很小且 $e=3$，$M^e$ 可能小于 $n$，开立方即可还原 $M$；若同一 $M$ 发给多个接收者，还可能被中国剩余定理攻破。因此实际 RSA 必须加**最优非对称加密填充（OAEP）**，把确定性加密变成带随机性的方案。<span class="marginnote">RSA-OAEP 是 PKCS#1 标准的一部分：加密前先对消息做带随机盐的变换，让同一明文在不同次加密里得到不同密文，堵住确定性带来的结构性弱点。</span>

**签名必须哈希**：直接对消息签名（$s = M^d \bmod n$）会招致伪造攻击，因此实际是**先哈希、再对摘要签名**——这也是下一节的引子。

**参数陷阱**：$p$、$q$ 不能太接近；$\phi(n)$ 不能有小的素因子；$d$ 不能太小。工业界 RSA 通常取 2048 位以上，NIST 已规定 2024 年起不再支持 1024 位 RSA。

## 5 Diffie-Hellman 密钥交换

在 RSA 之前，迪菲—赫尔曼（DH）提出了另一个公钥方案——它不加密消息，而是**让双方在公开频道上协商出一个共享密钥**。双方选定一个大素数 $p$ 与生成元 $g$（公开），各自选私密数 $a$、$b$：

$$A = g^a \bmod p \;\to\; B, \qquad B = g^b \bmod p \;\to\; A$$

双方分别计算 $B^a$ 与 $A^b$，得到同一个值：

$$K = g^{ab} \bmod p$$

**重点：** 窃听者能看到 $p, g, A, B$，但无法从 $A$ 反推 $a$——这依赖**离散对数问题**的困难性。DH 自身不认证身份，因此易受**中间人攻击**：攻击者冒充双方各协商一把密钥。要让 DH 安全，必须叠加认证——这正是 TLS 里 DH 与数字签名协同工作的原因。<span class="marginnote">中间人攻击是公钥世界里最容易忽视的威胁：你以为是「你—对方」的协商，其实是「你—攻击者」「攻击者—对方」两段协商。下一篇的证书体系就是用来识别这种冒名顶替的。</span>

## 6 椭圆曲线密码 ECC

**椭圆曲线密码（ECC）** 是公钥密码的年轻主力。它把数学运算搬到椭圆曲线群上：曲线 $y^2 = x^3 + ax + b$ 定义在有限域 $\mathbb{F}_p$ 上，点与点之间有「加法」，一个点自加 $k$ 次记为标量乘法 $kP$。<span class="marginnote">椭圆曲线上的「加法」不是坐标相加，而是几何定义：过 $P$、$Q$ 的直线与曲线交于第三点，关于 $x$ 轴镜像即 $P+Q$。它构成一个阿贝尔群，这条性质是全部 ECC 的基石。</span>

**ECDH** 是 DH 在椭圆曲线上的版本：双方分别计算 $aG$、$bG$ 并交换，再各自算出 $abG$ 作为共享密钥。**ECDSA** 是椭圆曲线数字签名。安全性依赖**椭圆曲线离散对数问题（ECDLP）**：知道 $P$ 与 $kP$，求 $k$
