## 为什么从无线安全开始

有线网络的安全前提是「物理接触」——想窃听，你得先接上那根线。无线彻底摧毁了这个前提：**Wi-Fi 信号是广播的，凡在覆盖范围内、持有无线网卡的人都能收到每一帧**。攻击者甚至不需要进入大楼，停车场里开着车就能「听」到你办公室的无线流量——这就是著名的**战争驾驶（war driving）**。

无线安全因此必须在一个「敞开的信道」上重建一切：认证、加密、防重放。IEEE 为此制定了 **802.11i** 标准，产业界则包装成我们熟悉的 **WPA / WPA2 / WPA3**。理解这条演进线，等于看懂「一次失败的安全设计如何被推倒重来」。

对普通用户，这条线藏在路由器的设置页里：`WEP`、`WPA`、`WPA2`、`WPA3` 的下拉选项背后，就是这一节讲的协议史。**读完本篇，你应该能解释「为什么路由器默认只推荐 WPA2/WPA3、且 WEP 早已消失」。**<span class="marginnote">无线安全是前面所有密码学工具的又一次「极端场景」总装：信道完全不设防，所以每个环节都必须用足加密与认证。它与后面的防火墙/IDS 形成对照——无线把威胁从「外部」直接拉进「信道内部」。</span>

## 1 WLAN 的安全威胁：广播信道的原罪

无线局域网面临的威胁，除了有线网络的全部威胁（窃听、篡改、伪装、DoS），还有无线特有的几种：

**窃听与战争驾驶**：被动接收空中的帧，破解弱加密后直接读取内容；
**未授权接入**：破解口令或利用配置漏洞，蹭网或进入内网；
**流氓 AP（rogue AP）**：攻击者架设一个同名假热点，用户自动连上去，流量全被劫持——**它是「中间人」的无线版**；
**会话劫持**：抢占合法客户端的 MAC 或会话；
- **DoS**：发送大量去认证帧把合法客户端踢下线。

**重点：威胁的核心源于「信道开放 + 身份难辨」**。有线网络里的「物理接入即身份」，在无线里彻底失效；任何安全机制都必须先回答「如何在没有物理边界的前提下，验证『接入者是谁、AP 是谁』」。

## 2 WEP：一次教科书级的失败

**WEP（Wired Equivalent Privacy，有线等效保密）** 是 802.11 最初的安全方案，目标是「让无线像有线一样安全」——结果成了密码学史上最著名的反面教材。它用 RC4 流密码加密，但存在一串致命设计缺陷：

1. **IV 太短且会复用**：24 位初始向量直接拼在密钥前，繁忙的 AP 几小时内就用尽 IV 空间，导致**密钥流重用**——两份用同一密钥流加密的密文异或，明文即刻泄露；
2. **密钥静态**：所有客户端共享一把静态密钥，无密钥管理、无逐帧密钥；
3. **完整性用 CRC-32**：CRC 是**线性**的，攻击者可以翻转明文比特后「修正」校验值，篡改不被发现；
4. **无相互认证**：AP 不认证客户端，客户端也不认证 AP，伪装 AP 无从识别。<span class="marginnote">WEP 的崩溃过程也很有教学意义：2001 年 Fluhrer-Mantin-Shamir 攻击利用 RC4 密钥调度弱点，只需截获数百万帧即可在几分钟内恢复密钥；随后 chopchop、ARP 注入等攻击让破解 WEP 成为「一键脚本」级操作。</span>

**辨析｜易错点：** 常有人以为「WEP 破不了是因为密钥太长」——恰恰相反，**WEP 的问题几乎全在协议设计，不在密钥长度**：RC4 本身在当时尚可用，但 IV 重用、CRC 线性、静态密钥这三条结构性缺陷，让任何长度的密钥都救不回来。**「算法安全 ≠ 协议安全」是这篇历史给我们的最大教训。**

## 3 802.11i：稳健安全网络 RSN

IEEE 的正式回答是 **802.11i 标准**，定义了一个 **RSN（Robust Security Network，稳健安全网络）** 框架，分四块协同工作：

**认证**：采用 **802.1X/EAP**——基于端口接入控制，客户端（申请者）向认证服务器（AS/RADIUS）证明身份，AP 只是转发者；
**访问控制**：认证通过前，端口只放行认证流量；
**数据机密性**：提供两套加密方案——过渡性的 **TKIP** 与强制的 **CCMP**；
**密钥管理**：通过**四次握手（4-way handshake）** 协商成对密钥与组密钥。

**重点：802.11i 把「认证」与「加密」分离成两层**——认证层（802.1X）决定「你是谁」，加密层（TKIP/CCMP）决定「数据怎么保护」。这种分层让企业可以接自己的认证服务器（RADIUS/AD），家庭用户则退而使用预共享密钥（PSK）模式，同一框架兼容两种规模。

两种模式的信任差异值得展开：**企业模式**下每个用户有独立身份，认证失败即拒绝，且个人密钥互不相同——一人泄露不影响他人；**PSK 模式**下所有客户端共享同一把口令，只要有一台设备知道口令，就能解密全网广播的流量。这也是为什么公共场合与安全要求高的环境，必须走企业模式而非家庭 PSK。<span class="marginnote">802.1X 的名字和「端口」容易让人误解：它不是物理端口，而是「逻辑端口」——认证通过前，这个逻辑端口只放行 EAP 认证帧，其余全部丢弃。这与 NAC 篇里说的「先认证后入网」是同一思想，无线场景是它最典型的落地。</span>

## 4 核心对比表：WEP / TKIP / CCMP

> 本篇为纯概念主题，按编辑章程以核心对比表替代公式解析。

三代加密方案对比，演进逻辑一目了然：

| 维度 | WEP | TKIP | CCMP |
| --- | --- | --- | --- |
| 底层密码 | RC4 流密码 | RC4 + 逐帧密钥混合 | **AES**（CCM 模式） |
| 密钥管理 | 静态共享 | 逐帧派生 + 密钥轮换 | 逐帧派生 |
| 完整性 | CRC-32（线性，可被改） | Michael MIC | CBC-MAC |
| 防重放 | 无 | IV 序号检查 | 序号检查 |
| 相互认证 | 无 | 无（依赖 802.1X） | 无（依赖 802.1X） |
| 状态 | 已彻底废弃 | 过渡方案，已弃用 | 现行标准（WPA2 核心） |

**重点：TKIP 是「给 WEP 打补丁」，CCMP 是「推倒重来」**。TKIP 保留 RC4，靠逐帧密钥混合 + 更强 MIC + IV 序号，把 WEP 的漏洞逐条堵上，作为过渡期兼容老硬件的方案；CCMP 直接改用 AES，从密码学底层干净重做，成为 WPA2 的强制加密算法。<span class="marginnote">TKIP 的妥协很有深意：它刻意保留 RC4 是为了让旧硬件只需升级固件即可支持，是「安全与兼容的权衡」。但它仍被称为「过渡方案」，最终被 CCMP 全面取代——安全债迟早要还。</span>

## 5 公式解析：四次握手与 PTK 派生

WPA2 的关键不在加密算法，而在**密钥怎么来的**。客户端（申请者）与 AP（认证者）先各自持有同一个 **PMK（成对主密钥）**——企业模式由 802.1X 认证后分发，家庭模式由口令（PSK）直接派生。双方要在不直接交换 PMK 的前提下，派生出一致的会话密钥 **PTK（成对瞬态密钥）**：
