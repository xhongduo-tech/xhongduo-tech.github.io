## 为什么从入侵者开始

前面的篇章都在建「防线」：加密让数据不可读，TLS/IPSec 让传输不可窃听，防火墙把边界堵上。但**防线总有被攻破的时候**——世界上不存在攻不破的系统，只存在「攻破了也没被发现」的系统。于是安全体系里必须有这样一支力量：**负责发现「已经有人进来了」**。

这支力量就是**入侵检测（intrusion detection）**。本篇先认识它的对象——**入侵者**，再认识它的骨架——**入侵检测系统（IDS）**。下一篇《入侵检测技术》再深入引擎内部，讲特征、异常、蜜罐三种具体检测思路。<span class="marginnote">本专题最后四篇构成「检测与边界防御」板块：本篇「认识敌人 + 认识 IDS 骨架」，下一篇「检测引擎怎么工作」，再往后「防火墙怎么挡」「IPS 怎么拦」。层层递进，拼出纵深防御的最后一块拼图。</span>

斯托林斯的入侵检测有一个很实际的前提：**攻击者也是人，有动机、有工具、有行为模式**。理解入侵者「长什么样、爱怎么动」，是设计检测系统认识论的第一步。

## 1 入侵者的三种身份

**核心概念：入侵者（intruder）**：未经授权试图访问系统、或虽已授权但超越权限使用系统的个人。斯托林斯把入侵者按「身份」分成三类，这张分类是理解入侵行为的总纲：

**伪装者（masquerader）**：未经授权、通过盗取他人合法账号进入系统的外部人员。他借用别人的身份活动，最典型的例子是密码被破解后冒充正常用户登录。
**非法用户（misfeasor）**：**拥有合法账号**、但越权使用系统的内部人员——比如普通员工尝试读取只有管理员能访问的文件、利用职权窃取客户数据。它是最难防的一类：**他有合法身份，行为却已越界**。
**隐秘用户（clandestine user）**：**窃取系统的管理/超级用户权限**，把自己隐藏起来的入侵者——通常是攻击链条的终点，因为拿到 root 后他可以让系统「对他不可见」。<span class="marginnote">三类入侵者对应的防护重点不同：伪装者靠「强认证 + 异常行为检测」拦截，非法用户靠「权限最小化 + 审计」约束，隐秘用户最危险，一旦得手常规检测很难发现——这也是「纵深防御」必须叠加多层的原因。</span>

**重点：三类入侵者的本质区别是「身份从哪来」**。伪装者偷别人的身份，非法用户滥用自己的身份，隐秘用户自己造一个「看不见的身份」。检测策略必须分别应对：对前两类，行为异常是信号；对第三类，需要系统级的完整性监控。

入侵者的**动机**也值得分辨——它决定攻击的烈度与时长：**金钱**（勒索、窃取数据变现）是今天的头号动机，**情报**（商业机密、国家机密）驱动力强劲且极具耐心，**破坏与炫耀**（黑客主义、报复）伤害直观但通常短期。动机不同，检测的耐心也不同——奔着金钱与情报来的攻击者，往往潜伏期以周、月计，这正对应现代 IDS 强调的「长周期行为分析」。

## 2 入侵者的行为模式

入侵者不是随机乱撞的，他们的行为有可识别的**模式（patterns of behavior）**。识别这些模式，正是 IDS 能工作的前提。斯托林斯强调几个典型的入侵行为特征：

**时间反常**：正常员工 9 点到 18 点工作，入侵者常常在凌晨登录；
**频率反常**：短时间内大量登录尝试、重复扫描端口、批量下载文件；
**资源反常**：CPU 占用骤升、网络连接数异常、临时文件大量增加；
**访问范围反常**：一个账号突然访问了从不碰的系统目录或服务器。

**重点：入侵行为几乎必然在「时间、频率、资源、范围」四者之一上露出破绽。** 这就是入侵检测的理论基础——检测系统不必知道「攻击者具体在干什么」，只需发现「行为偏离了正常轨道」。至于「偏离多少算异常」，是下一篇检测技术的核心难题。<span class="marginnote">行为模式的思想跨越了整个安全史：从早期 UNIX 系统的「谁在凌晨登录」告警，到今天 SIEM 的「用户与实体行为分析（UEBA）」，本质都是「识别行为偏差」——只是数据源从日志变成了全流量。</span>

一个经典的行为画像例子能把概念落地：某员工的历史模式是「工作日 9—18 点、公司 IP、办公三件套」。当系统检测到「凌晨 3 点、陌生 IP、批量下载源码」时——没有命中任何已知攻击特征，但每一项都严重偏离画像——异常检测就会报警。**「画像」与「偏差」一旦建立，攻击者的「不像平常」就成了它的指纹。**

入侵者的工具也成体系：**口令破解**（字典攻击、暴力枚举、彩虹表）、**漏洞利用**（针对已知 CVE 打补丁前的空窗期）、**社会工程**（钓鱼邮件、伪装客服骗取凭据）。值得强调的是，**社会工程往往比技术漏洞更有效**——人永远是系统里最薄弱的环节。

## 3 入侵检测系统 IDS：架构与定位

**核心概念：入侵检测系统（Intrusion Detection System, IDS）**：一种监视系统事件、分析其中是否有入侵迹象，并在发现时发出告警的软件或硬件系统。它的三个核心能力是：**监视（看什么）、分析（怎么看）、告警（何时喊）**。

IDS 有两项关键的设计维度——**数据来源**与**分析方式**：

按数据来源，IDS 分成两大类：

**主机型 IDS（Host-based IDS, HIDS）**：运行在**单台主机**上，监视该主机的系统日志、进程活动、文件完整性、系统调用。它能看清「这台主机内部发生了什么」，但对网络流量无能为力。典型代表有系统审计日志监控与文件完整性校验（如 Tripwire）。
**网络型 IDS（Network-based IDS, NIDS）**：架设在**网络的关键节点**上（如交换机镜像端口），被动监听流经的流量，从中识别攻击模式。它能覆盖整段网络、对现有主机透明，但**看不到加密流量内的内容**，也无法知道主机内部状态。

**重点：HIDS 与 NIDS 的视角互补**——一个「从内往外看」，一个「从外往里看」。加密流量让 NIDS 失明，主机行为让 HIDS 洞若观火；反之，横向扫描全网的行为 NIDS 一览无余，HIDS 却只看到单机。<span class="marginnote">现代安全体系几乎从不用单一种类：EDR（端点检测与响应）继承 HIDS 的基因，NDR/NTA 继承 NIDS 的基因，再叠加 SIEM 做全局关联——「只看单点」从来不够，这是 IDS 演进的固定方向。</span>

## 4 审计记录：IDS 的眼睛

无论 HIDS 还是 NIDS，检测都要建立在**数据**上。对主机型 IDS，这个数据来源就是**审计记录（audit records）**。

审计记录是系统对「发生了什么」的原始档案，分两种：

**原生审计日志（native audit log）**：操作系统自带的日志（登录记录、进程启动、文件访问）。开销小、现成，但格式分散、字段不全；
**专用审计记录（detection-specific audit record）**：IDS 为检测目的专门采集的记录，只保留「与安全相关的字段」——用户 ID、会话起止、访问的资源、请求的参数。数据更聚焦，但需要额外采集开销。

**重点：审计记录是「事实」，不是「结论」**。它只回答「发生了什么」，不回答「是不是攻击」——把「事实」判成「攻击」的，是下一篇要讲的检测引擎。好的检测系统，一半功夫花在「采集什么」上：数据不全，再强的分析也巧妇难为无米之炊。<span class="marginnote">「采集」环节在今天的地位远高于教科书时代：全流量采集、端点遥测、云日志，数据量爆炸式增长。现代安全团队最头疼的往往不是「不会分析」，而是「日志太多、采集不全、格式不统一」。</span>

## 5 核心对比表：HIDS vs NIDS

> 本篇为纯概念主题，按编辑章程以核心对比表替代公式解析。

主机型与网络型 IDS 的全部差异，浓缩成一张表：

| 维度 | HIDS | NIDS |
| --- | --- | --- |
| 部署位置 | 单台主机内部 | 网络关键节点 |
| 数据来源 | 系统日志、进程、文件 | 网络流量 |
| 可见范围 | 主机内部行为 | 全网流量模式 |
| 对加密流量 | 看得见（解密后主机视角） | 看不见内容 |
| 对现有系统影响 | 需安装代理，有开销 | 透明旁路，无侵入 |
| 覆盖广度 | 单点 | 整段网络 |
| 典型场景 | 关键服务器加固 | 网络边界监控 |

**重点：两者不是「二选一」，而是「互相补盲」**。一个部署良好的安全架构，通常对关键主机上 HIDS、对网络边界上 NIDS，再让两者把告警汇入同一套分析平台。单靠任何一类，都会有一整片视野是盲区。

## 6 IDS 在纵深防御中的位置

把 IDS 放回本专题铺开的整个安全版图，它的位置一目了然：**加密通信**让数据不可读，**TLS/IPSec** 让传输不可窃听，**防火墙**把边界封住，**IDS** 则在防线内部站岗——「即使敌人进来了，我也要知道」。四个环节不是一个取代一个，而是**一层套一层**的纵深防御。

IDS 有一个必须坦白的固有代价：**它只告警，不拦截**。检测到入侵后，具体怎么处置（断开连接、封禁 IP、隔离主机）由安全团队执行，或者交给**入侵防御系统（IPS）**——那是本专题最后两篇的主角。理解 IDS 与 IPS 的分工，就是理解「检测」与「处置」的边界。

**辨析｜易错点：** 不少人把 IDS 误当成「装了就安全」的防御工具。更准确的说法是：**IDS 是「报警器」不是「盾牌」**。它的价值在于让你知道「何时、何地、谁，被怎样入侵了」——没有这个「知道」，再多防线都可能被无声地绕过。报警器虽然不能挡刀，但能救你的命。

## 7 告警质量：误报与漏报的永恒权衡

把「看」变成「报」之后，IDS 最核心的工程难题浮出水面：**告警质量**。它衡量的是「报得准不准」，由两个对立的指标刻画：

**误报率（false positive）**：把正常行为错判成入侵——告警太多，安全团队被淹没在噪声里，真正的攻击反而被忽略（「狼来了」效应）；
**漏报率（false negative）**：把真正的入侵漏掉——这最危险，因为**你不知道自己不知道**，入侵无声无息地完成。

**重点：误报与漏报是一对无法同时压到最低的矛盾**——把阈值收紧，漏报降、误报升；放阈值，误报降、漏报升。这不是调参能完美解决的，而是 IDS 设计的结构性权衡。下一篇的「特征检测 vs 异常检测」之争，本质就是在这两端之间选边。<span class="marginnote">告警质量直接决定 IDS 的生死：一个天天狂报假警的 IDS，安全团队很快就不看了——这叫「告警疲劳」。成熟的 SOC 用「分诊、降噪、关联」三招对付噪声，把告警压到「每条都值得看」的量级。</span>

衡量告警质量，还常用两个衍生指标：**检测率（detection rate）**——真实入侵中被报出的比例；**基准误报率（base-rate fallacy）**——当真实入侵本身极其罕见时，即使误报率很低，大部分告警仍是误报。这一概率直觉是理解 IDS 长期争论的关键：**检测系统的价值不取决于「准不准」，而取决于「在罕见的真实攻击面前，告警里有多大比例是真的」。**

## 8 小结

- 入侵者分三类：**伪装者**（偷身份）、**非法用户**（滥用身份）、**隐秘用户**（隐藏身份）。
- 入侵行为几乎必在**时间、频率、资源、范围**之一上偏离正常，这是检测的理论基础。
- **HIDS** 从主机内部看行为，**NIDS** 从网络节点看流量，视角互补、互相补盲。
- **审计记录**是「事实」，检测引擎是「结论」——数据采集决定了分析的起点。
- IDS 只**告警不拦截**，处置交给安全团队或 IPS；它是「报警器」，不是「盾牌」。

在下一节，我们将掀开检测引擎的盖子，看它凭什么把一条事件判为「入侵」——这就是**入侵检测技术：特征/异常/蜜罐**。
