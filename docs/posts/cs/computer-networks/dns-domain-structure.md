## 为什么从 DNS 开始

你会在浏览器里输入 `www.example.com`，但网络层只认 IP 地址——**域名怎么变成 IP？** 这就是 **DNS（Domain Name System，域名系统）** 的职责：**把域名解析成 IP 地址。**<span class="marginnote">DNS 是人类与机器之间的「翻译官」：<strong>人记住好记的域名，机器需要精确的 IP</strong>。它不是一个「大表」，而是一棵<strong>层次化的命名树</strong> + 一套<strong>分布式服务器体系</strong>——因为全世界的域名如果集中在一台服务器，容量与可靠性都不可想象。理解 DNS = 理解「如何用分布式系统管理海量名字」。</span>

这一节讲：**域名的层次结构、DNS 服务器的层次体系。**

## 1 域名的层次结构：一棵「倒置的树」

**域名（domain name）**：按层次结构组织的名字，用点分隔，如 `www.example.com`。它是一棵**倒置的树**：<span class="marginnote">域名的阅读顺序：<strong>从右到左层次越来越高</strong>。`www.example.com` 中，`.com` 是顶级域，`example` 是 com 下的一级域，`www` 是 example 下的主机名。整棵 DNS 树的根是「根域」（空，用「.」表示），下面是顶级域（TLD），再往下逐级分支。</span>

```
          （根域 .）
        /    |    \
     com   org   cn   ...   （顶级域 TLD）
      |            |
   example       edu.cn  （二级域）
      |
     www       （主机名）
```

- **根域**：所有域名的顶端，通常省略不写（`example.com.` 末尾的点就是根）。
- **顶级域（TLD）**：通用顶级域（`.com`、`.org`、`.net`）与国家顶级域（`.cn`、`.jp`）。
- **二级域及以下**：由各级域名所有者自行划分。

**辨析｜易错点：** 域名的层次是**从右往左读**的——最右边是最高层（顶级域），最左边是主机名。**「www.example.com 的顶级域是 com，不是 www」**是最基本的判断。另外，**域名是「大小写不敏感」的**（通常规范为小写），但层次结构本身不含主机名（`www` 是主机名，不是域名层级的一部分）。

## 2 DNS 服务器的层次体系：分布式「电话簿」

DNS 服务器按层次分四类，各管一段：<span class="marginnote">DNS 服务器不是「一张大表」而是「<strong>分布式数据库</strong>」：<strong>根服务器</strong>只知道「每个顶级域在哪」；<strong>顶级域服务器</strong>只知道「每个二级域在哪」；<strong>权威服务器</strong>才知道「具体的域名对应哪个 IP」；<strong>本地域名服务器</strong>替用户缓存与转发查询。没有任何一台服务器存全部域名——每个域名只存在它的「权威服务器」里。</span>

| 服务器 | 职责 | 位置/数量 |
| --- | --- | --- |
| 根域名服务器 | 指向顶级域服务器 | 全球 13 组（多台镜像） |
| 顶级域（TLD）服务器 | 指向二级域服务器 | 每个 TLD 一组（如 .com） |
| 权威域名服务器 | 存储某域的「域名→IP」记录 | 每个域名所有者维护 |
| 本地域名服务器 | 替用户查询与缓存 | 每个 ISP/机构一台 |

**辨析｜易错点：** **「权威」这个词是重点**：一个域名「权威」地属于某个服务器——只有权威服务器能给出该域名的最终答案。其他服务器只是「指路」（告诉你下一站去哪）。**「根与 TLD 是指路的，权威是给答案的」**是一句话概括四类服务器的分工。

## 3 域名解析：一条查询的「旅程」

以用户访问 `www.example.com` 为例（迭代查询视角）：<span class="marginnote">查询过程像「打怪升级」：<strong>用户问本地服务器 → 本地服务器问根 → 根指路去 .com → .com 指路去 example → example 给出最终 IP</strong>。每一站都只回答「下一站去哪」或「最终答案」。这套「逐级指路」避免了在单一服务器存全表。</span>

1. 用户主机把 `www.example.com` 交给**本地域名服务器**。
2. 本地服务器若缓存有答案，直接返回；否则问**根服务器**。
3. 根服务器回答：「.com 的顶级域服务器是 xxx」。
4. 本地服务器问 **.com 顶级域服务器**，得到「example 的权威服务器是 yyy」。
5. 本地服务器问 **example 的权威服务器**，得到最终 IP。
6. 本地服务器把 IP 返回给用户，并缓存备用。

**辨析｜易错点：** **缓存是 DNS 高效的关键**——本地服务器缓存解析结果，绝大多数查询直接命中缓存，不必每次都逐级走一遍。缓存条目有 **TTL**（生存时间），过期后重新查询。**「缓存让 DNS 快，TTL 让缓存不 stale」**是理解 DNS 性能的钥匙。

## 4 域名结构 vs IP 结构：两种「地址」

域名与 IP 都是「定位用的」，但结构完全不同：<span class="marginnote"><strong>域名是给人类看的、有语义的、可变的</strong>（换个域名注册商就能换）；<strong>IP 是给机器用的、无语义的、全局唯一的</strong>。域名系统解决的是「名字 → 地址」的映射——与电话簿把「人名」映射到「电话号码」同构。<strong>「域名管名字，IP 管位置」</strong>，两者通过 DNS 关联，各自独立演进。</span>

| 对比维度 | 域名 | IP 地址 |
| --- | --- | --- |
| 面向对象 | 人类 | 机器 |
| 是否有语义 | 有（example 公司） | 无（纯数字） |
| 是否可变 | 可换（换注册商） | 跟着网络位置走 |
| 层次 | 名字树（com → example → www） | 地址树（网络号 → 主机号） |
| 谁解析 | DNS | 路由器 |

**辨析｜易错点：** **域名与 IP 不是一一对应的**——一个域名可以对应多个 IP（负载均衡），一个 IP 也可以对应多个域名（虚拟主机）。**「域名 ↔ IP 是多对多」**是理解 Web 托管、CDN 的基础。

## 5 小结

- **DNS 的职责**：把域名解析成 IP，是互联网的「分布式电话簿」。
- **域名层次**：倒置的树——根 → 顶级域 → 二级域 → 主机名，从右往左读。
- **四类服务器**：根（指路 TLD）、TLD（指路二级域）、权威（给最终答案）、本地（缓存 + 代查）。
- **解析旅程**：本地 → 根 → TLD → 权威，逐级指路；缓存让大多数查询直接命中。
- **域名 vs IP**：名字 vs 位置，多对多关系。
- **设计精髓**：分布式存储 + 层次指路 + 缓存，让海量名字可扩展地解析。
