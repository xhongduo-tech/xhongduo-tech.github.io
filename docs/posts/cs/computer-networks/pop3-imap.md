## 为什么从 POP3 与 IMAP 开始

邮件被 SMTP 送进了收件人的邮箱，但收件人**怎么把邮件「取」出来看**？这是 **POP3 与 IMAP** 的职责——它们是**邮件读取协议（mail access protocol）**，解决「从服务器把邮件读到客户端」的问题。<span class="marginnote">关键区分：<strong>SMTP 是「推」</strong>——把邮件推进收件人的服务器；<strong>POP3/IMAP 是「拉」</strong>——收件人的客户端把邮件从服务器「拉」下来。SMTP 是「送货上门」，POP3/IMAP 是「收货入库」。</span>

这一节讲：**POP3 的「下载删除」模式、IMAP 的「服务器管理」模式、以及两者的选择。**

## 1 POP3：下载即删除的「老式取信」

**POP3（Post Office Protocol version 3，邮局协议第 3 版）**：基于 **TCP 110 端口**（加密版 POP3S 用 995）。它的工作模式：<span class="marginnote">POP3 的设计哲学是「<strong>取走即拥有</strong>」：<strong>客户端把邮件从服务器下载到本地，服务器端的邮件通常被删除</strong>。这像去邮局取信——取完信，邮局的信箱就空了。优点是简单、服务器压力小；缺点是「单设备」——你在电脑上收过的邮件，手机上就看不到了（因为服务器已删除）。</span>

**下载并删除**：客户端连服务器，下载邮件，通常删除服务器副本。
**离线阅读**：邮件在本地，离线也能看。
**单设备**：邮件只在下载它的那台设备上。

**辨析｜易错点：** **POP3 的「下载即删除」是它的核心特征**——但也因此不适合多设备场景。现代 POP3 客户端通常可选「保留服务器副本」，但默认的「取走即删」是其传统行为。**「POP3 是取走型，邮件跟设备走」**是它的本质。

## 2 IMAP：服务器端的「云管理」

**IMAP（Internet Message Access Protocol，互联网邮件访问协议）**：基于 **TCP 143 端口**（加密版 IMAPS 用 993）。它的工作模式：<span class="marginnote">IMAP 的设计哲学是「<strong>邮件留在服务器</strong>」：<strong>客户端只是「查看」服务器上的邮件，邮件始终存在服务器</strong>。你在电脑、手机、网页端登录同一邮箱，看到的是同一批邮件、同样的已读状态——因为「状态」存在服务器端。<strong>IMAP 是现代邮箱（Gmail、Outlook）的标准协议</strong>，天然支持多设备。</span>

**邮件留在服务器**：客户端只下载「查看」，邮件不动。
**服务器端管理**：文件夹、已读/未读状态都存服务器。
**多设备同步**：任何设备登录，看到同一状态。
**部分下载**：可以先下载首部/正文的一部分，按需取附件。

**辨析｜易错点：** **IMAP 与 POP3 的核心差别是「邮件留在哪」**：POP3 把邮件搬走（下载删除），IMAP 把邮件留在服务器（随时查看）。**「POP3 是搬，IMAP 是看」**是一句话对照。IMAP 的「部分下载」是它高效之处——大附件不必整封下载，先看首部再决定。

## 3 POP3 vs IMAP：一张表

| 对比维度 | POP3 | IMAP |
| --- | --- | --- |
| 端口 | 110（加密 995） | 143（加密 993） |
| 邮件存放 | 下载到本地、服务器删除 | 留在服务器 |
| 多设备 | 不支持（单设备） | 支持（多设备同步） |
| 服务器存储 | 占用小（取走即删） | 占用大（邮件长驻） |
| 已读状态 | 本地维护 | 服务器维护 |
| 适用场景 | 单设备离线阅读 | 多设备、网页/移动端 |

**辨析｜易错点：** 选择口诀：**「一台设备用 POP3，多台设备用 IMAP」**。另外注意：**POP3/IMAP 都是「拉」邮件，它们不发送邮件**——发信永远用 SMTP。**「收信用 POP3/IMAP，发信用 SMTP」**是邮箱配置里的黄金规则（所以邮箱设置里既有「收件服务器」也有「发件服务器」两个地址）。

## 4 从 POP3 到 IMAP：邮件协议的演进

POP3 诞生于「一台电脑一个邮箱」的年代，IMAP 诞生于「多设备同步」的需求之后。这个演进背后是使用习惯的变化：<span class="marginnote">早期人们只有一台电脑，邮件「下载即删」没问题；现在手机、平板、电脑、网页端同时要用邮箱——<strong>「邮件在服务器端管理」成为刚需</strong>。IMAP 正是顺应「多设备 + 云同步」时代的主流协议。不过 POP3 并未消失——它在「只想把邮件备份到本地」的场景里仍有价值。<strong>「协议选择跟随使用场景」</strong>是理解 POP3/IMAP 共存的关键。</span>

- **POP3 时代**：单设备、离线为主。
- **IMAP 时代**：多设备、云端同步。
- **现实**：两者并存，IMAP 是主流，POP3 用于特定备份需求。

**辨析｜易错点：** 别以为「IMAP 全面取代 POP3」——**两种协议解决不同需求，没有谁淘汰谁**。Gmail 两者都支持（IMAP 为主、POP3 可选）。**「现代默认 IMAP，特殊需求 POP3」**是对现状的准确描述。

## 5 一封邮件的完整旅程：MUA、MTA、MDA

把 SMTP 与 POP3/IMAP 放进一封邮件的完整旅程，角色分工才清晰：

- **MUA（邮件用户代理）**：你的邮件客户端（Outlook、手机邮件 App）——负责写、读、收。
- **MTA（邮件传送代理）**：发送方/中转的邮件服务器——负责用 SMTP 把信「接力投递」。
- **MDA（邮件投递代理）**：收件人的邮箱服务器——把信放进收件人的邮箱。
- **POP3/IMAP**：MUA 从 MDA（收件箱）把信「取走」阅读。

**完整旅程**：你（MUA）写邮件 → SMTP 传给发送方 MTA → 一路 SMTP 接力 → 收件方 MDA 放入邮箱 → 收件人用 IMAP/POP3 从邮箱取信阅读。**「SMTP 管路上送，POP3/IMAP 管末端取」**。

**辨析｜易错点：** 一个常见误区是「POP3/IMAP 能发邮件」——**不能**。发邮件永远走 SMTP，收邮件才用 POP3/IMAP。**「发用 SMTP、收用 POP3/IMAP」**是配置邮件客户端时填「发送服务器」与「接收服务器」两个地址的原因。

## 6 现实中的选择：一个场景决策

结合前面的知识，看两个真实场景该选什么协议：

- **场景一（只用一台电脑、想本地备份全部邮件）**：选 POP3——邮件下载到本地、服务器可删除，占用服务器空间小，离线可读。
- **场景二（手机 + 电脑 + 网页端都要用，随时同步已读状态）**：选 IMAP——邮件留服务器，任何设备看到同一状态。

**实际提示**：Gmail/Outlook 默认 IMAP，且支持「POP3 下载后仍保留服务器副本」——所以现实里边界不是那么死。**「默认 IMAP，特殊需求 POP3」**仍是稳妥的选择公式。

**辨析｜易错点：** 别只看「有没有网」——POP3 的「离线阅读」是优点，但「离线 ≠ 安全」：邮件在本地明文存储，设备丢失即泄露。**「协议选择也要考虑安全与备份策略」**。

## 7 加密与认证：邮件协议的安全层

邮件协议最初都是明文，现代加了加密与认证：

- **明文端口**：POP3=110、IMAP=143、SMTP=25——早期全明文，口令与内容都可被窃听。
- **加密版**：POP3S=995、IMAPS=993、SMTPS=465——全程 TLS 加密。
- **STARTTLS**：在明文端口上先建立连接、再升级到 TLS——更灵活（同一端口兼容明文与加密）。
- **认证**：现代邮箱要求强认证（OAuth、应用专用密码），避免口令明文传输。

**辨析｜易错点：** **「用加密端口」不等于「一定安全」**——还要看服务器是否真正启用 TLS、证书是否可信。**「端口只是入口，TLS 与认证才是安全本体」**。配置邮箱时优先选 995/993/465 或 STARTTLS，是对自己口令负责。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| MUA | 邮件用户代理（客户端） |
| MTA | 邮件传送代理（发送方服务器） |
| MDA | 邮件投递代理（收件箱） |
| SMTP | 发信协议（推送） |
| POP3 | 收信协议（下载即删） |
| IMAP | 收信协议（留在服务器） |
| POP3S / IMAPS | 加密版收信端口（995/993） |
| STARTTLS | 明文端口上升级 TLS |
| 邮件服务器 | 存储与转发邮件的服务 |

## 9 小结

- **POP3**：下载即删除、单设备、离线阅读；端口 110/995。
- **IMAP**：邮件留服务器、多设备同步、部分下载；端口 143/993。
- **黄金对照**：POP3 是「搬」（取走即删），IMAP 是「看」（留在服务器）。
- **选择规则**：一台设备用 POP3，多台设备用 IMAP。
- **收/发分工**：收信用 POP3/IMAP，发信用 SMTP。
- **演进逻辑**：从单设备到多设备云同步，IMAP 成为主流但 POP3 仍在。
- **全链条**：MUA 写、MTA 送、MDA 存、POP3/IMAP 取，SMTP 管路上送。
- **加密选择**：995/993/465 或 STARTTLS 优先，端口只是入口、TLS 才是本体。
