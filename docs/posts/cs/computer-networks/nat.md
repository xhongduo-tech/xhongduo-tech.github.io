## 为什么从 NAT 开始

IPv4 地址只有 43 亿个，而全球联网设备远超此数。在 IPv6 全面铺开之前，让这么多设备上线的「临时方案」就是 **NAT（Network Address Translation，网络地址转换）**：**让整个局域网共享一个（或几个）公网 IP 地址上网。**<span class="marginnote">NAT 的思路：<strong>局域网内部用私有地址（如 192.168.1.1），出口路由器（NAT 路由器）把私有地址映射成公网地址</strong>。家里所有设备的「对外身份」都是那一个公网 IP——NAT 路由器靠「端口号」区分内网的不同设备。这个方案今天几乎无处不在，你家路由器里自动开启的就是 NAT。</span>

这一节讲：**NAT 的原理（NAPT）、转换表、优缺点、与 IPv6 的关系。**

## 1 NAPT：地址 + 端口一起映射

最基本的 NAT 是「一对一」映射（一个内网 IP 换一个公网 IP）——不解决地址不足。真正的主力是 **NAPT（Network Address Port Translation，网络地址端口转换）**：**把「内网 IP + 端口」映射成「公网 IP + 端口」，多个内网设备共享一个公网 IP。**<span class="marginnote">NAPT 是 NAT 的现代形态，也叫「端口多路复用 NAT」。它利用运输层的端口号做区分：<strong>内网 192.168.1.10:5000 与 192.168.1.11:6000，对外分别映射成 203.0.113.1:40000 与 203.0.113.1:40001</strong>——一个公网 IP 加上 65535 个端口，理论上可区分大量内网设备。</span>

**NAT 转换表（translation table）** 记录映射关系：

| 内网地址:端口 | 公网地址:端口 |
| --- | --- |
| 192.168.1.10:5000 | 203.0.113.1:40000 |
| 192.168.1.11:6000 | 203.0.113.1:40001 |

**辨析｜易错点：** NAT 工作在**网络层 + 运输层**——它既改 IP 地址，又改端口号。这是它与路由器（只改 MAC 帧头）的根本区别：**路由器改写 MAC 不碰 IP，NAT 改写 IP 还碰端口。** 抓包时看到「源 IP 与源端口都被改了」，那一定是过了 NAT。

## 2 NAT 的转换过程：出门换装，进门换回

NAT 路由器处理每个数据报：<span class="marginnote">内网设备访问外网时：<strong>出方向</strong>，NAT 把「源 IP + 源端口」换成「公网 IP + 新端口」，并记入转换表；<strong>入方向</strong>，NAT 收到应答，查转换表，把「目的公网 IP + 端口」换回「内网 IP + 原端口」，送给对应设备。转换表的条目靠「出方向的流量」建立——所以外网主动访问内网时，表里没有对应条目，就进不来。</span>

1. **出方向**：内网主机 192.168.1.10:5000 访问外网服务器。NAT 换成源 203.0.113.1:40000，记入转换表，发出去。
2. **服务器应答**：应答的目的地址是 203.0.113.1:40000，送到 NAT 路由器。
3. **入方向**：NAT 查转换表，把目的换回 192.168.1.10:5000，送给内网主机。

**辨析｜易错点：** NAT 的转换表是**「出方向建立的」**——内网先发起通信，表里才有条目。这意味着**外网无法主动访问内网主机**（除非配置端口映射/UPnP），这是 NAT 既「省地址」又「天然防火墙」的双重属性。**「NAT 破坏端到端，但也挡了外网入侵」**是它最典型的「一个硬币两面」。

## 3 NAT 的优缺点：功过分明

**NAT 的优点**：<span class="marginnote">① <strong>大幅缓解 IPv4 地址枯竭</strong>——一个公网 IP 服务整个局域网；② <strong>天然的内外隔离</strong>——内网地址不暴露、外网难以主动进入，具备基础防火墙效果；③ <strong>便于灵活组网</strong>——内部改地址、加设备，不惊动公网。</span>

缓解地址枯竭（一个公网 IP 供全局域网用）。
天然隔离内网（外网看不到私有地址，难以主动访问）。
灵活迁移（内部网络改造不涉及公网）。

**NAT 的缺点**：

**破坏端到端原则**：NAT 在中间改写地址与端口，违背「网络保持哑管道」的哲学——P2P、VoIP 等需要端到端直连的应用会受限。
**增加转发开销**：每个数据报都要查转换表、改字段、重算校验，路由器负担加重。
**上层协议适配麻烦**：有些应用把自己的 IP 写在数据里（如 FTP、SIP），NAT 还得改写载荷——需要专门的 ALG。

**辨析｜易错点：** 一个经典误解是「NAT 是安全设备」——**NAT 不是防火墙**，它只是在「没有入方向表项」时碰巧挡掉了外网主动连接。真正的访问控制要交给防火墙（第 7 章）。**「NAT 的隔离是副产品，不是设计目标」**。

## 4 NAT 与 IPv6：过渡期的「功臣」与 IPv6 的「颠覆」

NAT 是 IPv4 枯竭时代的功臣，但它的存在恰恰说明 IPv4 已经「撑不下去」了。**IPv6 的地址足够多，不需要 NAT**——每个设备都可以拥有全球唯一地址，端到端通信回归纯粹。<span class="marginnote">有趣的反转：<strong>IPv4 时代靠 NAT 撑场面（地址不够，NAT 凑），IPv6 时代 NAT 沦为可选项（地址管够，直连回归）</strong>。但现实中，很多 IPv6 部署仍保留了 NAT（NAT66）用于「隐藏内部拓扑」或「避免重新规划网络」——技术问题解决了，习惯与管理因素仍然存在。</span>

**辨析｜易错点：** **NAT 不是 IPv6 的替代品，也不是 IPv6 的敌人**——NAT 是「IPv4 时代省地址的手段」，IPv6 用「地址本身管够」从根上消除了对 NAT 的需求。**「IPv6 消除的是 NAT 的『必要性』，不一定是它的『存在性』」**。

## 5 NAT 的类型与穿越：P2P 的「闯关」

NAT 不止一种，且给 P2P 带来麻烦：

- **静态 NAT**：一个内网 IP 固定映射一个公网 IP——适合服务器（需外网访问）。
- **动态 NAT**：内网 IP 从公网地址池里临时分配——地址不足时用。
- **NAPT（端口复用）**：最常见的家用形态，多设备共享一个公网 IP。
- **NAT 穿越（NAT traversal）**：P2P 应用（BT、VoIP、游戏）需要「外网直连内网」，但 NAT 挡着——靠 **STUN**（探测自己的公网映射）与 **UDP 打洞**（双方同时主动发包建立映射）来「闯关」。

**辨析｜易错点：** **NAT 穿越的「打洞」依赖双方同时主动向外发包**——让 NAT 各自建立「出方向映射」，之后外网才能通过这个映射回连。**「NAT 是墙，打洞是两墙各开一个小门」**是 NAT 穿越的直观比喻。

## 6 算例：NAPT 表的一次完整建立

设内网两台主机同时访问同一个外网 Web 服务器（203.0.113.9:80），NAT 公网 IP 是 203.0.113.1：

| 步骤 | 方向 | 源 | 目的 | 转换后源 |
| --- | --- | --- | --- | --- |
| 主机 A 请求 | 出 | 192.168.1.10:5000 | 203.0.113.9:80 | 203.0.113.1:40000 |
| 主机 B 请求 | 出 | 192.168.1.11:6000 | 203.0.113.9:80 | 203.0.113.1:40001 |

NAT 在转换表里记下「内网 5000 → 公网 40000」「内网 6000 → 公网 40001」。服务器应答发往 40000 与 40001，NAT 据此换回内网端口——**同一个公网 IP 与端口（80）目标，靠「源端口」区分两个内网设备**。

**辨析｜易错点：** 转换表的条目有**生存时间**——长时间不通信的条目会被删除，导致连接被「掐断」。**「NAT 表项会过期，长连接要保活」**是许多「莫名断连」问题（尤其 VoIP、长连接）的根源。

## 7 NAT 的现代困境：IPv6 时代的双重角色

NAT 帮 IPv4 撑到今天，但它也在被新趋势挑战：

- **NAT 与隐私**：NAT 隐藏了内网拓扑，但「一个公网 IP 全家共用」也让运营商更难做精细化的用户管理——身份识别成了灰色地带。
- **NAT 与新兴应用**：WebRTC（浏览器视频通话）、P2P 游戏、去中心化网络都渴望端到端直连——NAT 是它们共同的「墙」。
- **IPv6 与 NAT66**：IPv6 地址管够，理论上不需要 NAT；但部分部署仍用 NAT66 隐藏内部结构——技术必要性消除，管理与习惯仍保留。

**辨析｜易错点：** **NAT 的「功过」取决于视角**：对地址枯竭它是救星，对端到端哲学它是破坏者。**「NAT 是 IPv4 时代的权宜之计，却意外成了互联网生态的一部分」**——理解它的两面，才算真正读懂 NAT。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| NAT | 网络地址转换 |
| NAPT | 地址 + 端口一起转换（端口复用） |
| 私有地址 | 内网使用的保留地址（如 192.168.x.x） |
| 转换表 | 内网↔公网映射关系表 |
| 出方向 / 入方向 | 内网发外网 / 外网发内网 |
| 静态 NAT | 固定一对一映射 |
| 动态 NAT | 地址池临时分配 |
| STUN | 探测自己的公网映射 |
| NAT 穿越 | 让 P2P 穿过 NAT 的技术 |
| 端口映射 | 把公网端口固定映射到内网主机 |

## 9 小结

- **NAT 的本质**：内网私有地址 ↔ 公网地址的转换，让一个公网 IP 服务整个局域网。
- **NAPT**：地址 + 端口一起映射，用端口区分内网设备——现代 NAT 的主流形态。
- **转换表**：由出方向流量建立；外网主动访问内网会因「表里没条目」而被挡。
- **优点**：省地址、天然隔离、灵活组网；**缺点**：破坏端到端、增开销、需上层适配。
- **NAT ≠ 防火墙**：隔离是副产品，不是安全设计。
- **与 IPv6**：IPv6 地址管够，消除 NAT 的必要性；端到端回归纯粹。
- **类型与穿越**：静态/动态/NAPT 各管一摊，P2P 靠 STUN + 打洞闯关。
- **算例结论**：同一个公网 IP 目标，靠「源端口」区分内网设备；表项会过期。
- **双重角色**：NAT 是地址枯竭的救星，也是端到端哲学的破坏者。
