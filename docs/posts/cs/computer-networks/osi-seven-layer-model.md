## 为什么从 OSI 七层开始

上一节我们搭起了"协议 + 分层"的脚手架。但分层到底分成几层？每层干什么？1970 年代末，各大厂商各说各话，网络世界乱成一团：IBM 有 SNA，DEC 有 DNA，互不兼容——那时一台设备接入网络，几乎等于被某家厂商绑死。国际标准化组织（ISO）决定终结混乱，于 1984 年推出**开放系统互连基本参考模型（OSI/RM）**——一套七层的体系结构，作为全球通信的标准蓝图。

OSI 七层模型是计算机网络教科书里最"出圈"的一张图。它的历史命运很反讽：**作为标准，它没有真正统治世界；作为教学工具，它统治了全世界每一本计算机网络教材。** 学懂它，你就拥有了一张理解所有网络体系结构的地图——后面讲的 TCP/IP 五层，就是在它基础上"砍掉两层"的务实版本。

## 1 一张分层总表：七层各自干什么

OSI 把通信自下而上分成七层：**物理层、数据链路层、网络层、运输层、会话层、表示层、应用层**。记忆口诀是"**物链网运会表应**"。

| 层（自下而上） | 一句话职责 | 数据单元 | 典型协议/设备 |
| --- | --- | --- | --- |
| 7 应用层（Application） | 为应用进程提供网络服务 | 报文（message） | HTTP、DNS、SMTP |
| 6 表示层（Presentation） | 数据格式转换、加密、压缩 | 报文 | JPEG、ASCII 转换 |
| 5 会话层（Session） | 会话管理、同步、断点续传 | 报文 | RPC 的会话管理 |
| 4 运输层（Transport） | 端到端进程通信、差错恢复、流量控制 | 报文段（segment） | TCP、UDP |
| 3 网络层（Network） | 分组转发、路由选择、拥塞控制 | 分组/数据报（packet/datagram） | IP、路由器 |
| 2 数据链路层（Data Link） | 相邻结点间帧的可靠传送、差错检测 | 帧（frame） | 以太网、交换机 |
| 1 物理层（Physical） | 透明传输比特流，定义电压、速率、接口 | 比特（bit） | 集线器、网线 |

下面这张图把七层堆起来，右侧标注每层的数据单元与典型协议，红色高亮的是运输层：

![OSI 七层参考模型：各层职责与数据单元](/images/computer-networks/osi-seven-layer-model-1.svg)

逐层展开看：

- **物理层**：最底层，关心"比特怎么变成电/光信号、怎么穿过介质"。它要规定电压多少伏、一个比特持续多久、接口是几根针。
- **数据链路层**：把比特流组装成**帧**，在**相邻两个结点**之间传送，负责差错检测与流量控制——注意它只管"这一段"，不管全程。
- **网络层**：负责**端到端**的路由选择与分组转发，把数据从源主机一路送到目的主机，是"互联网"这个名字的真正所在。IP 地址在这里登场。
- **运输层**：第一次进入"进程级"通信——网络层把分组送到主机，运输层把数据送到这台主机上的**具体哪个进程**（端口）。它提供端到端的可靠传输与流量控制。<span class="marginnote">"端到端"这三个字是运输层的身份证：中间的路由器只干活到网络层为止，不碰运输层。通信双方各自的主机里才有运输层实现——这也是为什么运输层是图中红色高亮的那一层。</span>
**会话层**：管理会话的建立、维持与同步，负责"说一段话的过程"。
**表示层**：负责语义与语法转换——编码格式不同怎么办、要不要加密压缩，都在这里。
**应用层**：最顶层，直接为用户的应用程序提供服务，是所有网络的"目的"。<span class="marginnote">"一切通信最终都是为了应用"，这句话在 OSI 里体现得最直接：下面六层都是手段，应用层才是目的。后面讲应用层时，HTTP、DNS、SMTP 全都住在这里。</span>

## 2 层层之间怎么协作：服务与接口

七层不是七座孤岛。它们之间有两种协作关系，很容易混淆，必须分清楚：

**对等层通信靠协议（protocol）**：第 N 层与另一台机器的第 N 层之间，是**逻辑上的**通信——仿佛它们直接"对话"，实际上物理上并不直接相连。它们靠的是共同的协议规则。

**相邻层通信靠服务（service）**：同一台机器上，第 N+1 层调用第 N 层提供的服务，通过**服务访问点（SAP）**这个接口传递数据。

**辨析｜易错点：** "对等层协议"是逻辑连接，**数据在物理上从不跨越对等层**。真正的数据流动是：发送方数据从第 7 层逐层向下，每层加一个首部（封装），到物理层变成比特流，走链路到达接收方后，再逐层向上、每层剥掉对应首部（解封装）。"对等层对话"是概念上的捷径，物理上的轨迹是"向下封装 → 传输 → 向上解封装"。<span class="marginnote">这条"逐层封装/解封装"的流水线，就是数据在网络里旅行的真正路径。下一节《五层协议体系结构与封装、解封装》会专门放大这条流水线，画清楚每个首部长什么样。</span>

数据单元随层而变的名字——**比特 → 帧 → 分组 → 报文段 → 报文**——正是封装动作的"指纹"：每多戴一顶首部的"帽子"，名字就换一次。认准这条命名链，是读任何网络报文的起点。下一节《五层协议体系结构与封装、解封装》会把这串名字对应的每个首部逐一画出来。

## 3 数据在七层里的一次完整旅行

光看静止的层次不够，让一个真实请求沿着七层走一遍，一切就活了。场景：你在浏览器里访问 `www.example.com` 的网页。

**发送端，自上而下层层封装：**

1. **应用层**生成一个 HTTP 报文——"请把首页给我"。
2. **表示层**（现实中常被并入应用层）把数据压缩或加密。
3. **会话层**管理这次对话的上下文。
4. **运输层**把应用数据切成合适的块，加上 TCP 首部——首部里最重要的信息是**端口号**（这次请求发给 example.com 的 80 端口）。
5. **网络层**把整段数据包进 IP 数据报，加上 IP 首部——里面装着**源 IP 地址与目的 IP 地址**（路由器靠它决定下一步往哪走）。
6. **数据链路层**再把 IP 数据报装进以太网帧，加上帧首部——里面装着**源 MAC 地址与目的 MAC 地址**（交换机靠它决定往哪个端口送）。
7. **物理层**把这一整帧变成电信号或光信号，送上链路。

**接收端，自下而上层层解封装：** 物理层把信号还原成比特，数据链路层剥掉帧首部、取出 IP 数据报，网络层剥掉 IP 首部、取出 TCP 报文段，运输层剥掉 TCP 首部、把应用数据交给表示层，最终由应用层的 HTTP 解析出"这是首页内容"。

**这一趟旅行的关键信息，都藏在每层自己加的那个首部里**：端口号属于运输层，IP 地址属于网络层，MAC 地址属于数据链路层——**各层各管一段，谁也不越界**。<span class="marginnote">这就是为什么"抓包"能一层层展开：同一个数据包里，你既能看到 MAC 地址（数据链路层），又能看到 IP 地址（网络层），还能看到端口号（运输层）。后面讲 ARP、IP、TCP 时，你会反复见到这三个地址的配合。</span>

## 4 七层的分层逻辑：为什么要这七层

七这个数字不是拍脑袋定的。把它从中间切开看，分层的逻辑非常清晰：

**下三层（物理、数据链路、网络）——"媒体层"**：负责把数据搬过链路、搬过网络。它们与物理媒体打交道，工作在每一台联网设备上，包括路由器、交换机这些"中间设备"。
**运输层——"端到端"**：只有通信的两端（源主机与目的主机）才需要它，中间设备不碰运输层。它把"尽力而为"的网络层，改造成"可靠有序"的端到端通道。
**上三层（会话、表示、应用）——"应用层"**：面向用户，处理的是"怎么把数据呈现给程序和人"。

这个三段式划分是理解整张图的钥匙：**越往下越靠近物理，越往上越靠近用户。** 一台路由器只实现到下三层，而通信双方的完整实现则覆盖全部七层。<span class="marginnote">"路由器只实现到下三层"这句话请务必记住：网络层的 IP 地址是路由器看得懂的，运输层的端口号路由器根本不解析——这在抓包和排障时能帮你快速定位问题出在哪一段。</span>

这套三分法还能解释一个工程现象：防火墙既能按 IP 地址过滤（工作在网络层），也能按端口号过滤（工作在运输层），还能按应用内容过滤（工作在应用层）——**每一层都有它看得见、管得着的"信息字段"，安全产品选在哪一层部署，本质上就是选看哪一层的首部。** 网络安全章节讲防火墙时，你会看到这个选择的两难：层越低过滤越快但看得越少，层越高看得越全但性能开销越大。

**辨析｜易错点：** 会话层和表示层的"存在感"很弱——因为它们在现实互联网里几乎被应用层"吸收"了。会话管理并入了应用逻辑，加密压缩也直接由应用层协议（如 TLS）实现。这恰恰预告了下一节的主题：**OSI 的七层是理论上的完美，TCP/IP 的五层是工程上的务实。**

## 5 辨析：OSI 模型 vs 现实世界

OSI 是"开放系统互连"的标准蓝图，但它从未真正统治互联网。原因很实在：

- **标准出台太晚**：TCP/IP 已经实际运行多年、装机量巨大，OSI 想另起炉灶，阻力重重。
- **实现过于复杂**：七层中会话层、表示层功能模糊，很多功能可以合并；逐层实现成本高。
- **教科书的胜利**：OSI 作为"教学模型"极其成功——它把分层的概念讲得最清楚，因此被全世界教材采用；但作为"现实协议栈"，它输给了更精简的 TCP/IP。

**OSI 的价值不在于"被使用"，而在于"被理解"。** 它是理解任何网络体系结构的坐标系：拿任何协议问一句"它属于哪一层"，你的大脑就会自动调出这张表——它解决什么问题、和谁对等通信、给谁提供服务。这份心智地图，是后续所有章节的导航。

从 OSI 的结局里还能提炼一条普适的教训：**一个标准要胜出，光靠设计得完美不够，还要靠部署得足够早、足够简单。** 这套"设计 vs 生态"的张力，在后面的 IPv6 与 IPv4 之争、HTTP/3 与传统 HTTP 的换代里，还会一再重演。

Tanenbaum 那句"标准的好处在于你可以选择的标准太多了"，说的正是 OSI 与 TCP/IP 并存的讽刺：**理论标准不止一个，而真正胜出的往往是那个更简单、更早被部署的。** 下一节，我们就来看那个务实胜出者——TCP/IP 四层体系结构。

## 6 小结

- **七层口诀**：物链网运会表应；下三层是媒体层，运输层是端到端，上三层是应用层。
- **三分结构**：下三媒体层、运输端到端、上三应用层；路由器只实现到下三层，端口号对路由器透明。
- **两层协作**：对等层靠协议（逻辑通信），相邻层靠服务（经服务访问点 SAP）。
- **封装命名链**：比特 → 帧 → 分组 → 报文段 → 报文，每加一层首部换一次名字。
- **一次旅行**：发送端逐层封装（每层加自己那层的首部），接收端逐层解封装；端口号、IP 地址、MAC 地址分别属于运输层、网络层、数据链路层。
- **历史命运**：OSI 作为标准没赢，作为教学模型统治了所有教材；现实互联网用更精简的 TCP/IP。
- **通用教训**：标准要胜出，除了设计得好，还要部署得早、足够简单。
- **下一跳**：从七层到四层——TCP/IP 体系结构，以及它的"复用/分用"哲学。

在下一节，我们将从"理想的七层"走向"现实的四层"：**TCP/IP 四层体系结构**，看它如何砍掉会话层与表示层，把互联网真正跑起来。
