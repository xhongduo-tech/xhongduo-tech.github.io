## 为什么从 SDN 开始

前面讲路由器时提到「控制面与转发面分离」——但传统网络里，**控制面分散在每台设备里**：每台路由器自己跑协议、自己算路由，网络像一个「各自为政的联邦」。**SDN（Software-Defined Networking，软件定义网络）** 做了一场革命：**把控制面从设备里「抽出来」集中到一个控制器，让网络变得可编程。**<span class="marginnote"><strong>SDN 的核心思想</strong>：<strong>控制面与转发面彻底分离</strong>——<strong>控制面</strong>集中到「SDN 控制器」（一个软件平台），<strong>转发面</strong>留在交换机/路由器里（只做「查表转发」）。交换机不再自己「思考」，而是听从控制器的指挥。<strong>「把大脑集中，把手脚分散」</strong>是 SDN 的精髓——网络从「每台设备自治」变成「一个大脑统一指挥」。</span>

这一节讲：**传统网络的痛点、SDN 的三层架构、OpenFlow 协议。**

## 1 传统网络的痛点：控制面分散

传统网络的「联邦制」带来几个问题：<span class="marginnote"><strong>① 配置复杂</strong>：每台设备要单独配置（ACL、VLAN、QoS），一个大规模网络有成百上千台设备，配置靠人肉、易出错。<strong>② 难以全局优化</strong>：每台设备只知局部，无法做「全网视角」的流量调度。<strong>③ 网络封闭</strong>：设备厂商各自为政，控制逻辑「焊死」在设备里，用户无法自定义网络行为。<strong>「分布式控制 = 灵活性差、运维难」</strong>是传统网络的核心痛点。</span>

**配置复杂**：逐台配置，运维成本高。
**难全局优化**：设备只知局部，无法全网调度。
**网络封闭**：控制逻辑锁在厂商设备里，不可编程。

**辨析｜易错点：** 传统网络的「分布式控制」不是「错」，而是「历史选择」——它的健壮性（没有中心故障点）是优点，但灵活性差。**「分布式控制保健壮，牺牲灵活」**是它被 SDN 挑战的原因。

## 2 SDN 的三层架构

SDN 把网络划分为三层：<span class="marginnote"><strong>① 基础设施层（转发面）</strong>——物理交换机/路由器，只做「查表转发」，通过南向接口听控制器指挥。<strong>② 控制层（控制面）</strong>——SDN 控制器（如 OpenDaylight、ONOS），掌握全网视图，计算转发表并下发。<strong>③ 应用层</strong>——网络应用（负载均衡、安全策略、流量工程），通过北向接口与控制器交互。<strong>「应用层提需求、控制层算策略、基础设施层执行」</strong>。</span>

| 层 | 角色 | 代表 |
| --- | --- | --- |
| 应用层 | 网络应用（提需求） | 负载均衡、流量工程 |
| 控制层 | SDN 控制器（算策略） | OpenDaylight、ONOS |
| 基础设施层 | 交换机/路由器（执行） | 支持 OpenFlow 的交换机 |

**辨析｜易错点：** **SDN 的「分离」不是「删掉控制面」**——控制面还在，只是从「每台设备」搬到了「集中控制器」。**「SDN 不消灭控制面，只集中控制面」**。另一个易错点：**南向接口（控制器↔交换机）与北向接口（控制器↔应用）方向不同**——南向向下发策略，北向向上接应用。**「南管设备、北管应用」**。

## 3 OpenFlow：南向的「通用语言」

**OpenFlow** 是最著名的 SDN 南向协议，定义**控制器如何控制交换机**：<span class="marginnote"><strong>OpenFlow 的核心机制</strong>：<strong>流表（flow table）</strong>——交换机里的一张「匹配-动作」表：匹配字段（源 IP、目的端口、协议等）+ 动作（转发到哪、丢弃、修改）。<strong>控制器通过 OpenFlow 协议下发流表项</strong>，交换机按流表转发。<strong>查不到匹配项时</strong>，交换机可以把「未知流」发给控制器询问（控制器决定后下发流表并缓存）。<strong>「OpenFlow 把交换机的转发逻辑变成了可远程下发的流表」</strong>。</span>

**流表（flow table）**：匹配-动作表（匹配字段 → 动作）。
**控制器下发**：控制器用 OpenFlow 把流表项下发到交换机。
**未知流询问**：交换机查不到匹配项时，问控制器怎么办。

**辨析｜易错点：** **OpenFlow 是「南向接口的一种」，不是 SDN 本身**——SDN 是架构思想，OpenFlow 是实现手段（后来的南向接口还有 P4、OVSDB 等）。**「SDN 是理念，OpenFlow 是其中一种实现」**。另一个易错点：**流表的「匹配」是支持通配的**——可以匹配「目的网段」而非「单台主机」，这让流表能复用、规模可控。**「流表支持通配，才能控制海量流量」**。

## 4 SDN 的价值与代价

SDN 的「集中控制」带来巨大价值，也付出代价：<span class="marginnote"><strong>价值</strong>：① <strong>可编程</strong>——网络行为用软件定义，快速迭代（新策略像写代码一样上线）；② <strong>全局优化</strong>——控制器有全网视图，能算全局最优路径（负载均衡、流量工程）；③ <strong>简化运维</strong>——集中管理，不再逐台配置。<strong>代价</strong>：① <strong>控制器是新的单点</strong>——控制器挂了，依赖它的网络可能瘫痪（需高可用）；② <strong>性能开销</strong>——逐流询问控制器会慢（需缓存优化）。<strong>「SDN 用集中换灵活，用单点换智能」</strong>。</span>

- **价值**：可编程、全局优化、简化运维。
- **代价**：控制器单点风险、逐流询问的性能开销。
- **数据中心应用**：Google B4、数据中心网络大量使用 SDN。

**辨析｜易错点：** **SDN 不是「要取代传统网络」**——它的最佳场景是数据中心、园区等「可集中控制」的环境；骨干网（AS 间）仍靠分布式协议（BGP）。**「SDN 管局部、BGP 管全局」**是两者共存的现实格局。

## 5 OpenFlow 流表：一次匹配的算例

OpenFlow 流表项的核心是「匹配字段 + 动作」。设一张简化的流表：

| 匹配：源 IP | 匹配：目的端口 | 动作 |
| --- | --- | --- |
| 10.0.0.0/8 | * | 转发到端口 1 |
| * | 80 | 转发到控制器（策略检查） |
| * | * | 丢弃 |

收到一个目的端口为 80、源 IP 为 10.1.2.3 的分组时，第一条匹配（源 IP 命中）→ 转发端口 1；若源 IP 是 172.16.0.1、目的端口 80，则第一条不匹配、第二条命中 → 交给控制器处理。**流表的匹配按优先级从上到下，命中即止**——这与防火墙规则表的逻辑如出一辙。

**辨析｜易错点：** OpenFlow 的匹配字段远不止「源/目的 IP」——还包括 VLAN、端口号、协议、甚至某些链路层字段。**匹配的粒度决定了你能编排什么策略**：匹配「源 IP + 端口」就能做细粒度 QoS，匹配「目的网段」就能做粗粒度路由。**「匹配字段多，策略就细」**。

## 6 实践场景：SDN 在数据中心

SDN 最有说服力的实践在数据中心：

- **Google B4**：Google 的广域网内部用 SDN 集中调度，把链路利用率从平均 30%–40% 提升到接近 90%——这是「全局优化」价值的经典证明。
- **数据中心多路径**：传统网络防环路（STP 阻塞冗余链路），SDN 可以同时启用多条路径做负载均衡——流量工程随心所欲。
- **网络切片与多租户**：云平台用 SDN 为不同租户隔离网络、动态分配带宽——「网络即服务」由此而来。

**辨析｜易错点：** SDN 的「全局优化」依赖控制器拥有准确的全网状态——状态越新、调度越准，但同步开销越大。**「全局视图是 SDN 的甜点，也是它的负担」**——这就是为什么 SDN 主要用于可集中控制的环境。

## 7 SDN 的演进：从 OpenFlow 到 P4

SDN 不是一成不变的，它的演进反映了网络可编程的深化：

- **OpenFlow 的黄金时代**：约 2010–2015 年，OpenFlow 是 SDN 的代名词，被用于数据中心与学术网络。
- **瓶颈浮现**：OpenFlow 的「匹配-动作」集合由协议委员会事先定义，想支持新协议（如新型负载均衡）就得等规范更新——**灵活性受限于预定义字段**。
- **P4 的登场**：P4 语言让数据平面**可编程**——不仅行为可编程，连「报文的解析方式」也可编程。交换机不再只能匹配「预定义字段」，而是可以理解任意自定义的包格式。

**辨析｜易错点：** **OpenFlow 与 P4 不是取代关系，而是「同一理念的两代实现」**：OpenFlow 让「转发逻辑」可编程，P4 让「报文解析 + 转发」都可编程。**「OpenFlow 管行为，P4 管结构」**——对学习而言，抓住「控制面集中 + 数据面可编程」这条主线就够。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| SDN | 软件定义网络，控制与转发分离 |
| 控制面 | 集中到控制器的「大脑」 |
| 转发面 | 交换机里的「查表转发」 |
| 南向接口 | 控制器 ↔ 交换机的接口（如 OpenFlow） |
| 北向接口 | 控制器 ↔ 应用的接口 |
| OpenFlow | 最著名的南向协议 |
| 流表 | 匹配-动作表，控制器的下发目标 |
| P4 | 数据平面可编程语言 |
| 控制器 | 掌握全网视图的软件平台 |

## 9 小结

- **SDN 核心**：控制面与转发面分离，控制面集中到控制器。
- **传统痛点**：配置复杂、难全局优化、网络封闭。
- **三层架构**：应用层（提需求）、控制层（算策略）、基础设施层（执行）。
- **OpenFlow**：南向协议，用「流表」（匹配-动作）让控制器远程指挥交换机。
- **价值与代价**：可编程、全局优化 vs 控制器单点、性能开销。
- **现实格局**：SDN 管数据中心/园区，BGP 管骨干网。
- **流表算例**：匹配按优先级从上到下，命中即止；字段越多策略越细。
- **实践证据**：Google B4 把链路利用率从 30%–40% 提升到近 90%。
- **演进方向**：OpenFlow 管行为可编程，P4 让解析与转发都可编程。
- **一句话**：SDN 用「集中的大脑」换「灵活的手脚」。
