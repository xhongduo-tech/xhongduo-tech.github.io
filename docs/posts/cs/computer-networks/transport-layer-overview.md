## 为什么从传输层概述开始

第 4 章的网络层把数据报送到「目的主机」，任务就算完成。但一台主机上同时跑着几十个程序——浏览器、微信、邮件客户端……**数据到底该交给哪个程序？** 这就是**传输层（transport layer）** 的领地：**它把通信从「主机与主机」推进到「进程与进程」。**<span class="marginnote">传输层是五层体系里「<strong>端到端</strong>」的起点：网络层连接的是「主机」，传输层连接的是「主机上的进程」。两个层次的分工一句话——<strong>网络层负责「把数据送到这栋楼」，传输层负责「把数据送到这栋楼的某个房间」</strong>。</span>

这一节立起传输层的全景：**它提供什么服务、两种协议（TCP/UDP）的定位、以及复用与分用。**

## 1 传输层的职责：进程级通信

传输层向上（应用层）提供**进程之间的逻辑通信**——「逻辑」意味着双方进程仿佛直接相连，中间的路由器完全透明。传输层的核心职责：

**进程寻址**：用**端口号**标识主机上的具体进程，把数据交给正确的应用。
**复用与分用**：多个应用进程共用同一个 IP 层服务；接收端按端口把数据分发给正确的进程。
**（TCP 的）可靠传输**：在不可靠的 IP 之上，提供可靠、有序的字节流。
**流量控制与拥塞控制**：TCP 的看家本领。<span class="marginnote">传输层是「应用与网络」之间的适配层：<strong>网络层给的是「尽力而为、可能丢失乱序」的服务，传输层（尤其是 TCP）把它改造成「可靠有序」的字节流</strong>。应用层永远不需要看到 IP 的「坏脾气」——这是传输层最大的贡献。</span>

**辨析｜易错点：** 传输层的「端到端」与网络层的「端到端」含义不同：**网络层的端到端指「源主机到目的主机」，传输层的端到端指「源进程到目的进程」**。中间的路由器只处理到网络层，**不碰传输层**——路由器看不到端口号。**「端口号对路由器透明」**是抓包排障时的重要认知。

### 传输层的「四元组」：一条连接靠什么区分

网络层识别「一条流」靠「源 IP + 目的 IP」；传输层在其上再叠加端口，就得到了**四元组**：

$$
\text{连接身份} = (\text{源 IP}, \text{源端口}, \text{目的 IP}, \text{目的端口})
$$

四元组的意义在于**解开了「一台主机只有一个端口」的错觉**。你在同一台电脑上开三个浏览器标签页访问同一个网站，对方服务器上就存在三条连接——它们的源端口各不相同，服务器正是靠四元组把它们分开。<span class="marginnote">这就是为什么同一时刻「一个网站可以被几千个客户端同时访问」：<strong>服务器只「守」知名端口（如 80），每个连接靠四元组区分，连接数上限由系统资源决定</strong>。五元组还要加上协议号（TCP/UDP），见下一节《端口、套接字》。</span>

**辨析｜易错点：** 「源端口 + 目的端口」必须在**两端的连接上都唯一**：一对通信双方只要四元组不冲突，就能并存多条连接。**「四元组是传输层连接的唯一标识」**——抓包时判断「这是不是同一条连接」，就看四元组是否一致。

这套「四元组分连接」的机制，下一节《端口、套接字与多路复用/分用》会落到**套接字（socket）**这个具体编程接口上——网络编程里 `bind`、`listen`、`accept` 全部围绕端口与套接字展开。

## 2 两个协议：TCP 与 UDP

传输层有且仅有两个主力协议，定位天差地别：

**TCP（Transmission Control Protocol，传输控制协议）**：**面向连接、可靠、有序、有流量控制与拥塞控制**的字节流协议。它把不可靠的 IP 改造成「可靠管道」。

**UDP（User Datagram Protocol，用户数据报协议）**：**无连接、尽力而为、无流量控制**的数据报协议。它只在 IP 之上加了一点点（端口、长度、校验），把「不可靠」原样交给应用。

| 对比维度 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠（确认重传） | 不可靠（尽力而为） |
| 有序性 | 有序 | 可能乱序 |
| 流量/拥塞控制 | 有 | 无 |
| 首部开销 | 20 字节以上 | 8 字节 |
| 典型应用 | 网页、文件、邮件 | 音视频、DNS、游戏 |

**辨析｜易错点：** **UDP 不是「劣质 TCP」——它是「为不需要可靠性的场景设计」的**。实时音视频丢几帧没关系、但不能等重传（时延敏感），所以用 UDP；DNS 查询就一个来回，用 TCP 建连反而浪费。**「TCP 为可靠服务，UDP 为实时/简单服务」**，各司其职，没有优劣。

### 端口号：进程的「门牌号」

无论是 TCP 还是 UDP，都依赖**端口号（port number）** 来标识进程。端口号是 16 位二进制数，取值 $0 \sim 65535$，分三段：

| 端口段 | 数值范围 | 说明 |
| --- | --- | --- |
| 知名端口（well-known） | $0 \sim 1023$ | 系统保留，分配给固定服务 |
| 注册端口（registered） | $1024 \sim 49151$ | 用户进程可申请使用 |
| 动态端口（dynamic/ephemeral） | $49152 \sim 65535$ | 客户端临时借用，用后即还 |

几个必须背下来的知名端口：HTTP 的 `80`、HTTPS 的 `443`、DNS 的 `53`、SSH 的 `22`、FTP 控制连接的 `21`、SMTP 的 `25`、POP3 的 `110`、IMAP 的 `143`。<span class="marginnote">记忆技巧：<strong>80/443 是「网页」，53 是「查名」，22 是「远程登录」，25/110/143 是「邮件三件套」</strong>。这些数字在抓包时天天见面，务必记熟——它们与第 6 章应用层协议一一对应。</span>

**辨析｜易错点：** **端口号是 16 位，所以范围只有 0~65535，不可能出现「大于 65535 的端口」**。若配置里看到 `port: 65536`，那是配置错误。另外**服务器用固定知名端口「守候」，客户端用动态端口「出击」**——你访问网页时，服务器端是 `80`，而你本机那一侧往往是 `49152~65535` 里随机挑的一个。

## 3 复用与分用：传输层的「分拣系统」

传输层最日常的工作是**复用（multiplexing）与分用（demultiplexing）**：<span class="marginnote"><strong>复用</strong>：发送端多个应用进程把数据交给同一个传输层协议，共享 IP 层服务发出。<strong>分用</strong>：接收端传输层收到数据后，按「目的端口号」把数据分发给对应进程。<strong>端口号是分用的「分拣标签」</strong>——源端口标识发送进程，目的端口标识接收进程。</span>

- **发送端复用**：浏览器（HTTP）、微信（自定义端口）同时发数据，传输层把它们打上各自的源端口，统一交给 IP。
- **接收端分用**：收到数据后看目的端口——80 交给 Web 进程，53 交给 DNS 进程。

一个数值例子帮你看清复用/分用的全流程。假设你的电脑（IP 为 `192.168.1.10`）同时发起两个 DNS 查询和一次网页访问：

| 发出的数据报 | 源 IP | 源端口 | 目的 IP | 目的端口 | 交给哪个进程 |
| --- | --- | --- | --- | --- | --- |
| 查询 1 | 192.168.1.10 | 54321 | 8.8.8.8 | 53 | 系统解析器 |
| 查询 2 | 192.168.1.10 | 54322 | 8.8.8.8 | 53 | 系统解析器 |
| 网页请求 | 192.168.1.10 | 54323 | 203.0.113.9 | 80 | 浏览器 |

三个数据报目的端口各不相同（53、53、80）；两个 DNS 查询靠**不同的源端口（54321 vs 54322）**区分。<span class="marginnote">这里的重点是：<strong>分用依据的是「目的端口」，区分并发靠的是「源端口」</strong>——同目的端口的两个查询，用源端口区分各自对应的响应。DNS 响应回来时，53 只是「它们都该进解析器」，靠源端口 54321/54322 才能对上「是哪一个查询的答案」。</span>

**辨析｜易错点：** 复用与分用都是「一个标签管到底」：**TCP/UDP 首部里的「源端口 + 目的端口」就是复用与分用的全部依据**。这与你第 2 章学的「链路层 Type 字段、IP 层协议号」同属一条「逐层分用」链条：链路层看 Type、网络层看协议号、传输层看端口号。**「每一层都有自己认人的标签」**是分层体系最整齐的一条线索。

## 4 传输层与网络层的分工：一张总表

| 分工维度 | 网络层（IP） | 传输层（TCP/UDP） |
| --- | --- | --- |
| 通信主体 | 主机 ↔ 主机 | 进程 ↔ 进程 |
| 寻址方式 | IP 地址 | 端口号 |
| 可靠性 | 尽力而为 | TCP 保证 / UDP 不保证 |
| 中间设备是否参与 | 路由器参与 | 中间不参与（端到端） |
| 服务对象 | 传输层 | 应用层 |

**辨析｜易错点：** 一个高频考点：**路由器「不碰」传输层**——它只看 IP 头，看不到端口号。所以「某端口被墙了」「防火墙按端口拦截」这些操作，都发生在**传输层及以上**的设备上（防火墙、主机）。**「端口是传输层的户口本，路由器不认户口本」**。

## 5 小结

- **传输层职责**：把通信从「主机间」推进到「进程间」，用端口寻址。
- **TCP vs UDP**：面向连接可靠 vs 无连接尽力而为；各有适用场景。
- **复用与分用**：发送端多进程复用、接收端按目的端口分用。
- **与网络层分工**：网络层寻址到主机（IP），传输层寻址到进程（端口）。
- **端口对路由器透明**：中间设备不碰传输层，端口只在端系统之间有意义。
