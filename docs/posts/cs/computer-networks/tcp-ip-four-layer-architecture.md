## 为什么从 TCP/IP 四层开始

上一节我们看了 OSI 七层——那是理论上的完美蓝图。但现实世界运行的，不是七层，而是 **TCP/IP 四层**：它的前身是 1969 年诞生的 ARPANET，1983 年正式采用 TCP/IP 协议族，之后互联网就是在这套四层骨架上长大的。<span class="marginnote">TCP/IP 里的「IP」是网际协议（Internet Protocol），「TCP」是传输控制协议（Transmission Control Protocol）。这个组合名本身透露了它最重要的两个层面：负责「把数据送到」的 IP，与负责「可靠送达」的 TCP。</span>

为什么实际选择四层而不是七层？一句话：**七层是「标准委员会设计出来的」，四层是「真实网络里跑出来的」。** TCP/IP 先有实现、后有标准，每一层都是为了解决一个实际工程问题而存在，砍掉了会话层与表示层这两个「存在感最弱」的层。

## 1 四层分别是哪四层

TCP/IP 自下而上依次是：**网络接口层、网际层、运输层、应用层**。先看一张总表，把每一层与 OSI 的对应关系、代表协议一次摆清：

| TCP/IP 层 | 一句话职责 | 数据单元 | 代表协议 | 对应 OSI |
| --- | --- | --- | --- | --- |
| 4 应用层（Application） | 应用进程之间的通信，直接为用户提供网络服务 | 报文 | HTTP、DNS、SMTP、FTP | 会话+表示+应用 |
| 3 运输层（Transport） | 端到端进程通信，可靠传输与流量控制 | 报文段/用户数据报 | TCP、UDP | 运输层 |
| 2 网际层（Internet） | 分组转发与路由选择，把数据跨网送达 | 数据报（packet） | IP、ICMP、ARP | 网络层 |
| 1 网络接口层（Network Interface） | 在链路上传送帧，与硬件接口打交道 | 帧 | 以太网、Wi-Fi、PPP | 数据链路+物理 |

逐层看：

- **网络接口层**：最低层，负责把数据转换成能在物理链路上传输的帧。它没有独立定义协议，而是直接借用各家数据链路层协议——以太网、Wi-Fi、光纤、拨号，都能成为它的「宿主」。<span class="marginnote">这一层其实是 TCP/IP 的「偷懒」之处：它不规定链路层具体怎么做，只要求「任何能传帧的链路都可以接入」。这种包容性让 TCP/IP 后来能覆盖从同轴电缆到光纤再到无线的一切介质。</span>
- **网际层**：整座大厦的核心。它负责把分组从源主机送到目的主机，核心协议是 **IP**。注意这里有个关键选择：网际层提供的是「尽力而为」（best-effort）的交付——只努力送，不保证送到、不保证不丢、不保证有序。这份「不管质量」的洒脱，正是后面运输层必须亲自扛起可靠性大旗的原因。
- **运输层**：第一次进入「进程级」通信。它把网际层送来的数据，分派给主机上**具体哪个应用进程**。TCP 提供可靠有序的字节流，UDP 只做最简单的传输。
- **应用层**：直接面向用户。DNS、HTTP、SMTP 这些我们每天打交道的协议全部住在这里。

## 2 沙漏模型：为什么 IP 是「瘦腰」

TCP/IP 最著名的结构特征，是一个 **沙漏模型（hourglass model）**。把四层立起来看，网际层的 IP 协议处于最窄的「腰部」：<span class="marginnote">沙漏模型是说：体系结构像一个沙漏，上下都很宽，中间（IP 层）只有唯一一个协议。所有上层协议都通过 IP 传输，所有下层协议都要为 IP 服务。</span>

这个「瘦腰」的设计绝不是巧合。想想看：

- **下层接口统一**：以太网、Wi-Fi、光纤……无论哪种链路技术，都要把自己的帧格式「翻译」成 IP 能认识的形式。上层协议不用关心下面用的是什么网。
- **上层协议共享**：TCP、UDP、ICMP 全都复用 IP 这同一条「管道」。新增一种应用层协议，不必为每种链路单独实现，只要跑在 IP 之上即可。

**沙漏的哲学是「一中立法」：让各种上层协议和各种下层技术，都只与 IP 这一个中间层对话。** 这使得互联网可以同时演进两端——你可以在不变更 IP 的前提下，既升级应用层协议（从 HTTP/1 到 HTTP/3），又更换底层介质（从铜缆到光纤）。

**辨析｜易错点：** 有人误以为「TCP/IP 协议族只有 TCP 和 IP 两个协议」。其实 TCP/IP 是一个**协议族**，内含数十个协议：网际层的 ICMP、ARP，运输层的 UDP，应用层的 HTTP、DNS、FTP 等等。TCP 和 IP 只是其中最核心的两个，故以此命名。

## 3 复用与分用：数据如何找到正确的进程

四层里藏着一个贯穿全栈的机制：**复用（multiplexing）与分用（demultiplexing）**。

- **发送端的复用**：多个上层进程/协议可以同时「共用」一个下层协议的服务——例如浏览器用 TCP 发 HTTP，同时视频通话用 UDP 传音视频，它们共用同一个 IP 层。<span class="marginnote">复用好比一条大马路上跑着许多辆车：应用层每个进程是不同目的地的人，运输层端口号是车上的「门牌标签」，IP 层只管把整条路铺好。</span>
- **接收端的分用**：到达后，接收方要依据「标签」把数据准确分发给对应的上层进程——这个标签在运输层就是**端口号**，在网络层就是**协议号字段**。

分用的具体动作靠「首部里的标识字段」完成：IP 首部里的「协议」字段告诉 IP「这一包数据该交给 TCP 还是 UDP」；TCP/UDP 首部里的「端口号」字段告诉运输层「这份数据该交给哪个应用进程」。<span class="marginnote">这套「首部标识 → 逐层分用」的机制，是抓包工具能一层层展开数据的根本原因：你打开一个抓包文件，看到以太网帧、IP 数据报、TCP 报文段、HTTP 报文层层嵌套，每一层的字段都精确指明了「往哪一层交」。</span>

**辨析｜易错点：** 「分用」发生在接收方，「复用」发生在发送方——两者是同一过程的两个方向，不要混淆。更不要把它与第 5 章会讲到的「多路复用」（多个连接共用同一信道）混为一谈，那是物理层/数据链路层的概念，名字像，机制完全不同。

## 4 辨析：TCP/IP 四层与 OSI 七层的对照

两套体系并存于教材与工程中，最容易记混的就是它们的对应关系。一张对照表收尾：

| 对照项 | OSI 七层 | TCP/IP 四层 |
| --- | --- | --- |
| 层数 | 7 层 | 4 层 |
| 会话/表示层 | 独立成层 | 合并进应用层 |
| 数据链路/物理层 | 分开两层 | 合并为网络接口层 |
| 产生方式 | 委员会先定标准 | 先有实现再总结标准 |
| 面向的哲学 | 理论完整、通用蓝图 | 工程务实、跑通为要 |
| 现实地位 | 教学模型 | 互联网事实标准 |

**辨析｜易错点：** OSI 的「数据链路层+物理层」合起来，约等于 TCP/IP 的「网络接口层」；OSI 的「会话层+表示层+应用层」合起来，约等于 TCP/IP 的「应用层」。**两层合并不等于功能消失**，而是因为会话管理与数据表示在现实中常常并入了应用协议自身的逻辑（比如 TLS 接管加密）。理解了这张对照表，你在读任何资料时都能在「OSI 语言」与「TCP/IP 语言」之间自由切换。

下一节我们进入一个关键细节：既然教材讲课用的是「五层」而不是四层，那这个折中的五层是怎么来的？数据在五层里到底是怎么被一层层「包起来」又「拆开」的？

## 5 小结

- **TCP/IP 四层**：网络接口层、网际层、运输层、应用层；是互联网的事实标准，由 ARPANET 演化而来。
- **核心是网际层**：IP 提供尽力而为的交付；可靠性由运输层的 TCP 负责，这是「端到端原则」的体现。
- **沙漏模型**：IP 位于最窄的腰部，各种上层协议与下层介质都只与它对话，支撑互联网两端独立演进。
- **复用/分用**：发送方多个进程共用下层服务，接收方靠端口号、协议号字段准确分发。
- **与 OSI 对照**：会话/表示并入应用层，数据链路/物理合并为网络接口层；「合并不等于消失」。
- **协议族**：TCP/IP 是数十个协议的集合，TCP 与 IP 只是其中最重要的两个。
