## 为什么从 ARP 开始

第 3 章说帧头用的是 MAC 地址，第 4 章说寻址用的是 IP 地址——**两者之间的「翻译」谁来负责？** 答案就是 **地址解析协议（ARP，Address Resolution Protocol）**：**把 IP 地址解析成 MAC 地址。**<span class="marginnote">为什么要这个翻译？因为链路层只认 MAC，网络层只认 IP——一台主机要发帧，必须知道「目的 IP 对应的 MAC 是什么」。ARP 就是这套「IP → MAC」的查询机制。它属于网际层（网络层），为 IP 服务。</span>

这一节讲清：**ARP 的广播请求/单播应答过程、ARP 缓存、以及跨网段时 ARP 的特殊行为。**

## 1 ARP 的工作过程：广播喊话，单播应答

主机 A 要把数据报发给同一网络的主机 B（已知 B 的 IP，未知 B 的 MAC）：

1. **A 查 ARP 缓存**：看 B 的 IP → MAC 映射是否已缓存。命中则直接用。
2. **A 广播 ARP 请求**：发一个目的 MAC 为全 1（广播）的 ARP 请求：「谁的 IP 是 192.168.1.5？请把 MAC 告诉我。」同网段所有主机都收到。
3. **B 单播 ARP 应答**：只有 B 发现自己 IP 匹配，**单播**回复自己的 MAC。
4. **A 缓存结果**：把「B 的 IP → B 的 MAC」写入 ARP 缓存，之后一段时间内直接使用。<span class="marginnote">为什么请求要「广播」、应答要「单播」？<strong>请求方不知道目的 MAC，只能广播问所有人；应答方知道请求方是谁（从请求帧头能看到），所以直接单播回复</strong>。这个「不知道就广播、知道了就单播」的模式，是网络里「地址发现」类协议的通用套路。</span>

**辨析｜易错点：** ARP 请求是广播，ARP 应答是单播——**「请求广播、应答单播」**是最常考的对称关系。另外，**ARP 请求用的是广播帧，但它携带的 IP 地址是 B 的 IP**——广播是为了「找到人」，不是发给所有人。

## 2 ARP 缓存：避免每次都喊话

如果每次通信都广播 ARP，网络会被广播请求淹没。因此主机维护**ARP 缓存（ARP cache）**：把解析过的「IP → MAC」映射保存一段时间（通常几分钟），过期删除。

**ARP 缓存的优点**：
**减少广播**：大多数帧直接命中缓存，不必广播。
**加快转发**：查缓存比广播询问快得多。

**辨析｜易错点：** ARP 缓存有**生存时间（TTL）**，到期必须重新解析——因为主机的 MAC 可能变（网卡更换）、可能被移走。**缓存既不是永久的，也不是每次通信都重新查**——「有缓存用缓存、没缓存才广播」是 ARP 的完整逻辑。<span class="marginnote">你在命令行输入 `arp -a`（Windows）或 `ip neigh`（Linux）看到的那张表就是 ARP 缓存。缓存条目在通信时会「刷新」，长时间不用就过期。理解缓存过期机制，就能理解为什么「刚 ping 通又断」的诡异问题往往与 ARP 表项过期/冲突有关。</span>

## 3 跨网段的 ARP：问网关，不问最终目的

**ARP 只在本网段内有效**——它解决的是「同一条链路内」的 IP→MAC。当目的主机不在同一网络时，发送方的 ARP 行为发生关键变化：

主机 A 要发数据给另一网络的 C，**A 不查 C 的 MAC**（查不到也不该查）。
A 查**网关（默认路由器）**的 MAC，把帧的目的 MAC 填成**网关的 MAC**，IP 头的目的 IP 仍填 **C 的 IP**。
路由器收下帧，剥掉帧头，按 IP 路由到下一跳，再重新封装帧——**下一段的 ARP 由路由器来做**。<span class="marginnote">这是「IP 端到端、MAC 逐跳」的最佳注脚：<strong>跨网段时，MAC 永远指向「下一跳」而不是「最终目的」</strong>。每跳的路由器都只问「下一站在哪」，不问最终站在哪——ARP 从不为「远方的主机」服务。</span>

**辨析｜易错点：** **ARP 广播请求里问的 IP，一定是「同网段可达」的 IP**——本网段问目的主机，跨网段问网关。**「跨网段时 ARP 问的是网关，不是最终目的」**是理解 ARP 应用边界的关键。抓包时你会发现：发给外网的帧，目的 MAC 是路由器接口的 MAC，而不是远方服务器的 MAC。

## 4 ARP 的安全暗面：ARP 欺骗

ARP 是「无认证的」，这是它最大的安全漏洞：<span class="marginnote">ARP 应答不需要验证——<strong>任何主机都可以主动发 ARP 应答，宣称「某个 IP 对应的 MAC 是我」</strong>。攻击者发送伪造的 ARP 应答，把网关的 IP 映射到自己的 MAC，于是受害者发往网关的流量全部先经过攻击者——这就是 <strong>ARP 欺骗（ARP spoofing）/中间人攻击</strong>。</span>

**ARP 欺骗的攻击链**：
1. 攻击者广播伪造 ARP 应答：「网关 IP 的 MAC 是我的 MAC」。
2. 受害者的 ARP 缓存被污染，把发往网关的帧都交给攻击者。
3. 攻击者窃听/篡改后，再转发给真正的网关——受害者毫无察觉。

**防御手段**：静态 ARP 表、ARP 检测（DAI）、DHCP Snooping 等。

**辨析｜易错点：** ARP 欺骗是**信任无认证协议**的经典教训。它与「中间人攻击」的关系是：**ARP 欺骗是手段，中间人攻击是目的**——攻击者先靠 ARP 欺骗「卡」进链路中间，再实施窃听与篡改。这个「先伪装、再窃听」的模式，在第 7 章网络安全中还会反复出现。

## 5 小结

- **ARP 的职责**：把 IP 地址解析成同网段内的 MAC 地址。
- **工作过程**：广播请求 → 单播应答 → 写入缓存。
- **ARP 缓存**：保存 IP→MAC 映射，有生存时间，减少广播。
- **跨网段行为**：ARP 问网关的 MAC，不问最终目的——「MAC 指向下一跳，IP 指向最终目的」。
- **安全漏洞**：ARP 无认证，可被 ARP 欺骗污染缓存，实施中间人攻击。
- **思想延伸**：「未知就广播、已知就单播」是地址发现类协议的通用套路。
