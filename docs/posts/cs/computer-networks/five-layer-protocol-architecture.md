## 为什么从五层协议体系开始

我们有了两个模型：OSI 七层太理想、太细，TCP/IP 四层又太粗——网络接口层把「物理」和「数据链路」两个性质迥异的层次捆在一起，讲课时说不清帧与比特的分工。于是教材采用了一个折中方案：**五层协议体系结构**。<span class="marginnote">五层体系把 TCP/IP 的网络接口层重新拆开成「物理层」与「数据链路层」，其余三层照搬——既保留了 TCP/IP 的现实骨架，又恢复了 OSI 的讲授清晰度。这是几乎所有教材的默认讲法。</span>

五层自上而下是：**应用层、运输层、网络层、数据链路层、物理层**。与四层相比，它只是把最底层一分为二；与七层相比，它砍掉了会话层与表示层。但这一节最重要的不是「有几层」，而是**封装（encapsulation）与解封装（decapsulation）**——数据在这五层里被一层层「套娃」、又一层层「拆娃」的完整过程。理解了封装，你就理解了整条网络通信的流水线。

## 1 封装：发送方从上到下的「套娃」过程

假设你在浏览器里请求一个网页。发送端的数据沿着应用层一路向下，每一层都做同一件事：**把上层交下来的数据整体当作「数据」，在前面加上本层的首部（header）**。这个「加首部」的动作，就叫**封装**。

一个 HTTP 请求的封装旅程：

1. **应用层**：生成 HTTP 请求报文，这时的数据是明文可见的应用数据。
2. **运输层**：把 HTTP 报文作为「数据」，加上 TCP 首部——首部里有**源端口号、目的端口号**，还有序号、确认号等可靠性字段。此时形成 **TCP 报文段（segment）**。
3. **网络层**：把整个 TCP 报文段作为「数据」，加上 IP 首部——首部里有**源 IP 地址、目的 IP 地址**、协议号等字段。此时形成 **IP 数据报（datagram）**。<span class="marginnote">注意一个重要的不变量：<strong>IP 首部里不装端口号，TCP 首部里不装 IP 地址。</strong> 各层只加自己那层的「身份信息」，绝不越权。抓包时你能在同一个包里同时看到三个地址，正因它们是叠加在一起的。</span>
4. **数据链路层**：把整个 IP 数据报作为「数据」，加上帧首部（以及帧尾部）——首部里有**源 MAC 地址、目的 MAC 地址**。此时形成 **以太网帧（frame）**。
5. **物理层**：不再加首部，而是把整个帧变换成比特流，送上传输介质。

下面这张图把「套娃」画出来：每一层都把上层数据整体吞进肚子里，再戴上自己那顶首部的「帽子」：

**数据单元的名字随层而变**：应用数据 → 报文段（segment）→ 数据报（datagram）→ 帧（frame）→ 比特。**每加一层首部，名字就换一次**——这条命名链是你读任何网络报文的指南针。

## 2 解封装：接收方从下到上的「拆娃」过程

接收端做完全相反的**解封装（decapsulation）**：比特流到达后，从物理层一路向上，每一层做同一件事——**剥掉本层的首部，把剩余的数据原样交给上一层**。

1. **物理层**：把收到的电/光信号还原成比特流。
2. **数据链路层**：识别帧边界，剥掉帧首部，**校验帧是否损坏**（帧尾还有校验码，见第 3 章 CRC），把载荷交给网络层。
3. **网络层**：剥掉 IP 首部，依据首部里的「协议号」字段，把载荷交给对应的运输层协议（TCP 或 UDP）。
4. **运输层**：剥掉 TCP 首部，依据「目的端口号」，把数据交给对应的应用进程。
5. **应用层**：得到原始的应用数据，HTTP 解析出网页内容。

**辨析｜易错点：** 封装与解封装是「严格对称」的镜像过程：发送方第 N 层加首部，接收方第 N 层剥首部。**中间的路由器和交换机呢？** 它们只处理到网络层或数据链路层就停手——路由器剥到 IP 首部、查路由表、重写链路层首部再转发，它绝不打开 TCP 首部；交换机则只在数据链路层工作，连 IP 首部都不看。这就是「各层各管一段」的含金量。

## 3 各层的首部里到底有什么：一次「解剖」

把同一时刻同一个包里的三个首部拆开看，你会清楚地看到每层各管什么：

| 首部 | 关键字段 | 用途 |
| --- | --- | --- |
| TCP 首部（运输层） | 源端口、目的端口、序号、确认号、窗口 | 找到进程、保证可靠、控制流量 |
| IP 首部（网络层） | 源 IP、目的 IP、协议号、TTL、总长度 | 跨网路由、防止环路、标识上层协议 |
| 以太网帧首部（链路层） | 源 MAC、目的 MAC、类型 | 在同一链路内寻址、标识网络层协议 |

**辨析｜易错点：** 最容易被忽视的是那三个「标识上层是谁」的字段：以太网首部的**类型字段**（Type）告诉链路层「帧里装的是 IP 还是 ARP」，IP 首部的**协议号字段**告诉网络层「数据报里装的是 TCP、UDP 还是 ICMP」，TCP/UDP 首部的**端口号**告诉运输层「数据该给哪个进程」。**这三层标识字段层层递进，正是「分用」得以实现的机关。** <span class="marginnote">TCP 的协议号是 6，UDP 的协议号是 17，ICMP 是 1——这几个小数字在抓包和写防火墙规则时经常要亲手输入。记不住没关系，但要知道「协议号」是网络层分用的钥匙。</span>

## 4 为什么「封装」值得单独一课

封装看起来只是「加个首部」，但它是整个网络体系结构最核心的工程思想，值得停下来想透：

**信息隔离**：每一层只需要看懂自己那层的首部，其他层的细节对它是「黑盒」。网络层不需要知道应用数据是什么，链路层不需要知道 IP 路由怎么做——**复杂系统靠层层遮蔽才建得起来**。
**独立演进**：因为各层只依赖「接口约定」（首部格式），某一层的升级不必改动其他层。把 HTTP/1 换成 HTTP/2，链路层一无所知；把 IPv4 换成 IPv6，只要数据链路层按新格式封装即可。
**排障定位**：抓包看封装，能一眼定位故障层——链路层帧都收不到，问题在物理层或链路层；帧正常但 TCP 握手不完成，问题在网络层或以上。**「在哪一层加不进首部、在哪一层剥不出来」就是故障的坐标。** <span class="marginnote">「包能到但打不开」与「包根本不到」是两种截然不同的病：前者多半是端口或应用问题，后者多半是地址或路由问题。学会用抓包工具的层级展开视图，是网络工程师的第一基本功。</span>

下一节，我们把镜头从「数据怎么流」拉近到「层与层之间、对等实体之间怎么对话」——**实体、协议、服务与服务访问点**。

## 5 小结

- **五层体系**：应用层、运输层、网络层、数据链路层、物理层；是四层（合并链路/物理）与七层（拆出会话/表示）之间的教材折中。
- **封装**：发送方每层把上层数据整体加上本层首部，自上而下逐层套娃。
- **解封装**：接收方每层剥掉本层首部，自下而上逐层拆娃，两过程严格对称。
- **命名链**：报文段 → 数据报 → 帧 → 比特，加一层首部换一次名字。
- **三个标识字段**：帧类型字段、IP 协议号、端口号，层层决定分用方向。
- **工程价值**：封装带来信息隔离、独立演进与排障坐标。

在下一节，我们将走进层与层之间的内部机制——**实体、协议、服务与服务访问点**，看「对等层」与「相邻层」到底如何各说各话、又怎么交接数据。
