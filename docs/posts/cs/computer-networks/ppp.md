## 为什么从 PPP 开始

前面几节讲的滑动窗口、ARQ 是「方法」，现在该看一个**真实协议**把这些方法落地了。**点对点协议（PPP，Point-to-Point Protocol）** 是互联网最早、最经典的**点对点链路层协议**——曾用于拨号上网、ADSL 接入、路由器之间专线，至今仍是许多场景的底子。<span class="marginnote">PPP 诞生于 1990 年代拨号上网时代，取代了笨重的 SLIP。它的目标很朴素：<strong>在一条点对点链路上，可靠地、多协议地、带认证地传输数据</strong>。虽然今天家庭宽带已不用拨号，但理解 PPP 仍是理解「链路层协议如何组成、帧长什么样」的最佳范本。</span>

这一节讲 PPP 的两大组成部分与帧格式。先立住一个框架：**PPP 不是单个协议，而是一个协议族**，它靠三个子协议分工协作。

## 1 PPP 的三个组成部分

**PPP 协议族**由三部分组成，各管一段：

**链路控制协议（LCP，Link Control Protocol）**：负责**建立、配置、测试和释放数据链路连接**。它协商链路参数（如最大帧长）、验证链路是否可用。
**网络控制协议（NCP，Network Control Protocol）**：负责**配置网络层协议**。PPP 可以承载多种网络层协议（IP、IPv6 等），NCP 就是「协商在网络层用哪个协议、怎么配置」的接口。IPCP 是承载 IP 时的 NCP。
**认证协议**：负责**身份验证**——常见的是 **PAP**（密码认证，明文）与 **CHAP**（挑战握手认证，加密）。<span class="marginnote">三个子协议的分工：LCP 管「链路本身通不通」，NCP 管「网络层协议怎么配置」，认证管「你是谁」。拨号上网时你看到的「正在验证用户名和密码」就是认证协议在工作；而「连接建立」则要先后过 LCP 与 NCP 两道关。</span>

**辨析｜易错点：** 别把「PPP」当成一个协议——**它是协议族**：LCP 管链路、NCP 管网络层配置、认证协议管身份。很多教材爱考「PPP 包含哪些部分」，答案就是这三类。其中最容易漏的是 NCP——它的存在让 PPP 能「一种链路承载多种网络层协议」，这是 PPP 优于早期 SLIP 的关键。

## 2 PPP 的帧格式：逐字段解剖

PPP 帧的格式如下（按字节）：

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 标志（Flag） | 1 字节 | `0x7E`，帧的定界符 |
| 地址（Address） | 1 字节 | `0xFF`（广播地址，PPP 点对点不寻址） |
| 控制（Control） | 1 字节 | `0x03`（无编号帧） |
| 协议（Protocol） | 2 字节 | 指明信息字段承载的协议（`0x0021`=IP，`0xC021`=LCP，`0x8021`=IPCP） |
| 信息（Information） | 可变 | 载荷数据，最长默认 1500 字节 |
| 帧校验（FCS） | 2 或 4 字节 | CRC 校验码 |
| 标志（Flag） | 1 字节 | `0x7E` |

**辨析｜易错点：** PPP 帧的**地址字段固定 0xFF、控制字段固定 0x03**——因为 PPP 是点对点，不需要寻址，这两个字段是「历史遗产」（从 HDLC 继承），实际没有信息量。**真正重要的是协议字段**：它告诉接收端「信息字段里的数据该交给谁」——交给 IP（0x0021）、LCP（0xC021）还是 IPCP（0x8021）。**「协议字段」是 PPP 帧的灵魂，别被地址字段迷惑。**

## 3 PPP 的透明传输：字节填充

PPP 帧用 `0x7E` 作标志，数据里若出现 `0x7E` 就会与定界符冲突，所以要**字节填充**（前文已介绍，这里看 PPP 的具体规则）：

信息字段中出现 `0x7E`：改为 `0x7D 0x5E`。
信息字段中出现 `0x7D`：改为 `0x7D 0x5D`。
若使用异步链路，`0x7D` 还会转义其他控制字符（如小于 0x20 的控制符）。

**辨析｜易错点：** PPP 的填充发生在**异步链路（字节流）**上；在**同步链路（如 SDH）**上，PPP 也可改用 HDLC 式的比特填充。**「字节填充」与「比特填充」的选用取决于链路性质**——PPP 默认面向字节流，所以教材通常讲它的字节填充版本。<span class="marginnote">PPP 字节填充与透明传输是配套的：填充保证数据里出现 `0x7E` 也不会被误认成帧尾，接收端收到 `0x7D` 就知道「下一个字节要还原」。这套机制正是第 3 章「透明传输」的直接应用。</span>

## 4 PPP 的工作流程：三步走

PPP 的完整工作流程：

1. **链路建立（LCP 阶段）**：双方发送 LCP 报文，协商链路参数（最大接收单元 MRU、认证方式等）。协商成功，链路进入「已建立」状态，但此时还不能传网络数据。
2. **认证（可选）**：按协商的认证协议（PAP/CHAP）进行身份验证。
3. **网络配置（NCP 阶段）**：通过 NCP（如 IPCP）协商 IP 层参数——发送方告诉对端「我要用的 IP 地址」，配置完成后，链路进入「可传网络数据」状态，开始承载 IP 数据报。<span class="marginnote">这个「先 LCP 后 NCP」的顺序是 PPP 的骨架：链路先通、身份先验、网络层参数最后配。理解了这三步，拨号上网的「连接中 → 验证 → 正在登录网络」就能对号入座了。</span>

**辨析｜易错点：** 链路建立（LCP 通）≠ 可以传 IP 数据。**必须等 NCP 配置完成，链路才真正「可传网络数据」**。LCP 阶段传的是 LCP 报文，NCP 阶段传的是 NCP 报文，都是「控制面」；只有到最后阶段才传「用户数据」。**把「链路层连接」与「网络层就绪」混为一谈，是理解 PPP 状态机的常见错误。**

## 5 算例：读懂一个真实 PPP 帧

把帧格式落成一个具体例子。设 PPP 帧要承载一个 IP 数据报（假设数据字段 100 字节）：

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| Flag | 0x7E | 帧开始标志 |
| Address | 0xFF | 点对点不寻址，固定广播地址 |
| Control | 0x03 | 无编号帧 |
| Protocol | 0x0021 | 表示信息字段是 IP |
| Information | 100 字节 | IP 数据报 |
| FCS | 2 字节 | CRC 校验 |
| Flag | 0x7E | 帧结束标志 |

**抓包观察**：看到 `7e ff 03 0021` 开头的帧，就知道「这是 PPP 帧、装的是 IP」。若 Protocol 字段是 0xC021，则是 LCP 控制报文；0x8021 是 IPCP 报文。**「读协议字段，就知道这帧是数据还是控制」**。

**辨析｜易错点：** PPP 帧里**没有「长度」字段**（不像以太网有显式长度/类型）——帧长由 Flag 定界 + FCS 校验决定。**「PPP 靠标志定界，不靠长度字段」**是与以太网帧的一大差异。

## 6 PPP 与 HDLC：同源不同用

PPP 的帧格式从 HDLC 演变而来，两者关系值得理清：

| 对比维度 | HDLC | PPP |
| --- | --- | --- |
| 定界 | 比特填充（01111110） | 字节填充（0x7E） |
| 面向 | 面向比特 | 面向字节 |
| 网络层支持 | 有限 | 多协议（NCP） |
| 认证 | 无 | 有（PAP/CHAP） |
| 典型场景 | 同步链路、路由器互联 | 拨号、ADSL、PPPoE |

**辨析｜易错点：** **PPP 是 HDLC 的「网络化改良」**——继承了帧格式骨架，但加了 NCP（多协议）、认证、字节填充适配。**「PPP 是面向字节的 HDLC + 网络层控制 + 认证」**是一句话概括两者关系。

## 7 PPP 的现代形态：PPPoE 与拨号时代

PPP 今天还在用，最重要的形态是 **PPPoE（PPP over Ethernet，以太网上的 PPP）**：

- **为什么需要**：以太网本身没有「用户认证与计费」能力；而运营商需要「谁在用、用多久、收多少钱」——PPP 提供认证与计费，于是「把 PPP 的会话能力搬到以太网上」就成了 PPPoE。
- **工作方式**：在以太网帧之上建立 PPP 会话（先发现阶段，再 LCP/NCP），典型用于 ADSL/光纤宽带拨号。
- **今天**：家庭宽带「拨号上网」（输入宽带账号密码）多数就是 PPPoE——**「以太网做传输、PPP 做会话与认证」**。

**辨析｜易错点：** **PPPoE 不是「PPP 的以太网版」这么简单**——它要在以太网帧里加 PPPoE 首部，并经历「发现 → 会话」两个阶段。**「PPPoE 把拨号的会话管理带进了以太网时代」**，是理解宽带认证的关键。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| PPP | 点对点协议，链路层协议族 |
| LCP | 链路控制协议，建链协商 |
| NCP | 网络控制协议，配置网络层 |
| IPCP | 承载 IP 时的 NCP |
| PAP | 密码认证协议（明文） |
| CHAP | 挑战握手认证（加密） |

| PPPoE | 以太网上的 PPP |
| 0x7E | PPP 帧标志 |

## 9 小结

- **PPP 是协议族**：LCP（链路控制）、NCP（网络层配置）、认证协议（PAP/CHAP）。
- **帧格式**：Flag 0x7E + 地址 0xFF + 控制 0x03 + 协议 + 信息 + FCS + Flag。
- **协议字段是灵魂**：0x0021=IP、0xC021=LCP、0x8021=IPCP，决定数据交给谁。
- **透明传输**：异步链路用字节填充（0x7E→0x7D 0x5E）。
- **三步流程**：LCP 建链 → 认证 → NCP 配网络层参数，之后才传数据。
- **历史地位**：拨号时代的主角，路由器专线的常见底子。
- **算例要点**：7e ff 03 0021 开头即 PPP+IP 帧，读协议字段辨数据与控制。
- **同源对照**：PPP 是面向字节的 HDLC + NCP + 认证的网络化改良。
- **现代形态**：PPPoE 让以太网宽带具备 PPP 的认证与会话管理。
