# 用户数据报协议（UDP）：首部与特点

## 为什么从 UDP 开始

传输层有两位选手：TCP 与 UDP。TCP 复杂到要写十篇，UDP 简单到一篇讲完——但**简单不是没用，而是恰到好处**。**UDP（User Datagram Protocol，用户数据报协议）**：在 IP 之上只加了一点点「进程寻址」能力，把「不可靠、无连接」原样保留。<span class="marginnote">UDP 的设计哲学：<strong>「少即是多」</strong>——既然 IP 已经尽力而为，很多应用也不在乎「万一丢包」，那就不需要可靠传输。UDP 只做两件事：<strong>用端口区分进程、用校验和验一下数据</strong>，首部只有 8 字节。省下的开销，换来了实时性与极简性。</span>

这一节讲：**UDP 的四大特点、8 字节首部、以及那个著名的「伪首部」校验。**

## 1 UDP 的四大特点

UDP 的定位，一句话：「**无连接、尽力而为、面向报文、首部开销小**」的传输协议。

- **无连接**：发送前不建立连接，直接发——省去握手开销。
- **尽力而为（不保证可靠）**：不保证送达、不保证有序、不重传——是否重传由应用自己决定。
- **面向报文**：UDP 以「报文」为单位——应用层的报文加首部后原样发出，**不拆分、不合并**，报文边界保持完整。<span class="marginnote">「面向报文」是 UDP 与 TCP 的关键区别：<strong>TCP 是字节流，把数据看成连续的流、自己切段；UDP 是报文，每个应用报文原样交付</strong>。所以 UDP 天然保留「一次 send 对应一次 recv」的边界——这对 DNS 查询（一问一答）这类应用非常自然。</span>
- **首部开销小**：仅 8 字节，比 TCP 的 20 字节起省了一半以上。

**辨析｜易错点：** UDP 的「不可靠」不意味着「没校验」——UDP 有**校验和**（见下），只是它「发现错误就丢弃、不重传」。**「检测错误但不恢复错误」是 UDP 的可靠观**。另外，「面向报文」意味着：**若一个 UDP 报文过大超过接收缓冲区，会被截断丢弃**——它不像 TCP 那样帮你拆分。

## 2 UDP 首部：8 字节的极简

UDP 首部固定 **8 字节**，四个字段：

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| 源端口 | 2 字节 | 发送进程端口 |
| 目的端口 | 2 字节 | 接收进程端口 |
| 长度 | 2 字节 | UDP 用户数据报总长度（首部+数据） |
| 校验和 | 2 字节 | 检测传输错误 |

**辨析｜易错点：** 「长度」字段是**UDP 报文总长**（含 8 字节首部）。**源端口可选**——如果不需要对方回复（如单向广播），源端口可置 0。**「UDP 首部只有 8 字节、字段都是 2 字节」**是最容易记的点，也是它与 TCP 20 字节首部的直观对比。

## 3 UDP 校验和：带着「伪首部」的校验

UDP 校验和覆盖三部分：**伪首部 + UDP 首部 + 数据**。其中的**伪首部（pseudo header）**很特别：<span class="marginnote">伪首部不是一个真实的字段，而是<strong>计算校验和时临时拼凑出来的 12 字节</strong>，含源 IP、目的 IP、协议号、UDP 长度。它的作用是<strong>让 UDP 校验「顺带」覆盖 IP 头里的源/目的地址</strong>——防止数据被「送错主机」却仍通过 UDP 校验。</span>

**伪首部的组成**：源 IP（4 字节）+ 目的 IP（4 字节）+ 0 + 协议号（1 字节，UDP=17）+ UDP 长度（2 字节）。

**公式解析：UDP 校验和的覆盖范围**

$$
\text{校验和覆盖} = \underbrace{\text{伪首部 (12B)}}_{\text{含 IP 地址}} + \underbrace{\text{UDP 首部 (8B)}}_{\text{含端口}} + \underbrace{\text{数据}}_{\text{用户载荷}}
$$

- **第一步，为什么要伪首部**：UDP 的校验不能只验「UDP 自己的内容」——如果 IP 把数据报送错了主机，端口对了但 IP 错了，UDP 得能发现。伪首部把「源/目的 IP」也纳入校验。
- **第二步，怎么算**：把这三部分按 16 位一组的二进制数相加（进位回卷），取反码作为校验和。
- **第三步，怎么验**：接收端对同样内容再算一遍，结果全 1 则无错。<span class="marginnote">注意：<strong>TCP 也有同样的伪首部机制</strong>（把 IP 地址纳入校验）。而且 UDP 的校验和是「可选」的——IPv4 下若不用校验，字段置 0（但 IPv6 强制要求校验）。「<strong>伪首部 = 让传输层校验覆盖 IP 地址</strong>」是理解校验和设计的钥匙。</span>

**辨析｜易错点：** 伪首部**只在计算校验和时存在**，不出现在网络上，也不计入 UDP 长度。**「伪首部是算出来的、不是传出去的」**是最常考的辨析点。另外，**UDP 校验和是端到端的**——从源进程到目的进程全程有效，中间路由器不碰。

## 4 UDP 的典型应用：什么时候该用 UDP

UDP 看似「简陋」，但一大批重要的应用恰恰选它：

| 应用 | 为什么用 UDP |
| --- | --- |
| DNS 查询 | 一问一答，建连成本不划算 |
| 视频/语音通话 | 丢包可接受，时延不可接受（不重传） |
| 在线游戏 | 低时延优先，偶尔丢包无所谓 |
| DHCP | 客户端还没有 IP，必须广播式交互 |
| QUIC（HTTP/3） | 在 UDP 上自建可靠层（第 9 章） |

**辨析｜易错点：** 一个常被误记的结论是「可靠的应用都用 TCP」。实际上，**可靠性是一个「设计选择」而非「协议属性」**——QUIC 在 UDP 上实现了可靠的可靠传输，说明「应用需要什么，就自己实现什么」。**「UDP 是把选择权交还应用」**，这正是它生命力的来源。<span class="marginnote">「可靠」可以自己造：QUIC 在 UDP 之上实现了连接、可靠、多路复用——这说明 UDP 不是「只能不可靠」，而是「不替你保证，你想怎么保证自己来」。<strong>UDP 的「空」恰恰是它的「满」</strong>——它给了应用最大的自由。</span>

## 5 小结

- **UDP 四大特点**：无连接、尽力而为、面向报文、首部开销小（8 字节）。
- **UDP 首部**：源端口、目的端口、长度、校验和——各 2 字节，共 8 字节。
- **伪首部**：计算校验和时临时拼凑（源/目的 IP + 协议号 + 长度），让校验覆盖 IP 地址；不上网络。
- **校验和**：端到端、覆盖伪首部 + UDP 首部 + 数据；发现错误即丢弃，不重传。
- **典型应用**：DNS、音视频、游戏、DHCP、QUIC。
- **哲学**：UDP 把「要不要可靠」的选择权交还应用——「空」即「自由」。
