## 为什么从分组转发开始

上一节我们学会了「划分子网、算掩码」——但那是静态知识。路由器拿到一个数据报后，**到底怎么决定往哪转发**？这就是**分组转发（forwarding）**：路由器用目的 IP 地址查找路由表，决定下一跳。划分子网后，转发算法也要相应地「多一步」——用子网掩码逐项匹配。<span class="marginnote">「转发」与「路由」是两个常被混用的词：<strong>转发（forwarding）是查表送出，是每来一个包都要做的「动作」；路由（routing）是建立路由表，是路由协议持续运行的「过程」</strong>。这一节讲转发（查表动作），下一节起讲路由（建表过程）。</span>

这一节的核心：**路由表长什么样、转发算法的三步流程、以及「默认路由」这个救命稻草。**

## 1 路由表的结构：目标网络 + 掩码 + 下一跳

划分子网后，路由表不再按「完整 IP」记，而是按**网络（子网）**记。路由表的典型条目：

| 目的网络地址 | 子网掩码 | 下一跳（接口） |
| --- | --- | --- |
| 192.168.1.0 | 255.255.255.0 | 直接交付（接口 1） |
| 192.168.2.0 | 255.255.255.0 | 直接交付（接口 2） |
| 192.168.3.0 | 255.255.255.0 | 192.168.1.254（路由器 R1） |
| 0.0.0.0 | 0.0.0.0 | 默认路由（网关） |

**辨析｜易错点：** 路由表的「目的」是**网络地址**，不是单台主机——这就是「按网络寻路」原则的体现。**「直接交付」**指目的主机与路由器在同一网络，路由器直接把帧交给该主机（用 ARP 查 MAC）；**「间接交付」**指要转发给下一跳路由器。**「直接 vs 间接」是转发决策的第一个分叉。**

## 2 转发算法的三步流程

路由器收到数据报后，用目的 IP 地址 D 执行转发算法：

1. **先查直接交付**：从数据报的源地址与目的地址判断，若目的主机与路由器**直接相连**（在同一网络），则直接交付，结束。
2. **查路由表**：对路由表中每一行，把 **D 与该行子网掩码做 AND**，看结果是否等于该行的「目的网络地址」。若匹配，按该行的下一跳转发。
3. **查默认路由**：若所有行都不匹配，按**默认路由（default route）**转发——通常指向出口网关，把「去往未知网络」的包交给它。<span class="marginnote">默认路由就是掩码为 0.0.0.0 的那一行：<strong>任何 D 与 0.0.0.0 做 AND 都得 0，永远匹配</strong>。它像一个「兜底方案」：查不到具体路由的包，一律交给默认网关。家庭路由器的「默认网关」配置，就是在写这条默认路由。</span>

**辨析｜易错点：** 三步的顺序不能乱：**先直接、再查表、最后默认。** 且注意，**路由表中匹配用的是「AND 结果 = 目的网络」**——不是「IP 地址相等」。同一目的 IP 可能匹配多行（不同掩码），这时选**最长前缀匹配**（匹配的掩码越长越精确）——这是下一节 CIDR 的核心，这里先埋下伏笔。

## 3 公式解析：路由匹配的 AND 运算

路由查找的本质是重复做「AND 运算」。对数据报的目的地址 $D$ 与路由表第 $i$ 行的掩码 $M_i$：

$$
D \;\text{AND}\; M_i \;\overset{?}{=}\; N_i \quad (\text{该行的目的网络})
$$

- **第一步，取目的地址 D**：数据报 IP 头里的目的 IP。
- **第二步，逐行 AND**：把 D 与每行掩码相与，得到「该掩码下的网络号」。
- **第三步，比对网络号**：与行首的「目的网络地址」相等则匹配，按此行转发。<span class="marginnote">举例：目的 192.168.3.5，某行掩码 255.255.255.0，AND 得 192.168.3.0；若该行网络地址是 192.168.3.0 则匹配。<strong>同一 D 与不同掩码 AND 会得到不同结果</strong>——这正是「不同粒度的路由」并存的原因。</span>

**辨析｜易错点：** 掩码为 255.255.255.255 的行是**主机路由**（精确匹配某台主机）；掩码为 0.0.0.0 的是默认路由。**掩码越长 = 匹配越精确 = 优先级越高**——这个「最长前缀优先」原则在下一节 CIDR 中正式登场。

### 数值算例：逐行 AND 的完整过程

设目的地址 D = `192.168.3.5`，路由表三行如下，逐行 AND 验证：

| 行 | 掩码 | D AND 掩码 | 等于目的网络？ |
| --- | --- | --- | --- |
| 192.168.1.0/24 | 255.255.255.0 | 192.168.1.0 | 否 |
| 192.168.2.0/24 | 255.255.255.0 | 192.168.2.0 | 否 |
| 192.168.3.0/24 | 255.255.255.0 | 192.168.3.0 | 是 → 转发 |

**辨析｜易错点：** 每行都要**独立**做一次 AND——D 是同一个，但掩码不同，AND 结果也不同。这解释了为什么路由查找要「逐行比对」：**目的 IP 不会变，变的是每行的掩码**。「逐行 AND、匹配即转发」是转发引擎的基本循环。

## 4 一张流程图：数据报的「人生三问」

把转发算法浓缩成一张决策图：

```text
收到数据报（目的地址 D）
  │
  ├─① D 与某接口直接相连吗？
  │    ├─ 是 → 直接交付给目的主机（ARP 查 MAC）
  │    └─ 否 → ② 逐行 AND：D AND 掩码 = 目的网络？
  │              ├─ 匹配 → 按该行下一跳转发
  │              └─ 不匹配 → ③ 走默认路由（0.0.0.0 → 默认网关）
```

**辨析｜易错点：** 转发算法是**逐包执行**的——每个数据报都要走一遍这三问，即使它们是同一对主机的通信。这带来一个重要推论：**路由器的转发速率取决于「每秒能查多少次表」**——查表速度是路由器性能的核心指标（这就是后面「路由器的构成」一节讲硬件转发的伏笔）。

## 5 一个完整的转发算例

把三步算法放到一张小网络上走一遍：网络含三个子网，路由器 R 有接口分别连 192.168.1.0/24、192.168.2.0/24、并有一条到 192.168.3.0/24 的间接路由（下一跳 192.168.1.254）。<span class="marginnote"><strong>跟着数据报走</strong>：目的 192.168.1.7 → 与 R 的接口 1 同网，直接交付；目的 192.168.3.9 → 接口直连不符，查表 AND 匹配 192.168.3.0 行，交给 192.168.1.254；目的 8.8.8.8 → 全表不匹配，走默认路由出公网。<strong>三类结果：直接、间接、默认</strong>，一包一判。</span>

- **目的 192.168.1.7**：与 R 的 192.168.1.0/24 接口同网 → **直接交付**（ARP 查 MAC，帧直送）。
- **目的 192.168.3.9**：与接口不同网 → 查表：$192.168.3.9 \text{ AND } 255.255.255.0 = 192.168.3.0$，匹配 → **间接交付**给下一跳 192.168.1.254。
- **目的 8.8.8.8**：所有行都不匹配 → **默认路由**，交给默认网关送上公网。

**辨析｜易错点：** 「直接交付」也要查 ARP——**它只是不用查路由表，仍要解析目的主机的 MAC 地址**。而「间接交付」时，路由器用 ARP 解析的是**下一跳路由器**的 MAC，而不是最终目的主机。**「直接交付查目的主机 MAC，间接交付查下一跳 MAC」**——ARP 的查询对象随交付方式而变。

## 6 转发与路由：一图分清

「转发」与「路由」容易混，用一张表钉死：<span class="marginnote"><strong>转发 = 每个数据报都执行的查表送包动作</strong>（微秒级、逐包）；<strong>路由 = 路由协议（RIP/OSPF/BGP）持续运行、维护路由表的过程</strong>（秒级、周期）。<strong>路由协议建表，转发引擎查表</strong>——现代路由器把这两件事分别交给「控制平面」与「数据平面」的硬件（转发表用 TCAM 硬件加速，查表 O(1)）。</span>

| 维度 | 转发（forwarding） | 路由（routing） |
| --- | --- | --- |
| 含义 | 查表决定下一跳 | 建立/更新路由表 |
| 执行频率 | 每个数据报 | 周期性/事件驱动 |
| 数据来源 | 路由表 | 路由协议、直连、静态配置 |
| 所在平面 | 数据平面 | 控制平面 |
| 典型实现 | TCAM 硬件查表 | RIP/OSPF/BGP 进程 |

**辨析｜易错点：** 面试常问「转发快还是路由快」——**转发要快（纳秒级，靠硬件），路由可以慢（秒级，靠软件协议）**。把「建表的活」和「查表的活」分开，正是现代路由器「控制面 + 数据面」分离架构的动机。**「路由慢没关系，转发必须快」**。

## 7 小结

- **转发 vs 路由**：转发是查表动作（每包执行），路由是建表过程（持续运行）。
- **路由表**：以「目的网络 + 掩码 + 下一跳」为条目，按网络寻路。
- **转发三步**：先查直接交付 → 逐行 AND 匹配 → 默认路由兜底。
- **AND 匹配**：$D \text{ AND } M_i = N_i$ 即匹配；掩码越长越精确（最长前缀优先）。
- **直接 vs 间接交付**：同一网络直接给主机，跨网络交给下一跳路由器。
- **默认路由**：掩码 0.0.0.0，查不到就交给默认网关。
