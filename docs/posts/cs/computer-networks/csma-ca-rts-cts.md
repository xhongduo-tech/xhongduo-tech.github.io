## 为什么从 CSMA/CA 开始

上一节说无线不能用 CSMA/CD——因为无线有「隐藏终端」问题，听不见对方的发送。所以 802.11 采用了 **CSMA/CA（Carrier Sense Multiple Access with Collision Avoidance，载波监听多路访问/碰撞避免）**：**先听后说、随机退避、请求-允许握手**，把「碰撞」尽量「避免」而不是「检测」。<span class="marginnote">一字之差见真章：<strong>CSMA/CD 的 D 是 Detection（检测）——边发边听、撞了再说；CSMA/CA 的 A 是 Avoidance（避免）——先看再说、尽量不撞</strong>。为什么无线不能「边发边听」？因为无线信号在空气中衰减严重，发送方听不到远处设备发送的信号（自己发送时也会「淹没」接收通道）——「检测碰撞」物理上不可靠，只能「避免碰撞」。</span>

这一节讲：**CSMA/CA 的流程、隐藏终端问题、RTS/CTS 机制。**

## 1 CSMA/CA：先听后说 + 随机退避

**CSMA/CA** 的基本流程（DCF 分布式协调功能）：<span class="marginnote"><strong>① 载波监听</strong>：发送前先听信道是否空闲。<strong>② 帧间间隔（IFS）</strong>：信道空闲后，还要等一段帧间间隔（不同优先级用不同 IFS）。<strong>③ 随机退避</strong>：若信道忙，进入随机退避（在竞争窗口内随机选时隙），倒计时为 0 才发送。<strong>④ 确认（ACK）</strong>：接收方收到帧后回 ACK，发送方没收到 ACK 就认为碰撞/丢失，重新退避重发。<strong>「监听 + 退避 + ACK」</strong>是 CSMA/CA 的三板斧。</span>

1. **监听**：发送前听信道。
2. **等待 IFS**：信道空闲后再等帧间间隔。
3. **随机退避**：信道忙则随机退避，倒计时到 0 发送。
4. **ACK 确认**：接收方回 ACK，没收到则重发。

**辨析｜易错点：** CSMA/CA 的「随机退避」与以太网的「二进制指数退避」思想一致，但**无线每次发送前都要退避**（即使信道空闲），而不只是碰撞后——因为有线「空闲=没人发」，无线「空闲也可能有人正在发（只是你听不到）」。**「无线的不确定性强，所以更保守」**是 CSMA/CA 比 CSMA/CD 更「谨慎」的原因。

## 2 隐藏终端问题：无线独有的「盲区」

**隐藏终端（hidden terminal）**：A 与 C 都能与 B 通信，但 A、C 互相听不见对方（信号到不了）。当 A、C 同时给 B 发数据时，就在 B 处碰撞——而 A、C 各自监听时都以为信道空闲。<span class="marginnote"><strong>隐藏终端的场景</strong>：A 和 C 隔得远，信号互相到不了；但它们都在 B 的覆盖范围内。<strong>A 发送时，C 听不见（监听显示空闲），于是 C 也发送——两个信号在 B 处撞车</strong>。这正是无线「监听不可靠」的典型体现：<strong>「你听不见的邻居，正在和你的目标说话」</strong>。CSMA/CA 的监听在这里失效，需要 RTS/CTS 机制补救。</span>

**问题**：A、C 互相听不见，却同时在 B 处发送 → B 处碰撞。
**根源**：监听的「视野」有限——信号到不了的地方，你无法感知。

**辨析｜易错点：** **隐藏终端不是「网络故障」，是无线介质的固有属性**——任何无线系统都有。它揭示了「载波监听的盲区」：**监听只能感知「你听得到的」，不能感知「对方听得到的」**。**「听得到不代表信道闲，听不到不代表没人发」**是无线监听的两面性。

## 3 RTS/CTS：预约信道，消除隐藏终端

解决隐藏终端的经典机制是 **RTS/CTS 握手机制**：<span class="marginnote"><strong>RTS/CTS 流程</strong>：发送方先发 <strong>RTS（Request To Send，请求发送）</strong>——「我想发数据，大家让一让」；接收方回 <strong>CTS（Clear To Send，允许发送）</strong>——「可以发，我已经广播让大家知道了」。<strong>关键是 CTS 是广播的</strong>：隐藏终端 C 也能收到 B 的 CTS（虽然听不到 A 的 RTS），于是 C 知道「B 要收数据了」，主动退避，不再干扰。<strong>「RTS 约发射方，CTS 通知隐藏终端」</strong>。</span>

1. A 发 RTS（广播「我想发给 B」）。
2. B 回 CTS（广播「我允许，你们都别发」）。
3. A 收到 CTS 后发送数据。
4. 隐藏终端 C 收到 CTS，知道 B 忙，主动退避。

**辨析｜易错点：** **RTS/CTS 的妙处是「用接收方广播 CTS 来通知隐藏终端」**——因为 CTS 由 B 发，B 的信号能被 C 收到（A 的信号不行）。**「自己通知不到的人，让接收方替你通知」**是 RTS/CTS 的精髓。另一个易错点：**RTS/CTS 有开销**（握手本身占时间）——所以只在帧较长时启用，短帧直接发更划算。**「长帧用握手，短帧直接发」**是 802.11 的实用取舍。

## 4 CSMA/CA vs CSMA/CD：一张表

| 对比维度 | CSMA/CD（有线） | CSMA/CA（无线） |
| --- | --- | --- |
| D/A 含义 | Detection（检测） | Avoidance（避免） |
| 核心动作 | 边发边听、撞了重发 | 先听后说、随机退避、ACK |
| 是否发送时监听 | 是 | 否（发送时不听） |
| 隐藏终端问题 | 无 | 有（靠 RTS/CTS） |
| 可靠性保证 | 无显式确认 | ACK 确认 |
| 适用场景 | 共享式以太网 | 802.11 无线 |

**辨析｜易错点：** 一句话对比：**「有线撞得起、无线撞不起」**——有线碰撞后检测重发即可，无线碰撞后（因为听不见）很难及时知道、且重发代价大，所以尽量避免。**「CD 靠检测救，CA 靠避免防」**是两者的本质分工。

## 5 无线共享信道的更多难题

隐藏终端之外，无线还有两个经典问题：

- **暴露终端（exposed terminal）**：与隐藏终端相反——A 想发给 B，C 想发给 D，而 C 在 A 的监听范围内。A 监听发现 C 在发，就误以为信道忙而退避——其实 C 发给 D 与 A 发给 B 互不冲突。**暴露终端让无线「该发不敢发」，白白损失吞吐**。
- **公平性问题**：隐藏终端环境下，某些节点可能「抢不到信道」（一直退避），出现不公平——需要协议的公平性设计来缓解。

**辨析｜易错点：** **隐藏终端是「听不见该听的」（不该发时发了），暴露终端是「听见不该听的」（该发时不敢发）**——一个多发了、一个少发了，方向正好相反。**「隐藏怕撞、暴露怕误」**是记忆两者的钥匙。

## 6 DCF 的细节：IFS 优先级与 NAV

CSMA/CA 的「先听后说」比表面更精细，两个关键机制：

- **帧间间隔（IFS）分级**：不同优先级的帧等待不同的 IFS——SIFS（短，最高优先级，用于 ACK/CTS）、PIFS（点协调）、DIFS（分布式，普通数据）。**等待越短优先级越高**，这是无中心环境里的「软优先级」。
- **NAV（网络分配向量）**：RTS/CTS 里携带「我预计占用信道多久」，其他设备据此设置 NAV 计时器「假装信道忙」，即使听不到实际传输——这叫**虚拟载波监听（virtual carrier sensing）**，弥补了物理监听的盲区。

**辨析｜易错点：** 无线监听有两种：**物理监听（听信号）与虚拟监听（看 NAV）**。NAV 机制让「没听到传输」的设备也知道「现在别发」——这正是 RTS/CTS 真正生效的底层机制。**「NAV 是虚拟的耳朵」**，一句话记住它的作用。

## 7 802.11 MAC 的其他机制：分片与省电

除了 RTS/CTS，802.11 的 MAC 层还有两个实用机制：

- **分片（fragmentation）**：长帧出错后重传代价大，于是把长帧切成小片分别传输、分别 ACK——错误只重传坏的那片。无线误码率高，分片能显著提高成功率。
- **省电模式（Power Save）**：无线设备（手机）为了省电，可进入休眠；AP 缓存发给它的帧，等它醒来再取——802.11 的 AP 会周期广播 TIM（流量指示图），告诉休眠设备「你有消息了」。

**辨析｜易错点：** **分片是「拿开销换成功率」，省电是「拿时延换功耗」**——都是无线场景下特有的工程权衡。以太网不需要分片（低误码），也不常需要省电（有线供电）。**「无线协议的一切特别机制，都源于它『不靠谱 + 靠电池』」**。

## 9 小结

- **CSMA/CA**：监听 → IFS → 随机退避 → ACK 确认，把碰撞「避免」在发生前。
- **为什么不能 CD**：无线听不见远处的发送（隐藏终端），边发边听不可靠。
- **隐藏终端**：A、C 互相听不见，却同时在 B 处碰撞——无线介质的固有盲区。
- **RTS/CTS**：RTS 约发射方、CTS（广播）通知隐藏终端，长帧用、短帧不用。
- **黄金对比**：有线「撞了再说」，无线「先让一步」；CD 靠检测救，CA 靠避免防。
- **思想延伸**：「用接收方广播弥补发送方盲区」是无线设计的精妙一招。
- **更多难题**：暴露终端是「该发不敢发」，与隐藏终端方向相反。
- **底层机制**：IFS 定优先级，NAV 是虚拟载波监听，弥补物理监听盲区。
- **实用取舍**：分片换成功率、省电换续航，都是无线独有的权衡。
