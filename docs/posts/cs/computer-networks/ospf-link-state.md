## 为什么从 OSPF 开始

上一节 RIP 的「坏消息传得慢」让人头疼——问题出在距离向量只交换「距离数字」，信息量太小。**开放最短路径优先（OSPF，Open Shortest Path First）** 换了一套思路：**每个路由器把「自己和谁相连、链路代价多少」广播给全网，人人都能画出一张完整的网络拓扑图，再用 Dijkstra 算法自己算最短路径。**<span class="marginnote">「开放」指它是公开标准（非私有），「最短路径优先」指用 Dijkstra 求最短路径树。OSPF 属于<strong>链路状态（link state）算法</strong>：<strong>泛洪链路状态、全局建图、本地计算</strong>。它的收敛速度远快于 RIP，是中型以上网络的主流 IGP。</span>

这一节讲：**链路状态的三大步骤、OSPF 的工程特性、与 RIP 的全面对比。**

## 1 链路状态算法：三步走

链路状态算法的核心是「让每个路由器拥有全网拓扑图」。它分三步：

1. **发现邻居，测链路代价**：每台路由器确认自己的邻居，并测量到每个邻居的链路代价（可配置，可反映带宽、时延等）。
2. **泛洪链路状态通告（LSA）**：每台路由器把自己「与邻居的连接及代价」封装成 **LSA（Link State Advertisement）**，**广播（泛洪）给全网所有路由器**。<span class="marginnote">「泛洪（flooding）」是链路状态的标志动作：<strong>每个收到 LSA 的路由器把它转发给除来源外的所有邻居</strong>，直到全网每台路由器都收到每份 LSA。于是全网所有路由器最终拥有<strong>相同的「链路状态数据库（LSDB）」</strong>——一张完整的网络拓扑图。</span>
3. **各自计算最短路径**：每台路由器用自己的 LSDB，运行 **Dijkstra 算法**，算出到所有网络的最短路径树，生成路由表。

**辨析｜易错点：** 距离向量交换的是「结果」（距离数字），链路状态交换的是「原材料」（拓扑信息）——**原材料可以反复用，结果只能信一次**。这就是为什么链路状态「全局一致、收敛快」：拓扑一变，LSA 重新泛洪，所有路由器立刻重新计算。**「共享拓扑、各自计算」是链路状态与距离向量的根本分野。**

## 2 OSPF 的工程特性

OSPF 作为工业级协议，还带着一批工程特性：<span class="marginnote">OSPF 用 <strong>IP 协议号 89</strong> 直接封装（不靠 TCP/UDP）；它把大 AS 划分成<strong>区域（area）</strong>，区域间通过<strong>骨干区域（area 0）</strong>连接，把泛洪限制在区域内，支持超大规模；还支持<strong>等价多路径（ECMP）</strong>——多条等代价路径可以同时使用、负载分担。</span>

| 特性 | 说明 |
| --- | --- |
| 传输方式 | 直接用 IP（协议号 89），不经 TCP/UDP |
| 度量 | 链路代价（可配置，常用带宽倒数） |
| 区域划分 | 分层区域（area），骨干 + 非骨干 |
| 收敛速度 | 快（拓扑变化立即触发 LSA 泛洪） |
| 环路防护 | 天然无环（每台按同一张图算最短路径树） |
| 等代价负载 | 支持 ECMP 多路径 |

**辨析｜易错点：** OSPF 不像 RIP 那样周期广播整张表，而是**仅在拓扑变化时泛洪 LSA**（另有 Hello 报文维护邻居关系）。它的度量是「代价（cost）」而非「跳数」——可以反映带宽、时延等真实网络质量。**「拓扑变才广播、代价可配置」**是 OSPF 高效与灵活的来源。

## 3 公式解析：Dijkstra 最短路径树

OSPF 用 **Dijkstra 算法**计算最短路径。设源为 u，边（i→j）的代价为 $c(i,j)$，算法维护已确定最短距离的集合 S 与候选集合，每次取距离最小的结点加入 S 并松弛其邻居：

$$
d(j) = \min(d(j),\ d(i) + c(i,j)) \quad (i \in S,\ j \text{ 是 } i \text{ 的邻居})
$$

- **第一步，初始化**：源 u 距离 $d(u)=0$，其余无穷大。
- **第二步，取最小**：从候选里选距离最小的结点 i 加入已确定集合。
- **第三步，松弛**：对 i 的每个邻居 j，若 $d(i)+c(i,j) < d(j)$，更新 $d(j)$。<span class="marginnote">Dijkstra 的贪心正确性来自「边权非负」：一旦某结点被加入已确定集合，它的最短距离就不会再被更新。OSPF 要求代价非负，因此 Dijkstra 必然收敛。这个算法在第二级《算法设计与分析》中会详细证明——这里只需理解「每台路由器用自己的图跑一遍 Dijkstra」。</span>

**辨析｜易错点：** Dijkstra 是**单源最短路径**算法——每台路由器以自己为源，算到所有网络的最短路径。它要求**边权非负**（OSPF 代价满足），否则要用 Bellman-Ford。**「每台路由器各算各的 Dijkstra」**正是 OSPF「分布式但全局一致」的数学基础。

## 4 OSPF vs RIP：全面对比

| 对比维度 | RIP | OSPF |
| --- | --- | --- |
| 算法类型 | 距离向量 | 链路状态 |
| 交换的信息 | 距离表 | LSA（拓扑信息） |
| 度量 | 跳数 | 链路代价 |
| 收敛速度 | 慢（坏消息更慢） | 快 |
| 环路风险 | 有（计数到无穷） | 无 |
| 规模限制 | 15 跳内 | 可分区域、可大规模 |
| 更新方式 | 30 秒周期广播 | 拓扑变化触发泛洪 |
| 传输 | UDP 520 | IP 89 |

**辨析｜易错点：** 一句话对比：**RIP 是「邻居告诉我距离」，OSPF 是「大家都画同一张图、自己算路」**。RIP 简单但慢、易环、限规模；OSPF 复杂但快、无环、可扩展。**「OSPF 是 RIP 在『收敛、规模、环路』三个维度上的全面升级」**——这正是路由协议演进的主线。

## 5 小结

- **链路状态三步**：发现邻居 → 泛洪 LSA → 各自跑 Dijkstra。
- **核心思想**：共享拓扑、各自计算——全网一致，收敛快、无环路。
- **OSPF 特性**：IP 协议号 89、链路代价度量、区域划分、ECMP。
- **Dijkstra 松弛**：$d(j)=\min(d(j), d(i)+c(i,j))$，边权非负保证收敛。
- **与 RIP 对比**：距离向量 vs 链路状态，收敛、环路、规模全面胜出。
- **演进主线**：新协议修旧协议的缺陷——OSPF 修 RIP 的收敛慢与环路。
