# 差错检测：奇偶校验与循环冗余检验（CRC）

## 为什么从差错检测开始

物理层的比特在链路上奔跑，噪声、串扰、信号衰减都会让某些比特「翻车」——0 变 1、1 变 0。数据链路层必须有能力**发现**这些错误，否则接收端会把「被污染的 IP 数据报」当成好数据往上送。<span class="marginnote">差错检测（error detection）的思路是：发送端对数据做某种<strong>冗余运算</strong>，在帧尾附加一段<strong>冗余码（校验码）</strong>；接收端用同样的运算验证数据与校验码是否自洽，不自洽就认定出错、丢弃该帧。核心是「用少量冗余换差错可见」。</span>

这一节从最简单的**奇偶校验**讲起，再到数据链路层的主角——**循环冗余检验（CRC）**，并用一个完整的二进制除法示例把它算透。

## 1 奇偶校验：最简单也最弱

**奇偶校验（parity check）**：在数据后附加一个校验位，使整个码字中 1 的个数为偶数（偶校验）或奇数（奇校验）。

**偶校验**：数据中 1 的个数为偶数时，校验位填 0；为奇数时填 1。使「数据+校验位」里 1 的个数保持偶数。
接收端统计「数据+校验位」里 1 的个数，若不是偶数（对偶校验而言），就说明传输出错。

**辨析｜易错点：** 奇偶校验只能检测**奇数个**比特的错误，**检测不了偶数个比特的错误**——因为两个比特同时翻车，1 的个数奇偶性不变。<span class="marginnote">这个「奇数/偶数」限制是奇偶校验的死穴：噪声引起的突发错误常常波及多个连续比特，若是偶数个，奇偶校验就「视而不见」。所以它只能用在内存校验这类低要求场合，数据链路层必须用更强的 CRC。</span>

## 2 CRC 的原理：模 2 除法

**循环冗余检验（CRC，Cyclic Redundancy Check）**：把数据看成一个**二进制多项式**，用约定的**生成多项式 G(x)** 对它做**模 2 除法**，把余数作为校验码（**帧校验序列 FCS**）附在数据后面。<span class="marginnote">模 2 除法与普通除法的差别：<strong>每一步的减法都用「异或」代替，没有进位借位</strong>。也就是说，在二进制里 1-1=0、0-0=0、1-0=1、0-1=1（当作异或）。CRC 的全部奥妙，就是「数据多项式 ÷ 生成多项式，取余数」。</span>

设数据多项式为 $M(x)$，生成多项式为 $G(x)$（r 次），CRC 的计算分四步：

1. **补零**：在数据 M 后补 r 个 0，得到 $M \cdot x^r$（因为余数最高 r 位）。
2. **模 2 除法**：用 $M \cdot x^r$ 除以 $G(x)$，得余数 $R(x)$（r 位）。
3. **发送**：把余数 $R(x)$ 附加在数据后面，形成要发送的码字 $M \cdot x^r + R(x)$。
4. **验证**：接收端用同一个 $G(x)$ 去除收到的码字，**余数为 0 则无错**，非 0 则出错丢弃。

## 3 公式解析：一个完整的 CRC 例子

用最经典的例子算一遍。数据 $M = 101001$（对应多项式 $x^5 + x^3 + 1$），生成多项式取 $G(x) = x^3 + x^2 + 1$，即二进制 $x^5 + x^3 + 1$，$r = 3$。

**第一步，补 3 个 0**：$101001$ → $101001000$。

**第二步，模 2 除法**：

```text
          110101       ← 商
     ______________
1101 ) 101001000
       1101
       ----
        1110
        1101
        ----
         0111
         0000
         ----
          1110
          1101
          ----
           0110
           0000
           ----
            1100
            1101
            ----
             001        ← 余数（FCS）
```

**第三步，附加余数**：发送码字 = 101001 + 001 = 101001001。

**第四步，验证**：接收端用 1101 去除 101001001，若余数为 0，判定无错。<span class="marginnote">关键理解：<strong>发送码字恰好能被 G(x) 整除</strong>——因为我们在数据后补了 r 个 0、再模 2 加上了余数，等价于把数据多项式凑成了 G(x) 的整数倍。接收端只要检查「能否整除」即可，无需知道原始数据。</span>

**辨析｜易错点：** 三个最常见的坑：① **补零的个数是 r，即生成多项式的次数**，不是生成多项式的位数（位数 = r+1）；② 余数不足 r 位时**前面要补 0**（如余数 1 补成 001）；③ 除法全程用**异或**，不是普通减法——一旦用了普通减法，整个 CRC 就错了。

## 4 CRC 的能力与工程使用

CRC 的检错能力由生成多项式决定：<span class="marginnote">CRC 能保证：<strong>检测出所有奇数个错误、所有突发长度 ≤ r 的突发错误，以及 1 - 2^{-r} 比例的更长突发错误</strong>。r 越大（校验位越多），检出能力越强，但开销也越大——这是「冗余度」与「检错力」的权衡。</span>

工程中常用的生成多项式：

| 协议 | 生成多项式（二进制） | 名称 |
| --- | --- | --- |
| 以太网 | 100000100110000010001110110110111（33 位） | CRC-32 |
| HDLC/PPP | 10001000000100001（17 位） | CRC-16 |
| 早期磁盘 | 11000000000000101（17 位） | CRC-16 |

以太网帧尾的 **FCS（Frame Check Sequence）** 就是 CRC-32 计算出的 4 字节校验码。

**辨析｜易错点：** CRC 是**检错**，不是**纠错**——它只能告诉你「这个帧错了」，不能告诉你「哪一位错了」、更不能修复。检测到错误后，数据链路层通常**丢弃该帧**，靠上层的重传机制（如 TCP 的确认重传）来恢复。「检错 + 重传」这套组合拳，就是数据链路层实现可靠传输的基本范式。

## 5 小结

- **奇偶校验**：加 1 个校验位，只能检测奇数个错误，检测不了偶数个。
- **CRC 原理**：数据多项式对生成多项式做模 2 除法，余数作 FCS 附在帧尾。
- **四步流程**：补 r 个 0 → 模 2 除 → 取余数 → 附加发送；接收端验证能否整除。
- **易错三坑**：补零个数 = r；余数不足要补 0；全程用异或而非普通减法。
- **检错能力**：由 r 决定；能检出所有 ≤ r 位的突发错误，越强越贵。
- **检错≠纠错**：CRC 只报错，恢复靠上层重传。
