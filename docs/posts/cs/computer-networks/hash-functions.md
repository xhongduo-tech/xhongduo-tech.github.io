## 为什么从散列函数开始

数字签名「先哈希、后签名」，MAC 也建立在哈希之上——**散列函数（hash function）** 是鉴别与签名的「通用零件」。它把任意长度的数据，映射成固定长度的「摘要」，且具有两个神奇性质：**单向性**（从摘要推不回原文）与**抗碰撞性**（很难找到两个不同数据哈希相同）。<span class="marginnote">散列函数的本质是「<strong>数据指纹</strong>」：<strong>任意长度输入 → 固定长度输出（如 256 位）</strong>。两个核心性质：<strong>① 单向性</strong>——从摘要算不回原文；<strong>② 抗碰撞性</strong>——想找两个「哈希相同」的不同数据，计算上不可行。有了这两个性质，摘要就能充当「完整性凭据」：数据改一个比特，摘要立刻变。</span>

这一节讲：**散列函数的性质、MD5 与 SHA 的兴衰、完整性校验的应用。**

## 1 散列函数的三大性质

密码学安全的散列函数必须满足：<span class="marginnote"><strong>① 单向性（one-way）</strong>：已知 $H(M)$ 求 $M$，计算上不可行。<strong>② 抗碰撞（collision resistance）</strong>：找到 $M_1 \ne M_2$ 使 $H(M_1)=H(M_2)$，计算上不可行。<strong>③ 雪崩效应（avalanche）</strong>：输入改 1 比特，输出约一半比特变化。<strong>「单向保隐私、抗碰撞保完整、雪崩让篡改现形」</strong>是三大性质的通俗版。</span>

**单向性**：从摘要推不回原文。
**抗碰撞性**：很难找到两个哈希相同的不同数据。
**雪崩效应**：输入微小变化 → 输出剧烈变化。

**辨析｜易错点：** 散列与加密的本质区别：**加密可逆（有密钥能解回），散列不可逆（单向）**。**「加密是双行道、散列是单行道」**是两者最根本的区分。另一个易错点：**散列没有密钥**——任何人都能对任何数据算哈希；它的「完整性」靠「比对摘要」，不是靠「保密」。

## 2 散列函数的用途：完整性校验

散列函数最常见的用途是**完整性校验**：<span class="marginnote"><strong>文件校验</strong>：下载软件时，网站公布文件的 SHA-256 值，你下载后算一遍比对——一致则文件完整未篡改。<strong>密码存储</strong>：服务器不存你的明文密码，只存「密码的哈希」——登录时算哈希比对，即使数据库泄露，攻击者也拿不到明文。<strong>签名基础</strong>：先哈希再签名，让公钥算法只需处理短摘要。<strong>「摘要 = 完整性凭据」</strong>贯穿这些场景。</span>

**文件校验**：比对下载文件的哈希，确认没被篡改。
**密码存储**：只存密码哈希，数据库泄露也不暴露明文。
**签名基础**：先哈希后签名（上一节的标准姿势）。
**去重**：相同内容 → 相同哈希，可用于数据去重。

**辨析｜易错点：** **密码存储「直接存密码哈希」也不够安全**——攻击者可以用「彩虹表」（预计算的常见密码哈希表）反查。所以现代做法要**加盐（salt）**：在密码后拼接随机值再哈希，让相同密码的哈希也不相同。**「裸哈希可被彩虹表破解，加盐哈希才是正解」**是密码存储的进阶知识。

## 3 MD5 与 SHA：两代散列的兴衰

散列算法经历了「MD5 → SHA-1 → SHA-2/SHA-3」的演进：<span class="marginnote"><strong>MD5</strong>`（128 位）：曾经无处不在，但 2004 年发现<strong>碰撞攻击</strong>——攻击者能构造两个哈希相同的数据，已不再安全。<strong>SHA-1</strong>`（160 位）：2017 年 Google 演示了首个实际碰撞攻击，正式退役。<strong>SHA-2</strong>`（SHA-256/512）：当前主流，256 位摘要，碰撞攻击在计算上不可行。<strong>SHA-3</strong>`：新一代标准，结构完全不同（Keccak）。<strong>「MD5/SHA-1 已破、SHA-2 是主流」</strong>是现代哈希选择的结论。</span>

| 算法 | 摘要长度 | 状态 | 说明 |
| --- | --- | --- | --- |
| MD5 | 128 位 | 已破 | 2004 年碰撞攻击 |
| SHA-1 | 160 位 | 已破 | 2017 年实际碰撞 |
| SHA-256 | 256 位 | 现行主流 | SHA-2 家族 |
| SHA-3 | 可变 | 新一代 | Keccak 结构 |

**辨析｜易错点：** **「MD5 已不安全」不是「MD5 不能用了」**——它仍可用于非安全场景（如数据去重），但**绝不可用于签名、证书、密码存储等安全场景**。**「安全场景只用 SHA-2/SHA-3」**是现代最佳实践。另一个易错点：**SHA-256 的「256」是摘要长度，不是「密钥」**——散列函数没有密钥。

## 4 公式解析：为什么「改一个比特，指纹全变」

用一个简化模型理解雪崩效应。设 $H$ 是散列函数，$M$ 与 $M'$ 只差一个比特：

$$
H(M) \ne H(M'), \quad \text{且约一半输出比特不同}
$$

- **第一步，看内部结构**：散列函数内部有「压缩函数」把输入分块处理，每块都搅动内部状态。
- **第二步，看雪崩**：一个比特的变化经过多轮置换/替换扩散，最终影响约一半输出位。
- **第三步，看安全性**：正因为雪崩，攻击者无法通过「微调数据」来「微调摘要」——想伪造摘要只能暴力碰撞。<span class="marginnote">雪崩效应是「<strong>数据指纹</strong>」这一比喻的数学基础：<strong>指纹对微小的改变极度敏感</strong>。它把「数据完整性」变成了「摘要比对」——任何篡改都会留下明显痕迹。这也解释了为什么 CRC（第 3 章）不能替代密码散列——CRC 是「检测随机错误」，密码散列要防「恶意构造」，要求强得多。</span>

**辨析｜易错点：** **CRC 与密码散列不是一回事**：CRC 防「无意差错」（链路层用），密码散列防「恶意篡改」（安全用）。**「CRC 防随机错误、哈希防恶意构造」**是两者的本质区别，也是为什么密码散列要求「抗碰撞」而 CRC 不要求。

## 5 算例：两次实际应用的完整流程

**场景一：文件完整性校验**。你要下载一个软件（setup.exe）：
1. 网站公布「SHA-256: 3a7b...e9」。
2. 你下载 setup.exe，本地算 SHA-256。
3. 比对：一致 → 文件完整未篡改；不一致 → 文件被改过，弃用。
**要点**：攻击者若要篡改文件，必须同时篡改「公布的哈希」——所以官方哈希通常放在 HTTPS 页面或签名证书里。

**场景二：加盐密码存储**。用户注册时：
1. 服务器生成随机盐 salt。
2. 存储 hash(salt + password) 与 salt 本身。
3. 登录时：取回 salt，算 hash(salt + 输入)，比对存储值。
**要点**：即使两个用户密码相同，盐不同 → 哈希不同 → 彩虹表失效。**「加盐让相同的密码也有不同的哈希」**。

**辨析｜易错点：** 加盐防的是「彩虹表」与「相同密码可批量破解」，但**防不住「弱密码本身」**——密码还是「123456」时，攻击者可以逐个试。**「加盐防表，强密码防试」**是密码存储的两道防线。

## 6 散列的更多应用：从 HMAC 到 Merkle 树

散列的用途远超「校验」，几个现代应用值得知道：

- **HMAC（哈希消息鉴别码）**：带密钥的散列——发送方用「密钥 + 消息」算 HMAC，接收方用同样的密钥验证。**「HMAC = 有密钥的哈希，能验证『谁发的』」**（消息鉴别，上一节 MAC 的正规实现）。
- **Merkle 树（默克尔树）**：把大量数据块的哈希逐层合并成一棵哈希树，根哈希代表整批数据——**「区块链用它高效验证数据未被篡改」**。
- **内容寻址**：用「内容的哈希」作为内容的地址（IPFS 等）——**「相同的哈希 = 相同的内容，天然去重」**。
- **Git**：Git 的 commit 对象就是内容的哈希，靠它保证历史不可篡改。

**辨析｜易错点：** **普通散列不防「中间人换数据」**——攻击者可以同时换数据与哈希；HMAC/签名才解决「认证」。**「裸哈希验完整，HMAC/签名验真伪」**是两者的分工。

## 7 散列与加密：一张对照表

| 对比维度 | 散列 | 加密 |
| --- | --- | --- |
| 可逆性 | 不可逆（单向） | 可逆（有密钥解密） |
| 输出 | 固定长度摘要 | 与输入同长量级 |
| 密钥 | 无 | 有 |
| 用途 | 完整性、指纹 | 机密性 |
| 例子 | SHA-256 | AES、RSA |

**辨析｜易错点：** **散列管「没被改」，加密管「不被看」**——两者互补而非替代。**「先加密保机密、再哈希保完整」**是完整安全链的标准组合（TLS 记录协议就是「加密 + MAC」）。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 散列函数 | 任意长度 → 固定长度摘要 |
| 单向性 | 从摘要推不回原文 |
| 抗碰撞 | 难找两个哈希相同的数据 |
| 雪崩效应 | 微小输入变化 → 输出剧变 |
| 完整性校验 | 比对摘要验证数据未篡改 |
| 加盐 | 密码后拼随机值再哈希 |
| 彩虹表 | 预计算的常见密码哈希表 |
| MD5 / SHA-1 | 已被攻破的旧算法 |
| SHA-256 / SHA-3 | 现行安全算法 |
| HMAC | 带密钥的哈希（消息鉴别） |
| Merkle 树 | 哈希逐层合并的验证结构 |

## 9 小结

- **散列函数**：任意长度 → 固定长度摘要；单向、抗碰撞、雪崩三大性质。
- **完整性校验**：文件校验、密码存储、签名基础、去重。
- **密码存储**：加盐哈希防彩虹表；裸哈希不够安全。
- **算法演进**：MD5（破）→ SHA-1（破）→ SHA-256（主流）→ SHA-3（新一代）。
- **CRC vs 哈希**：CRC 防随机错误、哈希防恶意构造。
- **黄金规则**：安全场景只用 SHA-2/SHA-3，不用 MD5/SHA-1。
- **算例结论**：文件校验靠比对官方哈希、加盐让相同密码哈希不同。
- **现代应用**：HMAC 验真伪、Merkle 树验批量、Git/区块链靠哈希防篡改。
- **散列 vs 加密**：散列管没被改、加密管不被看，两者互补。
