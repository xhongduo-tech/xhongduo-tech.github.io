## 为什么从防火墙开始

密码学保护了「数据本身」，但还没解决「谁该被允许进入网络」。**防火墙（firewall）** 是网络的「守门员」：**部署在内网与外部网络之间的边界设备，根据规则决定放行还是阻止流量。**<span class="marginnote">防火墙的核心是「<strong>访问控制</strong>」：<strong>在信任的内网与不信任的外网之间设一道关卡，按预设规则过滤流量</strong>。它是纵深防御（§7.1）里「边界防御」的关键一环。防火墙经历了从「简单查表」到「跟踪状态」再到「深度检查」的演进——这一节讲最核心的两种：<strong>分组过滤与状态检测</strong>。</span>

这一节讲：**防火墙的定位、分组过滤、状态检测、应用代理。**

## 1 防火墙的定位：内外的边界

**防火墙（firewall）**：位于**可信内网与不可信外部网络之间**的安全设备，执行访问控制策略。它的价值：<span class="marginnote"><strong>防火墙的原则</strong>：默认拒绝——没有明确允许的流量，一律拒绝。<strong>检查对象</strong>：IP 地址、端口号、协议类型、连接状态、甚至应用内容。<strong>部署位置</strong>：企业边界、内部网段之间（分区隔离）、DMZ（非军事区）。<strong>「防火墙是边界思维：把网络分成信任区域，边界处设防」</strong>——这与纵深防御一脉相承。</span>

- **边界设备**：部署在信任边界（内网/外网之间、分区之间）。
- **访问控制**：按规则放行/拒绝。
- **默认拒绝**：未明确允许的流量一律阻止。

**辨析｜易错点：** 防火墙**不是「杀毒软件」**——它管「谁能进来」，不管「进来的数据里有没有病毒」（那是 IPS/杀毒的事）。**「防火墙管访问，IPS 管内容」**是两类安全设备的分工。另一个易错点：**防火墙是「边界防御」，管不了内部攻击**——内网自身的威胁要靠其他手段（下一节 IDS/IPS）。

## 2 分组过滤：最基础的防火墙

**分组过滤防火墙（packet filtering）**：**逐包检查**，按「五元组」（源 IP、目的 IP、源端口、目的端口、协议）与规则表比对，决定放行或丢弃。它是**无状态（stateless）**的——只看单个包，不看连接上下文。<span class="marginnote"><strong>分组过滤的规则</strong>：如「允许内网访问外网的 80/443 端口」「拒绝外网主动访问内网的 22 端口」——按五元组精确匹配。<strong>优点是快</strong>（每个包只查表）、<strong>简单</strong>；<strong>缺点是「无状态」</strong>——它无法判断「这个包是不是某个已允许连接的应答」，攻击者可以伪造「看起来像应答」的包混进来。</span>

- **五元组**：源 IP、目的 IP、源端口、目的端口、协议。
- **无状态**：只看单个包，不看连接上下文。
- **优点**：快、简单；**缺点**：不能区分「合法应答」与「伪造包」。

**辨析｜易错点：** **分组过滤的「无状态」是它的天花板**——它不知道「这个包属于哪个连接」。所以它很难精细地回答「应不应该放行」。**「无状态防火墙是『只看快递单』，看不到包裹的前后关系」**是它的形象比喻。

## 3 状态检测：有记忆的防火墙

**状态检测防火墙（stateful firewall）**：**跟踪每个连接的状态**，决策时结合「该包属于哪个连接、连接处于什么状态」。它是**有状态（stateful）**的。<span class="marginnote"><strong>状态检测的核心</strong>：维护一张「<strong>状态表</strong>」记录每个活动连接（四元组 + 状态）。当一个新包到达，防火墙先查状态表——如果是「已建立连接的合法后续包」，放行；如果是「外网主动发起的新连接」，查规则表。这样就能精确区分「内网发起的连接的应答」与「外网主动的入侵尝试」——<strong>应答放行、主动进入拒绝</strong>。<strong>「分组过滤看单包，状态检测看连接」</strong>。</span>

- **状态表**：记录所有活动连接的状态。
- **有状态判断**：新包先查「是否属于已建立连接」。
- **精确放行**：内网发起连接的应答放行，外网主动进入拒绝。

**辨析｜易错点：** **状态检测解决了分组过滤的「应答与伪造难分」问题**——它知道「哪些连接是内网发起的、合法存在」。**「状态检测 = 分组过滤 + 连接记忆」**是最准确的概括。它也是现代防火墙的基础形态（NAT 也是「有状态」的，两者常在同一设备实现）。

## 4 应用代理防火墙：深入内容的检查

更高一层的防火墙是**应用代理（application proxy / application gateway）**：<span class="marginnote"><strong>应用代理防火墙</strong>：不直接转发流量，而是<strong>代理应用层通信</strong>——客户端先连代理，代理再连服务器。代理可以<strong>检查应用层内容</strong>（如 HTTP 请求里的 URL、命令），执行更细粒度的策略。优点是安全级别高（应用层可见）；缺点是慢（要解析应用协议）、不支持所有协议。<strong>「分组过滤看包头、状态检测看连接、应用代理看内容」</strong>是三代防火墙的递进。</span>

- **代理**：客户端连代理、代理连服务器，中间可见应用内容。
- **深度检查**：能检查 HTTP URL、命令等应用层内容。
- **优点**：安全级别高；**缺点**：慢、协议覆盖有限。

**辨析｜易错点：** 防火墙的三代不是「取代」，而是「分层」——现代企业常常「分组过滤 + 状态检测 + 应用代理」组合使用。**「三层防火墙各管一段」**。另一个易错点：**代理防火墙与正向代理的区别**——代理防火墙是「安全设备」（检查内容），正向代理是「加速/缓存设备」（优化访问），功能不同。

## 5 小结

- **防火墙**：信任边界上的访问控制设备，默认拒绝。
- **分组过滤**：按五元组查表，无状态、快但不够精细。
- **状态检测**：跟踪连接状态，精确区分「应答」与「主动进入」。
- **应用代理**：代理应用层通信，检查内容，安全高但慢。
- **三代递进**：分组过滤看包头 → 状态检测看连接 → 应用代理看内容。
- **边界思维**：防火墙管「谁能进来」，管不了内部攻击（交给 IDS/IPS）。
