## 为什么从虚电路与数据报开始

第 4 章的主角是网络层，它最根本的问题在开头就要回答：**网络层向上层提供什么服务？** 历史上存在两种对立的设计哲学——**虚电路（virtual circuit）** 与 **数据报（datagram）**。这不是「实现细节」的分歧，而是**「要不要先建连接」**的路线之争，决定了整个网络层的性格。<span class="marginnote">虚电路源于<strong>电信网络</strong>（电话网的思维），数据报源于<strong>计算机网络</strong>（邮政/分组交换的思维）。互联网选择了数据报——<strong>这个选择是「尽力而为」哲学的第一步</strong>：网络层不保证质量，把可靠性推给上层（TCP）。理解了这个选择，你就能理解后面 IP、路由、TCP 的一切设计。</span>

这一节把两种服务的机制、对比、以及互联网为何选数据报讲透。

## 1 虚电路服务：先建「线路」，再传数据

**虚电路（virtual circuit，VC）**：通信前先**建立一条逻辑连接**，双方约定好路径与资源，数据沿着这条「虚拟线路」传送，通信结束再释放。它叫「虚」，因为**它不是真实的物理专线**，而是路由器转发状态中记录的「逻辑路径」——数据仍走共享链路，只是看起来像一条专线。

虚电路的三阶段：<span class="marginnote">虚电路的生命周期与打电话完全同构：<strong>呼叫建立（拨号）→ 数据传送（通话）→ 释放连接（挂断）</strong>。每个分组里带着「虚电路号」，路由器按它查表转发——转发简单、有 QoS 保证，但建链有开销、断链需重拨。典型代表：ATM、帧中继、MPLS 标签交换。</span>

1. **建立连接**：发送方发出请求，沿途路由器为这条连接分配**虚电路号（VCID）**并建立转发表项。
2. **传输数据**：所有分组带同一个 VCID，路由器按 VCID 转发，不需要每次查目的地址。
3. **释放连接**：拆除各路由器上的表项，回收资源。

**辨析｜易错点：** 虚电路是「**面向连接**」的服务，但**不保证可靠**——它只是「先建路径再传」，可靠与否由协议自身决定。**「面向连接」与「可靠」是两个独立维度**（第 1 章讲服务时已经强调过）。虚电路的价值在于「转发快、可预留资源」，不在「可靠」。

### 一个数值例子：虚电路的建立

假设主机 A 想与主机 B 通信，途经路由器 R1、R2 两个中转节点。建立阶段的分工如下：

| 步骤 | 发生在哪 | 动作 | 分配到的 VCID |
| --- | --- | --- | --- |
| 1 | 主机 A | 发出「建立请求」分组 | — |
| 2 | 路由器 R1 | 记录「来自 A 的分组走输出端口 2」 | 在本段分配 15 |
| 3 | 路由器 R2 | 记录「来自 R1 的分组走输出端口 3」 | 在本段分配 8 |
| 4 | 主机 B | 接受请求，回送「建立确认」 | — |

此后 A→B 的每个数据分组都只带 VCID，路由器查「连接表」转发，**不需要再看目的 IP 地址**——这就是虚电路「转发快」的由来：查表项是精确匹配，而不是最长前缀匹配。<span class="marginnote">注意 VCID 是<strong>逐段分配、每段不同</strong>的（15、8），只在相邻两台设备之间有局部意义——这与数据报「分组全程携带同一个目的 IP」形成对照。MPLS 的标签栈正是这套思想的现代实现，见第 9 章。</span>

## 2 数据报服务：每分组独立寻路

**数据报（datagram）**：**每个分组独立地**根据目的地址逐跳转发，**没有建立连接的过程**。每个分组带着完整的目的地址，每一跳路由器独立查路由表、决定下一跳。

数据报的特点：

**无连接**：发送前不建链，直接发。像寄信——每封信独立写地址、独立投递。
**逐跳独立决策**：同一份数据的多个分组，可能走不同路径到达。
**可能乱序**：因为路径可能不同，分组的到达顺序可能与发送顺序不一致。<span class="marginnote">「同一份数据的分组可能走不同路径」是数据报与虚电路的关键差异：虚电路所有分组走同一条路径（有序到达），数据报的分组各自为政（可能乱序）。<strong>「乱序」是数据报服务的固有属性，接收端的排序问题交给上层（TCP）解决。</strong></span>

**辨析｜易错点：** 数据报是「**无连接**」服务，但它**同样需要转发表**——只是这个表是「按目的地址前缀 → 下一跳」的路由表，不是「按连接 → 出口」的连接表。**虚电路查「连接号」，数据报查「目的地址」**——这是两者在转发机制上的本质区别。

**「有表」不等于「有连接」**：数据报的路由表是「全网共享、各路由器独立维护」的，它不认识「某一条具体的流」；虚电路的连接表是「每条流建立时逐个写入」的，它精确到「这一条流」。这个「表认不认得出你」的差别，正是判断网络层是否面向连接的最直观判据。

### 一个数值例子：数据报的逐跳转发

假设路由器 R1 的路由表如下，主机 A 发出的目的地址为 `10.0.4.7` 的分组经过 R1：

| 目的地址前缀 | 下一跳 |
| --- | --- |
| 10.0.0.0/8 | 接口 0（直连） |
| 10.1.0.0/16 | R2 |
| 10.1.4.0/24 | R3 |
| 默认 | R4 |

`10.0.4.7` 与 `10.0.0.0/8` 匹配（10 开头即属此前缀），于是从接口 0 转发。若分组的目的地址是 `10.1.4.99`，则按最长匹配选 `10.1.4.0/24` 走 R3。<span class="marginnote">注意数据报转发里每次查表都<strong>带着完整目的地址、逐跳独立决策</strong>——下一跳可能因路由表更新而改变，同一个数据流的后续分组也可能改走新路径。这与虚电路「建立时就定死路径」形成鲜明对比。</span>

## 3 一张表：虚电路 vs 数据报

| 对比维度 | 虚电路 | 数据报 |
| --- | --- | --- |
| 是否建连 | 先建再传 | 直接发 |
| 转发依据 | 虚电路号（VCID） | 目的地址 |
| 路径 | 建立时固定 | 逐跳独立决定 |
| 分组顺序 | 有序到达 | 可能乱序 |
| 路由器状态 | 维护连接表项 | 只维护路由表 |
| 资源预留/QoS | 可预留 | 无（尽力而为） |
| 故障处理 | 断链要重建 | 路由自动绕行 |
| 典型代表 | ATM、MPLS | IP（互联网） |
| 可靠性 | 取决于实现 | 尽力而为，靠上层 |

**辨析｜易错点：** 常考的一句话总结：**虚电路是「电话思维」——先占线再通话；数据报是「邮政思维」——每封信独立寄。** 互联网选数据报，意味着**网络层「傻而快」、上层「聪明而负责」**：IP 只做「尽力而为」，可靠性、有序性、流量控制全交给 TCP。**「端到端原则」是数据报哲学的学名**：下层保持简单，把复杂留给端系统。

## 4 互联网为什么选数据报

互联网选择数据报，是深思熟虑的工程决策，有三条理由：

**对故障健壮**：数据报没有「连接」可断——某条链路断了，路由器自动改走别的路径；虚电路断了整条连接就瘫痪，必须重建。
**适合突发流量**：数据报不需要预留资源，谁有数据谁发，对「网页浏览、视频点播」这类突发流量利用率高；虚电路预留的资源在空闲时是浪费。
**让网络简单、让终端智能**：路由器越简单越好——不做连接状态、不做可靠性，只做转发；可靠性由端系统的 TCP 负责。<span class="marginnote">这就是著名的「<strong>端到端原则（end-to-end principle）</strong>」：应该把功能放在端系统而不是网络中间，因为「中间网络保持哑管道」最利于演进。互联网的「哑管道 + 聪明终端」设计，与电信网「聪明管道 + 哑终端」形成鲜明对照。</span>

**辨析｜易错点：** 别以为「数据报一定比虚电路好」——在**需要 QoS 保障**的场景（语音、视频实时通信），虚电路能预留带宽、保证时延；互联网对这类需求是用「上层努力 + 网络尽力」来近似解决的（如 RTP、DiffServ）。**「选数据报」是互联网的历史选择，不是「唯一正确的选择」。**

### 再看一层：为什么「连接」是网络层而非传输层的事

这里必须厘清一个高频混淆：**虚电路的「连接」发生在网络层内部，TCP 的「连接」发生在传输层之上，两者不是一回事**。

- **TCP 连接**：是端系统之间、逻辑上「收发双方状态的建立」，中间路由器完全不知道它存在。
- **虚电路**：是中间路由器**共同维护**的转发状态，网络层自己记住「这条流走哪个端口」。

**辨析｜易错点：** 互联网用的是「TCP 面向连接 + IP 数据报」，也就是说**连接只在两端（传输层）有，网络层永远无连接**。若把「虚电路」误当成「TCP 连接的网络层版」就错了——虚电路的网络层是有状态的，而 IP 网络层的路由器**无状态、无连接**。这条「无状态网络层」原则，正是第 4 章《IP 与虚拟互连网络》一切设计的前提。

用一句话记住这对概念：**虚电路是「网络层记着你的连接」的网络，数据报是「网络层只认目的地址」的网络**。前者把「认识你」的成本摊到建链时，后者把「认识你」的成本摊到每个分组的每个字节里——「连接开销放在哪里」是理解二者效率差异的钥匙。掌握这两种服务，就为后面第 4 章《IP 与虚拟互连网络》做好了思想准备。

## 5 小结

- **两种服务**：虚电路（先建连、按连接号转发、有序）与数据报（无连接、按地址转发、可能乱序）。
- **黄金对比**：虚电路 = 电话思维，数据报 = 邮政思维。
- **转发机制差异**：虚电路查连接号，数据报查目的地址。
- **互联网的选择**：数据报——对故障健壮、适合突发、符合端到端原则。
- **端到端原则**：让网络简单、终端智能；可靠性交给上层。
- **不是谁好谁坏**：需要 QoS 的场景（实时通信）虚电路仍有用武之地。
