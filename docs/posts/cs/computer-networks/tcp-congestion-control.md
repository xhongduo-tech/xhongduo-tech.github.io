# TCP 的拥塞控制：慢开始与拥塞避免

## 为什么从拥塞控制开始

流量控制解决了「接收方处理不过来」，但还有一个更隐蔽的问题：**网络本身可能堵了**——如果大量发送方都全速发送，链路的交换节点缓冲区会溢出、丢包，大家互相拖累，整体吞吐暴跌。**拥塞控制（congestion control）**：**让每个发送方自觉地探测网络容量，把发送速率维持在「网络受得了」的范围内。**<span class="marginnote">拥塞控制的独特之处：<strong>发送方没有「网络容量」的直接信息——它只能靠「丢包」或「延迟增大」间接推断</strong>。所以 TCP 拥塞控制是一套「试探 + 反应」的自适应算法：先小心试探（慢开始），再逐渐加码（拥塞避免），撞到拥塞就退回来。</span>

这一节讲核心的两段：**慢开始（slow start）与拥塞避免（congestion avoidance）**，以及它们与阈值 ssthresh 的配合。

## 1 拥塞窗口 cwnd：发送方的「探路杖」

**拥塞窗口（cwnd，congestion window）**：发送方自己维护的一个「窗口」，反映**它对当前网络容量的估计**。发送方实际发送量 = min(rwnd, cwnd)。

cwnd 的**单位**在教材里常简化为「报文段个数」（实际是字节数）：<span class="marginnote">拥塞窗口 cwnd 不是接收方给的，是<strong>发送方根据网络反馈自己算的</strong>。它的核心逻辑：<strong>没丢包 → 网络还受得了 → cwnd 增大（试探更多）；丢包 → 网络堵了 → cwnd 缩小（退让）</strong>。「丢包当信号」是 TCP 拥塞控制的信息基础——它没有网络内置的流量计，只能靠自己的丢包感受。</span>

- 收到 ACK、没丢包 → cwnd 按规则增大。
- 超时/丢包 → cwnd 大幅缩小（并可能退到慢开始）。
- 实际发送窗口 = min(rwnd, cwnd)。

**辨析｜易错点：** cwnd 是**发送方本地**的，rwnd 是**接收方上报**的——一个代表「网络容量」，一个代表「接收能力」。**两者取小才是真实发送窗口**。考试常考「cwnd 如何随事件变化」，核心就是「没丢增大、丢了大减」。

## 2 慢开始：从 1 开始，指数增长

**慢开始（slow start）**：连接刚建立（或超时后），发送方**从很小的 cwnd 开始**（如 1 个 MSS），然后**每收到一个 ACK，cwnd 加 1**——效果是 cwnd **指数增长**（每经过一个 RTT 翻倍）。

$$
\text{cwnd} = 1,\ 2,\ 4,\ 8,\ \ldots \quad (\text{每 RTT 翻倍})
$$

**公式解析：慢开始为什么是「指数」增长**

- **第一步，看单位**：假设 cwnd = n（可同时发 n 段）。
- **第二步，看一个 RTT 内收到几个 ACK**：发出 n 段，收到 n 个 ACK。
- **第三步，每个 ACK 使 cwnd+1**：一个 RTT 后 cwnd 变为 n + n = 2n——**翻倍**。<span class="marginnote">「慢开始」的名字有点反直觉：它从「小」开始，但增长是「快」（指数）的——<strong>「慢」指起点低，「快」指增速猛</strong>。设计动机：连接刚建立时不知道网络水位，先从很小流量试探，但试探的过程要足够快，别让用户等太久。所以慢开始的本质是「快速探测」。</span>

**辨析｜易错点：** 「慢开始」不是「慢慢增长」——它是「**从 1 开始、指数增长**」。把「慢开始 = 增长慢」理解反，是最常见的错误。**「慢开始快增长」**才是真相。

## 3 拥塞避免：过了阈值，加法增长

cwnd 不能无限翻倍——设一个阈值 **ssthresh（慢开始门限）**：

- **cwnd < ssthresh**：慢开始阶段，指数增长。
- **cwnd ≥ ssthresh**：进入**拥塞避免**，改为**加法增长（加性增）**——每个 RTT 只让 cwnd +1（线性增长）。

**拥塞避免**的规则：**每个 RTT 使 cwnd 增加 1 个 MSS**（线性、保守），避免一下子冲到拥塞点。它不是在「避免拥塞」，而是在「接近拥塞点时放慢试探的脚步」。<span class="marginnote">「慢开始指数探、拥塞避免线性加」的动机：<strong>远离阈值时大胆翻倍（快速逼近），接近阈值时小心加一（避免撞墙）</strong>。这是典型的「先快后稳」控制策略——在工程里到处可见（比如电梯加速再匀速）。</span>

**公式解析：加性增**

$$
\text{cwnd} \;\leftarrow\; \text{cwnd} + 1 \quad (\text{每个 RTT，仅当 cwnd} \geq \text{ssthresh})
$$

- **第一步，触发条件**：cwnd 已经达到或超过 ssthresh。
- **第二步，增长量**：每 RTT 只 +1，不再是翻倍。
- **第三步，物理含义**：接近拥塞点了，小心推进，留出反应空间。

**辨析｜易错点：** 慢开始与拥塞避免的**分界是 ssthresh**，不是某个固定 cwnd 值。而且 **ssthresh 会动态调整**——发生超时丢包时，ssthresh 被设置为「当前 cwnd 的一半」，cwnd 退回 1（慢开始重启）。**「撞墙时 ssthresh = cwnd/2」**是重传后最经典的数值变化。

## 4 慢开始 + 拥塞避免的完整曲线

把两者合起来，cwnd 随时间的轨迹（假设某时刻超时）：

1. 连接建立：cwnd=1，慢开始，指数翻倍。
2. cwnd 到 ssthresh（如 16）：进入拥塞避免，线性 +1。
3. 某 RTT 超时（拥塞信号）：**ssthresh = cwnd/2**，cwnd = 1，重进慢开始。
4. 重复 1–3，cwnd 呈「锯齿状」在平衡点附近波动。<span class="marginnote">这个「锯齿」是 TCP 拥塞控制最经典的图形：<strong>上升是试探（指数或线性），骤降是退让（减半或归 1）</strong>。整体上看，TCP 就是在「逼近网络容量 → 撞一下 → 退让 → 再逼近」的循环中，自发地把发送速率稳定在可用带宽附近——这就是「端到端拥塞控制」的数学形态。</span>

**辨析｜易错点：** **超时与「三个重复 ACK」触发的反应不同**——超时是「严重的拥塞信号」，cwnd 直接归 1、重进慢开始；而「三个重复 ACK」只丢了一个段，拥塞没那么严重，进入「快重传 + 快恢复」（下一节），cwnd 只减半不归 1。**「超时归 1、快重传减半」**是 TCP 对「不同严重程度拥塞」的差异化响应。

## 5 小结

- **拥塞控制的本质**：发送方靠「丢包当信号」自发调节速率，端到端、无中央控制。
- **cwnd**：发送方对网络容量的估计，实际发送 = min(rwnd, cwnd)。
- **慢开始**：cwnd 从 1 起、每 RTT 翻倍（指数）——「慢开始快增长」。
- **拥塞避免**：cwnd ≥ ssthresh 后每 RTT +1（线性）——接近拥塞点小心试探。
- **ssthresh**：阈值，超时后设为 cwnd/2、cwnd 归 1。
- **锯齿曲线**：指数/线性上升 + 骤降退让，自发稳定在带宽附近。
