## 为什么从端口与套接字开始

上一节说传输层用「端口」寻址进程。这一节把这件事做细：**端口号怎么分类、端口与 IP 如何组合成「套接字」、多路复用/分用到底怎么执行。**<span class="marginnote">理解这一节，你就理解了「一个 IP 上怎么同时跑几十个服务」、以及「为什么服务器开个端口就有人能访问」。端口是传输层最日常、也最容易被低估的概念——它是「进程寻址」的全部答案。</span>

这一节讲：**端口的分类、套接字（socket）的定义、复用/分用的执行细节。**

## 1 端口号：进程的「门牌号」

**端口（port）**：传输层的服务访问点（SAP），用 **16 位端口号**（0–65535）标识主机上的一个进程。TCP 与 UDP 各有独立的 65536 个端口号。

端口号的分类：<span class="marginnote">端口分三类：<strong>熟知端口（well-known，0–1023）</strong>——固定分配给公共协议（HTTP=80、DNS=53、FTP=21、SMTP=25）；<strong>登记端口（1024–49151）</strong>——供需要注册的应用程序使用；<strong>动态/私有端口（49152–65535）</strong>——客户端临时使用，用完即释放。</span>

| 范围 | 名称 | 用途 |
| --- | --- | --- |
| 0–1023 | 熟知端口 | 公共协议固定使用（80、443、53、21、25…） |
| 1024–49151 | 登记端口 | 已注册的应用程序 |
| 49152–65535 | 动态端口 | 客户端临时分配 |

**辨析｜易错点：** 熟知端口是「服务器监听」的端口，不是「客户端」的端口。**客户端连接服务器时，源端口是随机的动态端口，目的端口才是熟知端口**——抓包时看到源端口是 `5xxxx` 正是这个原因。**「服务器用熟知端口监听，客户端用动态端口发起」**是一句话考点。

## 2 套接字：IP + 端口 = 通信端点

**套接字（socket）**：**IP 地址 + 端口号**的组合，唯一标识网络中的一个进程通信端点。

$$
\text{socket} = (\text{IP 地址},\ \text{端口号})
$$

例如 `(203.0.113.9, 80)` 表示「203.0.113.9 这台主机上的 80 号进程」。<span class="marginnote">套接字是网络编程的核心抽象：应用进程通过「套接字」向传输层读写数据，就像打开一个文件句柄。TCP 连接靠「四元组」标识：<strong>（源 IP，源端口，目的 IP，目的端口）</strong>——四者完全相同的两个套接字之间，才是一条唯一的 TCP 连接。</span>

**辨析｜易错点：** 套接字与「端口」不能画等号：**套接字 = IP + 端口**，端口只是套接字的一半。一个服务器进程监听一个熟知端口（如 80），它可能有成千上万个套接字连接——每个连接的「对端套接字」不同。**「端口是服务器的一扇门，套接字是这扇门上挂的一把把钥匙」**。

## 3 多路复用与分用的执行：以 TCP 为例

多路复用/分用是传输层的核心操作，用 TCP 看它的执行：

**复用（发送端）**：多个应用进程的数据，都交给 TCP。TCP 给每份数据加上「源端口 + 目的端口」的首部，构成报文段，交给 IP 发送。

**分用（接收端）**：TCP 收到报文段，看**目的端口**，把数据交给对应的进程。注意 TCP 的分用**不只靠目的端口**——它还看源端口、目的 IP、源 IP（四元组），因为同一端口可能有多条连接。<span class="marginnote">TCP 与 UDP 的分用细节不同：<strong>UDP 分用只看「目的 IP + 目的端口」</strong>（二元组），凡发给该端口的一律交给那个进程；<strong>TCP 分用看「四元组」</strong>——因为 TCP 是多连接的，同一目的端口上可能并行多条连接，必须靠源端区分。这个差异在编程里体现为「UDP 一个 socket 收所有，TCP 每条连接一个 socket」。</span>

**辨析｜易错点：** **UDP 分用看二元组，TCP 分用看四元组**——这是传输层分用的核心区别。别以为「分用就是看目的端口」——对 TCP 来说远远不够。抓包分析时，UDP 流按「两 IP + 两端口」识别，TCP 连接也按同一四元组识别，但 TCP 还要维护「连接状态」这一层。

## 4 端口与复用的关系：一张表

| 概念 | 作用 | 关联 |
| --- | --- | --- |
| 端口号 | 标识进程 | 16 位，TCP/UDP 各自独立 |
| 套接字 | 标识通信端点 | IP + 端口 |
| 复用 | 发送端多进程共用传输层 | 靠源端口区分 |
| 分用 | 接收端按端口分发 | UDP 二元组 / TCP 四元组 |

**辨析｜易错点：** 复用/分用发生在**同一台主机内**：发送端在主机内做「合并」（复用），接收端在主机内做「分发」（分用）——它不跨网络。**「复用分用是本机的传输层事务」**，与网络层、链路层的复用（信道复用）完全是两回事——后者是「共享信道」，前者是「分发进程」。**「传输层的复用分用 vs 物理层的信道复用」是最易混淆的一对词。**

## 5 小结

- **端口号**：16 位，标识进程；熟知（0–1023）、登记（1024–49151）、动态（49152–65535）。
- **服务器监听熟知端口，客户端用动态端口发起**——抓包的经典规律。
- **套接字**：IP + 端口，唯一标识一个进程通信端点；TCP 连接用四元组标识。
- **复用/分用**：发送端复用（合并），接收端分用（分发）。
- **UDP 分用看二元组，TCP 分用看四元组**——多连接场景的根本差异。
- **别混**：传输层复用分用（分发进程）≠ 物理层信道复用（共享信道）。
