# 实体、协议、服务与服务访问点

<div class="epigraph">

## 为什么从这四个术语开始

我们已经知道网络「分层」，但层与层之间、同一层的两台机器之间，到底靠什么机制协作？答案藏在四个术语里：**实体、协议、服务、服务访问点**。<span class="marginnote">这四个词是计算机网络体系结构的「语法」，几乎所有教材第一节讲完分层，第二节就讲它们。很多同学把它们当成名词背诵题，其实它们描述的是一套生动的分工：谁在说话（实体）、按什么规矩说话（协议）、能给邻居什么帮助（服务）、在哪交接（服务访问点）。</span>

理解这组概念，等于拿到一张「分层协作的工程图纸」：任何一层，向上提供服务、向下依赖服务、向对等层用协议通信。抓住了这个三角关系，后面每一章（链路层、网络层、运输层）的协议设计，你都能看出「它向上提供了什么服务、用什么协议实现」。

## 1 四个术语的精确定义

先逐一立住定义：

**实体（entity）**：任何可发送或接收信息的**硬件或软件进程**。一台主机里有多个实体——发送邮件的进程是一个实体，收发网页的进程是另一个实体。<span class="marginnote">注意「实体」是动态的：它特指正在运行的进程（process），不是指程序文件本身。你开了两个浏览器窗口，就有两个并行的 HTTP 实体。</span>

**协议（protocol）**：控制**两个对等实体**进行通信的规则的集合。协议的三要素是**语法**（数据与控制信息的结构或格式）、**语义**（发出何种控制信息、完成何种动作及做出何种应答）、**同步**（事件实现顺序的详细说明）。

**服务（service）**：本层向**上层**提供的功能。服务的实现者是下层的实体，受益者是上层。

**服务访问点（SAP，Service Access Point）**：**相邻两层实体之间交换信息的接口**，是上层调用下层服务的「门」。

用一张表把这四个概念一次分清：

| 术语 | 作用对象 | 一句话 | 生活中的类比 |
| --- | --- | --- | --- |
| 实体（entity） | 本层 | 通信的主角，能收发信息的进程 | 打电话的两个人 |
| 协议（protocol） | 对等层 | 对等实体间的通信规则 | 两人约定的「说话语言」 |
| 服务（service） | 相邻层（向上） | 本层向上层提供的功能 | 电信运营商提供的「通话服务」 |
| 服务访问点（SAP） | 相邻层（交接处） | 上下层交换数据的接口 | 电话机的插孔 |

## 2 协议与服务：最容易混淆的一对

**「协议」管对等层，「服务」管相邻层**——这是全章最重要的辨析。

**协议是水平的**：连接的是两台机器上的**同一层**（对等层）。数据并不真的在对等层之间传输，它们各自与自己的下层交互，从而「模拟」出对等通信。
**服务是垂直的**：连接的是同一台机器上的**上下相邻两层**。下层是服务提供者，上层是服务使用（调用）者。

**辨析｜易错点：** 协议的实现「使用了」下层提供的服务，但协议本身不向用户（上上层）直接暴露。例如 TCP 协议向上层提供「可靠的字节流服务」，但 TCP 协议的实现依赖网络层提供的「尽力而为的数据报交付服务」。**服务是「能做什么」，协议是「怎么做才能做到」。** <span class="marginnote">再补一句关键区分：<strong>协议是「水平」的，服务是「垂直」的</strong>。很多面试题爱考这个：两句话背熟——「对等层之间是协议，相邻层之间是服务」。</span>

还要注意：**上层能看见服务，但看不见协议的实现细节**。这正体现了分层的黑盒思想——运输层向上层承诺「保证送达」，至于它内部怎么重传、怎么编号，应用层一概不必关心。

**辨析｜再补一个「协议三要素」的落地例**：以 HTTP 为例——**语法**是请求行的格式（`GET /index.html HTTP/1.1`），**语义**是每个字段的含义（`200` 表示成功、`404` 表示不存在），**同步**是事件的先后顺序（必须先发请求，才能收响应）。同一套三要素套到任何协议（TCP、DNS、FTP）上都成立，**「语法、语义、同步」是解剖一切协议的通用手术刀**——看到一个新协议，先问这三问。

## 3 服务访问点（SAP）与协议栈

**服务访问点（SAP）**：相邻两层实体之间交换信息的接口。每个 SAP 有唯一的标识——**服务原语的传递就在 SAP 上进行**。<span class="marginnote">SAP 的作用可以类比「方法调用的入口」：上层要下层的服务，就调用对应的 SAP，如同程序里调用一个函数接口。各层的 SAP 各有名字——运输层的 SAP 是端口号，网络层的 SAP 是 IP 地址，链路层的 SAP 是 MAC 地址。</span>

**协议栈（protocol stack）**：把同一台机器上的各层协议自下而上叠起来，就是协议栈。数据在协议栈中下行（发送）或上行（接收），每一层都通过 SAP 与相邻层交换数据。

**服务原语（service primitive）**：上层调用下层服务时使用的抽象操作，有四种类型：

| 原语 | 方向 | 含义 |
| --- | --- | --- |
| 请求（Request） | 上层 → 下层 | 请求下层开始提供服务 |
| 指示（Indication） | 下层 → 上层 | 下层通知上层「有事件发生」 |
| 响应（Response） | 上层 → 下层 | 上层应答下层的指示 |
| 确认（Confirm） | 下层 → 上层 | 下层确认上层的请求已完成 |

**辨析｜易错点：** 这四条原语常被误记。抓住方向就好记：**请求与响应是上层发起的，指示与确认是下层发起的。** 例如打电话建立连接：主叫发起「请求」，被叫端收到「指示」，被叫端回答「响应」，主叫端得到「确认」——一次呼叫的建立就是这四条原语的两轮交互。

**辨析｜SAP 与「对等通信」再落一层**：SAP 是**同机相邻层**之间的接口，而「对等实体通信」是**两台机器同层**之间的逻辑通信。数据真正流动的路径是「发送方一层层往下经各 SAP 送到底层 → 物理传输 → 接收方一层层往上经各 SAP 交给目标实体」。**「SAP 管纵向交接，协议管横向对话，实体是两端的执行者」**——这一句话把四个术语的协作关系收拢在一起。

## 4 面向连接服务与无连接服务

服务按「是否先建立连接」可分为两类，这是贯穿全书的二分法，第 4、5 章会反复用到：

**面向连接服务（connection-oriented）**：通信前先**建立连接**，双方约定好状态，数据按序交付，通信结束再**释放连接**。像打电话：先拨号接通，再说话，最后挂断。TCP 是典型代表。

**无连接服务（connectionless）**：通信前**不建立连接**，每个分组独立地发往目的地。像寄快递：每次寄件都是一次独立行为，不需要先「建立关系」。UDP 是典型代表。

| 对比维度 | 面向连接服务 | 无连接服务 |
| --- | --- | --- |
| 是否建立连接 | 是，有建立/使用/释放三阶段 | 否，直接发送 |
| 可靠性 | 通常可靠（可确认重传） | 通常尽力而为 |
| 数据有序性 | 保证有序 | 不保证 |
| 开销 | 大（有握手开销） | 小（即发即走） |
| 典型协议 | TCP | UDP |

**辨析｜易错点：** 「面向连接」不等于「可靠」，只是机制上的约定；「无连接」也不等于「不可靠」——例如无连接的服务也可以逐分组确认。把「是否建连」与「是否可靠」当成同一个问题，是最常见的误解。<span class="marginnote">后面讲 IP 时你会看到：IP 提供的是「无连接、尽力而为」的服务，而 TCP 在 IP 之上通过确认、重传、编号把它包装成「面向连接、可靠」的服务——<strong>可靠性不是网络给的，是运输层「挣」来的</strong>。</span>

### 一个贯穿例子：四个术语在一封邮件里的角色

假设你用浏览器提交一个 HTTP 请求，四个术语各自登场：

| 环节 | 实体 | 协议 | 服务 | SAP |
| --- | --- | --- | --- | --- |
| 应用层 | 浏览器进程 | HTTP | 网页传输 | 端口 80 |
| 运输层 | TCP 进程 | TCP | 可靠字节流 | 端口号 |
| 网络层 | IP 模块 | IP | 尽力而为交付 | IP 地址 |
| 数据链路层 | 网卡驱动 | 以太网 | 帧传输 | MAC 地址 |

**辨析｜易错点：** 一个「实体」往往**同时是上层服务的调用者与下层服务的提供者**——TCP 进程调用 IP 的服务（向下），又向上层提供可靠字节流服务（向上）。**「每层既是顾客又是店家」**，这正是分层体系能逐级堆叠的原因。

**辨析｜为什么把「服务访问点」单独立一个概念**：SAP 强调「上下层的交接需要一个明确的地址」——没有 SAP，上层就不知道「该把数据交给下层的谁」。每个 SAP 的唯一标识（端口号、IP 地址、MAC 地址）就是「交接的门牌号」。**「分层靠服务协作，服务靠 SAP 落地」**，这三个概念因此必须绑定记忆。

作为这一节的收束：**实体是「谁」，协议是「怎么约」，服务是「能给什么」，SAP 是「在哪交接」**——四个词正好回答通信的四问。抓住这四问，第 2 章到第 6 章任何协议的讲解，你都能用这套框架对号入座。

## 5 小结

- **实体**：能收发信息的进程；**协议**：对等实体间的通信规则（语法、语义、同步）。
- **服务**：本层向上层提供的功能；**服务访问点（SAP）**：相邻层交换数据的接口。
- **黄金辨析**：协议是水平的（对等层），服务是垂直的（相邻层）；「服务是能做什么，协议是怎么做到」。
- **服务原语四类**：请求、指示、响应、确认——上两层发起请求/响应，下两层发起指示/确认。
- **两种服务**：面向连接（TCP）与无连接（UDP）；「是否建连」与「是否可靠」是两回事。
- **SAP 实例**：运输层 SAP 是端口号，网络层 SAP 是 IP 地址，链路层 SAP 是 MAC 地址。
