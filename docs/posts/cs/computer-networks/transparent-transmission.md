## 为什么从透明传输开始

上一节讲帧定界时，我们遇到了一个尖锐矛盾：**数据里如果恰好出现与帧定界符相同的比特组合，怎么办？** 这个矛盾就是「透明传输」要解决的问题。<span class="marginnote">「透明（transparent）」这个术语在第 1 章物理层也出现过——那里指「对上层屏蔽媒体差异」。这里再出现一次，含义一脉相承：<strong>数据链路层必须对上层数据「完全透明」——你给我的数据是什么样，我传到对端就是什么样，绝不允许因为「帧边界标记」而偷偷篡改你的数据。</strong></span>

这一节的主题：**字节填充（byte stuffing）与比特填充（bit stuffing）**——两套让传输「透明」的具体机制。上一节我们从「帧定界」的角度看过它们，这一节从「数据完整性」的角度再看一遍，重点落在它们的工程实现细节上。

## 1 「透明」的含义：一个字也不能改

**透明传输**：数据链路层在传输数据时，**不论数据中出现什么样的比特组合，都必须不加修改地、原封不动地传送**，并且不能误认为它是帧的定界符。

为什么这很难？因为帧定界符（如 `0x7E` 标志、`DLE STX`/`DLE ETX` 定界符）也是「比特组合」。如果数据里恰好出现定界符，接收端会误以为「帧在这里结束」，于是把数据拦腰截断、把后面的内容当成新帧——**数据传输就「不透明」了**。<span class="marginnote">想象你发一封邮件，正文里恰好写着「此邮件到此结束，请勿再读」——接收者真的就不读了。要保证正文原样送达，你得想个办法让这句话「不算数」。填充机制就是干这个的。</span>

**辨析｜易错点：** 「透明」的反面不是「加密」，而是「被误读」。**透明传输关心的是「数据不被帧定界机制篡改或误切」**，与保密无关。一个系统若在数据里遇到定界符就直接切帧，它就是不透明的；加上填充机制后，数据得以原样通过，系统就「透明」了。

## 2 字节填充（byte stuffing）：面向字符的方案

**字节填充**（也叫字符填充）用于**面向字符（字节）**的链路层协议，典型代表是 **PPP 的字节填充**。规则：

帧的定界符是 `0x7E`（Flag，标志）；转义字符是 `0x7D`（Control Escape）。
发送端扫描数据：遇 `0x7E` 时，把它改为**两字节** `0x7D 0x5E`；遇 `0x7D` 时，改为 `0x7D 0x5D`。
接收端遇 `0x7D`，就把它后面那个字节取反还原，恢复出原始数据。<span class="marginnote">PPP 的字节填充规则其实比「加个转义」更精细：`0x7E` 变成 `0x5E`（0x7E 的第六位取反），`0x7D` 变成 `0x5D`。取反的目的是让转义后的第二个字节永远不等于 `0x7E` 或 `0x7D`，彻底杜绝再次「撞车」。</span>

**辨析｜易错点：** 字节填充以**字节（8 比特）**为单位操作，它只对「面向字节的链路」有意义。**不要以为「字节填充」能解决所有链路的问题**——如果链路是面向比特的（如 HDLC），就要用比特填充。

## 3 比特填充（bit stuffing）：面向比特的方案

**比特填充**用于**面向比特**的链路层协议，典型代表是 **HDLC**。规则（复习一遍）：

帧标志：`01111110`。
发送端：数据中每遇到**连续 5 个 1**，就在其后**插入一个 0**。
接收端：数据中每遇到**连续 5 个 1 后跟 0**，就把这个 0 **删除**，还原数据。

因为发送端总在「5 个 1」后插 0，数据里就**永远不会出现连续 6 个 1**——而帧标志 `01111110` 里恰好有 6 个 1。于是接收端只要见到 `01111110`，必定是真正的帧边界。<span class="marginnote">比特填充是「插入式」，字节填充是「转义式」，两者殊途同归：<strong>都让「数据」与「控制标志」在语义上彻底隔离</strong>。选哪种，取决于链路是面向字节还是面向比特——PPP 链路是字节流，HDLC 链路是比特流。</span>

**辨析｜易错点：** 一个高频考点：比特填充的插入点是「**连续 5 个 1 之后**」，不是「5 个 0 之后」——因为标志是 `01111110`（重点是 1 的连续），破坏「连续 1」才能保标志唯一。把插零规则记反，是做这类题最常见的错误。

## 4 两张表对比：字节填充 vs 比特填充

| 对比维度 | 字节填充 | 比特填充 |
| --- | --- | --- |
| 操作单位 | 字节（8 比特） | 比特（1 比特） |
| 适用链路 | 面向字符的链路（PPP） | 面向比特的链路（HDLC） |
| 帧定界符 | `0x7E`（PPP 标志） | `01111110`（HDLC 标志） |
| 填充规则 | 遇 `0x7E`/`0x7D` 加转义 | 遇 5 个连续 1 后插 0 |
| 接收端还原 | 去转义、取反还原 | 删 5 个 1 后的 0 |
| 带宽开销 | 约一字节/特殊字节 | 每 5 比特最坏 1 比特 |

**辨析｜易错点：** 两者的选择不是随意的：**PPP 跑在字节流的串行链路上，用字节填充自然；HDLC 面对比特流，用比特填充高效。** 现代高速链路（如以太网）其实不需要这两种填充——因为它用「前导码 + 帧间间隙」而非「数据内定界符」来定界，帧长由字段显式给出（见第 3 章以太网 MAC 帧）。**「定界」的解法随技术而变，但「让数据透明」的目标不变。**

## 5 算例：亲手做一次填充与还原

**字节填充算例**：发送端要把数据 `AB 7E 7D CD` 送出去，帧标志是 `0x7E`。逐字节扫描：
- `AB` 不是标志 → 原样保留。
- `7E` 是标志 → 转为 `7D 5E`（两字节）。
- `7D` 是转义字符 → 转为 `7D 5D`（两字节）。
- `CD` 正常 → 保留。

所以线上实际传输的是 `AB 7D 5E 7D 5D CD`。接收端遇 `7D` 就取反还原：`5E → 7E`、`5D → 7D`，恢复出 `AB 7E 7D CD`——**数据原样到达，透明达成**。

**比特填充算例**：数据为 `011111101`（含连续的 6 个 1）。发送端在每遇「5 个连续 1」后插 0：`011111 0 0 1`…… 还原时接收端删掉「5 个 1 后的 0」，得到原始数据。**关键是：插 0 之后，数据里不再出现连续 6 个 1，帧标志 `01111110` 成为唯一的「6 个 1 组合」**。

**辨析｜易错点：** 算例最容易错在「取反还原」——字节填充里 `0x7E → 0x7D 0x5E`，接收端是把 `0x5E` **取反**（变成 `0x7E`）还原，不是把 `0x5E` 直接当原始数据。**「转义第二字节取反，而非原样」**是 PPP 字节填充的还原规则。

## 6 定界技术的演进：不止填充一种答案

帧定界历史上出现过几种方案，各自的命运说明「没有万能的定界法」：

| 方案 | 做法 | 局限 |
| --- | --- | --- |
| 字符计数法 | 首字节记帧长 | 长度字段一旦出错，后面全错（失同步） |
| 字节填充 | 转义特殊字符 | 只适合面向字节的链路 |
| 比特填充 | 插 0 破坏连续 1 | 只适合面向比特的链路 |
| 前导码 + 显式长度（以太网） | 物理层前导码 + 帧内长度字段 | 需要明确帧长、全双工环境 |

**辨析｜易错点：** 字符计数法的「一错全错」是它被淘汰的致命伤——**长度错一位，接收端从错误位置重新找帧边界，可能连续错很多帧**。填充方案的健壮性在于「逐字节/逐比特检查」，不会因一处错误全局失步。**「计数怕错，填充怕慢」**是两类定界技术的取舍。

## 7 关于填充的常见误区

- **误区一「填充是为了加密/压缩」**：不是。填充只为了让「数据」与「控制标志」区分开，不改变数据内容，更不保密——**它管的是「会不会被误读」，不是「读不读得懂」**。
- **误区二「填充是永久的」**：不是。填充是「线上格式」，接收端还原后，应用层看到的还是原始数据——**「填充只在链路上存在，到接收端即还原」**。
- **误区三「所有链路都要填充」**：不是。现代以太网用「前导码 + 显式长度」定界，不需要填充；填充只用于「数据内可能混入定界符」的老式/串行链路。

**辨析｜易错点：** 把填充与「帧校验（CRC）」也区分开：**填充防「误切帧」，CRC 防「传错比特」**——一个管「边界不被误认」，一个管「内容不被误传」，是数据链路层两个独立的基本问题。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| 透明传输 | 数据原样传送，不被定界机制误切 |
| 字节填充 | 遇定界符/转义符加转义（面向字节） |
| 比特填充 | 遇 5 个连续 1 后插 0（面向比特） |
| 帧定界 | 接收端识别帧的起止 |
| 转义字符 | 表示「下一个字节是数据」的标志 |
| 面向字符 / 面向比特 | 按字节还是按比特处理数据 |
| 字符计数法 | 用长度字段定界 |
| HDLC | 高级数据链路控制，用比特填充 |

## 9 小结

- **透明传输**：数据链路层对数据「不加修改、原样传送」，绝不因定界符而误切。
- **字节填充**：面向字节链路，遇 `0x7E`/`0x7D` 加转义（PPP）；以字节为单位。
- **比特填充**：面向比特链路，遇 5 个连续 1 后插 0（HDLC）；以比特为单位。
- **共同目标**：让「数据」与「控制标志」语义隔离，保证帧边界唯一、数据完整。
- **工程演进**：以太网改用「前导码 + 显式长度」定界，不再需要数据内填充。
- **算例直觉**：转义第二字节取反还原；插 0 后数据里不再出现连续 6 个 1。
- **定界谱系**：字符计数怕错、填充怕慢、显式长度适合现代高速链路。
- **误区澄清**：填充不为保密、只在链路上、并非所有链路都需要。
- **一句话**：填充管「边界不被误认」，CRC 管「内容不被误传」。
