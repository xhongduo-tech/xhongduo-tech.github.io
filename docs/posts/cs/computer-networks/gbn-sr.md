# 回退 N 帧（GBN）与选择重传（SR）

## 为什么从 GBN 与 SR 开始

上一节说，连续 ARQ 发得快，但「出错后怎么重传」分化出了两大流派。这一节把它们摆上擂台：**回退 N 帧（GBN，Go-Back-N）** 与 **选择重传（SR，Selective Repeat）**。<span class="marginnote">二者的分水岭是一个简单的问题：<strong>当第 k 帧出错或丢失、而它后面的帧已经到达时，接收方该怎么办？</strong> GBN 的选择是「全都不认，退回第 k 帧重发」，SR 的选择是「好帧先收下缓存，只重发第 k 帧」。一个重传得多、实现简单；一个重传得少、实现复杂。</span>

这一节把两个协议的行为、窗口约束、优缺点一次讲清。这一节的知识在第 5 章讲 TCP 快重传时还会复用，是「重传策略」的完整版。

## 1 GBN：接收窗口 = 1，出错就全退

**回退 N 帧（GBN）** 的规则：

**发送窗口** > 1（可连续发送），**接收窗口 = 1**（只按序接收）。
接收方收到**乱序帧**（不是期望的那一帧）时，**一律丢弃**，并重复发送**对最后一个正确帧的 ACK**。
发送方收到对第 n 帧的 ACK，就认为 n 及以前**所有帧**都已正确到达（**累积确认**），窗口滑过 n。
某帧超时未确认，发送方**重传该帧及其后面的所有帧**——这就是「回退 N」：退回到出错点，N 帧从头再来。<span class="marginnote">为什么接收方要「丢弃乱序帧 + 重复 ACK」？因为 GBN 的设计哲学是「简单」：接收方不缓存任何乱序数据，一旦发现乱序就认定「前面有帧丢了」，用重复 ACK 催发送方尽快回退。代价是已经收到的后面的好帧全被丢弃重传。</span>

**辨析｜易错点：** GBN 有两个「丢弃」要分清：**发送方丢弃的是「重传的坏帧后面的帧」（重传），接收方丢弃的是「乱序到达的好帧」**。GBN 的「回退」体现在发送方——它一退就退到出错帧，把后面全重发。

## 2 SR：接收窗口 > 1，只补缺

**选择重传（SR）** 的规则：

**发送窗口** > 1，**接收窗口** > 1（可缓存乱序好帧）。
接收方**逐个确认**（不是累积确认）：收到哪一帧，就 ACK 哪一帧，即使它是乱序到达的。
接收方把乱序的好帧**缓存**起来，等缺的帧补齐后，**按序交付**给上层。
某帧超时未确认，发送方**只重传该帧**，不重传后面的帧。<span class="marginnote">SR 的核心是「不浪费已收到的数据」：接收方用缓冲区把乱序好帧存着，只差那一帧没到。等它到了，缓冲区里整段就绪，按序交付。代价是接收方要有缓存、要逐帧管理，发送方要为每个帧单独计时。</span>

**辨析｜易错点：** SR 与 GBN 的确认方式不同——**GBN 用累积确认（ACK n 代表「n 及以前全到」），SR 用逐个确认（ACK n 只代表「第 n 帧到了」）**。另外，SR 的发送方不能「收到一个 ACK 就无脑滑窗」，它要**按序号位图管理**每个帧的确认状态。

## 3 一张表：GBN vs SR 全对比

| 对比维度 | 回退 N 帧（GBN） | 选择重传（SR） |
| --- | --- | --- |
| 接收窗口 | 恒为 1 | > 1（可缓存） |
| 乱序帧处理 | 丢弃 + 重复 ACK | 缓存 + 逐个 ACK |
| 确认方式 | 累积确认 | 逐个确认 |
| 出错重传 | 重传出错帧及其后全部 | 只重传出错帧 |
| 接收方缓冲 | 无 | 需要 |
| 序号约束 | $W_s \leq 2^k - 1$ | $W_s + W_r \leq 2^k$ |
| 实现复杂度 | 低 | 高 |
| 重传开销 | 大（错误率高时尤其） | 小（每帧只传一次） |

**辨析｜易错点：** 两个窗口约束极易记混。**GBN 的 $2^k - 1$ 与 SR 的 $2^k$** 一起记：GBN 因为「重复 ACK 可能混淆新旧」，必须让窗口比序号空间小 1；SR 因为收发窗口都大于 1，要求**收发窗口之和**不超过序号空间。**「谁跟谁加起来 ≤ 2^k」是 SR 的专属考点。**

## 4 公式解析：错误率对两者的影响

在出错概率为 $p$ 的信道上，两者的**平均重传量**差异显著。设窗口内帧数为 $W$，则每帧平均需要传输的次数：

$$
E[\text{传输次数}] = \begin{cases} \approx \frac{W}{1-p} & \text{GBN（一错重传 W 帧）} \\ \frac{1}{1-p} & \text{SR（每帧独立重传）} \end{cases}
$$

- **第一步，看 GBN**：任何一帧出错，要把**包括它后面 W-1 帧**在内全重传，等于把出错的代价放大了 W 倍。
- **第二步，看 SR**：每帧独立重传，平均每帧传输 $\frac{1}{1-p}$ 次，与窗口大小无关。
- **第三步，工程含义**：**信道错误率高时，GBN 的重传风暴极其浪费；SR 几乎不受窗口大小拖累。** 这也是为什么可靠传输要求高的协议（如 TCP）更接近 SR 的思想。<span class="marginnote">GBN 的 W 倍惩罚是它的「阿克琉斯之踵」：窗口越大（为了利用率），出错代价越大。<strong>GBN 适合「错误率低 + 实现要简单」的场景，SR 适合「错误率不低 + 带宽昂贵」的场景。</strong></span>

## 5 小结

- **GBN**：接收窗口=1，乱序帧丢弃+重复 ACK，累积确认，出错退到 N 全部重传。
- **SR**：接收窗口>1，乱序帧缓存+逐个 ACK，只重传出错的帧。
- **窗口约束**：GBN 需 $W_s \leq 2^k - 1$；SR 需 $W_s + W_r \leq 2^k$。
- **效率对比**：GBN 重传量被窗口放大 W 倍；SR 每帧独立重传，开销与窗口无关。
- **适用场景**：GBN 简单省资源、适合低错误率；SR 复杂但省带宽、适合高错误率。
- **与 TCP 的关系**：TCP 的确认与重传更接近 SR 思想（快重传只补缺帧）。
