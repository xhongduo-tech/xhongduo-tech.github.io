## 为什么从过渡技术开始

IPv6 再好，也不能「一键切换」——全球有海量的 IPv4 设备、应用与网络，IPv4 到 IPv6 必然是**漫长的共存期**。在这段共存期里，两个问题必须解决：**一台设备同时支持两代协议吗？IPv6 的包怎么穿过只有 IPv4 的网络？**<span class="marginnote">过渡技术的核心思想是「<strong>平滑共存，渐进迁移</strong>」：不是「今天全换 IPv6」，而是「新旧长期共存、逐步过渡」。两大主力手段是<strong>双协议栈</strong>（一台设备两代协议都跑）与<strong>隧道</strong>（把 IPv6 包装进 IPv4 包里穿行）。理解它们，就理解了「新老技术如何在同一张网上共存」的通用范式。</span>

这一节讲：**双协议栈的原理、隧道技术的工作方式、以及翻译技术的补充。**

## 1 双协议栈：一台设备，两代协议

**双协议栈（dual stack）**：一台设备（主机或路由器）**同时安装并运行 IPv4 与 IPv6 两套协议栈**，对上层提供两个地址（一个 IPv4、一个 IPv6）。<span class="marginnote">双栈设备的逻辑：<strong>上层应用可以选择用 IPv4 或 IPv6 通信</strong>——访问双栈网站时优先用 IPv6，对方只有 IPv4 时退回 IPv4。网络层同时维护 IPv4 路由与 IPv6 路由，转发时按数据报的版本走对应的栈。</span>

- **兼容性最好**：双栈设备与 IPv4 设备、IPv6 设备都能通信，是过渡期的「通用语」。
- **地址双份**：设备要配一个 IPv4 地址 + 一个 IPv6 地址。
- **默认优先 IPv6**：现代双栈系统（如你的电脑与手机）通常「IPv6 优先，IPv4 兜底」。

**辨析｜易错点：** 双协议栈只是「同时支持」，**它不解决「IPv6 包穿过纯 IPv4 网络」的问题**——那要靠隧道。**「双栈解决端点能力，隧道解决穿越路径」**，两者分工不同、常常配合使用。

## 2 隧道技术：IPv6 装进 IPv4 的「信封」

**隧道（tunneling）**：当 IPv6 数据报需要穿过一段**只有 IPv4** 的网络时，发送端的双栈路由器把**整个 IPv6 数据报当作数据**，封装进一个 **IPv4 数据报**里，穿过 IPv4 网络，到出口再剥掉 IPv4 信封，还原出 IPv6 数据报继续走。<span class="marginnote">隧道最形象的类比是「把 IPv6 的快递装进 IPv4 的信封寄过去」：<strong>外面的信封（IPv4）只负责穿越老网络，里面的信件（IPv6）是真正的货</strong>。隧道两端必须是支持 IPv6 的双栈路由器，中间的老路由器完全无感知——它只当普通 IPv4 包转发。</span>

隧道的工作流程：

1. **入口路由器**：收到 IPv6 数据报，判断「目的在 IPv4 网络的另一侧」，把它**封装成 IPv4 数据报**（协议字段标 41，表示「里面是 IPv6」）。
2. **IPv4 网络传输**：IPv4 路由器把它当普通 IPv4 包转发，不关心内层。
3. **出口路由器**：剥掉 IPv4 首部，还原出 IPv6 数据报，继续按 IPv6 路由转发。

**辨析｜易错点：** 隧道的封装有「**隧道首部开销**」：IPv4 信封本身要占 20 字节。另外，**隧道内层的 IPv6 数据报的 TTL 与 IPv4 信封的 TTL 是两套**——内层 TTL 只在 IPv6 网络上跳转时递减，隧道段不减（这是常见考点）。**「隧道是一条逻辑链路，两端的双栈路由器是它的两个端点」**是理解隧道的核心。

## 3 翻译技术：IPv6 与 IPv4 的「同声传译」

隧道解决「IPv6 过 IPv4 网」，但还差一种场景：**纯 IPv6 主机与纯 IPv4 主机直接通信**——两者的地址格式完全不同，需要**翻译（translation）**。<span class="marginnote">翻译技术（如 NAT64）在协议栈中间做「IPv6 报文 ↔ IPv4 报文」的转换：<strong>地址、首部字段全部改写</strong>。它像同声传译，但比隧道复杂得多——因为两代协议的首部、分片、ICMP 都不完全一样。NAT64 通常配合 DNS64（把 IPv4 域名解析成合成的 IPv6 地址）一起用。</span>

**辨析｜易错点：** 翻译与隧道的区别：**隧道是「包住」**（IPv6 原封不动地装进 IPv4），**翻译是「改写」**（把 IPv6 报文变成真正的 IPv4 报文）。翻译更彻底，但会丢失某些 IPv6 特性（如端到端地址）。**「隧道靠封装，翻译靠改写」**是两种技术的分野。

## 4 三种过渡技术对比

| 对比维度 | 双协议栈 | 隧道 | 翻译 |
| --- | --- | --- | --- |
| 解决什么问题 | 设备同时支持两代 | IPv6 穿 IPv4 网 | 纯 IPv6 与纯 IPv4 互通 |
| 工作机制 | 同时运行两套栈 | IPv6 封装进 IPv4 | 报文格式改写 |
| 是否需要改写 | 否 | 否（只封装） | 是 |
| 典型场景 | 所有过渡期设备 | 运营商骨干间的 IPv6 互联 | 移动网络、企业出口 |
| 复杂度 | 低 | 中 | 高 |

**辨析｜易错点：** 三种技术不是互斥的，**现实部署常是「双栈打底 + 隧道穿行 + 翻译兜底」的组合拳**。理解它们的分工，看新闻里的「某运营商 IPv6 改造」时就能看懂它到底在做什么。**「双栈给能力、隧道给路径、翻译给互通」**——过渡是一套组合方案，不是单选。

## 5 小结

- **过渡的必然性**：IPv4 存量巨大，两代协议长期共存，渐进迁移。
- **双协议栈**：一台设备同时跑 IPv4 与 IPv6，解决端点兼容；IPv6 优先、IPv4 兜底。
- **隧道**：把 IPv6 数据报装进 IPv4 信封穿行，两端是双栈路由器，中间无感知。
- **翻译（NAT64）**：报文格式改写，让纯 IPv6 与纯 IPv4 互通。
- **黄金对比**：隧道靠封装，翻译靠改写；双栈给能力、隧道给路径、翻译给互通。
- **现实组合**：双栈打底 + 隧道穿行 + 翻译兜底。
