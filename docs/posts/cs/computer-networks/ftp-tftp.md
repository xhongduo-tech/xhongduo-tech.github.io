## 为什么从 FTP 开始

在 HTTP 之前，互联网用来传文件的主角是 **FTP（File Transfer Protocol，文件传送协议）**。它有一个在协议家族里很「另类」的设计：**用两条 TCP 连接工作**——一条传控制信息、一条传数据。理解它，你就看到了「控制面与数据面分离」的早期范本。<span class="marginnote">FTP 的地位：<strong>它是互联网最早的应用协议之一，定义了「客户端-服务器 + 控制/数据分离」的经典范式</strong>。虽然今天个人传文件多用 HTTP/云盘，但 FTP 仍是服务器间、嵌入式设备间（TFTP）常用的文件传输手段——理解 FTP，是理解「应用协议如何设计」的好教材。</span>

这一节讲：**FTP 的双连接结构、两种工作模式、以及轻量版 TFTP。**

## 1 FTP 的两条连接：控制与数据分离

FTP 使用**两条独立的 TCP 连接**：<span class="marginnote">这是 FTP 最独特的设计：<strong>控制连接（端口 21）</strong>传输命令与应答（如「列出目录」「下载文件」）；<strong>数据连接（端口 20）</strong>传输真正的文件内容。控制连接全程保持，数据连接「按需建立、传完即断」。把「指挥」与「干活」分开——指挥连接要稳定可靠，数据连接可以频繁开合。</span>

| 连接 | 端口 | 传输内容 | 生命周期 |
| --- | --- | --- | --- |
| 控制连接 | 21 | 命令与应答（FTP 命令） | 全程保持 |
| 数据连接 | 20 | 文件内容（数据） | 按需建立，传完关闭 |

**辨析｜易错点：** **控制连接是「带内」的吗？** 不——FTP 的控制连接在端口 21，数据连接在端口 20，两者分开。这与「带外信令」（如电话的带内拨号音）不同，FTP 是「**双连接带外控制**」的典型。**「FTP 有两个连接」是它最常被考的标识**——别把 FTP 当成「一个端口一个连接」。

## 2 FTP 的两种工作模式

数据连接的建立有两种模式，区别在于**谁主动建立数据连接**：<span class="marginnote"><strong>主动模式（PORT）</strong>：服务器主动连回客户端——客户端告诉服务器「我的数据端口是 X」，服务器从 20 端口连过去。<strong>被动模式（PASV）</strong>：客户端主动连服务器——服务器告诉客户端「我在端口 Y 等你」，客户端连过去。被动模式的出现，是因为<strong>NAT/防火墙环境下服务器「主动连回」客户端常常被挡</strong>（客户端没有公网地址）。</span>

**主动模式（PORT）**：服务器从端口 20 **主动连接**客户端的数据端口。
**被动模式（PASV）**：服务器开放一个随机端口，**客户端主动连接**它。

**辨析｜易错点：** 在 **NAT 后的内网用户**用 FTP 时，主动模式会失败——因为服务器无法主动连回内网客户端的私有地址。**「被动模式是为 NAT/防火墙时代准备的」**是理解两种模式的关键。这也解释了为什么浏览器/文件管理器连接 FTP 时常常自动用被动模式。

## 3 FTP 的工作过程与命令

FTP 的工作流程：<span class="marginnote">FTP 的命令是文本形式的，如 <code>USER</code>`（用户名）、<code>PASS</code>`（密码）、<code>LIST</code>`（列目录）、<code>RETR</code>`（下载）、<code>STOR</code>`（上传）、<code>QUIT</code>`（退出）。服务器的应答是三位数字码（如 <code>220</code>` 服务就绪、<code>331</code>` 需密码、<code>230</code> 登录成功）。<strong>FTP 是「文本命令 + 数字应答」的经典协议</strong>——它的设计影响了后来的许多应用协议。</span>

1. 客户端连控制端口 21，发送 `USER`/`PASS` 登录。
2. 服务器回数字应答确认身份。
3. 客户端发 `RETR`/`STOR` 等命令，通过数据连接传文件。
4. 传完，`QUIT` 关闭控制连接。

**辨析｜易错点：** **FTP 的控制信息是明文传输的**（用户名、密码、命令都是明文）——这是它的重大安全隐患，所以现代 FTP 已普遍被 **FTPS（FTP + TLS）** 或 **SFTP（基于 SSH）** 取代。**「明文控制是 FTP 的原罪，加密版本是它的续命」**。

## 4 TFTP：简单到极致的「小文件协议」

**TFTP（Trivial File Transfer Protocol，简单文件传送协议）**：FTP 的「极简版」：<span class="marginnote">TFTP 只用 <strong>UDP 69</strong>、一次只传一个文件、没有目录浏览、没有认证。它用「停止-等待」式的简单确认机制保证传输（第 3 章学过的思想在这里落地）。优点是小巧、实现简单，适合<strong>无盘工作站引导、嵌入式设备升级固件</strong>这类「只传一个小文件」的场景。</span>

**基于 UDP 69**：无连接、轻量。
**无目录、无认证**：功能极简。
**停止-等待确认**：每块数据等确认再发下一块。
**典型应用**：路由器/交换机固件升级、无盘启动。

**辨析｜易错点：** **TFTP 的「简单」既是优点也是缺点**——没有认证意味着任何人都能读写（危险），只靠「停止-等待」意味着效率低。**「FTP 全功能、TFTP 极简」**，它们的共同点都是「传文件」，但定位天差地别。<span class="marginnote">对比 FTP 与 TFTP：<strong>FTP 用 TCP + 双连接 + 认证，面向「全功能文件传输」；TFTP 用 UDP + 单连接 + 停止-等待，面向「简单引导场景」</strong>。一句话：FTP 是「货车」，TFTP 是「手推车」——各有各的用武之地。</span>

## 5 FTP 与 HTTP：两个「传文件」的路线

FTP 与 HTTP 都能传文件，但设计哲学不同：

| 对比维度 | FTP | HTTP |
| --- | --- | --- |
| 连接结构 | 双连接（控制 + 数据） | 单连接（请求-响应） |
| 传输层 | TCP 21/20 | TCP 80/443 |
| 会话状态 | 有状态（登录态） | 无状态（靠 Cookie） |
| 目录操作 | 完整（列目录、改名、删除） | 基本没有 |
| 认证 | 内置（USER/PASS） | 靠应用层（Basic/Bearer） |
| 典型用途 | 批量文件同步、固件升级 | Web 页面与资源传输 |

**辨析｜易错点：** **HTTP 的「无状态」与 FTP 的「有状态」是根本差异**——FTP 整个会话记住「你是谁、在哪个目录」，HTTP 每个请求彼此独立。**「FTP 是有会话的，HTTP 是无会话的」**，理解这一点，很多「为什么 FTP 要登录、HTTP 不用」的困惑就解开了。

## 6 主动与被动：一次抓包的视角

两种模式在抓包里差异非常直观：

- **主动模式**：抓包会看到服务器（20 端口）主动向客户端发起 TCP 连接——**方向是「服务器 → 客户端」**。若中间有 NAT/防火墙，这个「入站连接」很可能被丢弃，传输失败。
- **被动模式**：抓包看到客户端向服务器（21 控制 + 随机数据端口）发起连接——**方向是「客户端 → 服务器」**。所有连接都是「出站」，NAT/防火墙一般放行，兼容性最好。

现代 FTP 客户端默认用被动模式，且支持 **EPSV（扩展被动）** 以兼容 IPv6。**「能出站不进出站」**是 NAT 时代 FTP 用被动模式的根本原因。

**辨析｜易错点：** 别把「被动」理解成「服务器被动等待」——**被动模式里服务器是主动开启端口等客户端来连**。理解两种模式的钥匙是「**谁先发起数据连接**」：主动 = 服务器发起，被动 = 客户端发起。

## 7 FTP 的进阶话题：断点续传与并发

- **断点续传（REST）**：FTP 支持从文件中间继续传输（REST 命令 + 数据连接偏移）——大文件传输中断后不用从头再来。
- **并发数据连接**：一些 FTP 客户端（如多线程下载）同时建立多条数据连接分段下载，加快大文件传输——这已偏离标准 FTP 的简单语义。
- **ASCII 与二进制模式**：FTP 区分文本（ASCII）与二进制传输——文本模式会做换行符转换，二进制模式原样传送。**传图片、程序必须用二进制模式**，否则字节被「好心」改写导致文件损坏。

**辨析｜易错点：** **「传文件用二进制模式」是 FTP 老兵的共识**——用 ASCII 模式传图片/压缩包，换行符被转换，文件就坏了。**「文本才做转换，二进制原样传」**是选择传输模式的原则。

## 8 术语速查

| 术语 | 含义 |
| --- | --- |
| FTP | 文件传送协议，双连接 |
| 控制连接 | 端口 21，传命令与应答 |
| 数据连接 | 端口 20，传文件内容 |
| 主动模式 | 服务器主动连客户端数据端口 |
| 被动模式 | 客户端主动连服务器数据端口 |
| PASV / EPSV | 被动模式的命令 |
| FTPS | FTP + TLS 加密 |
| SFTP | 基于 SSH 的文件传输 |
| TFTP | 基于 UDP 69 的极简文件传输 |
| 停止-等待 | 每块确认后再发的传输方式 |

## 9 小结

- **FTP**：双连接——控制连接（21，命令/应答）与数据连接（20，文件内容）。
- **两种模式**：主动（服务器连客户端）vs 被动（客户端连服务器）；NAT 环境用被动。
- **FTP 命令**：USER/PASS/LIST/RETR/STOR/QUIT，文本命令 + 数字应答。
- **FTP 的软肋**：控制信息明文，需 FTPS/SFTP 加密升级。
- **TFTP**：UDP 69、极简、停止-等待确认，适合固件升级与无盘启动。
- **黄金对比**：FTP 是「货车」，TFTP 是「手推车」。
- **HTTP 对照**：FTP 有会话有目录操作，HTTP 无状态无目录，定位不同。
- **抓包识别**：主动模式方向是服务器→客户端，被动模式是客户端→服务器。
- **二进制原则**：传图片/程序必须用二进制模式，防止字节被改写。
- **进化路径**：FTP → FTPS/SFTP 加密化，功能交给 HTTP/云盘，简单留给 TFTP。
