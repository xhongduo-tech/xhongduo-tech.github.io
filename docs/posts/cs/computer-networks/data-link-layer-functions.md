# 数据链路层的功能与点对点信道

## 为什么从数据链路层开始

第 2 章物理层负责「传输比特」，但比特本身没有「边界」——接收端怎么知道一串比特里哪几比特是一个完整的数据块？如果比特传错了怎么办？这是**数据链路层（data link layer）**要解决的问题：**它把物理层的裸比特流，组织成一个个有边界、可校验、可交付的「帧」。**<span class="marginnote">一句话记住两层的分工：物理层管「比特怎么传」，数据链路层管「比特怎么组成帧、帧怎么可靠地穿过一段链路」。物理层是「路」，数据链路层是「车」，网络层是「导航」——这个比喻会陪你走完整个网络学习。</span>

这一节立住三个东西：**链路与数据链路的区别、数据链路层的核心功能、点对点信道这个典型场景。**

## 1 链路 vs 数据链路：一字之差

**链路（link）**：一条**无源的点到点的物理线路段**，中间没有任何其他交换结点。它只是一段物理介质——比如两台路由器之间的一段光纤。

**数据链路（data link）**：**链路 + 实现通信协议的硬件和软件**。也就是说，数据链路是「物理链路 + 协议栈里的链路层逻辑」合在一起，能真正实现可靠通信。

**辨析｜易错点：** 链路是**物理存在**，数据链路是**物理+协议**的复合概念。打个比方：链路是「一段路」，数据链路是「这段路 + 路上的交通规则」。**「链路」只谈介质，「数据链路」才谈通信**——教材强调这个区别，是为了提醒你：光有物理线缆，没有链路层协议，无法构成可用的信道。

## 2 数据链路层的核心功能

数据链路层把「比特流」组织成「帧」，并完成三类核心任务：

**封装成帧（framing）**：在数据的前后分别加上**帧首部与帧尾部**，确定帧的边界，让接收端知道「一帧从哪里开始、到哪里结束」。
**透明传输（transparent transmission）**：无论数据里出现什么比特组合（包括与首尾标记相同的组合），都要能原样传输，不能让接收端误判帧边界。
**差错检测（error detection）**：接收端检测帧在传输中是否出错，出错则丢弃或请求重传。

除这三个基本问题外，数据链路层还承担：**流量控制**（协调收发双方速率）、**可靠传输**（确认与重传机制）、以及**链路管理**（链路的建立、维持与释放）。<span class="marginnote">把「封装成帧、透明传输、差错检测」这三大基本问题记牢，它们是整个数据链路层的主线——接下来的几节全部围绕它们展开：帧定界讲封装成帧，字节填充/比特填充讲透明传输，CRC 讲差错检测。</span>

**辨析｜易错点：** 数据链路层**不负责「端到端」的可靠性**——它只保证「相邻两个结点之间」的传输。数据要穿过多个链路，每一段各自做帧的封装、校验；「端到端的可靠交付」是运输层（第 5 章）的责任。**「相邻」与「端到端」的区别，是分层体系里最容易被忽略的一条分界线。**

## 3 数据链路层的两种信道

数据链路层面对两种典型信道，处理方式完全不同：

**点对点信道（point-to-point channel）**：一条链路只连接**两个结点**，一方发送、一方接收，没有第三方竞争。这种信道上一对一通信，问题纯粹——主要解决封装、透明、差错检测与可靠传输。典型例子：路由器之间的专线、PPP（拨号/专线接入）。<span class="marginnote">点对点信道没有「多个结点抢信道」的问题，所以不需要介质访问控制（MAC）——谁发谁收清清楚楚。它的问题集中在「帧的边界与正确性」。</span>

**广播信道（broadcast channel）**：一条链路上**连接多个结点**，大家共享信道。这种信道上必须解决「多个结点同时发送」的冲突问题，需要介质访问控制（MAC）协议——典型例子是传统的以太网。本章后面会专门展开 CSMA/CD 等协议。

| 对比维度 | 点对点信道 | 广播信道 |
| --- | --- | --- |
| 连接方式 | 两个结点独占 | 多个结点共享 |
| 核心问题 | 帧边界、差错、可靠 | 介质访问控制（避免冲突） |
| 典型协议 | PPP、HDLC | 以太网（CSMA/CD）、Wi-Fi（CSMA/CA） |
| 是否需要 MAC | 否 | 是 |

**辨析｜易错点：** 别把「点对点」理解成「两台电脑直连」。**点对点信道指一条链路上只有两个通信结点**——比如两台路由器之间的专线；而「点对点协议（PPP）」就是专为这种场景设计的。广播信道则相反，一条线上挂多个结点，大家必须「排队发言」。

## 4 一个数据链路层通信的完整图景

把「点对点信道」上的通信流程串起来：

1. **发送端链路层**：从网络层取来 IP 数据报，作为「数据」，**加上帧首部与帧尾部**，封装成帧。
2. **封装成帧后**：对帧内的特殊字符做**透明传输处理**（防止帧定界符在数据中出现）。
3. **计算并附加校验码**：发送端对帧做 **CRC 计算**，把校验码附在帧尾。
4. **送入物理层**：把帧变成比特流送上链路。
5. **接收端链路层**：从物理层收到比特流，**识别帧边界**、**验证校验码**、**去除透明传输的填充**、**剥掉帧首尾**，把数据交给网络层。

**辨析｜易错点：** 帧是数据链路层的**数据单元**，它由「帧首部 + 数据（IP 数据报）+ 帧尾部」构成。注意**帧尾不只是收尾标记，还承载校验码**——差错检测的「尾巴」就在帧尾部。后面讲以太网帧格式时，你会看到帧尾的 FCS（帧校验序列）字段。

## 5 公式解析：数据单元在层间的「变身」

数据在不同层有不同的名字与大小限制，理解这层「变身」是网络学习的必修课。以一个以太网链路为例：

**网络层的 IP 数据报（最大 65535 字节）被装进数据链路层的帧（最大 1500 字节数据）**——也就是说，**IP 数据报可能被链路层的 MTU（最大传输单元）截断**，超出的部分要靠 IP 层的分片（第 4 章）解决。<span class="marginnote"><strong>MTU（Maximum Transmission Unit）</strong>：数据链路层一次能承载的最大数据量。以太网的 MTU 是 1500 字节。它像一个「货柜限重」：<strong>网络层再大的包，装进这个货柜时也要被切开</strong>。这就是 IP 分片的由来——链路层「限重」决定了网络层「分片」。</span>

$$
\text{帧} = \text{帧首部} + \text{IP 数据报} + \text{帧尾部（含 FCS 校验码）}
$$

- **第一步，上层打包**：应用 → 运输层 → 网络层，数据逐层加上各层首部，成为一个 IP 数据报。
- **第二步，链路层再包**：网络层把数据报交给链路层，链路层加上**帧首部**（如以太网的目的/源 MAC、类型）与**帧尾部**（校验码 FCS），构成一帧。
- **第三步，物理层送比特**：链路层把帧交给物理层，变成比特流上线。
- **第四步，接收端逐层剥壳**：物理层收比特 → 链路层去帧首尾、验 FCS → 网络层取回 IP 数据报 → 交给上层。

**辨析｜易错点：** 「帧（frame）」特指**数据链路层**的数据单元；「分组（packet）/数据报（datagram）」指**网络层**的数据单元；「报文段（segment）」「报文（message）」分别是运输层与应用层的叫法。**「哪一层的单元叫什么名」**是分层概念里最基础的命名题，也是最常考的选择题考点。

### 数值算例：一帧里装了多少「不相关」的东西

以典型以太网帧为例，把「数据」与「开销」分开数：

| 部分 | 字节数 | 是不是有效载荷 |
| --- | --- | --- |
| 目的 MAC | 6 | 寻址开销 |
| 源 MAC | 6 | 寻址开销 |
| 类型字段 | 2 | 分用开销 |
| IP 数据报（含上层全部） | 最多 1500 | 有效载荷 |
| FCS 校验码 | 4 | 差错检测开销 |
| 合计 | 最多 1518 | — |

**辨析｜易错点：** 帧首部 + 帧尾部（共 18 字节）是链路层的**固定开销**——它们不是数据，是「打包费」。**「有效载荷占帧的比例」**就是上一节五层体系里讲过的传输效率，这里从帧结构的角度又算了一遍——两条线汇合在「开销」这个共同概念上。

## 6 数据链路层协议的「家族谱」

数据链路层并不是「一个协议」，而是一族协议，按信道类型与用途各司其职：<span class="marginnote"><strong>点对点信道</strong>`：PPP（拨号/专线）、HDLC（同步链路）；<strong>广播信道</strong>`：以太网（CSMA/CD）、Wi-Fi 802.11（CSMA/CA）。<strong>「点到点解决『帧的边界与正确』，广播还要多解决『谁先发言』」</strong>——两种信道催生了两种完全不同的协议族。</span>

| 协议 | 信道 | 特点 |
| --- | --- | --- |
| PPP | 点对点 | 拨号/专线接入，简单，含认证 |
| HDLC | 点对点 | 同步链路，面向比特 |
| 以太网 | 广播 | CSMA/CD，如今最普遍 |
| 802.11 | 广播（无线） | CSMA/CA，Wi-Fi |

**辨析｜易错点：** 别把「数据链路层协议」误以为是「只有一个」。**点对点信道与广播信道各自需要不同的链路层协议**——PPP 解决不了以太网的冲突问题，CSMA/CD 也不适合 PPP。**「信道类型决定协议类型」**是选择链路层协议的总纲。

## 7 小结

- **链路 vs 数据链路**：链路是物理线路段，数据链路是「链路 + 协议软硬件」。
- **三大基本问题**：封装成帧、透明传输、差错检测。
- **两种信道**：点对点信道（无 MAC 问题）与广播信道（需介质访问控制）。
- **职责边界**：链路层保证「相邻结点」间的帧传输，不负责端到端可靠（那是运输层）。
- **帧的结构**：帧首部 + 数据 + 帧尾部（含校验码）。
