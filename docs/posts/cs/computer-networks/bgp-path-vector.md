# 边界网关协议（BGP）：路径向量与路由策略

## 为什么从 BGP 开始

RIP、OSPF 解决的是「AS 内部怎么走」；但不同 AS 之间（运营商与运营商、企业与其上游）怎么交换路由？这是 **BGP（Border Gateway Protocol，边界网关协议）** 的领域。<span class="marginnote">BGP 是<strong>互联网的「事实标准」外部网关协议（EGP）</strong>，当前版本 BGP-4。它不用「最短路径」思维，而是用<strong>路径向量（path vector）</strong>：把「到达某个前缀需要穿越的 AS 序列」完整记下来，AS 之间据此做带策略的选路。可以说，BGP 是互联网「商业路由」的宪章。</span>

这一节讲：**BGP 要解决什么问题、路径向量怎么防环、BGP 的选路策略。**

## 1 BGP 不是「最短路径」，是「可达性 + 策略」

BGP 与 IGP 的根本区别：**IGP 找技术最优，BGP 找策略允许。** BGP 连接的 AS 之间存在商业关系（付费转接、对等互联、客户关系），路由选择必须服从这些合约——不是「哪条路近走哪条」，而是「哪条路符合商业策略走哪条」。<span class="marginnote">举例：运营商 A 与 B 是付费关系（B 付钱让 A 转接流量），BGP 会让 B 的路由「优先」走付费链路；如果 A、B 是免费对等（peering），双方通常只交换「自己的客户」的路由，不免费转接对方上游的流量。<strong>「路由策略 = 商业利益的数学化」</strong>——这是 BGP 最不同于 IGP 的地方。</span>

**辨析｜易错点：** 别用「最短跳数」的直觉理解 BGP。**BGP 的路径常常不是技术最短的**——可能绕很远，但符合商业合约。**「BGP 选路先看策略、再看路径质量」**是理解 BGP 的第一原则。另外，BGP 只交换「可达性」（这个前缀可达、经哪些 AS），不做细粒度的「代价计算」。

## 2 路径向量：防环的天然利器

**路径向量（path vector）**：BGP 路由中携带**完整的 AS 路径（AS_PATH）属性**——即「到达该前缀所经过的所有 AS 编号的序列」。

路径向量的价值：<span class="marginnote">距离向量用「距离数字」防环效果差（计数到无穷），链路状态靠全网拓扑防环，而 BGP 用<strong>「AS 路径」防环——接收方只要发现路径里包含自己的 AS 号，就知道这条路由「绕回了自己」，直接丢弃</strong>。因为 AS 路径是全局唯一的编号序列，环一出现就立刻被识别。</span>

**防环**：收到路由时若 AS_PATH 里含自己的 AS 号，丢弃——绝不接收「绕回自己」的路由。
**可决策**：AS_PATH 长度本身也是一个可用的选路依据（路径短者优先，但策略优先于长度）。

**辨析｜易错点：** 路径向量是「距离向量的升级版」：距离向量只传「距离数字」，路径向量传「完整路径」。**升级的收益是天然防环**——环可以通过「路径里有我」直接检测，不需要靠「距离到无穷」来兜底。**「传距离会环，传路径不环」**是一句话概括。

## 3 eBGP 与 iBGP：BGP 的两种会话

BGP 有两种运行模式：<span class="marginnote"><strong>eBGP</strong>`：连接<strong>不同 AS</strong>` 的 BGP 路由器（AS 边界路由器之间），交换跨 AS 的路由。<strong>iBGP</strong>`：连接<strong>同一 AS 内</strong>的 BGP 路由器，把 eBGP 学到的外部路由在全 AS 内传播。区别的关键：iBGP 传播时<strong>不改写 AS_PATH</strong>`，eBGP 则会在路径前追加自己的 AS 号。</span>

| 对比维度 | eBGP | iBGP |
| --- | --- | --- |
| 会话双方 | 不同 AS | 同一 AS |
| AS_PATH 处理 | 追加自己的 AS 号 | 不追加 |
| 用途 | 交换跨 AS 路由 | 在 AS 内传播外部路由 |
| 典型对端 | 运营商边界路由器 | 同 AS 的 BGP 路由器 |

**辨析｜易错点：** 「BGP 用 TCP（端口 179）传输」是它的标志性特点——BGP 不靠 UDP、不靠 IP 广播，而是**在 TCP 可靠连接上交换路由**。**「BGP over TCP」**意味着路由交换本身是可靠的、有序的，这在路由协议里独树一帜（RIP 用 UDP、OSPF 用 IP）。但这也带来一个「鸡生蛋」问题：BGP 依赖 TCP 可达，而 TCP 可达又依赖路由——解决靠「BGP 邻居是手工静态配置的」。

## 4 BGP 的关键属性：选路的「筹码」

BGP 选路靠一系列**路径属性（attributes）**，核心几个：

| 属性 | 含义 | 选路时的作用 |
| --- | --- | --- |
| AS_PATH | 经过的 AS 序列 | 防环 + 路径长度参考 |
| NEXT_HOP | 下一跳 IP | 指向转发出口 |
| LOCAL_PREF | 本地偏好（AS 内） | 值越大越优先（越高越好） |
| MED | 对外宣告的度量 | 值越小越优先（越低越好） |

BGP 选路时按属性逐级比较：**LOCAL_PREF 高者优先 → AS_PATH 短者优先 → 其他属性……**<span class="marginnote">BGP 的选路不是单一度量，而是「<strong>逐级筛选</strong>」：先比策略属性（LOCAL_PREF），再比路径质量（AS_PATH），最后才比具体度量（MED）等。这套「多级比较」让运营商可以精细控制流量走向——比如「这个方向我更喜欢，路由就优先从这走」。</span>

**辨析｜易错点：** LOCAL_PREF 是 **AS 内部**设置的策略（越高越好），MED 是 **AS 间**宣告的度量（越低越好）——**一个控制「我这边偏好谁」，一个控制「我劝对端怎么选」**。把两者方向记混（一个高好一个低好），是做 BGP 策略题最经典的错误。

## 5 小结

- **BGP 的本质**：AS 之间的外部路由协议，传「可达性 + 策略」，不是最短路径。
- **路径向量**：携带完整 AS_PATH，天然防环（路径里有自己就丢弃）。
- **eBGP vs iBGP**：eBGP 跨 AS 且追加 AS 号，iBGP 在 AS 内传播且不追加。
- **BGP over TCP**：用 TCP 179 传输，路由交换可靠有序。
- **关键属性**：LOCAL_PREF（高好，本地策略）、AS_PATH（防环）、MED（低好，对外度量）。
- **选路逻辑**：多级筛选——策略优先，路径质量次之。
