## 为什么从 IP 地址与 MAC 地址的关系开始

一台主机上同时存在两种地址：**IP 地址**（网络层的逻辑地址）与 **MAC 地址**（数据链路层的硬件地址）。它们的功能是什么、为什么需要两个、数据在链路上到底用哪个？<span class="marginnote">一个最常见的困惑：既然 MAC 地址全球唯一，为什么还要 IP 地址？反过来，既然有了 IP 地址，为什么帧里还要写 MAC 地址？答案是：<strong>两种地址在不同层各司其职——IP 负责「端到端寻路」，MAC 负责「一跳一跳送货」</strong>。理解这个分工，是理解数据在网络里真实旅程的关键。</span>

这一节把两套地址的差异、分工、以及它们在「逐跳转发」中的配合讲透。

## 1 两种地址的本质差异

| 对比维度 | IP 地址 | MAC 地址 |
| --- | --- | --- |
| 所属层次 | 网络层 | 数据链路层 |
| 位数 | 32 位（IPv4） | 48 位 |
| 性质 | 逻辑地址（软件分配） | 硬件地址（固化网卡） |
| 全球唯一性 | 不是（可私有/可复用） | 是（出厂唯一） |
| 随位置变化 | 变（换网络就换 IP） | 不变（网卡不变就变） |
| 作用范围 | 端到端（跨网络） | 一跳一跳（同一链路内） |
| 类比 | 你的快递地址 | 你的身份证号 |

**辨析｜易错点：** **IP 地址是逻辑的、可变的，MAC 地址是物理的、不变的。** 你带着笔记本从家里（`192.168.1.x`）到咖啡馆（`10.0.0.x`），IP 变了，MAC 没变。**「IP 变、MAC 不变」**是一句话考点。注意：IP 的「非全球唯一」体现在私有地址——`192.168.1.1` 在全世界无数家庭网络里同时存在，这不冲突，因为它们不在同一个网络里互通。

## 2 为什么需要两种地址：端到端 vs 逐跳

核心问题是：**为什么不能只用一种？** 用一个具体旅程来理解。

假设主机 A 要发数据给远隔多个路由器的主机 B。数据报的 IP 头里始终写着**源 IP（A）与目的 IP（B）**——这两个地址在整个旅程中**保持不变**。但每一段链路上，帧头的 MAC 地址**每一跳都换**：

- 第一跳：A 的帧头写「源 MAC = A，目的 MAC = 路由器 R1」。
- 第二跳：R1 把帧头改写为「源 MAC = R1，目的 MAC = 路由器 R2」。
- 最后一跳：改写为「源 MAC = 最后路由器，目的 MAC = B」。
- **IP 地址全程不变，MAC 地址逐跳更换。**<span class="marginnote">这就是「端到端 vs 逐跳」的精髓：<strong>IP 地址是「写信时的收件人」，全程写一次；MAC 地址是「每一站快递单上的收件人」，每到一站换一次</strong>。数据在 IP 层看来是「一封直达的信」，在链路层看来是「一段段接力传递」。</span>

**辨析｜易错点：** 一个非常经典的错误是「认为 MAC 地址也全程不变」。**MAC 地址只在同一局域网内有效**——跨越路由器就必须更换。**IP 地址不可变（端到端），MAC 地址逐跳变**，这两句话必须同时成立。抓包时你会看到：帧头 MAC 每一跳都在变，但 IP 头里的源/目的 IP 始终如初。

## 3 为什么路由器「只看 IP 不看 MAC 转发」

顺着上面的旅程，还能澄清一个分工：

- **路由器**：剥开帧头、取出 IP 数据报，**按目的 IP 地址查路由表**决定下一跳，然后**重新封装新的帧头**（新 MAC）转发出去。
- **交换机**：只处理到链路层，**按目的 MAC 地址查转发表**决定从哪个端口送出。

**辨析｜易错点：** **路由器会「改写 MAC 地址」但「不改写 IP 地址」**。这正是「路由」与「交换」的分界：路由是「在 IP 层按目的地址选路」，交换是「在链路层按 MAC 地址送帧」。一台设备到底是路由器还是交换机，就看它工作在 IP 层还是 MAC 层。**「路由器改写帧头、保留 IP 头」**是抓包排障时最有用的观察点。

## 4 IP 地址如何映射到 MAC 地址：ARP 的预告

IP 地址是逻辑的，帧里用的是 MAC 地址——两者之间怎么转换？答案就是 **ARP（地址解析协议）**：<span class="marginnote">当发送方知道目的主机的 IP 地址、但不知道它的 MAC 地址时，就广播一个 ARP 请求：「谁的 IP 是 192.168.1.5？请把你的 MAC 地址告诉我。」目的主机收到后单播回复自己的 MAC。这个「IP → MAC」的解析就是 ARP——下一节专门展开。</span>

**辨析｜易错点：** ARP 解决的是「**同网段内**的 IP→MAC 映射」。如果目的主机不在同一网络，发送方查 ARP 缓存找到的是**网关（默认路由器）的 MAC 地址**，把帧发给网关，由网关接力——**「不在同一网络时，MAC 指向网关，IP 仍指向最终目的」**。这句话是理解「IP 端到端 + MAC 逐跳」的最后一环。

## 5 小结

- **两种地址分工**：IP 是端到端的逻辑地址（寻路），MAC 是逐跳的硬件地址（送货）。
- **变化规律**：IP 地址全程不变（跨网络要换），MAC 地址每一跳都换。
- **本质差异**：IP 逻辑可变、MAC 物理不可变；IP 可私有、MAC 出厂唯一。
- **路由器行为**：改写 MAC 帧头、保留 IP 头，按目的 IP 选路。
- **ARP 预告**：IP→MAC 的映射靠 ARP 完成；跨网段时 MAC 指向网关、IP 指向最终目的。
