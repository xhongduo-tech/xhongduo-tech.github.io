## 为什么从路由器构成开始

前面我们把路由协议（RIP/OSPF/BGP）与转发算法都讲了一遍，但它们是在哪运行的？答案是**路由器**。一台路由器内部藏着两套并行的系统：**路由选择部分**（慢速、算路径）与**分组转发部分**（快速、查表送包）。<span class="marginnote">路由器是网络层的核心设备。理解它的最好框架是「<strong>控制面（control plane）与转发面（forwarding plane）分离</strong>」：控制面负责「怎么走」（跑路由协议、建路由表），转发面负责「怎么送」（查转发表、高速转发）。这个「两脑分工」是现代路由器的架构基石。</span>

这一节讲：**路由器的四部分组成、分组转发的完整流程、以及路由表与转发表的区别。**

## 1 路由器的组成部分

一台路由器由四大部分组成：

**输入端口（input port）**：接收从链路来的分组，做物理层接收、链路层解封装、网络层查表。
**交换结构（switching fabric）**：把分组从输入端口**交换**到正确的输出端口——类似交换机背板，是路由器内部的「十字路口」。
**输出端口（output port）**：从交换结构接收分组，做链路层封装、物理层发送。
**路由选择处理器（routing processor）**：运行路由协议（OSPF/BGP），计算路由表，是路由器的「大脑」。<span class="marginnote">四个部件的「快慢」差异极大：<strong>输入/输出端口与交换结构运行在「线速」（每秒钟十亿级分组），路由选择处理器运行在「慢速」（每秒若干次路由计算）</strong>。把「快的转发」与「慢的路由」分开并行，是路由器高性能的秘密。</span>

**辨析｜易错点：** 交换机与路由器的内部结构相似（都有端口与交换结构），但**路由器多了「路由选择处理器」这个第三层大脑**——交换机不做 IP 路由。**「交换机交换帧、路由器交换分组 + 路由计算」**，一字之差，层次不同。

## 2 控制面与转发面：两套系统

**控制面（control plane）**：负责**决定路由**——运行路由协议，计算并维护路由表。它慢、但重要，变化不频繁。

**转发面（forwarding plane）**：负责**执行转发**——收到分组，查转发表，送出去。它快、每包执行，是性能的瓶颈。<span class="marginnote">一个形象比喻：控制面是「画地图的规划局」，转发面是「照着地图送快递的快递员」。规划局慢慢研究新路，快递员见到包裹秒查秒送。<strong>两者可以分离：转发表可以提前由控制面算好、下发到硬件（如 TCAM 转发表）</strong>——这正是现代路由器的 SDN 式演进方向（第 9 章讲 SDN 时再展开）。</span>

**辨析｜易错点：** 路由表与转发表是两个不同的表：<span class="marginnote"><strong>路由表</strong>由控制面维护，条目细（含下一跳、度量、来源协议等）；<strong>转发表</strong>由转发面使用，是路由表的「精简编译版」——只保留「目的前缀 → 输出端口」，适合硬件高速查找。<strong>「路由表是源代码，转发表是编译产物」</strong>。</span> 做题时别把两个表混为一谈。

## 3 分组转发流程：一个分组的「路由器之旅」

一个分组经过路由器的完整流程：

1. **物理层接收**：输入端口把信号还原成比特。
2. **链路层解封装**：剥掉帧头/帧尾，取出 IP 数据报（校验 FCS）。
3. **网络层查表**：取出目的 IP 地址，查转发表（最长前缀匹配），决定输出端口。
4. **交换结构传送**：把分组从输入端口交换到输出端口。
5. **链路层封装**：输出端口重新封装帧头（改写源/目的 MAC）。
6. **物理层发送**：把帧变成信号送出去。<span class="marginnote">注意第 5 步的细节：<strong>路由器转发时必须「重写 MAC 地址」</strong>——出接口的 MAC 是新的，目的 MAC 换成下一跳的 MAC，而 IP 头里的源/目的 IP 不变。这正是第 4 章前面「IP 端到端、MAC 逐跳」原则在路由器上的具体执行。</span>

**辨析｜易错点：** 路由器是**逐跳转发**——它只决定「下一跳」，不保证「全程」；每经一台路由器，MAC 帧头就换一次，IP 头不变。**「TTL 每跳减 1、MAC 每跳重写、IP 全程不变」**是抓包观察路由器行为的三条铁律。

## 4 表驱动 vs 缓存：转发速度的工程

现代路由器追求**线速转发**，关键的工程手段：

**硬件转发表**：用 **TCAM（三态内容寻址存储器）** 或专用 ASIC 做最长前缀匹配——一次查表 O(1)，不需要软件遍历。
**交换结构无阻塞**：交换结构（如纵横开关、多级互联网络）保证输入与输出之间不拥塞。
**快速路径 vs 慢速路径**：绝大多数分组走「硬件快速路径」直接转发；异常分组（首片分片、选项、需要 ICMP）才交给软件慢速路径处理。<span class="marginnote">「快速路径/慢速路径」是路由器性能优化的经典设计：<strong>99% 的普通分组在硬件里光速转发，1% 的特殊分组才惊动 CPU</strong>。这也解释了为什么「带选项的 IP 包」或「分片包」在网络里会被特殊对待——它们迫使路由器走慢速路径，容易成为被攻击利用的靶子。</span>

**辨析｜易错点：** 「查表」与「转发」在硬件里是并行的：输入端口**边接收边查表**（流水线），而不是「收完整个包再查表」——这叫**直通转发（cut-through）**思想。**「边收边查、收完即转」**让现代路由器能做到「线速转发」，而不是「存储转发」的慢速模型。

## 5 小结

- **路由器四部件**：输入端口、交换结构、输出端口、路由选择处理器。
- **控制面 vs 转发面**：控制面算路径（慢），转发面送包（快）；两者分离是架构基石。
- **路由表 vs 转发表**：前者是控制面的「源代码」，后者是转发面的「编译产物」。
- **转发六步**：物理接收 → 链路解封装 → 查转发表 → 交换结构 → 链路封装 → 物理发送。
- **逐跳三铁律**：TTL 每跳减 1、MAC 每跳重写、IP 全程不变。
- **工程提速**：TCAM 硬件查表、无阻塞交换结构、快速/慢速路径分离。
