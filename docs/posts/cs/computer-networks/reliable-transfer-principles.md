## 为什么从可靠传输的工作原理开始

第 3 章数据链路层讲过停止-等待、GBN、SR——那是「帧」层面的可靠传输。TCP 把同样的思想搬到了「字节流」层面，但它面对的信道更复杂：**全双工、双向数据、双向确认、动态往返时延**。这一节把「可靠传输的工作原理」做一次系统化：从最简单的理想条件开始，一步步加入现实约束。<span class="marginnote">可靠传输是网络协议设计的「母题」：<strong>无论链路层、传输层还是应用层，只要需要「可靠」，都逃不出「确认 + 重传 + 序号」这套组合</strong>。理解它的推导过程，比背协议细节重要得多——因为一切可靠协议都是这套原理的实例。</span>

这一节用一个「逐步放松假设」的方法，重建可靠传输的原理。

## 1 理想条件：假设信道完全可靠

**第一步，假设信道完全可靠**——不会出错、不会丢包、不会乱序。这时可靠传输最简单：发一帧，对方收一帧，什么额外机制都不需要。这个「理想假设」是推导的起点。

但现实信道不可能完美，于是我们逐步放松假设，每放松一个，就引入一个机制。

## 2 放松假设一：信道会出错——引入确认

如果信道会出错（比特翻转），接收方怎么知道「收到了正确数据」？引入**确认（acknowledgment）**：

接收方收到数据，校验通过，回一个 **ACK**（确认）。
发送方收到 ACK，知道数据已安全到达，才发下一份。

**但只加 ACK 够吗？** 如果 ACK 本身丢了，发送方会一直等下去——所以还要**超时重传**：发送方设一个计时器，超过一定时间没收到 ACK，就重发。<span class="marginnote">「确认 + 超时重传」是可靠传输的第一块基石：<strong>确认告诉发送方「到了」，超时告诉发送方「可能没到、重发」</strong>。注意「可能」二字——发送方其实无法区分「数据丢了」还是「ACK 丢了」，只能用超时统一兜底。</span>

## 3 放松假设二：会丢包或重复——引入序号

超时重传带来新问题：如果 **ACK 丢失但数据其实到了**，发送方重传，接收方会**收到重复数据**。怎么识别重复？**给数据编号（序号）**：

接收方记住「已收到的最大序号」，重复的序号直接丢弃（但仍回 ACK）。
发送方按序号跟踪「哪些还没被确认」。

**辨析｜易错点：** **丢弃重复数据是可靠传输的必要环节**——序号让接收方有能力识别「重传的旧数据」与「新数据」。如果只确认不编号，重复问题无解。**「确认防丢失、序号防重复」**是可靠传输的两大支柱。

## 4 放松假设三：乱序与连续发送——引入窗口与排序

如果数据可能乱序到达（不同路径）、且为了效率要连续发送，怎么办？引入**滑动窗口与按序重组**：

**发送窗口**：允许「未确认的数据」上限为 W，可以连续发送 W 份，不必停等。
**接收窗口**：接收方缓存乱序数据，按序号排序后交付。
**累积确认**：ack = n 表示「n 之前全部收到」，一个确认覆盖一片。<span class="marginnote">从「停等」到「窗口」是效率的革命：<strong>停等让在途数据 = 1，窗口让在途数据 = W</strong>。TCP 发送方可以一边发数据、一边收确认（全双工），配合滑动窗口把链路带宽-时延积填满。上一节链路层的 GBN/SR，就是窗口思想在帧层面的体现。</span>

**辨析｜易错点：** TCP 的可靠传输是「全双工的」——**两端各有一套序号、各发各的确认**，而不是「一问一答」的停等。TCP 还能在数据报文段里「捎带」确认（piggyback），让 ACK 几乎不占额外开销。

## 5 一张表：理想到现实的「机制演进」

| 现实约束 | 引入的机制 | 解决什么 |
| --- | --- | --- |
| 信道出错 | 确认（ACK） | 知道数据到达 |
| ACK 丢失/数据丢失 | 超时重传 | 数据终会到达 |
| 重复数据 | 序号 | 识别并丢弃重复 |
| 乱序到达 | 接收窗口排序 | 按序交付 |
| 连续发送提速 | 发送滑动窗口 | 利用率提升 |
| 确认开销 | 捎带确认/累积确认 | 减少确认报文 |

**辨析｜易错点：** 这套「逐步加机制」的推导，是 TCP 设计的完整逻辑链。**任何「可靠传输协议」都可以在这张表里对号入座**——理解它，比背任何协议细节都值钱。**「可靠 = 确认 + 重传 + 序号 + 窗口」**，四个部件缺一不可。

## 6 小结

- **可靠传输的母题**：确认 + 重传 + 序号 + 窗口，一切可靠协议都是这套组合的实例。
- **确认**：告诉发送方「数据到了」；**超时重传**：兜底「可能丢了」。
- **序号**：识别重复数据，是「防重复」的必要手段。
- **窗口**：让多个数据同时在途，解决停等的效率灾难。
- **TCP 的特殊性**：全双工、双向序号、捎带确认、字节级编号。
- **推导方法**：从理想信道出发，逐条放松假设、逐条加机制——可靠协议的设计方法论。
