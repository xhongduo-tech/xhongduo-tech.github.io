## 为什么从 Web3 开始

我们已经走完区块链的「基础设施层」：共识、智能合约、Token、DeFi、DAO。**Web3** 是这些技术的「用户体验层」——一个去中心化的互联网愿景。这一节把它从口号还原成架构：DApp 长什么样、钱包扮演什么角色、身份如何自持、以及「去中心化应用」究竟去中心化了什么。理解 Web3，才能判断哪些是真实的技术进步、哪些只是营销话术。

## 1 从 Web1 到 Web3

三代互联网的对比：

| 时代 | 范式 | 数据与身份 | 典型代表 |
| --- | --- | --- | --- |
| Web1 | 只读 | 内容静态、无账户体系 | 门户网站、个人主页 |
| Web2 | 可读写 | 平台托管数据与身份 | 社交平台、电商 |
| Web3 | 可读写 + 拥有 | 用户自持身份与资产 | 区块链 DApp、钱包 |

**Web2 的核心问题**：平台是「数据的中介」——用户数据被平台占有、身份被平台锁定、规则被平台单方面修改（封号、改条款）。Web3 的回应是：**身份（钱包地址）、资产（Token/NFT）、数据（链上/去中心化存储）由用户自持，平台只是「应用」而非「主权者」**。<span class="marginnote">Web3 最常被误解的地方是「Web3 = 用区块链的网站」。真正的分野不在技术栈，而在「谁控制数据」：一个把用户数据放在中心化数据库、只是接了个钱包按钮的网站，本质还是 Web2。Web3 的关键是可验证性——用户可以离开平台，带走自己的数据与资产。</span>

## 2 DApp 的架构

**DApp（Decentralized Application）** 通常由四层组成：

1. **前端**：普通 Web 前端（React/Vue），通过钱包连接链上。
2. **钱包**：管理私钥、签名交易、与链交互（MetaMask 等）。
3. **智能合约**：核心逻辑，部署在链上。
4. **去中心化存储/索引**：IPFS（文件）、The Graph（链上数据索引）、Arweave（永久存储）。

**前端不是去中心化的**——它的 HTML/JS 可以托管在中心化服务器；DApp 的「去中心化保证」来自合约逻辑与数据所有权，而非前端托管方式。<span class="marginnote">「前端可以改」是 DApp 的信任盲区：恶意前端可以把用户导入钓鱼合约。行业方案是「前端 IPFS 托管 + ENS 域名 + 内容寻址」，让前端版本可验证、可审计。</span>

**一次典型 DApp 交互**：

```javascript
import { ethers } from "ethers";

// 连接钱包
const provider = new ethers.BrowserProvider(window.ethereum);
const signer = await provider.getSigner();

// 读操作：免费、无需签名
const balance = await token.balanceOf(signer.address);

// 写操作：必须由钱包签名并支付 Gas
const tx = await token.transfer(recipient, amount);
await tx.wait(); // 等待上链确认
```

关键：**所有「改变状态」的操作都必须由用户钱包签名**——没有「服务端替你改数据」，这是 DApp 与 Web2 的体验分水岭。

## 3 钱包：Web3 的身份基础设施

**钱包（wallet）** 不只是「存钱」——它是 Web3 的**身份与钥匙管理**：

- **身份**：钱包地址 = 你的链上身份（不依赖任何平台注册）。
- **签名**：登录 DApp 用「签名消息」（不暴露私钥），取代「用户名 + 密码」。
- **交易**：构造、签名、广播交易。
- **助记词**：12/24 个单词可恢复私钥——**谁有助记词，谁就有该身份的全部控制权**。

**公式解析：从助记词到地址**

$$
\text{seed} \xrightarrow{\text{PBKDF2}} \text{master key} \xrightarrow{\text{HD 派生}} k_i \xrightarrow{secp256k1} Q_i \xrightarrow{\text{keccak}} \text{address}_i
$$

- **第一步**：助记词通过密钥派生函数生成主密钥（master key）。
- **第二步**：分层确定性（HD）钱包用路径（如 `m/44'/60'/0'/0/0`）派生出无数子私钥。
- **第三步**：每个私钥经椭圆曲线得公钥，再哈希成地址——一个助记词可以管理无数账户，这就是「一个钱包，无数身份」的来源。<span class="marginnote">BIP-32/39/44 定义了 HD 钱包的标准：助记词（BIP-39）→ 种子 → 主密钥 → 分层派生（BIP-32）→ 账户路径（BIP-44）。这套标准让任何钱包都能恢复同一组账户——「助记词即身份」成为 Web3 的通用约定。</span>

## 4 去中心化身份（DID）与 ENS

**DID（Decentralized Identifier）**：由用户自持、不依赖中心化注册机构的标识符；凭证（资质、学历）由签发方签名、用户选择性披露。
**ENS（Ethereum Name Service）**：把 `vitalik.eth` 这样的可读名字映射为钱包地址，让地址可读、可携带；ENS 域名的所有权即链上 NFT。<span class="marginnote">ENS 的深层价值是「可移植的身份命名」：你的 ENS 名字跟随钱包走，任何 DApp 都能解析，不依赖某个平台——这正好对 Web2「用邮箱注册被平台锁定」的痛点。ENS 也常被当作「链上身份的入口」，与 DID 体系互相补充。</span>

## 5 从 DApp 到「应用互联网」

DApp 生态已经超出「加密原生」：

**DeFi**（金融应用）与 **NFT/游戏**（资产应用）是第一批 DApp。
**社交协议**（Farcaster、Lens）：用户关注关系与内容是链上资产，可迁移。
**创作者经济**：版税、会员资格用 Token/NFT 表达，去中介化分发。
**链上治理应用**：DAO 工具、提案、金库管理（见《DAO 与治理》）。

**辨析｜易错点：DApp 的「去中心化」是分层的，不是全有或全无。** 一个 DApp 可以「合约去中心、前端中心化、存储混合」——评估一个 DApp 是否名副其实，要分别看逻辑、前端、数据、治理四个维度各有多去中心化。**另一个易错点：「钱包」不是 DApp 的附属品，而是独立的身份层**——同一钱包可以连接无数 DApp，你的身份与资产不属于任何 DApp，这恰恰是 Web3 与 Web2 的本质差异。

## 6 从 DApp 到链上用户体验

DApp 的用户体验（UX）与传统 Web 有本质差异，也是 Web3 普及的最大瓶颈。几个关键挑战与解法：

**签名疲劳**：每一笔「改变状态」的操作都要弹窗确认——买一个 NFT 可能要签名 3–5 次。解法方向：**会话密钥（session keys）**（一次授权、短时免签）、**意图协议（intents）**（用户声明「我要什么」，求解器自动路由最优路径，只签一次）。

**钱包安全与易用**：助记词是「最安全的钥匙」也是「最易丢的钥匙」。解法：**智能账户（smart account / ERC-4337 账户抽象）**——把「钱包」本身做成合约，支持社交恢复、多签、限额、免 Gas（由应用代付）等策略。账户抽象被广泛视为「钱包体验」的下一个革命。

**Gas 门槛**：新用户没有 ETH 就无法「上车」。解法：**元交易（meta-transaction）**与**中继（relayer）**——应用替用户付 Gas，用户用「签名授权」代替「持有 ETH」；这是「无 Gas 体验」的技术基础。<span class="marginnote">ERC-4337 账户抽象把「钱包」从「私钥管理的 EOA」升级为「可编程的合约账户」：支付 Gas 可以由任意人代付、权限可以分层、丢失可以社交恢复。它让「钱包」第一次成为「可编程身份」，是 DApp UX 与合规（多签金库、限额消费）的共同底座。2024–2026 年，账户抽象的普及度持续上升。</span>

**链下索引与查询**：前端需要「读」大量链上数据（余额、价格、历史）。直接遍历链上太慢太贵——**索引器（indexer）**与**子图（subgraph）**把链上事件组织成可查询的数据库（The Graph），前端一次 GraphQL 查询即可拿到数据。理解 DApp 架构，就理解「链上写、链下读」的常态：**链上只存「状态」与「事件」，链下负责「组织」与「展示」**。

**应用生态的「全链化」**：随着账户抽象、跨链消息与链抽象成熟，DApp 正在从「单链应用」走向「全链应用」——一个应用可以同时运行在以太坊、L2、其他公链上，用户不感知「在哪条链」。这对前端架构、Gas 模型与状态同步都提出新要求。

**公式解析：账户抽象下的「无 Gas」流程**

$$
\text{UserOp} = \{\text{sender}, \text{target}, \text{data}, \text{paymaster}, \text{signature}, \cdots\}
$$

- **第一步**：用户不再发「交易」，而是提交「用户操作（UserOp）」——一条「我想要什么」的签名请求。
- **第二步**：聚合器（bundler）把多条 UserOp 打包成一条普通交易提交上链；`paymaster` 字段指定「谁付 Gas」。
- **第三步**：验证与执行分离——`EntryPoint` 合约先验证签名、再执行；用户不需要持有 ETH，只需持有「能被接受为签名」的任何凭证。**「账户抽象」的本质是把「交易发起权」从「私钥 EOA」扩展到「任意可编程账户」**。

**辨析｜易错点：DApp 前端「连了钱包」不代表「去中心化」。** 判断去中心化要看「资产与数据由谁控制」「合约能否被关停」，而不是「有没有钱包弹窗」。**另一个易错点：账户抽象 ≠「没有私钥」**——它是把「私钥管理」变成「可编程策略」，私钥仍然存在（只是可以被恢复、被委托、被限额），「无私钥」的营销说法是在偷换概念。

## 7 小结

- **Web1/Web2/Web3** 的分野在「谁控制数据与身份」；Web3 = 用户自持 + 平台可退出。
- **DApp 四层架构**：前端、钱包、智能合约、去中心化存储/索引；「改变状态必须钱包签名」是体验分水岭。
- **钱包 = 身份 + 钥匙管理**：地址即身份，助记词可恢复一切，「助记词即控制权」。
- HD 钱包从助记词经 **PBKDF2 → 主密钥 → 派生 → 公钥 → 地址** 管理无数账户。
- **DID/ENS** 让身份自持、地址可读；DApp 去中心化是**分层**的，评估要分维度。

在下一节，我们转到 Web3 的黑暗面——资产高度集中、代码不可回滚的世界里，有哪些致命攻击？这就是**区块链安全（重入/闪电贷）**。
