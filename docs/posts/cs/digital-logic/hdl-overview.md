## 为什么从 HDL 概述开始

前面十篇，我们都在用**原理图**的语言看硬件——门、触发器、连线。但从这一篇起，我们换一种语言：**硬件描述语言（HDL）**。用代码描述硬件、用工具自动综合，这不仅是现代数字设计的标准工作方式，也是第十二篇「用 Verilog 搭 CPU」的入场券。<span class="marginnote">HDL 的全称是 Hardware Description Language——注意是「描述」而非「编程」。<strong>写 HDL 是在「描述一个硬件电路」，不是在「写一段顺序执行的程序」</strong>——这是从软件思维转向硬件思维的第一道坎，也是本篇反复强调的核心。</span>这一节讲清 HDL 是什么、为什么需要它、以及它和原理图、和软件语言的差别。

## 1 从原理图到 HDL：一次设计范式的革命

**原理图设计**：用图形工具画门、画连线，直观但——规模一大就崩溃：一个上千门的电路，原理图变成「蜘蛛网」，没法看、没法改、没法复用。

**HDL 设计**：用文本描述「电路的行为或结构」，由工具自动综合成门级网表。

**对比**：

| 对比 | 原理图 | HDL |
|---|---|---|
| 表达方式 | 图形连线 | 文本代码 |
| 设计规模 | 小（几十门） | 大（百万门级） |
| 可复用性 | 差 | 好（模块参数化） |
| 可仿真性 | 难 | 容易（Testbench） |
| 可维护性 | 差 | 好（版本管理、注释） |
| 现代地位 | 辅助 | 绝对主流 |

<span class="marginnote">HDL 的价值不仅是「省画图」：<strong>它让硬件设计获得了软件的工程能力——版本控制、模块复用、自动化验证、团队协作</strong>。今天的 CPU、GPU、FPGA 设计，全靠 HDL（Verilog/VHDL/SystemVerilog）。</span>

## 2 HDL 的两种描述层次

HDL 可以从两个层次描述硬件：

**行为级（behavioral）**：描述「电路做什么」，不关心具体门怎么连。

```verilog
assign y = a & b | c;   // y = a·b + c，行为描述
```

**结构级（structural）**：描述「电路怎么连」，例化具体的门/模块。

```verilog
and g1(w1, a, b);       // 一个与门，输出 w1
or  g2(y, w1, c);       // 一个或门，输出 y
```

**设计流程**：通常**先写行为级**验证功能，**再综合**成结构级网表，最后布局布线。

**辨析｜易错点：** 行为级不等于「软件程序」——行为级 HDL 依然描述**并行硬件**：所有 `assign`/`always` 块是**同时执行**的，没有「先来后到」。这与 C 语言顺序执行完全不同。理解「并行性」是学 HDL 的第一课。<span class="marginnote">「并行 vs 顺序」是 HDL 最核心的思维转换：<strong>电路里所有门同时工作，所以 HDL 里所有赋值语句「同时」有效</strong>。一段 Verilog 里两个 `assign` 没有先后，就像两个门没有先后。而 C 语言里语句有严格顺序。把 C 的习惯带进 Verilog，是初学者最大的坑。</span>

## 3 为什么选择 Verilog

HDL 的两大主流是 **Verilog** 与 **VHDL**，本篇选 Verilog，理由是：

- **语法类似 C**：`if`、`case`、`for` 等结构熟悉，上手快。
- **简洁灵活**：表达组合/时序逻辑直接。
- **生态最大**：FPGA 工具（Vivado、Quartus）、开源工具（Icarus、Verilator）、大量 IP 库都支持。
- **SystemVerilog 兼容**：现代验证方法学（UVM）基于它。

**Verilog 简史**：1980 年代 Gateway Design 开发，1995 年成为 IEEE 标准，2005 年推出 SystemVerilog 扩展。它是数字设计的事实标准之一。<span class="marginnote">VHDL 与 Verilog 之争像「Python vs Java」之争：<strong>VHDL 更严谨冗长（军工、航天青睐），Verilog 更简洁灵活（业界主流）</strong>。本篇学 Verilog，一通百通——概念（模块、信号、时钟、状态机）两者共享。</span>

## 4 公式解析：Verilog 与硬件的一一对应

HDL 最重要的能力是「**代码 ↔ 硬件**」的双向翻译。看几个基本对应：

| Verilog 代码 | 对应硬件 |
|---|---|
| `assign y = a & b;` | 一个与门 |
| `assign y = ~a;` | 一个反相器 |
| `always @(posedge clk) q <= d;` | 一个边沿 D 触发器 |
| `wire w;` | 一根连线 |
| `reg q;` | 一个存储变量（在过程块中） |

**第一步，看组合逻辑**：`assign` 语句的右端表达式 → 组合逻辑电路；输入变，输出立即变。

**第二步，看时序逻辑**：`always @(posedge clk)` 块 → 触发器；只在时钟边沿更新。

**第三步，看信号**：`wire` 是「连线」（组合逻辑的输出），`reg` 是「过程变量」（常在触发器中使用）。

**第四步，看并行性**：所有语句同时生效，互不等待——这就是硬件的「并行」本质。<span class="marginnote">这条对应表是学习 Verilog 的「翻译词典」：<strong>读代码时把它翻译回硬件，写代码时把硬件翻译成代码</strong>。做到「看到代码想到电路」，HDL 就学会了。Verilog 里没有「顺序」，只有「并行」——时刻记住这一点。</span>

## 5 HDL 在现代设计中的流程地位

HDL 位于现代数字设计流程的**入口**：

```
需求 → HDL 设计输入 → 功能仿真 → 综合（HDL→网表）→ 布局布线 → 时序分析 → 下载
```

- HDL 是「源代码」，综合工具是「编译器」，网表是「汇编」，位流是「可执行文件」。
- 仿真（Testbench）是「调试器」——在软件里验证硬件。

这一篇后面几节会依次学：模块结构（11.2）、数据类型与运算符（11.3）、组合建模（11.4）、时序建模（11.5）、状态机（11.6）、Testbench（11.7）。<span class="marginnote">从「从极限到大模型」的视角：<strong>今天所有 AI 芯片（GPU、TPU、NPU）都是用 HDL 设计出来的</strong>。你在 Verilog 里写的每一个模块，都是硬件；理解 HDL，就是理解 AI 硬件是如何「被写出来」的。</span>

## 6 HDL 设计的常见思维陷阱

从软件思维转向硬件思维，有几个经典的「坑」，提前识破能少走弯路：

**陷阱一：以为 HDL 顺序执行**。Verilog 的 `assign`、`always` 块是**并行**的——没有「先来后到」。两个 `assign` 同时生效，与书写顺序无关。把 C 的顺序思维带进来，是最普遍的坑。

**陷阱二：以为 `reg` 就是寄存器**。`reg` 只是「过程块里的变量」，综合成什么取决于赋值方式——组合块里是连线、时序块里才是触发器（第十一篇详述）。

**陷阱三：写完不仿真就下载**。HDL 的「编译通过」不代表「逻辑正确」——必须用 Testbench 仿真验证。软件里编译错是运行时错，硬件里逻辑错是「芯片不对」。

**陷阱四：忽略时序约束**。HDL 能综合成电路，但电路能不能跑在目标频率，由建立/保持时间决定——不写时序约束、不看时序报告，设计可能「综合过了、上板翻车」。

**陷阱五：把 `if` 当「判断」而非「选择」**。HDL 的 `if/case` 最终是**多路选择器（MUX）**——不是「程序分支」，是「电路选择」。理解这一点，才能预判综合结果。

**如何避开**：学 HDL 时反复提醒自己「我描述的是硬件，不是算法」——每个语句都问一句「这对应什么电路」。时刻带着「代码 ↔ 电路」的翻译镜，陷阱自然消失。

**辨析｜易错点：** 陷阱一最隐蔽：在 `always` 里写 `a = b; b = a;`（阻塞赋值）会交换失败（a 先更新），非阻塞 `a <= b; b <= a;` 则正确交换——这正是「并行 vs 顺序」的直接后果。用这段代码自测，就能判断自己是否真的理解了并行。

## 7 小结

- HDL 用代码描述硬件，是现代数字设计的主流范式，取代了原理图。
- 两种层次：行为级（做什么）与结构级（怎么连）。
- **并行性**是 HDL 与软件的根本区别：所有语句同时生效。
- Verilog 语法类 C、生态最大，是学习与实践的主流选择。
- 代码 ↔ 硬件一一对应：`assign`→组合、`always @(posedge clk)`→触发器。
- HDL 是设计流程的入口，综合工具把它翻译成门级网表与位流。
