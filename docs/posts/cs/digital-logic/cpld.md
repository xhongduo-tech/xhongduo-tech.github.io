## 为什么从 CPLD 开始

单个 PAL/GAL 只有几十个乘积项，做复杂设计不够用。**CPLD（Complex Programmable Logic Device，复杂可编程逻辑器件）**把多个 PAL 型功能块、可编程互连与 I/O 集成到一颗芯片上，逻辑容量达到几千至上万等效门，且**时序可预测**。<span class="marginnote">CPLD 的本质一句话：<strong>「多个 PAL/GAL 块 + 可编程互连总线」</strong>。它保留了 PAL 的与-或阵列与乘积项结构，只是把规模放大、把互连加入。相比 FPGA，CPLD 的延迟更可预测（基于乘积项的固定时序），适合对时序要求严的控制逻辑。</span>这一节解剖 CPLD 的三层结构：逻辑块、互连、I/O。

## 1 CPLD 的总体结构：三层架构

CPLD 芯片内部由三部分组成：

1. **逻辑块（Logic Block）**：核心计算单元，本质是一个「放大版 PAL/GAL 宏单元」——包含与-或阵列、乘积项分配、触发器等。
2. **可编程互连（Interconnect）**：连接各逻辑块的「网络」，决定信号如何在块之间传递。
3. **I/O 块**：芯片引脚与内部逻辑的接口，可配置输入/输出/三态。

结构示意：多个逻辑块围绕一个**互连阵列**排列，I/O 块分布在芯片四周。

**容量**：典型 CPLD 有几十到几百个宏单元，等效几千到几万个门。<span class="marginnote">CPLD 的宏单元数是最常用的容量指标：<strong>每个宏单元 ≈ 一个可编程的输出逻辑单元（含乘积项、或门、触发器）</strong>。「64 宏单元」「128 宏单元」的 CPLD 就是按这个数标称的。选型时看宏单元数，就是看逻辑容量。</span>

## 2 逻辑块：放大版 PAL

CPLD 的逻辑块（也叫功能块，FB）是 PAL/GAL 思想的规模化：

**与阵列**：可编程，产生乘积项。
**乘积项分配**：把乘积项灵活地分配给各输出（有的 CPLD 用「乘积项共享」机制，让一个输出能用更多乘积项）。
**宏单元**：或门 + 触发器 + 输出选择，可配组合/寄存器输出。

**与 PAL 的区别**：CPLD 的宏单元更多、乘积项分配更灵活、每个宏单元带触发器（支持时序设计）。

**辨析｜易错点：** CPLD 与 FPGA 最容易被混为一谈，但底层实现完全不同：**CPLD 用「乘积项（与-或）」实现逻辑，FPGA 用「查找表（LUT）」实现逻辑**。一个是「与或阵列」，一个是「查表」——这是两者的根本分界。前者延续 PAL 血统，后者是「用存储器实现逻辑」的现代形态。

## 3 互连与 I/O：把块连成系统

**可编程互连**是 CPLD 的「神经系统」：

传统 CPLD 用**全局互连总线**：所有逻辑块都接到一条（或几条）共享总线上，信号经总线在块间传输。
互连点可编程，决定「哪个块的输出送到哪个块的输入」。

**特点**：全局总线结构的延迟**可预测**——信号经过的路径长度大致固定，时序分析容易。这是 CPLD 相比 FPGA 的核心优势之一。

**I/O 块**：

可编程配置为输入、输出、双向（三态）。
带输出使能控制，支持总线接口。
部分 CPLD 的 I/O 支持不同电平标准（LVTTL、LVCMOS 等）。

<span class="marginnote">CPLD 的互连哲学：<strong>「共享总线、延迟可预测」</strong>——所有信号走统一的总线结构，走线延迟一致，时序稳定。FPGA 则用「局部互连 + 全局互连」的层次网络，延迟因路径而异（更灵活但更难预测）。这是两者设计哲学的分野。</span>

## 4 公式解析：CPLD 与 FPGA 的选择

选 CPLD 还是 FPGA，取决于需求。用一张决策表看关键权衡：

| 需求 | 推荐 | 原因 |
|---|---|---|
| 时序要求严、延迟可预测 | CPLD | 乘积项结构、全局总线，延迟稳定 |
| 逻辑量大（>万门） | FPGA | CPLD 容量上限远小于 FPGA |
| 上电即用（无需配置加载） | CPLD | 非易失（EEPROM 工艺），上电直接工作 |
| 高性能算法、并行计算 | FPGA | LUT + 大量寄存器 + 高速互连 |
| 低功耗待机 | CPLD | 静态功耗低 |

**第一步，看时序确定性**：CPLD 的延迟可预测（如 $t_{PD}$ 固定），FPGA 的布线延迟因设计而异——时序苛刻用 CPLD。

**第二步，看容量与性能**：FPGA 容量大几个数量级、支持高频——大而快用 FPGA。

**第三步，看上电行为**：CPLD 非易失、上电即工作；FPGA 多为 SRAM 配置，上电需从 Flash 加载——需要「秒启动」用 CPLD。

**第四步，看成本**：小规模控制逻辑用 CPLD 更省；大规模设计 FPGA 摊薄成本。<span class="marginnote">现实中的分工：<strong>CPLD 常用于「胶合逻辑、接口控制、简单状态机」，FPGA 用于「处理器、DSP、大规模并行」</strong>。许多板卡两者都放：CPLD 管启动与配置、FPGA 干重活——各取所长。</span>

## 5 CPLD 的应用场景

- **胶合逻辑（glue logic）**：把多块芯片粘合成系统的简单逻辑。
- **接口与电平转换**：总线桥接、引脚扩展。
- **简单状态机**：小规模控制器。
- **上电配置**：负责给 FPGA 加载配置。
- **中低速控制**：电机控制、电源管理、通信协议控制。

**辨析｜易错点：** CPLD 不是「大号 PAL」那么简单——它的价值在于**集成度 + 互连 + 可预测时序**的结合。单个 PAL 能做的 CPLD 都能做，但 CPLD 能做的（多块协同、复杂状态机）单块 PAL 做不了。看 CPLD 时关注「宏单元数 × 触发器数 × I/O 数」三个容量指标。

## 6 CPLD 的典型应用场景

CPLD 在现代系统里的「生态位」是什么？看几个典型应用：

**① 胶合逻辑（Glue Logic）**：把多块芯片的接口「粘合」起来——地址译码、片选生成、信号整形。CPLD 比一堆 74 系列小芯片省面积、可改，是胶合逻辑的主力。

**② FPGA 配置加载**：FPGA 上电需要从 Flash 读配置，CPLD 常承担「配置控制器」——时序简单、上电即用、无需配置，正好补 FPGA 的「启动空窗」。

**③ 上电初始化与接口控制**：系统上电瞬间，CPLD 先于 FPGA/CPU 就绪，做时钟复位管理、电源时序控制——这类「开机就要工作」的逻辑，只有非易失、上电即用的 CPLD 能胜任。

**④ 简单状态机与协议控制**：中低速协议（如 I²C 从机、SPI 转换、编码器接口）用 CPLD 实现，比 MCU 快、比 FPGA 省。

**⑤ 电平转换与引脚扩展**：CPLD 的 I/O 常支持多种电平标准，能做电平转换、扩展 GPIO。

**为什么 CPLD 没有被 FPGA 完全取代**：CPLD 的**可预测延迟**与**非易失即用**是 FPGA 没有的——FPGA 上电要加载、延迟随布线变化。对「时序苛刻 + 上电即需」的应用，CPLD 仍是不可替代的。

**选型总结**：小规模控制与接口用 CPLD，大规模计算与灵活逻辑用 FPGA——两者互补而非互斥，一块板上常同时出现。

**辨析｜易错点：** CPLD 的「复杂」指「多个逻辑块」，不代表「大容量」。CPLD 的容量上限远低于 FPGA（宏单元几千 vs FPGA 逻辑单元百万）——选型时先看容量需求，小则 CPLD、大则 FPGA。

## 7 小结

- CPLD = 多个 PAL 型逻辑块 + 可编程互连 + I/O 块。
- 逻辑块是「放大版 PAL」：与-或阵列 + 乘积项分配 + 宏单元（含触发器）。
- 互连用全局总线，**延迟可预测**——CPLD 的核心优势。
- CPLD vs FPGA：乘积项 vs LUT、容量小 vs 大、非易失上电即用 vs SRAM 需加载。
- 应用：胶合逻辑、接口控制、简单状态机、FPGA 配置加载。
