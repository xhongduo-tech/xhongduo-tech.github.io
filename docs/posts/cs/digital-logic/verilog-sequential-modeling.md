## 为什么从时序逻辑建模开始

组合逻辑描述「算」，时序逻辑描述「存与同步」——而这一切由时钟驱动。Verilog 里时序逻辑的建模只有一种标准写法：**`always @(posedge clk)` + 非阻塞赋值 `<=`**。掌握这个模板，就能描述一切带记忆的硬件：寄存器、计数器、状态机。<span class="marginnote">时序建模的黄金模板：<strong>`always @(posedge clk)`（或 negedge）+ `<=`（非阻塞）</strong>——这是综合器识别触发器的「官方格式」。改变这个模板的任何一个部分（如用阻塞赋值），都可能让触发器「消失」或行为错误。</span>这一节把时序建模讲透，重点是**阻塞与非阻塞赋值的区别**——Verilog 最经典、最易错的主题。

## 1 时序逻辑的标准模板

**D 触发器**的 Verilog 描述：

```verilog
always @(posedge clk) begin
    q <= d;
end
```

- `@(posedge clk)`：在时钟上升沿触发。
- `q <= d`：非阻塞赋值，把 d 采入 q。
- 综合结果：一个边沿 D 触发器——与我们第五篇画的触发器完全等价。

**带异步复位的 D 触发器**：

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end
```

- `or negedge rst_n`：复位信号也触发。
- `if (!rst_n)`：复位优先，异步清零。
- 综合结果：带异步复位端的 D 触发器。<span class="marginnote">异步复位的写法要点：<strong>复位信号必须出现在敏感列表里（`or negedge rst_n`），才能综合成异步复位</strong>。若只在 `if` 里用复位而敏感列表只有 clk，综合出的是同步复位——两者行为不同，务必分清。现代设计常用异步复位 + 同步释放。</span>

## 2 阻塞赋值与非阻塞赋值

这是 Verilog 最重要的概念之一，两条铁律：

- **组合逻辑 always 用阻塞赋值 `=`**。
- **时序逻辑 always 用非阻塞赋值 `<=`**。

**阻塞赋值 `=`**：赋值**立即**生效，语句按顺序执行（像 C 语言）。

```verilog
always @(*) begin
    y = a & b;   // 先算
    z = y | c;   // 用 y 的当前值
end
```

**非阻塞赋值 `<=`**：所有赋值在块结束时**同时**更新（像并行硬件）。

```verilog
always @(posedge clk) begin
    q1 <= d;      // 同时采入
    q2 <= q1;     // q2 用的是 q1 的旧值
end
```

**关键区别**：非阻塞赋值里，`q2 <= q1` 用的是**更新前**的 `q1`——这正好对应硬件的「同一时钟沿同时采样」行为。<span class="marginnote">为什么时序必须用 `<=`？因为硬件是并行的：<strong>同一时钟沿，所有触发器同时采样，用的是边沿前的值</strong>。`<=` 模拟的正是这个「同时取旧值」。若用 `=`，移位寄存器会变成「连锁更新」（一位传一位，像异步），行为与硬件不符。</span>

## 3 公式解析：阻塞/非阻塞的差异实例

用「移位寄存器」演示两种赋值的差异。目标是每拍把数据右移一位：`q[1] <= q[0]`、`q[0] <= d`。

**非阻塞写法（正确）**：

```verilog
always @(posedge clk) begin
    q[1] <= q[0];
    q[0] <= d;
end
```

**第一步，看非阻塞语义**：两条赋值同时用旧值——`q[1]` 得到旧 `q[0]`，`q[0]` 得到 `d`。**一次时钟沿完成整体移位**。

**阻塞写法（错误）**：

```verilog
always @(posedge clk) begin
    q[1] = q[0];   // 先更新 q[1]
    q[0] = d;      // 再更新 q[0]
end
```

**第二步，看阻塞语义**：`q[1] = q[0]` 先执行，用的是旧 q[0]；`q[0] = d` 后执行。看起来结果一样？——**不完全**。

**第三步，找差异**：若换成 `q[0] = d; q[1] = q[0];` 的顺序，阻塞写法里 `q[1]` 会得到**新的 q[0]（即 d）**——数据跳了一位！而非阻塞写法无论顺序如何都正确。

**第四步，结论**：**非阻塞赋值与书写顺序无关，阻塞赋值与顺序有关**——这就是「仿真 vs 硬件」差异的根源。工程规范：**时序 always 一律用 `<=`**。<span class="marginnote">一句话记牢：<strong>「时序用非阻塞，组合用阻塞；混合建模时，时序块里读组合块用 `=` 算、`<=` 存」</strong>。这条规范被写进所有 FPGA 设计指南，违反它是最常见的仿真-综合不一致来源。</span>

## 4 常用时序建模：计数器与寄存器

**同步计数器**（4 位加法计数）：

```verilog
always @(posedge clk) begin
    if (!rst_n)
        count <= 4'b0000;
    else if (en)
        count <= count + 1'b1;
end
```

- `count <= count + 1'b1`：每拍加 1（综合成计数器）。
- `en`：使能控制（暂停）。

**移位寄存器**（8 位，串入并出）：

```verilog
always @(posedge clk) begin
    if (!rst_n)
        q <= 8'b0;
    else
        q <= {q[6:0], d_in};   // 左移一位，最低位进新数据
end
```

**带使能的寄存器堆写入**：

```verilog
always @(posedge clk) begin
    if (we)
        mem[addr] <= data;   // 写使能时存入
end
```

<span class="marginnote">这些模板的共同点：<strong>`@(posedge clk)` + 非阻塞赋值 + if/else 控制</strong>。会写 D 触发器，就会写一切时序电路——计数器是「自增的 D 触发器」，寄存器堆是「按地址选中的 D 触发器组」。硬件的能力边界，由你会写哪些模板决定。</span>

## 5 时序建模的工程规范

- **一个 always 只描述一种逻辑**：时序 always 只做时序，组合 always 只做组合。
- **敏感列表**：时序用 `posedge clk`（加必要的异步复位），组合用 `@(*)`。
- **复位策略**：异步复位 + 同步释放是主流，复位信号进敏感列表。
- **避免锁存器**：时序块里 if 无 else 时保持（这是期望的——时序寄存器天然「保持」），但要明确。

**辨析｜易错点：** 时序块里 `if` 没有 `else` **不会**推断锁存器（因为寄存器本身会保持），这是与组合块的重要区别。但若你想「清零/置位」的默认行为，还是要写清楚——否则输出保持旧值，可能不是本意。

## 6 小结

- 时序建模黄金模板：`always @(posedge clk) q <= d;` → 边沿 D 触发器。
- **阻塞 `=`（组合、立即更新）vs 非阻塞 `<=`（时序、同时更新）**——时序一律用 `<=`。
- 非阻塞赋值的「同时取旧值」对应硬件的并行采样，与书写顺序无关。
- 计数器、移位寄存器、寄存器堆都是「D 触发器 + 控制」的变体。
- 异步复位要写进敏感列表；时序块 if 无 else 不推断锁存器。
