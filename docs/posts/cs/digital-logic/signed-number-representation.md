## 为什么从原码、反码、补码开始

前面两课解决了「怎么用 0/1 写一个非负的数」。但现实世界有一半的数是负的——温度、海拔、银行余额、坐标。于是数字电路面临一个棘手的问题：**一堆 0 和 1 怎么表达「负号」？** 直觉的第一反应是「用一位专门当符号」，这个朴素方案就是**原码**；但它在电路里极不友好。工程师们折腾出反码、补码，最终几乎全世界都收敛到**补码**——今天所有 CPU（x86、ARM、RISC-V）内部的整数全是补码。

这一课讲的就是这段「从直觉到最优」的收敛过程。它不只是一堆编码定义的罗列：**补码真正的价值，是让减法与加法共用同一套电路**——机器只需要一个加法器，就能完成加减乘除里最基础的加减。这个「用模运算化减为加」的思想，正是后面第四篇加法器、第十二篇 ALU 的设计基石。

## 1 问题：电路里没有「负号」

先看清难点。十进制里我们写 $-5$ 有专用的负号，但二进制信号只有两种电平，**没有第三个符号位「负号」可以用**。要表示负数，只能在 0/1 的排列里「借位」出来。

于是出现了一个根本约定：**用二进制位串的最高位作符号位**。规定 $0$ 表示正、$1$ 表示负，剩下的低位表示数值的绝对值。这叫**符号-数值表示**。但它立刻带来一个问题：既然绝对值相同的正负数只差一个符号位，那**「+0」和「-0」就成了两个不同的数**——同一个零被编码了两次。这个「冗余的零」会一路纠缠到反码，直到补码才解决。

- **原码（sign-magnitude / true form）**：最高位是符号位（0 正 1 负），其余位是绝对值的二进制。
- **反码（ones' complement）**：正数与正数原码相同；负数把原码的**每一位取反**（0 变 1、1 变 0）。
- **补码（two's complement）**：正数与正数原码相同；负数等于反码再加 1，即**「取反加一」**。

以 4 位为例，把 +5 与 -5 分别写成三种形式：

| 表示 | +5 | -5 | 0 的表示 |
| --- | --- | --- | --- |
| 原码 | 0101 | 1101 | 0000 与 1000（两个零） |
| 反码 | 0101 | 1010 | 0000 与 1111（两个零） |
| 补码 | 0101 | 1011 | 只有 0000（一个零） |

**重点：三个符号里，只有补码消灭了「双零」**，所以 4 位补码能表示 16 个数（-8~+7），而原码、反码各有 16 个编码却只表示 15 个数（因为 0 占了两份）。凭空多出一个数来，这是补码的第一个红利。

## 2 原码：直观，但加法器会「卡壳」

原码最符合人的直觉：符号位 + 绝对值，看编码几乎能「读」出数值。但它有一个致命缺陷——**做加法必须先判断符号**。

用原码算 $(-5) + (+3)$：符号不同，机器不能直接加绝对值。它得先比较 $|5| > |3|$，再决定结果是「$5-3=2$ 且取负号」。也就是说，**加法和减法被强行分成了两套逻辑，电路里得同时准备「加法器」和「比较器 + 减法器」**。这还不是最糟的——$(-5)+(-3)$ 还要处理「同负相加进位」的问题。原码把「符号」与「数值」焊死在同一个位串里，运算时必须频繁拆装，电路复杂、速度还慢。<span class="marginnote">历史上确有计算机用原码做算术，最著名的例子是 IBM 7090（1960 年代的大型机）。它的加减法要用一串微操作绕路，工程师们很快发现这不划算。今天原码主要残留在「浮点数的符号位」里——IEEE 754 规定浮点最高位就是符号位，因为浮点数的绝对值部分需要可比较大小，符号单独拎出来反而方便。</span>

## 3 反码：向补码过渡的一步

反码的念头是：**与其让符号位独立，不如让负数「镜像」正数**。+5 是 $0101$，那 -5 就把每一位翻过来成 $1010$。这样有个好处：**两个反码相加，可以丢开符号判断**，直接按普通二进制加，并把最高位产生的进位「循环加回最低位」（叫**循环进位 / end-around carry**）。

以 4 位反码算 $-5 + 3 = -2$：

$$
1010 + 0011 = 1101,\quad \text{无进位，直接得 } -2
$$

再算 $-5 + (-3) = -8$ 的边界：$1010 + 1100 = 1\,0110$，最高位进位 1，把它循环加回最低位得 $0110 + 0001 = 0111$？不对——这里进位 1 加回后是 $0110+1=0111$，表示 +7 而非 -8。可见反码的循环进位很绕，而且**双零问题依旧**（$0000$ 与 $1111$ 都表示 0）。<span class="marginnote">反码在历史上真实存在过：UNIVAC 1101、PDP-1、CDC 6600 等早期机器都用反码。循环进位让加法器多了一条「进位回绕」的连线，电路实现比补码麻烦，后来被淘汰。但「化负为取反」这一步的思想没有浪费——补码就是「反码 + 1」。</span>

**辨析｜易错点：** 很多人把「取反」理解成「把负号去掉」。其实取反是**逐位翻转每一位**（bitwise NOT），不是「去绝对值」。$-5$ 的反码是 $1010$，你把它当无符号数看是 10、当反码看是 -5——**同一个位串在不同「解释」下数值不同**，这正是符号表示的本质：编码是死的，解释是活的。

## 4 补码：把减法变成加法

补码的定义可以一句话说完：**$n$ 位补码的负数 $-x$（$x>0$）编码为「$x$ 的二进制按位取反再加 1」，即 $2^n - x$ 的二进制表示。** 它带来两个决定性优点：

**第一，只有一个零。** $0000$ 取反是 $1111$，加 1 进位回环成 $0000$——负零和正零是同一个编码，双零消失。

**第二，减法变成加法。** 这是补码的灵魂。在 4 位补码里算 $3 - 5 = -2$，机器不做任何减法，只算：

$$
0011 + 1011 = 1110 = (-2)_{\text{补}}
$$

其中 $1011$ 正是 $+5$ 的补码 $-5$。**加一个负数 = 减一个正数，于是减法器可以整个删掉，只留加法器。** 你的电脑里没有「减法电路」，所有减法都是加法器用补码完成的——这是「从极限到大模型」里每一台机器共同的设计底色。

4 位补码的完整分布可以画成一个「数值环」——把数轴 $-8$ 到 $+7$ 首尾相接：沿顺时针加 1，走到 $+7$ 再走一步就落到 $-8$，符号位翻转，这就是**溢出**。

![四位二进制补码的数值环](/images/digital-logic/signed-number-representation-1.svg)

**重点：补码是「模 $2^n$」的算术。** 4 位补码的每一位运算都在模 16 的世界里发生，所以 $+7$ 加 $1$ 在模 16 下等于 $8$，而这个 $8$ 的 4 位编码是 $1000$，按补码解释恰是 $-8$。**溢出不是算错了「模运算」，而是结果超出了「有符号解释」的合法范围**——同一个 $1000$，无符号解释是 8，有符号解释是 -8，解释方式不同而已。

## 5 公式解析：补码为什么是「取反加一」

「取反加一」四个字背得再熟，不如知道它从哪来。设 $n$ 位二进制，模 $M = 2^n$。$n$ 位补码的本质定义是：

$$
[x]_{\text{补}} = (x \bmod M) = \begin{cases} x, & 0 \le x < 2^{n-1} \\ M + x, & -2^{n-1} \le x < 0 \end{cases}
$$

对负数 $-x$（$x>0$），$[\,-x\,]_{\text{补}} = M - x$。下面三步把它变成电路上能直接做的操作：

- **第一步，利用 $M - 1 = 111\cdots1$**（$n$ 位全是 1），改写 $M - x$：

$$M - x = (M - 1) - x + 1$$

- **第二步，看穿 $(M-1) - x$ 是什么**：$M-1$ 每位都是 1，用它减 $x$，从最低位开始 $1-0=1$、$1-1=0$——**恰好把 $x$ 的每一位取反**（这就是按位 NOT）。于是：

$$(M-1) - x = \overline{x} \quad\Longrightarrow\quad M - x = \overline{x} + 1$$

**「取反再加 1」不是巧合，而是「凑模」的必然结果。** 一个数加上它的补码：$x + (\overline{x}+1) = x + (M - x) = M$，模 $M$ 下等于 0，所以 $\overline{x}+1$ 就是 $x$ 的加法逆元——这就是为什么它能当 $-x$ 用。

- **第三步，证明减法化加法**：对任意整数 $x, y$，在模 $M$ 下

$$[\,x - y\,]_{\text{补}} = (x - y) \bmod M = \bigl(x + (M - y)\bigr) \bmod M = [x]_{\text{补}} + [\,-y\,]_{\text{补}}$$

因为模运算对加法分配，**减一个数等于加上它的补码，天然成立**。这是整篇课文的题眼。

- **第四步，溢出判定**：补码运算何时出错？结果超出 $[-2^{n-1},\, 2^{n-1}-1]$ 时。工程判据一句话：**两正相加得负、或两负相加得正，即为溢出**；等价地，看最高位的**进位输入与进位输出是否不同**（不同则溢出）。<span class="marginnote">「进位」和「溢出」是两回事：无符号加法里最高位进位是正常的（比如 $8+8=16$，溢出到第 5 位）；有符号加法里最高位进位却可能无害（$-1 + 1 = 0$，无进位）。真正危险的是符号位被「吃掉」——进位输入输出不一致。这个辨析在《计算机组成原理》的 ALU 设计里是常考点。</span>

## 6 补码的溢出：一个具体例子

用 4 位补码算 $7 + 1$：

$$
0111 + 0001 = 1000
$$

$0111$ 是 $+7$，$0001$ 是 $+1$，和 $1000$ 在补码里是 $-8$。**两个正数相加得到一个负数——这明显错了**，因为 $+7$ 和 $+1$ 都在合法范围内，但 $+8$ 超出了 4 位补码的最大值 $+7$。这就是图里箭头标注的：沿顺时针从 $+7$ 跨过虚线跳到 $-8$，符号位翻转。**溢出时机器不会「自动喊停」**——硬件只是把模 16 的结果如实算给你，是否溢出由专门的标志位（如 $+7$）报告，由程序（或你）来判断。这正是浮点数、整数溢出漏洞（比如经典的游戏里生命值变负数）在底层发生的原因。

## 7 Verilog 里如何用补码

硬件描述语言里，补码被内置进 `signed` 类型。声明为有符号后，Verilog 自动按补码解释，加减法直接写符号：

```verilog
reg signed [7:0] a, b, sum;
assign sum = a - b;      // 减法：底层就是 a + (~b + 1)
```

减法 `a - b` 综合出的电路并不是「减法器」，而是一个加法器对 `b` 先取反加一。**看到 `signed` 就想到补码，看到减法就想到「加补码」**——把这两条翻译成肌肉记忆，读任何硬件的算术电路都不再困惑。

## 8 小结

- **原码** = 符号位 + 绝对值，直观但**有两个零**，加减法需要先判断符号，电路复杂。
- **反码** = 负数对原码逐位取反，仍**有两个零**，且需要**循环进位**。
- **补码** = 负数「取反加一」，即 $M-x$；**只有一个零**，表示范围比原码/反码多一个 $-2^{n-1}$。
- **补码的灵魂是模 $2^n$ 运算**：减法 = 加补码，于是电路只需加法器。
- **溢出 ≠ 进位**：溢出发生在符号位翻转（如 $+7+1 \to -8$），判据是两同号相加结果异号，或最高位进位输入输出不同。
- 硬件描述语言里 `signed` 类型即补码，减法在底层就是「a + b 的补码」。

在下一节，我们将处理「如何用二进制表示十进制以外的信息」——数字世界里不只 0~9 需要编码，字母、符号、十进制每一位本身也需要约定。BCD 码、格雷码、ASCII 码与奇偶校验码，那是《常用编码》一课的舞台。
