## 为什么从指令译码开始

取指拿到了 32 位「原始指令」，但它是什么意思？**指令编码**定义了「这 32 位怎么拆」——哪几位是操作码、哪几位是寄存器号、哪几位是立即数；**指令译码**把指令拆开并翻译成**控制信号**，驱动 ALU、寄存器堆、存储器工作。<span class="marginnote">指令就是「硬件能读的机器语言」：<strong>一条指令 = 一个编码好的命令</strong>，CPU 用译码器把它翻译成一串控制信号。指令编码格式（Instruction Set Architecture, ISA）是软件与硬件的「契约」——编译器生成它，CPU 执行它。</span>这一节设计一个小指令集，并实现它的译码器。

## 1 指令编码：把「做什么」编码成位

一个最小指令集（简化 RISC）的指令格式，用 32 位编码。以 RISC-V 风格的 R 型（寄存器-寄存器）指令为例：

```
31        25 24     20 19     15 14     12 11       7 6      0
+----------+---------+---------+---------+----------+---------+
| funct7   |  rs2    |  rs1    | funct3  |   rd     | opcode  |
| 7 位     | 5 位    | 5 位    | 3 位    |  5 位    | 7 位    |
+----------+---------+---------+---------+----------+---------+
```

- **opcode**（操作码）：指令类型（如 0110011 = 运算类）。
- **rd**：目标寄存器号（结果写哪）。
- **rs1、rs2**：源寄存器号（操作数从哪读）。
- **funct3、funct7**：具体功能（如加/减/与/或）。

**I 型指令**（带立即数）在此基础上把 rs2 换成立即数低 12 位。

**为什么这样编码**：寄存器号固定 5 位（32 个寄存器）、操作码固定位置——**译码器可以直接按位拆，无需查找表**。这就是 RISC 指令「规整」的价值。<span class="marginnote">指令编码的设计原则：<strong>「规整即硬件简单」</strong>——字段位置固定，译码就是「按位切 + 查 opcode」。RISC-V 的 opcode、rd、rs1、rs2、funct3 位置在所有指令里都一致，这让译码器极简，也让流水线（第十二篇延伸）更容易实现。对比 x86 的可变长指令，译码复杂度天差地别。</span>

## 2 指令译码：从指令到位信号

**译码器**把指令的 opcode + funct 字段翻译成控制信号。一个最小译码器：

```verilog
module decoder(
    input  [31:0] instr,
    output reg        reg_write,   // 写寄存器使能
    output reg        alu_src,     // ALU 第二操作数：寄存器 or 立即数
    output reg [3:0]  alu_op,      // ALU 功能选择
    output reg        mem_read, mem_write,
    output reg        branch, jump
);
    wire [6:0] opcode = instr[6:0];
    wire [2:0] funct3 = instr[14:12];

    always @(*) begin
        // 默认值
        reg_write = 0; alu_src = 0; alu_op = 4'b0000;
        mem_read = 0; mem_write = 0; branch = 0; jump = 0;
        case (opcode)
            7'b0110011: begin        // R 型：寄存器运算
                reg_write = 1; alu_src = 0;
                alu_op = {instr[30], instr[14:12]};  // 从 funct 生成
            end
            7'b0010011: begin        // I 型：立即数运算
                reg_write = 1; alu_src = 1; alu_op = {1'b0, funct3};
            end
            7'b0000011: begin        // load
                reg_write = 1; alu_src = 1; mem_read = 1;
            end
            7'b0100011: begin        // store
                mem_write = 1; alu_src = 1;
            end
            7'b1100011: begin        // branch
                branch = 1; alu_op = {1'b0, funct3};
            end
            default: ;               // 未知指令
        endcase
    end
endmodule
```

<span class="marginnote">译码器的关键习惯：<strong>「先给默认值，再按 opcode 覆盖」</strong>——这既是防锁存器（组合 always），也是「未列出的控制信号默认关断」的安全策略。译码器输出的是「指挥信号」：`reg_write` 决定要不要写寄存器，`alu_src` 决定 ALU 第二操作数来源，`alu_op` 决定 ALU 干什么——这些信号合起来就是 CPU 的「命令」。</span>

## 3 公式解析：译码器 → 控制信号 → 硬件

译码器的输出如何驱动硬件？用 `add r3, r1, r2` 走一遍：

**第一步，取指**：得到指令 `0000000_00010_00001_000_00011_0110011`。

**第二步，拆字段**：
- opcode = `0110011`（R 型运算）。
- rs1 = `00001`（寄存器 1），rs2 = `00010`（寄存器 2），rd = `00011`（寄存器 3）。
- funct7/funct3 = 加法的编码。

**第三步，译码产生控制信号**：`reg_write=1`、`alu_src=0`（用寄存器）、`alu_op=加法`、`mem_read/write=0`。

**第四步，驱动数据通路**：
- 寄存器堆读 rs1、rs2 → ALU 两个操作数。
- ALU 执行加法 → 结果送到寄存器堆写端口。
- 写使能打开 → 结果写入 rd（寄存器 3）。

**一条指令 = 一组合适的控制信号**，指令的「语义」被译码器翻译成了硬件的「动作」。<span class="marginnote">「译码 = 把语义翻译成控制」是 CPU 的心脏：<strong>指令集定义了「指令 → 控制信号」的映射，译码器就是这张映射的硬件实现</strong>。RISC 的优势在此凸显——字段规整，译码器就是 case 语句 + 位提取，逻辑极简。</span>

## 4 控制信号的完整集合

一个最小 CPU 需要的控制信号：

| 控制信号 | 作用 |
|---|---|
| `reg_write` | 写寄存器堆使能 |
| `alu_src` | ALU 第二操作数：寄存器/立即数 |
| `alu_op` | ALU 功能选择 |
| `mem_read` | 读数据存储器使能 |
| `mem_write` | 写数据存储器使能 |
| `branch` | 分支指令标志 |
| `jump` | 跳转指令标志 |
| `mem_to_reg` | 写回数据来源：ALU 结果/内存数据 |

这些信号从译码器发出，广播到数据通路的各个部件——它们是 CPU 的「命令总线」。<span class="marginnote">控制信号的数量与粒度体现了 CPU 的「复杂程度」：<strong>最小 CPU 十个信号以内，现代 CPU 几百个</strong>（微码、乱序控制）。但本质相同——把指令翻译成「该做什么」的动作序列。下一节「硬布线 vs 微程序」讲的就是怎么产生这些控制信号。</span>

## 5 从译码到执行：指令的完整旅程

一条指令的完整旅程（非流水线）：

1. **取指**：PC → 指令存储器 → IR。
2. **译码**：IR → 译码器 → 控制信号 + 读寄存器堆。
3. **执行**：ALU 计算 / 访存 / 分支判断。
4. **写回**：结果写寄存器。

每一拍完成一条指令。这个「取指-译码-执行-写回」循环，将在下一节由**控制器**（硬布线/微程序）统一指挥。译码器是循环的「翻译官」——它让 CPU 理解每一条指令。<span class="marginnote">回顾这一篇的拼图：<strong>ALU（会算）、寄存器堆（会存）、取指（会读程序）、译码（会翻译指令）</strong>——还差一个「总指挥」（控制器）和「总连接」（数据通路）。下一节就把指挥权装上。</span>

## 6 小结

- **指令编码**：操作码 + 寄存器号 + funct 等字段，按固定位置编码（RISC 规整）。
- **指令译码**：按位拆字段 + 查 opcode，翻译成控制信号（reg_write、alu_src、alu_op…）。
- 译码器是「指令 → 控制信号」映射的硬件实现；case + 位提取即可。
- 一条指令 = 一组合适的控制信号，驱动 ALU/寄存器/存储器协同工作。
- 完整旅程：取指 → 译码 → 执行 → 写回，译码是理解指令的「翻译官」。
