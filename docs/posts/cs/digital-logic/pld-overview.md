## 为什么从 PLD 开始

前面我们用的都是「固定功能」器件：74LS 系列的门、译码器、计数器，出厂定型。**可编程逻辑器件（PLD, Programmable Logic Device）**则相反——芯片出厂时逻辑是「空」的，由用户通过编程决定它干什么。这彻底改变了数字设计：从「搭电路」变成「写逻辑」。<span class="marginnote">PLD 的历史地位：<strong>它是「硬件软化的起点」</strong>——一块 PLD 可以代替几十块 74LS 芯片，且改逻辑只需重新编程、无需改板。从 PROM（可编程只读）、PLA、PAL、GAL，到 CPLD、FPGA，一条「可编程能力越来越强」的演进线贯穿至今。</span>这一节搭出 PLD 的整体框架与基本结构。

## 1 为什么需要 PLD：固定逻辑的局限

固定逻辑（SSI/MSI）芯片有三个痛点：

**集成度低**：几十个门就要一堆芯片，板面积大、可靠性差。
**不灵活**：改一个逻辑功能就要换芯片、改电路板。
**设计周期长**：从需求到成品板要经历设计、制板、焊接、调试。

PLD 的回应：

**高集成**：一块芯片容纳几百到几百万个逻辑单元。
**可重配**：改逻辑 = 重新编程（或重下载配置），板子不动。
**快速迭代**：仿真验证通过后直接下载，设计周期从周缩到小时。

<span class="marginnote">PLD 的思想源头是「<strong>把通用的结构预埋进芯片，用配置决定用途</strong>」——这与软件里「用数据驱动逻辑」异曲同工。今天的 FPGA 能实现 CPU、能重配为 AI 加速器，都是这个思想的极致。</span>

## 2 PLD 的基本结构：与阵列 + 或阵列

几乎所有 PLD 的基本结构都可以抽象为**两级与-或结构**：

1. **输入缓冲**：输入变量及其反变量（提供原变量/反变量）。
2. **与阵列（AND array）**：产生乘积项。
3. **或阵列（OR array）**：把乘积项相加，产生输出。
4. **输出电路**：可编程的输出极性、寄存器等。

逻辑函数的标准与-或式 $Y = \sum(\text{乘积项})$，正好对应「与阵列生成乘积项、或阵列求和」——**PLD 的两级结构与逻辑代数的与-或式天然对应**。<span class="marginnote">为什么是「与-或」两级？因为任何组合逻辑都能写成与-或式（最小项之和）。<strong>PLD 用硬件实现这个标准形式：与阵列做「与」，或阵列做「或」</strong>。PLA、PAL、GAL 的差别，就在这两个阵列「哪个可编程」。</span>

## 3 PLD 家族谱系：一张分类图

按结构与可编程能力，PLD 家族分四代：

| 器件 | 与阵列 | 或阵列 | 特点 |
|---|---|---|---|
| PROM | 固定（全译码） | 可编程 | 最早，实质是译码器+可编程或阵列 |
| PLA | 可编程 | 可编程 | 最灵活，但速度慢、工具复杂 |
| PAL | 可编程 | 固定 | 速度快、简单，经典器件 |
| GAL | 可编程 | 固定（可配置输出） | PAL 的改进，可重复编程 |
| CPLD | 多个 PAL 块 + 互连 | — | 高集成、可预测延迟 |
| FPGA | 查找表（LUT）+ 互连 | — | 最灵活、海量逻辑 |

<span class="marginnote">演进主线：<strong>从「部分可编程」到「全部可编程」，从「与或两级」到「LUT + 互连」</strong>。PROM/PLA/PAL/GAL 是「经典 PLD」，CPLD 是 PAL 的规模化，FPGA 则是「查表实现一切」的现代形态。理解经典 PLD，才能看懂 FPGA 为何那样设计。</span>

## 4 公式解析：与-或结构与逻辑式的对应

用一道题展示「PLD 结构 ↔ 逻辑式」的翻译。设函数：

$$Y = AB + \overline{A}C + BC$$

**第一步，识别乘积项**：三个与项 $AB$、$\overline{A}C$、$BC$——与阵列要能产生这三个乘积项。

**第二步，识别求和**：三个与项相加——或阵列要把它们或起来。

**第三步，映射到 PLD**：
- 输入变量 $A,B,C$ 及其反变量进入与阵列。
- 与阵列中，每行对应一个乘积项（用熔丝/配置决定是否包含某变量）。
- 或阵列把乘积项相加，输出 $Y$。

**第四步，观察规模**：要产生 $P$ 个乘积项，与阵列要有 $P$ 行；$P$ 是 PLD 的**关键资源指标**（PAL 的「乘积项数」）。<span class="marginnote">PLD 的能力瓶颈往往是「<strong>乘积项不够用</strong>」——化简逻辑式、减少乘积项，就是在省 PLD 资源。这就是为什么第二篇的卡诺图化简在 PLD 时代依然重要：化简不仅是省门，更是省 PLD 的乘积项。</span>

## 5 PLD 的设计流程概述

PLD 的使用已经「软件化」：

1. **设计输入**：原理图或硬件描述语言（HDL，如 Verilog——第十一篇）。
2. **综合**：把 HDL 翻译成逻辑网表（与-或式/查找表）。
3. **适配（布局布线）**：把网表映射到具体 PLD 的阵列/互连上。
4. **编程/配置**：生成位流文件，下载到芯片。
5. **验证**：仿真与硬件测试。

这个流程与软件编译惊人地相似——**「写代码 → 编译 → 运行」的软件开发范式，被完整搬进了硬件设计**。<span class="marginnote">PLD 让硬件设计师第一次像程序员一样工作：<strong>用 HDL 描述逻辑、用工具综合布局、下载即生效</strong>。这个范式的集大成者是 FPGA + Verilog/VHDL——第十二篇「从逻辑门到 CPU」里，我们将亲手用这个流程搭出一台 CPU。</span>

## 6 PLD 与 ASIC 的对比

PLD 不是数字设计的唯一归宿，与 ASIC（专用集成电路）对比，能看清 PLD 的位置：

| 对比 | PLD（FPGA/CPLD） | ASIC |
| --- | --- | --- |
| 定制方式 | 现场编程/配置 | 制造时定制 |
| 设计周期 | 短（小时~天） | 长（月~年） |
| 流片成本 | 无（买现成芯片） | 极高（百万级起） |
| 批量单价 | 较高 | 大批量很低 |
| 性能/功耗 | 较差（可编程开销） | 最优（定制电路） |
| 修改灵活性 | 高（重配置即可） | 无（流片后改不了） |
| 适用 | 小批量、原型、灵活 | 大批量、高性能 |

**演进关系**：**FPGA 常作为 ASIC 的原型**——先 FPGA 验证功能，再流片 ASIC 量产。也可「先 ASIC 太贵、FPGA 性能够用」直接用 FPGA。

**为什么大公司用 ASIC、小产品用 FPGA**：ASIC 的流片成本摊到百万片才划算；FPGA 的单价高但无一次性成本——「量决定选型」。

**PLD 设计的本质**：用 HDL 写逻辑 → 综合映射到 LUT/乘积项 → 布局布线 → 配置。这一整套流程与 ASIC 设计的前端（HDL → 综合 → 时序分析）**几乎完全一样**——学 FPGA 就是学数字设计的前端方法论，换到 ASIC 只是后端不同。

**从「从极限到大模型」的视角**：GPU 是 ASIC（大规模定制），FPGA 加速卡是 PLD——大模型推理硬件里两者并存。理解 PLD，就理解了「可编程硬件」这半边天。

**辨析｜易错点：** 「PLD 比 ASIC 慢」是普遍但非绝对——性能差距来自「可编程开销」（互连开关、LUT 查表），设计得好可以把差距缩小。选型时用「性能 × 成本 × 周期」三维判断，别只盯单点。

## 7 小结

- PLD 解决固定逻辑的痛点：集成度、灵活性、迭代速度。
- 基本结构：**输入缓冲 + 与阵列 + 或阵列 + 输出电路**，对应逻辑代数与-或式。
- 家族谱系：PROM → PLA → PAL/GAL → CPLD → FPGA，可编程能力渐强。
- 乘积项是 PLD 关键资源，化简逻辑式 = 省乘积项。
- 设计流程已软件化：HDL → 综合 → 适配 → 编程 → 验证。
