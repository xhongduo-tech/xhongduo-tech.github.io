## 为什么从常用编码开始

前三课都在回答「怎么用 0/1 表示数」。但数字电路面对的世界远不止数：键盘上的字母 `A`、屏幕上的符号 `$`、十进制显示器的每一位「7」、甚至「这份数据传过去有没有出错」，都需要用 0/1 来表达。**把现实世界的符号翻译成二进制位串的那张「约定表」，就是编码（code）。** 编码是「从二进制回到现实」的桥梁，也是通信可靠性问题的第一道防线。

这一课是数制章的收尾，也是后面很多课的「预习材料」：BCD 码会在第十篇 A/D 转换里出现（十进制显示），格雷码会在《计算机组成原理》的异步 FIFO 与《嵌入式》的旋转编码器里出现，奇偶校验则是一切纠错码的起点。**它们共享同一个灵魂：编码是「约定」，约定合理与否，取决于你用它干什么。**

## 1 为什么不能直接用二进制编码一切

最朴素的想法是：一个字母不就是个数吗？给它编个号存进去不就行了。这没错——**任何符号集合，只要能与一个正整数集合一一对应，就能用二进制表示**。ASCII 正是这么干的。但「能编码」和「编码得合适」是两回事：

- **可读性**：二进制位串难读，人类需要十六进制、需要「把一位十进制数字单独编码」的 BCD。
- **抗噪性**：编码位串如果相邻值相差多位，传输中一位翻转可能变成「完全不同的值」，于是需要让相邻编码只差一位的格雷码。
- **检错性**：传输会出错，编码需要留出「冗余」来判断对错，于是有了奇偶校验。

**编码设计的核心权衡，就是在这三件事之间做取舍**：每一位都是钱，多一位冗余就多一份可靠性，也就多一份成本。下面四种编码分别对应这四种不同的取舍。

## 2 BCD 码：用二进制表示「十进制的一位」

**二进制编码的十进制（Binary Coded Decimal，BCD）**：用 4 位二进制给 0~9 这十个十进制数字分别编码。最常用的是 **8421 BCD 码**——4 位的位权从上到下恰是 8、4、2、1，所以它就是「把十进制的每一位单独用二进制写出来」。

| 十进制 | 8421 BCD | 2421 BCD | 余3码 |
| --- | --- | --- | --- |
| 0 | 0000 | 0000 | 0011 |
| 1 | 0001 | 0001 | 0100 |
| 2 | 0010 | 0010 | 0101 |
| 3 | 0011 | 0011 | 0110 |
| 4 | 0100 | 0100 | 0111 |
| 5 | 0101 | 1011 | 1000 |
| 6 | 0110 | 1100 | 1001 |
| 7 | 0111 | 1101 | 1010 |
| 8 | 1000 | 1110 | 1011 |
| 9 | 1001 | 1111 | 1100 |

例如 $549_{10}$ 写成 8421 BCD 是 `0101 0100 1001`——**每一位十进制数字各占 4 位，数位之间是独立的**。这正是 BCD 与「真二进制」的区别：真二进制把整个 549 一起编码成 `10 0010 0101`，而 BCD 把每一位分开编。<span class="marginnote">为什么十进制显示器不用真二进制而用 BCD？因为一个十进制位 = 4 个 LED 段，如果直接用二进制，硬件译码器要处理 0~15 的映射；BCD 把 0~9 单独编码，1010~1111 这六个码直接判为「无效」，译码逻辑大大简化。今天的计算器、电表、停车场电子屏，内部仍是 BCD 的天下。</span>

**重点：8421 BCD 的 1010~1111 六个编码是「无效码」**，因为 4 位二进制本可以表示 16 个值，BCD 只用其中 10 个。硬件遇到无效码要能正确处理（通常当输入非法处理）。另外 BCD 的加法有坑：$9 + 1 = 10$ 在 BCD 里要写成 `1001 + 0001 = 1010`，可 $1010$ 不是合法 BCD，必须「加 6 修正」成 `0001 0000`——这个修正电路我们在第四篇加法器里会专门处理。

2421 BCD 与余 3 码的出现，是为了解决另一个问题：**让 9 的补数恰好是码的按位取反**。比如余 3 码里 4 是 `0111`，取反得 `1000` 恰是 5 的余 3 码——**自补（self-complementing）**，这让「9 减某数」这类十进制运算可以直接靠取反完成。<span class="marginnote">余 3 码 = 8421 码 + 3，故意把码「偏移」3 个，避开 0000~0010 这几个在早期电传设备里没有信号的码。2421 码的权重不对称（2、4、2、1），所以 5 的编码有两个选择（0101 或 1011），表里取的是「最高位为 1」的那种，以保证自补性。</span>

## 3 格雷码：相邻值只差一位

再看一个完全不同思路的编码。**格雷码（Gray code）**：让**相邻的两个数值，其码位串只差 1 位**（叫「单位距离」或 Hamming 距离为 1）。4 位格雷码从 0 到 15：

```
0000, 0001, 0011, 0010, 0110, 0111, 0101, 0100,
1100, 1101, 1111, 1110, 1010, 1011, 1001, 1000
```

注意相邻码之间**只有一位翻转**：`0011` → `0010`（变了最低位），`0111` → `0101`（变了第三位）。这有什么用？**在一个「数值连续变化」的物理系统里，格雷码可以避免「多位同时翻转时的瞬间歧义」。**

经典场景是旋转编码器：一个转盘上刻着码道，旋转时码盘在变化。如果用的是二进制，从 `0111`（7）变到 `1000`（8）要同时翻 4 位，如果机械安装有偏差，读出的瞬时值可能是 `1111`、`0000`、`1000` 里任何一个——**一个错误漂移就产生了极大的错误读数**。而用格雷码，从 7 变到 8 只需翻一位，误差最多是「差一个最小步进」。<span class="marginnote">格雷码是弗兰克·格雷（Frank Gray）1953 年在贝尔实验室申请专利的，本意就是用在脉冲编码调制（PCM）的传输系统里。今天它在工程上最常见的两个去处：机械/光电编码器的位置读数，以及 CPU 异步跨时钟域传输时的「格雷码同步器」——数据没就绪时位串翻转一位最多导致「读到旧值」，不会产生完全错误的跳变，这在《计算机组成原理》异步 FIFO 设计里是标准技巧。</span>

格雷码的构造有一个漂亮的规律，叫**镜像反射法**：$n$ 位格雷码可以由 $n-1$ 位格雷码「上面照抄、下面镜像加前缀 1」递归造出——这也是「反射码（reflected code）」这个名字的来历。从 1 位 `0, 1` 出发，2 位是 `00, 01, 11, 10`（上半照抄 `0,1`，下半镜像成 `1,0` 再在前面加 `1`）。

## 4 公式解析：二进制与格雷码互转的异或公式

格雷码最漂亮的地方，是它与二进制之间有一条**纯异或的换算公式**。设 4 位二进制 $B = B_3B_2B_1B_0$，对应格雷码 $G = G_3G_2G_1G_0$：

$$
G_3 = B_3,\qquad G_2 = B_3 \oplus B_2,\qquad G_1 = B_2 \oplus B_1,\qquad G_0 = B_1 \oplus B_0
$$

通式写作 $G_i = B_i \oplus B_{i+1}$（最高位约定 $B_n = 0$）。以 $B = 0110$（十进制 6）为例做三步拆解：

- **第一步，写公式的直觉**：二进制转格雷码 = **逐位与「右边一位」异或**。为什么这样能保证相邻码只差一位？因为「进位」这件事在二进制里是连锁的：$0110 \to 0111$ 只有最低位变，$0111 \to 1000$ 却四位全变。异或把「每一位和它右边一位比」，恰好把「连锁进位」的信息压缩进格雷码，使得加 1 时只有出现进位的那一段变 1 位。
- **第二步，代入算一遍**：

$$
G_3 = B_3 = 0,\quad G_2 = 0 \oplus 1 = 1,\quad G_1 = 1 \oplus 1 = 0,\quad G_0 = 1 \oplus 0 = 1
$$

得 $G = 0101$。查上一节的格雷码表，十进制 6 的格雷码正是 `0101`，对上。

- **第三步，反向公式**：格雷码转二进制是它的「镜像」——从最高位一路向右累加：

$$
B_3 = G_3,\qquad B_2 = G_2 \oplus B_3,\qquad B_1 = G_1 \oplus B_2,\qquad B_0 = G_0 \oplus B_1
$$

以 $G = 0101$ 回推：$B_3 = 0$，$B_2 = 1 \oplus 0 = 1$，$B_1 = 0 \oplus 1 = 1$，$B_0 = 1 \oplus 1 = 0$，得 $B = 0110$，正好转回来了。**两个方向都是纯异或，硬件里一组异或门就能完成换算**——这也是格雷码常被直接接在译码器前面的原因。Verilog 里一整行就能写：

```verilog
// 二进制 → 格雷码：逐位与右移一位异或
assign gray = bin ^ (bin >> 1);

// 格雷码 → 二进制：从最高位向右逐位累加
assign bin[3]   = gray[3];
assign bin[2]   = bin[3] ^ gray[2];
assign bin[1]   = bin[2] ^ gray[1];
assign bin[0]   = bin[1] ^ gray[0];
```

## 5 ASCII 码：把字母与符号编成 7 位

编码不只是给数用的，还要给字符用。**美国信息交换标准代码（American Standard Code for Information Interchange，ASCII）**用 7 位二进制给 128 个字符编码：大小写字母、数字、标点、控制符各就各位。<span class="marginnote">ASCII 是 1963 年由美国国家标准协会（ASA，即后来的 ANSI）标准化、1968 年修订成我们现在用的样子，前身可追溯到更早的电传电报代码。今天你在任何文本文件里看到的英文字符，底层都是 ASCII 或它的扩展。</span>

| 十进制 | 十六进制 | 二进制 | 字符 |
| --- | --- | --- | --- |
| 48 | 0x30 | 011 0000 | '0' |
| 65 | 0x41 | 100 0001 | 'A' |
| 66 | 0x42 | 100 0010 | 'B' |
| 97 | 0x61 | 110 0001 | 'a' |
| 122 | 0x7A | 111 1010 | 'z' |

几个值得背的锚点：`'0'` = 48、`'A'` = 65、`'a'` = 97，**大小写字母恰好相差 32**（即第 5 位不同），所以「大写转小写」在电路或程序里就是「把第 5 位置 1」一次位运算的事。7 位够用，但现代存储普遍按 8 位（1 字节）处理，于是有了各种 8 位扩展；中文则超出 ASCII，需要 GBK、UTF-8 等多字节编码——那是第五级《编程语言》与《计算机网络》的话题。

## 6 奇偶校验码：给数据加一位「把关」

传输和存储都会出错——一位 0 被读成 1。怎么发现？**在数据位之外附加一位校验位，使整串 1 的个数满足某个约定**，这叫**奇偶校验（parity check）**。

- **偶校验（even parity）**：附加校验位 $P$，使 $P \oplus b_{n-1} \oplus \cdots \oplus b_0 = 0$，即**含校验位在内，1 的个数为偶数**。
- **奇校验（odd parity）**：同理使 1 的个数为奇数。

例如数据 `1011`（3 个 1，奇数个）做偶校验：要补成偶数个 1，校验位取 $P = 1$，得到 `11011`（4 个 1）。接收方收到后重新数一遍 1 的个数，**若约定偶校验却数出奇数个，就说明传输出了错**。<span class="marginnote">海明距离的视角：数据码的码间距离是 1，加了 1 位奇偶校验后，所有合法码的 Hamming 距离变成至少 2——于是一位翻转必然落到「非法码」上，可以被发现。若想「发现并纠正」一位错，需要距离 ≥ 3，那就是海明码（Hamming code）的领地，它在网络传输（如 ECC 内存）里至今活跃——也呼应本课开头的海明引言。</span>

**辨析｜易错点：奇偶校验只能「检错」不能「纠错」，而且只能检测「奇数个」错误。** 两个比特同时翻转，1 的个数奇偶性不变，校验就漏检了。它没有能力告诉你「错在哪一位」，所以只能「发现异常、请求重传」，不能「当场改正」。**它是最便宜的一道保险**——每字节只多 1 位，代价极低，所以至今用于串口、UART、内存 ECC 的基础结构里。真正能纠错的是海明码、CRC 这类更复杂的编码，那是《计算机网络》与《计算机组成原理》的后续内容。

## 7 小结

- **编码是「约定」**：每一位都是成本，编码设计的核心是在可读性、抗噪性、检错性之间取舍。
- **BCD 码**：4 位编一个十进制位；8421 BCD 直接对应十进制，1010~1111 是无效码；2421 码与余 3 码用于「自补」运算。
- **格雷码**：相邻数值码距为 1，用**镜像反射法**构造，用于旋转编码器与跨时钟域同步；与二进制互转是纯异或公式 $G_i = B_i \oplus B_{i+1}$。
- **ASCII 码**：7 位编 128 个字符，`'0'=48`、`'A'=65`、`'a'=97`，大小写相差 32。
- **奇偶校验**：附加 1 位使 1 的个数为偶/奇，能**检奇数位错、不能纠错**，是 Hamming 距离为 2 的检错码。
- 四种编码在 Verilog 里各有落点：BCD 用于十进制显示、格雷码一行 `assign` 互转、ASCII 是字符存储、奇偶校验位可用异或链生成。

到这里，本专题的第一篇《数制与码制》就收尾了——从「信号为什么是二值的」一路走到「如何把数、字母、可靠性都装进 0/1」。下一篇我们进入整本书的心脏：**逻辑代数基础**。从「用 0/1 表示信息」到「对 0/1 做运算」，与、或、非三种基本运算将把「布尔」这个名字和数字电路焊在一起，那是香农 1938 年完成的惊人之举。
