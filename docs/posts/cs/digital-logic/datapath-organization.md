## 为什么从数据通路开始

CPU 的零件齐了：ALU、寄存器堆、取指、译码、控制。**数据通路（datapath）**就是把这些零件「接起来」的骨架——数据在部件之间流动的路径。数据通路的组织方式决定了 CPU 的结构与性能。<span class="marginnote">数据通路 = 「<strong>部件 + 连线 + 多路选择器</strong>」。多路选择器在这里至关重要：同一个部件（如 ALU）的输入可能来自多个源，用 MUX 选择当前来源。控制信号就是「拨动这些 MUX 的开关」。</span>这一节讲两种数据通路组织：总线结构与单周期数据通路。

## 1 数据通路的两大流派

**① 单总线结构**：所有部件挂在一根（组）共享总线上，一个时钟最多传一个数据——简单省，但慢（总线是瓶颈）。

**② 多通路/专用通路结构**：各部件之间用专用连线直接相连，可并行传多个数据——快，但连线复杂。

现代 CPU 用**多通路**为主（并行度高），单总线常见于教学与极简设计。这一节重点讲**单周期数据通路**——它是经典教材（如《计算机组成与设计》Patterson）的标准模型。

<span class="marginnote">「单总线 vs 多通路」是「<strong>共享 vs 专用</strong>」的硬件权衡：总线省连线但一次只能传一个数据，专用通路费连线但可并行。CPU 性能差距，很大程度来自「一个周期能并行搬多少数据」——这正是数据通路组织的核心。</span>

## 2 单周期数据通路：一条指令一个周期

**单周期数据通路（single-cycle datapath）**：每条指令**在一个时钟周期内**完成取指、译码、执行、写回。它的结构：

```text
      ┌─────────── 控制单元 ───────────┐
      │          (译码器)             │
PC ──▶│指令存储器│──▶ 寄存器堆 ──▶ ALU ──▶ 数据存储器 ──▶ 写回
      │          ▲                    │
      └──────────┘                    └──▶ MUX（选择写回来源）
```

**关键元件**：

**PC 与指令存储器**：取指。
**寄存器堆**：读操作数、写结果。
**ALU**：运算。
**数据存储器**：load/store。
**多路选择器**：选择操作数来源（寄存器/立即数）、写回来源（ALU/内存）、分支地址。

**控制信号**：一条指令的所有控制信号**在一个周期内同时有效**——译码器输出全部就位，数据在组合逻辑里一路流过，周期末写入寄存器。<span class="marginnote">单周期的直觉：<strong>「一锤子买卖」</strong>——时钟上升沿启动，所有部件用组合逻辑算完，周期末把结果锁进寄存器（PC、寄存器堆、存储器）。所以单周期的时钟周期 = 最慢指令的全部路径延迟。</span>

## 3 单周期数据通路的信号流

以三种典型指令走一遍单周期数据通路的信号流：

**① R 型（add r3, r1, r2）**：

1. 取指：PC → 指令存储器 → 指令。
2. 读寄存器：rs1、rs2 → 寄存器堆 → 两个操作数。
3. 运算：操作数 → ALU → 结果。
4. 写回：结果 → 寄存器堆写端口（rd），reg_write=1。

**② I 型（addi r3, r1, 5）**：

1~2 同上（读 rs1）。
3. **选择立即数**：`alu_src = 1`，MUX 选立即数而非 rs2 作为 ALU 第二操作数。
4. 运算 + 写回。

**③ 分支（beq r1, r2, offset）**：

1~3 同上（ALU 计算 r1-r2）。
4. **判断分支**：ALU 结果是否为 0 → `zero` 标志。
5. **选择 PC**：`branch` 信号决定 PC 取「+4」还是「分支目标」。

每种指令就是「控制信号的一种组合」——**同一套数据通路，不同的控制信号，实现不同的指令**。<span class="marginnote">这是冯·诺依曼体系结构的精髓：<strong>一套硬件，通过控制信号的变化执行无限多种指令</strong>。数据通路是「身体」，控制信号是「意念」——同样的身体，不同的意念做不同的事。理解这一点，就理解了「可编程」的本质。</span>

## 4 公式解析：单周期时钟周期的计算

单周期 CPU 的时钟周期由**最慢指令的路径延迟**决定：

$$T_{clk} = t_{fetch} + t_{reg\_read} + t_{ALU} + t_{mem} + t_{reg\_write} + t_{setup}$$

**第一步，看路径**：一条指令从 PC 到写回寄存器，依次经过取指（读指令存储器）、读寄存器堆、ALU、访存（load）、写寄存器堆。

**第二步，看串行**：单周期内所有部件**串行**工作——一个时钟周期要容纳整条路径。

**第三步，看最慢**：load 指令路径最长（读指令 + 读寄存器 + ALU + 读内存 + 写寄存器），它的延迟就是 $T_{clk}$。

**第四步，看代价**：如果只有 1/3 的指令是 load，但时钟周期按 load 定——**大部分周期在「空等」**。这就是单周期慢的根本原因：**「周期按最坏情况定，好指令也被拖慢」**。<span class="marginnote">单周期的效率问题：<strong>「最长路径决定所有人的速度」</strong>——就像队列按最慢的人走。流水线（下一节的延伸）通过「把路径切段并行」，让不同指令不同部件同时工作，把吞吐率提上去。但单周期是理解一切数据通路的基础。</span>

## 5 从单周期到流水线：性能的下一步

单周期简单但慢，**流水线（pipeline）**把指令执行切成 5 段（取指/译码/执行/访存/写回），各段并行处理不同指令：

时钟周期 ≈ 最长一段的延迟（而非整条路径）。
吞吐率提升近 5 倍（理想）。
代价：流水线寄存器、冒险处理（数据冒险、控制冒险）。

现代 CPU 全部用流水线。但**单周期数据通路是流水线的基础**——理解了「一条指令怎么流过数据通路」，就理解了流水线每一段在干什么。<span class="marginnote">从「从极限到大模型」的视角：<strong>GPU 的数据通路是「大量并行 ALU + 统一取指」</strong>——同一套 SIMD 数据通路，靠控制信号执行向量指令。CPU 数据通路怎么组织，GPU 就怎么放大——理解单周期，是理解一切处理器微架构的起点。</span>

## 6 从单周期到多周期：另一种折中

单周期慢（周期长）、流水线复杂（冒险处理），中间还有一个**多周期数据通路**——把每条指令拆成多步，每步一个时钟周期。

**多周期设计**：

- 每条指令按「取指 → 译码 → 执行 → 访存 → 写回」分多拍执行。
- 各部件**分时复用**：一个 ALU 既算地址又算运算、一个存储器既存指令又存数据。
- 时钟周期按「最长一步」定，而不是「最长整条指令」——比单周期短。

**多周期 vs 单周期 vs 流水线**：

| 对比 | 单周期 | 多周期 | 流水线 |
| --- | --- | --- | --- |
| 每条指令周期数 | 1 | 3~5 | 1（平均） |
| 时钟周期 | 最长整条路径 | 最长一步 | 最长一段 |
| 硬件复用 | 低（每指令全用） | 高（分步复用） | 中 |
| 复杂度 | 低 | 中 | 高 |

**为什么选多周期**：单周期「好指令也被拖慢」、流水线「冒险复杂」——多周期用「分步」折中：硬件复用省面积、时钟周期适中。经典教材（Patterson）把单周期、多周期、流水线作为三阶段演进来讲。

**现代趋势**：现代 CPU 用流水线 + 乱序执行，多周期/单周期更多是教学模型——但理解三者的演进（周期怎么定、硬件怎么复用、怎么提速），是理解处理器微架构的必经之路。

**辨析｜易错点：** 单周期与多周期的时钟周期定义不同：单周期「周期 = 最慢整条指令路径」，多周期「周期 = 最慢单步」——多周期时钟可以更短，但一条指令要多拍。比较速度要算「总时间 = 周期 × 拍数」，别只看频率。

## 7 小结

- 数据通路 = 部件 + 连线 + MUX；控制信号拨动 MUX、指挥部件。
- 两种组织：单总线（共享、简单慢）vs 多通路（专用、并行快）。
- **单周期**：一条指令一个周期完成，所有控制信号同时有效。
- 单周期时钟周期 = 最慢指令的路径延迟——好指令也被拖慢。
- 流水线把路径切段并行提升吞吐，但单周期是理解流水线的基础。
