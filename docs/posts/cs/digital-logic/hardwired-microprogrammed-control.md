## 为什么从控制器开始

译码器产生了控制信号，但「谁来决定每拍发出哪些控制信号、如何分步执行一条指令」？这就是**控制器（control unit）**的职责。控制器有两种经典实现：**硬布线控制器**（逻辑门直接搭）与**微程序控制器**（用 ROM 存微指令）。<span class="marginnote">控制器的两种风格是「<strong>用逻辑算</strong> vs <strong>用表查</strong>」的又一次体现：硬布线用组合逻辑直接产生控制信号（快而难改），微程序用 ROM 存「微指令」逐拍读出（灵活但慢）。这与「门电路实现 vs 存储器实现逻辑」（第八篇）是同一对思想。</span>这一节把两种控制器讲透。

## 1 控制器的职责：分步指挥

一条指令的执行可以拆成若干**微操作（micro-operation）**——每个时钟拍做一个动作：

**取指阶段**：`PC→AR`、`读存储器`、`IR←M[AR]`、`PC+1`。
**执行阶段**（按指令类型）：`取操作数`、`ALU 运算`、`写回结果` 等。

**控制器**的工作：在每个时钟拍，根据「当前状态 + 当前指令」，产生**这一拍该做的控制信号集合**。

所以控制器本质上是一个**状态机**：状态 = 当前处于指令的哪个阶段，输出 = 该阶段的控制信号。

<span class="marginnote">控制器的本质：<strong>一个「以指令和阶段为状态」的状态机</strong>——每一拍处于某个微操作，输出对应控制信号，下一拍推进到下一个微操作。第六篇学的状态机设计，在这里兑现为 CPU 的「指挥中枢」。</span>

## 2 硬布线控制器：组合逻辑直接产生

**硬布线控制器（hardwired control）**：用**组合逻辑**（门电路）直接根据「指令操作码 + 状态」产生控制信号。

**结构**：

**指令译码**：操作码 → 指令类型。
**状态寄存器**：记录当前微操作阶段。
**组合逻辑网络**：输入（指令类型 + 状态）→ 输出（控制信号 + 下一状态）。

**实现**：一张「真值表」——指令类型 × 状态 → 控制信号。用 PLA/PAL 或门电路实现这张表。

**特点**：

| 优点 | 缺点 |
|---|---|
| 速度快（组合逻辑直接产生） | 设计复杂（真值表大） |
| 面积小（无 ROM 存储） | 难修改（改指令要改逻辑） |
| RISC 处理器主流 | 指令集扩展难 |

<span class="marginnote">硬布线是 RISC 的「<strong>用逻辑换速度</strong>」：指令集简单规整，控制真值表不大，用组合逻辑实现又快又省。RISC-V、ARM 的内核基本都用硬布线——因为它简单、快、面积小。改指令集意味着改组合逻辑，但这在 RISC 世界里不频繁。</span>

## 3 微程序控制器：ROM 存微指令

**微程序控制器（microprogrammed control）**：把控制信号**存进 ROM**——每条指令对应一段「微程序」，每拍读出一条微指令（micro-instruction）作为控制信号。

**结构**：

**控制存储器（ROM）**：存全部微程序（微指令）。
**微指令寄存器（μIR）**：当前微指令。
**微地址寄存器（μPC）**：下一条微指令地址。
**微操作译码**：微指令字段 → 控制信号。

**工作**：执行一条指令时，控制器逐拍从 ROM 读出该指令对应的微指令序列，每条微指令发出控制信号。

**特点**：

| 优点 | 缺点 |
|---|---|
| 灵活（改微程序即改行为） | 慢（多一次 ROM 访问） |
| 设计规整（写微程序而非搭逻辑） | 面积大（ROM 存储） |
| CISC 处理器传统 | 复杂指令集需要大微码 |

<span class="marginnote">微程序是「<strong>用表换灵活性</strong>」：改 CPU 行为 = 改 ROM 内容，不用改硬件。历史上 x86 等 CISC 处理器用微码实现复杂指令，也靠微码打补丁（微码更新修复 CPU 漏洞）。但微程序比硬布线多一次 ROM 访问，速度慢——所以 RISC 重回硬布线。</span>

## 4 公式解析：微指令的字段与执行

一条微指令如何「指挥」硬件？看微指令的字段设计：

**微指令格式**（字段分两组）：

$$\text{微指令} = \underbrace{\text{控制字段（产生控制信号）}}_{\text{每组控制一个部件}} + \underbrace{\text{下址字段（下一条微指令地址）}}_{\text{顺序或跳转}}$$

**第一步，看控制字段**：每个「微命令」控制一个部件的动作。例如：

- `ALUop` 字段：选择 ALU 运算。
- `RegWrite` 字段：写寄存器使能。
- `MemOp` 字段：存储器读写。

**第二步，看下址字段**：决定下一条微指令——顺序 +1，或按分支跳转到指令对应的微程序首地址。

**第三步，看执行**：取指阶段微程序（每指令共享）：

```text
地址  微命令（控制字段）                   下址
-----------------------------------------------
000   PC → AR，读存储器                   001
001   IR ← M[AR]，PC ← PC + 1            010
010   指令译码，跳转指令微程序首地址       按 opcode 分支
```

**第四步，看对比**：硬布线的「真值表」与微程序的「ROM 内容」——**描述的是同一件事，只是实现载体不同**：一个用组合逻辑，一个用存储。<span class="marginnote">微程序与硬布线的统一视角：<strong>两者都是「指令 × 状态 → 控制信号」的映射</strong>——硬布线用 PLA/门实现这张映射，微程序用 ROM 存储这张映射。用「映射」的眼光看，两种控制器殊途同归。</span>

## 5 两种控制器的选择

| 对比 | 硬布线 | 微程序 |
|---|---|---|
| 实现载体 | 组合逻辑（PLA/门） | ROM（控制存储器） |
| 速度 | 快 | 慢（ROM 访问） |
| 面积 | 小 | 大（ROM） |
| 灵活性 | 低（改逻辑） | 高（改微码） |
| 设计方式 | 真值表/逻辑 | 微程序（类汇编） |
| 典型应用 | RISC（ARM、RISC-V） | CISC 传统（x86 微码） |

**选型逻辑**：

**指令集简单、重速度** → 硬布线。
**指令复杂、重灵活、不追极致速度** → 微程序。
**现代趋势**：主流 CPU 用硬布线为主（RISC 内核），微码作为辅助（复杂指令的扩展）。

<span class="marginnote">历史的钟摆：<strong>CISC 时代微程序大行其道，RISC 革命回归硬布线，今天两者混合（RISC 核 + 微码补丁）</strong>。这背后是「速度 vs 灵活」的永恒权衡——也是「组合逻辑 vs 存储器实现逻辑」（第八篇）在控制器领域的又一次上演。</span>

## 6 小结

- 控制器把「指令 → 分步微操作 → 控制信号」——本质是一个状态机。
- **硬布线**：组合逻辑直接产生控制信号，快、省、难改，RISC 主流。
- **微程序**：ROM 存微指令逐拍读出，慢、灵活、易改，CISC 传统。
- 两者统一视角：都是「指令 × 状态 → 控制信号」的映射，载体不同（逻辑 vs 存储）。
- 选型：简单指令集重速度用硬布线，复杂指令重灵活用微程序。
