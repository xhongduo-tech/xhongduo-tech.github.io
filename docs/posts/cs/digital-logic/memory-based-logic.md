## 为什么从用存储器实现逻辑开始

把逻辑函数「算」出来（门电路）是一种思路；把函数「查」出来（存储器）是另一种思路。用 ROM（或 RAM）实现组合逻辑，把真值表直接烧进存储——**免化简、免画门、改内容即改逻辑**。这不仅是本章的高潮，也是 FPGA 查找表（LUT）与查表实现一切计算的原理源头。<span class="marginnote">核心思想一句话：<strong>逻辑函数就是真值表，真值表就是存储器的内容</strong>。用 $2^n \times m$ 的 ROM，地址接输入、数据接输出，就把 $m$ 个 $n$ 变量函数全部实现——一个芯片，成千上万条逻辑。</span>这一节讲清原理、设计流程与优缺点。

## 1 原理：ROM = 固化的真值表

回顾 8.2 的核心洞察：ROM 的地址译码器生成全部最小项，存储阵列记录每个最小项的输出——这正是真值表的全部信息。

用 ROM 实现逻辑函数的映射关系：

- **地址线** $A_{n-1}\sim A_0$ ← 逻辑函数输入变量。
- **数据线** $D_{m-1}\sim D_0$ → 逻辑函数输出。
- **ROM 内容**：每个地址存对应输入组合下的输出值（真值表逐行写入）。

于是：输入变量 → 地址 → 查表 → 输出。**函数被「存」而不是「算」出来**。<span class="marginnote">这个映射优雅地统一了「数据存储」与「逻辑实现」：<strong>同一片 ROM，既可以说它在「存数据」，也可以说它在「实现逻辑」——只是看问题的角度不同</strong>。真值表、ROM、查找表（LUT），本质是同一个东西的三个名字。</span>

## 2 设计流程：三步走

用 ROM 实现逻辑函数的流程：

1. **确定规模**：$n$ 个输入、$m$ 个输出 → 用 $2^n \times m$ ROM。
2. **写内容表**：对每个输入组合（地址），算出各输出值（数据），列真值表。
3. **编程**：把内容表烧进 ROM（或加载到 RAM），接好地址与数据线。

**例题**：用 ROM 实现一个 2 位加法器（两个 2 位数相加，输出 3 位和）。

- 输入：$A_1A_0$、$B_1B_0$（4 个变量）。
- 输出：$S_2S_1S_0$（3 位和）。
- 规模：$2^4 \times 3 = 16 \times 3$ ROM。

**内容表**（部分）：

| $A_1A_0B_1B_0$ | 和 | $S_2S_1S_0$ |
|---|---|---|
| 0000 | 0 | 000 |
| 0001 | 1 | 001 |
| 0010 | 2 | 010 |
| 0011 | 3 | 011 |
| 0100 | 1 | 001 |
| … | … | … |
| 1111 | 6 | 110 |

把这张表写进 ROM，输入接地址，输出即 3 位和——**一个 ROM 实现了整个 2 位加法器，无需任何门电路**。<span class="marginnote">这个例子的震撼之处：<strong>加法器如果用门电路要十几个门，用 ROM 只需一张表</strong>。而且想改成减法器？重写 ROM 内容即可，硬件纹丝不动——「改内容即改逻辑」是存储实现的最大魅力。</span>

## 3 优点与缺点：查表实现的权衡

**优点**：

- **免化简**：不需要卡诺图、不需要公式法——真值表直接可用。
- **规则规整**：所有函数用同一结构（ROM）实现，设计时间短。
- **易修改**：改内容即改逻辑（对可擦写 ROM/RAM），无需重新布线。
- **时序一致**：所有输出经过同一存取时间，无组合级联延迟差异。

**缺点**：

- **容量爆炸**：$n$ 个输入需要 $2^n$ 个存储单元——**变量数每加 1，容量翻倍**。10 个输入就要 1024 单元/输出，20 个输入要百万级。
- **利用率低**：真值表里大量组合可能是无关项，但 ROM 必须为它们预留单元。
- **速度上限**：ROM 的存取时间（几十 ns）慢于优化后的门电路。

**辨析｜易错点：** ROM 实现逻辑的容量随输入**指数增长**。这不是「面积换速度」的线性权衡，而是「输入变量数」的指数爆炸——所以 ROM 实现只适合**输入少、输出多、函数复杂**的场合（如查表、编码转换），输入多时要改用 PLD/FPGA（第九篇）。<span class="marginnote">容量爆炸的直观：<strong>实现 $n$ 变量函数需要 $2^n$ 个最小项，这就是 ROM 的地址数</strong>。变量多时，门电路（用化简）和 PLD（用可编程结构）都比 ROM 划算——这是「查表法」的天花板。</span>

## 4 公式解析：ROM 容量与输入的指数关系

定量看 ROM 实现逻辑的容量规律。设 $n$ 个输入、$m$ 个输出：

**第一步，地址数**：$2^n$ 个地址（每个输入组合一个）。

**第二步，总容量**：$2^n \times m$ bit。

**第三步，增长规律**：**$n$ 每 +1，容量 ×2**。对比：

| 输入数 $n$ | ROM 容量（$m=8$） |
|---|---|
| 4 | $16\times8 = 128$ bit |
| 8 | $256\times8 = 2$ Kbit |
| 12 | $4096\times8 = 32$ Kbit |
| 16 | $65536\times8 = 512$ Kbit |

**第四步，结论**：16 个输入就要 512 Kbit——所以 ROM 只适合少量输入。这就是为什么现代可编程逻辑用 **LUT（查找表）切成小块**（如 6 输入 LUT）再级联，而不是一个大 ROM——把指数爆炸切碎，让每片 LUT 保持小规模。<span class="marginnote">从 ROM 到 LUT 的演进：<strong>ROM = 一个大查找表，LUT = 切成小块的查找表 + 可编程互连</strong>。FPGA 的每个逻辑单元就是一个小的 ROM（6 输入 LUT = 64×1 的 ROM），用互连网络拼出任意逻辑。理解「ROM=真值表」，就理解了 FPGA 的内部。</span>

## 5 应用与展望

- **查表计算**：正弦表、对数表、开方表——用 ROM 存函数值，查表代替计算。
- **编码转换**：BCD→二进制、格雷码→二进制、ASCII→七段码。
- **微码**：CPU 控制器用 ROM 存微指令（第十二篇微程序控制器）。
- **字符发生器**：存字形点阵。
- **现代扩展**：FPGA 的 LUT、AI 芯片里的查表激活函数——「用存储实现函数」的思想至今活跃。

<span class="marginnote">「查表代替计算」是大模型推理里也在用的技巧：<strong>激活函数、权重存储、甚至部分注意力计算都可以预计算成表</strong>。从 ROM 查表到 LUT 到查表神经网络，思想一脉相承——把「算」换成「存」，用空间换时间。</span>

## 6 查表实现逻辑的现代形态：LUT 与查表计算

「用存储实现逻辑」在现代数字设计中以更精致的形态延续。

**FPGA 的 LUT**：每个 LUT 是一个小 ROM（$2^k \times 1$），综合器把逻辑函数「填」进 LUT——这正是「用存储器实现逻辑」的微型化。FPGA 逻辑 = 海量小查表 + 可编程互连（第九篇）。

**查表计算（table lookup）**：把「计算」变成「查表」——正弦表、对数表、伽马校正、CRC 查表、神经网络的查表激活函数。凡函数值可预计算，就能用存储换时间。

**查表 vs 计算的权衡**：

- 查表快（一次访存）、无浮点、电路简单。
- 代价是存储容量（精度×范围）与更新困难（改函数要重填表）。

**现代应用**：AI 芯片用查表做激活函数（省浮点运算）、用 LUT 存权重查表；通信系统用查表做星座映射；图像处理用查表做曲线校正——「查表代替计算」在今天依旧活跃。

**本质统一**：ROM 查表、FPGA LUT、查表计算——都是「预计算函数值存入存储，用时按输入索引取出」。理解「函数 → 表 → 存储」这条链路，就掌握了硬件实现函数的另一条腿（除了门电路）。

**辨析｜易错点：** 查表与「计算」的分界：查表的前提是「函数值可预计算」——输入范围有限、值可离线算好。输入范围无限（如实时反馈计算）就不能纯查表，需查表 + 插值或计算。选「查表 or 计算」看「表会不会太大、值能不能预知」。

## 7 小结

- 原理：ROM = 固化的真值表，地址接输入、数据接输出，查表实现逻辑。
- 流程：定规模（$2^n\times m$）→ 写内容表 → 编程接线。
- 优点：免化简、规整、易改、时序一致；缺点：容量随输入**指数爆炸**。
- 容量规律：$n$ 每 +1 容量 ×2，ROM 只适合输入少、输出多的场合。
- 从 ROM 到 LUT：FPGA 用小块查找表 + 互连拼出任意逻辑，思想同源。
