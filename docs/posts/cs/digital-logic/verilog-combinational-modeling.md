## 为什么从组合逻辑建模开始

组合逻辑是数字系统的基础。在 Verilog 里，组合逻辑有两种建模方式：**assign 连续赋值**（适合简单表达式）与 **always 过程块**（适合复杂真值表）。理解两者的适用场合与写法，才能写出既正确又可综合的组合逻辑。<span class="marginnote">两种方式的直觉：`<strong>`assign` 是「一句话的与或式」，`always` 是「一张表的分支判断」。表达式简单用 assign，判断多、需要 case/if 用 always——就像数学里「公式」vs「分段函数」。</span>这一节把两种方式都讲透，并指出「锁存器陷阱」这一经典错误。

## 1 assign 连续赋值：表达式即电路

**`assign`（连续赋值）**：用表达式描述组合逻辑，输入变化，输出**立即**（经过传播延迟）变化。

```verilog
assign y = a & b;
```

**特点**：

赋值对象必须是 `wire`（连线）。
连续赋值 = 连续驱动：表达式的任何输入变化都会重新计算输出。
只能用于组合逻辑。

**多个 assign**：多个 assign 并行执行，像多个门同时工作。

**可综合性**：assign 里的表达式可直接综合成门电路——`&`→与门、`|`→或门、`~`→非门、`? :`→MUX、`+`→加法器。

**例题**：实现多数表决器 $Y = AB + AC + BC$：

```verilog
assign y = (a & b) | (a & c) | (b & c);
```

综合后就是三个与门加一个或门。<span class="marginnote">assign 是最「贴近硬件」的写法：<strong>一个 assign 就是一个组合逻辑块，表达式结构直接映射门结构</strong>。写 assign 时心里想的是「这个表达式对应什么电路」，而不是「这个表达式怎么算」。</span>

## 2 always 过程块：行为级描述

**`always` 过程块**用于描述需要 if/case 等控制流的逻辑。组合逻辑的 always 模板：

```verilog
always @(*) begin
    // 组合逻辑
end
```

**`@(*)`** 表示「任何输入变化都触发」——灵敏度列表为全部信号。

**组合逻辑的 always 内部用阻塞赋值 `=`**：

```verilog
always @(*) begin
    case (sel)
        2'b00:   y = a;
        2'b01:   y = b;
        default: y = c;
    endcase
end
```

这实现了一个 4 选 1 的选择器（`2'b00` 选 a，`2'b01` 选 b，其他选 c）。

**赋值对象**：always 里赋值的变量必须声明为 `reg`（过程变量）。

**辨析｜易错点：** 组合 always 里的 `reg` 综合成**连线**（不是触发器）——它只是「被过程块赋值的变量」。判断综合结果看赋值方式：组合块（`@(*)` + 阻塞赋值）→ 纯组合逻辑；时序块（`@(posedge clk)` + 非阻塞赋值）→ 触发器。

## 3 公式解析：case 语句实现真值表

`case` 语句是描述真值表最自然的方式。用 case 实现 3-8 译码器：

```verilog
module decoder38 (
    input  [2:0] in,
    output reg [7:0] y
);
    always @(*) begin
        case (in)
            3'b000: y = 8'b0000_0001;
            3'b001: y = 8'b0000_0010;
            3'b010: y = 8'b0000_0100;
            3'b011: y = 8'b0000_1000;
            3'b100: y = 8'b0001_0000;
            3'b101: y = 8'b0010_0000;
            3'b110: y = 8'b0100_0000;
            3'b111: y = 8'b1000_0000;
            default: y = 8'b0;
        endcase
    end
endmodule
```

**第一步，看 case**：每个分支对应真值表一行——输入 `in` 的值对应输出 `y`。

**第二步，看 default**：`default` 处理未列出的值；用 `default: y = 8'bx` 声明无关项，给综合器化简空间。

**第三步，看 reg**：`y` 是 `reg`（在 always 里赋值），但综合成组合逻辑（`@(*)` + 阻塞赋值）。

**第四步，对应硬件**：这段代码综合后就是 3-8 译码器——与第四篇手画的译码器等价。<span class="marginnote">case 与真值表的对应是学 HDL 的「顿悟时刻」：<strong>你在代码里写的每一行 case，都是一行真值表；综合器把它翻译成译码逻辑</strong>。写 case 时就是「填真值表」——这是最直觉的硬件描述方式。</span>

## 4 锁存器陷阱：不完整 if/case

**组合 always 最大的坑是「锁存器推断（latch inference）」**：

如果 `if` 没有 `else`、`case` 没有 `default`，且条件不满足时某些输出**没有赋值**——综合器会推断出**锁存器**（保持上一个值），而不是你想要的组合逻辑。
这是**无意生成的锁存器**，往往不是设计本意，且时序难料。

**为什么会推断锁存器**：组合逻辑要求「每个输入组合都有确定输出」。分支没覆盖到时，硬件必须「记住」之前的值——能记忆的只有锁存器/触发器。

**消除方法**：

1. **补齐 else 与 default**：每个分支都有赋值。
2. **赋默认值**：块开头给所有输出赋初值。

```verilog
always @(*) begin
    y = 1'b0;              // 默认值
    case (sel)
        2'b00:   y = a;
        2'b01:   y = b;
        default: y = c;
    endcase
end
```

**辨析｜易错点：** 现代综合器会警告「inferred latch」。看到这个警告，先检查 if/case 是否完整。**有意的锁存器**（如 D 锁存器）用 `if (en) q = d;` 且故意不补全——但要明确「这是有意为之」，并用注释说明。无意锁存器是综合 bug 的头号来源。<span class="marginnote">锁存器陷阱的深层原因：<strong>「组合逻辑 = 每个输入都有输出」的完备性要求</strong>。补 else/default 不只是语法习惯，而是「保证组合完备性」。FPGA 里意外锁存器还会浪费资源、引入时序问题——写组合 always 时「先默认赋值、再分支覆盖」是最稳的习惯。</span>

## 5 assign 与 always 的选型

| 场合 | 推荐方式 | 原因 |
|---|---|---|
| 简单表达式 | `assign` | 简洁直接 |
| if/case 分支 | `always` | 控制流自然 |
| 多位真值表 | `case` | 表格化 |
| 三态输出 | `assign` + 条件 | `z`（高阻） |
| 有运算（+、*） | `assign` | 运算符直接可用 |

**组合逻辑建模规范**（工程经验）：

组合 always 用**阻塞赋值 `=`**（时序块用非阻塞，下一节）。
组合 always 用 `@(*)`，别手写敏感列表（漏信号会导致「综合前后仿真不一致」）。
每个分支都赋值，防锁存器。

<span class="marginnote">工程规范的意义：<strong>「组合用阻塞、时序用非阻塞」是一条铁律</strong>，违反它会导致仿真与综合不一致（RTL 仿真对、上板错）。`@(*)` 不用手写敏感表，则避免「综合器按全信号、仿真器按手写列表」的不一致。</span>

## 6 小结

- **assign**：表达式即组合电路，对象是 wire，适合简单逻辑。
- **always @(*) + 阻塞赋值 `=`**：行为级组合描述，适合 if/case。
- `case` 就是真值表：每行 case 对应真值表一行，default 给无关项。
- **锁存器陷阱**：if 无 else、case 无 default → 意外推断锁存器；用「默认赋值 + 补全分支」消除。
- 选型：表达式用 assign，分支用 always；组合用阻塞赋值。
