## 为什么从 PAL 与 GAL 开始

PROM 的可编程在或阵列（与阵列固定）、PLA 两个阵列都可编程但速度慢，而 **PAL** 选择了「与阵列可编程、或阵列固定」——这一选择让它速度快、结构简单、成本低，成为 1980 年代最成功的 PLD。**GAL** 则用可擦写工艺与可配置输出寄存器改进了 PAL，成为可重复编程的经典。<span class="marginnote">PAL 的名字含义：<strong>Programmable Array Logic，可编程「与」阵列</strong>。它的每个输出固定对应若干乘积项的或——这正适合「每个输出是几个与项之和」的典型逻辑。理解 PAL 的「固定或阵列」限制，就能理解它为什么被 FPGA 取代，又为何仍有身影。</span>这一节解剖 PAL 的结构、GAL 的改进，以及编程实现逻辑的方法。

## 1 PAL 的结构：与可编程、或固定

**PAL** 由输入缓冲、**可编程与阵列**、**固定或阵列**与输出电路组成。

- **与阵列**：每个交叉点有熔丝，编程时决定「是否把该变量（或其反）接进某个乘积项」——即决定每个乘积项由哪些变量构成。
- **或阵列**：固定连接——每个输出固定「或」若干乘积项。
- **输出电路**：部分 PAL 的输出带三态缓冲、可反馈、可带寄存器（时序 PAL）。

**固定或阵列的限制**：每个输出能用的乘积项数是固定的（如 74LS 兼容 PAL 每个输出最多 7~8 个乘积项）。若某函数需要的乘积项超过限制，就无法用这个 PAL 实现——**化简逻辑式，让乘积项数压进上限，是用 PAL 的前提**。<span class="marginnote">乘积项上限是 PAL 的「紧箍咒」：<strong>化简不好、乘积项超标，PAL 就用不了</strong>。所以 PAL 时代的设计师对卡诺图化简格外上心——每一个省下的乘积项，都是能否装进芯片的关键。</span>

## 2 用 PAL 实现逻辑：编程的实质

用 PAL 实现 $Y = AB + \overline{A}C$ 的过程：

**第一步，确定乘积项**：两个与项 $AB$ 与 $\overline{A}C$——需要 2 个乘积项（该输出的与阵列行）。

**第二步，确定每个乘积项含哪些变量**：
- 乘积项 1：$AB$——连接 $A$、$B$（不连 $C$、不连反变量）。
- 乘积项 2：$\overline{A}C$——连接 $\overline{A}$、$C$。

**第三步，编程（烧熔丝）**：在编程器上，把乘积项 1 中 $C$ 的连接点烧断（保持 $A$、$B$），把乘积项 2 中 $B$ 的连接点烧断（保持 $\overline{A}$、$C$）——未烧断的即「连接」。

**第四步，输出**：固定或阵列把这两个乘积项相加，$Y$ 得到。

**编程格式**：传统 PAL 用 **JEDEC 文件**描述每个交叉点「断/不断」，由软件（如 ABEL、CUPL）从逻辑式自动生成。<span class="marginnote">编程的现代形态：<strong>不再用手工烧熔丝，而是用 HDL 写逻辑 → 综合工具生成 JEDEC/位流 → 编程器下载</strong>。但对「每个乘积项连了哪些变量」的理解，仍然是读懂 PAL/CPLD 内部的基础。</span>

**辨析｜易错点：** PAL 与 PROM 的可编程位置正好相反：**PROM 与阵列固定（全译码）、或阵列可编程；PAL 与阵列可编程、或阵列固定**。一个是「生成全部最小项再选」，一个是「自己选乘积项再固定相加」。记住这个「反」字，就分清了。

## 3 GAL：可重复编程的 PAL

**GAL（Generic Array Logic，通用阵列逻辑）**是 PAL 的进化：

- **与阵列可编程**（同 PAL）。
- **或阵列固定**（同 PAL）。
- **输出逻辑宏单元（OLMC）**：输出可以配置为组合输出、寄存器输出、三态输出等——**每个输出的形态可编程**。
- **工艺改进**：用 **E²CMOS 工艺**（电可擦），替代熔丝——**可擦写、可重复编程**。

**对比 PAL 与 GAL**：

| 对比 | PAL | GAL |
|---|---|---|
| 编程工艺 | 熔丝（一次） | E²CMOS（可擦） |
| 输出结构 | 固定（或少量可选） | OLMC 可配置 |
| 重复编程 | 否 | 是 |
| 兼容性 | — | 可模拟多种 PAL 型号 |

<span class="marginnote">GAL 的价值：<strong>一个 GAL 通过配置 OLMC，可以代替多种不同型号的 PAL</strong>——「通用」二字正源于此。可擦写让开发期反复调试成为可能，GAL 因而统治了 1980~90 年代的胶合逻辑（glue logic）市场。</span>

## 4 公式解析：OLMC 的配置原理

GAL 的 OLMC（输出逻辑宏单元）如何实现「一个输出多种形态」？核心是**可编程的多路选择器（MUX）**：

**OLMC 内部**：乘积项求和后，经一个由配置位控制的 MUX，选择：

- **组合输出**：直接输出 $Y = \sum(\text{乘积项})$。
- **寄存器输出**：先存入 D 触发器，再由时钟沿输出——用于时序逻辑。
- **三态输出**：由使能信号控制是否输出高阻。
- **反馈选择**：输出可反馈回与阵列，实现更复杂的逻辑。

**第一步，看基本数据流**：乘积项 → 或门 → MUX → 三态 → 输出。

**第二步，看配置位**：MUX 的选择端由 E²CMOS 配置决定——配置不同，输出形态不同。

**第三步，看寄存器路径**：若配置为寄存器输出，则 $Y$ 是 D 触发器的 $Q$，输入是乘积项之和。

**第四步，结论**：**OLMC = 输出 + 一组可编程开关**。配置位决定「组合/时序/三态」，让同一个 GAL 既能做组合逻辑又能做时序逻辑。<span class="marginnote">这个「输出宏单元 + 配置」的设计被 CPLD 与 FPGA 继承：<strong>CPLD 的每个宏单元就是 PAL 宏单元的规模化，FPGA 的每个逻辑单元也是「查找表 + 触发器 + 配置」</strong>。从 GAL 到 FPGA，宏单元思想一脉相承。</span>

## 5 从 PAL/GAL 到 CPLD

PAL/GAL 的局限：**单个器件的逻辑量有限**（几十个等效门、几十个乘积项）。要更大的逻辑规模，厂商把多个 PAL 型块 + 可编程互连集成到一颗芯片上——这就是**CPLD**（下一节）。

**回顾地位**：PAL/GAL 是「经典 PLD」的代表，如今仍在教学、低成本胶合逻辑中使用；主流大规模设计已全面转向 CPLD 与 FPGA。<span class="marginnote">演进链：<strong>PAL（单块、可编程与阵列）→ GAL（可擦、输出可配）→ CPLD（多个 PAL 块 + 互连）→ FPGA（LUT + 互连）</strong>。每一步都在「增加可编程的自由度」——从熔丝到电擦、从固定输出到宏单元、从单块到多块互连。</span>

## 6 PAL 的乘积项资源与化简

用 PAL 设计时，「乘积项够不够」是第一约束。这一节把资源概念讲透。

**PAL 的乘积项资源**：每个输出固定对应若干乘积项（如 74LS 兼容 PAL 每输出 8 个乘积项）。设计时，化简后的函数式乘积项数必须 ≤ 上限。

**例题**：某 PAL 每个输出最多 4 个乘积项，判断 $Y = AB + AC + \overline{A}B + BC$ 能否直接实现？

**第一步，数乘积项**：4 个乘积项——刚好等于上限，**可以直接实现**。

**第二步，若化简**：$AB + AC + \overline{A}B + BC = A(B+C) + \overline{A}B + BC$……用卡诺图看，$BC$ 可能是冗余项：化简后 $Y = AB + AC + \overline{A}B$（3 项）——**化简后只剩 3 项，留出 1 项裕量**。

**第三步，结论**：化简让乘积项从 4 降到 3——多出的裕量可留给未来扩展或提高可靠性。

**为什么乘积项是 PAL 的关键资源**：PAL 的与阵列物理上只有固定的行数，每行是一个乘积项。函数复杂（乘积项多）就装不下——化简逻辑式 = 压缩乘积项 = 让设计能装进 PAL。

**工程启示**：PAL 时代的设计师把「卡诺图化简」练到炉火纯青，因为每个省下的乘积项都是「能不能用这块芯片」的胜负手。现代 FPGA 的 LUT 虽无乘积项概念，但「化简 = 省资源」的思想仍然成立——综合器报告里的「LUT 用量」就是现代的「乘积项数」。

**辨析｜易错点：** 乘积项数 ≠ 逻辑门数：一个乘积项是「一个与门」，或门是固定的。化简的目标是「减少乘积项 + 减少每个乘积项的因子」，两者都要省——前者省与门，后者省与门输入。

## 7 小结

- **PAL**：与阵列可编程、或阵列固定；速度快、结构简，但输出乘积项数受限。
- 编程实质：决定每个乘积项连哪些变量（断熔丝），JEDEC 文件描述。
- **GAL**：E²CMOS 可擦写 + **OLMC 输出宏单元**可配置——一个芯片多种输出形态。
- OLMC = 输出 + 可编程 MUX（组合/时序/三态），思想被 CPLD/FPGA 继承。
- PAL 与 PROM 可编程位置相反：一个可编程与阵列、一个可编程或阵列。
