## 为什么从基本类型开始

上一章我们写出了能跑的 `main`，但程序中所有的计算都发生在**变量**里，而变量的形态由**类型**决定。如果说 C++ 是「带类的 C」，那么类型就是 C++ 一切特性的地基：类型决定了数据占多少字节、能表示多大范围、能参与哪些运算，也决定了函数怎么接收参数、对象怎么拷贝、模板怎么推导。这一章是后续所有章节的词汇表。<span class="marginnote">Python 里写 `x = 1` 时，类型是对象自带的，变量只是名字；C++ 里写 `int x = 1` 时，类型属于变量本身，编译期就已确定。这就是<strong>静态类型</strong>与<strong>动态类型</strong>的分水岭——C++ 是前者，它让类型错误在编译期暴露，代价是写起来更啰嗦。</span>把类型想清楚，后面学引用、指针、类与模板时才不会处处漏气。

## 1 内置类型：算术类型与空类型

C++ 的**内置类型（built-in type）**是语言自带的类型，主要分三类：**算术类型（arithmetic type）**、**空类型（void）** 与 **`std::nullptr_t`**。算术类型又分**整型**与**浮点型**两族。

**整型族**按「是否能表示负数」分成**有符号（signed）**与**无符号（unsigned）**；按「占据字节数」分成 `short`、`int`、`long`、`long long`。最小的 `bool` 与 `char` 也属于整型。一张表看全：

| 类型 | 常见宽度 | 典型取值范围 | 说明 |
| --- | --- | --- | --- |
| `bool` | 1 字节 | `true` / `false` | 逻辑值，可隐式转为 `0/1` |
| `char` | 1 字节 | 实现相关，通常 `-128~127` 或 `0~255` | 一个字符的机器字节 |
| `short` | 2 字节 | ±32767 | 小整数 |
| `int` | 4 字节 | ±2.1×10⁹ | 「默认」整数类型 |
| `long` | 4 或 8 字节 | 平台相关 | 保证不小于 `int` |
| `long long` | 8 字节 | ±9.2×10¹⁸ | 保证不小于 `long` |
| `float` | 4 字节 | 约 7 位有效数字 | 单精度浮点 |
| `double` | 8 字节 | 约 16 位有效数字 | 双精度浮点 |

**只有这些「常见宽度」是直观的，标准只保证相对大小**：`short` 至少 16 位，`int` 至少 16 位，`long` 至少 32 位，`long long` 至少 64 位，且 `long` 不短于 `int`。在 32 位与 64 位平台上，`long` 的宽度甚至可能不同。<span class="marginnote">为了摆脱平台差异，现代 C++ 用 `<cstdint>` 里的定宽整型：`int32_t`、`uint64_t` 等精确指定位数。跨平台代码（比如网络协议、文件格式解析）几乎必须用它们，因为字节数直接决定内存布局。</span>浮点数的表示遵循 IEEE 754 标准，这在第2级《计算机组成原理》中会拆开讲；这里只需记住 **`float` 精度约 7 位十进制数字，`double` 约 16 位**——凡是对精度有要求的地方（科学计算、金额），默认选 `double`。

**`void`** 是特殊的「无类型」：它不能声明变量，只用于函数的返回类型（表示不返回值）与指针（`void*` 表示「指向未知类型的指针」）。

## 2 变量：声明、定义与初始化

**声明（declaration）**让名字在作用域内可见；**定义（definition）**额外为变量分配存储空间。一个变量在程序中只能**定义一次**（一个翻译单元），但可以**声明多次**。要定义只声明不定义的变量，用关键字 `extern`：

```cpp
extern int count;   // 声明：count 在别处定义
int total = 0;      // 定义：为 total 分配空间并初始化为 0
```

**初始化（initialization）**与**赋值（assignment）**是本章最容易混淆的一对概念。初始化发生在**创建变量时**——变量被赋予初值的那一刻；赋值发生在变量**已存在之后**——用 `=` 修改它的值。下面的例子第 1 行是初始化，第 3 行是赋值：

```cpp
int a = 10;    // 初始化：a 被创建，值为 10
a = 20;        // 赋值：a 已存在，值改为 20
int b(30);     // 直接初始化：C++ 风格的括号初始化
int c{40};     // 列表初始化（C++11）：最严格，可防窄化
```

C++ 至少有四种初始化语法，理解它们的差别是初学难点：

**拷贝初始化** `int a = 10;`：用 `=` 号，从右侧拷贝一份。
**直接初始化** `int b(30);`：用圆括号，把参数直接传给构造函数。
- **列表初始化** `int c{40};`：用花括号（C++11 引入），**不允许窄化转换**——把 3.14 塞进 `int` 会被编译器拒绝。
- **默认初始化** `int d;`：不给初值。对内置类型而言，**在函数体内它拥有一个「未定义的值」**——直接使用是未定义行为。<span class="marginnote">函数外的全局变量会被默认初始化为 0；函数内的局部变量不会。C++ Primer 反复警告：<strong>永远别依赖「恰好是 0」的运气</strong>，用之前先初始化。这也是静态分析工具最爱抓的一类 bug。</span>

## 3 const、constexpr 与常量表达式

有些值在整个程序中都不变，比如圆周率、端口号、颜色定义。用 `const` 修饰，告诉编译器「这个变量一旦初始化就不可修改」：

```cpp
const int bufSize = 512;   // bufSize 的值在生命周期内不可变
bufSize = 1024;            // 编译错误：不能给 const 赋值
```

`const` 变量**必须初始化**——既然之后不能改，创建时就得定下来。更重要的是 `const` 的作用域：**文件作用域的 `const` 变量默认只在当前文件内可见**，想在多个文件共享，须在头文件中定义（或加 `extern`）。

**常量表达式（constant expression）**是指**编译期就能算出结果**的表达式，比如 `2 * 21`。用 `constexpr` 声明变量，编译器会强制要求右侧是常量表达式：

```cpp
constexpr int max = 1000;          // 编译期常量
constexpr int half = max / 2;      // 合法：max 在编译期已知
constexpr double pi = 3.14159;     // 合法：字面量
```

`const` 与 `constexpr` 的区别是：`const` 保证「运行期不可改」，`constexpr` 保证「编译期可求值」。模板参数、数组大小、`switch` 的 case 标签都需要编译期常量，这时候必须用 `constexpr`。<span class="marginnote">`constexpr` 函数在 C++11 中只能写一条 `return`，C++14 放宽到可以有多条语句。现代 C++ 里「能写 `constexpr` 就写」是性能与安全兼得的习惯——它把计算提前到编译期，还能让代码在常量上下文中复用。</span>这两个关键字在第5篇 Effective C++ 第2条「尽量以 const、enum、inline 替换 #define」里会再次相遇。

## 4 引用与类型别名

**引用（reference）**是变量的另一个名字（别名）。定义引用时，编译器**不会**新建对象，只是把新名字绑定到已存在的对象上：

```cpp
int x = 42;
int &ref = x;        // ref 是 x 的引用，二者指向同一块内存
ref = 7;             // 修改 ref 就是修改 x：x 现在也是 7
```

引用有三条铁律：**引用必须初始化**（没有「空的引用」）；**引用一旦绑定就不能再改绑**；**引用不是对象**，所以不能定义「引用的引用」，也没有引用的数组。引用最重要的用途是**函数参数**：按引用传参避免拷贝大对象，还能让函数修改实参——这在本专题函数一章是核心技巧。

**类型别名**用 `using` 或 `typedef` 给类型起小名。C++11 后更推荐 `using`：

```cpp
using Money = double;          // C++11：using 别名
typedef int Status;            // 旧式：typedef，含义相同

Money price = 9.9;
Status code = 200;
```

别名的价值在复杂类型上一目了然：`using Callback = void(*)(int, int);` 比起手写函数指针类型，可读性高出一个数量级。**别名与原类型是同一个类型**，别名与 `const` 组合时要格外小心——后面讲指针时专门辨析。

## 5 代码解析：类型选择决定程序行为

类型不是「声明时的装饰」，它直接改变程序的行为。看一个著名的坑：

```cpp
#include <iostream>

int main()
{
    unsigned u = 10;
    int i = -42;
    std::cout << u + i << std::endl;      // 输出 4294967264（而非 -32）
    return 0;
}
```

**第一步，看类型**：`u` 是 `unsigned int`，`i` 是 `int`，二者做 `+` 运算时，C++ 把 `i` **隐式转换**为 `unsigned int` 再相加。
- **第二步，看转换结果**：`-42` 转成 `unsigned int`，在 32 位系统上等于 $2^{32} - 42 = 4294967254$；再加 10，得到 $4294967264$。
- **第三步，看陷阱**：结果**不是**直觉中的 `-32`，而是一个巨大正数。因为无符号类型**永不小于 0**，它按模 $2^{32}$
