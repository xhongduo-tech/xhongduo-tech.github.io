## 为什么从构造析构开始

第13章拷贝控制已经建立了「五大特殊成员函数」的框架；Effective C++ 第2章（条款5–12）换一个角度问：**编译器偷偷替你生成的那些函数，什么时候是帮助、什么时候是陷阱？** 这 8 个条款是 C++ 世界里出现频率最高的「面试题+线上事故」清单：编译器自动生成了哪些函数（条款5）、如何禁止不想要的（条款6）、多态基类析构为什么要虚（条款7）、析构函数为什么不能抛异常（条款8）、构造/析构期间为什么不能调虚函数（条款9）、赋值运算符为什么要返回引用且防自赋值（条款10–11）、拷贝为什么必须复制对象的所有部分（条款12）。<span class="marginnote">这 8 个条款有一个共同底色：<strong>对象生命周期里的「默认行为」常常不是你想要的行为</strong>。编译器愿意代劳的，恰恰是最容易出错的地方——所以 Meyers 反复强调「知道编译器在偷偷做什么」。</span>

## 1 条款5：了解 C++ 默默编写并调用了哪些函数

**编译器会自动生成**哪些函数？只有这些「用得到时」才生成：

- **默认构造函数**（如果类没有任何构造函数）
- **拷贝构造函数**
- **拷贝赋值运算符**
- **析构函数**
- C++11 起还有**移动构造**与**移动赋值**

这些「默认生成」的版本做**逐成员**操作：内置类型逐位复制、类类型调用各自的拷贝/移动。**重点：** 编译器只在「有人用」时才生成，且**一旦你声明了某个，它就不再替你生成对应的默认版本**——这正是「知道自动行为」的意义。<span class="marginnote">几个让编译器「拒绝生成」的情形值得记住：成员里有引用或 const 的类，<strong>拷贝赋值运算符默认生成会被删除</strong>（引用/const 不可重新绑定）；基类拷贝赋值是 private 的类，派生类的拷贝赋值也被删除。这些「删除」正是保护你不写出坏代码的机制。</span>

## 2 条款6：明确拒绝不想使用的编译器生成函数

**易错点：** 类的**拷贝**能力有时是**错误的**——比如「银行账户」「独一无二的锁」「序列化句柄」，两个对象共享同一份资源就是灾难。禁止拷贝的 C++11 正统写法是 **`= delete`**：

```cpp
class Uncopyable {
protected:
    Uncopyable() = default;
    ~Uncopyable() = default;
private:
    Uncopyable(const Uncopyable &) = delete;             // 禁止拷贝构造
    Uncopyable &operator=(const Uncopyable &) = delete;  // 禁止拷贝赋值
};
```

**辨析：** C++98 时代的标准做法是「把拷贝操作声明为 private 且不实现」——任何调用（类内、友元外）都编译失败或链接失败，但报错信息很晦涩。`= delete` 让意图显式、让错误在**编译期**直接报「已删除的函数」，体验好得多。<span class="marginnote">现代 C++ 里「禁止拷贝、允许移动」比「完全禁止」更常见——`std::unique_ptr`、`std::thread` 都是「删除拷贝、保留移动」。删除拷贝但不定义移动，则移动也会退化走拷贝而同样被删。这条的思路：<strong>把「不该有的能力」在类型层面焊死</strong>，比在文档里写「请勿复制」可靠一万倍。</span>

## 3 条款7：多态基类应声明虚析构函数

**重点：** 如果一个类要作为**多态基类**（派生类会通过基类指针被删除），其析构函数**必须是 virtual**：

```cpp
class TimeKeeper {
public:
    TimeKeeper();
    virtual ~TimeKeeper();       // 多态基类：虚析构
};
class AtomicClock : public TimeKeeper { /* ... */ };

TimeKeeper *p = new AtomicClock;
delete p;                        // 虚析构 → 正确调用 AtomicClock 析构
```

**不虚的后果**：`delete p` 只调用 `TimeKeeper::~TimeKeeper()`，派生类 `AtomicClock` 的成员**不析构**——它的资源泄漏、它的析构逻辑被跳过，行为未定义。<span class="marginnote">析构函数「非虚但会被人多态删除」是 C++ 最常见的未定义行为之一。反过来，<strong>不是多态基类的类（如纯数据类）就不该有虚析构</strong>——虚函数会引入 vtable、对象多 8 字节 vptr，纯浪费。判断标准一句话：类里有虚函数 → 析构也要虚；没有任何虚函数 → 析构不要虚。</span>

## 4 条款8 与 9：析构不能抛、构造/析构别调虚函数

**条款8——析构函数绝不能抛出异常**：析构函数默认 `noexcept`，一旦在析构里 `throw`，栈展开或 `delete` 过程中会调用 `std::terminate` 直接终止程序。如果析构函数里要做可能失败的操作（关文件、释放连接），**捕获异常、记录日志、吞掉它**，绝不让异常逃出析构。<span class="marginnote">为什么析构抛异常如此致命？因为析构常在「异常展开」的路上被调用——那时栈上已经有一个异常在传播，析构再抛一个，两个异常同时在场，标准规定调用 `terminate`。这也解释了「析构里 `delete` 资源用智能指针而不是手写 try/catch」——RAII 让析构「不抛」成为默认。</span>

**条款9——绝不在构造和析构期间调用虚函数**：构造期间，对象还在「半成品」状态——基类构造时它只是基类对象，虚调用走**基类版本**，不会进入派生类实现；析构期间同理，派生类部分已销毁，虚调用同样退化。**违反的后果**：你以为「调了虚函数会多态」，实际执行的是基类版本——若该版本是纯虚或访问未初始化成员，直接崩溃。

```cpp
class Transaction {
public:
    Transaction() { logTransaction(); }   // 糟糕：调用的是基类版本，而非多态！
    virtual void logTransaction() const = 0;   // 纯虚 → 构造期调用即未定义行为
};
```

**对策**：把「构造/析构期间需要的行为」抽成**非虚的辅助函数**，并在派生类构造时**显式传参**，而不是依赖虚调用。

## 5 条款10、11、12：赋值运算符的三件套

**条款10——赋值运算符应返回 `*this` 的引用**：C++ 允许链式赋值 `a = b = c`，靠的是「赋值表达式的结果就是被赋值者」。返回 `*this` 的引用保持这一惯例，也让代码与内置类型一致。

**条款11——在 `operator=` 中处理「自我赋值」**：`a = a` 虽然罕见，却会在 `a[i] = a[j]`、别名引用等场景悄悄发生。**先释放再复制**的实现会在自赋值时把自己删掉：

```cpp
Widget &Widget::operator=(const Widget &rhs) {
    if (this == &rhs) return *this;   // 自赋值检查（旧式）
    // 先复制后删除（copy-and-swap 更优）
}
```

更稳的 `copy-and-swap`：先用 rhs 构造一个临时副本，再与 `*this` 交换——同时解决自赋值与异常安全（第13章讲过）。

**条款12——复制对象时勿忘其每一个部分**：拷贝构造/拷贝赋值**必须复制所有成员与所有基类部分**。派生类自定义拷贝操作时**漏掉基类**是经典 bug——基类部分被默认构造、而非复制：

```cpp
class Derived : public Base {
public:
    Derived(const Derived &rhs) : Base(rhs), data_(rhs.data_) {}   // 别忘了 Base(rhs)!
    Derived &operator=(const Derived &rhs) {
        Base::operator=(rhs);     // 先复制基类部分
        data_ = rhs.data_;
        return *this;
    }
};
```

**重点：** 拷贝操作实现「不应该互相调用」——拷贝构造调用拷贝赋值、或反之，都是错误（对象还没构造完就赋值）。复制「全部成员 + 全部基类」，是条款12唯一的铁律。<span class="marginnote">这一条与第13章 Rule of Three 呼应：你写了析构，几乎总要写拷贝；写了拷贝，几乎总要写「复制所有部分」。实践中「成员全是值语义类型（string、vector、智能指针）」时，编译器默认的逐成员拷贝就是正确的——<strong>少写、靠默认，反而是最安全的</strong>，Rule of Zero 因此成了现代 C++ 的口号。</span>

## 6 小结

- **条款5**：编译器按需生成默认构造、拷贝、析构、移动——「有人用才生成，你声明即接管」。
- **条款6**：用 **`= delete`** 明确禁止拷贝；「禁止拷贝、允许移动」比「完全禁止」更常见。
- **条款7**：**多态基类析构必须 virtual**；没有虚函数的类别加虚析构（白付 vtable 开销）。
- **条款8、9**：析构不抛异常；构造/析构期间不调虚函数（用显式传参的非虚辅助函数替代）。
- **条款10、11、12**：`operator=` 返回 `*this`、防自赋值（copy-and-swap）、**复制所有成员与基类部分**。
- 编译器默认行为「对你有利时就接受，对你不利时就 `=default`/`=delete`/自定义」——这是本章的决策心法。
