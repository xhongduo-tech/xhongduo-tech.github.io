## 为什么从运算符重载开始

第6章的 `print(int)` 告诉我们重载让函数按类型分发；第14章把同样的思想推广到**运算符**：`a + b`、`a << b`、`v[i]`、`fn(x)` 这些「看似是语法」的表达式，其实都可以被用户类型**重载（overload）**成自己的版本。`std::string` 的 `+` 之所以能拼字符串、`std::cout << 42` 之所以能输出整数，全是运算符重载的功劳。同时这一章还讨论**类型转换**——对象如何在类型之间互转，以及 `explicit` 如何堵住隐式转换的漏洞。掌握它，你写的类才会「用起来像内置类型」，这也是 C++ 「零开销抽象 + 用户类型与内置类型平等」哲学的集中体现。<span class="marginnote">运算符重载的经典守则来自 C++ 之父：<strong>重载运算符应当「保持直觉语义」</strong>——`+` 该是可结合、可交换的操作，`==` 该是等价关系，`<<` 该是输出。把 `+` 重载成「减法」是允许的、却是被社区唾弃的。</span>

## 1 重载运算符的基本规则

**重载运算符（overloaded operator）**是特殊名字的函数——关键字 `operator` 后跟运算符符号：

```cpp
Sales_data operator+(const Sales_data &lhs, const Sales_data &rhs);
```

硬性规则：

- **只能重载已有的运算符**（`+ - * / % == != < > <= >= = += << >> & | ^ ~ ! && || ++ -- [] () -> * new delete`），**不能发明新符号**（如 `**`）。
- **不能改变运算对象的个数、优先级与结合性**——`a + b` 重载后仍是二元、优先级不变。
- **至少一个运算对象是用户自定义类型**——不能给 `int + int` 写新含义。
- 有四个**不能重载**：`::`、`.`、`.*`、`?:`（作用域、成员访问、成员指针、条件运算符）。

**重点：** 重载运算符合法名字的表征是「至少一个参数是类类型」，这保证了「`42 + 42` 永远是你知道的那个加法」——内置语义由语言保留，用户只能在自己的类型上开疆拓土。<span class="marginnote">`::`、`.`、`.*`、`?:` 之所以禁重载，是因为它们的语义与「对象的内存布局 / 作用域解析」绑定太深，交给用户重写会造成不可理喻的代码。保留这四个的「原生性」，是 C++ 对可读性的最后底线。</span>

## 2 成员 vs 非成员：运算符归属的判定

每个运算符要么定义为**成员函数**（左操作数就是调用对象 `*this`），要么定义为**非成员函数**（两个参数都是显式实参）。判定标准是一个问题：**左侧运算对象是否需要隐式转换？**

**核心对比表：**

| 运算符 | 建议 | 原因 |
| --- | --- | --- |
| `=` `[]` `()` `->` | **必须成员** | 语言规定 |
| `+=` `-=` 等复合赋值 | 成员 | 修改左操作数本身 |
| `++` `--` `*`（解引用） | 成员 | 直接操作对象状态 |
| `+` `-` `*` `/` 算术 | 非成员 | 允许 `3.0 + obj`（左操作数被转换） |
| `<<` `>>`（IO） | **非成员** | 左操作数是流 `ostream`，不能改流类 |
| `==` `<` 等关系 | 非成员 | 左右对称，避免「成员 + 转换」不对称 |

**辨析：** `operator+` 若写成成员函数，`obj + 3.0` 合法、`3.0 + obj` 却编译失败（左操作数 `3.0` 不是 `Sales_data`，无法调用成员）。因此「**对称二元运算符用非成员函数**」是标准库与 C++ Primer 的一致建议——这与 Effective C++ 第24条「当类型转换应作用于所有操作数时，声明非成员函数」完全吻合。<span class="marginnote">IO 运算符 `operator<<` 必须是非成员：左操作数是 `std::ostream`，你不可能往标准库的流类里加成员函数，只能定义「`ostream& operator<<(ostream&, const T&)`」并把要打印的私有成员设为友元——这就是为什么打印类时经常出现 `friend`。</span>

## 3 常用运算符重载实战

**输入输出** `<<` 与 `>>`：

```cpp
std::ostream &operator<<(std::ostream &os, const Sales_data &s) {
    os << s.isbn << " " << s.units_sold;
    return os;                    // 返回流，支持链式 cout << a << b
}
```

返回流本身是为了**链式调用**：`cout << a << b` 从左到右执行，`<<` 的返回值继续作为左操作数。

**下标 `[]`** 通常写两个版本（普通 + const）：

```cpp
T &operator[](size_t i) { return data[i]; }        // 可变访问
const T &operator[](size_t i) const { return data[i]; }  // 只读访问
```

**函数调用运算符 `()`** 让对象「可调用」，这样的对象叫**函数对象（function object / functor）**：

```cpp
class Print {
public:
    void operator()(const std::string &s) const { std::cout << s << '\n'; }
};
Print p; p("hello");     // 对象像函数一样被调用
```

functor 是第10章 lambda 的实现基础——lambda 的糖衣下就是一个匿名 functor。<span class="marginnote">为什么标准库偏爱函数对象而非函数指针？因为 functor 可以<strong>携带状态</strong>（成员变量）、可以内联、且 `operator()` 参数类型在编译期已知——lambda 捕获的变量正是存成了 functor 的成员。这是「行为即对象」的泛型编程基石。</span>

## 4 递增递减与成员访问

`++` 与 `--` 有前置与后置两个版本，靠一个**占位 int 参数**区分：

```cpp
T &operator++();               // 前置 ++obj：返回修改后的自己
T operator++(int);             // 后置 obj++：保存旧值、返回旧值副本
```

**易错点：** 前置返回引用（`T&`）、后置返回值（`T`）——后置因为要保存旧值，实现通常是「先拷贝旧值、再前置自增、返回旧拷贝」，天然更贵。`->` 与 `*` 重载后，对象就能「像指针一样」使用——`shared_ptr`、迭代器正是靠它们实现的。

## 5 类型转换运算符与 explicit

**转换运算符（conversion operator）**让类**隐式地**转成其他类型：

```cpp
class SmallInt {
public:
    SmallInt(int v) : val(v) {}        // int → SmallInt（转换构造函数）
    operator int() const { return val; }  // SmallInt → int（转换运算符）
private:
    int val;
};
SmallInt si = 3;      // 隐式：3 → SmallInt
int n = si + 2;       // 隐式：si → int，然后相加
```

**辨析｜易错点：** 隐式转换**很方便，也会很危险**——`si + 2` 到底是「先转 int 再加」还是「先构造成 SmallInt 再加」？多重隐式转换会让重载决议陷入混乱。C++ 的防线是：

- **转换构造函数**加 `explicit`，禁止隐式构造（`SmallInt si = 3` 会报错，需 `SmallInt si(3)` 或 `static_cast<SmallInt>(3)`）。
- **转换运算符**（C++11 起）也可加 `explicit`，仅允许显式 `static_cast`。

**重点：** 现代 C++ 的建议是「**默认显式**」——只有确实无歧义、无风险的转换才允许隐式。`std::string` 的 `operator bool`、`std::shared_ptr` 的 `operator bool` 都是 `explicit` 的典型例子。<span class="marginnote">`std::cin >> v` 之所以能当 `if (cin)` 用，正是因为流类提供了 <strong>`explicit operator bool`</strong>——它只允许在布尔语境（条件、`!`、`&&`）里隐式转换，防止 `int n = cin;` 这种误用。explicit + operator bool 是现代 C++ 防「诡异隐式转换」的标准招式。</span>

## 6 小结

- **重载运算符** = 名字是 `operator` + 符号的函数；不能发明新运算符、不能改优先级、至少一个类类型操作数。
- `::`、`.`、`.*`、`?:` **不能重载**。
- **成员 vs 非成员**：`=` `[]` `()` `->` 必须成员；对称二元运算符（`+` `==` `<<`）用非成员以支持左操作数隐式转换。
- `<<`/`>>` 返回流引用以支持**链式**；`[]` 写普通 + const 双版本；`()` 定义**函数对象**。
- 前置 `++` 返回引用、后置返回旧值；`->`/`*` 让对象像指针。
- **转换**：构造/转换运算符默认隐式，`explicit` 显式收紧；「默认显式」是现代 C++ 的纪律。
