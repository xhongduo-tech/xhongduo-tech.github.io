## 为什么从表达式开始

第2章我们学会了「变量怎么声明」，第3章学会了「数据怎么装进容器」，但程序真正的计算发生在**表达式（expression）**里——一切能算出值的东西：`a + b * 2`、`v.size()`、`x < 10 && ok`。C++ 的表达式规则是出了名的多（运算符超过四十种），但底层只有几根主线：**优先级与结合性**决定计算顺序，**左值与右值**决定表达式能否被赋值、能否被移动，**求值顺序**决定同一条式子里的副作用何时发生。这些规则与 Python、JavaScript 大同小异，却又在细节上处处不同——吃透它们，读别人的代码才不靠猜。<span class="marginnote">《C++ Primer》第4章开头就说：C++ 的表达式要么是字面量、要么是变量、要么是「运算对象 + 运算符」。理解表达式 = 理解运算符表 + 理解两种值类别 + 理解求值顺序，三根主线抓住，剩下的都是查表。</span>

## 1 优先级与结合性

**运算符（operator）**作用于**运算对象（operand）**，例如 `a + b` 中 `+` 是运算符，`a`、`b` 是运算对象。表达式可能嵌套，于是需要规则决定「先算谁」：

- **优先级（precedence）**：高优先级先算。`a + b * 2` 中 `*` 先于 `+`，等价于 `a + (b * 2)`。
- **结合性（associativity）**：同优先级运算符按结合方向依次计算。加减乘除是**左结合**，`a - b - c` 等价于 `(a - b) - c`；而**赋值是右结合**，`a = b = c` 等价于 `a = (b = c)`。

一张最常用的优先级梯子（从高到低）：

| 级别 | 运算符 | 结合性 |
| --- | --- | --- |
| 最高 | `() :: . -> []` 后缀 | 左 |
| | 前缀 `! ~ ++ -- + - * &`、`sizeof` | 右 |
| | `* / %` | 左 |
| | `+ -` | 左 |
| | `<< >>` | 左 |
| | `< <= > >=` | 左 |
| | `== !=` | 左 |
| | `&&` | 左 |
| | `\|\|` | 左 |
| | `?:` | 右 |
| | `=` `+=` 等赋值 | 右 |
| 最低 | `,` | 左 |

**易错点：** 位运算的优先级低于算术运算、却高于比较运算——`a & 0xFF == 0` 会被解析成 `a & (0xFF == 0)`，与直觉完全相反。写复杂条件时**宁可多打括号**，不要依赖记忆优先级。<span class="marginnote">C++ 的优先级表是历史包袱：`&&`/`||`/`&`/`|` 沿用了 C 语言 1970 年代的设定，与日常数学直觉有出入。真正的经验是：<strong>优先级只记几个常用组合，其余一律加括号</strong>——编译器不会嫌括号多，读者会感激你。</span>

## 2 左值、右值与求值顺序

**左值（lvalue）**指能「站在 `=` 左边」的表达式——代表**内存中的一个对象**，如变量、`v[i]`、`*p`；**右值（rvalue）**指「只能站在右边」的表达式——代表**一个值**，如字面量 `42`、表达式 `a + b` 的结果。判断口诀：**能取地址的就是左值**。<span class="marginnote">左/右值的区分不是纯粹的理论洁癖：函数参数「按左值还是按右值接收」直接决定对象是被拷贝还是被移动——第13章的移动语义、`std::move` 全靠这个二分法运转。</span>

**求值顺序（order of evaluation）**是 C++ 表达式的另一个陷阱：大多数二元运算符**不保证**左右操作数的求值先后。`f() + g()` 可能先调 `f` 也可能先调 `g`，这是实现相关的；而 `i + ++i` 里对 `i` 的读写交织，属于**未定义行为**，结果不可预测。

**例外**只有三组：`&&`、`||` 保证**短路求值**（左侧为假/真就停，右侧不执行）；`?:` 只求值被选中的一支；`,` 从左到右依次求值。这给写代码带来一条铁律：**同一个表达式中不要对同一变量既读又写**，除非其间有短路、条件或序列点隔开。

## 3 自增自减与复合赋值

`++` 与 `--` 有**前置**与**后置**之分：前置版本 `++i` 先加 1、返回新值；后置版本 `i++` 先返回旧值、再自增。<span class="marginnote">对内置类型，前置与后置结果相同、只是值不同；对迭代器与类类型，<strong>后置版本要额外保存旧值，开销更大</strong>——《C++ Primer》第4章的建议是：能前置就前置。</span>

**复合赋值** `+=`、`*=` 等是「取当前值运算再写回」的缩写：`a += 2` 等价于 `a = a + 2`，但只求一次左值（对复杂下标如 `v[i++ * 2]` 有细微差别）。复合赋值省代码、省一次求值，是现代 C++ 的推荐写法。

## 4 位运算与移位

C++ 提供整型上的位运算：`&`（按位与）、`|`（按位或）、`^`（按位异或）、`~`（按位取反）、`<<`（左移）、`>>`（右移）。它们把整数当作二进制位串处理，是标志位、位掩码、底层协议的头号工具：

```cpp
unsigned flags = 0;
flags |= 1u << 3;      // 把第 3 位设为 1
bool has = flags & (1u << 3);   // 检测第 3 位是否为 1
flags ^= (1u << 5);    // 翻转第 5 位
```

**重点：** 左移与右移在数学上有清晰的对应——左移 $k$ 位等于乘以 $2^k$，右移 $k$ 位等于整除 $2^k$。

$$a << k = a \times 2^{k}, \qquad a >> k = \lfloor a / 2^{k} \rfloor$$

因此 `1 << 10` 就是 $2^{10}=1024$，`x >> 1` 就是 `x / 2`（对无符号数）。编译器看到乘以 2 的幂也会自动优化成移位，但**你自己写位运算时一定要用无符号类型**——对带符号类型右移，空出的高位填符号位还是 0 是实现相关的。<span class="marginnote">右移分两种：<strong>逻辑右移</strong>高位补 0、<strong>算术右移</strong>高位补符号位。C++ 对无符号数保证逻辑右移，对带符号数不保证——所以位操作前先确认类型无符号，这是无数二进制协议 bug 的源头。</span>

## 5 公式解析：无符号数的溢出回转

第2章我们见过了无符号的模运算，这里把它算清楚。设 `unsigned` 是 32 位，则一切无符号运算都在模 $2^{32}$ 下进行：

$$u = (u \bmod 2^{32}), \qquad u + 1 \equiv 0 \pmod{2^{32}} \Rightarrow \max_{u} + 1 = 0$$

拆开看：

- **第一步，读式子**：无符号整数可以看成「以 $2^{32}$ 为周期的循环计数器」，从 0 数到 $2^{32}-1$ 后加 1 就回到 0。
- **第二步，算溢出**：`UINT_MAX + 1` 溢出为 `0`，`0 - 1` 变为 `UINT_MAX = 4294967295`。
- **第三步，看后果**：负数转无符号时，`-1` 变成 $2^{32}-1$，`-42` 变成 $2^{32}-42$。上一章 `u + i` 输出 4294967264，正是这个回转的直接体现。

这条规则不是 bug，而是**被标准明确保证的行为**——但「被保证」不等于「符合直觉」。**只要可能溢出，就先用 `long long` 或显式判断**，别让整数悄悄回转。

## 6 sizeof、类型转换与 C++11 的 nullptr

`sizeof` 返回**类型或表达式**所占字节数（`size_t`，编译期常量），例如 `sizeof(int)` 通常是 4，`sizeof(v)` 给出整个 vector 对象（不随元素个数变）——真正算元素个数要靠 `v.size()`。<span class="marginnote">`sizeof` 不参与求值：`sizeof(i++)` 不会真的让 `i` 自增——它只关心「类型多大」。这个「只看类型、不求值」的怪异行为在模板里反而有用，第16章还会碰到。</span>

**类型转换**分两种：**隐式转换**由编译器自动完成（算术转换、整型提升、数组到指针退化），可能丢失信息；**显式转换**用四种 cast——`static_cast`、`const_cast`、`reinterpret_cast`、`dynamic_cast`，语义各不同，第19章专门展开。

C++11 引入 **`nullptr`** 表示「空指针」字面量，取代容易在重载里造成歧义的 `NULL`（`NULL` 常是整数 0，`nullptr` 的类型是 `std::nullptr_t`）。`int *p = nullptr;` 是空指针的标准写法。

**条件运算符与逗号运算符**：**条件运算符** `cond ? a : b` 先求值 `cond`，再只求值被选中的一支——它是表达式，可以嵌在别的表达式里：`int max = a > b ? a : b;`。**逗号运算符** `,` 从左到右依次求值、取最后一个的结果：`i = (j = 1, j + 2);` 先把 `j` 赋 1、再取 `j + 2 == 3`。二者都保证了求值顺序，是「有序列点」的运算符。<span class="marginnote">条件运算符最容易被误读成「if 的缩写」，其实它有严格的要求：<strong>两个分支的类型必须能统一</strong>（否则编译错误），且只求值被选中的一支——副作用只发生在选中的分支。逗号运算符在实际代码里多见于 `for (int i=0, j=n; ...)` 这种「多变量初始化」。</span>

**布尔语境与隐式转换的边界**：`bool` 与算术类型互相转换在 C++ 里是隐式的——`if (ptr)` 判断指针非空、`while (cin)` 判断流状态、`n && m` 把整数当逻辑值。但「整数当布尔」是有代价的：`if (x = 5)` 这类「赋值写成比较」的 bug 编译器默认不报（`x = 5` 的结果是 5、非零、为真）。**对策**：-Wall 打开时对「赋值进条件」有警告；更稳的写法是 `if (5 == x)`（常量在左，把 `=` 写错成 `==` 会编译报错）。这条「常量前置」的旧习惯在现代 C++ 里仍值得保留。<span class="marginnote">`!= 0` 与隐式转 bool 的差别在 C++11 后更精细：<strong>类类型想进布尔语境必须显式提供 `explicit operator bool`</strong>（第14章讲过）——流对象、智能指针都是这么做的。而「整数到 bool」仍是隐式的，因为内置转换规则就是如此，这也是「宁可显式比较、别靠隐式 truthiness」的原因。</span>

**表达式层面的「一行一坑」自查清单**：写完一条复杂表达式，逐项问自己——① 优先级对吗？（拿不准就加括号）；② 同一个变量有没有「既读又写」？（有 → 拆开）；③ 有符号/无符号混了吗？（混 → 统一）；④ 位运算的对象是无符号吗？（不是 → 转）；⑤ 结果可能溢出吗？（可能 → 换宽类型或提前判断）。这五问覆盖了本章绝大多数「运行时才爆」的表达式 bug——养成「写完表达式先自查」的习惯，能省下大量排查时间。

**补充：赋值与复合赋值的差别**：`a = a + 1` 与 `a += 1` 语义等价，但复合赋值只求一次左值（`a` 的地址只取一次），而 `a = a + 1` 对 `a` 的求值可能发生两次（右侧读、左侧写）。对「下标表达式」`v[compute()] += 1` 这类「左值求值昂贵」的场景，复合赋值的差别是真实的。这也是 C++ 标准把「复合赋值」作为一等运算符而非宏展开的原因。

**几个「必须靠求值顺序」的经典写法**：`a && b`（短路：先判 `a`，假则 `b` 不执行）常用于「指针判空后再解引用」——`if (p != nullptr && *p > 0)`；`i < n && vec[i] > 0` 在「下标越界前先判界」；`cond ? f() : g()` 只调用被选中的函数。这三处「顺序敏感」的写法，是短路与条件求值在实际代码里的日常面孔，也是「表达式中既有副作用又要保证顺序」的少数合法场景。<span class="marginnote">对比之下，`f() + g()` 里 `f` 与 `g` 的调用顺序是未定义的——<strong>别在多个实参里都写「带副作用的调用」然后假设从左到右执行</strong>。想严格控制顺序，就把表达式拆成多行语句，用「分号」而不是「求值顺序」来保证。</span>

**承上启下**：表达式的规则是「语言语义」的最后一块拼图——第5章的语句、第6章的函数参数、第14章的运算符重载，全都建立在「表达式求值」之上。吃透本章，后面读任何 C++ 代码都不再被「它到底先算哪个」卡住。

## 7 小结

- **优先级 + 结合性**决定计算顺序；赋值右结合、算术左结合，复杂表达式加括号。
- **左值 = 可取地址的对象**，右值 = 值；这个二分法第13章移动语义还要用。
- **`&&`、`||` 短路求值**，`?:`、`,` 有确定的求值顺序；其余运算符求值顺序未定义，**别在同式内既读又写同一变量**。
- 位运算 `& \| ^ ~ << >>` 是底层工具；`a << k = a·2^k`，右移需确认无符号。
- 无符号数按模 $2^{32}$ **回转**：`UINT_MAX + 1 == 0`，`-1` 变巨大正数。
- `sizeof` 不求值、返回字节数；空指针用 `nullptr` 而非 `NULL`。

在下一节，我们讨论「让程序有顺序地做事」——**语句与流程控制**：if/else、switch、while、for、范围 for，以及 break/continue 与异常语句。
