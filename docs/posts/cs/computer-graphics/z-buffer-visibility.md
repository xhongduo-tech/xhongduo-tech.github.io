## 为什么需要深度缓冲

场景里物体相互遮挡：山挡着后面的房子，房子挡着更远的树。光栅化逐三角形、逐像素地涂色，但**涂色顺序**并不等于遮挡顺序——画家算法（painter's algorithm）试图「从远到近」排序绘制，但遇到互相穿插的物体就破产了。<span class="marginnote">画家算法（painter's algorithm）先画远处的再画近处的，靠覆盖实现遮挡。它要求场景可排序，但三个三角形两两穿插时不存在合法顺序；且对每个三角形排序的成本随三角形数 $n$ 是 $O(n \log n)$。深度缓冲（Z-Buffer）则把排序问题<b>转嫁到每个像素</b>，与三角形数量无关。</span>

**Z-Buffer 算法**（也即深度缓冲，depth buffer）：为每个像素额外记录一个「当前最近的深度值」，新涂色时只画「比已记录的更近」的像素。它简单、O(n) 级别、可并行，是光栅化管线中可见性问题的事实标准。

## 1 Z-Buffer 算法的核心

初始化一个与帧缓冲等大的**深度缓冲**，所有像素的深度置为 $+\infty$（或「最远」）。对每个要光栅化的三角形，逐像素处理：

```
for 每个三角形 T:
  for 每个被 T 覆盖的像素 (x, y):
    if z(x, y) < zbuffer[x, y]:     # 比已记录深度更近
        zbuffer[x, y] = z(x, y)     # 更新深度
        frame[x, y] = color(x, y)   # 写入颜色
```

`z(x, y)` 是三角形在该像素处插值得到的深度值（在 NDC/屏幕空间里）。

**关键性质：绘制顺序无关（order-independent）**。无论三角形先画谁、后画谁，最终每个像素都保留「最近的那个」，结果完全一样。<span class="marginnote">这是 Z-Buffer 打败画家算法的决定性优势：不需要排序，不需要对复杂遮挡做预处理。GPU 可以按任何顺序提交三角形，深度缓冲自动保证正确遮挡。</span>

## 2 深度插值：三角形内每个像素的 z 怎么算

深度 `z(x, y)` 不是常量——三角形是三维的，屏幕空间里每个像素对应三角形上一个不同的三维点。深度由重心坐标插值得到：

$$
z(x, y) = \alpha z_A + \beta z_B + \gamma z_C
$$

其中 $(\alpha, \beta, \gamma)$ 是像素在三角形 $ABC$ 中的重心坐标。<span class="marginnote">注意：屏幕空间的重心坐标插值在透视投影下需要<b>透视校正</b>——直接对屏幕空间的 $z$ 做线性插值会得到错误深度（因为投影非线性）。标准做法是对「深度除以 $w$」插值再乘回，见《纹理映射》一节的透视校正插值。</span>

这个插值在光栅化里是「免费的」：上一节的边缘函数 $e_i$ 恰好给出重心坐标（面积比），深度插值只是把重心坐标点乘三个顶点的深度——没有额外开销。

## 3 公式解析：比较、更新、写入三步

把 Z-Buffer 的单像素处理拆成三个动作：

$$
\text{if}\quad z_{\text{new}} < z_{\text{buf}}[x,y]: \quad z_{\text{buf}}[x,y] \gets z_{\text{new}},\; \text{frame}[x,y] \gets C
$$

- **第一步，比较**：新片元深度 $z_{\text{new}}$ 与缓冲里存的 $z_{\text{buf}}$ 比较。$z_{\text{new}}$ 更小（更近）才继续，否则这个片元被丢弃——它被更近的物体挡住了。
- **第二步，更新深度**：$z_{\text{buf}}$ 记录更小的新值，让「目前最近」的深度始终保持最新。
- **第三步，写入颜色**：只有深度获胜的片元才写颜色，保证屏幕上每个像素显示的是可见几何。

## 4 Z-Buffer 的复杂度与并行性

Z-Buffer 的复杂度分析非常优雅：

- **空间**：一个与帧缓冲同尺寸的深度缓冲（现代 24 bit 或 32 bit 浮点）。
- **时间**：每个片元 O(1) 的「比较 + 可能写入」，总时间 O(三角形覆盖的片元总数)，与三角形数量线性相关、与场景复杂度无关。
- **并行**：每个像素的深度比较只依赖它自己的缓冲项，互不干扰——GPU 天然可以并行处理所有像素。<span class="marginnote">Z-Buffer 的<b>每个像素独立</b>是它成为 GPU 标准算法的根本原因：不需要全局排序、不需要跨像素通信，正好适配 SIMD 式的并行架构。相较之下，画家算法的排序无法这样并行。</span>

## 5 Z-Buffer 的经典陷阱

- **Z-fighting（深度冲突）**：两个几乎共面的表面（如地面上贴一张贴花）深度值相近，浮点精度无法区分先后，像素在两者间闪烁。<span class="marginnote">透视投影把深度非线性压缩（见《透视投影》），远处深度值分辨率更低，Z-fighting 更容易在远处发生。工程对策：近平面尽量远、用更高精度深度缓冲、对数深度编码，或把贴花略微抬高（polygon offset）。</span>
- **深度精度分配**：透视投影下 $z' = A + B/z$，深度精度集中在近处、远处很粗糙。理解这条曲线才能选对近远平面的设置。
- **透明物体**：Z-Buffer 处理不了透明度——半透明物体需要特殊排序（按深度从远到近混合），否则「近处透明挡不住远处物体」会出错。

## 6 Z-Buffer 与后续内容的连接

Z-Buffer 看似只是一个小算法，但它是整个渲染管线的一个枢纽：

- **阴影映射（Shadow Mapping）**：从光源视角渲染一张深度图，就是 Z-Buffer 的「相机在光源处」用法。
- **MSAA 深度测试**：上一节提过，MSAA 把深度测试移到子采样点级，正建立在 Z-Buffer 之上。
- **延迟渲染**：G-Buffer 里同样存深度，用于重建世界坐标与做光照。<span class="marginnote">「深度缓冲」在现代引擎里几乎是万能的中间表示：既可以做遮挡，也能做屏幕空间环境光遮蔽（SSAO）、雾效、运动模糊的输入。它从一个「排除遮挡」的算法，长成了整个屏幕空间特效的基础设施。</span>

## 6 深度缓冲的工程细节：精度、比较函数与带宽

Z-Buffer 看似简单，工程细节决定成败。几个关键决策：

**深度精度**：

- **16 位**：精度差，远处 Z-fighting 严重——只用于极低端。
- **24 位定点**：传统标准，精度分配在近处密、远处疏（透视非线性）。
- **32 位浮点**：动态范围大，近远都能保留精度——现代引擎默认。

**深度比较函数**：默认是「小于等于」（LESS_EQUAL，更新深度与颜色）。但特定效果要改比较函数——如「深度越大越近」的反 Z 缓冲（reversed-Z）用 GREATER，它把近处精度提高（浮点深度在 1 附近精度最高）。**reversed-Z 是现代引擎的标准**——同样的 24 位深度，反 Z 让近处精度远好于正 Z。

**深度写入与测试分离**：深度测试（比较）与深度写入（更新）可以分开开关。典型用途：半透明物体「测试深度但不写深度」——让半透明被不透明遮挡，但半透明之间不互相遮挡（避免「排序问题」）。

**辨析｜易错点：** 三个高频坑：

1. **深度测试与写入的开关组合**——「测试开、写入关」用于透明，「测试关、写入开」用于「先写深度再画」的预处理 pass——用错组合会「画面乱掉」。
2. **深度缓冲的格式切换成本**——切换深度格式（24→32）或分辨率会「清空深度」，性能骤降——尽量保持格式稳定。
3. **深度偏移（depth bias）的应用位置**——多边形偏移（polygon offset）在光栅化时加深度，用于贴花、阴影，偏移方向错会让「贴花陷进地面」。

**为什么深度是「渲染管线里最被忽视的调优对象」**——它决定带宽（每帧读写）、精度（Z-fighting）、以及许多效果的正确性。理解深度缓冲的工程细节，是调试「闪烁」「错位」「透明乱序」三类问题的钥匙。

## 7 深度缓冲的一页速查

把 Z-Buffer 的关键点压成速查：

- **核心**：每像素记录「最近深度」，更近才写入——绘制顺序无关。
- **深度来源**：重心坐标插值（透视投影下要透视校正）。
- **精度**：24 位定点（传统）、32 位浮点（现代）；透视下近密远疏。
- **reversed-Z**：反 Z 缓冲让近处精度更高——现代引擎标准。
- **透明**：深度测试与写入分离——透明「测不写」。
- **经典坑**：Z-fighting（近远平面、bias）、深度精度不均、透明排序。

**一句话记忆**：「比深度、近者胜、顺序无关」——抓住这句，Z-Buffer 的一切都能推出来。

## 8 小结

- **Z-Buffer = 每像素记录最近深度 + 更近才写入**，绘制顺序无关，O(n) 线性时间。
- 深度用重心坐标在三角形内插值，透视投影下需要透视校正。
- 每个像素独立，天然并行，是 GPU 的标准可见性算法。
- 经典陷阱：**Z-fighting**（深度冲突）、透视深度精度不均、透明物体排序。
