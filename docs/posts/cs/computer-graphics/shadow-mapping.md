## 为什么阴影这么难做

阴影是「光被遮挡」的视觉结果。光栅化不知道「光路」，所以不能像光线追踪那样直接问「这个点被挡了吗」。**阴影映射（Shadow Mapping）** 用「从光源拍深度图」的巧妙 trick 判断遮挡——它是实时渲染阴影的事实标准，从 1978 年的 Lanczos-Carter 到 1990 年代被游戏全面采用，统治至今。<span class="marginnote">阴影映射的核心思想：<strong>把光源当成一架相机，从光源视角渲染场景，只记录深度（不记录颜色），得到一张「光深度图」（shadow map）</strong>。之后渲染正常视角时，每个点变换到光源视角，比较「它的深度」与「光深度图里存的值」——若它比光深度图远，说明它被「更近的物体」挡住了，处于阴影。</span>

本节讲阴影映射的原理与它的两大走样问题——理解走样，是理解 PCF、CSM、VSM 等全部改进的前提。

## 1 阴影映射的两遍渲染

**第一遍（光视角）**：从光源位置用正交/透视投影渲染场景，只写深度到**阴影贴图（shadow map）**：

$$
z_{\text{shadow}}(\text{光源像素}) = \text{该点离光源的最近深度}
$$

**第二遍（相机视角）**：正常渲染。对每个片元 $p$：

1. 把 $p$ 变换到光源视角，得到光源像素坐标与深度 $z_p$。
2. 采样阴影贴图，得到「光看到的最近深度」$z_{\text{shadow}}$。
3. **比较**：$z_p > z_{\text{shadow}}$ → 被遮挡 → 阴影；否则 → 可见。

**核心公式**：阴影判定 = 深度比较。这个「先拍深度、再比深度」的流程，本质是用 Z-Buffer 的两次使用判断遮挡。<span class="marginnote">阴影映射的「两遍」：<strong>第一遍用 Z-Buffer 记录「光看到的最近点」，第二遍用 Z-Buffer 的深度比较判断「这个点是否比光看到的最近点更远」</strong>——两次 Z-Buffer 的组合，实现了「遮挡查询」。它完全在光栅化框架内工作，不需要光线追踪——这就是它统治实时渲染的原因。</span>

## 2 阴影映射的三大走样问题

阴影映射教科书级地演示了「走样」的三种形态：

**问题一：锯齿（阴影边缘阶梯）**。阴影贴图分辨率有限，阴影边缘的判定是「二值」的（要么阴影要么不阴影），像素级的深度比较产生锯齿边缘。

**问题二：自阴影失真（shadow acne / 阴影粉刺）**。表面自身在阴影贴图里，由于浮点精度，同一表面上的点深度比较「时而通过时而失败」——出现明暗相间的「粉刺」点阵。解法：**深度偏移（depth bias）**——比较时给 $z_p$ 加一个小偏移。

**问题三：彼得潘效应（Peter Panning）**。偏移加得太大，阴影「脱离」物体根部——物体看起来「漂浮」在阴影上方。<span class="marginnote">「粉刺与彼得潘是同一枚硬币的两面」：<strong>深度偏移太小 → 自阴影粉刺（浮点误差暴露）；太大 → 彼得潘效应（阴影脱离）</strong>——偏移是「误差容忍」与「几何正确」之间的走钢丝。现代引擎用「斜率偏移」（偏移量随表面坡度自适应）在两者间平衡。</span>

## 3 公式解析：阴影判定的深度比较

把阴影判定的核心步骤精确化：

$$
\text{inShadow}(p) = \begin{cases} \text{true}, & z_p + \text{bias} > z_{\text{shadow}}(u_s, v_s) \\ \text{false}, & \text{otherwise} \end{cases}
$$

- **第一步，变换到光源空间**：$p$ 经光源的 view-projection 矩阵变换，得到光源像素坐标 $(u_s, v_s)$ 与深度 $z_p$。
- **第二步，采样阴影贴图**：用 $(u_s, v_s)$ 采样，得到「光在 $p$ 处看到的最近深度」$z_{\text{shadow}}$。
- **第三步，比较（含偏移）**：$z_p + \text{bias} > z_{\text{shadow}}$ 意味着「$p$ 比光看到的最近点还远」——$p$ 被遮挡。偏移 $\text{bias}$ 防止浮点误差把「自己」误判为「遮挡者」。
- **第四步，输出**：阴影处把光照乘以 0（或环境项），得到暗部。

**辨析｜易错点：** 三个高频坑——**偏移的符号**（要在被测试深度上加，方向搞反反而加重粉刺）、**阴影贴图采样**（默认最近邻会加剧锯齿，需要 PCF 软化）、以及**比较的方向**（$z_p > z_{\text{shadow}}$ 是「更远=被挡」，方向写反阴影会「内外反转」）。

## 4 从硬阴影到软阴影：为什么要 PCF

阴影映射产生的是**硬阴影**——每个点要么全影要么全亮，边缘生硬。真实光源有面积，阴影边缘有半影（软边）。**PCF（Percentage Closer Filtering）** 的思路：**不比较单个像素，而是比较阴影贴图周围一片区域**，把「被遮挡的比例」当阴影浓度：

$$
\text{shadow}(p) = \frac{\#\{ \text{邻域采样中 } z_p + \text{bias} > z_{\text{shadow}} \}}{\#\{ \text{邻域采样总数} \}}
$$

采样 $3\times3$ 或 $5\times5$ 的阴影贴图邻域，统计「被挡的百分比」——边缘处百分比从 0 渐变到 1，产生柔和过渡。<span class="marginnote">PCF 的「百分比」让它既是反走样（软化锯齿）又是软阴影（模拟半影）：<strong>它对「深度比较」做滤波（不是对颜色滤波）</strong>——比较是二值的，但「多个比较的平均」是连续的，边缘自然过渡。PCF 是阴影映射改进的第一步，也是理解后续 CSM、VSM 的起点。</span>

## 5 阴影映射的局限

阴影映射虽然在实时渲染里无处不在，但边界要诚实：

**只能处理「点/方向光」的直接阴影**：面光源、软阴影需要更多技巧。
**分辨率受限**：大场景阴影贴图分辨率不够，远处阴影模糊——需要 CSM 分层。
**自阴影与偏移的张力**：粉刺与彼得潘难以两全。
**半透明与体积光**：阴影贴图记录不透光深度，无法表达「半影」的半透明穿透。

这些局限催生了整个「阴影映射改进」家族——下一节逐一展开 PCF、CSM、VSM。<span class="marginnote">「阴影映射是『够用但不完美』的阴影方案」：<strong>它快、硬件友好、无场景限制，但硬阴影、分辨率、偏移三座大山需要一层层补丁</strong>。从 PCF（软边）到 CSM（大场景分层）到 VSM（可滤波深度），每个改进都是「补一个洞」。理解阴影映射的原理与走样，就理解了整个阴影改进家族为什么长那样。</span>

## 6 阴影映射的实现细节：从深度图到判定

把阴影映射的工程实现拆开，几个「决定成败」的细节值得展开：

**第一遍渲染（生成阴影图）的注意点**：

- **光源视角的投影**：方向光用正交投影（平行光没有透视），点光源用透视投影 + 立方体阴影图（六面）。
- **只写深度**：阴影图 pass 不输出颜色、不做光照——只跑「深度输出」的最小管线，省掉片元着色器开销。
- **深度格式**：阴影图用「深度专用格式」（D16/D24/D32），配合「深度比较采样器」——采样时直接返回「比较结果」，省掉手动比较。

**第二遍渲染（判定）的注意点**：

- **变换矩阵**：物体顶点经「光源的 view-projection 矩阵」变换，得到光源视角的 NDC——这一步与《投影》篇的矩阵链条完全一致，只是「相机换成光源」。
- **深度比较采样器**：现代 API 用 **比较采样器**（comparison sampler，GLSL 里是 `sampler2DShadow`、HLSL 里是 `SamplerComparisonState`，即深度比较纹理）——一次采样返回「$z_p$ 与存储深度比较的结果」，硬件原生支持，避免「采样深度再比较」的额外读写。
- **PCF 采样**：对深度比较采样器做邻域多次采样/加权平均——硬件支持「一次采样多个比较结果并平均」，这就是 PCF 的硬件基础。

**一个典型实现的伪代码结构**：

```text
// 第一遍：从光源视角渲染深度图（只写深度，不输出颜色）
bind_depth_target();
set_view_projection(light_vp);          // 光源的 view-projection
for (mesh : scene)
    draw_depth_only(mesh);              // 片元着色器省略，只写深度

// 第二遍：相机视角渲染，用深度比较采样器判阴影
bind_framebuffer(color_target);
set_view_projection(camera_vp);
bind_shadow_map(shadow_tex);
for (mesh : scene)
    for (fragment : rasterize(mesh))
        vec3 p_light = light_vp * fragment.position;   // 变换到光源空间
        float z = p_light.z + bias;                     // 加偏移防粉刺
        fragment.shadow = compare(shadow_tex, p_light.xy, z);
        fragment.color = shade(fragment) * (1.0 - fragment.shadow);
```

**辨析｜易错点：** 三个工程坑：

1. **阴影图的分辨率 vs 覆盖范围**——同一分辨率覆盖的场景越大，每像素代表的世界越大，锯齿越明显——这就是 CSM 存在的理由（按距离分级）。
2. **光源空间矩阵的裁剪**——物体超出光源视锥，阴影图里没有对应深度，判定「默认被挡」或「默认可见」——要处理「越界」的边界情况。
3. **双向 PCF 的陷阱**——PCF 的滤波核在屏幕空间做，阴影边缘「软的方向」可能与几何不匹配——PCSS 用「遮挡物距离」修正方向。

理解阴影映射的实现细节，你就从「知道原理」进到「能写出/调好阴影渲染」——它是「多 pass 渲染」的经典范例，也是理解一切「把光当相机」技术的基础。

## 7 小结

- **阴影映射 = 两遍渲染**：第一遍从光源拍深度图，第二遍比深度判遮挡。
- 判定公式：$z_p + \text{bias} > z_{\text{shadow}} \Rightarrow$ 阴影——深度比较 + 偏移。
- 三大走样：**锯齿**（分辨率）、**自阴影粉刺**（浮点、靠 bias）、**彼得潘**（bias 过头）。
- **PCF** 对深度比较做邻域滤波，把硬阴影软化成半影——阴影改进的起点。
- 局限：硬阴影、分辨率、半透明——引出一整族阴影改进方法。
