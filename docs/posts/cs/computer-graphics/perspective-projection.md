## 为什么透视投影是「挤压」

上一节的正交投影保持平行、没有近大远小——工程图纸式的硬朗。但人眼与相机看到的世界不是这样：**远处的东西小、近处的东西大**，平行铁轨在视野尽头汇聚。这种「远小近大」的投影叫**透视投影（perspective projection）**，它才是渲染真实感画面的默认选择。<span class="marginnote">透视投影的几何模型是一个<b>视锥体（frustum）</b>：相机在锥尖，近平面（$z=-n$）与远平面（$z=-f$）之间是被看到的空间。视锥体在远处横截面大，所以同样大小的物体在远处占的屏幕面积小。</span>

GAMES101 的关键洞见是：**透视投影 = 把视锥体「挤压」成正交投影能处理的长方体，再做正交投影**。挤压是一个非线性操作，但它在齐次坐标里可以用一个线性矩阵表示——这正是上一节引入齐次坐标的真正回报。

## 1 挤压变换：把视锥体变成长方体

设点 $(x, y, z)$ 在视锥体内。我们想找一个变换，把每个点映射到 $(x', y', z')$，使得：

- $x'$、$y'$ 被「压」得与 $z$ 成反比：同样大小的物体，离得越远（$|z|$ 越大）屏幕投影越小。
- $z'$ 保持深度顺序，供深度缓冲使用。

从「近大远小」的几何关系出发，$x'$ 与 $y'$ 的挤压规律是：

$$
x' = \frac{n}{z}\, x, \qquad y' = \frac{n}{z}\, y
$$

这里 $z$ 是负的（点在相机前方），$n$ 是近平面距离。直觉：离相机越远的点（$|z|$ 大），分母越大，$x'$、$y'$ 越小——正是「越远越小」的数学表达。<span class="marginnote">为什么是 $n/z$ 而非别的？因为投影到近平面 $z=-n$ 上：用相似三角形，屏幕上的坐标 = $\frac{n}{|z|}$ 倍的三维坐标。$z=-n$ 处的点缩放系数为 1，$z$ 更负（更远）的点系数小于 1。</span>

## 2 齐次坐标大显身手：透视除法

现在关键一步来了。$x' = \frac{n}{z}x$ 显然不是线性变换（有除法、有 $1/z$），没法写成普通矩阵。但**在齐次坐标里可以**！我们构造一个矩阵 $M_{\text{persp}\to\text{ortho}}$，使得：

$$
\begin{pmatrix} x \\ y \\ z \\ 1 \end{pmatrix} \xrightarrow{M_{\text{persp}\to\text{ortho}}} \begin{pmatrix} n x \\ n y \\ \text{??} \\ z \end{pmatrix}
$$

然后做**透视除法**：把齐次坐标 $(nx, ny, \text{??}, z)$ 除以 $w = z$，得到 $\left(\frac{nx}{z}, \frac{ny}{z}, \frac{\text{??}}{z}, 1\right)$——前两维恰好是想要的 $\frac{n}{z}x, \frac{n}{z}y$。<span class="marginnote">这一手就是「先写一个看似不能表示的变换，让 $w$ 变成 $z$，再靠除以 $w$ 完成非线性」。透视除法（perspective divide）是整个图形学最优雅的套路之一——它把几何上非线性的投影，硬塞进了线性矩阵的框架里。</span>

矩阵里的「$\text{??}$」是 $z'w$ 的未知数，我们下一节解它。

## 3 构造透视矩阵：解出第三行

透视矩阵形如：

$$
M_{\text{persp}\to\text{ortho}} = \begin{pmatrix} n & 0 & 0 & 0 \\ 0 & n & 0 & 0 \\ 0 & 0 & A & B \\ 0 & 0 & 1 & 0 \end{pmatrix}
$$

前两行来自 $x', y'$ 的挤压。第三行 $(0,0,A,B)$ 决定 $z$ 的变换，要求：(1) 透视除法后 $z$ 仍然落在 $[-1,1]$；(2) 近平面 $z=-n$ 上的点映射到 $z'=-1$，远平面 $z=-f$ 映射到 $z'=1$。解这两个条件：

$$
A = \frac{n+f}{n-f}, \qquad B = \frac{2nf}{f-n}
$$

代入验证：对 $z=-n$，$w=-n$，透视除法后 $z' = \frac{A(-n)+B}{-n} = -1$；对 $z=-f$，$z' = \frac{A(-f)+B}{-f} = 1$。两个边界都命中。

## 4 公式解析：为什么近平面映射到 -1、远平面映射到 1

我们把「第三行怎么解出来」这一步完整拆开。设透视除法后 $z' = 1$ 当且仅当 $z = -f$、$z' = -1$ 当且仅当 $z = -n$，代入第三行方程：

- **第一步，列出约束**：矩阵作用后齐次坐标 $w = z$，所以 $z' = \frac{Az + B}{z} = A + \frac{B}{z}$。
- **第二步，代入近平面**：$z = -n$ 时要求 $z' = -1$，即 $A - \frac{B}{n} = -1$。
- **第三步，代入远平面**：$z = -f$ 时要求 $z' = 1$，即 $A - \frac{B}{f} = 1$。
- **第四步，联立求解**：两式相减得 $B\left(\frac{1}{n} - \frac{1}{f}\right) = 2$，即 $B = \frac{2nf}{f-n}$；代回得 $A = \frac{n+f}{n-f}$。

**辨析｜易错点：** 透视矩阵的符号是最容易写错的地方。因为 $n, f$ 是正的距离，但坐标 $z$ 是负的，第三行常数项 $B = \frac{2nf}{f-n} > 0$、一次项系数 $A = \frac{n+f}{n-f} < 0$。若把 $z$ 坐标当成正的来推（例如误设 $w = -z$），整个深度顺序会反转。另一个常见错误是忘记「先 $M_{\text{persp}\to\text{ortho}}$ 再除以 $w$」两步缺一不可——只做矩阵乘法不做除法，画面会被错误拉伸。

## 5 完整透视投影 = 挤压 + 正交

透视投影的完整矩阵是：

$$
M_{\text{persp}} = M_{\text{ortho}}\; M_{\text{persp}\to\text{ortho}}
$$

先挤压（非线性藏在 $w$ 里），再做正交投影（线性），最终经过透视除法得到 NDC 坐标。<span class="marginnote">现代图形 API（OpenGL/DirectX）把「除以 $w$」放进硬件固定管线，程序员只需设置 $M_{\text{persp}}$ 矩阵。透视除法之后，$w$ 变成 1，齐次坐标回到普通坐标——一个完整的投影变换就这样把三维世界拍扁到了 $[-1,1]^3$。</span>

透视投影的两个关键后果：

**近大远小**：离相机近的物体占据更多屏幕面积，带来真实的纵深观感。
**深度非线性压缩**：$z' = A + \frac{B}{z}$ 不是线性函数，$z$ 越靠近远平面变化越缓慢——这导致远距离的深度分辨率差，是 Z-fighting（闪烁）的根源。<span class="marginnote">Z-fighting 是透视投影的经典副作用：远处的两个物体深度值几乎相同，深度缓冲无法区分先后，画面疯狂闪烁。工程解法包括「近平面尽量远」「加深深度缓冲位数」「用对数深度」——这些都建立在对 $z' = A + B/z$ 的理解之上。</span>

## 6 透视投影的工程参数：视场角与宽高比

投影矩阵里的「几何参数」直接决定「画面长什么样」，理解它们才能「把相机调对」。

**垂直视场角（FOV）**：控制「视野多宽」，在投影矩阵里的体现是「近平面半高」：

$$
\text{half height} = \tan\left(\frac{\text{fov}_y}{2}\right)
$$

- $\text{fov}_y$ 大（如 90°）→ 视野宽、透视夸张（近大远小更明显）。
- $\text{fov}_y$ 小（如 30°）→ 视野窄、像「长焦镜头」，透视压缩。
- **fov 与「相机距离」的关系**：同样的构图，fov 大 + 相机近 = fov 小 + 相机远——游戏里「调整相机距离保持构图」时，fov 要联动。

**宽高比（aspect ratio）**：屏幕宽高比，进投影矩阵的横向缩放：

$$
x' = \frac{x}{a} \cdot \frac{1}{\tan(\text{fov}/2)} \cdots
$$

- 宽高比错 → 画面「横向拉伸/压缩」（圆变椭圆）。
- 窗口 resize 时，宽高比必须跟随投影矩阵更新——这是「窗口变扁物体变形」的经典 bug 来源。

**近远平面**：决定深度精度（Z-fighting）与裁剪。近平面太近 → 近处深度精度浪费（透视深度非线性集中在近处）；太远 → 近处的精度被「让给」远处。**「近平面尽量远」是减少 Z-fighting 的第一招**。

**辨析｜易错点：** 三个高频坑：

1. **fov 用度数还是弧度**——投影矩阵里 $\tan$ 的参数是弧度——传度数不转弧度，画面「扭曲」。
2. **fov 是「垂直」还是「水平」**——图形 API 约定垂直 fov——想按水平 fov 设，要乘宽高比换算——搞混则「横向视野不对」。
3. **宽高比用「像素宽/高」还是「物理宽/高」**——非正方形像素（老 CRT、某些输出）要区分——现代屏几乎都是正方形像素，但跨平台仍要确认。

**投影参数是「相机的语言」**——理解 fov、宽高比、近远平面的数学，你就知道「调哪个参数让画面变成什么样」。

## 7 小结

- **透视投影 = 挤压（$M_{\text{persp}\to\text{ortho}}$）+ 正交投影**，挤压的关键是让 $w = z$。
- 挤压是**非线性**的，但通过齐次坐标写成矩阵，再用**透视除法（除以 $w$）**完成。
- 第三行 $A = \frac{n+f}{n-f}$、$B = \frac{2nf}{f-n}$ 由「近平面 → $-1$、远平面 → $+1$」解出。
- 深度被非线性压缩为 $z' = A + B/z$，远距离精度差，是 Z-fighting 的根源。

在下一节，我们将离开数学空间，进入**屏幕空间**——用视口变换把标准立方体铺到具体的像素网格上。
