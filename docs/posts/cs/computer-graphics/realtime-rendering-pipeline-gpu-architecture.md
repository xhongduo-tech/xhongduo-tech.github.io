## 为什么实时渲染「难」

影视离线渲染一帧算几小时；游戏要一秒 60 帧——**每帧只有约 16 毫秒**。实时渲染就是在「16ms 预算」内完成从几何到像素的全过程。它靠的不是「更聪明的算法」，而主要是 **GPU（Graphics Processing Unit）** 的并行架构——理解实时渲染，必须理解 GPU。<span class="marginnote">实时渲染的约束是「<strong>16ms 预算</strong>」：<strong>一帧要在一秒的 1/60 内完成，任何超过预算的阶段都会掉帧</strong>。这个预算驱动了实时渲染的一切设计——能预计算的预计算、能近似的近似、能并行的并行。GPU 之所以能在这个预算内渲染上亿三角形，靠的是「<strong>成百上千个并行核 + 流水线</strong>」的架构。</span>

本节俯瞰实时渲染管线与 GPU 架构：从「软件管线的三阶段」到「硬件如何把它并行化」，为后面阴影映射、延迟渲染等实时技术提供架构背景。

## 1 实时管线的三阶段：顶点 → 光栅化 → 片元

回顾《图形管线》一节的经典管线，实时渲染把它固化成 GPU 的三个硬件阶段：

1. **顶点阶段**：顶点着色器（可编程）处理每个顶点——变换、顶点光照。输入顶点数组，输出屏幕空间顶点。
2. **光栅化**（固定功能）：三角形遍历、插值——把顶点变成片元。
3. **片元阶段**：片元着色器（可编程）处理每个片元——纹理采样、逐像素光照。经深度测试、混合写帧缓冲。

**「可编程 + 固定」的混合**是 GPU 管线的本质：程序员控制顶点/片元着色器，硬件负责光栅化、深度测试等固定操作。<span class="marginnote">「可编程（着色器）+ 固定功能（光栅化/测试）」是 GPU 的设计哲学：<strong>把「需要表达力的计算」开放给程序员（着色器），把「吞吐量极大的机械操作」固化进硬件（光栅化、深度测试、混合）</strong>——既灵活又高效。现代 GPU 的着色器几乎全能（连光栅化都能绕过去做通用计算），但「顶点-片元」的分工仍是经典框架。</span>

## 2 GPU 的并行架构：SIMD 与千核

GPU 与 CPU 的根本区别在**并行粒度**：

- **CPU**：几个强核，每核能乱序执行复杂逻辑，擅长「串行 + 分支」。
- **GPU**：成百上千个弱核，**SIMD**（单指令多数据）——同一指令同时处理大量数据，擅长「大量相同计算」。

GPU 的组织层级：

```
GPU
 └─ 若干 SM（流多处理器）
     └─ 数百个 CUDA 核（流处理器）
         └─ 以 warp/wavefront（32 线程）为单位并行执行
```

**warp**（32 线程）是 GPU 调度的基本单位：一个 warp 里的 32 个线程执行**同一条指令**，但处理不同的数据（比如 32 个不同顶点）。<span class="marginnote">「warp 是 GPU 的『灵魂单位』」：<strong>一个 warp 的 32 个线程同执行一条指令，只是数据不同</strong>——这就是 SIMT（单指令多线程）。代价是「<strong>分支分歧</strong>」：warp 里若一半线程走 if、一半走 else，两部分要串行执行（都执行一遍再屏蔽），性能减半。理解 warp，就理解了为什么 GPU 代码要「少分支、内存连续」。</span>

## 3 管线的并行：为什么不是「先完成 A 再 B」

实时管线能跑到 60fps，不仅因为核多，更因为**管线并行（pipeline parallelism）**：

```
时间 →
顶点  v1  v2  v3  v4  v5 ...
光栅  |   v1  v2  v3  v4 ...
片元  |   |   v1  v2  v3 ...
```

当第一个三角形还在光栅化时，第二个三角形已经在顶点阶段——**不同阶段同时处理不同数据**。这让管线的「吞吐量」由最慢阶段决定，而不是所有阶段之和。<span class="marginnote">「流水线让吞吐量 = 最慢阶段的速率」是工业流水线的通用规律：<strong>光栅化器还在处理三角形 1 时，顶点着色器已经在算三角形 2——各阶段「接力」而非「排队」</strong>。瓶颈阶段（通常是片元或光栅化）决定整体帧率，这就是为什么「填充率」（每秒多少片元）是 GPU 的关键指标。</span>

## 4 延迟与吞吐：GPU 怎么「藏」内存延迟

GPU 核要访问显存（纹理、缓冲区），而显存延迟高达数百周期——GPU 不像 CPU 那样「等待」，而是**用并行隐藏延迟（latency hiding）**：

- 一个 warp 等待内存时，GPU **切换到另一个 warp** 执行。
- 只要「可切换的 warp」足够多，内存等待就被「掩盖」——GPU 保持满载。

**「算得越多，藏得越好」**：GPU 需要足够多的并行工作来掩盖内存延迟，否则「吃不饱」。这解释了为什么 GPU 代码要「尽量开很多线程」。<span class="marginnote">「GPU 靠并行吃饭」：<strong>单个线程的内存等待被其他线程的运算掩盖——只要并发线程足够多，GPU 就永远「有事做」</strong>。这与 CPU 的「缓存 + 乱序」策略截然不同。理解「延迟隐藏」，就理解为什么 GPU 不适合「少量但复杂的任务」——它天生为「海量简单任务」设计。</span>

## 5 实时渲染的常用加速技巧

在 16ms 预算内，实时渲染的常用「省」法：

- **LOD（Level of Detail）**：远处用低模、近处用高模——三角形预算自适应。
- **视锥剔除（frustum culling）**：屏幕外的物体不提交——宽相排除。
- **遮挡剔除（occlusion culling）**：被挡住的物体不渲染。
- **纹理流送（streaming）**：只加载可见纹理的 Mipmap 层。
- **TAA / 降噪**：用少量采样 + 时间/后处理补质量。

「剔除 + LOD + 预计算」是实时渲染的三板斧——把「算不到的」排除，把「算得贵的」预存。<span class="marginnote">「实时渲染 = 算得少 + 预存得多」：<strong>剔除让 GPU 不碰看不见的东西（省三角形），LOD 让远处的东西便宜（省精度），预计算把阴影/AO 提前烤好（省运行时）</strong>。现代实时渲染的每一项技术几乎都是「把计算从每帧挪到预处理、或从全屏挪到局部」的变形——理解这个总原则，就理解了实时渲染的每一项优化。</span>

## 6 从管线到实时技术的地图

实时渲染的后续技术都建立在「管线 + GPU」之上：

- **阴影映射**：多渲染一次「从光源看」的深度图——用管线多 pass。
- **延迟渲染**：改管线结构——先存 G-Buffer，再逐像素光照。
- **后处理**：把整帧当纹理再渲染一遍——全屏 pass。
- **实时 GI**：在管线里加「光传播」的近似步骤。

「16ms 预算 + 管线并行 + 剔除预计算」是理解所有这些技术的框架——它们都是「在预算内把光算得更真」的不同策略。<span class="marginnote">「实时渲染的每一项技术都是『预算内交易』」：<strong>阴影映射用「多一次渲染 pass」换「真实阴影」，延迟渲染用「多一张 G-Buffer」换「大量动态光源」，TAA 用「历史帧」换「反走样」</strong>——每个技术都是一个「花多少换什么」的工程决策。理解了管线与 GPU 的约束，就能理解这些交易为什么存在、怎么权衡。</span>

## 6 GPU 性能的度量与瓶颈定位

理解 GPU 架构的最终目的是「让渲染变快」——几个性能度量工具值得掌握。

**关键指标**：

- **占用率（occupancy）**：SM 上活跃的 warp 数 / 能容纳的最大 warp 数——占用率低说明「线程不够」或「资源受限」——GPU「吃不饱」。
- **带宽（bandwidth）**：显存读写的吞吐——纹理采样、缓冲读写都耗带宽——「带宽瓶颈」是渲染的常见瓶颈（尤其移动端）。
- **填充率（fill rate）**：每秒能光栅化的片元数——全屏后处理、过采样时受限于它。
- **几何吞吐（geometry throughput）**：每秒能处理的顶点/三角形——顶点着色器重或三角形太多时受限于它。

**瓶颈定位的「哪个满」**：渲染慢，先问「是哪个阶段满」：

- **CPU 提交瓶颈**：draw call 太多，CPU 提交跟不上 GPU——「合批（batching）」解决。
- **几何瓶颈**：顶点/三角形太多——「LOD + 剔除」解决。
- **片元瓶颈**：片元着色器太重或填充率满——「降分辨率 + 减后处理」解决。
- **带宽瓶颈**：纹理/缓冲读写太多——「压缩纹理 + 减缓冲」解决。

**Profiling 工具**：Nsight、PIX、RenderDoc 显示「每个阶段的耗时」——「看哪个阶段满」是优化第一步。

**辨析｜易错点：** 三个优化误判：

1. **「瓶颈只有一个，但会移动」**——优化掉几何瓶颈，片元瓶颈可能冒出来——「再 profile 一遍」是常态。
2. **「看平均不看峰值」**——帧率平均 60，但某帧卡顿（峰值 100ms）——「看帧时间分布」而非「平均帧率」。
3. **「优化 GPU 不看 CPU」**——CPU 提交跟不上（draw call 多），GPU 再快也没用——「CPU-GPU 平衡」是优化全景。

**「GPU 架构知识 → 性能优化的罗盘」**——理解了占用率、带宽、瓶颈定位，你就知道「渲染慢时先看哪、怎么对症下药」。

## 7 小结

- **实时渲染 = 16ms 预算**：一切技术都在预算内取舍。
- 管线三阶段：顶点 → 光栅化 → 片元；可编程 + 固定功能混合。
- **GPU = 千核 SIMD**：warp（32 线程）同指令并行，分支分歧是性能杀手。
- **管线并行**让吞吐量由最慢阶段决定；**延迟隐藏**靠并行掩盖内存等待。
- 三板斧：**剔除 + LOD + 预计算**——省三角形、省精度、省运行时。
- 阴影映射、延迟渲染、实时 GI 都是「预算内交易」，本册后续逐一展开。
