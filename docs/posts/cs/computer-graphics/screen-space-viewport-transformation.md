## 为什么需要视口变换

经过模型、视图、投影三步，三维几何已经被塞进 $[-1, 1]^3$ 的标准立方体（NDC 空间）。这个立方体是抽象的：原点在正中心、坐标从 $-1$ 到 $1$。但屏幕不是这样——屏幕的原点在左上角，坐标向右向下增长，像素位置用整数编号。<span class="marginnote">NDC 坐标是「与分辨率无关」的：无论最终渲染到 1080p 还是 4K，三维点在 NDC 里的表示都一样。把 NDC 映射到具体像素网格这一步，叫<b>视口变换（viewport transformation）</b>。</span>

**视口变换**决定了一个 NDC 点显示在屏幕的哪个像素上。理解它，你就走完了「三维几何 → 屏幕像素」的完整链条，可以真正开始讨论光栅化怎么把三角形涂成像素了。

## 1 屏幕坐标的约定：像素中心在 (0.5, 0.5)

先约定屏幕坐标系的规则。设视口（viewport）宽 $w$、高 $h$（像素），屏幕坐标系约定：

原点在**左上角**，$x$ 向右、$y$ 向下。
像素 $(i, j)$ 是占据 $[i, i+1] \times [j, j+1]$ 的方块，其**中心在 $(i + 0.5, j + 0.5)$**。<span class="marginnote">「像素中心在整数加 0.5」是光栅化的头号细节：像素 $(0,0)$ 覆盖 $[0,1]\times[0,1]$，中心在 $(0.5,0.5)$。如果忘记这 0.5 的偏移，所有几何都会被错半个像素，边缘出现系统性偏移。</span>
- 整个视口覆盖的坐标范围是 $[0, w] \times [0, h]$。

这套约定在 D3D11 与多数引擎里通用。它把「离散的像素格」和「连续的坐标」焊接起来——0.5 偏移就是两者之间的那层胶水。

## 2 视口矩阵：把 [-1,1]³ 铺到 [0,w]×[0,h]

NDC 的 $x \in [-1, 1]$ 要映射到屏幕 $x \in [0, w]$，$y \in [-1, 1]$ 要映射到 $y \in [0, h]$。$z$ 轴则继续留在深度缓冲里（先不管）。这个映射分两步：缩放 + 平移。

$$
M_{\text{viewport}} = \begin{pmatrix} \frac{w}{2} & 0 & 0 & \frac{w}{2} \\ 0 & \frac{h}{2} & 0 & \frac{h}{2} \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{pmatrix}
$$

验证：$x = -1$ 时 $\frac{w}{2}(-1) + \frac{w}{2} = 0$；$x = 1$ 时得 $w$。$y$ 同理，$y = -1$ 映到 0、$y = 1$ 映到 $h$。<span class="marginnote">注意这里 $y$ 轴被「倒转」了：NDC 里 $y$ 向上（$y=1$ 在顶），屏幕里 $y$ 向下（$y=h$ 在底）。视口矩阵把 NDC 的「顶」映到屏幕坐标的 $y=0$，因为屏幕坐标的原点在左上角——这层倒转是二维贴图与三维渲染坐标系的经典差异。</span>

再配上像素中心偏移，实际把 NDC 点 $(x, y)$ 送到像素格的公式是：

$$
\text{pixel}_x = \frac{w}{2}(x + 1), \qquad \text{pixel}_y = \frac{h}{2}(y + 1)
$$

落在像素 $(i, j)$ 的判定再叠加 0.5 中心规则：NDC 点显示在中心为 $(\text{pixel}_x, \text{pixel}_y)$ 的像素格内。

## 3 公式解析：一个 NDC 点如何变成像素坐标

跟踪一个具体例子：视口 $w = 800$、$h = 600$，取 NDC 点 $(-0.5, 0.5)$。

- **第一步，横向映射**：$x' = \frac{800}{2}(-0.5 + 1) = 400 \times 0.5 = 200$。
- **第二步，纵向映射**：$y' = \frac{600}{2}(0.5 + 1) = 300 \times 1.5 = 450$。
- **第三步，读像素**：屏幕坐标 $(200, 450)$ 位于像素 $(199, 449)$ 的格子内（因为该格覆盖 $[199,200]\times[449,450]$，中心在 $(199.5, 449.5)$）。

注意第二步里 $y = 0.5$ 在 NDC 是「偏上」，映射到屏幕坐标 $450$ 是「偏下」——正好验证了 $y$ 轴的倒转。**NDC 的「上半」对应屏幕的「上半」**（屏幕坐标小），因为视口矩阵把倒转嵌进了缩放里。

**辨析｜易错点：** 三个高频错误：

1. **忘记 0.5 偏移**：像素中心在 $(i+0.5, j+0.5)$，直接把 NDC 结果当像素编号会整体错半格。
2. **$y$ 轴方向搞反**：把「NDC 的 $y=1$（顶部）」映射到屏幕坐标「$y = h$（底部）」，画面上下颠倒。
3. **分辨率依赖放错位置**：视口变换只在这一步引入分辨率；三维几何的模型/视图/投影矩阵与分辨率无关。把分辨率塞进模型矩阵是架构性错误，会导致窗口缩放时模型变形。

## 4 视口变换在管线中的位置

视口变换是投影之后、光栅化之前的一环：

```text
模型空间 → 世界空间 → 相机空间 → 裁剪空间 → NDC → 屏幕空间（视口变换）→ 光栅化
```

其中「投影 → NDC」要经历透视除法（$w$ 分量变 1），而「NDC → 屏幕」由视口矩阵完成。在现代 API 里，视口信息通过 `glViewport` 或 `RSSetViewports` 设置，硬件把 NDC 自动映射到对应窗口区域。<span class="marginnote">视口不必占满整个窗口：分屏游戏、小地图、后处理缓冲都在用「子视口」。每个子视口有自己独立的 $w, h$ 与原点偏移，共享同一套 NDC 约定。</span>

视口变换同时也是「像素空间」与「NDC 空间」的分界线：在它之前的空间里，坐标是连续的、可被数学优雅处理；在它之后，坐标被钉死在像素网格上，一切讨论都变成离散的——光栅化就是在这个离散世界里进行的。

## 5 从屏幕空间到光栅化

屏幕空间准备好了，光栅化的第一个问题就浮出水面：**一个三角形被变换到屏幕坐标后，覆盖了哪些像素？** 回答这个问题的算法（扫描线、包围盒 + 逐像素测试）构成了光栅化的主体。而判断像素是否在三角形内，用的是下一节将登场的**叉积符号判定**。

还有一个常被忽略的细节：视口变换改变了 $z$ 的用途。NDC 的 $z$ 留在 $[-1,1]$（或 $[0,1]$，取决于 API），它不再用于显示，而是用于**深度缓冲**——决定谁遮挡谁。于是「屏幕空间 + 深度值」的组合，正是后续 Z-Buffer 工作的全部输入。

## 6 视口变换与坐标系的完整链条

把「三维点到屏幕像素」的完整链条拼起来，看视口变换在整个流程里的位置：

```text
模型空间 → 世界空间 → 相机空间 → 裁剪空间 → 透视除法 → NDC → 视口变换 → 屏幕像素
```

- **裁剪空间**：投影矩阵输出的是齐次坐标 $(x, y, z, w)$——此时做**视锥裁剪**（剔除 $w$ 外的点），这是「为什么投影矩阵要输出 $w$」的原因。
- **透视除法**：除以 $w$ 得到 NDC $[-1, 1]^3$——非线性投影在这里「落地」。
- **视口变换**：NDC → 屏幕像素（含 $y$ 翻转与 0.5 偏移）。

**每个空间都有自己的「用途」**：模型空间适合「编辑物体」，世界空间适合「摆放场景」，相机空间适合「判断前后/裁剪」，NDC 适合「统一比较深度」，屏幕空间适合「光栅化」。理解「每个空间解决什么问题」，是调试渲染 bug 的思维框架——「这个坐标在哪一空间？」是第一步要问的。

**辨析｜易错点：** 三个跨空间混淆的经典 bug：

1. **在错误空间做光照**——光照要在「世界空间」或「相机空间」做（要距离/方向），在屏幕空间做会「随分辨率变」。
2. **视口矩阵里 $y$ 翻转的时机**——OpenGL 在视口变换翻转 $y$，D3D 在投影矩阵里翻转——跨 API 移植忘了这个差异，画面「上下颠倒」。
3. **NDC 的 $z$ 范围约定**——OpenGL 的 NDC $z \in [-1, 1]$，D3D 的 $z \in [0, 1]$——深度比较、投影矩阵都依赖这个约定，混用会「深度全错」。

「空间链条」是图形学的坐标系全景——理解每个空间与它的变换，你就掌握了「坐标从哪来到哪去」的完整地图，这也是调试任何渲染问题的第一工具。

## 7 视口变换的一页速查

把视口变换的关键点压成速查：

- **屏幕约定**：原点左上、$y$ 向下、像素中心在 $(i+0.5, j+0.5)$。
- **视口矩阵**：$M_{\text{viewport}} = \text{缩放} + \text{平移}$——NDC $[-1,1]$ 映射到 $[0,w]\times[0,h]$。
- **$y$ 翻转**：NDC 向上、屏幕向下——矩阵里嵌翻转。
- **分辨率无关**：视口变换才引入分辨率，三维变换矩阵与分辨率无关。
- **空间链条**：模型 → 世界 → 相机 → NDC → 屏幕——每个空间管一件事。

**一句话记忆**：「NDC 是抽象的，屏幕是具体的，视口矩阵是它们之间的桥」——记住这一句，整个链条的坐标转换就通了。

## 8 小结

- 屏幕坐标约定：原点左上、$y$ 向下、像素中心在 $(i+0.5, j+0.5)$。
- 视口矩阵把 NDC $[-1,1]^2$ 映射到 $[0,w]\times[0,h]$，含 $y$ 轴倒转与缩放平移。
- 像素坐标 = $\frac{w}{2}(x+1)$，再叠加 0.5 中心规则落到像素格。
- 视口是「连续数学空间」与「离散像素空间」的分界线，之后就是光栅化。
