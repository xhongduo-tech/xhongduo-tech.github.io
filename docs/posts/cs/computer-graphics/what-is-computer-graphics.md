## 为什么从「图形学」开始

这个网站叫「从极限到大模型」。沿着这条路往前走，我们会穿过微积分、线性代数、概率论与计算机系统，然后在一个岔路口遇见这样一类问题：一张照片是怎么来的？一段三维动画的每一帧、一场游戏里那个能自由奔跑的世界，又是怎么被「算」出来的？

回答这些问题的学科，就是**计算机图形学（Computer Graphics）**。它几乎是整条路线里最「可见」的一站——其他章节的结论藏在公式与代码里，而图形学的输出就是你眼睛看到的那张图。更关键的是，它与 AI 的汇流正在加速：扩散模型在学「生成图像」，NeRF 与 3D 高斯泼溅在学「渲染图像」，而它们的数学骨架——线性变换、光线传播、相机模型、积分与采样——几乎全部来自图形学。<span class="marginnote">本专题对标两套经典教材：GAMES101（闫令琪，图形学入门公开课）与虎书《Fundamentals of Computer Graphics》（Shirley 等著），按它们的章节体系逐节写作。</span>

本专题的第一篇，我们不急着碰公式，而是先回答三个问题：图形学到底在做什么？它和我们常听说的**计算机视觉**、**图像处理**是什么关系？它又用在了哪些地方？把这三件事立住，后面每一篇才有了坐标系。

## 1 图形学的核心任务：合成图像

虎书第一章开宗明义：计算机图形学是「用计算机生成和处理图像所涉及的一切（concerned with all aspects of producing pictures or images using a computer）」。这句话里最值得停下来品一品的是「**生成（producing）**」。

**图形学的本质是合成（synthesis）：给定一个三维场景的描述，计算出你应当看到的那张二维图像。** 这里的关键是方向——图像不是被拍摄、被扫描、被采集来的，而是被**从无到有地算出来**的。在计算的起点，世界只是一堆数学对象：点的坐标、三角形网格、材质的反射参数、光源的位置与强度、相机的位置与朝向；在计算的终点，才出现一个由成千上万个像素组成的二维数组。整幅图像，就是一次大规模计算的结果。

举个具体的例子。《玩具总动员》里安迪的房间、皮克斯的台灯，都不是摄像机拍出来的：电影里每一个像素的颜色，都由程序根据场景描述算出。你在游戏里看到的每一帧画面也同样——渲染管线每 16.7 毫秒（60 帧每秒）就要把数千万个三角形换算成几百万个像素的颜色。<span class="marginnote">60 帧每秒意味着每帧只有约 16.7 ms 的预算。实时图形学的大量技巧——缓存、LOD、预计算光照——本质上都是在和这个预算赛跑。</span>

理解「合成」二字，是进入图形学的前提。因为一旦方向反过来——从一张已有的图像去反推场景，那就是另一个学科了。

## 2 图形学的四大领域：建模、动画、渲染、交互

图形学内部按「一个场景从构想到呈现在眼前」的生命周期，大致分成四大领域，它们也是本专题的骨架：

- **建模（modeling）**：如何表示物体与场景。用三角形网格、隐式曲面、还是点云？物体表面是什么材质？——这是第六篇《几何表示》的内容。
- **动画（animation）**：如何让场景随时间动起来。关键帧插值、骨骼动画、布料与流体的物理模拟——这是第九篇《动画与模拟》的内容。
- **渲染（rendering）**：如何把三维场景变成二维图像。光栅化与光线追踪两条技术路线、着色、纹理映射——这是全专题篇幅最大的一块（第四到第八篇）。
- **交互（interaction）**：如何让用户实时地影响场景。相机控制、实时渲染管线、GPU 并行——这是第十篇《实时渲染》的内容。

用一段伪代码可以把这条宏观管线写得很直观：

```python
# 从三维场景到二维图像：图形学管线的宏观骨架
scene = build_scene()          # 建模：网格、材质、光源、相机
while running:                 # 动画：一帧一帧地运行
    update(scene, t)           #   物理模拟 / 关键帧插值
    frame = render(scene)      # 渲染：光栅化或光线追踪，逐像素求颜色
    display(frame)             # 交互：把帧送上屏幕，等待用户输入
```

这四件事并不是彼此孤立的：游戏里的「渲染」必须跑在实时预算内，因此「建模」要产出适合实时绘制的网格，「动画」要兼顾成本，「交互」则约束着前三者的上限。真正好的图形学从业者，眼里看到的是这条流水线在整体上如何协作。

## 3 与计算机视觉、图像处理的分工与关系

「图形学」这个词常与另外两个名字纠缠不清：**计算机视觉（Computer Vision）** 与 **图像处理（Image Processing）**。它们共享同一个对象——图像，但对待图像的方向截然不同。先把结论摆出来：

- **计算机图形学**：场景描述 → 图像。**合成**。图像是答案。
- **计算机视觉**：图像 → 场景描述。**理解**。图像是已知条件，场景是待求的答案。
- **图像处理**：图像 → 图像。**加工**。输入输出都是图像，做的只是让图像变得更好或不同。

![计算机图形学、计算机视觉与图像处理的分工：图形学合成图像，视觉理解图像，图像处理在像素层加工图像](/images/computer-graphics/what-is-computer-graphics-1.svg)

**图形学与计算机视觉互为逆问题。** 如果把图形学写成 $图像 = f(场景)$，那么视觉的终极目标就是求解 $场景 \approx f^{-1}(图像)$：给你一张照片，重建出照片里的三维结构、物体类别与语义。视觉这门第四级课程（对标 Szeliski 的《计算机视觉：算法与应用》与 CS231n）里，针孔相机模型、几何变换、三维重建这些内容，恰与图形学的相机与变换互为镜像。

**辨析｜易错点：** 图像处理 ≠ 计算机视觉。去噪、锐化、增强对比度、压缩——输入输出都是图像，属于图像处理，它停留在像素层，不问「图里有什么」；而「判断这张图里有没有猫、猫在哪、猫的姿势是什么」，是视觉，它要把像素提升为语义。判断标准一句话：**输出还是图像，就是图像处理；输出是语义或结构，就是视觉。** 图形学则恰好站在对面，把语义和结构渲染成图像。

三者的关系可以整理成一张对照表：

| 领域 | 方向 | 输入 | 输出 | 典型问题 |
| --- | --- | --- | --- | --- |
| 计算机图形学 | 合成 | 场景描述 | 图像 | 这个三维场景长什么样？ |
| 计算机视觉 | 理解 | 图像 | 场景描述 | 图里有什么、在哪里？ |
| 图像处理 | 加工 | 图像 | 图像 | 怎么让这张图更清晰？ |

需要补充的是，这条分界线正在被新技术抹平：**可微渲染**与**逆向渲染**（从图像反推几何、材质与光照）让图形学与视觉合流；NeRF、3D 高斯泼溅这类「神经渲染」方法，同时出现在本专题第十一篇与视觉专题的三维视觉一节。<span class="marginnote">神经渲染（NeRF 等）是图形学与视觉真正接壤的地带：它既是从图像中学习场景（视觉），又是把场景渲染成新视角图像（图形学）。学完两个专题，你会在这里看到它们手牵手。</span>但理解它们各自的原点——谁在合成、谁在理解、谁在加工——依然是读懂一切新技术的出发点。

## 4 公式解析：渲染方程——「合成」的数学定义

如果说图形学四阶段是这门学科的「工程骨架」，那么**渲染方程（rendering equation）**就是它的「物理宪法」。它由 James Kajiya 于 1986 年提出，把「一幅图像最终是怎么来的」压缩成一条积分方程：

$$
L_o(\mathbf{x}, \omega_o) = L_e(\mathbf{x}, \omega_o) + \int_{\Omega} f_r(\mathbf{x}, \omega_i, \omega_o)\, L_i(\mathbf{x}, \omega_i)\, \cos\theta_i\, \mathrm{d}\omega_i
$$

初次看到这条式子的人常被吓住，其实它只讲了一件事。逐项拆解：

- **第一步，看等式左边 $L_o(\mathbf{x}, \omega_o)$**：从表面点 $\mathbf{x}$ 沿方向 $\omega_o$ 离开的辐射亮度（radiance）。对你而言，它就是「这一小块表面朝这个方向看过去的最终颜色」——也就是图像里对应像素的值。
- **第二步，看第一项 $L_e(\mathbf{x}, \omega_o)$**：点 $\mathbf{x}$ **自身发出**的光。只有发光物体（光源）这一项才非零；普通物体上没有它。
- **第三步，看积分号 $\int_{\Omega} \cdots \mathrm{d}\omega_i$**：对法线上方半球 $\Omega$ 里的**所有**入射方向 $\omega_i$ 求和。照亮一个点的光来自四面八方，不是只有一根光线。
- **第四步，看被积的三个因子**：$L_i(\mathbf{x}, \omega_i)$ 是从方向 $\omega_i$ 照进来的光；$\cos\theta_i$ 是**兰伯特余弦**——光越斜着照到表面，单位面积收到的能量越少（正午的太阳比傍晚晒）；$f_r(\mathbf{x}, \omega_i, \omega_o)$ 是**双向反射分布函数（BRDF）**，它刻画材质：这一小块表面把 $\omega_i$ 方向进来的光反射到 $\omega_o$ 方向的比例。漫反射、镜面、玻璃、金属，差别全在这一个函数里。

所以渲染方程的一句话读法是：**离开的光 = 自发光 + 所有入射光按材质与几何加权后的总和。** 整门图形学可以浓缩为：给你场景（$L_e$、$f_r$、$L_i$、几何），求每个像素的 $L_o$。光栅化与 Blinn-Phong 着色，是这条方程在「忽略间接光」下的廉价近似（本专题第五篇）；光线追踪与路径追踪，则是它的精确数值求解（第七篇）。<span class="marginnote">如果你学到最后发现「渲染 = 解渲染方程」，那就对了。GAMES101 的课程正是从光栅化的近似出发，一路走到这条方程的蒙特卡洛求解——本专题第七篇会完整推导它。</span>

作为对照，光栅化路线里还有一个几乎同样重要的公式——**视口变换**，它把标准立方体坐标映射到屏幕像素：

$$
x_{screen} = \frac{W}{2}(x_{ndc} + 1), \qquad y_{screen} = \frac{H}{2}(y_{ndc} + 1)
$$

<span class="marginnote">视口变换是渲染管线的「最后一公里」：几何还在连续坐标里，屏幕要的是整数像素。这个公式将在第四篇《屏幕空间与视口变换》里详细展开。</span>一个是「图像为什么是这样」，一个是「像素画在哪」，恰好对应本专题两条技术路线的起点。

## 5 图形学的应用版图

有了上面的骨架，再去看应用就一目了然了。图形学的四个领域在不同行业里被调配成不同的配方：

- **游戏与实时渲染**：建模、动画、渲染、交互四样全要，且在 16.7 ms 的预算内完成。光栅化管线与 GPU 并行是其技术底座，画面从早期的一两万个三角形发展到今天数千万三角形的开放世界。
- **影视与离线渲染**：不求快，只求真。路径追踪、全局光照、次表面散射逐帧慢慢算。《玩具总动员》（1995）是人类第一部长篇三维动画电影，如今一帧高质量特效镜头可以渲染数小时甚至更久。
- **科学可视化**：把仿真与测量的数据变成眼睛能读的图——气象云图、流体场、MRI 断层扫描、蛋白质三维结构。数学、物理、生物的结论，靠图形学「显形」。
- **CAD 与工业设计**：建筑还没开工，先渲染出效果图；汽车还没投产，先做数字化风洞。参数化建模与仿真驱动着现代制造业。
- **渲染（产品可视化 / 建筑表现）**：家具、汽车、楼盘的「照片」在拍摄之前就存在了——这既是图形学最直接的应用，也是它与摄影术最浪漫的对话。

你会发现，这些应用的差异不在于「图形学做了不同的数学」，而在于四个领域被组合的比例不同。理解了四阶段，你就理解了所有应用的同构骨架。

## 6 小结

- 图形学的核心是**合成**：图像不是拍来的，而是从场景描述**算出来的**——这是它与视觉、图像处理的分水岭。
- 图形学四大领域：**建模、动画、渲染、交互**，对应本专题各篇的骨架。
- 三者分工：**图形学（场景→图像）**、**视觉（图像→场景）**、**图像处理（图像→图像）**；图形学与视觉互为逆问题。
- **渲染方程** $L_o = L_e + \int_\Omega f_r L_i \cos\theta\, \mathrm{d}\omega_i$ 是合成问题的数学定义；光栅化与光线追踪是它的近似与精确求解。
- 应用版图：游戏、影视、科学可视化、CAD 与产品渲染，是四个领域的不同配比。

在下一节，我们将把视角从「图形学在做什么」转向「图形学被用在哪里」——展开**图形学的应用版图**，随后进入渲染管线总览与颜色基础，为第一篇的数学准备（线性代数回顾）铺路。
