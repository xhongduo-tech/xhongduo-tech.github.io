## 为什么 GPU 不只是渲染器

GPU 的并行架构（上一节）不只适合画三角形——任何「海量相同计算」都适合 GPU：物理模拟、粒子、图像处理、神经网络、科学计算。**通用 GPU 计算（GPGPU）** 把这个潜力释放出来：用 CUDA / Compute Shader 把 GPU 当「通用并行计算机」用。<span class="marginnote">「GPU 的真相：<strong>它是『数据并行计算器』，渲染只是它最著名的应用</strong>」——成千上万个核同时做「相同运算、不同数据」，这个结构既适合画像素，也适合算物理、跑神经网络。GPGPU 让图形学与计算科学共享同一块硬件——<strong>CUDA 用 C 语言的思维写并行代码，Compute Shader 用着色器的形式写通用计算</strong>。</span>

本节讲 GPU 并行计算的思维模型：CUDA/Compute Shader 怎么写、为什么快、以及它在图形学里的经典加速应用。

## 1 CUDA：C 语言的并行扩展

**CUDA（Compute Unified Device Architecture）** 让程序员用类 C 语言写「核函数（kernel）」，GPU 并行执行：

```cuda
__global__ void add(float* a, float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];   // 一个线程处理一个元素
}

// 启动配置：开 N 个线程并行执行核函数
add<<<gridSize, blockSize>>>(a, b, c, N);
```

**线程层级**：线程（thread）→ 线程块（block）→ 网格（grid）。
**启动配置（launch config）**：声明「开多少线程」。
**核函数**：描述「一个线程做什么」，GPU 把它并行应用到所有线程。

**「一个线程做什么」是 GPU 编程的核心思维**——写核函数时想的是「单个元素的处理逻辑」，GPU 负责把它铺到所有元素上。<span class="marginnote">「CUDA 的思维：<strong>写『一个元素的处理』，GPU 铺到『所有元素』</strong>」——<strong>核函数</strong>只描述「两个数组的第 i 个元素相加」，<strong>启动配置（<<<gridSize, blockSize>>>`）</strong>声明「开 N 个线程各做一次」。这个「单线程逻辑 + 海量并行」的模型，让程序员用串行思维写并行代码——正是 GPU 编程与 CPU 编程的最大心智差异。</span>

## 2 线程组织与并行度

CUDA/Compute Shader 的线程组织决定了「并行度」：

**grid**：整个核函数启动的「线程块」集合。
**block**：一组线程（通常 128–1024 个），可共享内存、可同步。
**thread**：最小执行单元。

GPU 硬件把线程块调度到 SM（流多处理器）上执行。**「要开足够多的线程」**——因为 GPU 靠并行掩盖内存延迟（上一节的 latency hiding），线程太少 GPU「吃不饱」。

**并行度经验法则**：开「远多于 SM 核心数」的线程（通常上万个），让 GPU 有足够的 warp 可切换。<span class="marginnote">「线程越多越好（但要资源够）」：<strong>GPU 的 SM 会切换 warp 来掩盖内存等待——线程太少，切换不过来，GPU 空闲等内存</strong>。现代 GPU 一个核函数动辄开几十万线程。但线程多也带来「调度开销」与「资源限制」（每 SM 的线程数有上限）——「开多少线程」是 GPU 性能调优的第一课。</span>

## 3 Compute Shader：渲染管线的「计算通道」

**Compute Shader** 是图形 API 里的通用计算——不进渲染管线，直接操作 GPU 并行：

```hlsl
[numthreads(8, 8, 1)]
void CSMain(uint3 id : SV_DispatchThreadID) {
    // 一个线程算一个输出像素/元素
    float4 color = tex.SampleLevel(samp, uvFromID(id), 0);
    output[id.xy] = blur(color);
}
```

Compute Shader 的威力：**与渲染管线共享同一块 GPU，但不受「顶点-片元」结构约束**——可以做任意并行计算，且结果可以直接喂给渲染（纹理、缓冲）。

**「计算 + 渲染」的混合**是现代 GPU 编程的标准：计算着色器算物理/粒子/后处理，把结果写进纹理，顶点/片元着色器读它渲染。<span class="marginnote">「Compute Shader 是渲染与计算的『桥梁』」：<strong>计算着色器算出的结果直接写成纹理/缓冲，喂给渲染管线——物理模拟的粒子位置 → 渲染成点精灵，后处理的滤波结果 → 显示成画面</strong>。这让「GPU 上算物理、算光照、算 AI，再一起渲染」成为可能——现代引擎（物理、粒子、GI 的 Lumen、TAA）全是计算着色器的应用。</span>

## 4 公式解析：GPU 加速的经典范式

以「图像模糊」为例，看 GPU 如何把「O(N²) 的卷积」变成「O(1) 的并行」：

$$
\text{out}(x,y) = \sum_{i=-k}^{k}\sum_{j=-k}^{k} w(i,j)\, \text{in}(x+i, y+j)
$$

- **第一步，识别并行性**：每个输出像素的卷积**互相独立**——一个线程算一个像素。
- **第二步，分配线程**：$W \times H$ 个线程，每个算一个输出像素的卷积——「一像素一线程」。
- **第三步，并行执行**：GPU 同时跑成千上万个线程，每个做一次 $k \times k$ 的卷积——总时间 ≈ 单像素卷积时间，与图像大小无关（吞吐视角）。
- **第四步，加速比**：理论上近「线程数」倍的加速——GPU 上模糊一张 4K 图只需几毫秒。

**「数据并行 = 一个线程一个输出」是 GPU 加速的通用范式**——图像处理、物理、矩阵运算全部适用。<span class="marginnote">「GPU 加速的范式：<strong>识别『每个输出独立计算』→ 分配『一输出一线程』→ 并行铺开</strong>」——只要问题能被分解成「大量独立的小计算」，GPU 就能线性提速。卷积、模糊、矩阵乘法、粒子更新、神经网络层，全是这个范式。写 GPU 代码的第一步永远是「找并行性」。</span>

## 5 图形学里的 GPU 加速应用

图形学用 GPU 并行计算加速了大量原本「CPU 太慢」的任务：

**物理模拟**：粒子、流体（SPH 的邻居查找）、布料——每个粒子/顶点一个线程。
**后处理**：模糊、锐化、Bloom、色调映射——每个像素一个线程。
**光照与 GI**：延迟光照、RSM/LPV/VXGI、Lumen——GPU 计算着色器的实时 GI。
**几何处理**：曲面细分、网格简化、点云处理。
**AI 推理**：神经网络（深度学习推理）——GPU 是 AI 的发动机（虽然这已超出图形学，但共享硬件）。

「GPU 加速 = 把算法改写成『数据并行』」——理解并行性，就理解了 GPU 加速的本质。<span class="marginnote">「GPU 加速的边界：<strong>适合『海量独立小计算』（像素、粒子、矩阵元素），不适合『强依赖的串行逻辑』（循环依赖、全局同步）</strong>」——这就是为什么 GPU 加速物理/图像/神经网络飞快、却不适合「编译器」「操作系统」这类强逻辑任务。选择 GPU 加速的第一问永远是「这个问题的并行度有多高？」</span>

## 6 从并行计算到图形学的新范式

GPU 并行计算不只是「加速旧算法」，它催生了图形学的新范式：

**实时全局光照**：计算着色器让「每帧算 GI」成为可能（上一节的 Lumen/VXGI）。
**神经渲染**：NeRF、3D Gaussian 的训练与推理全在 GPU 上——GPU 既是渲染器又是「神经网络的引擎」（最后几节的主题）。
**可微渲染**：让渲染过程可求导，用梯度优化场景——GPU 上的自动微分。

「GPU 并行计算 + 图形学」的融合，正是「从极限到大模型」这条主线在图形学末端的体现——GPU 把渲染、模拟、AI 统一在同一块硬件上。<span class="marginnote">「GPU 是渲染、模拟、AI 的统一硬件」：<strong>同一块 RTX 显卡既画三角形（渲染）、又算物理（模拟）、又训练/推理神经网络（AI）</strong>——图形学的现代专题（神经渲染、可微渲染）全部建立在这个统一之上。下一节我们进入神经渲染的第一步——「可微渲染」：让渲染变成「可求导的函数」，用梯度反过来优化场景。</span>

## 7 小结

- **GPU = 数据并行计算器**：成千上万的核做「相同运算、不同数据」，渲染只是最著名应用。
- **CUDA**：类 C 语言 + **三级线程层级**（线程/块/网格），「一个线程做什么」是核心思维。
- **Compute Shader**：图形 API 里的通用计算，与渲染管线共享 GPU、结果直接喂渲染。
- GPU 加速范式：**找并行性 → 一输出一线程 → 并行铺开**；卷积/模糊/物理全适用。
- 应用：物理、后处理、实时 GI、AI 推理；边界是「强依赖串行逻辑」。
- GPU 统一渲染、模拟、AI——是神经渲染与可微渲染的硬件地基。
