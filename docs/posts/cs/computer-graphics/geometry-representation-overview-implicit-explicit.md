## 为什么「怎么存几何」是独立的问题

前面几篇我们假设场景里已经有三角形网格了——但三维几何从哪来？扫描仪扫出点云，CAD 造出曲面，程序生成地形，物理模拟演化出流体。**同一种形状可以有截然不同的表示方式**，而表示方式决定了：怎么判断点在不在形内、怎么求交、怎么渲染、怎么编辑。本节是第六篇的总纲，把几何表示的所有流派放进一个框架。<span class="marginnote">几何表示的分水岭是<strong>隐式（implicit）与显式（explicit）</strong>：隐式用「条件/方程」描述点集，显式用「直接给出点或参数」描述表面。这个二分法是理解一切几何表示的地图——知道每个流派站哪边，就知道它的能力与软肋。</span>

## 1 隐式表示：用方程圈出一个形状

**隐式表示（implicit representation）** 用「一个点是否满足条件」来定义形状。最常见的形态是方程：

$$
f(x, y, z) = 0
$$

满足 $f(p) = 0$ 的点构成表面，$f(p) < 0$ 是内部，$f(p) > 0$ 是外部。<span class="marginnote">球心在原点、半径为 $R$ 的球：$f(p) = \|p\|^2 - R^2 = 0$。判断一个点是否在球内只需算一次 $f(p)$ 的符号——O(1) 的点判定是隐式表示的头号优势。</span>

隐式表示家族包括：代数曲面、CSG（布尔运算）、距离函数、水平集、分形。它们共享的优点与缺点：

- **优点**：点是否在形内**判定极快**（一个符号判断）；对拓扑变化（流体融合、水花四溅）天然友好。
- **缺点**：**采样困难**——从隐式方程直接枚举表面上的点很麻烦，渲染需要 Marching Cubes 等额外算法；且复杂的隐式函数难以直观设计。

## 2 显式表示：直接给出表面

**显式表示（explicit representation）** 要么直接列出所有表面点（点云），要么通过**参数映射**给出表面：一个函数把参数域映射到表面点。

$$
\text{表面点} = f(u, v)
$$

例如球面的参数形式：

$$
f(u, v) = (R\cos u \cos v,\; R\sin u \cos v,\; R\sin v)
$$

显式家族包括：点云、多边形网格、贝塞尔/B 样条曲面、NURBS。优点与缺点正好与隐式互补：

- **优点**：**采样直接**——把参数代入就能拿到表面点，天然适合光栅化与光线追踪；直观可编辑。
- **缺点**：**点判定困难**——「这个点在不在形状里」没有简单的公式；拓扑变化需要专门处理。

**显式是图形学的主场**：三角形网格、贝塞尔曲面、NURBS 都是显式表示，因为它们与 GPU 的采样/光栅化模型无缝衔接。<span class="marginnote">「隐式好判定、显式好采样」这条规律贯穿整个几何篇：做碰撞检测、体积渲染时偏爱隐式（判内外快）；做建模、渲染时偏爱显式（采样直接）。而顶级的表示（如 SDF 与 Marching Cubes 的组合）试图两全其美——先用隐式存，再用显式采。</span>

## 3 公式解析：隐式与显式的判定/采样对比

同一个球，两种表示，暴露两种思维：

$$
\underbrace{\|p\|^2 - R^2 = 0}_{\text{隐式：判定式}} \qquad \underbrace{(R\cos u\cos v,\; R\sin u\cos v,\; R\sin v)}_{\text{显式：生成式}}
$$

- **第一步，隐式读法**：给一个点 $p$，算 $\|p\|^2 - R^2$。小于 0 在球内、等于 0 在球上、大于 0 在球外——**判定**。
- **第二步，显式读法**：给一对参数 $(u,v)$，代入公式得到表面上一个点——**生成**。
- **第三步，反向操作**：隐式想「生成表面点」很难（解方程）；显式想「判定点在形内」很难（对凸体可算，对复杂网格要射线法）。**两种表示的强弱恰好互补**，这正是为什么两者都要学。

## 4 几何表示的九大流派一览

把图形学里常见的几何表示放进隐式/显式两个阵营：

| 流派 | 隐式/显式 | 表示方式 | 典型应用 |
| --- | --- | --- | --- |
| 代数曲面 | 隐式 | 多项式方程 | 解析几何、CAD 基础 |
| CSG | 隐式 | 基本体 + 布尔运算 | CAD 实体建模 |
| 距离函数 (SDF) | 隐式 | 到表面最近距离 | 碰撞、体积渲染 |
| 水平集 | 隐式 | 高维函数零集 | 流体、拓扑演化 |
| 分形 | 隐式 | 迭代自相似 | 自然景观、艺术 |
| 点云 | 显式 | 离散点集合 | 三维扫描、LiDAR |
| 多边形网格 | 显式 | 顶点+面片 | 游戏、影视（主流） |
| 贝塞尔/B 样条/NURBS | 显式 | 控制点参数曲线曲面 | CAD、字体、动画 |
| 细分曲面 | 显式 | 网格迭代细化 | 动画角色（Pixar） |

**网格是渲染的事实标准，NURBS 是 CAD 的事实标准，SDF 是体积与碰撞的事实标准**——不同的领域被不同的表示统治，理解这张表就知道该学什么。<span class="marginnote">为什么没有一个「万能表示」？因为判定、采样、编辑、渲染四个需求互相冲突：隐式擅长判定与编辑（布尔），显式擅长采样与渲染。真实工业管线因此是「混合的」：CAD 用 NURBS 建模、导出成网格渲染、再烘焙成 SDF 做碰撞——每种表示各司其职。</span>

## 5 表示与渲染管线的接口

几何表示必须最终能「喂」给渲染管线（GPU 吃三角形）。这个接口决定了表示的可用性：

- **网格**：天然可渲染，顶点/索引数组直接进管线。
- **NURBS/贝塞尔**：先**细分**（tessellate）成三角形再渲染，或由 GPU 的曲面细分阶段处理。
- **SDF/隐式**：用 **Marching Cubes** 等算法提取等值面生成网格，或直接做体渲染（ray marching）。
- **点云**：用点精灵（point sprites）或先表面重建（如 Poisson 重建）成网格。

「把表示转成三角形」这一步（tessellation / meshing）是几乎所有非网格表示的必经之路，也是它们的主要成本。<span class="marginnote">「渲染 = 先把任意表示离散成三角形」是现代 GPU 的基本范式。但神经渲染（NeRF、3D Gaussian）正在打破它：直接把隐式场/高斯原语送进光栅化或体渲染，不再需要显式网格。这个趋势我们到第十一篇《神经渲染》再展开。</span>

## 6 表示选择的决策框架：何时用哪种

「隐式 vs 显式」不是「哪个好」，而是「按需求选」——给一个决策框架，你就知道「什么时候选什么」。

**按操作选表示**：

| 需要的操作 | 适合的表示 | 原因 |
| --- | --- | --- |
| 判定「点在不在形内」 | 隐式（SDF/方程） | 一次符号判断 O(1) |
| 采样「表面上的点」 | 显式（网格/参数） | 代入参数即得点 |
| 渲染（GPU 光栅化） | 显式（网格） | GPU 吃三角形 |
| 物理碰撞 | 隐式（SDF/凸体） | 距离/穿透查询快 |
| 建模编辑（布尔/变形） | 隐式（CSG/SDF） | 布尔是函数操作 |
| 动画（骨骼蒙皮） | 显式（网格） | 顶点跟随骨骼 |
| 从照片重建 | 隐式/神经 | 训练出连续场 |

**核心权衡**：**「判内外」要隐式，「采样渲染」要显式**——一个表示很难两全，所以工业流程常「混用」：

- **CAD**：NURBS 建模（显式参数）→ 导出网格（显式）→ 烘焙 SDF（隐式）做碰撞。
- **游戏**：网格渲染（显式）→ 碰撞用凸体/隐式近似。
- **神经渲染**：NeRF 隐式场（训练）→ 3DGS 显式高斯（渲染）。

**「混用」是常态**：真实系统用「每种表示做它最擅长的事」，用「转换」（Marching Cubes、细分、烘焙）把它们接起来——「表示不是终点，是工具」。

**辨析｜易错点：** 两个选择误判：

1. **「隐式更高级」**——隐式在判内外、拓扑上有优势，但渲染/编辑要显式——「高级」是错觉，是「分工」。
2. **「一种表示走到底」**——从建模到渲染到物理用同一种表示，常常「处处凑合」——「按环节选表示 + 转换」是工程正解。

**「表示选择 = 操作的函数」**——理解了决策框架，你就知道「为什么图形学有这么多表示方式，它们各管什么」。

## 7 小结

- 几何表示二分：**隐式（条件方程）** 擅长判定与拓扑，**显式（点/参数）** 擅长采样与渲染。
- 隐式 $f(p)=0$ 判内外快、采样难；显式 $f(u,v)$ 采样快、判定难——**强弱互补**。
- 九大流派各据一方：网格统治游戏、NURBS 统治 CAD、SDF 统治体积与碰撞。
- 渲染接口统一为「转成三角形」；神经渲染正在打破这个范式。
