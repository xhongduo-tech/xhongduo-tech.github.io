## 为什么角色要「骨骼」

动画师想动的不是「顶点」，而是「关节」——抬手、弯腰、转身，这些是骨骼动作，不是顶点动作。**骨骼动画（skeletal animation）** 把角色抽象成两件事：**骨骼**（关节层级）定义「怎么动」，**蒙皮**（顶点绑定）定义「皮肤怎么跟着动」。本节讲前者——运动学。<span class="marginnote">骨骼动画的分工：<strong>骨骼管「运动的结构」，蒙皮管「表面的形变」</strong>。动画师操作关节角度，骨骼把角度传播到所有子关节，蒙皮把骨骼姿态映射到顶点——两个层次解耦，让「调动作」与「管表面」互不干扰。这是角色动画的根本架构。</span>

**运动学（kinematics）** 研究「关节角度 ↔ 末端位置」的关系，分两个方向：**正向运动学（FK）** 从关节角度求末端位置，**反向运动学（IK）** 从目标位置求关节角度。

## 1 骨骼的层级结构

骨骼是一棵**树**：根关节（如骨盆）是树根，每块骨头（bone/joint）是节点，通过父子关系连接：

```text
骨盆（根关节）
├── 脊柱 → 胸 → 锁骨
│        ├── 左上臂 → 左前臂 → 左手
│        └── 右上臂 → 右前臂 → 右手
├── 左大腿 → 左小腿 → 左脚
└── 右大腿 → 右小腿 → 右脚
```

每个关节相对父关节有一个**局部变换**（通常是旋转，也可有平移）。关节的世界变换 = 沿骨骼链从根到该关节的局部变换连乘：

$$
\mathbf{M}_{\text{joint}} = \mathbf{M}_{\text{parent}} \cdot \mathbf{R}_{\text{local}} = \mathbf{M}_{\text{root}} \cdots \mathbf{M}_{\text{grandparent}} \cdot \mathbf{M}_{\text{parent}} \cdot \mathbf{R}_{\text{local}}
$$

**改一个关节角度，它和所有后代一起动**——这正是层级变换（模型变换篇的递归）在角色上的应用。<span class="marginnote">骨骼树的「一动百动」来自层级变换的传递性：<strong>旋转大腿，小腿和脚自动跟着转</strong>——因为小腿的世界变换包含大腿的旋转。动画系统每帧对每个关节算一次「从根到它的连乘」，把所有关节的世界变换更新一遍——这是骨骼动画每帧的核心计算。</span>

## 2 正向运动学（FK）：从角度到位置

**正向运动学**：给定每个关节的旋转角度，计算末端（如手、脚）的世界位置。

$$
\mathbf{P}_{\text{end}} = \mathbf{M}_{\text{root}}\, \mathbf{R}_{\text{hip}}\, \mathbf{R}_{\text{knee}}\, \mathbf{R}_{\text{ankle}}\, \mathbf{P}_{\text{end-local}}
$$

FK 是**直接、唯一**的：关节角度定了，末端位置就定了（解析计算）。动画师摆「关节角度」就是 FK——直观但费力（要调好几个角度才能让手碰到目标）。<span class="marginnote">FK 的「直接性」是优点也是缺点：<strong>每个末端姿势对应唯一的关节角度组合，但「让手碰到某个点」需要反推角度——FK 不擅长这个</strong>。动画师常用 FK 摆「挥手的姿态」（从关节出发），但要让「手抓杯子」（从目标出发）就得用 IK。</span>

## 3 反向运动学（IK）：从目标到角度

**反向运动学**：给定末端的**目标位置**（如手要碰到杯子），反解关节角度。

$$
\text{求 } \theta_{\text{shoulder}}, \theta_{\text{elbow}} \text{ 使得 } \mathbf{P}_{\text{hand}}(\theta) = \mathbf{P}_{\text{target}}
$$

IK 是**困难、非唯一**的：

- **多解**：肘关节可以「朝内」或「朝外」摆，都让手碰到目标。
- **无解**：目标超出关节链的伸展范围。
- **非线性**：末端位置是角度的非线性函数。

**IK 的解算方法**：解析法（简单链的闭式解）、迭代法（雅可比伪逆、CCD）。迭代法最通用：从当前角度出发，反复调整角度使末端逼近目标。<span class="marginnote">IK 的「多解性」让它需要额外约束：<strong>指定肘关节偏向哪一侧（关节限位）、或让 IK 解「尽量接近当前姿势」</strong>——否则每次解算末端的位置都对，但手臂可能「乱扭」。工程上 IK 常与「平滑度」约束配合，保证解连续变化不抖。</span>

## 4 公式解析：雅可比法解 IK

迭代 IK 的通用框架用**雅可比矩阵**把「角度变化」与「末端位移」线性化：

$$
\Delta \mathbf{P} \approx \mathbf{J}(\theta)\, \Delta\theta
$$

其中 $\mathbf{J}$ 是雅可比矩阵（末端位置对关节角度的偏导数）。

- **第一步，线性化**：在当前位置，末端位移 $\Delta P$ 与关节角度变化 $\Delta\theta$ 近似线性关系，系数矩阵是雅可比 $\mathbf{J}$。
- **第二步，求逆**：解 $\Delta\theta = \mathbf{J}^{-1} \Delta P$（欠定/超定时用伪逆 $\mathbf{J}^+$）——得到让末端移动 $\Delta P$ 的角度调整。
- **第三步，迭代**：重复「算雅可比 → 解 $\Delta\theta$ → 更新角度」直到末端到达目标（或收敛）。

**辨析｜易错点：** 雅可比矩阵可能是**奇异**的（关节链伸直时某些方向不可达），伪逆在这时产生病态解。另一个坑是**迭代不收敛**：目标不可达或步长太大时，解在目标附近振荡——需要阻尼（如阻尼最小二乘）或限制步长。

## 5 FK 与 IK 的工程分工

现代动画系统里 FK 与 IK 各司其职：

| | FK | IK |
| --- | --- | --- |
| 输入 → 输出 | 角度 → 末端位置 | 目标位置 → 角度 |
| 计算 | 直接、唯一 | 迭代、多解 |
| 适用 | 挥手、摆姿势 | 抓取、脚落地 |
| 动画师体验 | 从关节出发 | 从目标出发 |

**混合**：手部用 IK（抓杯子），身体用 FK（躯干摆动）——层次混合是角色动画的标配。脚部 IK 让脚贴合地形（走路时不陷地），是游戏角色的必备。<span class="marginnote">「上肢 IK、下肢 IK、躯干 FK」是角色动画的典型分工：<strong>手抓取用 IK（目标驱动）、脚落地用 IK（贴合地面）、躯干摆动用 FK（自然姿态）</strong>。每帧先算 FK 得到基础姿态，再叠 IK 约束修正局部，最后合成骨骼的世界变换——这套「FK 为主、IK 为辅」的流程是引擎动画系统的标准架构。</span>

## 6 从运动学到蒙皮

骨骼的「运动」只是骨架——真正让角色「看起来在动」的是**蒙皮（skinning）**：把骨骼姿态映射到网格顶点。蒙皮要回答「每个顶点跟随哪些骨骼、各占多少权重」——这是下一节《蒙皮与混合变形》的主题。

骨骼动画的完整管线：**关键帧（动画数据）→ FK/IK（骨骼姿态）→ 蒙皮（顶点形变）→ 渲染**——每一环都在把「时间」翻译成「画面」。<span class="marginnote">骨骼动画的管线是「信息逐级翻译」：<strong>动画曲线给出关节角度（时间 → 角度）→ FK/IK 给出骨骼世界变换（角度 → 变换）→ 蒙皮给出顶点位置（变换 → 顶点）</strong>。每一级的输出是下一级的输入，理解每一级的「输入输出」，就理解了整个角色动画引擎。</span>

## 6 运动学与动画系统的结合：FK/IK 的工程现实

FK/IK 不是「二选一」——动画系统里它们「分工协作」，理解工程现实就理解了「为什么都要学」。

**动画剪辑里的 FK**：动画数据（关键帧）驱动的是「关节旋转」（FK 的输入）——走路、跑步的动画都是「FK 姿势」。引擎每帧对每个关节算「FK 世界矩阵」——这是「基础姿态」。

**IK 作为「后处理修正」**：基础 FK 姿态上，加 IK 约束修正局部：

- **脚部 IK**：脚要「贴合地面」（不陷地、不滑步）——用 IK 把脚「拉」到地面的正确位置。
- **手部 IK**：手要「抓杯子」——用 IK 把手「拉」到目标。
- **实现**：先 FK 得基础姿态，再 IK 解算「末端位置约束」，把修正「局部」应用到受影响关节——「FK 为主、IK 为辅」。

**为什么「FK 为主」**：FK 直接、稳定、可控（动画师摆的姿势）；IK 是「约束求解」，可能「多解、抖动」——「能 FK 解决的别用 IK」是动画工程的原则。

**混合与权重**：FK 与 IK 的权重可以渐变——「走路时手自然摆（FK），接近桌子时手被 IK 拉向目标（权重渐增）」——「FK/IK 渐变」是「自然过渡」的工程手法。

**辨析｜易错点：** 两个工程坑：

1. **IK 的「抖动」**——每帧 IK 解算的数值微小变化累积，末端「抖」——「平滑化 + 收敛阈值」缓解。
2. **FK/IK 的「叠加错误」**——FK 姿态与 IK 修正叠加，关节可能「过度拉伸」——「限制关节角度范围」防过度。

**「FK/IK 的结合 = 基础姿态 + 约束修正」**——理解了工程现实，你就知道「为什么角色动画既需要 FK（摆姿势）又需要 IK（抓取落地）」。

## 7 小结

- **骨骼动画** = 骨骼（关节层级）+ 蒙皮（顶点绑定），运动与表面解耦。
- 骨骼是树，关节世界变换 = 根到该关节的连乘，「改父动子」。
- **FK**：角度 → 位置，直接唯一，适合摆姿势。
- **IK**：目标 → 角度，迭代多解，适合抓取/落地；雅可比法是通用框架。
- 工程分工：上肢/下肢 IK、躯干 FK，混合解算；下一节进入蒙皮。
