## 为什么法线贴图还不够

前两节的法线/凹凸贴图把表面细节做得惟妙惟肖，但有个硬伤始终绕不过去：**轮廓是假的**。一个用法线贴图做了砖缝的平面，从侧面看依旧是一条直线——光照骗过去了，几何没骗过去。当镜头贴近、需要真实轮廓与自阴影时，必须让**几何真的位移**。这就是**位移贴图（displacement mapping）**：用高度图把顶点沿法线方向真的挪动。<span class="marginnote">位移贴图与法线贴图的本质区别：<strong>法线贴图骗光照，位移贴图改几何</strong>。位移后，轮廓会真实变化、凹处会挡住光、凸起会投射阴影——代价是几何复杂度真实增加，需要足够密的网格来承载位移。</span>

本节还把「纹理」的概念再拓宽一步：从「存图片」到「用函数生成」——**程序纹理（procedural texture）**。它与位移贴图放在一起，因为它们共享一个理念：**纹理是表面的通用属性，几何也是**。

## 1 位移贴图：沿法线挪动顶点

位移贴图的输入与凹凸贴图一样是**高度图**，但用法不同——不是扰动法线，而是**沿法线方向移动顶点位置**：

$$
p' = p + h(p)\, \vec{n}(p)
$$

$h(p)$ 是高度图上该点的高度值，$\vec{n}(p)$ 是法线。正高度向外凸、负高度向里凹。<span class="marginnote">位移的方向取法线——这意味着位移后的表面在凹凸处法线也随之变化，光照与几何「内外一致」：凸起处真的凸起，其法线也真的朝外，明暗自然正确。这是位移贴图相对法线贴图的根本优势：<strong>几何与光照自洽</strong>。</span>

位移必须发生在**网格足够密**时才有意义：若一个三角形跨过好几个凸起，位移只会把整块三角形平移，凹凸出不来。所以位移贴图的经典实现是「细分 + 位移」：先用曲面细分（tessellation）把网格细化，再在每个细分的顶点上做位移。

## 2 位移后的法线：重新计算

位移改变了表面形状，法线不能再从原模型取——必须**重新计算**。取位移表面上的相邻点 $p + \delta p_1$、$p + \delta p_2$，位移后：

$$
\vec{n}' = \text{normalize}\left( \frac{\partial p'}{\partial u} \times \frac{\partial p'}{\partial v} \right)
$$

其中 $\frac{\partial p'}{\partial u} = \frac{\partial p}{\partial u} + \frac{\partial h}{\partial u}\vec{n} + h\frac{\partial \vec{n}}{\partial u}$ 是位移表面沿 $u$ 方向的切线。物理上，这个法线是「真实几何」的法线——它同时携带了位移后的形状信息。<span class="marginnote">有趣的是，位移贴图的法线计算在数学上等价于「先求高度梯度再合成法线」——与凹凸贴图的公式殊途同归。区别只在：凹凸贴图用法线骗光照，位移贴图先位移几何再重算法线，二者结果一致，但位移贴图的<strong>轮廓是真的</strong>。</span>

## 3 位移贴图与细分：硬件管线的配合

位移贴图在实时渲染里依赖**曲面细分阶段（tessellation）**：

1. **控制点细分**：GPU 硬件把每个三角形细分成更多小三角形（细分因子由距离、屏幕面积决定）。
2. **顶点位移**：在每个细分顶点上采样高度图，沿法线位移。
3. **法线重算**：对位移后的顶点重算法线。
4. **常规光栅化**：把细分并位移后的网格送入光栅化。

曲面细分让位移贴图的密度自适应：近处细分细（细节足），远处细分粗（省性能）。<span class="marginnote">曲面细分 + 位移贴图是现代 GPU 的可选管线阶段（DirectX 11 的 Hull/Domain shader、OpenGL 的 Tessellation shader）。它把「位移贴图」从离线渲染技术变成了实时可行的方案，代价是细分因子选不好会导致远处的「抖动」（顶点在山峰山谷间跳变）。</span>

**辨析｜易错点：** 位移贴图最容易错的是**忘配细分**——用普通网格跑位移，顶点太少，位移后表面出现严重「台阶」而非平滑凹凸。另一个坑是高度图与法线贴图的混用：若同时用位移贴图与法线贴图，法线贴图必须与位移后的几何一致，否则「位移的凸起」与「法线贴图的凹凸」打架，出现双重明暗。

## 4 三维程序纹理：摆脱 UV 的纹理

位移贴图把纹理用于几何，而**程序纹理（procedural texture）** 则彻底摆脱「存图片」的范式：**颜色由一个数学函数直接计算**，不需要 UV、不需要存储。

$$
\text{color}(p) = f(p_x, p_y, p_z)
$$

- **木纹**：$f = \text{stripes}(\text{noise}(\text{radius}))$——用噪声扰动圆柱半径，得到木头的年轮。
- **大理石**：$f = \text{sin} + \text{turbulence}$——正弦叠加噪声，得到大理石纹路。
- **云彩**：$f = \text{fracal noise}(p)$——分形噪声，得到云的体积感。<span class="marginnote">程序纹理的核心工具是<strong>噪声函数（noise）</strong>：一个看似随机、实则连续平滑的函数。Perlin 噪声（Ken Perlin 1985 年提出，奥斯卡技术奖）通过插值随机梯度生成，是木纹、大理石、云朵等一切自然纹理的原料。它的「平滑随机」恰好匹配自然界的斑驳。</span>

程序纹理的优势：无限分辨率（任意放大不糊）、无穷细节（无需存储）、自动无缝（三维连续）。代价：计算成本随复杂度上升，且「好看」的程序纹理极难设计——需要噪声、分形的深厚功底。

## 5 三维程序纹理 vs 二维纹理贴图

| | 二维纹理贴图 | 三维程序纹理 |
| --- | --- | --- |
| 来源 | 存好的图片 | 数学函数 |
| 坐标 | UV（表面参数） | 世界/物体坐标 |
| 分辨率 | 固定 | 无限 |
| 存储 | 需要 | 不需要 |
| 拉伸 | UV 展开不好会拉伸 | 无拉伸（三维各向同性） |
| 成本 | 采样快 | 计算贵 |

程序纹理常与位移贴图连用：**同一套噪声既做颜色又做位移**——石头的高度与颜色来自同一个三维噪声场，表面凹凸与明暗天然一致，比人工对齐的贴图自然得多。<span class="marginnote">「同一个函数驱动颜色与几何」是程序化建模与渲染的黄金组合：山体的高度场、颜色、湿度、植被分布全部从同一个噪声场派生，产生出高度自洽的自然景观。这是《隐式表示：分形与自相似》与离线渲染（如 RenderMan 的 Ptext）里的常用手法。</span>

## 6 程序纹理与噪声函数的工程基础

程序纹理的「原料」是噪声——理解噪声的工程实现，才能写出「好看」的程序纹理。

**Perlin 噪声（Perlin noise）** 是最经典的平滑噪声，核心三要素：

- **晶格（lattice）**：把空间切成网格，每个格点一个「随机梯度向量」（方向随机、长度固定）。
- **插值**：点 $p$ 处的噪声 = 对周围 4（2D）/8（3D）个格点的「梯度 · 到格点的向量」做平滑插值。
- **平滑**：插值权重用「smoothstep」（$6t^5-15t^4+10t^3$），让噪声连续且导数连续——这是「看起来自然」的关键。

**Simplex 噪声**：Perlin 的改进——用单纯形（三角/四面体）替代超立方体晶格，计算更快、各向同性更好、无方向伪影。

**fBm（分形噪声）**：叠加多层噪声（频率翻倍、幅度减半），是程序纹理的「主力工具」：

$$
\text{fBm}(p) = \sum_{i=0}^{n} \frac{\text{noise}(2^i p)}{2^i}
$$

- 每层加「高频细节」，幅度递减——自相似结构（《分形》篇）。
- 层数 $n$ 决定「细节到多细」，也是性能/质量旋钮。

**程序纹理的「无限细节」**：任意放大，噪声函数都连续可算——不像位图纹理有分辨率上限。这让程序纹理在「巨大表面」（地面、天空、水体）上有天然优势——没有接缝、没有分辨率预算。

**辨析｜易错点：** 程序纹理的三个常见坑：

1. **噪声的「格子伪影」**——Perlin 噪声在晶格点处有「格子感」——用 Simplex 或「域扭曲」（domain warping）缓解。
2. **fBm 的幅度/频率关系**——幅度减半太快则细节少，太慢则「噪」——「$1/2^i$ 幅度、$2^i$ 频率」是「自相似」的平衡点。
3. **噪声的哈希种子**——同一噪声函数的不同种子产生不同「图案」——程序化地形、材质要「按种子可复现」，否则每次启动场景「不一样」。

程序纹理把「纹理」从「存的图」变成「算的函数」——理解噪声的实现与调参，是写出「像自然」的程序内容的基础。

## 7 小结

- **位移贴图 = 沿法线真的挪动顶点**：$p' = p + h(p)\vec{n}(p)$，几何与光照自洽，轮廓真实。
- 位移后的法线需**重新计算**（位移表面的切向叉积），等价于「高度梯度合成法线」。
- 实时位移依赖**曲面细分**提供足够密的网格，细分因子要慎选。
- **程序纹理 = 函数生成颜色**，摆脱 UV 与存储，靠噪声函数实现自然纹理。
- 程序纹理 + 位移贴图连用，颜色与几何同源，自洽度最高。
