## 为什么 BVH 是工业标准

上一节我们看到了空间划分（KD-Tree/Octree）的致命伤：三角形跨切面要被复制。**BVH（Bounding Volume Hierarchy，包围盒层次结构）** 换了一个思路——**不切空间，切物体**：把场景中的物体递归分组，每组用一个包围盒圈住。<span class="marginnote">BVH 的关键区别：<strong>空间划分「切空间，物体被切碎」；BVH「切物体，空间被分割成重叠的包围盒」</strong>。每个三角形只属于一个叶子节点、只存一份——没有复制、没有「切碎」问题，构建也简单得多。现代光追（RTX、Embree、OptiX）几乎全部使用 BVH。</span>

BVH 的代价是：兄弟节点的包围盒可能**重叠**（因为切的是物体分组，不是空间），光线可能要进多个分支。但重叠造成的额外遍历，远小于空间划分的复制膨胀——实践验证 BVH 全面胜出。

## 1 BVH 的结构

**BVH** 是一棵二叉树：

- **叶子节点**：存放一组三角形（通常少量，如 5–16 个）及其包围盒。
- **内部节点**：存放「两个子节点的包围盒并集」的包围盒，以及指向子节点的指针。
- **根节点**：整个场景的包围盒。

每个节点的包围盒 = 该节点下所有三角形的最小包围盒（AABB）。树的构建目标：**让每个节点的包围盒尽量小、兄弟节点的重叠尽量少**——这样光线进入一个分支后，能尽快排除另一个分支。<span class="marginnote">BVH 的「层次」体现在包围盒的嵌套：根节点包围盒最大，向下逐层缩小，叶子包围盒最小。这个嵌套让遍历可以「由上到下剪枝」——光线不碰上层大盒子，下面整棵子树跳过。</span>

## 2 BVH 的构建：递归分组

BVH 的构建是一个「分治」过程：

1. **初始化**：把所有三角形作为根节点的集合。
2. **选划分轴**：通常选「三角形重心分布最分散」的轴（包围盒最长轴或方差最大轴）。
3. **划分**：按该轴的重心坐标，把三角形分成两组（如按中位数、或按 SAH 最优切点）。
4. **递归**：对每组递归构建，直到组的三角形数 ≤ 阈值（成为叶子）。

划分质量决定 BVH 效率：**好的划分让两个子包围盒都小且不重叠**。最简单的划分是按重心坐标中位数——两半数量均衡，深度 $O(\log N)$。<span class="marginnote">「按重心中位数划分」保证树的平衡（两半数量差不多），但包围盒可能大（同一半里的三角形可能很分散）。「按空间位置划分」让包围盒小，但数量可能失衡。SAH（表面积启发式）在这两者间找最优——下一节《BVH 的构建与遍历：SAH 划分》专门讲它。</span>

## 3 BVH 的光线遍历

遍历 BVH 求交的递归流程：

```
function intersect(node, ray, t_best):
    if 光线不碰 node.bbox: return          # 剪枝
    if node 是叶子:
        for tri in node.tris: t_best = min(t_best, MT(tri, ray))
    else:
        # 先近后远：优先遍历更近的子节点
        intersect(近子节点, ray, t_best)
        if t_best 未更新? 继续: 还要遍历远子节点吗?
        intersect(远子节点, ray, t_best)
```

遍历的两个关键点：**剪枝**（不碰包围盒就返回）与**先近后远**（先查更近的子节点，让 $t_{\text{best}}$ 尽快变小，从而剪掉更远的子树）。<span class="marginnote">「先近后远」的顺序优化：先遍历「光线先到达的子节点」，尽早找到一个近的命中，$t_{\text{best}}$ 迅速变小——远子节点的包围盒若在 $t_{\text{best}}$ 之后，直接跳过。这个「用近命中剪远子树」的机制，让 BVH 期望遍历成本接近 O(log N)。</span>

## 4 公式解析：BVH vs 空间划分的对比

把两种结构的核心差异用一张对比表钉死：

| | 空间划分（KD-Tree/Octree） | 物体划分（BVH） |
| --- | --- | --- |
| 划分对象 | 空间区域 | 物体集合 |
| 三角形归属 | 可复制到多个叶子 | 每三角形只属一个叶子 |
| 兄弟包围盒 | 不相交（切空间） | 可能重叠 |
| 构建 | 复杂（处理跨切面） | 简单（分组 + 包围盒） |
| 动态更新 | 难 | 较易（重算包围盒） |
| 现代光追 | 基本弃用 | **工业标准** |

- **第一步，看三角形归属**：空间划分里一个跨切面的三角形复制两份；BVH 里它只属于一组。→ BVH 无复制膨胀。
- **第二步，看包围盒**：空间划分的兄弟盒不重叠；BVH 的兄弟盒可能重叠（物体分组的结果）。→ 空间划分遍历「不重不漏」，BVH 可能有重复访问。
- **第三步，权衡**：BVH 用「可能重叠」换「不复制、易构建」，实践上净收益为正——这是它胜出的原因。

## 5 BVH 的动态场景与更新

静态场景的 BVH 一次构建、多次复用。**动态场景**（物体移动）有两种策略：

- **重建**：每帧重新构建 BVH。对几万三角形现代 CPU/GPU 可以做到每帧重建（硬件 BVH builder）。
- **重定位（refit）**：拓扑不变，只从叶子向上重算包围盒。快，但包围盒会「膨胀」——物体移动后，旧的分组不再最优，包围盒越滚越大。

工程上常用「局部重建 + 重定位」混合：移动物体先重定位，膨胀到阈值就局部重建。现代引擎（UE 的 Nanite、光追管线）普遍用 BVH 的四叉/八叉变体（BVH4/8）提高带宽效率。<span class="marginnote">BVH 的动态更新是实时光追的关键工程：RTX 硬件提供「重建模式」与「更新模式」两种 BVH 操作，前者保质量、后者省带宽——游戏里远距离物体重建、近距离物体更新，是性能调优的常见手法。BVH4/8（每个内部节点 4/8 个子节点）减少树深、利用 SIMD，是现代实现的标配。</span>

## 6 BVH 在现代光追硬件的形态

BVH 不只是软件结构——它被「烧进」了 GPU：

- **RTX / OptiX**：硬件遍历 BVH，每个光追核心原生执行「包围盒测试 + 三角形求交」。
- **Embree**：Intel 的软件 BVH 库，影视渲染的事实标准。
- **加速结构与着色解耦**：硬件只管「找命中」，命中后法线、材质、着色仍是通用的（可编程）。

理解 BVH 的构建与遍历，等于理解现代 GPU 光追单元「里面在干什么」——它是光追从「玩具」到「实时工业」的最后一块拼图。<span class="marginnote">「BVH 是光追工业化的支点」：没有 BVH，光线与一亿三角形的求交不可能实时；有了 BVH + 硬件化，光追从电影特效走进每一块游戏显卡。理解 BVH 不只是理解一个数据结构，更是理解「算法如何变成芯片」的典范——<strong>最高频的操作被硬件化，是所有实时图形技术的宿命</strong>。</span>

## 6 BVH 的工程细节：内存布局与遍历优化

BVH 的「数据结构」只是骨架，工程实现还有几个「决定性能」的细节。

**内存布局（SOA vs AOS）**：BVH 节点存包围盒（两个角点）+ 子节点指针/索引。对 GPU 遍历，用**数组存储**（无指针，用索引）——「结构体数组（SOA）」让包围盒数据连续，SIMD 一次读多个节点的包围盒，遍历吞吐翻倍。

**扁平化（flattened BVH）**：把树「压平」成数组，节点用「索引」而非「指针」——GPU 能「预取」、CPU 缓存友好——现代 BVH 都是扁平数组。

**遍历的 SIMD 优化**：一个 warp 的 32 条光线同时遍历——「宽 BVH」（每个节点 4/8 个子节点）+ SIMD 同时测试多个包围盒——「一指令测多个节点」，遍历成本大幅下降。

**遍历顺序**：先近后远（按光线进入包围盒的 $t$ 排序子节点）——「近子节点先查」让 $t_{\text{best}}$ 尽快变小、远子树更快被剪。

**辨析｜易错点：** 三个工程坑：

1. **节点大小与缓存**——BVH 节点太大（缓存装不下几个）、太小（深度深、间接层多）——「节点布局」是遍历性能的关键调优点。
2. **「分支」vs「数据并行」**——GPU 遍历 BVH 时「光线分歧」（不同光线走不同分支）导致 warp 效率低——「栈遍历 + 宽节点」缓解。
3. **重建的「内存碎片」**——动态重建频繁分配释放节点——用「内存池 + 复用」管理。

**「BVH 的工程 = 内存布局 + 遍历优化 + 重建管理」**——理解了这些细节，你就知道「为什么同样的 BVH，有的实现快 10 倍」。

## 7 小结

- **BVH = 物体划分**：递归把三角形分组，每组一个包围盒，三角形永不复制。
- 叶子存三角形，内部节点存子包围盒并集；构建 = 选轴、划分、递归。
- 遍历靠**剪枝**（不碰包围盒就跳过）与**先近后远**（近命中剪远子树）。
- 空间划分切空间（不重叠、但复制三角形），BVH 切物体（可重叠、但不复制）——实践上 BVH 全面胜出。
- 动态场景用重建/重定位混合；BVH 已被 RTX/Embree 硬件化。
