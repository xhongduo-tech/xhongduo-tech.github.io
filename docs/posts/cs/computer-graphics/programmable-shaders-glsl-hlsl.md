## 为什么着色器是渲染的灵魂

早期 GPU 是「固定功能管线」——光栅化、光照、纹理混合全是硬件写死的规则，程序员只能调参数。**可编程着色器（programmable shaders）** 把这个铁板撬开：让程序员用**着色器语言**（GLSL/HLSL）写「每个顶点/片元执行的代码」——从此 GPU 从「照本宣科的机器」变成「任你编程的并行计算机」。<span class="marginnote">着色器革命（2000 年代）的本质：<strong>把「固定功能」换成「可编程阶段」——顶点着色器、片元着色器可以写任意代码</strong>。这解放了渲染：PBR、卡通、水、全屏后处理……一切效果都从「硬件预设」变成「代码实现」。理解着色器，就理解了现代渲染「一切皆代码」的现实。</span>

本节深入可编程管线：着色器阶段、GLSL/HLSL 的语言结构、以及「一个着色器怎么编译运行在 GPU 上」。

## 1 着色器阶段地图

现代管线的可编程阶段：

| 阶段 | 输入 → 输出 | 执行频率 | 用途 |
| --- | --- | --- | --- |
| 顶点着色器 | 顶点属性 → 变换后顶点 | 每顶点 | 变换、顶点光照 |
| 曲面细分（Tessellation） | 控制点 → 细分网格 | 每面 | 动态加密几何 |
| 几何着色器 | 图元 → 图元 | 每图元 | 生成/修改图元 |
| 片元着色器 | 插值属性 → 颜色 | 每片元 | 纹理、光照、后处理 |
| 计算着色器 | 任意数据 → 任意数据 | 自定义 | 通用并行计算 |

顶点与片元是「主线」，细分/几何是可选增强，计算着色器是「全能的通用计算」——它们共同构成「可编程 GPU」的完整图景。<span class="marginnote">「顶点/片元/计算」是三个核心可编程阶段：<strong>顶点管「几何怎么变」，片元管「像素什么色」，计算管「任意并行计算」</strong>——细分与几何是「可选的中段」。现代引擎大量用计算着色器做「非渲染」任务（物理、粒子、后处理），让 GPU 不只是渲染器，而是「通用并行处理器」。</span>

## 2 GLSL 与 HLSL：着色器语言的家族

**GLSL**（OpenGL Shading Language）与 **HLSL**（High-Level Shading Language，DirectX）是两大主流着色器语言。它们的结构相似：

**main 函数**：入口，处理一个顶点/片元。
**in/out 变量**：输入与输出（顶点属性输入、插值变量传递）。
**uniform**：全局常量（每帧从 CPU 传入：矩阵、光源、时间）。
**内置变量**：`gl_Position`（顶点位置）、`gl_FragColor`（片元颜色，现代 GLSL 多用自定义 out 变量）。

一个最小片元着色器（GLSL）：

```glsl
#version 330 core
out vec4 FragColor;

void main() {
    FragColor = vec4(1.0, 0.5, 0.2, 1.0);   // 输出一个橙色的片元
}
```

**着色器语言是「数据并行」的**：你写「一个」片元的逻辑，GPU 把它应用到「所有」片元。<span class="marginnote">「着色器语言的关键认知：<strong>你写的代码只描述『一个顶点/片元』，GPU 会把它并行应用到百万个</strong>」——这是 SIMT 思维在语言层的体现。in/out 变量定义了「数据流」：顶点着色器的输出（颜色、UV、法线）经光栅化插值后成为片元着色器的输入——着色器之间的「数据契约」由变量声明表达。</span>

## 3 从源码到机器码：着色器编译

着色器从源码到 GPU 指令的旅程：

1. **编译**：GLSL/HLSL 源码编译成**中间表示（IR）**。
2. **平台适配**：IR 转成目标 GPU 的**着色器字节码**（如 SPIR-V for Vulkan、DXIL for DX12）。
3. **驱动转译**：GPU 驱动把字节码转成硬件指令。
4. **加载**：运行时（glShader/glProgram）链接、绑定到管线。

现代渲染 API（Vulkan/DX12）支持**预编译**：把 SPIR-V/DXIL 预先编译好，避免运行时编译卡顿（shader compilation stutter）——这是游戏优化的关键一环。<span class="marginnote">「着色器编译是现代引擎的『启动瓶颈』」：<strong>运行时编译成千上万个着色器会让游戏『卡顿』——现代引擎用预编译（离线编译好 SPIR-V）、异步编译、以及缓存（首次编译后缓存复用）来消除卡顿</strong>。Vulkan/DX12 的「管线对象」预创建让这个流程可控。理解编译流程，就理解了『shader compilation stutter』这个游戏优化热点。</span>

## 4 公式解析：一个顶点着色器在做什么

看一个典型的顶点着色器，追踪它在每个顶点上做的数学：

```glsl
#version 330 core
layout(location = 0) in vec3 aPos;   // 顶点位置（模型空间）

uniform mat4 uModel;       // 局部 → 世界
uniform mat4 uView;        // 世界 → 相机
uniform mat4 uProjection;  // 相机 → NDC

void main() {
    gl_Position = uProjection * uView * uModel * vec4(aPos, 1.0);
}
```

**第一步，顶点属性**：`aPos` 是顶点在模型空间的坐标，来自顶点缓冲。
**第二步，变换链**：`uModel`（局部→世界）→ `uView`（世界→相机）→ `uProjection`（相机→NDC），三个矩阵从右往左作用——这正是《变换》篇的完整链条。
**第三步，输出**：`gl_Position` 是 NDC 坐标，光栅化器据此遍历三角形、插值属性。

**辨析｜易错点：** 着色器的**精度**与**平台差异**是经典坑：移动端 GLSL 的 `mediump`/`highp` 精度声明、HLSL 的 `half`/`float` 精度选择——精度不足导致颜色带、闪烁。另一个坑：**uniform 对齐**——CPU 传入的 uniform 缓冲要按 GPU 的对齐规则打包，错位会让矩阵「读歪」。

## 5 着色器风格：从「画一个像素」到「写一种风格」

着色器的威力在于它把「渲染风格」变成代码：

**PBR 着色器**：读材质贴图、算 Cook-Torrance、查 IBL——一行行实现《材质》篇的公式。
**卡通着色**：对漫反射做阶梯量化（色阶）、描边——风格化的「toon shading」。
**全屏后处理**：片元着色器处理「整帧纹理」——色调映射、模糊、发光。
**程序纹理**：片元着色器用噪声函数生成颜色——上一节《程序纹理》的运行时版。

「着色器 = 渲染效果的可编程表达」——同一条管线上，换一个着色器就换一种画风。<span class="marginnote">「着色器让渲染从『效果』变成『代码』」：<strong>同样是光栅化管线，卡通着色器画出二次元、PBR 着色器画出写实、屏幕着色器画出抽象——渲染风格完全由着色器决定</strong>。这也是为什么引擎的「材质系统」本质是「着色器 + 参数的集合」——程序员写着色器模板，美术填参数，各司其职。</span>

## 6 从着色器到整个 GPU 编程生态

着色器只是 GPU 编程的入口，现代 GPU 编程是完整的生态：

**着色器语言**：GLSL、HLSL、还有可编译到多后端的 **HLSL→SPIR-V 工具链**（如 DXC）。
**计算着色器**：通用并行计算（物理、粒子、AI 推理）——GPU 从「渲染器」变成「通用处理器」。
**Compute API**：CUDA、OpenCL 直接面向通用计算（下一节）。

着色器语言与现代计算语言的界限越来越模糊——「在 GPU 上写代码」是现代软件工程的核心技能之一。<span class="marginnote">「GPU 编程的『一体两面』：<strong>渲染侧用着色器语言（GLSL/HLSL，面向图形管线），通用计算侧用 CUDA/Compute Shader（面向数据并行）</strong>」——两者的硬件（SM/CUDA 核）相同，只是「面向的抽象」不同。下一节我们把视角从「渲染」转向「通用计算」，看 GPU 如何成为「并行计算的发动机」。</span>

## 7 小结

- 可编程阶段：**顶点 / 细分 / 几何 / 片元 / 计算**着色器，把固定管线变成可编程。
- **GLSL / HLSL**：着色器语言，`main` 入口 + in/out 变量 + uniform 的结构，数据并行。
- 编译链：源码 → IR → 字节码（SPIR-V/DXIL）→ 硬件指令；预编译解决运行时卡顿。
- 顶点着色器执行《变换》篇的完整矩阵链；片元着色器执行光照/纹理/后处理。
- 着色器 = 渲染风格的可编程表达；GPU 编程从渲染走向通用计算（下一节）。

在下一节，我们把 GPU 从「渲染器」看成「通用并行计算机」——**GPU 并行计算：CUDA/Compute Shader 与图形加速**。
