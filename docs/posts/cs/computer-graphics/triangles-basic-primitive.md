## 为什么三角形是基本图元

现代 GPU 渲染一个 3D 模型，最终都把它切成**三角形**喂给光栅化。为什么偏偏是三角形？三角形在二维里是最简单的多边形，但它的优势远不止「简单」。虎书与 GAMES101 都花一整节论证：三角形是「平面、可插值、可判定、可细分」四重优良性质的完美载体。<span class="marginnote">三角形（triangle）是图形学最基本的<b>图元（primitive）</b>：GPU 的输入输出都围绕它组织。四边形、五边形乃至任意多边形，最终都要剖分为三角形才能被光栅化。</span>

理解「为什么是三角形」，比记住「模型是三角形网格」更重要——它解释了光栅化算法的设计动机，也解释了为什么 GPU 硬件长成今天这个样子。

## 1 三角形是最简单的平面多边形

任意三角形必是**平面图形**：三个点总能落在一个平面上（不共线时）。而四边形不一定——一个四边形可以沿对角线「翘」起来，四个顶点不共面。对渲染而言，这意味着：

- 三角形上的任意点都能用一个平面方程描述，深度、光照计算可靠。
- 四边形若被强行渲染，必须劈成两个三角形，否则可能出现「扭面」、裂缝与深度错误。<span class="marginnote">这就是为什么建模软件里四边形最终也会被三角剖分（triangulation）。GPU 光栅化器只「认识」三角形，任何更复杂的图元都必须先切开。</span>

**任何多边形都能剖分为三角形**：对凸多边形，取一个顶点连对角线即可；对凹多边形，需要耳切（ear clipping）等算法。剖分是「复杂 → 基本」的归约，让图形硬件只需实现一种图元的处理逻辑。

## 2 三角形是「定义内部」最简单的图形

判断一个点是否在三角形内，是光栅化逐像素测试的核心。三角形的「内部」可以这样判定：对三角形三个顶点，如果点始终位于三条有向边的同一侧，则点在三角形内。用叉积表示：

$$
\text{inside}(p) = \bigwedge_{i} \left( \text{cross}(v_{i+1} - v_i,\; p - v_i) \cdot \hat{z} > 0 \right)
$$

即对每条有向边 $v_i \to v_{i+1}$，计算叉积的 $z$ 分量符号；三者的符号一致则 $p$ 在内部。<span class="marginnote">这一判定只需几次叉积和符号比较，是 GPU 能并行处理百万像素的原因之一。下一节《三角形遍历》我们会把这条公式用到包围盒的每个像素上。</span>

三角形内部的这个性质让「像素是否被覆盖」变成一个 O(1) 的代数测试，无需复杂几何算法——这是它作为光栅化基本图元的决定性优势。

## 3 三角形是天然的插值载体：重心坐标

光栅化不仅要回答「覆盖哪些像素」，还要回答「每个像素处颜色、深度、纹理坐标是多少」。这些属性只定义在三个顶点上，中间像素要靠**插值**。三角形给出了统一且唯一的插值工具——**重心坐标（barycentric coordinates）**：

$$
p = \alpha A + \beta B + \gamma C, \qquad \alpha + \beta + \gamma = 1
$$

任意像素 $p$ 可以被唯一写成三个顶点的凸组合 $(\alpha, \beta, \gamma)$，然后用同样的权重插值任何顶点属性。<span class="marginnote">重心坐标的美妙在于「同一组权重管一切」：颜色、深度、法线、纹理坐标全部用 $(\alpha,\beta,\gamma)$ 线性混合。而且 $\alpha,\beta,\gamma \ge 0$ 恰好等价于「$p$ 在三角形内」——内外的判定与插值由同一套坐标统一起来。</span>

重心坐标的存在，让 GPU 可以把「着色」降维成「顶点算一次 + 像素插值一次」，极大地压缩了计算量——这是后面《图形管线》与《纹理映射》的技术基础。

## 4 公式解析：重心坐标如何计算

给定三角形 $ABC$ 与点 $p$，重心坐标 $\alpha, \beta, \gamma$ 用面积比计算：

$$
\alpha = \frac{S_{\triangle PBC}}{S_{\triangle ABC}}, \qquad \beta = \frac{S_{\triangle PCA}}{S_{\triangle ABC}}, \qquad \gamma = \frac{S_{\triangle PAB}}{S_{\triangle ABC}}
$$

- **第一步，面积代替距离**：重心坐标的几何定义是「三个子三角形的面积比」。$S_{\triangle PBC}$ 是以 $P,B,C$ 为顶点的面积，$S_{\triangle ABC}$ 是总面积。
- **第二步，面积用叉积算**：二维面积 $S_{\triangle XYZ} = \frac{1}{2}\left|\text{cross}(Y-X, Z-X)\right|$，把点代入即可数值求解。
- **第三步，归一化**：三个子三角形面积之和恰为总面积（点 $p$ 在三角形内时），故 $\alpha+\beta+\gamma=1$ 自动成立；若 $p$ 在三角形外，某个系数为负——这也正是「内外判定」的统一。

**辨析｜易错点：** 重心坐标是「点在三角形内」的充分必要条件中，最容易被过度简化的一环。常见错误是直接用「点到三边的距离」代替面积比——那只在等边三角形附近近似成立；严格定义永远是面积比。另一个误区是把重心坐标与「均匀网格插值」混为一谈：重心坐标是**仿射**插值，在透视投影下必须用透视校正插值（除以 $w$ 后重新加权），否则纹理在透视场景里会「漂移」——这到《纹理映射》一节正面处理。

## 5 三角形还意味着：网格的数学地基

把三角形网格看作一个整体，它自身拥有丰富的数学结构：

- **拓扑**：顶点、边、面的连接关系构成一个二维复形，是网格处理（细分、简化）的代数基础。
- **法线**：三角形面法线 = 两条边的叉积；顶点法线 = 相邻面法线的加权平均，是平滑着色的依据。
- **流形性**：正规网格要求每条边恰被两个三角形共享，这是网格是否「合法」的判据。

三角形把几何与代数焊在了一起：**一条边是拓扑对象，叉积是几何对象，重心坐标是插值对象**——三者都建立在「三角形是最基本图元」这一前提上。<span class="marginnote">从《几何表示》篇开始，我们会深入三角形网格的细分、简化与正则化，那时你会看到：几乎所有网格算法都以「对每条边/每个三角形做局部操作」为单元，三角形是这些局部操作的天然粒度。</span>

## 6 三角形网格的数据结构与内存布局

「三角形是基本图元」的工程含义，藏在「怎么把三角形存进内存喂给 GPU」里。两种主流布局：

**索引三角形列表（indexed triangle list）**：

```
顶点数组：  v0(x,y,z,nx,ny,nz,u,v)  v1(...)  v2(...) ...
索引数组：  0 1 2   2 1 3   3 1 4 ...
```

- 顶点只存一份，索引引用它——相邻三角形共享顶点。
- GPU 顶点缓存（vertex cache）利用共享：处理完三角形 0-1-2，处理 2-1-3 时顶点 1、2 已在缓存——吞吐翻倍。

**非索引三角形列表（triangle list）**：

```
三角形 0： v0(x,y,z,nx,ny,nz,u,v)  v1(...)  v2(...)
三角形 1： ...
```

- 每个三角形独立存顶点——共享的顶点被复制 N 次，内存浪费但无索引间接层。

**为什么大多数管线用索引列表**：内存省 + 顶点缓存命中高。**为什么有时用非索引**：顶点没有共享（如纯色三角形、粒子四边形）时，索引层是纯开销。

**辨析｜易错点：** 三个工程坑：

1. **顶点格式的对齐**——位置（3 浮点）、法线（3 浮点）、UV（2 浮点）打包进结构体时，要对齐到 16 字节（GPU 的读取粒度），否则带宽浪费。
2. **索引的类型**——16 位索引上限 65535 个顶点，大网格要用 32 位索引，用错会「顶点索引越界」导致三角形「乱连」。
3. **退化三角形（面积为零）**——三个顶点共线或重合，渲染无效果但消耗带宽，导入时清理。

**顶点格式设计**是「三角形如何被 GPU 消费」的第一课——理解「共享索引 + 对齐布局」为什么是标准，就理解了 GPU 顶点处理的带宽优化。

## 7 小结

- **三角形必共面、可剖分任意多边形**，是 GPU 唯一认识的基本图元。
- 叉积符号判定让「点是否在三角形内」成为 O(1) 的代数测试。
- **重心坐标 $(\alpha,\beta,\gamma)$** 统一了「内外判定」与「属性插值」。
- 三角形网格自带拓扑、法线与流形性三重结构，是几何处理的数学地基。
