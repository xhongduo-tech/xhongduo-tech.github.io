## 为什么需要「管线」的视角

到此为止，我们已经零散地掌握了模型变换、视图变换、投影、光栅化、深度缓冲、着色。但它们不是一个个孤立的算法——真实 GPU 把它们焊成一条**流水线（pipeline）**：顶点进去，像素出来，中间每一站处理一件事。<span class="marginnote">「管线」这个名字来自工业流水线：每个阶段只做自己的事，前一阶段的输出是后一阶段的输入。GPU 之所以快，是因为管线各阶段<b>可以同时处理不同的数据</b>——第一个三角形还在光栅化时，第二个三角形已在顶点着色——这就是指令级并行的「流水线」在图形硬件上的放大版。</span>

理解管线，等于把前四节的知识串成一条能跑的通路。本节给出经典渲染管线的完整地图：**顶点处理 → 光栅化 → 片元处理**三大阶段，以及它们之间的数据流。

## 1 管线总览：三大阶段

经典 GPU 管线可以压缩为三个阶段：

```text
顶点输入 → 顶点着色器（变换/光照/属性）
        → 图元装配 → 光栅化（裁剪/遍历/插值）
        → 片元着色器（纹理采样/光照）→ 深度测试/混合 → 帧缓冲 → 屏幕
```

**顶点阶段**：每个顶点独立执行「顶点着色器」，做变换（模型/视图/投影）、顶点光照、属性传递。输出的是**屏幕空间顶点 + 顶点属性**。
**光栅化阶段**：把三角形拆成片元（像素候选），插值顶点属性（深度、颜色、纹理坐标、法线）。
**片元阶段**：每个片元独立执行「片元着色器」，做逐像素光照、纹理采样，输出颜色；再经深度测试、透明度混合，写入帧缓冲。<span class="marginnote">「顶点着色器」与「片元着色器」是 GPU 里可编程的部分，其余（光栅化、深度测试）是固定功能硬件。现代管线的精髓是「可编程 + 固定」的混合：程序员控制着色器，硬件负责快速、并行的固定操作。</span>

## 2 阶段一：顶点处理

进入管线的数据是**顶点数组**：位置、法线、纹理坐标，外加顶点索引（描述哪些顶点组成三角形）。顶点着色器对每个顶点做：

1. **变换**：模型矩阵 → 视图矩阵 → 投影矩阵，把顶点从局部系一路送到 NDC。
2. **顶点光照**（可选）：在顶点上算 Blinn-Phong 等光照，输出顶点颜色（Gouraud shading 的着色点）。
3. **属性传递**：把纹理坐标、法线等原样或变换后传给光栅化阶段。

顶点着色器是**逐顶点、无顺序**的——任意两个顶点互不依赖，GPU 可以同时跑成千上万个顶点。<span class="marginnote">顶点着色器的「无依赖」是它并行化的前提：GPU 一次性取一批顶点，交给数百个流处理器同时算。这也解释了为什么顶点数与 Shader 复杂度直接决定 GPU 负载——顶点阶段是「每顶点算一次」的工作量。</span>

## 3 阶段二：光栅化

顶点处理完，屏幕上有了一批三角形。光栅化阶段把三角形「像素化」：

1. **图元装配**：按索引把顶点组装成三角形。
2. **剪裁（clipping）**：把超出视锥体/屏幕的部分切掉，防止屏幕外的三角形污染边缘。
3. **透视除法与视口变换**：NDC → 屏幕坐标。
4. **三角形遍历**：上一节的包围盒 + 叉积判定，找出覆盖的像素。
5. **属性插值**：用重心坐标把顶点属性插值到每个片元——包括深度、颜色、纹理坐标、法线。<span class="marginnote">光栅化是固定功能硬件：它不做任何「智能」决策，只做几何分割与插值。它的速度决定了 GPU 的「填充率」（fill rate）——每秒能生成多少片元。剪裁、透视除法、插值全在这里发生，全部针对每个三角形/每个片元。</span>

光栅化输出的是**片元（fragment）**：一个「候选像素」——位置、深度、一组插值后的属性。它还不是最终像素，因为还不知道能不能通过深度测试、颜色怎么最终确定。

## 4 阶段三：片元处理与输出

片元着色器对每个片元执行：

1. **纹理采样**：用插值的纹理坐标去取纹理颜色。
2. **逐像素光照**：Phong shading 在这里做——用插值法线算完整 Blinn-Phong。
3. **输出颜色**：片元着色器输出一个颜色（RGBA）。

然后进入**逐片元测试**：

**深度测试**：与 Z-Buffer 比较，被挡住的片元丢弃。
**透明度混合（alpha blending）**：半透明片元与已有颜色按 alpha 混合。
**模板测试**（可选）：掩膜裁剪区域。

通过测试的片元写入帧缓冲，成为屏幕像素。<span class="marginnote">片元着色器的输出经深度/混合后写入帧缓冲。一个像素可能被多个三角形产生多个片元竞争，最终只留下「通过全部测试的那个」——这正是 Z-Buffer 一节「谁近谁赢」的机制在管线末端的执行。</span>

## 5 管线中的数据流：属性怎么「旅行」

追踪一个纹理坐标从顶点到像素的旅程，能看清管线的数据流：

**顶点阶段**：纹理坐标 $(u,v)$ 作为顶点属性，原样传给光栅化。
**光栅化**：三角形的三个顶点的 $(u,v)$ 用重心坐标插值，每个片元得到自己的 $(u,v)$。
**片元阶段**：片元用这个 $(u,v)$ 采样纹理。

**注意**：插值在屏幕空间进行，但纹理坐标与位置的关系在透视投影下是**非线性**的——直接线性插值会让纹理在透视场景里「漂移」。正确做法是**透视校正插值**（perspective-correct interpolation）：对 $\frac{u}{w}, \frac{v}{w}$ 插值再除以 $\frac{1}{w}$ 的插值。现代 GPU 硬件自动做这一步，但理解它是理解纹理映射正确性的关键。<span class="marginnote">透视校正插值是管线里最容易被忽略的正确性细节：如果直接插值 $u,v$，远处的地板纹理会出现弯曲的「波浪」，而不是自然收敛到消失点。GPU 免费提供透视校正，但在自己写软件光栅化器时极易踩坑。</span>

## 6 管线与 GPU 硬件的对应

管线的每一个阶段，几乎都对应 GPU 里的一块物理硬件：

| 管线阶段 | 硬件单元 | 特点 |
| --- | --- | --- |
| 顶点着色 | SIMD 流处理器 | 可编程，逐顶点并行 |
| 光栅化 | 固定功能单元 | 不可编程，极高吞吐 |
| 片元着色 | SIMD 流处理器 | 可编程，逐片元并行 |
| 深度/混合 | 固定功能单元 | 内存带宽敏感 |
| 帧缓冲 | 显存 | 颜色/深度/模板 |

GPU 的本质是「一堆并行算 + 一堆固定逻辑」：可编程部分用着色器语言（GLSL/HLSL）控制，固定部分由硬件设计决定。<span class="marginnote">理解管线与硬件的对应，是后面《GPU 渲染管线深入》与《GPU 并行计算》的铺垫：当你写 Compute Shader 时，其实是在「绕过固定管线，直接用可编程单元的并行能力」。管线不是终点，而是理解 GPU 的起点。</span>

## 6 管线的 Debug 思维：一个片元的一生

理解管线的最好方式，是「跟踪一个片元从生到死」——这也是调试渲染 bug 的思维框架。

**一个片元的一生**：

1. **出生**：顶点阶段产出三个屏幕空间顶点，光栅化器把它们连成三角形。
2. **裁剪**：三角形超出视锥的部分被剪掉（在裁剪空间做）。
3. **遍历**：包围盒 + 叉积判定，找出「被覆盖的像素」，每个像素中心成为一个片元。
4. **插值**：重心坐标插值 UV、法线、深度——片元获得「自己的属性」。
5. **着色**：片元着色器采样纹理、算光照，输出颜色。
6. **测试**：深度测试（被挡则死）、模板测试（被掩则死）。
7. **混合**：通过测试的片元与帧缓冲现有颜色混合（透明度）。
8. **死亡/写入**：要么被丢弃，要么写入帧缓冲成为像素。

**Debug 思维的三个问题**：

- **「这个片元活了吗？」**——它过了裁剪/遍历/插值吗？没到片元着色器 → 几何/光栅化问题。
- **「它算对了吗？」**——片元着色器输出对吗？颜色不对 → 着色/纹理问题。
- **「它活到最后了吗？」**——深度/模板测试过了吗？被挡了 → 遮挡/测试问题。

**调试工具**：现代调试器能「停住管线」（RenderDoc、Nsight）——断点设在顶点/片元着色器，查看「一个顶点/片元的输入输出」——「把管线当代码调试」是现代渲染调试的标准。

**辨析｜易错点：** 三个常见调试误判：

1. **「画面全黑」的定位**——可能是几何没进管线（摄像机朝向错）、可能是片元全被深度挡（深度缓冲没清）、可能是着色器输出 0——「按阶段二分排查」。
2. **「颜色错」的定位**——可能是插值错（顶点属性）、可能是采样错（UV）、可能是光照错（法线）——「在管线各阶段断点看中间值」。
3. **「闪烁」的定位**——可能是 Z-fighting（深度精度）、可能是未初始化的缓冲（残留数据）——「检查每个缓冲的初始状态」。

**「管线的 Debug 思维 = 跟踪片元的一生 + 分阶段定位」**——理解了每个阶段的输入输出，你就能「在 16ms 的管线里找到 1 个错误的片元」。

## 7 小结

- 管线三阶段：**顶点处理 → 光栅化 → 片元处理**，各阶段可并行流水。
- 顶点阶段做变换与顶点光照；光栅化做剪裁、遍历与插值；片元阶段做纹理采样与逐像素光照。
- 片元经深度测试与混合后写入帧缓冲，像素归属由「通过全部测试」决定。
- 属性在管线中旅行：顶点 → 重心插值 → 片元采样，透视投影下需要**透视校正插值**。

在下一节，我们把「属性插值」放大——**纹理映射：重心坐标插值**，让物体真正有「图案」。
