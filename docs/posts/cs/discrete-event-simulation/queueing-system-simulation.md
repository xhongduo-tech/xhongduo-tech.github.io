## 为什么从排队系统开始

排队是离散事件仿真最经典、也最立体的应用场景——银行柜台、医院分诊、客服电话、计算机网络的路由器缓存，全都是排队系统。<span class="marginnote">学排队系统仿真，等于同时在做三件事：把前四篇的工具（四件套、事件推进、随机数、输入分布）全部组装起来；用解析模型给仿真结果当「标准答案」做验证；然后走向解析模型够不着的现实队列。它是全专题的「集成测验」。</span>同时，排队分析也是第二级《排队论与可靠性数学》在仿真视角下的重演——那里求公式，这里跑实验。

## 1 排队系统的三要素与记号

一个排队系统由三要素构成：

**到达过程（arrival process）**：顾客何时到达，通常用到达间隔分布描述，最常见的是泊松到达（间隔服从指数分布）。**服务过程（service process）**：服务时长的分布，指数服务假设带来解析便利。**服务设施（service facility）**：服务台个数、队列容量、排队规则（FIFO / 优先级 / 随机）。

三个要素用一个叫 **Kendall 记号**的紧凑形式描述：

$$
A / B / c / K / N / D
$$

逐项含义：$A$ 到达间隔分布、$B$ 服务时间分布、$c$ 服务台数、$K$ 系统容量（含服务台，缺省为无穷）、$N$ 顾客总体（缺省为无穷）、$D$ 排队规则。<span class="marginnote">记号的常见写法：$M$ 表示泊松/指数（马尔可夫性），$D$ 表示确定性（定长），$G$ 表示一般分布。于是 $M/M/1$ 就是「泊松到达 + 指数服务 + 单服务台」——排队论里解析解最漂亮的系统。</span>

## 2 解析模型能做什么：M/M/1 与 Little 定律

$M/M/1$ 系统在稳定条件 $\rho = \lambda/\mu \lt  1$ 下有一组闭式结果：

- 平均队长（含服务中）：$L = \dfrac{\rho}{1-\rho}$
- 平均等待队长：$L_q = \dfrac{\rho^2}{1-\rho}$
- 平均逗留时间：$W = \dfrac{1}{\mu-\lambda}$
- 平均等待时间：$W_q = \dfrac{\rho}{\mu-\lambda}$

这些公式背后是**生灭过程**的平衡方程——第二级《排队论》的推导我们不再重复，这里只强调一个贯穿一切的普适关系：**Little 定律**。

## 3 公式解析：Little 定律 L = λ W

Little 定律是排队理论里最普适的公式，几乎不需要任何分布假设：

$$
L = \lambda W
$$

其中 $L$ 是系统内平均顾客数，$\lambda$ 是到达率，$W$ 是顾客平均逗留时间。三步拆解：

- **第一步，理解三个量**：$L$ 是「看任一时刻，系统里平均蹲着多少人」；$W$ 是「跟丢一个顾客，看他平均待多久」；$\lambda$ 是「单位时间放进来多少人」。
- **第二步，几何直觉**：画一张「系统内人数随时间变化」的阶梯图，$L$ 是曲线下的面积除以时长，$W$ 是每个顾客的逗留面积，$\lambda$ 是顾客个数除以时长。**人数×时间** 这个量被「除以人数」和「除以时间」各切一刀，等式自然成立。
- **第三步，看懂它的威力**：Little 定律对**任何**稳态排队系统成立——不限分布、不限服务台数、不限排队规则。它还能在更细的层面使用：$L_q = \lambda W_q$ 对等待中的顾客同样成立。

**辨析｜易错点：** Little 定律要求系统**稳态**且 $\lambda$ 是长期平均到达率。在仿真里用它做验证时，要等系统过了初始暂态、进入平稳后再统计——这正是《输出数据分析》篇里「终止型 vs 稳态型」要处理的问题。

## 4 仿真怎么跑排队系统

用第一篇的事件调度法实现一个 $M/M/1$，核心代码骨架不过几十行：

```
initialize: clock=0, queue=[], server_idle=True, N=0
schedule first arrival at T = -ln(U)/λ
loop while clock < T_end:
    pop earliest event E from FEL
    clock = E.time
    if E.type == arrival:
        N += 1
        if server_idle:
            server_idle = False
            schedule departure at clock -ln(U)/μ
        else:
            queue.append(customer)
        schedule next arrival at clock -ln(U)/λ
    if E.type == departure:
        if queue not empty:
            pop customer, schedule departure at clock -ln(U)/μ
        else:
            server_idle = True
```

事件循环的三段式（更新状态 → 调度新事件 → 记录统计量）在此一目了然。<span class="marginnote">注意到达与服务用的是<strong>两串独立的随机数</strong>：到达间隔用流 A、服务时长用流 B。这符合上一篇的种子纪律——两件事互不干扰，也便于用公共随机数做方案对比。</span>

仿真运行期间，连续记录队列长度，运行结束后按时间加权求平均队长——积分而不是简单平均，因为队列长度是分段恒定的阶梯函数。

## 5 解析够不着的现实队列

$M/M/1$ 的假设在现实里几乎总被打破，而每破一条，闭式解就消失一次：

**一般服务分布（$M/G/1$）**：仅剩 Pollaczek–Khinchin 公式给出有限指标，分布细节仍被抹平。
**有限容量（$M/M/1/K$）**：顾客见队满即走（**阻塞 balking**），队列自然封顶，但指标式变复杂。
**优先级排队**：高优先顾客插队，低优先顾客等待时间爆炸——解析困难，仿真却是改一行规则的功夫。<span class="marginnote">优先级队列是计算机网络里的真实日常：实时语音包优先于文件下载。仿真里它只是「从队尾取 vs 按优先级取」的区别，而解析里却要引入优先级的复杂分析——这是仿真「表达力换可解性」最生动的例子。</span>
**不耐烦（reneging）**：顾客等太久会离开；**可重试（retrial）**：被阻塞的顾客过会儿再来。
**多服务台 + 有限缓冲区 + 服务台故障**：任意组合都让解析模型望而却步。

这正是仿真的用武之地：**解析模型负责「已经被证明的系统」，仿真负责「尚未被解析的系统」**——前者是后者的验证基准，后者是前者的延伸。

## 6 性能指标与实验设计

排队系统仿真要汇报的核心指标：

| 指标 | 定义 | 对应解析基准（M/M/1） |
| --- | --- | --- |
| 平均队长 $L$ | 系统内平均顾客数 | $\rho/(1-\rho)$ |
| 平均等待队长 $L_q$ | 队列中平均人数 | $\rho^2/(1-\rho)$ |
| 平均逗留时间 $W$ | 从进入到离开的平均时长 | $1/(\mu-\lambda)$ |
| 平均等待时间 $W_q$ | 排队等待的平均时长 | $\rho/(\mu-\lambda)$ |
| 利用率 | 服务台忙碌时间占比 | $\rho$ |

这套指标正是验证模型的第一站。<span class="marginnote"><strong>验证套路</strong>：先仿真一个 $M/M/1$，把四个指标与解析值对比，若偏差在随机波动范围内（用置信区间判断），说明引擎正确；再一步步放开假设，逼近现实。这个「从解析基准出发逐步加复杂度」的流程，是排队仿真最可靠的工作方式。</span>

实验设计上要控制的两件事：**暂态期剔除**（前若干分钟系统在「启动」，统计会偏低，先预热再统计）与**运行次数**（一次运行只是单条样本轨迹，要多次独立复现、报告均值与置信区间）。

## 7 小结

- 排队系统三要素：**到达过程、服务过程、服务设施**；用 **Kendall 记号** $A/B/c/K/N/D$ 描述。
- $M/M/1$ 的闭式指标（$L=\rho/(1-\rho)$、$W=1/(\mu-\lambda)$）是仿真的验证基准。
- **Little 定律 $L = \lambda W$** 对一切稳态排队系统成立，是仿真内部最常用的自检等式。
- 解析够不着的现实队列（$M/G/1$、有限容量、优先级、不耐烦）正是仿真的主场：**解析负责验证基准，仿真负责延伸**。
