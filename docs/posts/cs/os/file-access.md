## 为什么从文件访问方法开始

文件建好了，用户怎么读？**文件访问方法（access methods）**定义「程序如何定位和读写文件中的数据」。三类基本方法——**顺序、直接（随机）、索引顺序**——对应不同的存储介质与使用场景。选择哪种，取决于「数据是按序处理，还是任意跳转」。<span class="marginnote">回顾文件操作：`read`/`write` 推进位置、`lseek` 随机定位。访问方法就是「位置如何被推进」的更高层策略——顺序访问只用 read/write，直接访问用 lseek + read/write。</span>

## 1 顺序访问（sequential access）

**顺序访问**：按文件内容的**线性顺序**读写——从开头读，或从当前位置连续读写，**不能跳转**（或跳转很贵）。

```c
int fd = open("data.txt", O_RDONLY);
char buf[4096];
ssize_t n;
while ((n = read(fd, buf, sizeof buf)) > 0) {
    process(buf, n);          // 按序处理，无需 lseek
}
```

- 文件位置指针自动推进，`read` 一次读下一个数据块。
- **无需 seek**，实现最简。
- 典型介质：**磁带**（只能顺序读写）；也适合「从头到尾处理」的文件（日志、转录、流式处理）。
- 现代系统中，顺序访问是**顺序 I/O 优化**（预读、大块读）的受益者——顺序读性能远高于随机（回顾磁盘性能）。

**辨析｜易错点：** 「顺序访问 = 只能从头开始」是字面理解偏差。**顺序访问是「只能按序推进」，可以从任意位置开始，但之后只能连续向前。** 传统磁带必须把磁带倒回到开头才能从头读——那是介质限制；现代「顺序访问」更多指「应用不跳转地连续读」。

## 2 直接访问（direct / random access）

**直接访问**：按**任意顺序**读写文件的任意位置——跳到哪里读哪里，不需要从头扫过。

```c
// 直接跳到第 k 条记录（每条定长 rec_size 字节）读取
lseek(fd, k * rec_size, SEEK_SET);
read(fd, &rec, rec_size);
```

- 文件被当作「定长记录的数组」——按**记录号**定位。
- 相对访问：`lseek(fd, n * rec_size, SEEK_CUR)` 相对当前位置跳 n 条。
- 典型介质：**磁盘/SSD**（随机定位便宜）；数据库、索引、任何需要「任意跳转」的场景。

**直接访问是磁盘时代的主流**——因为磁盘可以随机寻道，直接访问成为可能；而数据库的 B+ 树索引、文件的随机读都依赖它。

## 3 索引顺序访问（indexed sequential access）

**索引顺序访问（indexed sequential access）**：**顺序访问 + 索引**——用索引表快速跳到目标附近的「顺序区域」，再顺序找到目标。文件的数据块按顺序组织，同时维护一个**索引**记录「关键值 → 数据块位置」。

- 要读「关键值 = K」的记录：查索引找到 K 所在的数据块，跳到该块，再**顺序搜索**。
- 兼顾「顺序处理的效率」与「随机查找的速度」。
- 典型应用：**文件索引文件（ISAM，Indexed Sequential Access Method）**——数据库早期索引方法；现代数据库的 B+ 树是它的进化版。

**公式解析：索引跳转的查找代价**

设文件有 $N$ 条记录，索引把文件分成 $B$ 个块：

$$\text{查找代价} \approx \text{查索引} + \frac{N}{B} \text{（块内顺序扫）}$$

- **查索引**：在索引里找到记录所在的块（索引小，查得快）。
- **$N/B$**：每块含 $N/B$ 条记录，块内顺序扫描的平均步数。
- **对比纯顺序访问**：最坏要扫全部 $N$ 条；**索引顺序把「全表扫」降为「索引查 + 块内扫」**——这是「索引」一切收益的来源。

**设计启示**：索引顺序访问是「**空间换时间**」的经典——用一小块索引（额外存储），把随机查找从 O(N) 降到 O(log 索引 + 块内)。你会在数据库篇的 B+ 树、文件系统索引（ext4 的索引节点）里反复见到这个思想。

## 4 核心对比表：三种访问方法

| 维度 | 顺序访问 | 直接访问 | 索引顺序访问 |
| --- | --- | --- | --- |
| 定位方式 | 线性推进 | 任意跳转 | 索引跳块 + 块内顺序 |
| 是否需要 lseek | 否 | 是 | 是 |
| 随机查找效率 | O(N) 最坏 | O(1) | O(log 索引 + 块内) |
| 顺序处理效率 | 最高 | 中 | 高 |
| 典型介质/场景 | 磁带、日志、流式 | 磁盘、数据库 | 数据库索引、ISAM |

**记忆主线**：顺序访问「从头到尾」，直接访问「随便跳」，索引顺序「跳个大概再顺着找」——三者是「速度 vs 灵活性」的光谱，索引顺序站在中间。

## 5 小结

- **顺序访问**：线性读写、位置自动推进，适合流式与顺序 I/O。
- **直接访问**：任意跳转、按记录号定位，磁盘时代的主流。
- **索引顺序访问**：索引跳块 + 块内顺序，兼得顺序效率与随机速度。
- 查找代价从「扫全表 O(N)」降到「索引 + 块内」，是「空间换时间」的经典。
- 选择依据：数据按序处理选顺序、任意跳转选直接、大文件 + 查找选索引。
