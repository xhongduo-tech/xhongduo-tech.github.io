## 为什么从 epoll 内核实现开始

上一节讲了 epoll 的 API 与复杂度优势，这一节揭开它的**内核实现**：为什么 epoll 能 O(k) 返回就绪？答案是**红黑树 + 就绪链表**的双数据结构。理解这个实现，就真正理解了「先注册、只回报变化」的机制，也理解了回调（callback）在系统设计中的威力。<span class="marginnote">回顾《epoll API》：epoll_create 建表、epoll_ctl 登记、epoll_wait 回报。内核实现对应三件事——<strong>红黑树存登记表、回调机制把就绪 fd 挂链、epoll_wait 直接取链</strong>。复杂度优势来自「回调」，不是「轮询」。</span>

## 1 epoll 的两大数据结构

**epoll 实例在内核中有两个核心结构**：

**① 红黑树（rbtree）：登记表**

- **存所有注册的 fd**（`epoll_ctl ADD` 的 fd）。
- 按 fd 排序——**查找/添加/删除 O(log n)**。
- 作用：快速判断「某个 fd 是否注册过」「要删哪个」。

**② 就绪链表（ready list）：就绪队列**

- **存「此刻就绪」的 fd**。
- 内核把就绪 fd 挂进链表，`epoll_wait` 直接取链表——**O(k) 返回就绪数**。

```
epoll 实例：
  红黑树（所有注册 fd）      就绪链表（就绪 fd）
  ┌─────────────┐        ┌─────────────┐
  │ fd 5         │        │ fd 7 → fd 3 │
  │ fd 3  fd 7   │  ←就绪→  │              │
  │ fd 9         │        └─────────────┘
  └─────────────┘        epoll_wait 取这
```

## 2 回调机制：就绪如何进链表

**核心机制：回调（callback）**。注册 fd 时，epoll 给该 fd 挂一个**回调函数**（`ep_poll_callback`）。当 fd 就绪（如 socket 有数据），**驱动/协议栈调用这个回调**：

1. fd 就绪事件发生（如网络包到达）。
2. 内核协议栈调用 epoll 注册的回调。
3. 回调把该 fd 加入**就绪链表**（如果还没在）。
4. 唤醒等待 `epoll_wait` 的进程。

**关键**：**就绪是「被推」进链表的（回调），不是「被拉」出来的（轮询扫描）**——这就是 epoll 与 select 的本质区别：

- **select**：epoll_wait 时**主动扫**所有 fd（拉）。
- **epoll**：fd 就绪时**回调挂链**（推），epoll_wait 只**取链**。

**公式解析：回调 vs 轮询的成本**

设总 fd 数 $N$、一轮中就绪 fd 数 $k$：

$$\text{轮询（select）每轮} = O(N), \qquad \text{回调（epoll）每轮} = O(1)_{\text{触发}} + O(k)_{\text{返回}}$$

- select：每轮主动扫 N 个 fd——成本与 N 成正比。
- epoll：fd 就绪时回调**主动通知**（触发成本摊销），epoll_wait 取就绪链表（O(k)）。
- **「事件驱动」的本质：用「发生时回调」代替「等待时扫描」**——成本从「总 fd」变成「就绪 fd」。

**直觉**：回调是「**事件驱动**」的核心——**不主动查，等别人来通知**。epoll 把「我有没有就绪」从「epoll_wait 时扫一遍」变成「就绪那一刻主动上报」。这就是为什么 epoll 在连接多、就绪少时碾压 select。

## 3 epoll_ctl 与 epoll_wait 的内核动作

**epoll_ctl（注册）**：

1. 在红黑树中查找 fd（O(log n)）。
2. 添加/修改/删除 fd 节点。
3. 给 fd 挂上**回调函数**（ep_poll_callback）——fd 就绪时会触发。

**epoll_wait（等待）**：

1. 检查就绪链表。
2. **非空**：把就绪 fd 拷贝给用户，返回。
3. **空**：进程睡眠（阻塞模式），直到回调把 fd 挂链并唤醒它。

**关键设计**：`epoll_wait` 的 O(k) 来自「直接取就绪链表」——**它不做任何扫描**；扫描的活由「回调挂链」分散到了「事件发生时」。

## 4 核心对比表：红黑树 vs 就绪链表

| 结构 | 存什么 | 操作复杂度 | 用途 |
| --- | --- | --- | --- |
| 红黑树 | 所有注册 fd | 增删查 O(log n) | 登记表、快速定位 |
| 就绪链表 | 就绪 fd | 取 O(k) | epoll_wait 直接取 |

**辨析｜易错点：** 「epoll 的 O(1) 是红黑树给的」是误解。**红黑树是 O(log n)——它管「登记表」的查找；O(k) 的「就绪返回」来自就绪链表 + 回调**。**两个数据结构分工不同**：红黑树管「有哪些 fd 注册了」，就绪链表管「哪些 fd 现在能用了」。**复杂度优势主要来自「回调挂链」，不是红黑树。**

## 5 小结

- epoll 内核实现 = **红黑树（登记表）+ 就绪链表（就绪队列）**。
- **回调机制**：fd 就绪时协议栈调用 epoll 回调，回调把 fd 挂进就绪链表。
- **事件驱动**：就绪是「推」进去的（回调），不是「拉」出来的（扫描）。
- epoll_wait **直接取就绪链表**——O(k)，不做任何全量扫描。
- 复杂度优势来自「**回调 + 就绪链表**」，不是红黑树（它只负责登记表 O(log n)）。
