## 为什么从索引分配开始

链接分配解决了碎片，但随机访问要沿链跳——慢。**索引分配（indexed allocation）**给出两全方案：**为每个文件维护一个索引块，里面集中存放该文件所有数据块的块号**。访问第 $i$ 块 = 查索引块第 $i$ 项——$O(1)$ 随机访问，且无碎片。这是现代文件系统（ext4、NTFS）的标准方案，也是理解 ext4「inode + 块指针」结构的前置课。<span class="marginnote">回顾 FAT：把指针集中成表，但表是全盘一张（FAT 表）。索引分配更进一步：<strong>每个文件一张「小表」</strong>（索引块），随文件存在——表跟着文件走，不再占用全局区域。这是「元数据跟对象走」的胜利。</span>

## 1 索引分配的基本思想

**索引分配（indexed allocation）**：每个文件有一个**索引块（index block）**，它是「块号数组」——`index[0]` 是逻辑块 0 的物理块号，`index[1]` 是逻辑块 1 的物理块号，依此类推。

```
索引块（文件 A 的）：
  [0]=块4  [1]=块9  [2]=块2  [3]=块7  ...
   └─逻辑块号   └─物理块号

访问逻辑块 i → 读索引块第 i 项 → 得到物理块号
```

**FCB 只需记录**：**索引块的块号**。

**优点**：

- **无外部碎片**：数据块任意散落，索引块记录位置。
- **随机访问 O(1)**：查索引块第 $i$ 项即得物理块，不需遍历。
- **文件可增长**：追加数据 = 分配新块 + 在索引块加一项。

**缺点**：

- **索引块开销**：每个文件一个索引块——小文件浪费（一个几 KB 的文件也要一个索引块）。
- **索引块大小限制**：一个索引块能装 $N$ 个块号，超过 $N$ 个块的文件装不下——需要**多级索引**。

## 2 多级索引：突破单块限制

单索引块能索引的文件大小 = 块号数 × 块大小。为了支持大文件，用**多级索引**：

- **两级索引（two-level index）**：主索引块里存的不是数据块号，而是「指向二级索引块的指针」；二级索引块里才是数据块号。
- 访问逻辑块 i：先查主索引定位二级索引块，再查二级索引得数据块——**两级查表**。

```
主索引块 → [二级索引块1][二级索引块2]...
                ↓           ↓
            数据块号列表   数据块号列表
```

**可索引大小**：设块大小为 $B$ 字节，块号 $4$ 字节，则一块能存 $B/4$ 个块号。两级索引可寻址 $(B/4)^2$ 个块——4KB 块下约 1M 块 = **4GB**（单级只能 4MB）。

**多级索引的代价**：访问大文件的块要多级查表——**级数越多，访问越慢**（每级一次磁盘读）。

## 3 组合方案：ext 文件系统的 inode

**ext 文件系统（ext2/ext3/ext4）**的 inode 采用**「直接 + 间接」组合索引**——这是对纯多级索引的务实优化：

- **12 个直接块指针**：小文件直接用（最常用，无需间接）。
- **1 个单级间接指针**：指向一个间接块（存块号数组）。
- **1 个二级间接指针**：指向两级间接块。
- **1 个三级间接指针**：指向三级间接块。

```
inode:
  [直接0][直接1]...[直接11]  → 12 个直接数据块
  [间接1级]   → 间接块 → 数据块
  [间接2级]   → 间接块 → 间接块 → 数据块
  [间接3级]   → 三层间接
```

**设计智慧**：

- **小文件直接用**（12 个直接块覆盖 12×4KB=48KB）——绝大多数文件 <48KB，访问零间接。
- **大文件逐级扩展**——按需用间接，代价只在真需要时付。

**公式解析：ext 单文件最大大小**

设块大小 $B = 4\text{KB}$，块号 4 字节，每块可存 $B/4 = 1024$ 个块号。单文件最大块数：

$$N = 12 + 1024 + 1024^2 + 1024^3$$

- **12**：直接块。
- **1024**：单级间接（1024 个块号）。
- **1024²**：二级间接（1024 个间接块 × 各 1024 块号）。
- **1024³**：三级间接。
- 总块数 ≈ $1.07 \times 10^9$ 块 ≈ **4TB**（4KB 块下）。

**直觉**：三级间接已经够用到大到夸张的文件——**组合索引用「按需增长」的层级，让小文件廉价、大文件可行**。<span class="marginnote">「直接块 + 间接块」的组合是「为最常见场景优化」的经典：绝大多数文件小于 48KB（12 个直接块就够），访问零间接、一次读 inode 即可；只有超大文件才逐级付出间接读的代价。<strong>你把预算花在最常见的情况上，罕见情况付出一点额外成本——这是工程优化的黄金法则。</strong></span>

## 4 核心对比表：三种分配方法

| 维度 | 连续 | 链接/FAT | 索引（ext） |
| --- | --- | --- | --- |
| 外部碎片 | 严重 | 无 | 无 |
| 随机访问 | O(1) | O(n) | **O(1)** |
| 文件增长 | 难 | 易 | 易 |
| 元数据 | 起始+长度 | 起始+结束（或 FAT） | 索引块指针 |
| 小文件开销 | 无 | 指针占用 | 索引块占用 |
| 现代使用 | 否 | FAT32（U 盘） | **ext4/NTFS 标准** |

## 5 小结

- **索引分配**：每文件一个索引块（块号数组），随机访问 O(1)、无碎片、易增长。
- **多级索引**：主索引指向二级索引，突破单块限制，但级数越多访问越慢。
- **ext 组合索引**：12 直接 + 单/二/三级间接，小文件零间接、大文件按需扩展。
- 单文件最大块数 $N = 12 + 1024 + 1024^2 + 1024^3$（4KB 块下约 4TB）。
- 组合索引是「为最常见场景优化」的典范，现代文件系统的标准。
