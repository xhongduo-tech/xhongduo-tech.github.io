## 为什么从多处理器调度开始

前面的算法都假设「一个 CPU，多个进程」。但现代机器早已是多核：手机有 8 核，服务器有 64 核甚至更多。多核带来两个新问题：**任务该往哪个核上放？核与核之间如何避免「一边忙死、一边闲死」？** 这就引出多处理器调度的两大主题：**负载均衡**与**处理器亲和性**。<span class="marginnote">回顾 Amdahl 定律：多核让可并行部分 $P$ 有出路，但调度器若不能让任务合理分布到各核，$P$ 也发挥不出来。多处理器调度 = 单核调度的「横向复制 + 两个新难点」。</span>

## 1 对称多处理（SMP）与非对称

**对称多处理（SMP, Symmetric Multi-Processing）**：所有处理器地位平等，**每个处理器各自运行一个调度器**，从共享的就绪队列（或各自队列）取进程。Linux 就是 SMP——每个 CPU 有自己独立的一条就绪队列。

**非对称多处理（ASMP, Asymmetric Multi-Processing）**：主处理器负责调度决策，从处理器执行。实现简单但主处理器易成瓶颈，现代系统基本不用。

SMP 下有两种队列组织：

**共享就绪队列**：所有核从一个队列取任务，天然负载均衡，但需要锁保护队列（竞争）。
**每核独立队列**：各核有自己的队列，无锁竞争，但可能出现「一核空转、一核爆满」的失衡——需要负载均衡来纠偏。

Linux 采用**每核独立队列**，因此负载均衡是刚需。<span class="marginnote">每核独立队列 + 负载均衡，正是「本地性优先、必要时迁移」的思路。这个「先就近、再平衡」的两阶段策略，在 NUMA 内存架构、分布式系统的数据放置里反复出现。</span>

## 2 负载均衡：让每核都忙

**负载均衡（load balancing）**：尽量让所有处理器的负载相近，避免某些核空闲、另一些核堆积。两种基本机制：

**推迁移（push migration）**：有专门任务定期检查各核负载，把过载核的任务**推给**空闲核。
**拉迁移（pull migration）**：空闲核主动**从**过载核的队列**拉取**任务。

两者常结合使用：Linux 的负载均衡器既会 push 也会 pull，周期性地在各核调度域（scheduling domain）之间迁移任务。

**辨析｜易错点：** 「负载均衡 = 平均分配进程数」是粗略理解。均衡的对象是**负载**而非**进程数**——一个 CPU 密集型进程抵得上十个 I/O 密集进程，按进程数平均反而失衡。好的均衡器用「每个核上排队任务的总预估运行时间」作为负载度量，而不是简单计数。

## 3 处理器亲和性：让进程赖着不走

**处理器亲和性（processor affinity）**：让进程尽量在同一个核上运行，而不是在核之间频繁迁移。

为什么要亲和？

**缓存局部性**：进程在一核上跑久了，它的数据留在该核的 L1/L2 缓存里；换核后缓存全废，得重新加载（cache miss 代价高）。
**减少迁移开销**：频繁迁移本身就是成本。

两种亲和性：

**软亲和（soft affinity）**：调度器尽量不迁移，但负载均衡时可以迁移。Linux 默认如此。
**硬亲和（hard affinity）**：进程通过系统调用（`sched_setaffinity`）强制绑定某核，调度器绝不迁移。

Linux 中 `sched_setaffinity` 即可把进程绑定到 0~3 号核——数据中心里高性能服务常用这招锁定核心。<span class="marginnote">亲和性与负载均衡是一对矛盾：<strong>亲和性要「不搬」，均衡要「搬」</strong>。Linux 的解法是折中——进程先本地跑，负载明显失衡时才迁移。大模型推理里把 GPU 绑核、把 worker 绑 NUMA 节点，都是亲和性思想的实战。</span>

## 4 核心对比表：多处理器调度的两个主题

| 维度 | 负载均衡 | 处理器亲和性 |
| --- | --- | --- |
| 目标 | 各核负载相近 | 进程留在一个核上 |
| 手段 | push/pull 迁移 | 优先本地队列、绑定 |
| 收益 | 吞吐最大化、无空转核 | 缓存局部性、少迁移开销 |
| 代价 | 迁移开销、缓存失效 | 可能造成负载不均 |
| 冲突 | 要「搬」 | 要「不搬」 |

**设计启示**：负载均衡与亲和性天然矛盾——搬多了毁缓存，不搬则失衡。现代调度器（Linux CFS）的策略是：**优先保证亲和（缓存为王），只在负载差距显著时迁移（公平兜底）**。这个「本地优先、全局兜底」的哲学贯穿分布式系统一切资源调度。

## 5 小结

- **SMP**：每核一个调度器，Linux 采用**每核独立队列** + 负载均衡。
- **负载均衡**：push（推）与 pull（拉）两种迁移机制，均衡的是「负载」而非「进程数」。
- **处理器亲和性**：让进程留在同一核，保住缓存局部性；分软亲和与硬亲和（`sched_setaffinity`）。
- 均衡与亲和的矛盾由「本地优先、失衡才迁」化解。
- 多处理器调度 = 单核调度 × 多核 + 均衡与亲和两个新约束。
