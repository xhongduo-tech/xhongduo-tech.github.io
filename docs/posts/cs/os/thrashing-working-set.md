## 为什么从抖动开始

置换算法解决「换哪页」，但还有个更根本的问题：**每个进程分到多少页框？** 分少了，进程频繁缺页；分多了，其他进程缺页。最坏的情况下，系统陷入**抖动（thrashing）**——进程不停缺页、不停换页、CPU 几乎不干活。理解抖动与**工作集模型**，是虚拟内存从「单进程优化」走向「全系统平衡」的关键。<span class="marginnote">回顾《缺页率与 EAT》：缺页率 $p$ 决定性能。抖动就是 $p$ 逼近 1 的灾难态——系统把全部时间花在磁盘 I/O 上。工作集模型回答「每个进程该分多少页才不抖动」。</span>

## 1 页框分配策略

**页框分配（frame allocation）**：决定每个进程分配多少个页框。两种基本策略：

- **固定分配（fixed allocation）**：每个进程分到固定数量的页框（等分或按进程大小比例）。简单，但进程的页框需求随运行阶段变化，固定分配可能「旱的旱死、涝的涝死」。
- **可变分配（variable allocation）**：根据进程的缺页情况动态增减页框。灵活，但管理复杂（全局调度页框）。

**分配范围**：每个进程至少要有**足够**的页框支撑其工作集；太少的页框必然导致高缺页率甚至抖动。最少页框数的下限取决于**单条指令最多能访问的页数**（如 x86 块移动指令）——指令需要的所有页必须同时在内存。

**页框分配与置换的关系**：

- **局部置换（local replacement）**：进程缺页时只能换**自己**的页。一个进程的缺页不影响别人，但可能因自己的页框不够而抖动。
- **全局置换（global replacement）**：进程缺页时可换**任意**进程的页。页框利用率高，但一个进程可能抢走别人的页，引发级联缺页。

## 2 抖动：系统的「死亡之舞」

**抖动（thrashing）**：进程频繁缺页、系统忙于页换入换出、CPU 利用率极低的现象。

**抖动的恶性循环**：

1. 内存中进程太多，每个进程分到的页框不足。
2. 页框不足 → 缺页率飙升 → 频繁换页。
3. 频繁换页 → 磁盘 I/O 占用大量时间 → CPU 利用率下降。
4. 调度器看到 CPU 利用率低 → **加载更多进程** → 每个进程页框更少 → 缺页更频繁。

**最终状态**：系统把几乎全部时间花在「把页从磁盘搬进搬出」上，CPU 几乎闲置，却没有任何进程能顺利推进——**死循环式的搬运狂欢**。

**关键洞察**：抖动的根源不是「缺页」，而是**进程的页框数少于其工作集**。调度器「看 CPU 利用率低就加进程」的策略在虚拟内存下会适得其反——**必须用工作集模型来约束多道程度**。<span class="marginnote">抖动的教训是「单看一个指标会骗人」：CPU 利用率低，传统调度以为「资源没喂饱」，在虚拟内存下其实是「喂过头了」。<strong>多道程序的度必须受「内存能否装下所有进程的工作集」约束</strong>——这是工作集模型取代 CPU 利用率作为负载依据的原因。</span>

## 3 工作集模型：给每个进程画「热区」

**工作集（working set）**：进程在**最近 Δ 个时间单位**内访问过的页的集合，记为 $WS(t, \Delta)$。

- $\Delta$ 是**窗口（window）**——回顾时间窗长度。
- 工作集大小 **WSS**：窗口内不同页的数量。

**工作集模型（working-set model）**：每个进程分配 **WSS 个页框**（加上少量余量），使它的工作集能完全驻留内存——这样缺页率低，不抖动。

**工作集如何估计**：用引用位 + 定时扫描。每隔固定时间（如每 1000 次访问）：

- 检查每个页的引用位，记录「窗口内是否被访问过」。
- 引用位 = 1 的页属于当前工作集；引用位 = 0 的页已离开工作集，可回收。
- 清引用位，开始下一窗口。

**公式解析：多道程序的度**

设系统内存总量为 $M$，每个进程工作集大小为 $WSS_i$，则工作集模型要求：

$$\sum_i WSS_i \le M$$

- **$WSS_i$**：进程 $i$ 的工作集大小。
- **$M$**：物理内存总量。
- 条件不满足时：**减少多道程序的度**（把某些进程换出内存，让出页框），而不是继续加进程。

**直觉**：内存就像酒店的床，每个进程的工作集是「它需要同时躺下的床位数」。所有进程需要的床位总和 ≤ 总床位数，大家才都睡得好；超了，就有人睡地板（抖动）——所以要么劝退客人（换出进程），要么别接新客（不加进程）。

## 4 预防与缓解抖动

- **工作集模型**：监控每个进程的工作集，页框不足时换出部分进程——**从根上防止过度多道**。
- **缺页率控制（page-fault frequency, PFF）**：监控每个进程的缺页率——缺页率过高则增加页框，过低则减少页框（可变分配）。
- **系统级**：总缺页率过高时，暂停加载新进程。

**辨析｜易错点：** 「抖动是内存不足的表现，加内存就能解决」——加内存只是缓解，不治本。**抖动的直接原因是「多道程度超过内存容量」，即使总内存够，若调度器不看工作集、疯狂加进程，依然抖动。** 治本之策是**用工作集约束多道度**，而不是单纯加大内存。

## 5 小结

- **页框分配**：固定分配 vs 可变分配；局部置换 vs 全局置换。
- **抖动**：页框不足 → 缺页飙升 → CPU 闲置 → 调度器加进程 → 更缺页，死循环。
- **工作集** $WS(t,\Delta)$：最近 Δ 时间访问过的页集合；**WSS** 是其大小。
- **工作集模型**：$\sum WSS_i \le M$——多道程度受工作集总和约束。
- 防抖手段：**工作集模型 / 缺页率控制**，从根上限制多道程度。
