## 为什么从文件操作开始

认识文件是静态的，操作文件才是动态的。文件系统的用户接口由**文件操作**构成——创建、打开、读、写、定位、截断、关闭、删除。这一节把它们逐个讲透，重点理解 **open 与文件描述符（file descriptor）** 这个贯穿一切文件操作的核心概念。<span class="marginnote">回顾《系统调用的类型与实现原理》：文件管理是系统调用五大家族之一。`open` 正是那个家族的成员——每个文件操作背后都是一次系统调用、一次用户态→内核态的往返。</span>

## 1 文件操作全集

文件系统支持的最基本操作：

| 操作 | 功能 | Linux 调用 |
| --- | --- | --- |
| 创建（create） | 建立新文件 | `open(path, O_CREAT, mode)` |
| 打开（open） | 访问前打开，建立文件描述符 | `open(path, flags)` |
| 读（read） | 从文件读取数据 | `read(fd, buf, count)` |
| 写（write） | 向文件写入数据 | `write(fd, buf, count)` |
| 定位（seek） | 移动文件读写位置 | `lseek(fd, offset, whence)` |
| 截断（truncate） | 删除文件部分内容（通常是尾部） | `truncate(path, length)` |
| 关闭（close） | 结束访问，释放描述符 | `close(fd)` |
| 删除（delete） | 从文件系统移除文件 | `unlink(path)` |

**创建 vs 打开**：创建建立「新文件」这个实体；打开是「开始访问已有文件」。现代 Unix 用 `open` 一个调用同时表达两者（加 `O_CREAT` 标志）。

## 2 open 与文件描述符：一切操作的前提

**文件描述符（file descriptor, fd）**：进程打开文件后获得的**整数句柄**——后续所有读写都通过它引用文件。它是「文件」在进程内的化身。

**open 返回一个 fd**：

```c
int fd = open("data.txt", O_RDWR | O_CREAT, 0644);
if (fd < 0) { perror("open"); exit(1); }

/* 后续所有读写都用 fd，不再查文件名 */
write(fd, "hello", 5);

close(fd);
```

**为什么需要 fd，不直接用文件名**：

- **效率**：文件名查找（遍历目录）很贵，只在 open 时做一次；之后用 fd 直接定位。
- **状态封装**：fd 背后是内核的**打开文件表项（open file description）**，记录当前读写位置、访问模式、引用计数等状态。
- **统一接口**：fd 不只对应文件，还对应管道、套接字、设备——「一切皆文件」的物理落点。

**fd 表**：每个进程一张 **fd 表**（file descriptor table），fd 是它的下标。`0`（`STDIN_FILENO`）标准输入、`1`（`STDOUT_FILENO`）标准输出、`2`（`STDERR_FILENO`）标准错误是三个默认 fd。

**辨析｜易错点：** 「fd = 文件」是误解。**fd 是「对文件的一次打开」的句柄**——同一文件被打开两次得到两个不同的 fd，各自有自己的读写位置（若不用共享）；fd 还对应管道/套接字（根本不是磁盘文件）。**fd 是「打开文件」这个动作的编号，不是「文件」的编号。**

## 3 读写与位置指针

**顺序访问**：文件有一个隐式的**当前读写位置（file offset）**，`read`/`write` 自动从当前位置开始并推进它。

```c
/* 顺序读：每次从当前位置开始，读后位置自动推进 */
char buf[128];
read(fd, buf, sizeof buf);   /* 读位置 0 处的数据 */
read(fd, buf, sizeof buf);   /* 继续从上次结束处读 */
```

**随机访问**：用 `lseek` 移动位置，然后读写。

```c
/* 随机访问：先定位再读写 */
off_t off = lseek(fd, 4096, SEEK_SET);  /* 把读写位置移到偏移 4096 */
read(fd, buf, sizeof buf);              /* 从 4096 处开始读 */
```

**读写模式**（open 时指定）：`O_RDONLY`（只读）、`O_WRONLY`（只写）、`O_RDWR`（读写）。

两个高频标志值得单独记：**`O_TRUNC`**——打开时把文件截断为 0（常用于日志轮换前的清空）；**`O_APPEND`**——每次 `write` 前先把位置移到文件末尾，保证多进程追加互不覆盖。<span class="marginnote">`O_APPEND` 与「先 `lseek` 到末尾再 `write`」不同：后者不是原子的，两个进程可能写串；前者由内核在每次 write 时原子地定位到末尾。日志系统（如系统 journal、RDBMS 的 WAL）都依赖 O_APPEND 的原子追加语义。</span>这两个标志把一个「打开」动作变成「清空文件」或「安全追加」的惯用法。

**截断（truncate）**：把文件缩短到指定长度——常用于「清空文件」或「删除尾部数据」。`ftruncate(fd, 0)` 把文件清空为 0 字节。

**关闭（close）**：释放 fd。资源有限——**fd 泄漏**（不 close）会耗尽进程可用 fd 数，是长驻服务常见的资源泄漏。

## 4 文件操作的共享语义：两个进程同时写

文件操作要回答：**两个进程打开同一文件，各自怎么访问？** 内核用两个层次：

- **每进程 fd 表**：每进程私有——每个 fd 独立。
- **打开文件表（共享）**：多个 fd 可以指向**同一个打开文件表项**（如 `dup`、`fork` 继承）——此时它们**共享读写位置**。

**共享打开文件表项的后果**：父子进程共享位置指针——父进程读了 100 字节，子进程接着从 100 处读（不是从 0）。这是 `fork` 后父子读写同一文件时的经典陷阱。

**辨析｜易错点：** 「两个 open 同一文件 = 共享位置」——**不共享**！两个独立的 `open` 产生两个独立的打开文件表项，各有各的位置指针。**只有通过 `dup`/`fork` 共享同一打开文件表项的 fd 才共享位置。** 这个区分是并发文件访问正确性的关键。

## 5 数值算例：读写位置指针的算术

设文件内容是 8 字节的 `ABCDEFGH`，`fd` 刚打开时位置指针为 0。跟着三次调用走一遍：

| 调用 | 之前位置 | 动作 | 之后位置 | 读到的数据 |
| --- | --- | --- | --- | --- |
| `read(fd, buf, 3)` | 0 | 读 3 字节 | 3 | `ABC` |
| `lseek(fd, 2, SEEK_SET)` | 3 | 位置设为 2 | 2 | — |
| `read(fd, buf, 3)` | 2 | 读 3 字节 | 5 | `CDE` |

位置指针就是「下一次读写从哪里开始」的游标：`read`/`write` 会推进它，`lseek` 直接改它。<span class="marginnote">`SEEK_SET`（从文件头算）、`SEEK_CUR`（从当前位置算）、`SEEK_END`（从文件尾算）三个 whence 的含义必须分清楚——面试常问「`lseek(fd, 0, SEEK_END)` 返回什么」，答案是「文件长度」，因为位置被移到末尾。这也是实现 `wc -c` 的原理。</span>

**截断的算术**：`ftruncate(fd, 4096)` 把文件裁到 4096 字节——原长 10000 字节时，尾部 5904 字节被丢弃；原长 100 字节时，**反而把文件扩展到 4096 字节，中间空洞补零**。截断不是只能删、也可能加长，这个反直觉点容易踩坑。

## 6 术语速查表

| 术语 | 含义 | 一句话记忆 |
| --- | --- | --- |
| fd | 打开文件的整数句柄 | 打开动作的编号 |
| 打开文件表项 | 内核记录打开状态的结构 | 含位置、模式、计数 |
| `O_CREAT` | 不存在则创建 | 一调用两用 |
| `O_TRUNC` | 打开即清空 | 打开=清空 |
| `O_APPEND` | 写前原子移到末尾 | 追加不打架 |
| `lseek` | 移动位置指针 | 改变下一次读写点 |
| `ftruncate` | 缩短（或加长）文件 | 截断到指定长度 |

## 7 小结

- 文件操作八件套：**创建、打开、读、写、定位、截断、关闭、删除**。
- **文件描述符 fd** 是打开文件的句柄，背后是**打开文件表项**（含位置、模式、计数）。
- `read`/`write` 自动推进位置；`lseek` 随机访问；`truncate` 缩短文件。
- **fd 是「打开动作」的编号，不是「文件」的编号**；fd 泄漏是资源泄漏。
- 共享打开文件表项（`dup`/`fork`）才共享位置指针，独立 open 不共享。
