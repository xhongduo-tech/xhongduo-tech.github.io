## 为什么从内核 I/O 子系统开始

前几节把 I/O 的部件逐个讲完——现在把它们**组装**起来。**内核 I/O 子系统（kernel I/O subsystem）**是内核中所有 I/O 机制的统合层：调度、缓冲、缓存、错误处理、保护。它是《I/O 软件层次》中「设备无关层」的全部职责的落地。这一节做第十三篇的「总装与收尾」，并总结 I/O 性能优化的方法论。<span class="marginnote">回顾《I/O 软件层次》：设备无关层做「共性」。内核 I/O 子系统就是这一层的实体——它服务所有设备，是 I/O 系统的心脏。这一节把前几节的调度、缓冲、缓存、SPOOLing 串成一条主线。</span>

## 1 I/O 子系统的五大机制

**内核 I/O 子系统**整合五个核心机制：

**① I/O 调度**：把多个 I/O 请求**重排与合并**，优化设备利用率。

**磁盘调度**：SCAN/LOOK 等（回顾第十篇）——减少寻道。
**请求合并**：相邻块的小请求合并成大请求——减少 I/O 次数。
**排队与优先级**：按设备繁忙程度排队，平衡公平与效率。

**② 缓冲（buffering）**：平滑速率差、攒批（回顾《缓冲技术》）。

**③ 缓存（caching）**：页缓存留热点数据，减少重复 I/O（回顾《文件系统性能优化》）。

**④ 错误处理**：把设备错误翻译成统一错误码，向应用报告。

瞬时错误（传输重试）自动重试；持久错误（介质损坏）报告 `EIO`。

**⑤ 保护与访问控制**：I/O 设备不能被任意进程访问——设备权限、`/dev` 设备文件的权限控制。

**辨析｜易错点：** 「I/O 子系统 = 一堆驱动的集合」是误解。**驱动只是 I/O 子系统的一部分**——真正的「子系统」是驱动之上的通用机制层（调度、缓冲、缓存、错误处理）。**驱动做「个性」，子系统做「共性」**，两者配合。

## 2 I/O 调度：请求重排的艺术

**I/O 调度（I/O scheduling）**是 I/O 子系统的性能核心：

**重排（reordering）**：把请求按「更优顺序」排列——磁盘按磁道顺序（SCAN）、SSD 按合并机会。
**合并（coalescing/merging）**：把相邻块请求合并——一次大 I/O 替代多次小 I/O。

**Linux 的 I/O 调度器**（block layer）：

**Noop**：几乎不重排（适合 SSD——无寻道，合并即可）。
**Deadline**：按截止时间保证公平与延迟，适合交互系统。
**CFQ（已退役）**：按进程公平排队。
**BFQ / MQ-Deadline / none**：现代多队列调度器。

**设计启示**：I/O 调度与 CPU 调度、磁盘调度同源——都是「**用重排换效率**」。区别在优化目标：CPU 调度优化等待时间，I/O 调度优化设备利用率（寻道最少、合并最多）。<span class="marginnote">回顾第十篇磁盘调度：SCAN 家族是 I/O 调度的子集。现代 Linux 的 I/O 调度在「block layer」统一做重排与合并，再交给驱动——<strong>「调度」从「磁盘专属」泛化为「块设备通用」</strong>，SSD 上也照样合并请求。</span>

## 3 公式解析：I/O 调度的吞吐收益

设 $N$ 个相邻块的小请求（各 $S$ 字节），合并成一个大请求：

$$\text{I/O 次数} = N \quad \rightarrow \quad 1$$

$$\text{吞吐提升} \approx \frac{N \times (T_{seek} + T_{rot} + \frac{S}{R})}{T_{seek} + T_{rot} + \frac{N \cdot S}{R}}$$

- **$T_{seek} + T_{rot}$**：每次 I/O 的寻道 + 旋转（毫秒级大头）。
- **$\frac{S}{R}$**：小请求的传输时间。
- 合并后：一次寻道 + 一次旋转 + 一次大传输——**省掉了 $(N-1)$ 次的寻道与旋转**。

**直觉**：合并把「N 次随机访问」变成「1 次顺序访问」——**N 越大，省掉的寻道越多，吞吐提升越大**。这正是「顺序化」优化的量化表达。

## 4 I/O 性能优化的完整工具箱

**I/O 性能优化**三板斧 + 更多：

| 手段 | 原理 | 对应机制 |
| --- | --- | --- |
| 减少 I/O 次数 | 合并、缓冲、缓存 | I/O 调度、页缓存 |
| 顺序化 | 把随机变顺序 | 调度重排、预读 |
| 异步化 | 不阻塞等待 | 中断、DMA、SPOOLing |
| 零拷贝 | 减少数据拷贝 | mmap、sendfile |
| 并行化 | 多设备/多队列 | 多块盘 RAID、多队列 |

**关键认识**：所有优化都指向同一目标——**「让慢速设备的访问次数最少、每次访问最大、等待不阻塞 CPU」**。

## 5 核心对比表：I/O 子系统的机制与目标

| 机制 | 目标 | 关键思想 |
| --- | --- | --- |
| I/O 调度 | 重排 + 合并，减少寻道 | 顺序化 |
| 缓冲 | 攒批、平滑速率 | 批量 I/O |
| 缓存 | 热点留内存 | 局部性 |
| 错误处理 | 统一错误报告 | 错误翻译 |
| 保护 | 设备访问控制 | 权限 |

## 6 小结

- **内核 I/O 子系统** = 调度 + 缓冲 + 缓存 + 错误处理 + 保护——驱动之上的通用机制层。
- **I/O 调度**：重排（顺序化）+ 合并（相邻块合成大 I/O），是性能核心。
- 合并把 N 次随机访问变 1 次顺序访问，吞吐提升巨大。
- 优化工具箱：**减少次数、顺序化、异步化、零拷贝、并行化**。
- 驱动的「个性」与子系统的「共性」配合，构成完整 I/O 系统。
