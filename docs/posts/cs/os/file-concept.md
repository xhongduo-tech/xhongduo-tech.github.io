## 为什么从文件概念开始

操作系统管理资源，而**文件是「信息资源的容器」**——程序、文档、数据库、设备，统统以文件形式存在。文件系统（file system）是操作系统对持久存储的抽象：**把磁盘上的杂乱扇区，组织成用户友好的「文件」**。这一节从用户视角认识文件：它有哪些属性、哪些类型、内部结构长什么样。这是整个文件系统篇的起点。<span class="marginnote">回顾磁盘结构：磁盘的最小单位是扇区（512B/4KB）。文件系统的工作就是「把扇区组织成文件，把文件组织成目录，把目录呈现给用户」——文件是这一切的用户可见入口。Unix 里「一切皆文件」，连设备、管道都是文件。</span>

## 1 什么是文件

**文件（file）**：存储在持久介质上的、有名字的数据集合。它是操作系统的**信息存储单元**——程序员通过文件名读写数据，不必关心数据在磁盘哪个扇区。

**文件的本质**：文件系统把「物理扇区」抽象成「逻辑字节流」，向用户提供统一、方便、持久的数据存取接口。

**为什么需要文件抽象**：

- **持久性**：进程结束、机器重启，数据还在（磁盘持久）。
- **统一接口**：程序、文档、设备都用同一套 open/read/write 操作。
- **命名与组织**：文件名 + 目录，让海量数据可检索。

## 2 文件属性

文件系统为每个文件维护一组**属性（attributes）**：

| 属性 | 含义 |
| --- | --- |
| 名称（name） | 文件唯一的名字 |
| 标识符（identifier） | 文件系统内部唯一 ID（如 inode 号） |
| 类型（type） | 普通文件、目录、设备等 |
| 位置（location） | 指向文件数据的物理位置（指针） |
| 大小（size） | 当前字节数 |
| 保护（protection） | 谁可读/写/执行（权限） |
| 时间戳（time） | 创建、最后修改、最后访问时间 |

**辨析｜易错点：** 「文件名 = 文件标识」是常见误解。**文件名是给用户看的，标识符（inode 号）是给系统用的**——两个不同的文件名（硬链接）可以指向同一个标识符，即同一份数据。文件名改了就找不到原名字，但文件本身（标识符）没变。Unix 里 `ls -i` 可看到每个文件的 inode 号。

## 3 文件类型与结构

**文件类型（file type）**：按内容/用途分类。

- **普通文件（regular）**：数据文件（文本、二进制、可执行）。
- **目录（directory）**：存放文件名的索引结构（也是文件）。
- **特殊文件（special）**：Unix 中设备、管道、套接字都以文件形式出现——「一切皆文件」。
- 可执行文件（`a.out`/`.exe`）有固定内部结构（如 ELF 格式，见 Linux 篇《ELF 格式解析》）。

**文件结构（file structure）**：文件内部如何组织数据。

- **无结构（字节流）**：Unix 把文件当作**无结构的字节序列**——不做任何解释，结构由应用程序自己定义。这是最灵活的设计。
- **记录序列（records）**：把文件看作记录的集合，每条记录有固定结构（早期大型机）。
- **树形结构**：如文档的章节结构。

**Unix 的选择（字节流）**是极简主义：**文件系统不知道也不关心文件内部是什么**——文本、图片、程序都只是字节流。好处是通用（任何程序都能读任何文件），坏处是「结构」完全由应用负责。

**辨析｜易错点：** 「文件的扩展名决定文件类型」——**扩展名（`.txt`、`.jpg`）只是命名约定，文件系统一般不强制**。Unix 里 `myfile.jpg` 里存文本也能执行（如果权限允许）；文件「是什么」由**内容**与**应用**决定，不是扩展名。**扩展名是给人和工具看的，不是文件系统的硬性约束。**

## 4 核心对比表：文件系统对「结构」的两种态度

| 维度 | 无结构字节流（Unix） | 记录/结构文件 |
| --- | --- | --- |
| 文件系统解释内容 | 不解释 | 解释成记录/结构 |
| 灵活性 | 最高（应用自定结构） | 低（结构由系统定） |
| 通用性 | 高（任何程序可读） | 低（结构不匹配则乱） |
| 典型 | Linux/Unix | 早期大型机、部分数据库文件 |

**设计启示**：Unix「无结构文件」是「**内核极简、用户自由**」哲学的体现——内核只管「字节流的存取」，不管「字节流的含义」。这个选择让 Unix 文件系统极其简单、通用，也让「结构」问题下沉到应用层（文本格式、二进制格式由各程序定义）。对比：数据库把自己的文件做成有结构记录，是应用层的主动选择，不是文件系统的要求。

## 5 小结

- **文件**：持久介质上有名字的数据集合，把扇区抽象成字节流。
- 属性包括**名称、标识符、类型、位置、大小、保护、时间戳**。
- **文件名 ≠ 标识符**：硬链接下多个名字指向同一份数据。
- 类型分普通/目录/特殊；Unix 文件是**无结构字节流**，「一切皆文件」。
- 扩展名只是约定，文件「是什么」由内容与应用决定。
