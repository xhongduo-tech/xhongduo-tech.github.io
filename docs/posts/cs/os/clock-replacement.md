## 为什么从时钟算法开始

LRU 很准，但精确实现需要硬件时间戳或每次访问都移动链表——太贵。真实系统需要「够准、够便宜」的置换。**时钟算法（clock / 第二次机会）**用每个页一个**引用位（reference bit）**，配合一个循环指针，以近乎 FIFO 的成本实现接近 LRU 的效果。它是现代操作系统（包括 Linux）页面置换的默认选择。<span class="marginnote">回顾 LRU 的实现负担：每次访问都要更新记录。时钟算法的折中：硬件只需在<strong>每次访问时置一个引用位</strong>（几乎零成本），置换时再扫位做决策——把「昂贵的排序」换成「廉价的置位」。</span>

## 1 引用位与第二次机会算法

**引用位（reference bit）**：每个页表项（或页框）配一位，进程访问该页时**硬件自动置 1**。成本：每次访存只需置一个位，几乎免费。

**第二次机会（second-chance）算法**：FIFO + 引用位。

页按 FIFO 排队，但换出前先看它的引用位：
引用位 = 1：说明最近被用过——**给第二次机会**：清引用位、把页移到队尾（当新页），不换它。
引用位 = 0：说明一直没用过——换出它。

**直觉**：被用过的页「缓刑」一次，移到队尾重新排队；只有「老 + 没用过」的页才被换。这比纯 FIFO 聪明，因为它考虑了「最近是否被用」。

## 2 时钟算法：第二次机会的环形实现

**时钟算法（clock algorithm）**：把页组织成**环形**（像钟面），一个指针（时针）循环移动：

```
while (true) {
    if (page_table[hand].ref_bit == 1) {
        page_table[hand].ref_bit = 0;   // 最近用过，清位并跳过
        hand = (hand + 1) % n;          // 指针前移
    } else {
        victim = hand;                  // 自上次检查以来未用过 → 换出
        hand = (hand + 1) % n;
        break;
    }
}
```

**置换过程**：

1. 指针指向一个页，检查其引用位：
**位 = 1**：说明最近用过 → 清位为 0，**指针前移**，继续检查下一页（不给这次机会，但页继续留在内存）。
**位 = 0**：说明自上次检查以来没用过 → **换出这页**，调入新页（新页引用位置 1），指针前移。

**关键性质**：一轮检查中，引用位为 1 的页被清为 0 并跳过——它们获得「再活一圈」的机会；指针走一圈后，所有「其实没被用」的页都被清 0，最终被换出。**时钟算法 = 第二次机会的环形实现，O(1) 每步，开销接近 FIFO。**<span class="marginnote">时钟指针转一圈的成本是可接受的：多数页的引用位为 0（局部性下很少的页被反复访问），指针很快找到可换页。而「被频繁访问的页」每次都把引用位置 1、被清 0 后下一圈又置 1，<strong>永远活指针的刀下</strong>——这与 LRU 的直觉一致：热页永不换出。</span>

### 一次时钟置换的走查

设 4 个页框，页 A、B、C、D 各占一个，引用位分别为 1、0、1、0，指针停在页 A：

- 检查 A（位 1）→ 清 0，指针到 B。
- 检查 B（位 0）→ 换出 B，调入新页 E（引用位置 1），指针到 C。

**看效果**：B 和 D 虽然都在内存里，但 B 自上次指针扫过以来没用过（位 0），D 也是——**指针最先遇到谁，谁先被换**，带有一定的「任意性」。而 A、C 因最近用过获得续命。**这就是「近似 LRU」：不精确，但「最近用过的多活一圈」的方向正确**。

**数值直觉：时钟在多大窗口内近似 LRU**。设页框 100 个，一次置换最多转一圈（100 次检查）。若某页在最近约 100 次访问内被用过，它的引用位大概率还是 1——**时钟相当于给「最近 N 次访问内被用过」的页续命，N = 页框数**。<span class="marginnote">页框越多，这个「近因窗口」越大，时钟与 LRU 的命中率越接近；负载的局部性越强，两者差距越小。这也是时钟在真实工作负载下表现稳健的原因。</span>这与 LRU 的「最近使用」在时间窗口上对齐，只是分辨率粗糙——1 位 vs 精确时间戳。

## 3 改进型时钟算法：考虑「脏页」

基本时钟只看引用位，但现实里页还有「脏页」问题：**被写过（脏）的页换出时要写回磁盘，干净页直接丢弃**——写回是额外 I/O。**改进型时钟算法**用**引用位 + 脏位**两个位，把页分成四类：

| 类别 | 引用位 | 脏位 | 含义 | 换出代价 |
| --- | --- | --- | --- | --- |
| 0 | 0 | 0 | 没用过、不脏 | 最低（直接丢） |
| 1 | 0 | 1 | 没用过、但脏 | 中（写回） |
| 2 | 1 | 0 | 用过、不脏 | 较高（先清位观察） |
| 3 | 1 | 1 | 用过、且脏 | 最高（写回+换出） |

**置换策略（多轮扫描，逐类升级）**：

- **第一轮**：找「00」页（最理想，无写回）——找到即换。
- **第二轮**：找「01」页（要写回，但接受）。
- **第三轮**：找「10」页（清引用位后重扫）。
- **第四轮**：找「11」页（兜底，一定能找到）。

**改进的意义**：优先换出「干净页」，避免不必要的写回 I/O——**把「换出成本」也纳入置换决策**，这是对基本时钟的重要优化。Linux 的页面回收（`kswapd`/`shrink_page_list`）就按「干净优先」思路选择回收对象。

**辨析｜易错点：** 「时钟算法 = 近似 LRU」需要正确理解。**时钟只近似「LRU 的粗粒度版本」**——它的粒度是「有没有被用过」（1 位），而 LRU 是「精确的最后使用时间」。引用位 0/1 只区分「用过/没用过」，不区分「多久前用过」。**时钟是「低分辨率 LRU」**，精度够用、成本极低，这才是它成为工业标准的原因。

### 时钟算法的取舍：为什么它是工业默认

对比几种方案的「精度 vs 成本」：

| 方案 | 每次访问开销 | 置换决策成本 | 精度 |
| --- | --- | --- | --- |
| 精确 LRU | 高（时间戳/移链表） | 高 | 高 |
| 时钟（引用位） | 极低（置位） | 低（扫指针） | 中 |
| FIFO | 零 | 最低 | 低 |

**结论**：时钟的每次访问开销几乎为零（硬件置位），置换时指针扫一圈也便宜；精度虽不达 LRU，但在局部性负载下命中率与 LRU 差距很小。**「够准 + 极便宜」让时钟成为现代操作系统的页面置换默认**——Linux 的近似 LRU 置换（`lru_gen`、`clock`）都是它的演进。

## 4 核心对比表：置换算法全谱系

| 算法 | 依据 | 每次访问开销 | 精度 | 是否栈式 |
| --- | --- | --- | --- | --- |
| OPT | 未来 | 不可实现 | 最优 | 是 |
| LRU | 精确使用时间 | 高 | 高 | 是 |
| 时钟/第二次机会 | 引用位（0/1） | 低（置位） | 中 | 近似 |
| FIFO | 调入时间 | 最低 | 低 | 否 |

## 5 小结

- **引用位**：硬件每次访问自动置 1，几乎零成本——近似 LRU 的基础。
- **第二次机会**：FIFO + 引用位，被用过的页缓刑移队尾。
- **时钟算法**：环形指针 + 引用位，位 1 清位跳过、位 0 换出，O(1) 每步。
- **改进型时钟**：引用位 + 脏位四类（00/01/10/11），优先换干净页，减少写回 I/O。
- 时钟是「低分辨率 LRU」：精度够用、成本接近 FIFO，是工业默认。
