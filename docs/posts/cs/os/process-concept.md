## 为什么从进程开始

从这篇开始，我们进入操作系统的绝对核心。操作系统管理的资源千千万，但一切工作的主角只有一个——**进程（process）**。调度器调度的是进程，内存管理服务的是进程，文件系统为进程读写数据，进程间通信让进程协作。前面六篇是「操作系统这台机器的骨架」，进程则是「这台机器上真正活着的东西」。<span class="marginnote">回顾《用户态与内核态》：模式位区分的是「谁在运行」；而「谁在运行」这个主体，正是进程。进程是双模式设计真正服务的对象。</span>

「进程 vs 程序」是第一道必过的大关，因为它几乎是一切的起点。

## 1 程序与进程：一个静态，一个动态

**程序（program）**：存储在磁盘上的一组指令与数据的静态集合——一个可执行文件，PE、ELF 可执行文件都是程序。它不占用 CPU，不占用内存，只是「躺在那里的一段代码」。

**进程（process）**：程序的一次执行过程，是一个**正在运行**的实体。它有自己的地址空间、寄存器状态、打开的文件、执行进度。

用一句话区分：**程序是菜谱，进程是照着菜谱正在做的那顿饭**。同一个菜谱可以做很多次饭（一个程序可以起多个进程）；每次做饭的火候、时间、佐料用量都不同（每个进程的执行轨迹都不同）。

| 维度 | 程序 | 进程 |
| --- | --- | --- |
| 存在形态 | 静态，磁盘上的文件 | 动态，内存中的执行 |
| 时间性 | 无生命周期，可永久存放 | 有创建、运行、消亡 |
| 资源 | 只占磁盘空间 | 占用 CPU、内存、I/O 设备 |
| 数量关系 | 一个程序 | 可对应多个进程 |
| 是否在调度 | 从不被调度 | 被调度器调度 |

## 2 进程的组成：程序 + 数据 + 栈 + 控制块

一个进程在内存中由四个部分组成：

1. **程序段（text）**：可执行代码。多个进程可以共享同一份程序段（如多个终端跑同一个 `bash`）。
2. **数据段（data）**：全局变量与静态变量。
3. **堆栈段**：运行时栈（函数调用、局部变量）与堆（动态分配的内存）。
4. **进程控制块（PCB）**：记录进程全部状态的数据结构——下一篇专门讲。

这四个部分里，前三个是「程序的影像」，第四个是「操作系统的账本」。**操作系统眼里，进程约等于它的 PCB**：只要 PCB 在，进程就在。<span class="marginnote">「进程 = 资源（地址空间、文件、信号）+ 执行（CPU 上下文）」。这个两分法会反复出现：上下文切换换的是执行部分，资源部分则常被复用（如线程共享地址空间）。</span>

## 3 程序如何变成进程

从程序到进程要经历一次「被加载执行」的过程。以 Linux 为例：

1. 用户输入命令，shell 调用 `fork()` 创建新进程。
2. 新进程调用 `exec()`，把磁盘上的可执行文件读入内存，替换自身的地址空间。
3. 内核为新进程分配进程控制块、建立地址空间映射、打开标准输入输出。
4. 进程从入口点开始执行，从此「活」了起来。

**辨析｜易错点：** 「进程 = 运行中的程序」这个说法太粗略。两个进程可以运行**同一个**程序（比如两个浏览器标签页共用 Chrome 程序）；一个进程也可以先后执行**不同**的程序（shell 先 `fork` 再 `exec` 另一个程序）。**进程与程序是多对多的关系，不是一一对应。**<span class="marginnote">浏览器用多进程模型管理标签页：每个标签页是一个进程，但共享同一份浏览器程序代码。这就是「一份程序、多份进程」的日常实例，见 Linux 专题《进程描述符 task_struct》。</span>

## 4 核心对比表：进程给操作系统带来什么

用一张表总结「为什么必须有进程」：

| 操作系统的职责 | 没有进程概念会怎样 | 进程概念如何解决 |
| --- | --- | --- |
| 公平使用 CPU | 无法区分「谁在用 CPU」 | 调度器以进程为单位轮转 |
| 内存隔离 | 程序可以随便踩彼此的内存 | 每个进程独立地址空间 |
| 资源记账 | 不知道谁占了什么 | 进程持有资源清单 |
| 多任务并发 | 一次只能跑一个程序 | 多个进程交替执行 |
| 系统安全 | 恶意程序畅通无阻 | 按进程检查权限 |

**进程是现代操作系统一切资源管理的归属单位**——CPU 时间归进程，内存页归进程，文件描述符归进程，权限检查的对象也是进程。理解了这个「归属」模型，后面内存、文件、I/O 各篇都是在问同一个问题：这块资源，属于哪个进程，由谁管理。

## 5 小结

- **程序是静态的指令集合，进程是动态的一次执行**——菜谱与做菜的关系。
- 进程由**程序段、数据段、堆栈段、PCB** 四部分组成。
- 程序与进程是**多对多**关系：一份程序可多进程，一进程可先后执行多程序。
- 进程是 CPU 调度、内存隔离、资源记账、权限检查的**统一归属单位**。
- 操作系统眼里的进程，核心就是它的 **PCB**。
