## 为什么从线程开始

前十四篇的主角是进程。但细心观察会发现进程「太重了」：每个进程有自己的地址空间，进程间通信要过内核，上下文切换要动页表。如果一个程序想同时做几件事——边渲染边下载边响应用户点击——为每件事各开一个进程太浪费，开几个「轻量级进程」又不够。**线程（thread）就是操作系统对「进程太重」的回应**：在同一个进程内部再划分出多个可以独立调度的执行流。<span class="marginnote">回顾《进程概念》：进程 = 资源（地址空间、文件）+ 执行（CPU 上下文）。线程把「执行」部分再细分：同一进程的多个线程共享资源、各自执行。这是理解线程的钥匙。</span>

## 1 什么是线程

**线程（thread）**：进程内的一条独立执行路径，是 CPU 调度的基本单位。一个进程包含一个或多个线程，每个线程有自己的：

**线程 ID（TID）**
**程序计数器（PC）与寄存器集合**
**栈（局部变量、函数调用链）**

而同一进程内的线程**共享**：

**代码段、数据段**
**堆与动态内存**
**打开的文件、信号处理器等进程级资源**

**进程是资源分配的单位，线程是 CPU 调度的单位**——这句话是全篇的题眼。调度器调度的是线程而非进程；内存、文件等资源则挂在进程名下，由该进程的所有线程共享。<span class="marginnote">对照 PCB 与 TCB：每个进程一个 PCB，进程内每个线程一个 TCB（线程控制块），TCB 只记录线程自己的 PC、寄存器、栈指针，比 PCB 小得多——这正是线程上下文切换比进程切换便宜的原因。</span>

## 2 线程 vs 进程：一张对比表

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 资源分配 | 独立地址空间、文件表 | 共享所属进程的资源 |
| 调度单位 | 是（内含线程时调度线程） | 是（基本调度单位） |
| 上下文切换成本 | 高（动页表、TLB 失效） | 低（只需换寄存器与栈） |
| 通信方式 | IPC（管道、消息、共享内存） | 直接读写共享变量 |
| 独立性 | 一个崩溃不影响其他进程 | 一个线程崩溃可能拖垮整个进程 |
| 创建开销 | 大 | 小（快一个量级） |

**核心权衡**：线程的「共享」是双刃剑——共享让通信快、创建快、切换快，但也意味着**没有隔离**：一个线程越界写坏内存，整个进程（所有线程）一起遭殃；多线程同时写共享变量，就会出竞态条件（见第四篇《共享数据与竞态条件》）。

## 3 多线程的优势

**多线程编程（multithreaded programming）**让一个程序同时做多件事。四个主要优势：

**响应性（responsiveness）**：交互式程序一个线程阻塞（如下载），其他线程仍能响应点击——界面不「卡死」。
**资源共享（resource sharing）**：线程默认共享进程资源，无需 IPC，通信高效。
**经济性（economy）**：创建线程比创建进程便宜；线程上下文切换比进程切换便宜。多线程「轻」体现在每一次操作上。
**可扩展性（scalability）**：多核 CPU 上，多线程可以真正并行执行，充分利用多核——单线程程序只能用一个核。

**辨析｜易错点：** 「多线程 = 多核并行」是初学者最常犯的错。**多线程只是「可能并行」，在单核 CPU 上多线程依然是分时交替（并发），并不提速。** 并发（concurrent）是「同时推进多个任务」，并行（parallel）是「同一时刻真在多个核上执行」。多线程能否加速，取决于有没有多核、任务能否切分——这正是 Amdahl 定律（见第四篇《并行与并发》）要算的账。

另一个易错点：**「多线程一定更快」**。在线程频繁争抢共享数据时，同步开销可能超过并行收益；创建过多线程还会耗尽内存与调度时间。多线程是「工具箱里的工具」，不是「万能的加速器」。<span class="marginnote">一个经典例子：单线程遍历数组算和，与开 8 个线程分块求和，在数据量小时多线程反而更慢——线程创建、同步、合并的开销超过了并行收益。「先量数据，再定线程数」是工程常识。</span>

## 4 多线程的典型应用

- **Web 服务器**：每个请求一个线程，或线程池处理请求（见第四篇《隐式线程》）。
- **字处理器/浏览器**：渲染线程、网络线程、UI 线程分离，互不阻塞。
- **科学计算**：矩阵分块给多线程并行算。
- **大数据/大模型训练**：GPU 与 CPU 之间、多个数据并行 worker 之间都是多线程协作。

现代 Web 服务器常从「一进程一请求」转向「一进程多线程」再到「多线程 + 事件驱动」，其演变就是「进程太重 → 线程够轻 → 线程也重（改用协程）」的不断权衡——你会在大模型部署篇的推理引擎里再次见到这个演化。

## 5 小结

- **线程**是进程内独立执行流，是**调度单位**；进程是**资源分配单位**。
- 线程共享进程的代码、数据、文件，独享 PC、寄存器、栈。
- 线程 vs 进程：**线程轻（创建快、切换快、通信快）但不隔离**。
- 多线程四大优势：**响应性、资源共享、经济性、可扩展性**。
- **并发 ≠ 并行**，多线程在多核上才可能真正加速，同步开销也可能吃掉收益。
