## 为什么从网络威胁开始

单机安全还不够——现代系统连在网络里，攻击者可以从**网络**发起攻击。这一节看网络威胁的两大类：**探测与攻击**（端口扫描、拒绝服务），以及**防御**（防火墙、入侵检测）。这是操作系统安全与《计算机网络》的交叉地带。<span class="marginnote">回顾《安全威胁》：木马/病毒/蠕虫是「恶意代码」，缓冲区溢出是「程序漏洞」。网络威胁是第三类——<strong>攻击者不一定要进系统，可以从网络层面探测、轰炸、瘫痪</strong>。完整网络攻防见《计算机网络》与《密码学与信息安全》专题。</span>

## 1 端口扫描：攻击者的「踩点」

**端口扫描（port scanning）**：攻击者向目标机器的**大量端口**发送探测连接，判断「哪些端口开着、跑着什么服务」——为后续攻击踩点。

- 每个开放端口 = 一个可攻击的服务（SSH、Web、数据库）。
- 扫描结果告诉攻击者「目标有哪些攻击面」。

**常见扫描**：TCP 全连接扫描、SYN 半开扫描、UDP 扫描。

**防御**：**关闭不需要的服务/端口**（减少攻击面）、防火墙过滤未授权扫描。

**辨析｜易错点：** 「端口扫描本身就是攻击」不准确——**扫描是「侦查」，不是「直接破坏」**。但扫描是攻击的前奏（像踩点），被扫描的机器应警惕。**「减少开放端口」是缩小攻击面（$p/P$）的网络版（回顾最小特权）。**

## 2 拒绝服务（DoS）与分布式拒绝服务（DDoS）

**拒绝服务（DoS, Denial of Service）**：让目标系统**无法提供服务**——不是窃取，而是「瘫痪」。

**常见手段**：

- **洪水攻击（flooding）**：向目标发送海量请求/数据包，耗尽带宽或连接资源——正常用户挤不进来。
- **资源耗尽**：耗尽 CPU、内存、连接表。
- **放大攻击**：利用放大协议（如 DNS 放大）用少量请求制造海量流量。

**DDoS（分布式拒绝服务）**：攻击者用**大量被控制的机器（僵尸网络）**同时发起 DoS——单点防御难以抵挡，流量大到能压垮骨干网络。

**公式解析：DoS 的本质**

系统能处理的并发请求有上限 $C$，攻击者发送 $A$ 个请求：

- 若 $A > C$：合法请求被挤出——**服务不可用**。
- DDoS 的 $A$ 来自成千上万台机器，$A$ 可以远超 $C$——**防御者无法用「封一个 IP」解决**。

**直觉**：DoS 攻击的是「**可用性**」（回顾保护三目标）——系统还在，但谁也用不了。防御思路：**限流（rate limiting）、弹性扩容、流量清洗**。

## 3 防火墙：网络的「门卫」

**防火墙（firewall）**：部署在网络边界的设备/软件，**按规则过滤进出流量**——允许合法、阻断可疑。

**防火墙的过滤依据**：

- **IP 地址**：允许/拒绝来自某 IP 的流量。
- **端口**：只开放必要端口（如只放行 80/443）。
- **协议**：允许/拒绝 TCP/UDP/ICMP。
- **状态**：有状态防火墙跟踪连接状态，只允许「已建立连接」的返回流量。

**防火墙的位置**：

- **主机防火墙**：每台机器上（Linux `iptables`/`nftables`、Windows 防火墙）。
- **网络防火墙**：网络边界（企业出口、云安全组）。

**防火墙的局限**：**它是「门卫」不是「守卫」**——只按规则放行/阻断，**不检测流量内容**（不识别恶意 payload）。防「不该进的流量」，不防「进来的恶意内容」。

## 4 入侵检测与防御（IDS/IPS）

**入侵检测系统（IDS, Intrusion Detection System）**：**监控网络/系统行为，发现攻击迹象并告警**。

**入侵防御系统（IPS）**：IDS + **主动阻断**——检测到攻击即拦截。

**检测方法**：

- **特征检测（signature-based）**：匹配已知攻击的「特征码」——准但只能防已知攻击。
- **异常检测（anomaly-based）**：学习正常行为，偏离即报警——能发现新攻击但误报多。
- **行为分析**：结合日志、流量、进程行为综合判断。

**IDS 的位置**：网络边界（监控进出流量）、主机（监控进程/文件/系统调用）。

**公式解析：检测的精确率与召回率**

设攻击实际发生 $P$ 次，检测系统报警 $R$ 次，其中 $TP$ 次是真攻击、$FP$ 次是误报：

$$\text{精确率} = \frac{TP}{TP + FP}, \qquad \text{召回率} = \frac{TP}{P}$$

- **精确率**：报警里有多少是真攻击（误报越低越好）。
- **召回率**：真攻击里有多少被报出来（漏报越低越好）。
- 两者**此消彼长**：阈值调严 → 漏报少但误报多；调松 → 误报少但漏报多。

**直觉**：入侵检测是「**平衡误报与漏报**」的艺术——误报太多管理员「狼来了」疲劳，漏报则攻击成功。现代方案是特征 + 异常 + 行为分析组合。

## 5 核心对比表：威胁与防御

| 威胁/防御 | 是什么 | 防/攻什么 |
| --- | --- | --- |
| 端口扫描 | 探测开放服务 | 攻击前踩点 |
| DoS/DDoS | 洪水瘫痪服务 | 可用性 |
| 防火墙 | 过滤流量 | 不该进的流量 |
| IDS/IPS | 检测/阻断攻击 | 入侵行为 |

**设计启示**：网络安全的完整图景是「**缩小攻击面（关端口）+ 边界过滤（防火墙）+ 检测响应（IDS）+ 弹性容灾（抗 DoS）**」的纵深防御。与单机安全的「最小特权 + 访问控制 + 审计」互补——**安全永远是分层叠加，没有单一银弹。**

## 7 小结

- **端口扫描**：探测开放服务，是攻击的踩点；防御 = 关不必要端口。
- **DoS/DDoS**：洪水/资源耗尽瘫痪服务；防御 = 限流、扩容、流量清洗。
- **防火墙**：按 IP/端口/协议/状态过滤流量，是「门卫」不查内容。
- **IDS/IPS**：特征/异常/行为检测，平衡精确率与召回率。
- 网络防御 = **缩小攻击面 + 边界过滤 + 检测响应 + 弹性容灾**的纵深防御。
