## 为什么从中断开始

上一篇搭好了这台机器：CPU、内存、设备控制器、总线。现在出现一个现实问题：**CPU 在做自己的算术，设备控制器在后台默默传输数据，它们之间怎么同步？** 你不可能让 CPU 放下手里的事去死等设备——那算力就全浪费了。**中断（interrupt）**就是硬件给出的标准答案：设备干完了，主动「打断」CPU 一下，报个信；CPU 处理完再回去接着算。中断是计算机保持对外界响应的物理基础，也是系统调用、异常处理、用户态与内核态切换全部机制的地基。当年正是它把计算机从「提交作业等结果」的批处理解放出来，才催生了交互式的分时系统——这是艾伦 · 凯那句话在硬件史上的注脚。

## 1 从轮询到中断：CPU 为什么要学会「被插队」

在中断之前，最朴素的同步方式是**轮询（polling）**：CPU 反复去读设备的状态寄存器，问「好了吗？好了吗？」。设备没准备好，CPU 就在空转——这称为**忙等（busy waiting）**。<span class="marginnote">轮询在现代并没有绝迹：等待极短的寄存器握手、或追求极致低延迟的路径（DPDK 收包、virtio 高吞吐）反而偏爱它，因为省掉了中断本身的开关与切换开销。关键判断是「等多久」：比一次中断还快，就轮询；否则就中断。</span>

**重点：轮询把「等待」的代价全部算在 CPU 头上；中断则把「通知」的责任转交给硬件，让 CPU 在等待期间去做别的事。** 这是事件驱动思想的硬件版——CPU 不再主动询问，而是被事件唤醒。

**核心概念**：**中断（interrupt）**：由硬件（多为 I/O 设备或时钟）发出的异步电信号，它打断 CPU 当前的指令流，使 CPU 转去执行预先注册的中断处理程序（interrupt handler），处理完再返回被中断的现场继续执行。

中断并不是先有计算机就有的机制：它诞生于 20 世纪 50 年代的 Whirlwind 计算机，为的是让机器在慢速输入设备前保持响应。今天看来理所当然的「边输入边计算」，当年是需要一项新硬件机制才能解开的难题——这正是开头那句「预测未来的最好方式就是创造它」的注脚。

## 2 中断的两大家族：异步中断与同步异常

按来源与触发时机，事件分两大类——中文教材常统称「中断」，英文里则严格区分：

| 类别 | 英文 | 触发时机 | 典型例子 |
| --- | --- | --- | --- |
| 外部中断 | interrupt | 异步，随时可能来 | 磁盘完成、键盘敲击、网卡收包、定时器 |
| 异常 | exception | 同步，随指令触发 | 除零、缺页、非法指令、系统调用 |

**核心概念**：**异常（exception）**：由正在执行的指令**同步**引发的事件，又分三种——**陷阱（trap）**：主动引发，如系统调用（程序故意请内核办事）；**故障（fault）**：可恢复的错误，如缺页（page fault）——处理完还能回到引发它的那条指令重试；**终止（abort）**：不可恢复的错误，如硬件故障——程序直接被终止。<span class="marginnote">「系统调用是故意制造一次陷阱」：Linux 用一条 <code>syscall</code> 指令（老内核是 <code>int 0x80</code>）触发异常，CPU 借此切换到内核态。这条从用户态到内核态的完整路径，是第十五篇《Linux 专题：系统调用》的主题。</span>

**辨析｜易错点：** 区分中断与异常最可靠的判据是**「跟当前指令有没有关系」**：外部中断与正在执行的指令无关，随时可能插入；异常必然由当前指令触发。一个常见误解是把「系统调用」当成中断——它是异常（陷阱）：虽然是主动请求，但走的是同步的异常通道，而非设备异步通知。

**时钟（定时器）中断是特殊而重要的一种**：操作系统靠它获得周期性的控制权——每过一小段时间就打断当前进程，检查是否该换一个进程上 CPU。没有时钟中断，多道程序与分时调度就无从谈起；第五篇《CPU 调度》里每一次抢占（preemption），都建立在这颗「心跳」之上。可以说，时钟中断是操作系统从「被服务的旁观者」变成「有节奏的管理者」的那一拍。

## 3 流程解析：一次中断的完整旅程

从设备发出信号到 CPU 回到原指令，一次中断处理是一条有固定环节的流水线，配图逐步拆开：

1. **设备发出请求**：设备控制器完成 I/O 后，向 CPU 的中断请求线（interrupt-request line）拉高信号。
2. **CPU 应答**：CPU 在每个指令周期末尾检查中断请求线——发现信号，便不再开始下一条指令，转入中断响应。
3. **保存现场**：CPU 把程序计数器（PC）与必要的寄存器压入栈（或写入被中断进程的上下文），以便之后准确回到「被打断的那一条指令」。
4. **查表定位**：用设备提供的中断号（vector number）查**中断向量表（interrupt vector table）**，拿到对应中断处理程序的入口地址。
5. **执行处理程序**：CPU 跳转到中断服务例程（ISR），处理本次事件：读设备状态、搬运数据、复位设备等。
6. **恢复现场**：从栈中弹出之前保存的寄存器与 PC。
7. **返回**：继续执行被中断的指令，仿佛什么都没发生。

![一次中断的完整处理流程](/images/os/interrupts-1.svg)

**重点：中断处理的两条铁律——快**（处理程序要尽量短，长工作推迟到下半部或软中断再做，否则会丢失后续中断）**和干净**（进出处理程序时现场必须完整保存与恢复，不能污染被打断的程序）。这两条铁律贯穿整个操作系统：Linux 的硬中断与软中断（下半部）、第十一篇《I/O 系统》里的中断驱动，都是它们的延伸。

一段极简的中断服务程序大概长这样（现场保存与恢复由硬件与内核协作完成）：

```c
void disk_isr(void) {              /* 磁盘完成中断服务程序 */
    int status = disk->status;     /* 读设备状态，确认成功 */
    *buf++ = disk->data_reg;       /* 取走一个字节（中断驱动模式） */
    if (--remaining == 0)
        wakeup(waiting_process);   /* 全部读完，唤醒等待进程 */
}   /* 处理得越短，丢失后续中断的风险越小 */
```

注意它「短」：读状态、搬数据、唤醒进程，三件事办完立刻返回——这就是铁律「快」在代码层面的样子。

## 4 公式解析：中断方式到底为 CPU 省下多少时间

中断的动机是「别让 CPU 死等」，它省了多少可以量化。设某设备的数据速率是 $r$ 字节/秒，CPU 主频 $f$，处理一次中断平均花 $c$ 个时钟周期，那么中断驱动方式下，CPU 为处理这台设备中断所占的时间比例是：

$$
U = \frac{r \cdot c}{f}
$$

逐步拆解：

- **第一步，算每秒中断次数**：设备每秒产生 $r$ 个字节，每来一个字节中断一次，所以每秒约 $r$ 次中断。
- **第二步，算每秒中断开销**：每次中断花 $c$ 个周期，每秒共 $r \cdot c$ 个周期。
- **第三步，归一化**：除以主频 $f$（每秒总周期数），得到 CPU 被这台设备占用的比例 $U$。
- **代入数字**：一台 3 GHz 机器（$f = 3 \times 10^9$），处理一次中断平均 500 个周期，设备速率 1 MB/s（$r = 10^6$）：

$$
U = \frac{10^6 \times 500}{3 \times 10^9} \approx 0.17\%
$$

结论：对于慢速设备，中断驱动的开销微乎其微。但注意两个放大因素——设备变快（$r$ 上升）或中断变频繁（每字节都中断），$U$ 会迅速攀升。这正是下一篇《输入输出结构：DMA 与设备控制器》里 DMA 出场的数学原因。

再看一眼公式的结构：分子是「事件量 × 单次代价」，分母是 CPU 总能力。凡是「事件太频繁」或「单次代价太高」的地方，就是设计者引入专门硬件的地方——中断本身是第一次，DMA 是第二次。

## 5 中断向量表、优先级与嵌套

**核心概念**：**中断向量表（interrupt vector table）**：一张「中断号 → 处理程序入口地址」的映射表，通常驻留在主存低地址。设备通过总线把自己的中断号带给 CPU，CPU 直接查表跳转，避免了用 if-else 链逐个比对设备的低效。<span class="marginnote">x86 的中断描述符表（IDT）最多 256 项：0 号是除零异常，14 号是缺页故障，32–255 号留给硬件外设；Linux 32 位时代用 0x80（128 号）作为系统调用陷阱。这些数字在第十五篇还会以「系统调用号 + 向量表」的形式重逢。</span>

多个中断同时到来怎么办？两个机制：

- **优先级（priority）**：每条中断线有优先级，高优先级先处理。
- **嵌套中断（nested interrupt）**：处理一个中断时，可被更高优先级的中断打断（保存现场、处理、恢复）；低优先级中断会被屏蔽，直到高优先级处理完。<span class="marginnote">嵌套中断必须配合「关中断 / 开中断」指令：进入处理程序先关中断，防止被同类打断，关键区结束再开。这就是内核「临界区」与「原子操作」概念的硬件源头，第六篇《进程同步》会正面研究它。</span>

一个典型的排序：x86 体系里时钟中断的优先级高于键盘中断，时钟的滴答绝不会被键盘输入耽误——因为时间片的分发比字符输入更紧迫。这种「越紧急越优先」的排序，本身就是一种调度策略，只不过它由硬件固定，而第五篇里进程级的调度策略由操作系统决定。

**核心概念**：**不可屏蔽中断（non-maskable interrupt，NMI）**：无法被软件屏蔽的中断，专用于电源故障、内存奇偶错误等必须立刻响应的灾难性事件。

## 6 小结

- **中断**是设备异步通知 CPU 的硬件机制；按来源分**外部中断**（异步）与**异常**（同步），异常又分陷阱、故障与终止。
- 中断处理七步：设备发信号 → CPU 应答 → 保存现场 → 查向量表 → 执行 ISR → 恢复现场 → 返回。
- 中断处理两大铁律：**快**与**干净**；长工作推迟到软中断 / 下半部。
- 中断向量表把「中断号」映射到处理程序入口；优先级与嵌套保证多中断下的秩序。
- 中断驱动 CPU 占用率 $U = rc/f$，对慢速设备开销极小——这为 DMA 出场埋下伏笔。
- 中断的诞生让计算机从批处理走向交互，是分时系统与多道程序的硬件前提（第六篇《操作系统的发展历史》）。

在下一节，我们将从「数据怎么被通知」转向「数据本身怎么存放」：CPU 访问寄存器只要一拍，访问磁盘却要几毫秒——速度差跨越多个数量级，靠什么弥合？答案是**多级存储层次**。
