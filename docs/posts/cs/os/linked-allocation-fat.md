## 为什么从链接分配开始

连续分配的「连续性」带来了碎片与增长难题。**链接分配（linked allocation）**彻底放弃连续：**文件的数据块散落各处，每块存一个「指向下一块」的指针**，串成一条链表。碎片问题从根上消失——只要有一个空闲块，就能加入文件。这一节还看它的著名变体 **FAT**（文件分配表）。<span class="marginnote">回顾连续分配的缺陷：碎片 + 无法增长。链接分配用「指针串链」同时解决两者——文件可以任意增长（链尾加块），无需连续空间（任何空闲块都可加入）。<strong>用指针换连续性，是文件分配的第二次革命。</strong></span>

## 1 简单链接分配：每块一个指针

**链接分配（linked allocation）**：文件的数据块分散在磁盘各处，每个块末尾存一个**指向下一块的指针**，最后一个块的指针为 null。

**FCB 只需记录**：**起始块号 + 结束块号**。

```
文件 FCB：起始块 = 9，结束块 = 25

块 9 ──▶ 块 16 ──▶ 块 22 ──▶ 块 25 ──▶ null
       (指针)      (指针)      (指针)
```

**优点**：

**无外部碎片**：只要有任意空闲块即可分配。
**文件可任意增长**：链尾加一块即可。
创建文件无需预知大小。

**缺点（致命）**：

**顺序读慢**：要一块一块沿指针跳，每块都有指针寻址（随机寻道）。
**随机访问极慢**：访问第 $i$ 块必须从头遍历 $i$ 次——$O(n)$。
**指针占空间**：每块末尾的指针（4~8 字节）浪费存储。
**指针损坏灾难**：指针断了，文件后半部分全丢。

## 2 FAT：把指针集中放到一张表

**文件分配表（FAT, File Allocation Table）**：不把指针存在数据块里，而是**单独用一张表**存「每一块的下一块」——表的下标就是块号，表项存「下一块号」。

FAT 放在磁盘的**固定区域**（表本身占一小块磁盘）。
文件 = 一个**起始块号**；查找时在 FAT 里沿表项跳转。

```
FAT（下标 = 块号，表项 = 下一块号）：
  块号:   0    1    2    3    4
  表项:   3   EOF   4    2   EOF

文件 A 起始块 = 0 → 链为：0 → 3 → 2 → 4 → EOF
```

**FAT 的改进**：

**指针集中**：数据块不再被指针占用，全部存数据。
**顺序/随机访问变快**：FAT 在内存（或缓存）里，沿表跳转不走磁盘——随机访问 $O(n)$ 但表项访问是内存级。
**FAT 的代价**：**表本身占磁盘空间**（随磁盘增大而增大）；FAT 需常驻缓存，太大则缓存不下。

**FAT 是历史名将**：**FAT16/FAT32** 是微软的经典文件系统（U 盘、旧 Windows），它把 FAT 放在磁盘开头、多份备份。它的名字「FAT」就是这张表。

**辨析｜易错点：** 「FAT 与链接分配是两种东西」——**FAT 是链接分配的实现变体**：同样的「串链」思想，只是把指针从「数据块内」挪到「独立表内」。二者共享「链表寻址」的本质，区别只在指针的存放位置。<span class="marginnote">把「指针跟着数据走」改成「指针集中存表」，是文件系统设计的一次经典优化：<strong>集中表让指针访问变内存级、让数据块不再被指针占用</strong>。同样的思路你在页表（集中存映射）、索引分配（下一篇）里还会看到——「把分散的元数据集中起来」是系统设计的万能招。</span>

**数值算例：FAT 表占多少磁盘**。以 FAT32 为例：32 位表项、每簇通常 4 KB。一块 32 GB 的 U 盘约有 $32\text{ GB} / 4\text{ KB} = 8 \times 10^6$ 簇，FAT 表项数 = 簇数，每项 4 字节：

$$\text{FAT 表大小} \approx 8 \times 10^6 \times 4\text{ B} = 32\text{ MB}$$

磁盘开头还存**两份备份**（约 64 MB 元数据开销）。**簇大小是把「表开销」与「内部碎片」放在天平两端**：簇设小 → 表变大（浪费空间存表）；簇设大 → 最后一簇的零头浪费变多（内部碎片）。<span class="marginnote">这也是为什么大分区建议用大簇：簇越大，FAT 表越小、可缓存性越好；代价是大量小文件时每个文件尾簇浪费平均半簇。FAT32 的 4 KB 默认簇正是在「U 盘小文件多」的场景下取的平衡点。</span>

## 3 链接分配的现代命运

- **简单链接分配**：几乎绝迹于现代文件系统（指针脆弱、访问慢）。
- **FAT32**：仍用于**U 盘与跨平台交换**（兼容性最好），但大文件支持有限（4GB 上限）与无日志是硬伤。
- 现代文件系统（ext4、XFS、NTFS）都转向**索引分配**（下一篇）——用索引块存「块号列表」，兼顾连续的速度与链表的灵活。
- 若想同时拥有 FAT 的简单与索引的随机访问，还有 exFAT 这类改进——它保留「表驱动」思路但去掉了 FAT32 的 4GB 单文件上限，成为 U 盘与相机卡的新标准。

**可靠性辨析**：FAT 的「表集中」是双刃剑——指针集中让访问快，也让**整张表成为单点故障**：表损坏 = 全盘文件的链全断。相比之下简单链接的指针随文件走，单文件指针坏了只丢该文件。<span class="marginnote">这也是 FAT 保留多份表备份的原因——用「复制表」对冲「表是单点」的风险。而 ext4 把块指针放进每个 inode（分散的元数据），天然避免「一张表坏全盘死」。</span>

**设计启示**：链接分配的历史地位在于证明了「**文件不必连续也能工作**」——它用「指针链」彻底解决了碎片与增长，代价是访问慢。FAT 是它的集大成优化。最终，**索引分配**把「链表的多级寻址」与「连续的直接跳转」结合，成为现代标准——这是下一篇的内容。

## 4 核心对比表：连续 vs 链接 vs FAT

| 维度 | 连续分配 | 简单链接 | FAT |
| --- | --- | --- | --- |
| 连续性 | 连续 | 散落 + 指针 | 散落 + 表 |
| 外部碎片 | 严重 | 无 | 无 |
| 文件增长 | 难 | 容易 | 容易 |
| 随机访问 | O(1) | O(n) | O(n)（表在内存） |
| 指针存哪 | 无 | 数据块内 | 独立 FAT 表 |
| 可靠性 | 中 | 指针易断 | 表损坏危险 |

**术语速查表**：

| 术语 | 含义 |
| --- | --- |
| 连续分配 | 文件占一段连续磁盘块 |
| 链接分配 | 数据块散落 + 每块存下一块指针 |
| FAT | 文件分配表，指针集中存放的独立表 |
| FCB | 文件控制块，记起始/结束块号 |
| 簇（cluster） | FAT 的分配单元（多为 4 KB） |
| EOF 表项 | 标记链尾的特殊表项值 |
| 内部碎片 | 文件最后一簇未用满的零头 |
| 表损坏 | FAT 表本身被破坏导致的整盘风险 |

## 5 小结

- **链接分配**：数据块散落 + 每块存下一块指针，FCB 记起始与结束块。
- 优点：**无碎片、易增长**；缺点：**顺序读慢、随机访问 O(n)、指针占空间且易损坏**。
- **FAT**：把指针集中到独立表，数据块纯存数据，表访问走内存——FAT32 统治 U 盘时代。
- FAT 是链接分配的实现变体，不是两种方法。
- 现代文件系统转向**索引分配**，兼得速度与灵活。
