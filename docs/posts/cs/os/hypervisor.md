## 为什么从虚拟机开始

前面几篇讲的是「一个内核如何组织自己」，而虚拟化问的是一个更狂妄的问题：**一个物理机器，能不能同时跑多个操作系统？** 1960 年代 IBM 用虚拟机让大型机分时共享，2010 年代云计算靠虚拟机把一台服务器切成几十个「电脑」出租，再到今天的容器与「云原生」——虚拟化是理解现代数据中心的必修课。<span class="marginnote">虚拟化的本质是「把硬件也变成软件可管理的资源」。这与操作系统「把 CPU、内存抽象成进程与地址空间」是同一条路，只是抽象层级又抬高了一层——从「进程之上」抬到「OS 之上」。</span>

## 1 虚拟机与虚拟机监控器

**虚拟机（virtual machine, VM）**：一个用软件模拟出来的、具有完整硬件的「假电脑」，可以独立安装并运行一个完整的操作系统。运行在 VM 里的操作系统称为**客户操作系统（guest OS）**。

让 VM 成立的核心软件是**虚拟机监控器（VMM / hypervisor，虚拟机管理程序）**，它运行在物理硬件与各客户 OS 之间，负责：

- **资源分配**：把物理 CPU、内存、磁盘、网卡切片，分给每个 VM。
- **隔离**：保证一个 VM 的崩溃或恶意行为不影响其他 VM。
- **指令模拟**：让客户 OS 以为自己独占整台机器。

**关键认识：hypervisor 本身也是一个小型操作系统**——它管理进程（VM）、调度 CPU、管理内存，只是它的「进程」是整个客户 OS。学过本专题前面的进程、内存管理，你会惊喜地发现虚拟化的所有概念都能对号入座。<span class="marginnote">这也解释了为什么虚拟化专题被放在操作系统结构篇里：VM 就是「更重的进程」，hypervisor 就是「只做隔离与调度的超薄内核」。Linux 专题《虚拟化基础》将进一步展开指令模拟的细节。</span>

## 2 Type-1 hypervisor：裸金属

**Type-1 hypervisor（裸金属 / native / bare-metal）**：直接运行在物理硬件上，不依赖任何宿主操作系统。它自己就是「最底层的内核」，客户 OS 运行在它之上。

| 特性 | 说明 |
| --- | --- |
| 运行位置 | 直接管理硬件 |
| 典型代表 | VMware ESXi、Xen、Microsoft Hyper-V、KVM（Linux 内嵌） |
| 性能 | 最高，无宿主 OS 中间层 |
| 使用场景 | 数据中心、云计算（AWS、阿里云底层） |

Xen 是 Type-1 的代表：它运行在硬件上，客户 OS 可以是 Linux、Windows，甚至还能再套一层虚拟化（嵌套虚拟化）。数据中心里绝大多数虚拟机都跑在 Type-1 hypervisor 上。

## 3 Type-2 hypervisor：寄宿式

**Type-2 hypervisor（寄宿式 / hosted）**：作为一个普通应用程序运行在宿主操作系统之上，把宿主 OS 当作它的「硬件」来使用。

| 特性 | 说明 |
| --- | --- |
| 运行位置 | 宿主 OS 内的应用进程 |
| 典型代表 | VirtualBox、VMware Workstation、QEMU（纯软件模式） |
| 性能 | 较低，经过宿主 OS 间接访问硬件 |
| 使用场景 | 开发测试、个人电脑、教学 |

**Type-1 与 Type-2 的分界不是「能不能用」，而是「谁直接碰硬件」**：Type-1 自己碰，Type-2 借宿主的服务碰。<span class="marginnote">QEMU 比较特殊：单独运行时是 Type-2（纯软件模拟，很慢）；配合 KVM 使用时就变成 Type-1（KVM 是内核模块直接管硬件）。同一个软件，两种身份，见 Linux 专题《KVM 架构》。</span>

## 4 核心对比表：Type-1 与 Type-2

| 维度 | Type-1 裸金属 | Type-2 寄宿式 |
| --- | --- | --- |
| 底层依赖 | 直接管理硬件 | 依赖宿主 OS |
| 性能 | 高（接近物理机） | 低（多一层间接） |
| 故障波及 | 客户 OS 崩溃互不影响 | 宿主 OS 崩溃全部完蛋 |
| 部署成本 | 需要专用服务器 | 桌面装个软件即可 |
| 典型场景 | 云数据中心 | 开发、测试、学习 |
| 代表 | ESXi、Xen、Hyper-V | VirtualBox、Workstation |

**辨析｜易错点：** 「Type-2 比 Type-1 安全」是个常见错觉。实际上 Type-2 的客户 OS 与宿主 OS 共享一台机器的信任边界，宿主一旦被攻破，所有客户都暴露；Type-1 的每个 VM 在硬件层被隔离，安全性反而更可控。**性能与安全都指向 Type-1，Type-2 赢在「方便」二字。**

## 5 小结

- **虚拟机**是软件模拟出的完整「假硬件」，可装可跑完整 OS。
- **hypervisor** 是虚拟化的核心，本质是一个「以 VM 为进程」的微型内核。
- **Type-1** 直接管硬件，性能与隔离最好，统治数据中心；**Type-2** 跑在宿主 OS 上，胜在方便，用于开发与学习。
- QEMU 兼有两种身份：纯软件是 Type-2，配合 KVM 变 Type-1。
- 虚拟化是「把硬件抽象成资源」思想的最高形态，是云计算的基石。
