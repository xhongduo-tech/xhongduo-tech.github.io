## 为什么从虚拟机开始

前面几篇讲的是「一个内核如何组织自己」，而虚拟化问的是一个更狂妄的问题：**一个物理机器，能不能同时跑多个操作系统？** 1960 年代 IBM 用虚拟机让大型机分时共享，2010 年代云计算靠虚拟机把一台服务器切成几十个「电脑」出租，再到今天的容器与「云原生」——虚拟化是理解现代数据中心的必修课。<span class="marginnote">虚拟化的本质是「把硬件也变成软件可管理的资源」。这与操作系统「把 CPU、内存抽象成进程与地址空间」是同一条路，只是抽象层级又抬高了一层——从「进程之上」抬到「OS 之上」。</span>

为什么要绕这么大一圈跑多个 OS，而不是像进程那样共享？答案是**隔离与遗产**两股力量：隔离方面，云厂商必须保证「租客 A 的崩溃/攻击伤不到租客 B」，进程级隔离还不够强，VM 是完整的硬件级隔离；遗产方面，很多企业系统（银行、税务）跑在特定 OS 上，直接迁移成本极高，把它们装进 VM 就能在新型硬件上继续活几十年。这两点合起来解释了虚拟化为什么不是可选项，而是数据中心的必选项。

## 1 虚拟机与虚拟机监控器

**虚拟机（virtual machine, VM）**：一个用软件模拟出来的、具有完整硬件的「假电脑」，可以独立安装并运行一个完整的操作系统。运行在 VM 里的操作系统称为**客户操作系统（guest OS）**。

让 VM 成立的核心软件是**虚拟机监控器（VMM / hypervisor，虚拟机管理程序）**，它运行在物理硬件与各客户 OS 之间，负责：

**资源分配**：把物理 CPU、内存、磁盘、网卡切片，分给每个 VM。
**隔离**：保证一个 VM 的崩溃或恶意行为不影响其他 VM。
**指令模拟**：让客户 OS 以为自己独占整台机器。

**关键认识：hypervisor 本身也是一个小型操作系统**——它管理进程（VM）、调度 CPU、管理内存，只是它的「进程」是整个客户 OS。学过本专题前面的进程、内存管理，你会惊喜地发现虚拟化的所有概念都能对号入座。<span class="marginnote">这也解释了为什么虚拟化专题被放在操作系统结构篇里：VM 就是「更重的进程」，hypervisor 就是「只做隔离与调度的超薄内核」。Linux 专题《虚拟化基础》将进一步展开指令模拟的细节。</span>

拿「调度」做一次类比：普通内核调度的是**线程**，切换一次要保存/恢复线程上下文；hypervisor 调度的是**整个客户 OS**，切换一次相当于「保存整个客户 OS 的全部 CPU 状态（寄存器、页表基址、中断状态）再换出」——代价大得多，所以虚拟机的上下文切换比进程切换昂贵一到两个数量级。这也是为什么云厂商宁可用「一台机器跑固定几个 VM」而不是频繁启停虚拟机。

## 2 Type-1 hypervisor：裸金属

**Type-1 hypervisor（裸金属 / native / bare-metal）**：直接运行在物理硬件上，不依赖任何宿主操作系统。它自己就是「最底层的内核」，客户 OS 运行在它之上。

| 特性 | 说明 |
| --- | --- |
| 运行位置 | 直接管理硬件 |
| 典型代表 | VMware ESXi、Xen、Microsoft Hyper-V、KVM（Linux 内嵌） |
| 性能 | 最高，无宿主 OS 中间层 |
| 使用场景 | 数据中心、云计算（AWS、阿里云底层） |

Xen 是 Type-1 的代表：它运行在硬件上，客户 OS 可以是 Linux、Windows，甚至还能再套一层虚拟化（嵌套虚拟化）。数据中心里绝大多数虚拟机都跑在 Type-1 hypervisor 上。

**Type-1 的内部也要分工**：Xen 一类采用「特权域（dom0）+ 普通域（domU）」的架构——一个特殊的客户域 dom0 负责管理真实的设备驱动，向其他域提供虚拟设备；普通客户域只跟虚拟设备打交道。这样物理驱动只需要写一份，放在 dom0 里，其余 VM 共享它。KVM 则把 hypervisor 直接做进 Linux 内核（成为内核的一个功能模块），客户 VM 就是 Linux 眼里的「特殊进程」。

## 3 Type-2 hypervisor：寄宿式

**Type-2 hypervisor（寄宿式 / hosted）**：作为一个普通应用程序运行在宿主操作系统之上，把宿主 OS 当作它的「硬件」来使用。

| 特性 | 说明 |
| --- | --- |
| 运行位置 | 宿主 OS 内的应用进程 |
| 典型代表 | VirtualBox、VMware Workstation、QEMU（纯软件模式） |
| 性能 | 较低，经过宿主 OS 间接访问硬件 |
| 使用场景 | 开发测试、个人电脑、教学 |

**Type-1 与 Type-2 的分界不是「能不能用」，而是「谁直接碰硬件」**：Type-1 自己碰，Type-2 借宿主的服务碰。<span class="marginnote">QEMU 比较特殊：单独运行时是 Type-2（纯软件模拟，很慢）；配合 KVM 使用时就变成 Type-1（KVM 是内核模块直接管硬件）。同一个软件，两种身份，见 Linux 专题《KVM 架构》。</span>

## 4 核心对比表：Type-1 与 Type-2

| 维度 | Type-1 裸金属 | Type-2 寄宿式 |
| --- | --- | --- |
| 底层依赖 | 直接管理硬件 | 依赖宿主 OS |
| 性能 | 高（接近物理机） | 低（多一层间接） |
| 故障波及 | 客户 OS 崩溃互不影响 | 宿主 OS 崩溃全部完蛋 |
| 部署成本 | 需要专用服务器 | 桌面装个软件即可 |
| 典型场景 | 云数据中心 | 开发、测试、学习 |
| 代表 | ESXi、Xen、Hyper-V | VirtualBox、Workstation |

**辨析｜易错点：** 「Type-2 比 Type-1 安全」是个常见错觉。实际上 Type-2 的客户 OS 与宿主 OS 共享一台机器的信任边界，宿主一旦被攻破，所有客户都暴露；Type-1 的每个 VM 在硬件层被隔离，安全性反而更可控。**性能与安全都指向 Type-1，Type-2 赢在「方便」二字。**

## 5 虚拟机的工作原理：如何让客户 OS 以为自己独占硬件

客户 OS 里运行着内核代码，它想执行特权指令（改页表、开关中断、读 CPU 状态），而这些指令在虚拟化环境下**不能被真的执行**——否则客户 OS 就能改写宿主的内存映射了。虚拟化处理这个问题经历了三代技术：

**陷阱与模拟（trap-and-emulate）**：让特权指令在执行时触发一个**陷阱（trap）**，把控制权交回 hypervisor，hypervisor 模拟这条指令的效果后再把控制权还回去。问题是：许多指令在非特权模式下并不触发陷阱，而是被静默忽略或产生错误结果，导致模拟不可靠。

**二进制翻译（binary translation）**：VMware 的早期方案，运行前把客户 OS 的敏感指令**扫描并替换**成一组调用 hypervisor 的等价指令序列，避免在运行时反复陷入。

**硬件辅助虚拟化（hardware-assisted virtualization）**：Intel VT-x / AMD-V 直接在 CPU 里加了虚拟化支持——CPU 有了「根模式」与「非根模式」两层特权，客户 OS 运行在非根模式下，敏感指令**自动**陷入 hypervisor，无需扫描也无需模拟。<span class="marginnote">硬件辅助虚拟化把「模拟敏感指令」的成本从软件搬进了 CPU 硬件，是现代虚拟化性能接近物理机（5% 以内损耗）的根本原因。这也解释了为什么近 20 年的 CPU 都带 VT-x/AMD-V——云计算的芯片级地基。</span>

三代技术是「模拟能力从软件走向硬件」的缩影：trap-and-emulate 是概念原型，二进制翻译是工程补丁，硬件辅助才是生产级答案。本节只讲到这里，指令级的细节在 Linux 专题《虚拟化基础》与《内存与 I/O 虚拟化》展开。

## 6 数值算例：虚拟化的「税」有多重

把上面的抽象对比落成数字，感受虚拟化的真实成本量级：

| 操作 | 开销量级 |
| --- | --- |
| 进程上下文切换 | ~1–5 µs |
| 虚拟机上下文切换（整客户 OS） | ~数十到上百 µs |
| 硬件辅助虚拟化性能损耗 | <5%（接近物理机） |
| 纯软件模拟（QEMU 无加速） | 慢 10~50 倍 |

**读这张表的三条结论**：其一，VM 是「大号进程」，切换它比切换线程贵一到两个数量级，所以云厂商倾向「一台机器固定跑几个 VM」而非频繁启停；其二，硬件辅助虚拟化把虚拟化损耗从「数量级」压到「个位数百分比」，这正是生产环境必用 KVM/Hyper-V 的原因；其三，纯软件模拟只适合「极轻量、一次性」的教学场景，跑真实负载会被它的税拖垮。<span class="marginnote">把这串数字和《系统调用》那篇的「模式切换税」放在一起看，会得到一个统一的认识：<strong>凡是「换一层上下文」都有税，设计系统就是在不同的税之间做取舍</strong>——线程的税最低所以并发用它，VM 的税最高所以能少切换就少切换。</span>

## 7 术语速查表

| 术语 | 含义 | 一句话记忆 |
| --- | --- | --- |
| 虚拟机 VM | 软件模拟出的完整「假硬件」 | 一台电脑里的另一台电脑 |
| 客户 OS | 跑在 VM 里的操作系统 | 以为自己独占硬件 |
| hypervisor | 虚拟机监控程序，虚拟化的核心 | 管「进程是整个 OS」的微内核 |
| Type-1 | 直接跑在硬件上的 hypervisor | 裸金属，数据中心主力 |
| Type-2 | 作为宿主 OS 应用的 hypervisor | 寄宿式，桌面方便 |
| trap-and-emulate | 用陷阱模拟特权指令 | 最早期的虚拟化思路 |
| 硬件辅助虚拟化 | CPU 内置虚拟化支持（VT-x/AMD-V） | 性能接近物理机的原因 |

## 8 小结

- **虚拟机**是软件模拟出的完整「假硬件」，可装可跑完整 OS。
- **hypervisor** 是虚拟化的核心，本质是一个「以 VM 为进程」的微型内核。
- **Type-1** 直接管硬件，性能与隔离最好，统治数据中心；**Type-2** 跑在宿主 OS 上，胜在方便，用于开发与学习。
- QEMU 兼有两种身份：纯软件是 Type-2，配合 KVM 变 Type-1。
- 虚拟化是「把硬件抽象成资源」思想的最高形态，是云计算的基石。
