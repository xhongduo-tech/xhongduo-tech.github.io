## 为什么从空闲空间管理开始

文件分配方法决定「文件块放哪」，但系统得先知道「哪些块是空的」。**空闲空间管理（free-space management）**维护「空闲块清单」——分配时从中取块，释放时把块还回去。它是文件系统吞吐与可靠性的隐形关键，也对应着内存管理里「空闲块链表/位图」的姊妹篇。<span class="marginnote">回顾内存管理的空闲管理：伙伴系统、位图、链表。文件系统的空闲管理几乎复刻了这些方案——<strong>「空闲资源怎么记账」在内存与磁盘上是同一个问题</strong>，只是规模与持久性不同。</span>

## 1 位图：每个块一个位

**位图（bitmap / bit vector）**：一块独立的区域，每个磁盘块对应**一个位**——1 表示已分配，0 表示空闲（或反之）。

```
位图： 1 0 0 1 1 0 1 1 ...
      ↑↑↑ ↑ ↑↑ ↑ ↑
     块0 1 2 3 4 5 6 7 ...（1=已用，0=空闲）
```

**优点**：

- **空间极省**：1 块（4KB）位图能管理 4KB×8 = 32K 块 = 128MB 磁盘——开销 1/32768。
- **连续分配查找快**：找连续空闲块 = 在位图里找连续 0——**容易找到「连续的空闲区」**，支持连续分配与「尽量连续」的优化。
- 实现简单（位运算）。

**缺点**：

- **内存占用随磁盘线性增长**：大磁盘的位图要占不少内存（1TB 磁盘位图约 32MB，可缓存但大）。
- 位图需**持久化**（存磁盘），分配/释放要更新位图并刷盘。

**位图是现代文件系统的主流**：ext4、XFS 都用位图（或位图 + 日志）管理块组内的空闲块。它的「找连续区」能力与「按块组组织」天然契合。

## 2 空闲链表：把空闲块串起来

**空闲链表（free list）**：用**链表**把所有空闲块串起来——每个空闲块存一个指向下一个空闲块的指针。

- 分配一块：取链表头，更新头指针。
- 释放一块：把块插回链表头。

**优点**：内存占用极小（只在空闲块里存指针，无独立表）。

**缺点**：

- **不能高效找连续区**：链表上的空闲块可能分散，找「连续空闲块」要遍历。
- **碎片化**：反复分配释放后，空闲块分散，分配出的文件块不连续（顺序读慢）。
- 指针在数据块内，块被分配时要擦除指针。

**FAT 式的空闲管理**：不把指针放块内，而用 FAT 表（空闲块表项值为 -1 或特殊标记）串空闲块——FAT 文件系统同时用 FAT 管「文件链」与「空闲链」。

## 3 成组链接：Unix 的折中方案

**成组链接（grouping）**：Unix 系统 V 采用的方案——**把空闲块指针分组存放**：

- **空闲盘块栈**：一个「栈」保存一组空闲块号；栈顶存「下一组空闲块号所在块」的指针。
- 分配时从栈顶取块；栈空时，读下一组空闲块指针块，继续。

```
空闲块栈：
  [块号1][块号2]...[块号49][指向下一组的块号]
    └─ 当前空闲块组 ─┘   └─ 下一组指针
```

**优点**：**兼顾「取块快」（从内存栈直接取）与「开销小」（指针分组存放，不是每块一个指针）**。

**成组链接 vs 位图 vs 链表**：

| 方案 | 空间开销 | 找连续区 | 分配速度 |
| --- | --- | --- | --- |
| 位图 | 小（1/32768） | **好** | 快（位运算） |
| 空闲链表 | 极小 | 差 | 快（取头） |
| 成组链接 | 小（分组指针） | 中 | 快（栈取） |

**辨析｜易错点：** 「空闲链表 = FAT 文件系统的空闲管理」不准确——**FAT 文件系统用 FAT 表同时表达「文件块链」与「空闲块链」，不是独立链表**。而位图与成组链接是独立于文件结构的空闲管理。**「文件的数据结构」与「空闲空间的数据结构」是两个独立话题**，别混在一起。

## 4 现代实践与细节

现代文件系统（ext4、XFS）的实践：

- **按块组管理**：磁盘分成多个**块组（block group）**，每组一个位图——位图小、可缓存、组内就近分配（保证文件块尽量连续）。
- **组内优先分配**：新文件优先在**同一块组**内分配，文件块靠得近 → 顺序读快（回顾磁盘性能的「顺序 I/O 快」）。
- **与日志配合**：位图的更新要走日志（见《日志文件系统》），崩溃时能恢复一致。

**公式解析：位图的内存占用**

位图大小（字节）与磁盘大小的关系：

$$\text{位图字节数} = \frac{\text{磁盘块数}}{8} = \frac{\text{磁盘字节数}}{8 \times \text{块大小}}$$

- **磁盘块数**：磁盘总块数。
- 每块 1 位，8 块占 1 字节。
- 1TB 磁盘、4KB 块：位图 $= 1\text{TB}/(8\times4\text{KB}) = 32\text{MB}$。

**直觉**：位图把「空闲信息」压缩到块数的 1/8 字节——开销是磁盘的 1/32768，可接受；但 32MB 也要合理缓存与分块管理，这正是块组设计的动机。

## 5 小结

- 空闲空间管理三方案：**位图**（每块一位）、**空闲链表**（块内指针串链）、**成组链接**（分组指针栈）。
- **位图**空间省、找连续区好，是现代主流（ext4 按块组位图）。
- 空闲链表内存极小但难找连续区、易碎片化。
- **成组链接**是 Unix 的折中：栈取块快、指针分组省空间。
- 现代实践：**块组 + 位图 + 组内就近分配 + 日志配合**，兼顾速度与连续性。
