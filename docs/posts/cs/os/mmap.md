## 为什么从 mmap 开始

虚拟内存的页可以来自交换区，也可以来自**文件**——把文件的某段直接映射进进程的地址空间，进程读那个地址就等于读文件。**内存映射文件（memory-mapped file）**统一了「内存」与「文件」两个世界：`mmap()` 是它的系统调用入口。这是理解共享库加载、进程间共享内存、数据库缓冲池的钥匙。<span class="marginnote">回顾虚拟内存：页按需调入。mmap 把「磁盘上的文件」当作「虚拟内存的后备存储」——访问映射的地址即触发缺页，从文件调入对应页。<strong>文件与内存从此共享同一套分页机制</strong>。</span>

## 1 mmap 的基本机制

**内存映射文件（memory-mapped file）**：把文件的若干字节映射到进程地址空间的某段区域，进程通过读写这段内存来读写文件。

```c
#include <sys/mman.h>

void *p = mmap(NULL, length,                 // 地址（NULL 让内核选）、映射长度
               PROT_READ | PROT_WRITE,       // 保护：可读、可写
               MAP_SHARED,                   // 标志：共享映射
               fd, 0);                       // 文件描述符、文件偏移
// 之后读写 p[0..length-1] 就等价于读写文件
```

**读文件**：进程读映射地址（如 `p[0]`）→ 若对应页不在内存 → **缺页** → 内核从文件调入该页 → 正常读。**写文件**：进程写同一映射地址 → 修改的是内存页 → 页被标脏 → 由内核**写回**到文件（`msync()` 强制或惰性回写）。

**mmap 的三要素**：

**长度 length**：映射多少字节。
**标志 flags**：`MAP_SHARED`（共享，写回文件）vs `MAP_PRIVATE`（私有，写时复制）。
**保护 PROT**：`PROT_READ`/`PROT_WRITE`/`PROT_EXEC`（只读/写/执行权限）。

**结束映射与强制写回**：映射关系用 `munmap(p, length)` 解除；`msync(p, length, MS_SYNC)` 把脏页同步写回文件（对 `MAP_SHARED` 才有效）。<span class="marginnote">`mmap` 失败返回 `MAP_FAILED`（即 `(void *) -1`），不是 `NULL`——用 `if (p == MAP_FAILED)` 判断错误。这个细节常被写坏，也是不少面试题的陷阱。</span>注意 `munmap` 与 `close(fd)` 的顺序：映射一旦建立，`fd` 可以立刻关闭，映射仍然有效——文件对象已被页缓存接管。

## 2 MAP_SHARED vs MAP_PRIVATE：两种语义

**MAP_SHARED（共享映射）**：

多个进程映射同一文件同一段 → 共享同一物理页。
一个进程的写，其他进程**可见**，最终**写回文件**。
用途：进程间共享内存（IPC）、多进程协作更新同一文件。

**MAP_PRIVATE（私有映射）**：

进程「以为」自己独享映射，实际初始共享文件的页。
写时：触发 **COW**（写时复制）——复制页、改副本，**不影响文件、不影响其他进程**。
用途：加载可执行文件/共享库（`ld.so` 加载时把代码段只读映射、数据段私有映射）。

**辨析｜易错点：** 「MAP_PRIVATE 的修改会写回文件」是误解。**MAP_PRIVATE 的写是 COW 副本上的写，永远不写回原文件**——这正是「私有」的含义。反过来，**MAP_SHARED 的修改会写回文件**（最终会），这也是它的名字含义。**两个标志决定「写是否落到文件」与「写是否影响他进程」。**<span class="marginnote">对照《写时复制》：`fork()` 的共享页 + MAP_PRIVATE 的映射页都是 COW 的应用。Linux 里每个可执行文件用 `mmap` 映射——代码段只读共享、数据段私有 COW。<strong>一个 `mmap` 调用同时用到了「只读共享」与「写时复制」两种虚拟内存机制。</strong></span>

## 3 mmap 与 read/write 的对比

传统文件 I/O（`read`/`write`）：

- 数据路径：文件 → 内核页缓存 → **拷贝到用户缓冲区**（两次拷贝：内核↔用户）。
- 每次 `read`/`write` 都是一次系统调用 + 一次拷贝。

mmap 文件 I/O：

- 数据路径：文件 → 内核页缓存 → **用户地址空间直接映射**（零拷贝——用户访问的就是页缓存）。
- 没有「内核↔用户」的显式拷贝。

**mmap 的优势**：

- **零拷贝**：省去用户缓冲区的中间拷贝（大文件场景收益显著）。
- **随机访问高效**：像数组一样任意定位，不需要 `lseek`。
- **共享**：多进程映射同一文件共享页。

**mmap 的劣势**：

- **小文件不划算**：映射建立/拆除有开销，小文件直接 `read`/`write` 更简单。
- **页对齐浪费**：映射长度按页取整，可能浪费半页。
- **内存占用**：映射页占虚拟地址空间（虽然物理页按需调入）。

**设计启示**：mmap 的「零拷贝 + 按需分页」是高性能文件处理的基石——数据库缓冲池、`malloc` 的大块内存分配、共享库加载、容器镜像的分层文件系统，全都在用 mmap。

## 4 核心对比表：mmap vs 传统 read/write

| 维度 | read/write | mmap |
| --- | --- | --- |
| 数据路径 | 内核页缓存 → 用户缓冲（拷贝） | 用户地址空间直映页缓存（零拷贝） |
| 系统调用 | 每次 read/write 一次 | 映射一次，之后纯访存 |
| 随机访问 | 需 lseek | 直接下标 |
| 共享 | 不支持（除非额外 IPC） | MAP_SHARED 天然共享 |
| 适用 | 小文件、流式 | 大文件、随机访问、共享 |

## 5 数值算例：映射 10 KB 文件要占多少地址空间

页表以页为单位管理虚拟地址，因此 **mmap 的长度与偏移都必须按页取整**。设页面大小 $P = 4096$ 字节，要映射一个 $S = 10000$ 字节的文件，内核为该映射保留的虚拟地址空间是

$$N \cdot P = \left\lceil \frac{S}{P} \right\rceil \cdot P = \left\lceil \frac{10000}{4096} \right\rceil \cdot 4096 = 3 \times 4096 = 12288\ \text{字节}$$

第 3 页真正用到的只有 $12288 - 10000 = 2288$ 字节，剩下 $1808$ 字节被「浪费」。反过来，若文件只有 100 字节，映射仍要占满一页 4096 字节，浪费率高达 $1 - 100/4096 \approx 97.6\%$——这就是「小文件用 mmap 不划算」的数量级直觉：固定开销吃掉了全部收益。<span class="marginnote">同理，`offset` 参数必须是页的整数倍，否则 `mmap` 直接返回 `EINVAL`。想映射「文件第 100 字节起的区域」，只能先页对齐映射，再用 `p + 100` 访问——多出的对齐偏移靠指针补偿。</span>

**偏移对齐的完整手法**：设目标偏移为 $\text{off}$，取 `aligned = off & ~(P-1)`（向下取整到页边界），`extra = off - aligned`，然后

```c
size_t P = sysconf(_SC_PAGESIZE);            // 4096
char *p = mmap(NULL, extra + length, PROT_READ, MAP_PRIVATE, fd, aligned);
char *data = p + extra;                       // data 才是真正要用的起点
```

这套「页对齐 + 指针补偿」在每个文件型数据库、每个序列化加载器里都会出现。

## 6 术语速查表

| 术语 | 含义 | 一句话记忆 |
| --- | --- | --- |
| `mmap` | 把文件段映射进地址空间 | 文件变内存 |
| `MAP_SHARED` | 共享映射，写回文件 | 我改你见、落盘 |
| `MAP_PRIVATE` | 私有映射，写时复制 | 我改你看不见、不落盘 |
| `COW` | 写时复制 | 写的那一刻才复制 |
| `msync` | 强制脏页写回 | 手动落盘 |
| `munmap` | 解除映射 | 内存里拆除文件 |
| `MAP_FAILED` | 映射失败返回值 | 是 `-1` 不是 `NULL` |

## 7 小结

- **mmap**：把文件映射进地址空间，读写内存 = 读写文件。
- 访问映射页触发**缺页从文件调入**；写脏页由内核**写回文件**。
- **MAP_SHARED**：写可见、写回文件（共享内存 IPC）；**MAP_PRIVATE**：COW，写不影响文件。
- mmap **零拷贝**、随机访问高效、天然支持共享——大文件与共享场景的利器。
- 应用遍布：共享库加载、数据库缓冲池、`malloc` 大块、容器分层镜像。
