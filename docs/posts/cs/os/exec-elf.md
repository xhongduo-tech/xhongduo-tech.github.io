## 为什么从 exec 与 ELF 开始

fork 创建了「空壳进程」，`exec` 把可执行文件加载进来、替换进程的地址空间——**「创建进程」与「运行新程序」在 Unix 中是两步**。这一节看 exec 家族的执行流程，以及 Linux 可执行文件的格式 **ELF** 的内部结构。<span class="marginnote">回顾《fork/vfork/clone》：fork 管「创建」，exec 管「换程序」。exec 成功后不返回——进程的代码、数据、栈全被替换，只有 PID、打开的文件（除非 close-on-exec）保留。<strong>exec 是「换灵魂」，不是「换身体」。</strong></span>

## 1 exec 家族

**exec 家族**：一组功能相同、参数形式不同的系统调用封装：

| 函数 | 程序路径 | 参数形式 |
| --- | --- | --- |
| `execl` | 显式指定 | 参数列表 |
| `execv` | 显式指定 | 参数数组 |
| `execlp` | 靠 PATH 搜索 | 参数列表 |
| `execvp` | 靠 PATH 搜索 | 参数数组 |
| `execve` | 显式指定（**真正的系统调用**） | 参数数组 + 环境 |

**exec 的行为**：

1. 校验权限、格式。
2. **加载可执行文件**：把 ELF 的各段映射进地址空间（mmap）。
3. 设置**新的栈**（含 argv、envp）。
4. 跳转到**入口点**（ELF 头的 `e_entry`），开始执行。

**exec 的保留**：PID 不变、**已打开且未设 `FD_CLOEXEC` 的文件描述符保留**、进程信号处理重置。

**辨析｜易错点：** 「exec 创建新进程」是误解。**exec 不创建进程——它替换当前进程的映像**。fork 创建进程，exec 换程序，两者必须配合（先 fork 再 exec）。**exec 成功后原进程的代码不再存在**——这就是「exec 成功不返回」的原因（返回就说明 exec 失败了）。

## 2 ELF 格式：可执行文件的地图

**ELF（Executable and Linkable Format）**：Linux 可执行文件、目标文件、共享库的统一格式。

**ELF 文件结构**：

```
┌─────────────────────────────┐
│ ELF 头（魔数、类型、入口点）  │
├─────────────────────────────┤
│ 程序头表（段视图，加载用）   │
├─────────────────────────────┤
│ .text    代码段              │
│ .rodata  只读数据            │
│ .data    已初始化数据        │
│ .bss     未初始化数据（零填） │
├─────────────────────────────┤
│ 节头表（节视图，链接用）     │
└─────────────────────────────┘
```

**两类视图**：

- **节（section）视图**：链接时用（`.text`、`.data`、`.bss`、符号表…）。
- **段（segment）视图**：加载时用（把节合并成段，mmap 进内存）。

**ELF 头关键字段**：

- **魔数**：`\x7fELF`——标识 ELF 格式。
- **类型**：ET_EXEC（可执行）、ET_DYN（共享库/位置无关）、ET_REL（可重定位）。
- **入口点（entry point）**：程序开始执行的地址。
- **程序头表**：段的信息（虚拟地址、大小、权限）。

## 3 程序加载：ELF 如何变成进程

内核加载 ELF 的过程（`load_elf_binary`）：

1. 校验 ELF 头（魔数、类型）。
2. 读**程序头表**，对每个段：
   - 用 **mmap** 把段映射进进程地址空间（代码段只读、数据段读写）。
   - 处理权限（NX 位：数据段不可执行——回顾《缓冲区溢出》的防御）。
3. **BSS 段**（未初始化数据）映射为零填充区域。
4. 建立初始栈（压入 argv、envp、辅助向量）。
5. 跳转入口点执行。

**动态链接**：若 ELF 需要共享库（`.so`），内核先加载**动态链接器**（`ld-linux.so`），由它加载依赖库、重定位，最后跳转程序入口（回顾《链接与装入》的动态链接）。

**公式解析：ELF 段的映射权限**

每个段有权限位（读/写/执行），映射时设 MMU 保护：

$$\text{段权限} = \text{读} + \text{写} + \text{执行} \quad (\text{每段不同组合})$$

- **.text（代码）**：读 + 执行——**不可写**（代码段不能被修改，也防注入）。
- **.data（数据）**：读 + 写——**不可执行**（数据段不能跑代码，防 shellcode）。
- **.rodata（只读数据）**：只读。

**直觉**：ELF 段的权限映射是「**W^X（写与执行互斥）**」的实现——**可写的页不可执行，可执行的页不可写**。这是防御缓冲区溢出（NX 位）在 ELF 层的落地：即使攻击者把代码写进数据段，CPU 也拒绝执行。

**辨析｜易错点：** 「ELF = 可执行文件」是窄化。**ELF 是「可执行 + 可链接」格式**——它同时服务**链接器**（节视图）与**加载器**（段视图），`.o` 目标文件、`.so` 共享库、可执行程序都是 ELF。**同一个格式，三种用途**——这是 ELF 设计的高明之处。

## 4 核心对比表：节 vs 段

| 维度 | 节（section） | 段（segment） |
| --- | --- | --- |
| 谁用 | 链接器 | 加载器 |
| 组织 | 按用途（.text/.data/.bss） | 按加载（合并节成段） |
| 权限 | 无（链接期概念） | 有（读/写/执行） |
| 是否 mmap | 否 | 是 |

## 5 小结

- **exec 家族**：`execl`/`execv`/`execlp`/`execvp`，真正系统调用是 `execve`。
- exec **替换进程映像**（代码、数据、栈），PID 与部分 fd 保留，成功不返回。
- **ELF** 统一可执行/目标/共享库三种格式；**节视图**（链接）与**段视图**（加载）。
- 加载流程：ELF 头 → 程序头表 → mmap 段（带权限）→ 建栈 → 入口点。
- 段权限实现 **W^X**——可写不可执行，可执行不可写，防代码注入。
