## 为什么从缓冲区溢出开始

如果说木马/病毒是「外来的恶意」，那**缓冲区溢出（buffer overflow）**是「程序自身的漏洞被利用」——它是最经典、最普遍的程序安全漏洞。攻击者喂给程序一段超长输入，让它**溢出缓冲区、改写内存中的关键数据（返回地址）**，从而劫持程序执行任意代码。理解它，等于理解为什么现代系统要加地址空间随机化、栈保护、NX 位。<span class="marginnote">回顾《程序威胁》：溢出攻击属于「程序漏洞被利用」——程序本身有 bug（不检查边界），攻击者利用 bug 植入恶意代码。它是「安全威胁」与「程序正确性」的交界：<strong>没有边界的复制，就是漏洞的温床。</strong></span>

## 1 溢出如何发生

**缓冲区溢出（buffer overflow）**：向缓冲区写入的数据**超过了缓冲区的容量**，多余数据溢出到相邻内存区域，覆盖了不该覆盖的数据。

```c
void vulnerable(char *input) {
    char buf[64];
    strcpy(buf, input);   // 不检查长度！input 超过 64 字节就溢出
}
```

`strcpy` 不检查目标缓冲区大小——若 `input` 长于 64 字节，多余数据溢出 `buf`，覆盖栈上**相邻的内存**——包括**返回地址**（函数返回时要跳回去的地址）。

**攻击者的手法**：

1. 构造超长输入：前半部分是**恶意代码（shellcode）**，末尾是**精心选择的地址**。
2. 输入溢出栈缓冲区 → 覆盖**返回地址**为 shellcode 的地址。
3. 函数返回时，CPU 跳转到 shellcode → **执行攻击者的代码**（通常是启动一个 shell）。

**关键**：攻击者**不需要程序授权**——只要输入能触发溢出，就能让程序（以它的权限）执行任意代码。

## 2 为什么栈会被攻击：栈布局

理解攻击需要看**栈的内存布局**（回顾进程组成：栈向下增长）：

```
高地址： [函数参数]
          [返回地址]    ← 攻击目标：覆盖这里
          [保存的帧指针]
          [局部变量 buf] ← 溢出从这里开始（写入 buf 溢向高地址）
低地址：
```

- 局部变量 `buf` 在栈上，**返回地址在 buf 的高地址侧**。
- `strcpy(buf, input)` 从 `buf` 开始往高地址写——**写超长时恰好越过 buf，一路覆盖到返回地址**。
- 攻击者把返回地址改成 shellcode 的地址，函数返回时就被劫持。

**公式解析：溢出需要的输入长度**

设缓冲区大小 $B$，缓冲区起始到返回地址的偏移为 $O$（含帧指针、对齐等），攻击输入结构：

$$\text{攻击输入} = \underbrace{\text{shellcode}}_{S \text{ 字节}} + \underbrace{\text{填充}}_{O - S \text{ 字节}} + \underbrace{\text{返回地址}}_{4/8 \text{ 字节}}$$

$$\text{输入总长} = O + 4 \text{（或 } 8\text{）} > B$$

- 只要输入总长超过 $B$，就会溢出；超过 $O$ 就能碰到返回地址。
- **攻击的要点**：知道 $O$（栈布局偏移）与 shellcode 地址。

## 3 经典防御：现代系统的四道防线

**① 边界检查（bounds checking）**：使用检查长度的函数（`strncpy`、`memcpy_s`）或安全语言（Rust 自动检查）——**从源头杜绝溢出**。

**② 栈保护（stack canary）**：在返回地址前放一个**金丝雀值（canary）**——函数返回前检查它是否被改动；被改则中止程序。

- canary 是随机值，攻击者不知道它，覆盖返回地址时必然破坏 canary → 检测到 → 终止。

**③ NX 位（数据不可执行）**：把**栈/数据段标为不可执行**——shellcode 放在栈上也执行不了（CPU 拒绝执行数据段的代码）。

- 攻击者无法直接在栈上执行 shellcode → 需改用「返回导向编程（ROP）」等复杂技巧（更难）。

**④ 地址空间布局随机化（ASLR）**：随机化**栈、堆、库的加载地址**——攻击者不知道 shellcode 在哪，无法构造正确的跳转地址。

**四道防线组合**：边界检查防溢出、canary 防改返回地址、NX 防执行 shellcode、ASLR 防定位地址——**纵深防御层层设卡**。

**辨析｜易错点：** 「NX 和 ASLR 能完全防住溢出」是过度乐观。**NX 让直接执行 shellcode 失效，攻击者改用 ROP（重用已有代码片段拼出攻击）**；ASLR 让地址不可预测，但信息泄露（leak）可绕过。**现代攻击与防御是「道高一尺、魔高一丈」的军备竞赛**——但四道防线把攻击门槛提高了几个量级。

## 4 核心对比表：四道防线

| 防线 | 防什么 | 原理 |
| --- | --- | --- |
| 边界检查 | 溢出发生 | 拷贝前检查长度 |
| 栈 canary | 返回地址被改 | 返回前校验金丝雀 |
| NX 位 | 栈上执行代码 | 数据段不可执行 |
| ASLR | 定位 shellcode/ROP | 地址随机化 |

**设计启示**：缓冲区溢出教训的升华是——**「不信任输入」**。任何外部输入都可能被构造，程序必须假设输入恶意：检查边界、验证长度、用安全函数。现代语言（Rust、Go）在语言层面解决这个问题，而 C/C++ 需要程序员自觉 + 编译器工具（`-fstack-protector`、ASLR 由内核启用）。

## 5 小结

- **缓冲区溢出**：超长输入溢出缓冲区，覆盖返回地址，劫持控制流。
- 攻击原理：栈上 `buf` 溢出 → 覆盖返回地址 → 跳转 shellcode。
- 经典攻击输入 = shellcode + 填充 + 伪造返回地址。
- 四道防线：**边界检查、栈 canary、NX 位、ASLR**。
- 防御哲学：**不信任输入 + 纵深防御**；安全语言从源头解决。
