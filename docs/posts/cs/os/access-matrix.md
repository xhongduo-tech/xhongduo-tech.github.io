## 为什么从访问矩阵开始

保护域定义「进程能碰什么」，但「能碰什么」怎么记录、怎么检查？**访问控制矩阵（access matrix）**给出统一模型：**行是主体（进程/域），列是对象（文件/设备/内存），单元格是权限集合**。它是所有访问控制机制（ACL、能力表）的统一理论基础。这一节把矩阵讲透，并看它的两种实现——**按列（ACL）与按行（能力表）**。<span class="marginnote">回顾《文件保护》：ACL 是「对象维度」的权限表。访问矩阵把视野扩到「所有主体 × 所有对象」——ACL 只是矩阵的按列存储，能力表是矩阵的按行存储。一张矩阵，两种投影。</span>

## 1 访问矩阵的定义

**访问控制矩阵（access control matrix）**：二维表，**行 = 主体（domain）**，**列 = 对象（object）**，单元格 $Access[i][j]$ = 主体 $i$ 对对象 $j$ 的**权限集合**。

| 主体＼对象 | file.txt | printer | 内存段X |
| --- | --- | --- | --- |
| 域 A | read, write | print | read |
| 域 B | read | — | — |
| 域 C | — | print | read, write |

- 单元格为空的 = 无任何权限（不可访问）。
- 每次访问检查：主体 $i$ 请求访问对象 $j$ 的权限 $r$ → 查 $Access[i][j]$ 是否含 $r$。

**矩阵的三个要素**：**主体（谁）、对象（对什么）、权限（能做什么）**——访问控制的一切都是这三要素的组合。

## 2 矩阵的两种实现：ACL 与能力表

矩阵是「逻辑模型」，实现时按存储视角分两种：

**按列组织 → 访问控制列表（ACL）**：每个**对象**维护一张「谁对我有什么权限」的列表。

```
file.txt 的 ACL：
  [域A: read, write]
  [域B: read]
```

- 检查「域 A 读 file.txt」：查 file.txt 的 ACL 里有没有「域 A: read」。
- **适合「对象多、主体相对固定」**：文件保护（每文件一张 ACL）。
- **缺点**：主体多时，检查要扫列表（或哈希）。

**按行组织 → 能力表（capability list）**：每个**主体**维护一张「我能对什么有什么权限」的列表——每一项是一个**能力（capability）**。

```
域 A 的能力表：
  [file.txt: read, write]
  [printer: print]
  [内存段X: read]
```

- 检查「域 A 读 file.txt」：看域 A 的能力表里有没有「file.txt: read」。
- **适合「主体权限动态变化」**：进程带着自己的能力走。
- **能力即令牌**：能力本身是一个「不可伪造的令牌」——持有能力就能访问（类 Unix 的 capability、能力指针）。

**辨析｜易错点：** 「ACL 和能力表是两种不同的东西」——**它们是同一张访问矩阵的两种存储方式**：ACL 按列（对象为中心），能力表按行（主体为中心）。**ACL 问「这个对象谁能碰」**（对象视角），**能力表问「这个主体能碰什么」**（主体视角）。<span class="marginnote">两种视角各有适合场景：ACL 适合「以资源为中心」的管理（文件、数据库表——查「谁有权碰这个资源」）；能力表适合「以进程为中心」的授权（进程拿着能力跑，切换域 = 换能力表）。<strong>现代系统常常两者并用</strong>：文件系统用 ACL，进程特权用 capability。</span>

## 3 矩阵的扩展：复制与所有权

访问矩阵还定义了权限的**转移机制**：

- **所有权（owner）**：对象的创建者是 owner，可授予/撤销其他主体的权限。
- **复制（copy）**：权限可以带「复制标志」——持有者可把自己的权限复制给其他主体。

**复制传播**：

```
域 A 拥有 file 的 read*（* = 可复制）
  → A 把 read* 复制给 域 B
  → B 也能读 file，并继续复制
```

**复制的控制**：不带 `*` 的权限不能传播——**限制「权限的传播」是防止权限无限扩散的关键**（与最小特权呼应）。

## 4 核心对比表：ACL vs 能力表

| 维度 | ACL（按列） | 能力表（按行） |
| --- | --- | --- |
| 中心 | 对象 | 主体 |
| 记录 | 对象 → 谁有权限 | 主体 → 能碰什么 |
| 撤销权限 | 容易（改对象 ACL） | 难（要收回所有能力令牌） |
| 检查方式 | 查对象列表 | 查主体列表 |
| 典型应用 | 文件系统、数据库 | 进程能力、分布式令牌 |

**设计启示**：ACL 与能力表是「**以对象为中心 vs 以主体为中心**」的两种管理哲学——ACL 好管理（资源集中授权），能力表好授权（权限跟着主体走）。**撤销的难度**是两者的关键差异：ACL 撤销容易（改一处），能力表撤销难（要全网回收令牌）。

## 5 小结

- **访问控制矩阵**：主体 × 对象 × 权限的二维模型——访问控制的理论骨架。
- **ACL（按列）**：对象为中心的权限表——文件保护的标准实现。
- **能力表（按行）**：主体为中心的能力令牌——进程特权的实现。
- 两者是同一矩阵的两种投影，常并用。
- 矩阵支持**所有权**与**复制**——复制传播需限制（最小特权）。
