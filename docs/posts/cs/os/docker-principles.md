## 为什么从 Docker 原理开始

前几节把容器的「零件」讲完——Namespace、cgroup、Mount/Network。这一节把它们**组装成 Docker**：**镜像**（分层的文件系统模板）、**联合文件系统**（层叠文件）、**容器运行时**（把镜像 + Namespace + cgroup 实例化成运行中的容器）。这是容器专题的「总装」。<span class="marginnote">回顾容器三件套：Namespace（视图隔离）+ cgroup（资源配额）+ rootfs（根文件系统）。Docker 的价值在于<strong>把这三件套工程化</strong>——镜像解决「rootfs 怎么分发」，联合文件系统解决「分层怎么省空间」，运行时解决「容器怎么启动」。</span>

## 1 镜像（Image）：分层的模板

**镜像（image）**：容器运行所需的**文件系统快照 + 元数据**——一个只读的模板。**镜像由多层（layer）组成**，每层是一次构建的改动。

```
镜像（如 ubuntu:22.04）：
  Layer 4：CMD/ENTRYPOINT（配置层）
  Layer 3：apt install 的改动（应用层）
  Layer 2：apt update 的改动（系统层）
  Layer 1：基础文件系统（ubuntu rootfs）
```

**分层的好处**：

- **复用**：多个镜像共享底层（都基于 ubuntu）——**只存一份，不重复下载**。
- **增量**：改动只产生新层，不重做全部。
- **分发**：Docker 镜像仓库按层分发，拉取只拉缺的层。

**镜像 vs 容器**：

- **镜像**：只读模板（静态）。
- **容器**：镜像 + 可写层 + 运行中的进程（动态）——**容器是镜像的实例**。

**镜像的构建**：**Dockerfile** 的每条指令（`RUN`、`COPY`、`ENV`）产生**一层**。

## 2 联合文件系统（OverlayFS）：层叠的魔法

**联合文件系统（UnionFS）**：把**多个目录（层）叠加**成一个统一视图的机制。Docker 的 OverlayFS 是核心实现。

**OverlayFS 的结构**：

- **lowerdir（低层）**：只读的镜像层（多层叠加）。
- **upperdir（上层）**：容器的**可写层**（空，记录容器的修改）。
- **merged（合并视图）**：叠加后的统一文件系统——容器看到的 `/`。

```
OverlayFS 视图：
  lowerdir（只读镜像层）:  /bin、/lib、/etc...
  upperdir（可写层）:      （容器修改写入这里）
  merged:                  容器看到的完整 /
```

**写入时的行为（copy-up）**：

- 容器**修改**镜像层里的文件：OverlayFS 把该文件**从 lowerdir 拷贝到 upperdir**，再修改——**镜像层不被改动**（COW 思想！回顾《写时复制》）。
- 容器**删除**镜像层文件：在 upperdir 写一个「白名单（whiteout）」标记隐藏它。

**OverlayFS 与 COW**：**「读共享、写时拷贝」正是写时复制的机制**——**多个容器共享同一镜像层，各自的修改互不影响**。这就是「一个镜像能跑无数容器、互不干扰」的实现。

**公式解析：镜像分层的空间节省**

设 $N$ 个容器共享底层 $S$ 字节、各自可写层 $W_i$：

$$\text{总磁盘} = S + \sum_{i=1}^{N} W_i \quad \text{（而非 } N \cdot S \text{）}$$

- 无分层：N 个容器各存完整 rootfs = $N \cdot S$。
- 分层共享：底层只存一份 $S$，各容器只存可写层 $W_i$——**空间从「每容器一份」降到「共享一份 + 各写各的」**。

**直觉**：联合文件系统把「N 个容器的磁盘开销」从「N 份完整系统」降到「1 份共享 + N 份增量」——**这是容器能大量创建的成本基础**（回顾虚拟机的完整磁盘镜像）。

**辨析｜易错点：** 「容器修改镜像层」是误解。**容器的修改永远在可写层（upperdir），镜像层（lowerdir）只读不可改**——这正是 OverlayFS 的 COW 设计。**「镜像不可变」是容器可靠性的基础**：镜像一旦构建，内容确定（除非显式重建）。**「容器退出，修改即丢（除非挂载卷）」的根源也是这个——可写层随容器销毁。**

## 3 容器运行时（Runtime）：把镜像变成进程

**容器运行时（container runtime）**：负责把镜像实例化成运行中的容器的软件。

**容器的创建流程（运行时做四件事）**：

1. **准备 rootfs**：用 OverlayFS 挂载镜像层 + 可写层，`pivot_root` 到合并视图（Mount Namespace）。
2. **创建 Namespace**：`clone` 带六个 Namespace 标志——PID/Network/UTS/IPC/Mount/User（回顾《Namespace》）。
3. **配置 cgroup**：把容器进程加入 cgroup，设置 CPU/内存限制（回顾《cgroup》）。
4. **启动进程**：执行镜像的 CMD/ENTRYPOINT——容器开始运行。

**运行时分层**：

- **高层运行时**：Docker Engine、containerd——镜像管理、API、编排。
- **底层运行时**：runc——真正创建/运行容器的工具（OCI 标准）。

**OCI 标准**：容器规范由 **Open Container Initiative（OCI）** 定义——镜像格式、运行时规范统一，Docker、Podman、Kubernetes 的容器都遵循它。

## 4 核心对比表：镜像 vs 容器 vs 运行时

| 概念 | 是什么 | 生命周期 |
| --- | --- | --- |
| 镜像 | 只读分层模板 | 持久（构建后不变） |
| 容器 | 镜像 + 可写层 + 进程 | 临时（创建→运行→销毁） |
| 运行时 | 实例化镜像的工具 | 常驻服务 |

**设计启示**：Docker 的三大发明——**分层镜像（分发与复用）、联合文件系统（空间与 COW）、OCI 运行时（标准化）**——本质是「**用分层与标准把环境打包成可复制的商品**」。这彻底改变了软件分发：**「在我的机器上能跑」变成了「在任何有容器的机器上都能跑」**（云原生、K8s 的基础）。

## 5 小结

- **镜像** = 分层只读模板（Layer 叠加）；**容器** = 镜像 + 可写层 + 进程。
- **联合文件系统（OverlayFS）**：lowerdir（只读镜像）+ upperdir（可写层）+ merged 视图。
- 写时 **copy-up**（COW）——容器修改不影响镜像层；删除用 whiteout。
- **运行时**：rootfs 挂载 + Namespace + cgroup + 启动进程（runc 是底层运行时）。
- 分层 + COW + OCI 标准 = 容器「轻量、可复用、可分发」的基础。
