## 为什么从内存保护开始

动态运行时装入给了进程「移动与共享」的自由，但自由必须配上边界：**一个进程的越界访问，绝不能写进另一个进程的地盘**。基址寄存器与界限寄存器是最朴素也最经典的内存保护方案——它们定义了「这个进程能用哪一段物理内存」，越界即中断。这一节是理解所有内存保护（分页保护、段保护、权限位）的起点。<span class="marginnote">回顾《逻辑地址与物理地址》：重定位寄存器把逻辑地址翻译成物理地址。保护是翻译的「安全检查」——不仅要翻译得对，还要检查「翻译出来的地址在不在该进程的合法范围内」。</span>

## 1 两个寄存器的分工

**基址寄存器（base register）**：存放进程在物理内存中的**起始地址**（基址）。

**界限寄存器（limit register）**：存放进程可用地址空间的**大小/上界**。

进程的合法物理地址范围是：

$$[\text{base}, \text{base} + \text{limit})$$

即从基址开始，连续 limit 个字节。任何地址翻译与检查都在这两个寄存器配合下完成：

```
逻辑地址 LA
  │
  ▼
[检查 LA < limit ？]
  │ 是（合法）              否（越界）→ 触发陷阱/中断，进程被杀
  ▼
物理地址 PA = base + LA
```

**检查逻辑地址 LA 是否 < limit，而不是检查物理地址**——因为 limit 以逻辑地址空间的尺寸定义。如果 LA ≥ limit，说明逻辑地址越界，访问非法。

## 2 保护如何生效：两段式检查

一次访存的两步：

1. **越界检查**：CPU 硬件把逻辑地址与 `limit` 比较——LA ≥ limit 则发出**地址越界陷阱（trap）**，操作系统终止该进程。
2. **翻译**：合法地址 `base + LA` 送物理内存。

**关键：检查与翻译都由硬件完成（MMU），不是软件**——因为每次访存都要检查，软件检查太慢。硬件比较在访存流水线里完成，几乎零开销。<span class="marginnote">「保护靠硬件」是操作系统安全模型的根基：用户进程无法绕过 MMU 的检查（MMU 由内核配置），所以进程再恶意也越不过它的 base/limit 边界。这与《保护与安全》篇的「用户态不能执行特权指令」互相配合——权限的边界是硬件强制的。</span>

**辨析｜易错点：** 「检查物理地址是否在 base 到 base+limit 之间」是常见表述错误。**正确做法是检查逻辑地址 LA < limit，再翻译成物理地址**。为什么？因为越界的是「逻辑地址」，逻辑地址超限说明程序访问了「自己的地址空间之外」——至于物理地址是否越界，在翻译前根本无从谈起。**保护的判据在逻辑层，不在物理层。**

## 3 为什么说这是「最简单」的保护

基址+界限是**连续分配**时代的保护方案——每个进程占一段连续物理内存，base/limit 就是这段的边界。它的局限很明显：

- **只能保护「一块连续区间」**：进程装在哪，边界就是哪。
- **无法细粒度保护**：进程内「代码段只读、数据段可写」这种细分做不到——整个区间要么都可访问。
- **内部碎片**：进程的区间按最大需求划分，实际用不满，浪费。

更精细的保护（逐页保护、逐段保护）需要分页/分段——但「硬件检查越界 + 越界即中断」这个**核心机制**，是分页/分段保护共用的骨架。<span class="marginnote">base/limit 模型的价值不在「现代性」而在「原理性」：它清晰展示了内存保护的三要素——边界定义（base+limit）、硬件检查、越界处置（陷阱）。你后面学分页的「页表 + 有效位」、分段的「段长 + 段界」，会发现都是这三要素的变体。</span>

## 4 核心对比表：三种保护粒度

| 维度 | base/limit | 分页保护 | 分段保护 |
| --- | --- | --- | --- |
| 保护单元 | 整块连续区间 | 页（固定大小） | 段（逻辑单元） |
| 粒度 | 粗 | 中 | 细（每段可有权限） |
| 代码只读/数据可写 | 做不到 | 每页可设 | 每段可设 |
| 实现复杂度 | 最低 | 中 | 中高 |
| 现代使用 | 教学/最简 | Linux/Windows | 已并入分页体系 |

## 5 小结

- **基址寄存器**（进程起始地址）+ **界限寄存器**（地址空间大小）定义进程的合法内存区间 $[\text{base}, \text{base}+\text{limit})$。
- 每次访存：**先查 LA < limit**，越界即陷阱终止进程，再翻译 `base + LA`。
- 检查与翻译**由硬件 MMU 完成**，几乎零开销，进程无法绕过。
- 局限：只保护一块连续区间、粒度粗、有内部碎片。
- 「边界定义 + 硬件检查 + 越界处置」三要素是分页/分段保护共用的骨架。
