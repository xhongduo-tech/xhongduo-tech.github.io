## 为什么从文件保护开始

共享的前提是「允许谁」，但也必须「拒绝谁」——**文件保护（protection）**决定谁可以对文件做什么。多用户系统里，一个用户的文件不能被另一个用户随意读写。文件保护机制从 Unix 的三元组（owner/group/other）到细粒度的 ACL，是安全模型的基础。<span class="marginnote">回顾《文件共享》：共享讲「谁能访问」，保护讲「谁能以什么方式访问」。保护与第十四篇《保护与安全》直接呼应——文件访问控制是访问控制矩阵（access matrix）最经典的应用场景。</span>

## 1 访问权限的类型

文件保护要裁决的**访问权限（access rights）**：

| 权限 | 含义 |
| --- | --- |
| 读（read） | 读取文件内容 |
| 写（write） | 修改文件内容 |
| 执行（execute） | 作为程序运行 |
| 追加（append） | 只能在末尾添加 |
| 删除（delete） | 删除文件 |
| 列目录（list） | 列出目录内容（对目录） |

**权限的组合**：不同用户对同一文件可有不同权限组合——「owner 可读写、group 可读、other 不可访问」就是最常见的组合。

## 2 Unix 的简单保护：三元组

**Unix 权限模型**：对每个文件，按三类主体分别设权限——**属主（owner）、组（group）、其他（other）**，每类三位的 rwx（读/写/执行）。

```
$ ls -l report.txt
-rw-r--r--  1 alice staff  1024 Aug  7 12:00 report.txt
```

- 9 个权限位 = 3 类主体 × 3 种权限。
- 例：`rw-r--r--`——owner 可读写、group 只读、other 只读。

**优点**：实现极简（9 个位）、表达紧凑。**缺点**：粒度粗——**只能区分「三类人」，不能精确到单个用户**。一个文件想给「张三读、李四写、其他人不可见」，三元组做不到。

## 3 访问控制列表 ACL：细粒度的答案

**访问控制列表（ACL, Access Control List）**：每个文件维护一张**列表**，列出「哪个用户/组 → 什么权限」。

```
$ getfacl report.txt
# file: report.txt
# owner: alice
# group: staff
user::rw-
user:bob:r--
group::r--
mask::r--
other::---
```

- **粒度细**：可精确到每个用户、每个组。
- **顺序匹配**：访问时从表头开始匹配主体，命中最具体的条目。
- 现代 Linux 文件系统（ext4 等）支持 **POSIX ACL**——在传统三元组之上扩展出「命名用户」「命名组」条目。

**ACL 的代价**：每文件一张表，存储与维护开销比 9 位权限大；访问检查比「查 3 位」复杂。

**辨析｜易错点：** 「ACL 完全取代 Unix 权限」是误解。**现代系统是「ACL + 传统权限」共存**——传统三元组是「默认/兜底」，ACL 是「细粒度扩展」。`ls -l` 看到传统权限，`getfacl` 看到 ACL 条目；改 ACL 时传统位也会相应变化。**ACL 是叠加层，不是替代品。**

## 4 公式解析：访问控制矩阵

把「保护」看成一个矩阵——**访问控制矩阵（access control matrix）**：行是**主体**（用户/进程），列是**对象**（文件/资源），单元格是**权限集合**：

| 主体＼对象 | file.txt | dir/ | printer |
| --- | --- | --- | --- |
| alice | rw- | rwx | — |
| bob | r-- | r-x | print |
| root | rwx | rwx | print |

**访问矩阵的两种实现**（第十四篇会细讲）：

- **按列组织 → 访问控制列表（ACL）**：每列（对象）列出「谁能对它做什么」——**文件保护采用这种**。
- **按行组织 → 能力表（capability list）**：每行（主体）列出「我能碰什么」——用于授权令牌。

**直觉**：访问矩阵是「主体 × 对象」的二维表。**文件保护按列存（ACL），主体授权按行存（能力表）**——同一张矩阵，两种存储视角，对应两种安全模型的哲学。

**保护原则**：**最小特权（least privilege）**——每个主体只获得完成工作所需的最少权限。ACL 的细粒度正是为了支撑最小特权（如只给某人读、不给写）。

## 5 核心对比表：Unix 权限 vs ACL

| 维度 | Unix 三元组 | ACL |
| --- | --- | --- |
| 粒度 | 三类主体 | 任意用户/组 |
| 存储 | 9 位 | 每文件列表 |
| 精细度 | 粗 | **细** |
| 检查复杂度 | O(1) | O(列表长度) |
| 典型 | 所有 Unix | ext4、Windows NTFS、macOS |
| 关系 | 基础/兜底 | 叠加扩展 |

## 6 小结

- 文件保护裁决**谁可以以什么方式访问**：读、写、执行、追加、删除等。
- **Unix 三元组**（owner/group/other × rwx）实现极简但粒度粗。
- **ACL** 用「每文件列表」实现细粒度控制，可精确到用户/组。
- **访问控制矩阵**：主体 × 对象；**按列存 → ACL，按行存 → 能力表**。
- 现代系统 **ACL + 传统权限共存**，ACL 是叠加扩展；原则是**最小特权**。
