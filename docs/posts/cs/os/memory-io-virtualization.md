## 为什么从内存与 I/O 虚拟化开始

KVM 解决了 CPU 虚拟化，但内存与 I/O 是另外两座山：**客户 OS 的页表翻译需要二次翻译（影子页表/EPT），设备的共享需要虚拟化（virtio/设备直通）**。这一节把虚拟化的「内存」与「I/O」两条腿讲透——它们是「虚拟机快不快」的决定因素。<span class="marginnote">回顾《分页》：客户 OS 用页表把「客户虚拟地址 GVA」翻译成「客户物理地址 GPA」。问题来了——<strong>GPA 不是真物理地址（HPA）</strong>，hypervisor 还要再翻一次。<strong>「两级地址翻译」是内存虚拟化的核心难题</strong>，影子页表与 EPT 是两种解法。</span>

## 1 内存虚拟化：两级地址翻译

客户机里有两级地址：

- **GVA（客户虚拟地址）** → **GPA（客户物理地址）**：客户 OS 的页表负责。
- **GPA** → **HPA（宿主机物理地址）**：hypervisor 负责。

**客户 OS 以为自己掌控物理内存（GPA），实际 GPA 是 hypervisor 映射出来的**——访问内存要经过两级翻译。

**解法一：影子页表（shadow page table）**：

- hypervisor 为每个客户进程维护一张**影子页表**：直接 **GVA → HPA**（合并两级翻译）。
- 客户改页表时，hypervisor 截获并**重算影子页表**。
- **优点**：访存时只查一级（快）；**缺点**：客户每次改页表都要**截获+重算**（VMEXIT 频繁），且每进程一张影子表（内存开销）。

**解法二：EPT（Extended Page Tables，Intel）/ NPT（AMD）**：

- **硬件支持两级页表**：客户页表翻译 GVA→GPA，**EPT 硬件再翻译 GPA→HPA**——两级都由硬件完成。
- **优点**：客户改页表**不需截获**（硬件自动处理）——**VMEXIT 大幅减少**；性能接近原生。
- **缺点**：访存多查一级（有 TLB 加速，几乎无感）；需要 CPU 支持（VT-x 的 EPT）。

**公式解析：影子页表 vs EPT 的 VMEXIT**

设客户每改一次页表触发一次处理：

$$\text{影子页表 VMEXIT 次数} = \text{页表修改次数}$$

$$\text{EPT VMEXIT 次数} = 0 \quad \text{（硬件自动翻译）}$$

- 影子页表：**每次客户改页表都要 VMEXIT**（进 hypervisor 重算）。
- EPT：**硬件直接处理两级翻译**，客户改页表不打扰 hypervisor。
- **EPT 把「频繁的页表修改」从「每次截获」变成「零介入」**——这是现代虚拟化接近原生性能的关键。

**直觉**：**影子页表是「软件合并两级翻译」，EPT 是「硬件支持两级翻译」**——后者把工作从「每次截获」变成「硬件自动」。（对照《虚拟化基础》：「软件难题用硬件做掉」的又一例。）

## 2 I/O 虚拟化：三条路线

客户机的 I/O 如何访问真实设备？三条路线：

**① 纯软件模拟（QEMU 模拟）**：

- QEMU 完全模拟设备（虚拟网卡、虚拟磁盘）。
- **优点**：兼容好（客户不需要特殊驱动）。
- **缺点**：**慢**——每次 I/O 要 VMEXIT + QEMU 模拟 + 再进真设备。

**② virtio（半虚拟化设备）**：

- 客户安装 **virtio 驱动**（配合），与 QEMU 通过**共享环形队列**通信。
- **优点**：**快**——数据经共享队列批量传输，减少 VMEXIT 与拷贝。
- **缺点**：客户要装 virtio 驱动（Linux 已内置，Windows 要装）。

**virtio 的核心机制**：

- 客户与宿主机**共享一块内存队列**（virtqueue）。
- 客户把 I/O 请求写入队列，**kick（踢一脚，写通知寄存器）**宿主机；宿主机处理完写回结果，**中断通知**客户。
- **批量 + 共享内存 + 减少退出**——半虚拟化的现代实现（回顾《虚拟化基础》的半虚拟化思想）。

**③ 设备直通（device passthrough / SR-IOV）**：

- 把**真实物理设备直接分配给客户机**——客户直接操作设备硬件，不经 QEMU。
- **优点**：**性能接近原生**（无虚拟化开销）。
- **缺点**：设备被独占（不能共享给其他客户）；需要 IOMMU（I/O Memory Management Unit）做 DMA 隔离。

**三条路线的性能谱**：纯模拟 < virtio < 设备直通（性能递增、灵活性递减）。

**辨析｜易错点：** 「virtio 是设备」是混淆。**virtio 是「设备接口标准」**（一组半虚拟化设备规范：virtio-net、virtio-blk），不是具体硬件——它定义「客户驱动」与「宿主机后端」如何通过共享队列通信。**「virtio 快」的本质是「用共享内存队列 + 批量 I/O 减少虚拟化开销」，不是「设备变快」。**

## 3 核心对比表：I/O 虚拟化的三条路线

| 维度 | 纯模拟 | virtio | 设备直通 |
| --- | --- | --- | --- |
| 客户驱动 | 无（模拟） | virtio 驱动 | 真实设备驱动 |
| 数据路径 | QEMU 模拟 | 共享队列 | **直接访问设备** |
| 性能 | 低 | 中高 | **最高** |
| 设备共享 | 可共享 | 可共享 | **独占** |
| 典型 | 兼容优先 | **生产默认** | 高性能（网卡/GPU） |

**设计启示**：I/O 虚拟化的三条路线是「**性能 vs 灵活性**」的光谱——纯模拟最灵活最慢，直通最快但独占，virtio 站中间（共享 + 快）。生产虚拟化（云）的标准是 **virtio（磁盘/网络）+ 必要时直通（GPU/高速网卡）**。

## 5 小结

- **内存虚拟化**：两级翻译（GVA→GPA→HPA）。
- **影子页表**：软件合并翻译，客户改页表要 VMEXIT——慢。
- **EPT/NPT**：硬件支持两级页表，客户改页表零介入——**接近原生**。
- **I/O 虚拟化三路线**：纯模拟（慢）、**virtio**（共享队列、半虚拟化、生产默认）、设备直通（最快、独占）。
- virtio = 共享内存队列 + 批量 I/O + 减少 VMEXIT——半虚拟化思想的现代实现。
