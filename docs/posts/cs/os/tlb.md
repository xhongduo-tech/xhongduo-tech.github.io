# 快表 TLB：加速地址转换的硬件机制

## 为什么从 TLB 开始

分页解决了碎片，却带来一个性能危机：**每次访存都要查页表，而页表在内存里——查页表又是一次访存**。原本一次访存变成两次，性能几近腰斩。**快表（TLB）**是 CPU 里的一个小型高速缓存，专门缓存「最近的页号 → 页框号」映射，让绝大多数地址转换在 CPU 内部完成，不再访问内存。这一节看 TLB 的工作原理与命中率分析。<span class="marginnote">回顾《分页》的两次访存：一次查页表、一次读数据。TLB 是「缓存页表项」的硬件结构，本质是「页表这个主存的缓存」——它让「查页表」这一步大多数时候变成 CPU 内部的寄存器查找。</span>

## 1 TLB 的结构与查找

**快表（TLB, Translation Look-aside Buffer）**：MMU 内部的一个小型关联存储器（associative cache），存放「页号 → 页框号」的键值对。典型大小几十到几千项（如 64~4096 项）。

地址转换流程（带 TLB）：

1. 从逻辑地址拆出页号 p 与偏移 d。
2. **先在 TLB 里找 p**：
   - **TLB 命中（hit）**：直接得到页框号 f，物理地址 = f×页大小 + d，**一次访存完成**。
   - **TLB 未命中（miss）**：去内存查页表，得到 f，同时把「p → f」写进 TLB（供下次命中），再访存数据——**两次访存**。
3. TLB 满时，用替换策略（LRU 等）淘汰旧项。

**核心目标：让命中率尽量接近 100%**——命中率决定了分页的实际性能。

## 2 有效访问时间（EAT）

**有效访问时间（EAT, Effective Access Time）**：考虑命中与未命中的平均单次访存时间：

$$\text{EAT} = (1 + \epsilon) \cdot a \cdot \text{命中率} + (2 + \epsilon) \cdot a \cdot \text{未命中率}$$

简化为经典公式（设 TLB 查找时间 $\epsilon$、内存访问时间 $a$、命中率 $h$）：

$$\text{EAT} = (1 + \epsilon) a \cdot h + (2 + \epsilon) a \cdot (1 - h)$$

展开即：

$$\text{EAT} = a(2 - h) + \epsilon$$

**公式解析：命中率如何决定性能**

- **$a$**：一次内存访问时间。
- **$\epsilon$**：TLB 查找时间（远小于 $a$，纳秒级）。
- **$h$**：TLB 命中率。
- **命中时总耗时**：$\epsilon + a$（TLB 查完 + 一次访存）。
- **未命中时总耗时**：$\epsilon + 2a$（TLB 查完 + 查页表 + 访数据）。

代入示例：$a = 100\text{ns}$，$\epsilon = 20\text{ns}$，$h = 0.9$：

$$\text{EAT} = 100 \times (2 - 0.9) + 20 = 130\text{ns}$$

若没有 TLB（$h=0$），EAT $= 220\text{ns}$；若 $h = 0.99$，EAT $\approx 121\text{ns}$。**命中率从 90% 提到 99%，EAT 只降 9ns——命中率在 90% 以上时，TLB 已经接近「翻译免费」；命中率掉到 80% 以下，性能显著恶化。**<span class="marginnote">TLB 的命中率依赖<strong>局部性原理</strong>：程序短时间内反复访问同一批页（代码循环、栈、热数据），这些页的映射留在 TLB 里，命中率自然高。这就是《虚拟内存》里局部性原理在硬件缓存层面的一次提前演示。</span>

## 3 TLB 与上下文切换：进程切换的隐藏成本

**TLB 是进程私有缓存**——每个进程的页表不同，TLB 里缓存的是「当前进程」的映射。进程切换时：

- **方案一（清空 TLB）**：切换进程就清空 TLB。简单，但新进程首次访问全部未命中，性能骤降。
- **方案二（带地址空间标识符 ASID）**：TLB 表项带上「属于哪个进程」的标识，切换进程时不用清空，靠 ASID 区分。现代 CPU（x86、ARM）都支持 ASID。

**这也解释了为什么上下文切换贵**——不仅换寄存器，还可能换 TLB（见《进程上下文切换》）。进程切换频繁，TLB 命中率就低；所以**调度器减少切换频率，也等于保护 TLB 命中率**。<span class="marginnote">「上下文切换清 TLB」是隐藏成本的大头：切换后新进程的首次访存全部 miss，要重新填 TLB。这反过来证明了「处理器亲和性」（让进程留在同一核）的价值——不换核，TLB 里的映射就还在。</span>

## 4 核心对比表：TLB 命中 vs 未命中

| 维度 | TLB 命中 | TLB 未命中 |
| --- | --- | --- |
| 访存次数 | 1 | 2 |
| 耗时 | $\epsilon + a$ | $\epsilon + 2a$ |
| 是否更新 TLB | 否 | 是（写入映射） |
| 触发替换 | 否 | 满时淘汰旧项 |
| 频率 | 高（~99%） | 低（~1%） |

**辨析｜易错点：** 「TLB 是页表的一部分」是误解。**TLB 是页表的「缓存」，不是页表本身**——页表完整存在于内存，TLB 只缓存最近用到的表项。两者关系如同「L1 缓存 vs 主存」。另一个易错点：**「TLB 命中 = 不需要页表」**——页表永远在内存里，TLB 只是让多数查找不必碰它；未命中时仍要查页表，并把结果写回 TLB。

## 5 小结

- **TLB** 是 MMU 内部缓存「页号→页框号」映射的硬件，让地址转换大多不访内存。
- 命中一次访存，未命中两次访存；命中率 $h$ 决定性能。
- **EAT** $= a(2-h) + \epsilon$：命中率 90%+ 时翻译近乎免费，低于 80% 性能恶化。
- TLB 是进程私有；进程切换可清空（方案一）或带 **ASID** 区分（方案二）。
- TLB 依赖**局部性原理**，上下文切换是 TLB 命中率的最大敌人。
