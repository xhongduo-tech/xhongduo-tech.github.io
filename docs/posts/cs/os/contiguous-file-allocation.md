## 为什么从文件分配开始

文件的数据块在磁盘上怎么排？**文件分配方法（allocation methods）**决定了「文件的逻辑块 → 物理块」的映射方式，直接影响访问速度、空间利用与文件扩展性。三种经典方法——**连续、链接、索引**——各有优劣。这一节看**连续分配**：最简单，也最受「碎片」与「无法增长」之苦。<span class="marginnote">回顾《内存管理》的连续分配：进程要求连续内存，产生碎片。文件系统的连续分配是同一思想在磁盘上的复刻——文件要求连续磁盘块，同样面临碎片与增长问题。<strong>历史在内存与磁盘上重演了一遍。</strong></span>

## 1 连续分配的定义

**连续分配（contiguous allocation）**：文件占用的磁盘块是**连续的**——从某个起始块开始，连续 N 块。

**inode/FCB 只需记录两个字段**：

- **起始块号（start block）**
- **文件长度（length，块数）**

```
磁盘：
[块0][块1][块2][块3][块4][块5][块6][块7]...
       └─── 文件 A（块1~3，start=1, len=3）───┘
```

**优点**：

- **顺序读极快**：块连续，磁头几乎不寻道，接近磁盘传输率（回顾磁盘性能：顺序 I/O 快百倍）。
- **实现与寻址最简**：FCB 只需两个字段；随机访问 $O(1)$——逻辑块 $i$ 的物理块 = 起始块 + $i$。
- **直接访问方便**：`lseek` 到第 i 块 = 起始 + i，一步到位。

## 2 连续分配的致命缺点

**缺点一：外部碎片**。

文件被分配后，磁盘被切成大小不一的已分配区与空闲区——新文件要装进「连续的空闲区」，若没有足够大的连续空闲块就装不下，即使空闲总量够（回顾《动态分区》的外部碎片）。

**缺点二：无法增长（文件扩展难）**。

文件创建后要增长（追加数据）——但文件两侧可能已被其他文件占据，没有连续空间可扩展。解决办法：

- 创建时**预留最大空间**（预分配）——浪费，且未必预知大小。
- 文件满了就**迁移**（整个复制到更大的连续区）——昂贵，与内存的「紧凑」同病相怜。

**辨析｜易错点：** 「连续分配 = 最快，所以最好」——顺序读确实最快，但**写场景（创建、追加、修改大小）被碎片与扩展问题拖垮**。现实中几乎没有现代文件系统用纯连续分配——文件大小动态变化、频繁创建删除，连续分配撑不住。

## 3 公式解析：连续分配的空间浪费

连续分配下，新文件需要「一块大小 ≥ 文件大小」的连续空闲区。最坏情况的外部碎片浪费：

设空闲块分散成 $k$ 段，各段大小为 $s_1, s_2, \ldots, s_k$，空闲总量 $S = \sum s_i$。若文件需要 $s$ 块且 $s \le S$，但**每一段都 < s**，文件仍无法分配——浪费了全部 $S$ 块中的可用空间。

- **外部碎片率**：无法利用的碎片比例可能很高，且**随着文件的创建与删除不断恶化**。
- 需要**紧凑（compaction）**或**碎片整理（defrag）**来归并空闲区（回忆内存的紧凑）。

**对比链接分配**：链接分配只需要「单个空闲块」就能装文件，外部碎片几乎消失（只剩小块碎块）。**连续分配用「连续性」换速度，代价是「碎片 + 无法增长」**——这正是链接分配登场的原因。

## 4 核心对比表：连续分配的评价

| 维度 | 连续分配表现 |
| --- | --- |
| 顺序读 | 最快（接近传输率） |
| 随机访问 | O(1)（起始 + i） |
| 创建文件 | 需找连续空闲区，可能失败 |
| 文件增长 | 难（无连续空间则迁移/预留） |
| 外部碎片 | 严重 |
| 现代使用 | 几乎不用（教学/极简系统） |

**设计启示**：连续分配的价值在于它揭示了「**顺序 I/O 快**」这一物理优势——现代文件系统虽然不用纯连续分配，却通过「**尽量让文件的块在磁盘上连续**」（ext4 的块组、日志的预分配）来保留这个优势。**「让块尽量连续」是现代文件系统性能优化的核心目标之一。**

## 5 小结

- **连续分配**：文件占连续磁盘块，FCB 只存**起始块 + 长度**。
- 优点：**顺序读最快、随机访问 O(1)、实现最简**。
- 缺点：**外部碎片严重、文件无法方便增长**（预留或迁移）。
- 对比内存的连续分配：同样的「连续性换速度、碎片换增长」权衡。
- 现代文件系统追求「**块尽量连续**」以保留顺序 I/O 优势，但用其他分配方法实现。
