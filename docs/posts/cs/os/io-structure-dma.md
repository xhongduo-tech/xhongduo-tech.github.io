## 为什么从输入输出结构开始

中断解决了「CPU 不用死等设备」，但还没解决「数据搬运的成本」：中断驱动方式下，设备每准备好一个字节就中断一次，CPU 要把数据从控制器寄存器搬进主存。设备一快，中断就会像暴风雨一样把 CPU 淹没——还记得上一篇的公式 $U = rc/f$ 吗？设备速率 $r$ 一上去，CPU 占用率就压不住。**直接存储器访问（direct memory access，DMA）**把「搬数据」这件苦差事从 CPU 手里外包给专门的硬件，让 CPU 只管发起和收尾。这是 I/O 结构里最重要的一次分工，也是理解一切高吞吐设备（NVMe SSD、万兆网卡、GPU）的前提。

## 1 设备控制器：CPU 与设备之间的代理

再回看《计算机系统组成与硬件结构》的设定：CPU 不直接操作设备，每类设备挂着一个**设备控制器（device controller）**。控制器内部有一组寄存器，是 CPU 与设备通信的窗口：

- **状态寄存器**：设备忙不忙、上次操作成功与否。
- **命令寄存器**：CPU 写「做什么」——读、写、复位。
- **数据寄存器**：数据进出的中转站。

寄存器组的窄与慢，决定了 I/O 的效率天花板：数据寄存器一次只有几个字节，逐字节搬运时，CPU 每搬一次都要跟设备控制器握手一次。这正是把搬运外包给 DMA 的直接动机——带宽再大的设备，如果每一步都等 CPU 亲手搬，速度上限就被 CPU 卡死了。

换句话说，控制器的寄存器是「硬件写给软件的 API」：驱动读状态、写命令、搬数据，而这一切都发生在中断与 DMA 的框架之内。

**核心概念**：**设备驱动程序（device driver）**：内核中与特定控制器寄存器打交道的代码，向上对操作系统提供统一接口，向下读写各控制器的寄存器。<span class="marginnote">驱动是把「千奇百怪的硬件」翻译成「统一接口」的那层胶水。Linux 把设备抽象成文件，<code>open/read/write/ioctl</code> 一套系统调用操作一切设备——这个统一抽象正是第十五篇《系统调用》与第十三篇《I/O 系统》的主线。</span>

## 2 三种 I/O 控制方式：从亲自问到底层代办

设备与主存之间搬运数据，历史上先后出现三种方式，恰好是 CPU 参与度递减的三档。

**方式一：程序轮询（polling）。** CPU 反复读状态寄存器，等设备就绪后逐字节搬运。实现最简单，但等待期间 CPU 全程空转。<span class="marginnote">轮询并没有绝迹：等待时间极短的设备（寄存器握手）或需要极致低延迟的路径（DPDK 收包、virtio 高吞吐）反而偏爱它，因为省掉了中断的开销。关键判断是「等多久」：等待比一次中断还快，就轮询；否则就中断。</span>

**方式二：中断驱动（interrupt-driven I/O）。** 设备就绪后发中断，CPU 在中断处理程序里把数据从控制器寄存器搬进主存（每字节一次中断）。CPU 不再空等，但每个字节都要「切进切出」一次，中断频繁时开销巨大。

**方式三：DMA。** 专门的 **DMA 控制器（DMA controller）** 在设备与主存之间直接搬运整块数据，搬完才打断 CPU 一次。CPU 只在开头配置、结尾收账，中间全程自由。<span class="marginnote">注意 DMA 的「D」是 direct——它直接访问主存，不经过 CPU 逐字节搬移。把 DMA 误读成「搬运全交给设备、CPU 彻底不管」是常见误区：启动、地址设置、传输收尾仍由 CPU 经驱动完成，DMA 外包的是「搬运过程」而非「管理职责」。</span>

**重点：三种方式是 CPU 参与度递减的三档——轮询是 CPU 亲自等、亲自搬；中断驱动是 CPU 被通知后亲自搬；DMA 是 CPU 只管两头，中间整块搬运交给专门硬件。**

三种方式的适用边界可以用一句话记住：**等得越久、量越大，越该把工作往硬件推。** 慢速单字节粒度的设备（键盘）用中断驱动足够；高速大批量的设备（磁盘、网卡）必须 DMA；而等待时间比一次中断还短的寄存器握手，轮询反而更省。现代系统甚至在同一台设备上混合使用——Linux 网卡驱动（NAPI）先轮询一会儿，没等到包再用中断兜底，既躲开中断风暴，又不至于忙等。

## 3 DMA 的工作过程：一次传输的逐步拆解

以「把磁盘一整个扇区读进主存」为例，DMA 的完整过程分五步，配图如下：

1. **CPU 初始化 DMA 控制器**：驱动把三个关键参数写入 DMA 控制器——内存起始地址、传输字节数、传输方向（读还是写）。
2. **CPU 命令设备开始传输**：设备控制器收到命令后开始产生数据；DMA 控制器接管后续搬运，CPU 立刻可以去执行其他程序。<span class="marginnote">「CPU 发起 I/O 后立即返回」正是异步 I/O 的雏形：程序发出请求后被挂起，等 DMA 完成中断再来唤醒。操作系统里同步 / 异步、阻塞 / 非阻塞的完整分类，是第十七篇《I/O 模型》的主题。</span>
3. **DMA 控制器搬运数据**：数据沿「设备 → DMA 控制器 → 主存」（或反向）整块流动，每传一个字节就更新内部计数。
4. **传输完成，发一次中断**：字节计数归零，DMA 控制器向 CPU 发一个完成中断。
5. **CPU 收尾**：中断处理程序确认传输完成，唤醒等待这次 I/O 的进程。

![DMA：数据搬运绕开 CPU](/images/os/io-structure-dma-1.svg)

**辨析｜易错点：** DMA 搬运期间，CPU 依然要访问主存才能取指、取数据，两者都会占用总线，所以 DMA 与 CPU 会**竞争内存带宽**。当 DMA 占满总线，CPU 的访存会被拖慢，这称为「周期窃取（cycle stealing）」。现代系统用更快的内存总线与缓存一致性协议缓解，但「DMA 不是免费的」必须记牢。

下面是一段简化的驱动伪代码，展示 CPU 侧「发起」的写法：

```c
/* 读取磁盘一扇区到内存（简化） */
dma->memory_addr = buf;        /* ① 内存起始地址        */
dma->byte_count  = 512;        /* ② 传输字节数（一扇区） */
dma->direction   = READ;       /* ③ 方向：设备 → 内存   */
disk->cmd        = CMD_READ;   /* ④ 命令设备开始        */
/* 此后 CPU 返回继续工作；传输完成由④步的中断通知      */
```

注意第④行：命令设备之后，CPU 立刻返回——它既没有等待，也没有参与搬运。**「发起后立即返回、完成后被中断唤醒」，正是异步 I/O 的雏形。**

## 4 公式解析：DMA 比中断驱动省在哪

把两种方式的 CPU 开销算一笔账。设一次要传输 $S$ 字节，设备速率 $R$ 字节/秒：

- **中断驱动**：每字节中断一次，共 $S$ 次；设每次中断处理要 $t_b$ 秒，则 CPU 花费 $S \cdot t_b$。
- **DMA**：每 $K$ 字节一块，共 $S/K$ 次中断；设每次收尾处理要 $t_k$ 秒，则 CPU 花费 $(S/K) \cdot t_k$。

$$
T_{\text{中断}} = S \cdot t_b, \qquad T_{\text{DMA}} = \frac{S}{K} \cdot t_k
$$

逐步拆解：

- **第一步，抓关键差**：中断驱动按「字节」付账，DMA 按「块」付账——搬运粒度不同，中断次数差一个 $K$ 倍。
- **第二步，代数量级**：设 $S = 1$ MB，块大小 $K = 1024$ B，$t_b = 1\ \mu$s，$t_k = 2\ \mu$s（DMA 收尾略贵）：
  - 中断驱动：$T = 10^6 \times 1\ \mu\text{s} = 1$ 秒。
  - DMA：$T = \dfrac{10^6}{1024} \times 2\ \mu\text{s} \approx 2$ 毫秒。
- **第三步，读结论**：同一笔传输，CPU 的花费从 1 秒降到 2 毫秒——**约 500 倍的差距**。更要紧的是：中断驱动的 1 秒是 CPU 在中断里「切进切出」地被耗掉；而 DMA 的 2 毫秒只是「收账」，中间整块数据搬运期间 CPU 完全可以算别的事情。

**重点：DMA 的价值不在「省多少毫秒」，而在「把 CPU 从搬运工的位子上解放出来」。** NVMe SSD、千兆网卡动辄 GB/s 级速率，若逐字节中断，CPU 早就被淹没——DMA 正是这些设备能跑满速率的物理前提。

再补一个极端例子感受量级：一块 NVMe SSD 顺序读约 7 GB/s，逐字节中断的话每秒要处理 70 亿次中断，任何 CPU 都会瞬间崩溃；按 4 KB 一块做 DMA，每秒约需 175 万次中断，仍然偏多——于是现代驱动再把多块合并成一次中断（中断合并、MSI-X 多队列）。量级就是设计的分水岭。

## 5 I/O 结构的全景：CPU、DMA 与缓存的三角关系

把前几篇的部件拼起来看 I/O 全景：

- 设备 → 设备控制器 → 系统总线 → 主存；DMA 控制器是这条路上的「搬运工」。
- CPU 通过驱动读写控制器寄存器发起 I/O；设备 / DMA 通过中断通知 CPU。
- 现代 CPU 有缓存（Cache），DMA 直接写主存可能让缓存里的旧副本失效——这就是**缓存一致性**问题：DMA 写完后，CPU 缓存中对应地址的旧数据必须作废或更新。<span class="marginnote">x86 靠总线窥探（snooping）协议维护一致性：DMA 写入时，总线上的缓存控制器会观察到并作废对应缓存行。这套机制在《计算机组成原理》与第六篇《进程同步》的多处理器一致性中展开；驱动侧常用 <code>dma_alloc_coherent</code> 分配「一致内存」来绕开这个问题。</span>

DMA 在现代系统里还有更激进的形态：多队列 DMA 直接把数据写入用户态缓冲区、配合内存映射实现**零拷贝（zero-copy）**——网卡把收到的包直接放进应用程序的页框，内核只负责通知，数据全程不经过内核缓冲。第十八篇《虚拟化与容器》里 virtio 的队列模型、第十七篇《epoll 与 io_uring》的异步 I/O，本质都是 DMA 思想的延伸：让数据尽量少经过 CPU，让 CPU 只处理「决定」而不是「搬运」。

一句话总结 I/O 结构的设计哲学：**让最慢的部件（设备）与最快的部件（CPU）互不拖累——慢的一头用控制器异步准备，快的一头用 DMA 外包搬运，中间用中断汇报进度。**

## 6 小结

- 设备通过**设备控制器**接入系统；驱动是读写控制器寄存器的代码；三种 I/O 方式——**轮询、中断驱动、DMA**——是 CPU 参与度递减的三档。
- DMA 用专门的 **DMA 控制器**在设备与主存间整块搬运，CPU 只做「发起」与「收尾」。
- DMA 五步：配置 DMA 控制器 → 命令设备 → 硬件搬运 → 完成中断 → CPU 收尾。
- DMA 按块付账、中断驱动按字节付账：$T_{\text{DMA}} = (S/K)\,t_k$，大块传输可省两三个数量级。
- DMA 不是免费的：与 CPU 争用总线（周期窃取），还要处理**缓存一致性**。
- 现代 DMA 形态：多队列、中断合并、零拷贝——让数据尽量少经过 CPU。
