## 为什么从调度基本概念开始

前面的章节确立了进程与线程，但还没回答一个最实际的问题：**就绪队列里排着十个进程，先让谁上 CPU？** 这就是**CPU 调度（CPU scheduling）**。调度算法是操作系统的「交通指挥」，它的每一个决定都影响用户体感的快慢。这一篇先打地基：了解进程的「突发」模型、调度发生的时机、以及判断调度好坏的标准。<span class="marginnote">回顾《进程状态模型》：就绪 → 运行由「调度器分派」推动。调度算法就是决定「从就绪队列里选谁」的规则。这篇是后续所有调度算法的共同地基。</span>

## 1 CPU 突发与 I/O 突发

一个进程的生命就是「用 CPU 算一会儿 → 等 I/O 一会儿」的循环。把连续使用 CPU 的时间段称为**CPU 突发（CPU burst）**，把等待 I/O 的时间段称为 **I/O 突发（I/O burst）**。

```
CPU 突发 → I/O 突发 → CPU 突发 → I/O 突发 → ... → CPU 突发 → 结束
```

进程按突发特征可分为两类：

- **CPU 密集型（CPU-bound）**：CPU 突发长、很少等 I/O（科学计算、视频编码）。
- **I/O 密集型（I/O-bound）**：CPU 突发短、频繁做 I/O（交互式程序、数据库、Web 服务器）。

**关键观察**：大多数程序的 CPU 突发都很短——研究表明大量 CPU 突发在 8ms 以内。<span class="marginnote">这个「突发大多很短」的统计特性是短作业优先、多级反馈队列等算法有效的依据：把 CPU 先给「短突发」进程，能让多数进程快速响应。</span>调度算法需要同时讨好两类进程：I/O 密集的想要「快响应」，CPU 密集的想要「高吞吐」。

## 2 调度发生的四个时机

调度器在什么时刻被调用？四种典型情况：

1. 进程从运行态转入**等待态**（发起了 I/O）。
2. 进程从运行态转入**就绪态**（时间片耗尽或被抢占）。
3. 进程从等待态转入**就绪态**（I/O 完成）。
4. 进程**终止**。

其中 1、4 是「进程主动让出 CPU」，2、3 是「外部推动」。据此调度分两大类：

- **非抢占式调度（non-preemptive）**：只在 1、4 时切换。一旦进程上 CPU，除非它自己让出或结束，谁也抢不走。
- **抢占式调度（preemptive）**：在 2、3 也可能切换。调度器可随时把运行进程换下。

**辨析｜易错点：** 抢占调度有一个隐藏成本——**共享数据被抢占时会出竞态**（见《共享数据与竞态条件》）。非抢占调度不存在「做到一半被抢」的问题，所以实现同步更简单；但非抢占的响应性差。现代操作系统几乎都是抢占式，代价是必须配同步机制。

## 3 调度准则：好调度是什么样

评价调度算法有六个常用准则，前四个涉及「要快」：

- **CPU 利用率（CPU utilization）**：CPU 忙的时间占比，越高越好。
- **吞吐量（throughput）**：单位时间完成的进程数，越多越好。
- **周转时间（turnaround time）**：从进程提交到完成的总时间（含等待 + 执行），越短越好。
- **等待时间（waiting time）**：进程在就绪队列里等待的总时间，越短越好。
- **响应时间（response time）**：从提交到「第一次响应」的时间，对交互程序尤其关键，越短越好。
- **公平性（fairness）**：各进程都得到合理 CPU 份额，不被饿死。

**核心矛盾**：这些准则彼此冲突。让 CPU 利用率高，可能就得让短任务等长任务；让周转时间短，可能损害响应时间；追求公平，可能牺牲吞吐。**调度的艺术 = 在冲突的准则间按应用场景权衡**——实时系统要响应时间，批处理系统要吞吐量，交互系统要公平。

## 4 核心对比表：三类系统看重什么

| 准则 | 批处理系统 | 交互式系统 | 实时系统 |
| --- | --- | --- | --- |
| CPU 利用率 | ★★★ | ★★ | ★ |
| 吞吐量 | ★★★ | ★ | ★ |
| 周转时间 | ★★ | ★ | ★ |
| 响应时间 | ★ | ★★★ | ★★★ |
| 公平性 | ★ | ★★★ | ★★ |
| 截止时间 | — | — | ★★★ |

**记忆主线**：批处理要「喂饱 CPU」，交互要「快点应答」，实时要「绝不迟到」。后面每一种调度算法，都是对着这三类需求的某一种展开的。

## 5 小结

- 进程生命周期 = **CPU 突发与 I/O 突发交替**；CPU 密集型突发长，I/O 密集型突发短且频繁。
- 调度发生在四种时机，分**抢占式**（可强停）与**非抢占式**（自觉让出）两类。
- 六大准则：**CPU 利用率、吞吐量、周转时间、等待时间、响应时间、公平性**，彼此冲突。
- 批处理/交互/实时系统对准则的权重截然不同，调度是「按场景权衡」。
- 抢占式调度必须配套同步机制，否则引入竞态条件。
