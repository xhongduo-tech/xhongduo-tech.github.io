## 为什么从模块化内核开始

前两篇把内核结构摆到了宏内核与微内核两个极端：宏内核性能好但脆，微内核可靠但慢。现实世界的操作系统不能二选一，它要「都拿」：要性能，要可靠，还要能随时加驱动、换文件系统、升级网络协议而不重启机器。**模块化内核与可加载内核模块（LKM）正是现代系统给出的折中答案**——保持宏内核的性能，同时获得微内核式的可扩展性。<span class="marginnote">回忆上一篇的坐标：宏内核与微内核是连续谱两端，这篇讲的就是谱系中央最拥挤的区域——几乎所有现代操作系统都住在这里。</span>

## 1 模块化内核：把内核拆成可组装的部件

**模块化内核（modular kernel）**：在宏内核的基础上，把内核按功能拆成若干**内核模块（kernel module）**，每个模块实现一组相关功能（一种文件系统、一类设备驱动、一种网络协议），模块之间通过明确定义的接口调用。

模块化与「简单结构」的区别在于：简单结构是「一大坨」，模块化是「一堆积木」。每个模块有自己的加载、卸载、初始化与清理函数，模块间依赖关系通过接口显式声明。Linux 内核就是模块化宏内核的教科书级范例：`ext4` 文件系统是模块，`e1000` 网卡驱动是模块，`netfilter` 防火墙是模块。<span class="marginnote">「模块化」解决的是组织问题，它仍是宏内核——模块一旦加载就运行在内核态、共享同一地址空间，所以模块 bug 依然可以搞崩整个系统，这点与微内核的进程隔离有本质区别。</span>

## 2 可加载内核模块 LKM：运行时插拔

**可加载内核模块（LKM，Loadable Kernel Module）**：允许在系统运行时动态地把模块装入内核或从内核卸载的机制。Linux 中就是 `*.ko`（kernel object）文件，通过 `insmod` 加载、`rmmod` 卸载。

一个 LKM 的生命周期由两对函数定义：

```c
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/init.h>

static int __init hello_init(void) {   // 加载时调用（出生钩子）
    printk(KERN_INFO "Hello, kernel\n");
    return 0;
}

static void __exit hello_exit(void) {  // 卸载时调用（死亡钩子）
    printk(KERN_INFO "Goodbye, kernel\n");
}

module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("GPL");
```

`module_init` 与 `module_exit` 是模块的「出生」与「死亡」钩子。加载时内核把模块的代码链接进内核符号表，卸载时再解链——**模块与内核共享同一地址空间，因此符号可以直接互相引用**，这是 LKM 性能好的原因，也是它不安全的根源。<span class="marginnote">LKM 的「动态链接」与用户态 `.so` 动态库机制同构：都是运行时把代码接进已有进程/内核。区别在于内核模块没有进程边界，一个越界写就是整机崩溃。容器时代的「内核模块」仍然是这个机制，见 Linux 专题《Docker 原理》。</span>

**辨析｜易错点：** 初学者常把「模块化内核」误当成「微内核」。两者的差别在**边界**：微内核的服务是独立进程，被隔离、需要 IPC；模块化内核的模块只是「功能上分块」，运行在同一内核地址空间、直接函数调用。**模块化 = 组织上的拆分；微内核 = 权限上的拆分。**

## 3 混合内核：兼收并蓄的现实选择

**混合内核（hybrid kernel）**：把宏内核的性能与微内核的可扩展性混在一起的折中结构。Windows（NT 内核）与 macOS（XNU）是典型代表。

Windows 的做法很能说明问题：驱动可以运行在内核态（WDM/WDF 驱动，性能优先），也可以运行在用户态（用户态驱动框架，稳定优先）；内核里既有一大块「执行体」直接提供系统服务，又内嵌微内核式的对象管理与调度核心。<span class="marginnote">macOS 的 XNU 更典型：宏内核主体 + Mach 微内核的调度与内存管理 + BSD 的文件系统与网络。历史地看，「混合」是商业操作系统对「可靠性与性能都要」的工程回答。</span>

## 4 核心对比表：四种结构的定位

| 维度 | 简单结构 | 分层结构 | 微内核 | 模块化/混合 |
| --- | --- | --- | --- | --- |
| 内核态范围 | 一切 | 层层嵌套 | 极小 | 大（宏内核为基础） |
| 模块边界 | 无 | 层级约束 | 进程边界 | 模块接口 |
| 动态扩展 | 不支持 | 不支持 | 支持（新服务进程） | 支持（LKM） |
| 错误隔离 | 无 | 弱 | 强 | 弱（共享地址空间） |
| 性能 | 最高 | 中 | 较低 | 高 |
| 代表 | MS-DOS、早期 Unix | THE、VENIX | QNX、seL4 | Linux、Windows、macOS |

**核心结论**：现代操作系统几乎都是「模块化的宏内核」，Windows/macOS 再叠一点微内核的组件，就构成**混合内核**。纯微内核只在实时、安全关键等特殊领域（QNX、seL4）与学术研究中占据一席之地。

## 5 小结

- **模块化内核**把宏内核按功能拆成模块，模块间通过接口协作，Linux 是其代表。
- **LKM** 允许运行时加载/卸载内核模块，`module_init`/`module_exit` 是生命周期钩子。
- 模块化与微内核的本质区别：**模块共享内核地址空间（组织拆分），微内核是独立进程（权限拆分）**。
- **混合内核** = 宏内核性能 + 微内核式组件，Windows、macOS 是典型。
- 现代系统收敛到「模块化宏内核 + 少量微内核思想」，纯微内核退守安全关键领域。
