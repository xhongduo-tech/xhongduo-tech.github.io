## 为什么从管道与 FIFO 开始

回顾 IPC 篇的管道与 FIFO——这一节在 Linux 上深入**实现与使用**：管道的内核缓冲结构、读写的阻塞语义、shell 里的管道、FIFO 的跨进程使用。管道是 Unix IPC 最古老也最优雅的机制，理解它是理解「一切皆文件」的活教材。<span class="marginnote">回顾《IPC 经典机制》：管道是「有血缘、单向、字节流」；FIFO 是「有名字、跨血缘」。这一节落到实现——<strong>管道在内核里是一个环形缓冲区，通过 file 操作（read/write）访问，这就是「一切皆文件」在 IPC 上的体现</strong>。</span>

## 1 管道的实现：内核环形缓冲

**管道（pipe）**的实现：内核维护一个**环形缓冲区**（默认 64KB），配两个 file 对象：

- **写端 fd**：往缓冲区写（`write`）。
- **读端 fd**：从缓冲区读（`read`）。

```c
int fd[2];
pipe(fd);      // fd[0] = 读端，fd[1] = 写端
```

**读写语义（阻塞模式）**：

- **写满阻塞**：缓冲区满时 `write` 阻塞，直到有空间。
- **读空阻塞**：缓冲区空时 `read` 阻塞，直到有数据。
- **读端关闭 → 写端写**：收到 **SIGPIPE**（回顾信号篇），进程默认终止。
- **写端关闭 → 读端读**：`read` 返回 0（EOF）。

**核心洞察**：管道就是「**生产者-消费者问题**」的内核实现——缓冲区 + 满/空阻塞（回顾第六篇），只是生产者与消费者是**进程**，同步由内核自动完成。

## 2 shell 里的管道：`grep foo file | wc -l`

shell 执行管道的流程：

1. `fork` 两个子进程：`grep` 与 `wc`。
2. `pipe` 创建管道（读端 fd[0]、写端 fd[1]）。
3. **grep 子进程**：`dup2(fd[1], STDOUT_FILENO)`——把标准输出重定向到写端；关掉多余 fd。
4. **wc 子进程**：`dup2(fd[0], STDIN_FILENO)`——把标准输入重定向到读端；关掉多余 fd。
5. 父进程关掉两端，等待两个子进程。

**关键**：**`dup2` 把管道的 fd 复制到标准输入/输出**——子进程的 `printf`/`scanf` 就自然地读写管道了。**管道在这里是「进程间重定向」的载体。**

**辨析｜易错点：** 「管道两端必须显式关闭无关 fd」是新手常忽略的细节。**每个进程都要关闭自己不需要的那端**——grep 要关读端、wc 要关写端、父进程两端都关。**不关的后果**：读端没关完，`read` 不会返回 EOF（还有「写端」存在）；写端没关完，管道不会满而阻塞——**经典 bug：子进程忘记关读端导致管道永不 EOF，程序卡死**。

## 3 FIFO：命名管道的使用

**FIFO（命名管道）**：`mkfifo` 创建，以文件系统的名字标识——**任意两个进程**（不必有亲缘）通过名字通信。

```c
mkfifo("/tmp/myfifo", 0666);   // 创建 FIFO

// 进程 A（写）：
int fd = open("/tmp/myfifo", O_WRONLY);
write(fd, "hello", 6);

// 进程 B（读）：
int fd = open("/tmp/myfifo", O_RDONLY);
read(fd, buf, 6);
```

**FIFO 的语义细节**：

- **打开是阻塞的**：`open(O_RDONLY)` 会阻塞直到有写端打开（反之亦然）——FIFO 需要两端都就绪才能开始。
- **数据不落盘**：数据在内核缓冲区，FIFO 的「文件」只是名字。
- **单向**：一端读一端写（同管道）。

**FIFO vs 管道**：唯一本质区别是**有无名字、能否跨血缘**——其余语义（单向、字节流、阻塞）完全相同。

**FIFO 的典型场景**：

- **客户端-服务器**：服务器创建 FIFO，客户端写入请求。
- **进程间简单通信**：无需亲缘关系的两个进程交换数据。

## 4 公式解析：管道的容量与背压

管道缓冲容量为 $C$（Linux 默认 64KB），生产速率 $r_p$、消费速率 $r_c$：

$$\text{管道传播的背压} = \begin{cases} 0 & r_c \ge r_p \text{（消费跟得上）} \\ (r_p - r_c) \cdot t & r_c < r_p \text{（生产更快）} \end{cases}$$

- 当消费慢于生产：缓冲区**逐渐填满**。
- 缓冲满后：生产者 `write` **阻塞**——**背压（backpressure）**让快的一方等慢的一方。
- **背压是管道的天然流量控制**：快慢不匹配时，慢的一方「拖住」快的一方，保证数据不丢。

**直觉**：管道不只是「数据通道」，更是「**速率适配器**」——它的满/空阻塞（背压）自动协调生产者与消费者的速度（回顾《缓冲技术》的循环缓冲）。`grep | wc` 中如果 grep 输出爆炸，wc 处理慢，grep 会被背压拖慢——**这是系统级的自适应限流**。

## 5 核心对比表：管道 vs FIFO

| 维度 | 管道（pipe） | FIFO |
| --- | --- | --- |
| 名字 | 无（匿名） | 有（文件系统路径） |
| 亲缘要求 | 必须（fork 继承） | 不需要 |
| 数据位置 | 内核缓冲 | 内核缓冲（名字只是门牌） |
| 打开语义 | pipe() 即就绪 | open 阻塞等对端 |
| 用途 | shell 管道、父子进程 | 跨进程命名通信 |

## 6 小结

- 管道 = **内核环形缓冲 + 读写 file**——生产者-消费者的内核实现。
- 阻塞语义：**写满阻塞、读空阻塞、读端关写端收 SIGPIPE、写端关读端 EOF**。
- shell 管道 = **fork + pipe + dup2 重定向**；要**关掉不需要的 fd**。
- **FIFO** = 命名管道，`mkfifo` 创建、`open` 阻塞等对端、跨血缘可用。
- 管道有**背压**——满/空阻塞自动协调快慢，是系统级流量控制。
