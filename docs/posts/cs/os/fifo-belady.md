## 为什么从 FIFO 开始

OPT 不可实现，那就从最简单的实用算法开始。**FIFO 置换**最直接：谁先进内存，谁先被换出——像排队。它实现简单，却暴露了置换算法的两个核心教训：**「最老的」不等于「最该换的」**，以及著名的 **Belady 异常**（加内存反而更多缺页）。<span class="marginnote">回顾 OPT：它换「将来最久不用」，因为「最老」不代表「最久不用」——一个刚被反复使用的老页可能马上又要用。FIFO 的缺点从它选择依据的那一刻就注定了。</span>

## 1 FIFO 置换算法

**FIFO 置换（First-In-First-Out）**：把驻留页按调入时间排队，**缺页时换出队首（最先进来、待得最久的）页**。

实现：一个队列（或环形缓冲区），调入页进队尾，换出队首。

对参考串 $7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1$，页框数 3：

| 步骤 | 访问 | 内存（3 框） | 是否缺页 |
| --- | --- | --- | --- |
| 1 | 7 | 7 | 缺 |
| 2 | 0 | 7,0 | 缺 |
| 3 | 1 | 7,0,1 | 缺 |
| 4 | 2 | **0,1,2**（换出 7） | 缺 |
| 5 | 0 | 0,1,2（命中） | 否 |
| 6 | 3 | **1,2,3**（换出 0） | 缺 |
| 7 | 0 | **2,3,0**（换出 1） | 缺 |
| ... | ... | ... | ... |

**FIFO 的特点**：完全不管「页用得勤不勤」，只按「来得早晚」。它体现的假设是「待得最久 ≈ 最不用」——这个假设常常是错的。

## 2 FIFO 的缺点：最老的未必最没用

FIFO 的最大问题是**不考虑访问频率**：

一个**常被使用的老页**（如循环中的代码页）待在内存很久，FIFO 却把它当「最该换」的——换出去后马上又缺页调回，如此反复。
FIFO 对「访问模式」无感知，缺页率常显著高于 LRU 等算法。

**直觉错位**：FIFO 用「时间先后」代替「使用频度」，而置换真正该看的是「将来会不会用」——**过去用得最少的页，才最可能将来不用**。FIFO 连「过去的使用」都不看，自然选不准。

## 3 Belady 异常：加内存反而更糟

**Belady 异常（Belady's anomaly）**：**页框数增加，缺页次数反而增加**——FIFO 特有的反常现象。

经典反例：参考串 $1,2,3,4,1,2,5,1,2,3,4,5$。

**3 个页框**：缺页 **9** 次。
**4 个页框**：缺页 **10** 次——**更多内存，反而更多缺页！**

**为什么**：FIFO 换出的页「太老」，换入的页「太新」，两者都在局部性之外。页框从 3 增到 4 时，FIFO 换出的「老页」恰好是即将要被访问的页（如 1,2），反而引发更多缺页。**FIFO 不遵循「栈式性质（stack property）」**——页框集合不是「含前 k 个最常用页」的嵌套集合，所以扩大内存不保证缺页减少。<span class="marginnote">Belady 异常的名字来自 Belady 1969 年的发现。它证明「内存越大越好」在 FIFO 下不是定理——这推动了 LRU 等「栈式算法」的研究。<strong>栈式算法（LRU、OPT）满足：页框数增加时缺页次数不会增加</strong>——这也是 LRU 优于 FIFO 的数学层面原因。</span>

**辨析｜易错点：** 「Belady 异常只对 FIFO」是常见说法，要精确一点：**FIFO 是「可能发生」Belady 异常的代表，但不是唯一**——任何**非栈式**算法都可能。栈式算法（LRU、OPT）保证缺页次数随页框数单调不增。**「加内存一定减少缺页」的直觉，只在栈式算法下成立。**

## 4 核心对比表：FIFO vs OPT vs LRU 的性质

| 维度 | FIFO | OPT | LRU |
| --- | --- | --- | --- |
| 选择依据 | 最先进来 | 将来最久不用 | 最久没用过 |
| 栈式性质 | **无（Belady 异常）** | 有 | 有 |
| 需未来信息 | 否 | 是 | 否 |
| 缺页次数 | 高 | 最低 | 接近 OPT |
| 实现代价 | 最低 | 不可实现 | 中（需时间戳/栈） |

## 5 小结

- **FIFO 置换**：换出最先进来的页，实现最简单，但不考虑使用频度。
- FIFO 的缺点：**「最老」≠「最没用」**，常用老页被反复换出换入。
- **Belady 异常**：页框数增加缺页反而增加——FIFO 不满足**栈式性质**。
- 栈式算法（LRU、OPT）保证「内存越大缺页越少」，FIFO 做不到。
- FIFO 的价值：作为朴素基线，反衬出「按使用历史置换」的必要性。
