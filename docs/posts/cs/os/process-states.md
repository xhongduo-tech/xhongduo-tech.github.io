## 为什么从进程状态开始

上一节确立了「进程是活的执行」，那么一个自然的问题就来了：**一个进程从生到死，一共会经历哪些「生命阶段」？** 现代计算机的 CPU 远少于进程数，大多数进程并不在真正占用 CPU，它们在排队、在等 I/O、在睡大觉。给这些「不同处境」的进程起名字、规定它们之间如何迁移，是调度器工作的前提——**不了解状态，就理解不了调度；理解了状态，整部调度史就是状态转换史。**<span class="marginnote">状态模型是「进程生命周期」的地图。后面讲调度队列、上下文切换、同步与死锁时，你会反复回到这张地图上定位「此刻进程在哪个格子」。</span>

## 1 进程的五状态模型

恐龙书给出了经典的**五状态模型**。每个进程在任一时刻必然处于且仅处于其中一个状态：

| 状态 | 含义 | 通俗比喻 |
| --- | --- | --- |
| 新建（new） | 进程刚被创建，还没进入就绪队列 | 出生登记，还没下地 |
| 就绪（ready） | 万事俱备，只等 CPU；在就绪队列中排队 | 候诊室坐着等叫号 |
| 运行（running） | 正占用 CPU 执行指令 | 正在诊室里看病 |
| 等待/阻塞（waiting） | 等待某事件（如 I/O 完成）而暂停 | 出去做检查，叫号时不在 |
| 终止（terminated） | 执行完毕或出错，正被回收 | 看完病离开医院 |

**核心状态是就绪与运行**：就绪表示「想用 CPU 但没抢到」，运行表示「正用着 CPU」。这两个状态的区别是调度器存在的全部理由。

## 2 状态转换：谁在推动进程搬家

五状态之间只存在确定方向的转换，用一张转换表把「从哪 → 到哪 → 谁触发」说清：

| 转换 | 触发者 | 说明 |
| --- | --- | --- |
| 新建 → 就绪 | 系统 | 进程初始化完成，进入就绪队列 |
| 就绪 → 运行 | **调度器（分派）** | 选中该进程，分配 CPU |
| 运行 → 就绪 | 时间片耗尽或更高优先级抢占 | 进程被换下 CPU，回到队列 |
| 运行 → 等待 | 进程自身 | 发出 I/O 请求或等待事件 |
| 等待 → 就绪 | 事件完成（中断/信号） | 等到了，重新排队 |
| 运行 → 终止 | 进程自身/系统 | 执行 `exit` 或出错被杀 |

**辨析｜易错点：** 最常见的错误是画「就绪 → 等待」或「等待 → 运行」的直接转换。**就绪进程没有占用 CPU，它无法发起 I/O，所以不可能「就绪 → 等待」；等待中的进程没有 CPU，不可能直接跳到「运行」**，必须先回就绪队列重新排队。唯一的例外是特权级中断上下文里的少数优化，教学模型里不存在。

另一个易错点：**只有「运行 → 等待」和「运行 → 终止」是进程主动发起的**（进程自己请求 I/O 或退出），其余转换都来自外部（调度器、中断）。<span class="marginnote">这个「谁触发」的视角很重要：调度器是外部力量，它随时可以把运行中的进程踢回就绪（抢占）；而进程只能决定自己何时去等 I/O——它无法决定自己何时被调度。这是「抢占式调度」与「协作式调度」分野的起点。</span>

## 3 七状态模型：加上挂起

实际系统还会引入**挂起（suspend）**：把进程从内存整体搬到磁盘（交换区），以腾出内存。于是五状态扩展为七状态：

- 新增**就绪挂起（ready-suspend）**：在磁盘上但已准备好运行。
- 新增**等待挂起（waiting-suspend）**：在磁盘上且仍在等事件。

挂起与等待的区别是**换出地点不同**：等待是在内存里等，挂起是被搬到磁盘上等。<span class="marginnote">挂起是「内存不够用」时的极端手段，见第八篇《交换技术》。Linux 的 swap 分区就是「挂起队列」的现代形态，不过现代 Linux 更倾向把整个进程换出（swap）而非按状态区分。</span>

## 4 核心对比表：就绪 vs 等待

就绪与等待是最容易混淆的两个非运行状态，单独对比：

| 维度 | 就绪（ready） | 等待（waiting） |
| --- | --- | --- |
| 缺什么 | 缺 CPU | 缺某事件（I/O、信号） |
| 占不占 CPU | 不占 | 不占 |
| 谁让它进入 | 调度器/事件完成 | 进程自己请求 I/O |
| 怎么离开 | 被调度器选中 → 运行 | 事件完成后 → 就绪 |
| 在哪个队列 | 就绪队列 | 等待队列（按事件分类） |

**一句话记忆**：就绪是「什么都能干，只等 CPU」，等待是「有 CPU 也干不了，得先等事」。CPU 空闲时调度器一定从就绪队列取进程——等待队列再长也与调度无关。

## 5 小结

- **五状态模型**：新建、就绪、运行、等待、终止；任一时刻进程恰处其一。
- **就绪 vs 等待**：就绪只缺 CPU，等待缺事件；等待必须经就绪才能回到运行。
- 合法转换中只有「运行 → 等待」与「运行 → 终止」是进程主动的，其余由调度器或中断推动。
- **七状态模型**在五状态之上加**就绪挂起、等待挂起**，用于内存不足时的换出。
- 状态模型是调度、同步、死锁各篇的公共地图。
