## 为什么从 CFS 开始

前面的理论算法（MLFQ、RR、优先级）各有各的问题：时间片难选、需要预知突发、会饥饿。Linux 从 2.6.23 起换上了 **CFS（完全公平调度器）**，用一套全新的思路解决了这些老问题——**不再给进程分时间片，而是让每个进程「跑到该停的点」**。理解 CFS 等于把前几节的调度理论「现代实战化」一遍。<span class="marginnote">回顾 MLFQ：它需要多级队列 + 时间片 + 升降级 + 老化，参数多、行为复杂。CFS 的目标是「一个简单的公平模型，几乎不用调参」——它是 MLFQ 思想的极简且优雅的继承者。</span>

## 1 CFS 的核心思想：虚拟运行时间

**CFS（Completely Fair Scheduler，完全公平调度器）**：让所有可运行进程**按虚拟运行时间（vruntime）均衡推进**。vruntime 是每个进程累计的「加权运行时间」——运行得越少的进程，vruntime 越小，越该被优先调度。

CFS 的调度决策极其简单：**每次选 vruntime 最小的进程运行**。

为什么这样「公平」？想象一条起跑线：所有进程从 vruntime=0 起跑，谁跑得少谁排前面。运行中的进程 vruntime 不断增加，很快就不再最小，于是把 CPU 让给落后者——**所有进程的 vruntime 保持大致齐头并进**，每个人获得的 CPU 时间趋于相等。<span class="marginnote">CFS 里没有「时间片」概念，没有「降级」，没有「老化」。它用「vruntime 落后 → 被优先」这一个机制，同时实现了公平、响应、无饥饿——后进者天然被补偿。</span>

直观地看，CFS 是「跑步比赛裁判」：所有人从同一起跑线出发，谁落后就让他先跑一段，跑到追上为止。没有固定的「每人几秒」，只有「落后就补」——**它是按「欠的债」而非「排的队」来决定调度**，这正是它与 FCFS、RR 最深刻的差别。

## 2 vruntime 与权重的计算

vruntime 不是简单的墙上时间。它按进程**权重（weight）**加权：高权重（高优先级）进程的 vruntime 增长慢，因此能获得更多 CPU；低权重进程增长快，跑一会儿就得让位。

进程的权重由 **nice 值**映射而来（nice 越低，权重越高）：

$$\text{vruntime 增长速率} \propto \frac{1}{\text{weight}}$$

而**实际运行时间**与权重的关系为：

$$\frac{\text{实际获得时间}_i}{\text{实际获得时间}_j} = \frac{\text{weight}_i}{\text{weight}_j}$$

即两个可运行进程获得的实际 CPU 时间之比，等于它们权重之比。nice 每差一档，权重差约 1.25 倍；nice 每差一个「台阶」（如 -20 到 -19），权重约差 1.25 倍，这与 Unix 传统语义一致。

**nice 值与权重对照**（节选，Linux 内核 `prio_to_weight` 表）：

| nice | 权重 | 说明 |
| --- | --- | --- |
| -20 | 88761 | 极高优先级，权重最大 |
| -10 | 9548 | 高优先级 |
| 0 | 1024 | 默认值，即基准权重 |
| 10 | 117 | 低优先级 |
| 19 | 15 | 极低优先级，权重最小 |

权重近似按 nice 每降 1 增长约 1.25 倍：nice 从 0 到 -10，权重从 1024 增到 9548（约 9.3 倍）；nice 从 0 到 19，权重从 1024 降到 15。**nice 是「相对」的标尺，权重才是「绝对」的配额来源**——CPU 时间按权重比分配，这是 CFS 一切计算的根基。

**公式解析：vruntime 的含义**

$$vruntime_i \mathrel{+}= \frac{\text{实际运行时间}_i}{\text{weight}_i} \times \text{基准权重}$$

- **实际运行时间**：进程真实占用 CPU 的时间。
- **weight**：进程权重（由 nice 值决定），权重大的除后增量小。
- **基准权重**：归一化常数，保证 nice=0 时 vruntime 增长率等于墙上时间。
- 直观含义：**vruntime 是「按权重折算后的运行时间」**——高权重进程运行同样时长，vruntime 涨得少，所以看起来「更落后」，从而被优先调度、获得更多 CPU。

调度时，CFS 从红黑树中取出 vruntime 最小的进程——红黑树的查找是 $O(\log n)$，这就是 CFS 高效的原因之一。

### 数值算例：两个进程的 vruntime 追逐

设两个进程 A、B，nice 相同（权重相等），初始 vruntime 都是 0：

| 时刻 | 被调度者 | A.vruntime | B.vruntime | 说明 |
| --- | --- | --- | --- | --- |
| t0 | A（均等，先到先得） | 0 → 3 | 0 | A 运行 3 个单位 |
| t1 | B（A=3 > B=0） | 3 | 0 → 3 | B 运行 3 个单位，追平 |
| t2 | A（并列，先到先得） | 3 → 6 | 3 | A 再跑 3 个单位 |
| t3 | B | 6 | 3 → 6 | B 追平 |

可见两个进程**严格交替推进**，vruntime 始终咬合在同一条起跑线附近。若给 A 更高权重（nice 更低），A 每次运行 vruntime 只涨 1、B 涨 3——A 每轮跑得久、轮次少，总获得时间之比恰为权重之比。**vruntime 的「齐头并进」不是每个进程跑一样久，而是每个进程推进一样多**——这就是公平的真正含义。

## 3 从运行到睡眠：vruntime 的补偿机制

vruntime 模型有个微妙问题：**进程睡眠后，它的 vruntime 就停了；醒来时它远远落后，会立刻抢占 CPU 很长时间。** 这既不公平也不稳定。

CFS 的解法：

- **睡眠进程在唤醒时，其 vruntime 被「追赶」**：把睡眠进程的 vruntime 设为当前最小值附近，保证它醒来后能较快获得 CPU（交互进程体验好）。
- **防止「睡眠者霸占」**：同时限制追赶幅度，避免一个进程靠反复睡眠骗 CPU。

这本质上是**老化的现代化身**——等得越久的进程（睡眠、I/O 等待）醒来后越优先，对应上一篇《优先级调度》的 aging 思想。<span class="marginnote">CFS 的唤醒补偿 ≈ MLFQ 的「升级」 + 优先级调度的「老化」。CFS 用 vruntime 一个标量统一表达了这些原本分散的机制——这就是「一个好模型胜过十个好补丁」。</span>

### 两个关键参数：target_latency 与 min_granularity

CFS 有两个可调参数，共同决定「每轮跑多久」：

- **target_latency**（目标延迟，默认约 20ms）：调度周期内所有可运行进程都要被「照顾」一遍——CFS 把这段时间按权重切成片分给每个进程。
- **min_granularity**（最小粒度，默认约 0.75ms）：每轮运行时间不得少于这个值，防止进程数太多时每片小到「切换开销超过运行收益」。

当可运行进程很多、片切得太碎时，CFS 以 `min_granularity` 为下限，宁可多轮分别调度，也不把单轮切成纳米级碎片——**「公平」是有粒度的，过度的公平反而制造浪费**。

## 4 核心对比表：CFS vs MLFQ

| 维度 | MLFQ | CFS |
| --- | --- | --- |
| 核心数据结构 | 多级队列 | 红黑树（按 vruntime） |
| 时间片 | 每级不同 | 无（按目标延迟动态决定） |
| 公平模型 | 升降级反馈 | vruntime 齐头并进 |
| 短作业优待 | 高层快速完成 | 醒来即落后 → 被优先 |
| 饥饿防护 | 需要老化 | 天然无饥饿 |
| 调参负担 | 参数多 | 极少（nice 值即可） |

**辨析｜易错点：** 「CFS 是纯 RR」是常见误读。CFS 与 RR 形似（都轮换），但**RR 是固定时间片，CFS 是按 vruntime 动态决定「每轮跑多久」**——优先级高的进程每轮跑得久、轮次少，优先级低的每轮跑得短、轮次多。另一个易错点：**「CFS 没有优先级」**。CFS 有优先级，只是以 nice → 权重 → vruntime 增长率的形式存在，而不是传统「数字优先级」的表象。

## 5 小结

- **CFS** 以 **vruntime** 为标尺，每次选 vruntime 最小的进程运行，所有进程 vruntime 齐头并进。
- **公平 = 每个进程 vruntime 推进相同**，而非运行时间相同；权重决定「跑得久但轮次少」。
- **vruntime 按权重加权**：`vruntime += 实际运行时间/weight`，nice → weight（`prio_to_weight` 表）→ 增长率，高权重进程获得更多 CPU。
- 调度决策 $O(\log n)$，用**红黑树**维护。
- 睡眠唤醒时 **vruntime 追赶**实现交互优待，是老化思想的现代化身——把 MLFQ 的升级与 aging 统一成一个机制。
- `target_latency` 与 `min_granularity` 控制每轮时长，防止「过度公平」制造切换浪费。
- CFS 用一个标量模型取代了 MLFQ 的多级队列与调参负担，是调度器设计的当代范例。
