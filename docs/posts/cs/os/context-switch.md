## 为什么从上下文切换开始

上一节我们认识了 PCB，说它保存着进程的「现场」。这一节回答：**现场怎么被存进去，又怎么被换出来？** 这就是**上下文切换（context switch）**——操作系统制造「多个程序同时运行」错觉的核心魔术。CPU 只有一个，进程成千上万，靠的就是在进程之间高速「换人」，每次换人都快到你感觉不到。<span class="marginnote">上下文切换与《进程状态模型》互为表里：状态转换是「逻辑上」的搬家，上下文切换是「物理上」的换场。就绪 → 运行的转换，物理动作就是一次上下文切换。</span>

## 1 什么是上下文

**上下文（context）**：一个进程在某一时刻的完整运行现场，包括三部分：

- **CPU 寄存器**：通用寄存器、程序计数器（PC）、程序状态字（PSW）、栈指针（SP）。
- **内存映射**：进程的地址空间（页表基址寄存器 CR3 等）。
- **内核上下文**：进程在内核态时保存的内核栈指针等。

**上下文切换（context switch）**：把当前进程的上下文保存进它的 PCB，再从目标进程的 PCB 恢复其上下文，使 CPU 转而执行目标进程的过程。

## 2 上下文切换的步骤

一次典型切换分三步：

1. **保存现场**：把当前进程的 PC、寄存器、状态字压入内核栈，再写入当前进程的 PCB。
2. **切换地址空间**：把页表基址寄存器换成新进程的，TLB 随之失效。
3. **恢复现场**：从新进程的 PCB 读出寄存器与 PC，CPU 从新进程的断点继续执行。

看起来简单，但每一步都有代价：保存/恢复寄存器、切换页表使 TLB 全部作废、内核栈切换、可能还要清空各类缓存。<span class="marginnote">TLB（快表）是地址转换的高速缓存，进程切换后里面全是旧进程的映射，必须作废重填——这是上下文切换隐藏成本的大头之一，见第八篇《快表 TLB》。</span>

**上下文切换时间（context switch time）**：完成一次切换所需的时间，典型为几微秒。它依赖硬件支持：寄存器越多、缓存越大，切换越贵。**切换频率 × 切换时间 = 系统花在「换人」上的纯开销**，这部分时间不执行任何用户代码，所以调度器要尽量减少无谓切换。

## 3 调度队列：PCB 排队的三种队

进程从创建到终止，一直在不同的**调度队列（scheduling queue）**之间迁移，对应上一篇的状态：

- **就绪队列（ready queue）**：所有就绪进程的 PCB 队列。常以链表实现，头指针指向第一个 PCB。
- **等待队列（wait queue）**：因等待某事件（I/O 完成、信号量、定时器）而阻塞的进程队列。通常**每个事件一种队列**，方便事件发生时精准唤醒。
- **设备队列（device queue）**：等待某设备的进程队列，本质是等待队列的一种特例（如等待磁盘的队列）。

**队列的迁移就是状态的迁移**：进程创建 → 入就绪队列；被调度 → 出就绪队列上 CPU；请求 I/O → 入该设备的等待队列；I/O 完成 → 中断唤醒，回到就绪队列。

## 4 核心对比表：两种调度形式

调度器的动作分为两个层次，容易混为一谈：

| 维度 | 长期调度（作业调度） | 短期调度（CPU 调度） |
| --- | --- | --- |
| 决策频率 | 低（秒~分钟级） | 高（毫秒级，每次切换） |
| 控制什么 | 从磁盘作业中选谁进入内存 | 从就绪队列选谁上 CPU |
| 决定什么 | 进程创建速率、多道程度 | 谁立即运行 |
| 实现位置 | 较少见（现代多为按需创建） | 每个操作系统必备 |

（部分教材还提**中期调度**，即交换，见第八篇《交换技术》。）

**辨析｜易错点：** 「上下文切换 = 模式切换」是最常见误区。**模式切换（user↔kernel）只改变特权级，不换进程**——中断处理、系统调用都是模式切换，切换时仍服务同一进程，现场由内核栈保存，不必动 PCB；**上下文切换才换进程**，要动 PCB 与地址空间。**模式切换比上下文切换便宜得多**，一次系统调用只是模式切换，不是上下文切换。<span class="marginnote">这个区分极其重要：你写程序调用 `read`，是模式切换；两个进程轮流跑，是上下文切换。前者纳秒~微秒级，后者通常贵一个数量级，因为要动 TLB。</span>

## 5 小结

- **上下文** = 寄存器 + PC + 状态字 + 地址空间 + 内核栈；**上下文切换** = 存旧 PCB、换地址空间、恢复新 PCB。
- 切换三步：**保存现场 → 切换页表 → 恢复现场**；切换时间典型几微秒，是调度器的纯开销。
- **调度队列**包括就绪队列、等待队列（含设备队列），进程在队列间迁移即状态迁移。
- **长期调度**决定谁进内存，**短期调度**决定谁上 CPU，两者频率差几个数量级。
- **上下文切换 ≠ 模式切换**：模式切换不换进程，便宜得多。
