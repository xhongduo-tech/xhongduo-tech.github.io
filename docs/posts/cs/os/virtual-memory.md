## 为什么从虚拟内存开始

分页解决了「怎么把进程装进内存」，但没解决「进程比内存还大」。一个程序想用 8GB 内存，而物理内存只有 4GB——装得下吗？**虚拟内存（virtual memory）**的回答是：**装得下**。它的底气来自一个经验事实——**局部性原理**：程序某一时刻真正用到的内存只有一小部分。既然大部分内存闲着，不如只把「正在用的部分」放进物理内存，其余留在磁盘，用到了再调入。<span class="marginnote">回顾《交换技术》：整进程换进换出太粗。虚拟内存把它细化成「按页换」——只用到的页才驻留内存。<strong>虚拟内存 = 分页 + 按需装入 + 页级换出</strong>，是内存管理的最高形态。</span>

## 1 虚拟内存：逻辑空间与物理空间分离

**虚拟内存（virtual memory）**：允许进程的**逻辑地址空间大于物理内存**的一种技术——进程「以为」自己独占一个巨大的地址空间，实际只把正在用的页装入物理内存，其余页留在磁盘（交换区）上。

核心思想：**逻辑地址空间 ≠ 物理内存**，两者通过页表映射，映射关系可以动态变化——缺哪页、装哪页。

**虚拟内存带来的能力**：

**进程可以比物理内存大**：程序写 8GB 的数组，物理内存只有 4GB 也能跑（一次只装用的部分）。
**更多进程驻留**：每个进程只占「实际用的内存」，内存里能同时装下更多进程，多道程度提高。
**内存不足不再致命**：需要时从磁盘调入，而不是拒绝进程。

## 2 局部性原理：虚拟内存的物理依据

**局部性原理（principle of locality）**：程序在短时间内倾向于只访问**一小部分**地址空间。分两方面：

**时间局部性（temporal locality）**：刚访问过的数据，很可能很快再次访问（循环、栈、计数器）。
**空间局部性（spatial locality）**：刚访问过的数据附近的数据，很可能接下来被访问（数组遍历、顺序执行指令）。

**为什么局部性成立**：

指令是**顺序执行**的（空间局部性）。
**循环**反复执行同一段代码（时间 + 空间）。
数组、结构体连续存放（空间局部性）。
栈、热变量反复使用（时间局部性）。

**局部性 → 虚拟内存可行**：既然程序某一刻只碰一小片地址，那么「只装这一小片」就够了——其余页留在磁盘不占内存。<span class="marginnote">局部性是计算机系统的「万有引力」：缓存（L1/L2）、TLB、虚拟内存、预读、工作集模型——全都建立在「程序访问有局部性」这个经验事实上。你会在《计算机组成》的缓存篇再见到它，那里它是硬件缓存存在的理由。</span>

## 3 虚拟内存的三大收益

- **进程隔离增强**：每个进程一个独立虚拟地址空间，互不可见——安全性比共享物理内存更强。
- **内存共享更优雅**：多个进程的虚拟页可以映射到同一物理页（共享库、共享内存 IPC）——虚拟内存让「共享」成为「页表条目」层面的小事。
- **程序员心智简化**：程序员可以假装内存无限，不用管理内存布局（虽然实际还要小心内存占用）。

**辨析｜易错点：** 「虚拟内存 = 用磁盘假装内存」是常见简化，方向对但不够准确。**虚拟内存不只是「慢速扩充内存」，它更是「逻辑地址与物理地址的动态解耦」**——分页已经解耦了「连续与否」，虚拟内存进一步解耦「驻留与否」。磁盘交换只是手段之一，核心是「按需驻留」的抽象。

另一个易错点：**「虚拟内存让程序不再受物理内存限制，所以内存分配不用节制」**——这是危险的误解。**虚拟内存是「用磁盘换容量」**，缺页时要从磁盘调入，性能骤降（缺页率决定一切，见《缺页率与有效访问时间》）。程序过度使用虚拟内存会陷入「抖动」（见《页框分配与抖动》），比物理内存不足更糟。

## 4 虚拟内存需要什么：四根支柱

虚拟内存不是免费的抽象，它依赖四样东西缺一不可：

1. **页表**：记录每个逻辑页映射到哪个物理页、还是留在磁盘哪个位置——这是「按需驻留」的地图。
2. **MMU**：硬件完成逻辑地址 → 物理地址的翻译，缺页时触发异常交给内核。
3. **TLB**：翻译结果的高速缓存，避免每次访存都查页表（见《快表 TLB》）。
4. **交换区**：磁盘上存放被换出页的区域，缺页时从中调回。

这四根支柱解释了为什么虚拟内存直到 1960 年代 Atlas 计算机才诞生：**不是概念难，而是硬件条件先成熟**——分页硬件与足够大的磁盘都到位后，「按需驻留」才成为可能。<span class="marginnote">回想《逻辑地址与物理地址》：那里 MMU 只做「加基址」的简单翻译；到虚拟内存这里，翻译升级成「页表查表 + 缺页处理」，复杂度上了一个数量级——你正在经历操作系统内存管理从简到繁的主线。</span>

## 5 核心对比表：物理内存 vs 虚拟内存

| 维度 | 物理内存 | 虚拟内存 |
| --- | --- | --- |
| 地址空间 | 0 到物理上限 | 0 到逻辑上限（可更大） |
| 驻留性 | 全部驻留 | 只驻留用到的页 |
| 映射 | 直接 | 页表动态映射 |
| 容量限制 | 硬件决定 | 逻辑空间 + 交换区 |
| 速度 | 快 | 缺页时慢（磁盘 I/O） |
| 进程隔离 | 弱（共享物理） | 强（独立虚拟空间） |

## 6 数值算例：为什么缺页率决定一切

虚拟内存的代价全藏在**缺页**里——缺页要从磁盘调入页面，一次就要毫秒级。用有效访问时间（EAT）公式预先感受一下：

$$\text{EAT} = (1-p) \cdot t_{\text{mem}} + p \cdot t_{\text{page fault}}$$

设内存访问 $t_{\text{mem}} = 100\,\mathrm{ns}$，一次缺页处理 $t_{\text{fault}} = 8\,\mathrm{ms}$，缺页率 $p$ 分别为：

| 缺页率 $p$ | EAT | 相比无缺页慢多少 |
| --- | --- | --- |
| 0（无缺页） | 100 ns | 1 倍 |
| 0.00001 | 180 ns | 1.8 倍 |
| 0.0001 | 900 ns | 9 倍 |
| 0.001 | 8.1 μs | 81 倍 |
| 0.01 | 80 μs | 800 倍 |

关键结论：**缺页率哪怕只有 0.1%，程序也会慢 80 倍**。因为 $t_{\text{fault}}$ 比 $t_{\text{mem}}$ 大 8 万倍，一点点缺页率都会被放大成灾难。这就是虚拟内存的全部工程重心所在——**让缺页率尽可能接近 0**，靠局部性、合适的页面置换与充足的页框（见后续《缺页率与有效访问时间》《页框分配与抖动》）。

## 7 术语速查

| 术语 | 含义 |
| --- | --- |
| 虚拟内存 | 逻辑空间可大于物理空间，只驻留用到的页 |
| 时间局部性 | 刚访问过的数据很快会被再次访问 |
| 空间局部性 | 刚访问过的数据附近的数据很快会被访问 |
| 交换区 | 存放被换出页的磁盘区域 |
| 缺页 | 访问的页不在内存，需从磁盘调入 |
| 有效访问时间 | 考虑缺页概率后的平均访存时间 |
| 抖动 | 缺页过于频繁，系统几乎全在换页 |

## 8 小结

- **虚拟内存**：逻辑空间可大于物理空间，只把用到的页装入内存，其余留磁盘。
- **局部性原理**：时间局部性 + 空间局部性——程序某一刻只碰一小片地址，是虚拟内存的物理依据。
- 虚拟内存 = **分页 + 按需装入 + 页级换出**，是交换技术的细粒度演化。
- 收益：进程可大于内存、更多进程驻留、隔离与共享更优雅。
- 代价与陷阱：缺页要磁盘 I/O，过度使用会**抖动**——性能比内存不足更糟。
- 四根支柱：页表、MMU、TLB、交换区——硬件成熟后才催生虚拟内存。
- EAT 数值：缺页率 0.1% 时程序慢约 80 倍，所以工程重心是压低缺页率。
