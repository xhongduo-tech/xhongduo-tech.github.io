## 为什么从操作系统结构开始

系统调用定义了内核「对外长什么样」，但这只是面子。真正决定一个操作系统能否长期演进、能否被维护、能否在几百万行代码里找出 bug 的，是它**内部怎么组织**——内核的骨架。上一节我们讲了服务入口，这一节我们俯瞰骨架本身：同样是「管理进程、内存、文件」，不同的操作系统内部可以长成完全不同的样子。<span class="marginnote">「结构决定可维护性」是软件工程的核心命题，操作系统正是这门学问最极端的学生——它不能轻易停机，错误代价极高，因而结构选择比普通软件更生死攸关。</span>

一个操作系统的结构选择，本质是在回答三个问题：模块之间如何分工？依赖关系如何约束？错误如何隔离？

## 1 简单结构：MS-DOS 与早期 Unix

**简单结构（monolithic / simple structure）**：把内核所需的全部功能堆在一个大型可执行文件里，模块之间没有严格的层次约束，任何模块都可以直接调用任何其他模块的代码与数据。

MS-DOS 是简单结构的典型：应用程序、设备驱动、文件系统逻辑混在同一个二进制里，没有明确的模块边界。早期 Unix（1969—1970 年）也相当简单——内核与系统程序一起编译，能分成文件系统、进程管理、设备管理几个部分，但各部分之间没有强制分层。<span class="marginnote">「Monolithic」一词中文常译「单体内核」或「宏内核」。注意它描述的是「编译期就捆死、无边界」的组织方式，而非功能多寡——现代 Linux 也是宏内核，但模块化程度远高于早期 Unix。</span>

**优点**：直接调用，无边界开销，性能最好；代码量小的时候清晰易懂。
**缺点**：模块边界模糊，一处改动可能影响全局；错误隔离差，驱动崩溃拖垮整个内核；难以扩展为大规模系统。

## 2 分层结构：把内核切成蛋糕

**分层结构（layered structure）**：把操作系统按抽象层级组织，底层是硬件，顶层是用户接口，每一层只依赖其下方的一层，层间通过定义良好的接口通信。1970 年代 Dijkstra 设计的 **THE 系统** 是第一个分层操作系统，共分六层；之后的 VENIX 与 Windows NT 的早期设计也采用了分层思想。

每一层就像一个「被服务的层」：

- 第 0 层：进程调度与内存分配（最贴近硬件）
- 第 1 层：内存管理
- 第 2 层：操作员—进程通信
- 第 3 层：I/O 管理
- 第 4 层：用户程序
- 第 5 层：操作员控制台

**分层的关键收益是「层内隔离」**：调试时从底层往上逐层验证，上层出错不用怀疑下层；修改某层内部实现时，只要接口不变，其他层不受影响。<span class="marginnote">分层思想远不止于操作系统：网络协议栈的 TCP/IP 四层、计算机体系结构的分级存储器层次，都是同一招——用接口隔离变化，用层级控制依赖。你在《计算机网络》中还会反复见到它。</span>

**代价**：每层都要经过下层服务才能触达硬件，链路过长导致性能损失；而且层间职责划分并不总清晰——「文件系统到底该在第几层？」这类问题会让分层退化为名义分层。

## 3 从简单到分层：一条抽象阶梯

把两个极端放在一起看，就理解了结构演进的逻辑：

| 维度 | 简单结构 | 分层结构 |
| --- | --- | --- |
| 模块边界 | 无强制边界 | 严格层级依赖 |
| 依赖方向 | 任意互调 | 只允许向下依赖 |
| 调试策略 | 整体调试 | 自底向上逐层验证 |
| 性能开销 | 最低 | 每层增加间接性 |
| 可维护性 | 代码量小时尚可 | 适合大型系统 |
| 错误隔离 | 差，一处崩溃全域崩 | 较好，层内相对隔离 |

**辨析｜易错点：** 分层结构 ≠ 层次分明就万事大吉。实际系统中「环形依赖」几乎必然出现——例如文件系统需要内存管理分配缓冲，而内存管理的换页又需要把页写到磁盘、访问文件系统。为此，操作系统普遍采用「层间允许少量横向调用」的务实分层，而不是教科书式的严格分层。**纯粹的严格分层只在教学与协议栈中成立，工程上总是要破例。**

## 4 核心对比表：结构选择的三维权衡

用一张表总结不同结构对应的问题定位：

| 关注点 | 简单结构给出 | 分层结构给出 |
| --- | --- | --- |
| 性能至上 | 直接调用、零间接 | 每层有开销 |
| 可靠性第一 | 难保证 | 层内隔离 |
| 快速演进 | 改动波及面大 | 接口稳定则安全 |
| 学习调试 | 简单直观 | 依赖图清晰 |

后文将要讲的**微内核**、**可加载内核模块**与**混合内核**，都是对「简单」与「分层」两种极端的补救——它们试图同时要性能、可维护性与可扩展性。理解这两个极端，是看懂所有后续内核结构的坐标原点。

## 5 小结

- **简单结构**把所有功能揉在一个二进制里，性能最好、边界最少，适合小系统。
- **分层结构**按依赖方向切成自底向上的层级，每层只向下依赖，调试与维护性好，但有性能损耗与职责划分难题。
- 分层思想跨领域通用：网络协议栈、存储器层次都是同构思路。
- 严格的纯粹分层在工程中不现实，环形依赖需要务实破例。
- 简单与分层是**微内核、模块化、混合结构**的坐标原点，后续几篇将逐一展开。
