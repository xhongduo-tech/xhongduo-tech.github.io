## 为什么从最优置换开始

缺页时要腾页框，换出谁？**页面置换算法（page replacement algorithm）**决定答案。所有置换算法都有一个「理论上限」——**最优置换算法（OPT）**：它总换出「将来最久不会被使用」的页，给出**最小缺页次数**。OPT 不可实现（要预知未来），但它是一把标尺：所有实用算法都拿自己的缺页次数与 OPT 比，差距越小越优秀。<span class="marginnote">回顾《缺页率与 EAT》：缺页率 $p$ 决定虚拟内存性能。置换算法直接决定 $p$ 的高低——选错置换对象，就是给系统添缺页。OPT 给了「$p$ 的下限」，是所有实用算法的对照基准。</span>

OPT 之所以放在置换算法的第一课，是因为它确立了「评价的坐标系」：没有 OPT 这个下界，你就无法判断 FIFO 的 15 次缺页到底是好是坏；有了 OPT 的 9 次，差距一目了然。**先立标尺，再谈优劣**——这是研究一切「可优化问题」的标准姿势。

## 1 置换问题的设定

**页面置换问题**：缺页发生时，若无空闲页框，必须**换出一个驻留页**给新页让位。换出谁？

**页面置换算法**：决定「换出哪个驻留页」的规则。评估指标：**缺页次数/缺页率**——越少越好。

**参考串（reference string）**：进程访问页号的序列，如：

$$7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1$$

评估算法就是在给定参考串与页框数下数缺页次数。

### 为什么用「参考串」评估

参考串是评估置换算法的「测试用例」。真实系统的访问串是无穷的，但评估时只需两类参考串：

- **人工构造串**：专门设计来暴露算法弱点（如制造 FIFO 的 Belady 异常）。
- **真实追踪串**：用性能计数器记录真实程序的内存访问序列，事后离线重放。

**评估口径**：同一参考串 + 同一页框数下比较缺页次数。这个「同题竞技」保证了可比性——置换算法的研究，本质是在一组公开参考串上互相 PK。

## 2 OPT 算法：换出「最久不用」的

**最优置换（OPT, Optimal / MIN）**：缺页时，**换出将来最长时间不会被访问的页**。

对上面的参考串，页框数 = 3，OPT 的做法：每缺页时看「驻留的三页里，谁下次被访问得最晚」，换掉它。

**OPT 的最优性**：对任何参考串与页框数，OPT 的缺页次数**最少**——这是 Belady 在 1966 年证明的（它也是最优性的定义）。

**为什么最优**：把「将来最远才用」的页换走，意味着「近期就要用」的页都保留在内存——每次置换都最大化「未来命中率」。这本质是**贪心选择在置换问题上是全局最优**的特例。

### 一个 OPT 的走查

对参考串 $7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1$、3 个页框，看 OPT 的关键决策：

| 访问 | 内存（换出者） | 决策依据 |
| --- | --- | --- |
| 2（第 4 次） | 7 被换出 | 7 下次在第 18 次才用，最远 |
| 3（第 6 次） | 1 被换出 | 1 下次第 14 次才用；0、2 都快用 |
| 4（第 8 次） | 2 被换出 | 2 下次第 9 次用，但 0、3 用得更早 |

**判据**：缺页时看「驻留页各自的下一次访问位置」，选「位置最远」的换出——这就是「将来最久不用」的可操作定义。整个串跑完，OPT 的缺页次数是 9，是所有算法在该串上的最小值。

## 3 OPT 的致命缺陷：需要预知未来

OPT 要「看穿整个参考串」，而参考串是进程**未来的**访问——**运行前不可能知道**。所以 OPT 不能实际实现，只能：

- **作为理论基准**：衡量其他算法的缺页率下界。
- **在仿真/回放中**：记录真实访问串，事后离线算出「最优缺页次数」，用来评估线上算法。

**辨析｜易错点：** 「OPT 能用于实际系统」是误解。**OPT 只是理论标杆**——真实系统没有「未来访问」信息。但它的价值巨大：**如果一个实用算法在常见负载下的缺页次数接近 OPT，就说明它已经很好了，不值得再优化。** 这给置换算法研究提供了「还差多少」的度量。

另一个易错点：**「OPT 是最小缺页，所以实用算法都要无限逼近它」**——不必。**实用算法（LRU 等）只需在局部性负载上接近 OPT 即可**；而 OPT 的「预知」在现实中的替代品是「局部性假设」：过去常用的页 ≈ 将来常用的页（LRU 正是这么做的）。

### OPT 的「预言」与现实的对应

OPT 的「预知未来」在现实中的替代品，是一个假设：**过去最近访问的页，就是将来最可能访问的页**（局部性原理）。于是：

- OPT「换最久不用的」→ LRU「换最久没用过的」——用「过去」近似「未来」。
- 这个近似的质量决定 LRU 与 OPT 的差距：局部性越强，近似越准，LRU 越接近 OPT。

**理解 OPT 的终极价值**：它是一面「镜子」，照出实用算法离「完美」还差多少——如果 LRU 在常见负载下只比 OPT 多 10%~30% 缺页，说明置换算法已经没有太多优化空间了。

## 4 公式解析：用 OPT 定缺页率下界

设最优缺页次数为 $F_{OPT}$，访问总次数为 $N$，则最优缺页率下界：

$$p_{\min} = \frac{F_{OPT}}{N}$$

- **$F_{OPT}$**：OPT 在给定参考串与页框数下的缺页次数（最小可能）。
- **$N$**：参考串总长（访问总数）。
- **$p_{min}$**：任何置换算法能实现的最小缺页率——**不可能低于它**。

**用法**：设某实用算法缺页 $F$ 次，则它的「相对最优率」为：

$$\text{相对差距} = \frac{F - F_{OPT}}{F_{OPT}}$$

相对差距小 → 算法接近最优；差距大 → 还有优化空间。**OPT 是「缺页次数的标尺」，不是「能用的算法」**——这个「理论上限、实践标尺」的双重身份，让它成为每个置换算法篇章的起点。

### 数值算例：用 OPT 衡量一个实用算法

设访问总次数 $N=10000$，OPT 缺页 $F_{OPT}=200$，某实用算法缺页 $F=260$：

- 最优缺页率下界 $p_{min}=200/10000=2\%$。
- 相对差距 $(260-200)/200=30\%$——该算法比 OPT 多缺 30% 的页。
- 若另一个算法 $F=210$，相对差距仅 $5\%$——它已经很接近最优，再优化的收益有限。

**用法总结**：OPT 给出「还有多少提升空间」的度量。相对差距大 → 值得换算法；差距小 → 当前算法已够好，把精力放到别处。

## 5 核心对比表：OPT 与实用算法的关系

| 维度 | OPT | 实用算法（LRU/FIFO） |
| --- | --- | --- |
| 选择依据 | 将来最久不用 | 过去的使用历史 |
| 需要未来信息 | 是 | 否 |
| 可实现 | 否（理论标杆） | 是 |
| 缺页次数 | 最少（下界） | ≥ OPT |
| 作用 | 度量上限 | 实际使用 |

## 6 小结

- **页面置换**：缺页无空闲页框时决定换出谁；指标是缺页次数/缺页率；评估用「参考串 + 同页框数」的同题竞技。
- **OPT**：换出「将来最久不用」的页，缺页次数**最少**（理论下界）——Belady 1966 年证明其最优性。
- OPT 的判据可操作化：看驻留页的下一次访问位置，选「位置最远」的换出。
- OPT 需要**预知未来**，不可实现，只能作理论基准与离线评估；其「预言」由「过去 ≈ 未来」的局部性假设替代（LRU 的思路）。
- 用 OPT 定**缺页率下界** $p_{min} = F_{OPT}/N$，相对差距 $(F-F_{OPT})/F_{OPT}$ 衡量算法好坏。
- 数值例：$F_{OPT}=200$、$F=260$ 时相对差距 30%；$F=210$ 时仅 5%，后者已近最优。
- 相对差距大 → 值得换算法；差距小 → 已够好，优化收益有限。
