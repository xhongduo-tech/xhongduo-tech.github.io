## 为什么从文件系统层次结构开始

第十一篇讲的是文件系统的**用户视角**（接口），第十二篇转向**实现视角**（内部怎么建）。文件系统的实现不是一坨代码，而是分层的：最上面是通用的虚拟文件系统层，中间是具体文件系统的逻辑结构，最下面是物理存储。理解这个分层，才能看懂为什么一个 Linux 能同时跑 ext4、XFS、NTFS、NFS 而应用毫无感知。<span class="marginnote">回顾《操作系统结构》的分层思想：层与层之间通过接口解耦。文件系统分层是这一思想最彻底的应用——VFS 层把「文件系统」抽象成统一接口，每种具体文件系统只是这个接口的一种实现。</span>

## 1 文件系统的三层结构

**文件系统（file system）**的实现分三层：

**逻辑文件系统（logical file system）**：管理**元数据**——目录、文件控制块（inode）、文件结构。负责「文件是什么、目录怎么组织」。
**文件组织模块（file-organization module）**：把逻辑块地址翻译成物理块地址，管理**空闲空间**与**分配**（见后续几篇的连续/链接/索引分配）。
**基本 I/O 系统（basic I/O system）**：与设备驱动交互，执行底层块读写（`read_block`/`write_block`）。

```text
应用程序
   │ 系统调用
   ▼
逻辑文件系统        ← 元数据：inode、目录、超级块
   │
   ▼
文件组织模块        ← 逻辑块 → 物理块映射、空闲空间管理
   │
   ▼
基本 I/O 系统       ← 与设备驱动交互、块读写、缓冲
   │
   ▼
设备驱动 → 磁盘硬件
```

**数据流向**：应用请求 → 层层向下，最终落到磁盘块；返回时反向层层向上。

## 2 虚拟文件系统 VFS：统一一切文件系统的门面

**虚拟文件系统（VFS, Virtual File System）**：内核中位于系统调用之下的一层抽象，它定义了一套**统一的文件操作接口**，让不同文件系统（ext4、XFS、NFS、proc…）都以同一套方式被调用。

**VFS 的核心**：**对象 + 操作表（vtable）**：

**inode 对象**：统一表示「文件/目录」（无论底层是 ext4 还是 NFS）。
**dentry 对象**：统一表示「目录项」（路径中的一个名字）。
**file 对象**：统一表示「打开的文件」（对应文件描述符）。
**superblock 对象**：统一表示「整个文件系统」。
每个对象挂一张**操作函数表**——`inode_operations`、`dentry_operations`、`file_operations` 各有各的实现，但都通过同一张 VFS 操作表接口调用。

**VFS 的价值**：

**插件式文件系统**：加载新文件系统 = 注册一组操作表，应用零改动。
**统一接口**：`open`、`read`、`write` 不管底层是什么，走同一套 VFS 调用。
**支撑「一切皆文件」**：proc（进程信息）、sysfs（设备）、pipe（管道）都是「挂到 VFS 下的特殊文件系统」。

**辨析｜易错点：** 「VFS = 一种文件系统」是误解。**VFS 不是存储数据的文件系统，而是「文件系统的接口层」**——它本身不存数据，只是把「文件操作」翻译给具体的文件系统。你可以把 VFS 理解为「文件系统的插件系统」。

## 3 层与层之间：on-disk 结构

文件系统在磁盘上也要组织成层次（on-disk layout），典型结构：

| 磁盘区域 | 内容 |
| --- | --- |
| 引导块（boot block） | 启动引导代码 |
| 超级块（superblock） | 文件系统全局信息（块大小、总块数、空闲计数、inode 区位置） |
| inode 区 | 所有文件控制块（inode）集中存放 |
| 数据块区 | 文件数据与目录内容 |

**on-disk 与 in-memory 对应**：超级块、inode 表、目录在磁盘上有持久版本，运行时加载进内存并维护缓存（页缓存、inode 缓存）——**VFS 对象是「内存中的镜像」，磁盘结构是「持久化的真身」**。<span class="marginnote">「内存镜像 vs 磁盘真身」的对应关系，是文件系统正确性的关键：写文件要同时更新内存缓存与（最终）磁盘结构；崩溃时若两者不一致，就需要日志/一致性检查恢复（见《日志文件系统》）。这也是 ext4 等文件系统做日志的原因。</span>

## 4 核心对比表：三层各自的职责

| 层次 | 管什么 | 典型内容 | 代表概念 |
| --- | --- | --- | --- |
| 逻辑文件系统 | 元数据、结构 | inode、目录、超级块 | 文件组织 |
| 文件组织模块 | 块映射、分配 | 逻辑块→物理块、空闲表 | 分配方法 |
| 基本 I/O 系统 | 块读写 | 读写盘、缓冲 | 设备驱动 |

**设计启示**：文件系统的三层分层 + VFS 抽象，让「格式」（ext4 vs XFS vs NFS）与「语义」（本地 vs 网络 vs 虚拟）都变成了**可插拔的实现**。这个「抽象接口 + 可插拔实现」的模式，正是操作系统架构的最高级形式——你会在设备驱动、网络协议栈里看到同样的结构。

## 5 小结

- 文件系统实现分三层：**逻辑文件系统**（元数据）、**文件组织模块**（块映射）、**基本 I/O 系统**（块读写）。
- **VFS** 提供统一文件操作接口，让 ext4/NFS/proc 等以同一套接口被调用。
- VFS 核心是**对象 + 操作表**：inode/dentry/file/superblock + 各自的函数表。
- on-disk 结构：**引导块、超级块、inode 区、数据块区**；内存对象是磁盘结构的镜像。
- VFS 是「文件系统的插件系统」，「一切皆文件」的支撑。
