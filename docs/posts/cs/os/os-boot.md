## 为什么从系统生成与引导开始

前五篇讲的是「操作系统运行时长什么样」，这篇回答一个更基础的问题：**操作系统是怎么被造出来、又是怎么被「唤醒」的？** 一台刚上电的机器，内存是空的、没有进程、没有内核，从「一坨硅片」到「跑着一个操作系统、能登录、能跑容器」——这条路上的每一步都藏着对前面所学概念的总复习：内存、中断、设备、进程，全部在启动中被首次激活。<span class="marginnote">引导是「先有鸡还是先有蛋」问题的计算机版本：内核要运行就需要内存与驱动，但内核本身还没被加载，谁来干第一件事？答案是一级级接力——硬件、固件、引导程序、内核。</span>

## 1 操作系统的生成（SYSGEN）

**操作系统的生成（system generation, SYSGEN）**：根据特定机器的硬件配置，从操作系统源码或预编译组件「组装」出一份适合该机器的内核。早期操作系统必须为每台机器重新生成，因为当时的硬件千差万别，没有统一的驱动接口。

生成时要确定的信息包括：

CPU 类型与数量、是否支持特定扩展指令集。
可用内存总量与地址空间布局。
可用设备及型号（磁盘、网卡、显卡）。
需要装载的模块与内核选项。

现代 Linux 用「发行版 + 内核配置（`.config`）+ 模块化驱动」基本消灭了手动 SYSGEN：内核把几乎一切做成模块，启动时再自动探测硬件、动态加载对应驱动。<span class="marginnote">现代意义上的「生成」还在，只是变懒了：Ubuntu 内核几乎内置全部驱动，启动时靠 udev 探测硬件再加载模块。生成从「编译期决策」变成了「运行期决策」。</span>

## 2 引导（Boot）：从复位到内核

**引导（bootstrap / boot）**：上电后，把操作系统内核从磁盘加载进内存并开始运行的过程。引导必须靠**引导程序（bootstrap loader）**逐级接力：

1. **硬件复位**：CPU 从固件入口开始执行——传统 BIOS 从固定地址取第一条指令；现代 UEFI 从固件 ROM 启动。
2. **固件初始化**：BIOS/UEFI 做加电自检（POST），探测内存与设备，建立设备表。
3. **加载引导程序**：固件从启动磁盘的第一个扇区（或 EFI 系统分区）读取引导程序，如 Linux 世界的 **GRUB**。
4. **引导程序加载内核**：GRUB 根据配置找到内核镜像（`vmlinuz`）与初始 RAM 盘（`initramfs`），装入内存，把控制权交给内核。
5. **内核初始化**：内核建立页表、初始化内存管理、创建第一个进程（`idle`（PID 0） / `init`（PID 1）），挂载根文件系统。
6. **进入用户态**：`init`（systemd）启动各项系统服务，最终呈现登录提示或桌面。<span class="marginnote">`initramfs`/`initrd` 是个精妙的接棒机制：根文件系统在磁盘上，但磁盘驱动可能没加载——所以先加载一个「内存里的迷你根文件系统」，靠它挂载真正的磁盘根文件系统，再 pivot_root 切换过去。</span>

## 3 Linux 的现代启动路径

现代 Linux（UEFI + systemd）的启动链路可以写成一条清晰的接力线：

```
上电 → UEFI 固件 → GRUB → vmlinuz（内核镜像）→ initramfs（初始 RAM 盘）→ systemd（PID 1）→ 登录界面/桌面
```

每一步都向后移交「更大的能力」：固件只会认磁盘与加载，GRUB 会认文件系统与选内核，内核会管全部资源，systemd 负责拉起用户态世界。**越往后，抽象层级越高，职责越重。**<span class="marginnote">systemd 是 Linux 世界的 SysVinit 继任者，它用并行化加速启动、用 cgroup 跟踪服务、用 socket 激活懒加载守护进程——你会发现它几乎就是「进程管理的用户态操作系统」。</span>

## 4 数值算例：一次启动的时间都花在哪

「开机慢」人人有感知，但慢在哪里？把一次现代 Linux 桌面启动的 12 秒拆开看（典型笔记本、SSD、UEFI）：

| 阶段 | 耗时 | 说明 |
| --- | --- | --- |
| 固件 POST + UEFI 初始化 | 约 2 s | 自检内存与设备，可并行化但常受硬件牵制 |
| 固件 → GRUB | 约 1 s | 读取 EFI 分区、加载引导程序 |
| GRUB → 内核 + initramfs | 约 2 s | 解压内核、装载初始 RAM 盘、挂载根文件系统 |
| systemd 启动服务 | 约 7 s | 拉起 systemd-journald、网络、图形栈、登录管理器 |

关键的结论是：**真正的瓶颈几乎总是最后一段**——用户态服务的启动。systemd 的并行化（把互不依赖的服务同时拉起）能把串行启动的 30 秒压到几秒；而换成机械硬盘，initramfs 加载那一项会暴涨数秒，因为解压与读盘都慢。<span class="marginnote">可以动手验证：`systemd-analyze blame` 会列出每个服务启动耗时排序，`systemd-analyze critical-chain` 画出最长关键路径——你会发现「开机慢」多半是某个服务在等网络或等锁。</span>

## 5 引导故障排查速查

启动链路每一环都可能断，故障现象与排查方向是一一对应的：

| 症状 | 可能原因 | 排查方向 |
| --- | --- | --- |
| 启动停在 GRUB 菜单 | 找不到内核或根分区 | 检查 `/etc/fstab`、GRUB 配置是否指向正确分区 |
| 内核 panic：VFS：Unable to mount root fs | initramfs 缺驱动或根文件系统损坏 | 用急救盘挂载根分区，重建 initramfs |
| 黑屏、无登录界面 | 显卡驱动未加载 | 进单用户模式（`systemd.unit=rescue.target`）检查驱动 |
| 启动慢、卡在某服务 | 某服务等待超时（常是网络） | `systemd-analyze blame` 定位，改依赖或禁用 |

**辨析｜易错点：** 「引导出问题 = 系统坏了，只能重装」是新手常见焦虑。绝大多数引导故障是**分区表 / fstab / initramfs 三者错位**造成的，与数据无关——用 Live 光盘挂载后修一处配置就能恢复；真正需要重装的情形（盘阵物理损坏等）反而少得多。<span class="marginnote">记住一条保命命令：`grub-install /dev/sda && update-grub` 可以在 Live 环境里重建引导程序；而「能开机但进不了系统」多从 `rescue.target` 入手，比重装快得多。</span>

## 6 内核启动参数与引导日志

引导的最后一个旋钮是**内核命令行（kernel command line）**——传给内核的参数，是排查启动故障时最常动的地方。它在 GRUB 里由 `/etc/default/grub` 的 `GRUB_CMDLINE_LINUX` 配置，常用的有：

| 参数 | 作用 | 典型场景 |
| --- | --- | --- |
| `quiet` | 隐藏启动日志，加快观感 | 正常发行版默认 |
| `nomodeset` | 禁用显卡内核模式设置（KMS） | 黑屏排查：先用它进系统再装驱动 |
| `systemd.unit=rescue.target` | 进单用户救援模式 | 修复 fstab、密码、损坏服务 |
| `mem=4G` | 强制内核只看到 4G 内存 | 内存故障定位、压测 |
| `root=/dev/sda2` | 手动指定根分区 | 根分区识别失败时 |

配合日志能还原故障现场：**内核日志**用 `dmesg` 查看，**本次启动的用户态日志**用 `journalctl -b`（`-b -1` 看上上一次启动）。故障排查的经典套路就是「改启动参数 → 进救援模式 → 看日志 → 修配置 → 重启验证」。

值得停下来看的是：引导过程本身就是整门操作系统课程的一次**总复习**——内核初始化要建页表（内存管理）、装中断描述符表（中断机制）、枚举设备（I/O 子系统）、启动第一个进程 `init`（进程管理）。**「开机」不是一条孤立流水线，而是把前面十几篇的概念按时间顺序重新激活了一遍。**<span class="marginnote">把这层关系钉在心里：你在《进程》《内存管理》《中断机制》里学的每个概念，在 `dmesg` 的开头几行都能找到对应物。这也是「学操作系统最好的练习之一是研究一次开机日志」这句老话的来历。</span>

## 7 核心对比表：BIOS 传统引导 vs UEFI 引导

| 维度 | BIOS + MBR | UEFI + GPT |
| --- | --- | --- |
| 固件接口 | 16 位实模式 | 32/64 位保护模式 |
| 磁盘分区表 | MBR（最多 4 主分区） | GPT（128+ 分区） |
| 引导程序位置 | 固定第一扇区（512B） | EFI 系统分区（FAT32） |
| 可扩展性 | 差，引导程序容量受限 | 好，支持安全启动 Secure Boot |
| 现代趋势 | 正在淘汰 | 标准方案 |

**辨析｜易错点：** 「重启一下系统就干净了」是常见误解。引导只重置内存中的运行时状态，**磁盘上的文件系统、数据、持久化配置并不会因重启而清空**；相反，崩溃后重启还要依赖日志文件系统（见《日志文件系统与崩溃恢复》）来修复不一致。重启是「换一套内存」，不是「换一块磁盘」。

## 7 小结

- **系统生成（SYSGEN）**：按硬件配置组装内核；现代系统靠模块化与动态探测取代手动生成。
- **引导**是固件 → 引导程序 → 内核 → init 的逐级接力，每一级都比上一级能力更强。
- Linux 现代路径：**UEFI → GRUB → vmlinuz → initramfs → systemd**。
- 传统引导用 BIOS+MBR，现代标准是 UEFI+GPT，并支持安全启动。
- 重启只重置内存运行时状态，磁盘数据由日志文件系统负责一致性。
- 启动耗时大多花在 systemd 服务段，`systemd-analyze blame` 可定位瓶颈。
- 内核命令行（`quiet`、`nomodeset`、`systemd.unit=rescue.target`）是排查启动故障的入口。
- 引导过程是整门课程的总复习：页表、中断、设备、init 进程按时间顺序被逐一激活。
