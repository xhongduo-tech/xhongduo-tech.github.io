## 为什么从死锁恢复开始

检测算法报告了「谁被卡住」，接下来必须**打破死锁**。恢复（recovery）有两大流派：**终止进程**（杀死卡住的进程）与**剥夺资源**（抢走资源给别的进程）。这一节看这两派的手段、代价与选择策略——它也是死锁章节的收尾，讲完恢复，四种处理策略就完整了。<span class="marginnote">回顾总览：检测与恢复是一对。恢复的两大手段分别对应死锁四条件里的「打破循环等待」（终止进程）与「打破不可剥夺」（剥夺资源）。恢复是「暴力解」，目标是尽快打破僵局，不求优雅。</span>

## 1 恢复手段一：进程终止

**进程终止（process termination）**：强制终止一个或多个死锁进程，打破循环等待，释放其资源给其他进程。

两种策略：

**终止所有死锁进程**：简单、彻底，但代价巨大——可能终止大量无辜进程，浪费大量已完成的工作。
**逐个终止，直到死锁解除**：每终止一个就重新检测；终止数量最少，但每次终止都要重跑检测算法。

**终止谁？** 选择标准（按代价）：

进程的**优先级**（终止低优先级的）。
进程**已运行时间**与**还差多少完成**（牺牲快完成的太亏）。
进程使用的资源**数量与类型**（终止占资源多的，释放多）。
进程还需要多少资源（终止「还要更多」的，因为它更难满足）。
**是否交互式**（交互进程终止用户能感知，优先终止批处理进程）。

**工程视角**：数据库系统里「终止一个事务」就是「回滚事务」——被终止的进程回到事务起点，代价是已做的修改被撤销。<span class="marginnote">数据库的「回滚」是最温和的进程终止：事务是可恢复的，回滚后重新执行即可。而通用操作系统里进程终止不可恢复——用户辛辛苦苦跑的计算全部丢失。这解释了为什么数据库敢用「检测+恢复」，通用 OS 却宁可「忽略」。</span>

## 2 恢复手段二：资源剥夺

**资源剥夺（resource preemption）**：从死锁进程手中**强行夺走**部分资源，分配给其他进程，打破死锁。

资源剥夺要解决三个问题：

- **选择被剥夺者**：剥夺哪个进程的资源？通常选择「牺牲代价最小」的进程（占资源多、运行时间短的优先被剥夺）。
- **回滚**：被剥夺的进程怎么办？不能继续执行（资源没了），必须**回滚到安全状态**。安全状态需在死锁前建立检查点（checkpoint），被剥夺后从检查点重跑。**检查点是回滚的基础**——没有检查点，剥夺后进程不知道回到哪。
- **防止饥饿**：如果总是剥夺同一个进程，它会反复被抢、反复回滚——**饥饿**。必须保证「每个进程最多被剥夺有限次」（如记录剥夺次数，超过阈值改为终止）。

**辨析｜易错点：** 「剥夺资源 = 让被剥夺的进程等待，等资源回来了再继续」是常见误解。**被剥夺后进程必须回滚重跑，不是原地等待**——它已经用了一部分资源、改了一部分状态，直接等待会带着「半完成状态」继续，可能再次死锁。**剥夺与回滚是一体的，光剥夺不回滚等于没解决。**

## 3 两种手段的对比

| 维度 | 进程终止 | 资源剥夺 |
| --- | --- | --- |
| 打破的条件 | 循环等待 | 不可剥夺 |
| 对进程的影响 | 直接死亡（不可恢复） | 回滚重跑（可恢复） |
| 代价 | 已完成工作全部丢弃 | 回滚开销 + 检查点存储 |
| 适用 | 进程不可恢复的通用系统 | 进程可回滚的事务系统 |
| 饥饿风险 | 无（终止即消失） | 有（反复剥夺） |

## 4 恢复策略的选择：一张决策表

死锁恢复没有银弹，选择取决于系统特性：

| 系统特性 | 推荐恢复手段 |
| --- | --- |
| 进程工作不可恢复（通用 OS） | 终止牺牲代价最小的进程 |
| 进程可回滚（数据库事务） | 资源剥夺 + 回滚 |
| 实时系统（不容许长时间僵持） | 终止，快速打破死锁 |
| 进程占资源差异大 | 先剥夺/终止「占资源多」的 |

**核心原则**：**恢复是「最不坏」的选择**——死锁已经发生，任何恢复都伴随损失，目标只是「以最小代价尽快恢复」以及「不因恢复引入新的问题（饥饿）」。

**设计启示**：检测 + 恢复这套组合拳的真正价值，在于它**不需要预防或避免的前提**（不需要破坏资源利用率、不需要预知最大需求），代价是「偶尔的死锁损失」。数据库与银行系统选择它，正是权衡了「极少发生的死锁损失」与「持续的利用率/信息优势」之后的结果。

## 5 小结

- **进程终止**：终止一个或多个死锁进程，打破循环等待；选「代价最小」者（低优先级、少已运行、多资源）。
- **资源剥夺**：抢走资源并**回滚**被剥夺者到检查点；需要检查点支撑，且要防反复剥夺导致的饥饿。
- 剥夺与回滚是一体——光剥夺不回滚等于没解决。
- 终止适合不可恢复进程，剥夺适合可回滚事务。
- 恢复是「最不坏」的选择，检测+恢复以「偶尔损失」换「免预防前提」。
