## 为什么从请求分页开始

虚拟内存的理论基石是「只装用到的页」，但「用到时怎么装」还没讲。**请求分页（demand paging）**是虚拟内存的落地机制：**进程的页不是全部装入内存，而是「用到哪页、才调哪页」**——这一「按需调入」的瞬间，由**缺页中断（page fault）**触发。这一节把「页面调入」的完整流程走一遍，它是虚拟内存性能的分水岭。<span class="marginnote">回顾《分页》与《虚拟内存》：分页给了「页表」这张地图，虚拟内存给了「地图上很多页不驻留」的约定。请求分页就是「地图上的页缺失时，怎么把真页找回来」的执行协议。</span>

这一节与「局部性原理」直接呼应：请求分页之所以可行，是因为进程运行时**只访问一小部分页**（工作集），其余页几乎不被碰。把不碰的页也装入内存，是纯浪费；请求分页把「浪费」降到零，代价是「缺页时的一次磁盘等待」。

## 1 请求分页：用哪页调哪页

**请求分页（demand paging）**：进程启动时**不装入任何页**（或只装极少数），运行中每当访问一个尚未装入的页，就触发调入该页——**只有被访问的页才进入内存**。

页表项因此多了一个关键位：**有效位/存在位（valid-invalid bit）**。

**有效（valid）**：该页在内存中，页表项给出页框号，正常访问。
**无效（invalid）**：该页不在内存中（在磁盘上，或根本未分配），访问时触发缺页中断。

页表项还记录**页在磁盘上的位置**（如交换区（swap）或可执行文件中的偏移），供调入时使用。

**辨析｜易错点：** 「请求分页 = 启动时把所有页都装上」是误解。**请求分页恰恰相反——「惰性装入」**：只在访问时调入，从不多装。这也让进程**启动更快**（不用把整个可执行文件读入内存）且**内存占用更少**。

### 缺页的两个来源：文件页与交换页

缺页中断要调页，但页的来源有两种，处理方式不同：

- **文件后备（file-backed）**：页的内容来自磁盘上的文件（如可执行代码、mmap 的文件）。首次访问时从**文件**读入；被换出后再访问，也从文件重新读入——**文件本身就是「原始副本」，不需要额外保存**。
- **匿名页（anonymous）**：页的内容是进程自己产生的（栈、堆、动态数据），没有文件作为原始副本。这类页被换出时必须写入**交换区（swap）**，否则内容就丢了。

**判断依据**：页表项里有没有「页在哪个文件」的信息。代码页永远可以从可执行文件恢复，堆页只能靠 swap 救——这也是「为什么 swap 分区不能没有」的原因。

**术语速查**：

| 术语 | 含义 |
| --- | --- |
| 请求分页 | 用哪页调哪页，惰性装入 |
| 有效位 | 页表「驻留 / 在盘」标志 |
| 缺页中断 | 访问无效页触发的硬件中断 |
| 文件后备页 | 内容可从文件恢复的页 |
| 匿名页 | 内容只能靠 swap 保存的页 |

## 2 缺页中断：请求分页的心脏

**缺页中断（page fault）**：进程访问一个页表项为「无效」的页时，硬件触发的中断，交给操作系统处理。

**页面调入的完整流程（六步）**：

1. 进程访问逻辑地址，MMU 查页表，发现该页「无效」。
2. 硬件触发**缺页中断**，CPU 切换到内核态。
3. 操作系统检查页表项：若访问**非法**（地址超出进程空间）→ 终止进程；若访问**合法**（页确实属于进程，只是在磁盘上）→ 继续。
4. 找空闲页框；若没有，先执行**页面置换**（见后续几篇），换出一个页腾位置。
5. **从磁盘把页调入页框**（磁盘 I/O）。
6. 更新页表项为「有效」，**重新执行**刚才中断的那条指令——这次命中。

**关键细节**：第 6 步是「重新执行指令」，不是「从下一条继续」——因为缺页发生时那条指令**没执行完**（取指或访存失败），必须重跑。这正是缺页中断与普通中断的一大区别。

### 一次缺页的完整时间线

以「访问一个从未用过的堆页」为例，把六步串成时间线：

| 时刻 | 事件 | 谁在执行 |
| --- | --- | --- |
| t0 | 进程访问地址，MMU 查页表 | 硬件 |
| t1 | 页表项无效 → 触发缺页中断 | 硬件 → OS |
| t2 | 合法性检查（地址在进程空间内） | OS |
| t3 | 分配/置换页框 | OS |
| t4 | 从 swap 读入页（毫秒级） | OS + 磁盘 |
| t5 | 更新页表、返回用户态 | OS |
| t6 | 重新执行原指令，命中 | 硬件 |

注意 t4 是唯一「真慢」的环节——**一次缺页 = 一次磁盘 I/O**，这就是缺页率决定性能的原因。t0 到 t1 由硬件完成，微秒级；t2 到 t5 由 OS 完成；真正的时间大头全在磁盘。

## 3 缺页中断的「重新执行」陷阱

**辨析｜易错点：** 缺页中断处理完**必须重新执行原指令**，而普通中断处理完是「从下一条继续」。这个区别藏着一个经典难题：**一条指令可能访问多个地址**（如 x86 的 `REP MOVSB` 块移动指令一次搬多个字节），如果只调入了第一个页、第二个页又缺页怎么办？

解决方案：

硬件设计成「缺页时指令的中间状态可恢复」——把寄存器、PC 保存到可重放状态。
或用**预取/预映**：复杂指令涉及的页尽量提前调入。
现代 CPU 与 OS 配合：页错误发生后，CPU 保证指令可以从头重放。

**核心认识**：缺页中断的「重放语义」要求 CPU 与 OS 精细配合——这也是为什么虚拟内存需要硬件支持（不只软件能做）。<span class="marginnote">「缺页 → 重放指令」是硬件/软件协作的经典案例：CPU 负责在缺页时精确保存现场（保证指令可重放），OS 负责调入页并更新页表。谁偷懒，进程就可能在「半执行状态」上崩溃——这是虚拟内存能工作的隐藏契约。</span>

## 4 请求分页的性能要点

请求分页的性能由**缺页率（page-fault rate）**决定——有效访问时间公式见下一节，这里先给结论：

- **缺页率极低（<0.001）**：请求分页的性能几乎与「全部装入」无异——因为绝大多访存都命中。
- **缺页率升高**：每缺一页就是一次磁盘 I/O（毫秒级），性能断崖式下跌。
- **预读（prefetching）**：按局部性原理，调入一页时把**相邻页也调进来**，减少后续缺页（空间局部性的利用）。

**请求分页的关键权衡**：**调入的粒度（页大小）**——页大则每次 I/O 调入多、缺页次数少但浪费多；页小则精确但缺页频繁。现代页大小（4KB~2MB）就是在这两者间的折中。

**预读的粒度权衡**：预读多调入几页，减少后续缺页，但也可能调入用不到的页（浪费磁盘带宽与内存）。现代系统用「顺序检测 + 动态窗口」：只在检测到顺序访问模式时预读，且预读量随顺序性增强而加大——这是「空间局部性」与「别浪费」之间的平衡。

**辨析｜易错点：** 「进程启动时要预热，把所有页都装入」是常见误解——这正是请求分页要避免的。**启动时预装入所有页，等于放弃请求分页的全部好处**（启动慢、内存占用大），且大部分页可能永远用不到（浪费）。真实系统只在极少数场景（如实时系统要保证最坏延迟）才预装入。

## 5 核心对比表：缺页中断 vs 普通中断

| 维度 | 普通中断 | 缺页中断 |
| --- | --- | --- |
| 触发 | 外部设备/定时器 | 访问无效页 |
| 处理完从哪继续 | 下一条指令 | **重新执行原指令** |
| 处理内容 | 设备服务 | 调入页 + 更新页表 |
| 是否可重放 | 否（继续即可） | **必须可重放** |

## 6 小结

- **请求分页**：按需调入，用哪页调哪页；进程启动快、内存占用少。
- 页表项有**有效位**：有效=驻留、无效=在磁盘；访问无效页触发**缺页中断**。
- 缺页来源两种：**文件后备页**（从文件读回）与**匿名页**（靠 swap 保存）——代码页永远可恢复，堆页只能靠 swap。
- 缺页处理六步：查页表→中断→合法性检查→找页框（必要时置换）→磁盘调入→**重新执行原指令**；时间线中 t4（磁盘调入）是唯一的时间大头。
- 缺页中断「重放原指令」与普通中断「继续下一条」本质不同；复杂指令需要 CPU 保证可重放。
- 请求分页与局部性原理呼应：只装工作集内的页；预读只用于顺序访问，动态窗口平衡「少缺页」与「别浪费」。
- 预装入只用于保证最坏延迟的实时场景，平时放弃请求分页是自缚手脚。
- 性能由**缺页率**决定，缺页率 <0.001 时请求分页几乎免费，升高则每缺一页一次磁盘 I/O、断崖式恶化。
