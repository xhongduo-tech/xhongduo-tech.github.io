## 为什么从链接与装入开始

上一篇讲逻辑地址与物理地址的翻译，但还没回答：**程序文件里的地址是怎么来的？** 一个已编译好的 ELF 可执行文件在磁盘上，它内部记录的地址到底是逻辑地址、物理地址、还是别的什么？答案藏在「链接与装入」这两步——它们决定了地址在什么阶段被确定，也就决定了进程能不能「搬家」。<span class="marginnote">回顾上一节的「重定位」：进程可以装在任何物理位置，靠 MMU 基址翻译。但「程序里的地址怎么写的」由链接与装入决定——<strong>地址在哪个阶段确定</strong>，是本节的主线。</span>

## 1 三步走：编译、链接、装入

**编译（compile）**：把源码翻译成目标文件（`.o`），地址是**相对地址**——从 0 开始的逻辑地址，尚未确定最终位置。
**链接（link）**：把多个目标文件与库合并成一个可执行文件，解决符号引用，生成完整的**逻辑地址空间**。
**装入（load）**：把可执行文件读入内存，建立地址映射，准备执行。

装入又有三种方式，地址确定的时机不同：

| 装入方式 | 地址何时确定 | 是否需要重定位 |
| --- | --- | --- |
| 绝对装入 | **编译/汇编时**就确定物理地址 | 不需要 |
| 可重定位装入 | **装入时**确定物理地址 | 需要（重定位器） |
| 动态运行时装入 | **运行期间**才确定 | 需要（硬件 MMU 支持） |

## 2 三种装入方式详解

**绝对装入（absolute loading）**：编译时就生成**物理地址**，装入时直接把程序放到这个物理位置。

优点：简单，装入器什么都不用做。
缺点：**程序只能装在固定位置**，无法重定位——同一份代码换个位置就废了。现代系统**绝不使用**（除了早期批处理系统与一些固件）。

**可重定位装入（relocatable loading）**：编译生成**逻辑地址**，装入时由**重定位器（relocator）**根据「程序将被装入的物理基址」，把程序中的每个逻辑地址加上基址，**写死成物理地址**。

装入时一次性翻译所有地址，之后程序运行不再需要重定位。
优点：程序可以装在任意位置（只要基址告诉重定位器）。
缺点：**一旦装入就不能移动**——移动就又要重写地址。

**动态运行时装入（dynamic run-time loading）**：编译生成逻辑地址，**装入时不翻译**，运行时每次访问地址都由 **MMU** 现场翻译（逻辑地址 + 重定位寄存器）。

优点：**程序在内存里可以移动**——只要改一下重定位寄存器，整个进程就「搬家」了；甚至同一份代码可以被多个进程共享（各自基址不同）。
缺点：需要**硬件 MMU 支持**，翻译发生在每次访存，有开销（用 TLB 加速，见《快表 TLB》）。<span class="marginnote">动态运行时装入是现代系统的标配：Linux 的可执行文件 ELF 就用它，配合分页让进程「看似独占内存、实则可共享代码段」。它是「逻辑地址真正解耦物理地址」的完成形态——程序彻底不知道也不关心自己在物理内存的哪个角落。</span>

## 3 链接的两种方式：静态与动态

与装入并行的是**链接方式**：

**静态链接（static linking）**：程序用到的库代码**在链接期**被拷贝进可执行文件。优点：自包含、不依赖系统库版本；缺点：文件大、升级库要重新编译。
**动态链接（dynamic linking）**：程序只记录库的**引用**（名字 + 符号），运行时由**动态链接器（dynamic linker, ld.so）**把库装入内存、解析引用。优点：库只存一份、升级库无需重编程序；缺点：运行时依赖库存在，首次加载稍慢。

动态链接还允许**共享库在多个进程间共享同一份物理内存**（代码段只读共享）——这是「省内存」的重要手段，也是「动态运行时装入 + 分页」的现实组合。<span class="marginnote">你电脑上几乎每个程序都动态链接 libc（C 标准库）。几百个进程共享一份 libc 的代码页，而不是每人复制一份——这就是为什么动态链接「省内存」的具体机制，也解释了为什么改一个库 bug 全系统受益。</span>

**动态链接的工程细节**：Linux 的动态链接依赖 **PLT（过程链接表）与 GOT（全局偏移表）**——程序调用库函数时先走 PLT，第一次调用触发 `ld.so` 把库函数真实地址填入 GOT，之后直接跳转。这种**延迟绑定（lazy binding）**让程序启动只解析真正用到的符号，而不是一次性解析全部依赖；`ldd` 命令则能列出程序依赖的所有共享库。这套机制让「动态链接省内存、省启动时间」从理念变成可运行的现实。

## 4 核心对比表：三种装入方式

| 维度 | 绝对装入 | 可重定位装入 | 动态运行时装入 |
| --- | --- | --- | --- |
| 地址确定 | 编译期 | 装入期 | 运行期 |
| 能否移动 | 否 | 否 | **是** |
| 硬件需求 | 无 | 无 | MMU |
| 现代使用 | 几乎不用 | 早期 OS | **现代 OS 标配** |
| 内存共享 | 不可能 | 不可能 | 可能 |

**辨析｜易错点：** 「可重定位装入 = 动态链接」是常见混淆。**可重定位装入关心「物理地址什么时候定」，动态链接关心「库代码什么时候合并进进程」**——两个正交的概念。动态运行时装入的进程同样可以静态链接（库提前编入文件）或动态链接（运行时才解析库）。**装入管「地址」，链接管「符号」，别混为一谈。**

## 5 数值算例：一个地址的三种命运

设某进程代码段从逻辑地址 `0x1000` 开始，可执行文件要装入物理基址 `0x8000`。三种装入方式对这个逻辑地址的处理完全不同：

| 装入方式 | 逻辑地址 0x1000 的结局 | 程序能否移动 |
| --- | --- | --- |
| 绝对装入 | 编译期就写死为物理地址 `0x1000` | 否（必须装在 0x1000） |
| 可重定位装入 | 装入期重定位器把它改写成 `0x9000`（0x8000+0x1000），写进内存 | 否（装完就固定） |
| 动态运行时装入 | 保持 `0x1000` 不变，每次访存 MMU 现场算 `0x9000` | **是**（改重定位寄存器即可） |

**「能否移动」的差异就是现代系统选择动态运行时装入的原因**：多道程序环境下，内存里几十个进程随时可能换入换出、压缩整理，若程序一装定死，每次内存整理都要重写地址。动态运行时装入让「移动进程」变成「改一个寄存器」——这就是重定位寄存器在《上下文切换》里被反复保存/恢复的深层意义。<span class="marginnote">一个易混点：动态链接和动态装入都带「动态」，但一个是「库代码运行时才合并」，一个是「地址运行时才翻译」。「动态」二字在这里各自独立，别互相套用——先分清是「链接阶段」还是「装入阶段」。</span>

## 6 术语速查

| 术语 | 含义 |
| --- | --- |
| 编译 | 源码 → 目标文件，地址为相对地址 |
| 链接 | 目标文件与库合并，生成完整逻辑地址空间 |
| 装入 | 可执行文件读入内存，建立地址映射 |
| 绝对装入 | 编译期确定物理地址，不能移动 |
| 可重定位装入 | 装入期把逻辑地址改写为物理地址 |
| 动态运行时装入 | 运行期由 MMU 现场翻译，可移动可共享 |
| 静态链接 | 库代码在链接期拷贝进可执行文件 |
| 动态链接 | 运行时由 ld.so 解析库引用，库跨进程共享 |

## 7 小结

- 程序生命周期三步：**编译**（相对地址）→ **链接**（逻辑地址）→ **装入**（物理地址或保持逻辑）。
- **绝对装入**编译期定址、不能移动；**可重定位装入**装入期定址、装后可执行但不能动；**动态运行时装入**运行期由 MMU 翻译、可移动可共享。
- **静态链接**把库编进可执行文件；**动态链接**运行时由 ld.so 解析，库跨进程共享。
- 现代系统 = 动态运行时装入 + 动态链接 + 分页，三者组合实现内存共享与高效利用。
- 数值：逻辑地址 0x1000 装到基址 0x8000——绝对装入写死 0x1000，可重定位写成 0x9000，动态运行时保持 0x1000 由 MMU 现场算。
- 「能否移动」是三种装入方式的分水岭：只有动态运行时装入让「移动进程 = 改一个寄存器」。
- 动态链接让 libc 这类共享库只存一份，几百个进程共享同一批代码页。
- 链接解决「符号引用」，装入解决「地址定位」，两个正交维度构成四象限组合。
- 动态链接器 `ld.so` 是第一个被装入并运行的「程序」，负责解析所有库引用。
- PLT/GOT + 延迟绑定：首次调用才解析库符号，启动只解析用到的部分。
- 现代 OS 几乎不用绝对装入，可重定位装入停留在早期系统，动态运行时装入是标配。
- `ldd` 可列出程序依赖的共享库，`readelf`/`objdump` 可查看 ELF 的符号与重定位表。
- 理解「地址在哪个阶段确定」是读懂内存管理与虚拟内存一切细节的地基。
- 绝对装入仅存在于早期批处理与固件，可重定位装入是「能搬家」的历史第一步。
- 三种装入方式沿「地址确定越来越晚」的方向演化，动态运行时装入是终点。
- 「装入管地址，链接管符号」——两个概念正交，别混淆。
