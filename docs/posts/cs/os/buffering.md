## 为什么从缓冲开始

设备与 CPU 的速度差 5~6 个数量级，且一个要快一个要慢、一个一阵一阵一个持续不断。**缓冲（buffering）**在两者之间放一块「蓄水池」：数据先攒进缓冲，再由慢的/快的一方按自己的节奏取用。缓冲是 I/O 系统「平滑速率差」的核心技术，从单缓冲到循环缓冲，复杂度递增、效率递增。<span class="marginnote">回顾《文件系统性能优化》的缓冲：攒批小 I/O。I/O 系统的缓冲更通用——它不只攒批，还负责「<strong>速度匹配</strong>」：慢设备（键盘）一字节一字节来，CPU 一次取一批；快设备（磁盘）一次来一大块，CPU 慢慢消费。</span>

## 1 缓冲的三大作用

**缓冲（buffering）**：在内存中划一块区域，暂存设备与进程之间传输的数据。三大作用：

- **速度匹配（matching speeds）**：快慢设备之间用缓冲过渡——慢设备攒够一批，快设备一次性取走。
- **数据格式转换**：设备输出与进程需要的格式不同（如字符与块），缓冲中转换。
- **减少 I/O 次数**：攒批合并，把多次小 I/O 合成一次大 I/O（回顾「顺序 I/O 快」）。

**缓冲 vs 缓存的区别**：**缓冲是「暂存待处理的数据」**（面向传输流程），**缓存是「保存已处理的数据备查」**（面向复用）。缓冲的数据用一次就没了，缓存的数据可反复命中。

## 2 单缓冲：最简，但串行

**单缓冲（single buffering）**：进程与设备之间共享**一个缓冲区**。

- 进程从缓冲区取数据，同时设备向缓冲区写新数据——**但是同一块缓冲，不能同时读写**。
- 读流程：设备填满缓冲 → 进程取走处理 → 设备再填……

**问题**：**串行化**——设备等待进程取走，进程等待设备填满。两者的「等待」叠加，效率低。

**公式解析：单缓冲的传输时间**

设数据总量为 $D$，设备填满缓冲耗时 $T_{dev}$，进程处理完缓冲耗时 $T_{cpu}$：

$$\text{单缓冲总时间} \approx n \cdot (T_{dev} + T_{cpu})$$

其中 $n$ 是缓冲批数。**设备与进程是串行等待的**——每批都要「先设备后 CPU」或「先 CPU 后设备」，总时间几乎等于两者之和。**单缓冲没有实现「设备与 CPU 并行」。**

## 3 双缓冲：让设备与 CPU 并行

**双缓冲（double buffering）**：两块缓冲区交替使用。

- 进程处理缓冲区 A 时，设备同时填充缓冲区 B。
- 下一批：进程处理 B，设备填充 A。

一个典型的双缓冲交替序列（设备填、CPU 处理）：

```text
时间 →
设备填缓冲： [A]        [B]        [A]        [B]
CPU 处理：         [A]        [B]        [A]
```

设备与 CPU 像「交接棒」一样各用各的缓冲，互不等待。

**收益**：**设备与 CPU 真正并行**——设备的填充与进程的处理重叠进行。

**公式解析：双缓冲的传输时间**

$$\text{双缓冲总时间} \approx n \cdot T_{dev} + T_{cpu\_最后一批}$$

- 第一批：设备填 A（$T_{dev}$），CPU 等待。
- 之后每批：设备填 B 的同时 CPU 处理 A——**重叠**，每批时间 ≈ $\max(T_{dev}, T_{cpu})$。
- 总时间 ≈ $n \cdot T_{dev}$（若设备慢）+ 最后处理时间——**比单缓冲省了几乎一半**。

**双缓冲的局限**：只解决「两块交替」——数据流如果持续不断、且速度不均，两块缓冲仍可能「一个满了没取、一个空着没填」。这就需要**循环缓冲**。

## 4 循环缓冲：多块连成环

**循环缓冲（circular buffering）**：多块缓冲区组成**环形队列**，生产端往队尾填、消费端从队头取。

```text
             队头（消费者读）
              │
              ▼
   [块1] → [块2] → [块3] → … → [块N]
      ↑                          │
      └──── 写满后绕回队尾 ←──────┘
              │
              ▼
           队尾（生产者写）
```

生产与消费共用一个环形队列，队尾写、队头读，满了绕回。

- **生产者**（设备/CPU）往队尾写。
- **消费者**（CPU/进程）从队头读。
- 队列满则生产者等待，空则消费者等待——**用「队列」平滑生产与消费的速率差异**。

**收益**：**多次生产/消费不需要等对方完成**——数据可以攒一批再处理，或边来边处理。这是**生产者-消费者问题**（回顾第六篇）在 I/O 层的直接应用——循环缓冲就是一个有界缓冲区。

**缓冲的代价**：缓冲占内存、数据多一次拷贝（设备→缓冲→进程）。**「双拷贝」是 I/O 性能的重要成本**，所以现代系统（mmap、零拷贝）努力减少缓冲拷贝（回顾《mmap》）。

**辨析｜易错点：** 「缓冲越多越好」是误解。**缓冲不是越多越好的「越大越好」**——缓冲增加延迟（数据要在缓冲里攒着）、占内存、多一次拷贝。**缓冲的目标是「够用即好」：平滑速率差、减少 I/O 次数，而不是无限增大。**

## 5 核心对比表：三种缓冲

| 维度 | 单缓冲 | 双缓冲 | 循环缓冲 |
| --- | --- | --- | --- |
| 缓冲数 | 1 | 2 | 多（环形队列） |
| 设备与 CPU 并行 | 否 | **是** | 是 |
| 每批耗时 | $T_{dev}+T_{cpu}$ | $\max(T_{dev},T_{cpu})$ | 平滑速率差 |
| 复杂度 | 最低 | 中 | 较高 |
| 适用 | 极简场景 | 一对设备 | 生产消费持续/速率不均 |

## 6 小结

- **缓冲**三大作用：**速度匹配、格式转换、减少 I/O 次数**。
- 缓冲 vs 缓存：缓冲面向**传输流程**（暂存待处理），缓存面向**复用**（保存已处理）。
- **单缓冲**串行（设备+CPU 等待叠加）；**双缓冲**并行（两块交替）。
- **循环缓冲**= 环形队列 + 生产者-消费者，平滑持续生产/消费。
- 缓冲不是越大越好——占内存、增延迟、多拷贝，够用即好。
