## 为什么从多级队列开始

前面的算法都在一条队列里挑进程。但现实里进程分三六九等：系统进程必须实时响应，交互进程要快，批处理进程慢慢跑也行。**一条队列装不下所有要求**——于是把队列分成多条，各层用不同的调度策略。**多级反馈队列（MLFQ）**则更进一步：进程可以在层间「升降级」，用历史行为自动识别「这是不是一个短作业」。<span class="marginnote">回顾 RR 与 SJF：RR 保证响应但不区分长短，SJF 偏爱短作业但需预知。MLFQ 的目标是不需要预知，却让短作业像被 SJF 优待一样快——它用「反馈」替代「预知」。</span>

## 1 多级队列调度（MLQ）：分层排队

**多级队列（MLQ, Multilevel Queue）**：把就绪队列分成多个**优先级不同的队列**，每个队列可以有自己的调度算法。

典型分层（由高到低）：

| 队列 | 常驻进程 | 调度算法 |
| --- | --- | --- |
| 系统进程队列 | 内核/实时任务 | 优先级最高 |
| 交互进程队列 | 前台交互程序 | RR（时间片小） |
| 交互编辑队列 | 后台交互作业 | RR（时间片大） |
| 批处理队列 | 后台作业 | FCFS |

**MLQ 的关键规则**：**队列间固定优先级**——高优先级队列非空时，低优先级队列绝不调度。进程**固定分派**到某个队列，创建时定性，终身不变（如「系统进程」永远在顶层）。

MLQ 的缺点：**分层死板**。一个进程被分到批处理队列，即使它其实是 I/O 密集的交互程序，也只能在低层排队——没有「改过自新」的机会。

## 2 多级反馈队列（MLFQ）：让进程自我归类

**多级反馈队列（MLFQ, Multilevel Feedback Queue）**：进程可以在队列间**移动**。新进程进入最高优先级队列；若它在当前层时间片内用完仍没完成，就**降级**到下一层；若它经常在时间片内主动让出 CPU（等 I/O），就**保持或升级**。

一个经典的三层 MLFQ：

**Q0**：时间片 8ms，最高优先级。
**Q1**：时间片 16ms。
**Q2**：FCFS，最低优先级。

调度规则：

1. 新进程进入 **Q0**。
2. 若 Q0 时间片内没跑完 → 降级到 Q1。
3. Q1 时间片内没跑完 → 降级到 Q2。
4. **只要高优先级队列非空，先服务高优先级**（低层可能饥饿，需老化兜底）。
5. 周期性刷新：把长时间没被调度的进程提升回高层，防饥饿。

**MLFQ 的魔力**：它**不需要预知突发**，却自动优待短作业——短作业在 Q0 一个时间片就完成了，感觉像被 SJF 优先；长作业才一次次降级，最终在 Q2 用 FCFS 慢慢跑。<span class="marginnote">MLFQ 是「用行为识别类型」的调度器：I/O 密集进程频繁让出 CPU，被识别为「交互型」保持高层；CPU 密集进程用满时间片，被识别为「计算型」降级。行为即身份——这是自适应系统的经典一课。</span>

**辨析｜易错点：** 不要把 MLFQ 与 MLQ 混为一谈。**MLQ 分层固定、进程终身定性；MLFQ 分层动态、进程升降级。** MLFQ 的「反馈」正体现在降级/升级机制上——用执行历史调整调度待遇。另一个易错点：**MLFQ 的低层仍然可能饥饿**——高优先级队列若总非空，低层进程永远轮不到，所以成熟 MLFQ 必须配老化或定期提升。

## 3 参数设计：MLFQ 的调参维度

一个完整的 MLFQ 设计要回答：

- **几层队列？** 太少则层次不分明，太多则管理复杂。
- **各层时间片多大？** 高层小（快速轮转），低层大（减少切换）。
- **降级条件？** 用完时间片即降（CPU 密集特征）。
- **升级/刷新策略？** 定期把所有进程提升回顶层（防饥饿）。
- **层间是否抢占？** 通常高层可抢占低层。

这些参数没有唯一答案——Linux 的 CFS 调度器、BSD 的 `ULE` 调度器、Windows 的调度器各有各的参数。**调参的本质是在「响应性、公平、吞吐」之间为特定负载做权衡。**

## 4 核心对比表：MLQ vs MLFQ vs 单队列 RR

| 维度 | RR（单队列） | MLQ | MLFQ |
| --- | --- | --- | --- |
| 队列数 | 1 | 多（固定分层） | 多（动态分层） |
| 进程分层 | 无 | 创建时定性，终身不变 | 可升降级 |
| 短作业优待 | 无 | 无 | **有（高层快速完成）** |
| 需要预知突发 | 否 | 否 | **否** |
| 饥饿 | 无 | 低层可能 | 低层可能（需老化） |
| 复杂度 | 最低 | 中 | 较高 |

**设计启示**：MLFQ 是「通用分时系统」的黄金标准调度器——现代操作系统（Linux CFS 之前的 O(1) 调度器、Windows、BSD）都以它为骨架。它的核心贡献是把「作业长短」「交互强弱」这类**事后才知道的属性**，变成**运行时自适应识别**。

## 5 小结

- **MLQ**：多条优先级队列、各自调度算法、进程固定分层、高优先级先服务。
- **MLFQ**：进程**可升降级**，新进程进高层，用完时间片降级，等太久提升。
- MLFQ **无需预知突发**，却让短作业快、长作业慢——用行为反馈识别进程类型。
- 低层可能**饥饿**，必须配老化/定期提升。
- MLFQ 是通用分时系统调度器的事实标准，CFS 是其现代演进。
