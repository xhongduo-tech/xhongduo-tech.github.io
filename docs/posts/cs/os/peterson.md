## 为什么从 Peterson 算法开始

互斥三原则定下了标准，但怎么实现？最直接的办法是**软件方案**——不靠任何硬件特殊指令，只靠普通变量读写。**Peterson 算法**（1981 年）是双进程互斥的经典软件解，它简洁优雅地满足了全部三原则，也是理解「为什么软件方案走不远」的绝佳样本。<span class="marginnote">回顾《临界区问题》：我们需要的是一组进入区/退出区协议。Peterson 只用两个变量就实现了双进程的完整协议——它是同步原语发展史上的「软件巅峰」。</span>

## 1 Peterson 算法：两个变量，一个约定

Peterson 算法针对**两个进程** $P_0$ 与 $P_1$，使用两个共享变量：

`turn`：轮到谁进入（`turn == i` 表示轮到 $P_i$）。
`flag[i]`：每个进程的「想进」标志，`flag[i] = true` 表示 $P_i$ 想进入临界区。

$P_i$（$i$ 取 0 或 1，对方是 $j = 1-i$）的进入协议：

```c
do {
    flag[i] = true;          // ① 声明「我想进」
    turn = j;                // ② 礼让：把 turn 交给对方
    while (flag[j] && turn == j)
        ;                    // ③ 对方想进且轮到他，则忙等待
    /* 临界区 */
    flag[i] = false;         // 退出区：声明「我不再想进」
    /* 剩余区 */
} while (true);
```

三个关键步骤的直觉：

**① flag[i]=true**：声明「我要用临界区」。
**② turn=j**：把「礼让权」交给对方——**先到者后设 turn**，所以后设 turn 的一方（即先执行到 ② 的另一方？不，是后执行 ② 的）会等。实际效果：最后写 `turn` 的进程是「被礼让」的那个。
**③ while**：只有当对方想进**且**轮到他时，我才等；否则我进。

### 一次完整的执行走查

设 $P_0$ 先到、$P_1$ 后到，看两个变量如何演化：

| 步骤 | 事件 | flag[0] | flag[1] | turn | 谁在临界区 |
| --- | --- | --- | --- | --- | --- |
| 1 | $P_0$ 执行 ① ② | true | false | 1 | — |
| 2 | $P_0$ 检查 ③：flag[1]=false，进入 | true | false | 1 | $P_0$ |
| 3 | $P_1$ 执行 ① ② | true | true | 0 | $P_0$ |
| 4 | $P_1$ 检查 ③：flag[0]=true 且 turn=0 → 等待 | true | true | 0 | $P_0$ |
| 5 | $P_0$ 退出，flag[0]=false | false | true | 0 | — |
| 6 | $P_1$ 检查 ③：flag[0]=false → 进入 | false | true | 0 | $P_1$ |

注意第 4 步的关键：$P_1$ 后来居上把 `turn` 改成 0（礼让给 $P_0$），于是自己等待；等 $P_0$ 离开后 $P_1$ 才进入——**「后写 turn 者先让、先到者先进」，两个进程绝不重入**。

## 2 正确性验证：满足三原则

**互斥**：若 $P_0$ 与 $P_1$ 同时在临界区，则二者都已越过 while。越过 while 意味着 $turn \ne i$（对每个 $P_i$ 而言），即 $turn = j$ 对两者同时成立——但 `turn` 只有一个值，不可能同时等于 0 又等于 1。矛盾，故互斥成立。

**前进**：若临界区空闲，且双方都想进。考虑最后写 `turn` 的进程——它把 turn 设为对方，所以对方 while 条件中 `turn == i` 为假，直接进入。**「最后写 turn 者被礼让出去，先写者先进」**——总有人能进，前进成立。

**有限等待**：$P_i$ 想进时，若 $P_j$ 正在临界区，$P_i$ 最多等 $P_j$ 一次——因为 $P_j$ 一旦退出就置 `flag[j] = false`，$P_i$ 的 while 条件不再满足。**任何进程最多等对方一次，有限等待成立。**

### 三原则的直观对照

| 原则 | Peterson 如何满足 | 若违反的后果 |
| --- | --- | --- |
| 互斥 | `turn` 只有一个值，双方不可能都满足 `turn == j` | 两进程同时改共享数据，数据损坏 |
| 前进 | 临界区空闲时总有人能进（先写 turn 者进） | 死锁：谁都不进 |
| 有限等待 | 最多等对方一次（对方退出即置 `flag = false`） | 饥饿：某进程永无机会 |

这张表也点出三原则的**职责分工**：互斥管「安全」（数据不坏），前进与有限等待管「活性」（系统不死锁、不饥饿）。Peterson 是「一个算法同时满足三条」的最小证明。

**辨析｜易错点：** 初学者常把 `flag` 与 `turn` 的先后搞反。**必须先设 flag、再让 turn——即「先声明，再礼让」。** 若顺序颠倒（先 turn 后 flag），可能两个进程同时进入临界区（互斥被破坏）。这个「声明—礼让」的顺序是 Peterson 正确性的命门。

## 3 软件方案的命运：为什么被硬件取代

Peterson 算法在「两进程 + 内存一致」模型下完美，但现代系统几乎不用它：

**只支持两个进程**：扩展到 n 个进程的软件算法复杂得多。
**不能处理临界区内的阻塞**：若进程在临界区被抢占或阻塞，整个协议卡死。
**依赖内存模型**：现代 CPU 有缓存与乱序执行，写入后另一个核可能仍读到旧值（需要内存屏障）。**Peterson 算法在 x86 多核上并不正确**，除非编译器与 CPU 保证顺序。

这三点把实现方向推向了硬件——**用一条原子的特殊指令**（Test-and-Set、Compare-and-Swap）解决互斥，这就是下一篇《硬件同步原语》。<span class="marginnote">Peterson 的意义不在「实用」，而在「证明」：它证明了互斥在纯软件层面是可能的，从而把「为什么还需要硬件指令」的问题逼到台面——软件方案的瓶颈不在逻辑，而在性能与可扩展性。这是一堂绝佳的「理论 vs 工程」课。</span>

**辨析｜易错点：** 「Peterson 用普通变量就实现了互斥，所以锁也不需要原子指令」是错误推理。**Peterson 的正确性前提是「写后读立即可见且有序」**——现代 CPU 有写缓冲与乱序执行，`flag[i]=true; turn=j;` 两条写可能被重排，`flag[j]` 的读取也可能读到缓存旧值。要让 Peterson 在真实硬件上正确，必须插入**内存屏障（memory barrier）**；而硬件原子指令（Test-and-Set）把「原子 + 有序」一起包办，这才是它取代软件方案的根本原因。

### 历史注脚：Dekker 算法与软件互斥的终点

Peterson 算法之前，还有 1960 年代的 **Dekker 算法**——它用四个变量（两个 flag + 一个 turn + 一个「谁先来」的优先级位）实现了双进程互斥，是第一个被正确证明的软件互斥算法。Peterson 把四个变量精简到两个，成为教科书标准。

软件方案此后走向终点，不是「逻辑不漂亮」，而是**性能与可扩展性**：每次进入临界区都要忙等待，多核共享缓存行导致「缓存一致性风暴」，扩展性差。硬件方向则是「一次原子指令解决互斥」——用一条不可中断的读-改-写，从根源上消灭「检查与设置之间被插入」的可能。

## 4 核心对比表：Peterson vs 后续方案

| 维度 | Peterson 算法 | 硬件同步原语 |
| --- | --- | --- |
| 依赖 | 普通变量 + 严格顺序 | 一条原子指令 |
| 进程数 | 仅 2 | 任意 |
| 多核正确性 | 需内存屏障，易错 | 硬件保证 |
| 在临界区阻塞 | 协议卡死 | 锁同样会卡（另有方案） |
| 应用 | 教学、理论证明 | 一切真实系统 |

## 5 小结

- **Peterson 算法**用 `flag`（想进）与 `turn`（礼让）两个变量实现双进程互斥——双进程软件互斥的最小实现。
- 步骤顺序关键：**先声明 `flag`，再礼让 `turn`**，再检查等待；「后写 turn 者先让、先到者先进」。
- 满足互斥、前进、有限等待三原则（双进程、内存一致模型下）；互斥管安全、前进与有限等待管活性。
- 局限：仅双进程、临界区阻塞即卡死、依赖内存顺序，现代多核上需内存屏障。
- 正确性前提是「写后读立即可见且有序」，乱序/缓存使纯软件方案在多核失效。
- Dekker 是前身，软件方案止步于忙等待与缓存一致性——意义在于证明「软件互斥可能」，从而把工程实现逼向硬件原子指令。
