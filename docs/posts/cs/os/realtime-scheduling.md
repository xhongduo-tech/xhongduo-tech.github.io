## 为什么从实时调度开始

前面所有算法追求「快」与「公平」，但都允许「偶尔慢一点」。而实时系统（自动驾驶、飞行控制、工业机器人、5G 基站）不允许——**任务必须在截止时间（deadline）前完成，否则就是事故**。实时调度因此有了全新的判据：不是平均等待时间，而是「能否保证所有任务都在截止时间前完成」。<span class="marginnote">回顾《调度基本概念》的准则表：实时系统把「截止时间」放到最高权重，其余准则统统让位。这是调度目标从「性能」转向「可保证性」的一次范式转移。</span>

## 1 实时系统的两类任务

**实时系统（real-time system）**：系统行为的正确性不仅取决于计算结果的逻辑正确，还取决于**结果产生的时间**。实时任务分两类：

- **硬实时（hard real-time）**：错过截止时间 = 系统失败。飞行控制、刹车系统、心脏起搏器。绝不妥协。
- **软实时（soft real-time）**：错过截止时间 = 质量下降，但不至于灾难。视频流、在线游戏、语音通话。

实时任务还常分**周期性（periodic）**与**非周期性**。周期性任务是实时调度的主角：每个周期 $T_i$ 内，任务 $i$ 要用 $C_i$ 时间，且必须在周期末（截止时间 $D_i = T_i$）前完成。

关键参数：

- $C_i$：任务 $i$ 每次执行所需的 CPU 时间。
- $T_i$：任务 $i$ 的周期（两次执行的间隔）。
- $U_i = C_i / T_i$：任务 $i$ 的**利用率**（占 CPU 的比例）。

**利用率**是实时调度分析的货币：所有任务的总利用率 $\sum U_i$ 必须 ≤ 1，CPU 才可能来得及，这是必要条件。

## 2 RM 调度：周期越短，优先级越高

**速率单调（RM, Rate-Monotonic）**：优先级**静态**分配——**周期越短（速率越高）的任务优先级越高**。周期性任务 $i$ 与 $j$ 若 $T_i < T_j$，则 $i$ 优先级更高。

RM 是固定优先级抢占式调度的最优算法：在**固定优先级**前提下，若任何固定优先级算法都能满足截止时间，RM 也一定能。

**RM 的可调度性判定（充分条件）**：设 $n$ 个周期性任务，若总利用率满足：

$$\sum_{i=1}^{n} U_i \le n \left( 2^{1/n} - 1 \right)$$

则 RM 保证所有任务都在截止时间前完成。其中 $n(2^{1/n}-1)$ 是 RM 的**利用率上界**，随 $n$ 增大单调下降，极限为 $\ln 2 \approx 0.693$。<span class="marginnote">这个上界说明：RM 最多能保证 CPU 用到约 69.3%（任务无限多时），剩余约 30% 可能被闲置却仍无法保证——这是固定优先级调度「静态」付出的代价。利用率落在 $0.693$ 与 $1$ 之间时，RM 可能可调度也可能不可，需要更精细判定。</span>

**公式解析：RM 利用率上界**

$$n\left(2^{1/n} - 1\right)$$

- **$n$**：周期性任务个数。
- **$2^{1/n}$**：$2$ 的 $1/n$ 次方，数学上源于「最坏情况下高优先级任务的抢占次数」的边界分析。
- **$n \cdot (2^{1/n} - 1)$**：把「最坏情形」折算成利用率上限。
- 当 $n=1$，上界 $= 1$——单任务可用满 CPU；$n=2$，上界 $\approx 0.828$；$n \to \infty$，上界 $\to \ln 2 \approx 0.693$。

**直觉**：任务越多，RM 越「不敢打包票」——因为高优先级任务可能频繁抢占，使低优先级任务在最坏情况下被堵。上界给出的是「只要总利用率不超过它，就绝对安全」的充分条件。

## 3 EDF 调度：谁先到期谁先跑

**最早截止时间优先（EDF, Earliest-Deadline-First）**：优先级**动态**分配——**截止时间最早的任务优先级最高**。截止时间随时间逼近，优先级也动态变化。

EDF 比 RM 更强大：它是**最优的动态优先级调度算法**，且可调度性条件更宽松——只要总利用率 $\sum U_i \le 1$，EDF 就能保证所有任务在截止时间前完成（对周期性任务、截止时间等于周期而言）。<span class="marginnote">对比鲜明：RM 需要利用率 ≤ 0.693（多任务时）才能「保证」，EDF 只要 ≤ 1 就保证。EDF 的理论优越性来自动态决策——它总是选择「最急」的任务，永不浪费。</span>

EDF 的代价：

- **实现复杂**：需要维护按截止时间排序的队列（优先队列）。
- **过载行为不确定**：当 $\sum U_i > 1$（过载）时，EDF 无法保证，且错过截止时间的任务可能「扎堆」——没有 RM 那种「低优先级任务牺牲，高优先级任务保全」的清晰层次。
- 在固定优先级系统（如很多商业 RTOS 只支持静态优先级）上无法直接实现。

## 4 核心对比表：RM vs EDF

| 维度 | RM | EDF |
| --- | --- | --- |
| 优先级分配 | 静态（周期短者高） | 动态（截止早者高） |
| 可调度性保证 | 利用率 ≤ $n(2^{1/n}-1)$ | 利用率 ≤ 1 |
| 最优性 | 固定优先级中的最优 | 动态优先级中的最优 |
| 实现难度 | 低（调度时无需排序） | 高（需按截止时间排序） |
| 过载行为 | 可预测（低优先级牺牲） | 不确定 |
| 适用硬件 | 简单嵌入式 RTOS | 需优先队列支持的 RTOS |

**辨析｜易错点：** 「EDF 总是比 RM 好」是理论上的正确、工程上的片面。**EDF 的保证需要系统负载可控（利用率 ≤ 1）；一旦过载，EDF 会「雨露均沾」式地错过大量截止时间，而 RM 至少保证高优先级（短周期）任务。** 军事航空等关键系统宁可要「可预测的失败」（RM）也不要「最优但不可预测的失败」（EDF）。**可预测性也是实时系统的重要指标，不是只有最优性。**

## 5 小结

- 实时系统看「**截止时间保证**」而非平均性能；分**硬实时**（错过即失败）与**软实时**（错过降质）。
- 周期性任务的三个参数：**执行时间 $C_i$、周期 $T_i$、利用率 $U_i = C_i/T_i$**。
- **RM**：静态优先级，周期短者优先；保证条件为利用率 ≤ $n(2^{1/n}-1)$（极限约 0.693）。
- **EDF**：动态优先级，截止早者优先；利用率 ≤ 1 即保证，理论最优。
- EDF 理论更优，但过载行为不可预测；RM 失败可预测，关键系统更偏爱。
