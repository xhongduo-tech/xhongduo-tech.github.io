## 为什么从 PCB 开始

上一节我们看了进程的生命状态，但还留着一个关键问题：**操作系统凭什么知道「这个进程在哪个状态、用着哪块内存、打开了哪些文件」？** 答案是一块数据结构——**进程控制块（PCB）**。它是操作系统为每个进程建立的「户口本」，进程的所有信息都登记在这本户口本里。<span class="marginnote">在《进程概念》里我们说过：操作系统眼里的进程约等于它的 PCB。这篇把这个断言展开——PCB 里到底登记了什么，为什么它敢代表整个进程。</span>

Linux 中 PCB 的实体就是 task_struct，它会作为独立专题在 Linux 篇里逐字段展开；这篇先讲通用原理。

## 1 PCB：进程的户口本

**进程控制块（PCB，Process Control Block）**：操作系统为每个进程维护的一个数据结构，集中存放该进程的全部管理信息。进程被创建时分配 PCB，进程终止时回收 PCB。**没有 PCB，进程就不存在。**

PCB 的内容按功能可分为四组：

| 信息组 | 包含内容 |
| --- | --- |
| 进程标识 | 进程号（PID）、父进程号（PPID）、用户标识（UID） |
| 处理器状态 | 程序计数器 PC、各寄存器值、状态字（PSW）、栈指针 |
| 调度信息 | 进程状态、优先级、已用 CPU 时间、事件、调度参数 |
| 内存与资源 | 地址空间（页表/段表指针）、打开文件表、I/O 设备清单 |

**处理器状态组是 PCB 的「灵魂」**：进程被换下 CPU 时，寄存器全部存入 PCB；下次被调度时，再从 PCB 恢复寄存器——这就是进程「像从没被打断过一样继续跑」的物理保证。

## 2 PCB 的作用：三个「凭此」

PCB 是操作系统一切「按进程办事」的依据，至少体现在三处：

**凭 PCB 调度**：调度器扫描就绪队列中的 PCB，看优先级、看状态，决定选谁上 CPU。
**凭 PCB 中断现场恢复**：进程被打断时，现场（寄存器、PC）存入 PCB；中断处理结束，从中断前的 PCB 状态恢复执行。
**凭 PCB 记账与保护**：记录进程用了多少 CPU 时间（记账）；记录进程的内存界限与权限（保护）。

所以，**PCB 是连接「进程的逻辑存在」与「操作系统的物理管理」的唯一桥梁**。没有 PCB，调度器、内存管理、文件系统都找不到「谁是谁」。<span class="marginnote">把 PCB 想成图书馆的索书卡：书（进程）在书架上，索书卡（PCB）记录书的位置、状态、借阅记录。系统不直接翻书，永远先查卡。</span>

## 3 进程的组织：PCB 被组织成什么结构

PCB 不能散落一地，操作系统用数据结构把它们组织起来，常见三种：

**链表**：按状态（就绪队列、等待队列）串成链表——就绪 PCB 串成就绪队列，等待某设备的 PCB 串成该设备的等待队列。**这是最常用的组织方式，直接对应状态模型中的队列。**
**索引表**：按状态建索引，表项指向对应 PCB。
**树**：按父子关系组织（Linux 的进程树，用 pstree 可见）。

调度器只关心就绪队列，I/O 完成时系统扫描对应设备的等待队列——**队列的组织方式决定了「找进程」的代价**。<span class="marginnote">这就是上一篇状态模型里「队列」概念的具体落点：就绪队列就是「就绪 PCB 链表」，等待队列就是「阻塞 PCB 链表」。状态模型与 PCB 组织是同一张图的两面。</span>

## 4 核心对比表：PCB vs 进程实体

初学者总把 PCB 与进程「本尊」混淆，对照如下：

| 维度 | 进程实体（程序+数据+栈） | PCB |
| --- | --- | --- |
| 内容 | 进程自己的代码与数据 | 操作系统对进程的登记信息 |
| 谁创建 | 程序加载时 | 进程创建时由内核分配 |
| 可共享吗 | 程序段可共享 | 每进程独占一份 |
| 谁访问 | 进程自己（自己的地址空间） | 只有内核能访问（特权保护） |
| 存哪 | 用户地址空间 | 内核地址空间 |

**辨析｜易错点：** PCB 存在内核空间，普通用户进程**无权访问**自己的 PCB——进程甚至不知道自己被登记了哪些信息（从 /proc 看到的只是系统管理接口读出的快照）。把 PCB 当作「进程自己能读的变量」是常见误解，它恰恰是内核的私有账簿。

另一个易错点：**PCB 不是程序的一部分**。程序文件（可执行文件/ELF）里没有 PCB，PCB 是进程创建时操作系统「外加」的。这再次印证进程 = 程序影像 + 操作系统附加的账本。

## 5 小结

- **PCB** 是操作系统为每进程维护的**户口本**，分**标识、处理器状态、调度信息、内存与资源**四组。
- **处理器状态组（寄存器、PC、PSW）**是上下文切换时保存/恢复现场的关键。
- PCB 支撑**调度、中断恢复、记账保护**三大职责。
- PCB 按状态组织成**就绪队列、等待队列**，也可用索引表或进程树组织。
- PCB 是内核私有数据结构，存于内核空间，进程无权访问。
