## 为什么从系统调用表开始

前两篇讲了「怎么进内核」，这一节回答「进去之后找谁」：**系统调用表**是「调用号 → 内核函数」的映射，**系统调用号**是用户报出的号码，**参数传递**是两者的桥梁。三者共同构成系统调用的「寻址机制」。<span class="marginnote">回顾《系统调用原理》：系统调用号是内核找处理函数的钥匙。这一节把这张表、号码的编号约定、以及参数的验证与传递讲透——它们是系统调用「安全与正确」的保障。</span>

## 1 系统调用表 sys_call_table

**系统调用表（sys_call_table）**：一个**函数指针数组**，下标是系统调用号，值是对应的内核处理函数。

```c
/* 内核：系统调用表 = 函数指针数组，下标即调用号 */
void (*sys_call_table[])(void) = {
    [0] = sys_read,    /* 调用号 0 → sys_read  */
    [1] = sys_write,   /* 调用号 1 → sys_write */
    [2] = sys_open,    /* 调用号 2 → sys_open  */
    [3] = sys_close,   /* 调用号 3 → sys_close */
};
```

**内核流程**：

1. 从 rax 取系统调用号 $n$。
2. **校验范围**：$0 \le n < \text{表长}$（越界直接返回错误）。
3. **查表**：`sys_call_table[n]` 得到函数指针。
4. 调用该函数，参数从 rdi/rsi/rdx 传入。

**系统调用号的稳定性**：**系统调用号是 ABI 的一部分**——一旦发布，不能随便改（改了就破坏二进制兼容）。新增系统调用只能**追加新号**（Linux 当前约 450+ 个）。

## 2 系统调用号的约定

**系统调用号（syscall number）**：每个系统调用一个整数编号，定义在 <asm/unistd.h>`（`__NR_xxx` 宏）。

**两个约定值得注意**：

- **号越小越基础**：早期的 read/write/open/close 是 0/1/2/3——最常见的调用号最小（但这不是性能原因，只是历史顺序）。
- **架构相关**：x86-64 与 arm64 的调用号**不同**——同一系统调用在不同架构上号码可能不同（ABI 是架构相关的）。

**辨析｜易错点：** 「系统调用号全局统一」是误解。**系统调用号是架构相关的 ABI**——x86-64 的 `__NR_read = 0`，arm64 的 `__NR_read = 63`。**跨架构的「统一」靠的是系统调用名（libc 封装），不是号码**。写汇编直接调系统调用时必须用当前架构的号码。

## 3 参数传递与验证

**参数传递**：第 1~6 个参数放 rdi/rsi/rdx/r10/r8/r9（与函数调用类似但用寄存器而非栈）。

**内核的参数验证（安全关键）**：

- **指针验证**：用户传的指针必须指向**用户空间**（`access_ok`/`copy_from_user` 会检查）——防止用户传入内核地址读写内核内存。
- **值验证**：fd 是否合法、size 是否合理。
- **错误处理**：失败返回负值（`-errno`），libc 把它转成 `errno` 并返回 -1。

**为什么必须验证**：用户态传入的参数**不可信**——恶意程序可以传任何值。**内核绝不信任用户参数**，每个参数都要校验（回顾「不信任输入」的防御哲学）。

**公式解析：系统调用错误返回的约定**

Linux 系统调用返回值规则：

$$\text{返回值} = \begin{cases} \ge 0 & \text{成功} \\ < 0 \quad (-\text{errno}) & \text{失败} \end{cases}$$

- 成功：返回非负值（如 `read` 返回读取字节数）。
- 失败：返回 `-errno`（如 `-EINVAL` = -22）。
- libc 检测负值 → 置 `errno` → 返回 -1 给应用。

**直觉**：**「负返回值 = 错误」是 Linux ABI 的约定**——一个返回值同时携带「成功/失败」与「错误码」，极简高效。这也是为什么 C 程序员要检查返回值——负数就是错误信号。

## 4 核心对比表：系统调用的组成要素

| 要素 | 内容 | 作用 |
| --- | --- | --- |
| 系统调用号 | 整数（`__NR_*` 宏） | 用户报号码 |
| 系统调用表 | 号 → 函数指针数组 | 内核找函数 |
| 参数寄存器 | rdi/rsi/rdx/r10/r8/r9 | 传递参数 |
| 返回值 | rax（负值 = 错误） | 回传结果 |
| libc 封装 | 函数名 → syscall 指令 | 用户友好接口 |

**设计启示**：系统调用的寻址机制是「**间接层**」的经典——**应用不直接调用内核函数，而是通过「号码 + 表」间接寻址**。好处：**内核函数可以换实现（改表项），应用不用改（号码不变）**——ABI 稳定 + 实现可演进。这是「接口与实现解耦」在系统层的体现。

## 5 小结

- **系统调用表** = 调用号 → 内核函数的映射数组；内核查表寻址。
- **系统调用号**是架构相关 ABI，一旦发布不能改，新调用只能追加。
- 参数经 rdi/rsi/rdx/r10/r8/r9 传递，内核**必须验证**（指针、值）——用户参数不可信。
- 返回值约定：**负数 = -errno（失败），非负 = 成功**。
- 「号码 + 表」的间接寻址让 ABI 稳定、实现可演进。
