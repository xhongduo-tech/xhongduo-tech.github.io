## 为什么从进程创建与终止开始

有了 PCB、状态模型与上下文切换，我们已经能描述「进程跑起来之后」的样子。现在补上进程的两端：**它如何诞生，又如何死亡？** Unix/Linux 用一对系统调用 fork 与 exit 回答了这两个问题，而这背后藏着三个让无数新手困惑的概念：写时复制、僵尸进程、孤儿进程。<span class="marginnote">进程创建与终止是系统编程的「hello world」之后的第一个大坑。理解了 fork 的返回值语义与僵尸进程的成因，你才算真正理解了「进程是操作系统的记账单位」这句话。</span>

## 1 进程的创建：fork 一分为二

**进程创建（process creation）**：进程由父进程创建，父进程可创建多个子进程，形成一棵**进程树**。Unix 的创建方式是 **fork**：

**fork**：一个系统调用，调用它的进程（父进程）被复制成一个几乎完全相同的子进程。**子进程从 fork 返回处继续执行，与父进程执行同一份代码。**

fork 的精妙与陷阱都在返回值上：

```c
#include <unistd.h>
#include <stdio.h>

int main(void) {
    pid_t pid = fork();          /* 一次调用，两个进程从这里各走各路 */
    if (pid == 0) {
        /* 子进程：fork 返回 0 */
        printf("I am the child (pid=%d)\n", getpid());
    } else if (pid > 0) {
        /* 父进程：fork 返回子进程 PID */
        printf("I am the parent of child %d\n", pid);
    } else {
        perror("fork");          /* pid < 0：fork 失败 */
    }
    return 0;
}
```

**fork 一次调用，两次返回**：父进程返回子进程 PID，子进程返回 0。这正是判断「我是谁」的钥匙——同一个 pid 变量，在两个进程里值不同。<span class="marginnote">为什么子进程返回 0 而不是「自己的 PID」？因为子进程可以用 getpid() 拿到自己的 PID，却难以知道「父进程是谁」的便捷方式（getppid 虽也有）；0 则简洁地标记了「我是新生的那一个」。</span>

创建后，子进程要么与父进程并发执行同一份代码，要么立刻调用 exec 加载新程序——Unix 把「创建进程」与「换程序」拆成 fork 与 exec 两步，这是它最优雅的设计之一（详见 Linux 篇《exec 家族》）。

## 2 写时复制：让 fork 从昂贵变便宜

早期的 fork 会把父进程整个地址空间完整复制给子进程，代价昂贵。现代系统用**写时复制（Copy-on-Write, COW）**优化：

**写时复制**：fork 时并不真正复制内存，而是让父子进程**共享同一份物理页**，并把这些页标为只读；只有某一方**真的去写**某个页时，才触发缺页异常，复制该页再写入。<span class="marginnote">COW 与第九篇《虚拟内存》的缺页机制绑定：写只读页 → 缺页异常 → 内核复制页 → 更新页表 → 重新执行写指令。这是「用懒分配换性能」的经典手法。</span>

**收益**：fork 的开销从「复制全部内存」降到「只复制页表」；子进程若马上 exec，就几乎不复制任何东西。
**代价**：COW 页的识别与写时复制需要额外机制；父子进程共享页导致「不可变」假象。

COW 在虚拟内存篇还会从「共享页被写」的角度再讲一次，这里先记住它在进程创建中的角色。

## 3 进程的终止与 exit：清理与回收

**进程终止（process termination）**：进程执行完最后一条语句，或显式调用 exit，或收到终止信号，都会进入终止态。终止后进程资源（内存、文件）由内核回收，但——**PCB 不会立刻消失**。

父进程应调用 **wait/waitpid** 等待子进程终止并回收其 PCB。于是出现两个「灵异」状态：

**僵尸进程（zombie）**：子进程已终止、PCB 尚未被父进程 wait 回收的进程。它不再执行任何代码，但占用一个 PID 与 PCB，ps 里显示 Z 状态。**僵尸无法被杀掉**，只能等父进程 wait 或父进程死亡后由 init 收养并回收。
**孤儿进程（orphan）**：父进程先于子进程终止，子进程被「过继」给 init（PID 1）收养，由 init 负责回收。孤儿不危险，被收养后就有人照料了。

**辨析｜易错点：** 僵尸 ≠ 孤儿。**僵尸是「死了没人收尸」，孤儿是「活着但没了爹」**。僵尸占着资源、杀不死、只能靠父进程 wait 或父进程死亡来清理；孤儿则被 init 收养，正常存活。大量僵尸是父进程不调 wait 的 bug 信号（比如长循环里 fork 后不管）。

另一个易错点：**终止 ≠ 立即消失**。进程终止后 PCB 仍在，直到 wait 回收——这正是僵尸存在的原因。父进程崩溃退出后，它的僵尸子进程会被 init 接管回收，所以僵尸不会永远堆积。<span class="marginnote">写守护进程/长驻服务时，fork 出的子进程死亡后必须 wait 回收，否则每次子进程退出都积累一个僵尸——服务跑上一个月，ps 里密密麻麻全是 Z（僵尸）。这是系统编程最常见的资源泄漏之一。</span>

## 4 核心对比表：三个状态

| 维度 | 终止且被回收 | 僵尸进程 | 孤儿进程 |
| --- | --- | --- | --- |
| 进程是否运行 | 否 | 否 | 是（继续运行） |
| PCB 是否还在 | 否 | 是 | 是 |
| 谁负责清理 | 内核直接回收 | 等父进程 wait | 被 init 收养后回收 |
| 危险性 | 无 | 占用资源，杀不死 | 无害 |
| 产生原因 | 正常退出 | 父进程不调 wait | 父进程先退出 |

## 5 小结

- 进程由父进程创建，构成**进程树**；Unix 用 **fork** 创建、exec 换程序、exit 终止。
- fork **一次调用两次返回**：父进程得子 PID，子进程得 0，靠返回值分岔执行。
- **写时复制 COW** 让 fork 只复制页表不复制内存，被写的页才真正复制。
- **僵尸进程** = 已终止、PCB 未被 wait 回收；杀不死，只能由父进程 wait 或父进程死亡清理。
- **孤儿进程** = 父进程先死，被 init 收养，无害。
- 终止 ≠ 立即消失，PCB 要等 wait 才回收。
