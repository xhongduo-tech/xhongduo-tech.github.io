## 为什么从 ext4 开始

前面所有文件系统概念——FCB、目录、分配、位图、日志——在 **ext4** 上全部具象化。ext4 是 Linux 最广泛使用的文件系统，它是 ext2（基础）/ext3（日志）的演进，并加入了现代特性（扩展块 extents、延迟分配）。剖析 ext4 等于把第十二篇的所有知识做一次「总装」。<span class="marginnote">回顾第十二篇各节：inode（FCB）、目录项、索引分配（直接+间接）、块组位图、日志。ext4 就是这些概念的完整实现——<strong>它是「文件系统教科书」的现实化身</strong>。</span>

## 1 ext4 的整体布局：超级块 + 块组

ext4 把磁盘分区组织成多个**块组（block group）**，每个块组自包含元数据与数据：

```
磁盘分区布局：
┌──────────────┬────────────┬────────────┬────────────┬─────┐
│ 超级块       │ 块组 0     │ 块组 1     │ 块组 2     │ …   │
│ (多处备份)   │            │            │            │     │
└──────────────┴────────────┴────────────┴────────────┴─────┘

每个块组内部（自含元数据 + 数据）：
┌──────────┬──────────┬───────────┬──────────┬──────────────┐
│ 组描述符 │ 块位图   │ inode位图 │ inode表  │ 数据块区      │
└──────────┴──────────┴───────────┴──────────┴──────────────┘
```

**超级块（superblock）**：分区头部，记录全局信息——块大小、总块数、块组数、未分配块数、第一个 inode 号等。超级块在多个位置有**备份**（重要！）。

**每个块组包含**：

| 区域 | 内容 |
| --- | --- |
| 组描述符表 | 本组的元数据位置（位图、inode 表地址） |
| 块位图（block bitmap） | 本组数据块的分配状态（每块一位） |
| inode 位图 | 本组 inode 的分配状态 |
| inode 表 | 本组所有 inode 集中存放 |
| 数据块区 | 本组的文件数据块 |

**块组的意义**：**局部性**——新文件优先在本组分配 inode 与数据块，文件块靠得近，顺序读快（回顾磁盘性能）；位图小，可缓存。

## 2 ext4 的 inode：直接 + 间接块指针

**inode** 是 ext4 文件的「户口本」（回顾《文件控制块》）。ext4 inode 包含：

- 文件类型、权限、属主、组。
- 文件大小、时间戳。
- **数据块指针数组**：**15 个指针**，其中前 12 个是**直接块指针**，后 3 个分别是**单级/二级/三级间接指针**（回顾《索引分配》的组合方案）。

```
inode 的数据块指针数组（15 项）：
┌───────────┬──────────────────────────────────┐
│ block[0]  │ 直接块 → 数据块 0                │
│ block[1]  │ 直接块 → 数据块 1                │
│ …         │ …                                │
│ block[11] │ 直接块 → 数据块 11               │
│ block[12] │ 单级间接 → 指向一个块，块内存 1024 个块号 │
│ block[13] │ 二级间接 → 一层块表 → 再一层块表        │
│ block[14] │ 三级间接 → 三层块表 → 最深指向数据块     │
└───────────┴──────────────────────────────────┘
```

**最大文件大小**（4KB 块、4 字节块号）：直接 12 块 + 间接 $1024$ + 二级 $1024^2$ + 三级 $1024^3$ ≈ **4TB**。

**ext4 的改进——扩展块（extent）**：ext3 用「块号数组」记录文件块；ext4 改用**扩展块（extent）**——记录「起始块号 + 连续块数」，把「一串连续的块」记成一条。**大文件（如 100MB）在 ext3 要 25600 个块号，在 ext4 只需少量 extent**——元数据大幅缩小，顺序读更快。

**公式解析：extent 的压缩效率**

设文件含 $C$ 个连续块，extent 记法用 2 个字段（起始块号 + 长度）：

$$\text{extent 条目数} = \text{连续段数}，\quad \text{而块号条目数} = C$$

- 若文件完全连续（1 段）：extent 只需 **1 条**，块号需 $C$ 条——**压缩 $C$ 倍**。
- 文件越连续，extent 越省。**extent 把「文件尽量连续」的物理优势，转化成了「元数据更小」的逻辑优势**——这是 ext4 性能提升的关键。

## 3 ext4 的日志（journaling）

ext4 继承 ext3 的**日志**（回顾《日志文件系统》）：

- **元数据日志（默认）**：inode、目录、位图的修改先写日志，再应用——崩溃秒级恢复，结构一致。
- **日志区**：分区开头的固定区域（可指定大小）。

**ext4 的额外机制**：

- **延迟分配（delayed allocation）**：待写的数据**先攒在页缓存**，等到真正刷盘时才分配块——**能一次性分配「连续的 extent」**（因为攒够了才知道要多大、哪连续），减少碎片、提高顺序性。
- **fsync 语义**：fsync() 强制刷盘，保证持久性（延迟分配的代价是崩溃丢数据）。

**辨析｜易错点：** 「ext4 数据一定安全」是误解。**ext4 默认是元数据日志 + 延迟分配**——数据块可能停在页缓存里，断电会丢最近写入的数据（结构不损坏）。**要数据不丢，必须 fsync 或使用全数据日志模式（data=journal）**——数据库等关键应用会显式 fsync。

## 4 核心对比表：ext2 / ext3 / ext4

| 特性 | ext2 | ext3 | ext4 |
| --- | --- | --- | --- |
| 日志 | 无 | **有**（元数据） | 有（+延迟分配） |
| 块寻址 | 块号 | 块号 | **extent** |
| 最大文件 | 2TB | 2TB | **16TB** |
| 最大分区 | 16TB | 16TB | **1EB** |
| 延迟分配 | 无 | 无 | **有** |
| 现代地位 | 淘汰 | 过渡 | **Linux 默认** |

**设计启示**：ext2 → ext3 → ext4 的演化史就是本专题的缩影——ext3 加了**日志**（崩溃一致性），ext4 加了 **extent + 延迟分配**（性能与元数据压缩）。**文件系统的进步 = 可靠性与性能的持续打磨**，而它的知识骨架（inode、目录、位图、分配、日志）你已经在前面各节全部学完。

## 5 小结

- **ext4 布局**：超级块（多备份）+ 多个**块组**（自含位图、inode 表、数据区）。
- **inode**：15 个指针 = 12 直接 + 3 间接（单/二/三级），最大文件 ~4TB（4KB 块）。
- **extent（扩展块）**：记录「起始块 + 连续数」，把大文件的元数据压缩几十倍。
- **日志**：元数据日志 + 延迟分配——崩溃结构一致、性能好，但数据需 fsync 才保险。
- ext4 = inode/目录/位图/分配/日志/一致性全部概念的现代总装。
