## 为什么从页表结构开始

分页的页表是「每个进程一张、每页一项」的线性表。问题是：**64 位地址空间 + 4KB 页 = 2^52 个页，页表需要天文数字的空间**。线性页表装不下，必须改造页表的结构。这一节看三种主流方案：**分层页表**（树形）、**哈希页表**、**倒置页表**——它们各有各的「空间换时间」或「时间换空间」策略。<span class="marginnote">回顾《分页》：页表是「页号→页框号」的数组。当页表本身太大时，数组这种「一步到位」的结构就不行了——分层让它变树、哈希让它变散列、倒置让它「按页框建表」。</span>

## 1 分层页表：把页表也切成页

**分层页表（hierarchical page table）**：把页表本身按页切分，再用更高一级的页表索引这些「页表页」。最著名的是**两级页表**：

- **逻辑地址拆成三段**：一级页号 $p_1$ + 二级页号 $p_2$ + 偏移 $d$。
- **外层页表（page directory）**：$p_1$ 索引外层页表，表项指向一个内层页表页。
- **内层页表（page table）**：$p_2$ 索引内层页表，表项指向物理页框。
- **物理地址** = 页框号 × 页大小 + $d$。

**核心收益**：**不需要为整个地址空间分配页表**——内层页表页按需分配（进程只用到的页才建对应页表页）。一个 2^52 页的地址空间，若只用了 1000 页，就只需 1 个外层页表 + 1~2 个内层页表页。

**公式解析：两级页表的地址拆分**

$$\text{逻辑地址} = \underbrace{p_1}_{\text{外层索引}} \; \underbrace{p_2}_{\text{内层索引}} \; \underbrace{d}_{\text{页内偏移}}$$

- **$p_1$**：外层页表索引，定位「哪个内层页表页」。
- **$p_2$**：内层页表索引，定位「哪一页 → 哪个页框」。
- **$d$**：页内偏移，原样保留。
- 若页大小 4KB（$d$ 占 12 位），地址 48 位，则 $p_1$ 与 $p_2$ 各占 18 位。

**直觉**：分层把「一个巨大的数组」变成「按需生长的树」——像字典先查「首字母」再查「具体词」。现代 x86-64 用四级页表（PML4→PDPT→PD→PT），就是把两级扩展到四级的同构结构。<span class="marginnote">x86-64 的四级页表 = 分层的终极形态：PML4（页目录指针表的指针）→ PDPT → PD → PT。每级一个字段，4KB 页下 48 位地址正好拆成 9+9+9+9+12。理解两级，四级只是「多套两层」。</span>

## 2 哈希页表：哈希加速查找

**哈希页表（hashed page table）**：用哈希表组织页表——**页号作为键，哈希到哈希桶**，桶里存「页号 → 页框号」的表项（通常用链表解决冲突）。

查找：算出页号 p 的哈希值 → 定位桶 → 遍历桶内链表找 p 的表项 → 得到页框号。

**适用场景**：**地址空间远大于物理内存**（如 64 位系统，进程逻辑页数远多于物理页框）时，线性页表太大，哈希表只存「实际存在的映射」，空间高效。

- 优点：空间紧凑（只存用到的映射）。
- 缺点：哈希冲突需要遍历链表；访问局部性差（TLB 命中率低）；**非连续访问（链表）对缓存不友好**。

哈希页表在 64 位系统上常与「聚簇页表（clustered page table）」结合——把连续的多页映射存进一个表项，减少冲突与链长。

## 3 倒置页表：按页框建表

**倒置页表（inverted page table）**：**颠覆思路——不按「进程的页」建表，而按「物理页框」建表**。每个物理页框一项，表项记录「哪个进程的哪一页占着这个页框」。

- 物理内存 4GB、4KB 页 → 1M 个页框 → 倒置页表只有 1M 项——**大小与物理内存成正比，与进程数和逻辑地址空间无关**。
- 查找：给进程号 + 页号，遍历倒置页表，找「进程号匹配且页号匹配」的表项 → 该项的索引就是页框号。

**优点**：**空间极大节省**——不再为每个进程维护独立页表，整个系统一张倒置页表。
**缺点**：

- **查找慢**：要遍历全表找匹配项（需哈希加速，变成哈希倒置页表）。
- **共享困难**：多个进程共享一页时，一个页框只有一个表项，无法记录「多个进程都映射到这里」（需要额外机制）。
- 现代系统（如 64 位 Solaris、PowerPC）用**哈希倒置页表**：把「进程号+页号」哈希到桶，桶内小范围查找。

**辨析｜易错点：** 「倒置页表 = 省空间，所以最好」是片面之词。**倒置页表省了空间却毁了「每个进程独立页表」的隔离简洁性**——多进程共享内存时表项冲突、查找要带进程号。三种结构各有利弊，现代系统实际是**分层页表为主（x86-64）、哈希/倒置为辅**的组合。**结构选择是空间、时间、隔离三者的权衡。**

## 4 核心对比表：三种页表结构

| 维度 | 分层页表 | 哈希页表 | 倒置页表 |
| --- | --- | --- | --- |
| 组织方式 | 树形（多级） | 散列桶 | 按物理页框建表 |
| 空间 | 按需分配，中 | 紧凑 | 最小（与物理内存成正比） |
| 查找 | 多级索引，快 | 哈希+遍历链 | 全表遍历（需哈希） |
| 进程隔离 | 独立页表 | 独立 | 需带进程号 |
| 共享支持 | 好 | 中 | 差 |
| 现代使用 | **x86-64 主流** | 64 位系统辅助 | PowerPC、Solaris |

## 5 小结

- **分层页表**把页表切成页再建外层索引，按需生长，x86-64 用四级分层。
- 两级地址拆成 $p_1 + p_2 + d$；分层省的是「为整个地址空间预留页表」的空间。
- **哈希页表**用散列桶存「实际存在的映射」，空间紧凑但局部性差。
- **倒置页表**按物理页框建表，空间与物理内存成正比，但查找慢、共享难。
- 结构选择是空间/时间/隔离的权衡，现代以分层为主、哈希倒置为辅。
