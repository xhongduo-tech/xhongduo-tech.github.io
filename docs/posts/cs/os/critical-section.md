## 为什么从临界区问题开始

我们在《共享数据与竞态条件》里看到：两个线程同时执行 `count++` 会丢更新。当时的结论是「需要互斥」。这一节把「互斥」做成形式化的要求——**临界区问题**。它是第六篇《进程同步》的纲领：所有同步工具（Peterson、锁、信号量、管程）都是在满足临界区问题的三原则。<span class="marginnote">回顾竞态条件的因果链：共享数据 → 临界区 → 竞态 → 互斥。临界区问题是「互斥该达到什么标准」的形式化定义，后续所有原语都是它的实现方案。</span>

## 1 临界区问题：定义与结构

**临界区问题（critical-section problem）**：设计一组协议，让多个进程访问共享数据时不会产生竞态。每个进程的代码按结构分为四段：

1. **进入区（entry section）**：请求进入临界区的许可。
2. **临界区（critical section）**：访问共享数据的代码段，一次只允许一个进程进入。
3. **退出区（exit section）**：释放临界区，允许下一个进程进入。
4. **剩余区（remainder section）**：其余代码。

典型结构（伪代码）：

```
do {
    /* 进入区：请求进入临界区的许可 */
    /* 临界区：访问共享数据，一次只进一个进程 */
    /* 退出区：释放临界区，允许下一个进程进入 */
    /* 剩余区：其余代码 */
} while (true);
```

**进入区与退出区是协议的核心**——进程在进入区「敲门」，在退出区「开门」。临界区问题的全部学问，就是让这扇门「一次只放一个人进」。

## 2 互斥三原则：同步的黄金标准

一个正确的临界区解决方案必须满足三个要求：

**互斥（mutual exclusion）**：若进程 $P_i$ 在临界区执行，则其他任何进程不得同时处于临界区。**同一时刻最多一个进程在临界区内。**
**前进（progress）**：若临界区空闲，且若干进程正在进入区请求进入，则**必须由这些进程中的一个进入**，且这一选择不能无限推迟。**「门开着但没人进」是不允许的。**
**有限等待（bounded waiting）**：一个进程发出进入请求后，在**有限次**其他进程进入临界区之后，它必须被允许进入。**任何进程都不能被无限饿死。**

这三个原则从三个角度堵住漏洞：互斥堵「同时进」，前进堵「没人进」，有限等待堵「有人永远进不去」。<span class="marginnote">互斥三原则与调度的「无饥饿」一脉相承，但层次更高：调度解决「谁上 CPU」，三原则解决「谁进临界区」。而且注意：三原则是「至少要有」的底线，工程实现往往还要更强的性质（如优先级继承）。</span>

## 3 三原则背后的设计直觉

- **互斥**是最根本的：没有互斥，前面所有同步都失去意义。它直接对应「一次一个进程」的物理要求。
- **前进**针对「死锁式的空转」：若所有进程都在进不去，说明协议把「门」锁死了。它排除「互相谦让导致无人进入」的窘境。
- **有限等待**针对「饥饿式的排队」：若某个进程永远轮不到，即使互斥和前进都满足，协议对它是「慢性谋杀」。它排除「高优先级进程无限插队」的可能。

**三原则是递减的宽松**：互斥最严（硬性要求），前进次之，有限等待最软（但要存在）。一个协议可能满足前两个却违背第三个——比如「到达次序写死、先到者永远优先」可能让后到者无限等待。

## 4 核心对比表：三原则 vs 两个反例

| 原则 | 禁止的现象 | 反例场景 |
| --- | --- | --- |
| 互斥 | 两进程同时进临界区 | 无锁计数器丢更新 |
| 前进 | 门开着却无人进（死锁） | 双进程互相等对方先退 |
| 有限等待 | 有人永远进不去（饥饿） | 高优先级进程无限插队 |

**辨析｜易错点：** 「有了互斥就安全」是最常见的误区。**互斥只是第一步**——它防「同时」，但防不了「死锁」与「饥饿」。一个方案若满足互斥却在极端情况下死锁（违背前进）或饿死某进程（违背有限等待），仍然是错误的方案。**评判一个同步协议，要拿三原则逐一过筛，缺一不可。**

另一个易错点：**「临界区越小越好」**。临界区里是共享数据操作，临界区越大，互斥的「门」关得越久，其他进程等得越久，并发度越低。但临界区太小（比如把一个操作拆成两半）又可能破坏原子性。**临界区的粒度是并发正确性与并发性能的权衡点。**

## 5 小结

- 进程代码分为**进入区、临界区、退出区、剩余区**四段；临界区一次只进一个进程。
- **互斥三原则**：**互斥**（同时最多一个进入）、**前进**（空闲时必须有人进）、**有限等待**（无人被无限饿死）。
- 三原则分别防「同时进」「没人进」「永远进不去」三类漏洞。
- 只满足互斥不够，还要满足前进与有限等待，方案才算正确。
- 临界区粒度是正确性与性能的权衡，越小并发越好但不可破坏原子性。
