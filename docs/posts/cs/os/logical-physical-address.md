## 为什么从逻辑地址与物理地址开始

从死锁回到主线。操作系统管理资源，而**内存是最重要的资源**——所有进程的代码与数据都装在内存里。内存管理的起点是两个看似相近却天差地别的概念：**逻辑地址**（进程看到的）与**物理地址**（硬件看到的）。这两个地址之间的「翻译」机制，就是内存管理的全部技术演化史。<span class="marginnote">回顾进程概念：进程有独立地址空间。为什么能独立？因为每个进程用的是「自己的逻辑地址」，经翻译后才落到物理内存——互不打架。逻辑地址是进程的「幻觉空间」，物理地址是机器的「真实空间」。</span>

先做一个思想实验，把这两个概念分清楚。假设物理内存只有 4 KB，里面装着两个进程 A 和 B。A 装在物理地址 0–2047，B 装在物理地址 2048–4095。两个进程里的**第一个变量**（逻辑地址 0）分别对应物理地址 0 和 2048——**同一个逻辑地址 0，在两个进程里指向完全不同的物理单元**。如果操作系统不做这层翻译，让 B 也直接写物理地址 0，就会覆盖 A 的数据。记住这个实验，本节的所有概念都从这里长出来。

这个思想实验还顺带回答了「为什么每个进程都从地址 0 开始」的疑问：不是巧合，而是**逻辑地址空间是每个进程私有的「幻觉」，从 0 开始只是约定**。真实位置由操作系统分配，翻译机制负责对接。

## 1 两个地址的定义

**物理地址（physical address）**：内存单元的硬件地址——从 0 到物理内存总量-1 的真实编号。CPU 通过物理地址访问物理内存。

**逻辑地址（logical address）**：程序生成的地址，是进程视角下的地址——从 0 开始，与物理地址**无关**。程序里的指针、变量地址都是逻辑地址。

**关键区别**：

同一个逻辑地址（如 0x1000）在不同的进程里，翻译后可能是**不同的物理地址**。
程序的链接、编译、跳转都基于逻辑地址——**程序从不知道、也不必知道物理地址**。

一个更细的区分值得记下来：**逻辑地址由 CPU 产生、在执行流中可见**（取指、访存、跳转目标都是逻辑地址）；**物理地址只在访存那一瞬间由 MMU 产出，之后就被硬件消化掉了**，不进入程序的任何数据结构。你可以把「逻辑地址」理解为程序语言的地址，把「物理地址」理解为硬件总线上的地址——两者之间隔着一道 MMU 的关卡。

**逻辑地址有时也叫虚拟地址（virtual address）**，但严格说二者有细微差别（虚拟地址在分页/虚拟内存体系里，逻辑地址更泛指 CPU 生成的地址）。大多数教材把「逻辑地址」与「虚拟地址」混用。

地址空间的大小由**逻辑地址的位数**决定，与物理内存大小无关。32 位系统逻辑地址从 0 到 $2^{32}-1$，即 4 GB 的逻辑空间；64 位系统理论上可达 $2^{64}$。物理内存可能只有 8 GB，但每个进程的逻辑地址空间照旧是 4 GB 或更大——**「逻辑空间大」不等于「物理内存大」，中间全靠翻译机制去对账**。<span class="marginnote">这个「逻辑空间远大于物理内存」的差额，正是后面虚拟内存、请求分页能成立的前提：进程以为有 4 GB 可用，实际只有少量物理页，其余按需调入。</span>

## 2 地址翻译：MMU 的活

进程访问逻辑地址时，硬件**内存管理单元（MMU, Memory Management Unit）**负责把逻辑地址翻译成物理地址，再送去访存：

MMU 是**独立于 CPU 执行单元的一块硬件**，每次访存指令都经过它。它的关键设计是：翻译发生在「取指/访存」这个动作的**微架构层面**——对程序员和高级语言完全透明。你写 `int a = b + 1;` 时根本不会知道 `b` 的地址被 MMU 平移过；但在操作系统内部，MMU 的配置（基址、界限、页表基址）却是内核在每次进程切换时都要更新的「关键状态」。

```
CPU ──逻辑地址──→ MMU ──物理地址──→ 主存
```

**最简单的翻译（重定位）**：物理地址 = 逻辑地址 + **重定位寄存器（relocation register）**中的基址。进程被装入物理内存的基址，例如基址 = 14000，则逻辑地址 346 翻译成物理地址 14346。

把这个加法做成一个完整的数值算例：进程 P 被装入物理内存的基址 14000，它的代码段占用逻辑地址 0–1999，数据段 2000–2999，栈段从 3000 向下。CPU 想读 P 的第 500 个字节（逻辑地址 500），MMU 算出物理地址 $500 + 14000 = 14500$，于是访问物理单元 14500。若 P 后来被换出再换入，装到了基址 30000，MMU 只需把重定位寄存器改成 30000——**P 的代码一个字都不用改**，逻辑地址 500 依然翻译到新位置 30500。这就是「重定位」这个名字的含义：装到哪里，由装载时决定，程序本身无感。

**辨析｜易错点：** 「逻辑地址是假的，物理地址是真的，翻译只是加法」——加法只是最简模型。**现代系统用分页/分段做翻译（见后续几篇），不是简单加基址**。简单加法模型（连续分配）的问题是：进程必须装在连续的内存块里，内存碎片严重。**翻译机制的复杂度，决定了内存管理的精致程度。**

## 3 为什么要翻译：三个好处

**进程隔离**：每个进程从逻辑 0 开始，互不干扰——进程 A 的逻辑 100 与进程 B 的逻辑 100 翻译到不同物理区，天然隔离。没有翻译机制，进程 A 的指针就能直接操作进程 B 的内存，系统就只剩崩溃与泄密。
**重定位（relocation）**：进程可以装在物理内存的任何位置——只要把基址告诉 MMU，逻辑地址不变。程序「搬家」无需修改代码。
**保护**：MMU 可检查访问是否越界（超出该进程的物理范围），配合「界地址寄存器」实现保护（见《内存保护机制》）。

**重定位的好处尤其重要**：编译链接时程序不知道会装到哪，运行前才决定——这就是「从源码到运行」的最后一步（链接与装入），是下一节的主题。<span class="marginnote">「程序能装在任何位置」是重定位的核心价值：多道程序环境下，内存里有几十个进程，每个都从自己的物理基址开始，但逻辑地址都从 0 开始。<strong>逻辑地址让「写程序」与「装程序」彻底解耦</strong>——这是内存管理送给编程的礼物。</span>

三条好处不是并列的三个装饰，而是**一环扣一环**：先有隔离（进程互不干扰），才敢让多个进程同时驻留内存；能同时驻留，就必须解决「每个进程装在哪」——于是需要重定位；装好了还不放心，才要加保护（越界检查）兜底。换句话说，**翻译机制一次性地把「多道程序」从概念变成了可能**：没有它，多道程序只是「把多个程序塞进一块内存」的物理拼图，每个程序都要在编译时就定死装载位置，重编译是家常便饭。

再补充一个保护的实际意义：内存里既有操作系统内核，又有各进程，若进程能随便写物理地址 0（那通常是中断向量或内核区），一次越界写就能让整台机器崩溃。**保护不是「礼仪」，而是把「用户进程访问内存」这扇门从「全通」收紧成「只通自己的那一段」**——这扇门在用户态/内核态之分（第一篇《用户态与内核态》）之上再加一层粒度更细的控制。

## 4 核心对比表：逻辑地址 vs 物理地址

| 维度 | 逻辑地址 | 物理地址 |
| --- | --- | --- |
| 谁生成 | 程序/CPU（编译期与运行期） | MMU 翻译后的地址 |
| 空间 | 0 到逻辑空间上限 | 0 到物理内存上限 |
| 是否唯一 | 不唯一（多进程共用同一逻辑空间） | 唯一（每个物理单元一个地址） |
| 谁看见 | 进程（指针、跳转） | 硬件（访存） |
| 翻译 | — | 由 MMU 完成 |

**记忆主线**：**逻辑地址是「进程的世界」，物理地址是「机器的世界」，MMU 是翻译官。** 后面几篇的分页、分段、段页式，都是「翻译官」的不同任职方式。

## 5 数值算例：同一程序装两次

把「重定位」用一个完整的两次装载过程演算一遍，理解会更牢固。设程序 P 含三个逻辑段：代码 0–999、数据 1000–1499、栈 2000–2499。

| 逻辑地址 | 第一次装入（基址 3000）物理地址 | 第二次装入（基址 60000）物理地址 |
| --- | --- | --- |
| 代码第一条指令 0 | 3000 | 60000 |
| 数据区起始 1000 | 4000 | 61000 |
| 栈顶 2499 | 5499 | 62499 |
| 越界地址 2500 | 5500（若未加界地址检查则越界） | 62500（同上） |

**读表要点**：两列物理地址完全不同，但逻辑地址一模一样——程序代码一字未改，只是 MMU 的基址寄存器换了值。同时注意最后一行：逻辑地址 2500 超出 P 的逻辑空间（最大 2499），单纯加基址**不会**报错，必须配合**界限寄存器**检查，否则进程会误读它之后的物理区域——这正是下一节《内存保护机制》要解决的问题。<span class="marginnote">重定位解决「装哪里」，界限检查解决「装多宽」。两者配合才是完整的连续分配内存保护：基址管起点，界限管终点，越界即抛出异常交给操作系统处理。</span>

## 7 小结

- **逻辑地址**：进程视角、从 0 开始、与物理位置无关；**物理地址**：硬件真实地址、唯一。
- **MMU** 负责翻译，最简单的模型是「物理 = 逻辑 + 重定位基址」。
- 翻译带来**隔离、重定位、保护**三大好处。
- 「逻辑地址与物理地址解耦」让程序与装位置无关，是多道程序的前提。
- 现代翻译用分页/分段，连续分配 + 基址只是最简起点。
- **逻辑空间大小由地址位数决定**：32 位是 4 GB 逻辑空间，与物理内存大小无关——差额是虚拟内存的地基。
- **加基址不等于越界检查**：重定位管「装哪」，界限寄存器管「装多宽」，两者缺一不可。
- **翻译透明但昂贵**：对程序透明，却要在每次进程切换时更新 MMU 状态——这为后面「上下文切换开销」埋下伏笔。
- **翻译机制的复杂度 = 内存管理的精致程度**：从加法到分页、分段，都是「翻译官」换任职方式。
- 复习提示：把本节「基址 + 逻辑地址」的翻译路径与第一篇《进程概念》的「进程 = 地址空间 + 资源」对读，两条线在 MMU 处交汇。

在下一节，我们看程序「从磁盘到内存」的最后旅程——**程序链接与装入：绝对装入、可重定位装入与动态运行时装入**。那里我们将回答一个本节刚埋下的问题：程序在编译链接时地址还没有定下来，装入时究竟怎么一步步走到「MMU 拿到基址」这一步，以及「链接期重定位」与「运行时重定位」两条路线各付什么代价——答案会印证本节那句「翻译机制越复杂，内存管理越精致」。
