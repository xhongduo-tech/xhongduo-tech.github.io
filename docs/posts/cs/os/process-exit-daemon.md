## 为什么从进程退出与守护进程开始

讲了进程的「生」（fork/exec）与「变」（状态），这一节补上「死」（exit）与「回收」（wait），以及一种特殊的长驻进程——**守护进程（daemon）**。退出与 wait 是防止僵尸的关键，daemon 是服务进程的常见形态。<span class="marginnote">回顾《进程创建与终止》：僵尸 = 已死未回收。这一节在 Linux 上展开——exit 做什么、wait 怎么回收、exit vs _exit 的区别，以及守护进程如何「脱离终端」永驻后台。</span>

## 1 进程退出：exit 与 _exit

**进程退出**的两个层次：

- **_exit / exit_group**：**真正的系统调用**——内核终止进程：释放内存、关闭文件、通知父进程。
- **exit**：**库函数**——先执行用户清理（调用 atexit 注册的函数、冲刷 stdio 缓冲），最后调 _exit。

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("hello");     /* 只写进 stdio 缓冲区，未落盘 */
    // exit(0);          /* 会冲刷缓冲区：正常输出 */
    _exit(0);            /* 跳过一切清理：缓冲内容丢失 */
}
```

**辨析｜易错点：** 「exit 和 _exit 一样」是常见误解。**exit 会刷新 stdio 缓冲区、执行 atexit 清理**；_exit 立即终止、**跳过一切清理**。**fork 后子进程若用 exit，会刷新父进程的 stdio 缓冲（子进程共享副本），可能造成缓冲被写两次**——所以 fork 后的子进程通常用 _exit。

**退出后的状态**：

- 进程变为**僵尸**（回顾《僵尸进程》）——PCB 保留，等父进程 wait。
- 退出码（0~255）记录在 PCB，供 wait 读取。

## 2 wait 家族：回收与状态

**wait 家族**回收子进程并读取退出状态：

| 函数 | 作用 |
| --- | --- |
| wait | 等待**任意**子进程终止 |
| waitpid | 等待**指定**子进程 |
| waitid | 更精细的等待 |

**wait 的语义**：

1. 阻塞直到子进程终止（或已有僵尸）。
2. 读取子进程的**退出状态**（正常退出码 / 信号终止）。
3. **回收 PCB**——僵尸消失。

**状态解读宏**：

- WIFEXITED：是否正常退出；WEXITSTATUS：退出码。
- WIFSIGNALED：是否被信号终止；WTERMSIG：终止信号。

**不 wait 的后果**：子进程变僵尸，占着 PID 与 PCB——**长驻服务里每个 fork 都必须配 wait**，否则僵尸堆积（回顾《进程创建与终止》的警示）。

## 3 守护进程（Daemon）：离群的守望者

**守护进程（daemon）**：**后台运行、无终端、长期存活**的进程——服务系统或其他程序（如 sshd、httpd、crond）。

**守护进程的特征**：

- **后台运行**：脱离控制终端（不因终端关闭而死）。
- **无交互**：标准输入/输出/错误重定向到 /dev/null 或日志文件。
- **长期存活**：通常随系统启动、常驻运行。

**如何创建守护进程（daemonize）**——经典步骤：

1. fork 后**父进程退出**——子进程变成孤儿，被 init 收养。
2. 子进程 setsid()——**创建新会话，脱离控制终端**。
3. chdir("/")——不占用当前目录（防止卸载问题）。
4. umask(0)——清除文件创建掩码（保证创建文件权限可控）。
5. **关闭/重定向标准 fd**——把 stdin/stdout/stderr 指向 /dev/null 或日志。
6. 可选再 fork 一次——确保不再获得终端。

**公式解析：setsid 的作用**

```c
pid_t setsid(void);   /* 创建新会话并脱离控制终端 */
```

- **会话（session）**：一组进程的集合，通常关联一个控制终端。
- setsid 让进程**成为新会话的领头进程**，且**没有控制终端**——终端关闭不影响它。
- **脱离终端 = 不依赖终端存活**——这是守护进程「永驻」的关键。

**直觉**：守护进程的本质是「**脱离用户环境、自成体系**」——不依赖终端、不依赖 cwd、不依赖用户的标准 fd。**systemd 是现代 Linux 的守护进程管理器**——它负责启动/监控/重启守护进程。

**辨析｜易错点：** 「守护进程 = 后台进程（&）」是常见混淆。**「&」只是「后台执行」，仍属于当前终端会话**——终端关闭它会被挂起（SIGHUP）；**守护进程是「完全脱离终端」**，终端关闭与它无关。**区别在「是否脱离会话/终端」**，不是「是否后台」。

## 4 核心对比表：前台 / 后台 / 守护进程

| 维度 | 前台进程 | 后台进程（&） | 守护进程 |
| --- | --- | --- | --- |
| 控制终端 | 有 | 有 | **无（setsid 脱离）** |
| 终端关闭 | 收到 SIGHUP | 收到 SIGHUP | **不受影响** |
| 生命周期 | 随终端 | 随会话 | 长期独立 |
| 交互 | 有 | 无 | 无（重定向 fd） |
| 典型 | shell 命令 | 命令 & | sshd、nginx |

## 5 小结

- **exit**（库，清理+终止）vs **_exit**（系统调用，立即终止）——fork 后子进程用 _exit 更安全。
- **wait 家族**回收子进程、读取退出状态——不 wait 则僵尸堆积。
- **守护进程**：后台、无终端、长期存活——setsid 创建。
- setsid 让进程脱离控制终端，终端关闭不影响。
- 前台/后台/守护进程的区别在**是否脱离终端与会话**。
