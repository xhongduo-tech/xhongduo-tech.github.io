## 为什么从 I/O 控制方式开始

CPU 与设备交换数据，关键问题是：**CPU 要花多少精力在「等设备」上？** 从最原始的程序轮询，到中断驱动，再到 DMA 与通道——每一次演进都在**把 CPU 从 I/O 的等待与搬运中解放出来**。这一节是理解「为什么现代系统能一边做计算一边做 I/O」的关键。<span class="marginnote">回顾《计算机系统结构》的 I/O 结构：DMA 与设备控制器。这一节把 I/O 控制的四种方式按「CPU 介入程度」从高到低排开——<strong>从「CPU 亲力亲为」到「CPU 当甩手掌柜」</strong>，是理解 I/O 演进的坐标系。</span>

## 1 程序轮询：CPU 死等

**程序轮询（polling）**：CPU 发起 I/O 后，**反复检查设备状态寄存器**，直到设备「完成」才继续。

```c
// 轮询读磁盘（概念示意）
while (status_reg & BUSY);   // 忙就死等
data = data_reg;             // 设备完成后取数据
```

**问题**：**忙等（busy-waiting）**——CPU 把时间花在「空转检查」上，设备慢（毫秒级）时 CPU 几乎被锁死。**浪费极其严重**：磁盘读 10ms，CPU 就空转 10ms。

**适用**：极简单的设备、I/O 极快的场景（如读一个状态寄存器）；现代系统里轮询只用于「等设备就绪」的极短时刻。

## 2 中断驱动：设备好了叫 CPU

**中断驱动 I/O（interrupt-driven I/O）**：CPU 发起 I/O 后**去干别的**；设备完成时**发中断**，CPU 被中断打断、处理完成、继续原来的工作。

```
CPU 发 I/O 命令 → 继续执行其他进程
        ...设备工作...
设备完成 → 发中断 → CPU 处理中断（取数据/检查结果）→ 恢复执行
```

**收益**：CPU 不再空等——设备慢时 CPU 可以做计算（**I/O 与计算重叠**）。这是多道程序并发的基础。

**代价**：

- **每次 I/O 一次中断**：小数据量高频 I/O（如每字节一次）会中断风暴。
- 中断处理有开销（保存现场、切换）。

**适用范围**：字符设备（键盘每按一键一次中断）、控制器按「每块完成」发中断的磁盘 I/O。**中断驱动是「每次传输数据量小」时的默认方案**。

## 3 DMA：数据自己飞进内存

**DMA（Direct Memory Access，直接内存访问）**：**DMA 控制器**直接在**设备与内存之间搬运数据**，CPU 只负责「下达命令」与「接收完成通知」。

```
CPU 配置 DMA（源、目的、长度）→ CPU 去做别的
        DMA 控制器搬运数据（设备 ↔ 内存，不经 CPU）
DMA 完成 → 发中断通知 CPU → CPU 处理
```

**为什么需要 DMA**：中断驱动虽然不空等，但**每传输一个数据单元（字节/字）都要 CPU 参与**（从控制器缓冲拷到内存）。大块数据（如读 1MB 磁盘块）时，CPU 会被「逐单元拷贝」淹没。**DMA 让控制器自己把整块数据搬进内存，CPU 只在开始与结束时介入。**

**公式解析：DMA 省下的 CPU 时间**

设要传输 $N$ 字节，每字节经 CPU 拷贝耗时 $c$：

$$\text{CPU 节省} = N \times c \quad \text{（中断驱动逐字节搬运被 DMA 替代）}$$

- **中断驱动**：CPU 参与每字节的搬运——开销 $N \cdot c$。
- **DMA**：CPU 只配置（一次）+ 收完成中断（一次）——开销可忽略。
- 1MB 传输，$c = 100\text{ns}$：节省约 **100ms** 的 CPU 时间。

**DMA 是现代块设备（磁盘、SSD、网卡）的标准**——大块数据传输全靠它。

## 4 通道：I/O 的「专职小 CPU」

**通道（channel / I/O processor）**：一种**更独立于 CPU 的 I/O 控制方式**——通道是**专门执行 I/O 程序的小处理器**，可以执行一串 I/O 指令（I/O 程序），自主完成复杂的 I/O 操作。

- **通道程序**：由 CPU 定义的一连串 I/O 操作（读多个块、到不同内存位置）。
- 通道独立执行通道程序，CPU 只发起与接收结果。
- 通道 I/O 主要见于大型机（mainframe）——比 DMA 更强的自主性，可管理多设备。

**对照**：DMA 是「一次搬一块」，通道是「执行一整段 I/O 程序」——**通道 = DMA 的「程序化」版本**。

## 5 核心对比表：四种 I/O 控制方式

| 维度 | 轮询 | 中断驱动 | DMA | 通道 |
| --- | --- | --- | --- | --- |
| CPU 等待 | 忙等 | 不等待 | 不等待 | 不等待 |
| 数据搬运 | CPU | CPU | **DMA 控制器** | 通道处理器 |
| 一次传输单元 | 字节/字 | 字节/字 | 块（大批量） | 通道程序 |
| CPU 开销 | 最高 | 高 | 低 | 最低 |
| 现代使用 | 简单设备 | 字符设备 | **块设备标准** | 大型机 |

**设计启示**：四种方式的演进主线是「**CPU 参与度递减**」——从「CPU 死等」到「CPU 被叫醒」到「CPU 被解放」到「CPU 只下令」。这条主线也贯穿了中断与 DMA 的现代组合：**中断通知 + DMA 搬运**是当前 I/O 的事实标准。

## 6 小结

- **程序轮询**：CPU 忙等设备状态——最简单但浪费 CPU。
- **中断驱动**：设备完成发中断，CPU 去干别的——I/O 与计算重叠，适合小数据量。
- **DMA**：DMA 控制器直接搬设备↔内存数据，CPU 只下命令收通知——块设备标准。
- **通道**：通道处理器执行 I/O 程序，CPU 只发起与收结果——大型机方案。
- 演进主线：**CPU 参与度递减**，现代标准 = 中断通知 + DMA 搬运。
