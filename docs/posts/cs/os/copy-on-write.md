## 为什么从写时复制开始

`fork()` 要创建子进程，最直接的做法是把父进程地址空间全部复制一份——代价与进程大小成正比。**写时复制（Copy-on-Write, COW）**给出聪明的答案：**先不复制，让父子共享同一批物理页；只有当某一方真正「写」某个页时，才复制那一页。** 这让 `fork()` 的开销从「复制整个地址空间」降到「只复制页表」。<span class="marginnote">回顾《进程创建》：早期 fork 完整复制地址空间。COW 把「复制」推迟到「写」发生的那一刻——这是「懒求值（lazy evaluation）」在内存管理中的经典应用，也是请求分页思想的延伸。</span>

## 1 COW 的基本思想

**写时复制（COW, Copy-on-Write）**：多个进程**共享**同一物理页，把这些页标为**只读**；当某个进程**尝试写入**共享页时，触发缺页中断，操作系统**复制该页**并把写进程的页表改为指向副本，再执行写操作。

`fork` + COW 的流程：

1. 父进程 `fork()`：**不复制任何物理页**，子进程页表指向父进程的物理页，所有共享页标为只读。
2. 父/子进程**读**共享页：正常访问，零开销。
3. 某个进程**写**共享页：写保护 → **缺页中断**。
4. 缺页处理：复制该页（分配新页框、拷贝内容），把写进程的页表项指向副本并改为可写，重新执行写指令。
5. 从此该页归写进程私有，父子分道扬镳。

**核心洞察**：fork 之后子进程通常立刻 `exec`（`execve`）换程序（根本用不到父进程的内存）——**复制的 99% 都是浪费**。COW 把浪费推迟为「写才付」，而大多数共享页永远没人写，复制成本被省掉。

## 2 COW 的机制细节

**写保护的设置**：共享页的页表项只读位（read-only）置位。写只读页 → CPU 触发「写保护」缺页异常 → 内核识别「这是 COW 页」→ 复制。

**页表项/页帧需要额外信息**：内核要区分「真只读页」（如代码段，永远只读）与「COW 页」（临时只读，可写者共享）——用**页表项的标志位**或**页帧结构（如 Linux 的 `struct page` 的 `_refcount` 引用计数）**来记录：该物理页被几个进程共享（引用计数）。引用计数 = 1 时无需复制，直接改回可写。

**空闲页框不足时的退路**：COW 复制需要新页框；若内存紧张，fork 本身可能失败或触发回收——这也是「fork 可能失败」的原因之一。

**一个工程细节**：COW 页的只读位也有副作用——父子频繁**交替写**同一共享页时，每一页都要各复制一次，COW 反而比「干脆共享可写」更慢。因此追求极致性能的中间件往往改用 `mmap` 的共享映射（`MAP_SHARED`）或共享内存直接传数据，而不是靠 fork 传参——读懂了 COW 的机制，你就能理解这些工程取舍的来由。

**辨析｜易错点：** 「COW 的页永远只读」是误解。**COW 页是「临时的只读」，一旦复制完成、引用计数归 1，就恢复可写**——它只是「用只读位做共享标记」，不是「永久只读」。另一个易错点：**「COW 只在 fork 里用」**——COW 思想遍布系统：`mmap`（`MAP_PRIVATE`）的私有映射、`malloc`（堆区）的延迟分配、虚拟机的内存共享（KSM）、数据库的页级延迟复制，都是 COW 变体。<span class="marginnote">COW 的「共享直到写」思想在更广的领域发光：数据库用 COW 做快照（写时才复制数据页，快照几乎零成本）、文件系统 Btrfs 用 COW 做写时复制语义、KVM 的 KSM 合并相同页。<strong>「延迟到必须时再付代价」是系统设计中反复出现的万能工具。</strong></span>

## 3 公式解析：COW 省下的复制量

设进程有 $N$ 个物理页，fork 后子进程实际会写入的比例为 $w$（$0\le w \le 1$）：

$$\text{传统 fork 复制量} = N, \qquad \text{COW fork 复制量} = w \cdot N$$

- **$N$**：进程物理页数。
- **$w$**：子进程实际写入的页比例（通常远小于 1——子进程往往马上 exec）。
- 传统 fork 复制全部 $N$ 页；COW 只复制被写的 $wN$ 页。

**直觉**：$w$ 越小，COW 越赚。典型场景：shell（bash）fork 子进程去跑一个命令——子进程立即 exec，$w \approx 0$，COW 让 fork 近乎免费。若子进程真的大改特改父进程内存（$w$ 接近 1），COW 与传统 fork 复制量相当，但 COW 至少**摊销**了复制成本（按需、分散到写时）。

**COW 与请求分页的联动**：COW 的复制页与请求分页的调入页都需要「先缺页、再处理」。Linux 的 `fork()` 甚至不分配子进程的新页表页（延迟到需要时），把「懒惰」贯彻到底。

**Linux 中的 COW 细节**：`fork()` 在内核对应 `kernel_clone`，创建子进程时复制 `task_struct` 与页表；COW 的关键动作在 `dup_mmap`——把父子共享的私有页统一标只读、递增物理页引用计数。首次写共享页触发 `handle_mm_fault` 的 COW 路径（`do_cow_fault`），分配新页框、拷贝内容、把写进程页表项指向副本。而 `vfork`/`clone(CLONE_VM)` 干脆共享整个地址空间、跳过页表复制——代价是父子不能同时运行。想观察它：`strace -f` 能看 fork 的系统调用轨迹，`perf` 可测 fork 的耗时随地址空间大小是否几乎不变。

## 4 核心对比表：传统 fork vs COW fork

| 维度 | 传统 fork | COW fork |
| --- | --- | --- |
| 初始复制 | 复制全部 $N$ 页 | 不复制（共享） |
| 共享页权限 | 各自可写 | 临时只读 |
| 写触发 | 直接写 | 缺页中断 → 复制 |
| 开销 | 与 $N$ 成正比 | 与写入页数成正比 |
| 子进程马上 exec | 白付全部复制 | 几乎零成本 |
| 现代实现 | 已废弃 | Linux/Unix 标配 |

## 5 数值算例：COW 到底省了多少

给公式配一组具体数字。设进程有 $N = 10000$ 页、每页 4 KB，即地址空间约 40 MB；内存拷贝带宽按 5 GB/s 估算：

- **传统 fork**：复制全部 $N$ 页，拷贝量 $= 10000 \times 4\,\mathrm{KB} = 40\,\mathrm{MB}$，耗时约 $40\,\mathrm{MB} / 5\,\mathrm{GB/s} \approx 8\,\mathrm{ms}$。
- **COW fork（子进程写入 1% 的页）**：只复制 $wN = 100$ 页，拷贝量 $= 400\,\mathrm{KB}$，耗时约 $80\,\mu s$。
- 两种 fork 的时间差约 **100 倍**；若子进程立刻 `exec`（$w \approx 0$），COW 的拷贝量趋近于零。

把 $w$ 与省下的比例做成一张表：

| 子进程写入比例 $w$ | COW 复制量 | 相比传统 fork 省下 |
| --- | --- | --- |
| 0%（立即 exec） | 0 页 | 100% |
| 1% | 100 页（400 KB） | 99% |
| 10% | 1000 页（4 MB） | 90% |
| 100% | 10000 页（40 MB） | 0% |

**结论**：COW 的收益几乎完全取决于「子进程到底写多少」。这就是为什么 Unix 编程里「fork 之后立刻 exec」是铁律——它让 $w$ 压到接近 0，把 fork 的代价省到可以忽略。

## 6 术语速查

| 术语 | 含义 |
| --- | --- |
| 写时复制（COW） | 共享物理页、标只读，写时才复制该页 |
| 引用计数 | 记录一个物理页被几个进程共享，归 1 则恢复可写 |
| 写保护缺页 | 写只读共享页触发的缺页异常，COW 的入口 |
| MAP_PRIVATE | `mmap` 的私有映射，读共享写复制，COW 应用 |
| 懒求值 | 把代价推迟到必须发生时才付（COW 的哲学） |
| KSM | 内核的页合并机制，合并相同物理页以省内存 |

## 7 小结

- **COW**：共享物理页 + 标只读，写时才复制——把复制推迟到必须的时刻。
- fork + COW：**不复制页、只复制页表**，共享页只读，写触发缺页复制。
- 引用计数标记共享程度：归 1 则恢复可写。
- 传统 fork 复制 $N$ 页，COW 只复制 $wN$ 页（$w$ 为写入比例，通常极小）。
- 数值：40 MB 地址空间，传统 fork 约 8 ms；COW 在 $w=1\%$ 时约 80 μs，快约 100 倍。
- COW 思想遍布系统：`mmap`（`MAP_PRIVATE`）私有映射、数据库快照、文件系统、虚拟机 KSM。
- Linux 中 COW 落在 `dup_mmap` + 缺页 COW 路径；`vfork`/`CLONE_VM` 直接共享地址空间、不复制页表。
- 「fork 后立刻 exec」是 Unix 铁律：它让写入比例 $w$ 压到接近 0，COW 近乎免费。
- 父子频繁交替写共享页时 COW 反而更慢，中间件因此倾向共享内存而非 fork 传参。
- COW 本质是**懒求值**：把「复制」的代价从 fork 时刻推迟到写发生时刻。
- 需要区分「真只读页」与「COW 临时只读页」，靠页表标志位与引用计数完成。
- 传统 fork 已废弃，COW 是 Linux/Unix 的标准实现——「共享直到写」已成为通用内存管理原则。
- 懒求值思想在下文继续出现：请求分页「用到了才调入」正是同一哲学的延续。
