## 为什么从标记-清扫开始

追踪式 GC 的第一课就是**标记-清扫（mark-sweep）**——1958 年麦卡锡为 Lisp 写的回收器，至今仍是所有现代 GC 的思想基石。它把「找垃圾」分成两个清晰的阶段：**标记（mark）**——从根出发标出所有可达对象；**清扫（sweep）**——线性扫过堆，把没标记的对象回收。简单、正确、无迁移，是一切更精细算法（复制、分代、并发）的参照系。<span class="marginnote">「标记-清扫」之所以是入门首选，因为它最直白地体现了「可达性判据」：标记阶段就是算上一节的可达集合，清扫阶段就是回收它的补集。理解了它，你就理解了「追踪式 GC 的骨架」，后续算法都是它的变体或改进。</span>

## 1 两阶段：标记与清扫

**标记-清扫（mark-and-sweep）** 分两个阶段：

**阶段一，标记（Mark）**：
1. 从根集出发，深度优先遍历对象引用图。
2. 每个被访问到的对象打上「已标记」位。
3. 结束时，所有可达对象都带标记——不可达对象无标记。

**阶段二，清扫（Sweep）**：
1. 线性扫描整个堆（所有对象）。
2. 未标记的对象：回收（把它的空间并入空闲链表）。
3. 清除所有标记，为下一轮做准备。

标记决定「谁活着」，清扫决定「谁回收」——两个阶段各自简单，组合起来正确。<span class="marginnote">「清扫是线性扫堆、不是跟着标记走」是容易忽略的细节：标记已经知道了可达对象，但清扫仍然要<strong>扫过全部对象</strong>（O(堆大小)）来找到不可达的。这个「清扫成本与存活对象多少无关、与堆大小有关」的特性，是标记-清扫的一个隐藏代价。</span>

## 2 标记阶段：深度优先遍历

标记用深度优先搜索（DFS）遍历引用图：

```
mark(obj):
  若 obj 已标记: 返回
  obj.已标记 = true
  for child in obj 的所有引用:
      mark(child)
```

**递归实现**最直接，但深度大时**递归栈会爆**——对象图可能很深。
**显式栈实现**：用显式栈替代递归，或「指针反转」等无栈技巧（Deutsch-Schorr-Waite）。
现代 GC 用显式工作栈 + 位图标记，避免递归深度问题。

**标记的代价**：时间 ∝ 可达对象数（要遍历的引用数）；而清扫的代价 ∝ 堆大小。<span class="marginnote">「标记走引用、清扫走全堆」的成本结构决定了标记-清扫的适用面：存活对象多时标记贵、堆大时清扫贵。这个「两阶段各花各的钱」的特点，被后面的复制式（只付存活对象钱）与分代（只扫年轻代）算法针对性地改进。</span>

## 3 清扫阶段：回收与空闲链表

清扫线性扫描堆，把未标记对象连入**空闲链表（free list）**：

```
sweep():
  p = 堆起始
  while p < 堆末尾:
    if p 未标记:
        把 p 并入空闲链表
    else:
        清除 p 的标记位
    p = p 的下一个对象
```

回收后的空间变成空闲块，供后续分配复用——分配器从空闲链表找块（首次/最佳适配，第六篇的堆管理策略）。

**清扫与碎片的宿命**：标记-清扫**不移动对象**（原位回收），所以它不可避免地产生**外部碎片**——大块对象分配可能因碎片失败。这是标记-清扫的经典短板。<span class="marginnote">「不移动 = 碎片」是标记-清扫的宿命：对象留在原地，回收的只是零散的空洞，无法把存活对象聚拢成大块。碎片积累到严重时，即使总空间够也可能分配失败——这促使复制式 GC 用「移动对象」根治碎片。</span>

## 4 公式解析：标记-清扫的语义正确性

标记-清扫实现的就是「回收不可达对象」：

$$\text{标记集} = \text{Reach}(R), \qquad \text{清扫回收} = \text{Heap} \setminus \text{Reach}(R)$$

- **第一步，标记即可达集**：DFS 恰好遍历「根集沿引用的传递闭包」——与可达集合的递归定义完全一致（上一节公式）。
- **第二步，清扫即补集**：未标记对象 = 堆中不在可达集里的对象——正是「可回收」的集合。
- **第三步，安全性**：回收不可达对象不影响程序——不可达意味着无引用可达，任何代码都无法访问它。

**「标记 = 可达集、清扫 = 补集」把回收正确性归结为可达性定义的正确性**——只要标记阶段忠实计算传递闭包，回收就绝对安全。

## 5 标记-清扫的优缺点

**优点**：

- 处理**循环引用**：从根出发的标记天然绕开循环问题（环里无根入口的整环都不可达）。
- 不移动对象：对象的地址不变，不破坏外部指针（对 C 风格的内存模型友好）。
- 概念简单，是理解一切 GC 的基线。

**缺点**：

- **全停顿（STW）**：标记 + 清扫都要暂停程序。
- 清扫**扫全堆**，成本与堆大小成正比。
- **外部碎片**：不移动对象，碎片积累。
- 分配需要搜索空闲链表，较慢（相对 bump pointer）。

**辨析｜易错点：** 标记-清扫 vs 复制式是「不移动」与「移动」的根本分叉：标记-清扫保住地址不变但碎片化，复制式聚拢对象但改变地址（要更新引用）。现代 GC 多采用复制式的「半区 + 分代」组合，但标记-清扫的思想（标记 + 清扫）仍在并发 GC（如 CMS 的标记阶段）中活跃。<span class="marginnote">「不移动 vs 移动」的分叉影响的不只是碎片，还有「外部指针能否持有对象」：C 语言把对象地址传给外部代码（如系统调用）后，GC 若移动对象会让指针失效，所以 C 的 GC（如 Boehm GC）只能用不移动的标记-清扫。这是「GC 策略被语言特性绑架」的典型案例。</span>

**一个两阶段的完整走查**：设堆含对象 A、B、C、D，根指向 A，A 指向 B，C、D 与根无关。

- **标记阶段**：从根出发 DFS——标记 A（根）、B（A 引用）。C、D 未标记。
- **清扫阶段**：线性扫堆——A、B 已标记，清除标记保留；C、D 未标记，空间并入空闲链表。
- **结果**：C、D 被回收，A、B 幸存且地址不变。

这个例子里，A、B 构成一条可达链，C、D 是两座「孤岛」。标记-清扫对「孤岛」和「环」（多个对象互相引用但整体不可达）一视同仁——从根走不到，就全回收。<span class="marginnote">「对孤岛与环一视同仁」正是追踪式 GC 优于引用计数的地方：环内的对象即使互相引用，只要整体从根不可达，标记就扫不到它们、清扫就全回收——不存在引用计数的「循环泄漏」问题。</span>

**术语速查**：

| 术语 | 含义 |
| --- | --- |
| 可达集合 | 从根沿引用能到达的对象集合 |
| 标记阶段 | DFS 标出全部可达对象 |
| 清扫阶段 | 线性扫堆，回收未标记对象 |
| 空闲链表 | 清扫回收的空间组织成的可复用链表 |
| STW | Stop-The-World，GC 时暂停程序 |

## 6 小结

- **标记-清扫**两阶段：标记（DFS 标出可达对象）+ 清扫（线性扫堆回收未标记）。
- 标记 = 根集传递闭包（可达集合），清扫 = 回收补集——正确性来自可达性定义。
- 成本结构：标记 ∝ 可达对象，清扫 ∝ 堆大小；深度大的对象图要用显式栈标记。
- **不移动对象** ⇒ 保留地址但产生**外部碎片**。
- 优点：处理循环引用、地址稳定、概念基础；缺点：STW、扫全堆、碎片。
