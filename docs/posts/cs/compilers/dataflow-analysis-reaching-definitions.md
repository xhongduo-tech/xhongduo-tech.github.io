## 为什么从到达定值分析开始

全局优化（CSE、常量传播、死代码消除）都需要回答同一个问题：**在程序的某一点，哪些「关于变量的定值」仍然有效？** 例：`x = 1` 之后、`x` 被重新赋值之前，`x` 的值为 1——这个「定值」到达了后续的读取点。**数据流分析（data-flow analysis）** 系统地回答这类问题，而**到达定值（reaching definitions）** 是它最经典的入门案例。<span class="marginnote">数据流分析是全局优化的「情报系统」：它不直接优化，而是告诉优化器「这里 x 一定等于 1」「这里 x 的值有两个可能来源」——优化器据此决定能否安全变换。没有数据流分析，全局优化只能是盲目的猜测。</span>

## 1 数据流分析的通用框架

数据流分析在**流图**上工作，它的骨架是四个组件：

**数据流信息**：每一点要分析的「事实」，如「哪些定值可能到达」。
**转移函数（transfer function）**：一条指令对信息的影响——「执行这条指令后，信息怎么变」。
**汇合操作（meet operation）**：多个前驱的信息汇合时怎么合并（取并集或交集）。
**方向**：向前（从入口往出口传播）或向后（从出口往入口）。

不同分析的区别只是「信息的内容」「转移」「汇合」「方向」四个参数不同——框架完全相同。<span class="marginnote">「四个组件一把框架」是数据流分析的统一视角：到达定值、活跃变量、可用表达式、常量传播，全是同一台机器换参数。理解了这台机器，就理解了第八篇的全部数据流分析。</span>

## 2 到达定值的定义

**定值（definition）**：给变量赋值的语句，如 `x = 1`。

**到达（reach）**：定值 $d$ 到达点 $p$，如果存在一条从 $d$ 到 $p$ 的执行路径，路径上 $x$ **没有被重新赋值**。直观说：沿着某条路径走到 $p$ 时，$d$ 对 $x$ 的赋值**仍然生效**。

$$x = 1 \quad(\text{定值 } d_1)$$ 
$$y = x + 1 \quad(\text{此处 } x \text{ 的定值来源是 } d_1)$$

若中间插了 $d_2$（定值 $d_2$），则 $d_1$ 被 $d_2$ **杀死（killed）**——$d_1$ 不再到达 $d_2$ 之后的位置。<span class="marginnote">「杀死」是数据流分析的生动词：新的定值把旧的定值从「到达集合」里剔除。这个「新值覆盖旧值」的机制，是转移函数的本质——也是「到达」这个分析名不虚传的由来。</span>

## 3 到达定值的方程

对每个基本块 $B$，定义两组定值集合：

- **$\text{gen}[B]$**：$B$ 内生成的定值——块内对变量赋值、且**之后块内不再重新赋值**的那些（最后一个定值才是「活着离开块」的）。
- **$\text{kill}[B]$**：$B$ 内被**杀死**的定值——程序里其他对同一变量赋值、但在 $B$ 内被重新赋值覆盖的。

数据流方程（向前传播）：

$$\text{in}[B] = \bigcup_{P \in \text{pred}(B)} \text{out}[P]$$

$$\text{out}[B] = \text{gen}[B] \cup (\text{in}[B] \setminus \text{kill}[B])$$

- **in**：块入口处到达的定值 = 所有前驱的出口定值之**并**（任一路径到达即到达）。
- **out**：块出口处到达的定值 = 块内生成的 + 入口中「未被块杀死的」。
- **kill** 的减法：入口到达的定值，若在块内被重新赋值，就被杀死了。<span class="marginnote">注意 `kill` 是「全局」集合：它包含<strong>整个程序</strong>中与块内重赋值同名的其他定值——所以「并、减」操作发生在全局变量集合上。这就是为什么数据流分析需要「全局视角」而非逐块独立的道理。</span>

## 4 公式解析：不动点迭代

数据流方程构成一个方程组，求解方法是**不动点迭代**：

$$x^{(0)} = \emptyset, \qquad x^{(k+1)} = F(x^{(k)})$$

其中 $F$ 是「把当前信息代入所有块的转移方程」。从空集出发反复迭代，直到两次迭代结果相同——**不动点（fixpoint）**。

- **第一步，起点**：所有块的 `in`/`out` 初始为空集——「还不知道任何定值到达」。
- **第二步，迭代**：每轮把各块的 in 计算成「前驱 out 的并」，再算 out。随着迭代，更多定值被发现「到达」。
- **第三步，单调收敛**：信息**只增不减**（单调），且有上界（定值总数有限），所以必然收敛到最小不动点——恰好是所有「真到达」的定值。

**「空集起步、只增不减、有界收敛」是不动点法的三件套**——它保证迭代必然终止且结果正确。这套思想不仅在编译（数据流、FIRST/FOLLOW）里，也在静态分析、抽象解释等更广的领域。

## 5 到达定值的用途

到达定值信息是多个优化的「前提」：

- **常量传播**：若 `x` 的定值只有一个、且它是常量，则 `x` 的读取可替换为常量（下一节）。
- **检测未初始化变量**：若某读取点的 `x` 无任何到达定值，说明 `x` 可能未初始化——编译器警告的依据。
- **死代码检测**：定值被杀死后从未被读，就是死代码。
- **复制传播**：`x = y` 的定值到达读取点时，可用 `y` 替换 `x`。

**重点是**：到达定值是「值的来源」信息——任何需要「x 当前等于什么」的问题，都从它出发。<span class="marginnote">「到达定值 = 值的溯源」这个视角很有用：调试器里「x 是哪一行赋的值」、静态分析器里「x 的可能取值」、甚至逆向工程里「这个变量被谁改写」，本质都是到达定值或它的变体。</span>

## 6 一个完整的不动点迭代走查

把不动点迭代落在一个含循环的小流图上。设两个块 A、B，A → B、B → A（循环）。块内容：

```
A: x = 1      # gen_A = {d1}；若程序里还有别的 x 定值 d2，kill_A = {d2}
B: y = x + 1  # gen_B = {}；kill_B = {}
```

**迭代过程**（in/out 都从空集起步）：

- **第 0 轮**：in(A)=in(B)=out(A)=out(B)=∅。
- **第 1 轮**：out(A) = gen_A ∪ (in(A)∖kill_A) = {d1}。in(B) = out(A) ∪ out(其他前驱) = {d1}；out(B) = gen_B ∪ (in(B)∖kill_B) = {d1}。in(A) = out(B) = {d1}。
- **第 2 轮**：in(A) = {d1}（不变），out(A) 不变，in(B)、out(B) 不变——**收敛**。结果：B 入口处 x 的定值来源是 d1（A 里的赋值）。

**要点**：两轮就收敛——因为「信息只增不减、有界」，且这个流图很小。真实的循环流图需要更多轮，但「空集起步、单调增、有界收敛」的三件套保证任何流图都会停。<span class="marginnote">「循环让信息在环上自我强化」是数据流迭代的直观：B 入口的 d1 被 A 杀不死（B 不写 x），所以 d1 绕环一圈仍到达——<strong>迭代正是让「绕环传播」的信息累积到收敛</strong>。没有迭代，只扫一遍会漏掉环上的信息。</span>

**辨析｜易错点：** 迭代顺序影响收敛速度但不影响结果——先用拓扑序（正向）能更快收敛，但最终不动点唯一。别把「迭代轮次」当「结果依赖迭代顺序」——结果只依赖方程，不依赖顺序。

## 7 思考与练习

**练习 1 手算 gen/kill**：对基本块 `x = 1; y = x + 1; x = 2;`，手算 `gen` 与 `kill`——注意「块内被重新赋值的变量，其旧定值被杀」。

**练习 2 不动点迭代**：对含两个块（A → B → A 的循环）的流图，手工迭代到达定值方程，标出每轮的 in/out，直到收敛——体会「从空集起步、单调增、有界」。

**练习 3 到达定值的语义**：解释「定值 d 到达点 p」的精确含义——「存在一条从 d 到 p 的路径，路径上 x 未被重新赋值」。构造一个「到达但被中间杀掉」的反例。

**练习 4 用途**：把「到达定值」接给「常量传播」（若唯一定值且为常量则替换）与「未初始化检测」（某读取点无到达定值）——各写一个小例子。<span class="marginnote">「到达定值 = 值的溯源」是它两个用途的共同基础：常量传播问「这个 x 的定值是不是常量」，未初始化检测问「x 有没有定值」——都是「谁定义了这里的 x」。调试器里「x 是第几行赋的值」也是同一个问题。</span>

**练习 5 四组件框架**：用「信息 / 转移 / 汇合 / 方向」四组件描述到达定值分析——为下两节「活跃变量」「可用表达式」的对比做准备。

**练习 6 与 FIRST/FOLLOW 对照**：到达定值的「空集起步、单调增、收敛」与 FIRST/FOLLOW 的不动点迭代是同一套数学——找两者的「转移规则」与「汇合」对应。

**常见误区**：

- **误区一**：把「到达」当「一定到达」——到达是「存在路径」，可能有多条路径、多种可能。
- **误区二**：漏掉 kill——新定值杀死旧定值，`in`/`out` 方程组的核心是「先杀后并」。
- **误区三**：以为 in 是「块内第一条指令处的到达」——in 是块入口，out 是块出口，中间指令的到达要靠「块内顺序传播」。

**延伸**：数据流分析的不动点迭代与第三级《数值分析》的「不动点迭代」同名——但一个是「集合格上的单调收敛」，一个是「实数上的收敛」；把两者的「收敛条件」对比，体会「抽象解释」的格论根基。

## 8 小结

- **数据流分析**用「信息 + 转移 + 汇合 + 方向」四组件框架，在流图上系统地推导每点的信息。
- **到达定值**：定值 $d$ 到达点 $p$ ⇔ 存在路径使 $d$ 的赋值沿路仍生效。
- 每块两组集合：**gen**（块内存活定值）与 **kill**（块内杀死的全局定值）。
- 方程：$\text{in} = \cup\,\text{out(前驱)}$，$\text{out} = \text{gen} \cup (\text{in} \setminus \text{kill})$——向前传播。
- 求解用**不动点迭代**：空集起步、单调增长、有界收敛；信息是常量传播、未初始化检测、死代码等优化的前提。
