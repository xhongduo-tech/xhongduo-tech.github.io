## 为什么从布尔表达式翻译开始

算术表达式翻译成了「算值、存临时」，但 `a < b && c != 0` 这类**布尔表达式**还有第二种玩法：不一定要算出「真/假」这个值，而是直接用**跳转**表达「什么时候走到哪」。尤其 `&&`、`||` 的**短路语义**（左侧定了就不算右侧）天然是控制流，硬用「算值」翻译会白算甚至算错。<span class="marginnote">`x != 0 && y / x > 1` 里若 `x==0`，短路要求<strong>不执行</strong> `y / x`——否则除零。用「算值」的朴素翻译会先把两侧都算出来，语义就错了。短路语义只能在控制流层面实现——这是布尔翻译必须转向跳转的根本原因。</span>

## 1 两种表示范式

**数值表示法（numerical representation）**：把布尔当整数算，真=1、假=0。

```
t1 = a < b          # 1 或 0
t2 = c != 0
t3 = t1 && t2       # 逻辑与（数值版）
```

**控制流表示法（flow-of-control representation）**：不产生布尔值，而是用「条件跳转」把程序流导向「真标号」或「假标号」。

```
if a < b goto Ltrue
goto Lfalse
```

两种范式各有主场：**数值**适合「布尔也是值」（把 `a<b` 赋给变量）；**控制流**适合「布尔决定去向」（`if` 条件、循环条件）——而后者是布尔表达式的头号用途。<span class="marginnote">C 语言把两种需求混在一起：`if (a < b)` 里 `<` 产生控制流，`x = a < b` 里 `<` 产生值。编译器通常把布尔翻译成「带真假跳转标号的代码 + 必要时贴一个真值」，两用。</span>

## 2 数值表示法的翻译

数值表示法把布尔运算当作「整数运算」的扩展：

$$a < b \quad \to \quad t = \text{如果 } a < b \text{ 则 } 1 \text{ 否则 } 0$$

$$a \land b \quad \to \quad t = a \times b \quad (\text{或 } \min(a,b))$$

$$a \lor b \quad \to \quad t = a + b - a \times b \quad (\text{或 } \max(a,b))$$

$$\neg a \quad \to \quad t = 1 - a$$

三地址码里关系运算通常是一条指令：`t = a < b` 直接产生「比较 + 置 1/0」；逻辑与/或用按位指令或算术式模拟。<span class="marginnote">数值表示法的代价：它<strong>总是算出两侧</strong>——无法短路。所以纯数值翻译只用于「布尔无副作用、无除零风险」的简单场景；真实语言只要允许 `a && f()` 这类带副作用的用法，就必须给 `&&`、`||` 用短路。</span>

## 3 短路求值：翻译成跳转

**短路求值（short-circuit evaluation）** 的语义：`a && b` 先算 `a`，若 `a` 为假则整个为假、**不再算 `b`**；`a || b` 先算 `a`，若 `a` 为真则整个为真、不再算 `b`。翻译用跳转：

$$E \to E_1 \ \&\&\ E_2$$

```
t1 = E1.code          # 计算 E1
if t1 == 0 goto Lfalse
t2 = E2.code          # 仅当 E1 非零才执行
if t2 == 0 goto Lfalse
t = 1
goto Lnext
Lfalse: t = 0
Lnext:
```

`E1` 为假直接跳 `Lfalse`，`E2` 的代码被跳过——短路由跳转结构天然实现。<span class="marginnote">观察 `Lfalse` 标签的作用：它把「短路的出口」与「正常计算的出口」统一起来。这套「真/假/下一条」三个标号的管理，是控制流翻译的标准道具，下一节的回填技术会系统化它。</span>

## 4 公式解析：跳转翻译的一般形态

把「布尔表达式翻译成跳转」写成带**真标号与假标号**的 SDT：设 $E$ 的翻译结果是「若 E 为真跳 $T$，若 E 为假跳 $F$」：

$$\text{gen}(E \to E_1 \lor E_2):\quad E_1 \text{ 真时跳 } T, \quad E_1 \text{ 假时翻译 } E_2, \quad E_2 \text{ 真跳 } T,\ E_2 \text{ 假跳 } F$$

- **第一步，逻辑或**：`a || b`——`a` 真则整体真（跳 T），`a` 假才看 `b`（翻译 `E_2`），`b` 真跳 T、假跳 F。
- **第二步，逻辑与**：`a && b`——`a` 假则整体假（跳 F），`a` 真才看 `b`，`b` 真跳 T、假跳 F。
- **第三步，标号管理**：`T`（整体为真）、`F`（整体为假）这两个标号由**上下文**传入——在 `if (E) S` 里，`T` 指向 `S` 的代码、`F` 指向 `if` 之后。

**「标号当参数传」是布尔翻译控制流化的核心**：布尔表达式不再「返回一个值」，而是「接受两个目标标号，自己决定跳向何方」。

## 5 布尔与控制流的合流

布尔表达式翻译与控制流翻译密不可分：

- `if (E) S1 else S2`：把 `E` 的真标号设成 `S1` 入口、假标号设成 `S2` 入口——条件语句就是「布尔跳转」的外壳。
- 循环 `while (E) S`：真标号指向循环体、假标号指向循环出口。
- 布尔值本身（`x = a < b`）：把跳转翻译「收尾」成 `t = 1`/`t = 0` 再赋给 `x`——控制流转数值。

**重点是**：短路求值不是「优化」而是「语义」——有副作用的语言必须短路。翻译为跳转既实现语义又提升效率，一箭双雕。<span class="marginnote">Rust 甚至禁止布尔表达式中出现副作用（用 `&&` 时不允许右侧改状态），把短路的语义复杂度限制住。理解「短路为什么必须用跳转」，也就理解了这类语言设计的动机。</span>

## 6 小结

- 布尔翻译两大范式：**数值表示**（布尔当整数算）与**控制流表示**（布尔决定跳向）。
- 数值表示简单但**无法短路**，只适合无副作用场景。
- **短路语义**必须用跳转：`&&` 假则跳、`||` 真则跳，另一侧代码被跳过。
- 翻译带「真/假标号」作为继承参数——布尔表达式「接受两个标号，决定跳向何方」。
- 短路是**语义**不是优化：有副作用语言必须短路；控制流翻译是条件/循环语句的公共底盘。
