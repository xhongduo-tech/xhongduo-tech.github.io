## 为什么从非局部名字访问开始

局部变量用「帧指针 + 偏移」直接访问，但**嵌套函数**有个新需求：内层函数要访问**外层函数的局部变量**——比如 Pascal、Python 的闭包、以及现代语言里嵌套定义的函数。这个「非局部名字」（不是自己帧里的名字）去哪找？答案关系到运行时最精巧的结构之一：**访问链（access link / static link）**。<span class="marginnote">没有嵌套函数的语言（C、Java）根本不需要访问链——所有名字要么局部、要么全局。一旦允许嵌套定义（Pascal、Swift、Rust 的闭包），「我词法外层在哪」就成了运行时必须回答的问题。这也解释了为什么 C 没有嵌套函数：省掉访问链，运行时就简单一档。</span>

## 1 词法作用域与嵌套深度

**词法作用域（lexical scoping / static scoping）**：一个名字的可见范围由**源代码的嵌套结构**决定，而非调用历史。内层函数能引用外层函数的局部变量——这是「闭包」「嵌套定义」的根基。

**嵌套深度（nesting depth）**：从最外层（深度 1）开始，每嵌套一层深度 +1。例：

```
program P          # 深度 1
  procedure A      # 深度 2
    procedure B    # 深度 3
      # B 可访问 P、A、B 三层的名字
```

运行中，`B` 的某次活动要访问 `A` 的局部变量 `x`——`x` 不在 `B` 自己的 AR 里，得找到「词法外层 A 的当前活动记录」。<span class="marginnote">关键难点：B 的<strong>词法外层</strong> A 与 B 的<strong>动态调用者</strong>可能是两回事——B 可能是被另一个函数 C 调用的，但 C 里没有 `x`。所以「沿调用链找 A」是错的，必须沿「词法外层链」找——这就是访问链与动态链的分工。</span>

## 2 访问链（静态链）：沿词法外层指

**访问链（access link / static link）**：每个活动记录里存一个指针，指向**它的词法外层函数**的当前活动记录。

- 函数 `A` 定义在 `P` 内：`A` 的 AR 里的访问链 → `P` 的当前 AR。
- 函数 `B` 定义在 `A` 内：`B` 的 AR 里的访问链 → `A` 的当前 AR。

于是「找外层名字」= **沿访问链跳对应次数**。若 `B` 要访问深度差为 $k$ 的外层变量，就沿访问链跳 $k-1$ 次（到目标函数帧），再加该变量在帧内的偏移。<span class="marginnote">访问链「沿词法嵌套指」，「动态链」沿调用历史指——两根链在同一条 AR 里并存，各司其职。递归函数里两者常常重合（词法外层就是调用者），但嵌套函数交叉调用时立刻分道扬镳。理解这个区别，就理解了活动记录里的「双链」。</span>

## 3 访问链的建立：调用时怎么传

建立访问链的规则：当深度 $n_i$ 的函数 $p$ 调用深度 $n_j$ 的函数 $q$ 时，`q` 的新 AR 的访问链应指向「包含 `q` 定义的那个函数」的当前 AR：

- 若 $n_j = n_i + 1$（调用**直接内层**）：新访问链 = `p` 的访问链本身指向的帧（`p` 就是词法外层）——即复制 `p` 的访问链到 `q` 的 AR 下方，或更精确地，`q` 的访问链 = `p` 的 AR（当 `q` 定义在 `p` 内）。
- 若 $n_j \le n_i$（调用外层或同级）：**沿 `p` 的访问链跳 `n_i - n_j + 1` 次**，找到「包含 `q` 的最近外层」的帧，作为 `q` 的访问链。

这条规则编译成「调用序列里的一段访链代码」——现代编译器把访问链作为**隐藏参数**传给被调函数，或者放在寄存器里优化。<span class="marginnote">「访问链当隐藏参数」是工程上的落地方式：调用嵌套函数时，除了正常实参，还偷偷传一个「指向词法外层帧」的指针。这样被调方不用猜、不用回溯，直接拿这个指针找外层。Swift、Rust 闭包的实现沿用了同一思想。</span>

## 4 公式解析：沿访问链的访问成本

设当前函数深度为 $n$，目标外层函数深度为 $m$（$m < n$），变量在目标帧内偏移为 $o$：

$$\text{访问链步数} = n - m, \qquad \text{addr} = (\,\cdot\!\cdot\!\cdot(\text{self.link})) \cdots).\text{link} + o$$

- **第一步，步数**：从当前帧到深度 $m$ 的外层帧，需要跳 $n-m$ 次访问链——链长与嵌套深度差成正比。
- **第二步，多级访存**：每跳一次是一次指针解引用，所以嵌套深的非局部访问 = 多次访存——比局部访问（一次基址+偏移）慢。
- **第三步，权衡**：访问链的代价是「访问外层变量 = O(嵌套深度)」次访存。为此出现替代方案——**显示表（display）**。

**「深度差 = 链步数」揭示了访问链的空间/时间权衡**：结构简单（每帧一个指针），但深嵌套的访问变慢。

## 5 显示表：用一张表换速度

**显示表（display）**：维护一个全局数组 `d[1..k]`，`d[i]` 指向「当前最内层的深度为 i 的活动记录」。于是：

$$\text{addr} = d[m].\text{base} + o$$

- 访问深度 $m$ 的外层变量，**一次查表 + 一次偏移**——与嵌套深度无关，O(1)。
- 代价：每次调用/返回都要**更新显示表**（把 `d[n]` 改成新帧、返回时还原），维护开销前移。

**辨析｜易错点：** 访问链 vs 显示表是经典的「时间换空间」对子：访问链省维护（每帧一个指针）、费访问（链跳）；显示表省访问（一次查表）、费维护（调用即更新）。现代语言两者都用变体：JVM 的局部变量表、Python 的 cell 变量，各有各的妥协。<span class="marginnote">「闭包捕获」是显示表思想的现代延伸：Rust 的闭包直接把捕获的变量打包进闭包结构体（相当于预先把外层变量「搬」进来），访问时零链跳——用「拷贝而非指向」换速度，代价是所有权要厘清。</span>

## 7 思考与练习

**练习 1 嵌套深度**：对 Pascal 式嵌套 `P → A → B`（B 定义在 A 内），画出运行中「B 访问 A 的局部变量」时的访问链路径——标出要跳几步。

**练习 2 链的建立**：当深度 $n_i$ 的函数调用深度 $n_j$ 的函数时，分「$n_j = n_i + 1$（直接内层）」与「$n_j \le n_i$（外层/同级）」两种情况，各说明新 AR 的访问链怎么定。

**练习 3 动态链 vs 静态链**：构造一个「B 的词法外层是 A、动态调用者是 C」的交叉调用场景，画出调用栈——标出「沿动态链找 A」为什么错、「沿访问链找 A」为什么对。<span class="marginnote">这是访问链最经典的辨析题：B 被 C 调用，但 B 要访问的 `x` 定义在 A 里——沿动态链（调用史）会走到 C，而 C 里没有 `x`。只有沿静态链（词法嵌套）才能到 A。两根链的方向，就是「调用史」与「词法结构」的分野。</span>

**练习 4 显示表更新**：实现一个显示表（全局数组 `d[1..k]`），说明函数进入/退出时如何更新 `d`——进入把 `d[n]` 指向新帧、退出恢复。

**练习 5 成本对比**：对嵌套深度 5 的外层访问，访问链要跳几步、显示表要查几次——把「O(深度) vs O(1)」的数值写具体。

**练习 6 闭包联系**：Rust 闭包「把捕获变量打包进结构体」为什么省掉链跳？——对比「指向外层帧」与「拷贝捕获值」两种方案的所有权差异。

**常见误区**：

- **误区一**：把「访问链」与「动态链」混为一谈——一个沿词法嵌套、一个沿调用历史；递归时重合、交叉调用时分道。
- **误区二**：以为「没有嵌套函数的语言也需要访问链」——C 没有嵌套定义，非局部名字只有「全局」，查全局表即可。
- **误区三**：把「显示表」当「访问链」的升级——它们是「省维护费访问」与「省访问费维护」的平行取舍，不是优劣。

**延伸**：访问链/显示表解决「非局部名字去哪找」，与第二级《程序设计语言原理》的「作用域实现」、第七篇「活动记录」是同一问题域——画一张「名字解析的实现手段」总表，把符号表、访问链、显示表、闭包捕获排进去。

## 8 小结

- **词法作用域**让内层函数看见外层局部变量；**嵌套深度**从最外层数起，每嵌一层 +1。
- **访问链**是 AR 里指向词法外层帧的指针；非局部访问 = 沿链跳「深度差」次 + 帧内偏移。
- 访问链建立规则按调用双方深度差处理：内层调用复制链，外层/同级调用沿链找目标帧。
- 访问链成本 = **O(嵌套深度)** 次访存；**显示表**用全局表换 O(1) 访问，代价是调用时维护。
- 访问链（省维护费访问）vs 显示表（省访问费维护）是经典权衡；现代闭包实现各有变体。
