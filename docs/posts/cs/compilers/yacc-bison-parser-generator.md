## 为什么从 Yacc/Bison 开始

手写递归下降分析器灵活，但工作量大；上一节的 LR 分析表威力强，但手算几千个表项不现实。编译实践找到了中间态：**让工具从文法生成分析器**。1975 年，斯蒂芬 · 约翰逊在贝尔实验室写了 **Yacc**（Yet Another Compiler-Compiler），把「文法 + 语义动作」编译成一台 LALR 分析器；**Bison** 是它的 GNU 开源重写，兼容 Yacc 语法而功能更全。<span class="marginnote">Yacc 常与 Lex/Flex 配对使用：flex 把字符流切成记号，yacc 把记号流拼成语法树——一个管「字」，一个管「句」。两者的组合至今仍是教科书与小型编译器的事实标准。</span>

使用 Yacc/Bison 的体验，是写「文法 + 每条文法的动作」，然后工具帮你解决「如何分析」的机械问题。它把前面十几篇的 LR 理论浓缩成一个命令：bison grammar.y。

## 1 Bison 规范文件的结构

与 flex 相似，Bison 文件由 %% 分隔三部分：

```
%{
  声明段：%token、%left 等声明 + 原样复制的 C 代码
%}

%%

规则段：产生式 + 动作

%%

用户段：main、yyerror 等函数
```

**声明段**：%token 声明终结符（记号），%left/%right/%nonassoc 声明优先级与结合性，%{ ... %} 包 C 代码。
**规则段**：每条规则 产生式 { 动作 }。
**用户段**：main、yyerror 等函数。<span class="marginnote">`$$` 表示本规则的语义值（左侧非终结符的值），`$1`、`$2`、`$3` 表示右侧第 1、2、3 个符号的语义值。动作就是「用子值算出父值」——这正是语法制导翻译的核心写法。</span>

## 2 从规范到分析器

bison grammar.y 生成 y.tab.c（分析器 C 代码）与 y.tab.h（记号常量定义）。内部发生了四件事：

1. **文法归一化**：把 %left/%right/%nonassoc 声明转成对应的冲突消解规则，合并产生式。
2. **构造 LALR 表**：LR(0) 项集 + 前瞻传播（上一节的高效算法），产出 ACTION/GOTO 表。
3. **语义栈设计**：除状态栈外，Bison 维护并行的**语义值栈**——每个符号的语义值存在这里，归约时把子值弹出、算好父值压回。
4. **生成驱动循环**：yyparse 就是 LR 分析器主循环 + 错误恢复，直接可调用。

**语义值栈与状态栈同步压弹**，是 Bison「一边分析一边算语义」的机制——分析树甚至不必显式构造，语义在归约瞬间自底向上地算完。<span class="marginnote">这就是「分析器即求值器」：对表达式文法，yyparse 结束时你已经拿到了整棵树的求值结果。真实编译器里动作不是算值，而是建 AST 结点或发中间代码——动作是钩子，挂什么都行。</span>

## 3 语义值与类型：`$$` 和 $n

动作的典型模式：

```
expr: expr '+' term   { $$ = $1 + $3; }   // 加法：左值 + 右值
    | term            { $$ = $1; }        // 传递：直接上抛
    ;
```

`$1` 取第一个 expr 的语义值，`$3` 取 term 的语义值，`$$` 赋给本规则的 expr。
若一个非终结符的多个候选动作不同，可 %type 统一声明类型；用 %union 定义多个语义类型（int、double、AST 指针），供不同规则选择。

**易错点**：不写动作时，Bison 默认 `$$` = `$1`（取第一个符号的值）——这条默认行为常让新手意外。空动作 ≠ 无动作，它在传播值。<span class="marginnote">`$$ = `$1`` 的默认很有用：纯「传递」的规则（如 expr → term 直接上抛）可以省略动作。但也正因此，漏写动作时悄悄在传值，调试时留意。</span>

## 4 冲突报告与消解

Bison 编译文法时若发现冲突，会打印：

```text
$ bison -v grammar.y
grammar.y: conflicts: 2 shift/reduce, 1 reduce/reduce
```

**每个冲突都是要处理的信号**：

有优先级声明 → 冲突被声明消解（无警告的静默消解通常合理）。
无声明覆盖 → Bison 默认**偏向移进**，打印警告——悬空 else 靠它就近匹配，但其他冲突可能被「猜错」。
归约-归约冲突默认选**靠前**的产生式，同样打印警告。

生产纪律：**把警告当错误**。-Wconflicts-sr 打开，逐条消解，直到零冲突——否则分析器可能在真实输入上给出意外行为。<span class="marginnote">Bison 还有 -v（--verbose）生成详细的 grammar.output 状态报告，逐状态列出项集与冲突，是调试文法最重要的工具。遇到神秘冲突时先开它。</span>

## 5 实现原理：Bison 与 LR 理论

把 Bison 的内部与前面的理论逐一对上：

| 理论部件 | Bison 实现 |
| --- | --- |
| 增广文法 | 自动加 $S'\to S$ |
| LR(0) 项集族 | 构造状态图 |
| LALR 前瞻 | 传播算法（不用完整 LR(1)） |
| ACTION/GOTO 表 | 压缩后的稀疏表 |
| 移进-归约冲突 | 优先级/结合性声明 |
| 错误恢复 | 内置恐慌模式 + 可定制 |

**重点是**：Bison 是「LR 理论的工业封装」——理解前面 LALR 构造的原理，Bison 就不再是黑盒。它把「文法 → 表」这件事自动化，把「表 → 程序」机械完成，而所有语义决策留给你的动作代码。<span class="marginnote">现代替代品（如 ANTLR 的 LL(\*)、手写的递归下降）各有取舍，但 Bison 的 LALR 组合在「表达能力 × 生成效率 × 生态成熟度」上仍是教科书标准。理解它，就等于理解了生成式编译工具的通用架构。</span>

## 6 小结

- **Yacc/Bison** 从「文法 + 语义动作」生成 LALR 分析器；%% + %% 三段式：声明、规则、用户代码。
- **动作语法**：`$$` 是左侧语义值，$n 是右侧符号值；动作在归约瞬间自底向上执行。
- 生成流程：归一化 → LALR 表 → 语义栈 → yyparse 驱动循环；语义栈与状态栈同步。
- 冲突（shift/reduce、reduce/reduce）靠**优先级声明**与默认移进消解；警告必须清零。
- Bison 是 LR 理论的标准封装：增广、LR(0)、LALR 前瞻、稀疏表、错误恢复逐一对齐。
