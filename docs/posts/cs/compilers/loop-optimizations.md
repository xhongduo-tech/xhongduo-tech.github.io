## 为什么从循环优化开始

「程序 90% 的时间花在 10% 的代码上」——那 10% 几乎都是循环。优化循环，收益按「迭代次数」放大：循环体里省一次乘法，一万次迭代就省一万次。所以循环优化是优化器里**投入产出比最高**的战场，而它的两个主力是：**代码外提（loop-invariant code motion）**——把循环里不变的计算搬到循环外；**归纳变量消除（induction-variable elimination）**——把随循环线性变化的变量用更省的运算替代。<span class="marginnote">「迭代次数放大收益」是循环优化的第一直觉：省下循环体里的任何一次省算，都被 n 次放大。这也是为什么编译器团队在循环优化上投入最多——Amdahl 定律的程序级版本：优化最热的代码，收益最大。</span>

## 1 循环不变计算：该搬出去的东西

**循环不变计算（loop-invariant computation）**：表达式的值在循环体**每次迭代都相同**——因为它的所有操作数在循环内不被改变。

例：

```c
for (i = 0; i < n; i++) {
    x = p * q;      /* p * q 与 i 无关：循环不变 */
    a[i] = x + i;
}
```

`p * q` 每次迭代都算同一个值——**循环不变**，应该只算一次。

**代码外提（hoisting）**：把循环不变计算从循环体**搬到循环之前**，只算一次：

```c
x = p * q;              /* 外提：只在进入循环前算一次 */
for (i = 0; i < n; i++) {
    a[i] = x + i;
}
```

**安全前提**（龙书三条）：

1. 外提的语句在循环内**必然执行**（不在条件分支里）——否则可能「本来不执行、却被执行了」。
2. 语句没有副作用（不写循环外可见的内存）。
3. 循环内没有其他语句**修改**该语句用到的变量。<span class="marginnote">外提的三条前提是「行为不变」的保证：搬出去只影响「执行次数」，不影响「执行结果」。若语句在循环内是条件执行的，搬出去可能改变「是否执行」——语义就变了。所以编译器只外提「无条件、无副作用、操作数不变」的语句。</span>

## 2 归纳变量：随循环线性变化的值

**归纳变量（induction variable）**：值随循环迭代**线性变化**的变量——每次迭代加/减一个固定量。经典的归纳变量：

```c
for (i = 0; i < n; i++) {
    t = 4 * i;      /* t 是 i 的派生归纳变量 */
    sum += t;
}
```

`i` 是归纳变量，`t` 也是（它是 `i` 的线性函数 `t = 4i`）。**归纳变量消除**的目标：用「每次自加固定步长」替换「每次乘法」，并把多余的归纳变量删掉。<span class="marginnote">`t = 4 * i` 每次迭代都做一次乘法，但 `t` 的值其实每次固定 +4——把乘法换成「自加 4」是典型的<strong>强度削弱</strong>。归纳变量消除 = 识别线性关系 + 用加减替换乘除 + 删除冗余的中间变量。</span>

## 3 归纳变量消除的做法

对线性关系 $t = c \cdot i + d$（c、d 循环内不变），归纳变量消除的步骤：

1. **识别**：找循环内「每次迭代步长固定」的变量（基本归纳变量 $i$），以及由它线性导出的（派生归纳变量 $t = c \cdot i + d$）。
2. **替换运算**：把 `t = c \cdot i + d` 改为「t 初始 = c\*i0 + d，每次迭代 t += c」——乘法变加法。
3. **消除多余变量**：若 `t` 只用于数组寻址等、不再需要「t 这个名字」，直接删除 `t` 的定值，用「基址 + 自增」替代。

例：

```c
for (i = 0; i < n; i++) {
    a[4 * i] = i;   /* &a[4*i] = base + 4*i，地址随 i 线性增长 */
}
```

数组寻址 `&a[4 * i]`（即 `base + 4 * i`）变成「地址游标每次 +4」——这正是数组寻址强度削弱的经典场景。<span class="marginnote">「把乘 4 的寻址换成地址游标 +4」是循环优化的经典战果：数组访问的地址计算从「每次乘法 + 加法」变成「每次加法」，而 `t` 甚至可以被完全删除（若它只用于控制循环次数，可用「计数到零」替代）。这就是为什么手写优化的循环（指针游标）与编译器生成的循环性能相当。</span>

## 4 公式解析：归纳变量的识别

称变量 $x$ 是循环的**基本归纳变量**，若它每次迭代变化固定步长：

$$x := x \pm c \quad (c \text{ 循环内不变})$$

称 $y$ 是**派生归纳变量**，若存在基本归纳变量 $x$ 使：

$$y := c_1 \cdot x + c_2 \quad (c_1, c_2 \text{ 循环内不变})$$

- **第一步，基本识别**：$x := x + 1$ 步长为 1——基本归纳变量；$x := x \times 2$ 不是（步长随值变化）。
- **第二步，派生识别**：$t = 4 \cdot i + 3$——t 是 i 的派生；每次迭代 `t += 4`。
- **第三步，消除收益**：把 `t` 的定值换成「初始值 + 步长自增」，若能证明 `t` 不再被读出，整个删除——乘法、临时变量一起消失。

**「基本 + 派生 + 线性」是归纳变量识别的完整配方**——识别出来，加减替换乘除、删除冗余就在眼前。

## 5 循环优化的联动

循环优化是一个「组合拳」：

| 优化 | 作用 | 搭档 |
| --- | --- | --- |
| 代码外提 | 循环不变计算只算一次 | 依赖「不变」判定 |
| 归纳变量消除 | 乘除换加减、删冗余变量 | 依赖「线性」识别 |
| 强度削弱 | 高价运算换低价运算 | 与归纳变量一体 |
| 循环展开 | 减少循环开销、暴露更多优化 | 放大其他优化的视野 |

**重点是**：循环优化的每一步都建立在对「循环结构」的认识上——而认识循环结构靠**支配结点**（下一节）。没有支配关系，编译器甚至分不清「哪里是循环头」。<span class="marginnote">「循环优化依赖支配结构」是优化器的依赖链：支配结点识别循环 → 循环不变判定 → 外提/消除。这也解释了为什么「支配结点与循环的识别」排在循环优化之后——它是最热优化的地基，理解了它，循环优化就有了完整的支撑。</span>

## 6 小结

- 循环是优化的**主战场**：收益被迭代次数放大。
- **循环不变计算**：操作数在循环内不变的计算；**代码外提**把它搬到循环前。
- 外提三条前提：**必然执行、无副作用、操作数不变**——保证行为不变。
- **归纳变量**随迭代线性变化；消除 = 乘除换加减、删除冗余派生变量。
- 循环优化是**组合拳**（外提、归纳变量消除、强度削弱、展开），建立在支配结构之上。
