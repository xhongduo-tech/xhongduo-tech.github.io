## 为什么从目标代码生成开始

语义分析通过后，ToyLang 迎来了「产出」阶段：把 AST **翻译成目标代码**。三种常见目标各有取舍——**C**（用现成 C 编译器收尾，最简单）、**汇编**（看见真正的机器指令）、**字节码**（写一个虚拟机解释它）。三种都是「代码生成」的具体形态，本节的机制（表达式、控制流、函数）三种通用，差异只在「输出的文本」。<span class="marginnote">「目标的选择决定你能看到什么」：编译到 C——你看到「我们的语言 ≈ C 的翻译」；编译到汇编——你看到「if 变成几条跳转」；编译到字节码——你看到「一台你自己的虚拟机」。教材路线建议先编译到 <strong>C</strong>（最快跑通），再考虑汇编/字节码——每深一层，前七篇的代码生成理论就多落地一层。</span>

## 1 三种目标的对比

| 目标 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **C** | ToyLang AST → C 源码，`gcc` 收尾 | 最快跑通、C 帮你做后端 | 没看到「真机器」 |
| **汇编** | AST → x86/ARM 汇编，`as`/`ld` 收尾 | 看见指令选择/寄存器 | 工作量大、平台绑定 |
| **字节码** | AST → 自定义字节码，写 VM 解释 | 可移植、自己掌控一切 | 要额外写一个 VM |

**ToyLang 的推荐路线**：**先编译到 C**——几百行代码把 AST 变成 C 程序，立即能跑；有精力再升级。

**编译到 C 的本质**：ToyLang 的每个结构翻译成 C 的同构结构——变量变 C 变量、表达式变 C 表达式、函数变 C 函数。C 编译器接管「真正的代码生成」。<span class="marginnote">「编译到 C 是玩具编译器的作弊器」：你的语言 → C 源码，然后 C 编译器免费提供指令选择、寄存器分配、优化。ToyLang 的 `if` 变成 C 的 `if`，`while` 变成 `while`，函数变成 C 函数——翻译直白，但把「语义保留」这件事练得明明白白。</span>

## 2 表达式翻译：到 C / 到汇编

**到 C**（表达式翻译直白）：

```c
/* ToyLang: a + b * c   →   C */
c_expr = a + b * c;      /* 优先级由 C 的运算符规则保证 */
```

**到汇编**（第七节的简单代码生成器思路）：

```asm
# ToyLang: a + b * c   →   每个表达式一个临时变量
MOV  b, R1
MUL  c, R1        # b * c → R1
MOV  a, R2
ADD  R1, R2       # a + (b*c) → R2
STORE R2, t1
```

汇编要管理寄存器/临时变量——ToyLang 用「每个表达式一个临时变量」的朴素策略（第三十节），不搞寄存器分配，也能跑。

**重点是**：表达式翻译 = **后序遍历 AST，每个结点发一段代码**——与第三十节的三地址码生成同构，只是输出语言不同。<span class="marginnote">「表达式代码生成 = 后序遍历 + 拼接」：`Binary(op, e1, e2)` 的树，后序先发左子树的代码再发右子树——子树的代码先于父。这就是第四篇综合属性的执行：`gen(e1)`、`gen(e2)`、`emit(op)`，无论目标是 C、汇编还是字节码，这个顺序逻辑不变。</span>

## 3 语句与控制流翻译

**到 C**（控制流翻译几乎 1:1）：

```c
/* ToyLang: if (x > 0) y = 1; else y = 2;   →   C */
if (x > 0) {
    y = 1;
} else {
    y = 2;
}
```

**到汇编**（第三十五节回填/跳转）：

```asm
# ToyLang: if (x > 0) ... else ...   →   跳转 + 标号
    cmp  x, 0
    jle  L_else
    ... then 分支 ...
    jmp  L_end
L_else:
    ... else 分支 ...
L_end:
```

**短路的 `&&`/`||`**（到汇编）：左侧为假则跳过右侧——用跳转实现（第三十四节）。

**编译到 C 时 `&&` 怎么办**？直接生成 C 的 `&&`——C 本身短路，语义自动保留。这是「编译到高级语言」的便利：目标语言替你实现了低级机制。<span class="marginnote">「编译到 C 时，低级机制被 C 白送」：`&&` 的短路、`if` 的跳转、函数的调用约定——C 语言全替你实现。所以编译到 C 是「验证前端正确性」的捷径：你只需保证「ToyLang 的 AST 语义 = 生成的 C 语义」，C 编译器负责所有机器层细节。想学「跳转怎么生成」，再转到汇编目标。</span>

## 4 公式解析：表达式代码生成的递归

设 `gen` 生成表达式 $e$ 的代码，则递归：

$$gen(\text{Number}(v)) = \text{load\_const}(v)$$

$$gen(\text{Var}(x)) = \text{load\_var}(x)$$

$$gen(\text{Binary}(\text{op}, e_1, e_2)) = gen(e_1) \cdot gen(e_2) \cdot \text{emit\_op}(\text{op})$$

- **第一步，叶子**：数字/变量 → 一条加载。
- **第二步，组合**：二元表达式 = 左子树代码 + 右子树代码 + 运算指令——**后序拼接**。
- **第三步，目标差异**：`emit_op` 到 C 是 `+`/`*` 运算符、到汇编是 `ADD`/`MUL` 指令、到字节码是 `OP_ADD`/`OP_MUL` 操作码——**只有 emit_op 不同，拼接逻辑通用**。

**「树形结构 → 线性代码」的递归翻译，是代码生成的通用骨架**——换目标只是换 emit_op 的实现。

## 5 函数与调用

**到 C**：

```c
/* ToyLang: def f(x, y) { return x + y; }   →   C */
int f(int x, int y) {
    return x + y;
}
```

参数按值传（C 的默认语义）；返回类型恒 int。

**到汇编**：要生成**调用序列**（第三十八节）——压参数、call、返回、清理：

```asm
# 到汇编：压参数 → call → 清理（调用者清理）
    push y
    push x
    call f
    add  sp, 8        # 调用者清理 2 个参数
```

汇编版需要决定「参数放哪」（调用约定）——ToyLang 用最简单的「全压栈 + 调用者清理」，与活动记录理论对得上。

**到字节码**：定义 `CALL`/`RET` 指令，VM 里维护调用栈。

**重点是**：函数翻译是「活动记录理论的最小实现」——参数、返回、调用栈，三种目标都要面对，只是抽象层次不同。<span class="marginnote">「函数是活动记录的最小剧场」：函数翻译时，参数怎么传、返回值怎么拿、调用怎么跳——第六篇的调用序列理论，在编译到汇编时全部要亲手实现；编译到 C 时则被 C 的调用约定替代。从 C 到汇编的升级，就是「把 C 编译器替你做的事自己做一遍」。</span>

## 6 小结

- 三种目标：**C**（最快跑通）、**汇编**（看见真机器）、**字节码**（自己写 VM）——推荐先到 C。
- 表达式翻译 = **后序遍历 + 拼接**：叶子加载、二元 = 左+右+运算——与三地址码生成同构。
- 控制流翻译：到 C 几乎 1:1；到汇编用**跳转 + 标号**（if/while 的模式）。
- 编译到 C 的便利：**C 替你实现低级机制**（短路、跳转、调用约定）——适合验证前端。
- 函数翻译 = 活动记录理论的最小实现：参数/返回/调用栈，三种目标都要面对。
