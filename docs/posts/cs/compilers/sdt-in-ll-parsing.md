## 为什么从 LL 中的 SDT 开始

L-属性定义保证了「从左到右、一趟算完」，但抽象保证要落到代码，还得有一层「接口设计」：继承属性怎么传下去？综合属性怎么传回来？在递归下降分析器里，答案出奇地朴素——**用函数参数传继承属性，用函数返回值传综合属性**。文法符号的属性，翻译成了函数签名里的参数与返回值。<span class="marginnote">这一节是「文法即代码」的第二次亮相：递归下降不只把产生式变成函数，还把属性变成函数接口。读者学完会发现，手写编译器的类型系统、符号表实现，都是这套「参数/返回值」约定的自然延伸。</span>

## 1 L-属性 SDT 在递归下降中的形态

把每个非终结符 $X$ 写成一个函数 `parse_X`。L-属性定义的对应关系：

**继承属性** → 函数的**参数**（调用 `parse_X` 时由父传入）。
**综合属性** → 函数的**返回值**（子算完传回父）。
**动作代码** → 函数体里的语句。

以声明类型传递为例，文法 $D \to T\,L$、$L \to L_1,\ \textbf{id} \mid \textbf{id}$，L 属性 `T.type`（继承）与综合属性 `L.type`：

```c
Type parse_D() {
    Type t = parse_T();      /* 综合：T 的类型 */
    return parse_L(t);       /* t 作为继承属性下传 */
}

Type parse_L(Type in) {      /* in = 继承属性（来自左侧） */
    if (lookahead == COMMA) {
        match(COMMA);  match(ID);
        return parse_L(in);  /* 综合属性链式上抛 */
    } else {
        return in;
    }
}
```

`t` 一路作为参数下传，`L.type` 作为返回值上抛——继承与综合在代码里的位置一目了然。<span class="marginnote">「继承属性是参数」这条约定极强：它把「依赖左侧兄弟」翻译成「调用时左边的值已在手里」。左侧兄弟的属性能传进来，是因为从左到右的分析顺序保证了它们先算完——这正是 L-属性定义允许的那类依赖。</span>

## 2 继承属性的参数化：向左看与向下传

L-属性允许的两种继承依赖，在递归下降里各有对应：

**父 → 子**：父调用子函数时传参。`parse_L` 里的 `in` 来自 `parse_D`。
**左侧兄弟 → 右侧**：左侧兄弟先返回，把值存进局部变量，再传给右侧。`D → T L` 里 `T` 与 `L` 的共享逻辑就是靠局部变量。

代码形态上，「依赖左侧兄弟」体现为**同一函数内的两次调用**：先调左侧（得值），再把它作为参数调右侧。L-属性定义的「从左到右」保证这个顺序总是可行。<span class="marginnote">若 SDD 允许「向右看」，递归下降里就会需要「先看完右侧再回头算左侧」——与单趟从左到右的递归下降矛盾。这正是 L-属性定义存在的原因：它把「哪些依赖能一趟实现」划得清清楚楚。</span>

## 3 综合属性的返回值：链式上抛

综合属性作为返回值，形成「子树算完、父结点收下」的链条：

```c
/* 表达式求值：综合属性 = 返回值，链式上抛 */
int parseAdditive() {
    int left = parseTerm();          /* 左子树的值 */
    while (lookahead == PLUS) {
        match(PLUS);
        int right = parseTerm();     /* 右子树的值 */
        left = left + right;         /* 综合属性：合并上抛 */
    }
    return left;
}
```

每个函数 `parse_A` 返回该非终结符的综合属性；归约/展开的次序即求值次序，返回值自然串联。对表达式求值，`parseExpr` 最终返回整棵表达式的值——分析即求值。<span class="marginnote">对比 Bison 的后缀动作 `$$`：那里用语义栈传值，这里用 C 函数调用栈传值——机制不同，语义完全同构。手写编译器用函数返回，生成的编译器用语义栈，两条路殊途同归。</span>

## 4 公式解析：函数接口与属性的对应

设非终结符 $A$ 的继承属性为 $i_1, \ldots, i_m$、综合属性为 $s_1, \ldots, s_n$，则其分析函数接口：

$$\text{parse}_A(i_1, \ldots, i_m) \to (s_1, \ldots, s_n)$$

- **第一步，参数**：全部继承属性作参数——它们由父/左侧兄弟提供，调用时已就绪（L-属性的保证）。
- **第二步，返回值**：全部综合属性作返回值——子树分析完才能算，返回时已就绪。
- **第三步，调用约定**：对产生式 $A \to X_1\cdots X_k$，`parse_A` 内依次调用 `parse_{X_1}` 到 `parse_{X_k}`，把需要的继承属性传进去、把返回的综合属性存进局部变量——顺序恰好是 $X_1$ 到 $X_k$ 的从左到右。

**这条接口约定把 SDD 的属性依赖，映射成过程调用的数据流**——任何 L-属性 SDD 都能机械地变成递归下降代码，这正是「语法制导」可自动化的原因。

## 5 表驱动 LL 分析器中的 SDT

递归下降不是唯一选择。若用表驱动 LL 分析器，SDT 的实现改走「语义栈 + 动作表」：

- 分析表 $M[A, a]$ 里每个产生式关联一串**动作编号**。
- 展开 $A \to X_1\cdots X_k$ 时，逆序压入 $X_k\cdots X_1$，同时把该产生式的动作排进待执行序列。
- 归约/匹配到动作时执行——属性放语义栈，与 LR 语义栈同构。

**辨析｜易错点：** 表驱动的 LL 分析器没有「函数调用」这层便利，继承属性要显式地操作语义栈，代码比递归下降难写——所以「在 LL 中实现 SDT」的工程实践几乎都选**递归下降**。表驱动 LL 更适合「文法频繁变动」的生成器场景（Yacc 风格），此时动作代码由工具生成，语义栈对用户透明。<span class="marginnote">这也解释了生态格局：需要手写灵活逻辑的编译器前端（Clang、rustc）用递归下降；需要「文法即规范」的场合（Yacc/Bison 生成）用表驱动。两种 LL 风格各守一方。</span>

## 7 思考与练习

**练习 1 参数化继承**：把声明类型传递的 L-属性 SDT 写成递归下降函数——`parse_L` 的 `in` 参数如何沿调用链传递。

**练习 2 返回值综合**：把表达式求值的 S-属性 SDT 写成「返回 int 的函数」——`parseExpr` 如何通过返回值逐层上抛综合属性。

**练习 3 左侧兄弟**：解释「依赖左侧兄弟」在代码里的形态——先调 `parse_T` 得值、存局部变量、再传给 `parse_L`——为什么 L-属性保证这个顺序可行。

**练习 4 接口约定**：写出「继承属性 → 参数、综合属性 → 返回值」的接口公式，用 `parse_A(in) → out` 表达——并说明为什么「向右看」在递归下降里实现不了。

**练习 5 表驱动对照**：对比「递归下降（函数传参）」与「表驱动 LL（语义栈）」实现 SDT 的差异——继承属性在后者里怎么处理（显式栈操作）？<span class="marginnote">「递归下降用调用栈、表驱动用语义栈」是两条等价路线：函数参数天然是「值传递」的载体（继承属性），函数返回值是「综合属性」的通道；而表驱动没有「调用」这层便利，继承属性要手动压语义栈。所以手写编译器选递归下降、生成器选表驱动——各取所长。</span>

**练习 6 工程观察**：在 Clang 或 rustc 的语法分析器里找一个「带参数的分析函数」——确认「继承属性 = 参数」是工业惯例。

**常见误区**：

- **误区一**：以为「继承属性只能靠参数」——参数是递归下降的落地方式；表驱动用语义栈，是另一套。
- **误区二**：把「S-属性」与「L-属性」的实现混为一谈——L 允许继承属性（参数），S 只有综合（返回值）。
- **误区三**：忽视「向左不向右」——依赖右侧兄弟的继承属性在单趟 LL 里实现不了。

**延伸**：递归下降的「函数签名 = 属性接口」与第七十六节「Kaleidoscope 的 AST codegen」、第八十一节「ToyLang 的 AST 遍历」是同一设计——把「属性怎么在代码里传递」的三种风格（参数/返回值/方法调用）写成一页总结。

## 8 小结

- **继承属性 → 函数参数，综合属性 → 函数返回值**——L-属性 SDT 在递归下降中的落地约定。
- 「父→子」靠传参、「左侧兄弟→右侧」靠局部变量中转，都符合从左到右的单趟顺序。
- 综合属性链式上抛，分析即求值；函数调用栈与 Bison 语义栈机制不同、语义同构。
- 接口约定 $\text{parse}_A(\text{继承}) \to (\text{综合})$ 把属性依赖映射成调用数据流，可机械实现。
- 表驱动 LL 用「语义栈 + 动作表」实现 SDT，继承属性靠显式栈操作，故手写实践多用递归下降。
