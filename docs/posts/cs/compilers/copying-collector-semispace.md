## 为什么从复制式回收开始

标记-清扫有两个痼疾：扫全堆、留碎片。**复制式回收（copying collection）** 用「搬新家」的思路根治两者：把堆分成两半（半区），回收时**只遍历存活对象，把它们搬到另一半**——存活少的场景下成本只与存活对象成正比，且搬完自然**聚拢无碎片**。<span class="marginnote">复制式的口号是「把活的搬走，死的自然消失」：它不扫全堆、不找垃圾，只关心「活着的要搬家」。这个「只付存活对象的钱」的特性，让它在「存活率低」的场景（年轻代）大放异彩——这是分代 GC（下一节）的地基。</span>

## 1 半区策略

**半区策略（semispace）** 把堆对半分成**两片** from-space 与 to-space：

**分配**：一律在 to-space 用**碰头指针（bump pointer）** 分配——连续地推进指针，O(1)、无碎片。
**回收**：GC 时遍历 from-space 的存活对象，**复制**到 to-space，同时**更新所有引用**指向新位置。
**切换**：复制完毕，from-space/to-space 角色互换——新分配在旧 from-space 上进行。

```
┌──────────────────────────────┬──────────────────────────────┐
│          from-space          │           to-space           │
│    GC 时从这里搬走存活对象    │  GC 时把存活对象复制到这里    │
└──────────────────────────────┴──────────────────────────────┘
分配在 to-space 用 bump pointer 连续推进；复制完毕两区角色互换
```

存活对象被**紧致排列**在新空间——分配变回连续 bump，碎片归零。<span class="marginnote">「bump pointer 分配」是复制式的隐藏福利：因为 to-space 每次从零开始连续分配，分配就是「指针 += 大小」，比标记-清扫的空闲链表搜索快得多。这个「分配 O(1)、回收 O(存活)」的特性，让复制式在分配频繁的场景（年轻代对象大量诞生）特别高效。</span>

## 2 Cheney 算法：广度优先的复制

**Cheney 算法**（1970）用**广度优先搜索（BFS）** 实现复制——它不用递归栈，只用两根指针扫描：

```
cheney(root):
  scan  = to_space 起始地址
  alloc = to_space 起始地址
  对每个根 r: 复制 *r 到 to_space，写转发指针，alloc 前进
  while scan < alloc:
    obj = scan 处的对象
    for f in obj 的所有引用:
      若 *f 尚未复制: 复制到 to_space，写转发指针，alloc 前进
      更新 f 指向新地址
    scan += obj 的大小
```

**要点**：`scan` 与「分配指针（alloc）」之间的区域是「已复制但引用未处理」的对象——BFS 的天然工作队列。复制过程中 `scan` 与 `alloc` 之间的对象，被 BFS 逐层处理，直到 `scan` 追上分配指针。<span class="marginnote">Cheney 算法的优雅在于<strong>用 to-space 本身当队列</strong>：`scan` 与分配指针之间就是待处理队列，不需要额外数据结构。它证明了「复制可以只靠两根指针 + 原地更新引用完成」——这是复制式 GC 的经典实现，也是「算法即数据结构」的范例。</span>

## 3 复制式的「转发指针」技巧

复制时，被搬走的旧对象位置要留一个**转发指针（forwarding pointer）**：记录「我搬到哪去了」。这样：

若同一个对象被多个引用指向，第一次复制后，后续引用通过转发指针**直接找到新位置**，不再重复复制。
复制完成后，from-space 里的转发指针标记着「已搬走」，也可用于检测（垃圾无需转发）。

```
复制前:                       复制后:
┌─────────────┐              ┌─────────────┐   ┌─────────────┐
│   对象 O     │   ──复制──▶  │  转发指针    │──▶│   对象 O     │
│  (from-space)│              │  (from-space)│   │  (to-space) │
└─────────────┘              └─────────────┘   └─────────────┘
```

**转发指针是复制式的「去重」机制**——它保证一个对象只被复制一次，引用更新一次到位。<span class="marginnote">「转发指针 = 对象迁移的户口本」：旧地址留条「我搬去新地址 X」的纸条，所有后续来找它的引用都通过纸条找到新家。这个技巧在分布式迁移、内存压缩（compact）里同样出现——「移动后留转发」是通用的迁移协议。</span>

## 4 公式解析：半区的空间效率

半区策略的**空间代价**是一目了然的：堆的一半始终闲置。

$$\text{可用堆} = \frac{\text{总堆}}{2}$$

$$\text{复制成本} = O(\text{存活对象大小} + \text{根数})$$

- **第一步，空间减半**：任何时刻只有一半堆可分配——要装下同样的对象集，总堆要翻倍。
- **第二步，成本结构**：回收成本只与「存活对象」与「根」成正比，**与堆大小、垃圾多少无关**——这是它胜过标记-清扫（扫全堆）的核心。
- **第三步，权衡**：存活率低 → 复制成本低 → 半区的浪费可接受；存活率高 → 复制成本高 → 半区浪费反而明显。

**「复制成本 ∝ 存活率」让半区策略天然适合存活率低的场景**——年轻代对象大量快速死亡，正是它的主场。

## 5 优缺点与适用场景

**优点**：

- **无碎片**：存活对象紧致排列，分配永远 bump pointer。
- **成本与存活对象成正比**：存活率低时极快。
- **处理循环引用**：从根出发的复制天然绕开环。
- **分配 O(1)**：连续 bump，无空闲链表搜索。

**缺点**：

- **空间减半**：一半堆闲置——内存利用率下降。
- **移动对象**：所有引用要更新；无法处理「外部世界持有对象地址」（C 兼容问题）。
- **存活率高时成本高**：复制大量存活对象很贵。

**辨析｜易错点：** 复制式「移动对象」与标记-清扫「不移动」是根本分叉——移动虽根治碎片，但让「对象地址不稳定」。这解释了为什么 JVM 的新生代用复制式（对象地址随时变，引用由 GC 统一更新）而 Boehm GC（要兼容 C 指针）只能用不移动的标记-清扫。<span class="marginnote">「地址稳定性」是 GC 与语言内存模型的接口约束：能忍受地址变动的语言（Java、Go——引用由运行时统一管理）用复制式；必须保持地址的语言（C——指针就是地址，外部代码依赖它）只能用不移动的回收。GC 的选择被语言的内存模型绑架。</span>

**一个复制算例**：设 from-space 有对象 A（根）、B（A 指向）、C（B 指向）、D（无根），to-space 从零开始。

- **Cheney 复制**：复制 A 到 to-space 起始（分配指针前进），A 旧位置写转发指针指向新址；扫 A 的引用 → B 未复制，复制 B，写转发指针；扫 B → C 复制；D 从根不可达，不复制。
- **结果**：to-space 里是紧致的 A、B、C；D 留在 from-space（随角色互换被覆盖）。引用更新：A/B/C 内部指向新位置。
- **空间**：to-space 恰好用掉三个对象的大小；from-space 整体作废、下次当 to-space 重新 bump。

这个算例显示复制式的两个特性：只搬存活对象（D 消失）、搬完紧致（A、B、C 连续）——都是「不扫全堆、只付存活对象钱」的直接结果。<span class="marginnote">「D 从根不可达，不复制」正是复制式不做清扫的原因：<strong>不需要「找出 D 并回收」，只需要「不搬 D」</strong>——整块 from-space 在角色互换后直接作废。这是复制式效率的秘密：回收垃圾的成本为零，因为垃圾从不用被显式处理。</span>

**术语速查**：

| 术语 | 含义 |
| --- | --- |
| from-space / to-space | 半区的两个角色：搬出区 / 搬入区 |
| bump pointer | 连续推进的分配指针（O(1) 分配） |
| Cheney 算法 | BFS 复制，用 to-space 当工作队列 |
| 转发指针 | 旧地址留的「搬去哪」纸条 |
| 角色互换 | GC 后 from/to 对调 |

## 6 小结

- **复制式回收**把堆分两半，回收时把存活对象搬到另一半——只付存活对象的钱，搬完无碎片。
- **半区策略**：from-space/to-space 互换；分配用 bump pointer（O(1)、连续）。
- **Cheney 算法**用 BFS + 两根指针复制，用 to-space 本身当工作队列，无递归。
- **转发指针**记录「搬去哪」，保证对象只复制一次、引用更新一次到位。
- 空间减半、地址移动是代价；存活率低时成本 ∝ 存活对象，是年轻代回收的天然主场。
