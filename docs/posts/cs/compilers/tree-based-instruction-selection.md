## 为什么从基于树的模式匹配开始

指令选择的第一条路是「逐条 IR 查指令」——但真实机器的指令往往「一口吃掉一大块表达式」：x86 的 `ADD eax, [ebx + 4*ecx]` 一条指令同时完成加法与数组寻址。要充分利用这种复杂指令，得把**整棵表达式树**切成能被单条指令覆盖的子区域——这就是**树模式匹配（tree pattern matching）**。<span class="marginnote">「树覆盖」把指令选择变成组合优化：一棵表达式树，一套指令模板（每个模板是一棵子树），用模板把树盖满、且代价最小。LLVM 的 SelectionDAG 指令选择、GCC 的 combine 模式，都是这套思想的工业实现——「一块指令 = 一棵子树」。</span>

## 1 表达式树与指令模板

把三地址码恢复成**表达式树**（或直接从前端拿 AST/DAG），内部结点是运算、叶子是变量/常量。**指令模板（instruction template）** 描述一条机器指令能覆盖的树形：

```
ADD 模板（加法指令）      LOAD 模板（取内存）
    +                        MEM
   / \                        |
  REG REG                    REG
```

模板的叶子是「可匹配任何子树的槽」——`ADD` 模板说「加法指令能吃掉一个 + 结点及其两个子树的全部计算」，`LOAD` 模板说「加载指令能吃掉一个内存访问」。

**覆盖（cover）**：用一组模板把整棵树的所有结点盖满，每个结点恰好属于一个模板——模板之间的重叠边界就是「先算什么、用什么指令」的划分。<span class="marginnote">「覆盖」是拼图游戏：模板像形状各异的拼图块，树是目标拼图。不同的覆盖 = 不同的指令序列；目标不是「盖满」而是「盖满且最省」——这就把指令选择变成了「最优覆盖」问题。</span>

## 2 指令选择的组合爆炸

朴素的「枚举所有覆盖」是指数级的——一棵 n 结点的树可能有指数多种覆盖方式。但观察到一个关键结构：**最优覆盖有最优子结构**——若某子树的最优覆盖已知，则整个树的最优覆盖可以由子树的最优覆盖组合而成。

这就是**动态规划（dynamic programming）** 的用武之地：自底向上，对每个结点算「以它开头的最优覆盖代价」，父结点只用子结点的最优结果。于是指数枚举被压成多项式。<span class="marginnote">「最优子结构 + 重叠子问题」是 DP 的两大前提：子树的最优解独立于父，且同一子树会被多个父共享计算。表达式树天然满足——所以树覆盖是 DP 的教科书应用，与背包、最长公共子序列同族。</span>

## 3 动态规划求最优覆盖

对表达式树做后序遍历，维护每个结点的一个表：

表项：`cost[v][T]` = 「用模板 T 覆盖以 v 为根的子树」的最小代价。
递推：`cost[v][T] = c_T + Σ_j cost[v_j][T_j]`。

算法：

1. **自底向上**：对每个叶子，用能覆盖它的模板（LOAD、常量加载）算代价。
2. **对每个内部结点**：对每个匹配的模板，代价 = 模板自身代价 + 各子结点「以该模板要求的子模板」的最小代价。
3. **回溯**：根结点选最小代价的覆盖，回溯记录每步选的模板，得到指令序列。

例：`a[i] = b + c` 的树，用「ADD + 索引存储」两条指令覆盖，可能比「LOAD、ADD、STORE」三条更省——DP 会自动选前者。<span class="marginnote">DP 的产物不只是「一条指令序列」，而是「一棵覆盖树」——每个结点的覆盖模板都记录了「先算什么、用什么指令」。这个覆盖树可以直接指导「求值顺序 + 指令发射」，所以树覆盖同时解决了「选什么指令」与「按什么顺序算」。</span>

## 4 公式解析：覆盖代价的递推

设树根 $v$、指令模板 $T$（代价 $c_T$）、$T$ 要求子树 $v_1, \ldots, v_k$，则：

$$\text{best}(v) = \min_{T \text{ 匹配 } v} \left[ c_T + \sum_{j=1}^{k} \text{best}(v_j) \right]$$

- **第一步，匹配**：$T$ 的根模式必须与 $v$ 的运算一致，子槽与 $v_1..v_k$ 一一对应——模板形态与树形态对齐。
- **第二步，组合**：用 $T$ 覆盖的总代价 = $T$ 自己的代价 + 每个子树的**最优覆盖**代价——子问题的解直接复用。
- **第三步，取最小值**：$v$ 的最优覆盖 = 所有匹配模板里的最小者——DP 表自底向上填满，根处得全局最优。

**这条递推是「指令选择 = 加权树覆盖」的精确数学**：它把机器指令的形态与代价，编码成一组树模式，然后用标准 DP 求解。

## 5 从树到现代后端

树模式匹配是教科书形态，现代后端的实现演进：

- **规范中间表示**：LLVM 把 IR 降到 SelectionDAG，再在其上做树覆盖。
- **模式数量**：真实指令集有数百条指令模板，用 **TableGen** 自动生成匹配器。
- **DAG 而非树**：真实 IR 是 DAG（共享子表达式），覆盖扩展到 DAG 更复杂，但骨架相同。
- **结合调度**：指令选择与指令调度（重排指令利用流水线）在现代后端相互配合。

**重点是**：树覆盖的「模板 + 代价 + DP」骨架，是 LLVM/GCC 指令选择的底层逻辑——变的是模板来源与规模，不变的是「最优覆盖」的问题形式。<span class="marginnote">理解树覆盖，也就理解了为什么「指令选择」被称为「代码生成里的优化问题」：它不追求「能翻译」——任何后端都能翻译——而是追求「翻译得最省」。编译器质量的一半，藏在「选择」里。</span>

## 7 思考与练习

**练习 1 树覆盖**：给一棵表达式树 `a = b + c * d`，用「ADD 模板」「MUL 模板」「LOAD 模板」找两种覆盖方案，各算总代价——验证 DP 选出最小者。

**练习 2 模板设计**：为「内存加常量」设计一个指令模板（树形），说明它如何一次覆盖「取内存 + 加常量」两个 IR 构造——体会「复杂指令 = 大模板」。

**练习 3 最优子结构**：解释「子树的最优覆盖」为什么能组合成「整树的最优覆盖」——DP 正确性依赖的「最优子结构」在树覆盖里的具体含义。

**练习 4 手工 DP**：对一棵 5 结点的小表达式树，用手工 DP 自底向上填代价表——每个结点的表项「用模板 T 的代价 = 模板代价 + 子结点最优」。<span class="marginnote">「手工 DP 填表」是把「指令选择 = 加权树覆盖」的抽象落地的关键练习：对每个结点枚举「匹配的模板」，每项代价 = 模板自身 + 各子树的<strong>最优</strong>——自底向上填满，根处取最小。填完这张表，DP 的骨架就长在手里了。</span>

**练习 5 求值顺序**：说明「覆盖树」如何同时决定「指令序列」与「求值顺序」——覆盖的边界就是「先算什么、用什么指令」的划分。

**练习 6 工程观察**：读 LLVM 的 SelectionDAG 文档（或 TableGen 指令描述），找「指令模板」的声明形态——把教科书的「模板 + 代价 + DP」映射到工业代码。

**常见误区**：

- **误区一**：以为「指令选择 = 一行 IR 配一条指令」——复杂寻址一条指令覆盖多结点，反之可拆分。
- **误区二**：忽略「覆盖要盖满」——每个结点必须属于恰好一个模板；漏盖/重叠都错。
- **误区三**：把 DP 当「枚举」——指数枚举 vs 多项式 DP 的差别在于「子问题复用」。

**延伸**：树覆盖的「模板 + 代价 + DP」与第三级《算法》的「矩阵链乘法」同是区间/树 DP——把「最优覆盖」与「最优括号化」的 DP 结构对比，找「最优子结构」的共性。

## 8 小结

- **树模式匹配**把表达式树切成「单条指令能覆盖」的子树，覆盖方案即指令序列。
- **指令模板**是一棵子树形态的机器指令描述，叶子是「可匹配任何子树」的槽。
- 最优覆盖有**最优子结构**，用**动态规划**自底向上求解——指数枚举压成多项式。
- 覆盖代价递推：$\text{best}(v) = \min_T [c_T + \sum \text{best}(子结点)]$。
- 现代后端（LLVM SelectionDAG、GCC）用自动生成的模板 + 相同 DP 骨架；树覆盖是「指令选择 = 加权覆盖」的精确模型。
