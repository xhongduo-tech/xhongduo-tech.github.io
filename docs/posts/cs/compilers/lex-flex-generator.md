## 为什么从 Lex/Flex 开始

前面四篇是完整的理论链条：正则表达式 → NFA → DFA → 最小化。但理论要变成编译器，还得有人写代码。如果每个编译器都手写词法分析器，工作量大且容易出错——于是有了**词法分析器生成器（lexer generator）**：你只写「记号长什么样、认出来怎么办」的规则，工具替你生成识别代码。

**Lex** 是 1975 年贝尔实验室的迈克 · 莱斯克在 Unix 上写的第一个此类工具；**Flex**（fast lexical analyzer）是它的开源高速重写，接口兼容而性能更好。今天的编译教科书几乎都用 flex + bison 的组合，理解 Lex/Flex 等于理解了「规则驱动代码生成」这一族工具的第一性原理。<span class="marginnote">「词法分析器生成器」还有更广的家族：parser generator（Yacc/Bison）、代码生成器、以及今天的 DSL 编译器——核心思想一致：把声明式规范翻译成命令式代码。</span>

## 1 lex 规范文件的三段结构

一份 lex 文件由 %% 分隔的三个部分构成，一眼可辨：

```
%{
  定义区：原样复制的 C 代码（用 %{ ... %} 包裹）
%}
digit   [0-9]          正则定义，给复杂模式起名字
letter  [a-zA-Z_]

%%

规则区：每行一条「模式 + 动作」规则

%%

用户代码区：C 代码
```

**定义区**：%{ ... %} 内是原样复制的 C 代码；其余是**正则定义**，给复杂模式起名字（如 digit、letter），供规则区复用。
**规则区**：每行一条「模式 + 动作」规则。模式是正则表达式，动作是匹配成功后执行的 C 代码。
**用户代码区**：第二个 %% 之后的 C 代码被原样拷入生成的 lex.yy.c 尾部。<span class="marginnote">yytext 是 flex 自动维护的「当前匹配到的文本」全局变量；yylex 是生成的入口函数，每次调用返回下一个记号或 0。</span>

flex 生成的 lex.yy.c 由编译器编译链接，得到一个可执行词法分析器。**规则与动作分离**是它的设计灵魂：识别逻辑由工具生成，业务动作由你书写。

## 2 规则区：最长匹配与优先级

lex 的匹配有两个关键规则，新手最容易栽跟头：

**最长匹配（maximal munch）**：多个模式同时匹配时，lex 取**匹配最长**的那个。例如标识符规则 [a-zA-Z_][a-zA-Z0-9_]* 与关键字规则 "if"，输入 ifx 时两者都匹配前缀，但 ifx 整体更长，于是按标识符处理。<span class="marginnote">最长匹配保证「能读多长读多长」，符合语言直觉：ifx 不会先被读成 if 再被读成 x。</span>

**规则顺序优先（first match）**：若两个模式匹配同样长度，lex 取**文件中靠前**的规则。因此关键字规则通常写在标识符规则**前面**——"if" 与 [a-zA-Z_][a-zA-Z0-9_]* 匹配等长时，靠前的 "if" 规则胜出，if 才是关键字。

**回退（lookahead / trailing context）**：lex 支持在匹配末尾做位置检查。例如 Fortran 风格分隔符可写 [a-zA-Z]+/; 规则，但更常用的回退形式是 r/s（s 是前瞻部分，不计入匹配），flex 用 / 表示「后面必须跟 s」。<span class="marginnote">flex 内部实现回退（trailing context）靠生成特殊的「前瞻状态」：在试探路径上多读一个字符，若失败则回退已读字符。代价是这种规则会让 DFA 复杂化，工程上建议少用。</span>

## 3 实现原理：从规范到查表机器

flex 生成的内部结构，正是前面三篇理论的完整落地：

1. **编译期（生成 lex.yy.c 时）**：把所有规则的正则表达式合并成一个大 NFA（Thompson 构造），子集构造法确定化，填表最小化，得到一台精简 DFA。
2. **运行期（执行 yylex() 时）**：维护输入缓冲，逐字符驱动 DFA 查表；每到达一个接受状态就记录位置与规则号；一旦后续字符让 DFA「无路可走」，回退到最后一次接受的位置，执行对应动作。
3. **回退机制**：DFA 必须记住「最近一次完整匹配」的位置，才能在最坏情况下回溯。flex 用一个变量跟踪当前接受状态，配合缓冲管理实现 O(n) 平均开销。

**重点是**：flex 的「聪明」全部在编译期一次付清，运行期只是机械的查表——这就是「把理论变成工具」的标准姿势。<span class="marginnote">对比之下，某些正则引擎（如 Perl 的 NFA 回溯）把成本放在运行期，遇到 (a+)+b 这类模式会灾难性回溯。lex 用 DFA 从根上回避了这个问题——但它也因此在「环视、反向引用」等能力上弱于 Perl 系引擎，这是选择 DFA 的代价。</span>

## 4 flex 的实用细节与工程实践

写真实编译器时，flex 有几个高频用法：

**返回记号给语法分析器**：动作里 return TOKEN 把记号编号交给 yylex 的调用者（通常是 yacc 生成的语法分析器）。yylval 全局变量携带语义值（如数字的值、标识符的字符串）。

**起始条件（start conditions）**：flex 支持 %x（互斥）/ %s（包含）起始条件，让同一套规则在不同「词法语境」下启用不同模式——例如字符串字面量内部与注释内部，规则完全不同。<span class="marginnote">起始条件把「上下文敏感」注入词法层：写 C 注释时 /* 之后所有字符都归注释，直到 */。这是用状态机视角管理词法状态的正规做法。</span>

**防冲突与性能**：用 -o 指定输出文件名；-t 只输出到标准输出；较大 DFA 可关掉某些优化换取构建速度。工程上常用 %option header-file 把接口声明导出，便于与 bison 解耦。

**辨析｜易错点：** 不要把 lex 规则区写成「穷举所有输入」——lex 默认在**无匹配时**报错并返回。真实语言里「非法的字符序列」恰恰要靠「没有规则匹配」来捕获，而不是专门写一条错误规则。

## 5 从工具回到原理

理解了 flex 的实现，前面几篇就不再是孤立的定理，而是一条生产流水线：

| 你的输入 | 工具动作 | 产物 |
| --- | --- | --- |
| 正则定义 + 规则 + 动作 | Thompson 构造 | NFA |
| NFA | 子集构造 | DFA |
| DFA | 填表最小化 | 最小 DFA |
| 最小 DFA | 生成 C 代码 | lex.yy.c |

每一行规则背后，都是一台被压缩到极限的确定机器。<span class="marginnote">这四条流水线今天仍然活在 Rust 的 regex crate 编译器、syntect 高亮库等现代工具中——「编译正则到自动机」并未过时，只是换了语言与场景。</span>

## 6 从一条规则到一台机器：完整走查

把「正则 → NFA → DFA → 最小化 → 查表」在一条具体规则上走一遍。规则：标识符 `[a-zA-Z_][a-zA-Z0-9_]*`。

- **Thompson 构造**：`[a-zA-Z_]` 是一个「字符类」，建一个「类边」的零件；`[a-zA-Z0-9_]*` 是闭包零件。合并得到 NFA——几个状态、若干 ε 边。
- **子集构造**：ε 闭包合并状态，得到 DFA——「首字符是字母/下划线」进一个状态，「后续字符是字母数字下划线」留在原地，死字符进陷阱状态。
- **最小化**：合并等价状态，DFA 精简到「首字符态 + 续字符态」两个核心状态（+ 陷阱）。
- **生成代码**：flex 把这个 DFA 编成一张查表——`yylex` 每读一个字符查表，接受态处记录规则号，无路可走时回退到最后接受点。<span class="marginnote">「陷阱状态」是词法 DFA 的常客：<strong>不属于任何合法记号的字符，会驱动 DFA 进入陷阱态——在 lex 里这对应『没有规则匹配』</strong>。所以「非法字符」的检测不是专门写一条规则，而是「所有规则都不匹配」的默认结果。这正是词法分析器用 DFA 的好处：错误检测内置在机器里。</span>

**要点**：一条三行的规则，背后是一台「编译出来」的确定机器。flex 的价值就在把「人类可读的规范」翻译成「机器可查的表」——理论链条的每一步都在这里落地，也正是前面三篇知识的「验收现场」。

**辨析｜易错点：** 别把「规则区」当「按顺序试的 if-else」——flex 不是逐条试规则，而是把**所有规则合并成一台 DFA** 同时匹配，再用「最长匹配 + 规则顺序」裁决。这个「并行匹配、事后裁决」的设计，是它与朴素「逐规则尝试」的本质区别。

## 7 思考与练习

**练习 1 写一份 lex 规范**：为 ToyLang（第八十节的玩具语言）写一份 flex 词法规范——定义数字、标识符、关键字、运算符、注释的正则，并给每个规则配上「返回记号」的动作。写完用 flex 编译跑一个测试输入。

**练习 2 最长匹配验证**：给 flex 规则 "if" 与 [a-zA-Z_][a-zA-Z0-9_]*，输入 ifx 时输出什么记号？再输入 if 呢？用实际运行验证「最长匹配」与「规则顺序优先」两条规则的相互作用。

**练习 3 起始条件**：用 %x 起始条件实现「// 注释」：进入注释后切换状态、忽略内容、遇到换行退出。对比不用起始条件时「注释里出现换行之外的内容会怎样」。

**练习 4 从规则到 DFA**：对你写的标识符规则 [a-zA-Z_][a-zA-Z0-9_]*，手动画出它的 NFA（Thompson）与 DFA（子集构造），再用 flex -d（trace）观察工具生成的转移表——三层对应起来看。

**练习 5 错误处理**：flex 规则区对「无匹配的字符」默认做什么？写一条规则让非法字符被显式报错（打印行号与字符），对比「不写规则」的行为。<span class="marginnote">提示：flex 默认在无匹配时调用默认规则 ECHO（把字符原样复制到输出），输入结束时 yylex 返回 0。要捕获非法字符，通常是最后写一条「任意字符」规则专门报错——把「无规则匹配」变成「有规则报错」，错误信息才可控。</span>

**练习 6 与 yacc 对接**：把练习 1 的 flex 文件与一个最简单的 yacc 文法（只认一个表达式并归约）对接，编译链接跑通——理解 yylex 返回给 yyparse 的记号流如何驱动语法分析。

**延伸**：flex 的「正则 → DFA」流水线，和第八十二节 ToyLang 手写词法器相比，各自在「可读性」「灵活性」「性能」上的取舍是什么？写一段对比说明。

## 8 小结

- **Lex/Flex** 用三段式规范文件（定义区、规则区、用户代码区）描述词法，工具生成 lex.yy.c。
- 匹配遵循**最长匹配**与**规则顺序优先**：ifx 不误判为 if，靠「更长者胜」；关键字靠「靠前者胜」。
- **实现原理**就是理论流水线：合并正则 → Thompson 构造 NFA → 子集构造 DFA → 最小化 → 生成查表代码。
- 运行期**每字符查表**、记录最近接受点以便回退，平均 O(n)；起始条件处理上下文敏感词法。
- flex 用 DFA 从根上回避回溯灾难，代价是放弃环视/反向引用等「超越正则」的能力。
