## 为什么从支配结点开始

循环优化全靠「认出循环」——但「哪里是循环」不是肉眼能定的，它由**流图结构**精确决定：一个循环必须有一个**入口**（循环头），且从入口能回到入口的路径都在循环内。「谁能成为循环入口」由**支配关系（dominance）** 刻画——支配是理解程序结构性的基石，也是代码外提、SSA 构造、寄存器分配（活跃区间）的共同依赖。<span class="marginnote">「支配」的回答是「必经」：如果从程序入口到结点 $B$ 的任何路径都必须经过 $A$，那么 $A$ 支配 $B$。这个「必经」概念让「循环头」有了严格定义——它是唯一能进入循环的支配者。支配树是编译器里最高频的结构之一，SSA（第十一篇）直接建在它之上。</span>

## 1 支配关系与支配树

**支配（dominate）**：结点 $d$ 支配结点 $n$（记 $d \ \text{dom}\ n$），如果从入口结点到 $n$ 的**每一条路径**都经过 $d$。平凡地，每个结点支配它自己；入口结点支配所有结点。

**直接支配者（immediate dominator, idom）**：$n$ 的**最接近**的支配者——支配 $n$、但不支配其他支配 $n$ 的支配者（即「离 n 最近的真支配者」）。

**支配树（dominator tree）**：每个结点的直接支配者作为父结点组成的树——它是「必经关系」的树形压缩：

```
CFG（流图）:              支配树:
entry                     entry
  |                         |
  v                         v
  B1                        B1
 /   \                    /  |  \
v     v                  v   v   v
B2   B3                  B2  B3  B4
 \   /
  v v
   B4
```

**辨析｜易错点：** 「A 支配 D」≠「A 到 D 有边」——支配是路径关系，不是相邻关系。D 可能有多条路径到达，但都经过 A；A 是 D 的支配者，尽管 A 与 D 之间隔着 B、C 多个结点。<span class="marginnote">支配树是「谁必然先于谁执行」的树：支配者一定先于被支配者执行（沿所有路径）。这条「必然先执行」正是代码外提安全性的来源——把计算搬到它的支配者处，等于保证「执行它之前一定执行过搬出点」。</span>

## 2 计算支配者：数据流方程

支配者可以像数据流分析一样用**不动点方程**计算。设 $\text{Dom}(n)$ 是支配 $n$ 的结点集合：

$$\text{Dom}(n) = \{n\} \cup \bigcap_{p \in \text{pred}(n)} \text{Dom}(p)$$

- 入口结点：$\text{Dom}(entry) = \{entry\}$。
- 其他结点：支配者 = 自己 + **所有前驱**支配者的**交集**——「必经所有前驱路线的结点」才是支配者。
- 取**交**：因为「每条路径都经过」要求所有前驱路线的公共必经点。

迭代：从「全集」起步、逐步收缩到不动点；或用更快的 Lengauer–Tarjan 算法 $O(E \cdot \alpha)$。<span class="marginnote">「前驱支配者取交」的直觉：$n$ 的前驱是进入 $n$ 的所有可能「来路」，一个结点若支配 $n$，必须支配每一条来路的共同前缀——所以取交集。这与可用表达式的「全称」语义同构，都是「所有路径都满足」的信息。</span>

## 3 循环的识别

有了支配关系，循环的定义变得精确。**自然循环（natural loop）** 由两部分构成：

1. **一个入口（头）** $h$：循环的唯一入口。
2. **一个返回边（back edge）** $n \to h$：其中 $n$ 被 $h$ 支配。

**识别算法**：对每条边 $n \to h$，若 $h \ \text{dom}\ n$，则它是**回边**（back edge），于是「以 $h$ 为头、含 $n$ 及所有能到 $n$ 的结点」构成一个自然循环。

例：

```
       entry
         │
         v
      ┌─ h ──┐
      │      │
      v      v
      B      C
      │      │
      └─ n ──┘
         │
         └── 回边 n → h（h 支配 n）
```

边 n→h 是回边（h 支配 n），循环 = {h, B, C, n}，头是 h。<span class="marginnote">「h 支配 n」这个条件精确定义了「回到头」的边：只有从被头支配的结点跳回头，才是「合法」的循环；否则跳出去就散了。自然循环的概念是循环优化的基石——外提、归纳变量消除都要求「明确循环头」。</span>

## 4 公式解析：回边与循环的判定

称边 $n \to h$ 为**回边**，当且仅当：

$$h \ \text{dom}\ n$$

由此「自然循环」为：以 $h$ 为头的最大结点集合 $L$，使 $h \in L$、$n \in L$，且 $L$ 中每个结点都有一条（不经过 $h$ 的）路径到 $n$。

- **第一步，回边判定**：h 支配 n ⇔ 从入口到 n 必经 h ⇔ 从 n 回到 h 确实「回到循环内」。
- **第二步，循环体**：所有「能到达 n 而不经过 h」的结点都在循环里——它们要么在头到 n 的路上，要么在 n 回到头的路上。
- **第三步，唯一头**：自然循环有**唯一入口**（h），这保证外提等优化有明确的「循环外」位置。

**「回边 + 支配」把循环从「肉眼直觉」变成「可判定结构」**——优化器可以系统地发现所有循环。

## 5 支配结构的广泛用途

支配树是编译器的「基础设施」，用途遍布：

- **代码外提**：把计算搬到其支配者处，保证「必先执行」。
- **SSA 构造**：支配边界决定 φ 函数的插入位置（第十一篇）。
- **死代码消除**：被支配者的执行以支配者为前提，删除支配者时连带考虑。
- **区域分析**：支配树划分「区域」，供寄存器分配等做局部化处理。
- **结构化控制流验证**：支配关系帮助还原「if/while」结构。

**重点是**：支配是「结构性的信息」——它不依赖具体计算，只依赖流图形状，所以被无数优化共享。<span class="marginnote">支配树与 SSA 的关系尤其密切：SSA 的 φ 函数要插在「支配边界」（一个结点支配 A 但支配不了 A 的某个后继），而支配边界直接由支配树算出。可以说，支配树是 SSA 形式的地基——理解了支配，第十一篇的 LLVM IR 就有了结构支柱。</span>

## 6 小结

- **支配**：$d$ 支配 $n$ ⇔ 从入口到 $n$ 的所有路径都经过 $d$；**直接支配者**组成**支配树**。
- 计算支配者：$\text{Dom}(n) = \{n\} \cup \bigcap \text{Dom(前驱)}$，不动点迭代或 Lengauer–Tarjan。
- **回边**：$h \ \text{dom}\ n$ 的边 $n \to h$；**自然循环** = 回边 + 头到回边的结点集。
- 自然循环有**唯一入口**（循环头），是外提、归纳变量消除的明确作用范围。
- 支配树是编译器的**基础设施**：代码外提、SSA 构造、区域分析都建在它之上。
