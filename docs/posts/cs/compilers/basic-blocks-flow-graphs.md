## 为什么从基本块开始

代码生成与优化都要处理**控制流**——而控制流让「逐条看指令」失效：一条指令可能跳到很远，跳过中间的代码。要看清程序的行为，先把代码切成「没有分支的直线段」——**基本块（basic block）**，再把基本块之间的跳转画成图——**流图（flow graph / control-flow graph, CFG）**。<span class="marginnote">「直线段 + 跳转图」是分析程序结构的标准分解：段内可做局部优化（顺序执行、无岔路），段间可做全局分析（数据流、支配关系）。任何「理解程序行为」的编译器算法，几乎都建在 CFG 这个地基上——包括第八篇全部数据流分析与后端的寄存器分配。</span>

## 1 基本块的定义

**基本块（basic block）** 是满足以下条件的指令序列：

**单一入口**：只有第一条指令能被（程序中的任何跳转）作为目标进入。
**单一出口**：只有最后一条指令能（跳到别处或结束）离开。
块内**顺序执行**，无跳转进出。

性质：若进入块，则块内指令**全部执行**且按序执行——块内没有分支，所以「进入即执行到底」。

**划分算法**（给定三地址码序列）：

1. 找出**入口指令**（leader）：
第一条指令。
任何跳转目标指令。
任何紧跟条件跳转/无条件跳转之后的指令。
2. 每个 leader 到「下一个 leader 之前」（或程序尾）的区间就是一个基本块。

**辨析｜易错点：** 「紧跟跳转之后」也是 leader——因为跳转可能跳过它到达。漏掉这条，会错误地把「被跳过的指令」并入前一个块。<span class="marginnote">leader 的三条规则是划分的「入口集合」，块就是「从每个入口延伸到自己结束」。一个常见考题：跳转目标、分支合并点、函数入口全是 leader；把它们找全，块的划分就唯一确定。</span>

## 2 流图：基本块间的控制流

**流图（flow graph）**：以基本块为结点的有向图：

**结点**：每个基本块。
**边**：块 $B_1$ 到 $B_2$ 有一条边，若 $B_2$ 的第一条指令可能紧接着 $B_1$ 的最后一条指令执行（条件/无条件跳转指向 $B_2$，或 $B_1$ 末尾顺序落入 $B_2$）。

从入口结点（含程序第一条指令的块）出发，沿边可到达一切可达块。

**流图的表示**：邻接表（每块存后继列表）；同时可维护**前驱列表**（谁指向我）——前驱/后继双向索引是数据流分析的基本设施。<span class="marginnote">「入口 + 前驱/后继」让流图既是「控制流地图」，也是「数据流分析的载体」：沿边传递信息（到达定值、活跃变量）时，边的方向就是信息流动的方向。把流图想成一张「信息的高速路网」，各种分析就是在上面跑信息。</span>

## 3 流图的用途

流图是整个优化与代码生成后端的公共骨架：

**局部优化**在基本块内做（公共子表达式、死代码——下一节）。
**全局优化**在流图上做（数据流分析、循环识别、支配树——第八篇）。
**寄存器分配**以流图为界（活跃区间、图着色——后面一节）。
**代码布局**（块的排列顺序）也基于流图（热块靠拢、跳转消除）。

**重点是**：流图把「程序」抽象成「图」，从此优化/生成的一切算法都是图算法。<span class="marginnote">现代编译器里 CFG 不只是理论——LLVM 的 `BasicBlock` 就是基本块，`successors()` 方法返回后继块（流图边），几乎每个 pass 都在 CFG 上迭代。把 CFG 当作「程序的地图」，是所有后端知识的统一入口。</span>

## 4 公式解析：前驱与后继

对结点 $B$ 定义其前驱与后继：

$$\text{pred}(B) = \{A \mid A \to B \text{ 是流图边}\}, \qquad \text{succ}(B) = \{C \mid B \to C \text{ 是流图边}\}$$

- **第一步，后继的三种来源**：$B$ 末尾顺序落入的块、条件跳转的目标、无条件跳转的目标——都构成后继。
- **第二步，前驱的对称性**：前驱是「可能跳进 $B$ 的块」——$B$ 的 leader 若是跳转目标，那个跳转所在的块是前驱；若 $B$ 是顺序落入的，上一块是前驱。
- **第三步，分析用途**：数据流分析沿前驱/后继传播；「到达定值」需要前驱集合，「可达性」需要后继集合——两个索引配合使用。

**「前驱/后继是流图的左右手」**——绝大多数图算法同时用两者，构建时就双向维护。

## 5 一个划分示例

给定三地址码：

```
i = 1
L1: s = s + i
    i = i + 1
    if i < n goto L1
t = s * 2
```

划分结果：

- **块 1**：`i = 1` 单指令。
- **块 2**：`L1: s = s + i` 到 `if i < n goto L1`——从 goto 目标到条件跳转。
- **块 3**：`t = s * 2`——跳转后的指令。

流图：块 1 → 块 2（顺序落入）；块 2 → 块 2（自环，`goto L1` 回到自己）与块 3（条件不成立落入）。<span class="marginnote">自环（块 2 指向自己）是循环的流图签名——一个块「跳回自己」就是最简循环。流图上一旦出现环，就标识了循环结构，而循环是优化（外提、强度削弱）的主战场——第八篇的支配与循环识别正是从这里出发。</span>

**第二个例子：if-else 分支**。对三地址码：

```
t = a < b
if t goto L1
x = y
goto L2
L1: x = z
L2: w = x
```

划分出四块：块 1（`t=a<b`、`if t goto L1`）、块 2（`x=y`、`goto L2`）、块 3（`x=z`，goto 目标）、块 4（`w=x`，落入点）。流图：块 1 指向块 2 与块 3（分支），块 2、块 3 都指向块 4（汇合）。**汇合点（join point）** 是数据流分析最忙的结点——多个前驱的信息在此融合，正是活跃变量、到达定值计算的交汇处。<span class="marginnote">「分支 + 汇合」是流图最常见的形态：if/else、switch、循环都归结为「出度 1–2 的块 + 入度 ≥2 的汇合块」。数据流分析沿边传播信息，在汇合块做并/交运算——理解汇合，就理解了一半的数据流框架。</span>

**术语速查**：

| 术语 | 含义 |
| --- | --- |
| leader | 基本块的入口指令 |
| 基本块 | 单入口单出口、无内部跳转的直线段 |
| 流图 / CFG | 以基本块为结点、跳转/落入为边的有向图 |
| 自环 | 块到自己的边，循环的流图签名 |
| 汇合点 | 多个前驱汇聚的结点，数据流分析的交汇处 |

## 6 小结

- **基本块**是单一入口、单一出口、块内无跳转的直线指令段；「进入即执行到底」。
- 划分靠 **leader 三规则**：首条、跳转目标、跳转之后；漏第三条会切错块。
- **流图**以基本块为结点、跳转/落入为边，是程序控制流的图化。
- 前驱/后继双向索引是数据流分析的「左右手」，构建时双向维护。
- 流图是局部优化、全局分析、寄存器分配、代码布局的**公共骨架**；CFG 上的算法即图算法。
