## 为什么从正则表达式开始

词法分析器面对的是原始字符流，它要回答一个朴素的问题：**当前读到的这串字符，属于哪一种记号（关键字、标识符、数字、运算符）？** 要精确回答，必须先把「标识符长得什么样」「无符号整数长得什么样」这种日常描述，翻译成可以机械检查的语言。

**正则表达式（regular expression）正是这种语言。** 它是描述「一类字符串集合」的代数记号，比自然语言精确，比逐串穷举简洁。1956 年，逻辑学家克雷尼（Stephen Kleene）在研究神经网络表达能力时提出了正则表达式；1968 年，肯 · 汤普森（Ken Thompson）把它实现进 QED 编辑器，从此 grep、lex、Perl、Python 一路继承。<span class="marginnote">你今天写下的 `\d+`、`[a-zA-Z]`，正是汤普森那套记号的直系后代。编译原理的意义之一，就是把这份「随手能写」变成「可以证明正确」。</span>

而正则表达式之所以配得上「原理」二字，在于它与**有限自动机**之间那条可以双向转换的数学桥梁——「一个正则表达式描述的字符串集合，恰好就是某台机器能识别的集合」。这是本节之后几篇共同的主题，也是词法分析器从「规则」走向「程序」的必经之路。

## 1 正则表达式：描述字符串集合的代数

先立两个词。**字母表（alphabet）** $\Sigma$：记号可以使用的字符集合，例如 $\Sigma = \{a, b\}$ 或 ASCII 全集。**语言（language）**：字母表上所有字符串的一个子集，即 $L \subseteq \Sigma^*$。<span class="marginnote">$\Sigma^*$ 表示由 $\Sigma$ 中字符构成的全体字符串（含空串）。语言就是字符串集合——记住这一点，正则表达式的一切都变得直白：它不过是在描述「哪些串属于这个集合」。</span>

正则表达式递归地定义它描述的语言：

$$L(\varepsilon) = \{\varepsilon\}, \quad L(\emptyset) = \emptyset, \quad L(a) = \{a\}\ (a \in \Sigma)$$

$$L(r \mid s) = L(r) \cup L(s), \quad L(rs) = \{xy \mid x \in L(r),\, y \in L(s)\}, \quad L(r^{*}) = \bigcup_{i \ge 0} L(r)^i$$

逐条读：

- **基础**：$\varepsilon$ 匹配**空串**；$\emptyset$ 匹配**空语言**（任何串都不匹配）；单个字符 $a$ 匹配恰含这一个字符的串。
- **选择（union）** $r \mid s$：匹配 $r$ 或 $s$ 能匹配的串。
- **连接（concatenation）** $rs$：先匹配 $r$ 再匹配 $s$，两个串首尾相接。
- **闭包（Kleene star）** $r^*$：$r$ 重复零次或任意多次。

设 $\Sigma = \{a, b\}$，看几个具体的语言：$L(a) = \{a\}$；$L(a \mid b) = \{a, b\}$；$L(ab) = \{ab\}$；$L(a^*) = \{\varepsilon, a, aa, aaa, \ldots\}$；$L((a \mid b)^* b)$ 是「以 $b$ 结尾的、由 $a,b$ 组成的全体字符串」。<span class="marginnote">闭包允许零次，所以 $\varepsilon \in L(a^*)$。这个「零次也算」的约定，与后面 `+` 表示「至少一次」形成互补，是扩展记号的基础。</span>

**重点是**：正则表达式与正则语言之间是「表达」关系——一个正则表达式精确地描述一个字符串集合，不多不少。这也是词法分析器「按正则定义去识别记号」的理论依据：识别正确与否，是可以用集合相等来判定的。

## 2 正则定义：给复杂记号起名字

直接用单个表达式描述真实语言的关键字、数字会很冗长。**正则定义（regular definition）** 允许给子表达式命名并递归复用：

$$d_1 = r_1, \quad d_2 = r_2, \quad \ldots, \quad d_n = r_n$$

每个 $d_i$ 是名字，$r_i$ 是正则表达式，且 $r_i$ 中只能引用**前面已经定义**的 $d_j$（$j < i$）——这条顺序约束保证了定义不会循环。以 C 风格语言的标识符为例：

$$\begin{aligned} \textbf{digit} &\to 0\mid1\mid\cdots\mid9 \\ \textbf{letter} &\to \text{A}\mid\text{B}\mid\cdots\mid\text{Z}\mid a\mid b\mid\cdots\mid z \\ \textbf{id} &\to \textbf{letter}(\textbf{letter}\mid\textbf{digit})^* \end{aligned}$$

读法：**标识符 = 一个字母后跟零个或多个（字母或数字）**。无符号整数则可定义为 $\textbf{digit}^{+}$（一次或多次），例如 `1984`、`0` 都匹配，而空串不匹配。这些「名字」正是词法分析器要向语法层报告的记号类别。<span class="marginnote">lex/flex 工具的做法与此一一对应：先写名字与表达式，工具据此生成识别代码。名字在这里承担了「给集合起名」的角色，与数学里「定义新符号」是同一个动作。</span>

**辨析｜易错点：** 正则表达式能描述「重复任意次」，但不能描述「嵌套任意层」——例如括号任意层嵌套 $(\ldots(\ldots))$ 的结构就不是正则语言。这是词法层的边界：**凡是需要「记住已经嵌套了几层」的规则，都越过了正则的边界**，要交给语法层（上下文无关文法）处理。

## 3 正则表达式的代数定律

正则表达式构成一个代数系统，满足若干定律。设 $r, s, t$ 是任意正则表达式：

| 定律 | 表达式 |
| --- | --- |
| 交换律 | $r\mid s = s\mid r$ |
| 结合律 | $(r\mid s)\mid t = r\mid(s\mid t)$，$(rs)t = r(st)$ |
| 分配律 | $r(s\mid t) = rs\mid rt$，$(s\mid t)r = sr\mid tr$ |
| 恒等律 | $r\mid \emptyset = r$，$r\varepsilon = r$ |
| 零元 | $r\emptyset = \emptyset$ |
| 闭包恒等式 | $\emptyset^* = \varepsilon$，$\varepsilon^* = \varepsilon$，$(r^*)^* = r^*$ |

运算符优先级从高到低为：**闭包 $^*$ > 连接 > 选择 $|$**。所以 $a\mid bc^*$ 应读作 $a \mid (b(c^*))$，而不是 $(a\mid b)(c^*)$。<span class="marginnote">这个优先级与「乘法优先于加法」的约定如出一辙：先算「乘积」再算「和」。工具与教材都建议用括号显式分组，避免跨工具的行为差异。</span>

**辨析｜易错点：** 连接不满足交换律——$ab \neq ba$。选择满足交换律、连接不满足，这与数的乘法交换律形成对照；正则表达式里的「顺序」是语义的一部分，因为串本身的字符顺序就是语义。

## 4 公式解析：$L(r)$ 的递归定义

**正则表达式与它描述的语言，是靠一条递归定义绑定的。** 把这条定义拆成三层看：

- **第一步，基础情形**：$L(\varepsilon)=\{\varepsilon\}$、$L(\emptyset)=\emptyset$、$L(a)=\{a\}$。这三条像自然数公理里的 0 与后继——是递归的「地基」，保证任何正则表达式最终都能归结到它们。
- **第二步，组合规则**：$L(r\mid s)=L(r)\cup L(s)$、$L(rs)=\{xy\mid x\in L(r), y\in L(s)\}$、$L(r^*)=\bigcup_{i\ge0}L(r)^i$。这三条把「语言运算」与「集合运算」对齐：选择对应集合并，连接对应串的拼接，闭包对应有限次幂的并。
- **第三步，归约**：任何正则表达式都可以反复用组合规则拆到基础情形，所以 $L(r)$ 是**良定义的（well-defined）**——这保证「判断一个串是否属于 $L(r)$」有确定答案，词法分析器才有资格谈正确性。

**这一条递归定义，就是整篇词法分析正确性的锚点。** 后面从正则到 NFA、从 NFA 到 DFA 的所有构造法，本质上都是在把这条「语言的递归描述」翻译成「机器能机械执行的状态转移」。

## 5 正则表达式与词法分析器的接口

有了正则定义，词法分析器的工作就被规范了：**为每种记号写一条正则定义，然后把所有定义拼成一个整体识别器。** 实现上有「模拟 NFA」与「构造 DFA」两条路线，后者正是下一节的主题——**有限自动机（finite automaton）** 就是正则表达式的「机器形态」。

工业与教学常用的**扩展记号**（简写，均可等价翻译为基本运算）：

| 扩展记号 | 含义 | 等价写法 |
| --- | --- | --- |
| $r^+$ | 一次或多次 | $rr^*$ |
| $r?$ | 零次或一次 | $r\mid\varepsilon$ |
| $[a-z]$ | 字符区间 | $a\mid b\mid\cdots\mid z$ |
| $.$ | 任意字符 | 按字母表展开 |
| `"\*"` | 字面量转义 | $\ast$ |

这些扩展记号让 `[a-zA-Z_][a-zA-Z0-9_]*` 这样的标识符规则一行写尽，而它背后的语言仍是正则的。<span class="marginnote">「扩展记号不增加表达能力」是一条重要事实：任何 `+`、`?`、区间写出来的语言，都还是某个基本正则表达式的语言。扩展只是为了人类可读，机器的能力并未变强。</span>

## 7 思考与练习

**练习 1 正则转语言**：设 $\Sigma = \{0, 1\}$，写出以下语言的正则表达式：

- 由 0、1 组成且以 1 结尾的串：`(0|1)*1`。
- 含至少一个 0 的串：`1*0(0|1)*`。
- 不含连续两个 0 的串：`1*(0|ε)(1*01*)*`（提示：把串按 1 分段）。

写完后，每个表达式挑两个「属于」与两个「不属于」的串验证一遍——这是检验正则直觉最快的办法。

**练习 2 语言求值**：表达式 `a(b|c)*d` 描述的语言是什么？给出三个属于、两个不属于它的串，并说明理由。<span class="marginnote">答案提示：语言 = 「以 a 开头、d 结尾、中间是零个或多个 b 或 c 的串」，如 `ad`、`abcd`、`abccd` 属于；`abd`、`ab` 不属于。</span>

**练习 3 正则定义的改写**：若标识符允许「以数字开头」，正则定义 $\textbf{id} \to \textbf{letter}(\textbf{letter}\mid\textbf{digit})^*$ 应如何改写？提示：首字符与后续字符的「字母表」不同，需分开声明。

**练习 4 代数定律证明**：用分配律与闭包恒等式证明 $(a\mid b)^*$ 与 $(a^*b^*)^*$ 描述同一语言。提示：两边都等于「由 a、b 组成的一切串」；从「⊇」与「⊆」两个方向分别论证。

**练习 5 能力边界**：解释为什么正则表达式**无法**描述「回文串」（正读反读相同，如 `abcba`）。提示：识别回文需要「记住」已读前缀并在结尾对比——这需要与输入长度无关的存储，而正则语言对应的有限自动机只有固定大小的记忆。<span class="marginnote">这道题是本节的「能力边界题」：它逼你理解「有限记忆」的局限，也是下一节 NFA/DFA 的铺垫——有限自动机记不住任意深的前缀。</span>

**练习 6 优先级陷阱**：`a|bc*` 与 `(a|b)c*` 描述的语言有何不同？若不写括号，`a|bc*` 会被误读成什么？请写出两个「被括号改变归属」的具体例子。

**延伸**：思考「正则表达式与集合运算」的对应——选择对应并、连接对应笛卡尔积式的拼接、闭包对应迭代——然后在第三级《数据结构》里找一个「用正则做匹配」的真实场景（如 `grep` 的 `[a-zA-Z]`），把本节的记号对应上去。

## 8 小结

- **正则表达式**是描述字符串集合的代数记号，递归定义于字母表之上，语言 $L(r)$ 由基础情形与选择、连接、闭包三条规则生成。
- **正则定义**用带顺序约束的命名复用组织复杂记号，是词法规范的书写形式；「名字」即记号类别。
- 正则表达式满足**交换律（仅选择）、结合律、分配律**等代数定律；优先级为**闭包 > 连接 > 选择**；**连接不满足交换律**。
- 扩展记号（`+`、`?`、字符区间、转义）**不增加表达能力**，只增加可读性。
- **正则语言不能表达嵌套结构**，那是上下文无关文法的领地——词法层的边界在此。

在下一节，我们把正则表达式从「代数记号」翻译成「机器模型」：**有限自动机 NFA 与 DFA**，这是词法分析器得以机械执行的关键一步。
