## 为什么从输入缓冲开始

词法分析器的工作对象是源程序的**字符流**。最天真的实现是：每次要下一个字符，就调用一次文件读取。但文件 I/O 是编译流水线里最慢的操作之一——如果词法分析器每读一个字符都触发一次系统调用，整个编译器都会慢得不可接受。

解决方案朴素而有力：**一次性读入一大块字符放进内存缓冲，词法分析器在内存里取字符。** 但缓冲带来的新问题是**边界**：指针走到缓冲末尾时，怎么知道该停下来补充数据，而不是越界读取？龙书给出的经典答案是**哨兵（sentinel）**——在缓冲末尾放一个哨兵字符，用「检查哨兵」代替「每次判断越界」。<span class="marginnote">哨兵思想贯穿计算机科学：单链表的尾哨兵节点、C 字符串末尾的 `\0`、回溯搜索里的边界哨兵，全是「用哨兵把边界检测摊薄」的同一种技巧。它是《算法导论》里「哨兵可以简化边界条件」的教科书案例，对应第二级《数据结构与算法》中链表哨兵的应用。</span>

## 1 为什么必须缓冲：I/O 的昂贵与局部性

先量化一下问题。一个中等规模的源文件有几十万字符，词法分析器要**逐字符**消费它。若每个字符都从磁盘读，一次系统调用约几十微秒——几十万次就是几十秒，任何编译器都无法忍受。<span class="marginnote">现代机器上内存访问比磁盘快几个数量级：磁盘访问约毫秒级，内存约纳秒级——相差约一百万倍。因此「一次读入、多次使用」是 I/O 优化的第一法则，操作系统本身也靠页缓存、预读实现同样的思想。</span>

**输入缓冲（input buffering）**：词法分析器不直接操作文件，而是通过一个缓冲区管理器取字符。这样一来：

- **读入按块进行**：每次向操作系统请求一大块（如 4096 字节），分摊系统调用开销。
- **取字符按个进行**：词法分析器在内存缓冲中移动指针取字符，代价接近 O(1)。
- **支持放回**：词法分析器常常「多读一个字符再放回」（lookahead），缓冲让放回只是把指针回退一格，零成本。

用数字把「必须缓冲」说透：设源文件 10 万字符，若逐字符调用 `fgetc`（每次触发一次系统调用），按每调用约 1 微秒计，光读字符就要 0.1 秒以上，这还没算字符处理本身；而一次 `fread` 读入 4096 字节的缓冲，只需约 25 次系统调用，读入时间可忽略不计。**把 10 万次 I/O 压成 25 次，正是缓冲的全部意义。** 这也是为什么任何语言标准库的字符读入函数，内部都藏着一段缓冲逻辑——`fgetc` 之所以不慢，正因为它背后有 `fread` 级别的缓冲垫着。

## 2 一对缓冲：交替使用避免搬迁

一个缓冲不够：词法分析器可能正读着缓冲前半段的字符，同时还要「向前看」后面几十个字符——如果缓冲区太小，向前看就会越过边界。龙书的方案是**一对缓冲（pair of buffers）**：

- 缓冲 1 与缓冲 2 各长 $N$，交替填装；
- 词法分析器用**两个指针**在其中移动：**begin** 指向当前词素的开始，**forward** 指向正在扫描的位置；
- 当 `forward` 越过缓冲 1 末尾时，系统把**下一块数据填入缓冲 2**，`forward` 跳到缓冲 2 的开头继续；
- 填缓冲 2 的同时，`begin` 之前的字符早已消费完毕，可以放心覆盖。<span class="marginnote">为什么是两个而不是一个？因为 `begin` 到 `forward` 的距离就是当前词素的长度，一个缓冲放不下「正在匹配的长词素 + 向前看余量」时就会撞墙。两个缓冲交替，就保证了 `begin` 到 `forward` 之间的内容始终完整。单缓冲方案想获得同样保证，只能在每个词素结束时把后半段搬回开头——多一次拷贝。</span>

用伪代码表达「双缓冲 + 哨兵」的字符读取：

```c
/* 伪代码：双缓冲 + 哨兵字符读取 */
char* forward = buffer1;       /* 当前扫描位置 */
char* begin    = buffer1;      /* 当前词素起点 */
const char SENTINEL = 0xFF;    /* 哨兵字符，源程序中不会出现 */

char nextChar(void) {
    if (*forward != SENTINEL) {       /* 绝大多数情况：不是哨兵，直接取 */
        return *forward++;
    }
    if (forward == buffer2 + N)       /* 第二缓冲末尾的哨兵 */
        return EOF;                   /* 输入真正结束 */
    fill(forward);                    /* 填充另一块缓冲 */
    return *forward++;
}
```

## 3 哨兵：用「检查字符」代替「检查越界」

**哨兵（sentinel）**：在**每个缓冲的末尾**放置一个**不会出现在源程序中的特殊字符**，比如 `eof`。它的作用是把「每次读字符都要判断『指针是否越界』」变成「只在读到哨兵字符时才判断」。

没有哨兵的实现，每次取字符都要写一遍：

```c
if (forward == buffer1_end) fill(forward);  /* 每次都要检查 */
```

有了哨兵，每次取字符只需判断「当前字符是不是哨兵」——而判断字符本身是词法分析器**本来就要做**的事（每个字符都要决定它属于哪一类），于是**哨兵检查几乎免费**。<span class="marginnote">龙书强调这个技巧的妙处：判断「是否是哨兵」与判断「字符类型」合并在同一个比较里，越界检测的次数从「每字符一次」降为「每缓冲一次」。这就是戈登 · 贝尔那句话的精神——不是把组件做得更快，而是让组件不存在。</span>

哨兵还区分了两种「走到头」的情况，龙书用**两个哨兵位置**把它们分开：

- **缓冲末尾的哨兵**：表示「这块缓冲读完了，需要填另一块」——词法分析器填充新数据后继续；
- **缓冲 2 末尾的哨兵**：表示「整份输入已经读完，真正的 EOF」——词法分析器结束扫描。

**易错点：** 哨兵字符必须**不可能出现在合法输入中**。若源程序里恰好有该字符（比如用了 `0xFF` 而文件是二进制），词法分析器就会提前「假 EOF」。因此选哨兵要小心：文本源码通常不含 `0xFF`；更稳妥的做法是用「两个字符的哨兵对」，进一步降低冲突概率。这是「用约定换速度」方案的通病——**约定的前提一旦被打破，正确性就告吹**。

## 4 公式解析：哨兵把边界检查摊薄到 O(1)

哨兵的价值可以用**摊还分析（amortized analysis）**精确刻画。设每读一个字符的基本代价为 $1$（取字符并判类型），一次越界检查的代价为 $c$。

- **无哨兵**：每读一个字符都要做一次越界判断，总代价是 $N \times (1 + c)$。
- **有哨兵**：只在读到缓冲末尾的哨兵字符时才做一次越界判断。每个缓冲长 $N$，每读 $N$ 个字符只需一次检查：

$$
\text{摊还代价} = 1 + \frac{c}{N} \;\longrightarrow\; 1 \quad (N \to \infty)
$$

逐项拆解：

- **$1$ 是取字符并判断类型**：这是不可省的基本功，每字符必有。
- **$c/N$ 是摊薄的越界检查**：每 $N$ 个字符才付一次代价 $c$，摊到每个字符只有 $c/N$。
- **$N \to \infty$ 的极限**：缓冲越大，越界检查摊得越薄，摊还代价趋近 $1$——**哨兵使「边界管理」在渐近意义上免费**。
- **代价与收益的权衡**：$N$ 太大浪费内存（两个缓冲共 $2N$），太小则填充频繁、摊薄效果差。工程上取 $N = 4096$，是内存与效率的良好平衡。

**这就是哨兵的核心公式：把「每次检查」换成「定期检查」，用一次性的哨兵比较换掉逐字符的越界判断。** 它不减少检查的**总次数**（两种方案都要在边界检查），但把检查从「每字符」压缩到「每缓冲」，常数因子缩小 $N$ 倍。

## 5 辨析：哨兵不是唯一答案

哨兵是龙书的教学经典，但工程上还有别的路：

- **索引比较**：每次读字符都显式比较指针是否到达末尾。直观，但每字符多一次比较，与哨兵相比效率略低。
- **内存映射文件（mmap）**：把整个文件映射进地址空间，操作系统负责分页读入；词法分析器像访问数组一样访问字符，**根本没有「缓冲边界」概念**，越界由页错误机制兜底。<span class="marginnote">现代解释器（如 Lua、V8 的部分路径）常直接用 mmap 或整体读入的 `byte[]`，彻底绕开「缓冲区管理」——代价是文件必须能整体进地址空间。哨兵思想并未消失，只是换成了「字符串末尾的 `\0`」。</span>
- **整体读入**：把整个源文件读成一个字符串，词法分析器只维护 `begin` / `forward` 索引，越界检查变成一次 `forward < length`。

**易错点：** 哨兵方案依赖「哨兵字符不出现在输入中」的假设，而 mmap / 整体读入方案没有这个假设、更普适。哨兵的价值在于**教学上极其清晰 + 常数因子最优**，但现代工程实现更常用整体读入。**理解哨兵，是理解「用空间 / 约定换取时间」的第一课，而不是照搬它的实现。**

## 6 小结

- 词法分析器必须**缓冲**输入：一次读入一块，逐字符在内存中消费，避免昂贵的一次性 I/O。
- 经典方案是**一对缓冲** + 两个指针：`begin` 指向当前词素起点，`forward` 指向扫描位置，缓冲交替填充。
- **哨兵（sentinel）**在缓冲末尾放一个不可能出现在输入中的字符，把「每字符越界检查」换成「每缓冲一次检查」。
- 摊还分析给出哨兵的价值：**摊还代价 $1 + c/N \to 1$**，边界管理渐近免费。
- 现代实现可用 **mmap / 整体读入**替代哨兵，但哨兵「用约定消除检查」的思想仍然普适。

在下一节，词法分析终于要迎来它的核心算法：**正则表达式与正则定义**——如何用一套形式语言，精确地写出「什么是一个记号」，为自动机的构造提供原料。
