## 为什么从活动树开始

活动记录解决了「一次调用放什么」，但要证明**栈式分配为什么总是够用**，还需要看清调用的整体结构。程序运行期间的调用历史不是随意的线性序列，而是一棵有规律的树——**活动树（activation tree）**。看清这棵树，栈的正确性、递归的行为、栈深度的上界就都有了答案。<span class="marginnote">「调用是树、栈是 DFS」是运行时的隐藏对称：活动树从根（主程序）生长，栈从根一路压到当前叶子，返回时原路弹回。这个「树与栈的对应」让栈式分配成为调用历史的天然镜像——不需要搜索，只需要前进与后退。</span>

## 1 活动树：调用历史的树形表示

**活动树（activation tree）** 的构造规则：

**根**：主程序的活动。
**结点**：每次过程调用产生一个子活动（调用结点）。
**次序**：活动按「调用发生时刻」从左到右排列。

例如 `main` 调 `r`，`r` 里调 `a`、`b`、`c`（依次），树为：

```
        main
         │
         r
       / | \
      a  b  c
```

**一次「活动」（activation）** 对应树中的一个结点：从进入函数到返回的那段时间。同一函数被调多次，就有多个结点（区分不同的活动）。<span class="marginnote">活动树与「调用栈回溯」是同一棵树的两个视角：活动树是「俯视图」（静态看全部调用），栈是「俯视图的当前截面」（只看从根到当前叶子的路径）。调试器里 `bt`（backtrace）打印的栈帧链，正是活动树的根到当前结点路径。</span>

## 2 栈 = 活动树的深度优先游历

栈式分配的核心观察：**程序运行的过程，恰是活动树的深度优先遍历（DFS）**——

调用一个过程 = 沿树**向下走进一个子结点**（压入 AR）。
返回 = 沿树**向上退回父结点**（弹出 AR）。
任意时刻栈中的 AR，恰好是**根到当前结点的整条路径**。

因此栈的大小 = 活动树的**深度**，而非总结点数。这带来一个关键性质：**同时活跃的活动，是树上的一条路径**，绝无「分支共存」——所以它们的存储可以线性排列，互不重叠。<span class="marginnote">「同时活跃的是一条路径」是栈式分配正确性的核心：`b` 调用 `d` 时 `a` 已返回、`c` 还没开始，`b` 返回时 `c` 才启动——兄弟活动<strong>时间上不重叠</strong>，于是可以复用同一块栈空间。这就是栈能「节省」的根源。</span>

## 3 递归：同一函数，多层活动

递归是活动树最生动的体现：`fact` 的活动树是一条链 `fact → fact → …`，每个结点是同一函数的**不同活动**，各有独立的 AR。

```
fact(4)
  │
  v
fact(3)
  │
  v
fact(2)
  │
  v
fact(1)
```

每一层调用压入一个 AR，栈深 = 递归深度 + 1。
每层 AR 有自己的参数与局部变量——递归的「每一层数据独立」由栈天然保证。
无尾递归优化时，`fact(n)` 的栈占用 O(n)；若编译器做了尾调用优化（复用同一帧），可降到 O(1)。

**辨析｜易错点：** 递归**不是**函数「重复使用自己」——是「创建自己的多个活动」。代码只有一份，AR 却有多份；把递归理解为「多层活动」而非「循环」，就不会混淆层与层之间的数据。<span class="marginnote">这也解释了两类递归的性能差异：普通递归每层建帧、深度与输入成正比；尾递归若被优化成「同一帧复用」，则空间 O(1)——像循环。栈空间能否复用，取决于返回后还有没有后续计算（是否为尾位置）。</span>

## 4 公式解析：活动树深度与栈上界

设活动树的深度为 $d$（根到最深叶子的边数），则：

$$\text{栈空间上界} = d \times \text{最大 AR 大小}, \qquad \text{同时活跃的 AR 数} = d+1$$

- **第一步，深度即共存数**：栈中 AR 数 = 根到当前结点的路径长度 = 当前深度。最大共存数 = 树的最大深度。
- **第二步，每层尺寸**：每层 AR 大小可能不同，取所有层 AR 大小的上界乘深度，得栈空间上界。
- **第三步，与输入的关系**：树深随输入变化（递归深度取决于输入），所以「栈溢出」风险取决于**最大递归深度 × 每帧大小**——编译器可在栈上布置警戒页（guard page），触到即报「栈溢出」。

**「栈空间 ∝ 树深」给出递归程序的内存画像**：斐波那契的朴素递归树深 O(n)、结点数 O(2^n)——栈只需 O(n)，但时间爆炸；真正的瓶颈往往在时间而非栈。

## 5 栈式分配的正确性条件

栈式分配「总是够用」有一个前提，语言必须满足：

**过程在返回后，其局部数据不再被引用**——即「禁止返回指向本地数据的指针」（至少不能解引用）。

若违反（如 C 里返回局部数组的地址），就是**悬垂引用（dangling reference）**：AR 已弹出，数据区被后续调用覆盖。C 的「返回局部变量地址」是未定义行为，根因正在于栈式分配的回收。<span class="marginnote">「数据不能逃出帧」的约束，是栈式分配与闭包/对象模型的分界：需要把数据带出过程（闭包捕获、对象返回）的语言，要么用堆（Java、Python），要么用所有权规则显式转移（Rust）。栈的便宜，换来的是「寿命不能超过帧」的纪律。</span>

## 7 常见误区与延伸

**常见误区**：

- **误区一**：以为「栈中装的是所有活动」——栈只装「根到当前结点的路径」，兄弟活动不共存，所以栈可线性复用。
- **误区二**：把「递归」当「函数用自己」——递归是「同一函数的多层活动」，每层一个 AR，代码共享、数据独立。
- **误区三**：以为「递归一定栈溢出」——栈深 = 递归深度；尾递归被优化后复用同一帧，空间 O(1)。
- **误区四**：忽视「数据不能逃出帧」——返回局部变量地址是悬垂引用，根因在栈的回收语义。

**延伸**：活动树与第三级《数据结构》的「表达式求值栈」、第四级《调试器》的「调用栈回溯」是同一棵树——调试器的 `bt` 命令打印的正是「根到当前叶子的路径」。把「活动树」当作「程序的动态结构档案」，与「静态的 CFG」对比，说说「静态结构 vs 动态调用」的互补。

**练习提示**：对互递归 `f`、`g`（f 递归调用 g、g 调用 f），画出活动树，标出「f 的两个活动」与「g 的一个活动」——验证「同函数多结点、兄弟不共存」。

## 8 小结

- **活动树**把调用历史画成树：结点 = 一次活动，兄弟按调用时刻排序；根为主程序。
- **栈 = 活动树的 DFS**：压栈 = 进子结点、弹栈 = 退父结点；栈中 AR 恰是根到当前结点路径。
- **同时活跃的活动是一条路径**——兄弟不共存，栈空间因此可复用、可线性排列。
- **递归 = 同函数的多个活动**，各层 AR 独立；尾递归优化可让空间降为 O(1)。
- 栈上界 = **树深 × 每帧上界**；栈式分配的正确性前提是「数据不逃出帧」——违反即悬垂引用。
