## 为什么从窥孔优化开始

代码生成器产出的指令流往往带着「笨拙」：明明刚加载进寄存器的值又加载一遍、跳转到下一个指令的跳转、永不执行的代码。逐条看都无害，累计起来却拖慢程序。**窥孔优化（peephole optimization）** 用一个滑动的「小窗口」扫描指令序列，窗口内匹配到固定模式就做局部替换——简单、廉价、效果立竿见影。<span class="marginnote">「窥孔」的名字来自它的工作方式：只透过一个小窗看相邻的几条指令，不做全局分析。它像是「局部补丁」——任何生成器产出的笨拙，都能用窥孔规则抹掉。它通常是代码生成后的最后一道打磨，成本几乎为零，收益却稳定。</span>

## 1 窥孔优化的思想与结构

**窥孔优化**：设一个固定大小的滑动窗口（如相邻 2–3 条指令），从指令序列头部扫到尾：

1. 每次看窗口内的指令。
2. 若匹配某条**替换规则**（左边是原模式、右边是等价更优指令），则替换。
3. 窗口滑动一格，继续。

由于替换可能「暴露」新的匹配（替换后窗口内又出现可优化的模式），通常**反复扫描**直到窗口不再变化——或者用一个循环把窗口拉回，确保后效被捕捉。<span class="marginnote">「替换可能暴露新匹配」是窥孔优化的一个细节：如删掉一条跳转后，两条跳转可能相邻，又触发「跳转到跳转」规则。实现上常在替换后把窗口回退，保证连锁反应被处理完。</span>

## 2 经典规则一：冗余加载/存储消除

**冗余加载消除**：若指令序列是

```
LD  R1, x        # 加载 x 到 R1
LD  R2, x        # 第二次加载同一地址——冗余，R2 可用 R1 替代
```

第二条冗余，删除。更常见的是「加载后又被加载同一地址」——窗口里发现两次相同 `LD R, x`，删后一次。

**冗余存储消除**：

```
ST  x, R1         # 存储 R1 到 x
ST  x, R1         # 第二次写同一地址——冗余，删除
```

或者「加载后立刻存回同一地址」——值没变，整个存取都删掉。

**辨析｜易错点：** 删除前必须确认**中间没有别的指令修改 x 或寄存器**——窗口大小就是「安全性」的保证：规则只在窗口内检查，窗口内的指令都看得见，不会误删。<span class="marginnote">「窗口内的安全检查」是窥孔优化正确性的关键：规则看似大胆（删指令），但只在「小窗内已确认无副作用」时动手。这与全局优化需要数据流分析不同——窥孔用「看得见」换「敢动手」。</span>

## 3 经典规则二：不可达代码与控制流化简

**不可达代码消除**：紧跟无条件跳转之后的指令永远不会执行，可删：

```
    goto L
    x = y + z      # 不可达：goto 之后、标签之前的指令永不到达
L:  t = x * 2
```

**跳转到跳转**：

```
    goto L1
L1: goto L2         # 跳转目标又是一条跳转：可直接改为 goto L2
```

**跳转到下一指令**：

```
    goto L1
L1: x = y + z        # 跳转目标就是下一条指令：goto 整条删除
```

**控制流化简**的连锁：把 `goto L` 中 L 指到的指令直接挪进窗口内，跳转消除、基本块合并——指令流变短、分支变少。<span class="marginnote">「跳转到跳转」「跳转到下一条」这些规则加起来，能把生成器留下的「保险式跳转」全部清掉。真实编译器里窥孔优化对控制流的清理，往往让指令数下降 5%–10%，是「免费午餐」的典型。</span>

## 4 经典规则三：代数化简与强度削弱

窗口内匹配代数恒等式：

`x * 1` → `x`、`x + 0` → `x`、`x - 0` → `x`。
`x * 2` → `x + x`（或移位 `x << 1`）——**强度削弱**的窥孔版本。
常量折叠：`2 + 3` → `5`。

这些规则与基本块优化的恒等式重合，但窥孔版的优势是**作用在最终指令上**——连代码生成器刚造出来的「笨」也能抹掉。<span class="marginnote">窥孔的代数规则是「最后一道防线」：前端优化可能漏掉的代数化简，后端生成指令时可能重新引入的冗余，窥孔全部兜底。它不怕「重复劳动」——优化的正确心态是「每层都尽力，窥孔兜底」。</span>

## 5 公式解析：窥孔规则的验证

一条窥孔规则 $P \Rightarrow Q$（指令模式 P 替换为 Q）正确，当且仅当：

$$\text{对任意指令流上下文，} P \text{ 的执行效果} \equiv Q \text{ 的执行效果}$$

- **第一步，语义等价**：替换前后，程序对任意输入产生相同结果——这是正确性的唯一标准。
- **第二步，窗口前提**：P 的匹配隐含「窗口内无冲突指令」的前提（如「x 未被修改」）——前提写在规则里，窗口负责检查。
- **第三步，规模控制**：规则只认「窗口内能确认」的前提，绝不做需要全局信息才能保证的替换——这是窥孔「敢删」的安全边界。

**「每条规则都是一个小证明」**——窥孔优化的力量来自大量这种「证明过的小规则」的叠加。

## 6 小结

- **窥孔优化**用滑动窗口扫指令序列，窗口内匹配固定模式即替换——简单、廉价、稳定。
- 规则一：**冗余加载/存储消除**（删重复存取）。
- 规则二：**不可达代码消除与控制流化简**（删死代码、消间接跳转）。
- 规则三：**代数化简与强度削弱**（`x*1 → x`、`x*2 → x<<1`、常量折叠）。
- 正确性靠「**窗口内可见即敢动**」的安全边界；它是代码生成后的最后一道打磨，成本近乎为零。
