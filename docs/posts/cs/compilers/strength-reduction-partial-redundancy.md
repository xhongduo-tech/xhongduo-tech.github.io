## 为什么从强度削弱与部分冗余消除开始

循环优化再深一层，两个更精细的武器登场：**强度削弱（strength reduction）**——把「贵」的运算（乘法、除法）换成「便宜」的运算（加法、移位）；**部分冗余消除（partial redundancy elimination, PRE）**——识别「有的路径算过、有的路径没算过」的表达式，通过**提前插入**让它在所有路径上都算过一次，从而删掉重复计算。<span class="marginnote">「强度削弱」的名字很直观：运算的「强度」（执行成本）被削弱——乘法降到加法、加法降到移位。而 PRE 是 CSE 与代码外提的<strong>统一推广</strong>：CSE 处理「全部路径都算过」（可用表达式），外提处理「循环内不变」，PRE 把两者织进同一个框架。</span>

## 1 强度削弱：换便宜运算

**强度削弱（strength reduction）**：把高成本运算替换为等价但低成本运算：

整数乘法（乘以 2 的幂）→ 移位。
乘法 → 多次加法（当常量小时）。
归纳变量的寻址计算 → 每次迭代加法（循环里的强度削弱）。
除法（无符号）→ 移位（无符号时）。

**安全前提**：替换必须保持语义——溢出、舍入、除法的负数行为都要一致，所以编译器通常只对**无符号整数**做除法削弱、对**有符号整数**小心做乘法替换。<span class="marginnote">强度削弱的边界全是「语义细节」：有符号除法 `/` 与右移 `>>` 对有符号负数结果不同（向零截断 vs 向下取整），所以有符号除法削弱要先加校正项；`x * 4` 变 `x << 2` 若中间溢出会与原乘法不同。编译器宁可少做，不冒险。</span>

## 2 部分冗余：一条路径算过、一条没算过

**部分冗余表达式（partially redundant expression）**：表达式 `a + b` 在某条到达路径上**已算过**（且结果有效），但在另一条路径上**没算过**——所以 `a + b` 的重算「有的路径是多余的，有的路径是必要的」。

```text
if (c) {
    t = a + b;        // 真分支：a + b 已算过
}
y = a + b;            // 汇合点：真分支来时冗余，假分支来时必须算
```

`a + b` 在真分支已算、假分支没算——在汇合点是**部分冗余**：真分支来时白算，假分支来时必须算。

**部分冗余消除（PRE）** 的策略：把 `a + b` **提前插入假分支**（在汇合点之前先算好），使它在汇合点**所有路径**上都可用——部分冗余升级为完全冗余，于是汇合点的计算可删。<span class="marginnote">PRE 的洞察：与其「有的路径重复算」，不如「在没算过的路径上补算一次」——虽然假分支多了一次计算，但汇合点删掉一次，总账是省的（省掉真分支与汇合点的重复）。「提前插入 + 汇合点删除」是 PRE 的标准动作。</span>

## 3 PRE 的统一视野：CSE + 外提 + 插入

PRE 是一个强大的统一框架，它把三类优化纳入同一机制：

**公共子表达式消除**：表达式在**全部**路径可用（完全冗余）→ 删重算——PRE 的特例。
**代码外提**：表达式在循环内**部分**路径可用、且循环不变 → 插入到循环前——PRE 的循环版本。
**部分冗余消除本身**：部分路径可用 → 在不可用路径上插入、在汇合点删除。

PRE 的算法（龙书）基于**可用性（availability）** 与**可预期性（anticipatability）** 两个数据流分析：

**可预期**：从当前点往后，所有路径都会计算 `a + b`——「往后一定会算」。
**可用**：从入口到当前点，所有路径都算过——「往前已经算过」。

两者交汇的位置，就是「该插入/该删除」的决策点。<span class="marginnote">「可预期 + 可用」是 PRE 的两只眼睛：可预期告诉编译器「这个表达式迟早要算，不如提前算」，可用告诉编译器「这个表达式已经算过，不必再算」。把「提前算（插入）」放在可预期点、把「删重算」放在可用点——两个分析一配合，部分冗余就被整体消除。</span>

## 4 公式解析：PRE 的决策

设表达式 $e$，在点 $p$ 处：

$$\text{若 } \text{anticipat}(p, e) \land \neg \text{available}(p, e) \Rightarrow \text{在 } p \text{ 前插入计算 } e$$

$$\text{若 } \text{available}(p, e) \Rightarrow \text{在 } p \text{ 处可删 } e \text{ 的重算}$$

- **第一步，插入条件**：$e$ 可预期（往后必算）但还不可用（往前没算过）——提前算一次，让它「往后可预期」变成「这里已可用」。
- **第二步，删除条件**：$e$ 已可用——所有路径都算过，重算是冗余，删。
- **第三步，收敛**：插入使下游更可用，删除使上游更干净——迭代到不动点，全部部分冗余被消除。

**「可预期就提前、可用就删除」是 PRE 的一行决策公式**——它统一了 CSE 与外提，是全局优化的高级形态。

## 5 PRE 的收益与代价

**收益**：PRE 同时消除「完全冗余」（CSE 的活）与「部分冗余」（只靠 CSE 做不到的），还能顺带把循环不变计算外提——一个优化顶三个。

**代价**：

- 实现复杂度高：两个数据流分析 + 插入/删除 + 不动点迭代。
- 插入可能**增加代码量**（每个可预期点都插一份）。
- 副作用与别名使「可预期/可用」判定保守化，可能错失机会。

**辨析｜易错点：** PRE 的「插入」不是无条件的——只有「插入后能删除更多」才划算；若插入点太多、删除点太少，总代码量反增。真实的 PRE 实现会做**成本权衡**：只在「净收益为正」的位置插入。<span class="marginnote">现代编译器（LLVM 的 GVN 内嵌的 PRE、以及专门的 `PRE pass` 等）继承了 PRE 的思想但做了工程化妥协：用「值编号 + 支配树」实现近似的 PRE，兼顾效果与实现复杂度。理解教科书 PRE，是理解这些工业实现的钥匙。</span>

## 7 思考与练习

**练习 1 强度削弱**：把 `x * 4`、`y * 3`、`z / 8`（无符号）分别替换为更便宜的运算——并讨论「有符号除法」为什么不能直接移位（向零截断 vs 向下取整）。

**练习 2 循环内削弱**：对访问 `a[i]` 的循环，把 `a[i]` 的寻址（每次 `i * 4`）改为「地址游标每次 +4」——写出改写后的循环，数一数省了几次乘法。

**练习 3 部分冗余识别**：对 `a + b`，标出 `a + b` 的「可用」「可预期」状态——并说明为什么它是部分冗余（一条路径算过、一条没算过）。

**练习 4 PRE 决策**：用「可预期就插入、可用就删除」的公式，对练习 3 写出插入点与删除点——验证部分冗余被消除后总指令数减少。<span class="marginnote">「插入 + 删除」是 PRE 的双动作：在「不可用但可预期」的路径上<strong>插入</strong>计算（补算一次），在「可用」的汇合点<strong>删除</strong>重算——部分冗余升级为完全冗余后被消除。总账：假分支多算一次，汇合点省一次，且真分支不再重复——净省。</span>

**练习 5 与 CSE/外提统一**：解释「PRE ⊇ CSE + 代码外提」——完全冗余（全部路径可用）是 CSE 的活，循环不变的部分冗余是外提的活，PRE 一个框架全包。

**练习 6 成本权衡**：讨论 PRE 插入过多时「代码膨胀」的代价——为什么真实实现要「净收益为正才插入」。

**常见误区**：

- **误区一**：以为「强度削弱是免费的」——有符号、溢出语义会限制替换，无符号才敢大胆移位。
- **误区二**：把「部分冗余」当「完全冗余」——只有「所有路径都算过」才可直接删，部分冗余要先插入再删。
- **误区三**：忽视 PRE 的代码膨胀——插入不是无条件的好，要算净收益。

**延伸**：PRE 的「可预期 + 可用」双分析是数据流框架里最精巧的实例（两个方向的分析交汇）——把「可预期（向后）」「可用（向前）」放进数据流四象限表，与到达定值、活跃变量并排。

## 8 小结

- **强度削弱**：高价运算换低价运算（乘法→移位/加法、归纳变量 `i * 4` 寻址→每次 `addr += 4`）；边界在有符号/溢出语义。
- **部分冗余**：表达式「有的路径算过、有的没算过」——汇合点的重算部分是冗余。
- **PRE**：在「不可用但可预期」处提前插入、在「可用」处删重算——部分冗余升级为完全冗余后消除。
- PRE 用**可预期 + 可用**两个数据流分析驱动，统一了 **CSE + 代码外提 + 插入**。
- PRE 代价高（双分析 + 插入/删除），真实实现做成本权衡与工程化近似。
