## 为什么从 LR 分析器开始

移进-归约分析器有了动作框架，但还缺「决策中枢」：什么时候移进、什么时候归约、归约哪条产生式？这些决策要是写死进代码，每换一个文法就得重写一遍分析器。**LR 分析（LR parsing）** 把这套决策编码进一张**分析表**，用统一引擎驱动——表随文法变，引擎永远不变。这正是 Yacc/Bison 能「从文法生成分析器」的机制。

L 表示从左到右读输入，R 表示构造**最右推导的逆**（即规范归约）。LR 分析器能处理的文法，比 LL 更宽——几乎所有实际语言的文法都在 LR 家族的覆盖范围内。<span class="marginnote">「LR 比 LL 强」的直觉：LL 每步只看一个非终结符的开头（FIRST），而 LR 是「先把东西读进来，直到攒够一个产生式的右侧再归约」，前瞻利用更充分。工程上 Bison 默认生成 LALR，兼容性极广。</span>

## 1 总览：状态栈与两张表

LR 分析器由三件东西组成：

**状态栈**：存的是**分析器状态编号**（每个状态对应文法中一个「位置」），不是文法符号。状态栈顶的左侧另附一个**符号栈**（由移进/归约自动维护），合起来记录「当前走到了文法哪里」。
**ACTION 表**：$\text{ACTION}[s, a]$，给定当前状态 $s$ 与输入记号 $a$，决定动作——移进到哪个状态、归约哪条产生式、接受或报错。
**GOTO 表**：$\text{GOTO}[s, A]$，给定状态 $s$ 与非终结符 $A$，决定归约完成后「该跳去哪个状态」。

`ACTION` 管「对终结符的动作」，`GOTO` 管「归约后的状态迁移」——前者处理输入，后者处理归约，两者合起来才完整。<span class="marginnote">直观对应：`ACTION` 是「读字符后下一步」，`GOTO` 是「归约后下一步」。符号栈里的非终结符正是靠 `GOTO` 恢复分析方向的，所以 `GOTO` 表行数与 `ACTION` 相同、列是非终结符。</span>

## 2 LR 分析表的语义

每个动作的含义：

**移进 $s'$**：把输入记号 $a$ 压入符号栈，把状态 $s'$ 压入状态栈，输入前进。
**归约 $A \to \beta$**：从符号栈弹出 $|\beta|$ 个符号（$\beta$ 的长度），从状态栈也弹出同样个数；然后压入 $A$，查 $\text{GOTO}[\text{新栈顶}, A]$ 压入新状态。
**接受**：输入为 `$`（结束符）且当前状态指示「开始符号的完整产生式已归约」。
**报错**：表项为空。

**归约时栈顶的 $|\beta|$ 个符号，正是上一节的句柄**——LR 分析器通过查表找到句柄、执行规范归约，不用自己「找」，而是「看表」。<span class="marginnote">这就是 LR 的强大：句柄识别被编译进表里。分析器运行期只是查表 + 压栈/弹栈，机械而线性——这也是 LR 分析器与 LL 一样 O(n) 的原因。</span>

## 3 驱动算法

```
ip ← 指向输入串的第一个符号
把初始状态 s₀ 压入状态栈
repeat
    s ← 栈顶状态;  a ← ip 指向的记号
    if ACTION[s, a] = 移进 s' then
        把 a 压入符号栈、把 s' 压入状态栈;  ip 前进
    else if ACTION[s, a] = 归约 A → β then
        从符号栈与状态栈各弹出 |β| 个
        压入 A 到符号栈; 压入 GOTO[新栈顶, A] 到状态栈
    else if ACTION[s, a] = 接受 then
        返回成功
    else
        报错
until 接受或报错
```

注意归约动作**不消费输入**——它只改写栈。移进才消费输入。这个「归约不吃输入、移进才吃」的区分，是理解 LR 运行的关键。<span class="marginnote">对比 LL 预测分析器：LL 的展开会「逆序压栈」，LR 的归约是「弹出右侧、压入左侧」。两者都靠栈，但一个向下长，一个向上收。</span>

## 4 公式解析：归约动作的栈操作

把归约 $A \to \beta$（$|\beta| = k$）写成状态与符号栈的联合更新：

$$(\text{符号栈} \cdot \beta,\ \text{状态栈} \cdot s_1s_2\cdots s_k) \Rightarrow (\text{符号栈} \cdot A,\ \text{状态栈} \cdot s_1\cdots s_{j} \cdot \text{GOTO}[s_j, A])$$

- **第一步，弹出**：$\beta$ 的长度 $k$ 决定弹出 $k$ 个符号、$k$ 个状态。$j$ 是弹完后的新栈顶下标。
- **第二步，压入**：左侧非终结符 $A$ 压入符号栈；状态栈压入 $\text{GOTO}[s_j, A]$——由「归约前的历史状态」决定下一步去哪。
- **第三步，不变式**：符号栈串始终是「活前缀」——已读入部分的最右句型前缀。归约保持它，移进保持它，接受时它等于完整句型。

**GOTO 是 LR 的状态传递**：归约相当于「在已读历史里识别出一个非终结符」，之后往哪走由历史决定——这正是 LR 比 LL 更强的原因：决策基于**整个已读历史**（栈），而非单字符前瞻。

## 5 LR 分析家族一览

LR 按「状态里装多少信息」分档：

| 家族 | 状态内容 | 前瞻 | 能力 |
| --- | --- | --- | --- |
| LR(0) | 项不含前瞻 | 无 | 最弱，实践少用 |
| SLR(1) | 项不含前瞻 | 归约时查 FOLLOW | 简单，中等能力 |
| LR(1) | 项含一个前瞻符号 | 精确 | 最强，状态爆炸 |
| LALR(1) | LR(1) 合并同心项 | 折中 | 能力逼近 LR(1)，状态数如 SLR |

**LR(k)** 泛指「前瞻 k 个记号」；LR(1) 是理论主流，LALR(1) 是工程主流。<span class="marginnote">语言「每个 LR(1) 文法都存在等价的 LALR(1) 文法」这句不成立——LALR 严格弱于 LR(1)。但对真实语言，LALR 几乎从不掉链子，Yacc 的默认配置就是 LALR。后续几篇逐一展开这些状态构造法。</span>

## 6 一次完整的手工运行

把驱动算法走在一台具体的小表上。文法 $S \to a\,S\,b \mid \varepsilon$，输入 `a a b b`。

**关键状态**：设状态 0 是初始态。部分 ACTION/GOTO（示意）：
- ACTION[0, a] = 移进 1；ACTION[1, a] = 移进 1；状态 1 在 b 处归约 $S \to \varepsilon$……

**手工轨迹（简化）**：
1. 状态 0 见 a → 移进（符号栈 [a]，状态栈 [0,1]）。
2. 状态 1 见 a → 移进（符号栈 [a,a]，状态栈 [0,1,1]）。
3. 状态 1 见 b → 查表：归约 $S \to \varepsilon$（弹 0 个符号，压 S，查 GOTO）。
4. 依表继续…… 每步「查 ACTION → 移进或归约」，直到接受。

**要点**：这个例子的每一行都可以「查表 + 压弹」机械复现——分析器不知道文法的语义，只按表执行。这张表就是「文法 + 冲突消解」的全部智慧的固化。<span class="marginnote">「分析器不懂文法、只懂表」正是 LR 生成器（Yacc）的工作方式：<strong>文法在编译期被编译进表里，运行期的分析器是「无文法知识」的查表机器</strong>。这带来一个好处：换文法只需重新生成表，分析器代码一行不改——「表驱动」让编译器前端与文法解耦。</span>

**辨析｜易错点：** 归约 $S \to \varepsilon$ 时 $|\beta| = 0$——**弹 0 个符号**。别被「弹出 $|\beta|$ 个」误导成「至少弹一个」；ε 产生式的归约只压入 S、不弹任何符号。空产生式是 LR 分析里最易错的特例。

## 7 思考与练习

**练习 1 手工运行 LR**：给定一张 4 状态的 ACTION/GOTO 表，手工走完 `id + id * id` 的分析——每步记录「状态栈、符号栈、输入、动作」，特别标出归约时「弹出 $|\beta|$ 个、查 GOTO」。

**练习 2 ACTION vs GOTO**：解释为什么「移进查 ACTION、归约后查 GOTO」——两个表各回答什么问题？若把 GOTO 错误地并进 ACTION（对非终结符查 ACTION），会发生什么？

**练习 3 归约不消费输入**：在练习 1 的轨迹中，找出「归约动作发生时输入没动」的证据——为什么归约不消费输入？提示：归约改写的是栈（把右侧换成左侧），不是读入。<span class="marginnote">「归约不消费输入」是 LR 与 LL 的一个关键差异：LL 的展开「把产生式压栈」、LR 的归约「把右侧换成左侧」——两者都不动输入指针；只有「移进」（LL 的匹配）才消费。想通这一点，两种算法的驱动循环就都对上了。</span>

**练习 4 句柄的栈顶性**：论证「LR 归约的句柄一定在栈顶」——为什么 LR 不用「在栈中搜索句柄」？提示：活前缀不变式保证句柄不越过栈顶。

**练习 5 四表对比**：把 LR(0)、SLR、LR(1)、LALR 的「状态内容」「前瞻来源」列成一张对照表，标出「为什么 LR(1) 最准、LALR 折中」。

**练习 6 栈的三种内容**：状态栈、符号栈、语义栈（Bison 的 value stack）三者的同步关系——为什么状态栈与语义栈「同进同出」？提示：一次移进/归约，三个栈各动一次。

**延伸**：LR 分析表的「表驱动」与第十三节 LL 的表驱动、第七节词法的 DFA 表——三张表都回答「状态 × 输入 → 动作」。把三张表的结构画在一起，总结「表驱动编译」的通用模式。

## 8 小结

- **LR 分析器** = 状态栈 + 符号栈 + ACTION 表 + GOTO 表；追踪最右推导的逆（规范归约）。
- **ACTION** 管终结符（移进/归约/接受/报错），**GOTO** 管非终结符（归约后的状态迁移）。
- 归约动作**不消费输入**，只弹 $|\beta|$ 个符号/状态、压入 $A$ 与 $\text{GOTO}$ 值；移进才消费输入。
- 不变式：符号栈始终是**活前缀**，决策基于整个已读历史——这是 LR 强于 LL 的根源。
- 家族谱系：LR(0) ⊂ SLR ⊂ LALR ⊂ LR(1)（按能力）；工程默认 **LALR(1)**。
