## 为什么从数组寻址的翻译开始

声明翻译给了每个变量一个偏移量，但数组的访问 `a[i]` 有一个「活的下标」：它的地址不固定，要运行时算。把 `a[i]` 翻译成「取地址 + 偏移」的三地址码，是中间代码生成里最有代表性的「地址计算」问题——它把语言层的下标抽象，降维成机器层的乘法与加法。<span class="marginnote">数组寻址是「语言的便利」与「机器的朴素」之间的桥梁：程序员写 `a[i][j]`，编译器得把它展开成 `基址 + (i×行宽 + j)×元素宽` 的算术序列。理解这段翻译，也就能理解为什么 C 数组下标从 0 开始（省一次减法）、为什么行优先/列优先会影响性能。</span>

## 1 一维数组：基址加偏移

一维数组 `A[10]`，元素宽度 `w`，基址（首元素地址）为 `base`。元素 `A[i]` 的地址：

$$\text{addr}(A[i]) = base + i \times w$$

翻译成三地址码（用临时变量）：

```
t1 = i * w          # 下标 × 元素宽
t2 = base + t1      # 基址 + 偏移
```

`t2` 就是元素地址；若是读，`x = t2` 的内容要再 `x = *t2`；若是写，`*t2 = y`。

**边界检查**：若语言规定下标越界是错误（Java、Rust），翻译还要加：

```
if i < 0 or i >= 10 goto 越界处理
```

**辨析｜易错点：** 下标从 0 开始的语言，偏移恰好是 `i×w`；若从 1 开始（Fortran、Pascal 默认），偏移是 `(i - lower)×w`——多一次减法。从 0 开始不是美学选择，是「少算一步」的工程优化。<span class="marginnote">「下标从 0 开始省一次减法」看似微小，却是编译器在热路径上斤斤计较的典型：每次数组访问少一条指令，在密集循环里就是实打实的性能。这就是为什么现代语言几乎清一色从 0 开始。</span>

## 2 二维数组：行优先的线性化

二维数组 `A[10][20]` 在内存里是**线性**的（一行接一行，行优先）。设元素宽 `w`、每行 `n` 个元素，`A[i][j]` 的地址：

$$\text{addr}(A[i][j]) = base + (i \times n + j) \times w$$

翻译步骤：

```
t1 = i * n          # i 行偏移（元素个数）
t2 = t1 + j         # 加上列下标
t3 = t2 * w         # 乘元素宽得字节偏移
t4 = base + t3      # 最终地址
```

**行优先（row-major）** 意味着「第 i 行从 `base + i×n×w` 开始，行内再偏 j」——C、Python、Java 都如此；**列优先（column-major）** 则调换 i、j 的角色，Fortran、MATLAB 如此。<span class="marginnote">行优先与列优先不只是内存布局的癖好，它决定遍历顺序的性能：行优先下「按行遍历」连续访存、缓存友好，按列遍历则跳跃。编译器无法改变布局，但能按布局优化遍历——这是后端「循环分块」优化的基础。</span>

## 3 更一般的翻译：地址计算的两段式

对任意维数组 `A[i1][i2]...[ik]`，龙书给出两段式翻译：**先算「相对于基址的偏移」，再「加基址」**。关键优化是**归纳出公共子表达式**：高维下标的地址计算里有大量可复用的中间量。

$$\text{addr} = base + ((\cdots((i_1 \times n_1 + i_2) \times n_2 + i_3) \cdots) \times w$$

每一步 `×(行宽) + 下标` 可复用一个临时变量链。翻译器生成指令时，**不必每个下标单独算**——像 `A[i][j]` 里 `i*n` 若在循环内不变，可以提到循环外（这是第八篇「代码外提」的雏形）。

**一个 SDD 视角**：数组访问的翻译可以写成「左值地址」的综合属性——`E.addr`（名字）与 `E.offset`（偏移量）分离，读用 `*(E.addr + E.offset)`，写同理。这套「地址 + 偏移」的双属性设计，是数组翻译的标准姿势。<span class="marginnote">「地址与偏移分离」的价值在结构体、指针运算里反复出现：`p->f` 是 `p` 的地址加字段 `f` 的固定偏移；`a[i].f` 是数组偏移加字段偏移。编译器的内存布局翻译，处处是「基址 + 偏移」的二分法。</span>

## 4 公式解析：地址计算的归纳

把 k 维数组寻址写成一递推：设 $P_0 = base$，则

$$P_m = P_{m-1} \times n_m + i_m \quad (m = 1..k), \qquad \text{addr} = P_k \times w$$

- **第一步，维内递推**：$P_m$ 表示「前 m 个下标已折算成元素数」——第 $m$ 维的上一步结果乘「该维行宽 $n_m$」，加当前下标 $i_m$。
- **第二步，收尾乘宽**：所有维度折算完，$P_k$ 是「相对首元素偏移几个元素」，乘元素宽 $w$ 得字节偏移。
- **第三步，翻译策略**：$P_m$ 每步一个临时变量，可顺序生成；若某维下标在循环中不变，$P_m$ 可提出循环。

**这条递推把「数组下标」压缩成「一组乘加指令」**，也让编译器能精确回答「数组访问的代价」——几条指令、几个临时变量，尽在掌握。

## 5 数组寻址与优化、代码生成的衔接

数组寻址的翻译不是终点，它与后端的几个机制直接对接：

- **强度削弱**：循环内 `A[i]` 的地址若随 `i` 每次加 `w`，可以把「乘法」变成「每次自加 w」——第八篇的强度削弱专门优化这种模式。
- **寄存器分配**：`base`、`i`、`w` 这些值若能留寄存器，数组访问少几次访存。
- **公共子表达式**：`A[i][j]` 与 `A[i][j+1]` 共享 `i*n + j` 的公共部分。

**重点是**：数组寻址的「乘加序列」是优化器的富矿——几乎所有经典优化（强度削弱、代码外提、CSE）都能在数组访问上找到用武之地。<span class="marginnote">这也是为什么「循环 + 数组」是性能分析的经典场景：`for(i) A[i] = f(A[i])` 的地址计算若被优化干净，比手写指针还快；若没优化，慢十倍不止。理解了数组寻址，你就理解了性能优化的第一批靶心。</span>

## 6 小结

- **一维数组**地址 = `base + i × w`；翻译成「乘法 + 加法」两条指令，可加边界检查。
- **二维数组**行优先线性化：`base + (i×n + j) × w`；行/列优先决定遍历性能。
- 通用 k 维寻址用**两段式递推**：维内 `P_m = P_{m-1}×n_m + i_m`，收尾 `×w` 得字节偏移。
- 翻译用「**地址 + 偏移**」双属性（`addr`/`offset`），读 `*(addr+offset)`、写同构。
- 数组寻址的乘加序列是**强度削弱、代码外提、CSE** 等优化的经典富矿。
