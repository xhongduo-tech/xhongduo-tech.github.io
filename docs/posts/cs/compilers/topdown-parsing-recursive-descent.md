## 为什么从递归下降分析开始

前面几篇完成了文法的「整形」：消除二义、去左递归、提取公因子。现在问题变成——**给定一个记号串，如何高效地找到它的语法分析树？** 答案分两大阵营：自顶向下与自底向上。

**自顶向下分析（top-down parsing）** 从开始符号 $S$ 出发，反复用产生式「向下展开」，让树从根长到叶，直到叶子正好覆盖整个输入。它的执行路径正好是一条**最左推导**的镜像。**递归下降分析（recursive descent parsing）** 是自顶向下最直接、也最广泛使用的实现：**每个非终结符对应一个函数，产生式右侧对应函数体里的调用序列**——文法是什么形状，代码就长什么样。<span class="marginnote">递归下降是「文法即代码」的极致体现：改写一条产生式，就是改一段函数。它极好写、极好懂、错误信息可定制，所以 GCC、Clang、rustc 的手写前端都大量使用它。工业界的默认选择，不是教材里的神话算法，而是这棵朴素的递归树。</span>

## 1 自顶向下的总体思路

自顶向下分析维护一个「已匹配前缀 + 待匹配后缀」的视图。初始时整句待匹配，从 $S$ 开始；每一步，盯着待匹配串**最左边**的非终结符 $A$，用某条产生式 $A \to X_1\cdots X_k$ 替换它，然后把 $X_1\cdots X_k$ 与输入对照：终结符必须恰好等于当前输入记号，非终结符继续展开。<span class="marginnote">「最左边」这个细节定义了自顶向下 = 追踪最左推导。读者可以在纸上对 $A$ 手工走一遍：每一步只动最左非终结符，输入指针只会往前。</span>

核心挑战在于**选择哪条产生式**：

- 若有多个候选 $A \to \beta_1 \mid \beta_2$，必须决定用哪个。
- 若选错，需要**回溯（backtracking）**：撤销已经吃进去的输入，换个候选重试。
- 回溯昂贵且指数级，于是我们想要「一选就对」——这需要前瞻（lookahead）。

## 2 递归下降分析器：文法翻译成函数

对改写后的文法

$$\begin{aligned} E &\to T\,E' \\ E' &\to +T\,E' \mid \varepsilon \\ T &\to F\,T' \\ T' &\to \times F\,T' \mid \varepsilon \\ F &\to (E) \mid \textbf{id} \end{aligned}$$

递归下降分析器长这样（伪码）：

```text
function E()  { T(); E_prime(); }
function E_prime() {
    if (lookahead == '+') { match('+'); T(); E_prime(); }
    // 否则默认 ε：什么都不做，直接返回
}
function T()  { F(); T_prime(); }
function T_prime() {
    if (lookahead == '*') { match('*'); F(); T_prime(); }
    // 否则默认 ε
}
function F() {
    if (lookahead == '(') { match('('); E(); match(')'); }
    else if (lookahead == id) { match(id); }
    else error();            // 当前记号不属于任何候选
}
```

**要点**：每个函数开头先「看」当前记号（前瞻一个 token），据此决定走哪条候选；ε 候选意味着「什么都不匹配也行」，函数直接返回。<span class="marginnote">上面的 `if` 分支就是「候选选择」的实现：看到 `+`（或 `*`）就走递归分支，否则默认 ε。这个「看一眼再决定」的动作，正是下一节 FIRST 集 / FOLLOW 集要做数学化的东西。</span>

## 3 预测分析：不用回溯的诀窍

**预测分析（predictive parsing）** 指不用回溯的自顶向下分析：任何时候，只凭当前记号就能唯一决定产生式。递归下降 + 足够的改写 = 预测分析器。

条件是**候选可区分**：对 $A \to \beta_1 \mid \beta_2$，$\beta_1$ 与 $\beta_2$ 能「开头的记号集合」必须不相交；若某个 $\beta_i$ 能导出 ε，则还要它与「$A$ 之后可以出现的记号」不相交。这两套集合正是 **FIRST 集与 FOLLOW 集**，下一节专门计算。

**辨析｜易错点：** 递归下降 ≠ 预测分析。带回溯的递归下降也是递归下降，但它最坏指数时间。预测分析是「能承诺单次选择」的递归下降——两者的分界线，就是 FIRST/FOLLOW 集算出来的「能否一选就中」。<span class="marginnote">这也解释了一种常见困惑：为什么教材既讲递归下降又讲 LL(1)？递归下降是实现方式，LL(1) 是「文法满足单字符前瞻可预测」的性质。递归下降的代码人人会写，但要证明它「不需要回溯」，得靠 LL(1) 分析表。</span>

## 4 公式解析：候选选择的判据

对非终结符 $A$，候选 $\beta_1, \ldots, \beta_n$，预测分析能「看一眼」选择，需满足：

$$\text{FIRST}(\beta_i) \cap \text{FIRST}(\beta_j) = \emptyset \quad (i \neq j)$$

$$\text{且若 } \beta_i \Rightarrow^* \varepsilon \text{，则 } \text{FIRST}(\beta_j) \cap \text{FOLLOW}(A) = \emptyset \quad (j \neq i)$$

- **第一步，可区分**：$\beta_i$ 与 $\beta_j$ 各自由什么记号开头。若两候选可能开头的记号有重叠，读到那个记号时无法分辨。
- **第二步，ε 的特殊性**：能导出 ε 的候选可以「不匹配任何东西」。于是它什么时候被选？当前记号不属于任何非 ε 候选、但属于 FOLLOW($A$)（$A$ 后面该出现的记号）时——此时选 ε 候选「放 $A$ 过去」，把位置让给下一个非终结符。
- **第三步，LL(1) 条件**：这两条同时满足的文法叫 **LL(1) 文法**。第一个 L 表示「从左到右读输入」，第二个 L 表示「产生最左推导」，1 表示「前瞻一个记号」。它保证预测分析器线性时间、无回溯。

**这两条判据是整个自顶向下体系的检验标准**：文法改写（去左递归、提公因子）的最终目的，就是让这两个交集全部为空。

## 5 递归下降的工程化

真实编译器里的递归下降，比教材伪码更复杂也更强大：

- **错误恢复**：手写函数可以打印精确的错误信息，用「同步记号」跳过错误段，继续分析——这是自动生成分析器难做到的人性化。
- **运算符优先级爬升（precedence climbing / Pratt parsing）**：表达式常用「优先级表 + 循环」而非深层递归实现，代码更紧凑、错误信息更好。
- **左递归的绕过**：手写分析器可以用循环模拟左递归的语义（如表达式左结合），而不必先把文法改写掉——Clang 就是这样处理表达式的。

**重点是**：递归下降的「慢」在工程上并不成立——它线性时间、内存少、可读可调，所以成了现代编译器前端的主流。<span class="marginnote">值得留意：递归下降是「人写」的，Yacc/Bison 是「生成」的。人写的好处是自由与错误信息质量，坏处是文法正确性全凭自觉；生成的好处是文法即规范，坏处是错误信息又臭又硬。两种路线至今并存。</span>

## 7 思考与练习

**练习 1 手写递归下降**：为文法 $E \to T E'$、$E' \to +T E' \mid \varepsilon$、$T \to \textbf{id}$ 手写递归下降分析器的伪代码（三个函数），并用手工走完 `id + id` 的调用过程，标出每次 `match` 与递归调用。

**练习 2 回溯演示**：对文法 $S \to aAd \mid aB$、$A \to c$、$B \to d$，用手工走「带回溯」的自顶向下分析处理 `ad`——先试 $aAd$ 失败，回溯换 $aB$ 成功。标出「回溯点」与「浪费的匹配」。

**练习 3 预测 vs 回溯**：对练习 2 的文法，用「提取左公因子」改写（$S \to aA'$、$A' \to Ad \mid B$），说明改写后为什么不再需要回溯——把「试错」变成「看首记号直接选」。

**练习 4 ε 分支**：在 `E_prime()` 里，为什么「当前记号不是 `+`」时选择 ε 候选？若当前记号是 `$`（属于 FOLLOW($E'$) 吗？），手动推演一遍——这是「ε 兜底」的机制。

**练习 5 栈与递归的对应**：把练习 1 的递归调用序列画成「调用栈的压弹」，对比第十三节「表驱动分析器的记号栈」——两者是不是同一棵最左推导的两种执行？<span class="marginnote">「递归调用栈 vs 显式记号栈」的对应是理解自顶向下的一条暗线：递归下降用「程序调用栈」隐式管理推导位置，表驱动用「显式栈」管理——执行路径（最左推导）完全相同。看懂这个对应，两节就连成一体了。</span>

**练习 6 错误信息**：给练习 1 的分析器加错误恢复——在 `match` 失败时打印「期望 X 得到 Y」并跳到同步记号。对比第八十四节 ToyLang 的同步策略。

**延伸**：递归下降在 Clang、rustc 里是手写的主力——读一段 Clang 的 `ParseExpr.cpp` 开头，找「一个非终结符一个函数」的实证，把本节的抽象对应到工业代码。

## 8 小结

- **自顶向下分析**从 $S$ 出发向下展开树，追踪**最左推导**；核心问题是「选哪条产生式」。
- **递归下降分析**让每个非终结符对应一个函数，产生式对应调用序列，**文法即代码**。
- **预测分析** = 无回溯的自顶向下，靠「看一眼」当前记号唯一确定候选。
- 可预测的条件：候选的 **FIRST 集两两不相交**，ε 候选再对 **FOLLOW 集**避让——合起来就是 **LL(1) 条件**。
- 工程上递归下降以**错误信息质量高、可调可控**取胜，是现代编译器手写前端的主流。
