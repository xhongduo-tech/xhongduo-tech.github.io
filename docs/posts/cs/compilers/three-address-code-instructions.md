## 为什么从三地址码指令类型开始

三地址码是「每行三个地址」的线性 IR，但「三个地址」具体有哪些指令？怎么在内存里表示？这两问决定后续优化与代码生成的难易。本节先把指令类型归成几个小家族，再看两种经典存储结构——**四元式**与**三元式**——各自的取舍。<span class="marginnote">指令类型是「IR 的词汇表」，表示结构是「IR 的语法」——词汇决定了优化器能识别哪些操作，结构决定了改指令（如删冗余、重排）是否容易。两者一起构成三地址码的完整形态。</span>

## 1 三地址码的指令家族

三地址指令按功能分成几个家族，几乎覆盖结构化程序的全部运算：

**赋值与运算**：
二元：`x := y op z`（`+`、`-`、`*`、`/` 等）
一元：`x := op y`（`uminus`、`!` 等）
复制：`x := y`

**控制流**：
无条件转移：`goto L`
条件转移：`if x relop y goto L`（`x relop y` 为真时跳转）

**数据结构访问**：
数组：`x := y[i]`、`x[i] := y`
指针：`x := *y`、`*x := y`

**过程调用**：
`param x`（传参）
`call p, n`（调用，n 为参数个数）
`return y`（返回）

地址 `x` 可以是**名字**（指向符号表条目）、**常量**（字面值）或**编译生成的临时变量**（如 `t1`）。<span class="marginnote">这六类指令是「最小但完整」的：任何结构化程序都能翻译成它们。把指令家族固定下来，优化器和后端只需认识这些形态，不必理解源语言——这是 IR 作为「契约」的核心价值。</span>

## 2 四元式：指令的「四字段」表示

**四元式（quadruple）** 用四个字段表示一条指令：

$$(\text{op},\ \text{arg}_1,\ \text{arg}_2,\ \text{result})$$

- `op`：运算符。
- `arg1`、`arg2`：操作数（可为空，如一元运算与复制指令）。
- `result`：结果存放处（临时变量或名字）。

例如 `a = b * -c + b * -c` 的四元式序列：

| # | op | arg1 | arg2 | result |
| --- | --- | --- | --- | --- |
| 0 | uminus | c | - | t1 |
| 1 | × | b | t1 | t2 |
| 2 | uminus | c | - | t3 |
| 3 | × | b | t3 | t4 |
| 4 | + | t2 | t4 | t5 |
| 5 | := | t5 | - | a |

**四元式的优点**：每个结果都有名字（`result` 字段），重排指令、删除指令时**无需修改其他指令**——这是优化器最看重的性质。<span class="marginnote">「有显式结果」让四元式成为优化的舒适区：把第 4 条换成 `+ t2 t2 t5`（若知 t3==t1）只是改一条指令，不影响旁处。对比三元式你会发现，这个「显式 result」是根本差异。</span>

## 3 三元式与间接三元式

**三元式（triple）** 只用三个字段，**结果不显式命名**：

$$(\text{op},\ \text{arg}_1,\ \text{arg}_2)$$

结果「就是这条指令的位置」——需要结果时，用「指向三元式数组下标的指针」来引用。例如 `a = b * -c + b * -c`：

| # | op | arg1 | arg2 |
| --- | --- | --- | --- |
| 0 | uminus | c | - |
| 1 | × | b | (0) |
| 2 | uminus | c | - |
| 3 | × | b | (2) |
| 4 | + | (1) | (3) |
| 5 | := | (4) | a |

`(0)` 表示「第 0 条指令的结果」。**三元式省了临时变量名**，但代价很大：**移动或删除一条指令，所有引用它的地方都要改**——因为结果是通过「数组下标」隐式引用的。<span class="marginnote">「三元式的重排灾难」是经典的编译课陷阱：把第 0 条 `uminus c -` 挪走，第 1、3 条的 `(0)`、`(2)` 引用就全错了。所以优化器几乎不用朴素三元式——除非升级成间接三元式。</span>

**间接三元式（indirect triple）** 在三元式外加一张**指针表**：三元式存内容，指针表存「指向第几条」的引用。改内容不动指针、删内容改指针——既保留了三元式的紧凑，又恢复了四元式的可重排性。

## 4 公式解析：三种表示的等价与取舍

三种表示都在编码同一条指令 `a = b * -c + b * -c`，差别只在「结果如何被引用」：

$$\text{四元式}: (\text{op}, y, z, x) \quad \text{三元式}: (\text{op}, y, z) \quad \text{结果} = \text{指令下标}$$

- **第一步，显式 vs 隐式结果**：四元式给结果一个**名字**（`a` 或临时变量），三元式用**指令下标**代替——前者独立，后者绑定位置。
- **第二步，引用方式**：四元式里想用「上次运算的结果」，直接写结果名；三元式写 `(n)`（指向上一条指令的下标）——这是对「数组下标」的引用。
- **第三步，优化代价**：四元式删一条指令，旁处引用名不变；三元式删一条，所有 `(n)` 引用可能错位。间接三元式用指针解绑，兼顾两者。

**结论**：**可重排性（优化友好）优先 → 四元式或间接三元式；空间紧凑优先 → 朴素三元式。** 现代编译器几乎都选「显式结果 + 名字」的形态（LLVM IR 即其现代版）。

## 5 从四元式到静态单赋值

四元式的「显式结果」思想在现代 IR 里被推到极致：**SSA（static single assignment）**——每个变量只赋值一次，每次赋值得到一个新名字。

$$t_1 = y \times z, \qquad t_2 = t_1 + 1, \qquad x = t_2$$

SSA 是四元式 + 「单赋值」约束：它让「变量的定义与使用」关系变成**唯一的**，优化器能直接看出一个值何时被覆盖、哪些使用共享同一版本。LLVM IR 就是 SSA 形态的三地址码。<span class="marginnote">四元式 → SSA 的演进脉络：显式结果（四元式）→ 结果唯一（SSA）。「每个结果有名字」从「方便重排」升级为「可证明正确优化」的基石，这就是为什么第十一篇的 LLVM IR 如此强大——它的基础是几十年前四元式思想的现代化。</span>

**辨析｜易错点：** 三地址码不是「源语言的逐行翻译」——它是「表达式摊平成指令」，可能比源语句数多得多。一个数组访问（如 `a[i] = b*c`）会展开成数组地址计算 + 乘法 + 存储多条指令。「指令数 ≈ 原子运算数」，而非「语句数」。

## 6 小结

- 三地址指令六大家族：**运算、复制、转移、数组/指针、过程调用**，覆盖结构化程序全部运算。
- **四元式** `(op, arg1, arg2, result)`：结果显式命名，删改指令不影响旁处，**优化友好**。
- **三元式** `(op, arg1, arg2)`：结果 = 指令下标，紧凑但**重排灾难**；间接三元式用指针表解绑。
- 表示选择：优化优先用四元式/间接三元式，空间优先用朴素三元式。
- 四元式的「显式结果」思想演化为 **SSA**（静态单赋值），是 LLVM IR 等现代 IR 的基石。
- **走查对照**：同一 `a=b*-c+b*-c` 用四元式/三元式/间接三元式三种表示并排，差别只在「结果如何被引用」——显式名字 vs 指令下标 vs 指针表。
