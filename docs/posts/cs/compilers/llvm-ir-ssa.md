## 为什么从 LLVM IR 开始

三段式架构的「契约」就是 **LLVM IR**——一门虚拟指令集，既是前端的目标，也是后端的输入。它最独特的属性是 **SSA 形式（static single assignment）**：每个变量只赋值一次。这个「自缚手脚」的约束，让数据流关系变得**显式**——优化器不再需要「到达定值分析」去猜谁定义了谁，看 IR 就知道。SSA 是 LLVM 优化的根基，也是它区别于传统三地址码的灵魂。<span class="marginnote">「SSA 的每个变量只有一个定值」=「数据流图直接写在 IR 里」：`%1 = add %a, %b` 之后，所有使用 `%1` 的地方都<strong>必然</strong>是这个加法的结果——定义与使用关系 1:1，优化器无需分析即可追踪。这是 SSA 让 CSE、常量传播等优化「退化」成简单遍历的原因。</span>

## 1 LLVM IR 的三层形态

LLVM IR 有**三种等价表示**，同一程序三种形态：

| 形态 | 载体 | 用途 |
| --- | --- | --- |
| 文本 IR | `.ll` 文件 | 人类可读、调试 |
| 位码（bitcode） | `.bc` 文件 | 序列化、跨工具传递 |
| 内存 IR | 编译器内存对象 | 优化器/后端操作的对象模型 |

三种形态**语义完全一致**，可互相转换：`llvm-as`（文本 → 位码）、`llvm-dis`（位码 → 文本）、`opt`（读入 IR 跑 pass）。

**类型系统**：LLVM IR 是**强类型**的——`i32`（32 位整数）、`float`、`ptr`（指针）、数组、结构体、向量。类型让 IR 自含「宽度/运算语义」，后端不需要猜。<span class="marginnote">「三层形态」让 LLVM IR 既适合机器处理（位码/内存对象）也适合人类阅读（文本）——这是工程设计的体贴：编译器的开发者用 `clang -emit-llvm -S` 导出文本 IR 观察优化前后，教学与调试都靠它。强类型则让 IR 既是「汇编」又是「带类型的中间语言」——后端选指令时类型直接可用。</span>

## 2 SSA 形式：每个变量只赋值一次

**SSA（static single assignment）** 的两个规则：

1. **每个变量只被赋值一次**——赋值后变量名不可复用。
2. 使用变量时，它的值就是那次唯一赋值的值。

传统代码：

```
x = 1
x = x + 2        # x 被赋值两次
y = x * 3
```

SSA 化：

```
x1 = 1
x2 = x1 + 2      # 新名字 x2
y1 = x2 * 3
```

每次赋值产生**新名字**（版本号），值的历史被编码进名字。优化器看到 `x2` 就知道它是 `x1 + 2` 的结果——无需「到达定值分析」。

**SSA 的红利**：常量传播、CSE、死代码消除、复写传播都变成「沿 use-def 链走」的简单遍历——第八篇需要数据流方程的分析，在 SSA 下大多**免费**。<span class="marginnote">「SSA 让数据流分析免费」是它的最大卖点：传统 IR 里「x 当前的值来自哪条路径」要跑不动点分析；SSA 里直接看 `x` 的<strong>唯一定值</strong>即可。代价是变量名爆炸（每次赋值新名）——但这是「用名字换分析成本」的划算交易。LLVM 的全部优化 pass 都建立在「use-def 链」之上。</span>

## 3 φ 函数：处理控制流的汇合

SSA 的一个难题：**控制流汇合**时，变量可能来自不同分支——它该是哪个值？例：

```
if (c) x = 1; else x = 2;
y = x + 3;
```

SSA 化时，汇合处的 `x` 有两个可能的定值（`x1 = 1` 或 `x2 = 2`）——SSA 用 **φ（phi）函数**表达「按到达路径选择」：

```
if c goto L1 else goto L2
L1: x1 = 1; goto L3
L2: x2 = 2; goto L3
L3: x3 = φ(x1, x2)    # 来自 L1 则取 x1，来自 L2 则取 x2
y1 = x3 + 3
```

φ 函数是「伪指令」：它不计算，只按「当前是从哪个前驱进入」选择参数。它让「汇合处的一个变量」在 SSA 里也有唯一的定义（那个 φ）。<span class="marginnote">「φ 函数是 SSA 处理汇合的缝衣针」：它把「多个可能的定值」缝成一个逻辑定值。实现时 φ 不是真指令，而是「合并点」的标记——后端在寄存器分配时把 φ 实现为「按前驱移动值」。理解 φ，就理解了 SSA 为什么能覆盖任意控制流。</span>

## 4 公式解析：φ 的插入位置——支配边界

φ 函数该插在哪？答案是**支配边界（dominance frontier）**：

$$\text{DF}(n) = \{m \mid n \text{ 支配 } m \text{ 的某前驱，但 } n \text{ 不支配 } m\}$$

- **第一步，语义**：$m$ 在 $n$ 的支配边界上，意味着「从 $n$ 出发的支配在这里失效」——某个分支绕过 $n$ 到达了 $m$。
- **第二步，为何插 φ**：变量 $x$ 在 $n$ 定值，凡是在 $n$ 的支配边界上的汇合点，$x$ 都可能「来自 $n$ 或来自别处」——必须插 φ 表达「按路径选值」。
- **第三步，构造**：算所有定值点的支配边界，沿边界插入 φ，再重命名变量（每次赋值新版本）——这就是标准 SSA 构造（Cytron 算法）的核心。

**「支配边界 = φ 的必插点」是 SSA 构造的地基**——支配树（第五十九节）在此派上大用场。

## 5 LLVM IR 的其他关键设计

- **基本块**：`label:` 标记，块内指令顺序执行，块尾是终结指令（`br`/`ret`/`switch`）。
- **指令格式**：`%result = op i32 %a, %b`——类型显式标注（`i32`）。
- **全局变量与常量**：`@g = global i32 0`；常量 `constant`。
- **函数**：`define i32 @f(i32 %x) { ... }`。
- **无类型指针 `ptr`**：LLVM 的指针不带元素类型（`ptr`），类型信息在 load/store 指令上——这让别名分析更灵活。

**重点是**：LLVM IR 是「SSA + 强类型 + 显式控制流」的三地址码现代版——第五篇的四元式思想，在这里长成了工业标准。<span class="marginnote">「无类型指针 ptr」是 LLVM 的设计反转：传统 C 的 `int*`/`char*` 把「指针」与「所指类型」绑定，LLVM 把它们分开——指针就是地址，类型只在访问（load/store）时给出。这让别名分析、类型擦除（C 的 `void*`）都更自然，也是 LLVM 能同时服务 C、Rust、Swift 的秘诀之一。</span>

## 6 小结

- **LLVM IR** 有三种形态（文本/位码/内存对象），强类型、语义一致、可互相转换。
- **SSA 形式**：每个变量只赋值一次——使用-定义关系 1:1，数据流分析「免费」。
- **φ 函数**处理控制流汇合：按进入路径选择值——SSA 覆盖任意控制流的缝衣针。
- φ 插在**支配边界**（Cytron 算法）：支配树 + 支配边界是 SSA 构造的地基。
- LLVM IR = **SSA + 强类型 + 显式控制流**的三地址码现代版，是「契约」IR 的工业标准。
