## 为什么从复写传播与死代码消除开始

程序里到处都是**复写语句（copy statement）** `x = y`——中间变量、临时变量、为清晰而写的别名。复写本身廉价，但它制造了「两个名字、一个值」的冗余：`x` 只是 `y` 的别名，使用 `x` 的地方其实都能直接用 `y`。**复写传播（copy propagation）** 消除这层别名；而传播之后，原来的复写语句往往变成**死代码**——于是**死代码消除（dead-code elimination, DCE）** 接棒清理。两兄弟配合，是优化流水线里「先传播、后清理」的标准动作。<span class="marginnote">「先传播后清理」是一个经典配对：复写传播把 `x = y` 的使用点全部替换成 `y`，随后 `x = y` 自己变成「定义却无人用」的死代码，DCE 删掉它。一个优化创造的工作，正好由下一个优化收尾——优化器的 pass 编排常常利用这种「互补」。</span>

## 1 复写语句与传播

**复写传播**：若 `x = y` 是 `x` 在某个点的**唯一到达定值**（且 `y` 在那之后未被重新赋值），则 `x` 的读取可替换为 `y`：

```
x = y
a = x + 1     →   a = y + 1
```

- 替换后，`x = y` 若再无人使用 `x`，就成了死代码。
- 传播的收益：**减少寄存器压力**（少一个活跃变量）、**为后续优化开路**（`y + 1` 可能触发 CSE、常量折叠）。

**安全前提**：`x = y` 是 `x` 的**唯一**到达定值，且沿路径 `y` 未被改写。<span class="marginnote">「唯一到达定值」这条前提使复写传播可以用到达定值分析实现：检查使用点的 `x` 是否只有一个到达定值、且它形如 `x = y`。这与常量传播的「所有路径一致」是同一族条件——都是「唯一/一致才安全」。</span>

## 2 复写传播的实现

用到达定值分析实现复写传播的朴素流程：

1. 对每个点算 `x` 的到达定值。
2. 若读取 `x` 处的唯一到达定值是 `x = y`，把该读取替换为 `y`。
3. 若 `y` 在替换后又成为不可达/死，交给 DCE。

**局限**：文本形式的复写传播遇到别名（`*p = ...` 可能改 `y`）就保守放弃；SSA 形式的复写传播（`copy folding`）直接利用「值的唯一版本」，更精确也更简单。<span class="marginnote">SSA 让复写传播几乎「免费」：SSA 中每个变量只有一个定值，`x = y` 之后所有 `x` 的读取天然都是该定值的唯一使用——替换成 `y` 不过是「用同一个值编号」。这又是 SSA 简化优化的一个例子（第十一篇详述）。</span>

## 3 死代码消除：删掉无人要的值

**死代码消除（dead-code elimination, DCE）**：删除**结果永不被使用**的语句。判据（用活跃变量分析）：

$$\text{语句 } x = y \ op \ z \text{ 可删} \iff x \text{ 在语句后不活跃}$$

- `x` 不活跃 = 之后（沿所有路径）不再被读取——这个定值白算了。
- 删除可能**连锁**：删掉 `x = ...` 后，`y`、`z` 的定值若也变得不活跃，继续删。

**辨析｜易错点：** DCE 不是「删没用的语句」这么简单——它删的是**结果没用的定义**。带副作用的语句（函数调用、写内存、`volatile` 读）绝不能删，即使其结果未用。编译器把「有副作用的语句」视为不可删除的根。<span class="marginnote">「副作用不可删」是 DCE 的第一铁律：`printf()` 的返回值没人用，但调用本身必须保留；`*p = 1` 可能被别的指针读到，也不能删。真实编译器用「语句是否可能有副作用」作为删除的否决条件，宁可保守。</span>

## 4 公式解析：复写传播的条件

设点 $p$ 读取 `x`，则把该读取替换为 `y` 的条件：

$$\text{唯一到达定值}(x, p) = \{x = y\} \ \land \ y \text{ 在 } x=y \text{ 之后未被重写}$$

- **第一步，唯一性**：到达 `p` 的 `x` 定值只有一个——否则不知道 `x` 到底是谁的别名，替换不安全。
- **第二步，形如复写**：那个唯一定值是 `x = y`（不是 `x = a + b`）——只有纯复写才有「x 就是 y」的关系。
- **第三步，y 未被改**：`x = y` 之后 `y` 不能再被赋值——否则 `y` 的值变了，`x` 却还是旧值，替换就错了。

**「唯一 + 复写 + 源存活」是复写传播的三重前提**——任何一条不满足，宁可保留复写。

## 5 复写传播与 CSE、寄存器分配的联动

复写传播不是孤立优化，它与邻居们配合：

- **与 CSE**：传播后 `y + 1` 可能与别处 `y + 1` 文本一致，触发 CSE——「传播开路、CSE 收割」。
- **与常量传播**：若 `y` 是常量，传播后 `y + 1` 触发折叠——同样的开路模式。
- **与寄存器分配**：消除别名 = 少一个活跃变量 = 寄存器压力下降——间接收益。
- **与 DCE**：传播制造死代码，DCE 清理——直接配对。

**重点是**：复写传播的价值一半在自身（少别名），一半在**为其他优化开路**——它是优化流水线里的「催化剂」。<span class="marginnote">把复写传播想成「清理中间层」：程序员写中间变量为了可读，编译器先传播（让值直接可见）、再清理（删无用定值）——最终代码既快又不冗余。这种「先规范化、再优化」的模式贯穿整个中端。</span>

## 7 思考与练习

**练习 1 复写传播**：对 `x = y; a = x + 1; x = z; b = x * 2;`，指出哪些 `x` 的读取可替换为 `y`/`z`——并说明「为什么第二处 `x` 不能传播成 `y`」。

**练习 2 死代码判定**：对 `a = 1; b = a + 2; a = 3; c = b;`，用活跃变量分析判定哪些定值是死的——注意 `a = 1` 在 `a = 3` 之前、之后 `a` 是否被读。

**练习 3 传播开路**：说明「复写传播 → 常量折叠」的接力：`x = y; ... x + 1` 若 `y` 是常量 5，传播后如何触发折叠——把「开路」机制写清楚。

**练习 4 副作用否决**：给出「结果未用但绝不能删」的语句（函数调用、写内存），说明 DCE 为什么把它们当根保留。<span class="marginnote">「副作用不可删」是 DCE 的红线：`foo()` 的返回值没人用，但调用本身可能有打印/改全局的副作用；`*p = 1` 可能被别的指针读到。编译器判断「是否可删」先问「有没有副作用」——有则保留。这也解释了 `volatile` 读为什么禁止删。</span>

**练习 5 连锁删除**：构造一个「删一条死代码后，另一条也变死」的连锁场景，模拟 DCE 迭代到不动点的过程。

**练习 6 SSA 简化**：解释「SSA 里复写传播几乎免费」——SSA 中 `x = y` 之后 `x` 的所有使用都是该定值的唯一使用，替换成 `y` 就是「用同一值编号」。

**常见误区**：

- **误区一**：以为「复写传播就是把 x 全换成 y」——只在「x 的唯一定值是 x=y 且 y 未变」时安全。
- **误区二**：把「死代码」当「没用的代码」——严格说是「结果没用的定值」，副作用语句不算。
- **误区三**：忽略「传播开路」的价值——传播本身省得少，但它让 CSE/常量折叠有机会。

**延伸**：复写传播与第三十节「临时变量」、第八十三节「ToyLang 代码生成」的中间变量治理是同一主题——「别名消除」让寄存器压力下降，与第七篇图着色衔接，把「少一个别名 = 少一个活跃变量」的因果写清楚。

## 8 小结

- **复写传播**：`x = y` 是 `x` 的唯一到达定值且 `y` 未变时，把 `x` 的读取替换为 `y`。
- 前提三重：**唯一定值、形如复写、源存活**——任何一条不满足就保守保留。
- **死代码消除**：语句结果不活跃则可删；**带副作用的语句是删除的否决项**。
- DCE 可**连锁**：删一个定值可能让其他定值变死，继续删到不动点。
- 复写传播「开路」、CSE/常量折叠「收割」、DCE「清理」——优化流水线的标准协作模式。
