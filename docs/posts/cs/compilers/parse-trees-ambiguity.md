# 语法分析树与文法的二义性

## 为什么从语法分析树开始

上一节我们有了推导：从开始符号一路替换，最终得到句子。但推导只是「步骤清单」，它没有把**结构**可视化。一句程序的意义不只来自「由哪些词构成」，更来自「这些词如何分组」——`2 + 3 × 4` 的意义取决于 `×` 是否先于 `+` 结合，也就是结构。

**语法分析树（parse tree / derivation tree）** 把推导的分组结构画出来：内部结点是非终结符，叶结点是终结符，父子关系来自产生式的应用。给定「`id + id × id` 按 $E \to E+T$ 拆分还是按 $E \to E\times E$ 拆分」，会得到**两棵不同形状的树**——而形状不同，语义（运算次序）就不同。<span class="marginnote">语法制导翻译（第四篇）就是在语法分析树这个骨架上挂语义动作。树的形状直接决定语义：同一串字，树不同，值不同——这就是歧义为何危险。</span>

## 1 语法分析树：推导的可视化

**语法分析树（parse tree）** 满足：

- 根结点是开始符号 $S$；
- 内部结点标非终结符；
- 叶结点标终结符（或 ε）；
- 每个内部结点 $A$ 的孩子，从左到右恰好是某条产生式 $A \to X_1X_2\cdots X_k$ 右侧的符号序列。

推导序列与语法分析树并不一一对应：同一棵树对应**多条**推导（替换顺序不同），但对应**唯一一棵**「最左推导树」与「最右推导树」。<span class="marginnote">所以「推导的集合」大于「树的集合」：顺序是过程信息，树是结构信息。分析器真正想要的是树，推导顺序只是实现路径。</span>

树的**叶子从左到右**读出的终结符串，就是被分析的句子。若某叶是 ε，它不占可见字符，但仍算一个位置——处理「空产生式」的树时要注意这点。

## 2 二义性文法：一句话，两棵树

**二义性（ambiguity）**：如果文法 $G$ 存在某个句子 $w \in L(G)$，它对应**两棵不同的语法分析树**，则称 $G$ 是二义的（ambiguous）。

经典二义文法：

$$E \to E + E \mid E \times E \mid (E) \mid \textbf{id}$$

句子 `id + id × id` 可以有两棵不同的树：一棵把 `+` 放在树根（先算乘法），一棵把 `×` 放在树根（先算加法）。两棵树给出不同的求值结果——`2+3×4` 一个得 14，一个得 20。<span class="marginnote">问题不在「+ 和 ×」本身，而在于文法没有规定运算优先级与结合性。`E → E+E` 没有区分「左结合还是右结合」，也没有让 `×` 比 `+` 更贴近叶子（更深）——这两件事必须由文法结构强制。</span>

还有另一种二义：**悬空 else（dangling else）**。文法

$$S \to \textbf{if} \ E \ \textbf{then} \ S \mid \textbf{if} \ E \ \textbf{then} \ S \ \textbf{else} \ S \mid \text{其他}$$

对 `if E1 then if E2 then S1 else S2` 有两棵标准树：else 归属内层 if 还是外层 if。多数语言规定 else 就近匹配内层——这是用「额外规则」而非文法本身消解的。

## 3 二义性的危害与处理

二义为何是编译器的大敌？因为分析器只能选一棵树往下走，而**语义挂载在树上**：同一棵树决定一种中间代码。若文法有二义，分析器要么「任意选一棵」（结果可能是错的），要么「报错」（把合法程序拒之门外）。<span class="marginnote">注意一个微妙点：文法二义 ≠ 语言二义。有些二义文法可以通过改写变成等价的无二义文法（下一节讲左递归、提取公因子等改写技术），但有些<strong>语言本身</strong>（如某些含 `if-then-else` 与匹配规则的组合）就是本质二义的。</span>

三种常见对策：

- **重写文法**：把 $E\to E+E$ 拆成分层的 $E\to E+T$，用「项/因子」的层次强制优先级。这是最正统的做法。
- **加规则约束**：悬空 else 用「就近匹配」消除，不改文法而改分析器的默认行为（yacc 的优先级/结合性声明也走这条路线）。
- **接受二义但语义独立**：个别场景刻意保留二义文法（如表达式文法）以减小文法规模，再用优先级表单独解析——这是下一节与 Yacc 章节的内容。

## 4 公式解析：二义性的精确判据

把「两棵不同的树」翻译成可操作的判据：

$$G \text{ 二义} \iff \exists w \in L(G),\ \text{tree}_1(w) \neq \text{tree}_2(w)$$

- **第一步，树的等价**：两棵语法分析树「相同」当且仅当结构完全相同（结点的标号与父子关系一致）。不同的最左推导必然对应不同的树。
- **第二步，换一种说法**：$w$ 存在**两个不同的最左推导**（或两个不同的最右推导）⇔ $w$ 有两棵不同的树。所以检查二义，可以检查「是否存在一个句子有两个最左推导」。
- **第三步，难点**：这个判据是存在性的，理论上不可判定——对任意 CFG 判断其是否二义，**没有通用算法**（这是形式语言理论的一个不可判定性结论）。工程上只能靠测试、凭经验、或对特定文法子类（LL/LR）用构造法规避。

**所以二义性是一个「无法自动消灭」的性质**：编译器设计者的责任是在设计文法时避开它，或在接受它时用明确的附加规则消解。这也解释了为何下一节的「消除二义性」是手艺活而非一键操作。

## 5 语法分析树与语言的更深联系

语法分析树的价值不止于语法检查。它是**编译前端的公共底座**：

- **语法制导翻译**把语义动作挂在树的结点上（第四篇）。
- **抽象语法树（AST）**是语法分析树的「瘦身版」：去掉只用于语法结构的结点（如括号、分隔符），保留语义要点（第五篇）。
- **二义性检测**常被编译器的测试套件用作健全性检查：对候选文法随机生成句子，若两个不同分析器给出不同结构，说明可能二义。<span class="marginnote">「随机句子 + 两个分析器对拍」是验证文法无二义的实用手段：构造一个语法分析器对同一串输出「标准树」，再用另一个（如 Earley 全量分析器）枚举所有树，若超过一棵则标记。工具 antlr、yacc 的开发者都用这类技巧。</span>

**辨析｜易错点：** 「文法无二义」与「分析器能处理」是两回事。即使文法无二义，LL(1) 或 LR(1) 分析器也可能因为「需要超过一字符前瞻」而无法处理它。二义是语言属性，可分析性是文法 + 算法属性——后几篇会反复用到这对区分。

## 7 思考与练习

**练习 1 画两棵树**：对文法 $E \to E+E \mid E \times E \mid (E) \mid \textbf{id}$，为 `id + id × id` 画出**两棵不同**的语法分析树，并给每棵树写出对应的求值（假设 id 都是 2，算两棵树的「值」）。

**练习 2 悬空 else**：对悬空 else 文法，画出 `if E1 then if E2 then S1 else S2` 的两棵标准树，标出「else 就近匹配」对应哪一棵。再用「改写文法」消除二义，写出等价的无二义文法。

**练习 3 二义判定**：判断文法 $S \to aS \mid Sa \mid a$ 是否二义——找「存在一句有两棵树」或证明无二义。提示：$aaa$ 有几棵不同的推导树？

**练习 4 不可判定性**：为什么「判断任意 CFG 是否二义」不可判定？用「停机问题归约」的思路口头论证——说明「自动消除二义」为何不存在通用算法。<span class="marginnote">这是编译原理里第一个「不可判定」结论：二义性检测没有通用算法。它解释了为什么编译器设计者要「靠手艺避开二义」——不是不够聪明，而是数学上根本不存在自动方法。</span>

**练习 5 语义挂树**：对 `2 + 3 × 4`，两棵树分别「先算 +」与「先算 ×」，结果各是多少？由此说明「语义挂在树上」——同一句话，树不同，值不同，编译器必须选一棵。

**练习 6 语法制导联系**：预告一下第四篇：若在每棵树上挂「计算值」的语义规则，两棵树会算出不同结果——这正是二义文法在语义层的「投影」。找出本节的「树」与第四篇「属性」的连接点。

**延伸**：自然语言的「花园小径句」（如「The horse raced past the barn fell」）也有「两棵句法树」——把「二义性」类比到语言学，说说自然语言处理里「消歧」与编译器「消除二义」的异同。

## 8 小结

- **语法分析树**把推导结构可视化：根为 $S$，内部结点为非终结符，叶为终结符；一棵树对应多条推导，但最左/最右推导各对应唯一树。
- **二义性** = 存在一个句子有两棵不同的语法分析树；`E→E+E` 与悬空 else 是两大经典来源。
- 二义的危险在于**语义挂在树上**，树不同则语义不同，分析器无从选择。
- 处理三招：**重写文法**、**附加规则约束**、**接受二义 + 独立优先级表**。
- 二义性对一般 CFG **不可判定**，工程靠改写规避、测试验证。
- 语法分析树是语法制导翻译、AST 与后续优化共同的基础。
