## 为什么从回填技术开始

上一节的布尔翻译把「真标号、假标号」当参数传——但有个现实麻烦：**翻译 `if (E) S1 else S2` 时，`S1` 的代码还没生成，它的入口地址是多少？** 传统的做法是「先生成代码、记下位置，回头填地址」——即 **回填（backpatching）**。<span class="marginnote">回填是编译器里「前向引用」问题的标准解法：目标未知时先占位，等目标确定再回头改。这个模式在汇编器（符号地址）、链接器（重定位）里反复出现——「先占位、后填补」是处理未知地址的通用工程手段。</span>

## 1 控制流翻译的挑战

`if (E) S1 else S2` 的翻译轮廓：

```
if E 为真 goto ??      # S1 的入口，尚未生成
goto ??
S1.code
goto ??               # 跳过 else 分支
S2.code
```

`??` 全是**尚未确定的目标**。若按「翻译完再返回位置」的做法，需要：先把 `E` 翻译成带标号的跳转、再生成 `S1`、再回来填 `E` 的真标号……这要求语法分析与代码生成「穿插进行」，在自底向上分析里尤其别扭。

**难点本质**：三地址码是**线性的**，而控制流是**跳跃的**——线性生成过程中，跳转目标往往「在未来」。回填把这个「未来」先留白。

## 2 回填的思想：占位与填补

**回填（backpatching）** 的机制：

1. 生成跳转指令时，目标位置**暂填 `0`**（占位），并把「这条指令的地址」记入一个**待填列表**。
2. 目标确定后（对应的代码生成完、知道了它所在的位置），遍历待填列表，把每条 `0` 改成真实目标地址。

于是翻译 `if (E) S1` 的流程变成：翻译 `E` 时，把「真跳转」填入待填列表 `truelist`；生成完 `S1`，记录 `S1` 的起始位置 `L`，然后**回填**：把 `truelist` 里所有指令的目标改为 `L`。<span class="marginnote">回填把「翻译顺序」与「代码生成」解耦：无论分析顺序如何，最终所有跳转都能指向正确位置。它也是「增量式」思想的体现——代码不必全部规划好再生成，可以边写边补。</span>

## 3 回填的三地址码实现：用链表

龙书的经典实现：每条跳转指令占一个四元式，其 `result` 字段（目标）暂记 `0`；「待填列表」用**链表**表示——每个跳转指令的下一个待填位置由**另一个字段**串联（把 `result` 为 0 的四元式串成链）。

```c
// 四元式: (op, arg1, arg2, result)
// 生成跳转: gen(jump, 0, 0, 0) —— result=0 占位
// 链表: 四元式的某个字段(如 arg2) 存"下一个待填项的下标"
int makelist(int i);        // 新建单元素链
int merge(int p1, int p2);  // 合并两条链
void backpatch(int p, int target);  // 把链 p 的所有项填 target
```

- `makelist(i)`：以四元式 `i` 为头的链。
- `merge(p1, p2)`：把 `p2` 接在 `p1` 尾后。
- `backpatch(p, t)`：遍历链 `p`，把每项的目标字段改成 `t`。<span class="marginnote">用「四元式的字段作指针」把待填项串成链表，是龙书里著名的节俭技巧——不额外分配链表结点，直接用现成字段。这在 1970 年代的存储受限环境里是实打实的工程智慧，今天看也仍然优雅。</span>

## 4 公式解析：布尔翻译的回填规则

回填版的布尔表达式 SDT 管理两个属性：`truelist`（真跳转链）与 `falselist`（假跳转链）。以 `E → E1 or E2` 为例：

$$\text{truelist}(E) = \text{truelist}(E_1) \cup \text{truelist}(E_2), \qquad \text{falselist}(E) = \text{falselist}(E_2)$$

- **第一步，逻辑或的语义**：`E1 || E2`——`E1` 真则整体真，所以 `E` 的**真链**是 `E1` 与 `E2` 的真链**合并**；`E1` 假则看 `E2`，所以 `E` 的假链只需 `E2` 的假链。
- **第二步，中间的坑**：`E1` 的假跳转「不知道跳哪」——它该跳到 `E2` 的代码开始处，而那时 `E2` 还没翻译。于是先把它放进 `E1.falselist`，翻译完 `E2` 后**回填**到 `E2` 的起始位置。
- **第三步，对称规则**：逻辑与 `E1 && E2` 恰好镜像：真链取 `E2` 的、假链合并两者，`E1` 的真跳转回填到 `E2` 入口。

**「用合并 + 回填管理真假链」让布尔翻译完全摆脱「返回数值」**——真/假链像接力棒一样传递，跳转目标全部最终被回填到位。

## 5 控制流语句的完整翻译

用回填把整族控制流语句翻译统一起来：

| 语句 | 真链去向 | 假链去向 |
| --- | --- | --- |
| `if (E) S` | 回填到 `S.code` 起点 | 回填到 `if` 之后 |
| `if (E) S1 else S2` | `S1` 起点 | `S2` 起点；`S1` 尾的跳转回填到 `if` 后 |
| `while (E) S` | 循环体起点，体尾回填回条件 | 循环出口 |
| `do S while (E)` | 体起点（回填） | 循环出口 |
| `for (...)` | 用真链/假链组合 | 出口 |

**重点是**：回填让「条件、循环、短路布尔」共享一套「链 + 回填」机制——它们本质都是「跳转目标未知」的翻译。<span class="marginnote">理解了回填，也就理解了为什么「控制流翻译」常是中间代码生成里最绕的一节——但它也只是「先占位、后填补」这一句话的无数次应用。练一次手写翻译，这句话就刻进直觉了。</span>

## 7 常见误区与延伸

**常见误区**：

- **误区一**：以为「回填是优化」——回填是实现「前向引用」的机制，不是性能优化；跳转目标未知就必须回填。
- **误区二**：把「待填列表」当「运行期数据」——它只在编译期存在，是「尚未确定的目标地址」的编译期暂存。
- **误区三**：以为「布尔表达式必须返回数值」——控制流表示法用「跳转标号」而非「值」，真/假链是更自然的形式。
- **误区四**：混淆「真链/假链」的方向——`||` 合并真链（任一为真则整体真），`&&` 合并假链（任一为假则整体假）。

**延伸**：回填的「先占位、后填补」是处理「前向引用」的通用技巧——在第三级《汇编语言与链接》的「符号地址解析」、第五篇「跳转表」、第四级《链接器》的「重定位」里反复出现。把「编译器回填」与「链接器重定位」对比，找「占位 → 解析 → 填补」的同一骨架。

**练习提示**：用回填手工翻译 `if (a < b && c > d) S;`——标出 `&&` 的假链如何跳过 `c > d`、真链如何进入 `S`。这张「布尔 + 回填」的手工轨迹，是第三十四节与本节合体的最好练习。

## 8 小结

- **控制流翻译的难点**：跳转目标往往指向「尚未生成的代码」——线性生成与跳跃结构矛盾。
- **回填**：跳转目标先占位（填 0），目标确定后回头把占位改成真实地址。
- 实现用**四元式字段作链表指针**：`makelist`/`merge`/`backpatch` 三个原语管理待填链。
- 布尔翻译的回填规则：`||` 合并真链、`&&` 合并假链，中间跳转回填到另一侧入口。
- 条件、循环、短路布尔**共享一套链 + 回填机制**——「先占位、后填补」是通用解。
