## 为什么从基本块优化开始

流图把程序切成基本块，优化就有了第一批靶子：**块内**的冗余。块内无分支，一切顺序执行——公共子表达式、死代码、可折叠的常量，全在「眼前」，不必跨块追踪。**局部优化（local optimization）** 就在基本块内部做文章，它是优化的最小单元、也是最稳的收益。<span class="marginnote">「局部 = 基本块内」的定义非常精确：局部优化只看一个块，不跨边。它简单可靠（块内无控制流，信息完全确定），所以是每个编译器最先实现的优化。跨块的版本（全局 CSE、全局死代码）是第八篇数据流分析的任务——局部是它的预热。</span>

## 1 用 DAG 表示基本块

龙书用**基本块的 DAG（有向无环图）** 来做局部优化：把块内每条三地址指令表示成 DAG 结点。

**叶子**：变量名、常量（当前值）。
**内部结点**：运算符。
**关键性质**：**同一个运算（同操作数）只建一个结点**——天然暴露公共子表达式。

构造规则：对 `x := y op z`，若 y、z 当前值与某已有内部结点相同，**复用**该结点并把 `x` 挂上去，否则新建。对 `x := y`（复制），直接让 x 指向 y 的结点。

对 `a = b * c; d = b * c` 构造的 DAG 会显示：`a` 与 `d` 的 `b * c` 是同一个结点——公共子表达式当场现形。<span class="marginnote">DAG 是「块内唯一化」：每个计算只出现一次，多个名字共享同一计算。这个「共享」既是 CSE 的依据，也是死代码消除的依据——没人引用的结点就该删。</span>

## 2 局部公共子表达式消除

**公共子表达式消除（common subexpression elimination, CSE）**：同一运算在之前已算过、且操作数未被修改，则复用结果，不重算。

在 DAG 上：构造 `x := y op z` 时若结点已存在（y、z 当前值与过去一致），把 x 的定值指向那个结点，不再生成新指令。效果：

```
a = b * c
d = b * c

// CSE 后：d 复用 a 的结果
a = b * c
d = a
```

前提是**操作数在两次之间未被重新赋值**——DAG 的「当前值」追踪恰好保证这一点：若 `b` 被改过，结点就不同了。<span class="marginnote">CSE 的「安全前提」是优化里反复出现的主题：合并两个计算，必须证明中间没有改操作数的指令。块内 DAG 用「当前值版本」天然满足；跨块的 CSE 就要数据流分析证明「到达」——同一个想法，两个难度档位。</span>

## 3 死代码消除与代数化简

**死代码消除（dead-code elimination, DCE）**：删除「结果永不被使用」的指令。判据：某变量的定值之后从未被读取，则该定值是**死代码**。

在 DAG 上：没有结点引用某个名字（且名字不是块的出口活跃变量），则删除其定值指令。

**代数恒等式化简（algebraic identities）**：利用运算性质消掉多余计算：

`x + 0` → `x`、`x * 1` → `x`、`x - 0` → `x`。
`x * 0` → `0`、`x / 1` → `x`。
强度相关：`x * 2` → `x + x` 或移位（`x << 1`）。

这些恒等式在 DAG 构造时直接应用（结点创建前先化简），是「廉价但高频」的优化。<span class="marginnote">代数化简要小心浮点：`x + 0` 对浮点不总是 `x`（`-0.0`、`NaN` 的陷阱），`x * 1` 也同理。所以编译器通常只对整数做这些恒等式，浮点要开 `-ffast-math` 才敢——「安全前提」在浮点下更严格。</span>

## 4 公式解析：DAG 构造的复用判据

设当前变量绑定函数 $\text{value}(v)$ 给出「v 当前所指的 DAG 结点」。构造 `x := y op z` 时：

$$\text{若 } \exists\ \text{结点 } n:\ n.\text{op} = op \land n.\text{左} = \text{value}(y) \land n.\text{右} = \text{value}(z)，\text{则复用 } n，否则新建$$

- **第一步，匹配**：找「运算符 + 左右操作数当前结点」都相同的已有结点——这正是「同一次计算」的定义。
- **第二步，绑定**：把 $\text{value}(x)$ 设为该结点，x 的定值不再生成指令（DCE 会把这条定值也识别掉）。
- **第三步，当前值语义**：操作数被赋值时，$\text{value}$ 改变——所以匹配天然排除「a 被改过」的情况，安全前提自动成立。

**「当前值 + 唯一结点」是 DAG 的双保险**：CSE 找共享，DCE 找闲置，两个优化在同一张图上完成。

## 5 局部优化的限度

局部优化简单，但有天花板：

- **不跨块**：`b * c` 在块 A、块 B 都出现且中间没改 b、c——局部优化看不到，全局 CSE 才能合并。
- **不跨循环**：循环不变计算（`b * c` 在循环内不变）是局部视角看不到的——要第八篇的代码外提。
- **依赖精确活跃信息**：DCE 需要知道「名字在块出口是否还活跃」——这其实是活跃变量分析（数据流）提供的，局部优化借用了它的结论。

**重点是**：局部优化是「看得见的都收下」，看不见的留给全局。<span class="marginnote">优化编译器的经典分层：局部（块内 DAG）→ 全局（流图上数据流分析）→ 循环（支配 + 外提）。每一层在前一层之上扩大视野，复杂度上升、收益递增。理解局部优化，是进入后续全局优化的阶梯。</span>

## 7 思考与练习

**练习 1 构造 DAG**：对基本块 `a = b * c; d = b * c; e = a + d`，构造 DAG，指出哪些是公共子表达式（DAG 里共享的结点）。

**练习 2 局部 CSE**：在练习 1 的 DAG 上做 CSE——把重复计算改为「复用」后，重写基本块，数一数省了几条指令。

**练习 3 死代码**：对 `t = a + b`（假设 `t` 在块内不被用且出口不活跃），在 DAG 上标出哪些定值是死的、为什么。

**练习 4 代数化简**：对 `x = b + 0; y = x * 1`，应用恒等式化简，写出化简后的块——并讨论「浮点下这些恒等式还成立吗」。

**练习 5 安全前提**：`a = b * c; b = 1; d = b * c`——第二次 `b * c` 为什么**不能**复用第一次？用 DAG 的「当前值」机制解释。<span class="marginnote">这是 CSE 安全前提的关键练习：`b` 被重新赋值后，`b` 指向的结点变了，第二次 `b * c` 的「操作数当前结点」与第一次不同——DAG 不会合并它们。若没有「当前值」追踪而只看文本，就会错误合并、编译出错。理解「当前值」= 理解 CSE 的安全边界。</span>

**练习 6 局部 vs 全局**：把练习 2 的 CSE 场景放到两个基本块里（中间隔一个块），说明局部 DAG 为什么看不到——预告全局 CSE（第五十五节）。

**常见误区**：

- **误区一**：以为「DAG 合并 = 删除指令」——DAG 只是「值唯一化」，删除指令由 DCE 做。
- **误区二**：把「代数化简」当「无条件」——浮点下 `x + 0`、`x * 1` 的恒等式未必成立。
- **误区三**：忽略「当前值」——文本相同的表达式若操作数被改，不算同一个值。

**延伸**：基本块 DAG 的「唯一结点」思想，与第五十五节「全局值编号（GVN）」、第五篇「DAG 中间表示」是同一主线——把「局部 DAG → 全局 GVN → SSA 值编号」三级写成一页演进史。

## 8 小结

- **局部优化**限定在基本块内，块内无控制流、信息完全确定，是最稳的优化单元。
- **DAG 表示**把块内计算「唯一化」：同一运算一个结点，公共子表达式当场现形。
- **局部 CSE**：同操作数同运算复用结果；DAG 的「当前值」自动保证操作数未被改的安全前提。
- **死代码消除**删「结果永不被读」的定值；**代数化简**用恒等式砍掉冗余运算。
- 局部优化有天花板：不跨块、不跨循环、依赖活跃信息——更广的视野留给全局优化。
