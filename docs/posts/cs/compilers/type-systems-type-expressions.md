## 为什么从类型系统开始

中间代码生成的另一块基石是**类型**。没有类型信息，编译器无法决定 `a + b` 是整数加法还是浮点加法、无法知道 `x.f` 该往哪偏移、更无法拒绝「给函数传字符串当数字」的程序。类型把「合法运算」的形式化，让错误在编译期暴露。

**类型系统（type system）** 是「类型」的集合 + 「程序表达式有类型」的规则；**类型表达式（type expression）** 是描述类型的递归记号——用它能表达 `int`、`int[10]`、`int→float`、`struct{...}` 等一切类型。<span class="marginnote">「类型即集合」是一个深刻的视角：`int` 是机器能表示的一堆整数，`int→float` 是函数输入输出关系的集合。类型检查 = 验证「程序里的每个运算，参数类型都在允许的集合里」。数学类型论与编译器的类型系统，在此交汇。</span>

## 1 类型在编译器中做什么

编译器里类型至少承担五种职责：

- **决定指令选择**：`int+int` 用整数加法指令，`float+float` 用浮点指令。
- **决定存储布局**：`int[10]` 的宽度、`struct` 各字段的偏移，都靠类型算。
- **决定地址计算**：数组寻址的 `×w`，`w` 来自元素类型宽度。
- **安全检查**：拒绝把 `int*` 当 `float*` 用、拒绝把函数当变量调用。
- **重载决议**：`+` 对整数、浮点、字符串重载，靠参数类型选择实现。

这五条贯穿前端与后端：类型错了，生成的代码就错了。<span class="marginnote">静态类型 vs 动态类型的分野也在编译器形态上：静态类型语言（C、Java、Rust）在编译期做类型检查；动态语言（Python、JS）把检查推迟到运行期，换取灵活性、付出性能与可靠性代价。理解「类型检查在哪个阶段」，就理解了语言的哲学差异。</span>

## 2 类型表达式：类型的递归记号

**类型表达式（type expression）** 递归定义：

- **基本类型**：`boolean`、`char`、`integer`、`float`、`void`。
- **类型名**：`type_error`（错误类型）、`no_type`（无类型）。
- **构造类型**：
  - 数组：`array(n, T)`——n 个类型 T 的元素。
  - 指针：`pointer(T)`——指向 T。
  - 乘积（记录/结构体）：`T1 × T2 × ⋯ × Tn`。
  - 函数：`S → T`——参数类型 S、返回类型 T。
  - 命名类型：用类型名引用已定义类型。

例子：`int[10]` 写作 `array(10, integer)`；`int*` 写作 `pointer(integer)`；`int→float` 写作 `integer → float`。<span class="marginnote">类型表达式与文法惊人地同构：基本类型是「终结符」，构造符是「运算」，递归结构可以无限组合——`pointer(array(10, pointer(integer)))` 就是「指向含 10 个整型指针的数组的指针」。类型是一种小语言。</span>

## 3 类型构造符详解

**数组 `array(n, T)`**：n 是编译期常量，T 是元素类型。宽度 = n × width(T)。

**指针 `pointer(T)`**：指向 T 的存储。指针宽度通常是定值（地址字长），与 T 无关——这是 C 里 `int*` 与 `float*` 同样大的原因。

**记录 `T1×⋯×Tn`**：字段按序排列，宽度 = 各字段宽度之和，字段 i 的偏移 = 前 i-1 个字段宽度之和。这就是声明翻译里 `offset += width` 的理论形态。<span class="marginnote">记录的类型表达式 `T1×T2×⋯×Tn` 只描述「乘积」，不描述字段名——字段名由符号表补充。这也解释了为什么 C 的 `struct` 在类型层只是「一堆字段的类型」，字段名是命名层的附加信息。</span>

**函数 `S→T`**：参数类型 S（可为乘积，表示多个参数）与返回类型 T。`integer × float → boolean` 表示「接收一个 int 和一个 float，返回 boolean」的函数。

## 4 公式解析：类型表达式的良定义

类型表达式的集合 $T$ 是满足以下规则的最小集合：

$$\text{integer}, \text{float}, \ldots \in T, \qquad \frac{T_1, T_2, \ldots, T_n \in T}{\text{array}(n, T_1),\ \text{pointer}(T_1),\ T_1 \times T_2 \times \cdots \times T_n,\ S \to T \in T}$$

- **第一步，基底**：基本类型本身在 $T$ 里——递归的「0」。
- **第二步，构造**：若 $T_1, T_2, \ldots, T_n$ 都是类型表达式，则它们的数组、指针、乘积、函数也是——递归的「后继」。
- **第三步，最小性**：$T$ 是「满足规则的最小集合」——只有用规则能构造出来的才算类型表达式，杜绝「无限下降」的病态类型。

**这条「最小闭包」定义保证了类型表达式结构良好、可递归遍历**——编译器可以安全地在类型上做递归操作（算宽度、比较等价、取子类型），而不用担心遇到怪异的构造。

## 5 类型名与类型等价

编程语言允许 `typedef`/`type` 给类型命名。命名引出**类型等价**的判定：

- **结构等价（structural equivalence）**：展开所有命名后，类型表达式**结构相同**则等价。`int*` 与 `int*` 结构等价。
- **名字等价（name equivalence）**：`typedef int A; typedef int B;` 中 A 与 B 是否同一类型？名字等价说「不是」——它们名字不同。

**辨析｜易错点：** 结构等价把 `typedef int A;` 的 `A` 与 `int` 视为同型，名字等价则区分。多数语言取折中：基本类型结构等价、用户定义类型名字等价（防止两个同名结构体被混用）。「递归类型」（链表 `struct Node { Node* next; }`）只能用名字等价或加指针间接层来打破无限展开。<span class="marginnote">递归类型是类型系统的试金石：`Node` 的定义里含 `Node*`，展开成结构表达式会无限循环。解决办法要么指针截断（结构等价+指针），要么名字等价（遇到名字就停）。理解这个困境，就理解了为什么链表必须用指针。</span>

## 7 思考与练习

**练习 1 类型表达式**：用类型表达式表示：`int[10]`、`int*`、`char**`、`int→float`、`(int,float)→bool`、`int[2][3]`——注意「数组含长度、函数含参数/返回」的递归结构。

**练习 2 类型宽度**：设 `int` 宽 4、`float` 宽 4、`char` 宽 1，计算 `float[10]`、`int[2][3]`、`struct{int a; char b;}` 的宽度——体会「宽度 = 递归计算」。

**练习 3 最小闭包**：解释「类型表达式集合是满足规则的最小集合」——为什么「最小性」保证类型结构良好、可递归遍历？

**练习 4 递归类型**：`struct Node { int val; Node* next; }` 的类型表达式若强行展开会发生什么？——用「指针截断」与「名字等价」两种方案各说怎么打破。

**练习 5 指针独立性**：`int*` 与 `float*` 的宽度相同（都是地址字长）——说明「指针类型独立于所指类型」对编译器布局的意义。<span class="marginnote">「指针宽度与所指类型无关」让指针类型统一（地址都占一个字长），也让 `void*` 可行——C 里所有指针互转都不改变存储大小。这个「指针即地址」的简化，是 C 能在「内存模型」上自由操作的基础，也是「类型系统的存储无关性」的来源。</span>

**练习 6 类型即集合**：用「类型 = 值的集合」视角解释 `int→float`、`int[10]`——函数类型是「输入输出关系的集合」，数组类型是「定长序列的集合」。

**常见误区**：

- **误区一**：把「数组类型」与「指针类型」混为一谈——C 的「数组退化」是运行时行为，类型层 `int[10]` 与 `int*` 不同。
- **误区二**：忽略长度——`int[10]` 与 `int[20]` 类型不同（结构等价下），因为 `array` 构造符含长度参数。
- **误区三**：以为「类型名」就是类型——`typedef` 只是别名，底层是同一个类型表达式或名字等价。

**延伸**：类型表达式的「递归构造」与第二级《离散数学》的「递归定义」、第四篇「属性」的递归结构同源——把「类型语言」当作一门小语言，对比它与文法的「终结符/构造符/递归」三要素。

## 8 小结

- **类型系统**决定指令选择、存储布局、地址计算、安全检查与重载决议——类型错则代码错。
- **类型表达式**是描述类型的递归记号：基本类型 + 数组/指针/乘积/函数构造符。
- 各构造符的语义：数组带长度、指针独立于所指类型、记录是字段乘积、函数是 S→T。
- 类型表达式集合是**最小闭包**：结构良好、可递归遍历，编译器可安全做递归操作。
- **类型等价**分结构等价与名字等价；递归类型靠指针或名字等价打破无限展开。
