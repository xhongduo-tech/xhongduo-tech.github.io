## 为什么从自底向上分析开始

自顶向下从 $S$ 向下「猜」推导，遇到复杂文法就要改写、要前瞻、要排除左递归。而编译器实际想要的树，往往从**叶子**长出来更自然：先看到 `id`、`+`、`id`，再把它们归约成表达式，一步步拼回 $S$。这条路叫**自底向上分析（bottom-up parsing）**，它不需要去左递归，能处理的文法类比自顶向下更宽，LR 分析器正是它的巅峰形态。<span class="marginnote">自底向上对应「最右推导的逆过程」：把叶子归约回根，等于把最右推导的每一步倒放。Yacc/Bison、以及几乎所有 LALR 语法分析器生成器，都站在这一侧。</span>

理解自底向上的钥匙是一个动作：**归约（reduction）**——把一串「刚好是某产生式右侧」的符号，替换回该产生式左侧的非终结符。移进-归约分析器就靠「移进」与「归约」两个动作完成整棵树的构建。

## 1 自底向上的核心动作：归约

给定文法 $E \to E+T \mid T$、$T \to T\times F \mid F$、$F \to (E) \mid \textbf{id}$，分析 `id × id`：

```
id × id     归约 F → id
F × id      归约 T → F
T × id      归约 F → id
T × F       归约 T → T × F
T           归约 E → T
E           完成
```

每一步都用产生式的**逆方向**：右侧替换成左侧。最终从 `id×id` 归约到 $E$，就找到了语法分析树——不过是自下而上长的。<span class="marginnote">注意每一步的选择：为什么第一次归约 $F\to\textbf{id}$ 而不是 $T\to F$ 或 $E\to T$？因为<strong>可归约的串必须匹配某条产生式的右侧</strong>。`id` 匹配 $F\to\textbf{id}$ 的右侧，而单独一个 `F` 并不在输入串里——归约对象是「当前串的一段」，不是「整个串」。</span>

**句柄（handle）** 是这整个过程的关键概念：每个归约步骤，被替换的那段「可归约子串」。规范的做法是只归约**句柄**——它保证分析出的树对应一条最右推导。

## 2 移进-归约分析器：两个动作的机器

**移进-归约分析器（shift-reduce parser）** 维护一个**符号栈**与输入指针：

- **移进（shift）**：把当前输入记号压入栈，输入前进一格。
- **归约（reduce）**：若栈顶一串符号恰好是某产生式右侧 $\beta$，弹出 $\beta$、压入左侧非终结符 $A$——栈顶 $\beta$ 被「替换」为 $A$。
- **接受（accept）**：栈内恰为 `$ S` 且输入为 `$` 时，成功。
- **报错（error）**：无法移进也无法归约时，语法错误。

以 `id + id` 为例走几步：

| 栈 | 输入 | 动作 |
| --- | --- | --- |
| `$` | `id + id $` | 移进 id |
| `$ id` | `+ id $` | 归约 $F\to\textbf{id}$ |
| `$ F` | `+ id $` | 归约 $T\to F$ |
| `$ T` | `+ id $` | 归约 $E\to T$ |
| `$ E` | `+ id $` | 移进 + |
| `$ E +` | `id $` | 移进 id |
| `$ E + id` | `$` | 归约 $F\to\textbf{id}$、$T\to F$ |
| `$ E + T` | `$` | 归约 $E\to E+T$ |
| `$ E` | `$` | 接受 |

**要点**：栈里的符号总是「已读入但尚未归约完成的活前缀」；什么时候移进、什么时候归约，正是分析表的决策点。<span class="marginnote">「活前缀（viable prefix）」是自底向上的核心不变式：栈中符号串始终是某个最右句型的前缀，且不会越过句柄的右端。合法活前缀构成的语言，正是下一节 LR(0) 项集要精确定义的集合。</span>

## 3 句柄与规范归约

**句柄（handle）** 的形式定义：对最右句型 $\gamma = \alpha\beta w$，其中 $\beta$ 是产生式 $A \to \beta$ 的右侧，且 $w$ 只含终结符，则 $\beta$ 在**位置 $\alpha$ 之后**的是该句型的一个句柄。直观说：**句柄是「最右推导中下一步要被替换」的那段，且替换点右边的部分全是终结符。**

**规范归约（canonical reduction）** = 每次都归约句柄。它产生一棵与最右推导一一对应的树——不同的归约顺序可能得到不同树，只有句柄归约给出「标准答案」。<span class="marginnote">「只归约句柄」为何对？因为最右推导每一步替换的都是最右非终结符，倒放时先替换的必然在最右边；所以规范归约 = 最右推导的镜像。LR 分析器做的正是规范归约——这保证分析结果无歧义。</span>

**辨析｜易错点：** 一个句型可能有多个候选可归约，但**句柄是唯一的**（对无二义文法）。「能归约的子串」≠「句柄」：比如 `F × F` 里的 `F` 和 `F × F` 都能按产生式归约，但只有最右那个才是句柄。归约错了，就得到一棵不正确的树。

## 4 公式解析：句柄的精确定义

把句柄拆开：

$$\text{若 } S \Rightarrow_{rm}^* \alpha A w \Rightarrow_{rm} \alpha\beta w，\text{则 } \beta \text{ 是 } \alpha\beta w \text{ 的一个句柄}$$

- **第一步，最右推导**：$S$ 经最右推导到 $\alpha A w$，其中 $A$ 是最右非终结符，$w$ 是纯终结符后缀。
- **第二步，最后一步**：最右推导的最后一步把 $A$ 换成 $\beta$，得到 $\alpha\beta w$。那么「$A$ 换 $\beta$」这个位置就是**句柄位置**。
- **第三步，唯一性**：对无二义文法，$\alpha A w$ 里 $A$ 的位置唯一（最右非终结符），所以句柄唯一。

**所以句柄总是「最右推导最后一步的逆」**——归约句柄，就是在倒放最后一步。规范归约持续倒放，直到 $S$。

## 5 冲突：移进 vs 归约

移进-归约分析器的难点在于**决策**：栈顶既可以归约，也可以继续移进。两种经典冲突：

- **移进-归约冲突（shift-reduce conflict）**：栈顶既能按某产生式归约，又能把下一个记号移进。典型例子：`if-then-else` 的悬空 else——看到 `else` 时，是归约掉内层 `if` 还是移进 `else`？
- **归约-归约冲突（reduce-reduce conflict）**：栈顶同时匹配两条产生式的右侧，不知归约哪条。例如词法层把 `id` 和 `int` 混在一起时，`id` 既可归约为变量也可归约为类型。

LR 分析器用**前瞻**来解冲突：看一眼下一个记号，属于 FOLLOW 的归约，否则移进——这正是下一节 LR 分析表的核心设计动机。<span class="marginnote">有些冲突用前瞻也解不开，比如真正的二义文法。那时分析器生成器会报「冲突」，由用户用优先级声明消解——Yacc 的 `%left`/`%right` 声明就是干这个的。</span>

## 7 思考与练习

**练习 1 归约演练**：用文法 $E \to E+T \mid T$、$T \to \textbf{id}$，把 `id + id + id` 完整地归约回 $E$——每一步标出「栈、输入、动作（移进/归约）」，感受自底向上的「从叶到根」。

**练习 2 找句柄**：对最右句型 $E + T + \textbf{id}$（假设完整文法），指出句柄在哪、为什么是它——用「最右推导最后一步的逆」来论证唯一性。

**练习 3 错误归约**：对 `F × F`（$F$ 是因子），列出所有「能按产生式归约」的子串，指出哪个才是句柄——体会「能归约 ≠ 该归约」。

**练习 4 冲突制造**：构造一个文法，让它在某一步同时出现「移进-归约冲突」——例如悬空 else 的变形。说明冲突点与两种选择各自的后果。<span class="marginnote">「造冲突」比「认冲突」更能检验理解：只有想清楚「为什么这一步既能移进又能归约」，才算真正懂了移进-归约的决策机制。造完再想「用什么前瞻能解」，就接到了 LR 分析的门口。</span>

**练习 5 活前缀直觉**：在练习 1 的轨迹中，每次移进后检查「栈中符号串是不是某个最右句型的前缀」——体会「活前缀」不变式如何被保持。

**练习 6 与最右推导的镜像**：把练习 1 的归约序列**倒过来**写，验证它就是最右推导——归约是推导的逆，亲手证明一次。

**延伸**：移进-归约的「栈 + 输入指针」模型，与第三级《数据结构》的「栈应用」（括号匹配、逆波兰求值）同源——找一个「用栈做语法判定」的场景，对比两者的异同。

## 8 小结

- **自底向上分析**从叶子归约回 $S$，是最右推导的逆过程；核心动作是**归约**（右侧→左侧）。
- **移进-归约分析器**用符号栈 + 输入指针，四种动作：移进、归约、接受、报错。
- **句柄**是最右句型中「下一步该替换」的唯一段落；**规范归约**= 只归约句柄，保证树与最右推导一一对应。
- 句柄唯一性来自最右推导的「最右非终结符」唯一；归约错段会得到错误树。
- **两类冲突**（移进-归约、归约-归约）靠前瞻与优先级声明消解，是 LR 分析表设计的直接动机。
