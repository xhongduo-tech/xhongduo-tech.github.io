# 垃圾回收的基本概念：可达性与安全点

## 为什么从垃圾回收开始

堆管理的显式释放（`malloc`/`free`）给了程序员完全控制，也给了两种经典 bug：**内存泄漏**（忘了释放）与**悬垂引用**（释放了还用）。**垃圾回收（garbage collection, GC）** 接管「何时释放」：程序只分配、不释放，GC 自动找出「再也不用的对象」并回收。它把「内存安全」从程序员的责任变成运行时的承诺。<span class="marginnote">「GC 不是优化，是正确性工具」是理解 GC 的第一心态：它的首要目标不是快，而是消灭泄漏与悬垂。代价是回收时程序要停顿（STW），现代 GC 用分代、增量、并发等手段把停顿压短——但「自动回收」的基本盘不变。</span>

## 1 从手动释放到自动回收

**手动内存管理**（C/C++）：

程序员负责 `malloc` 对应的 `free`。
优点：零回收开销、内存可预测。
缺点：泄漏（忘 free）、悬垂（free 后用）、双重释放（free 两次）——全是「人为错误」的高发区。

**自动内存管理**（Java、Go、Python、Rust 部分场景）：

分配后不手动释放，GC（或所有权系统）负责。
优点：消灭一类整族内存 bug，程序员专注逻辑。
缺点：GC 有运行期开销（追踪对象、回收时暂停）。

**GC 的适用场景**：对象生存期复杂、共享多、程序员难以手动管理的语言——动态类型语言几乎全用 GC；Rust 用**所有权（ownership）** 在编译期解决同一问题，是「零开销的另类自动管理」。<span class="marginnote">Rust 是所有权的特别案例：它不用运行时 GC，却靠编译期的「所有权 + 借用」规则保证内存安全——「谁拥有这个对象、谁借它」在编译期被检查。对比 GC 的「运行时找垃圾」，Rust 是「编译期防垃圾」——两种哲学的极致对比。</span>

## 2 可达性：什么对象该回收

GC 的核心判据是**可达性（reachability）**：

- **根集（root set）**：程序「当前直接持有」的对象——栈上的局部变量、全局变量、寄存器中的引用。
- **可达（reachable）**：从根集出发，沿对象引用能到达的对象。
- **不可达（unreachable）**：从根集无法到达的对象——它们**绝不可能**再被程序使用（没有引用能指向它们），可以回收。

$$\text{可回收} = \text{堆中对象} \setminus \text{可达对象}$$

**重点是**：不可达性是一个**保守但安全**的判据——它可能「误收」吗？不会：不可达对象无法被任何代码引用，回收它不影响程序。它可能「漏收」吗？可能——可达但永远不用的对象（如缓存里的死条目）GC 收不掉，这是「语义级泄漏」，不是 GC 的错误。<span class="marginnote">「可达性 ≈ 有用性」是 GC 的简化：程序可能持有引用却再也不用（可达但无用），GC 无法识别——因为「会不会用」不是可判定的。所以 GC 保证的是「不用的一定回收」，而不是「不用的尽量回收」。理解这个边界，就不会对「内存还涨」大惊小怪。</span>

## 3 根集与安全点

**根集（roots）** 是 GC 追踪的出发点。不同语言/实现的根集：

栈上的**局部变量**（含寄存器里的）。
**全局变量/静态字段**。
JVM 的**方法栈**与**本地方法栈**。

**安全点（safepoint）**：GC 需要在「程序状态一致」的时刻暂停线程——这个时刻叫安全点。在安全点上，栈与寄存器里的引用是**完整且已知**的，GC 能准确枚举根集。典型安全点位置：方法调用、循环回边、异常抛出处。

编译器在安全点**插入**暂停检查（如 JVM 的安全点轮询指令）：到达安全点时，检查是否有 GC 请求，有则暂停等待。<span class="marginnote">「安全点」是 GC 与编译器协同的接口：GC 不能随便停线程（栈可能处于中间态），必须在编译器标注的「状态完整」点停。这也是为什么「安全点插入」是 JIT 编译器（第十篇）与 GC 联动的核心——JIT 生成的代码里必须埋安全点。</span>

## 4 公式解析：可达集合的递归定义

设根集 $R$、对象间引用关系 $E$（对象 $a$ 引用 $b$ 记 $a \to b$），则**可达集合** $\text{Reach}$ 是满足以下规则的最小集合：

$$R \subseteq \text{Reach}, \qquad \frac{a \in \text{Reach} \land a \to b}{b \in \text{Reach}}$$

- **第一步，根可达**：所有根对象都是可达的——它们被程序直接持有。
- **第二步，传递闭包**：可达对象引用的对象也可达——引用链就是可达链，沿链扩散。
- **第三步，最小性**：$\text{Reach}$ 是「满足规则的最小集合」——只有能从根沿引用到达的才算，杜绝「凭空可达」。

**「根 + 沿引用传递闭包」是可达性的精确定义**——所有 GC 算法（标记-清扫、复制、分代）都是「计算这个集合」的工程实现。

## 5 GC 算法的分类图谱

GC 的家族庞大，按策略分类：

| 维度 | 类别 | 代表 |
| --- | --- | --- |
| 按追踪方式 | 追踪式（tracing）vs 引用计数 | 标记-清扫 vs 引用计数 |
| 按空间策略 | 原位清扫 vs 复制迁移 | Mark-Sweep vs Copying |
| 按时机 | 暂停式（STW）vs 增量/并发 | 全暂停 vs G1、ZGC |
| 按代际 | 单代 vs 分代 | 朴素 vs Generational |

后续几节逐一展开这些家族。**记住骨架**：一切 GC 都从「根集 + 可达性」出发，差异在「怎么找不可达对象」与「怎么回收它们」。<span class="marginnote">「追踪式 vs 引用计数」是 GC 最大的分水岭：追踪式「从根出发找活的」（标记-清扫等），引用计数「数每个对象被引用几次」（0 就回收）。追踪式能处理循环引用，引用计数不能——这个差异在「引用计数及其循环引用问题」一节会深挖。</span>

## 6 一个根集与可达性的完整走查

把「根集 + 可达性 + 安全点」落在一个具体运行瞬间。设 Java 方法执行中，栈上有局部变量 a、b，堆里有对象 O1..O6，引用关系：a→O1，O1→O2，b→O3，O3→O4，O5、O6 无人引用。

- **安全点暂停**：GC 在方法调用处暂停线程——此时栈引用完整可枚举，根集 = {a, b}（加全局变量，假设无）。
- **标记（可达）**：从 a 出发 → O1 → O2；从 b 出发 → O3 → O4。O1–O4 可达。
- **不可达**：O5、O6 从根不可达——回收。
- **结果**：O1–O4 保留，O5、O6 被回收。<span class="marginnote">「O5、O6 即使互相引用也回收」——本节的走查只到「可达/不可达」的判定；下一节标记-清扫会展示如何把这个判定实现成算法。可达性的「从根出发」与「循环引用」，正是后面引用计数一节对比的焦点：<strong>追踪式看连通、引用计数看计数</strong>。</span>

**要点**：这个走查浓缩了 GC 的完整骨架——安全点保证「根集完整」，根集出发的传递闭包 = 可达集合，补集 = 可回收。后续所有 GC 算法（标记-清扫、复制、分代）都是「算这个闭包」的不同工程实现。

**辨析｜易错点：** 可达性判定发生在**安全点的瞬间**——对象在被安全点「冻结」的快照上判定，而非实时。若程序在两次安全点之间改了引用（如 a 不再指向 O1），GC 仍按上次快照判定——这正是「安全点一致性」要求的：所有线程必须在同一逻辑时刻暂停，快照才自洽。

## 7 思考与练习

**练习 1 可达性判定**：给一个对象图（根 + 若干对象 + 引用边），标出可达/不可达对象——验证「不可达 = 可回收」的保守性。

**练习 2 根集枚举**：列出一个 Java/Python 程序的根集成员（栈局部、全局、寄存器）——说明为什么根集必须「完整且已知」才能准确回收。

**练习 3 安全点**：解释为什么 GC 必须在安全点暂停——若在「栈引用不完整」的时刻暂停，枚举根集会漏/错；安全点是「状态完整」的约定位置。

**练习 4 可达 vs 有用**：构造一个「可达但永远不用」的对象（如缓存里的死条目），说明 GC 为什么收不掉——体会「可达性 ≠ 有用性」的边界。<span class="marginnote">「可达但无用」是 GC 的盲区：对象被某个引用持有，但程序再也不碰它——GC 判断「可达」就不回收，于是泄漏。这是「语义级泄漏」：不是 GC 的错，是「会不会用」不可判定的数学事实。理解这个边界，就不会把「内存还涨」全怪 GC。</span>

**练习 5 手动 vs 自动**：对比 C 的手动释放与 Java 的 GC——各列出「被消灭的 bug」与「新增的代价」——把「泄漏/悬垂/双重释放」与「停顿/开销」写成一页对照。

**练习 6 分类图谱**：把标记-清扫、复制式、引用计数、分代、并发按「追踪方式 / 空间策略 / 时机 / 代际」四维归类——为后续各节做地图。

**常见误区**：

- **误区一**：以为「GC 能回收所有不再用的内存」——它回收「不可达」的，可达但无用（语义泄漏）收不掉。
- **误区二**：把「安全点」当「任意暂停点」——必须在编译器标注的「状态完整」处停。
- **误区三**：以为「手动管理总比 GC 快」——手动有零开销但有人为 bug；GC 有停顿但有确定性保证。

**延伸**：可达性的「根 + 引用传递闭包」与第五十三节「图遍历」、第二级《图论》的「连通分量」是同一数学——把「对象图」当作「有向图」，用「从根可达」的图论语言重述 GC 的回收判据。

## 8 小结

- **GC 接管「何时释放」**，消灭泄漏与悬垂；代价是运行期开销与暂停。
- **可达性**是回收判据：从根集沿引用能到达的对象才保留，不可达即可回收。
- **根集** = 栈局部变量、全局变量、寄存器引用；**安全点** = 程序状态完整、可安全暂停的位置。
- 可达集合是「根 + 引用传递闭包」的最小集合——一切 GC 算法的共同基础。
- GC 按追踪方式、空间策略、时机、代际分类；后续几节逐一展开。
