## 为什么从增量式与并发回收开始

标记-清扫、复制式、分代的共同痛点是**停顿（STW, stop-the-world）**：GC 跑的时候程序必须暂停。对大堆，一次全量 GC 可能停几十毫秒甚至秒级——对交互式应用（游戏、UI、实时系统）是灾难。**增量式（incremental）与并发式（concurrent）GC** 的目标是把停顿压到「可接受」，甚至到「近乎零」：增量式把回收切成小片穿插执行，并发式让回收线程与程序线程**同时跑**。<span class="marginnote">「停顿」是 GC 语言的阿喀琉斯之踵：JVM 早期一次 full GC 可能让服务卡顿数秒，这在低延迟交易、游戏里不可接受。增量/并发 GC 的全部工作，就是把「暂停时长」从「与堆大小成正比」压到「恒定小量」。这是现代 JVM（G1、ZGC）的主战场。</span>

## 1 停顿从哪来

**全停顿（STW）**：GC 标记/复制期间，程序线程全部冻结。停顿时长 ∝ 堆大小/存活对象——堆越大停越久。

停顿的三种来源：

**标记**：要遍历整个对象图（大堆 = 长遍历）。
**复制/整理**：移动所有存活对象 + 更新引用（大堆 = 大量移动）。
**清扫**：扫全堆找垃圾。

**增量/并发**策略的核心问题：**程序在 GC 进行中还在运行，它会修改对象图**——「我正要标记的对象被你删了」「我正要清扫的空间被你分配了」——必须保证 GC 与程序并发时**不错杀、不漏收**。<span class="marginnote">「并发下不错杀不漏收」是并发 GC 的难题：GC 看见的对象图是<strong>动态变化</strong>的——程序可能给未标记对象加引用（漏收风险）、也可能让已标记对象变垃圾（错杀风险）。三色标记法给出了一套「让 GC 看得见变化」的协议。</span>

## 2 增量式回收：把回收切碎

**增量式（incremental）GC**：把一次回收**切成很多小片**，穿插在程序运行之间——每小片很短（毫秒级），程序在片间运行。用「小停顿 × 多次」代替「一次大停顿」。

增量回收的关键是**追踪状态持久化**：上次做到哪、下次从哪继续——GC 的中间状态要保存下来。每小片像「断点续传」的一次续跑。

优点：停顿可预测、上界可控。
难点：程序在片间改变了对象图，增量追踪要处理「变化」。

**辨析｜易错点：** 增量式 ≠ 并发式：增量式是**交替**执行（GC 片与程序片轮流，总有一个在跑），并发式是**并行**执行（GC 与程序同时在多核上跑）。增量式实现更简单，但「停顿总量」可能仍不小；并发式把停顿压得更低，但并发同步更复杂。<span class="marginnote">「增量是时间片轮流、并发是空间并行」是最易混淆的一对：增量式像「限时清理」（干一会儿程序，再干一会儿 GC），并发式像「两个工人同时干活」（GC 线程与业务线程并行）。现代 JVM 的 G1 是「增量 + 并发」混合——分小步做，且能并行的部分并行跑。</span>

## 3 三色标记：并发的正确性协议

**三色标记（tri-color marking）** 是并发标记的经典框架，给对象涂三种颜色：

- **白色**：尚未发现（可能是垃圾）。
- **灰色**：已发现、但**引用未全部处理**（在队列中待扫）。
- **黑色**：已处理完所有引用（确定为存活）。

标记过程 = 「把白色变成灰色，再扫灰变黑」——最终黑色是存活，白色是垃圾。

**三色不变式（tri-color invariant）** 保证并发标记不犯错：

$$\text{不存在「黑色对象指向白色对象」的边}$$

- 黑色对象已处理完、不会再被扫——若它指向白色对象，那个白色对象会被误判为垃圾。
- 并发时程序可能**把黑色对象改成指向白色对象**——违反不变式，就必须**写屏障**拦截并「把黑色涂回灰色」（重新扫描）。

**写屏障维护不变式**：程序写入 `b.f = w`（黑色对象指向白色对象）时，写屏障把 `b` 涂回灰色（或把 `w` 涂灰）——保证「黑色不指白」恒成立。<span class="marginnote">「三色标记 + 写屏障」是并发 GC 的黄金组合：GC 在跑标记（灰→黑），程序在改引用（可能黑→白），写屏障保证「黑的不会偷偷指向白的」。这个不变式让「GC 与程序并发」成为可能——它是现代并发 GC 的理论基石。</span>

## 4 公式解析：三色不变式的维护

设对象集合为 $W$（白）、$G$（灰）、$B$（黑）。并发标记的正确性条件是：

$$\forall b \in B,\ \text{refs}(b) \cap W = \emptyset$$

- **第一步，不变式语义**：任何黑色对象的所有引用，都指向灰色或黑色——白色对象永远不会被「已扫完」的黑色对象指向。
- **第二步，破坏时机**：程序执行 `b.f = w`（$b \in B, w \in W$）——不变式被破坏。
- **第三步，写屏障修复**：写屏障把 $b$ 涂回灰色（$B \to G$）——`b` 被重新扫描，其引用重新处理，`w` 被涂灰，不变式恢复。

**「写屏障 = 不变式的守护者」**——每次可能破坏不变式的写入，都被拦截并修复。维护不变式，并发标记就永远不会错杀白色存活对象。

## 5 现代并发 GC：G1 与 ZGC

现代 JVM 的并发 GC 把上述思想推向极致：

- **G1（Garbage First）**：把堆分成大量**等大小区域（region）**，优先回收「垃圾最多的区域」（Garbage First）；标记用三色 + 写屏障；停顿**可预测**（-XX:MaxGCPauseMillis 目标）。
- **ZGC**：用**染色指针（colored pointers）** 在指针位里存标记状态，读写几乎零屏障；并发标记、并发整理——停顿低至**亚毫秒**，且与堆大小无关。

它们共同的哲学：**把「全堆扫」变成「分区域/染色」**，把停顿从「堆大小决定」变成「可配置常量」。<span class="marginnote">「染色指针」是 ZGC 的黑科技：64 位指针里抽几位存「标记位、移位移」——GC 状态不靠对象头，而靠指针本身。这让并发标记/移动几乎零同步开销，停顿降到 1ms 以下。理解三色 + 写屏障，就能理解 ZGC 的染色指针「存了什么」——它是三色状态搬进指针的实现。</span>

## 6 一次并发标记的完整走查

把三色标记 + 写屏障放在一个具体场景里走完。设 GC 正在并发标记，对象图里有黑、灰、白三类，且堆含对象 O（黑）、P（灰）、Q（白）。

- **并发进行中**：GC 线程把 P 从灰变黑（处理 P 的引用）；P 指向 Q，Q 从白变灰——正常推进。
- **程序线程运行**：程序执行 `O.ref = Q`——黑对象 O 现在指向白色 Q（Q 还是白的，因为它的引用还没处理）——**三色不变式被破坏**。
- **写屏障介入**：写屏障检测到「黑色对象写入指向白色对象的引用」，把 O 涂回灰色，并把 Q 涂灰——不变式恢复。
- **GC 继续**：O 作为灰色重新进队列，扫描到它指向 Q，Q 保持灰色直至处理完变黑。结束时不变量成立：黑不指白，Q 被确认为存活。

**要点**：没有写屏障，GC 可能已经扫过 O（把 O 当黑色收尾），而程序随后给 O 指向 Q——Q 就会在 GC 结束时被误判为垃圾。写屏障的「把黑涂回灰」让 GC「回头再扫一次」，堵住了这个错杀漏洞。<span class="marginnote">「黑涂回灰 = 让 GC 回头再扫」是这个走查的枢纽：<strong>黑色表示「已处理完、不再看」，但程序一写入，它就「不再可信」</strong>——涂灰就是「撤销已处理完的结论」。GC 的并发正确性，靠的就是这种「随时准备撤销」的机制。</span>

**辨析｜易错点：** 写屏障是「修复式」而非「预防式」——它不阻止程序写入，只保证「写入后不变式仍成立」。理解「不阻止、只修复」，就理解了并发 GC 为什么能与程序「相安无事」地并行。

## 7 思考与练习

**练习 1 停顿来源**：列出全停顿的三种来源（标记、复制、清扫），各说明「为什么随堆大小增长」——体会「停顿 ∝ 堆大小」的根源。

**练习 2 增量 vs 并发**：对比「增量式（时间轮流）」与「并发式（空间并行）」——各画一张时间线图，标出停顿段与运行段。

**练习 3 三色标记**：对一个对象图，手动跑一遍「白 → 灰 → 黑」的标记过程，标出每个对象的颜色变化——验证结束时「黑 = 存活、白 = 垃圾」。

**练习 4 写屏障修复**：构造一个「程序写入 `b.f = w`（黑对象指向白对象）」的场景，说明写屏障如何「把黑涂回灰」恢复三色不变式。<span class="marginnote">「把黑涂回灰」是写屏障的修复动作：黑色对象原本「已处理完引用」，但程序给它指向了白色——若不管，白色会被误判为垃圾。涂回灰色 = 「重新扫描它」，它的新引用（白色）也被处理——不变式恢复，不错杀。理解这一步，就理解了并发标记的正确性协议。</span>

**练习 5 不变量论证**：用「三色不变式」论证「黑色对象不指向白色 → 白色对象不会被误判」——把「为什么写屏障维护不变式就安全」写清楚。

**练习 6 现代 GC 调研**：读 G1 或 ZGC 的简介文档，找「分区域」「染色指针」「并发标记」的对应——把三色思想映射到工业实现。

**常见误区**：

- **误区一**：把「增量」与「并发」混为一谈——增量是时间片轮流、并发是多核并行。
- **误区二**：以为「三色标记是算法」——它是「并发标记的正确性协议」，不是回收算法本身。
- **误区三**：忽略写屏障——没有写屏障，并发下标记会错杀存活对象。

**延伸**：三色标记 + 写屏障的「并发正确性协议」与第四级《分布式系统》的「并发控制、读写屏障」是同一主题——把「GC 的并发正确性」与「数据库的并发正确性」对比，找「屏障/日志」的共性。

## 8 小结

- **停顿**是 GC 的痛点，时长 ∝ 堆大小；增量/并发 GC 的目标是把停顿压到「可接受」。
- **增量式**把回收切成小片穿插执行（时间轮流）；**并发式**让 GC 与程序并行（多核同跑）。
- **三色标记**：白（未发现）/灰（已发现未处理完）/黑（已处理完）；标记 = 白→灰→黑。
- **三色不变式**「黑色不指白色」是并发标记正确性的保障；**写屏障**在破坏时把黑涂回灰。
- 现代并发 GC：**G1**（分区域 + 可预测停顿）、**ZGC**（染色指针 + 亚毫秒停顿）——把停顿变成常量。
