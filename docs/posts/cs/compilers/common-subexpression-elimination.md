# 公共子表达式消除

<div class="epigraph">
<p>同一个算式算了两遍，编译器就有理由让它只算一遍。</p>

## 为什么从公共子表达式消除开始

第七篇的局部优化在**块内**做 CSE，但真正的重复计算常常**跨块**：同一个表达式在两条分支里都算、或在一个大循环体里反复算。要跨块合并，需要知道「这个表达式在到达此点时是否**一定已算过且结果仍有效**」——这正是上一节「可用表达式」分析提供的知识。**全局 CSE（global common subexpression elimination）** 把局部的 DAG 去重升级为跨块的复用。<span class="marginnote">「局部 CSE 看块内、全局 CSE 看块间」的分工很清晰：局部用 DAG 唯一化（看得见的都去重），全局用可用表达式分析（跨块的「一定算过」）。两者叠加，几乎消灭了所有「同值重复计算」。</span>

## 1 从局部到全局

**局部 CSE**（块内）：`b * c` 在同一块内 → 复用。

**全局 CSE**：两条路径各算了 `b * c`，汇合点之后又算 `b * c`：

```c
if (cond)
    x = b * c;      /* 路径 1：算 b*c */
else
    y = b * c;      /* 路径 2：也算 b*c */
z = b * c;          /* 汇合点之后：又算 b*c */
```

若 `b * c` 在汇合点**可用**（所有路径都算过且 b、c 未变），则 `b * c` 可复用前次结果。

**核心区别**：局部 CSE 是「块内顺序执行，看得见就算过」；全局 CSE 要证明「**所有**到达路径都算过」——这必须用可用表达式分析（取交的「全称」语义）。<span class="marginnote">全局 CSE 对「可用表达式取交」的依赖，解释了为什么可用表达式分析汇合取「交」而非「并」：只有「所有路径都可用」才能安全复用；「某条路径算过」不够，因为程序可能走的是没算过的那条路。</span>

## 2 全局 CSE 的算法

全局 CSE 的典型做法（龙书）：

1. **可用表达式分析**：对每个基本块算 `GEN`/`KILL`，得到「块入口处哪些表达式可用」。
2. **块内替换**：在块内顺序扫描，维护「当前可用表达式 → 存放结果的临时变量」的映射。遇 `b * c`：
若 `b * c` 在映射里（可用），把指令改为 `t1`（复用）。
否则：`b * c` 的计算本身就是「生成」，记录映射。
若 `b` 或 `c` 在块内被重新赋值，从映射里删除所有含它们的表达式。

第 3 步的「失效处理」与块内 DAG 的「当前值」异曲同工：操作数一变，含它的表达式全部作废。<span class="marginnote">「操作数被赋值 → 含它的表达式失效」是 CSE 的安全闸门：`b`（操作数）一旦被改，`b * c` 就不再是「同一个值」。块内维护这个失效表，全局分析提供「块入口的初始可用集」，两者配合，跨块复用才安全。</span>

## 3 复用的实现：临时变量接替

把重复计算替换为「复用临时变量」：

```c
/* CSE 之前 */        /* CSE 之后 */
x = b * c;            t1 = b * c;
...                   x = t1;
y = b * c;            ...
                      y = t1;
```

关键是第一次计算的结果要**存活**到复用点：`t1` 必须在中间不被覆盖。这又回到了活跃变量/寄存器的地盘——所以 CSE 通常与寄存器分配协同：CSE 减少了计算，寄存器分配保证被复用的临时变量活得够久。<span class="marginnote">「CSE 减计算、分配保存活」是优化器内部的协作：CSE 制造「跨点复用」，复用的前提是中间值不被覆盖。若 t1 的存活时间太长，可能会被溢出到内存——那就变成「内存换少算」，是否划算由代价模型决定。</span>

## 4 公式解析：CSE 的安全前提

把「在点 $p$ 复用 `b * c`」的正确性条件写清楚：

$$\text{安全} \iff a \ op \ b \in \text{AVAIL}(p)$$

其中 $\text{AVAIL}(p)$ 是 $p$ 处的可用表达式集合——它同时保证「**所有**到达路径都算过」与「自算过以来 `b`、`c` 都未被修改」。

- **第一步，算过且有效**：可用表达式的定义（全路径算过 + 操作数未变）正好是两个必要前提。
- **第二步，复用**：把 `b * c` 的计算替换为「读那个已算好的临时变量」——值相等，因为操作数未变。
- **第三步，保守**：只要可用表达式分析稍有不确定（如别名修改），编译器就放弃复用——宁多算一次，不读错值。

**「可用表达式是复用的许可证」**——拿到许可证才动手，这是 CSE 的正确性纪律。

## 5 CSE 的现代形态与局限

- **SSA 时代的 CSE**：LLVM 的 `GVN`（Global Value Numbering）给每个「计算」编号，相同编号的值直接统一——比「表达式文本匹配」更准（能识别 `b * c` 与 `c * b` 同值）。
- **DAG 与 CSE 的关系**：局部 DAG 的「唯一结点」是 CSE 的图论版本；全局 CSE 是它的流图推广。
- **局限**：
  - **不能跨「操作数被改」的点**：别名（两个指针指向同一内存）让「是否被改」难判断——保守放弃。
  - **浮点不适用**：`b * c` 的两次浮点求值结果可能因舍入环境不同而不同——编译器常只对整数做 CSE。

**辨析｜易错点：** CSE 不是「文本相同就合并」——它合并的是「**值**相同」的计算。`a + b` 与 `b + a` 文本不同但值相同（整数加法交换），GVN 能合并；`a + b` 与 `a - b` 文本不同值也不同，不能合并。判断标准是「值」而非「字」。<span class="marginnote">「值编号（value numbering）」是 CSE 的现代核心思想：给每个「语义值」一个编号，同编号即同值——文本、顺序、甚至不同的表达式只要算出的值确定相同，都能统一。GVN 是「以值为中心」的 CSE，比「以表达式为中心」的朴素版强大得多。</span>

## 6 一个全局 CSE 的完整走查

把全局 CSE 的算法落在一个具体例子上。程序：

```c
if (c) x = a * b;   /* 块 1：算 a*b */
else   y = a * b;   /* 块 2：也算 a*b */
z = a * b;          /* 块 3（汇合）：又算 a*b */
```

**可用表达式分析**：块 1 的 GEN = {a*b}，块 2 的 GEN = {a*b}；块 3 的入口可用集 = 前驱出口的**交** = {a*b}（两分支都算过且 a、b 未被改）。

**块 3 的替换**：`z = a * b` 在入口可用——但「复用什么」？块 1 的结果在 x、块 2 的结果在 y——两者不同名，怎么复用同一个值？

**龙书的做法**：在分支里把 a*b 结果放进**同一个临时变量** `t`：
```c
if (c) { t = a * b; x = t; }
else   { t = a * b; y = t; }
z = t;             /* 汇合点：直接读 t */
```

**要点**：全局 CSE 不是「随便复用」，而是**统一临时变量**——让两个分支把结果存进同名 t，汇合点才能安全读 t。这个「分支统一临时变量」的细节，是全局 CSE 与局部 CSE 最实质的差别。<span class="marginnote">「统一临时变量」也解释了全局 CSE 为什么需要「复制传播」的配合：`x = t`、`y = t` 是复制指令，后续若把 `x`、`y` 的使用都换成 `t`，复制指令本身还能被死代码消除清掉。CSE、复制传播、DCE 是一组「连锁反应」的优化——一个触发下一个。</span>

**辨析｜易错点：** 若两条分支里 a*b 的**结果名不同**（x 与 y），不能直接在汇合点复用 x 或 y——因为走假分支时 x 没有定义。必须让两分支都写同一个 t，汇合点读 t 才安全。这是全局 CSE「跨块复用」最容易踩的坑。

## 7 思考与练习

**练习 1 可用表达式**：对基本块 `x = b * c; b = 5; y = b * c;`，用可用表达式分析标出「`b * c` 在 `y = b * c` 处是否可用」——并说明 `b = 5` 之后 `b * c` 为什么不可用。

**练习 2 全局 CSE**：把 `b * c` 的重复计算放到两个分支块（`b * c` 各算一次），汇合点用全局 CSE 复用——验证「所有路径都算过」的前提。

**练习 3 失效处理**：`b = 1; x = b * c; b = 2; y = b * c;`——第二次为什么不能复用？在块内 CSE 的「操作数被赋值即失效」规则里找到答案。<span class="marginnote">这是 CSE 安全边界的核心练习：`b` 被重赋值后，含 `b` 的表达式从「可用映射」里删除——第二次 `y = b * c` 里的 `b * c` 是新值，与第一次不同。若忽略失效，就会错误复用旧值，编译错。理解「失效」= 理解 CSE 为什么保守。</span>

**练习 4 GVN 对比**：把「表达式文本匹配」与「值编号（GVN）」对比——`a + b` 与 `b + a`（整数加法）文本不同但值相同，GVN 为何能合并？

**练习 5 浮点限制**：解释为什么浮点 CSE 常被禁止——`b * c` 的两次结果可能因舍入/环境不同而不同，复用旧值可能改变结果。

**练习 6 与局部 CSE 衔接**：把「局部 DAG CSE」（第五十节）与「全局可用表达式 CSE」的覆盖范围写清楚——块内谁做、跨块谁做。

**常见误区**：

- **误区一**：以为「文本相同就合并」——CSE 合的是「值」相同，`a + b` 与 `b + a` 文本不同但值同。
- **误区二**：忽略「全路径」——全局 CSE 要求所有路径都可用（取交），一条路径算过不够。
- **误区三**：忘记失效——操作数被赋值后，含它的表达式必须从可用集合删除。

**延伸**：CSE 的「可用表达式」分析是第八篇数据流框架的实例（向前、取交）——把「可用表达式」与「到达定值」「活跃变量」放在同一张数据流对比表里，总结「方向 × 汇合」四象限。

## 8 小结

- **全局 CSE**跨块合并重复计算，靠**可用表达式分析**证明「所有路径都算过且结果有效」。
- 算法：可用分析给入口初始集，块内顺序扫描维护「可用表达式 → 临时变量」映射，操作数被赋值即失效。
- 复用实现为「读临时变量」；被复用的临时变量要**存活**到复用点，与寄存器分配协同。
- 安全前提 = `a \ op \ b \in \text{AVAIL}(p)`：全路径算过 + 操作数未变；保守原则宁多算不读错。
- 现代形态是**值编号（GVN）**，按「语义值」合并；别名与浮点会限制 CSE 的适用范围。
