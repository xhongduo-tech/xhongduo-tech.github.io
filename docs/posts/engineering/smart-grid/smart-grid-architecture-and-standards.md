## 为什么从架构与标准开始

**智能电网（Smart Grid）**：利用数字通信、传感与自动化技术，对电力的发、输、配、用全过程进行实时感知、双向交互与优化控制的新型电力系统。<span class="marginnote">美国能源部（DOE）的经典表述：智能电网用数字技术探测并响应局部用电的实时变化，实现「感知—决策—执行」的闭环。这个定义在本专题开篇定下基调：电网从「铁的机械系统」变成「会思考的机械系统」。</span>

学智能电网，最忌讳一上来就扎进某个协议或装置。电网是迄今人类建造的**最庞大的人造系统**：数以亿计的用户、数十万千米的线路、跨越多家运营商与多个国家。要理解这样的巨系统如何被改造，必须先回答两个问题：**它的顶层结构是什么、靠什么让千厂商的设备和睦相处**——前者是架构（architecture），后者是标准（standards）。这两件事互为表里：架构画出系统的骨架，标准规定骨架上每个接头的形状。Borlase 的教材把这两章放在全书之首，正是这个道理。

## 1 为什么传统电网不够用了

先看一张「传统电网」的简图：发电厂（火电、水电）→ 升压变电站 → 超高压输电线路 → 降压变电站 → 配电线路 → 用户。能量**单向流动**，信息几乎不回流。这样一个系统运行了一百多年，它的局限在当代被放大了三倍：

**一是单向性。** 电能只从发电侧流向用户侧，用户永远是「受体」。可当分布式光伏、电动汽车大量出现，潮流开始反向，单向设计的保护、计量、调度逻辑全部失灵。<span class="marginnote">配网潮流反向后，传统的「辐射状单向保护」不再成立，这会直接牵连本专题《分布式能源接入》《微电网》两讲。这里是伏笔。</span>

**二是感知缺失。** 变电站以外，电力公司对自己资产的实时状态近乎「盲」的。停电了只能等用户打电话报修，然后派人沿线排查。

**三是响应迟缓。** 传统电网应对扰动靠「过量的备用容量」硬扛，而不是靠实时调节。

智能电网的回答是给电网装上**神经系统**：在关键节点布置传感器与量测（AMI、PMU），用通信网络把数据汇聚，用信息系统做分析决策，再把指令送回可控设备。于是电网从「一条单向管道」变成「一个双向的信息物理系统」——这就是后文所有专题的总纲。

还要强调一点：**传统电网向智能电网的迁移不是「推倒重来」**，而是在保留物理资产的前提下逐层叠加数字能力——先在关键节点加量测（感知），再铺设通信（神经），最后上分析应用（大脑）。这种「渐进式升级」正是《软件工程》里「演进式架构」的缩影：老系统不能停机，新能力只能一层层长出来。

## 2 智能电网的四层架构

把智能电网从上到下切一刀，可以分成四个层次：

**电力层（Power Layer）**：发电、输电、配电、用电的物理设备——变压器、开关、线路、负荷。这是电网的「躯体」。
**传感与量测层（Sensing & Measurement Layer）**：智能电表、PMU、变压器状态监测、架空线路传感器。这是电网的「感官」。
**通信层（Communication Layer）**：光纤、无线、电力线载波组成的通信网，负责把感官的信号送回大脑。这是电网的「神经」。
**应用层（Application / IT Layer）**：SCADA、EMS、DMS、MDMS、停电管理等系统，负责分析决策。这是电网的「大脑」。

<span class="marginnote">把架构切成层是系统工程的标准动作。如果你学过《计算机网络》，会发现这四层与 TCP/IP 五层模型的心法完全同构：下层向上层提供透明的服务，每层只关心与相邻层的接口。层间解耦是系统得以演进的根基。</span>

这四层不是各自为政，而是靠两个方向的**数据流**耦合起来：向上的「量测流」与向下的「控制流」。智能电网区别于传统电网的本质特征，就是这两股流都是**双向的、实时的**。下面这张图把四层与双向数据流画在一起：

「信息物理系统（CPS）」这个词也值得单独拿出来说——它指「物理过程与计算/通信深度融合的系统」。智能电网正是 CPS 的原型：电网的物理规律（潮流、频率）与数字世界的算法（优化、学习）互相咬合，任何一方都离不开另一方。理解 CPS，就抓住了智能电网的本质，也为后面理解《微电网》《EV/V2G》里的「自治控制」打下思想基础。

**重点：** 一张架构图的价值不在「画得像」，而在它给出了一个**判断坐标**——任何一项智能电网技术，你都可以问：它处在哪一层？它利用哪条数据流？它和上下层之间的接口是什么？拿着这把尺子，本专题的每一讲（AMI、配电自动化、微电网……）都有了明确的定位。<span class="marginnote">「用坐标判断技术」是这套课程反复训练的核心习惯：读完本专题每一讲，都试着把该讲的技术放进「层 × 域 × 数据流」的坐标系里定位。当你能在一分钟内说出「它属于哪一层、横跨哪几域、靠哪条数据流」时，你就真正读懂了智能电网的地图。</span>

## 3 域：NIST 七域概念模型

四层架构是「纵向切」，还有一个「横向切」：把电网按**业务角色**分成若干**域（domain）**。美国国家标准与技术研究院（NIST）在其《智能电网互操作标准框架》（NIST Framework and Roadmap, SP 1108）中提出了著名的**七域概念模型**：

| 域 | 角色 | 典型实体 |
| --- | --- | --- |
| 发电（Bulk Generation） | 大规模集中发电 | 火电、水电、核电、大型风电场 |
| 输电（Transmission） | 高压输电与调度 | 输电运营商、EMS |
| 配电（Distribution） | 中低压配电与供电 | 配电公司、DMS、FTU |
| 用户（Customers） | 用电与产电 | 家庭、工厂、EV、光伏 |
| 市场（Markets） | 电力交易与定价 | 交易所、售电公司 |
| 运营（Operations） | 运行监控与维护 | 调度中心、SCADA |
| 服务提供（Service Provider） | 第三方增值服务 | 聚合商、储能服务商 |

域与域之间有大量的**信息交互接口**（例如「市场→发电」的竞价信号、「运营→用户」的需求响应指令）。NIST 模型最大的贡献是：它让标准制定者知道**该在哪两个角色之间定协议**。域模型是后文每一讲的「地图」——提到 AMI，你知道它横跨「用户」「运营」两域；提到需求响应，它连接「市场」「用户」「运营」三角。<span class="marginnote">NIST 七域模型与《软件架构》里的「架构视图」思想同构：纵向四层是「分层视图」，横向七域是「角色视图」，两个视图叠加才构成完整图景。它同时启发我们——任何复杂系统的架构，都要靠「多个正交的切面」才能讲清楚。</span>

## 4 标准：让千厂商的设备说同一种语言

架构画好了，谁来保证南方电网的变压器能和华北的调度系统对话、华为的电表和施耐德的采集终端互认？答案是**标准**。智能电网的标准化体系可以按「横坐标=层级、纵坐标=功能」来记忆，核心标准族有四条主线：

**变电站与自动化（站内）**：IEC 61850——把变电站内的智能设备（IED）用统一的对象模型和通信协议连起来，本专题《智能变电站与 IEC 61850》整讲展开。
**信息模型（系统级）**：IEC 61970 / 61968（CIM，公共信息模型）——用统一的数据模型描述电网对象（设备、拓扑、测量），让 EMS、DMS、GIS 等系统能互相交换数据。<span class="marginnote">CIM 的野心是给整个电网世界的概念（变压器、母线、遥测）制定一部「词典」。如果你学过数据库与《知识图谱》相关课程，会发现 CIM 的本质就是一种领域本体（ontology）——用 RDF/XML 表达、用语义定义类与关联。</span>
**分布式电源与用户侧**：IEEE 1547——分布式电源（光伏、储能等）并网的技术要求；IEEE 2030——智能电网与用户侧互操作指南。
**量测与需求响应**：ANSIC12 / IEC 62056（DLMS/COSEM）——电表数据与通信；OpenADR——需求响应信号的标准格式。
**安全**：IEC 62351——为上述通信提供加密与认证的「安全底座」。

**辨析｜易错点：** IEC 61850 管的是「变电站站内」，IEC 61970/61968（CIM）管的是「调度系统之间」，IEEE 1547 管的是「分布式电源并网点」。三者名字都带数字、内容互不相同，初学极易混记。记法：**站内、站间、并网点**——一个词对应一个标准族。

标准写出来只是第一步，真正让千厂商的设备「坐在一起」还要靠**一致性测试与互操作认证**：第三方实验室按标准逐项测试设备的「语言能力」，再办「互操作大会」（plugfest）让不同厂商的设备现场联调。这与《软件工程》里的「接口契约、测试与 CI/CD」是同一个道理——标准是契约，测试是履约的保障。

## 5 公式解析：可用率——架构的终极成绩单

架构与标准的优劣，最终都要落到一个数上：**系统有多可靠**。可靠性的第一号公式是**可用率（availability）**：

$$
A = \frac{\text{MTTF}}{\text{MTTF} + \text{MTTR}}
$$

- **MTTF（Mean Time To Failure）**：平均无故障时间，反映设备「多久坏一次」。<span class="marginnote">MTTF 与 MTTR 都来自可靠性工程（如 IEC 61709 与 MIL-HDBK-217 的失效数据）。若设备失效率 λ 恒定，则 MTTF = 1/λ——与《概率论》里的指数分布直接对应：指数分布正是「无记忆性」的失效模型，也是排队论里经典的假设。</span>
- **MTTR（Mean Time To Repair）**：平均修复时间，反映「坏了多久能修好」。
- **含义**：$A$ 是设备处于可用状态的时间占比。若一台变压器平均 5000 小时坏一次、修一次 50 小时，则 $A = 5000/5050 \approx 0.9901$，即约 99% 的时间可用。

三步拆解：**第一步**，看分子——MTTF 越大越好，这靠设备质量与预防性维护；**第二步**，看分母里多出的 MTTR——它说明：**架构的价值不只在于「少坏」，更在于「坏得快修、坏得快隔离」**。这就是本专题《电网自愈与可靠性》一讲的核心动机：自愈系统的本质，是用自动化把 MTTR 从「小时」压到「秒」；**第三步**，把多个设备串起来，系统可用率是各设备可用率的乘积——串联越多、越脆弱，这解释了为什么电网强调「N-1」冗余。

**公式的直觉**：$A$ 就像一个「出勤率」。一个人不生病（MTTF 大）、生病好得快（MTTR 小），出勤率就高。智能电网的通信、量测、自动化，本质上都是在给电网这台机器「缩短病假」。

**串联的脆弱性值得单独算一笔账**：若一条数据链路要经过「采集终端 + 通信通道 + 主站服务器」三个环节，各自可用率都是 99%，则整条链路可用率 = 0.99³ ≈ 97%——三个九变两个九。若每个环节都提升到 99.9%，则 0.999³ ≈ 99.7%。**这说明：串联环节越多，每个环节的可靠性要求就越高**——也解释了为什么电网的骨干通信要坚持「冗余与确定性」的哲学（见《智能电网通信网络与信息安全》一讲），以及为什么架构设计要尽量减少不必要的串联环节。

这个结论还引出一个设计原则：**关键路径尽量「并联」而非「串联」**。比如调度中心到变电站的数据链路，若只有一条光纤就是串联瓶颈；配上冗余通道（双光纤，或光纤 + 无线互为备份），链路就从「串联单点」变成「并联备份」，可用率大幅提升——这正是下一讲「冗余与确定性」哲学的前奏。

## 6 小结

- 智能电网的本质：在物理电网之上叠加**感知、通信、控制**，形成双向数据流的**信息物理系统**。
- 纵向四层：**电力层、传感量测层、通信层、应用层**；横向七域：发电、输电、配电、用户、市场、运营、服务提供。
- 架构是骨架、标准是接口规范；核心标准族：**IEC 61850（站内）、IEC 61970/61968 CIM（站间）、IEEE 1547（并网点）、IEC 62351（安全）**。
- 可用率公式 $A = \text{MTTF}/(\text{MTTF}+\text{MTTR})$ 揭示：可靠性的提升既靠「少坏」也靠「快修」。
- 串联环节的可用率相乘：环节越多、每环要求越高——架构设计要尽量减少不必要的串联点，骨干通信要「冗余 + 确定性」。
- 标准是「写在纸上的契约」，要靠**一致性测试与互操作认证**落实——这与其他工程领域的接口工程同理。
- 与课程接口：**计算机网络**（分层模型、接口契约）、**系统工程**（架构视图、正交切面）、**概率**（串联可靠性）。
- 智能电网是**信息物理系统（CPS）**的原型：物理规律与数字算法互相咬合；向智能电网的迁移是「逐层叠加」的演进式升级，而非推倒重来。
- 判断任何一项智能电网技术的口诀：**它在哪一层？横跨哪几域？靠哪条数据流？**——三个问题答清，技术定位就清晰了。
- 串联环节越多、可用率衰减越快；关键路径要「并联冗余」而非「串联单点」。
- NIST 七域 + 四层架构是「地图」，标准是「接头的形状」——带着地图和尺子读后面的每一讲。

在下一节，我们将走下架构图，进入这四层中承上启下的**通信层**——看看电网里的数据是靠哪些网络和技术运走的，以及为什么信息安全会成为智能电网的生死线。这就是《智能电网通信网络与信息安全》。
