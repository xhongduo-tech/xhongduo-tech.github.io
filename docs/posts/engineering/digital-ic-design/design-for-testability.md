## 为什么从可测试性开始

设计方法学一章把芯片做到了「流片」，但流片只是开始——**晶圆上刻出来的每颗芯片，都可能带着制造缺陷**：一根金属线断了、一个掺杂浓度偏了、一粒尘埃让两层短路。一颗包含百亿晶体管的芯片，出厂时一个缺陷都没有的概率极低。**可测试性设计（Design for Testability, DFT）** 回答的是：如何在芯片里「埋下探针」，让测试仪能快速判断每一颗芯片是好是坏、坏在哪。<span class="marginnote">Rabaey 把测试作为全书的收尾（Design Methodology Insert H：Validation and Test of Manufactured Circuits），Weste & Harris 第14章（Test）则系统给出扫描、BIST、ATPG 三件套。本专题第十一篇把它们与前面的设计流程串成闭环。</span>

测试不是「流片之后的事」，而是**设计时就要考虑**的：扫描链要插在综合阶段、BIST 要留出面积、边界扫描要布在 I/O 旁。一个「可测性好」的芯片，测试成本低、良率数据准、返工周期短——DFT 是设计方法论里与功耗、时序并列的第四大支柱。

测试的代价还有一面是「时间」：一片晶圆上几千颗芯片，每颗都要逐一测试，测试时间直接决定产能与成本。所以 DFT 的每一个决定——扫描链几条、BIST 覆盖哪块、JTAG 怎么串——最终都换算成「每颗芯片要测几秒」这个数字。

历史上，测试成本随芯片规模指数上升，而「把可测性设计进芯片」让测试从「几何级负担」降到「线性开销」——这是 DFT 从「可选优化」变成「行业标配」的根本原因。Weste & Harris 第14章开篇就强调：测试不是验证功能的仿真，而是制造之后的「体检」，两者目的不同、方法也不同。

## 1 缺陷、故障模型与覆盖率

制造出来的物理缺陷（defect）五花八门，测试不可能逐一穷举。工程上把它们**抽象成故障（fault）模型**，最经典的是**固定故障（stuck-at fault）**：假设一条信号线要么固定为 0（stuck-at-0）、要么固定为 1（stuck-at-1）。一颗芯片的任何物理缺陷，只要能让某条线固定在某电平，就落进这个模型。<span class="marginnote">此外还有<strong>转换故障（transition fault，延迟型）</strong>、<strong>桥接故障（bridge fault，两线短路）</strong>等模型。固定故障模型最简单、覆盖最广，是 ATPG 与覆盖率统计的基准——一个「全覆盖」的测试通常指固定故障覆盖 98% 以上。</span>

**测试覆盖率（fault coverage）** 定义如下：对芯片上全部可测试故障集合 $F$，测试向量能**检测**到的故障集合 $F_d$ 占比

$$FC = \frac{|F_d|}{|F|}$$

一个故障「被检测」的判定式也很朴素：

$$\text{故障 } f \text{ 被检测} \iff \exists\, v:\ good(v) \ne faulty(v)$$

**第一步，读 $good(v)$**：无故障电路在测试向量 $v$ 下的输出；**第二步，读 $faulty(v)$**：注入故障 $f$ 后电路在 $v$ 下的输出；**第三步，读不等号**：两者不同，说明故障被「暴露」到了输出——这正是故障仿真逐位比对的全部含义。

**第一步，读分子**：$|F_d|$ 是被测试向量「抓住」的故障数——一个故障被检测，指至少有一个测试向量让好芯片与坏芯片的输出不同；**第二步，读分母**：$|F|$ 是所有固定故障数，约等于「可观测节点数 × 2」；**第三步，读目标**：工业界以 $FC \geq 98\%$ 为门槛——低于此值，漏掉的故障可能让坏芯片混入出货，是可靠性的硬约束。<span class="marginnote">覆盖率的另一半是<strong>测试生成（ATPG）</strong>要做的：自动找出能检测每个故障的最小测试向量集。而测试成本与向量数成正比，所以「覆盖率 × 向量数」是 DFT 的核心权衡。</span>

**辨析｜易错点：** 覆盖率 ≠ 良率，也不等于「这颗芯片是好的概率」。覆盖率说的是「测试把设计里的故障抓住了多少」，良率说的是「晶圆上造出来的芯片有多少是好的」。高覆盖率是「把该测的都测了」的保证，但测不到的（未建模的）缺陷依然可能漏网。

## 2 扫描链：给寄存器装上「读写口」

测试的难点在于**可控性与可观测性**：芯片内部的节点，输入够不着、输出看不见。**扫描链（scan chain）** 一举解决这个问题：给每个触发器加一个测试模式（scan mode），把它们的输入切换成**串联成一条移位寄存器链**。

正常模式（functional mode）下，扫描触发器像普通 DFF 一样工作；**测试模式（scan mode）**下，所有触发器被串成一条大移位寄存器：测试数据从 `scan_in` 逐位**移入**，捕捉一拍组合逻辑的结果，再从 `scan_out` **移出**。于是「设内部任意触发器为任意值、读内部任意触发器的值」都变成了往一条移位寄存器里搬数据——**可控性与可观测性同时获得**。<span class="marginnote">Weste & Harris 第14章点破扫描的本质：它把「复杂时序电路测试」降维成「组合逻辑测试 + 移位寄存器测试」两件简单事。代价是每个触发器多约 2 个门的面积、多一根扫描时钟，以及测试时的时间开销。</span>

**辨析｜易错点：** 扫描不是「测扫描链本身」，扫描链是**手段**——它让内部状态变得可控可观测，从而让 ATPG 能对内部的组合逻辑生成测试。初学者常误以为「测试就是扫描移进移出」，其实扫描只是把「不可控的内部」变成「可控的端口」，真正测的还是组合逻辑本身。

扫描触发器的电路实现是一个「2:1 MUX + DFF」：正常输入 D 与扫描输入 `SI` 由 `scan_en` 选择。`scan_en=0` 时是普通触发器，`scan_en=1` 时输入改接 `SI`——于是整条链在测试模式下变成移位寄存器。这个 MUX 的加入，就是扫描触发器比普通触发器「多约 2 个门」的来源。<span class="marginnote">现代综合工具通常用「专用扫描触发器库单元」而不是「DFF + 外部 MUX」，因为前者把 MUX 做进触发器内部、路径更短、时序更好——这是库设计（本专题第十篇）与 DFT 相互渗透的一个例子。</span>

## 3 ATPG 与故障仿真：自动造测试向量

有了扫描结构，**自动测试向量生成（Automatic Test Pattern Generation, ATPG）** 就能系统地制造测试。经典算法基于 **D 算法 / PODEM / 二叉搜索**：为了「抓住」某个故障（如节点 X stuck-at-0），ATPG 反向推理出一组输入赋值，让节点 X 出现相反的逻辑值（激活故障），并把它的影响传播到一个可观测输出。<span class="marginnote">ATPG 的复杂度随电路规模指数上升，但现代工具用「约束 + 启发式 + 形式化」把超大设计压到可解。生成的向量还要经过<strong>故障仿真（fault simulation）</strong>验证：把每个故障注入逻辑网表，跑一遍向量，统计真正被检测到多少个，更新覆盖率。</span>

**公式解析：缺陷密度与良率**——一颗芯片做出来是好的概率（**良率 yield**）决定了「平均做几颗才有一颗能用」，成本核算的根基。在简单泊松缺陷模型下：

$$Y = e^{-D \cdot A}$$

**第一步，读 $D$**：缺陷密度，单位面积上的平均缺陷数（工艺越好 $D$ 越小，先进工艺目标在每平方厘米零点几的量级）；**第二步，读 $A$**：芯片面积——面积越大，碰到缺陷的概率越高，$D\cdot A$ 是「整片期望缺陷数」；**第三步，读直觉**：面积翻倍、良率按 $e^{-2D\cdot A}$ 指数塌陷——这就是为什么大芯片既贵又难产，也解释了「先做小片、再做大片」的工艺爬坡策略。<span class="marginnote">真实良率模型更复杂（含聚簇因子、边缘效应），但 $Y=e^{-DA}$ 给出了最清晰的直觉：<strong>良率是面积的指数函数</strong>。它把「设计多大」与「能造多好」直接挂钩——DFT 与冗余设计（如存储器冗余列）都是在良率上做文章。</span>

## 4 BIST：把测试仪装进芯片

**内建自测试（Built-In Self-Test, BIST）** 让芯片自己测自己，不依赖外部昂贵的自动测试仪（ATE）。最成功的 BIST 是**存储器 BIST**：给存储阵列旁边加一个小的测试状态机，按预设序列（如 March 算法）读写存储单元，自动报告「好/坏」与坏单元的地址。<span class="marginnote">March 测试是一组固定的读写序列（如 March C：升序写 0、升序读 0 写 1、降序读 1……），能高效暴露固定故障、转换故障与耦合故障。因为序列固定、状态机极小，它几乎不占面积，是 SRAM/DRAM 的标配。</span>

逻辑 BIST 用**伪随机测试**：用线性反馈移位寄存器（LFSR）产生伪随机向量灌入电路，再用特征分析（signature analysis）把输出压缩成一个签名，与好芯片的签名比对。<span class="marginnote">BIST 的哲学是「用芯片内部的逻辑资源换外部测试成本」：对复杂 SoC，一次完整的 ATE 测试时间与价格不菲，BIST 能离线或在线地快速自查，还能在芯片上电时做开机自检。缺点：随机向量的覆盖率通常达不到 98%，需配合 ATPG 的确定性向量。</span>

特征分析是 BIST 的「压缩器」：它把很长的输出序列压缩成几十位的签名——只要输出有一个 bit 不同，签名几乎必然不同（碰撞概率约 $2^{-w}$，$w$ 是签名位宽）。这样「比对整段输出」就被简化为「比对一段签名」，测试判定的硬件开销极小。<span class="marginnote">这背后是「多项式除法 + 循环冗余」的思想：LFSR 把输出序列当多项式，取除以特征多项式的余数作签名。它与软件里的 CRC 校验同源——硬件自检与数据校验共享同一套数学。</span>

**辨析｜易错点：** BIST 的「自测」不等于「不测试」——它只是把测试逻辑搬进了芯片。BIST 结果仍然需要被读出来（通过 JTAG 或专用引脚）并判定，而且 BIST 无法完全替代 ATPG 的高覆盖率确定性测试。两者的关系是互补：BIST 做「快速粗查 + 日常自检」，ATPG 做「出厂精测 + 高覆盖」。

**核心对比表：ATPG vs BIST**

| 维度 | ATPG（扫描+外部向量） | BIST（片上自测） |
| --- | --- | --- |
| 测试来源 | 工具离线生成、ATE 施加 | 片上 LFSR/状态机生成 |
| 覆盖率 | 可到 98%+ | 随机向量较低，需增强 |
| 硬件开销 | 扫描链（每触发器 2 门） | 额外 BIST 控制器/签名寄存器 |
| 适用 | 数字逻辑（面积适中） | 存储器、关键模块、系统级自检 |
| 成本 | 依赖昂贵 ATE 时间 | 降低外部测试成本，可开机自检 |

## 5 边界扫描与系统级测试

芯片与芯片之间怎么测？**边界扫描（boundary scan, IEEE 1149.1 / JTAG）** 在每个 I/O 引脚旁串一个「边界单元」，把它们也串成一条链：测试仪可以**绕过功能逻辑**，直接读写每一根引脚的状态——这在板级测试、多芯片互连验证、甚至调试（通过 JTAG 读写寄存器）中无处不在。<span class="marginnote">JTAG 几乎是每一颗现代芯片的标配五脚接口（TDI/TDO/TCK/TMS/TRST），既是测试口也是调试口。理解边界扫描，就理解了「芯片内部怎么测、芯片之间怎么连、软件怎么调」这三件平时分开讲的事其实共用同一套基础设施。</span>

系统级还常用**开机自检（POST）与在线测试（in-field test）**：利用 BIST 在芯片上电时快速自查、在运行间隙抽查，让「坏了能早知道」成为可能——这对汽车、医疗、航天等高可靠场景是硬需求。Rabaey 的 Insert H 正是把这些「制造后的验证」放在全书收尾，提醒设计者：流片不是终点，验证与维护才是。

## 6 可测试性设计速查

**可测试性术语速查表**

| 术语 | 一句话含义 |
| --- | --- |
| stuck-at | 固定故障模型（线固定 0 或 1） |
| FC | 测试覆盖率 |
| scan chain | 扫描链 |
| ATPG | 自动测试向量生成 |
| BIST | 内建自测试 |
| LFSR | 线性反馈移位寄存器 |
| JTAG | 边界扫描标准（IEEE 1149.1） |

一个经验量级帮助建立直觉：一颗 100 万门的 SoC，扫描链的总长可达数十万位，一次全扫描测试要「移入数十万位 + 捕捉一拍 + 移出数十万位」——所以测试时间与扫描链长度直接相关，而芯片测试费用按时间计费。这解释了为什么设计者要限制扫描链长度（分多条链并行扫描）、为什么**扫描压缩（scan compression）**成为标配。<span class="marginnote">扫描压缩用「每次移入一段压缩数据、片上解压」替代逐位移入，把测试时间压到原来的 1/10 甚至更低——它是「面积换测试时间」的典型交易，也是现代 DFT 流程的默认选项。</span>

设计上，「可测试性」还要求在 RTL 阶段就定下 DFT 策略：哪些触发器进扫描、扫描链怎么分、BIST 覆盖哪些存储器、JTAG 链怎么串——这些决策写在 DFT 设计文档里，由综合工具自动插入硬件。<span class="marginnote">DFT 策略与功能设计并行推进：功能工程师写 RTL，DFT 工程师定扫描与 BIST，两者在综合阶段合流。一个「先流片再想测试」的项目几乎注定失败——这正是「Design FOR Testability」这个名称里「FOR」的分量。</span>

## 7 小结

- 制造缺陷抽象成**故障模型**（stuck-at 为主），测试覆盖率 $FC=|F_d|/|F|$ 须 ≥98%。
- **扫描链**把触发器串成移位寄存器，把内部节点变成可控可观测端口。
- **ATPG** 用 D 算法/PODEM 自动生成测试向量，经**故障仿真**验证覆盖率。
- **良率 $Y=e^{-DA}$** 说明芯片越大越难造，DFT 与冗余是良率工程的抓手。
- **BIST** 用片上 LFSR/状态机自测，省外部测试成本，是存储器与系统自检的标配。
- **边界扫描（JTAG）**把 I/O 也串成链，是板级测试与调试的公共接口。
- **特征分析**用 LFSR 把长输出压缩成签名，碰撞概率约 $2^{-w}$，与 CRC 同源。
- 覆盖率 ≠ 良率，高覆盖率是「该测的都测了」，测不到的缺陷仍可能漏网。

在下一节，我们走出芯片内部，看芯片与世界打交道的边界——**I/O 与 ESD 保护**，以及高速片上传输线效应如何决定信号的最后一段旅程。这也是本专题的收束之篇。届时我们会看到：边界扫描测过的每一根引脚，都要靠 ESD 结构撑过出厂前的每一次触碰。
