## 为什么从时序分析开始

上一节我们得到了单条路径的时序方程 $T_c \ge t_{cq}+t_{pd}+t_{setup}$，但它隐含一个理想假设：**所有触发器同时收到时钟边沿**。真实芯片上，时钟要从时钟源分发到上百万个触发器，走不同的线、经过不同的缓冲器——到达时刻必然有先有后。**时钟到达时间的差异，正是现代数字设计最大的敌人之一**：它吃掉时序裕量，逼着设计者反复迭代，直到「时序收敛」。<span class="marginnote">Rabaey 第10章（Timing Issues）与 Weste & Harris 第9、12章把时序从「单路径」提升到「全芯片」：时钟分布网络、偏差与抖动的建模、以及静态时序分析（STA）如何成为流片前最后的守门员。</span>

时序分析的思维转变是本质性的：从「算一条路径的延迟」变成「**保证上百万条路径全部满足**」。这要求把延迟当作「分布」而非「单个数字」来对待，还要考虑工艺、电压、温度（PVT）的变化——时序收敛因此成为现代芯片设计中最耗时、最烧脑的环节。

## 1 时钟偏差与抖动：理想时钟的两处裂缝

理想时钟在每个触发器上都同时跳变。现实有两个偏离来源：

**时钟偏差（clock skew）**：时钟边沿到达不同触发器的时间差，是**空间性**的——由时钟网络拓扑、互连负载与工艺差异决定。偏差有两种：触发器 $i$ 比 $j$ 早收到边沿，称**正偏差（positive skew）**；反之**负偏差（negative skew）**。<span class="marginnote">偏差未必是坏事：如果接收端 $t_{skew}>0$（数据先出发、时钟晚到），反而给建立时间「多让出」一点裕量——设计者可以<strong>有意借用偏差</strong>来优化关键路径，但要时刻警惕它也可能加剧保持违例。</span>

**时钟抖动（jitter）**：同一触发器在不同周期收到的边沿时间**随机波动**，是**时间性**的——由电源噪声、热噪声、锁相环（PLL）本身的相位噪声造成。抖动无法像偏差那样「设计掉」，只能作为裕量扣除。<span class="marginnote">类比：偏差是「几个钟之间对表不准」，抖动是「同一个钟自己每一下都差一点」。偏差可预测可补偿，抖动只能统计。</span>

**辨析｜易错点：** 偏差是确定性的、与周期无关的「偏移」，抖动是随机性、与周期绑定的「涨落」。时序分析里，偏差进入建立/保持方程成为加减项，抖动则要按最坏周期（周期减抖动）来计算。

偏差的来源很具体：时钟树各分支的缓冲器数量不同、走线长度不同、负载不同——连电源网络上的 IR 压降差异都会让缓冲器延迟不同，进而转化为时钟偏差。所以「把时钟网络做对称」不只是布线技巧，更是从拓扑到电源的全局功夫。<span class="marginnote">一个真实量级帮助建立直觉：在 7nm 工艺、3GHz 时钟（$T_c \approx 333\,\text{ps}$）下，时钟偏差预算往往只有 20–50ps、抖动预算 10–30ps——两者加起来吃掉近四分之一的周期。这就是为什么「时钟网络」成为高速芯片最精细的设计对象之一。</span>

## 2 带偏差的时序方程：建立与保持的完整形态

把时钟偏差纳入上一节的方程。设发射触发器与接收触发器的时钟到达时间差为 $t_{skew}$（接收减发射），建立约束变为

$$T_c \ge t_{cq} + t_{pd} + t_{setup} - t_{skew}$$

保持约束变为

$$t_{hold} \le t_{cq} + t_{pd} - t_{skew}$$

**第一步，读建立方程**：$t_{skew}$ 让接收端时钟晚到，等于「多送」了 $t_{skew}$ 的时间——正偏差放宽建立约束，这是偏差可被利用的一面；**第二步，读保持方程**：同一项 $t_{skew}$ 出现在等号右侧被减去，意味着正偏差**收紧**保持约束——数据早到后，接收端时钟还「没到采样窗口」，数据可能过早穿透造成保持违例；**第三步，看矛盾**：同一偏差对建立「有利」、对保持「有害」，所以偏差不是越大越好，而是要**精确控制**。<span class="marginnote">保持违例与时钟周期无关——即使频率降得很低，保持违例依然存在。它的修复手段是「加缓冲器延长数据路径」（$t_{pd}$ 变大），这正是布局布线工具里 hold fixing 的本质。</span>

**辨析｜易错点：** 建立违例与保持违例的「敌人」不同：建立违例的敌人是「路径太长 + 周期太短」，可以靠降频或缩短路径解决；保持违例的敌人是「路径太短 + 数据穿透太快」，与频率无关、只能靠加缓冲器。设计者必须同时盯住两种违例，而它们常常此消彼长。

把两式合起来看，能读出设计者的两个「必守底线」：建立时间管「最高能跑多快」，保持时间管「最慢能降多稳」。任何一个方向违背，时序收敛都不成立——这也是为什么「先定周期、再查保持」成为 STA 的固定顺序。<span class="marginnote">设计者的两个底线对应两个极端场景：建立违例在「超频 + 最慢角」暴露，保持违例在「最速角 + 数据穿透」暴露——所以 STA 要同时覆盖慢角与快角，任何一个角漏检都可能让芯片在特定条件下失效。</span>

**公式解析：有用偏差的借裕量**——若接收触发器比发射触发器晚 $t_{skew}$ 收到时钟，则关键路径可用的时间从 $T_c$ 增加到 $T_c + t_{skew}$：

$$T_c + t_{skew} \ge t_{cq} + t_{pd} + t_{setup}$$

**第一步，读左边**：接收端晚到的时钟「多给了」 $t_{skew}$ 的时间来让数据稳定；**第二步，读右边**：路径延迟不变，但可用时间变多，建立裕量因此增加；**第三步，读代价**：省下的时间不是免费的——要保持不违例，必须保证 $t_{hold} \le t_{cq}+t_{pd}-t_{skew}$，否则数据穿透。设计者给关键路径寄存器加有用偏差、给非关键路径补回，就是「拆东墙补西墙但总账划算」的优化。

## 3 时钟分布网络：让边沿尽量同时

要控制偏差，就得精心设计时钟从源到各触发器的路径。主流结构是**时钟树（clock tree）**：根是时钟源（通常是 PLL 输出），经逐级放大缓冲器（clock buffer）像树一样分叉，最终送达每个触发器。<span class="marginnote">Weste & Harris 第12章对比了网格（mesh）、树（tree）与 H 树（H-tree）三种分布结构：H 树理论上路径等长、偏差最小，但被不规则布局打乱；现代工业多用「树 + 局部网格」的混合结构。</span>

EDA 工具里的**时钟树综合（clock tree synthesis, CTS）** 会自动插入缓冲器、均衡各分支的负载与线长，把偏差压到几百飞秒以内。偏差控制还依赖**插入延迟（latency）**的考量——不同触发器路径总延迟不同，CTS 会通过「延迟匹配」让叶子节点到达时间对齐。<span class="marginnote">一个直观目标：CTS 希望「同一逻辑层级的触发器时钟到达尽量同时」。但设计者可以主动给某些寄存器加<strong>有用偏差（useful skew）</strong>，把关键路径的裕量「借」出来，再在非关键路径上补回——这是高级时序优化手法。</span>

## 4 时序收敛与静态时序分析

**时序收敛（timing convergence）** 指：在给定的时钟频率下，全芯片所有路径的建立与保持约束都被满足，且不随综合、布局、布线迭代而恶化。它是「设计完成」的硬标准。<span class="marginnote">迭代中的经典现象：逻辑综合后时序「过了」，布局布线后却「爆了」——因为互连延迟在布局前只是估算。时序收敛的核心工作，就是在每轮物理实现后重新估算延迟、重新修路径，循环逼近。</span>

验证时序的主力是**静态时序分析（Static Timing Analysis, STA）**：它不仿真功能，只遍历所有路径，用工艺库中的延迟模型算出每条路径的建立/保持裕量，报告**最坏路径**。<span class="marginnote">STA 的优势是「穷举 + 快」：它可以检查上百万条路径而无需测试向量。业界标准格式是 SDC 约束（Synopsys Design Constraints）——设计者用 set_clock_period、set_input_delay 等语句告诉工具时序目标。</span>

STA 面对的不是单一延迟，而是**工艺角（process corner）**与 PVT 变化：同一块芯片在不同电压、温度、工艺偏差下延迟不同。设计者用「最慢角」查建立时间、用「最快角」查保持时间，还要做**片上变化（on-chip variation, OCV）**分析，把局部偏差纳入裕量。<span class="marginnote">Weste & Harris 第9章给出 OCV 的简单处理：对发射路径用「慢」延迟、对接收路径用「快」延迟，即最悲观组合——保守但安全。更精细的统计时序分析（SSTA）把延迟当分布处理，是现代 5nm 级设计的标配。</span>

时钟树还有一个隐蔽的成本：**时钟功耗**。时钟网络每周期翻转两次，是芯片动态功耗的最大单一来源——本专题第九篇《低功耗》的时钟门控正是「把不用的时钟分支掐掉」来省电。但门控本身也影响时钟树的负载与偏差，所以「省电」与「时序」在这里也要联合权衡。<span class="marginnote"><strong>统计时序分析（SSTA）</strong> 是 STA 的进阶：它把每条路径的延迟当作随机变量（来自工艺变化），计算「时序违反概率」而非「是否违反」。SSTA 能避免「最悲观假设」造成的过度设计，先进节点（7nm 及以下）的时序签核已普遍引入统计方法。</span>

**核心对比表：偏差、抖动与 PVT 变化**

| 类型 | 性质 | 来源 | 处理方式 |
| --- | --- | --- | --- |
| 时钟偏差 | 确定性、空间性 | 时钟网络拓扑 | 建立/保持方程加减项 |
| 时钟抖动 | 随机、时间性 | 电源/热/相位噪声 | 周期扣裕量 |
| PVT 变化 | 工艺/电压/温度 | 制造与运行环境 | 多工艺角 + OCV |
| OCV | 片上局部变化 | 同一芯片内差异 | 悲观假设 + 裕量 |

## 5 时序分析的方法论

把时序分析串成一个可执行的工作流，一名后端工程师的日常是：

- **第一步，定约束**：用 SDC 写清时钟周期、输入输出延迟、异步路径（false path/multicycle path）。
- **第二步，跑 STA**：在综合、布局、布线各阶段各跑一次，得到最坏路径报告。
- **第三步，分类违例**：分清建立违例（降频/缩路径）与保持违例（加缓冲），按「成本从低到高」修。
- **第四步，迭代收敛**：修完重跑，直到全部约束满足、裕量稳定。
- **第五步，签核**：在多个工艺角 + OCV 下全部通过，才算时序签核完成。<span class="marginnote">时序签核是流片前的最后一道关——任何一个角下的任何一条路径违例，都可能导致芯片在特定条件下不工作。这就是为什么「时序收敛」被设计团队当作比「功能正确」更折磨人的目标。</span>

## 6 时序术语速查

**本节术语速查表**

| 术语 | 一句话含义 |
| --- | --- |
| 时钟偏差 skew | 边沿到达不同触发器的时间差 |
| 时钟抖动 jitter | 同一触发器边沿的随机涨落 |
| CTS | 时钟树综合 |
| useful skew | 有用偏差（借裕量） |
| STA | 静态时序分析 |
| SDC | 时序约束文件 |
| 工艺角 corner | PVT 的一个取值组合 |
| OCV | 片上变化分析 |

**辨析｜易错点：** STA 是「穷举路径」，但它只检查「时序」，不检查「功能」。功能正确靠仿真（simulation）与形式化验证，时序正确靠 STA——两者互补，缺一不可。设计者常误以为「STA 过了 = 芯片好了」，其实 STA 只保证「该测的时序都测了」，功能 bug 仍需仿真去抓。

## 7 小结

- **时钟偏差**是空间性、确定性的边沿到达差；**抖动**是时间性、随机性的边沿涨落。
- 偏差进时序方程：对建立有利、对保持有害，须精确控制而非一味消除。
- **建立违例**靠降频/缩路径，**保持违例**靠加缓冲，两者敌人不同、常此消彼长。
- **时钟树综合（CTS）**通过插入缓冲器、延迟匹配把偏差压到飞秒量级。
- **时序收敛** = 全部路径满足约束且不随物理实现迭代而恶化。
- **静态时序分析（STA）**按 PVT 角与 OCV 检查最坏路径，是流片前的守门员。
- **SSTA** 把延迟当随机变量、算违反概率，避免最悲观假设的过度设计。
- STA 工作流：定约束 → 跑 STA → 分类违例 → 迭代收敛 → 多角签核。
