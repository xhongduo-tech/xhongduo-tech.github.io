# 数据通路运算单元：加法器族、乘法器与移位器

## 为什么从数据通路开始

至此我们有了门、有了触发器、有了时钟契约。现在把它们拼成**数据通路（datapath）**——真正执行算术与逻辑运算的硬件：加法器把两个数加在一起，乘法器把「加」重复上千次，移位器移动位的位置。它们是 CPU 的 ALU、GPU 的 tensor core、DSP 的 MAC 单元的共同地基。<span class="marginnote">Rabaey 第11章与 Weste & Harris 第10章是数据通路的双权威：前者按「加法→乘法→移位」逐个设计模块并量化延迟，后者用<strong>结构化的 bit-slice 方法</strong>把每个模块画成规整的位片阵列，二者互为表里。</span>

数据通路设计还有一个贯穿始终的主题：**用规则的并行结构把关键路径从 $O(N)$ 压到 $O(\log N)$**。加法器的进位链、乘法器的部分积、移位器的级联，处处是「串行→并行」的换算。掌握这些结构，等于掌握了大到处理器、小到算术单元的共同语法。

这些运算单元的「位宽」从 4 位到 128 位跨度巨大，但设计语言完全一致：无论 8 位单片机里的 RCA 还是 128 位浮点单元里的前缀加法器，用的都是「全加器 + 进位策略」的组合。位宽只改变规模，不改变语法——这正是数据通路设计可以「一次学会、处处套用」的原因。

## 1 全加器与进位：加法的基本细胞

一位二进制加法的核心是**全加器（full adder, FA）**，输入两个加数位 $a_i,b_i$ 与低位进位 $c_{i}$，输出和位 $s_i$ 与进位 $c_{i+1}$：

$$s_i = a_i \oplus b_i \oplus c_i, \qquad c_{i+1} = a_i b_i + c_i (a_i \oplus b_i)$$

**第一步，读和位**：异或三输入——异或操作对加法的含义是「不考虑进位地相加」；**第二步，读进位**：进位在两种情况下产生——本位的两个加数都是 1（$a_i b_i$），或者其中一个为 1 且低位有进位传来（$c_i(a_i\oplus b_i)$）；**第三步，读结构**：进位 $c_{i+1}$ 只依赖于本位的 $a_i,b_i$ 与低位的 $c_i$，进位是**串行传播**的——这正是加法器速度瓶颈的来源。<span class="marginnote">从「半加器 + 进位」的两级结构看，全加器本质上由两个异或（和）与一个「产生/传播」逻辑（进位）构成。CMOS 里常用传输门实现 XOR，从而把一个 FA 压缩到约 24–28 个晶体管。</span>

**串行进位加法器（ripple-carry adder, RCA）**把 N 个 FA 首尾相接，$c_{i+1}$ 从低位滚到高位。它面积最小、结构最简，但**进位要穿透 N 级**——延迟近似 $t_{RCA} \approx N \cdot t_{FA,carry}$。对 32 位加法器，这是几十个门级延迟，太慢。所有高速加法器的全部智慧，都在于**让进位别一级级滚**。

**半加器（HA）**是全加器的近亲：只有两个输入（$a,b$），输出和 $s=a\oplus b$、进位 $c=ab$。它用于「最低位相加」以及乘法部分积阵列的第一行——因为最低位没有进位输入。理解 HA 与 FA 的分工，是读懂任何加法阵列、乘法阵列的第一步。<span class="marginnote">一个实用的晶体管线数：一个 CMOS FA 约 24–28 管，HA 约 12–14 管。32 位 RCA 需要 31 个 FA + 1 个 HA ≈ 800 管，而 32 位前缀加法器还要翻倍——这就是「快是要花钱的」最直观的账单。</span>

## 2 加法器族：从纹波进位到前缀加法器

**核心对比表：加法器家族的速度-面积权衡**

| 类型 | 进位策略 | 延迟（约） | 面积 | 特点 |
| --- | --- | --- | --- | --- |
| 纹波进位 RCA | 逐位串行 | $O(N)$ | 最小 | 结构最简单 |
| 进位跳跃 CSA | 分组跳过全 1/全 0 进位 | $O(\sqrt{N})$ | 小 | 中等速度、省电 |
| 进位选择 CSelA | 并行算 0/1 两组进位再选 | $O(\sqrt{N})$ | 较大 | 分组并行 |
| 超前进位 CLA | 并行计算产生/传播 | $O(\log N)$ | 大 | 经典高速 |
| 前缀（Kogge-Stone） | 前缀并行前缀计算 | $O(\log N)$ | 很大 | 规则、可扩展 |

**超前进位（carry lookahead, CLA）** 的核心是把进位公式重写为**产生（generate）**与**传播（propagate）**两个信号：$g_i = a_i b_i$（本位必然产生进位）、$p_i = a_i \oplus b_i$（本位把低位进位传上去）。于是进位变成 $c_{i+1} = g_i + p_i c_i$，逐层展开后，高位的进位可以**直接用低位的 $a,b$ 算出来**，不再等进位逐级滚——这就是「超前」。<span class="marginnote">用生成/传播信号递归展开：$c_4 = g_3 + p_3 g_2 + p_3 p_2 g_1 + p_3 p_2 p_1 c_0$。公式展开得越深，进位算得越快，但门的扇入也越大——所以实际 CLA 用「4 位一组」的模块层层嵌套，是<strong>对数级延迟</strong>的结构化来源。</span>

**前缀加法器（prefix adder）** 把问题进一步抽象成「前缀运算」：定义组合算子 $\circ$ 把相邻位的 $(g,p)$ 合并，任意 $c_i$ 就是前 $i$ 位的**前缀组合结果**。Kogge-Stone 结构用「折半跳跃」的方式并行计算所有前缀，延迟降到 $\lceil \log_2 N \rceil$ 级，是现代 64 位加法器的工业标准。<span class="marginnote">Weste & Harris 第10章给出统一视角：RCA、CLA、前缀加法器只是「进位怎么合并」的不同实现，速度都换来面积与功耗——乘法器与浮点单元里的加法器几乎都用前缀结构。</span>

**辨析｜易错点：** 「32 位 CLA 比 32 位 RCA 快 8 倍」只是理想话术；实际延迟还受门扇入、互连与版图影响。真正的高性能加法器常是**混合结构**——前缀加速 + 进位选择 + 逐位优化，设计者用延迟-面积-功耗三维权衡而非单一指标。

## 3 乘法器：从移位相加到 Wallace 树

乘法 $P = A \times B$ 可以展开成「**部分积相加**」：把乘数 $B$ 的每一位与 $A$ 相乘得到 $N$ 个部分积，再全部加起来。所以乘法器的两个核心问题：**怎么产生部分积、怎么高效地加**。<span class="marginnote">基本乘法器：N 位乘 N 位产生 N 个部分积，用 N-1 个全加器行（加法器阵列）把它们累加。这种<strong>阵列乘法器</strong>结构规整、延迟 $O(N)$，是教科书常画的样式。</span>

**Booth 编码**减少部分积的个数：它利用「3 位一组的重编码」，把乘数位组合成 $\{-2,-1,0,1,2\}$ 的倍数，将部分积个数从 N 降到约 N/2。**Wallace 树**则用「进位保存加法器（CSA）」把部分积**并行**压缩：每层把三行（部分积 + 两个进位）压成两行，直到只剩两行，最后用一个快速加法器收尾——延迟从 $O(N)$ 降到 $O(\log_{3/2} N)$。<span class="marginnote">工业乘加单元（MAC）的标准配方 = Booth 编码 + Wallace 树 + 前缀加法器，正是 DSP 与 tensor core 的核心。Rabaey 第11章把 Wallace 树画成经典的「三二压缩」图形，值得亲手画一遍。</span>

一个具体而直观的例子：把 $A=1010_2$ 与 $B=1101_2$ 相乘，得到 4 个部分积（$A$ 按 $B$ 各位左移 0/1/2/3 位），把它们按位错开相加即得结果。这个「移位 + 相加」的流程，正是乘法器的定义式，也是软件里「乘法分解成移位与加法」的硬件根源。<span class="marginnote">算一算就知道：$1010_2 \times 1101_2 = 10 \times 13 = 130$，展开的部分积恰好是「$1010_2$ 左移 0 位、1 位、3 位再相加」——乘法器做的事情，本质上是把这张手工算式的每一步变成硬件。</span>

一个真实的延迟对比建立直觉：32 位乘法，阵列乘法器约需 32 级全加器行（数百 ps 到 ns 级），而 Booth + Wallace 树 + 前缀加法器只需约 8 层压缩 + 一次前缀相加，延迟几乎与 32 位加法器同量级。正是这个数量级的差距，让现代处理器与 GPU 的乘法「看起来不贵」——而代价是面积与布线的复杂度。

**公式解析：乘法延迟的粗略模型**——设部分积个数为 $P$，Wallace 树每层压缩比 $3/2$，则压缩层数约

$$L \approx \log_{3/2} P$$

**第一步，读 $P$**：Booth 编码后 $P \approx N/2$（对 N 位乘数）；**第二步，代层数**：$L \approx \log_{3/2}(N/2)$，对 32 位乘法约 8–9 层；**第三步，读总延迟**：总延迟 $\approx$ 树延迟 + 末级加法器延迟 + 寄存器开销，其中树延迟随位数呈**对数**增长——这就是「乘法不比加法慢多少」的硬件由来。<span class="marginnote">对比：阵列乘法器延迟 $O(N)$，Booth+Wallace 延迟 $O(\log N)$。对 64 位乘法，两者差一个数量级——这就是现代处理器宁可多花面积也要上 Wallace 树的理由。</span>

## 4 移位器：桶形移位器的结构之美

移位器把位向左或向右搬动，是 ALU 的第三个主角。**桶形移位器（barrel shifter）** 能在一个周期内完成任意位数的移位，它用「移位网络」实现：第 $k$ 级「决定是否移 $2^k$ 位」，由控制信号选择，N 位移位只需 $\lceil\log_2 N\rceil$ 级。<span class="marginnote">桶形移位器用传输门 MUX 网络实现：每级是一个「2 选 1」开关，数据可以在不同位上「跨越」——因为传输门双向导通、可并行穿过，所以各级可同时动作，实现单周期任意移位。Rabaey 第11章把它与旋转、算数移位（符号扩展）一起讨论。</span>

**辨析｜易错点：** 逻辑移位（补 0）、算术移位（补符号位）、循环移位（绕回）三种移位语义不同，桶形移位器的控制逻辑必须区分。算术右移在硬件里等价于「复制符号位」，这对有符号数处理至关重要——理解它，才能理解为什么编译器把「除以 2 的幂」翻译成算术右移而非除法。<span class="marginnote">一个易混点：算术右移与逻辑右移在「数据位都是 0」时结果相同，但符号位为 1 时结果天差地别——$1000_2$ 逻辑右移一位得 $0100_2$（=4），算术右移一位得 $1100_2$（=-4）。处理有符号数时用错移位类型，是经典 bug 的来源。</span>

旋转（rotate）是移位的第四种语义：把移出去的位绕回另一侧，常用于位操作指令与密码学（循环左移/右移）。桶形移位器加上「绕回」连线就能实现旋转——因为它本质上是「把移位结果与溢出的位拼起来」。

## 5 数据通路的系统视角：ALU 与 MAC

单个运算单元拼起来就是**算术逻辑单元（ALU）**——它把加法、减法、逻辑运算、移位放进一个模块，用功能选择信号切换。减法可以「加补码」实现，所以 ALU 只要一套加法网络再加点控制就能做加减：

$$A - B = A + \overline{B} + 1$$

**第一步，读 $\overline{B}$**：对 $B$ 逐位取反——把减法变成「加反码」；**第二步，读 $+1$**：反码加 1 才是补码，这是「无借位减法」的关键一步；**第三步，读代价**：一个 2:1 MUX 选 $B$ 或 $\overline{B}$、一个进位输入选 0 或 1，就能让加法器「顺便」做减法——ALU 的减法几乎零额外硬件。<span class="marginnote">ALU 的控制位越多、功能越全，面积与关键路径越长——处理器设计者在「功能完整」与「速度」之间反复取舍，这正是本专题第十篇《设计方法学》里综合优化的典型对象。</span>

**乘加单元（MAC）** 把乘法与累加合二为一：$acc \gets acc + A \times B$。它是 DSP 滤波、矩阵乘法、深度学习推理的最基本运算。现代 tensor core 的 MAC 阵列本质上是「几十×几十 个 MAC 单元铺成网格，配上前缀加法器做最终累加」——数据通路的设计语言在这里放大到极致。<span class="marginnote">MAC 的精度演进也值得一提：从 FP32 到 BF16、INT8、甚至 4-bit 低精度——降低位宽换来吞吐与能效的提升，这正是本专题第九篇《低功耗》在算力场景的延伸。Rabaey 与 Weste & Harris 的加法器、乘法器，是大模型加速芯片（见博客 GPU/TPU 专题）最底层的地基。</span>

## 6 数据通路速查

**核心术语速查表**

| 术语 | 一句话含义 | 相关单元 |
| --- | --- | --- |
| FA | 全加器 | 加法器细胞 |
| g/p | 产生/传播信号 | CLA |
| CSA | 进位保存加法器 | Wallace 树 |
| Booth | 重编码减少部分积 | 乘法器 |
| 桶形移位器 | 单周期任意移位 | ALU |
| MAC | 乘加单元 | DSP/深度学习 |

**进位保存加法器（CSA）**值得单独认识：它同时输出「和」与「进位」两套位，不等待进位传播——所以三个数相加可以「并行压成两个数」。这正是 Wallace 树「三二压缩」的核心：用一串 CSA 把 $N$ 个数并行压成两个，最后才用一个加法器收尾。<span class="marginnote">CSA 的代价是「中间结果变宽」：进位位需要多一位，且最终仍需一个加法器做真正的相加。但把「一次串行相加」拆成「多次并行压缩 + 一次串行相加」，正是把加法从 $O(N)$ 压到 $O(\log N)$ 的关键一步。</span>

**辨析｜易错点：** 注意 CSA 与 CLA 的区别：CSA 是「不传播进位、把和与进位分开输出」，CLA 是「用逻辑快速传播进位」。前者用于多操作数压缩，后者用于最终相加——两者互补而非替代，混合使用是乘法器与浮点加法器的常态。

## 7 小结

- **全加器**是加法细胞：和 = 异或，进位 = 产生 + 传播，进位链决定速度。
- **加法器族**从 RCA 到 Kogge-Stone，本质都是「让进位算得更快」，速度换面积与功耗。
- **乘法器** = 部分积产生（Booth 编码）+ 压缩（Wallace 树）+ 末级加法（前缀）。
- **桶形移位器**用 $\log N$ 级 MUX 网络实现单周期任意移位，旋转只需加绕回连线。
- 算术右移复制符号位、逻辑右移补 0，处理有符号数时混用是经典 bug。
- ALU 用「加补码」做减法，MAC 把乘加合一，是 DSP 与深度学习的最基本算子。
- CSA 不传播进位、把和与进位分开输出，是 Wallace 树「三二压缩」的核心。
- 半加器用于最低位与部分积阵列首行，与全加器共同构成加法/乘法阵列的砖块。
- 数据通路的统一法则：用**规则位片 + 并行前缀**把 $O(N)$ 关键路径压到 $O(\log N)$。
