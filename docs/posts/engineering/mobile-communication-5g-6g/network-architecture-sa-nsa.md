## 为什么从网络架构开始

前四篇都在讲空口——手机与基站之间那一段。但一部手机能上网、打电话、办业务，背后是整个网络在支撑：基站之上有传输网，传输网之上有**核心网（core network）**，核心网负责认证、计费、会话管理、路由转发。<span class="marginnote">一个类比把层级说清：<strong>空口是「最后一公里」，核心网是「城市主干道」</strong>。4G 的空口效率已经很不错，但它的核心网（EPC）是上一代「盒子化」思维的产物——升级难、弹性差。5G 的突破口之一，就是把这个「城市主干道」重建一遍。</span>

5G 网络架构要回答三个问题：**怎么起步（NSA 还是 SA）、怎么组织（SBA 服务化）、把用户面放哪里（UPF 下沉）**。这三个问题的答案，共同决定了 5G 网络是「一台更快的 4G 交换机」还是「一个可编程的分布式计算平台」。Dahlman 第6章「Radio-Interface Architecture」从空口协议栈切入，而核心网侧的标准文本是 3GPP TS 23.501 与 23.502——本篇把它们放在一起讲。

## 1 从 EPC 到 5GC：控制面与用户面彻底分离

4G 核心网 EPC 由 MME（移动性管理）、S-GW/P-GW（网关）等几个「大盒子」组成，一个盒子承担一大块职责，扩容要整盒升级。5G 核心网（5GC）的第一步革命是把职责**切片化**：引入 **CUPS（控制面与用户面分离）**，把「管信令」的控制面和「搬数据」的用户面彻底拆开。

- **控制面网络功能**：AMF（接入与移动性管理）、SMF（会话管理）、AUSF/UDM（认证与签约数据）、PCF（策略控制）、NRF（服务发现）、NSSF（切片选择）等。
- **用户面网络功能**：UPF（用户面功能）——负责数据包的转发、QoS 执行、计费统计。

**控制面像「交警」，用户面像「高速公路」**：交警重新规划路线时，高速路上的车可以不停。5G 里 AMF/SMF 可以按需扩展或升级，而海量的数据流量全部压在独立的 UPF 上，互不拖累。

接口拓扑也随之清晰：终端经 **N1** 口连 AMF（移动性信令），基站经 **N2** 口连 AMF（接入与移动性），基站经 **N3** 口连 UPF（用户数据），AMF 与 SMF 之间 **N11** 协作完成会话管理。**「哪段信令走哪个功能、哪段数据走哪个网关」在这张接口图上一目了然**——看懂 N1/N2/N3，就看清了 5GC 的分工骨架。<span class="marginnote">CUPS 不是 5G 的原创，4G 的 EPC 后期也做了 CUPS 改造；但 5GC 把它变成了标配，并进一步把「网络功能」彻底「云化」——每个功能都是可独立部署、独立扩缩容的微服务，跑在通用的数据中心服务器上，而非专用电信硬件。<strong>这是电信网络第一次真正拥抱云计算。</strong></span>

## 2 NSA 与 SA：两代建网路线

**NSA（非独立组网）**与**SA（独立组网）**是 5G 建网的两种形态，区别在于：新空口 NR 是不是「自己当家做主」。

- **NSA（以 EN-DC 为代表）**：LTE 基站当「锚点」，负责控制面（信令、移动性、接入），NR 只承担用户面数据。手机双连接：控制走 4G，数据走 5G。优点是可以复用 4G 核心网与既有站点，**2019 年全球首批 5G 商用几乎全是 NSA**，因为速度最快；缺点是没有发挥 5G 核心网的能力，时延下不来、切片用不上。<span class="marginnote">NSA 是「先上车后补票」的务实选择：运营商可以一边用 4G 核心网开卖 5G 数据业务，一边慢慢建设 5GC。对用户而言 NSA 与 SA 在「测速 App」上往往分不出区别，但在「时延、切片、边缘」这些深层能力上差距巨大。</span>
- **SA（独立组网）**：NR + 5GC 全套独立成网，控制面、用户面都在 5G 体系内。3GPP 定义了 Option 2（SA）与 Option 3x（NSA）等若干部署选项，业界通常把「Option 2」当作纯正 SA。SA 才能兑现 1 ms 时延、网络切片、UPF 下沉等 5G 独有的承诺。

**两条路不是互斥的**：很多运营商先 NSA 抢时间、后演进到 SA 提能力；中国三大运营商 2020 年便明确「以 SA 为目标」，2020 年底 SA 商用。**「NSA 是 4G 网络的延伸，SA 是 5G 自己的网络」**——这句话值得记一辈子。

**辨析｜易错点：** 「NSA 比 SA 快」是常见的理解偏差。NSA 早期只是「部署快」，SA 在架构上反而更简洁（少一次双连接与 4G/5G 间信令交互）。真正的差异在能力维度：SA 才有原生切片、才有 UPF 灵活下沉、才有更低时延。**测速 App 看不出 NSA/SA，但工业客户一眼就看得出。**

3GPP 还在标准里给部署选项编了号：Option 1（纯 4G）、Option 2（SA，纯 5G）、Option 3/3x（NSA，4G 锚点）、Option 4/7（LTE 与 NR 互换角色的双连接变体）。**这些「Option」是可勾选的菜单，不是技术必然**——选择权在运营商手里，取决于频谱、站点与投资节奏。

回看 2019 年的真实时间线会很有味道：美国运营商 T-Mobile 与 AT&T 用毫米波 NSA 抢「全球首个 5G 网络」头衔，韩国三大运营商同日开卖 NSA 5G，中国则先发 NSA 牌照、随后明确「SA 独立组网方向」并加速推进。**同一年的「5G 商用」四个字，背后是 NSA 与 SA 两条完全不同的技术路线**——不了解架构，就看不懂当年那场热闹。

## 3 无线侧协议栈：空口之上的五层协议

网络架构的另一半是**无线接入网（RAN）侧的分层协议栈**，Dahlman 第6章把它们自下而上拆开：

| 层 | 全称 | 职责 |
| --- | --- | --- |
| PHY | 物理层 | OFDM 调制、信道编码、波束（第2–4篇） |
| MAC | 介质访问控制 | 调度、HARQ 重传、参数集选择 |
| RLC | 无线链路控制 | 分片重组、ARQ、按需模式 |
| PDCP | 分组数据汇聚 | 加密、完整性、头压缩、乱序重排 |
| RRC | 无线资源控制 | 连接管理、移动性、测量配置 |
| SDAP | 服务数据适配 | 把 QoS 流映射到无线承载（5G 新增） |

**这条协议栈是「把空口的裸能力组织成可靠数据通路」的分层合同**：PHY 管怎么物理地发，MAC 管何时发，RLC 管丢了怎么补，PDCP 管安全与有序，RRC 管整条链路怎么建立与移动，SDAP 则把「业务流」翻译成「承载」。<span class="marginnote">对比 4G：5G 协议栈比 LTE 多了 <strong>SDAP</strong> 一层，专门负责「QoS 流 ↔ 无线承载」的映射——这层新增正是为了支撑网络切片：不同切片的业务流需要被清晰地映射到不同的承载上，SDAP 就是那张「翻译表」。</span> 5G 还让协议栈按「数据中心化」重构：**CU（集中单元）/ DU（分布单元）分离**——CU 放通用服务器上跑高层协议，DU 贴近基站跑低层协议，两者之间是标准化的 F1 接口。这套「控制集中、处理下沉」的结构，让 RAN 也能像核心网一样弹性伸缩。

## 4 SBA 服务化架构：把核心网变成微服务

5GC 最与众不同的设计是**服务化架构（SBA，Service-Based Architecture）**：控制面的网络功能不再用专有接口点对点互连，而是把各自的能力注册成「服务」，彼此通过**通用接口**互相调用——就像微服务一样。

具体实现上，5GC 控制面内部采用 **HTTP/2 + RESTful 风格的 API**：每个网络功能（如 AMF、SMF）把自己的能力（如「移动性管理」「会话建立」）暴露成服务，NRF（网络仓库功能）负责服务注册与发现，任意功能要调用别人时，先问 NRF「谁能干这个」，再直接调用。<span class="marginnote">SBA 的意义怎么强调都不为过：<strong>它让电信网络从「盒子互联」变成了「服务编排」</strong>。新增一个网络功能、部署一个新业务，不再需要改动一堆专有接口，只要注册服务、由 NRF 发现、按需调用即可——这正是网络切片（下一篇）能「按需拉起来一条逻辑网络」的架构前提。</span>

这套设计的直接受益者是**运营与编排（MANO）**：网络功能可以跑在标准服务器上、容器化部署、按业务负载自动扩缩容。运营商第一次可以在「软件商店」的意义上更新网络能力，而不是每次换代都「砸盒子重买」。

一个具体的「服务编排」例子是**5G 语音**：5GC 里没有独立的语音网元，话音走 **VoNR**（数据承载上跑 IMS），当 5G 覆盖不足时自动 **EPS fallback** 回落到 4G 承载——这段「回落」在 5GC 里就是 AMF 与 SMF 之间的一次服务调用与重定向。**把传统上「一个专用系统干的事」变成「几个通用服务拼出来的流程」，正是服务化的日常。**

## 5 UPF 下沉与边缘计算：把用户面推到离用户最近处

如果说 SBA 改变了控制面，**UPF 下沉**则重新定义了用户面。UPF 是 5G 网络里数据流量的「咽喉」：所有用户数据都要经 UPF 转发。它在核心网里可以灵活部署——既可以放在中心机房，也可以**下沉到地市、园区甚至基站侧**。

为什么要下沉？两个理由：

- **时延**：数据每经过一跳网络，时延就增加一截。URLLC 场景要求端到端 1–10 ms，若用户数据要绕行到几百公里外的中心核心网，物理上就不可能达标。把 UPF 放到边缘，数据在本地就转发掉，时延从「跨省」缩到「本地」。
- **流量卸载与本地业务**：把 UPF 放在园区边缘，企业数据不出园区、经本地 UPF 直通企业内网或边缘云，既安全又高效。<span class="marginnote"><strong>边缘计算（MEC）与 UPF 下沉是同一件事的两面</strong>：MEC 提供「算力放在边缘」，UPF 提供「流量在边缘就近处理」。两者配合，才谈得上把时延敏感、数据量大的业务（自动驾驶、工业控制、云游戏）从「核心网兜底」变为「边缘就地解决」——这也是下一篇「切片 + 边缘」组合拳的前奏。</span>

**辨析｜易错点：** 「UPF 下沉 = 网络变分散」不准确。控制面仍然可以集中（方便统一策略与编排），只有**用户面数据路径**被推向边缘。**「控制集中、用户分散」才是 5G 边缘网络的真实形态**——集中管策略、分散搬数据，各取所长。

MEC 的落地方向很具体：云游戏把渲染渲染到边缘、把画面就近推给手机，端到端时延压在 20 ms 内；工业园区的视觉质检把摄像头数据在园区边缘就地推理，不出园区；自动驾驶的路侧感知把时延敏感信息在路侧边缘直接处理。**「算力跟着用户走，而不是用户绕着算力跑」**——UPF 下沉是这一切的流量前提。

## 6 核心对比表：NSA vs SA、EPC vs 5GC

本主题为纯架构概念，无核心公式，按编辑章程以「核心对比表」替代公式解析。两张表把两条主线收拢：

| 维度 | NSA（EN-DC） | SA（独立组网） |
| --- | --- | --- |
| 控制面 | LTE 锚点，NR 只管数据 | NR + 5GC 全独立 |
| 核心网 | 复用 4G EPC | 全新 5GC |
| 部署速度 | 快（2019 年首商用） | 慢（需建 5GC） |
| 时延/切片/MEC | 受限 | 原生支持 |
| 定位 | 过渡形态 | 目标形态 |

| 维度 | EPC（4G） | 5GC（5G） |
| --- | --- | --- |
| 形态 | 大盒子（MME/S-GW/P-GW） | 云原生微服务 |
| 接口 | 专有点对点协议 | HTTP/2 + RESTful API |
| 控制/用户面 | 部分分离 | 彻底分离 + UPF 灵活下沉 |
| 扩展性 | 整盒升级 | 按功能独立扩缩容 |
| 切片 | 无 | 原生网络切片 |

把这两张表叠起来看，5G 网络架构的全部创新可以概括为一句话：**把「又大又专」的盒子，拆成「小而通用」的服务，再把这些服务像搭乐高一样按业务需求拼装。** 这套「拆解 + 编排」的思想，正是网络切片与边缘计算能够成立的地基。

## 7 小结

- 5GC 的第一次革命是 **CUPS**：控制面（AMF/SMF 等）与用户面（UPF）彻底分离，「交警」与「高速路」各管各的。
- **NSA** 复用 4G 核心网、控制面走 LTE，是 5G 起步的务实选择；**SA** 才完整兑现时延、切片与边缘能力。
- **SBA 服务化**用 HTTP/2 + RESTful API 把网络功能变成可调用服务，NRF 负责发现，电信网络首次云原生。
- **UPF 下沉**把用户面数据路径推向边缘，「控制集中、用户分散」，是 MEC 低时延业务的前奏。
- 5GC 的本质是「拆盒子 + 编服务」：把大而专的设备变成小而通用的微服务。
- 网络架构的演进主线：从「盒子互联」到「服务编排」，从「中心兜底」到「边缘就地」。
- RAN 侧协议栈 PHY→MAC→RLC→PDCP→RRC→SDAP 是「把空口组织成可靠通路」的分层合同，SDAP 为切片新增。
- CU/DU 分离让 RAN 也能弹性伸缩；5G 语音靠 VoNR + EPS fallback 的「服务编排」实现。

在下一节，我们将站在这套可编排的网络上，看 5G 最「产品化」的能力——**网络切片与边缘计算**，以及它们如何服务 eMBB/URLLC/mMTC 三大场景。
