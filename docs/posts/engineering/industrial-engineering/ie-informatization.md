## 为什么从工业工程信息化继续

前两节我们学会了用成本与价值判断「改不改」，但还有一个更基础的前提：**数据从哪来？** 手工抄录的数据永远滞后、残缺、易错。**工业工程信息化（IE informatization）**就是 IE 方法的数字化轨道——把《生产计划》的 MRP 升级成 ERP，把《精益生产》的看板升级成条码与 MES，让每一项 IE 分析都跑在实时数据上。<span class="marginnote">信息化的本质是把 IE 的「信息流」从纸面搬到数据库。回顾《供应链管理》里的三类流：物料流靠物理搬运，资金流靠财务系统，而<strong>信息流</strong>就是信息化要打通的血管——信息流不畅，物料与资金流必然随之阻塞。</span>今天的企业不缺少数据，缺的是**把数据组织成可决策的信息**。

## 1 从 MRP 到 MRP II 再到 ERP

信息化的起点是《生产计划》里的 **MRP**（物料需求计划）。它只回答一个问题：**需要哪些零件、什么时候要**。但生产只是企业众多职能之一，于是 MRP 逐渐扩展：

**闭环 MRP**：在 MRP 之外加产能校验——排出的计划先查产能够不够，不够就调整，形成「需求→计划→产能→反馈」的闭环。
**MRP II（制造资源计划）**：把财务、采购、销售也纳入同一套数据——计划直接联动成本核算与资金预算。
**ERP（企业资源计划）**：更进一步覆盖全企业——财务、人力资源、供应链、客户关系，用**一个统一的数据库**支撑所有业务模块。<span class="marginnote">从 MRP 到 ERP 的主线是「数据范围的扩张」：物料数据 → 产能数据 → 财务数据 → 全企业数据。但扩张也带来代价：系统变重、实施变难、数据规范化成本飙升。ERP 上线的失败案例，几乎都是「业务流程没理顺，先上系统」。</span>

**ERP 的核心不是软件，而是「一套数据、处处共享」**。过去销售、生产、财务各记各的账，同一个订单在不同系统里数字对不上；ERP 用一个数据库让三处看到同一份真相——这正是消除《供应链管理》牛鞭效应的企业内版本。

## 2 MES：车间级的神经系统

ERP 管「月/周/日」的计划与账务，但车间里的**每一分钟**它管不到。**制造执行系统（MES, Manufacturing Execution System）**补上这一层：实时采集车间的生产、质量、设备、物料状态，并把计划下达给现场。

MES 的典型功能（常概括为 11 个模块）包括：

**生产调度**：把工单派给具体设备与班组。
**数据采集**：自动记录每道工序的完成时间、数量、参数。
**质量管理**：在制品检验、SPC 数据实时收集。
**设备管理**：设备状态、OEE 实时计算。
**追溯（traceability）**：每一件产品用了哪些批次物料、经过哪些设备、哪些参数——出了问题能**一键溯源**。<span class="marginnote">追溯是 MES 最具杀手级价值的功能：《可靠性工程》与《质量管理》的教训是「缺陷要在源头揪出」，而溯源把「源头」变成了可查询的数据——一个零件出问题，10 分钟内能查出它来自哪个供应商批次、经哪台机床加工。这在食品、医药、汽车行业是合规刚需。</span>

**核心要点：ERP 管「应该做什么」，MES 管「实际做了什么」。** 两者之间的差距，就是 IE 的分析对象——计划与实际的差异，正是《成本控制》差异分析与《制造系统》OEE 的数据来源。

## 3 ISA-95：工厂信息化的楼层图

要理清 ERP、MES、PLC 之间谁管哪层，国际标准 **ISA-95** 给出了五层架构，像一栋楼的楼层：

| 层级 | 名称 | 时间尺度 | 典型系统 |
| --- | --- | --- | --- |
| 4 | 业务规划层 | 月/周/日 | ERP、APS |
| 3 | 制造运营层 | 日/班/时 | MES、仓储管理（WMS） |
| 2 | 监控层 | 分/秒 | SCADA、HMI |
| 1 | 控制层 | 秒/毫秒 | PLC、DCS |
| 0 | 物理层 | 实时 | 传感器、执行器、机床 |

**层与层之间靠数据接口对话**：ERP 把工单下给 MES，MES 把派工下给 SCADA/PLC，PLC 控制机床动作，再层层把实际数据回传。<span class="marginnote">ISA-95 把「计划」与「执行」的分层固化成了国际标准，也解释了为什么 MES 和 ERP 是两套系统而非一个——它们的时间尺度差了三个数量级。分层解耦让每层可以独立演进，这与软件工程的分层架构是同一个道理。</span>

**辨析｜易错点：** 新手常把 **ERP 与 MES 混为一谈**，以为上了一个就够。实际上 ERP 的车间数据靠人工录入、时滞以天计；MES 的现场数据自动采集、时滞以秒计。只上 ERP 不下 MES，车间就是「数据黑洞」——计划再好，执行状态一无所知。<span class="marginnote">行业里的一句玩笑话是「ERP 是大脑、MES 是神经、PLC 是肌肉」。没有神经，大脑的指令下不到肌肉，肌肉的动作也传不回大脑。三层缺一不可。</span>

ISA-95 的价值正在于此：它给这栋楼规定了**层与层之间的标准接口**（B2MML 等），让不同厂商的 ERP、MES、SCADA 能互相通信。没有这个标准，每上一个系统就要定制一堆「翻译器」，集成成本会吞掉信息化的全部收益。

## 4 核心对比：ERP 与 MES

用一张对比表把两者的分工钉死：

| 维度 | ERP | MES |
| --- | --- | --- |
| 管理对象 | 企业级资源（订单、物料、财务） | 车间级执行（工单、设备、质量） |
| 时间尺度 | 天/周/月 | 秒/分/班次 |
| 数据来源 | 单据录入、计划推演 | 现场自动采集 |
| 回答的问题 | 生产什么、需要什么资源 | 此刻在干什么、干得怎么样 |
| 与 ISA-95 层级 | 第 4 层 | 第 3 层 |
| 典型功能 | 采购、库存、财务、销售 | 派工、采集、追溯、OEE |

**核心要点：ERP 是「计划的世界」，MES 是「执行的世界」**；两者之间的接口质量，决定了企业「计划与实际」的落差有多小。工业工程的方法论——标准时间、OEE、差异分析——全部依赖 MES 层的数据才能自动化运转。

### APS：把运筹学装进排产系统

在 ERP 与 MES 之间，还有一个对工业工程特别亲切的系统——**高级计划与排程（APS, Advanced Planning and Scheduling）**。它把《生产计划与调度》里 NP 难的排产问题交给求解器：给定订单、产能、物料与交期，APS 用约束规划、启发式或数学规划自动算出最优排产方案。

**APS 的意义在于把「排产规则」从 Excel 和人的经验升级为可求解的模型**：

**约束建模**：设备产能、物料可用、工艺顺序、交期——全部写成约束。
**实时重排**：设备故障、插单、急单发生时，APS 秒级重排，替代人工反复调整。
**目标优化**：最小化拖期、最大化设备利用率、平衡负荷——按企业策略选目标函数。

APS 是运筹学从「纸面模型」到「生产系统」的桥梁：没有它，《线性规划与整数规划》《生产计划与调度》里的算法就只是书本上的习题。<span class="marginnote">APS 的排产本质与《网络计划技术》同宗——都是「有向无环图 + 资源约束」上的优化。现代 APS 还引入强化学习做「学习式排程」，把《智能制造》的 AI 能力直接注入了排产这个 IE 核心问题。</span>

## 5 工业数据：信息化的燃料

信息系统跑起来之后，真正的价值在**数据**。工业现场的数据来源日益丰富：

**自动识别**：条码、二维码、RFID——让每件物料、每道工序「有身份」。
**传感器与 SCADA**：温度、压力、振动、电流的实时流——设备状态的脉搏。
**工业互联网平台**：把分散在设备、MES、ERP 的数据汇聚到云端，做分析。<span class="marginnote">有了数据流，《质量管理》的 SPC 控制图可以每 30 秒自动重算一张；《成本控制》的差异分析可以每日自动归因；《制造系统》的 OEE 可以实时显示在车间大屏。信息化的回报，是让 IE 从「每月做一次分析」进化到「每时每刻都在分析」。</span>

**辨析｜易错点：** 「上系统」不等于「信息化成功」。**没有数据规范的 ERP 是高级 Excel，没有数据质量的 MES 是昂贵摆设**。信息化的成败，八成在数据规范与流程标准化，两成在软件本身——这与《制造系统》里 CIM 的教训一模一样：接口统一、编码一致，系统才有灵魂。

### 从数据到决策：信息化的闭环

信息化的终极形态，是把「数据 → 信息 → 决策 → 行动」接成一个自动闭环。以一个典型的「设备 OEE 异常」场景为例，完整的闭环长这样：

1. **采集**：PLC 与传感器每秒记录设备开停状态、加工节拍、废品数，MES 实时汇总。
2. **分析**：系统自动算出 OEE，发现可用率（Availability）低于目标——把《制造系统》的 OEE 分解到「停机原因」维度。
3. **报警**：看板亮起、工单自动派给维修组，附上最近 30 分钟的设备参数快照。
4. **行动**：维修组按数据定位是换型超时还是主轴异常，处理后在系统里关闭工单。
5. **积累**：历史数据沉淀，形成「哪类设备、哪种时段、最容易因何停机」的模式库，为下一次预防性维护提供依据。

**核心要点：信息化的回报不在「上了多少系统」，而在「闭环转得有多快」**。传统工厂的闭环以天计——月底才发现 OEE 掉了；信息化的工厂以分钟计——掉了马上被抓住。这个「反馈延迟的压缩」正是《质量管理》PDCA 里 Check 环节的数字化加速，也是《智能制造与工业4.0》里系统「自优化」的前提。

## 6 小结

- 信息化主线：**MRP → 闭环 MRP → MRP II → ERP**，核心是「一套数据、处处共享」。
- **ERP 管计划**（应该做什么），**MES 管执行**（实际做了什么）；两者差距就是 IE 的分析对象。
- **ISA-95** 五层架构把业务规划、制造运营、监控、控制、物理层分层解耦。
- **ERP vs MES**：企业级资源 vs 车间级执行，时间尺度差三个数量级，缺一不可。
- 数据来源：**条码/RFID、传感器/SCADA、工业互联网**；没有数据规范，系统只是昂贵摆设。

在下一节，信息化把 IE 的数据轨道铺好了，下一步是让这条轨道自己学会决策。**智能制造与工业4.0**将把大数据、AI 与数字孪生接上产线，走向「系统自己优化自己」的时代。
