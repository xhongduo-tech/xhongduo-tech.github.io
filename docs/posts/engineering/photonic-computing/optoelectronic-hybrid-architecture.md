## 为什么从光电混合架构开始

第四篇结尾我们看到了光的短板：非线性贵、不能存储、不好控制。于是「全光计算机」的理想让位于一个更务实的形态——**光电混合架构**：光负责矩阵乘与互连，电负责存储、控制、激活与精度修正。这不是妥协，而是当前工程界的主流共识。理解这条分工线，就理解了为什么所有光计算芯片的「光引擎」旁边总跟着一大片电子电路。<span class="marginnote">这条主线从第一至四篇的纯光原理，过渡到真正能商用的芯片形态。Lightmatter 的 Envise 把「电子存算 + 光子乘加」做成了产品，是本节最重要的现实参照；Shastri 2021 综述也明确把「混合架构」列为光子计算走向实用的必由之路。</span>

## 1 纯光为什么不够：三块短板

把前三篇的知识摊开，纯光系统的三块短板立刻显形：

**不能存储**：光没有「内存」。光场一旦传播过去就消散了，权重、激活、中间结果都必须停在电域或材料里。没有存储就没有「可编程性」，也就没有通用计算。

**非线性弱**：第四篇列的五条光学激活路线，没有一条能做到电子的可编程性。深度学习需要的非线性，目前仍由电子以绝对优势提供。

**控制与调度难**：光路的相位要稳定、波长要对齐、信号要定时，这些「控制面」工作几乎全是电的活。纯光系统连「怎么告诉下一个器件该干什么」都成问题。<span class="marginnote">这三块短板不是物理定律的死刑，而是「性价比」的裁决：光在需要高带宽、高并行的地方赢，在需要记忆与逻辑的地方输。混合架构就是顺着这条性价比曲线设计的。</span>

值得注意的是，这三块短板与「存算一体（in-memory computing）」的兴起高度同构。电学存算一体把存储与计算融合进同一器件（如忆阻器、SRAM 阵列内计算），本质上也是为了解决「搬运数据太贵」；光计算则是把「运算」本身从电搬到光。**一个把计算搬向存储，一个把计算搬向光，两股力量都在围攻同一堵墙——冯诺依曼的数据搬运墙。** 第九篇《非冯诺依曼光子学》会把这条线索正式接上。<span class="marginnote">这堵「搬运墙」也在电学侧催生了近存计算、存算一体等路线，与光计算的「算得快」互为镜像。</span>

## 2 分工原则：光做什么、电做什么

混合架构的分工不是随意的，它遵循一条清晰的**性价比原则**：

**光做**：矩阵乘法、卷积、傅里叶变换、高速互连——一切「高吞吐、高并行、强线性」的运算。

**电做**：存储权重与中间结果、非线性激活、控制调度、精度修正、数据格式转换。

这条分界还有一层**粒度**问题：光与电的交接是按「层」还是按「张量」还是按「运算」？粒度越粗（整层光算完再回电），转换次数越少、能效越好，但灵活性越差；粒度越细，灵活性越高，转换开销越大。主流工程选择「层级交接」——把一整层矩阵乘丢给光，结果回电做激活与下一层调度，这是能效与灵活性的常见平衡点。<span class="marginnote">「交接粒度」是混合架构里最容易被忽视却最能影响实测性能的参数。第五篇之后再看各家芯片的框图，首先数清楚的就是「光在哪个粒度介入」。</span>

这条分界可以用一句话概括：**让光做「乘加」，让电做「乘加以外的一切」。** 为什么矩阵乘必须交给光？因为那是深度学习中吞吐最大、也最适合并行的部分；为什么存储必须留给电？因为电有成熟的 SRAM/DRAM/缓存体系，而光连内存都造不出来。<span class="marginnote">这条分工与 GPU 内部「Tensor Core + CUDA 核」的分工同构：专用核做矩阵乘，通用核做其余。光计算只是把「专用核」从硅电路换成了光引擎——架构思想一脉相承。</span>

但分工比例不是固定的一半一半。不同应用对光与电的需求权重不同：**稠密大矩阵的 Transformer 推理，光占比高；稀疏、小批、控制密集的任务，电占比高。** 于是「光电混合」不是一种固定架构，而是一条从「光为主」到「电为主」的连续光谱——设计者按应用从中取点。这也是为什么各家的混合架构长相差异很大：不是原理不同，而是**取舍不同**。

## 3 数据进出光的边界：光电转换是双刃剑

混合架构最微妙的部分，是**光域与电域之间那道转换边界**。数据从电进光，需要**电光转换**（驱动调制器）；从光回电，需要**光电转换**（探测器 + 放大 + ADC）。

光电转换是一把双刃剑：一方面，它是混合架构得以成立的前提——没有它，光和电无法对话；另一方面，**每次转换都消耗能量、引入噪声、损失精度**。ADC 的位数、调制器的驱动电压、探测器的噪声，直接决定了系统能从光里「读回」多少有效信息。

**重点：混合架构的性能天花板，往往不在光引擎，而在转换边界。** 光引擎做到 160 TOPS/W 很容易，但把结果读回电、做 ADC、写内存，可能把整个系统的有效能效拉回电子的量级。这就是为什么光计算芯片设计者们如此重视「减少转换次数」——一次全光中间处理，胜过三次光电电光往返。<span class="marginnote">这条直觉会延伸到第七篇《共封装光学 CPO》：CPO 的本质之一，就是把光电转换从「很远的地方」搬到「交换芯片旁边」，缩短电链路、减少信号调理损耗。转换边界的远近，直接决定功耗。</span>

ADC 是边界上最贵的零件。一个高分辨率 ADC 的功耗随位数指数增长（每增加一位，功耗约翻倍），而光模拟计算的输出精度又受噪声限制——于是「读多少个有效比特」成为精打细算的问题：位太少，浪费光引擎的动态范围；位太多，ADC 吃掉全部能效优势。**混合架构的精度设计，本质上是在「光能给出多少位」与「电愿意花多少功耗去读」之间讨价还价。** 这正是第十二篇《与电子计算的边界》要系统展开的主题。<span class="marginnote">一个常在论文里出现的数字：6–8 个有效比特是光模拟计算的典型精度，而现代训练需要 FP16/FP32。混合架构用「低精度光做粗算、高精度电做精修」的分层策略弥合这道鸿沟。</span>

## 4 案例解剖：Lightmatter Envise

把上面的抽象原则落到具体产品上，最好的样本是 Lightmatter 的 **Envise**——一套「电子存算 + 光子乘加」的混合 AI 加速器：

- **光子张量核**：用 MZI 网格实现矩阵乘法，这是唯一的光学运算单元，负责吞吐最大的乘加。
- **电子存储与控制**：权重、激活值、中间结果存放在片内电子存储器；控制调度由电子逻辑完成。
- **波长复用**：用多个波长同时喂入同一个光子张量核，让不同的计算在同一片硬件上并行——光学的「多色并行」是 Envise 区别于纯电加速器的关键吞吐来源。
- **精度兜底**：光子模拟运算的误差，由电子端的高精度运算与激活函数修正。

Envise 的「电子存算」还有一层具体含义：权重不是「烧」进光学硬件的，而是存在电子存储器里、随时可加载进相位调谐器。这带来两个工程优势——**可编程**（换模型只需换权重，不需换硬件）与**可容错**（某节点的相位漂移，可通过重新加载标定补偿）。对比之下，纯光或衍射式方案把权重固化在器件里，换任务成本极高。**「权重存在电里、算在光里」这一句话，就是混合架构最浓缩的说明书。**

Envise 在 2025 年《自然》论文里的进阶版本，把四个 128×128 光子张量核与 12nm 电子控制接口叠在一起，跑通了 ResNet、BERT 等真实模型，精度与 32 位浮点基线相当。**它证明的不是「光赢了」，而是「光 + 电按分工组合，能无缝接住现有软件栈」**——这对产业化的意义远大于任何能效纪录。<span class="marginnote">「无缝接住现有软件栈」是混合架构最容易被低估的价值：如果换光计算要重写整个框架，迁移成本会杀死一切能效收益。Envise 让 PyTorch 训练好的模型直接跑在光上，才是它真正聪明的地方。</span>

## 5 公式解析：系统能效的分摊模型

混合架构的能效，可以写成一个简单的分摊式。一次完整的数据通路，总能耗是三部分之和：

$$E_{total} = E_{opt} + E_{conv} + E_{mem}$$

三步拆解：

- **第一步，读三项**：$E_{opt}$ 是光引擎（激光、调制、探测）的能耗；$E_{conv}$ 是光电/电光转换（ADC、DAC、放大）的能耗；$E_{mem}$ 是存储与访存的能耗。
- **第二步，看规模**：$E_{opt}$ 随吞吐增长很慢（一次传播算一整块矩阵），$E_{conv}$ 与 $E_{mem}$ 却随数据量线性增长。当矩阵变大，$E_{opt}$ 的占比会**越来越小**，$E_{conv} + E_{mem}$ 成为主角。
- **第三步，读结论**：混合架构的能效优化，核心是**让 $E_{conv} + E_{mem}$ 尽量小**——减少转换次数、增大数据复用、让光一次处理更大块的矩阵。光引擎本身已经「便宜」，系统的胜负手在边界与存储。

这条式子也解释了混合架构的一个悖论：**光越强，越不能只靠光。** 一旦光把乘加做到几乎免费，数据搬运与转换就变成新的瓶颈——于是工程重心从「把乘加做进光」转向「把数据喂进光」。这也是第九篇《非冯诺依曼光子学》里储备池、伊辛机的架构动机：让计算发生在数据所在的物理系统中，减少搬运。

举一个量级直观的算例。设光引擎 $E_{opt} = 1$（归一化），而每次光电转换加存储读写 $E_{conv} + E_{mem} = 3$。一个「全光中间处理」的流水：数据进光（1）+ 光算（1）+ 数据出光存回（3）= 5；若在中途必须出光一次再进光，就是 5 + 3 + 1 = 9。**多一次转换，总能耗接近翻倍。** 这个粗糙的算术足以说明：混合架构设计者的最高优先级，永远是「让光一次算完尽可能大的块」。

## 6 核心对比表：纯光 vs 光电混合 vs 纯电

| 维度 | 纯光 | 光电混合 | 纯电（GPU） |
| --- | --- | --- | --- |
| 矩阵乘 | 极强 | 强（光引擎） | 强（Tensor Core） |
| 存储 | 无 | 电存储 | 完善缓存体系 |
| 非线性 | 弱 | 电做 | 极强 |
| 控制调度 | 难 | 电做 | 成熟 |
| 数据转换 | 无 | 有（边界开销） | 无 |
| 软件生态 | 需重写 | 可复用现有框架 | 成熟 |
| 当前状态 | 研究 | 商用起步（Envise 等） | 主流 |

读这张表，结论很清楚：**纯电成熟但功耗墙；纯光有天花板但生态空白；混合架构用「光做乘加 + 电做其余」换来能效与生态的兼得。** 这也是为什么五年前遍地「全光」愿景，今天产业化声音几乎全部转向「光电混合」。

还有一个常被忽略的工程事实：混合架构的**验证成本**最低。纯光系统要证明一个端到端任务（如分类一个数据集）正确，需要一整套光学测试平台；混合架构则可以借用成熟的电子测试与调试手段，先验证电子部分、再逐块接入光引擎。**能借用现成工具链，是混合架构被产业化偏爱的隐形原因之一**——工程世界不只比性能，也比「谁更容易被造出来、测出来、修起来」。

## 7 小结

- 纯光的三块短板：**不能存储、非线性弱、控制难**——这是混合架构存在的物理理由。
- 分工原则：**光做乘加与互连，电做乘加以外的一切**；与 GPU 的 Tensor Core 分工同构。
- 性能天花板常在**转换边界**：$E_{total} = E_{opt} + E_{conv} + E_{mem}$，减少转换次数是关键。
- Envise 是混合架构的现实样板：电子存算 + 光子乘加 + 波长复用，无缝接住现有软件栈。
- 产业共识已转向「光电混合」：能效与生态兼得，是当下最可行的光计算商业化形态。
- ADC 功耗随位数指数增长，精度设计是在「光给几位」与「电读几位」之间讨价还价。
- 「权重存在电里、算在光里」+ 可复用的电子测试链，是混合架构产业化被偏爱的原因。
- 光电混合不是固定比例，而是一条从光为主到电为主的连续光谱，按应用取点。
- 多一次光电转换能耗近乎翻倍：设计铁律是「让光一次算完尽可能大的块」。
- 交接粒度（层/张量/运算）决定能效与灵活性的平衡，层级交接是常见选择。
- 精度分层：光做低精度粗算（6–8 bit），电做高精度精修，用混合精度弥合鸿沟。
- Envise 的可编程性来自「权重存电里」：换模型只换权重，不换硬件。
- 一句话收束：混合架构不是「光与电的妥协」，而是**「光算得快、电记得住」的最优组合**。
