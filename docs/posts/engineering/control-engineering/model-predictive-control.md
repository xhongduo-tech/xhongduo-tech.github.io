## 为什么从模型预测控制开始

前面的控制器大多是"看到现在，决定现在"——PID 用当前误差，状态反馈用当前状态。**模型预测控制（Model Predictive Control, MPC）**换一种更远的眼光：**用模型预测未来，在当前时刻做一段"规划"，只执行第一步，然后滚动重算**。这套"预测 → 优化 → 只走一步 → 重来"的滚动机制，让 MPC 能天然处理两样经典方法很难的事情：**多变量约束**（控制量不能太大、状态不能越界）与**前瞻性**（提前刹车、提前避障）。MPC 1960 年代诞生于过程工业（那时叫动态矩阵控制 DMC），如今已在先进过程控制、自动驾驶、无人机、机器人里遍地开花。它是"动态规划"与"最优控制"在工程上最成功的落地形态。<span class="marginnote">MPC 在工业界地位极高：现代石化、炼油、电厂的先进过程控制几乎全是 MPC 的变体。它能处理多输入多输出、硬约束、非线性，这在经典 PID 框架里做不到——所以即便计算量更大，工业界也愿意买单。</span>

## 1 MPC 的核心三步

每个采样时刻，MPC 重复三件事：

1. **预测（predict）**：用对象模型，从当前状态出发，对未来 $N$ 步（预测时域）的输入序列 $\{u_k, u_{k+1}, \dots, u_{k+N-1}\}$ 预测输出轨迹 $\{y_{k+1}, \dots, y_{k+N}\}$。
2. **优化（optimize）**：求解一个有限时域最优控制问题——最小化"输出跟踪误差 + 控制变化量"的代价函数，**同时满足输入、输出、状态的约束**，得到最优输入序列。
3. **滚动（rolling / receding）**：只执行序列中的**第一步** $u_k$，到下一时刻根据新测量**重新预测、重新优化**。

"只走一步、不断重算"称为**滚动时域（receding horizon）**——这是 MPC 名字里"预测"的含义，也是它区别于一次性开环最优控制的关键。<span class="marginnote">为什么只执行第一步？因为模型不准、扰动存在，规划到第 N 步的计划过了几步就过时了。滚动重算让 MPC 每步都用最新信息修正——这本质上是一种"负反馈"，也是 MPC 鲁棒性的来源之一。</span>

## 2 代价函数与约束

MPC 每步求解的优化问题写成：

$$\min_{u_k,\dots,u_{k+N-1}} \sum_{i=1}^{N} \big\| y_{k+i} - r_{k+i} \big\|_Q^2 + \sum_{i=0}^{N-1} \big\| \Delta u_{k+i} \big\|_R^2$$

$$\text{s.t.} \quad x_{k+1} = Ax_k + Bu_k, \quad u_{\min} \le u \le u_{\max}, \quad y_{\min} \le y \le y_{\max}$$

- 第一项罚**跟踪误差**（输出偏离参考轨迹的程度），$Q$ 加权；
- 第二项罚**控制变化量** $\Delta u$（动作不要太猛），$R$ 加权；
- 约束包括系统模型、输入上下限（执行器饱和）、输出/状态上下限（安全边界）。<span class="marginnote">把 $\Delta u$ 写进代价而不是 $u$，是为了让控制器"温和地变"——这个细节让 MPC 的动作比普通 LQR 平滑得多，是工业现场喜欢它的原因之一。</span>

对线性模型 + 二次代价 + 线性约束，这是**二次规划（QP）**问题，有成熟高效的求解器，每步毫秒级求解。非线性 MPC 则求解非线性规划（NLP），计算量大一个量级。

## 3 公式解析：MPC 的滚动优化

$$\min_u \sum_{i=1}^{N} \big\| y_{k+i} - r_{k+i} \big\|_Q^2 + \sum_{i=0}^{N-1} \big\| \Delta u_{k+i} \big\|_R^2$$

对它做四步拆解：

- **第一步，看预测时域 $N$**：$N$ 是"往前看几步"。$N$ 大，前瞻性强、规划更远，但优化变量多、计算慢、且模型误差累积；$N$ 小，计算快但短视。$N$ 是"远见与成本"的折中。
- **第二步，看第一项**：$\|y-r\|_Q^2$ 是加权平方误差——与 LQR 的 $x^TQx$ 一脉相承，但作用对象是"预测的未来输出"而非当前状态。**MPC = LQR 的有限时域 + 约束版本**，这个等式是理解 MPC 的最快路径。
- **第三步，看第二项**：$\|\Delta u\|_R^2$ 惩罚控制变化——保证动作平滑，同时保证解的唯一性。
- **第四步，看约束的"免费"性**：约束是硬性的不等式，直接嵌进优化问题——这是 MPC 相对 LQR 的**本质优势**：LQR 的线性反馈无法表达"限幅"，MPC 把限幅变成了优化问题的一部分。

**辨析｜易错点：** MPC 的解是"当前时刻的第一步"，不是"整个开环序列"。论文/程序里计算出的 $u_k$ 立即执行，$u_{k+1}$ 到下一时刻**重新算**——把开环最优误当闭环控制是初学者的经典错误。另外，MPC 的可行性问题：约束太紧时可能无解，工程上要设计**软化约束**（把硬约束变软、加罚项）保证永远有解。<span class="marginnote">可行性与稳定性是 MPC 的理论两大主题：为了保证"永远能解出第一步"，工程上给状态约束留余量或用软约束；为了证明闭环稳定，理论家常在代价函数末端加终端约束/终端代价。知道这些术语，读 MPC 文献就不慌。</span>

## 4 MPC 与 LQR、PID 的对比

| 维度 | PID | LQR | MPC |
| --- | --- | --- | --- |
| 模型 | 不需要 | 需要线性模型 | 需要模型（可非线性） |
| 约束处理 | 不支持 | 不支持 | **原生支持** |
| 前瞻性 | 无 | 无穷时域（隐式） | 有限时域显式规划 |
| 多变量 | 勉强 | 支持 | **天然支持** |
| 计算量 | 极小 | 小 | 大（每步解优化） |
| 使用场景 | 通用兜底 | 无约束最优 | 有约束、多变量、高要求 |

工程选型经验：简单回路用 PID；无约束最优用 LQR；**需要管约束、管多变量、管前瞻就用 MPC**。三者不是替代关系，而是同一工具箱里的不同档次。<span class="marginnote">MPC 与强化学习的关联：MPC 是"基于模型的规划"，RL 是"无模型的学习"。现代研究（如 Model-Based RL、MPC 作为策略先验）正在融合两者——MPC 提供安全与约束保证，RL 学习模型未知部分。这也是自动驾驶领域的主流探索方向。</span>

## 5 MPC 的工程应用

MPC 的工程生态非常成熟：

**过程控制**：炼油、化工的多变量协调控制（DMC、IDCOM 等经典算法都是 MPC 前身）。
**自动驾驶**：轨迹跟踪 MPC 同时约束转向、加速度、侧向偏移，预测前方道路曲率提前减速——"看路开车"的数学实现。
**无人机/机器人**：避障 MPC、腿式机器人步态规划、机械臂运动规划。
**能源**：电池充放电、楼宇温控、电网频率调节的调度层。

工业部署要点：模型辨识要准（MPC 的质量上限由模型决定）、预测时域与控制时域要调、软硬约束要分层、求解器要实时达标。<span class="marginnote">MPC 有一个"隐含的自适应"特性：模型不准时，滚动重算 + 输出反馈会在一定程度上补偿模型误差（因为每步都从实测状态重新出发）。但这个补偿有限——模型误差过大，预测就不可信，所以"预测模型的质量"始终是 MPC 的生命线。</span>

## 6 MPC 数值示例：一阶系统

用一个能手算的一阶系统看 MPC 的滚动机制。设对象 $x_{k+1} = 0.8 x_k + u_k$（一阶惯性离散化），目标把状态调到 $0$，预测时域 $N=2$，代价仅含状态项（$Q=1, R=0$），约束 $-1 \le u \le 1$。

**第一步，当前时刻**：设当前 $x_k = 2$。写出两步预测：

$$x_{k+1} = 0.8\cdot2 + u_k = 1.6 + u_k, \qquad x_{k+2} = 0.8 x_{k+1} + u_{k+1}$$

**第二步，求最优序列**：最小化 $J = x_{k+1}^2 + x_{k+2}^2$。无约束时令偏导为零，解得 $u_k = -1.28$，$u_{k+1} = -0.256$——理想上一步步把状态拉向零。

**第三步，处理约束**：$u_k = -1.28$ 越界（$u_{\min}=-1$），被**限幅到 $-1$**。重新算 $x_{k+1} = 1.6 - 1 = 0.6$，再优化 $u_{k+1}$（此时可行），得 $u_{k+1} = -0.48$。<span class="marginnote">注意约束的处理方式：不是"算完再截断"，而是"把约束嵌进优化重新求解"——限幅会影响 $x_{k+1}$，进而影响后续最优。这就是 MPC"原生处理约束"的含义，也是它优于"PID + 手动限幅"的地方。</span>

**第四步，只执行第一步**：本时刻只施加 $u_k = -1$；下一时刻用新的测量 $x_{k+1}$ **重新预测、重新优化**——滚动时域完成一次。

**第五步，体会滚动的好处**：若第二步的模型有误差（真实 $x_{k+2}$ 与预测不同），滚动重算会及时修正；而一次性开环执行 $u_k, u_{k+1}$ 则会把误差带到底。<span class="marginnote">这个例子虽小，却完整展示了 MPC 的三要素：预测（前两步的状态方程）、优化（带约束的最小化）、滚动（只执行第一步）。三要素齐了，MPC 的骨架就立住了。</span>

**辨析｜易错点：** $N$ 取太小（如 $N=1$）时 MPC 退化成"贪心"，可能短视；$N$ 取太大计算负担重。本例 $N=2$ 只是为了手算，真实系统 $N$ 常取 10~30。另外约束越紧越容易无解——工程上给状态约束留余量。

**MPC 的家族成员**：MPC 不是单一算法，而是一个按模型与约束复杂度展开的家族：

- **线性 MPC**：线性模型 + 二次代价 + 线性约束 = QP 问题，每步毫秒级求解，工业主流。
- **非线性 MPC（NMPC）**：非线性模型 + 非线性代价/约束，求解 NLP，计算量大一个量级，用于强非线性对象（火箭、化学反应器、双足机器人）。
- **鲁棒 MPC**：把模型不确定性纳入优化（最坏情况或鲁棒不变集），保证"整族对象稳定"。
- **随机 MPC（SMPC）**：用概率约束处理随机扰动，介于鲁棒（太保守）与确定性 MPC（太乐观）之间，是近年研究热点。
- **自适应/学习 MPC**：模型在线更新或从数据学习，把 MPC 的"预测能力"与自适应/强化学习的"学习能力"结合。

**选型经验**：能从简单线性 MPC 起步就别直接上 NMPC——模型的复杂度决定求解速度与调试难度，工程上"够用就好"。**MPC 家族的共同灵魂是"预测 + 优化 + 滚动"**，换的只是模型与约束的表达。

**一句话记住 MPC**：MPC = 用模型看未来、用优化选动作、只走一步再重来——**"走一步看一步"的滚动机制让它既有前瞻性、又天然鲁棒**。它是"最优控制 + 约束 + 滚动反馈"三者的工程合体。

## 7 小结

- **MPC**：预测 → 优化 → 执行第一步 → 滚动重算，是"有限时域最优控制 + 滚动反馈"。
- 代价函数 = 跟踪误差加权 + 控制变化加权；**约束（输入/输出/状态）原生嵌入优化**。
- 线性 MPC = 每步求解**二次规划（QP）**；非线性 MPC 求解 NLP。
- **MPC = LQR 的有限时域 + 约束版**；相对 PID/LQR 的核心优势是约束处理与前瞻性。
- 只执行第一步、滚动重算，是 MPC 闭环鲁棒性的来源；注意可行性（软约束）与稳定性（终端约束）。
- 应用：过程控制、自动驾驶、无人机、机器人、能源系统。

在下一节，我们转向一类"更猛"的非线性控制——**滑模控制**：让系统状态"滑"到一条设计好的轨道上，对不确定性天然免疫。
