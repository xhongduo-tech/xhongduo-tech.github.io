## 为什么从开放数据库与工作流开始

前面每一篇都默认「有一批高质量、可访问的计算数据」，而本专题的几乎所有方法——机器学习势的训练、材料信息学的模型、逆向设计的搜索空间、凸包判稳——都站在同一个地基上：**开放的高通量计算数据库与自动化工作流**。没有 Materials Project、OQMD、AFLOW 这批公开资产，材料基因组与逆向设计都只是口号。这一篇把地基本身拆开看：数据从哪来、怎么保证可比、怎么用工作流自动化地造出来。

开放数据对材料学是迟到的革命：比起高能物理、基因组学早在 2000 年前后就拥抱了开放数据，材料学的大规模开放要等到 2011 年之后——Materials Project 2011 年上线、OQMD 2015 年、AFLOW 同期。**这十年的「迟到」恰恰说明它来之不易**：要协调不同课题组的标准、要承担持续的算力与运维成本、还要让开放的数据真正被用起来。

本讲在专题里的位置是「地基中的地基」：前面十篇的模型、筛选、逆向，训练数据与候选空间全都来自这些数据库；而后面（本讲之后）只剩一篇案例复盘，等于「地基浇筑完毕后，盖最后一层瓦」。**先读本讲再回头读前面，很多「数据从哪来」的疑问会豁然开朗。**

<span class="marginnote">三个数据库全部基于 VASP + PAW 赝势 + PBE 泛函，这是它们之间能互相对照的前提；差异只来自参数选择（k 点密度、DFT+U、处理流程），而非不同的 DFT 实现——理解这一点，才能读懂「跨库差异」是怎么回事。</span>

## 1 三大数据库盘点

**Materials Project（MP）**：材料基因组计划的旗舰，约 15 万种无机化合物。性质覆盖广：形成能、带隙（PBE 与 HSE06 两套）、弹性张量、压电张量、介电、声子、表面能、缺陷、相图工具。它的杀手锏是**凸包相图**与 Pourbaix 图等分析 App，以及围绕 `pymatgen`/`emmet` 数据模型设计的 REST API。

**AFLOW（Automatic FLOW）**：体量最大，约 390 万条记录。它的特色是从原型晶体结构**系统生成假设结构**，对合金与金属间化合物覆盖极佳；提供标准化能带、团簇展开、有限温度热力学、弹性/热力学性质，走 PBE 一致性路线。

**OQMD（Open Quantum Materials Database）**：由 Wolverton 团队 2015 年发布，约 140 万条。最大特色是**计算一致性**：全库统一 VASP 设置与赝势，是做形成能基准的最可靠选择；它自带从数据构建 DFT 基态相图的工具（`qmpy` 维护）。

**关键对照表：**

| 数据库 | 规模 | 特色 | 首选场景 |
| --- | --- | --- | --- |
| Materials Project | 约 15 万化合物 | 性质广、工具全、API 好 | 默认首选、相图/电化学分析 |
| AFLOW | 约 390 万条 | 合金/假设结构覆盖广 | 成分空间大规模筛选 |
| OQMD | 约 140 万条 | 计算一致性最强 | 形成能基准与训练集 |

三个库的「体量—一致性—性质广度」各有所长：AFLOW 最大但每条的性质维度窄，MP 性质最全但一致性不如 OQMD，OQMD 最一致但性质种类有限。**选库先问自己的需求：要广度选 MP、要基准选 OQMD、要覆盖选 AFLOW。** 这也是为什么专业团队常常「多库并用、各取所长」。

值得补一笔的还有近年兴起的 **JARVIS-DFT**（NIST 维护）与 **OpenCatalyst**（催化体系）等专项库——前者侧重范德华体系、二维材料与拓扑性质，后者专注吸附与催化。**数据库生态已经不只是「三个巨头」，而是一个按需求细分、可组合的星座**——理解主库的逻辑，就可以快速读懂任何新库。

数据获取方式也值得记一笔：除了 REST API 在线查询，主库都支持**批量下载（bulk download）**，让用户在本地把整个子集拉下来做大规模分析或训练。对机器学习流水线而言，批量下载几乎是必选项——**几十万条的 API 分页请求既慢又容易触发限流，本地数据 + 自建索引才是正解**。

## 2 跨库一致性：能混用吗

把 MP 与 OQMD 对同一化合物的形成能拉出来对比，会发现在几到几十 meV/atom 量级上不一致——这个差异与「DFT 和实验的差异」同量级。<span class="marginnote">对同一结构，跨库对「是否金属」的判断可差到 7%，对「是否磁性」的判断可差到 15%。同一个材料在 MP 里稳定、在 AFLOW 里亚稳，两个结论可以同时「正确」——因为参考态、泛函细节与数值处理不同。</span>

**重点：数据一致性比数据量更重要。** 当你用它训练机器学习模型时，跨库差异会变成标签噪声。两条实操纪律：

- **训练集单一来源优先**：需要形成能精度时，整批用 OQMD；需要性质多样性时，整批用 MP——避免「一半 MP 一半 OQMD」的隐性双峰分布。
- **跨库结论先对齐约定**：比较相稳定性前，先核对能量参考态与 DFT+U 设置；必要时用同一流水线重算待比较的子集。

一篇 2023 年的研究在《物理评论材料》上系统量化了三个库对相同结构的性质分歧，结论是「分歧真实存在且可预期」——**这不是数据库的缺陷，而是你必须声明与处理的测量误差**。更精确地说：DFT 结果本来就不是一个「真值」，而是「参数选择的一个采样」；三个库的差异，暴露的正是这个采样空间有多宽。**把数据库当成「绝对真值」来用，是数据用户最危险的本能。**

处理跨库差异还有一条进阶策略：**做「同库对比」而非「跨库对比」**。当你要比较「材料 A 和材料 B 谁更稳定」时，尽量让两者来自同一个库、同一套参考态，这样系统性偏差在相减时抵消，结论更可靠。**跨库结论要谨慎，同库结论相对安全**——这条经验适用于相稳定性、带隙、磁性等一切可比较的性质。

这条策略也是机器学习训练的另一条铁律：**训练集与验证集最好同源**。若训练用 OQMD、验证用 MP，模型「分数差」里就混入了库间差异，你无法判断是模型不行还是数据不同。**报告模型分数前，先问一句：训练与验证是同库吗？**

## 3 工作流框架：把计算自动化

数据库不是天上掉下来的，它们由**工作流框架**流水线生产。理解这套工具链，你就能自己生产数据、而不只是消费数据：

- **pymatgen**：Python 材料分析库，结构、对称性、相图、能量学的瑞士军刀，MP 的数据模型基础。
- **ASE（Atomic Simulation Environment）**：统一多种计算代码接口的原子模拟框架。
- **FireWorks / atomate**：MP 团队的工作流系统——把 VASP 计算拆成「结构优化→自洽→带结构」等可断点续跑、可重试、可追溯的步骤。
- **AiiDA**：带完整数据谱系（provenance）的自动推理工作流平台，每一步算式的输入输出、参数、环境都被记录——这是「可复现」的工程化答案。
- **matminer**：材料数据挖掘工具，内置大量描述符与数据获取接口，直接对接信息学流水线。

<span class="marginnote">工作流框架的隐藏价值是<strong>谱系（provenance）</strong>：AiiDA 能回答「这条数据是哪台机器、用哪个版本的 VASP、哪批赝势算出来的」。对机器学习训练集而言，谱系 = 误差可解释 = 模型可审计。没有谱系的高通量数据，等于「来路不明的砖」。</span>

为什么「可复现」如此重要？因为材料计算的「跑通」与「跑对」是两回事：同样的体系、不同版本的 VASP、不同的赝势文件，结果可能差几十 meV。**当数据被拿去训练模型、指导设计时，「怎么算出来的」和「算出多少」同等重要**——谱系就是把「怎么算出来的」变成可查询、可审计、可回放的东西。这也是 AiiDA 在学术圈被广泛采用的根本原因。

工作流还有个常被新手忽略的细节：**重试与容错**。百万条计算里，总有一定比例会因为数值问题、磁盘满、节点故障而失败——工作流框架的「断点续跑、自动重试、失败归档」让这些意外可管理。**没有容错机制的高通量，等于没有应急预案的生产线，一停全停。**

还有一层「软性」却同样重要的基础设施：**文档与社区**。pymatgen、ASE、AiiDA 都有成熟文档与社区答疑，遇到「结构对称性怎么定」「相图怎么画」这类问题，社区是比任何教程都快的指南。**工具链的可维护性，一半在代码，一半在人**——这也是开源生态对材料计算如此关键的原因。

## 4 OPTIMADE：数据库之间的共同语言

七个机构的数据库想互查，不能各写各的 API。**OPTIMADE（Open Databases Integration for Materials Design）**定义了跨库查询结构的标准：用同一个 HTTP 查询语言按元素、空间群、晶格参数筛选结构。<span class="marginnote">注意 OPTIMADE 标准化的是<strong>结构查询</strong>，不是性质查询——形成能、带隙、声子这些性质仍要各库原生 API 取，跨库对比性质前仍须对齐约定。它解决「找到结构」，不解决「性质可比」。</span>

**重点：OPTIMADE 是「找得到」，一致性对齐是「比得对」**——两者合起来，才让跨库的逆向设计搜索成为可能。标准化的价值不在于消灭差异，而在于让差异显式、可处理。

标准化还有一个「看不见的回报」：**生态复利**。当一个标准被足够多的库采用，围绕它长出的工具（跨库查询客户端、结构搜索服务、自动化的数据管道）会越来越多，反过来又让加入标准的库更有价值——**这是典型的网络效应，也是标准最难被放弃的原因。**

OPTIMADE 的意义还可以从生态角度读：它让「材料数据」像「网页」一样有了统一的寻址方式——任何一个支持标准的库，都能被任何一套工具查询。**它不替代各库的原生 API，而是给它们加了一层「互操作」的公共层**，这正是材料基因组方法「数据基础设施」愿景的落地。

对使用者的实操意义也直接：**写一套 OPTIMADE 查询，就能同时问询 MP、OQMD、AFLOW 等多个库的结构数据**，不必为每个库各学一套 API。配合「批量下载」策略（超过约五万条时走导出而非分页 API），跨库筛选的工程门槛被大幅降低。

## 5 公式解析：形成能的参考态约定

数据库里的形成能不是裸的 DFT 总能，而是相对参考态的相对值。OQMD 与 MP 的约定：

$$
\Delta H_f = E_{\text{compound}} - \sum_i n_i E_i^{\text{ref}}
$$

- **$E_{\text{compound}}$**：化合物结构优化后的 DFT 总能。
- **$E_i^{\text{ref}}$**：第 $i$ 种元素的参考态总能——**约定为元素在其标准晶体结构（如 fcc 铝、hcp 钛）下的 DFT 总能**，而非孤立原子。这是化学热力学「标准态」思想的计算版本。
- **$n_i$**：化学计量系数。
- **物理意义**：$\Delta H_f$ 度量「从纯元素合成本化合物的能量得失」。**参考态一旦不同（如某库用磁有序态、某库用非磁态），同化合物的形成能就会系统性偏移**——这正是跨库一致性问题的具体来源之一。

理解这条式子，你就理解了为什么「同一个材料在两个库形成能不同」不是 bug：它可能是参考态约定的合法差异。**查库之前先看文档里参考态怎么写**，是数据用户的第一课。

还有一个实操细节：**「稳定」判据的参考不是裸形成能，而是凸包距离（distance to hull）**——数据库标记一个材料「亚稳」，说的是它相对凸包高出多少 meV/atom。这个「高出多少」才是可跨库比较的量；裸的形成能数值反而不具可比性。**学会读「凸包距离」，比记住某个形成能数值有用得多。**

「凸包距离」也因此成了本专题反复出现的「度量单位」：逆向设计用它当稳定性闸门、材料基因组用它判断候选是否可合成、机器学习势用它评估训练数据的物理合理性——**一个概念贯穿多个环节**，这正是数据库定义「口径」的力量。理解了它，你就理解了为什么「参考态」是材料数据世界的第一公民。

## 6 小结

- MP、AFLOW、OQMD 三大库**同源（VASP+PAW+PBE）但参数不同**，覆盖广与一致性各有侧重。
- 跨库差异可达「DFT 与实验差异」同量级，**训练与结论前必须对齐约定**。
- pymatgen/ASE 管分析、FireWorks/atomate 管流程、AiiDA 管谱系——**工作流把「算数据」变成流水线**。
- OPTIMADE 让跨库结构查询标准化，但**性质可比性仍需自己保证**。
- 形成能的**参考态约定**决定数值口径，查库第一课是读文档。
- 数据库不是「绝对真值」，而是「参数选择的一个采样」——**差异要声明，约定要处理**。
- 批量下载 + 本地索引是机器学习流水线的正解，**几十万条 API 分页既慢又易被限流**。
- 训练集与验证集最好**同源**，否则模型分数里混入库间差异、无法归因。
- 凸包距离是跨库可比的稳定性度量，**「参考态」是材料数据世界的第一公民**。
