## 为什么从系统方法论开始

上一篇我们确立了「系统」「系统工程」「生命周期」三个基本概念，回答了系统工程**是什么**。但概念不会自动变成行动：一个项目摆在面前，先做什么、再做什么、每一步用什么知识，需要一套**可操作的流程框架**——这就是方法论（methodology）。本节的霍尔三维结构给出的是**硬系统**的经典展开方式：把系统工程活动铺成一个三维坐标架，任何一项工作都能在架子上找到自己的位置。<span class="marginnote">硬系统方法与软系统方法的区分，是整个方法论篇的骨架：前者适合「目标明确」的问题，后者适合「目标本身都说不清」的问题。记住这个二分，后面读案例时就能预判作者会选哪条路。</span>

## 1 霍尔三维结构：给系统工程装上坐标架

1969 年，美国工程师阿瑟·霍尔（A. D. Hall）提出**三维结构方法**，把系统工程的活动组织成三个正交的维度：**时间维、逻辑维、知识维**。<span class="marginnote">霍尔 1969 年发表《系统工程方法论》（A Methodology for Systems Engineering）时还是贝尔实验室的工程师。他的三维结构后来成为我国系统工程界「硬系统方法」的标准讲法，汪应洛《系统工程》与钱学森的推广工作都以此为核心。</span>

**时间维（time dimension）**：系统从规划到更新的时间顺序，通常划分为六个阶段——规划、方案、研制、生产、运行、更新。它回答「系统生命周期走到哪一步」。

**逻辑维（logic dimension）**：在时间维的每个阶段内部，都要经历的一组思维步骤，共七步——明确问题、目标设计、系统综合、系统分析、系统优化、系统决策、实施计划。它回答「这个阶段该做哪些思考动作」。

**知识维（knowledge dimension）**：完成上述步骤所需的各种专业知识——工程、医学、法律、经济、管理、社会科学等。它回答「解决问题需要调谁的知识」。

时间维的六个阶段各司其职，可作一表：

| 阶段 | 主要工作 | 典型产出 |
| --- | --- | --- |
| 规划 | 明确需求与可行性 | 任务需求说明 |
| 方案 | 拟定总体方案 | 系统方案论证报告 |
| 研制 | 设计、试制、试验 | 样机与测试报告 |
| 生产 | 制造、装配、检验 | 定型产品 |
| 运行 | 使用、维护、保障 | 运行记录 |
| 更新 | 改进、退役、换代 | 改型方案 |

注意逻辑维的七步在时间维的**每个阶段都要完整走一遍**——「每阶段七步」的嵌套才是三维结构的完整用法。

逻辑维的七步是霍尔对「工程师头脑里的思维动作」的显式化，每一步对应一个可执行的问题：

| 逻辑步 | 核心问题 | 对应本专题 |
| --- | --- | --- |
| 明确问题 | 要解决的是什么 | 第 3 篇需求分析 |
| 目标设计 | 达到什么目标 | 第 3、7 篇 |
| 系统综合 | 有哪些候选方案 | 第 4、7 篇 |
| 系统分析 | 各方案表现如何 | 第 9 篇建模与仿真 |
| 系统优化 | 如何求最优 | 第 7、11 篇 |
| 系统决策 | 选哪个方案 | 第 7、11 篇 |
| 实施计划 | 怎么落地 | 第 5、6 篇 |

三个维度组合起来，任何一个系统工程活动都可以记为三维坐标中的一个点 $(t, l, k)$：处于哪个阶段 $t$、进行哪一步逻辑 $l$、调用哪类知识 $k$。**霍尔三维结构的价值在于「定位」**：它不替你解决问题，而是让你永远知道「自己正处在问题的哪个位置、接下来该做什么动作」——这直接解决了大型项目里「各干各的、互相不知道进度」的混乱。

用一个例子看定位怎么用。设某城市轨道交通项目：当前处于**研制**阶段（$t=3$），正在做线路方案的**系统分析**（$l=4$，比较几条候选线路的客流与造价），需要调用**交通工程、城市规划、经济学**知识（$k$）。有了坐标，项目管理者就能清楚回答「我们在哪、下一步是什么」——下一步是**系统优化**与**系统决策**：选定一条线路，进入详细设计。这个坐标架让本来「说不清的项目状态」变成一句话就能交代清楚的事。

## 2 硬系统方法与软系统方法：两种问题观

霍尔三维结构默认了一个前提：**问题可以明确定义，目标可以清楚给出**。这种「目标明确型」问题适合**硬系统方法（hard systems thinking）**：把问题当成「在一个已知系统里优化目标」。运筹学、系统工程、控制论都属于硬系统传统，本专题第 3–11 篇讲的都是硬系统方法。

但现实中大量问题恰恰相反：**目标本身都说不清**——「怎么提升城市交通」「怎么改善医患关系」——不同的利益相关者对「问题是什么」就有分歧。英国系统科学家彼得·切克兰德（Peter Checkland）在 20 世纪 70 年代把这些称为**软系统问题（soft problems）**，并发展出与之配套的**软系统方法论（Soft Systems Methodology, SSM）**。

硬系统方法与软系统方法的差别可作一表：

| 维度 | 硬系统方法 | 软系统方法（SSM） |
| --- | --- | --- |
| 问题假设 | 问题明确定义、目标清楚 | 目标本身存在分歧 |
| 处理对象 | 优化一个「已知系统」 | 澄清「什么才算问题」 |
| 主导者 | 系统分析者 / 运筹专家 | 利益相关者共同参与 |
| 典型工具 | 霍尔三维结构、运筹学、优化 | 根定义、概念模型、结构化辩论 |
| 典型产出 | 最优方案 | 被各方认同的行动计划 |

**辨析｜易错点：** 不要以为软系统方法「更先进」。两者适用的问题不同：要设计一台机器、一个信息系统，硬系统方法足够；要改变一个组织、一群人的行为方式，硬系统方法常常失灵，才轮到软系统方法登场。工程上往往是**先用软系统方法澄清目标，再用硬系统方法实现目标**——本专题后面各篇讲的都是硬系统方法，它们都默认「目标已经由前面的澄清阶段确定」。

## 3 软系统方法论（SSM）：让「说不清的问题」可操作

切克兰德 1981 年出版《系统思考、系统实践》（Systems Thinking, Systems Practice），把软系统方法论总结为七个步骤：

1. **感知问题情境**：研究者进入现场，了解「现状是什么样」，不做价值判断。
2. **表达问题情境**：用富图（rich picture）等工具把问题的结构、关系、冲突画出来。
3. **建立根定义（root definition）**：对「系统是什么、为谁、做什么」给出临时定义，用 **CATWOE** 检查完备性。
4. **建立概念模型**：从根定义出发，构建「应该怎么做」的逻辑模型。
5. **模型与现实比较**：把概念模型与现实情境对照，找出差距。
6. **商定可行的变革**：与利益相关者讨论哪些差距值得改、哪些可行。
7. **采取行动改进问题情境**：实施变革，再回到第 1 步——SSM 本身是一个不断迭代的学习环。

其中第 3 步的 **CATWOE** 是 SSM 最著名的检查清单，六个字母各对应一类必须想清楚的问题：

| 字母 | 英文 | 要回答的问题 |
| --- | --- | --- |
| C | Customer | 系统的受益者 / 受害者是谁 |
| A | Actor | 系统内谁在行动、谁在干活 |
| T | Transformation | 系统把什么转换为什么 |
| W | Weltanschauung | 支撑这个系统的世界观是什么 |
| O | Owner | 系统的所有者 / 决策者是谁 |
| E | Environment | 环境的约束有哪些 |

以「急诊科改进」为例走一遍：C 是患者与家属，A 是急诊医生、护士与分诊员，T 是「把分诊不清的患者转换为有序救治的流程」，W 是「危急优先」的价值观，O 是医院管理层，E 是医保政策、床位与设备约束。六项列清楚，「急诊科要改造成什么样」就从口号变成了一张可讨论的图纸。

SSM 最有价值的思想是**「问题本身也是要澄清的」**：它把「定义问题」从一句口号变成一套有步骤、可参与、可迭代的流程。CATWOE 里的 C（客户）与 A（行动者）——系统服务谁、谁在其中工作——正是下一篇《需求分析与利益相关者分析》的前奏。

## 4 核心对比表：霍尔三维结构、硬系统与软系统

方法论的选择，最终取决于问题类型。本主题是方法论型主题，用核心对比表替代公式解析：

| 维度 | 霍尔三维结构（硬） | 硬系统工程流程（硬） | 软系统方法论（软） |
| --- | --- | --- | --- |
| 问题前提 | 目标明确 | 目标明确 | 目标待澄清 |
| 思维动作 | 时间×逻辑×知识三坐标定位 | 需求→设计→验证（本专题主线） | 根定义→概念模型→辩论 |
| 代表人物 | 霍尔（A. D. Hall） | INCOSE / Blanchard | 切克兰德（Checkland） |
| 最适配场景 | 大型工程研制 | 有明确技术指标的系统 | 组织、管理、社会问题 |
| 与本专题的关系 | 方法论总纲 | 本专题第 3–11 篇 | 需求澄清的思想源头 |

**重点：方法论不是单选题。** 一个大型项目通常先要用软系统方法澄清「到底要解决什么问题」，再用硬系统方法把它实现出来——霍尔三维结构给硬系统活动提供坐标架，SSM 给「问题定义」提供流程。理解了这张对照，再读下一篇的需求分析，你会看见 CATWOE 里的 C 和 A，与利益相关者分析其实是同一件事的两副面孔。

## 5 小结

- **霍尔三维结构**用时间维（六阶段）、逻辑维（七步）、知识维三个正交维度给系统工程活动定位，任一活动可记为坐标 $(t, l, k)$。
- 逻辑维的七步（明确问题、目标设计、系统综合、系统分析、系统优化、系统决策、实施计划）在时间维的**每个阶段都要完整走一遍**。
- 方法按问题性质分**硬系统方法**（目标明确，优化已知系统）与**软系统方法**（目标分歧，澄清问题本身）。
- **软系统方法论（SSM）**用七步流程 + **CATWOE** 检查清单，把「说不清的问题」变成可操作的学习过程。
- 工程实践常是「软方法澄清目标、硬方法实现目标」的先后配合。

在下一节，我们将进入硬系统方法流程的第一步——**明确问题**：系统为谁服务、服务到什么程度、凭什么判断达标——这就是**需求分析与利益相关者分析**。
