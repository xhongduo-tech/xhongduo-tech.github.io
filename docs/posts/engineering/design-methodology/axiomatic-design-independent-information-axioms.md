# 设计公理（Axiomatic Design：独立公理与信息公理）

## 为什么从设计公理开始

前面各篇的方法各管一段：QFD 管需求、形态学矩阵管方案生成、决策矩阵管评价、田口管稳健。南·苏（Nam P. Suh，麻省理工学院教授，曾任美国国家科学基金会主任）想得更远：**能不能像欧几里得给几何立公理那样，给「好设计」立几条不证自明的公理？** 1980 年代末他在《The Principles of Design》中提出公理化设计（Axiomatic Design）：所有好设计都服从两条公理——**独立公理**与**信息公理**。<span class="marginnote">公理化设计与德国系统化设计（Pahl &amp; Beitz）是当代设计方法学的两大流派：前者主张「设计有无可争辩的判据」，后者主张「设计有可组织的过程」。本专题把两者都纳入，正是因为它们互补——过程给出路径，公理给出终点判定。</span>

在课程体系里，这一节与第四篇的决策矩阵共用「判据化」的思维，但更激进：公理不靠专家打分，而靠**结构上的数学判定**。它把设计从「凭经验」推向「可证明」，是本专题最接近第二级《离散数学》与《抽象代数》结构思维的一篇。

本篇的结构：**先立四域与设计矩阵（语言）→ 再用独立公理判结构（第一判据）→ 再用信息公理选最优（第二判据）→ 最后论价值与边界**。

## 1 四个域与设计矩阵

公理化设计把设计看成**域（domain）之间的映射**。四个域依次是：

1. **用户域（customer domain）**：用户要的属性（CA）。
2. **功能域（functional domain）**：满足用户属性所需的功能需求 **FR**（functional requirements）。
3. **物理域（physical domain）**：实现 FR 的设计参数 **DP**（design parameters）。
4. **过程域（process domain）**：制造 FR→DP 所需的过程变量 **PV**。

设计的核心一步是：**用设计参数 DP 实现功能需求 FR**，数学上写成设计方程：

$$\{FR\} = [A]\{DP\}, \qquad A_{ij} = \frac{\partial FR_i}{\partial DP_j}$$

**设计矩阵（design matrix）** $[A]$ 的元素 $A_{ij}$ 表示第 $j$ 个设计参数对第 $i$ 个功能需求的影响强度。矩阵的形状直接决定设计的优劣——这正是下面要拆解的核心。<span class="marginnote">四域映射是公理化设计最广为人知的骨架：从用户属性一路映射到过程变量，每一层都是一次「域跳变」。它提示设计者：只改物理域不动功能域，等于在错误的楼层上装修——这也是为什么「返工要回到功能域重想」。</span>

## 2 公式解析：独立公理与设计矩阵的形状

**独立公理（Independence Axiom）**：功能需求必须保持独立——**调节一个 DP 只能影响它对应的那个 FR，不能连累其他 FR**。它把设计矩阵判成三类：

- **非耦合（uncoupled）**：$[A]$ 为对角矩阵，每个 FR 只被一个 DP 控制。最优。
- **可解耦（decoupled）**：$[A]$ 为三角矩阵，按特定顺序调节 DP 仍能逐一满足 FR。可行。
- **耦合（coupled）**：$[A]$ 为满阵，调一个 DP 会同时扰动多个 FR。不可接受，必须重组。

举一个 2×2 的算例。设某产品有两个功能需求：$FR_1$ = 保持杯中液体温度，$FR_2$ = 便于握持。设计参数 $DP_1$ = 杯壁材料导热系数，$DP_2$ = 杯体外径。若矩阵为

$$\{FR\} = \begin{bmatrix} 9 & 0 \\ 0 & 5 \end{bmatrix}\{DP\}$$

这是对角阵——非耦合设计：改导热只影响保温，改外径只影响握持，各自独立，最理想。若矩阵出现交叉项（如改外径同时明显影响保温），就成耦合设计，设计者必须引入新参数重组，或者接受「牵一发而动全身」的脆弱。<span class="marginnote">独立公理直指本质：耦合设计的脆弱性在于「一个旋钮调不准两个目标」——这正是 TRIZ 的技术矛盾在结构上的镜像。TRIZ 用「分离」解矛盾，公理化设计用「让矩阵变对角」解耦合，两条路殊途同归。</span>

判断矩阵类型的实操方法：**敏感性试验**——把每个 DP 单独扰动 ±10%，观察每个 FR 的响应。若 FR1 只对 DP1 有响应，矩阵就是对角；若 FR1 对 DP1、DP2 都有响应，就有交叉耦合项。这个试验在仿真阶段做一遍，比事后在样机上发现耦合便宜得多。

独立公理还有一层「测量论」的解读：非耦合设计的每个 FR 都能被单独调准、单独验证——这直接降低了调试与验收的成本。反过来，耦合设计往往需要「调 A 看 B、调 B 看 A」的反复试探，试错次数呈指数增长。这正是公理化设计在生产性上的意义：它不是洁癖式的追求，而是用结构换效率。

**辨析｜易错点：** 可解耦（三角）设计并非不行，但调节有严格顺序：先调对角线上靠近第一个的 DP，再依次调后面的。工程上许多阀门、换热器都靠「顺序调节」勉强解耦——公理化设计建议不要止步于此，能重组到对角就重组。另一个易错点是「FR 的定义方式影响矩阵」：同一套物理结构，换一种 FR 划分，矩阵可能从耦合变对角——所以「FR 怎么划」本身也是设计决策。

## 3 公式解析：信息公理与最少信息量

**信息公理（Information Axiom）**：在所有满足独立公理的设计中，**信息量最小者最优**。信息量的定义借用了香农信息论：

$$I_i = \log_2 \frac{1}{p_i}, \qquad I_{total} = \sum_i I_i = -\sum_i \log_2 p_i$$

- **$p_i$**：第 $i$ 个 FR 被成功满足的概率——由设计参数的「系统范围（system range）」与需求的「设计范围（design range）」的重叠度决定。
- **$I_i$**：以比特计的信息量。$p_i$ 越大（达成概率越高）信息量越小；$p_i = 1$ 时 $I_i = 0$，设计零信息——确定成功。<span class="marginnote">直觉：香农说「越不确定的消息信息量越大」；公理化设计反着用——「越不确定能实现的功能，设计需要的信息越多」。信息公理把「复杂设计」定量为「大量信息的叠加」，让「简单即好」有了数学表达式。</span>

算例：某 FR 的设计范围是「直径 20.00 ± 0.05 mm」，而所选制造工艺的系统范围是「20.00 ± 0.15 mm」。两者重叠部分占系统范围的比例即达成概率 $p$——若重叠约占 1/3，则 $I = \log_2 3 \approx 1.58$ 比特。候选工艺系统范围越窄、越贴合设计范围，$p$ 越接近 1，信息量越小，按信息公理越优。**这正是第九篇容差设计的另一种表述：收紧工艺能力就是降低信息量。**<span class="marginnote">信息公理给「选工艺」提供了一个跨领域的标尺：候选工艺 A 的信息量 1.6 比特、B 是 0.4 比特，B 更优——不靠专家感觉，靠可计算的重叠度。Dieter &amp; Schmidt 第7章正是把这个逻辑用于概念与工艺的联合选择。</span>

## 4 公理化设计的两条公理如何配合使用

两条公理不是并列的两张纸，而是**两轮筛子**：先用独立公理把「耦合设计」全部淘汰（结构不健康，再优化也没用），再在剩下的「非耦合/可解耦」候选里用信息公理挑「信息最少」的。顺序不能颠倒——一个耦合设计的「信息量」再小也没有意义，因为它的每个 FR 都牵一发动全身。

这个「先判结构、再比信息」的两轮流程，正好对应工程实践里的两问：**「这方案能不能独立地调准每个目标？」→「在能独立调准的方案里，哪个最容易实现？」** 前者管健康，后者管成本——两条公理各管一问。

## 5 公理化设计的价值与局限（辨析）

价值是清晰的：

- **给「好设计」以可判定的结构判据**：设计矩阵是否对角、信息量是否最小，客观可查，不靠打分。
- **与流程方法互补**：概念设计（第三、四篇）生成方案，公理在方案之间做结构级筛选；独立公理还能预警「这个组合注定耦合，趁早放弃」。
- **跨域一致**：同一套域映射可用于产品设计、工艺设计、软件设计——Dieter &amp; Schmidt 第7章把它列为概念选择的结构化工具之一。

局限也真实存在：

- **FR 的选取本身是主观的**：公理不告诉你怎么定 FR，只在你定好之后判定好坏——「前提的功夫」没省掉。
- **信息公理的可操作性**：$p_i$ 的测定需要概率数据，实践中常常只能估算；学界对「信息量」定义的推广至今有争论。
- **两公理的次序依赖 FR 的定义**：FR 划得不同，同一套结构可能从耦合变非耦合——公理不保护「选错 FR 划分」的错误，这使它更像「尺子」而非「老师」。

把这些局限与价值合起来，公理化设计的最佳定位是：**概念方案生成之后、决策矩阵打分之前的一道结构体检**——它不负责灵感，只负责把「注定耦合、注定高信息量」的方案提前淘汰。
- **它不直接生成方案**：公理是「过滤器」，不是「发生器」——生成仍靠 TRIZ、形态学矩阵这些发散工具。

所以工程的正解是**混合使用**：用系统化方法生成方案，用公理化结构判据淘汰耦合与高信息量方案，再用决策矩阵做最后的综合评分。

这套「生成—筛结构—比信息—打分」的组合，也是本专题所有概念级工具的统一用法：第四篇的形态学矩阵负责生成，公理化设计负责结构体检，决策矩阵负责综合评分。工具之间不是竞争，而是接力。<span class="marginnote">这正是本专题的组织逻辑：过程方法（德国学派）负责「怎么走到方案」，公理与矩阵（美国学派）负责「怎么判断方案」——两条线索汇合于概念设计。下一篇 DFMA 将把「制造」这个域也纳入评判。</span>

## 6 案例：把耦合设计改成对角化

用一个真实感的小案例把两条公理走通。设想设计一套**可调夹具**，两个功能需求：$FR_1$ = 夹紧力可调，$FR_2$ = 钳口开度可调。两个设计参数：$DP_1$ = 螺旋夹紧机构，$DP_2$ = 钳口间距丝杠。

若两个机构共享同一根驱动轴，那么转动驱动轴会同时改变夹紧力与开度——设计矩阵出现交叉项，耦合设计：调开度会顺带松紧夹紧，操作者要反复来回调。公理化设计给出的出路是：把驱动解耦——夹紧用一个独立手柄，开度用另一个独立丝杠，两个 DP 各管一个 FR，矩阵变成对角阵，非耦合设计：夹紧归夹紧，开度归开度，独立可调。

这个案例揭示了公理化设计与直觉设计的差别：直觉会顺手「共用一个轴」图省事，公理却要求「各自的 FR 必须独立」。信息公理再补一刀——非耦合方案里，每个 FR 的实现信息量更小（不必再训练操作者练「来回微调」的手感），因此按信息公理也更优。**两条公理都指向同一个非耦合方案，设计者就有了不靠争论的拍板依据。**<span class="marginnote">这个「解耦」动作与 TRIZ 的「分离」、田口的「稳健化」在精神上高度一致：都是把「一个旋钮调不准两个目标」的病治好。设计方法学的各个流派，最终在「减少耦合、增加稳健」这一点上殊途同归——这正是本专题反复出现的总主题。</span>

公理化设计还有一个常被忽略的教学价值：它把「设计判断」第一次变成了可以用矩阵检查的作业——这正适合用来复盘别人的设计、也用来自查自己的概念方案。养成「画一画设计矩阵」的习惯，是接近公理化设计性价比最高的动作。

**动手练习**：选一个你在做的小设计，写下它的 FR 与 DP，画出设计矩阵，判断耦合类型；再试着重组 DP 让矩阵更接近对角。这个「画矩阵」的动作本身就是最好的检验——画不出来，往往意味着概念还没想清。

最后点题：公理化设计之所以称「公理」，是因为它把「好设计」从「见仁见智」推向「可以判定」——这本身就是设计方法学最大的贡献方向。

## 7 小结

- **四域映射**：CA → FR → DP → PV；核心设计方程 $\{FR\}=[A]\{DP\}$。
- **独立公理**：FR 必须相互独立；设计矩阵对角（非耦合）最优，三角（可解耦）可行，满阵（耦合）须重组。
- 判断矩阵用**敏感性试验**：逐 DP 扰动看 FR 响应；FR 的划分方式本身也会改变矩阵形状。
- **信息公理**：满足独立公理者，信息量 $I_i = \log_2(1/p_i)$ 最小者最优；工艺范围贴合设计范围即降低信息量。
- 两条公理是「先判结构、再比信息」的两轮筛子，顺序不能颠倒。
- 公理是**结构判据**，不生成方案，须与 TRIZ、形态学矩阵、决策矩阵配合使用。

在下一节，我们将把「制造与装配」从设计的后道工序提前到评判标准——如何在图纸阶段就让产品好造、好装，这就是**面向制造与装配的设计（DFMA、公差叠加分析）**。
