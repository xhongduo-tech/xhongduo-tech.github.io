## 为什么从功能结构开始

上一节我们用 QFD 与规格书把「需求」钉成了可测量的数字。但需求再清楚，也还不是方案——它还停在「要什么」，没有回答「怎么实现」。Pahl &amp; Beitz 第6章（概念设计）给出的路径是：**先把要什么抽象成功能，再把功能分解到可以逐个求解的粒度，最后为每个功能子块找一个物理原理解**。这一步是设计从「问题」跨向「解答」的分水岭，也是本专题最见方法论功夫的一节。<span class="marginnote">功能抽象的价值在于「延迟承诺」：先不决定用齿轮还是用摩擦轮来「传递扭矩」，把选择空间留着——功能分解越干净，后面的方案空间越完整。</span>

在课程体系里，功能分解与软件工程自顶向下的**模块分解**是同一个思想：把一个系统拆成高内聚、低耦合的子块，每块只对接口负责。理解了功能树，也就理解了第六篇模块化的种子。

功能结构分解的完整链条是：**总功能 →（分解）→ 功能结构 →（逐块）→ 物理原理解 →（组合）→ 整体原理解（概念）**。本篇按这条链的顺序展开。

## 1 功能：用动词描述「做什么」

**功能（function）**：系统对输入所做的、与实现无关的变换。规范的功能描述 = **动词 + 宾语**，例如「分离杂质」「储存能量」「调节流量」。Pahl &amp; Beitz 强调功能描述必须**实现无关（implementation-free）**——不能说「用离心机分离杂质」，只能说「分离杂质」。

设计对象仍是第一篇的技术系统，功能视角下它被看成**黑箱（black box）**：只关心输入、输出的能量/物料/信号流及其变换关系，不关心内部结构。<span class="marginnote">例如洗衣机是一个黑箱：输入电能、水、脏衣物，输出动能、热能、洗净的衣物与污水。黑箱把「要什么」与「怎么做」彻底切开，这是概念设计的第一招。</span>

功能还被分为两类：

- **总功能（overall function）**：系统整体对外实现的变换，是黑箱的「标题」。
- **分功能（subfunction）**：总功能分解出的子变换，它们按能量/物料/信号的流动次序组合成**功能结构（function structure）**。

规范的功能描述要经得起三问：主语对吗（谁的功）？宾语具体吗（对什么做）？实现无关吗（没偷带方案）？「把水加热到 80 ℃」合格；「用加热管把水加热」就带上了方案，不合格。

这第三问最容易被违反，也最值得练。例如需求是「保持咖啡温热」，正确功能是「维持温度」而非「安装保温套」——保温套只是实现之一，还有真空隔热、相变蓄热、电加热等候选。「功能不带方案」这一条，直接决定了第三篇「原理选择」时你能看到多大的方案空间：功能描述偷带了一个方案，就悄悄把其他原理挡在门外了。

## 2 功能结构：把总功能拆成可求解的分功能

**功能结构（function structure）** 是分功能及其相互连接关系的图。建立步骤：

1. 写出黑箱与三流，确立总功能；
2. 追问「要实现这个变换，必须依次做哪些子变换」，逐层分解；
3. 用箭头把分功能按三流的流向连接，形成一张功能树或功能流程图。

以**家用洗衣机**为例（简化）：总功能 = 「洗净衣物」。分功能包括：提供动力（电能→机械能）、带动衣物旋转、注入与排出水、溶解并投送洗涤剂、加热水温、监测水位与时长、保证安全断电。其中「带动衣物旋转」又可再分为「产生回转运动」与「传递扭矩」两级。<span class="marginnote">分解的停止判据：当每个分功能都小到「能为它找到至少一个现成物理效应」时，就可以停手了。继续拆只会增加组合复杂度，不见得增加方案多样性。</span>

分解得越细，原理选择的自由度越大，但组合爆炸也越凶——所以 Pahl &amp; Beitz 建议分功能数量以能清晰组织为准，不要无谓求细。

再举一个自动化的例子体会功能分解的层次：一台**食品灌装线**。总功能「把液体定量装入容器」。分功能包括：供瓶（物料流）、计量液体（物料流 + 信号流）、输送与定位、封口、贴标、剔除次品（信号流 + 控制）。其中「计量液体」又可分「感知液位」与「控制流量」两级——到「感知液位」这个粒度，就可以查效应目录选「浮球 / 电容 / 称重 / 光电」了。功能分解的粒度感，正是在「还能不能再为它找一个效应」的反复追问中练出来的。

功能结构还有一个容易被忽视的收益——**它是沟通的语言**。机械工程师、电气工程师、软件工程师看同一张功能结构图，能快速对齐「这块谁负责、那块由什么机制实现」；功能结构因此也是跨学科团队评审的共同坐标。Ulrich &amp; Eppinger 第7章把功能图称作「团队的共享地图」，理由正在于此。Ulrich &amp; Eppinger 第7章把这个过程称为**功能图（function diagram）**，并建议先画「骨干流」（主能量/物料路径），再补辅助功能（控制、传感、支撑），最后才检查有没有遗漏的边界功能（安全、维护、防误操作）。

## 3 物理原理解：从分功能到效应与载体

**物理原理解（working principle）** 是 Pahl &amp; Beitz 体系的核心概念：它为某个分功能指定「用哪个物理效应、配什么几何形状与材料特征」来实现。一个原理解 = 物理效应 + 几何结构 + 材料选择。<span class="marginnote">例如「分离固体颗粒」这个分功能，物理效应可以是重力沉降、离心、过滤、静电吸附——不同的效应，对应完全不同的原理解，也对应完全不同的后续构形。</span>

Pahl &amp; Beitz 第6章提供了**效应目录（catalogue of effects）**：把力学、电磁学、热学、流体力学的已知物理效应按「输入—输出」索引排成表。工程师查目录，就像查字典一样为分功能找候选原理。这是「有据可查的发明」——不靠灵感，靠检索。

效应目录的收录遵循三个原则：

- **按输入输出类型索引**：想「电 → 机械运动」就查电机的各种效应（电磁、压电、静电、形状记忆），想「压力 → 位移」就查弹性/液压效应。
- **每种效应标注关键特征**：效率、可逆性、响应速度、力/位移量级、对环境的敏感性——这些正是下一次方案评价的判据素材。
- **允许跨学科组合**：热、电、磁、流体、光学可以串联，这给「创新」提供了系统化的原料库。<span class="marginnote">效应目录与 TRIZ 的 40 条原理（第五篇）互补：目录提供「有哪些物理效应可用」，TRIZ 提供「在什么矛盾下该换哪种效应」——两者都让「创新」从玄学变成可查表。</span>

## 4 从分功能到原理解组合（核心对比表）

把每个分功能的候选原理都列出来，整体方案就是「每个分功能各取一个原理」的组合。下表对照常见分功能与其可选物理效应：

| 分功能 | 候选物理效应/原理解 | 关键判据 |
| --- | --- | --- |
| 传递扭矩 | 齿轮啮合 / 摩擦轮 / 皮带 / 链条 / 液压 | 效率、转速比、噪音、寿命 |
| 分离固体颗粒 | 重力沉降 / 离心 / 过滤 / 静电吸附 | 粒度范围、流量、能耗 |
| 抑制振动 | 橡胶隔振 / 弹簧阻尼 / 主动控制 / 质量调谐 | 频带、可靠性、成本 |
| 检测位移 | 电阻应变 / 电容 / 电感 / 光电编码 | 分辨率、环境鲁棒性 |
| 提供直线运动 | 螺旋机构 / 曲柄滑块 / 液压缸 / 直线电机 | 行程、力、速度、定位精度 |

关键判据这一列就是下一次选择（决策矩阵）的雏形。Pahl &amp; Beitz 强调：**原理选择决定了产品性能上限的七八成**——同一个需求，用离心分离还是静电分离，是数量级的差异，构形阶段的优化只能在这个选择之内微调。<span class="marginnote">这也解释了为什么「概念错了，后面全白做」：原理级错误无法靠详细设计补救。所以本专题把原理求解放在这么靠前的位置。</span>

组合原理解时还要过一道**兼容性检查**：不同分功能的原理之间可能有物理冲突（离心分离要求高速旋转，但重力进料要求低速）或几何冲突（两个机构抢同一空间）。这道检查在下一篇的形态学矩阵里以「列内兼容性」的形式再次出现——原理组合不是自由搭配，而是受系统约束的装配。

## 5 从原理解到概念草图：把方案显式化

物理原理解选定后，下一步是把它画成**概念草图（concept sketch）**：用简图画出各分功能原理如何衔接、三流如何贯通、总体布局大致如何。Ulrich &amp; Eppinger 第7章特别强调「画出来」的价值：

- 草图强制你**面对接口**：两个原理在草图上接不上，说明方案有隐藏缺陷。
- 草图是**沟通媒介**：概念阶段的团队讨论、客户确认、评审都以草图为对象，比文字高效得多。
- 草图是**评审记录**：一张草图的演进史，就是概念设计的决策史。

概念草图不需要精确到尺寸，但必须能回答「它是个什么样的机器」——这是原理解从抽象走向具体的第一站。

草图之后还有一层「轻验证」：对概念草图做粗略的可行性估算——体积量级对不对、所需的功率量级有没有现成电机、关键的受力路径通不通。这层验证不需要精确计算（那是第七篇优化与仿真的事），只需要把「原理上荒谬」的方案尽早判死刑，避免它一路溜进详细设计。Ulrich &amp; Eppinger 第7章把这称作「用 10% 的力气排除 50% 的错误」，性价比极高。<span class="marginnote">这一节与第六级《机械制图》《机械设计》衔接的节点就在这里：概念草图是它们的前置，CAD 造型是它们的主力。概念阶段画得越清楚，构形阶段返工越少。</span>

## 6 功能结构校验：完整性检查与通用功能

功能结构画完不等于合格，Pahl &amp; Beitz 与 Ulrich &amp; Eppinger 都强调要做**完整性检查**——逐条核对：

- **三流齐全吗？** 能量、物料、信号每条流都要有「输入→变换→输出」的完整路径，断了任何一条流，系统就不能工作。例如一台设备若漏了「信号流」分支，就是「能转但不会停」的半成品。
- **需求清单逐条对得上吗？** 每一条硬性需求都要能追溯到至少一个分功能在承担它；对不上的要么是漏了功能，要么是这条需求其实是冗余的。
- **边界功能覆盖了吗？** 安全联锁、防误操作、维护口、散热——这些「看不见的功能」最容易被功能树漏掉，而它们在第八篇 FMEA 里恰好是最贵的失效源。

功能结构还有一个被低估的用途——**识别通用功能**。不同产品之间，「传递扭矩」「储存能量」「分离杂质」这类分功能高度重合，它们的原理解可以跨产品复用。这正是第六篇「模块化与产品平台」的底层依据：功能级的一致，才是模块级共享的真正来源。

最后补一个跨领域的连接：功能结构也是「功能成本分析（Function Analysis System Technique, FAST）」的基础。第五级《工业工程》的价值工程（VA/VE）就用功能树问「这个功能值多少钱、有没有更便宜的实现」——功能结构不只是技术工具，还是成本语言。

功能结构这节的核心可浓缩为一句：**先定「做什么」，再谈「怎么做」**——这个次序看似朴素，却是概念设计一切方法的原点。掌握了它，后续的效应选择、方案组合、决策矩阵都只是在给这个原点装配工具。

**动手练习**：选一件机电产品（如电风扇、自动咖啡机），画它的黑箱与功能结构图，逐功能给候选物理效应，再用「兼容性检查」筛掉冲突组合。这一遍下来，「从功能到原理」就不再是抽象概念，而是你亲手搭过的脚手架。

## 7 小结

- **功能**是实现无关的变换，用「动词+宾语」描述；设计先用黑箱切分「要什么」与「怎么做」。
- **功能结构**把总功能递归分解成分功能，按三流连接；停止判据是每个分功能都能找到候选效应。
- **物理原理解** = 物理效应 + 几何 + 材料；效应目录让原理检索有据可查，并标注关键判据。
- 整体方案 = 每个分功能各取一个原理的组合，还要过**兼容性检查**。
- 原理解用**概念草图**显式化，暴露接口问题、支撑团队评审。
- 原理级决策决定性能上限，必须慎重——这是后续一切优化的天花板。

在下一节，我们将进入「方案生成之后怎么办」——用形态学矩阵把所有原理组合摊开，再用决策矩阵打分收束，这就是**概念设计与方案评价（形态学矩阵、决策矩阵）**。
