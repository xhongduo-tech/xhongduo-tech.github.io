## 为什么从 DDR 存储接口开始

PCIe 讲的是「点对点、串行、CDR 恢复时钟」，而 DDR 存储接口走的几乎是相反的路线：它**保留了并行数据位**，却用一整套源同步与训练的机制躲开了 skew 死刑——这是《从并行到串行》一节留下的悬念，本节来兑现。<span class="marginnote">DDR 接口是并行信号完整性最后的堡垒：数据线多达几十根、共享一根选通时钟、频率却已到 3.2–8 Gb/s（DDR4–DDR5）。它能在并行框架下活到今天，靠的是三件法宝：源同步 DQS、按位训练、复杂的拓扑端接。这三件事正好是前面所有物理层知识的综合应用。</span>

## 1 从 SDR 到 DDR：用双沿换时间

DDR 的起点是一次聪明的信号设计：**DDR = Double Data Rate**，在时钟的上升沿**和**下降沿各采一次数据，用同样的时钟频率把数据传输率翻倍。<span class="marginnote">1998 年前后的 SDR SDRAM 只在上升沿采样；DDR 把下降沿也利用起来，等效数据率翻倍而时钟频率不变——这一招避免了「加频率就撞 skew 墙」的老路。DDR 起还引入了差分的选通时钟 DQS（DQ Strobe），与数据同行同向发送。</span>

关键设计是**源同步（source-synchronous）**：数据 DQ 与选通 DQS 由同一个发送器同时发出，接收端用 DQS 的边沿去采样 DQ。因为 DQS 与 DQ 走相同的路径、受相同的温度电压漂移，它们的相对关系稳定——**时钟不再是全局共享，而是贴着数据走**。这正是并行系统对抗 skew 的正解。

注意 DDR 的 DQS 只对数据组（每 8 或 16 位一组）独立发送，并非全接口共享——**每个数据组有自己的小时钟**，组内同步、组间偏斜由训练补偿。这种「组内源同步 + 组间训练对齐」的层次，是 DDR 能在并行框架下跑高速的架构密码。

## 2 拓扑与端接：多点总线的物理难题

DDR 的数据线是**点到点**（一个控制器对应一个 rank 的一组芯片），但地址/控制线是**多点**（multi-drop）的——同一组地址线要扇到同一 rank 的全部内存颗粒。多点拓扑的反射与串扰远比点对点复杂，于是出现三类拓扑：

| 拓扑 | 结构 | 适用代际 | 端接要点 |
| --- | --- | --- | --- |
| T 型（T-topology） | 从控制器分成两条等长支路 | DDR2 常见 | 两条支路末端各端接 |
| 菊花链（Fly-by） | 信号依次经过每个颗粒 | DDR3/DDR4 主流 | 末端端接，中间颗粒用触须接入 |
| 点到点（Point-to-point） | 数据线一对一只 | 数据线普遍 | 简单匹配端接 |

**辨析｜易错点：** 菊花链中，每个内存颗粒的封装引脚会形成一个容性负载（stub），使信号在每个颗粒处都有轻微反射。地址控制信号「经过」而不「终止」在颗粒上，因此必须在链的**末端**放置端接（ODT 或外部端接电阻）来吸收最终反射——端接放错位置，链越长波形越烂。<span class="marginnote">ODT（On-Die Termination，片内端接）是 DDR2 起的重大工程：把端接电阻做进内存芯片内部，由控制器通过模式寄存器配置阻值（如 40/60/120 Ω）。这消除了大量板级离散电阻，也让端接值可以在运行中切换——写入时用大端接、空闲时用高阻，兼顾信号质量与功耗。</span>

## 3 读写训练：把时序余量「量」出来

DDR 接口没有 CDR，靠的是**训练（training）**——在上电与初始化阶段，控制器与内存颗粒反复发送训练模式，逐个把 DQS 相对 DQ 的延迟、DQ 的驱动强度、ODT 阻值调整到最优。核心是两大训练：

- **写训练（Write Training）**：调整 DQS 相对 DQ 的相位（tDQSS），使 DQS 边沿对准数据窗口中心。
- **读训练（Read Training）**：调整 DQS 与 DQ 的返回对齐，通常配合 **DLL 延迟锁定**（片内 DLL 把 DQS 延迟到与 DQ 对齐）。

**训练的本质是「穷举相位找窗口」**：控制器在一个符号周期内把采样相位从早扫到晚，画出「每一拍能否正确采样」的地图，找到最大的开眼区间，再把采样点钉在窗口正中央。这与《时钟与抖动》里 CDR 锁定、与《编码与均衡》里自适应均衡用的是同一套思想——**用算法去找时序裕量，而不是靠物理保证裕量**。这也是为什么 DDR 每次加频率，训练算法都要跟着升级。

具体到实现，写训练通常分两步：先对齐 DQS 与时钟（tDQSS 校准），再逐个 DQ 位调相位直到读回正确数据；读训练则利用 DQS 与 DQ 的往返延迟（读延迟 RL）做相位扫描。有些控制器还会用「数据眼扫描（data eye scan）」画出每个 DQ 位的 2D 眼图，把电压与相位两个维度的裕量一次看清。

## 4 DDR 代际演进：同一套架构的极限冲刺

DDR 从 1998 年诞生至今，架构骨架（源同步 + 训练 + 拓扑端接）几乎没有变，变的只是把每个皮秒榨得更狠：

| 代际 | 数据率（MT/s） | 片内端接 | 训练手段 | 关键新增 |
| --- | --- | --- | --- | --- |
| DDR2 | 400–800 | ODT 引入 | 简单写/读训练 | ODT、FBGA 封装 |
| DDR3 | 800–2133 | ODT 多档 | 写入均衡（leveling） | Fly-by 拓扑、Write Leveling |
| DDR4 | 1600–3200 | ODT 可编程更细 | 更精细训练 | VREF 校准、伪开漏 |
| DDR5 | 4800–8800 | 更强 ODT | 每颗粒独立训练 | 片内 DFE、双通道独立 |

**规律**：每一代都在「频率翻倍」的同时引入**新的训练/校准手段**去守住余量——DDR3 加 Write Leveling（补偿 DQS 到达不同颗粒的偏斜），DDR4 加 VREF 校准（逐颗粒调参考电平），DDR5 加片内 DFE 与每颗粒训练。这与 PCIe 代际翻倍史（《PCIe 协议栈》）是同一个剧本：**物理提速，算法兜底**。

## 5 公式解析：时序余量怎么算

**DDR 的时序余量是「数据有效窗口」与「采样点位置」之差。** 对读数据，接收端有效的数据窗口由两个时间参数夹出：

$$t_{\text{margin}} = t_{\text{valid-data-window}} - (t_{\text{setup-required}} + t_{\text{hold-required}})$$

- **$t_{\text{valid-data-window}}$**：发送端保证数据稳定的时间窗口，约等于一个 UI 减去数据自身的抖动与偏斜——DDR 规范用 tVAC/tVAD 或 tIS/tIH 描述。
- **$t_{\text{setup-required}} + t_{\text{hold-required}}$**：接收端（内存颗粒或控制器）建立、保持时间的硬需求，由器件工艺决定。
- **余量为正则收**：训练的目标就是把采样点放进窗口正中心，让两侧余量最大。余量一旦为负，数据就会稳定出错——于是有了「眼图 + 裕量扫描」的合规手段。

对 DDR5，数据率已到 4800–8800 MT/s，一个 UI 只有约 200 ps；时钟 jitter、DQ 偏斜、串扰每吃掉 20–30 ps，就是 10%–15% 的余量蒸发。所以 DDR5 进一步引入了更强的片内均衡（DFE）与每位的训练粒度——**信号完整性问题的答案，永远在「把每一皮秒的量测清楚、再用算法守住」这两步里**。

规范里描述这些余量的参数名值得认识：

| 参数 | 含义 |
| --- | --- |
| tDQSS | 写命令到 DQS 的相位 |
| tDS / tDH | 数据建立 / 保持时间 |
| tIS / tIH | 输入建立 / 保持时间（含参考） |
| tVAC / tVAD | 数据有效窗口的交流/直流定义 |
| tDQSQ | DQS 到数据有效之间的延迟 |
| tQH | 数据有效保持窗口 |

训练的目标，就是让这些参数的实际值都落在规范的最小余量之上——**每个参数都是一条「最低水位线」，所有水位线同时满足，DDR 才算稳定**。这也是为什么 DDR 初始化阶段如此漫长：上百个参数要逐个扫出来。

## 6 电源与参考：常被低估的第三战场

DDR 接口还有电源完整性的隐形约束：大量数据线同时翻转时，**同步开关噪声（SSN）**会在电源平面掀起噪声，直接影响 DQ 的电平判读。<span class="marginnote">这就是为什么《电源完整性》一节与 DDR 设计深度绑定：DDR 的片内 VDDQ/VDQ 需要多个去耦电容（bulk + 高频 MLCC）铺在颗粒周围，把 PDN 目标阻抗压到毫欧级。参考电压 VREF（DQ 电平判读的基准）更要单独布线、单独滤波——VREF 的一点点噪声，直接等量吞掉数据余量。</span> 实践中，DDR 设计的失败案例里，因 PDN 与 VREF 噪声导致的比例不亚于走线阻抗不匹配——这提醒我们：信号完整性从来不只是「信号」的事。

一个实用的经验：DDR 数据线上叠加的 SSN 噪声幅度，往往与「同时翻转位数的平方根」近似成正比——翻转的位越多，地弹越大。因此控制器的 DQ 组翻转模式、片内的同步开关电流整形，都成为 DDR5 控制器设计的一部分。

## 7 术语速查表

| 术语 | 含义 |
| --- | --- |
| DQ / DQS | 数据 / 数据选通，DQS 与 DQ 同向源同步 |
| 源同步 | 时钟（选通）由发送端贴数据一起送出 |
| ODT | 片内端接，运行中可配置阻值 |
| Fly-by / T 拓扑 | 地址控制线两种多点分布拓扑 |
| tDQSS | DQS 相对 DQ 的写相位参数 |
| 训练 | 上电阶段穷举相位/强度，把采样点钉进窗口中心 |
| tIS / tIH | 数据输入的建立 / 保持时间参数 |

## 8 小结

- DDR 用**双沿采样**翻倍数据率，用**源同步 DQS** 让时钟贴着数据走，绕开全局 skew。
- 数据线点到点、地址控制线多点：菊花链（Fly-by）需在**末端**端接，**ODT** 把端接做进芯片并可运行中切换。
- **读写训练**用穷举相位画「能采样地图」，把采样点钉在窗口中心——与 CDR、自适应均衡同源。
- 时序余量 $t_{\text{margin}} = t_{\text{valid-window}} - (t_{\text{setup}} + t_{\text{hold}})$，余量为正是 DDR 稳定工作的底线。
- 电源与 VREF 噪声会等量吞噬数据余量，PDN 是 DDR 设计的第三战场。
- DDR5 在 200 ps 级 UI 下把每皮秒都训练到位，是并行信号完整性的巅峰表演。
- 时序参数（tDQSS/tIS/tDS 等）是 DDR 的「最低水位线」，训练目标就是让每条水位线都达标。
- Write Leveling（DDR3）与 VREF 校准（DDR4）证明：算法校准是 DDR 每代提速的关键推动力。
- DDR 按数据组配 DQS 小时钟、组间靠训练对齐，是「组内源同步 + 组间校准」的层次化架构。
