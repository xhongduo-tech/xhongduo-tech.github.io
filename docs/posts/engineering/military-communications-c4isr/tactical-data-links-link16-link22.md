## 为什么从战术数据链开始

前几篇讲的是"点对点把比特传过去"，战术数据链则回答了更高级的问题：**如何让几十上百个作战平台（飞机、舰艇、导弹、指挥所）在一个共享的实时信息空间里自动协作？** 数据链不是一条链路，而是一套"信道 + 消息标准 + 网络管理 + 保密"的完整体系，它让一艘驱逐舰的雷达看到的目标，能在亚秒级内变成千里之外一架战机的火控解算依据。1970 年代美军在越战中吃了"平台各自为战"的亏，催生了 Link 4/Link 11；1980 年代起 Link 16 成为北约与美军联合战术信息的骨干，至今仍是全球最广泛的战术数据链标准。本篇有公式，将解析数据链容量计算。

**数据链与普通通信的本质差别**：普通通信传输的是"语音与文电"，是给人听的；数据链传输的是**格式化消息**，是给机器自动处理、直接驱动武器的。正因为消息格式标准、链路时延可控，数据链才能把"人读、人传、人判"的流程压缩成"机器自动上报、机器自动装定"的闭环——这是杀伤链提速的关键，也是它区别于前四篇所有"传输手段"的根本。

本篇读完后，你将拥有判断一切数据链的框架：**看体制（怎么分时/分频）、看消息（怎么定语义）、看网络（怎么管理时隙）、看保密（怎么加密）**。这套框架同样适用于下一代数据链——只要它们还在用"标准化消息 + 共享信道"的范式，就能用这套眼光去审视。

## 1 Link 16 的信道体制：TDMA 共享

Link 16 工作于 **960–1215 MHz** 频段（与 IFF 敌我识别、TACAN 测距导航共用），采用**跳频扩频（FHSS）+ 时分多址（TDMA）**：所有参与者按统一的时隙表轮流发射，同一时刻网内只允许一个节点占用信道。<span class="marginnote">Link 16 在 960–1215 MHz 内安排 51 个离散频点，发射时隙内按伪随机图案跳变，配合高速跳频实现抗干扰与抗截获，同时把对 IFF/TACAN 的同频干扰降到最低。</span>

时间结构是 Link 16 的骨架，三个关键量：一个**时隙（time slot）**长 7.8125 ms；每 12.8 秒一个**时帧周期（epoch）**；一个周期内有 **1536 个时隙**。这些时隙按 A、B、C 三组交错排列，再通过**网络参与组（NPG，Network Participation Group）**按业务类型划分使用：给定位报告、监视情报、武器协同、语音、网络管理各自分配不同的时隙集合。谁在哪个时隙发言、说什么，都由时隙分配表与网络管理消息决定。<span class="marginnote">时隙分配是 Link 16 网络设计的核心：既要保证每个平台的 PPLI 报告有固定"呼吸位"，又要给高流量业务（如多平台协同交战）按需增配时隙。网络管理在作战前离线完成预分配，战时再由网络管理节点动态调整。</span>

**一个时隙里发生什么？** 7.8125 ms 并不全部用于数据：开头是**同步与精确定时**字段（接收方借此锁定信号与时间基准），中段是**数据段**（携带 J 消息与纠错码），尾部留有**传输保护时间**（guard time，让信号在最大传播延迟内落地，避免相邻时隙串扰）。同步、数据、保护三段的时间配比决定了时隙利用效率——Link 16 大约把相当一部分时隙时间花在同步与保护上，这是 TDMA 体制"确定性优先"的代价。

**评判一条数据链，看四个指标**：**数据率**（每秒能传多少比特）、**时延**（端到端延迟多少毫秒）、**覆盖**（视距还是超视距）、**抗毁性**（抗干扰与抗截获能力）：

| 指标 | 军事要求 |
| --- | --- |
| 数据率 | 火控级协同 ≥ 上百 kbit/s |
| 时延 | 协同交战 < 百毫秒量级 |
| 覆盖 | 视距内必须，超视距加分 |
| 抗毁 | 跳频 + 加密 + 冗余网络 |

<span class="marginnote">这四个指标是评价一切数据链的"体检表"，也是理解后续 Link 16/Link 22 差异的坐标轴：Link 16 在"率、时延、抗毁"占优，Link 22 在"覆盖"占优。</span>

## 2 J 序列消息标准：平台的共同语言

Link 16 传输的消息称为 **J 序列（J-series）消息**，其格式定义在美军的 MIL-STD-6016 与北约的 STANAG 5516 标准中，是全网通用的"语法与词表"。每条 J 消息由若干**词（word）**组成，按功能可分为几个主要类别：

- **J2 精确参与位置与识别（PPLI）**：J2.2 报告平台的身份、位置、航向速度，是全网"我在哪"的基础。
- **J3 监视情报**：J3.0 参考点、J3.2 空中航迹、J3.4 水面航迹，共享雷达/传感器看到的目标。
- **J5 武器协同**：目标分配、交战指示、协同作战消息，把多个平台的火力接成网络。
- **J7 相对导航**：平台间测距测时，实现无 GPS 情况下的相对定位。
- **J6/J10 管理与网络**：平台状态、时隙管理、网络同步管理。

正是因为消息格式被标准化，美军的 E-3 预警机、航母、F-16、岸基指挥所才能"互说一种话"。**消息标准是数据链的灵魂**：信道只是管道，J 消息才是内容与语义，后者的标准化程度决定了互操作的上限。

**J 消息的字结构**：每条 J 消息由若干**词（word）**构成，每个词固定长度并含字标签与数据字段。消息头标定类型与长度，主体由数据字组成，不同的 J 消息类型对应不同的字集合。工程上把 J 消息做成"可扩展词表"：新增一种目标类型，只需在标准里追加一个词，不必改动整个消息体系——这正是 J 系列标准能延续几十年的原因。

**J 消息里还保留自由文本与话音**：数据链并非"只见数据不见人"，它用固定时隙同时承载格式化数据与压缩话音（如 2.4–16 kbit/s 的 CVSD 话音），让"机器协同"与"人工沟通"在同一个网里并行不悖——机长既可以自动接收航迹，也可以直接喊话联络。

## 3 数据链的发展脉络

### 第一代：Link 4

1950 年代美国海军为舰载机自动着舰与控制研制 Link 4：点对点、时分半双工，用很简单的消息在舰与机之间传递控制指令。它本质上是"一台终端控制一架飞机"的单向数据线。

### 第二代：Link 11

1960–1970 年代，海军需要多平台联网共享雷达态势，Link 11 应运而生：工作于 HF/UHF，采用**轮询（roll-call）**协议——网络控制站按名单依次点名，被点到的平台上报数据，像"击鼓传花"一样让各舰共享同一张海图。Link 11 的 M 系列消息与 HF 天波超视距能力使其沿用数十年，但轮询效率低、一个节点掉线全网停顿。

### 第三代与第四代：Link 16、Link 22

1970 年代末美国海军与北约开始研制 Link 16，目标直指 Link 11 的三大痛点：速率低、易干扰、共享效率差。它改用 **TDMA + 高速跳频**，并首创"以时隙为资源、以 NPG 分工、以 J 消息统一语义"的完整体系——这就是本节的主角。1990 年代北约又启动 Link 22，把 J 消息体系搬到 HF 超视距信道，解决 Link 16 的视距限制。<span class="marginnote">一条脉络读下来就清楚了：Link 4 是"点到点"，Link 11 是"轮询共享"，Link 16 是"TDMA 全联网"，Link 22 是"HF 超视距版 Link 16"。每一代都解决上一代的一个致命短板。</span>理解这条演进线，再看现代战术数据链的各种变体（如用于精确制导武器的武器数据链）就有了坐标系。

## 4 公式解析：一个时隙能装多少比特

时隙是 TDMA 的基本运输单位，容量计算一目了然：

$$
\text{每时隙比特数} = R_b \times T_{slot}
$$

取基础数据率 $R_b = 28.8\ \text{kbit/s}$，时隙长 $T_{slot} = 7.8125\ \text{ms}$：

- **第一步，代入计算**：$28.8 \times 10^3 \times 7.8125 \times 10^{-3} \approx 225$ 比特/时隙。这是单脉冲体制下每个时隙能携带的编码比特数。
- **第二步，考虑编码开销**：这 225 比特里包含同步头、Reed-Solomon 纠错码等开销，实际有效信息比特约 60–70%，所以工程上常说 Link 16 基础信息率约为 8–33 kbit/s（视脉冲体制与打包方式而定）。
- **第三步，算网络总容量**：如果全网 1536 个时隙全用最高打包方式，理论吞吐量可达约 **2 Mbps 量级**——与香农公式给出的上限相比，Link 16 的带宽（约 51 个频点、数百 kHz 量级）下已相当逼近工程极限，剩余余量都留给了跳频与抗干扰。

**核心直觉：TDMA 用"时间精确排队"换来了抗干扰与共享确定性**——因为同一时刻只有一台发射机，网内不会自相干扰，接收方只需守住自己的时隙表。

从容量公式还能读出一个设计原则：**时隙就是资源**。给某个 NPG 分配 100 个时隙，它就拥有全网约 $100 \times 225 / (12.8 \times 10^3) \approx 1.8$ kbit/s 的平均速率。指挥员在战前分配时隙，本质上就是在分配"信息带宽"——把关键业务（协同交战、PPLI）的时隙优先保证，次要业务排队等候。这与第一级《计数与估算》里"资源总量有限、按优先级分配"的思想一脉相承。

## 5 Link 22：把数据链拉过地平线

Link 16 工作于超高频视距，受地球曲率限制，舰对舰一旦远离视距就断链。**Link 22（STANAG 4522）**正是为此而生：它是北约的**高频/超高频战术数据链**，主要工作于 **3–30 MHz 高频（HF）**频段，借助天波传播实现**超视距（OTH）**互连，把 Link 16 的 J 序列消息体系延伸到了数千公里之外。

Link 22 采用与 Link 16 兼容的消息结构与 TDMA 体制，但针对 HF 信道做了针对性设计：抗衰落交织、慢速跳频（HF 频段的窄带信道上跳频速率低）、自动链路建立选择可用频率。<span class="marginnote">Link 22 的数据率从数百 bps 到约 12.6 kbit/s，比 Link 16 低，但换来的是超视距覆盖与更强的抗截获性——它把战术数据链从"视距内的精确协同"扩展到"大洋上的编队互联"。</span>在实际体系中，Link 16 与 Link 22 通过网关互联：舰队内用 Link 16 高速共享，舰队之间用 Link 22 超视距连接，构成覆盖两层的战术信息网。

用核心对比表看清两者的分工：

| 维度 | Link 16 | Link 22 |
| --- | --- | --- |
| 工作频段 | 960–1215 MHz | HF 3–30 MHz（含 UHF） |
| 传播方式 | 视距 | 天波超视距 |
| 数据率 | 高（全网约 2 Mbps 量级） | 低（数百 bps–12.6 kbit/s） |
| 抗干扰 | 高速跳频 | 慢跳 + 自适应选频 |
| 覆盖 | 视距内 | 上千公里 |
| 标准 | STANAG 5516 / MIL-STD-6016 | STANAG 4522 |

<span class="marginnote">设计哲学的分野：Link 16 追求"短距离高速共享"，Link 22 追求"超视距低速保底"。两者不是替代而是互补——舰队内用 Link 16 高速互联，舰队间用 Link 22 超视距连接，中间用网关桥接，构成两层叠加的战术信息网。</span>

## 6 小结

- Link 16 用 **TDMA + 跳频**共享 960–1215 MHz：12.8 秒时帧、1536 个时隙、每时隙 7.8125 ms。
- 数据链演进：**Link 4（点到点）→ Link 11（轮询）→ Link 16（TDMA）→ Link 22（HF 超视距）**，每一代解决上一代的短板。
- 消息标准是灵魂：**J 序列消息**（MIL-STD-6016 / STANAG 5516）统一了 PPLI、监视、武器协同、导航与网络管理的语义。
- 时隙容量 $R_b \times T_{slot}$ 约 225 bit/时隙，全网吞吐约 2 Mbps 量级，是抗干扰与共享确定性的权衡结果。
- Link 22 用 **HF 天波实现超视距**，与 Link 16 通过网关互联，构成"视距高速 + 超视距兜底"的体系。
- 数据链四维评价：**数据率、时延、覆盖、抗毁**，一切数据链都能用这张"体检表"度量。
