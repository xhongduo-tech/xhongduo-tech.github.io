## 为什么从 GPU 互联开始

上一篇确立了五层架构图，其中最关键的一格是「节点内 vs 节点间」的带宽鸿沟：NVLink 域内 900 GB/s，域外一条 400 Gbps 网卡只有 50 GB/s，相差 18 倍。**GPU 互联网络**就是要解释这 18 倍的鸿沟从哪来、又靠什么结构填平——它把「两层设计」讲透：域内用 NVLink 家族，域外用 InfiniBand 或 RoCE 以太网，两者在物理、协议与用途上完全不同，却又通过 NVIDIA 的 PXN 等机制无缝衔接。<span class="marginnote">Barroso Ch.3 把服务器网络分为 cluster networking 与 host networking 两层，GPU 集群的两层设计正是这一区分的极端化：把「芯片间互连」与「机箱间互连」彻底分工。这也呼应「从极限到大模型」主线——并行粒度必须贴着硬件带宽来划分。</span>

这篇是理解后面一切（拓扑、集合通信、无损以太网）的地基。先记一句话：**域内管「同一个逻辑 GPU 的多卡协作」，域外管「成百上千台机器的大规模并行」**。

顺着上一篇的层次图，这篇是「节点」这一格的完整展开：节点内怎么连（NVLink）、节点间怎么连（NIC + 交换机）。读的时候请抓住一条主线——**每一次「能不能并行」「并行到什么程度」，最终都被互联带宽问住**。这也是为什么在芯片算力早已单卡上天的今天，互联仍然是大模型训练的第一工程约束。

## 1 NVLink 域内：把 8 张卡焊成一个 GPU

**NVLink**：NVIDIA 专有的 GPU 点对点互连协议，专为「把多张 GPU 当作一个更大的 GPU」而设计。它直接连在 GPU 片上，绕过 PCIe 根复合体，因此延迟比 PCIe 低一个量级。<span class="marginnote">第 4 代 NVLink（DGX H100）：每链路双向 450 GB/s，单机 8 卡构成 18 条全互联，任意两卡之间都有直连或一跳路径，总双向带宽 900 GB/s/GPU。到第 5 代（DGX B200）提升到 1.8 TB/s/GPU。</span>

NVLink 家族有三个成员，作用域逐级放大：

- **NVLink**：GPU 到 GPU 直连，用于机箱内互联。
- **NVSwitch**：一个独立的交换芯片，把多张 GPU 组织成无阻塞的交换拓扑。DGX H100 机箱内有 3 个 NVSwitch 平面，任意两卡通信都走最短路径。
- **NVLink-C2C**：芯片到芯片，用于连接 CPU 与 GPU（如 Grace-Hopper），或 GPU 与定制 ASIC。

**域内的关键性质是「一致性」**：NVLink 域内的多卡共享同一块显存视图，`cudaMemcpy` 在域内几乎免费（P2P 访问），所以张量并行（TP）这种「每步都同步、通信量极大」的并行方式必须被锁在域内。域内带宽的数字决定了 TP 的粒度上限——TP 维度设太大，同步开销会吃掉全部算力收益。

**为什么要单独造一套芯片间互连，而不是复用 PCIe**：PCIe 5.0 ×16 单链路 128 GB/s，远低于 NVLink 的 450 GB/s，且 PCIe 要走根复合体、有协议开销。更关键的是，PCIe 是「处理器为中心」的外设总线，而 NVLink 是「对等 GPU 为中心」的并行总线——NVLink 允许 GPU 之间像处理器访问内存一样直接读写对方显存，`cudaMemcpyPeerAsync` 在域内走硬件直通。**「能不能直接读对方显存」是域内与域外的分水岭**。

**NVLink-C2C 把域边界推到 CPU**：在 Grace-Hopper 这种超级芯片里，CPU 与 GPU 通过 NVLink-C2C 连成统一的 512 GB 一致内存池，CPU 可以直接访问 GPU 显存而不用拷贝。它的意义是「域内」的范围不再止于 GPU 之间——当域内能容纳 CPU 侧的数据预处理，数据搬运就几乎从训练循环里消失了。<span class="marginnote">Barroso Ch.3.2 专门讨论了加速器时代的内存体系：CPU 与加速器的内存不再泾渭分明。NVLink-C2C 让「统一内存」从软件抽象变成硬件默认，训练管线里最常被忽视的「CPU↔GPU 拷贝」就发生在这一层。</span>

从拓扑看，DGX H100 的 18 条 NVLink 并不是全两两直连，而是经过 3 个 NVSwitch 平面组成无阻塞交换网：任意两卡之间都有最短路径，多卡同时通信互不干扰。这个「机箱里的胖树」与第四篇要讲的机柜间胖树，是同一套思想的两种尺幅。<span class="marginnote">NVLink 代际演进：Volta 时代 300 GB/s → Ampere 600 GB/s → Hopper 900 GB/s → Blackwell 1.8 TB/s。每代翻倍，靠的是串行速率提升与链路数增加双管齐下；域内带宽每翻一倍，TP 就能多吃一倍模型、或把同步开销减半。</span>

## 2 域外：InfiniBand 与 RoCE 的登场

一旦通信要跨出机箱，NVLink 就鞭长莫及，必须交给网络接口卡（NIC）与交换机构成的**域外网络**。这里有两个技术路线，构成了本专题第二、三篇的主题：

- **InfiniBand**：专门为高性能计算设计的互连协议，从链路、交换到拥塞控制整套自研。DGX SuperPOD 采用 NVIDIA Quantum QM9700 交换机，单端口 400 Gb/s（NDR），延迟低至亚微秒，并内置 SHARP 集合通信卸载。
- **RoCE（RDMA over Converged Ethernet）**：把 RDMA 语义搬到以太网上。RoCEv2 用 IP/UDP 封装，理论上能复用现成的以太网交换机，但必须配合无损网络改造（PFC/ECN）才能跑出 RDMA 的可靠性——这正是第三篇《无损以太网》的全部内容。

**辨析｜易错点：** InfiniBand 与 RoCE 不是「同一种技术的两种实现」，而是「自研协议栈」与「以太网借用协议栈」之争。IB 的原生拥塞控制、自适应路由、SHARP 归约都是为 HPC 从零设计的；RoCE 的卖点是「不用换交换机、网卡便宜」，代价是必须在以太网里人工补上 IB 天生就有的无损与拥塞机制。**选 IB 还是 RoCE，本质是「整套换新」与「存量改造」的成本权衡**，两者在应用层都走 RDMA 语义，所以本专题后面讲集合通信时两者可并行讨论。

从 SuperPOD 的官方参考架构看，NVIDIA 的默认答案是 InfiniBand：机算网、存储网都明确用 Quantum 交换机。RoCE 的主场是「已有大容量以太网、希望渐进式升级到 RDMA」的场景——例如把现有 25G/100G 以太网改造成支持 RoCEv2 的无损以太网。**先记结论：主流万卡集群默认 IB，RoCE 是兼容与成本的备选**，两者的细节差异是第三篇的主战场。

**InfiniBand 的代际数字**值得先记：从 EDR（100 Gb/s）、HDR（200 Gb/s）、NDR（400 Gb/s）到 XDR（2025 年首发的 800 Gb/s），每代翻倍；DGX SuperPOD 现网主流是 NDR 400 Gb/s 的 Quantum QM9700 交换机。InfiniBand 的另一个王牌是**自适应路由（adaptive routing）**与**动态网络自愈（SHIELD）**——链路故障时能动态改路而不打断流量，这对万卡训练至关重要。

还要区分「单端口速率」与「每节点聚合速率」两个概念：DGX H100 每节点配 8 张 400 Gb/s 网卡，聚合入站 3.2 Tb/s（约 400 GB/s）。全集群所有节点同时打满，就是 SuperPOD 机算网要满足的峰值——这个「8 × 400 Gb/s」的每节点聚合速率，正是第四篇轨式拓扑里每条「轨」的带宽来源。

**为什么域外必须 RDMA，不能走传统 TCP**：分布式训练每一步迭代都有全局梯度同步，一次 all-reduce 的延迟预算只有几十毫秒。TCP 的慢启动、重传与内核协议栈拷贝，会让梯度同步变成分钟级，训练根本跑不动。<span class="marginnote">一句话总结三层差距：TCP 是「尽力而为 + 重传」，RDMA 是「硬件直通 + 端到端可靠」；同为 400 Gbps，RDMA 的 CPU 占用几乎为零，而 TCP 每 Gbps 要吃掉一个 CPU 核的相当一部分。</span>RDMA 把「数据从网卡直进显存」这条路径打通，CPU 只负责发指令、不负责搬数据。

## 3 两层设计如何协同：NVLink 域 + 网络域的对齐

两套网络不是各管各的，它们的**边界必须对齐**。NVIDIA 的做法是把「第 n 张网卡连到第 n 层交换机」的轨式（rail）结构做得与 NVLink 域一一对应，让域内通信尽量留在 NVLink、域间通信只走最短的轨。为此还有几个关键机制：

- **PXN（PCI × NVLink）**：允许一张 GPU 的数据绕过 CPU，先经 NVLink 到达同机另一张 GPU、再经那张 GPU 的网卡发出——相当于用 NVLink 域「借」网卡带宽，单机 8 张卡可以把 8 张网卡的出口聚合起来。<span class="marginnote">PXN 从 NCCL 2.12 引入，是「两层设计协同」的典型：通信路径（NVLink + PCIe）与数据路径（GPU 直发 NIC）被解耦，既避免了 CPU 互连瓶颈，又能把跨域流量在域内先聚合再发出。见《DGX SuperPOD Reference Architecture》与 NCCL 文档。</span>
- **SHARP 集合通信卸载**：把 all-reduce 的归约计算下沉到交换机内部完成，数据流到中间交换机就被合并，通信量按树深度削减——这在第五篇《集合通信》会展开。
- **非阻塞设计**：域外网络做成全胖树满二分带宽，保证「任意两 GPU 域间通信都能到线速」，不因位置产生热点。

**两层协同的实践准则**是「轨优先」：凡是域间流量，尽量让它沿「源节点第 i 卡 → 第 i 轨 → 目的节点第 i 卡」的最短路径走。之所以强调这一点，是因为 NVLink 域内聚合后发出的流量在交换机上具有极强的相关性与突发性——如果两条大流撞进同一个交换机端口，就会形成微突发拥塞（microburst），这正是第三篇 DCQCN 要解决的难题。所以「两层设计」不只是硬件划分，更是一套**流量编排纪律**。

**怎么验证两层设计到位**：上线后跑一次全集群 all-reduce 带宽测试，看是否接近理论峰值；再跑一次「跨域随机通信」对比——若两者吞吐差异明显，说明域边界没有对齐（很可能就是错插线或非阻塞没做满）。这一「测」一「比」，是运维里最便宜的架构体检，也是第五篇实测方法的预告。

## 5 公式解析：域内外通信量的分界

两层设计的量化依据是「同一数据在不同并行策略下的通信量」。以张量并行下每个 Transformer 层的一次前向为例，需要同步的激活张量大小为：

$$
T = 2 \cdot H \cdot S \cdot B \cdot \frac{p-1}{p} \quad \text{（字节）}
$$

其中 $H$ 是隐藏维，$S$ 是序列长度，$B$ 是微批次大小，$p$ 是 TP 维度，系数 2 来自一次 AllReduce 的发送+接收。<span class="marginnote">这是 Megatron-LM 论文（NVIDIA, 2020）给出的标准 TP 通信量公式，符号约定沿用原文：通信量与隐藏维、序列长度线性相关，但只随 $(p-1)/p$ 缓慢增长——所以 TP 维度不宜太大。</span>分三步解读：

- **第一步，通信量随 $H$、$S$、$B$ 线性增长**：模型越宽、序列越长，每一步要同步的数据就越多，对域内带宽的要求越高。
- **第二步，$(p-1)/p$ 项**：TP 维度从 2 提到 8，通信量只增加约 12.5%，但算力翻 4 倍——这解释了为什么 TP 被锁在 NVLink 域内（8 卡）是「性价比最优」的选择。
- **第三步，与域外对比**：数据并行下每步全量梯度同步，通信量与模型参数量成正比，远超 TP 的 $O(H)$ 量级，所以 DP 需要 1:1 无收敛的域外网络。

把这两类通信量代入「域内带宽 900 GB/s vs 域外 50 GB/s」的差距，就得到工程设计准则：**通信密度高的并行留在域内，通信总量大但频率低的并行放域外**——两条线各守其位。

**套一组真实数字**：以 7B 模型、隐藏维 $H=4096$、序列长 $S=2048$、微批次 $B=1$、TP 维度 $p=8$ 代入，单个 Transformer 层单次前向的 TP 通信量。先看单位换算：$2\cdot4096\cdot2048\cdot1 = 16{,}777{,}216$ 字节，乘 $(p-1)/p = 7/8$ 得约 14.68 MB，按二进制的 MiB 折算约 13.4 MiB。为便于直觉，用十进制近似：

$$
T = 2 \times 4096 \times 2048 \times 1 \times \frac{7}{8} \approx 13.4 \text{ MB}
$$

每层每步同步 13.4 MB，在 NVLink 域内只要约 15 微秒，若同样数据流经 400 Gbps 网卡则约 270 微秒——域内快 18 倍。而一个 7B 模型有约 32 层，每步光 TP 同步就累积约 430 MB，这个量如果被错误地放到域外，训练吞吐会立刻被网络卡死。<span class="marginnote">这组数字也解释了为什么「TP 维度从 8 扩到 16」收益骤减：$(p-1)/p$ 从 7/8 升到 15/16，通信量只增约 7%，却被迫把域内通信扩散到域外——除非用 NVLink-C2C 或 NVLink 域扩展把域边界推大。并行度必须贴着域边界设。</span>

## 6 小结

- GPU 互联是**两层设计**：域内 NVLink 家族（900 GB/s 级、亚微秒、P2P），域外 InfiniBand/RoCE（400 Gb/s、RDMA、需交换机）。
- NVLink 家族三成员：NVLink 直连、NVSwitch 交换、NVLink-C2C 跨芯片；域内性质是「一致共享显存」。
- 域外必须 RDMA：TCP 的内核拷贝与慢启动撑不起每步几十毫秒的梯度同步。
- 两层靠 **PXN**（域内借卡发流量）、**SHARP**（交换机内归约）、**非阻塞拓扑**协同对齐。
- 核心公式是 TP 通信量 $2HSB(p-1)/p$：通信密度高留域内、总量大放域外的准则由此而来。
- 两层设计不只是硬件划分，更是一套**流量编排纪律**：轨优先、防微突发、域边界对齐。

**把这层概念固化成一张心智图**：域内 = 带宽的富矿（900 GB/s），域外 = 规模的战场（2048 GPU 起步）。训练框架（如 Megatron、DeepSpeed）在划分并行策略时，默认就把 TP 绑在域内、DP/PP 绑在域外——这篇学的是「为什么」，后面学调度与容错时会反复用到这个默认。

在下一节，我们将钻进域外网络最微妙的地方：以太网明明会丢包，怎么才能跑出 RDMA 的可靠性——这就是 **无损以太网**。
