## 为什么从机器人编程开始

前面的课给了机器人"身体"（结构）、"头脑"（运动学与动力学）、"手法"（控制与规划），但还差最后一环：**怎么把任务告诉它**。这一课讲机器人编程——从最古老的示教器逐点记录，到离线编程在虚拟世界里排练，再到今天大模型直接"用自然语言写机器人代码"。

它是把整个学科闭环收口的环节：**一条轨迹能否落地，取决于编程方式与标定精度；一个机器人系统能否量产，取决于编程是否高效、可复用**。理解它，你就明白了前面所有运动学、动力学、规划的知识最终是以什么形式进入生产线的。<span class="marginnote">机器人编程位于「从极限到大模型」主线的接缝处：它是工程方法，而现代范式——自然语言生成任务代码、模仿学习动作策略——正是大模型层级技术在机器人上的直接投射，这在本课第 5 节会展开。</span>

## 1 在线示教：手把手教会

最早、也至今最普及的编程方式是**在线示教（teaching）**。工程师用**示教器（teach pendant）** 逐点移动机器人末端：移动到位、记录点位与速度、再移动、再记录……把整个流程录成一条轨迹，机器人再逐步复现。

示教有两种形式：**点动示教**（记录离散点位，机器人按点插补运动）与**拖动示教**（lead-through，直接握住末端"演示"一遍，常见于喷涂、打磨）。

示教的优点深刻而朴素：**它依赖的是重复精度，不依赖绝对精度**。工程师亲眼看着末端到位，真实运动学里的系统误差被"录"进了轨迹本身——这就是为什么示教机几乎永远"能干活"。缺点是：点数多、改一处重录一片、危险环境（焊接、喷漆）人不能近身，且不产生可移植的程序资产。<span class="marginnote">拖动示教（lead-through）在"轨迹型"任务（喷涂、打磨、点胶）里格外有优势：工人的手感直接变成轨迹形状，无需逐点定义。新一代协作机器人把拖动示教做成了默认交互方式——这也让"示教"从工业老手艺变成了消费级操作。</span><span class="marginnote">上一课《机械结构设计》里说过"重复精度远好于绝对精度"——示教编程正是这一现象的工程红利。它不需要标定，因为误差被轨迹"自带"了。</span>

## 2 机器人编程语言：从按钮到代码

示教器之下，是一层**机器人专用编程语言**。早期如 VAL（Unimation）、AML，工业界常见 KUKA 的 KRL、ABB 的 RAPID、发那科的 TP——这些语言围绕"运动指令"设计：

```
MOVE P1 SPEED 50mm/s      ; 直线插补到点位 P1
MOVE P2
Grip CLOSE                 ; 闭合抓手
```

运动指令的核心是"点位 + 运动类型（关节/直线/圆弧插补）+ 速度 + 加减速"——**插补**就是把点位之间按《轨迹规划》课的曲线生成中间点。现代更流行的做法是用**通用语言 + 库**：Python/C++ 调 ROS（Robot Operating System）或厂商 SDK，把机器人的关节、末端、传感器暴露成 API——机器人编程由此从"设备语言"走向"软件开发"。

不论哪种语言，程序都围绕一套**固定的运行时骨架**运行：

**主循环**：机器人控制器以固定周期（通常 1–4ms）扫描程序，逐条执行运动与 I/O 指令；
- **程序流控制**：循环（`WHILE`）、条件（`IF`）、等待（`WAIT`，如等光电传感器）、多任务（后台跑信号监听）——它与通用编程语言的语法几乎同构，只是每条"运动语句"背后拖着一条实时的运动学计算管线；
- **安全逻辑**：急停、门锁、限位回退（home）、碰撞检测后恢复——**机器人程序区别于普通软件的地方，在于它的每条指令都可能造成物理后果**，所以错误处理必须比普通软件保守得多。<span class="marginnote">"安全第一"不是口号而是语法：工业控制器里 `SPEED`、`ACC` 等参数都带强制上限，超出即拒绝执行；`WAIT` 等待超时则触发安全停机。把"程序"与"物理"之间的这层敬畏写进代码，是机器人编程与 Web 开发最大的分野。</span>

## 3 离线编程与数字孪生：先虚拟后现实

**离线编程（offline programming, OLP）**：不用真机器人，而在 CAD + 仿真软件（如 RoboDK、Process Simulate、CoppeliaSim）里搭建虚拟工作站，规划轨迹、检查碰撞、估算节拍，把程序"预演"好了再下载到真机。它解决了示教的所有痛点：不占用产线、改版快、危险场景零风险、程序可版本管理。

OLP 还有一个示教做不到的硬核能力——**节拍预估（cycle time estimation）**。仿真器用第 3 节的运动学、上一课的动力学参数（加速度/速度上限）把整个程序"虚拟跑一遍"，输出精确到毫秒的循环时间。产线设计阶段就能据此算出产能、决定机器人数量与夹具布局，**把"能不能投产"从真机调试提前到电脑前回答**——这是 OLP 在汽车焊装、3C 装配这些重产线行业的立足之本。

OLP 得以成立的**关键前提是标定（calibration）**。虚拟世界用的是理论运动学模型，而真实机器人有装配误差、减速器背隙、连杆变形——两者对不上，离线程序到真机就"偏位"。

**辨析｜易错点：离线编程不标定 = 白搭。** 离线生成的轨迹精度受限于**绝对精度**，而真实机器人的绝对精度通常远差于重复精度。对策是出厂/现场标定（把 $M, C, g$ 之外的那套几何误差——D-H 参数偏差——测出来并补偿进模型），标定后的机器人绝对精度可以逼近重复精度。**没有标定，离线编程只配当动画；标定之后，它才配叫程序。**<span class="marginnote">标定在工程上是一套成熟流程：用外部测量（激光跟踪仪、相机）测末端实际位姿，反推真实 D-H 参数与关节零位偏差，再把这些修正写进控制器的运动学模型。它与上一课"动力学参数辨识"是同一哲学的两次施展：模型不准确，就测出来、补进去。</span>

## 4 公式解析：仿真里的正向运动学

OLP 仿真每时每刻都在做同一件数学工作——算出末端位姿。设机器人的 D-H 变换为 $A_i$（回顾《正向与逆向运动学》的 $T_i^{i-1} = A_i$），末端相对基座的位姿是六个矩阵的连乘：

$$T_6^0 = A_1\,A_2\,A_3\,A_4\,A_5\,A_6$$

三步拆解它在仿真中的角色：

- **第一步，看懂它解决的问题**：仿真器拿到一组关节角 $(q_1, \ldots, q_6)$，连乘六个 $A_i$，得到末端位姿——于是"关节角 → 3D 模型上的末端位置"每一步都能算。
- **第二步，看懂它的反向**：离线程序里用户指定的是末端点位（笛卡尔坐标），仿真器要用**逆运动学**反解出关节角（复习《正向与逆向运动学》的多解与奇异），再逐点验证这些关节角不撞障碍、不越限位。**仿真 = 正解 + 逆解 + 碰撞检测三件套的循环。**
- **第三步，看懂它的时效**：一个 6 轴机器人 1ms 控制周期要算几十次正逆解，而六矩阵连乘 $O(1)$ 次即可完成——这就是《机器人动力学》里 O(n) 牛顿–欧拉递归能在嵌入式上实时运行的同款理由。

## 5 现代编程范式：状态机、ROS 与学习

机器人编程的今天已经远不止"点位 + 指令"：

- **任务级与行为树**：把任务拆成"感知—决策—动作"的树状节点，状态机管理流程，逻辑与运动解耦——现代产线系统几乎都这套。
- **ROS 生态**：以节点/话题/服务为骨架的机器人中间件，让感知、规划、控制以"软件组件"方式组合——它是机器人领域的"操作系统 + 微服务"。

**数字孪生（digital twin）** 是 OLP 的最新形态：把产线上的每一台机器、传感器、PLC 在虚拟世界里建一份"实时镜像"，程序改动、故障模拟、产能预测都在孪生体里先跑一遍。它的核心价值不是"更炫的动画"，而是**让"软件改动"与"物理风险"解耦**——改一条轨迹，先让虚拟机器人背锅，而不是真机。
- **学习与生成式编程**：**模仿学习**让机器人从示范数据中学策略；**大模型**则把自然语言/视觉指令直接翻译成可执行动作代码或任务子目标——"把机器人从洗盘子到换灯泡"这类新范式，本质是把本课前面所有"编程"抽象了一层。<span class="marginnote">大模型机器人编程的代表路线：LLM 接收自然语言任务 → 分解为子任务/生成代码或中间表示（如 PDDL 规划、行为树、运动原语）→ 底层执行器复用经典控制。它是「从极限到大模型」博客大模型层级知识在具身智能上最直接的工程出口。</span>

这几条路线不是替代而是叠加：**底层仍是运动学、动力学、规划与经典控制，上层换成了更聪明的"写程序的人"**。理解本课，你就看到了这条叠加链的最外层。

## 6 插补与点位编程的工程细节

无论示教还是离线，最终落到机器人的都是一串"点位 + 运动指令"，而**插补（interpolation）**是这串指令的执行引擎：

**关节插补（MoveJ）**：各关节直接从当前角运动到目标角，路径是关节空间的直线（对应末端走一条"别扭"但最快的曲线），适合点到点、无碰撞要求的搬运。
- **直线插补（MoveL）**：末端沿笛卡尔直线走，途中逐点求逆解（复习《正向与逆向运动学》的逆解 + 奇异处理），适合需要精确直线路径的场景——但路径中途若经过奇异位形，关节速度会爆炸，控制器必须提前报警或绕行。
- **圆弧插补（MoveC）**：用三点定义一段圆弧，末端沿弧走，常用于焊接、涂胶这类"画线"任务。

**转接（corner blending）** 是产线效率的关键：连续两条直线段之间如果"走到点、停稳、再走"，每段都要减速到零，节拍被浪费；工程上用**圆弧/样条过渡**让轨迹在点位附近"圆滑拐弯"，速度不用降到零——节拍收益常达 10–30%，是编程层最划算的优化。

**辨析｜易错点：MoveL 下奇异不是"不存在"，而是"被隐藏"。** 直线插补在奇异附近时，逆解给出的关节速度趋于无穷，控制器只能临时降速或轨迹失真。离线编程里检测这类问题正是它的价值之一：**在仿真阶段就把奇异、碰撞、限位全部暴露出来，而不是等真机报警。**<span class="marginnote">"仿真里没问题的程序，真机才敢跑"——这正是离线编程相对示教的不可替代之处：它把试错成本从"产线停机"降到了"虚拟重放"。数字孪生的价值也在这里：仿真越贴近真机（含动力学、传感器噪声），离线程序的可靠性越高。</span>

## 7 小结

- **在线示教**：示教器/拖动逐点记录，靠**重复精度**吃饭，简单可靠但不产生可移植资产。
- **机器人编程语言**：从 VAL、KRL、RAPID 等设备语言，走向 Python/C++ + ROS/SDK 的软件化。
- **离线编程（OLP）**：虚拟工作站里规划、验碰撞、算节拍，再下载真机；**成败系于标定**——绝对精度不补偿，离线程序只是动画。
- OLP 仿真的数学内核 = 正向/逆向运动学 + 碰撞检测的循环，正逆解即《正向与逆向运动学》的软件实例。
- 现代范式（行为树、ROS、模仿学习、大模型生成代码）**叠加**而非替代经典控制。

至此，我们从「空间描述与变换」一路走到了「机器人编程」——从数学语言到机械语言再到软件语言，机器人工程的完整链路就此闭环。
