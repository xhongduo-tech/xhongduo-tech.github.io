## 为什么从「NVLink 域」开始

上一节确立了整机柜的立论：72 块 GPU 被当成「一块大 GPU」用。可「当成一块」是一句口号，把它变成现实的是那张把 72 块 GPU 两两连通的高速网络——**NVLink 域（NVLink domain）**。域的设计决定了训练一个万亿参数模型时数据在芯片之间怎么流动，也决定了第 3 节铜互连背板、第 4 节计算托盘结构的全部形态。在从极限到大模型的主线上，这是「怎么把并行的算力真正喂饱」的物理层答案：带宽不够，模型再大也只是纸上算力。

读这一节前最好先建立起一个画面：**机柜 = 一台 72 处理器 + 一张全互连交换网 + 一套电与冷却系统**。本篇只讲中间的「网」，其余在后续篇目补齐。

## 1 为什么 GPU 之间需要「全对全」互连

训练与推理里，数据在 GPU 之间的交换模式大体分两类：**张量并行（tensor parallelism）**把一层矩阵拆到多块 GPU 上，每步前向/反向都要在 GPU 之间搬运中间激活；**专家并行（expert parallelism）**让 token 在多个专家之间路由，通信同样是细粒度的。这两种模式共同要求：**任意两块 GPU 之间都能以接近本地内存的速度交换数据**——这就是「全对全（all-to-all）」通信。

如果走传统的 PCIe + 交换机路线，每次搬运都要穿过 PCIe 控制器、再经过网卡和交换机，延迟从亚微秒级跳到微秒到毫秒级，训练步长会被通信完全拖垮。<span class="marginnote">业界把这种现象叫「通信墙」（communication wall）：算力每年翻倍，但跨芯片互连带宽的提升追不上，通信逐渐吃掉整个训练时间。绕过这堵墙，就是 NVLink 存在的全部理由。</span>NVIDIA 的解法是：**把互连直接做到 GPU 封装里，让 GPU 之间的「局域网」退化成「片上网络」**。

### 为什么要 18 条端口

每颗 Blackwell GPU 在封装里留出 18 条 NVLink 端口，这个数字不是拍脑袋定的，而是**封装引脚的物理预算**决定的。每条 NVLink 5 端口由几十对差分信号线组成，乘以 18 就是上千对引脚——它们要和 HBM3e 内存、PCIe、和其他 I/O 争抢 GPU 封装上有限的引脚面积。18 条端口换来 1.8 TB/s 的域内带宽，是在「带宽」和「硅面积、封装成本、功耗」之间取的平衡点。把这个逻辑推到底，就能理解为什么 NVLink 域不能无限扩大——端口数是有限的，第 5 节会算这笔账。

## 2 拓扑解剖：18 颗 NVLink Switch 怎么把 72 块 GPU 织成一张网

GB200 NVL72 的 NVLink 域由三层构成：

- **第一层：GPU 上的 NVLink 端口**。每颗 Blackwell GPU 集成了 **18 条 NVLink 5 代端口**，每条双向 100 GB/s，合计每 GPU **1.8 TB/s**。这 18 条链路不是拿来点对点互连 GPU 的，而是全部接到交换网络上。
- **第二层：NVLink Switch 交换芯片**。机柜里有 **18 颗 NVLink Switch**（9 个托盘、每托盘 2 颗），每颗提供 144 个 100 GB/s 端口，即约 14.4 TB/s 的交换容量。
- **第三层：接线拓扑**。每颗 Switch 用 72 个端口分别接 72 块 GPU 各一条，再用 72 个端口与其余 Switch 互连，构成一张 **2 级 fat-tree**：任何两块 GPU 之间最多经过一跳交换即可直达。

关键点是**「任意两两直达」**：因为每块 GPU 的 18 条链路分别连向 18 颗 Switch，所以从 GPU A 发出的数据总能找到一条只经过一个交换芯片就到达 GPU B 的路径。对上层软件来说，这个域表现得像一台拥有 72 个处理器的巨型机器——这正是 NVIDIA 强调的「像一块大 GPU 一样编程」。

走一次看一遍：GPU A 要送数据给 GPU B。GPU A 把数据切成若干 flit（流控单元），分摊到它连向 18 颗 Switch 的链路上；携带目标地址的 flit 到达某颗 Switch 后，交换芯片查路由表、以直通（cut-through）方式转发到指向 GPU B 的输出端口，整个转发过程在几个时钟周期内完成。**因为每条路径最多一跳，交换延迟被压到几乎可以忽略**——这就是域内通信能做到「像本地内存访问」的结构基础。

### NVLink Switch 芯片与托盘

每颗 NVLink Switch 5 代芯片提供 **144 个 100 GB/s 端口**，即约 14.4 TB/s 的交换容量，两颗一板、两板一托盘，就得到每托盘 57.6 Tbps 的全双工交换能力。与上一代 H100 的 HGX 方案不同，Blackwell 的 NVLink Switch 是**独立机架式器件**（stand-alone appliance），不再焊在 GPU 载板上——这样设计的目的正是为了让交换网可以脱离计算托盘单独布局、单独维护，也让「9 托盘夹在计算托盘中间」的布线方案成为可能。

交换芯片本身也是「吃电大户」：每颗 NVLink Switch 的功耗在数百瓦量级，18 颗合计占机柜相当比例的功率预算。好在交换托盘与计算托盘一样走液冷冷板，能把热量直接带出机柜——这恰好预告了本专题第六篇《机柜级液冷》的主线：**在 120 kW 的机柜里，连交换芯片都离不开液冷**。

### 托盘怎么摆：把线长压到最短

机柜内部不是把 18 个计算托盘随便一叠：**9 个 NVLink Switch 托盘被夹在两组计算托盘中间**——上方 8 个、下方 10 个计算托盘，中间夹着 9 个交换托盘。这样布置的唯一目的是缩短电缆：NVLink 跑的是高频铜信号，线一长信号就衰减，还得加信号整形芯片；把交换托盘摆在计算托盘的「邻居位」，就能用最短的铜线完成盲插连接。<span class="marginnote">铜缆的传输距离以分米计、而不是以米计，这是机柜内互连「中间夹交换」布局的直接原因。同样的物理约束，在第 12 篇讲 Kyber 机柜的「正交背板」时还会再出现。</span>整柜合计 **1,296 个 NVLink 端口、5,184 条铜信号线**，全部走无源铜缆背板。

**辨析｜易错点：** 交换托盘多不代表拓扑更复杂。NVL72 是「交换规模巨大但逻辑简单」的典型：虽然物理上有 18 颗 Switch，但任意 GPU 对之间的路径都是等长的两段（GPU→Switch→GPU），**没有多跳路径选择的复杂度**。这与数据中心里动辄三到五跳的 Spine-Leaf 网络形成鲜明对比——柜内网络用「物理换简单」，把复杂性留给了背板布线与连接器。

## 3 铜线还是光？一根电缆里的物理账

有人会问：这么高带宽，为什么不用光模块？答案在功耗和成本。NVIDIA 给出的数据是：若把域内互连换成光互连，需要额外约 **20 kW** 的功耗——光模块的激光器、驱动器、DSP 都要吃电，而机柜本来就只剩约 120 kW 的总预算。铜线的代价是传输距离短、线缆沉重，但在机柜这种「线长以分米计」的场景里，铜线是压倒性更优的选择。

铜线要在这么高频率下工作，靠的是三样东西：**低损耗板材**（背板 PCB 用 Megtron 类高速材料）、**连接器镀层**（金/钯镀层降低接触电阻与氧化）、以及**发送端的信号整形**。信号以 **PAM4**（四级脉幅调制）编码——每个符号携带 2 bit，把 100 GB/s 的比特率压到一半的波特率上，再用前向纠错（FEC）兜住高频噪声带来的误码。这条链路如何建模、如何权衡，正是下一篇《铜互连背板》的信号完整性主线；这里先记住结论：**在机柜尺度上，铜是「性能/功耗/成本」三者的最优解，而它换来的工程复杂度全部砸在信号完整性上**。

**易错点｜辨析：** 域内（机柜内）用铜，域间（机柜之间）用光，这不是工程师偷懒，而是**距离决定介质**。机柜内 NVLink 用铜，机柜间 InfiniBand/RoCE 用光纤——两者的分界在几米处。这一点在后文第 3 篇《铜互连背板》会深入信号完整性层面。

## 4 公式解析：域带宽与 AllReduce 带宽

NVLink 域的「总能力」可以用两条数表达：

$$
B_{\text{域内}} = N_{\text{GPU}} \times B_{\text{每GPU}} = 72 \times 1.8\ \text{TB/s} \approx 130\ \text{TB/s}
$$

$$
B_{\text{AllReduce}} = 2 \times B_{\text{域内}} \approx 260\ \text{TB/s}
$$

拆开看：$N_{\text{GPU}}=72$ 是域内 GPU 数，$B_{\text{每GPU}}=1.8\ \text{TB/s}$ 是每颗 GPU 到交换网络的聚合带宽，两者相乘得到域内「一次性双向吞吐」约 **130 TB/s**。<span class="marginnote">AllReduce 要先把各 GPU 的梯度收齐、再广播回去，一来一回正好把域内带宽用两遍，所以是 $2\times$——这就是 NVIDIA 给出「260 TB/s AllReduce 带宽」这个数字的来源。</span>对比一下：单根 InfiniBand NDR 400G 链路全双工约 0.1 TB/s，要让 130 TB/s 的域内吞吐等价，需要 1,300 根 InfiniBand 线——这就是「为什么不能拿网络交换机拼出 NVL72」的数学理由。

**带宽与延迟要分开谈**：域内通信的快感一半来自带宽（每秒搬 1.8 TB），另一半来自延迟（亚微秒级）。一条数据要 130 TB/s 的吞吐，但一次交互（比如 AllReduce 的一个规约步）只搬几 KB，这时延迟才是瓶颈——而一跳直连的拓扑把单跳延迟压到了百纳秒级，比跨交换机通信（微秒级）快一个数量级。**带宽解决「搬多少」，拓扑解决「等多快」，NVL72 两样都要。**

## 5 为什么是 72？域的规模上限

既然「任意两两直达」这么好，为什么不把 576 块 GPU 织进一个域？答案是四个维度的约束同时收口：

- **端口物理预算**：每颗 GPU 只有 18 条 NVLink 端口，交换芯片也只有 144 个端口。把 N 块 GPU 全互连，交换端口数随 N 线性增长，而端口面积是固定预算——72 恰好是「当前封装技术下把成本压住」的规模。
- **线缆与背板**：5,184 条铜信号线已经是背板布线的极限工程；规模翻倍到 144，线缆量翻四倍，背板层数、连接器密度全部爆炸。
- **功耗与冷却**：72 GPU 域已经要吃 120 kW，要靠液冷整柜伺候；域再扩大，单柜功率与散热都无法用现有物理手段满足。
- **故障域**：域越大，单点故障影响面越大。72 是「算力、成本、可靠性」三方妥协的产物。

这正好解释了行业路线的分野：NVIDIA 的下一代 Rubin Ultra 走 **NVL144**（把域翻倍到 144 颗），代价是整柜功率升到约 600 kW、供电改 800V 高压直流、背板改正交 PCB 中板——每一个维度都在挑战物理极限。**「域的规模」从来不是一个纯技术题，而是「封装、线缆、电、热、可靠」五本账的联立求解。**

还有一个被低估的约束来自**软件**：把 72 块 GPU 暴露成「一块 GPU」，需要 CUDA 运行时、通信库（NCCL）、驱动把底层拓扑抽象成单一计算资源。域越大，这套软件栈的调度与容错越复杂——域的设计从来不是纯硬件的独角戏，这也是本专题第十一篇《交付形态》和第九篇《可靠性工程》会反复遇到的「软硬协同」主题。

## 6 带宽层级表：把三张网放在一起看

| 层级 | 介质 | 单 GPU 带宽 | 延迟 | 用途 |
| --- | --- | --- | --- | --- |
| NVLink 域（柜内） | 铜缆背板 | 1.8 TB/s | 亚微秒 | 张量并行、专家并行、梯度同步 |
| InfiniBand / RoCE（柜间） | 光纤 | 400–800 Gbps | 微秒级 | 数据并行、检查点、机柜间聚合 |
| 以太网（管理/存储） | 光纤/铜 | 10–400 Gbps | 毫秒级 | 管理、遥测、对象存储 |

注意 NVLink 域把「每 GPU 带宽」做到了第二层网络的**几十倍**。所以工程上有条铁律：**能留在域内解决的通信，绝不出域**。模型并行度（tensor parallel degree）的取值，本质上就是「把多少 GPU 拉进同一个 NVLink 域」的决策——这正是第 1 篇里 $\eta$（通信/算力比）的具体落地。

真实的 7B/70B 模型训练里，张量并行通常取 8，正好等于把一层 Transformer 的注意力头与 MLP 分到 8 块 GPU 上；再往上（更大模型）就叠加数据并行，把不同 batch 分给不同的 GPU 组。**分组的边界永远贴在带宽台阶上**：NVLink 域内一个台阶，InfiniBand 域间一个台阶，把需要高频同步的维度（张量并行）留在台阶内侧，把低频同步的维度（数据并行）放在外侧——这是分布式训练工程的通用心法，也是本节「三张网」表格的实践意义。

### 别忘了还有一颗「小域」：NVLink-C2C

在 72 GPU 域之外，还有一层更亲密的互连：**NVLink-C2C**。它把机柜里每一颗 Grace CPU 和同板的 Blackwell GPU 以 900 GB/s 的速度连起来，让 CPU 能像访问本地内存一样读 GPU 显存。C2C 域是「CPU 与大域之间的门厅」——CPU 把任务派发进 NVLink 域、把检查点数据搬出来，都走这条高速通道。三篇之后讲《计算托盘结构》时，会再看到它的具体形态。

## 7 小结

- NVLink 域把 72 块 Blackwell GPU 织成一张**全对全、任意两两直达**的网，任何两块 GPU 间带宽 1.8 TB/s。
- 拓扑是 **2 级 fat-tree**：GPU 的 18 条 NVLink 端口接到 18 颗 NVLink Switch，18 颗 Switch 再相互连接，数据最多一跳到达任意目标。
- 机柜内 **9 个交换托盘夹在计算托盘中间**，把铜缆长度压到最短——线长以分米计是布局的第一约束。
- 域内聚合带宽约 **130 TB/s**，AllReduce 带宽约 **260 TB/s**；域内用铜、域间用光，分界在几米处。
- 模型并行度 = 拉进同一 NVLink 域的 GPU 数；能域内解决的通信绝不出域。
- 域的规模上限是「封装端口、线缆、功耗、故障域」四本账的联立求解；下一代 Rubin Ultra 把域翻倍到 NVL144，代价是 600 kW 与 800V 直流。
- 别忘了 **NVLink-C2C**：Grace CPU 与同板 Blackwell GPU 间 900 GB/s 的「门厅」高速通道。
