## 为什么从「单机与整机柜的分界」开始

这套专题讲的是 GPU 机柜，而「为什么一台服务器不够、要把 72 块 GPU 装进一个机柜当成一台电脑用」，是一切工程决策的起点。上一级我们学过互连与封装，知道芯片间的带宽决定了系统的上限；这一篇把视角从芯片拉到机柜，回答一个根本问题：**当我们说「扩展」，到底在扩展什么**。从极限到大模型的主线上，模型参数从 10 亿涨到万亿、再到十亿亿级，单个 GPU 的显存装不下，就必须把计算拆开——拆开的粒度与方式，决定了 Scale-Up 与 Scale-Out 的分野，也决定了后面整柜 NVLink、液冷、母排供电的全部约束。

在动手之前先交代一个判断框架：**系统设计者在「横向」与「纵向」之间做选择，本质是在买带宽还是在买机器。** 横向扩展买的是海量廉价算力，代价是每次通信都要穿过网络；纵向扩展买的是芯片间的超高带宽，代价是硬件越来越贵、越难造。GPU 集群的特殊之处在于，训练任务同时吃这两种能力——于是今天的 AI 数据中心把两者叠起来用：**柜内纵向、柜间横向**。这个「叠」字，是理解 NVL72 一切细节的第一把钥匙。

## 1 Scale-Out：把问题摊到很多台机器上

**Scale-Out（横向扩展）**：把一个大任务拆散给成百上千台独立服务器，机器之间用以太网或 InfiniBand 连接。Barroso 在《The Datacenter as a Computer》里反复强调一个观点：在 Web 规模的数据中心里，单台服务器的可靠性远低于企业级服务器，但**规模本身就是可靠性的来源**——成百上千台廉价机器互为冗余，坏了就换，不用停机。<span class="marginnote">Barroso 所在的 Google 用「重试 + 冗余」把不靠谱的组件拼成靠谱的系统，这套思想后来直接塑造了云计算的形态。它解决的是「巨量并行、容忍单点失效」的问题。</span>

Scale-Out 的关键约束是**网络**：机器之间每次交换数据都要穿过交换机，延迟以微秒计、带宽以几百 Gbps 计，而芯片内部的带宽以 TB/s 计——差了两个数量级。所以 Scale-Out 擅长「粗粒度并行」：每个节点独立处理一批数据，节点间只需要低频的同步与聚合，例如分布式训练里的数据并行（data parallelism）与参数服务器。

看一个真实的 Scale-Out 例子：Meta 在 2024 年训练 LLaMA 3 405B 时，用 1.6 万块 H100 GPU 组成训练集群，集群被切成若干个「计算组」，组内用 InfiniBand 全互连、组间用稀疏的长途链路。组内通信的强度决定了「纵向扩展的域」画到哪里——**域的边界，就是网络带宽从 TB/s 掉到 Gbps 的那个断点**。<span class="marginnote">这也是行业里常说的「计算组 / 超节点」概念：NVLink 域是性能最高的第一层，InfiniBand 域是第二层，以太网是第三层。每一层的带宽差一个数量级，模型并行的切分就要贴合这个带宽层级。</span>

## 2 Scale-Up：把机器越做越大

**Scale-Up（纵向扩展）**：把尽可能多的计算单元放进一个紧密耦合的域里，单元之间用超高带宽、超低延迟的专用互连相连，让它们像一个「大芯片」一样协同工作。GPU 加速器天然倾向 Scale-Up：单个训练步里每个 GPU 的权重梯度要和所有其他 GPU 交换，这种**细粒度、全对全（all-to-all）**的通信模式，只有专用的域内互连才扛得住。

历史上 NVLink 每一代都把这个域做大：V100 时代是 8 块 GPU 插在一张 HGX 板上，H100 时代是 8 块 GPU 通过 4 颗 NVSwitch 两两互连，而到了 Blackwell，域被扩大到 **72 块 GPU**——这就是整机柜（rack-scale）概念的诞生。NVIDIA 自己的表述很直白：一个 GB200 NVL72 机柜「就是一块巨大的 GPU」。<span class="marginnote">「把机柜当一块 GPU 用」不是比喻：72 块 GPU 通过 NVLink 全互连，任何两块 GPU 之间的点到点带宽都高达 1.8 TB/s，等于把一整柜芯片塞进同一个存储一致性域。</span>

### NVLink 的域扩张史

看 NVLink 每一代「每 GPU 带宽」的增长，就能理解 Scale-Up 为什么越走越极端：

| 代际 | 年份 | 典型 GPU | 每 GPU NVLink 带宽 |
| --- | --- | --- | --- |
| NVLink 1 | 2016 | P100 | 160 GB/s |
| NVLink 2 | 2017 | V100 | 300 GB/s |
| NVLink 3 | 2020 | A100 | 600 GB/s |
| NVLink 4 | 2022 | H100 | 900 GB/s |
| NVLink 5 | 2024 | Blackwell B200 | 1800 GB/s |

五年间单 GPU 的域内带宽翻了十倍以上，而 PCIe 总线同期只从 32 GB/s（Gen3 x16）涨到 64 GB/s（Gen5 x16）——**专用互连与通用总线的带宽差距越拉越大，这正是「GPU 要绕开 PCIe 自己组网」的根本原因**。到了 Blackwell，72 块 GPU 的域内聚合带宽达到约 130 TB/s，相当于几千条 InfiniBand 链路叠在一起。

构造这么大的域靠的是**两层器件**：一是 GPU 上集成的 18 条 NVLink 端口（每条 100 GB/s），二是独立的 **NVLink Switch** 交换芯片。72 块 GPU 各自连到全部 18 颗 NVLink Switch 上，形成一张「任意两点直达」的全互连网——这张网具体怎么接线、托盘怎么摆，正是下一节《NVLink 域设计》的主题；这里只需记住：**Scale-Up 域的规模 = GPU 端口数 × 交换芯片规模**。

## 3 分界的本质：通信与算力的比值

Scale-Out 与 Scale-Up 的分界，本质是**每一次计算操作平均要搬动多少字节**。

$$
\eta = \frac{\text{节点间通信数据量}}{\text{本地计算量}} = \frac{B_{\text{net}} \cdot T}{F_{\text{compute}}}
$$

其中 $B_{\text{net}}$ 是节点间带宽，$F_{\text{compute}}$ 是节点算力，$T$ 是单步计算时间。当 $\eta$ 很大时，机器大部分时间在等数据、而不是在算——通信成为瓶颈；反之计算成为瓶颈。GPU 训练一个万亿参数模型的场景里，权重同步的 AllReduce 通信量极其巨大，$\eta$ 必须靠 Scale-Up 的域内带宽压下去，这就是 NVL72 存在的理由。

**辨析｜易错点：** 有人以为「Scale-Up 就是单机、Scale-Out 就是多机」，其实 NVL72 这种整机柜既有 72 块 GPU 的多处理器结构、又是一台逻辑上的单机——**区分两者的标准不是「几台机器」，而是「单元之间走的是域内专用互连还是通用网络」**。NVLink 连起来的 72 块 GPU 是 Scale-Up，InfiniBand 连起来的两个机柜是 Scale-Out。PCIe 在这里扮演夹层角色：它仍然负责 GPU 挂接网卡、NVMe 等 I/O 设备，但已不再承担 GPU 之间的数据交换重任。<span class="marginnote">一句话记忆法：<strong>NVLink 管「通信」，PCIe 管「上外设」。</strong> 这个分工从 H100 时代就定型了，Blackwell 只是把它放大到机柜尺度。</span>

## 4 公式解析：Ring AllReduce 的通信量为什么与节点数无关

**核心概念：Ring AllReduce（环形全规约）**是让 N 块 GPU 把梯度规约成一份的经典算法，它的美妙之处在于通信量几乎与 N 无关。

在环结构里，每块 GPU 把梯度切成 N 段，每次只向环上的下一个邻居传一段，同时从上一个邻居接收一段。规约与广播各走一圈，**每块 GPU 收发两遍数据**，所以单节点通信量是：

$$
C = 2M \cdot \frac{N-1}{N}
$$

拆开看：$M$ 是梯度总量（模型参数 × 4 字节），$N$ 是参与的 GPU 数，$C$ 是每块 GPU 要搬动的字节数。<span class="marginnote">当 $N$ 很大时 $\frac{N-1}{N} \to 1$，$C \to 2M$——也就是说，不管你有 72 块还是 576 块 GPU，每块 GPU 只需要搬自己的两倍梯度量，通信量不随规模线性增长。这就是环算法打败「主节点汇聚」算法的原因。</span>对比之下，若由单一主节点汇聚，主节点要接收 $M$、再广播 $M$，通信量是 $2M$ 固定不变，但主节点成了串行瓶颈；环算法把瓶颈摊到每个节点上，链路利用率拉满。

**重点：训练一个模型要多久，不只取决于算力，更取决于数据能不能以匹配的速度流到每一块 GPU。** Ring AllReduce 让「扩展到更多 GPU」的通信代价近似恒定，这正是 Scale-Up 域从 8 块扩到 72 块仍然可行的数学基础。

套一个真实的数：假设模型有 1.5 万亿参数，FP32 梯度就是 6 TB。若 72 块 GPU 做 Ring AllReduce，每块 GPU 要搬 $2 \times 6 \times \frac{71}{72} \approx 11.8$ TB 数据；按 NVLink 单 GPU 1.8 TB/s 计，梯度同步约需 6.6 秒。若退回到没有 NVLink 的 Scale-Out 环境（单链路 400 Gbps 网络），同步时间立刻涨到近 30 秒——训练步长一旦到秒级，算力再多也是空转。**这 6.6 秒与 30 秒的差距，就是 Scale-Up 存在价值的全部理由。**

现实中工程师还会做**梯度压缩**（量化、稀疏化）进一步压低 $M$，把同步时间再砍一个数量级；但压缩有精度代价，且无法弥补「网络带宽差两个数量级」的硬伤。这也解释了为什么先进模型训练几乎无一例外地拥抱 Scale-Up 域——通信的物理成本，最终只能靠物理层解决。

## 5 核心对比表：Scale-Up 与 Scale-Out 的关键差异

| 维度 | Scale-Up（纵向扩展） | Scale-Out（横向扩展） |
| --- | --- | --- |
| 典型对象 | GPU 域（NVLink 72 GPU） | CPU 服务器集群、GPU 服务器集群 |
| 互连介质 | NVLink / NVLink Switch，域内 1.8 TB/s | InfiniBand / 以太网，单链路 200–400 Gbps |
| 通信延迟 | 亚微秒级（同柜铜缆） | 微秒到毫秒级（跨交换机） |
| 粒度 | 细粒度全对全，如逐层梯度同步 | 粗粒度，如数据并行 batch 划分 |
| 可靠性来源 | 硬件冗余 + RAS 特性 | 规模冗余 + 软件重试 |
| 适用场景 | 万亿参数大模型、张量并行、专家并行 | 推理服务横向扩展、海量小任务 |

Barroso 书里预言的图景是：整座数据中心 = 一台巨型计算机。今天 NVL72 把这个图景压缩到了一个机柜里——**Scale-Up 负责让「一台」变得更强，Scale-Out 负责让「很多台」组织起来**，两者不是二选一，而是叠在一起的：机柜内 NVLink 做 Scale-Up，机柜间 InfiniBand 做 Scale-Out。

行业里也不只有 NVIDIA 一家在赌 Scale-Up：AMD 用 Infinity Fabric 把 MI300 系列做成单机 8 卡域，Intel 的 Gaudi 走的是「多机横向 + 域内窄带宽」的折中路线，而 2024 年成立的 UALink 联盟（AMD、博通、思科、谷歌、惠普、英特尔、Meta、微软共同参与）正在定义开放标准下的 Scale-Up 域内互连。**GPU 域互连正在从「私有生态」走向「开放标准」**——这与第十篇《OCP 开放计算》的主题直接呼应，也是理解行业格局的重要背景。

## 6 整机柜的收益：用数字说话

NVL72 把 Scale-Up 推到极致后，账面数字是这样：一个机柜装 **72 块 Blackwell GPU + 36 块 Grace CPU**，集成 13.5 TB 的 HBM3e 高带宽内存，稀疏 FP4 下算力达 1.44 exaFLOPS（即 1440 PFLOPS），FP8 下为 720 PFLOPS。NVIDIA 官方给出的关键指标是：**实时万亿参数 LLM 推理，比上一代提升约 30 倍**。<span class="marginnote">这 30 倍不来自单颗 GPU，而来自「模型不再需要切碎塞进跨机网络」：显存大到能把整个模型放进一个域，推理时不必在交换机间反复搬运权重。</span>

整机柜的收益要算三笔账：

- **带宽账**：域内聚合带宽约 130 TB/s，GPU 之间同步数据的瓶颈被压到芯片互连级，训练与推理的通信开销都大幅下降。
- **内存账**：13.5 TB 的 HBM3e 可以让万亿参数模型「驻留」在域内，省掉了跨机反复读权重的开销——这是推理加速 30 倍的最直接来源。
- **管理账**：一个机柜在逻辑上是一台机器，软件栈（驱动、容器、调度）把它当单个单元对待，比管理 72 台独立服务器简单得多。

代价同样真实：这个机柜功耗约 **120 kW**、总重约 **1.36 吨**，必须整柜液冷，供电走直流母排。**把 Scale-Up 做到机柜尺度，等于把「数据中心基础设施问题」全部下放到一个柜子里解决**——这恰恰是本专题后面所有篇目（液冷、母排、热设计、可靠性）要逐一拆解的对象。

还有一层工程代价被大多数人低估：**可靠性边界变了**。Scale-Out 时代一块 GPU 坏了，任务重调度到别的机器即可；Scale-Up 时代 72 块 GPU 共享一个训练作业，任何一块失效都可能拖住整个机柜。于是「热插拔」「降频降级」「故障域隔离」这些词从服务台话题变成了芯片设计话题——这正是第九篇《可靠性工程》的伏笔，也说明整机柜的收益从来不是免费午餐。

## 7 小结

- **Scale-Out** 靠成百上千台机器分摊任务，网络是瓶颈，可靠来自规模冗余；**Scale-Up** 靠域内高速互连把机器做强，通信是决定因素。
- GPU 训练要求**细粒度全对全通信**，天然倾向 Scale-Up，NVLink 从 8 GPU 域扩展到 72 GPU 整柜域。
- 通信与算力比值 $\eta$ 决定瓶颈在数据通路还是计算单元；Ring AllReduce 的通信量 $2M\frac{N-1}{N}$ 近似与节点数无关，是 GPU 域能持续扩大的数学支撑。
- GB200 NVL72 首次把「一块大 GPU」做到机柜尺度：72 块 Blackwell GPU 全互连，域内任意点到点 1.8 TB/s。
- 机柜内 Scale-Up、机柜间 Scale-Out 叠加，是当前 AI 数据中心的标准形态。
