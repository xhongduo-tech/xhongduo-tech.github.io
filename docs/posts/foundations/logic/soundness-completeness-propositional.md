# 命题逻辑的可靠性与完全性

<div class="epigraph">
<p>可靠性与完全性：推演出的都是真的，真的都能被推演出来。</p>
<footer>—— 元逻辑学（metalogic）的两个基本定理</footer>
</div>

## 为什么从可靠性与完全性开始

我们已经握有两种判定「论证有效」的工具：**真值表**是语义的方法（看真假），**自然演绎**是语法的方法（走规则）。
两种方法是否一致？会不会有一条规则能推出的结论在真值表上并不成立？
反过来，会不会真值表成立的结论规则却推不出来？
本课回答这两个问题，结论出乎意料地漂亮：**在命题逻辑里，两者完全一致**。
这个「一致」被拆成两个方向，就是**可靠性（soundness）**与**完全性（completeness）**——它们是元逻辑的第一批定理，也是「一个形式系统是否可信、是否够用」的判据。

## 1 两个视角与两个记号

先固定记号，分清两种「推出」：

- **语义后承 $\models$**：$P_1, \dots, P_n \models C$，意思是「真值表上，前提全真时结论必真」——真值表判定出来的有效论证。
- **语法推出 $\vdash$**：$P_1, \dots, P_n \vdash C$，意思是「自然演绎从前提按规则走得出结论」——推演证明出来的有效论证。

$\models$ 回答「有没有道理」，$\vdash$ 回答「走不走得到」。两者是不同层面的概念：一个看真值，一个看规则。可靠性定理与完全性定理要论证的，正是这两个记号在命题逻辑中**重合**。<span class="marginnote">这也是《用真值表判定论证有效性》一课留下的悬念：当时我们用 $\models$ 检验有效性，但 $\models$ 与 $\vdash$ 的关系还没有回答。本课补上这一环。</span>

## 2 可靠性：推出来的都是真的

**可靠性定理（soundness theorem）**：如果 $P_1, \dots, P_n \vdash C$（可推演），那么 $P_1, \dots, P_n \models C$（语义上有效）。

用大白话说：**自然演绎不会「胡推」——凡是按规则走出来的结论，在真值表上也一定成立。**

可靠性的证明思路非常朴素，三步：

**第一步，对基本规则逐一检查**：每条基本规则都是保真的——前提为真时结论必真（我们在上一课用真值表验证过肯定前件）。
**第二步，归纳**：一个推演是由规则的多次应用组成的。如果每一步都保真，那么整条推演链也保真——从真前提出发，最后一行必真。
**第三步，收尾**：因此只要 $\vdash$ 存在，$\models$ 必然成立。规则系统不会制造「看似能推、其实不成立」的幻影。

可靠性是形式系统的**底线要求**：一个不可靠的系统会从真前提推出假结论，这样的系统毫无价值。
数学证明、程序验证之所以相信「证明」，前提就是规则可靠。

## 3 完全性：真的都能推出来

**完全性定理（completeness theorem）**：如果 $P_1, \dots, P_n \models C$（语义上有效），那么 $P_1, \dots, P_n \vdash C$（可推演）。

用大白话说：**自然演绎足够强大——真值表上成立的每一个论证，都能用规则一步一步走出来，一个都不漏。**

完全性远非显然：规则集给定了，凭什么相信它覆盖了所有可能的有效论证？
这个方向由哥德尔（Kurt Gödel）在 1930 年首先严格证明（针对一阶谓词逻辑，命题逻辑是其特例）。
证明的巧妙之处在于**构造**：证明的核心是说明，任何「真值表上有效的结论」都能被翻译成一条规则推演。

完全性的意义在于：**语法与语义在这个系统里是同一个东西的两面**。「有没有道理」（语义）与「走不走得到」（语法）完全同步——你不必担心某个真理藏在规则的缝隙里永远推不出来。<span class="marginnote">完全性之所以了不起，是因为它把「世界上的真理」与「系统里的可证性」连接起来：只要一个命题在真值表意义上为真，就一定能形式地证明它。这为「逻辑 = 计算」埋下了种子——第三篇讲一阶逻辑不可判定性时，你会发现这个连接在一阶逻辑那里开始松动。</span>

## 4 公式解析：可靠性—完全性的一体两面

把两个定理浓缩成一对公式，它们说的是同一个对象关系的两个方向：

$$
\Gamma \vdash C \;\Longrightarrow\; \Gamma \models C \quad(\text{可靠性})
$$

$$
\Gamma \models C \;\Longrightarrow\; \Gamma \vdash C \quad(\text{完全性})
$$

逐项拆解：

- **$\Gamma$**：前提集（可以有一堆前提），$C$ 是结论。
- **$\Longrightarrow$ 方向一（可靠性）**：从「走得到」推出「有道理」——推演不出差错。
- **$\Longrightarrow$ 方向二（完全性）**：从「有道理」推出「走得到」——规则足够强。
- **合起来**：$\vdash$ 与 $\models$ 在两个方向上互相蕴含，即 $\Gamma \vdash C$ 当且仅当 $\Gamma \models C$。命题逻辑的语法与语义完全同构。

**辨析｜易错点：** 可靠性与完全性**互相独立**：一个系统可能可靠但不完全（规则太少，推不出该推的），也可能完全但不可靠（规则太多，推出不该推的）。一个好的逻辑系统两个都要。命题逻辑两者兼备，但这不是免费的——完全性在一阶逻辑中依然成立（哥德尔 1930），而「可判定性」却在一阶逻辑中失败（丘奇—图灵定理），那是第三篇的终点。

## 5 例题演练

**例 1**：为什么「可靠」与「完全」缺一不可？各举一个反例系统。

- 只可靠不完全：规则只有肯定前件、没有析取三段论——推不出的有效论证存在（不完全），但推出的都对（可靠）。只完全不可靠：允许从 $P$ 推出任意 $Q$——什么都能推（完全），但会推出假结论（不可靠）。

**例 2**：$\models$ 与 $\vdash$ 在命题逻辑中重合，这个事实有什么实用意义？

- 意义是「证明」与「查表」等效：你想验证一个论证，既可以构造自然演绎证明（$\vdash$），也可以用真值表判定（$\models$），两条路答案一致。机器判定用真值表/真值树，人写证明用自然演绎——工具不同，结论相同。

**例 3**：可靠性定理的证明为什么用归纳？

- 一个证明是规则的有限次应用。先证每条规则保真（基础步），再证「若前面几步保真，则下一步保真」（归纳步），从而整条证明链保真——这就是数学归纳法在元逻辑里的典型用法。

**例 4**：为什么「可靠但完全」的系统可以被简化而不丢失正确性？

- 可靠性保证不推错，完全性保证不漏推——两者合起来是「恰好推完所有有效结论」。若只保留一个方向的保证，系统要么漏（不完全）要么错（不可靠），都不理想。

**例 5**：完全性定理的证明为何要用「构造」？

- 要证「凡有效皆可证」，不能靠枚举（论证无穷多），而要对任意有效论证构造出一个证明——哥德尔的证明用「极大一致集 + 典范模型」构造，把一个语义有效式变成一个语法可证式。

**延伸思考**：可靠性—完全性框架是「形式系统质量」的通用度量，在逻辑之外同样适用：编程语言类型系统的可靠性（类型安全）与完全性（不拒绝合理程序）、验证工具的健全性与完备性——同一对概念贯穿整个计算理论。

**例 4**：为什么「可靠但完全」的系统值得追求？

- 可靠性保证「推得出的都对」（不误导），完全性保证「对的都推得出」（不漏掉）——两者合起来，语法与语义完全同步。命题逻辑恰好两者兼备。

**延伸思考**：$\vdash$ 与 $\models$ 的重合让「证明」与「查表」等效——机器判定与人工推演殊途同归。

**本节要点自检**：可靠性=推得出的都对（不胡推），完全性=对的都推得出（不漏推）；两者合起来说明语法与语义同构。

## 6 小结

- **两种「推出」**：语义后承 $\models$（真值表）与语法推出 $\vdash$（规则推演）。
- **可靠性**：$\Gamma \vdash C \Rightarrow \Gamma \models C$——推演保真，系统不出错。证明靠「每条规则保真 + 归纳」。
- **完全性**：$\Gamma \models C \Rightarrow \Gamma \vdash C$——凡有效皆可证，规则不漏。哥德尔 1930 年证明。
- 二者合起来：命题逻辑的语法与语义**同构**，$\vdash$ 与 $\models$ 重合。
- 可靠与完全互相独立：一个好系统两者兼备；命题逻辑做到了，一阶逻辑里这个完美图景开始松动。
