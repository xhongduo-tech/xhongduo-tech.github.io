# 交替更新过程及其在可靠性中的应用

<div class="epigraph">
<p>一个系统的可靠性，是它「能工作」的时间在所有时间里的占比——而占比只由两个均值决定。</p>

## 为什么「开-关」结构如此普遍

很多系统只有两种状态，在之间来回切换：机器「运行—停机」，设备「正常—故障」，服务「忙—闲」，网络「连通—断连」。这类现象可以用**交替更新过程（alternating renewal process）**精确建模——它由两个交替的更新过程拼接而成，一个负责「开」的时长，一个负责「关」的时长。

交替更新过程是可靠性工程的**工作马（workhorse）**：**可用度（availability）**——系统在长期运行中「能用」的时间比例——几乎都是用它算的。而它本质上是更新报酬定理的一个应用：把「开」的时间当成报酬，把「开 + 关」的周期当成更新周期。<span class="marginnote">可靠性里有三个易混概念：<strong>可靠性（reliability）</strong>指「在规定时间内不失效的概率」；<strong>可用度（availability）</strong>指「在随机时刻处于可用状态的概率」；<strong>维修性（maintainability）</strong>指「失效后修复的快慢」。交替更新过程主要伺候「可用度」。</span>

本节的目标：定义交替更新过程、推出长期可用度公式、并辨析「瞬时可用度」与「长期可用度」的差别。

交替更新过程是「更新报酬定理」的第一个工业级应用：它把「系统能用多久」这种工程问题，翻译成「周期平均报酬」这种数学问题。学完这一节，你会看到一条清晰的链条——**开-关结构 → 周期报酬 → 可用度公式 → SLA 估算**——可靠性工程的基本盘就握住了。

## 1 定义

**交替更新过程（alternating renewal process）**：系统在「开」与「关」两种状态间交替。设 $U_1, U_2, \dots$ 为**开（up）**时段的时长，$D_1, D_2, \dots$ 为**关（down）**时段的时长，满足：

$U_i$ 独立同分布，$E[U] = \mu_U$；
$D_i$ 独立同分布，$E[D] = \mu_D$；
所有 $U_i$ 与所有 $D_i$ 相互独立。

系统从「开」开始：$[0, U_1)$ 开，$[U_1, U_1 + D_1)$ 关，$[U_1 + D_1, U_1 + D_1 + U_2)$ 开……如此交替。<span class="marginnote">把一个「开-关」对 $(U_n, D_n)$ 看成一个周期：周期长度 $X_n = U_n + D_n$，周期报酬 $R_n = U_n$（周期内「开」的时长）。这样交替更新过程就嵌进了更新报酬过程的框架——<strong>一切长期结论自动继承</strong>。</span>

这个「周期化」的视角是整节的钥匙：一旦把开-关对看成更新周期，长期可用度就是「周期内开时长期望 ÷ 周期长度期望」——**更新报酬定理 $E[R]/E[X]$ 一秒钟给出答案**。这也是为什么本节几乎不需要新定理，只是把第三篇的报酬框架套到可靠性上。

## 2 长期可用度

把周期定义为 $X_n = U_n + D_n$，报酬 $R_n = U_n$，由更新报酬定理：
$$
\lim_{t\to\infty} \frac{1}{t} \int_0^t \mathbb{1}[\text{系统在 } s \text{ 时刻可用}]\, ds = \frac{E[R]}{E[X]} = \frac{\mu_U}{\mu_U + \mu_D}.
$$
这个极限叫**长期可用度（long-run availability）**，记作 $A$：
$$
A = \frac{\mu_U}{\mu_U + \mu_D}.
$$
**长期可用度 = 平均开时长 ÷ 周期平均时长。**<span class="marginnote">直觉：开与关按期望时长交替，时间被「开」占的比例就是 $\mu_U / (\mu_U + \mu_D)$。若平均运行 90 小时、平均停机 10 小时，则长期可用度 90%。这个公式在可靠性合同中常常直接出现——SLA（服务等级协议）里的「99.9% 可用」正是此类量。</span>

**不可用度（unavailability）** $= 1 - A = \frac{\mu_D}{\mu_U + \mu_D}$。两个量互补，用哪个看语境。

互补关系让可靠性分析总是「二选一」：谈 SLA 用可用度，谈停机成本用不可用度。**两者只是同一个分数换了个分子**——$\mu_U$ 换成 $\mu_D$ 而已，不必重复计算。

## 3 瞬时可用度与极限

长期可用度是时间平均。可靠性工程还常问**瞬时可用度（pointwise availability）** $A(t) = P(\text{系统在 } t \text{ 时刻可用})$——从 $t=0$ 开始算，到时刻 $t$ 可用的概率。

$A(t)$ 可以用更新方程刻画。设开时长分布 $G$（密度 $g$），关时长分布 $H$（密度 $h$）。条件于第一个周期的结构，可写出
$$
A(t) = P(U_1 > t) + \int_0^t A(t - x)\, dF_{U+D}(x),
$$
其中 $F_{U+D}$ 是 $U_1 + D_1$ 的分布。直接项 $P(U_1 > t)$ 是「第一个开时段还没结束」的概率；积分项是「至少完成一个周期后重新开始」的贡献。

**关键更新定理的结论**：$A(t) \to \mu_U / (\mu_U + \mu_D)$ 当 $t \to \infty$——**瞬时可用度收敛到长期可用度**，与起点无关。<span class="marginnote">可靠性里另有一个与 $A(t)$ 易混的量：<strong>可靠性 $R(t)$</strong>（从 $t=0$ 到 $t$ 不失效的概率）。$R(t)$ 是「一次都不坏」的概率，随 $t$ 单调下降且不回升；$A(t)$ 允许「坏了又修好」，趋于常数。<strong>可靠性管『第一失败』，可用度管『长期占比』</strong>——别用混。</span>

一个数值感受两者的差别：若系统平均运行 90 小时、平均停机 10 小时，长期可用度 $A = 90\%$；但若单次运行时长服从指数分布（均值 90），可靠性 $R(10) = e^{-10/90} \approx 0.895$——**10 小时不失效的概率约 89.5%，略低于可用度 90%**。两者的数值相近却含义不同：$R(t)$ 盯着「第一次失败」，$A$ 盯着「长期平均」。

## 4 公式解析：A(t) 的更新方程推导

**目标：把瞬时可用度 $A(t)$ 的更新方程写出来，并确认它的极限就是长期可用度。**

第一步，条件于第一个开时段 $U_1$。
- 若 $U_1 > t$：系统全程可用，概率 $1$，直接贡献 $P(U_1 > t)$。
- 若 $U_1 \le t$：第一个开时段结束后进入关时段，再完成整个周期后系统回到「开」状态，从 $U_1 + D_1 = x$ 重新开始。剩余时间 $t - x$ 内可用的概率恰为 $A(t-x)$。

第二步，综合。设 $x = U_1 + D_1$，其分布为 $F_{U+D} = G * H$：
$$
A(t) = \big(1 - G(t)\big) + \int_0^t A(t - x)\, dF_{U+D}(x).
$$
第三步，认直接项 $h(t) = 1 - G(t)$。由关键更新定理，$A(t) = h(t) + h * m(t)$ 的极限为
$$
\lim_{t\to\infty} A(t) = \frac{1}{E[U+D]} \int_0^\infty \big(1 - G(u)\big)\, du = \frac{E[U]}{E[U] + E[D]}.
$$
第四步，核对：$\int_0^\infty (1-G(u))du = E[U]$（非负随机变量的期望 = 生存函数积分），$E[U+D] = \mu_U + \mu_D$。于是极限正是 $\mu_U/(\mu_U + \mu_D)$。

**这个推导为什么重要**：它把「瞬时」与「长期」两个概念用同一条更新方程缝合起来——**先写瞬时量的方程，再取极限得长期量**。这是可靠性数学的核心工作流：$A(t)$ 的瞬态方程 + 关键更新定理 = 长期可用度。

## 5 应用：系统设计中的可用度

- **冗余设计**：双机热备系统，主机失效后备份接管。交替更新模型可算「至少一台可用」的概率，进而评估冗余带来的可用度提升。
- **维护策略**：把「定期检修」建模为受控的关时段。延长检修间隔提高可用度，但增加故障风险——在 $E[D]$ 与失效频率之间权衡。
- **SLA 估算**：给定平均故障间隔（MTBF）与平均修复时间（MTTR），可用度
$$
A = \frac{\mathrm{MTBF}}{\mathrm{MTBF} + \mathrm{MTTR}}.
$$
这个公式是运维行业的标准估算——**MTBF 与 MTTR 是两个均值，可用度立刻出来**。<span class="marginnote">MTBF（Mean Time Between Failures）= $\mu_U$，MTTR（Mean Time To Repair）= $\mu_D$。注意 MTBF 是「两次失效之间」的平均，包含运行与停机；而这里 $\mu_U$ 是纯运行时间。工程里两者定义略有差异，但数量级一致——先掌握公式骨架，细节对照行业惯例。</span>

把 SLA 落到数字：若某服务承诺 99.9% 可用，则 $\mu_U/(\mu_U + \mu_D) \ge 0.999$，解得 $\mu_D \le \mu_U/999$——**若平均运行 1000 小时，停机不得超过约 1 小时**。一年 8760 小时里 99.9% 意味着故障时间不超过约 8.76 小时，「三个九」的代价是「故障预算」极其苛刻。这条换算在运维谈判里天天用到。

## 6 交替更新与可靠性术语速查

| 术语 | 记号 | 含义 | 要点 |
| --- | --- | --- | --- |
| 交替更新过程 | 开 / 关时段交替 | 双状态更新过程 | 可靠性工作马 |
| 长期可用度 | $A = \mu_U/(\mu_U+\mu_D)$ | 长期可用时间占比 | 更新报酬直接给出 |
| 瞬时可用度 | $A(t)$ | $t$ 时刻可用概率 | 满足更新方程 |
| 可靠性 | $R(t)$ | 到 $t$ 不失效概率 | 管第一失败 |
| 不可用度 | $1 - A$ | 停机占比 | 与可用度互补 |
| SLA / MTBF | $\mu_U$、$\mu_D$ | 平均运行 / 修复时间 | 可用度快速估算 |

## 7 小结

- **交替更新过程**：开/关时长各自独立同分布、互相独立，构成「开-关」周期。
- **长期可用度** $A = \mu_U / (\mu_U + \mu_D)$——开时长占比，由更新报酬定理直接给出。
- **瞬时可用度** $A(t)$ 满足更新方程 $A(t) = 1 - G(t) + \int_0^t A(t-x) dF_{U+D}(x)$，极限收敛到长期可用度。
- 辨析：可靠性 $R(t)$（不失效概率）vs 可用度 $A(t)$（可用概率，可修复）。
- 应用：冗余设计、维护策略、SLA 估算（MTBF/MTTR）。
- **数值直觉**：$\mu_U/\mu_D = 999$ 才到「三个九」；$R(10) \approx 0.895$ 与 $A = 0.9$ 相近却含义不同。

在下一节，我们给更新过程加上「初始延迟」：第一个间隔的分布与后续不同。这就是**延迟更新过程与再生过程**——它统一了普通更新与平衡更新的框架。
