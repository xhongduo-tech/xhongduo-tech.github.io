# M/M/s 与 M/M/∞ 排队系统

<div class="epigraph">

## 一个变一群

$M/M/1$ 假设只有一个服务员。但现实几乎总有多个：银行开 5 个窗口、呼叫中心坐 30 个客服、云计算集群有上百台机器。**$M/M/s$** 把模型推广到 $s$ 个**同质**服务员：一个公共队列，谁空谁接。这是「多服务器 + 单队列」的标准模型。

更极端的情形是 $M/M/\infty$——**服务员无穷多**，每个顾客到达即被服务、永不等待。它看起来不现实，却是分析「无限资源」的理想极限：比如自助商店（每个人都是自己的收银员）、云资源无限供应的近似。**$M/M/\infty$ 的价值在于它有一个绝美的结论：稳态人数服从泊松分布。**<span class="marginnote">Kendall 记号里的 $s$ 可以是正整数或 $\infty$。$M/M/\infty$ 常作为「没有排队的上限」与 $M/M/1$ 对照——<strong>真实系统夹在「全等待」与「零等待」两个极端之间</strong>。</span>

本节目标：推导 $M/M/s$ 的平稳分布、掌握爱尔朗 C 公式（等待概率）、并看清 $M/M/\infty$ 的泊松结构。

多服务器是排队论从「教科书」走向「工业界」的一步：呼叫中心座席、云计算集群、银行窗口，几乎全是 $M/M/s$ 的化身。**掌握它，等于掌握了「容量规划」这门手艺的数学内核**——爱尔朗 C 公式就是那个「配几个服务员」的答案。

## 1 M/M/s 的生灭结构

$M/M/s$：到达强度 $\lambda$，每个服务员服务速率 $\mu$。系统人数 $n$ 时：

- **出生速率**（有人到）：$\lambda_n = \lambda$，恒不变；
- **死亡速率**（有人服务完）：若 $n \le s$，$n$ 个服务员都在忙，服务总速率 $n\mu$；若 $n > s$，$s$ 个服务员全忙，服务总速率 $s\mu$。故
$$
\mu_n = \begin{cases} n\mu, & 0 \le n \le s, \\ s\mu, & n \ge s. \end{cases}
$$

**流量强度**：$\rho = \frac{\lambda}{s\mu}$。**稳定性条件** $\rho < 1$（到达率必须小于总服务能力 $s\mu$）。<span class="marginnote">与 $M/M/1$ 对照：$M/M/1$ 的利用率就是 $\lambda/\mu$；$M/M/s$ 的利用率是 $\lambda/(s\mu)$——<strong>除以服务员数，才能比较不同规模的系统</strong>。一个「利用率 90%」的 $s$ 服务器系统，与「利用率 90%」的单服务器系统，排队表现差别巨大（$s$ 越大越稳）。</span>

一个数值感受「$s$ 越大越稳」：同样利用率 $\rho = 0.9$，$M/M/1$ 的平均队长 $L = \rho/(1-\rho) = 9$；而 $M/M/s$（利用率 0.9，$\lambda = 0.9 s\mu$）的平均队长远小于 9——**多个服务员把「队」拆成「等」，让同一利用率下的排队大为缓解**。这就是云集群「横向扩展」的排队论依据。

## 2 M/M/s 的平稳分布

用生灭递推 $\pi_{n+1} = \pi_n \lambda_n/\mu_{n+1}$：

**当 $n \le s$**：
$$
\pi_n = \pi_0 \prod_{k=1}^{n} \frac{\lambda}{k\mu} = \pi_0\, \frac{(s\rho)^n}{n!}.
$$
**当 $n \ge s$**：
$$
\pi_n = \pi_0\, \frac{(s\rho)^n}{s!\, s^{n-s}}.
$$
$\pi_0$ 由归一化 $\sum \pi_n = 1$ 定出：
$$
\pi_0 = \left[ \sum_{n=0}^{s-1} \frac{(s\rho)^n}{n!} + \frac{(s\rho)^s}{s!}\cdot \frac{1}{1-\rho} \right]^{-1}.
$$

**结构与 $M/M/1$ 的对比**：$n \le s$ 时是「泊松形态」$(s\rho)^n/n!$（服务员没全忙，等效于 $M/M/\infty$）；$n \ge s$ 时是「几何尾巴」$\rho^{n-s}$（全忙时等效于 $M/M/1$ 以速率 $s\mu$ 服务）。**系统在「充裕」与「拥塞」两个区域的行为判若两人。**<span class="marginnote">这个「两段式」分布是理解多服务器的钥匙：<strong>服务员没全忙时，队列像无限服务（泊松）；全忙时，队列像单服务器（几何）</strong>。临界点 $n = s$ 就是两种行为的切换。</span>

## 3 爱尔朗 C 公式：等待概率

**爱尔朗 C 公式（Erlang C）**：顾客到达时**需要排队**（所有 $s$ 个服务员都忙）的概率
$$
P(\text{等}) = \sum_{n=s}^\infty \pi_n = \frac{\frac{(s\rho)^s}{s!} \cdot \frac{1}{1-\rho}}{\sum_{n=0}^{s-1}\frac{(s\rho)^n}{n!} + \frac{(s\rho)^s}{s!}\cdot\frac{1}{1-\rho}}.
$$
**这个公式是呼叫中心的核心**——它告诉你要配多少个座席才能把「等待概率」压到可接受水平（如 5%）。<span class="marginnote">爱尔朗 C 是「容量规划」的第一公式：<strong>给定到达率与服务率，算出不同座席数下的等待概率，选能满足 SLA 的最小 $s$</strong>。它还有配套的 Erlang B（无等待、直接放弃的损失制系统）——电话呼叫中「线路全忙就挂断」的情形。</span>

**例**：$\lambda = 10$/分，$\mu = 6$/分（每个服务员每分钟服务 6 个）。$s = 2$：$\rho = 10/(12) = 0.833$。代入 Erlang C 得 $P(\text{等}) \approx 0.68$——**两个服务员时，68% 的顾客要排队**。加到 $s = 3$：$\rho = 10/18 = 0.556$，$P(\text{等}) \approx 0.20$。**多一个服务员，等待概率从 68% 降到 20%。**

把「非线性改善」再看透：$s$ 从 2 到 3 只多一个座席，等待概率却从 68% 跌到 20%——**临界点附近的容量投入，回报是指数级的**。这也是为什么呼叫中心宁可多配几个座席，也不愿承担「等待超时」的客户流失；Erlang C 让这种权衡从「拍脑袋」变成「查公式」。

## 4 公式解析：M/M/∞ 的泊松分布

**目标：证明 $M/M/\infty$ 的稳态人数服从泊松分布 $\pi_n = e^{-\rho}\frac{\rho^n}{n!}$（$\rho = \lambda/\mu$）。**

第一步，写生灭速率。$M/M/\infty$：$\lambda_n = \lambda$，$\mu_n = n\mu$（$n$ 个服务员每人服务 $\mu$）。

第二步，递推平稳分布。$\pi_n = \pi_0 \prod_{k=1}^n \frac{\lambda}{k\mu} = \pi_0 \frac{(\lambda/\mu)^n}{n!} = \pi_0 \frac{\rho^n}{n!}$。

第三步，归一化。$\sum_{n\ge0} \pi_n = \pi_0 \sum_{n\ge0} \frac{\rho^n}{n!} = \pi_0 e^{\rho} = 1$，故 $\pi_0 = e^{-\rho}$。

第四步，结论。$\pi_n = e^{-\rho} \frac{\rho^n}{n!}$——**泊松分布，均值 $\rho = \lambda/\mu$**。平均队长 $L = \rho$，平均逗留 $W = L/\lambda = 1/\mu$——**每个顾客来了就服务，等待时间等于服务时间，永不排队**。

**这个推导为什么重要**：$M/M/\infty$ 是「无拥塞」的理想基准——<strong>人数是泊松、等待为零</strong>。它常被用来做上限对比：真实系统的人数「介于」$M/M/\infty$（泊松）与 $M/M/1$（几何）之间。

## 5 三模型对照

| 指标 | $M/M/1$ | $M/M/s$ | $M/M/\infty$ |
| --- | --- | --- | --- |
| 稳定性 | $\rho = \lambda/\mu < 1$ | $\rho = \lambda/(s\mu) < 1$ | 恒稳 |
| 稳态人数 | 几何 $(1-\rho)\rho^n$ | 泊松段 + 几何段 | 泊松 $e^{-\rho}\rho^n/n!$ |
| 平均队长 $L$ | $\rho/(1-\rho)$ | 两段求和 | $\rho$ |
| 平均逗留 $W$ | $1/(\mu-\lambda)$ | 公式较繁 | $1/\mu$ |
| 等待概率 | $\rho$ | **Erlang C** | 0 |

**一句话**：$s$ 越大，越接近 $M/M/\infty$ 的「泊松 + 零等待」理想；$s = 1$ 是最差的「全排队」极端。<span class="marginnote">这个对照也解释了云计算的「弹性」价值：<strong>资源越多越接近理想，但成本也越高——容量规划就是在 Erlang C 算出的服务质量与资源成本之间找平衡</strong>。</span>

## 6 M/M/s 术语速查

| 术语 | 记号 | 含义 | 要点 |
| --- | --- | --- | --- |
| 多服务器队列 | $M/M/s$ | 单队列、$s$ 个同质服务员 | 银行/呼叫中心模型 |
| 流量强度 | $\rho = \lambda/(s\mu)$ | 系统利用率 | $\rho < 1$ 稳定 |
| 两段式分布 | 泊松段 + 几何段 | 充裕/拥塞切换 | 临界 $n = s$ |
| Erlang C | $P(\text{等})$ | 全忙时的等待概率 | 座席规划核心 |
| Erlang B | 损失制 | 无等待、直接放弃 | 电话忙线情形 |
| M/M/∞ | $\pi_n = e^{-\rho}\rho^n/n!$ | 无穷服务员 | 理想上限、零等待 |

## 7 小结

- **$M/M/s$**：$\lambda_n = \lambda$，$\mu_n = \min(n,s)\mu$；$\rho = \lambda/(s\mu) < 1$。
- 平稳分布两段式：$n \le s$ 泊松形态，$n \ge s$ 几何尾巴。
- **Erlang C** = 等待概率，呼叫中心座席规划的核心公式。
- **$M/M/\infty$**：稳态人数泊松 $\pi_n = e^{-\rho}\rho^n/n!$，零等待，理想上限。
- 对照：$s = 1$ 最拥挤，$s = \infty$ 最理想，真实系统居中。
- **数值直觉**：利用率 0.9 时 $M/M/1$ 队长 9，$M/M/s$ 大幅缓解——「横向扩展」的排队论依据。

**例（座席规划）**：$\lambda = 10$、$\mu = 6$、$s = 3$：$\rho = 0.556$，Erlang C 得 $P(\text{等}) \approx 0.20$；改 $s = 4$ 则 $\rho = 0.417$、$P(\text{等}) \approx 0.05$——多一个座席，等待概率从 20% 压到 5%。「多一人、降四倍」的非线性改善，正是 SLA 容量规划反复权衡的对象。

在下一节，我们补上排队论最普适的一件武器：**Little 公式与排队系统的性能指标**——它把队长、等待、到达率用一条恒等式焊在一起。
