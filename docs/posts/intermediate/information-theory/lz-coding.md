## 为什么从「不知道概率」开始

Huffman 与算术编码都需要一个**已知的概率模型**——而现实里这个模型几乎总是未知的：一篇文本、一段程序、一个传感器流，谁知道下一个字符的概率？

**通用编码（universal coding）**回答这个问题：不预先知道分布，也能达到与「预知分布」相同的压缩极限。

它的代表就是**Lempel-Ziv（LZ）算法家族**——ZIP、GZIP、PNG、Zstandard 的压缩核心。LZ 的伟大之处在于两点：

1. **在线自适应**：一边读数据一边建立字典，不需要任何概率估计。
2. **渐近最优**：对任何平稳遍历信源，LZ 的压缩率渐近达到熵率——**它自动「学到」了信源的结构**。

这一篇我们讲 LZ77 与 LZ78 两种思路、它们如何工作、以及「重复即信息」这句话为什么成立。<span class="marginnote">Ziv 与 Lempel 1977、1978 年各发一篇论文（即 LZ77/LZ78），奠定了通用编码的基石。Ziv 因此获 1995 年 IEEE 香农奖。LZ 的渐近最优性对「任意平稳遍历信源」成立——它甚至不需要信源是记忆独立的。</span>

## 1 核心直觉：把「重复」写成「指针」

文本、程序、图像里充满了重复：英文里「the」反复出现，代码里「return」反复出现。**重复是冗余最显眼的形式。**

- 如果一段内容「之前已经出现过」，那么不必重新写一遍，只需说「从那个位置开始、长度为 $l$」。
- 这个「位置 + 长度」的指针，通常比原始内容短得多。
- 压缩 = 把重复替换成指针；解压 = 沿指针回溯还原。

**两种实现路线**：

- **LZ77（滑动窗口）**：用「当前位置之前的窗口」当字典，输出「(偏移, 长度, 下一字符)」三元组。
- **LZ78（词典树）**：维护一个全局词典，把新短语编进词典，输出「(词典索引, 下一字符)」二元组。

两者哲学不同：LZ77 用**最近的历史**做参考，LZ78 用**累积的全局词典**做参考。GZIP/DEFLATE 用 LZ77，GIF/早期压缩用 LZ78 变体。<span class="marginnote">LZ77 的窗口是「局部记忆」，LZ78 的词典是「全局记忆」——这是「短时记忆 vs 长时记忆」在压缩里的第一次分岔。现代压缩器（如 Zstandard）多用 LZ77 家族 + 更聪明的后端（Huffman/熵编码），因为它局部性好、实现简单。</span>

## 2 LZ77：滑动窗口与三元组

**算法（编码端）**：

1. 维护一个滑动窗口（已编码的部分）与一个前瞻缓冲（待编码的部分）。
2. 在前瞻缓冲里找「窗口中出现的最长匹配」。找不到就匹配长度为 0。
3. 输出三元组 $(\text{offset}, \text{length}, \text{next char})$：offset 是匹配离窗口末尾的距离，length 是匹配长度，next char 是匹配后的下一个字符。
4. 窗口右移 length + 1，重复。

**示例**：编码 `abracadabrad`（简化版）。

- 前 5 个字符 `abra` 没有匹配，输出 `(0,0,a), (0,0,b), (0,0,r), (0,0,a)` 之类（实际实现用字面量表示）。
- 到第二个 `c` 后出现 `adab`，其中 `ab` 在窗口里匹配，输出 `(3,2,r)`——「从窗口末尾往前 3 个字符、取 2 个（ab）、下一个字符是 r」。
- 解压端按三元组回溯，逐段还原整个串。

**为什么有效**：窗口越大，能捕获的重复越长；三元组里 offset 与 length 的编码长度都是对数级，而匹配内容可以很长——**长匹配时「指针」远短于「内容」**。<span class="marginnote">LZ77 的参数（窗口大小、最小匹配长度）决定压缩率与速度的权衡：窗口越大越能发现远处重复但内存与查找成本高。DEFLATE 用 32KB 窗口；Zstandard 可配到 128MB——这正是「更大的字典 = 更好的压缩」的工程化。</span>

## 3 LZ78：词典与二元组

**算法（编码端）**：

1. 维护一个词典，初始为空。
2. 从当前位置开始，找「词典里能匹配的最长前缀」；词典里没有的字符作为新词条。
3. 输出二元组 $(\text{index}, \text{char})$：index 是已匹配前缀在词典中的编号，char 是下一个新字符。
4. 把「前缀 + 新字符」加入词典，继续。

**示例**：编码 `aababaab`（逐步，简化）：

- `a`：词典空，输出 `(0, a)`，词典添 `1: a`。
- `a` 再次出现：最长匹配是 `1: a`，后面接 `b`，输出 `(1, b)`，词典添 `2: ab`。
- `a`：匹配 `1: a`，接 `b` 又是 `2: ab`，但后面是 `a`，输出 `(2, a)`，词典添 `3: aba`。
- 依此类推。

**解压端**：收到二元组后同步重建词典——**编码端与解码端只靠数据本身就能长出一棵一致的字典树**，无需传输词典。这是 LZ78 最优雅的设计：**词典是「隐式共享」的**。<span class="marginnote">「解码端自己长出同样的词典」是 LZ 家族的灵魂：编码不需要把字典传过去，因为字典完全由已收发的数据决定。这让压缩协议免除了「共享字典」的握手负担，也是它与传统「静态字典压缩」的分水岭。</span>

## 4 公式解析：为什么 LZ 能达到熵率

**定理（LZ 的渐近最优性）**：设信源是平稳遍历的，熵率为 $H$。对任意长度为 $n$ 的序列，LZ 编码的平均码长 $\bar L_n$ 满足

$$
\lim_{n \to \infty} \frac{\bar L_n}{n} = H
$$

**证明的直觉分三步**：

- **第一步，把 LZ 的输出与「短语」对应**：LZ78 把序列切成互不相同的短语（词典词条），短语个数 $N(n)$ 满足 $N(n) \log N(n) \approx n$（总长度被短语「覆盖」）。
- **第二步，把短语与「典型」挂钩**：由 AEP，长为 $l$ 的典型短语只有约 $2^{lH}$ 种。LZ 的词典恰好让每个短语都「新」——所有短语拼起来长度近似「典型计数」所允许的下限。
- **第三步，导出熵率**：每个短语编号约需 $\log N(n)$ 比特，乘上短语个数再除以 $n$，收敛到 $H$。核心关系是 $\frac{N(n)\log N(n)}{n} \to H$。<span class="marginnote">这里的数学本质是「把序列切成<strong>互不重复</strong>的短语」：互不重复 ⇒ 每个短语都可以用「它第一次出现的位置 + 词典编号」代替 ⇒ 码长由短语的个数而非长度决定。Ziv-Lempel 证明的关键，就是估计这个「切分」的效率恰好等于熵率。</span>

**辨析｜易错点：** LZ 的渐近最优性有两个边界要记牢：

- **渐近**：LZ 需要「足够长的序列」才逼近熵率。短序列上，LZ 常不如「用一个合适概率模型的算术编码」。
- **与「预知分布」的区别**：LZ 的极限是「对未知信源的最优」，与「已知分布后最优」在同一量级（熵率），但**常数项**可能差一点；在极端短序列或强相关信源上，精心设计的模型压缩器（如 PPM）可能更优。
- **实现差异**：LZ77 与 LZ78 渐近等价，但有限长度的实际表现、内存占用、速度差异显著——工程选型要看具体数据分布。<span class="marginnote">一个有趣的对照：LZ 家族与「预测编码 + 算术编码」（如 PPM、CM）是现代无损压缩的两大路线。LZ 靠「找重复」，PPM/CM 靠「预测下一个符号的条件概率」——前者工程健壮、速度极快，后者压缩率更高但更慢。Zstandard 的终极形态（Brotli、LZMA）则混合两者。</span>

**与全课程体系的连接：** LZ 的「字典/滑动窗口」在第三级《数据结构》对应「字符串匹配与哈希查找」；在第三级《算法》对应「在线算法与字典结构」。它的「通用性」哲学则通向第十篇的**科尔莫戈罗夫复杂度**——那里把「压缩」抽象成「最短描述」，不再需要概率论。

## 5 LZ 与现代压缩器的对照

把 LZ 家族放进现代压缩器的全景，看它与其他路线的关系。

**DEFLATE（ZIP/GZIP）**：LZ77 + 规范 Huffman——先找重复，再熵编码。

- LZ 处理「重复冗余」，Huffman 处理「概率冗余」。
- 两步各管一段，组合逼近熵率。

**Zstandard / LZMA**：LZ + 更聪明的熵编码（FSE/range coding）+ 更长的窗口。

- 更大的字典 = 捕获更远的重复。
- 现代实现用「哈希链」「后缀数组」加速匹配查找。

**Brotli**：LZ + 预定义字典 + 上下文模型——针对网页文本优化。

**PPM / CM**：预测编码路线——不找重复，而是「预测下一个符号的条件概率」。

- 压缩率通常优于 LZ，但速度慢、内存大。
- 与现代 LZ 的差距越来越小，但仍是「压缩率之王」候选。

**LZ 的独特地位**：工程健壮、速度极快、自适应无需模型——是「默认通用压缩器」。

**「找重复」vs「预测概率」的哲学**：

- LZ：重复是冗余的显眼形式，抓它。
- PPM/CM：概率是冗余的终极度量，算它。
- 两者最终都逼近熵率——只是「抓手」不同。

**一句话**：LZ 是「快而通用」的默认，PPM/CM 是「更慢但更紧」的备选——现代压缩器常在两者间按场景取舍。
## 6 小结

- **通用编码**：不预知分布也能逼近熵率；LZ 家族是代表。
- **LZ77**：滑动窗口找最长匹配，输出「(偏移, 长度, 下一字符)」三元组。
- **LZ78**：全局词典输出「(索引, 下一字符)」，解码端自行长出相同词典。
- **渐近最优**：对平稳遍历信源，$\frac{\bar L_n}{n} \to H$——重复切分 + 典型计数是证明主线。
- **辨析**：LZ 渐近最优但短序列上可能不如「好模型 + 算术编码」；两大路线（重复查找 vs 预测编码）各有取舍。
- LZ 的「最短描述」思想通向科尔莫戈罗夫复杂度。

在下一篇，我们为第四篇收尾：**信源编码定理：平均码长的熵界**——把 Huffman、算术、LZ 三条路线统一到同一个定理之下，正式宣告「熵是压缩的极限」。
