# 霍夫曼编码（Huffman Coding）的构造与最优性证明

<div class="epigraph">
<p>最优的方案常常藏在最朴素的动作里：先把最不重要的两个合并，其余交给归纳。</p>
<footer>—— 大卫 · 霍夫曼（David A. Huffman）</footer>
</div>

<div class="article-byline">
<p>第二级 · 信息论 ｜ Cover &amp; Thomas《Elements of Information Theory》 §5.6–5.8 ｜ 2026-08-07</p>

## 为什么从「真正最优的那个」开始

香农码证明了「存在逼近熵的码」，但它不保证最优。这一篇的主角**霍夫曼编码（Huffman coding）**把「最优」两个字坐实：在所有整数码长的前缀码中，它的平均长度最小。

而且它的构造简单得不可思议：**每次把概率最小的两个符号合并成一个，重复直到只剩一个。**

这个「只顾眼前合并最小的两个」的贪心算法，居然全局最优——这既是信息论里最漂亮的算法之一，也是「贪心偶尔正确」的经典范例。它支撑了 ZIP、JPEG、DEFLATE 等无数压缩标准，是工程与理论双料明星。

这一篇我们走完构造、亲手算一个例子、并给出最优性的归纳证明。<span class="marginnote">Huffman 的最优性是个「反直觉」的结果：合并最小的两个符号看起来只在优化局部，却恰好是全局最优。原因是「最小概率符号在最优码里必然是同一深度（互为兄弟叶子）」——这个结构引理把局部操作与全局目标焊死在一起。</span>

## 1 构造算法：贪心合并

**输入**：符号概率 $p_1, \dots, p_M$。

**算法**：

1. 把所有符号作为单节点叶子，权重为 $p_i$，放进候选集合。
2. **重复**：取出权重最小的两个节点，作为左右孩子合并成一个新节点，权重 = 两者之和；新节点放回候选集合。
3. 直到候选集合只剩一个根节点。
4. 从根到叶子：左枝记 `0`，右枝记 `1`；每个叶子的路径就是它的码字。

**为什么合并最小的两个？** 最优码中，概率最小的两个符号必须位于**同一深度、互为兄弟**（否则可以交换，平均长度更小）。合并它们等于「先把这对最穷的兄弟打包」，把问题缩小一个符号——这正是归纳法的起点。

**示例**：概率 $(0.4, 0.3, 0.2, 0.1)$。

- 合并 0.2 与 0.1 → 0.3。集合：0.4, 0.3, 0.3。
- 合并两个 0.3 → 0.6。集合：0.4, 0.6。
- 合并 0.4 与 0.6 → 1.0。
- 码字：0.4 → `0`，0.3 → `10`，0.2 → `110`，0.1 → `111`。
- 平均长度 $= 0.4\cdot1 + 0.3\cdot2 + 0.2\cdot3 + 0.1\cdot3 = 1.9$，而 $H \approx 1.846$——比香农码的 2.4 更短，且满足 $H \le \bar L < H+1$。<span class="marginnote">注意这个例子中概率最小的两个符号（0.2 与 0.1）的确在最终码树里成为兄弟（`110` 与 `111`），与「结构引理」完全一致。每次合并都「兑现」一次引理，最终整棵树都由引理保证。</span>

## 2 最优性证明：交换引理 + 归纳

**定理**：Huffman 算法给出的前缀码，平均长度不超过任何其他前缀码。

**证明分两段：一个引理 + 一次归纳。**

**引理（最浅层结构）**：存在一个最优前缀码，其中概率最小的两个符号 $a, b$ 互为兄弟叶子、且处于整棵树的最深层。

- 最优码里，若有比 $a$ 更深的符号 $c$，交换 $a$ 与 $c$：$p_a \le p_c$，把大概率符号放到更深位置会让平均长度变小或不变。
- 故最小概率符号一定在最深层；最深层至少两个叶子，另一个必是次小符号 $b$。

**归纳**：合并 $a, b$ 成新符号 $c$（概率 $p_a + p_b$），对 $M-1$ 个符号递归构造。

- 若 $\mathcal{C}'$ 是合并后信源的最优码，把 $c$ 的码字后面接 `0`/`1` 给 $a$、$b$，就得到原信源的一个码。
- 平均长度满足 $\bar L = \bar L' + p_a + p_b$（$a$、$b$ 各比 $c$ 多 1 位，总增量 $p_a + p_b$）。
- 反之，任何原信源的最优码都可以转成合并后的码而不更短（用引理把 $a,b$ 摆成兄弟）。
- 于是「原信源最优」$\iff$「合并后最优」，归纳完成。<span class="marginnote">归纳证明的巧妙在于：它把「$M$ 个符号的最优性」归结为「$M-1$ 个符号的最优性」，每一步都在兑现「最小两个符号是兄弟」这个结构引理。从 1 个符号（平凡最优）一路推上去，Huffman 的全局最优性被彻底坐实。</span>

## 3 公式解析：平均长度与熵的关系

Huffman 码的平均长度满足

$$
H(X) \le \bar L_{\text{Huffman}} < H(X) + 1
$$

- **左边 $H \le \bar L$**：由上一节「任何前缀码平均长度 ≥ 熵」直接得到——熵是全局下界，谁也无法突破。
- **右边 $\bar L < H + 1$**：Huffman 码每层合并都对应一个二元决策，把「码长 ≥ 熵」的间隙控制在 1 比特以内。直观上，码长 $l_i$ 与 $\log\frac{1}{p_i}$ 最多差 1。
- **改进空间**：对**符号块**编码（一次编码 $n$ 个符号），平均每符号码长 $\frac{1}{n}\bar L^{(n)}$ 落在 $[H, H + \frac{1}{n})$ 内——**分块越粗，越接近熵**。这就是信源编码定理（本专题倒数几篇）的构造性证明。

**一个重要的量**：冗余 $\rho = \bar L - H$。

- 均匀分布的 $M$ 符号信源，$H = \log M$，而 Huffman 给每个符号 $\lceil\log M\rceil$ 位，冗余 $< 1$ 比特。
- 分布「偏斜」时，Huffman 能压得很狠；分布均匀时，几乎无冗余可压。
- **冗余是「整数化」与「概率分布」共同决定的**，不是算法缺陷——任意整数码都无法消除它，只能靠分块摊薄。<span class="marginnote">冗余的上下界也有理论：对最优整数码，$\bar L \ge H$，且可以构造 $H + \frac1M$ 以内的紧例子。Galil 等人的工作还给出了冗余 $< \min(1, p_{\min} + 0.086)$ 的精细界——说明概率最小符号的权重决定了冗余能压到多低。</span>

## 4 辨析：Huffman 的边界与变体

**辨析｜易错点：** Huffman 最优是「整数码长、前缀码、无记忆信源」意义下的最优，换场景结论就变。

- **D 元字母表**：每次合并 D 个最小的（不足时补虚节点），算法与证明原样推广。JPEG 里的 Huffman 用的就是多元字母表。
- **符号间有记忆**：Huffman 对独立符号最优；对相关信源，需先分块或先用预测，把「记忆」转成概率差异。这正是后续 LZ 与算术编码的用武之地。
- **动态/自适应场景**：Huffman 需要静态概率表；实时压缩用自适应 Huffman（动态更新树）或算术编码替代。
- **平局处理**：合并时概率相等，选谁当左右兄弟不影响平均长度，但可能改变个别码字——解码时必须与编码器用**完全相同的平局规则**，否则解码出错。<span class="marginnote">平局规则是工程上的隐藏地雷：编码端和解码端必须约定「相等时先取谁」，一旦不一致，整棵码树就错位。规范的实现（如 DEFLATE）会把这一规则写死，这也是「规范 Huffman 码（canonical Huffman）」存在的原因——它只存码长、按序重排码字，省去整树传输。</span>

**与全课程体系的连接：** Huffman 树在第三级《数据结构》是「最优二叉树（WPL 最小）」的经典案例；在第三级《算法》里是「贪心算法正确性证明」的教材级例子（交换论证）。信息论给它提供了「为什么平均码长接近熵」的终极解释——一棵树，三处学问。

## 5 Huffman 码的变体与工程实现

Huffman 编码在理论上是「整数码最优」，工程上还有一批变体。

**自适应 Huffman（adaptive Huffman）**：不预先知道概率，边编码边更新码树。

- 编码与解码同步维护一棵动态树。
- 每个符号到来时更新频率、必要时重构树。
- 用于流式压缩（如早期的 GIF 变体）。

**规范 Huffman 码（canonical Huffman）**：只传输「码长表」，接收端按长度重排码字。

- 无需传输整棵树，只传码长数组。
- DEFLATE（ZIP/GZIP）用它——大幅降低「树的传输开销」。

**多元 Huffman（$D$ 元）**：每次合并 $D$ 个最小的，JPEG 的 DC/AC 系数编码用它。

**与算术编码的关系**：Huffman 是「整数码」的最优；算术编码是「按符号分比特」的逼近熵——两者是「离散最优」与「连续逼近」的两级。

**Huffman 的局限**：概率为极端值（0.99/0.01）时，整数码浪费明显——这正是算术编码登场的地方。

**工程选择的准则**：

- 概率表小、静态：Huffman 够用且快。
- 概率极端、自适应：算术编码更优。
- 树太大：规范 Huffman 省传输。

**一句话**：Huffman 是「快而稳」的默认选择，变体解决「树传输」「自适应」「多元」等工程细节——它是压缩工具箱里最常用的一把。
## 6 小结

- **Huffman 构造**：反复合并概率最小的两个符号，直到一棵树；路径即码字。
- **最优性**：结构引理（最小两个符号必为最深层兄弟）+ 归纳 = 全局最优前缀码。
- **平均长度**：$H \le \bar L < H + 1$；分块编码可把每符号冗余压到 $\frac{1}{n}$。
- 冗余 $\rho = \bar L - H$ 来自整数化，任何整数码都无法消除。
- **辨析**：Huffman 最优的适用范围是「整数码长、前缀码、无记忆」；D 元、自适应、动态场景各有变体。
- 平局规则必须编码解码一致，工程上用规范 Huffman 码规避。

在下一篇，我们走向「不按符号、按整段」的编码：**算术编码（Arithmetic Coding）的原理与实现**——把整条序列编成一个 $[0,1)$ 里的数，平均码长可以任意逼近熵。
