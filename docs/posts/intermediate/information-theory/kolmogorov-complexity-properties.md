# 科尔莫戈罗夫复杂度的性质与不可计算性

<div class="epigraph">

## 为什么从「算不出来的复杂度」开始

上一篇定义了 $K(x)$——生成 $x$ 的最短程序长度。它是个良定义的数：最小程序一定存在（自然数集合有最小值）。

但有一个令人不安的事实：**没有任何算法能算出 $K(x)$。**

这不是「暂时没找到好算法」，而是「原则上不可能」——与停机问题同等级别的不可判定性。这一篇我们证明它、并趁机梳理 $K$ 的一批「算得出」的性质（虽然算不出值，但能证明关于它的定理）。<span class="marginnote">「$K$ 不可计算」由 Kolmogorov 与 Chaitin 独立发现，证明用的是「最小不可描述整数」悖论（Berry 悖论的变体）——「用少于 $n$ 个词描述的最小整数」这句话自指矛盾。$K$ 的不可计算性，是「自指」在信息论里的又一次现形。</span>

## 1 不可计算性的证明：最小不可描述数

**定理**：$K(x)$ 作为 $x$ 的函数**不可计算**。

**证明（反证 + Berry 悖论）**：假设存在算法 $\mathcal{K}$ 能计算 $K(x)$。

- 用 $\mathcal{K}$ 构造程序 $P$：**枚举所有字符串 $x$，找出第一个满足 $K(x) > N$ 的 $x$，输出它**（$N$ 是 $P$ 的长度乘一个大常数）。
- $P$ 的长度固定（约 $\log N$ + 常数），但它输出的 $x$ 满足 $K(x) > N$。
- 矛盾：$P$ 本身就是「长度 $< N$ 却能生成 $x$ 的程序」，故 $K(x) \le |P| < N$，与 $K(x) > N$ 矛盾。

**核心悖论**：「第一个复杂度超过 $N$ 的字符串」这句话本身太短——它自指地压过了 $N$。这与「这个数不能用少于一百个汉字描述」悖论同构。<span class="marginnote">「$P$ 能生成 $x$ 且 $|P| < N$」是矛盾的核心：$P$ 用「搜索」代替「直接描述」，用「枚举」获得了一个 $K$ 大于自身长度的对象。这个「搜索型短程序」就是自指矛盾的具体载体——它证明「计算 $K$」会立刻撞出比自身更短的描述。</span>

**推论**：不仅 $K$ 不可计算，连「近似计算 $K$」都不可行——任何能给出 $K(x)$ 的「足够好」上下界的算法都不存在。$K$ 是理论上完美、算法上不可及的量。

## 2 但性质可以证明：$K$ 的「可证明」面

不可计算不意味着「一无所知」。$K$ 的很多**性质**是可以用数学证明的：

**次可加性（subadditivity）**：$K(x, y) \le K(x) + K(y) + c$——把两个程序拼接，可同时生成两者。

**上界**：$K(x) \le |x| + c$；$K(x \mid y) \le K(x) + c$——条件不比无条件更容易描述太多。

**对称性**：$K(x,y) \approx K(x) + K(y \mid x) \approx K(y) + K(x \mid y)$（差对数项）——「联合描述 = 一个 + 条件另一个」。

**信息不增**：$K(g(x)) \le K(x) + c_g$——任何确定性处理（函数 $g$）都不能增加复杂度（处理不创造信息，只可能损失）。

**绝大多数串的复杂度**：长度为 $n$ 的串中，至少 $2^n(1 - 2^{-k})$ 个满足 $K(x) > n - k$——**绝大多数串几乎不可压缩**。<span class="marginnote">「$K(g(x)) \le K(x)$」是算法信息论的「数据处理不等式」——与 Shannon 的 DPI 遥相呼应：确定性处理不增加信息。两个世界（概率 / 算法）在「处理不创造信息」上又一次握手。</span>

## 3 公式解析：$K(x,y)$ 的链式结构

把「联合 vs 条件」的关系精确化：

$$
K(x, y) \le K(x) + K(y \mid x) + c
$$

- **$K(x,y)$**：同时描述两者的最短程序。
- **$K(x)$**：描述 $x$ 的最短程序。
- **$K(y \mid x)$**：**给定 $x$ 后**描述 $y$ 的最短程序。
- **直觉**：先描述 $x$（花 $K(x)$），再「在已知 $x$ 的前提下」描述 $y$（花 $K(y|x)$）——拼接成联合描述。反向不等式也成立（差一个对数项），所以「联合 ≈ 一个 + 条件另一个」在量级上精确。

**算法互信息**：定义 $I(x;y) = K(x) + K(y) - K(x,y)$。

- 由链式结构，$I(x;y) \approx K(x) - K(x \mid y)$——「$y$ 解释 $x$ 省下的比特」。
- 它度量「两条字符串共享多少结构」——Shannon 互信息的算法对应，不需要分布。

**与 Shannon 互信息的对照**：

| | Shannon $I(X;Y)$ | 算法 $I(x;y)$ |
| --- | --- | --- |
| 对象 | 随机变量（分布） | 具体字符串 |
| 定义 | $H(X) + H(Y) - H(X,Y)$ | $K(x) + K(y) - K(x,y)$ |
| 可计算 | 已知分布时可算 | 不可计算 |
| 意义 | 平均共享信息 | 具体共享结构 |

两者同构、互补：Shannon 版管「平均」，算法版管「具体」。<span class="marginnote">「$I(x;y)$ 不需要分布」是算法互信息最独特的价值：它可以度量「这两篇论文共享多少结构」「这段 DNA 与那段 DNA 的关联」，而不需要假设它们服从某分布。代价是它不可计算——所以实际中用「压缩率」近似它（压缩后长度 ≈ $K$ 的上界）。</span>

## 4 不可计算性的后果与工程应对

$K$ 不可计算，但工程并没有因此瘫痪——因为实践只用到它的**上界**：

- **压缩器近似**：$K(x)$ 的任何「可计算的描述」都给出一个上界。压缩算法（LZ、PPM）的输出长度是 $K(x)$ 的一个**可行上界**——「ZIP 压到 $L$ 比特」意味着 $K(x) \le L + c$。
- **MDL 的应用**：模型选择不追求「精确 $K$」，而是「最小化可计算的上界」——比较不同模型的「压缩后总长度」，选最短的。
- **$K$ 的角色**：它提供「极限」与「直觉」，像信息论里的 $H$——$H$ 也常常不可算（未知分布），但它是理论的坐标原点。

**辨析｜易错点：** 三个容易误解的点：

- **「不可计算」≠「$K(x)$ 不是数」**：$K(x)$ 是良定义的整数（最短程序长度），只是无法用算法求出。
- **「不可计算」≠「不能近似」**：可以高效地得到上界（压缩）、甚至某些串的精确 $K$（穷举小范围），只是「对所有串的算法」不存在。
- **别混淆「$K(x)$ 不可计算」与「熵不可计算」**：熵在分布已知时可算，$K$ 即使已知一切（除了程序）也不可算——两者「不可算」的来源完全不同。<span class="marginnote">「$K$ 不可计算」与「$H$ 需要未知分布」是两种不同的「难」：$H$ 难在「不知道分布」，$K$ 难在「就算知道一切也停不下来」。前者是统计困难，后者是逻辑不可能。用「压缩上界」绕开后者，是工程的全部技巧。</span>

**与全课程体系的连接：** 不可计算性在《计算理论》里是「停机问题、Rice 定理」的亲戚；在《算法》里对应「不可判定问题的复杂度分析」；在《机器学习》里，$K$ 的不可计算性是「MDL 为什么用可计算上界」的原因——理论给方向，工程给近似。

## 5 复杂度的排序与比较

虽然 $K(x)$ 不可计算，但「比较两个串的复杂度」仍有可用的工具。

**可计算的比较**：用压缩器比较——$K$ 的上界。

- 压缩长度短 ⇒ 复杂度「至少不大于」压缩长度。
- 两个串压缩后的长度之比，是「复杂度之比」的可行近似。

**「$K(x)$ 与 $K(y)$ 谁大」原则上可判定吗**？——不可判定，但实践中几乎总能给出可信答案。

**为什么实践可行**：真实数据的「最短描述」通常被压缩器捕捉到大部分——上界够紧，足以排序。

**对机器学习的意义**：「数据有多复杂」的排序（用压缩率）可以用来：

- 检测离群点（复杂度过高的样本）。
- 评估数据集的「内在维度」。
- 挑选「更简单」的模型（MDL）。

**「$K$ 的不可计算性」的哲学后果**：它提醒我们「复杂度」是概念上清晰、算法上不可及的量——理论用它，工程用上界。

**一句话**：$K$ 的值不可算，但 $K$ 的排序与上界实践可用——「用压缩器比较复杂度」是算法信息论在工程里的日常工具。
## 6 小结

- **$K$ 不可计算**：Berry 悖论证明——「找复杂度 $> N$ 的串」的程序自身太短，自指矛盾。
- 不可计算 ≠ 一无所知：次可加性、上界、对称性、信息不增、绝大多数串不可压缩——都可证明。
- **链式结构**：$K(x,y) \le K(x) + K(y|x) + c$；算法互信息 $I(x;y) = K(x)+K(y)-K(x,y)$ 不需分布。
- 与 Shannon 互信息同构互补：一个管平均、一个管具体。
- **工程应对**：压缩器给上界，MDL 用可计算上界做模型选择。
- **辨析**：不可计算 ≠ 不是数；不可计算 ≠ 不能近似；$K$ 的难与 $H$ 的难来源不同。

在下一篇，我们把算法与概率两个世界接起来：**科尔莫戈罗夫复杂度与熵的联系**——$K$ 与 $nH$ 在典型意义下如何相等。
