## 为什么最后一节谈「怎么评价」

启发式算法（退火、遗传、禁忌、粒子群）没有收敛保证——那么「哪个更好」只能靠**实验**回答。但实验做得好不好，直接决定结论可不可信：跑一次说「我的算法最好」是典型的统计陷阱。本节给出评价启发式算法的完整方法论：**理论边界（NFL 定理）、实验协议（多次运行、统计检验）、以及「何时该用哪个方法」的决策树**。<span class="marginnote">这是本书的收尾之节，也是「从理论走向实践」的最后一课：前九篇学的是「有保证的算法」，这篇学的是「没保证但有用的算法」——而学会「诚实地评价没有保证的东西」，是从学者变成工程师的分水岭。</span>

在「从极限到大模型」的知识地图里，本节是第十一篇的收官：前面五篇分别讲了退火、遗传、禁忌、粒子群四种元启发式，本节回答最关键的问题——「既然都没保证，凭什么说这个比那个好？」没有本节的方法论，前面四种算法就只是「好玩的想法」；有了它，它们才变成「可以被审慎对待的工程工具」。这也是全专题收尾前的一次「方法自省」。

## 1 收敛保证：启发式算法的「诚实」边界

把各类算法的保证做一次总盘点：

| 算法 | 收敛保证 | 条件 |
| --- | --- | --- |
| 梯度下降 | 全局最优（凸） | 凸 + 光滑 |
| 内点法 | 多项式时间 | 凸 + 品性 |
| 分支定界 | 全局最优（有限） | 指数时间 |
| 模拟退火 | 几乎必然全局 | 对数降温（不可实用） |
| 遗传 / 禁忌 / PSO | 无 | —— |

**诚实的定位**：启发式算法**不保证最优、不保证多项式时间、不保证每次结果一致**——它们提供的是「在有限预算内，以大概率找到足够好的解」。<span class="marginnote">这个「诚实」不是缺陷，而是问题本质决定的：NP-hard 问题在理论上就不可能有「多项式 + 全局 + 确定性」的算法（除非 P=NP）。启发式算法是「在不可能性边界内，用工程智慧换实践可行」。<strong>评价启发式算法的第一步，是接受它没有「证明」——只有「证据」</strong>。</span>

**把「保证」从强到弱排一遍**，你会得到一条清晰的谱系：

- **确定性全局保证**：凸优化、线性规划、内点法——「给出最优，且是多项式时间」。
- **有限时间全局保证**：分支定界、穷举——「一定给最优，但可能指数时间」。
- **概率全局保证**：模拟退火（对数降温）——「几乎必然收敛到全局」，但降温太慢，不可实用。
- **统计/经验保证**：遗传、禁忌、PSO——「在特定问题上反复表现好」，无普适承诺。

理解这条谱系的价值在于：**每一步「降级」都有明确代价，也都换来更强的实用性**。评价一个启发式算法时，问的不是「它有保证吗」（答案总是「没有」），而是「它在哪些问题上、以多大代价、多可靠地有效」。

## 2 NFL 定理：为什么「没有最好算法」

**无免费午餐定理（No Free Lunch, NFL, Wolpert–Macready 1997）**：对所有「有限搜索空间、目标函数均匀随机」的问题，**任何两个算法的平均表现完全相同**。

直觉：如果算法 A 在某类函数上更好，必然在另一类函数上更差——「免费午餐」（对一切问题都好）不存在。<span class="marginnote">NFL 定理的深刻含义：<strong>「哪个算法最好」取决于「你面对的问题分布」</strong>——没有脱离问题域的普适冠军。这正是优化这门学科「算法多样性」的根本原因：不同算法适配不同景观（平滑的、多峰的、离散的）。工程含义：<strong>选算法必须基于对问题的理解</strong>（连续/离散？光滑/黑盒？维度？预算？），而不是迷信「某某算法最牛」。</span>但 NFL 是「均匀分布」下的平均结论——**真实问题并非均匀分布**（常有结构、平滑、相关性），所以实践中「针对问题族调算法」依然有效。

**NFL 的一个常见误读**：它并不否定「遗传算法在工程问题上普遍好用」——因为工程问题不是「均匀随机函数」，而是「有结构、有平滑性、有相关性的函数族」。NFL 说的是「若把全世界所有可能的函数都看成等可能，任何算法都一样」；真实世界的函数分布**强烈偏向**结构化函数，于是「针对结构的算法」（如利用局部性的局部搜索、利用平滑性的梯度法）在真实分布上显著胜出。**所以 NFL 不是「别用启发式」的借口，而是「用问题结构定制算法」的哲学依据**。<span class="marginnote">这也解释了为什么「为特定问题设计专用启发式」几乎总是吊打「通用启发式」：你注入的问题结构越多，离「均匀分布」越远，算法的相对优势越大。<strong>评价算法时，永远带着你面对的问题分布来谈</strong>。</span>

## 3 实验协议：怎样比较才是可信的

评价启发式算法的标准实验协议（避免最常见的统计陷阱）：

**多次独立运行**：启发式有随机性，**跑 1 次没有意义**——至少 10–30 次独立运行（不同随机种子）。
**报告分布而非单点**：报均值、标准差、中位数、最好/最差——看「稳定性」而不只看「最好的一次」。
**相同预算**：给所有算法**相同的函数求值次数**（或相同时间）——否则「跑得更久的赢」不说明算法好。
**统计检验**：用 Wilcoxon 秩和检验 / 配对 t 检验判断「差异显著」——别用肉眼。
**多类测试函数**：在多种景观（球函数、Rastrigin 多峰、Ackley）上测试，别只挑对自己有利的。<span class="marginnote">评价启发式的「黄金标准」：<strong>在公平预算下、多次运行、统计检验、多测试集、报分布而非极值</strong>。初学者的典型错误：跑一次说「我的算法更优」、或只报「最好的一次」、或给己方算法更多求值预算。<strong>实验方法论的好坏，往往比算法本身更能决定「结论是否成立」。</strong></span>

**一个「坏实验 → 好实验」的对照**。**坏实验**：调好自己算法的 20 组参数，挑最好的一组；在 5 个「碰巧适合自己的问题」上各跑一次；报告「我的算法找到了 $f=10^{-8}$，而 PSO 只有 $10^{-3}$」。问题在哪？参数挑过的（过拟合）、测试集挑过的（selection bias）、只跑一次（随机波动没控制）、且没给 PSO 调参（不公平）。**好实验**：所有算法都用默认参数（或都花同样的调参预算）、在 20 个涵盖各种景观的 benchmark 上、各跑 30 次、报告均值 ± 标准差、用 Wilcoxon 检验判定差异、并给出计算预算。<span class="marginnote">业界标准 benchmark 套件（如 BBOB/COCO、CEC 系列）就是为「公平评价」而生的：统一函数、统一初始条件、统一停止准则。<strong>除非你的论文/报告用了公认 benchmark，否则「我的算法好」几乎不值得相信</strong>。</span>

## 4 公式解析：NFL 定理的直觉证明

把 NFL 的核心论证压缩成三步，看懂「为什么没有免费午餐」：

**第一步，配对观察**：对任意两个算法 $A, B$，把目标函数 $f$ 与它的「补」$g = c - f$（在有限搜索空间上的常数补）配对。算法在 $f$ 上的表现与在 $g$ 上的表现**互补**。
**第二步，均匀平均**：当目标函数从所有函数中均匀抽取时，$f$ 与 $g$ 等可能——于是 $A$ 在 $f$ 上的收益被它在 $g$ 上的损失抵消。
**第三步，对称性**：对所有算法做同样的对称论证，得到「平均表现全等」——**任何算法的平均收益都相同**。
**第四步，读出含义**：脱离问题分布谈「最优算法」是无意义的；**算法的价值是「相对特定问题族」的**。<span class="marginnote">NFL 的数学形式：$\sum_f P(\text{观察序列} \mid f, A) = \sum_f P(\text{观察序列} \mid f, B)$——对所有 $f$ 求和后，$A$ 与 $B$ 的「表现之和」相等。它不否定「算法 A 在真实问题上更好」——只否定「A 在一切问题上更好」。<strong>工程师的正确读法：算法选择 = 问题匹配，不是信仰之争。</strong></span>

## 5 选算法的决策树

| 问题特征 | 推荐算法 | 理由 |
| --- | --- | --- |
| 凸、可微 | 梯度/牛顿/内点 | 有全局保证 |
| 小规模离散 | 分支定界 | 精确 |
| 大规模黑盒连续 | PSO / 退火 | 简单稳健 |
| 离散组合 + 邻域清晰 | 禁忌搜索 | 记忆驱动 |
| 多模态 + 无梯度 | 遗传 / 多起点局部 | 种群探索 |
| 数据海量 + 非凸 | SGD / Adam | 随机梯度 |

**辨析｜易错点：**其一，**先查凸性/结构再上启发式**——能用精确/凸算法就别用启发式（这是本书反复强调的）；其二，启发式的「参数调优」容易**过拟合测试集**——用独立测试集验证；其三，**比较算法时预算必须公平**（NFL 的最直接工程教训）；其四，别把「一次跑出来的好结果」当结论——多次运行 + 统计检验；其五，**别只看收敛曲线的终点**——算法 A 终点好但前期差、或只在特定预算下好，都要如实呈现；其六，**随机种子要交代**——复现性是评价可信度的底线，报告里写明种子与实现细节（初版可复现实验是「从极限到大模型」全系列强调的科学素养）。<span class="marginnote">在「从极限到大模型」里，这套评价方法论直接适用于：比较不同优化器（Adam vs SGD vs LBFGS）、不同学习率调度、不同超参数搜索策略——「公平预算 + 多次运行 + 统计检验」是它们共同的标准。<strong>学会诚实地评价算法，是优化这门学科通往工程实践的最后一课。</strong></span>

**一个决策树的走查**。假设你要选一个算法调一个「有 50 个连续参数、目标不可微、每次求值要跑 2 秒仿真」的黑盒问题：

- **第一步**：目标不可微 → 梯度类算法出局。
- **第二步**：连续参数空间、黑盒 → 属于「大规模黑盒连续」，PSO / 退火 / CMA-ES 进入候选。
- **第三步**：求值昂贵（2 秒/次）→ 预算有限，选「每轮求值信息量最大」的——CMA-ES（协方差适应）通常比朴素的 PSO 更省求值次数。
- **第四步**：跑 30 次独立试验、报均值与最好值、与「多起点随机」基线对照——确认它真的优于「随机 + 局部」这个最便宜基线。

这四步就把「决策树 + 实验协议」用在了实处。<span class="marginnote">一个常被忽视的基线：<strong>「多起点随机 + 简单局部搜索」往往已经够好</strong>。先跑它，再决定要不要上复杂启发式——这是成本最低、最该先试的一步。</span>

**术语速查：**

| 术语 | 含义 | 一句话记忆 |
| --- | --- | --- |
| 收敛保证 | 算法给出最优/近似最优的证明性承诺 | 理论证书 |
| 证据 evidence | 实验观察到的表现 | 经验支持 |
| NFL 定理 | 均匀分布下所有算法平均等优 | 没有普适冠军 |
| 预算 budget | 函数求值次数 / 时间上限 | 公平的天平 |
| 统计检验 | 判断差异是否显著（Wilcoxon/t 检验） | 别用肉眼 |
| benchmark | 公认测试函数/实例集 | 统一考场 |
| 多次独立运行 | 不同随机种子的重复实验 | 看分布 |
| 复现性 | 他人能按你的描述重现结果 | 科学底线 |

**一个「算法之外」的提醒**：启发式评价里最容易翻车的不是统计，而是**目标函数实现错误**——一个负号、一个边界条件错了，所有结论作废。跑 benchmark 前先对已知最优的简单函数（如球函数 $f = \sum x_i^2$，最优值 0）做 sanity check：算法必须能「合理地」逼近已知最优。这个「先验证实现、再做对比」的习惯，在工业界是保命级别的。

## 6 小结

- **诚实边界**：启发式无收敛保证——它们给「证据」而非「证明」。
- **NFL 定理**：均匀问题分布下所有算法平均表现相同——「最好算法」脱离问题域无意义。
- **实验协议**：多次运行、报分布、公平预算、统计检验、多测试集。
- **选算法决策树**：凸 → 精确；小规模 → 分支定界；黑盒连续 → PSO/退火；组合 → 禁忌；多模态 → 遗传。
- **坏实验警示**：调参选优 + 挑测试集 + 只跑一次 + 不公平预算 = 不可信结论；sanity check 目标函数实现是第一步。
- **决策先做基线**：多起点随机 + 局部搜索往往已经够好，先跑它再上复杂启发式。
- **收尾**：优化 = 理论保证 + 工程智慧——全书到此，愿你既会证明、也会评价。

**一句话送给即将离开本篇的你**：优化不是「背算法」，而是「读问题」——结构决定方法，预算决定策略，统计决定信心。把这条方法论带走，无论遇到凸还是不凸、连续还是离散、有公式还是黑盒，你都能像一个工程师那样，先分类、再选型、后验证。

至此，本专题从凸集与凸函数出发，历经凸优化、对偶、线性规划、无约束与约束优化、二次规划、整数规划、多目标、随机优化，直至全局优化与启发式算法——「最优化理论」的全部主题规划已写完。恭喜你走完这条路：从极限到大模型，优化的语言你已备齐。
