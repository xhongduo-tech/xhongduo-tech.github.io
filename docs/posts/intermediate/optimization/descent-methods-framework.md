## 为什么「算法」可以被统一成一个框架

梯度下降、牛顿法、共轭梯度、拟牛顿……表面看是完全不同的算法，骨子里却是同一个模板：**当前点 $x_k$ → 选一个下降方向 $\Delta x_k$ → 沿它走一步（步长 $t_k$）→ 到 $x_{k+1}$，重复直到收敛**。本节把这条模板立起来，再把「方向怎么选、步长怎么定、何时停」三个组件逐一拆解。<span class="marginnote">框架的价值在于：它把「设计算法」变成「在框架里填三个参数」——方向、步长、判停。后面每一节新算法，都可以看作「在方向这个组件上做了不同的选择」。理解了框架，读任何优化算法的代码都像读同一篇文章的变体。</span>

## 1 一般下降算法

**下降算法（descent method）**的通用格式是

$$
x_{k+1} = x_k + t_k \Delta x_k
$$

其中 $\Delta x_k$ 是**搜索方向（search direction）**，$t_k > 0$ 是**步长（step size）**。算法的全部要求只有一条：

**$f$ 沿方向下降**：$\nabla f(x_k)^T \Delta x_k < 0$（当 $\Delta x_k \ne 0$ 时）。

满足此条件的方向称为**下降方向（descent direction）**——它与负梯度方向成锐角，走一小步函数必降。<span class="marginnote">注意这是<strong>必要条件</strong>而非充分：方向是下降方向只保证「足够小的步长下降」，不代表「任意步长都下降」。大步长可能跨过谷底跑到对面斜坡上（过冲），所以「定步长」才成为一门独立的学问（下一节线搜索）。</span>整个算法框架因此是：

```
给定初始点 x₀，k ← 0
repeat:
    1. 选下降方向 Δxₖ，满足 ∇f(xₖ)ᵀΔxₖ < 0
    2. 线搜索定步长 tₖ > 0
    3. 更新 xₖ₊₁ ← xₖ + tₖ·Δxₖ
    4. k ← k + 1
until ‖∇f(xₖ)‖₂ ≤ ε   （或达到迭代上限）
```

## 2 终止条件与收敛性度量

**终止条件（stopping criterion）**：最常见的度量是梯度范数

$$
\| \nabla f(x) \|_2 \le \epsilon
$$

这是「一阶必要条件 $\nabla f = 0$ 的数值近似」。为什么用梯度而不是函数值下降量？因为**梯度是「离最优还有多远」的普适标尺**——对二次函数，$\|\nabla f\|$ 与到最优点的距离成正比；对一般函数，它也给出「一阶最优性残差」。<span class="marginnote">工程里更稳的判停常是复合条件：梯度范数 + 连续几轮函数值下降量 < 阈值 + 步长太小。单纯用函数值下降量会误判「平原」为「收敛」，单纯用梯度会在高度病态问题上要求过多迭代。真实求解器会把几个信号加权组合。</span>**收敛速度**的度量则分三档：

**线性收敛**：$\|x_{k+1}-x^*\| \le c\|x_k-x^*\|$（$c<1$）——每步缩小固定比例。
**超线性收敛**：$\lim \|x_{k+1}-x^*\|/\|x_k-x^*\| = 0$——比线性快。
**二次收敛**：$\|x_{k+1}-x^*\| \le c\|x_k-x^*\|^2$——误差平方级缩小，位数翻倍。

**收敛速率是选择算法的核心指标**：梯度下降通常线性，牛顿法局部二次，拟牛顿超线性——各章的收敛性分析都围绕这三档展开。

## 3 方向选择的谱系

所有无约束算法在方向选择上排成一条「信息量递增」的谱：

| 算法 | 方向 $\Delta x_k$ | 用到的信息 | 收敛速率 |
| --- | --- | --- | --- |
| 最速下降 | $-\nabla f$ | 一阶 | 线性（条件数相关） |
| 共轭梯度 | 修正的负梯度 | 一阶 + 历史 | 线性（更优常数） |
| 拟牛顿（DFP/BFGS） | $-B_k^{-1}\nabla f$ | 一阶 + 近似二阶 | 超线性 |
| 牛顿法 | $-(\nabla^2 f)^{-1}\nabla f$ | 二阶 | 二次 |

**谱的两端**：最速下降只靠梯度、每步最省；牛顿法用完整 Hessian、每步最贵但收敛最快。<span class="marginnote">工程里的核心权衡就是「每步代价 vs 收敛速率」：问题很大、Hessian 算不起 → 用一阶方法（深度学习几乎都是这个阵营）；问题规模适中、需要高精度 → 用拟牛顿或牛顿法。这张谱系图是算法选择的决策树。</span>共轭梯度与拟牛顿是「中间路线」：用一阶信息 + 巧妙的历史构造，逼近二阶方法的收敛速率而不付 Hessian 的代价。

## 4 公式解析：下降条件的几何含义

把「$\nabla f^T \Delta x < 0$」读成几何与代数两层。设 $\Delta x$ 与 $-\nabla f(x_k)$ 的夹角为 $\theta$，则

$$
\nabla f(x_k)^T \Delta x = \|\nabla f\|_2 \|\Delta x\|_2 \cos\theta
$$

- **第一步，代数**：条件 $\nabla f^T\Delta x < 0$ ⟺ $\cos\theta < 0$ ⟺ $\theta > 90°$——**方向必须与负梯度成钝角**，即「偏向下坡」。
- **第二步，几何**：$f$ 在 $x_k$ 处的等高面法向是 $\nabla f$；$\Delta x$ 与法向成钝角，意味着「穿出等高面向外走」——正指向函数值更低的一侧。
- **第三步，一阶展开**：$f(x_k + t\Delta x) = f(x_k) + t\nabla f^T\Delta x + o(t)$，$t$ 足够小时首项主导，符号由 $\nabla f^T\Delta x$ 决定——负即下降。
- **第四步，极端情形**：$\theta = 180°$（沿 $- \nabla f$）是**最陡下降方向**——单位步长下降最多；$\theta = 90°$（垂直于梯度）沿等高面走，一阶不降不升——二阶效应决定。

**条件 $\nabla f^T\Delta x < 0$ 是算法「不犯错」的底线**：任何合格的搜索方向都必须先通过这个检查。

## 5 框架的工程落地

把框架付诸实践时，三个组件的分工清晰化：

- **方向组件**：决定「往哪走」。梯度、牛顿方向、拟牛顿方向各有成本与速率，见上表。
- **步长组件**：决定「走多远」。下一节的线搜索（Armijo、Wolfe）负责在「太小太慢」与「太大过冲」之间取平衡。
- **判停组件**：梯度范数 + 函数值变化 + 迭代上限的组合，决定「何时认为到站」。

**辨析｜易错点：**最常见的框架级错误有两个：其一，只降函数值而不检查梯度——在平原上可能「看起来在降」却离最优很远；其二，步长恒定时不做自适应——固定步长要么太慢（欠拟合收敛）要么震荡（过冲）。**框架的三个组件都要「活」**：方向要下降、步长要线搜索、判停要梯度——缺一不可。

## 6 一个数值例子：三组件怎么咬合

用一个一维函数 $f(x) = x^2$ 把框架走一遍，看方向、步长、判停如何配合。梯度 $\nabla f = 2x$，从 $x_0 = 1$ 出发。

**方向**：取最速下降方向 $\Delta x_0 = -\nabla f(x_0) = -2$。
**步长**：沿 $f(1 - 2t) = (1-2t)^2$ 做精确线搜索，最小化得 $t_0 = 1/2$。
**更新**：$x_1 = 1 + \frac12(-2) = 0$。
**判停**：$\|\nabla f(x_1)\| = 0 \le \epsilon$——一步收敛。

这个例子太顺，因为 $x^2$ 是凸二次函数、精确线搜索一步到位。换成 $f(x) = x^4$（梯度 $4x^3$，从 $x_0 = 1$ 出发）：

$$
f(1 - 4t) = (1-4t)^4, \qquad t_0 = \frac14, \qquad x_1 = 1 - 1 = 0
$$

同样一步到 0。**但若把起点换成 $x_0 = 1.0001$**，梯度不会恰好为 0，框架就得靠「$\|\nabla f\| \le \epsilon$」判停——这才是真实世界的样子：判停不是「恰好到最优点」，而是「够近就行」。

**框架三组件在这个例子里的分工**：方向给出「向下的斜率」，步长决定「走多远恰好到谷底」，判停回答「够不够好」。三者缺一，算法就只剩半条命——后面每一章都在深化这三个组件中的一个：线搜索管步长，各种「新方法」都在换方向，收敛性分析全部在谈判停的可靠性。

## 7 小结

- **统一模板**：$x_{k+1} = x_k + t_k\Delta x_k$，三组件 = 方向、步长、判停。
- **下降方向**：$\nabla f^T\Delta x < 0$，与负梯度成钝角；是算法不犯错的地板。
- **终止**：$\|\nabla f\|_2 \le \epsilon$ 最常用，配合函数值变化与迭代上限更稳。
- **收敛三档**：线性、超线性、二次——牛顿二次、拟牛顿超线性、梯度线性。
- **方向谱系**：最速下降 → 共轭梯度 → 拟牛顿 → 牛顿，信息量递增、每步代价递增。
