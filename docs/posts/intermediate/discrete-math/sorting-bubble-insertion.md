## 为什么从排序开始

上一节我们看到：**有序**是一笔巨大的资产——二分搜索正是靠它把复杂度从 $n$ 降到 $\log n$。但数据不会天然有序，于是有了本专题算法篇的核心问题：**排序（sorting）**——把序列按递增（或递减）顺序重新排列。排序被誉为计算机科学「最基础的子程序」：几乎所有数据处理的第一步都是排序，从成绩排名到数据库建索引，从「找中位数」到「去重」，无不以排序为构件。<span class="marginnote">「从极限到大模型」里，排序无处不在：训练数据的预处理要洗牌、要排序；检索系统的倒排索引要排序；大模型推理时的 top-k 采样要在整个词表分布里挑出概率最高的前 k 个 token——那正是一次「取最大 k 个」的排序变体。</span>

这一节介绍两个最直观的排序算法：**冒泡排序（bubble sort）**与**插入排序（insertion sort）**。它们都不是最快的，但都是**最透明**的——你能清楚地看见「每一趟在做什么、为什么正确」。更重要的是，它们的复杂度分析直接动用前几篇的双重求和与伸缩求和，把抽象的工具变成具体的数字。

## 1 问题设定：把序列排好

**排序问题**：给定 $n$ 个元素的序列 $a_1, a_2, \dots, a_n$，把它重排成递增序列 $a_1' \le a_2' \le \cdots \le a_n'$，其中 $a_1', \dots, a_n'$ 是原序列的一个**排列（permutation）**——元素一个不多、一个不少。

排序算法的「基本操作」有两大类，我们要分开数：**比较次数**（元素之间比了几次）与**交换次数**（相邻元素换了几次）。两者常常一起变化，但代表不同的成本——比较是「读取信息」，交换是「改写内存」。<span class="marginnote">在真实系统里，交换往往比比较贵得多：交换要写内存、可能触发缓存失效。所以<strong>同时报告比较次数与交换次数</strong>是算法分析的基本礼仪，第五篇《算法复杂度》会把它们统一成时间复杂度的上下界。</span>

另一个关键约定：这一节的两个排序算法都是**基于比较的排序（comparison sort）**——它们只允许通过「$a_i$ 与 $a_j$ 比大小」来获取信息。这个限制看似自然，却暗含一个深刻结论（第十四篇会证明）：任何基于比较的排序，最坏都至少要 $\lceil \log_2 (n!) \rceil$ 次比较。我们马上会看到，冒泡与插入恰好都没突破这个下界。

## 2 冒泡排序：把最大值顶到末尾

**冒泡排序（bubble sort）**：重复地扫描序列，每次比较相邻两元素，若顺序反了就交换。一轮下来，最大的元素像气泡一样「冒」到序列末尾；下一轮对剩余部分重复。伪代码：

```text
procedure bubble_sort(a1, a2, …, an)
    for i := 1 to n - 1            # 共 n-1 趟
        for j := 1 to n - i        # 第 i 趟只需看到 n-i
            if a_j > a_{j+1} then  # 相邻逆序，交换
                swap(a_j, a_{j+1})
```

正确性靠一条**不变量**：第 $i$ 趟结束时，后 $i$ 个位置已经是整个序列中最大的 $i$ 个元素，且已排好序。因为第 $i$ 趟把当前「未排序部分」的最大值一路交换到其末尾，于是它被钉死在最终位置，永不回头。<span class="marginnote">「第 $i$ 趟结束后后 $i$ 位正确」——这是冒泡排序的循环不变量。它保证 $n-1$ 趟后，后 $n-1$ 位正确，剩下第一个位置自然也是正确的。<strong>每一趟处理的对象是「未排序前缀」的最大值，而不是全局最大值——因为全局最大值在第 1 趟就已经到末尾了。</strong></span>

**看一个具体的例子**：对 $[6, 2, 9, 1]$ 冒泡排序。

- 第 1 趟：比较 6 与 2，交换 → $[2, 6, 9, 1]$；比较 6 与 9，不换；比较 9 与 1，交换 → $[2, 6, 1, 9]$。最大值 9 到位。
- 第 2 趟：比较 2 与 6，不换；比较 6 与 1，交换 → $[2, 1, 6, 9]$。6 到位。
- 第 3 趟：比较 2 与 1，交换 → $[1, 2, 6, 9]$。2 到位，排序完成。

4 个元素 3 趟，比较次数 $3 + 2 + 1 = 6 = 4\cdot 3 / 2$。**每一趟都印证「后 $i$ 位正确」的不变量**，也预示了下一节公式解析的双重和结构。

冒泡排序的性格：**稳定、直观，但慢**。它要比较很多次，哪怕序列几乎有序也要跑满全部趟数（除非加一个「若某趟没发生交换就提前终止」的优化标志）。我们下一节精确数出它的代价。

## 3 插入排序：像整理扑克牌

**插入排序（insertion sort）**：把序列分成「已排序前缀」与「未排序后缀」，每次取后缀的第一个元素，**插入**到前缀的正确位置——就像打扑克时把新摸的牌插进手里已排好的牌中。伪代码：

```text
procedure insertion_sort(a1, a2, …, an)
    for j := 2 to n                # 前缀从 1 个元素开始
        x := a_j                   # 取要插入的元素
        i := j - 1
        while i ≥ 1 and a_i > x    # 从右往左找插入点
            a_{i+1} := a_i         # 比 x 大的元素右移一格
            i := i - 1
        a_{i+1} := x               # 放入正确位置
```

正确性靠另一条不变量：**外层第 $j$ 轮开始时，$a_1, \dots, a_{j-1}$ 已经有序**；内层 `while` 把 $a_j$ 一路左移，越过所有比它大的元素，插入后 $a_1, \dots, a_j$ 有序。归纳地，$j=n$ 时整个序列有序。<span class="marginnote">插入排序的「在线性」常被人忽略：它可以在数据<strong>一个接一个到达</strong>时就保持有序——这就是「在线算法」的雏形。数据库插入记录、实时榜单维护，用的都是这个思想。相比之下，冒泡排序必须等全部数据到齐才能开始。</span>

**辨析｜易错点：插入排序的「比较」与「移动」不是一回事。** 内层 `while` 的每次循环做一次比较 `a_i > x` **和**一次移动 `a_{i+1} := a_i`。在倒序输入下两者都达到 $O(n^2)$；但在正序输入下，每个元素只比较一次（`a_{j-1} > x` 为假就退出），移动次数为 0——这正是插入排序的**最好情形优势**，下一节会精确刻画。

## 4 公式解析：冒泡排序的比较次数

冒泡排序第 $i$ 趟要做 $n - i$ 次相邻比较，$i$ 从 1 到 $n-1$。总比较次数是

$$
C(n) = \sum_{i=1}^{n-1} (n - i) = (n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}
$$

分四步拆解这条公式：

- **第一步，读懂内层上限**：第 $i$ 趟的 `for j := 1 to n-i` 恰好做 $n-i$ 次比较。为什么是 $n-i$？因为后 $i-1$ 个位置已被前面的趟次钉死，这一趟只需处理前 $n-i+1$ 个元素，它们的相邻对数是 $n-i$。
- **第二步，写成双重和**：$C(n) = \sum_{i=1}^{n-1}\sum_{j=1}^{n-i} 1$——内层上限依赖外层 $i$，正是我们讲过的**三角区域双重求和**。
- **第三步，先算内层**：$\sum_{j=1}^{n-i} 1 = n-i$，于是 $C(n) = \sum_{i=1}^{n-1}(n-i)$。
- **第四步，伸缩 / 配对**：$n-i$ 从 $n-1$ 一路减到 1，首尾配对得
  $$
  (n-1) + 1 = n,\quad (n-2) + 2 = n,\ \dots
  $$
  共 $\frac{n-1}{2}$ 对，故 $C(n) = \frac{n(n-1)}{2}$。也可以用伸缩和 $\sum_{i=1}^{n-1}(n-i) = \sum_{k=1}^{n-1}k$ 直接读出。<span class="marginnote"><strong>冒泡排序的比较次数与输入内容无关</strong>——无论序列是否已排序，只要没有提前终止，它都恰好比较 $n(n-1)/2$ 次。这是它与插入排序最本质的差别：插入排序最好情形是 $O(n)$，冒泡排序（朴素版）最好情形仍是 $\Theta(n^2)$ 次比较。<strong>「最好情形好不好」取决于算法是否能把「有序」这个信号转化为少做事。</strong></span>

现在给两张算法的复杂度画像：

| 算法 | 比较（最好） | 比较（最坏 / 平均） | 交换 / 移动（最坏） | 稳定性 |
| --- | --- | --- | --- | --- |
| 冒泡排序 | $\dfrac{n(n-1)}{2}$ | $\dfrac{n(n-1)}{2}$ | $\dfrac{n(n-1)}{2}$ | 稳定 |
| 插入排序 | $n-1$ | $\dfrac{n(n-1)}{2}$ | $\dfrac{n(n-1)}{2}$ | 稳定 |

**重点：两者最坏都是 $\Theta(n^2)$，但插入排序在「几乎有序」的输入上优势巨大。** 倒序输入时，插入排序第 $j$ 个元素平均要移动约 $j/2$ 次，总计仍约 $n^2/2$；但正序输入时它只比较 $n-1$ 次——这就是为什么真实工程里，对「基本有序」的小数据，插入排序往往是最佳选择。<span class="marginnote">两个算法都是<strong>稳定排序</strong>：相等元素的相对顺序不变。稳定性在真实排序里很关键——比如先按姓氏再按名字排序，稳定排序能保二次排序的次序信息。第十二篇《树的应用》里，归并排序也靠稳定性取胜。</span>

## 5 排序的下一步：为什么要比这更快

冒泡与插入告诉我们：$O(n^2)$ 是什么体验——$n=10^4$ 时约 $5 \times 10^7$ 次比较，$n=10^6$ 时约 $5 \times 10^{11}$ 次，已经慢到不实用。**排序必须更快**，而突破口正是「结构信息」。

- **分治排序**：第三级《算法设计与分析》的归并排序与快速排序，把问题二分再合并，达到 $O(n \log n)$——这对应第九篇《分治递推关系与主定理》的核心。
- **树形排序**：第十二篇的二叉搜索树，让插入与查找都保持 $O(\log n)$。
- **下界定理**：任何基于比较的排序最坏至少 $\lceil \log_2 (n!) \rceil \approx n \log_2 n - 1.44 n$ 次比较——$O(n\log n)$ 不是「可以更快」，而是**理论极限**。<span class="marginnote">$\lceil \log_2(n!)\rceil$ 是信息论式的论证：$n$ 个元素的合法排列有 $n!$ 种，排序就是把「哪一种是输入」这个信息从 $n!$ 种可能中区分出来；一次比较最多给出一个二选一，所以至少 $\log_2(n!)$ 次。<strong>「从极限到大模型」里，信息论的下界思想（第四级《信息论》）在这里第一次露出面容。</strong></span>
- **大模型中的应用**：top-k 采样只需「最大 $k$ 个」而不必全排，堆（第十二篇《树》）用 $O(n \log k)$ 完成；推荐系统的召回阶段，靠近似最近邻与分层可导航小世界图（HNSW）在亿级数据里做排序——搜索与排序从未远离现代 AI。

## 6 小结

- **排序问题**：把序列重排成递增；排序算法的代价分为**比较次数**与**交换 / 移动次数**。
- **冒泡排序**：每趟把未排序部分的最大值顶到末尾；比较次数恒为 $n(n-1)/2$，与输入无关；稳定。
- **插入排序**：把新元素插进已排序前缀；最好 $O(n)$（几乎有序时），最坏 $O(n^2)$；稳定。
- **复杂度分析**：两者的比较次数都是**三角区域双重和**，$\sum_{i=1}^{n-1}(n-i) = n(n-1)/2$——直接复用第四篇的工具。
- **最好情形差异**：插入排序能利用「有序」信号，冒泡排序（朴素版）不能。
- 基于比较的排序最坏有 $\Theta(n \log n)$ 下界，更快必须靠结构（分治、树、堆）。

在下一节，我们将离开「把一个序列排好」的固定任务，进入一个更贪心的设计范式——**贪心算法**：每一步都选「眼前最优」，并学会论证这种短视为何有时是正确的。
