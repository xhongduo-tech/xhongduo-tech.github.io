# 前缀码与赫夫曼编码（Huffman coding）

## 为什么"无歧义编码"是树的问题

摩尔斯电码用点划表示字母，但若不设停顿，"...---..." 无法唯一解码——因为码可能互相是前缀。**前缀码（prefix code）**通过"没有一个码字是另一个的前缀"保证唯一解码，而**赫夫曼编码（Huffman coding）**用贪心算法构造**最短平均长度**的前缀码。这是信息论里压缩的基石，也是贪心算法的又一个正确性论证（与第五篇一脉相承）。<span class="marginnote">赫夫曼编码是数据压缩的祖爷爷：ZIP、JPEG、PNG 里的 Huffman 表都是它的后代。而"前缀码 ⟺ 满二叉树"的对应，把编码问题翻译成树问题——贪心在树上建树。第四级《信息论》会从熵的角度解释为什么赫夫曼平均长度 ≈ 熵。</span>

## 1 前缀码

**前缀码（prefix code）**：一组码字（0/1 串），若**没有一个码字是另一个码字的前缀**，则称前缀码。

**例**：$\{0, 10, 110, 111\}$ 是前缀码——没有码是另一个的前缀。编码 $\{0, 10, 110, 111\}$：$\{0, 10, 110, 111\}$ 唯一解码为 $\{0, 10, 110, 111\}$。

**非例**：$\{0, 01, 011\}$ 不是——`0` 是 `01` 的前缀、`01` 是 `011` 的前缀。收到 `011` 无法确定是 `0` 还是 `01` 开头。

**前缀码 ⟺ 满二叉树**：每个码字对应二叉树的一个叶，路径上的 0/1 是码位。**前缀性质 = 码字是叶（没有码字落在路径中途）**。

**解码**：从根按 0/1 走，到叶输出对应字符，回根继续——**无需分隔符**就能唯一解码。

**例**：$0$（左）、$10$（右左）、$110$（右右左）、$111$（右右右）对应一棵满二叉树的四个叶。

## 2 最优前缀码问题

**问题**：给每个符号 $s_i$ 一个出现频率（权）$w_i$，构造前缀码使**平均码长**最小：

$$
\text{最小化} \sum_i w_i \cdot \text{len}(c_i)
$$

（归一化后即期望码长。频率高 ⟹ 码短。）

**例**：字符 a(0.4)、b(0.3)、c(0.2)、d(0.1)。等长码需 2 位（平均 2 位）；赫夫曼码应给 a、b 短码，d 长码。

**贪心直觉**：**频率最低的两个符号应该给最长的码，且它们只在最后一位不同**（共享同一父节点）——把"最不常用"的合并，反复进行。

## 3 赫夫曼算法

**赫夫曼编码算法**（每次合并两个最小频率节点）：

1. 每个符号一个节点，权 = 频率。
2. 重复：取权最小的两个节点，合并为一个权为两者之和的节点，作为它们父节点。
3. 直到只剩一个节点（根）。
4. 从根到叶，左分支标 0、右分支标 1，码字 = 路径标签。

**实例**：a(0.4)、b(0.3)、c(0.2)、d(0.1)。

- 合并 c(0.2)、d(0.1) → 节点 cd(0.3)。
- 合并 b(0.3)、cd(0.3) → 节点 bcd(0.6)。
- 合并 a(0.4)、bcd(0.6) → 根(1.0)。

码字：d = 110（右右左）？取决于合并方向——标准结果：a=0、b=10、c=110、d=111 或对称形式。平均长度 $= 0.4\times1 + 0.3\times2 + 0.2\times3 + 0.1\times3 = 1.9$ 位，优于等长码的 2 位。

**复杂度**：每次合并取最小两个 → 用堆 $O(n\log n)$。

## 4 公式解析：赫夫曼的正确性（贪心论证）

**定理**：赫夫曼算法构造的前缀码具有最小平均码长。

**证明（交换论证 + 归纳）**：

- **引理 1（最深两叶是兄弟）**：最优前缀码中，频率最小的两个符号是深度最深的两片叶，且是兄弟（共享父）。否则可交换位置减小平均码长。
- **引理 2（合并保持最优性）**：把最小两符号 $x, y$ 合并成权 $w_x + w_y$ 的新符号，得到 $(n-1)$ 符号问题。若 $(n-1)$ 问题有最优解，则把 $x, y$ 展开回其子树即得 $n$ 问题最优解。
- **归纳**：算法第 1 步的合并对应引理 2 的归约；对 $n-1$ 问题递归最优，展开即整体最优。∎

**关键直觉**：

- **第一步，深叶给低频**：交换论证——若低频符号不在最深，把它的位置与最深码互换，平均码长不增。
- **第二步，兄弟合并**：最深两叶共父，合并等价于"给它们的共同前缀再延一位"。
- **第三步，子问题同构**：合并后是更小规模的同一问题，贪心递归正确。∎

**辨析｜易错点：** 赫夫曼树的"最优"是**平均码长**最小，不是"每个符号码长"最小。可能某个高频符号的码并不是全局最短（受其他符号约束）。另外**等权时多个最优解**——不同合并顺序都最优，别以为唯一。

<span class="marginnote">赫夫曼编码的最优性正是第五篇贪心正确性的又一实例：<strong>贪心（合并最小两权）+ 交换论证（深叶给低频）+ 归纳（子问题最优）</strong>。而它与熵的关系——赫夫曼平均码长总在 $[H, H+1)$ 之间——是第四级《信息论》的精彩结论：<strong>压缩的下界由熵刻画</strong>。</span>

## 5 赫夫曼编码的完整构造与平均长度计算

把赫夫曼算法从头到尾走一遍，包括"合并方向"对码字的影响。

**例**：符号 a(0.35)、b(0.25)、c(0.20)、d(0.12)、e(0.08)。

**合并过程**（每次取两个最小权）：

- 合并 e(0.08)、d(0.12) → 0.20。
- 合并 c(0.20)、上一步的 0.20 → 0.40。
- 合并 b(0.25)、0.40 → 0.65。
- 合并 a(0.35)、0.65 → 1.00（根）。

**分配码字**（左 0 右 1，从根到叶）：a = 0、b = 10、c = 110、d = 1110、e = 1111。

**计算平均长度**：

$$
0.35\times1 + 0.25\times2 + 0.20\times3 + 0.12\times4 + 0.08\times4 = 0.35 + 0.5 + 0.6 + 0.48 + 0.32 = 2.25
$$

**公式解析：平均长度与熵的关系**

设符号频率 $p_i$、码长 $l_i$，熵 $H = -\sum p_i\log_2 p_i$。赫夫曼保证

$$
H \le \bar{L} < H + 1
$$

- **第一步，算熵**：本例 $H \approx 2.12$ 比特，$\bar{L} = 2.25$，满足 `$2`.12 \le 2.25 < 3.12$ ✓。
- **第二步，读下界**：任何前缀码平均长度 ≥ 熵——**熵是压缩的极限**（信息论核心，第四级详讲）。
- **第三步，读上界**：赫夫曼逼近熵，最多多 1 比特——**它是熵最优的（整数码长下）**。∎

**这个例子的要点**：赫夫曼的"合并最小两权"保证高频短码、低频长码，平均长度逼近熵。**它既是贪心算法正确性的范例，也是信息论"压缩极限"的工程实现**。

**辨析｜易错点：** 合并时**权相等**的选择会影响码字分配（左/右），但**平均长度不变**——多棵最优树都是最优。别纠结"哪个合并顺序对"——它们一样好。**判据是平均长度，不是码字具体形状**。

## 6 小结

- **前缀码**：无码字互为前缀；对应满二叉树（码字=叶），解码无需分隔符。
- **最优前缀码**：最小化 $\sum w_i \text{len}(c_i)$。
- **赫夫曼算法**：反复合并两个最小权节点，堆实现 $O(n\log n)$。
- **正确性**：交换论证（低频最深）+ 归纳（合并归约子问题）。
- 平均码长 $\ge$ 熵 $H$ 且 $< H+1$；ZIP/JPEG/PNG 的压缩核心。
