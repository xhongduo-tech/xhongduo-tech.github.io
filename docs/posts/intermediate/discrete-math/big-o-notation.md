## 为什么需要大 O 记号

上一节我们用贪心算法把解空间从指数压缩到线性，但还缺一把尺子：**一个算法到底多快？** 直接数 CPU 秒数没有意义——同一段代码在不同机器、不同语言、不同优化级别下的运行时间差出百倍。我们需要一个与机器无关的度量，衡量的是**输入规模增长时，运行时间的增长速度**。

这就是**渐近分析（asymptotic analysis）**：忽略常数与低阶项，只关心输入规模 $n$ 很大时主导运行时间的那一项。**大 O 记号（big-O notation）**是这套语言的第一个词，它回答"运行时间至多增长多快"，给算法复杂度一个上界。<span class="marginnote">渐近分析让"算法复杂度"成为数学对象，可比较、可证明。第三级《数据结构》与《算法设计与分析》里所有复杂度论断都建立在这一记号之上；连大模型推理的 FLOPs 估算、KV cache 的显存分析，本质也是渐近思维。</span>

## 1 大 O 记号的严格定义

**大 O 记号**：设 $f$ 与 $g$ 是从正整数集到实数的函数。称 $f(x)$ 是 $O(g(x))$ 的，记作 $f(x) = O(g(x))$，若存在常数 $C > 0$ 与 $k \ge 0$，使得对所有 $x > k$，有

$$|f(x)| \le C\,|g(x)|$$

直觉是：当 $x$ 足够大（超过阈值 $k$）以后，$f$ 的绝对值**至多**是 $g$ 的 $C$ 倍。换句话说，$f$ 的"长期增长速度"不会超过 $g$。注意这里只要求**存在**一对 $(C, k)$，不要求唯一——我们只需要一个能说明问题的具体对子。

<span class="marginnote">英文里常把 $f(x) = O(g(x))$ 读作 "f is big-O of g"。严格说这个等号是记号滥用——$O(g(x))$ 是一族函数，更准确该写 $f \in O(g)$，但约定俗成用等号，只要心里明白它表示"属于某个增长类"即可。</span>

## 2 公式解析：从具体复杂度读出大 O

设某算法的运行时间精确为 $f(n) = 3n^2 + 7n + 12$，证明 $f(n) = O(n^2)$：

$$
|3n^2 + 7n + 12| \le 3n^2 + 7n^2 + 12n^2 = 22n^2 \quad (n \ge 1)
$$

- **第一步，把每一项都"放大"到目标函数 $n^2$ 的倍数**：对 $n \ge 1$，有 $7n \le 7n^2$、$12 \le 12n^2$。于是整式每一项都能被 $n^2$ 吸收。
- **第二步，合并系数**：$3 + 7 + 12 = 22$，得到 $|f(n)| \le 22 n^2$。
- **第三步，读出 $(C, k)$**：取 $C = 22$、$k = 1$，定义条件满足，所以 $f(n) = O(n^2)$。

这个"**每一项都放大到最高次项**"的技巧说明了一件事：**多项式的大 O 只由最高次项决定，常数与低阶项全部可以吞掉**。这也是为什么我们在前几节写"冒泡排序是 $O(n^2)$"时，从不去纠结到底跑了 $n(n-1)/2$ 还是 $n^2$ 次比较——差的是一个常数因子，在渐近意义下无足轻重。

**辨析｜易错点：** 大 O 是**上界**，不是精确估计。$n^2 = O(n^2)$、$n^2 = O(n^3)$、甚至 $n^2 = O(2^n)$ 全都成立——上界松一点并不算错，只是没用。说"这个算法是 $O(n^2)$"只保证它不比 $n^2$ 更慢，不保证它真到 $n^2$。想要"精确到阶"的说法，需要下一节的 $\Theta$ 记号。

## 3 常见增长阶的谱系

按增长速度从慢到快，最常见的一组增长阶是：

| 记号 | 典型函数 | 直觉 | 例 |
| --- | --- | --- | --- |
| $O(1)$ | 常数 | 与规模无关 | 哈希表取一个键 |
| $O(\log n)$ | 对数 | 每步砍一半 | 二分搜索 |
| $O(n)$ | 线性 | 每个元素看一眼 | 线性搜索 |
| $O(n\log n)$ | 线性对数 | 分治后合并 | 归并排序 |
| $O(n^2)$ | 平方 | 两两比较 | 冒泡排序 |
| $O(n^3)$ | 立方 | 三重循环 | 矩阵乘法（朴素） |
| $O(2^n)$ | 指数 | 每个子集试一遍 | 子集枚举 |
| $O(n!)$ | 阶乘 | 每个排列试一遍 | 旅行商问题（朴素） |

$O(\log n)$ 与 $O(2^n)$ 之间隔着天堑：$n=100$ 时 $\log_2 n \approx 7$，而 $2^{100}$ 是天文数字。**多项式增长（$n^c$）与指数增长（$c^n$）的分界，是算法分析中最重要的一条线**——能保持在多项式内的问题通常"可解"，落入指数的问题则常常需要换思路（贪心、动态规划、近似算法）。

<span class="marginnote">为什么 $\log_2 n$ 和 $\log_{10} n$ 写出来都是 $O(\log n)$？因为换底公式 $\log_b n = \log_b a \cdot \log_a n$，差的只是一个常数因子，被大 O 吞掉了。所以对数的大 O 记号里从不写底数。</span>

## 4 大 O 的运算规则

大 O 记号对函数的复合运算有简单规则，做复杂度分析时直接套用：

- **加法规则**：若 $f = O(g)$、$h = O(s)$，则 $f + h = O(\max(g, s))$——程序里依次执行的片段，总复杂度取各片段中最高的。<span class="marginnote">这正是顺序代码段的复杂度定律：三个循环依次跑，总开销由最贵那个决定，不求和。</span>
- **乘法规则**：若 $f = O(g)$、$h = O(s)$，则 $f \cdot h = O(g \cdot s)$——嵌套循环总复杂度是各层循环之积。
- **放缩规则**：$c \cdot O(g) = O(g)$ 对常数 $c>0$ 成立——常数因子无足轻重。
- **传递性**：$O(O(g)) = O(g)$。

这些规则来自定义的直接推论。以乘法规则为例：$|f| \le C_1|g|$、$|h| \le C_2|s|$ 对足够大的 $x$ 成立，两式相乘得 $|f\,h| \le C_1C_2\,|g\,s|$，取 $C = C_1C_2$ 即得。

## 5 大 O 记号的性质与一个反直觉例子

大 O 记号还有一些常用性质，做题时直接套用：

**性质 1（系数无关）**：$c f(n) = O(f(n))$ 对常数 $c>0$——常数因子被吞。

**性质 2（幂次主导）**：$n^a = O(n^b)$ 当且仅当 $a \le b$——同底幂比较指数。

**性质 3（对数底无关）**：$\log_a n = \Theta(\log_b n)$——换底只差常数，所以大 O 里不写底数。

**性质 4（多项式 vs 指数）**：对任意 $c > 1$、$k > 0$，$n^k = O(c^n)$——**任何多项式都被指数压过**。

**公式解析：证明 $n^k = O(c^n)$**

$$
\lim_{n\to\infty}\frac{n^k}{c^n} = 0 \implies n^k = O(c^n)
$$

- **第一步，取对数**：$\ln(n^k / c^n) = k\ln n - n\ln c \to -\infty$（因为 $n$ 项压过 $\ln n$ 项）。
- **第二步，还原**：比值 $\to 0$，故对足够大的 $n$，$n^k \le c^n$。
- **第三步，读出 $(C, k')$**：取 $C = 1$、$k'$ 为某阈值即可。∎

**反直觉例子**：$n^{100}$ 与 $1.0001^n$ 谁增长快？从"渐近"看是 $1.0001^n$（指数终胜），但对所有现实输入规模（$n \le 10^9$），$n^{100}$ 远大于 $1.0001^n$。**渐近分析说的是"足够大以后"，不是"实际输入"**——这是大 O 记号最容易被误用的地方。工程上既要看渐近阶，也要看常数与输入规模区间。

## 6 小结

- **大 O 记号** $f = O(g)$：存在 $C>0$ 与 $k$，使 $x>k$ 时 $|f(x)| \le C|g(x)|$——$f$ 的增长至多像 $g$。
- 多项式的大 O **只看最高次项**，常数与低阶项可吞并。
- 常见增长谱系：$1 \prec \log n \prec n \prec n\log n \prec n^2 \prec n^3 \prec 2^n \prec n!$。
- 大 O 是**上界**：$n^2 = O(2^n)$ 不错但无用，"精确到阶"要等 $\Theta$。
- 运算规则：顺序取 $\max$，嵌套相乘，常数放缩无效化。

**再辨析｜易错点：** 大 O 定义里的阈值 $k$ 与常数 $C$ 是"存在即可"，不必最优。证明 $f = O(g)$ 时，**找到一个能用的 $(C, k)$ 就够了**——别纠结"最小的 C 是多少"。而读大 O 时，"$O(n^2)$"与"$O(n^2)$ 且最坏即 $n^2$"是两句话——前者只给上界，后者才是精确阶。

**小结补记**：大 O 记号把"算法的速度"压缩成"增长阶"，让机器差异、常数差异全部消失，只留下"随规模怎么涨"。**它是算法分析的公制单位**——第三级《算法》的所有复杂度声明都建立在这套语言上。记住"只问增长阶、不纠结常数"是使用大 O 的第一纪律。

**快速自测**：$f(n) = 5n^3 + 2n^2 + 10$ 是 $O(n^3)$ 吗？是。对 $n \ge 1$，每一项放大：$5n^3 \le 5n^3$、$2n^2 \le 2n^3$、$10 \le 10n^3$，合并 $|f| \le 17n^3$，取 $C=17$、$k=1$。**常考套路：逐项放大到最高次、合并系数**。

**本节一句话回顾**：大 O 只回答"至多增长多快"，忽略常数与低阶项，是算法分析的公制单位。
**易混点再提醒**：$O$ 是上界不是精确值——"是 $O(n^2)$"与"最坏就是 $n^2$"是两句话。

在下一节，我们给大 O 配上它的两个兄弟——**大 Ω 与大 Θ**——一个管下界，一个管"精确阶"，把增长谱系完整拼起来。
