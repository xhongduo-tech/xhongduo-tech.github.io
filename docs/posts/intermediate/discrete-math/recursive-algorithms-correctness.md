## 为什么递归算法需要单独一课

前两节我们有了递归定义（函数与集合）和结构归纳法（证明工具），现在把它们合体：**递归算法（recursive algorithm）**——算法在解决一个规模为 $n$ 的问题时，把问题拆成更小的同类问题，调用自身。递归算法的"正确性"不是靠感觉，而是有标准证明套路；而"效率"则是另一场战争——同一问题递归写出来可能指数爆炸，也可能优雅地 $\log n$。这一节要同时讲**怎么设计、怎么证明、怎么算复杂度**。<span class="marginnote">递归算法是分治法的雏形。第九篇《分治递推关系与主定理》会系统分析递归算法的复杂度；第三级《算法设计与分析》则把归并排序、快速排序、最大子段和等经典递归算法全面展开。今天打的是地基。</span>

## 1 递归算法的结构

**递归算法** = 两部分：

1. **基础情形（base case）**：问题小到可以直接解决，不调用自身。
2. **递归情形（recursive case）**：把原问题拆成更小规模的同型问题，递归求解后合并结果。

**例（递归求最大值）**：在数组 `a[0..n-1]` 中找最大值。

```
procedure max(a, l, r)   # 找 a[l..r] 的最大值
    if l == r:            # 基础情形：单元素
        return a[l]
    mid = (l + r) // 2
    m1 = max(a, l, mid)   # 递归：左半
    m2 = max(a, mid+1, r) # 递归：右半
    return max(m1, m2)    # 合并
```

设计递归算法的要点：**递归情形必须把问题变小**（区间 `[l,r]` 拆成更短的左右两段），否则算法永远停不下来。

**辨析｜易错点：** 最常犯的错误是递归情形的**合并步骤**写错。最大值的合并是"取两半最大值之大"，可有些问题（如"子数组最大和"）的合并远比这复杂——递归算法里"拆"是套路，"合"才是问题特有。

## 2 递归算法的正确性证明

**递归算法的正确性证明 = 结构归纳法**。证明"对任意合法输入，算法返回正确结果"，分两步：

1. **基础步**：基础情形对最小输入返回正确结果。
2. **归纳步**：假设递归调用对所有更小输入返回正确结果（归纳假设），证明合并步骤把正确子结果拼成正确总结果。

**实例**：证明上面的 `max` 对任意区间 `[l,r]` 正确。

- **基础步**：$l = r$ 时区间只有一个元素，返回 `a[l]` 即为最大值。
- **归纳步**：假设 `max` 对区间长度小于当前的问题都正确，即 `m1` 是左半最大值、`m2` 是右半最大值。整个区间的最大值必然在左半或右半中，所以 `max(m1, m2)` 是全局最大值。∎

**这为什么充分**：归纳假设覆盖所有"更小区间"，而合并步骤正确地把两个更小区间的解合成当前区间的解。每一步都在更小的实例上"递归地正确"，最终落到基础情形——链条闭合，正确性成立。

## 3 公式解析：递归复杂度——递推式

递归算法的运行时间天然是一个**递推关系（recurrence relation）**：$T(n)$ 表示规模 $n$ 的运行时间，递归步的"拆 + 合"转换成递推式。对上面的 `max`（假设数组大小为 $n$）：

$$
T(n) = 2T\left(\frac{n}{2}\right) + c, \qquad T(1) = c
$$

- **第一步，读递归项**：每次调用把问题拆成两个规模 $n/2$ 的子问题，各耗时 $T(n/2)$；"拆"本身是常数时间 $c$。
- **第二步，展开**：$T(n) = 2(2T(n/4) + c) + c = 4T(n/4) + 2c + c = \dots = 2^k T(n/2^k) + kc$。
- **第三步，落到基础**：$n/2^k = 1$ 即 $k = \log_2 n$，得 $T(n) = nT(1) + c\log_2 n = cn + c\log n = \Theta(n)$。

**结论**：这个递归最大值的复杂度是 $\Theta(n)$——和线性扫描一样快（毕竟找最大值总得看每个元素一眼）。**递归不必然慢**，关键是子问题的个数与规模：2 个子问题、各减半，合并常数，总开销仍是线性。

**对比斐波那契的朴素递归**：

$$
T(n) = T(n-1) + T(n-2) + c
$$

这个递推式的解是 $T(n) = \Theta(\varphi^n)$——**指数爆炸**。同样递归，最大值线性、斐波那契指数，差别全在递推式的形态：前者子问题不重叠，后者子问题指数级重复。这就是为什么动态规划（缓存子问题解）能把斐波那契拉回线性。

<span class="marginnote">怎么算 $T(n) = T(n-1)+T(n-2)+c$ 的解？把 $c$ 项暂时忽略，这个递推式长得和斐波那契 $F_n = F_{n-1}+F_{n-2}$ 一模一样，所以 $T(n)$ 以斐波那契速度增长，约 $\varphi^n$。第九篇《递推关系》会给出解这类式的系统方法（特征方程）。</span>

## 4 递归与迭代的工程权衡

递归算法优美但并非免费：

| 维度 | 递归 | 迭代 |
| --- | --- | --- |
| 代码可读性 | 与定义对齐，直观 | 需手动维护状态 |
| 调用开销 | 每次调用压栈 | 无额外栈开销 |
| 栈深度 | $O(\text{递归深度})$，可能溢出 | 常量 |
| 适用场景 | 分治、树、回溯 | 简单线性推进 |

**实践准则**：递归深度 $\log n$ 级别的（如二分搜索、归并排序）很安全；深度 $n$ 级别的（朴素递归处理长链）可能栈溢出，应考虑改迭代或尾递归。

**工程对应**：编译器与解释器里的**递归下降解析**就是按语法（递归定义的集合）逐层下降——第十四篇讲文法时，你会看到"递归定义集合"直接翻译成"递归解析程序"。

## 5 递归算法正确性证明的完整案例：归并排序

把"结构归纳证明"完整走在一个真实算法上——归并排序，看它如何被拆、如何被证明。

**归并排序（MergeSort）**：

```
procedure mergeSort(a, l, r):      # 排序 a[l..r]
    if l == r:                      # 基础：单元素已有序
        return
    mid = (l + r) // 2
    mergeSort(a, l, mid)            # 递归：左半
    mergeSort(a, mid+1, r)          # 递归：右半
    merge(a, l, mid, r)             # 合并两个有序段
```

**引理（merge 正确）**：若左段 `a[l..mid]` 与右段 `a[mid+1..r]` 各自有序，则 `merge` 把它们合并成一个有序段。证明：每次比较两段头元素，取较小者放入结果——保持结果有序且覆盖两段全部元素。

**定理（mergeSort 正确）**：`mergeSort(a, l, r)` 把 `a[l..r]` 排成有序。

- **基础步**：$l = r$ 时单元素已经有序 ✓。
- **归纳步**：假设 `mergeSort` 对区间长度更小的问题正确——则左半、右半分别有序（归纳假设）；由 merge 引理，合并后整体有序。∎

**公式解析：正确性 = 归纳假设 + 合并引理**

$$
\text{mergeSort}(a, l, r) \text{ 正确} \iff (\text{两半各自正确}) \land (\text{merge 正确})
$$

- **第一步，读递归假设**：归纳假设覆盖所有"更小区间"的排序。
- **第二步，读合并引理**：把"两个有序段"变成"一个有序段"是 merge 的职责——**基础事实必须单独证明**。
- **第三步，读组合**：递归正确 + 合并正确 = 整体正确。∎

**为什么这个证明"完备"**：它把正确性分解为"递归调用（假设）+ 合并步骤（引理）"两件独立的事——**结构归纳让递归算法的证明有了固定流程**：证基础、证子问题、证合并。

**这个例子的要点**：归并排序的正确性证明是递归算法证明的标准范本。**"每个递归算法 = 基础情形 + 更小子问题 + 合并步骤"**——证明也照这个三件套走。复杂度 $O(n\log n)$ 的分析（主定理）见第九篇。

**辨析｜易错点：** merge 的正确性**不能**混进归纳步里"顺便"处理——它是独立引理，要单独验证（两段有序 ⟹ 合并有序）。**"合并逻辑对"与"递归逻辑对"是两件事**，分开证明才不会漏。

## 6 小结

- **递归算法** = 基础情形 + 递归情形（更小的同类问题 + 合并）。
- **正确性证明** = 结构归纳：基础步 + 归纳步（假设更小输入正确，证合并正确）。
- **复杂度** = 递推式：$T(n)$ 展开到基础情形，读主导项。
- 递推式的形态决定一切：$2T(n/2)+c$ 线性，$T(n-1)+T(n-2)+c$ 指数。
- 递归优雅，但要留意栈深度与重复子问题。

在下一节，我们把"证明算法正确"这件事彻底形式化——**程序正确性**，用前置断言、后置断言与循环不变量给任何算法一个可检验的证明框架。
