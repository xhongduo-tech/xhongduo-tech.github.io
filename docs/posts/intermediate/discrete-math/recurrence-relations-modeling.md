## 为什么递推关系是"高级计数"的入口

我们在第七篇见过递归定义（斐波那契、阶乘），也用它算过递归算法的复杂度。但递归定义能做的远不止这些——很多**计数问题**无法直接套排列组合公式，却能写成"第 $n$ 项与前面若干项的关系"，这就是**递推关系（recurrence relation）**。它是高级计数技术的入口：先把问题建模成递推式（本节），再找系统解法（特征方程、生成函数，后续各节）。<span class="marginnote">递推关系是动态规划的数学语言：DP 的"状态转移方程"就是一个递推关系，DP 表格就是顺着递推把值算出来。第九篇整篇都是为第三级《算法设计与分析》的动态规划章节打地基——汉诺塔、爬楼梯、铺砖问题，届时会以"DP 经典题"的身份重逢。</span>

## 1 递推关系的定义

**递推关系（recurrence relation）**：对数列 $\{a_n\}$，若存在 $k$，使 $a_n$ 能由 $a_{n-1}, a_{n-2}, \dots, a_{n-k}$ 表示（对 $n \ge k$ 成立），则称该关系是 $k$ **阶**递推关系，连同**初始条件（initial conditions）**一起构成对数列的**递归定义**。

**例 1（斐波那契）**：$a_n = a_{n-1} + a_{n-2}$，初始条件 $a_0 = 0$、$a_1 = 1$。

**例 2（存款）**：年利率 5%，复利。第 $n$ 年末余额 $P_n = P_{n-1} + 0.05 P_{n-1} = 1.05 P_{n-1}$，初始 $P_0 = 1000$。

**关键区分**：
- **递推关系本身**只给"相邻项如何递推"，不指定起点；
- **初始条件**锁定起点；
- 二者合起来才**唯一确定**一个数列。

**辨析｜易错点：** "递推关系"与"递归定义"容易混。递推关系是那一条方程；递归定义 = 递推关系 + 初始条件。写题时两条都要给全，缺初始条件的递推关系确定不了一个数列。

## 2 建模：从问题到递推式

递推关系建模的套路是：**设 $a_n$ 为"规模 $n$ 的计数结果"，然后分析"第一个动作"如何把问题拆成更小规模**。

**例（汉诺塔）**：$n$ 个圆盘从 A 移到 C，每次移一个、大盘不能压小盘，最少移动次数 $H_n$ 是多少？

**建模**：要把 $n$ 个盘从 A 移到 C：

1. 先把上面 $n-1$ 个盘从 A 移到 B（借助 C）：$H_{n-1}$ 步；
2. 把最大的盘从 A 移到 C：1 步；
3. 把 $n-1$ 个盘从 B 移到 C（借助 A）：$H_{n-1}$ 步。

所以

$$H_n = 2H_{n-1} + 1, \qquad H_1 = 1$$

**这个"三步拆解"是建模的模板**：把"第 $n$ 步问题"分成"前 $n-1$ 步的子问题 + 一个动作 + 后 $n-1$ 步子问题"。

**例（爬楼梯）**：每次爬 1 或 2 阶，爬到第 $n$ 阶有多少种方式？最后一步要么从第 $n-1$ 阶跨 1 阶、要么从第 $n-2$ 阶跨 2 阶：

$$a_n = a_{n-1} + a_{n-2}, \qquad a_1 = 1,\ a_2 = 2$$

这就是斐波那契数列的"换装"——同一个递推关系，不同的初始条件，不同的数列。

## 3 公式解析：解出递推的封闭形式

建模之后，问题变成"求 $a_n$ 的显式公式"。先看一个能直接观察出答案的：

**例（存款）**：$P_n = 1.05 P_{n-1}$，$P_0 = 1000$。展开：

$$
P_n = 1.05 P_{n-1} = 1.05^2 P_{n-2} = \dots = 1.05^n P_0 = 1000 \times 1.05^n
$$

- **第一步，展开**：每步乘一个 $1.05$，$n$ 步后乘了 $n$ 个。
- **第二步，识别等比**：形如 $a_n = r a_{n-1}$ 的递推，解是 $a_n = a_0 r^n$。
- **第三步，验证**：$P_3 = 1000 \times 1.05^3 = 1157.625$，与逐年复利计算一致。

这个"展开找规律 + 归纳证明"正是第七篇讲过的套路。但更多递推（如 $H_n = 2H_{n-1}+1$、斐波那契）展开也难直接看出公式，需要后面几节的特征方程法。

**汉诺塔的封闭解**：$H_n = 2^n - 1$（$H_n = 2(2^{n-1}-1)+1 = 2^n -1$ 归纳即得）。传说是"梵天完成 64 层塔时世界毁灭"，$2^{64}-1$ 秒 ≈ 5850 亿年——这个数字让"指数增长"有了血肉。

## 4 递推关系的应用图谱

递推关系渗透了本教材的多个篇章：

- **计数**：错排 $D_n = (n-1)(D_{n-1}+D_{n-2})$、组合数 $\binom{n}{k} = \binom{n-1}{k-1}+\binom{n-1}{k}$。
- **算法复杂度**：$T(n) = 2T(n/2)+c$（分治）、$T(n) = T(n-1)+T(n-2)+c$（斐波那契递归）。
- **数据结构**：二叉树的节点数与深度的关系。
- **概率**：随机游走、赌徒破产问题的期望步数。

<span class="marginnote">递推关系是离散数学的"万金油"：同一套数学工具，既能描述算法耗时、又能数路径、又能算复利。而求解它的两大武器——<strong>特征方程法</strong>（下两节）与<strong>生成函数法</strong>（第 6–8 节）——正是本篇接下来要逐一打磨的。</span>

## 5 递推建模的完整练习：铺砖问题

把"建模三步"（设 $a_n$、分析第一个动作、写递推）走在一个经典问题上。

**例（铺砖）**：用 $1 \times 2$ 的骨牌铺满 $2 \times n$ 的棋盘，有多少种铺法？

**设 $a_n$** = 铺满 $2 \times n$ 棋盘的方式数。

**分析第一个动作**：看棋盘最左边的竖列。

- 若放**竖骨牌**（一块盖住左列两格）：剩下 $2 \times (n-1)$，$a_{n-1}$ 种。
- 若放**横骨牌**（两块横放，各占左列一格和次列一格）：左两列被这两块横骨牌占满，剩下 $2 \times (n-2)$，$a_{n-2}$ 种。

两类互斥且穷尽，所以

$$
a_n = a_{n-1} + a_{n-2}, \qquad a_1 = 1, \ a_2 = 2
$$

**这就是斐波那契数列**（$a_n = F_{n+1}$）：1, 2, 3, 5, 8, …——铺 $2\times5$ 棋盘有 8 种。

**公式解析：为什么"看第一列"是建模钥匙**

$$
a_n = a_{n-1} \ (\text{竖}) + a_{n-2} \ (\text{横})
$$

- **第一步，读局部决策**：第一列只有两种合法铺法（竖一块 / 横两块）——没有第三种。
- **第二步，读剩余问题**：两种铺法分别留下 $n-1$ 与 $n-2$ 的同型子问题。
- **第三步，读初值**：$a_1 = 1$（一块竖骨牌）、$a_2 = 2$（两块竖或两块横）。∎

**为什么"第一个/最后一个动作"几乎总是最优视角**：它把大问题规约为更小规模的同型问题——**这正是递推建模与递归算法的共同灵魂**。爬楼梯、汉诺塔、铺砖、括号配对全是这个模板。

**辨析｜易错点：** 分析"第一个动作"时要确保**分类穷尽且互斥**。铺砖问题两类覆盖了全部可能——漏掉横放就会得到错误递推。**穷尽性 = 递推正确的保证**，建模完建议算 $a_3$ 人工核对。

**这个例子的要点**：铺砖问题展示了递推建模的完整流程——**"设未知 → 拆第一动作 → 写递推 → 定初值"**。它的解竟是斐波那契——同一个递推关系在不同初始条件下的多变身份，也是递推理论迷人的地方。

## 6 小结

- **递推关系**：$a_n$ 由前 $k$ 项表示；递推 + 初始条件才唯一确定数列。
- **建模三步**：设 $a_n$ → 分析"第一个/最后一个动作" → 写成更小规模的递推。
- 汉诺塔 $H_n = 2H_{n-1}+1$、爬楼梯 $a_n = a_{n-1}+a_{n-2}$ 是两大标准模型。
- **展开找规律**是简单递推的求解法（等比型 $a_n = a_0 r^n$）。
- 递推关系贯穿计数、算法复杂度、数据结构与概率。
