## 为什么机器需要"状态"

到目前为止的电路（组合电路）没有记忆——输出只由当前输入决定。但现实系统需要"记住过去"：电梯要知道到了几层、自动售货机要知道已投入多少钱、网络协议要知道握手到哪一步。**有限状态机（finite-state machine, FSM）**为"带记忆的计算"建模：一组**状态**，输入驱动状态转移，输出由状态（和输入）决定。它是时序电路、数字设计、协议分析、以及一切"有状态系统"的数学模型。<span class="marginnote">FSM 是现代计算无处不在的骨架：CPU 的控制单元、通信协议的状态机（TCP 握手）、编译器词法分析器、游戏角色 AI、以及正则表达式匹配引擎。第三级《数字逻辑》的时序电路、第四级《大模型部署》的流式解码状态，都是 FSM 或其扩展。从 FSM 到图灵机（本篇后半），是"增加记忆容量"的升级路径。</span>

## 1 有限状态机的定义

**有限状态机（FSM）** $M = (S, I, O, f, g, s_0)$：

- $S$：**状态（states）**的有穷集。
- $I$：**输入字母表（input alphabet）**。
- $O$：**输出字母表（output alphabet）**。
- $f: S \times I \to S$：**转移函数（transition function）**——当前状态 + 输入 → 下一状态。
- $g$：**输出函数（output function）**。
- $s_0 \in S$：**初始状态（initial state）**。

**例（自动售货机的一部分）**：状态 = 已投金额（0、5、10 分），输入 = 投 5 分或 10 分，输出 = 是否可出货。

**表示**：状态转移表或**状态图**（有向图：顶点 = 状态，边 = 转移，边标"输入/输出"）。状态图正是我们图论的直接应用。

## 2 米利机与摩尔机

按**输出函数**依赖什么，分两类：

- **米利机（Mealy machine）**：输出依赖**当前状态 + 输入**：$g(s, x)$。输出在**转移时**产生。
- **摩尔机（Moore machine）**：输出只依赖**当前状态**：$g(s)$。输出在**进入状态时**产生。

**例（"识别 01"检测器）**：

- 米利机：状态记忆"读到 0 没"，输入 0/1，输出"是否刚形成 01"。$g(s,x)$ 看状态和输入。
- 摩尔机：状态含"上一个读到的字符类别"，输出由状态决定。

**区别的关键**：

| | 米利机 | 摩尔机 |
| --- | --- | --- |
| 输出依赖 | 状态 + 输入 | 仅状态 |
| 输出时机 | 转移时 | 入态时 |
| 状态数 | 通常更少 | 通常更多 |
| 输入响应 | 更快（组合逻辑） | 慢一拍 |

**辨析｜易错点：** 米利机输出在**转移边上**、摩尔机输出在**状态圈上**——画图时别标错位置。而且两类机器**能力等价**（能算同样的输入-输出函数），只是实现风格不同。**"等价但实现差异"** 是理解两类机最关键的视角。

## 3 公式解析：设计一个米利机

**例**：设计识别"输入串以 01 结尾时输出 1，否则输出 0"的米利机。

**状态设计**：

- $s_0$：还没读到有效的后缀（重置点）。
- $s_1$：刚读到 0（有可能以 01 结尾）。

**转移表**：

| 状态 | 输入 0 | 输入 1 |
| --- | --- | --- |
| $s_0$ | $s_1 / 0$ | $s_0 / 0$ |
| $s_1$ | $s_1 / 0$ | $s_0 / 1$ |

- **第一步，定状态**：只需要两个状态——"是否刚读到 0"。记忆需求决定了状态数。
- **第二步，写转移**：$s_0$ 读 0 → 到 $s_1$（记住"刚读了 0"）；$s_1$ 读 1 → 输出 1（形成 01）、回 $s_0$。
- **第三步，输出函数**：输出标在转移边：$g(s_1, 1) = 1$，其余 0。

**这个例子的要点**：**状态 = 记住的必要信息**。设计 FSM 的第一步永远是问"为了算对输出，机器必须记住关于输入的哪些事？"——这里只需记"上一个字符是不是 0"。

## 4 FSM 的应用与局限

**应用**：

- **词法分析**：正则匹配（识别关键字、标识符）——下一节的语言识别。
- **协议状态机**：TCP、HTTP 的状态迁移。
- **数字电路**：时序电路的控制器。
- **游戏与 UI**：角色状态、流程控制。

**局限（预告）**：FSM 的状态数**有穷**，所以它只能"记住有穷多信息"。像"检查括号是否匹配且嵌套任意深"这类需要**无限记忆**的任务，FSM 做不到——那需要下推自动机或图灵机（本篇后面）。**有穷记忆是有穷状态机的天花板**，也是通向更强调算模型（图灵机）的动机。

<span class="marginnote">FSM 最小化（合并等价状态，行为不变）是工程与理论的双料主题：状态等价是等价关系（第十篇）、最小化算法把"多余状态"消掉——我们在"等价关系与划分"一节学的等价类在此直接使用。<strong>状态等价 = 等价类；最小化 = 划分压缩</strong>。</span>

## 5 米利机与摩尔机的等价性

两类机器看似不同（输出时机不同），但**能力完全等价**——能实现的输入-输出函数一样。这由两条转换定理保证。

**定理**：每个摩尔机都能转换成等价的米利机，反之亦然。

**摩尔 → 米利**：摩尔机输出 $g(s)$ 依赖状态。转换：把输出从状态搬到**进入该状态的转移边上**——米利机在转移时输出，输出值取"目标状态"的摩尔输出。

**例**：摩尔机状态 $s_1$ 输出 1（进入 $s_1$ 就输出 1）。转米利：任何进入 $s_1$ 的转移边标输出 1。

**米利 → 摩尔**：米利输出 $g(s,x)$ 依赖输入。转换：把"状态 + 输入"拆成更多状态，使输出只由状态决定——状态数可能增加。

**公式解析：转换的本质是"信息挪位置"**

摩尔机 $M_{Moore}$：$g: S \to O$（输出只看状态）。米利机 $M_{Mealy}$：$g: S \times I \to O$（输出看状态 + 输入）。

$$
\text{摩尔} \to \text{米利}:\ g'(s, x) = g(s'), \quad s' = f(s, x)
$$

- **第一步，读摩尔→米利**：转移边 $(s,x) \to s'$ 上标输出 $g(s')$——"进入即输出"，与摩尔语义一致。
- **第二步，读米利→摩尔**：若两个转移 $(s,x_1) \to s'$、$(s,x_2) \to s'$ 输出不同，就把 $s'$ 拆成两个状态，各自带各自输出。
- **第三步，读能力等价**：往返转换都保持输入-输出函数——**两类机器算同样的函数**。∎

**工程取舍**：摩尔机状态多但"输出稳定"（入态即定），米利机状态少但"输出与输入同拍"。**时序电路设计里，摩尔机输出不易有毛刺，米利机响应更快**——选型看需求。

**辨析｜易错点：** 转换时别忘**初始输出**。摩尔机初始状态就有输出；转米利时"还没读任何输入"的输出要单独约定（通常设一个初态输出）。**边界的初始输出最容易漏**。

**这个例子的要点**：米利与摩尔"能力等价、风格不同"——这是计算机科学里常见的"表示等价"现象（类似 NFA/DFA 等价）。**选哪种看工程偏好，数学能力无差别**。

## 6 小结

- **FSM** = 状态集 + 输入/输出字母表 + 转移函数 + 输出函数 + 初始状态。
- 状态图 = 带标边的有向图，图论的直接应用。
- **米利机**：输出依赖状态+输入（边上标输出）；**摩尔机**：输出依赖状态（状态上标输出）。
- 设计第一步：确定"机器要记住什么"——记忆决定状态。
- FSM 记忆有穷，需要无限记忆的问题要更强的模型。
