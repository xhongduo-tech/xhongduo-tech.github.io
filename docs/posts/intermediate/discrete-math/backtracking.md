## 为什么"试错"能成为正式算法

很多问题的解空间巨大（$n$ 皇后、数独、图着色），但可以**增量构造**：一次放一个决策，每步检查是否还能救活。**回溯法（backtracking）**就是这样一种系统化的深度优先搜索——在解空间树上 DFS，一旦发现当前部分解**不可能**扩展成完整解，就**剪枝**回头。它是"穷举 + 剪枝"的教科书形态，也是很多 NP 难问题的实际求解器。<span class="marginnote">回溯法是第三级《算法设计与分析》约束满足问题（CSP）的核心：8 皇后、数独、图着色、正则匹配回溯、以及 SAT 求解器（DPLL）全是它的化身。大模型推理里的"自我纠错"与"树搜索"（MCTS、ToT）也共享"分步构造 + 剪枝"的精神——<strong>在搜索树上做深度优先，是组合问题最通用的求解框架</strong>。</span>

## 1 回溯的基本框架

**回溯法**：增量构造解，每步选择 + 约束检查；若当前部分解与约束冲突，回溯到上一步换选择。

**通用骨架**：

```text
procedure backtrack(部分解 S)
    if S 是完整解
        record(S)                       // 记录一个完整解
        return
    for each 候选选择 c
        S ← S ∪ {c}                     // 做选择
        if S 满足约束（可能扩展成完整解）
            backtrack(S)                // 递归深入
        S ← S \ {c}                     // 撤销选择（回溯）
```

**关键**：**剪枝**——提前排除不可能的分支，避免无谓探索。剪枝条件越强，搜索树越小。

## 2 n 皇后问题

**问题**：在 $n \times n$ 棋盘放 $n$ 个皇后，使任意两个不同行、不同列、不同对角线。

**建模**：逐行放置。第 $i$ 行放第 $i$ 个皇后，选择列 $c_i$。约束：不同列、对角线不冲突。

**回溯过程**（$n=4$ 例）：

- 第 1 行放列 1。
- 第 2 行尝试列 1（同列，剪）、列 2（同对角线，剪）、列 3（可行）。
- 第 3 行：所有列都与前两个冲突 → 无可行 → **回溯**，回第 2 行换列 4。
- 第 3 行列 2 可行；第 4 行尝试后无解 → 继续回溯……
- 直到找到解或搜索完。

**剪枝检查**：放 $(i, j)$ 前检查"是否已有皇后在列 $j$ 或对角线 $i-j$ / $i+j$"——用三个数组维护占用即可 $O(1)$ 检查。

**复杂度**：最坏 $O(n!)$ 种放置，但剪枝后实际远小。$n=8$ 时解 92 个，回溯瞬间完成。

## 3 公式解析：回溯树与剪枝

回溯的搜索空间是一棵**回溯树（state-space tree）**：根是空解，每层是一个决策，叶是完整解或死胡同。

**以 $n=4$ 皇后的前两步为例**：

$$
\text{第1行: } [1], [2], [3], [4] \quad (\text{4 分支})
$$

$$
\text{第2行从 } [1] \text{ 出发: } [1,3], [1,4] \quad (\text{列 1,2 被剪})
$$

- **第一步，树的广度**：每层候选数 = 剩余可行选择。
- **第二步，剪枝消枝**：约束检查提前砍掉分支，树变瘦。
- **第三步，DFS 遍历**：深度优先访问，遇死胡同回退——**回溯 = 带剪枝的 DFS**。

**为什么"部分解 + 剪枝"正确**：若部分解已违反约束，任何完整扩展都违反——剪枝安全（不会漏掉解）。**剪枝只删"不可能"，不删"可能"**，这是回溯正确性的根本。

**辨析｜易错点：** 回溯最易错的是**忘记撤销**。深入前修改状态，返回后要**还原**（撤销上一步的选择），否则后续分支带着脏状态。实践中用"选前标记、回退时撤销"的成对操作，或拷贝传参。

## 4 回溯的应用图谱

| 问题 | 决策 | 约束 |
| --- | --- | --- |
| n 皇后 | 每行放哪列 | 列/对角线不冲突 |
| 数独 | 每格填什么数 | 行/列/宫不重复 |
| 图着色 | 每个顶点什么色 | 相邻异色 |
| 子集和 | 每个数取不取 | 和 ≤ 目标 |
| 正则匹配 | 字符匹配或回溯 | 模式语法 |
| SAT 求解 | 每个变量真假 | 子句全部满足 |

**例（子集和）**：从 $\{3, 5, 6, 7\}$ 找和为 14 的子集。回溯：取 3 → 取 5 → 取 6（超 14，剪）→ 回溯 → 取 7（15，剪）→ 回溯取 5 不取……最终 `$3`+6+5=14$ 或 `$7`+...$ 试出解。

**为什么有些问题只能回溯**：n 皇后、数独等问题的判定是 NP 完全——没有多项式算法；回溯 + 剪枝是实际可用的"最坏指数、通常很快"的求解器。

<span class="marginnote">回溯在现代 AI 里以<strong>约束满足与搜索</strong>的形态复活：SAT 求解器的 DPLL、规划问题的状态空间搜索、以及大模型推理的 Tree-of-Thoughts（把推理展开成搜索树，失败分支回溯）——"分步构造 + 剪枝 + 回溯"是跨越教科书与前沿的共同骨架。第四级《最优化理论》与《AI 智能体》里会反复再见。</span>

## 5 一个完整实例：子集和问题的回溯

把回溯的三板斧（选择、约束、撤销）走一遍完整流程。**问题**：给定集合 $\{3, 5, 6, 7\}$，找出所有和为 $14$ 的子集。

**建模**：决策是"每个数取或不取"，共 `$2`^4 = 16$ 种子集。回溯逐层决定：

- 取 3 → 取 5 → 取 6（和 14，**记录**）→ 继续取 7（和 21 超限，剪枝）→ 回溯。
- 不取 6 → 取 7（和 15 超限，剪枝）→ 回溯；不取 5 → 取 6 → 取 7（和 16 超限，剪）→ 回溯。
- 不取 3 → 取 5 → 取 6 → 取 7（和 18 超限，剪）→ 回溯……
- 继续穷尽，得解 $\{3, 5, 6\}$。

**公式解析：剪枝的不等式**

第 $k$ 步当前和为 $s_k$，剩余可加的最大值为 $R_k$（尚未考虑的数的和）。剪枝条件：

$$
s_k + R_k < \text{目标} \implies \text{剪枝}
$$

- **第一步，读下界**：当前和加上剩余最大值都够不到目标，后面无论如何都无解——**安全剪枝**。
- **第二步，读上界**：若 $s_k$ 已超目标，同样剪枝（本例子集和单调增，和一旦超就回不去）。
- **第三步，读正确性**：剪枝只删"必然无解"的分支，不漏解。

**这个例子的要点**：回溯的工程效率全在剪枝条件——条件越紧，搜索树越瘦。子集和问题"排序后剪枝"（先考虑大数）通常比随机顺序快得多。**"先试最有希望的分支 + 剪枝"** 是回溯优化的通用法则。

## 6 小结

- **回溯** = 增量构造 + 约束检查 + 剪枝 + DFS；"聪明的穷举"。
- 剪枝只删不可能的分支，保证不漏解。
- **n 皇后**：逐行放、检查列/对角线，$O(1)$ 剪枝检查。
- 回溯 = 带剪枝的 DFS（状态空间树）；剪枝越强搜索越瘦。
- 回溯适用 NP 难组合问题，是实际求解器的通用骨架。
