## 为什么同一句算术有三种写法

日常写 `a + b` 这种形式叫**中缀记法（infix）**。但计算机科学家很早就发现：把运算符放前面（**前缀 / 波兰记法**）或放后面（**后缀 / 逆波兰记法**）有巨大好处——**不需要括号，也不依赖优先级**，因为运算顺序被位置完全编码了。这三种写法恰好对应表达式的三种树遍历：中序、前序、后序。这一节把算术表达式翻译成树，再翻译成三种线性记法。<span class="marginnote">后缀记法是栈计算的经典教材：后缀表达式用一张栈就能求值，无需考虑优先级。这正是第四级《编译原理》里表达式求值、以及第三级《数据结构》"栈的应用"的核心。而"表达式 → 树 → 遍历"的管线，是语法分析的微缩模型。</span>

## 1 表达式树与三种记法

**表达式树（expression tree）**：二叉树的叶是操作数，内点是运算符，括号体现为树结构。

**三种记法 = 三种遍历**：

**中缀**：中序遍历——运算符在中间。`a + b`
**前缀（波兰记法）**：前序遍历——运算符在前。`+ a b`
**后缀（逆波兰记法）**：后序遍历——运算符在后。`a b +`

**例**：表达式 $a + b \times c$ 的树：根 $+$，左子树是 $a$，右子树是 $\times(b, c)$。

前序（前缀）：`+ a × b c`
中序（中缀）：`a + b × c`——注意需要括号区分 `a + (b × c)` 与 `(a + b) × c`！
后序（后缀）：`a b c × +`

**关键**：**中缀依赖括号与优先级**，前缀/后缀不需要。

## 2 公式解析：后缀记法为什么无歧义

后缀表达式 `a b c × +` 的求值用**栈**：

1. 从左到右扫描，遇操作数压栈；
2. 遇运算符，弹出两个数，运算，结果压回；
3. 扫描结束，栈顶即结果。

**实例**：`1 2 3 * +`：压 $1$；压 $2$；压 $3$；遇 $*$ 弹 $3$ 算 `$2` \times 3$ 压回；遇 $+$ 弹 $6$ 算 `$1` + 6$ 压回。结果 $7$。

**第一步，操作数进栈**：每个数都"攒着"等运算符。
**第二步，运算符消化**：弹两个最新的数运算——"后进先出"保证最近的数被最先使用。
**第三步，顺序即结构**：没有括号、没有优先级——**运算符的"触发时机"由它出现的位置决定**。

**为什么无歧义**：前缀码的思想（上一节）在这里重演——后缀记法是一种"运算符后置"的线性编码，每个运算符恰好作用于它前面的两个操作数/中间结果，栈的状态唯一决定运算树。

**例**：`1 2 + 3 *` 求值：压 1、压 2、遇 $+$ → 3、压 3、遇 $*$ → 9。而中缀 `$1` + 2 \times 3$ 需要优先级才知是 7（先乘）还是 9（先加）——后缀直接给出 9。

**辨析｜易错点：** 后缀求值时**弹出的两个操作数顺序**很重要：`b c -` 是 $b - c$ 而非 $c - b$。第一个弹出的是右操作数、第二个是左操作数。**减法和除法顺序敏感**，这是后缀求值最常见的 bug。

## 3 中缀转后缀

把中缀表达式转成后缀（计算机里编译器要做的第一步）：

**调度场算法（shunting-yard）**，核心规则：扫描中缀，操作数直接输出；运算符与栈顶比较优先级——栈顶优先级 ≥ 当前则弹出（输出），当前入栈；左括号入栈，右括号弹到左括号。

**例**：`a + b * c` → `a b c * +`：

输出 $a$；$+$ 入栈；输出 $b$；$*$ 入栈（优先级高于栈顶 $+$）；输出 $c$；结束，弹栈输出 $*$、$+$。
结果 `a b c * +`。✓

**为什么要弹出高优先级**：$b \times c$ 的乘法必须先生成，所以 $*$ 要先于 $+$ 输出——**高优先级运算符在栈里"插队"**。括号则强制分组。

## 4 前缀与后缀的对称性

前缀记法（如 `+ a b`）与后缀对称：**从右往左扫描 + 栈**求值。它们的共同优势：

| 记法 | 求值方向 | 需要括号？ | 需要优先级？ |
| --- | --- | --- | --- |
| 中缀 | — | 是 | 是 |
| 前缀 | 右→左 | 否 | 否 |
| 后缀 | 左→右 | 否 | 否 |

**为什么工程用后缀多**：前缀需从右往左扫描（或先反转），后缀天然支持从左到右的单遍扫描 + 栈——与 CPU/解释器顺序执行契合。**表达式的"可计算性"由栈编码**。

<span class="marginnote">表达式求值在第四级《编译原理》的词法/语法分析里是"求值器"的入门实现；而 Lisp 家族语言直接用前缀记法（如 `(+ 1 2)`）作为核心语法——前缀记法的括号就是函数调用结构。<strong>三种记法是同一棵语法树的三张照片</strong>。</span>

## 5 从中缀到后缀的完整例子：括号与优先级

调度场算法 + 一个带括号的例子，把"中缀转后缀"彻底讲透。

**例**：中缀 $(a+b) \times (c-d)$ 转后缀。

**调度场算法**：扫描，操作数直接输出；运算符与栈顶比优先级，栈顶 ≥ 当前则弹出；左括号入栈；右括号弹到左括号。

| 扫描 | 输出 | 栈 |
| --- | --- | --- |
| ( | | ( |
| a | a | ( |
| + | a | ( + |
| b | a b | ( + |
| ) | a b + | （弹到左括号，栈空） |
| × | a b + | × |
| ( | a b + | × ( |
| c | a b + c | × ( |
| - | a b + c | × ( - |
| d | a b + c d | × ( - |
| ) | a b + c d - | ×（弹到左括号） |
| 结束 | a b + c d - × | 弹空 |

结果：`a b + c d - ×`。

**公式解析：为什么括号被"消费"掉**

- **第一步，读左括号**：左括号入栈，标记"这层括号开始"。
- **第二步，读右括号**：弹出到左括号为止的**全部运算符**——括号内的运算符在括号结束前必须输出。
- **第三步，读效果**：括号不出现在后缀里，但它的"分组"效果被保留（括号内运算符先输出）。∎

**验证求值**：`a b +` 得 $(a+b)$，`c d -` 得 $(c-d)$，最后 `×` 相乘——与中缀 $(a+b)*(c-d)$ 一致。✓

**辨析｜易错点：** 右括号弹出时**左括号本身不输出**（只弹不掉）。若把左括号也输出，后缀就混入非法符号。**"弹到左括号为止，左括号丢弃"**是调度场最常错的细节。

**这个例子的要点**：中缀转后缀 = 调度场算法，它是编译器表达式求值的标准前奏。**"括号决定优先级，栈决定顺序"**——理解了栈的进出时机，转换就是机械流程。

## 6 小结

- **中缀**=中序遍历、**前缀**=前序遍历、**后缀**=后序遍历——同一表达式树三种线性化。
- 中缀要括号/优先级；前缀与后缀**天然无歧义**。
- 后缀求值：单遍扫描 + 栈，操作数压栈、运算符弹两数。
- 中缀转后缀：调度场算法，栈维护优先级。
- 减/除操作数顺序敏感：先弹右操作数、后弹左操作数。
