## 为什么从搜索开始

上一节我们建立了算法的概念与伪代码。现在让算法处理第一个经典问题：**搜索（searching）**——在一串数据里找某个目标。搜索是人类最古老的信息需求，也是现代计算机最频繁的运算：在通讯录里找人、在数据库里查记录、在词表里找下一个 token，本质都是同一件事。<span class="marginnote">「从极限到大模型」的每一步几乎都有搜索的影子：向量检索系统在海量向量里找最相似者、推荐系统的 top-k 查询、大模型推理时从词表里找概率最大的候选。<strong>搜索是「在大数据里定位」的元能力</strong>，第三级《数据结构》、第四级《信息检索》都会在它之上起高楼。</span>

这一节给出两个对照鲜明的算法：**线性搜索**（不要求任何前提，从前往后逐个找）与**二分搜索**（要求数据有序，利用「折半」换来对数级提速）。透过它们，你会第一次尝到**用「有序」这一结构信息换「速度」**的滋味——这个「以结构换效率」的主题，将贯穿排序、树、图与整个算法设计。

## 1 问题设定：搜索与它的复杂度

**搜索问题**：给定一个目标元素 $x$ 与一个序列 $a_1, a_2, \dots, a_n$，若 $x$ 出现在序列中，找出它的位置；否则报告「不在」。

这个问题的输出是**位置索引**或「未找到」——用伪代码习惯，位置 $i$ 表示 $x = a_i$，找不到时用 0 表示。度量搜索算法最自然的「基本操作」是**比较次数**：$x$ 与序列元素比了几次。<span class="marginnote">为什么以「比较次数」为尺子？因为它与数据大小、机器速度无关，只取决于算法的策略。<strong>复杂度分析的三大情形</strong>——最好（best）、最坏（worst）、平均（average）——在这一节第一次全部登场，是第五篇《算法复杂度》的预演。</span>

两个算法面对的数据条件不同：

- **线性搜索**：对**任意**序列都可用（无需排序）。
- **二分搜索**：要求序列**已按递增排序**。

「要不要多花一次排序的代价，换取每次搜索更快」——这是一个工程权衡，下一节排序篇会给出答案。

## 2 线性搜索：朴素而坚韧

**线性搜索（linear search）**：从第一个元素开始，依次与 $x$ 比较，直到找到或到末尾。伪代码如下：

```text
procedure linearSearch(x, a1, a2, …, an)
    for i ← 1 to n
        if x = ai
            return i                    // 找到，返回位置
    return 0                            // 未找到
```

这个算法**不要求任何结构前提**，哪怕数据乱成一团也能工作。它的性格一目了然：

- **最好情形**：$x$ 恰好就是 $a_1$，只比 1 次。
- **最坏情形**：$x$ 是最后一个，或者根本不在——要扫完整个序列，比 $n$ 次。
- **平均情形**：若 $x$ 一定在序列中且等可能地出现在每个位置，则位置 $k$ 需要 $k$ 次比较，平均为
  $$
  \frac{1 + 2 + \cdots + n}{n} = \frac{n+1}{2}
  $$

**重点：线性搜索的复杂度是 $\Theta(n)$——数据翻一倍，最坏代价也翻一倍。** 它朴素，却不笨：当数据无序、或者 $n$ 很小、或者你只搜一次时，它没有预处理成本，往往是最划算的选择。<span class="marginnote">注意「平均情形」依赖一个概率假设：目标等可能出现在每个位置。若目标从不出现，平均情形就是最坏情形 $n$。<strong>先声明概率模型，再谈平均复杂度</strong>——这个习惯在第二级《概率论与数理统计》与算法随机化分析里会反复用到。</span>

## 3 二分搜索：用有序换效率

**二分搜索（binary search）**：在**递增序列**中，每次把目标与「中间元素」比较，据此把搜索范围**砍掉一半**。伪代码：

```text
procedure binarySearch(x, a1, a2, …, an)   // 前提：a1 ≤ a2 ≤ … ≤ an
    i ← 1;  j ← n
    while i < j
        m ← ⌊(i + j) / 2⌋
        if x > am
            i ← m + 1                     // 目标在右半，左边界跳到 m+1
        else
            j ← m                         // 目标在左半（含 m），右边界收至 m
    if x = ai then return i else return 0
```

为什么对？**循环不变量（loop invariant）**：每一轮开始时，目标 $x$（如果存在）一定落在闭区间 $[i, j]$ 内。每次迭代，我们把区间缩小到原来的约一半，且不变量保持成立——于是当 $i = j$ 时，区间只剩一个候选位置，检查它即可。<span class="marginnote">这里 $i = j$ 的写法是 Knuth 所提醒的「棘手细节」之一：因为 $a_m$ 与 $x$ 相等时也不能丢掉它，所以右边界收缩到 $j := m$ 而不是 $m-1$，左边界则安全地跳到 $m+1$。<strong>边界条件的每一个 +1 / −1，背后都是一句不变量论证</strong>。</span>

**辨析｜易错点：二分搜索要求「递增」且取整方向要与边界一致。** 三个经典错误：①对无序序列用二分——结果完全错误；②忘记下取整 $\lfloor (i+j)/2 \rfloor$，用「向零取整」的编程语言默认行为时搞混边界；③退出条件写成 `i < j` 导致死循环或漏检。**写二分搜索的黄金法则是：先写不变量，再写代码**，让每一处边界都由不变量驱动。

## 4 公式解析：二分搜索的比较次数

二分搜索最坏要比较多少次？设比较次数为 $T(n)$。每次比较后，搜索区间至少缩小一半，于是

$$
T(n) \le T\!\left(\left\lfloor \frac{n}{2} \right\rfloor\right) + 1, \qquad T(1) = 1
$$

分三步拆解这条递推：

- **第一步，读懂递推**：一次比较确定 $x$ 落在哪一半，剩下规模至多 $\lfloor n/2 \rfloor$；那一次比较计入 $+1$。$T(1)=1$ 是因为只剩一个元素时，仍要一次最终比较（`a_i == x`）确认是否命中。
- **第二步，展开（unwrap）**：设 $n = 2^k$（先看最理想的情形）。$T(2^k) = T(2^{k-1}) + 1 = T(2^{k-2}) + 2 = \cdots = T(1) + k = k + 1$。
- **第三步，翻译回 $n$**：$k = \log_2 n$，所以 $T(n) = \log_2 n + 1$。对一般的 $n$，向下取整带来至多多一次比较，故最坏情形不超过 $\lfloor \log_2 n \rfloor + 1$。Rosen 的结论正是：**二分搜索最坏做 $\lfloor \log_2 n \rfloor + 1$ 次比较**。<span class="marginnote">从 $n$ 到 $\log_2 n$ 是什么体验？$n = 10^6$ 时，线性搜索最坏要百万次比较，二分搜索只要约 21 次。<strong>对数级是「指数级灾难的镜像」</strong>——指数让 $2^{20}$ 爆炸成百万，对数让百万收回成 20。第四级《大模型原理》里，$\log$ 级的检索结构（如跳表、近似最近邻）正是靠这个魔法在亿级数据里实时搜索。</span>

把两种搜索放进一张表对照，复杂度差距一目了然：

| 算法 | 前提 | 最好 | 最坏 | 平均（目标必在） |
| --- | --- | --- | --- | --- |
| 线性搜索 | 无 | $1$ | $n$ | $\dfrac{n+1}{2}$ |
| 二分搜索 | 递增有序 | $1$ | $\lfloor \log_2 n \rfloor + 1$ | $\approx \log_2 n$ |

**重点：二分搜索的提速来自「有序」这一结构信息。** 没有序，就没有「中间元素能告诉你往哪边找」这个魔法。这引出一个贯穿全部算法的深刻主题——**信息决定效率**：你利用了输入的结构信息越多，付出的计算代价就越少。<span class="marginnote">这条主题会反复出现：排序算法利用「比较交换」逐步建立序，树的遍历利用「层级结构」组织访问，图算法利用「邻接关系」剪枝。<strong>「以结构换效率」是离散数学递给计算科学最贵重的礼物。</strong></span>

**数值体验**：在 $n = 10^6$ 条记录里搜索一次，线性搜索最坏要扫 100 万次；二分搜索只要 $\lfloor \log_2 10^6 \rfloor + 1 = 19 + 1 = 20$ 次比较。假设每次比较耗时 10 纳秒，线性搜索最坏约 10 毫秒，二分搜索约 0.2 微秒——五万倍的差距，而且随 $n$ 增大还会继续拉开。<span class="marginnote">$\lfloor \log_2 10^6 \rfloor = 19$，因为 $2^{19}=524288$、$2^{20}=1048576$。<strong>把对数想成"翻倍次数"</strong>：$10^6$ 每次砍半，砍约 19 次才剩 1 个。</span>

## 5 搜索的工程与思想遗产

搜索算法的价值远超「找一个数」本身：

**数据库索引**：第三级《数据库》里，B+ 树索引本质上是一个多路二分搜索——每次比较把候选范围缩小到 $1/m$，磁盘读的次数从 $n$ 降到 $\log_m n$ 量级。<span class="marginnote">「二分」的思想可以推广到「多分」：每次把区间切成 $m$ 段而不是 2 段，比较次数降到 $\log_m n$。数据库用大扇出 $m$ 的树，正是因为磁盘每次读一大块数据，多分能压榨每次读盘的效率。</span>
- **查找与判定**：从「查字典」「找单词是否在词典里」到「判断一个数是否在集合中」，都是搜索的变体；配合第七篇的**二分法求根**（连续版本的二分搜索），它还是数值计算的常用武器。
- **大模型解码**：生成下一个 token 时，模型对词表打分后要做「搜索」——argmax 是找最大分，采样是带权随机搜索。**搜索是决策的基础操作**，第四级《大模型原理》的采样算法正是搜索思想的概率版本。

## 6 小结

- **搜索问题**：找目标 $x$ 在序列 $a_1,\dots,a_n$ 中的位置，否则报告不存在。
- **线性搜索**：无前提，从头扫到尾；最好 $1$、最坏 $n$、平均 $(n+1)/2$ 次比较，复杂度 $\Theta(n)$。
- **二分搜索**：要求递增；每次比较把区间折半；最坏 $\lfloor \log_2 n \rfloor + 1$ 次比较，复杂度 $\Theta(\log n)$。
- **循环不变量**驱动二分搜索的正确性；边界 `j := m`/`i := m + 1` 必须由不变量论证。
- **以结构换效率**：有序这一信息，把搜索从线性级降到对数级。
- 搜索是数据库索引、数值求根、大模型解码的共同底层。

在下一节，我们把「有序」这个宝贝亲手造出来——**排序算法**：冒泡排序与插入排序。你会发现，排序的复杂度分析，正是前面双重求和与伸缩求和的直接应用。
