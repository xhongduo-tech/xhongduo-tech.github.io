# 图灵机：定义与计算

## 为什么图灵机是"计算"的终点

前面我们一路升级识别器：FSM 有穷记忆 → NFA 加非确定 → 下推自动机（教材略）加栈。但**记忆永远有穷**，很多函数算不了。**图灵机（Turing machine）**把记忆换成**无限长的纸带**——在纸上读写、左右移动、按状态表决定下一步。这个 1936 年提出的抽象机器，成了"可计算"的**定义**：一个函数可计算 ⟺ 能被某台图灵机计算（丘奇-图灵论题）。现代计算机的一切计算，本质上都在模拟图灵机。<span class="marginnote">图灵机是计算机科学的"原点"：冯·诺依曼体系、通用图灵机（一台机器模拟所有机器）直接启发了"存储程序计算机"。而"图灵完备"（编程语言能否模拟图灵机）是现代语言能力评级的标尺——从 Lisp 到神经网络到 RNN 到注意力机制，都在被问"它图灵完备吗"。</span>

## 1 图灵机的定义

**图灵机（Turing machine）** $T = (S, I, f, s_0)$：

- $S$：状态有穷集。
- $I$：**带字母表（tape alphabet）**，含特殊符号 `B`（空白）。
- $f$：**部分函数** $f: S \times I \to S \times I \times \{R, L\}$——(当前状态, 读到的符号) → (新状态, 写下的符号, 左移/右移)。
- $s_0$：初始状态。

**纸带**：无限长的格子，每个格子一个符号（初始含 `B` 空白）。**读写头**指向当前格子。

**一步计算**：读当前符号 $x$，查表 $f(s, x)$，若未定义则**停机**；否则写新符号、移头、换状态。

**例**：把输入的 0 改写成 1 的图灵机：状态 $s_0$：读 0 → (写 1, 右移, $s_0$)；读 `B` → 停机。

## 2 图灵机如何"算"

**计算语言（识别）**：给输入串（写在纸带上），图灵机从 $s_0$ 开始运行。**接受**：进入某个接受状态（约定）停机；**拒绝**：在其他状态停机或无限循环。图灵机识别的语言 = 所有被接受的串。

**计算函数**：把输入编码在纸带上，停机时纸带内容 = 输出。图灵机计算一个函数 $f$：对每个输入 $x$，停机且输出 $f(x)$。

**例（加法器）**：给 `111`（表示 3）与 `11`（表示 2），机器把它们变成 `11111`（5）——纸带符号的机械操作完成算术。

**为什么"无限纸带"是关键**：内存无限 = 能记住任意多的中间信息。FSM 卡在"有穷记忆"，图灵机解开这个束缚——**无限记忆 + 有穷规则**，就是"通用计算"的全部配方。

## 3 公式解析：设计一台图灵机

**例**：设计识别语言 $\{0^n 1^n \mid n \ge 1\}$ 的图灵机（$n$ 个 0 后 $n$ 个 1）——这是 FSM 做不到的语言。

**思路**：来回配对——把最左的 0 改成 X，把最右的 1 改成 Y，反复直到全部配对。

状态设计（简化）：

- $s_0$：向右找最左的 0，改成 X，转 $s_1$。
- $s_1$：向右找最右的 1，改成 Y，转 $s_0$。
- $s_2$（接受）：扫描全带只有 X、Y 与 B。

**运行**：`0011` → X011 → X01Y → XX1Y → XXYY → 接受 ✓。串 `010`：配对到 X0Y 后剩余 `0` 无法配对 → 拒绝。

- **第一步，设计"配对"策略**：匹配一个 0 与一个 1，用 X/Y 做标记——**纸带 = 可改写的草稿纸**。
- **第二步，写状态表**：每个状态 + 符号 → 动作；向右/向左来回扫描。
- **第三步，定接受条件**：全部配对完毕即接受。

**这个例子说明**：图灵机用"标记 + 移动"完成 FSM 做不到的"计数配对"——**纸带的无限长度是记忆的来源**。`0^n1^n` 是经典"证明图灵机比 FSM 强"的例子。

**辨析｜易错点：** 图灵机的 $f$ 是**部分函数**——未定义就停机。设计时"停机"要分清是"接受停机"还是"拒绝停机"（或永不停止）。**无限循环是第三种可能**，它在可计算性理论里至关重要（下一节停机问题）。

## 4 图灵机与现代计算的对应

**丘奇-图灵论题（Church–Turing thesis）**：一切"可直觉计算"的函数都是图灵机可计算的。这不是可证明的定理，而是被广泛接受的**论题**——因为无数替代模型（λ 演算、递归函数、寄存器机、现代编程语言）都被证明与图灵机等价。

**通用图灵机（universal Turing machine）**：一台图灵机把"另一台图灵机的描述 + 它的输入"作为输入，模拟那台机器的运行——**一台机器能算所有可计算函数**。这是"存储程序计算机"（冯·诺依曼）的思想源头。

**图灵完备**：一个系统（语言/芯片/框架）若能模拟通用图灵机，则它能计算一切可计算函数。现代编程语言、甚至很多"意外"的系统（单指令集、生命游戏、注意力机制）都被证明图灵完备。

<span class="marginnote">"图灵完备性"在现代 AI 语境里频繁出现：RNN 被证明图灵完备，Transformer 在特定假设下也逼近图灵完备。但完备 ≠ 实用——<strong>图灵完备只回答"能不能算"，不回答"算得多好"</strong>。这是下一节可计算性的边界（什么算不了）的前提：即使最强模型，也有不可计算的问题。</span>

## 5 一个图灵机的完整运行：状态表的阅读

把"状态表驱动计算"完整走一遍，是理解图灵机的关键练习。

**例**：设计把输入"0/1 串"全部右移一位、末尾补 0 的图灵机（简化版）。状态表 $f$：

| 状态 | 读 0 | 读 1 | 读 B |
| --- | --- | --- | --- |
| $s_0$ | (写 0, 右, $s_0$) | (写 1, 右, $s_0$) | (写 0, 左, $s_1$) |
| $s_1$ | (写 0, 左, $s_1$) | (写 1, 左, $s_1$) | (写 B, 左, $s_2$) |
| $s_2$ | — | — | (写 B, 左, $s_3$) |

（$s_3$ 停机；$s_2$ 未定义项即拒绝——简化演示。）

**运行**：输入 `10B`（纸带 `1 0 B B...`，头在 1 处）。$s_0$ 读 1 → 写 1 右移；读 0 → 写 0 右移；读 B → 写 0 左移进 $s_1$；$s_1$ 向左回写（把 0 放到末尾）……

**公式解析：状态表 = 一小段程序**

$$
f(s, x) = (s', x', \text{方向}) \quad \text{—— 一条"指令"}
$$

- **第一步，读三元组**：每条转移 = 新状态、写符号、移动方向——**一次计算就是执行一条指令**。
- **第二步，读程序**：整张表 = 程序；状态 = 程序计数器；纸带 = 内存。
- **第三步，读停机**：$f$ 未定义处停机（接受/拒绝/终止）。∎

**图灵机 = 计算机的最小模型**：状态（控制）+ 纸带（内存）+ 状态表（程序）。现代 CPU 也是"状态 + 寄存器 + 指令表"，只是纸带换成随机访问内存。**理解图灵机 = 理解计算机的本质分工**。

**这个例子的要点**：图灵机的每一步都"简单到荒谬"（读一个格、写一个符号、移一格），但**有穷简单指令 + 无限纸带 = 通用计算**。这个"极小指令集"思想直接启发了 RISC 精简指令集与分层设计。

**辨析｜易错点：** 状态表的"未定义"与"明确定义"要分清——**未定义 ⟹ 停机**，可能是接受（进入接受态）也可能是拒绝（非接受态停机）。设计时明确"哪些未定义是接受、哪些是拒绝"。

## 6 小结

- **图灵机**：无限纸带 + 有穷状态表；读写头读/写/移，未定义即停机。
- 识别语言、计算函数都靠"停机时的状态/纸带内容"。
- **无限纸带 = 无限记忆**：让图灵机能算 $0^n1^n$ 等 FSM 算不了的问题。
- **丘奇-图灵论题**：可计算 ⟺ 图灵机可计算（论题非定理）。
- **通用图灵机**：一台模拟所有机器；图灵完备 = 能模拟它。

**小结补记**：图灵机是"可计算"的定义标尺——**有穷规则 + 无限纸带 = 通用计算**。丘奇-图灵论题把它与一切算法模型等价，通用图灵机则预告了存储程序计算机。下一节将揭示这台"万能机器"也有算不了的问题。
