## 为什么树要"遍历"

树的递归结构（根 + 子树）意味着"系统地访问每个顶点"有多种自然顺序。**前序、中序、后序遍历（preorder / inorder / postorder）**是三种最经典的访问顺序，各自服务于不同目的：前序输出目录结构、中序输出排序结果（BST）、后序计算子树信息。遍历是把"树"这个非线性结构**线性化**的基本手段，也是递归算法的第一堂实操课。<span class="marginnote">遍历是第三级《数据结构》二叉树章节的核心；前序/中序还能唯一确定一棵树。而遍历的递归实现正是第七篇递归算法的标准样例——每个遍历都是"访问根 + 递归左 + 递归右"的三段式。下一节的表达式记法（前缀/中缀/后缀）就是三种遍历的直接应用。</span>

## 1 三种遍历的定义

设二叉树的每个顶点记 `V`，左子树 `L`、右子树 `R`：

- **前序遍历（preorder）**：访问根 → 前序左子树 → 前序右子树。**VLR**。
- **中序遍历（inorder）**：中序左子树 → 访问根 → 中序右子树。**LVR**。
- **后序遍历（postorder）**：后序左子树 → 后序右子树 → 访问根。**LRV**。

**例**：树根 `+`，左子树是 `a`、右子树是 `*`（其左 `b`、右 `c`）。

- 前序：`+ a * b c`
- 中序：`a + b * c`
- 后序：`a b c * +`

**递归实现（前序）**：

```
procedure preorder(v):
    visit(v)
    preorder(左子 v)    # 若存在
    preorder(右子 v)
```

## 2 遍历的直觉与用途

| 遍历 | 顺序 | 典型用途 |
| --- | --- | --- |
| 前序 | 根 → 左 → 右 | 目录结构、复制树、前缀记法 |
| 中序 | 左 → 根 → 右 | **BST 升序输出** |
| 后序 | 左 → 右 → 根 | 先处理子树再处理根（删除树、表达式求值） |

**例（BST 中序）**：BST 中序遍历输出**升序**序列——因为中序是"左（小）→ 根（中）→ 右（大）"。这是一棵 BST 是否合法的快速检验法，也是"BST 排序"（tree sort）的基础。

**例（后序）**：删除一棵树要先删子树再删根；计算目录总大小要先算子目录再汇总——都是后序逻辑。

## 3 公式解析：遍历的递归展开

以中序 `LVR` 为例，看递归如何展开。设树根 $T$，左子树 $T_L$、右子树 $T_R$：

$$
\text{inorder}(T) = \text{inorder}(T_L) + [\text{根}] + \text{inorder}(T_R)
$$

- **第一步，读三段式**：中序 = 左子树的中序 + 根 + 右子树的中序。
- **第二步，递归替换**：$T_L$ 的中序继续按同一公式展开，直到叶（叶是"左空根右空"，输出叶本身）。
- **第三步，拼接**：层层展开后拼接成完整序列。∎

**实例展开**：树 `+ (a, *(b,c))` 的中序：

$$
\text{inorder}(+) = \text{inorder}(a) + [+] + \text{inorder}(*(b,c)) = a + [ + ] + (b + [*] + c) = a + b * c
$$

**关键**：**遍历是递归定义的"输出版"**——树的递归结构（第七篇结构归纳）直接翻译成递归遍历。三种遍历只差"访问根"的位置（前/中/后），代码结构几乎一样。

**复杂度**：三种遍历都访问每个顶点恰一次，$O(n)$ 时间、$O(h)$ 栈深（$h$ 为高度）。

**辨析｜易错点：** 中序的"左根右"顺序最易与后序"左右根"混淆。记忆锚：**名字里的"序"指根的访问时机**——前序=根最先、中序=根居中、后序=根最后。**看根的位置，不看左右**。

## 4 由遍历重建树

**定理**：给定一棵二叉树的前序与中序序列，可唯一重建原树（若各顶点键互异）。

**重建算法**：

- 前序第一个元素是根。
- 在中序里找根，根左边是左子树中序、右边是右子树中序。
- 用前序中对应的长度切出左右子树前序，递归重建。

**例**：前序 `ABDEC`、中序 `DBEAC`。根 = A。中序里 A 左是 `DBE`（左子树）、右是 `C`（右子树）。前序里 `BDE` 是左子树前序、`C` 是右子树前序。递归：左子树根 B，中序 `DBE` 中 B 左 `D`、右 `E`……重建完成。

**为什么需要两个序列**：单靠前序无法确定左右划分（不知道哪些属于左）；前序 + 中序的组合恰好锁定结构。这在第四级《编译原理》的语法树重建里是基础操作。

<span class="marginnote">"前序+中序重建树"是遍历信息的反问题：树→序列是编码，序列→树是解码。这类"编码-解码"对在第四级《信息论》里是"无歧义表示"的核心思想——<strong>序列必须携带足够的结构信息才能还原原对象</strong>。</span>

## 5 遍历的栈实现与"为什么递归够用"

遍历除了递归，还能用**显式栈/队列**实现——理解两者等价，是读懂迭代版遍历的关键。

**前序的迭代实现（显式栈）**：

```
procedure preorder_iter(root):
    stack := [root]
    while stack 非空:
        v := stack.pop()
        visit(v)
        push(v 的右子); push(v 的左子)   # 先压右，后压左
```

**为什么先压右再压左**：栈是 LIFO，后压的左子先弹出——保证"左子树先于右子树"，与前序 VLR 一致。

**公式解析：递归与栈的等价**

递归调用栈保存"未完成的工作"；显式栈手动管理同一份工作：

$$
\text{递归深度} \leftrightarrow \text{栈大小}, \qquad \text{调用/返回} \leftrightarrow \text{push/pop}
$$

- **第一步，读工作清单**：递归隐式用系统栈存"待访问的子树"。
- **第二步，读显式化**：迭代版用栈存"待处理的顶点"——同一份清单。
- **第三步，读顺序保证**：栈的压入顺序（先右后左）复刻递归的访问顺序。∎

**为什么通常用递归**：遍历的递归实现与树的结构定义（根+子树）逐行对应，几乎不会写错；栈深度 $O(h)$ 在平衡树上是 $O(\log n)$，安全。**显式栈仅在"栈溢出风险"或"需要控制顺序"时使用**（如非递归中序、Morris 遍历）。

**这个例子的要点**：遍历的递归与迭代是"同一算法的两种穿着"——**递归清晰、迭代可控**。理解"系统栈 = 显式栈"的对应，任何递归算法都能改成迭代（反之亦然）。

**辨析｜易错点：** 迭代中序不能照搬前序"先压右再压左"——中序要先走完左子树再访问根，需要"压根但暂不访问"的标记技巧。**三种遍历的迭代实现各不相同**，别互相套用。

## 6 小结

- **三种遍历**：前序 VLR、中序 LVR、后序 LRV——差在"访问根"的时机。
- 中序对 BST 输出升序；前序适合复制与目录；后序适合先子后根的归约。
- 遍历 = 递归三段式，$O(n)$ 时间、$O(h)$ 栈深。
- 前序 + 中序可**唯一重建**树。
- 遍历是树的"线性化"，下一节的表达式记法直接用它。
