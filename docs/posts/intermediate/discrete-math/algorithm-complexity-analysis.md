## 为什么需要真正的复杂度分析

前两节我们有了记号（$O$、$\Omega$、$\Theta$），但这只是**语言**。真正的战场是：给出一段算法（或一段代码），你能否**用这套语言说出它的运行时间与占用空间**？这就是**复杂度分析（complexity analysis）**——把算法的每一步抽象成基本操作，数出"操作总数随输入规模如何增长"。<span class="marginnote">复杂度分析是第三级《数据结构》所有章节的共同骨架：哈希表的均摊 $O(1)$、平衡树的 $O(\log n)$、图遍历的 $O(V+E)$，全部源自这里学会的"数基本操作"方法。</span>

## 1 最坏情形、平均情形与最佳情形

运行时间**随具体输入变化**。同一个二分搜索，目标在最中间位置时一步命中，在边缘时要走满 $\log n$ 步。于是分析要区分三种口径：

- **最坏情形（worst case）**：在所有输入中取**最大**运行时间，记为 $T_{\text{worst}}(n)$。
- **平均情形（average case）**：对输入按某种分布（通常均匀）取数学期望。
- **最佳情形（best case）**：在所有输入中取**最小**运行时间，记为 $T_{\text{best}}(n)$。

**最坏情形是默认选择**，原因有两条：一是它给出**承诺**——无论输入多刁钻，运行时间都不会超过这个上界，这正契合 $O$ 记号的语义；二是最坏输入通常结构清晰、容易分析，而平均情形常需要引入概率分布，复杂得多。<span class="marginnote">最坏情形分析在第二级《概率论与数理统计》之后可以进阶为"期望复杂度"：给输入赋分布再算期望。但工程上最坏的保证永远是第一位的——没人愿意自己的搜索在最坏输入上卡死。</span>

以线性搜索在 $n$ 个元素中找目标为例：目标在第一个位置是 $T_{\text{best}} = \Theta(1)$；目标不在数组里是 $T_{\text{worst}} = \Theta(n)$；若目标等概率出现在任意位置，平均比较次数是 $(1+2+\dots+n)/n = (n+1)/2 = \Theta(n)$。三者的 $\Theta$ 阶分别是常数、线性、线性。

## 2 基本操作计数：以插入排序为例

**复杂度分析的核心动作：把"运行时间"抽象为"基本操作的次数"。** 一次赋值、一次比较、一次算术运算都算一次基本操作，各自耗时假设为常数。于是运行时间 $\approx$ 基本操作总数 $\times$ 常数，后者被 $O$ 吞掉，剩下的就是"数操作"。

以插入排序为例，逐行数基本操作：

```python
def insertion_sort(a):              # n = len(a)
    for i in range(1, n):           # 外层循环
        key = a[i]                  # 1 次赋值
        j = i - 1
        while j >= 0 and a[j] > key:  # 内层比较
            a[j + 1] = a[j]           # 后移
            j = j - 1
        a[j + 1] = key              # 插入
```

- **最坏情形**：输入已降序排列时，第 $i$ 轮内层 while 要比较并后移 $i$ 次。总后移次数 $\sum_{i=1}^{n-1} i = n(n-1)/2$。
- **操作总数**：比较 + 赋值总数 $\approx n(n-1)/2 \cdot c$，加上外层循环的 $n$ 次迭代开销。
- **结论**：$T_{\text{worst}}(n) = \Theta(n^2)$。

**最佳情形**：输入已升序，每轮 while 第一次比较就失败，总操作 $\Theta(n)$。于是插入排序的完整复杂度画像是一张"上窄下宽"的表格：最好 $\Theta(n)$、最坏 $\Theta(n^2)$、平均 $\Theta(n^2)$。

**辨析｜易错点：** 数操作时最容易漏掉的是**内层循环实际执行的次数**。很多人把 while 写成 $O(n)$ 就完事，忘了它在最坏情形下每一轮几乎都会走满 $i$ 步——$i$ 本身随外层在变，必须把两层合起来算 $\sum i$，而不能简单地"外层 $\times$ 内层常数"。

## 3 公式解析：嵌套循环的复杂度求和

嵌套循环的总复杂度几乎总是落进一个求和式。对插入排序的最坏情形：

$$
T(n) = \sum_{i=1}^{n-1} i = \frac{n(n-1)}{2} = \frac{n^2 - n}{2} = \Theta(n^2)
$$

- **第一步，识别求和对象**：第 $i$ 轮内层循环执行约 $i$ 次基本操作，$i$ 从 1 到 $n-1$。
- **第二步，套等差数列公式**：$\sum_{i=1}^{m} i = m(m+1)/2$，令 $m = n-1$。
- **第三步，读出主导项**：$\frac{n^2 - n}{2}$ 的最高次项是 $n^2/2$，故 $\Theta(n^2)$。

再给一个三重循环的经典例题：`for i in range(n): for j in range(i): for k in range(j): 一步`。操作总数是

$$
\sum_{i=0}^{n-1} \sum_{j=0}^{i-1} \sum_{k=0}^{j-1} 1 = \sum_{i=0}^{n-1} \frac{i(i-1)}{2} = \frac{1}{2}\sum_{i=0}^{n-1}(i^2 - i) = \Theta(n^3)
$$

其中用了 $\sum i^2 = n(n+1)(2n+1)/6 = \Theta(n^3)$。**三层循环压出一个立方**——"嵌套层数"是最直观的复杂度量尺，但每层循环到底跑几圈仍需具体算。

## 4 空间复杂度

时间不是唯一的稀缺资源，**空间复杂度（space complexity）**刻画算法运行时占用的额外存储随输入规模的增长。它的数法同样是"数单元"：把每个变量、每个数组元素都算一个存储单元。

- **原地（in-place）算法**：只使用常数个额外变量，空间 $\Theta(1)$。插入排序、冒泡排序都是原地算法——交换只靠几个临时变量。
- **线性辅助空间**：需要一个与输入同规模的辅助数组，空间 $\Theta(n)$。归并排序的合并步骤需要 $\Theta(n)$ 的辅助数组。
- **递归的空间代价**：递归深度就是调用栈的规模，空间 $\Theta(\text{深度})$。二分搜索递归深度 $\log n$，空间 $O(\log n)$。

<span class="marginnote">时间与空间常常此消彼长，这就是<strong>时空权衡</strong>：缓存、预计算表、数据库索引都是拿空间换时间；流式算法则是拿时间精度换空间。到大模型时代，KV cache 就是最典型的"空间换速度"设计——第三级《计算机组成原理》与第四级《大模型部署》会反复碰到这条权衡线。</span>

## 5 案例分析：二分搜索的复杂度全貌

用二分搜索把本节的工具串起来。二分搜索在有序数组 `a` 中找目标 `x`：

```python
def binary_search(a, x):
    l, r = 0, len(a) - 1
    while l <= r:
        mid = (l + r) // 2
        if a[mid] == x:
            return mid
        elif a[mid] < x:
            l = mid + 1
        else:
            r = mid - 1
    return -1
```

- **最坏情形**：每次比较把区间砍半，从 $n$ 缩到 1 需要 $\lceil \log_2(n+1) \rceil$ 步，每步常数操作，$T_{\text{worst}} = \Theta(\log n)$。
- **最佳情形**：`mid` 恰好命中，$T_{\text{best}} = \Theta(1)$。
- **平均情形**：目标均匀分布时约 $\log_2 n$ 次比较，$\Theta(\log n)$。
- **空间**：迭代版只用 `l/r/mid` 三个变量，$\Theta(1)$；递归版栈深 $\log n$，空间 $O(\log n)$。

**解析：区间缩放的递推式**

设 $T(n)$ 为 $n$ 个元素的最坏比较次数：

$$
T(n) = T(n/2) + 1, \qquad T(1) = 1
$$

- **第一步，展开**：$T(n) = T(n/2) + 1 = T(n/4) + 2 = \dots = T(1) + \log_2 n = 1 + \log_2 n$。
- **第二步，读阶**：$\Theta(\log n)$。
- **第三步，对比线性搜索**：二分把搜索代价从 $\Theta(n)$ 压到 $\Theta(\log n)$——**有序带来的红利是指数级的**。这个"有序 ⟹ 对数"的对应，在第三级《数据结构》的二叉搜索树、B 树里会反复重现。

**辨析｜易错点：** 二分搜索的区间更新最容易写错边界。若用 `l <= r` 配 `mid = (l+r)//2`，则收缩必须写 `l = mid + 1` 或 `r = mid - 1`——写成 `l = mid` 会因区间不再严格缩小而死循环。**开闭区间的约定必须自洽**：左闭右闭配 `l<=r`、左闭右开配 `l<r`，两者选一，全程不变。

## 6 小结

- 复杂度分析 = **数基本操作**：运行时间 ≈ 基本操作数 × 常数，常数被 $O$ 吞掉。
- 三种口径：**最坏**（默认，给承诺）、**平均**（需概率分布）、**最佳**（常为理论值）。
- 嵌套循环压出多项式的**最高阶**；内层循环次数随外层变化时必须合起来求和。
- **空间复杂度**看额外存储：原地 $\Theta(1)$、线性辅助 $\Theta(n)$、递归栈按深度算。
- 时间与空间存在**权衡**，没有免费的午餐。
