## 为什么从算法开始

前几篇我们掌握了逻辑、集合、函数、序列与求和——这些都是**静态**的语言，用来描述「世界是什么」。从这一节起，离散数学转向**动态**的问题：给出一串精确的指令，让一台机器（或一个人）一步步把输入变成输出。这串指令就是**算法（algorithm）**。<span class="marginnote">「从极限到大模型」的终点是大模型，而大模型本身就是一个巨大的算法系统：token 化、注意力打分、softmax 归一化、采样——每一步都是一条精确指令。把「算法」这第一个概念立稳，后面看大模型就是在看一个个算法的拼装。</span>

这一节回答三个问题：**算法是什么**（它有哪些必备属性）、**如何用伪代码写算法**（不偏袒任何编程语言）、**如何度量算法**（我们关心它的正确性、时间与空间）。它是本专题第五篇《算法与复杂度》全部内容的入口，也是第三级《算法设计与分析》的地基。

## 1 什么是算法：一份精确到能执行的处方

**算法（algorithm）**：对计算或求解问题的一组**有限**、**精确**的指令，把合法的输入一步步变成输出。Rosen 给算法列出七条属性，我们把它压缩成最容易记住的四条：

**输入（input）**：算法从一个指定集合取得输入。比如「求最大元素」的输入是 $n$ 个整数 $a_1, \dots, a_n$。
**输出（output）**：算法必须产生至少一个输出，且输出与输入有确定关系——解决的是「给定输入，应该得到什么」。
**确定性 / 有效性（definiteness）**：每条指令**不含歧义**，且每一步都能被人在有限时间内执行。这一点把算法与「含糊的建议」分开。
**有限性（finiteness）**：对**所有合法输入**，算法在有限步后终止。这是算法的「停机承诺」。<span class="marginnote">「有限性」听起来平凡，却是计算机理论最深的问题之一：第十四篇《计算模型》里，图灵机的停机问题正是「能否判断任意程序必然停机」——结论是<strong>不能</strong>。现在你觉得有限性是理所当然，等到那篇就会明白它有多苛刻。</span>

**重点：算法的输出与输入的关系必须由「逻辑」保证，而不是靠运气。** 一个「大部分时候对、偶尔错」的指令序列，不是算法。为了把「正确性」说清楚，我们引入两个断言：**前置条件（precondition）**是输入必须满足的条件，**后置条件（postcondition）**是算法结束时输出的性质。写算法的理想流程是：声明前置条件 → 设计指令 → 证明后置条件成立。第七篇《程序正确性》会把「证明算法正确」变成系统方法。

「算法」一词源自九世纪波斯数学家**花拉子米（al-Khwārizmī）**——他的名字经过拉丁化的辗转，变成了「algorithm」。**算法比计算机古老一千多年**：欧几里得求最大公约数的方法（公元前 300 年）就是最经典的算法，第六篇《数论与密码学》会与它重逢。<span class="marginnote">欧几里得算法是人类现存最古老的算法之一：两个整数的 gcd 可以通过反复「用大减小、再取余」得到。它完美满足算法的全部属性——有输入、有输出、无歧义、必然终止。<strong>算法是先于计算机存在的数学对象</strong>，这一认识对学离散数学的人很重要。</span>

## 2 用伪代码描述算法：不偏袒任何语言

算法要有用，必须先被**无歧义地写出来**。我们不用任何具体编程语言，而用**伪代码（pseudocode）**——一种介于自然语言与真实代码之间的中间语言，它继承了程序的精确性，又摆脱了语法的束缚。Rosen 全书使用以下约定：

| 构造 | 写法 | 含义 |
| --- | --- | --- |
| 赋值 | $a := b$ 或 $a \leftarrow b$ | 把 $b$ 的值存入 $a$ |
| 分支 | `if 条件 then 语句`（必要时加 `else`） | 按条件选择路径 |
| 循环 | `while 条件` / `for i := 1 to n` | 重复执行 |
| 过程 | `procedure 名称(参数)` | 定义一段可调用的指令 |
| 返回 | `return 值` | 结束并给出输出 |

以「求最大元素」为例，这是 Rosen §3.1 的经典算法，也是我们整篇反复解剖的标本：

```
procedure max(a_1, a_2, …, a_n: 整数)
    max := a_1
    for i := 2 to n
        if max < a_i then max := a_i
    return max
```

读一遍：把 $a_1$ 当作临时的最大值，逐个比较，遇到更大的就替换。**伪代码的重点不是语法漂亮，而是每一步都对应一句可执行的自然语义。**<span class="marginnote">伪代码与真实代码的距离，是「可读性」与「可运行性」的权衡。真实的 C 或 Python 还要处理数组下标从 0 开始、内存分配、边界检查——这些与算法思想无关。<strong>写伪代码时，把与核心思想无关的实现细节全部剥掉。</strong></span>

再看一个用 `for` 循环做累加的例子——把前 $n$ 个整数加起来：

```
procedure sum(n: 非负整数)
    s := 0
    for i := 1 to n
        s := s + i
    return s
```

这个算法执行的正是求和记号 $\sum_{i=1}^{n} i$。**变量 `s` 就是「累加器」，循环变量 `i` 的上下界就是求和的下限与上限**——上一节的求和语言在这里被翻译成了伪代码。读懂一段伪代码，本质上是读懂它的循环结构：循环的起止、步进、以及每轮改写了什么变量。

**辨析｜易错点：不要把伪代码写成「任意一种语言的方言」。** 伪代码的灵魂是**读者能按它逐行翻译成自己熟悉的语言**。常见的病是混入语言专属语法（如 Python 的缩进、C 的指针），或反过来写成含混的散文（如「然后不断找更大值」——这违反了确定性）。好伪代码的检验标准：**让一个从没写过那门语言的人，也能照此写出正确的程序**。

## 3 算法分析：我们关心的三件事

写完一个算法，立刻要问三件事：**它对吗？它快吗？它省空间吗？**

**正确性（correctness）**：对所有满足前置条件的输入，它都终止且满足后置条件。这需要证明，不是试几组数据就算数——第七篇会给出归纳法式的证明框架。
**时间复杂度（time complexity）**：执行步数随输入规模 $n$ 增长的速度。我们通常数「**基本操作**」的次数——比较、赋值、加法——而不是真实秒数，因为秒数依赖机器，操作次数是机器无关的。<span class="marginnote">为什么用「操作次数」而不用「运行时间」？因为同一个算法在不同 CPU 上快慢不同，但「比较了几次」是不变的。<strong>操作次数 = 机器的语言，运行时间 = 这台机器特有的翻译</strong>。第五篇《算法增长：大 O 记号》会给这个直觉装上严格的数学壳。</span>
- **空间复杂度（space complexity）**：除了输入本身，算法额外占多少内存。现代大模型的显存占用、训练时的激活缓存，都是空间复杂度的工程化身。

先看 max 算法的时间。它有一个 `for` 循环，从 $i=2$ 走到 $i=n$，循环体每次做**恰好一次比较** `max < a_i`。于是比较次数与 $n$ 的关系极其规整——这是下一节公式解析的主角。我们还需要一个词：**最坏情形（worst case）**。当输入最不利时，算法要做多少步？max 算法的比较次数与输入内容无关（任何输入都比 $n-1$ 次），而有的算法（比如下一节的搜索）最坏与平均差别很大，必须分情形讨论。

空间复杂度也可以立刻算一笔：max 算法只用一个额外变量 `max` 存临时最大值，**空间消耗不随 $n$ 增长**——记为 $O(1)$（常数空间）。二分搜索同样只用两个边界指针，也是 $O(1)$；而第三级《算法设计与分析》里的归并排序需要 $O(n)$ 的辅助数组。**空间与时间常常此消彼长**——省时间往往费空间，省空间往往费时间，这是算法工程里最经典的取舍。

## 4 公式解析：max 算法的比较次数

**max 算法对任意 $n$ 个元素的输入，恰好做 $n-1$ 次比较。** 用求和语言写：

$$
T(n) = \sum_{i=2}^{n} 1 = n - 1
$$

分三步拆解这条「公式」：

- **第一步，读懂 $T(n)$**：$T(n)$ 表示输入规模为 $n$ 时算法的基本操作数。这里我们只数比较次数（比较是最昂贵的操作，赋值与循环开销忽略不计）。
- **第二步，读懂求和**：$\sum_{i=2}^{n} 1$ 是从 $i=2$ 到 $n$ 每次都贡献 1 次比较。项数 = 上限 − 下限 + 1 = $n - 2 + 1 = n - 1$。
- **第三步，读懂「恰好」**：无论输入是 `$1`, 2, 3, \dots, n$ 还是 $n, n-1, \dots, 1$，循环都完整走完 $n-1$ 轮，每轮都比一次。所以**最好、最坏、平均三种情形全都等于 $n-1$**——这是 $T(n) = \Theta(n)$ 的第一个、也是最平和的例子。<span class="marginnote">不是所有算法都这么温和。下一节你会看到线性搜索最坏 $n$ 次、平均 $(n+1)/2$ 次；再往后，冒泡排序最坏 $n(n-1)/2$ 次。<strong>「$T(n)$ 是否随输入变化」本身就是算法的性格特征</strong>，第五篇会系统度量它。</span>

把 $n-1$ 记住的同时，把它和微积分里的「增长阶」挂钩：当 $n$ 翻倍，$n-1$ 也大约翻倍——**线性增长**。这是所有「扫一遍数据」类算法的共同代价曲线。第三级《算法设计与分析》会告诉你，线性常被当作「可接受」的基准线：比线性快的（如 $\log n$、$n\log n$）是优化目标，比线性慢的（$n^2$、`$2`^n$）则需要警惕。

## 5 算法是大模型与一切计算的齿轮

把视野拉回整条学习路线，算法不是孤岛：

**搜索与排序**：§3.1 接下来两节将给出线性搜索、二分搜索、冒泡排序、插入排序的伪代码与分析——它们是最小的、却最经典的算法案例。<span class="marginnote">搜索与排序号称「计算机科学的两大元问题」：<strong>几乎任何数据处理都以它们为构件</strong>。数据库的索引是排序好的 B 树，推荐系统要在海量物品里查 top-k，大模型的采样要从整个词表里搜索下一个 token。</span>
- **贪心与动态规划**：第五篇之后，我们会遇到「每一步选局部最优」的贪心算法，以及第七篇递归、第九篇递推关系催生出的动态规划——它们都建立在「算法」这个总概念之上。
- **图与树算法**：第十一篇的迪克斯特拉最短路径、第十二篇的最小生成树，是真实世界里导航、网络路由的算法实现。
- **大模型本身就是算法**：一个 `repeat` 循环——把提示词 token 化、过 Transformer 层、softmax 归一化、逐 token 采样，直到遇到结束符。**你读完了「什么是算法」，就看懂了「大模型如何被描述」。**

## 6 小结

- **算法**是有限、精确、确定性、能终止的指令序列；属性可浓缩为输入、输出、确定性 / 有效性、有限性。
- **正确性**用**前置条件 → 后置条件**来刻画；算法的目标是「对所有合法输入，后置条件必然成立」。
- **伪代码**是介于自然语言与代码之间的精确语言；与具体语言无关，可读性优先。
- **复杂度**关注正确性、时间、空间；时间用**基本操作次数**度量，机器无关。
- **max 算法**：恰好 $n-1$ 次比较，$T(n) = n - 1$，与输入内容无关。
- 搜索、排序、图算法、大模型——全是「算法」这个总概念的具体化身。

在下一节，我们把算法开动起来，处理第一个经典问题——**搜索**：在序列里找一个目标元素。线性搜索朴素直接，二分搜索则利用「有序」换来了数量级的提速。
