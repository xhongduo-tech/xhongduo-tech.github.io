## 为什么从集合的划分开始

前三节我们学会了把集合「合」起来——并、交、补、差、对称差。这一节换一个方向：**把集合「拆」开来**。拆成一个由互不相交的块组成的整体，每一块非空，块的并又恰好还原成原集合——这叫**划分（partition）**。同时我们要回答一个工程问题：**计算机到底怎么存储和运算集合？** 答案是位串（bit string）。<span class="marginnote">「整体大于部分之和」是亚里士多德的一句名言；划分则是它的逆向操作——把整体拆成部分，并且要求这些部分互不相交、合拢无损。拆得干净，加起来才准确，这正是「分而治之」能成立的前提。</span>

「拆开再分别处理」是计算机科学最古老的套路。分治算法把问题切成互不相交的子问题，MapReduce 把数据按键切分到不同机器，数据库按区间或哈希把表分成多片（sharding），哈希表把键空间分进一个个桶——它们本质上都在做同一件事：**把一个集合划分成若干互不相交的块，然后逐块处理、汇总结果**。

划分还与第十篇《关系》中的**等价关系**是一对孪生概念：任何等价关系都给出一个划分（等价类），任何划分也都定义出一个等价关系。这一节先把「拆」的数学讲清楚，到《关系》一章你会发现，两个看似无关的话题其实是同一枚硬币的两面。

## 1 划分：把集合拆成互不相交的块

**划分（partition）**：设 $S$ 是一个集合，$\{A_1, A_2, \dots, A_k\}$ 是 $S$ 的一个划分，当且仅当下面三条同时成立：

$$
\begin{aligned}
&(\mathrm{i})\ \ A_i \neq \emptyset \quad (1 \le i \le k); \\
&(\mathrm{ii})\ \ A_i \cap A_j = \emptyset \quad (i \neq j); \\
&(\mathrm{iii})\ \ A_1 \cup A_2 \cup \cdots \cup A_k = S.
\end{aligned}
$$

三条条件各有分工：**（i）每块非空**——空块既不增加信息，还会让「每个元素恰属一块」的说法变含糊；**（ii）两两不相交**——任何两个元素不能同时落在两块里，这是「不重复」的保证；**（iii）并起来等于 $S$**——不能有元素被漏掉，这是「不遗漏」的保证。<span class="marginnote">三条合起来等价于一句大白话：划分把 $S$ 的每个元素分进恰好一个块。「恰好一个」= 非空 + 两两不相交 + 并得全。这个三条件结构在第十篇《等价类》里会原封不动地再现。</span>

看一个具体例子。设 $S = \{1,2,3,4,5,6,7\}$，则下面三个都是 $S$ 的划分：

$$\{\{1,2\}, \{3,4,5\}, \{6,7\}\}, \qquad \{\{1\}, \{2\}, \{3\}, \{4\}, \{5\}, \{6\}, \{7\}\}, \qquad \{\{1,2,3,4,5,6,7\}\}$$

第一个把 $S$ 分成三块；第二个让每个元素各自成块（最细）；第三个干脆一整块（最粗）。而下面这些**不是**划分：

- $\{\{1,2\}, \{2,3\}, \{4,5,6,7\}\}$：块一与块二共用元素 $2$，违反（ii）；
- $\{\{1,2\}, \{3,4\}, \{5,6\}\}$：元素 $7$ 无处安放，违反（iii）。

**辨析｜易错点：划分是「集合的集合」。** 每个块本身是一个集合，而划分是这些块组成的集合。所以 $S = \{1,2,3\}$ 的一个划分写作 $\{\{1\}, \{2,3\}\}$——外层花括号里装的是两个集合。$2 \in \{2,3\}$，而 $2 \notin \{\{1\}, \{2,3\}\}$；$\{2,3\} \in \{\{1\}, \{2,3\}\}$。**「属于块」与「属于划分」是两回事**，混用它们正是初学划分最容易犯的错。

## 2 划分、细分与计数

划分之间可以有「粗细」关系。设 $P_1$ 与 $P_2$ 都是 $S$ 的划分，若 $P_1$ 的**每一块**都含于 $P_2$ 的**某一块**，则称 $P_1$ 是 $P_2$ 的**加细（refinement）**，记作 $P_1 \preceq P_2$。<span class="marginnote">「加细」直译自 refinement，意思是把粗块继续切细。最细的划分是「每个元素单独一块」，最粗的划分是「整块 $S$」。加细关系在第十篇《偏序》中是一个标准例子——划分组成的集合在这关系下形成一个偏序结构。</span>

例如 $S = \{1,2,3,4\}$ 上，$\{\{1\},\{2\},\{3,4\}\}$ 是 $\{\{1,2\},\{3,4\}\}$ 的加细（因为 $\{1\} \subseteq \{1,2\}$、$\{2\} \subseteq \{1,2\}$、$\{3,4\} \subseteq \{3,4\}$）；而 $\{\{1\},\{2,3,4\}\}$ 与 $\{\{1,2\},\{3,4\}\}$ 互不为加细。

划分与计数之间有一条极其直白的桥：**如果 $\{A_1,\dots,A_k\}$ 是 $S$ 的划分，那么 $|S| = |A_1| + |A_2| + \cdots + |A_k|$**。这几乎是废话，却是一切计数的地基——第八篇《计数》里的**加法原理**说的就是这句话。它的前提正是划分的第二条：块两两不相交，所以没有元素被数两次。<span class="marginnote">「先划分、再逐块数、最后相加」是数数的默认姿势：数一个班的人数，先按性别分两组，再相加；数一本书的页数，先按章节数再累加。一旦块与块重叠，加法就失灵，必须改用第八篇《容斥原理》的扣除法。</span>

一个 $n$ 元集合有多少种划分？$n=3$ 时答案是 $5$：

$$\{\{1,2,3\}\}, \ \{\{1\},\{2,3\}\}, \ \{\{1,2\},\{3\}\}, \ \{\{1,3\},\{2\}\}, \ \{\{1\},\{2\},\{3\}\}$$

这个数叫**贝尔数（Bell number）** $B_n$，$B_1=1, B_2=2, B_3=5, B_4=15$，增长快得惊人（$B_{20} \approx 5.2 \times 10^{13}$）。它将在第八篇《计数》与组合数学里正式登场，现在只需记住：**「分成多少块」本身就是一个值得数的组合对象。**

## 3 计算机如何表示集合：位串

数学里集合怎么写都行，但计算机里一切都要落成 0/1。给定一个有 $n$ 个元素的**论域** $U$，我们先把 $U$ 的元素排定一个顺序 $a_1, a_2, \dots, a_n$，然后用一条长度为 $n$ 的**位串（bit string）**表示 $U$ 的每个子集：**第 $i$ 位是 1 表示 $a_i$ 在子集里，是 0 表示不在**。<span class="marginnote">这条位串本质上就是 $U$ 上每个元素「在/不在」的是非答案，也就是《幂集与笛卡尔积》一节里「子集 ⟺ 二进制串」那层对应关系在工程上的兑现。</span>

设 $U = \{1,2,\dots,10\}$（顺序取自然序），则：

偶数集合 $\{2,4,6,8,10\}$ 表示为 $0101010101$；
$\{1,2,3,4,5\}$ 表示为 $1111100000$；
空集表示为 $0000000000$，全集表示为 $1111111111$。

位串的最大好处是：**集合运算直接变成逐位逻辑运算**。

| 集合运算 | 位串运算 | 结果（对应上面的 $U$） |
| --- | --- | --- |
| $A \cup B$ | 按位 **OR** | `$0101010101` \lor 1111100000 = 1111110101$ |
| $A \cap B$ | 按位 **AND** | `$0101010101` \land 1111100000 = 0101000000$ |
| $\overline{A}$ | 按位 **NOT** | $\lnot 0101010101 = 1010101010$ |

验证一下：$1111110101$ 的第 `$1`,2,3,4,5,6,8,10$ 位为 1，对应 $\{1,2,3,4,5,6,8,10\}$，正好是偶数集与 $\{1,2,3,4,5\}$ 的并；$0101000000$ 只取第 `$2`,4$ 位，即 $\{2,4\}$，正是两者的交；$1010101010$ 取第 `$1`,3,5,7,9$ 位，即奇数集，正是偶数的补。

**重点：集合运算与位逻辑运算是同一件事的两种说法。** $\cup$ 对应 OR、$\cap$ 对应 AND、补对应 NOT——这与第一篇逻辑里「$\lor, \land, \neg$ 对应 $\cup, \cap, \overline{\cdot}$」的对应完全一致。学会位串表示，就等于给集合运算装上了一台「硬件加速器」。

## 4 位串为什么高效：从 0/1 到机器字

位串表示不止是理论玩具。现代 CPU 一条指令就能对 64 位做 AND/OR/NOT，**所以论域不超过 64 的子集，整个集合就是 CPU 的一个寄存器，一次并/交/补就是一条指令**。相比之下，哈希表、红黑树等通用集合结构做一次并集需要 $O(n)$ 甚至更久。这就是为什么操作系统权限、网络包过滤、编译器的「位掩码」全用位串。

举个例子：文件权限在 Unix 里就是 9 个 bit（读/写/执行 × 用户/组/他人）。rw-r--r-- 写作二进制 110100100——判断「某用户能否读某文件」，就是一次 AND 运算。<span class="marginnote">位串在概率数据结构里也大放异彩：布隆过滤器（Bloom filter）用一条位串近似表示一个大集合，查询「元素可能在集合里吗」只需几次哈希加几次位运算，代价是可能误报——「用 1/0 位串换速度与空间」的思想一脉相承。</span>

Python 里这套运算原样可用，但有一个坑：Python 的按位取反 `~` 是对**无限长二进制**取反（结果为负），不是「对论域取补」。要得到「论域内的补」，需要用异或掩码：

```python
A = 0b0101010101          # 偶数集合 {2,4,6,8,10}
U = (1 << 10) - 1         # 论域的全 1 掩码 0b1111111111
complement = A ^ U        # 0b1010101010，即论域内的补（奇数集）
```

**辨析｜易错点：$A$ 不等于数学里的补集。** 数学里的 $\overline{A}$ 是「相对全集 $U$ 的补」；Python 里的 $U$ 是把 $A$ 的每一位取反，包括「论域之外无限多的前导 0」，于是结果带了负号。正确写法是先与 $U$ 的全 1 位串做异或（XOR）。这个「有限世界 vs 无限位」的落差，与第一级集合里「补集必须相对全集才有意义」是同一个道理。

## 5 公式解析：为什么互不相交才能相加

这一节最常被使用的公式是划分的基数公式。设 $\{A_1, A_2, \dots, A_k\}$ 是 $S$ 的一个划分，则

$$
|S| = |A_1| + |A_2| + \cdots + |A_k|
$$

对这条式子做四步拆解：

- **第一步，回顾划分的三条件**：每块非空、两两不相交、并起来是 $S$。基数公式依赖的是后两条。
- **第二步，抓住「恰好一块」**：由条件（ii）与（iii），$S$ 的每个元素 $x$ 恰好属于 $k$ 个块中的一块。这是整条公式的灵魂——**没有元素被重复数，也没有元素被漏掉**。
- **第三步，把「逐块数」翻译成「逐一数」**：先数 $A_1$ 的 $|A_1|$ 个，再数 $A_2$ 的 $|A_2|$ 个……因为块与块不相交，这些数出来的元素互不相同，全部加起来正好是 $S$ 的元素总数。
- **第四步，对照「有重叠」的情形**：如果两块有重叠，上述加法就数重了。两个集合时正确公式是 $|A \cup B| = |A| + |B| - |A \cap B|$——多减掉一次被重复数的部分。这正是第八篇《容斥原理》的雏形，而划分（不相交）是容斥最干净的边界情形。

这条公式还给了我们一个通用直觉：**遇到「求一个大集合的大小」，先想能不能把它划分成若干好数的块。** 后面学概率（样本空间按事件划分）、学算法（分治的合并步骤）、学计数，都会反复使用这个「划分 → 相加」的动作。

## 6 划分与计算机科学：从分桶到等价类

划分在计算机里无处不在，举三个例子：

- **哈希表**：哈希函数把「键的集合」划分到若干个桶，查询时先定位桶、再在桶内找，平均 $O(1)$。哈希函数的理想状态是让各桶尽量均匀——这正是「划分要大小适中」的工程版。
- **数据库分片（sharding）**：把一张大表按某个键划分成多片，分布在多台机器上；查询能「裁剪」到相关分片，避免全表扫描。
- **MapReduce / 分布式计算**：Map 阶段之后，中间结果按键划分（partition）到不同节点，Reduce 阶段逐块汇总——「划分后并行、再归并」的教科书案例。

更深刻的是，划分与**等价关系**在数学上是同一个概念。一个等价关系把集合分成若干**等价类**，这些等价类恰好构成一个划分；反过来，给定任意划分，可以定义「同属一块即等价」，它就满足自反、对称、传递三条性质。<span class="marginnote">这条联系在第十篇《关系》会严格证明。届时你会看到：划分、等价关系、商集、映射的核，这四个看似不同的词全在描述「把集合按某种标准归并」这一件事。</span>

## 7 小结

- **划分**的三条件：每块**非空**、块与块**两两不相交**、块的并**等于原集合**——合起来就是「每个元素恰属一块」。
- 划分是**集合的集合**；「元素属于块」与「块属于划分」是两回事。
- **加细** $P_1 \preceq P_2$：$P_1$ 的每块含于 $P_2$ 的某块；$n$ 元集合的划分数是**贝尔数** $B_n$。
- 划分的**基数公式** $|S| = \sum_i |A_i|$ 是计数加法原理的地基；块一旦重叠就要改用容斥扣除。
- **位串表示**：论域排定顺序后，子集 ↔ 0/1 串；$\cup,\cap,\overline{\cdot}$ 对应 OR、AND、NOT。
- 位串让集合运算变成机器字级的一条指令；Python 里 `~` 是无限位取反，论域内的补要用 `^ U`（全 1 掩码）。
