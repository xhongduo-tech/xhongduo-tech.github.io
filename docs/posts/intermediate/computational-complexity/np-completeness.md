## 为什么从 NP 完全性开始

上一课我们发现 SAT、TSP、CLIQUE 等一大群问题都是 NP 成员，各有各的「难」。但它们之间的难是孤立的吗？1971 年，库克证明了第一个惊人的结论
**SAT 是 NP 完全的**——NP 里每个问题都能多项式时间归约到 SAT。这意味着 SAT 是 NP 的「老大」：只要 SAT 有多项式算法，整个
NP 都能在多项式时间内解决。1972 年，卡普一口气把 21 个著名问题归约进这个俱乐部。NP 完全性理论由此诞生：**它用「归约」把成千上万互不相干的问题
焊成了一张困难之网**——这张网至今是算法设计、近似算法、以及 P vs NP 研究的中心地图。

## 1 NP 完全的定义与两张面孔

**NP 完全（NP-complete）**：语言 $B$ 是 NP 完全的，若

1. $B \in \mathrm{NP}$；
2. 对**每个** $A \in \mathrm{NP}$，有 $A \leq_p B$（$A$ 可多项式归约到 $B$）。

条件 2 说的正是「$B$ 是 NP 里最难的问题之一」：任何 NP 问题都能翻译成 $B$ 的一个实例。定义立刻给出一个**决定性推论**：

$$
B \in \mathrm{P} \iff \mathrm{P} = \mathrm{NP}
$$

即：**只要任何一个 NP 完全问题被证明有多项式算法，P = NP；反过来，只要有一个 NP 完全问题被证明无多项式算法，P ≠ NP。** 
<span class="marginnote">
这个「全有或全无」的性质就是 NP 完全性的全部威力：你不需要对一万个问题各证明一次难易，只要盯住一个最难的。 
<strong>NP 完全问题是 P vs NP 问题的「探针」</strong>——挑一个你顺手的，证明它的 P 或非 P 即可。</span>

归约 $A \leq_p B$ 的严格定义：存在多项式时间可计算函数 $f$，使 $w \in A \iff f(w) \in B$。这个「$\iff$
 」是双向的（双向都保持答案），与不可判定性那章的归约一脉相承，只是多了「多项式时间」的限制。

## 2 公式解析：第一个 NP 完全问题

库克-列文定理的陈述简洁：**SAT 是 NP 完全的**。它的证明思路是「把任意 NP 验证者的运行历史编码成布尔公式」。给定验证者 $V$ 与输入 $w$
 ，构造公式 
$\phi$ 使得：

$$
w \in A \iff \phi \text{ 可满足}
$$

四步拆解这条证明（思路层面）：

- **第一步，想象验证者的运行**：$V$ 对 $\langle w, c \rangle$ 运行 $t = |w|^k$ 步。它的全部历史可以摊成一个**计算表格**：行是时间步，列是带格位置，每个格子记「该时刻该位置放什么符号」。
- **第二步，引入布尔变量**：变量 $x_{i,j,s}$ 表示「第 $i$ 时刻第 $j$ 个带格是符号 $s$」，再加状态变量表示「第 $i$ 时刻机器处于哪个状态、读写头在哪」。整个计算就变成一个布尔赋值问题。
- **第三步，写成合取范式**：把「合法初始配置」「每一步转移合法」「最后到达接受态」全部写成布尔子句，得到公式 $\phi$。$\phi$ 是可满足的，当且仅当存在一条合法计算链通向接受。<span class="marginnote">这一步最妙的地方在于「把机器翻译成公式」：<strong>每台图灵机的每个输入，都被编译成一个命题公式</strong>，机器的行为变成了公式的满足性。通用计算被编码成布尔逻辑，这是「计算 = 逻辑」的第一次完全实现。</span>
- **第四步，成立**：$\phi$ 的长度是 $O(t^2)$，是 $|w|$ 的多项式；构造也是多项式时间。于是每个 NP 语言都多项式归约到 SAT，SAT 是 NP 完全的。

**核心直觉：SAT 之所以是 NP 的「老大」，是因为布尔公式本身能「模拟」任何一台图灵机——逻辑是计算的通用语言。**

## 3 从 SAT 出发：卡普的 21 个问题

一旦 SAT 立足，归约就开始了连锁反应。证明新问题 $B$ 是 NP 完全的标准三步：

1. 证明 $B \in \mathrm{NP}$（给出验证者）；
2. 选一个已知 NP 完全的问题 $A$；
3. 构造多项式归约 $A \leq_p B$，证明 $w \in A \iff f(w) \in B$。

卡普的经典链条是这样的「归约钻石」：

$$
\text{SAT} \leq_p \text{3SAT} \leq_p \text{CLIQUE} \leq_p \text{VERTEX-COVER} \leq_p \text{HAMILTONIAN} \leq_p \text{TSP}
$$

每一步都是一个「翻译」：把 3SAT 的公式变成图（文字做顶点、子句做三角形），把图的团变成顶点覆盖（补图），把顶点覆盖变成回路（覆盖 gadgets）
把回路变成旅行路线。
<span class="marginnote">
 gadget（装置）是归约构造的主角：一小块精心设计的结构，用来模拟原问题的某个局部约束。比如把「一个子句至少一个文字为真」编码成「一个小图必须被覆盖到」—
<strong>归约是建模，gadget 是积木</strong>。</span>这些归约全部可在多项式时间完成，于是这一大串问题全体成为 NP 完全。

## 4 易错辨析：NP 完全 vs NP 难 vs P 中问题

**辨析｜易错点：**

- **「NP 完全」≠「NP 难」**：NP 难（NP-hard）只要求「所有 NP 问题可归约到它」，**不要求它本身在 NP 里**。NP 完全 = NP ∩ NP-hard。一个 NP 难问题甚至可能不是语言（比如「求最优值」的函数问题）。<span class="marginnote">例如「最优化版旅行商：找最短回路」是 NP 难的，但它不是判定问题、不在 NP 定义里——虽然它的判定版本「是否存在 ≤ B 的回路」是 NP 完全的。判定与优化之间隔着一层「问答题与判断题」的距离。</span>
- **「NP 完全问题互不相关」**——恰恰相反，它们通过归约连成一张网。这张网是 NP 完全性理论最大的财富：给任何新问题，只要证明它「不难于」某个已知 NPC 问题，它就被拖进网里。
- **「证明 B ∈ NP 可以省略」**——不能。归约只证明 $B$ 是 NP 难，要称「完全」必须补上「$B$ 本身在 NP」。遗漏这一步是竞赛和作业里的高频扣分点。

### 例题：一张归约项链的检查

把「归约必须双向保持」落到实例上检查一条真实项链 
$\mathrm{3SAT} \leq_p \mathrm{CLIQUE} \leq_p \mathrm{VERTEX-COVER}$。对 3SAT 公式 
$\phi = (x_1 \lor \neg x_2 \lor x_3) \land (\neg x_1 \lor x_2 \lor x_4)$
 ，CLIQUE 构造每个子句一个三角形、跨子句连「不矛盾的文字对」。验证「 
$\phi$ 可满足 ⇒ 团存在」：取满足赋值，从每个子句挑一个真文字，它们两两不矛盾，所以构成团。「团存在 ⇒ 可满足」：团在三角形里各取一个顶点、共 $k$
 个互不矛盾的文字，赋这些文字为真，每个子句都有真文字，公式可满足。再走第二跳： 
$G$ 含 $k$-团当且仅当补图含 $|V|-k$
 顶点覆盖（取补集）。**每一步都做「原解 → 翻译解」与「翻译解 → 原解」的双向验证，归约项链才算闭合**
这也是为什么归约证明在竞赛与论文里必须两方向都写——只证一半的归约，比不证还危险。

### 核心对比：P、NP、NP 难与 NP 完全

这四个概念的分界是全书最常被考的知识点，一张表钉死：

| 概念 | 定义 | 已知关系 |
| --- | --- | --- |
| P | 多项式时间可判定 | P ⊆ NP |
| NP | 多项式时间可验证 | NP ⊆ PSPACE |
| NP 难 | 所有 NP 问题可归约到它 | 可不在 NP 里 |
| NP 完全 | NP ∩ NP 难 | NPC 有解 ⇔ P = NP |

**读表要点：NP 难比 NP 完全更宽——NP 难只要求「难」（所有 NP 都能归约到它），不要求「在 NP 里」；NP 完全才要求两个条件都满足**
优化版问题（求最短回路）常常只是 NP 难而不是 NP 完全，因为它不是判定问题。**「完全性」永远要求「本身在类里 + 类里最难」，缺一不可—
这张表是判断任何问题「算哪一格」的坐标系。**

## 5 小结

- **NP 完全** = 在 NP 中 + 所有 NP 问题可多项式归约到它。
- **库克-列文定理**：SAT 是第一个 NP 完全问题——布尔公式能编码任意图灵机的计算。
- 决定性推论：任何一个 NPC 问题的多项式算法 ⇔ P = NP。
- **归约三步**：证 NP → 选已知 NPC → 构造多项式归约（gadget 建模）。
- 卡普链条把 SAT、3SAT、CLIQUE、顶点覆盖、哈密顿回路、TSP 全部连入同一张困难之网。
- NP 难 ≠ NP 完全；完全必须加上「在 NP 里」。

在下一节，我们将从归约链条的源头出发，专门解剖最核心的那台发动机：**SAT 与可满足性问题**——为什么它是库克选择的第一个 NPC 问题，3SAT
又如何成为后续无数归约的起跑线。
