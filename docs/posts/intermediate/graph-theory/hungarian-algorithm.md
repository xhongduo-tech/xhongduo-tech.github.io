## 为什么从匈牙利算法开始

Berge 定理说「最大匹配 ⇔ 无增广路」，
但要把它变成能跑的算法，还差一个关键问题：**怎么高效地找增广路？** 1955 年库恩基于匈牙利数学家柯尼希与埃格瓦里（Egerváry）的工作，
给出了二部图上找最大匹配的增广路算法——为了纪念它的渊源，
库恩称之为**匈牙利方法（Hungarian algorithm）**。
<span class="marginnote">在中文算法社区，「匈牙利算法」几乎专指这种「逐个顶点尝试增广」的二部图最大匹配算法；
它简洁到几十行代码，却是无数分配问题（课程分配、任务指派、恋人配对）的工业标准。
加权版本叫 Kuhn–Munkres 算法，
我们最后会提及。
</span>这一节把它的原理、实现与复杂度讲透。

## 1 算法思想：逐个顶点尝试增广

匈牙利算法的骨架极其朴素：**对 $X$ 侧的每个顶点，尝试为它找一条增广路；找到了就翻转，找不到就跳过。**

维护两个数组：`match[x]` 记录 $x \in X$ 配对的 $Y$ 顶点（`-1` 表示未配），
`match[y]` 反向记录。
算法流程：

1. 清空匹配，`match` 全为 `-1`。
2. 对 $X$ 中每个顶点 $x_0$：重置访问标记，调用「找增广路」。
3. 递归搜索：从 $x_0$ 出发沿「非匹配边」走到 $Y$；
对每个 $y$，若 `match[y] == -1`，则配成对（找到增广路）；
否则继续从 `match[y]` 递归，试图「腾位」。
4. 若某次尝试让匹配数 +1，则继续下一个 $x$；
全程不能增广时，匹配即最大。

关键在「腾位」：$x_0$ 想娶 $y$，但 $y$ 已配给 $x_1$，
算法就尝试给 $x_1$ 另找新欢 $y'$；
若 $y'$ 又已配给 $x_2$，继续递归……这条「$x_0 \to y \to x_1 \to y' \to x_2 \to \cdots$」的路径正是一条交替路，
一旦走到一个未配的 $y$，整条链翻转就完成一次增广。
<span class="marginnote">「腾位递归」是匈牙利算法的灵魂：宁可拆散旧的配对，也要腾出位置，只要最终能腾出。
DFS 的回溯天然实现了「试错 + 复原」，
配对了就沿增广路翻转，失败了就回退到尝试前状态。
</span>

## 2 伪代码与正确性

```
def try_augment(x, vis, match):
for y in N(x):                 # 遍历 x 的每个 Y 侧邻点
if not vis[y]:
vis[y] = True          # 标记，
防死循环
if match[y] == -1 or try_augment(match[y], vis, match):
match[y] = x; match[x] = y
return True
return False

for x in X:                        # 主循环
if try_augment(x, vis, match):
ans += 1
```

正确性由 Berge 定理直接保证：`try_augment(x)` 本质上是在 DFS 中寻找一条以 $x$ 为端点的增广路；
若它对某个 $x$ 返回 `True`，说明找到增广路，
匹配 +1；
主循环结束时，**对每个 $x$ 都尝试过且找不到增广路**，
此时不存在任何增广路（否则其端点会在某次尝试中被找到），
故匹配最大。
<span class="marginnote">一个细节：`vis` 数组每轮尝试都要重置，防止递归绕圈，也保证每条 $Y$ 顶点每轮至多被访问一次。
`match[y]` 的反向更新由「先更新 match[x] 再 match[y]」保证一致。
</span>

## 3 复杂度分析

设 $|X| = n_1$，$|Y| = n_2$，
边数 $m$，匹配最大为 $\nu \le \min(n_1, n_2)$：

- 每次 `try_augment` 遍历的顶点不超过 $n_2$、边不超过 $m$，代价 $O(m)$。
- 主循环最多执行 $n_1$ 次，且匹配每次至多加一，增广次数 ≤ $\nu \le n_1$。

总复杂度 $O(n_1 \cdot m)$，
即 $O(VE)$。
对 $n$ 个顶点、$m$ 条边的二部图，$O(nm)$。
<span class="marginnote">相比暴力的 $O(n!)$ 枚举，$O(nm)$ 是指数级进步。
若用 Hopcroft–Karp 算法（每轮 BFS 找多条不相交增广路）可优化到 $O(m\sqrt n)$，
适合大规模稀疏图；
两者都是「增广路范式」的不同实现。
</span>

## 4 公式解析：为什么每轮至多 $O(m)$

**找一条增广路的开销被访问标记限制在线性。**
设某轮 `try_augment` 访问了 $v$ 个 $Y$ 顶点、$e$ 条边：

$$
\text{单轮代价} \le O(v + e) = O(m)
$$

三步拆解：

- **第一步，访问不重复**：`vis` 标记保证每个 $Y$ 顶点每轮至多进入一次递归，DFS 的递归调用次数 ≤ $|Y|$。
- **第二步，边遍历有限**：每个被访问的 $x$ 顶点会遍历它全部邻边，但由于 $Y$ 顶点不重复进入，递归形成的是一条树状搜索，每条边至多被检查常数次，总边数 $O(m)$。
- **第三步，总轮数**：匹配每轮至多 +1，增广轮数 ≤ $\nu$；
加上主循环的 $n_1$ 次「空转」尝试，总轮数 $O(n_1)$。
于是总复杂度 $O(n_1 m)$。

「每轮找一条增广路，每轮线性」——这就是匈牙利算法「朴素但够用」的全部秘密。

## 5 加权版：Kuhn–Munkres 与指派问题

当每条边还带权、目标是**最大/最小权完美匹配**时，
问题升级为**指派问题（assignment problem）**：
$n$ 个人做 $n$ 项工作，每人做每项工作的效率不同，
如何一一指派使总效率最大？

**Kuhn–Munkres 算法**（KM 算法）解决它：
为每个 $X$ 顶点和 $Y$ 顶点维护一个**标杆（label）**，
满足 $l(x) + l(y) \ge w(x,y)$，
贪心地在「相等子图」（满足 $l(x)+l(y)=w(x,y)$ 的边）上找完美匹配；
找不到时调整标杆，让相等子图逐步扩大，最终得到最优指派。
<span class="marginnote">标杆调整的本质是「松弛」：
哪些边值得进入相等子图，取决于当前未匹配顶点的标杆和。
KM 算法 $O(n^3)$，是指派问题的经典解法，
也是《线性规划》对偶理论在图上的化身——标杆正是对偶变量的角色。
</span>

## 6 辨析｜易错点：匈牙利算法的适用边界

- **只适用于二部图**：它依赖 $X$-$Y$ 两侧的交替结构。
一般图（非二部）的最大匹配需要 Edmonds 带花算法（处理奇圈），复杂度更高。
- **找到的匹配是「最大」不是「指定目标」**：它不保证匹配特定的顶点，只保证边数最多。
若要「$X$ 全部饱和」，需额外检查 $\nu(G) = |X|$。
- **DFS 的访问标记必须每轮重置**：忘记重置 `vis` 会导致跨轮的错误复用，是手写匈牙利算法最常见的 bug 来源。

**辨析｜易错点：匈牙利算法 ≠ 旅行商问题的匈牙利方法。**
匈牙利算法解决的是**匹配/指派**；
旅行商问题（TSP）虽然有时被误称，但两者的数学模型完全不同。
命名混淆在中文资料里很常见，务必以「最大匹配 / 指派问题」为准。

## 7 小结

- **匈牙利算法**：对 $X$ 每个顶点尝试找增广路（DFS 腾位），找到就翻转，匹配 +1。
- **正确性**：由 Berge 定理担保——主循环结束即无增广路，匹配最大。
- **复杂度** $O(n_1 m)$；
Hopcroft–Karp 可到 $O(m\sqrt n)$。
- **KM 算法**：标杆 + 相等子图，$O(n^3)$ 解**加权指派问题**。
- 只适用于**二部图**；
一般图匹配需 Edmonds 带花算法。
