## 为什么从矩阵化简开始

持续同调讲了四篇，但「怎么把它**真的算出来**」一直悬着。答案非常漂亮：一次带纪律的**矩阵列消元**。标准算法（Zomorodian–Carlsson 2005；Edelsbrunner–Letscher–Zomorodian 2002 的增量版本）把过滤顺序编进矩阵的**上三角结构**，然后用高斯消元把边界矩阵化成「每列的主元互不重复」的形式，主元对就给出全部持续配对。理解它，等于理解 TDA 工具箱里每一行代码的物理意义。<span class="marginnote">复杂度上界：$m$ 个单形的边界矩阵消元最坏 $O(m^3)$，实际因上三角稀疏结构而快得多。工程优化三件套：<strong>clearing（清空）</strong>——先把「有主元的列」在后续列中直接消除；<strong>对偶（dualization）</strong>——改算上同调以减少非零操作；<strong>按维数分块</strong>——各维分别消元。Ripser 等现代库把三者叠加，能在秒级处理百万单形。</span>

## 1 边界矩阵与过滤顺序

设过滤顺序为 $\sigma_1, \sigma_2, \dots, \sigma_m$，要求**兼容序**：每个单形的面都在它之前出现（Rips/Čech 过滤天然满足——面比子集先出现）。**边界矩阵（boundary matrix）** $D$ 是 $m \times m$ 的域上矩阵：

$$
D[j][i] = [\sigma_i \in \partial \sigma_j],
$$

即第 $j$ 列是 $\partial \sigma_j$ 在基 $\{\sigma_1, \dots, \sigma_m\}$ 下的坐标。兼容序使 $D$ 为**严格上三角**：$\partial\sigma_j$ 只用更早的（行号更小）单形，主对角线及以下全是零。<span class="marginnote">上三角结构是算法的全部资本：消元时「只往左加列」就能保持三角性，且<strong>低行指标永远 < 列指标</strong>——这个「出生早于死亡」的刚性约束，正是持续图里 $b < d$ 的矩阵根源。若用户给乱序（面晚于复形出现），$D$ 不再上三角，配对会错乱。</span>

先澄清一个常见困惑：$D$ 是「域上的矩阵」，系数域选 $\mathbb{Z}_2$ 还是 $\mathbb{Q}$ 会改变列操作。$\mathbb{Z}_2$ 下「加列」就是按位异或，一次操作 $O(1)$；$\mathbb{Q}$ 下要做标量除法，慢一档但保留定向信息。绝大多数 TDA 管线用 $\mathbb{Z}_2$——第二篇讲过，点云数据的挠极少，牺牲定向换取速度是划算的交易。若你的数据确实需要定向（如曲面网格的方向判断），再换 $\mathbb{Q}$ 并对结果做交叉验证。

## 2 化简：每列主元唯一

对列 $j = 1, \dots, m$ 依次处理，维护一个已化简矩阵 $R$（初始 $R = D$，始终满足 $R = D \cdot V$，$V$ 可逆）：

**主元（pivot）**：列 $j$ 的**最低非零行**指标，记 $\operatorname{low}(j) = \max\{ i : R[i][j] \neq 0 \}$；零列的主元未定义。

对每一列 $j$，反复执行：若 $\operatorname{low}(j) = i$ 且之前某列 $k$（$k < j$）也有 $\operatorname{low}(k) = i$，则做**列操作 $R[\cdot][j] \mathrel{+}= R[\cdot][k]$**（在 $\mathbb{Z}_2$ 下就是「按列异或」），直到主元唯一或列为零。<span class="marginnote">这完全是对第一级《线性代数》高斯消元思路的复用：我们做的只是「把各列的主元互不相同」——等于把列空间化成「主元列标准形」的弱版本。区别在于我们<strong>不追求</strong>每列上方为零，因为只关心主元，不关心其余位置。理解这一点，算法立刻不神秘。</span>

**化简不变量（reduction invariant）**：整个过程中 $R = D \cdot V$ 恒成立（$V$ 是列操作的乘积），且最终每列主元互不重复（或为 0）。配对就藏在这些主元里。

整个流程可以压缩成不到十行的伪代码：

```text
输入：兼容序过滤 σ₁,…,σₘ 的边界矩阵 D
R ← D
for j = 1,…,m:                    # 从左到右处理每列
    while 存在已化简列 k < j 使 low(k) = low(j) ≠ ∅:
        R[·][j] ← R[·][j] + R[·][k]     # Z₂ 下即按列异或
输出：化简后的 R
配对：对每列 j，若 R 第 j 列非零，则 (σ_low(j), σ_j) 是一对
```

循环会终止：每次加列都严格降低主元位置（新主元比原主元行号小），最多降到空列。这个「主元必降」的论证是算法正确性的骨架——它保证 while 不会无限循环，也保证最终主元两两不同。

## 3 主元对 = 持续配对

化简完成后，若列 $j$ 的主元为 $\operatorname{low}(j) = i$，则单形 $\sigma_i$ 与 $\sigma_j$ 配成一对：

$$
\text{配对：}(\text{birth}=\sigma_i,\ \text{death}=\sigma_j),\qquad \text{死亡时刻} = \text{第 } j \text{ 个单形加入的时刻}.
$$

**重点：主元对的语义是「后加入的单形 $\sigma_j$ 填补了由 $\sigma_i$ 创造的类」**。若 $\sigma_j$ 是 $k$-单形，$\partial\sigma_j$ 由 $(k-1)$-单形组成，所以 $\sigma_i$ 是 $(k-1)$-单形——$H_{k-1}$ 的一个类在 $\sigma_i$ 处诞生、在 $\sigma_j$ 处消亡。<span class="marginnote">这个「$k$ 维死亡配对 $(k-1)$ 维诞生」的规则，是持续配对最常见的记混点：<strong>列（死亡）的维数比行（诞生）高 1</strong>。例如 $H_1$ 的条形码，诞生边是 1-单形、死亡面是 2-单形——列是那个填洞的三角形。零列（化简后全零）没有配对：它们要么是「从没被杀死」的<strong>本质类</strong>（配对到 $\infty$），要么是纯边界（噪声类）。</span>例如：1-单形（一条边）的出生配对 2-单形（填洞的三角形）的死亡 → $H_1$ 的一根横条；0-单形与 1-单形的配对 → $H_0$ 的合并事件。

主元对语义里还有一个「出生与死亡同刻」的边界情形：当一对 $(i, j)$ 的出生与死亡发生在同一步（例如 $H_0$ 的某次合并恰好与某条边的加入同时发生）时，持续图里它会落在对角线上，寿命为 0。这类点被视为噪声、不产生特征，但算法层面它们仍是合法的配对——下游筛选「寿命 $> 0$」时会被统一滤掉。理解这一点，就不会把「图上的对角线点」误当成程序 bug。

## 4 公式解析：$\operatorname{low}(j) = \max\{ i : R[i][j] \neq 0 \},\qquad R = D\,V$

化简算法只有两个「公式」，拆开它们：

**第一步，$R = D\,V$**：$V$ 是列操作的乘积（每次 $R[\cdot][j] \mathrel{+}= R[\cdot][k]$ 对应乘一个初等可逆阵）。这条等式保证「消元不改变任何同调信息」——$R$ 的列空间与 $D$ 的相同，圈与边界的关系不变。
- **第二步，$\operatorname{low}(j) = \max\{i: R[i][j] \ne 0\}$**：主元 = 列里**最靠下**的非零行。兼容序使主元 $i < j$，于是「行出生、列死亡」且「出生严格早于死亡」。重复主元冲突时加列，等于在消元过程中**合并同生类**——冲突解决的那一步，正是两个类的合并/死亡事件本身。
- **第三步，主元唯一性**：最终每列主元互不相同，意味着每个死亡类唯一对应一个出生类——配对良定义。若存在两列共享主元而不解决，则两个「死亡」会对应同一个「出生」，配对失效。化简循环的目的就是杜绝这种情况。

这套「行列双下标」的记号也解释了算法的几何直觉：**行 = 出生（更早的单形），列 = 死亡（更晚的单形）**。主元对 $(i, j)$ 就是「第 $i$ 个单形出生的类在 $j$ 时死去」的代数翻译。把行号列号换成过滤时刻，就是持续图上的点 $(b, d) = (\text{时刻}_i, \text{时刻}_j)$——矩阵里的主元、图上的点，同一件事的两种记法。

## 5 手算一遍：三角形

取过滤 $\sigma_1=v_0,\ \sigma_2=v_1,\ \sigma_3=v_2,\ \sigma_4=e_{01},\ \sigma_5=e_{12},\ \sigma_6=e_{02},\ \sigma_7=t_{012}$，用 $\mathbb{Z}_2$ 系数（消元即按列异或）：

- 边界：$\partial e_{01} = v_0 + v_1$（行 1,2），$\partial e_{12} = v_1 + v_2$（行 2,3），$\partial e_{02} = v_0 + v_2$（行 1,3），$\partial t = e_{01}+e_{12}+e_{02}$（行 4,5,6）。
- 化简：列 4 主元 2 → 配对 $(v_1, e_{01})$（$v_1$ 并入 $v_0$，符合 Elder 规则）；列 5 主元 3 → 配对 $(v_2, e_{12})$；列 6 主元先为 3 与列 5 冲突，加列 5 得 $v_0+v_1$，主元 2 与列 4 冲突，再加列 4 变**零列** → $e_{02}$ 是 $H_1$ 的「诞生者」（环闭上，无人杀它）；列 7 主元 6 → 配对 $(e_{02}, t_{012})$：$H_1$ 的类在 $e_{02}$ 出生、在三角形填实 $t$ 时死亡。<span class="marginnote">最终配对：$(v_1,e_{01}), (v_2,e_{12}), (e_{02},t_{012})$，外加 $v_0$ 未配对 → 本质类（$H_0$ 的无穷条）。于是 $H_0$ 一条无穷横条、$H_1$ 一条 $(\text{σ6},\text{σ7})$ 的横条——与「三角形最终可缩」一致：$H_1$ 的条在过滤末被杀死。这个 7×7 的例子涵盖了算法的全部机制：冲突、加列、零列、配对。</span>

把同样的机制向上推一维，就明白 $H_2$ 的配对怎么来。给三角形补上内部再升级成四面体：顶点 4、边 6、面 4、体 1，共 15 个单形。边界上，$\partial$ 四面体 = 4 个三角面的和（$\mathbb{Z}_2$ 下）；四面体列的主元是某个三角面列。按「死亡列维数 = 诞生行维数 + 1」，四面体（3-单形）的死亡配对的是 2-单形（一个面）——$H_2$ 的类在那个面闭合成「空腔」时出生、在四面体把空腔填实时死亡。**同一套主元逻辑无缝复制到所有维数**，这就是矩阵化简「一维通了、维维皆通」的原因。

## 6 辨析：三个高频坑

**辨析｜易错点：**

- **列序必须兼容**：面未先出现 → $D$ 非上三角 → 主元可能大于列号，配对错乱。任何自定义过滤都要先验证兼容序。
- **零列 ≠ 噪声**：零列可能是「从未被杀的类」（$\infty$ 配对），也可能真是「被边界化的类」；要区分必须看它是否曾作为主元配对过。把零列一律当噪声，会丢掉 $H_0$ 的无穷条。
- **$\mathbb{Z}_2$ 下符号消失**：$(-1)^i$ 系数在 $\mathbb{Z}_2$ 下全为 $+1$，列操作退化为异或——快，但**方向信息丢失**（第二篇提过）；要定向信息就换 $\mathbb{Q}$ 系数，代价是消元出现标量乘除。
- **复杂度上界要清醒**：最坏 $O(m^3)$，指数级复形（如全 Rips）会让 $m$ 爆炸——所以工程库才需要 clearing + 对偶 + 分块。

clearing 的加速原理值得单独讲清。观察到：一旦某列 $j$ 化简后非零且主元为 $i$，那么在处理任何后续列 $k$ 时，凡边界里含 $\sigma_i$ 的项都可以直接用「已化简列 $j$ 的倍数」消掉——因为主元的唯一性已经保证不会再产生新主元。于是可以倒过来做：先按维数从高到低扫一遍，把每一列的主元提前标记，再正式化简时跳过所有「已被标记杀掉」的操作。实践中 clearing 往往把有效工作量砍掉一个量级——这正是 Ripser 能在秒级处理百万单形的原因之一。

对偶（dualization）是第二件加速工具：改算 $H^k$ 的上同调，因为上同调矩阵在过滤早期更稀疏（高维单形加入得晚），非零操作的次数随之减少。对偶计算的配对可通过「同调-上同调对偶」与原始结果互相转换，殊途同归。

### 术语速查

| 术语 | 一句话定义 |
| --- | --- |
| 兼容序 | 每个单形的面先于它出现的过滤顺序 |
| 边界矩阵 $D$ | 第 $j$ 列为 $\partial\sigma_j$ 的坐标，兼容序下严格上三角 |
| 主元 | $\operatorname{low}(j)$，列 $j$ 最低非零行的指标 |
| 列化简 | 主元冲突时加列，保持 $R = DV$ 且主元唯一 |
| 零列 | 化简后全零：本质类或纯边界，需区分 |
| clearing | 用已有主元列提前消除后续列，工程加速三件套之一 |

## 7 小结

- **输入**：兼容序过滤 + 域上边界矩阵 $D$（严格上三角）。
- **化简**：左到右列消元，保证 $R = DV$ 且主元互不重复；主元 = 列内最低非零行。
- **配对**：$\operatorname{low}(j) = i$ → $(\sigma_i$ 诞生, $\sigma_j$ 死亡)；死亡列维数 = 诞生行维数 + 1。
- **语义**：列操作 = 合并同生类；零列 = 本质类或噪声，需区分。
- **工程**：clearing、对偶、按维分块把 $O(m^3)$ 拉到可用；三角形例子覆盖全部机制。

在最后一节，我们把持续同调从「单参数」推向「多参数」—— **多重持续同调与 zigzag 持久性**，那里稳定性与算法的故事要重新讲一遍。
