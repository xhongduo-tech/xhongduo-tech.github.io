## 为什么从 Curry–Howard 开始

本专题前面反复埋下同一句伏笔：「证明像程序，蕴含像函数，规范化像 $\beta$-归约」。现在把这些伏笔一次性兑现——**Curry–Howard 对应**是证明论与计算理论之间的一座完整桥梁，它把「证明一个命题」与「写一个程序」彻底等同起来。<span class="marginnote">这条对应有两条独立谱系：库里（Haskell Curry）在 1958 年注意到组合子逻辑与希尔伯特系统的对应；霍华德在 1969 年提出（1980 年正式发表）「公式即类型」。德·布鲁因（de Bruijn）在 AUTOMATH 里把它工程化，最终催生了 Coq、Agda、Lean 这些「证明助手」。</span>

为什么它在当代如此重要？因为今天的软件验证工具（Coq、Lean）和类型论编程语言（Haskell、Agda、Idris）都是 Curry–Howard 的直系后裔。理解它，等于同时理解证明论的「证明规范化」与编程语言的「程序求值」——两个领域最深的技术，原来是一个东西。

## 1 对应表

Curry–Howard 对应给出了一张「翻译字典」，把逻辑对象与计算对象一一对应：

| 逻辑侧 | 计算侧 |
| --- | --- |
| 命题 $A$ | 类型 $A$ |
| 证明 $\pi$ | 程序 / 项 $t$ |
| 蕴含 $A \to B$ | 函数类型 $A \to B$ |
| 合取 $A \land B$ | 积类型 $A \times B$（有序对） |
| 析取 $A \lor B$ | 和类型 $A + B$（带标记联合） |
| 假 $\bot$ | 空类型 $\mathbf{0}$（无元素） |
| 否定 $\neg A$ | 函数类型 $A \to \mathbf{0}$ |
| 全称 $\forall x\,A(x)$ | 依值函数类型 $\Pi x\,A(x)$ |
| 存在 $\exists x\,A(x)$ | 依值对类型 $\Sigma x\,A(x)$ |
| 证明规范化 | $\beta$-归约（程序求值） |
| 截消 / 截规则 | 引理内联 / 宏展开 |

字典的要点不在单行，而在**整体结构**：逻辑里的每一条规则，在计算侧都是一条类型规则；逻辑里的每个证明，在计算侧都自动是一个类型正确的程序。<span class="marginnote">最令人称奇的是「真值」没有对应物——类型系统里没有「真假」，只有「类型是否被居住（inhabited）」。一个类型有程序居住，当且仅当对应命题可证。这就是为什么库里坚持说：<strong>类型的「存在性」比「真」更根本</strong>。</span>

聪明的读者立刻会追问：经典逻辑的排中律对应什么？答案见第 5 节——它需要控制算子，不是普通程序能表达的。字典为此只对直觉主义逻辑「全额生效」，这个边界本身就是信息。

## 2 公式解析：蕴含 = 函数类型

对应字典里最核心的一行是蕴含。在自然演绎里，蕴含引入与消去是一对；在类型系统里，它们恰好是函数定义与函数调用：

$$
\frac{x : A \qquad \vdots}{t : B} \qquad \longmapsto \qquad \frac{[x : A]}{\vdots}{t : B} \quad \text{得} \quad \lambda x.\,t : A \to B
$$

分四步拆解：

- **第一步，看假设变变量**：自然演绎里的假设 $[A]$ 变成了类型环境里的变量声明 $x : A$。假设「$A$ 成立」= 变量「$x$ 有类型 $A$」。
- **第二步，看证明变项**：假设 $A$ 下推出的证明 $t$，变成一个可能引用 $x$ 的项 $t$。
- **第三步，看蕴含引入变抽象**：蕴含引入「消去假设 $[A]$ 得 $A \to B$」对应 $\lambda$-抽象「绑定变量 $x$ 得函数 $\lambda x.\,t$」——两者都把一个「开放」的推导/表达式变成一个「闭」的对象。
- **第四步，看蕴含消去变应用**：蕴含消去（分离规则）对应函数应用：给 $\lambda x.\,t$ 喂一个 $A$ 类型的实参 $s$，得到 $t[s/x]$。于是**「证明 $A \to B$」=「写一个类型为 $A \to B$ 的函数」**，一句废话都不差。

这条对应还同时解释了规范化：一个「定义后立即调用」的 $\lambda$-抽象——$(\lambda x.\,t)\,s$——被 $\beta$-归约成 $t[s/x]$，正是自然演绎里「蕴含引入后立即消去」的绕路消除。

这条对应还有一个语言学的彩蛋：为什么叫「蕴含」？拉丁语 implicare 是「卷入、包含」——$A \to B$ 把 $A$ 的证明「卷入」对 $B$ 的证明之中；函数类型把参数 $A$「卷入」对结果 $B$ 的构造之中。同一个词，两种语言，说的都是同一件事。

## 3 用类型系统重写自然演绎

把整张字典搬到形式语言里，就得到**简单类型 $\lambda$-演算（simply typed lambda calculus）**——一门同时是逻辑与编程语言的形式系统。它的核心判定规则：

| 类型规则 | 名称 | 对应的逻辑规则 |
| --- | --- | --- |
| $\dfrac{\Gamma, x:A \vdash t : B}{\Gamma \vdash \lambda x.\,t : A \to B}$ | 抽象 | 蕴含引入 |
| $\dfrac{\Gamma \vdash s : A \qquad \Gamma \vdash f : A \to B}{\Gamma \vdash f\,s : B}$ | 应用 | 蕴含消去（分离） |
| $\dfrac{\Gamma \vdash s : A \qquad \Gamma \vdash t : B}{\Gamma \vdash (s, t) : A \times B}$ | 配对 | 合取引入 |
| $\dfrac{\Gamma \vdash t : A \times B}{\Gamma \vdash \pi_1 t : A}$ | 第一投影 | 合取消去 |

这张表读起来几乎就是第 1 篇自然演绎规则表的「翻译版」。**每个可证命题对应一个可居住类型，每个证明对应一个程序**，反过来也一样。简单类型 $\lambda$-演算还自动带上一条漂亮的元性质：它是**强规范化**的——每个项都能归约到唯一范式，且归约必然终止。这正是自然演绎规范化的对应物，也是「类型安全保证程序终止」的原始版本。<span class="marginnote">「类型可居住性（inhabitation）问题」——给定类型 $A$，是否存在程序 $t : A$——在一阶逻辑里恰是可满足性问题的化身。这个平移使得「逻辑不可判定」的结论直接转移为「类型居住性不可判定」，逻辑与计算的界限因此完全打通。</span>

## 4 为什么它如此有价值

Curry–Howard 的价值不在它好看，而在它好用。三条最实际的产出：

**程序提取（program extraction）**：在一个直觉主义证明系统里证明 $\forall x\,\exists y\,P(x,y)$，自动得到一个「对每个输入算出见证 $y$」的程序——证明即算法，见第 11 篇。
**类型化编程语言**：Haskell、OCaml 的类型系统直接继承 Curry–Howard 的骨架；「类型检查」在数学上就是「检查证明是否正确」。
**证明助手（proof assistants）**：Coq、Lean、Agda 把「写证明」实现为「写程序」，把「证明检查」实现为「类型检查」——数学证明第一次可以被机器完全验证。当代的数学形式化（如四色定理、费马大定理的局部形式化、乃至大模型辅助的定理证明）都站在这个地基上。

**这条链路的终点是：机器能检查我们信不信得过的每一个数学步骤。** 这正是「从极限到大模型」主线里，数学被算法化的最直接例证——证明不再是纸上的修辞，而是可运行的、可验证的代码。

还要注意一个看似平凡、实则关键的事实：**从证明提取的程序没有死循环**。因为程序提取自规范化证明，而规范形保证了求值终止。这个「证明即程序」的承诺，正是认证程序（certified programs）与验证编译器（如 CompCert）的理论地基——程序的安全性不是靠测试「碰运气」，而是由构造它的证明直接保证。

## 5 从简单类型到依赖类型

字典里有一行格外醒目：全称 $\forall$ 对应**依值函数类型（dependent function type）** $\Pi x\,A(x)$——函数的返回类型随参数变化。这是简单类型 $\lambda$-演算所没有的，它把 Curry–Howard 从「一阶逻辑」提升到「依值逻辑」，构成现代证明助手的核心：

| 维度 | 简单类型 | 依值类型 |
| --- | --- | --- |
| 返回类型 | 固定 | 依赖参数 |
| 对应逻辑 | 命题逻辑 | 量词深入类型内部 |
| 类型检查 | 可判定 | 一般不可判定（需交互） |
| 代表系统 | 简单 λ 演算 | Coq / Lean / Agda |

举例：命题「对每个自然数 $n$，存在它的后继」写作 $\Pi n{:}\mathbb{N}\,\Sigma m\,(m = Sn)$。它的证明就是一个程序：输入 $n$，输出对 $(Sn, \mathrm{refl})$——见证项与证明一起打包返回。<span class="marginnote">依值类型把「数据」与「性质」统一进同一个类型空间：一个类型的元素可以同时携带数据与证明。这就是为什么在 Coq / Lean 里，「证 $\forall n\,\exists m\,P(n,m)$」就是「写一个函数，输入 $n$ 输出见证 $m$ 及其证明」——数学定理与程序在此完全合一。</span>依赖类型把不变量写进类型本身：安全索引、有序结构、正确排序，都能由类型系统在编译期强制。

## 6 辨析：经典逻辑的 Curry–Howard 呢

字典有个前提：**它是为直觉主义逻辑量身定做的**。经典逻辑多了双重否定消去 $\dfrac{\neg\neg A}{A}$，这对应什么样的程序？答案是**控制运算符（control operators）**——如 Scheme 的 `call/cc`、程序里的「跳转」与「异常」。

- 在类型系统里，双重否定消去对应类型 $((A \to \mathbf{0}) \to \mathbf{0}) \to A$，它不能被普通 $\lambda$-项居住，需要额外原语 $\mathcal{C}$。
- $\mathcal{C}$ 的求值行为是非局部跳转：它把「未来的继续」捕获成续延（continuation），再按需调用——这正是经典证明里「反证法」的运行时形态。
- 反过来，**双重否定翻译**（第 5 篇）把经典逻辑编码进直觉主义，对应程序语言里的**续延传递风格（CPS）**——把每个函数都改成「接受续延」的形式。

**辨析｜易错点：** 很多人以为「Curry–Howard 对经典逻辑也自然成立」。准确说法是：直觉主义逻辑的 Curry–Howard 是干净的同构；经典逻辑需要额外机制（续延、控制算子），且规范化性质（强规范化）往往受损。**经典证明「可程序化」，但需要更复杂的运行时**——这正是证明论与编程语言交叉处最微妙的一课。

这个「经典逻辑需要额外运行时」的观察，在编程语言研究里对应一个著名结论：格列芬（Timothy Griffin）在 1990 年正式把类型 $((A \to \mathbf{0}) \to \mathbf{0}) \to A$ 对应到 Scheme 的 `call/cc`，确认了经典证明的算法内容就是「非局部跳转」。从那以后，「经典证明能提取出什么算法」成为证明论与类型论交叉处长期活跃的课题。

## 7 小结

- **Curry–Howard 对应**把命题与类型、证明与程序、规范化与 $\beta$-归约一一对应。
- 核心一行：蕴含 $A \to B$ = 函数类型；蕴含引入 = $\lambda$-抽象；蕴含消去 = 函数应用。
- 简单类型 $\lambda$
