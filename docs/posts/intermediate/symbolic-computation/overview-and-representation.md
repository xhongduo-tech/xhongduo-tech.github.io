## 为什么从符号计算开始

从小学到大学的「解方程」，我们一直在做同一件事：**把 $x$ 当成一个真正的符号去变形**，而不是代入某个数值去近似。$x^2 - 3x + 2 = 0$ 的答案是 $x = 1, 2$，这是精确的；而用二分法得到 $x \approx 1.0000001$，这是数值的。前者叫**符号计算（symbolic computation）**，后者叫**数值计算（numerical computation）**。<span class="marginnote">符号计算在英文里也叫 computer algebra（计算机代数），两者在文献中几乎同义。本专题沿用的三部教材——《计算机代数算法》《现代计算机代数》《理想、簇与算法》——正是这门学科的三大支柱。</span>

为什么要单独开一门课来研究它？因为「把符号当成对象去运算」这件事，隐藏着一连串只有机器才会暴露的难题：**多项式怎么存才不爆炸？两个看似不同的表达式何时算相等？方程组的解如何精确给出？** 这些问题构成了符号计算的全部内容。从极限到大模型这条主线上，符号计算是「精确数学」在计算机上的化身——它是自动定理证明的推理引擎、科学计算中误差分析的对照物，也是符号回归、可解释 AI 等技术的基础。这一篇先把地图铺开：**我们到底在计算什么对象，用什么表示它们，站在什么样的代数结构上。

## 1 符号计算的对象

符号计算的**对象**是那些「带结构的精确数学对象」，而非浮点数。按复杂性递增排列，常见的对象有：

**任意精度整数（big integers）**：整数没有机器字长的上限，$2^{1000}$ 是一个合法的对象，可以精确存储与运算。<span class="marginnote">C 语言的 `int` 只有 32 或 64 位，溢出是常态；计算机代数系统则内置任意精度整数（GMP 之类），这是整个符号计算大厦的地基。数值计算里「溢出了」，符号计算里没有这个概念。</span>

**有理数**：分数 $\frac{p}{q}$ 在机器里不是两个浮点数的比值，而是「分子 + 分母」两个任意精度整数，且永远保持最简形式。

**多项式与有理函数**：$3x^2y - xy + 7$ 是一个二元多项式；$\frac{x^2+1}{x-1}$ 是一个有理函数。这是符号计算的主角，后面八篇几乎都围绕它展开。

**代数数与超越数**：$\sqrt{2}$ 是最小多项式 $t^2 - 2 = 0$ 的根，可用「最小多项式 + 一个隔离区间」表示；$e$、$\pi$ 则需特殊处理。

**矩阵、群元、微分算子**：线性代数、群论、微分方程中的对象，都以符号形式参与运算。

这些对象与其典型表示，可以收进一张表：

| 对象 | 典型表示 | 关键点 |
| --- | --- | --- |
| 整数 | 任意精度整数（数组式存储） | 无溢出 |
| 有理数 | 「分子 + 分母」对 | 恒保持最简 |
| 多项式 | 稠密数组 / 稀疏项列表 | 表示选择见下一篇 |
| 有理函数 | 「最简分子 + 分母」 | 需 GCD 规范化 |
| 代数数 | 最小多项式 + 隔离区间 | 精确表示根 |
| 矩阵 | 符号元素数组 | 符号线性代数 |

这些对象的共同点是什么？**它们都能被有限的数据结构精确刻画，且在其上定义了确定、可计算的运算。** 这正是「计算机代数」四个字的含义：计算机 + 代数结构。

## 2 表示：从表达式树到规范形式

同一个数学对象，可以有无数种「写法」；但计算机只能给一种存储。**表示（representation）**是符号计算的第一道分水岭，它直接决定算法能跑多快、比较两个对象是否相等有多难。

最基本的表示是**表达式树（expression tree）**：内部节点是运算符（`+`、`×`、`^`、`∂` 等），叶子是原子（数、变量、常量）。表达式树忠实反映人的书写，但它有两个致命缺陷：

**共享度低**。$x^{100}$ 如果存成一棵 100 层的指数树，遍历一遍就要走 100 步；更聪明的做法是**带共享的 DAG（有向无环图）**——同一个子表达式只存一份，用指针引用。$x^{100}$ 的 DAG 只有两层：根节点「幂」，指向唯一的叶子 $x$ 与常量 100。<span class="marginnote">「共享」在符号计算里几乎无处不在：化简时同一个子表达式被反复用到，DAG 让重复计算归零。这与编译原理里的公共子表达式消除、深度学习框架里的计算图共享是同一个思想，见第三级《编译原理》与第四级《深度学习》。</span>

**相等性难判**。$x^2 - 1$ 与 $(x-1)(x+1)$ 是同一个多项式，但表达式树完全不同。为了判定相等，符号计算引入**规范形式（canonical form）**：每个等价类选出唯一代表元。若系统把每个多项式都规范化为「按字典序展开的形如 $a_n x^n + \cdots + a_0$ 的表达式」，那么两个多项式相等当且仅当它们的规范形式逐项相同——问题瞬间变成字符串比较。

规范形式是把「语义相等」翻译成「语法相等」的手段。**一个运算是否保值（即两个相等的对象运算后仍相等）决定了它能否安全地化简**，这就是下文要说的代数结构的意义。

## 3 代数系统：运算必须在结构里成立

符号计算的正确性，最终要靠**代数结构**来背书。我们最常站立的三个结构是：

**域（field）**：一个集合配上加、乘两种运算，满足交换律、结合律、分配律，且每个非零元有乘法逆元。$\mathbb{Q}$（有理数）、$\mathbb{R}$、$\mathbb{C}$ 都是域。<span class="marginnote">有限域 $\mathbb{F}_p$（模素数 $p$ 的剩余类）也是域，而且它在因式分解、编码理论里比实数域更重要——因为里面的算术是精确的、可判定的。第二级《抽象代数》里你会系统学到域的公理，这里先把它当「运算能自由进行的场所」来用。</span>

**环（ring）**：域去掉「非零元有逆」得到的结构。$\mathbb{Z}$（整数）、多项式环 $\mathbb{Z}[x]$、$\mathbb{Q}[x]$ 都是环。环里可以加、减、乘，但不一定能除——这正是「最大公因子」问题诞生的土壤。

**特征（characteristic）**：域里最小的正整数 $p$ 使 $1+1+\cdots+1 = 0$ 成立，若不存在则为 0。$\mathbb{Q}$ 的特征是 0，$\mathbb{F}_p$ 的特征是 $p$。<span class="marginnote">特征 $p$ 带来一个反直觉现象：$(a+b)^p = a^p + b^p$（因为中间项的系数都被 $p$ 整除）。这被称作「新鲜土豆定理」（freshman's dream），它让有限域上的运算与特征 0 完全不同——因式分解、微分都要分别对待。</span>

为什么必须先分清这些结构？因为**同一个算法在不同结构上可能失效**。例如「除以首项系数」在 $\mathbb{Z}[x]$ 里不总是允许，在 $\mathbb{Q}[x]$ 里才总是允许；「求导后 $f' = 0$ 蕴含 $f$ 是常数」只在特征 0 成立。写算法之前先问「我在哪个环/域上工作」，是符号计算的第一职业习惯。

三种基本结构对照：

| 结构 | 运算 | 例子 | 符号计算的关注点 |
| --- | --- | --- | --- |
| 域（field） | $+,-,\times,\div$ 均封闭 | $\mathbb{Q}, \mathbb{R}, \mathbb{C}, \mathbb{F}_p$ | 除法总可行，算法最顺畅 |
| 环（ring） | $+,-,\times$ 封闭 | $\mathbb{Z}, \mathbb{Z}[x], \mathbb{Q}[x]$ | 除法不一定可行 → GCD 问题 |
| 整环上的欧几里得结构 | 带余除法 | $\mathbb{Z}, K[x]$ | 辗转相除、规范化的土壤 |

**选结构的口诀**：想让算法「无脑顺畅」就用域；想研究「整除、因子、理想」就用环；想做「辗转相除」就需要欧几里得整环。符号计算的大多数麻烦，都源于「在环上用了域的算法」或「在整环上用了域的概念」。

## 4 公式解析：规范化的有理数表达式

把一个有理函数规范化，是符号计算最常见的操作之一。设

$$
R = \frac{P(x)}{Q(x)}, \qquad \deg P \lt  \deg Q
$$

规范化分三步：

- **第一步，约分**：用欧几里得算法求出 $g = \gcd(P, Q)$（多项式最大公因子），令 $P_0 = P / g$，$Q_0 = Q / g$，使分子分母互素。
- **第二步，定型**：把分母化为首一（首项系数为 1），即 $Q_0$ 乘以 $c^{-1}$（$c$ 为首项系数），分子相应乘以 $c$。于是每个有理函数有**唯一**的「最简 + 首一分母」表示。
- **第三步，规约**：若 $\deg P_0 \ge \deg Q_0$，做多项式带余除法写成 $A + \frac{P_1}{Q_0}$ 的形式，其中 $\deg P_1 \lt  \deg Q_0$，$A$ 是商。

**这个三步流程的每一个细节都依赖代数结构**：第一步需要「能算最大公因子」（环），第二步需要「能除以首项系数」（域），第三步需要「带余除法成立」（欧几里得整环）。把三个结构分清，规范化才能既正确又高效。

## 5 辨析｜易错点

**辨析｜易错点：** 把符号计算与「用符号变量做数值计算」混为一谈，是最常见的误解。`numpy` 里的 `polyval` 输入的是系数数组，输出的是**数值**；而 SymPy 的 `Poly` 输入系数，输出的仍是**符号表达式**。前者在浮点域上近似，后者在符号环上精确——这是两条不同的技术路线。

另一个易错点：**多项式相等 ≠ 表达式相同**。$x^2 - 1$ 与 $(x-1)(x+1)$ 是同一个多项式，但它们的表达式写法完全不同。符号系统靠**规范形式**判定相等：先把每个表达式展开、合并同类项、按选定的序排列，再逐项比较。若系统没有做规范化就宣称「两个表达式不等」，很可能只是没化简而已——**把「未化简」误报成「不相等」，是初用 CAS 的人最容易踩的坑**。<span class="marginnote">成熟系统对相等性判定各有一套「默认尺度」：SymPy 的 `simplify`、`expand` 会先做规范形式预处理；而 Maple 的 `evalb` 与 Mathematica 的 `SameQ` 默认只比较语法形式，相等判断往往需要先手动 `expand`。用 CAS 前弄清系统的默认尺度，是减少误报的第一步。</span>

第三个易错点：**对象表示与「计算模型」绑定**。同一个多项式在稠密数组里是 $[3, 0, 2, 0, -1, 7]$，在稀疏列表里是 $[(3,5),(2,3),(-1,1),(7,0)]$，在表达式树里又是一棵嵌套树。三种表示下的同一算法（比如求最大公因子）复杂度完全不同。**先确定表示，再谈算法**——这是贯穿本专题的方法论：下一篇《多项式算术》的全部内容，都是「表示决定算法」的展开。

**本篇术语速查**：

| 术语 | 含义 | 一句话记忆 |
| --- | --- | --- |
| 符号计算（symbolic computation） | 对精确数学对象做运算，不做浮点近似 | 与数值计算相对 |
| 表达式树 / 带共享 DAG | 表达式的两种存储结构 | DAG 让重复子表达式只存一份 |
| 规范形式（canonical form） | 每个等价类选出的唯一代表元 | 相等判定的标尺 |
| 稠密 / 稀疏表示 | 系数数组 / 非零项列表 | 表示决定算法 |
| 域（field）/ 环（ring） | 除法是否总是可行的代数结构 | 域里顺畅，环里出 GCD |

这张速查表浓缩了本片的全部概念：对象（第一行）、表示（中间两行）、结构（最后一行）。记住它们，后面的每一篇都能在这里找到坐标系。

## 6 小结

- **符号计算**处理精确的数学对象（整数、有理数、多项式、代数数），与浮点近似相对，目标是「不丢失信息」。
- 对象的**表示**（表达式树、稠密/稀疏数组、带共享 DAG）直接决定算法效率与相等性判定的难度。
- **规范形式**把「语义相等」翻译成「语法相等」，是 CAS 判定相等、化简结果的基础设施。
- **代数结构**（域、环、欧几里得整环）为算法的适用条件背书——写算法之前先问「我在哪个结构上工作」。
- 三个易错点：符号计算 ≠ 符号变量的数值计算；多项式相等 ≠ 表达式相同；表示决定算法。

在下一篇，我们将进入符号计算的第一个主战场——**多项式算术**：稠密与稀疏表示如何落地、Karatsuba 与 FFT 如何让乘法超越 $O(n^2)$。
