## 为什么从递归函数开始

上一篇我们从机器出发定义了可计算；这一篇换成函数的视角：**不看机器怎么做，只看函数怎么从更简单的函数"长"出来。** 这条路线由哥德尔（Kurt Gödel）与丘奇（Alonzo Church）开辟，它把可计算性还原为数学里最古老也最可靠的机制——**递归**。递归在编程中是人人都熟悉的技巧（阶乘、斐波那契、树遍历），而原始递归函数理论告诉我们：递归不是"一种编程风格"，它本身就是可计算性的骨架。学完这篇，你将同时掌握两条通往"可计算"的路径，并为理解下一节的**可计算枚举集**与**停机问题**备好函数层面的工具。<span class="marginnote">"递归"贯穿本专题：这里讲函数如何递归定义，后面讲集合如何递归可枚举。第三级《编译原理》中的递归下降、数据结构里的递归算法，都能在这里找到理论源头。</span>

## 1 从机器到函数：换一副眼镜

Turing 机回答"哪些函数可被算出"，但没有给出函数的"制造工艺"。递归函数论回答同一个问题，却换了一种提问方式：**从极少的、显然可算的函数出发，用极少的、显然保持可算性的操作，能拼出什么样的函数？** 如果这些"积木"拼出的恰好是全部可计算函数，那就得到了可计算性的第二个定义。

答案分两步走：第一步先拼出**原始递归函数（primitive recursive functions）**——它覆盖了日常几乎全部算术函数；第二步发现原始递归不够用，于是引入**μ 算子**，得到完整的**部分递归函数（partial recursive functions）**。本节先走第一步。

## 2 三块积木与一个拼装规则

原始递归函数从一个极小的基类出发，用两个规则迭代生成。

**基础函数** 有三类，每一个都"显然可算"：

**零函数**：$Z(x) = 0$，对任何输入都返回 0。
**后继函数**：$S(x) = x + 1$，把输入加一。<span class="marginnote">后继函数是整个系统的"发动机"：它只加一，但加法的本质就是"反复加一"，乘法是"反复加"，幂是"反复乘"——一切算术都从这一格一格的+1 中涌现。</span>
- **投影函数**：$P^n_i(x_1, \dots, x_n) = x_i$，把第 $i$ 个参数原样返回，用来"丢弃"不用的参数。

**拼装规则** 有两条：

- **合成（composition）**：若 $g_1, \dots, g_k$ 与 $h$ 都已是原始递归函数，则
$$f(\vec{x}) = h\big(g_1(\vec{x}), \dots, g_k(\vec{x})\big)$$
也是原始递归函数。就是把几个函数的输出喂给另一个函数。
- **原始递归（primitive recursion）**：若 $g$ 与 $h$ 已是原始递归函数，则按下式定义的 $f$ 也是：
$$f(\vec{x}, 0) = g(\vec{x}), \qquad f(\vec{x}, y+1) = h\big(\vec{x}, y, f(\vec{x}, y)\big)$$

第二条规则是递归的"官方版本"：先给出**基底**（$y=0$ 时的值），再给出**递推步**（如何从 $f(\cdot, y)$ 算出 $f(\cdot, y+1)$）。**只要知道 $f(\vec{x}, 0)$，就能一步一步推出 $f(\vec{x}, 1), f(\vec{x}, 2), \dots$**——这就是"原始递归"名字的由来，也是它显然可算的原因：计算一定在有限步内结束。

## 3 从零函数到加法、乘法、阶乘

空谈规则不如动手搭。我们一步步从基础函数造出熟悉的算术函数，这个过程相当于"用最少的指令写一个标准库"。

**加法**：$add(x, y) = x + y$，对 $y$ 做原始递归：

$$add(x, 0) = P^1_1(x) = x, \qquad add(x, y+1) = S\big(add(x, y)\big)$$

基底说"加 0 等于原数"，递推步说"加 $y+1$ 等于（加 $y$ 的结果）再 +1"。反复展开：$add(x,3) = S(S(S(x)))$。<span class="marginnote">注意这个定义里"$x$ 不变、对 $y$ 递归"的模式：原始递归的第二个变量 $y$ 扮演"循环计数器"，第 3 节公式解析会拆开看这一点。</span>

**乘法**：$mult(x, y) = x \cdot y$：

$$mult(x, 0) = 0, \qquad mult(x, y+1) = add\big(x, mult(x, y)\big)$$

**阶乘**：$fact(y) = y!$（这里不需要参数 $\vec{x}$，是"零元参数"的原始递归）：

$$fact(0) = 1, \qquad fact(y+1) = mult\big(y+1, fact(y)\big)$$

**辨析｜易错点：** 有人以为"原始递归"必须每一步都调用自己，其实递推步 $h$ 可以完全不用 $f(\vec{x}, y)$——这时递归退化为普通的递推。真正要紧的是：$h$ 的第三个参数里放着"上一步的结果"，而 $h$ 本身必须已经（通过合成或基底）被证明是原始递归的。每造一个新函数都必须"注册"进这个体系，不能指望魔术。

## 4 公式解析：加法函数的递归定义

把加法定义逐行拆开，它是一切复杂递归的样板：

$$add(x, 0) = x, \qquad add(x, y+1) = S\big(add(x, y)\big)$$

- **第一步，读基底**：$add(x, 0) = x$。用 $g(x) = P^1_1(x)$ 实现——当第二个参数为 0 时直接返回第一个参数。这是递归的"锚点"，保证计算有处落脚。
- **第二步，读递推步**：$add(x, y+1) = S(add(x, y))$。这里 $h(x, y, z) = S(z)$：它忽略 $x$ 与 $y$，只对"上一步结果 $z$"做一次后继。于是每递归一层，值就 +1。
- **第三步，追踪一次展开**：
$$add(2, 3) = S(add(2, 2)) = S(S(add(2, 1))) = S(S(S(add(2, 0)))) = S(S(S(2))) = 5$$
递归把"加 3"翻译成"对 2 做三次后继"，计算过程就是一个符号一个符号地踏实展开。
- **第四步，看终止性**：递归的参数 $y$ 每层减一，最终到达 0 命中基底。**凡原始递归函数的计算都必然终止**——这是它与后面"部分递归函数"最关键的分界线：部分递归允许永不停止，原始递归不允许。

## 5 原始递归的边界：阿克曼函数

原始递归函数家族庞大得惊人：四则运算、取模、大小比较、指数、质数判定……都能证明是原始递归。但它有一个天花板：**阿克曼函数（Ackermann function）**。

$$A(0, n) = n + 1, \qquad A(m+1, 0) = A(m, 1), \qquad A(m+1, n+1) = A(m, A(m+1, n))$$

$A$ 增长极快：$A(1, n) = n + 2$，$A(2, n) = 2n + 3$，$A(3, n) = 2^{n+3} - 3$，而 $A(4, 3)$ 就已经是天文数字。1928 年，阿克曼（Wilhelm Ackermann）证明了：**$A$ 不是原始递归函数**。<span class="marginnote">直觉是：每个原始递归函数都被某个固定的"嵌套深度"所限制——它可以自己调用自己，但内层调用的"复杂度"不能比外层跳级太多；阿克曼函数则会调用 $A(m, A(m+1, n))$，把 $m+1$ 层的输出塞回 $m$ 层作为输入，这种"越级自指"超出了原始递归的章程。</span>

于是原始递归不够了。要包含 $A$（以及所有直觉上可计算的函数），必须引入更强的一步。

## 6 μ 算子：把"搜索"变成计算

**核心概念**：**μ 算子（minimization）** 接受一个函数 $g$，返回"使 $g$ 第一次取 0 的最小输入"：

$$\mu y\, \big[ g(\vec{x}, y) = 0 \big] = \text{最小的 } y \text{，使得 } g(\vec{x}, y) = 0$$

从编程的角度，μ 算子就是**一个 while 循环**：从 $y = 0$ 开始，逐个检查 $g(\vec{x}, y)$ 是否为 0，不是就 $y{+}{+}$，直到命中。它对 $g$ 的调用次数没有上界——因此**如果永远等不到 0，计算就永不停止**。<span class="marginnote">这就是"部分"二字的来源：$\mu$ 只在存在满足条件的 $y$ 时有定义，否则无定义。数据结构里的线性查找、求解 $x^2 - 5 = 0$ 的最小整数解，都是 μ 算子的日常化身。</span>

**核心概念**：**部分递归函数（partial recursive functions）** = 从基础函数出发，用合成、原始递归与 μ 算子生成的（部分）函数。若某部分递归函数对全部输入都有定义，则称它是**全递归函数（total recursive function）**。

**Church–Turing 论题的函数版**断言：*部分递归函数类 = Turing 可计算的部分函数类\*。1936 年前后，丘奇与图灵分别证明了这一等价，随后 λ 演算、递归函数与 Turing 机三方会师——这正是上一篇所说的"殊途同归"。
