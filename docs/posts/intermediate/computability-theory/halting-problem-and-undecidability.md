# 停机问题与不可判定问题

<div class="epigraph">
<p>不存在这样的机器，它能判定任意给定的机器是否在任意给定的输入上停机。</p>
<footer>—— 艾伦 · 图灵（Alan Turing，*On Computable Numbers\*, 1936）</footer>
</div>

<div class="article-byline">

## 为什么从停机问题开始

前面三篇建立了"可计算"的正统定义，现在到了检验它的时候：**是否存在一个算法，看一眼程序，就能预知它会不会永远跑下去？** 直觉上，"程序会不会停机"像是一个可以检查的性质——调试器、静态分析、测试框架不都在做类似的事吗？1936 年图灵证明：**不存在这样的算法**。这就是**停机问题（halting problem）**，人类发现的第一个、也是最著名的不可判定问题。<span class="marginnote">停机问题不是"很难"而是"原则上不可能"：不是目前科技算不出来，而是数学上已经证明没有任何程序能完成它。这是"计算"这个词的边界，也是从可计算性通往不完备性的门户。</span>理解它的证明，你就理解了递归论最核心的思想工具——对角化，也为下一篇《多一归约与 Turing 归约》备好了"如何比较不可判定程度"的动机。

## 1 问题的精确表述

停机问题可以精确写成：是否存在一个判定程序 $H$，输入是"程序编码 + 输入"，输出是"是否停机"？

$$H(e, n) = \begin{cases} 1 & \text{若 } \varphi_e(n)\!\downarrow \text{（第 } e \text{ 个程序在输入 } n \text{ 上停机）} \\ 0 & \text{若 } \varphi_e(n)\!\uparrow \text{（永不停止）} \end{cases}$$

这里 $\varphi_e(n)\!\uparrow$ 表示"$\varphi_e$ 在 $n$ 处不停机"。$H$ 必须对**每一对** $(e, n)$ 都给出答案，而且必须在有穷时间内停机给出 0 或 1。

**辨析｜易错点：** 常见的误解是"停机问题对特定程序可判"。确实，对**任意给定的一个**程序（比如"打印 hello 然后停机"），我们常常能手工判断它停不停。但停机问题要求的是**一个统一算法，对无穷多个程序都自动判定**——这才被证明不可能。逐个特判与统一算法，是两层完全不同的事。

## 2 对角化证明：让机器自己咬自己

图灵的证明极短，短到可以用五行概括。假设存在判定停机的程序 $H$，我们用它构造一个"坏程序" $D$：

$$D(n): \text{ 运行 } H(n, n) \text{，若 } H \text{ 说"第 } n \text{ 个程序在输入 } n \text{ 上停机"，则 } D \text{ 故意永不停机；否则 } D \text{ 立即停机。}$$

把 $D$ 自己编成第 $d$ 个程序，然后问：$D$ 在输入 $d$ 上到底停不停？

- 若 $D(d)$ 停机，则 $H(d, d)$ 会如实回答"停机"，于是 $D$ 按定义故意不停机——矛盾。
- 若 $D(d)$ 不停机，则 $H(d, d)$ 会回答"不停机"，于是 $D$ 按定义立即停机——矛盾。

两个方向都矛盾，所以假设不成立：**$H$ 不存在**。<span class="marginnote">这个论证的结构叫"对角化"：$D$ 把 $H$ 用到"程序编号=输入编号"的对角线上（$H(n,n)$），再反转结果。康托尔用同一招证明实数不可数（见第一级《集合的概念》），哥德尔用它构造不可证命题，图灵用它证明停机问题——一条论证贯穿三座丰碑。</span>

## 3 公式解析：对角线集合 $K$ 不可判定

上一篇定义的 $K = \{ e \mid e \in W_e \}$（程序 $e$ 在输入 $e$ 上停机）是不可判定的，这是停机问题的一个等价形式。它的证明只有三行，值得逐行拆开：

$$K = \{ e \mid \varphi_e(e)\!\downarrow \}, \qquad \overline{K} = \{ e \mid \varphi_e(e)\!\uparrow \}$$

- **第一步，假设可判定**：设存在判定 $K$ 的算法，即特征函数 $\chi_K$ 是全可计算的：$\chi_K(e) = 1$ 当 $e \in K$，否则 0。
- **第二步，造一个部分函数**：
$$\psi(n) = \begin{cases} 1 & \text{若 } \chi_K(n) = 0 \\ \text{undefined} & \text{若 } \chi_K(n) = 1 \end{cases}$$
$\psi$ 是一个"读 $K$ 判定结果并反转"的部分函数：$n \notin K$ 时 $\psi(n)$ 停机，$n \in K$ 时永不停机。由于 $\chi_K$ 可计算，$\psi$ 也是部分可计算的，于是 $\psi = \varphi_j$（某编号 $j$）。
- **第三步，让 $j$ 问自己**：问 $j \in K$ 吗？$j \in K$ 当且仅当 $\varphi_j(j)\!\downarrow$ 当且仅当 $\psi(j)\!\downarrow$（因 $\psi = \varphi_j$）当且仅当 $j \notin K$（由 $\psi$ 的定义）。于是 $j \in K \iff j \notin K$——矛盾。
- **第四步，结论**：$\overline{K}$ 不是任何可计算函数的定义域，即 $K$ 不可判定。又因为 $K$ 是 c.e. 的（半判定：跑 $\varphi_e(e)$），于是**$K$ 是 c.e. 但不可判定**，它的补集 $\overline{K}$ 连 c.e. 都不是——正是上一篇"补运算不封闭"的具体实例。

## 4 Rice 定理：不可判定会"传染"

停机问题只是一个点，但 Rice 定理把它推广成一大片：**凡涉及"程序行为"的非平凡性质都不可判定**。

**Rice 定理（Rice's theorem）**：设 $P$ 是部分可计算函数性质的一个**非平凡**集合——存在某些编号 $e$ 使 $\varphi_e$ 具有性质 $P$，也存在编号 $i$ 使 $\varphi_i$ 不具有。那么集合 $\{ e \mid \varphi_e \text{ 具有性质 } P \}$ 不可判定。

换言之，你**无法通过算法判断一个程序是否计算了某个特定函数**：判断"这个程序是不是在算加法"、"这个程序是否对所有输入停机"、"这个程序是否总返回偶数"——全部不可判定。<span class="marginnote">注意前提"非平凡"：若性质对所有程序都成立或都不成立，问题当然可判定（回答恒真或恒假）。Rice 定理只在非平凡时发力。</span>

直觉解释：任何"只看输入输出行为"的性质，其判定都等价于解决停机问题——因为要判断程序行为，就必须预知它会不会陷入某个无穷计算。**你无法用有限时间去检验一个无限行为**，除非放弃某些情况。

**数值算例：把 Rice 定理用在一个具体性质上。** 设性质 $P$："$\varphi_e$ 是常值函数（对所有输入返回同一个数）"。$P$ 非平凡吗？是——程序 `return 7` 具有 $P$，程序 `return n` 不具有。于是 Rice 定理立即宣告：**"程序 $e$ 是否计算常值函数"不可判定**。同理可套用："是否算加法"、"是否对所有输入停机"、"输出是否恒为正"——只要性质非平凡，结论立刻成立。Rice 定理的价值正在于**免去逐题构造归约**：你只需辨认性质是非平凡的，不可判定性就自动到位。

## 5 不可判定问题的版图

停机问题打开了潘多拉盒子，一大批经典问题被相继证明不可判定：

**希尔伯特判定问题（Entscheidungsproblem）**：给定一阶逻辑公式，判断它是否永真——图灵 1936 年正是为证明它不可判定而发明了 Turing 机。<span class="marginnote">这也是本篇题记所引论文标题"An Application to the Entscheidungsproblem"的由来：Turing 机最初是证明判定问题不可判定的工具，后来才成为可计算性的标准定义。</span>
**群的**字问题（word problem）**：给定一个群及其生成元上的两个字，判断它们是否表示同一元素——诺维科夫（Novikov）1955 年证明一般情形不可判定。
**丢番图方程的可解性（希尔伯特第十问题）**：判断整系数多项式方程 $P(x_1, \dots, x_n) = 0$ 是否有整数解——马季亚谢维奇（Matiyasevich）1970 年证明不可判定。<span class="marginnote">这大概是"物理上最违反直觉"的不可判定问题：方程长什么样可以打印出来，却不存在通用算法判断它有没有整数解。它与《高等数学》里"隐函数存在定理"形成鲜明对照——存在性定理在算法层面并不总能被实现。</span>

把这几个问题的"归约谱系"排成一张表，共同骨架一目了然：

| 问题 | 首次证明不可判定 | 关键一步 |
| --- | --- | --- |
| 希尔伯特判定问题 | 图灵 1936 | 把停机问题编码成一阶公式 |
| 群的字问题 | 诺维科夫 1955 | 把停机问题编码成群中的等式 |
| 半群的字问题（Thue 问题） | Post 1947 / Markov 1947 | 把图灵机编码成重写规则 |
| 希尔伯特第十问题 | 马季亚谢维奇 1970 | 用丢番图方程模拟停机 |

它们共享同一个证明模板：**把停机问题归约到该问题**——"若能用算法解决新问题，就能用它解决停机问题，而停机问题不可解决"。这个"归约"技术，正是下一篇《多一归约与 Turing 归约》要正式化的概念。

这些不可判定问题还有一个共同教训：**问题看起来越"贴近算法"，越容易让人误以为可判定**。判定问题问的是"所有公式"，字问题问的是"所有群"，第十问题问的是"所有方程"——一个"所有"把它们推过了可计算性的悬崖。今后读到"对任意 $X$，是否存在算法……"这样的表述，就该警惕它可能不可判定；而验证的手段，几乎总是归约。

## 6 关于停机问题的四个常见误解

停机问题太有名，也招来了最多的误解。逐一澄清：

**误解一："我们其实可以在实践中判断程序是否停机。"** 静态分析、测试、lint 工具确实能抓住很多停机问题，但它们抓的是**特殊情况**——不是通用算法。停机问题说的是"不存在一个算法对**所有**程序都给出正确答案"，而不是"不能对某些程序判断"。实践中工具有效，恰恰是因为它们只覆盖了特定子集。

**误解二："停机问题不可判定，所以调试与测试没有意义。"** 恰恰相反：正因为通用停机判定不存在，软件工程才发展出类型系统、模型检测、模糊测试、覆盖率分析等**启发式**手段——它们不能保证正确，但能大幅提高置信度。可计算性的边界不是劝退，而是解释"为什么工程上要分层设防"。

**误解三："量子计算机能解决停机问题。"** 不能。停机问题的不可判定性是**数学性质**，与物理实现无关：无论量子叠加、DNA 计算还是任意新奇计算模型，只要它能被"算法"刻画，就受 Church–Turing 论题的边界约束。量子计算改变的是**计算资源**（多项式时间的类，见第二级《计算复杂性理论》），不是"可判定 / 不可判定"的划分。

**误解四："不可判定 = 无法知道答案。"** 不。$K$ 的每个元素事实上有确定答案——程序要么停机要么不停机——只是不存在**统一算法**在有穷步内给出这个答案。可判定性是关于"算法"的性质，不是关于"事实"的性质。把两者分开，是读懂一切不可判定性证明的前提。

把四个误解放在一起，共通点一目了然：它们都把"可判定性"误当成关于具体事实或技术的问题。而递归论教给我们的是**算法之眼**——凡是声称"存在统一算法"的命题，先问一句：它能否编码停机问题？若能，这条路就到头了。

## 8 小结

- **停机问题**：问是否存在统一算法判定任意程序在任意输入上是否停机——答案是不存在。
- 证明方法是**对角化**：用判定程序构造一个"反转结果"的坏程序 $D$，让 $D$ 问自己，导出矛盾。
- 对角线集合 $K = \{ e \mid e \in W_e \}$ 是 c.e. 但不可判定的，其补集连 c.e. 都不是。
- **Rice 定理**：任何非平凡的"行为性质"都不可判定，不可判定性会传染到一大片问题。
- 希尔伯特判定问题、群的字问题、丢番图方程可解性都是不可判定的，证明都靠**归约**。
- 不可判定性是关于"算法"的性质，不是关于"事实"的性质：$K$ 的每个元素都有确定答案，只是不存在统一算法在有穷步内给出它。

在下一节，我们将把"归约"这个证明模板正式化为一门技术——**多一归约与 Turing 归约**，用它给不可判定问题排难度、建立完备性，并通往 Turing 度的世界。
