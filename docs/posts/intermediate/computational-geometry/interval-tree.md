# 区域树

<div class="epigraph">

## 从「点找区间」到「区间找点」

范围树家族回答「哪些点落在区间里」；**区域树（interval tree）**回答**反过来**的问题：**给定一个点 $x$，哪些区间把它包含在内？** 这叫**刺穿查询（stabbing query）**——像一枚钉子穿过一叠区间。它解决的是真实世界的高频问题：一条时间线被哪些会议占用、一次坐标被哪些传感器覆盖、一个地理点落在哪些地块边界内、计算机网络里一个时刻被哪些定时任务覆盖。<span class="marginnote">区域树（interval tree）常被译作「区间树」。它与范围树（range tree）的区别必须分清：<strong>范围树管「区间查点」，区域树管「点查区间」</strong>——一个按键找值，一个按值找键。两者结构相近（都是 BST），却服务相反的问题，是初学者最容易混淆的一对。</span>

## 1 问题与朴素解

**刺穿查询**：给定 $n$ 个区间 $[l_i, r_i]$（闭区间，端点可为实数），回答「包含查询点 $x$ 的全部区间」。

朴素解：扫描全部区间，判断 $l_i \leq x \leq r_i$，$O(n)$ 每次查询。目标是亚线性。

另一个角度——**窗口查询（windowing）**：把区间看成平面上的「横条」（$x$ 轴是位置，$y$ 轴区分不同区间），查询「哪些横条包含竖直直线 $x = x_0$」。几何上就是「线与横条相交」的查询。这个视角能直接推广到二维矩形刺穿（「哪些矩形含这个点」），应用更广。

## 2 区域树结构：按中位数分治

区域树是一棵**中位数平衡树**：

- 取全部区间端点的**中位数 $x_\text{mid}$** 作为根键。
- **跨越中位数的区间**（$l_i \leq x_\text{mid} \leq r_i$）：存在根节点的两个列表里——按左端点降序存一份、按右端点升序存一份。
- **完全在中位数左边**的区间递归进左子树；**完全在右边**的进右子树。

每个节点存「跨过本节点键的区间」的端点有序表。空间分析：每个区间恰好存在**一个**节点里（它「跨越」的那个键），所以**总空间 $O(n)$**——这与范围树的 $O(n\log n)$ 不同，是区域树的关键优势。<span class="marginnote">每个区间只属于一个节点，这使区域树空间 $O(n)$、比范围树省一个 $\log$。原因：区间在「跨越」的节点处被「吞掉」，之后的递归两侧都不再包含它。设计者的思路很直接——<strong>把区间存在它「过不去的坎」上，查询时就地判断</strong>。</span>

## 3 查询：到节点、就地报

刺穿查询点 $x$ 的流程：

1. 从根出发，比较 $x$ 与节点键 $x_\text{mid}$。
2. 若 $x \leq x_\text{mid}$：该节点的**跨键区间中，左端点 $\geq x$ 的不能含 $x$**（它们起点在 $x$ 右侧），**左端点 $\leq x$ 的全部含 $x$**——按「左端点降序」列表从大往小扫，直到左端点 $< x$，逐个报告；然后只递归**左子树**（右子树里的区间起点全大于 $x_\text{mid} \geq x$，不可能含 $x$）。
3. 若 $x > x_\text{mid}$：对称地按「右端点升序」列表从小往大扫，报告右端点 $\geq x$ 的区间；只递归**右子树**。

每层只在一个子树下潜，深度 $O(\log n)$；在每层报告的区间数恰为「含 $x$ 的区间数」，故查询 **$O(\log n + k)$**（$k$ 为输出数）。<span class="marginnote">为什么每层扫描能「从中间断开」？关键在于节点里存了两个<strong>有序表</strong>：按左端点降序、按右端点升序。查询 $x$ 落在中位数左侧时，只有「左端点 $\leq x$」的区间可能含 $x$，而按降序表从大往小扫到左端点 $< x$ 就停——被扫过的区间全是答案，剩下的全不是。<strong>一个有序表 + 一次单调扫描 = 整层的答案</strong>，这正是 $O(k)$ 输出的来源。</span>

## 4 公式解析：为什么查询是 O(log n + k)

设查询路径上经过 $O(\log n)$ 个节点，节点 $v$ 处报告 $k_v$ 个区间。要证明：

$$
\sum_v k_v = k, \qquad \text{且每层扫描不会多碰非答案}
$$

拆解四步：

- **第一步，不重不漏**：每个含 $x$ 的区间 $[l,r]$，存在唯一的「跨越」节点 $v^*$（它跨越的那个中位数键）。在 $v^*$ 处，$x$ 与 $x_\text{mid}$ 的关系决定扫描方向，$l \leq x \leq r$ 保证该区间一定被扫到并报告；在其他节点处它不会被报告（它在那些子树之外）。所以**每个答案恰好报告一次**。
- **第二步，$k_v$ 求和**：各节点报告的区间互不相同（每个区间只在一个节点），故 $\sum_v k_v = k$。
- **第三步，非答案不碰**：在节点 $v$ 处，若 $x \leq x_\text{mid}$，右子树整棵跳过（其区间起点全 $> x_\text{mid}$，不含 $x$）；左端点降序表只扫到「左端点 $\geq x$」的段——这段里的每个区间左端点 $\leq$ 当前值且含 $x$（因跨键且左端点 $\leq x$），全是答案，不多碰。
- **第四步，总复杂度**：路径长度 $O(\log n)$，加报告总数 $k$，得 $T(n) = O(\log n + k)$。

**核心公式**：每个节点处的报告由「一个有序端点表 + 从端点单调扫」完成，每层 $O(k_v)$，跨层不重不漏——于是总代价 = 路径 + 输出，输出敏感。

## 5 区域树 vs 范围树

| 维度 | 区域树（interval tree） | 范围树（range tree） |
| --- | --- | --- |
| 查询 | 刺穿：含 $x$ 的区间 | 区间 $[a,b]$ 内的点 |
| 结构 | 中位数键 + 跨键区间双表 | 主树 + 次树 |
| 空间 | $O(n)$ | $O(n\log n)$ |
| 查询 | $O(\log n + k)$ | $O(\log^2 n + k)$（级联后 $O(\log n + k)$） |
| 每区间存储 | 一个节点 | $O(\log n)$ 个节点 |

它们各管一个方向，且都在各自问题上是**最优**的。刺穿查询用区域树，范围查询用范围树——「树的名字不重要，问题的方向才重要」。

## 6 扩展：二维矩形刺穿

区域树最自然的推广是**二维矩形刺穿**：给定 $n$ 个轴对齐矩形，查询「哪些矩形包含点 $(x,y)$」。方法：

- 主树按 $x$ 建区域树，跨键矩形的列表改为「按 $y$ 区间组织的次级结构」——跨键矩形里再按 $y$ 用区域树筛。
- 查询：$x$ 路径上每个节点做一次 $y$ 刺穿，总 $O(\log^2 n + k)$。

这个结构在 GIS（点落在哪些地块）、电子设计自动化（哪个元件覆盖这个点）、数据可视化（哪些标注横穿这个像素）里都是主力。

### 辨析：区域树 vs 范围树的方向

**辨析｜易错点：** 「区域树（interval tree）」与「范围树（range tree）」名字只差一字，问题方向却相反，混淆它们的代价是直接写出「查不出答案」或「报错对象」的代码。

- **范围树**：键是**点**，查询给**区间**，问「哪些点落在区间里」——一维范围树、二维范围树两讲的主角。
- **区域树**：键是**区间**，查询给**点**，问「哪些区间包含这个点」（刺穿）——本讲主角。

| 维度 | 范围树 | 区域树 |
| --- | --- | --- |
| 存储对象 | 点（坐标值） | 区间（一对端点） |
| 查询参数 | 区间 $[a,b]$ | 点 $x$ |
| 返回 | 区间内的点 | 含 $x$ 的区间 |
| 空间 | $O(n\log n)$ | $O(n)$ |

**记忆锚点**：范围树管「**区间查点**」（range → points），区域树管「**点查区间**」（stabbing，像钉子扎进一叠纸）。英文里 range tree 对 range query，interval tree 对 stabbing query，对上了就不容易错。

**一个实际例子**：会议系统里「10:00 到 11:00 有哪些会议在用会议室」——这是范围查询，用范围树；「现在 10:30，我订的会议是否撞了别人」——这是刺穿查询，用区域树。同一个时间轴，两个问题方向相反。

<span class="marginnote"><strong>实现误区</strong>：区域树每个区间只存一个节点（跨键处），查询时「就地扫描有序表」；若误按范围树的「节点挂整棵子树列表」实现，空间会从 $O(n)$ 胀到 $O(n\log n)$，且每个区间被重复报告——两个 bug 一起来了。</span>

**区域树的构建代码要点**：

```
build(nodes):
    若节点无区间: return
    取全部端点中位数 mid
    把跨过 mid 的区间存入本节点双表
    递归 build(左子树，全在 mid 左侧的区间)
    递归 build(右子树，全在 mid 右侧的区间)
```

关键在「分派」：每个区间只进一个分支（要么跨 mid 留下，要么全左，要么全右），绝不重复存储。查询时也只走一侧子树，另一侧整体跳过——空间线性、查询对数，都由这个「一分到底」的分派保证。

## 7 小结

- **区域树**回答刺穿查询「哪些区间含点 $x$」，与范围树的「区间查点」方向相反。
- 结构：**中位数键 + 跨键区间双有序表**（左端点降序 / 右端点升序），每区间恰好存一个节点，**空间 $O(n)$**。
- 查询：每层按 $x$ 与中位数比较，选一侧子树下潜，就地扫描有序表报告，**$O(\log n + k)$**。
- 每个答案恰在一个节点报告，$\sum k_v = k$ 保证输出敏感。
- 区域树与范围树互补，各自最优；**方向记清**：点查区间用区域树。
- 推广到二维矩形刺穿 $O(\log^2 n + k)$，GIS 与 EDA 里广泛应用。

「范围查询与对偶」这一篇至此收束。在下一节，我们进入第四篇「应用与高级主题」：**可见性图与最短路**——把几何世界变成一张图，然后问最短路径怎么走。
