## 从一次判定到全部交点

上一节我们学会判定「两条线段是否相交」。但现实问题是：**平面上有 $n$ 条线段，找出所有交点。** 最朴素的做法是两两检查，$O(n^2)$ 对每对都做一次跨立测试。当 $n$ 有十万条（比如一张城市地图的街道）时，这彻底不可行——即使交点只有几千个，$O(n^2)$ 的天花板依然压着。<span class="marginnote">一个基本问题浮出水面：<strong>能否只检查「可能相交」的线段对？</strong> 答案是把线段的<strong>空间邻近性</strong>利用起来——两条不相邻、隔着十万八千里又互不相交的线段，凭什么要花时间去测？扫描线正是把「谁靠近谁」这件事变得可查询。</span>

**Bentley–Ottmann 算法**（1979）用一把**竖直扫描线**从左向右扫过平面，维护扫描线与线段的交点顺序，只在「顺序发生变化」的时候检查相邻线段——把求交从 $O(n^2)$ 优化到 **$O((n + k)\log n)$**，其中 $k$ 是交点个数。

## 1 扫描线的核心观察

设扫描线当前在 $x = x_0$。它与每条线段至多交于一点；把这些交点按 $y$ 坐标排序，得到扫描线与线段的一个**竖直顺序**。这个顺序有两个关键性质：

- **性质 A（相邻才相交）**：两条线段在扫描线上相邻的瞬间，才可能是「刚相交过」或「即将相交」。若两条线段将来相交，在交点之前的某个时刻，它们必在扫描线上**相邻**。因此只需检查相邻对的相交即可——检查远处的线段对是浪费。
- **性质 B（顺序只在事件点变化）**：线段竖直顺序只有在三类时刻才改变——线段**左端点**进入扫描范围、线段**右端点**离开、两条线段**相交**。这三个时刻就是全部**事件点（event points）**。<span class="marginnote">「只在事件点改变」是扫描线方法的灵魂：平面上的无穷连续，被压缩成有限个离散事件。算法只需在这些事件点之间维护好顺序，中间的任意时刻顺序都不变，无需处理。这个「离散化连续」的思想，在点定位、Voronoi 图、最近点对里反复出现。</span>

## 2 两个数据结构

算法用两个平衡数据结构维持状态：

**状态结构（status structure）**：当前与扫描线相交的线段，按交点 $y$ 坐标排序。C++ 用 `std::set` 或带序遍历的平衡树；它支持 $O(\log n)$ 的插入、删除、找前后邻居。

**事件队列（event queue）**：一个优先队列，存三类事件：

- **左端点事件**：一条线段开始与扫描线相交，插入状态结构，检查它与其上下邻居是否相交。
- **右端点事件**：一条线段结束，从状态结构删除，检查删除后新邻居对是否相交。
- **交点事件**：两条线段在此相交，报告交点；交换它们在状态结构中的位置（跨立），然后检查交换后新的相邻对。

处理事件的顺序按 $x$ 坐标，同 $x$ 时按 $y$（退化处理见下）。

## 3 算法主循环

伪代码骨架：

```
S = 空状态结构（按 y 排序的线段集合）
Q = 所有线段的左、右端点事件

while Q 非空:
    e = Q.pop()                // 取 x 坐标最小的事件
    if e 是左端点(l):
        S.insert(l)
        a, b = S 中 l 的上下邻居
        if a 与 l 相交: Q.push(交点事件)
        if b 与 l 相交: Q.push(交点事件)
    if e 是右端点(r):
        a, b = S 中 r 的上下邻居
        if a 与 b 相交: Q.push(交点事件)   // 删除后新相邻
        S.delete(r)
    if e 是交点(l1, l2):
        报告交点 (l1, l2)
        交换 S 中 l1, l2 的顺序
        检查交换后新的相邻对，可能产生新交点事件
```

**关键不变量**：事件队列永远只装「相邻线段对」可能产生的交点；不相邻的线段对永远不会被检查。每条线段插入、删除各一次，每个交点事件产生常数次新检查，于是总操作数 $O(n + k)$，乘以平衡树的 $O(\log n)$，总复杂度 **$O((n+k)\log n)$**。

## 4 公式解析：为什么只查相邻对

扫描线正确性的命门，在于这个断言：

**若两条线段 $s_1, s_2$ 在交点 $c$ 处相交，则存在一个时刻 $x_0 < c_x$，使得 $s_1, s_2$ 在扫描线上相邻。**

拆开证明的直觉：

- **第一步**：在 $c$ 点，$s_1, s_2$ 的竖直顺序发生交换——之前一个在上、之后另一个在上。
- **第二步**：交换只能发生在某次「相邻对检查」被触发时；也就是说，在 $c$ 之前某个时刻 $x_0$，$s_1, s_2$ 之间**没有其他线段隔开**，否则扫描线顺序不会只涉及它俩的交换。
- **第三步**：因此在 $x_0$ 时刻算法必然已经检查过这对相邻线段，计算出 $c$，把交点事件压进队列。
- **第四步**：事件按 $x$ 顺序处理，$c_x > x_0$，交点事件会在 $c$ 处被处理并报告。

于是**没有任何交点会被漏掉**，同时不相邻的线段对（不可能相交时）根本不被触碰——效率与正确性同时成立。

## 5 退化情况的处理

扫描线算法的实现难点集中在退化：

- **多个线段共端点**：左端点、右端点在同一 $x$ 的事件，需约定处理次序（通常左端点先于右端点，先插入后删除，避免悬空）。
- **三条及以上线段交于一点**：同时到达的交点事件要一起处理——把交于同一点的所有线段在状态结构里整体重排，避免重复报告与顺序混乱。
- **水平线段 / 竖直交点**：水平线段与扫描线重合会产生无限多交点，Bentley–Ottmann 对水平线段的处理需要特殊约定（视作斜率为 0 的一般线段，交点事件按端点与交点区分）。
- **浮点求交**：交点坐标用浮点计算，事件点比较需容差；稳健实现常用 Shewchuk 的自适应谓词配合符号扰动。

一个更稳健的现代替代是 **Bala's 算法**或基于 **BSP / 区间树**的方法，但 Bentley–Ottmann 因其简单与普遍仍是最常被讲授和实现的版本。

## 6 扩展：布尔叠加与地图制图

扫描线求交不是终点，而是工具。把它包装起来，可以得到：

- **线段叠加**：求两个线段集合交叠产生的全部「面」，是 GIS 地图叠加（polygon overlay）的底层。
- **求并 / 求差**：把线段集合当作闭合多边形的边界，扫描线可顺带计算并集、差集的面积。
- **最短路预处理**：可见性图构造时，「哪条边被哪条边挡住」需要线段相交检测，扫描线负责把遮挡关系算出来（见「可见性图与最短路」一讲）。

### 辨析：浮点求交带来的「事件错乱」

**辨析｜易错点：** Bentley–Ottmann 的实现几乎都会撞上同一个病：**浮点求交让两个本该重合的事件点「差开」$10^{-16}$**，导致：

- 同一交点被报告两次；
- 状态结构里线段顺序错乱（跨立判断失败）；
- 死循环（事件反复产生）。

**三个实用对策**：

| 对策 | 做法 | 效果 |
| --- | --- | --- |
| 事件按 $(x, y)$ 字典序 + 容差合并 | 相近事件合并为一点 | 消除重复报告 |
| 交点用精确算术 / 稳健谓词 | 避免符号翻转 | 顺序不再乱 |
| 处理「三线共点」整体重排 | 同一点上的线段统一交换 | 避免部分交换 |

**事件比较的约定**：左端点优先于右端点优先于交点——这个次序约定保证「先插入、后删除」，避免状态结构里出现「悬空」的线段。

**另一个易错点：水平线段**。水平线段与扫描线「重合」，竖直顺序无法定义。标准处理是约定「水平线段不与扫描线相交」（或把水平线段的端点按特殊规则参与事件），否则状态结构无法排序。

<span class="marginnote"><strong>测试建议</strong>：用「随机线段 + 暴力 $O(n^2)$ 求交对拍」是最有效的验证——两个实现交点集合应完全一致。Bentley–Ottmann 的退化 bug 几乎都能被这种对拍在几秒内暴露。</span>

## 7 小结

- 朴素两两求交 $O(n^2)$，**扫描线把复杂度压到 $O((n+k)\log n)$**，$k$ 为交点个数。
- 核心观察：线段只在**相邻**时才可能刚相交或将要相交，因此只查相邻对即可。
- 两个数据结构：**状态结构**（平衡树，维护竖直顺序）与**事件队列**（优先队列，按 $x$ 处理三类事件）。
- 交点事件触发相邻交换，交换后再检查新相邻对，保证不漏、不重。
- 退化处理（共端点、多线共点、水平线段）是工程实现的重头戏。
- 扫描线是布尔叠加、可见性图、Voronoi 图等许多算法的公共骨架。
