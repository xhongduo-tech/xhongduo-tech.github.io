## 地图的底层是几何

**地理信息系统（GIS）**把现实世界抽象成**矢量**（点、线、多边形）与**栅格**（像素）两层数据，而矢量层的一切操作——叠加、缓冲区、邻域查询、地形建模——全是计算几何问题。可以说，**GIS 是计算几何最大的单一生意**：每点一次地图、查一次「附近的加油站」、叠一次土地利用图层，底层都在跑扫描线、范围树或 Delaunay。<span class="marginnote">GIS 与计算几何是互相滋养的一对：GIS 的问题（地图叠加、缓冲区、地形）催生了计算几何的经典算法（扫描线求交、Delaunay、点定位）；计算几何则给 GIS 提供了「快而不近似」的精确工具。两者的接口是「几何引擎」——PostGIS、GEOS、JTS 这些库，就是几何算法的工业封装。</span>

**标注（编辑章程第 5 节）**：本节为纯概念 / 应用主题，无核心推导公式，按章程以「核心要点对比表」替代公式解析——本节的关键对比表包括「叠加算子 INTERSECT / UNION / DIFFERENCE」「拓扑一致性预处理的表」「TIN vs 栅格 DEM」等。

## 1 矢量数据模型

GIS 矢量层由三类基本对象构成：

- **点**：地标、采样点、事故位置。
- **折线**：河流、道路、等高线。
- **多边形**：地块、行政区、湖泊、建筑轮廓。

每个对象带**属性**（属性表），几何 + 属性 = 一个要素（feature）。计算几何关心的是几何部分：**对象之间的空间关系（拓扑）**——相交、包含、相邻、重叠，都要靠几何谓词判定。

**拓扑关系判定**正是前面所有章节的汇合：线段相交（道路交叉）、点在多边形内（地址归属）、多边形相交（地块重叠）——每个都是成熟算法的直接应用。

## 2 多边形叠加：地图代数的核心

**多边形叠加（polygon overlay）**是 GIS 最经典也最贵的操作：给定两层多边形（如「土地利用」与「洪水淹没区」），计算它们交叠产生的**全部新面**——每个新面携带两层的属性。

算法骨架：

1. **求交**：用扫描线求交（线段求交扫描线算法）找出两层所有边的交点，把它们作为新顶点插入。
2. **重连**：在交点处把边断开，得到细分后的边集。
3. **遍历面**：沿边追踪，把平面重新组织成面（DCEL），给每个面贴上「属于哪几个输入多边形」的标签。
4. **输出**：按需求取交、并、差（叠加分析有三种算子：INTERSECT、UNION、DIFFERENCE）。<span class="marginnote">叠加操作的正确性依赖一个底层保证：<strong>交点被精确插入并打断原边</strong>——若两个交点因浮点误差「错开」而不合并，层面遍历就会错乱。这也是为什么 GIS 引擎极度重视几何谓词的稳健性：一个 `robustness` 的失败会让整层叠加「撕裂」。数值稳健性不是锦上添花，而是 GIS 的刚需。</span>

扫描线求交把复杂度从「每对多边形相交」降到 $O((n+k)\log n)$，是叠加在大数据量下可用的关键。

## 3 缓冲区分析：闵可夫斯基和的重逢

**缓冲区（buffer）**：给一个几何对象画一个「距它不超过 $d$ 的所有点」的区域——道路的缓冲区是它的影响范围、污染源的缓冲区是风险区。

缓冲区 = **对象 ⊕ 半径为 $d$ 的圆盘**（闵可夫斯基和，见机器人一讲）。对多边形：

- 向外扩张边 $d$，顶点处用圆弧连接（拐角圆化）；
- 结果可能是带孔的多边形（对象本身挖掉）；
- 实现上先扩张边、再对顶点加圆角、再求并去重。

缓冲区与**偏移曲线（offset curve）**、**骨架线（medial axis）**同族：骨架线（到边界至少两条等距点的轨迹）在 GIS 里用于「河流中心线提取」「道路中心线生成」。**广义 Voronoi 图**正是骨架线的离散版本——一讲里的工具在这里直接落地。

## 4 地形建模：TIN

**TIN（不规则三角网，Triangulated Irregular Network）**：用点集三角剖分表示地表——每个三角形是一块平面，顶点是采样点。

- 构建：通常用 **Delaunay 三角剖分**——它最大化最小角，避免瘦三角形导致的坡度误差。
- 插值：任一点的高程用所在三角形平面插值，或自然邻域插值（Voronoi 一讲）。
- 分析：坡度 = 三角形法向与竖直方向的夹角，坡向 = 法向的方位角，均可从三角形三顶点直接算。

TIN 与栅格 DEM 对比：TIN 在平原区大三角形（省存储）、山区小三角形（保细节），自适应远优于固定栅格。**Delaunay 剖分在 GIS 里最日常的角色，就是建 TIN**。<span class="marginnote">TIN 的「自适应细节」让它成为测绘与地形分析的标准：Delaunay 的空圆性质保证了「没有瘦三角形」，而瘦三角形在坡度量测里意味着「采样点连错了邻居、坡度被夸大」。用地形点集做 Delaunay 再插值，比均匀栅格在同等点数下精度高一个量级——这是「几何质量 → 应用精度」的直观例证。</span>

## 5 空间查询：点定位与范围查询的日常

GIS 的空间查询种类繁多，每种对应一个计算几何结构：

- **点定位**：点落在哪个多边形（地址→行政区），用梯形图 / 空间索引。
- **范围查询**：矩形 / 圆内的要素（「这 5 公里内的加油站」），用 R 树 / 网格。
- **最近邻**：最近的要素，用 R 树或 Voronoi。
- **空间连接**：两层要素按「相交 / 包含」配对，叠加 + 索引联合。

PostGIS 的 `ST_Intersects`、`ST_Buffer`、`ST_Within` 等函数的底层，就是这些算法的工业封装；GeoSpark、MobilityDB 等大数据 GIS 系统继续沿用同一套几何内核。

## 6 空间数据的其他几何需求

- **凸包**：点集的最小外接形状，用于「占地区域」「聚类边界」。
- **线简化**：Douglas–Peucker 算法把折线稀疏化（保留拐点），是地图缩放显示的必备（这是计算几何的兄弟话题——曲线逼近）。
- **Voronoi 应用**：基站覆盖、商圈划分、降雨插值（泰森多边形）。
- **地图投影**：把椭球坐标投影到平面，几何变换的专场。

### 辨析：叠加的拓扑一致性与坐标参考

**辨析｜易错点：** 多边形叠加在 GIS 里出了名的「容易错」，最常见的两类错误：

**一是拓扑不一致**。两层数据各自采集，同一地块边界在两层里坐标「差几厘米」，叠加时产生细碎缝隙（sliver polygon）。处理办法是**先做拓扑清理**：把「距离小于容差的顶点」合并、把「几乎共线」的边界对齐，再叠加。工业界的经验法则：**叠加之前先修拓扑，叠加之后必查 sliver**。

| 预处理 | 作用 |
| --- | --- |
| 顶点合并（snap） | 消除微小的裂缝 |
| 边界对齐 | 让公共边真正重合 |
| 面积阈值过滤 | 剔除 sliver 小面 |

**二是坐标参考（CRS）不一致**。两层的投影坐标系不同（如一个 UTM、一个经纬度），直接叠加几何毫无意义。**必须先重投影到同一坐标系**，再谈叠加——这是 GIS 新手最容易踩的坑。

**为什么 GIS 坚持「精确几何」而不是「近似栅格」**：行政区划、地权边界是法律意义的几何对象，几厘米的误差会变成法律纠纷。所以 PostGIS 底层用精确的扩展精度计算边界交点，宁可慢一点也要确定——这正是「数值稳健性与退化处理」一讲在 GIS 里的极端体现。

<span class="marginnote"><strong>工程建议</strong>：数据量大时，叠加前用「空间索引 + 包围盒粗筛」先排除明显不相交的要素对，只对潜在相交者做精确叠加——又是「宽相位 + 窄相位」的两层结构，与碰撞检测完全同构。</span>

**叠加结果的自查**：叠加后每个输出面应同时满足「面积守恒」（输入各层面积之和 ≈ 输出面面积之和）与「属性完整」（每个输出面带齐各层属性）。这两条能抓出绝大多数叠加实现 bug。

**一句话总结 GIS 与计算几何的关系**：GIS 是计算几何最大的应用场景——叠加、缓冲区、TIN、空间查询，每一个都是前面若干讲的直接落地。学完计算几何再学 GIS，会发现后者只是前者的「业务包装」。

**给读者的下一步**：若对 GIS 方向有兴趣，可以从 PostGIS 的官方教程入手，逐个动手做叠加、缓冲区与空间查询——每个操作都能在这里找到它背后的算法名字。

**本篇用到的基础工具索引**：

- 线段求交扫描线 → 多边形叠加（INTERSECT / UNION / DIFFERENCE）
- 闵可夫斯基和 → 缓冲区、偏移曲线
- Delaunay 剖分 → TIN 地形建模

## 7 小结

- GIS 矢量模型 = 点 / 折线 / 多边形 + 属性；空间关系全靠几何谓词。
- **多边形叠加** = 扫描线求交 + DCEL 面遍历，是 GIS 最贵的经典操作，稳健性刚需。
- **缓冲区** = 闵可夫斯基和（⊕ 圆盘），与骨架线、Voronoi 同族。
- **TIN 地形** = Delaunay 三角剖分 + 三角形平面插值，自适应细节、精度高。
- 空间查询（点定位 / 范围 / 最近邻）由 R 树、梯形图、Voronoi 支撑。
- 凸包、线简化、投影把几何工具铺满 GIS 全流程。

在下一节，也是本专题的收官一讲，我们回到所有算法的地基：**数值稳健性与退化处理**——浮点误差、稳健谓词与符号扰动。
