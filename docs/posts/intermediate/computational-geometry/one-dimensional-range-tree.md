## 范围查询：几何里的数据库问题

前面几讲的查询都是「找一个点」；**范围查询（range query）**问的是「给我一群点」：**给定区间 $[a, b]$，列出所有 $x$ 坐标落在这个区间内的点。** 一维版本是所有高维范围查询的基石，而它的高效解法——**一维范围树**——是计算几何与数据结构第一次深度握手。<span class="marginnote">范围查询贯穿现代系统：数据库的 $[a, b]$、搜索引擎的时间过滤、金融数据的区间聚合、传感器网络的时空检索，全都是它。几何里的范围树、kd 树、区间树，本质是「把坐标空间组织成可剪枝的索引」——这与数据库 B 树、位图索引共享同一哲学：<strong>预处理结构，让查询只碰相关数据</strong>。</span>

## 1 问题与朴素解法

**一维范围查询**：给定有序点集（$x$ 坐标唯一，不失一般性），回答「列出 $x \in [a, b]$ 的全部点」。

朴素解法：线性扫描，$O(n)$ 每次查询。当查询数 $m$ 很大时，$O(mn)$ 不可接受。

更聪明的朴素解法：**排序 + 二分**。把点按 $x$ 排序，二分找到 $a, b$ 的插入位置，中间的一段就是答案——但「取出答案」仍要 $O(k)$（$k$ 为输出点数）。于是查询时间是 $O(\log n + k)$，其中 $O(\log n)$ 是定位、$O(k)$ 是必然的输出代价。<span class="marginnote">$O(\log n + k)$ 里那个 $+k$ 值得注意：输出本身要 $k$ 个点，谁也没法少于 $O(k)$ 把答案「倒」出来。因此「输出敏感（output-sensitive）」是范围查询的黄金标准——效率只随输出增长，而不随无关数据增长。这个 $k$ 项在整个范围树家族里都会如影随形。</span>

**排序数组**其实已经达到最优了。那为什么还需要「范围树」这个名字？因为一维只是热身——二维、三维的范围树要从一维结构「叠」出来，而这个「叠」需要一个支持快速查询的底层结构。一维范围树就是那个可叠加的积木。

## 2 一维范围树的结构

**一维范围树**是一棵**完全平衡二叉搜索树**（如 AVL 或红黑树），叶子按 $x$ 坐标升序排列，每个内部节点存「子树里的最小值/最大值」或干脆叶子存于有序链表。

具体设计（de Berg 风格）：

- 叶子：每个点一个叶子，按 $x$ 升序。
- 内部节点：存一个**中位值**作为切分键（左子树都比它小，右子树都比它大）。
- 每个节点还可以附一棵「以该节点为根的子树叶子列表」（对一维是冗余的，但对二维叠加是必需的——先记住这个伏笔）。

范围查询 $[a, b]$ 的过程：

- **找分岔点**：从根出发，找第一个「$a$ 在左子树、$b$ 在右子树」的节点 $v_\text{split}$。若查询区间完全落在一边，就一直下到叶子。
- **左分支**：从 $v_\text{split}$ 沿左子树下到 $a$ 的插入位置，沿途把**每个右子树**整棵报告（这些子树里的点全部落在 $[a, b]$ 内）。
- **右分支**：对称地沿右子树下到 $b$ 的位置，沿途把**每个左子树**整棵报告。

## 3 查询为什么是 O(log n + k)

报告「整棵子树」是关键动作：若某节点的子树全部落在查询区间内，整棵子树 $O(1)$ 时间批量给出（通过子树叶子列表），而不是逐点判定。这正是「范围树」相对「排序数组线性扫」的优势结构。

查询路径上，从分岔点到 $a$ 的路径长 $O(\log n)$，沿途报告的整棵子树数量 $O(\log n)$ 个，报告的总点数恰好是 $k$。于是：

$$
T(n) = O(\log n) + O(k) = O(\log n + k)
$$

每个被报告的子树都是「剪枝」掉的整体，不浪费任何一次对区间外点的访问。<span class="marginnote">与排序数组「二分定位 + 线性输出」对比：两者查询都是 $O(\log n + k)$，但范围树的报告是「按子树整体倒出」，为二维叠加准备了「按子树递归」的机制。一维看不出差别，二维范围树就是靠这个机制把查询从 $O(n)$ 降到 $O(\log^2 n + k)$ 的。</span>

## 4 公式解析：分岔点与整棵子树报告

范围查询正确性的核心，是把「区间」翻译成「树上的 $O(\log n)$ 个整子树」。拆解分岔策略：

- **第一步，分岔点定义**：$v_\text{split}$ 是「$a$ 的插入位置在左子树、$b$ 的插入位置在右子树」的最深节点。若整段 $[a,b]$ 落在某子树内，则从根沿单路径下潜即可，无需分岔。
- **第二步，左分支报告右子树**：从 $v_\text{split}$ 往左下走到 $a$，每经过一个节点，该节点**右子树**里所有点的 $x$ 值都 $\geq a$（因在 $a$ 的右侧）且 $\leq b$（因在 $v_\text{split}$ 左侧），整棵落入区间——整体报告。
- **第三步，右分支报告左子树**：对称地，往右下走到 $b$，沿途每个节点的**左子树**整棵落入区间——整体报告。
- **第四步，路径上节点的报告量**：左路径与右路径各长 $O(\log n)$，沿途整体报告的子树数 $O(\log n)$，报告的点总数恰为 $k$（每个在区间内的点恰好被一棵子树报告一次，不重不漏）。

关键公式是报告复杂度：

$$
T_{\text{query}}(n) = O(\log n) + k
$$

「$O(\log n)$ 个整子树 + $k$ 个输出点」——这个形态在后面二维范围树里会升级成「$O(\log n)$ 个节点、每个节点再递归一维查询」，从而得到 $O(\log^2 n + k)$。

## 5 一维范围树的可叠加性

一维范围树真正的价值，在于它是二维范围树的**构件**：

- **二维范围树**：主树按 $x$ 建一维范围树，每个节点再挂一棵「该子树内所有点的 $y$ 一维范围树」。查询 $[x_1,x_2] \times [y_1,y_2]$ 时，先用 $x$ 找到 $O(\log n)$ 个整子树，再对每个子树用 $y$ 范围树过滤——$O(\log^2 n + k)$。
- **分数级联（fractional cascading）**：还能把这 $O(\log n)$ 次 $y$ 二分「级联」成一次二分 + $O(\log n)$ 次推进，把 $\log^2 n$ 压到 $\log n$——这是第三级《算法》里也值得单独学习的技巧。

**一维范围树必须支持「给定一个键，快速二分定位」**，所以底层要平衡 BST；而它「节点挂有序列表」的设计，正是为了二维叠加时无需重构。

## 6 实现要点

- **平衡保证**：AVL / 红黑树或权值线段树都可；平衡是关键，否则退化成链表。
- **重复键**：$x$ 坐标重复时需要按 $y$ 做次级排序（或去重），避免查询区间边界歧义。
- **输出顺序**：范围树输出天然按「子树整体」顺序，不保证按 $x$ 全局有序；需要有序输出时用叶子链表连接。
- **空间**：一维范围树 $O(n)$ 空间（每个点一个叶子、一棵 BST）。

### 辨析：范围树 vs 排序数组

**辨析｜易错点：** 一维范围树与「排序数组 + 二分」的查询都是 $O(\log n + k)$，那为什么还要树？因为范围树是为**多维叠加**设计的积木，排序数组不具备这个性质。

| 维度 | 排序数组 | 一维范围树 |
| --- | --- | --- |
| 一维查询 | $O(\log n + k)$ | $O(\log n + k)$ |
| 报告方式 | 线性扫描一段 | 整棵子树批量 |
| 可叠加为二维 | 否（无法挂 y 结构） | 是（节点挂次树） |
| 插入 / 删除 | $O(n)$ | $O(\log n)$ |

**重复键的处理**：$x$ 坐标重复时，范围查询的「二分定位」会产生歧义（$a$ 落在多个相同键之间）。工程处理是先按 $(x, y)$ 字典序排序，让重复键有确定次序，或直接对重复点去重。

**报告顺序的坑**：范围树按「整棵子树」批量输出，得到的点**不保证按 $x$ 全局有序**。若调用方需要有序输出，要么用叶子链表串起来，要么事后排序——不要假设范围树自带序。

<span class="marginnote"><strong>一句话</strong>：一维范围树不是「比排序数组快」，而是「能为二维变快」。它的价值在下一讲二维范围树才完全兑现——先把它当成一块可靠的一维积木。</span>

**插入 / 删除的支持**：用平衡 BST 作为底层，插入删除 $O(\log n)$；若用静态数组实现（权值线段树风格），则不支持在线修改但更省常数。选择取决于「静态批量查询」还是「动态在线查询」。

## 7 小结

- 一维范围查询回答「哪些点的 $x \in [a,b]$」，朴素 $O(n)$，范围树 **$O(\log n + k)$**。
- 结构：**完全平衡 BST + 叶子按 $x$ 升序 + 子树有序列表**。
- 查询三步：**找分岔点 → 左分支报告右子树 → 右分支报告左子树**。
- 报告整棵子树是效率关键：$O(\log n)$ 个整子树 + $k$ 个输出点，不碰区间外数据。
- 输出敏感 $+k$ 是范围查询的黄金标准，会一直伴随后续结构。
- **可叠加性**：节点挂有序列表的设计为二维范围树铺路，配合分数级联可达 $O(\log n + k)$。

在下一节，我们把它从「一棵树」推广到「一个空间划分」：**kd 树**——用递归二分把平面切成矩形，范围查询与最近邻通吃。
