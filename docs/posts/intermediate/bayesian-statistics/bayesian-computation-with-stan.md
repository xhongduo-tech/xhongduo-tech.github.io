## 为什么从「计算引擎」开始

前几节我们把贝叶斯推断讲完了思想，却把「怎么算」留在了半路：Metropolis 随机游走效率不高，Gibbs 要手动推导条件分布，高维后验常常连诊断都过不了。现代贝叶斯实践需要一个**通用的、自动的、高效的**计算引擎。业界标准答案是 **Stan**——一个声明式建模语言 + 基于**哈密顿蒙特卡洛（HMC）与 NUTS** 的采样引擎。

这节回答三个问题：为什么现代引擎用 HMC 而不是随机游走？Stan 的模型怎么写、算完怎么诊断？以及「贝叶斯计算」这一层在整个贝叶斯工作流里的位置。<span class="marginnote">Stan 名字取自统计学家斯坦尼斯拉夫·乌拉姆（Stanislaw Ulam）。它由 Gelman、Bob Carpenter 等人发起，2012 年前后成型，配套诊断指标（R-hat、ESS）也成为社区事实标准。同类工具还有 PyMC（Python 原生）、JAGS、Bugs——Stan 以 HMC 的高效与诊断工具的完备著称。</span>

## 1 随机游走太慢：MCMC 的效率危机

Metropolis 随机游走每步只「试探一小步」，在**高维**后验里效率灾难性恶化：相邻样本高度相关、ESS 极小、要跑到天荒地老才能覆盖后验。原因直观——高维空间中大多数方向都是「错误的」，随机乱撞很难沿等高线有效移动。

**哈密顿蒙特卡洛（Hamiltonian Monte Carlo, HMC）**换了一种哲学：**别乱走，用梯度。** 把后验对数密度 $U(\theta) = -\log p(\theta\mid y)$ 想象成一座山的地势，把参数 $\theta$ 想象成在山上滑行的「位置」，再引入一组虚构的「动量」$m$。系统遵循哈密顿力学（先沿梯度「推一下」，再让物理规律自己滑动），沿等高线大步长滑行后采样。

**HMC 的优势**：相邻样本几乎独立（大步滑动）、接受率高（物理上几乎必然可行）、在高维空间里明显更高效。<span class="marginnote">HMC 的思想出自统计物理（Duane 等人 1987 年的混合蒙特卡洛），由 Neal 引入统计采样。它需要能算<strong>对数后验的梯度</strong>——因此模型必须可微。这解释了为什么 Stan 只支持连续参数、并要求模型可微；离散参数（如混模型指示变量）要积分掉或边际化。</span>

## 2 NUTS：自动选步长的 HMC

HMC 有一个恼人的超参数：模拟步长 $\varepsilon$ 与步数 $L$。步长太大物理方程失稳、步数太多浪费算力。**NUTS（No-U-Turn Sampler）**自动解决：它每次动态地加长「滑动轨迹」，直到轨迹开始「掉头」（U-turn）为止——用一个递归树（双倍化）自动决定跑多远，再沿轨迹做切片采样（slice sampling）挑一个点。

**NUTS 的工程意义**：把「调 HMC 超参数」变成自动过程，让贝叶斯建模者把精力放在模型而非调参上。Stan 的默认后端正是 NUTS。<span class="marginnote">NUTS 由 Hoffman 与 Gelman 2014 年提出，是 Stan 高效性的核心技术。它也有自适应：预热阶段自动调整步长 $\varepsilon$，目标是让接受率落在理想区间。理解这一点，就能读懂 Stan 输出里的 `stepsize__` 与 `treedepth__` 字段——前者异常小说明后验极不光滑，后者频繁超限说明模型参数化欠佳。</span>

## 3 用 Stan 写模型：声明式建模

Stan 代码分块声明，最核心的是 `data`、`parameters`、`model`。以 8 所学校分层模型为例：

```stan
data {
  int<lower=0> J;            // 组数
  vector[J] y;               // 各组观测效应
  vector<lower=0>[J] sigma;  // 各组已知标准误
}
parameters {
  real mu;                    // 总体均值
  real<lower=0> tau;          // 组间标准差
  vector[J] theta;            // 各组参数
}
model {
  theta ~ normal(mu, tau);    // 参数层：组间共享先验
  y ~ normal(theta, sigma);   // 数据层：似然
}
```

还可以加上 `generated quantities` 块——它不属于采样，而是在每个后验样本上计算「导出量」，是《模型检验与后验预测检验》一节的标准入口：

```stan
generated quantities {
  vector[J] y_rep;      // 后验预测：模型眼里「应该看到」的数据
  for (j in 1:J)
    y_rep[j] = normal_rng(theta[j], sigma[j]);
}
```

`y_rep` 的每一行都是一次「按模型模拟的新数据」——把它与真实 `y` 对比，就能量化模型在哪些特征上失真。这段代码同时展示了 Stan 的设计哲学：**采样与计算分离**——`model` 块定义目标分布，`generated quantities` 块事后按样本算量，不改动后验本身。

另一个实践细节：Stan 对 `y ~ normal(...)` 这类语句会在预处理阶段自动展开为对数密度，并在采样时自动求梯度（自动微分）。**建模者永远不需要手写梯度**——这是它与早期 MCMC 工具（如 WinBUGS 需要手动写条件分布）的本质区别，也是「声明式建模」能落地的技术前提。

注意三点。**第一**，Stan 的 `~` 只是把对应项**累加进对数后验**，`y ~ normal(...)` 等价于 `target += normal_lpdf(y, ...)`——我们在《贝叶斯推断基础》里讲的「后验 ∝ 先验 × 似然，相乘在 log 空间就是相加」在这里落地。**第二**，分层结构直接翻译成两层 `~`。**第三**，声明式的好处：**引擎自动推导目标分布、自动算梯度、自动采样**——建模者只写模型，不写采样器。<span class="marginnote">Stan 里没有显式「先验行」也行——不写先验意味着均匀（improper）先验。真实工程中建议给每个参数显式写先验（弱信息先验），这既是防呆，也是《先验分布与共轭先验》里「透明建模」要求的代码化。</span>

## 4 公式解析：HMC 的目标函数

HMC 全程只用一个量：**对数后验（的核）及其梯度**。写清楚：

$$
\theta \sim p(\theta \mid y), \qquad
U(\theta) = -\log p(\theta \mid y), \qquad
H(\theta, m) = U(\theta) + \frac{1}{2} m^\top M^{-1} m
$$

- **第一步，势能 $U$**：取对数后验的负值。密度高的地方 $U$ 低（山谷），密度低的地方 $U$ 高（山顶）。把「密度」翻译成「地势」，随机游走的抽象目标就变成了可以求梯度的物理曲面。
- **第二步，动能**：$\tfrac12 m^\top M^{-1} m$，$M$ 是质量矩阵（通常取后验协方差的近似）。动量 $m$ 是虚构变量，与 $\theta$ 相互独立——联合分布 $p(\theta, m) \propto e^{-H(\theta,m)}$ 关于 $m$ 边际化后正好回到 $p(\theta\mid y)$。
- **第三步，哈密顿方程**：$\frac{d\theta}{dt} = \frac{\partial H}{\partial m} = M^{-1}m$，$\frac{dm}{dt} = -\frac{\partial H}{\partial \theta} = \nabla_\theta \log p(\theta \mid y)$——动量沿**对数后验梯度**驱动位置滑动。
- **第四步，积分与接受**：用蛙跳（leapfrog）数值积分滑行 $L$ 步，末尾按 $\min(1, e^{-H_{\text{new}}+H_{\text{old}}})$ 接受。物理守恒让接受率极高、轨迹长而有效——**用可微性换采样效率**，这就是 HMC 的全貌。<span class="marginnote">拉普拉斯用「对数后验」做近似，HMC 用「对数后验的梯度」做采样——两代人都在「对数后验」上做文章。可微建模（differentiable programming）的思想后来溢出到深度学习：贝叶斯计算与自动微分、反向传播本是同一套梯度引擎的两种用途。</span>

## 5 算完必查：Stan 的五个诊断字段

Stan 输出的诊断是「计算结果是否可信」的照妖镜，五个字段务必看：

**`R-hat`（$\hat{R}$）**：多链收敛诊断，< 1.01 视为收敛（Stan 新默认 1.01，旧版 1.1）。超限则加长采样或改参数化。
- **`n_eff`（ESS）**：有效样本量；与总样本比过低（如 < 总样本 × 0.1）说明自相关严重，需换参数化（如中心化 ↔ 非中心化）。
- **`mcse`**：蒙特卡洛标准误——点估计的采样误差，报告结果时顺带报告。
- **`treedepth__`**：超过默认阈值说明 NUTS 轨迹被截断，通常是参数化欠佳或模型太复杂。<span class="marginnote">参数化的「中心化 vs 非中心化」是 Stan 用户第一课：$\theta_j \sim N(\mu,\tau)$ 是中心化，改写为 $\theta_j = \mu + \tau z_j,\ z_j\sim N(0,1)$ 是非中心化。分层模型在数据弱时中心化版会「漏斗」状收缩、采样极慢；非中心化版把相关性打散，常显著改善 ESS。这类「重参数化」是贝叶斯计算的必修手艺。</span>
- **`divergent transitions`（发散转变）**：发现发散说明数值问题——最可能是厚尾、尺度差异大或参数化不佳。发散不是小噪音，是「结果不可信」的红灯。

**重点：诊断不通过，结果不作数。** 贝叶斯计算与传统「跑通即出结果」不同，诊断（尤其是发散转变与 R-hat）是计算结论合法性的组成部分。这也是为什么贝叶斯工作流里「先看诊断、再看数字」是铁律。

把五个诊断字段收进一张速查表，做诊断时一眼对照：

| 字段 | 含义 | 通过线 | 常见病灶 |
| --- | --- | --- | --- |
| `R-hat` | 多链混合度 | < 1.01 | 链未收敛、初始点太分散 |
| `n_eff`（ESS） | 有效样本量 | 越接近总样本越好 | 自相关高、参数化欠佳 |
| `mcse` | 点估计采样误差 | 相对点估计足够小 | 样本量不足 |
| `treedepth__` | NUTS 轨迹深度 | 不超过默认上限 | 模型太复杂、参数化不佳 |
| `divergent` | 发散转变数 | 0 | 厚尾、尺度差异大、参数化差 |

**一次真实诊断的阅读示范**：假设你跑完 8 学校分层模型（见《分层模型》），控制台给出 `R-hat = 1.06`、`n_eff = 210`、`treedepth__ 最大值 15`、`divergent = 3`。逐条读：

- `R-hat = 1.06` 高于 1.01——链还没完全收敛，**结论暂不作数**；
- `n_eff = 210` 相对 4000 次迭代偏低——自相关严重，多半是**中心化参数化**在漏斗处打转；
- `treedepth__` 超限 + 发散 3 次——进一步坐实「参数化欠佳」。

对策就是换**非中心化参数化**（$\theta_j = \mu + \tau z_j$），重跑后 `R-hat ≈ 1.00`、`n_eff > 2000`、发散清零。**同一个模型、同一批数据，只换参数化就能从「不可信」变成「可信」**——这就是「诊断驱动建模」最直观的一课。<span class="marginnote">这条经验对读者自己动手时同样适用：先别急着加样本量、改模型，先试<strong>重参数化</strong>。它不改变后验本身（只是把后验写成对计算更友好的坐标），却能成倍提升 ESS、消除发散——是性价比最高的一味「药」。</span>

## 6 小结

- 随机游走 MCMC 在高维低效，**HMC 用「对数后验的梯度」驱动大步滑动**，用可微性换效率；**NUTS** 自动选步长，是 Stan 的默认引擎。
- Stan 是**声明式建模语言**：写 `data`/`parameters`/`model` 三个块即可，`~` 是往对数后验里累加；引擎自动推梯度、自动采样。
- **公式解析**：势能 $U=-\log p$ + 动能，哈密顿方程让动量沿梯度驱动位置——物理守恒换高接受率与低自相关。
- 模型结构（如分层）直接翻译为多行 `~`；不写先验即均匀先验，建议显式弱信息先验。
- **诊断五件套**：R-hat、ESS、mcse、treedepth、发散转变——**诊断不过，结果不作数**。

在下一节，我们把模型复杂度往上再推一层：多参数、多变量正态、还有棘手的缺失数据——这就是 **多参数模型：多变量正态与缺失数据**。
