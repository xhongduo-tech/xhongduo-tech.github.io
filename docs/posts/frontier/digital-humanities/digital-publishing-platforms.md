## 为什么数字人文要谈出版与平台

一篇数字人文论文做完分析、画好图，还差最后一环——**发表**。但数字人文的成果形态天然「装不进 PDF」：一个交互地图、一个可查询语料库、一份带标注的数字校勘本，它们如何被评审、引用、长期保存？这正是**数字出版（digital publishing）**与**平台（platforms）**要解决的问题，也把数字人文从「研究方法」推进到「学术基础设施」层面。本节讲清数字出版改变了什么、有哪些出版形态与平台、评审与引用的新规则，以及平台繁荣背后的保存危机——一个发布于 2008 年的数字项目，到 2028 年还打不开的，并不少见。

## 1 出版范式的迁移：从纸本到「超越 PDF」

传统学术出版的核心单元是「论文」——一份线性的、定稿的、印在纸或 PDF 上的文本。数字出版把「发表」从一个名词变成一个过程：

| 维度 | 传统出版 | 数字出版 |
| --- | --- | --- |
| 成果单元 | 论文/专著 | 论文 + 数据集 + 代码 + 交互应用 |
| 评审 | 双盲、发表前 | 发表前评审 + 发表后开放评议 |
| 版本 | 定稿即终版 | 持续修订、版本可追溯 |
| 读者 | 读者 | 读者 + 共同研究者（可复算） |
| 载体 | 期刊/出版社 | 期刊 + 仓储 + 平台 + 个人站点 |

「**超越 PDF（Beyond the PDF）**」运动主张：一篇数字人文论文的「正文」只是入口，真正的成果是链接背后的数据、代码与交互——评审要评的是**整个研究系统**，而不仅是文字。这让「可复现性」从科学界口号变成人文学科的现实要求：读者点击图上的点，应能回到原始数据与算法。

## 2 数字人文的出版形态与平台

数字人文成果没有单一出版渠道，常见形态各配平台：

- **数字校勘版（digital scholarly edition）**：TEI 编码的带版本异文、注释、影像对照的「超文本」定本。平台如 TEI Publisher、eXist-db；这是古籍数字化的最终形态，也是数字人文最「学术」的出版。
- **交互式研究发布**：Scalar、Omeka 等平台把文本、图、数据组装成叙事化网页——**Omeka** 偏展览与藏品管理，**Scalar** 偏长文叙事与媒体混合。
- **分析工具即出版**：Voyant Tools、Gephi、Neatline 这类工具自带 Web 界面，研究者在工具里发布可复现的分析流程。
- **开放仓储与代码**：Zenodo、Figshare（存数据）、GitHub（存代码与版本）——给项目发 **DOI**，让它可被引用、可被归档。<span class="marginnote">DOI 是数字出版的生命线：一个没有 DOI 的数据集等于「无法引用、无法追责、无法保全」。给数据发身份证，与《数字档案与数据库》里 FAIR 原则的全局唯一标识符是同一件事。</span>

选平台的标准不是「功能多」，而是**可持续与可迁移**：平台能否导出开放格式、能否脱离原平台存活、被并购或停服后数据是否可搬走。**平台是租来的，数据才是自己的。**

## 3 评审、引用与复现的新规则

数字出版打乱了既有的学术信用体系，催生三套新规则：

1. **评审新形态**：数字成果评审从「看论文」变为「看系统」——评数据质量（抽样框？κ 值？）、评代码可运行性（能在新环境复现吗？）、评交互可用性。开放评审（如 PubPeer、期刊的发表后评议）让评审从一次性裁决变成持续对话。
2. **引用新单位**：除了引论文，还要引**数据集**与**方法**——给出数据集的 DOI、软件的版本号（连 commit hash 都要），结论才可复现。引用规范从「作者—标题—期刊」扩展为「作者—数据—版本—哈希」。
3. **复现即审查**：同行评议时可以「跑一遍」作者的代码与数据——**能复现的结论才是结论**。这迫使数字人文项目把「可复现性」写进开发纪律，也把「文档化管线」从加分项变成必需项。

这三条合起来的趋势是：**数字人文的学术信誉，从「发表的文本」转向「可审计的系统」**——你的项目能被别人重建，才算是真正发表过。

## 4 平台的政治与保存危机

数字出版繁荣的另一面是**平台危机**：学术平台的寿命往往短于学术结论的寿命。

**链接腐败（link rot）**：论文里引用的 URL 五六年内大量失效；项目下线、域名易主、平台改版，都让引用链断裂。
**技术过时**：Flash 交互、旧版 Web 框架停用，项目变成「数字废墟」——代码还在，运行环境没了。
**商业风险**：依赖商业 SaaS 平台的学术项目，随平台涨价、收购、停服而命运飘摇。

应对之道是一条完整的保全链：**项目立项就定「退出策略」**（数据开放导出）、**用开放格式与标准（TEI/CSV/JSON）**、**存入可信仓储（Zenodo/机构库）**、**定期做格式迁移**。最好的数字人文项目，会像档案馆一样给自己的出版物做「备份与迁移计划」。这正呼应《数字档案与数据库》的 OAIS 承诺——**学术成果也配得上档案级的保存**。

## 5 平台时代的学术共同体

平台不止是技术容器，还重塑了学术共同体的运作：

**预印本与先发**：社科与人文学科逐步接受预印本（preprint），成果抢先流通，评审意见公开透明。
**众包与协作**：Wikisource、各古籍众校平台把校对变成开放协作，参与者横跨学者与爱好者——「业余者」进入学术生产过程。
**学术博客与数据集市**：个人站点、学术社交平台成为「半成品讨论场」，正式的期刊论文反而滞后。**研究的「过程」第一次被公开化**，这既是民主化，也带来「谁有资格发言」的新争议。

<span class="marginnote">平台让数字人文的「产出」从论文扩展到整个研究过程——这是好事也是考验：开放让学科更透明，但<strong>没有把关的开放会稀释学术标准</strong>。如何既开放又可靠，是平台时代尚未解完的题。</span>对学习者而言，理解平台生态等于理解了数字人文成果的「生存环境」：发表不再是一次交付，而是一次**进入公共知识基础设施的长期居留**。

## 6 平台选型对照表

数字人文项目发布平台的选择，直接决定成果的寿命与可访问性。把主流选项放一起对照：

| 平台 | 擅长 | 短板 | 适用场景 |
| --- | --- | --- | --- |
| Omeka | 藏品/档案的策展式发布 | 不适合长文叙事 | 展览、专题库 |
| Scalar | 多媒体长文叙事 | 数据结构化弱 | 研究叙事作品 |
| TEI Publisher | 数字校勘版 | 上手门槛高 | 古籍定本 |
| Voyant / 分析工具 | 在线复现分析 | 不是「出版」形态 | 方法附录 |
| Zenodo / GitHub | 数据与代码存档 | 不是阅读界面 | 配套资产 |

### 一个项目发布的 checklist

发布前逐项核对：

- [ ] 数据有 DOI、可下载、有许可证
- [ ] 代码有版本号、依赖清单、可复现说明
- [ ] 界面无死链、导出格式开放
- [ ] 保存计划与退出策略已写清
- [ ] 批评与反馈渠道公开

**发布不是终点，而是「可复核性的起点」**——数字人文成果被引用的次数，往往取决于它的可复现打包做得多好，而不只是结论多新颖。这份 checklist 背后的逻辑是《数字人文批评与伦理》劳动与责任清单的落地：每一项都在回答「谁能复核我、谁能复用我、谁该署名、数据归谁」。

一个实用的验收技巧：把自己当成十年后的陌生人，只看你留下的文档——能不能重建这个项目？不能的话，说明文档还差得远。

### 开放获取的两种姿势

开放获取（Open Access）有两条路线，数字人文二者都用：

- **金色 OA**：直接在开放期刊发表，全文即刻公开——费用常由资助方或机构承担。
- **绿色 OA**：在传统期刊发表，同时把预印本/数据存入开放仓储——零额外成本，但版本需合规。

**对数字人文而言，开放的不只是论文，更是数据与方法**——这正是「超越 PDF」的题中之义：全文开放让读者读到，数据开放让读者复算，方法开放让读者质疑。

### 平台时代的学术身份

数字出版还改变了一个更根本的东西——**学术身份的认定**。当「发表」从论文扩展到数据、代码与交互项目，评价体系如何给这些新型成果记功？许多机构已把「数据集」「数字校勘版」列入成果认定，但这套标准仍在演化：**数字人文从业者需要主动参与制定「什么算数」的规则，而不是被动等待它定型**。

## 7 小结

- 数字出版把成果单元从「论文」扩展为「**论文 + 数据 + 代码 + 交互**」；「超越 PDF」要求评审整个研究系统。
- 出版形态多样：数字校勘版、交互发布（Omeka/Scalar）、工具即出版、开放仓储；**DOI 是数据生命线**。
- 评审/引用/复现新规则：评数据质量与代码可运行、引数据集与版本哈希、复现即审查。
- 平台危机：**链接腐败、技术过时、商业风险**；对策是开放格式 + 可信仓储 + 退出策略 + 迁移计划。
- 平台重塑共同体：预印本、众包校对、学术博客让「研究过程」公开化，开放与把关的平衡仍是未解题。
