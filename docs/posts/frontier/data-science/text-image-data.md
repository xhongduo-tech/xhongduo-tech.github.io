## 为什么从文本与图像开始

前面的分析对象都是**结构化数据**：有列名、有类型、一行一条记录。但现实中海量信息藏在**非结构化数据**里——客服对话、商品评论、新闻报道、产品图片、监控画面。文本与图像是其中最主流的两种。<span class="marginnote">文本与图像数据在本专题的定位是「衔接层」：数据科学用它们做业务分析（情感分析、图像质检），而完整的 NLP 与 CV 方法论在第四级《自然语言处理》与《计算机视觉》专题。本文给数据科学家一份「够用的武器」：把非结构化数据转成能进模型的特征，理解核心方法与易错点。</span>数据科学的完整能力，必须包括处理这两类数据。

## 1 文本数据：从字符到向量

文本不能直接进模型，第一步是把它变成数值。三条主线构成了文本向量化的谱系。

**词袋与 TF-IDF（经典）**。**词袋模型（bag of words）** 把文本看成词的集合，忽略顺序，统计词频。**TF-IDF** 在词频上加权，突出「对这篇文本重要、但对整个语料少见」的词：

$$
\text{TF-IDF}(t, d) = \text{TF}(t, d) \times \log\frac{N}{\text{DF}(t)}
$$

- **TF$(t,d)$（词频）**：词 $t$ 在文档 $d$ 里出现的次数。词出现越多越重要。
- **$\log\frac{N}{\text{DF}(t)}$（逆文档频率）**：$\text{DF}(t)$ 是包含词 $t$ 的文档数，$N$ 是总文档数。「的」「了」出现在几乎所有文档里，DF 大、IDF 小、权重被压低；「量子」「甲状腺」只在少数文档出现，IDF 大、权重被抬高。<span class="marginnote">TF-IDF 的思想可以概括为「<strong>越少见越特异</strong>」：在某一篇文档里频繁出现、但在整个语料里很少见的词，最可能是这篇文章的「主题词」。它是文本检索（第五级《信息检索》）与文本分析的基础特征，至今仍是很多文本任务的第一基线。注意它完全不理解语义：「苹果」指水果还是公司，TF-IDF 分不出来。</span>
- **乘积**：两者相乘，得到词对文档的重要性权重。

**嵌入（现代）**。词袋与 TF-IDF 都**忽略词序与语义**。**词嵌入（word embedding）** 用向量表示词义：意思相近的词（「汽车」「轿车」）在向量空间里彼此靠近。Word2Vec、GloVe 是经典实现，大语言模型的表示（第四级《大模型原理》）是它的当代形态。

**重点：文本分析的任务决定特征选哪档。** 情感分析、主题分类用 TF-IDF + 线性模型就能达到相当好的效果；需要理解语义（问答、摘要、翻译）则必须用嵌入与语言模型。**先试经典特征，再上大模型**，是数据科学处理文本的性价比纪律。

## 2 图像数据：从像素到张量

图像在计算机里是一个**像素矩阵**：灰度图是一个 $H \times W$ 的矩阵，彩色图是 $H \times W \times 3$ 的「三通道」张量（R、G、B）。图像分析的第一步同样是「转成模型能吃的特征」。

经典图像特征（深度学习之前）靠**手工设计**：

- **颜色直方图**：统计各颜色占比，对「蓝天绿树」这类区分有用。
- **纹理特征**（HOG、LBP）：统计局部梯度方向，捕捉「边缘与纹理」。
- **关键点描述子**（SIFT）：提取并描述图像里的显著局部特征，用于匹配与检索。

**卷积神经网络（CNN）** 改变了这一切：它**自动从像素里学特征**。卷积层用可学习的滤波器在图像上滑动，第一层学到边缘、纹理，深层学到「眼睛」「轮子」等语义部件——特征不再是手工设计，而是从数据中端到端学出来。<span class="marginnote">CNN 的核心归纳偏置是「<strong>局部性 + 平移不变性</strong>」：卷积只在局部窗口内运算（猫的眼睛是局部特征），且同一滤波器滑过整张图（猫出现在图任何位置都该被识别）。这两个先验让 CNN 用远少于全连接网络的参数学到了强大的视觉特征。完整体系见第四级《计算机视觉》与《深度学习》。</span>

**辨析｜易错点：** 图像数据的预处理有特殊纪律。**像素值要归一化**（除以 255 或标准化），否则数值范围大、梯度不稳定；**数据增强**（随机翻转、裁剪、调色）是防过拟合的主力，尤其在小数据集上。但**增强必须语义安全**：对「带方向性的图」（如车牌、文字 OCR）做水平翻转会造出「反的字」，反而伤害模型——增强策略要按任务挑选，不能无脑套模板。

## 3 从非结构化到业务结论：两类数据科学任务

数据科学家接触文本与图像，多是完成两类业务任务：

**任务一：分类与情感分析。** 文本情感（好评/差评/中性）、图像质检（合格/缺陷）、图像分类（品类识别）。管线是：加载数据 → 文本做 TF-IDF 或嵌入、图像做像素归一化与增强 → 训练分类模型 → 评估（第15篇的指标）。<span class="marginnote">情感分析是文本分类最经典的商业应用：把几十万条客服工单、商品评论自动打上情感标签，就能监控「口碑突然变差」的异常（配合第23篇的质量监控思路）。注意中文情感分析要先分词（jieba 等工具），英文则按空格与标点切词——语言差异影响管线第一步。</span>

**任务二：多模态信息提取。** 把非结构化数据「翻译」成结构化字段：从图片里识别出商品、从合同文本里抽取金额与日期（命名实体识别 NER）、从评论里提取「价格贵」「物流慢」的方面。这需要第四级《自然语言处理》的序列标注与抽取技术。

**重点：非结构化数据项目的瓶颈常在「标注」而非「模型」。** 分类模型需要带标签的数据，而文本/图像的标注比表格标签贵得多（要人读、人看）。数据科学里「**先小样本人工标注 → 弱监督/半监督扩量 → 模型迭代**」是处理非结构化数据的标准节奏。标注成本常是决定项目成败的第一约束。

## 4 图像与文本的工程要点

处理非结构化数据，工程上有几个容易踩的坑：

1. **中文文本必须先分词**：中文没有天然空格，「我爱北京天安门」要切成「我 / 爱 / 北京 / 天安门」，分词错误会污染所有下游。
2. **图像数据要检查「加载后真的对」**：`imread` 之后打印 shape、看一眼样例图——路径错误、通道顺序错误（RGB vs BGR）是最常见的隐形 bug。
3. **超参数随数据规模走**：文本里 `min_df`（忽略出现太少的词）、图像里图像尺寸 `resize`，都要看数据量定，不能抄教程默认值。

**辨析｜易错点：** 一个隐蔽但致命的坑是「**训练/测试图像的来源分布不一致**」：训练集是摄影棚拍的、测试集是手机拍的，模型在测试集崩盘。非结构化数据的**域差异（domain shift）** 比表格数据更常见也更隐蔽——上线前务必检查「模型要服务的数据长得像不像训练数据」。<span class="marginnote">域差异的经典例子：用「网络商品图」训练的图像分类器，部署到「门店监控摄像头」的画面——光线、角度、遮挡全变了，准确率断崖。第31篇《案例实践》会讲怎么用「灰度上线 + 分布监控」来提前发现这类问题。非结构化数据的域漂移，是「看起来训练得很好、上线就崩」的头号元凶。</span>

## 5 一个情感分析小流程：从评论到分数

把文本数据的方法串成一个能跑通的小流程：**对商品评论做情感分析（好评/差评/中性）**。

**第一步，数据与标签**。拿到 1 万条评论，人工标注 1000 条（好评/差评/中性）作为训练样本——注意「先小样本标注」的纪律（第3节），不必全量标。

**第二步，预处理与向量化**。中文先分词（`jieba`），再做 TF-IDF 向量化。控制特征量：`min_df=2`（出现少于 2 次的词丢弃）、`max_features=5000`（只保留最常用的 5000 词），避免稀疏爆炸。

**第三步，训练与评估**。用逻辑回归 + 第15篇的评估流程：按时间或随机切分，报精确率/召回率/F1（三类问题看 macro-F1）。情感分析用朴素贝叶斯或逻辑回归这类线性模型往往就够——**先经典后大模型**（第1节）。

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

pipe = Pipeline([
    ("tfidf", TfidfVectorizer(min_df=2, max_features=5000)),
    ("clf", LogisticRegression(max_iter=1000)),
])
pipe.fit(X_train, y_train)
```

**第四步，上线与监控**。部署为接口（第14篇），对全量评论打分；监控「好评率」的变化——好评率突降就是舆情异常的早期信号（呼应第25篇的质量监控思路）。

**辨析｜易错点：** 情感分析最经典的坑是「**否定词与程度词**」——「不太差」「绝不说好」这类表达，词袋模型很容易判反。线性模型能学到「不」和「差」的局部共现，但整句语义（「一点也不好」是负面）仍会漏。**如果业务对负面识别的召回要求很高，就要上更深的模型或预训练语言模型**（第四级《大模型原理》）——这再次说明「先经典、按需升级」的性价比原则。

**重点：非结构化数据的项目，走通「小样本标注 → 经典模型 → 上线监控」的闭环，比一上来追求大模型更重要。** 情感分析如此，图像分类、信息抽取皆然。**先让闭环转起来，再逐步升级模型**——这是数据科学处理文本图像数据最稳妥的成长路径。

### 图像增强的更多例子与边界

数据增强（第2节提了一句）值得展开——它是图像数据防过拟合的头号工具，尤其是在数据量小的时候。

**增强的常见手段按「是否改变语义」分两类：**

**语义安全的增强（图像分类常用）**：随机水平翻转、小幅旋转、随机裁剪、缩放、颜色抖动（微调亮度/对比度/饱和度）、随机擦除。这些操作不改变「物体是什么」——一只猫翻转 30 度还是猫。

**语义敏感的增强（必须谨慎）**：垂直翻转（「鸟在树上」变「鸟在树下方」，语义崩坏）、大幅旋转（「6」转 180° 变「9」，数字识别崩坏）、裁剪掉关键部位（车牌、文字被裁没）。**对「方向敏感」的任务，水平翻转都可能有害**——OCR、车牌识别、带朝向的物体（第2节的辨析）。

**增强与训练的正确姿势**：增强应只作用在训练集，验证/测试集保持原图——否则「评估」混进「增强过的图」，分数虚高。现代框架（PyTorch `torchvision.transforms`、TensorFlow Keras）把增强做成「训练时的随机变换」，「每轮看到的是不同的增强版本」——这本身就是一种正则化。

**辨析｜易错点：** 一个常被忽略的增强陷阱是「**增强改变了数据分布，却忘了评估在哪个分布**」。训练用「增强 + 原图」，测试用「原图」，这本身就是一种「训练/测试分布略有差异」——合理，因为增强让模型学到「不变性」。但若增强太狠（颜色过度扭曲），模型学到的是「原图特征被掩盖」，测试反而变差。**增强的强度要与数据量、任务难度匹配**，用第15篇的交叉验证对比「增强前 vs 增强后」的效果，是最稳妥的检验。

**重点：增强的本质是「把人对『什么不变』的先验喂给模型」。** 图像分类的不变的是「类别在翻转/裁剪后不变」；OCR 不变的只有「数字在轻微位移下不变」。**先想清「你的任务对哪些变换不变」，再选增强**——这比无脑套一套增强模板更能命中要害。

## 6 小结

- 文本向量化三档：**词袋 → TF-IDF → 词嵌入/大模型**；任务难度决定档位，先经典后大模型。
- **TF-IDF** = 词频 × 逆文档频率，突出「篇内频繁、语料少见」的主题词，但不理解语义。
- 图像是 **H×W×3 张量**；经典特征（颜色/纹理/SIFT）已被 **CNN 自动学特征**取代；像素归一化与语义安全的增强是纪律。
- 两类业务任务：**分类/情感分析** 与 **信息提取**；瓶颈常在**标注成本**而非模型。
- 工程要点：**中文分词、图像加载自查、按数据量定超参**；警惕非结构化数据的**域差异**。
