## 为什么从数据清洗开始

现实世界的数据永远是脏的：缺值、重复、格式混乱、单位不统一、异常值扎堆。**「真实数据长什么样」和「教科书数据长什么样」之间，隔着一整套清洗工序。**<span class="marginnote">为什么清洗这么耗时间？因为数据是「测量世界的记录」，而世界是混乱的：同一个用户可能用「北京」「Beijing」「BJ」三种写法填城市，同一个日期可能有人写「2026/08/07」有人写「08-07-2026」。机器不关心这些差异，建模却在乎。</span>清洗直接决定后续分析的可靠性——清洗错了，后面所有漂亮方法都在精加工垃圾。

## 1 清洗的四大目标与常用手法

数据清洗可以归纳为四个目标，每个目标对应一组手法：

**目标一：完整性（处理缺值）**。缺值（missing value）有几种产生机制：设备故障、用户跳过填写、系统截断。处理手段有删除、填充、保留三种思路，我们在第 3 节专门展开。

**目标二：唯一性（处理重复）**。同一实体被记录多次，需要去重。<span class="marginnote">去重的关键是定义「重复」：是整行完全一致，还是主键字段一致？企业客户数据里，同一家公司可能以「华为技术有限公司」「华为技术」「Huawei」三条记录并存——整行去重去不掉它们，需要按业务主键或模糊匹配去重。</span>

**目标三：有效性（处理错误与格式）**。值域之外的数据（年龄 200 岁）、格式不统一的数据（手机号带不带国家码）、类型错位的数据（数字字段里混进字母）都属于这一类。

**目标四：一致性（处理冲突与单位）**。同一字段在不同来源里含义或单位不同。温度有的用摄氏度有的用华氏度，金额有的按元有的按美元——不统一就无法比较。

**重点：清洗的每一步都要「可复现、可回溯」。** 不要手工在 Excel 里点来点去，而是把清洗写成脚本，保留处理日志。这样当结论被质疑时，你能回答「我们对数据做了什么」。

## 2 缺值处理的三种策略

缺值是清洗里最需要判断力的部分。按比例与机制，有三种策略：

1. **删除（删除行/列）**：当缺值比例很低（如 < 5%）时，直接删除含缺值的行；当某一列缺值比例极高（如 > 70%）时，考虑删除整列。删除最简单，但**丢弃了数据**，且如果缺值机制不是随机的，删除会引入偏差。
2. **填充（imputation）**：用统计量填充，如均值、中位数、众数；或用模型预测缺失值（如 KNN 填充、回归插补）。填充保留了样本量，但**人为注入了信息**，会低估不确定性。<span class="marginnote">一个常被忽略的细节：<strong>填充应该只基于训练集计算统计量</strong>。如果先用全量数据算均值再填充，再用全量数据训练模型，测试集的信息就泄漏进了训练过程——这是「数据泄漏」的经典形态，第15篇《模型评估与选择》会系统讲。</span>
3. **保留并标记**：把「是否缺失」本身当作一个信息，构造缺失指示列。某些场景下（如医疗数据），「没填」本身就携带含义。

**辨析｜易错点：** 缺值处理没有银弹，**删除与填充的选择要结合缺值机制（missing mechanism）**。如果缺值完全随机（MCAR），删除与填充都相对安全；如果缺值与未观测因素相关（如高收入人群更少填收入），删除会系统性丢数据，此时应谨慎对待。判断机制只能靠领域知识与探索性分析，不能拍脑袋。

## 3 异常值：先辨别，再决定

异常值（outlier）不是「错误」的同义词。它可能是测量错误、录入错误，也可能是**真实但罕见的极端事件**——一只身长 8 米的鲸鱼是数据，不是错误。

处理异常值的第一步是**发现**，常用三种方法：

**统计法**：基于分布假设，如 $z$ 分数超过阈值。设数据服从均值 $\mu$、标准差 $\sigma$ 的分布，则 $z = \frac{x - \mu}{\sigma}$，通常取 $|z| > 3$ 为异常。<span class="marginnote">$z$ 分数法隐含「数据近似正态」的假设。对偏态分布（如收入、房价），更好的选择是<strong>基于四分位距（IQR）</strong>的方法：$IQR = Q_3 - Q_1$，凡落在 $[Q_1 - 1.5\,IQR,\ Q_3 + 1.5\,IQR]$ 之外的都视为异常。IQR 法对分布形状不敏感，更稳健。</span>
**可视化法**：箱线图（boxplot）直接画出四分位与异常点，一目了然。
**模型法**：孤立森林（Isolation Forest）等专门算法在特征空间里找「离群」样本。

第二步是**处理**，原则是「先分诊，后动手」：

1. 先判断异常值是**错误**还是**真值**（查元数据、查业务规则）。
2. 错误：修正（如果能追溯到正确值）或删除。
3. 真值：**一般保留**，除非它确实是业务上不可能的值。极端真值恰恰是模型要学习的「长尾」，盲目删除会破坏分布。

## 4 清洗的工程化：管道与日志

单次清洗容易，可复现的清洗难。工程化的做法是：把每一步清洗写成**可组合的函数**，串成清洗管道（pipeline），并用日志记录每一步的输入/输出规模。

```python
import pandas as pd

def log_step(name, df):
    print(f"{name}: {df.shape[0]} 行")
    return df

def drop_duplicates(df):
    return log_step("去重", df.drop_duplicates())

def fill_price_median(df):
    df["price"] = df["price"].fillna(df["price"].median())
    return log_step("补缺失值", df)

# 串成管道：每一步都留痕
df = fill_price_median(drop_duplicates(df))
```

**重点：清洗管道的每一步都应留下「发生了什么」的痕迹。** 数据从 10 万行变成 9 万行，为什么少了 1 万行？这份台账是数据科学报告里「数据质量」章节的素材，也是你与同事争论「结果可信吗」时的底气。<span class="marginnote">工程化的清洗管道与第三级《软件工程》里的代码复用、第四级《机器学习》里的预处理管道一脉相承。数据科学的工程化水平，往往就体现在这份台账的完整程度上。</span>

## 5 清洗检查单：实战时可对照的清单

清洗是熟练工种，靠的是「按清单逐项过」。一份可直接抄用的检查单：

**第一步，结构体检**：

- 表有多少行、多少列？行数与预期是否相符（对不上就查取数逻辑）？
- 每列的数据类型正确吗？数字列里有没有混入字符串（`pd.to_numeric` 的 `NaN` 一眼能查）？
- 列名是否规范、有无重复？

**第二步，缺失与唯一性**：

- 每列缺失率是多少？超过 70% 的列考虑删除，低于 5% 的考虑删行（第2节）？
- 主键（如用户 ID）是否唯一？重复记录怎么合并？
- 关键字段（金额、日期）的缺失是否集中于某些来源？

**第三步，值域与格式**：

- 数值列是否有超出常识的值（年龄 200、金额为负）？
- 日期列格式是否统一？时区是否一致？
- 类别列是否出现「从未见过的取值」（说明数据源或枚举变了）？

**第四步，一致性**：

- 单位是否统一（元 vs 万美元、摄氏 vs 华氏）？
- 同一实体在不同来源的取值是否一致（两个系统里「客户 A」的注册日期是否相同）？

**第五步，留痕**：

- 每一步清洗的「输入行数 → 输出行数」是否记录？
- 清洗规则是否写成脚本、可复现？

**重点：把这张清单当作「下结论前的安检」。** 当你准备「基于这批数据出结论」时，逐项打勾。任何一项说不清，都意味着分析的地基还没打好——宁可多花一小时核对，也不要让「数据错误」在结论里潜伏三周。

## 6 小结

- 清洗的四大目标：**完整性（缺值）、唯一性（重复）、有效性（格式/错误）、一致性（单位/冲突）**。
- 缺值三策略：**删除、填充、保留并标记**；选择取决于缺值比例与缺值机制。
- 异常值先**分诊**（错误还是真值）再处理，真值一般保留，不盲目删除。
- 清洗必须**工程化**：写成管道、保留日志，保证可复现可回溯。
- 清洗时的每一次填充、删除，都要警惕**数据泄漏**的风险。
