## 为什么从工作流开始

前九篇我们已经掌握了统计推断、回归、分类、聚类、降维、时序与贝叶斯等一把把工具。但**工具齐了不等于能干活**——把数据、模型、评估串成一条可靠的流水线，本身就是一门手艺。<span class="marginnote">数据科学专题的定位是「把散件拼成体系」：统计与机器学习给出方法，数据工程（第三篇）给出系统，本文负责的则是两者之间的胶水——让「一份干净数据」变成「一个可部署、可评估、不泄漏的模型」的标准流程。更系统的机器学习方法论，见第四级《机器学习》全篇。</span>这一篇讲的就是这条胶水。

## 1 一条完整的工作流长什么样

把机器学习项目落到时间轴上，标准工作流是七步：

1. **数据切分**：把数据划分成训练集、验证集、测试集。
2. **预处理**：清洗残留、编码类别、缩放数值、处理缺值（用训练集学到的参数）。
3. **基线模型**：先跑一个最简单的模型（均值预测、线性回归、决策树桩），拿到「下限」。
4. **模型选择**：在验证集上比较多种模型与超参数。
5. **调参与验证**：用交叉验证选超参数，反复迭代。
6. **最终评估**：在**从未参与任何决策**的测试集上做一次最终评估。
7. **部署与监控**：上线、记录、监控性能衰减。

**重点：切分发生在一切模型决策之前，测试集是「不可侵犯」的。** 测试集一旦参与任何调参或特征选择，评估结果就打了折扣——这叫做「测试集污染」。保护测试集是工作流纪律的第一条。<span class="marginnote">一个实用的纪律：把测试集「锁进保险箱」——在项目一开始就切好、存好，之后所有探索、调参、特征工程都只用训练/验证部分，直到项目收尾才解锁做最终评估。这能根治「反复看测试集、越调越乐观」的慢性病。</span>

## 2 数据泄漏：工作流里最隐蔽的敌人

**数据泄漏（data leakage）** 指「本不该出现在训练时的信息，被模型在训练时看到了」，导致评估指标虚高、上线后断崖式变差。它是数据科学里「看起来成功、实际失败」的头号元凶。

三类最常见的泄漏：

1. **切分泄漏**：随机打乱时间序列再切分，让模型从「未来」学到「过去」——时序数据必须按时间顺序切分（第12篇已强调）。
2. **预处理泄漏**：用全量数据（含测试集）计算均值/标准差再标准化，或做 PCA 拟合——**所有预处理都必须只在训练集上拟合，再应用到测试集**。<span class="marginnote">一个隐蔽的例子：用全量数据做中位数填充缺值。填充的「中位数」这个数字本身携带了测试集的信息，相当于把测试集偷偷喂给了训练。正确做法是用 sklearn 的 Pipeline 把「填充-缩放-建模」绑成一个整体，Pipeline 只在训练集上 fit、再到测试集上 transform。</span>
3. **目标泄漏**：特征里包含了「只有未来才知道」的字段。例如预测「用户明天是否流失」，特征里却有一列「用户是否已提交退订申请」——退订申请就是明天流失的果，不是因。这种泄漏靠领域知识排查。

**辨析｜易错点：** 泄漏的可怕之处在于**指标看不出异常**——泄漏模型的交叉验证分数往往漂亮得很，却在上线后原形毕露。因此排查泄漏不能靠看指标，要靠审计整条数据流：每个特征是否「在预测时点就能拿到」？每步预处理是否只用训练集信息？

## 3 预处理与管道：把「工作流」编码成「代码」

手工按顺序执行预处理，极易在某一步不小心用上全量数据。工程化的解法是 **Pipeline（管道）**：把「预处理 + 模型」绑定为一个可整体 fit/predict 的对象，确保每一步只在训练集上学参数。

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("imputer", SimpleImputer(strategy="median")),  # 只在训练集上学参数
    ("scaler", StandardScaler()),
    ("clf", LogisticRegression(max_iter=1000)),
])

pipeline.fit(X_train, y_train)
y_pred = pipeline.predict(X_test)
```

**重点：Pipeline 的价值是把「不泄漏」从纪律变成结构。** 你不需要每次提醒自己「填充均值只能算训练集的」，因为 Pipeline 的机制保证参数来自训练集。配合**交叉验证**（用 cross_val_score 对 Pipeline 整体做），调参、评估、防泄漏三者一次完成。<span class="marginnote">交叉验证为什么要在 Pipeline 上做？因为如果先在完整训练集上标准化、再做交叉验证，每一折的验证集已经被「全训练集拟合的 scaler」处理过，同样构成轻微泄漏。把整个 Pipeline 放进交叉验证循环，每一折的预处理参数都只来自该折的训练部分，这才干净。这个细节与第4篇清洗的「只基于训练集填充」一脉相承。</span>

## 4 工作流的节奏：基线先行，复杂渐进

工作流不只是技术清单，还有**节奏**。数据科学项目最常见的失败模式是「一步跳到最复杂模型」——直接用 XGBoost 或神经网络跑起来，调参调到天荒地老，却不知道它与简单基线相比到底赢了多少。

推荐的节奏是：

1. **先定基线**：均值预测 / 线性模型 / 决策树，成本低、可解释，给一切复杂模型提供参照系。
2. **再加复杂度**：只在基线明显不够时（欠拟合或业务要求更高精度）升级到复杂模型。
3. **每次只改一个变量**：加一个特征、换一个模型、调一组超参，分别记录效果——科学方法在数据科学里的化身。

**辨析｜易错点：** 复杂模型「看起来赢」常常是假象：可能是泄漏、可能是过拟合、可能是验证划分运气好。**把复杂模型与基线放在同一个 Pipeline、同一套评估流程下对比**，才谈得上「谁更好」。

## 5 常用工具栈与协作模式

工作流讲的是「方法论」，工具栈讲的是「用什么干活」。一套数据科学标准工具栈大致是这样分工的：

- **数据处理**：pandas / Polars——表格清洗、变换、聚合（第4-5篇）。
- **建模**：scikit-learn——统一接口（fit/predict）的模型与 Pipeline 全家桶；XGBoost/LightGBM——树模型的工业主力。
- **调参与实验**：Optuna、MLflow——超参搜索与实验追踪（第2篇 MLOps 的落地）。
- **版本与协作**：git + DVC（数据版本控制）——代码和数据都纳入版本管理。
- **部署与调度**：FastAPI 提供推理接口；Airflow 调度批任务（第20篇）；Docker 封装环境。

**协作模式**上，数据科学是强协作工种，两条经验值得记下：

1. **代码评审**：模型代码也要过评审——评审者重点看「数据是否泄漏、评估是否规范」，而不只是「代码能不能跑」。
2. **分析即文档**：用 Jupyter/Quarto 写分析，但**笔记本只做探索，正式流程必须进脚本**——否则「结果不可复现」会立刻找上门。

**辨析｜易错点：** 工具栈的坑往往不在「不会用」，而在「**混用抽象层次**」。例如在 pandas 里做特征、却想放进 scikit-learn 的 Pipeline 做交叉验证——两者对「数据形态」的假设不一致，硬拼会让第14篇的防泄漏结构失效。**工具的选择要以「是否兼容 Pipeline 的 fit/predict 契约」为准**，而不是以「哪个库我熟」为准。

**重点：工具栈是流程的「可执行化」。** 第14篇的七步工作流，每一步都有一个对应的工具落点。当你能把「工作流」翻译成「工具调用」时，你就从「知道怎么做」进阶到「真能这么做」——这也是数据科学工程能力的标志。

### 随机种子：复现的最小单位

工作流里一个最容易忽略、却决定「能否复现」的细节是——**随机种子（random seed）**。机器学习处处有随机性：数据切分、模型初始化、采样与增强。不固定种子，同一份代码跑两次，结果可能不同。

**三个必须固定种子的地方：**

1. **数据切分**：固定 train_test_split 的 random_state——否则每次跑的划分不同，结果不可比。
2. **模型训练**：随机森林、神经网络等带随机初始化/采样的模型，random_state 固定才能「重跑一致」。
3. **整个环境**：Python 的 random.seed(42)、NumPy 的 np.random.seed(42)、PyTorch/TensorFlow 的全局种子——深度学习里还要配合 deterministic 模式（PyTorch 的 torch.use_deterministic_algorithms(True)），才能完全复现。

**重点：固定种子是「结果可辩护」的第一步。** 当别人问你「这个 AUC 0.85 是运气还是实力」，你能回答「换 5 个种子、取均值，都是 0.83–0.86」——这比「就这一次跑出来的」有说服力得多。**报结果时，报告「多颗种子下的均值 ± 波动」，而不只是一次结果**，是第8篇「不确定性」思维在工作流里的最小实践。

**辨析｜易错点：** 别把「固定种子」当「结果就正确」。**种子固定只是让实验可重复，不能消除过拟合与泄漏**——一个泄漏的模型，固定了种子也一样会「稳定地错」。固定种子 + 第5节的错误清单，两者都要：**先保证流程正确，再保证结果可复现**。

## 6 小结

- 工作流七步：**切分 → 预处理 → 基线 → 模型选择 → 调参 → 最终评估 → 部署监控**。
- **测试集不可侵犯**：切分先行，一切模型决策只用训练/验证部分。
- **数据泄漏**三类：切分泄漏、预处理泄漏、目标泄漏；指标看不出泄漏，要靠审计数据流。
- **Pipeline** 把「预处理 + 模型」绑成整体，把「不泄漏」从纪律变成结构。
- 节奏上**基线先行、复杂渐进**，每次只改一个变量，对比才有意义。
