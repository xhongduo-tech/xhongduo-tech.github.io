## 为什么从 NetLogo 开始

上一节我们立住了「涌现要从底部生长」的思想，但思想不变成能跑的模型就只是隐喻。这一节的任务是把范式落地：选择一门最小的建模语言，亲手把第一批主体放进虚拟世界。<span class="marginnote">NetLogo 由 Uri Wilensky 于 1999 年在西北大学开发，源自 1960 年代 Papert 的 LOGO 语言传统——「海龟」（turtle）一词正是从 LOGO 继承而来。它至今是 ABM 教学与科研引用量最高的平台之一。</span>选择 NetLogo 不是因为它是功能最强的 ABM 平台——功能最强的是用于大规模仿真的 Repast 与 Mason，本专题后面会专门讲到——而是因为它把 ABM 的「主体-规则-观察」三件事暴露得最干净，学它等于学 ABM 的共同语法。

## 1 ABM 范式：从写方程到写规则

在进入 NetLogo 前，先想清楚 ABM 建模者与常规建模者做的事有什么本质不同。常规模型（微分方程、统计模型）的建立方式是：**先确定感兴趣的宏观变量，再写这些变量之间如何变化的方程**。ABM 的方式正好颠倒：

**常规范式**：宏观变量 $\to$ 宏观方程 $\to$ 求解/模拟 $\to$ 得到宏观行为。

**ABM 范式**：定义主体 $\to$ 写个体规则 $\to$ 运行虚拟世界 $\to$ 观察宏观模式 $\to$ 与真实模式比对。

常规范式的全部知识都浓缩在方程里，宏观行为由求解得到；ABM 范式的宏观行为「不在任何一行代码里」——它只存在于运行之后、统计之上的观察结果里。**常规建模是先假设宏观律，ABM 是先写微观律、让宏观律自己长出来**。这一颠倒就是第 1 篇「从底部生长」的全部含义，也是 ABM 论文里「结果」一栏写的是仿真输出的原因。

**辨析｜易错点：** 不要把「ABM 范式」误解成「不用数学」。ABM 里的个体规则本身是数学对象——概率、分布、决策函数；第 7 篇的冯·贝塔朗菲生长方程、第 10 篇的接触概率都是个体规则里的数学。区别不在「用不用数学」，而在「数学写在哪个层面」：方程范式写在群体层面，ABM 写在个体层面。两者甚至可以互相验证——第 12 篇会讲到，ABM 在均匀混合极限下应当退化为解析方程的解。

| 维度 | 常规范式 | ABM 范式 |
| --- | --- | --- |
| 起点 | 宏观变量与方程 | 主体与个体规则 |
| 宏观行为 | 由求解得到 | 由运行涌现 |
| 主体 | 同质、可平均 | 异质、不可平均 |
| 解释方向 | 从顶部推导 | 从底部生长 |
| 知识形态 | 解析解、封闭方程 | 计算实验、虚拟世界 |

## 2 NetLogo 的世界：四类主体

NetLogo 的虚拟世界只有四类主体，全部 ABM 都用它们搭成：

**海龟（turtle）**：可以移动、携带属性（`energy`、`age`）、执行规则的主体。动物、人、车辆、企业都是海龟。<span class="marginnote">在 NetLogo 里创建海龟用 `create-turtles 100`，让它动起来用 `ask turtles [ forward 1 ]`。`ask` 是 NetLogo 最核心的原语——「让某类主体各自执行一段规则」，这正是一句 ABM 个体规则的语法化。</span>

**地块（patch）**：把世界切成方格的环境单元，携带环境属性（`grass?`、`temperature`）。海龟读写地块，地块记录环境状态——第 3 篇「主体—环境交互」的两端就是海龟与地块。

**连接（link）**：连接两只海龟的边，用于表示网络结构——朋友关系、交易关系、传染接触。连接把 NetLogo 从「格子世界」扩展到「网络世界」，是第 8 篇扩散模型与第 9 篇社会网络模型的语法基础。

**观察者（observer）**：不在世界里，负责创建世界、读取统计、调度运行——它是「上帝视角」的实验室操作员。

四类主体的分工正好复刻了 ABM 的骨架：**海龟是「谁」，地块是「环境」，连接是「关系」，观察者是「实验者」**。写 ABM 时先问一句「我的主体该由哪类承载」，等于先画出了模型的骨架图。

在 NetLogo 里，四类主体各有对应的原语：海龟用 `create-turtles` 创建，地块是网格自动生成、用 `pcolor` 与 `plabel` 读写属性，连接用 `create-links` 建立，观察者则是模型文件的顶层代码。`ask turtles [ ... ]`、`ask patches [ ... ]`、`ask links [ ... ]` 三个 `ask` 恰好覆盖主体间、主体—环境、网络三条交互通道——**先把骨架图想清楚，再查这些原语，比边写边想高效得多**。

## 3 第一个模型：让海龟在草地上漫游

NetLogo 用「代码 + 界面 + 行为空间」三个面板构成一个完整的实验平台。一个最小模型只有三行核心代码，足以说明「规则如何变成宏观」：

**setup（初始化）**：`clear-all` 清空世界，`create-turtles 50` 放 50 只海龟在随机位置。

**go（主循环）**：`ask turtles [ forward 1 ]` 让每只海龟向前走一步，`ask patches [ if pcolor = white [ set pcolor gray ] ]` 让海龟踩过的白色地块变灰——**环境被改写了**。

**repeat（循环）**：把 go 包进 `forever` 按钮，世界就自动运转。你看到的不是预先画好的图案，而是 50 条简单规则在 50 只主体上运行后「长出来」的灰色轨迹网。完整代码只有两个过程：

```netlogo
to setup
  clear-all
  create-turtles 50 [ setxy random-xcor random-ycor ]
  ask patches [ set pcolor white ]
end

to go
  ask turtles [ forward 1 ]
  ask patches [ if pcolor = white [ set pcolor gray ] ]
  tick
end
```

注意 `tick` 把时间推进一步——它是 ABM 里「时钟」的最小实现，也是第 3 篇调度讨论的起点。

这个模型小得近乎无聊，却已包含 ABM 的全部三要素：主体（海龟）、规则（向前、染色）、观察（轨迹图案）。把它换成更真实的规则——海龟发现灰色地块就转向（记住「草地被踩过」）、或者彼此碰撞就回弹——同一个骨架就能长成 Resnick 著名的海龟—白蚁模型、以及模型库里的鸟群（Boids）模型。<span class="marginnote">Boids 模型用三条局部规则（对齐、靠近、分离）就能涌现出逼真的鸟群阵形——没有中央指挥，没有「整体转向」指令。它是「微观规则 → 宏观涌现」最直观的入门演示，也是 NetLogo 模型库（Models Library）里最受欢迎的模型之一。</span>**第一次运行 ABM 的仪式感在于：你写的规则里没有「群」，但屏幕上出现了群。**

## 4 公式解析：随机游走的位移

**第一个模型里海龟做的正是随机游走——它背后有一条支配整个扩散物理的平方根律。** 若海龟每步等概率向随机方向走单位长度，走 $N$ 步后的期望位移大小近似为：

$$
\mathbb{E}\big[\|\vec{R}_N\|\big] \approx \sqrt{N}
$$

分四步拆解：

- **第一步，看单步**：每一步位移 $\vec{r}_t$ 是方向随机的单位向量，其期望 $\mathbb{E}[\vec{r}_t] = \vec{0}$——平均位移是零，所以「平均位置」无法描述随机游走。
- **第二步，看位移平方**：总位移 $\vec{R}_N = \sum_{t=1}^{N}\vec{r}_t$，其平方的期望为 $\mathbb{E}[\vec{R}_N^2] = \sum_t \mathbb{E}[\vec{r}_t^2] + 2\sum_{t<s}\mathbb{E}[\vec{r}_t \cdot \vec{r}_s]$。因为各步独立、方向随机，交叉项 $\mathbb{E}[\vec{r}_t \cdot \vec{r}_s]=0$，于是 $\mathbb{E}[\vec{R}_N^2] = N$。
- **第三步，开根号**：位移大小的量级由 $\sqrt{\mathbb{E}[\vec{R}_N^2]} = \sqrt{N}$ 刻画——**位移随步数按平方根而非线性增长**。走 100 步，期望位移约 10 步；走 10000 步，约 100 步。扩散之所以「慢」，就慢在这条平方根律上。
- **第四步，连接 ABM 与宏观方程**：这条 $\sqrt{N}$ 律正是扩散方程 $D = \langle r^2\rangle/(2\,\mathrm{d}t)$ 的微观来源——**一群随机游走的海龟，在宏观上等价于一个扩散过程**。ABM 里「每个主体随机走动」的规则，与物理里「浓度按扩散方程演化」的方程，是同一个现象的两种描述层次。这一连接是本专题第一次看到「个体规则与宏观方程可以互相印证」——后面第 10 篇的 SIR-ABM 会再次遇到。

这条平方根律还给了我们一个免费的工程验证：**在 NetLogo 里跑一个随机游走模型，测量位移平方随步数的增长，若斜率远离 1，说明随机数或步长实现有误**——用解析结果校核 ABM 实现，是第 6 篇「与解析极限对照」的最早演练。模拟与解析在这里不是对手，而是互相验证的两种语言。

## 5 从动画到科学：观察者与测量

把 ABM 当「动画看」只是第一步，它要成为科学必须能**测量**。NetLogo 的观察者（observer）正是为此存在：

**监视器（monitor）**：实时显示一个统计量——海龟总数、平均能量、地块变色比例。
**图表（plot）**：把统计量随时间画成曲线，宏观动态一目了然。
**输出（export）**：把每次运行的数据导出成表格，供统计与灵敏度分析使用（第 11 篇）。

**从动画到科学的关键一步，是把「看起来有模式」翻译成「能测度的量」**——这一翻译是第 5 篇 POM 与第 6 篇验证的起点：模式（pattern）必须先被量化成可比的指标，模型才能被筛选与校准。NetLogo 界面上的每一次点击（setup → go → 观察），本质都是一次微型计算实验；把「一次实验」升级为「参数扫描的系统实验」，正是第 11 篇行为空间探索（BehaviorSpace）要做的事。

### 与相邻专题的衔接

- 第 1 篇的涌现概念，在本篇变成「海龟规则 → 群形」的可见事实；
- 第 3 篇的主体—环境交互，语法基础就是这里的 `ask` 与 `patch`；
- 第 4 篇的 ODD 描述，需要你先把模型「写成 NetLogo 代码」才能被描述；
- 第三级《编程语言》为 NetLogo 的 `ask`/`set` 提供编程概念底座。

## 6 小结

- **ABM 范式**颠倒常规范式：定义主体、写个体规则、运行虚拟世界、观察宏观模式——宏观行为从运行中涌现，不在任何一行代码里。
- NetLogo 只有**四类主体**：海龟（个体）、地块（环境）、连接（关系）、观察者（实验者），它们复刻了 ABM 的完整骨架。
- 一个最小模型由 **setup、go、repeat** 三部分构成，三行代码就能演示「规则 → 宏观」的涌现。
- 随机游走的期望位移 $\approx \sqrt{N}$——这是扩散方程 $D=\langle r^2\rangle/(2\mathrm{d}t)$ 的微观来源，也是「个体规则与宏观方程互证」的第一次相遇。
- **从动画到科学**：把「看起来有模式」翻译成「能测度的量」，是 POM 与校准的起点。
- NetLogo 的 `ask` 原语是「个体规则」的语法化，覆盖三条交互通道；随机游走的 $\sqrt{N}$ 律可用来校核实现正确性。

在下一节，我们将追问一个最小模型漏掉的关键问题：主体之间、主体与环境之间到底如何交互，时间又以什么顺序流过它们——这就是**主体—环境交互与调度**。
