## 为什么从材料数据库与标准开始

上一节说材料基因组计划的三根支柱之一是「数据」。但数据不是天然可用的：几十万条记录散落在论文里、用各自不同的格式与单位书写，机器读不懂、人也难比对。**材料数据库与数据标准**，就是把「数据」变成「可计算的数据资产」的那道工序。<span class="marginnote">类比：人类基因组计划成功的前提，不只是「测了很多基因」，而是确立了统一的序列数据库（GenBank）与格式标准。材料领域要复制的正是这条经验——先有标准与库，才有大规模自动化的可能。</span>

这一节讲四件事：有哪些主流材料数据库、数据以什么格式存储、为什么「数据标准」决定了机器能否读懂、以及开放数据运动的得与失。

## 1 主流材料数据库巡礼

材料信息学的数据库大致分三类：**计算数据库**（第一性原理算出的性质）、**实验数据库**（实测性质与晶体学数据）、**文献与结构数据库**。最重要的几张名片：

| 数据库 | 类型 | 规模与特点 |
| --- | --- | --- |
| Materials Project | 计算 | 数十万条 DFT 计算记录，形成能/带隙/弹性等，API 开放 |
| AFLOW | 计算 | 高通量结构-性质库，注重自动化协议与可复现 |
| OQMD | 计算 | 热力学性质库，聚焦凸包与相稳定性 |
| ICSD | 实验 | 无机晶体结构库，收录已合成化合物的结构 |
| NIST 材料数据 | 实验 | 权威实测性质，注重溯源与不确定性 |
| JARVIS | 计算 | NIST 出品，含机器学习基准数据集 |

对这些库的第一印象应该是：**「材料数据库」不是一张大表，而是一个生态**——计算库负责「通量」，实验库负责「真值」，两者在筛选流程里接力使用。<span class="marginnote">一个使用惯例：粗筛（百万候选）用计算库的 DFT 数据；复核（几十个候选）用实验库或自己补算的 DFT；两者不一致时，以「标注了计算方法与误差」的条目为准。数据库的「元数据」比「数值」更能告诉你该信它几分。</span>

### 辨析｜易错点：数据量大 ≠ 数据可信

计算库的几十万条记录，是不同论文、不同参数、不同版本算出来的「拼图」。同一化合物在库 A 与库 B 里可能差出几十 meV——这不是错误，而是计算协议不同。**用库之前先读它的「协议」**：用了什么泛函、什么截断能、什么 K 点密度，决定了这批数据的「性格」。

## 2 数据格式：把材料翻译给机器

机器要读材料，材料必须先被「编码」。材料信息学里最重要的几种格式：

- **CIF（Crystallographic Information File）**：晶体结构的标准文本格式——晶格参数、空间群、原子坐标、占位，一个晶体就是一份 CIF。
- **JSON/XML**：结构化元数据，Materials Project 的 API 返回 JSON，机器友好。
- **VASP/POSCAR 等计算输入格式**：计算软件自己的结构文件，工具间常需互转。
- **描述符向量**：把结构/成分转成固定维度数值向量，是机器学习模型的直接输入（见《材料描述符》一节）。

CIF 是其中最核心的「语言」：**只要拿到一份 CIF，就能重建一个晶体并重算它的性质**。<span class="marginnote">CIF 是「人可读 + 机器可读」的典范——它既是给科学家看的结构档案，也是给软件算的输入。材料信息学里大量工具（`pymatgen` 等）都以 CIF 为交换格式。这也是为什么数据库通常允许「按 CIF 下载结构」——结构才是性质的本体。</span>

### 公式解析：数据行 = 结构 + 描述符 + 性质

一条材料数据记录，本质上是三段的拼接：

$$\text{record} = \left(\underbrace{\text{结构}}_{\text{CIF 或图}}, \underbrace{\text{描述符}}_{\text{定长向量}}, \underbrace{\text{性质}}_{\text{带单位标量}}\right)$$

- **第一步，结构段**：晶体怎么排列（CIF / 晶体图），决定「这是哪个材料」。
- **第二步，描述符段**：把结构编码成数值向量，供机器学习消费——这一步质量决定模型上限。
- **第三步，性质段**：形成能、带隙等目标值，**必须带单位与计算方法**（eV/atom？PBE 还是 HSE？），否则数值没有意义。

「一条记录」的这三个字段，正好对应本专题后续的数据处理链：结构进 → 描述符出 → 性质被预测。理解记录的三段式，就理解了数据库与模型之间的接口。

## 3 数据标准：为什么格式统一如此值钱

数据标准的重要性，可以用一个词概括：**互操作性（interoperability）**。几十万条记录只有能被同一套工具统一读取、统一转换，才能被批量计算与学习。MGI 特别强调的「数据可复现」，落实下来就是标准：

- **单位与坐标系统一**：能量用什么单位（eV、Ha、J）、结构用什么坐标系（分数坐标 vs 笛卡尔），不统一就是灾难。
- **计算参数可溯源**：每条记录标注泛函、截断能、K 点，复现者才知道怎么重算。
- **命名与检索规范**：元素、相、结构的命名一致，才谈得上跨库比对与去重。

<span class="marginnote">一个真实的「不标准」教训：早期论文常只报「带隙 1.8 eV」而不说算的还是测的、什么泛函。这类记录放进数据库，机器学习模型会把它当成「带隙真值」，学到一堆互相矛盾的标签。数据标准的本质是<strong>把隐性的实验/计算条件显性化</strong>。</span>

### FAIR 原则：数据共享的宪法

近年数据界把标准总结成 **FAIR** 四原则——**可发现（Findable）、可访问（Accessible）、可互操作（Interoperable）、可复用（Reusable）**。材料数据库的评分，如今几乎都按这四把尺子量：能不能被检索到？API 通不通？格式能不能被工具直接读？重算能不能复现？

## 4 开放数据：共享的红利与代价

开放数据运动让材料数据库成为公共物品，红利巨大：**任何人拿到同一批数据，就能复现同一条发现链**；跨库合并让样本量指数增长；标准基准（benchmark）让不同模型可以在同一起跑线上比较。

但开放不等于免费午餐。三个现实代价：

**数据质量参差**：开放库里的记录来自不同来源，错误与标注不一致难以根除——用前要清洗（呼应《特征工程》一节）。
**「库锁」风险**：主要数据库掌握在少数机构手中，API 政策、收费模式可能变化——科研的长期依赖要留后手。
**隐私与商业张力**：企业的工艺数据、专利前的实验数据不愿公开——开放与商业保密之间永远有张力。

### 辨析｜易错点：开放数据 ≠ 直接可用

开放数据库给的是「原材料」，不是「训练集」。把 Materials Project 的 5 万条形成能直接喂给模型，往往踩坑：数据分布偏（高通量库偏爱稳定的、好算的体系）、标签带系统偏差（DFT 低估带隙）、缺失与重复记录横生。**正确姿势是把库当「数据源」而非「成品集」**——下载、清洗、去重、标注协议，这些预处理（第 5 节）决定了模型真实的上限。

### 案例：一次真实的「库到模型」取数流程

把前面的概念串成一个实操流程——从 Materials Project 拉一批形成能数据，准备训练集：

1. **登录并查询**：用 API 或网页筛选器，按元素（如 Fe、O）、相、性质字段过滤，返回候选列表；
2. **下载结构**：每条记录下载 CIF 或直接取晶格 + 坐标，作为「结构段」；
3. **提取标签**：读取形成能字段，**同时记下计算方法（泛函、版本）**——同一字段可能混着不同计算协议的值；
4. **检查完整性**：缺失性质、异常能量的记录标记或剔除；
5. **导出为数据表**：把「结构 + 描述符 + 性质」整理成模型能吃的格式，存档元数据。

第 3 步是新手最容易漏的：只抓数值不记协议，等于把「PBE 带隙」和「HSE 带隙」混成同一个标签——模型会学到一团互相矛盾的目标。**每一次取数，都要把「这条数据怎么来的」一并带走**，这是数据标准在实践中最落地的体现。

### 数据版本：数据库也会「生长」

数据库不是静态的：Materials Project 每年都新增计算记录、修正旧条目。这意味着**同一化合物的性质，在不同版本库里可能不同**——如果你用 2024 版数据训模型，论文里却引用 2020 版的值，就是版本不一致。

工程上两条纪律：一是**固定版本**，下载数据时记录数据库版本号与下载日期；二是**记录去重与清洗规则**——你删了哪些重复结构、补了什么缺失值，都要可复现。数据版本管理（data versioning）是数据工程里与代码版本管理同等重要的一环，材料信息学的严肃工作都在遵守它。

## 5 小结

- **数据库生态**：计算库（Materials Project、AFLOW、OQMD）负责通量，实验库（ICSD、NIST）负责真值，筛选流程里接力使用。
- **记录三段式**：结构（CIF/图）+ 描述符（定长向量）+ 性质（带单位标量）——结构进、描述符出、性质被预测。
- **CIF 是核心语言**：拿到 CIF 就能重建晶体、重算性质，是「人可读 + 机器可读」的交换格式。
- **数据标准**：单位统一、参数溯源、命名规范，本质是把隐性条件显性化；FAIR 原则是数据共享的宪法。
- **开放红利与代价**：共享带来复现与通量，但也带来质量参差与「库锁」风险。
- **辨析提醒**：开放数据 ≠ 直接可用，要当「数据源」清洗，不当「成品集」直接喂。
