## 为什么从 NTFS 开始

FAT 把「文件名 → 簇链」藏在目录项里；NTFS 则把「一个文件的所有信息」装进一条**记录**，全部记录集中在一张主表里。这个设计带来两个巨大优势：**所有元数据统一管理**，以及**文件小到可以整段塞进元数据**。NTFS 是 Windows 的默认文件系统，也几乎是最常被恢复的对象——理解它的「文件即记录、属性即字段」模型，是 Windows 逻辑层恢复的核心能力。

<span class="marginnote">NTFS 与 FAT 最大的哲学差异：FAT 里「目录」是特殊文件、文件位置在 FAT 表里；NTFS 里<strong>一个文件就是一条 MFT 记录，记录里的属性字段各司其职</strong>——属性把「名字、数据、时间、安全」全部内聚在一起。</span>

## 1 NTFS 卷的布局

一个 NTFS 卷从前往后依次是：

**引导扇区（Boot Sector）**：第一个扇区，含 NTFS 的 BPB 参数与 \$MFT 起始位置。NTFS 的引导扇区还有一个特殊能力——**\$Boot 文件**本身就是一条 MFT 记录，引导扇区与 MFT 记录互相引用。

**&#36;MFT（Master File Table，主文件表）**：NTFS 的中枢。它本身也是一个文件，存放着卷上**每一个文件（包括它自己）的一条记录**。<span class="marginnote">\$MFT 记录一条 1024 字节（1 KB）。记录 0 是 \$MFT 自己，记录 1 是 \\$MFTMirr（\$MFT 前几项的镜像备份），记录 2 是 \$LogFile（日志），记录 3 是 \$Volume（卷信息），记录 4 是 \$AttrDef，记录 5 是根目录「\」，之后才是用户文件。恢复 NTFS，第一步永远是定位 \$MFT。</span>

**\\$MFTMirr**：\$MFT 开头部分（通常前 4 条记录）的镜像。\$MFT 自身损坏时用它救急。

**\$LogFile**：日志文件，记录文件系统事务，用于崩溃后的一致性恢复。它也是数据恢复的「线索档案」——被删文件的信息可能残留其中。

**数据区**：其余空间，存文件内容与非系统元数据。

## 2 MFT 记录与属性模型

每条 MFT 记录是一份定长（通常 1024 字节）的结构，核心部分包括：

**记录头**：标志（是否为 `FILE` 记录）、记录号、使用状态等。
**属性列表**：一串「属性头 + 属性内容」，按属性类型排列。

关键属性（属性类型编号）有：

| 属性 | 类型号 | 内容 |
| --- | --- | --- |
| \$STANDARD_INFORMATION | 0x10 | 时间戳、属性标志 |
| \$FILE_NAME | 0x30 | 文件名（可含长名），父目录引用 |
| $SECURITY_DESCRIPTOR | 0x50 | 访问控制（ACL） |
| \$DATA | 0x80 | 文件内容数据 |
| $INDEX_ROOT / $INDEX_ALLOCATION | 0x90/0xA0 | 目录索引（B+ 树） |

**常驻属性（resident）与非常驻属性（non-resident）**：若数据小（如几十字的短文本），\$DATA 直接内嵌在 MFT 记录里，叫**常驻**——读文件都不用去数据区。若数据大，\$DATA 变成「运行列表（runlist）」——记录「数据占用了哪些簇」，即文件的散装地图。<span class="marginnote">常驻属性是 NTFS 恢复的一大福利：<strong>小文件的正文就住在 MFT 记录里</strong>，即使数据区被覆盖，只要 MFT 记录还在，内容就还在。恢复工具对常驻数据可直接提取。但注意：\$FILE_NAME 属性被更新（如改名）后旧值可能丢失，恢复时优先取时间戳最合理的那条。</span>

## 3 目录：B+ 树索引

NTFS 目录不像 FAT 那样是一长串固定目录项，而是用 **B+ 树**组织子项。每个目录项含文件名、MFT 记录号、时间戳等。

目录索引分布在 $INDEX_ROOT 与 $INDEX_ALLOCATION 中：小目录的索引驻留在 MFT 记录的 $INDEX_ROOT 里；目录一大，索引就溢出到 $INDEX_ALLOCATION 指向的索引缓冲区（index buffer），$INDEX_ROOT 只保留 B+ 树的根。

恢复意义：**目录损坏不一定影响文件本身**。目录 B+ 树断了，文件的数据仍在其 MFT 记录里——恢复工具常靠**全盘扫描 MFT 记录**重建目录结构，而不是依赖原目录索引。

## 4 删除机制与恢复原理

NTFS 删除文件的本质动作比 FAT 更「温和」：

**只改 MFT 记录头**：把记录的使用状态标志改成「未使用」，记录内容、数据 runlist、文件数据全部原样保留。文件的目录项被移除，但 MFT 记录里的 \$FILE_NAME 与 \$DATA runlist 都还在。<span class="marginnote">NTFS 删除的另一个好帮手是 <strong>\$Bitmap</strong>（空闲簇位图）与 <strong>\$LogFile</strong>。被删文件的 runlist 里记录的簇会重新标记为空闲，但只要还没被新文件占用，数据就在。<strong>关机后别开机、开机后别写入</strong>，仍然是最高原则。</span>

所以 NTFS 误删恢复的标准做法是：**定位 \$MFT → 扫描未使用记录 → 从 \$FILE_NAME 认出文件 → 沿 \$DATA runlist 提取数据**。删得越久、写入越多，runlist 里被覆盖的簇越多，可恢复比例越低。

## 5 核心要点：NTFS 关键系统文件速查表

| 系统文件 | MFT 记录 | 作用 | 恢复用途 |
| --- | --- | --- | --- |
| \$MFT | 0 | 全卷文件的主表 | 恢复的总入口 |
| \\$MFTMirr | 1 | \$MFT 开头镜像 | \$MFT 损坏时救急 |
| \$LogFile | 2 | 事务日志 | 找回删除痕迹 |
| \$Volume | 3 | 卷信息/序列号 | 校验卷身份 |
| \$Bitmap | 6 | 空闲簇位图 | 判断哪些簇未占用 |
| \$Boot | 7 | 引导扇区对应文件 | 重建引导区 |

## 6 术语速查表

| 术语 | 含义 | 恢复意义 |
| --- | --- | --- |
| \$MFT | 主文件表，全卷文件记录集中地 | NTFS 恢复的总入口 |
| MFT 记录 | 一个文件一条，通常 1 KB | 记录号定位文件 |
| \$FILE_NAME | 文件名属性 | 找回被删文件名 |
| \$DATA | 数据属性 | 常驻/非常驻 |
| 常驻属性 | 小数据内嵌在记录里 | 数据区被覆盖也不怕 |
| runlist | 非常驻数据的簇分布表 | 沿它提取全部数据 |
| B+ 树索引 | 目录的组织结构 | 目录坏不影响文件 |
| \\$MFTMirr | \$MFT 前几条的镜像 | 损坏时救急 |
| \$LogFile | 事务日志 | 删除痕迹档案 |
| \$Bitmap | 空闲簇位图 | 判断簇是否可用 |
| 删除标记 | 把记录标为未使用 | 数据原样保留 |

## 7 快速自查清单

做 NTFS 恢复时，按这份清单把握主线：

- 是否先**定位 \$MFT**，而不是直接在数据区找文件？
- \$MFT 开头损坏时，是否用 **\\$MFTMirr** 修复？
- 是否区分**常驻属性**（数据内嵌）与**非常驻属性**（runlist）？
- 目录（B+ 树）损坏时，是否转而**扫描 MFT 记录**重建？
- 误删恢复是否沿 **\$DATA runlist** 提取数据？
- 是否用 **\$LogFile / \$Bitmap** 找删除痕迹或判断簇可用性？
- 提取前是否先**只读镜像**？

## 8 小结

- NTFS 卷核心是 **\$MFT**：一个文件一条记录，记录按**属性**组织。
- \$DATA 属性**常驻**则内容内嵌记录，**非常驻**则以 runlist 指向数据簇。
- 目录用 **B+ 树**索引，目录损坏不影响文件数据本身。
- NTFS 删除**只标记 MFT 记录为未使用**，记录与数据原样保留。
