## 为什么从文件系统基础开始

前一篇我们走到了「盘面有扇区」这一层。但操作系统用户不直接面对扇区，他们面对的是**文件**。把「扇区」变成「文件」，中间隔着文件系统。逻辑层数据恢复的全部工作，本质是**读懂文件系统、修复文件系统、绕过文件系统**——所以文件系统原理是逻辑层恢复的地基。这一节先建立全局：磁盘逻辑结构怎么分层、文件系统在里面扮演什么角色、为什么「删了还能找回」。

<span class="marginnote">整个存储层次可以这样记：<strong>物理扇区（盘）→ 逻辑块（LBA）→ 分区 → 卷 → 文件系统 → 文件</strong>。恢复时从最外层（文件）往最内层（扇区）逐层剥。</span>

## 1 磁盘逻辑结构的层次

把「数据在哪」这件事从抽象到具体排成一条链：

**CHS 寻址（柱面-磁头-扇区）**：老式寻址，用柱面号、磁头号、扇区号定位物理位置。现代盘内部物理布局已不对外暴露，CHS 更多是历史概念。

**LBA（Logical Block Address）**：把整块盘看成一条**连续编号的逻辑块序列**，从 0 开始编号，每块通常对应一个扇区（512 B 或 4 KB）。操作系统和固件打交道用的是 LBA，不再关心物理位置。<span class="marginnote">LBA 是「把复杂物理世界抽象成一条直线」的经典思想：固件负责把 LBA 翻译成真实盘面位置，对上层完全隐藏。上层只关心「第 N 块」，不关心「这块在哪个磁道」——这正是地址翻译的价值，也解释了固件翻译表损坏为什么会让整个盘失联。</span>

**分区（partition）**：把 LBA 空间切成若干段，每段是一个分区。分区表（MBR/GPT）记录每段的起止位置与类型，见本专题《MBR 主引导记录与分区表》。

**卷（volume）**：操作系统眼中「一个有文件系统的存储空间」，通常与分区一一对应，也可以由多个分区拼成（如跨区卷、RAID 卷）。

**文件系统（file system）**：在卷上建立「文件名 → 数据块」的映射，并管理空闲空间。

## 2 文件系统在做什么

文件系统本质上回答四个问题：

**如何组织目录**：把文件名与目录结构记录下来，形成一棵树。目录是「文件」的一种，内容是「子项名称 + 子项索引」的列表。

**如何分配空间**：把卷划分成固定大小的**簇/块（cluster/block）**，文件占整数个簇。簇是文件系统分配空间的最小单位。

**如何记录文件位置**：每个文件有一份「地图」，说明它的数据占了哪些簇——这就是**索引**。FAT 用文件分配表，NTFS 用 MFT 记录，详见后面两节。

**如何维护元数据**：记录文件大小、时间戳、权限、属性等「关于数据的数据」——**元数据（metadata）**。

<span class="marginnote">关键区分：<strong>元数据 vs 数据</strong>。文件系统把信息分成「地址簿/属性」（元数据）与「正文」（数据）。误删恢复的核心洞察就是：删文件常常只删元数据，数据正文还留在簇里——所以能找回。格式化也类似，重写的是元数据区域。</span>

## 3 文件存储的完整链条

以写入一个文件为例，看文件系统的分工：

**第一步，找空间**：文件系统查空闲簇位图，找到足够连续的空簇。

**第二步，写数据**：把文件内容写入这些簇，并记录「文件占用了簇 100–105」。

**第三步，记元数据**：新建目录项，写上文件名、大小、时间、首簇号；更新空闲空间记录。

**第四步，建索引**：把「文件 → 簇链」的关系写入索引结构（FAT 表项或 MFT 记录）。

读取文件时反向执行：按目录项找到首簇，沿索引链拿到全部簇，拼出完整数据。

## 4 公式解析：LBA 与 CHS 的换算

虽然现代盘对上层隐藏了物理几何，但老盘、镜像分析、某些固件操作仍需要换算。LBA 与 CHS 的关系是：

$$
\text{LBA} = (C \times H_{\text{max}} + H) \times S_{\text{max}} + (S - 1)
$$

逐步拆解：

- **$C$（柱面）、$H$（磁头）、$S$（扇区）**：老式寻址的三元组。注意扇区号 $S$ 从 1 开始，其余从 0 开始。
- **$H_{\text{max}}$（每柱面磁头数）、$S_{\text{max}}$（每磁道扇区数）**：几何参数。
- **换算逻辑**：先算出「这个位置之前共有多少个完整柱面」（$C \times H_{\text{max}}$ 个磁头行），每个柱面含 $H_{\text{max}} \times S_{\text{max}}$ 个扇区；再加上当前柱面内、当前磁头前的完整磁道（$H \times S_{\text{max}}$）；最后加当前磁道内第 $S-1$ 个扇区（扇区号从 1 计，减 1 转成从 0 计）。

反方向换算就是已知 LBA 求 (C, H, S)：

$$
S = (\text{LBA} \bmod S_{\text{max}}) + 1, \qquad H = \left\lfloor \text{LBA} / S_{\text{max}} \right\rfloor \bmod H_{\text{max}}, \qquad C = \left\lfloor \text{LBA} / (S_{\text{max}} \times H_{\text{max}}) \right\rfloor
$$

这段公式的实际意义：**在镜像文件里用十六进制编辑器导航时，能随时在「LBA 偏移」与「柱面/磁头/扇区」之间互相换算**，定位引导扇区、分区表等关键位置。<span class="marginnote">很多恢复教材的旧案例用 CHS 描述分区，因为老 MBR 分区表里就存着 CHS 字段（每磁道扇区数、每柱面磁头数、起始/结束 CHS）。现代盘用 LBA 为主，CHS 字段多为兼容占位——读分区表时优先看 LBA 字段。</span>

## 7 快速自查清单

建立文件系统基础时，用这份清单检验概念是否牢固：

- 能否说出存储层次：**物理扇区 → LBA → 分区 → 卷 → 文件系统 → 文件**？
- 是否分清 **CHS 与 LBA**，理解 LBA 的抽象价值？
- 是否理解文件系统负责的**四件事**（目录、分配、索引、元数据）？
- 是否明白**元数据 vs 数据**的区别，以及误删丢的是什么？
- 能否用 LBA↔CHS 公式在镜像里手工导航？
- 是否知道「有索引，碎片不是问题」的含义？
- 是否理解「数据 = 元数据 + 数据正文」的恢复视角？

## 8 小结

- 存储层次是 **物理扇区 → LBA → 分区 → 卷 → 文件系统 → 文件**。
- 文件系统负责**目录组织、空间分配、位置索引、元数据维护**四件事。
- **误删只是丢了元数据，数据正文常在**——这是逻辑层恢复的根本依据。
- LBA 把复杂物理位置抽象成连续编号，固件负责翻译。
- CHS→LBA 换算用于老盘与镜像手工导航：$\text{LBA} = (C \times H_{\text{max}} + H) \times S_{\text{max}} + (S-1)$
