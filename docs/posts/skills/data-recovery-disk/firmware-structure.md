## 为什么从固件开始

上一节修好了电路板，但有些盘「板是好的、电是通的、盘却不认」——问题出在**固件（firmware）**。固件是硬盘主控里运行的程序与数据模块，它管理寻道、读写、缓存、缺陷表，并对外报告「我是什么盘、多大容量」。固件损坏的典型症状：**不认盘、容量异常、型号错乱、反复复位**。这一篇讲清固件的结构、它存在哪里、为什么会坏，以及「重定位」这类固件级处理手段。

<span class="marginnote">固件在数据恢复里的位置很特殊：<strong>盘片上的用户数据还完好，但固件模块坏了，操作系统连「这是一块正常盘」都认不出来</strong>。修好固件，数据往往就「重见天日」——所以固件恢复是「数据没丢却读不出来」场景的主力手段。</span>

## 1 固件存在哪里

固件不是存在电路板的 ROM 里那么简单，而是**分散在多个位置**：

**ROM / SPI 闪存（电路板上）**：存放**初始引导代码**——加电后最先执行的微程序，负责把固件主体从盘片加载到内存。ROM 损坏，盘完全无法启动。

**固件区（盘片上的保留区）**：盘片内侧有一段**用户不可见的保留区**（service area / SA），存放固件主体模块——翻译表、缺陷表（P-list/G-list）、固件版本模块、盘体适配参数等。这部分不参与用户容量，普通工具读不到。

**主控缓存（DRAM）**：固件加载后运行于内存中的副本。

**关键认识**：固件区在盘片上，而 ROM 只有引导代码——所以**换电路板时，ROM 里的引导代码必须与原盘匹配**（上一节讲的「保 ROM」），否则新板不知道怎么去盘片固件区加载适配模块。<span class="marginnote">ROM 与固件区的分工：<strong>ROM 是「开机钥匙」，固件区是「完整说明书」</strong>。钥匙对了，主控才会去盘片上的固件区读说明书；说明书（固件模块）损坏，就要用专业工具修复或从模块备份重写。</span>

## 2 固件的组成模块

固件区里不是一块「整体」，而是若干**模块（module）**，各司其职：

**引导模块**：从 ROM 加载后运行，读取并初始化其他模块。

**固件版本模块**：记录固件版本号，用于校验与升级。

**翻译表（Translator）**：把逻辑地址（LBA）翻译成物理位置（CHS/物理扇区）。这是恢复的核心——翻译表损坏，用户数据明明在盘上，却「找不到」。

**缺陷表（P-list / G-list）**：记录出厂与新增坏道（见《固件级坏道处理与缺陷表维护》）。

**盘体适配参数模块**：序列号、型号、容量配置、磁头参数——每块盘各有一套，与盘体物理特征绑定。

**SMART 模块**：健康统计数据的存储区。

**日志模块**：记录盘的自检与错误日志。

**模块损坏的典型症状**：翻译表坏 → 容量/寻址异常；版本模块坏 → 不认盘；适配参数坏 → 容量错乱；SMART 模块坏 → 健康数据全 0 或错误。

## 3 固件为什么会坏

**固件区坏道**：固件区本身也在盘片上，也会长坏道。固件模块所在扇区坏掉，模块读不出来。

**异常断电**：写入固件模块时断电，模块写了一半，损坏。

**固件 bug**：厂商固件自身缺陷，可能在特定操作下崩溃。

**ROM 损坏**：引导代码所在芯片损坏或内容被清。

**病毒 / 恶意操作**：针对固件区的恶意程序。

**老化**：闪存芯片（ROM）电荷泄漏、主控退化。

**重要认知**：固件损坏不等于用户数据损坏——用户数据在数据区，固件在保留区。**固件坏了，数据还在，只是读不出来**。这正是固件恢复「性价比高」的原因。

## 4 固件修复与重定位

固件级修复需要专业工具（PC-3000 为主），核心手段：

**读模块 / 备份固件**：加电后若能进入「终端模式」，先读出固件模块备份——**有备份才有修复的底牌**。

**修复损坏模块**：对坏掉的模块，从同型号盘的固件备份里提取对应模块，写入修复。部分模块（如版本模块、SMART）可通用替换；**翻译表与缺陷表必须与盘体匹配**。

**重定位（relocation）**：当固件区某些扇区损坏时，把固件模块**重新定位到保留区的健康位置**，并更新引导参数——这就是「重定位」一词的由来。让固件绕过坏区继续工作。

**ROM 重写**：ROM 内容损坏时，写入匹配型号的 ROM 内容（引导代码），使主控能重新加载固件。

**模块重建**：翻译表损坏且无备份时，用专业工具扫描重建翻译关系——复杂且高风险。

**修复的前提**：磁头与盘片必须健康——磁头坏了，固件区也读不出来。**先保物理，再修固件**。<span class="marginnote">固件恢复的铁律：<strong>先备份、再动手、能不动就不动</strong>。固件模块之间相互引用，乱写一个模块可能引发连锁损坏——专业工具的意义不仅是「能写」，更是「知道该写什么、不该写什么」。家庭用户最好的做法是「识别出这是固件问题」，然后把盘交给专业工具处理。</span>

## 5 核心要点：固件模块 × 损坏症状 × 修复手段对照表

| 模块 | 损坏症状 | 修复手段 |
| --- | --- | --- |
| 引导代码（ROM） | 完全无法加电启动 | 写 ROM 内容 |
| 版本模块 | 不认盘/版本错乱 | 从同型号备份替换 |
| 翻译表 | 容量/寻址异常 | 重定位/重建 |
| 缺陷表 | 坏道处理失效 | 重读/重建 |
| 适配参数 | 容量错乱 | 从原 ROM/备份恢复 |
| SMART 模块 | 健康数据异常 | 重置/替换 |

## 7 公式解析：固件损坏的可恢复性判断

固件损坏是否「数据还在」，取决于损坏是否波及数据区。粗略判断：

$$
R_{\text{user-data}} = \frac{C_{\text{user}} - C_{\text{affected}}}{C_{\text{user}}}
$$

逐步拆解：

- **$C_{\text{user}}$（用户数据区容量）**：用户分区/文件所在区域。
- **$C_{\text{affected}}$（被损坏波及的用户数据）**：固件问题连带损坏的数据区部分（通常极少——固件区在保留区，与用户区物理分离）。
- **$R_{\text{user-data}}$（用户数据完好率）**：只要 $C_{\text{affected}} \approx 0$，用户数据基本完好——固件修复后即可访问。

这就是「固件坏了 ≠ 数据丢了」的数学表达：固件区与用户数据区物理隔离，固件修复只是「让访问通路恢复」。

## 8 快速自查清单

遇到「不认盘」但疑似固件问题，按这份清单判断：

- 是否**先排除电路板**（供电、保险丝、换板保 ROM）？
- 是否确认**磁头/盘片健康**（固件修复的前提）？
- 是否意识到这是**固件问题**（不认盘/容量错乱/反复复位）？
- 是否**有固件备份**或能读终端模式？
- 是否避免**乱写模块**引发连锁损坏？
- 是否把固件操作交给**专业工具**（PC-3000）处理？

## 9 小结

- 固件分散在 **ROM（引导代码）与盘片固件区（主体模块）**，损坏症状多样。
- 核心模块：**翻译表、缺陷表、版本模块、适配参数**——各管一摊，各坏各的症状。
- 固件损坏不等于数据损坏——固件区与用户数据区**物理隔离**。
- 修复手段：**备份模块 → 替换修复 → 重定位 → ROM 重写**，先保物理再修固件。
- 固件操作风险高，**家庭用户识别问题、专业工具动手**是最优分工。
