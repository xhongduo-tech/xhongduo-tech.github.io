## 为什么从 MBR 开始

一块装了操作系统的盘，电脑开机后第一个读的不是系统，而是盘上**第 0 号扇区**——主引导记录（MBR）。它同时干两件事：**指明去哪找操作系统**，以及**用分区表记录整个盘怎么切分**。MBR 是分区层的「户口本」，也是误删分区、分区表损坏后首先要修的东西。这一节把 MBR 的结构与引导流程拆开，为下一节对比 GPT 做准备。

<span class="marginnote">现代新盘多用 GPT，但 MBR 仍是<strong>兼容性与老系统</strong>的基础，也是 U 盘、老 Windows、部分 Linux 工具的默认。恢复工作必须两者都熟——很多「分区丢失」正是 MBR 与 GPT 互相误认造成的。</span>

## 1 MBR 的物理位置与整体结构

MBR 固定在**硬盘 0 号逻辑扇区（LBA 0）**，大小 512 字节，由三部分组成：

**引导代码（前 446 字节）**：一段机器码，开机时由 BIOS 读入内存执行，它的职责是找到活动分区、把控制权交给该分区的引导扇区（PBR/DBR）。这段代码本身与数据无关，损坏会导致「无法启动」但不丢数据。

**分区表（紧接的 64 字节）**：4 个分区表项，每项 16 字节，记录每个分区的起止位置、类型、状态。这是 MBR 恢复的核心。<span class="marginnote">64 字节 ÷ 16 字节/项 = 恰好 4 个主分区。<strong>为什么是 4 个？</strong> 这是 1980 年代设计时拍板的，受当时 512 字节扇区布局限制。要突破，就得用「扩展分区」技巧或改用 GPT。</span>

**结束签名（最后 2 字节）**：固定值 `0x55AA`，表示「这是一个有效的 MBR」。读 MBR 时先验这个签名——签名不对，说明 MBR 被破坏或根本不是 MBR。

## 2 分区表项详解

每个 16 字节的分区表项，字段如下：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 1 | 引导标志 | `0x80` 表示活动（可引导）分区 |
| 1–3 | 3 | 起始 CHS | 起始柱面/磁头/扇区 |
| 4 | 1 | 分区类型 | 如 `0x07`=NTFS，`0x0C`=FAT32 |
| 5–7 | 3 | 结束 CHS | 结束柱面/磁头/扇区 |
| 8–11 | 4 | 起始 LBA | 分区起始扇区号 |
| 12–15 | 4 | 扇区数 | 分区占用的扇区总数 |

**恢复的黄金字段是「起始 LBA」与「扇区数」**：它们用 LBA 精确描述分区范围，不依赖 CHS 的几何换算。CHS 字段在现代盘上往往只是兼容占位。

**主分区 / 扩展分区 / 逻辑分区**：4 个表项里若不够用，可以把其中一个设成**扩展分区（类型 0x05/0x0F）**，它本身只是一个「容器」，内部再划分成若干**逻辑分区**——逻辑分区的分区表藏在扩展分区内部的**扩展引导记录（EBR）**里。逻辑分区之间用 EBR 链表串联。<span class="marginnote">链式结构是恢复的麻烦点：<strong>MBR 只记录主分区，逻辑分区要沿着 EBR 链逐个找</strong>。一旦链上某个 EBR 损坏，后续逻辑分区全部「失踪」。这也是「分区丢了但数据还在」的常见来源——重建 EBR 链即可找回。</span>

## 3 引导流程：BIOS → MBR → PBR

理解引导流程，才知道「启动不了」坏在哪一环：

**BIOS 自检** → 按启动顺序找到硬盘 → **读 LBA 0 的 MBR** → 校验 `0x55AA` → 执行引导代码 → 引导代码找**活动分区** → 读该分区的**引导扇区（PBR/DBR）** → 交棒给操作系统加载器 → 启动系统。

于是「无法启动」的排查思路清晰了：MBR 引导代码损坏 → 修 MBR；活动分区标志错 → 改分区表；PBR 损坏 → 重建引导扇区；引导扇区里的引导文件丢失 → 修系统文件。**每一环坏的症状不同，恢复手段也不同。**

## 4 公式解析：分区表项的 LBA 换算

分区表项里的起始 LBA 与扇区数是**小端序（little-endian）**的 4 字节整数。十六进制编辑器里看到的原始字节要这样换算：

$$
\text{LBA}_{\text{start}} = b_0 + b_1 \times 256 + b_2 \times 256^2 + b_3 \times 256^3
$$

逐步拆解：

- **$b_0, b_1, b_2, b_3$**：表项偏移 8–11 的四个字节，**低字节在前**（小端序）。例如读到 `00 20 00 00`，则 LBA = 0x00002000 = 8192。
- **扇区号 × 每扇区字节数 = 字节偏移**：要转成镜像文件的字节偏移，再乘扇区大小：$\text{offset} = \text{LBA} \times B_{\text{sector}}$。
- **换算的应用**：手工验证分区表——算出分区起始偏移后，跳到该偏移查看是否真的存在文件系统引导扇区（如 NTFS 的 `NTFS    ` 签名、FAT 的 BPB），来确认分区表项是否可信。<span class="marginnote">这是恢复师的「验算」习惯：<strong>表项说这里有分区，就跳过去看有没有引导扇区签名</strong>。签名对上了才敢按这个表项去挂载——签名对不上，说明分区表项被改错或分区已被重建。</span>

## 5 核心要点：MBR 常见故障与修复手段

| 症状 | 故障点 | 修复手段 |
| --- | --- | --- |
| 开机黑屏/无法引导 | MBR 引导代码损坏 | 重写引导代码（`bootrec /fixmbr` 类） |
| 找不到活动分区 | 分区表引导标志丢失 | 恢复活动标志 0x80 |
| 分区整体消失 | 分区表项被清零/覆盖 | 扫描分区签名重建表项 |
| 扩展分区里的逻辑分区丢失 | EBR 链断裂 | 沿链重建 EBR |
| 显示未格式化 | PBR/DBR 损坏 | 重建引导扇区 |

## 6 术语速查表

| 术语 | 含义 | 恢复意义 |
| --- | --- | --- |
| MBR | 主引导记录，LBA 0 的扇区 | 引导 + 分区表 |
| 引导代码 | MBR 前 446 字节程序 | 损坏 → 无法引导 |
| 分区表 | 64 字节的 4 个表项 | 恢复的核心对象 |
| 结束签名 | 0x55AA 有效性标记 | 签名不对 → MBR 坏 |
| 活动分区 | 引导标志为 0x80 的分区 | 引导代码找它 |
| 扩展分区 | 4 分区不够时的容器 | 内含逻辑分区 |
| EBR | 扩展引导记录 | 逻辑分区表 |
| 起始 LBA | 分区起始扇区号 | 恢复黄金字段 |
| 扇区数 | 分区占用扇区总数 | 与起始 LBA 定范围 |
| PBR/DBR | 分区引导扇区 | 引导流程下一环 |

## 7 快速自查清单

修复 MBR 分区问题时，按这份清单逐步验证：

- 是否先校验 **0x55AA 签名**，确认这是有效的 MBR？
- 分区表项是否**优先读 LBA 字段**，而不是 CHS 字段？
- 逻辑分区丢失时，是否检查 **EBR 链**是否断裂？
- 动手前是否**备份原始 MBR 扇区**？
- 填完表项后，是否**跳转到起始 LBA 验证文件系统签名**？
- 引导失败是否按 **BIOS → MBR → PBR → 系统** 逐环排查？
- 是否避免在「初始化磁盘」提示上直接点确认？

## 8 小结

- MBR 位于 **LBA 0**，由**引导代码（446 B）+ 分区表（64 B）+ 签名 0x55AA（2 B）**组成。
- 4 个主分区项各 16 字节，**起始 LBA 与扇区数是黄金字段**；不够用靠扩展分区 + 逻辑分区。
- 引导流程是 **BIOS → MBR → 活动分区 PBR → 系统加载器**，逐环排查「无法启动」。
- LBA 字段小端序换算：$\text{LBA} = b_0 + b_1\cdot256 + b_2\cdot256^2 + b_3\cdot256^3$。
- 4 分区不够用就靠**扩展分区 + 逻辑分区**，逻辑分区沿 EBR 链串联，断链会「失踪」。
- 修复铁律：**先镜像、写回前备份、写回后验算**——用「表项指向的位置真有文件系统签名」来证明表项正确。

- MBR 与引导流程的关系是「牵一发而动全身」：**任何一环坏，症状不同、修复手段也不同**——逐环排查是唯一可靠的路径。

- 收束一句话：**MBR 是「盘 → 分区」的户口本，逐环排查、先镜像、后写回**。
