## 为什么从 FAT 开始

FAT（File Allocation Table，文件分配表）诞生于 1977 年，历经 FAT12/16/32 三代，至今仍是 U 盘、SD 卡的默认文件系统。对数据恢复来说，FAT 的意义在于**它足够简单、足够透明**——整个结构几乎可以手工解析。学会 FAT，你就拿到了「文件系统怎么记录数据」的第一张完整图纸；后面学 NTFS、APFS 时，FAT 会成为你对比例尺。

<span class="marginnote">FAT 家族的血缘：<strong>FAT12</strong>（软盘，簇号 12 位）、<strong>FAT16</strong>（老硬盘）、<strong>FAT32</strong>（U 盘与老 Windows）、<strong>exFAT</strong>（大容量 U 盘/SDXC）。FAT12/16/32 结构同源，exFAT 是重构版，另见本专题《其他文件系统》。</span>

## 1 FAT 卷的整体布局

一个 FAT 卷（分区）从逻辑上按顺序排成几块：

**引导扇区（DBR）**：卷的第一个扇区，包含 **BPB（BIOS Parameter Block）**——记录卷的关键参数：每扇区字节数、每簇扇区数、保留扇区数、FAT 表个数、每 FAT 表扇区数、根目录项数（FAT16）、每簇大小等。恢复时读这里，就知道整个卷怎么划分。

**保留区**：引导扇区之后、FAT 表之前的一小段，通常只有几个扇区。

**FAT 表（一般两份）**：核心索引结构，下面专门讲。

**数据区**：真正存放文件内容的地方，从「簇 2」开始编号。<span class="marginnote">注意数据区第一个簇是 <strong>2 号簇</strong>，不是 0 号。0 号与 1 号簇被保留，FAT 表里对应位置存放介质类型描述等特殊值。所以「首簇号 2」就意味着数据区最开头。</span>

## 2 簇与 FAT 表的簇链

文件系统把数据区切成等大的**簇**。FAT 表的精髓是：**每个簇在 FAT 表里占一项，项的值指出「下一个簇是谁」**，由此形成一条**簇链（cluster chain）**。

例如文件占簇 4、5、6、7：FAT 表第 4 项写 5，第 5 项写 6，第 6 项写 7，第 7 项写「文件结束」（EOF，值为 0x0FFFFFFF）。读文件时从目录项里的「首簇号 4」出发，沿链把 4→5→6→7 全部取出，拼成完整文件。<span class="marginnote">簇链就是「文件的散装地图」：文件不一定连续存放，可以东一块西一块，但 FAT 表把碎片串成一条链。链上任何一项损坏，后面所有簇都「断链」——所以恢复时既要找回首簇，也要尽量重建整条链。</span>

FAT 表项的值有几类特殊含义：

| 值（FAT32） | 含义 |
| --- | --- |
| 0x00000000 | 空闲簇 |
| 0x00000002–0x0FFFFFF6 | 指向下一个簇 |
| 0x0FFFFFF7 | 坏簇标记 |
| 0x0FFFFFF8–0x0FFFFFFF | 文件结束（EOF） |

## 3 目录项与删除机制

目录（包括根目录与子目录）在 FAT 里就是一个特殊文件，内容是**目录项（directory entry）**的数组。FAT32 的每个目录项占 **32 字节**，短文件名格式如下：

**0–7**：主文件名（8 字符）
**8–10**：扩展名（3 字符）
- **11**：属性字节（只读/隐藏/系统/卷标/目录/归档）
- **12–21**：保留、创建时间等
- **26–27**：首簇号高 16 位
- **20–21**：首簇号低 16 位
- **28–31**：文件大小（4 字节）

**删除机制的钥匙**：删除文件时，FAT 不抹数据，只做两件事——把目录项**首字节改成 0xE5**（标记「已删除」），并释放 FAT 表中该文件的簇链（表项清零）。数据簇原封不动。<span class="marginnote">0xE5 就是恢复的入口：扫描目录区，凡是首字节为 0xE5 的目录项，都是「被删但数据可能还在」的痕迹。恢复软件做的第一件事往往就是找回这些 E5 项，读它的首簇号，沿簇链把数据重新拼出来。不过簇链可能已被新文件复用部分——所以「删除后立刻停止写入」那么重要。</span>

**长文件名（VFAT）**：FAT 天生只有 8.3 短名。Windows 用「长文件名目录项 + 短名目录项」成组存储长名，长名目录项用 0x0F 属性标记、按序号逆序排列。恢复时若只恢复短名项而忽略长名项，文件名会变成 `XXXX~1.EXT` 之类——细节决定体验。

## 4 公式解析：FAT 表大小与容量

恢复时经常要手动定位 FAT 表位置、判断簇大小是否合理，核心公式是容量与 FAT 表大小的关系：

$$
N_{\text{clusters}} = \frac{C_{\text{data}}}{S_{\text{cluster}}} = \frac{(L_{\text{end}} - L_{\text{start}} + 1) \times B_{\text{sector}}}{B_{\text{sector}} \times S_{\text{sector-per-cluster}}}
$$

实际估算时常用更直接的形式——数据区总扇区数除以每簇扇区数：

$$
N_{\text{clusters}} = \frac{S_{\text{data}}}{S_{\text{spc}}} ,\qquad \text{FAT 表扇区数} = \left\lceil \frac{N_{\text{clusters}} \times W_{\text{entry}}}{B_{\text{sector}}} \right\rceil
$$

逐步拆解：

- **$S_{\text{data}}$（数据区扇区数）**：卷总扇区数减去保留区与 FAT 表占用的扇区。
- **$S_{\text{spc}}$（每簇扇区数）**：BPB 里的 `BPB_SecPerClus`，如 1、8、64 等，必须为 2 的幂。
- **$W_{\text{entry}}$（表项字节宽）**：FAT12 用 1.5 字节、FAT16 用 2 字节、FAT32 用 4 字节——这决定了 FAT 表能管理的最大簇数与最大容量。
- **向上取整 $\lceil \cdot \rceil$**：FAT 表占用的扇区数必须取整，因为扇区是分配单位。

这套换算的实战意义：**用 BPB 参数就能算出每份 FAT 表的起始扇区与大小，进而手工检查两份 FAT 表是否一致、FAT 表是否被破坏**——FAT 恢复中最常见的手法之一，就是用第二份 FAT 表修复第一份。

## 5 核心要点：FAT 恢复的三个典型手法

| 场景 | 做法 | 依据 |
| --- | --- | --- |
| 误删文件 | 扫描目录项中的 0xE5 项，沿簇链拼数据 | 删除只改首字节与释放簇链 |
| FAT 表损坏 | 用第二份 FAT 表覆盖第一份，或按空闲簇重建 | FAT 卷通常存两份表 |
| 引导扇区损坏 | 用 BPB 参数重建 DBR | BPB 决定整个卷布局 |

## 6 术语速查表

| 术语 | 含义 | 恢复意义 |
| --- | --- | --- |
| FAT | 文件分配表 | 簇链索引 |
| BPB | 卷参数块 | 决定整个卷布局 |
| 保留区 | 引导扇区后的一段 | 通常很小 |
| 数据区 | 存放文件内容 | 从簇 2 开始 |
| 簇 | 分配最小单位 | 文件占整数簇 |
| 簇链 | 文件各簇的指针链 | 沿链提取数据 |
| 目录项 | 32 字节的文件记录 | 0xE5 标记删除 |
| 0xE5 | 已删除标记 | 恢复的入口 |
| VFAT | 长文件名机制 | 逆序排列的 0x0F 项 |
| EOF 标记 | 簇链结尾值 | 0x0FFFFFFF |
| 双 FAT | 卷通常存两份表 | 副本覆盖修复 |

## 7 快速自查清单

做 FAT 恢复时，按这份清单验证每一步：

- 是否先读 **BPB**，确认每扇区字节数、每簇扇区数等布局参数？
- FAT 表损坏时，是否**用第二份 FAT 表**覆盖第一份？
- 误删恢复是否扫描**0xE5 标记**的目录项？
- 长文件名是否处理 **VFAT 项**（0x0F 属性）？
- 是否用簇数公式验证 FAT 表大小与容量合理？
- 是否沿簇链完整提取，遇到断链是否尝试重建？
- 数据区从簇 2 开始，是否在换算时注意这个偏移？

## 8 小结

- FAT 卷布局：**引导扇区（BPB）→ 保留区 → FAT 表（两份）→ 数据区**，数据区从簇 2 开始。
- **FAT 表 = 簇链索引**：表项写「下一个簇」，链尾写 EOF。
- 删除只做两件事：**目录项首字节置 0xE5 + 释放簇链**，数据簇原封不动。
- FAT32 目录项 32 字节，字段从属性到首簇号到文件大小一应俱全。
- 容量换算核心：$N_{\text{clusters}} = S_{\text{data}} / S_{\text{spc}}$，FAT 表大小 = 簇数 × 表项宽 ÷ 扇区字节数。
