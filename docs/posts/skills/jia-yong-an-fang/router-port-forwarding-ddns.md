## 为什么从端口映射开始

上一篇讲了远程访问的三条路线，其中「公网 IP + 端口映射 + DDNS」是**用户完全自控**的一条：不依赖厂商云，访问直接、可控。前提是你家有**真公网 IP**。<span class="marginnote">端口映射适合「想自己掌控一切」的用户：调试、自建服务、不信任第三方云。它比 P2P 云复杂，也把 NVR 直接暴露在公网——所以这一篇既讲「怎么开」，也讲「怎么守」。</span>这一篇把端口映射与 DDNS 的完整配置流程走一遍。

## 1 端口映射的前提：确认你有公网 IP

端口映射的第一步不是配置路由器，而是**确认宽带有公网 IP**。判断方法：

登录路由器后台，看 WAN 口（外网口）IP：若与你在网上查到的「本机公网 IP」一致，则是**真公网 IP**。
若 WAN 口 IP 是 100.64.x.x、10.x.x.x、192.168.x.x 之类的私有网段，则是**运营商内网 IP（NAT 后再 NAT）**——端口映射将无法从外网生效。<span class="marginnote">100.64.0.0/10 网段是运营商级 NAT（CGNAT）的地址段，它意味着你的宽带 IP 是运营商又包了一层 NAT——这种情况下外部连不进来。解决办法是找运营商申请公网 IP（部分宽带可申请，或换支持公网 IP 的套餐）。</span>

**辨析｜易错点：** 没有公网 IP 时，端口映射「配了也白配」。**先确认公网 IP 再折腾映射**，否则浪费大量时间；确认没有，直接走 P2P 云方案最省事。

## 2 端口映射配置：给 NVR 开一扇「公网门」

端口映射的配置动作在**路由器后台**完成。以常见的「虚拟服务器/端口转发/端口映射」功能为例：

**第一步，固定 NVR 的局域网 IP**。到 NVR 设置里把 IP 固定（如 192.168.1.200），或在路由器里做 **IP/MAC 绑定**（DHCP 静态分配），确保 NVR 的局域网 IP 永不变——否则映射规则指向的地址漂移，远程又连不上了。<span class="marginnote">「固定 IP」是端口映射成立的前提：映射规则是「公网端口 → 局域网固定地址」，局域网地址一变，规则就失效。用路由器 IP/MAC 绑定最稳妥。</span>

**第二步，查 NVR 需要映射的端口**。家用 NVR 通常需要映射几个端口：

| 端口 | 用途 |
| --- | --- |
| 8000（或厂商默认） | 私有协议/客户端接入主端口 |
| 80（或 8080） | HTTP 网页访问 |
| 554 | RTSP 流媒体取流 |
| 443 | HTTPS 安全访问 |

**第三步，在路由器添加映射规则**：服务端口 = NVR 的端口（如 8000），内部 IP = NVR 的固定局域网 IP（192.168.1.200），内部端口 = 同样端口，协议 = TCP（流媒体可加 UDP）。

**第四步，用「外网 IP + 端口」验证**：把手机切到 4G（不在家里 Wi-Fi），访问 `公网IP:8000`，若能连上说明映射成功。<span class="marginnote">验证必须在「离开家里 Wi-Fi」的状态下做——在局域网内用公网 IP 访问，数据包走了内网捷径，验证不出映射是否真的生效（这叫「NAT 回流」，很多路由器支持但不代表映射正确）。</span>

**辨析｜易错点：** 映射端口与**客户端实际连接的端口**必须一致。若 NVR 网页访问端口改成了 8080，映射规则里还是 80，外部访问 80 端口就失效。**改过端口就要同步改映射规则。**

## 3 DDNS 配置：给会变的 IP 一个固定的名字

公网 IP 是动态的（重启光猫、运营商定期重拨都会变）。**DDNS（Dynamic DNS，动态域名解析）** 把「域名 → 当前公网 IP」的映射交给路由器或 DDNS 服务商自动维护——你只要记一个固定域名，不用管 IP 怎么变。

**配置两种途径**：

**路由器内置 DDNS**：多数路由器支持花生壳、`no-ip`、`dyndns` 等 DDNS 服务。登录服务商注册一个域名 → 在路由器「DDNS/动态DNS」界面填入账号密码 → 路由器自动上报当前公网 IP 并更新解析。
**NVR 内置 DDNS**：部分 NVR 直接支持 DDNS 客户端，注册账号后填入 NVR 即可。

配置完成后，远程访问从 `公网IP:8000` 变成 `你的域名:8000`——IP 变了也不影响。<span class="marginnote">DDNS 解决的是「地址会变」的问题：它像一个自动更新的电话簿，把你的域名永远指向当前的最新公网 IP。注意 DDNS 只负责「域名→IP」，端口映射仍要单独配置——两者是两件独立的事。</span>

**辨析｜易错点：** **DDNS 与端口映射是两件事**——DDNS 解决「IP 会变」，端口映射解决「外部能连进 NAT」。**只配 DDNS 不配端口映射，远程照样连不上**；反之，只配映射不配 DDNS，IP 一变动画失效。家用正确组合是「**固定 IP + 端口映射 + DDNS**」三件套。

## 4 核心对比表：端口映射与 DDNS 分工（纯概念主题）

本主题是纯概念性内容，用核心对比表代替公式解析：

| 环节 | 解决的问题 | 配置位置 | 家用要点 |
| --- | --- | --- | --- |
| 固定 IP | IP 漂移 | NVR / 路由器 DHCP | IP/MAC 绑定最稳 |
| 端口映射 | NAT 阻挡 | 路由器 | 端口、协议、内部 IP 三对 |
| DDNS | 公网 IP 会变 | 路由器 / NVR | 注册域名、账号绑定 |
| 安全加固 | 公网暴露 | 路由器 / NVR | 见第4篇安全一篇 |

## 5 端口映射后的安全核查清单

开了端口映射，NVR 就暴露在公网上，**安全核查是必修课**：

| 核查项 | 要求 | 说明 |
| --- | --- | --- |
| 改默认端口 | 80/8000 改成非默认 | 避开批量扫描 |
| 强密码 | 管理员密码强度达标 | 弱密码 = 开门揖盗 |
| 禁用 guest | 关闭匿名/guest 访问 | 减少匿名入口 |
| 限源 IP | 只允许你的固定 IP 访问 | 路由器 ACL |
| 启用 HTTPS | 网页访问走加密 | 防明文截获 |
| 及时升级 | 固件保持最新 | 修补已知漏洞 |

**核心概念**：端口映射的安全铁律是「**暴露面越小越好**」——每开一个端口、每个默认配置，都是攻击面。映射开通后，把这张核查表逐项过一遍，确认全绿再正式使用。

**辨析｜易错点：** 端口映射 + P2P 云**同时开着**，等于「自己开了一条公网直连路，又用云服务兜底」——多一条路就多一个攻击面。**家用二选一**：要么 P2P 云（不开映射），要么端口映射（关 P2P 或分开用），别同时敞开。

## 6 本节自测：检验端口映射

**问题一：端口映射的前提是什么？**
宽带要有真公网 IP。WAN 口 IP 是 100.64.x.x 等私有网段时，映射配了也白配。

**问题二：为什么映射前要先固定 NVR 的 IP？**
映射规则是「公网端口 → 局域网固定地址」，局域网地址一变，规则就失效。用路由器 IP/MAC 绑定最稳。

**问题三：DDNS 解决什么问题？**
公网 IP 会变，DDNS 把「域名 → 当前公网 IP」的映射自动维护，你只要记一个固定域名。

**问题四：DDNS 与端口映射是同一件事吗？**
不是。DDNS 管「IP 会变」，端口映射管「NAT 阻挡」，两者缺一不可。

**问题五：为什么验证必须在离开家里 Wi-Fi 的状态下做？**
局域网内用公网 IP 访问走了内网捷径，验证不出映射是否真生效（NAT 回流假象）。

### 本节实践建议

走端口映射路线，按「固定 IP → 查端口 → 加规则 → 4G 验证 → 安全核查」五步走。改完端口后客户端要同步改，安全核查表逐项过一遍，确认全绿再正式使用。

## 7 小结

- 端口映射前提是**真公网 IP**：先确认 WAN 口 IP，没有就直接用 P2P 云。
- 映射流程：**固定 NVR IP → 查端口 → 路由器加规则 → 4G 下验证**。
- NVR 常用端口：**8000 客户端、80/8080 网页、554 RTSP、443 HTTPS**。
- **DDNS 管「IP 会变」，端口映射管「NAT 阻挡」，两者缺一不可**。
- 验证必须在**离开家里 Wi-Fi** 的状态下做，避免 NAT 回流假象。
