## 为什么从系统类型开始

上一篇我们画出了监控系统的五部件骨架，但同一副骨架可以穿上不同的「衣服」——**模拟、网络、高清**是三条不同的技术路线。选择哪条路线，决定了你能买什么摄像机、布什么线、花多少钱、以后好不好升级。家用装修前如果不先定路线，等线埋进墙里再后悔，改造成本就大了。<span class="marginnote">「先定制式，再谈设备」与「从极限到大模型」博客里学数学的顺序如出一辙：先确定公理体系（制式），再在其上推定理（选型）。制式选错，后面每一步都是错上加错。</span>

本专题以「网络高清」为默认主线，但你必须能一眼认出另外两条路，才谈得上判断一条路线适不适合自己。

## 1 模拟监控：电视技术的遗产

**模拟监控系统**是最早进入家庭的监控形态，其信号链路直接借用了广播电视的制式：摄像机把画面变成**模拟视频信号**，经同轴电缆传输，由 DVR 采集压缩。

它的核心技术是两套模拟制式：**PAL**（中国、欧洲等地采用，50 场/秒）与 **NTSC**（美国、日本等地采用，60 场/秒）。<span class="marginnote">模拟制式的分辨率上限被行扫描结构锁死，PAL 制下有效分辨率约 704×576，这就是模拟监控「怎么换好摄像机也上不了高清」的根本原因——瓶颈在制式本身，不在传感器。</span>模拟时代的「高清」靠的是后来出现的 **960H**、**CVI/TVI/AHD** 等改造制式，它们提高了有效扫描行数，但仍是「模拟的修修补补」。

**辨析｜易错点：** 市面上所谓「高清模拟摄像机」不是真正的网络高清。它们依然走同轴电缆、依然由 DVR 接管，只是把模拟制式的行数撑高到约 960×576 或 1280×720。**判断系统类型要看「信号形态」而不是看商品名**：只要是模拟信号 + 同轴 + DVR，就还是模拟系统。

## 2 网络监控：IP 化的全面接管

**网络监控系统（IP 监控）** 的核心变化是：**摄像机内置处理器与网络接口，输出的是 IP 数据包**，而不是模拟波形。整个链路变成「摄像机编码 → 网络传输 → NVR/平台接收」。

IP 化带来三个模拟系统做不到的能力：

**分辨率天花板消失**：画面分辨率由传感器与编码器决定，200 万、400 万、800 万像素（4K）都可实现。<span class="marginnote">分辨率「消失」的前提是编码与带宽跟得上。H.265 编码就是为了让 4K 画面在普通家用宽带与硬盘容量下「装得下」——编码效率与存储、带宽是同一枚硬币的两面。</span>

**一根网线多用**：网线可以同时传视频流、供电（PoE）与控制信令，布线成本大幅下降。模拟系统里「供电线 + 视频线」两根线，网络系统里一根网线全包。

**真正意义上的远程访问**：视频流是 IP 数据，天然可以在局域网与互联网上路由，配合 P2P 云服务，手机在任何有网的地方都能看。模拟系统的远程化需要视频服务器做「模拟→网络」转换，隔了一层。

## 3 高清监控：从「看得见」到「看得清」

**高清（HD）监控**严格来说不是与模拟、网络并列的第三种制式，而是**分辨率与编码维度上的升级**：无论走模拟改造制式还是 IP 制式，画面分辨率达到 720P 以上即算高清。

高清的核心指标是**像素数**与**编码标准**的配合：

| 名称 | 像素（约） | 常见用途 | 对应关系 |
| --- | --- | --- | --- |
| 720P | 1280×720 ≈ 92 万 | 入门高清 | 1MP 级 |
| 1080P（全高清） | 1920×1080 ≈ 207 万 | 家用主流 | 2MP 级 |
| 3MP / 4MP | 2048×1536 / 2560×1440 | 需要看清车牌、人脸细节 | 300/400 万 |
| 4K（超高清） | 3840×2160 ≈ 830 万 | 大范围、高细节 | 8MP 级 |

**核心概念**：**分辨率（resolution）** 指画面横向 × 纵向的像素数，决定画面细节；**码流（bitrate）** 指每秒钟产生的数据量，决定存储占用与带宽需求。两者靠编码标准联系：同一个分辨率下，H.265 的码流大约只有 H.264 的一半到三分之二。<span class="marginnote">「分辨率决定细节、码流决定开销」这句话请记住，它是后面「存储容量计算」与「摄像头核心参数」两篇反复使用的核心关系。</span>

**辨析｜易错点：** 「高清」不等于「画质好」。分辨率高只是「细节多」，实际画质还取决于传感器尺寸、镜头质量、夜间性能与编码码率。**400 万像素但码率被压得很低的摄像机，画面可能不如码率充足的 200 万机型。** 选型要像素与码率一起看，不能只看数字。

## 4 核心对比表：三条技术路线横向比较（纯概念主题）

本主题是纯概念性内容，用核心对比表代替公式解析：

| 维度 | 模拟监控 | 网络监控 | 高清监控 |
| --- | --- | --- | --- |
| 信号形态 | 模拟视频信号 | IP 数据包 | 模拟改造或 IP，分辨率≥720P |
| 传输介质 | 同轴电缆 | 网线 / Wi-Fi | 同轴或网线 |
| 录像设备 | DVR | NVR | DVR 或 NVR |
| 典型分辨率 | 704×576（PAL） | 最高 4K | 720P–4K |
| 远程访问 | 需视频服务器转换 | 原生支持 | 原生支持（IP 高清） |
| 布线成本 | 每路一根同轴+供电线 | 一根 PoE 网线全包 | 依制式而定 |
| 升级空间 | 低 | 高 | 高 |

阅读要点：**模拟看制式、网络看 IP 化、高清看分辨率**。三个维度并不互斥——今天家用的主流其实是「网络 + 高清」两条线的交汇，即 **IPC（网络高清摄像机）**。

## 5 小结

- 监控系统三大类型：**模拟（同轴 + DVR）、网络（IPC + NVR）、高清（分辨率≥720P）**；家用主线是「网络 + 高清」交汇的 IPC 路线。
- **判断制式看信号形态**，不看商品名——「高清模拟」仍是模拟系统。
- 网络监控的三项独特能力：**分辨率天花板消失、一根网线多用、原生远程访问**。
- 高清的核心关系：**分辨率决定细节、码流决定开销**；H.265 在同画质下码流约为 H.264 的一半。
- 高清 ≠ 画质好：像素、码率、传感器、镜头四者共同决定最终画质。
