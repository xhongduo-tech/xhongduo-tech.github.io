## 为什么从OBD开始

前两篇学完了「电控系统怎么工作」，从这一课起进入本专题的核心战场：**怎么诊断**。而现代汽车诊断的一切入口，都通向同一个法规化的系统——**OBD（车载诊断，On-Board Diagnostics）**。<span class="marginnote">OBD 不是厂商的豪华配置，而是被法律强制装上每一辆车的「排放自检报告系统」。理解它，必须先理解它是怎么被法规逼出来的。本课先讲法规、再讲技术——<strong>没有法规，就没有今天全世界统一的诊断接口与故障码格式</strong>。</span>上一课的《新能源汽车高压电控》让你看到电控时代的终点，本课则站在诊断的起点：把 OBD 的由来、使命与标准家族讲清楚，后面所有「读码、读数据流、分析波形」才有落脚的框架。

## 1 OBD 的由来：从加州到全美

20 世纪 70 年代，美国加州的空气污染严重到需要立法治理。1970 年《清洁空气法案》（Clean Air Act）授权加州空气资源委员会（CARB）制定比联邦更严的排放标准——加州自此成为全球汽车排放法规的「试验场」。

电控时代早期，排放部件坏了车照跑，车主和修理厂都未必知道。<span class="marginnote">1980 年代初，化油器车的氧传感器、三元催化器损坏后，油耗与排放悄悄恶化，却没有任何提示。CARB 意识到：<strong>必须让车辆自己「报警」</strong>，否则再严的出厂标准也管不住十年里的劣化。</span>1985 年，CARB 颁布法规要求 1988 车型年起在加州销售的车辆具备 **OBD-I**：加装**排放警示灯**与简化的故障检测，当排放部件损坏时点亮警示灯。

**OBD-I 的核心是「报灯」，OBD-II 的核心是「报码 + 可读数据」。** OBD-I 的局限很明显：各厂接口不同、检测内容杂乱、无法读取具体参数。1994 车型年起，加州强制 **OBD-II**；1996 车型年起，美国环保署（EPA）依据《清洁空气法案》把 OBD-II 推广到**全美所有轻型车**——从这一年起，全美销售的汽车都必须配备统一标准的 OBD-II 诊断系统。

## 2 OBD-II 的使命：让「排放健康」可查证

OBD-II 的法规目标可以浓缩为三句话：

**检测**：持续监测与排放相关的部件与功能是否失效（催化器、氧传感器、失火、燃油系统、蒸发系统等），在部件导致排放超标之前及时发现。

**提示**：确认故障后点亮仪表盘上的 **MIL（故障指示灯，Malfunction Indicator Lamp）**——俗称「发动机灯」。

**可查证**：通过**标准化的诊断接口与协议**，让任何合规的诊断仪都能读取故障码（DTC）、冻结帧、就绪状态与实时数据流。

<span class="marginnote">三句话合起来就是「车辆自检 + 车辆举证」。<strong>关键点：OBD 的设计动机是「让维修和年检能查证排放是否健康」</strong>，而不是「帮修理厂诊断」。理解这一点，你就明白为什么故障码与法规阈值绑定、为什么部分排放故障码清不掉——那是给监管留的「案底」。</span>

**OBD-II 是「法定功能」，不是「维修功能」。** 它只监测法规关心的排放相关项，并不覆盖全车所有故障——很多车身、舒适系统故障根本没有 OBD 故障码。

这是诊断体系里重要的边界：**OBD 之外还有厂家扩展诊断（enhanced diagnostics）**，后者才是全车系统的完整诊断手段。本专题第 3 篇以 OBD 为主，第 1–2 篇讲的传感器、执行器、各系统检修，则属厂家扩展诊断的范畴。

## 3 核心对比表：OBD-I / OBD-II / EOBD（纯概念主题）

本课是法规与体系主题，不含数值公式，改用**核心对比表**梳理三代系统的差异：

| 维度 | OBD-I | OBD-II | EOBD（欧洲） |
| --- | --- | --- | --- |
| 强制年份 | 1988（加州） | 1994 加州 / 1996 全美 | 2001 汽油车 / 2004 柴油车 |
| 核心要求 | 点亮排放警示灯 | 标准故障码 + 数据流 + 就绪监测 | 与 OBD-II 基本对齐 |
| 诊断接口 | 各厂各异 | 统一 16 针 OBD 座 | 同左（ISO 15031） |
| 故障码格式 | 无统一格式 | P0xxx 等五字符统一格式 | 与 OBD-II 互通 |
| 数据流 | 基本不可读 | 标准 PID 数据流 | 同左 |
| 代表性标准 | CARB 早期法规 | SAE J1979/J2012 + ISO 15031 | ISO 15031 / EOBD |

**重点：OBD-II 之所以「全球通行」，靠的是标准家族把接口、协议、服务、故障码全部统一。** 同一台诊断仪能插遍所有品牌的车，同一组 PID 在任何车上读转速、水温——这种「通用性」正是 OBD-II 相对 OBD-I 的本质飞跃，也是后面几课全部内容的由来。日本市场的 JOBD 亦以 ISO 15031 为基础，三者彼此兼容。

## 4 标准家族：ISO 15031 与 SAE J 系列

OBD-II 的实现由一批标准协同规定。美国汽车工程师学会（SAE）先制定了 J 系列，后被国际标准化组织（ISO）采编为 ISO 15031 系列，两者内容一一对应：

| ISO 15031 分册 | 内容 | 对应 SAE 标准 |
| --- | --- | --- |
| 15031-1 | 总则、用途与基本概念 | SAE J2405 |
| 15031-2 | 术语、定义与缩写 | SAE J1930 |
| 15031-3 | 诊断座与相关电气电路 | SAE J1962 |
| 15031-4 | 外部测试设备要求 | SAE J1978 |
| 15031-5 | 排放相关诊断服务（模式/PID） | SAE J1979 |
| 15031-6 | 诊断故障码（DTC）定义 | SAE J2012 |
| 15031-7 | 数据链路安全 | SAE J2186 |

<span class="marginnote">记住这张表的「分工口诀」：<strong>15031-3 管「插哪」、15031-5 管「问什么」、15031-6 管「答案怎么编号」</strong>。本课对标本篇第 1 章（总则），后续几课分别深入第 5、6 分册——你手上那张 16 针诊断座就是 15031-3，读数据流的服务与 PID 就是 15031-5，故障码格式就是 15031-6。</span>

**不同年代的通信协议不同。** OBD-II 早期允许三种物理层：SAE J1850 PWM（通用）、SAE J1850 VPW（部分克莱斯勒与通用车）、ISO 9141-2（K 线，欧洲与亚洲车）。2008 年后，法规逐步强制 **CAN 总线**作为统一物理层（ISO 15765-4）。

今天的 OBD 通信几乎都是 CAN——这与你第 1 篇《车载网络与 CAN/LIN 总线》学的 CAN 是同一个东西，诊断报文只是 CAN 上的一种特殊应用。

## 5 硬件层：16 针诊断座与引脚

法规规定的 **OBD 诊断座（DLC，Data Link Connector）** 是标准 16 针接口，通常位于驾驶员侧仪表台下。熟悉常用引脚，是「插得上、读得到」的基础：

| 引脚 | 功能 |
| --- | --- |
| 1、3、8、9、11、12、13 | 厂商保留 |
| 2、10 | SAE J1850 信号（PWM/VPW） |
| 4 | 车身搭铁（底盘地） |
| 5 | 信号搭铁 |
| 6、14 | CAN-H / CAN-L（ISO 15765-4） |
| 7 | K 线（ISO 9141-2 / KWP2000） |
| 15 | L 线（早期 ISO 9141-2） |
| 16 | 蓄电池正极（常电） |

**易错点：诊断座供电不是「点火才通电」。** 引脚 16 接的是**常电**，即使拔了钥匙，诊断仪也能建立通信唤醒部分模块——但很多测试（读数据流、动作测试）仍要求点火开关处于 ON 位。遇到「诊断仪连不上」，先量引脚 16 的电压与引脚 4/5 的搭铁，再谈协议与地址问题——这一步与第 1 篇《电控系统供电与电源管理》的电源思维完全一致。

## 6 MIL 与就绪监测的法规语义

**MIL（故障指示灯）** 的亮灭规则由法规严格规定，它直接决定了「读码—修车—清码—复测」的全流程语义：

- **两行程逻辑**：排放故障须在两个连续行驶循环中均被检测到，MIL 才点亮，故障码确认为「已确认码」——滤掉偶发干扰，防止灯乱闪。
- **确认即记录**：MIL 点亮的同时，ECU 记录故障码、冻结帧与就绪状态。
- **熄灯条件**：连续三个通过监测的行程后，MIL 熄灭，但已确认码仍保留，直到用模式 04 清除。
- **清不掉的案底**：部分严重排放故障产生**永久故障码（permanent DTC）**，即使清码也不会消失，须实际修复后由 ECU 自行清除——年检时若见永久码，说明「清码作弊」无效。

**就绪监测（readiness monitors）** 是另一项法规要求：车辆须定期对催化器、氧传感器、失火、燃油、EVAP 等项目执行自检，并记录「已完成/未完成」状态。<span class="marginnote">就绪状态是年检（I/M，检修维护制度）的判断依据之一：若刚清完码去验车，就绪监测未完成，车辆会直接被判定为「未就绪」而不合格——<strong>这是法规对「清码应付年检」的专门堵漏</strong>。完整监测条件见本组第 6 课《就绪监测与排放诊断》。</span>

**重点：MIL 亮 ≠ 车要立刻大修，而是「排放健康已不合格」。** 法规的关注点是排放，但同一套硬件与数据流被维修业复用为通用诊断手段——这正是 OBD 从「法规工具」变成「维修基础设施」的原因。

**OBD 与年检（I/M 制度）：法规如何落地到车检。** 排放年检（I/M，检修维护制度）直接调用 OBD 的就绪监测与故障码——先读 OBD 数据，若有已确认排放码或就绪未完成，即判定不合格。

中国自 2019 年起在用汽油车排放检验中同步检测 OBD 数据，思路与美欧一致。清码后就绪监测立即归零，反而更容易被判「未就绪」——这就是现代法规体系下「清码应付年检」越来越行不通的原因。

本专题后续所有读码、数据流、波形分析，都建立在这套法规化的语义之上。

## 7 小结

- **OBD 是法规强制的排放自检系统**：加州 1988 年推 OBD-I，1994 年推 OBD-II，1996 年起全美强制；欧洲对应 EOBD。
- OBD-II 三大使命：**检测排放部件失效 → 点亮 MIL → 提供标准化接口供外部读取**。
- 标准家族：**ISO 15031 系列**与 SAE J 系列对应，本课对标本系列第 1 章（总则）。
- 硬件入口是 **16 针 OBD 诊断座**，现代通信几乎都是 CAN（ISO 15765-4）。
- MIL 遵循**两行程确认、三行程熄灯**的法规逻辑；永久故障码与就绪监测堵住了「清码应付年检」。
