## 为什么从失效保护开始

电子部件会老化、会坏，线路会断路、会短路——这是电子控制的「原罪」。ECU 的应对之道不是「祈祷别坏」，而是**设计好坏了之后怎么办**：检测到故障，记录它、提示它、用替代方案维持车辆安全行驶。<span class="marginnote">这一整套逻辑，就是<strong>失效保护与安全模式（fail-safe & limp-home）</strong>。它同时解释了电控维修的三个核心现象：故障码从哪来、故障灯为什么亮、车为什么「突然变肉了」。不理解失效保护逻辑，你只会「读码—清码—换件」的机械操作；理解了它，你才能从故障码反推 ECU 当时到底看到了什么。</span>本课讲清失效保护的三层内容：怎么发现故障、发现后怎么办、不同系统怎么分级响应。

## 1 故障如何被发现：四种自检

ECU 判断「信号坏了」不是靠感觉，而是靠一套内置的**自检（self-diagnostics）**规则，大体有四类：

**范围检查（range check）**：信号是否超出物理合理范围。例如冷却液温度读数 −50 °C（低于传感器量程下限）说明开路，+150 °C（超量程上限）说明短路。<span class="marginnote">范围检查是最基础的一关。<strong>易错点：</strong> 信号「在范围内」不等于「正确」——一个漂移了 30 °C 的水温读数仍在合理范围内，范围检查发现不了，要靠下面的合理性检查。</span>
**合理性检查（plausibility check）**：信号是否与其他信号互相矛盾。例如空气流量计与节气门位置、转速算出的负荷严重不一致，就判空气流量计可疑。
**电路检查（circuit check）**：对执行器回路持续监测——通电时有没有电流、关断时有没有漏电流、有没有对地/对电源短路。
- **超时检查（timeout check）**：期待某个响应（如氧传感器进入闭环、CAN 节点应答）在限时内没出现，即判异常。

**重点：ECU 的自检是「程序员预先写死的规则」，不是 AI。** 它只能发现被规则覆盖的故障。所以诊断时「没故障码」不代表「没故障」，只代表「ECU 的规则没发现异常」——信号漂移、机械卡滞这类故障常常要靠人的经验与波形分析去补位。

## 2 发现故障之后：记录、提示、替代

ECU 检测到故障后，按轻重依次执行：

1. **存储故障码（DTC）**：把故障分类编码存入内存（详细机制见第 3 篇《OBD 故障码结构与定义》）。
2. **点亮故障灯**：排放相关故障点亮**发动机故障灯（MIL）**；非排放相关故障只存码，不亮灯。
3. **启用替代值（substitute value）**：用预设值或别的传感器值「顶替」坏掉的信号，让控制策略继续运行。
4. **降级模式（limp-home）**：整机进入保守的、安全优先的控制策略，牺牲性能保安全。

以水温传感器开路为例：ECU 判定信号开路后，不再相信水温读数，改用预设的「假设水温」（如 90 °C）控制喷油与风扇——车还能开，但控制是「盲飞」的。诊断时**数据流里能看到这种替代值**，但替代值往往被标成「固定不随工况变化」，这是识破失效保护正在生效的关键线索。<span class="marginnote">常见替代策略一览：水温传感器失效 → 按冷机策略加浓、风扇常转；氧传感器失效 → 退出闭环，按开环标定喷油；爆震传感器失效 → 全局推迟点火、动力下降；节气门位置失效 → 电子油门进入受限模式，油门踩到底也只有部分开度。</span>

## 3 安全模式的分级：失效安全与失效静默

不是所有系统都用「替代值维持运行」，安全关键系统有更严格的分级：

| 级别 | 策略 | 典型系统 |
| --- | --- | --- |
| 失效—安全（fail-safe） | 失效时进入安全状态，功能降级但仍受控 | 发动机降功率、ESP 关闭但保留常规制动 |
| 失效—静默（fail-silent） | 失效时整个子系统退出，不让错误数据污染总线 | 安全气囊、自动驾驶域控制器 |
| 失效—可操作（fail-operational） | 冗余备份，单点失效功能不中断 | 线控转向、双通道制动 |

以 ABS 为例：ABS 失效时，系统会**退出 ABS 功能、点亮警告灯，但保留常规制动**——因为常规制动的液压通道仍完好，失效保护的目标是「让驾驶员还能正常刹车，只是没有防抱死」；反观安全气囊，碰撞信号若有故障，系统宁可**整条回路静默**，也绝不在错误的时刻点火。

**核心概念：降级模式的哲学是「保守」。** 失效保护永远偏向安全的一侧：不确定水温 → 假设冷机加浓（宁可费油，不可过热）；不确定爆震 → 推迟点火（宁可动力弱，不可爆震伤机）；不确定空燃比 → 开环加浓（宁可费油，不可过稀烧阀）。**理解这个「宁可」的方向，你就能预判替代值的取值方向**——诊断时对照数据流，一眼看出哪些是替代值在起作用。

## 4 公式解析：合理性检查

合理性检查是四类自检中最需要「数学」的一类，其核心是**偏差阈值**判断：

$$
|x_{\text{meas}} - x_{\text{exp}}| > \Delta_{\text{th}} \quad \Rightarrow \quad \text{判定可疑}
$$

分三步拆解：

- **第一步，看测量值 $x_{\text{meas}}$**：某传感器当前读数，例如空气流量计的输出换算出的进气量。
- **第二步，看期望值 $x_{\text{exp}}$**：ECU 用其他信号（转速、节气门、MAP）**交叉推算**出的同参数应有值。两条独立的「算进气量」的路径，是互相验证的基础。
- **第三步，看阈值 $\Delta_{\text{th}}$**：允许的偏差上限。偏差超过阈值才判故障，**小于阈值则容忍**——因为信号本来就有噪声与误差，不能一有偏差就报错。**易错点：** 阈值是标定值，随转速、负荷变化；把某个固定数字当普适标准，会误判。

合理性检查的精髓是**用冗余信号互相印证**：单一信号可能说谎，两个独立来源都指向同一结论，可信度才高。这也是为什么发动机管理常设「MAP + 节气门」「空气流量 + 转速」等多条并行信息链。

## 5 失效保护对诊断的意义

失效保护逻辑让诊断有了「反向阅读」的能力：**故障码和替代值，是 ECU 留下的案发现场记录。**

- 读故障码时想：ECU 依据哪条自检规则判定？范围、合理性、电路还是超时？这决定了要往哪个方向查。
- 看数据流时想：哪些值是真实信号，哪些是替代值？替代值「不随工况变化」的特征，能帮你识别 ECU 正在降级运行。
- 修完后想：清码后会不会复现？如果只是暂时清除、真实故障未除，替代值又会回来、灯又会亮。

<span class="marginnote">失效保护还有个实用推论：<strong>不要用「清码后暂时不亮灯」判断修好了。</strong> 清码只是把「案发现场记录」删了，ECU 的后续自检很快会重新发现故障。真正的修好，是让 ECU 在下一次自检中「找不到毛病」——所以修完要走完一个完整驾驶循环，让各监测项重新跑一遍，再确认故障码不再出现。</span>

## 6 故障确认计数与故障灯策略

故障从「第一次被发现」到「点亮故障灯」，中间是一套**计数（counter）**机制，理解它就能读懂「为什么清码后灯还会亮」：

| 阶段 | 计数状态 | 故障灯 |
| --- | --- | --- |
| 首次检测到 | 存入待定码，计数 +1 | 不亮 |
| 第二行程再次检测 | 计数达到确认阈值，升级确认码 | 点亮 |
| 连续多行程未复现 | 计数递减，达清零阈值 | 熄灭（码可能保留） |
| 40 个暖机循环未复现 | 计数清零，码被老化删除 | 熄灭 |

**重点：故障灯点亮不是「瞬间决策」，而是「计数决策」。** ECU 用计数器权衡「及时报警」与「避免误报」：偶发一次不亮，连续两次才亮；故障消失后也不是立刻灭灯，而要满足**灭灯条件**（通常是连续三个行程检测正常）——这样灯不会因一次颠簸就闪一下。<span class="marginnote"><strong>易错点：灯灭 ≠ 码清。</strong> 故障灯熄灭只代表「最近几个行程没再检出」，故障码可能仍存于内存（需要清码或老化删除）。年检、质保判定的依据是故障码与就绪状态，不是灯亮不亮。</span>

**闪烁故障灯是最紧急的信号**：失火严重到可能损坏催化器时，ECU 用**故障灯闪烁**代替常亮，提醒驾驶员立即停车——这是整车失效保护里最急的一档，读到闪烁必须优先处理（呼应第 3 篇失火监测）。

**失效保护逻辑与诊断动作的对应表**，是「读码时想什么」的速查：

| ECU 动作 | 对应诊断动作 |
| --- | --- |
| 存储故障码 | 读码后先看是哪类自检触发 |
| 使用替代值 | 数据流里识别「不随工况变化」的值 |
| 点亮故障灯 | 判断是单行程还是两行程点亮 |
| 进入降级模式 | 对照冻结帧理解降级触发条件 |
| 清除故障码 | 修后跑循环验证不复发 |
| 记录冻结帧 | 读取现场工况，确定复现方向 |
| 请求其他模块动作 | 多模块联动故障找共享根因 |
| 退出闭环 | 氧传感器失效时数据流表现为开环 |
| 限制动力 | 后处理/安全相关保护，先修根因 |

**读码的最高境界，是能从「码 + 数据流 + 替代值」里反向读出 ECU 当时的判断逻辑**——这一步跨过去，诊断就从「查表」变成了「破案」。

## 7 小结

- 失效保护 = **发现故障（自检）→ 记录提示（DTC/MIL）→ 替代值顶替 → 降级模式**。
- 自检四类：**范围、合理性、电路、超时**；「无故障码 ≠ 无故障」。
- 降级模式偏向安全侧：不确定就「宁可费油、不可伤机」；替代值通常**不随工况变化**，数据流里可识别。
- 安全模式分级：**失效—安全（降级可用）、失效—静默（整系统退出）、失效—可操作（冗余备份）**。
- 合理性检查：$|x_{\text{meas}} - x_{\text{exp}}| > \Delta_{\text{th}}$
