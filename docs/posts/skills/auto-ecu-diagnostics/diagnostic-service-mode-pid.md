## 为什么从诊断服务开始

上一课学会了「读故障码」，本课学习「读数据」。诊断仪能读到发动机转速、车速、水温、喷油脉宽、氧传感器电压……这些实时数据就是**数据流**——它是故障码之外最重要的诊断证据。<span class="marginnote">故障码告诉你「哪里可疑」，数据流告诉你「现在到底发生了什么」。很多故障没有故障码（信号漂移、机械卡滞），或故障码不够精确——这时候数据流就是唯一的判断依据。而数据流背后有一套<strong>标准化的请求—应答协议</strong>：诊断仪发一个「服务模式 + PID」的请求，ECU 回一段数据。本课把这套协议讲透。</span>

## 1 诊断服务模式：OBD 的「菜单」

ISO 15031-5 / SAE J1979 把「外部设备能对车辆做的操作」定义成一组**服务模式（service mode）**，用十六进制编号：

| 模式 | 名称 | 作用 |
| --- | --- | --- |
| 01 | 当前数据 | 读实时数据流（PID） |
| 02 | 冻结帧数据 | 读故障发生瞬间的数据快照 |
| 03 | 已存故障码 | 读已确认的故障码 |
| 04 | 清除数据 | 清故障码、冻结帧、就绪状态 |
| 06 | 在线监测结果 | 读各监测项的具体测试数值 |
| 07 | 待定故障码 | 读「检测到但未确认」的故障码 |
| 08 | 动作测试 | 远程控制执行器（如开风扇） |
| 09 | 车辆信息 | 读 VIN、标定 ID 等 |
| 0A | 永久故障码 | 读不可清除的永久故障码 |

<span class="marginnote"><strong>模式分工的记忆诀窍：</strong> 03 是「已定罪」（确认码）、07 是「嫌疑人」（待定码）、0A 是「案底」（永久码，法规规定部分排放故障清不掉）、02 是「案发现场照片」（冻结帧）、01 是「实时监控」（数据流）。把诊断服务想成办案流程，模式就不难记。</span>其中**模式 01（数据流）是使用最频繁的**，本课重点讲它，其余模式简要说明。

## 2 模式 01 与 PID 请求格式

诊断仪读一个数据项，走的是「请求—应答」两步：

1. **请求**：诊断仪发送请求，指定模式 01 和要读的 **PID（参数标识符）**。例如请求 `01 0C`，意思是「模式 01，读发动机转速（PID 0x0C）」。
2. **应答**：ECU 返回该 PID 的一个或多个数据字节，诊断仪按**换算公式**把字节翻译成物理量显示出来。

**核心概念：PID 是「数据项的编号」。** 每个可读参数（水温、转速、车速、喷油脉宽、氧传感器电压）都有标准 PID 编号，全球通用。例如 `0x05` 水温、`0x0C` 转速、`0x0D` 车速、`0x10` 空气流量、`0x11` 节气门开度。<span class="marginnote"><strong>诊断含义：</strong> 诊断仪界面上的「发动机转速」「冷却液温度」等数据，本质上都是「请求 PID → 收到字节 → 套公式」的结果。理解这一点，你就知道为什么<strong>数据流读数可能不精确</strong>——换算公式、字节截断、采样时刻都会引入误差。数据流适合看趋势与相对变化，精确判断要靠波形与量测。</span>

## 3 公式解析：转速与空气流量的换算

ECU 返回的是原始字节，物理量靠公式换算。两个最常用的换算：

$$
n = \frac{A \times 256 + B}{4} \;(\text{r/min}), \qquad
\dot{m} = \frac{A \times 256 + B}{100} \;(\text{g/s})
$$

分四步拆解：

- **第一步，看双字节拼合**：多数 PID 返回 2 个字节，高字节 $A$ 在前、低字节 $B$ 在后。拼合公式 $A \times 256 + B$ 就是把两个字节拼成一个 16 位整数（256 就是 $2^8$，一个字节 8 位）。
- **第二步，看转速换算**：转速 PID（`0x0C`）返回拼合值后**除以 4**。原因：协议规定转速以 0.25 r/min 为分辨率存储——原始值 8000 代表 2000 r/min。**易错点：** 数据流里转速「跳 4 的倍数」，就是这个分辨率导致的，不是信号抖动。
- **第三步，看流量换算**：空气流量 PID（`0x10`）返回拼合值后**除以 100**，单位 g/s，分辨率 0.01 g/s。怠速时约 2–4 g/s，全负荷可达几十 g/s。
- **第四步，看通用模式**：**每个 PID 的换算公式是标准定义的**（有的减 40、有的乘 100/255、有的除 4）——查 SAE J1979 的换算表，不要凭感觉猜。诊断仪已经内置了这些公式，但遇到「诊断仪显示值与实际差一个常数」时，就要回到换算公式去核对。

**易错点：把「请求到的原始值」当「物理量」。** 例如水温 PID（`0x05`）的换算是 $A - 40$（°C）：原始字节 130 → 90 °C。若某些诊断仪显示「−40 °C」，说明请求无应答或字节无效——不是车真的在零下 40 度，而是**通信或换算的边界情况**，此时要检查连接与协议，而不是去查加热器。

## 4 模式 03/04/07：读码与清码的完整语义

- **模式 03（读已存码）**：读出当前存储的**确认故障码**（已满足点亮条件的码）。这是「读码」的标准动作。
- **模式 07（读待定码）**：读出**待定故障码**——检测到但尚未满足「确认/点亮」条件的故障（见上一课两行程逻辑）。**待定码是早期预警**：故障还不稳定、还没亮灯，但 ECU 已经盯上了。
- **模式 04（清除数据）**：清掉故障码、冻结帧、就绪状态与部分学习值。**清码是「重置自检记录」，不是「修车」**——清码后车辆重新自检，故障若在会再次出现。<span class="marginnote"><strong>易错点：清码的连带影响。</strong> 模式 04 会同时清掉<strong>就绪监测状态与自适应学习值</strong>（如换挡学习、燃油修正）——清码后短期数据流可能「不真实」，需要跑一段路让系统重新学习。这也是「清码后立刻测排放/年检」会被判不合格的制度原因：就绪监测没完成，车辆无法自证健康。</span>

## 5 模式 06/08/09：监测结果、动作测试与车辆信息

**模式 06（在线监测结果）**：读各监测项（催化器、氧传感器、失火等）的**具体测试数值与阈值**——比故障码更细的「体检报告」。例如催化器监测会返回前后氧传感器信号的对比值，即便还没到报码的程度，也能看出「正在恶化」。技师用它做**预防性诊断**。
**模式 08（动作测试）**：诊断仪远程控制执行器——强制继电器吸合、风扇旋转、喷油器喷射、EGR 阀开闭。这是**执行器检修的标准手段**（呼应第 1 篇第 3 课），不需要拆车就能验证「执行器 + 驱动」是否正常。
**模式 09（车辆信息）**：读 **VIN（车辆识别码）**、标定 ID 等身份信息。**换 ECU 后要用它核对软件版本**，防止刷错程序。

<span class="marginnote"><strong>模式 06 的价值常被低估。</strong> 通用诊断仪上它是「OBD 监测测试结果」页面，很多维修工从不用——但它能读出「还没报码但已劣化」的早期趋势，是预防性诊断与「疑难杂症」排查的利器。配合模式 01 的数据流，模式 06 等于把 ECU 的「体检指标」全部摊开给你看。</span>

## 6 实际应用：用数据流做诊断

把模式 01 的数据流用在真实诊断上，套路很清晰。以「怠速不稳」为例：

1. **读关键 PID**：转速、水温、节气门开度、MAF、喷油脉宽、长期/短期燃油修正、氧传感器电压、点火提前角。
2. **看趋势与关系**：怠速转速是否稳定在标定值附近？燃油修正是否偏向一侧？氧传感器是否正常跳变？点火提前角是否稳定？
3. **交叉验证**：MAF 读数与节气门开度、转速是否匹配？数据矛盾点就是故障点（呼应第 1 篇失效保护的合理性检查）。
4. **复现与对比**：原地加油、踩刹车、开空调，看哪个 PID 异常随工况变化——用「控制变量」缩小范围。

**重点：数据流是「动态」的，静态看数值没有意义。** 一个 PID 的瞬时值只能说明「此刻如此」，诊断要的是「随工况的变化规律」——所以诊断时要在不同工况（怠速、加速、巡航、冷车、热车）下反复观察，找出「该变不变、不该变乱变」的异常点。

## 7 CAN 诊断的请求应答与扩展 PID

在 CAN 总线上，OBD 诊断对话走的是**固定的报文地址**，理解它有助于排查「连不上、读不到」：

| 报文 | 含义 |
| --- | --- |
| `07DF`（请求帧） | 诊断仪发向车辆的**功能寻址**请求（对所有 ECU） |
| `7E8`–`7EF`（应答帧） | 各 ECU 的**物理寻址**应答 |
| `7DF` 应答例外 | 功能请求时各 ECU 依次应答 |

**核心概念：功能寻址 vs 物理寻址。** 诊断仪用功能寻址（`07DF`）问「谁有故障码」，各 ECU 用各自的物理地址应答；读特定模块数据时则直接物理寻址该模块。**这就是「读整车码」与「读单模块数据」在报文层面的区别**——诊断仪界面上的差异，底层是寻址方式的不同。

**扩展 PID（enhanced PID）**：标准 PID（0x00–0xFF 中已定义的）之外，厂家可自定义扩展 PID 读取内部数据（如喷油脉宽精确值、涡轮压力、氧传感器细节）。**易错点：** 扩展 PID 不通用——同一 PID 号在不同品牌含义可能不同，且通用诊断仪不一定支持。遇到「诊断仪读不到某参数」，先确认它是标准 PID 还是扩展 PID。

**诊断服务模式的「维修场景」对照**，让模式不再只是菜单：

| 维修场景 | 用到的模式 |
| --- | --- |
| 快速体检 | 01 数据流 + 03 读码 |
| 偶发故障 | 02 冻结帧 + 07 待定码 |
| 执行器验证 | 08 动作测试 |
| 换 ECU 核对 | 09 车辆信息 |
| 年检准备 | 06 监测结果 + 就绪 |

**模式选择跟着诊断目标走**：先想「我要证明什么」，再选「哪个模式能证明」——模式是工具，目标是诊断。

## 8 小结

- 诊断服务模式是 OBD 的**功能菜单**：01 数据流、02 冻结帧、03/07/0A 读码、04 清码、06 监测结果、08 动作测试、09 车辆信息。
- 读数据流 = **请求模式 01 + PID → 收到字节 → 按标准公式换算**。
- 转速 PID 换算 $n = (A\cdot256+B)/4$，空气流量 $= (A\cdot256+B)/100$，水温 $= A-40$
- 模式选择跟着诊断目标走：先想「要证明什么」，再选「哪个模式能证明」。
- 功能寻址 vs 物理寻址：读整车码用功能寻址 `07DF`，读单模块数据用物理寻址。
