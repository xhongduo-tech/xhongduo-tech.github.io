## 为什么从 NAT 开始

前面几篇反复提到「一个公网 IP 全家共享」，这个「共享」的机制，就是 **NAT（网络地址转换，Network Address Translation）**。它是家庭网络里**最核心也最容易被误解**的一环：它让几十台设备共用一个公网地址上网，也让「外网无法直接访问内网设备」成了默认状态——直到你用端口映射打开一扇门。

理解 NAT 的收益很大：你会在「为什么外网打不开家里的 NAS」「为什么游戏联机显示 NAT 类型严格」「为什么需要内网穿透」这些问题上一下子通透。这一篇从原理讲到配置，最后落到端口映射。

## 1 为什么需要 NAT

IPv4 地址只有约 43 亿个，而全球设备早已超过百亿——**地址不够用**。解决办法之一，是让大量设备共用少数公网 IP。家庭场景的做法是：

- 运营商只给你**一个公网 IP**（挂在光猫或路由器的 WAN 口）。
- 家里所有设备用 `192.168.x.x` 私有地址。
- 出网时，路由器把每个数据包的「内网地址」改写成「公网地址」，并记录在案；回程时再改回来。

**NAT（网络地址转换）**：在数据包穿越网关时，改写其源或目的 IP 地址（以及端口）的机制。<span class="marginnote">NAT 诞生的直接动机是缓解 IPv4 枯竭，但它意外成了一个「安全边界」——内网设备默认不可被外网直接访问，这层「隐藏」是家庭网络的第一道防线。</span>

**辨析｜易错点：**NAT 不是路由器「可选的附加功能」，而是**家庭上网的必经之路**。只要你的路由器 WAN 口是公网 IP、LAN 口是私有网段，数据出网就必然经过 NAT 改写。IPv6 时代 NAT 不再是必须（地址足够多），但家用 IPv6 部署尚未完全普及。

## 2 NAT 的工作原理：一张会话表

NAT 工作的核心，是路由器里一张**连接跟踪表（conntrack / NAT 表）**。以手机访问外网服务器为例：

1. 手机（`192.168.1.5:52340`）向服务器（`93.184.216.34:80`）发请求。
2. 路由器在出网时把**源地址**改写成自己的公网 IP（`203.0.113.8:52340`），并记一条表项：`内网 192.168.1.5:52340 ↔ 公网 203.0.113.8:52340`。
3. 服务器回包，目的地址是 `203.0.113.8:52340`，回到路由器。
4. 路由器查表，把**目的地址**改写回 `192.168.1.5:52340`，转发给手机。

**重点：NAT 是靠「改写地址 + 记表 + 查表回改」完成双向通信的。** 方向很重要——**出站改写源地址（SNAT），入站改写目的地址（DNAT）**。这张表有超时时间，连接结束或超时后表项删除。<span class="marginnote">这个「记表-查表」的模式，是整个 NAT 体系的精髓：没有表项，回程数据就没法找到内网设备——这正是外网无法主动访问内网的根本原因。</span>

## 3 NAT 的类型：家庭用的是 NAPT

NAT 有几种形式，家庭最常见的是最后一种：

| 类型 | 机制 | 场景 |
| --- | --- | --- |
| **静态 NAT** | 一个内网 IP 固定对应一个公网 IP | 企业、服务器 |
| **动态 NAT** | 从公网地址池里临时分配 | 地址池大于内网需求 |
| **NAPT / PAT** | 多个内网 IP 复用同一个公网 IP，用**端口号区分** | **家庭路由器** |

**NAPT（端口地址转换，Network Address Port Translation）**：家用路由器的默认模式。它把「公网 IP + 端口」当成「房间号」，一个公网 IP 上可以同时挂几万条连接，每条连接用不同端口号区分。

**公式解析：一条连接靠「四元组」唯一标识**

路由器区分「谁是谁」靠的是四个要素——这就是数据包的「身份证号」：

$$
\text{连接标识} = (\text{源 IP},\ \text{源端口},\ \text{目的 IP},\ \text{目的端口})
$$

分三步拆解：

- **第一步，看源端（IP, 端口）**：两台内网设备可能源 IP 不同，或源端口不同，NAT 表据此区分。
- **第二步，看目的端**：同一设备访问不同服务器，目的 (IP, 端口) 不同，也构成不同连接。
- **第三步，组合直觉**：四元组中的任何一项不同，就是一条新连接。这就是为什么**一个公网 IP 能支撑成千上万台内网设备同时上网**——端口号提供了 65536 个「槽位」，配合连接表动态复用。

## 4 端口映射：给外网开一扇门

**端口映射（port forwarding）**：在路由器上手动配置一条规则，把「公网 IP 的某个端口」的所有入站流量，转发到「内网某台设备的某端口」。它本质是一条**静态 DNAT 规则**。

配置三个要素：

- **外部端口**：外网访问时用的端口（如 8080）。
- **内网 IP**：目标设备的私有地址（如 `192.168.1.10`）。
- **内部端口**：目标设备上的服务端口（如 80）。

例如：把公网 `8080` 转发到内网 `192.168.1.10:80`，外网用户访问 `公网IP:8080`，就到达了你家里 NAS 的网页界面。

**典型应用场景**：远程访问家里的 NAS、查看监控摄像头、搭建游戏服务器、自建网站。<span class="marginnote">端口映射成功的两个前提：一是路由器 WAN 口拿到的是<strong>公网 IP</strong>（运营商如果是 CGNAT 大内网，公网 IP 其实是假的，映射无效）；二是目标设备 IP 固定（用 DHCP 静态保留，见《DNS 与 DHCP 服务机制》一篇）。</span>

**辨析｜易错点：**「映射配了还是连不上」的排查顺序：① 目标设备的 IP 是否变了（先做静态保留）；② 路由器 WAN 口是否真的是公网 IP（打电话给运营商确认）；③ 内网先测试 `内网IP:端口` 通不通（确认服务本身活着）；④ 防火墙是否拦截入站。**绝大多数「映射不生效」，都栽在前两步。**

### NAT 类型与游戏联机

游戏玩家经常在联机设置里看到「NAT 类型：开放 / 中等 / 严格」，这直接关系能不能顺畅联机。NAT 的「严格程度」本质是**路由器对入站连接的处理策略**：

- **开放（Full Cone）**：任何外网地址都能通过该端口访问内网——联机最顺畅，但暴露面最大。
- **中等（Restricted Cone / 端口受限）**：只放行「内网设备主动联系过的外网地址」的后续流量——家用最常见，游戏基本可用。
- **严格（Symmetric）**：每次连接都换端口，P2P 联机最难穿透——打联机游戏最容易报错。

**提升 NAT 类型的常用手段**：开 UPnP（让游戏机自动申请端口映射）、为主机做 DMZ/端口映射、或开启路由器的「游戏/NAT 增强」功能。**辨析：**「NAT 类型越开放越好」——对游戏是，对安全不是；用「只给游戏主机开 UPnP/映射」的方式，比全局开放更稳妥。

## 5 端口映射、UPnP 与 DMZ

除了手动端口映射，还有两个相关的机制：

**UPnP（通用即插即用，Universal Plug and Play）**：让内网应用**自动**向路由器申请端口映射，无需手动配置。游戏机、P2P 下载、语音软件常依赖它。**但它也是双刃剑**：恶意软件可借 UPnP 自行开放端口，所以不少安全建议是「不用就关」。

**DMZ（隔离区，Demilitarized Zone）**：把一台内网设备的**所有端口**全部暴露到公网（本质是「全量端口映射」）。它配置简单，但等于把该设备完全置于公网之下，**安全性最差**。能用端口映射就别用 DMZ。

| 机制 | 开放范围 | 安全性 | 适用 |
| --- | --- | --- | --- |
| 端口映射 | 指定端口 | 较高 | 只暴露需要的服务 |
| UPnP | 应用自申请 | 中 | 游戏/下载 |
| DMZ | 全部端口 | 低 | 极少数特殊场景 |

**重点：能精准映射，就不开全量。** 家庭安全的原则永远是「最小暴露面」——只开放必须开放的那个端口，其余一概关闭。

## 6 小结

- **NAT** 是「一个公网 IP 全家共享」的机制，靠**改写地址 + 连接跟踪表**完成双向通信。
- 出站改写源地址（SNAT），入站改写目的地址（DNAT）；无表项则外网无法主动访问内网。
- 家庭用的是 **NAPT/PAT**：用**端口号复用**公网 IP；连接由**四元组**唯一标识。
- **端口映射**是一条静态 DNAT 规则，把公网端口指向内网设备，前提是**公网 IP + 静态 IP**。
- 三种「开门」方式按安全性排序：**端口映射 > UPnP > DMZ**，坚持最小暴露面。
