## 为什么从转发原理开始

上一篇认识了交换机与路由器「各看各的地址」，但**它们内部到底怎么转发？** 这一篇把两台设备拆开来看：交换机凭什么知道帧该从哪个口出去？路由器凭什么决定数据包走哪条路？

这两台设备是家庭网络（乃至整个互联网）的中枢。理解它们的工作原理，意义远超「考试」：路由器后台里那些让人眼花缭乱的路由表、DHCP 分配、MAC 过滤，本质上都是「转发决策规则」的配置界面。会配置的前提是会判断——而判断的依据，正是转发原理。

## 1 交换机的转发原理：学习、泛洪、转发

交换机在数据链路层工作，它转发的依据是**MAC 地址表**。这张表不是人工配置的，而是交换机**自己学出来的**。它的工作循环只有四步：

**第一步，学习（learning）**：交换机收到一帧，先看**源 MAC 地址**，把「这个 MAC 来自哪个端口」记进 MAC 地址表，并记录时间戳。<span class="marginnote">学习机制让交换机「即插即用」：不需要任何配置，设备一连上，交换机就开始记地址。家用路由器内置的交换功能也完全一样。</span>

**第二步，查找（forwarding）**：再看帧头的**目的 MAC 地址**，去 MAC 地址表里查该从哪个端口出去。

**第三步，决定**：查到了 → 只往那个端口转发（单播）；查不到 → 往除源端口外**所有端口泛洪（flooding）**，让目标设备自己回应。广播帧（目的 MAC 全 F）永远泛洪。

**第四步，老化（aging）**：MAC 地址表条目有时间限制（通常 300 秒），设备长时间不通信，条目就过期删除，防止表被死地址撑满。

**辨析｜易错点：**「交换机是广播的，路由器是智能的」——这句话对也不对。交换机**用泛洪解决未知目标**，但一旦学会地址，就精准转发、不会向无关端口广播；路由器的「智能」体现在按 IP 前缀选路，而不是「不广播」。两者是**不同层的寻址方式**，不是「笨/聪明」的区别。

## 2 路由器的转发原理：路由表与最长前缀匹配

路由器在网络层工作，它转发的依据是**路由表（routing table）**。路由表里每一行是一条**路由**，指明「去往某个网段的数据，交给哪个下一跳」。

一条典型路由长这样：

| 目标网段 | 掩码 | 下一跳 / 出接口 | 来源 |
| --- | --- | --- | --- |
| 192.168.1.0 | /24 | 接口 LAN | 直连路由 |
| 192.168.2.0 | /24 | 192.168.1.2 | 静态路由 |
| 0.0.0.0 | /0 | 光猫 WAN | 默认路由 |

路由器收到一个数据包，做**最长前缀匹配（longest prefix match）**：在所有「能匹配上」的路由里，选**前缀最长（最具体）**的那一条。

**默认路由（default route）**：`0.0.0.0/0`，它匹配一切地址，是「最后兜底」的路由——家庭路由器发往公网的数据都走它。内网精确路由匹配不到的，一律交给默认路由上网。这正是「路由选择 = 先精确后兜底」的直觉。

**逐跳转发（hop-by-hop）**：路由器只负责把数据包送到**下一跳**，并不负责全程。每个数据包每经过一台路由器，就重新做一次「最长前缀匹配」决定下一跳。互联网上的一个数据包要经过十几台路由器，每一台都只「看一步」，合起来却把包送到了地球另一边。<span class="marginnote">逐跳转发是互联网能「零配置全局可达」的根本原因：没有任何一台设备需要知道全网的完整拓扑，每台只需要知道「下一步交给谁」。</span>

## 3 核心对比：二层转发与三层转发

交换机（二层）与路由器（三层）的转发，是两种完全不同的「寻路哲学」：

| 对比维度 | 交换机（二层） | 路由器（三层） |
| --- | --- | --- |
| 看的地址 | MAC 地址 | IP 地址 |
| 转发依据 | MAC 地址表 | 路由表 |
| 表如何建立 | 自动学习 | 直连 + 静态配置 + 动态协议 |
| 转发单位 | 帧（frame） | 数据包（packet） |
| 是否跨越网段 | 否，仅同网段 | 是，连接不同网段 |
| 广播域 | 不隔离 | 隔离 |
| 速度 | 快（硬件查表） | 稍慢（还要解包看 IP） |

**重点：家用路由器「既当路由器又当交换机」。** 它内部有一个三层路由模块（做 NAT、路由、上网）和一个二层交换模块（就是背后那几个 LAN 口）。数据在本网段内走交换模块，出网才走路由模块——这解释了为什么「内网互传不占外网带宽」。

## 4 公式解析：路由度量（OSPF 开销）

当路由表里有多条路能到同一个目标网段时，路由器怎么选「最好」的那条？答案是**度量值（metric）**——越小越优。不同的动态路由协议用不同的度量，这里看最常见的 **OSPF 开销（cost）**：

$$
\text{cost} = \frac{10^8}{\text{链路带宽（bit/s）}}
$$

代入常见速率：

- **100 Mbps 链路**：$\text{cost} = 10^8 / 10^8 = 1$
- **10 Mbps 链路**：$\text{cost} = 10^8 / 10^7 = 10$
- **1 Gbps 链路**：$\text{cost} = 10^8 / 10^9 = 0.1 \rightarrow$ 取整为 1

分三步拆解：

- **第一步，理解基准**：`10^8` 是「参考带宽」（100 Mbps），代表 OSPF 把百兆当作标准参照。
- **第二步，相除**：带宽越大，开销越小——千兆的开销是 1，十兆的开销是 10，所以路由器会**优先走更快的链路**。
- **第三步，累加**：一条完整路径的开销是沿途各段链路开销之和，路由器选总和最小的一条。

**直觉：路由选路本质是「选一条总成本最小的路」**，成本和带宽挂钩；这也解释了为什么家里多路由器组网时，让数据优先走千兆有线、而不是无线中继——后者开销大。

## 5 ARP：把 IP 翻译成 MAC

路由器和交换机一个看 IP、一个看 MAC，那数据从三层落到二层时，**IP 怎么变成 MAC？** 靠 **ARP（地址解析协议，Address Resolution Protocol）**。

过程只有四步：

1. 主机想发数据给 `192.168.1.10`，但不知道它的 MAC。
2. 主机在局域网里广播一条 ARP 请求：「谁是 `192.168.1.10`？请告诉我你的 MAC。」
3. 目标主机收到后，单播回复：「我是 `192.168.1.10`，我的 MAC 是 `aa:bb:cc:dd:ee:ff`。」
4. 请求方把「IP → MAC」的对应记进 **ARP 缓存**，下次直接用。

<span class="marginnote">ARP 是故障排查的高频对象：`arp -a` 能看本机缓存，ARP 缓存过期或不匹配会导致「能 ping 通 IP 却访问不了服务」的怪问题——这在第4篇《常见家庭网络故障诊断》会专门讲。</span>

**辨析｜易错点：**ARP 是**局域网内的协议，只在同一网段生效**。跨网段通信时，数据包里的目的 IP 是最终目标，但帧的目的 MAC 却是**下一跳路由器**的 MAC——「IP 始终是最终地址，MAC 每跳都变」，这是「封装」思想在链路层的具体体现。

### 交换机的两种转发模式

交换机收到一帧后，「什么时候转发」有讲究，主流有两种模式：

**直通转发（cut-through）**：读到帧头里的目的 MAC 就开始转发，不等整帧收完——延迟最低（微秒级），但不检测错误帧。
**存储转发（store-and-forward）**：收完整帧、校验通过才转发——延迟稍高，但能丢弃错误帧，稳定性更好。

**家用路由器内置的交换芯片基本都是存储转发**，无需纠结设置；但理解这个区别，能帮你读懂数据中心网络「低延迟选直通、高可靠选存储」的设计取舍。

## 6 小结

- **交换机**转发四步曲：**学习源 MAC → 查找目的 MAC → 精准转发或泛洪 → 老化表项**。
- **路由器**按**路由表 + 最长前缀匹配**转发，`0.0.0.0/0` 默认路由兜底；**逐跳转发**让全网无需任何设备知道完整拓扑。
- 二层转发看 MAC、不跨网段、不隔离广播；三层转发看 IP、跨网段、隔离广播。
- 路由度量 **cost = 10^8 / 带宽**，选「总成本最小」的路径；OSPF 优先走高速链路。
- **ARP** 负责 IP→MAC 翻译，只在局域网内生效；跨网段时帧的 MAC 每跳更换，IP 始终不变。
