## 为什么从分层开始

上一篇我们认识了家庭网络的设备，但设备之间到底靠什么「对话」？答案是**协议（protocol）**——一套双方共同遵守的、格式固定的语言规则。而现代网络把「对话」这件复杂的事，拆成了**一层叠一层的分工体系**，这就是网络分层。

分层是整个网络世界最重要的设计思想，没有之一。你今天刷视频、跑大模型，数据在毫秒级穿过你家的路由器、运营商的骨干网、云服务商的数据中心，中间涉及成百上千种设备与标准——如果所有逻辑揉在一起，任何一家厂商都没法独立升级，任何一台新设备都没法即插即用。分层让每一层只需「管好自己的事、对上层承诺一种能力、对下层使用一种服务」。<span class="marginnote">这种「关注点分离」与软件工程里的模块化、操作系统里的分层内核一脉相承——在第三级《操作系统》你会看到同样的思想，在 AI 领域，大模型的「数据层 / 训练层 / 推理层 / 应用层」也是分层的翻版。</span>

## 1 分层的思想：从一封信说起

想象你要给远方的朋友寄一封信。这件事可以拆成好几层：

**内容层**：你想说什么（信息本身）。
**信函层**：把话写成信，装进信封，写清收件人姓名。
- **运输层**：邮局把信封分拣、装上卡车、送到对方城市的邮局。
- **物理层**：卡车在公路上行驶。

你只需要管「内容层」，不需要知道卡车走哪条路；邮局不需要知道你写了什么。这就是分层：**每一层都只依赖下一层提供的服务，并向上层屏蔽实现细节**。

网络把同样的道理放大了无数倍。两台设备要通信，双方的对等层之间「看起来在直接对话」，实际上每一层都只是把数据交给相邻下层处理——这种抽象的建立，正是网络分层最核心的机制。

## 2 OSI 七层模型

**OSI 参考模型（Open Systems Interconnection）**：国际标准化组织（ISO）为网络通信定义的一个七层概念模型，从下到上依次是：

**物理层（Layer 1）**：传输原始比特流，定义电压、线缆、接口、速率等物理特性。对应我们家里的网线、光猫的光信号、WiFi 的无线电波。
**数据链路层（Layer 2）**：把比特组装成**帧（frame）**，通过 **MAC 地址**在同一个网段内寻址，负责差错检测与介质访问控制。对应交换机。
**网络层（Layer 3）**：把帧里的数据封装成**数据包（packet）**，通过 **IP 地址**跨越不同网段寻址与路由，负责「走哪条路」。对应路由器。
**传输层（Layer 4）**：负责端到端通信，用**端口号**区分同一台主机上的不同应用，提供可靠的 TCP 或高效的 UDP。对应操作系统里的协议栈。
**会话层（Layer 5）**：建立、管理、终止会话。
**表示层（Layer 6）**：数据格式转换、加密、压缩，让不同系统的数据「长得一样」。
**应用层（Layer 7）**：直接面向用户的网络应用与协议，如 HTTP、DNS、DHCP。

**辨析｜易错点：**OSI 模型是「参考模型」，现实中几乎没人逐层实现它；真正统治互联网的是下一节要讲的 TCP/IP 模型。OSI 的价值在于**教学与标准化**——它把「分层」这个概念讲得最清楚，所以考试与教材都从它讲起。<span class="marginnote">记忆口诀「All People Seem To Need Data Processing」对应第 7 层到第 1 层；中文常记「应、表、会、传、网、数、物」自上而下。</span>

## 3 TCP/IP 四层模型与封装

**TCP/IP 协议族（TCP/IP suite）**：支撑互联网运转的**实际**协议集合，它把 OSI 七层压缩为四层：

| TCP/IP 分层 | 大致对应 OSI 层 | 核心协议举例 | 对应设备 |
| --- | --- | --- | --- |
| **应用层** | 5–7 层 | HTTP、HTTPS、DNS、DHCP、SMTP | 终端应用 |
| **传输层** | 4 层 | TCP、UDP | 操作系统协议栈 |
| **网络层** | 3 层 | IP、ICMP、IGMP | 路由器 |
| **链路层** | 1–2 层 | 以太网、WiFi、ARP | 交换机、网卡 |

TCP/IP 模型比 OSI 更贴合现实：会话与表示的功能被并入应用层（由具体应用各自实现），物理层并入链路层。

### 封装与解封装

数据从应用层向下传递时，每一层都要给数据**加一个「信封」——协议头（header）**，这个逐层加头的过程叫作**封装（encapsulation）**；对端设备从下往上逐层「拆信封」，叫作**解封装（decapsulation）**。

$$
\text{应用数据} \xrightarrow{\text{+TCP头}} \text{报文段} \xrightarrow{\text{+IP头}} \text{数据报} \xrightarrow{\text{+帧头尾}} \text{帧} \xrightarrow{\text{比特}} \text{线缆}
$$

每一层只认识自己那一层「信封」上的地址：链路层认 **MAC 地址**，网络层认 **IP 地址**，传输层认 **端口号**。<span class="marginnote">「TCP 头 + IP 头 + 帧头」每一层都占用几十字节的额外开销，这就是上一篇文章里「实际速率永远低于理论值」的深层原因——协议开销真实存在。</span>

## 4 核心对比：分层模型与设备、协议的一张表

把「分层、设备、协议、数据单位」四样东西钉进同一张表，是理解整个网络体系的捷径：

| 层级 | 数据单位 | 寻址依据 | 关键协议 | 工作设备 |
| --- | --- | --- | --- | --- |
| 应用层 | 消息（message） | 域名 / 应用逻辑 | HTTP、DNS、DHCP、SMTP | 终端应用 |
| 传输层 | 报文段（segment） | 端口号 | TCP、UDP | 操作系统 |
| 网络层 | 数据报（packet） | IP 地址 | IP、ICMP、IGMP | 路由器 |
| 链路层 | 帧（frame） | MAC 地址 | 以太网、WiFi、ARP | 交换机、网卡 |

**这张表值得背下来**：问「某协议属于哪一层」、问「某设备看哪一层地址」、问「某数据单位叫什么」，都能在这张表里找到答案。整篇家庭组网的后续内容，都会频繁引用这四行。

## 5 传输层的主角：TCP 与 UDP

分层模型里离用户最近、也最影响体验的选择，发生在**传输层**：数据到底用 TCP 还是 UDP 送？

**TCP（Transmission Control Protocol）**：面向连接、可靠的传输协议。它先「三次握手」建立连接，发送后等对方确认，丢包自动重传，数据按序到达。代价是慢、开销大。<span class="marginnote">「三次握手」是 TCP 建立连接的过程：客户端发 SYN → 服务器回 SYN+ACK → 客户端回 ACK，双方确认「你能听到我、我也能听到你」，才正式开传。抓包工具里最常见的三条记录就是它。</span>

**UDP（User Datagram Protocol）**：无连接、不可靠但极快的传输协议。它不握手、不确认、不重传，发出去了就不管。代价是可能丢包乱序，但延迟低、开销小。

**辨析｜易错点：**「UDP 一定比 TCP 好」是常见误解。正确姿势是**按场景选**：

| 场景 | 推荐协议 | 原因 |
| --- | --- | --- |
| 网页、文件下载、邮件 | TCP | 必须完整、有序 |
| 视频通话、在线游戏 | UDP（或 QUIC） | 宁可丢一帧，不可卡半秒 |
| DNS 查询 | UDP | 一问一答，快即可 |
| 大模型 API 调用 | TCP | 请求-响应必须可靠 |

**连接的本质是「可靠性换取速度」**：需要完整 → 用 TCP；需要实时 → 用 UDP。这个选择题在后面的 QoS 与故障排查里会反复出现。

### 端到端原则：分层思想的一条「宪法」

网络分层里有一条著名的**端到端原则（end-to-end principle）**：尽量把「智能」放在通信的端点（用户设备），让中间的转发设备保持简单。它的直接推论是——**网络中间只负责尽力转发，可靠性由两端负责**（TCP 就是端点负责可靠的例子）。

这条原则解释了家庭网络里的很多现象：路由器不关心你传的是视频还是文字（只按 IP 转发）；加密由两端完成（HTTPS 的证书与密钥都在端点）；中间设备被攻破不等于数据被解密。**理解端到端原则，你就理解了「为什么分层让互联网如此强韧」**——因为任何一段坏了，两端都能自适应重传或绕路。

## 6 小结

- 网络分层是「**关注点分离**」思想的体现：每一层只依赖下层服务，并向上层屏蔽细节。
- **OSI 七层模型**（物、数、网、传、会、表、应）是参考模型，教学价值高；**TCP/IP 四层模型**（链路、网络、传输、应用）才是互联网的现实。
- 数据发送时逐层**封装加头**，接收时逐层**解封装拆头**；链路层认 MAC、网络层认 IP、传输层认端口。
- 核心对比表：**数据单位、寻址依据、关键协议、工作设备**一一对应，是整个网络体系的速查表。
- **TCP 面向连接可靠但慢，UDP 无连接快但可能丢包**；按场景选，不按好坏选。
- 分层的最大收益是**独立演进**：任意一层技术升级（链路层从百兆到万兆、应用层不断出新协议）都不影响其他层，互联网因此能持续进化五十年。
