## 为什么从排查思路开始

网络总会出问题，而**排查能力才是家庭组网真正的分水岭**：同样面对「上不了网」，会排查的人十分钟定位，不会的人只能重启路由器碰运气。这一篇先建立**方法论**（思路比工具重要），再系统认识**常用工具**（每件工具查哪一层），最后用一个完整案例把思路串起来。

它是第4篇的「总纲」，下一篇《常见家庭网络故障诊断与解决》是它的「病例集」——先学会诊断方法，再看典型病例。

## 1 排查的总体思路：分层定位

网络是分层的（《TCP/IP 协议体系与网络分层》），所以排查的第一原则是：**按层定位，从上到下或从下到上逐层排除。**

**经典的分层排查法**，从最底层开始：

1. **物理层**：网线插紧了吗？光猫/路由器指示灯正常吗？WiFi 信号有吗？
2. **链路层**：能连上路由器吗？（WiFi 关联成功、能拿到 IP？）
3. **网络层**：能 `ping` 通网关吗？能 `ping` 通公网 IP 吗？
4. **传输/应用层**：能解析域名吗？目标服务的端口通吗？应用本身正常吗？

**重点：每一层排查都能回答一个明确的问题。** 「ping 不通网关」说明问题在内网链路/物理层；「网关通、公网 IP 不通」说明问题在外网/运营商；「公网 IP 通、域名不通」说明问题在 DNS。**哪一层断了，就在哪一层修**——这是排查的最高纲领。

**第二个原则：隔离变量。** 换一台设备试试（排除设备问题）、换一个位置试试（排除信号问题）、换一根线试试（排除线缆问题）。**一次只变一个变量**，否则改了两处还不好，你根本不知道是哪一处修好的。

<span class="marginnote">「重启路由器」之所以万能，是因为它同时重置了链路、DHCP、NAT、DNS 缓存——一次重置了所有层。但「重启好了一阵又坏」往往说明存在结构性原因（信道冲突、设备过热、固件 bug），这时必须回到分层排查。</span>

## 2 常用命令行工具速查

排查的核心工具是操作系统自带的命令行命令。**这些命令是通用的**，Windows 与 macOS/Linux 只是个别命令名不同：

| 工具 | 命令示例 | 查哪一层 | 能回答的问题 |
| --- | --- | --- | --- |
| **ping** | `ping 192.168.1.1` | 网络层 | 到目标通不通、延迟多少 |
| **ipconfig / ifconfig** | `ipconfig /all` | 网络层 | 本机 IP、网关、DNS 是否正常 |
| **ip route / route** | `ip route` | 网络层 | 默认路由是否存在、下一跳是谁 |
| **tracert / traceroute** | `tracert baidu.com` | 网络层 | 到目标经过哪些跳、卡在哪一跳 |
| **nslookup** | `nslookup baidu.com` | 应用层 | DNS 能否解析、解析到哪个 IP |
| **netstat** | `netstat -an` | 传输层 | 本机端口监听、连接状态 |

**ping 是排查的第一板斧**，它的输出有三个关键信息：

- **通/不通**：请求是否有响应。
- **TTL**：目标的初始 TTL 减去响应 TTL，可粗略估算跳数。
- **延迟（RTT）**：往返时间，毫秒级。

**辨析｜易错点：**「ping 不通 = 网络断了」——不一定。很多服务器与路由器**屏蔽了 ICMP**（ping 用的协议），此时 ping 不通但服务正常；反之「ping 通 = 一切正常」也不成立——ping 通只说明**网络层可达**，应用层（网页、DNS、端口）可能照样有问题。**ping 只是第一板斧，不是万能诊断。**

## 3 公式解析：延迟（RTT）由什么构成

「网络慢」到底慢在哪？看 RTT 的构成就明白了：

$$
\text{RTT} \approx 2 \times (\underbrace{t_{\text{传播}}}_{\text{光速传输}} + \underbrace{t_{\text{传输}}}_{\text{数据串行}} + \underbrace{t_{\text{排队}}}_{\text{路由器排队}} + \underbrace{t_{\text{处理}}}_{\text{设备处理}})
$$

分三步拆解：

- **第一步，认识四项延迟**：**传播延迟**是信号在介质里走的时间（光纤里约为光速的 2/3，跨洋几十毫秒）；**传输延迟**是把数据「放到线上」的时间（带宽越小越长）；**排队延迟**是数据在路由器缓冲里的等待（《QoS 流量控制》一篇讲过，拥塞时暴涨）；**处理延迟**是设备查表转发的时间（通常微秒级，可忽略）。
- **第二步，乘 2**：RTT 是往返，四项各算去程与回程。
- **第三步，直觉**：**家庭网络里，排队延迟是唯一的「变量」，其余三项基本恒定。** 所以你测出「延迟忽高忽低」，第一嫌疑就是链路拥塞（有人占满带宽）；延迟「恒定很高」才是距离问题（跨洋、服务器远）。

<span class="marginnote">这个拆解也解释了「为什么重启后延迟就正常了」：重启清空了积压的队列与异常的连接状态，排队延迟从秒级跌回毫秒级——治标，但能立刻验证「问题出在拥塞/状态异常」。</span>

## 4 工具实战：一个完整案例

把思路与工具串起来。场景：**电脑连不上网，但手机能上。**

**第一步，查物理/链路**：电脑网线插好、指示灯亮；WiFi 已连接。→ 物理层排除。

**第二步，看本机网络配置**：

```
ipconfig /all
```

检查 IP 是否为 `192.168.1.x`、网关是否为 `192.168.1.1`、DNS 是否有值。**发现 IP 是 `169.254.x.x`**——这是 Windows 的「自动专用地址」（APIPA），说明 DHCP 没拿到地址。

**第三步，定位 DHCP 问题**：手机能上网说明路由器 DHCP 正常，问题在**这台电脑与路由器的通信**。`ping 192.168.1.1` 不通 → 链路层/网络层故障。换一根网线 → 通了。**定位：网线坏或网口接触不良。**

整个排查只用了 `ipconfig` 与 `ping` 两件工具，靠的是**分层定位 + 隔离变量**：先确认「断在哪一层」，再通过「换变量」锁定「断在哪一环」。

## 5 排查的通用流程清单

无论什么问题，套用这个流程都能找到方向：

1. **问清楚症状**：是全屋断网，还是单台设备？是有线还是无线？是刚发生还是持续很久？
2. **确认影响范围**：换一台设备/换一个网段试试，判断是「局部」还是「全局」。
3. **分层定位**：从物理层开始，用 ping/ipconfig/nslookup 逐层往上确认。
4. **隔离变量**：一次换一个因素（线、口、位置、设备），逐步缩小范围。
5. **查日志与状态**：路由器后台的运行状态、在线设备列表、连接日志。
6. **修复并验证**：修复后必须复测，确认问题真正解决而非暂时缓解。

**易错点收尾：**「排查到最后没有结论」最常见的原因是**没有记录**——试过什么、结果如何、改了什么，全凭记忆。排查的严肃版本是「假设 → 验证 → 记录 → 下一条假设」，记下来，很多问题第二次见就是十分钟的事。

### 排查记录：让经验可复用

老手与新手排查的差距，一半在「有没有记录」。简单做法：每次排查在备忘录里记三行——**症状、做了哪些尝试、最终原因与解法**。

三个月后回头翻，你会发现自己遇到的大多是重复问题，而记录让你「第二次见就是十分钟」。这个习惯的价值，远超任何一款排查工具。

## 6 小结

- 排查第一原则：**分层定位**——物理 → 链路 → 网络 → 传输/应用，哪层断修哪层。
- 第二原则：**隔离变量**——一次只变一个因素。
- 工具速查：**ping**（可达性/延迟）、**ipconfig**（本机配置）、**ip route**（路由表）、**tracert**（逐跳路径）、**nslookup**（DNS）、**netstat**（端口与连接）。
- 延迟构成 **RTT ≈ 2×(传播+传输+排队+处理)**：家庭网络里排队延迟是唯一变量，忽高忽低=拥塞。
- **ping 通 ≠ 一切正常**，只证明网络层可达；通用排查流程：问症状 → 看范围 → 分层定位 → 隔离变量 → 查日志 → 修复验证。
