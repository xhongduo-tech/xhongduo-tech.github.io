## 为什么从远程访问开始

前面几篇把家管得井井有条，这一篇解决一个「人在外」的问题：**出门在外，怎么安全地访问家里的 NAS、摄像头、文件？**

直接暴露端口映射（见《NAT 与端口映射》）是一种方式，但它把服务直接晾在公网上，等于在门外挂一串钥匙。**更好的方案是 VPN**：在外面的设备先「加密隧道」连回家里，然后像坐在家里一样访问内网。这一篇讲透远程访问的三条路线，重点落在**家庭 VPN 搭建**——它也是「人在外，家随身」的核心能力。

## 1 远程访问的前提：你的家「找得到」吗

远程访问的第一道坎，不是加密，而是**寻址**：外面的设备怎么找到你家的路由器？两个现实问题摆在前面：

**问题一，公网 IP 可能不是真的。** 运营商普遍使用 **CGNAT（运营商级 NAT）**：用户拿到的「公网 IP」其实是运营商大内网里的私网地址，外网根本摸不到你的路由器。这种情况下，端口映射与自建 VPN 全部失效。

**问题二，公网 IP 会变。** 即便拿到真公网 IP，拨号重连后 IP 就会变化——你记下昨天的 IP，今天就连不上了。

**对策**：先向运营商确认能否拿到**真正的公网 IP**（拨打客服申请，不少地区可免费开通）；再配合 **DDNS**（下一节）解决 IP 变化问题。**没有公网 IP，所有「直连家里」的方案都无从谈起。**

## 2 远程访问方案横向对比

拿到公网 IP 后，三条路线摆在你面前：

| 方案 | 原理 | 安全性 | 易用性 | 适用 |
| --- | --- | --- | --- | --- |
| **端口映射 + DDNS** | 把指定端口暴露到公网 | 低（服务直接裸露） | 高 | 单个服务临时访问 |
| **内网穿透（frp/花生壳）** | 借中转服务器转发 | 中 | 高 | 无公网 IP 时的替代 |
| **家庭 VPN 回连** | 加密隧道连回内网 | **高** | 中 | 需要访问多个内网服务 |

**核心对比：端口映射 vs 家庭 VPN**

| 对比维度 | 端口映射 | 家庭 VPN |
| --- | --- | --- |
| 暴露面 | 每个端口单独暴露 | 只开一个 VPN 端口 |
| 认证 | 靠服务自身 | VPN 强认证 + 服务弱密码也可 |
| 访问范围 | 只开放的那个服务 | 整个内网 |
| 安全性 | 服务被扫描/攻击风险高 | 加密隧道，公网看不到内部 |
| 体验 | 每个服务单独配 | 连上后像在家上网 |

<span class="marginnote">VPN 的本质是「把公网这个大危险区，压缩成一条受保护的单点隧道」：外面的人只看到你路由器开了一个 VPN 端口，看不到你家里有 NAS、摄像头、打印机——攻击面从「N 个服务」收敛到「1 个强认证入口」。</span>

## 3 DDNS：让变化的 IP 有个固定名字

**DDNS（动态域名解析，Dynamic DNS）**：把「家庭公网 IP 的变化」实时同步到一个固定域名上。你只需要记住 `myhome.ddns.net`，无论家里 IP 怎么变，解析都指向当前的最新地址。

工作原理：

1. 路由器或内网主机定期检查公网 IP。
2. IP 变化时，自动通知 DDNS 服务商，更新域名的 A 记录。
3. 你在外网访问 `myhome.ddns.net`，DNS 解析到当前公网 IP，连接回家。

**DDNS 的搭配场景**：DDNS 解决了「IP 会变」，配合端口映射或 VPN 就构成完整方案——**DDNS 给地址命名，端口映射/VPN 给连接开门**。

**辨析｜易错点：**「有了 DDNS 就能远程访问」——不完全对。DDNS 只解决寻址，**不解决 CGNAT**。如果你没有真公网 IP，DDNS 解析到的也是假的运营商私网地址，外面依然连不上。**先解决公网 IP，再谈 DDNS。**

## 4 家庭 VPN：WireGuard 与 OpenVPN

**VPN（虚拟专用网络，Virtual Private Network）**：在公共网络上建立一条**加密隧道**，让两端的设备像在同一个私有网络里通信。家庭 VPN 的核心是「**回连**」：你在外，通过 VPN 连回家里，成为「内网的一员」。

家用路由器支持的两种主流 VPN 服务：

**OpenVPN**：老牌、兼容性极广（几乎所有平台都有客户端），配置稍重、性能略低。

**WireGuard**：新一代轻量 VPN，内核级实现，**配置简单、性能高、延迟低**，已成为现代家用路由器与自建 VPN 的首选。

**WireGuard 的配置三要素**：

**私钥/公钥对**：每台设备生成自己的密钥对，公钥相互交换。
**端点（Endpoint）**：家里路由器的公网地址 + 端口（配合 DDNS）。
- **AllowedIPs**：声明「哪些网段的流量走这条隧道」——通常是家里的 `192.168.1.0/24`。<span class="marginnote">WireGuard 的精髓是「每个对等方只有一把公钥、一条 Endpoint、一组 AllowedIPs」，配置全部浓缩在一段配置文件里。它比 OpenVPN 的证书体系简单一个量级——这正是它近年成为家庭 VPN 主流的根本原因。</span>

**公式解析：VPN 隧道要吃掉多少带宽**

加密隧道会为每个数据包套上额外的封装头。以 WireGuard 通过 UDP 封装为例：

$$
\text{MTU}_{\text{VPN}} = 1500 - 20(\text{外层 IP}) - 8(\text{UDP}) - 32(\text{WireGuard 头+加密开销}) \approx 1440
$$

分三步拆解：

- **第一步，算外层开销**：WireGuard 隧道把原始包再包一层 UDP/IP 头，占用 28 字节。
- **第二步，算加密开销**：WireGuard 为认证与加密附加约 32 字节（类型、保留、计数、Poly1305 标签等）。
- **第三步，相减**：1500 − 28 − 32 ≈ **1440 字节**，这是 VPN 链路里单个数据包能装的最大负载。

**直觉：隧道有成本，但很小。** 每包约 60 字节的开销占 1500 字节的 4%，对家用千兆几乎无感——这也是「VPN 慢」这个刻板印象的误区：**慢的往往不是加密，而是中转链路或服务器本身。**

## 5 没有公网 IP 怎么办：内网穿透

如果运营商坚持不给公网 IP，还有一条路——**内网穿透（NAT traversal / reverse proxy）**：

- 在家里跑一个**穿透客户端**（如 frp、花生壳客户端），主动向外网的中转服务器建立**长连接**。
- 你在外访问中转服务器，它把流量通过这条长连接转发回家里。
- 因为连接是「家里主动发起的」，运营商的 CGNAT 无法阻止。

**内网穿透的取舍**：它解决了无公网 IP 的访问问题，但流量绕行第三方服务器，**延迟更高、带宽受限，且中转服务器的安全性成为信任边界**。对「临时访问家里一个页面」够用，对「长期、高带宽、高安全需求」不如争取公网 IP + VPN。

**辨析｜易错点：**「VPN = 买机场节点看视频」——那是商业代理，与本篇的「家庭 VPN」是两回事。**家庭 VPN 是「把外网设备并入自家内网」的隧道**，方向相反（是你回连家里，不是把家里流量送出去）。理解了这个方向，「自建 VPN 到底在干嘛」就清晰了。

## 6 小结

- 远程访问的前提是**真公网 IP**；CGNAT 下先向运营商申请，否则一切直连方案失效。
- 三条路线：**端口映射+DDNS（低安全）、内网穿透（无公网 IP 的替代）、家庭 VPN（高安全首选）**。
- **DDNS** 把变化的公网 IP 绑定到固定域名，解决「找得到」；不解决 CGNAT。
- 家庭 VPN 首选 **WireGuard**：密钥对 + Endpoint + AllowedIPs 三要素，配置极简、性能好。
- VPN 封装开销很小（**MTU ≈ 1440**，仅占 4%），「VPN 必慢」是误解；没有公网 IP 用**内网穿透**兜底。
