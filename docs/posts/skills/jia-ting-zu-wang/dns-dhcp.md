## 为什么从这两个服务开始

手机连上 WiFi 的瞬间，屏幕上就出现了网络图标——这个「瞬间」背后，有两项服务在无声地工作：**DHCP** 给手机发了一张「内网身份证」（IP 地址），**DNS** 保证你接下来输 `www.example.com` 时能到达正确服务器。没有它们，家庭网络寸步难行，你却几乎感知不到它们的存在。

它们是家庭组网里「默认就开着、默认就够用」的两项服务，但恰恰因为太「无感」，一旦出问题（IP 冲突、DNS 劫持、域名打不开），大部分人就卡住了。这一篇把它们的机制讲透，既是原理，也是第4篇故障排查的直接弹药。

## 1 DHCP：自动分配 IP 的管家

**DHCP（动态主机配置协议，Dynamic Host Configuration Protocol）**：让设备接入网络时自动获得 IP 地址、子网掩码、网关、DNS 等配置信息的服务。家用路由器默认开着 DHCP 服务，地址池一般是 `192.168.1.2`–`192.168.1.254`。

设备获取地址的过程是经典的 **DORA 四步**：

**Discover（发现）**：新设备接入，发广播「我没有 IP，谁能给我分一个？」
**Offer（提供）**：DHCP 服务器（路由器）回应「我可以给你 `192.168.1.100`，有效期 24 小时。」
**Request（请求）**：设备说「我就要这个地址。」<span class="marginnote">为什么 Offer 之后还要 Request？因为网段里可能有多个 DHCP 服务器（比如误接了第二个路由器），Request 是设备「选定一个服务器」的确认动作，避免两台服务器都以为自己在管这台设备。</span>
**Acknowledge（确认）**：服务器最终确认，分配完成。

**租期（lease）**：DHCP 分配的不是永久地址，而是「租」来的，默认 24 小时。租期过半设备会自动续租，续不上才重新走 DORA。租期机制保证地址能被回收再利用，不会越积越少。

**静态保留（DHCP reservation / 地址绑定）**：在路由器后台把某个设备的 MAC 地址与一个固定 IP 绑定，让这台设备**每次接入都拿到同一个 IP**。NAS、打印机、需要端口映射的设备（见第2篇《NAT 与端口映射》），都建议做静态保留——否则设备重启后 IP 变了，端口映射就指向了错误的机器。

## 2 DHCP 派发的三件套

DHCP 不只发 IP，它一次把**四样配置**一起给设备：

| 配置项 | 作用 | 家用典型值 |
| --- | --- | --- |
| IP 地址 | 设备在内网的身份证 | 192.168.1.x |
| 子网掩码 | 划分网络位/主机位 | 255.255.255.0 |
| 默认网关 | 出网的第一跳 | 192.168.1.1 |
| DNS 服务器 | 域名解析服务地址 | 路由器的 192.168.1.1 |

**重点：设备「上网」真正需要的是后三样，而它们全来自 DHCP 一次派发。** 所以手动配置静态 IP 时最容易犯的错，就是只填了 IP 和掩码、漏填网关或 DNS——结果「IP 通了，网却上不去」。

**辨析｜易错点：**「为什么我手动设了静态 IP 反而上不了网？」最常见原因是**和 DHCP 地址池冲突**或**网关填错**。正确做法是：要么用 DHCP 静态保留（推荐），要么手动 IP 必须落在地址池之外、且网关/DNS 全部填对。手动静态 IP 与 DHCP 动态分配，不是「选一个就完事」，而是「手动要手动到底，不能半途而废」。

## 3 DNS：把域名翻译成 IP

**DNS（域名系统，Domain Name System）**：把人类好记的**域名**（`www.example.com`）翻译成机器需要的 **IP 地址**（`93.184.216.34`）的全球分布式数据库。你可以把它想成互联网的「电话簿」。

域名是**分层结构**，从右往左看：

$$
\underbrace{\text{www.}}_{\text{主机名}} \ \underbrace{\text{example}}_{\text{二级域名}} \ \underbrace{\text{.com}}_{\text{顶级域}}
$$

- **根域（root）**：所有域名的顶端，用「.」表示，全球 13 组根服务器负责。
- **顶级域（TLD）**：`.com`、`.org`、`.cn` 等，由各注册机构管理。
- **二级域**：`example`，由域名所有者管理。
- **主机名**：`www`，网站服务器的主机名。

**记录类型**是 DNS 里的「数据表」，家用配置里最常遇到：

| 记录类型 | 含义 | 示例 |
| --- | --- | --- |
| A | 域名 → IPv4 地址 | `example.com → 93.184.216.34` |
| AAAA | 域名 → IPv6 地址 | `example.com → 2606:2800:...` |
| CNAME | 别名指向另一个域名 | `www → example.com` |
| MX | 邮件服务器 | `example.com → mail.example.com` |
| TXT | 任意文本，常用于验证与安全 | `SPF`、`DKIM` 记录 |

<span class="marginnote">家用场景里 A 记录与 CNAME 最常见：你给自家 NAS 配了域名，本质就是让它解析到家庭公网 IP；而域名商后台配的解析记录，就是在建这些「电话簿条目」。</span>

## 4 核心对比：递归查询与迭代查询

当你输入一个域名，本机 DNS 解析器（通常就是路由器）要完成一次完整的解析，涉及两种查询方式：

**递归查询（recursive）**：你（客户端）问本地解析器，解析器「负责到底」，把最终答案带回给你。
**迭代查询（iterative）**：解析器去问根服务器，根服务器说「去问 `.com` 服务器」；再问 `.com` 服务器，它说「去问 `example.com` 的权威服务器」；层层下探，每台都只指路、不负责。

一次完整解析的链路：

$$
\text{客户端} \xrightarrow{\text{递归}} \text{本地解析器} \xrightarrow{\text{迭代}} \text{根} \rightarrow \text{顶级域} \rightarrow \text{权威服务器} \rightarrow \text{答案}
$$

**缓存（cache）**：每一步的结果都会被各级缓存存下来，TTL（生存时间）内再次查询直接命中缓存，不用重新走全程。这就是为什么「第一次打开一个网站慢，之后都快」。

**辨析｜易错点：**「DNS 是某个公司的服务器」是误解——DNS 是**全球分布式**的，没有单一中心。你在路由器里填的 `223.5.5.5`、`8.8.8.8`，只是**本地解析器**的地址（公共 DNS），它们代替你做递归查询。换公共 DNS 能解决的，通常是**运营商 DNS 不稳定的问题**；而「域名被解析到错误 IP」（DNS 劫持），才是换 DNS 的核心动机。

## 5 hosts 文件：绕开 DNS 的本地捷径

在 DNS 出现之前，互联网靠 **hosts 文件**手动记录「域名 → IP」。今天它仍然存在，且优先级**高于 DNS**：本机解析域名时，先查 hosts 文件，命中了就直接用，不再走 DNS。

**hosts 文件的位置**：Windows 在 `C:\Windows\System32\drivers\etc\hosts`，macOS/Linux 在 `/etc/hosts`。一行一个条目：

```
93.184.216.34   www.example.com
```

**重点：hosts 是排查与优化的一把双刃剑。** 用它可以把域名强行指到内网 IP（比如「把 `nas.local` 直接指到 NAS 的内网地址」），避开 DNS 的麻烦；但**恶意软件也常篡改 hosts**，把正常域名指向钓鱼服务器——所以系统安全软件都会检查 hosts 文件是否异常。看到 hosts 里多出自己没写过的条目，要立刻警惕。

### 公共 DNS 换哪个好

路由器里可填的 DNS 不止运营商默认，常见的公共 DNS 有：国内 223.5.5.5（阿里）、119.29.29.29（腾讯）；国际 8.8.8.8、1.1.1.1。**国内家庭优先选国内公共 DNS**（延迟低、更稳定），运营商 DNS 出问题时换公共 DNS 常能立即缓解「域名解析慢/失败」。换完后 `ipconfig /flushdns` 清一下本机缓存再测。

## 6 小结

- **DHCP** 通过 **DORA 四步**（发现、提供、请求、确认）给设备自动分配 IP + 掩码 + 网关 + DNS，地址按**租期**回收复用。
- 需要固定 IP 的设备（NAS、打印机、端口映射目标）用 **DHCP 静态保留**，而不是手动改 IP。
- **DNS** 是域名→IP 的全球分布式「电话簿」，域名按 **根 → 顶级域 → 二级域 → 主机名** 分层。
- 解析分**递归**（客户端→本地解析器）与**迭代**（解析器逐级问询）两种，靠 **TTL 缓存**加速。
- A/AAAA/CNAME/MX/TXT 是家用最常打交道的记录类型。
- **hosts 文件优先级高于 DNS**，可用于本地定向，也可能被恶意篡改。
