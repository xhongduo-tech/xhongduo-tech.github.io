## 为什么从常见故障开始

上一篇建立了排查方法论，这一篇是「病例集」：家庭网络最常见的问题就那么几类，每类都有固定的套路。把这些病例装进脑子，再遇到「上不了网」「网很卡」时，你不是从零开始摸索，而是**按病名调出对应方案**。

这一篇按「影响范围」组织：**全屋断网 → 单台设备问题 → WiFi 问题 → 网速慢 → 特定服务异常**，最后给一张「症状速查表」，把方法浓缩成一张随时能翻的卡。

## 1 全屋断网：问题几乎一定在「上游」

所有设备同时上不了网，说明**路由器以内的内网是好的**，问题出在路由器或它的上游。

排查顺序，从最便宜的开始：

**第一步，看光猫指示灯**：光猫的「光信号/PON」灯红灯或闪，说明运营商线路故障——直接打客服。**光信号灯的状态是「运营商问题」与「自家问题」的分水岭。**

**第二步，看路由器指示灯**：WAN 口灯不亮，说明光猫到路由器的网线/接口有问题，换线换口试。

**第三步，登录路由器后台**：看 WAN 口是否「已连接」。显示「未连接/拨号失败」，检查宽带账号密码、或重启光猫与路由器。<span class="marginnote">重启的先后顺序有讲究：<strong>先重启光猫，等它完全就绪（约 2 分钟），再重启路由器</strong>。顺序反了或重启太快，光猫还没上线，路由器拨号照样失败——很多人「重启没用」其实是重启方式不对。</span>

**第四步，判断是不是运营商故障**：用手机流量查运营商公告，或直接打客服确认片区故障。

**核心：全屋断网 = 内网没问题，往外查**。别在自家设备上纠结太久。

## 2 单台设备上不了网

只有一台设备连不上，问题高度集中在「这台设备与网络之间的环节」。

**排查脚本**（从上到下）：

**WiFi 连上了吗**：连上但没网，看 DHCP 有没有拿到 IP。
**看 IP 是否正常**：`ipconfig` 看到 `169.254.x.x`（Windows）或 `10.x.x.x` 异常段，说明 DHCP 没下发地址——重启路由器 DHCP 服务或重连设备。
- **换接口/换线试**：有线设备换一个 LAN 口，换一根网线，排除物理层。
- **查 IP 冲突**：手动配过静态 IP 的设备，可能与 DHCP 分配的地址撞车，导致「时通时断」。路由器后台看「在线设备」，是否有两个设备同 IP。
- **查 MAC 过滤**：路由器开了 MAC 黑白名单，新设备可能被挡（《防火墙与访问控制》一篇讲过）。

**辨析｜易错点：**「重连 WiFi 没用」时，先做「**忘记网络再重连**」而不是单纯关开 WiFi——系统可能记住了错误的密码或认证信息，忘记网络才能彻底清除重来。这也是《路由器初始配置》一篇「改了密码连不上」的标准解法。

## 3 WiFi 连接与掉线问题

WiFi 的「连不上」与「频繁掉线」是两大类，原因不同：

**连不上（有信号但连不了）**：

- 密码错误 → 忘记网络重连。
- 设备不支持当前加密方式（老设备连 WPA3 网络失败）→ 加密改 WPA2/WPA3 混合。
- 信号太弱 → 靠近路由器试。
- 设备被 MAC 过滤或访客网络限制。

**频繁掉线（连上了但断断续续）**：

- **信道干扰**：邻居 WiFi 密集，信道冲突（《WiFi 频段与信道选择优化》一篇）→ 手动换信道。
- **频段拥挤**：2.4 GHz 设备过多、微波炉/蓝牙干扰 → 高速设备切 5 GHz。
- **路由器过热**：夏季长时间高负载，路由器过热降速/重启 → 改善散热。
- **DHCP 租期冲突**：设备 IP 冲突导致周期性掉线 → 设 DHCP 静态保留。
- **固件 bug**：特定固件版本的掉线问题 → 更新固件。

<span class="marginnote">「掉线」的排查关键是看<strong>规律</strong>：定时掉线（每天固定时间）→ 多半是邻居/设备周期性干扰或运营商线路；随机掉线 → 多查无线信道与路由器散热；只有一台设备掉线 → 查那台设备的休眠策略与 IP 冲突。</span>

## 4 网速慢：把「慢」拆开看

「网速慢」是最模糊的症状，必须先拆成「下载慢」「上传慢」「延迟高」三种，再分层查：

| 症状 | 优先怀疑 | 快速验证 |
| --- | --- | --- |
| 下载慢 | 运营商线路、WiFi 信号、被其他设备占满 | 有线直连测速 |
| 上传慢 | 上行带宽被占满（摄像头/备份） | 路由器后台看各设备实时速率 |
| 延迟高 | 拥塞、干扰、服务器距离远 | ping 网关 vs ping 公网对比 |

**关键验证动作：有线直连测速。** 电脑用网线直连路由器测速：

- **有线快、无线慢**：问题在无线（信号、信道、频段），对 WiFi 动手。
- **有线也慢**：问题在宽带本身（运营商、光猫、线路），联系运营商。

**公式解析：无线「协商速率」与实际吞吐**

无线连接上后，网卡会显示「协商速率」（如 866 Mbps），但它**不等于实际网速**。实际吞吐约为协商速率的 50%–70%：

$$
\text{实际吞吐} \approx \text{协商速率} \times 0.5 \sim 0.7
$$

分三步拆解：

- **第一步，看协商速率**：它是「当前信号质量下，链路理论上限」，受信号强度、频宽、干扰共同决定。
- **第二步，乘上无线开销**：WiFi 是半双工共享信道，还要扣除帧间间隙、确认帧、重传等开销，实际只能到一半左右。
- **第三步，直觉**：网卡显示 866 Mbps，实际跑 400–600 Mbps 属正常；**如果你的测速远低于协商速率的一半，才说明有问题**（干扰、信道冲突、设备瓶颈）。

## 5 症状速查表：十种常见故障

把本篇所有病例浓缩成一张速查表：

| 症状 | 最可能原因 | 首选动作 |
| --- | --- | --- |
| 全屋断网，光信号灯红 | 运营商线路故障 | 打客服 |
| 全屋断网，WAN 灯不亮 | 光猫到路由器的线/口 | 换线换口 |
| 单台设备无 IP（169.254） | DHCP 未下发 | 重启路由器/重连 |
| 两台设备同 IP | IP 冲突 | 改静态保留 |
| WiFi 能连但没网 | 网关/DNS 配置异常 | 查网关与 DNS |
| WiFi 频繁掉线 | 信道干扰/过热/固件 | 换信道、散热、更固件 |
| 下载慢但有线快 | 无线信号/频段 | 切 5 GHz、优化摆放 |
| 上传慢 | 上行被占满 | QoS 限速摄像头/备份 |
| 网页打不开但微信能用 | MTU 或 DNS 异常 | 改 MTU 1492、换 DNS |
| 延迟忽高忽低 | 链路拥塞 | 查谁在占带宽 |

**易错点收尾：**「把所有排查动作一起做」是常见失误——换了信道、清了缓存、又改了 DNS，好了却不知是谁修好的。**一次改一个变量，确认生效再动下一个**（《网络故障排查思路》一篇的原则），才不会被「玄学修复」坑到下次复发。

## 6 小结

- **全屋断网往外查**：光猫指示灯分水岭 → 路由器 WAN → 运营商。
- **单台设备问题**：查 DHCP、换线换口、查 IP 冲突与 MAC 过滤；「忘记网络再重连」是 WiFi 万能第一步。
- **掉线看规律**：定时掉线查干扰，随机掉线查信道/散热，单台掉线查 IP 与休眠。
- **网速慢先拆解**：下载慢/上传慢/延迟高分别处理；**有线直连测速**是区分「无线问题」与「宽带问题」的关键动作。
- **实际吞吐 ≈ 协商速率 × 0.5~0.7**，低于一半才说明异常。
- 对症下药、**一次只改一个变量**，是让排查可复现的底线。
