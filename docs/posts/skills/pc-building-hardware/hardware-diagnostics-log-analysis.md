## 为什么从诊断工具与日志分析开始

上一节我们用「最小系统 + 逐段隔离」解决了「点不亮」，但机器「能亮却偶尔蓝屏、无故重启、速度变慢」这类**隐性故障**，靠拆机排查效率太低——这时要靠**诊断工具与系统日志**，让数据告诉我们问题在哪。<span class="marginnote">从「从极限到大模型」的方法论看，诊断是「<strong>用数据验证假设</strong>」的典范：不靠「我觉得是内存问题」，而是<strong>用工具读出温度、日志、错误码</strong>，让证据指向结论。<strong>会排障的人，是让硬件「开口说话」的人</strong>。</span>本小节讲清三套「听诊器」：**软件诊断工具**、**系统日志与蓝屏分析**、**硬盘健康监测**——并用一套诊断工作流把它们串起来。

## 1 软件诊断工具：给硬件「量体温、看参数」

装机与排障常用的一组免费工具，是硬件的「体检仪」：

**HWiNFO**：最全的传感器读数——CPU/GPU 温度、频率、电压、功耗，风扇转速，一网打尽。<span class="marginnote"><strong>HWiNFO 是排障的「总仪表盘」</strong>：开机后开着它，观察温度曲线——<strong>温度异常（过高/波动）是散热问题的第一信号</strong>（回看《散热方案与机箱风道设计》的热阻公式）。它还能记录日志，烤机后回放找「最高点」。</span>

**CPU-Z / GPU-Z**：CPU 与显卡的详细参数——型号、步进、频率、内存双通道是否开启。**验证「XMP 开了没」「双通道对不对」用它最直观**。

**CrystalDiskInfo**：硬盘健康监测——SMART 数据、健康度百分比、温度、通电时间。

**AIDA64 / Prime95**：压力测试与稳定性验证（回看《整机性能测试与稳定性验证》）。

**核心对比表：诊断工具速查**

| 工具 | 看什么 | 典型用途 |
| --- | --- | --- |
| HWiNFO | 温度/电压/功耗/风扇 | 烤机监控、散热排查 |
| CPU-Z / GPU-Z | CPU/GPU 参数 | 验证频率、双通道、XMP |
| CrystalDiskInfo | 硬盘 SMART 健康 | 硬盘寿命与坏块预警 |
| AIDA64 | 综合信息 + 烤机 | 内存带宽、稳定性 |

## 2 系统日志与蓝屏分析：让 Windows 「写病历」

操作系统会把异常记进日志，是隐性故障的第一手资料：

**事件查看器（Event Viewer）**：Windows 内置——「系统」日志里记录硬件错误、驱动警告、意外关机。**排查「无故重启」先看这里**：是否有「严重错误」事件（如 Kernel-Power 41）指向断电/重启。

**蓝屏（BSOD）分析**：蓝屏会显示错误代码（如 `MEMORY_MANAGEMENT` 指内存、`VIDEO_TDR_FAILURE` 指显卡），并生成 **dump 文件**（MEMORY.DMP）——用 Windbg / BlueScreenView 解析，能定位到具体驱动与模块。<span class="marginnote"><strong>蓝屏不是「死机了」而是「系统在自保」</strong>：Windows 检测到致命错误时主动停机并写下诊断记录——<strong>错误代码 + dump 文件，就是系统留给你的「病历」</strong>。记下蓝屏代码再查，比盲修高效十倍。</span>

**「无故重启」排查法**：查事件查看器「系统」日志的**时间戳**——断电重启前有无 Kernel-Power 事件、有无过热（温度日志）、有无驱动错误。**让日志的时间轴说话**，是这类故障的标准做法。

## 3 硬盘健康监测：SMART 数据与预警

硬盘是「数据之家」，它的健康要**主动监测**，别等坏了才后悔：

**SMART（Self-Monitoring, Analysis and Reporting Technology）**：硬盘内置的自我监测技术，记录通电时间、重映射扇区数、坏道数、温度等指标。<span class="marginnote"><strong>SMART 是硬盘的「体检报告」</strong>：CrystalDiskInfo 把它读成「健康度 %」——<strong>出现「重映射扇区」「待映射扇区」计数上升，就是坏道在扩大的信号，赶紧备份</strong>。硬盘故障的黄金法则是「<strong>备份先行，监测为辅</strong>」（回看《存储设备》的备份三原则）。</span>

**机械硬盘（HDD）**：重点看 **重映射扇区数** 与 **通电时间**（机械磨损），运行中听到「咔哒」异响就要警惕。
**固态硬盘（SSD）**：重点看 **剩余寿命（TBW 消耗）** 与 **温度**，突然掉速也可能与健康度相关。

**诊断动作**：定期（如每月）开一次 CrystalDiskInfo 看一眼健康度；出现「警告」即着手备份与更换准备。

## 4 诊断工作流：从症状到定位

把工具串成一套可复用的诊断流程：

1. **收集症状**：什么时候发生（开机/负载/随机）、什么表现（蓝屏/重启/花屏/变慢）——**先问「何时何地」，再问「何种现象」**。
2. **看日志**：事件查看器 + 蓝屏代码——让系统自己「报姓名」。
3. **读参数**：HWiNFO 看温度电压、CPU-Z 验证配置（XMP/双通道）——排除「配置未到位」这类软因素。
4. **查健康**：CrystalDiskInfo 看硬盘 SMART——排除硬盘隐患。
5. **压力验证**：烤机/内存测试——把隐性不稳「逼出来」（回看《整机性能测试与稳定性验证》）。

**辨析｜易错点：** **别只看单一数据**。比如「温度高」可能是散热问题，也可能是「XMP 没开导致内存异常」「风扇策略错误」——**把温度、日志、配置交叉起来看**，才不会被一个数据带偏。<span class="marginnote"><strong>诊断的「交叉验证」</strong>：一个异常现象，用两个独立工具/数据互相印证——<strong>日志说是内存、HWiNFO 显示电压不稳、烤机复现蓝屏</strong>，三者指向一致才下结论。<strong>诊断的价值不在工具多，而在结论可靠</strong>。</span>

### 温度与电压监控实践：读懂 HWiNFO

以 HWiNFO 为例，学会「读监控」：

**关键读数**：
- **CPU Package 温度**：待机 30–50°C、满载 70–90°C——超过 95°C 危险。
- **CPU 核心电压（VCore）**：波动过大 = 供电不稳。
- **风扇转速（RPM）**：满载时是否跟着温度爬升。
- **主板 / 显卡温度**：对照风道判断（回看《散热方案与机箱风道设计》）。

**「读曲线」比「读数」更准**：烤机时观察温度曲线——**平稳是健康，直线飙升是散热失守**；曲线剧烈波动 = 接触不良或供电不稳。

**核心对比表：HWiNFO 关键读数**

| 读数 | 健康区间 | 异常信号 |
| --- | --- | --- |
| CPU 温度 | 待机 ≤50°C | 满载 >95°C |
| VCore 电压 | 波动小 | 大幅波动 |
| 风扇转速 | 随温度响应 | 满载不升 |
| 主板温度 | ≤60°C | 持续走高 |

**一句话**：HWiNFO 是「量体温」，读曲线是「看病情」——**工具给数据，你给判断**。

### 诊断记录模板：让每次排障都可复盘

职业排障讲究「可追溯」——用一张诊断记录表留档：

| 日期 | 症状 | 工具/日志证据 | 结论 | 处置 |
| --- | --- | --- | --- | --- |
| 8月7日 | 随机蓝屏 | 事件查看器内存错误 + MemTest 报错 | 内存坏块 | 更换内存 |

**记录的价值**：下次同类故障，翻记录直接对号入座；为「这台机器修过什么」留了档案——**诊断的终点不是修好，而是修好并记录**。

**一句话**：让硬件「开口说话」是第一步，让记录「留下记忆」是第二步——**会诊断 + 会留档，才是完整的排障闭环**。

**诊断的「工具边界」**：软件诊断只能看到「系统层面」的信息——电源电压、物理接触这类「硬件层」问题，最终还要靠万用表与拆机确认；**工具缩小范围，动手最终定性**。

## 5 小结

- 软件诊断工具：**HWiNFO（温度电压）、CPU-Z/GPU-Z（参数）、CrystalDiskInfo（硬盘健康）**——免费且够用。
- 系统日志：**事件查看器**记错误与意外关机，**蓝屏代码 + dump** 指认问题模块。
- 硬盘用 **SMART** 主动监测：重映射扇区上升即「坏道扩散」，先备份再处理。
- 诊断工作流：**症状 → 日志 → 参数 → 健康 → 压力验证**——让数据说话。
- 交叉验证：**多工具互证再下结论**，避免被单一数据带偏。
