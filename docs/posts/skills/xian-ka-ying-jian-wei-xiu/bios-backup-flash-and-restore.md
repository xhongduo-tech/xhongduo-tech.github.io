## 为什么从备份开始

BIOS 是显卡的「出厂设置」，而刷写是把设置替换掉。替换一旦中断（断电、文件损坏、型号不匹配），显卡就可能「变砖」——点不亮、风扇狂转、无输出。**刷 BIOS 的第一原则：永远先备份，备份是一切操作的前提。**这一节把「备份→刷写→还原→救援」的完整流程走一遍，让你既敢刷，也能救。<span class="marginnote">「先备份再变更」是运维界的通用纪律：数据库改表前先 dump，系统升级前先做镜像。显卡 BIOS 只是把同一纪律应用到一块固件上——理解了这个模式，你就在任何「改配置」的场景都有了保险意识。</span>

## 1 备份：两条路，按需选

**软件备份（在线）**：系统下用工具把 BIOS 从 Flash 读出保存。

NVIDIA：**GPU-Z**（保存当前 BIOS，点「BIOS 版本」旁的保存按钮）或 **NVFlash** 的 `--save` 参数。
AMD：**GPU-Z** 或 **ATIFlash**（`-s` 参数）。
优点：不动硬件、最快。缺点：**软件读到的只是「驱动可见」的 BIOS 区域**，双 BIOS 卡的第二个 BIOS 不一定能全量读出。

**编程器备份（离线）**：拆下 Flash 芯片或用编程器夹子（SOP8 夹）夹住芯片，用编程器软件读出完整镜像。

- 优点：完整、可靠，**连「隐藏的救援 BIOS」也能读**。缺点：需要拆卡、夹子要对准芯片引脚。<span class="marginnote">软件备份「看似成功、实则读不全」是翻车高发点：部分卡 BIOS 有多个分区，软件只备份了主区。编程器备份虽然麻烦，却是维修店的标配——因为专业维修必须拿到<strong>完整镜像</strong>才能做「写死救援」。</span>

## 2 刷写：匹配、校验、再动手

刷写（flash）是把新 BIOS 写入 Flash。主流工具：

**NVIDIA**：NVFlash（命令行），`nvflash -6 <bios.rom>`。
**AMD**：ATIFlash / amdvbflash（`-f -p <index> <bios.rom>`）。
**Windows GUI**：个别厂商提供刷写工具，但命令行工具更通用、更可控。

刷写三查，缺一不可：

1. **查型号匹配**：BIOS 必须来自**同型号同显存配置**的卡——不同品牌同 GPU 可以通用，但显存颗粒类型不同（如 GDDR6 vs GDDR6X）绝不能混刷。
2. **查文件校验**：刷前用工具计算 ROM 的校验值（MD5/SHA），与来源发布的校验值对比，**防止下载到损坏或改写的文件**。
3. **查供电环境**：刷写过程必须稳定供电——**接上 UPS 或保证不碰电源线**，刷写中断是变砖的头号原因。<span class="marginnote">「校验值比对」在正规 ROM 分发站（如 TechPowerUp 的 VGA BIOS 库）都能找到：每份 BIOS 页面都列出哈希值。养成「下载→比哈希→再刷」的习惯，能挡掉大部分网上流传的坏文件与恶意修改版。</span>

## 3 还原与救援：刷坏了怎么办

刷坏不意味着报废，救援路径按严重程度分级：

**第一级：双 BIOS 切换**。拨到另一片 BIOS，能点亮则说明只是主 BIOS 坏——重启后在系统里把好的 BIOS 重新刷回坏区。

**第二级：无头刷写（blind flash）**。屏幕黑但系统能进（显存初始化失败仅影响显示）：按盲操作流程运行刷写命令，等几秒后强制重启，靠肌肉记忆完成刷回。

**第三级：亮机卡引导**。插一张能亮的低端卡当主显示，把坏卡放副插槽，进系统后对坏卡执行刷写。**这是维修店最常用的救援法**：坏卡在副槽一样能被识别、被刷写。<span class="marginnote">亮机卡引导的原理很朴素：显卡只要「被系统枚举到」，即使它自己不能显示，也能通过 PCIe 通信完成刷写。所以救援的优先级永远是把卡「插回可被枚举的环境」，而不是急着上编程器。</span>

**第四级：编程器离线刷写**。以上都不行（BIOS 区彻底写坏、卡完全不被识别），只能拆 Flash 芯片，用编程器把备份镜像**离线重写**。这是最后的保险，也解释了为什么「备份」必须在刷写之前做——没有原始镜像，救援无从谈起。

## 4 防砖清单（本主题以表代式）

| 环节 | 动作 | 防什么 |
| --- | --- | --- |
| 备份 | GPU-Z / NVFlash 保存、编程器完整读 | 无镜像可救 |
| 校验 | 比对 MD5/SHA | 坏文件、篡改文件 |
| 型号匹配 | 同型号同显存颗粒 | 刷错导致黑屏 |
| 供电稳定 | UPS / 不断电 | 刷写中断变砖 |
| 救援预案 | 双 BIOS / 亮机卡 / 编程器 | 意外变砖后恢复 |

## 5 易错辨析与术语速查

BIOS 刷写的三处高危误区：

**误区一：软件备份等于完整备份。** GPU-Z 等软件读到的可能只是「驱动可见」的 BIOS 主区，双 BIOS 卡的第二区不一定读全。专业维修用**编程器离线读完整镜像**——备份的完整性决定救援的可行性，别在备份上省事。<span class="marginnote">「备份读不全」的教训：刷写失败后想还原，发现备份缺了一半，救援无从谈起。对重要操作，用编程器夹子读一份完整镜像，成本最低的保险。</span>

**误区二：不校验哈希就刷。** 从网上下载的 ROM 文件可能损坏或被篡改。刷前用 MD5/SHA 与发布站提供的哈希比对——哈希一致才放心刷。这是挡住「坏文件变砖」的第一道闸。

**误区三：刷写途中断电。** 刷写 Flash 的瞬间断电，很可能写坏引导区。接 UPS、别碰电源线、别在刷写时动其他硬件——**刷写期间的电稳定，比什么都重要**。

### 术语速查

| 术语 | 英文 | 一句话含义 |
| --- | --- | --- |
| 刷写 | Flash | 写入固件到 Flash 芯片 |
| 变砖 | Brick | 固件损坏导致无法使用 |

| 编程器 | Programmer | 离线读写 Flash 的仪器 |

## 6 实操清单与自查

刷 BIOS 的完整操作按这份清单执行：

1. **确认需求**：明确为什么要刷（解锁、修故障、还原）——没有明确收益不刷。
2. **先备份**：GPU-Z/NVFlash 保存 + 编程器读一份完整镜像，双保险。
3. **找对来源**：从可信站点下载与「型号 + 显存颗粒」完全匹配的 ROM。
4. **校验哈希**：比对 MD5/SHA 与发布值一致，不一致坚决不刷。
5. **准备供电**：接 UPS 或保证刷写期间不断电。
6. **确认救援路径**：想好「刷坏了我怎么救」——双 BIOS、亮机卡、编程器哪个可用。
7. **执行刷写**：按工具参数刷入，过程不碰电源线、不操作其他硬件。
8. **断电重启**：刷完正常关机，再开机验证。
9. **验证功能**：设备信息正确、能点亮、各接口正常、温度/功耗读数正常。
10. **留存记录**：把备份镜像与刷入版本记入档案，方便日后还原。

### 快速自查表

| 环节 | 必做动作 | 防什么 |
| --- | --- | --- |
| 备份 | 完整镜像×2 | 无镜像可救 |
| 下载 | 核对型号颗粒 | 刷错黑屏 |
| 校验 | 比对哈希 | 坏文件变砖 |
| 供电 | UPS/不断电 | 中断写坏 |
| 救援 | 预案确认 | 变砖无路 |

一句话收尾：**刷 BIOS 的每一次「变砖」，背后都缺了备份、校验、供电三件事中的一件**。

## 7 小结

- **先备份再刷写**：软件备份快但可能不完整，编程器备份完整但需拆卡。
- 刷写三查：**型号匹配、文件校验、供电稳定**——三条都过才动手。
- 救援四级：**双 BIOS 切换 → 无头刷写 → 亮机卡引导 → 编程器离线刷**。
- 亮机卡引导是维修店主力救援法：坏卡只要能被枚举，就能被刷写。
- 防砖的根本是**备份先行 + 校验 + 稳定供电**，缺一不可。
