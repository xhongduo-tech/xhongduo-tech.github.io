## 为什么从核心显存分开调试开始

上一节认识了工具，这一节把「超频」落到具体动作。核心（Core）与显存（Memory）是两条独立的超频线：**核心超频直接提升计算频率，显存超频提升带宽**，但两者的故障表现完全不同——核心超太多是「掉驱动、黑屏」，显存超太多是「花屏、贴图错误、ECC 报错」。分开调、分开测，才能把每一条线推到各自的极限。<span class="marginnote">核心与显存的关系，就像 CPU 与内存：核心吃频率，显存吃带宽。回想第 1 篇的公式——像素填充率=ROP×核心频率、显存带宽=位宽×等效频率——核心超频动前者，显存超频动后者，两条公式就是两条超频线。</span>

## 1 核心超频：逐步偏移，稳定为先

核心超频的标准流程是「**小步加频、逐档验证**」：

1. **记录基线**：烤机 10 分钟，记录满载频率、温度、功耗、风扇转速与跑分。
2. **拉功耗墙**：先把 Power Limit 拉到 100%~110%（默认上限），给核心预算。
3. **每次 +25~50 MHz**：在 Afterburner 的 Core Clock 上逐步加偏移，每加一档烤机 5~10 分钟确认稳定。
4. **找到极限**：某档开始掉驱动（驱动重启）、黑屏或跑分下降，**退回上一档**——上一档就是稳定极限。
5. **留安全余量**：极限频率再 -20~30 MHz 作为日常使用档，因为长时间游戏比烤机更考验稳定性。

<strong>核心超频的铁律：出现任何异常（掉驱动、花屏、黑屏、跑分倒退）就退回上一档。</strong><span class="marginnote">「跑分倒退」是超频过头的隐蔽信号：频率太高导致芯片纠错或降频，性能反而下降。跑分曲线像一个钟形——上升段是有效超频，过了顶点就回落。看跑分不只看「有没有提升」，还要看「是否还在上升段」。</span>

## 2 显存超频：带宽的甜头与暗坑

显存超频动的是「带宽」，收益取决于场景：

**高分辨率/高纹理**：显存带宽是瓶颈时，显存超频收益明显。
**低分辨率/低负载**：显存带宽用不满，显存超频几乎无收益。

显存超频的故障表现比核心「温柔」但更隐蔽：

- **轻微超频**：帧率小幅提升，一切正常。
- **超频过头**：出现**贴图错误、花屏、驱动重置**；部分卡带显存 **ECC**，超频后 ECC 纠错次数激增——**不花屏但性能下降**，因为 GPU 在偷偷纠错。<span class="marginnote">「ECC 纠错」是显存超频的专业判据：用 GPU-Z 或 HWiNFO 监控显存 ECC 计数，超频后计数快速上涨，说明显存已到极限——即便画面还正常，也应该退回。这是维修时「显存有没有坏」也看同一指标的原因。</span>

显存超频同样**小步加**（每次 +100~200 MHz 等效频率），烤机 + 游戏双测，退回极限档 -100 MHz 留余量。

## 3 降压超频：白赚的优化

上一节预告的「降压超频（undervolt）」，实操步骤：

1. 在 Afterburner 曲线编辑器里，把「目标频率对应的电压点」逐档降低。
2. **保持频率不变**（或略降），电压每次 -25 mV，烤机验证稳定。
3. 降到「再降就掉驱动」的临界，**回退 25 mV** 作为日常档。

效果：同频率下功耗降 10%~20%，温度降 5~10°C，风扇转速下降，**噪音更低、温度墙余量更大，甚至因散热改善而 boost 更高**——这是「性能不变或微升 + 功耗大降」的最优解。<span class="marginnote">降压超频的物理依据还是 $P \propto V^2$：电压降 10%，功耗项降约 19%。相比「加电压换频率」的低性价比，降压是「用电压换温度」的正收益操作——它把之前所有散热与功耗的知识一次性用上了。</span>

## 4 公式解析：显存超频的带宽增益

显存超频的收益直接用带宽公式量：

$$
\text{带宽提升} = \frac{\text{新等效频率} - \text{原等效频率}}{\text{原等效频率}}
$$

- **第一步，看原带宽**：GDDR6 卡原等效 14 Gbps、位宽 256 bit，带宽 = 448 GB/s。
- **第二步，超频**：显存等效频率拉到 15.5 Gbps（+10.7%），带宽 = 256 × 15.5 ÷ 8 = 496 GB/s。
- **第三步，对比**：带宽提升约 10.7%——但**帧率不会同比例提升**，因为带宽只是瓶颈之一；实际帧率提升通常只有 3%~6%。

<strong>推论：显存超频的收益有上限——只有「显存带宽是瓶颈」的场景（4K 高纹理、大显存占用）才吃得到甜头。</strong><span class="marginnote">判断「当前场景是否带宽瓶颈」：游戏中看 GPU 显存占用与带宽利用率，若带宽跑满而核心占用不满，显存超频就有肉吃；反之（核心满载、带宽有余）显存超频是隔靴搔痒。</span>

## 5 核心 vs 显存超频对照表

| 维度 | 核心超频 | 显存超频 |
| --- | --- | --- |
| 动的是 | 计算频率 | 显存带宽 |
| 故障表现 | 掉驱动、黑屏 | 花屏、贴图错误、ECC 计数涨 |
| 判稳方式 | 烤机 + 游戏双测 | 画面 + ECC 计数 |
| 收益场景 | 核心瓶颈（低分辨率） | 带宽瓶颈（高分辨率） |
| 推荐幅度 | +25~50 MHz/档 | +100~200 MHz/档 |

## 6 易错辨析与术语速查

核心与显存超频的三处易错点：

**误区一：核心显存一起加频。** 两者故障表现不同（核心超频掉驱动、显存超频花屏），一起加频时出了问题无法判断是谁的锅。**分开调、分开测**：先定核心稳定值，再单独调显存。<span class="marginnote">「一次只改一个变量」是实验方法的基本纪律：同时动两个变量，出了问题无法归因。超频如此，维修排查、AI 调参也一样。</span>

**误区二：显存超频只看画面不看 ECC。** 显存超频过头不一定花屏，可能 ECC 悄悄纠错——不花屏但性能下降。用 HWiNFO 监控**显存 ECC 计数**，计数猛涨就是超频过头的信号。

**误区三：把「极限频率」当「日常频率」。** 烤机测出的极限频率，长时间游戏可能站不住。日常档应在极限频率基础上**留 20~30 MHz 余量**——超频的收益来自「稳定地快」，不是「冒险地快」。

### 术语速查

| 术语 | 英文 | 一句话含义 |
| --- | --- | --- |
| 核心超频 | Core OC | 提高计算频率 |
| 显存超频 | Memory OC | 提高显存带宽 |
| ECC | Error Correction Code | 显存纠错机制 |
| 掉驱动 | Driver Crash | 驱动崩溃重启 |
| 花屏 | Artifact | 画面出错 |
| 降压超频 | Undervolting | 同频降电压 |
| 余量 | Headroom | 为稳定预留的空间 |

## 7 实操清单与自查

核心与显存超频调试按这份清单执行：

1. **记基线**：默认状态烤机，记录满载频率、温度、跑分。
2. **拉功耗墙**：先把 Power Limit 拉满。
3. **核心单独调**：每次 +25~50 MHz，每档烤机验证。
4. **找核心极限**：掉驱动/跑分倒退即退回上一档。
5. **核心留余量**：极限频率 -20~30 MHz 作日常档。
6. **显存单独调**：每次 +100~200 MHz，画面 + ECC 双看。
7. **找显存极限**：花屏或 ECC 猛涨即退回。
8. **降压超频**：同频降压 -25 mV/档，降到临界回退 25 mV。
9. **双测验收**：烤机 + 游戏双测，监控指标全绿。
10. **确认自启**：长期稳定后才开启开机自启。

### 快速自查表

| 参数 | 步进 | 过头信号 |
| --- | --- | --- |
| 核心频率 | +25~50 MHz | 掉驱动、跑分倒退 |
| 显存频率 | +100~200 MHz | 花屏、ECC 涨 |
| 电压 | -25 mV/档 | 掉驱动 |
| 功耗墙 | 拉满 | 温度跟不跟得上 |
| 余量 | 20~30 MHz | 长期稳定 |

一句话收尾：**超频的两条线——核心与显存——分开调、分开测，用数据找各自的极限**。

## 8 小结

- 核心与显存**分开调、分开测**：核心超频掉驱动，显存超频花屏/ECC 涨。
- 核心超频**小步加频 + 烤机验证 + 退回上一档**，日常档留 20~30 MHz 余量。
- 显存超频看 **ECC 计数**——不花屏但 ECC 猛涨也是超频过头的信号。
- **降压超频**是性价比之王：同频降压，功耗降、温度降、噪音降。
- 显存超频收益有上限：**只有带宽瓶颈场景才吃得到**，先判断瓶颈在哪。
