## 为什么从本地备份开始

3-2-1 原则落地，第一步是「本地备份」——把 NAS 的数据复制到家里另一块介质上（外置硬盘、另一台 NAS）。本地备份是 3-2-1 里最容易实现、速度最快的一环，也是「异地备份」的前提（异地备份常先本地打包再上传）。<span class="marginnote">本专题把「本地备份」放在「云备份」之前，符合工程上的依赖顺序：先解决「NAS 崩了数据还在」（本地），再解决「家没了数据还在」（异地）。一步登天直接上云，往往因带宽与成本半途而废。</span>

本篇介绍两条主流路径：群晖的 **Hyper Backup** 与通用的 **Rsync**。

## 1 本地备份的形态：外置盘与另一台 NAS

本地备份的「目标介质」通常有两种：

**外置硬盘 / USB 硬盘**：最朴素、最便宜的方案。

插上 USB 硬盘，备份任务把 NAS 数据复制过去，完成后可拔下收好。
关键纪律：**备份完成后与 NAS 物理分离**（拔下放抽屉），否则同处一室且通电的两块盘，火灾/雷击/电源故障时可能一起遭殃。
- 容量约束：外置盘容量要 ≥ NAS 数据量，且要留出版本空间。

**另一台 NAS / 局域网存储**：更进阶的本地备份。

- 两台 NAS 之间通过备份协议互备，一台崩了另一台顶上。
- 适合数据量大、想要「异机」保障的用户；成本是第二台设备。

**辨析｜易错点：备份盘也要「体检」。** 备份盘同样会坏——「备份了」不等于「备份一定可用」。定期校验备份内容、抽查恢复，是备份体系里最容易被跳过、也最致命的一环。<span class="marginnote">「备份没有验证 = 没有备份」是运维铁律：备份任务显示「成功」只代表复制动作完成，不代表数据可恢复。每季度做一次「从备份恢复测试」，才是对备份真正的确认。</span>

## 2 Hyper Backup：群晖的备份工具箱

**Hyper Backup**：群晖的官方备份套件，支持多目的地、多模式、版本保留与完整性检查，是 DSM 用户本地备份的首选。

Hyper Backup 的关键能力：

**多目的地**：本地 USB 硬盘、另一台群晖（Synology NAS）、Rsync 服务器、云存储（S3、Azure、Google Drive 等）——一套任务覆盖本地与异地。
**多种备份模式**：全量、增量、以及**多版本备份**（保留每次快照，可回滚到任意版本点）。
- **应用与系统备份**：除了文件，还能备份套件配置、系统设置，甚至 Docker 容器配置。
- **完整性检查**：备份后自动校验数据一致性，回答「备份到底能不能用」。
- **智能回收**：按「保留策略」自动清理旧版本（如每天一份留 7 天、每周一份留 4 周）。

配置要点：

1. 建「备份任务」→ 选择目的地（外置盘/另一台 NAS）→ 勾选要备份的共享文件夹。
2. 设置「计划」：每周全量 + 每日增量是合理起点。
3. 设置「版本保留策略」与「完整性检查」频率。
4. **重要：至少每月手动跑一次「恢复测试」**，把某个版本恢复到测试位置确认可用。

<span class="marginnote">Hyper Backup 的价值在于「一套工具管全套」：本地、异地、版本、校验全在一个界面里。它把「备份」从「手工复制」升级成「可审计的自动化流程」——这正是「家庭数据中心」与「随便拷一份」的分水岭。</span>

## 3 Rsync：通用而强大的同步工具

**Rsync（Remote Sync）**：Unix/Linux 世界的经典同步工具，通过**增量传输**把源目录同步到目标，NAS 与 NAS、NAS 与 Linux 服务器之间的备份常用它。

Rsync 的核心特性：

**增量传输**：只传输变化的部分（按块对比），首次全量后每次备份极快。
**保留属性**：保留文件权限、时间戳、链接，适合目录结构精确同步。
- **配合 SSH**：通过 SSH 加密传输，安全可靠（群晖的「Rsync 备份」服务即基于此）。
- **通用性**：跨平台（Linux/macOS/群晖/威联通均支持），不绑定厂商。

典型用法：

```
rsync -avz --delete /volume1/数据 备份服务器:/backup/数据
```

参数解析：`-a` 归档模式（保留属性）、`-v` 显示过程、`-z` 压缩传输、`--delete` 删除目标端多余文件（保持两端一致）。

在群晖里启用：控制面板 → 文件服务 → Rsync → 开启 Rsync 服务；在「备份与复制」套件中建 Rsync 备份任务，或通过任务计划调用命令行。

**辨析｜易错点：Rsync 是「同步」，不是严格意义的「版本备份」。** 加了 `--delete` 后，源端删除的文件目标端也会删除——**同步保证「两边一样」，但不保留历史版本**。若想「回滚到一周前」，需要配合快照（下一节）或 rsync 的备份目录（`--backup`）实现。<span class="marginnote">Rsync 与 Hyper Backup 的分工：Rsync 擅长「保持多份数据完全一致」（同步、镜像），Hyper Backup 擅长「保留多个历史版本」（版本化备份）。前者管「一致」，后者管「回滚」——家庭备份建议两者搭配。</span>

## 4 核心对比表：Hyper Backup vs Rsync

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | Hyper Backup | Rsync |
| --- | --- | --- |
| 定位 | 版本化备份工具 | 同步/镜像工具 |
| 历史版本 | 支持（多版本） | 默认不保留 |
| 增量传输 | 支持 | 支持（按块对比） |
| 目的地 | 盘/群晖/Rsync/云 | 任意 SSH/Rsync 主机 |
| 加密传输 | 视目的地 | SSH 加密 |
| 界面 | 图形化 | 命令行 |
| 恢复验证 | 内置完整性检查 | 需自行验证 |

从表里能读出组合方案：**Hyper Backup 管「版本与回滚」，Rsync 管「镜像同步」**——家庭可「Hyper Backup 为主、Rsync 为辅」，或二选一从简开始。

## 5 小结

- 本地备份目标：**外置盘（物理分离）** 或 **另一台 NAS（异机保障）**。
- **Hyper Backup**：多目的地 + 多版本 + 完整性检查，群晖用户的备份首选。
- **Rsync**：增量同步、SSH 加密、通用跨平台，擅长「保持两端一致」。
- **备份不验证 = 没备份**：定期抽查恢复，是备份体系的最后一道确认。
- 组合建议：Hyper Backup 管版本回滚，Rsync 管镜像同步。
