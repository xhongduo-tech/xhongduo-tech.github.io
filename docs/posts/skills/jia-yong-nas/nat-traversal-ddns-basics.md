## 为什么从远程访问开始

NAS 装在家、数据也存家，但你不会永远坐在家里用。上班想看照片、出差要取文件、旅途中把手机照片备份回 NAS——**远程访问**是私有云「云」字的来源。而远程访问的第一道坎，是理解家用网络的结构：你的 NAS 在「内网」，外界在「外网」，两者之间隔着一道叫 NAT 的墙。<span class="marginnote">本专题把「远程访问」放在第 4 篇，是因为它绕不开前面所有基础：没有存储、系统、文件服务的铺垫，远程访问无从谈起；而没有安全的远程访问，私有云就名不副实。这一节先把「连接」的地基打好。</span>

本篇讲清两件事：**DDNS（让动态 IP 有个固定名字）** 与 **内网穿透（没有公网 IP 时怎么连进去）**。

先记住一句话总纲：远程访问的所有方案，本质都是在回答「外网如何到达内网」这一个问题——DDNS、端口转发、内网穿透是三种不同的答案，它们的取舍贯穿第 4 篇后续每一节。

## 1 内网与外网：NAT 的隔离

先建立一个基本模型。家庭网络通常长这样：

**内网**：路由器后面的局域网，NAS、电脑、手机共享一个私有网段（如 `192.168.1.x`）。内网地址只在局域网内有效。
**外网**：互联网。家用宽带的公网出口通常是一个 **公网 IP**。
**NAT（网络地址转换）**：路由器把内网设备的私有地址「翻译」成公网 IP 出门，把回来的数据「翻译」回对应内网设备。这是家用宽带让多台设备共享一个公网 IP 的机制。<span class="marginnote">NAT 的隔离副作用：外网主动发起的连接，找不到内网设备——除非路由器上做了「端口转发」规则（把公网某端口的流量转给内网某设备）。这既是安全的屏障，也是远程访问必须打洞的原因。</span>

**NAT 的两种形态**：家用最常见的是「一进一出」的简单 NAT；运营商机房还可能套一层 **CGNAT（运营商级 NAT）**，此时你家路由器拿到的都不是真公网 IP，远程访问只能靠内网穿透。判断自己属于哪一种，是选择远程方案的第一问——下一节给出判断方法。

远程访问的本质问题有两个：

1. **路径问题**：外网怎么找到你家的公网 IP，并穿过 NAT 到达 NAS？
2. **名称问题**：家宽的公网 IP 往往是**动态的**（运营商隔段时间就换），怎么让外部始终用一个固定名字找到你？

**DDNS** 解决第 2 个问题，**端口转发 / 内网穿透**解决第 1 个问题。

## 2 DDNS：让动态 IP 变成固定域名

**DDNS（Dynamic DNS，动态域名解析）**：把「变化的公网 IP」持续更新到一个固定域名上，让外部始终可以通过域名访问你。

原理：NAS 或路由器上的 DDNS 客户端定期检测当前公网 IP，变化时自动向 DDNS 服务商提交更新，把 `你的名字.example.com` 解析到新 IP。外网用户只需记住域名，不用关心 IP 怎么变。

使用前提：**你的宽带要有公网 IP**。判断方法：登录路由器查看「WAN IP」，与「在百度搜'IP'显示的地址」对比，一致则说明有公网 IP。

DDNS 的典型配置（群晖）：「控制面板 → 外部访问 → DDNS」→ 选择服务商（Synology 自带、或花生壳/No-IP 等）→ 注册域名 → 填入账号。配置完成后，`你的域名:端口` 即指向你家 NAS。

**DDNS 服务商怎么选**：

- **厂商自带**（Synology 的 `xxxx.synology.me`）：免费、零配置、与 NAS 深度集成，家庭用户首选。
- **传统 DDNS 商**（No-IP、花生壳、DuckDNS）：免费域名或自有域名解析，功能灵活，常需注册与定期续期。
- **云解析 + 脚本**：把域名托管到阿里云/腾讯云，用 API 脚本让 NAS 定时更新解析记录——自由度最高，适合已有域名的玩家。

**辨析｜易错点：有 DDNS 不等于能远程访问。** DDNS 只解决「域名→IP 的对应」，不解决「外网→内网的通路」。没有公网 IP 时，DDNS 解析到的是运营商 NAT 后不可用的地址，域名照样连不通——此时需要**内网穿透**。<span class="marginnote">把 DDNS 和端口转发分开记：DDNS 负责「知道你家在哪」（地址簿），端口转发负责「放外面的车进来」（开门）。地址簿 + 开门都齐了，远程访问才能通。</span>

## 3 内网穿透：没有公网 IP 的出路

如果宽带没有公网 IP（CGNAT 运营商大内网），DDNS 就失效了。**内网穿透（NAT Traversal / Tunneling）** 是另一条路：在 NAS 与一台「有公网 IP 的中继服务器」之间建立一条加密隧道，外部用户访问中继服务器，由隧道把流量转发到家里的 NAS。

典型实现：

- **厂商中转服务**：群晖 **QuickConnect**、威联通 **myQNAPcloud**——NAS 主动连接厂商服务器，用户通过厂商的「连接码/域名」访问，全程无需公网 IP、无需端口转发。这是「零配置」体验的来源（下一节详述）。
- **自建穿透**：用 **frp**、**Tailscale / WireGuard** 等工具，租一台轻量云服务器作中继，把 NAS 的服务映射到云服务器的端口。自由度最高，但要自己维护。

**自建穿透的两种风格**：

**frp 式（端口映射隧道）**：在云服务器上跑 frps，NAS 上跑 frpc，把「NAS 的 5000 端口」映射为「云服务器的 15000 端口」，外部访问 `云服务器IP:15000` 即到达 NAS。逻辑直白，但要自己管理云服务器与安全。

**Tailscale 式（虚拟局域网）**：所有设备登录同一账号，自动组成虚拟局域网，设备间点对点加密直连。不用专门租服务器、不用记端口——体验最接近「局域网」的穿透方案。

内网穿透的代价：**数据流量经中转服务器转发**，延迟更高、带宽受限；自建穿透还要操心中继服务器的安全。这也是为什么「有公网 IP 直连」仍是体验最好的方案。

**穿透方案的取舍一句话：厂商中转买省心，自建穿透买自由，Tailscale 买体验**——三者的共同点都是「绕开 NAT」，区别只在「谁提供中转」。

**DDNS 配置的五个常见坑**：

1. **域名解析延迟**：IP 变化后解析更新不是瞬时的，DNS 缓存会让旧 IP 生效几分钟到几十分钟——刚搬家/换网后连不上，先等缓存刷新。
2. **免费域名不续期**：部分免费 DDNS 域名需要定期「续签」，过期即被回收——绑个日历提醒。
3. **路由器与 NAS 都要配**：有的环境需要在路由器和 NAS 两头都开 DDNS，只配一头可能无效。
4. **DDNS 与端口转发要配套**：DDNS 给了域名，端口转发给了通路，缺一个都连不通——检查时要两个一起看。
5. **IPv6 时代的 AAAA 记录**：启用了 IPv6 的宽带，DDNS 也建议同步更新 IPv6（AAAA）记录，否则 IPv6 直连时域名解析不到。

**把远程访问想成「搭桥」**：DDNS 是桥的名字、端口转发是桥的承重结构、内网穿透是绕道的渡船、组网隧道是桥下的涵洞——不同条件下选不同的过河方式，才是「远程访问」这章的完整画面。本节是「概念地基」，接下来的几节逐一教你搭每一座桥。

## 4 核心对比表：DDNS vs 内网穿透

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | DDNS + 端口转发 | 厂商中转（QuickConnect 类） | 自建穿透（frp/Tailscale） |
| --- | --- | --- | --- |
| 需要公网 IP | 需要 | 不需要 | 不需要 |
| 配置难度 | 中 | 零 | 高 |
| 带宽/延迟 | 直连最优 | 受中转限制 | 受中转限制 |
| 数据路径 | 直接到你家 | 经厂商服务器 | 经你的云服务器 |
| 成本 | 域名费 | 免费 | 云服务器费用 |
| 自主可控 | 高 | 低 | 高 |

从表里能读出远程访问的优先级：**有公网 IP → 优先 DDNS 直连（体验最好）；没公网 IP → 厂商中转最省心，自建穿透最自由**。

**选择前的三个自问**：

1. **你家宽带有没有公网 IP？** 有 → DDNS + 端口转发；没有 → 穿透。
2. **你愿意维护几台设备？** 只想维护 NAS 一台 → 厂商中转；不介意租云服务器 → frp。
3. **你更看重速度还是省心？** 追求直连速度 → 想办法拿公网 IP；能接受中转 → 零配置优先。

这三个问题答完，你的远程访问路线图基本就出来了——多数家庭用户的答案是「厂商中转起步，等拿到公网 IP 再切 DDNS 直连」。

## 5 小结

- 远程访问的两个问题：**路径**（穿 NAT）与**名称**（动态 IP 变域名）。
- **DDNS** 把动态公网 IP 绑定到固定域名，解决「名称」问题。
- **端口转发**解决「路径」问题——但需要公网 IP；没有则走**内网穿透**。
- 厂商中转（QuickConnect 类）零配置，自建穿透（frp/Tailscale）自由但费心。
- 优先级：有公网 IP 直连 > 厂商中转 > 自建穿透。
- 选择路线图：先问「有没有公网 IP」，再问「愿不愿意多维护设备」。
