## 为什么从存储规划开始

前面几篇把硬盘、阵列、SHR 都讲透了，但「盘怎么组」只是存储的一半。另一半是**怎么把阵列组织成用户可用的空间**——这就要引入存储池、卷、文件系统三层概念。规划得好，未来扩容、备份、快照都顺畅；规划得差，可能面临「想开快照发现文件系统不支持」「想扩容发现当初没留盘位」的尴尬。<span class="marginnote">群晖与威联通的存储体系大同小异：群晖叫「存储池 + 卷」，威联通叫「存储池 + 卷」，底层逻辑一致，只是界面措辞不同。理解通用模型后，两家的向导都能看懂。</span>

本篇把三层概念拆开讲，并给出规划一份「建池检查清单」。

## 1 存储池与卷：两层抽象

**存储池（Storage Pool）**：由一块或多块物理盘按 RAID/SHR 组织而成的「硬件层容器」，它管的是「哪些盘、什么级别、多少冗余」。

**卷（Volume）**：在存储池上划分出的「逻辑层容器」，它管的是「用户能用多少空间、怎么分配」。卷是共享文件夹、应用数据的直接载体。

两层抽象的意义在于**解耦**：

加盘扩容 → 动的是存储池；
新建共享、装应用 → 动的是卷；
两者互不干扰，改一层不必重建另一层。

**辨析｜易错点：一个存储池可以建多个卷，也可以一个卷占满整个池，但卷不能跨存储池。** 这一点与「卷组」概念一致——卷的「地盘」被限定在它所属的存储池内。规划时要先想清楚「要不要分区」，例如「一个卷放系统与容器、另一个卷放影音」这种隔离，就需要在创建时规划好卷的划分。<span class="marginnote">是否多卷？建议：家庭数据量小的话，单存储池 + 单卷最省心；数据想按「快照策略」区分（如系统卷每天快照、影音卷不设快照），才值得拆多个卷。</span>

## 2 文件系统：ext4 与 Btrfs 的差别

卷之上还有一层：**文件系统**，决定卷内部如何存放文件、支持哪些高级特性。家用 NAS 最常见的两种是 **ext4** 与 **Btrfs**。

**ext4**：Linux 经典文件系统，成熟、稳定、性能好，但高级功能少——不支持原生快照，数据完整性校验有限。

**Btrfs（B-tree File System）**：现代写时复制（CoW，Copy-on-Write）文件系统，是群晖现代机型的默认推荐，也是威联通部分机型的可选文件系统。

Btrfs 给 NAS 带来的核心能力：

**原生快照（Snapshot）**：瞬间捕获卷在某个时刻的状态，用于版本回滚，几乎不占额外空间（写时复制，只有变化的数据才占空间）。<span class="marginnote">写时复制的直观理解：快照不是「复制一份数据」，而是「记下这一刻的指针」。之后改了某个文件，旧版本的数据块仍被快照引用、保留，新版本写到新块——这就是快照「瞬间完成、省空间」的奥秘。</span>
**数据自检**：定期校验数据块，发现静默损坏（bit rot）时结合阵列冗余自动修复。
**共享文件夹快照与回收站**：为单个共享文件夹做快照、开回收站，误删可找回。

威联通默认使用 ext4（部分型号可选 ZFS/Btrfs），群晖现代机型推荐 Btrfs——**只要系统支持，优先选 Btrfs/ZFS 这类现代文件系统**。

## 3 核心对比表：ext4 vs Btrfs

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | ext4 | Btrfs |
| --- | --- | --- |
| 成熟度 | 极高 | 高 |
| 原生快照 | 不支持 | 支持 |
| 数据自检/自愈 | 无 | 有（需阵列冗余配合） |
| 写时复制 | 无 | 有 |
| 回收站 | 共享文件夹级 | 共享文件夹级 |
| 适用 | 简单存储、兼容优先 | 需要快照与自检的现代 NAS |

从表里能读出结论：**家用 NAS 新建卷时，默认选 Btrfs（或威联通机型的 ZFS）**，它用很小的代价换来了快照与数据自检两项关键能力——这两项是后面「快照与版本回滚」章节的基础。

## 4 规划实战：建池前的检查清单

把理论落成可执行清单，创建存储池/卷之前逐项确认：

1. **盘位数与 RAID 级别**：按「数据量 × 增长预期」确定盘数与级别（2 盘 RAID 1、3–4 盘 SHR/RAID 5、数据重上 SHR-2/RAID 6）。
2. **预留热备盘位**：至少留 1 个空盘位，坏盘时即插即换，不必停机等新盘到货。
3. **文件系统**：默认 Btrfs/ZFS；若看重兼容或已在使用 ext4 旧池，可保持 ext4。
4. **卷的划分**：决定单卷还是多卷——默认单卷最省心，需要「按快照策略隔离」才拆多卷。
5. **系统盘位置**：系统、应用与数据是否分卷（分卷可避免应用日志写满影响数据卷）。
6. **确认后再操作**：创建存储池会清空盘上数据，**操作前确认盘上无未备份数据**。

<span class="marginnote">「先规划后建池」与「从极限到大模型」里反复强调的「先建模后求解」是同一方法论：存储的约束（盘数、容量、快照需求）就是模型的约束，池/卷/文件系统就是模型的解。规划一次到位，能省下后面大量迁移工作。</span>

## 5 小结

- **存储池**管物理盘组织，**卷**管可用空间，两层解耦、互不干扰。
- 卷**不能跨存储池**；单卷最省心，多卷用于「按快照/备份策略隔离」。
- **Btrfs**（及 ZFS）提供原生快照、数据自检、写时复制，是现代 NAS 的优先选择。
- 建池检查清单：盘位/级别 → 热备位 → 文件系统 → 卷划分 → 系统盘位置 → 确认清盘。
- 规划一次到位，避免未来「想快照发现不支持」的返工。
