## 为什么从 Docker 开始

NAS 的价值上限，一半由「能跑什么应用」决定。厂商套件中心的应用有限，但 **Docker 让 NAS 变成一个可以运行任意服务的应用平台**——影音、相册、下载、笔记、智能家居网关、甚至大模型推理工具，都能以容器形式跑起来。理解了 Docker，你的 NAS 就从「文件服务器」升级成了「家庭服务器」。<span class="marginnote">Docker 是「从极限到大模型」主线里 `容器与云原生` 专题的前置知识：NAS 上的容器部署是理解镜像、卷、端口映射的绝佳动手场景。本专题只讲「会用」，背后的隔离原理见第三级「容器与云原生」。</span>

## 1 Docker 是什么：镜像与容器

**Docker**：一种容器化技术，把应用及其运行环境（代码、依赖、配置）打包进一个标准化的**镜像（Image）**，运行时创建为隔离的**容器（Container）**。

两个核心概念：

**镜像（Image）**：只读的模板，包含应用运行所需的全部内容。类比「安装包」或「程序的快照」。镜像从 Docker Hub 等仓库拉取（`docker pull`）。
**容器（Container）**：镜像的运行实例，可启动、停止、删除。多个容器从同一镜像运行，互不影响。类比「装好的程序」。

Docker 与传统虚拟机（VM）的根本差别：VM 虚拟化整台机器（含操作系统），开销大；Docker 共享宿主机的操作系统内核，只隔离进程与文件系统，开销小、启动快。<span class="marginnote">这正是第三级「虚拟化与容器」专题要展开的核心对比：容器 = 共享内核 + 隔离命名空间（Namespace + Cgroup），虚拟机 = 独立内核 + 硬件虚拟化。家用 NAS 上跑容器，配置要求远低于跑虚拟机。</span>

NAS 上的 Docker 通常以图形化界面呈现：群晖叫 **Container Manager**，威联通叫 **Container Station**，TrueNAS 用 **Apps/Docker 集成**——背后都是同一套 Docker 引擎。

## 2 部署一个容器的三要素

在 NAS 图形界面里部署容器，无论哪个应用，都要理解三个核心配置项：

**镜像（Image）**：从镜像仓库拉取。指定 `镜像名:标签`，如 `jellyfin/jellyfin:latest`。**建议用明确的版本标签而非 `latest`**——`latest` 跟随上游更新，可能在未知时间点引入破坏性变化。

**端口映射（Port Mapping）**：把「容器的端口」映射到「NAS 的端口」。例如容器内部跑在 8096 端口，映射为 NAS 的 8096，访问 `NAS地址:8096` 即到达容器。<span class="marginnote">端口映射是容器网络的核心概念：容器像一栋楼里的房间，宿主机像大门。映射 = 给房间开一扇对外可见的门。映射到 NAS 的端口要避开系统已占用的端口，且记住「暴露到公网」的端口就是攻击面（第 4 篇会讲安全基线）。</span>

**卷挂载（Volume Mount）**：把 NAS 上的目录「挂进」容器内部，让容器读写宿主机的持久数据。例如把 NAS 的 `/media/电影` 挂到容器的 `/media`。**挂载是数据持久化的关键**——不挂载，容器删除后数据全部丢失。

三个概念对应一段标准 `docker run` 命令：

```
docker run -d --name jellyfin \
  -p 8096:8096 \
  -v /volume1/media:/media \
  jellyfin/jellyfin
```

对这条命令做三步拆解：`-d` 表示后台运行；`-p 8096:8096` 是端口映射（宿主机端口:容器端口）；`-v /volume1/media:/media` 是卷挂载（宿主机目录:容器目录）。看懂这三个参数，图形界面的每个输入框都能对上号。

## 3 部署实战：跑一个影音服务

以部署 Jellyfin（开源影音服务器，本专题第 5 篇会专章讲影音库）为例，走一遍标准流程：

1. **拉镜像**：在 Container Manager 的「注册表」搜索 `jellyfin`，拉取稳定版镜像。
2. **建容器**：创建容器，设置端口映射（`8096:8096`）与卷挂载（把 NAS 的影音文件夹挂进 `/media`）。
3. **配权限**：给容器指定访问该文件夹的用户权限（容器以特定用户运行，需能读取影音目录）。
4. **启动并验证**：启动容器，浏览器访问 `NAS地址:8096`，按向导添加媒体库。
5. **开机自启**：确认容器「随系统自动启动」选项开启，重启 NAS 后服务不丢。

**辨析｜易错点：容器删了，数据还在吗？** 取决于数据存哪——存「容器内」的数据随容器删除而消失；存「卷挂载的 NAS 目录」的数据则永久保留。**所有重要数据都应通过挂载落到 NAS 目录**，容器本身可以随时删除重建。<span class="marginnote">「容器可抛弃、数据要挂载」是容器运维的第一原则：容器随时删了重建，配置写进 compose 文件，数据留在挂载目录——这样升级应用只需重建容器，数据毫发无损。</span>

**升级应用的推荐姿势**：不要直接「更新运行中的容器」。正确流程是「停容器 → 拉新镜像 → 重建容器」——因为运行中的容器无法替换镜像。在图形界面里对应「停止 → 拉取新版本 → 用同一份配置再创建一个」。只要挂载与端口配置不变，新容器启动即接续旧数据，升级的破坏性几乎为零。

## 4 核心对比表：Docker 容器 vs 厂商套件

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | 厂商套件（Package） | Docker 容器 |
| --- | --- | --- |
| 安装 | 一键安装 | 拉镜像 + 建容器 |
| 更新 | 厂商控制 | 换镜像重建 |
| 生态 | 官方筛选 | 几乎无限（Docker Hub） |
| 隔离性 | 与系统耦合深 | 强隔离 |
| 数据 | 由套件管理 | 靠卷挂载持久化 |
| 学习成本 | 零 | 中 |

从表里能读出定位：**套件省心、容器自由**。家用建议「套件打底（官方应用）、容器补位（生态缺口）」——两者并不互斥，反而是组合拳。

## 5 数值算例：一台入门 NAS 能跑几个容器

容器轻量，但不等于「无限装」。用一台常见的入门 NAS（如 4 核 CPU、8GB 内存）做一次账，看看能跑多少个容器。

**先算内存**：内存是容器最硬的约束。常见容器内存占用大致为——影音服务器 Jellyfin 空闲约 500MB、下载工具 qBittorrent 约 200MB、密码管理器 Vaultwarden 约 150MB、智能家居网关 Home Assistant 约 300MB、监控类应用另算。假设你计划跑这 4 个，合计约 1.15GB。

**再留系统余量**：DSM/QTS 系统自身占 2GB 左右，文件服务（SMB、索引、缩略图）再占 1GB。8GB 内存里留给容器的实际可支配空间约 5GB——上面 4 个容器用 1.15GB，**只占计划额度的四分之一**，再跑 10 个类似规模的小容器也从容。

**CPU 与转码**：CPU 的瓶颈只在「实时转码」。Jellyfin 用 Intel 核显硬解时 CPU 占用极低；用纯 CPU 软解一部 4K HEVC 电影，四核处理器会顶到满载——所以影音转码容器要「预留一颗核」，下载、笔记类容器几乎不吃 CPU。

| 容器 | 内存占用（约） | CPU 压力 |
| --- | --- | --- |
| Jellyfin（影音） | 500MB | 转码时高 |
| qBittorrent（下载） | 200MB | 低 |
| Vaultwarden（密码） | 150MB | 低 |
| Home Assistant（智能家居） | 300MB | 低 |

账算完的结论：**内存看「总量」，CPU 看「转码」**。入门 NAS 跑 10 个以内的小容器绰绰有余；真正吃资源的只有影音转码，把它配置成硬件加速即可。<span class="marginnote">容器数量不是越多越好：每个容器都会随系统启动、占用少量内存与日志空间。<strong>「装完就用」比「装很多」更省心</strong>——不用的容器随手停止，让资源留给真正在用的服务。</span>

## 6 术语速查

- **镜像（Image）**：只读的应用模板，从镜像仓库（Docker Hub 等）拉取，如 `jellyfin/jellyfin`。
- **容器（Container）**：镜像的运行实例，可启动、停止、删除，互不影响。
- **端口映射（Port Mapping）**：把容器端口映射到 NAS 端口，形如 `-p 8096:8096`。
- **卷挂载（Volume Mount）**：把 NAS 目录挂进容器，形如 `-v /volume1/media:/media`，数据持久化的关键。
- **compose 文件**：用 `docker-compose.yml` 声明多容器的镜像、端口、挂载与网络，一行命令批量启停。
- **Container Manager / Container Station**：群晖与威联通的 Docker 图形界面，封装的是同一套 Docker 引擎——界面不同，概念全通。

## 7 小结

- **镜像**是只读模板、**容器**是运行实例；容器共享宿主机内核，轻量且启动快。
- 部署三要素：**镜像、端口映射、卷挂载**——`docker run` 的三个参数一一对应。
- 容器数据要**通过挂载落盘**，容器本身可随时删除重建。
- 套件与容器是组合拳：官方应用用套件，生态缺口用容器。
- 端口映射就是攻击面，容器端口暴露到公网前先想清楚安全。
