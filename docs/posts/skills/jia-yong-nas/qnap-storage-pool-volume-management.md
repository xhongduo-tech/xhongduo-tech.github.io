## 为什么从威联通的存储管理讲起

群晖与威联通都遵循「存储池 + 卷」的模型，但威联通的实现更有代表性：它把**静态卷（厚卷）与动态卷（精简卷）**的差别摆到了明面上，让用户被迫理解「空间分配」这件事。理解了威联通的这套设计，等于同时理解了群晖、TrueNAS 的卷管理——因为它们的底层逻辑完全一致，只是界面措辞不同。<span class="marginnote">本专题在群晖篇讲了 SHR 与 Btrfs，这一篇换威联通视角看同一个「存储池—卷」模型，为的是「一家操作、两家通吃」：看懂一家系统的卷类型设计，换系统时不会从头学起。</span>

本篇以威联通 QTS 为例，讲存储池与卷的创建、管理，以及厚卷/精简卷的取舍。

## 1 威联通的存储体系：从磁盘到卷

威联通 QTS 的存储层级：

**磁盘（Disk）→ RAID 组/存储池（Storage Pool）→ 卷（Volume）→ 共享文件夹**

与群晖完全同构，但两个细节不同：

**RAID 组即存储池**：威联通建存储池时直接选 RAID 级别（RAID 1/5/6/10，或 QTS 的 Qtier 自动分层），不提供类似 SHR 的混插自动优化——所以威联通对「盘容量一致」的要求更严格。
**存储池可以再分成卷**：一个存储池可划分多个卷，卷的类型分**厚卷**与**精简卷**。

**辨析｜易错点：威联通的「存储池」里如果只剩一个卷，卷通常会自动占满整个池**——这与「存储池 ≠ 卷」的直觉相悖。查看容量时要分清「存储池总空间」「卷已分配空间」两个数字，别把池的剩余空间当成卷的可用空间。<span class="marginnote">存储池与卷的关系，类比《操作系统》里的「物理内存与虚拟地址空间」：池是物理资源，卷是逻辑视角。池有剩余不代表卷可写，因为卷的配额是独立设置的——这是容量管理的常见盲区。</span>

## 2 创建流程：从建池到建卷

威联通 QTS 的标准创建流程：

**第一步，建存储池**：进入「存储与快照总管 → 存储池 → 创建」→ 选择 RAID 级别、勾选参与盘位、设置磁盘扫描策略。创建存储池会**清空所选盘上的数据**，务必先备份。

**第二步，建卷**：在存储池上「创建卷」→ 选择卷类型（厚卷/精简卷，见下节）、容量配额、文件系统（ext4 或 Btrfs/ZFS 视机型）。

**第三步，建共享文件夹**：在卷上创建共享文件夹，设置访问权限（复用上一篇的权限模型）。

**第四步，验证与观察**：确认卷出现在「共享文件夹」列表、局域网内其他设备能正常访问（下一节 SMB 挂载）。

整个过程与群晖高度一致，威联通的界面更「工程化」——每个选项都直接暴露，不替你隐藏细节，这正是它的学习价值所在。

## 3 卷类型：厚卷与精简卷

威联通把卷分成两类，核心差别在「空间是否预分配」：

**厚卷（Thick Volume，静态卷）**：创建时一次性从存储池划走全部配额空间。

优点：空间固定、可预测，快照与性能管理简单；写入时不会出现「存储池满了但卷以为还有空间」的意外。
缺点：不够灵活，配额占用的空间无法被其他卷借用。

**精简卷（Thin Volume，动态卷）**：只按需占用存储池空间，配额是「上限」而非「占用」。

优点：空间利用率高，多个精简卷可共享存储池剩余空间，扩容灵活。
- 缺点：必须监控存储池总剩余空间——**配额没用完也可能因池满而写不进去**；频繁分配/释放对性能略有影响。

**选型建议：数据量小、想省心 → 厚卷；数据量增长快、想灵活利用池空间 → 精简卷 + 监控池余量。** 对绝大多数家庭用户，厚卷更稳妥——因为「池满导致写失败」的意外，比「空间浪费」更难排查。<span class="marginnote">精简卷的「池满风险」与虚拟化的「超量分配（overcommit）」是同一问题：多个卷各说各有 5TB，池实际只有 8TB，全写满时必然有人失败。理解了精简卷，就理解了云计算里「存储超卖」的工程权衡。</span>

## 4 核心对比表：厚卷 vs 精简卷

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | 厚卷（静态卷） | 精简卷（动态卷） |
| --- | --- | --- |
| 空间分配 | 创建时预分配 | 按需增长 |
| 空间利用率 | 低（可能闲置） | 高 |
| 池满风险 | 低 | 高（需监控池余量） |
| 扩容 | 需扩展卷或新建 | 配额内自动增长 |
| 性能 | 稳定 | 略有波动 |
| 适合场景 | 省心、量小 | 增长快、想灵活 |

从表里能读出结论：**厚卷买「确定性」，精简卷买「灵活性」**——家用默认厚卷，除非你明确要共享池空间。

## 5 小结

- 威联通存储层级：**磁盘 → 存储池 → 卷 → 共享文件夹**，与群晖同构。
- 建池清空数据，操作前先备份；存储池与卷的容量要分开看。
- **厚卷**预分配、稳定、省心；**精简卷**按需增长、灵活但需监控池余量。
- 家用默认厚卷；精简卷的价值在「池空间共享」，代价是池满写失败的意外。
- 存储管理通三系统：看懂一家，群晖/威联通/TrueNAS 的卷模型即通。
