## 为什么从 HTTPS 开始

前几节讲了「怎么连上 NAS」——但连接本身只解决了「通路」，没有解决「安全」。当你在地铁 Wi-Fi、酒店网络访问 NAS 时，明文数据可能被旁人截获：账号密码、照片、文件一览无余。**HTTPS 就是给这条「通路」加上加密层**，让 NAS 的远程访问从「裸奔」变成「穿盔甲」。<span class="marginnote">密码学是「从极限到大模型」里《密码学与信息安全》专题的内容，这里只取家用 NAS 需要的切片：HTTPS = HTTP + TLS。TLS 负责加密与身份验证，证书负责「证明服务器是真的 NAS」。</span>

本篇讲清 HTTP 与 HTTPS 的差别、SSL/TLS 证书的角色，以及家用 NAS 上证书怎么配。

## 1 HTTP 与 HTTPS：明文与加密

**HTTP（超文本传输协议）**：浏览器与服务器之间传输网页数据的协议。缺陷：**明文传输**——数据在网络上以原始形式传递，中间任何节点（Wi-Fi 热点、运营商、路由器）都能读取或篡改。

**HTTPS（HTTP Secure，HTTP 安全版）**：在 HTTP 之上叠加 **TLS（传输层安全协议）**，对数据加密后再传输。效果：

**机密性**：即使数据被截获，没有密钥也读不懂。
**完整性**：数据在传输中若被篡改，接收方能检测出来。
- **身份验证**：证书证明「你连接的就是你家的 NAS」，防止中间人冒充。

家用 NAS 为什么要 HTTPS：

- 远程访问时，登录密码若明文传输，等于把家门钥匙交给路上的每个人。
- 浏览器对非 HTTPS 站点会显示「不安全」警告，体验与信任都受损。
- 群晖/威联通默认支持 HTTPS（群晖 DSM 默认 5001 端口），配置成本极低。

**辨析｜易错点：HTTPS 加密的是「传输过程」，不是「存储安全」。** HTTPS 保护数据在网络上不被窃听；数据存进 NAS 后是否安全，取决于权限、加密卷、备份等另一套体系。两者是「路」与「仓库」的分工——别以为开了 HTTPS 就万事大吉。<span class="marginnote">把 HTTPS 与「数据加密存储」分开记：HTTPS 管「在路上」，全盘加密/加密卷管「在库」。家用场景最常见的误解是把 HTTPS 当成数据安全的全部，实际上它只是传输层的保障。</span>

## 2 SSL/TLS 与证书：谁来证明「你是谁」

**SSL/TLS**：加密协议（SSL 是旧名，现代都叫 TLS）。它用**非对称加密 + 对称加密**的组合完成「安全握手」。

握手的核心流程（简化为三步）：

1. **客户端 → 服务器：你好，请证明你是谁**：服务器出示自己的**数字证书**。
2. **客户端验证证书**：证书由受信任的**证书颁发机构（CA）**签发，客户端用 CA 的公钥验证证书真伪，并取出服务器公钥。
3. **协商会话密钥**：双方用公钥加密机制安全地商定一个临时的**会话密钥**，之后所有数据都用这把密钥做对称加密传输——快且安全。

**数字证书（Certificate）**：把「服务器身份 + 公钥」绑定在一起、由 CA 签名盖章的电子文档。家用 NAS 场景常见两类证书：

**自签名证书（Self-Signed）**：NAS 自己生成的证书，没经过第三方 CA 盖章。加密能力一样，但浏览器会报「不受信任」——因为没有第三方为「你是你」背书。
**权威 CA 证书**：由 Let's Encrypt 等免费 CA 签发，浏览器直接信任，地址栏显示小锁。

<span class="marginnote">证书的本质是「第三方担保」：自签名证书相当于「自己给自己开证明」，可信度只在你我之间；CA 证书相当于「权威机构开证明」，所有人都认。家用 NAS 用 Let's Encrypt 免费证书，就能获得浏览器完全信任的 HTTPS。</span>

## 3 证书部署：自签名 vs Let's Encrypt

家用 NAS 上证书怎么配？两条路：

**路线一：Let's Encrypt 免费权威证书（推荐）**

前提：有域名（DDNS 域名即可）+ 该域名能访问到 NAS。
群晖：「控制面板 → 安全性 → 证书 → 新增 → Let's Encrypt」，填入域名与邮箱，群晖自动完成申请与续期。
- 效果：浏览器完全信任，地址栏小锁，访问 `https://你的域名` 无警告。
- 注意：Let's Encrypt 证书有效期 90 天，群晖/威联通会自动续期，无需手动干预。<span class="marginnote">Let's Encrypt 把「HTTPS 证书」从付费服务变成了免费、自动化的公共服务——它用 ACME 协议让服务器自动完成「域名验证 → 签发 → 续期」整个流程。NAS 系统已内置 ACME 客户端，填域名即可。</span>

**路线二：自签名证书（临时/内网用）**

- 群晖在启用 HTTPS 时可生成自签名证书，内网访问可用，但浏览器有警告。
- 适合：纯内网使用、或公网访问走「组网工具加密隧道」、不需要浏览器信任的场景。
- 局限：外网直连时警告吓人，且无第三方背书。

**配置 HTTPS 的完整建议：**

1. **远程访问走 HTTPS**：远程访问入口一律 HTTPS，杜绝明文登录。
2. **本地也尽量 HTTPS**：局域网访问默认也切到 HTTPS，统一体验。
3. **HTTP 可重定向到 HTTPS**：系统设置里把 HTTP 流量重定向到 HTTPS，避免误走明文。
4. **证书要续期**：自签名证书到期需手动更新，Let's Encrypt 自动续期更省心。

## 4 核心对比表：自签名 vs 权威 CA 证书

本篇的核心对比表如下（纯概念主题，以表格替代公式解析）：

| 维度 | 自签名证书 | Let's Encrypt 证书 |
| --- | --- | --- |
| 颁发者 | NAS 自己 | 权威 CA（免费） |
| 浏览器信任 | 不信任（警告） | 完全信任 |
| 加密能力 | 相同 | 相同 |
| 获取成本 | 零 | 免费 + 需域名 |
| 续期 | 手动 | 自动（90 天） |
| 适用场景 | 内网/隧道 | 公网直连 |

从表里能读出结论：**有域名就上 Let's Encrypt（浏览器信任 + 自动续期），没域名或纯内网才退而用自签名**。

## 5 小结

- **HTTPS = HTTP + TLS**，提供机密性、完整性、身份验证三保障。
- HTTPS 加密「传输过程」，不负责「存储安全」——两者是路与仓库的分工。
- **证书**把「身份 + 公钥」绑定并由 CA 背书；自签名证书自己证明自己，权威证书第三方担保。
- 家用推荐 **Let's Encrypt 免费证书**：浏览器信任 + 自动续期。
- 配置要点：远程与本地都走 HTTPS、HTTP 重定向到 HTTPS、证书确保续期。
