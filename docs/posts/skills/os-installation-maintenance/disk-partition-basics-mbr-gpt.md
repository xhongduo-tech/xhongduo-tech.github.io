## 为什么从磁盘分区开始

操作系统的一切都「住」在磁盘上，而磁盘不是一整块拿来就用，要先被切成若干区域，这个行为就叫**分区（partition）**。分区决定了系统装在哪、数据存哪、开机从哪里引导，也决定了你能用多少容量、能装几个系统。可以说，**分区是操作系统与硬件之间第一层契约**——装系统时你选分区，就是在签这份契约；选错了，轻则容量浪费，重则整盘数据无法引导。

鸟哥在《基础学习篇》第2章「主机规划与磁盘分区」和第7章「Linux 磁盘与文件系统管理」里，用两章的篇幅把「分区 → 文件系统 → 挂载」这条线讲透。本节先把两张「分区表」（MBR 与 GPT）和常见文件系统一次说清，后面的分区实战才有地基。

## 1 磁盘的物理结构：扇区、磁道与 LBA

先回到物理层。传统机械硬盘（HDD）由盘片、磁头、磁道组成，盘片被同心圆分成一圈圈**磁道（track）**，每个磁道又被分成一段段**扇区（sector）**——扇区是磁盘读写的最小物理单位。<span class="marginnote">传统扇区大小为 512 字节；2009 年后行业转向「先进格式化」（Advanced Format），物理扇区为 4 KiB，逻辑扇区仍报告为 512 字节以便兼容。4K 扇区与系统不对齐时，小文件读写会明显变慢。</span>

为了方便寻址，磁盘控制器把所有扇区从 0 开始**线性编号**，这个编号叫 **LBA（逻辑块寻址）**。操作系统不关心物理磁道，只跟 LBA 打交道——这就是「分区」能被实现的前提：分区本质上就是一段连续的 LBA 区间。

**重点：分区表就是记录「哪段 LBA 归谁、类型是什么」的登记簿。** 这张登记簿用两种格式写，就是 MBR 与 GPT。而「对齐」这个词也在这里第一次登场：分区起点若不在 4K 物理扇区边界上，每次读写都要跨越两个扇区，性能打折，这就是老教程常说的「4K 对齐」。

## 2 MBR：只懂四个主分区的老前辈

**MBR（Master Boot Record，主引导记录）** 位于磁盘最开头的 0 号扇区，它同时干两件事：存放引导代码，以及存放分区表。

一个 512 字节的 MBR 扇区布局如下：

| 偏移 | 内容 | 大小 |
| --- | --- | --- |
| 0 | 引导代码（boot loader） | 446 字节 |
| 446 | 分区表（4 个分区表项） | 64 字节 |
| 510 | 结束标志 `0x55AA` | 2 字节 |

每个分区表项固定 **16 字节**，因此 MBR 最多记录 **4 个主分区**。想要超过 4 个，就必须把某个主分区设为**扩展分区（extended partition）**，再在它内部划分多个**逻辑分区（logical partition）**——这是 MBR 时代绕开数量限制的妥协方案。<span class="marginnote">扩展分区里嵌套逻辑分区，是老手电脑里「一个主分区 + 若干逻辑分区」的来历。现代 GPT 直接干掉了这套嵌套，这也是 GPT 更受欢迎的原因之一。</span>

MBR 最大的硬伤是**容量上限**：它用 32 位整数表示扇区号，2^32 × 512 字节 = 2 TiB。超过 2 TiB 的磁盘，MBR 无从记录，详见第6节的公式解析。

## 3 GPT：面向大磁盘的新格局

**GPT（GUID Partition Table，GUID 分区表）** 是 UEFI 时代的标准分区表，随 2000 年代初的 EFI 规范一同登场。它彻底抛弃了 MBR 的「一个扇区里挤分区表」的做法，改用一套冗余、带校验的结构：

- **保护性 MBR（Protective MBR）**：磁盘最前端保留一个假的 MBR 扇区，防止老工具误认磁盘为空盘而覆盖。
- **分区表头 + 分区表项**：位于 LBA 1 起，用 GUID（全局唯一标识符）标识每个分区。
- **备份分区表**：磁盘末尾再存一份完整的分区表副本，主表损坏时可恢复。
- **CRC32 校验**：每次读写都校验分区表完整性，避免静默损坏。

GPT 的优势是碾压式的：分区数量最多 **128 个**（Windows 默认），单分区容量支持到 9.4 ZB（2^64 × 512B），远超现有硬件；每个分区有 GUID 与名称，语义清晰。<span class="marginnote">GPT 与 UEFI 是配套关系：UEFI 固件只认 GPT 磁盘上的引导分区（ESP）。反过来，传统 BIOS 也能引导 GPT 磁盘，但必须借助 GRUB 等支持 BIOS-BOOT 的引导器，较麻烦。</span>

## 4 文件系统：分区里的一层「整理术」

分区只是划分出「一片空间」，要在里面存文件，还必须给它格式化成一种**文件系统（filesystem）**——文件系统负责把字节组织成文件、目录、权限与日志。分区是容器，文件系统是容器里的整理术，二者不能混为一谈。

常见文件系统速查：

| 文件系统 | 所属平台 | 典型用途 | 特点 |
| --- | --- | --- | --- |
| NTFS | Windows | 系统盘、数据盘 | 日志、权限、压缩，Windows 默认 |
| FAT32 | 通用 | 启动 U 盘、跨平台交换 | 兼容性最好，单文件上限 4 GiB |
| exFAT | 通用 | 大容量移动硬盘 | 无 4 GiB 限制，跨 Win/mac |
| ext4 | Linux | 根分区、数据分区 | 日志、稳定，发行版默认 |
| xfs | Linux | 大文件、大数据 | 高吞吐，Red Hat 系默认 |
| APFS | macOS | 系统盘 | 苹果 2017 年起默认，支持快照 |
| swap | Linux | 交换分区 | 不是文件系统，是「虚拟内存」落盘 |

Windows 里 U 盘启动盘必须用 **FAT32**，因为 UEFI 固件只识别 FAT32 的引导分区；Linux 桌面发行版普遍用 **ext4**；macOS 从 High Sierra 起全面转向 **APFS**。<span class="marginnote">鸟哥在第7章用「把大象装进冰箱」来类比：分区是分好格的冰箱，文件系统是决定每个格子怎么放物品的规则。`mkfs` 命令就是「给分区盖戳，声明它用哪种规则」。</span>

**辨析｜易错点：** 「分区」和「文件系统」常常被混说，但它们完全是两层东西。一个分区只有经过格式化（写文件系统）才能用；你可以把分区表看成「楼房的户型」，文件系统是「每个房间怎么摆家具」。格式化会清空分区里的数据，所以「给 D 盘格成 exFAT」之前，先确认里面没有要留的东西。

## 5 引导分区（ESP）与挂载点：分区的实际应用

分区理论最终要落成两件事——**系统怎么引导**、**系统怎么用**：

- **UEFI 引导分区（ESP）**：FAT32 格式，存放 `.efi` 引导文件，Windows 下叫「EFI 系统分区」（约 100–300 MB），Linux 下通常挂载在 `/boot/efi`。
- **Windows 系统保留区**：安装器会额外建「MSR（Microsoft Reserved）」与「恢复分区（Windows RE）」，分别约 16 MB 与 500–750 MB，不要手痒删掉。
- **Linux 挂载点（mount point）**：挂载点就是「把分区接进目录树的位置」，如 `/` 根分区、`/home`、`/boot`、`swap`。分区是物理的，挂载点是逻辑的——同一块分区可以重新挂载到别处，这是 Linux 分区最灵活的所在，详见《Linux 自定义分区与挂载点规划》。<span class="marginnote">挂载（mount）是 Linux 文件系统的灵魂概念：插上 U 盘后要 `mount` 才能看到内容，`df -h` 查看谁挂在哪。Windows 把分区固化为「盘符 C:/D:」，Linux 则统一到一棵目录树里，这是两种哲学的分水岭。</span>

## 6 公式解析：2 TiB 上限是怎么算出来的

MBR 容量上限的公式，是整节唯一值得拆解的算式：

$$
\text{最大可寻址容量} = 2^{32} \times 512 \,\text{B} = 2^{32} \times 2^9 = 2^{41} \,\text{B} = 2 \,\text{TiB}
$$

分三步拆解：

- **第一步，扇区号是 32 位**：MBR 用 32 位二进制数编号扇区，能表示的最大编号是 $2^{32} - 1$，即最多 $2^{32}$ 个扇区。
- **第二步，每个扇区 512 字节**：传统扇区大小是 512 B，所以总容量 = 扇区数 × 512 B。
- **第三步，换算成 TiB**：$2^{41}$ B，因为 1 TiB = $2^{40}$ B，所以 $2^{41}$ B = 2 TiB。这就是「MBR 认不了超过 2 TiB 的盘」的数学根源。

GPT 把扇区号从 32 位提到 64 位，容量上限骤增至 $2^{64} \times 512$ B ≈ 9.4 ZB——这个数量级在可预见的未来都不会被耗尽。

## 7 补充速查：MBR 与 GPT 对照表

把两种分区表的差异收敛成一张对照表，装机前扫一眼：

| 对比项 | MBR | GPT |
| --- | --- | --- |
| 分区数量 | 4 主分区（可扩） | 最多 128 |
| 容量上限 | 2 TiB | 约 9.4 ZB |
| 引导入口 | 446 字节引导代码 | ESP 里的 `.efi` |
| 保护机制 | 无 | CRC32 + 备份表 |
| 配套固件 | Legacy BIOS | UEFI |
| 扩展分区 | 有（嵌套） | 无此概念 |
| 适用 | 老电脑、小磁盘 | 新电脑、大磁盘 |

## 8 小结

- 磁盘最小读写单位是**扇区**（512 B / 4K），用 **LBA 线性寻址**；分区就是一段连续的 LBA 区间。
- **MBR**：0 号扇区放引导代码 + 64 字节分区表，最多 **4 个主分区**（或扩展分区里套逻辑分区），容量上限 **2 TiB**。
- **GPT**：保护性 MBR + 带 CRC32 校验的冗余分区表，最多 128 个分区，支持超大容量，与 UEFI 配套。
- **分区是容器，文件系统是整理术**；NTFS/FAT32/exFAT/ext4/APFS 各有定位，启动盘多用 FAT32。
- UEFI 引导靠 **ESP（FAT32）**；Linux 用**挂载点**把分区接进目录树。
- **UEFI 配 GPT，Legacy 配 MBR**，配对才能正常引导。
