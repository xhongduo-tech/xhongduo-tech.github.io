## 为什么从引导模式开始

计算机按下电源键后，第一件事不是「启动操作系统」，而是运行一段固化在主板芯片里的程序——**固件（firmware）**。固件负责自检硬件、初始化设备，然后把控制权交给磁盘上的引导器。这段「从通电到引导器」的过程，就是**引导（boot）**。它离普通用户很远，却离安装成败最近：装系统时选错引导模式，装完就「无法开机」，这是新手上路遇到的第一堵墙。

现代固件分两代：传统 **BIOS** 与新一代 **UEFI**。本节讲清两者的区别、与磁盘分区表的配对关系，以及「让 U 盘能被固件认出来」的启动介质制作原理——它是后续三篇（Windows、Linux、macOS 介质制作）的共同地基。

## 1 从 BIOS 到 UEFI：固件的一场革命

**BIOS（Basic Input/Output System，基本输入输出系统）** 诞生于 1975 年的 IBM PC 时代，它以 16 位实模式运行，功能简单：上电自检（POST）、初始化硬件、然后试图从第一个引导设备加载引导扇区。它支持的设备接口、启动菜单能力都非常有限，且无法提供图形化交互。<span class="marginnote">BIOS 时代从 MBR 引导：固件把 0 扇区的 446 字节引导代码读入内存执行，引导代码再去找活动分区里的引导器。整个过程一环套一环，任何一环出错都会「黑屏」。</span>

**UEFI（Unified Extensible Firmware Interface，统一可扩展固件接口）** 由 Intel 于 2002 年提出 EFI 规范，后移交 UEFI 论坛维护。它运行在 32/64 位模式，有自己的驱动模型与文件系统支持（能直接读取 FAT32），还支持**安全启动（Secure Boot）**——用数字签名校验引导器的合法性，防止恶意软件在引导阶段劫持系统。<span class="marginnote">Secure Boot 是 UEFI 最有争议也最有价值的能力：它要求引导器有合法签名。Windows 10/11 都依赖它防 rootkit；但装 Linux 时若不开相应签名（如部分发行版需要自己在固件里注册密钥），可能无法引导——这是双系统新手常踩的坑。</span>

## 2 两种引导模式的技术分水岭

两种模式的分水岭，在于「引导器住在哪、怎么被执行」：

**BIOS（Legacy）引导路径：** 固件读磁盘 **0 号扇区（MBR）** 的 446 字节引导代码 → 引导代码找活动分区 → 执行该分区的引导器（如 `bootmgr`、GRUB）→ 引导操作系统。依赖 MBR，最多 2 TiB 磁盘。

**UEFI 引导路径：** 固件直接查找 **ESP（EFI System Partition，FAT32 格式）** 里的 `.efi` 引导程序，例如 Windows 的 `\EFI\Microsoft\Boot\bootmgfw.efi` 或 Linux 的 `\EFI\grub\grubx64.efi` → 执行它 → 引导操作系统。不依赖 MBR，天然支持 GPT 大磁盘。

**重点：UEFI 引导只认「GPT 磁盘上的 FAT32 引导分区」；BIOS 引导只认「MBR 磁盘的活动分区」。** 这就是「UEFI 配 GPT、Legacy 配 MBR」的根源——硬要交叉，装完就无法引导。这句话值得背下来，它是整个专题里重复率最高的判断标准。

## 3 核心对比表：BIOS 与 UEFI

| 对比项 | BIOS（Legacy） | UEFI |
| --- | --- | --- |
| 诞生年代 | 1975 年 IBM PC | 2002 年起（EFI） |
| 运行模式 | 16 位实模式 | 32/64 位 |
| 引导入口 | MBR 446 字节引导代码 | ESP 里的 `.efi` 文件 |
| 磁盘格式 | MBR（≤2 TiB） | GPT（支持超大容量） |
| 安全能力 | 无 | Secure Boot 签名校验 |
| 界面 | 文字蓝屏菜单 | 图形化，支持鼠标 |
| 启动速度 | 慢 | 快（并行初始化） |

新电脑几乎都是 UEFI。只有 2012 年前的老主板才纯 BIOS；多数现代主板还保留一个 **CSM（Compatibility Support Module）** 兼容层，用于模拟 BIOS 以引导旧系统——但它只是兼容，不推荐依赖，因为它会关闭 UEFI 的很多安全与速度特性。

## 4 引导模式与系统安装的对应

理解了上面的配对关系，安装时的「引导模式报错」就都能看懂：

- **Windows**：安装镜像里同时含 UEFI 与 Legacy 两套引导文件，系统会根据你从哪种模式启动介质而自动选择，并要求磁盘分区表与之匹配。<span class="marginnote">Windows 装到 UEFI 模式下却选了 MBR 磁盘，或 Legacy 模式配 GPT，安装程序会直接报「无法安装到该磁盘」或「引导模式不匹配」，此时只需转换分区表或换启动方式。</span>
- **Linux**：鸟哥第3章强调，安装时选择「UEFI 安装」就会自动建 ESP（通常 100–500 MB，FAT32）与 `/boot/efi` 挂载点；GRUB 会被装成 `.efi` 版本。
- **macOS**：Mac 从 Intel 时代的 EFI 起步，天然 UEFI；不需要用户操心配对。

一个实用判断技巧：进固件设置（BIOS Setup）看有没有「CSM」或「UEFI/Legacy」开关，凡是 2015 年后出厂的主板，默认就是 UEFI 模式，安装介质也应按 UEFI 来做。

## 5 启动介质制作：让 U 盘能被固件认出来

制作启动 U 盘的本质，是**让 U 盘具备「固件能识别的引导结构」**。对 UEFI 来说，U 盘必须满足两点：

- **文件系统是 FAT32**——UEFI 固件只读得懂 FAT32（U 盘默认 FAT32 即可，别格成 NTFS 或 exFAT）。
- **引导文件放在 `\EFI\` 目录**——镜像里的 `efi` 目录被复制到 U 盘根目录，固件就能找到它。

这正是「为什么不能「右键→格式化→把 ISO 解压进去」」的原因：ISO 是镜像文件，直接解压会丢失引导结构。正确做法是用工具「整盘写入镜像」，把 ISO 的引导区也写进去。工具差异见后续三篇：Windows 用微软媒体创建工具或 Rufus，Linux 用 `dd` 或 Ventoy，macOS 用 `createinstallmedia`。<span class="marginnote">Ventoy 是一种特殊做法：把 U 盘装成「多系统启动盘」，之后只需把任意 ISO 文件拷贝进去就能启动，不必反复刷写。对经常装系统的人非常省事。</span>

## 6 动手：验证一台电脑的引导模式

学到这里，值得亲自验证一次「我的电脑是哪种引导模式」，方法三选一：

- **Windows**：`Win+R` 运行 `msinfo32`，看「BIOS 模式」一栏——显示「UEFI」就是 UEFI 引导，显示「传统」就是 Legacy。
- **Linux**：`ls /sys/firmware/efi` 若存在 `efi` 目录，说明当前是 UEFI 引导；或查 `efibootmgr` 是否有输出。
- **固件界面**：重启进 BIOS Setup，看启动模式设置项。

这个「体检」很有用：装系统前先确认目标机器是 UEFI 还是 Legacy，介质与分区就按对应方式做，能避免一大半「装完起不来」的悲剧。

## 7 补充速查：引导模式判断与启动介质检查清单

把「我是哪种引导模式、U 盘对不对」做成一张体检表：

| 检查项 | 方法 | 判断 |
| --- | --- | --- |
| 本机引导模式（Windows） | `Win+R` → `msinfo32` → BIOS 模式 | UEFI / 传统 |
| 本机引导模式（Linux） | `ls /sys/firmware/efi` | 有 efi 目录 = UEFI |
| 固件设置入口 | 开机按 Del/F2/F10/F12 | 各主板不同 |
| 启动菜单入口 | 开机按 F12/F11 | 临时选启动设备 |
| CSM 是否开启 | 固件设置里查 CSM | 老系统才需要 |
| Secure Boot | 固件设置里查 | 装 Linux 遇阻先看它 |
| U 盘文件系统 | 磁盘管理/属性 | 启动盘应是 FAT32 |
| U 盘引导文件 | 看根目录是否有 `efi` 目录 | 有 = UEFI 引导结构 |
| 启动失败排查 | 介质 → 引导模式 → 固件设置 | 按顺序来 |

## 8 补充速查：引导相关的常见报错

把引导环节的高频报错与处理收敛成一张速查表：

| 报错/现象 | 原因 | 处理 |
| --- | --- | --- |
| 「找不到操作系统」 | 引导顺序/活动分区问题 | 设启动盘、修引导 |
| 「Boot Device Not Found」 | 固件找不到启动设备 | 查 BIOS 启动顺序 |
| 「引导模式不匹配」 | UEFI 配了 MBR 等 | 转换分区表 |
| U 盘启动不了 | 文件系统/引导结构问题 | 重做 FAT32 启动盘 |
| Secure Boot 拦截 | 未签名引导器 | 临时关闭或注册密钥 |
| 装完无法引导 | 配对关系错 | 重装引导器 |

## 9 小结

- 引导是**固件 → 引导器 → 操作系统**的接力；固件分 **BIOS** 与 **UEFI** 两代。
- **UEFI 配 GPT、Legacy 配 MBR**，交叉配对会导致装完无法引导。
- UEFI 从 **ESP（FAT32）里的 `.efi` 文件**引导，支持 **Secure Boot** 签名校验。
- BIOS 读 **MBR 0 号扇区**的 446 字节引导代码，最多 4 个主分区、2 TiB 上限。
- 制作启动 U 盘的关键：**FAT32 + 整盘写入镜像**，别直接解压 ISO。
- 用 `msinfo32`（Windows）或 `ls /sys/firmware/efi`（Linux）确认本机引导模式，再决定介质怎么配。
