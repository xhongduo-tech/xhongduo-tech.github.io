## 为什么从备份开始

这一节的标题看似「老生常谈」，却是整个专题最值钱的一节。前面讲过修驱动、修引导、修磁盘，但有一类损失谁也修不回来——**没备份的数据**。硬盘可能突然报废、勒索软件可能加密全盘、误操作可能清空分区，唯一能让你「回到昨天」的手段，就是备份。

鸟哥在《基础学习篇》第8章「文件与文件系统的压缩、打包与备份」里，把 `tar`、`dd`、rsync 这些备份工具讲透。本节把它和三平台的官方备份方案（Windows 文件历史/系统映像、macOS Time Machine）放在一起，并重申贯穿全专题的 **3-2-1 原则**，最后给你一套能落地执行的备份体系。

## 1 备份的三层目标：先想清楚要保什么

备份不是「把文件复制一份」这么简单，先分清三层：

| 层级 | 保什么 | 典型工具 |
| --- | --- | --- |
| 文件备份 | 个人文档、照片、配置 | 云盘、文件历史、rsync |
| 系统备份 | 能还原到「某个时刻的系统状态」 | 系统映像、Time Machine |
| 镜像/整盘备份 | 整个磁盘原样复制 | `dd`、克隆工具 |

<span class="marginnote">一个常见误区：以为「把文件拷到移动硬盘」就是备份。那是「文件备份」，只能找回文件，找回不了「系统的那个时刻」。想「出问题一键回到一周前」，需要的是<strong>系统级备份</strong>（Windows 系统映像 / Time Machine / Linux tar 打包系统目录）。</span>

**重点：备份的价值在于「能还原」，而不在于「存了多少」。** 定期验证「能不能真的还原」，比勤快备份更重要——没有验证过的备份，约等于没有备份。

## 2 Windows：文件历史、还原点与系统映像

Windows 提供三档备份，从轻到重：

- **文件历史（File History）**：自动备份「文档、图片、桌面、下载」等个人文件夹到外部盘/网络盘，按时间点保留多个版本。
- **系统还原点（System Restore）**：为系统关键文件与设置拍「快照」，出问题时回到还原点。默认自动创建。
- **系统映像备份（System Image）**：整个系统分区（C:）的完整映像，可从「控制面板 → 备份和还原（Windows 7）→ 创建系统镜像」制作，配合「系统映像恢复」还原整机。<span class="marginnote">Windows 11 里「文件历史」被集成进「设置 → 系统 → 存储 → 高级存储设置 → 备份选项」，核心是「文件历史记录」；系统映像在「控制面板 → 备份和还原（Windows 7）」里（藏在较深的位置，但功能仍在）。</span>

**判断要点：** 普通用户「文件历史 + 还原点」够用；想要「硬盘全盘换新也能恢复」，加一个系统映像。

## 3 Linux：tar、rsync 与 dd

Linux 备份的经典三件套：

| 工具 | 用途 | 特点 |
| --- | --- | --- |
| `tar` | 打包文件/目录 | 配合 `-czf` 压缩，可备份整个 `/home` |
| `rsync` | 增量同步 | 只同步变化的部分，适合定期备份 |
| `dd` | 整盘克隆 | `dd if=/dev/sda of=/dev/sdb`，原样复制 |

鸟哥第8章的核心思路是「打包 + 压缩 + 异地存储」。常用命令：

```
tar -czf home-backup.tar.gz /home    # 打包压缩 /home
rsync -av /home /backup/             # 增量同步到备份目录
```

<span class="marginnote">`rsync` 是 Linux 备份的灵魂工具：`-a` 归档保留权限时间戳，`-v` 显示过程。用它做「定期同步备份」最省空间——第一次全量，之后只传变化部分。把 rsync 放进 `cron` 定时任务，就实现了「自动备份」。</span>

## 4 macOS：Time Machine

**Time Machine（时间机器）** 是 macOS 的招牌备份方案：接一块外部硬盘（或网络时间胶囊），在「系统设置 → 通用 → 时间机器」里开启，它会自动**每小时、每天、每周**保留多个时间点的完整快照。还原时进恢复模式选「从时间机器恢复」，或直接浏览快照找回单个文件。<span class="marginnote">Time Machine 的聪明之处是「只备份变化的部分 + 保留多版本」：你在 3 点删了个文件，它能找回 2 点的版本；即使电脑整体报废，新 Mac 也能从时间机器全量恢复。开启后基本「无感自动备份」，是 Mac 用户最省心的方案。</span>

## 5 公式解析：备份容量怎么规划

备份需要多大空间，用「数据量 × 版本数」估算：

$$
\text{备份容量} \approx D \times (1 + r \times n)
$$

分三步拆解：

- **第一步，$D$ 是当前数据总量**：如个人数据 200 GB。
- **第二步，$r$ 是每期新增比例，$n$ 是保留期数**：假设每月新增 5%，保留 12 个月，则 $r \times n = 0.05 \times 12 = 0.6$，即版本累积约为数据量的 60%。
- **第三步，代入**：备份盘需要 $200 \times 1.6 = 320$ GB 左右。所以「买 2 倍数据量的备份盘」是稳妥经验——给版本与增长留够余量。

这个估算对 Time Machine、文件历史、rsync 的增量备份都适用：**版本越多、增长越快，备份盘就要越大。**

## 6 动手：建立你的备份体系

**第一步：选备份介质。** 一块容量为数据量 2 倍的外部硬盘 + 一个云盘（满足 3-2-1 的「1 份异地」）。

**第二步：开启系统级备份。** Windows 开「文件历史」，macOS 开 Time Machine，Linux 用 rsync + cron。

**第三步：关键数据云端同步。** 文档/照片用网盘同步，多一份异地副本。

**第四步：设还原点。** Windows 确认「系统保护」开启，自动创建还原点。

**第五步：验证还原。** 每季度试一次「从备份还原一个文件」，确保备份真的能用。

## 7 速查表：备份工具速记

| 平台 | 文件备份 | 系统备份 | 整盘 |
| --- | --- | --- | --- |
| Windows | 文件历史 | 系统映像 / 还原点 | 第三方克隆工具 |
| Linux | rsync | tar 打包系统目录 | `dd` |
| macOS | iCloud 同步 | Time Machine | 克隆工具 |
| 通用原则 | 3-2-1 | 定期验证还原 | 数据量×2 容量 |

## 8 补充速查：三平台备份方案对照

把三平台备份方案收敛成一张速查表：

| 需求 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| 个人文件 | 文件历史 | rsync | iCloud |
| 系统快照 | 还原点 | tar 打包 | Time Machine |
| 整盘克隆 | 系统映像 | `dd` | 克隆工具 |
| 自动定时 | 文件历史 | cron + rsync | Time Machine |
| 增量备份 | 文件历史 | rsync | Time Machine |
| 还原验证 | 系统映像恢复 | tar 解包 | 时间机器还原 |

## 9 小结

- 备份分三层：**文件备份、系统备份、整盘镜像**；价值在于「能还原」。
- 3-2-1 原则：**3 份、2 种介质、1 份异地**，是数据安全的通用准绳。
- Windows：**文件历史 + 还原点 + 系统映像**三档齐全。
- Linux：`tar` 打包、`rsync` 增量、`dd` 整盘，cron 实现自动备份。
- macOS：**Time Machine** 自动多版本备份，最省心。
- 备份容量 ≈ **数据量 × (1 + 增长比例 × 版本数)**，按数据量 2 倍准备稳妥。
- 定期**验证还原**，没有验证过的备份约等于没有备份。

在下一节，我们迎来本专题的收官篇——**系统重装与数据迁移恢复**，把所有技能串成「重装不丢数据」的完整闭环。
