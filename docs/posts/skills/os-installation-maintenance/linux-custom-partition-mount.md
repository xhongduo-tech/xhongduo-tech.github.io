## 为什么从挂载点开始

Windows 用盘符（C:、D:）固定数据位置，Linux 完全不同——它把所有分区「接」进一棵统一的目录树，这个动作叫**挂载（mount）**，接进去的位置就叫**挂载点（mount point）**。装 Linux 时「自定义分区」的本质，就是决定：每个分区格式化后，挂载到目录树的哪个位置。

这个设计给了 Linux 极高的灵活性：`/home` 独立分出去，重装系统时个人文件原封不动；`/` 和 `swap` 分开，能避免内存不够时系统直接崩溃。鸟哥在第2章做「主机规划」、第3章做安装分区时，反复强调的就是这套「分区 + 挂载点」的规划思维。本节把最常见的挂载点讲清，并给出一套新手可抄的分区方案。

## 1 目录树与挂载点：一棵倒挂的树

Linux 的文件系统不是多个盘符，而是一棵**从 `/`（根）开始的目录树**。`/home`、`/boot`、`/var` 等都是树上的目录，它们既可以只是根分区里的普通目录，也可以是**独立分区挂载上来的「另一个存储区」**——这就是「挂载点」的威力：目录是接口，背后可以是任何一块磁盘。

```
/
├── /boot        ← 引导文件（可独立分区）
├── /home        ← 用户数据（可独立分区，重装不丢）
├── /var         ← 日志与缓存（可独立分区）
├── /usr         ← 系统软件（一般不分）
├── /tmp         ← 临时文件
└── swap         ← 交换空间（不是目录，是特殊分区）
```

**重点：挂载点是「把磁盘空间挂到目录树的某个节点」。** 数据放在 `/home` 里，究竟是存在根分区还是独立分区，对普通用户完全透明——只有系统管理员知道区别。这正是 Linux 分区「逻辑清晰」的来源。<span class="marginnote">鸟哥在第7章详细讲了 `mount`/`umount` 命令与 `/etc/fstab`：`fstab` 里记录「哪个分区挂到哪个挂载点」，开机时系统照单全收。手写 `fstab` 是进阶技能，安装器会自动生成。</span>

## 2 常见挂载点速查

| 挂载点 | 用途 | 建议 |
| --- | --- | --- |
| `/`（根） | 系统主体 | 必选，建议 ≥40 GB |
| `/boot` | 内核与引导文件 | 独立分区可选，UEFI 下需 `esp` 标志 |
| `/home` | 用户个人数据 | **强烈建议独立分区**，重装不丢 |
| `/var` | 日志、缓存、队列 | 服务器常独立，桌面可省 |
| `swap` | 虚拟内存落盘 | 建议设，容量见第4节 |
| `/boot/efi` | UEFI 引导分区（ESP） | UEFI 安装时自动创建 |

## 3 新手分区方案：三区打天下

对普通桌面用户，一套简洁的方案就够：

1. **`/boot/efi`（ESP）**：UEFI 引导分区，FAT32，约 100–500 MB，安装器自动建。
2. **`/`（根）**：系统所在，建议 **40–80 GB**，格式 ext4。
3. **`/home`（家目录）**：用户所有数据，**把剩余空间都给它**，格式 ext4。
4. **`swap`**：交换空间，按第4节公式估算。

这套方案的核心思想是**「系统与数据分离」**：以后想重装系统，只要不动 `/home` 分区，重装后用户文件、配置（`.bashrc`、`.config`）都还在——这比 Windows 的「保留我的文件」更彻底，因为 `/home` 是物理上独立的一块分区。<span class="marginnote">把 `/home` 独立出来，是 Linux 老手给新手的第一条装机建议。配合系统备份（见《系统备份与还原》），`/home` 独立分区 = 重装零丢失 + 备份粒度更细。</span>

## 4 公式解析：swap 该设多大

swap 大小没有唯一答案，但有一个实用的估算思路。经典建议（鸟哥与官方安装器共识）：

$$
\text{swap 建议容量} =
\begin{cases}
\text{与 RAM 相等}, & \text{RAM} \le 2\,\text{GB}\\
2\,\text{GB} \sim \text{RAM 的一半}, & \text{RAM} > 2\,\text{GB}
\end{cases}
$$

分三步拆解：

- **第一步，小内存机器**：内存不足 2 GB 时，swap 至少等于内存，甚至 1.5–2 倍，否则内存一满系统就卡死。
- **第二步，大内存机器**：现代机器动辄 16 GB 内存，swap 设 2–8 GB 即可。内存充裕时 swap 很少被用到，只是「紧急缓冲区」。
- **第三步，特殊场景**：服务器要开休眠（hibernation）时需要 swap ≥ RAM；桌面日常 4–8 GB 足够。

一个直觉：swap 是「内存的溢出池」。内存够大，池子可以小；内存紧张，池子要够深。设 swap 的底线是「别不设」——Linux 在内存耗尽时没有 swap 会直接 OOM 杀进程，而不是优雅降级。

## 5 动手：在安装器中自定义分区

Ubuntu 安装器里选「手动分区」（Something else）后，按下面操作：

**第一步：认磁盘。** 看准目标磁盘（如 `/dev/sda` 或 `/dev/nvme0n1`），别选错。

**第二步：建 ESP。** 若有未分配的磁盘，建一个 FAT32 分区，大小 512 MB，挂载点选 `/boot/efi`，并勾选「可作为 EFI 系统分区」。

**第三步：建根分区。** 再建一个 ext4 分区，大小 60 GB，挂载点 `/`。

**第四步：建 home 分区。** 剩余空间建 ext4，挂载点 `/home`。

**第五步：建 swap。** 建一个「交换空间」分区，大小按第4节。

**第六步：确认安装。** 安装器会列出「要格式化并写入的分区」清单，核对无误后继续——格式化会清空对应分区，务必确认。<span class="marginnote">安装器最后会展示一屏「如果你继续，下列分区将被格式化」的清单。这是手动分区唯一的「后悔确认」，眼睛在每一个分区上停两秒再点继续。</span>

## 6 易错点：手动分区的三个坑

- **没建 ESP 又选了 UEFI**：UEFI 模式必须有 `/boot/efi`，否则安装器报「缺少 EFI 系统分区」。
- **`/home` 没独立，重装全没**：不把 `/home` 单独分区，重装根分区时用户数据会一起被清掉。
- **swap 设成 0**：高内存机器可以，但新手别省，swap 是系统稳定的保险。

## 7 补充速查：常见挂载点与分区建议

把「挂载点 → 作用 → 建议」收敛成速查表：

| 挂载点 | 作用 | 建议 |
| --- | --- | --- |
| `/`（根） | 系统主体 | ≥40 GB，ext4 |
| `/boot/efi` | UEFI 引导（ESP） | FAT32，100–500 MB |
| `/boot` | 内核与引导文件 | 可独立，常规可不分 |
| `/home` | 用户数据 | **强烈建议独立** |
| `/var` | 日志与缓存 | 服务器常独立 |
| swap | 交换空间 | 按第4节公式估算 |
| `/tmp` | 临时文件 | 默认随根分区 |

## 8 小结

- Linux 用**挂载点**把分区接进统一的目录树，`/home`、`/boot`、`/var` 都可独立分区。
- **分区是物理容器，挂载点是逻辑接口**，数据放哪由挂载点决定。
- 新手方案：**`/boot/efi` + `/` + `/home` + `swap`**，核心是系统与数据分离。
- `/home` 独立分区 = 重装系统用户数据零丢失。
- **swap 估算**：小内存≥内存容量，大内存 2–8 GB，别不设。
- UEFI 安装必须配 `/boot/efi`（ESP），否则无法引导。

在下一节，我们给 Linux 的分区再上一层「弹性」——**Linux 使用 LVM 分区安装与扩容**，让磁盘空间能像内存一样动态调整。
