## 为什么 Linux 驱动和 Windows 不一样

Windows 的驱动是厂商提供的「闭源安装包」，而 Linux 的驱动绝大部分**编译进内核或以内核模块（Kernel Module）形式存在**，由内核统一管理。这意味着 Linux 驱动通常不用「下载安装」，而是「看内核认不认、要不要加载某个模块」。这一节的三大命令 `lsmod`、`modprobe`、`dmesg`，就是 Linux 驱动排查的全部核心。学会它们，Linux 下「网卡不认、显卡没驱动」这类问题就有了系统化的解法。

先建立一个总览认识：**Linux 驱动的排查，绝大多数时候不是「装」，而是「查」。** 因为内核已经为绝大多数硬件准备好了驱动模块，插上设备后系统会自动加载对应模块。所以遇到「网卡不认」「显卡没加速」，第一反应不是「去哪下载驱动」，而是「模块加载了吗？加载出错了吗？」——`dmesg` 里的报错往往直接告诉你缺什么。把「查」放在「装」之前，是 Linux 驱动维护与 Windows 最大的不同，也是本节要反复强化的思维。

## 1 模块：内核的「即插即用」零件

**内核模块（Kernel Module）** 是一段可以在运行时加载进内核的代码，扩展内核能力而不必重编内核。驱动就是最常见的内核模块。<span class="marginnote">类比 Windows：内核相当于系统核心，模块相当于「按需加载的驱动服务」。区别在于 Linux 模块与内核版本强绑定——装模块前先看内核版本，是 Linux 维护的第一习惯。</span>

查看模块状态的三板斧：

| 命令 | 作用 | 典型输出 |
| --- | --- | --- |
| `lsmod` | 列出已加载模块 | 模块名、依赖、被谁使用 |
| `modinfo <模块>` | 查看模块元信息 | 描述、作者、依赖、license |
| `dmesg \| grep -i <关键词>` | 看内核日志 | 设备识别、驱动加载报错 |

设备对应的驱动是否加载，常见判断：`lsmod | grep e1000` 看网卡驱动，`dmesg | grep -i nvidia` 看显卡驱动加载过程。<span class="marginnote">`dmesg` 是内核日志，记录硬件被识别与驱动加载的过程。设备「没被认出来」时，`dmesg` 里往往躺着真正的报错原因——这是 Linux 版「设备管理器」，比 Windows 更接近底层。</span>

## 2 加载与卸载：modprobe 的核心用法

手动管理模块用 `modprobe` 命令族：

```
sudo modprobe <模块名>          # 加载模块（自动处理依赖）
sudo modprobe -r <模块名>       # 卸载模块
sudo modprobe <模块名> param=值  # 加载并传参
```

`modprobe` 的智能化在于它会**自动加载依赖模块**。比如加载 `e1000e`（Intel 网卡驱动）时，它会把依赖的 `mii` 等模块一并加载。<span class="marginnote">`modprobe` 从 `/lib/modules/$(uname -r)/` 目录按模块依赖树加载；它替代了更底层的 `insmod`（加载）与 `rmmod`（卸载），日常用 `modprobe` 即可，`insmod` 多用于加载无依赖的特殊模块。</span>

**辨析｜易错点：** 手动 `modprobe` 加载的模块**重启后失效**——这是设计如此，不是出错。要「开机自动加载」，把模块名写入 `/etc/modules-load.d/` 下的 `.conf` 文件，或（有依赖关系的场景）写进 `/etc/modprobe.d/` 配置。

## 3 驱动安装：从内核自带到第三方

Linux 驱动按获取方式分三类：

1. **内核自带**：多数硬件驱动已在内核里，插上即用（如常见网卡、声卡）。「装 Linux 驱动」多数时候其实是「激活对应模块」。
2. **内核外树模块（DKMS）**：如 NVIDIA 显卡驱动。用发行版包管理器安装即可，DKMS 会在内核升级后自动重编模块：

```
sudo apt install nvidia-driver-535    # Debian/Ubuntu 系
sudo dnf install akmod-nvidia         # Fedora 系
```

3. **从源码编译**：老设备或内核没有的驱动，`make && make install` 编译安装；仅当包管理器没有时才走这条路。<span class="marginnote">为什么 NVIDIA 驱动「安装」在 Linux 里是个事件？因为它是闭源、内核树外的：安装的本质是把厂商提供的模块代码对<strong>当前内核版本</strong>编译成模块。DKMS 的意义就是内核升级时自动重新编译，否则每次升级内核显卡驱动就失效。</span>

**重点：优先用发行版包管理器装第三方驱动。** 从 NVIDIA 官网下载 `.run` 手动装容易与内核升级、包管理冲突；发行版仓库里的版本经过适配，卸载也干净。

## 4 核心要点对比：Windows vs Linux 驱动管理

纯概念主题用表格代替公式解析。两套体系对照，理解差异才能熟练切换：

| 对比项 | Windows | Linux |
| --- | --- | --- |
| 驱动形态 | 厂商安装包 | 内核模块 / DKMS |
| 管理工具 | 设备管理器 | `lsmod` / `modprobe` / `dmesg` |
| 安装来源 | 厂商官网为主 | 内核自带 / 包管理器为主 |
| 更新方式 | Windows 更新 + 厂商工具 | 内核升级随包管理器 |
| 排查入口 | 设备管理器错误代码 | `dmesg` 内核日志 |

**判断口诀：** Windows 出驱动问题先看设备管理器，Linux 出驱动问题先看 `dmesg`。两个入口背后是「闭源安装包」与「开源内核模块」两种哲学。

## 5 实战：给新设备装驱动的完整路径

把理论走成一条可执行的路径，遇到「新设备没驱动」时照做：

**第一步：确认设备被系统看到。** `lspci` / `lsusb` 里能看到设备吗？看不到，先解决硬件识别问题（接口、供电、固件）；能看到但没驱动，继续下一步。

**第二步：查内核日志，找报错线索。**

```
dmesg | grep -iE "fail|error|not found" | tail -20
```

报错里常直接给出缺的固件名或模块名，比如 `firmware: failed to load iwlwifi-*.ucode` 说明无线网卡缺固件。

**第三步：按类型补驱动。**

- 缺固件 → 装 `linux-firmware` 包（Debian/Ubuntu）或对应 `firmware-*` 包。
- 设备在内核支持列表但模块没加载 → `modprobe <模块名>` 手动加载。
- 完全无内核驱动（如部分 NVIDIA、新款网卡）→ 走厂商闭源驱动或 DKMS。

**第四步：验证并持久化。**

```
lsmod | grep <模块名>       # 确认已加载
```

手动加载的模块要开机自动生效，写进 `/etc/modules-load.d/`。

**判断要点：** 路径的关键是「先查日志再动手」。`dmesg` 的报错比任何教程都更精确地告诉你「缺什么」，照着缺的东西补，而不是盲目下载安装——这是 Linux 驱动维护的核心方法论。

## 6 操作清单：内核与模块的常用查询

把内核与模块的日常查询命令汇总成速查表，随时可查：

**内核版本与硬件：**

```
uname -r                  # 当前内核版本
uname -a                  # 完整内核信息
lspci                     # 列出 PCI 设备（显卡、网卡等）
lsusb                     # 列出 USB 设备
```

**模块操作：**

```
lsmod                     # 已加载模块
modinfo <模块名>          # 模块信息（描述、依赖、参数）
modprobe <模块名>         # 加载模块（含依赖）
modprobe -r <模块名>      # 卸载模块
sudo modprobe <模块> 参数=值  # 加载并传参
```

**驱动与设备对应：**

```
lsmod | grep <关键词>      # 某驱动是否已加载
dmesg | grep -i <关键词>   # 内核日志里搜驱动加载记录
lspci -k                  # 看设备使用了哪个内核驱动
```

- `lspci -k` 是最快确认「某设备用了什么驱动」的命令：它直接列出设备对应的内核驱动模块名。
- `dmesg` 是驱动加载的「流水账」，报错都能在里面找到蛛丝马迹。

**判断要点：** 查询命令是排查的基础——「先查清再动手」。内核版本、设备型号、模块状态三查之后，大多数驱动问题已经定位了一半。

## 7 小结

- Linux 驱动以**内核模块**形式存在，与内核版本绑定，运行时按需加载。
- 三大命令：`lsmod`（看已加载）、`modprobe`（加载/卸载）、`dmesg`（看内核日志）。
- `modprobe` 自动处理依赖；手动加载的模块**重启失效**，要开机自动加载就写 `/etc/modules-load.d/`。
- 第三方驱动（NVIDIA）用**发行版包管理器** + DKMS 安装，别用官网 `.run` 手动装。
- Linux 驱动排查先看 `dmesg`，对应 Windows 的设备管理器。
