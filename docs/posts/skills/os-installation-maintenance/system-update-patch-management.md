## 为什么从系统更新开始

系统装好、驱动装完，看似「完工」，其实真正的日常维护才刚开始——**更新**。很多人觉得「更新烦、更新完变卡、我不用新功能」，于是长期关闭更新。这正是电脑被病毒攻破、越用越慢的头号原因。**补丁（patch）不只是加新功能，更是在堵安全漏洞**——Windows 的漏洞、Linux 内核的漏洞、macOS 的漏洞，都在一次次更新中被修复。

本节讲清「为什么必须更新」、三平台的更新机制（Windows Update、apt/yum/dnf、macOS 软件更新），以及怎么把「更新」变成不打扰日常的低成本习惯。

## 1 为什么必须更新：补丁的本质

**更新 = 功能更新 + 安全补丁 + 驱动修复 + 稳定性修复** 的混合体。安全补丁是其中不能省的部分：每年都有大量「已公开漏洞」在野外被利用，而厂商在发现后几周内就会推送修复补丁——不更新的电脑，等于把家门敞开着等漏洞上门。<span class="marginnote">2017 年的 WannaCry 勒索病毒是教科书级案例：它利用的 SMB 漏洞在病毒爆发前一个月微软就发布了补丁（MS17-010），但大量没更新的机器依旧中招。补丁不只是「系统优化」，是「数字安全的基础卫生」。</span>

几个容易误解的真相：

- **「更新完变卡」≠ 更新有害**：卡顿常来自驱动不兼容或新功能开销，可通过回滚驱动解决；而放弃更新的代价是安全风险。
- **「不用新功能就不用更新」**：新功能只是顺带，安全补丁才是核心价值。
- **「更新会重启，烦」**：现代系统支持「更新计划重启」，可安排在你不用电脑的时段。

## 2 Windows：周二补丁日与更新选项

Windows 的更新节奏有个著名惯例——**周二补丁日（Patch Tuesday）**：微软固定在每个月第二个星期二推送安全更新（约几十到上百个补丁）。日常入口：「设置 → Windows 更新」→「检查更新」。<span class="marginnote">「周二补丁日」从 2003 年起成为惯例，企业 IT 因此能预判「每月第几天会出更新」。它后来还演生出「Exploit Wednesday」的说法——补丁公开的第二天，攻击者会加速利用旧漏洞，所以「补丁日之后尽快更新」尤其重要。</span>

Windows 更新里的常见选项：

| 选项 | 作用 |
| --- | --- |
| 检查更新 | 立即检查并下载安装 |
| 暂停更新 | 最多暂停数周（避开关键工作期） |
| 更新历史记录 | 查看已装补丁、卸载问题补丁 |
| 可选更新 | 含驱动更新，手动安装 |
| 高级选项 → 活跃时间 | 设置重启避开时段 |

**判断要点：** 日常做法是「自动更新保持开启 + 把活跃时间设成你睡觉前的时间段」。补丁日后的 1–3 天内主动检查一次更新，别拖到月底。

## 3 Linux：apt、yum、dnf

Linux 的更新机制是「包管理器」，没有「周二补丁日」，而是**滚动推送**。各发行版命令：

```
# Debian/Ubuntu 系
sudo apt update && sudo apt upgrade -y

# Red Hat 系（Fedora / Rocky / AlmaLinux）
sudo dnf upgrade

# 旧版 yum（CentOS 7）
sudo yum update
```

`apt update` 刷新软件包索引，`apt upgrade` 应用升级；Linux 更新不止系统本体，**连同所有软件**一起升级——这是 Linux 与 Windows 的显著差异：一个命令更新一切。<span class="marginnote">鸟哥在第13章「认识系统服务」前后多次强调：Linux 的安全更新同样重要，服务器尤其要在重启维护窗口统一 `dnf upgrade`。桌面 Linux 可以设置自动更新（Ubuntu 的「软件与更新 → 自动检查更新」），服务器则讲究「计划重启窗口」。</span>

## 4 macOS：软件更新与 App Store

macOS 走「系统设置 → 通用 → 软件更新」，推送内容包括系统版本与安全更新。它还有一个特点：**App Store 里的应用更新也一起管**，入口是 App Store 的「更新」标签。Apple Silicon 的 Mac 还会通过更新管理固件（T2/Apple Silicon 的固件密钥），这是比 Windows 更「整体」的更新哲学——系统、应用、固件一体更新。<span class="marginnote">macOS 每次大版本更新（如 Sonoma → Sequoia）前，建议先做一次 Time Machine 备份（见《系统备份与还原》）。大版本更新偶有兼容问题，备份是安全网。</span>

## 5 核心对比表：三平台更新机制

| 对比项 | Windows | Linux | macOS |
| --- | --- | --- | --- |
| 更新入口 | 设置 → Windows 更新 | `apt`/`dnf`/`yum` 命令 | 系统设置 → 软件更新 |
| 更新节奏 | 周二补丁日（月更） | 滚动推送 | 不定期（随发布） |
| 软件更新 | 独立更新商店/应用 | 与系统同命令 | App Store 一起 |
| 驱动更新 | 含在更新内 | 内核升级随之 | 系统更新内 |
| 主动暂停 | 支持 | 需手动配置 | 支持 |

## 6 动手：把三平台的更新养成习惯

**Windows：** 打开「自动更新」，设好活跃时间（避开重启），补丁日后主动检查一次。

**Linux 桌面：** Ubuntu 在「软件与更新」里打开自动检查；或每周手动跑一次 `sudo apt update && sudo apt upgrade`。

**macOS：** 系统设置里打开「自动更新」；大版本更新前先备份。

**通用原则：** 别在重要演示/答辩前更新；更新后给系统几小时「消化」，观察是否异常。

## 7 速查表：更新常见问题

| 问题 | 解法 |
| --- | --- |
| 更新后蓝屏 | 进安全模式卸载最近更新（更新历史记录 → 卸载） |
| 更新卡在下载 | 暂停再继续，或清理更新缓存后重试 |
| 更新占用大量磁盘 | 更新后清理（Windows 磁盘清理 / `sudo apt autoremove`） |
| 服务器不想自动重启 | Linux 关闭自动重启，设维护窗口手动 `reboot` |
| 不确定该不该更新 | 至少装安全更新，功能更新可缓 |

## 8 补充速查：三平台更新命令与入口

把「怎么更新」收敛成一张可执行表：

| 平台 | 更新入口 | 常用命令/操作 |
| --- | --- | --- |
| Windows | 设置 → Windows 更新 | 「检查更新」 |
| Windows | 更新历史 | 卸载问题补丁 |
| Debian/Ubuntu | 终端 | `sudo apt update && sudo apt upgrade` |
| Fedora/Rocky | 终端 | `sudo dnf upgrade` |
| CentOS 7 | 终端 | `sudo yum update` |
| macOS | 系统设置 → 软件更新 | 点「现在更新」 |
| macOS | App Store | 「更新」标签 |
| Linux 清残留 | 终端 | `sudo apt autoremove` |
| 查看更新记录 | Linux | `apt list --upgradable` |
| 规划重启 | Windows | 活跃时间设置 |

## 9 小结

- 补丁 = **功能 + 安全 + 驱动 + 稳定性**，安全补丁不可省。
- **WannaCry** 证明：不更新的电脑是网络安全的「裸奔」。
- Windows 走**周二补丁日**，每月第二个周二；保持自动更新 + 活跃时间。
- Linux 用**包管理器**滚动更新：`apt update && upgrade` 或 `dnf upgrade`，系统软件一起升。
- macOS 走**软件更新 + App Store**，Apple Silicon 连固件一起更新。
- 更新原则：**别在重要场合前更新，大版本更新前先备份**。
