## 为什么模块是 Magisk 生态的灵魂

Magisk 给 root 提供了一个干净的基础，而真正让刷机者离不开它的，是**模块（module）**——一个个可以随时装卸的「系统增强包」。想改字体、想装音频增强、想隐藏 root、想换内核调度，不用重刷系统，装个模块就行。这一篇讲透模块的机制（包结构、生命周期、挂载逻辑），再给一套「按类别选模块」的思路。**关于具体模块，只给类别与判断标准，不给「必装清单」**——因为模块生态更新极快，教你判断比喂你结论更长久。模块的「装卸即还原」哲学，与相邻专题《手机维修》里的「先备份、可回退」原则遥相呼应——可逆，是折腾的底气。

## 1 模块是什么：Magisk 生态的扩展包

**Magisk 模块**是一个 zip 包，里面装着一套「要在系统里新增或覆盖的东西」。安装后，模块内容经 **Magic Mount** 挂载到系统目录之上，产生「系统被修改了」的效果——而底层 system 依旧原样。

模块能做的事范围极广：新增应用与二进制、覆盖系统文件、修改系统属性、注入服务脚本、调整 SELinux 策略。**模块与「直接改系统」的本质区别在可逆性**：模块随装随卸、卸载即还原，而直接改系统要重刷才能还原。<span class="marginnote">模块的「乐高」属性来自 Magic Mount：<strong>模块文件放在独立目录，靠 overlay 挂载生效，禁用/删除模块只是「撤掉这层叠加」</strong>——底层系统从未被碰过。这就是为什么「模块玩坏了，禁用即可恢复」成了社区共识。</span>

**模块的风险**：模块运行在内核/框架层，坏的模块可能导致**开机循环（bootloop）**——但 Magisk 提供了「安全模式」兜底（见第 3 节），让坏的模块可以禁用。**模块不是「随便装」的理由**——来源不明的模块可能含恶意脚本，装前看来源、看评论、看更新记录。

## 2 模块包结构：module.prop 与挂载目录

一个标准的 Magisk 模块 zip，解压后大致是这个结构：

```
module.zip
├── module.prop        # 模块元信息（必填）
├── system/            # 挂载到 /system 的文件（可选）
│   ├── etc/hosts
│   └── app/...
├── system.prop        # 追加的系统属性（可选）
├── sepolicy.rule      # 追加的 SELinux 策略（可选）
├── post-fs-data.sh    # 启动早期脚本（可选）
├── service.sh         # 启动后期脚本（可选）
└── customize.sh       # 安装时自定义脚本（可选）
```

**module.prop** 是模块的「身份证」，记录 `id`、`name`、`version`、`author`、`description` 等元信息——Magisk App 用它显示模块列表。

**system/ 目录**是模块的主体，内容会在启动时挂载到对应的系统路径：`system/etc/hosts` 挂到 `/system/etc/hosts`，`system/app/xxx` 挂到 `/system/app/xxx`。**挂载目录与系统路径一一对应**，这就是模块「看起来改了系统」的机制。

**脚本文件**（`post-fs-data.sh`、`service.sh`）让模块能在特定时机执行命令——它们是模块里「有行为」的部分，也是安全审查的重点。<span class="marginnote">看一个模块可不可信，先读它的脚本：<strong>`post-fs-data.sh` 在挂载后执行、`service.sh` 在系统服务启动后执行，恶意模块常在这里塞私货</strong>。装来源不明的模块前，用解压工具把这两个脚本打开读一遍，比任何「信誉评价」都实在。</span>

## 3 模块的生命周期：安装、启用、禁用与移除

**安装**：三种方式——Magisk App 里直接选 zip 安装；TWRP 里刷入；`adb install`（少见）。安装后模块**需重启生效**。

**启用/禁用**：Magisk App 的模块列表里可切换启用状态。**禁用 = 不挂载，下次重启后模块不生效**，底层系统回到原样。

**移除（卸载）**：删除模块文件，重启后完全消失。

**模块更新**：作者发布新版，App 里可更新。更新前建议看更新日志——**大版本更新可能不兼容，装坏了用「移除」兜底**。

**开机循环的救星——安全模式（Safe Mode）**：若某个模块导致无法开机，进入安全模式可**暂时禁用全部模块**。进入方法：长按电源键进入启动菜单选安全模式，或连续按音量下多次（视版本）。安全模式下系统可启动，就能进 App 把坏的模块禁用/删掉。<span class="marginnote">安全模式是模块翻车的「后悔药」：<strong>它让 Magisk 跳过所有模块挂载，只保留系统本身</strong>。记住这条逃生路线：bootloop → 进安全模式 → 禁用坏模块 → 重启恢复。当然，连安全模式都进不去的极端情况，就回到「fastboot 刷回原版 boot」的兜底了。</span>

## 4 常用模块类别与选择思路

模块生态按功能可分几大类，每类给你「判断标准」而不是「过时清单」：

**系统框架类**：如 LSPosed（Xposed 的现代实现），用「模块套模块」的方式在应用内注入修改。选择标准：**确认 LSPosed 版本与 Magisk/系统版本兼容**；框架类模块影响面大，先只装一个测试稳定。

**音频增强类**：如 ViPER4Android、杜比音效。选择标准：**看是否支持你的 Android 版本与音频栈**；音频模块与 HAL 绑定深，装完务必测通话/媒体音。

**屏幕与外观类**：字体、主题、状态栏修改。选择标准：**优先选「纯资源替换」型模块**（只覆盖字体/图标），少选「系统框架依赖」型，降低冲突概率。

**性能与功耗类**：内核调度、温控、电池优化。选择标准：**同一时间只启用一个调度类模块**，两个调度器打架是 bootloop 常见来源。

**网络与隐私类**：广告拦截 hosts、DNS 工具、**root 隐藏**（如 Shamiko，配合 Denylist）。选择标准：**隐藏类模块依赖 Zygisk 与 Magisk 版本**，保持三者在同一时代。

**相机与成像类**：GCam 配置、影像增强。选择标准：**按机型与系统版本找对应配置**，跨机型通用性差。

选模块的核心方法论是：**一模块一功能、来源可信、版本兼容、装完即测**。宁可少装，不可乱装。

## 5 公式解析：模块挂载的「覆盖优先级」

多个模块同时启用时，系统读到某个路径时到底看谁？可以用覆盖优先级表达：

$$
\text{读到 } /system/xxx = \begin{cases}
\text{启用模块里的覆盖版本} & \text{若存在且优先级高} \\
\text{底层 system 原版} & \text{否则}
\end{cases}
$$

逐步拆解：

- **多个模块覆盖同一文件**：Magisk 按模块的 id 或安装顺序决定优先级——**后安装/优先级高的模块覆盖先安装的**。所以「两个模块都改 hosts」，谁生效取决于优先级。
- **模块覆盖 vs 底层原版**：只要模块里存在该文件，读到的是模块版本；模块被禁用或删除，回落到底层原版。
- **「覆盖失败」的表现**：模块装了但效果没出现，多半是**文件路径不对**（模块里的目录层级与系统不匹配），或**被另一模块覆盖**。

这个公式帮你排查「模块不生效」的常见原因：**路径对不对、有没有被别的模块抢了、模块到底启没启用**。

## 6 核心要点：模块类别对照表

| 类别 | 典型作用 | 选择标准 | 风险点 |
| --- | --- | --- | --- |
| 系统框架 | 应用内注入 | 版本兼容 | 影响面大 |
| 音频增强 | 音质/音效 | 支持 Android 版本 | 与 HAL 绑定深 |
| 屏幕外观 | 字体/主题 | 纯资源替换优先 | 与框架冲突 |
| 性能功耗 | 调度/温控 | 同时只装一个 | 调度器打架 |

| 相机成像 | 影像增强 | 按机型匹配 | 通用性差 |
| 系统工具 | 状态栏/按键 | 源码开放 | 脚本审查 |

## 8 快速自查清单

装任何模块前，逐条确认：

- 模块**来源可信**（官方发布、社区活跃维护）？发布者是谁？
- 已用解压工具**读过 `post-fs-data.sh`/`service.sh`**，没有可疑命令？
- 模块**与 Magisk 版本、系统版本、Android 版本兼容**？
- 是否**一模块一功能**，没有与已装模块重复/冲突？
- 出问题时知道**逃生路线**：安全模式禁用 → 移除 → 必要时刷回原版 boot？

## 9 小结

- 模块是**经 Magic Mount 挂载生效的系统增强包**，可逆性强，装错拆掉即可。
- 模块包结构核心是 **module.prop（元信息）+ system/（挂载内容）+ 脚本（行为）**，脚本是安全审查重点。
- 生命周期：**安装 → 重启生效 → 启用/禁用 → 移除**；bootloop 用**安全模式**禁用全部模块兜底。
- 选模块方法论：**一模块一功能、来源可信、版本兼容、装完即测**。
- 模块不生效排查三问：**路径对不对、有没有被覆盖、启没启用**。
