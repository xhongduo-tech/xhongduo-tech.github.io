## 为什么「保资料刷机」值得单独一篇

前面反复强调「刷机前备份、刷机清数据」，但刷机者真正想要的是：**系统升了级，数据还都在**。这在特定条件下是可行的——**保资料刷机（不清 data 的刷写）**。同时，刷机后的系统升级（OTA）也是一门学问：改过 Recovery 会破坏 OTA、OTA 后 root 会消失。这一篇把「保资料刷机」的条件与姿势、以及「系统升级维护」的完整流程讲清楚。

## 1 保资料刷机的本质：清与不清的边界

回顾《定制 ROM 刷写流程》里的决策链：**data 清不清，取决于新旧版本的数据格式是否兼容**。保资料刷机的本质，就是**在「数据格式兼容」的前提下跳过清 data**：

- **兼容 → 不清 data（保资料）**：系统升级、同系列 ROM 小版本更新。
- **不兼容 → 必须清 data**：换 ROM、跨 Android 大版本、跨 ROM 类型。

**保资料刷机能省事的代价**：不清 data 意味着旧系统的残留设置、应用数据原样保留——若新旧版本存在不兼容的组件，可能出现 FC、设置异常。**所以「保资料」不是无条件的**，它依赖「版本跨度可控」这个前提。<span class="marginnote">「保资料」与「清数据」不是二选一的赌注，而是按版本跨度选的策略：<strong>同系列小版本放心保资料，跨大版本/换 ROM 老老实实清 data</strong>。硬要在不兼容时保资料，省的是几分钟，赌的是「数据冲突后设置全乱」的风险。</span>

**判断兼容性的经验法则**：同 ROM 的**小版本升级**（如 LineageOS 19 的月度更新）→ 兼容；**Android 大版本升级**（13→14）→ 部分兼容，建议备份后试保资料，出问题再清；**换 ROM**（A 家的 ROM → B 家的 ROM）→ 不兼容，必须清。

## 2 保资料刷机的三种姿势：卡刷、线刷与专项

不同刷写方式，保资料的操作各有讲究：

**卡刷保资料（Dirty Flash）**：TWRP 里**只清 Dalvik/ART Cache + Cache**，不清 data，然后刷入新 ROM 包。适合同系列 ROM 升级。注意：刷完若出现大量 FC，说明数据不兼容，备份后清 data 重来。<span class="marginnote">卡刷保资料的「只清 cache/dalvik」是关键细节：<strong>清这两个只是「扔缓存」，不碰用户数据；不清 system 与 data，旧系统与新包共存</strong>。很多新手保资料翻车，是误把「四清」当成了默认动作——保资料就要明确「只清缓存」。</span>

**线刷保资料（保留数据模式）**：MiFlash 选「**保留用户数据**」模式；三星 Odin 用 **HOME_CSC** 文件代替普通 CSC。这类模式在线刷脚本里**跳过了 `erase data`**。前提同样是版本兼容。

**专项保资料**：部分场景用「刷 boot/system 不动 data」的方式——如升级内核（只刷 boot 分区）、修补系统（只刷 system 分区）。这类操作天然保资料，但要求你清楚「动哪个分区、别动哪个分区」。

**保资料刷机的共同前提**：**备份仍要做**——保资料不是「不用备份」，而是「概率上不清数据」。万一中途出错、或数据冲突需要清 data，备份就是最后的底牌。

## 3 系统升级维护：OTA 与刷机后的升级

系统升级维护，分两种场景：

**场景一：官方系统 / 未改动的系统 → OTA 升级**。OTA 是官方推送的增量升级，最安全。前提：**Recovery 与系统未被第三方替换**。若刷过 TWRP 或改过系统分区，OTA 可能失败（Recovery 被替换 → OTA 无法执行）。

**场景二：已 Root / 刷机后的系统升级**。这是刷机者的常态，几个关键点：

**OTA 后 root 会消失**：OTA 会替换 boot 分区的原版镜像，Magisk 被冲掉。**升级后需重新修补新 boot 重装 Magisk**（顺序：先 OTA，再重装 root）。
**OTA 可能失败**：改过系统分区、TWRP 顶掉了官方 Recovery，OTA 校验过不了。**解决**：恢复官方 Recovery/系统后升级，或改用「下载全量包 + TWRP 保资料刷」的方式。
- **跨大版本升级建议 clean flash**：从 Android 大版本升级，即使同 ROM，也建议备份后 clean flash——大版本数据迁移的坑最多。<span class="marginnote">「OTA 后 root 消失」是刷机者最常「惊到」的现象：<strong>不是 root 坏了，而是 OTA 把 boot 换回了原版</strong>。牢记「先系统、后 root」的顺序——OTA 完成后对新 boot 重新 patch 即可，别在 OTA 前折腾 root。</span>

**升级前的标准动作**：**备份（Nandroid + 数据）→ 确认电量与存储空间充足 → 确认升级包与机型匹配 → 读 changelog/Known Issues → 执行升级**。

## 4 升级失败的应对与维护习惯

**升级失败的常见形态与应对**：

**OTA 下载后安装失败**：多半是系统被改动（root/TWRP）。回官方状态再升，或改走全量包。
**升级后 bootloop**：跨大版本未 clean 的典型症状。备份数据 → 回 TWRP clean flash 当前版本。
- **升级后 root 没了 / 应用 FC**：root 消失按「重装 Magisk」处理；FC 多半是数据不兼容，按「清应用数据 → clean flash」顺序排查。
- **升级后变砖（罕见）**：按上一节救砖流程处理——线刷官方包兜底。

**维护习惯**（让升级少翻车的长期策略）：
- **定期备份**：每次重要升级前 Nandroid + EFS。
- **跟踪更新渠道**：从官方/可信渠道获取更新与 changelog，别装来路不明的「新版」。
- **读 Known Issues**：升级前看该版本已知问题，避开「已知翻车版本」。
- **保持版本克制**：不是每版都要追，稳定版优先——**生产主力机少用 nightly**。<span class="marginnote">升级维护的黄金法则：<strong>「稳定优先、追新适度」</strong>——主力机用稳定版（stable），备机/折腾机才用 nightly/实验版。夜版更新频繁、问题多，把主力机搭进去得不偿失。刷机是老手的乐趣，不该成为日常的负担。</span>

## 5 公式解析：保资料刷机的「兼容性」前提

保资料刷机能不能做，取决于一个兼容性判定。设当前系统版本为 $V_{\text{cur}}$，目标版本为 $V_{\text{new}}$，数据格式兼容函数为 $\text{Compat}(V_{\text{cur}}, V_{\text{new}})$，则：

$$
\text{保资料} \iff \text{Compat}(V_{\text{cur}}, V_{\text{new}}) = \text{true}
$$

逐步拆解：

- **$V_{\text{cur}} \to V_{\text{new}}$**：版本变化方向。同系列小版本（$V_{\text{cur}}$ 与 $V_{\text{new}}$ 接近）通常兼容；换 ROM / 大版本跨度大，兼容性存疑。
- **Compat 函数**：由「数据格式是否兼容」决定——同 ROM 更新兼容度高，跨 ROM 类型基本不兼容，Android 大版本之间部分兼容。
- **判定结果**：兼容 → 保资料（不清 data）；不兼容 → 必须清 data。**拿不准时按「不兼容」处理**——先备份，试保资料，出问题再清。

这个公式的实操价值是「**默认保守**」：保资料是「版本可控时的福利」，不是「刷机的默认权利」。**不确定兼容性，就当作不兼容——先备份，再决定**。

## 6 核心要点：保资料刷机与升级对照表

| 场景 | 能否保资料 | 正确姿势 |
| --- | --- | --- |
| 同系列 ROM 小版本升级 | 能 | 卡刷只清 cache/dalvik |
| 线刷官方升级 | 能 | MiFlash 保留数据 / HOME_CSC |
| 换内核（只刷 boot） | 能 | 不动 data |
| 换 ROM | **不能** | clean flash |
| Android 大版本升级 | 部分 | 备份后试，出问题清 |
| 跨 ROM 类型 | **不能** | clean flash |
| 刷机后 OTA | 视情况 | 恢复官方状态或全量包 |

## 8 快速自查清单

保资料刷机或升级前，逐条确认：

- 新旧版本**数据格式是否兼容**？同系列小版本还是跨大版本/换 ROM？
- 保资料姿势正确吗——卡刷**只清 cache/dalvik**，线刷选**保留数据模式**？
- 升级前是否**备份了 Nandroid + 数据**？电量与空间是否充足？
- 已 Root/刷机设备升级，是否记得**先 OTA、后重装 Magisk**？
- 升级包来自**可信渠道**吗？changelog/Known Issues 看了吗？

## 9 小结

- 保资料刷机的本质是**在版本兼容的前提下跳过清 data**——不兼容时硬保资料是赌运气。
- 三种保资料姿势：**卡刷只清缓存（dirty flash）、线刷保留数据模式（MiFlash/HOME_CSC）、只刷特定分区**。
- 升级维护两条主线：**官方系统走 OTA**（需未改动状态），**已 Root 系统先 OTA 后重装 Magisk**；跨大版本建议 clean flash。
- 升级失败应对：**bootloop → clean flash，root 消失 → 重装，变砖 → 线刷兜底**。
- 维护习惯：**稳定优先、定期备份、读 changelog、关注 Known Issues**；保资料的前提永远是「备份先行」。
