## 为什么完整备份是刷机的「安全气囊」

前面每一篇都在提「先备份」，这一篇把它做成完整操作手册。备份分两个层次：**用户数据备份**（联系人、相册、应用数据）与**系统级备份**（整分区镜像）。后者——Nandroid——才是「刷坏了能一键还原」的关键。而其中 **EFS/基带** 的备份，是刷机者的「保险单」：IMEI 丢了，手机就不再是「你的手机」。这一篇讲透 TWRP 分区备份/恢复与 EFS 备份。「整分区镜像备份」正是《数据恢复与磁盘维护》里磁盘镜像技术在手机上的对应物——两者互为表里。

## 1 完整备份的两层：用户数据与系统镜像

备份要分两层想，因为它们解决不同的问题：

**第一层：用户数据备份**。联系人、短信、相册、应用数据。手段：云备份、本地导出、应用自带迁移。**解决的是「手机还在、数据没了」**——恢复出厂、误删、刷机清 data 后的数据找回。

**第二层：系统级备份（Nandroid）**。把 `boot`、`system`、`data`、`EFS` 等分区做成**整块镜像**。手段：TWRP 备份。**解决的是「系统坏了、设备变砖」**——刷坏任何分区，用 Nandroid 一键还原整个系统状态。<span class="marginnote">为什么 Nandroid 是不可替代的？<strong>用户数据备份只能救「数据」，救不了「系统」——而 Nandroid 备份的是「系统+数据打包的完整状态」</strong>。刷 ROM 前做一个 Nandroid，相当于给整个手机拍了一张「可恢复快照」，比任何文件级备份都彻底。</span>

**两层的关系**：Nandroid 里其实**包含**了 data 的用户数据，但它和「独立用户数据备份」不冲突——Nandroid 用于「还原整个状态」，独立备份用于「只要数据不要系统」。**成熟的刷机者两层都做**。

## 2 TWRP 分区备份：勾什么、存哪里

**TWRP 的 Backup 菜单**是系统级备份的主战场。操作要点：

**勾选分区**：TWRP 备份界面列出可备份的分区，常见勾选组合：

**Boot**：内核 + ramdisk。
**System**：系统主体。
**Data**：用户数据与应用（**加密 data 需输入屏锁密码**）。
- **EFS**：基带身份数据（IMEI、校准）。
- **Vendor**：厂商分区（部分机型）。
- **Modem**：基带固件。

**推荐组合**：日常刷机前勾 **Boot + System + Data + EFS**；刷底层固件前再加 **Vendor/Modem**。<span class="marginnote">TWRP 备份「勾什么」按刷机风险定：<strong>只刷 ROM 就备 Boot+System+Data+EFS，够覆盖系统崩溃；要动基带/厂商层就加 Vendor/Modem</strong>。备份不是越全越好——全分区备份体积巨大、耗时长，按风险勾选才高效。</span>

**存哪里**：TWRP 默认存到内部存储的 `/sdcard/TWRP/BACKUPS/`，也可选 **OTG U 盘**或 **MicroSD**。**强烈建议备份后把备份文件夹复制到电脑**——因为刷机/恢复出厂可能把手机存储本身也清掉，备份存手机上等于「把钥匙锁进保险箱」。

**备份加密**：TWRP 支持给备份加密码（可选），加了密码要记牢——**忘了密码，备份等于白备**。

## 3 EFS/基带备份：IMEI 的「保险单」

**EFS 分区**存放 IMEI、基带校准数据、设备序列号等身份信息。**EFS 丢失的症状**：无基带（状态栏无信号）、IMEI 变 0、无法拨号。**且 EFS 极难恢复**——补写 IMEI 需要底层工具与对应文件，多数用户只能求助售后。<span class="marginnote">为什么 EFS 备份被刷机社区奉为第一铁律？<strong>IMEI 是设备的「身份证」，EFS 是它的存放处；刷机、清 data、刷错误基带都可能波及 EFS</strong>。而 EFS 只有几 MB，备份几乎零成本——用最小的投入换最大的保险，没有理由不备。</span>

**EFS 的备份方式**：

**TWRP 勾选 EFS 分区备份**：最常用，随 Nandroid 一起备。
**`dd` 命令手动备份**：在 TWRP 的 Terminal 或 root 的 shell 里执行 `dd if=/dev/block/bootdevice/by-name/efs of=/sdcard/efs.img`——直接读分区做镜像。适合 TWRP 不支持该机型 EFS 备份的情况。
**专用工具**：部分机型有专门的 EFS 备份工具。

**EFS 的恢复**：在 TWRP 的 Restore 里选包含 EFS 的备份恢复；或用 `dd` 反向写回。**恢复 EFS 后必须重启验证信号与 IMEI**——IMEI 变 0 则恢复失败，别再继续操作。

## 4 分区级恢复：什么时候用、怎么用

**TWRP 的 Restore 菜单**用于把 Nandroid 备份还原回去。**使用时机**：

- **刷 ROM 翻车**（bootloop、卡 Logo）→ 恢复刷机前的 Nandroid。
- **改坏系统文件** → 恢复 System/Boot。
- **只想找回数据** → 只恢复 Data 分区。
- **IMEI/基带异常** → 恢复 EFS。

**恢复操作**：Restore → 选择备份 → 勾选要恢复的分区 → 滑动确认。**恢复后一般不用重新清 data**——Nandroid 的 data 直接覆盖。

**恢复的注意事项**：

- **备份与当前系统版本可能不兼容**：跨大版本恢复 Nandroid（如从 Android 14 的备份恢复到 13），可能因数据格式不兼容出问题。**恢复「最近的、匹配当前场景的」备份**。
- **恢复 bootloop 的兜底**：若恢复 System/Boot 后仍 bootloop，先恢复 Data 试试；仍不行则回官方线刷包。
- **恢复前也要确认备份完好**：TWRP 备份带校验（MD5），恢复时若校验失败会提示——**备份损坏时别强刷**。<span class="marginnote">Nandroid 恢复的正确心态：它是「回到过去」不是「修复未来」——<strong>恢复到备份时刻的状态，之后发生的一切（应用更新、聊天记录）都会消失</strong>。所以恢复前想清楚「我要回到哪个时刻」，而不是随手恢复一个「最新」备份。</span>

## 5 公式解析：备份的「覆盖范围」决策

决定「备份哪些分区」，可以用风险驱动的公式：

$$
\text{备份范围} = \underbrace{\text{Boot} + \text{System} + \text{Data}}_{\text{系统崩溃可还原}} + \underbrace{\text{EFS}}_{\text{身份保险}} + \underbrace{\text{Vendor/Modem}}_{\text{动底层才需要}}
$$

逐步拆解：

- **Boot + System + Data**：覆盖「系统层事故」——刷 ROM 翻车、系统崩溃、应用数据丢失，这一组都能还原。
- **EFS**：覆盖「身份层事故」——IMEI/基带丢失。**体积最小、价值最高、必须无条件包含**。
- **Vendor/Modem**：只有要动厂商层/基带固件时才需要——日常刷 ROM 不必每次备。

这个公式的决策逻辑是「**风险覆盖，而非全量覆盖**」：备份范围与你的操作风险匹配，既保证出事能救，又不让每次备份都耗时占空间。**EFS 无条件备、系统三件套按刷机频率备、底层分区按操作备**——这套节奏就是老手的备份习惯。

## 6 核心要点：备份/恢复对照表

| 分区 | 内容 | 丢失症状 | 备份方式 | 恢复场景 |
| --- | --- | --- | --- | --- |
| Boot | 内核+ramdisk | 无法开机 | TWRP | 刷内核翻车 |
| System | 系统主体 | 系统崩溃 | TWRP | 刷 ROM 翻车 |
| Data | 用户数据 | 数据丢失 | TWRP/云/导出 | 清 data 后悔 |
| EFS | IMEI/基带校准 | 无基带 | TWRP/dd | IMEI 丢失 |
| Vendor | 厂商层 | 硬件异常 | TWRP | 改厂商层后 |
| Modem | 基带固件 | 无信号 | TWRP | 刷基带翻车 |

## 8 快速自查清单

做备份或恢复前，逐条确认：

- 这次备份是否**包含 EFS**？EFS 是否单独确认过存在？
- 备份存到了**手机之外**（电脑/OTG/SD）？
- 加密 data 的**屏锁密码**准备好了吗？
- 恢复前确认备份**完好可校验**？恢复到哪个「时刻」想清楚了吗？
- 恢复后是否验证**信号、IMEI、系统启动**三项关键状态？

## 9 小结

- 完整备份分两层：**用户数据备份**（救数据）与 **Nandroid 系统备份**（救整个状态），两者互补。
- TWRP 备份按风险勾分区：**Boot+System+Data+EFS 是日常组合**，动底层才加 Vendor/Modem；备份务必复制到电脑。
- **EFS 备份是第一铁律**：IMEI 丢了极难恢复，EFS 只有几 MB，TWRP 或 `dd` 都能备。
- 恢复是「回到过去」：跨版本恢复可能不兼容，恢复前想清楚目标时刻、恢复后验证信号/IMEI/启动。
- 备份范围公式：**EFS 无条件备 + 系统三件套按需备 + 底层分区按操作备**。
