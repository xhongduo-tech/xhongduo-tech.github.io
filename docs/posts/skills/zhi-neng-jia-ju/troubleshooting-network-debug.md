## 为什么排障能力决定服务口碑

安装调试的最后一项技能，是**排障**。客户记住的不是你装得多快，而是出问题时你能多快解决。很多新手排障靠「重启大法」——重启路由器、重启设备、重装 App，碰运气。老手的排障是一条**分层定位**的流水线：先确定故障在哪一层，再在这一层里做二分排查，通常几分钟就能锁定根因。这一篇把排障方法论、常见故障速查与网络信号调试讲透。

## 1 分层定位：故障在哪一层

回顾第 1 篇的四层架构，排障的第一动作永远是**定位层级**：

**物理层（电与信号）**：设备有没有电、指示灯状态、网线/天线物理连接。症状：设备完全无反应、灯不亮。

**网络层（连接与传输）**：设备是否入网、Wi-Fi 信号强弱、网关是否在线、IP 是否冲突。症状：App 显示离线、时好时坏。

**平台层（云与自动化）**：厂商云是否正常、场景规则是否匹配、自动化是否触发。症状：设备在线但控制不了、场景不执行。

**应用层（交互界面）**：App/语音助手的问题。症状：App 操作无反应但设备本身正常、语音识别不准。

**排障口诀：从物理层往上逐层排除。** 先看设备灯亮不亮，再看 App 在线状态，再测云端/规则，最后怀疑 App 与语音。<span class="marginnote">「重启大法」为什么时灵时不灵：<strong>重启一次往往同时刷新了物理层（重上电）、网络层（重新入网）、平台层（重新握手）三层状态</strong>——碰巧修好的就是「哪一层暂时卡住」，修不好的就是「哪一层真断了」。分层定位能把「碰巧」变成「确定」。</span>

## 2 常见故障速查表

| 故障现象 | 优先怀疑层 | 快速检查 | 处理 |
| --- | --- | --- | --- |
| 设备完全无反应 | 物理层 | 指示灯亮吗 | 查供电、插头、漏保跳闸 |
| App 显示离线 | 网络层 | 设备灯亮但离线 | 查 Wi-Fi 信号、网关在线、是否被 AP 隔离 |
| 时好时坏 | 网络层 | 信号强度/RSSI | 挪设备、加 AP、固定信道 |
| 设备在线但控制不了 | 平台层 | 云端状态 | 重启设备/网关，查厂商云公告 |
| 场景不触发 | 平台层 | 触发源在线吗 | 查传感器电量、条件匹配、日志 |
| 语音叫不醒 | 应用层 | 唤醒灵敏度 | 查静音、麦克风、唤醒词 |
| 配网失败 | 网络层 | 手机 2.4 GHz？ | 按第 11 篇六步查 |

**重点：同一个「离线」，三种完全不同的处理。** 灯不亮 → 查电；灯亮但 App 离线 → 查网；灯亮、App 在线但场景不动 → 查规则。**别把所有问题都叫「网不好」。**<span class="marginnote">给客户远程排障时，第一句话永远问「设备灯什么颜色」：<strong>灯的颜色/闪烁模式是设备自带的「自报家门」</strong>——红灯=故障、蓝灯闪烁=配网模式、常亮=正常。先让客户报灯，比让客户乱点 App 高效得多。</span>

## 3 网络信号调试

无线信号问题是智能家居「隐痛」，四个调试手段：

**① 看 RSSI（信号强度）**。设备信息里能看到与路由器的信号强度，单位为 dBm。经验值：`-50dBm` 以上优，`-67dBm` 左右一般，`-80dBm` 以下设备会频繁掉线。**RSSI 是「该不该挪设备/加 AP」的客观依据。**

**② 换信道与频段**。2.4 GHz 信道拥挤时，固定到空闲信道（1/6/11 中选干扰小的）；支持 5 GHz 的设备尽量用 5 GHz（干扰少、速度快，但穿墙弱）。

**③ 挪设备与 AP**。设备掉线重灾区常是「跨墙、远距、金属遮挡」。路由器/AP 位置往全屋中心挪、避开弱电箱与金属柜；设备挪到信号好的位置（USB 供电的传感器可换插座）。<span class="marginnote">「金属是 Wi-Fi 的墙中墙」：<strong>路由器放进金属电视柜、设备塞进铝合金窗框边，信号衰减远超想象</strong>。调试时先排除「金属遮挡」这个隐藏杀手。</span>

**④ 用工具量化**。手机装 Wi-Fi 分析 App（看信道占用、信号热力），路由器后台看设备连接数与信号强度。设备多时，把非必要 Wi-Fi 设备挪到 Zigbee 网关下，给 Wi-Fi 减负。

## 4 工具清单

一套趁手工具，排障效率翻倍：

**软件**：各生态 App（米家/HomeKit/HA）、Wi-Fi 分析工具、MobaXterm/SSH（进 HA/路由器）、浏览器开发者工具（查 API）。

**硬件**：万用表（查供电与电压）、网线测试仪（查网线通断）、备用的电源适配器与网线、标签打印机（给线与设备贴标签）。<span class="marginnote">「备用电源适配器」是排障神器：<strong>设备反复重启，十有八九是适配器老化或功率不足</strong>——换一个已知好的适配器，立刻见分晓。排障包里常备几个 12V/5V 适配器，能现场排除一大类「灵异重启」。</span>

**文档**：给每个客户留一份**设备清单**（型号、IP、账号权限、安装位置、售后联系），排障时对照清单逐项核对，比现场乱翻 App 高效。

## 5 核心对比表：三类信号问题的判断

纯技能主题，用对比表替代公式解析：

| 信号问题 | 典型表现 | 判断依据 | 对策 |
| --- | --- | --- | --- |
| 距离太远 | 远端设备频繁离线 | RSSI 低（< -75dBm） | 加 AP/挪设备 |
| 信道拥塞 | 时好时坏、延迟高 | 信道占用分析 | 固定空闲信道 |
| 频段错误 | 设备搜不到 | 设备只支持 2.4G | 手机切 2.4G 配网 |
| 金属遮挡 | 局部区域全灭 | 挪开金属即恢复 | 避开金属箱体 |

## 6 术语速查表

排障现场要用到的信号与网络词汇：

| 术语 | 含义 |
| --- | --- |
| RSSI | 信号强度指标，单位 dBm，越低越强 |
| 分层定位 | 按物理→网络→平台→应用逐层排除故障 |
| 时延 | 指令到响应的时间，云端链路延迟明显 |
| 信道拥塞 | 同一信道设备过多导致相互干扰 |
| 频段 | 2.4/5 GHz，设备兼容性决定配网频段 |
| AP 隔离 | 客户端互不可见，阻断设备通信的设置 |
| 掉电记忆 | 断电后设备自动恢复状态的能力 |
| 幽灵执行 | 无触发记录的异常自动化执行 |
| 回程 | Mesh 节点到主路由的传输路径，有线回程更稳 |

## 7 分层排障速查

把「分层定位」做成一张可对照的速查卡，远程指导客户也能用：

| 故障层 | 典型症状 | 第一检查动作 |
| --- | --- | --- |
| 物理层 | 设备无反应、灯不亮 | 查供电、插座、漏保 |
| 网络层 | App 离线、时好时坏 | 查信号强度、网关在线、AP 隔离 |
| 平台层 | 在线但控制不了 | 查云端状态、重启设备/网关 |
| 应用层 | App/语音操作无反应 | 查 App 版本、唤醒灵敏度 |
| 电源层 | 设备反复重启 | 查适配器功率、插座供电 |
| 网关层 | 传感类设备集体离线 | 查网关在线、网关与设备生态匹配 |
| 云层 | 多品牌同时异常 | 查厂商云公告、运营商宽带状态 |

## 8 小结

- 排障第一动作：**分层定位**——物理 → 网络 → 平台 → 应用，从下往上排除。
- 同一「离线」三种处理：**灯不亮查电、灯亮离线查网、在线不动作查规则**。
- 信号调试四手段：**看 RSSI、换信道频段、挪设备 AP、用工具量化**。
- 工具三件套：**生态 App、万用表、备用适配器**；客户设备清单要存档。
- 先让客户报设备灯的状态，远程排障就成功了一半。
