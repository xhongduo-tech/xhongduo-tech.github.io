## 为什么米家是多数家庭的「第一套自动化」

米家是绝大多数中国家庭的第一套智能家居，它的自动化是**「当…就…」的图形化拼装**——不需要写代码，手指点点就能搭出场景。但简单不等于没门道：同样的几个组件，新手拼出的场景频繁误触发，老手拼出的场景稳如老狗。这一篇把米家自动化的模型、条件与实战步骤讲透，让「当…就…」拼出专业级场景。

## 1 米家自动化的「当…就…」模型

米家 App 里的自动化，骨架是标准的 **TCA 模型**（第 18 篇），但用「当…就…」的句式呈现：

**「当」（触发条件）**：满足什么条件开始执行。米家把触发分两类：
- **状态触发**：设备状态变化，如「人体传感器：有人移动」「门磁：打开」「门锁：从外面开锁」。
- **时间/定时触发**：「每天 7:00」「日出时」「日落时」。

**「且」（附加条件）**：触发后还需满足的条件。例如「仅当 18:00–23:00」「仅当家中无人」。

**「就」（执行动作）**：执行什么。可选：**控制设备**（开灯、关窗帘、调空调）、**执行智能场景**（调出已保存的场景快照）、**延时后执行**、**发送通知**、**语音播报**。<span class="marginnote">米家的「智能场景」是快照复用机制：<strong>把「全屋关灯 + 关窗帘 + 空调关机」存成一个场景，多个自动化都可以引用它</strong>——改一处，所有引用同步生效，避免到处复制粘贴。</span>

**重点：米家自动化的本质是「一条当→就」，但可以层层嵌套。** 一条「就」里可以「执行场景」，而场景本身又由多条自动化驱动——这就是「复杂逻辑拆成多条简单规则」的米家哲学。

## 2 拼装动作的四个细节

**① 延时动作**：动作里支持「等待 X 分钟再执行」。例：「门磁打开」→ 等 30 秒 → 还没关 → 才报警。**延时是防误报的关键**，但要注意米家延时只支持「先等后动」，不支持「动后等」。

**② 生效时间**：自动化可以限定「仅这个时间段生效」。例：回家场景限定 18:00 后亮灯、白天只开窗帘。<span class="marginnote">生效时间是区分「老手」与「新手」的第一道分水岭：<strong>新手写「一开门就亮灯」，白天进门也亮；老手写「18:00 后才亮灯」，白天自然光够就不开</strong>——省电且不刺眼。</span>

**③ 反向逻辑与布防**：离家布防要「离家自动化的动作里，把门窗磁的报警自动化设为布防状态」。米家用「安防」体系管理：设防状态下门窗磁触发才报警，撤防状态下不报。

**④ 设备在线校验**：自动化执行「控制设备」时，若设备离线，动作静默失败。给关键动作加「执行后通知」，能发现「规则跑了但设备没动」的隐蔽故障。

## 3 实战：回家场景完整配置

把第 18 篇的「回家场景」在米家 App 里一步步搭出来：

**第 1 步：新建智能场景（快照）**。在米家 App → 智能 → 右上角「+」→ 手动执行 → 新建场景，命名「回家模式」。添加动作：客厅灯开（亮度 80%）、窗帘打开、空调调至 26℃、小爱播报「欢迎回家」。

**第 2 步：新建自动化**。「+」→ 自动化 → 命名「回家自动触发」。

**第 3 步：设置触发**。「当」选「门锁：从外面开锁」（指纹/密码开锁都算）或「人体传感器：有人移动」。

**第 4 步：添加附加条件**。「且」选「仅当 17:30–23:30」（傍晚回家才亮灯）与「家中无人」（需要家中有人体传感器，判断家里没人才执行，防反复触发）。

**第 5 步：设置动作**。「就」选「执行智能场景：回家模式」+「发送通知到手机」。<span class="marginnote">「家中无人」这类条件依赖人体传感器——<strong>如果没有装人体传感器，就别勾这个条件</strong>，否则自动化永远不触发。条件引用的设备不在家，是「自动化不生效」的隐藏原因。</span>

**第 6 步：保存并测试**。保存后手动触发一次（App 里有「测试运行」或直接关门模拟），看日志：触发有没有发生、动作有没有执行。

## 4 米家自动化的局限与进阶

**局限一：云端为主**。多数米家自动化在小米云上跑，断网时自动化失灵（手动控制仍可用）。**破解**：优先选支持「本地执行」的中枢网关，把关键自动化设为本地执行（App 里有「本地化」标识的设备）。

**局限二：条件表达能力有限**。复杂的「或」「嵌套」「变量」在米家里难实现。例如「温度 > 30℃ 或 湿度 < 40% 就开空调」这种多条件，米家拼起来很别扭。

**局限三：跨生态受限**。米家自动化只能控制米家设备。设备横跨米家 + HomeKit + 其他品牌时，自动化必须交给 HA（第 20 篇）。

**进阶路线**：米家负责「日常简单自动化」，HA 负责「复杂与跨生态自动化」，两者通过 MIoT 集成打通——**米家设备多，HA 大脑强**，是当下主流的高级架构。<span class="marginnote">米家 + HA 的分工是黄金组合：<strong>米家设备便宜且全，负责「执行」；HA 逻辑强，负责「决策」</strong>。米家里关掉与 HA 冲突的自动化，避免两套规则抢同一个开关。</span>

## 5 核心对比表：米家 vs HA 自动化能力

纯技能主题，用对比表替代公式解析：

| 能力维度 | 米家自动化 | Home Assistant |
| --- | --- | --- |
| 配置方式 | 图形化「当…就…」 | YAML/图形化编辑器 |
| 上手难度 | 低 | 高 |
| 条件表达 | 有限 | 强（模板、变量、嵌套） |
| 跨生态 | 仅米家 | 全部接入设备 |
| 运行位置 | 云为主（可本地化） | 全本地 |
| 断网可用 | 部分 | 完全 |
| 适合 | 多数家庭日常场景 | 复杂/跨生态/极客 |

## 6 术语速查表

米家生态的自动化词汇，配置时共用：

| 术语 | 含义 |
| --- | --- |
| 智能场景 | 米家中的设备状态快照，可被多个自动化引用 |
| 自动化 | 「当…就…」的图形化规则 |
| 触发条件 | 自动化开始评估的「当」 |
| 附加条件 | 触发后还需满足的「且」 |
| 执行动作 | 满足后执行的「就」 |
| 延时动作 | 先等待再执行的中间步骤 |
| 生效时间 | 自动化只在指定时间段内生效 |
| 本地执行 | 场景在本地中枢运行，断网可用 |
| 设防/撤防 | 安防警戒状态的开启与解除 |

## 7 米家自动化调试口诀

场景不生效时，按这套口诀逐步定位：

| 排查步骤 | 检查内容 |
| --- | --- |
| ① 触发源 | 传感器是否在线、电量是否充足 |
| ② 附加条件 | 条件引用的设备是否在家、条件是否满足 |
| ③ 生效时间 | 是否落在生效时间段外 |
| ④ 动作目标 | 目标设备是否离线、名称是否匹配 |
| ⑤ 云端状态 | 厂商云是否异常、是否需改本地执行 |
| ⑥ 场景冲突 | 多条自动化是否抢同一个开关 |

## 8 小结

- 米家自动化 = **「当…就…」的 TCA 图形化拼装**；「智能场景」是快照复用机制。
- 拼装四细节：**延时防误报、生效时间、布防/撤防、离线校验通知**。
- 回家场景五步：**建快照 → 建自动化 → 设触发 → 加条件 → 设动作**。
- 局限三处：**云端为主、条件表达有限、仅米家生态**。
- 进阶架构：**米家负责执行、HA 负责决策**，两套自动化避免抢同一开关。
