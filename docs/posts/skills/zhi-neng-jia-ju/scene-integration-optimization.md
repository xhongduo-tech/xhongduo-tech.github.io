## 为什么联调才是「交付」

设备装好、自动化写好，还不能叫完工。真正的完工是：**所有场景在真实生活里反复演练不出错，客户不看说明书也能用好**。联调（集成测试）就是交付前的总彩排——把第 18–22 篇的成果串起来，全场景走查一遍，发现问题当场修掉。这一篇讲联调方法论、体验优化方向与交付标准，作为整个专题的收尾。

## 1 联调方法论：全场景走查

联调不是「随便试几个」，而是有套路的**验收流程**：

**第 1 步：拉出场景清单**。把交付单里的全部自动化、场景列成表（第 18 篇的「场景对照表」），逐条过，不遗漏。

**第 2 步：全场景走查**。模拟真实操作逐条验证：
- 手动触发一次（App/语音/物理按键），确认动作正确。
- 模拟触发源（开门、进人、到时间），确认自动触发链路完整。
- 确认**反向场景**成立（睡眠 → 起床、离家 → 回家）。

**第 3 步：边界测试**。测「最容易翻车」的边界情况：反复进出防抖、断电恢复后设备状态、低电量告警、场景并发冲突。<span class="marginnote">边界测试的三个金场景：<strong>①反复开关门 5 次（防抖是否生效）；②拔掉路由器电源再恢复（设备能否自动重连）；③同时触发两个场景（会不会打架）</strong>。这三个过了，日常使用基本稳。</span>

**第 4 步：日志复盘**。在米家/HA 日志里回看联调过程的触发记录，确认每个自动化都按预期触发与执行，没有「幽灵执行」。

## 2 体验优化：五个方向

联调不是「能跑就行」，要「用得舒服」。五个优化方向：

**① 延迟优化**。指令从按下到设备响应的时间，超过 1 秒就有「迟钝感」。排查路径：云端链路（换本地执行）、Wi-Fi 拥塞（挪设备/换信道）、网关负载（拆分网关）。**本地执行的场景延迟百毫秒级，云端要经过厂商服务器往返，是延迟的最大来源。**

**② 误触发治理**。联调时观察哪些场景「不请自来」：空调误触发灯、窗外车灯误触发人体。逐条调灵敏度、加条件、加双触发。

**③ 光与声的过渡**。把「瞬间切换」改成「渐变过渡」：灯光渐亮渐暗、音量渐起。体验优化的细节全在这里——**智能家居的高级感，藏在「过程」里。**

**④ 故障兜底**。设备离线、场景失灵时，要有「手动兜底」：物理按键保留、语音兜底、App 手动控制。**智能是增量，不能取代安全与可靠的基本盘。**<span class="marginnote">「智能是增量」是设计底线：<strong>家里必须有离开智能也能用的路径——灯要能手动开、门锁要有机械钥匙、安防要有物理开关</strong>。联调时专门检查「把智能全关掉，这房子还能不能正常住」。</span>

**⑤ 能耗与寿命**。传感器低电量提醒、设备不必要的频繁动作（如窗帘反复微调）减少损耗。给客户规划「年度维护」：换电池、清滤网、查固件。

## 3 交付清单与客户培训

联调通过后，交付不是「交钥匙」，而是三件事：

**① 交付文档**：设备清单（型号、IP、安装位置、账号权限）、场景对照表（反向场景成对）、故障速查卡（设备灯的含义、重启步骤）、售后联系方式。

**② 现场培训**：带客户走一遍四个核心场景——离家、回家、睡眠、起床，让客户**亲手操作一遍**；教客户「App 在哪、语音怎么说、物理按键在哪、出了问题找谁」。<span class="marginnote">培训的黄金法则是「让客户亲手做一遍」：<strong>看十遍不如做一遍</strong>。客户亲手设置过一次睡眠场景，就不会因为「不会用」而把智能当摆设。</span>

**③ 回访机制**：交付后 1 周、1 个月回访，收集真实使用中的问题——**智能家居的问题往往在入住后才暴露**（生活习惯与预设场景不匹配）。回访是口碑的来源，也是下一单的开始。

## 4 常见联调问题与优化方向

| 联调问题 | 根因方向 | 优化动作 |
| --- | --- | --- |
| 场景触发有延迟 | 云端链路 | 改本地执行、减 Wi-Fi 拥塞 |
| 误触发频繁 | 传感器太灵敏/条件缺失 | 调灵敏度、加时间/双触发条件 |
| 断电后设备不恢复 | 设备无掉电记忆 | 开「断电恢复自动重连」、检查固件 |
| 两个场景打架 | 规则冲突、重复控制同一设备 | 拆分场景、统一「一个大脑」 |
| 客户不会用 | 交付培训不足 | 现场亲手演示、做指令卡 |

**优化心法**：联调发现的问题，**优先改「条件与结构」，而不是改「设备」**。多数体验问题（误触发、延迟、冲突）都是规则设计问题，换设备解决不了。

## 6 术语速查表

联调与交付阶段的词汇，统一服务口径：

| 术语 | 含义 |
| --- | --- |
| 联调 | 全场景集成的验收测试 |
| 走查 | 按清单逐场景验证执行链路 |
| 边界测试 | 测反复触发、断网恢复、并发冲突等边界情况 |
| 反向场景 | 与场景成对的撤销场景 |
| 故障兜底 | 自动化失灵时的手动控制路径 |
| 渐变过渡 | 灯光/音量用渐变更替而非瞬间切换 |
| 幽灵执行 | 无触发记录的异常执行，需日志复盘 |
| 回访机制 | 交付后定期收集使用问题的服务流程 |
| 交付文档 | 设备清单、场景表、速查卡等服务资料 |

## 7 交付服务流程

把联调与交付做成可复制的服务流程，保障口碑：

| 阶段 | 关键动作 | 输出 |
| --- | --- | --- |
| 联调前 | 拉出场景清单，逐条过 | 场景对照表 |
| 联调中 | 全场景走查、边界测试、日志复盘 | 验收记录 |
| 交付时 | 文档移交、现场亲手培训 | 设备清单、指令卡 |
| 交付后 | 1 周/1 月回访收集问题 | 优化清单 |

## 8 小结

- 联调四步：**拉清单 → 全场景走查 → 边界测试 → 日志复盘**。
- 体验优化五方向：**延迟、误触发、渐变过渡、故障兜底、能耗寿命**。
- 交付三件事：**文档、现场亲手培训、回访机制**。
- 优化心法：**先改条件与结构，后换设备**；多数体验问题出在规则设计。
- 「智能是增量」——离开智能也能正常住，是设计底线也是职业底线。
