## 为什么网关决定系统「活不活得起来」

前面装好的传感器、灯、窗帘，很多都还「各说各话」：Zigbee 设备用的是私有的短距离无线电，Wi-Fi 设备用的是 IP 协议，两者根本不通。把这一堆设备拧成一个系统、让它们互相听懂，靠的就是**网关与家庭中枢**。网关选错、部署错，全屋设备再多也是散沙。这一篇把网关与中枢的角色、选型与部署讲清楚。

## 1 网关与中枢：两个易混的概念

**网关（Gateway）**：协议转换器。把 Zigbee/蓝牙/Thread 等私域网络的数据，翻译成局域网/互联网能懂的 IP 协议。**网关管的是「设备怎么进网络」。**

**家庭中枢（Hub/Home Hub）**：家庭的大脑与协调者。它保存场景规则、在本地执行自动化、管理家庭成员授权。**中枢管的是「场景在哪跑」。**

两者的关系：**网关负责「翻译」，中枢负责「决策」**。很多设备（如米家多功能网关）兼做两者，但也有明确分工的架构：Zigbee 网关只管收设备，自动化规则却可能在云端或 HA 中枢上跑。<span class="marginnote">分清「网关」与「中枢」是架构能力的分水岭：<strong>网关坏了，设备失联；中枢断了，场景失灵——但设备还能手动控制</strong>。排障时先问「是设备连不上（网关问题）还是场景不触发（中枢问题）」。</span>

## 2 网关类型

**Zigbee 网关**：Zigbee 设备唯一的上网通道。常见形态：独立网关（米家多功能网关）、内置在智能音箱/摄像头里的「子网关」、以及 USB 网关（用于 HA）。选型关键：**同一生态**——米家 Zigbee 设备要米家网关；且**覆盖范围**——一个 Zigbee 网关约覆盖 50–80㎡，大户型要多网关。

**Thread 边界路由器（Border Router）**：Thread 网络的「门」，把 Thread Mesh 接进 IPv6 家庭局域网。常见由 HomePod、Apple TV、米家中枢网关兼任。Thread 设备部署前，先确认家里**至少有一个已启用**的边界路由器。<span class="marginnote">Zigbee 与 Thread 网关的差别：<strong>Zigbee 网关是「私域翻译官」，Thread 边界路由器是「IPv6 原生门户」</strong>。Thread 设备自带 IP，边界路由器只是放行；Zigbee 设备没有 IP，全靠网关转译。这也是 Thread 架构更干净的原因。</span>

**多模网关**：一个盒子同时支持 Zigbee + 蓝牙 + Wi-Fi（+Thread），省去多网关堆叠，是全屋布点的首选——米家中枢网关、Aqara M 系列都是多模形态。

**HA 中枢（跑 Home Assistant 的设备）**：以树莓派、迷你主机、NAS 形式存在的本地大脑，配合 USB Zigbee 网卡（如 Conbee、Zigbee 2 MQTT 网卡）即可接收 Zigbee 设备，配合 Thread 边界路由器接收 Thread 设备。是极客路线的一体化中枢。

## 3 网关部署原则

网关的物理部署，比选型更容易被忽略，四条原则：

**① 位置居中**：网关放全屋**几何中心附近**的开阔位置（客厅电视柜、走廊吊顶内），不要塞进弱电箱（金属箱屏蔽无线信号），不要放地面角落。

**② 数量按户型**：单网关覆盖 50–80㎡；大户型、复式、隔墙多的地方要**多网关分区域部署**，各区域设备就近入网。Zigbee 的 Mesh 特性让「路由器节点」能接力，但网关本身仍是「根」。

**③ 常供电 + 有线**：网关是 7×24 设备，必须**常供电**（不要插在带开关的排插上）；关键网关（HA 中枢、HomePod）优先插网线——网关本身不稳定，全屋跟着遭殃。<span class="marginnote">网关插在带开关排插上是「全屋掉线」的经典乌龙：<strong>家人顺手按掉排插开关，整个 Zigbee 网络集体离线</strong>。网关、路由器这类核心设备，要么插常通插座，要么在交付单上大字标注「请勿断电」。</span>

**④ 固件更新**：网关固件定期更新，修复安全漏洞与协议 bug。给客户设置好自动更新或提醒机制。

## 4 家庭中枢的角色与方案

中枢让「场景在本地跑」，是响应速度与断网可用的分水岭。三种主流方案：

**米家体系**：场景规则在小米云上执行（部分支持本地执行）。带「本地执行」能力的中枢网关（如小米中枢网关）能把关键场景放本地，断网也能跑。**给客户推荐带本地执行的网关**，体验质变。

**HomeKit 体系**：家庭中枢 = HomePod / Apple TV / 长期在家的 iPad。场景全部在本地执行，断网不影响自动化（远程访问才依赖外网）。**提醒客户家里至少有一个常驻中枢**，否则 HomeKit 自动化不完整。

**HA 体系**：HA 本身就是一个本地中枢，自动化全在本地跑，断网完全可用，还能通过「本地云」桥接把米家等设备也纳入本地控制。<span class="marginnote">「本地执行」是这套系统高级感的来源：<strong>米家本地场景延迟百毫秒级，云端场景要经过厂商服务器往返</strong>。同样是「开门亮灯」，本地快、稳、断网可用，体验完全两档。</span>

## 5 核心对比表：常见中枢方案

纯技能主题，用对比表替代公式解析：

| 方案 | 中枢硬件 | 场景运行位置 | 断网可用 | 上手难度 | 适合 |
| --- | --- | --- | --- | --- | --- |
| 米家+本地网关 | 小米中枢网关 | 本地/云混合 | 本地场景可用 | 低 | 米家生态主流家庭 |
| HomeKit | HomePod/Apple TV/iPad | 本地 | 全本地可用 | 低 | 苹果用户 |
| HA | 树莓派/迷你主机/NAS | 本地 | 全本地可用 | 高 | 极客/跨品牌集成 |
| 纯云端方案 | 无本地中枢 | 厂商云 | 断网失灵 | 最低 | 低预算轻场景 |

**选型结论**：主流家庭优先「米家 + 支持本地执行的中枢网关」；苹果用户上 HomeKit 中枢；要跨品牌一统、追求极致本地，直接上 HA。

## 6 术语速查表

网关与中枢是架构的核心词，先把口径统一：

| 术语 | 含义 |
| --- | --- |
| 网关 | 协议转换设备，私域协议与 IP 之间的翻译官 |
| 中枢 | 家庭自动化大脑，保存场景规则并本地执行 |
| 多模网关 | 同时支持 Zigbee/蓝牙/Wi-Fi/Thread 的网关 |
| 子网关 | 内置于音箱、摄像头等设备中的网关功能 |
| 边界路由器 | Thread 网络接入家庭 IPv6 局域网的门户 |
| 本地执行 | 场景在家庭中枢本地运行，断网可用 |
| 云端执行 | 场景在厂商云运行，断网时自动化失灵 |
| 常供电 | 设备持续通电运行，不经过开关排插 |
| 弱电箱 | 入户线缆汇集的金属箱体，会屏蔽无线信号 |

## 7 网关部署常见误区

网关部署的坑，往往在「全屋掉线」时才暴露：

| 误区 | 正解 |
| --- | --- |
| 网关塞进弱电箱 | 金属箱屏蔽信号，网关要放开阔高处 |
| 网关插在开关排插上 | 排插一关全屋离线，核心设备必须常供电 |
| 一个网关管全屋 | 单网关覆盖 50–80㎡，大户型要分区多网关 |
| 网关随便买个便宜的就行 | 网关是系统根节点，稳定性直接决定全屋体验 |
| 只买设备不配本地中枢 | 云端执行断网失灵，本地中枢是体验质变的关键 |
| 固件更新可有可无 | 网关固件修复协议 bug 与安全漏洞，必须定期更新 |
| 网关越多越好 | 网关过多会增加管理复杂度，够用即可 |
| 网关必须用网线 | 网线更稳，但无线 Mesh 网关也能用 |
| 中枢和网关是一回事 | 网关管翻译、中枢管决策，两者可分离 |
| 断网全屋就瘫 | 本地中枢+本地执行，断网核心场景仍可用 |
| 网关放角落就行 | 位置居中、避开金属，覆盖才均匀 |
| 只认一个品牌网关 | 跨生态需求下，多模/HA 网关更灵活 |
| 网关离线就换新 | 先查供电、固件、路由器，别急着换硬件 |
| 中枢随便选 | HomeKit 中枢要常驻，米家优先本地网关 |
| 忽略网关负载 | 单网关设备过多会卡顿，注意容量上限 |

## 8 小结

- **网关管「翻译」、中枢管「决策」**：网关坏设备失联，中枢断场景失灵。
- 网关类型：**Zigbee 网关、Thread 边界路由器、多模网关、HA 中枢**，按生态与协议选。
- 部署四原则：**位置居中、多网关分区、常供电有线、固件勤更新**。
- 中枢让场景本地跑：**米家选本地网关、HomeKit 需常驻中枢、HA 天然全本地**。
- 网关勿插开关排插，交付单要标注「核心设备请勿断电」。
