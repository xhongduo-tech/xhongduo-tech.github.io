## 为什么安装师傅必须先懂协议

刚入行的安装师傅常被一个现象困惑：同是「智能插座」，A 牌子的插上电、手机扫一下就配好了；B 牌子的却要再买一个网关，不然怎么扫都搜不到。差别不在插座好坏，而在它们用了不同的**通信协议**。

协议决定了一台设备的三个安装要素：**要不要网关、功耗多大、能传多大数据**。不懂协议，就做不好三件事——选型（该给客户配什么设备）、布线（电源怎么留）、排障（设备连不上时先怀疑哪一层）。这一节把最常见的四种协议讲透，后面每一篇的设备安装都在用这里的结论。

## 1 先分层：用「三层视角」看协议

协议很难讲，是因为「Wi-Fi」这个名字同时指了好几层的东西。我们只需要三个层次就能把四种协议讲清楚：

**应用层**：设备之间「说人话」的规矩，规定消息的格式与含义——「开灯」「报温度 25.3℃」怎么写。Matter、MQTT、各家私有协议都在这层。

**网络层**：数据包如何在设备间寻址与路由，IP 地址、Mesh 组网、路由算法都在这层。

**物理层/链路层**：电波怎么发、用什么频率、一个「0/1」怎么编码，以及一个设备怎么接入网络。

**重点：四种常用协议的分层归属完全不同。** Wi-Fi、Zigbee、蓝牙、Thread 主要工作在物理层与链路层，解决「信号怎么传」；而 Matter 是纯应用层标准，它**可以跑在** Thread、Wi-Fi 或以太网上。这解释了 Matter 设备为何能跨品牌——它把所有品牌统一到同一套「人话」上，至于底下用哪种无线电，各选各的。<span class="marginnote">这个分层思想不是书斋概念，而是排障的第一工具：设备「搜不到」，多半是<strong>物理层</strong>问题（频段、距离、干扰）；设备「搜得到但控制不动」，多半是<strong>应用层</strong>问题（协议不匹配、云不通）。</span>

## 2 Wi-Fi：带宽最大，代价是功耗与拥塞

**Wi-Fi** 是智能家居里最「常见也最娇贵」的协议。它基于 IEEE 802.11 系列，2.4 GHz 与 5 GHz 双频段，直连路由器，**不需要额外网关**——这是它最大的安装优势：通电、配网、完事。

**优点**：带宽大（几十到几百 Mbps），能承载视频流，摄像头、音箱、电视这类「大流量」设备非它不可；部署零成本，家里路由器现成。

**代价**：功耗高，电池设备撑不了多久，所以 Wi-Fi 设备几乎都要常供电；2.4 GHz 频段极度拥挤——邻居家的 Wi-Fi、蓝牙、微波炉、无线鼠标都在挤，信道拥塞是「设备总掉线」的头号嫌疑；设备数量多了之后，家用路由器的连接数上限（通常 30–50 台）会被迅速吃满。<span class="marginnote">2.4 GHz 只有 1、6、11 三个互不重叠的信道，三四个路由器就能把它占满。这是第 22 篇《故障排查与网络信号调试》要展开的内容，这里先种下「频段拥挤」的概念。</span>

## 3 蓝牙 Mesh：手机直连，低配但够用

**蓝牙（Bluetooth）** 最常见的形态是 **BLE（低功耗蓝牙）**，几乎所有手机都内置，因此诞生了智能家居里最简单的一种配网：**手机直连**——灯亮起、手机一搜、点一下，配对完成。蓝牙协议里专门用于智能家居的网状网络形态，叫作 **蓝牙 Mesh**。

蓝牙 Mesh 的特点：2.4 GHz 频段，功耗介于 Wi-Fi 与 Zigbee 之间，组网是**泛洪式（flooding）**——消息发给附近所有节点，层层转发，无需复杂路由。它适合**小规模、以手机为中心的轻量联动**：一把支持蓝牙的智能锁，手机靠近就开；一个蓝牙温湿度计，手机路过就同步数据。

**短板**：带宽小，传不了视频；泛洪式组网在节点多、消息频繁时效率骤降；手机直连模式意味着「手机不在家，设备就断联」。所以蓝牙设备通常只做**单品功能**，不承担全屋系统主干。<span class="marginnote">记住蓝牙的定位：<strong>它是「配网的引路人」与「手机近场交互」的补充协议</strong>——很多 Zigbee 设备第一次配网，正是借蓝牙由手机把 Wi-Fi 信息喂给网关的。</span>

## 4 Zigbee：低功耗 Mesh 的主力，但必须有网关

**Zigbee** 基于 IEEE 802.15.4，工作在 2.4 GHz，是当下国内智能家居传感生态（米家、Aqara、涂鸦）的绝对主力。它的安装特征最鲜明：**所有 Zigbee 设备都不能直连路由器，必须通过 Zigbee 网关入网。**

**Mesh 组网**：Zigbee 节点分三类——协调器（Coordinator，即网关）、路由器（Router，常供电设备如插座、灯泡充任）、终端（End Device，传感器这类休眠设备）。终端只跟路由器通信，数据一跳一跳传到协调器再上局域网。Mesh 的好处是**覆盖广、自愈**：一盏 Zigbee 灯泡断电，旁边的插座会自动接管转发路径。<span class="marginnote">Zigbee 网络里「常供电设备越多，网络越强壮」——因为每个常供电设备都可能是中继节点。这也是为什么布线时把<strong>插座、灯这类常供电 Zigbee 设备均匀分布</strong>，全屋信号会更稳。</span>

**优点**：功耗极低，纽扣电池的传感器能跑一两年；Mesh 覆盖大、自愈强；时延低、稳定。

**短板**：需要网关（选型多一层成本与排障点）；2.4 GHz 与 Wi-Fi 同频段，有潜在干扰；不同厂商的 Zigbee 网关之间**不能互通**——A 家网关收不了 B 家设备。

## 5 Thread：IPv6 的 Mesh 新锐，Matter 的「高速公路」

**Thread** 是近十年最有技术野心的智能家居协议。它仍基于 802.15.4 物理层，但把**网络层直接换成 IPv6**——每个 Thread 设备都拥有自己的 IP 地址，Mesh 网络内部用 IP 寻址，并通过**边界路由器（Border Router）**接入家庭局域网。

**为什么重要**：因为设备有了 IP，天然和互联网、局域网统一了语言——家庭中枢可以直接通过 IP 与每个 Thread 节点通信，无需私有协议转换。Matter 标准把它列为主要传输载体，Thread 也因此成为 HomeKit、Google、Amazon 新生态的底层。

**安装注意**：Thread 网络需要至少一个**边界路由器**（Thread Border Router），当前常由智能音箱、中枢网关（如 Apple TV、HomePod、小米中枢网关）兼任。<span class="marginnote">边界路由器是 Thread 网络的「门」：<strong>没有边界路由器，Thread 设备就只能在一个小范围内自我组网，上不了家庭局域网</strong>。部署 Thread 设备前，先确认家里有没有已启用的边界路由器。</span>

## 6 核心对比表：四选一怎么定

纯技能主题，用对比表替代公式解析。给客户做方案时，四种协议的选择逻辑就一句话：**数据形态决定协议**。

| 对比维度 | Wi-Fi | 蓝牙 Mesh | Zigbee | Thread |
| --- | --- | --- | --- | --- |
| 物理层标准 | IEEE 802.11 | Bluetooth 5.x | IEEE 802.15.4 | IEEE 802.15.4 |
| 频段 | 2.4 / 5 GHz | 2.4 GHz | 2.4 GHz | 2.4 GHz |
| 网络层 | IP | 私有 | 私有 | **IPv6** |
| 直连路由器 | 是 | 否 | 否 | 否 |
| 需要网关 | 不需要 | 不需要（手机直连） | **需要** | 需要（边界路由器） |
| 典型带宽 | 数百 Mbps | ~1–2 Mbps | ~250 kbps | ~250 kbps |
| 设备功耗 | 高 | 中 | 低 | 低 |
| Mesh 组网 | 无（AP 网络） | 泛洪式 | 路由式、自愈 | 路由式、IPv6 |
| 适合设备 | 摄像头/音箱/电视 | 锁/近场交互 | 传感/灯/插座 | Matter/HomeKit 新生态 |

读表抓两条结论：**要传视频，选 Wi-Fi，没有第二个选项**；**要低功耗、大覆盖、多节点，选 Zigbee（当下）或 Thread（面向未来）**。蓝牙是两者的轻量补充，不适合做全屋主干。这张表会贯穿本专题全部选型章节，值得在排障手册里抄一份。

## 7 小结

- 协议分**应用层/网络层/物理层**，排障先定层级：搜不到查物理层，控制不了查应用层。
- **Wi-Fi** 直连、带宽大、费电，负责视频与音箱；2.4 GHz 拥塞是掉线头号原因。
- **蓝牙 Mesh** 手机直连、轻量，做单品近场交互，不做全屋主干。
- **Zigbee** 低功耗 Mesh，**必须有网关**，是国内传感生态主力；常供电设备越多网络越强。
- **Thread** 用 IPv6 组 Mesh，需要**边界路由器**，是 Matter 与 HomeKit 新生态的传输底座。
- 选型主线：**视频走 Wi-Fi，传感走 Zigbee/Thread，网关负责协议转换**。
