## 为什么安全配置是「交付的最后一块拼图」

设备装好、场景跑通，很多人觉得完工了。但智能家居是**家里第一批「同时连着网和物理世界」的设备**——摄像头对着卧室、门锁守着大门、音箱竖着耳朵。这些设备一旦被攻破，网络风险会直接变成物理风险。安全配置不是可选加分项，而是**交付验收的标准项**。这一篇讲清智能家居的威胁模型与三层防护配置。

## 1 威胁模型：攻击面在哪里

先搞清楚「谁可能被攻击」，才能对症下药。智能家居的攻击面分三个：

**云侧**：设备与厂商云之间。厂商服务器被拖库、账号密码泄露、设备云接口被滥用——攻击者通过**你的账号**远程控制你的家。

**局域网侧**：家庭网络内部。家里一台设备被入侵（如劣质摄像头中招），攻击者以它为跳板**横向渗透**到其他设备；或邻居/陌生人在 Wi-Fi 覆盖内发起攻击。

**物理侧**：设备本体。门锁被撬、摄像头被拔、设备固件被物理读取。物理侧最容易被忽视，但对门锁、摄像头尤其致命。

**重点：智能家居安全的本质，是控制「身份」与「边界」。** 身份——谁能控制我的设备；边界——哪些设备之间能互相通信。<span class="marginnote">普通家庭的威胁排序：<strong>账号泄露与弱密码 > 局域网横向渗透 > 物理破坏</strong>。多数智能家居「被黑」事件，根源是账号密码泄露 + 默认口令未改，而非高级黑客攻击。</span>

## 2 网络安全三层配置

### 第一层：账号与口令

**所有平台强制改默认密码**，用强密码（≥12 位，混合大小写/数字/符号），开启**两步验证（2FA）**。
每个厂商账号用**独立密码**，避免一个密码泄露拖垮全家。
语音助手、门锁、摄像头这类**高危设备**，禁用「远程一键解锁/开锁」等免密远程功能，只开必要功能。<span class="marginnote">两步验证是「账号防丢」的保险：<strong>门锁 App 一旦被他人登录，等于把家门钥匙交给陌生人</strong>。给客户配置时，2FA 必须现场开启，并演示「异地登录」时的验证流程。</span>

### 第二层：网络分段

把家庭网络按信任级别**隔离（VLAN）**，是高级方案的标准配置：

**主网络**：手机、电脑等信任设备。
**IoT 网络**：智能设备专用，**与主网络隔离**——即便某台 IoT 设备被攻破，也够不到你的电脑与手机数据。
**访客网络**：客人用，完全隔离。

实现：支持 VLAN 的路由器/交换机上划分网段，IoT 设备全部连 IoT SSID。**注意：跨品牌集成（第 16 篇）要求设备与 HA 同网段**，隔离时要让 HA 与它控制的设备在同一 IoT 网段。<span class="marginnote">VLAN 隔离与「设备互相可见」是一对要平衡的矛盾：<strong>HA 要能看到所有设备（同网段），但设备又不该碰到你的电脑</strong>。折中方案：设备与 HA 放 IoT 网段，主设备（电脑手机）放主网段，仅开放必要的跨段通信。</span>

### 第三层：固件与端口

**固件保持最新**，定期检查厂商更新——固件补的是已知漏洞，老固件等于敞门。
关闭不必要的远程端口映射（UPnP 自动映射默认关），远程访问优先走**厂商官方加密通道**或 **VPN**，不要裸奔做端口转发。
摄像头等设备的默认服务端口、默认密码一律修改。

## 3 隐私保护配置

安全防「被入侵」，隐私防「被滥用」，同样要配置：

**摄像头隐私**：室内摄像头避开卧室与卫生间（第 8 篇已提）；不信任的摄像头用**物理遮挡**或隐私遮蔽功能；关键区域的录像存本地（NAS/SD 卡），避免全部上云。

**语音隐私**：音箱的录音与语音记录可查看/删除，敏感场景按麦克风物理静音键（第 12 篇）；了解并关闭不需要的「录音上传分析」类设置。<span class="marginnote">隐私不是「不用智能」，而是「知道数据去哪了」：<strong>给客户一份「数据流向说明」——哪些数据在本地、哪些上云、云上存多久</strong>，是专业服务的加分项，也是《个人信息保护法》下的合规义务。</span>

**家庭数据**：HA/米家的自动化日志、传感器数据，默认本地保存；如需远程访问 HA，用官方 Nabu Casa 云（加密通道）或自建 VPN，不要直接暴露 HA 的 Web 端口。

## 4 物理安全

网络配置再强，物理侧被突破也白搭：

**门锁**：确认防撬报警、防猫眼开启（室内把手防猫眼钮）功能开启；备用机械钥匙妥善存放（智能锁电子部分故障时，钥匙是唯一备用入口）。
**摄像头**：室外摄像头装在高处防破坏，选带防拆报警的型号。
**网关/HA 主机**：放在隐蔽、通风处；**关键设备断电会全屋失灵**，可加 UPS 保证门锁、网关在停电时仍工作。<span class="marginnote">「停电 = 门锁打不开」是智能家居特有的坑：<strong>电子锁在断电后靠电池供电，电池耗尽且无机械钥匙，就是被困在门外</strong>。交付时务必叮嘱客户：备好机械钥匙，并定期检查门锁电池。</span>

## 5 核心对比表：三类风险与对策

纯技能主题，用对比表替代公式解析：

| 风险类型 | 典型威胁 | 核心对策 | 优先级 |
| --- | --- | --- | --- |
| 云侧 | 账号泄露、弱密码 | 强密码 + 2FA + 独立密码 | 最高 |
| 局域网侧 | 横向渗透、IoT 跳板 | VLAN 分段 + 固件更新 + 关多余端口 | 高 |
| 物理侧 | 门锁被撬、设备破坏 | 防撬报警 + 防猫眼 + 机械钥匙 + UPS | 中高 |
| 隐私侧 | 录像/语音外泄 | 本地存储 + 物理遮蔽 + 数据流向透明 | 高 |

## 6 术语速查表

安全配置涉及网络安全与隐私合规，术语先对齐：

| 术语 | 含义 |
| --- | --- |
| VLAN | 虚拟局域网，把网络按信任级别分段隔离 |
| IoT 网段 | 智能设备专用网段，与主网络隔离 |
| 访客网络 | 给客人用的隔离网络 |
| 2FA | 两步验证，登录时需第二重验证 |
| UPnP | 即插即用端口映射，易被滥用，建议默认关闭 |
| 横向渗透 | 攻击者从一台被攻破设备跳转到其他设备 |
| 固件 | 设备内运行的底层软件，需定期更新 |
| 物理遮蔽 | 摄像头镜头盖或隐私遮蔽功能 |
| 数据流向 | 数据在本地还是上云、云上存多久的说明 |

## 7 安全交付检查清单

把安全做进交付流程，每单按清单执行：

| 检查项 | 标准 |
| --- | --- |
| 默认密码 | 所有平台与设备已改默认口令 |
| 两步验证 | 门锁/摄像头等关键 App 已开 2FA |
| 网络分段 | IoT 设备与主网络隔离（VLAN） |
| 端口映射 | 关闭 UPnP 自动映射，无裸奔转发 |
| 固件更新 | 所有设备固件为最新版 |
| 隐私边界 | 摄像头避开卧室卫生间，告知数据流向 |
| 物理备份 | 门锁机械钥匙、关键设备 UPS 就位 |

## 8 小结

- 威胁分**云侧、局域网侧、物理侧**；核心是管好「身份」与「边界」。
- 安全三层：**账号强口令 + 2FA、IoT 网络分段（VLAN）、固件更新 + 关多余端口**。
- 隐私三件事：**摄像头避开私密区、语音记录可查可删、数据流向向客户透明**。
- 物理侧：**门锁防撬 + 机械钥匙备份、关键设备 UPS**。
- 交付清单加上安全验收项：改默认密码、开 2FA、检查固件、说明数据流向。
