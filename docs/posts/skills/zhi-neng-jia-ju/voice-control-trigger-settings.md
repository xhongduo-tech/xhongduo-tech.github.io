## 为什么「触发」是场景灵不灵的试金石

场景跑得再好，触发错了也白搭：传感器太灵敏，人没到灯先亮；语音指令太绕，喊三遍才听懂；双触发没配好，误报不断。**触发是整个自动化链条的「扳机」**——扳机没调好，后面再精密的逻辑都是空转。这一篇把触发条件做一次全景梳理：传感器触发的高级设置、语音触发设计、以及触发条件的常见陷阱。

## 1 触发源全景

一个自动化可以被五类触发源启动，各有适用场景：

**传感器触发**：人体（PIR/存在检测）、门窗磁、温湿度、烟雾水浸。**最常用、最贴近物理世界**，但最需要防误报。

**时间触发**：定时（每天 7:00）、日落日出（日出亮窗帘、日落开灯）。**最可预期**，但不知变通——日出日落要按季节自动算，米家/HA 都内置太阳轨迹。

**设备状态触发**：某设备状态变化触发另一设备，如「门锁开锁 → 回家场景」「扫地机回充 → 通知」。本质是状态联动。

**语音触发**：用户说一句指令触发，如「小爱同学，睡觉了」。**最自然，但依赖设备在场与唤醒成功**（第 12 篇）。

**地理围栏触发**：手机进出某个地理区域（离家/回家）触发。**最智能**，但依赖手机定位精度与后台权限，误判率高——只适合做「离家布防」这类容错高的场景，不适合「进门亮灯」这种要精确的。

**重点：触发源的可靠性排序，传感器与时间最可靠，地理围栏最不可靠。** 重要场景用「可靠触发 + 条件」双保险，把不可靠的触发源当辅助。<span class="marginnote">地理围栏的坑：<strong>手机省电模式会杀掉定位服务，人离家几百米了围栏才触发</strong>。用它做布防可以（晚布防好过不布防），做「回家亮灯」就会人进门灯不亮。可靠场景请用门锁/门磁触发。</span>

## 2 传感器触发的高级设置

传感器触发不是「插上就用」，三个高级设置决定它的准头：

**① 灵敏度与防抖**。PIR 人体传感器（第 9 篇）可调灵敏度：过灵敏被空调气流误触发，过低人走过不触发。**防抖（冷却时间）**：设置两次触发的最小间隔，避免人站在门口时场景反复触发——常见设置为 30–60 秒。

**② 双触发（双重确认）**。重要场景用两个独立触发源互为校验：如「回家」用门磁 + 人体双触发，都成立才执行；「有人进卧室」用人体 + 门磁，避免「路过门口」误判成「进入卧室」。<span class="marginnote">双触发的本质是「用两个传感器互相验证」：<strong>人体传感器只看「有人动」，分不清「路过」还是「进入」；加一道门磁或压力传感器，才能确认「真的进了屋」</strong>。这就是第 9 篇说的「一个场景配两种触发源」。</span>

**③ 状态保持与持续触发**。存在检测（毫米波）能输出「有人/无人」持续状态，适合「人离开 5 分钟关灯」这类基于持续状态的场景；普通 PIR 只输出「动作」瞬时事件，做不了持续判断。**选传感器前先想清楚场景要「动作」还是「状态」**。

## 3 语音触发设计

语音触发的体验，三分靠硬件，七分靠指令设计：

**指令命名四原则**：口语化（说得出）、无歧义（不重名）、短（好记）、指向场景（不指单品）。「小爱同学，睡觉了」优于「小爱同学，关闭主卧灯、关闭客厅灯、关闭窗帘」。

**场景优先**：语音入口全部绑定**场景**而非单品（第 12 篇）。一个「睡眠模式」场景覆盖全屋动作，比逐句控制快且不容易出错。

**设备重名检查**：交付前把全屋设备名过一遍，找「主卧灯」与「主卧射灯」这类易混名，改成「主卧主灯」「床头灯」等无歧义名称。<span class="marginnote">语音最怕「有歧义的反问」：<strong>一次「你是说客厅灯还是客厅射灯？」的追问，就足以让用户弃用语音</strong>。命名时把「容易混的设备」当成需要规避的雷区，宁可多花十分钟，别让客户喊十遍。</span>

**误唤醒治理**：唤醒灵敏度调到适中；电视声、闲聊声频繁误唤醒时，开「连续对话关闭」「唤醒音提示」，或夜间用「勿扰模式」。

## 4 触发条件常见陷阱

**陷阱一：触发源离线。** 传感器没电、网关掉线，触发永远不发生。**对策**：给所有触发源配低电量提醒自动化，定期检查在线状态。

**陷阱二：条件写进触发。** 把「时间」写进触发（设了 10 个定时）而不是条件，导致逻辑爆炸。**对策**：触发只放「启动信号」，所有「限定」进条件。

**陷阱三：重复触发堆积。** 门磁开合瞬间触发多次，自动化反复执行。**对策**：用防抖、mode（single/queued）、或「状态变化」触发（只在状态改变时触发一次）。

**陷阱四：反向触发没处理。** 只写了「开灯」没写「关灯」，或布防/撤防没成对。**对策**：第 18 篇的「可逆性原则」，场景成对设计。<span class="marginnote">「触发源低电量」是幽灵故障之王：<strong>场景偶尔不灵、时好时坏，查到最后往往是一颗纽扣电池</strong>。给传感器低电量告警绑进自动化（如小爱播报「门磁电量低」），能省下 90% 的「灵异事件」排查时间。</span>

## 5 核心对比表：各类触发源特点

纯技能主题，用对比表替代公式解析：

| 触发源 | 可靠性 | 实时性 | 典型场景 | 主要风险 |
| --- | --- | --- | --- | --- |
| 传感器 | 高 | 高 | 亮灯、报警、离家确认 | 误报、低电量 |
| 时间/日出日落 | 极高 | 定时 | 起床、夜间亮灯 | 不知变通 |
| 设备状态 | 高 | 高 | 门锁联动、回充通知 | 状态同步延迟 |
| 语音 | 中 | 中 | 手动触发场景 | 唤醒失败、歧义 |
| 地理围栏 | 低 | 低 | 离家布防 | 定位漂移、省电杀进程 |

## 6 术语速查表

触发条件相关词汇，排障时能准确描述问题：

| 术语 | 含义 |
| --- | --- |
| 触发源 | 启动自动化的信号来源 |
| 防抖 | 设置两次触发的最小间隔，防反复触发 |
| 双触发 | 两个触发源互为校验，重要场景防误判 |
| 存在检测 | 判断「是否有人在」的持续状态 |
| 动作触发 | 瞬时事件，如「有人移动」 |
| 状态触发 | 持续状态，如「有人/无人」 |
| 地理围栏 | 手机进出地理区域触发 |
| 唤醒词 | 触发语音助手的口令 |
| 误唤醒 | 非本人呼叫却响应，常因灵敏度太高 |
| 指令歧义 | 设备命名接近导致语音选错设备 |

## 7 触发配置检查清单

触发是场景的扳机，按清单逐项验证可靠性：

| 检查项 | 标准 |
| --- | --- |
| 触发源在线 | 传感器电量充足、网关在线 |
| 防抖设置 | 关键触发已设冷却时间 |
| 双触发 | 重要场景有双重校验 |
| 设备命名 | 无重名、无易混名 |
| 反向触发 | 每个触发配好对应撤销 |
| 低电量告警 | 触发源低电量接进自动化 |
| 地理围栏 | 只用于容错高的场景 |

## 8 小结

- 五类触发源：**传感器、时间、设备状态、语音、地理围栏**；可靠性从高到低。
- 传感器触发三设置：**灵敏度防抖、双触发校验、动作/状态选型**。
- 语音触发设计：**命名口语化无歧义、绑定场景、治理误唤醒**。
- 四个陷阱：**触发源离线、条件误写进触发、重复触发堆积、反向触发缺失**。
- 低电量告警接进自动化，是消灭「灵异事件」的捷径。
