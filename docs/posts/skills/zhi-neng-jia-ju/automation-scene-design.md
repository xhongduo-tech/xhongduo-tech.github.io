## 为什么「场景」才是智能家居的成品

设备是零件，自动化是齿轮，**场景是最终端上桌的菜**。客户不会因为「装好了 50 台设备」满意，只会因为「下班回家，灯自动亮、窗帘拉开、空调已开」而惊喜。但场景设计也是最容易翻车的地方——规则写复杂了互相打架，写简单了体验无感。这一篇先建立场景设计的方法论，把离家/回家/睡眠/起床四大场景拆成可复制的模板。

## 1 三个易混概念

**场景（Scene）**：一组设备状态的「快照」，一键或自动地同时设置。例如「观影模式」= 客厅灯 20%、窗帘关、投影开。**场景是一次性设置，不监听变化。**

**联动（Linkage）**：设备 A 的状态变化直接触发设备 B 的动作，无中间逻辑。例如门磁开了 → 灯亮。简单直接，但不会「看条件」。

**自动化（Automation）**：完整的 **触发（Trigger）→ 条件（Condition）→ 动作（Action）** 逻辑，可以叠加条件、延时、嵌套。例如「门磁开了 + 时间为晚上 + 家里没人」→ 才触发「全屋关灯」。

**重点：场景是「快照」，自动化是「规则」，联动是最简自动化。** 调场景用「一键执行」；做智能用自动化。客户说的「我想要一回家灯就亮」，本质是一个自动化：触发（门锁开）+ 条件（时间晚）+ 动作（执行回家场景）。<span class="marginnote">一句话区分：<strong>场景回答「此刻要什么状态」，自动化回答「何时自动切换场景」</strong>。先定义好场景，再为场景写自动化，是设计的正确顺序。</span>

## 2 四大核心场景拆解

### 回家场景

**目标**：进门即安顿——灯亮、窗帘开、空调到舒适温度、语音播报欢迎。
**触发**：门锁开锁（指纹/密码/手机蓝牙靠近）+ 门磁开。
**条件**：时间为白天（亮灯 vs 只开窗帘）、家里无人（防止家人反复进出反复触发）。
**动作**：执行「回家场景」快照 + 关闭「离家布防」状态 + 播报「欢迎回家」。
**注意**：给「反复进出」留防抖——锁舌关闭后再触发才有效，避免门半掩时自动反复执行。

### 离家场景

**目标**：出门即安心——全屋灯关、窗帘关、空调/电器断电、安防布防。
**触发**：门锁从内反锁 / 手机离开家（地理围栏）+ 门磁关。
**条件**：确认家里无人（人体传感器无人在屋）。
**动作**：执行「离家场景」+ 摄像头布防 + 扫地机启动 + 智能门锁自动反锁。
**注意**：离家是「布防」逻辑，**必须有「家里无人」确认**——否则家人还在家，误触发布防会触发误报警。<span class="marginnote">离家场景的安全边界：<strong>宁可晚布防，不可误布防</strong>。加一条「全部人体传感器 5 分钟无人在屋」条件，比任何酷炫都重要——误报警的成本远高于晚 5 分钟布防。</span>

### 睡眠场景

**目标**：入睡即静音——卧室灯渐暗关闭、客厅灯全关、窗帘闭合、空调调睡眠温度、安防布防（阳台门磁+人体监测）。
**触发**：语音「睡觉了」/ 卧室灯长按 / 定时（22:30）。
**动作**：执行「睡眠场景」快照 + 开启「夜间安防模式」。
**注意**：睡眠场景要**平滑**——灯光用「渐暗」，不要瞬间全灭；保留「起夜模式」：人体传感器检测到起夜，亮起微光地灯，不惊醒。

### 起床场景

**目标**：唤醒即清醒——卧室灯缓缓亮起（模拟日出）、窗帘渐开、播报天气与日程、厨房热水器预热。
**触发**：定时（工作日 7:00）/ 手环睡眠监测（浅睡阶段叫醒）。
**动作**：执行「起床场景」+ 播放早间新闻 + 窗帘电动打开。
**注意**：起床场景的「仪式感」靠**渐变**——灯光 10 分钟内从 1% 渐亮到 80%，比瞬间全亮体验好得多。

## 3 触发-条件-动作模型（TCA）

所有自动化都长一个骨架：**触发（Trigger）、条件（Condition）、动作（Action）**。设计场景时按这三段填空：

**触发（When）**：什么时候开始评估——传感器变化、时间、设备状态、语音、地理围栏。触发是「启动器」，不是「判断器」。

**条件（If）**：触发后还要满足什么才执行——时间范围、设备状态、是否有人。条件是「过滤器」，防误触发。

**动作（Then）**：满足后做什么——执行场景、发通知、调设备。动作是「执行器」。

设计时的常见错误：把「条件」写成「触发」（该在条件里限定的时间却作为触发写多个定时），或漏掉条件导致「下雨天也执行晒衣模式」。<span class="marginnote">TCA 的调试心法：<strong>场景不执行时，按 TCA 三段逐段查——「触发有没有发生」「条件满足没有」「动作有没有执行」</strong>。米家与 HA 的日志都能看到触发与执行记录，逐段对号入座，比瞎猜快得多。</span>

## 4 场景设计五条原则

**① 一个场景一个目的**。别把「回家场景」写成「回家 + 做饭 + 放音乐」的巨型混合体，拆成独立场景便于复用与调试。

**② 场景优先，单品兜底**。语音与控制尽量指向场景；单品控制作为手动兜底。

**③ 考虑「反复触发」**。用防抖、条件、延时处理反复进出、门半掩等真实场景。

**④ 可逆性**。每个场景要有一个「反场景」——睡眠有起床、离家有回家。不可逆的场景（如误布防）必须有手动解除入口。

**⑤ 渐进体验**。灯光渐变、音量渐起，用「过程」制造体验，不用「瞬间」制造惊吓。<span class="marginnote">「可逆性」是专业与业余的分水岭：<strong>业余只写「开」不写「关」，专业把每个场景配好反向场景</strong>。交付时给客户一张「场景对照表」——离家↔回家、睡眠↔起床、观影↔日间，一目了然。</span>

## 5 核心对比表：四大场景对照

纯技能主题，用对比表替代公式解析：

| 场景 | 核心触发 | 关键条件 | 标志动作 | 常见翻车点 |
| --- | --- | --- | --- | --- |
| 回家 | 门锁开 + 门磁 | 时间/家中无人 | 灯亮、布防解除 | 反复进出重复触发 |
| 离家 | 反锁/地理围栏 | **确认家中无人** | 全关、布防、扫地机 | 误布防、误报警 |
| 睡眠 | 语音/定时 | 已到深夜 | 灯渐暗、夜间布防 | 瞬间全灭吓一跳 |
| 起床 | 定时/手环 | 工作日 | 灯渐亮、窗帘开、播报 | 光线突变、周末误唤醒 |

## 6 术语速查表

场景设计的核心概念，先在团队与客户间统一口径：

| 术语 | 含义 |
| --- | --- |
| 场景 | 一组设备状态的快照，一键或自动同时设置 |
| 联动 | 设备 A 状态变化直接触发设备 B，无中间逻辑 |
| 自动化 | 完整的触发→条件→动作规则 |
| 触发（Trigger） | 自动化何时开始评估的启动信号 |
| 条件（Condition） | 触发后还需满足的过滤器 |
| 动作（Action） | 满足后执行的操作 |
| 防抖 | 防止短时间内重复触发的机制 |
| 反向场景 | 与某场景对应的「撤销」场景，如睡眠↔起床 |
| 布防/撤防 | 安防系统开启/关闭警戒状态 |
| 双触发 | 两个触发源互为校验，防误判 |

## 7 场景调试检查清单

场景交付前逐条验证，重点在「反复触发」与「可逆性」：

| 检查项 | 标准 |
| --- | --- |
| 手动执行 | 每个场景一键执行状态正确 |
| 自动触发 | 触发源→条件→动作链路全通 |
| 防抖测试 | 反复开关门不重复触发 |
| 反向场景 | 每个场景有对应撤销场景 |
| 条件校验 | 时间、有人无人等条件生效 |
| 误触发排查 | 观察一周无「不请自来」的场景 |
| 手动兜底 | 自动化失灵时手动控制可用 |

## 8 小结

- **场景是快照、自动化是规则**：先定义场景，再写自动化。
- 四大场景模板：**回家、离家、睡眠、起床**，各有触发、条件、动作的标配。
- TCA 模型：**触发启动、条件过滤、动作执行**；不执行时按三段逐段查。
- 五条设计原则：**一场景一目的、场景优先、防反复、可逆、渐进体验**。
- 交付配「场景对照表」，反向场景成对给客户。
