## 为什么从视觉指令微调开始

前面所有微调都在「文本的世界」里。多模态微调打开第二个世界——**视觉**。**LLaVA**（Large Language and Vision Assistant，Liu et al., 2023）是视觉指令微调的开山之作：它用「一条投影层」把视觉特征接入语言模型，让 LLM 学会「看图说话」。它的两阶段训练——**视觉-语言对齐预训练**与**视觉指令微调**——成了后续几乎所有 VLM（视觉语言模型）微调的标准模板。

理解 LLaVA，你就理解了「多模态微调」的骨架：**一个视觉编码器 + 一条投影桥 + 一个语言模型**，以及「先用图文对搭桥、再用指令数据教对话」的两阶段配方。它也是多模态对齐（多模态学习专题）与「微调」的交汇点。<span class="marginnote">一句话定位：<strong>LLaVA 的核心贡献不是「新架构」，而是「用最简单的桥（一个 MLP）＋两阶段训练，让 LLM 学会看图」</strong>——它证明了「微调」这个范式可以横跨模态。后续的视觉模型（LLaVA-NeXT、Qwen-VL 等）几乎都是「LLaVA 骨架 + 更精的数据/更大的桥」。</span>

## 1 架构：视觉编码器 + 投影桥 + 语言模型

LLaVA 的架构只有三个组件：

1. **视觉编码器（vision encoder）**：一个预训练的视觉模型（CLIP 的 ViT），把图像变成「视觉特征序列」——一张图被切成若干 patch，每个 patch 变成一个向量；
2. **投影层（projection layer）**：把视觉特征「翻译」成语言模型的输入空间——**一座桥**（LLaVA 最初用线性层，LLaVA-1.5 用 MLP）；
3. **语言模型（LLM）**：一个预训练的 LLM（Vicuna/Llama），接收「视觉 token + 文本 token」的混合序列，生成回答。

图像进入模型的方式：图像 → 视觉编码器 → 视觉特征 → 投影层 → **与文本 embedding 拼接**成一条序列 → LLM 处理。图像在输入里占据若干「视觉 token」的位置——用一个特殊占位 token `<image>` 标记。

**为什么需要「桥」？** 视觉特征与文本特征处于不同的向量空间——视觉编码器输出的「像素语义」与 LLM 理解的「词义」不对齐。投影层的作用就是**把视觉特征「映射」进语言空间**，让 LLM 能「读懂」视觉信息。**桥的质量决定了「视觉信息能不能被语言模型理解」**——这就是两阶段训练第一阶段的全部目的。

## 2 两阶段训练：先搭桥，再教对话

LLaVA 的训练分两阶段，各解决一个问题：

**阶段一：特征对齐预训练（feature alignment）**。目标是**把桥搭起来**：

- 数据：**图像-标题对**（图像 + 一句话描述，如 CC3M）；
- 训练：**冻结视觉编码器与 LLM，只训练投影层**；
- 效果：让投影层学会「把视觉特征映射成 LLM 能理解的输入」——模型开始「能看图」，但还不会「看图对话」。

**阶段二：视觉指令微调（visual instruction tuning）**。目标是**教会对话**：

- 数据：**视觉指令数据**（图像 + 问题 → 答案，如「图中有什么动物？」）；
- 训练：**解冻 LLM（与投影层），一起训练**（视觉编码器通常仍冻结）；
- 效果：让 LLM 学会「基于图像信息回答指令」——模型真正成为「能看图说话的助手」。

**两阶段为什么不能合并？** 因为「先搭桥、再教事」比「同时做」更稳：桥没搭好就教对话，LLM 在「看不懂图」的状态下学对话，既学不好对话、也学不好「用图」。**先让视觉信息「进得来」，再教「怎么用」**——这是多模态微调的节奏。

## 3 公式解析：视觉指令微调的损失

视觉指令微调的目标函数，与文本 SFT **完全同构**——只是输入变成了「视觉 + 文本」混合序列：

$$
\mathcal{L} = -\frac{1}{|\mathcal{R}|}\sum_{t \in \mathcal{R}} \log P_\theta\big(y_t \mid [\,V,\, \langle\text{image}\rangle,\, x\,],\, y_{<t}\big)
$$

逐项拆解：

- $V$：图像经视觉编码器与投影层得到的**视觉 token 序列**；
- $\langle\text{image}\rangle$：图像占位 token（标记「这里有图」）；
- $x$：文本指令（问题）；
- $y_t$：回答 token；$\mathcal{R}$：回答部分（loss mask 只算回答，第二篇）；
- $P_\theta$：给定「视觉 + 文本」上下文，预测回答的下一个 token。

**关键**：**视觉 token 不参与损失预测**（它们是「输入」不是「目标」）；模型只在「回答」上算损失——与普通 SFT 的 loss mask 逻辑完全一致，只是「输入」里多了一段视觉 token。**「图像信息」通过上下文传递，模型学会「看图作答」**。

**训练细节**：阶段二通常解冻 LLM + 投影层、冻结视觉编码器——因为视觉编码器（CLIP）已在海量图文对上预训练好，「再训它」既贵又可能损害视觉特征；「让它冻着、只学桥和语言模型」更稳。

「桥」在代码里就是一个投影模块，两阶段的冻结/解冻区别只在 `requires_grad`：

```python
class ProjectionBridge(nn.Module):
    def __init__(self, vis_dim, llm_dim):
        super().__init__()
        self.mlp = nn.Sequential(
            nn.Linear(vis_dim, llm_dim), nn.GELU(),
            nn.Linear(llm_dim, llm_dim),      # LLaVA-1.5 用两层 MLP
        )
    def forward(self, vis_feats):              # (B, num_patches, vis_dim)
        return self.mlp(vis_feats)             # → (B, num_patches, llm_dim)

# 阶段一：只训桥，冻结视觉编码器与 LLM
for p in vision_encoder.parameters(): p.requires_grad = False
for p in llm.parameters():          p.requires_grad = False
for p in bridge.parameters():       p.requires_grad = True

# 阶段二：解冻 LLM，视觉编码器仍冻结
for p in llm.parameters():          p.requires_grad = True
```

两阶段的差别，就是这几行 `requires_grad` 的开关——**「先让桥能把视觉特征送进语言空间，再让 LLM 学会用它们」**。

## 4 指令数据构造：用 GPT-4 造「看图说话」

视觉指令微调的数据，是「图像 + 问答」对。它的构造是 LLaVA 的另一个核心贡献——**用 GPT-4 从图文对「蒸馏」出指令数据**：

1. **输入**：图像 + 它的标题（caption）+ 检测到的区域（bounding boxes + 区域描述）；
2. **GPT-4 生成**：让 GPT-4「看到」这些文本信息，生成三类指令：
   - **对话类**：「描述这幅图」；
   - **详细描述类**：「详细描述图中每个物体及其关系」；
   - **复杂推理类**：「图中人物可能是什么职业？依据是什么？」；
3. **产出**：（图像，问题，答案）三元组——问题多样、答案由 GPT-4 撰写。

**为什么要用 GPT-4 造数据？** 因为「图像-标题对」只有「一句话描述」，训练不出「对话能力」；而人工标注「看图问答」成本高。**用 GPT-4 基于标题+区域信息「脑补」出问答**，把「描述」扩展成「对话」——数据从「单句」变成「指令」。（这是指令数据合成在视觉域的落地，与第二篇《Self-Instruct》同源。）<span class="marginnote">LLaVA-1.5 的数据配方值得记住：<strong>用公开的图文对（CC 等）做阶段一的「搭桥」，再用「GPT-4V 生成的指令 + 公开视觉问答数据」做阶段二的「教对话」</strong>——它证明了「公开数据 + 合成指令」就够训出一个能看的视觉助手，不必依赖大规模人工标注。</span>

## 5 训练细节与评测

**训练细节**：

- **图像分辨率**：视觉编码器有固定输入尺寸（如 224×224）——高分辨率图像要么缩放、要么切成块（LLaVA-NeXT 用「切片」处理高清图）；
- **冻结策略**：阶段二默认冻结视觉编码器，只训 LLM + 投影——**显存友好、训练稳定**；
- **loss mask**：视觉 token 与用户文本都不算损失，只算回答（与文本 SFT 一致）。

**评测**：视觉语言模型有一套专门基准——**MME**（多模态能力）、**MMBench**、**SEED-Bench**、**LLaVA-Bench**（视觉对话质量）。评测维度包括：感知（看图认物）、认知（基于图的推理）、对话（看图问答的连贯性）。

**「看图」与「用图」的区分**（呼应长上下文的「名义 vs 有效」）：模型「把图读进去了」不等于「真的用了图」——有的模型会「无视图直接答」或「幻觉出图里没有的东西」。评测时要测「**不依赖图就答不对**」的任务，才能看出「视觉能力是否真实」。

## 6 小结

- **LLaVA 架构三件套**：视觉编码器（CLIP ViT）+ 投影桥（线性/MLP）+ 语言模型——**「桥」把像素翻译成词向量**。
- **两阶段训练**：① 特征对齐（冻视觉与 LLM，只训桥，用图文对）→ ② 视觉指令微调（解冻 LLM，用视觉指令数据）——**先搭桥、再教对话**。
- **损失与文本 SFT 同构**：输入是「视觉 + 文本」混合序列，loss mask 只算回答；视觉 token 不参与预测。
- **指令数据构造**：用 GPT-4 基于「标题 + 区域信息」生成「对话/描述/推理」三类指令——数据合成的视觉版。
- **训练细节**：冻结视觉编码器（显存友好）、高分辨率用切片、loss mask 一致。
- **评测**：MME/MMBench/SEED-Bench/LLaVA-Bench；要测「不依赖图就答不对」的任务，验证「真在看图」。
