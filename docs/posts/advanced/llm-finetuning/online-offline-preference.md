## 为什么从在线/离线取舍开始

偏好优化这一篇的最后一节，回到一个贯穿所有方法的问题：**你的训练数据，是「现采的」还是「陈旧的」？**

- **在线方法（PPO、GRPO）**：每一步都用**当前策略**采样、实时打分——数据永远「新鲜」；
- **离线方法（DPO、IPO、ORPO）**：在**固定的偏好数据集**上训练——数据是「过去某个模型」产生的。

离线方法便宜、稳定，却埋着一个隐患——**分布偏移（distribution shift）**：训练用的偏好数据来自旧模型，而你在优化一个新模型；当新模型偏离旧模型越远，旧数据越「配不上」它。本节把分布偏移讲透，并介绍它的主流解药——**迭代 DPO（iterative DPO）**，它把「离线」升级成「半在线」，让 DPO 家族也能吃到「在线」的红利。<span class="marginnote">一句话定位：<strong>在线是「水活」，离线是「水死」</strong>——在线数据永远跟得上模型，离线数据会「过期」。但「活水」贵、「死水」便宜——迭代 DPO 在两者之间架了一座桥：定期换水，但不每步都换。</span>

## 1 离线数据的「保质期」：分布偏移从哪来

离线偏好数据的长相是固定的三元组（$x, y_w, y_l$）——但它有一个隐藏的「出身」：**这组偏好是「某个采样模型」生成的回答、由「某个评判」打的标签**。当训练开始后，正在优化的 $\pi_\theta$ 与「生成这些数据的模型」不是同一个——这个「出身错位」就是分布偏移的根源。

分布偏移的两个具体表现：

**① 数据覆盖失配**。旧模型生成的回答分布，与新模型的回答分布不同。新模型可能生成「旧数据里从未出现的回答类型」——对这些「新风格回答」，模型没有偏好信号可学，训练等于「盲区」。

**② 标签过时**。偏好标签（$y_w \succ y_l$）是「当时」的判断——当模型变强后，「当时觉得好的 $y_w$」可能已经不怎么样了。用「过时的偏好」训练「更聪明的模型」，等于让「青出于蓝」的学生去背「蓝」的旧作业。

**后果**：离线 DPO 训练越久，模型偏离数据生成者越远，分布偏移越严重——这正是「DPO 训久了会退化」的一个机制解释。

## 2 在线数据的优势：为什么「现采」更可靠

在线方法（PPO/GRPO）没有分布偏移问题，因为它们**每一步都用当前策略采样**：

$$
\text{在线：} \quad y \sim \pi_{\theta_t}(\cdot \mid x), \qquad r = \text{验证器/奖励}(x, y)
$$

数据永远来自「当前的 $\pi_{\theta_t}$」——**数据分布与模型分布严格同步**。在线方法的好处：

- **无过时标签**：每步的偏好都是「当前模型 + 当前判断」的产物；
- **持续探索**：模型能采到「以前没见过的回答」，探索新方向（这正是 RLVR 里 R1 涌现推理行为的基础）；
- **上限更高**：数据天花板随模型同步抬升（呼应 ReST 的「采样天花板」机制）。

代价就是上一篇反复提到的：**在线采样 + 策略梯度，工程重、显存贵、调参难**。离线方法的「便宜」vs 在线方法的「新鲜」，是偏好优化最基本的取舍。

## 3 迭代 DPO：把「死水」定期换成「活水」

**迭代 DPO（iterative DPO）** 在「便宜」与「新鲜」之间取中间态：**不每步采样，但定期用当前模型重新生成偏好数据**。循环：

1. 用**当前模型** $\pi_{\theta_t}$ 对提示池采样，生成回答对；
2. 用**评判器**（奖励模型 / LLM 判官 / 规则验证器）标注偏好（$y_w \succ y_l$）；
3. 在这些「新鲜」数据上跑一轮 DPO，得到 $\pi_{\theta_{t+1}}$；
4. 回到第 1 步，用 $\pi_{\theta_{t+1}}$ 重新采样。

$$
\pi_{\theta_{t+1}} = \mathrm{DPO}\Big( \pi_{\theta_t},\; \mathcal{D}_{\text{采样自 }\pi_{\theta_t}} \Big)
$$

逐项拆解：

- 每轮的数据都来自**上一轮的模型**——数据「新鲜度」与模型同步；
- 训练仍是「便宜的 DPO」（无策略梯度、无价值网络）；
- 循环次数（迭代轮数）是核心超参——**每轮都是「用新模型采新数据、再 DPO」**。

**迭代 DPO 的意义**：它让 DPO 家族拿到了「在线」的大部分好处（数据不陈旧、能持续探索），却仍保持「离线」的工程简单。**研究（如《Is DPO Superior to PPO?》）表明，DPO 与 PPO 的主要差距正是「在线数据可得性」——迭代 DPO 把两者的差距大幅缩小**。这解释了「为什么迭代 DPO 现在这么流行」。<span class="marginnote">迭代 DPO 与 ReST 的关系：两者是「近亲」——ReST 迭代的是「SFT + 筛选」，迭代 DPO 迭代的是「DPO + 偏好标注」。核心循环同构：<strong>用当前模型产数据 → 外部信号筛/标 → 训练 → 再采样</strong>。理解了 ReST，迭代 DPO 只是把「训练损失」从 SFT 换成 DPO。</span>

## 4 公式解析：分布偏移的量化与缓解

分布偏移不是「有/无」的二元问题，而是「偏离多少」的连续量。一个可操作的度量是**KL 散度**——当前模型与「数据生成模型」的偏离程度：

$$
\mathrm{KL}\big(\pi_{\theta_t} \,\|\, \pi_{\text{data}}\big) = \mathbb{E}_{y \sim \pi_{\theta_t}}\Big[ \log \frac{\pi_{\theta_t}(y \mid x)}{\pi_{\text{data}}(y \mid x)} \Big]
$$

其中 $\pi_{\text{data}}$ 是「生成偏好数据的模型」（离线时是旧模型，迭代 DPO 时是上一轮模型）。逐项拆解：

- $\pi_{\theta_t}$：当前正在优化的模型；
- $\pi_{\text{data}}$：数据的「出身模型」；
- 比值：当前模型相对数据出身的偏离——**偏离越大，数据越「过时」**。

**缓解分布偏移的三个手段**（按性价比排序）：

1. **迭代 DPO**（最有效）：定期用当前模型换新数据——把 $\pi_{\text{data}}$ 与 $\pi_{\theta_t}$ 的「时差」控制在「一轮」以内；
2. **DPO 加 KL 约束**：在 DPO 损失里加一个「不偏离数据生成模型」的项——**治标**（限制偏离，但不能消除过时）；
3. **混合新旧数据**：每轮把「旧数据」按比例保留——**折中**（保多样性，但旧数据仍占训练预算）。<span class="marginnote">一个直觉阈值：<strong>当 $\mathrm{KL}(\pi_{\theta_t}\|\pi_{\text{data}})$ 开始「陡增」时，就该换一轮数据了</strong>——这相当于把分布偏移当「仪表盘」，用它决定迭代 DPO 的换水频率。实践中可以用「当前模型在旧偏好验证集上的准确率」当代理：准确率开始下降，说明数据「过时」了。</span>

## 5 DPO 与 PPO 之争的真相

「DPO 好还是 PPO 好」是偏好优化最常见的争论，而在线/离线的视角给出了一个更清醒的答案：

| 维度 | 离线 DPO | 迭代 DPO | PPO/GRPO |
| --- | --- | --- | --- |
| 数据新鲜度 | 固定（易过时） | 每轮更新 | 每步更新 |
| 工程成本 | 低 | 中 | 高 |
| 分布偏移 | 明显 | 轻微 | 无 |
| 训练稳定性 | 高 | 高 | 中 |
| 探索能力 | 无 | 有（每轮） | 强（每步） |

**结论**：DPO 与 PPO 的差距，**主要不在「算法」，而在「数据新鲜度」**。把 DPO 从「离线」升级成「迭代」，就拿到了 PPO 大部分收益，却避开了 PPO 的工程复杂度——这是当前偏好优化领域的「共识性实践」：**能用迭代 DPO 解决的，不必上 PPO**。

## 6 选型与实战

把整篇的取舍收成实战建议：

1. **第一版对齐，用离线 DPO**：快、稳、便宜，先拿到「不错的对齐基线」；
2. **想继续提升，切迭代 DPO**：每轮用当前模型重采偏好、重跑 DPO——数据新鲜度是「下一档提升」的主要来源；
3. **推理任务（数学/代码），直接上 GRPO + RLVR**：可验证奖励 + 在线采样，是这类任务的当前最优；
4. **预算充足、要极限效果，再考虑 PPO**：它仍是「在线探索」最强的选项，但只有在「迭代 DPO 不够」时才值得那笔工程成本。

一条贯穿始终的原则：**数据的新鲜度，比算法的精巧度更影响最终效果**——这也是为什么「迭代」这个词，在这一篇里反复出现。

## 7 小结

- **在线 vs 离线**：在线数据永远新鲜（贵），离线数据会过时（便宜）——分布偏移是离线的核心隐患。
- **分布偏移两表现**：数据覆盖失配（新风格没信号）与标签过时（旧判断配不上新模型）。
- **迭代 DPO**：定期用当前模型重采偏好、重跑 DPO——把「死水」定期换成「活水」，拿到在线大部分好处、保持离线简单。
- **偏移可量化**：$\mathrm{KL}(\pi_{\theta_t}\|\pi_{\text{data}})$——用它当仪表盘，决定「换水频率」。
- **DPO vs PPO 的真相**：差距主要在数据新鲜度而非算法——迭代 DPO 大幅缩小差距。
- 实战顺序：**离线 DPO 打底 → 迭代 DPO 提升 → 推理任务上 GRPO+RLVR → 预算充足再上 PPO**。

至此，偏好优化这一篇全部收官：从 RLHF 三阶段到 PPO，从拒绝采样、ReST 到 DPO 家族，再到 GRPO、RLVR、PRM 与在线/离线取舍。在下一篇，我们进入应用落地：**领域与多模态微调**。
