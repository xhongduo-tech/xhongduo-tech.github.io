## 为什么从 DPO 实践开始

上一节证明了 DPO 的数学成立——但「公式对」不等于「训得好」。DPO 在工程上有一堆「看起来微妙、实际致命」的细节：参考模型选谁、β 取多大、为什么训练到一半模型开始「胡言乱语」、为什么回答越来越长……

本节把 DPO 的工程面讲透：**参考模型**与 **β** 这两个「唯一的模型级超参」，加上一份**常见陷阱清单**。读完你不仅能「训起来」，还能「训稳」——知道 loss 在降但模型在变差时，该去查哪个旋钮。<span class="marginnote">DPO 相对 PPO 的「简单」是双刃剑：<strong>没有 RL 阶段的在线反馈，一切「纠偏」都要在设计时做对</strong>。参考模型、β、数据质量这三个旋钮，就是 DPO 的全部「纠偏机制」——它们调错了，DPO 会安静地训出一个「分数高但质量怪」的模型，没有 loss 报警。</span>

## 1 参考模型：DPO 的「隐形锚」

DPO 损失里有 $\pi_{\mathrm{ref}}$——它看似只是分母，实际决定了整个训练的方向：

$$
\mathcal{L}_{\mathrm{DPO}} = -\log\sigma\Big( \beta \log \frac{\pi_\theta(y_w)}{\pi_{\mathrm{ref}}(y_w)} - \beta \log \frac{\pi_\theta(y_l)}{\pi_{\mathrm{ref}}(y_l)} \Big)
$$

参考模型在 DPO 里扮演两个角色：

- **隐式奖励的零点**：$\pi_\theta/\pi_{\mathrm{ref}} = 1$ 意味着「模型与参考一致，隐式奖励为 0」。参考模型定义了「什么叫中性」；
- **KL 约束的锚**：DPO 虽然**没有显式 KL 项**，但「相对参考模型的概率比」在数学上等价于「以参考为锚点的 KL 约束」——参考模型就是那个「不许走太远」的锚。

**参考模型选谁？** 标准做法是**用 SFT 模型**（即 DPO 训练起点之前的模型）。这样训练起点恰好是「锚点」，模型从「参考位置」出发、逐步学习偏好。**若参考模型与起点不匹配**（如用另一个预训练模型当参考），隐式奖励的零点与模型实际分布错位，训练会不稳定甚至发散。<span class="marginnote">一个隐蔽的坑：<strong>训练过程中参考模型必须保持冻结</strong>——若不小心把参考模型也更新了，锚点就「漂移」了，KL 约束失去意义，训练会静默退化。实现上务必确认参考模型 `requires_grad_(False)`。</span>

## 2 β：偏好强度的旋钮

**β（beta）** 是 DPO 的「温度系数」，控制「偏好信号」的强度。它的作用可以从两个角度理解：

- **从推导看**：β 是 KL 约束的系数（推导链第一步里的 $\beta$）——**β 大，模型被约束得更贴近参考模型**（保守）；**β 小，模型更放飞自我去贴合偏好数据**（激进）；
- **从损失看**：β 放大了「隐式奖励」的尺度——β 大，sigmoid 输入饱和更快，梯度更容易归零；β 小，梯度更平缓。

经验值：**主流实现（如 TRL）默认 β = 0.1**，多数任务在 0.01–1.0 之间调。几个判断信号：

| 症状 | β 的问题 | 处理 |
| --- | --- | --- |
| 训练不动、偏好没学进去 | β 太大（信号被压缩） | 调小 β |
| 训练发散、模型乱说话 | β 太小（约束失效） | 调大 β |
| 学进去了但很快过拟合 | β 太小 | 调大 β + 早停 |

**β 与数据规模的互动**：偏好数据越多、越干净，可以用更小的 β（更激进地学）；数据少或噪声大，β 要偏大（更保守）。**β 是 DPO 里「性价比最高」的超参**——它一个旋钮同时控制「学习强度」与「稳定性」。

## 3 公式解析：DPO 梯度与「过拟合的根源」

DPO 为什么会过拟合？看它的梯度就能明白。对 $\pi_\theta$ 的参数 $\theta$ 求导，DPO 损失的梯度为：

$$
\nabla_\theta \mathcal{L}_{\mathrm{DPO}} = -\beta\, \mathbb{E}\Big[\, \underbrace{\sigma\big(\hat{r}_l - \hat{r}_w\big)}_{\text{权重}} \cdot \Big( \nabla_\theta \log \pi_\theta(y_w) - \nabla_\theta \log \pi_\theta(y_l) \Big) \Big]
$$

其中 $\hat{r}_w = \beta\log\frac{\pi_\theta(y_w)}{\pi_{\mathrm{ref}}(y_w)}$、$\hat{r}_l = \beta\log\frac{\pi_\theta(y_l)}{\pi_{\mathrm{ref}}(y_l)}$ 是胜败双方的隐式奖励。逐项拆解：

- $\sigma(\hat{r}_l - \hat{r}_w)$：**权重项**——当「败者隐式奖励 > 胜者」时（模型还没学好），权重接近 1，梯度大；当「胜者已明显高于败者」时，权重趋近 0，梯度衰减；
- 括号里：**提高胜者概率、降低败者概率**的方向；
- **过拟合的根源**：这个梯度**永不停歇地提高胜者概率**（除非权重恰好为 0）。若训练不早停，模型会不断把胜者的概率推向极端——出现「对训练集里的胜者过分自信、对未见过的输入却退化」的现象。**β 小会让权重衰减得更慢，加剧过拟合**。

**防过拟合的手段**（实践里按顺序用）：**早停**（看验证集）、**调大 β**、**在 DPO 损失上叠加一个 SFT 项**（防止模型在胜者概率上失控）：

$$
\mathcal{L} = \mathcal{L}_{\mathrm{DPO}} + \lambda\, \mathcal{L}_{\mathrm{SFT}}(\pi_\theta, y_w)
$$

叠加 SFT 项的效果是「**既学偏好、又不偏离正常生成**」——它像一个「软锚」，把模型拉在「能正常说话」的范围里。<span class="marginnote">这个「DPO + SFT」混合损失是社区里最实用的防退化配方之一：<strong>纯 DPO 容易让模型「过分自信地输出」，混合 SFT 项则保证「就算偏好没学会，至少还能正常说话」</strong>。λ 取 0.5–1.0 量级即可，是「保底」而非「主导」。</span>

DPO 损失的核心实现只有几行：

```python
import torch
import torch.nn.functional as F

def dpo_loss(logps_w, logps_l, logps_ref_w, logps_ref_l, beta=0.1):
    """logps_*：模型/参考模型在胜者(y_w)、败者(y_l)上的对数概率"""
    r_w = beta * (logps_w - logps_ref_w)      # 胜者的隐式奖励
    r_l = beta * (logps_l - logps_ref_l)      # 败者的隐式奖励
    loss = -F.logsigmoid(r_w - r_l).mean()    # DPO 损失
    return loss, (r_w - r_l).mean()           # 顺带返回「隐式奖励差」用于监控
```

注意 `r_w - r_l` 就是「胜者 vs 败者的隐式奖励差」——训练时把这个差值打印出来，它就是「偏好学进去没有」的最直接信号（应随训练上升）。

## 4 常见训练陷阱：DPO 的「安静翻车」

DPO 的坑大多「不报错、loss 正常降、模型悄悄变差」。几个高频陷阱：

**陷阱一：回答变「话痨」**。DPO 常让模型输出更长——因为偏好数据里「更详细」的回答常被标为更好，模型学会「越长越保险」。缓解：长度归一化的 DPO 变体、或在偏好数据里平衡长短回答。

**陷阱二：参考模型漂移**。训练中参考模型被意外更新（`requires_grad=False` 没设对）——锚点漂移，训练静默失效。

**陷阱三：偏好数据有「平局」**。DPO 无法处理「平局」标签（它假设严格排序）；数据里的平局样本会让损失震荡。处理：清洗时把平局剔除，或改用能处理平局的方法（KTO，见后文）。

**陷阱四：β 与数据量不匹配**。数据量大而 β 太小 → 过拟合；数据量小而 β 太大 → 学不进去。**β 应该随数据量反方向调**。

**陷阱五：DPO 起点不当**。若从「未经过 SFT 的基座模型」直接做 DPO，隐式奖励的零点错位——**DPO 的起点必须是 SFT 模型**（除非用特殊初始化技巧）。

## 5 实践配方：一个能用的 DPO 流水线

把上面的细节收成一份可执行的配方：

1. **数据**：清洗偏好对，剔除平局与矛盾对；平衡长短回答；
2. **起点**：用 SFT 模型作初始化，同时作参考模型（冻结）；
3. **超参**：β 从 0.1 起步；学习率比 SFT 更小（如 $5\times10^{-6}$）；用 LoRA 训练策略（显存友好）；
4. **损失**：默认纯 DPO；若观察到「模型变怪」，加 SFT 混合项（λ≈0.5）；
5. **监控**：不只盯 loss——盯「胜者 vs 败者的隐式奖励差」（应该上升）、「回答长度」（不该暴涨）、以及留出的验证集偏好准确率；
6. **早停**：在验证集上早停，别让胜者概率推到极端。

这份配方的核心哲学：**DPO 的每个旋钮都在「学偏好」与「保稳定」之间找平衡**——β、SFT 混合项、早停，都是同一枚硬币的两面。

## 6 小结

- **参考模型是隐形锚**：定义「中性」与「KL 锚点」——用 SFT 模型作参考且全程冻结。
- **β 是偏好强度旋钮**：默认 0.1，数据少调大、数据多调小；同时控制「学习强度」与「稳定性」。
- **过拟合根源在梯度**：$\sigma(\hat{r}_l - \hat{r}_w)$ 权重衰减慢时，胜者概率被推向极端——靠早停、调 β、加 SFT 混合项缓解。
- **五大陷阱**：话痨化、参考漂移、平局数据、β 与数据量不匹配、起点不当——全部「安静翻车」。
- **实践配方**：SFT 起点 + 冻结参考 + β=0.1 起步 + 小学习率 + 混合损失 + 早停 + 盯「隐式奖励差 / 长度 / 验证准确率」。
