## 为什么从长数据构造开始

位置扩展让模型「接受」长输入，序列并行让它「装得下」长序列——但还差最后一环：**模型真的学会「利用」长距离信息了吗？** 这一环的答案不在算法里，而在**数据**里。

长序列数据的构造有一个核心陷阱，一句话概括：**「长而浅」不是长上下文数据**。一段 100k 的文本，如果只用读开头 1k 就能答出所有问题，那它训练不出「长距离利用」能力——模型只需学会「开头最重要」就行，这恰恰助长了「lost in the middle」（信息丢失在中段）的病。本节讲清三种真正有效的长数据构造策略：**长文档续写、长对话、合成长依赖任务**。<span class="marginnote">一句话判断数据好坏：<strong>这段数据里，有没有「答案在 50k 之外、必须跨过 49k 才能找到」的时刻？</strong> 有，才是长上下文训练；没有，只是「长的短数据」。</span>

## 1 「长而浅」的陷阱：长度不是目的

先破除一个直觉误区：**把短数据 pad 到长序列，不是长数据**。长上下文能力的关键不是「序列长」，而是「**依赖距离远**」——即「回答某个问题需要的信息，离问题本身很远」。

把「序列长度」与「依赖距离」拆开看：

**长度**：输入有多少 token——位置扩展能解决「装不装得下」；
**依赖距离**：答案与线索之间的 token 间隔——只有「线索真的在远处」的数据才能训练出「远距离检索」。

一段 100k 的合同，若所有问答都只涉及相邻几段，依赖距离近——模型不需要「远距离注意力」就能答对。**这类数据喂再多，也练不出长上下文能力，反而教会模型「忽略远处」**。这就是为什么长数据构造的第一原则是：**让依赖距离与序列长度同步增长**。

## 2 策略一：长文档续写——拿现成的长文本练「长程连贯」

**长文档续写**是最自然的长数据来源：直接拿书籍、论文、长报告这些「天然长文本」，让模型做**下一个 token 预测**（继续预训练）或在长文档上做指令微调。

为什么长文档有效？因为**连贯的长文本自带长距离依赖**：一本书的前文设定，在后文被反复引用；一篇论文的引言结论，与正文呼应。模型要预测后面的 token，就必须「记得前面说过什么」——依赖距离天然很远。

工程要点：

**用位置扩展后的模型**做继续预训练（第一篇《继续预训练》的长序列版），在长文档上跑几百到几千步；
**文档要「真长」**：把同一本书的连续章节拼起来，让上下文真的跨过很远——不是把短篇拼一起（那会引入「拼接断裂」，下一节的对话构造更合适）；
**长度混合**：全喂 100k 会过度训练长文本、伤短文本能力——按「短为主、长渐进」的配比混合（呼应第二篇《数据多样性与配比》）。<span class="marginnote">长文档续写的最大障碍是「文档边界」：书籍、论文的电子版常有页眉、目录、公式错乱等噪声。工业界的经验是<strong>先把文档清洗干净、识别章节结构</strong>，再按「章节连续的整块」切成长上下文，而不是盲目按固定长度硬切——硬切会把一句话从中间斩断，生成「假长文」。</span>

## 3 策略二：长对话构造——把多轮对话拉长

第二种策略瞄准「长对话」这个真实场景：**多轮对话天然是长上下文**——用户在第 1 轮给的偏好，可能在第 20 轮还要遵守。

长对话数据从哪来？三条路：

**真实长对话**：从客服、论坛、开源对话数据里筛「轮数多」的对话（如 >10 轮），直接使用；
**拼接扩展**：把**主题相关**的短对话按顺序拼接成一条长对话——注意要「相关」，否则拼接断裂会让模型学「突然换话题」的坏模式；
**合成对话**：让强模型扮演「多轮追问」的用户，围绕一个长文档连续问 10–20 轮——每轮都引用前文信息（呼应第二篇《多轮对话数据》的「跨轮线索」）。

长对话构造的关键不是「轮数多」，而是「**跨轮依赖**」：前文提到的信息，必须在后续轮次被用到。只拼一堆「你好/再见」的短轮，长度上去了、依赖距离没上去——又是「长而浅」。

## 4 策略三：合成长依赖任务——刻意制造「远处的答案」

前两种策略都依赖「自然文本里恰好有长距离依赖」，但自然文本的长依赖**密度低**——一本书里真正需要跨 50k 才能答的问题没几个。**合成长依赖任务**则反过来：**刻意制造「答案必须从远处找」的问题**，把长距离依赖「量产」。

最典型的合成任务是**大海捞针（Needle in a Haystack，NIAH）**家族：

1. 往一段长文本的**特定位置**（如第 60k token 处）插入一句「事实」——例如「旧金山的隐藏宝藏码是 7432」；
2. 让模型回答「宝藏码是多少」；
3. 若模型答对，说明它能跨过 60k 的距离检索到这条信息。

合成任务的价值在于**可控性**：可以精确控制「依赖距离」（插到 10k、50k、100k）、「线索数量」（几条针）、「干扰程度」（有没有误导性文本）——从而系统性地训练与测量长上下文能力。

工程上，合成任务不只是「造 NIAH 数据」，而是**造出一族「必须有远距离检索才能完成」的任务**：

**键值检索**：在长文中多处插入「键-值」对，问「某键的值是什么」；
**长程指代**：前文定义了一个概念，后文多次引用，问「这个概念的定义」；
**跨段推理**：两个事实分处序列两端，要求把它们联合起来推理。<span class="marginnote">合成任务的质量控制有个反直觉点：<strong>太容易的合成任务（针插得显眼、干扰少）会让模型「学会找针」而非「学会读长文」</strong>。好的合成任务要有「干扰项」——插入若干条相似的假信息，逼模型真正定位而非靠位置猜测。这也是 NIAH 从「单针」演化出「多针」「干扰针」变体的原因。</span>

合成一条 NIAH 样本的代码骨架（理解思想即可）：

```python
import random

def make_niah(text, fact, pos_ratio=0.6, num_distractors=2):
    """合成一条大海捞针样本。
    pos_ratio:       针插入的位置（0~1）→ 决定依赖距离
    num_distractors: 干扰针的数量      → 决定定位难度
    fact:            事实（风格）      → 决定任务类型
    """
    pos = int(len(text) * pos_ratio)                       # 1. 选定插入位置
    context = text[:pos] + " " + fact + " " + text[pos:]   # 2. 把「针」插进去

    for _ in range(num_distractors):                       # 3. 插入干扰针，逼模型真正定位
        i = random.randint(0, len(context))
        context = context[:i] + " " + fake_fact(fact) + " " + context[i:]

    question = f"根据上文，{fact.split('是')[0]}是什么？"
    return {"context": context, "question": question, "answer": fact.split("是")[-1]}
```

三个变量是合成的「自由旋钮」：**插入位置**（决定依赖距离）、**干扰数**（决定定位难度）、**事实风格**（决定任务类型）。批量生成时轮换这三者，就能覆盖「各种距离 × 各种难度」的长依赖训练空间。

### 别漏了「中间位置」：对抗 lost in the middle

长上下文评估里有个著名的现象——**lost in the middle**：模型对「上下文开头与结尾」的信息利用得好，对「中间位置」的信息利用差。这在长数据构造里直接对应一个要求：**不能只把答案插在开头或结尾**。

训练数据的合成任务若总是「针在 60% 处」，模型会学会「关注 60% 附近」而非「全上下文检索」。正确的做法是**让插入位置均匀覆盖 0%–100%**——尤其多安排「中间位置」的样本，刻意逼模型检索中段信息，把 lost in the middle 的弱点在训练期就补上。## 5 公式解析：长度分布与依赖密度

把三种策略的数据混在一起时，两个指标决定数据配比的质量。定义「依赖密度」为「长距离依赖出现的频率」：

$$
\rho = \frac{\text{包含长距离依赖的样本数}}{\text{总样本数}}, \qquad
d = \text{平均依赖距离} \approx \frac{\sum \text{每条样本的线索-答案间隔}}{\text{样本数}}
$$

逐项拆解：

- $\rho$：**依赖密度**——越高，训练数据越「逼」模型用长距离信息。长文档续写 $\rho$ 低（天然文本依赖稀疏），合成任务 $\rho$ 高（刻意安排）；
- $d$：**平均依赖距离**——越大，模型的远距离检索压力越大；
- 配比原则：**让 $\rho$ 与 $d$ 随训练进度「渐进增大」**——先训「密度低、距离近」的（巩固短程），再逐渐引入「密度高、距离远」的（突破长程）。这对应第二篇的「采样课程」思想在长数据上的应用。

**为什么不能全是合成任务？** 合成任务依赖距离可控但**多样性有限**——模型的远距离检索能力练出来了，但「真实长文档里那些不规则的远距离依赖」没见全。所以实践配方通常是：**长文档续写打底（多样性）+ 长对话补充（交互形态）+ 合成任务拔高（刻意训练长依赖）**——三者按 6:2:2 之类的比例混合，让长上下文能力「既有广度又有强度」。

## 6 小结

- **「长而浅」是陷阱**：序列长 ≠ 依赖距离远；没有远距离依赖的数据练不出长上下文能力。
- **长文档续写**：拿自然长文本做继续预训练——依赖距离天然远，但要清洗文档边界、按章节整块切。
- **长对话构造**：多轮对话是天然长上下文——关键是「跨轮依赖」，不是「轮数多」。
- **合成长依赖任务**：NIAH 等「刻意让答案在远处」的任务，可控地量产远距离检索压力。
- 两个指标：**依赖密度 $\rho$** 与**平均依赖距离 $d$**——配比遵循「渐进增大」的课程原则。
- 实践配方：**长文档打底 + 长对话补充 + 合成任务拔高**，三者混合（如 6:2:2）。
