## 为什么从 PPO 开始

RLHF 三阶段里，第三阶段的「强化学习」在 LLM 上的事实标准是 **PPO（Proximal Policy Optimization，近端策略优化）**。它是 OpenAI 在 InstructGPT 里用的算法，也是「RLHF 很复杂」这个印象的主要来源——因为 PPO 在 LLM 上要同时维护**四个模型**、处理「生成采样」与「奖励打分」的不可微链路、还要用 KL 惩罚防跑偏。

但 PPO 的「复杂」是**工程复杂**，不是**概念复杂**。它的核心只有两件事：**算优势（这个回答比预期好多少）**与**裁剪更新（别一次走太远）**。本节把 PPO 的架构、公式与调参技巧讲透——读完后，你就能理解为什么 PPO 需要四模型、为什么 KL 惩罚不可或缺、以及那些「loss 突然起飞」的 PPO 惊魂夜到底发生了什么。它是 RLHF 路线里最「正统」也最「重」的一环。<span class="marginnote">先给一个心理预期：<strong>PPO 是 RLHF 里「效果上限最高、但最不友好」的选项</strong>。它的价值在于「在线」——每一步都用当前策略采样、实时打分，能持续挖掘新信息；代价是工程重、调参玄。理解它，不是为了「非它不可」，而是为了知道「什么时候该用、什么时候该换 DPO」。</span>

## 1 PPO 在 LLM 上的角色：策略更新的引擎

PPO 是「策略梯度」家族的一员。它回答的核心问题是：**给定奖励信号，如何更新策略（模型参数）让「期望奖励」变大？**

在 RLHF 里，这个「策略」就是正在对齐的模型 $\pi_\theta$。PPO 的训练循环可以压缩成五步：

1. **采样**：从提示池抽一批提示，让当前策略 $\pi_\theta$ 生成回答；
2. **打分**：奖励模型给每个回答打奖励 $r$，同时参考模型计算 KL 惩罚；
3. **算优势**：把「奖励 + KL」与价值网络的预期比较，得到**优势（advantage）**——「这个回答比预期好多少」；
4. **更新策略**：用 PPO 的裁剪目标更新 $\pi_\theta$，让「优势为正」的回答更可能被生成；
5. **更新价值网络**：让价值网络更好地拟合「实际回报」，为下一轮的优势计算服务。

五步循环往复，策略逐步学会「生成高分回答」。注意第 1 步的「采样」用的是**当前策略**——这是 PPO 与「离线方法」（DPO）最本质的区别：**数据是策略自己现采的，而不是固定的**。

关于「优势」还有一个值得记的细节：LLM 生成是**单步决策**（不是多步序列决策），所以优势计算通常退化为简单的「奖励 - 价值」，无需复杂的时序归约（GAE 的 $\lambda$ 参数在 LLM 场景里几乎不起作用）。这个简化让 PPO 在 LLM 上的实现比「标准 PPO」轻了不少——**每个 token 的优势 ≈ 修正后的奖励 - 价值网络的预测**。若你在代码里看到 `advantage = reward - value`，这就是它。## 2 四模型架构：RLHF 的「重资产」

PPO 在 LLM 上要同时加载**四个模型**，这是它显存压力的直接来源：

| 模型 | 角色 | 是否更新 | 用途 |
| --- | --- | --- | --- |
| 策略 $\pi_\theta$ | 正在训练的对齐模型 | ✅ 更新 | 生成回答 |
| 参考模型 $\pi_{\mathrm{ref}}$ | SFT 模型（冻结） | ❌ | 算 KL 惩罚 |
| 奖励模型 $r_\phi$ | 打分器 | ❌ | 给回答打分 |
| 价值网络 $V_\psi$ | 预测「期望回报」 | ✅ 更新 | 算优势 |

**为什么需要价值网络？** 因为「优势」需要一个「基线」——「这个回答值多少」需要跟「预期值多少」比，才能知道「好于预期」还是「差于预期」。价值网络就是那个「预期」的估计器。**为什么参考模型要冻结？** 因为 KL 惩罚需要一个「固定的锚点」——若参考模型也在变，KL 就失去意义（等于「自己在跟自己比」）。

**显存账本**：四个模型 ≈ 4 份权重。7B 全参 PPO 需要约 4×14 GB = 56 GB 起步（不含激活与优化器）——这就是为什么 PPO 通常**用 LoRA 训策略**（策略的权重被低秩参数替代，但参考/奖励/价值仍是全量）。<span class="marginnote">「四模型」也是 PPO 与 DPO 最直观的成本差异：<strong>DPO 只要两个模型（策略 + 参考），省掉 RM 与价值网络</strong>。这是 DPO 流行的重要工程理由——但 DPO 省掉的是「在线采样」，后面 DPO 两篇会展开这个取舍。</span>

## 3 公式解析：PPO 的裁剪目标

PPO 的更新目标，是它名字里「Proximal（近端）」的由来——**每一步都别走太远**：

$$
L^{\mathrm{clip}}(\theta) = \mathbb{E}\Big[\, \min\big(\rho_t A_t,\; \mathrm{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\, A_t\big) \Big]
$$

逐项拆解：

- $\rho_t = \frac{\pi_\theta(y_t \mid \cdots)}{\pi_{\theta_{\text{old}}}(y_t \mid \cdots)}$：**概率比**——新策略产出该 token 的概率是旧策略的几倍；
- $A_t$：**优势**——该位置「比预期好多少」。$A_t > 0$ 鼓励「提高这个 token 的概率」，$A_t < 0$ 则相反；
- $\mathrm{clip}(\rho_t, 1-\epsilon, 1+\epsilon)$：把概率比限制在 $[1-\epsilon, 1+\epsilon]$（$\epsilon$ 通常 0.2）；
- **min**：取「未裁剪」与「裁剪后」的较小者——**当且仅当「提高概率会推高目标」时，裁剪才生效**。

**直觉**：$\rho_t$ 是「这一步走多远」的度量。PPO 的裁剪规则是：**若策略想大幅提高某个 token 的概率（$\rho_t > 1+\epsilon$），就把增益截住**——因为「一次走太远」可能是个坏主意（旧策略未必可靠）。这正是「Proximal」的含义：**每一步都被限制在旧策略的邻域内**。

## 4 KL 惩罚的两种实现

KL 惩罚是 RLHF 的「护栏」，在 PPO 里有两种落地方式：

**方式一：奖励修正（reward shaping）**。把 KL 直接加进奖励：

$$
\tilde{r}_t = r - \beta\, \mathrm{KL}\big(\pi_\theta(\cdot\mid\cdot) \,\|\, \pi_{\mathrm{ref}}(\cdot\mid\cdot)\big)
$$

每生成一个 token，用「修正后的奖励」替代原始奖励——模型既想「高分」又怕「偏离参考」。实现简单，是 TRL 等库的默认。

**方式二：独立 KL 损失（separate KL loss）**。把 KL 作为独立的正则项加进 PPO 目标：

$$
L = L^{\mathrm{clip}} - \beta\, \mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}})
$$

两路各有取舍：**方式一**直接、好调（$\beta$ 直接控制「奖励 vs KL」的平衡）；**方式二**更「平滑」（KL 不作为奖励的一部分参与优势计算，不影响尺度）。实践上**方式一更常用**，且 $\beta$ 的经验值在 0.01–0.1 之间。<span class="marginnote">KL 惩罚有个常被误解的点：<strong>它防的不是「模型变差」，而是「模型失控」</strong>。没有 KL，策略可以无限提高奖励——但奖励模型是「代理」，它的空子越钻越多，最终「分数很高、质量很怪」。KL 把策略「拴」在 SFT 附近，让「钻空子」变得昂贵——这正是 reward hacking 的防线。</span>

## 5 工程调参技巧：PPO 的「驾驶手册」

PPO 是出了名的难调，几个最有用的经验：

**① 学习率要小**。策略更新目标 + 裁剪已经够激进，学习率再大极易发散——经验值 $\sim 10^{-6}$ 到 $10^{-5}$ 量级（比 SFT 小一个数量级）。

**② 价值网络与策略同步初始化**。价值网络常从策略模型复制初始化（去掉生成头），让它的「预期」起点与策略一致——否则优势计算一开始就偏。

**③ 奖励标准化**（上一节）：batch 内减去均值、除以标准差——让 $\beta$ 与奖励尺度解耦，大幅减少「调一次奖励就重调 $\beta$」的噩梦。

**④ 熵奖励（entropy bonus）**：在目标里加一点「生成分布的熵」，防止策略过早坍缩成「只会说一种高分话」的复读机——**熵系数调太低，模型变复读机；太高，训练发散**。

**⑤ 显存优化**：策略用 LoRA、其他三个模型全量但冻结；梯度检查点全开；必要时用「参考模型 offload」。

**⑥ 监控优势与 KL**：**KL 持续放大**说明 $\beta$ 太小或学习率太大；**优势长期为正**说明价值网络没跟上；**KL 突然暴跌**可能预示模型坍缩——这些曲线比 loss 更值得盯。

**⑦ 从「采样」到「更新」的节奏**：PPO 的「生成采样」与「梯度更新」是两段耗时——采样阶段 GPU 利用率低（生成是内存/带宽瓶颈），更新阶段利用率高。**把采样与更新的比例调平衡**（如 1 次采样配多次微更新），能显著提升整体吞吐——这是 PPO 吞吐调优的隐藏杠杆。

**⑧ 参考模型与奖励模型的「冻结纪律」**：PPO 的四模型里，**参考与奖励必须全程冻结**——参考一旦漂移，KL 锚点失效；奖励一旦被更新，策略在「打一个移动的靶」。实现上给这两个模型挂 `requires_grad=False`，并确认优化器参数组里**只有策略与价值网络的参数**——这是「四模型架构不乱」的工程保障。<span class="marginnote">PPO 训练有个「玄学时刻」：loss 会突然起飞。绝大多数情况下是「优势估计失真」——价值网络没跟上、或奖励标准化失效。此时别急着调学习率，先查三条曲线：<strong>KL 是不是在爆、优势是不是长期为正、奖励是不是在虚涨</strong>——找到「哪条曲线先失控」，对症下药。</span>

## 6 小结

- **PPO = 策略梯度 + 裁剪更新**：采样 → 打分 → 算优势 → 裁剪更新 → 更新价值网络，五步循环。
- **四模型架构**：策略（训）、价值（训）、参考（冻）、奖励（冻）——显存重、常配 LoRA 策略。
- **裁剪目标**：$L^{\mathrm{clip}} = \mathbb{E}[\min(\rho A, \mathrm{clip}(\rho, 1\pm\epsilon)A)]$——「别一次走太远」。
- **KL 惩罚两种实现**：奖励修正（$\tilde{r} = r - \beta\mathrm{KL}$）与独立 KL 损失——默认用前者。
- 调参要点：**小学习率、价值网络从策略初始化、奖励标准化、熵奖励防坍缩、盯 KL/优势曲线**。
- 与 DPO 的分水岭：**PPO 在线采样、工程重；DPO 离线、轻量**——下一篇之后两者长期并存。
- 一句话记忆：**PPO 是「边走边学」的在线优化，DPO 是「翻旧账」的离线优化**——前者上限高、成本高，后者稳定、轻量。
- 落地提醒：**PPO 不是「第一次对齐」的默认选择**——先用 SFT + 拒绝采样/DPO 拿到不错基线，确需在线探索再上 PPO；「先便宜后昂贵」是多数团队的真实节奏。
