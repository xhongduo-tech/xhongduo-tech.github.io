## 为什么从 PRM 开始

RLVR 给数学、代码提供了「客观奖励」，但它默认奖励**只看最终结果**——「答对了给 1，否则 0」。这个「结果奖励（outcome reward）」有个明显盲区：**它不关心过程**。模型可能「答案对了但推理一塌糊涂」（蒙对的），也可能「推理对了但最后一步抄错」（会做却失分）——结果奖励对这两种情况都给出同样的 0/1，无法引导模型「学会正确的推理过程」。

**过程奖励模型（PRM，Process Reward Model）** 把监督粒度从「结果」细化到「每一步」：给推理链的**每个步骤**打分，判断「这一步对不对」。它来自 OpenAI 的《Let's Verify Step by Step》（2023）与清华的 Math-Shepherd 等工作，是当前推理模型训练的重要组件。本节讲清 PRM 是什么、怎么训、怎么用，以及它「为什么比只看结果更强」。<span class="marginnote">一句话对比：<strong>ORM（结果奖励模型）打「整段分」，PRM（过程奖励模型）打「每步分」</strong>。PRM 的直觉来自教学：光看学生「期末成绩」不知道他哪步不会，逐题逐步批改才能精准纠错——PRM 就是那个「逐步骤批改的老师」。</span>

## 1 结果奖励的盲区：两个「被冤枉」的例子

设一道数学题的推理链为「步骤 1 → 步骤 2 → … → 最终答案」，结果奖励 $r_{\mathrm{outcome}}$ 只看最终答案对不对。这会带来两类「冤案」：

**冤案一：蒙对的**。模型写出「胡乱推理 + 碰巧正确的答案」——结果奖励给 1，模型学到「乱写也可能得分」。**推理能力没被训练，反而可能强化「猜」**。

**冤案二：会做却失分**。模型推理全部正确，最后一步把答案抄错——结果奖励给 0，模型被「全盘否定」，但它真正缺的只是「最后一步的细心」。**正确的推理过程没得到正反馈**。

结果奖励的另一个根本问题是**稀疏**：整个推理链只在最后有一个 0/1 信号，中间步骤「有没有学对」完全未知——**梯度无法定位「哪一步该改」**。

**PRM 的回应**：给每个步骤一个独立的「对/错」标签，让监督「密集」起来——模型每走一步都能收到「这一步对不对」的反馈，推理过程被逐步引导。

## 2 PRM 是什么：给每一步打分

PRM 的输入是「提示 + 推理链」，输出是**每个步骤一个分数**（表示「该步骤正确与否」）。设推理链有 $T$ 个步骤 $s_1, \dots, s_T$，PRM 输出：

$$
r_{\mathrm{PRM}} = \big[\, r_1, r_2, \dots, r_T \,\big], \qquad r_t \in [0, 1]
$$

其中 $r_t$ 是「第 $t$ 步正确的概率」。逐项拆解：

- 每个步骤独立打分——**细粒度监督**；
- 分数 0–1：1 表示「这一步完全正确」，0 表示「这一步就错了」；
- 关键性质：**一旦某一步得低分，后面的步骤即使「看似合理」也没有意义**——因为推理链是「一错到底」的，前一步错了，后面的都是空中楼阁。

训练时，PRM 通常是在「判断每一步对不对」的**二分类任务**上训练的：给模型「提示 + 推理链 + 一个步骤」，让模型判断「这一步是否有效」。它与奖励模型（判整段好坏）的区别，只在「评分粒度」。

## 3 公式解析：步骤级损失

PRM 的训练目标，是对每一步做二分类监督。设第 $t$ 步的真值标签为 $z_t \in \{0, 1\}$（1 正确、0 错误），PRM 的损失：

$$
\mathcal{L}_{\mathrm{PRM}} = -\sum_{t=1}^{T}\Big[\, z_t \log r_t + (1 - z_t) \log(1 - r_t) \Big]
$$

逐项拆解：

- $r_t$：PRM 对第 $t$ 步「正确」的预测概率；
- $z_t$：第 $t$ 步的真值标签（来自标注）；
- 括号里：标准的**二分类交叉熵**——$z_t=1$ 时鼓励 $r_t \to 1$，$z_t=0$ 时鼓励 $r_t \to 0$；
- 对 $T$ 步求和：**每个步骤都贡献梯度**——监督从「整段一个信号」变成「每步一个信号」。

**PRM 的推理时用法**：对一条候选推理链，PRM 给每步打分，取「**最低分步骤**」（或「所有步骤分数的某种聚合」）作为整条链的分数——因为「一步错，全盘错」，**最弱的一步决定了这条链的可靠性**。这个「取最小」的设计，是 PRM 与 ORM（取整段分数）的本质区别。

聚合方式在代码里只有几行：

```python
import math

def aggregate(r_scores, mode="min"):
    """r_scores: 一条推理链各步骤的分数 [r_1, r_2, ..., r_T]"""
    if mode == "min":
        return min(r_scores)                 # 最弱一步：一步错，全盘错
    if mode == "prod":
        return math.prod(r_scores)           # 全链稳健性：积越小越不牢
    if mode == "mean":
        return sum(r_scores) / len(r_scores) # 平均，折中方案
```

`min` 与 `prod` 的区别值得体会：**min 对「最弱一步」最敏感**（一条链若有个 0.2 的步，min 直接把它判死），**prod 对「全链稳健性」更敏感**（积越小越说明整体不牢）。实践中两者常结合——用 min 做「硬淘汰」、用 prod 做「精排序」。

## 4 步骤标签从哪来：人工、LLM 判官与自动估计

PRM 最大的工程难点是**步骤标签**——它比「最终答案对错」贵得多。三条获取路径：

**① 人工标注**：人逐步骤标「对/错」。最可靠但最贵——一条推理链要标 $T$ 次。OpenAI 的《Let's Verify Step by Step》用了这种方法，验证了「逐步监督」的价值。

**② LLM 判官**：让强 LLM 判断每一步对不对。成本低，但判官本身可能犯错——「学出来的裁判」问题依旧。

**③ 自动估计（蒙特卡洛）**：Math-Shepherd 的做法——**让模型从一个步骤出发继续生成多个「未来」，看最终答案正确率**。若从某步出发的续写大多能答对，说明这一步是对的；反之则错。这个「未来正确率」作为步骤标签，完全自动：

$$
z_t \approx \frac{\text{从第 } t \text{ 步出发、最终答对的续写数}}{\text{从第 } t \text{ 步出发的续写总数}}
$$

**自动估计的意义**：它让「逐步骤标签」不再依赖人工，PRM 的训练可以规模化——这是 Math-Shepherd 能训练大规模 PRM 的关键。<span class="marginnote">自动估计的直觉：<strong>「这一步对」意味着「从这一步继续，大概率能走到正确终点」</strong>——用「未来的正确率」反推「现在的对错」，是蒙特卡洛思想在步骤级监督上的应用。它比「看这一步的文本」更客观，也避免了判官的「文本偏见」。</span>

## 5 推理时与 RL 中的应用

PRM 有两大应用场景：

**场景一：推理时搜索（best-of-N + 重排）**。对每个提示生成 $N$ 条候选推理链，用 PRM 给每条打分，选分数最高的那条。论文报告：**用 PRM 做 best-of-N，比用 ORM 做 best-of-N 的搜索效率更高**——因为 PRM 能「提前淘汰」推理中途就走错的链，而不是等结果出来才判。

**场景二：RL 的逐步奖励（RLVR 的 PRM 版）**。在 RLVR 里，PRM 的逐步分数可以作为**每一步的密集奖励**——模型每生成一步就收到「对不对」的信号，而不是只有结尾的 0/1。这让 RL 的梯度更密集、训练更稳，是「推理模型」训练的重要组件。

**关键结果**：《Let's Verify Step by Step》报告，**逐步监督的 PRM 在数学推理上显著优于结果监督的 ORM**，且这个优势在「搜索 + 重排」的场景下更明显——「会做对每一步」比「能蒙对结果」更能泛化到新题目。

## 6 挑战与局限

PRM 不是银弹，几个必须知道的局限：

**步骤切分是难点**：推理链怎么切「步」？切得太粗（整段一步）退化成 ORM，切得太细（每词一步）噪声大——**切分粒度本身就是个超参**；
**标签质量决定一切**：无论人工、判官还是自动估计，标签错了 PRM 就学错——自动估计在「困难题」上尤其不稳（模型本身不会做，未来正确率不可靠）；
**「步骤对、整体错」的困境**：每一步都「看似合理」，合起来却推出错误结论——PRM 逐步骤打分抓不到这种「组合性错误」；
**可被 hack**：PRM 可能被「故意写得每一步都像对的」话术骗过——它与奖励模型共享「judge 可被利用」的问题。<span class="marginnote">一个务实的分工建议：<strong>结果用规则（RLVR 的验证器）、过程用 PRM</strong>——规则判「最终答案客观对不对」，PRM 判「过程质量高不高」。两者互补，比「只用一个」更稳：规则防「答案 hack」，PRM 防「过程注水」。</span>

## 7 小结

- **PRM 给推理链的每一步打分**，把监督从「结果级」（稀疏 0/1）细化到「步骤级」（密集 0–1）。
- 结果奖励的盲区：**蒙对的被加分、会做的被冤枉**——PRM 用逐步信号定位「哪一步该改」。
- **步骤级损失** $-\sum_t [z_t\log r_t + (1-z_t)\log(1-r_t)]$：每步一个二分类监督。
- **标签三来源**：人工（最可靠）、LLM 判官（省成本）、**蒙特卡洛自动估计**（可规模化，用「未来正确率」反推步骤对错）。
- 两大应用：**推理时 best-of-N 重排**（搜索效率高于 ORM）与 **RL 的逐步密集奖励**。
- 局限：步骤切分、标签质量、组合性错误、可被 hack——**结果用规则、过程用 PRM** 是务实组合。
