## 为什么从 RLHF 总览开始

本专题走到第六篇，我们终于来到微调最具「价值观」色彩的一环：**偏好优化**。前三篇的 SFT 教模型「看到指令就作答」，但它只学「示范」——示范是「人写过的某个答案」，未必是「最好的答案」。偏好优化的目标，是让模型学会**在众多答案里偏好更好的那个**，并最终内化为「有用、诚实、无害」的行为准则。

**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）** 是这条路的开山范式，2017 年被 Chris-style 等引入语言模型，2022 年经 InstructGPT 一举成名，成为 ChatGPT 训练的核心。它是一条三阶段流水线：**SFT → 奖励模型 → 强化学习**。本节先把全景图铺开，后面 14 节再逐个拆解。<span class="marginnote">先立住一个坐标系：SFT（第二篇）给模型「基础的对话能力」，RLHF 给模型「价值的判断力」。判断力来自<strong>比较</strong>——「这个答案比那个好」比「这个答案是对的」更容易标注，也更接近真实的质量观。偏好优化的一切，都建立在「比较」这个动作上。</span>

## 1 为什么 SFT 不够：示范的天花板

SFT 是 RLHF 的第一站，但 RLHF 的存在本身就在说「SFT 不够」。SFT 的局限有三：

1. **示范不等于最优**：人类写的一个答案，只是「一个可接受的答案」，不是「最优答案」。让模型模仿它，模型学会的是「像人一样答」，不是「比人答得更好」；
2. **示范难覆盖「拒绝」**：真正有用的助手要会拒绝有害请求、承认不知道。但示范数据里「拒绝」样本稀少，模型很难从模仿中学到「什么时候不该答」；
3. **示范缺乏「相对偏好」**：同一个问题的两个答案，哪个更好？示范数据只给了一个，无法承载「比较」信息——而「比较」正是质量判断的原始素材。

RLHF 的回应：**与其让模型模仿「一个答案」，不如让模型优化「人类偏好的信号」**。这个信号从哪来？从「成对比较」里来——人类更容易判断「A 比 B 好」，比「A 是满分」容易得多。于是就有了三阶段流水线的第二阶段：奖励模型。

## 2 三阶段流水线：SFT → RM → RL

RLHF 是一条三段式流水线，每段有明确输入、目标函数与产物：

| 阶段 | 输入数据 | 目标函数 | 产物 |
| --- | --- | --- | --- |
| ① SFT | 指令-回答配对 | 交叉熵（仅回答） | SFT 模型（会对话） |
| ② 奖励模型（RM） | 人类成对偏好 | 排序损失 | 奖励模型（会打分） |
| ③ 强化学习（RL） | 提示词（无答案） | 奖励最大化 + KL 约束 | 对齐模型（会择优） |

**① SFT**：与第二篇完全一样，用「指令-回答」配对训练，得到会对话的基线。它是后续所有步骤的「起点模型」。

**② 奖励模型（reward model）**：训练一个「打分器」。它接收「提示 + 回答」，输出一个分数——分数越高，代表「人类越可能偏好这个回答」。训练数据是人类标注的**成对比较**（两个回答哪个更好），目标函数是排序损失（Bradley-Terry 模型，下一节展开）。这个奖励模型就是「人类偏好的代理」。

**③ 强化学习**：把「奖励模型当环境、SFT 模型当策略」跑 RL。对每个提示，SFT 模型生成回答，奖励模型打分，**用这个分数当回报去更新策略**——让模型学会「产出更高分（更被偏好）的回答」。同时用一个 **KL 惩罚**把模型「拉住」，防止它为了刷分而偏离 SFT 模型太远（这正是 PPO 与 DPO 两篇文章的主角）。

用一次「采样循环」看清三阶段如何协作。设提示是「写一首关于秋天的诗」：

- **SFT 模型**（第①阶段产物）负责**生成**：对提示采样出回答 A、回答 B（两个候选）；
- **人类**（标注）负责**比较**：判断「B 比 A 更有诗意」，产出偏好对「(A, B) → B 胜」；
- **奖励模型**（第②阶段产物）负责**打分**：学会「B 的分数 > A 的分数」后，对**任何新回答**都能打出一个连续分数——替代人类做判断；
- **强化学习**（第③阶段）负责**优化**：让模型多采样出「奖励模型打分高」的回答，并把「采样高分回答」内化成参数。

三阶段的产物各司其职：**生成、比较、打分、优化**——这就是 RLHF 流水线的分工图。<span class="marginnote">三个阶段里，前两阶段的目标函数都是「可微的」（交叉熵、排序损失），第三阶段却要处理「采样 + 打分」的不可微链路——这是 RL 登场的根本原因。但也正是这条「不可微」之路，让 RLHF 成为整条流水线里最难调、最容易翻车的环节。</span>

## 3 公式解析：RLHF 的优化目标

把第三阶段的目标函数写出来，RLHF 的「奖励最大化 + KL 约束」就一目了然：

$$
\max_{\pi_\theta} \; \mathbb{E}_{x \sim \mathcal{D},\; y \sim \pi_\theta(\cdot \mid x)}\Big[ r_\phi(x, y) \Big] - \beta\, \mathbb{E}_{x \sim \mathcal{D}}\Big[ \mathrm{KL}\big(\pi_\theta(\cdot\mid x) \,\|\, \pi_{\mathrm{ref}}(\cdot\mid x)\big) \Big]
$$

逐项拆解：

- $\pi_\theta$：正在训练的策略（对齐模型），给定提示 $x$ 生成回答 $y$；
- $r_\phi(x, y)$：**奖励模型**对（提示，回答）打的分数——训练目标的第一项是「让生成回答的平均奖励最大化」；
- $\pi_{\mathrm{ref}}$：**参考模型**——通常是 SFT 模型（或上一轮迭代的模型）；
- $\mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}})$：策略与参考模型的 **KL 散度**——衡量「当前策略偏离参考模型多少」；
- $\beta$：**KL 系数**，控制「偏离程度」的容忍度——$\beta$ 大，模型不敢偏离参考（更稳但更保守）；$\beta$ 小，模型放飞自我去刷奖励（可能 reward hacking）；
- 减号：第二项是**惩罚**——既要奖励高，又不能偏离参考太远。

**直觉**：RLHF 在「讨好奖励模型」与「不偏离 SFT 模型」之间走钢丝。KL 惩罚不是可有可无的细节，而是**防「reward hacking」的护栏**——没有它，模型会钻奖励模型的空子（说一些奖励模型喜欢、但人类觉得莫名其妙的话）。这个「奖励 vs KL」的平衡，是整个 RLHF 调参的核心。<span class="marginnote">这个目标函数还是理解 DPO 的钥匙：DPO 的推导，就是把这个「带 KL 约束的 RL 目标」<strong>闭式求解</strong>，消掉奖励模型与 RL 步骤，直接得到「用偏好数据训练策略」的损失——它让「对齐」从三段式简化成一段式，代价是失去「在线采样」的灵活性（详见 DPO 两篇）。</span>

## 4 RLHF 的工程全景：从数据到部署

把三阶段展开成工程步骤，你会看到 RLHF 是一个「重数据、重调参」的流水线：

1. **数据**：收集提示池（覆盖各种任务），用 SFT 模型（或更强模型）生成多个回答，请人类标注「哪个更好」——得到成对偏好数据；
2. **训练 RM**：在偏好数据上训练奖励模型，注意**校准**（避免分数膨胀）、**多样性**（多个 RM 取集成）——详见《奖励模型训练》；
3. **训练策略**：用 PPO 等 RL 算法，在提示池上反复「采样 → 打分 → 更新」，期间用 KL 惩罚约束偏离；
4. **评估**：用 MT-Bench、AlpacaEval 等对齐质量基准（第九篇）验证「偏好质量」是否提升，并检查**能力是否退化**（RL 最容易把模型的通用能力带走）；
5. **迭代**：RLHF 是「数据-训练-评估」的循环——一轮训练完，用新模型重新采样、重新标注、再训一轮（ReST 与迭代式采样一节的主题）。

### 从 InstructGPT 到 ChatGPT：RLHF 的成名史

RLHF 并非新概念——它在 2017 年就被用于训练对话与摘要模型，但真正「封神」是在 OpenAI 的 InstructGPT 论文（2022）里。InstructGPT 的工作在 ChatGPT 上被验证为可行，也确立了 RLHF 的「标准配方」：

- **提示池**来自真实用户请求（OpenAI API 的真实流量），而非人工编造——保证任务分布贴近使用；
- **偏好标注**用「多个模型回答排序」而非「两两比较」——标注效率更高；
- **奖励模型**做**集成**（多个 RM 取平均）——降低单个 RM 的偏差。

这套「真实提示 + 排序标注 + RM 集成」的配方，几乎是后来所有 RLHF 工作的默认模板。理解它的每一步为什么这么做，比记住配方本身更有价值——它们分别对应「数据代表性」「标注效率」「信号可靠性」三个工程关切。

## 5 两大路线与本节定位

RLHF 并非唯一路线。本专题第六篇的 15 篇文章覆盖了两大偏好优化家族：

- **RL 路线**：RLHF（三阶段）→ PPO 实现 → GRPO（组相对估计）→ RLVR（可验证奖励）——「用强化学习最大化奖励」；
- **直接优化路线**：DPO → IPO/KTO → ORPO/SimPO——「从偏好数据直接推出最优策略，跳过 RM 与 RL」。

两条路线各有取舍：RL 路线灵活（可在线迭代）、但复杂难调；直接路线简单稳定、但偏离线。本节的「三阶段全景」是 RL 路线的骨架；读后续文章时，带着「这条路在优化第 3 节的哪个目标函数」的问题，就能把 15 篇串成一张网。

最后给一个「RLHF 会不会把模型训坏」的预警。RL 阶段最容易出现的三宗罪：**reward hacking**（钻奖励模型空子）、**能力坍塌**（为了讨好奖励而丢失通用能力，如答非所问、过度谄媚）、**KL 失控**（$\beta$ 调错导致偏离参考过远）。这三宗罪分别在《奖励模型训练》《在线与离线偏好优化的取舍》与 PPO 两篇里系统展开。记住：**RLHF 不是「训完就完」，而是一个「数据、训练、评估」反复迭代的过程**——这也是后面 ReST 与迭代式 DPO 的出发点。

一个「RLHF 前后必做的对照」值得养成习惯：**RL 前后各跑一遍「能力 + 对齐 + 安全」三维评估**（第九篇的总框架）——RLHF 最怕「对齐涨了、能力悄悄塌了」而不自知；有了「前后对照」，能力坍塌会在第一轮就被看见，而不是等部署后才发现。

## 6 小结

- **RLHF 三阶段**：SFT（会对话）→ 奖励模型（会打分）→ 强化学习（会择优）。
- **SFT 的局限**：示范 ≠ 最优、难覆盖拒绝、缺「比较」信息——偏好优化补的正是「比较」。
- **奖励模型**：在成对偏好上训练「打分器」，是「人类偏好的代理」。
- **核心目标**：$\max \mathbb{E}[r_\phi] - \beta\,\mathrm{KL}(\pi_\theta\|\pi_{\mathrm{ref}})$——「奖励最大 + 不偏离参考」的平衡。
- **KL 惩罚是护栏**：防 reward hacking，是整个 RLHF 调参的核心。
- 两条路线：**RL 路线**（PPO/GRPO/RLVR）与**直接优化路线**（DPO/IPO/ORPO）——本篇 15 节全是它们的分支。
- 一句话记忆：**三阶段分工——SFT 教「怎么答」、RM 学「哪个好」、RL 学「选好的」**；每阶段的数据、损失与产物都不同。
