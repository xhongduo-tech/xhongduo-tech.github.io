## 为什么从长上下文挑战开始

现代用户不满足于「一句一问」——他们要模型读懂整本书、整份合同、整段代码库。模型能处理的上下文长度，成了继参数量之后第二个「军备竞赛」指标：2k → 8k → 32k → 128k → 1M。而微调，正是把「短上下文模型」改造成「长上下文模型」的主战场。

但把上下文从 2k 拉到 128k，不是「把训练数据改长一点」那么简单。它同时撞上三堵墙：**注意力显存**（随长度平方爆炸）、**位置外推**（模型没见过那么远的位置）、**数据稀缺**（高质量长文本少且难标）。本节先把这三堵墙的成因讲透，后面五节再逐个破墙。读这一篇，就像看一场「工程上如何驯服长度」的战役——每一堵墙都有专门的破法。<span class="marginnote">为什么长上下文值得单独开一篇？因为「长序列微调」不是「短序列微调的加长版」，而是一组全新的工程问题：注意力算力、位置编码、并行策略、数据构造、评估方法——每一环都有专门的技术栈。这也正是它与第三篇《全参数微调》里「长序列要上序列并行」那句伏笔的衔接点。</span>

## 1 第一堵墙：注意力显存随长度平方爆炸

上一节激活公式已经埋下伏笔：**标准注意力的显存随序列长度二次增长**。回顾第三篇的每层激活公式：

$$
M_{\text{attn}} = s b a \cdot s \times \text{常数} \propto s^2
$$

其中 $s$ 是序列长度、$a$ 是注意力头数。逐项拆解这堵墙：

- **注意力分数矩阵** $s \times s$：每个 query 要对所有 key 算分数，所以分数矩阵是 $s$ 行 $s$ 列——**面积随 $s$ 平方增长**；
- 从 2k 到 8k，$s$ 变 4 倍，**分数矩阵面积变 16 倍**；从 2k 到 128k，是 4096 倍；
- 激活值公式里的 $5as/h$ 项（第三篇）正是这个平方项的来源——序列一长，它吞掉整个显存。

**为什么是墙**：显存是物理的，平方增长意味着「长度翻倍，显存四倍」。128k 的注意力显存是 8k 的 256 倍——**任何单卡都装不下，除非换算法**。这就是为什么长序列必须用**分块注意力**（FlashAttention、Ring Attention，见后文）——把「算完整分数矩阵」换成「按块算、算完即弃」。

分块注意力的核心思想值得先剧透：**不显式构造 $s \times s$ 的完整分数矩阵，而是把序列切成块、逐块算注意力、在线更新输出**。它把「平方显存」降回「线性显存」，是长序列微调的第一块地基——后文的序列并行与 Ring Attention 都是在它之上再做「跨卡切分」。记住这条主线：**先分块（单卡内），再并行（跨卡）**。

## 2 第二堵墙：位置外推，模型「没见过那么远」

即使显存解决了，还有更隐蔽的问题：**模型根本不知道「位置 100000」长什么样**。

多数模型的位置编码是**外推能力有限**的：

- **绝对位置编码**（如 GPT-2 的可学习位置）：只在训练见过的位置上有定义——训练到 2k，位置 5000 就是一个「从未被优化过」的随机向量；
- **RoPE（旋转位置编码）**（Llama 系列）：理论上能外推，但实践上直接外推会掉点——**距离超过训练长度后，注意力分数分布失衡**（某些相对距离的分数异常高），模型「注意力失焦」。

**为什么需要「位置扩展」**：为了让模型处理超出训练长度的输入，必须显式调整位置编码，让「远距离」也能被模型理解。这就是第五篇第二篇文章的主题——**位置插值（PI）、NTK 与 YaRN**，它们本质上是「把 2k 训练过的位置编码『重标定』成 128k 可用的」。

RoPE 直接外推失败的机制值得一提：RoPE 的旋转频率是按训练长度设定的，超出训练长度后，高频旋转会让「相邻 token 的相对位置」在旋转后迅速失去可区分性——注意力分数被某些异常大的位置分支配，模型陷入「注意力集中到错误位置」的状态。这不是「不知道位置」，而是「位置信息被旋转得无法使用了」。理解了这一点，就能理解为什么「降低旋转频率」（NTK 的核心）能让外推变稳——**把旋转放慢，位置信息就不会在远距离处失效**。<span class="marginnote">一个直观类比：模型在「1 到 2000 的地图」上训练过；现在要它理解「1 到 128000 的城市」。位置插值是「把 2000 张老地图重新铺到 128000 的范围上」——不是画新地图，而是把旧地图的刻度重标定。</span>

## 3 第三堵墙：数据稀缺，长文本难找也难标

显存与位置是「硬件与算法」问题，数据稀缺是「更现实」的问题——**高质量长文本数据又少又贵**。

- **少**：互联网上的长文档（书籍、论文、长报告）数量远少于短文本；且长文档内的高质量片段占比更低；
- **难标**：短指令数据可以人工标注，**长对话/长文档的标注成本随长度线性增长**——128k 的标注，一个人一天标不了几条；
- **难合成**：模型生成短文本很稳，生成 128k 的连贯长文容易「烂尾」——长程一致性（前文埋的伏笔后面还能接上）是合成的硬骨头。

数据稀缺的后果是「**数据分布失配**」：训练时长文档稀少，推理时却要处理长文档，模型自然力不从心。对策（第五篇第五篇文章）包括：**长文档续写**（拿现成的长文本让模型续写）、**长对话构造**（把短对话拼成长对话）、**合成长依赖任务**（刻意制造「需要读很远的线索」的任务）。

### 长度翻倍的成本账：为什么不是「免费升级」

把「把上下文做长」的成本量化一下，就会明白为什么长上下文是系统性问题。假设序列从 $s_0$ 拉到 $s_1 = 4s_0$：

- **算力**：注意力部分 $\propto s^2$，MLP 与 embedding 部分 $\propto s$——总算力大约增长 4–16 倍（长序列时注意力占主导）；
- **显存**：激活值同样 $\propto s^2$，即便有分块注意力，长序列仍需更大的显存或更强的并行；
- **数据**：长文本的 token 数总量其实不少（整本书就是几百万 token），但**单条样本变长**让 batch 更难组织、更难处理坏样本；
- **训练步数**：同样 token 预算下，长序列让「每步的 token 数」变大、步数变少——学习率调度、checkpoint 频率都要跟着调。

一句话：**上下文长度不是「改个配置」，而是「全栈成本」**——每个环节都随长度线性或二次放大。这也解释了为什么「短模型 + 位置插值」能临时撑住长输入，但真正的长上下文能力必须用「长数据 + 长训练」练出来。

## 4 三堵墙的关联：为什么必须「协同破墙」

三堵墙不是独立的，它们彼此放大：

| 墙 | 破墙手段 | 依赖 |
| --- | --- | --- |
| 注意力显存 | 分块注意力 / 序列并行 | 算法与硬件 |
| 位置外推 | 位置插值 / NTK / YaRN | 位置编码重标定 |
| 数据稀缺 | 长文档续写 / 合成长依赖任务 | 数据工程 |

**协同点**：位置扩展要配合「真的用长数据训练过」才有效（否则只是「能接受长输入」但「不会用长信息」）；长数据训练又依赖「显存装得下长序列」（否则训不起来）；而显存解决后，数据质量决定「长上下文到底是真能力还是假能力」。三者环环相扣，这就是为什么长序列微调需要一整套技术栈而非单个技巧。

一个工程上的「破墙顺序」建议：**先解决显存（换分块注意力 / 并行），再扩展位置（PI/NTK/YaRN），最后补长数据**。顺序反过来会浪费——显存装不下，位置扩了也用不了；数据再好的长上下文，没有位置扩展也只是「输入进去了但位置混乱」。<span class="marginnote">一个常被忽略的真相：<strong>「能处理 128k」不等于「会用 128k」</strong>。位置扩展解决了「输入得进去」，但「模型真的去读远处信息」取决于训练数据里有没有「需要远距离检索」的任务。这就是为什么长上下文评估（大海捞针）既测「能读进去」也测「真在用」。</span>

## 5 一张破墙路线图

把整个第五篇的地图铺开，三堵墙的破法各就各位：

1. **显存墙** → 分块注意力（FlashAttention 系）+ 序列并行（Ulysses 切头、Ring Attention 环形通信）——本篇第 3、4 节；
2. **位置墙** → 位置插值（PI）、NTK-aware scaling、YaRN——本篇第 2 节；
3. **数据墙** → 长文档续写、长对话、合成长依赖任务——本篇第 5 节；
4. **验证** → 大海捞针（NIAH）、RULER 等长上下文基准——本篇第 6 节。

这条路线图也是读后续各篇的索引：每一篇文章都是在「破一堵墙」。读的时候可以带着「这堵墙为什么存在、这招怎么破」的问题，比逐篇记忆更有体系。

### 「名义上下文」与「有效上下文」：一个必须记住的区分

长上下文领域有两个概念最容易被混淆：

- **名义上下文（nominal context）**：模型「声称」支持的长度——通常来自位置编码扩展或推理参数设置。它回答「模型能不能把 128k 塞进窗口」；
- **有效上下文（effective context）**：模型在 128k 里**真的能利用远处信息**的长度——回答「把答案埋在 100k 处，模型还找不找得到」。

两者的差距是长上下文领域最核心的「水分」所在：**很多模型「名义 128k」，有效上下文只有 16k**——它能把长文读进去，但读完就忘。所有长上下文评估（大海捞针、RULER）本质都在测「有效上下文」而不是「名义上下文」。记住这个区分，你就能一眼识破营销话术里的「128k」。

## 6 小结

- 长上下文微调撞上**三堵墙**：注意力显存（随 $s^2$ 爆炸）、位置外推（模型没见过远位置）、数据稀缺（长文本又少又难标）。
- **注意力显存墙**：分数矩阵面积 $\propto s^2$，128k 的显存是 8k 的 256 倍——必须换分块注意力与序列并行。
- **位置外推墙**：绝对位置无定义、RoPE 直接外推失焦——需要位置插值 / NTK / YaRN 重标定。
- **数据稀缺墙**：长文本少、标注贵、合成易烂尾——需要长文档续写与合成长依赖任务。
- 三堵墙**环环相扣**，必须协同破墙：「能处理长」≠「会用长」，评估（大海捞针）是最终裁判。
- 记住「**名义上下文 vs 有效上下文**」：很多模型名义 128k、有效只有 16k——长上下文评估测的永远是有效能力。
- 三堵墙的先后：**先破显存（算得动）、再破位置（进得去）、最后破数据（用得上）**——顺序颠倒，前面的努力会白费。
- 提醒：三堵墙的「破法」在后续各节——读的时候带着「这堵墙为什么存在、这招怎么破」的问题，比逐篇记忆更有体系。

在下一节，我们先破「位置墙」：**位置编码扩展——位置插值（PI）、NTK 与 YaRN**。
