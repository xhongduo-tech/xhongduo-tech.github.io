## 为什么从偏好数据收集开始

RLHF 三阶段里，**奖励模型的质量上限由偏好数据决定**——而偏好数据是整个流水线里「最难造假」的一环：它需要人类真实判断，既贵又慢，还充满主观性。偏好数据做不好，后面奖励模型再强、强化学习再精，也只是「在坏数据上精雕细琢」。

本节回答偏好数据收集的三个核心问题：**怎么标**（标注协议）、**标得信不信得过**（一致性检验）、**数据长什么样才能训练奖励模型**（Bradley-Terry 模型）。这三个问题构成了从「人类判断」到「模型信号」的完整转换链。<span class="marginnote">先记住偏好数据的「一条铁律」：<strong>偏好数据记录的是「比较」，不是「评分」</strong>——人类擅长判断「A 比 B 好」，但不擅长给「A 值 8.7 分」。整条 RLHF 流水线，就是围绕「利用比较、避开评分」这个原则设计的。</span>

## 1 为什么「比较」比「评分」好：认知心理学视角

让人类标注偏好，有两种基本格式：

- **评分（rating）**：给单个回答打 1–5 分。简单，但**主观性极强**——两个标注者对「4 分」的理解可以完全不同；
- **比较（comparison）**：给出两个回答，判断「哪个更好」。相对判断比绝对判断**稳定得多**——「这个比那个更有帮助」几乎不需要校准。

评分的问题在「参照系漂移」：不同人、不同时段、不同上下文的「4 分」不是同一个东西。比较的问题在「只能得到相对信息」——「A 比 B 好」不告诉你 A 有多好。RLHF 的选择是**拥抱比较**：相对信息虽然「不绝对」，但足够训练出「能区分好坏」的奖励模型——毕竟奖励模型只需要「排序正确」，不需要「分数精确」。

于是偏好数据的标准形态是：**（提示 $x$，回答 $y_w$，回答 $y_l$）**——其中 $y_w$ 是「更被偏好（win）」，$y_l$ 是「较少被偏好（lose）」。

## 2 标注协议：两两比较、排序与平局

收集（$x, y_w, y_l$）三元组，有三种主流标注协议：

**① 两两比较（pairwise）**：给标注者两个回答，二选一「哪个更好」。最简单、最稳定，但标注量随回答数线性增长——N 个回答要标 N-1 次（或 C(N,2) 次全比较）。

**② 排序（ranking）**：给标注者 K 个回答（K=4–9），要求按质量排序。InstructGPT 用它——**一次标注产出多个两两比较对**（排第 1 的胜于所有排后面的），标注效率高。代价是「给 9 个回答排序」对标注者认知负担大、质量波动。

**③ 带平局与豁免（tie & skip）**：两回答「差不多」时允许平局；「两个都烂」时允许标注「都不好」或跳过。这些「边缘样本」不是噪声——它们告诉奖励模型「这类问题根本没有好答案」，对训练「会拒绝」的能力至关重要。<span class="marginnote">一个工程经验：<strong>平局的比例要控制</strong>——平局太多说明生成的候选质量趋同（采样温度太低），太少说明候选差异过大（采样太野）。理想平局率约 5%–15%，超出这个区间就该调生成温度。</span>

**标注指南**：无论哪种协议，都必须给标注者一份**指南**，定义「好」的标准。RLHF 的三维标准：**有用性**（helpfulness，是否完成任务）、**诚实性**（honesty，是否准确不编造）、**无害性**（harmlessness，是否拒绝有害请求）。指南写得越具体，标注者之间的一致性越高。

一个具体的标注界面示例，能说明「指南」长什么样：

```text
【指令】把下面这句话翻译成英文：「今天天气很好」

【回答 A】The weather is good today.
【回答 B】Today the weather is very nice, and I hope you have a great day!

请选择（单选）：
( ) A 更好        ( ) B 更好        ( ) 差不多（平局）     ( ) 两个都不好
评分维度（可多选，帮助质检）：
[ ] 有用性      [ ] 诚实性      [ ] 无害性      [ ] 其他
```

注意两个细节：**「两个都不好」单独成选项**——它收集「这个提示没有好答案」的信号；**「评分维度」不是让标注者打分，而是让标注者标注「为什么」**——这些「理由标签」既帮助质检（判断标注是否敷衍），也能用于分析模型的具体短板。

## 3 一致性检验：标注者信不信得过

偏好数据是**人标的**，而人会有分歧。衡量「标注信得过信不过」的指标，最常用的是**Cohen's κ**：

$$
\kappa = \frac{p_o - p_e}{1 - p_e}
$$

其中 $p_o$ 是两位标注者的**观察一致率**（两人做出相同判断的比例），$p_e$ 是**偶然一致率**（两人纯靠猜能达到的一致比例）。逐项拆解：

- 分子 $p_o - p_e$：观察一致**超出偶然**的部分——这才是「真实的」一致性；
- 分母 $1 - p_e$：一致率能超出的**最大幅度**（即完全一致时）；
- 比值 $\kappa$：**扣掉偶然因素后的一致性**，取值 0–1；
- 经验刻度：$\kappa > 0.6$ 算「可用」，>0.8 算「优秀」；<0.4 说明标注协议或指南有问题。

**为什么必须测一致性？** 因为它决定了偏好数据里有多少「噪声」。两人对同一对回答判断相反，训练时奖励模型会收到矛盾的信号——数据里这样的「矛盾对」越多，奖励模型学得越糊涂。一致性检验的价值是**在训练前发现问题**：κ 低，先改指南、改协议、换标注者，而不是硬着头皮把矛盾数据喂给模型。<span class="marginnote">除 κ 外，工程上还有几个「软」检查：<strong>标注耗时</strong>（太快说明没认真看）、<strong>标注者自评置信度</strong>（低置信的样本可重标）、<strong>随机的「金标准对」</strong>（插入已知答案的测试对，看标注者答对率）。这些「质检样本」是数据流水线的常备手段。</span>

## 4 公式解析：Bradley-Terry 模型

偏好数据收集的终点，是把它变成奖励模型的训练目标。**Bradley-Terry（BT）模型**是这个转换的数学桥梁：它给「偏好概率」一个可微的参数化形式。

设奖励模型对（提示 $x$，回答 $y$）输出分数 $r_\phi(x, y)$，BT 模型定义「$y_w$ 被偏好」的概率：

$$
P_\phi\big(y_w \succ y_l \mid x\big) = \frac{\exp\big(r_\phi(x, y_w)\big)}{\exp\big(r_\phi(x, y_w)\big) + \exp\big(r_\phi(x, y_l)\big)} = \sigma\Big(r_\phi(x, y_w) - r_\phi(x, y_l)\Big)
$$

逐项拆解：

- $r_\phi(x, y_w)$、$r_\phi(x, y_l)$：奖励模型给胜者与败者的分数；
- 指数化 + 归一化：把两个分数变成「胜者的偏好概率」——分数差越大，概率越接近 1；
- $\sigma(\cdot)$：**sigmoid 函数**——最终等价于「两个分数之差的 sigmoid」；
- **训练目标**：最大化「胜者概率」——即「让奖励模型给 $y_w$ 的打分**相对高于** $y_l$」。用对数损失写就是 $\mathcal{L} = -\log \sigma(r_w - r_l)$。

**直觉**：BT 模型把「比较」翻译成「分数差」。奖励模型不需要知道「绝对分数」该是多少，只需要**让胜者的分数高于败者**——这与「比较优于评分」的哲学完美对齐：收集的数据是相对偏好，训练的模型也只学相对排序。<span class="marginnote">BT 模型来自 20 世纪初 Bradley 与 Terry 的统计学工作——最初用于「运动队两两对决的胜负概率」建模。RLHF 把它「移植」到语言模型：把「队伍实力」换成「回答分数」，把「胜负」换成「偏好」。这个移植之所以成立，是因为两者的数学结构同构：<strong>两两比较 + 潜在强度 → 相对概率</strong>。</span>

BT 损失的代码实现只有几行（下一节的奖励模型训练会展开）：

```python
def bt_loss(reward_w, reward_l):
    """reward_w / reward_l: 胜者与败者的奖励分数 (B,)"""
    logits = reward_w - reward_l                    # 分数差
    loss = -F.logsigmoid(logits).mean()            # -log σ(r_w - r_l)
    return loss
```

注意它只依赖「分数差」——**奖励模型的绝对分数没有任何约束**。这就是为什么单独训好的奖励模型分数会随意漂移（有的给 0–1、有的给 ±10），也引出后文「奖励校准」的必要性。先记住这个损失，它就是「比较 → 训练信号」的最终形态。## 5 数据规模与质量工程

偏好数据该收集多少、怎么保质量？几个经验数字与原则：

- **规模**：奖励模型训练通常需要 **1 万到 10 万对**偏好数据——远少于 SFT 的指令数据量。因为「比较」的信息密度高于「示范」：一对比较就能传递「一个回答优于另一个」的相对信息；
- **提示池多样性**：提示要覆盖**任务类型与难度的长尾**——常见任务太多会偏科，长尾任务太少会「没见过的不会评」；
- **来源**：提示来自真实用户请求（最贴近使用），回答由「当前 SFT 模型 + 更强模型」混合采样——**覆盖不同质量档**，让比较有「区分度」；
- **迭代式收集**：每轮 RLHF 训练后，用新模型重新采样回答、重新标注——偏好数据不是一次性的，而是随模型能力「水涨船高」的（这正是 ReST 与迭代式 DPO 的主题）。<span class="marginnote">质量工程的终极原则：<strong>宁可少而精，不可多而杂</strong>。一条清晰一致的偏好对，比十条互相矛盾的样本更有价值——因为矛盾样本会同时「教」奖励模型「A 好」和「B 好」，等于没教。数据清洗时，优先剔除「标注者分歧大」「金标准对答错」的样本。</span>

## 6 小结

- **偏好数据是「比较」不是「评分」**：相对判断比绝对评分稳定，这是 RLHF 的哲学起点。
- 三种标注协议：**两两比较**（最稳）、**排序**（效率高，InstructGPT 用）、**带平局/豁免**（处理边缘，教「会拒绝」）。
- **一致性检验**用 Cohen's κ：$\kappa = (p_o - p_e)/(1 - p_e)$，>0.6 可用、>0.8 优秀——训练前先查数据信不信得过。
- **Bradley-Terry 模型**：$P(y_w \succ y_l) = \sigma(r_w - r_l)$——把「比较」翻译成「分数差」，是奖励模型的训练目标。
- 数据规模 **1 万–10 万对**；提示池要覆盖长尾；答案要混合质量档；数据随模型迭代更新。
- 质量铁律：**少而精 > 多而杂**——矛盾样本等于没教。
