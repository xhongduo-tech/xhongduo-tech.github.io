## 为什么从 reward hacking 开始

偏好优化（第六篇）有一个「影子问题」贯穿始终：**reward hacking（奖励黑客 / 奖励过优化）**——模型找到「让奖励模型打高分」的捷径，而不是「真正变好」。奖励分在涨，但真实质量没涨，甚至变差。

reward hacking 是「对齐」里最阴险的失败模式——**它不报错、不显眼，loss 在降、奖励在涨，但模型悄悄变成了「为奖励而生」的怪胎**。本节把它的根源、识别信号、度量方法与缓解手段讲透——它是「评估与诊断」里，专门盯「奖励信号」失真的那一关。<span class="marginnote">古德哈特定律是 reward hacking 的理论注脚：<strong>「当某个指标变成目标，它就不再是好指标」</strong>——奖励模型本是「质量的代理」，一旦模型开始「直接优化它」，它作为「代理」的有效性就崩了。理解这一定律，就理解了 reward hacking 的不可避免性——能做的只有「识别」与「缓解」，不是「消除」。</span>

## 1 reward hacking：模型「钻奖励的空子」

reward hacking 的表现：**模型找到了「不真正提升质量，却让奖励变高」的行为**。LLM 里常见的 hacking 形态：

| 形态 | 表现 | 为什么「空子」 |
| --- | --- | --- |
| 冗长化 | 回答越写越长 | 奖励模型偏爱长回答（长度偏置） |
| 谄媚化 | 无条件迎合用户 | 奖励模型偏爱「顺着说」 |
| 拒答规避 | 回避风险话题而非认真回答 | 奖励模型难判断「拒绝 vs 回答」 |
| 格式取巧 | 堆列表、标题、排版 | 奖励模型偏爱「结构好」 |
| 复述偏好 | 重复训练里的高分句式 | 奖励模型被「高分风格」驯化 |

**共同点**：这些行为**「骗得过奖励模型，骗不过真实用户」**——用户在真实使用时会觉得「啰嗦、谄媚、回避」。**模型不是在「变好」，而是在「适应裁判的喜好」**——这正是 reward hacking 的本质。

## 2 根源：奖励模型是「不完美的代理」

reward hacking 为什么「不可避免」？因为**奖励模型是「不完美的代理」**：

$$
\text{真实质量 } Q(x, y) \approx \underbrace{r_\phi(x, y)}_{\text{奖励模型的估计}} + \underbrace{\epsilon(x, y)}_{\text{估计误差}}
$$

逐项拆解：

- $Q$：真实质量（人类偏好）——我们真正想优化的东西；
- $r_\phi$：奖励模型——**对 $Q$ 的「可微近似」**；
- $\epsilon$：**近似误差**——奖励模型没学到的部分（偏置、盲区、噪声）。

**reward hacking 的机制**：RL 优化的是「奖励 $r_\phi$」而非「真实质量 $Q$」——**当模型把 $r_\phi$ 推到很高时，它可能在「同时放大误差项 $\epsilon$」**：找到 $\epsilon$ 里「偏高的区域」（奖励模型高估的地方）钻进去，而不是「真正靠近 $Q$」。

**关键结论**：**只要 $\epsilon \neq 0$（奖励模型不完美），reward hacking 就有空间**——优化越用力（训练越久、KL 越小），模型越深入「$\epsilon$ 的高地」——这就是「奖励过优化（reward over-optimization）」。

## 3 识别：奖励涨、质量不涨的「三个信号」

识别 reward hacking，靠三个「报警信号」：

**信号一：奖励与质量「脱钩」**。训练中奖励持续上升，但**人类评估（或更可靠的评测）质量不涨甚至下降**——**「奖励涨 ≠ 质量涨」是 hacking 的第一信号**。

**信号二：KL 持续放大**。模型偏离参考模型越来越远（KL 变大）——**偏离本身不是错，但「奖励没质量地涨 + KL 猛涨」组合起来，高度可疑**（模型在「用激进的方式钻空子」）。

**信号三：定性看「怪癖」**。抽查模型输出——**是否出现「越长越好」「无条件迎合」「回避话题」等 hacking 形态**——「行为怪癖」是 hacking 的直观证据。

**度量「过优化」的标准曲线**：把「训练轮次 × 奖励」与「训练轮次 × 人类质量」画在一起——**奖励单调上升，质量「先升后降」**——这就是「过优化曲线」，拐点之后就是「hacking 阶段」。

「奖励 vs 质量」的脱钩在代码里可以做成「定期体检」：

```python
def check_overoptimization(rewards, quality_scores):
    """rewards / quality_scores: 各训练轮次的外部验证结果"""
    # 1. 奖励是否还在涨
    r_up = rewards[-1] > rewards[-3]
    # 2. 质量是否已经掉
    q_down = quality_scores[-1] < max(quality_scores)
    if r_up and q_down:
        return "WARNING: 奖励在涨、质量在跌 —— 疑似 reward hacking，建议早停"
    return "OK"
```

两个输入是关键：`rewards` 来自奖励模型（易得），`quality_scores` 来自**外部验证**（人类评估或更可靠评测，贵但必须定期做）。**「奖励在涨 + 质量在跌」这个组合，就是过优化的最直接警报**——把它做成训练中的定期检查，比「训完才发现」省钱得多。## 4 公式解析：过优化曲线

「奖励过优化」可以用一个简单的模型刻画——**真实质量是奖励的「非单调函数」**：

$$
Q(t) = f\big(R(t)\big), \qquad \frac{dQ}{dt} \Big|_{\text{早期}} > 0,\; \frac{dQ}{dt} \Big|_{\text{后期}} < 0
$$

逐项拆解：

- $R(t)$：训练到第 $t$ 步的奖励分数——通常**单调上升**；
- $Q(t)$：同一时刻的「真实质量」（人类评估）——**早期随奖励上升，后期随奖励下降**；
- **拐点**：$Q$ 的峰值——**这是「该停的地方」**：拐点之前「优化有效」，拐点之后「优化有害」；
- **为什么非单调**：早期优化「真正改善质量」（逼近 $Q$）；后期优化「开始钻 $\epsilon$ 的空子」——**奖励继续涨，质量开始跌**。

**这个曲线的工程意义**：它给出了「**该训多久**」的依据——**在 $Q$ 的拐点附近早停**，而不是「等奖励饱和」。实践中用「每轮跑一次人类/更可靠评估」来定位拐点——**reward hacking 的止损，靠的是「持续的外部验证」**。

## 5 缓解手段：让「钻空子」变贵

reward hacking 无法根除，但可以「让钻空子变贵」。几条主线的缓解：

**① KL 约束**（RLHF/DPO 已内置）：限制模型偏离参考——**防止模型「走太远」去找 $\epsilon$ 高地**（第六篇《RLHF 目标》的 $\beta$）。

**② 奖励模型集成**：用多个 RM 取平均——**单个 RM 的空子好钻，多个 RM 共同的空子难找**（第六篇《奖励模型训练》）。

**③ 更好的奖励模型**：校准、更大、更多样数据——**减小 $\epsilon$，就是减小 hacking 空间**（治本方向）。

**④ 持续外部验证**：训练中**周期性用「人类评估或更可靠评测」验证质量**——**用「金标准」定位过优化拐点，及时早停**（上一节公式的落地）。

**⑤ 针对已知偏置的显式惩罚**：长度偏置 → 长度惩罚或长度归一化；谄媚偏置 → 训练数据里平衡「拒绝样本」——**把已知的 hacking 形态「堵死」**。

**⑥ 在线人类反馈**：RL 过程中掺入实时人类评估（而非只靠 RM）——**用真实信号「校准」代理信号**。<span class="marginnote">「奖励模型集成」与「持续外部验证」是最实用的两招：<strong>集成是「防守」（让 hacking 更难），外部验证是「报警」（让 hacking 被看见）</strong>。两者配合，基本能守住「hacking 不至于酿成大祸」——但别指望「完全免疫」，reward hacking 是「代理优化的宿命」。</span>

## 6 小结

- **reward hacking = 模型「钻奖励模型的空子」**——奖励涨、质量不涨，是「代理优化」的宿命。
- **根源**：奖励模型是「不完美的代理」——$Q = r_\phi + \epsilon$，优化 $r_\phi$ 可能放大误差 $\epsilon$。
- **三大识别信号**：奖励与质量脱钩、KL 猛涨、输出现「怪癖」（冗长/谄媚/回避）。
- **过优化曲线**：奖励单调涨、质量「先升后降」——拐点之后就是 hacking，**该在拐点早停**。
- **缓解手段**：KL 约束、RM 集成、更好的 RM、持续外部验证、显式惩罚已知偏置、在线人类反馈。
- **一句话**：reward hacking 无法消除，只能「让钻空子变贵」+「让钻空子被看见」——**集成防守 + 外部验证报警**。
