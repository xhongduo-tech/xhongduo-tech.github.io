## 为什么从连续提示开始

提示工程（prompt engineering）是给模型写「人话指令」。但人话指令有两个天花板：其一，**人类觉得自然的话，不一定是最优的模型输入**；其二，**离散的词语没有梯度**——你无法知道「把『请』改成『麻烦你』」到底让输出好了几个百分点。

**连续提示（soft prompt）** 把「提示」从离散文本变成**连续向量**：不学「词」，而学「词向量」。这些向量可以落到词表里任何两个词之间，还能被梯度直接优化——**提示从此有了可优化的方向**。2021 年的 **Prefix-Tuning** 与 **Prompt-Tuning** 是这条路的两个代表作：一个把可学习向量放进每一层，一个只放在输入层。本节把两者的机制、公式与选型讲透。<span class="marginnote">一句话区分：<strong>硬提示（hard prompt）是「写词」，软提示（soft prompt）是「学向量」</strong>。软提示的向量可以取到词空间里不存在的值——它是在连续空间中搜索「模型最喜欢的前缀」，比在离散词表里挑词自由得多。</span>

## 1 从离散到连续：软提示的思想

预训练模型已经「知道」大量世界知识，但「如何调用」取决于输入。提示工程就是在输入上做文章。软提示把「做什么文章」变成可学习参数：

- **离散提示**：输入 = tokenize("请把这段翻译成英文")，每个 token 对应词表里的一个固定词向量；
- **连续提示**：输入 = $[P_1, \dots, P_{l_p}]$ + tokenize(原输入)，其中 $P_i \in \mathbb{R}^d$ 是**可训练向量**，不与任何词对应。

训练时，基座模型完全冻结，只有这些 $P_i$ 参与梯度更新。优化目标还是标准的下一个词预测——模型被要求「在看到这些提示向量 + 真实输入后，预测出正确的回答」。于是提示向量被迫学会「最有助于引出正确答案的前缀形态」。

<p></p>

为什么连续提示通常比离散提示强？一个直觉：**离散提示必须在词表里挑选，而词表是离散的「瓶颈」**——最优提示可能落在「介于『请』和『麻烦你』之间的语义」，这个词不存在，但连续向量可以无限逼近它。连续空间的搜索自由度，是软提示的核心优势。

## 2 Prefix-Tuning：每一层的「隐形前缀」

**Prefix-Tuning**（Li & Liang, 2021）的做法最彻底：**在每一层的注意力里，都注入一段可学习前缀**。

具体地，对每个 Transformer 层 $i$，维护两组可学习向量 $P_i^K$ 与 $P_i^V$（长度各为 $l_p$）。计算注意力时，把 $P_i^K$ 拼在键矩阵前面、$P_i^V$ 拼在值矩阵前面：

$$
K_i' = \big[\, P_i^K \,\big\Vert\, K_i \,\big], \qquad V_i' = \big[\, P_i^V \,\big\Vert\, V_i \,\big]
$$

其中 $\Vert$ 表示拼接，$K_i, V_i$ 是原始输入算出的键值。查询 $Q_i$ 不变。于是**每一层的注意力都「看见」了这段前缀**，但它不属于任何输入 token——它是模型自己学会的「隐形上下文」。<span class="marginnote">关键设计：前缀只加到键和值上，不加到查询上——因为查询是从真实输入来的，前缀只需要「被看到」而不需要「主动看」。这个「K/V 加前缀、Q 不动」的细节，是 Prefix-Tuning 与在输入层硬拼 token 的本质区别。</span>

**参数规模**：每个前缀向量是 $d$ 维，共 $l_p$ 个，两层（K 和 V），乘上 $L$ 层——总参数量 $2 l_p d L$。论文里还提出用一个小 MLP 重参数化前缀（训练更稳），后来发现直接优化也足够。

## 3 Prompt-Tuning：只改输入层的软提示

**Prompt-Tuning**（Lester et al., 2021）把软提示推到最简：**只在输入层加一组可学习向量，其余任何层都不动**。

设输入 $x$ 的 token 嵌入矩阵为 $E(x) \in \mathbb{R}^{n \times d}$，模型的实际输入变为：

$$
\text{Input} = \big[\, P \,\big\Vert\, E(x) \,\big], \qquad P \in \mathbb{R}^{l_p \times d}
$$

其中 $P$ 是唯一的可训练参数。它的参数量只有 $l_p \times d$——比 Prefix-Tuning 少了三个数量级，是「参数效率」的极致。

Prompt-Tuning 的一个关键发现是**规模效应**：**在 100 亿参数以上的大模型上，Prompt-Tuning 能达到与全参微调相近的效果；在几十亿的小模型上则明显落后**。原因是软提示的表达能力有限，只能「引导」模型，不能「重构」模型——大模型本身能力足够强，一点引导就够；小模型需要更实质的权重调整。<span class="marginnote">这个「规模效应」是理解软提示方法的钥匙：<strong>提示越简单，越依赖基座本身的强大</strong>。所以 Prompt-Tuning 适合大模型 + 简单任务，小模型 + 复杂任务要用 Prefix-Tuning 或 LoRA。</span>

## 4 公式解析：训练目标与「占位成本」

两种方法共享同一个训练目标——冻结基座、只优化提示向量，用标准 LM 损失：

$$
L(\theta_P) = -\sum_{t \in \text{回答}} \log P_{\theta_{\text{frozen}}}\big(y_t \mid [\,P \,\Vert\, \text{前缀输入}\,], y_{\\lt t}\big)
$$

逐项拆解：

- $P$：可学习的提示向量（Prefix-Tuning 是每层 $P_i^K, P_i^V$；Prompt-Tuning 是输入层 $P$）；
- $[P \Vert \cdots]$：提示向量与真实输入拼接，作为模型输入；
- $\theta_{\text{frozen}}$：基座参数完全冻结，只有 $P$ 在更新；
- 求和范围：只对回答部分的 token 计算损失（loss mask，第二篇）——模型学的是「在有这个前缀的情况下如何作答」。

**「占位成本」**：软提示与 Adapter 有个不同的隐性成本——**它占用序列长度**。$l_p$ 个前缀向量占据模型上下文窗口的 $l_p$ 个位置，序列一长，前缀就把真实内容的可用窗口挤短。选 $l_p$ 时要在「提示表达能力」与「上下文预算」之间权衡；这也是软提示与「可合并」方法（LoRA）在长上下文场景的关键差异之一。<span class="marginnote">一个常被忽略的实现细节：软提示的 token 位置是「新增的」，不消耗词表——它们不参与词表 embedding 查询，是直接在 embedding 空间里加的自由向量。这也意味着它们<strong>不会出现在生成文本里</strong>，不像硬提示那样可能被模型复述出来。</span>

### 软提示的初始化：别从随机开始

软提示的训练还有一个实操要点：**初始化方式决定了训练稳定性**。三种常见初始化：

1. **随机初始化**：用正态分布随机向量。通用但训练慢，容易陷进差解。
2. **词表嵌入初始化**：用若干真实 token 的 embedding 做起点——例如用「请翻译成英文：」这串词的向量初始化前缀。**实践中最常用**：它把模型已知的语义「种子」放进提示，训练只需微调这些种子，收敛快、效果好。
3. **针对任务的种子**：为每个任务选择不同的种子文本，让提示从「接近任务的起点」出发。

经验法则：**优先用词表嵌入初始化**，且种子的措辞越贴近目标任务越好——这是软提示最「免费」的性能提升。若发现训练不稳定，先换初始化，再调前缀长度。

### 与 HuggingFace PEFT 的对接

HF 的 **`peft`** 库把软提示封装成了 **`PromptEmbedding`** / **`PrefixEncoder`**，一行配置即可：

```python
from peft import PromptTuningConfig, get_peft_model

config = PromptTuningConfig(
    task_type="CAUSAL_LM",
    num_virtual_tokens=16,                        # 前缀长度，即公式里的 l_p
    tokenizer_name_or_path="Qwen/Qwen2.5-7B",     # 词表嵌入初始化需要传入
)
model = get_peft_model(model, config)
```

**`num_virtual_tokens`** 就是前文公式里的 $l_p$——它是软提示唯一的「模型大小旋钮」，选 8–32 之间通常够用。注意 Prompt-Tuning 在 HF 里**默认用词表嵌入初始化**（会提示你传入 `tokenizer_name_or_path`），这正对应上面「别从随机开始」的原则。



## 5 对比与选型：三组方法怎么挑

把 Prefix-Tuning、Prompt-Tuning 与 Adapter / LoRA 摆在一起：

| 维度 | Prefix-Tuning | Prompt-Tuning | Adapter | LoRA |
| --- | --- | --- | --- | --- |
| 注入位置 | 每层 K/V | 输入层 | 子层输出 | 权重映射 |
| 可训练参数 | 中 | 极小 | 中 | 小 |
| 表达能力 | 中强 | 弱 | 强 | 中 |
| 推理开销 | 占序列长度 | 占序列长度 | 每层计算 | 零（合并） |
| 适合规模 | 中大型模型 | 大模型（>10B） | 任意 | 任意 |
| 代表场景 | 少样本分类 | 多任务大模型 | 结构化改动 | 通用微调 |

选型口诀：**要极致省参数且模型很大 → Prompt-Tuning；要表达更强、模型中等 → Prefix-Tuning；要零推理开销 → LoRA；要非线性表达 → Adapter**。软提示类方法在「序列预算紧张」的场景尤其吃亏——长上下文任务里，占窗口的提示向量是实实在在的机会成本。

## 6 小结

- **软提示 = 可训练的连续向量**，从离散词表走向连续空间，可用梯度直接优化。
- **Prefix-Tuning**：每层注意力 K/V 前拼前缀（$K_i' = [P_i^K \Vert K_i]$），参数 $2 l_p d L$，表达力中强。
- **Prompt-Tuning**：只改输入层（$[P \Vert E(x)]$），参数 $l_p d$，极致省，但有明显规模效应（>10B 才逼近全参）。
- 两者都**占用序列长度**——软提示的「占位成本」是长上下文场景的隐形负担。
- 选型：大模型+简单任务用 Prompt-Tuning，中等规模用 Prefix-Tuning，零推理开销选 LoRA，强非线性选 Adapter。
