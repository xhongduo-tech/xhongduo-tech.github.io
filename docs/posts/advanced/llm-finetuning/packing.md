## 为什么从 packing 开始

上一节的 loss mask 处理了「一条样本怎么算损失」。但训练时 GPU 吃的是 **batch**，而 batch 里的样本长短不一——短的 200 token，长的 2000 token。常规做法是把它们全部 padding 到最长，于是大量算力浪费在「预测 pad」上。微调数据偏偏以短样本为主，padding 浪费动辄过半。

**packing（样本拼接）** 把多条短样本首尾相接、拼成一条接近满长的序列，把「填充用的 pad」换成「真正有价值的样本」。听起来只是省显存，实际却牵出三个必须处理好的问题：**跨样本注意力隔离、位置编码重置、loss mask 对齐**。本节把这三个问题逐个讲透——它们正是 packing 从「能跑」到「跑对」的分水岭。<span class="marginnote">一句话概括 packing 的收益：同样的显存与算力，能多喂 30%–80% 的真实 token。对以短样本为主的指令微调来说，这常常意味着「同样的钱，训出明显更好的模型」。</span>

## 1 padding 的浪费：packing 要解决的第一件事

先量化 padding 的浪费。假设一个 batch 里样本长度从 200 到 2000 不等，padding 到最长 2000：

$$
\text{浪费率} = 1 - \frac{\text{真实 token 总数}}{\text{实际计算 token 总数}} = 1 - \frac{\sum_i L_i}{B \cdot L_{\max}}
$$

其中 $B$ 是 batch size，$L_i$ 是第 $i$ 条样本的长度，$L_{\max}$ 是 batch 内最大长度。若平均长度 500、最大长度 2000，浪费率高达 75%——**四分之三的算力在算 pad**。更糟的是，模型还要在这些 pad 位置上「预测 pad token」（如果 loss mask 没做对），学出一堆废模式。

Packing 的思路很朴素：与其往空位里塞 pad，不如**再塞一条真实样本**。把若干条短样本按长度贪心装进一条最长可达 $L_{\text{max}}$ 的序列，直到装不下为止。于是 batch 里的序列条数减少了，但每条都被真实 token 填满。<span class="marginnote">贪心装箱（greedy bin packing）是 packing 的标配算法：把样本按长度从大到小排，依次往「还能装下」的序列里塞。排序 + 贪心就能把填充率做到 95% 以上，不需要更复杂的装箱算法。</span>

用一个具体例子看清「装」的动作。设 $L_{\text{max}} = 1024$，手头有四条样本，长度分别为 300、400、200、150：

- 无 packing：batch 里两条长 1024 的序列，只有 300+400+200+150 = 1050 个真 token，其余全是 pad，浪费率约 49%。
- 有 packing（贪心）：300+400+200 = 900 先装进第一条，150 装进第二条（余 874 空位可再装更多样本）。两条序列共 1050 个真 token，**pad 几乎为零**。

注意第二条序列还留了大片空位——实践中 batch 里的序列会继续从下一条样本补，直到填满或样本耗尽。这个「先长后短、见缝插针」的贪心过程，就是 packing 的全部算法内涵。

## 2 公式解析：packing 后的注意力必须是分块对角阵

样本拼成一条序列后，最危险的事是**跨样本注意力泄漏**：序列里第二条样本的 token 去 attend 第一条样本的 token，模型就「读到了不该读的内容」——仿佛对话里突然插入一段无关上下文。正确的要求是：**注意力只在同一条样本内部流动**。

设拼接后的序列由 $k$ 条样本构成，样本 $j$ 的 token 区间为 $[s_j, e_j]$，那么注意力矩阵 $A$ 应当满足：

$$
A_{i, j} = 0, \qquad \text{当 } i, j \text{ 属于不同的样本区间}
$$

也就是说，$A$ 必须是**分块对角阵（block-diagonal matrix）**：每个对角块是样本内部的注意力，块外全是 0。

$$
A = \begin{pmatrix} A_1 & 0 & \cdots & 0 \\ 0 & A_2 & \cdots & 0 \\ \vdots & \vdots & \ddots & \vdots \\ 0 & 0 & \cdots & A_k \end{pmatrix}
$$

逐项拆解：

- $A_j$：样本 $j$ 内部的自注意力矩阵（下三角，因果掩码）；<span class="marginnote">在 FlashAttention 等高效实现里，这个分块对角阵不用真的构造出来——用一条 1D 布尔 mask（每条样本内部为 True、边界为 False）即可让 kernel 跳过跨块位置，内存与计算都省。</span>
- 块外的 0：跨样本位置的注意力权重强制为零——第二条样本的第一个 token 只能看自己样本内部的 token，看不到第一条样本的尾巴；
- 因果性叠加：样本内部再叠加「只能看过去」的因果掩码，两个约束相乘，才是最终生效的掩码。

**直觉**：分块对角意味着「打包只共享计算，不共享信息」。模型看到的仍是 $k$ 个互不干扰的独立样本，只是恰好挤在一条序列里做了一次前向——这就是 packing 不改变模型行为、只改变训练效率的数学保证。

## 3 位置编码处理：RoPE 与位置 id 重置

注意力隔离只是第一关，第二关是**位置编码**。多数现代模型用 RoPE（旋转位置编码），位置信息由每个 token 的「绝对位置 id」注入。问题来了：拼接后，第二条样本的 token 位置 id 是继续往下数（如 2001、2002…），还是从 0 重新开始？

**为什么不重置会出问题？** 基座模型预训练时，每个训练序列都是一段独立文本，从位置 0 开始。到了微调，若打包样本沿用连续位置 id，第二条样本的 token 就顶着「第 2000 位」的位置信号去学「开新话题」——推理时用户的第一句话却从位置 0 开始，**训练与推理的位置分布不一致**，长距离相对位置关系也因此错位。

**正确做法**：**每条样本内部的位置 id 各自从 0 开始重置**，同时配合分块注意力，让模型感知到「这是一条独立样本」。实现上就是给每条样本重新生成一段从 0 递增的位置 id 序列，再按拼接顺序拼起来。例如 `[A 的三条 token → 0,1,2] + [B 的三条 token → 0,1,2]`，而不是 `[0,1,2,3,4,5]`。

一个常见的争论点值得说清：**如果注意力已经隔离了，RoPE 的相对位置差在样本内部仍然是正确的，位置重置是不是可有可无？** 对 RoPE 而言，注意力分数确实只依赖相对距离；但位置 id 还影响模型对「这是一段新文本」的语义感知，且与预训练分布的一致性要求有关。工程上**重置是更稳妥的选择**——它让训练样本与推理输入在位置上完全同构，不赌模型的鲁棒性。

具体到实现，位置 id 的重置通常与注意力隔离一起做：构造 packed 序列时同时产出 `position_ids`（按样本分段归零）与 `attention_mask`（按样本分段为 True/False），两者同源、同长，交给模型一次前向。不少框架（如 Axolotl、LLaMA-Factory）把这两个数组作为打包产物直接缓存，训练脚本不必关心细节。<span class="marginnote">对使用 ALiBi、绝对位置编码等不同机制的老模型，位置处理的结论类似：要么重置、要么保证与预训练一致。核心原则只有一条——<strong>训练时模型看到的位置分布，必须与推理时一致</strong>。</span>

## 4 loss mask 与打包的协同

打包后，loss mask 从「单条样本的指令/回答二分」变成「跨样本的复杂拼图」。要点有三个：

1. **mask 仍然是「只算回答」**：无论样本怎么拼，判定标准不变——目标是回答 token 的位置才计入损失。packing 只是改变了序列边界，没有改变「谁该被学习」的规则。
2. **边界处不能错位**：样本 $j$ 的最后一个位置的目标是「样本 $j$ 内回答的下一个 token」；若 mask 数组跨样本拼接时出现一位错位，损失就会算到「上一条样本的尾巴」上。这是 packing 实现里最隐蔽的 bug 源。
3. **没有 padding 但有截断**：packing 后基本没有 padding，但最后一条「装不满」的样本通常截断或丢弃。截断处若恰好切在回答中间，损失的归一化分母要按实际保留的回答 token 数算。

实现骨架与上一节的 loss mask 高度一致，只是 mask 的构造改为「按样本逐一生成、再拼接」：

```python
full_ids, full_mask = [], []
for s in packed_samples:                       # packed_samples 是一条序列里的多条样本
    ids, lm = s["input_ids"], s["response_mask"]
    full_ids.extend(ids)
    full_mask.extend(lm)                        # 各样本 mask 直接拼接
labels = [t if m else -100 for t, m in zip(full_ids, full_mask)]
```

## 5 常见错误与工程实践

Packing 的坑，绝大多数集中在「隔离与重置」两件事没做齐。逐个过一遍：

- **错误一：只拼接、不隔离注意力。** 最致命。拼完直接当一条长文本训练，模型学会「把上一条样本当上下文」，推理时行为怪异——输出里会莫名引用训练时拼在旁边的无关内容。修复：给 packed 序列设置 1D 分块注意力 mask。
- **错误二：只隔离、不重置位置。** 样本 2 顶着高位位置 id，相对位置虽对、绝对分布却与预训练不一致。修复：每条样本位置 id 从 0 重排。<span class="marginnote">TRL 旧版 SFTTrainer 曾内置 `packing=True`，若干版本里它只拼接样本、没正确处理分块注意力，埋下过不少「模型乱引用」的报错帖；后来 TRL 干脆移除了默认 packing。教训：用框架的 packing 开关时，务必确认它到底隔离了没有。</span>
- **错误三：mask 拼接错位。** 各样本 response_mask 与 input_ids 不是等长拼接，或漏了最后一截断样本的 mask 修正，损失静默算错。
- **错误四：把 packing 用在超长样本上。** 单条样本已经接近 $L_{\max}$ 时，packing 收益趋近于零，还引入隔离复杂度。实践上通常只对「平均长度远小于 $L_{\max}$」的数据集启用 packing。

一条实用的工程建议：**先在小数据上做「packing 开/关」对照**，用同一评测看模型行为是否一致。packing 做对了，训练效率显著提升而评测不掉点；做错了，评测会掉且伴随「乱引用」症状。这条对照实验，比任何代码 review 都更能验证隔离与重置是否真的做对了。

最后提醒一个容易混的点：**packing 是「训练期的显存优化」，与「长上下文能力」是两回事**。packing 只是把短样本拼在一起省算力，模型看到的分块注意力依然是短窗口；要让模型真的处理长文本，需要第五篇《长序列微调》的位置扩展、序列并行等手段。别指望 packing 顺手把长上下文教给模型。

## 6 小结

- **packing 用真实样本填满序列**，把 padding 浪费率（可达 75%）转化为有效训练 token。
- 注意力必须**分块隔离**：packed 序列的注意力矩阵是分块对角阵，跨样本位置强制为零。
- **位置 id 每条样本从 0 重置**，保证训练与推理的位置分布一致；RoPE 相对位置虽不受影响，重置仍是更稳的选择。
- loss mask 规则不变（只算回答），但**拼接时 mask 数组不能错位**，截断样本的归一化分母按实际回答 token 数算。
- 四大坑：**不隔离注意力、不重置位置、mask 拼接错位、超长样本强行 packing**。
- 用「packing 开/关对照」验证正确性：训练效率升、评测不掉点，才算真正做对。
- 一句话记忆：**packing = 「把零碎的短样本拼成整块」——共享计算、不共享信息（分块注意力隔离）**。
