## 为什么从训练稳定性开始

显存与吞吐解决「跑得起来、跑得快」，但训练还有第三个维度：**跑得稳**。所有微调工程师都见过这样的时刻——loss 正常下降了几百步，突然一根线拔地而起，接着就是 NaN 或者模型彻底变傻。

训练稳定性是一门「预防 + 应急」的工程：预防靠**梯度裁剪**与**学习率调度**这类设计好的机制，应急靠 **NaN 检测、坏 batch 回滚、checkpoint 重启**。本节把「loss 尖峰从哪来」「三件套如何防」「真崩了怎么办」一次讲清——读完你就有了一张完整的稳定性作战地图。它的重要性不亚于显存与吞吐：一个训练跑三天后在第四天崩掉，前面三天的算力全部归零。<span class="marginnote">注意区分三个「训练问题」的层次：<strong>loss 尖峰</strong>（单步异常，可恢复）、<strong>发散</strong>（持续恶化，不可恢复，必须回滚）、<strong>振荡</strong>（loss 在某个水平反复横跳，是超参问题）。三个层次对应三种不同的处理手段，别混为一谈。</span>

## 1 loss 尖峰从哪来：先诊断，再开药

loss 尖峰（loss spike）不是随机事件，绝大多数能归因到五类根因：

**① 坏 batch**。某个 batch 里混入了异常样本——超长文本、污染数据、标签错乱。模型在这一步被逼着做不可能的任务，损失瞬间拉高。这类尖峰通常**单步自愈**（下一步换正常 batch 就回来了）。

**② 学习率过大**。参数更新步幅超过「合理步幅」，一步跨出稳定域。尤其常见于**学习率调度重启**（warmup 没做好就跳到峰值学习率）或加载 checkpoint 后继续训练时。

**③ AdamW 的二阶矩偏小**。Adam 的更新幅度与 $\sqrt{v}$ 成反比；当某些参数的历史梯度 $v$ 极小时（长期梯度为零，突然来一个大梯度），更新会被放大到离谱。这就是 Adam 家族在 LLM 上仍需要梯度裁剪的原因之一。

**④ 数值下溢/上溢**。BF16 下极小概率的精度事故，或损失进入极端区间，反向传导后梯度带毒。

**⑤ 数据重复或分布突变**。训练数据在某处大量重复同一模式，模型在这一段上过拟合式地「跳变」。

诊断尖峰的第一动作永远是**回看样本**：把尖峰那一步的 batch 抽出来单独前向，loss 是否仍高？是 → 坏 batch 或数据问题；否 → 数值/超参问题。这一分，治疗方向就清楚了。

尖峰的形状也能透露病因，按「单点 vs 持续」两条特征对号入座：

| 尖峰形态 | 常见根因 | 处理 |
| --- | --- | --- |
| 孤立单点，下步自愈 | 坏 batch / 数据污染 | 排查该 batch，通常无需动作 |
| 连续数步走高 | 学习率过大 / warmup 不足 | 降低峰值学习率，重做 warmup |
| 集中在某类样本出现时 | 数据分布突变 / 重复 | 检查数据配比与去重 |
| 偶发 NaN 后恢复 | 数值下溢（BF16 精度事故） | 检查 loss scale、加梯度裁剪 |
| 一发不可收拾 | 参数已被污染 | 立即回滚 checkpoint + 降学习率 |

这张表的价值在于「分类即治疗」：多数尖峰不是随机事件，而是系统性问题在 loss 曲线上的投影——看到形态，就能锁定病因，不必靠猜。

## 2 梯度裁剪：给更新上保险

**梯度裁剪（gradient clipping）** 是最基础的稳定性保险。思想极简单：**如果这一步的梯度范数超过阈值，就把梯度整体缩小到阈值**，方向不变、只缩步幅。

$$
\text{if } \|g\| > c: \quad g \leftarrow g \cdot \frac{c}{\|g\|}, \qquad \|g\| = \sqrt{\sum_i g_i^2}
$$

逐项拆解：

- $\|g\|$：全局梯度范数（所有参数的梯度平方和开根号）；
- $c$：裁剪阈值，最常用的值约 **1.0**；
- 当 $\|g\| \le c$ 时**不做任何事**（正常步不受影响）；只有当范数越界时才缩放；
- 缩放保持梯度**方向不变**——只是「这步走过头了，收回来一点」。

**直觉**：裁剪不是「禁止大梯度」，而是「限制单步更新幅度」。它防止任何一种梯度异常（坏 batch、超参抖动）瞬间把参数推出稳定域。对 LLM 训练，`clip_grad_norm_(model.parameters(), 1.0)` 几乎是标配；调大阈值（如 5.0）更激进、可能更快但也更险，调小（如 0.3）更稳但可能拖慢收敛。<span class="marginnote">一个值得记住的关联：<strong>学习率是「步长的期望」，梯度裁剪是「步长的上限」</strong>。学习率调的是「通常走多大步」，裁剪管的是「最大能走多大步」——两者独立、配合使用。BF16 训练尤其依赖裁剪，因为它没有 FP16 的 overflow 报警（前一篇讲过）。</span>

## 3 公式解析：warmup 与余弦退火的节奏

学习率调度是稳定性的第二个旋钮。LLM 微调的标准调度是**线性 warmup + 余弦退火**：

$$
\eta(t) = \begin{cases} \eta_{\max} \cdot \dfrac{t}{T_w}, & 0 \le t < T_w \\[6pt] \dfrac{\eta_{\max}}{2}\Big(1 + \cos \dfrac{\pi (t - T_w)}{T - T_w}\Big), & T_w \le t \le T \end{cases}
$$

逐项拆解：

- $\eta_{\max}$：峰值学习率，微调通常取 $10^{-5}$–$10^{-4}$ 量级（远小于预训练的 $10^{-4}$–$10^{-3}$）；
- $T_w$：warmup 步数，通常占总步数的 1%–3%；
- **warmup 段**：学习率从 0 线性爬到峰值。为什么必须从 0 开始？因为模型从预训练权重出发，**初始参数已经在「好点」附近**——一上来就大学习率，等于把好参数一脚踢飞。warmup 给模型一个「先小步试探、确认方向」的过程；
- **余弦段**：峰值后按余弦曲线平滑降到接近 0。后期学习率趋近 0 让模型在最优解附近**精细收敛**，避免在盆底来回震荡。<span class="marginnote">微调与预训练的学习率哲学相反：预训练希望「大步探索」，微调希望「小步适配」。所以微调的 warmup 通常更短、峰值更低、总步数更少——它是「在已有好解的邻域内微调」，不是「从零学起」。</span>

**为什么调度能防尖峰？** 两个机制：warmup 防止开局过冲（尖峰最常见于前几百步）；余弦尾部让模型稳定地收敛而不是在最优解附近振荡。若你的 loss 曲线后期反复横跳，多半是学习率没退到位——把余弦尾部拉长、或加一个低学习率的尾巴，通常能压住振荡。

## 4 数值稳定性兜底：NaN 检测、坏 batch 与重启

即使有三件套，训练仍可能真崩。应急方案按严重程度分三级：

**一级：检测（detect）**。在每个 step 后检查 loss 与梯度是否为 NaN/inf——一行断言或日志钩子，成本极低。检测到就停下，不继续污染后续步。PyTorch 可注册 `torch.autograd.detect_anomaly()`（调试用，训练时太慢），生产上建议手动检查 loss。

**二级：跳过坏步（skip）**。若只是单步 NaN 而**参数还没被污染**（例如检查发生在 optimizer.step 之前），可以丢弃这一步、从上一个正常状态继续。实现上相当于「该步不更新」，配合 checkpoint 保存的上一步权重。

**三级：回滚重启（rollback）**。若 NaN 已经写进参数（检查太晚），唯一可靠的办法是**从最近一个正常 checkpoint 重启**，并降低学习率（如减半）继续。这就是「定期存 checkpoint」在稳定性层面的意义——它不是备份，是**时间机器**。

把三级应急画成决策流：**每步查 NaN → 未污染则跳过该步 → 已污染则回滚 + 降学习率 → 反复崩溃则查数据与超参**。值得强调的是：**不要试图「硬扛」NaN**——带着 NaN 继续训练，参数会被逐渐污染，损失从「可恢复的尖峰」滑向「不可恢复的发散」，这才是训练崩溃最致命的路径。<span class="marginnote">「跳过坏步」有一个现代变体：把 NaN 步的梯度替换为 0（而不是跳过整个 step），这样 batch 里的正常样本仍被学习。这招在一些框架里被实现为「NaN 梯度替换」，比完全跳过更平滑，但要注意它在极少数场景会掩盖真正的问题——<strong>如果 NaN 频繁出现，别用技巧压，先查根因</strong>。</span>

## 5 稳定性检查单

把全节的机制收成一张训练前的检查单：

- **梯度裁剪**：`clip_grad_norm_(..., 1.0)`，常开；
- **学习率调度**：线性 warmup（1%–3% 步数）+ 余弦退火，峰值 $10^{-5}$–$10^{-4}$；
- **NaN 检测**：每步查 loss 与梯度，发现即停；
- **checkpoint 频率**：每 N 步保存，作为回滚的「时间机器」；
- **数据巡检**：loss 尖峰伴随「某类样本复现」时，排查数据污染与重复；
- **精度选择**：优先 BF16 + FP32 主权重（上一篇），别在低精度上裸奔。

这套检查单是「默认全开」的——每一项的成本都极低，收益却是「训练不崩」。等崩了再补，代价是几小时甚至几天的算力。

## 6 小结

- **loss 尖峰五类根因**：坏 batch、学习率过大、AdamW 二阶矩偏小、数值下溢、数据分布突变——先诊断再开药。
- **梯度裁剪**：$g \leftarrow g \cdot c/\|g\|$，方向不变只缩步幅，阈值默认 1.0，是「步长的上限」。
- **学习率调度**：warmup 防开局过冲，余弦退火防后期振荡；微调峰值 $10^{-5}$–$10^{-4}$，总步数少。
- **应急三级**：每步检测 NaN → 未污染跳过坏步 → 已污染回滚 checkpoint 并降学习率；**别硬扛 NaN**。
- 稳定性检查单是「默认全开」的低成本保险，崩溃后再补要付出数倍算力代价。
- 一句话总纲：**裁剪管步幅上限、调度管节奏、检测管早发现、回滚管止损**——四者配合，把「崩溃」从事故降级为「小插曲」。
- 心态提醒：**训练不稳定是「常态」而非「异常」**——准备越充分（检查单全开），遇到问题时越不慌。
