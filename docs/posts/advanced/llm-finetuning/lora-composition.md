## 为什么从 LoRA 组合开始

LoRA 有一个全参微调做不到的杀手级特性：**可组合性**。因为增量 $\Delta W$ 与基座解耦、体积又小，它可以被**加、减、合并、路由**——就像一个「乐高积木」。同一份基座，可以挂上翻译 LoRA、代码 LoRA、客服 LoRA，按需切换或融合。

本节是 PEFT 这一篇的收官：把「单个 LoRA」升级为「LoRA 的系统」。我们会讲清四种组合方式——**切换、融合、叠加、路由（MoE 化）**——以及它们各自解决的场景。理解组合，你就掌握了「一个基座服务 N 个任务」的全部姿势。这条线也是社区从「如何微调一个模型」走向「如何用一个基座支撑一个产品矩阵」的必由之路。<span class="marginnote">LoRA 可组合的根源在数学：<strong>多个低秩增量相加仍是低秩</strong>（$BA + B'A'$ 的秩不超过 $r + r'$），且都与基座解耦。这让「多个适配器共存于一个基座」成为可能——全参微调下，两个任务的权重更新纠缠在同一份参数里，无法拆分。</span>

## 1 四种组合方式：从切换、融合到路由

多 LoRA 的组合有四个递进的层次，各自解决不同问题：

**① 切换（switching）**：同一基座挂多个适配器，推理时选一个生效。最简单，适合「任务明确、一次只用一个」的场景——客服机器人白天用客服 LoRA、晚上用营销 LoRA。

**② 融合（fusion / merging）**：把多个适配器**合成一个**。适合「想要综合多个任务能力」的场景——把中文 LoRA 与数学 LoRA 合并成一个「中文数学」模型。数学上就是把多个增量相加。

**③ 叠加（stacking）**：**按顺序在同一个基座上连续微调**，后一个任务在「前一个任务的产物」上继续。适合「能力需要按顺序累积」的场景——先学领域知识，再学对话风格。

**④ 路由（routing / MoE）**：给多个适配器配一个**路由器**，让模型根据输入自动选择「用哪个适配器或组合」。适合「输入类型动态变化」的场景——一条长文本里既有代码又有自然语言，路由器按内容分流。

四种方式不是互斥的：实际系统常「切换 + 融合」混用，「路由」则是一种更智能的切换。它们的共同前提，都是 LoRA 的「增量解耦」。

## 2 公式解析：LoRA 的加法组合与任务向量

融合与叠加的数学基础是「增量相加」。设两个任务各自训出 LoRA（$\frac{\alpha_1}{r_1} B_1 A_1$ 与 $\frac{\alpha_2}{r_2} B_2 A_2$），组合后的权重：

$$
W' = W_0 + \frac{\alpha_1}{r_1} B_1 A_1 + \frac{\alpha_2}{r_2} B_2 A_2
$$

逐项拆解：

- 两个增量**直接相加**，基座 $W_0$ 只出现一次——这是「任务向量（task vector）」思想的体现：每个 LoRA 增量就是一个「任务向量」，指向「从基座往这个任务方向走多少」；
- **方向与强度**：若两个任务方向一致，增量叠加放大；若方向冲突（如「更正式」与「更口语」），叠加会互相抵消——这引出融合中的一个关键问题：**任务冲突怎么处理**；
- **操作自由度**：不只是加，还能减（$W' = W_0 + \Delta W_1 - \Delta W_2$，做「能力消除」）——任务向量的算术是 LoRA 组合的通用语法。

**融合的工程技巧**：直接相加是最朴素的做法，但任务冲突时效果差。进阶方法如 **DARE**（随机丢弃部分增量 + 重缩放）与 **TIES**（先按幅值取方向、再合并）专门处理冲突——它们的核心都是「在相加前先清理掉可能冲突的噪声分量」。<span class="marginnote">一个实用的经验：<strong>融合前先检查两个 LoRA 是否「同向」</strong>——可以比较它们的余弦相似度。相似度高（>0.7）直接相加稳；相似度低甚至为负，就要用 TIES/DARE 这类「防冲突」合并，或干脆退回切换。</span>

## 3 叠加：顺序微调与能力累积

**叠加（LoRA stacking）** 与融合不同——它不是「合并已有的」，而是「顺序地练出新的」。流程：

1. 在基座上训练 LoRA₁（任务 A），得到一个「基座 + LoRA₁」；
2. **不合并**，直接在「基座 + LoRA₁」之上再挂 LoRA₂（任务 B），训练时 LoRA₁ 冻结、只训 LoRA₂；
3. 最终模型 = $W_0 + \Delta W_1 + \Delta W_2$，两个适配器各司其职。

叠加的价值在**能力顺序累积**：任务 A 学「领域知识」（如医学术语），任务 B 学「表达方式」（如对话口吻）——B 在 A 的基础上学，效果优于「两个任务一起学」的混合训练，因为混合训练可能互相干扰。

但叠加有个必须警惕的坑：**灾难性遗忘的顺序依赖**——LoRA₂ 训练时，LoRA₁ 的参数被冻结，但**梯度仍可能通过 LoRA₁ 影响基座与 LoRA₂ 的协同**；若任务 B 的数据分布与 A 差异过大，模型在 B 上学得好的同时可能在 A 上退化。缓解手段与第九篇《灾难性遗忘》一致：混合一点 A 的数据做回放，或对 LoRA₁ 加约束。

叠加在代码里就是「再挂一个适配器、冻结旧的」：

```python
from peft import LoraConfig, get_peft_model

# 任务 A：在基座上训出 LoRA₁，保存为 adapter "task_a"
model = get_peft_model(base_model, LoraConfig(r=8))
train(model, dataset_a)

# 任务 B：叠加 LoRA₂ —— 关键：冻结 LoRA₁、只训 LoRA₂
model.load_adapter("task_a")                    # 挂回 LoRA₁
model.add_adapter("task_b", LoraConfig(r=8))    # 新增 LoRA₂
for n, p in model.named_parameters():
    p.requires_grad = False                     # ← 冻结 LoRA₁ 的那行
for n, p in model.named_parameters():
    if n.startswith("task_b"):                  # 只放行新适配器
        p.requires_grad = True
```

注意 **冻结（`requires_grad = False`）** 那行：叠加训练的关键是**冻结前一个适配器、只训新适配器**。若忘了冻结，LoRA₁ 会被二次更新，「叠加」就变成了「一起重训」，顺序累积的意义就丢了。

## 4 MoE 化 PEFT：路由选择多个适配器

组合方式里最「智能」的是 **MoE 化**——把多个 LoRA 当作「专家」，配一个路由器（router）按输入选择。前向：

$$
h = W_0 x + \sum_{i=1}^{K} g_i(x)\; \frac{\alpha_i}{r_i} B_i A_i\, x, \qquad g(x) = \mathrm{softmax}\big(W_r\, x\big)
$$

逐项拆解：

- $K$ 个 LoRA 专家：各自在某个子任务上专精（如「代码专家」「数学专家」「闲聊专家」）；
- $g(x)$：路由权重——一个小的可学习线性层（$W_r$），对输入 $x$ 输出一个 $K$ 维 softmax 分布；
- 前向时**按路由权重加权组合各专家的增量**——不同输入激活不同专家；
- 训练时：路由器与各专家（LoRA）一起更新，**路由器学会「什么输入该找谁」**。

**MoE 化 PEFT 的价值**：把「全局一个适配器」变成「局部按需适配」——对多任务、多领域的模型，路由让每个任务都有专属的低秩空间，互不干扰。代表工作如 **LoRAMoE**、**MixLoRA**，它们在多任务基准上通常优于「单一大融合 LoRA」。

代价也清楚：**路由器本身要训练、要调参**（专家数 $K$、路由稀疏度），且推理时需评估路由再执行——比「合并后的单一权重」多一层逻辑。<span class="marginnote">MoE 化 PEFT 与「大模型架构里的 MoE」（如 Mixtral）不是一回事：MoE 化 PEFT 的「专家」是冻结基座之上的<strong>小适配器</strong>，基座本身仍是稠密 Transformer。它用「按输入路由」换「按内容分工」，是 PEFT 与稀疏性的结合。</span>

## 5 应用场景与选型

把四种组合方式收进一张决策表：

| 方式 | 操作 | 适用场景 | 冲突处理 |
| --- | --- | --- | --- |
| 切换 | 一次用一个 | 任务明确、互不干扰 | 天然隔离 |
| 融合 | 增量相加 / TIES / DARE | 要综合多任务能力 | 需防冲突 |
| 叠加 | 顺序挂新 LoRA | 能力顺序累积 | 需回放防遗忘 |
| 路由（MoE） | 路由器按输入选专家 | 输入类型动态多样 | 专家间天然分工 |

选型口诀：**任务少且明确 → 切换；任务多且要综合 → 融合；能力要按序累积 → 叠加；输入动态多变 → 路由**。它们的共同红利是「一个基座 + 一组小适配器」的存储与部署优势——这正是 LoRA 组合比全参微调组合更实用的根源。

## 6 小结

- **LoRA 的可组合性源于增量解耦**：多个低秩增量相加仍是低秩，且与基座分离——「一个基座服务 N 个任务」由此成为可能。
- 四种组合：**切换**（一次一个）、**融合**（增量相加，TIES/DARE 防冲突）、**叠加**（顺序累积）、**路由**（MoE 化，按输入选专家）。
- 加法组合 $W' = W_0 + \Delta W_1 + \Delta W_2$ 是「任务向量」思想的体现——可加可减，是组合的通用语法。
- 叠加要防**顺序依赖的灾难性遗忘**（回放旧数据）；融合要先查**任务方向冲突**（余弦相似度）。
- **MoE 化 PEFT** 用路由器按输入激活不同专家，多任务表现优于单一大融合，代价是多一层路由逻辑。
- 组合的前提：**「增量可拆」是组合的根基——LoRA 的增量解耦让加/减/融合成为可能**；全参微调的权重更新纠缠在一起，拆不开。
- 选型一句：**任务少用切换、要综合用融合、按序积累用叠加、输入多变用路由**。
