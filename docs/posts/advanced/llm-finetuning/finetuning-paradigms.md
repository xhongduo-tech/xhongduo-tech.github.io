## 为什么从微调范式开始

「从极限到大模型」走到第四级，你在《大模型原理》里已经见过 Transformer、见过因果语言建模——预训练把整个互联网压缩进一组权重。可你每天对话的那个「助手」，并不直接从预训练集群里走出来。基座模型会续写，不会听话；会填空，不会拒绝。把「会续写的模型」改造成「会对话、守价值的助手」，这一整段工程，就叫**微调（fine-tuning）**。

本专题《大模型微调》就是这整段工程的知识树：继续预训练、指令微调、偏好对齐、参数高效微调、长序列、评估诊断……而这一篇是地图。我们把现代大模型的打磨流水线压缩成三个阶段——**预训练、指令微调、对齐**——讲清每一阶段的输入、目标函数与产物，并回答一个贯穿全文的问题：**微调到底在改什么？**

## 1 从基座模型到助手模型：为什么需要微调

先把「微调的对象」看清楚。

一个刚结束预训练的模型，我们叫它**基座模型（base model）**：它学会的是「下一个词最可能是谁」。给基座模型输入「中国首都是」，它能流畅地补出「北京」；可你若输入「请帮我写一封道歉信」，它多半会继续像写百科一样往下接，而不是先答应「好，我来帮你」——它的权重里根本没有「你问我答」这件事。<span class="marginnote">「基础模型 / 基座模型」这一提法来自 2021 年斯坦福 CRFM 的报告《On the Opportunities and Risks of Foundation Models》，泛指在海量数据上预训练、可被下游任务二次开发的大模型。注意「基座模型」与「助手模型」是工程称谓，不是架构差异——二者的网络结构往往完全相同。</span>

你日常使用的、能对话、能遵循指令、会拒绝有害请求的模型，我们叫它**助手模型（assistant model）**。两者之间隔着的，不是推理时换个提示词就能填平的差距，而是一整套**训练时**的改造——这就是微调。

**为什么微调，而不是从头训练？** 第一，成本。预训练一个千亿参数模型要上万张卡与数万亿 token，绝大多数团队负担不起；而基座模型已经把「语言与世界知识」沉淀好了，微调只需用少得多的数据在它之上调整行为，通常单卡到数十卡即可完成。第二，界面。基座模型的「输出界面」是续写，不是服务用户；指令微调解决的就是把「续写界面」改造成「服从指令的界面」。第三，价值。模型学到了互联网里的一切，包括偏见、恶意与有害内容；对齐阶段负责在「能力」之上叠加「价值观」——这正是 [AI安全](/posts/advanced/ai-safety/) 专题的主线之一：安全不是推理时补一句提示词，而是在训练时就把价值观写进权重。<span class="marginnote">基座模型与助手模型的经典对照：GPT-3 是基座，InstructGPT 是对齐后的助手。OpenAI 在 2022 年的 InstructGPT 论文中系统报告了「对齐」带来的能力变化，这份工作也是 ChatGPT 的直接前身，对应《大模型原理》第一篇《InstructGPT 与 ChatGPT：指令微调与人类反馈对齐》。</span>

## 2 三阶段流水线：预训练 → 指令微调 → 对齐

现代大模型的制造，是一条**三段式流水线**：每一段都改变权重，但改变的目标、所用的数据与计算开销都完全不同。

![三阶段微调流水线：预训练产出基座模型，指令微调产出助手模型，对齐让助手模型符合人类价值](/images/llm-finetuning/finetuning-paradigms-1.svg)

### 预训练：海量语料的自监督学习

第一阶段是**预训练（pre-training）**。输入是**海量无标注文本**——网页、书籍、代码、论文，动辄数万亿 token。目标函数是**自监督**的因果语言建模：给定前文，预测下一个词，再与真实的下一个词计算交叉熵。所谓「自监督」，是因为标签根本不用人标——下一句话里真实的那个词，本身就是标签。

这一阶段换来的是「会说话 + 懂世界」：语法、常识、推理、世界知识都在此刻被压进参数。代价是它的行为是「续写」而不是「服务」。

### 指令微调（SFT）：对齐用户意图

第二阶段是**指令微调**，也叫**有监督微调（supervised fine-tuning，SFT）**。输入换成**人工撰写或模型蒸馏的「（指令，回答）」配对数据**，例如「把这句话翻译成英语 → Sure. 我来翻译。」目标函数仍然是交叉熵，但这次**只在回答部分的 token 上计算损失**——指令部分被 loss mask 遮掉，让模型学会「看到指令，就产出符合指令的回答」。

SFT 对齐的是**用户意图**：模型从此知道「你问我，我要答」，知道对话的格式，知道该用助手而非百科的口吻。ChatGPT 家族的前身 InstructGPT，第一步就是先做 SFT，再进入偏好对齐。<span class="marginnote">「指令微调」概念在 2021 年由 FLAN（Wei et al.）与 InstructGPT 等工作确立：把各类下游任务统一改写成「指令 → 回答」的形式，模型由此获得跨任务泛化。指令数据如何构造与清洗，是本专题第二篇《数据工程》的全部内容。</span>

### 对齐（RLHF / DPO）：价值对齐

第三阶段是**对齐（alignment）**。SFT 教会模型「照葫芦画瓢」，但示范数据回答不了「两个回答哪个更好」——人类写下的示范未必是模型应当追求的全部。对齐阶段的目标是**价值对齐**：让模型在「有用、诚实、无害」三个维度上稳定地偏好好的输出，拒绝有害请求，不做谄媚。

两大技术路线：

**RLHF（基于人类反馈的强化学习）**：先用人类对「哪个回答更好」的成对比较训练一个奖励模型，再用强化学习（典型是 PPO）让模型最大化奖励，同时用 KL 惩罚压住与 SFT 模型的偏离。
**DPO（直接偏好优化）**：把 RLHF 的优化目标闭式求解，绕过奖励模型与强化学习，直接用偏好数据做一轮训练。

注意一个关键分野：**前两阶段的目标函数都是「最大化真实文本的概率」，到了对齐阶段，才换成「最大化人类偏好的奖励」**。这是它与前两阶段最本质的区别，也是本专题第六篇《偏好优化》的主战场。<span class="marginnote">一个常被追问的问题：「指令微调还不够吗？」LIMA（2023）曾以「表面对齐假说」主张高质量小数据微调即可逼近对齐效果，与「大规模偏好优化」路线形成争论——本专题第一章第 8 条《小样本高效微调》专门辨析这一点。</span>

把三个阶段放在同一张表里对照：

| 阶段 | 数据 | 目标函数 | 产物 | 一句话角色 |
| --- | --- | --- | --- | --- |
| ① 预训练 | 数万亿 token 无标注语料 | 下一个词预测（交叉熵，全部 token） | 基座模型 | 学会语言与世界知识 |
| ② 指令微调 SFT | 指令-回答配对数据 | 交叉熵（仅回答 token） | 助手模型 | 学会听懂人话、按指令办事 |
| ③ 对齐 RLHF/DPO | 人类偏好比较数据 | 偏好 / 奖励目标 | 对齐助手模型 | 学会守规矩、有价值观 |

## 3 全参微调与参数高效微调（PEFT）

微调在工程上有一个绕不开的约束：**显存与参数量成正比**。

**全参微调（full fine-tuning）**更新全部参数。用 BF16 混合精度 + AdamW 优化器时，每 1 个参数大约要 16 字节：权重（2B）+ 梯度（2B）+ 优化器状态（fp32 主权重与两个动量，共 12B）。于是 7B 模型光参数与优化器状态就要约 110 GB，再另算激活值——单卡根本放不下，必须借助 ZeRO、FSDP 这类并行框架（本专题第三篇《全参数微调》逐条拆解）。它的好处是理论上限高，坏处是贵。

**参数高效微调（parameter-efficient fine-tuning，PEFT）**选另一条路：**冻结预训练权重，只训练一小撮新增参数**。它通常分三类：加性方法（Adapter、Prefix-Tuning 在结构里插入新模块）、选择性方法（只更新少量原始参数）、以及**重参数化方法**——其中最著名的是 **LoRA**。

LoRA 的核心观察是：**微调产生的权重更新往往落在低秩子空间**。于是不直接学 $\Delta W$，而是把它参数化为两个小矩阵的乘积：

$$
\Delta W = \frac{\alpha}{r}\, B A, \qquad B \in \mathbb{R}^{d \times r},\; A \in \mathbb{R}^{r \times k},\; r \ll \min(d,k)
$$

- $W_0 \in \mathbb{R}^{d \times k}$ 是冻结的原始权重，前向传播变为 $h = W_0 x + \Delta W\, x$；
- $A$ 用高斯初始化、$B$ 从零初始化，保证训练开始时 $\Delta W = 0$、模型从基座出发；
- 可训练参数从 $d \times k$ 降到 $r(d + k)$——通常只有全参的 0.1%–1%；
- $\alpha/r$ 是缩放系数，控制更新步长；推理时把 $\Delta W$ 合并回 $W_0$，**不增加任何推理延迟**，还能一份基座挂多份适配器、分别服务多个任务。

| 维度 | 全参微调 | PEFT（以 LoRA 为例） |
| --- | --- | --- |
| 可训练参数 | 100% | 0.1%–1% |
| 显存 / 优化器开销 | 高（约 16 字节 / 参数） | 低（仅增量矩阵） |
| 训练后部署 | 一份完整权重 | 基座 + 小适配器，可多任务共存 |
| 质量上限 | 理论最高 | 略低，多数场景够用 |

<span class="marginnote">训练好后把 $\Delta W$ 合并进 $W_0$，推理时它就是普通权重——这正是 LoRA 在低成本训练之外又带来低成本部署的原因。再叠一层 4-bit 量化基座，就是 QLoRA，见本专题第四篇《参数高效微调》。</span>

## 4 公式解析：SFT 的交叉熵损失

微调的目标函数看起来很多，但前两阶段其实共用同一个公式：**交叉熵**。区别只在于「在哪些位置、对什么数据算」。以 SFT 为例：

$$
L_{\mathrm{SFT}}(\theta) = -\frac{1}{|\mathcal{R}|}\sum_{t \in \mathcal{R}} \log P_\theta\big(y_t \mid x, y_{\\lt t}\big)
$$

逐符号拆解：

- $x$：指令（prompt），如「把这句话翻译成英语」；
- $y_1, y_2, \dots, y_T$：人工写好的回答 token 序列；
- $\mathcal{R}$：回答部分的 token 位置集合。指令部分的损失被 loss mask 遮掉——模型不该为「预测指令」负责，只该为「给出好回答」负责；
- $y_{\\lt t}$：位置 $t$ 之前的全部 token（含指令与已生成的回答），是模型此刻能看到的上下文；
- $P_\theta(y_t \mid x, y_{\\lt t})$：在当前参数 $\theta$ 下，模型认为真实 token $y_t$ 是下一个词的概率。这个概率越大越好，取对数再加负号，于是损失越小越好；
- $-\frac{1}{|\mathcal{R}|}\sum_{t \in \mathcal{R}}$：对回答部分每个 token 的负对数概率取平均，让不同长度的回答可比较。

**直觉**：在每一个回答位置上，我们都在问模型「人类写的这个词，你有多确信？」——然后更新参数，让模型对正确答案越来越「确信」。这正是预训练在做的事，唯一的差别是：预训练对语料里每个 token 都算（$\mathcal{R}$ = 全部位置，$x$ = 空前缀），SFT 只对回答部分算，且数据换成了「（指令，回答）」配对。到了第三阶段对齐，目标函数才从「最大化真实文本的概率」换成「最大化人类偏好的奖励」——这是它和前面两阶段最本质的分界。

代码里，loss mask 版交叉熵一句话就能实现：

```python
import torch.nn.functional as F

# labels 中被 mask 的位置置为 -100，cross_entropy 会自动忽略
loss = F.cross_entropy(logits.view(-1, vocab_size), labels.view(-1), ignore_index=-100)
```

## 5 小结

- 微调把**基座模型**（会续写）改造成**助手模型**（会听话、守价值），三段流水线各司其职。
- **预训练**：海量无标注语料 + 自监督下一个词预测，产出基座模型；**指令微调（SFT）**：（指令，回答）配对 + 交叉熵（loss mask 只算回答部分），对齐用户意图；**对齐（RLHF / DPO）**：人类偏好数据 + 偏好 / 奖励目标，做价值对齐。
- **目标函数的分界**：预训练与 SFT 共用交叉熵，区别在数据与掩码；对齐阶段换成偏好目标——这是全专题的总纲。
- **全参微调**约 16 字节 / 参数，7B 模型需上百 GB 显存；**PEFT（LoRA）**把可训练参数压到 0.1%–1%，训练与部署都更省。
- 微调不是「换个提示词」，而是**在训练时改写权重**；这正是它与提示工程（见《大模型原理》第十五篇 Agent 之外的推理篇）的本质差别。
