## 为什么从奖励模型训练开始

上一节我们把偏好数据「翻译」成了 BT 模型的训练目标。这一节训练那个「打分器」——**奖励模型（reward model，RM）**。它是 RLHF 三阶段的「中间人」：既要忠实反映人类偏好，又不能太「聪明」（否则会被 RL 阶段钻空子）。

奖励模型训练有三件核心事：**排序损失怎么设**、**分数怎么校准**、**怎么防 overfit 与 reward hacking**。前两件决定「RM 本身好不好」，第三件决定「RM 在 RL 里稳不稳」。本节把三件事讲透，下一节（PPO）就能站在一个可靠的 RM 之上展开。<span class="marginnote">奖励模型是整个 RLHF 里「最容易被低估」的环节：很多人以为它只是「给偏好数据训个分类器」，但它的好坏直接决定对齐质量的上限——<strong>奖励模型学错了，强化学习只会把「错」放大</strong>。所以奖励模型训练值得单独一整节。</span>

## 1 奖励模型是什么：从「生成」到「打分」的换头术

奖励模型与 SFT 模型**共享同一个骨干**（Transformer），差别在「头」：

- **SFT 模型**：输出每个 token 的概率分布（词表大小的 logits），用于「生成」；
- **奖励模型**：对整段（提示 + 回答）输出**一个标量分数**，用于「打分」。

实现上，奖励模型通常用 SFT 模型初始化，把「语言建模头」换成「回归头」：对输入序列的最后一个 token 的隐藏状态过一个线性层，压成一个分数。于是奖励模型学会了「看完整段话，给出一个偏好分数」。

训练数据就是上一节的偏好三元组（$x, y_w, y_l$）；训练目标是让「胜者的分数高于败者」。**训练完的奖励模型不再生成文本**——它只负责「评价」，是 RL 阶段的「环境」。

一个奖励模型的「换头」实现（HF 风格，理解思想即可）：

```python
class RewardModel(nn.Module):
    def __init__(self, base_model, hidden_size):
        super().__init__()
        self.base = base_model                       # SFT 骨干，可冻结部分
        self.reward_head = nn.Linear(hidden_size, 1, bias=False)
    def forward(self, input_ids, attention_mask):
        out = self.base(input_ids, attention_mask, output_hidden_states=True)
        h = out.hidden_states[-1]                    # 最后一层隐藏状态
        last = h[:, -1, :]                           # 取最后一个 token
        return self.reward_head(last).squeeze(-1)    # (B,) 每个样本一个分数
```

两个细节值得注意：其一，**取「最后一个 token」的隐藏状态**作为整段话的表示——这是 RM 的常见约定（最后一个 token 已「看过」全部上文）；其二，**`reward_head` 无 bias**——避免模型用「恒定偏置」偷懒（分数漂移的一个来源）。训练时把这个 RM 与 BT 损失接上，就是完整的奖励模型训练。

## 2 排序损失：从 BT 模型到训练目标

奖励模型的训练损失就是上一节的 BT 损失（无 margin 版）：

$$
\mathcal{L}_{\mathrm{RM}} = -\log \sigma\Big(r_\phi(x, y_w) - r_\phi(x, y_l)\Big)
$$

其中 $r_\phi$ 是奖励模型，$\sigma$ 是 sigmoid。逐项拆解：

- 分数差 $r_w - r_l$：越大代表「奖励模型越认可 $y_w$ 优于 $y_l$」；
- $-\log \sigma(\cdot)$：分数差越大、损失越小——**梯度把 $r_w$ 往上推、把 $r_l$ 往下压**；
- 一句话：**奖励模型被训练成「把胜者的分数抬到败者之上」**——它不关心绝对分，只关心排序。

**一个关键延伸：margin 变体**。有些实践在分数差上加一个 margin $m$：

$$
\mathcal{L} = -\log \sigma\big(r_w - r_l - m\big)
$$

margin 的作用是**要求「胜者明显高于败者」**，而非「只要高一点点」——它鼓励奖励模型拉开差距，减少「模棱两可」的打分。margin 调太小没效果，调太大可能让损失饱和（分数差超过 margin 后梯度为零）。经验上，**先不加 margin，若 RM 在验证集上「区分度不足」再加**。

## 3 公式解析：奖励校准——分数漂移的治理

奖励模型有个「天然毛病」：**分数绝对值会漂移**。两个 RM 用不同随机种子训练，一个给 0–1 的分数、一个给 ±10——因为它们只学了「相对排序」，绝对尺度由初始化与训练随机性决定。这种漂移在 RL 阶段会带来问题：**奖励尺度影响 KL 惩罚的平衡**（$\beta$ 与奖励同尺度）。

**奖励校准（reward calibration）** 的目标是让分数的「意义稳定」：**0 代表「中性」、正代表「好」、负代表「坏」，且尺度一致**。常用做法：

**① 数据级校准**：训练数据里混入「参考回答」——把 SFT 模型的回答当作「中性基准」，让奖励模型学「相对参考回答的好坏」。这样分数的零点对齐到「SFT 模型水平」。

**② 统计级校准（推理时）**：RL 阶段对每个 batch 的奖励做**标准化**：

$$
\tilde{r}_i = \frac{r_i - \mu_b}{\sigma_b}
$$

其中 $\mu_b$、$\sigma_b$ 是该 batch 内奖励的均值与标准差。逐项拆解：减去均值让「平均水平」归零，除以标准差让「波动幅度」统一——**不同 RM、不同 batch 的分数变得可比**。<span class="marginnote">统计级校准还有一个隐藏好处：它让 KL 惩罚的 $\beta$ 不再依赖奖励的绝对尺度——<strong>$\beta$ 调一次，换 RM 也不用重调</strong>。这是很多 RLHF 工程「为什么 batch 标准化奖励」的原因，比「拍脑袋定 $\beta$」科学得多。</span>

## 4 模型集成：防 overfit 与 reward hacking

奖励模型最容易踩的两个坑，都有「集成」这味药。

**坑一：overfit 偏好数据**。偏好数据通常只有几万对，奖励模型动辄几十亿参数——**极易把训练对「背下来」**，在验证集上分数却泛化不佳。**药**：集成——训练多个 RM（不同种子、不同数据子集），推理时取平均分数。集成后的 RM 更「平滑」、更不易过拟合单条样本。

**坑二：reward hacking**。RL 阶段的策略会「钻 RM 的空子」——找到让 RM 打分虚高的「语言模式」（如过度冗长、奉承句式），而真实质量没有提升。**药**：集成同样是有效威慑——**单个 RM 的空子好钻，多个 RM 共同的空子难找**（策略若在某一个 RM 上 hack，平均后分数不会虚高）。<span class="marginnote">集成不是万能的：若多个 RM 共享同一个「系统性偏差」（都偏好长回答、都偏好某种措辞），hacking 依然可能穿透。所以集成之外还要配合「RL 阶段的 KL 惩罚」与「人工抽查」——<strong>奖励模型是「防守」，不是「最后一道防线」</strong>。</span>

## 5 奖励模型的评估与工程要点

训练完的 RM 怎么验收？三个层次：

1. **排序准确率**：在留出的偏好验证集上，RM 判对「谁更好」的准确率——最简单、最直接；
2. **与人类相关性**：RM 分数与人类评分的相关度（Spearman/Pearson）——比准确率更细；
3. **RL 后的实际表现**：用 RM 跑一轮短 RL，看 MT-Bench 等对齐质量是否真的提升——**最终裁判**。

工程要点打包：

- **RM 用 SFT 模型初始化**（不是从零训），并**冻结部分层**（或全程低学习率）防过拟合；
- **偏好数据与验证集严格分离**，RM 训练用 early stopping；
- **RM 大小**：经验上 RM 与策略同规模或略小即可——过大反而更易 overfit、过小则区分度不足；
- **多个 RM 集成取平均**，作为 RL 阶段的稳定奖励信号。

最后给一个「奖励模型质量自检」清单，训练完逐条过：

1. **验证集排序准确率**是否明显高于随机（>70% 及格，>80% 良好）；
2. **分数分布**是否合理（不应出现「几乎所有样本都打高分」的膨胀现象）；
3. **对「明显更差」的回答**（如答非所问）是否给显著低分；
4. **对长/短回答的偏见**——RM 是否「见长就爱」（这是最常见的系统性偏差，直接导致 RL 后的回答过度冗长）。

第 4 条尤其值得盯：**长度偏置（length bias）是奖励模型最普遍的系统性缺陷**——它会让 RL 阶段训出「话痨模型」。若发现 RM 偏爱长回答，需要在训练数据里平衡长短样本，或在 RL 时显式惩罚长度。## 6 小结

- **奖励模型 = 打分器**：共享 Transformer 骨干、换成回归头，输入（提示 + 回答）输出一个标量分数。
- **排序损失**：$-\log\sigma(r_w - r_l)$，只学「胜者分数高于败者」；可选 margin 拉开差距。
- **奖励校准**：分数绝对值会漂移——数据级（混参考回答）与统计级（batch 标准化）两种治理；batch 标准化让 $\beta$ 与奖励尺度解耦。
- **模型集成**：多 RM 平均——同时防「过拟合偏好数据」与「reward hacking」。
- **验收三层**：排序准确率 → 与人类相关性 → RL 后实际表现（最终裁判）。
- RM 与策略同规模或略小、从 SFT 初始化、early stopping、严格数据分离。
