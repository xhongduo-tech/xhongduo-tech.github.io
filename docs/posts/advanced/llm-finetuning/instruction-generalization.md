## 为什么从指令泛化开始

上一篇我们做了 SFT：让模型学会「看到指令就回答」。但 SFT 最迷人的地方不在「学会训练时见过的指令」，而在**泛化**——训练时从未见过的指令，模型也能答。2021 年 FLAN 论文的标题就是这个问题的答案：《Finetuned Language Models Are Zero-Shot Learners》。为什么仅仅把任务改写成「指令 → 回答」，模型就突然获得跨任务能力？这篇我们从机制、规模证据、再到自动演化指令（Evol-Instruct）三层讲清。沿着这条主线，你会看到 SFT 从「背答案」走向「会解题」的完整机理。

## 1 指令泛化的机制：统一形式 + 任务迁移

**指令泛化（instruction generalization）**：模型在大量「指令 → 回答」样本上微调后，对未见过的指令也能给出合理回答。

机制上有两个成分：

- **统一形式（task unification）**：所有任务都翻译成同一个「自然语言指令 → 自然语言回答」接口。模型的注意力不再区分「这是摘要任务还是翻译任务」，只认「这是指令，这是回答」。<span class="marginnote">把异构任务「塞进同一个格式」，让模型把不同任务的共享结构（理解指令、组织语言、检索记忆）复用起来——这是指令泛化的第一块基石。</span>
**任务迁移（cross-task transfer）**：训练任务之间共享的「如何遵循指令」的元技能，被迁移到新任务上。模型学到的不再是「这条指令的答案」，而是「一条指令该怎么被理解」。

**重点：指令微调的目标不是记住答案，而是学会「读题」。** 这一句话，是理解后面所有规模效应与数据工程的关键。

## 2 任务多样性与规模效应：FLAN 的证据

FLAN 的实验给出了三个经典证据：

1. **任务数量越多，零样本泛化越强**：把 12 类任务、62 个数据集聚合到一起做指令微调，比用单个任务微调在**未见任务**上显著更准；
2. **模型越大，收益越大**：指令微调带来的增益随模型参数量增大而增大——小模型上指令微调收益有限，大模型上收益明显；
3. **任务均衡采样优于自然分布采样**：把不同任务按均衡比例混合（而不是按数据量自然混合），泛化更好。<span class="marginnote">这条直接改变数据工程实践：小数据集任务要「超采样」，大数据集任务要「欠采样」，让每个任务在训练中拥有相当的话语权——下一节公式解析我们把这一点写成数学。</span>

**重点：规模效应的对象不只是「模型参数」，还有「任务数量与多样性」。** 后续 T0、FLAN-T5 系列进一步确认：把规模推到数千任务、数百亿参数，指令泛化持续上涨。<span class="marginnote">T0（2021）与 FLAN-T5（2022）是这条线的两个里程碑。FLAN-T5 的工作《Scaling Instruction-Finetuned Language Models》直接把「规模」写进标题——既指模型规模，也指任务规模。</span>

把 FLAN 的结论翻译成一句工程口诀：**想要泛化，先堆任务形态，再堆数据量。** 一份只有「问答」形状的指令集，无论多少条，都教不会模型「总结」「翻译」「改写」——任务形态的覆盖，是先于数据量的第一约束。

## 3 数据质量 vs 数量：Self-Instruct 与 LIMA

规模证据说「任务越多越好」，但很快出现另一个声音：**质量**。

**Self-Instruct（2022）**：用大模型自己生成指令数据（bootstrap），用过滤策略保质量，证明**几万条自动生成的指令**就能让 GPT-3 获得不错的指令遵循能力；
**LIMA（2023）**：只用 **1,000 条**人工精挑的高质量「（指令，多轮回答）」数据微调，效果接近当时最强的 RLHF 模型——由此提出**表面对齐假说（superficial alignment hypothesis）**：模型的知识与能力早在预训练里就位，对齐只需「学会一种表层风格」，因此少量高质量数据就够。<span class="marginnote">LIMA 的「表面对齐假说」与「大规模偏好优化」路线的争论，是本专题第一章最后一条《小样本高效微调》的主角。我们这里先记住它的主张：质量可以部分对冲数量。</span>

**重点：数量管「广度」，质量管「深度」，两者都要，但权重不同。** 任务多样性需要数量（覆盖不同形式），每类任务的质量需要精挑（保证正确示范）。

## 4 Evol-Instruct：用大模型演化指令

当人工写指令成本太高时，WizardLM（2023）提出 **Evol-Instruct（指令演化）**：用一个强 LLM（如 GPT-4）当「演化器」，把种子指令一步步改得更难、更多样，自动造出大规模高质量指令集。

两条演化路径：

**深度演化（in-depth evolving）**：对一条指令增加约束、增加推理步骤、增加复杂性——例如「写一首诗」→「写一首七言律诗，每句押『安』韵，同时包含「月」和「江」两个意象」；
**广度演化（in-breadth evolving）**：生成主题不同但难度相当的新指令，例如「写诗」→「写词」「写散文」「写对联」，扩大覆盖。

每步演化后，用一个**判别器**做质量把关：新指令是否比旧指令复杂？是否可解？是否与原指令语义不同？过滤掉失败样本后再进入下一轮。<span class="marginnote">深度演化把「难度」当可编程的维度来操作，广度演化把「覆盖」当维度——这等于用规则约束让 LLM 在指令空间里做定向随机游走。论文报告 Evol-Instruct 数据微调出的 WizardLM 在指令遵循与推理上全面超越用原始种子数据微调的模型。</span>

**辨析｜易错点：** 演化不是「无限加难」就越好。难度爆炸会导致两类失败：一是**不可解指令**占比上升（判别器漏网，污染数据）；二是**模型被训练成「过度复杂」**——简单问题也要绕圈子。工程上通常设定复杂度上限，并让各难度层均匀分布。

WizardLM 的完整流水线可以压缩成三步：

1. **指令进化**：把种子指令连同「进化提示」送给 LLM，让它产出更复杂或更多样的新指令；
2. **指令消除**：判别器按「复杂度是否提升 / 是否可解 / 是否语义新颖」三把尺子过滤，不合格就丢弃；
3. **答案生成**：对合格的新指令，用 LLM 生成示范回答，得到「（新指令，回答）」样本，汇入指令池。<span class="marginnote">「进化 + 消除」是生成-筛选（generate-and-filter）范式的实例：先用模型扩量，再用规则或判别器控质。第二篇《数据工程》里 Self-Instruct、IFD 筛选都是同一思路的不同实现。</span>

这三步合起来，等于把「人工写指令」的成本，换成了「人工写种子 + 机器演化 + 规则筛选」——数据生产的边际成本被大幅压低，这也是指令数据从「手工艺」走向「工业化」的关键一步。也正因如此，Evol-Instruct 后来被广泛用于 RLHF 数据、领域微调数据的大规模构造。

## 5 公式解析：任务均衡混合目标

FLAN 发现的「任务均衡采样更好」，可以写成一条干净的公式。设共有 $K$ 个任务，第 $t$ 个任务的数据池大小为 $N_t$。指令微调的损失是各任务损失的加权平均：

$$
L(\theta) = \sum_{t=1}^{K} \pi_t \, \mathbb{E}_{(x,y)\sim\mathcal{D}_t}\big[\ell_t(x,y;\theta)\big]
$$

逐步拆解：

- **$\mathcal{D}_t$**：第 $t$ 个任务的数据集；$\ell_t$ 是单样本 SFT 损失（上一篇的交叉熵）；
- **$\pi_t$**：第 $t$ 个任务在训练中的**采样权重**。它不必等于 $N_t / \sum_j N_j$；
- **自然混合**：若 $\pi_t = N_t / \sum_j N_j$，大数据任务霸榜，小任务几乎学不到——FLAN 报告这种做法泛化较差；
- **均衡混合**：若 $\pi_t = 1/K$（每个任务等概率被采），则每次采样先均匀抽任务、再在任务内抽样本。小任务被超采样、大任务被欠采样，所有任务「话语权」均等——泛化最好；
- **平方根采样**：折中方案 $\pi_t \propto \sqrt{N_t}$，在大任务与小任务之间取平衡，常用在翻译等场景。

**直觉**：均衡混合的本质是**让模型的「读题经验」均匀覆盖各种指令形态**。它牺牲了一点大数据任务的拟合，换来的是对新指令更平滑的覆盖——这正是指令泛化的目标。<span class="marginnote">任务均衡、数据去重、长度分布控制……这些「看不见的配比」在第二篇《数据工程》里会逐条展开。配比是数据工程里最便宜也最容易被忽视的杠杆。</span>

一个简化示意，把「均衡采样」写进 DataLoader：

```python
import torch
from torch.utils.data import ConcatDataset, DataLoader, WeightedRandomSampler

# K 个任务，均衡混合：每个任务等概率被采（π_t = 1/K）
K = 3
tasks = [dataset_a, dataset_b, dataset_c]

weights = []
for ds in tasks:
    weights += [1 / (K * len(ds))] * len(ds)   # 每条样本权重 = π_t / N_t

loader = DataLoader(
    ConcatDataset(tasks),
    sampler=WeightedRandomSampler(weights, num_samples=sum(len(d) for d in tasks)),
    batch_size=32,
)
```

## 6 指令泛化的边界

泛化不是无条件的，三条边界值得记住：

**分布依赖**：指令微调泛化主要发生在「与训练指令形态相近」的新指令上。若新指令的格式、语言、领域与训练集差异巨大，泛化会明显衰减——模型不是无所不能；
**能力天花板**：指令微调只能「编排」模型已有的能力。若基座模型本身不会做某类推理（比如复杂的多步数学），再多的指令数据也补不出新能力——能力上限由预训练决定；
**规模不是万能**：FLAN 的规模曲线在大模型上明显，在小模型上增益有限。参数规模不到一定程度，指令微调「读题」能力本身也学不扎实；
**数据会过期**：指令数据的分布随用户习惯演化——两年前的指令风格未必适配今天的使用方式，指令集需要随真实反馈持续迭代。<span class="marginnote">这三条边界也解释了数据工程为何重要：指令数据要尽量贴近真实使用分布，而不是盲目堆量。</span>

## 7 小结

- **指令泛化** = 模型对未见指令也能作答，机制是**统一形式 + 任务迁移**：学到的是「读题」，不是「答案」。
- **规模效应**：任务数量、任务多样性、模型参数量三者都放大指令微调收益（FLAN / T0 / FLAN-T5）。
- **质量 vs 数量**：Self-Instruct 证明自动数据可行，LIMA 证明少量高质量数据可达惊人效果（表面对齐假说）。
- **Evol-Instruct**：用 LLM 做深度 / 广度演化自动造指令，判别器把关质量。
- **均衡混合** $\pi_t = 1/K$：让每个任务在训练中有相当话语权，是泛化的重要配方。
