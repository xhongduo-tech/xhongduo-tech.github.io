## 为什么从 P-Tuning v2 开始

上一节的 Prompt-Tuning 有一个明确短板：**它只在输入层加提示，表达能力有限，在小型模型与困难任务上远不及全参微调**。这给了研究者一个难题——软提示的方向是对的，但「只在门口挂灯」不够。

2022 年，清华的团队在 EMNLP 上提出 **P-Tuning v2**，把提示从「只在输入层」推广到「**每一层都加**」。论文标题直言其野心：《Prompt Tuning Can Be Comparable to Fine-tuning Universally Across Scales and Tasks》——**提示调优可以在所有规模、所有任务上与全参微调比肩**。它用「深层提示」补上了 Prompt-Tuning 的表达短板，是软提示方法族里一个承上启下的节点。本节从「浅层提示为什么不够」讲起，再展开深层提示的机制与公式，最后落到工程实现与选型。<span class="marginnote">P-Tuning v2 的前身是 P-Tuning v1（2021）：v1 在输入层加软提示，并引入「锚点（anchor）」让提示与任务建立联系，但依然受限于「只在一层生效」。v2 的突破就是去掉「一层」这个限制——让提示作用于每一层。</span>

## 1 Prompt-Tuning 的短板：一层提示为什么不够

回顾 Prompt-Tuning 的机制：软提示只拼在**输入 embedding** 上，之后的每一层都要靠模型自己「消化」这段提示。它的问题在于：

- **提示信号逐层衰减**：输入层的一段向量，经过十几层注意力与 MLP 的变换后，对深层输出的影响越来越弱。模型越大层越深，早期信号在到达输出层时已经「稀释」；
- **表达力受限于「引导」**：软提示只能「暗示」模型往哪个方向走，不能像全参微调那样直接改写深层权重行为。对依赖多步推理、深层特征的任务（如序列标注、问答），引导力不够。

**规模效应**在这里最刺眼：Prompt-Tuning 在 100 亿参数模型上接近全参，在 3 亿参数模型上却大幅落后。因为大模型本身能力强、一点引导就够；小模型必须被「实质性地调整」，而一层提示给不了这种调整。P-Tuning v2 的思路，就是**把提示从一层铺到所有层**——让每一层都被「实质性地影响」。

## 2 深层提示：每一层都加可学习前缀

P-Tuning v2 的做法直白而有效：**在每一层 Transformer 的输入处，都拼接一段可学习的提示向量**。设第 $i$ 层的输入隐藏状态为 $h_{i-1}$，则该层实际输入变为：

$$
h_i' = \big[\, P_i \,\big\Vert\, h_{i-1} \,\big], \qquad P_i \in \mathbb{R}^{l_p \times d}
$$

其中 $P_i$ 是第 $i$ 层专属的可学习前缀，所有层的 $P_i$ 一起构成可训练参数 $\{P_1, \dots, P_L\}$。逐项拆解：

- 每一层都有一套独立的 $P_i$，**不是共享同一段前缀**——每层学每层的；
- $l_p$：前缀长度，通常 20–100 之间，比 Prompt-Tuning 略大；
- 拼接发生在**层输入**（hidden states），所以这段前缀会参与该层注意力的查询、键、值计算——影响比「只改 K/V」更全面；
- 基座全部冻结，只优化 $\{P_i\}$。

**为什么每层都加就有用？** 因为深层信号不再依赖「从输入层一路衰减过来」——**每一层都在自己这一层「看到」任务指令**。深层特征被直接引导，模型规模再小也能获得足够的调整信号。这正是「深层提示（deep prompt tuning）」与「浅层提示」的本质区别。

顺带澄清一个常见误解：深层提示的「每一层前缀」与 Prefix-Tuning 的「每层 K/V 前缀」在效果上常被混为一谈，但 P-Tuning v2 的论文特别指出两者不等价——改层输入意味着**该层序列整体变长**，注意力的计算窗口、位置编码、后续各层的输入都随之改变；而只改 K/V 时序列长度不变。这种「影响面的差异」，正是两条路线在部分任务上表现不同的根源。<span class="marginnote">对比上一节的 Prefix-Tuning：两者都在「每一层」做文章，但<strong>Prefix-Tuning 改的是注意力 K/V（序列长度不变），P-Tuning v2 改的是层输入（每层序列变长）</strong>。P-Tuning v2 是「把 Prompt-Tuning 的做法搬进每一层」，Prefix-Tuning 是「把前缀融进注意力内部」——两条不同的「深层化」路线。</span>

## 3 公式解析：深层提示的训练目标与参数量

深层提示的训练目标与 Prompt-Tuning 相同（冻结基座、只训提示、标准 LM 或任务损失），差别全在「提示出现在哪些层」。参数量也容易算：

$$
\text{参数量} = L \times l_p \times d \qquad (\text{P-Tuning v2})
$$

对比一下三者的参数规模（设 $L$ 层、隐藏维 $d$、前缀长 $l_p$）：

| 方法 | 提示位置 | 参数量 |
| --- | --- | --- |
| Prompt-Tuning | 仅输入层 | $l_p \times d$ |
| Prefix-Tuning | 每层 K/V（两份） | $2 \times l_p \times d \times L$ |
| P-Tuning v2 | 每层输入 | $l_p \times d \times L$ |

对 7B 模型（$L=32, d=4096, l_p=50$），P-Tuning v2 的参数约 $32 \times 50 \times 4096 \approx 6.6$M——**仍然只是全参数的 0.1%**，却让每一层都有了直接可调的前缀。这就是「参数没多多少，能力跨了一个台阶」的由来。<span class="marginnote">深层提示的另一个工程要点：<strong>P-Tuning v2 不用 MLP 重参数化</strong>（P-Tuning v1 用过），直接用梯度优化前缀本身——实验表明对深层提示，直接优化既简单又稳。这给了后来所有软提示方法一条经验：方法越深，越不需要「重参数化拐杖」。</span>

## 4 设计细节与效果

P-Tuning v2 论文里有一组值得记住的设计决策：

**① 前缀长度要够**。输入层提示 20 个 token 也许够，深层提示通常要 50–100 个才稳定——太短表达力不足，太长占序列。论文用 100 作为 NLU 任务的默认值，20 用于生成任务。

**② 加 dropout 稳训练**。深层前缀直接优化容易过拟合，在提示上加 dropout（如 0.1）能显著提稳。

**③ 不同任务类型的适配**。序列标注、问答这类「依赖深层特征」的任务，正是深层提示的甜区；而简单分类任务浅层提示也许就够——选型时看任务需要多深的理解。

效果方面，论文的核心结论是：**在 300M 到 10B 的各规模模型上，P-Tuning v2 在 SuperGLUE 等基准上都能达到与全参微调相当的水平**——这是「提示调优 = 全参微调」第一次被跨规模地证明，一举扭转了 Prompt-Tuning「只适合大模型」的印象。<span class="marginnote">一个值得深思的后续：P-Tuning v2 之后，软提示方法被 LoRA 等重参数化方法的光芒盖过，但它的「深层化」思想没有消失——今天许多「每层加可学习参数」的方法（包括部分 MoE 化 PEFT）都带着 P-Tuning v2 的基因。它证明了「把参数铺到每一层」本身就能解锁表达力。</span>

### 一个实现视角：深层前缀在哪里插入

理解 P-Tuning v2，最好的办法是看「插入点」在代码里长什么样。以 HF 的 LLaMA 为例，深度提示的插入发生在**每个 decoder layer 的输入处**：

```python
# 在 HF LLaMA 的 decoder layer forward 里插入深层前缀
def forward(self, hidden_states, attention_mask, position_ids, ...):
    l_p = self.deep_prompt.shape[1]                       # 前缀长度
    # ① 拼接前缀：hidden: [B, T, d] → [B, T + l_p, d]
    hidden_states = torch.cat(
        [self.deep_prompt.expand(hidden_states.shape[0], -1, -1), hidden_states],
        dim=1,
    )
    # ② 位置 id：真实 token 的位置整体后移 l_p，RoPE 索引必须同步
    position_ids = position_ids + l_p
    # ③ attention_mask：前缀是真 token（可被 attend），前面补 1
    attention_mask = torch.cat(
        [torch.ones(attention_mask.shape[0], l_p,
                    dtype=attention_mask.dtype,
                    device=attention_mask.device),
         attention_mask],
        dim=1,
    )
    ...
```

两个隐藏的工程点：其一，**位置 id 要处理**——前缀占用序列前 $l_p$ 个位置，其后的真实 token 位置整体后移，RoPE 位置索引必须同步；其二，**attention_mask 要同步**——前缀都是真 token（可被 attend），不需要额外 mask。这两点处理错位，深层提示会静默失效，效果与浅层无异。

### 浅层还是深层：选型判断

Prompt-Tuning（浅层）与 P-Tuning v2（深层）不是取代关系，而是适用面不同：

- **任务依赖多深的理解？** 简单分类、情感分析 → 浅层提示够；序列标注、抽取式 QA、需要局部判断的任务 → 深层提示明显更强。
- **模型有多大？** 10B 以上的大模型，浅层提示已经很强，深层提示的增益变小；小模型（几亿到几十亿）是深层提示的主场。
- **序列预算紧不紧？** 深层提示每层都占 $l_p$，序列开销是浅层的 $L$ 倍；长上下文场景选浅层或改 LoRA。

一句话：**模型越大、任务越浅，越不需要深层；模型越小、任务越难，深层提示越值**。

## 5 小结

- **P-Tuning v2 = 深层提示调优**：把可学习前缀从「只在输入层」铺到「每一层的输入」，补上 Prompt-Tuning 的表达短板。
- 前向 $h_i' = [P_i \Vert h_{i-1}]$：每层独立前缀、基座冻结，参数量 $L \cdot l_p \cdot d$（仍是 0.1% 级）。
- 与 Prefix-Tuning 的区别：**改层输入（序列变长）vs 改注意力 K/V（序列不变）**——两条「深层化」路线。
- 设计细节：前缀长度 50–100、加 dropout、直接优化不用 MLP 重参数化。
- 效果：**300M 到 10B 全规模逼近全参微调**，序列标注、问答等深层任务尤其受益。
- 实现要点：深层前缀要处理**位置 id 前移**与 **attention_mask 同步**，否则静默失效；选型看「任务深浅 × 模型大小」。
- 意义：它证明了「把可学习参数铺到每一层」就能解锁表达力，这一思想后来被众多 PEFT 方法继承。

至此，加性方法（Adapter、软提示）的三员大将都讲完了。在下一节，我们转向整个 PEFT 家族里最重要的一员：**LoRA 原理——低秩假设、秩的选择与目标模块**。它用「低秩增量」重新定义了 PEFT 的性价比，也是后面 QLoRA、DoRA、PiSSA 等一系列方法的共同地基。
