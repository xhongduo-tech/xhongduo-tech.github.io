## 为什么从领域微调方法论开始

微调的下一个大类，是把通用模型改造成**某个领域的专家**——医疗、法律、金融、代码、数学。这类「领域微调」看似只是「换数据」，实则有一整套方法论：**语料配比**（怎么混合领域与通用数据）、**能力保持**（怎么不把通用能力学丢了）、**评测基线**（怎么确认「真的变专了」）。

本节先把领域微调的总方法论铺开——它是后续医疗、法律金融、代码、数学等具体领域的「共同骨架」。读完后，任何领域微调项目你都能从「该配什么数据、怎么防退化、怎么验收」三个角度下手。这一节是你读懂后续所有领域文章的「钥匙」。<span class="marginnote">一句话定位：<strong>领域微调 = 用「领域数据 + 通用数据」的混合配比，让模型在领域内变强、在领域外不退步</strong>。它同时踩在第二篇《数据配比》与第九篇《灾难性遗忘》两个主题的交汇点上——配比是「怎么喂」，遗忘是「别把旧的丢了」。</span>

## 1 领域微调的目标：不是「过拟合」，是「专精」

先想清楚「领域微调」到底要什么。一个通用模型在医疗上「会一点但不专业」——领域微调要把它变成「懂医学术语、会诊断推理、守医疗规范」的专家。这个目标的本质是：

$$
\theta^* = \arg\max_\theta\; \underbrace{\text{领域任务性能}(\theta)}_{\text{变专}} - \lambda\; \underbrace{\text{通用能力损失}(\theta)}_{\text{不退化}}
$$

逐项拆解：

- 第一项「领域任务性能」：在医疗问答、病历生成等领域任务上变强——这是微调的「进攻」；
- 第二项「通用能力损失」：模型在通用对话、常识、推理上不能明显退步——这是微调的「防守」；
- $\lambda$：两者间的权重——**λ 太大太保守（学不专），太小太激进（通用能力崩塌）**。

**为什么必须防守？** 领域微调最常见的失败不是「领域学不好」，而是「通用能力被带走」——模型对医疗题答得漂亮，却开始对「写一首诗」「解释世界卫生组织」这类通用问题变笨。这就是「灾难性遗忘」在领域微调里的体现（第九篇会系统展开），而它的根源往往是「配比里通用数据太少」。

### 「领域知识」与「领域任务」是两个不同的东西

领域微调里最常被混淆的一对概念：

- **领域知识（domain knowledge）**：事实与术语——「阿司匹林的药理」「民事诉讼法第几条」这类「知道什么」；
- **领域任务（domain task）**：行为与格式——「给出诊断建议」「起草一份合同」这类「会做什么」。

两者需要**不同的训练手段**：知识靠「继续预训练」（在领域语料上续训，让知识进权重）；任务靠「指令微调」（在领域指令上 SFT，让行为变成「指令-回答」）。**只用 SFT 灌任务、不补知识，模型会「会做但不懂」**——给出貌似专业实则错误的回答；**只补知识、不训任务，模型会「懂但不会用」**——知道术语但不会按领域格式作答。领域微调的两只手都要用：**继续预训练补知识、SFT 补任务、偏好优化守规范**。

## 2 语料配比：领域数据与通用数据的「黄金比例」

领域微调的第一个旋钮是**配比**——领域数据与通用数据的混合比例。经验法则（呼应第二篇《数据多样性与配比》）：

- **领域数据为主，通用数据打底**：常见配比是「领域 60%–80% + 通用 20%–40%」；
- **通用数据的作用**：维持通用能力、防止「领域腔」过重（模型只会说行话，不会正常对话）；
- **领域数据的作用**：注入领域知识、术语与任务模式。

配比还有一个「层次」问题——**不是只配比一次，而是分层配比**：

| 数据层 | 角色 | 配比策略 |
| --- | --- | --- |
| 领域预训练语料 | 注入领域知识（术语、概念） | 继续预训练（第一篇） |
| 领域指令数据 | 学会领域任务（问答、诊断） | SFT 主体 |
| 领域对齐数据 | 学会领域规范（拒绝、安全） | 偏好优化 |
| 通用数据 | 保持通用能力 | 混入各层打底 |

**关键**：领域微调不是「一次 SFT 完事」，而是「继续预训练（知识）→ SFT（任务）→ 偏好优化（规范）」的分层流水线——每一层都要混入通用数据保底。这与微调范式总览的三阶段同构，只是数据换成了「领域 + 通用」的混合。

## 3 能力保持：领域微调的「防守战」

配比之外，能力保持还有三件具体的手段：

**① 通用数据回放（replay）**：训练时持续混入通用数据——最简单的防守。回放比例就是配比里的「通用 20%–40%」那一部分。

**② 弹性权重（EWC 类）**：给「对通用能力重要的参数」加正则化，防止它们被领域训练大幅改动：

$$
\mathcal{L} = \mathcal{L}_{\text{领域}} + \lambda \sum_i F_i\,(\theta_i - \theta_i^{\text{旧}})^2
$$

其中 $F_i$ 是「参数 $i$ 对通用能力的重要性」（Fisher 信息）。**重要参数少动，次要参数随便改**——这是「选择性遗忘」的正则化版本。

**③ 模块隔离（PEFT 隔离）**：用 LoRA 等 PEFT 方法训练——**冻结通用权重，只训领域适配器**。这从结构上「隔离」了领域知识与通用知识：通用能力住在冻结的基座里，领域知识住在 LoRA 里，互不干扰——**这是领域微调里防遗忘最优雅的手段**。

**三者关系**：回放是「防守标配」，EWC 是「精修」，PEFT 隔离是「釜底抽薪」。实践上**回放 + PEFT 隔离**是性价比最高的组合，EWC 在「必须全参微调」时才需要。<span class="marginnote">PEFT 隔离还有一个额外红利：<strong>一份通用基座 + 多个领域 LoRA，可以服务多个领域而不互相污染</strong>——医疗 LoRA 与法律 LoRA 共存于同一基座，切换即换领域（呼应第四篇《LoRA 模块化组合》）。这比「每个领域训一个完整模型」的存储成本低一个数量级。</span>

## 4 评测基线：怎么确认「真的变专了」

领域微调最容易被「自我感觉良好」骗到——loss 降了、样例答得好了，但「真的专了吗」没有客观答案。一套完整的领域评测基线包括三层：

**① 领域任务基线（进攻侧）**。用领域内的标准基准（医疗有 MedQA、法律有法律 QA、代码有 HumanEval）评估「领域能力提升多少」。**必须与「微调前」的基线模型对比**——只报绝对分数、不报相对提升，等于没测。

**② 通用能力基线（防守侧）**。用通用基准（MMLU、GSM8K、对话质量）评估「通用能力掉了多少」。**领域微调交付的一个硬指标：通用能力下降幅度要在可接受范围内**（如 MMLU 掉 <2%）。

**③ 安全与规范基线**。领域模型还要测「守不守规范」——医疗模型会不会乱开药、法律模型会不会瞎给法律意见。**这是领域微调特有的评测维度**，比「答得准不准」更关乎责任。

把三层收成一句验收原则：**「领域分涨、通用分不跌、规范分不破」——三条同时满足，才算合格的领域微调**。<span class="marginnote">评测基线的另一个价值是「调参仪表盘」：配比、回放比例、λ 怎么调，都要靠「三层基线」的对比说话。实践上把三层基线做成「每次微调迭代必跑」的例行评测，比「训完才想起来测」科学得多——这与第九篇《微调效果评估体系》的「能力/对齐/安全三维度」完全同构。</span>

## 5 领域微调的通用流程

把方法论收成一条可复用的流水线：

1. **明确领域边界**：这个领域「负责什么、不负责什么」——医疗模型要不要懂养生？法律模型要不要懂税务？边界不清，数据必乱；
2. **语料收集与分层**：领域预训练语料、领域指令、领域对齐数据、通用打底数据——按第 2 节的分层配比；
3. **分层训练**：继续预训练（注入知识）→ SFT（学任务）→ 偏好优化（守规范），每层混入通用数据；
4. **三层评测**：领域分（进攻）、通用分（防守）、规范分（安全）——每次迭代都跑；
5. **迭代调参**：按评测结果调配比、调回放比例、调 λ——「领域分不够 → 加领域数据；通用分跌 → 加通用回放；规范分破 → 加对齐数据」。

这条流水线对任何领域（医疗、法律、金融、代码、数学）都成立——后续各节只是把「领域数据长什么样」具体化。

## 6 小结

- **领域微调 = 变专 + 不退化**：$\text{领域性能} - \lambda\,\text{通用损失}$，进攻与防守并重。
- **分层配比**：领域预训练 / 领域指令 / 领域对齐 / 通用打底四层，每层混入通用数据——不是一次配比完事。
- **能力保持三手段**：通用数据回放（标配）、EWC 正则（精修）、PEFT 隔离（釜底抽薪——领域知识住 LoRA、通用知识住冻结基座）。
- **三层评测基线**：领域分（进攻）、通用分（防守）、规范分（安全）——「涨、不跌、不破」三条同时满足。
- **通用流程**：定边界 → 分层收集 → 分层训练 → 三层评测 → 迭代调参——对任何领域都成立。
- 一句话记忆：**「知识靠续训、任务靠 SFT、规范靠对齐、通用靠回放」**——领域微调的四条腿，缺一不可。
- 方法论的普适性：后续的医疗、法律金融、代码、数学都只是「把『领域数据长什么样』具体化」——骨架一致，血肉各异。
- 上手建议：**第一次做领域微调，从「小模型 + 小数据 + 全流程」起步**——先跑通「数据→训练→三层评测」的闭环，再放大规模。
