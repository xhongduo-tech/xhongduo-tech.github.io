## 为什么从数学推理微调开始

数学与代码并列为「两大可验证领域」，但数学有一个代码没有的优点：**答案极简且唯一**——「最终答案是个数字」，验证成本比「跑测试」还低。这让数学推理微调可以走一条漂亮的自动化路径：**解题数据合成 → 验证器筛选 → 拒绝采样训练**，甚至一路通到 RLVR（可验证奖励强化学习）。

数学推理也是推理模型（o1、R1）训练的「发源地」——DeepSeek-R1、OpenAI o1 的推理能力，最早都是在数学上被验证的。理解数学推理微调，你就理解了「验证驱动」这条微调路线最纯粹的样子。本节从「数据合成」讲到「验证器筛选」，再串到「RLVR 强化」，把这条线一次拉通。<span class="marginnote">一句话定位：<strong>数学推理微调 = 「答案可验证」×「拒绝采样自提升」×「RLVR 强化」</strong>——它是「数据→验证→训练」闭环最完整的领域，也是推理模型能力的孵化器。</span>

## 1 数学推理的独特优势：答案的可验证性

数学与代码相比，验证更「廉价」：

- **代码验证**：要「跑」——沙箱、依赖、环境，成本高；
- **数学验证**：只需「比对最终答案」——解析模型输出的数字/表达式，与标准答案比对，**一行代码完成**。

这个「廉价验证」带来两个连锁优势：

**① 数据可以自动标注**。一条数学题，不需要人工写「标准解答」——让模型生成解答，验证「答案对不对」，对的就是「好数据」。**数据合成的自动化成为可能**。

**② 训练可以自举**。生成 → 验证 → 选对的训练 → 再生成——**每一轮都用「被验证过的正确答案」训练，模型越训越会做**（对应 ReST 的迭代自提升）。

数学推理也因此成为「self-improvement」研究的实验田：**只要答案可验证，模型就能「用答案当老师」**。

## 2 解题数据合成：CoT 与「答案对」

数学微调的数据，核心形态是**「题目 → 解题过程（CoT）→ 答案」**三元组。数据从哪来？

**① 现成题库**：GSM8K（小学应用题）、MATH（竞赛题）等公开基准——**但要「留测」**（这些也是评测基准，训练与评测必须分开）。

**② 合成新题**：用 LLM 从现有题目「改写」出新题（换数字、换情境、增加条件）——扩大题目多样性。合成的关键是**「答案要可验证」**：新题必须带标准答案，否则无法用验证器。

**③ 生成解答（CoT）**：对每道题，让模型（或更强模型）生成「思考过程 + 最终答案」——**生成多条**（温度采样），用答案验证器筛出「解答正确」的样本。

**合成的关键约束**：**「题目 + 答案」是硬数据（可验证），「解题过程」是软数据（可生成）**——合成时优先保证「答案对」，解题过程只是「通往正确答案的路径」。若解题过程错误但答案对（蒙对），这类样本要小心（它教模型「乱推也能对」）。

## 3 公式解析：验证器驱动的拒绝采样

数学微调的核心循环，是「生成 → 验证 → 筛选」的拒绝采样。设一道题 $x$，模型采样出 $N$ 条解题链 $y_1, \dots, y_N$，验证器给出「答案对不对」：

$$
y^* = \big\{ y_i \;\big|\; \mathrm{Verifier}(y_i) = 1 \big\}, \qquad \mathcal{L} = -\sum_{y^* \in D^*} \log \pi_\theta(y^* \mid x)
$$

逐项拆解：

- $\mathrm{Verifier}(y_i)$：**验证器**——解析 $y_i$ 的最终答案，与标准答案比对，对则 1 否则 0；
- $y^*$：通过验证的「正确答案链」集合；
- $D^*$：筛选后的数据集——只保留「答案对」的解题链；
- $\mathcal{L}$：在筛选数据上的 SFT——模型学会「生成那些能通过验证的解题链」。

**验证器与奖励模型的分工**：验证器是「规则裁判」（答案比对，客观）；奖励模型是「学出来的打分」（需要训练，主观）。数学里**优先用验证器**——它零成本、绝对客观；只有当「需要判解题过程质量」（不只是答案）时，才升级到 PRM（过程奖励模型，第六篇）。

**为什么拒绝采样在数学里特别有效**？因为数学的「答案可验证」让「筛选」极其可靠——**筛出来的样本「大概率真的对」**，模型学的是「正确的解题路径」，而非「模型自以为对的路径」。这比「用偏好模型筛」（有偏差）干净得多。<span class="marginnote">一个常被问的细节：<strong>「筛选答案对的样本」会不会让模型只学「简单题」？</strong>——不会。因为「答案对」不是「题简单」；难题只要采样够多，总会有「答对的路径」被采到。拒绝采样其实是在「挖」模型自己分布里的「正确解题能力」——难题的正确路径可能只占采样的 1%，但筛出来就有价值。</span>

「生成 → 验证 → 筛选」的循环在代码里清晰可见：

```python
for round in range(K):                            # 外层迭代（ReST 自提升）
    new_correct = []
    for x in train_prompts:
        ys = model.sample(x, n=8, temperature=0.7)   # 采样多条解答
        for y in ys:
            if verifier(y) == 1:                     # 验证器：解析最终答案并比对
                new_correct.append((x, y))
    train(model, new_correct)                        # 只在本轮的正确样本上增量训练
```

两个要点：其一，**验证器**只需「解析最终答案 + 比对标准答案」——**一行判对错**；其二，**外层迭代循环（`for round in range(K)`）**控制迭代轮数——**每轮用更新的模型重新采样**，把「挖正确路径」的能力逐轮加深（对应 ReST 的自提升）。注意**累积的正确样本**会越积越多，必要时每轮只取「本轮的正确答案」做增量训练，避免重复学习。## 4 从 SFT 到 RLVR：数学微调的进化

数学推理微调已经走过三代：

**第一代：SFT + CoT**。在「题目→解答」数据上直接微调——模型学会「像解题一样输出」，但「推理深度」有限。

**第二代：拒绝采样自提升**。SFT 模型生成多条解答 → 验证器筛选 → 在正确答案上再 SFT → 迭代（对应 ReST）。模型逐步「学会更稳的推理」，能力明显提升。

**第三代：RLVR / GRPO**。用「答案可验证」当奖励，直接做强化学习——模型在「多想想再答」中自主涌现「反思、验证、长链推理」等行为（DeepSeek-R1-Zero 的发现）。**这是当前数学推理的最强范式**。

三代的关系不是「取代」，而是「叠加」：**SFT 打底（会答）→ 拒绝采样提稳（多答对的）→ RLVR 冲刺（自主探索）**——这与代码模型微调的「配方 + FIM + RLVR」流水线完全同构。

## 5 评测与注意事项

**评测**：GSM8K、MATH 是数学推理的标准基准。**但要注意**：

**评测必须用「留出的题」**——题库一旦进过训练，评测就失真（模型可能背题）；
**pass@k 更有意义**：单次生成对错受采样运气影响，采样多次的成功率更能反映「能力」；
**关注「过程」而非只盯「答案」**：有的模型「答案蒙对了但推理是错的」——用 PRM 或人工抽查看「推理质量」。

**注意事项**：

**数据污染是最常见的翻车**：GSM8K/MATH 的题目广泛流传，容易混进训练数据——**训练前必须去重去污染**（第二篇《数据质量筛选》）；
**「蒙对」样本要警惕**：答案对但推理错的样本，教模型「乱推也能对」——必要时用 PRM 过滤；
**合成题的「答案正确性」要复核**：LLM 生成的新题，标准答案可能是错的——**合成数据的验证器也要验证**。<span class="marginnote">数学推理微调给「评测诚实度」的启示：<strong>公开基准的分数越来越「通胀」</strong>——因为题库到处流传、污染严重。真正可信的评估，要么用「全新未公开的题」，要么用「跨领域迁移」测「推理能力泛化」而非「背题能力」。这与第九篇《通用能力基准的正确使用》直接呼应。</span>

**按难度分桶看 pass@k 曲线**：一份总分可能掩盖「难题塌陷」——把评测题按难度分桶、逐桶画 pass@k，才能看到模型推理深度的真实边界；这正是 R1 类推理模型「在难题上涌现长链」被验证的方式，也提醒你「平均分高」不代表「难题能打」。

## 6 小结

- **数学的可验证性**：答案唯一 + 验证廉价——数据可自动标注、训练可自举。
- **数据合成**：「题目 + 答案」是硬数据（可验证）、「解题过程（CoT）」是软数据（可生成）——合成优先保「答案对」。
- **验证器驱动的拒绝采样**：生成 N 条 → 验证器筛「答案对」→ SFT——筛出的样本「大概率真的对」，比偏好模型筛选更干净。
- **三代进化**：SFT（会答）→ 拒绝采样（提稳）→ RLVR/GRPO（自主探索，R1 的诞生地）。
- **评测注意**：题库必须留测、pass@k 更可信、关注推理过程（防「蒙对」）、防数据污染。
- 与代码微调同构：**「会答 → 多答对 → 探索更强」**是两大可验证领域的共同节奏。
- 一句话总纲：**数学微调靠「答案当老师」**——验证器越可靠，自提升的循环越强。
- 延伸阅读：数学的「验证驱动」与第六篇《RLVR》一脉相承，与《大模型原理》的「推理」篇互为表里。
