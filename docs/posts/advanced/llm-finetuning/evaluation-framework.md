## 为什么从评估体系开始

本专题的最后一篇，回答微调后最关键的问题：**「微调到底有没有让模型变好？」** 这个问题的答案不在训练日志里，而在**评估**里。评估是微调的「裁判」——没有它，你的「微调成功」只是「自我感觉良好」。

评估之所以需要「体系」，是因为**微调的效果是三维的**：**能力**（会不会做事）、**对齐**（听不听话）、**安全**（守不守规矩）。只测一维会被另外两维的退化骗过去——模型能力涨了但变不安全了，不能算「变好」。本节先把「三维评估」的总框架立起来，后续八节逐个拆解。<span class="marginnote">一句话定位：<strong>微调评估 = 能力 × 对齐 × 安全的三维体检</strong>。它贯穿本专题的每一篇——SFT 要看能力、RLHF 要看对齐、领域微调要看安全——评估是检验「微调做了什么」的唯一客观手段。</span>

## 1 为什么评估必须是「三维」的

微调的每个阶段都可能「一维变好、另一维变差」：

- **SFT 能力涨了，但对齐没训**——模型会做事，但不听话、不拒绝；
- **RLHF 对齐涨了，但能力可能塌了**——模型变听话了，但「为了讨好奖励」丢了通用能力（能力坍塌）；
- **领域微调知识涨了，但安全没守**——医疗模型会答医疗题了，但也敢乱开药了。

**只测一维的盲区**：

| 只测… | 会漏掉… |
| --- | --- |
| 能力（MMLU） | 对齐、安全退化 |
| 对齐（MT-Bench） | 能力下降、安全漏洞 |
| 安全（越狱） | 能力、对齐问题 |

**三维评估的意义**：它把「微调变好」的判据从「一维涨」变成「三维都得守住」——**能力涨、对齐稳、安全不破，才算微调成功**。这正呼应领域微调方法论里的「三层评测基线」（第七篇），只是把「领域/通用/规范」抽象成「能力/对齐/安全」的总框架。

## 2 维度一：能力（Capability）——「会不会做事」

**能力维度**评估模型「会不会做事」——知识、推理、生成质量。典型基准：

- **知识**：MMLU（多任务知识）、C-Eval（中文知识）；
- **推理**：GSM8K（数学）、HumanEval（代码）；
- **生成**：对话质量、摘要质量。

**能力评估的关键原则**：

- **与「微调前」对比**：只报绝对分数、不报相对提升，等于没测——**「微调前 vs 微调后」的能力差才是微调的真实效果**；
- **覆盖「会退化」的能力**：微调最常带走的能力是「通用知识与长尾能力」——MMLU 等「通用基准」必须进能力评估，专门盯「有没有退化」；
- **同口径**：同一套基准、同一个解码配置（温度、采样）——口径不一致，对比就是错的。

## 3 维度二：对齐（Alignment）——「听不听话」

**对齐维度**评估模型「听不听话」——能否遵循指令、是否符合人类偏好。典型手段：

- **指令遵循**：IFEval、FollowBench——「让模型按格式/约束做事，做对没有」；
- **偏好质量**：MT-Bench、AlpacaEval——「回答是否更被人类/LLM 偏好」；
- **对话体验**：多轮一致性、角色保持。

**对齐评估的关键原则**：

- **「对齐」不等于「能力」**：模型会做题（能力）≠ 会按指令的约束做（对齐）——**对齐测的是「遵循」而非「会不会」**；
- **评估者本身要校准**：MT-Bench/AlpacaEval 用 LLM 当裁判（LLM-as-Judge）——**裁判的偏差会污染结果**（《对齐质量评估》一节专讲）；
- **对齐是「软指标」**：不像能力有客观答案，对齐质量带主观性——**要多维、多样本、多次评估取稳定结论**。

## 4 公式解析：三维评估的「验收公式」

把三维评估收成一个「验收公式」，微调是否成功的判据就清晰了：

$$
\text{微调成功} \iff \underbrace{\Delta_{\text{能力}} \ge 0}_{\text{能力不跌或涨}} \;\wedge\; \underbrace{\Delta_{\text{对齐}} \ge 0}_{\text{对齐不跌或涨}} \;\wedge\; \underbrace{\Delta_{\text{安全}} \ge 0}_{\text{安全不跌或涨}}
$$

逐项拆解：

- $\Delta_{\text{能力}} = \text{微调后能力分} - \text{微调前能力分}$：能力变化；
- $\Delta_{\text{对齐}}$、$\Delta_{\text{安全}}$：对齐与安全的变化；
- $\wedge$：**三个变化都得 ≥ 0**——任何一个为负，都说明「微调在某维上退步了」；
- 注意是「≥ 0」不是「> 0」：**「守住不跌」也是成功**——很多微调的目标是「某维提升，其他维不损」。

**这个公式的价值**：它把「微调成功」从「感觉」变成「可判定的条件」——**三个维度都有数值、都对比微调前**，缺一个维度，公式就不成立、验收就不完整。<span class="marginnote">「三维都 ≥ 0」是「及格线」，不是「优秀线」。对「领域微调」这类「明确要某维涨」的场景，还要加一条「目标维 > 0」（领域能力显著提升）；对「对齐微调」，「安全维 > 0」尤其重要——<strong>对齐微调把安全训坏了，是最讽刺也最危险的失败</strong>。</span>

## 5 建立自己的评估体系：一个可操作的流程

把三维评估落成「可操作」的流程，四步：

1. **定维度**：按微调目标定「哪维是主、哪维要守」——能力主攻、对齐要稳、安全必须守；
2. **选基准**：每维选 1–2 个基准——能力（MMLU + 领域基准）、对齐（IFEval + MT-Bench）、安全（越狱 + 毒性）；
3. **建基线**：**微调前先测一遍**「基线的三维分数」——没有基线，后面的「变化量」无从谈起；
4. **跑评估**：每次微调迭代都跑同一套三维评估，记录对比——**让「三维分」成为每次实验的「体检报告」**。

**评估体系的终极目标**：让「微调效果」变成「可追踪的数字」——**每次实验跑完，三维分一摆，好不好一目了然**。这也正是训练流水线工程化（第八篇）里「评估与记录」环节的内容。

一个最小「三维评估」的骨架，能把「评估是常态」落地：

```python
def run_eval(model, baseline):
    # 把基准按维度归类：能力 / 对齐 / 安全
    benches = {
        "能力": ["MMLU", "GSM8K"],
        "对齐": ["IFEval", "MT-Bench"],
        "安全": ["越狱", "毒性"],
    }
    scores = {dim: {b: run_bench(b, model) for b in bs} for dim, bs in benches.items()}
    deltas = {dim: {b: scores[dim][b] - baseline[dim][b] for b in bs}
              for dim, bs in benches.items()}
    return deltas   # 三维变化量表：每维与微调前对比
```

注意第 3 行的 **dict 结构**——**评估体系的第一步是「把基准按维度归类」**：能力 / 对齐 / 安全各一栏，跑完输出「三维变化量表」。**把这个函数做成「每次实验必跑」的例行步骤**，微调的「好不好」就不再是感觉，而是数字。## 6 小结

- **微调评估三维**：能力（会不会做事）、对齐（听不听话）、安全（守不守规矩）——缺一维就会被其他维的退化骗过去。
- **能力维**：MMLU/C-Eval（知识）、GSM8K/HumanEval（推理）——必须与微调前对比、盯通用能力退化。
- **对齐维**：IFEval（指令遵循）、MT-Bench/AlpacaEval（偏好质量）——测「遵循」而非「会不会」，注意裁判偏差。
- **安全维**：越狱、毒性——对齐微调把安全训坏是最危险的失败。
- **验收公式**：$\Delta_{\text{能力}} \ge 0 \wedge \Delta_{\text{对齐}} \ge 0 \wedge \Delta_{\text{安全}} \ge 0$——三维都得「不跌或涨」。
- **四步建立体系**：定维度 → 选基准 → 建基线（微调前先测）→ 每次迭代跑同一套评估。
