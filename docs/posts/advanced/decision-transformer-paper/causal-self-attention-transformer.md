## 为什么从注意力开始

前两篇已经把轨迹翻译成了 (return-to-go, 状态, 动作) 的 token 序列，也把 return-to-go 定位成了「遥控器」。但序列本身不会自己产生动作——是**模型**在完成「条件 → 动作」的映射。这篇讲模型本体：GPT 式的因果自注意力 Transformer。我们会拿下两件数学工具——缩放点积注意力与因果掩码——再看 DT 如何为三种 token 定制嵌入，以及「在 3K 个 token 里建立长程依赖」这件事为什么对决策至关重要。

## 1 GPT 式自回归 Transformer

DT 复用了与 GPT 几乎一致的架构：多层堆叠的**自注意力**（self-attention）加**前馈网络**，逐层处理 token 序列，输出每个位置的表示。它叫「自回归」（autoregressive）是因为：每一层都对「序列中靠前的位置」做有向的信息聚合，训练时用掩码让每个位置只能看到自己及左侧——与语言模型的「预测下一个词」完全同构，只是这里预测的是「下一个动作」。

DT 对 GPT 只做了一处结构性的改动：**位置编码**。标准 GPT 对每个 token 加一个位置嵌入；DT 因为「一个时间步 = 三个 token」，改用**按时间步学习的嵌入**——同一时间步的三个 token（$\hat{R}_t, s_t, a_t$）共享同一个时间步嵌入。<span class="marginnote">论文的表述是「不为 return-to-go 与状态加逐 token 位置编码」。原因是三步一组的结构里，逐 token 位置编码会模糊「三个 token 同属一个时间步」的分组信息；按时间步共享嵌入，则让模型一眼看出「哪些 token 属于同一个时刻」。官方实现里用一个学习到的 timestep embedding 加在每种嵌入上，效果等价。</span>

另一个值得一问的问题是：**为什么选自回归（GPT 式单向），而不是双向（BERT 式）？** 语言建模里 BERT 的双向编码在理解任务上更占优，但决策是严格因果的——预测 $a_t$ 时，$a_{t+1}$、$s_{t+1}$ 都还没有发生，让模型「偷看」未来只会让它在训练时学到作弊式的捷径、部署时彻底失灵。自回归的单向结构把「因果」焊死在架构里：**模型被物理上禁止看到未来，这本身就是一种归纳偏置，而且是一种正确的归纳偏置。** 序列建模 RL 后来几乎无一例外沿用这个选择，正是因为「决策必须因果」是这个领域不可退让的铁律。

## 2 三种嵌入与统一表示

上一节我们见过三种 token 各自的嵌入层，这里把它们汇总成「统一投影」的完整图景：

- **return-to-go 嵌入**：$\hat{R}_t \in \mathbb{R}$（连续标量）→ 线性层 → $d$ 维向量；
- **状态嵌入**：$s_t \in \mathbb{R}^{n}$（如 MuJoCo 的 17 维关节向量）→ 线性层 → $d$ 维向量（图像状态则用卷积编码器）；
- **动作嵌入**：连续动作 → 线性层；离散动作 → embedding 表；
- **时间步嵌入**：$t$ → 学习到的向量，加在同一时间步的三个 token 上。

于是三种类型的输入在同一个 $d$ 维空间里排成一串 $3K-1$ 个向量（最后一步缺动作），交给 Transformer。整条信息通路可以写成：

$$
\text{输入向量序列} = \big[\text{emb}(\hat{R}_{t-K+1}) + \text{emb}(t{-}K{+}1),\; \text{emb}(s_{t-K+1}) + \text{emb}(t{-}K{+}1),\; \dots \big]
$$

**重点：三种嵌入 + 时间步嵌入，是「多模态」的第一次落地。** 它把「目标、观测、行为」三种语义统一进一个向量空间，让注意力可以在它们之间自由求相关性——这正是序列建模能在决策上成立的前提。<span class="marginnote">这与第四级《大模型原理》里多模态模型「各模态独立投影 + 共享注意力空间」的设计同构。DT 的三种 token 本质上就是「决策域的多模态」，早于后来很多多模态大模型提出。</span>

嵌入维度 $d=128$ 的选择也值得一句点评：对 MuJoCo 这种状态只有 17 维、动作只有 3 维的低维控制问题，128 维的表示空间可以说是「杀鸡用牛刀」——但也正因如此，return-to-go 目标、状态、动作这三种本无共同刻度的信息，才能在同一个空间里被自由地比较与组合。**维度过小会挤掉三种模态的区分度，过大则浪费算力，128 是论文调出来的甜点区间**，后续大量工作沿用未改。

## 3 公式解析：缩放点积注意力与因果掩码

单头自注意力的核心公式：

$$
\text{Attention}(Q, K, V) = \mathrm{softmax}\!\left( \frac{QK^\top}{\sqrt{d_k}} + M \right) V
$$

- **第一步，认三件套**：$Q$（查询）、$K$（键）、$V$（值）都由输入序列经三个不同的线性投影得到，维度 $d_k$；$QK^\top$ 度量「每个位置该以多大权重去读其他位置」。
- **第二步，认缩放**：除以 $\sqrt{d_k}$ 防止点积随维度增大而爆炸，保持 softmax 的梯度稳定——这是《Attention Is All You Need》的原始设计。
- **第三步，认因果掩码 $M$**：$M$ 是一个加性掩码矩阵，规则是
$$
M_{ij} = \begin{cases} 0, & i \ge j \\ -\infty, & i < j \end{cases}
$$
  $i$ 是查询位置（行），$j$ 是键位置（列）。当 $j > i$（未来位置）时 $M_{ij} = -\infty$，进 softmax 后 $\exp(-\infty) = 0$——**未来 token 的注意力权重被精确清零**。
- **第四步，认结果**：输出是 $V$ 的加权和，每个位置只从「自己及左侧」的历史中收集信息，右侧一概不可见。下三角即「可注意区」，上三角即「屏蔽区」。

![因果注意力掩码](/images/decision-transformer-paper/causal-self-attention-transformer-1.svg)

图中 5×5 的表格，行是查询位置 $i$、列是键位置 $j$：青色下三角（$i \ge j$）允许注意，灰色上三角（$i < j$）被屏蔽。预测 $a_t$ 时，位置 $i$ 就是「当前状态」所在的位置，它能看到自己的左侧——包括远在 $t-K+1$ 的高回报轨迹开头，以及同时间步的 return-to-go $\hat{R}_t$。

**辨析｜易错点：** 这里有一个非常容易误读的细节。因果掩码保证模型**看不到未来的动作与状态**，但输入里明明有 $\hat{R}_t$——它可是「未来回报的和」！这两者矛盾吗？不矛盾：$\hat{R}_t$ 不是模型「偷看」到的，而是用户**主动塞进来当目标**的条件。因果掩码约束的是「模型内部的信息流动方向」，return-to-go 是「外部注入的目标」，两者作用在不同层面。把「条件的未来信息」误当「模型的未来泄漏」，是理解 DT 时最经典的误区。<span class="marginnote">换个说法：如果模型在预测 $a_t$ 时能看到 $a_{t+1}$，那是泄漏；看到用户指定的「总预算 $\hat{R}_t$」，那是目标。掩码只管前者。</span>

从计算复杂度的角度再看一眼掩码：注意力矩阵是 $3K \times 3K$ 的，因果掩码把它变成下三角——复杂度仍是 $O(K^2)$，但掩码把「哪些位置需要计算」的语义直接写进结构：训练时一次性并行算出所有位置（教师强制 teacher forcing），推断时逐个位置自回归生成。这种「训练并行、推断自回归」的二分法，正是 GPT 生态的核心工程节奏，DT 原样继承。<span class="marginnote">教师强制是语言模型训练的标准技巧：训练时把真实 token 喂进去、一次性算出所有位置的损失，而不是像推断那样逐字生成。DT 训练时把真实的动作序列放进上下文，模型被要求「看着正确答案练」，效率比在线探索高出一个数量级。</span>

## 4 依赖链：模型如何「记住」条件

自注意力的价值在于**任意长程依赖**：在 $3K$ 个 token 之间，任何两处都能直接建立相关性，不需要像 RNN 那样逐步传递。对 DT 而言，这意味着：

当前状态 $s_t$ 可以直接「检索」到 $t-K+1$ 处那段高回报轨迹的上下文，而不是把信息压进一个固定大小的隐状态；
- 当前 return-to-go $\hat{R}_t$ 的信息可以沿序列传播，持续「指挥」后续每一个动作的生成；
- 同一个注意力头可以学习「什么历史与什么行为相关」，例如「曾经在类似状态下拿到过高回报的那段前缀」。

**重点：条件不是被「加一次就忘掉」，而是通过注意力在每个时间步都被重新读取。** 这解释了为什么 $K$ 大通常更有帮助：更长历史的「记忆检索」天然契合 Transformer 的结构优势。也解释了为什么随机环境下 $K$ 过大反而有害（第 2 篇）：注意力会忠实检索到「不可复现的运气」，把噪声也纳入条件。

多头与多层各管什么事？直觉上，**多头负责「分工」**——8 个注意力头各自学一类相关性：有的头专门盯「return-to-go 到状态」的匹配，有的头盯「同类状态的历史行为」，有的头盯「动作之间的连贯性」，多头把它们的结果拼在一起，等于同时从多个角度检索条件；**多层负责「抽象」**——浅层处理局部、具体的 token 关系，深层把「目标-历史-行为」的语义抽象成更高层的决策上下文。这种「分工 + 抽象」的分工模式，与语言模型里多头多层扮演的角色完全一致：把条件建模成「在多个粒度上反复阅读」，比任何手工设计的特征都更省心。

这也引出一个常常被低估的观察：**DT 并没有为「强化学习」发明任何新的注意力机制。** 掩码是现成的、缩放是现成的、多头多层是现成的，唯一的「RL 定制件」只是三种嵌入、时间步嵌入与动作头。真正的新意不在网络结构，而在「把 RL 目标翻译成序列建模目标」这一步翻译本身——结构越通用，翻译的价值越凸显。这篇论文与其说发明了一个模型，不如说示范了一种「借用成熟序列模型解决决策问题」的姿势。

## 5 工程细节：规模、训练与损失头

论文使用了一套精炼的默认配置（MuJoCo 与 Atari 略有差异）：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 层数 | 6 | 自注意力 + 前馈的堆叠层数 |
| 注意力头数 | 8 | 多头并行 |
| 嵌入 / 注意力维 | 128 | $d_k = 128$ |
| 前馈维 | 512 | 每个 FFN 的中间宽度 |
| 激活 | GeLU | GPT 同款非线性 |
| dropout | 0.1 | 正则化 |
| 优化器 | AdamW | 权重衰减，梯度裁剪 1.0 |
| 学习率 | MuJoCo 1e-4 / Atari 6e-4 | 线性 warmup 10k 步 |
| batch size | 128 | 每次更新取 128 条轨迹片段 |
| 训练步数 | 约 500k 步 | MuJoCo 上的梯度步数 |

输出侧有一个 **动作头**：一个小的 MLP 把最后一个位置（$s_t$ 处）的表示映射为动作。连续动作用线性输出 + 均方误差损失 $\lVert \hat{a}_t - a_t \rVert^2$；离散动作用 softmax + 交叉熵。<span class="marginnote">损失头选择决定「这个 Transformer 被训练成回归器还是分类器」，但对主干架构没有影响。DT 的代码与 GPT 开源实现几乎只差一个动作头和一个时间步嵌入——这就是「复用大模型技术栈」的又一证据。</span>

几个超参数之间的权衡值得一提。dropout 0.1 防过拟合——轨迹数据里轨迹数量有限，网络很容易背下训练集；GeLU 是 GPT 同款非线性，相比 ReLU 在负区间的平滑性让梯度更温和；梯度裁剪 1.0 则专门防「个别异常 token 把梯度带飞」。这些都不是 DT 的独创，而是「从 GPT 生态继承的成熟默认值」——**论文的工程哲学是：不在已被验证过的零件上做多余的发明。** 这也是它能用极少的超参数获得稳定表现的原因之一。

## 6 小结

- DT 用 **GPT 式因果 Transformer**：自回归、多层自注意力 + 前馈，与语言模型同构，只是预测目标换成动作。
- 三套嵌入（return-to-go、状态、动作）+ **按时间步共享的位置嵌入**，把决策序列统一进一个向量空间。
- 核心数学是**缩放点积注意力** $\mathrm{softmax}(QK^\top / \sqrt{d_k} + M)V$，因果掩码 $M_{ij} = 0\ (i\ge j), -\infty\ (i<j)$ 保证「只看过去」。
- 掩码屏蔽的是「模型内部流向未来的信息」，而 return-to-go 是「外部注入的目标」——**不要把它误当未来泄漏**。
- 注意力提供任意长程依赖：当前状态可以直接检索 $K$ 步前的历史，条件在每个时间步都被重新读取。
- 工程配置简单：6 层、8 头、128 维、GeLU、AdamW；动作头按连续/离散选择 MSE 或交叉熵。
- 多头负责「分工」、多层负责「抽象」，条件在多个粒度上被反复读取；dropout、梯度裁剪等默认值全部继承自 GPT 生态。
- 训练用教师强制并行计算、推断逐位置自回归——沿用 GPT 的「训练并行、推断自回归」节奏。
- DT 没有为 RL 发明任何新的注意力机制，新意全在「把 RL 目标翻译成序列建模目标」这一步。
