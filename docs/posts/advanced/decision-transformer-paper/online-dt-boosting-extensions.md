## 为什么从扩展开始

DT 在离线基准上证明了「序列建模做 RL」不是花架子，但它的三条边界（第 7 篇）也在等着被补：离线数据质量再好也是「过去」，策略终归要面对**在线**的世界。Levine 的离线 RL 综述（Offline Reinforcement Learning: Tutorial and Review）第 5 节点出了这条主线：离线训练只是前半场，**离线 → 在线微调**才是把算法真正用起来的最后一公里。这篇讲三条支线：Online Decision Transformer 怎么把 DT 带进在线世界，QDT/ACT 怎么用动态规划给 DT「续命」，以及 Trajectory Transformer、Gato 怎么把序列建模 RL 推向更广的版图。

## 1 Levine §5 的视角：离线训练的瓶颈与在线微调

综述第 5 节的诊断很直接：**离线策略的最终性能，被数据集钉死。** 无论算法多强，它都无法超越数据能提供的信息——这就是第 7 篇那张「上限不等式」的另一种表述。所以「离线训练 + 在线微调」成为标准配方：

1. 先在离线数据集上把策略预训练到一个可用水平；
2. 部署后与真实环境交互，把新经验写回回放缓冲；
3. 用「离线旧数据 + 在线新数据」混合继续训练，逐步逼近真最优。

但这一步藏着两个陷阱：

- **Q 类方法在线微调易崩**：离线时辛苦压住的「自举高估」一旦遇到在线新数据，`max` 又活了，误差卷土重来——需要额外的保守微调策略；
- **过保守的方法又太怂**：离策略时不敢探索，上线后依然不敢越数据半步，学不到新东西。

**重点：DT 恰好是这条主线的「友好型」选手。** 它的监督学习目标没有自举可崩，在线微调 = 继续在混合数据上做最大似然，天然稳定。这个「稳定」的资产，在在线阶段被成倍兑现。<span class="marginnote">综述还点出另一个细节：离线预训练本身就可能「过拟合数据集分布」，上线后需要足够多样的在线探索来校正。DT 家族解决探索的方式不是 ε-贪心，而是「条件」——换一个 return-to-go 就是换一种探索风格。</span>

离线 → 在线也不是「接着训练」一种姿势，Levine §5 区分了三档：**离线直接部署**（最省事，但性能被数据钉死）、**离线 + 少量在线交互微调**（最常见，微调数个 epoch 就能明显提升）、以及**离线预训练 + 持续在线学习**（数据不断扩充、策略持续适应）。选哪档取决于「上线成本」：仿真里可以无限交互，真实系统（机器人、医疗）每步交互都昂贵，数据稀缺时「离线学好 → 在线微调」几乎是唯一现实路径。

「naive 直接上线」的翻车三连也值得写下来当警示：Q 类方法直接上线 → 自举高估爆炸、策略漂移失控；过保守方法直接上线 → 数据外不敢动、性能原地踏步；纯监督方法直接上线 → 不会崩，但探索不足、学得慢。ODT 的熵正则与 hindsight relabeling，正是针对第三种失败模式的补药。

## 2 Online Decision Transformer（Zheng 等，ICML 2022）

Zheng、Zhang、Grover 的 **ODT（Online Decision Transformer）** 把 DT 正式推进到「离线预训练 + 在线微调」的统一框架，四个关键机制：

**回放缓冲用 top-N 初始化**：微调开始时，回放缓冲不是随机装离线数据，而是**先装离线数据里回报最高的 N 条轨迹**——把「好榜样」直接喂给后续微调；
- **序列级熵正则**：在监督目标上叠加熵正则项，促进在线探索、避免过早坍缩到已有行为；
- **hindsight relabeling（事后重标注）**：在线收集到低回报轨迹后，用事后观测到的实际回报重新标注条件，让数据里的 (目标, 行为) 配对更丰富；
- **模型预测回报指导探索**：用已收集数据学一个世界模型，预测「未来状态的回报」，据此**选择更合理的 return-to-go 作为探索目标**——探索本身也被条件化了。<span class="marginnote">最后这一点很有意思：它等于把「目标该设多少」这个开放问题（第 7 篇局限三）部分外包给了世界模型——用模型滚动预测来挑一个值得追逐的回报目标。这也是「模型规划 + 条件生成」合流的典型。</span>

ODT 在 D4RL 上的结果是：**离线阶段与强基线相当，在线微调阶段取得显著增益**——补上了 DT「被数据封顶」的最大一块短板。

ODT 的消融实验还有两个值得注意的结论。其一，**回放缓冲用 top-N 高回报轨迹初始化，比随机初始化显著更好**——微调阶段最怕被平庸样本带偏，先喂好榜样能让策略「站在巨人肩膀上」继续学；其二，**较短的上下文（$K=1$）在在线微调时反而比长上下文（$K=5$）更稳**——在线数据更新快，长上下文让模型执着于旧记忆，反而是「只看当前 (目标, 状态)」的极简条件更容易被新数据改写。这两条都说明：**在线阶段的「记忆策略」与离线阶段并不相同，需要单独调。**

ODT 还有一个优雅的细节：**探索与利用被拆成两把「遥控器」。** 在线部署时，评估用「高一点的 return-to-go」（想要更多），探索用「低一点的 return-to-go」（出去看看再回来），两者共用一个模型、只是条件不同。这个设计把「探索策略怎么定」也收敛进了条件框架——你不再需要为探索单独设计 ε 衰减表或熵奖励，换一个条件值就是换一种行为模式。DT 的「条件即策略族」，在在线世界里第一次显出了实用价值。

## 3 公式解析：在线微调的目标

ODT 的监督目标在 DT 的似然上叠加了熵正则：

$$
\max_\theta \; \mathbb{E}_{\mathcal{B}}\Big[ \sum_{t} \log \pi_\theta(a_t \mid \hat{R}_t, s_t, \text{前缀}) \Big] + \beta \sum_{t} \mathbb{E}\big[ H\big(\pi_\theta(\cdot \mid \hat{R}_t, s_t, \text{前缀})\big) \big]
$$

- **第一步，认第一项**：与离线 DT 完全相同的条件似然——只是求期望的分布从「离线数据集」换成了「回放缓冲 $\mathcal{B}$」，即离线旧数据 + 在线新数据的混合。模型在两种分布上做最大似然。
- **第二步，认第二项**：熵 $H(\pi_\theta)$ 度量策略的随机性；加这项是鼓励模型「在没见过的情况下多试几条路」，防止在线阶段过早坍缩——这正是 Q 类方法需要复杂保守机制去做的「探索」，在监督目标里只是一项简单的正则。
- **第三步，读 $\beta$**：熵正则系数平衡「复用已知」与「探索未知」：离线预训练阶段 $\beta$ 小（专心拟合数据），在线阶段 $\beta$ 大（放开探索）。一个旋钮完成离线到在线的切换。
- **第四步，对照 Q-learning 的在线微调**：Q 类方法在线微调要处理「自举误差复活」，需要目标网络、保守项、早停等一堆工程；ODT 的整个目标就是「混合数据上的（正则化）最大似然」，**没有一项需要动态规划**。

hindsight relabeling 值得再拆一句：在线探索时智能体常常「想去 A 却走到 B」，按目标 A 标注这批数据就是负样本噪声；hindsight relabeling 干脆把它改成「想去 B 就走到 B」，把一次失败重写成「成功达成 B」的训练对。这是目标条件化 RL 的老技巧（与 GCSL 的 relabeling 一脉相承，见第 3 篇的血统梳理），ODT 把它搬进在线 DT 的管线：既缓解了稀疏奖励，也让低回报轨迹重新变成有信息量的样本。

$\beta$ 的取值直接左右在线微调的节奏：太小，模型迅速坍缩到离线学到的行为、探索不足；太大，模型变成随机游走、连已学好的好行为都忘了。实践中常把 $\beta$ 设计成随在线步数衰减的曲线——早期大步探索、后期收敛到已学行为——思路与 ε-greedy 的衰减神似，但在监督目标里实现起来干净得多：只是一个标量系数，不涉及任何值函数。

## 4 提升 DT 的更多方向

除了在线微调，「给 DT 补上动态规划能力」是另一条热闹的支线——它们都在回应第 7 篇的三条边界：

| 工作 | 核心思想 | 补的是哪条边界 |
| --- | --- | --- |
| **QDT**（Yamagata 等 2023） | 用学好的 Q 函数**重标注数据里的 return-to-go**，再训练 DT | 无拼接能力 |
| **ACT**（Gao 等 2024） | 用 **advantage 替代 return-to-go 作条件**，拆开策略与随机性 | 随机环境盲目乐观 |
| **Decision Diffuser / 扩散策略** | 把动作生成换成**扩散模型**，条件在回报/约束上 | 表达力与多样性 |
| **Decision Convformer** 等 | 换主干架构，降低计算成本 | 工程效率 |

**重点：这些工作的共同信号是——「序列建模」与「动态规划」从对手变成了搭档。** QDT 让 DT「借用」Q 值的拼接能力，ACT 让条件脱离「未来回报和」的依赖——序列建模负责稳定与生成，动态规划负责指导与提升。<span class="marginnote">这条合流趋势也印证了第 6 篇的结论：两条路线是互补而非互斥。今天看 DT 的后续生态，几乎每个方向都在做「序列建模 + 一点 DP」的联姻。</span>

两个方向的细节各补一句。QDT 的思路是「先离线学一个 Q 函数，再用 Q 值给数据里的 return-to-go 重打标签，最后训练 DT」——它训练的仍然是序列模型，只是条件从「原始累计和」换成了「动态规划后的价值」，等于给 DT 装上了拼接引擎；ACT 则把条件从单点 return-to-go 换成 advantage（优势函数），advantage 天然「扣掉了基线」，环境的运气被基线削掉，盲目乐观随之缓解。至于 Decision Diffuser 等扩散策略，它们把「生成动作」这个内核从 Transformer 换成扩散模型，牺牲速度换更精细的轨迹建模——这是「条件生成」框架下换引擎的又一实例。

把这些补丁工作统观起来，可以给「Boosting」一个准确的含义：**它不是在某一个数据集上把 DT 的分数刷高，而是系统性地把 DT 的三条结构短板一件件拆掉**——拼接短板交给 Q 值，随机性短板交给 advantage，目标设定短板交给世界模型。每一次修补都保留了「条件生成」这个内核，换的只是条件的来源与形式。到这一步，DT 已经从「一个算法」变成了「一个可插拔的条件生成框架」。

## 5 序列建模 RL 家族：Trajectory Transformer、RvS 与 Gato

把视野再拉远，DT 不是孤例，而是一个家族的代表：

**Trajectory Transformer**（Janner 等 2021）：比 DT 更早把整条轨迹当序列建模——它把状态、动作离散化为 token，对整个轨迹分布建模，推断时用**束搜索（beam search）规划**。DT 精简了它：去掉显式规划，直接用条件生成。**DT 是它的「减配 + 提速」版。**
- **RvS**（Emmons 等 2022）：比 DT 更极端地做减法——不条件于 return-to-go，只条件于目标（goal）或一个固定回报，证明「条件化监督学习」的核心价值在「条件」而不在「序列」。
- **Gato**（Reed 等 2022）：把 DT 配方推广到极限——一个模型、604 个任务、输出覆盖文本 / 图像 / 动作，条件不只是回报，还可以是文本指令与图像目标。**它把 DT 的「条件即遥控器」发挥成了「通用智能体说明书」。**<span class="marginnote">Gato 的意义在「规模」：证明 DT 式的「决策 = 条件生成」配方可以随模型规模与数据规模一起成长，这正是「从极限到大模型」这条主线在决策域的回响——大模型不只是会聊天，还能「会做事」。</span>

这一族的共同信条：**把决策问题翻译成条件生成问题，剩下的交给规模。** 它们是本专题与第四级《大模型原理》、以及「多模态大模型 → 具身智能」路线之间的桥梁。

把四个成员排成一行看，序列建模 RL 的版图就清晰了：**Trajectory Transformer 代表「显式规划」**（束搜索在模型内部搜索最优轨迹）、**DT 代表「隐式条件」**（用 return-to-go 当遥控器）、**RvS 代表「极简条件」**（目标或固定回报即可）、**Gato 代表「规模通才」**（一个模型通吃多任务多模态）。有意思的是，四条支线的训练目标几乎都是条件似然——差别只在「条件长什么样」与「要不要显式搜索」。**条件的形式，就是这一家族的分水岭。**

应用侧也值得瞥一眼：DT 的「条件生成」框架在机器人操控（用目标图像或语言指令当条件）、推荐系统（用回报预算当条件）、乃至游戏 AI（用胜率目标当条件）里都有落地尝试。这些应用的共性仍是那句话——**把「想要什么」翻译成条件，让模型去生成「怎么做」。** 框架的通用性，正是它从 2021 年一篇论文长成「决策序列建模」这一研究方向的最大底气。

## 6 小结

- Levine §5 的主线：离线性能被数据集封顶，**离线预训练 + 在线微调**是最后一公里；Q 类方法在线易崩、过保守方法又太怂。
- **ODT** 把 DT 带进在线世界：top-N 回放缓冲、序列级熵正则、hindsight relabeling、模型预测回报指导探索，在线阶段增益显著。
- 在线微调的目标 = 混合数据上的（正则化）条件似然，**全程无需动态规划**。
- QDT、ACT 等证明：**序列建模与动态规划从对手变搭档**，分别补上拼接与随机环境两条边界。
- 家族全景：Trajectory Transformer（束搜索规划）、RvS（极简条件）、Gato（多任务多模态通才）。
- 离线 → 在线有三档（直接部署 / 短微调 / 持续学习）；Q 类上线易崩、过保守上线太怂、监督方法上线学得慢。
- ODT 消融：top-N 回放初始化显著更好；在线微调时短上下文（$K=1$）反而比长上下文稳。
- hindsight relabeling 把「失败」重写成「成功达成目标」的训练对，是目标条件化 RL 的老技巧。
- 四条支线的分水岭在「条件长什么样」与「要不要显式搜索」，训练目标几乎都是条件似然。
- Boosting 的本质：把拼接、随机性、目标设定三条短板各交给 Q 值 / advantage / 世界模型，条件生成内核不变。
- 应用侧：机器人操控（目标图像/语言当条件）、推荐（回报预算当条件）、游戏 AI（胜率目标当条件）都在用「想要什么 → 条件」的通用配方。
- 一以贯之的信条：**把决策翻译成条件生成，剩下的交给规模。**
- 回到本专题的开篇：DT 最珍贵的遗产不是某一个分数，而是它示范的「借用成熟序列模型解决决策问题」这一整套姿势——它把 RL 第一次真正放到了大模型的生态里。
- 综述 §5 与 ODT 共同给出的路线图：离线学好 → 在线微调 → 世界模型选目标 → 动态规划补条件，这条流水线至今仍是「序列建模 RL」的主干。
