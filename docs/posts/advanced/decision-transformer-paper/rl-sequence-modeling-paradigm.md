## 为什么从序列建模开始

在第三级《强化学习》里，我们学到的一切几乎都围绕一个核心对象——**值函数**。无论是基于策略还是基于值的方法，引擎都是 **Bellman 方程** 与 **时序差分（TD）误差**：用「当前估计 + 一步真实回报 + 对未来的估计」去更新当前估计。这套引擎强大，但也有它著名的副作用——当函数逼近、自举、离策略三者叠加时，训练可能不稳定甚至发散，萨顿称之为「致命三角」。

2021 年，Chen 等人的论文《Decision Transformer: Reinforcement Learning via Sequence Modeling》提出了一个近乎「反着来」的问题：**如果决策过程本身可以被写成一段序列，那么能不能绕开值函数，直接用大模型的序列建模能力来生成动作？** 这篇论文不是把 Transformer 塞进强化学习当函数逼近器，而是把强化学习本身重写成了序列建模——这就是本专题要讲的第一次「范式翻译」。它和我们读过的 GPT（第四级《大模型原理》）共用同一套自回归语言模型的技术栈，因此理解它的成本被大大降低了。

## 1 传统强化学习的运转方式

先回顾标准设定。一个 **马尔可夫决策过程（MDP）**：状态集 $S$、动作集 $A$、转移概率 $p(s', r \mid s, a)$、折扣因子 $\gamma$。策略 $\pi(a \mid s)$ 描述智能体在每个状态下选动作的分布，学习目标是最大化期望折扣回报 $G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$。

几乎所有经典方法都落脚到两个对象：

- **值函数**：$V^\pi(s) = \mathbb{E}_\pi[G_t \mid S_t = s]$，$Q^\pi(s, a)$ 只是再多条件一个动作；
- **Bellman 方程 / Bellman 最优方程**：把一个状态的值写成「当前奖励 + 未来值的期望」，例如

$$
V^\pi(s) = \sum_a \pi(a \mid s) \sum_{s',r} p(s', r \mid s, a) \big[ r + \gamma V^\pi(s') \big]
$$

**时序差分（TD）学习**用「采样一步」来逼近这个方程：

$$
V(S_t) \leftarrow V(S_t) + \alpha \big[ R_{t+1} + \gamma V(S_{t+1}) - V(S_t) \big]
$$

更新里既用了真实单步奖励，也用了对未来的「估计」——**用估计去更新估计，就是自举（bootstrapping）**。<span class="marginnote">萨顿在《强化学习导论》第 11 章明确警告：函数逼近 + 自举 + 离策略学习三者叠加（即致命三角, the deadly triad）会造成不稳定乃至发散。DT 的路线恰好整个绕开这个组合——这是它「简单」的根源，也是本专题反复回扣的点。</span> 这套体系强大，但它把「学习」切成了一个个单步的小更新：每个样本只带来一步的信息增益，还需要目标网络、经验回放、熵正则等一连串工程零件来维稳。

## 2 序列建模：把决策翻译成「预测下一个 token」

现在切换视角。语言建模怎么工作？给定前缀，预测下一个 token，最大化似然。**序列建模（sequence modeling）**：学习一段数据序列的条件分布。只要我们能观察轨迹，轨迹本身就是天然的序列。

于是 DT 做了一个朴素但影响深远的**范式平移**：

**把一条轨迹从「状态、动作、奖励」的原始时间顺序，重排成「(return-to-go, 状态, 动作)」的三元组序列，然后训练一个自回归模型：给定过去与当前的状态，预测下一个动作。**

$$
\tau = \big(\hat{R}_{t-K+1},\, s_{t-K+1},\, a_{t-K+1},\, \dots,\, \hat{R}_t,\, s_t,\, a_t\big)
$$

其中 $\hat{R}_t$ 是 **return-to-go（剩余回报）**，即从 $t$ 时刻到回合结束的累计奖励（下一节讲它的严格定义）。模型不再学「这个状态值多少钱」，而是学「在这个状态、这个目标回报下，该做什么动作」——动作就是序列里的「下一个 token」。

为什么偏偏是 Transformer，而不是曾经统治序列建模的 RNN/LSTM？答案与「记忆的形态」有关。RNN 把历史压进一个固定维度的隐状态，信息沿时间步逐级传递，长距离依赖要靠门控机制小心翼翼地保；Transformer 的自注意力让任意两个位置直接相连，记忆以「检索」的方式存在——对决策序列这正是命脉：当前状态需要随时调用 $K$ 步之前「那一次高回报的走法」。DT 放弃循环结构换来的，正是这种非递推的全局记忆。<span class="marginnote">这也是 2021 年之后「序列建模 RL」普遍倒向 Transformer 而非 LSTM 的直接原因：长上下文里循环结构的遗忘问题几乎无解，而注意力的平方复杂度在 $3K$ 个 token 的尺度上完全可承受——大模型生态的成熟，恰好让这条路线变得便宜。</span>

**重点：DT 的训练完全不需要 Bellman 方程、不需要值函数、更不需要自举。** 它只学一个条件概率分布

$$
\pi_\theta\big(a_t \mid \hat{R}_t,\, s_t,\, (\hat{R}, s, a)_{t-K+1 : t-1}\big)
$$

并用一个监督目标去拟合：最大化观测数据中该轨迹的条件似然（连续动作下等价于最小化动作均方误差）。训练完毕，推断时只要「设定一个想要的回报」，模型就自动生成一串能达成它的动作。

## 3 三种 token：回报、状态、动作

序列里的每个元素不是单词，而是三种不同类型的 **token**：

- **return-to-go token $\hat{R}_t$**：条件信号，告诉模型「从现在开始我还想要多少回报」；
- **状态 token $s_t$**：观测，告诉模型「我现在在哪」；
- **动作 token $a_t$**：要预测的目标。

每个时间步贡献三个 token，因此上下文长度 $K$ 意味着 $3K$ 个 token。这种「三步一组」的节奏，决定了后面的位置编码必须按**时间步**而非按 token 来做——这是论文第 3.2 节的关键设计，我们会在第 4 篇详细展开。

这套「目标 + 现状 + 行为」的三元组，也可以读成一句自然语言的骨架：return-to-go 是「要去的方向」、状态是「所处的位置」、动作是「做出的选择」——序列建模做的，正是在这串骨架之间寻找条件关系。这个类比不是文字游戏：第 8 篇会看到，Gato 把同样的三元组格式推广到文本、图像与动作三种模态，说明「目标-观测-输出」的决策骨架天然就是多模态的通用接口。

与 **行为克隆（behavior cloning, BC）** 对比：BC 学的是 $\pi(a_t \mid s_t)$，纯粹模仿「看到什么状态就做什么动作」，不区分轨迹好坏；DT 学的是 $\pi(a_t \mid \hat{R}_t, s_t, \cdots)$，把「想要多好」作为条件——**条件就是策略的遥控器**。这也是 DT 常被归入「回报条件化监督学习」（return-conditioned supervised learning, RCSL）家族的原因，与 Schmidhuber 的「倒立强化学习」（Upside-Down RL）、目标条件化 RL（GCRL）一脉相承。<span class="marginnote">RCSL 家族把「目标/回报」当条件做监督学习：Schmidhuber 2019 年的 Upside-Down RL、Srivastava 等 2019、Kumar 等 2019 的 GCSL 都是先行者。DT 是这一家族里第一个吃上 Transformer 红利的代表作，也因此在 2021 年引爆了「序列建模 RL」这一支。</span>

## 4 公式解析：条件策略的目标函数

把 DT 的目标函数写完整，逐项拆解：

$$
\mathcal{L}(\theta) = -\sum_{t} \log \pi_\theta\big(a_t \mid \hat{R}_t,\, s_t,\, a_{t-1},\, s_{t-1},\, \hat{R}_{t-1},\, \dots\big)
$$

- **第一步，认符号**：$\theta$ 是 Transformer 的全部参数；$a_t$ 是数据集里真实发生过的动作；条件里依次是当前 return-to-go、当前状态，以及更早的（动作、状态、return-to-go）前缀。
- **第二步，理解因果**：括号内所有条件在时间上都「不晚于」$t$——模型严格按因果顺序使用历史，绝不允许看未来的动作。这是它叫「自回归」的含义。
- **第三步，理解条件中的未来**：$\hat{R}_t$ 是「从 $t$ 到回合结束」的累计回报，它本身包含未来信息——但它是作为用户指定的目标被塞进去的，不是模型偷看到的。**这是条件输入，不是泄漏。**
- **第四步，理解目标**：最大化似然，等价于让模型「在数据中见过的那种 (目标回报, 状态) 组合下，尽量复述当时真实发生的动作」。连续动作时等价于最小化 $\lVert \hat{a}_t - a_t \rVert^2$。

对比值函数路线，这里没有 $\gamma$、没有 $\max$、没有目标网络、没有策略梯度——整个目标就是一个标准的监督学习目标。**这篇论文的工程价值，正在于把强化学习里最不稳定的那些零件全部拆掉了。**

## 5 三种既有范式的对照

把 DT 放进强化学习方法论的坐标里，看它站在哪：

| 范式 | 学什么 | 引擎 | DT 的关系 |
| --- | --- | --- | --- |
| 值函数 / Q-learning | 状态（动作）的价值 | Bellman 方程、自举 | 完全不用 |
| 策略梯度 | 策略参数 | 对期望回报求梯度 | 不用 |
| 行为克隆（BC） | 状态 → 动作映射 | 监督学习 | 加上了「回报条件」 |
| **序列建模（DT）** | 回报、状态条件下的动作分布 | 自回归似然最大化 | 本专题主题 |

**辨析｜易错点：** 不要以为「DT 就是更聪明一点的行为克隆」。BC 对数据里的劣质轨迹一视同仁地模仿；DT 通过 return-to-go 条件**选择**数据里高回报的行为段，这带给了它超越简单模仿的「隐性规划」能力。但同样因为它是「选择」而非「推理」，它无法创造数据里从未出现过的更好行为——这条边界，我们在第 7 篇《序列建模的优势与局限》专门展开。<span class="marginnote">「选择 vs 推理」的边界贯穿全文：动态规划能拼接出新行为（stitching），条件分布只能挑已有行为。这也是 DT 与离线 Q-learning 的胜负手所在。</span>

顺带说一句「DT 这个名字」。它沿用了 Decision Transformer 的缩写，但读者要留意：名字里的「Decision」强调的是「输出动作、做决策」，而它的训练机制其实是**回报条件化的行为生成**——「决策」是它对外服务的接口，「条件生成」是它内部唯一的机制。这组「名与实的错位」，恰恰点出了全文的叙事张力：越简单的东西，越难把它看穿。

## 6 小结

- 传统强化学习以 **Bellman 方程 + TD 自举** 为引擎，可能触发「致命三角」不稳定。
- DT 的范式平移：**把轨迹重排成 (return-to-go, 状态, 动作) 序列，用自回归 Transformer 学条件策略**。
- 核心对象是条件分布 $\pi_\theta(a_t \mid \hat{R}_t, s_t, \text{前缀})$，目标是**最大化条件似然**，无需值函数与自举。
- DT 属于 **RCSL** 家族，与 Upside-Down RL、目标条件化 RL 同源，但吃上了 GPT 的技术栈红利。
- 与行为克隆的关键差别是**「回报条件」**：条件就是策略的遥控器。
