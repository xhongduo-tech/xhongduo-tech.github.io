## 为什么从嵌入模型开始

第 3 篇讲了 DPR 怎么训出检索向量，但生产系统通常不自己训——而是**选一个现成的嵌入模型**。这一步的杠杆极大：嵌入模型决定「什么算相似」，而「相似」的定义错了，后面所有环节（检索、重排、生成）都在错误的语义空间里打转。它是整条 RAG 链路上**替换成本最高、收益也最高**的一个零件。这一篇把「句子嵌入（sentence embedding）」讲透，并给出一套可落地的选型与评估方法。对标 SBERT（Reimers & Gurevych, 2019）这条主线。

## 1 从 BERT 到句子嵌入：SBERT 的贡献

BERT 能做句子嵌入吗？能，但不好用。原始 BERT 把句子编码成 token 级表示，直接用 [CLS] 向量当「句子向量」效果很差——因为 BERT 预训练目标（掩码预测、下一句预测）从未要求 [CLS] 携带「整句语义可比」的信息。<span class="marginnote">SBERT（Sentence-BERT）的洞察是：<strong>相似度必须被显式训练出来</strong>。它用孪生/三生网络结构（Siamese / Triplet）把两个句子各过一个 BERT 共享权重，再比较两个输出向量——相似句子拉开距离、不相似句子推远，语义空间从此「可度量」。</span>SBERT 也因此成为 sentence-transformers 生态与几乎所有现代嵌入模型的源头。

## 2 池化与相似度

嵌入模型把「句子 → 向量」的收尾步骤叫**池化（pooling）**，常见两种：

**[CLS] 池化**：取首令牌 [CLS] 的隐藏状态当句子向量。
- **平均池化（mean pooling）**：对所有 token 的隐藏状态取均值，更鲁棒，是现代模型的主流默认。<span class="marginnote">选池化方式时先查模型文档——许多发布模型（如基于 BERT/RoBERTa 的 SBERT 模型）都指定了对应的池化方式，配错会让相似度空间直接失效。</span>

配好池化后，两个句子 $s_1, s_2$ 的相似度通常用余弦：

$$
\text{sim}(s_1, s_2) = \cos\left(E(s_1), E(s_2)\right)
$$

向量归一化后即内积（第 2 篇公式解析）。**这也是为什么第 3 篇 DPR 的 $E_Q(q)^\top E_P(p)$ 与这里完全同构**——检索、相似度、嵌入本是同一套几何。

## 3 训练目标：相似度从哪学来

句子嵌入的质量由训练目标决定，三座里程碑：

- **softmax 目标（SBERT 原始）**：用蕴含数据（SNLI / MNLI）把句子对判成「蕴含 / 矛盾 / 中性」，让嵌入学会「A 蕴含 B 则靠近」。
- **对比学习（contrastive learning）**：把「同义改写对 / 同一段落的不同视图」拉近，把批次内其他样本推远——in-batch negatives（第 3 篇 DPR 同款技术）在这里复用。
- **Matryoshka 表示学习**：训练出的向量可以「截断前面若干维」仍保持好性能，让一个模型按需提供 128 维到 1024 维的向量，省存储、降延迟。<span class="marginnote">Matryoshka 直译「套娃」：向量高维段与低维段像套娃一样逐层兼容。第 11 篇讲向量数据库时会看到，维度直接决定索引内存与检索速度，所以「能截断」是巨大的工程红利。</span>

## 4 公式解析：对比损失的几何含义

对比学习把「拉近正对、推远负对」写成损失：

$$
\mathcal{L} = -\log \frac{e^{\,\text{sim}(q, p^+) / \tau}}{e^{\,\text{sim}(q, p^+) / \tau} + \sum_{j} e^{\,\text{sim}(q, p_j^-) / \tau}}
$$

- **第一步，温度 $\tau$**：缩放相似度得分，$\tau$ 越小，softmax 分布越尖锐，对负样本越「苛责」。调 $\tau$ 是训练时最灵巧的旋钮之一。
- **第二步，分子**：正样本的「被选中概率」——相似度越高，分子越大。
- **第三步，分母含全部负样本**：让负样本（批次内其他段落）得分越低越好。优化目标就是把「选对正样本」的对数概率顶到最大，与第 3 篇 DPR 的 NLL 损失同源。<span class="marginnote">几何直觉：对比损失在向量空间里「推开」每一个负样本、同时「拽近」正样本，最终把语义近邻关系刻进空间拓扑。这也是第 2 篇 HNSW 图能高效检索的前提——空间里相似点确实聚得近。</span>

## 5 选型与评估：MTEB 与「最后 1% 的坑」

选嵌入模型的现代标准是 **MTEB（Massive Text Embedding Benchmark）**：一个覆盖检索、分类、聚类、相似度等八大类任务、上百数据集的综合榜单。选型流程建议：

1. **看 MTEB 检索子榜**：检索任务是 RAG 的主战场，别被「综合分」误导——不同任务之间性能常常此消彼长。
2. **匹配语言与领域**：中文语料、法律/医疗/代码等专业领域，要看对应领域的榜单与微调版本。<span class="marginnote">通用模型在通用基准上亮眼，落到垂直领域往往退化——这正是第 8 篇「泛化差距」在嵌入层的重演。领域匹配比「总分高」重要得多。</span>
3. **算工程账**：维度（显存与检索速度）、延迟（CPU 还是 GPU 推理）、是否需要截断（Matryoshka）。

**辨析｜易错点：** 别用「相似度绝对值」判断好坏——同问两遍同一问题，自己跟自己比。要判断一个嵌入模型是否合适，正确姿势是拿**你自己的语料**做 Recall@k 冒烟测试（第 8 篇），而不是迷信排行榜分数。

## 6 小结

- 原始 BERT 的句子表示**未经相似度训练**，SBERT 用**孪生网络 + 显式相似度目标**补齐了这一步。
- 池化收尾两选一：**[CLS] 池化 / 平均池化**，与模型文档必须配套。
- 训练目标三阶段：**softmax 蕴含分类 → 对比学习 → Matryoshka 截断**。
- 核心公式是**余弦相似度 + 带温度 $\tau$ 的对比损失**，与 DPR 的 NLL 同源。
- 选型看 **MTEB 检索子榜 + 语言/领域匹配 + 工程账**；上线前必须用**自有语料做 Recall@k 冒烟测试**。
