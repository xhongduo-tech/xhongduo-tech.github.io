# 纵向联邦与联邦迁移：跨组织的合作

<div class="epigraph">
<p>当参与方持有同一批用户的不同特征时，纵向联邦使它们能在不共享数据的前提下共同建模；当样本与特征重叠都很小时，联邦迁移学习来补足。</p>

## 为什么需要纵向联邦

前八篇的主角是横向联邦：多家银行、多家医院，业务同质、特征同构，只是客户不同。但现实里更常见的合作是**产业链上的异构机构**：银行握着交易流水，电商握着消费记录，保险公司握着保单——它们面对**同一批用户**，各自只看到用户画像的一块碎片，却都急需一个完整模型（比如信贷风险分）。

这就是**纵向联邦学习（VFL）**的舞台：**样本空间相同、特征空间互补**。它比横向联邦难得多，因为「标签只在一方手里」「特征分布在不同机构手里」「样本对齐本身就不能泄露」。这一节把 VFL 与更难的联邦迁移学习（FTL）讲清楚。

## 1 纵向联邦的数据形态

回顾第一篇的表格：横向联邦切的是**行**（样本），纵向联邦切的是**列**（特征）。以银行 A、电商 B 合作为例：

- **样本**：同一批用户（用户 ID 相同）。
- **特征**：A 持「收入、存款、流水」，B 持「消费金额、频次、类目」。
- **标签**：只有 A 有「是否违约」——因为只有放贷方知道结果。

VFL 的核心困难由此而来：**模型的学习需要把各方特征拼接起来，但拼接过程不能交换原始数据**。

<span class="marginnote">一个微妙的区别值得记住：横向联邦的参与方「谁都能训出个差不多的模型」；纵向联邦则是「缺了任何一方的特征，谁也训不出好模型」——所以纵向联邦的参与方是天然的强互补关系，激励问题（第八篇）在这里最不尖锐。</span>

## 2 安全的实体对齐

第一步问题：**怎么确定「同一批用户」而互不知道对方的全部用户？** 这需要**隐私求交（private set intersection, PSI）**：参与方各自持有一个用户 ID 集合，用密码学协议计算出两个集合的**交集**，除此之外的一切（非交集成员、对方的完整集合）都不泄露。

常用技术有：基于哈希的盲目化（加盐哈希 + 置换）、基于不经意传输（oblivious transfer）的协议。对齐之后，双方只在自己的交集样本上协作训练——交集之外的数据留在本地，不参与本轮学习。

**辨析｜易错点：** 实体对齐不是「双方把 ID 哈希后比对」。哈希可比对，但字典攻击可以反查哈希——必须用加随机盐或专门的 PSI 协议。现实系统的失败案例，多半死在「以为哈希就安全」这一步。<span class="marginnote">隐私求交的代价也要心里有数：即使只比对 ID，参与方仍能学到「我的哪些用户与对方重叠」——交集大小本身就是敏感统计信息。因此严格的做法还要在协议层对交集的大小与成员做差分隐私处理，防止被用来侦察对方客户群。</span>

## 3 公式解析：纵向联邦的训练目标

VFL 中只有一方（设为 $A$）持有标签 $y$，双方各自持有特征 $\mathbf{x}_A, \mathbf{x}_B$。以线性模型为例，全局预测是：

$$
\hat{y} = \langle \mathbf{w}_A, \mathbf{x}_A \rangle + \langle \mathbf{w}_B, \mathbf{x}_B \rangle
$$

训练时，标签方 $A$ 计算损失，但梯度必须同时传给 $B$。逻辑回归的梯度分两半：

- **$B$ 侧梯度**：$\frac{\partial \ell}{\partial \mathbf{w}_B} = (\hat{y} - y)\, \mathbf{x}_B$。注意这个梯度里含有 $( \hat{y} - y)$——它是**全局信息**，$B$ 算不出来，因为 $B$ 没有 $y$。
- **$A$ 怎么把信息安全传给 $B$**：$A$ 计算残差 $(\hat{y} - y)$ 后，用**加法同态加密**加密残差，发给 $B$；$B$ 在**密文上**计算 $(\hat{y}-y) \cdot \mathbf{x}_B$（加法同态支持密文上的数乘），把密文梯度发回 $A$；$A$ 解密得到 $B$ 的梯度。整个过程 $B$ 看不到 $y$，$A$ 看不到 $\mathbf{x}_B$ 的明文梯度。

三步拆解：

- **第一步，同态加密是什么**：一种「密文上能直接算」的加密。加法同态保证 $\mathrm{Enc}(a) + \mathrm{Enc}(b) = \mathrm{Enc}(a+b)$——密文相加等于明文相加的加密。于是「在密文上乘一个明文常数」也是可行的。
- **第二步，谁加密谁解密**：$A$ 生成密钥对，把公钥发给 $B$。$A$ 用公钥加密残差，$B$ 在密文上完成本地那半计算，$A$ 用私钥解密。密钥掌握在标签方手里——信任模型是「标签方可信、特征方半可信」。
- **第三步，为什么这样够安全**：$B$ 从头到尾只见密文，解不出 $y$；$A$ 只见 $B$ 返回的密文梯度，但知道 $\hat y$ 与 $y$，无法从中拆分出 $\mathbf{x}_B$ 的明文。双方只共享了「学习所需的统计量」。
- **第四步，代价**：同态加密计算开销比明文高两到三个数量级，所以工程上常「加密一次、批量算完」，并且只在必要环节加密。更进一步的方案是用**安全多方计算**（MPC）在明文等价的安全电路上做，两者各有权衡。

## 4 联邦迁移学习

如果两方的**样本重叠很小、特征重叠也很小**，VFL 与 HFL 都失效——这时数据形态落在地图的第三格：**联邦迁移学习（FTL）**。

迁移学习（见第三级《迁移学习》）的思路是：把**源域**学到的知识迁移到**目标域**。FTL 的设定是：参与方 $A$、$B$ 数据不同域、不同分布，但存在一个小的重叠子集（对齐后样本），借助它做**跨域知识转移**。典型框架（Liu et al., 2019）的流程是：

1. **实体对齐**：找出双方的重叠样本（用 PSI）。
2. **特征加噪对齐**：双方在重叠样本上通过加法同态加密交换特征，学习一个共同的表示空间（如借助 DNN 的中间层）。
3. **迁移**：$A$ 用自己的标签在共享表示上训练，得到的能力通过表示层迁移给 $B$，供 $B$ 在它自己的域上推理。

FTL 是三类联邦中最难、也最贵的——通信与加密开销都大。它在「样本重叠少、特征互补弱」的跨行业、跨地区场景（比如跨语言、跨机构画像）才有不可替代的价值。

从工程视角，FTL 的开销有三个来源：加密计算、多轮通信、实体对齐成本。因此选用 FTL 前应先量化「重叠样本的价值」——若重叠子集太小，迁移收益可能覆盖不了加密开销。这是联邦里少有的「先算账、后合作」的场景：账算得清，FTL 才值得上。

## 5 应用案例

纵向联邦与联邦迁移的经典落点在**信贷风控**：银行 + 电商 + 运营商联合建模，违约预测的 AUC 相比单方模型有显著提升（Yang 等的书中报告了 FATE 平台上的这类结果）。另一个密集场景是**智慧医疗**：不同医院各持同一批病患的不同检查特征（影像、基因、化验），纵向联合提升诊断精度。这些都验证了纵向联邦的核心卖点——**特征互补带来的边际收益，值得为加密与对齐的复杂度买单**。

## 6 一个简化的加密梯度演练

回到银行 A × 电商 B。设某个样本的本地特征 $x_B = 2$，全局残差 $(\hat y - y) = 0.5$。A 要安全地告诉 B「你的半侧梯度是 $0.5 \times 2 = 1$」，却不泄露残差 $0.5$ 本身：

1. A 生成同态密钥对，把公钥 $pk$ 发给 B；A 算 $c = \mathrm{Enc}_{pk}(0.5)$ 并发送。
2. B 在密文上乘本地特征：$\tilde c = c \times 2 = \mathrm{Enc}_{pk}(0.5 \times 2) = \mathrm{Enc}_{pk}(1)$。
3. B 把 $\tilde c$ 发回 A，A 用私钥解密得 $1$。

B 全程只见密文，拿不到 $0.5$；A 得到 $1$，却无法从乘积中拆分出 $x_B = 2$。双方各得所需、各守机密——这就是纵向联邦「互补而不泄露」的最小单元。真实系统里特征成百上千、样本成千上万，这个基本单元被批量并行地执行无数次，配合同态加密的批量运算优化才能让开销落在可用范围内。

## 7 纵向联邦的完整生命周期

把第五节的最小单元放大成一次完整的纵向联邦合作，生命周期分五步：

1. **实体对齐（PSI）**：确定双方的公共样本，其余数据留在本地、不参与。
2. **参数协商**：确定模型结构、加密参数、谁持标签、谁参与聚合——通常是「有标签的一方」做协调者。
3. **加密训练轮**：反复执行「特征方算本地半梯度 → 加密交换 → 标签方聚合梯度 → 更新双方参数」这一循环。
4. **联合评估**：在公共样本上联合打分，验证模型效果（对缺失任何一方的特征做消融，量化互补价值）。
5. **上线与持续更新**：新样本到来时重新对齐、继续训练——注意「新用户是否属于公共样本」又引回 PSI。

这五步解释了为什么纵向联邦是三类里工程最重的：每一轮都跨越多方与加密层。也正因如此，它的商业价值最清晰——**谁缺谁不可**，合作意愿最稳固。

## 8 小结

- **纵向联邦（VFL）**：样本对齐、特征互补；标签常只在一方手里，是最难的「谁也不能缺」的合作。
- **实体对齐**用**隐私求交（PSI）**：只算交集，不泄露非交集与完整集合；哈希必须加盐，否则可被字典攻击。
- VFL 训练：**加法同态加密**传递梯度统计量——标签方加密残差，特征方在密文上算本地梯度。
- **联邦迁移学习（FTL）**：样本与特征重叠都小，靠重叠子集做跨域知识迁移，成本最高。
- 典型应用：信贷风控、智慧医疗等**特征互补**场景。
- 三类联邦按「行还是列还是都不同」切分数据，构成完整的合作地图。
- 加密梯度演练的最小单元：标签方加密残差、特征方密文上算、标签方解密——互补而不泄露。
- 完整生命周期五步：实体对齐、参数协商、加密训练轮、联合评估、上线更新。
- 应用选型按三步走：先问共同样本、再问特征是否相同、都不同才上 FTL——成本逐级升高。
- FTL 的三个成本来源（加密、通信、对齐）要先算账后合作，重叠子集太小就不值得上。
- 一句话定位：横向联邦「谁都能训」，纵向联邦「缺谁都不行」，FTL「先算账再合作」。

在下一节，我们回看横向联邦那个被反复推迟的问题——**公平性**。当模型的精度在不同客户端间差异巨大时，我们还能说这个联邦是「共同」的吗？公平性问题，是前几篇所有「平均」操作积累下来的账单。
