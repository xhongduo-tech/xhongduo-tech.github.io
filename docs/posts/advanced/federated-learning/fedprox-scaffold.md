# FedProx 与 SCAFFOLD：驯服客户端漂移

<div class="epigraph">

## 为什么 FedAvg 会漂移

上一篇诊断了病灶：数据异构。这一篇开药方。FedAvg 在异构数据下收敛变慢甚至发散，根因是一个直观的现象——**客户端漂移（client drift）**：每个客户端在本地多跑 $E$ 轮 SGD，参数就被拖向「只对自己数据最优」的方向，而不是全局最优。$E$ 越大、数据越异构，漂移越远。

漂移的本质是「本地目标」和「全局目标」错位。FedProx 和 SCAFFOLD 用两种不同的哲学处理同一个错位：**FedProx 靠「拉」**——给本地目标加一根拴住参数的绳子；**SCAFFOLD 靠「矫」**——用控制变量主动消除漂移项。两者都能在非 IID 下稳定收敛，但代价不同。

## 1 客户端漂移的形式化

设全局目标是所有客户端经验风险之和：

$$F(w) = \sum_{k=1}^{K} \frac{n_k}{n} F_k(w), \qquad F_k(w) = \frac{1}{n_k} \sum_{i \in D_k} \ell(w; x_i, y_i)$$

中心化训练直接优化 $F$。但 FedAvg 里，客户端 $k$ 实际优化的是**自己的** $F_k$。当 $P_k$ 与混合分布 $\bar P$ 差异大时，$F_k$ 的最小点 $w_k^*$ 偏离全局最小点 $w^*$ 很远。本地 $E$ 步 SGD 把 $w_t$ 朝 $w_k^*$ 推，服务器平均之后，每轮都带着一轮「偏斜的位移」。这就是漂移的数学来源。

<span class="marginnote">直觉：想象一群人围着一个坑想把它填平，但每人只看得见自己脚下的土堆，都在朝自己脚下扒土。FedAvg 每轮把各人扒土的方向平均一下，最后填了个四不像——这就是漂移。</span>

## 2 FedProx：近端项把参数拴住

FedProx（Tian Li et al., MLSys 2020）的思路极简：**让本地目标离全局起点 $w_t$ 远一点就惩罚一点**。修改后的本地优化问题为：

$$\min_w \left[\, F_k(w) + \frac{\mu}{2} \| w - w_t \|^2 \,\right]$$

新超参数 $\mu$ 是**近端系数**：$\mu=0$ 退化为 FedAvg；$\mu$ 越大，绳子越紧，本地参数越不敢远离服务端下发的 $w_t$。

FedProx 的哲学是「约束而非矫正」：它不试图修正漂移的方向，只限制漂移的幅度。代价是需要调一个超参数 $\mu$，且 $\mu$ 太大时本地学习形同虚设——因为客户端几乎复制了全局参数。<span class="marginnote">FedProx 的近端项与「弹性权重巩固」（EWC，防止灾难性遗忘的一种正则）在形式上同源——都是在优化目标里加「离旧参数太远就罚」的项。正则化思想在深度学习的多个场景里反复复用。</span>

## 3 公式解析：FedProx 的目标函数

把 FedProx 的本地目标拆开：

$$G_k(w) = \underbrace{F_k(w)}_{\text{本地经验风险}} + \underbrace{\frac{\mu}{2} \| w - w_t \|^2}_{\text{近端惩罚}}$$

- **第一步，第一项是什么**：$F_k(w)$ 是客户端 $k$ 在自己数据上的平均损失。它想往 $w_k^*$ 走——这是漂移的发动机。
- **第二步，第二项干什么**：$\| w - w_t \|^2$ 度量「当前参数离全局起点有多远」。加系数 $\frac{\mu}{2}$ 后，远离起点会付出二次方递增的代价，于是本地优化会**在「自己数据」与「靠近全局」之间找平衡**。
- **第三步，平衡点在哪**：最优 $w$ 大致满足 $\nabla F_k(w) + \mu(w - w_t) = 0$，即 $\mu(w - w_t) = -\nabla F_k(w)$。漂移梯度越大，第二项产生的「回拉力」也越大——**漂移被自动地对冲了一部分**。
- **第四步，直觉**：$\mu$ 像一个橡皮筋，一端系着本地数据，一端系着全局起点。橡皮筋越硬（$\mu$ 大），本地参数越贴在全局起点；越软（$\mu$ 小），越放飞自我。FedProx 论文证明：存在一个 $\mu$ 的选择，使得在非 IID 下收敛比 FedAvg 更快、损失更低。

## 4 SCAFFOLD：控制变量矫正漂移

SCAFFOLD（Karimireddy et al., NeurIPS 2020）走的是另一条路：不限制漂移，而是**在每一步修正漂移的方向**。它引入了两组「控制变量」（control variates）：

- 全局控制变量 $c$：由服务端维护，估计**全局梯度方向** $\nabla F(w_t)$。
- 客户端控制变量 $c_k$：每个客户端维护，估计**本地梯度方向** $\nabla F_k(w_t)$。

客户端 $k$ 的本地更新不再是「沿 $\nabla F_k$ 走」，而是沿**矫正后的方向**走：

$$w \leftarrow w - \eta \left( \nabla \ell_k(w) - c_k + c \right)$$

理解这个式子的关键是括号里的 $(-c_k + c)$：

- 若本地梯度 $\nabla \ell_k$ 正好等于本地平均梯度 $\nabla F_k$（即 $c_k$），那么第一项与 $c_k$ 抵消，剩下的只剩 $c$——**本地更新完全沿着全局梯度方向走**。
- 于是每个客户端不再是「各奔前程」，而是「统一朝全局方向前进」，只是各自用自己的数据估计梯度。漂移被系统性消除。

**辨析｜易错点：** 不要把 SCAFFOLD 的「矫正」理解成「服务端知道每个客户端的数据」——$c_k$ 是客户端自己维护并只把必要的差值传给服务端的统计量，原始数据依然不出本地。它只是**通信模式**变了：客户端要额外上传控制变量，通信量约为 FedAvg 的两倍。

还有一个容易被实现细节坑到的地方：SCAFFOLD 的 $c_k$ 需要跨轮保存，而参与客户端的集合每轮都在变。当客户端 $k$ 隔了几轮才再次被选中时，它的 $c_k$ 已经过时，需要用「上一轮自己保存的 $c_k$」与「服务端当前的全局 $c$」做插值，否则矫正会失准。这是 SCAFFOLD 在真实系统里比 FedProx 更容易出错的原因之一。

## 5 两者的对比与代价

| 维度 | FedProx | SCAFFOLD |
| --- | --- | --- |
| 核心机制 | 近端惩罚，限制漂移幅度 | 控制变量，消除漂移方向 |
| 新增超参数 | 一个：$\mu$ | 无 |
| 额外通信 | 无 | 上传控制变量，约 2 倍 |
| 额外存储 | 无 | 每客户端存 $c_k$ |
| 异构鲁棒性 | 改善，需调 $\mu$ | 强，异构下理论保证收敛 |
| 理论优势 | 无单调性保证 | 异构下通信轮数比 FedAvg 少 |

SCAFFOLD 有一个非常硬的结论：**在数据异构时，SCAFFOLD 需要的通信轮数比 FedAvg 严格更少**（两者若都跑相同轮数，SCAFFOLD 的损失上界更紧）。这是它作为「矫正派」的代表作被称为联邦优化新标杆的原因。但它那两倍的每轮通信量，恰好把它引向下一场战斗——通信压缩。

## 6 什么时候用哪个

实战选型按三条判据走：

- **异构程度**：轻偏斜用 FedAvg 足够；中偏斜上 FedProx（只需调一个 $\mu$）；重偏斜、且不想调超参数，用 SCAFFOLD。
- **通信预算**：FedProx 不增加每轮字节，通信紧张时优先；SCAFFOLD 每轮约两倍通信，带宽宽裕时划算。
- **客户端可否存状态**：cross-silo（机构，数量少、有状态）适合 SCAFFOLD；cross-device（手机，数量巨大、无状态、每轮随机采样）里 $c_k$ 无处安放，反而 FedProx 更稳健——这一点在第十一篇讲系统部署时还会回看。

再补一个公平性视角的提醒：FedProx 与 SCAFFOLD 都优化「平均损失」，它们**不保证公平**——最差客户端可能依旧掉队。要把「谁都别太差」写进目标，需要第十篇的 q-FedAvg。工程上的保守路线是：**先上 FedProx，收益不够再换 SCAFFOLD，最后才考虑公平性改造**。

## 7 一个漂移的数值直觉

用最简单的情形感受漂移。两个客户端，$w_0 = 0$，各自本地目标的最小点分别是 $w_1^* = +1$ 与 $w_2^* = -1$。

- **FedAvg**：客户端 1 的 $E$ 步本地训练把参数推向 $+1$，客户端 2 推向 $-1$；服务端平均得 $0$——**回到了起点**。只要异构严重，每一轮都在「推走再拉回」，这就是「原地打转」的微观画面。
- **SCAFFOLD**：控制变量 $c_1 \approx +1, c_2 \approx -1$（各自本地梯度的估计），矫正项 $-c_k + c$ 把两边的更新都「掰回」全局方向，参数不再被双双推偏。
- **FedProx**：近端项 $\frac{\mu}{2}\|w - w_t\|^2$ 让本地最优点从 $w_k^*$ 缩回 $w_t$ 附近——$w_1^*$ 实际变成 $w_t$ 与 $+1$ 之间的一个折中点，漂移幅度被压缩。

数值虽理想化，但它精确刻画了三者的机制差异：FedAvg 放任漂移、FedProx 压缩漂移、SCAFFOLD 消除漂移。

## 8 小结

- **客户端漂移**：本地目标 $F_k$ 与全局目标 $F$ 错位，本地 $E$ 步把参数拖偏。
- **FedProx**：在本地目标上加近端项 $\frac{\mu}{2}\|w - w_t\|^2$，用「拉」限制漂移；$\mu=0$ 退化为 FedAvg。
- **SCAFFOLD**：用控制变量 $c, c_k$ 构造矫正项 $(-c_k + c)$，用「矫」消除漂移方向。
- 代价对比：FedProx 多一个超参数 $\mu$，SCAFFOLD 多约一倍通信量。
- 理论结论：异构数据下 SCAFFOLD 的通信轮数优于 FedAvg。
- 两者的共性：都建立在「优化目标」这一层，还没碰「通信带宽」这一层。
- 漂移的数字直觉：两个极端的客户端把平均推回原点，SCAFFOLD 用控制变量掰回全局方向。
- 工程细节：SCAFFOLD 的 $c_k$ 过时需要与全局 $c$ 插值，参与集合变动时最容易出错。
- 两者都只优化平均损失，不保证公平——最差客户端仍可能掉队，公平需要第十篇的改造。

在下一节，我们把目光从「减轮数」转向「减字节数」——**通信效率与梯度压缩/量化**。既然本地多算能减轮，那么把梯度压得更小，能不能再省一层？这场关于字节的战争，将把联邦学习从「算法问题」推向「系统工程问题」。
