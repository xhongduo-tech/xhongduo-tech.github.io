# 联邦平均 FedAvg：第一座里程碑

<div class="epigraph">
<p>我们称这种方法为联邦平均（FedAvg），并证明它在非均衡、非独立同分布的数据分布下依然稳健，能以比全同步随机梯度下降少 10–100 倍的通信轮数收敛。</p>

## 为什么从 FedAvg 开始

上一篇画了地图，这一篇开始落地。联邦学习的第一性难题是**通信**：手机通过移动网络参与训练，每上传一个参数向量都要花钱、耗电、等带宽。如果你把经典的随机梯度下降（SGD，见第三级《深度学习》）直接搬到联邦场景——每步都让每个设备把梯度传回服务器——模型当然能训，但通信量会让它在现实中活不过第一轮。

FedAvg 的贡献，就是用一个「先本地多算几步、再拿平均」的朴素想法，把通信量砍掉一到两个数量级。**它是联邦学习的第一座里程碑：几乎所有后来的联邦算法（FedProx、SCAFFOLD、各种压缩方案）都以 FedAvg 为基线、以超越它为卖点。** 读懂 FedAvg，就等于读懂了联邦优化这个领域的通用语法。

## 1 从分布式 SGD 到联邦平均

先把「朴素方案」画清楚。设总样本数为 $n$，分布在 $K$ 个客户端上，第 $k$ 个客户端有 $n_k$ 个样本，$\sum_k n_k = n$。

**分布式 SGD**：每一轮，服务端下发当前参数，每个客户端用自己的本地数据算一个梯度 $g_k = \nabla \ell_k(w)$，上传；服务端求加权平均，更新一次：

$$w \leftarrow w - \eta \sum_{k=1}^{K} \frac{n_k}{n}\, g_k$$

这个方案每轮只走一步，通信量与训练步数一比一。FedAvg 的关键观察是：**本地计算很便宜，通信很贵**——那就在本地多算几步，攒够了再同步一次。于是「每步同步」变成「每轮同步」。

**联邦平均（FedAvg, Federated Averaging）**：每一轮，客户端不是算一个梯度，而是**在本地数据上自己跑若干个完整的 SGD 步骤**（称为本地轮次），得到一个新的参数 $w_{t+1}^k$，再把这个「参数」而不是「梯度」传回服务器。

<span class="marginnote">注意这个微妙但关键的区别：朴素方案传梯度，FedAvg 传参数。参数是「已经消费完本地数据之后的产物」，天然比单步梯度携带更多信息——这正是它能砍通信的根本原因。</span>

## 2 FedAvg 算法流程

McMahan 等的 Algorithm 1 可以压缩成四步：

1. **初始化**：服务端生成初始模型参数 $w_0$。
2. **每轮 $t$**：服务端按比例 $C$ 随机挑选一批客户端 $S_t$，把当前参数 $w_t$ 下发。
3. **本地训练**：每个被选中的客户端 $k$ 从 $w_t$ 出发，在自己的本地数据 $D_k$ 上跑 $E$ 轮 SGD（批大小 $B$），得到 $w_{t+1}^k$。
4. **聚合**：服务端按样本数加权平均所有返回的参数：

$$w_{t+1} = \sum_{k \in S_t} \frac{n_k}{n_{S_t}}\, w_{t+1}^k$$

其中 $n_{S_t} = \sum_{k \in S_t} n_k$ 是本轮参与客户端的样本总数。

下图把一轮通信画完整：服务端下发 $w_t$，客户端在本地数据上跑 $E$ 轮后传回 $w_{t+1}^k$，服务端加权平均。注意整个过程中**原始数据从未离开客户端**。

![FedAvg 一轮通信的架构示意](/images/federated-learning/fedavg-architecture.svg)

算法由三个超参数刻画，理解它们就理解了 FedAvg 的全部自由度：

- **$C$**：每轮参与客户端比例。$C=0.1$ 表示每轮只有约十分之一的设备干活——这就是「部分参与」。
- **$E$**：本地训练的轮数。$E=1$ 时一个本地轮次退化为一次梯度更新（接近朴素方案）。
- **$B$**：本地批大小。$B=\infty$ 表示客户端把本地数据一次性全量梯度下降（local full-batch GD）。

## 3 公式解析：加权平均聚合

聚合公式是 FedAvg 的心脏，把它拆开看：

$$w_{t+1} = \sum_{k=1}^{K} \frac{n_k}{n}\, w_{t+1}^k, \qquad w_{t+1}^k = w_t - \eta \sum_{\tau} \nabla \ell_k\!\left(w_t^{(\tau)}\right)$$

- **第一步，$n_k / n$ 是什么**：$n_k$ 是客户端 $k$ 的样本数，$n$ 是全部样本数。这个比值叫**样本权重**——数据多的客户端在平均里说话更大声。它保证聚合结果等价于「把所有数据当成一个大数据集来训」的一步。
- **第二步，$w_{t+1}^k$ 怎么来的**：客户端 $k$ 从 $w_t$ 出发，在自己本地跑 $E$ 轮 SGD。内层求和跑过本地轮次 $\tau=1,\dots,E$，每一步都减去学习率 $\eta$ 乘本地梯度 $\nabla \ell_k$。
- **第三步，为什么是平均而不是别的一步**：把 $E$ 步展开，$w_{t+1}^k$ 实质上是「本地数据的 $E$ 步累计梯度」作用在 $w_t$ 上。加权平均这些参数，等于在参数空间里对 $E$ 步的梯度做个加权合成——近似于「在全体数据上大步走一次」。
- **第四步，直觉**：当 $E=1$ 且所有客户端都参与（$C=1$）时，FedAvg 精确退化为分布式 SGD。所以 FedAvg 是「在通信与本地计算之间拨动旋钮」的通用框架，两个极端都是它的特例。

**辨析｜易错点：** 不要把聚合写成简单的算术平均 $\frac{1}{K}\sum_k w_{t+1}^k$。在非均衡数据下，不乘 $n_k/n$ 会让小数据客户端的更新被等权稀释，模型整体偏向数据少的参与方，性能显著劣化。

## 4 为什么「平均参数」居然有效

从优化直觉看，在参数空间取平均似乎没有道理——参数不是概率，凭什么能平均？但 FedAvg 的惊人之处在于它真的有效。三层直觉：

- **隐式集成**：$E$ 步本地训练后，各客户端的 $w_{t+1}^k$ 已各自在「自己的数据视角」上走了一段。平均这些参数，等价于在参数空间对多个「局部模型」做集成，集成往往比任一成员更稳。<span class="marginnote">集成直觉的一个证据：把「平均参数」和「平均预测」对比，FedAvg 用的是前者——参数平均比预测平均更激进，因为它直接共享权重而非软投票，这也是它能一步跨越大距离的原因。</span>
- **EM 视角**：联邦学习可以看作一个潜在变量模型——把「哪个客户端主导」当作潜在变量，FedAvg 的轮流采样 + 平均近似于 EM 式的交替更新。
- **鲁棒于非 IID**：虽然非 IID 会带来偏差（第三、四篇细讲），但 FedAvg 在标签偏斜、数量偏斜下仍能收敛，McMahan 等在 CIFAR-10 与下一个词预测 LSTM 上验证了这一点。

## 5 证据与局限

论文的核心实验结论值得记住：在 CIFAR-10 图像分类与莎士比亚作品字符级 LSTM 上，**FedAvg 用比全同步 SGD 少 10–100 倍的通信轮数达到同等精度**。这个数字定义了「减一轮」的成功标准，也成为后续所有通信压缩方案的标尺。

但 FedAvg 远非终点，它的局限恰好构成后几篇的引子：

- **异构数据下漂移**：非 IID 严重时，本地 $E$ 步会把参数推向「自己的分布」，全局收敛变慢甚至发散——FedProx 与 SCAFFOLD 来救（第四篇）。
- **只解决通信，不解决隐私**：传参数不等于隐私安全，仍可从参数反推数据——差分隐私与安全聚合来救（第六、七篇）。
- **假设客户端乐于参与**：现实中设备掉线、电池耗尽、不情愿——客户端选择与激励来救（第八篇）。

## 6 一个数字例子：三客户端的加权平均

让「加权 vs 算术平均」的差别落进具体数字。设三个客户端的样本数分别为 $n_1 = 100, n_2 = 200, n_3 = 700$，第 $t$ 轮服务端下发 $w_t = 0$，三个客户端本地训练后返回 $w_{t+1}^1 = 0.1$，$w_{t+1}^2 = -0.1$，$w_{t+1}^3 = 0.05$。

- **算术平均**：$\frac{0.1 + (-0.1) + 0.05}{3} \approx 0.0167$。
- **样本数加权平均**：$0.1 \times \frac{100}{1000} + (-0.1) \times \frac{200}{1000} + 0.05 \times \frac{700}{1000} = 0.01 - 0.02 + 0.035 = 0.025$。

两者相差近 50%。哪个对？若三个客户端代表 100、200、700 个真实用户，加权平均把最大话语权给了样本最多的客户端——这与「把所有数据合到一起训一步」一致，是统计上正确的聚合。**$n_k/n$ 这个权重，是「每个人说话的分量」的精确表达。**

**辨析｜易错点：** 有人会问：那如果小客户端的数据质量更高怎么办？答案是：信息量（质量）不属于 FedAvg 的输入，它只能按样本数加权——要按质量加权，需要额外评估机制（第八篇的贡献评估），那是另一个层面的问题，不要混进聚合公式。

## 7 FedAvg 与优化器的兼容性

FedAvg 论文默认本地用 SGD，但生产里客户端几乎都配更快的优化器（动量 SGD、Adam）。一个值得澄清的细节：

- **本地优化器可以五花八门**：每个客户端用自己的优化器跑 $E$ 轮，上传参数——只要聚合仍是无状态的加权平均，FedAvg 框架就成立。
- **服务端也可以「优化」**：把聚合公式 $w_{t+1} = \sum \frac{n_k}{n} w_{t+1}^k$ 看成「把客户端的更新当作梯度」，服务端用 Adam/Adagrad 再更新一次，就得到 FedAdam、FedAdagrad、FedYogi 一族算法——它们把「客户端优化」与「服务端优化」解耦，实践中常比裸 FedAvg 收敛更快。
- **易错点**：客户端用 Adam 时，每个客户端的自适应状态（一阶、二阶矩估计）只存在于本地，跨客户端不可共享——这与 SCAFFOLD 的 $c_k$ 状态问题同源（第四篇）。凡是「需要维护跨轮状态」的方法，都要先想清楚状态放在哪一层。

## 8 小结

- FedAvg 的核心是把「每步同步」改成「**每轮同步**」：客户端本地跑 $E$ 轮 SGD，服务端加权平均参数。
- 聚合公式按**样本数加权**：$w_{t+1} = \sum_k (n_k/n)\, w_{t+1}^k$，不能退化为算术平均。
- 三个超参数：$C$（参与比例）、$E$（本地轮数）、$B$（本地批大小）。
- $E=1, C=1$ 时 FedAvg 退化为分布式 SGD——它是通信与计算之间的一个旋钮。
- 有效性来自**隐式集成**与 EM 式交替更新；实验上比同步 SGD 少 **10–100 倍**通信轮数。
- 局限：异构漂移、无隐私保证、假设自愿参与。
- 本地优化器可各不相同，服务端也可套用 Adam（FedAdam 族）——优化与聚合解耦。

在下一节，我们直面 FedAvg 最头疼的敌人——**非独立同分布（非 IID）数据**。为什么「大家的数据不一样」会成为联邦学习的首要现实，以及它究竟怎样伤害模型。
