## 为什么从 Codex 讲起

上一篇的 CodeBERT 学会了「读」代码，但代码智能的真正主角是「**写**」。2021 年，OpenAI 的 **Codex** 论文《Evaluating Large Language Models Trained on Code》做了一个近乎革命性的选择：**不再用编码器做分类，而是直接用解码器续写代码**。它的副产品是人尽皆知的 GitHub Copilot，它的论文则顺带定义了本领域沿用至今的评测基准 **HumanEval** 与指标 **pass@k**。

从 Codex 到今天，代码生成大模型走了一条「**通用模型 → 代码专项模型 → 开源代码模型**」的路线：Codex 是 GPT-3 的代码微调，Code LLaMA 把代码能力注入 Meta 的开放权重家族，DeepSeek-Coder 则证明了「从零开始用纯代码语料训练」同样能登顶。这一篇我们拆这三代模型的**共同配方**，看它们在数据、目标函数、上下文长度上各自做了什么关键决策。它也是本专题后续各篇的引擎基础：第 4 篇的 IDE 补全、第 5 篇的 `pass@k` 评测、第 10 篇的 Agent 化编程，全都跑在「模型会续写代码」这个前提之上——先把引擎造出来，再谈怎么开。<span class="marginnote">这三代模型回答了同一个问题：把下一 token 预测做到极致，代码生成能力会不会自己长出来？答案是会，而且长出的能力还溢出到了数学推理上——Codex 在数学基准 Math 上同样大幅提升。这个「代码训练 → 推理增益」的现象至今仍是开放课题。</span>

## 1 Codex：续写即生成，一举定义评测

Codex 的本质很简单：**拿一个能生成文本的因果语言模型（GPT-3），用 GitHub 代码继续预训练**。OpenAI 从 GitHub 采集了约 **179 GB** 代码，做了三层清洗：删除超 1 MB 的文件、按许可证过滤、按文件内容去重——这三点后来成为所有代码预训练数据管线的标准动作。

Codex 的推理（inference）策略直接影响了后续所有代码模型：

**束搜索与贪心解码几乎不可用**。论文发现，代码的解空间极大，贪心容易走进「平庸但错误」的死胡同，必须用**随机采样**。
**温度是核心旋钮**。采样温度越高，输出越多样、越容易「碰」到正确解；温度越低，越稳定但越平庸。评测时用中等温度（约 0.2–0.6）采样多个候选，再验证哪个通过测试。
**函数级粒度**。Codex 学会的是「给定签名与文档字符串，生成函数体」，这是 HumanEval 的设计前提。

Codex 论文还有一个对后续评测影响深远的细节：**它用「采样 + 测试验证」来打分数**——对每题采样多个候选，逐个跑单元测试，只要有一个通过就算对。这个「多候选中任一成功」的计数方式，正是下一篇 `pass@k` 的直接来源：评测不是「模型一次说对」，而是「模型在 k 次尝试里能蒙对一次」的能力。

Codex 论文还有两个容易被忽略的结论。**第一，代码训练会「溢出」到数学与自然语言推理**：同一套模型在数学基准 Math 与编程竞赛基准 APPS 上同样显著提升，说明「读代码」锻炼的是一种通用的问题分解能力，而不是只会背代码。**第二，采样与验证是效果的放大器**：即便最强的模型，贪心解码也拿不到满分，而多采样 + 测试筛选能把分数抬高一大截——这个「生成-验证」回路正是第 10 篇 Agent 化编程的原型。

**辨析｜易错点：** 很多人以为「代码生成 = 训练时见多识广就行」。Codex 论文用实验告诉你：**模型在训练分布内的「见过」与测试时的「没见过」是完全两回事**。HumanEval 的 164 道题全部是**人工新写、从未出现在训练数据里**的题目——这是它与 Math、APPS 共同坚持的「防污染」原则。评测数据一旦泄漏进训练集，pass@k 就是废纸一张。这条原则在 DeepSeek-Coder 里被做成了数据管线的正式环节。

## 2 代码预训练的三味真火

从 Codex 到 Code LLaMA、DeepSeek-Coder，代码预训练逐渐收敛出三味「配方」，缺一不可。它们共同回答的是同一个工程问题：**怎样才能让下一 token 预测在「代码」上表现得像「推理」**。注意，这里没有花哨的新架构——全是 Transformer 解码器，差异全在数据与训练目标上。

**真火一：数据配比。** 代码模型的训练数据不是「纯代码」。Code LLaMA 用 500B token（代码为主），DeepSeek-Coder 用 **2T token、87% 代码 + 13% 自然语言**。为什么留 13% 的自然语言？因为自然语言提供常识与世界知识，代码提供结构化推理——两者互补。数据还讲究**仓库级组织**：DeepSeek-Coder 按仓库聚合文件、保留目录结构，让模型学到跨文件的依赖关系，这是后面「仓库级理解」那篇的伏笔。<span class="marginnote">数据清洗的具体动作几乎成了「玄学」：删除机器生成文件（如 `package-lock.json`）、按扩展名过滤、处理编码异常、按相似度去重。DeepSeek-Coder 还明确把与 HumanEval/MBPP 重叠的文件剔除——「评测防污染」从口头原则变成了管线代码。</span>

**真火二：填空（FIM，fill-in-the-middle）。** 代码生成的真实场景是「光标在中间，前后都有代码」，而因果 LM 只会从左往右续写。**FIM** 把训练样本改造成填空形式：把中间一段移到末尾，让模型学会「给定前缀与后缀，补出中间」。以 DeepSeek-Coder 的模板为例，一个函数被切分成前缀、中间、后缀三段后，训练序列被改写为：

**真火三：长上下文（long context）。** 代码生成是「看一眼整个仓库再动手」的任务，上下文越长越好。Code LLaMA 支持 16k 上下文（从 LLaMA 2 的 4k 扩展而来），DeepSeek-Coder 同样把窗口撑到 16k。长上下文不只是「能塞更多 token」，更意味着**注意力能跨文件建立依赖**——这正是下一批仓库级模型（以及 SWE-agent 这类 Agent）能跑起来的前提。扩展上下文的关键在**位置编码**：Code LLaMA 用旋转位置编码（RoPE）的外推/内插技术，DeepSeek-Coder 则在预训练阶段分两步走——先用 4k 上下文训练，再把窗口线性外推到 16k 继续预训练。为什么位置编码是瓶颈？因为绝对位置编码（如正弦函数）无法外推到训练时未见过的长度，而 **RoPE（旋转位置编码）** 通过相对位置旋转让模型天然具备一定的外推能力；在 16k 之上继续拉长，就需要做位置插值或 NTK 缩放。位置编码的完整讨论见第四级《长上下文与注意力优化》。三味真火必须**同时点火**：数据不对，模型学到的是垃圾分布；没有 FIM，IDE 里的中间补全只能靠硬凑；上下文太短，跨文件依赖根本建立不起来。这也是为什么「只换一个环节」很难复现别人的分数——配方是组合拳。

## 3 开源双子星：Code LLaMA 与 DeepSeek-Coder

2023 年，代码生成大模型进入开源时代，两个模型构成坐标轴。

**Code LLaMA：通用模型的代码扩展。** Meta 在 LLaMA 2 基础上继续训练了 500B token 的代码数据，推出 7B/13B/34B/70B 四档。它的工程贡献在于三点：一是把上下文从 4k 扩到 16k；二是用 **FIM** 训练，使其原生支持 IDE 里的中间补全；三是提供了 **Python 专项版** 与 **Instruct 版**——Instruct 版用「生成-执行-反馈」的自举数据微调，是「让模型学会用测试反馈改代码」的最早开源尝试之一。

**DeepSeek-Coder：从零开始的代码专项。** 与「通用模型 + 代码」路线相对，DeepSeek 选择从零用 **2T token** 训练纯代码模型，87% 代码 + 13% 中英文自然语言。它的三个杀手锏：

- **仓库级数据**：按 GitHub 仓库聚合文件、保留目录结构，模型能学到 `import` 与跨文件调用。
- **评测防污染**：明确剔除与 HumanEval、MBPP 等基准重叠的文件，保证分数可信。
- **FIM 训练**：约三成训练样本用 FIM 格式，让模型补齐「光标中间」。

代码大模型的最后一块拼图是**指令微调与执行反馈**：Code LLaMA Instruct 用「生成代码 → 跑测试 → 用结果微调」的自举流程，DeepSeek-Coder-Instruct 同样如此。这一步把「会续写」升级成「听懂指令」——用户说「写一个二分查找」，模型不是盲目续写，而是按指令产出。**执行反馈（execution feedback）**是代码 RL 训练与普通 RLHF 的分水岭：奖励信号来自测试用例是否通过，而非人类偏好打分。

在 HumanEval 上，DeepSeek-Coder-33B 的 pass@1 接近 **75%**，明显超过同量级 Code LLaMA-34B（约 49%）。它证明了一件事：**对代码任务，精心配比的代码语料比「更大的通用模型」更值钱**。

| 维度 | Codex (2021) | Code LLaMA (2023) | DeepSeek-Coder (2023) |
| --- | --- | --- | --- |
| 路线 | GPT-3 微调 | 通用模型扩展 | 从零代码专项 |
| 数据量 | 179 GB GitHub | 500B token | 2T token（87% 代码） |
| 上下文 | 约 4k | 16k | 16k |
| FIM | 否 | 是 | 是 |
| 典型 pass@1 (HumanEval) | 12B 约 28% | 34B 约 49% | 33B 约 75% |

读这张表要抓住**两条曲线**：横向看，从 Codex 到 2023 年，数据量涨了十几倍、上下文长了四倍、FIM 从无到有；纵向看，DeepSeek-Coder 用「数据配比 + 仓库级组织」在同样的参数量上把分数抬高一截。**参数不再是唯一杠杆，数据与训练目标才是。**

Code LLaMA 与 DeepSeek-Coder 之后的生态很快被这两条路线填满：Code LLaMA 衍生出量化版、Instruct 版，并被大量 IDE 插件以开源方式部署；DeepSeek-Coder 的仓库级数据策略则被 StarCoder2、Qwen-Coder 等后继模型沿用。这批开源模型的共同影响是：**代码智能的「模型层」从闭源黑盒变成了可自部署、可微调、可审计的组件**——这也为第 12 篇「许可证与安全风险」埋下了伏笔。

**辨析｜易错点：** 对比模型时别只盯着 HumanEval 分数。HumanEval 的函数粒度小、解法固定，容易「刷分」；真实工程还要看 MBPP（更简单但量大）、长尾语言（TypeScript、Rust）的表现。DeepSeek-Coder 在 HumanEval 领先不代表它在所有场景都赢——**评测一定要对齐使用场景**。

这批开源模型还催生了**本地化部署**的潮流：量化（如 4-bit）、vLLM 等推理引擎把 7B–34B 模型压进消费级 GPU，让代码补全可以完全离线运行——隐私敏感场景（如医疗、金融代码）因此受益。部署侧的量化与推理优化详见第四级《大模型部署》。

最后必须正视代码模型的**幻觉与过度信任**问题：模型生成的代码可能语法正确但逻辑错误，可能引用了不存在的库，还可能带着安全隐患。`pass@k` 测的是「能对」，产品要管的是「不能错」——这正是第 8 篇单元测试生成、第 9 篇缺陷检测与安全审计存在的理由。

## 4 公式解析：因果语言模型的续写目标

一切代码生成模型的**地基目标**都是同一个：因果语言建模（causal language modeling）。给定训练序列 $x = (x_1, x_2, \dots, x_T)$，目标是最大化所有位置「在已见前缀下预测下一 token」的对数概率之和：

$$
\mathcal{L}(\theta) = -\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t})
$$

对这条公式做四步拆解：

- **第一步，看懂 $x_{<t}$**：这是「位置 $t$ 之前的所有 token」——训练时它是真实文本，推理时它是模型自己生成的输出。因果注意力保证 $p_\theta(x_t \mid x_{<t})$ 只看左侧、不看右侧，这是「续写」成立的机制基础。
- **第二步，看懂 $p_\theta(x_t \mid x_{<t})$**：模型对下一 token 的预测分布，来自 Transformer 最后一层对词表的 softmax：logits 越大，对应 token 的概率越高。**代码生成就是反复从这个分布里采样**——这也解释了为什么采样温度能改变行为。
- **第三步，看懂求和与取负**：$\sum_{t=1}^{T}$ 把所有位置的预测难度加起来；负号把「最大化似然」变成「最小化损失」，方便梯度下降。由于每个位置的损失**相互独立**，FIM 才能「只改顺序、不改目标」。
- **第四步，看懂「无标签」**：这个目标里没有人工标签，训练信号就是数据本身——**自监督**。Codex、Code LLaMA、DeepSeek-Coder 的预训练全部在最小化这个 $\mathcal{L}$，分歧只发生在「数据喂什么、上下文多长、微调用什么」，而不是目标函数本身。

这条目标还解释了为什么**温度与采样**在代码评测里如此重要：$\mathcal{L}$ 只定义了「分布」，而生成时从分布里采哪个 token 由温度决定——温度越高分布越平、越容易探索不同解。所以「同一个模型」配上不同采样策略，pass@k 可以相差十几分，评测时必须固定采样配置才可比。

**辨析｜易错点：** 因果 LM 的损失只对前缀可见，因此「先给签名，再让模型补函数体」能严格测试生成能力。但这也带来一个隐蔽陷阱：**如果把期望输出也放进前缀，模型就是在抄写而非生成**。工程上最常犯的错误，是把测试用例、参考实现误放进上下文——这不叫增强，叫作弊。

## 5 小结

- **Codex** 用 GPT-3 + 179 GB GitHub 代码微调，证明「续写即生成」，并定义了 HumanEval 与 `pass@k`；采样与温度是代码解码的核心旋钮。
- 代码预训练的三味真火：**数据配比**（代码为主、掺自然语言、按仓库组织）、**FIM 填空**（让模型学会补光标中间）、**长上下文**（16k 起步，靠位置编码扩展）。
- **Code LLaMA** 是「通用模型 + 代码」路线：开源权重、FIM 原生支持、16k 上下文，是生态事实标准。
- **DeepSeek-Coder** 是「从零代码专项」路线：2T token、仓库级数据、防污染剔除，33B 在 HumanEval 上 pass@1 接近 75%，反超同量级 Code LLaMA。
- 因果语言模型目标 $\max \sum_t \log p_\theta(x_t \mid x_{<t})$ 是一切代码生成模型的共同地基；分歧只在数据、上下文与微调，不在目标函数本身。
- **温度与采样**是生成与评测的核心旋钮：同一个模型配不同采样策略，pass@k 可以相差十几分，报告分数必须固定采样配置。
- 代码预训练会「溢出」到数学推理——「读代码」锻炼的是一种通用的问题分解能力，而非只会背代码。
- 开源代码模型把「模型层」从闭源黑盒变成可自部署、可微调、可审计的组件，催生了本地化部署与隐私敏感场景。
- 代码生成大模型不是「只会背代码」：采样 + 测试筛选的「生成-验证」回路，正是第 10 篇 Agent 化编程的原型。
- 部署侧把 7B–34B 模型量化后压进消费级 GPU，让补全完全离线运行——隐私敏感行业由此受益。

这三代模型的演进给我们的方法论启示是：**代码智能的进步，往往不是架构的颠覆，而是数据、目标函数与工程配方的精进**。Codex 证明了「续写即生成」，Code LLaMA 证明了「开源可复制」，DeepSeek-Coder 证明了「数据配比是硬实力」——三者相加，才构成我们今天看到的代码生成生态。
- 仓库级数据组织（按仓库聚合、保留目录结构）让模型学到跨文件依赖，这是第 6 篇「仓库级理解」在预训练阶段埋下的伏笔。
- 数据清洗的动作（去重、按扩展名过滤、剔除机器生成文件）看似琐碎，却是「分数可复现、评测可信」的地基。
