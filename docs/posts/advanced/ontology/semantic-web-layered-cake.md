# 语义网愿景：Berners-Lee 的分层蛋糕

<div class="epigraph">

## 为什么从分层蛋糕开始

第五篇我们完成了描述逻辑的纯理论：语言、算法、复杂度。这一篇把它接回现实——
**语义网（Semantic Web）技术栈**，也就是把 DL 的语义装进 W3C 标准，
让知识可以在开放网络上被机器共享。一切的出发点，是伯纳斯-李在 2001 年
《科学》杂志上描绘的**分层蛋糕（layer cake）**——一张叠着七层技术的
体系图，从最底层的字符编码一路叠到最高层的逻辑推理与信任。
这张图定义了语义网的「宪法结构」：每一层解决一层问题，
上层依赖下层，每层都有 W3C 规范。理解这张蛋糕，你就掌握了
本系列后三篇（RDF、RDFS、OWL、SPARQL）的**整体坐标**。

## 1 从万维网到语义网

1990 年，伯纳斯-李发明了万维网：用 URL、HTTP、HTML 让文档互相链接。
万维网让**人**能读互相链接的文档，但机器只能「显示」文档，不能「理解」。
语义网的理想，是让**机器**也能「读懂」数据的含义：网页不只是给人看的
排版文件，而应携带**可被机器解析的语义**——这就是「语义网」的由来。

**语义网（Semantic Web）**：一个以「数据 + 语义」为核心的网络愿景——
信息以带明确含义的结构（RDF 三元组）发布，机器用共享的本体（OWL）
与查询语言（SPARQL）推理和检索，最终实现「机器可读、机器可理解、
机器可推理」的开放数据网络。<span class="marginnote">语义网与万维网的关系
不是替代，而是叠加：HTML 负责「给人看」，RDF 负责「给机器读」。
今天你在网页里看到的 `schema.org` 结构化标记，正是语义网愿景
「渗透进普通网页」的产物——语义网没有消失，它变成了网页的
「机器可读层」。</span>

## 2 分层蛋糕的七层结构

伯纳斯-李 2000 年提出的分层蛋糕，自下而上大致如下：

| 层 | 技术 | 解决的问题 | 本系列章节 |
| --- | --- | --- | --- |
| 数据层 | Unicode + URI/IRI | 字符编码与资源寻址 | 本节 |
| 结构层 | XML | 结构化语法 | 本系列第 2 节 |
| 数据模型层 | RDF | 三元组数据模型 | 第 2–3 节 |
| 语义层 | RDFS + OWL | 类、属性与推理语义 | 第 4–5 节 |
| 逻辑层 | 规则/推理 | 逻辑推理 | 第 8 节 |
| 证据层 | 证明 | 推理结果可验证 | 愿景层 |
| 信任层 | 信任模型 | 谁的话可信 | 愿景层 |

**重点：这张蛋糕的「自下而上」是依赖方向，也是抽象方向。**
下层是上层的载体：RDF 需要 URI 寻址资源，RDFS 需要 RDF 承载类声明，
OWL 建立在 RDFS 之上，SPARQL 查询 RDF 图。每一层都只做一件事、
把更复杂的问题留给上层——这就是**分层架构**的意义：每层可独立替换、
可独立演进。<span class="marginnote">「URI 统一寻址」是整张蛋糕的地基：
RDF 里一个 `:dog` 也是 IRI，与网页 URL 同一个命名空间。语义网之所以
能「网」起来，正因为一切资源共享一套地址体系——这也是它对比
数据库「封闭命名」的关键差异。</span>

## 3 2001 年宣言与现实的落差

分层蛋糕的伟大蓝图，在现实中遭遇了漫长的落差。2001 年宣言承诺
「智能代理替你比价订票」，但此后十几年，语义网「叫好不叫座」，
原因有三：

- **先有鸡还是先有蛋**：机器可读数据太少，没人愿建语义应用；
  应用太少，数据没人发布。
- **本体构建成本高**：手工建本体费时费力（第七篇详述），
  而「自动建本体」始终不成熟。
- **推理性能与规模**：OWL 推理在最坏情况下（双指数）跑不动大数据。

**重点：语义网的第一波理想破灭，不是理论错，而是生态没长出来。**
但它留下了极其重要的遗产：**RDF/OWL/SPARQL 一套标准与全部工程积累**。
2012 年谷歌推出 Knowledge Graph，业界突然发现：语义网的理念
以「知识图谱」的形式复活了——没有当年的标准，
就没有今天的图谱生态。<span class="marginnote">这段「理想—落差—复活」的曲线
值得反复咀嚼：它解释了为什么第八篇知识图谱开篇要讲「概念史」——
语义网的愿景、挫折与遗产，是理解知识图谱为什么「长成这样」的唯一钥匙。
而第九篇 LLM 时代，则是这曲线的第三段：大模型让「自动建本体」第一次变得可行。</span>

## 4 分层蛋糕的现代修订

进入大模型时代，分层蛋糕的「上层」（逻辑、证据、信任）被重新审视：

- **逻辑层不再唯一**：统计方法（LLM）承担了部分「推理」职能，
  与符号逻辑形成互补（第九篇神经—符号）。
- **证据与信任层**：从「形式化证明」转向「来源追踪 + 人工审核」——
  这正是知识图谱里 `provenance`（来源）与 RAG 引用溯源要解决的。
- **数据层更加务实**：现代图谱大量使用**属性图**（Neo4j）而非纯 RDF，
  两种模型之争（第八篇）本质是「蛋糕理想」与「工程现实」的拉锯。

**重点：分层蛋糕没有过时，它从「唯一的路线图」变成了「参照坐标系」。**
今天你看到的知识图谱工程，几乎都在蛋糕的「数据模型层到语义层」
之间选址：要纯语义就 RDF/OWL，要性能就属性图，
要两者兼得就用混合架构。<span class="marginnote">这张蛋糕还是选型的坐标系：
当你纠结「该用 RDF 还是属性图」时，其实是在问「我更需要语义推理
还是查询性能」——这正是分层蛋糕各层诉求的冲突。第八篇的
「属性图 vs RDF」一节，会带着这张蛋糕深入分析。</span>

## 5 小结

- 语义网是**万维网的机器可读扩展**：给数据明确的语义，让机器协作。
- 分层蛋糕自下而上：**Unicode/URI → XML → RDF → RDFS/OWL → 逻辑 → 证据 → 信任**。
- 分层架构的意义：**每层解决一层问题，上层依赖下层，各层可独立演进**。
- 2001 宣言与现实落差：**生态未长成，但标准遗产保留**。
- 知识图谱是语义网愿景的**工业复活**：标准在，理念在，形态变了。
- 现代修订：**逻辑层让位于符号—统计互补，证据层转向来源追踪**。
- 分层蛋糕从「路线图」变成「坐标系」，仍是知识建模的选型参照。
- 一句话记忆：**语义网 = 万维网 + 机器可读语义；知识图谱 = 语义网的工业落地**。
- 下一站的入口：**RDF 三元组**是蛋糕最容易被低估、却最持久的一层。
