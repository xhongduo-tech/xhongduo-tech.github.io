# 集合范畴 Set 与 Hask 范畴

## 为什么从 Set 与 Hask 开始

上一节的范畴定义是「空壳」，这一节往壳里装两个具体的范畴——
**集合范畴 $\mathbf{Set}$**（对象是集合，态射是函数）与 **Hask 范畴**
（对象是类型，态射是程序）。它们是范畴论的「具体锚点」：
之后每一个抽象概念（函子、自然变换、单子），你都能回到
「它在这个例子里长什么样」来验证直觉。理解 Set 与 Hask，
你就有了范畴论的两只脚——一只是数学的，一只是编程的。

## 1 Set：一切范畴的原型

**集合范畴 $\mathbf{Set}$**：

- **对象**：所有集合。
- **态射 $\mathrm{Hom}(A, B)$**：从集合 $A$ 到 $B$ 的**全函数**。
- **复合**：函数复合 $(g \circ f)(x) = g(f(x))$。
- **单位**：恒等函数 $1_A(x) = x$。

三条性质立刻验证：函数复合天然满足结合律，恒等函数天然满足
单位律——所以 $\mathbf{Set}$ 确实是一个范畴。

**重点：Set 是「范畴的原型」——因为它满足了我们对「对象与关系」
的全部直觉。** 集合是「一堆元素」，函数是「元素间的对应」，
复合是「对应接对应」。**当范畴论要举例子时，第一个总是 Set**——
它是「关系如何组合」的教科书。<span class="marginnote">Set 的特殊地位
（「所有集合的集合」在朴素集合论里会有悖论，严格处理要靠
「宇宙」或「足够大的集合」）——这个技术细节不阻碍直觉：
<strong>把 Set 想成「我们关心的所有集合」</strong>即可。范畴论甚至因此
发明「范畴的范畴」，层层往上——抽象没有尽头。</span>

## 2 Hask：类型与程序的范畴

**Hask 范畴**（Haskell 的类型范畴）：

**对象**：Haskell 类型（`Int`、`Bool`、`Char`、`[Int]`……）。
**态射**：纯函数 `f :: a -> b`。
**复合**：函数复合 `(.)`——`(g . f) x = g (f x)`。
**单位**：恒等函数 `id`——`id x = x`。

程序员的直觉在此对齐：**类型 = 集合（值的集合），函数 = 态射，
函数复合 = 复合，恒等函数 = 单位。** `Int`、`Bool`、`String` 这些你天天用的
东西，全都生活在这个范畴里。

**重点：Set 与 Hask 的对应表，是「数学直觉 ↔ 编程直觉」的翻译器。**

| Set | Hask |
| --- | --- |
| 集合 | 类型 |
| 元素 | 值 |
| 函数 | 纯函数 |
| 函数复合 | `(.)` |
| 恒等函数 | `id` |
| 积集合 $A \times B$ | 元组 `(a, b)` |
| 函数集 $B^A$ | 函数类型 `a -> b` |

**这张表让你能把「范畴论的定理」直接翻译成「程序的规律」。**
范畴论说「积的泛性质」，你听到的是「元组怎么用最自然的接口
构造与解构」——抽象在 Hask 里落地成具体的代码形态。<span class="marginnote">Hask 的
对应表是本书「从极限到大模型」主线的缩影：<strong>数学的范畴论
（极限之一）与程序的语言设计（工程之一）在 Hask 里合流</strong>。
你不需要懂 Haskell 才能受益——map、flatMap、柯里化，
这些主流语言的抽象全都有 Hask 式的范畴结构，只是名字不同。</span>

## 3 公式解析：curry 与函数类型

Hask 最重要的结构之一是**积类型与函数类型的关系**：

$$(a, b) \to c \;\cong\; a \to (b \to c)$$

**逐项拆解：**

- **左边 $(a, b) \to c$**：接收一个「元组」的函数——两个参数打包。
- **右边 $a \to (b \to c)$**：接收一个参数、返回一个函数的函数——**柯里化**。
- **$\cong$**：范畴论中的「同构」——两个类型可以无损互转。
- **两个方向的转换**：
  - `curry :: ((a, b) -> c) -> a -> b -> c`——把「元组参数」拆成「连续柯里化」；
  - `uncurry :: (a -> b -> c) -> (a, b) -> c`——把「柯里化」合并回「元组参数」。

**重点：这条同构不是 Haskell 的发明，而是范畴论的结构——**
它说的是「积」与「指数」（函数类型）之间的**伴随关系**
（倒数第二节正式展开）。**你每天写的 `->`（函数类型），
就是范畴论「指数对象」的语法糖**——抽象早已在你的指尖。<span class="marginnote">「积与指数的
伴随」将派生出整个「笛卡尔闭范畴」理论——它是一切函数式
语言类型系统的数学底座。这里只需记住：<strong>元组与函数类型之间
有「天然的双向翻译」，而「天然」在范畴论里有精确含义——
泛性质（下一节积与余积）</strong>。直觉先行，严格后到。</span>

## 4 易错点：Hask 不是「真正」的范畴

严谨地讲，Hask 并不满足范畴的公理，原因在**底（bottom）**：

Haskell 允许 `undefined`、`error`、无限递归——它们都是
  「不终止/无值」的 **bottom（⊥）**。
**⊥** 存在于每个类型里，导致「函数不是全函数」——
  `f ⊥` 可以是 `⊥`（非严格函数）。
更麻烦的是 **`seq`**：它能区分 `⊥` 与 `()`，
  破坏了一些范畴论成立的等式。

**重点：Hask 是「在忽略 bottom 的意义上」是个范畴。**
严格说，要得到「真正的」范畴，需要把态射限定为「全函数」
或使用「提升」技巧。**对程序员，这个「不严格」几乎不影响
直觉**——但要知道它的存在，否则会在「为什么范畴论定理在
Haskell 里偶尔不成立」时困惑。<span class="marginnote">Hask 的「伪范畴」身份是个
健康的提醒：<strong>范畴论是「理想化」的数学，工程是「现实化」的
妥协</strong>。这不意味着范畴论对编程无用——相反，它给「理想该长
什么样」提供了基准。像所有数学之于工程：<strong>理想是灯塔，
现实是航行</strong>。</span>

## 5 为什么这两个例子是全部抽象的锚

后续所有概念，都会在这两个范畴上「验算」：

**函子**（下一节）：在 Set 里是「把集合映到集合、函数映到函数」
  的结构保持映射；在 Hask 里就是 `fmap`——`map` 的泛化。
**自然变换**：在 Hask 里是「把一种容器变成另一种容器的多态函数」。
**单子**：在 Hask 里就是 `Maybe`——`return` 与 `>>=`。

**重点：没有 Set 与 Hask，范畴论会沦为「空洞的抽象」。**
有了它们，每个抽象都有「具体形态」可验——**「抽象的价值
= 它能解释多少个具体例子」**，而 Set 与 Hask 就是最基础
的两个例子。学后面的每一节，都要回到这张对应表问一句：
「这个概念在 Set 里是什么、在 Hask 里是什么？」<span class="marginnote">「两个锚点」的
方法论值得带走：学任何抽象概念，都给它找两个具体例子——
一个「数学的」、一个「工程的」——然后反复验算。这比
死记定义有效十倍。Set 与 Hask 就是范畴论的双锚，
后面每一节都会用它们来「接地气」。</span>

## 6 小结

- **Set 范畴**：对象是集合、态射是全函数、复合是函数复合——范畴原型。
- **Hask 范畴**：对象是类型、态射是纯函数、复合是 `(.)`——编程之锚。
- 对应表：**集合↔类型、函数↔程序、积↔元组、函数集↔函数类型**。
- **curry 同构**：$(a,b) \to c \cong a \to (b \to c)$——积与指数的关系。
- 易错点：**Hask 因 bottom/seq 不是严格范畴**——「理想化」的提醒。
- 方法：**每个抽象概念用 Set 与 Hask 双锚验算**。
- 定位：Set 与 Hask 是后续一切抽象（函子、自然变换、单子）的接地器。

如何用一个对象、一堆态射与一个复合，装下「可结合的二元运算」。
