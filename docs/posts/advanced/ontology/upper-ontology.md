## 为什么从上层本体开始

前几节我们学会了复用设计模式、构建本体网络，但还没回答一个更根本的
问题：**网络里所有本体共享的那层「共同语言」从哪来？**
这就是**上层本体（upper ontology / top-level ontology）**：
描述「实体、对象、过程、性质、关系」等最一般范畴的本体，
被所有领域本体 import 作为共享顶层。理解上层本体，
你就抓住了「互操作」的最后一环——两个系统若要真正共享语义，
光有相同的文件格式不够，还得有**相同的概念根基**。
这也让本节成为全书哲学线与工程线交汇的高潮之一。

## 1 上层本体是什么

**上层本体（upper ontology）**：覆盖一切领域通用范畴的本体——
它不关心「猫」「订单」「心肌细胞」，只关心「实体」「对象」「过程」
「性质」「关系」「角色」这类**放之四海而皆准**的顶层概念。

一个典型上层本体提供几类范畴：

| 范畴 | 含义 | 例 |
| --- | --- | --- |
| 实体（entity） | 一切存在物 | 顶概念 ⊤ |
| 持续物（continuant） | 在时间中持续的存在 | 人、桌子 |
| 发生物（occurrent） | 在时间中展开的存在 | 事件、过程 |
| 性质（quality） | 实体的属性 | 颜色、温度 |
| 角色（role） | 情境中的身份 | 患者、雇员 |
| 关系（relation） | 实体间的联系 | 参与、部分 |

**重点：上层本体是「领域的领域」**——它不回答「这个订单怎么处理」，
而回答「订单是持续物还是发生物」「处理是过程还是状态」。
领域本体 import 它，就自动继承这套顶层分类，获得「向上对齐」的
坐标。**上层本体是本体网络的「公共协议」。**<span class="marginnote">上层本体的哲学对应
正是全书的主线：亚里士多德追问「存在是什么」，阿奎那区分存在与本质，
康德给出范畴表——上层本体就是把这些哲学追问「工程化」的产物。
BFO、DOLCE 顶层的每一个类，都背着一部形而上学史。</span>

## 2 为什么共享顶层

共享顶层的价值，用「两个系统互操作」的场景最能说清。

设想 A 公司用本体建模「病人」，B 公司建模「治疗方案」。若两者
各自从零定义「人」，A 的「人」可能是有血有肉的主体，B 的「人」
可能是病历里的记录——**同名，不同义**。若两者都 import BFO，
BFO 会强制它们区分：「人」是一个**独立持续物（independent continuant）**，
而「病历」是一个**信息实体**。于是：

A 与 B 的「人」都落在 BFO 的同一个顶层类下——**可以对齐**；
谁都无权把「人」建模成「过程」——**偏差被顶层约束**；
新系统加入时，沿着 BFO 的顶层树找位置即可——**扩展有锚点**。

**重点：共享顶层的本质是「共享一套分类承诺」。** 它不像 `owl:imports`
那样只是「引入文件」，而是「接受一套关于世界如何分块的判断」。
**互操作不只是数据格式的互操作，更是本体论承诺的互操作。**<span class="marginnote">这层「承诺」让
上层本体的选择变成一件哲学决定：选 BFO 是接受实在论（世界有独立于
认知的结构），选 DOLCE 是接受认知论（本体是心灵的产物）。工程师
常以为「选个库而已」，其实选的是形而上学立场——下一节与再下一节
将分别展开这两条路线。</span>

## 3 上层本体的谱系与选型

上层本体是一个「市场」，主流候选各有立场：

| 上层本体 | 哲学立场 | 特点 | 典型用户 |
| --- | --- | --- | --- |
| BFO | 实在论 | 生物学/医学导向，OBO Foundry | 生物医学 |
| DOLCE | 认知/描述论 | 语言学导向，区分持续/发生物 | 语言学、通用 |
| SUMO | 实用主义 | 大而全，含中间本体 | 通用、标准 |
| UFO | 综合 | 统一基础本体，整合多家 | 信息系统 |

**选型不是「挑最好的」，而是「挑立场最匹配的」**：

做**医学/科学数据**，BFO 是事实标准（OBO Foundry 强制要求）；
做**语言学/认知建模**，DOLCE 的语言学根基更合用；
做**通用标准**（法律、金融通用词汇），SUMO 覆盖面更广。

**重点：上层本体选择是「可逆但昂贵」的决定。** 中途换上层本体，
意味着重排所有领域本体的顶层父类——代价巨大。**选之前想清楚
立场，选之后坚决执行。**<span class="marginnote">上层本体选型还有一个现实维度：
<strong>生态绑定</strong>。BFO 绑定 OBO Foundry（生物医学本体联盟），用 BFO
等于加入一个成熟生态；DOLCE 绑定 WordNet 等语言资源。
选上层本体，往往同时是在选「跟谁结盟」。</span>

## 4 批判与反思

上层本体也有尖锐的批评者：

**不存在普适的顶层**：不同领域对「什么是基本范畴」有不同需求，
  「放之四海而皆准」可能是幻觉。
**哲学承诺过重**：实在论 vs 认知论之争，未必有工程答案。
**采用成本高**：对齐上层本体需要大量建模改造，中小项目扛不动。

**对策与反思：**

**轻量对齐**：不 import 整个上层本体，只映射到它的关键类
  （例如把「人」对齐到 BFO 的若干顶层类），保留自由度。
**双层策略**：内部用自建轻量 schema，对外映射到上层本体做互操作。
**接受多元**：承认「没有唯一正确的顶层」，上层本体之间用
  **映射**互连（这正是本体对齐的用武之地，后续一节）。

**重点：上层本体的意义不在「找到唯一真理」，而在「建立可对齐的
共同参照」。** 它是手段不是目的——如果一套轻量对齐已经满足
互操作需求，就不必背上完整上层本体的哲学包袱。<span class="marginnote">这个反思与
全书第三篇呼应：奎因拒绝「本质」，迈农承认「不存在之物」也有地位——
本体工程同样拒绝「唯一正确的分类」。上层本体不是形而上学的终结，
而是「让形而上学分歧变得可讨论、可映射」的工程化尝试。</span>

## 5 小结

- **上层本体**：描述一切领域通用范畴（实体、持续物、发生物、性质、角色）的本体。
- 它是**本体网络的公共协议**：让不同系统「同名同义」、分类有锚点。
- 共享顶层的本质是**共享一套本体论承诺**——选上层本体即选哲学立场。
- 主流候选：**BFO（实在论/生物医学）、DOLCE（认知论/语言学）、
  SUMO（实用主义/通用）、UFO（综合）**。
- 选型看「**立场匹配 + 生态绑定**」，且「可逆但昂贵」。
- 批判：**普适顶层或为幻觉、承诺过重、采用成本高**。
- 对策：**轻量对齐、双层策略、顶层间用映射互连**。
