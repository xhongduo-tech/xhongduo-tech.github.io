# Tableau 算法：概念可满足性的判定

<div class="epigraph">
<p>判定一个概念是否可满足，就是在问：能不能为它造出一个模型？Tableau 的做法是直接去造——造不出来，就证明不可满足。</p>

## 为什么从 Tableau 开始

前面五节我们认识了 DL 的语言（ALC、SROIQ）与世界观（OWA），
但还没回答一个工程问题：**推理机到底怎么判「可满足」？**
这一节的主角是**Tableau 算法**——描述逻辑推理的「引擎室」。
它的思想朴素得惊人：要判断一个概念有没有模型，就**动手造一个模型**；
造得出来，可满足；任何尝试都撞上矛盾，则不可满足。这套「构造性判定」
让 DL 的可判定性从理论变成现实：Pellet、HermiT 这些推理机，
核心都跑着 Tableau（或其变种）。理解 Tableau，你就看穿了
所有本体推理工具的共同内脏。

## 1 预备：否定范式与知识库转化

Tableau 不是直接在原公式上跑，而是先做两步「预处理」：

- **否定范式（Negation Normal Form, NNF）**：把否定符号内推到
  原子概念前面——利用对偶律 $\neg(C \sqcap D) \equiv \neg C \sqcup \neg D$、
  $\neg\exists R.C \equiv \forall R.\neg C$。做完后，否定只出现在原子概念前。
- **TBox 内化（internalization）**：把每条包含公理 $C \sqsubseteq D$
  改写成等价形式 $\neg C \sqcup D$，并把它加到**每个**出现的个体上——
  这样 TBox 的全局约束就变成每个节点的局部要求。

**重点：预处理的目的，是把「全局公理」变成「局部规则」。**
Tableau 只在一个个节点上工作，若 TBox 的约束不落到节点上，
推理机就会「顾此失彼」。内化之后，每条公理对每个个体都生效，
判定过程就只剩「在节点上展开概念」这一件事。<span class="marginnote">NNF 的
对偶律我们已在 ALC 一节练过：$\neg\exists R.C \equiv \forall R.\neg C$。
Tableau 正是靠这些等价式把公式「摊平」成便于分解的形态——
逻辑等价式在这里不是理论，而是算法的燃料。</span>

## 2 完成规则：Tableau 的展开操作

Tableau 在一个**图（tableau）**上工作：节点代表个体，边代表角色关系。
算法的核心是**完成规则（completion rules）**——当节点上的概念包含某种
构造子时，按规则扩展图。ALC 的完成规则只有四条：

| 规则 | 触发条件 | 动作 |
| --- | --- | --- |
| $\sqcap$-规则 | 节点含 $C \sqcap D$ | 把 $C$ 与 $D$ 都加入该节点 |
| $\sqcup$-规则 | 节点含 $C \sqcup D$ | 分支：分别尝试加 $C$ 或加 $D$ |
| $\exists$-规则 | 节点含 $\exists R.C$ | 造一个新节点 $y$，连边 $R$，把 $C$ 放到 $y$ 上 |
| $\forall$-规则 | 节点含 $\forall R.C$，且已有边 $R(x,y)$ | 把 $C$ 加到邻居 $y$ 上 |

**重点：∃-规则「造个体」，∀-规则「传播约束」，⊔-规则「开分支」。**
算法的全部复杂度都藏在这三个动作里：造个体让图生长，传播约束让知识扩散，
开分支让可能性分叉。**Tableau 就是一个「受控的模型建造机」**——
它按逻辑规则把概念展开成一张具体的关系图。<span class="marginnote">注意 ∃-规则
与 ∀-规则的对称性：∃ 在<strong>没有</strong>邻居时<strong>造一个</strong>；∀ 在<strong>已有</strong>邻居时<strong>检查</strong>。
「造」与「查」的分工，正是存在量词与全称量词的语义差在算法里的投影——
存在要「找到见证」，全称要「逐一核对」。</span>

## 3 冲突与分支：如何判决

当某个节点同时含 $A$ 与 $\neg A$（同一原子概念及其否定），发生**冲突（clash）**——
这个分支无法成为模型。算法全程：

1. 从概念 $C$（或 ABox 断言）出发，初始化图的种子节点；
2. 反复应用完成规则，直到无法再应用（图「完备」）或发生冲突；
3. 遇到 ⊔-分支：分别尝试两个子图，任一成功即成功；
4. **若存在一个完备且无冲突的分支 → 该分支就是一个模型，$C$ 可满足**；
5. **若所有分支都冲突 → $C$ 不可满足**。

**重点：可满足性的判决，等价于「存在一个能造完的模型」。**
完备无冲突的分支给出了一个**具体模型**（节点、边、概念指派全在图上），
这正是「构造性证明」：不是抽象地说「可能存在模型」，而是
**把模型造出来给你看**。这个性质叫**模型构造性（model construction）**，
是 Tableau 区别于其他判定方法（如归结）的标志。<span class="marginnote">Tableau 的
「造模型」哲学与第四篇一阶逻辑的模型论一脉相承：可满足 = 有模型。
但一阶逻辑只<strong>半可判定</strong>（模型可能造不完），DL 的 Tableau 因为语言受限，
能保证「要么造完、要么证明造不完」——可判定性就这样落在算法上。</span>

## 4 公式解析：一次完整的判定演练

判定这个概念是否可满足：

$$\text{人} \sqcap \exists \text{有孩子}.\text{女性} \sqcap \forall \text{有孩子}.\text{男性}$$

它说的是「一个人，有一个女儿，且所有孩子都是男性」——直觉上自相矛盾。
Tableau 把它拆穿：

- **第一步，种子节点**：把整个概念放到根节点 $x$ 上。
- **第二步，⊓-规则**：拆出三个成分，加入 $x$：
  $\text{人}(x)$、$\exists \text{有孩子}.\text{女性}(x)$、$\forall \text{有孩子}.\text{男性}(x)$。
- **第三步，∃-规则**：为「有一个女儿」造见证——新节点 $y$，
  边 $\text{有孩子}(x,y)$，且 $\text{女性}(y)$ 加入 $y$。
- **第四步，∀-规则**：$x$ 有 $\forall \text{有孩子}.\text{男性}$ 且已有边到 $y$，
  于是把 $\text{男性}(y)$ 加入 $y$。
- **第五步，冲突检测**：$y$ 上同时有 $\text{女性}$ 与 $\text{男性}$——
  若知识库另有公理「女性 ⊑ ¬男性」（这是常识公理），则发生冲突。

若「女性 ⊑ ¬男性」在 TBox 里，冲突成立，**该概念不可满足**。
若没有这条公理，$y$ 可以同时「既是女性又是男性」而无矛盾（OWA 不禁止），
概念就可满足——**答案完全取决于知识库的公理**。<span class="marginnote">这个例子点破一个
反直觉事实：Tableau 的「矛盾」不是「看起来怪」，而是「违反显式公理」。
在开放世界里，「既是女性又是男性」不违反任何公理时就是合法的。
推理机的「聪明」永远以知识库的「公理」为边界。</span>

## 5 Tableau 的工程形态与边界

真正的推理机（Pellet、HermiT、FaCT++）不是直接跑朴素 Tableau，而是
叠加了大量工程优化：

- **阻塞（blocking）**：图可能无限生长（如传递角色链），算法用
  「子图同构」检测，在重复结构处停止扩展——保证终止。
- **回溯与回跳（backjumping）**：冲突后不从头重试，而是沿冲突依赖
  精准回退到「真正犯错的分支点」。
- **缓存与合取搜索**：缓存子问题的可满足性结果，避免重复求解。
- **吸收（absorption）**：把 GCI 变换成「惰性」形式，只在相关时触发。

**重点：这些优化不改变语义，只改变速度**——同一个判定问题，
朴素 Tableau 可能跑几小时，优化后几毫秒。但别忘了复杂度上限：
SROIQ 的最坏情况是指数级的（下一节详述），优化只是让「常见情况」
变快，不能消灭「最坏情况」。<span class="marginnote">Tableau 的思想也跨界活在其他领域：
模态逻辑的可满足性判定、以及把知识图谱规则推理翻译成 Datalog 的引擎，
都在用「规则展开 + 分支搜索」的同一骨架。理解 Tableau，等于掌握了一类
「构造式判定算法」的通用设计模式。</span>

## 6 小结

- Tableau 判定可满足性的方式：**动手造模型，造得出则可满足**。
- 预处理两步：**否定范式（NNF）** 与 **TBox 内化**——把全局公理变成局部规则。
- 四条完成规则：**⊓（分解）、⊔（分支）、∃（造个体）、∀（传播约束）**。
- 判决标准：**存在完备无冲突的分支 = 可满足**；全冲突 = 不可满足。
- 可满足性证明是**构造性**的：模型被实际造出来给你看。
- 工程优化（**阻塞、回跳、缓存、吸收**）只改速度不改语义。
- 复杂度上限不变：SROIQ 最坏指数级——Tableau 快在常见，难在极端。
