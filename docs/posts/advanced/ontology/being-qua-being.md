## 为什么从「存在之问」开始

这个网站叫「从极限到大模型」。**极限**把数学从有限推向无穷，**大模型**把符号运算推向统计学习；而把这两端缝在一起的，还有一条更隐蔽的线——**我们如何精确地说「某物存在」**。机器学习要谈「实体识别」，知识图谱要谈「本体对齐」，大模型要谈「幻觉抑制」——这些工程词汇背后，都站着一个古老的哲学问题：**到底有什么（what there is）？**

从这一篇开始，本专题用两条线并进：一条**哲学线**，从亚里士多德一路走到奎因，追问「存在」作为概念的含义；一条**工程线**，从语义网络走到知识图谱与大模型，追问「存在」如何被编码成机器可处理的数据。第一章第一问，就是整个追问的起点：作为存在的存在（being qua being）。

这里也接上第一级《科学史与科学哲学》：那里我们把科学哲学拆成本体论、认识论、方法论三支，本专题就是把「本体论」这一支单独拉出来纵深挖掘；而第一级《逻辑学》给的精确语言，正是后文一切辨析的脚手架。

## 1 作为存在的存在：亚里士多德的第一哲学

**核心概念：本体论（ontology）**：关于「何物存在」的哲学分支，源自希腊语 *on*（存在之物）与 *logos*（言说 / 研究），字面即「对存在者的研究」。它在 17 世纪被命名为 *ontologia*，而亚里士多德早在《形而上学》里就奠定了这门学科的第一个纲领。

篇首引文出自《形而上学》第四卷开头。亚氏的措辞极精微——「作为存在的存在」（τὸ ὂν ᾗ ὂν，*to on hē on*），不是「存在」这个字眼，而是**存在者就其作为存在者而言**。他借此划出一条分界：

- **特殊科学**（数学、物理学、生物学）各割取存在者的一部分，研究那一部分的属性；
- **第一哲学**不割取，它研究「存在者就其为存在者而言」所具有的属性——即一切特殊科学共同预设、却都不专门处理的那个地基。

**重点：存在不是一种属性。** 日常语言里「存在」像属性——「老虎存在」仿佛「老虎是黄的」。但亚里士多德指出，存在不是老虎的属性清单里的一项；它是老虎「在」的那个方式。追问「存在是什么」，不是追问某个存在者，而是追问「是（to be）本身」的分层结构。

紧接着亚氏给出关键观察：**存在以多种方式被言说（τὸ ὂν λέγεται πολλαχῶς，*to on legetai pollachos*）**——「这是一个人」「这人是聪明的」「这人在雅典」三句话里的「是」，意味各不相同：第一个是实体，第二个是性质，第三个是处所。但它们并非各说各话，而是**都朝向一个中心意义——实体**。这种「一个中心、多种派生」的结构，亚氏称为 *pros hen*（朝向一个东西），现代哲学称「核心意义」（focal meaning）。<span class="marginnote">「存在以多种方式被言说」是亚里士多德本体论的总开关：它拒绝把「存在」当作单义概念（那样会抹平一切差别），也拒绝把它当作纯歧义的同音词（那样会切断统一性），而主张「以实体为中心的派生统一」。后文讲范畴、讲实体优先性，都是这一句的展开。</span>

这里已经埋下与《逻辑学》的接头：**系词「是」的多义性，是谓词逻辑诞生之前，哲学对「S 是 P」结构最深刻的处理。** 第一级《逻辑学》里我们学会把「苏格拉底是会死的」翻译成 $\mathrm{Mortal}(\mathrm{Socrates})$，把多义系词压缩进谓词；而亚里士多德的问题是：这种压缩究竟丢掉了什么？<span class="marginnote">这句话预告了第二篇《分析传统》的叙事：弗雷格、罗素正是用函数—变元逻辑重新回答「存在是什么」，最后被奎因总结为「存在就是成为约束变量的值」。两千年后，哲学回到亚里士多德的问题，却用上了《逻辑学》给的精确语言。</span>

## 2 本体论与认识论：两个不同的问题

**辨析｜易错点：本体论问「何物存在」，认识论（epistemology）问「我们如何知道」。** 两者常被混为一谈，尤其在汉语语境里「本体论」经常被误读成「关于本质的认识论」。严格区分：

- **本体论（ontology）**：世界有什么？候选答案包括实体、属性、关系、事件、共相、殊相……
- **认识论（epistemology）**：我们如何知道世界有什么？这涉及感知、推理、证据、真理理论……

近代哲学以笛卡尔为界，一度让认识论先行——先把「我能知道什么」立住，再谈「有什么」。而亚里士多德—中世纪传统则把本体论放在前面。20 世纪分析哲学（尤其奎因）则指出：两者其实缠绕在一起——**你接受什么样的理论，就承认什么样的存在者；认识与存在在「理论承诺」处合流**。<span class="marginnote">这一分工在计算机科学里有直接投影：知识图谱里的「模式（schema）」是本体论意义上的承诺——系统承认哪些类别存在；而「查询 / 推理算法」是认识论意义上的——系统如何从既有断言推出新断言。Schema 与 query 的区分，正是 ontology 与 epistemology 的工程投影。</span>

## 3 存在论的基本范畴：实体、属性、关系

亚里士多德在《范畴篇》中给出存在者的十种分类，称为**十个范畴（category）**：实体、数量、性质、关系、处所、时间、姿态、状态、动作、承受。范畴是对存在者「最一般的谓述方式」——任何句子对某物的言说，最终都能归入这十类之一。

其中**实体（substance，ousia）**是中心的、独立的：实体不依存于其他东西而存在，其余九个范畴都是「属于某个实体的存在方式」。亚氏进一步区分：

- **第一实体**：个别的事物，如「苏格拉底」「这匹马」；
- **第二实体**：属与种，如「人」「动物」——它们是谓述第一实体的方式。

**重点：实体是主词，属性与关系是谓词；主词可以独立存在，谓词不能脱离主词存在。** 这是整个西方本体论的第一张骨架，也是后世无数争论（共相问题、束理论、模态本质主义）的原点。用《逻辑学》的语言说：实体落在论域里的个体上，属性与关系落在谓词上。<span class="marginnote">「关系」作为独立范畴值得单独注意：在十范畴里它是唯一涉及两个以上对象的范畴。今天的数据库、知识图谱、图神经网络全部建立在关系之上——两千年后，「关系」从哲学范畴变成了计算基础设施。这个接点到第二级《离散数学》的关系与图论。</span>

这张骨架会完整地投影到工程线：**实体 → 个体（individual），属性 → 属性（property），关系 → 关系（relation），范畴 → 类（class）**。哲学用两千年想清楚的主—谓结构，恰好就是 RDF 三元组「主语—谓词—宾语」的哲学原型。

## 4 知识表示线：本体 = 显式规范的概念化

从本节起转入工程线。1993 年，斯坦福大学的 Tom Gruber 给出知识表示界引用最多的定义：

**核心概念：本体（ontology）**：**一个概念化的显式规范（an explicit specification of a conceptualization）**。

拆开这八个字：

- **概念化（conceptualization）**：我们对世界某一部分（论域）的一套抽象模型——有哪些对象、哪些类别、哪些关系。它是「认知层面的世界模型」。
- **显式（explicit）**：这套模型必须被写出来、命名出来，而不是藏在代码注释或程序员的脑子里。
- **规范（specification）**：必须用某种语言给出形式化描述，使得机器能解析。

1998 年 Studer 等人补了一个词，成为更常用的版本：**本体是一个共享的（shared）、形式化的（formal）概念化显式规范**。「共享」意味着它被一个社群共同接受，「形式化」意味着它落到可计算的逻辑语言上。<span class="marginnote">「共享」把工程本体与个人头脑里的概念分开：一个人的私人心智模型不是本体，因为它无法被检验、被复用。知识表示里的「本体」天然是社会性的——它必须能被多个人、多个系统共同解释。</span>

对照哲学线：**哲学本体论追问「何物真实存在」，工程本体论规定「我们承诺系统里存在什么」**。工程本体不直接回答「宇宙真相」，而是回答「在我们的系统里，我们把什么当作存在」——这正是第二篇奎因「本体论承诺」的工程化。

## 5 一个本体的四要素：类、个体、关系、公理

无论用 OWL、RDFS 还是知识图谱的 schema，一个本体的骨架都是四类构件：

1. **类（class / concept）**：对对象的分类，如「人」「组织」「事件」；类构成层次（taxonomy），上层类涵盖下层类。
2. **个体（individual / instance）**：类下的具体成员，如「苏格拉底」「张三」。
3. **关系（relation / property）**：个体之间（对象属性）或个体与值之间（数据属性）的联系，如「作者」「出生于」「创建于」。
4. **公理（axiom）**：对以上三者的约束，如「人是动物的子类」「人与组织不相交」「一本书至少有一个作者」。

下面的 OWL 2 片段（Turtle 语法）演示这四个构件如何落到形式语言。它比人类语言「显式」在哪？**每一句都带 IRI（全局唯一的名字），每一句都有确定的逻辑语义**：

```turtle
# OWL 2（Turtle 语法）：一个微型本体的四要素
@prefix :   <http://example.org/onto#> .
@prefix owl:  <http://www.w3.org/2002/07/owl#> .
@prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .

# 类（class）：定义分类
:Person       a    owl:Class .
:Organization a    owl:Class .
:Author       a    owl:Class ;
              rdfs:subClassOf :Person .        # 公理：Author 是 Person 的子类
:Book         a    owl:Class .

# 关系（property）：定义对象属性
:authorOf  a  owl:ObjectProperty .
:Person  owl:disjointWith :Organization .       # 公理：两个类不相交

# 个体（individual）：类下的具体成员
:ZhangSan  a         :Person ;
           :authorOf :krcBook .
:krcBook   a         :Book .
```

对照前节的哲学范畴：这里的 `:Person` / `:Book` 是「范畴 / 类」，`:ZhangSan` / `:krcBook` 是「第一实体 / 个体」，`:authorOf` 是「关系」，`rdfs:subClassOf` 与 `owl:disjointWith` 是「公理」。**亚里士多德的主—谓—实体骨架，在 21 世纪变成了主语—谓词—宾语（SPO）三元组**——`<:ZhangSan> <:authorOf> <:krcBook>`，即 RDF 的基本数据单位。

## 6 语义网与知识图谱：本体在计算机中的角色

为什么「显式规范」如此重要？因为要让**机器之间**共享理解。2001 年 Berners-Lee、Hendler、Lassila 在《科学美国人》提出**语义网（Semantic Web）**愿景：给网页数据加上机器可读的语义标注，使 Web 从「给人看的文档网」升级为「给机器看的数据网」。技术栈自下而上：IRI → RDF 数据模型 → RDFS / OWL（本体语言）→ 推理与查询（SPARQL）。本体的角色是**给数据提供模式层（schema）与逻辑约束**——就像关系数据库的 DDL 之于数据行，但语义更强、且面向开放世界。

2012 年 Google 发布**知识图谱（Knowledge Graph）**，把这一套工程推向产业：用「实体—关系—实体」的三元组网回答搜索问题（如「李白写了哪些诗」）。背后的 Freebase、DBpedia、Wikidata 都是大规模本体实例库——Wikidata 的每一条陈述都是 SPO 三元组，项与属性都有稳定的 Q-编号 / P-编号。<span class="marginnote">知识图谱在工程上淡化了「先建本体再填实例」的严格顺序，常自底向上从数据抽取实体关系；但 schema 层仍然存在——它定义图里有哪些类型、哪些边合法。没有 schema 的「图」只是点线图，有了 schema 才成「知识图谱」。这一点在第八篇《知识图谱》会反复出现。</span>

与主线衔接：**大模型时代的幻觉抑制、GraphRAG、Agent 的世界模型，本质上都是让统计模型「锚定」在一个显式共享的概念化之上**——这正是第九篇「知识图谱 × 大模型」的内容。先在这里立住一个判断：**大模型记住的是分布，本体承诺的是存在；前者擅长生成，后者擅长校验。**

## 7 核心对比表：哲学本体论 vs 计算机本体论

本主题以概念辨析为主、无核心公式，故以「核心对比表」代替公式解析——按编辑章程第 5 节执行。

| 维度 | 哲学本体论 | 计算机本体论 |
| --- | --- | --- |
| 问题 | 何物**真实地**存在？ | 我们**承诺**系统里存在什么？ |
| 存在者 | 实体、属性、关系、共相、殊相 | 类、个体、关系、公理（OWL 构件） |
| 真值来源 | 形而上学论证（无实验） | 与共享概念化的一致、推理的可判定性 |
| 方法 | 范畴分析、概念辨析、思想实验 | 本体工程方法论（METHONTOLOGY、NeOn） |
| 失败方式 | 承诺了不存在的实体 / 遗漏了真实实体 | 概念模型与数据不一致、推理不可判定 |
| 检验标准 | 与直觉、理论、科学图景的融贯 | 能力问题（competency questions）能否被回答 |
| 社会维度 | 学派与传统的承诺 | 社群共享、本体复用、标准对齐 |

这张表里「真值来源」一行最值得停留：哲学本体论没有实验可做，它靠**论证与融贯**；工程本体论有「验收」——本体是否支撑了查询与推理、是否对齐了社区标准。**但两者共享同一个姿态：存在者不是理所当然的，而是被构造、被承诺、被批判的。**

## 8 两线如何汇合

双线并非「哲学讲完换工程讲」，而是在三个点互相支撑：

1. **术语同构**：实体 / 属性 / 关系 ↔ 类 / 个体 / 关系 / 公理。哲学的范畴分析为工程的数据建模提供了两千年打磨的概念直觉。
2. **承诺同构**：哲学「本体论承诺」告诉我们，任何理论都偷偷承诺了一组存在者；工程本体把这种承诺**显式化**，让系统的「世界假设」可以被审查、被对齐、被批评。显式化正是 Gruber 定义的核心，也是知识表示工程对哲学「存在之问」的直接回答。
3. **问题回流**：工程实践反过来给哲学提新问题——「关系」在知识图谱里成了头等公民；模态、部分—整体、时间延续这些哲学议题，在本体工程里（BFO、DOLCE 等上层本体）都成了实际设计决策。<span class="marginnote">上层本体（BFO、DOLCE、SUMO）是两线汇合最具体的产物：它们用工程语言实现哲学争论——比如「一物在时间中是延续存在（endurantism）还是延展存在（perdurantism）」的哲学之争，在 BFO 里被翻译成 continuant / occurrent 两个类。第七篇《本体工程》会专章处理；这也呼应第十篇范畴论的一句话——「对象由它的关系网络决定」，Yoneda 引理几乎是本体论的结构主义翻译。</span>

下方示意图把这三层汇合画成一条完整的流：哲学线从「存在之问」走向「本体论承诺」，工程线从「概念化」走向「语义网 / 知识图谱」，三条虚线把两线的术语一一对应，最终汇入一个椭圆——**显式、共享、可计算的概念化**。

## 9 小结

- **作为存在的存在（being qua being）**：亚里士多德的第一哲学纲领——不研究存在者的某一类，而研究「存在者就其为存在者」的性质；存在是多义的，但以实体为中心派生地统一。
- **本体论 vs 认识论**：一个问「有什么」，一个问「怎么知道」；20 世纪分析哲学（奎因）指出二者在理论承诺处缠绕。
- **存在论基本范畴**：十范畴之中，实体（第一实体 / 第二实体）为主词，属性与关系为谓词。
- **Gruber 定义**：本体是「概念化的显式规范」；Studer 补全为「共享的、形式化的、显式的概念化规范」。
- **本体四要素**：类、个体、关系、公理；在 OWL 中对应 `owl:Class`、`rdf:type`、`owl:ObjectProperty`、`rdfs:subClassOf` 等构子，落成 SPO 三元组。
- **两线汇合**：术语同构、承诺同构、问题回流；语义网 / 知识图谱 / 上层本体是工程对哲学「存在之问」的现代化回应。

在下一节，我们将走进《范畴篇》本身：十种范畴究竟如何划分，「实体」为什么被亚里士多德放上唯一中心的宝座——那是整个西方本体论的第一份详细图纸。
