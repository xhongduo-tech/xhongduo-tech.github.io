## 为什么从 schema 约束生成开始

上一节我们看到 LLM 抽取需要「纪律」——这个纪律就是 **schema**。
这一节把「用 schema 约束 LLM 输出」单独放大：它本质上是
**本体论「自顶向下」纪律在 LLM 时代的回归**——你不让模型自由发挥，
而是给它一张「本体的图纸」（schema），强制它的输出落在图纸上。
约束方式从「提示词劝导」到「解码期硬约束」到「校验重试」，
强度递增。理解 schema 约束生成，你就明白了 LLM 如何
从「自由生成器」变成「受约束的结构填充器」——
这是第九篇所有工程（抽取、GraphRAG、Agent）的底层机制。

## 1 为什么必须约束：自由生成的代价

LLM 默认输出是**自由文本**——对聊天很好，对工程是灾难：

- **不可解析**：没有固定结构，程序无法直接消费。
- **字段漂移**：同样的信息，这次叫 `name`、下次叫 `fullName`。
- **类型混乱**：`age` 时而是数字、时而是字符串。
- **幻觉放大**：自由输出里，编造的字段与真实字段混在一起。

**重点：schema 约束是「把 LLM 的生成从『作文』变成『填表』」。**
给定 schema，模型的搜索空间被限定——它只能输出结构合法的内容。
**这不是限制模型，而是让模型「精确地胡说」的概率降低**：
结构的约束卡掉了一部分自由发挥的空间。<span class="marginnote">「约束 = 降低自由度 = 降低幻觉」
是 LLM 工程的第一原理之一：模型的幻觉往往发生在「没被约束」的
自由角落。<strong>给模型越多的结构约束，它发挥的「危险空间」越小</strong>——
这与第六篇 SHACL「封闭世界约束」的思想一脉相承。</span>

## 2 三种约束方式：提示、解码、校验

约束 LLM 输出的技术分三档，强度递增：

| 方式 | 原理 | 强度 | 代表 |
| --- | --- | --- | --- |
| 提示约束 | 在提示里写 schema + 示例，劝导模型遵守 | 弱（可违背） | few-shot |
| 约束解码 | 解码时用语法屏蔽非法 token | 强（不可违背） | Outlines、Guidance、JSONformer |
| 校验重试 | 生成后校验，不合格重生成（带错误反馈） | 中（靠循环） | JSON Schema 校验 + retry |

- **提示约束**：最简单，但模型「偶尔不听话」——schema 复杂时
  输出常错。
- **约束解码（constrained decoding）**：在模型逐 token 生成时，
  用一个「语法掩码」只允许产出「能保持输出合法」的 token——
  **结构上不可能错**（前提是模型能完成）。
- **校验重试**：生成 → 用 JSON Schema/SHACL 校验 → 不合格
  就把错误喂回提示重生成——**靠循环逼近合法**。

**重点：三档是「信任模型」到「不信任模型」的光谱。**
提示靠模型自觉，解码靠机制保证，校验靠循环兜底。**工程上
常用「解码 + 校验」组合**：解码保证语法合法，校验保证语义合法
（语法对了、字段值可能仍不对）。<span class="marginnote">约束解码是「把形式语义
前置到生成」：模型还没说出下一个词，语法引擎就排除了
「会破坏 JSON 结构」的词。<strong>这相当于给 LLM 装了一个
「在线语法检查器」</strong>——是「生成 + 校验」从后置变成前置的
极致形态，也是第四篇「规则系统」纪律在生成时代的翻版。</span>

## 3 公式解析：一次约束生成的走查

设 schema 要求输出「人物卡片」：

```json
{
  "type": "object",
  "properties": {
    "name": {"type": "string"},
    "age": {"type": "integer", "minimum": 0},
    "employer": {"type": ["string", "null"]}
  },
  "required": ["name", "age"]
}
```

- **第一步，编码**：schema 编译成「语法状态机」。
- **第二步，约束解码**：模型生成 `{"name": "` 之后，解码器
  知道「下一个必须是字符串，且最终要闭合 `"`」——只允许
  字符串 token；生成 `"age":` 后，只允许整数 token。
- **第三步，完成**：模型结束生成时，语法状态机确认
  「JSON 完整合法」。
- **第四步，语义校验**（可选）：`age` 是否为非负整数、`employer`
  是否为 string 或 null——语法之外的语义检查。

**重点：语法约束管「形状」，语义校验管「值」。**
约束解码保证「输出是合法 JSON」，但 `age: -5` 仍是合法的
JSON——语义对不对要靠第二层校验。**「解码保形 + 校验保义」
是分层防线**，与第五篇「TBox 管语义、SHACL 管校验」的结构一致。<span class="marginnote">把这里的
「schema + 校验」翻译成本书语言：<strong>schema 就是 TBox（术语约束），
校验就是 SHACL（形状约束），LLM 的输出就是 ABox 断言</strong>。
「约束生成」的本质，是<strong>让 LLM 的 ABox 填充服从 TBox 公理</strong>——
本体工程的顶层纪律，在生成式 AI 里重新上岗。</span>

## 4 schema 即本体：知识图谱意义

约束生成在知识图谱里的深层意义，值得单独点破：

- **schema = 本体的投影**：`properties`、`required`、`type`——
  对应 TBox 的属性、基数约束、类型约束。
- **约束输出 = 受约束的 ABox**：LLM 生成的每条记录都是
  「符合 TBox 的断言」。
- **自然语言 → 结构化**：约束生成把「自由文本」翻译成
  「本体友好的结构」，省去下游大量清洗。

**重点：约束生成是「自顶向下」在 LLM 时代的复活。**
第八篇说「自底向上」因 LLM 空前可行，而约束生成
把「自顶向下」的 schema 纪律重新装回管道——**两者合流为
「schema 约束的自底向上」**：数据从下往上涌，schema 从上往下
卡口，中间是约束生成这个「过滤器」。<span class="marginnote">这个「双向合流」是
第九篇最重要的架构洞见之一：<strong>LLM 没有终结「自顶向下 vs
自底向上」之争，而是把两者的精华焊接成新范式</strong>——
schema 提供纪律，LLM 提供产能，约束生成是焊接点。
理解这一点，就理解了整个 LLM 图谱时代的骨架。</span>

## 5 价值与局限

**价值：**

- **结构合法**：输出可解析、字段稳定、类型正确。
- **幻觉降低**：结构约束卡掉部分自由发挥。
- **直接入库**：约束输出可省下游大量清洗。
- **schema 演进**：改 schema 即改约束，管道快速适配。

**局限：**

- **表达受限**：过于严格的 schema 会截断模型表达
  （真实世界信息装不进模板的部分被丢弃）。
- **约束解码成本**：语法掩码增加生成开销，且与某些采样策略冲突。
- **语义仍然不可靠**：结构合法 ≠ 内容正确——幻觉还在值里。

**重点：约束生成治「形」不治「义」。** 它保证输出「长得好」，
不保证「说得对」——`name: "孙悟空"` 结构完全合法，但可能是
模型编的。**「形」靠 schema，「义」靠知识图谱锚定**——这正是
第 9 节「幻觉抑制」的主题。约束生成是防线的第一层，不是全部。

## 6 小结

- **schema 约束生成**：用 schema 限定 LLM 输出，从「作文」变「填表」。
- 三档约束：**提示约束（弱）、约束解码（强）、校验重试（中）**。
- **约束解码**：语法状态机在解码期屏蔽非法 token——结构上不可能错。
- 分层防线：**解码保「形」，校验保「义」**。
- 知识图谱意义：**schema = TBox，约束输出 = 受约束的 ABox**。
- 架构洞见：**约束生成 = 「自顶向下纪律」×「自底向上产能」的焊接点**。
- 局限：**治形不治义**——内容正确要靠图谱锚定（第 9 节）。
