# GraphRAG：基于图结构的检索增强生成

<div class="epigraph">
<p>检索增强生成给大模型配了「外置记忆」；GraphRAG 把这份记忆从碎片升级成结构——让 LLM 能回答「整体」的问题。</p>

## 为什么从 GraphRAG 开始

上一节我们立下「图谱 × LLM 互补」的总纲，这一节进入旗舰组件——
**GraphRAG（Graph Retrieval-Augmented Generation）**。朴素 RAG
把文档切成碎片、用向量相似度检索，能答「单点」问题，
却在「全局/多跳」问题上翻车。GraphRAG 用知识图谱做检索结构：
**局部查询**沿实体子图遍历（多跳证据），**全局查询**聚合社区摘要
（全景回答）。它是「图谱给 LLM 装记忆」最成熟的工程形态，
也是微软 2024 年论文引爆的实践。理解 GraphRAG，
你就掌握了「图谱 × LLM」从理念到产品的主干道。

## 1 朴素 RAG 与其瓶颈

**检索增强生成（RAG）**（Lewis et al., 2020）：检索相关文档片段，
拼进提示词作为上下文，让 LLM 基于它们作答。它治好了
「知识截止」与部分「幻觉」——答案有了外部依据。

但**朴素 RAG（向量检索）有三个瓶颈**：

- **碎片化**：文档被切成 chunk，一条知识散落多处，检索不全。
- **全局盲区**：问「这个语料库的主线主题是什么」——没有哪个 chunk
  包含答案，向量检索必然失败。
- **多跳弱**：问「A 的供应商的竞争对手」——需要跨多个 chunk 推理，
  检索到的碎片连不成证据链。

**重点：朴素 RAG 是「检索段落」，GraphRAG 是「检索结构」。**
段落是**局部**的（一段文档），结构是**关系**的（实体—关系网络）。
**当答案需要「多跳」或「全局」时，段落检索的结构缺陷就暴露了**——
GraphRAG 正是为补这个缺陷而生。<span class="marginnote">把 RAG 放回本书坐标：
它是第四篇「替身」思想的 LLM 版——检索到的上下文是「世界的替身」，
让模型靠「读」而非「记」作答。朴素 RAG 的替身是「碎片文档」，
GraphRAG 的替身是「结构化子图」——<strong>替身的结构越好，思考越可靠</strong>。</span>

## 2 GraphRAG 的构建管线：从文本到社区摘要

GraphRAG（微软版）的构建分三步：

1. **图谱抽取**：用 LLM 从语料库抽取实体与关系，建成知识图谱
   （下一节专讲）。
2. **社区检测**：用图算法（如 Leiden）把图谱划分成
   **社区（community）**——稠密相连的实体簇。
3. **社区摘要**：对每个社区，用 LLM 生成**层级化摘要**
   （小社区 → 中社区 → 大社区，自底向上聚合成树状摘要）。

**重点：社区摘要是 GraphRAG 的「全局记忆」。**
每个社区摘要概括了「这一簇实体讲了什么故事」——从叶级社区
（细粒度）到根级社区（全语料主线）。**查询全局问题时，
不再需要命中某个 chunk，而是沿摘要树从粗到细遍历**——
这让「语料库的主线是什么」第一次能被 LLM 回答。<span class="marginnote">社区检测与
第六篇「本体网络」的结构异曲同工：社区 ≈ 图谱里的「模块」，
社区摘要 ≈ 模块的「注释」。<strong>把「网络结构」翻译成「可读摘要」，
是 GraphRAG 让 LLM 能「读图」的关键</strong>——模型读不了图，
但读得了摘要文本。</span>

## 3 GraphRAG 的查询：局部与全局双模式

GraphRAG 提供两种查询模式：

- **局部查询（local query）**：实体为中心——先把查询链接到实体，
  提取该实体的**邻域子图**（1-2 跳），把子图线性化成文本，
  作为上下文送给 LLM。适合「张三的供应商有哪些」「这个蛋白与
  哪些疾病相关」。
- **全局查询（global query）**：主题为中心——从社区摘要树出发，
  从根级摘要逐层筛选相关社区摘要，合并后作答。适合
  「这个语料库的主要论点是什么」。

**重点：局部 = 沿实体走，全局 = 沿社区摘要走。**
两种模式把「查询的粒度」翻译成「检索的结构」——
问实体走图，问全局走摘要树。**这是 RAG 从「相似度检索」到
「结构感知检索」的质变**：检索结果不再是「最像的碎片」，
而是「最相关的结构」。<span class="marginnote">局部/全局的区分在认知上
对应「分析性」与「概览性」两种思维——GraphRAG 把它们
做成了两种检索路径。工程上，<strong>复杂查询常先全局定位（哪个
社区可能含答案），再局部深挖（该社区里的具体实体路径）</strong>——
两级检索，一次回答。</span>

## 4 公式解析：局部查询的一次执行

把「张三的供应商有哪些」走一遍局部查询：

1. **实体链接**：把查询映射到图谱实体「张三」——`entity linking`。
2. **子图提取**：取张三的邻域子图（`supplies_to` 反向边 1 跳），
   得到「(供应商A, 供应给, 张三)」「(供应商B, 供应给, 张三)」。
3. **线性化**：把子图三元组写成文本：
   「张三的供应商包括：A（供应零件X，自2020）、B（……）」。
4. **生成**：子图文本 + 原始查询 + 指令 → LLM 生成答案。
5. **可溯源**：答案里的每条供应商都能指回图谱三元组——可验证。

**逐项拆解关键点：**

- **实体链接**决定了「查谁」——链接错了全盘皆错。
- **子图线性化**是「图→文本」的翻译，质量决定 LLM 能读懂多少。
- **可溯源**是 GraphRAG 相对纯 LLM 的核心价值——答案有据可查。

**重点：GraphRAG 的价值不在「更聪明的 LLM」，而在「更好的上下文」。**
检索到的子图是**结构化证据**，LLM 只是把它转述成自然语言。
**「证据在结构里，生成在语言里」**——这个分工，让答案
既流畅又可信。<span class="marginnote">子图线性化与第四篇「语义网络 → 文本」同构：
知识图谱的「图」最终要翻译成「语言」给 LLM 读。<strong>「图怎么转文字」
（三元组列表、自然语言句、表格式）是一个被低估的工程决策</strong>——
不同的线性化方式，LLM 的理解质量天差地别。</span>

## 5 变体与混合：向量 × 图谱

GraphRAG 不是唯一答案，实践里常见变体与混合：

- **混合检索**：向量检索（语义相似）+ 图检索（结构相关）双路召回，
  合并去重后送 LLM——取两者之长。
- **HybridRAG**：先向量粗召回，再用图谱校验/重排。
- **图谱增强的 chunk**：把「实体所在子图摘要」附到每个 chunk 上，
  让向量检索也能带回结构信息。
- **Self-RAG / 迭代检索**：LLM 先问自己「缺什么」，再决定
  查图还是查向量。

**重点：混合架构的原则是「按查询类型选检索器」**——单点事实
问向量，多跳关系问图，全局概览问社区摘要。**RAG 从「一种检索」
走向「检索器路由」**：让最合适的检索器回答最合适的问题。<span class="marginnote">「检索器路由」
的思想与第八篇「属性图 vs RDF」的选型同构：<strong>没有万能引擎，
只有按需路由</strong>。把查询分门别类、派给不同检索器，是 LLM 时代
信息系统的通用架构——也是第九篇 Agent 记忆一节要系统化的主题。</span>

## 6 价值与挑战

**价值：**

- **多跳推理**：子图遍历提供「跨实体」的证据链。
- **全局回答**：社区摘要让「整体问题」第一次可答。
- **幻觉抑制**：答案锚定图谱事实（第 9 节专讲）。
- **可溯源**：每条答案都能指回结构证据。

**挑战：**

- **构建质量**：图谱抽取得准，GraphRAG 才好——抽取噪声会放大。
- **线性化损失**：图→文本翻译可能丢失关系细节。
- **成本**：构建社区摘要要大量 LLM 调用，构建成本不低。

**重点：GraphRAG 的上限由「图谱质量」决定。** 它不能凭空造知识，
只能把图谱里的知识更聪明地捞出来。**「建好图」是 GraphRAG 的
前置条件**——这正是下一节「LLM 驱动的知识抽取」要解决的问题。<span class="marginnote">GraphRAG 的
成熟度提醒我们：<strong>「检索增强」不是终点，而是「记忆工程」的开始</strong>。
当图谱成为 LLM 的「结构记忆」时，下一个问题自然浮现——怎么让
这个记忆长期保持、随用随新？那就是第 6 节「Agent 的世界模型」的
领地。GraphRAG 与 Agent 记忆，共享同一张图谱，只是面向不同的任务。</span>

## 7 小结

- **GraphRAG**：用知识图谱结构做检索的 RAG，局部 + 全局双模式。
- 朴素 RAG 的三个瓶颈：**碎片化、全局盲区、多跳弱**。
- 构建三步：**图谱抽取 → 社区检测 → 社区摘要**（层级化）。
- 查询双模式：**局部**（实体邻域子图）+ **全局**（社区摘要树）。
- 局部查询五步：**实体链接 → 子图提取 → 线性化 → 生成 → 溯源**。
- 价值：**多跳、全局、抗幻觉、可溯源**；挑战：**构建质量、线性化、成本**。
- 混合原则：**按查询类型路由检索器**——向量、图、社区各司其职。
