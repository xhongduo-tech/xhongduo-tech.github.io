## 为什么从匹配对齐开始

前几节我们都假设「一个本体」——可现实是**本体总是多个**：
两套医学标准、合并前的两个公司图谱、BFO 与 DOLCE 两套顶层。
它们怎么共存？答案是**本体匹配（ontology matching）**：
自动发现两个本体的实体之间的**对应关系（correspondence）**，
如「这个本体的 `轿车` 等价于那个本体的 `汽车`」。这一步是
数据集成、本体合并、跨本体查询的枢纽。理解匹配对齐，
你就掌握了「本体网络时代」的核心引擎——也顺带为第八篇的
「实体对齐」预演了大部分思想。

## 1 问题设定：匹配、对齐、映射

先理清术语：

- **匹配（matching）**：找对应关系的过程。
- **对应（correspondence）**：一条「实体对 + 关系类型 + 置信度」，
  如（`:轿车`，`:汽车`，`≡`，0.9）。
- **对齐（alignment）**：全部对应关系的集合。
- **映射（mapping）**：被实际采用/执行的对齐（如用于数据转换）。

**重点：匹配是「找」，对齐是「集合」，映射是「用」。**
三者是同一工作的三个阶段——先找候选对应，再汇集为对齐，
最后把对齐变成可执行的转换规则。**工程上常把「对齐」当成
可以生成 SPARQL/规则代码的产品**，用于两个系统的数据互通。

## 2 匹配技术分类

匹配技术大体分两级，各有武器：

| 层级 | 技术 | 依据 | 例子 |
| --- | --- | --- | --- |
| 元素级 | 字符串相似度 | 名字、标签的字符相似 | Levenshtein、n-gram |
| 元素级 | 语言学 | 词典、同义词 | WordNet 同义词 |
| 元素级 | 属性相似 | 注释、数据类型 | label/comment 匹配 |
| 结构级 | 图传播 | 邻域结构相似 | 相似度传播（Similarity Flooding） |
| 结构级 | 分类学 | 共同祖先/子类 | 父类相似、子类相似 |
| 实例级 | 实例重叠 | 共享实例推断类等价 | 两个类有相同实例 → 类相似 |

**重点：层级越深，越可靠，但越贵。** 字符串匹配便宜但误报多
（`User` 与 `userId` 不一定同义）；结构匹配利用邻域，能发现
「名字不同但位置相同」的类；实例匹配最可靠但要求数据重叠。
**成熟匹配器把多级证据加权融合**——这就是匹配流水线的核心。<span class="marginnote">匹配技术的
分层与第四篇「知识表示五角色」异曲同工：每层证据回答一个不同的问题——
名字像不像（表面）、结构像不像（位置）、实例像不像（内容）。
「像」是一个多义词，匹配器要做的是把不同意义的「像」加权合成一个分。</span>

## 3 公式解析：一条匹配流水线

把一次匹配拆成标准的五步流水线：

1. **规范化**：两个本体的标签统一（去空格、统一大小写、分词）。
2. **元素级相似度**：对每对实体算名字/标签相似度 $s_{elem}(e_1, e_2)$。
3. **结构级相似度**：基于图结构算相似度 $s_{struct}(e_1, e_2)$。
4. **加权融合**：总相似度 $s = w_1 \cdot s_{elem} + w_2 \cdot s_{struct}$。
5. **阈值选择**：$s \geq \theta$ 的配对输出为对应关系（附置信度）。

**逐项拆解第 4 步的融合公式：**

- **$s_{elem}$**：来自字符串/语言学的表面相似度。
- **$s_{struct}$**：来自邻域结构的结构相似度。
- **权重 $w_1, w_2$**：可调——纯词典场景 $w_1$ 大，纯结构场景 $w_2$ 大。
- **阈值 $\theta$**：权衡 precision/recall——调高更准、调低更全。

**重点：融合公式是「证据加权」的抽象**——所有匹配器的差异，
本质都是「选哪些证据、怎么加权、怎么定阈值」。**没有放之四海
皆准的权重，只有「在这个数据集上调出来」的权重**——这解释了
为什么 OAEI 评测（下一节）如此重要。<span class="marginnote">融合公式的调参
哲学呼应了第二级《机器学习》：匹配器与分类器是同一类东西——
都是「特征 → 加权 → 决策」。近代匹配器甚至直接用机器学习
学权重、用 LLM 算相似度——匹配从「手工规则」走向「学习模型」，
正是第八、九篇主题的序曲。</span>

## 4 评测：OAEI 与 precision/recall

匹配质量怎么判？标准是信息检索的经典三件套：

- **精确率（precision）**：找出的对应里，多少是对的？
- **召回率（recall）**：真正的对应里，多少被找出来了？
- **F 值（F-measure）**：两者的调和平均，综合评价。

**OAEI（Ontology Alignment Evaluation Initiative）** 是匹配领域的
「世界杯」：每年发布标准测试集（真实本体对 + 人工标注的金标准），
各匹配器同台竞技。测试集覆盖从「同名本体」到「跨语言、跨结构」
的难度梯度。

**重点：评测揭示「匹配没有银弹」**——在「名字相似」的简单集上
字符串方法称王，在「结构不同、实例不同」的困难集上连最好的
匹配器也只有中等 F 值。**工程上必须「先测后选」**：用贴近自己
数据的测试集评估候选匹配器，而不是迷信「最强品牌」。<span class="marginnote">OAEI 的
历史还揭示一个趋势：<strong>匹配从「纯符号」走向「符号 + 统计」</strong>——
近年加入 LLM 的匹配器在语义相似度上显著提升（第九篇详述）。
评测基准的演化，忠实记录了匹配技术的代际更替。</span>

## 5 对齐的工程应用

对齐不是纸面练习，它驱动真实系统：

- **数据集成**：两个数据库 schema 对齐后，数据才能互转。
- **本体合并**：对齐是合并的前提——合并器按对应关系归并类。
- **跨本体查询**：对齐让「查这个本体」能自动映射到「查那个本体」。
- **知识图谱实体对齐**：第八篇的「实体对齐」是本体的个体级版本——
  对齐类与属性，对应消解个体与关系。

**重点：匹配与实体对齐是「同一个问题的两个尺度」**——匹配处理
「类与属性」的对齐（schema 级），实体对齐处理「个体」的合并
（数据级）。两者在知识图谱构建里常常**级联使用**：先对齐 schema，
再用 schema 对齐指导实例合并。<span class="marginnote">工具生态值得认识：
<strong>LogMap、AML（AgreementMakerLight）</strong> 是近年 OAEI 的常胜军，
支持结构 + 逻辑 + 实例的多策略匹配。它们把本书前半的
「相似度计算 + 推理校验」全部工程化——对齐工具是「本体工程
全栈」的缩影。</span>

## 6 小结

- **匹配**找对应，**对齐**是集合，**映射**是执行——同一工作的三阶段。
- 对应关系 = **实体对 + 关系类型 + 置信度**。
- 技术分两级：**元素级**（字符串、语言学）与**结构级**（图传播、分类学），
  实例级最可靠。
- 匹配流水线五步：**规范化 → 元素相似 → 结构相似 → 加权融合 → 阈值选择**。
- 评测看 **precision/recall/F 值**；OAEI 是匹配领域的标准竞赛。
- 应用：**数据集成、本体合并、跨本体查询、实体对齐的级联**。
- 趋势：匹配从手工规则走向 **ML/LLM 语义匹配**——第九篇的前奏。
