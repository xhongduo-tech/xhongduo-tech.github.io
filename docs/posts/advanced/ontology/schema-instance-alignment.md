# 模式对齐与实例对齐的技术路线

<div class="epigraph">
<p>两个知识图谱要对齐，对齐的从来不是一层，而是两层：类要找到同名的类，个体要找到同一个个体——而且这两层互相喂证据。</p>

## 为什么从两种对齐开始

上一节我们处理了「个体级的同一」，第七篇处理过「类级的匹配」。
但真实的知识融合中，**这两层是纠缠在一起的**：模式（schema）对齐
与实例（instance）对齐不是两条独立路线，而是**互相喂证据的双循环**——
类对齐了，同类的实例更容易对齐；实例大量对齐了，反过来说明
它们的类也是同一类。理解「模式对齐 × 实例对齐」的协作结构，
你就掌握了知识融合的完整纵深——这是构建跨语言、跨来源
大图谱的核心技能。

## 1 两层对齐的分工

**模式对齐（schema alignment）**：对齐**类与属性**——「A 图谱的
`Person` 类等价于 B 图谱的 `Human`」「A 的 `hasName` 属性等价于 B 的
`fullName` 属性」。它直接继承第七篇的**本体匹配**技术。

**实例对齐（instance alignment）**：对齐**个体**——「A 图谱的
`:zhangsan` 与 B 图谱的 `:zhang-san` 是同一实体」。它正是上一节的
**实体对齐**。

| 维度 | 模式对齐 | 实例对齐 |
| --- | --- | --- |
| 对象 | 类、属性 | 个体 |
| 粒度 | schema 层 | 数据层 |
| 证据 | 标签、结构、公理 | 属性、邻居、嵌入 |
| 技术 | 本体匹配 | 实体消解 |
| 输出 | 类/属性对应 | 实体对应（sameAs 链接） |

**重点：两层对齐的输出不同——模式对齐产出类/属性映射，
实例对齐产出实体映射。** 但它们在同一个融合系统里协作：
模式对齐给实例对齐「哪两类可以比」，实例对齐给模式对齐
「哪两类真的同」。<span class="marginnote">两层的哲学对应是「类 vs 个体」
（第一篇亚里士多德的第一/第二实体）：模式对齐处理「属种」，
实例对齐处理「个体」。工程上把这两个古老范畴变成两类算法，
是本体论双线在知识工程里的又一次完整映射。</span>

## 2 双向证据：两层的循环论证

为什么必须联合？因为**每一层都为另一层提供关键证据**：

**模式 → 实例（自上而下）**：若 `Person ≈ Human`，则「Person 类的
  实例」与「人类的实例」配对时，应该优先认为它们可能是同一实体——
  **类对齐约束了实例对齐的搜索空间**。
**实例 → 模式（自下而上）**：若 `Person` 的 80% 实例与 `Human` 的
  80% 实例对齐成功，则强烈提示 `Person` 与 `Human` 是同一类——
  **实例对齐的统计结果反哺模式对齐**。

**重点：这是「证据的双向增强」**——纯粹靠标签匹配（模式层）会
被多语言、多术语卡住；纯粹靠实例匹配（实例层）会被数据稀疏
卡住；两者互喂，各自的盲区被对方补齐。**「联合对齐」的本质，
是把「类—个体」的层级结构当成约束与证据的来源。**<span class="marginnote">这个
「自上而下约束 + 自下而上证据」的结构，是 AI 里最深刻的
模式之一——第四篇的「TBox 约束 ABox + ABox 反哺 TBox」、
第七篇的「schema 约束数据 + 数据演化 schema」，都是同一个循环。
理解它，等于掌握了「层级知识系统」的通用骨架。</span>

## 3 公式解析：一条联合对齐流水线

一个典型的两层联合对齐流水线：

1. **首轮模式对齐**：用标签/结构匹配出「粗模式对齐」。
2. **实例对齐（受约束）**：在「同模式类的实例对」里跑实体消解，
   产出高置信实例映射。
3. **证据回灌**：统计「类对的实例对齐比例」，修正/扩展模式对齐
   （把高共现的类对标记为候选类对齐）。
4. **迭代**：回到第 2 步，用新的模式对齐重新约束实例对齐，
   直到收敛（两层对齐不再显著变化）。

**逐项拆解第 3 步的「统计回灌」：**

**输入**：第 2 步产出的实例对齐集合。
**聚合**：按「实例所属的类对」分组，计算每对类的对齐比例 $r$。
**决策**：若 $r \geq \tau$（如 0.7），推断这两个类等价。
**风险**：$r$ 高可能是巧合（两个大类恰好实例相似），需人工确认。

**重点：流水线的灵魂是「迭代到收敛」**——一层对齐改进另一层，
循环往复直到稳定。**这也意味着融合不是一次性任务，而是
一个持续校准的过程**，与知识图谱「持续构建」的整体节奏一致。<span class="marginnote">迭代收敛
的数学对应是「不动点」：两层对齐互相作为「函数」作用，
收敛点就是「互相一致的固定点」。这与第五篇 Tableau 的
「固定点扩展」、第四篇 TMS 的「信念收敛」是同一种
「循环直到自洽」的计算结构。</span>

## 4 挑战：什么情况下两层都会失败

联合对齐也有关键失败模式：

**类粒度不对齐**：A 的 `Animal` 粒度是 B 的 `Mammal` 粒度——类不是「等价」
  而是「包含」，模式对齐的等价建模不准确。
**数据太稀疏**：实例很少时，实例→模式的统计证据不可靠。
**错误传染**：模式对齐错了，约束的实例对齐全错；实例对齐错了，
  回灌的模式对齐也错——**错误在两层间放大**。

**易错点｜等价与包含别混用**：若 `Animal` 是
`Mammal` 的超类（不是等价），用 `owl:equivalentClass` 会错误地断言
两者互斥成员。**模式对齐的首要判断是「等价还是包含」**——
这决定了后续实例对齐的约束方式。工程上宁可用 `rdfs:subClassOf`
（弱、安全），不要轻易用 `owl:equivalentClass`（强、危险）。

## 5 LLM 时代的双层对齐

大模型让两层对齐都上了一个台阶：

**模式对齐的 LLM**：把两个类的定义/注释喂给 LLM，
  「`Person` 与 `Human` 是不是同一类？」——零样本判断类等价。
**实例对齐的 LLM**：「`:zhangsan` 与 `:zhang-san` 是同一实体吗？」
  ——语义理解替代特征工程。
**双层联合的 LLM**：甚至可以用一个提示「这两个图谱该对齐哪些
  类与实例」，让 LLM 输出候选对齐，再由规则/图谱证据校验。

**重点：LLM 让对齐从「特征 + 统计」走向「语义 + 常识」**——
但**仍需要管道与校验**：LLM 的对齐候选必须回库验证
（实例对齐结果要查 `owl:sameAs` 传递性、模式对齐要查推理机一致性）。
**LLM 负责「聪明的猜测」，规则负责「严谨的确认」。**<span class="marginnote">这个「猜测 + 确认」
分工是第九篇的主题之一：神经部分负责「开放、模糊」的判断，
符号部分负责「封闭、精确」的验证。双层对齐是第一个尝到
这套分工甜头的任务——因为它天然就是「两层的」。</span>

## 6 小结

- 知识融合分**两层**：模式对齐（类/属性）与实例对齐（个体）。
- 两层**互喂证据**：模式约束实例的搜索空间，实例统计反哺模式的等价判断。
- 联合流水线：**粗模式对齐 → 受约束实例对齐 → 统计回灌 → 迭代收敛**。
- 关键判断：**等价 vs 包含**——`owl:equivalentClass` 慎用，`rdfs:subClassOf` 更安全。
- 失败模式：**粒度不对齐、数据稀疏、错误跨层放大**。
- LLM 时代：**LLM 做聪明猜测（语义对齐）+ 规则/推理机做严谨确认**。
- 结构洞察：**「自上而下约束 + 自下而上证据」是层级知识系统的通用骨架**。
