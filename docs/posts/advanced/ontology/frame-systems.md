# 框架系统（Frames）：槽、侧面与默认值

<div class="epigraph">
<p>当你遇到一种新情况时，你会选择一个名为「框架」的结构来理解它——一个记住情境的骨架，其细节可以随情况而改变。</p>
<footer>—— 马文·明斯基（Marvin Minsky），《知识表示的框架》（A Framework for Representing Knowledge, 1975）</footer>
</div>

<div class="article-byline">
<p>第四级 · 本体论 ｜ Minsky《知识表示的框架》(1975)；Schank & Abelson《脚本、计划、目标与理解》(1977) ｜ 2026-08-07</p>

## 为什么从框架开始

上一节的语义危机告诉我们：链接若没有精确语义，图再漂亮也危险。明斯基的回应却反其道而行——
**不追求逻辑的精确，而追求常识的灵活**。他在 1975 年提出**框架（frame）**，主张知识的基本单位
不是一个孤立的节点，而是一个「带槽的结构化描述」——用来表示一个**典型情境**的骨架。
语义网络从「关系」出发，框架从「结构」出发。这条路线最终孕育了面向对象编程、专家系统外壳，
以及今天 OWL 里「类 + 属性约束」的建模方式。可以说，框架是 KR 史上被低估最深、影响最广的设计。

## 1 框架：给常识一个骨架

明斯基的出发点是人如何理解「第一次见到的东西」。你走进一间从没见过的教室，却立刻知道
「这里有黑板、课桌、讲台」——因为你调用了**「教室」框架**：一个关于典型教室的知识结构，
其中每个部分（黑板、课桌、讲台）是**槽（slot）**，槽里有默认的预期值。新情境被塞进旧框架，
细节被逐个「填槽」，不符的部分再就地调整。**理解，就是成功调用一个框架去消化新输入。**

**框架（frame）**：表示某类典型对象或情境的数据结构——它由**框架名**、一组**槽（slot）**
与槽的**侧面（facet）**构成。槽描述该对象的属性或组成部分，侧面则规定槽的取值方式
（默认值、类型约束、取值过程等）。

明斯基强调框架的**层级组织**：框架可以继承——「教室」是「房间」的子类，
于是「房间有门、窗」自动传给「教室」。这与语义网络的继承同源，
但框架把继承落实为「子框架继承父框架的槽」，并允许子框架**局部覆盖**。
<span class="marginnote">注意框架的「常识主义」立场：明斯基从不承诺框架有逻辑的精确性，
他声称知识表示要像人一样「先默认、再修正」。这与伍兹要求精确语义的主张针锋相对——
一场「常识 vs 精确」的路线之争，贯穿了此后四十年的 KR 历史。</span>

## 2 槽、侧面与默认值

一个教室框架的骨架可以写成：

```
教室框架:
  槽 天花板: 白色(默认) | 类型: 颜色
  槽 课桌:  数量 30(默认) | 类型: 正整数
  槽 黑板:  存在 是 | 约束: 必须有
  槽 用途:  教学(默认) | IF-NEEDED: 询问管理员
```

解读其中三种机制：

- **槽（slot）**：框架的属性位，如「天花板」「课桌」。
- **侧面（facet）**：槽上的修饰信息，如「默认值」「类型」「约束」。
  同一个槽可以有多个侧面，分别规定它的默认、范围与触发过程。
- **默认值（default）**：槽没有显式填充时自动采用的假定值。
  教室默认有 30 张课桌——走进一间教室你默认它有课桌，直到数出 28 张再修正。

**重点：默认值是框架的灵魂。** 它让表示在信息不全时仍能推理，代价是非单调——
新事实可以推翻默认结论。上一节鸵鸟的继承问题，在框架里被正面接受：
「鸟会飞」是鸟框架「飞行」槽的默认值，「鸵鸟」框架覆盖为「不会飞」。
**框架把「例外」变成了语言的一等公民，而不是逻辑的异端。**<span class="marginnote">默认值在今天的本体语言里以
`owl:someValuesFrom`（存在约束）与 OWL 的「开放世界」语义得以部分继承——但注意，OWL 刻意
<strong>不提供默认值构造子</strong>，因为它会让推理非单调、破坏可判定性。框架的默认值遗产，
更多活在编程语言的默认参数、对象缺省值里，而非语义网标准里。</span>

## 3 继承与局部覆盖：框架的推理

框架的推理机制就是**沿框架层级继承槽、并按优先级覆盖**。规则大致如下：

1. 实例化一个框架时，先取它所有祖先框架的槽与默认值；
2. 若本框架显式声明了某槽的值，以本框架为准（**局部覆盖**）；
3. 若多个祖先给同一槽不同默认值，按「最具体优先」（most specific wins）裁决；
4. 槽值为空且无默认时，触发其 `IF-NEEDED` 侧面去求值（见下一节）。

这套规则让框架系统能回答「这间教室能坐多少人」而不必显式存储答案——
沿继承链累加课桌默认值再与容量约束比较即可。**框架的「知识量」不在显式事实，
而在继承结构与默认假设的组合。** 这与现代知识图谱的「本体 + 规则」思路完全一致。

**易错点｜局部覆盖要小心「最近邻」陷阱**：当两个祖先框架（如「鸟」与「宠物」）
都给「食性」槽设了不同默认值（虫子 vs 猫粮），「最具体优先」并不总能裁决——
到底哪个更具体？框架系统需要额外的**偏序约定**（如子类优先级、深度优先），
约定不同，同一只宠物鸟的食性结论就不同。**默认推理的歧义，从继承网络一路带进了框架。**

## 4 过程附件与脚本：让框架动起来

框架不只是静态数据，它允许在槽上挂**过程**，这些过程叫**过程附件（procedural attachment）**：

- **`IF-NEEDED`（需要时）**：槽为空且被问及时才执行，用一段程序算出值。
- **`IF-ADDED`（赋值时）**：槽被填入新值时触发，执行检查或连带更新。
- **`IF-REMOVED`（删除时）**：槽值被移除时触发，清理相关状态。

**重点：过程附件模糊了「声明式」与「过程式」的界线**——一部分知识用数据结构表达，
一部分用程序表达，两者在同一框架内协作。这正是后来「对象 + 方法」的雏形，
也是专家系统（如医疗诊断系统）把「数据 + 推理引擎」结合的鼻祖。

明斯基的学生沙克（Schank）把框架推广成**脚本（script）**：一组按时间顺序排列的框架，
表示一个**标准化事件序列**，如「去餐厅吃饭」= 进门 → 就座 → 点餐 → 上菜 → 结账 → 离店。
脚本让系统能理解故事中「他付了钱」意味着「他吃过饭了」——被省略的情节由脚本补齐。
**框架是「静态情境的骨架」，脚本是「动态流程的骨架」。**<span class="marginnote">脚本与第九篇的
Agent 记忆、事件抽取直接相关：现代知识图谱里的「事件本体」（event ontology）、
以及大模型 Agent 的「计划—执行」循环，都能在脚本思想里找到远祖。常识，一直是知识表示
最想抓住又最难抓住的东西。</span>

## 5 框架的工程遗产

框架系统在 1980 年代被大量用于专家系统与自然语言理解，其遗产今天无处不在：

| 现代系统 | 框架思想的投影 |
| --- | --- |
| 面向对象语言 | 类 = 框架，属性 = 槽，继承 = 框架层级，方法 = 过程附件 |
| OWL 本体 | `Class` 与 `Property`、约束 = 槽的侧面 |
| 数据库表结构 | 表 = 框架，列 = 槽，默认值 = 列的 DEFAULT |
| JSON Schema | 对象结构 + `default` + `type` 约束 |
| 原型继承（JS） | 对象沿原型链继承属性，可局部覆盖 |

**框架的教训与语义网络恰好相反**：语义网络死于语义太模糊，框架则死于语义太宽松——
它太擅长表达「方便的默认」，以至于从不承诺「什么一定真」。这正是后来描述逻辑
（第五篇）要做的补课：把框架的槽与约束翻译成有严格模型论语义的逻辑语言。
**框架提供建模直觉，逻辑提供语义保证，两者在 OWL 里最终合流。**<span class="marginnote">用上一节五角色复盘：
框架在「本体论承诺」（对象+槽的世界观）与「人类表达」（结构清晰）上极强，
在「推理的片段理论」上靠继承+默认勉强合格，在「计算效率」上不错（局部推理），
唯独缺乏「精确语义」。每一代表示都强在直觉、弱在严格——这个摆动的钟摆，
在第五篇描述逻辑那里第一次同时挂上了两端。</span>

## 6 小结

- 框架是明斯基对语义危机的回应：**不追求精确，而追求用「典型结构 + 默认值」模拟常识。**
- 框架的构件：**框架名、槽（slot）、侧面（facet）、默认值（default）**。
- 默认值是灵魂：**信息不全时仍能推理**，代价是非单调（新事实推翻旧结论）。
- 推理靠**继承 + 局部覆盖**：「最具体优先」裁决冲突，但需额外偏序约定。
- **过程附件**（`IF-NEEDED`/`IF-ADDED`）让框架从静态数据变成可行动的知识结构。
- **脚本**把框架推广为时间序列，让系统能补齐被省略的常识情节。
- 工程遗产遍布：**面向对象、OWL、JSON Schema、原型继承**都是框架思想的投影。
- 框架与语义网络的钟摆式对照：**直觉与精确、常识与逻辑**，最终在描述逻辑里合流。

在下一节，我们将专门拆解框架（与语义网络）留下的最烫手的问题——**默认推理**：
当继承网络的结论可以被新知识推翻时，「推理」还意味着什么？这就是非单调逻辑的入口。
