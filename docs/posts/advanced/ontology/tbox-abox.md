# TBox 与 ABox：术语知识与世界断言

<div class="epigraph">
<p>一个描述逻辑知识库由两部分构成：关于概念如何组织的术语知识，与关于个体处于何处的断言知识。前者是词典，后者是档案。</p>

## 为什么从 TBox/ABox 开始

上一节确立了描述逻辑的血统：KL-ONE 的结构直觉 + 一阶逻辑的语义 + 可判定性。
这一节进入 DL 的**内部解剖**：一个 DL 知识库被清晰地劈成两半——
**TBox（术语盒）**装「类与类之间的关系」（术语知识），
**ABox（断言盒）**装「个体属于哪个类、个体之间什么关系」（世界断言）。
这个「词典 vs 档案」的分工，是所有本体系统的骨架：
OWL 里 TBox 对应本体 schema（`owl:Class`、`rdfs:subClassOf`），ABox 对应实例数据
（`rdf:type`、`owl:NamedIndividual`）。理解这两层，
你就理解了「本体」与「数据」的边界在哪里，也理解了为什么
知识图谱的 schema 与实例必须分开建模。

## 1 TBox：术语知识，关于概念的词典

**TBox（terminological box）**：一组**术语公理（terminological axioms）**，
规定概念之间、角色之间的关系。它是关于「世界被分成哪些类、类如何嵌套」
的声明，不含任何具体个体。

TBox 里的公理主要有两种：

- **包含公理（subsumption axiom）** $C \sqsubseteq D$：「猫是宠物」「鸟是动物」。
- **等价公理（equivalence axiom）** $C \equiv D$：「单身汉 ≡ 未婚男性」——
  定义概念时给出必要且充分条件。

此外还有**一般概念包含（general concept inclusion, GCI）**——允许在包含的
前件也写复杂描述，如「有车的人 ⊑ 有身份的人」。GCI 让 TBox 能表达
更复杂的领域规则，代价是推理复杂度上升（后面会提到）。

**重点：TBox 回答的是「概念问题」——「猫是宠物吗」「单身汉是什么」，
它不回答「某只猫叫什么」。** 词典角色由此而来：TBox 是推理的「参照系」，
ABox 里的每一条断言都要回到 TBox 被解释。<span class="marginnote">TBox 与关系数据库的
「schema」貌似同类，实质不同：schema 只约束数据形状（列、类型），
TBox 还编码<strong>可推理的领域知识</strong>——它不只是「表结构」，而是「理论」。
这正是 OWL 与 SQL DDL 的根本区别，第六篇会反复强调。</span>

## 2 ABox：世界断言，关于个体的档案

**ABox（assertional box）**：一组**断言（assertions）**，记录具体个体的事实。
它回答「档案问题」——某个体叫什么、属于哪类、与谁有什么关系。

ABox 断言有两种：

**概念断言（concept assertion）**：$C(a)$，表示个体 $a$ 属于概念 $C$，
  如 $\text{猫}(花花)$——「花花是猫」。
**角色断言（role assertion）**：$R(a, b)$，表示个体 $a, b$ 之间有角色关系 $R$，
  如 $\text{拥有宠物}(张三, 花花)$——「张三拥有宠物花花」。

用 OWL 的语法说：概念断言是 `a rdf:type C`，
角色断言是 `a :R b`。
**ABox 是「填充了具体名字」的知识——它与 TBox 的「无名字的规则」互补。**

**重点：ABox 的每一条断言都隐含地服从 TBox 的公理。**
若 TBox 说「宠物 ⊑ 动物」，则「花花是宠物」自动蕴含「花花是动物」——
系统能推出来，哪怕 ABox 里从没写过。**「ABox + TBox」合起来才构成一个
完整的 DL 知识库 $KB = (\mathcal{T}, \mathcal{A})$**，推理总是在这组合上运行。
<span class="marginnote">把 TBox/ABox 的二分放到哲学线上：TBox 对应「概念框架」
（康德的范畴、亚里士多德的谓词），ABox 对应「经验事实」。知识 = 框架 + 事实，
这个两分法从亚里士多德到康德到 DL 一脉相承。工程上它对应「本体 vs 数据」，
第九篇 LLM 抽取的知识要落库，就是往 ABox 里填断言。</span>

## 3 公式解析：一条断言如何被检查

设知识库 $KB$ 含 TBox 公理「宠物 ⊑ 动物」，ABox 断言「宠物(花花)」。
问：「花花是动物吗？」即问 $KB \models \text{动物}(花花)$ 是否成立。

一条断言的检查分三步：

**第一步，读断言 $\text{宠物}(花花)$**：这是概念断言，
  把个体「花花」归入概念「宠物」。
**第二步，查 TBox 公理 $\text{宠物} \sqsubseteq \text{动物}$**：
  TBox 保证：任何模型里，宠物的解释都是动物的子集。
**第三步，结合两者**：既然花花在「宠物」的解释里，而宠物 ⊑ 动物，
  则花花必在「动物」的解释里——于是 $KB \models \text{动物}(花花)$。

形式上，这是最朴素的**实例检查（instance checking）**：
给个体 $a$ 与概念 $C$，判定 $KB \models C(a)$。它把 TBox 的「词典」能力
自动应用到 ABox 的「档案」上——**一条 TBox 公理，能让无数条 ABox 断言
被扩展出新的蕴含。**<span class="marginnote">这一步就是第五篇后面「推理服务」的
最小单位：实例检查、概念可满足性、分类、检索，全是从这个「TBox 公理 ×
ABox 断言」的结合部生长出来的。理解三步检查，就理解了 DL 推理的全部语义内核。</span>

**易错点｜「缺少反例 ≠ 为假」**：若问「花花是猫吗」，而知识库只说「宠物(花花)」，
没有说它是不是猫，DL 的答案是「不知道」，而不是「不是」。因为 DL 采用
**开放世界假设（OWA）**——没声明的不算假。这与数据库/编程的
**封闭世界假设（CWA）**截然相反（那里「没查到 = 不存在」）。
OWA vs CWA 是 DL 与数据库的分水岭，下一节专门拆。

## 4 TBox 与 ABox 的协同：推理任务全景

两盒合起来，支撑 DL 的四大标准推理任务：

| 推理任务 | 输入 | 问什么 | 对应 OWL 场景 |
| --- | --- | --- | --- |
| 概念可满足性 | 概念 $C$ | $C$ 能否非空？ | 检查本体无矛盾 |
| 包含判定 | 概念 $C, D$ | $C \sqsubseteq D$ 吗？ | 计算类层级 |
| 实例检查 | 个体 $a$，概念 $C$ | $a \in C$ 吗？ | 判断个体归属 |
| 一致性 | 知识库 $KB$ | $KB$ 有模型吗？ | 检查数据无冲突 |

**分类（classification）**是 TBox 上的总任务：给定一组概念公理，
算出**所有**概念之间的包含关系，得到完整的类层级。**实现（realization）**
是 ABox 上的对偶任务：对每个个体，找出它属于的**最具体**概念。
这两者分别是「把词典排好序」与「把档案归好位」——第七篇推理机
（Pellet、HermiT）做的就是这两件事的工程实现。

**重点：TBox 与 ABox 不是「两套数据」，而是「一套知识的两面」。**
TBox 让 ABox 的每一条事实获得更丰富的意义（花花是宠物 → 花花是动物）；
ABox 反过来检验 TBox 的定义是否与现实吻合（如果现实中有一只既非宠物
又非野生的动物，TBox 的定义就要修订）。**本体维护的生命周期，
就是这两层之间不断往返的校准过程。**<span class="marginnote">这个「词典—档案」往返
在第九篇 LLM 时代有了新形态：LLM 从文本抽出的实体与关系是 ABox 的「草稿」，
需要拿本体（TBox）去校验、归类、消解——「用 schema 约束 LLM 输出」的实质，
就是强迫生成的 ABox 断言服从 TBox 公理。</span>

## 5 小结

- DL 知识库 = **TBox（术语知识）+ ABox（世界断言）**，前者是词典，后者是档案。
- TBox 装**概念公理**：包含 $C \sqsubseteq D$、等价 $C \equiv D$、GCI。
- ABox 装**个体断言**：概念断言 $C(a)$ 与角色断言 $R(a, b)$。
- 实例检查三步走：读断言 → 查 TBox 公理 → 结合推出蕴含。
- **开放世界假设**：没声明的不算假——这是 DL 与数据库的分水岭。
- 四大推理任务：**可满足性、包含判定、实例检查、一致性**；
  分类与实现分别是 TBox/ABox 上的总任务。
- 方法论：**本体维护 = 词典（TBox）与档案（ABox）之间的往返校准**。
