## 为什么从「框架」开始

上一章，罗素用摹状词理论把「当今法国国王」这类词从本体论里消解掉了：不存在的描述不再增殖实体，存在被还原成量词。可是等一下——**量词本身要在一个「论域」上取值**。「存在一个 $x$，$x$ 是素数」这句话，得先有一个让 $x$ 取值的地方。那么问题来了：**这个「论域」本身，算不算存在？**

这一问把分析传统推到了悬崖边。弗雷格和罗素都勇敢地承认抽象实体——数、命题、属性——「存在」，因为它们是我们最好的理论（算术、逻辑）里的量词取值。但这等于把「何物存在」重新交给了理论。1940 年代末，逻辑经验主义的主将卡尔纳普（Rudolf Carnap, 1891–1970）给出了一个堪称釜底抽薪的解法：**「数是否存在」这类问题，本身问错了——它要把本体论问题区分成「内部」与「外部」两种，只有内部问题有真值，外部问题是一场实用的取舍。**<span class="marginnote">这是第二篇《分析传统》的转折点：弗雷格、罗素建立逻辑，卡尔纳普用逻辑给本体论「降温」，而下一章奎因将反手一击，证明这个内/外之分站不住。理解卡尔纳普，正是理解奎因的前提。</span>

## 1 语言框架：本体论问题被分成两种

1950 年，卡尔纳普发表《经验主义、语义学与本体论》（Empiricism, Semantics, and Ontology），开篇就点名了敌人：经验主义者对「属性、类、关系、数、命题」这类抽象实体素来警惕，觉得它们是形而上学的走私货。可现代数学和逻辑又离不开它们——不说「数」，连「一个命题是真的」都无法表达。卡尔纳普的方案是：**先别争「它们存不存在」，先问「你是在哪个语言框架里说这话的」。**

**核心概念：语言框架（linguistic framework）**：一套说话的系统，由四部分构成——（1）一组新词项（如「数」「素数」）；（2）用这些词项造句的规则；（3）判断句子真假的方法（经验检验或逻辑计算）；（4）真值条件。有了框架，「是否有一个 $x$ 使得 $\phi(x)$」才成为可回答的问题。

**重点：存在性命题必须在某个框架内部才能被判定。** 框架是「论域」的制度化形态——它规定了量词可以取哪些值、哪些句子合法、如何验证。卡尔纳普给经验主义者递上台阶：**你们不必假装数不存在，你们只需要把「数是否存在」这句话重新定位。**<span class="marginnote">「框架」的工程镜像极其直接：数据库的 schema、知识图谱的模式层、RDFS/OWL 里的类与属性声明，都是一个「语言框架」——它预先规定了这个系统里「存在」哪些类型的实体、可以形成哪些断言。</span>

## 2 内部问题：框架之内的真问题

在某个框架之内问「某物是否存在」，就是**内部问题（internal question）**。它是真问题，有确定答案，答案由框架内的规则给出：

**物的框架（thing language）**：「我桌上有一张白纸吗？」——这是经验问题，靠观察回答。
**数的框架（number framework）**：「存在大于 100 的素数吗？」——这是数学问题，靠计算和证明回答，答案是「有」。
**命题的框架（proposition framework）**：「存在关于巴黎的命题吗？」——用逻辑分析回答：能造句，就有。

卡尔纳普的关键观察是：**内部问题的答案，总是「在框架之内」被给出的，而且给出答案不需要额外承认任何可疑的实体。** 说「存在大于 100 的素数」，不是在宣称一个叫「数」的幽灵存在，而是在数论框架里执行一次判定。内部问题忙忙碌碌，却从不触碰到「数本身存不存在」——因为「是否存在」这个谓词，在框架内只适用于框架的元素，不适用于框架本身。

**重点：把「内部」看清楚了，就明白「实数是否存在」这类问题的平凡性。** 在实数框架内，「存在无理数」真；「存在不是实数的对象」——这句话压根不在框架里。内部问题的边界就是框架的边界。<span class="marginnote">这像极了程序语言的类型系统：在 int 类型内问「存在等于 3 的 int 吗」有明确答案；问「存在一个不是 int 的 int 吗」是类型错误，而不是一个值得深究的本体论谜题。Carnap 要说的正是：许多「存在之问」其实是类型层面的话。</span>

## 3 外部问题：框架本身的取舍

真正引爆争议的是另一种问题。**外部问题（external question）**问的不是框架之内的对象，而是**框架本身**——「数真的存在吗？」「外部世界是实在的吗？」「这些命题是真实的还是虚构的？」

卡尔纳普的答复分两层：

**若把外部问题当作理论问题（即当作一个有真假的陈述）**：它是**伪问题（pseudo-question）**。因为「实在」「存在」的意义由框架内部的验证规则给出，一旦把框架本身当作被判断对象，验证规则就失灵了——没有任何经验或逻辑能检验「数的实在性」。
**若把外部问题理解为一种实用的提议**：它完全正当，但不是「对错的判断」，而是「选择的决定」——**要不要采纳这个框架？** 采纳的标准不是真，而是**效率（efficiency）**：这个框架是否便利、富有成果、能顺利服务我们的目标。

于是卡尔纳普给出那句名言的方向：**「在科学意义上实在，就意味着是该系统的一个元素；因此这个概念不能有意义地应用于系统本身。」** 采纳物的框架，不是因为「外部世界真的存在」这一事实成立，而是因为**物语言是我们预测经验的最高效工具**。现实主义者与观念论者争论「外部世界是否实在」，在卡尔纳普看来双方都在争夺一个无法兑现的认知内容——**这不是世界观之争，是工具选择之争。**<span class="marginnote">这一刀极其锋利：它把两千年「何物存在」的形而上学大辩论，从「关于世界的理论」降格为「关于语言形式的决定」。Rorty 后来讽刺说，这等于把哲学问题都变成了「用什么语言写诗」的问题——赞赏者视之为解放，批评者视之为回避。</span>

## 4 核心对比表：内部问题 vs 外部问题

本主题以概念辨析为主、无核心公式，故以「核心对比表」代替公式解析——按编辑章程第 5 节执行。

| 维度 | 内部问题 | 外部问题 |
| --- | --- | --- |
| 提问位置 | 在框架之内 | 关于框架本身 |
| 问题形态 | 事实问题（可验证） | 采纳/拒绝框架的提议 |
| 有无真值 | 有，由框架规则决定 | 无理论真值（是选择，不是发现） |
| 回答方式 | 经验观察或逻辑计算 | 实用权衡：效率、成果、便利 |
| 例（数的框架） | 存在大于 100 的素数吗？ | 数「真的」存在吗？ |
| 例（物的框架） | 桌上有一张白纸吗？ | 外部世界「真的」实在吗？ |
| 典型位置 | 科学内部、数学内部 | 形而上学、本体论争论 |
| 工程投影 | 在既定 schema 下查询、验证 | 是否采纳某 schema / 本体 |

表中最锋利的一行是「工程投影」：**在系统里跑 SPARQL 查询，是内部问题；决定要不要引入一个「事件」类、要不要把属性建模成个体，是外部问题。** 本体工程师每天都在做外部决策，而卡尔纳普告诉我们：**这些决策不该用「哪个 schema 更真实」来辩护，而该用「哪个 schema 更能回答问题、更便宜地维护」来辩护**——这恰好预告了第七篇《本体工程》里「能力问题（competency questions）」的整套方法论。

## 5 宽容原则与本体论的「实用转向」

卡尔纳普的框架论不是孤立的巧思，它背后站着逻辑经验主义的**宽容原则（principle of tolerance）**，在《语言的逻辑句法》（1934）里被说得最透：

> 在逻辑中，没有道德。人人皆可随心所欲地构建他自己的逻辑，即他自己的语言形式。<span class="marginnote">宽容原则在 1934 年是一件激进的事：当时的数学基础之争（直觉主义 vs 经典数学）争得你死我活，卡尔纳普说「你们都别争了，各用各的框架，看哪个更管用」。这开启了今天多范式共存的温和气氛——就像编程语言之争，最终靠生态与实用性裁决，而不是靠「哪种语言更真实」。</span>

宽容原则不是凭空出现的宽容，它有坚实的语义学根源——逻辑经验主义的**意义标准（criterion of meaning）**：一个陈述有认知意义，当且仅当经验能够确认或否证它。外部本体论命题（「外部世界实在」「数真实存在」）恰好无法被任何经验检验——它们既不能由观察证实，也不能由逻辑推翻，于是被判为**伪问题（pseudo-problem）**。宽容原则因此不是「什么都可以信」，而是「**凡是能说清验证方法的，都可以说；凡是说不清验证方法的，都是伪问题——但对框架的选择，另当别论**」。这条界线日后成为奎因的靶子：经验论者引以为傲的「意义标准」本身，恰恰无法站在经验之外为自己辩护——这个反讽是下一章的主线。

宽容原则的应用方式：**数学里直觉主义与经典逻辑可以共存**，物理里不同时空模型可以共存，本体论里实在论与唯名论之争被转换成「选择哪个框架更便利」的工程问题。卡尔纳普并不要求所有人选同一个框架——他只要求：**把「何物存在」从「发现真理」改造成「选择工具」。** 这是本体论的一次彻底实用转向：存在之问不再通向世界的真相，而通向语言形式与工程目标的匹配。

这一转向在哲学内部立刻招来两拨人：一拨认为卡尔纳普是对的，形而上学本就是语言层面的事；另一拨（包括下一章的奎因）认为**内/外之分是个幻觉**——你说「采纳框架是实用的而非理论的」，可「采纳框架」本身也是我们整个知识体系的一部分，它同样需要被整合进我们对世界的整体理论里。理论与实用的界线，和分析与综合的界线一样，根本画不干净。

## 6 知识表示线：schema 的取舍是外部问题

卡尔纳普的框架论在知识工程里留下了一份可以直接落地的遗产：

**schema 即框架。** 一个知识图谱的类层次、属性定义、基数约束，就是这个系统采纳的「语言框架」。类与属性被声明，系统从此「存在」这类对象与关系——这正是卡尔纳普说的「框架内元素」。
**查询是内部问题。**「张三写过哪些书」在 schema 内有确定答案（SPARQL 求值）；「人真的存在吗」对系统没有意义——它不在 schema 内，也无法被验证。
**schema 取舍是外部问题。**「要不要把『事件』建模成类」「要不要用属性图而非 RDF」——这些问题无法用「哪个更真实」回答，只能用「哪个更有效率、更能回答能力问题」回答。

下面的 OWL 片段演示：声明类与属性，就是在**采纳一个框架**；随后的一切推理与查询，都是在这个框架内部进行的内部活动。

```turtle
:人 rdf:type owl:Class .
:著作 rdf:type owl:Class .
:作者 rdf:type owl:ObjectProperty .
:作者 rdfs:domain :人 ;
       rdfs:range :著作 .
```

**重点：这个片段里没有任何一行在回答「人真实存在吗」——它只是先选了一个框架（外部），再在框架里做事（内部）。** 本体工程师把「存在之问」的实现化，正是卡尔纳普式的：**把不可判定的本体论争论，转译成可评估的建模决策。** 到第七篇《本体工程》，我们会看到这种实用主义姿态被系统化——能力问题、方法论、复用，全是「效率」的展开。<span class="marginnote">这也是理解第九篇「知识图谱 × 大模型」的关键预埋：大模型「幻觉」的本质，是统计模型不承诺任何框架——它没有 schema，所以无法区分「框架内真」与「框架外假」。给 LLM 一个 schema（如 JSON Schema、SHACL）约束输出，正是把一个外部框架强加给它，强制它在框架内发言。</span>

## 7 小结

- **语言框架**：由词项、造句规则、验证规则、真值条件构成的说话系统；存在性命题必须在框架内才有答案。
- **内部问题**：框架之内的事实问题，有确定真值——「桌上有一张白纸吗」「存在大于 100 的素数吗」。
- **外部问题**：关于框架本身的采纳与否；当作理论问题是伪问题，当作实用决策则正当——标准是效率而非真。
- **宽容原则**：在逻辑中没有道德，人人可自选语言形式；本体论从「发现真理」转为「选择工具」。
- **工程投影**：schema 即框架、查询是内部问题、schema 取舍是外部问题；LLM 幻觉的本质是不承诺任何框架。

在下一节，我们将看到奎因对这套内/外之分的一次性反击：他说「采纳框架」同样是理论行为，**存在就是成为约束变量的值**——本体论问题没有被消解，而是被搬进了整个科学理论的大厦里。那正是**《论何物存在》：存在就是成为约束变量的值**。
