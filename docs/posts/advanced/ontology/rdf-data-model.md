# RDF 数据模型：三元组、IRI 与空白节点

## 为什么从 RDF 开始

分层蛋糕的数据模型层，坐着一个极其简单、又极其持久的构件——**RDF
（Resource Description Framework，资源描述框架）**。它把一切知识
压成一种形状：**「主语—谓语—宾语」的三元组**。简单到一句话能讲完，
强大到整个语义网都建立其上。理解 RDF，你就理解了
「机器可读语义」的最小单位长什么样、IRI 如何全球寻址、
空白节点如何表达「匿名个体」，以及为什么 RDF 是一种
**为「链接与合并」而生**的图模型——这与数据库的「表」、
JSON 的「树」有本质区别。

## 1 三元组：知识的最小陈述

**RDF 三元组（triple）**：形如「主语—谓语—宾语」的一条陈述，
记作 $(s, p, o)$ 或写成一行的三个部分：

```
:张三  :拥有宠物  :花花
```

- **主语（subject）**：被描述的资源——「张三」。
- **谓语（predicate）**：描述的性质或关系——「拥有宠物」。
- **宾语（object）**：性质的值或关系的另一头——「花花」。

一条三元组就是一句最小命题。多个三元组拼在一起，形成一张**RDF 图（graph）**——
把主语与宾语当节点、谓语当带标签的边。**知识 = 图的边集。**

**重点：RDF 图是「开放可拼接」的**——任何两组三元组可以随时合并成
一张更大的图，因为共享 IRI 的资源自动「对齐」。这是它对比数据库表
的根本特性：**表是封闭的 schema，图是开放的陈述集**。<span class="marginnote">用第五篇的
语言看，RDF 三元组天然就是 ABox 断言：`:张三 rdf:type :Person` 对应
`Person(张三)`，`:张三 :hasPet :花花` 对应 `hasPet(张三, 花花)`。
RDF 就是「把 DL 的 ABox 铺平成机器可交换的陈述」。</span>

## 2 IRI：全球寻址的语言

三元组里的资源用什么标识？答案是 **IRI（Internationalized Resource Identifier，
国际化资源标识符）**——URI 的国际化扩展，允许非 ASCII 字符。
IRI 是整个语义网的「地址系统」：

- **全局唯一**：同一个 IRI 在世界任何地方都指同一个资源。
- **可跨图合并**：两张图里出现相同的 IRI，就是同一个资源——自动拼接。
- **可反解**：IRI 往往指向一个可访问的文档（如网页），资源与描述可以互连。

三元组的规则：**主语必须是 IRI 或空白节点，谓语必须是 IRI，
宾语可以是 IRI、字面量或空白节点。** 谓语的 IRI 地位尤其重要——
「拥有宠物」这个关系本身也要有一个全球唯一的名字，才能被全世界
无歧义地引用。<span class="marginnote">IRI 的哲学意义：它把「指称」问题
（第二篇弗雷格的意义与指称）工程化了——名字（IRI）与所指
（资源）的关系被固定成全球约定。知识图谱里「实体消解」
（第八篇）要解决的，正是「两个名字是否指同一个资源」。</span>

## 3 字面量：带上数据类型的值

宾语若是「值」而非「资源」，用**字面量（literal）**表示：

```
:张三  :年龄  "35"^^xsd:integer
:张三  :姓名  "张三"^^xsd:string
```

- **字面量** = 值的字符串 + 可选的数据类型（datatype），
  如 `xsd:integer`、`xsd:string`、`xsd:date`。
- 数据类型让「35」能被机器当作数字比较，而不是当作字符串。
- 语言标签（`@zh`、`@en`）让同一文本的不同语言版本可共存。

**重点：字面量是 RDF 的「叶子」**——它不可再被当主语引用，
是陈述链的终点。这一层看似细节，却决定了 RDF 能表达
「结构化值」而不只是「资源链接」：人物年龄、日期、数量，
全部靠带类型的字面量落进图里。<span class="marginnote">对照属性图（第八篇）：
RDF 的「值」是字面量节点，属性图的「值」是节点属性。两种模型
对「数值存哪」的处理不同——RDF 把它当作三元组宾语，属性图
把它当作节点的属性字段。这一差异在「属性图 vs RDF」一节会细究。</span>

## 4 空白节点：匿名的存在者

有时我们需要表达「有个东西，但不想（或不能）给它起名」。
RDF 用**空白节点（blank node）**解决，记作 `_:b1` 或 `[]`：

```
:张三  :拥有宠物  _:b1
_:b1   rdf:type  :猫
_:b1   :名字      "花花"
```

`_:b1` 代表一个**存在但未命名**的个体——它只在本图的范围内有意义，
不能从图外被引用。**语义上，空白节点就是「存在量词」的图形式**：
「张三拥有一个宠物，这个宠物是猫，叫花花」——我们不必知道
这个宠物的全局 IRI，也能陈述关于它的一切。

**易错点｜空白节点不是「变量」**：它是**具体的匿名个体**，而不是
「某个未知的东西」。一张图里出现两次 `_:b1`，指的是同一个匿名个体；
但不同图里的 `_:b1` 是**不同**的个体。合并图时，空白节点的「同一性」
必须在合并过程中显式处理——这是 RDF 工程里最容易被忽略的坑。<span class="marginnote">空白节点
的哲学对应物，正是第三篇迈农式的「不命名个体」：它存在（在图的论域里），
但不需要一个名字来指称。工程上，能不用空白节点就不用——因为
它阻碍跨图合并与引用，现代图谱实践偏爱「一切资源都有 IRI」。</span>

## 5 公式解析：RDF 图与 ABox 的对应

把 RDF 与第五篇 DL 的 ABox 对照，两张图是同一种东西的两种记法：

| RDF 三元组 | DL 断言 | 逻辑含义 |
| --- | --- | --- |
| `:花花 rdf:type :猫` | 猫(花花) | 概念断言 |
| `:张三 :拥有宠物 :花花` | 拥有宠物(张三, 花花) | 角色断言 |
| `_:b1 rdf:type :猫` | ∃x. 猫(x) | 存在量化 |

**逐项拆解**：

- **`rdf:type`**：RDF 的「类型」谓词，对应 DL 的概念断言与一阶逻辑的
  一元谓词应用——它是唯一被 RDF 内置语义化的关系。
- **自定义谓词**：如 `:拥有宠物`，对应二元谓词/角色——语义由 RDFS/OWL
  或外部公理赋予。
- **空白节点 + `rdf:type`**：对应存在量词——「存在一个猫」。

**重点：RDF 本身不含 TBox**——它只陈述事实（ABox），类与属性的定义
（TBox）要靠 RDFS/OWL 加上去（下一节）。**RDF 是「数据」的语言，
RDFS/OWL 是「schema」的语言**，这一分工是语义网架构的核心设计。<span class="marginnote">这解释了一个
常见困惑：「为什么 RDF 里 `rdf:type` 推不出子类关系？」——因为子类
是 TBox 公理，需要 RDFS 的 `rdfs:subClassOf`。RDF 老老实实只做
「陈述」，把「推理」留给上层——分层蛋糕各司其职的又一次体现。</span>

## 6 RDF 与其他数据模型的对比

RDF 不是「最好的」数据模型，而是「最适合开放链接的」。横向对比一目了然：

| 维度 | RDF 图 | 关系表 | JSON 树 | 属性图 |
| --- | --- | --- | --- | --- |
| 结构 | 无固定 schema 的图 | 固定表结构 | 嵌套树 | 图 |
| 寻址 | 全局 IRI | 表名+主键 | 路径 | 局部 ID |
| 语义 | 可加 RDFS/OWL | 无 | 无 | 无 |
| 合并 | 天然可拼接 | 需 schema 对齐 | 需映射 | 需对齐 |
| 代表 | Jena, GraphDB | MySQL | MongoDB | Neo4j |

**重点：RDF 的定位是「开放网络的陈述语言」**——它牺牲了表的高效
与 JSON 的便利，换来了**全局可链接、可合并、可加语义**。
工程上选哪种，取决于你要「封闭的数据库」还是「开放的语义网」。
第八篇会详细展开属性图与 RDF 的取舍。

## 7 小结

- RDF 的原子单位是**三元组（主语—谓语—宾语）**，集合成**RDF 图**。
- **IRI** 是全球唯一的资源地址，让图可跨来源合并。
- **字面量**带数据类型，是陈述链的叶子。
- **空白节点**表达匿名个体，语义上对应存在量词。
- RDF = **ABox 的机器可交换形态**；TBox 靠 RDFS/OWL 补充。
- 定位对比：RDF 为**开放链接与语义推理**而生，表为封闭、JSON 为嵌套、属性图为性能。
- 工程提醒：**尽量给资源命名（IRI），少用空白节点**。
