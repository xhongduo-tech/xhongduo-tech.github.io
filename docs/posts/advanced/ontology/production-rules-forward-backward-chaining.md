# 产生式规则系统：前向链与后向链

<div class="epigraph">
<p>人类的大部分知识都可以写成「条件—行动」的规则：遇到某种情况，就采取某种行动。</p>
<footer>—— 艾伦·纽厄尔与赫伯特·西蒙（Allen Newell, Herbert A. Simon），产生式系统理论（1972）</footer>
</div>

## 为什么从规则系统开始

前面几节我们见到的表示（语义网络、框架）都在回答「世界是什么样」；
这一节的**产生式规则系统（production rule system）**换个角度，回答「遇到情况怎么办」。
它把知识写成一条条「**如果……就……**」的规则，配上事实库与一个推理循环，
就成了 1980 年代最成功的 AI 产品——专家系统。从 MYCIN 到 XCON，从商业规则引擎
到今天的智能体提示词，规则系统的「条件—行动」骨架四十年没变。理解它，
你就理解了「知识」如何被组织成**可执行的程序**——这是通向第五篇描述逻辑
（规则的严格化）与第九篇 LLM Agent（规则的柔性化）的桥梁。

## 1 产生式系统：三件套

一个产生式系统由三个部件构成：

- **规则库（production memory / rule base）**：一组「条件—行动」规则。
  条件是对事实的**模式（pattern）**，行动是添加/删除事实或执行动作。
- **工作记忆（working memory）**：当前已知事实的集合，是规则匹配的对象。
- **识别—行动循环（recognize–act cycle）**：不断重复「匹配规则 → 选择规则 → 执行行动」，
  直到没有规则可触发或达成目标。

一条典型规则长这样：

```
IF 患者有发热 AND 患者有咳嗽 AND 患者接触过流感患者
THEN 怀疑流感（置信度 0.8）
```

**规则（production rule）**：知识的最小单位，形如「IF 条件 THEN 行动」，
其中条件是一组对工作记忆的匹配模式，行动是对工作记忆的修改。
**重点：规则系统的知识是「模块化」的**——每条规则独立自洽，可以单独增删，
不必关心其他规则。这份模块化是它比语义网络更容易维护的原因，
也是它缺乏全局语义（下一节）的根源。<span class="marginnote">规则系统与框架系统的
哲学差异值得记住：框架把知识组织成<strong>对象结构</strong>（槽、继承），规则把知识组织成
<strong>行为准则</strong>（条件、行动）。一个偏「世界模型」，一个偏「决策逻辑」。
工程里两者常混合使用——对象存事实，规则做判断。</span>

## 2 前向链：从事实推向结论

**前向链（forward chaining）**，也叫**数据驱动推理（data-driven reasoning）**：
从已知事实出发，反复让规则匹配、触发，把新结论加入工作记忆，直到推不出新东西。

算法骨架如下：

1. 初始化工作记忆为已知事实；
2. 找所有「条件被满足」的规则，加入候选集；
3. 按冲突消解策略选一条触发，执行其行动（添加/删除事实）；
4. 回到第 2 步，直到候选集为空或达成目标。

前向链的方向与人的直觉一致：**看见什么，就推出什么**。它的强项是「无需预设目标」
——知识越多，越能顺藤摸瓜。XCON（为 DEC 公司配置计算机系统）就是前向链的成功案例：
输入订单，规则逐条触发，最终输出一套可安装的配置。

**重点：前向链的引擎开销在「匹配」**。每轮循环都要检查哪些规则匹配当前工作记忆，
而工作记忆在变、规则成千上万，逐条扫描是灾难。福吉（Forgy）在 1982 年提出
**RETE 算法**：把规则条件编译成一张网络，跨轮共享部分匹配结果，
把匹配成本从「每轮全扫」降到「只处理增量变化」。**RETE 是规则引擎的发动机**——
Drools、Jess、CLIPS 至今都在用它。<span class="marginnote">RETE 的「增量匹配」思想
是 KR 与数据库的交汇点：关系数据库的<strong>物化视图（materialized view）增量维护</strong>、
复杂事件处理（CEP）的「模式匹配」，与 RETE 是同一类问题的不同方言——
知识变化后，如何不重算全部而只更新受影响部分。</span>

## 3 后向链：从目标回溯到事实

**后向链（backward chaining）**，也叫**目标驱动推理（goal-driven reasoning）**：
从待证目标出发，反向寻找「结论能推出目标」的规则，把规则前提变成新的子目标，
递归求解，直到子目标被工作记忆中的事实直接满足。

算法骨架如下：

1. 把初始问题设为目标；
2. 若目标已在工作记忆中，成功；
3. 否则找「行动能产生目标」的规则，把其前提作为子目标；
4. 递归求解每个子目标；任一子目标失败则换规则重试；
5. 全部子目标满足，则目标得证。

后向链的方向是「**要证明什么，就倒查什么**」。它的强项是**聚焦**——只沿着目标
需要的路径推理，不会漫无目的地推导。MYCIN（细菌感染诊断专家系统）就用后向链：
医生问「患者是什么菌感染」，系统倒查规则库，把每条规则的证据（症状、化验）
逐一向医生追问，直到收集足够证据。Prolog 的求解机制本质上就是后向链
加上深度优先搜索与回溯。<span class="marginnote">后向链与数据库查询的
「递归展开」同构：SQL 的递归 CTE、以及知识图谱的图模式匹配，
都在做「从目标反向展开约束」的工作。理解后向链，等于理解了
「查询 = 反向推理」这个贯穿数据库与 KR 的等式。</span>

## 4 前向 vs 后向：一张对照表

| 维度 | 前向链 | 后向链 |
| --- | --- | --- |
| 方向 | 事实 → 结论 | 目标 → 事实 |
| 驱动 | 数据驱动 | 目标驱动 |
| 启动条件 | 事实更新 | 被提问 |
| 强项 | 无目标也能推 | 聚焦、省算力 |
| 弱项 | 可能推大量无关结论 | 目标不明时无从下手 |
| 代表系统 | XCON | MYCIN、Prolog |
| 典型引擎 | RETE 编译 | 深度优先 + 回溯 |

**易错点｜前向与后向不是「两种规则」，而是「两种调度」**：同一套规则库，
既可以前向跑也可以后向跑。差别只在「哪条规则先触发」的决策由谁驱动——
是新增的事实推动，还是待证的目标拉动。工程选型时，**若问题「已知事实、求结论」选
前向；若问题「给定目标、求证据」选后向**；两者都含大量动态变化时，
可考虑混合（事实驱动 + 目标驱动交替）。

**冲突消解（conflict resolution）**：无论前向还是后向，同一轮可能有多个规则候选，
系统要按策略挑选：优先更具体的规则、优先更近更新的事实（recency）、
按规则显式优先级、按规则顺序。**冲突消解是启发式的，不是逻辑的**——
它决定了推理的「风格」，也让规则系统难以给出「唯一正确的推理」。

## 5 规则系统的遗产与边界

规则系统的历史遗产极其丰厚，但也界限分明。

**成功的遗产：**

- **专家系统**：MYCIN、XCON 证明了「知识 = 规则」能落地到工业级。
- **可解释性**：每一条结论都有一条「规则链」可回溯，系统能向用户解释
  「为什么这么诊断」——这是规则系统对比神经网络最持久的优势。
- **商业规则引擎**：Drools、IBM ODM 把规则系统做成中间件，
  让业务逻辑（折扣、风控、合规）与程序代码分离。

**清醒的边界：**

- **无全局语义**：规则库是一个规则的堆，没有整体模型论语义——
  这与上一节语义网络被批评「链接没语义」是同一种病。
- **冲突消解是经验**：规则太多后，触发的顺序、覆盖的优先级全靠人工维护，
  「幽灵规则」互相干扰难以排查。
- **规模瓶颈**：几千条规则后，维护与调试成本陡增。

**重点：规则系统的真正遗产是「把推理显式化」**——它逼着设计者把「何时用什么知识」
写成规则，于是知识变得可增删、可解释、可复用。今天 LLM 智能体的
「提示词 + 工具调用」流程，本质上是一套**柔性产生式系统**：
条件是上下文匹配，行动是调用工具，冲突消解是模型的注意力。
理解规则系统，等于拿到了理解 Agent 的钥匙。<span class="marginnote">这个对照在第九篇会
正式展开：符号规则（硬、精确、可判定）与神经网络（软、统计、不可解释）的
结合点，正是「把规则变成可学习的偏好」。规则系统不是被大模型淘汰，
而是被大模型吸收——从「硬编码」变成「软偏好」。</span>

## 6 小结

- 产生式系统的三件套：**规则库、工作记忆、识别—行动循环**。
- 规则是「**IF 条件 THEN 行动**」的模块化知识单位，可单独增删。
- **前向链**（数据驱动）：从事实推结论，强项是无目标也能推，引擎靠 RETE。
- **后向链**（目标驱动）：从目标查证据，强项是聚焦省算力，Prolog 即此。
- **冲突消解**是启发式的调度策略，决定推理风格，也带来不确定性。
- 遗产：**专家系统、可解释推理、商业规则引擎**；边界：**无全局语义、维护困难**。
- 现代回响：**LLM Agent = 柔性产生式系统**，规则从硬编码变成软偏好。
