## 为什么从单子开始

这句话是全网最著名的范畴论段子：**「一个单子（monad）不过是一个
自函子范畴上的幺半体」**。这一节要把这个天书般的句子**一步步拆开**，
让「单子」从玄学变成清晰的构造。我们已经备好了全部原料：
幺半群（第 4 节，单对象范畴）、函子（第 7 节）、自然变换（第 8 节）。
现在把它们组装：**自函子范畴**（复合为乘法）→ **幺半体**（带
单位与乘法的对象）→ **单子**。对程序员，单子就是 Maybe、List、
State、IO 背后的统一结构——它让「纯函数世界里处理副作用」
成为可能。理解单子，你就真正登上了范畴论在编程里最有名的高地。

## 1 升级的原料：从幺半群到幺半体

第 4 节我们把「幺半群」重述成「单对象范畴」。现在做一次**升级**：

- **普通幺半群**：在一个集合里的「结合运算 + 单位元」。
- **单对象范畴里的幺半群**：在一个范畴里的「复合 + 单位态射」。
- **幺半体（monoid object）**：在一个「带张量积的范畴」里的
  「对象 + 乘法 + 单位」——把「幺半群」的概念搬到任意
  **单范畴（monoidal category）**里。

**单范畴**：一个范畴配上「张量积」$\otimes$（一种结合的双对象
运算）与「单位对象」$I$。集合范畴用「笛卡尔积」当张量积，
就回到普通幺半群；而我们要用**函子范畴**当底子。

**重点：幺半体是「把幺半群的一般化」。**
普通幺半群的「元素乘法」，在幺半体里变成「对象间的 $\otimes$」。
**只要底范畴有张量积，就能定义幺半体**——而自函子范畴恰好
有一个天然的张量积：函子复合。升级由此完成。<span class="marginnote">「从幺半群到幺半体」
是范畴论「把一切抽象化」的又一次演示：<strong>一个概念（结合运算 +
单位）只要满足三条公理，就能在任意合适的范畴里重新定义</strong>。
单子就是「幺半群」这个老朋友，在「函子世界」里的化身——
所以那句口号说它「不过是个幺半体」，意思是「别怕，是熟人」。</span>

## 2 自函子范畴：函子的世界

**自函子（endofunctor）**：从范畴到**自身**的函子 $T: \mathcal{C} \to \mathcal{C}$。

**自函子范畴 $[\mathcal{C}, \mathcal{C}]$**：

**对象**：所有的自函子 $T, S, \ldots$。
**态射**：自然变换 $\alpha: T \Rightarrow S$（上一节！）。
**张量积**：**函子复合**——$T \otimes S := T \circ S$。
**单位对象**：恒等函子 $\mathrm{Id}$（$F \circ \mathrm{Id} = F$）。

**重点：函子复合天然是「结合的」、恒等函子是「单位」——
所以自函子范畴是一个单范畴。** 这正是我们需要的「底子」：
它提供了「乘法」（复合）与「单位」（恒等函子）。**单子
就是在这个范畴里找一个「幺半体对象」**——就像在自然数里
找一个「带加法和 0 的东西」。<span class="marginnote">把「函子复合」当「乘法」是
那句口号的关键：<strong>幺半群在「数的乘法」里、在「字符串拼接」里、
在「函数复合」里都存在</strong>——而现在它在「函子复合」里也存在。
「自函子范畴上的幺半体」=「把『结合 + 单位』这个老配方，
用『函子复合』当乘法、用『恒等函子』当单位，做出来的东西」。</span>

## 3 公式解析：单子的两件套

**单子（monad）**：自函子范畴里的幺半体——由两部分组成：

**自函子 $T: \mathcal{C} \to \mathcal{C}$**。
**两个自然变换**：
**$\eta$（unit / return）**：$\mathrm{Id} \Rightarrow T$——
    把「平凡」放进「容器」。
**$\mu$（join）**：$T^2 \Rightarrow T$——把「两层容器」
    压平成「一层」。

并满足三条法则（幺半体公理在函子世界的翻译）：

**结合律**：$\mu \circ T\mu = \mu \circ \mu T$——「先合并哪两层都一样」。
**左单位律**：$\mu \circ T\eta = 1_T$——「先放进去再合并 = 没动」。
**右单位律**：$\mu \circ \eta T = 1_T$——同理。

**重点：这两件套对应程序员熟悉的 return 与 join（flatten）。**
$\eta$ 是 return/pure（把值放进容器），$\mu$ 是 join（把嵌套容器
M(M a) 压成 M a）。**三条法则保证「放进去再合并」不会出岔子**
——这正是 >>=（bind）安全性的来源。**单子的全部结构，就是
「装进去 + 压平 + 三条法则」。**<span class="marginnote">如果你用过 Option
（Scala）、IEnumerable（C#）、Promise（JavaScript），你已经用过
单子了——它们分别是 Maybe、List、IO 的别名。<strong>单子的工程直觉：一个
「带上下文的计算」可以被顺序拼接</strong>——Option 的上下文是
「可能为空」，IEnumerable 的上下文是「多个结果」，Promise 的上下文是
「与外部世界交互」。</span>

## 4 Hask 里的单子：return 与 >>=

程序员认识单子通常不是通过 $\eta$ 与 $\mu$，而是通过两个运算：

```haskell
return :: a -> m a
(>>=)  :: m a -> (a -> m b) -> m b
```

**bind（`>>=`）与 $\mu$ 的关系**：`>>= f = join (fmap f)`——
先 `fmap f`（把函数送进容器，得到 M(M b)），
再 `join` 压平。**所以 bind 可以用 $\mu$ 定义**——两个
定义等价。

**重点：do 记法是 bind 的语法糖。**

```haskell
do x <- ma
   y <- mb
   return (x + y)
```

等价于下面的 bind 链式写法：

```haskell
ma >>= \x -> mb >>= \y -> return (x + y)
```

**do 记法让「单子计算」读起来像「命令式代码」**——这正是单子在
纯函数语言里模拟「顺序执行」的方式。**单子让「纯函数世界」
里也能写「有副作用」的程序**（IO），这是它名满天下的原因。<span class="marginnote">「用纯函数模拟副作用」
的哲学很有意思：IO 单子并没有「真的」执行副作用——它把
「与世界的交互」建模成一个数据结构，由运行时解释。
<strong>这呼应本书的主题：一个东西可以被「表示」而不必「实现」</strong>——
IO 是一种「副作用的替身」（第四篇「替身」概念的极致应用）。</span>

## 5 单子的意义：效应封装

为什么单子如此重要？因为它统一了「带效果的计算」：

| 单子 | 上下文（效果） | 用途 |
| --- | --- | --- |
| Maybe | 可能失败 | 空安全、错误传播 |
| Either | 带错误信息 | 异常处理 |
| List | 多个结果 | 非确定性 |
| State | 可变状态 | 状态机 |
| Reader | 只读环境 | 依赖注入 |
| Writer | 累积输出 | 日志 |
| IO | 外部世界 | 副作用 |

**重点：单子让「不同效果」共享同一套「拼接语法」。**
无论失败、多结果、状态、副作用——都用 >>=（bind）顺序拼接。
**「同一套语法，不同语义」是抽象的最高形态**：一个接口
（Monad 类型类），多种实现（各单子）。这正是范畴论「结构主义」
的编程兑现——**不同的效果系统，共享同一个「结合 + 单位」
的结构**。<span class="marginnote">单子的哲学意义不止于编程：
它是「结构主义」的教科书案例——Maybe、List、IO 内容
千差万别，但<strong>结构相同</strong>（都是单子）。范畴论说「结构比内容
重要」，单子证明了这在工程上成立：一套代码（do 记法）
处理完全不同的效果。<strong>「结构相同」让你可以「一次学会、
处处使用」</strong>——这是抽象的最高回报。</span>

## 6 小结

- **单子** = 自函子范畴上的**幺半体**——口号的可计算化。
- 原料：**幺半群（第 4 节）→ 幺半体（张量积上的幺半群）→
  自函子范畴（复合当乘法）**。
- 两件套：**自函子 $T$ + 自然变换 $\eta$（return）与 $\mu$（join）**。
- 三条法则：**结合律 + 左右单位律**——「装进再压平不出错」。
- Hask 版：**return 与 >>=（bind）**；bind 可由 $\mu$ 定义；do 记法是语法糖。
- 意义：**统一「带效果的计算」**——Maybe、List、State、IO 共享一套语法。
- 哲学：**不同的效果系统，共享同一个结构**——结构主义的工程胜利。

在下一节，我们将把「最普适」推向极致——**伴随函子**：
那对「遗忘」与「自由」的函子之间最深刻的对应关系。
