## 为什么从实体抽取开始

构建流水线的第一道工序是**实体抽取**——从无结构的文本里挖出
「谁、哪里、什么时候、什么组织」这些**命名实体**。这一步是一切
知识抽取的地基：连「实体」都找不出来，后面的关系抽取、融合、
存储都无从谈起。这一节讲**命名实体识别（Named Entity Recognition, NER）**
的三代方法：**规则/词典**、**统计特征（CRF）**、**神经网络（BiLSTM-CRF、
BERT）**，以及**LLM 时代的提示式抽取**。理解 NER，
你就拿到了知识图谱构建的第一把铲子，也看到了 NLP 方法
「从规则到统计再到深度」的完整进化史。

## 1 任务定义：从「谁」到「标签序列」

**命名实体识别（NER）**：从文本中识别出命名实体及其类别——人（PER）、
组织（ORG）、地点（LOC）、时间（DATE）等。

NER 的标准做法是**序列标注（sequence labeling）**：把文本切成 token，
给每个 token 标一个标签，表示「它是不是实体、是什么实体的哪一部分」。
最常用的是 **BIO 标注**：

```
张三  在   谷歌   工作  。
B-PER  O    B-ORG  O    O
```

- **B-X**：实体 X 的开始（Begin）。
- **I-X**：实体 X 的中间（Inside）。
- **O**：非实体（Outside）。

**重点：NER 把「找实体」变成「给 token 贴标签」**——一个序列预测问题。
这一定义让 NER 能交给任意「序列标注器」处理（CRF、BiLSTM、Transformer），
也让它的评测变得客观（逐 token 比对标签）。<span class="marginnote">BIO 标注里
「B-X」与「I-X」的区分至关重要：没有 B，连续两个同名实体
（「张三和李四」）会被标成一段。序列标注的每一处设计，
都在处理「实体边界」这个 NLP 的经典难题。</span>

## 2 第一代：规则与词典方法

最早的 NER 靠**知识库与规则**：

- **词典/地名词典（gazetteer）**：维护人名、地名、组织名列表，
  在文本里查表匹配。
- **正则表达式**：日期、电话、邮箱等有固定模式的实体，
  用正则一条搞定。
- **上下文规则**：「XX 教授」「位于 XX」——靠触发词推断实体类别。

**优点：** 精确、可解释、不需要标注数据、在固定领域（如法律文号、
日期）里准确率极高。

**缺点：** 词典不完备、规则写不完（新实体层出不穷）、
跨领域要重写规则。**「词典 + 规则」的本质是「用人力编码知识」——
它精确但脆弱，恰似第四篇手工知识库的天花板。**<span class="marginnote">规则方法在
NLP 的遗产没有消失：<strong>正则 + 词典依然是今天 NER 流水线的「前处理层」</strong>，
用来保证高置信的固定实体不出错，再交给模型处理开放实体。
「规则兜底 + 模型开放」是工程上的常见双轨。</span>

## 3 第二代：统计特征与 CRF

统计方法把 NER 变成**特征驱动的分类/序列模型**。代表作是
**条件随机场（Conditional Random Fields, CRF）**——一个
考虑「相邻标签依赖」的序列模型。

CRF 为每个位置提取**特征**：

- 词形（`张三` 是专有名词、大写开头）；
- 词性（POS）；
- 前后词窗口；
- 词典命中；
- 形态（是否含数字、是否 URL）。

CRF 在「给定特征下给整个标签序列打分」，并用维特比算法找最优序列。
**它的强项是「全局一致性」**——能利用「I-PER 前必须是 B-PER 或 I-PER」
这类标签转移约束，避免「O 后面直接跳 I-ORG」的荒谬输出。

**重点：CRF 是「手工特征 + 结构化预测」的巅峰。** 它统治 NER 十多年，
直到深度学习的到来。它的局限也清晰：**特征要人工设计，泛化靠特征**——
换个领域，特征工程推倒重来。<span class="marginnote">CRF 与第五篇描述逻辑的
「推理」有奇妙的相通：CRF 的标签转移约束 ≈ 一阶马尔可夫的「状态图」，
维特比搜索 ≈ 动态规划。统计序列模型与符号推理的边界，
在 NER 这个小任务上曾经贴得最近。</span>

## 4 第三代：神经方法

2015 年起，神经网络接管 NER。两个里程碑：

- **BiLSTM-CRF（Lample et al., 2016）**：双向 LSTM 编码上下文，
  每个 token 得到向量表示，再接 CRF 层做标签解码。
  **特征从「人工」变成「自动学习」**——模型自己从词嵌入里
  学出「大写开头」「语义类别」等隐式特征。
- **BERT 时代（2019 起）**：用预训练 Transformer 做编码器，
  token 表示带上丰富的上下文语义；微调后 F1 大幅刷新。
  之后出现**span-based 方法**——直接预测「实体的起止区间」，
  更贴合「实体是一个连续片段」的本质。

**重点：神经方法的胜利是「表示学习」的胜利**——模型不再依赖
人工特征，而是从大规模文本里学出「什么是实体」的隐式知识。
**代价是「黑盒」与「数据依赖」**：需要大量标注数据，
且难以解释「为什么这么标」。<span class="marginnote">BiLSTM-CRF 把「上下文向量」与
「结构化标签」结合，是<strong>神经 × 符号</strong>融合的早期范例：编码器负责
「语义」（神经），CRF 层负责「结构约束」（符号）。这个「表示 +
约束」的双层设计，在第九篇神经—符号一节还会以更大规模回归。</span>

## 5 LLM 时代的抽取

大语言模型改变了 NER 的玩法：

- **提示式抽取**：用自然语言指令「找出文中所有公司名」，
  让 LLM 直接输出实体列表——零样本、少样本即可用。
- **统一抽取**：一个 LLM 同时做实体 + 关系 + 事件的联合抽取
  （下一个任务），替代级联流水线。
- **schema 约束**：把实体类型定义成 JSON Schema，强制 LLM
  按 schema 输出（第九篇详述）。

**重点：LLM 让 NER 从「专用模型」变成「通用能力」**——不必再为
每个领域训练专用 NER，一个通用模型 + 好提示词就能覆盖。
**但代价仍在：** LLM 输出不稳定、需要校验，且成本远高于
小型专用模型。**工程上「专用小模型打底 + LLM 兜复杂」是常见分工。**

## 6 三代方法对照

| 维度 | 规则/词典 | 统计（CRF） | 神经 | LLM |
| --- | --- | --- | --- | --- |
| 知识来源 | 人工规则/词典 | 手工特征 | 自动学习 | 预训练 + 提示 |
| 精度/召回 | 高精度低召回 | 中 | 高 | 高（不稳） |
| 标注数据需求 | 无 | 有 | 大量 | 少/零 |
| 跨领域迁移 | 差 | 差 | 好 | 最好 |
| 可解释性 | 高 | 中 | 低 | 低 |
| 成本 | 低 | 中 | 高 | 最高 |

**易错点｜评测看 F1，别只看精度**：NER 的精度是「找出的实体里对的
比例」，召回是「真正的实体里被找出的比例」。只调高精度（少标）
会漏实体，只调高召回（多标）会引入噪声。**评测基准（CoNLL-2003、
OntoNotes）统一报告 F1（两者调和均值）**——比较模型，永远用 F1。

## 7 小结

- NER 把「找实体」变成**序列标注**（BIO 标签），是一个客观可评测的任务。
- 三代方法：**规则/词典 → 统计（CRF）→ 神经（BiLSTM-CRF、BERT、span）**。
- 规则方法**精确脆弱**，统计方法**靠特征**，神经方法**靠表示学习**。
- **LLM 提示式抽取**让 NER 变成通用能力，但需校验、成本高。
- 评测看 **F1**（precision/recall 调和均值），标准基准 CoNLL-2003/OntoNotes。
- 工程分工：**规则兜底固定实体 + 专用模型开放实体 + LLM 处理复杂**。
- NER 是知识图谱构建的**第一道工序**，质量直接决定下游。

看如何从「认出了谁」走向「知道谁和谁是什么关系」。
