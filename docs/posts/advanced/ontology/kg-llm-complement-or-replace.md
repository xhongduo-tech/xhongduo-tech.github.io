# LLM 时代的知识图谱：互补还是替代

<div class="epigraph">
<p>大模型记住了很多知识，却常常记错；知识图谱记得很准，却记不全。它们不是对手，是天生的一对。</p>

## 为什么从「互补还是替代」开始

2022 年起，大语言模型（LLM）席卷一切，「知识图谱过时了吗」成为
悬在从业者头上的问题。LLM 的记忆里装着海量知识、能零样本回答，
看起来可以替代图谱。但答案远没有这么简单：**LLM 能说不能准，
图谱能准不能说**。这一节正面回答「互补还是替代」：
LLM 与知识图谱各自的强项与短板、为什么「记忆型」的 LLM
需要「锚定型」的图谱、以及两者如何分工协作。这是第九篇的
总纲——后续每一节（GraphRAG、抽取、约束生成、Agent、常识、
神经符号、幻觉抑制）都是这张「协作蓝图」的一个组件。

## 1 LLM 的强项与短板

**LLM 的强项：**

- **开放语义理解**：能处理未见过的表达、委婉说法、多义消歧。
- **零样本/少样本**：不需要标注，提示即用。
- **生成能力**：能写、能总结、能对话。

**LLM 的短板：**

- **幻觉（hallucination）**：自信地编造事实，且无法自我察觉。
- **知识截止**：训练数据有时间边界，新事实不知道。
- **无精确推理**：对「必须保证正确」的逻辑步骤（算术、多跳、
  规则一致）不稳定。
- **不可追溯**：答错了说不出「依据哪条事实」。

**重点：LLM 的短板恰好是知识图谱的强项**——图谱的事实是显式的、
可验证的、可溯源的、最新的。**LLM 提供「流畅与开放」，
图谱提供「准确与可查」。** 两者不是替代关系，而是互补关系。<span class="marginnote">把 LLM 的
「记忆」与第五篇的知识库对照：LLM 是「隐式记忆」（知识在权重里，
不可逐条检索），知识库是「显式记忆」（事实在库里，可逐条查询）。
<strong>「隐式 vs 显式记忆」是理解一切 LLM-图谱协作的钥匙</strong>——协作的本质，
就是让两种记忆互相借力。</span>

## 2 知识图谱的强项与短板

**知识图谱的强项：**

**精确**：每一条事实都是显式断言，可验证。
**可推理**：OWL/规则保证逻辑一致性（第五、六篇）。
**可追溯**：来源、时间、置信度都能挂上。
**结构化**：查询（SPARQL/Cypher）精准、可聚合。

**知识图谱的短板：**

**覆盖有限**：只有建进去的才算数，新知识要人工/半自动补。
**构建成本**：抽取、对齐、维护（第八篇）费时费力。
**表达刚性**：自然语言的多义、模糊、语境依赖难以建模。
**更新滞后**：领域变化要持续维护，跟不上「实时知识」。

**重点：图谱的短板恰是 LLM 的强项**——LLM 能低成本地从开放文本
抽取知识、能理解模糊表达、能辅助构建。**「图谱要覆盖广、要更新快」，
LLM 是天然的「知识供给器」；「LLM 要准、要可查」，图谱是天然的
「事实锚」。** 双向增强由此而来。<span class="marginnote">这个「互相补短」的结构
在第八篇已见端倪：远程监督用知识库造训练数据（图谱→模型），
LLM 抽取补全图谱（模型→图谱）。第九篇把它系统化成「双向
飞轮」——<strong>图谱喂 LLM 事实，LLM 反哺图谱构建</strong>。</span>

## 3 互补而非替代的三个论证

为什么不是替代？三个坚实的论证：

**准确性的不可让渡**：医疗、金融、法律场景「错一个」就是事故。
  LLM 的「大概对」在这些场景不达标——必须图谱兜底。
**可解释与可审计**：法规要求「为什么这么决策」。LLM 的黑盒
  无法回答「依据哪条事实」，图谱的显式三元组可以。
**知识的版本与来源**：企业需要「这条知识谁提供的、何时更新的」。
  LLM 给不了 provenance，图谱天生有。

**重点：替代叙事只成立在「准确性无所谓」的场景**（闲聊、初稿、
灵感）。一旦涉及「必须对、必须可查、必须可审计」，
图谱就是不可替代的底座。**「互补还是替代」的答案取决于
业务对准确性的要求——要求越高，图谱越不可少。**<span class="marginnote">这个论证与
第六篇「OWA vs CWA」同构：LLM 像「乐观的 OWA」（没把握也敢说），
图谱像「严谨的 CWA」（有凭据才下结论）。<strong>「敢说」与「敢准」
是两种不同的人格，产品需要的是「LLM 敢说 + 图谱敢准」的合体。</strong></span>

## 4 协作蓝图：第九篇的路线图

把「互补」落成工程蓝图，就是本系列的九节：

| 组件 | 协作方式 | 章节 |
| --- | --- | --- |
| GraphRAG | 图谱检索增强生成 | 第 2 节 |
| LLM 抽取 | 从文本自动建图谱 | 第 3 节 |
| schema 约束生成 | 用本体约束 LLM 输出 | 第 4 节 |
| 结构化验证 | JSON Schema/SHACL 校验 | 第 5 节 |
| Agent 记忆 | 图谱作长期记忆 | 第 6 节 |
| 常识推理 | 常识图谱 + LLM 常识 | 第 7 节 |
| 神经—符号 | 符号推理 + 统计学习 | 第 8 节 |
| 幻觉抑制 | 图谱作事实锚点 | 第 9 节 |

**重点：这八条路径共享一个核心——「让 LLM 的能力与图谱的准确
各司其职」。** 每一条都是一个「接口」：要么用图谱约束 LLM
（约束生成、校验、幻觉抑制），要么用 LLM 喂图谱（抽取、补全、
常识），要么两者深度融合（GraphRAG、Agent、神经符号）。
**第九篇的全部内容，都是这张协作蓝图的展开。**<span class="marginnote">把蓝图放回
全书坐标：第七篇的「本体工程」给协作提供 schema，
第八篇的「构建与存储」给协作提供数据与引擎，第九篇
给协作提供「LLM 这个新角色」。<strong>图谱 × LLM 不是新范式，
而是本体论工程传统在「生成式 AI」时代的自然延伸</strong>——
蓝图里的每个组件，都能在前面找到理论根。</span>

## 5 小结

- LLM 强在**开放理解与生成**，弱在**幻觉、截止、不可追溯**。
- 图谱强在**精确、可推理、可溯源**，弱在**覆盖、成本、刚性**。
- 两者**互相补短**：LLM 是「知识供给器」，图谱是「事实锚」。
- 替代叙事只在「准确性无所谓」处成立；要求越高，图谱越不可少。
- 协作蓝图八组件：**GraphRAG、LLM 抽取、约束生成、结构化验证、
  Agent 记忆、常识、神经符号、幻觉抑制**。
- 核心洞察：**「隐式记忆（LLM）× 显式记忆（图谱）」互相借力**。
- 一句话：**LLM 敢说，图谱敢准——合体才是完整的知识系统**。
