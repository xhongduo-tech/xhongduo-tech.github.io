## 为什么从 Return-to-go 开始

上一课我们确立了立场：Decision Transformer 把决策翻译成「给定前缀续写 token」。

但「前缀」里到底该放什么，是这份翻译成功与否的命门——放状态，学到的是行为克隆；放历史奖励，学到的是「复述平均水平」。

而 Chen 等人在 2021 年给出的答案是一个此前不常用的量：**Return-to-go（RTG）**。

它把「期望达到的总回报」直接塞进输入，让同一个网络按不同目标水平产生不同行为。

理解 RTG，就是握住整篇论文的钥匙。<span class="marginnote">Decision Transformer（Chen et al., NeurIPS 2021）的轨迹表示见其 §3：每条轨迹被写成 $(\hat{R}_1, s_1, a_1, \hat{R}_2, s_2, a_2, \dots, \hat{R}_T, s_T, a_T)$ 的 token 序列。本课对应这节的「return-to-go」定义。</span>

## 1 Return-to-go 的定义

**Return-to-go（返回目标，记作 $\hat{R}_t$）**：从当前时刻 $t$ 起到轨迹结束 $T$ 为止、尚未兑现的累积回报，即未来奖励之和。

$$
\hat{R}_t = \sum_{t' = t}^{T} r_{t'}
$$

它和「回报」$G_t$ 长得几乎一样，只差两点。

其一，**不乘折扣因子**——Decision Transformer 在离线数据上用的是无折扣求和。

其二，**它是已知量**——对离线数据集里的每条轨迹，奖励早就在那里，$\hat{R}_t$ 可以事后逐位算出。<span class="marginnote">在离线数据上，$\hat{R}_t$ 可以一次性离线算好，不需要在线交互，这是它能在监督学习框架里当作条件变量的前提。</span>

RTG 有个漂亮的递推关系：**$\hat{R}_t = r_t + \hat{R}_{t+1}$**。

今天的「还差多少目标」等于今天的奖励加上「明天还差多少」。

这条递推在推理阶段被反过来用：每收到一个真实奖励 $r_t$，就把条件里的 $\hat{R}$ 减去 $r_t$，保持「还差的目标」始终对准当初设定的总目标。

## 2 轨迹的 token 化：每个时间步三个 token

把 RTG 与状态、动作拼在一起，一条轨迹就被切成了规整的记号流：

$$
\tau = \left( \hat{R}_1, s_1, a_1,\ \hat{R}_2, s_2, a_2,\ \dots,\ \hat{R}_T, s_T, a_T \right)
$$

每个时间步贡献三个 token：**返回目标** $\hat{R}_t$、**状态** $s_t$、**动作** $a_t$。

它们分别走各自的线性嵌入（高维连续量）或查表嵌入（离散量），再加位置嵌入，逐时间步加和成一条向量序列，送入因果 Transformer。

模型的目标是：给定前 $K$ 步的全部 token，预测当前步的动作 $a_t$。<span class="marginnote">图见本页中部：轨迹 → 三 token 嵌入 → 因果自注意力 → 预测动作。这个「一组 token 加和」的做法直接继承自 GPT 式的因果语言模型，第三级《大模型原理》里有它的完整训练框架。</span>

![Decision Transformer 的轨迹 token 化与因果 Transformer](/images/decision-transformer/return-to-go-representation-1.svg)

于是训练目标写得很干净：最大化「给定条件，预测出数据里真实动作」的条件对数似然。

状态、返回目标都只是**条件**，只有动作是被预测的对象。

测试时同样干净：把想要的返回水平写进 $\hat{R}_t$，网络自回归地续写动作。

## 3 一个数值例子：三分段轨迹的 RTG

光有定义还不够，拿一条具体的三段轨迹把它走一遍。

设一条三段时间步的轨迹，奖励依次是 $r_1 = 2$、$r_2 = -1$、$r_3 = 3$，轨迹结束于 $T = 3$。

逐位算 RTG：

- $\hat{R}_3 = r_3 = 3$（最后一步，还差的就是这一步的奖励）；
- $\hat{R}_2 = r_2 + r_3 = -1 + 3 = 2$；
- $\hat{R}_1 = r_1 + r_2 + r_3 = 2 - 1 + 3 = 4$。

于是这条轨迹的 token 流是：

$$
\tau = \left( \underbrace{4}_{\hat{R}_1}, s_1, a_1,\ \underbrace{2}_{\hat{R}_2}, s_2, a_2,\ \underbrace{3}_{\hat{R}_3}, s_3, a_3 \right)
$$

注意几个容易被忽略的细节。

其一，**RTG 是「未来」的视角**：$\hat{R}_1 = 4$ 是整个「尚未兑现」的总目标，$r_1 = 2$ 只是其中第一步。

其二，**RTG 可以「跳水」**：第二步拿到 $-1$，$\hat{R}$ 从 4 掉到 2，幅度远超奖励本身——**RTG 的轨迹里藏着「这集过得好不好」的全程心跳**。

其三，**模型在训练中见过「$\hat{R}=4$ 时开头怎么走」这类组合**，于是测试时把目标设成 4，模型就按「目标 4 的走法」续写。<span class="marginnote">顺着这个例子看，RTG 序列其实是一段「目标水位线」：高水位段对应高手轨迹、低水位段对应平庸轨迹。模型学的正是「不同水位下的动作风格」的对照表。</span>

## 4 为什么是 RTG，而不是单步奖励

直觉上最自然的条件变量是「最近几步的奖励序列」。

但 Chen 等人的论证指出：**RTG 比奖励序列更优，因为它编码的是「这一集要达成什么」的完整目标，而不是「过去发生了什么」。**

举一个例子：在半猎豹（HalfCheetah）这类任务上，把条件从「奖励序列」换成「RTG」，同样的网络性能立刻拉开明显差距。

更深一层：行为克隆学的是「数据的平均行为」，而 RTG 条件让模型学会**「当目标足够高时，我就模仿高手；当目标很低时，我随便走走」**。

目标水平成了切换行为风格的开关——这正是离线强化学习里「从静态数据中提炼出超越数据平均质量策略」所需要的那种能力。<span class="marginnote">需要注意，RTG 条件要起作用，数据集里必须真的存在「高返回 vs 低返回」的对比信号。数据里如果全是随机轨迹，RTG 再怎么调也变不出高手，这是后文《序列建模 RL 局限性》的主题。</span>

**辨析｜易错点：** RTG 不是「把奖励换成未来奖励的累加」这么简单的工程改动。

它改变了**学习的对象**：奖励序列条件告诉模型「你过去走得怎么样」，RTG 条件告诉模型「你还想走到哪」——一个是事后的总结，一个是事前的目标。

模型据此学到的，前者是「复盘」，后者是「朝着目标执行」。

两者在数学上只差一个累加号，在语义上差着一整层「目标性」。

## 5 公式解析：RTG 与折扣回报的关系

把 RTG 与上一课的折扣回报并排写，能看清它们的分工：

$$
\underbrace{\hat{R}_t = \sum_{t'=t}^{T} r_{t'}}_{\text{RTG：无折扣、离线可算、作为输入条件}} \qquad \underbrace{G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}}_{\text{回报：带折扣、在线未知、作为优化目标}}
$$

三步拆解。

**第一步，看折扣**：$G_t$ 用 $\gamma < 1$ 压远奖，让无穷求和有意义；$\hat{R}_t$ 在有限长度的离线轨迹上直接求和，不需要折扣，语义也更直白——「我还差多少分达标」。

**第二步，看角色**：在传统方法里，$G_t$ 是价值函数的**回归目标**；在 Decision Transformer 里，$\hat{R}_t$ 是策略网络的**输入条件**。

同一个「未来奖励之和」的量，一个被当作要估的靶子，一个被当作要用的话筒。

**第三步，看推理时的用法**：设初始目标为 $\hat{R}_1 = g$，每当真实环境返回奖励 $r_t$，就把条件更新为 $\hat{R}_{t+1} = \hat{R}_t - r_t$。

目标达成与否、超额与否，都被换算成「剩余缺口」喂回网络——**条件随交互实时修正**，这是 RTG 与静态行为克隆最本质的差别。

这条「递推更新」也解释了为什么模型要看到最近 $K$ 步而非整条轨迹：$K$ 步窗口里的 $( \hat{R}, s, a )$ 三元组已足以刻画「当前处于什么目标水平、什么状态、刚做过什么」，更长历史往往只会稀释信号。

## 6 小结

- **Return-to-go** $\hat{R}_t = \sum_{t'=t}^{T} r_{t'}$ 是轨迹尚未兑现的累积回报，无折扣、离线可逐位计算。
- 轨迹被 token 化为 $(\hat{R}_t, s_t, a_t)$ 三 token 流，RTG 只作**条件**、动作才是预测目标。
- **选 RTG 而非奖励序列**：它编码「本集要达成什么」，是切换行为风格的开关，让模型能超越数据的平均质量。
- 推理时 RTG 按 $\hat{R}_{t+1} = \hat{R}_t - r_t$ 实时修正，把「剩余缺口」持续喂给网络。
- 训练目标是条件对数似然：最大化「在给定目标水平下复述数据动作」的概率。
- **数值直觉**：RTG 序列是全程「目标水位线」，高低水位对应高手与平庸，模型学的就是「水位—风格」对照表。

在下一节，我们将拆开这个框架的发动机——**因果自注意力 Transformer**：它如何只让信息从过去流向未来，又如何把 $K$ 步的三 token 序列变成一列可预测的动作。
