## 为什么从因果自注意力开始

上一课我们拿到了 Decision Transformer 的「剧本」：轨迹被 token 化成一列 $( \hat{R}, s, a )$ 三元组。

但光有剧本没有剧场——真正把「前缀 → 预测下一个动作」演出来的，是 **Transformer** 的因果自注意力机制。

它决定了信息只能从过去流向未来，决定了模型能在多大窗口上捕捉「目标水平如何塑造动作风格」。

这一课把它解剖开：注意力怎么算、因果掩码怎么加、多头怎么分工、以及它如何在 Decision Transformer 里被复用。<span class="marginnote">Transformer 的完整推导（位置编码、层归一化、残差、FFN）在第三级《深度学习》与《大模型原理》里逐节展开，本课只讲 Decision Transformer 用到的因果自注意力核心。</span>

## 1 从「查字典」到自注意力

**自注意力（self-attention）**：让序列里的每个位置，按照与其他位置的「相关性」加权汇总信息，相关性由查询、键、值三套向量之间的内积决定。

先讲直觉。想象一行 $L$ 个 token 排成矩阵 $X \in \mathbb{R}^{L \times d}$，每个 token 是一行 $d$ 维向量。

自注意力为每个位置准备三份投影：**查询（Query）$Q$**、**键（Key）$K$**、**值（Value）$V$**。

一次注意力的计算公式是：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left( \frac{Q K^{\top}}{\sqrt{d_k}} \right) V
$$

其中 $Q = XW_Q$、$K = XW_K$、$V = XW_V$ 分别是输入乘三套可学习权重矩阵的结果，$d_k$ 是键向量的维度。<span class="marginnote">$QK^\top$ 里第 $(i, j)$ 个元素是「第 $i$ 个位置想查询、第 $j$ 个位置能否回答」的相关性分数——相似度越高，内积越大。除以 $\sqrt{d_k}$ 是为了防止内积随维度增大而数值爆炸，softmax 再把它变成一组和为 1 的权重。</span>

打个比方：把序列想象成一场问答会。

每个 token 都同时是「提问者」（Query）与「应答者」（Key/Value）。

某个 token 想知道「我该模仿谁的动作风格」，它就把自己的 Query 拿去跟所有 Key 比对相似度；相似度高的应答者，其 Value 被更多地采纳进输出。

**输出是「按相关性加权平均的答案汇总」。**

## 2 因果掩码：只准回望，不准偷看

如果 $QK^\top$ 不加限制，第 $t$ 个位置就能「看到」未来的 token——这在语言模型里叫作弊，在决策里更是致命：**动作预测不能参考「未来的状态」，否则训练时靠偷看未来得分、测试时无未来可看，性能崩盘**。

**因果掩码（causal mask）**：把注意力矩阵的上三角（即「当前位置 ← 未来位置」的位置）全部替换为一个极大的负数（实践中用 $-\infty$），经过 softmax 后这些位置的权重归零。

于是每个位置只能从**它自己以及更早的位置**收集信息：

$$
\text{MaskedAttention}(Q, K, V) = \text{softmax}\left( \frac{Q K^{\top}}{\sqrt{d_k}} + M \right) V, \qquad M_{ij} = \begin{cases} 0, & j \le i \\ -\infty, & j > i \end{cases}
$$

**因果关系是自回归模型的纪律**：预测 $t$ 时刻动作时，模型可用的信息严格限于 $t$ 及以前的 token。

在 Decision Transformer 里，$L = 3K$ 个 token（$K$ 步 × 每步 3 个），掩码让第 $t$ 步的返回目标、状态、动作只能聚合它们自己以及前面 $t-1$ 步的信息。<span class="marginnote">这与 GPT 的训练完全同构——第三级《大模型原理》里「预训练 = 在因果掩码下预测下一个 token」的表述，到这里只需把「词」换成「三元组 token」。</span>

一个容易踩的坑是掩码的「时间步」边界：$3K$ 个 token 里，第 $t$ 步的「返回目标 token」能不能看到同一步的「状态 token」？

DT 的实现里，同一步的三 token 是加和成一条向量再进入网络的——**「一个时间步」在 Transformer 眼里是整一个位置**，掩码的粒度是「位置」，不是「子 token」。

这也是「逐时间步加和」这个设计的意义：它把「同步信息」预打包，让因果掩码天然只切在时间步之间。

## 3 多头注意力：分工与综合

单头注意力的相关性子空间可能太窄。

**多头注意力（multi-head attention）**把 $d$ 维空间切成 $h$ 个 $d/h$ 维子空间，每个头独立做一次注意力，再把结果拼起来过一次线性投影：

$$
\text{head}_i = \text{Attention}(XW_i^Q, XW_i^K, XW_i^V), \qquad \text{MultiHead}(X) = [\text{head}_1; \dots; \text{head}_h] W_O
$$

**直觉：不同头可以分工盯不同的关系**——某个头可能负责「返回目标与动作风格」，另一个头负责「状态序列的连续性」。

多头的价值在于把「关注什么」这个问题的多个候选答案并行摆出来，再由 $W_O$ 综合取舍。

在决策场景里，一个常见的可解释性观察是：部分头确实学出了「对齐当前目标水平」的模式——它们会把注意力集中在「返回目标 token」上，把它当成行动指南。

在标准 Transformer 里，注意力之后还要接残差、层归一化与逐位置的前馈网络（FFN），叠 $N$ 层。

Decision Transformer 沿用了这套堆叠：输入是 $3K$ 个 token 的嵌入加和（见上一课的图），输出取「当前步动作位置」的那一行，过一层线性头变成动作的预测分布。<span class="marginnote">DT 论文采用类似 GPT 的因果结构，超参也常见：上下文 $K$、头数、层数、嵌入维度，配合标准的 dropout 与权重衰减。它的「语言模型」前身是 GPT-2 架构。</span>

## 4 公式解析：注意力权重到底在算什么

把最核心的 softmax 展开，注意力权重 $A_{ij}$ 的含义就一目了然：

$$
A_{ij} = \frac{ \exp\left( \frac{q_i^{\top} k_j}{\sqrt{d_k}} \right) }{ \sum_{j' \le i} \exp\left( \frac{q_i^{\top} k_{j'}}{\sqrt{d_k}} \right) }, \qquad \text{输出}_i = \sum_{j \le i} A_{ij} v_j
$$

三步拆解。

**第一步，看分子**：$q_i^{\top} k_j / \sqrt{d_k}$ 是第 $i$ 个 token 与第 $j$ 个 token 的「相似度分数」，越大表示 $j$ 越能回应 $i$ 的查询。指数函数把它变成正的权重原型。

**第二步，看分母与掩码**：分母只对 $j' \le i$ 求和——这正是因果掩码的代数形式，未来位置根本不在分母里出现。softmax 保证 $\sum_j A_{ij} = 1$，权重归一成概率。

**第三步，看出力**：输出是「按相关性权重加权平均的值向量」$\sum_j A_{ij} v_j$。

**自注意力的本质，是一次按需召回的加权平均**：每个位置自己决定要吸收谁的什么信息。

$N$ 层叠起来，就允许「第 1 步的目标水平」一路影响「第 $K$ 步的动作」——长程依赖由此建立。

用两个 token 的微型例子走一遍。

设两个位置的相关性分数（$\sqrt{d_k}$ 归一化后）为 $s_{11} = 2.0$、$s_{12} = 0.5$。

**不带掩码**时：softmax 权重约 $(0.82, 0.18)$——位置 1 会吸收 18% 的「未来」信息。

**带上因果掩码**后，$M_{12} = -\infty$，$e^{-\infty} = 0$，权重变成 $(1.0, 0)$——未来被彻底关在门外。

这 18% 的差别，就是「偷看」与「不偷看」的全部差别：训练时看着无关紧要，测试时就是生与死。

## 5 小结

- **自注意力** $\text{softmax}(QK^\top/\sqrt{d_k})V$ 通过「查询—键」相似度做按需召回的加权平均。
- **因果掩码**把 $M_{ij} = -\infty \ (j > i)$ 填入上三角，保证预测只用过去信息——这是自回归与决策「不许偷看未来」的纪律。
- **多头注意力**并行捕捉多种相关性（目标↔动作、状态↔状态等），再综合成输出。
- 标准堆叠 = 注意力 + 残差 + 层归一化 + FFN，叠 $N$ 层；DT 用它在 $3K$ 个 token 上建模，输出当前动作的预测。
- **掩码粒度**是「位置」不是「子 token」——同一步的三 token 先加和，因果边界切在时间步之间。
- **长程依赖**：目标水平可以跨越 $K$ 步影响动作，这是序列建模框架的结构性优势。
