# 智能体的定义与能力

## 为什么从定义开始

这个网站叫「从极限到大模型」。**极限**教会我们如何让一个过程无限逼近目标，**大模型**让我们学会让机器理解语言、记忆与知识，
而**智能体（agent）**是这条主线最新的延伸——它不再满足于「回答一个问题」，
而是「在一个真实或数字的世界里**行动**」。
<span class="marginnote">回顾第四级《大模型原理》的最后一节：纯语言模型是「被动的知识库」，
而智能体把它改造成「主动的执行者」。
从被动到主动，
是这条主线上最大的一次范式跃迁。
</span>

定义是整座大厦的地基。
今天如果把「智能体」理解成「会调用工具的大模型」，
后面学 ReAct、多智能体、记忆系统时就会处处返工；
反过来，
把定义想清楚，
你会看到 Toolformer 与 ChatGPT 的差别、AutoGPT 与普通脚本的差别，
其实都是同一个定义在起作用。

## 1 智能体是什么

罗素与诺维格在《人工智能：一种现代方法》里给出一个**通用定义**：**智能体（agent）是通过传感器（sensor）感知环境，
通过执行器（actuator）作用于环境的任何事物。** 环境（environment）是智能体之外的一切；
感知序列（percept sequence）是智能体截至当前收到的全部感知输入的完整历史。

这个定义里有三个关键词，
是判断「一个系统算不算智能体」的试金石：

- **感知（perceive）**：从环境里获取信息。
  对人的智能体来说，
  传感器是眼耳口鼻；
  对大语言模型智能体来说，
  「传感器」是输入的文本、图片、函数返回结果。
- **决策（decide）**：根据感知序列选择下一步动作。
  这是智能体函数（agent function）的核心：把感知历史映射到动作。
  <span class="marginnote">罗素与诺维格把「智能体程序」（在机器上运行的具体实现）与「智能体函数」（描述行为的数学对象 $f: \mathcal{P}^* \to \mathcal{A}$）分开。
  $f$ 把所有可能的感知历史映到动作集合 $\mathcal{A}$，
  程序只是 $f$ 的一个可实现版本。
  这个区分和数学里「函数 vs 算法实现」的区分同构。
  </span>
- **行动（act）**：通过执行器改变环境。
  对代码智能体，
  执行器是命令行与文件系统；
  对机器人智能体，
  执行器是电机与机械臂。

**智能体的本质是「感知—决策—行动」的闭环，
而不是某个具体技术。** 一个纯函数调用脚本不是智能体，
因为它没有「感知—决策」环节；
一个没有环境反馈的大模型对话也不是智能体，
因为它没有「行动」环节。
理解这一点，
是本节最重要的一句话。

## 2 智能体的能力组件

从「定义」到「能力」，
中间隔着工程。
一个现代大语言模型智能体（LLM-based agent）通常由四个组件拼装而成：

- **大模型大脑（brain）**：负责推理、理解指令、生成计划与中间思考。
  这是智能体的「决策器」，
  对应第 1 节智能体函数里的映射本身。
- **工具（tools）**：一组可供调用的外部函数，
  如搜索引擎、代码解释器、数据库查询、日历 API。
  工具是智能体的「执行器」扩展。
  <span class="marginnote">工具的类型直接影响智能体的能力边界：只有文本生成的工具，
  智能体就只能「说」；
  有了代码解释器，
  它就能「算」；
  有了浏览器 API，
  它就能「上网」。
  给智能体配什么工具，
  等于给它配什么手脚。
  </span>
- **记忆（memory）**：短期记忆保存当前任务的上下文（通常就是对话窗口）；
  长期记忆保存跨会话的知识与经验（向量数据库、外部知识库）。
  详见本专题《检索与记忆机制》与《Agent 的长期记忆与状态》。
- **行动循环（action loop）**：把感知、推理、调用工具、观察结果、再推理串成一个循环的控制器。
  ReAct 与 Plan-and-Execute 就是两种著名的循环形态。

这四件套的顺序不是随意的：**大脑提供「会想」，
工具提供「会做」，
记忆提供「记得」，
循环提供「持续」**。
缺了循环，
前三者只是一堆静态能力；
缺了记忆，
循环只能活在当前对话里。

## 3 感知—决策—行动的闭环

把四组件合起来，
就得到一个可运行的闭环。
以「帮我查下周二的天气并提醒我带伞」为例，
走一遍完整的循环：

1. **感知**：智能体收到用户请求，
   解析出意图（查询天气）、实体（下周二）、附加动作（提醒）。
2. **规划与决策**：大脑判断「需要外部数据」，
   决定调用天气 API，
   并规划参数（城市、日期）。
3. **行动**：执行器发起 API 调用，
   拿到 JSON 响应。
4. **观察**：智能体把返回数据「感知」回来，
   解读为「下周二 40% 降水」。
5. **再决策**：判断降水概率高，
   决定生成提醒并建议带伞。

注意第 4、5 步：**行动的结果又变成新的感知输入**。
这就是「闭环」的含义——环境因为智能体的行动而改变，
改变的痕迹再通过传感器回到智能体。
<span class="marginnote">这个闭环与强化学习里的「状态—动作—回报」循环同构（见第四级《强化学习》）。
区别在于：强化学习通过试错学策略，
智能体通过推理与工具调用即时行动。
一个重「学」，
一个重「思」，
两者正走向融合——这正是本专题《智能体学习（自我进化）》的主题。
</span>

一个常见的误区是认为「循环 = 重复调用模型」。
真正的循环需要**状态**：智能体必须记住自己已经做过什么、环境变成什么样、还剩几步，
否则会陷入「反复查同一份数据」的死循环——这也是工业界要引入显式状态追踪的原因。

## 4 核心对比：智能体与相关系统

「智能体」是近年被用得最泛滥的词之一。
要守住定义，
最有效的办法是把容易混淆的几个概念并排比较：

| 系统 | 有没有感知 | 有没有行动 | 有没有环境反馈 | 一句话判别 |
| --- | --- | --- | --- | --- |
| 传统程序（脚本） | 无 | 有 | 无 | 直线执行，不回头看 |
| 专家系统（规则引擎） | 有（输入） | 有（结论） | 无 | 静态知识推理，不接触世界 |
| 大语言模型对话 | 有（提示词） | 无（只输出文本） | 无 | 只说不做 |
| 强化学习智能体 | 有 | 有 | 有（回报） | 在环境中试错学习 |
| 大模型智能体 | 有 | 有（工具） | 有（观察） | 用推理驱动行动 |

**辨析｜易错点：** 「会调用工具」不等于「智能体」。
如果调用链条是固定的「读文件 → 查数据库 → 写报告」，
没有根据观察结果改变下一步，
那它只是**工作流（workflow）**，
不是智能体。
判别的核心标准只有一个——**决策是否根据环境反馈动态调整**。
<span class="marginnote">「工作流 vs 智能体」的界线在工业界极为重要，
因为它决定工程架构：工作流用编排引擎实现（DAG、定时任务），
智能体则需要推理引擎、工具注册表与状态管理。
第 19 篇《Agent 与工作流自动化》会专门讨论二者如何分工。
</span>

## 5 小结

- 智能体的**通用定义**：通过传感器感知环境、通过执行器作用于环境，
  核心是「感知—决策—行动」闭环。
- 智能体的能力来自四个组件：**大脑**（推理）、**工具**（行动）、**记忆**（状态）、**循环**（持续）。
- **闭环的本质**是行动结果重新变成感知输入，
  因此智能体必须有状态追踪。
- 判别一个系统是不是智能体，
  看它**是否根据环境反馈动态决策**，
  而不是看它有没有调用工具。

我们将把「感知—决策—行动」的闭环拆开，
细看每一环在工程上具体如何实现——这就是**感知-规划-行动循环**。
