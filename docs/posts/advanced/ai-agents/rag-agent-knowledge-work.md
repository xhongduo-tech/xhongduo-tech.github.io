## 为什么从 RAG 讲起

「知识工作」（knowledge work）——调研、写作、分析、决策——是大模型最擅长的战场，
但纯模型有个致命短板：**它的知识冻结在训练时点，
还容易一本正经地编造**。**RAG（检索增强生成，
Retrieval-Augmented Generation）**给模型接上「外部知识库」：先检索相关资料，
再基于资料回答。
<span class="marginnote">回望第 4 篇《检索与记忆机制》：记忆系统的检索原理——向量相似度、BM25、两阶段打分——正是 RAG 的检索内核。
RAG 可以理解为「把外部知识库当作智能体的一种长期记忆」：每次回答都现场去「记忆」里取相关片段。
你在第四级《大模型原理》和第三级《信息检索》里学过的检索技术，
在这里变成 RAG 的引擎。
</span>

这一节我们讲三件事：RAG 的经典流水线、RAG 如何「Agent 化」、以及它在知识工作中的真实形态。

## 1 RAG 的经典流水线

RAG 的核心是一条**「检索 → 生成」流水线**，
通常拆成四个环节：

1. **文档切分（chunking）**：把长文档切成小段（chunk）。
   切法直接影响检索质量——切得太碎丢语义，
   切得太整召回率低。
2. **索引与向量化（indexing）**：把每个 chunk 编码成向量，
   建立向量索引（第 4 篇的向量数据库）。
3. **检索（retrieval）**：把用户问题也编码成向量，
   在索引里取回最相关的 top-$k$ 个 chunk。
4. **生成（generation）**：把「问题 + 检索到的 chunk」拼进提示词，
   让模型**基于资料**回答，
   并要求标注来源。

**重点：RAG 的目标不是「找资料」，
而是「让生成有据可依」。** 检索到的 chunk 不是给用户看的原文，
而是给模型的「参考资料」——它把模型的答案锚定在真实知识上，
既降低幻觉，
又让答案可溯源。
<span class="marginnote">「让生成有据可依」在数学上是给模型一个「条件」：从 $P(\text{答案} \mid \text{问题})$ 变成 $P(\text{答案} \mid \text{问题}, \text{资料})$。
检索到的资料<strong>限定了答案的空间</strong>，
这是 RAG 降低幻觉的本质机制——答案被「关在」真实资料的笼子里。
</span>

**辨析｜易错点：** 检索增强 ≠ 「搜索 + 生成」的简单拼接。
经典 RAG 的成败关键在于**检索质量**：如果 top-$k$ 没取回真正相关的资料，
生成环节再强也「无米下锅」。
所以工程上 70% 的力气花在切分、索引、检索优化上，
而不是生成提示上。

## 2 从 RAG 到 RAG Agent：检索的智能化

经典 RAG 有一个假设：**「一次检索就够了」**。
但真实的知识工作往往需要多轮、多源的探索——一个问题的答案散落在多份文档里，
需要多跳推理。
这促成了 RAG 的「Agent 化」，
即**Agentic RAG**：让检索本身成为一个智能决策过程。
核心升级有四：

- **查询改写（query rewriting）**：Agent 先把「模糊问题」改写成「多个精确检索词」。
  例如「AI 会取代知识工作吗」改写为「自动化对白领职业的影响」等多路查询。
- **迭代检索（iterative retrieval）**：第一轮检索结果不够，
  Agent 根据已有线索生成**追问查询**，
  逐步深入。
  这实现了「多跳推理」（multi-hop）：第 2 轮的检索词由第 1 轮的结果决定。
- **自反思检索（self-reflective retrieval）**：Self-RAG（Asai et al., 2023）让模型在生成中**自检**：「检索到的资料够不够？
  要不要再检索？
  答案是否忠于资料？
  」用一个「反思 token」显式控制检索的触发与终止。
  <span class="marginnote">Self-RAG 把第 5 篇的「反思」从「事后复盘」前移到了「事中控制」——不是做完了再想对不对，
  而是<strong>边做边判断该不该继续</strong>。
  它在生成流里插入了`` <retrieve> ``、`` <grounded> ``这样的控制记号，
  让模型自己决定「何时查、何时答、答得是否忠实」。
  </span>
- **工具化检索（tool-augmented retrieval）**：把检索本身封装成工具（第 3 篇的函数调用），
  Agent 可以组合「检索 + 计算 + 代码解释」完成更复杂的分析。

**重点：RAG Agent 的本质是「把检索从一次函数调用，
变成受推理驱动的决策链」。** 经典 RAG 问「查什么」，
RAG Agent 问「查几次、怎么查、查完够不够」。

## 3 RAG 与微调、与智能体：三者的分工

知识工作里，
「怎么给模型接知识」有三条路线，
经常被混淆，
放在一起对比：

| 路线 | 知识存储 | 知识更新 | 幻觉风险 | 适用场景 |
| --- | --- | --- | --- | --- |
| 微调（fine-tune） | 写进模型权重 | 要重新训练 | 中（固化但可能编） | 风格、领域语言、固定格式 |
| RAG | 外部知识库 | 换文档即更新 | 低（有据可依） | 事实问答、资料综述、时效知识 |
| 智能体 | 外部世界 + 工具 | 实时获取 | 中（可验证） | 需要行动、多步推理的复杂任务 |

**辨析｜易错点：** 这三者不是「选一个」，
而是**互补**。
微调教「怎么说」（风格与领域规范），
RAG 教「说什么」（事实与资料），
Agent 教「怎么做到」（行动与工具）。
成熟的知识工作系统往往三者叠加：**微调过的模型 + RAG 知识底座 + Agent 行动循环**。

## 4 公式解析：RAG 生成的条件概率

把 RAG 的「检索增强」写成条件概率，
能精确看到它改了什么。
设问题为 $q$，
检索系统 $R$ 取回文档集合 $D_q$，
生成模型为 $P_\theta$，
则 RAG 的生成分布为：

$$
P_\theta(y \mid q) = \sum_{D \in D_q} P_\theta(y \mid q, D) \cdot P_R(D \mid q)
$$

逐项拆解：

- **$P_R(D \mid q)$ 是检索条件分布**：给定问题 $q$，
  检索系统认为文档 $D$「相关」的概率。
  工程上通常取 top-$k$ 离散近似：只保留得分最高的 $k$ 篇，
  给均等权重或按得分加权。
- **$P_\theta(y \mid q, D)$ 是生成条件分布**：给定「问题 + 某篇资料」，
  模型生成答案 $y$ 的概率。
  注意此时答案 $y$ 以资料 $D$ 为条件——**资料限定了生成空间**。
- **$\sum_{D}$ 是求和**：把所有可能的资料都纳入考虑。
  直觉上，
  RAG 模型「在所有可取回的资料上，
  对各自的生成做加权平均」——资料越相关，
  它的答案越有发言权。
  <span class="marginnote">这个求和结构在第四级《大模型原理》里也有对应：语言模型的生成是对所有可能的 token 序列做概率求和。
  RAG 是对<strong>资料集合</strong>求和，
  模型生成的每个 token 都要「看」到检索回来的证据。
  理解了这个公式，
  就理解了「RAG 为什么能降幻觉」——$y$ 的分布被 $D_q$ 牢牢钉在真实资料附近。
  </span>
- **简化的工程实现**：实际系统几乎不用求和，
  而是「取 top-$k$ → 直接条件生成」。
  这个简化牺牲了「所有文档的加权」，
  换来了效率与稳定性。

## 5 知识工作的 RAG Agent 形态

把 RAG Agent 放到真实的「知识工作」里，
它长什么样？
以一个「写一份行业调研报告」的任务为例：

1. **问题分解**：Agent 把「调研报告」拆成若干子问题：行业规模、头部玩家、技术趋势、竞争格局。
2. **多路检索**：对每个子问题，
   改写查询、多源检索（新闻、报告、数据库）。
3. **迭代深挖**：对关键数据「再查一层」，
   核对来源、追踪原始数据。
4. **组织成稿**：基于检索资料组织论点、标注引用。
5. **交叉验证**：让评审模块检查「每个论断是否都有引用支撑」，
   对无据断言发起补充检索。

**重点：知识工作的核心是「把问题拆开、把证据找齐、把论点钉在证据上」。** RAG Agent 让这条流水线从「人肉检索 + 人肉写作」变成「智能体自动探索 + 人类审阅」。
它的上限取决于「检索的广度 × 论证的严谨度」——而这正是第 15 篇《Agent 评测基准》要度量的东西。

## 6 小结

- RAG 经典流水线：**切分 → 索引 → 检索 → 生成**，
  核心是「让生成有据可依」。
- RAG Agent 化：**查询改写、迭代检索、自反思检索、工具化检索**，
  让检索从「一次调用」变成「推理驱动的决策链」。
- 微调、RAG、智能体三者**互补而非互斥**：微调教「怎么说」、RAG 教「说什么」、Agent 教「怎么做到」。
- RAG 的数学本质是条件生成 $P_\theta(y \mid q, D) \cdot P_R(D \mid q)$ 的加权求和，
  资料把答案「关」在真实证据里。
