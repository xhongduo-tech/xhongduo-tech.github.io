## 为什么从多模态讲起

到目前为止，
我们的智能体几乎都活在「文本世界」里：它读文本、写文本、调工具。
但真实世界是**多模态**的——网页有截图，
监控有视频，
机器人有摄像头，
医生的诊断靠 CT 影像。
<span class="marginnote">回望第 13 篇《浏览器与操作系统 Agent》：「视觉像素路线」就是多模态能力的雏形——模型靠「看图」理解界面。
多模态 Agent 把这个能力泛化：不只「看界面」，
而是「感知世界的一切形态」——图像、音频、视频、文档，
并在感知之上行动。
</span>

这一节我们看：多模态给智能体带来什么、架构怎么搭、以及它独特的挑战。

## 1 模态的意义：从「读描述」到「见本体」

为什么智能体需要直接感知图像、声音，
而不是靠「文字描述」？
三个理由层层递进：

**信息无损**：一张 CT 片、一段代码截图、一份手写笔记，
  文字描述永远有损。
  视觉 Agent 直接看原图，
  不经过「翻译损耗」。
**时空连续性**：视频与音频是**时间流**，
  文本是**离散片段**。
  自动驾驶、实时翻译这类任务，
  必须在模态流里即时感知，
  而不是「等一段描述写好」。
**具身行动**：机器人、无人机需要「看」才能「动」——感知与行动在物理世界里天然耦合。
  文本智能体可以「想好了再说」，
  具身智能体必须「边看边动」。
  <span class="marginnote">「边看边动」正是第四级《具身智能》的核心命题：机器人把视觉感知直接接上运动控制。
  多模态 Agent 与具身智能在这里交汇——区别只在于行动器是「虚拟工具」还是「物理本体」。
  你在《具身智能》里学的视觉-语言-动作模型（VLA），
  就是多模态 Agent 的物理形态。
  </span>

**重点：多模态的本质是「让智能体的感知通道与人类的感官对齐」。** 人类不是「先看、再翻译成语言、再思考」——而是视觉与语言并行处理。
多模态 Agent 追求的正是这种并行：让视觉理解直接参与决策，
而不是绕道文本。

## 2 多模态 Agent 的架构

多模态 Agent 的架构，
是在文本智能体骨架上「换感知器、加融合器」。
核心模块：

**多模态编码器（encoder）**：把图像、音频、视频编码成向量。
  现代 VLM（视觉-语言模型）用一个共享的表示空间把「图像 patch 的向量」与「文本 token 的向量」对齐，
  让模型既能「看图」又能「读文」。
  <span class="marginnote">「共享表示空间」正是第四级《多模态学习》的核心思想——CLIP 用对比学习把图像与文本拉到同一向量空间，
  VLM 则更进一步，
  让两者能互相推理。
  你在《多模态学习》学的对齐机制，
  是多模态 Agent 的感知底座。
  </span>
**推理大脑（reasoning core）**：一个多模态大模型，
  接受「文本指令 + 图像 + 音频」的混合输入，
  输出推理与动作。
  它是「看得懂图、说得出话、做得出决定」的中央处理器。
**多模态工具集（tools）**：除了文本工具，
  还接入图像生成、图像编辑、语音合成、视频检索等工具，
  让智能体不仅能「感知」多模态，
  还能「产出」多模态。
**模态记忆（modality memory）**：长期记忆里存的不只是文本——还有图像片段、音频摘要、视频关键帧。
  第 17 篇的记忆系统在多模态下多了「非结构化媒体」维度。

**辨析｜易错点：** 多模态 Agent ≠ 「会用 OCR 的文本 Agent」。
OCR 只是「把图转成文字」，
多模态 Agent 是「直接对图像做推理」——它理解图片的构图、人物的表情、图表的趋势，
而不是先把图变成文字再理解。**判断标准：去掉 OCR，
模型还能不能看图作答？** 能，
才是真多模态。

## 3 多模态 Agent 的典型场景

多模态能力解锁了三类文本智能体做不到的场景：

**视觉问答与文档理解（VQA / document AI）**：看图表回答问题、「把这张发票里的金额提取出来并核对」。
  既「看」又「算」。
**GUI 与计算机视觉行动（GUI agents）**：第 13 篇的视觉路线——直接截图理解界面并操作。
  多模态模型让 Agent 能处理「DOM 拿不到的」页面（canvas、视频、图片按钮）。
  <span class="marginnote">视觉 GUI Agent 与 DOM Agent 的关系：DOM 路线是「精确但不通用」，
  视觉路线是「通用但不精确」。
  多模态模型越强，
  视觉路线的精度越高，
  两条路线的差距越小——这是多模态能力直接改变 Agent 工程格局的实例。
  </span>
- **视频与实时流理解（video / streaming）**：监控视频找异常、会议录音转纪要与要点提取、实时翻译。
  模态是「时间流」，
  要求模型具备**时间感知**——不只理解单帧，
  还理解帧间变化。
- **多模态内容生产（multimodal generation）**：听完需求后「生成一张配图 + 一段文案 + 一段配音」，
  形成完整的营销素材。
  产出端也从文本扩展到多模态。

## 4 公式解析：多模态感知的信息融合

多模态 Agent 的「看 + 读」如何融合成决策？
把「融合」写成条件概率，
能看清信息如何汇聚。
设输入为图像 $I$ 与文本 $q$，
模型生成答案 $y$：

$$
P(y \mid I, q) \approx \sum_{\mathbf{z}} P_\theta(y \mid \mathbf{z}, q) \cdot P_\phi(\mathbf{z} \mid I)
$$

其中 $\mathbf{z}$ 是图像 $I$ 经编码器 $P_\phi$ 得到的视觉表示（视觉 token 序列）。
逐项拆解：

- **$P_\phi(\mathbf{z} \mid I)$ 是视觉编码**：把像素变成视觉 token 序列 $\mathbf{z}$。
  这个编码器把「图像语义」压缩进一组向量，
  是视觉信息的「翻译器」。
- **$P_\theta(y \mid \mathbf{z}, q)$ 是跨模态推理**：模型在「视觉 token + 文本」上生成答案。
  关键在 $\mathbf{z}$ 与 $q$ 的**对齐**——模型要能「看着图中对应的区域」回答问题（如「图右上角的价格是多少」）。
  <span class="marginnote">「看着对应区域回答」在技术上叫<strong>视觉接地（grounding）</strong>——模型不只生成文本，
  还能输出「这个答案对应图像哪个位置」的坐标。
  接地能力是视觉 Agent 可靠性的关键：它能「指给你看」，
  证明它是真的「看见」了，
  而不是在胡猜。
  </span>
- **$\sum_{\mathbf{z}}$ 是求和/近似的简化**：工程上不显式求和，
  而是把 $\mathbf{z}$ 作为前缀直接拼进模型输入（VLM 的标准做法），
  让模型在统一的 token 序列上做自回归生成。
- **融合的价值**：$I$ 提供了 $q$ 之外的信息——模型能回答「纯文本答不了」的问题。**融合的成败在于「对齐的质量」**：视觉 token 与文本 token 对齐得好，
  模型才能跨模态推理；
  对齐得差，
  图就是「摆设」。

## 5 核心对比：多模态 Agent 的感知路线

| 路线 | 感知方式 | 精度 | 通用性 | 成本 | 适用 |
| --- | --- | --- | --- | --- | --- |
| 纯文本代理 | OCR / 描述转文本 | 中 | 低 | 低 | 文本为主的任务 |
| 视觉辅助 | OCR + 截图兜底 | 中 | 中 | 中 | GUI Agent 的 DOM 补充 |
| 原生多模态 | VLM 直接看图 | 高（随模型提升） | 高 | 高 | 通用感知 + 行动 |

## 6 小结

- 多模态的意义：**让智能体感知通道与人类感官对齐**，
  信息无损、时空连续、支撑具身行动。
- 架构四件套：**多模态编码器、推理大脑、多模态工具、模态记忆**；
  判断「真多模态」看能否不靠 OCR 直接看图推理。
- 典型场景：**VQA、视觉 GUI、视频流理解、多模态生成**。
- 融合的数学本质是「视觉编码 $P_\phi(\mathbf{z}\mid I)$ + 跨模态推理 $P_\theta(y\mid \mathbf{z},q)$」，**对齐与接地质量决定融合成败**。
