# 感知-规划-行动循环

<div class="epigraph">
<p>智能体应当不仅仅是一个反应式的机器，而是一个能够想象未来后果、据此选择行动的规划者。</p>

## 为什么从循环开始

上一节我们建立了智能体的定义：感知、决策、行动构成的闭环。
但「闭环」是个抽象概念，**循环（loop）才是它的工程实现**——就像「极限」定义了收敛，
「迭代」才是逼近极限的具体过程。
<span class="marginnote">想一想数学里的递推数列 $x_{n+1} = f(x_n)$：每一步的输出是下一步的输入。
智能体的行动循环就是把这个结构搬到决策上——行动 $a_t$ 改变环境，
环境的新状态 $s_{t+1}$ 又成为下一轮感知的输入。
第 8 篇《智能体间的通信与协议》里你会再次见到这个结构被搬到多智能体之间。
</span>

感知-规划-行动（Perceive-Plan-Act, PPA）循环是所有智能体架构的共同骨架。
今天看它是「常识」，
但在 AI 的早期，
研究者花了整整二十年才想清楚：**反应**与**规划**不是互斥的，
而是可以共存于同一个循环里。

## 1 三种经典架构：从反应到深思

罗素与诺维格按「内部状态的有无」把智能体架构分成三代，
理解这条演化线，
就理解了为什么今天的大模型智能体长成这个样子：

- **简单反射式（simple reflex）**：看到什么就做什么，
  输入直接映射到动作，
  不维护任何状态。
  例子是温度超过阈值就开风扇的温控器。
  它快、省、但短视——无法处理「看到的东西有历史依赖」的场景。
- **基于模型（model-based）**：内部维护一个**世界模型**，
  记录「环境当前大概是什么样」，
  再根据模型决定动作。
  有了模型就能处理**部分可观测**环境：即使看不到全部，
  也能推断。
  <span class="marginnote">「部分可观测」是理解智能体的关键词：现实世界你永远看不到全部状态，
  只能靠感知拼接。
  智能体维护的内部世界模型，
  就是它用来补全「看不见的部分」的猜测。
  这跟第三级《计算机网络》里「协议栈不知道链路全局、只能靠相邻层信息推断」是同一个思想。
  </span>
- **目标驱动与效用驱动（goal-based / utility-based）**：在基于模型之上，
  再加一个「我想要的未来状态」。
  目标驱动只问「能不能达到目标」，
  效用驱动进一步问「哪个结果更好」。
  规划（planning）这个概念就在这一层诞生——**规划 = 在行动之前，
  先在内部推演若干步，
  选一条通向目标的路径**。

这条演化线回答了一个根本问题：**智能体该不该在行动前多想？** 反应式说「行动优先」，
目标驱动说「多想一步」。
而现代大模型智能体把两者合并进同一个循环：既保留反应式的即时工具调用，
又用大模型的推理能力做目标驱动的前瞻。

## 2 感知-规划-行动循环的完整形态

一个工程化的 PPA 循环通常写成五个阶段，
每次迭代称为一轮（turn）：

1. **感知（Perceive）**：采集环境信息——用户新消息、工具返回结果、传感器读数。
   这些信息先被清洗、结构化（例如把 JSON 解析成字段），
   再进入决策器。
2. **理解（Understand）**：对感知信息做语义解释，
   更新内部状态。
   这一步常被并入感知，
   但它其实是独立一环：同样的天气数据，
   在「带伞任务」和「统计气候任务」里含义完全不同。
3. **规划（Plan）**：根据当前状态与目标，
   产出下一步行动计划。
   计划可以细到「调用天气 API」，
   也可以粗到「先搜索，
   再总结，
   最后生成报告」。
4. **行动（Act）**：执行计划。
   执行器可能是函数调用、命令行、浏览器操作、机器人电机。
   <span class="marginnote">行动一定会<strong>改变环境</strong>，
   这是循环得以闭合的原因。
   但注意：行动也可能失败——API 返回 500、命令报错、爬虫被拒绝。
   失败也是一种观察，
   它是下一轮循环的输入。
   本专题《反思与自我修正》专门讨论智能体如何从失败中学习。
   </span>
5. **观察（Observe）**：采集行动的结果，
   回到第 1 步。

**重点：规划发生在行动之前，
观察发生在行动之后，
而观察的结果又会改变下一轮的规划。** 这就是 PPA 与「一次性生成」的本质区别——它不是一条直线，
而是一个螺旋上升的过程。

## 3 规划的花样：执行前想多远

「多想一步」和「想一百步」之间，
代价天差地别。
规划深度（planning depth）是智能体设计里最核心的权衡之一：

- **短视（reactive）**：每轮只规划一步，
  做完再看。
  好处是灵活、能即时纠错；
  坏处是容易被眼前的动作带偏，
  忘记长期目标。
- **前瞻（lookahead）**：在内部推演完整的多步计划，
  再开始执行。
  好处是方向明确；
  坏处是计划可能基于过时的环境假设——你规划的「第二步」可能早已因为第一步的副作用失效。
- **分层（hierarchical）**：高层定「做什么」（子目标序列），
  低层定「怎么做」（具体调用）。
  这是 Plan-and-Execute 范式的雏形，
  也是第 7 篇的主题。

三者之间不存在绝对优劣，
只存在**匹配**：任务越不可预测、环境变化越快，
越该短视；
任务越宏大、越需要整体把握，
越该前瞻。
<span class="marginnote">这个权衡在经典 AI 里被形式化为「规划 vs 反应」之争：STRIPS 规划器（1971）追求前瞻，
布鲁克斯的行为主义（1986）鼓吹反应。
今天的智能体框架普遍采用「先规划后执行、执行中再重规划」的折中——你会在本专题第 7 篇《思维链与规划》看到它的现代形态。
</span>

## 4 公式解析：循环的状态更新

感知-规划-行动循环可以用一组状态递推式精确表达，
这也是「循环」在数学上的严格写法：

$$
\begin{aligned}
\text{状态更新} &\qquad s_{t+1} = \text{Env}(s_t, a_t) \\
\text{感知} &\qquad p_{t+1} = \text{Sense}(s_{t+1}) \\
\text{决策} &\qquad a_{t+1} = \text{Policy}(p_{t+1}, m_t) \\
\text{记忆更新} &\qquad m_{t+1} = \text{Memory}(m_t, p_{t+1}, a_{t+1})
\end{aligned}
$$

拆开看每一步：

- **$s_t$ 是环境状态，
  $a_t$ 是智能体的行动**。
  第一行 $\text{Env}$ 表示：环境是**确定性或随机**地由「旧状态 + 行动」推出新状态。
  这一行把「行动会改变世界」写成了数学。
- **$p_t$ 是感知结果**。
  第二行 $\text{Sense}$ 表示：智能体看不到完整状态 $s_t$，
  只能看到它的一部分——这就是部分可观测（partially observable）。
  第三级《操作系统》里进程调度器看到的也只是就绪队列的快照，
  而非 CPU 的全貌。
- **$a_{t+1} = \text{Policy}(p_{t+1}, m_t)$ 是决策**。
  策略函数接受「当前感知 + 记忆 $m_t$」，
  输出下一个行动。
  记忆 $m_t$ 的存在让策略能够「记住历史」，
  不再是一个纯反射函数——这正是第 1 节从反射式到基于模型的跃迁。
- **$m_{t+1}$ 是记忆的自我更新**。
  这一行是智能体区别于普通程序的关键：它的内部状态随循环推进而演化。

**为什么这套式子值得写出来？** 因为它把「智能体」从模糊的形容词变成了精确的变量关系。
任何自称智能体的系统，
都可以代入这套式子问四个问题：它的环境是什么？
感知函数是什么？
策略是什么？
记忆如何更新？**四个问题答得越清楚，
系统越接近「真正的循环」；
答不上来，
多半只是披着循环外衣的顺序脚本。**

## 5 小结

- 智能体架构沿「反射 → 基于模型 → 目标驱动」演化，**规划**概念在目标驱动层诞生。
- PPA 循环五阶段：**感知 → 理解 → 规划 → 行动 → 观察**，
  观察结果回到感知，
  形成闭环。
- 规划深度是核心权衡：**短视、前瞻、分层**各有适用场景，
  现代框架普遍采用「先规划、执行中再重规划」。
- 循环的数学本质是状态递推 $s_{t+1} = \text{Env}(s_t, a_t)$ 与 $a_{t+1} = \text{Policy}(p_{t+1}, m_t)$，
  记忆 $m_t$ 是区分智能体与脚本的关键变量。

循环里最外显、也最容易被误解的一环是「行动」——我们将深入看智能体如何通过**工具使用与函数调用**真正改变环境。
