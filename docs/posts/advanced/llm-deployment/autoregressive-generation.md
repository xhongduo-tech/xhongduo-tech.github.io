## 为什么从自回归生成开始

部署一个 LLM，第一件事不是选显卡、不是配量化，而是看清它到底在算什么。无论你用 vLLM 还是 TensorRT-LLM 起服务，被调度、被优化、被压测的核心对象都是同一个循环：**逐 token 地预测下一个词，把新词拼回输入，再预测下一个**。这个循环叫**自回归生成（autoregressive generation）**。

整个「大模型部署」专题的知识树，几乎都是从这一句话生长出来的：KV Cache 是为了不重算已经看过的内容；Prefill 与 Decode 的划分把一次循环拆成两种截然不同的计算形态；Continuous Batching、投机解码、量化，全部是在为「单次循环」省时间、省显存。所以这一章，我们先把循环本身讲透。

它会用到两级此前的内容。《大模型原理》已经讲过 decoder-only 架构、因果掩码与 softmax 解码；《AI基础设施》讲清了 GPU 的显存层次与带宽。今天，我们把这两条线在「生成」这个动作上汇合：**概率上它是一次链式分解，工程上它是一趟访存之旅**。

## 1 自回归：用条件概率给语言建模

**自回归（autoregressive）**：一种序列建模方式——生成序列第 $t$ 个位置时，只把它看作「在已生成前缀 $x_1 x_2 \cdots x_{t-1}$ 条件下的下一个词」，然后逐个位置递推。一个自回归语言模型本质上给出的是条件概率 $P(x_t \mid x_{<t})$。<span class="marginnote">「自回归」这个名字来自统计学与时间序列分析：AR 模型用「自己的过去值」回归来预测「当前值」。LLM 把同一思想搬到了 token 序列上——每个新 token 都是「自己历史」的函数。</span>

为什么能用条件概率描述整句话？因为任意一个 token 序列的联合概率，都可以严格地写成一系列条件概率的乘积——这就是概率论里的**链式法则（chain rule）**：

$$P(x_1, x_2, \dots, x_n) = \prod_{t=1}^{n} P(x_t \mid x_1, x_2, \dots, x_{t-1})$$

这条式子是本章的地基，我们会在「公式解析」一节逐步拆开它。现在只需抓住它的两个含义：

- **联合概率可以分解**：整句话「太阳从东方升起」的概率，等于「太阳」×「从｜太阳」×「东方｜太阳从」×「升起｜太阳从东方」……逐词相乘。
- **生成的方向被唯一确定**：只有从左到右、给定前缀才能说话，这也正是 decoder-only 架构的**因果掩码（causal mask）**所强制的东西——第 $t$ 个位置看不到 $t$ 之后的任何 token。<span class="marginnote">「因果」是这条性质的名字：每一个 token 只能影响它后面的 token，如同时间只能流向未来。它把 Transformer 这种「全双向」的注意力结构，硬生生改造成了适合逐词生成的单向结构，见《大模型原理》因果掩码一节。</span>

**一个语言模型的全部能力，最终都收敛到一个函数**：给定前缀，输出一个覆盖词表的概率分布。词表大小记为 $V$（常见约 3 万到 15 万），那么模型每一轮输出的就是一个 $V$ 维的概率向量。

## 2 生成循环：预测 → 拼接 → 再预测

有了条件概率，生成就变成一个机械但关键的循环。输入一段初始文本（prompt），模型反复执行四步：

![自回归生成逐 token 流程示意：输入 → 预测 → 拼接 → 再预测](/images/llm-deployment/autoregressive-generation-1.svg)

1. **输入当前序列**：把已生成的 token 序列 $x_1 \cdots x_{t-1}$ 送入模型；
2. **预测分布**：模型前向计算，输出下一 token 的概率分布 $P(x_t \mid x_{<t})$；
3. **解码选择**：按某种**解码策略**从分布里挑出一个 token $x_t$；
4. **拼接回环**：把 $x_t$ 追加到序列末尾，序列长度加一，回到第 1 步。

循环何时停止？训练时学到的特殊 token **EOS（end-of-sequence）** 被生成出来时，或长度达到上限时。用代码写出来，这个循环短得惊人：

```python
def generate(model, prompt_ids, max_len=128):
    ids = prompt_ids.copy()
    while len(ids) < max_len:
        logits = model(ids)               # 前向计算，对下一个 token 打分
        probs = softmax(logits[-1])       # 取最后一个位置，变为概率分布
        next_id = decode_strategy(probs)  # 贪心 / 束搜索 / 采样
        ids.append(next_id)               # 拼接到序列末尾
        if next_id == model.eos_id:       # 生成结束符则停止
            break
    return ids
```

这个循环每执行一轮，模型就要**把整条序列从头到尾重新看一遍**。第 $t$ 步序列长度是 $t$，第 $t+1$ 步长度是 $t+1$——长度只加一，但模型并没有「记住」上一步，它每次都要重新处理整条前缀。<span class="marginnote">这正是接下来 KV Cache 要解决的问题：如果模型能记住已算过的 key 与 value，就不用每次都从头重算。注意「模型没有记忆」这句：自回归循环本身是状态无关的，所有状态都藏在被重新计算的输入序列里。</span>

## 3 KV Cache 引子：为什么缓存 key 和 value

要理解 KV Cache，先看注意力这一步在生成时干了什么。单头注意力（略去缩放因子）写作：

$$\text{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right) V$$

生成第 $t$ 个 token 时，Transformer 每一层都会为**新 token** 算出一组 query，并与**所有历史 token** 的 key、value 做注意力。关键在于：新 token 的 query 是新的，但历史 token 的 key 与 value——$k_1 \cdots k_{t-1}$ 与 $v_1 \cdots v_{t-1}$——在上一步算过之后，**一个字都不会变**。

于是「重新处理整条前缀」里绝大部分计算都是浪费：$Q$ 只有新的一行，$K$、$V$ 却要重算 $t-1$ 行。**KV Cache 的做法是把每一层的 key 和 value 缓存在显存里**，每一步只增量计算新 token 的那一行 $k_t, v_t$，再拼进缓存。<span class="marginnote">这也是「KV Cache」名字的由来：Cache 的正是注意力里的 K 与 V 两个矩阵，Q 从不缓存——因为每个新 token 都要重新生成自己的 query。逐 token 的注意力开销因此从每一步 $O(t^2)$ 降为 $O(t)$。</span>

缓存不是免费的，它吃显存。一个序列每多生成一个 token，KV Cache 的增长量是：

$$M_{\text{per token}} = 2 \cdot L \cdot H \cdot d \cdot b$$

其中 $L$ 是层数，$H$ 是每层注意力头数，$d$ 是每个头的维度（head_dim），$b$ 是每个元素的字节数（FP16 为 2 字节），系数 2 来自「K 一份、V 一份」。以 LLaMA-2 7B 为例：$L=32,\ H=32,\ d=128,\ b=2$，每个 token 占 $2 \times 32 \times 32 \times 128 \times 2 = 524{,}288$ 字节，约 **0.5 MB/token**；上下文填满 4096 token 就要 **2 GB**——这笔账，正是后面「PagedAttention」「KV Cache 量化」全部故事的起点。

## 4 解码策略引子：贪心、束搜索与采样

模型输出的是概率分布，最终落到序列上的却是一个确定的 token。把分布变成 token 的规则叫**解码策略（decoding strategy）**。三类最经典：

**贪心解码（greedy decoding）**：每步取概率最大的 token，即 $\arg\max P(x_t \mid x_{<t})$。简单、确定、快，但代价是**短视**——单步最优可能把序列带进死胡同，也容易陷入重复循环（「我我我我……」「好的好的好的……」）。

**束搜索（beam search）**：不再只留一个候选，而是每步保留概率最高的 $k$ 条假设（beam），各自扩展后按累计对数概率排序，淘汰低分分支。适合翻译、摘要这类「最优路径」明确的任务；但 $k$ 倍的计算开销与依然可能的重复，让它在大语言模型的聊天场景里用得越来越少。

**采样（sampling）**：从分布中**随机**抽取 token，让低概率词也有机会出场。为了让分布「更尖」或「更平」，先除以温度 $\tau$ 再取 softmax；再配合 top-k（只保留概率最高的 $k$ 个）与 top-p / nucleus（保留累计概率达 $p$ 的最小集合）截断长尾。<span class="marginnote">temperature 的完整数学在《大模型原理》采样一节展开：$\tau \to 0$ 时退化为贪心，$\tau \to \infty$ 时趋于均匀分布。这里只需记住：<strong>解码策略决定了「多样性 vs 确定性」的取舍，也直接影响生成质量与延迟</strong>。</span>

这一章先点到为止。部署视角更关心的是：解码策略运行在 softmax 之后、权重之外，属于**几乎免费的轻量操作**，真正贵的永远是第 2 步的模型前向。所以后面讨论吞吐、延迟与批处理时，我们把「前向计算」当作成本主体，把「解码策略」当作一个可替换的小开关——这个抽象在投机解码等加速技巧里尤其有用。

## 5 生成的计算特征：Prefill 与 Decode 是两种动物

从计算形态看，一次完整的生成被天然切成两段：**预填充（Prefill）**与**解码（Decode）**。

**Prefill（预填充）**：处理整段 prompt。此时序列里有 $n_{\text{prompt}}$ 个位置，模型可以**并行**地为所有位置同时计算——虽然要做因果注意力，但每个位置的结果互不依赖地算出来。这一段的算术强度高（算得多、读得相对少），接近**计算受限（compute-bound）**。

**Decode（解码）**：逐 token 生成。每步只有 1 个新位置要算，但为了算它，模型必须把**全部权重**从头到尾读一遍——7B 模型在 FP16 下约 14 GB 权重，全部要从 HBM 搬进计算单元，而产出只有 1 个 token。<span class="marginnote">GPU 的算术强度上限在《AI基础设施》Roofline 一节定义过：A100 的 FP16 算力约 312 TFLOPs、HBM 带宽约 2 TB/s，二者之比约 150 FLOP/byte，是「脊点」。Decode 的算术强度只有约 1 FLOP/byte——远在脊点左侧，是典型的<strong>访存受限（memory-bound）</strong>。</span>

| | Prefill 预填充 | Decode 解码 |
| --- | --- | --- |
| 处理对象 | 整段 prompt（并行） | 每步 1 个新 token |
| 计算特征 | 并行度高、算术强度大 | 权重全读、产出极小 |
| 瓶颈 | 计算受限（compute-bound） | 访存受限（memory-bound） |
| 时间尺度 | 一次搞定，决定 TTFT | 每步一次前向，决定 TPOT |
| 典型优化 | FlashAttention、Chunked Prefill | KV Cache、批处理、投机解码 |

表格里的 TTFT（Time To First Token，首 token 延迟）与 TPOT（Time Per Output Token，每输出 token 时间）要到本专题第十篇才正式定义，但你现在已经能直觉地理解它们：**Prefill 的快慢决定了你等多久看到第一个字，Decode 的快慢决定了后续每个字之间的间隔**。一次前向只产出一个 token，这个「头重脚轻」的结构，是整个部署优化最核心的杠杆。

## 6 公式解析：自回归链式分解的逐步展开

回到那条地基公式，用一个具体的四词序列把它彻底摊开：

$$P(\text{太阳},\ \text{从},\ \text{东方},\ \text{升起}) = P(\text{太阳}) \cdot P(\text{从} \mid \text{太阳}) \cdot P(\text{东方} \mid \text{太阳},\ \text{从}) \cdot P(\text{升起} \mid \text{太阳},\ \text{从},\ \text{东方})$$

**第一步，认识等号左边的联合概率**：$P(x_1, x_2, x_3, x_4)$ 表示「这四个词按这个顺序连续出现」这个事件发生的概率。语言模型要评估一句话有多自然，评估的就是这种联合概率。

**第二步，用链式法则做第一次拆分**：把序列劈成「第一个词」和「后面所有词」：

$$P(x_1, x_2, x_3, x_4) = P(x_1) \cdot P(x_2, x_3, x_4 \mid x_1)$$

这一步来自条件概率的定义 $P(A \cap B) = P(A)\, P(B \mid A)$，是恒等式，不是近似。

**第三步，递归地继续拆**：对 $P(x_2, x_3, x_4 \mid x_1)$ 再拆成 $P(x_2 \mid x_1) \cdot P(x_3, x_4 \mid x_1, x_2)$，如此反复，直到每个条件事件里都只剩一个词。数学归纳式地做 $n-1$ 次，就得到通用形式：

$$P(x_1, \dots, x_n) = \prod_{t=1}^{n} P(x_t \mid x_{<t})$$

**第四步，读出「生成」的含义**：这条恒等式对任何序列都成立，但只有把它**反过来读**才有工程意义——我们不评估已写好的句子，而是**从左到右逐词构造**它：先按 $P(x_1)$ 生成第一个词，再在给定第一个词的条件下按 $P(x_2 \mid x_1)$ 生成第二个……每一步只需回答「给定前缀，下一个词是谁」。这正是「自回归」三个字的全部含义，也解释了为什么这类模型的推理延迟必然随序列长度线性增长——每多一个词就多一次完整前向，而这个「线性」正是后续所有优化要去对抗的东西。

## 7 小结

- **自回归生成**：按链式法则把序列的联合概率分解为逐词条件概率的乘积，从左到右一次预测一个 token。
- **生成循环**：输入 → 预测分布 → 解码选择 → 拼接回环，直至生成 EOS 或达到长度上限。
- **KV Cache 引子**：历史 token 的 K、V 每步不变，缓存它们可把逐 token 注意力从 $O(t^2)$ 降到 $O(t)$；代价是每 token 约 0.5 MB（LLaMA-2 7B，FP16）的显存增长。
- **解码策略**：贪心、束搜索、采样三条路线，本质是「确定性 vs 多样性」的取舍，成本相对前向计算几乎可忽略。
- **两阶段**：Prefill 并行处理 prompt、计算受限；Decode 逐 token 前向、访存受限——这是 TTFT 与 TPOT 差异的根源。
