## 为什么从 EAGLE 开始

Medusa 解决了「不要第二个模型」的问题，但它的草稿仍有一个根本弱点：**解码头直接预测 token，且远偏移头无法利用中间的真实 token**。EAGLE（Extrapolation Algorithm for Greater Language-model Efficiency）换了一个层次：不在 token 层做草稿，而在**特征层（隐藏状态）**做外推。它用模型最后一层的隐藏状态 + 一个轻量自回归解码器，在特征空间里「草拟」下一步，再映射回 token。<span class="marginnote">EAGLE 的核心观察：<strong>token 层的外推很粗糙，但隐藏状态层的外推要平滑得多</strong>——因为隐藏状态是「连续向量」，天然适合线性/低维外推，而 token 是「离散符号」，只能靠猜分布。</span>

本篇讲 EAGLE 的原理：在特征空间草拟、把草拟结果映射回 token 空间、以及它为什么在「接受率」这个关键指标上刷新纪录。

## 1 从 token 草稿到特征草稿

标准自回归模型在位置 $t$ 的输出是隐藏状态 $h_t$，经过解码头得到 token 分布。EAGLE 的草稿器做的是：**预测下一个隐藏状态 $\tilde{h}_{t+1}$，再从这个预测的隐藏状态解码出 token**。

草稿器的输入是两个东西的拼接：当前隐藏状态 $h_t$ 与当前 token 的 embedding（或其解码形式）。它用一个小型自回归解码器（通常只有 1–2 层）生成 $\tilde{h}_{t+1}$：

$$\tilde{h}_{t+1} = \text{Draft}_{\theta}(h_t, \text{emb}(x_t))$$

然后 $\tilde{h}_{t+1}$ 经原始模型的解码头（LM head）映射到 token 分布，取 top-k 作候选。<span class="marginnote">关键区别：<strong>EAGLE 复用了原模型的 LM head</strong>（把特征映射到 token 的那个矩阵），草稿器只负责「猜特征」，不负责「猜 token」。这让草稿分布与原模型分布天然在同一坐标系里，接受率因此更高。</span>

为什么在特征层更好？因为**隐藏状态的演化比 token 序列平滑**：连续向量在相邻位置高度相关，用前一步特征 + 当前 token 就能较准地外推下一步。token 是离散的、信息量被「压缩」过一次，直接从 token 层猜会更不确定。

## 2 草稿器的训练与结构

EAGLE 的草稿器是一个**极小的自回归模型**，但训练方式很特殊：

- **训练目标**：最小化「预测的隐藏状态」与「真实隐藏状态」之间的 L2 距离，而不是 token 的交叉熵：

$$\mathcal{L} = \sum_t \| h_{t+1} - \text{Draft}_{\theta}(h_t, \text{emb}(x_t)) \|_2^2$$

- **结构**：草稿器很浅（典型 1 层 transformer），参数量是主模型的 1–2%，训练成本低。
- **数据**：直接用主模型的真实前向输出（隐藏状态）做标签，无需额外标注。

训练好之后，草稿器在推理时每步：输入 $h_t$ 与 $x_t$ → 输出 $\tilde{h}_{t+1}$ → 过 LM head → 得到 top-k token 候选。**草稿器的开销远小于完整模型的一层**，因此 $t$（草稿成本）极小。<span class="marginnote">与 Medusa 对比：Medusa 的头<strong>无自回归条件</strong>（多个头各自独立预测不同偏移），EAGLE 的草稿器<strong>带自回归条件</strong>（用前一步特征逐步外推）——更接近真实生成过程，所以接受率更高，代价是草稿步骤是串行的、成本略高。</span>

## 3 为什么 EAGLE 的接受率更高

接受率（$\alpha$）取决于「草稿分布 vs 目标分布」的重合度。EAGLE 在三方面拉开差距：

- **条件质量**：草稿器用了「当前真实隐藏状态 $h_t$」做条件。$h_t$ 携带的信息远多于「仅 token 序列」——**草稿从一开始就在「知道得更多」的条件下工作**。
- **分布对齐**：复用原模型的 LM head，草稿的 token 分布与原模型处于同一预测头下，比独立的草稿头更贴合。
- **特征平滑性**：隐藏状态的外推误差在小向量空间里比 token 分布的外推误差小——**误差在特征层被「压缩」，进入 token 层前已经被校正**。

论文实测（LLaMA-2 70B 等）：EAGLE 的接受率可到 0.8–0.9，配合 $\gamma=4$ 时加速比约 3 倍，显著高于 Medusa 与自回归小模型草稿。

**辨析｜易错点：EAGLE 不是「通用加速器」，它是「单模型专用加速器」。** 草稿器是针对特定主模型训练的，主模型微调/更换后草稿器必须重训。它的优势（高接受率）绑定在「与主模型高度耦合」上——**灵活性差，但性能极致**。

## 4 公式解析：特征外推 vs token 外推

对比两种草稿方式的误差。设真实下一步隐藏状态为 $h_{t+1}$，token 层草稿（Medusa 式）的误差来自「离散采样」，特征层草稿（EAGLE 式）的误差来自「连续回归」。

- **第一步，写 token 层误差**：token 草稿 $x_{t+1} \sim q(\cdot)$，其中 $q$ 是草稿分布。它映射回特征空间的误差是 $E_{q} = \| h_{t+1} - \phi(\hat{x}_{t+1}) \|$，其中 $\phi$ 是 embedding。离散采样的误差**方差大**——选错一个 token，特征就完全错了。
- **第二步，写特征层误差**：EAGLE 直接回归 $h_{t+1}$，误差是回归残差 $E_{\text{EAGLE}} = \| h_{t+1} - \tilde{h}_{t+1} \|$。连续回归的残差**方差小**，且可以通过「靠近真实值」来保证 token 层的 top-k 命中。
- **第三步，看接受率差异**：接受率 $\alpha$ 正比于「草稿候选能覆盖真实 token」的概率。特征层残差小 → 草稿 token 更准 → top-k 覆盖真实值的概率大：

$$\alpha_{\text{EAGLE}} \approx \Pr\left(x_{t+1} \in \text{top-}k(\text{softmax}(W\, \tilde{h}_{t+1}))\right)$$

当 $\tilde{h}_{t+1}$ 接近 $h_{t+1}$ 时，top-k 几乎必然覆盖真实 token——**接受率逼近 1，加速逼近 $\gamma$ 倍**。这就是「特征级外推」比「token 级猜测」高明的数学表达。

## 5 数值算例：EAGLE 的加速账

把「特征层外推」的收益算成具体数字。设 70B 主模型单 token 推理 $T=100$ 单位、$\gamma=4$、EAGLE 草稿成本 $t=2$ 单位（远小于主模型一层）：

| 方案 | 接受率 $\alpha$ | 加速比（估） |
| --- | --- | --- |
| 外部小模型草稿 | 0.6 | ≈1.6 倍 |
| Medusa | 0.7 | ≈2.0 倍 |
| EAGLE | 0.85 | ≈3.0 倍 |

**读这张表**：EAGLE 的加速比接近 $\gamma$（4 倍）的理论上限——**因为它把接受率推到了 0.85**。对比外部草稿的 1.6 倍，EAGLE 几乎翻倍。加速比公式里，$\alpha$ 是分母的指数项，$\alpha$ 从 0.6 到 0.85 的收益远大于「草稿省多少 $t$」——**接受率是投机解码的第一杠杆**，EAGLE 正是靠「特征层外推」把它拉满。<span class="marginnote">这张表的教训：<strong>投机解码的竞争，本质是「谁能让草稿更贴近主模型分布」</strong>——EAGLE 用「特征层 + 真实隐藏状态 + 共享 LM head」三重贴近，把接受率做到接近 1。</span>

**一个实际工程的提醒**：EAGLE 的 $t=2$ 假设「草稿器串行步骤开销很小」——实际上草稿器要逐步串行外推 $\gamma$ 步，$t$ 会随草稿器深度增长。**收益要实测，不能只看论文数字**（加速比对 $t$ 与 $\alpha$ 都敏感）。

## 6 EAGLE 的工程落地与取舍

把 EAGLE 放进部署决策：

**适用场景**：主模型固定、长期服务、追求极限吞吐——**EAGLE 的「高接受率」值得为它付训练与耦合成本**。主模型频繁换代则不适合（草稿器要重训）。

**实现要点**：草稿器要与主模型同部署（共享权重加载）；推理时「草稿串行外推 + 主模型并行验证」的编排要调优；KV Cache 与主模型共享。

**与 Medusa 的取舍**：EAGLE 接受率高但草稿器更重（带自回归）、实现更复杂；Medusa 头更轻、更简单、接受率略低。**选型看「要极限还是要简单」**——多数场景 Medusa 的「够用 + 简单」已足够，追求极致的团队上 EAGLE。

**辨析｜易错点：EAGLE 的接受率优势在「长序列/多 token 验证」时更明显。** 短生成（几 token）下，草稿的串行开销占比大，EAGLE 相对 Medusa 的优势被压缩。**评估 EAGLE 要用「代表性负载」实测**，而不是只看接受率的单点数字。

**EAGLE 收尾一句**：它把草稿从「猜 token」升级为「猜特征」——**在更平滑、信息更丰富的空间里外推，接受率逼近理论极限**，是投机解码的「天花板」级方案。

投机解码方案的选型速查：

| 你的情况 | 推荐方案 |
| --- | --- |
| 想快速上线、免训练 | 外部小模型草稿 |
| 不想加模型、省显存 | 自推测浅层 / Medusa |
| 追求极限接受率 | EAGLE |
| 主模型频繁换代 | 外部草稿或自推测（免重训） |

**读这张表**：选型是「训练成本 vs 接受率」的权衡——**能训头、想极致 → EAGLE；免训练、求简单 → 外部草稿**。没有「全都要」的方案，选型就是「你愿意为接受率付多少」。

**一个 EAGLE 落地的提醒**：它需要「草稿器 + 主模型」双权重加载、串行外推的编排——**部署复杂度明显高于外部草稿**。上线前把「草稿器重训流程」与「主模型更新联动」写清楚，否则模型一换、加速比悄悄归零。

## 7 小结

- **EAGLE 在特征层做草稿**：轻量解码器预测下一个隐藏状态，复用原模型 LM head 映射回 token。
- **训练目标是最小化隐藏状态 L2 距离**：草稿器参数仅为主模型 1–2%，训练便宜。
- **接受率高的三个来源**：真实隐藏状态做条件、共享 LM head 分布对齐、特征层误差更平滑。
- **加速比约 3 倍**：接受率 0.8–0.9，高于 Medusa 与外部草稿路线。
- **局限**：单模型专用、耦合紧，主模型更新后草稿器需重训。
- **接受率是第一杠杆**：EAGLE 三重贴近把 $\alpha$ 做到接近 1；追求极限选 EAGLE、图简单选 Medusa。
