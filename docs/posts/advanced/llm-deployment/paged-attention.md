## 为什么 KV 的显存管理是个真问题

第二章对比引擎时我们算过一笔账：A100 80 GB 上服务 7B 模型，页式管理能把并发上界放大四倍。这四倍从哪来？全部来自一个词——**碎片**。

KV Cache 的问题在于它**逐 token 增长、且每条序列独立**：请求进来时你根本不知道它最后会吐多少 token。如果为每条序列预先留足最大长度的 KV，显存立刻爆掉；如果按需分配但要求连续，分配多了退不掉、分配少了又要搬家。**KV Cache 需要的，正是一个「动态增长、可回收、不碎片化」的内存管理方案——这正是操作系统里的虚拟内存解决过的问题。**<span class="marginnote">vLLM 的论文《Efficient Memory Management for Large Language Model Serving with PagedAttention》（SOSP 2023）开篇就指出：现有系统的 KV 显存平均浪费 60%–80%。PagedAttention 用一个「间接层」把浪费压到 4% 以下。</span>

## 1 连续分配的三种浪费

先把「朴素方案」的浪费看全。假设 KV 用**连续分配**，即一条序列的 KV 必须占据一块连续显存，那么有三层浪费：

**浪费一：预留浪费（内部碎片）。** 不知道序列会多长，只能按**最大可能长度**预留。平均上下文 1024、上限 4096 时，3/4 的预留是空着的——第二章引擎对比里的 `$\bar{K}_{\text{seq}}$` 取最坏情况，说的就是它。

**浪费二：无法回收（外部碎片）。** 序列结束后 KV 理应释放，但连续分配下释放出的小块显存往往**拼不成一块足够大的连续区**，新请求用不了。显存总量没少，可用碎片越来越多。<span class="marginnote">这与进程内存里的「外部碎片」一模一样：内存还有很多，但没有一块连续空间装得下新任务。操作系统用分页解决它，vLLM 同样用分页。</span>

**浪费三：扩容迁移。** 序列超过预留长度时，要么直接失败，要么把整块 KV 搬到更大的连续区——复制成本随序列长度线性增长，且迁移期间该序列无法计算。

三种浪费加在一起，就是论文里那个触目惊心的数字：**平均 60%–80% 的 KV 显存被浪费**。

## 2 操作系统早就解决过：虚拟内存

这套问题在通用计算里已经有标准答案：**虚拟内存 + 分页**。操作系统把进程的地址空间切成固定大小的**页**，不再要求物理上连续；CPU 通过**页表**把「虚拟页号」翻译成「物理帧号」，物理帧散落在内存各处也不妨碍进程看起来「连续」。

PagedAttention 把同一套思想移植到 GPU 上：

| 虚拟内存 | PagedAttention |
| --- | --- |
| 虚拟页 | **逻辑块**（KV 序列按固定大小切块） |
| 物理帧 | **物理块**（显存中固定大小的 KV 存储单元） |
| 页表 | **块表（Block Table）**，逻辑块号 → 物理块号 |
| 缺页 | 调度器为序列分配新块（无显存硬件 MMU，由软件完成） |

关键区别在于：GPU 没有 CPU 那种硬件 MMU，页表翻译必须由**引擎软件 + 注意力内核**自己完成。这正是 PagedAttention 这个名字的由来——**「页式」的分配 + 「注意力」内核要会按块表取数**。

## 3 块表：逻辑块与物理块的映射

vLLM 默认把 KV 切成 **16 token 一块**的逻辑块。每条序列维护一张**块表**：一个「逻辑块号 → 物理块号」的数组。序列的逻辑 KV 永远是连续编号的（逻辑块 0、1、2、3…），但对应的物理块可以散落在显存任何空闲位置——包括别人释放出来的、碎片化的位置。

![PagedAttention 的块表映射](/images/llm-deployment/paged-attention-1.svg)

图中这条序列的逻辑块 0–3 分别落在物理块 2、5、3、6——物理上既不连续、还夹着空闲块，但块表让它在逻辑上完全连续。**新增一个 token 需要扩容时，只需从空闲表里取一个物理块、在块表末尾追加一个指针**；序列结束回收时，把物理块还回空闲表即可。分配的粒度从「整条序列的连续区」变成「一块一块的页」，碎片问题被化解为「最多浪费不到一块」的粒度。

## 4 公式解析：分页注意力的内存利用率

先看内存效率。设页大小为 $B$ token，一条序列实际 KV 为 $k$ 个 token，则它占用：

$$\eta_{\text{seq}} = \frac{k}{B \cdot \left\lceil k / B \right\rceil}$$

逐步拆解：

- **第一步，认分子**：分子 $k$ 是这条序列真正用到的 KV token 数——这是「刚需」。
- **第二步，认分母**：分母是它实际占用的物理 KV 空间。`$\lceil k / B \rceil$` 是所需逻辑块数，乘上每块大小 $B$，就是占用的总槽位。
- **第三步，找浪费上界**：多分配的部分不超过一块，即最多 $B - 1$ 个 token 的 KV 被浪费（内部碎片的上界）。设 $B = 16$，最坏浪费是 15 个 token 的 KV，**与序列长度无关**——而连续分配下浪费随长度线性放大。
- **第四步，看注意力怎么算**：内核通过块表逐块取数，第 $j$ 个 KV 元素不再是「连续数组的第 $j$ 个」，而是「第 $\lfloor j/B \rfloor$ 个逻辑块、块内偏移 $j \bmod B$」对应的物理位置。注意力本身仍是标准形式：

$$o_i = \sum_{j=1}^{k} \frac{\exp(q_i k_j^\top / \sqrt{d_k})}{\sum_{t=1}^{k} \exp(q_i k_t^\top / \sqrt{d_k})} v_j$$

跨块求和时，softmax 的全局归一化必须用**在线 softmax**（逐步合并局部最大值与和）来完成——这与 FlashAttention 的处理方式同源，第七篇会展开。**换页式分配不用换注意力公式，只需换「取数路径」。**

## 5 PagedAttention 如何改写注意力内核

「换取数路径」在工程上意味着内核的数据布局变了。标准注意力把 KV 存成连续张量，形状近似 `[batch, num_heads, seq_len, head_dim]`；PagedAttention 把 KV 存成**按块组织**的张量，形状近似 `[num_blocks, num_heads, block_size, head_dim]`，再配一张块表。

于是注意力内核的循环变成：对每个 query，**沿着块表遍历它所属的所有逻辑块**，逐块取出 K、V，计算局部点积与累加；跨块用在线 softmax 维护正确的归一化。物理块是否连续不再重要——内核只认「块号 + 块内偏移」。<span class="marginnote">这层设计给内核留了巨大的优化空间：多个逻辑块可以并行取数、相邻物理块可以合并访存、块与块之间没有依赖（在线 softmax 的增量合并除外）。FlashAttention 与 PagedAttention 因此在工程上可以无缝叠加，vLLM 的注意力后端就是同时套这两层的。</span>

## 6 连锁收益与代价

页式管理带来的不止是「不碎片化」，它把 KV 从「一块连续的私有领地」变成了「一堆可寻址、可共享的块」，于是长出三棵新枝：

- **块共享（Prefix Sharing）**：多条请求如果有相同前缀，前缀对应的物理块可以被**共享**，只留一份（第三篇的 Prefix Caching、SGLang 的 RadixAttention 都建立在这个能力上）。
- **写时复制（Copy-on-Write）**：共享块需要改写时（如不同分支继续生成），复制该块再写，其余共享者不受影响——又便宜又安全。<span class="marginnote">写时复制是操作系统虚拟内存的经典招式（fork 的实现），vLLM 把它原封不动搬来管理 KV。这大概是「增加一层间接层」最优雅的一次实践。</span>
- **调度灵活性**：块可以按需增减，调度器就能精细控制「这条序列该占多少显存」，抢占与换出（第三篇）由此成为可能。

**代价**是：块表查找、在线 softmax 重归一化、块边界上的取数多了一层间接——每项都有少量开销。vLLM 的实测表明，PagedAttention 的吞吐相对最优连续分配仍提升 2–4 倍，这层间接的收益远大于成本。

**辨析｜易错点：**

- **误区一：以为 PagedAttention 是「把 KV 存成稀疏结构」。** 不是。KV 本身仍是稠密的，只是**存储的地址空间**被打散了。变的是地址，不是数据。
- **误区二：以为页越大越好。** 块表越短、取数越整；但块越大，内部碎片上界越大（$B-1$ 个 token 的浪费）。16 这个默认值是「表长与碎片」的折中，生产里可按平均上下文微调。
- **误区三：以为 PagedAttention 只有 vLLM 用。** 页式/块式 KV 已成为事实标准：SGLang、TensorRT-LLM、vLLM V1 都有等价物，差别在块的粒度、共享的方式与调度的耦合（第二章对比篇）。

## 7 小结

- **问题本质**：KV 动态增长 + 每条序列独立 → 连续分配必然产生预留浪费、外部碎片与扩容迁移，平均浪费 60%–80%。
- **答案来自操作系统**：虚拟内存的分页思想——逻辑块 + 块表 + 物理块，用一层间接换回连续性与可回收性。
- **块表是核心数据结构**：逻辑块号 → 物理块号的映射，让序列逻辑连续、物理分散；分配与回收都是 O(1) 级操作。
- **注意力内核要会按块取数**：数据布局变成按块组织，跨块 softmax 用在线归一化，公式本身不变。
- **连锁收益**：块共享、写时复制、调度精细化随之而来；代价是少量间接开销，收益是 2–4 倍的吞吐提升。
- **默认页大小 16 token**：表长与碎片之间的折中。

在下一节，我们把「块表」放大来看：它怎么被组织、怎么管理空闲块、怎么支持共享与写时复制——**块表（Block Table）与逻辑物理块映射**。
