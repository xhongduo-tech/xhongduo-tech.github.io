## 为什么从单 token 成本开始

部署到最后都要回答同一个问题：**这个模型服务到底花多少钱？** 数据中心有折旧、电费、人力；云端 API 有单价。要比较两者、给产品定价、评估「自建 vs 调用」，需要一个统一的度量单位——**单 token 成本（cost per token）**。它是推理的「单位成本」，像制造业的「单位成本」一样，把一切开支折算到产品上。<span class="marginnote">本专题最后一篇把「部署的经济账」算清楚：<strong>单 token 成本 = 总成本 ÷ 总 token 数</strong>，分子分母拆开，就能看出成本结构、找到优化杠杆。</span>

本篇讲单 token 成本的分层模型（硬件成本、电费、吞吐）、估算步骤、以及如何用它做「自建 vs API」的决策。

## 1 成本的两大块：固定与可变

推理服务的总成本分两块：

- **固定成本（资本开支 + 固定运营）**：GPU 采购（或云租用）、机房、人力。**与 token 量无关**，摊薄到每个 token。
- **可变成本（运营开销）**：电费、带宽、冷却。**随 token 量增长**，约等于「每 token 能耗 × 电价」。

单 token 成本 = 固定成本摊薄 + 可变成本：

$$\text{cost/token} = \frac{C_{\text{fixed}}}{N_{\text{tokens}}} + c_{\text{var}}$$

其中 $N_{\text{tokens}}$ 是生命周期内生成的总 token 数。<span class="marginnote">关键洞察：<strong>固定成本摊薄随 token 量下降</strong>——GPU 利用率越高、跑得越久，每个 token 的固定成本越低。这就是「<strong>吞吐 = 成本</strong>」的经济学：优化吞吐不只是性能问题，是直接省成本。</span>

## 2 硬件成本的摊薄

一块 GPU 的成本怎么摊到 token 上？三步：

**第一步，定折旧**：GPU 使用寿命（通常 3–5 年），月折旧 = 采购价 / 月数。4090（$1.6k）按 3 年 ≈ $44/月；H100（$30k）≈ $833/月。

**第二步，定月 token 产能**：月 token 产能 = 吞吐 × 秒数 × 利用率。设 H100 在线服务吞吐 50k token/s、利用率 50%：月产能 ≈ 50k × 86400 × 30 × 0.5 ≈ **648 亿 token/月**。

**第三步，除**：硬件摊薄成本 ≈ $833 / 648 亿 ≈ **$0.13 每百万 token**（约合人民币 ¥0.9）。<span class="marginnote">这是「<strong>硬件成本其实很便宜</strong>」的真相：H100 的硬件摊薄只有每百万 token 一两毛钱。真正的大头在后面——电费、以及「利用率低时摊薄暴涨」。</span>

## 3 电费与利用率：可变成本的主导

电费的计算：功耗 × 时长 × 电价。H100 推理典型功耗 ~700W，数据中心电价约 $0.1/kWh：

每秒耗电 ≈ 0.7 kWh 的 1/3600 ≈ 0.0002 kWh，每秒成本 ≈ $0.00002；
每秒产 50k token → 电费 ≈ **$0.4 每百万 token**——**是硬件摊薄的 3 倍**。<span class="marginnote">这个数字解释了行业的两个现象：<strong>① 为什么「利用率」被反复强调</strong>——利用率 20% 时，硬件摊薄涨 5 倍；② 为什么「<strong>推理成本主要由电费 + 利用率决定</strong>」——优化吞吐（更快出 token）直接摊薄电费。</span>

**利用率的杠杆**：利用率从 20% 提到 80%，硬件摊薄降 4 倍、电费摊薄降 4 倍——**单 token 成本随利用率近似反比下降**。Continuous Batching、PD 分离、投机解码这些「提吞吐」的技术，最后都落到「降单 token 成本」上。

## 4 公式解析：完整的成本模型

把全部成本塞进一个式子。设 GPU 数量 $G$、每卡采购价 $P$、折旧月数 $D$、每卡功耗 $W$（kW）、电价 $e$（$/kWh）、单卡吞吐 $R$（token/s）、利用率 $u$、月运行秒数 $T$（≈2.6M 秒）：

- **第一步，写月总成本**：

$$C_{\text{month}} = \frac{G \cdot P}{D} + G \cdot W \cdot e \cdot T \cdot u$$

（折旧项 + 电费项，电费随利用率线性增长。）
- **第二步，写月总 token**：$N_{\text{month}} = G \cdot R \cdot T \cdot u$（吞吐 × 利用率）。
- **第三步，除得单 token 成本**：

$$\frac{C_{\text{month}}}{N_{\text{month}}} = \frac{P}{D \cdot R \cdot T} + \frac{W \cdot e}{R}$$

**注意两个惊人的化简**：折旧项里的 $u$ 被约掉了？不——$C$ 的折旧项不含 $u$，但 $N$ 含 $u$，所以折旧摊薄 = $P/(D \cdot R \cdot T \cdot u)$，**仍随利用率下降**；电费项 $W \cdot e / R$ 中 $u$ 也被约掉（电费与产出同比例增长）——**电费的「单位成本」与利用率无关，只取决于吞吐 $R$**。这个式子的结论：**提高吞吐 $R$ 同时降低折旧与电费的单位成本——它是单 token 成本的第一杠杆**。

## 5 小结

- **单 token 成本 = 固定摊薄 + 可变成本**：固定（折旧、人力）随 token 量下降，可变（电费）与利用率同比例。
- **硬件摊薄很便宜**：H100 约 $0.13/百万 token，电费（$0.4/百万）才是主导。
- **利用率是第一杠杆**：利用率 20%→80%，摊薄降 4 倍；Continuous Batching 等技术本质是降本。
- **成本公式的化简**：折旧摊薄随利用率降、电费单位成本只取决于吞吐 $R$——提高 $R$ 是成本第一杠杆。
- **成本模型是决策工具**：用它做自建 vs API 的对比（见下一篇）、产品定价、扩容依据。
