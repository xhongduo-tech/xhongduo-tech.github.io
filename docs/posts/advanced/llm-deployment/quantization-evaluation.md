## 为什么从精度评测开始

量化省了显存、提了吞吐，但「省下来的东西」值不值，取决于一件事：**量化后的模型还是不是原来的模型**。GPTQ、AWQ、FP8、INT4，每种方案都声称「几乎无损」——但「几乎」在不同数据分布上的含义天差地别。评测方法选错了，可能把「已经崩了」的模型放上线。<span class="marginnote">本专题量化篇的收尾篇。前面的文章都在讲<strong>怎么量化</strong>，这篇讲<strong>怎么知道量化得好不好</strong>——它是量化能否上线的「质检关」。</span>

本篇讲量化精度评测的分层体系：感知指标（困惑度）、任务指标（benchmark）、文本级对比（关键 token），以及「校准集失配」这个最常见的翻车原因。

## 1 三层评测体系

量化精度评测不是「跑一个数」，而是从粗到细的三层：

**第一层：感知/分布指标**——**困惑度（perplexity, PPL）**。让模型计算一段文本的负对数似然。PPL 越低，模型对文本分布的建模越准。PPL 是量化评测的第一道筛子：PPL 涨得多，量化必然有伤；PPL 基本不变，量化「有希望」无损。<span class="marginnote">PPL 的敏感度恰好：<strong>INT8/FP8 通常 PPL 涨 <0.1，INT4 涨 0.1–1，INT3 及以下暴涨</strong>。它是量化方案间的「体检表」。</span>
**第二层：任务指标**——在标准 benchmark 上跑任务（MMLU 多任务、GSM8K 数学、HumanEval 代码、BBH 推理等），对比量化前后准确率。PPL 好的模型任务不一定好——**PPL 是「分布拟合」，任务分是「能力保留」**，两层都要看。
**第三层：文本级对比**——用同一 prompt 分别让 FP16 与量化模型生成，逐 token 对比输出。这一层最贴近真实用户感受：**「关键 token（数字、JSON 字段、工具调用名）错没错」**往往比 PPL 更能暴露部署风险。

**三层各有分工**：第一层快而粗、第二层准而慢、第三层贴而杂。工程实践通常是「PPL 筛 → 关键任务跑分 → 抽样文本对比」的漏斗。

## 2 校准集失配：最常见的翻车原因

量化误差不只是量化算法本身的事——**校准集（calibration set）与真实负载的分布差异**，会让一切评测失真。<span class="marginnote">回到《量化基本原理》的结论：scale 由校准集统计决定。校准集若是英语文本、线上全是代码，算出的 scale 在代码分布上可能差出几个量级。</span>

三种典型失配：

- **领域失配**：校准用 Wikipedia，线上是代码/法律文书/医疗文本。
- **格式失配**：校准用普通对话，线上是 JSON/工具调用——而 JSON 的标点、数字 token 恰恰对量化误差敏感。
- **长度失配**：校准用短文本，线上是长上下文——长上下文的 KV Cache 误差与注意力稀疏性与短文本不同。

**评测的「线上近似度」决定了评测的可靠性。** 专业做法是：**用线上真实请求的采样做校准集，再用另一段线上采样做评测集**——校准与评测都贴近真实分布，才不会被「虚假的无损」骗过。

## 3 量化误差的方向性：不是所有误差都平等

量化评测容易犯一个错误：只关心「平均误差」。但部署中，**误差是有方向、有位置的**：

- **离群通道的误差**比平均误差更危险（见 AWQ 篇：少数通道主导输出）；
- **首 token（prefill）的误差**会影响后续全部生成，比中间 token 更致命；
- **结构化输出的错误**（多一个括号、错一个字段名）会让下游解析直接崩溃，即使文本「看着像」正确。

因此评测要加**关键点检查**：

| 关注点 | 评测方式 | 风险 |
| --- | --- | --- |
| 平均质量 | PPL、任务准确率 | 掩盖局部崩坏 |
| 离群通道 | 逐通道误差分析 | 少数通道被 clip |
| 结构完整性 | JSON 解析成功率、字段匹配 | 语法破坏导致下游崩溃 |
| 长尾 token | 关键 token（数字、专名）错误率 | 高价值信息出错 |
| 自回归累积 | 长生成对比 | 早期误差被放大 |

**辨析｜易错点：不要只看「平均 PPL 涨了 0.1」就放行。** PPL 是全局平均，可能掩盖「某些 prompt 类别的输出崩坏」。**分组评测**（按 prompt 类型、长度、领域分组算 PPL 与任务分）才能暴露「哪个切片在退化」。

## 4 公式解析：PPL 的数学与它的局限

困惑度的定义：

$$\text{PPL}(D) = \exp\left( -\frac{1}{N} \sum_{i=1}^{N} \log P_\theta(x_i \mid x_{\\lt i}) \right)$$

其中 $D$ 是评测文本，$N$ 是 token 数，$P_\theta(x_i \mid x_{\\lt i})$ 是模型给第 $i$ 个 token 的概率。

- **第一步，读结构**：对每个 token 取对数概率、求和、平均、取指数。**PPL 是「平均负对数似然」的指数化**——模型越自信地预测正确 token，PPL 越低。
- **第二步，读量化影响**：量化让 $P_\theta$ 从「精准分布」退化为「模糊分布」，$\log P$ 变小（更负），PPL 上升。**PPL 上升量 ≈ 量化引入的分布偏移的平均值**。
- **第三步，读局限**：PPL 把每个 token 等权。但生成质量的真正风险在「关键 token 的错误」——而关键 token 往往占比极小，**PPL 的等权平均把它们稀释了**。所以 PPL 之后必须有任务级与文本级评测补位。

量化精度损失的合理接受线没有绝对标准，但经验范围是：**PPL 上涨 < 0.5、关键任务掉点 < 1%**，可视为「无损」；超出则需回到量化方案或校准集寻找原因。

## 5 小结

- **三层评测漏斗**：PPL（分布拟合）→ 任务 benchmark（能力保留）→ 文本级对比（用户感受）。
- **校准集决定评测可信度**：校准与评测都要贴近线上分布，领域/格式/长度失配是头号翻车原因。
- **误差有方向性**：离群通道、首 token、结构完整性比平均误差更关键，需要分组与关键点检查。
- **PPL 的局限**：等权平均稀释关键 token 错误，必须用任务分与文本对比补位。
- **验收线**：PPL 上涨 <0.5、关键任务掉点 <1% 视为可接受；超出要回查量化方案与校准集。
