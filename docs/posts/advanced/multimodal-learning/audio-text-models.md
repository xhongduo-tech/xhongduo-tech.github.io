## 为什么音频是「最难的多模态」

图像把世界拍成空间，视频把世界拍成时空，而**音频只有一个维度：时间**。没有像素、没有空间结构，只有「空气振动如何随时间变化」。这让音频多模态有两个独特之处：**一是信息全在时序里**（一句话的语义靠音高、节奏、停顿共同表达）；**二是原始波形与人耳感知差着十万八千里**（频率、掩蔽、噪声全混在一起）。<span class="marginnote">音频与图像的第一个不对称：图像模型可以直接吃像素，音频模型通常要先把波形变成<strong>语谱图</strong>（时频表示）或 mel 特征，再喂给网络。这个「声学前端」本身就是信号处理的学问，见第二级《语音技术》专题。</span>这一课讲清「把声音翻译成语言」的技术栈，以及它在多模态大模型里的位置。

与视觉相比，音频多模态在产业里被长期低估，却在 2023 年后突然升温——因为**大模型让「听懂声音」从「转写」升级成了「理解 + 对话」**。语音助手、会议纪要、无障碍、安防监听，都是音频-文本模型的用武之地。**如果说视觉多模态教模型「看世界」，音频多模态教模型「听世界」**——两条线最终要在统一多模态框架（下一课）里合流。

## 1 从波形到特征：音频的「图像化」

音频原始形态是一维波形：每秒 16000–48000 个采样点。直接喂给 Transformer 太原始、序列太长。标准做法是先**特征化**：

- **语谱图（spectrogram）**：短时傅里叶变换（STFT），把「时间 × 频率」画成二维图——**声音从此「看起来像图像」**，2D CNN 就能上。
- **Mel 谱（mel-spectrogram）**：把频率轴按人耳感知压成 mel 刻度，更贴近听觉。这是当今默认。
- **语音 token**（hubert/whisper 的离散编码）：用自监督模型把音频量化成离散 token——**声音从此「听起来像语言」**，语言模型那套直接能用。

三条路对应三种哲学：**「当图像看」（谱图 + CNN）、「当文本看」（离散 token + 语言模型）、「当序列看」（波形 + 专用编码器）**。现代音频-语言模型基本走第三条的升级版：专用音频编码器 + LLM。

一个常被忽略的参数是**采样率**：语音常用 16kHz（能覆盖人声频率范围），音乐需要 44.1kHz（保高频），而 8kHz 电话音质就足够转写。**采样率决定了「信息的频率上限」**——采样率不足，高频细节（齿音、乐器泛音）直接丢失。选采样率 = 选「要听多细」，与图像分辨率是同一个问题。

其中「**当文本看**」这条路在 2023 年后异军突起：先用自监督模型（如 hubert、wav2vec 2.0）把音频量化成**离散 token**，然后完全复用语言模型那套——**音频 token 与文本 token 共享同一个词表、同一个 Transformer**。SoundStream 式的音频编解码器（可逆的「音频 ↔ token」）更是让「文生音」「音生文」变成了对称的任务。**「把音频当另一种语言」是音频多模态最深刻的统一思想**——它让「语音」与「语言」的边界第一次变得模糊。

这个「统一」还带来一个副产品：**音频生成**。既然音频是 token，那么「文生音」「音生音」就都成了「token 序列生成」——音乐生成、声音克隆、文生音效全部落到同一条技术线上。**理解音频多模态，一半是理解「怎么听」，一半是理解「怎么把听到的变成 token」**——后者让生成与理解共享同一套语言模型。

## 2 音频理解的任务族

音频不是一个「任务」，而是一族任务，共享「听懂声音」这个底层能力：

| 任务 | 输入 | 输出 | 例子 |
| --- | --- | --- | --- |
| 语音识别（ASR） | 语音 | 文字 | 语音转写 |
| 语音翻译 | 语音 | 其他语言文字 | 同声传译 |
| 音频字幕 | 任意音频 | 文字描述 | 给音效配文 |
| 音频问答 | 音频 + 问题 | 答案 | 「这是什么声音？」 |
| 声学事件检测 | 音频 | 事件类别 | 枪声、警报、笑声 |

其中 **ASR 是音频-文本最成熟的形态**，也是 Whisper 的主场；**音频字幕与问答**则是「把音频当世界来理解」的新任务——后者正是音频多模态 LLM 的目标。**ASR 关心「说什么」，音频理解关心「发生了什么」**——前者只需语音，后者要理解环境声、音乐、语调。

「发生了什么」的典型场景：一段监控音频里有「先是一声闷响，接着玻璃破碎声，然后有人喊叫」。音频理解模型要能输出「发生了一次撞击事件，疑似入室」——这需要**多事件识别 + 时序推理 + 场景常识**的组合。**声学事件检测（AED）是其中的基础件**（识别「玻璃碎」「警报」「笑声」等），而把它接进 LLM 才是「理解事件」的完整形态。AudioSet（谷歌的 527 类声学事件数据集）是训练 AED 的标准基准。

音频的评测基准也在快速成型：**AudioCaps**（音频字幕）、**Clotho**（音频字幕/检索）、**AudioSet**（事件）、**LibriSpeech**（ASR）、**VoiceBench 类多任务基准**。与视觉一样，**音频评测也要「分能力」看**——语音识别强不等于环境声理解强，一个模型在 LibriSpeech 上近乎满分、在 AudioCaps 上可能不及格。**「全能耳朵」是伪命题，分能力评估才是常态**。

## 3 音频-文本模型的两条路线

**路线一：专用音频模型（Whisper 范式）。** Whisper 用「语谱图 + 编码器-解码器 Transformer」，直接做「音频 → 文本」的序列到序列。它的强项是 ASR/翻译，弱项是「不会聊天」——输出固定是转写或翻译，不能问答。**Whisper 是「把声音变成文字」的专用引擎**，量大管饱、稳定可靠。

Whisper 的设计值得细品：它用 **68 万小时的多语种弱监督音频**训练，覆盖 96 种语言、带时间戳与翻译任务。它的两个关键工程决策——**① 30 秒固定窗口**（按窗口切分、逐窗转写再拼接）；**② 多任务统一**（用特殊 token 区分转写/翻译/语言，一个模型干所有活）——让它在零样本上碾压了当时的专用 ASR。**「大规模弱监督 + 任务统一」在多模态的每一站都赢**，从 CLIP 到 Whisper 再到 GPT-4V，这条主线从未变过。

**路线二：音频接进 LLM（音频多模态 LLM）。** 把音频编码成 token 接进大语言模型，让它「边听边聊」。代表是 AudioLLM、Qwen-Audio 等。**音频 LLM 能做 ASR，更能做「听声问答」**——问「这是猫叫还是狗叫」，它边听边答。**这是「Whisper 会转写，音频 LLM 会理解」的分野**。<span class="marginnote">Whisper 与音频 LLM 的关系，恰如「OCR 模型」与「视觉 LLM」的关系：前者是专用「转写引擎」，后者是「看得懂的脑子」。工程上常<strong>两者串联</strong>——Whisper 转写 + LLM 处理文本（纯文本方案），或用音频 token 直接进 LLM（端到端方案）。</span>

级联与端到端的选择，是一个经典权衡：**级联**（Whisper → LLM）简单稳定、转写可审计，但丢掉「文本之外」的声学信息（语气、环境声、多说话人）；**端到端**（音频 token → LLM）信息全、能「听」出反讽与警报，但训练难、可解释性差。**2024 年后的主流是端到端**（GPT-4o、Gemini 等），因为模型越来越大后，「信息全」的价值超过了「可审计」的方便——**「听语气」正在成为刚需**。

音频 LLM 的训练数据也有一套「自产自销」配方：**用 Whisper 给海量音视频配文字**（自动转写），再让 LLM 把这些转写整理成问答对——本质上又是 BLIP 的「生成器-过滤器」循环，只是生成器换成了 ASR。**「数据循环」在多模态的每一个模态都会重演**：视觉用字幕模型、音频用 ASR 模型、视频用帧采样+字幕模型。**「自监督造数据」是多模态规模化最通用的发动机**。

## 4 公式解析：从波形到 mel 谱的变换

音频特征化的核心数学是**短时傅里叶变换 + mel 压缩**。波形 $x(t)$ 的语谱图是加窗 STFT 的幅值：

$$
S(\tau, f) = \left| \int_{-\infty}^{\infty} x(t)\, w(t - \tau)\, e^{-i 2\pi f t}\, dt \right|, \qquad M = \Phi_{\text{mel}}(S)
$$

三步拆解：

- **第（1）步，读懂加窗**：$w(t - \tau)$ 是一个「只在 $\tau$ 附近非零」的窗函数。**把波形切成一小段一小段，对每段做傅里叶变换**——得到「这个时刻有哪些频率」。$\tau$ 扫过时间轴，$f$ 扫过频率轴，$S$ 就是一张「时间 × 频率」的能量图（语谱图）。
- **第（2）步，mel 压缩**：$\Phi_{\text{mel}}$ 把线性频率轴映射到 **mel 刻度**——低频分得细、高频分得粗，模仿人耳。**mel 谱是「人耳看到的语谱图」**，能显著提升音频模型的样本效率。
- **第（3）步，为什么重要**：这一步把「无法直接学习的连续波形」变成「图像模型熟悉的二维特征」。**多模态音频模型的「感知前端」就是这条公式**——它决定了模型「听得多清、多省」。

工程里还有两个隐藏旋钮：**窗长（window size）** 与 **hop（窗间步长）**。窗长决定「频率分辨率」（窗越长，频率分得越细，但时间分得越粗）；hop 决定「时间分辨率」（hop 越小，时间采样越密，序列越长）。**「窗长-时间分辨率」此消彼长，是信号处理的测不准原理**——音频特征化的参数选择，本质是「频率要细还是要时间要细」的权衡。

## 5 音频多模态的挑战与易错点

**挑战一：时序长度与对齐。** 一分钟音频的特征也是长序列，且音频事件与文本的对应（「第 2 秒的枪声对应哪个词」）需要细粒度对齐——这与视频的时间对齐同病。

**挑战二：多说话人与噪声。** 真实场景多说话人重叠、背景噪声大，ASR 与理解都难。**说话人分离与噪声鲁棒**是音频工程的两大独立子问题。

评价也与视觉不同：**ASR 用 WER（词错误率）**——「模型转写与参考答案差多少词」，与 BLEU 类似但以「错误」为导向；**音频理解用字幕指标**（CIDEr 等）与问答准确率。一个易被忽略的坑：**ASR 的 WER 对「标点、大小写、数字格式」极敏感**——同一段转写，标准化方式不同，WER 可以差一倍。**「先标准化再算 WER」是 ASR 评测的必修课**，否则分数不可比。

**易错点一：把「转写」当「理解」。** ASR 转写对了不代表理解了——转写是「字到字」，理解是「声到意」。用 ASR 输出的文本喂 LLM（级联方案），会丢掉语气、停顿、环境声等「文本之外的信息」——**反讽、焦急、警报声，转写都表达不了**。

**易错点二：忽视采样率与时长上限。** 音频模型的输入有固定采样率（16k 是语音常用）与最大时长（Whisper 30 秒窗口）。**输入与训练分布不符（48k 采样率、3 分钟音频），性能会显著下降**。

**易错点三：把音频 LLM 当「全能耳朵」。** 音频 LLM 对「音乐结构」「精细声学参数」理解有限——它擅长「语义级」的听（这是什么、在说什么），不擅长「声学级」的分析（这个音的基频是多少）。**又是「粗读 vs 细读」的分工**：语义粗读交给 LLM，声学细读交给专用模型。<span class="marginnote">这与图像、视频的结论完全一致：<strong>多模态 LLM 是「语义理解」的通用前端，不是「信号分析」的精确仪器</strong>。凡是需要「精确数值」的感知任务（频谱测量、帧级检测），都要专用模型兜底。</span>

## 6 小结

- 音频是一维时序信号，特征化是第一步：**语谱图 / mel 谱 / 离散 token** 三种形态。
- 音频任务族：**ASR、翻译、字幕、问答、事件检测**；ASR 是「说什么」，理解是「发生了什么」。
- 音频 token 化让「音生文 / 文生音」对称——**「把音频当另一种语言」是最深刻的统一思想**。
- 两条路线：**Whisper 式专用转写**与**音频 LLM 式理解**；工程上常「转写 + 文本 LLM」级联或端到端。
- Whisper 的成功是「大规模弱监督 + 任务统一」的又一胜利——与 CLIP 同一套剧本。
- **STFT + mel** 是把波形变成「人耳看的二维图」的核心公式，是音频模型的感知前端。
- 采样率决定「听多细」，窗长/hop 决定「频率 vs 时间分辨率」——**音频特征化处处是权衡**。
- 真实场景的音频=多说话人+噪声，**说话人分离与噪声鲁棒**是独立的工程子问题。
- 与第二级《语音技术》的衔接：本课聚焦「音频作为多模态的一路」，声学与信号处理的细节在那里的专题。
- 三个易错点：**转写≠理解、采样率与时长错配、把音频 LLM 当全能耳朵**。
- 音频评估：ASR 用 **WER**（先标准化再算），音频理解用字幕指标与问答准确率。
- 音频是「最难的多模态」：一维时序、声学前端复杂、转写≠理解——但 token 化让它重回统一框架。
- 音频基准：AudioCaps（字幕）、AudioSet（事件）、LibriSpeech（ASR）——**分能力评估才是常态**。
- 级联 vs 端到端：**级联可审计、端到端信息全**；2024 年后主流转向端到端（「听语气」成为刚需）。
- 数据循环在多模态每站重演：**视觉用字幕模型、音频用 ASR 模型**——「自监督造数据」是通用的规模化发动机。
- 与后续课程连接：图像、视频、音频都有了——下一步是把它们**统一进一个框架**：**统一多模态框架（Any-to-Any）**。

**本课一句话**：音频多模态的全部技术选择，都围绕一个矛盾——**「波形里信息最全、却最不可直接学习」**。特征化是「把它变成可学的形状」，token 化是「把它变成可统一的形式」，理解是「在形状之上读出意义」。

在下一节，我们把前面所有的模态拼成一个整体：**统一多模态框架（Any-to-Any）**——一个模型输入任何模态、输出任何模态。
