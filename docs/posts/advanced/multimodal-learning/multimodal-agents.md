## 为什么 Agent 是多模态的「行动派」

前三篇教模型「看」，上一篇教模型「想」，而**真实世界的价值在「做」**。用户的需求不是「告诉我屏幕上有啥」，而是「帮我把这个表格填了」「帮我在网页上订个票」。**多模态 Agent（multimodal agent）**就是让模型「看 → 想 → 动」的闭环系统：它用视觉理解界面与场景，用推理制定计划，再通过动作（点击、输入、调工具）改变世界。<span class="marginnote">Agent 与单次问答的差别是<strong>「循环」</strong>：问答是一次「输入→输出」，Agent 是「输入→决策→动作→观察新状态→再决策……」的多轮循环。<strong>多模态 Agent 的关键在于「观察」也是多模态的</strong>——每一步都能重新截图、重新听、重新看。</span>这一课讲清多模态 Agent 的架构、技术栈与挑战。

## 1 Agent 循环：感知-规划-行动的闭环

一个多模态 Agent 的最小循环是三步：

1. **感知（perceive）**：接收当前状态的多模态观测——截图、屏幕、摄像头画面、声音。
2. **规划（plan）**：根据观测与目标，决定下一步动作——用多模态推理（上一课）拆解任务。
3. **行动（act）**：执行动作——点击、输入、调用 API、移动机器人。

然后循环：行动改变环境 → 新观测 → 新规划……直到目标完成。

这个循环看起来简单，但每一环都有「多模态特有」的坑：**感知环**——截图要压缩，细节会丢；**规划环**——视觉理解错的物体，计划就建在沙上；**行动环**——点击坐标要精确，偏几个像素就点错。**三环各自的可靠性相乘，才是 Agent 的总体成功率**——一个 90%×90%×90% 的 Agent，实际成功率只有 72.9%。这个「可靠性连乘」是 Agent 工程最残酷的算术。

**「循环」是多模态 Agent 与所有前序课程的本质区别**：前序模型是「一次到位」的（给图出答案），Agent 是「逐步逼近」的（看一步、动一步、再看）。这也意味着 **Agent 的错误会被放大**——第一步走错，后面全跟着错；反之，**Agent 有「重试」机会**——观察到失败，可以换策略。

**多模态 Agent 与「文本 Agent」的区别也值得点破**：文本 Agent（如 ReAct + 纯 LLM）只能「读文本、写文本」，它的「观察」是 API 返回的文本；多模态 Agent 的「观察」是**屏幕截图、摄像头画面、真实世界**——它不需要网站提供 API 就能「看懂界面、动手操作」。**「无需 API 就能操作任何界面」是多模态 Agent 对文本 Agent 的降维打击**——这也是为什么 GUI 自动化成为它的第一热门场景。

## 2 多模态 Agent 的技术栈

一个可用的多模态 Agent 不是「一个模型」，而是「一套系统」。它的组件有：

| 组件 | 职责 | 技术选型 |
| --- | --- | --- |
| 多模态大脑 | 理解观测、推理决策 | 多模态 LLM（GPT-4V、Qwen-VL） |
| 动作接口 | 把「意图」变成「动作」 | 工具调用、屏幕坐标、指令 |
| 记忆系统 | 记住上下文与中间结果 | 短期对话历史 + 长期向量记忆 |
| 环境感知 | 获取观测 | 截图、OCR、事件监听、传感器 |
| 反思与规划 | 拆解长任务、检查进度 | CoT、ReAct、任务清单 |

**两个关键设计**：

**① 动作空间（action space）**：Agent 能做什么。GUI Agent 的动作是「点击 (x,y)」「输入文本」；具身 Agent 的动作是「前进 10cm」「抓取」。**动作空间的设计决定了任务的粒度**——动作太粗无法精细操作，太细难以规划。

**② 观察频率（observation frequency）**：Agent 多久看一眼。每次截图都过一遍视觉模型，**成本高、延迟大**；只关键节点截图，可能漏掉变化。**「何时观察」与「如何行动」一样重要**——这是多模态 Agent 独有的设计自由度。<span class="marginnote">屏幕理解的工程现实：一个 1920×1080 的截图切成 patch 有几百个 token，每步都跑一次视觉模型，一轮操作的成本比纯文本 Agent 高一个量级。<strong>「先 OCR 提取文本、再小模型定位、大模型只在关键步介入」</strong>是控制成本的常用分层。</span>

「观察频率」还牵出一个主动性问题：**Agent 要不要主动「放大」界面细节？** 截图压缩后小字看不清——Agent 需要像人一样「把鼠标移过去看 tooltip」「放大图片区域」。**「主动获取更细的观察」是高级 Agent 的能力标志**——它不是被动消费截图，而是主动「凑近看」。这又把上一课的「交互推理」接了回来：**会主动看的 Agent，才是真「看得懂」的 Agent**。

## 3 多模态 Agent 的任务形态

多模态 Agent 的核心应用场景：

- **GUI 自动化（GUI agent）**：操作网页/桌面应用——「帮我把这份报告导出成 PDF」「在这个表格里把第二列排序」。

GUI 自动化是当前落地最热的场景，也催生了标准基准：**WebArena**（可交互的真实网页沙箱）、**Mind2Web**（从真实网站采样的任务）、**OSWorld**（桌面操作系统任务）。它们的评测方式一致：**让 Agent 在真实环境里执行任务，看能否完成**——完成率（success rate）而非「答案正确率」。**「能不能办成事」取代「答得对不对」，是 Agent 评测对前序课程的根本性转向**。
- **视觉问答代理（visual QA agent）**：需要「看图 + 查资料 + 推理」的复杂问题——「这张片子像不像文献里描述的病例」。
- **具身 Agent（embodied agent）**：控制机器人/虚拟角色——「走到厨房、拿杯子、接水」。下一课专门展开。
- **多模态搜索代理**：融合图像、文本、视频的检索与回答——「找一张类似的图，并告诉我出处」。

**共同点**：任务都要求「多模态理解 + 多步规划 + 环境交互」三合一。**Agent 的价值在于把「会看的模型」从「被动应答」解放成「主动办事」**。

## 4 公式解析：ReAct 循环

主流 Agent 的决策框架是 **ReAct**（Reasoning + Acting 交替）。在每一步，Agent 交替输出「思考」与「动作」：

$$
a_t = \text{LLM}(o_t, h_{t-1}), \quad h_t = \text{append}(h_{t-1}, [\text{Thought}_t, \text{Action}_t(a_t), \text{Observation}_t])
$$

三步拆解：

- **第（1）步，读懂 $o_t$ 与 $h_{t-1}$**：$o_t$ 是当前的多模态观测（截图/声音），$h_{t-1}$ 是截至上一步的完整轨迹（思考、动作、观察的交替历史）。**LLM 每次的输入 = 当前观测 + 全部历史**——Agent 的「记忆」就是不断增长的 $h$。
- **第（2）步，读懂交替结构**：每一步，模型先输出一句**思考**（Thought：「我需要先定位『导出』按钮」），再输出一个**动作**（Action：`click(450, 320)`），系统执行动作后把**观察**（Observation：新截图/反馈）append 回历史。**「想一步、动一步、看一步」就是 ReAct**。
- **第（3）步，为什么 ReAct 有效**：把「推理」与「行动」交替展开，**每一步的思考都可以参考真实的观察结果**——模型不会「闷头按计划走」，而是「走一步看一步」。这正是「规划」与「执行」解耦又协同的形态，也是上一课 CoT 在行动场景的延伸。

ReAct 里的「动作」不只是点击——它可以调用任何工具：**搜索、OCR、代码解释器、API、截图放大**。工具的多样性让 Agent 的「行动空间」远大于物理点击：**「会用什么工具」直接决定 Agent 能解决什么问题**。这也是第四级《AI 智能体》专题的系统主题，本课只点出它在多模态下的特殊含义：**多模态 Agent 的工具里天然含「看」的工具**（截图、OCR、放大、视频回放）——「观察工具」与「行动工具」共同构成它的完整工具箱。

## 5 挑战与易错点

多模态 Agent 的落地困难，比单模态 Agent 更严峻：

**挑战一：错误的级联放大。** Agent 一步错，后面全错；且多模态 Agent 的「观察错误」（看错屏幕、识别错物体）会污染后续所有决策。**「感知错误」与「规划错误」在循环里互相放大**。

**挑战二：长轨迹的记忆与一致性。** 十步以内的任务好办，五十步的任务里 Agent 会「忘记前面做了什么」「重复做同一件事」。**长程一致性（long-horizon consistency）是 Agent 的硬骨头**。

**挑战三：安全与可控。** Agent 有权「动手」——点错按钮、发错消息、移动机器人，后果可能是真实的。**「试错」在 Agent 里是昂贵的**，需要沙箱、确认机制、安全护栏（见《多模态安全》）。<span class="marginnote"><strong>「人机确认」是 Agent 上线前的一道铁门</strong>：高风险动作（付款、删除、发送）强制要求用户确认。经验法则：<strong>「越不可逆的动作，越需要人工确认」</strong>——这既是安全工程，也是产品信任的底线。</span>

**易错点一：把「调用模型」当「Agent」。** 一次「截图 + 问模型」不是 Agent——**没有循环、没有记忆、没有动作闭环，就不是 Agent**。判断标准：模型输出会不会改变环境、环境变化会不会回到模型输入？

**易错点二：忽视动作接口的可靠性。** Agent 的「手」（动作接口）出错率往往远高于「脑」（模型）。**坐标点偏了 5 个像素、元素选择器过时、API 参数传错**，都会让完美计划功亏一篑。**工程上，「手」的可靠性比「脑」的智能更常成为瓶颈**。

**易错点三：把「一次成功」当「可靠」。** Agent 可能「这次走运成功了」，但同一任务换一个网页布局就失败。**真正的可靠性要在「分布」上测**——同一类任务换多个界面、多次运行，看平均成功率。**Agent 评测必须「多环境、多运行」**，单次演示的成功没有任何统计意义。

## 6 小结

- **多模态 Agent** = 感知-规划-行动的闭环，观测是多模态的、循环是多轮的。
- 与第四级《AI 智能体》专题的关系：**本课聚焦「多模态观测」带来的特殊挑战**，Agent 的通用框架在那个专题展开。
- 技术栈六件套：**多模态大脑、动作接口、记忆、环境感知、反思规划**；关键设计是**动作空间**与**观察频率**。
- 「主动凑近看」（放大、OCR、tooltip）是高级 Agent 的能力标志——**观察工具与行动工具共同构成完整工具箱**。
- 任务形态：**GUI 自动化、视觉问答代理、具身 Agent、多模态搜索代理**。
- GUI 基准：**WebArena、Mind2Web、OSWorld**——「能不能办成事」是评测核心。
- **ReAct** 循环：$a_t = \text{LLM}(o_t, h_{t-1})$，「想一步、动一步、看一步」，观察回流进历史。
- 「可靠性连乘」：感知 × 规划 × 行动三环可靠性相乘才是总成功率——**Agent 工程的残酷算术**。
- 三挑战：**错误级联放大、长程一致性、安全可控**。
- 「人机确认」铁门：**越不可逆的动作，越需要人工确认**——安全工程与产品信任的底线。
- 两易错点：**调用模型≠Agent（无循环不是）**、**忽视动作接口可靠性**；外加第三个：**把单次演示当可靠**。
- 评测转向：**「能不能办成事」（完成率）取代「答得对不对」**——Agent 评测与前序课程根本不同。
- 与后续课程连接：Agent 的「行动」在物理世界里最彻底的形态，是**具身多模态感知**——下一课进入机器人。

**本课一句话**：多模态 Agent 把前三篇的「看」与上一篇的「想」接上了「动」——**它第一次让多模态模型对世界产生真实影响**。影响力带来价值，也带来责任：能力越大的 Agent，越需要评估（下一篇）、安全（再下一篇）的约束。

在下一节，我们让多模态模型「长出身体」：**具身多模态感知**——从操作屏幕到操作真实世界，这是 Agent 循环在物理世界的极限形态。
