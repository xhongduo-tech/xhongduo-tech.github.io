## 为什么从双塔走向单塔

CLIP 的双塔解决了「图文像不像」，但天花板也明显：**它只会打分，不会生成**——能给图文对打 0.9 分，却说不出「图里为什么是 0.9」。VQA 要回答、字幕要写出句子，这些都需要模型**理解图像的细粒度内容并生成语言**。答案是把图像也变成 token，让一个 Transformer **同时处理图文**——这就是**视觉语言 Transformer（Vision-Language Transformer）**。<span class="marginnote">关键转变：CLIP 把图文编码成<strong>两个向量</strong>再比；VLT 把图文编码成<strong>一串 token</strong>再混合。从「向量比较」到「序列混合」，是从「判别」走向「理解与生成」的分水岭。</span>这一课讲清它的架构骨架，后面 VQA、字幕、GPT-4V 都是它的变体。

这套架构的技术前提，是第三级《深度学习》里的 **Transformer 本身**：自注意力不关心输入是什么模态，只要都是「向量序列」。视觉语言 Transformer 没有发明新算子，只是**把「序列」的定义从「词」扩展到「词 + 图像 patch」**——同一个注意力机制，第一次同时处理两种模态。这再一次印证了深度学习的一条主线：**通用机制 + 模态适配 = 多模态能力**。

## 1 把图像变成 token：ViT 的 patch embedding

Transformer 吃序列，所以图像必须先被「切成序列」。**ViT（Vision Transformer）**给出了标准答案：

1. 把 $H \times W \times 3$ 的图像切成 $P \times P$ 的 **patch**（如 16×16），得到 $N = HW/P^2$ 个 patch。
2. 每个 patch 展平后过一个线性层，映射成 $d$ 维向量（patch embedding）。
3. 加上位置编码（patch 的空间顺序），再拼一个 `[CLS]` 或让所有 patch 参与后续聚合。

于是「一张图」变成了「$N$ 个 patch token」，与文本 token 结构同构。**图像与文本从此可以在同一个 Transformer 里被统一处理**——这是「统一」的第一步。

Patch 大小的选择是一个权衡：patch 越小，序列越长（信息越细，但计算贵）；patch 越大，序列越短（省算力，但丢失细节）。ViT-B/16 的「16」就是 patch 边长。**分辨率与 patch 的组合，决定了视觉 token 的数量与信息粒度**——后来的模型（如 GPT-4V 系）会动态调整分辨率来平衡。<span class="marginnote">为什么不用 CNN 特征直接当 token？可以，但 patch 序列让视觉与文本在<strong>同一套位置编码、同一个自注意力</strong>下交互——没有「先降维成向量再融合」的信息瓶颈。这是「token 化统一」比「特征拼接」更彻底的原因。</span>

一个常被忽略的细节是 **`[CLS]` token** 的角色：它不携带具体内容，专门用来「聚合」整个序列的信息，分类/匹配任务通常拿它的输出当整个序列的表征。在视觉语言模型里，判别头（如 ITM）就常挂在 `[CLS]` 上——**`[CLS]` 是「读完全序列后总结出的那个向量」**，与双塔的「全局向量」功能对位，但它是从深层交互里长出来的，而非独立编码的。

## 2 三种架构路线

视觉语言 Transformer 的架构可以按「文本怎么产生」分成三条路线：

| 路线 | 结构 | 擅长 | 代表 |
| --- | --- | --- | --- |
| **融合编码器** | 图文一起进编码器，出判别头 | 匹配、VQA（判别式） | ALBEF、VLMo |
| **编码器-解码器** | 编码器混合图文，解码器生成文本 | 字幕、生成式 VQA | BLIP、CoCa |
| **统一自回归** | 图文 token 拼接，自回归一起预测 | 视觉-语言统一 | Flamingo、LLaVA、GPT-4V |

**融合编码器**：图像 patch 与文本 token 拼成一个序列，过 N 层 Transformer，最后用 `[CLS]` 或 pool 输出做判别（ITM、VQA 分类头）。它继承 BERT 的「双向理解」，但没有生成能力。

**编码器-解码器**：在融合编码器后接一个语言解码器（自回归），让模型「读懂图之后再写」。生成能力从这里开始。

**统一自回归**：把图像 token 与文本 token 直接拼成长序列，用「下一个 token 预测」一个目标训到底——**视觉与语言共用一个模型、一个损失**。这是 2023 年后大模型多模态的主流，也是 GPT-4V 系的地基。

统一自回归的一个关键设计是**图像 token 的「只读」性质**：自回归预测「下一个 token」时，视觉 patch 通常只在序列**前面**作为「已见输入」，文本 token 负责被预测。这就引出了两个经典问题——**图像要不要也做「双向编码」**（让 patch 之间互相看到，而不是被文本单向查询）、**图像如何压缩成更少的 token**（几百个 patch 逐个预测太慢）。Flamingo 用「perceiver resampler」把图像特征压缩成固定数量的「视觉 token」，LLaVA 则用 CLIP 视觉塔直接出 token——**「图像 token 怎么产生、多少够用」是统一模型最重要的设计自由度**。

三条路线的演化逻辑：**从「判别图文」到「生成语言」再到「统一预测」**。每一步都让视觉与语言耦合得更深。

三个代表模型正好串起这条演化链：**ALBEF**（融合编码器，判别式 VQA/检索）→ **BLIP**（编码器-解码器，字幕 + 匹配）→ **Flamingo / LLaVA**（统一自回归，对话式视觉语言）。读者可以把这个顺序当作「看文献的目录」——从 ALBEF 看判别、从 BLIP 看生成、从 LLaVA 看统一，视觉语言模型的演进就一览无余。每条路线不是「取代」而是「叠加」：**新路线保留旧路线的能力，再往上加生成或统一的新能力**。

## 3 公式解析：Cross-Attention 的混合机制

单塔架构里，图文混合的核心是 **cross-attention**。设文本 token 的 query 序列 $Q$，图像 patch 提供的 key/value $(K_V, V_V)$：

$$
\text{CrossAttn}(Q, K_V, V_V) = \text{softmax}\left(\frac{Q K_V^{\top}}{\sqrt{d_k}}\right) V_V
$$

三步拆解：

- **第（1）步，谁查谁**：$Q$ 来自**文本**（query，「我想看图里哪里最重要」），$K_V, V_V$ 来自**图像 patch**（key/value，「我这里有这些内容」）。**文本主动去查图像**——这就是「文本 token 看图」的数学形态。
- **第（2）步，读懂 softmax 项**：$Q K_V^{\top} / \sqrt{d_k}$ 是「文本 token 与每个图像 patch 的注意力分数」，softmax 后归一化成权重。**权重大的 patch 就是「这个词在看的区域」**——对齐在这里隐式发生。
- **第（3）步，加权聚合**：按注意力权重对图像 patch 的 value 加权求和，得到「文本 token 结合了图像信息」的新表示。**这个新表示既含词的语义，又含图的证据**——融合在这里一步完成。

**对比双塔**：双塔里图文交互只发生在最终向量点积（一次）；cross-attention 让**每个文本 token 与每个图像 patch 在每一层都交互**。信息通道从「一扇门」变成「每一层都开着的窗」——这就是单塔比双塔细粒度强的根源。

走一个具体例子：问「图里狗旁边的球是什么颜色」。文本 token「球」作为 query，会去图像 patch 里找「球」的区域（注意力权重集中在球上），把那个 patch 的颜色信息取回来。**「词找区域」的每一步都被注意力显式记录**——这既是能力，也是可解释性：可视化注意力权重，就能看到模型「在看哪」。这为第四篇《多模态安全》里的「错误归因」检查提供了抓手。

## 4 预训练任务：单塔怎么学

单塔 Transformer 的预训练任务，是从 NLP 与视觉借来后改造的三件套：

- **图像-文本匹配（ITM）**：判别「这个图文对配不配」——上一篇已详讲。
- **掩码语言建模（MLM）**：把文本里的某些 token 盖住，让模型**看图补全**——「一只 [MASK] 在草地上」看图填「狗」。这迫使模型用视觉证据完成语言推断。
- **图文对比（ITC）**：双塔式的对比损失，常作为辅助头加上，保证全局对齐不丢。

生成式路线还会加第四件：**语言建模（LM）**——直接训练「看图写句子」的自回归损失。

**三件套的分工**：ITC 管全局对齐、MLM 管「以图释文」的细粒度理解、ITM 管一致性判断。**它们从三个角度逼同一个模型把视觉与语言揉在一起**——单塔的强能力就来自这些任务的合力。

其中 **MLM 是单塔的「灵魂任务」**：它要求模型看图猜词，比 ITM 的「二选一」难得多——因为猜词需要真正理解「图里有什么、词该怎么组织」。一个著名现象是：**MLM 训练出的注意力图，往往能自发地定位到「那个词对应的物体区域」**——细粒度对齐不是被显式标注出来的，而是被 MLM 逼出来的涌现行为。这与第一课《表示对齐》的「局部对齐要靠注意力」遥相呼应。

## 5 易错点与辨析

**易错点一：把「拼接」当「融合」。** 把图像特征与文本 token 拼在一起，如果后续层不做强交互，就只是「放在一起」（见第一篇《融合》的坑）。**真正的融合要靠 cross-attention 或深层的自注意力**——判别一个架构是不是真融合，就看图文 token 之间有没有直接交互路径。

**易错点二：忽视位置编码的跨模态问题。** 图像 patch 有空间位置，文本 token 有顺序位置——两者用**不同的位置编码**，拼接后必须区分。若共用一套位置编码，模型会把「第 3 个 patch」与「第 3 个词」的位置搞混。**分开编码、拼接时加类型标记**是标准做法。

**易错点三：把序列长度当细节。** 视觉 token 数量（patch 数 × 分辨率倍数）动辄数百到上千，是文本 token 的好几倍——**长序列的注意力是平方复杂度**，视觉 token 直接决定算力开销。这就是为什么 VLT 的工程优化（flash-attention、分辨率裁剪、token 压缩）成为一门学问。<span class="marginnote">一个反直觉的点：图像是「连续且信息稠密」的，但切成 patch 后却成了「冗余极高的长序列」——相邻 patch 高度相似。因此出现了 <strong>token 压缩</strong>（用注意力把相邻 patch 合并）与「先降分辨率、注意力后再上采样」等技巧，目的都是治这个冗余。</span>

还有一个更深的问题：**多模态输入的数量级与分布差异**。图像 patch 数百个、文本 token 几十个，两类 token 的「信息密度」与「角色」都不同——直接塞进同一层注意力，视觉 token 容易「淹没」文本信号。**分层交互**（先各自自注意力、再跨模态交互）、**轻量视觉塔**（视觉先被 CNN 压缩再进 Transformer）都是为平衡两类 token 而设计的结构选择。**「怎么排布两类 token」本身就是架构设计的一等公民**。

一个常见的架构困惑是「编码器 vs 解码器」：判别式任务用**双向编码器**（token 能看到左右，适合「理解整句」），生成式任务用**因果解码器**（token 只能看左边，适合「逐词生成」）。视觉语言模型里两者都有——**同一套 VLT 骨架，换注意力掩码（双向/因果）就换了一种能力**。这是理解「为什么同一个模型能同时做匹配与字幕」的关键：不是模型「全能」，而是**注意力掩码与任务头决定了能力形态**。

## 6 小结

- **视觉语言 Transformer** 把图像切成 patch token，与文本 token 在同一 Transformer 里混合，从「向量比较」升级到「序列混合」。
- **ViT patch embedding** 是图像 token 化的标准方法；patch 大小决定序列长度与信息粒度。
- 三条架构路线：**融合编码器、编码器-解码器、统一自回归**；演化方向是「判别 → 生成 → 统一预测」。
- **Cross-attention** 让每个文本 token 与每个图像 patch 逐层交互——单塔细粒度能力的数学根源；注意力权重同时提供了「模型在看哪」的可解释性抓手。
- 预训练三件套：**ITM + MLM + ITC**（生成式再加 LM），从三个角度逼模型融合图文；MLM 会自发涌现出「词找区域」的细粒度对齐。
- 三个易错点：**拼接≠融合、跨模态位置编码、视觉 token 的长度与算力**。
- 判别架构挂 `[CLS]` 头、生成架构挂解码器、统一架构走自回归——「挂什么头」决定「能干什么活」，这是理解一切 VLM 变体的钥匙。
- 预训练数据与任务（见上一篇）决定「它见过什么」，架构决定「它能做什么」——两者共同框定 VLT 的能力上限。
- 视觉语言 Transformer 没有新算子，只是把「序列」从词扩展到「词 + 图像 patch」——通用机制 + 模态适配。
- 统一自回归路线的关键自由度：**图像 token 的产生方式与数量**（perceiver 压缩 vs 直接 patch），直接决定「视觉」与「生成」的耦合深度。
- 双向/因果注意力掩码切换编码器/解码器能力——**同一骨架，掩码决定能力形态**。
- 与后续课程连接：VLT 是骨架，往它上面挂不同任务头/解码器，就得到 VQA、字幕、指代——下一课看**VLM 的下游任务**。

**本课一句话**：从 CLIP 到视觉语言 Transformer，本质是「**从比距离到读序列**」——把图像从「一个向量」变成「一段与文字同构的叙述」，模型才第一次有机会「边看边说」。这套骨架也让「模态融合」从「一次向量点积」彻底升级为「逐 token、逐层的深度混合」，前一篇的所有铺垫在此汇合。

在下一节，我们看这套骨架如何撑起真实任务：**VLM 的下游任务（VQA/字幕/指代）**——同样的架构，不同的任务头，如何各司其职。
