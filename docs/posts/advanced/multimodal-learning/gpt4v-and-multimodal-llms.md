## 为什么 GPT-4V 是「质变」而非「量变」

前面几课的多模态模型，本质都是「**视觉为主**」的：CLIP 给视觉配文本、VLM 用文本问视觉。GPT-4V 的站位完全不同——它是一个**「以语言模型为主」的多模态系统**：视觉只是语言模型的「另一个输入通道」，模型的主体是那个能对话、能推理、能规划的大语言模型（LLM）。<span class="marginnote">这就是「多模态大模型」与「视觉语言模型」的分野：VLM 是「视觉模型 + 文本输入」，多模态 LLM 是「<strong>语言模型 + 视觉输入</strong>」。前者问「图是什么」，后者问「图里的世界该怎么推理」。GPT-4V 是后者的代表，也定下了 2023 年之后多模态的主旋律。</span>这一课拆解它的架构范式、能力来源与边界。

从历史坐标看，GPT-4V 站在两条线的交汇点：**语言大模型线**（第四级《大模型原理》的预训练、指令微调、对齐）与**多模态线**（本专题第二、三篇的对齐、VLM、Florence 的「一切皆语言」）。**GPT-4V 不是「多模态模型的一个新版本」，而是「LLM 把视觉收编为自己的一个输入模态」**——所以理解它，一半靠多模态知识，一半靠大模型知识。本文假定读者对 LLM 已有基础，重点讲「视觉怎么被收编」。

## 1 架构范式：视觉塔 + 投影层 + LLM

GPT-4V 的详细架构未公开，但开源家族（LLaVA、Qwen-VL、InternVL）给出了公认的骨架——**视觉塔-投影层-LLM 三段式**：

1. **视觉塔（vision encoder）**：一个预训练图像编码器（如 CLIP 的 ViT），把图编码成 patch 特征。**它可以被冻结**——因为它已经学会了「看懂图」。
2. **投影层（projector）**：把视觉特征映射进 LLM 的词嵌入空间。最简是一个线性层（LLaVA-1.5），进阶是 Q-Former（BLIP-2）或 resampler。
3. **大语言模型（LLM）**：冻结或微调的 GPT 类模型，接受「视觉 token + 文本 token」拼接的序列，做自回归生成。

一句话：**LLM 是「大脑」，视觉塔是「眼睛」，投影层是「视神经」**。训练时「大脑」可以部分冻结，重点学「视神经」怎么把眼睛的信号翻译给大脑。

以 **LLaVA** 为例把这套骨架落到具体数字：视觉塔用 CLIP 的 ViT-L/14（图像编码成 576 个 patch token），投影层是一个**线性层**（把视觉嵌入线性映射进 Vicuna 的词嵌入空间），LLM 用 Vicuna-7B/13B。**整模型只有投影层是「新参数」**——LLaVA 证明了「一个线性层 + 指令微调」就能把已有的视觉塔与 LLM 接成能对话的多模态系统。这个「轻桥」思路后来成为开源多模态的默认起点，也被 InternVL、Qwen-VL 等用更复杂的投影层超越。

「三段式」是简化图景，实际工程的自由度比它大：**视觉塔可以多尺度**（不同分辨率各出特征）、**投影层可以是多层 Transformer**（Q-Former）、**LLM 可以是 MoE**（稀疏专家）。但**骨架不变：视觉进、语言出、中间有桥**。理解骨架，任何新模型都能一眼归类。

## 2 三个关键设计决策

**决策一：视觉 token 怎么进序列。** 视觉特征要么被压缩成**少量「可学习的 query token」**（Q-Former，如 32 个），要么**每个 patch 直接映射成一个 token**（LLaVA，如 576 个）。query 少则省算力、快；patch 多则细节足、慢。**「视觉 token 的数量」直接决定模型「看得细不细、跑得快不快」**。

**决策二：LLM 冻不冻、微调多少。** 三种策略：全冻结（只训投影层，最省）、只训投影层 + LoRA（中庸）、全量微调（最贵但能力最强）。**「视觉塔冻结 + LLM 微调」是性价比之王**——视觉已会看，重点是让 LLM「学会用眼睛」。

| 冻结策略 | 训练参数 | 成本 | 能力 | 适用 |
| --- | --- | --- | --- | --- |
| 全部冻结 | 仅投影层 | 极低 | 能看、不会多模态推理 | 快速验证 |
| 视觉冻结 + LLM 微调 | 投影层 + LLM | 中 | 会推理、指令跟随 | 主流默认 |
| 全量微调 | 全部 | 高 | 最强（含视觉塔适配） | 追求上限 |

**「冻结」不只是省钱，还是一种「保护」**：冻结视觉塔防止它被微调数据「带偏」而丢失通用视觉能力；冻结 LLM 防止它遗忘语言能力（灾难性遗忘，见第四级《大模型微调》）。**「冻什么」背后是「保住什么能力」的取舍**——这是多模态微调的核心权衡。

**决策三：训练数据怎么配。** 两阶段是标准配方：**先「图文对齐」预训练**（大量图文对，学投影层），**再「指令微调」**（VQA/对话数据，学跟着指令回答）。**第一阶段解决「能不能看」，第二阶段解决「会不会答」**——这与 LLM 的「预训练 + 指令微调」一脉相承。

指令微调的数据形态也决定了能力形态：**只喂「看图回答问题」→ 模型只会被动答题；喂「看图多轮对话 + 推理 + 拒绝」（如 LLaVA 的 15.8 万指令样本）→ 模型学会主动叙述、澄清、承认看不到**。**「指令数据的多样性 = 对话能力的上限」**——这也是为什么各家的数据配比（通用对话 / OCR / 图表 / 医学）成了核心竞争力。

## 3 能力来源：为什么「会说话」的视觉更聪明

多模态 LLM 比 VLM 强在哪？不是视觉编码更强，而是**语言模型的推理被接进了视觉**：

1. **组合式推理**：把「图里有什么」与「常识」结合——「看到伞」+「常识：雨天撑伞」→「推测在下雨」。VLM 只能描述「有人撑伞」，多模态 LLM 能推断「天气」。
2. **指令跟随**：用户问什么答什么，还能多轮对话、澄清、追问——VQA 是「一问一答」，多模态对话是「有来有往」。
3. **工具化**：LLM 可以「看图后决定查资料、算数、调工具」——多模态从「感知」走向「行动」，为第四篇《多模态 Agent》铺路。<span class="marginnote">GPT-4V 在「手写数学题」上能边看边算，靠的正是语言模型的<strong>符号推理</strong>能力——视觉给出题面，LLM 负责「算」。这种「视觉感知 + 语言推理」的耦合，是纯 VLM 做不到的。</span>

**核心洞察：多模态 LLM 的「智能增益」来自语言模型本身**。视觉塔负责「看」，推理、常识、对话全部继承自预训练 LLM——**多模态大模型的强大，是「把视觉接进一个已经很强的脑子」**。

拿一个具体例子串起三种能力：用户上传一张「冰箱内部」的照片，问「晚饭能做什么？」。**组合推理**：模型认出「鸡蛋、番茄、葱」，结合常识「蛋炒饭需要这些」→ 回答「可以做番茄蛋炒饭」。**指令跟随**：用户接着问「有没有更简单的？」，模型能针对上一条回答调整。**工具化**：模型还可以说「我帮你搜一下菜谱」然后调用检索。**每一个动作都不是「看图」而是「思考」**——图只是思考的输入之一。这就是「多模态 LLM」与「VLM 看图答题」的本质差别。

但要诚实指出：**这种「推理」也可能出错，且错得很隐蔽**。模型可能因为「番茄在冰箱里很常见」就默认图里有番茄（文本先验压过视觉证据）——这正是「幻觉」的温床。**能力的另一面是风险的放大**：一个会推理的视觉系统，也会「会推理地犯错」。如何区分「真看图」与「借常识蒙」、如何评估与缓解幻觉，是第四篇《多模态安全与幻觉》与《多模态评估基准》的主题，这里先埋下伏笔。

## 4 公式解析：视觉 token 的接入方式

视觉特征进入 LLM 的数学形态，是一个「重映射」：设视觉塔输出 $V \in \mathbb{R}^{N_v \times d_v}$，投影层 $\phi$ 把它映射成 LLM 的嵌入：

$$
Z_v = \phi(V) \in \mathbb{R}^{N_v \times d_{llm}}, \qquad \text{input} = [Z_v; E(T)]
$$

三步拆解：

- **第（1）步，读懂 $\phi$**：线性投影 $\phi(V) = V W + b$ 或 Q-Former 式可学习 query 交互。**它把「视觉塔的表示」翻译成「LLM 能读的嵌入」**——$d_v$ 与 $d_{llm}$ 往往不等，投影层负责对齐维度与语义。
- **第（2）步，读懂拼接 $[Z_v; E(T)]$**：视觉 token 排在**前面**（模型「先看」），文本 token 排在后面（模型「边看边说」）。自回归解码时，LLM 依次预测后面的文本 token，视觉信息始终在上下文里。
- **第（3）步，为什么「先看后说」很重要**：把图像放前面，让 LLM 在生成第一个词之前就已经「消化」了图像。**整个文本生成过程都沐浴在视觉信息里**——这与 VLM 的「先编码整图、再解码」本质相同，但多模态 LLM 的视觉信息能参与**每一层的注意力计算**，融合更深。

**投影层的两种形态对应两种哲学**：线性投影是「直接把视觉嵌入塞进 LLM」（简单、保真，LLaVA 用）；Q-Former 是「用 32 个可学习 query 去视觉特征里「提炼」出 LLM 需要的摘要」（压缩、去噪，BLIP-2 用）。**前者信息全但 token 多，后者 token 少但会丢细节**——没有绝对优劣，只看「你要快还是要细」。而 2024 年后的趋势是**二者融合**：先用大 patch 压缩、再用高分辨率细读，视觉 token 数从「固定」走向「按图动态分配」。

## 5 边界、风险与易错点

多模态 LLM 的能力强，但**失败模式同样放大**：

**幻觉**：LLM 会「一本正经地胡说」，多模态版更甚——它可能**「看见」图里没有的物体**（受文本先验驱动）。这是第四篇《多模态安全与幻觉》的主菜。

**计数与细节的失焦**：虽然比 CLIP 强，但多模态 LLM 在「数几十个物体」「精确读取长文本/小字」上仍不可靠——**压缩视觉 token 必然丢失细节**。这提醒我们：**多模态 LLM 的「视觉记忆」是有损的**，凡依赖精确像素的任务（医学影像细读、票据核验）仍需专用模型或更高分辨率方案。

**对「能力边界」的正确态度**：不是「有边界就失败」，而是「知道边界才能正确部署」。**多模态 LLM 适合「要理解、要推理、要对话」的场景；需要「像素级精确」的场景，应把它当作「入口」而非「终审」**——先让 LLM 定位，再让专用模型细读。这种「大模型粗读 + 专用模型精读」的分工，正是第四篇《多模态产业应用》的落地范式。

**易错点一：把「视觉塔冻结」当成「视觉不重要」。** 恰恰相反——**视觉塔是感知上限**。投影层和 LLM 再强，也补不回视觉塔「没看见」的信息。视觉塔的分辨率、patch 大小，直接决定模型能看清多细。

**易错点二：忽视「视觉 token 数量」的成本。** 一张高清图 576 个 token，比一段文本还长——**多模态推理的算力与延迟，很大一块耗在视觉 token 上**。部署时要权衡「分辨率 vs 速度」，动态裁剪分辨率（先低后高）是常见优化。<span class="marginnote">一个实测现象：<strong>图片 token 比文本 token 「贵」得多</strong>——一张图常等于几百个词。因此多模态 LLM 的推理成本主要被视觉占用，<strong>token 压缩</strong>（视觉 token 数压到几十个）成了性价比的关键战场。</span>

**易错点三：把「多模态」等同于「加个视觉塔」。** 视觉只是多模态的一种——**音频、视频、文档、结构化数据都能通过「投影层 + token 化」接进同一个 LLM**。GPT-4o、Gemini 等把音频输入也做成「音频 token」，让 LLM 直接「听」。**「多模态大模型」的野心是「把所有感知都接进一个大脑」**——视觉是第一个成功案例，不是最后一个。

## 6 小结

- **多模态大模型** = 视觉塔 + 投影层 + LLM；与 VLM 的分野是「**语言模型为主体、视觉为输入通道**」。
- 三个设计决策：**视觉 token 的数量、LLM 冻结程度、训练数据配方**。
- 冻结策略三档（全冻结 / 视觉冻结+LLM 微调 / 全量微调）：**「冻什么」背后是「保住什么能力」**。
- 两阶段训练：**图文对齐预训练（能不能看）→ 指令微调（会不会答）**；指令数据多样性 = 对话能力上限。
- 能力增益来自**语言模型的推理被接进视觉**：组合推理、指令跟随、工具化；但「会推理」也意味着「会推理地犯错」。
- 视觉接入的数学形态：$\phi$ 把视觉表示重映射进 LLM 嵌入，视觉 token 排在序列前面「先看后说」。
- 投影层两种哲学：**线性投影（信息全、token 多）vs Q-Former 提炼（token 少、会丢细节）**；2024 年后趋向动态分配。
- 边界：**幻觉、计数失焦**；两个易错点：**低估视觉塔是感知上限**、**忽视视觉 token 的成本**。
- 与第四级《大模型原理》《大模型微调》的关系：**多模态 LLM = LLM 的技术栈（预训练/微调/对齐）+ 视觉塔与投影层的多模态技术栈**——两条栈在此合流。
- 多模态 LLM 的视觉记忆是**有损压缩**——「大模型粗读 + 专用模型精读」是落地的正确分工。
- 多模态 ≠ 视觉：**音频、视频、文档都能用「投影层 + token 化」接进同一个 LLM**，视觉只是第一个成功案例。
- **评估提醒**：多模态 LLM 的分数「高得惊人」时，先检查基准是否含泄漏、是否依赖语言先验——见《跨模态表征的评价》。
- GPT-4V 定下了「语言模型收编视觉」的范式；**视频、音频的收编只是同一范式的扩展**——下一课从视频开始。
- 与后续课程连接：多模态 LLM 能「说」，下一步是让它「听懂视频、听见音频」——下一课**视频理解模型**。
- **一句话收束**：GPT-4V 的「质变」在于把多模态的坐标系从「视觉」搬到了「语言」——从此，**多模态问题的答案不是「更懂图」，而是「更会用脑子」**。
- **实操清单**：做多模态产品时，先想清「视觉塔看到多细」（分辨率）、「视觉 token 占多少预算」（速度）、「LLM 会不会被图带偏」（幻觉）——三问定生死。
