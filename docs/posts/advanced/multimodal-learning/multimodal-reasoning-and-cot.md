## 为什么「想」比「看」难

第三篇的多模态模型能「看」能「说」，但「说」还停留在「描述」层面：能告诉你「图里有一只狗」，却未必能推断「狗的主人可能刚遛完狗回来」。**描述是「看见什么说什么」，推理是「看见之后想什么」**——后者需要模型把图像信息与常识、逻辑、多步关系编织在一起。**多模态推理（multimodal reasoning）**就是让多模态模型「看图之后会想」。而「想」最流行的工程形态，是**思维链（Chain-of-Thought, CoT）**——让模型先说出推理步骤，再给出答案。<span class="marginnote">CoT 在纯语言模型里已被证明能显著提升推理（见第四级《大模型原理》的「思维链」一节）；多模态的挑战是：<strong>推理的每一步都可能要重新「看」图</strong>——「狗旁边有个球」需要先定位，再推理。文字 CoT 是「想」，多模态 CoT 是「边看边想」。</span>这一课讲清多模态推理的形态、方法与其独特困难。

**这一课在专题里的位置**：它把本专题从「感知」推向「认知」——前 17 课都在回答「模型能从模态里看到什么」，从这一课开始问「模型能对着模态想出什么」。第四篇的后续课程（Agent、具身、评估、安全、产业）全部建立在「会推理」之上：**没有推理，Agent 只是检索器；有了推理，Agent 才谈得上决策**。

## 1 多模态推理的任务形态

多模态推理不是一个任务，而是一族「需要多步思考」的任务。按「推理深度」排一个梯子：

| 任务 | 例子 | 需要几步思考 |
| --- | --- | --- |
| 属性识别 | 「球是什么颜色？」 | 1 步（看） |
| 视觉关系 | 「谁在谁旁边？」 | 2 步（定位 + 关系） |
| 视觉常识 | 「这人为什么撑伞？」 | 3 步（看到伞 + 常识 + 推断天气） |
| 图表推理 | 「哪年销量最高？」 | 多步（读表 + 比较 + 结论） |
| 多跳视觉问答 | 「如果狗跑向碗，会发生什么？」 | 多步（对象 + 动作 + 因果） |

**梯子的本质是「要不要想」**：属性识别只需「看」，视觉常识必须「看 + 想」，多跳问答要「想好几轮」。**推理深度的需求，决定了要不要上 CoT**——简单任务用 CoT 反而画蛇添足。

**「要不要想」还决定评测怎么设**：测属性识别，答案是唯一、客观的（颜色就是颜色）；测多跳推理，答案可以有多种合理解释（「狗会追球」和「狗会等主人」都可能对）。**推理任务的「答案开放性」随深度递增**——这给自动评测带来麻烦（怎么判「都算对」），也是《多模态评估基准》一课要专门处理的难题。

推理的「原材料」也不只自然图像：**图表（chart）、表格（table）、示意图（diagram）、数学公式图**都是推理的重要载体。「图表推理」在多模态评测里是独立板块——因为它把「视觉感知」与「数值/逻辑推理」绑在一起，是模型的「硬骨头」。

图表推理之所以难，在于它要求**「读图」与「算数」同时成立**：模型要先从折线图里读出「2023 年峰值约 80」这个视觉信息，再做「80 是 2022 年（约 50）的 1.6 倍」这个数值推理。**任一步错，答案就错**——读图错（把 80 看成 60）或算数错（1.6 算成 1.2）都致命。这类「感知 + 推理」双错误的叠加，正是多模态推理区别于纯文本推理的独特难度。

## 2 从文本 CoT 到多模态 CoT

文本 CoT 的做法是：**让模型先输出推理过程（「因为……所以……」），再输出答案**。多模态 CoT 继承了这一点，但要处理「图在哪一步被用」。

三种典型的多模态 CoT 方案：

1. **先描述、后推理（caption-then-reason）**：第一步让模型「看图写描述」，第二步把描述当文本上下文做 CoT 推理。**简单可行，但丢失了图像细粒度**——描述是「转述」，转述丢的信息推理就补不回来。
2. **视觉锚点推理（grounded CoT）**：推理过程中，每个推理步骤**引用图像的具体区域**——「[区域 A] 是一只狗，[区域 B] 是一只球，所以狗会去追球」。**模型边看边想，每一步都有图像证据锚定**。
3. **多模态交互推理（interleaved reasoning）**：让模型「看 → 想 → 再看 → 再想」循环（用工具重新读图、放大区域、多视角）。**最接近人类的推理方式，也最难工程化**。

三种方案的共性：**CoT 的价值在于「把隐性的一步判断，拆成显性的多步推理」**——每一步都可以被检查、被干预、被纠错。这也让「幻觉」有了抓手：模型说「狗在追球」，可以回溯它「有没有真的看到球」。

多模态推理的标准评测有 **ScienceQA**（科学问答，含图、文本、语音多种模态，带推理步骤标注）、**MMMU**（大学级多学科多模态理解）、**MathVista**（数学 + 视觉推理）。它们的共同点：**题目「图 + 问 + 推理链」三者齐全**，可以同时报「答案准确率」与「推理链质量」。**ScienceQA 还是 CoT 微调的标准实验场**——它公开的推理链标注让「推理数据」不再是稀缺品。

补充一个工程视角的对比：**方案一（先描述后推理）最便宜**——描述模型与推理模型都可以是现成的，拼起来就行，缺点是「两次压缩」损失细节；**方案二（视觉锚点）最「多模态」**——推理链里带图像坐标，是真正的「边看边想」，但需要「区域级标注」训练；**方案三（交互推理）最贵**——要反复调用视觉工具，延迟高、成本高。**「推理深度 vs 工程成本」永远要对赌**：任务越难，越值得上贵的方案。

## 3 公式解析：CoT 的贝叶斯视角

CoT 为什么有用？从概率视角看，条件答案 $a$ 关于图像 $I$ 与问题 $q$，一步直接给出答案 vs 先给推理链 $z$ 再给答案：

$$
P(a \mid I, q) \approx \sum_{z} P(z \mid I, q)\, P(a \mid z, q) \quad \text{(理想化)}
$$

三步拆解：

- **第（1）步，读懂 $z$**：$z$ 是中间推理链（「图里有伞 → 有伞通常因为下雨 → 答案：下雨」）。求和号表示「遍历所有可能的推理链」——现实中模型不做这个穷举，而是**采样一条链**。
- **第（2）步，拆成两步**：$P(z \mid I, q)$ 是「给定图与问题，这条推理链是否合理」；$P(a \mid z, q)$ 是「给定推理链，答案是什么」。**两步各自都更简单**——比一步直接猜更容易学对。
- **第（3）步，为什么有效**：一步预测 $P(a \mid I, q)$ 要求模型「同时完成看 + 推理 + 作答」；CoT 把「看 + 推理」放进 $z$，「作答」放进最后一步，**分解降低了每一步的复杂度**。而且 $z$ 是可读的——**推理链让模型的「思路」暴露，便于验证与纠错**，这是纯黑箱一步预测给不了的。

**CoT 的代价**：推理链越长，越容易「在中间某步出错后一路错下去」（错误累积）；且生成 $z$ 消耗更多 token、延迟更高。**「要不要上 CoT」是精度与成本的对赌**。

这个贝叶斯视角还揭示了一个被低估的点：**求和号（理想化）在现实中变成「采样一条链」**，而单次采样可能采到一条「看起来对但实际错」的链。**self-consistency 就是「多采样几条、投票取共识」**——它用「重复采样」近似求和号，摊平单次采样的运气成分。**CoT + self-consistency 的组合，是把「采样误差」这个 CoT 的副作用也治掉的完整方案**。

## 4 多模态推理的独特困难

多模态 CoT 比文本 CoT 难，难在三点：

**困难一：图像证据的「不可重读」。** 文本推理中模型随时可以「回看」前文；多模态推理中图像信息被压缩进 token，模型「回看」的是压缩过的版本——**细节已在压缩中丢失**。所以多模态 CoT 容易「推理结构对、事实细节错」（推理链漂亮但锚错了对象）。

**困难二：视觉锚定的可靠性。** 视觉锚点推理要求「每一步引用的区域是对的」。但**区域定位本身会错**——模型引用了「[区域 A] 是狗」，但区域 A 其实是猫，后面全错。**「锚定错误」是多模态推理特有的错误模式**，文本 CoT 没有这个问题。<span class="marginnote">一个判别技巧：看推理链里「对象名词」与「图像区域」的绑定是否稳定。若模型换了措辞就换区域，说明锚定是「编」的而非「看」的——<strong>这正是区分「真推理」与「装模作样的推理」的探针</strong>，也是《多模态评估基准》与《安全与幻觉》两课的前哨。</span>

**困难三：常识与视觉的交织。** 多模态推理经常「一半靠看、一半靠常识」——「撑伞 → 下雨」是常识，「看到伞」是视觉。**两者交织时，模型容易用常识「覆盖」视觉**（图里其实没伞，但模型按常识说有）——这是多模态幻觉的典型机制。

困难一与困难二还会合成一个「双重错误陷阱」：**推理结构越复杂，视觉证据被「用错」的概率越高**。一条五步推理链里，只要某一步锚错了对象（把 A 当成 B），后面四步再完美也是错的——而且因为推理链「看起来合理」，这种错误比「直接答错」更难被发现。**多模态推理的可靠性，受「链条中最弱一环」制约**——这也是为什么评测要专门看「推理链正确但答案错误」这类失败模式。

## 5 如何提升多模态推理能力

提升途径有三层，从便宜到昂贵：

1. **推理提示（prompting）**：用「请一步一步推理」等提示词唤醒 CoT 能力——**零成本，但受模型固有推理上限约束**。
2. **推理数据微调**：用「图 + 问题 + 推理链 + 答案」的标注数据微调模型——**成本中，效果直接**。关键是数据里的推理链要「真」（真看到图再推理），否则模型学的是「编推理」。
3. **推理时扩展（test-time scaling）**：让模型采样多条推理链、投票选最优（self-consistency），或让它「重新读图」后再推理——**成本高，但能显著压过单次推理的偶然错误**。<span class="marginnote">self-consistency（自一致性）是文本 CoT 的经典增强：<strong>采样 N 条推理链，答案多数投票</strong>。它的哲学是「单条链会错，多数链的共识更可靠」——多模态同样适用，且因为多模态错误更多样，投票收益往往更大。</span>

**三者可以叠加**：提示唤醒 → 微调夯实 → 推理时投票。**推理能力是「提示 + 数据 + 算力」的联合产物**，不是某一招独大。

推理数据的生产本身是个「鸡生蛋」问题：人工标注「图 + 推理链」极贵。主流解法是**「强模型蒸馏 + 人工校验」**——用 GPT-4V 这类强模型对图生成推理链，人工或规则过滤质量，再喂给弱模型微调。**「强模型当老师、弱模型当学生」**的蒸馏路线，是推理数据规模化的最经济路径——它的风险是「学生继承了老师的推理错误」（推理蒸馏会传偏见），需要持续抽检校准。

## 6 小结

- **多模态推理**是「看图之后会想」；任务形态从属性识别到多跳问答，推理深度递增。
- 评测基准：**ScienceQA、MMMU、MathVista**——「图 + 问 + 推理链」齐全，可同时评答案与推理质量。
- **CoT** 把「一步猜」拆成「显性多步」，每一步可检查、可纠错。
- 三种多模态 CoT：**先描述后推理、视觉锚点推理、多模态交互推理**；「推理深度 vs 工程成本」永远对赌。
- CoT 的代价：**错误累积 + token/延迟成本**；「要不要上 CoT」是精度与成本的对赌。
- **本专题的感知→认知转折点**：前 17 课回答「看到了什么」，从本课起回答「能想出什么」。
- CoT 的贝叶斯视角：$P(a \mid I, q) \approx \sum_z P(z \mid I,q) P(a \mid z,q)$——**分解降低每步复杂度，推理链暴露思路**。
- 多模态推理三难：**图像证据不可重读、锚定错误、常识覆盖视觉**；外加「链条最弱一环」决定整体可靠性。
- 图表推理是「读图 + 算数」双错误叠加的硬骨头——感知与推理任一环错就全错。
- self-consistency 用「多采样 + 投票」近似贝叶斯求和，**摊平单次采样的运气成分**。
- 提升三层：**提示、数据微调、推理时扩展（self-consistency / 重读图）**。
- 推理数据靠「强模型蒸馏 + 人工校验」，但会**继承老师的推理错误**，需持续抽检。
- **答案开放性随推理深度递增**——给自动评测带来「多解判定」难题，也是《评估基准》课的伏笔。
- 与后续课程连接：会推理的模型可以「自己动手」了——下一课**多模态 Agent**：让模型看图、决策、行动。

**本课一句话**：多模态推理的本质，是把「看图 + 常识 + 逻辑」这三件事从「一次模糊的直觉」拆成「一步步可见的思考」——**拆得开，才查得清；查得清，才信得过**。

在下一节，我们把「会看 + 会想」的模型放进真实任务循环：**多模态 Agent**——从理解世界到在世界里行动。
