## 为什么评估是最后的战场

前 20 课我们造了一堆模型——VLM、GPT-4V、视频理解、VLA。但它们**到底谁强谁弱**？「看图问答 85 分」意味着什么？**评估基准（benchmark）**就是多模态的「度量衡」：没有统一、可信的尺子，模型之间的比较就成了各说各话。<span class="marginnote">「评估基准」与第二篇第五课《跨模态表征的评价》的区别：那一课讲「评价方法」（指标怎么算），本课讲「评价体系」（用什么题、怎么组织、怎么对比）。<strong>方法讲「怎么量」，体系讲「量什么、跟谁比」</strong>。多模态评估从「单任务指标」走向「综合能力基准」，正是本课的主线。</span>这一课讲清现代多模态评估的架构、方法与陷阱。

**评估的重要性被严重低估**：它不只是「赛后记分」，而是**塑造模型发展的「指挥棒」**——论文按基准分数排名，团队按基准缺口改进，于是「基准考什么」直接决定「模型往哪个方向变强」。**一个设计不好的基准，会引导整个领域往错误的方向使劲**。这也解释了为什么评估方法论的讨论在多模态圈子里火药味十足。

## 1 从单任务到综合基准：三代评估

多模态评估经历了三次换代，代际划分看「基准怎么组织」：

**第一代：单任务基准。** COCO Captions（字幕）、VQA v2（问答）、Flickr30K（检索）——**一个基准测一个任务**。优点：指标简单、可比性强；缺点：**测不出「综合能力」**——模型可能字幕强、问答弱，一个分数看不出全貌。

**第二代：综合能力基准。** MMBench、MM-Vet、MMMU——**把多种能力（识别、OCR、常识、推理）打包进一个基准**，输出「能力雷达图」而非单一分数。**「分能力报告」取代「总分」**，是这一代的核心进步。

**第三代：对抗式 / 动态基准。** 用「模型能答对、但靠记忆/捷径」的题**主动攻击**模型的弱点（Winoground 的「极小对」、HaloQuest 的幻觉对抗、动态生成新题防「背题」）。**「评估与被评估的军备竞赛」**是本代特色。

三代演进的逻辑：**从「测单点」到「测全景」再到「测短板」**——评估越来越不满足于「报个分」，而要「画出能力边界」甚至「找出漏洞」。

具体的基准地图值得记住：**综合理解**用 MMBench、MM-Vet、MMMU、MMStar；**数学 + 视觉**用 MathVista、MathVerse；**OCR 与文档**用 OCRBench、DocVQA；**图表**用 ChartQA；**视频**用 Video-MME；**3D** 用 3D-QA 类。**每个基准都像一块「试纸」，测一种特定能力组合**——「多模态能力强不强」没有一个总答案，只有「在哪张试纸上显色」。



## 2 现代综合基准怎么设计

以 **MMBench 与 MM-Vet** 为例，看一个现代综合基准的内部结构：

**MMBench** 的做法是「**能力树 + 题目池**」：

1. 定义能力维度树：感知（细粒度识别、OCR）→ 认知（常识、推理、数学、语言）。
2. 每个维度生成一批题目（含图与问题），标注「该题测哪种能力」。
3. 评测时**分维度报分**，输出一张能力雷达图。

**MM-Vet** 则换了一个思路：按「**任务类型 + 能力要求**」交叉组织（如「OCR + 空间推理」的任务），并引入「**开放性回答的 LLM 判分**」——用 GPT-4 当「裁判」给模型答案打分，而不是死板的 exact match。

**两个关键设计**：

- **分能力分桶**：总分的意义远小于分桶分数——「总分 80」不如「识别 95、推理 65」信息量大。
- **难度分层**：题目分 easy/hard，hard 题测「真实能力」、easy 题测「基础功能」——**「hard 分数」是模型能力上限的探针**。

**MMMU（Massive Multi-discipline Multimodal Understanding）** 值得一提：它收集了大学级别的六大学科（艺术、商业、科学等）题目，含图 + 多选，被广泛用作「多模态模型天花板」的标尺。它的一个特点是**题目是「真实考试题」**而非人造题——**真实考题的分布更接近「人类水平的推理」，但也更接近「互联网可搜到」**，这也是它被质疑「易泄漏」的原因。**「越真实的基准越有价值，也越难防泄漏」——这是评估的固有张力**。

## 3 评测方法：从 exact match 到 LLM 判分

评估「怎么判答案对错」，也有三代演进：

| 方法 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **Exact Match** | 答案与参考答案完全一致 | 客观、零成本 | 表达差异被误杀（「狗」vs「狗狗」） |
| **软匹配 / 多参考** | 与多个参考答案部分匹配 | 宽容表达 | 参考答案覆盖有限 |
| **LLM 判分** | 让 LLM 当裁判评「对不对、好不好」 | 开放答案也能评 | 裁判自身有偏，成本高 |

**LLM 判分（LLM-as-judge）** 是 2023 年后的主流——因为多模态 LLM 的答案越来越开放（对话式、推理式），没有唯一标准答案。**「用大模型评大模型」的循环依赖**是它的核心争议：裁判会继承自己的偏好与盲区。

LLM 判分在实践里有几种加固手段：**① 多裁判投票**（多个 LLM 判分取多数）；**② 带 rubrics 判分**（给裁判明确的评分标准，减少主观）；**③ 判分与生成解耦**（用不同模型判分）。但根子上的问题仍在：**如果裁判模型弱于被评模型，它「看不懂」被评模型的复杂回答，分数就失真**。**「裁判必须比被评者强」是 LLM 判分的隐性前提**——当被评模型不断变强时，裁判也要不断换代，评估成本因此水涨船高。

## 4 公式解析：基准的稳定性度量

一个基准是否可信，先看它「稳不稳」。评测分数受**题目抽样**影响——同一模型跑同一基准，换一批抽样题，分数会波动。用置信区间量化：

$$
\text{score} \pm z_{\alpha/2} \sqrt{\frac{\text{score}(1-\text{score})}{N}}
$$

三步拆解：

- **第（1）步，读懂 $\text{score}$ 与 $N$**：$\text{score}$ 是该基准上的正确率（0–1），$N$ 是题目总数。公式给出「真值可能在的区间」。
- **第（2）步，读懂 $z_{\alpha/2}$**：95% 置信度取 $z \approx 1.96$。**区间宽度随 $N$ 的平方根收窄**——题目越多，分数越可信。
- **第（3）步，工程含义**：若某基准只有 100 题，$\text{score}=0.8$ 时误差约 $\pm 0.08$——**两个模型差 5 个点，在这个基准上可能是噪声**。「差几分算赢」要看置信区间是否重叠。**报告分数必须带「样本量」与「置信区间」**，否则「碾压 5 个点」可能只是「运气好」。

这个公式还解释了「为什么基准要越做越大」：MMMU 有 10500 题、MMBench 几千题——**题目越多，区间越窄，排名越可信**。但「题多」与「题新」又冲突：题目越多越容易从互联网泄漏。**「样本量」与「防泄漏」是现代基准设计的一对拔河**——动态生成新题是兼顾二者的折中，代价是「新旧基准分数不可直接比」。

## 5 评估的陷阱与失败模式

现代多模态评估有四个著名的坑：

**陷阱一：基准泄漏（contamination）。** 预训练数据包含基准题目——模型「背过答案」，分数虚高。**「基准与训练数据去重」是现代评估的必修课**，也是动态基准（不断出新题）兴起的原因。<span class="marginnote">一个著名案例：部分模型在 <strong>MMMU</strong> 上的高分被质疑部分来自「互联网上已有类似题目」——<strong>「背题」与「会做」在分数上无法区分</strong>，除非基准能证明「训练时没见过」。</span>

**陷阱二：语言先验过关。** 有些题「不看图也能答对」（语言分布泄漏）——模型靠「常识」蒙对，根本没看图。**对抗「语言先验」是基准设计的重要目标**（VQA v2 的配对问题、Winoground 的极小对都是为此而生）。

**陷阱三：判分偏置。** LLM 裁判会偏好「更长的答案」「更自信的措辞」甚至「按顺序更靠前的选项」。**「裁判偏置」让评估分数失真**——需要用「双盲」「交换选项」等设计缓解。

**陷阱四：以平均代全景。** 平均分隐藏长尾失败。「**缺口清单**」（第二篇第五课）再次适用：**分能力、分难度、分语言的分桶报告，才是诚实的评估**。

**陷阱五：忽视「答案开放性」的错配。** 用 exact match 评「开放式答案」的模型是「拿尺子量液体」——模型答得对但措辞不同，被误判错。**评测方法必须与任务开放性匹配**：判别式任务用客观匹配，生成式任务用 LLM 判分。**「评错方法」造成的分数失真，比「题目设计差」更常见**——这是评估工程里最容易被忽视的一环。

## 6 小结

- **多模态评估基准**是模型之间的「度量衡」；演进三代：**单任务 → 综合能力 → 对抗/动态**。
- 评估是「指挥棒」：**基准考什么，模型就往哪变强**——设计不好的基准会把领域引向错误方向。
- 现代综合基准（MMBench、MM-Vet）的核心设计：**能力树分桶 + 难度分层 + 开放答案 LLM 判分**。
- 基准地图：**MMMU/MMBench（综合）、MathVista（数学）、OCRBench（文档）、Video-MME（视频）**——每块试纸测一种能力组合。
- 评测方法三代：**Exact Match → 软匹配 → LLM 判分**；LLM 判分带来「以大评大」的循环依赖争议。
- 评测方法必须与任务开放性匹配：**判别式用客观匹配、生成式用 LLM 判分**——「评错方法」造成的失真最常见。
- 给读者的实操提醒：**拿到任何多模态分数，先问三个问题——题目量多少？是否与训练数据去重？判分是否客观？** 三问不过，分数打五折。
- 稳定性公式：$\text{score} \pm z\sqrt{\text{score}(1-\text{score})/N}$——**题目越少，分数越不可比**，报告必须带置信区间。
- 「样本量 vs 防泄漏」是基准设计的一对拔河——动态生成新题是折中，代价是「新旧分数不可直接比」。
- 四大陷阱：**基准泄漏、语言先验过关、判分偏置、以平均代全景**；外加第五个：**评测方法与答案开放性错配**。
- LLM 判分的前提是**「裁判必须比被评者强」**——裁判偏置让评估成本水涨船高。
- 与后续课程连接：评估能发现「模型在胡说」——下一步是**多模态安全与幻觉**：怎么让它少胡说、说错了怎么办。

**本课一句话**：评估基准是「多模态的体检报告」——好的报告不满足于「总评健康」，而要逐项标出「哪强哪弱、哪些指标不可信」。**会读报告，才知道模型能不能被信任**。

**承上启下**：评估发现了模型的问题，下一课就处理其中最严重的一个——**幻觉**。评估是「诊断」，安全是「治疗」。

在下一节，我们直面多模态最严重的问题：**多模态安全与幻觉**——模型「一本正经地胡说」怎么发生、怎么检测、怎么缓解。
