## 为什么感知要「长在身体上」

上一课的 Agent 动的是「鼠标和 API」，这一课让模型动「真实的机械臂、腿和轮子」。**具身多模态感知（embodied multimodal perception）**研究的是：当多模态模型**拥有物理身体**时，感知与决策会发生什么变化。答案是一条深刻的原理：**身体改变感知**——机器人在「伸手够杯子」时，它需要的不是「认出杯子」的通用能力，而是「杯子在什么 3D 位置、我的手臂怎么伸过去」的**行动导向感知**。<span class="marginnote">具身认知（embodied cognition）说：认知离不开身体与环境的互动。机器人学里这句哲学落成了工程现实——<strong>「感知」不再是为了「描述世界」，而是为了「在世界里行动」</strong>。同样的多模态模型，桌面端要「语义」，机器人端要「几何 + 语义」。</span>这一课讲清具身感知的特殊性、核心表征与代表性范式。

**本课与第五级《具身智能》专题的分工**：那个专题从机器人学出发（运动学、SLAM、控制、强化学习），本课从「多模态」出发，只讲「感知如何为行动服务」这一个切面。两个专题交叠处是 **VLA 模型**——它是多模态 LLM 与机器人学的交汇点，也是本课的核心主角。

## 1 具身感知与桌面感知的本质差别

把「看图说话」的模型搬到机器人上，会立刻暴露差距。一个直观例子：给多模态 LLM 看一张「桌上有杯子」的照片，它能完美描述；但让机器人去抓杯子，它还需要知道「杯子离我多近、朝哪个方向、该用多大的力」——**这些「行动所需的量」恰恰是桌面多模态不输出的**。差别有四层：

| 维度 | 桌面多模态 | 具身多模态 |
| --- | --- | --- |
| 空间 | 2D 像素 | **3D 场景**（深度、位姿） |
| 时间 | 静态/离线 | **实时流**（毫秒级响应） |
| 目标 | 理解/生成 | **行动决策**（抓哪、往哪走） |
| 观测来源 | 单张图/文本 | **多传感器**（相机 + 深度 + 力 + 关节角） |

**最关键的一条：具身感知是「行动导向」的**。机器人不需要「这张桌子的美学描述」，它需要「桌面上杯子的 3D 坐标 + 抓取位姿」。**同一个感知任务，桌面端输出「语义标签」，具身端输出「行动参数」**——这是「感知」与「感知-行动耦合」的分野。

多传感器是具身感知的另一大特色：一个机器人通常同时有 **RGB 相机（颜色/语义）、深度相机（几何）、IMU（姿态）、关节编码器（自身状态）、力传感器（接触）**。**「多模态」在具身语境里第一次真正名符其实**——桌面多模态的「模态」是图文音，机器人多模态是「视觉 + 触觉 + 本体感觉」。**触觉尤其独特**：它是机器人独有的、桌面模型没有的模态，用于「抓握力控制」「表面材质判断」——这正是第一篇《模态》里「异构性」的极致案例。

## 2 具身感知的核心问题

具身感知围绕三个「在哪里」展开：

**① 物体在哪里（3D 定位与姿态）。** 机器人要抓杯子，先要知道杯子的 3D 位置与朝向。这需要**深度感知**（深度相机/RGB-D）与**6D 姿态估计**（位置 + 旋转）。桌面视觉的「识别出杯子」在这里只是第一步。

**② 我自己在哪里（自定位与地图）。** 机器人要知道「自己在房间的哪个位置、朝哪个方向」。这是 **SLAM（同时定位与建图）** 的领域——多模态在这里意味着「视觉 + 里程计 + 惯性」融合。<span class="marginnote">SLAM 是机器人学的独立基础（见第五级《具身智能》专题），本课只强调它的多模态本质：<strong>单一的视觉或里程计都容易漂移，多传感器融合（视觉 + 惯性 + 轮速）才是可靠的来源</strong>——这正是「多模态冗余」原理在机器人学的经典应用。</span>

**③ 世界在哪里（场景理解与可交互性）。** 机器人要理解「桌面是可放东西的、窗户是不可穿越的、这个把手是可以拉的」。**场景的「可交互性（affordance）」比「类别」更重要**——机器人感知的输出，是「这里能不能做这个动作」。

「可交互性」是具身感知与桌面感知最深刻的差别：桌面模型问「这是什么」（类别），具身模型问「这能做什么」（affordance）。**「杯子是玻璃的」是类别，「杯子易碎、要轻拿」是 affordance**——后者直接决定抓取策略。现代 VLA 用语言模型的世界知识来推理 affordance：模型「知道」玻璃易碎，就会给抓取动作加「轻柔」约束。**「世界知识 → 动作约束」是多模态语言先验在机器人上最优雅的应用**。

## 3 视觉-语言-动作模型（VLA）

2023 年后，具身多模态的前沿是 **VLA（Vision-Language-Action）模型**：把多模态 LLM 直接接到**动作输出**，让「看图 + 理解指令 + 决定动作」在一个模型里完成。

```
观测 O（RGB 图 + 深度图）        指令 L（自然语言）
        │                            │
        ▼                            ▼
   [视觉编码器] ────────────┐   [文本编码]
                            ├──▶ [多模态 LLM] ──▶ [动作头] ──▶ A = (a_1, …, a_T)
                            │              │
                    （理解指令 + 推理）     └─ 动作 token：关节角度 / 末端位姿
```

VLA 的三个组件：

1. **视觉编码器**：看当前场景（RGB + 深度）。
2. **语言模型**：理解指令与推理。
3. **动作头**：输出动作——可以是**关节角度序列**（连续）、**末端位姿**（坐标），或**离散动作 token**。

**关键创新在「动作 token」**：像图像被离散成 token 一样，**把动作也离散化成 token，让 LLM 用「生成下一个动作 token」的方式来控制机器人**——这是「统一框架」（Any-to-Any）思想在机器人上的延伸：**「文字、图像、动作都是 token，一个 Transformer 全部生成」**。代表模型有 RT-2、OpenVLA 等。

RT-2 的训练思路尤其值得回味：**它直接用 RT-1（旧模型）采集的机器人数据 + 海量互联网图文数据，联合微调一个多模态 LLM**——「互联网知识」与「机器人经验」在同一权重里融合。**一个直接的好处是「语义泛化」**：模型在互联网上看过「红色杯子」，第一次见到红色杯子也能抓；看到「垃圾桶」能推断「垃圾该扔进去」。**「用互联网的常识补足机器人数据的稀疏」是 VLA 的核心红利**，也是具身智能搭大模型便车的缩影。

## 4 公式解析：从观测到动作的条件生成

VLA 的本质是一个「条件动作生成」模型。设当前观测 $O$（图像 + 深度），指令 $L$，机器人输出动作序列 $A = \{a_1, \dots, a_T\}$：

$$
P(A \mid O, L) = \prod_{t=1}^{T} P(a_t \mid O, L, a_{\\lt t})
$$

三步拆解：

- **第（1）步，读懂条件**：给定观测 $O$ 与指令 $L$，模型生成整个动作序列的概率。**注意「观测」是输入条件，不是输出**——模型「看着世界、听着指令」来生成动作。
- **第（2）步，看懂自回归分解**：$\prod$ 把联合概率拆成「每一步动作，在给定历史动作 $a_{\\lt t}$ 的条件下生成」——**与 LLM 生成文本、上一课 ReAct 的分解完全同构**。动作被当成「另一种语言」，逐 token 生成。
- **第（3）步，为什么可行**：这个公式说明 VLA 与多模态 LLM **共享同一个生成范式**——只要把动作 token 化，机器人的「行动」就变成了「生成」。**这就是「具身多模态」与「桌面多模态」统一在数学上的原因**：都是「条件 token 生成」，只是输出模态从文本换成了动作。

动作的「粒度」也有讲究：**末端位姿**（抓手该到哪、什么朝向）是「高层」动作，**关节角度**（每个电机转多少）是「低层」动作。VLA 通常输出**末端位姿**，把「关节怎么动」留给底层控制器——**「模型出意图、控制器出力度」的分层**，与上一课「大模型做大脑、经典控制做小脑」是同一句话。动作 token 化的关键，就是给「意图」找到合适的量化刻度。

## 5 具身多模态的挑战与易错点

**挑战一：数据稀缺与成本。** 机器人动作数据要靠**真实机器人操作**采集——慢、贵、危险。对策是**遥操作采集**（人遥控机器人，记录动作）与**仿真训练**（Sim-to-Real 迁移）。**「数据从哪来」是具身智能的头号瓶颈**，比桌面多模态严重得多。

**挑战二：Sim-to-Real 鸿沟。** 仿真里练的模型到真实世界会「失灵」——**sim-to-real gap**（材质、光照、物理差异）。多模态感知在这里有独特价值：**用视觉/语言先验弥补仿真不足**——模型「见过」真实世界（通过预训练），比纯仿真训练的模型迁移得更稳。

**挑战三：安全与物理约束。** 机器人的错误有**物理后果**——撞坏东西、伤到人。**动作输出必须过安全过滤**（速度限制、碰撞检测、急停），不能像文本模型那样「试错」。「**安全是具身多模态的硬约束，不是后处理**」——必须在架构与数据里内建。

**易错点一：把「2D 识别」当「具身感知」。** 在 2D 图上认出杯子，不等于机器人能抓杯子——还差深度、位姿、抓取点。「**识别 ≠ 可操作**」是具身感知的第一课。

具身模型的评测也自成体系——**在仿真器里考**：**Habitat**（室内导航）、**BEHAVIOR / AI2-THOR**（操作任务）、**RLBench**（机械臂操控）。评测指标是「**任务成功率**」（把杯子放对了没）而非「准确率」。**仿真评测的可重复性好，但要注意 sim-to-real 差距**——仿真里 90% 成功率，真实世界可能只有 30%。**「仿真分数只能横向比较仿真，不能直接预告真实表现」**，这是具身评测最容易被误读的地方。

**易错点二：忽视观测与动作的「频率匹配」。** 视觉模型慢（几百毫秒一帧），机器人控制快（几十毫秒一周期）。**感知跟不上控制，动作就是盲动**——「感知-动作频率鸿沟」需要异步流水线或预测补偿。<span class="marginnote">一个工程现实的数字：现代 VLA 推理一次约 0.5–2 秒，而机械臂抓取需要毫秒级控制——所以 VLA 通常用于<strong>「高层规划」（决定抓哪个、放哪）</strong>，底层用<strong>经典控制</strong>（PID、轨迹规划）执行。<strong>「大模型做大脑、经典控制做小脑」</strong>是当前具身系统的标准分工。</span>

## 6 小结

- **具身多模态感知**研究「模型拥有身体时感知如何改变」；核心转变是**「感知为了行动」而非「感知为了描述」**。
- 世界知识 → 动作约束：VLA 用语言先验推理 affordance（玻璃易碎 → 轻拿）——**多模态常识在机器人上的优雅应用**。
- 与桌面感知的四点差别：**3D vs 2D、实时 vs 离线、行动导向 vs 理解导向、多传感器 vs 单图**。
- 安全是硬约束不是后处理：**动作输出必须过安全过滤**（速度限制、碰撞检测、急停）。
- 三个「在哪里」：**物体在哪里（3D/6D 姿态）、我在哪里（SLAM）、世界在哪里（可交互性）**。
- 多传感器（视觉 + 深度 + 力 + 本体感觉）是具身多模态的标配；**触觉是机器人独有的模态**。
- **VLA（视觉-语言-动作）模型**把多模态 LLM 接上动作头，用「生成动作 token」控制机器人。
- 「识别 ≠ 可操作」是具身感知第一课；**affordance（可交互性）比类别更重要**。
- 核心公式：$P(A \mid O, L) = \prod_t P(a_t \mid O, L, a_{\\lt t})$——**动作生成与文本生成同构**。
- 感知-动作频率鸿沟：VLA 做高层规划、经典控制做低层执行——**「大模型做大脑、经典控制做小脑」**。
- 三大挑战：**数据稀缺、Sim-to-Real 鸿沟、安全与物理约束**。
- VLA 的红利：**互联网常识补足机器人数据稀疏**——「语义泛化」是具身搭大模型便车的缩影。
- 数据采集：**遥操作（人遥控记录）**与**仿真训练**是两大来源；遥操作慢、仿真有 gap，各有代价。
- 具身评测：仿真器（Habitat、RLBench）里考任务成功率——**仿真分数只能横向比仿真，不能预告真实表现**。
- 与第四级《多模态评估基准》的关系：具身评测是「任务成功率」逻辑的极端形态——**「做没做成」比「答没答对」更根本**。
- 与后续课程连接：具身模型到底行不行，必须有尺子量——下一课**多模态评估基准**。
- 收束：从桌面「看图说话」到具身「看图动手」，本专题的感知能力已走完「语义 → 行动」的完整光谱。

**本课一句话**：具身多模态把本专题的「感知」推到了极限——**当「看」直接连着「动」，感知就不再是「描述世界」，而是「在与世界的交互中不断校准的活地图」**。这也让「评估」变得比以往任何时候都关键：动得对不对，必须用真实世界的尺子来量。
