## 为什么下游任务是检验场

上一课搭好了视觉语言 Transformer 的骨架，但骨架不干活。真正让 VLM 有价值的是它**能干的三类活**：回答关于图的问题（**VQA**）、把图翻译成描述（**字幕**）、根据语言指出图中的对象（**指代**）。这三类任务合在一起，几乎覆盖了「人看图的全部语言行为」——而它们也恰好是对骨架三方面能力的检验：**VQA 检验理解+推理，字幕检验生成，指代检验定位**。<span class="marginnote">三类任务也是 VLM 发展的「试金石」：一个模型在 VQA 上分数高、在指代上翻车，说明它「会看但不认位置」——<strong>下游任务的分数分布，就是模型能力地图的等高线</strong>。</span>这一课逐个拆解，最后看它们如何统一进一个模型。

把这三类任务放进本专题的知识链里，位置很清楚：它们都是**「对齐好的表示」被任务化**的样子——对齐（第一篇）给了公共空间，VLT（上一篇）给了混合骨架，这三类任务就是骨架上的「输出形态」。**学这一课，本质是学会「把任意多模态输入组织成任务」的方法**，方法在手，新任务（如 3D 问答、医学影像问答）也能照葫芦画瓢。

## 1 VQA：看图回答

**视觉问答（Visual Question Answering, VQA）**：给定一张图 $I$ 与一个问题 $Q$，模型输出自然语言答案 $A$。

经典基准 VQA v2 有一个精巧设计：**配对问题（complementary questions）**——同一场景配两个答案相反的问题（「有香蕉吗」/「有苹果吗」），用来测试模型是真看图、还是靠语言先验蒙答案。**这是对抗「捷径学习」的基准级努力**，与《跨模态表征评价》的缺口检查一脉相承。

VQA 的难度梯度从「找颜色」到「数数量」到「推理关系」逐级上升：

| 问题类型 | 例子 | 需要的能力 |
| --- | --- | --- |
| 属性 | 「球的颜色？」 | 局部定位 + 属性识别 |
| 计数 | 「有几只鸟？」 | 多实例定位 + 计数 |
| 关系 | 「狗在谁左边？」 | 空间关系推理 |
| 常识 | 「为什么这人撑伞？」 | 常识 + 场景推理 |

**VQA 是「理解」任务**：答案往往很短（一个词或短语），价值在「看懂了再答」，不在「能写长句」。判别式 VLM 把 VQA 当分类（在候选答案里选），生成式 VLM 直接生成答案——后者的答案更开放，也更容易「自由发挥」。

VQA 的训练数据形态也决定了两种「答题」方式：**闭卷**（候选答案固定，训练成分类）与**开卷**（直接生成答案序列）。闭卷的答案空间是统计出来的高频答案集（约 3000 类）；开卷没有限制。**判别式强在「稳」——候选集内准确率高、不会胡说；生成式强在「活」——能答候选集外的开放式问题**。这也是为什么现代 VLM 几乎都走生成式：用户问的问题没有固定形态，闭卷的「候选集」兜不住。

另一个容易被忽视的点是 **VQA 的数据质量**：问题里有大量「复制题」（同一问题问不同图）、「先验题」（答案不问图也知道）。VQA v2 的配对问题就是专门稀释这两类的——**数据设计本身就是对抗「蒙」的武器**，这再一次呼应了「数据是模型的一部分」。

## 2 字幕：看图写话

**图像字幕（Image Captioning）**：给定一张图，生成一句描述整图内容的自然语言。

与 VQA 不同，字幕是**纯生成任务**：没有「问题」引导，模型要自主决定「图里什么值得说」。这带来两个难点：

1. **内容选择**：图里信息多，该说「人、狗、沙滩」还是「夕阳、剪影」？模型要建模「什么值得说」。
2. **语言组织**：把选中的内容组织成一句通顺、贴合图意的句子——涉及语言模型的全部生成能力。

字幕还有一个现实问题——**句子要多长、多具体**？COCO Captions 的参考答案是「一句话、约 8–12 词、描述核心内容」。但真实世界的图（广告、医学影像、设计稿）需要更长的描述。**字幕评价因此高度依赖「参考句的分布」**：参考句短，模型写长就被 BLEU 惩罚；参考句具体，模型写套话就得分低。**训练与评测都必须与「目标描述风格」对齐**——这是字幕任务区别于纯生成模型的工程现实。

字幕的评价指标是**文本生成指标**：**BLEU**（n-gram 重合）、**ROUGE**（召回导向）、**CIDEr**（tf-idf 加权）、**SPICE**（场景图语义匹配）。其中 **CIDEr 与 SPICE 比 BLEU 更能反映「说对了内容」**——BLEU 只看表面词重合，CIDEr 对「关键内容词」加权，SPICE 直接比「语义关系」是否正确。

**字幕与 VQA 的分工**：VQA 是「被问才答」，字幕是「主动叙述」。生成式 VLM 通常一个解码器同时干两件事——训练时用「问题-答案」和「图-描述」两种数据交替监督。

字幕有个「评价 vs 生成」的著名矛盾：**BLEU 高的句子不一定「好看」**——BLEU 偏爱「与参考答案字面重合」的套话，而人类更爱「具体、有细节、有惊喜」的描述。这导致模型被训练去「迎合指标」而非「描述真实」。**SPICE 的登场就是为了纠偏**：它把句子解析成场景图（对象、属性、关系），与参考答案的场景图比对——「说对了关系」比「词碰上了」更接近「真理解」。这一课给读者的启示是：**选评价指标时，先想清楚「什么才是这个任务的真目标」**。

## 3 指代：看图定位

**指代表达（Referring Expression）与指代分割（Referring Segmentation）**：给定一张图与一句描述（「站在左边穿红裙子的女人」），模型在图中**定位或分割**出所指对象。它是「自然语言 × 空间定位」的交叉点——**把「说」翻译成「指」**。

指代是三类任务里**最依赖「局部对齐」的**——它要求模型把描述中的每个限定词（位置、颜色、关系）精确锚定到图像区域：

- **指代定位（grounding）**：输出对象的**边界框**。
- **指代分割（segmentation）**：输出对象的**像素掩码**。
- **短语定位（phrase grounding）**：把描述里的短语与图像区域逐一对上。

指代任务的困难在于**描述的指代消解**：一句话里「她」「红裙子」「左边」每个词都指向同一对象的不同属性，模型必须把它们**聚合**成一个区域判断。RefCOCO、RefCOCO+、RefCOCOg 是标准基准，难度递增（是否允许「位置」词、句子长短）。

三个基准的难度设计很讲究：**RefCOCO** 允许位置词（「左边那个」），偏「定位」；**RefCOCO+** 禁止位置词，逼模型只靠外观（颜色、类别、关系）区分同类的不同实例——更难；**RefCOCOg** 的句子是完整自然语言（更长、更口语），最难。**难度阶梯的本质是「逐渐撤走辅助线索」**：撤掉位置词、加长句子，模型就不得不依赖更深的语义理解。这也是评测设计的经典思路：**想让模型更强，就逐步撤走捷径**。

## 4 公式解析：指代定位的定位头

指代定位可以形式化为「从视觉 token 里选出目标区域」。设视觉 token 为 $V = \{v_1, \dots, v_N\}$，描述编码为 $h$，定位头的输出是：

$$
\hat{b} = \text{MLP}\left(\sum_{i=1}^{N} w_i v_i\right), \qquad w = \text{softmax}(W_q h \cdot V^{\top})
$$

三步拆解：

- **第（1）步，读懂 $w$**：$w_i$ 是「描述 $h$ 对第 $i$ 个视觉 token 的注意力权重」——描述里「红裙子」「左边」等词的 query 会指向对应区域，权重汇聚到目标对象所在 token。
- **第（2）步，加权聚合**：用 $w$ 对视觉 token 加权求和，得到一个「描述所指向区域的聚合特征」——把分散在多个 patch 的目标信息集中起来。
- **第（3）步，MLP 出框**：把聚合特征过一个小 MLP，回归出边界框 $\hat{b} = (x, y, w, h)$。训练用 **L1 损失 + GIoU 损失**（前者管位置，后者管框的形状重叠度）。

**这个头的本质是「把 cross-attention 的注意力图翻译成坐标」**——模型其实早就在「看」那个区域了，定位头只是把「在看」变成「画出来」。这也是为什么指代任务被视为「对齐质量」的显式检验：**对齐不准，框就画偏**。

补充一个训练细节：**GIoU（Generalized IoU）** 比传统 IoU 更「温柔」——它把「框完全没重叠」的情况也从 0 变成负数，让梯度在「完全不搭边」时也有方向，避免训练卡死。**定位类任务的损失设计，核心是让「差得远」的预测也能获得有意义的梯度**——这与回归任务用 Huber loss 代替 L2 是同一个动机。

## 5 三类任务的统一：多任务学习

现代 VLM 不分别训练三个模型，而是**一个模型、多个任务头/多任务数据**：

- 判别式 VLM（ALBEF 系）：VQA 分类头 + ITM 头 + 检索头共享同一个融合编码器。
- 生成式 VLM（BLIP、LLaVA 系）：解码器统一承担 VQA 答案、字幕、指代描述三种生成——把任务都转成「文本输出」。

**统一的前提是任务可转译**：VQA 是「图 + 问题 → 答案」，字幕是「图 → 描述」，指代是「图 + 描述 → 框」——前两个天然是「文本到文本」的生成，可以合并；指代要出「框」，需要额外坐标头。**能统一的任务都统一到「输入多模态、输出语言」，不能统一的（坐标输出）就保留专用头**——这是 VLM 任务设计的实用原则。<span class="marginnote">LLaVA 这类模型把 VQA/字幕/指代<strong>全部写成对话</strong>：`<image>` 后接用户问题，模型回答案。指代也被转译成「描述对象并给出框」——<strong>一切任务都是对话</strong>，这正是 GPT-4V 的多模态对话形态。</span>

统一还带来一个工程红利：**多任务联合训练天然做「课程学习」**。任务难度不同（检索容易、VQA 中等、指代难），一起训时简单任务先收敛、提供稳定的梯度，难任务慢慢被带动。经验上，**把不同任务的数据按比例混入一个 batch，比分开训练三个模型省算力且往往更强**——因为共享表征在多个任务的约束下变得更通用。这也是「一个模型打天下」能赢过「三个专才」的原因之一。

## 6 小结

- **VLM 的三类核心下游任务**：VQA（看图回答）、字幕（看图写话）、指代（看图定位）。
- **VQA** 检验理解+推理，VQA v2 的配对问题专门对抗「语言先验蒙答案」。
- **字幕**检验生成，评价用 **BLEU/ROUGE/CIDEr/SPICE**——CIDEr 与 SPICE 更能反映「说对内容」；选指标前先想清任务真目标。
- 字幕质量高度依赖「参考句风格」：训练与评测都要对齐目标描述形态。
- **指代**检验局部对齐，是「对齐质量的显式检验」；定位头把注意力图翻译成坐标。
- GIoU 让「差得远」的框也有梯度方向——**定位任务损失设计的核心是让失败的预测可学习**。
- 三类任务**统一进一个模型**：能转译成「输出语言」的就统一到生成，必须输出坐标的保留专用头。
- 多任务联合训练有「课程学习」红利：**一个共享表征在多个任务约束下变得更通用**。
- **本课方法论**：学 VLM 任务不是背「VQA 怎么做、字幕怎么做」，而是掌握「**输入如何组织、输出如何解码、用什么损失与指标**」这套任务设计公式。
- VQA v2 的配对问题、RefCOCO 系列的难度阶梯，都是「用数据设计对抗捷径、逼出真理解」的范例。
- 三类任务输出形态：VQA 出短答、字幕出描述、指代出坐标——**输出形态决定任务头与损失**。
- 判别式 VLM 强在「稳」（候选集内不胡说），生成式强在「活」（开放答案）——现代 VLM 几乎全走生成式。
