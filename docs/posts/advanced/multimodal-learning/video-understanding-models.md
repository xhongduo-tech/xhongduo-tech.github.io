## 为什么视频是「另一个物种」

图像多模态讲了十几课，但视频不是「多帧图像」这么简单——**多了一个时间维，问题就换了一种难度**。判断「图里有什么」是空间理解；判断「这个人先做了什么、后做了什么、为什么做」是**时序理解**。前者是「看」，后者是「看懂一件事」。「看懂一件事」需要模型把「变化」本身当作对象来理解。<span class="marginnote">一个量级感受：一段 10 秒 30fps 的视频有 300 帧，每帧 576 个 patch token——<strong>约 17 万个视觉 token</strong>。这就是视频多模态的「数据墙」：模型不是「理解不了」，而是「塞不进去」。视频理解的核心，一半是建模时序，一半是打掉这堵数据墙。</span>这一课讲清「时序」给多模态带来的新问题，以及主流解法。

## 1 视频理解的问题族

视频理解不是单一任务，而是一族由「粒度」与「目标」组合出的任务：

| 任务 | 输入 | 输出 | 难度来源 |
| --- | --- | --- | --- |
| 视频分类 | 整段视频 | 类别（如「篮球比赛」） | 全局时序模式 |
| 时序动作定位 | 视频 + 动作类别 | 起止时间戳 | 对齐「何时发生」 |
| 视频字幕 | 视频 | 文字描述 | 选帧 + 生成 |
| 视频问答 | 视频 + 问题 | 答案 | 跨帧推理 |
| 视频检索 | 视频/文本 | 匹配项 | 语义对齐 + 时序 |

它们的共同底层能力是**时序建模（temporal modeling）**：让模型知道「第 5 秒发生了什么、与第 3 秒有什么关系」。**「运动」与「变化」是视频独有的信息**——挥手、奔跑、转身，单帧里没有，跨帧才有。

时序建模要回答的其实是三个递进的问题：**① 发生了什么**（动作识别）、**② 什么时候发生的**（时序定位）、**③ 为什么这样发展**（因果/意图推理）。三者的难度逐级上升——识别「有人在跑」只要空间+时间模式，判断「他跑是因为赶火车」需要场景常识。**视频理解的深度，就是在这三个问题上走多深**。而当前 Video-LLM 的强项在①②，③仍依赖 LLM 的常识补足（也因此容易幻觉）。

## 2 三种时序建模路线

给模型注入「时间感」，主流有三条路线：

**路线一：3D 卷积。** 把 2D 卷积的 kernel 扩成 3D（时间 × 高 × 宽），直接对「帧立方体」做卷积。C3D、SlowFast 是代表。**直觉：卷积同时在空间与时间上扫**，天然捕捉运动。缺点是 3D 卷积参数多、计算贵。

SlowFast 的一个设计值得记住：**双流不同帧率**——一条「慢流」低帧率看全局场景，一条「快流」高帧率看快速动作，两流融合。**「用不同时间分辨率分别看慢与快」**这个思想，比单流 3D 卷积更省算力且更准。它提示了一个通用原理：**视频里的「慢特征」（场景）与「快特征」（动作）应该被分开建模**，而不是混在一套卷积里。

**路线二：时空注意力（Video Transformer）。** 把视频切成「时空 patch」（每一帧的 patch 都带上时间索引），用注意力建模任意两 patch 的关系。TimeSformer 用「时间注意力 + 空间注意力」分步做，VideoMAE 用掩码自编码预训练。**直觉：注意力让「第 3 帧的手」直接关联「第 1 帧的球」**——长距离时序依赖比卷积强。

**路线三：帧采样 + 图像模型（最经济）。** 不专门设计时序结构，只**均匀采样 N 帧**，每帧用图像模型编码，再加一个「时序融合」头（平均池化、Transformer 或让 LLM 直接看帧序列）。**直觉：很多视频任务的答案，拆成 N 个「关键帧」就够**——不必每帧都建模。

帧采样路线最「轻」，但要防一个陷阱：**采样本身就在做「时序下采样」，采样策略就是模型的设计选择**。均匀采样「平均分配」时间注意力；随机采样破坏时序；**关键帧采样**（按帧间差异、显著性挑帧）则把「哪些时刻重要」的决策交给了采样器。Video-LLM 常把「关键帧选择」做成可学习的（让模型自己决定看哪几帧）——**「什么时候看」与「看什么」一样重要**。

**三者的取舍**：3D 卷积最「专」，时空注意力最强，帧采样最省。**「多细地建模时序」与「多大算力」直接挂钩**——这是视频模型的根本权衡。

## 3 视频多模态模型：把视频接进 LLM

2023 年后的视频理解主流，是把「视频接进 LLM」（Video-LLM）。骨架与图像多模态 LLM 相同，多了一个「如何从视频里取 token」的问题：

1. **帧采样**：均匀采样 N 帧（如 8/16/32 帧），每帧过视觉塔。
2. **token 压缩**：每帧的 patch token（576 个）太多，用 **Q-Former 或 perceiver 把每帧压成少量 token**（如 32 个），N 帧共 32N 个视觉 token。
3. **拼接进 LLM**：带时间戳的视觉 token + 文本 token 一起送进 LLM，自回归生成答案。

**关键设计：时间信息怎么保留**。两种做法：**① 在 token 里加「第几帧」的位置编码**（显式时间）；**② 让 LLM 自己从 token 顺序推断时间**（隐式）。前者更可控，后者更省——**「时间感知」是视频 LLM 相对图像 LLM 的唯一新增**。<span class="marginnote">一个工程现实：视频推理的延迟 = 视觉 token 数 × 单 token 成本，往往比图像慢一个量级。<strong>「先抽关键帧、再细读」</strong>（两段式）是控制延迟的常用手法——第一段选「值得看的帧」，第二段才让 LLM 细读。</span>

代表性 Video-LLM 能印证这条骨架：**Video-LLaMA** 用 Q-Former 分别压缩视觉与音频 token；**LLaMA-Video** 把「相邻帧的差异」也编码成 token（显式建模运动）；**Video-ChatGPT** 用「帧级描述 + 时序聚合」两步。它们共享「帧采样 → 压缩 → 接 LLM」的骨架，差异全在「**时间信息怎么编码**」——有的加时间位置编码、有的把帧间差异当特征、有的先让单帧模型写描述再让 LLM 串。**「时间」是视频 LLM 的兵家必争之地**。

## 4 公式解析：时空注意力

时空注意力的核心是让「时间」进入注意力计算。以 TimeSformer 的分离式注意力为例，对第 $t$ 帧、位置 $p$ 的 patch token $x_{t,p}$：

$$
\text{Attn}_{t,p} = \text{softmax}\left(\frac{q(x_{t,p}) \cdot K_{\text{time}}^{\top}}{\sqrt{d_k}}\right) V_{\text{time}}, \quad K_{\text{time}} = \{k(x_{t',p}) : t' \ne t\}
$$

三步拆解：

- **第（1）步，读懂 $K_{\text{time}}$**：它只包含**同一空间位置 $p$、不同时间帧 $t'$** 的 key——即「这个像素点在各个时刻的值」。**时间注意力让「这一帧的这里」去查「其他帧的这里」**——专门建模「同一个位置随时间怎么变」（正是运动）。
- **第（2）步，分离式的巧妙**：先做时间注意力（同位置跨帧），再做空间注意力（同帧跨位置），**两步拆开把「运动」与「结构」分开建模**——比全时空联合注意力的计算量小得多。
- **第（3）步，运动信号从哪来**：如果某一帧的某个 patch 与其他帧差异大，注意力权重会集中在那几个「变化的帧」——**模型自动学会了「盯住变化的地方」**。这就是「运动」被隐式编码的方式。

时间注意力之后还接一层**空间注意力**（同一帧内 patch 互查）——两步合起来，模型先知道「哪里在动」，再知道「动的东西周围是什么」。**分离式设计把「运动感知」与「结构感知」拆开，各司其职**，比混在一起的联合注意力更容易训练、也更省算力。这种「分而治之」的注意力设计，是视频 Transformer 对标准自注意力的最重要改造。

## 5 挑战与易错点

**挑战一：数据墙。** 视频数据量大、标注贵（给 10 秒视频标动作，比给一张图标类别贵几十倍）。主流对策：**用图像模型初始化 + 视频数据做时序微调**（让图像知识迁移到视频），以及**大规模视频自监督**（VideoMAE 式掩码重建）。

「图像初始化 + 时序微调」有一个值得强调的收益：**图像模型已经学会了「物体的外观」，视频微调只需补「物体怎么动」**——训练数据与算力需求都比从头训视频模型低一个量级。这也解释了为什么「帧采样 + 图像模型」路线如此流行：**它最大限度地复用了图像时代的遗产**。视频理解的每一次进步，几乎都站在「图像理解已经很强」这个前提上。

**挑战二：时间对齐。** 「动作发生在第几秒」需要帧级标注，昂贵且主观。时序动作定位常用「弱监督」（只给「视频里有这个动作」）降低标注成本——代价是模型要自己学会「找对时间」。

标准基准与评测也值得一提：**Kinetics-400/600**（动作分类）、**ActivityNet**（时序定位）、**MSR-VTT / VATEX**（视频字幕）、**MSVD-QA / TGIF-QA**（视频问答）。**每个基准都在「测」一个不同的时序能力**——动作分类测「识不识别得出」、时序定位测「找不找得对时间」、视频问答测「跨帧推理」。与图像一样，**分数必须配基准与输入帧数一起看**——同一个模型采 8 帧和采 64 帧，分数差几个点是常态。

**易错点一：把「均匀采样」当万能。** 均匀采样 N 帧会漏掉「关键时刻」——动作可能只在第 4 秒发生，采样的 8 帧恰好错过。**关键帧选择（saliency-based sampling）是视频理解的隐藏精度杠杆**。

**易错点二：忽视帧率与时长。** 30fps 的视频每隔 1 帧采样（每 1/15 秒一帧）与每隔 15 帧采样（每 0.5 秒一帧），看到的「动作粒度」完全不同——快速动作（挥手）需要高帧率，慢动作（体操）低帧率反而更稳。**采样策略要与动作时间尺度匹配**。<span class="marginnote">一个反直觉经验：<strong>不是采样越多越好</strong>。低帧率 + 长跨度（「每秒一帧、看全程」）对「理解视频在讲什么」往往比高帧率短跨度更有效——因为长跨度覆盖了叙事完整性。<strong>帧率管动作、跨度管叙事</strong>，两者要分开调。</span>

**易错点三：把视频 LLM 当「超强图像模型」。** 视频 LLM 的长处是「理解事件」，短处是「看细节」——压缩 token 后单帧细节远不如图像模型。**视频任务要「事件级」答案，图像任务要「像素级」答案，别混用**。

## 6 小结

- 视频不是「多帧图像」：**时序理解**是新增维度，运动与变化是视频独有的信息；一段视频动辄十几万视觉 token，「数据墙」是首要约束。
- 视频任务族：**分类、时序定位、字幕、问答、检索**，共享底层能力「时序建模」。
- 时序建模三问：**发生了什么（识别）→ 何时发生（定位）→ 为何发展（推理）**；Video-LLM 的强项在前两者。
- 时空注意力公式：时间注意力让「这一帧的位置」查「其他帧的同一位置」，**运动信号被隐式编码为注意力聚焦**。
- 三种时序建模路线：**3D 卷积、时空注意力、帧采样 + 图像模型**；算力与精度在此权衡。
- SlowFast 双流设计提示通用原理：**慢特征（场景）与快特征（动作）应分开建模**。
- Video-LLM = 帧采样 + token 压缩 + 接进 LLM；**时间信息保留方式（显式位置编码 vs 隐式顺序）是关键设计**。
- 视频多模态的「正确分工」：**大模型粗读事件、专用模型细读单帧**——与图像 LLM 的部署范式一致。
- 标准基准：Kinetics（分类）、ActivityNet（定位）、MSR-VTT/VATEX（字幕）、MSVD-QA（问答）——**每个基准测一个不同的时序能力**。
- 时空注意力公式拆解：时间注意力让「这一帧的位置」查「其他帧的同一位置」，自动盯住变化。
- 三个易错点：**均匀采样漏关键帧、采样率与动作尺度不匹配、把视频 LLM 当图像模型**。
- 数据墙对策：**图像初始化 + 时序微调**、**视频自监督掩码重建**。
- 帧采样路线里**「什么时候看」与「看什么」一样重要**——关键帧选择是可学习的设计维度。
- 「图像初始化 + 时序微调」大幅降低视频训练门槛——**视频理解站在图像理解的肩膀上**。
- 时间注意力「分而治之」：**先时间（哪里在动）后空间（动的东西是什么）**，是视频 Transformer 的关键改造。
- 与后续课程连接：视频之后是音频——**音频-文本模型**让多模态从「看」扩展到「听」。

**预演**：视频里除了画面还有声音——把音频也接进同一个多模态框架，就是下一课的**音频-文本模型**。

**本课一句话**：视频理解的核心矛盾是「**信息在时间轴上铺开，而模型必须在压缩中抓住关键**」——所有架构选择（3D 卷积、时空注意力、帧采样、token 压缩）都是这一矛盾的解法。抓住这个矛盾，任何视频模型都能看懂设计动机。
