## 为什么从内存复用与算子优化开始

前面的性能知识散落在各层：存储层级、融合、分块、剖析。这一节把它们**收拢成一套可操作的优化工具箱**，聚焦两个直接见效的战场：**内存复用**（让同一块显存被多个中间张量共享，压峰值内存）与**算子执行优化**（让每个算子在 AI Core 上跑得更快）。这两件事一个管「装得下」，一个管「跑得快」，是大模型能否在昇腾上落地的两个硬约束。<span class="marginnote">「内存复用」与「算子优化」对应大模型工程的两难：模型太大放不进卡（内存瓶颈）与算得不够快（计算瓶颈）。对照第四级《大模型部署》的显存优化（activation checkpointing、offload）与内核优化章节，昇腾的优化手法与其高度同源，只是硬件细节不同。</span>

## 1 内存复用：让中间张量共享家

图编译阶段，GE 为每个算子规划缓冲区。**内存复用**的原理很简单：两个中间张量如果**生命周期不重叠**（一个算完即弃、另一个才开始用），就可以共用同一块物理内存。

以一条链式计算为例：`A → B → C → D`，B 的输出是 C 的输入、C 算完 B 就没用了，那么 B 与 C 的输出可共享缓冲区。GE 在编译期分析所有中间张量的**生命周期区间**，做「区间着色」，把不冲突的张量分配到同一块内存——这就是图编译里的**内存规划（memory planning）**。<span class="marginnote">「生命周期分析 + 区间共享」是编译器的经典技术：寄存器分配、栈帧复用都用同一招。昇腾把它用在显存上，思路与 XLA 的 buffer assignment、PyTorch 的 caching allocator 完全一致——都是「错峰共享，消灭闲置」。</span>

内存复用带来两个直接收益：**峰值内存下降**（可容纳更大模型/更大 batch）与**分配次数减少**（少向运行时要内存）。它不需要改任何算子，是纯图编译期的红利。

**复用为什么能「白赚」？** 因为中间张量本来就是「用完即弃」的——它的生命周期由依赖关系天然约束。图编译器只需把这些生命周期画出来，找出互不重叠的「同居者」即可。**复用不改变任何计算结果，只改变数据的「住处」**，这是它被称为「白赚」优化的原因。

**辨析｜易错点：复用与并行冲突**。生命周期「不重叠」是前提。两个算子若可能并行执行（多流场景），其缓冲区不能复用，否则会互相覆盖。**内存复用计划必须与调度并行度保持一致**——这是图编译器里复用与并行之间永恒的张力。

**辨析｜易错点：复用不是「越省越好」**。过度复用会让生命周期分析变复杂、可并行度下降——有时「少复用一点」反而让多核并行更充分。复用的目标是「让峰值内存够用」，而不是「把内存压到极限」——压到极限往往以牺牲并行度为代价。

## 2 大模型场景的显存攻坚

对百亿/千亿参数模型，纯靠图级复用不够，还需要模型层面的显存策略：

**激活重计算（Activation Recomputation / Checkpointing）**：不保存所有中间激活，只在少数「检查点」保存，反向传播时重新计算被丢弃的激活。**用算力换显存**——训练时可显著压峰值显存，代价是重算增加的 FLOPs。

**梯度累加（Gradient Accumulation）**：小 batch 多步累加梯度，等效大 batch 效果，降低单步显存峰值。

**混合精度与内存压缩**：权重用 FP16/BF16 存储、优化器状态用低精度，甚至混合 FP32 主权重 + FP16 通信权重，把「住得最贵的」数据压缩。<span class="marginnote">激活重计算是训练侧「显存不够」的标准答案：显存不够就少存、反向再算。它与推理侧的 KV cache 优化（见第四级《大模型部署》）是同一个思想的两个分身——显存是稀缺资源，要么省着存，要么现用现算。</span>

这三个手段有一个共性：**都在「减少同时活着的数据量」**——重计算让激活「现用现算」、梯度累加让激活「分批存在」、低精度让数据「住得更小」。记不住三个名字没关系，记住它们共同的方向就够了：**凡是能减少「同一时刻必须存在的数据」，都能压峰值内存**。

## 3 算子执行的优化旋钮

算子内部怎么跑得更快，有一组可调的「旋钮」，按优先级排列：

**数据排布对齐**：确保算子的输入输出排布是芯片偏好（NC1HWC0 等），避免隐式 `TransData`。剖析报告里 `TransData` 算子扎堆，就是排布没对齐的信号。

**分块尺寸（Tiling）**：调整 tile 大小匹配 L0/UB 容量，让「搬一次数据算尽量多」。块太大装不下、块太小搬得勤——最优块是访存与计算的平衡点。

**多核并行**：把数据按 AI Core 数切分，让多个 Core 同时算。算子实现时通过 block 数控制并行度，剖析时看各 Core 是否都忙。

**搬运与计算重叠**：在算子内部用「先搬下一块、同时算当前块」的流水，把搬运时间藏进计算时间（呼应《同步/异步执行》的双流思想）。<span class="marginnote">这四个旋钮在 TIK 算子开发里都有对应的代码位置：排布决定 `tbe.xxx` 接口选型，tile 是循环分块参数，block 是核间切分，重叠是搬移与计算的指令排布。<strong>调优顺序建议：先排布，再 tiling，再核数，最后玩重叠</strong>——前三个对了，第四个才有意义。</span>

**辨析｜易错点：旋钮不是越大越好**。tile 增大提升命中率，但超过 L0/UB 容量就装不下；block 增多提升并行度，但核间通信与调度开销也涨。每个旋钮都有「甜点区」，找到它的方法是「单变量实验」——一次只动一个旋钮，用剖析报告对比前后。

## 4 公式解析：内存复用的峰值收益

内存复用的收益可以量化。设整图有 $k$ 个中间张量，各占 $s_i$ 字节，理想复用后峰值内存为

$$
M_{\text{峰值}} \le \sum_{i=1}^{k} s_i, \qquad \text{复用后} \to M'_{\text{峰值}} = \max_t \sum_{i \in \text{alive}(t)} s_i
$$

其中 $\text{alive}(t)$ 是时刻 $t$ 仍存活的中间张量集合。拆三步：

- **第一步，无复用**：每个中间张量独占一块，峰值 = 所有中间张量之和（最坏情况）。
- **第二步，有复用**：任一时刻只统计「还活着」的张量，峰值 = 各时刻存活集的最大总和。
- **第三步，看收益**：链式网络中存活集往往很小（前一个死了后一个才生），$M'_{\text{峰值}}$ 远小于 $\sum s_i$——**融合 + 复用叠加后，峰值常可压到最坏情况的几分之一**。

**这条式子的工程含义是：判断内存优化空间，就看「中间张量的存活重叠度」**。重叠度越低（链式网络），复用收益越大；分支多的网络（多路并行）存活集大，复用收益有限——此时该转向激活重计算等模型级手段。

**一个数字例子**：链式网络 `A → B → C`，任一时刻只有 1~2 个中间张量活着，峰值内存约为单张量的 2 倍，远小于三张量之和——这就是链式网络复用收益大的原因。反之，若四个分支同时计算、各自产出中间张量，存活集立刻变大，复用收益骤降。

## 5 内存复用的实践：从图级到模型级

图编译期的内存复用只是「第一层」，实际工程里要把三层复用叠加起来：

**图级复用（GE 自动）**：编译期生命周期分析，让不冲突的中间张量共享缓冲区——零成本、自动发生，是默认红利。

**框架级复用（显式配置）**：推理引擎、训练框架的缓存分配器，把「申请-释放」变成「借用-归还」，减少反复向运行时申请。

**模型级复用（算法设计）**：KV cache、激活重计算、梯度累加——从模型层面减少「必须同时活着」的数据量。

三层复用的关系是递进的：图级「消灭闲置」，框架级「消灭申请」，模型级「消灭存在」。**先保证图级复用生效，再谈框架与模型级**——这是内存优化的总顺序。<span class="marginnote">三层复用与 GPU 生态一一对应：XLA 的 buffer assignment（图级）、PyTorch 的 caching allocator（框架级）、activation checkpointing（模型级）。<strong>「复用」是内存优化的通用语言</strong>——在哪一层做，取决于资源由谁管理。</span>

**判断内存优化空间的通用方法**：用 msprof 看峰值内存曲线，找出「哪个时刻、哪些张量同时活着」。若峰值被少数几个大张量顶高，说明图级复用没吃透；若峰值来自「模型本身必须同时存在的权重」，才轮到模型级手段。**先定位存活集，再选优化手段**——这和「先诊断，后用药」是同一个道理。

## 6 核心术语速查表

本节的术语集中在「内存与算子优化」语境，整理如下：

| 术语 | 含义 |
| --- | --- |
| 内存复用 | 生命周期不重叠的中间张量共享同一块物理内存 |
| 生命周期 | 张量从创建到不再被引用的时间区间 |
| 内存规划 | 图编译期分析生命周期并分配缓冲区的过程 |
| 激活重计算 | 丢弃中间激活、反向传播时重新计算，以算力换显存 |
| 梯度累加 | 小 batch 多步累加梯度，等效大 batch 效果 |
| 混合精度 | 权重/梯度用 FP16/BF16 存储，降低显存占用 |
| 排布对齐 | 输入输出排布匹配芯片偏好，避免隐式转置 |
| 分块尺寸 | tile 大小，决定一次搬入缓冲的数据量 |
| 多核并行 | 把数据按 AI Core 数切分，多核同时计算 |
| 搬运/计算重叠 | 先搬下一块、同时算当前块的流水化执行 |
| 峰值内存 | 运行过程设备内存占用最大值，复用直接压低它 |
| 存活集 | 某时刻仍被引用的中间张量集合，决定复用收益 |

## 7 小结

- **内存复用**通过生命周期分析让不重叠的中间张量共享缓冲区，压峰值显存、减少分配次数。
- 复用的前提是**生命周期不重叠**；与多流并行存在张力，复用计划必须与调度一致。
- 大模型显存三招：**激活重计算（算力换显存）、梯度累加（小 batch 等效大 batch）、混合精度压缩**。
- 算子优化四旋钮，按序调节：**排布对齐 → 分块尺寸 → 多核并行 → 搬运/计算重叠**。
- 峰值内存 $M'_{\text{峰值}}=\max_t\sum_{i\in\text{alive}(t)}s_i$：**存活重叠度越低，复用收益越大**。
- 三层复用递进：**图级自动、框架级显式、模型级算法**；先定位存活集，再选手段。

在下一节，我们将把这一套优化手法放到最大规模的场景——学 **大模型训练在昇腾平台的工程实践**，从并行策略到显存账本到调优闭环，完成本专题的最后收束。
