## 为什么从达芬奇架构开始

「从极限到大模型」走到第四级，我们已经在 GPU 生态里见过一套成熟答案：NVIDIA 用 CUDA + Tensor Core 统治了训练与推理。但 AI 硬件并非只有一条路。华为昇腾给出了另一套自成体系的设计——**达芬奇（DaVinci）架构**。它选择了一条与「通用 GPU + 软件适配」相反的路：把 AI 计算中最常出现的模式（矩阵乘、逐元素、控制流）**直接做成硬件单元**，让芯片为算子而设计，而不是算子迁就芯片。理解这套架构，是进入 CANN（Compute Architecture for Neural Networks，华为昇腾计算架构）全部软件能力的前提——因为 CANN 的每一层，都是在为这颗芯片的硬件形态服务。<span class="marginnote">达芬奇架构的命名取意于文艺复兴巨匠列奥纳多 · 达 · 芬奇——华为希望这颗 AI 芯片像达 · 芬奇一样在多个领域都「专而精」。昇腾（Ascend）则是「上升、攀登」之意，暗示面向智能时代的爬坡。命名背后是华为把 AI 芯片当作完整体系来建设的意图。</span>

## 1 达芬奇架构的定位：AI 专用处理器

要理解昇腾，先理解它的对手面。GPU 是「图形处理器转职做计算」：它假设你什么都能算，用海量通用核心堆吞吐。而昇腾选择**专用**：先统计 AI 工作负载里计算形态的分布——矩阵乘占大头、逐元素运算次之、少量控制流——然后针对这些形态设计专门的硬件单元，砍掉通用计算里用不到的部分。

由此达芬奇架构确立了两个核心计算部件，分工明确：

**AI Core（人工智能计算核心）**：承担绝大多数密集计算。它内部再细分矩阵、向量、标量三个执行单元，专门消化「矩阵乘 + 逐元素 + 控制流」这三类负载——这就是下一节《AI Core 计算单元》的主角。

**AI CPU（人工智能中央处理器）**：一个通用处理器核心，负责 AI Core 不擅长或不便做的部分——复杂的控制逻辑、少数标量运算、算子调度、以及「像字符串处理、数据预处理」这类非张量计算。<span class="marginnote">「AI Core 算张量、AI CPU 管杂事」的分工，与 NVIDIA 的「Tensor Core + CUDA Core + 控制逻辑」在哲学上同构，只是昇腾把矩阵、向量、标量拆成了三个独立单元，比 GPU 的「一组 CUDA Core 什么都干」更贴合算子形态。对照第四级《AI 硬件：NVIDIA H100/Hopper》中 SM 的内部结构阅读，两种「分诊台」设计立刻可见。</span>

## 2 一颗昇腾芯片的组成

把昇腾 910 这类训练芯片摊开，除 AI Core 与 AI CPU 外，还有几块关键拼图：

**多核阵列**：一颗昇腾 910 上集成数十个 AI Core（官方口径为 32 个 AI Core 的核心集群），配合片上共享缓存与总线，构成「一群 AI Core 并行干活」的格局。

**专用计算模块**：部分昇腾芯片集成了专门加速特定操作的模块——例如图像预处理的 AIPP 模块（本专题第 2 篇会讲）、视频编解码模块等。它们在「搬进 AI Core 之前」就把数据加工好，减少核心的额外负担。

**片内总线与缓存层级**：AI Core 之间、AI Core 与外部内存之间靠高速总线互连，并配有一套 L0/L1/L2 的片上缓存层级——这是本专题第 3 篇《昇腾芯片存储层级》要展开的主题。<span class="marginnote">昇腾芯片家族有明确的分工：昇腾 310 主打边缘推理，功耗仅个位数瓦级；昇腾 910 主打训练与推理，是「算力担当」。理解「一个架构、多档产品」的路线，才能看懂为什么同一套 CANN 软件栈能同时服务边缘盒子与训练集群。</span>

## 3 软件怎么指挥硬件：从算子到指令

硬件造好了，软件如何驱动？昇腾给出了一条「算子 → 指令」的下钻链条，这也是 CANN 全栈的骨架：

1. **应用/框架层**：MindSpore、PyTorch（经 torch_npu）等框架描述「要算什么」。
2. **算子层**：算子库（或自定义算子）把「算什么」翻译成「按 AI Core 的形态怎么算」——哪个用 Cube、哪个用 Vector、数据怎么分块。
3. **指令层**：编译器把算子翻译成 AI Core 的指令流（矩阵指令、向量指令、标量指令），送入指令缓冲执行。

这条链条里，**软件工程师真正要打交道的，是算子层**——一旦掌握「我的算子会被拆成 Cube/Vector/Scalar 三类负载」的心智模型，CANN 的算子开发、图优化、性能剖析就都变得可预测了。<span class="marginnote">这条「框架 → 算子 → 指令」下钻链，与 CUDA 生态的「PyTorch → cuDNN/cuBLAS → SASS 指令」完全同构。学习昇腾最好的方法之一，就是对照你已经熟悉的 CUDA 生态做「翻译练习」——每个概念都能找到对应物，只是名字和细节不同。</span>

## 4 公式解析：一张芯片的算力从哪来

「多少 TFLOPS」是芯片最显眼的数字，它的来源其实是一道乘法。设一颗芯片有 $N$ 个 AI Core、每个 AI Core 每周期完成 $M$ 次乘加（MAC）、主频为 $f$，则其矩阵乘算力（FP16 下，一次乘加计 2 次浮点运算）为

$$
\text{FLOPS} = N \times M \times 2 \times f
$$

拆三步看：

- **第一步，单 Core 吞吐**：一个 AI Core 每周期做 $M$ 次 MAC（昇腾为 16×16×16 = 4096），即每周期 4096 次乘加。
- **第二步，多 Core 叠加**：$N$ 个 AI Core 并行，吞吐放大 $N$ 倍。
- **第三步，乘上主频**：每秒执行 $f$ 个周期，换算成每秒浮点运算数 FLOPS；FP16 下每次 MAC 折算 2 FLOPS（1 乘 + 1 加）。

以昇腾 910 为例，官方标称 FP16 算力约 256 TFLOPS、INT8 约 512 TOPS——把官方数字代回上式，恰好能反推出「核心数 × 单核 MAC × 主频」的量级。**读芯片规格表时，看 FLOPS 前先看它对应什么精度、什么操作**：矩阵乘算力永远高于逐元素算力，FP16 永远高于 FP32——「算力」离开精度与操作类型就是空话。

## 5 从架构到 CANN：硬件给软件留下的「接口」

达芬奇架构的每一处设计，都在软件栈里留下对应物。把这些对应关系记下来，等于提前拿到 CANN 的藏宝图：

| 硬件设计 | 对应的软件接口/工具 | 本专题章节 |
| --- | --- | --- |
| AI Core（Cube/Vector/Scalar） | TBE / Ascend C 算子开发 | 算子开发篇 |
| 多级片上缓存（L0/L1/L2/UB） | 分块、内存复用、排布优化 | 存储层级篇 |
| AIPP 图像模块 | AIPP 配置 | 第 2 篇 |
| 多卡互连（HCCS/RoCE） | HCCL 集合通信 | 通信篇 |
| 硬件计数器 | msprof 剖析 | 剖析篇 |

这张表的阅读要领：**硬件决定了「能力边界」，CANN 决定「如何触达这个边界」**。所有优化话题——融合、分块、复用、拓扑——本质都是在问同一个问题：如何让算子与这颗芯片的硬件形态对齐。

## 6 昇腾芯片家族与代际演进

达芬奇架构不是静态的，它随昇腾芯片一路演进。理解「一个架构、多档产品、持续演进」，才能看懂为什么同一条 CANN 软件栈能覆盖从边缘盒子到训练集群的广阔区间：

| 世代 | 代表芯片 | 定位 | 特征 |
| --- | --- | --- | --- |
| 第一代 | Ascend 310 / 910 | 边缘推理 / 训练推理 | 确立 AI Core 三单元与 16×16 Cube |
| 第二代 | Ascend 910B 等 | 训练主力 | 算力与芯片间互联增强，支持更大模型 |
| 后续代际 | Ascend 9xx 系列 | 大模型训练与推理 | 更强多卡互连、更大高带宽显存 |

演进的主线有两条：**算力向上**——Cube 阵列更强、AI Core 更多、主频更高，单卡算力一路走高；**互联向上**——芯片间互连（HCCS）与跨机网络（RoCE）的能力持续增强，多卡协同的规模越来越大。第二条主线尤其重要：**它是大模型时代「单卡装不下、靠集群堆起来」的硬件本钱**，也为本专题后面的 HCCL 集合通信埋下了伏笔。<span class="marginnote">对照 NVIDIA 的代际演进（Volta → Turing → Ampere → Hopper → Blackwell），昇腾的演进脉络惊人相似：Tensor Core 尺寸变大、NVLink 带宽变高、显存容量变大。<strong>「算力 + 互联」双主线是 AI 芯片演进的通用规律</strong>——读任何一家 AI 芯片的 roadmap，盯住这两条线就不会迷失。</span>

对开发者来说，代际演进带来的直接后果是：**同一套 CANN 知识在不同代际芯片上几乎全部复用**——AI Core 的三单元、存储层级、AscendCL、GE、HCCL 都是「同一套底层、不同规模」。这也是本专题敢于用「CANN 计算架构」统摄全部章节的原因：你学的是软件栈的「不变骨架」，而不是某颗芯片的「一次性说明」。

## 8 小结

- **达芬奇架构是 AI 专用处理器**：按「矩阵乘 + 逐元素 + 控制流」三类负载设计硬件单元，砍掉通用计算冗余。
- 芯片由 **AI Core（密集计算）+ AI CPU（通用控制）** 双核心构成，另有 AIPP 等专用模块与多级片上缓存。
- 昇腾产品线分两档：**310 边缘推理**、**910 训练/推理**，同一架构、不同规模。
- 软件通过「**框架 → 算子 → 指令**」链条驱动硬件；CANN 的全部能力都是「触达硬件形态」的手段。
- 算力公式 $\text{FLOPS} = N \times M \times 2 \times f$：读规格表先看精度与操作类型。
