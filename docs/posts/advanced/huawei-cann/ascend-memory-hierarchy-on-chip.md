## 为什么从存储层级开始

上一节我们看到 Cube 单元每周期要吞下 16×16×16 次乘加，也就是每个周期要喂进 256 个输入数。问题立刻来了：**数据从哪里来？** 如果每个数都要从外存（DDR/HBM）读取，Cube 的速度再快也只能干等——访存延迟会掐死全部算力。达芬奇架构的答案，是一套精心设计的**多级存储层级**：让「最贵的计算」配上「最近的存储」，把数据尽量留在芯片内。CANN 的许多优化（数据搬移指令、内存复用、算子融合）本质上都是在操纵这套层级，所以它是理解 CANN 一切性能话题的前提。<span class="marginnote">这套「寄存器→缓存→主存」的层级思想与计算机组成原理的 Cache 一致，可对照第三级《计算机组成原理》存储器层次章节；区别在于 AI 芯片把层级设计得更加显式——程序要主动管理往哪一层搬数据，而不是像通用 CPU 那样靠硬件缓存自动命中。</span>

## 1 从全局内存到 AI Core 的六级旅程

昇腾芯片的数据通路，可以抽象成一条「从大到小、越来越快、越来越近」的链条：

| 层级 | 位置 | 典型角色 |
| --- | --- | --- |
| 全局内存（Global Memory） | 片外 DDR / HBM | 存放模型权重、输入输出张量 |
| L2 Cache | 片上共享 | 多 AI Core 共享的二级缓存，缓冲全局内存到 Core 的数据 |
| L1 Buffer | 片上 | AI Core 的中间缓存，衔接 L2 与 L0 |
| L0 Buffer | 片上 | Cube 的直接输入输出缓冲（L0A / L0B / L0C） |
| 统一缓冲（Unified Buffer, UB） | 片上 | Vector 单元的直接数据区 |
| 寄存器 / 标量缓冲 | AI Core 内 | Scalar 单元与地址计算用 |

这张表从左到右，容量逐级缩小、带宽逐级升高、延迟逐级降低。**性能优化的黄金法则是：让数据尽可能停在靠右（靠近计算）的层级，只在必要时才向全局内存搬运一次。**

## 2 L0 Buffer：Cube 的专属餐盘

L0 Buffer 是 Cube 单元的**专用输入输出缓冲**，按用途细分为三个区域：

**L0A**：存放矩阵乘中 $A$ 矩阵的分块；
**L0B**：存放 $B$ 矩阵的分块；
- **L0C**：存放累加结果的 $C$ 矩阵分块（初始为旧 $C$，逐块累加后写回）。

一次矩阵乘的执行节奏是：把 $A$、$B$ 分块搬入 L0A/L0B → Cube 每周期从这两个缓冲读 16×16 数据做乘累加、结果写入 L0C → 一块算完，L0C 写回 UB 或全局内存，再搬入下一块。<span class="marginnote">L0 的容量有限（数十 KB 量级），所以 GEMM 分块策略（tiling）的每一个选择都直接决定 L0 命中率。这也是为什么 TBE 算子开发里最常调整的参数就是 tile 尺寸——它本质上是「往 Cube 餐盘里怎么摆菜」的问题。</span>

## 3 统一缓冲与 Vector 的数据生活

与 Cube 的 L0 对应，**统一缓冲（Unified Buffer）** 是 Vector 单元的直接数据区。Vector 逐元素运算的读、写都发生在 UB 内：数据先由搬移指令从全局内存或 L2 搬进 UB，Vector 在 UB 上完成运算，再把结果搬走。

UB 之所以叫「统一」，是因为它还兼任**数据中转站**：Cube 的结果（在 L0C 中）要先搬到 UB，才能由 Vector 做后续处理（比如激活、归一化）；反过来，Vector 处理完的数据也可能再送回 L0 供 Cube 使用。算子与算子之间、单元与单元之间的数据交接，大多经由 UB 完成。<span class="marginnote">「L0C → UB → Vector 处理 → UB → 全局内存」是昇腾上一个标准算子（如 Conv + ReLU 融合）的完整数据流。记住这条链，后面读 TBE 代码、做算子融合时就有一条主线可循。</span>

## 4 片上缓存与多核共享

L1 与 L2 位于多个 AI Core 之间。**L2 Cache 被所有 AI Core 共享**，用来缓冲「被多个 Core 反复使用」的数据——比如卷积里被多个输出通道共用的输入特征图；L1 则是单 Core 的中间缓存，衔接 L2 与 L0。

多核共享缓存带来一个调度问题：**如果两个 AI Core 同时读写同一块 L2 数据，如何保证一致性？** 达芬奇架构通过「数据在多核间显式同步」来管理，CANN 的图引擎在生成多核任务时会插入同步点。这解释了后面会学到的现象：算子的「核间通信开销」往往比「计算开销」更值得优化。

## 5 公式解析：访存受限的判据

判断一个算子「卡在计算还是卡在搬运」，是昇腾性能调优的第一步。设某算子每计算一次需要搬运 $B_w$ 字节、做 $F$ 次浮点运算，定义

$$
\text{计算强度（Arithmetic Intensity）} = \frac{F}{B_w}
$$

它与硬件能力比较后决定瓶颈位置：

- 若 $\dfrac{F}{B_w} \gg \dfrac{\text{峰值算力}}{\text{峰值带宽}}$，则**计算受限（compute-bound）**，优化应聚焦 Cube 利用率；
- 若 $\dfrac{F}{B_w} \ll \dfrac{\text{峰值算力}}{\text{峰值带宽}}$，则**访存受限（memory-bound）**，优化应聚焦减少数据搬移、提高存储层级命中率。

拆解这条式子：$F$ 越大、$B_w$ 越小，计算强度越高，硬件越「饿」算力；反之则「饿」带宽。**激活函数（计算强度低）天然访存受限，矩阵乘（计算强度高）天然计算受限**——所以达芬奇把激活交给 Vector、把矩阵乘交给 Cube，本质上是在按计算强度分配硬件。<span class="marginnote">这与 GPU 上「Roof-line 模型」的判断完全一致。昇腾的 msprof 剖析报告会直接给出算子的「利用率」与「带宽占用率」，对照这两个数字与本节判据，就能快速定位优化方向。</span>

## 6 核心术语速查表

本节的术语集中在「存储层级」语境，整理如下：

| 术语 | 含义 |
| --- | --- |
| 全局内存 | 片外 DDR/HBM，存放权重与输入输出张量 |
| L2 Cache | 多 AI Core 共享的片上二级缓存 |
| L1 Buffer | 单 AI Core 的中间缓存，衔接 L2 与 L0 |
| L0 Buffer | Cube 的直接输入输出缓冲（L0A/L0B/L0C） |
| 统一缓冲 | Vector 单元的直接数据区，也是中转站 |
| 计算强度 | 每次访存对应的计算量，判断瓶颈的指标 |
| 访存受限 | 带宽不足，数据供给慢于计算 |
| 计算受限 | 算力不足，计算慢于数据供给 |
| 分块策略 | 决定 L0 命中率的 GEMM 切块方式 |
| 数据搬移 | 数据在存储层级间的移动，优化主目标 |
| 缓存命中 | 数据在更近层级直接取得，免去远距访问 |
| 峰值带宽 | 硬件能提供的最大数据吞吐率 |

## 7 小结

- 昇腾存储层级 = 全局内存 → L2 → L1 → L0 → 统一缓冲 → 寄存器，**越靠近计算越贵越快**。
- **L0 Buffer** 是 Cube 的专用输入输出缓冲（L0A/L0B/L0C），GEMM 分块策略决定其命中率。
- **统一缓冲（UB）** 是 Vector 的直接数据区，也是单元间数据交接的中转站。
- **L2 被多核共享**，多核调度需要显式同步，核间通信开销常是优化重点。
- 用**计算强度** $\dfrac{F}{B_w}$
