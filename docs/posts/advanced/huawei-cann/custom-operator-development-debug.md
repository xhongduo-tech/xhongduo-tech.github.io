## 为什么从自定义算子全流程开始

前三节我们分别看了 TBE 风格、算子原型、注册与自动生成——它们是「零件」。这一节把它们拧成一台机器：**从一个自定义算子（以最简单的逐元素算子为例）从模板生成到设备上跑通并验准的完整流程**。昇腾算子开发最大的门槛不在「写代码」，而在「调试验证」：代码跑通了不代表算对了，算对了不代表性能达标。这一节把「正确性」这条线的完整方法论给你，让你第一次写算子就能走完全程。<span class="marginnote">算子开发调试的核心矛盾是「看不见」：AI Core 上没有标准输出流，算子的中间结果在设备内存里，只能靠专门的 dump/比对机制看。这与 CUDA 内核调试要依赖 `cuda-gdb`/内存拷贝如出一辙——「睁眼」的手段不同，但「先验逻辑再验数值」的思路完全一致。</span>

## 1 完整流程：从模板到跑通

以开发一个逐元素算子（例如把输入每个元素加一个常数）为例，完整流程分六步：

1. **生成工程**：用自动生成工具生成算子工程骨架，填入算子名与输入输出规格。
2. **填原型**：在生成的原型文件里补全形状推导（输出形状 = 输入形状）与类型支持。
3. **写实现**：用 TIK 或 DSL 写 kernel——搬入数据、逐元素计算、写回。
4. **编译注册**：编译算子，生成二进制，注册进 `oplib`。
5. **单算子验证**：用官方提供的算子验证工具（如 `msopst` 系列的算子测试工具，或编写 AscendCL 单算子调用代码）输入已知数据，检查输出。
6. **集成验证**：把算子放进真实模型（ONNX 里替换节点，或用 MindSpore 自定义算子机制），跑完整推理对比结果。

前四步是把算子「造出来」，后两步是把它「验明白」。**大多数人卡在第 5 步**——单算子验证是错误定位的主战场：它把「整图报错」缩小为「这一个算子对不对」，隔离度最高。<span class="marginnote">「先隔离到单算子，再逐层放大」是昇腾算子调试的标准战术：先在最小单元上确认数值正确，再放进算子库、再进模型。跳过单算子验证直接上模型，一旦报错，错误可能来自形状推导、排布转换、调用约定任何一个环节——排查成本成倍上升。</span>

**辨析｜易错点：单算子验证要「喂已知答案」**。单算子验证的价值在于「输入已知、输出可预测」——喂随机数可以，但要同时喂几个「手工可算」的边界输入（全 0、全 1、小整数），这样输出一眼能看出对错，不必完全依赖比对脚本。

## 2 数值正确性的三重检查

算子「跑通」≠「算对」。数值正确性要过三关，按成本从低到高：

**第一关：形状与类型**。输出张量的形状、数据类型是否与原型推导一致。很多「数值不对」实为「形状不对」——先打印输出 shape 与 dtype 核对。

**第二关：边界值**。用全 0、全 1、正负大数、特殊值（NaN、Inf、极小数）等输入测试，检查算子对边界条件的处理。逐元素算子特别要测**末块不足一个 tile** 的情况——分块循环的边界处理是 TIK 错误的高发区。<span class="marginnote">「末块边界」是昇腾算子调试里最经典的坑：当 $N$ 不是 tile 大小 $B$ 的整数倍时，最后一块只有 $N \bmod B$ 个有效元素，若代码不处理剩余区，就会读越界或算入脏数据。测试时务必覆盖「$N$ 恰为 $B$ 的倍数」与「$N$ 不为 $B$ 的倍数」两种情况。</span>

**第三关：随机数比对**。生成大量随机输入，把算子输出与**标准实现**（CPU 上的 NumPy 实现、或框架里的同功能算子）逐元素比对，统计最大绝对误差与相对误差。误差在容差范围内才算通过。

**三重检查的次序不能乱**：形状错了，边界值测出的「错」是假错；边界值错了，随机数比对的意义就打折。按「形状 → 边界 → 随机」逐层过关，每一关都在为下一关建立可信的前提。

## 3 精度比对与数据 dump

昇腾提供了系统化的**精度比对（accuracy compare）**能力，把「随机数比对」做成工具化流程：

**dump**：把算子输入/输出（甚至中间张量）从设备内存导出到文件——昇腾的 dump 机制可按图/算子粒度配置，导出成可读格式。
**比对**：用官方比对工具（或自定义脚本）把 dump 结果与标准结果逐元素比对，生成误差报告（最大误差、平均误差、余弦相似度等）。

用法上的要点：**dump 要小而精**——全量 dump 整张图会产生海量文件，先缩小到目标算子、目标张量，定位后再逐步放大。<span class="marginnote">dump 好比在设备里「装摄像头」：想看清哪个环节就装哪个环节，但别一次全装上——文件爆炸会让分析瘫痪。先隔离目标，再定点 dump，是昇腾调参的基本节奏。</span>

**dump 的粒度选择是效率关键**：整图 dump 会产生海量文件，先按算子粒度定位、再按张量粒度细查、最后按迭代 step 收敛。昇腾的 dump 配置支持按算子名、按图、按 step 三种维度裁剪——会用这个裁剪，等于给调试装上了「定点放大的镜头」。

浮点误差还有一个常被误解的点：**FP16 算子与 FP32 标准实现的误差是「正常」的**，只要在容差内就不算 bug。判断「算法错」与「精度损失」的分界，正是精度比对工具要给出误差报告的原因。

## 4 公式解析：精度比对的误差判据

精度比对最终要回答「误差是否可接受」。设算子输出为 $\hat{y}_i$，标准输出为 $y_i$，常见的判据是**最大相对误差**

$$
E_{\max} = \max_{i} \frac{| \hat{y}_i - y_i |}{|y_i| + \epsilon}
$$

其中 $\epsilon$ 是一个小的正数，防止除零。拆三步：

- **第一步，逐元素绝对误差**：$|\hat{y}_i - y_i|$ 衡量每个位置差多少。
- **第二步，除以参考量级**：除以 $|y_i| + \epsilon$ 得到相对误差——把「绝对差」归一化为「相对差」，避免大数值元素掩盖小数值元素的错误。
- **第三步，取最大值**：$E_{\max}$ 关注最坏情况——只要有一个元素严重偏离，$E_{\max}$ 就会变大，提示算法可能存在结构性错误而非单纯精度损失。

**这条判据的工程含义：** 若 $E_{\max}$ 在 $10^{-2}$ 量级以下且随机输入下稳定，通常视为 FP16 量化下的正常精度损失；若出现 $O(1)$ 甚至更大的误差，则基本可以断定算子逻辑有 bug。<span class="marginnote">「最大相对误差」只是众多判据的一种，工程上还常用余弦相似度（整体方向一致性）与均方误差（整体量级）。多个判据交叉验证，比单一判据更能暴露不同类型的错误。</span>

多判据交叉验证还有一个实际好处：**不同判据暴露不同类型的错误**——最大相对误差抓「个别点爆掉」，均方误差抓「整体量级偏差」，余弦相似度抓「方向整体跑偏」。三者一起看，错误几乎无处遁形。

## 5 常见调试问题的定位清单

算子调试中「翻车」最多的几类问题，收成一张对照表：

- **形状不匹配**：输出 shape 与预期不符 → 先查形状推导，再查分块边界（末块）。
- **数值全错 / 结果乱**：大概率逻辑 bug → 先隔离到单算子，用边界值定位是哪段逻辑。
- **输出为 0 或常量**：可能是数据没搬进去或没搬回来 → 查内存拷贝方向与大小。
- **误差在容差内但偶发超标**：浮点非确定性问题 → 检查是否对浮点加法顺序有依赖。
- **性能远差于预期**：正确性过了、性能不过 → 查排布、分块尺寸与多核利用率。
- **编译注册报错**：原型与实现名字不一致或注册缺失 → 先查算子名与两段注册。

这六类问题的定位顺序有一致性：**先形状、再数值、再性能**。每类问题有各自的「第一怀疑对象」，按清单排查能大幅减少在错误方向上耗费的时间。<span class="marginnote">「先形状、再数值、再性能」是算子调试的总顺序：形状错了，数值验证毫无意义；数值错了，性能调优毫无意义。<strong>每一步通过，才进入下一步</strong>——这条纪律能让调试过程始终有明确方向。</span>

还有一类「工具层面」的坑值得单列：**验证工具版本与算子编译版本不一致**，会导致「明明对的算子报错」。排查时先确认验证工具、CANN 版本、编译选项三者匹配——这类问题最难从代码层面发现，但最常见于跨版本升级后。

调试验证的最终目标是建立「可复现」：固定输入、固定精度、固定环境，让「对与错」可判定。**不可复现的调试是徒劳**——这也是为什么昇腾官方始终强调「精度比对 + dump」的组合：它把「感觉对了」变成「报告说了算」。

## 6 核心术语速查表

本节的术语集中在「算子调试」语境，整理如下：

| 术语 | 含义 |
| --- | --- |
| 单算子验证 | 在最小单元上确认一个算子数值正确 |
| 集成验证 | 把算子放进真实模型做端到端对比 |
| dump | 把设备内存中的张量导出到文件 |
| 精度比对 | 设备输出与标准实现逐元素比对 |
| 最大相对误差 | 逐元素相对误差的最大值，判据之一 |
| 容差 | 允许的误差范围，FP16 下正常精度损失 |
| 边界值 | 全 0、全 1、特殊值等极端输入测试 |
| 末块 | 分块循环末尾不足一块的部分，易越界 |
| 余弦相似度 | 整体方向一致性的比对指标 |
| 均方误差 | 整体量级的比对指标 |
| 隔离定位 | 先缩到单算子再逐层放大定位错误 |
| 标准实现 | CPU 上的 NumPy 或框架同功能算子 |

## 7 小结

- 自定义算子全流程六步：**生成工程 → 填原型 → 写实现 → 编译注册 → 单算子验证 → 集成验证**。
- **先隔离到单算子**再逐层放大，是错误定位的主战场；跳过它会付出成倍排查代价。
- 数值正确性三重检查：**形状类型 → 边界值（含末块不足）→ 随机数比对**。
- 用 **dump + 精度比对工具**把设备内存里的数值「捞出来」与标准实现比对，dump 要小而精。
- 最大相对误差 $E_{\max}$ 是常用判据：小误差为正常精度损失，$O(1)$ 级误差则是逻辑 bug。
- 调试总顺序「先形状、再数值、再性能」，目标是建立**可复现**的验证环境。
