## 为什么从 ATC 开始

昇腾推理的模型形态是 `.om` 离线模型，而 `.om` 是怎么来的？答案是一个工具：**ATC（Ascend Tensor Compiler，昇腾张量编译器）**。ATC 把训练框架产出的模型（ONNX、MindSpore、Caffe、TensorFlow 等）离线编译成昇腾可执行的 `.om` 文件。这不是简单的「格式转换」——ATC 在编译期完成算子映射、图优化、布局转换、甚至量化，把**最贵的优化提前到部署前做一次**，运行期直接执行。理解 ATC，你就理解了「训练模型如何变成生产可用的昇腾模型」这一关键一跳。<span class="marginnote">ATC ≈ TensorRT 的模型转换（`trtexec` + builder）：都是「把框架模型编译成设备专属可执行文件」。两者的共同哲学是——训练时模型是「描述」，部署时模型必须是「编译产物」；把编译放在部署前，运行期只剩执行。</span>

## 1 ATC 是什么：一次转换，三步优化

ATC 的输入是框架模型，输出是 `.om`，中间它默默做了三件事：

**算子映射**：把框架算子映射到昇腾算子库中对应的实现；库中没有的算子会尝试用通用实现编译，或报错提示需要自定义算子。

**图优化**：复用 GE 的优化能力——常量折叠、算子融合、布局转换、死节点消除，让图在编译期就「最优」。

**精度与性能选择**：支持 FP16、INT8 等低精度转换，把权重与计算降到目标精度，换取算力与带宽的解放。<span class="marginnote">「算子映射失败」是 ATC 转换最常见的报错——模型里出现了昇腾算子库没有的算子。此时有两个选择：换成算子库支持的等价算子，或走自定义算子开发（本专题第 3 篇）。<strong>先看报错清单，再决定是「改模型」还是「写算子」</strong>，这是 ATC 使用者的第一课。</span>

## 2 ATC 的命令行：参数即编译选项

ATC 是一个命令行工具，一条转换命令把「编译选项」全部说清。核心参数：

```
atc --model=model.onnx --framework=5 --output=model \
    --soc_version=Ascend910B --input_shape="data:1,3,224,224"
```

各参数含义：

**`--model`**：输入模型路径。
**`--framework`**：框架类型编号（ONNX 为 5，MindSpore、Caffe、TensorFlow 各有编号）。
**`--output`**：输出 `.om` 文件名前缀。
**`--soc_version`**：目标芯片型号——**同一模型转给不同芯片，产物不同**，这是 ATC 最容易被忽视的参数。
**`--input_shape`**：指定输入形状；可固定形状，也可声明动态维度。<span class="marginnote">`--soc_version` 决定编译产物适配哪款芯片——升腾 310 的 `.om` 不能直接跑在 910 上。部署时「芯片型号写错」会让 `.om` 加载直接失败。把 soc_version 当作「模型编译的目标硬件」，与「编译到哪个架构」的思维完全一致。</span>

## 3 静态形状与动态形状：部署的取舍

`.om` 里输入形状可以是固定的，也可以是带动态维度的。这是 ATC 转换最重要的一个设计决策：

**静态形状（Static Shape）**：转换时指定固定输入形状（如 `1,3,224,224`）。优点：编译期做满优化，运行期开销最小、性能最好；缺点：换形状就得重新转换。

**动态形状（Dynamic Shape）**：用 `--dynamic-shape` 声明某些维度可变（如 batch 可变）。优点：一份 `.om` 适配多路输入；缺点：编译期无法针对具体形状优化，运行期有额外处理开销。

**辨析｜易错点：动态形状不是「无成本」的灵活**。动态形状的每个「实际形状」都要在运行期额外分析、分配合法内存，性能与稳定性都会打折扣。工程惯例是：**能静态就静态**，只有「输入尺寸确实多变」的在线服务才上动态。<span class="marginnote">「静态 vs 动态」的取舍在编译类工具里是通用主题：TensorRT 也有 static/dynamic shape 之分。背后的统一原则是「<strong>编译期知道得越多，运行期优化得越好</strong>」——静态形状让编译器「为具体形状做满优化」，动态形状则必须留出通用路径。</span>

## 4 公式解析：静态形状的优化红利

为什么静态形状更快？设模型的批大小为 $B$，静态转换时 ATC 能为该形状预分配好缓冲、预生成分块方案；动态时则需按 $B$ 现场推导。定义动态形状相对静态形状的「额外开销比例」为

$$
\eta = \frac{T_{\text{dynamic}} - T_{\text{static}}}{T_{\text{static}}} \times 100\%
$$

拆三步看：

- **第一步，$T_{\text{static}}$ 是静态时延**：静态 `.om` 对固定形状做了全部编译期优化，是性能天花板。
- **第二步，$T_{\text{dynamic}}$ 是动态时延**：动态 `.om` 要多做形状推导、缓冲分配、分块适配。
- **第三步，$\eta$ 衡量代价**：$\eta$ 通常在个位数到数十个百分点——形状越「规整」、优化空间越大，$\eta$ 越大。

**这条式子的工程含义是：上线前先测 $\eta$**——如果动态形状带来的灵活性值这个性能代价，就用；否则静态形状 + 多份 `.om` 往往更划算。这也是为什么主流推理引擎默认「静态 + 分 shape 转换」。

## 5 转换失败与排查：最常见的三类错误

ATC 转换失败是昇腾新手的高频遭遇，三类错误按发生频率排：

**算子不支持**：模型算子不在库中。对策：换等价算子，或自定义算子。
**形状不匹配**：`--input_shape` 与模型实际输入不符。对策：先查模型输入规格，再填参数。
**Soc 版本写错**：`--soc_version` 与实际芯片不符，产物无法加载。对策：用 `npu-smi info` 查真实芯片型号。

这三类错误有一个共同点：**都是「信息不一致」问题——你告诉 ATC 的信息，和模型/硬件的真实情况对不上**。排查思路因此统一：先核对「模型真实规格」与「芯片真实型号」，再检查命令参数。<span class="marginnote">ATC 的报错日志会明确提示问题算子或参数，但读懂它需要「翻译」：把报错文本里的算子名、形状、芯片名与你的模型结构一一对照。养成「<strong>先核对事实，再怀疑工具</strong>」的习惯，ATC 的错误大多是信息核对问题，而非工具 bug。</span>

## 6 精度转换：从 FP32 到 FP16 与 INT8

ATC 的另一项核心能力是**低精度转换**——把 FP32 模型转成 FP16、甚至 INT8 的 `.om`，换取算力与带宽的解放。昇腾对低精度的支持分两档：

**FP16 混合精度**：权重与计算降为 FP16，关键激活保留 FP32。收益：算力提升明显、显存减半；风险：精度下降，需逐层验证。

**INT8 量化**：权重与激活量化到 INT8。收益：算力进一步提升、显存进一步压缩；风险：精度损失更大，通常需要校准数据（calibration）确定量化范围。

精度转换的决策不是「越低越好」，而是「精度预算」问题：

- 对精度不敏感的任务（分类、检测），FP16 通常无损，INT8 需验证；
- 对精度敏感的任务（分割、回归、大模型推理），FP16 仍要逐层检查；
- 转换后必须用**精度比对**复核——`.om` 与原始模型的输出差异要在容差内。

**一句话：精度是「目标业务给的预算」，转换是「在预算内榨性能」**——预算不够就退回高精度，预算充裕就往下压。这也是为什么本专题《自定义算子开发与调试验证》把「精度比对」列为算子正确性的硬指标：低精度世界的每个误差都要在容差内说清楚。<span class="marginnote">「精度预算」的思维同样适用于 GPU 生态：TensorRT 的 FP16/INT8 校准、PyTorch 的 AMP 都是「用精度换性能」。换来的性能不是免费的，而是从「精度预算」里花的钱——<strong>每一分性能，都要有一份误差报告买单</strong>。</span>

## 7 核心术语速查表

本节的术语集中在「模型转换」语境，整理如下：

| 术语 | 含义 |
| --- | --- |
| ATC | Ascend Tensor Compiler，昇腾模型编译工具 |
| .om | ATC 产出的离线模型文件 |
| 算子映射 | 框架算子到昇腾算子的翻译过程 |
| 图优化 | 融合、折叠、布局等编译期优化 |

| 动态形状 | 形状可变，运行期推导，灵活而有代价 |

| 精度选择 | 转换时指定目标计算精度 |

## 8 小结

- **ATC 把框架模型编译成 `.om`**，编译期完成算子映射、图优化、低精度选择。
- 核心参数：`--model`、`--framework`、`--output`、`--soc_version`、`--input_shape`——**芯片型号与输入形状是关键**。
- **静态形状**性能最好、换形状需重转；**动态形状**灵活但有额外开销，能静态就静态。
- 三类常见失败：**算子不支持、形状不匹配、soc 写错**——本质都是「信息不一致」。
- 动态相对静态的额外开销 $\eta$ 上线前先测，决定「静态 + 多 om」还是「动态一份」。
