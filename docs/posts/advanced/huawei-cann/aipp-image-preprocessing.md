## 为什么从 AIPP 开始

视觉模型的输入几乎从来不是「模型想要的样子」：摄像头出的是 YUV 或 JPEG，模型要的是 RGB、固定尺寸、归一化后的张量。在通用平台上，这些预处理要么写在 CPU 上（OpenCV），要么写在框架里，都会占用 CPU 时间、增加一次额外的数据搬移。昇腾的答案是 **AIPP（AI PreProcessing，AI 预处理）**：把裁剪、缩放、色域转换、归一化下沉到**硬件模块**完成，且常常直接融入模型执行流程，预处理与推理之间几乎不再有数据折返。这一节讲清 AIPP 是什么、怎么配、静态与动态怎么选。<span class="marginnote">AIPP 的工程动机与 NVIDIA 平台上「在 GPU 上做图像预处理（cuDNN/cv2-cuda）」同款：把预处理从 CPU 挪到加速器，消除 CPU-GPU 之间的搬运往返。但 AIPP 更进一步——它以硬件模块形态存在，连「调用一个 kernel」的开销都省了。</span>

## 1 AIPP 能做什么

AIPP 在硬件上完成一组固定图像操作，能力可以归纳为四类：

**几何变换**：裁剪（crop）、缩放（resize）、补边（padding）——把任意尺寸输入规整到模型要求的尺寸。
**色域转换**：RGB ↔ BGR、YUV（如 YUV420SP）→ RGB，让摄像头原生格式直接变成模型需要的通道顺序。
- **数值归一化**：逐通道减均值、乘缩放因子（mean/scale），把像素值映射到模型期望的分布。
- **格式转换**：把像素排布转换成模型输入要求的格式（如 NHWC 相关排布）。

这些操作原本需要逐像素在 CPU 上循环完成；AIPP 用硬件流水线一次搬移即完成，**图像数据从 DMA 进入设备后，直接被 AIPP 加工成模型输入，中间不再落回 CPU**。这就是它带来的最大收益：少搬一次数据、少占一份 CPU。

## 2 静态 AIPP 与动态 AIPP

AIPP 有两种配置时机，这是本节最重要的概念分叉：

**静态 AIPP**：在 **ATC 模型转换时**把预处理配置写进 `.om` 文件。优点是零运行期开销、参数不可变、最稳定；缺点是参数固化——换一组均值就得重新转模型。

**动态 AIPP**：在**运行期**通过 `aclmdlSetAIPP` 接口动态下发预处理参数。优点是同一份 `.om` 可适配不同输入（不同尺寸、不同归一化参数）；代价是运行期多一次参数下发、且对模型有要求（转换时需开启动态 AIPP 支持）。<span class="marginnote">静态/动态的取舍在推理部署里无处不在：静态 = 快而僵，动态 = 灵活而贵。这与上一节「静态形状 vs 动态形状」是同一枚硬币的两面——追求通用性就要付出弹性开销。实际项目常见组合是：模型用动态形状 + 动态 AIPP，换取一套 `.om` 服务多路输入。</span>

**辨析｜易错点：AIPP 不是万能预处理**。AIPP 支持的是固定的、结构化的图像操作。复杂的归一化逻辑（如逐样本统计、需要上下文的数据增强）不适合 AIPP，仍应在前端完成。**判断标准一句话：操作是否是「逐像素可表达」的固定映射——是，交给 AIPP；否，留在 CPU/框架。**

## 3 AIPP 配置文件长什么样

静态 AIPP 的配置以文本形式在 ATC 转换时传入（配置语法以官方文档为准），核心结构示意如下：

```
aipp_op {
  aipp_mode: static                 # 静态 AIPP
  input_format: YUV420SP_U8         # 输入格式
  crop { crop_h: 224  crop_w: 224 } # 裁剪
  resize { resize_h: 224 resize_w: 224 }  # 缩放
  csc_switch: true                  # 色域转换开关
  mean: 123.675  mean: 116.28  mean: 103.53   # 逐通道均值
  min_chn_0: 0.0  min_chn_1: 0.0  min_chn_2: 0.0
  var_reci_chn_0: 0.0171  ...       # 逐通道缩放（标准差倒数）
}
```

配置里的每一项都对应 AIPP 硬件模块里的一级处理：先裁剪、再缩放、再做色域转换、最后减均值乘缩放。**读懂这份配置 = 读懂了 AIPP 的硬件流水线顺序**。<span class="marginnote">注意配置里的 `var_reci_chn_*` 是「标准差的倒数」——它对应归一化公式 $y=(x-\text{mean})\times\text{var\_reci}$。把除法在配置期折算成乘法，是硬件实现归一化时避免除法器、只留乘法器的经典手法。</span>

## 4 公式解析：AIPP 里的归一化

AIPP 的数值归一化本质是一个逐像素仿射变换。对输入像素 $x$，输出 $y$ 为

$$
y = (x - \mu) \cdot s
$$

其中 $\mu$ 是逐通道均值，$s$ 是逐通道缩放因子。拆三步：

- **第一步，减均值**：$\mu$ 取自配置的 `mean`，把像素分布中心搬到 0 附近，稳定训练分布。
- **第二步，乘缩放**：$s$ 取自配置的 `var_reci`（标准差倒数，即 $s = 1/\sigma$），把分布压缩到单位方差量级。
- **第三步，硬件化**：AIPP 不逐像素跑这套算式，而是在配置期把 $(\mu, s)$ 折算成硬件参数，搬移流水线上乘加一次完成——**软件里的三步，在硬件里是一步**。

这套「软件多步、硬件一步」的折算逻辑，是理解 AIPP 乃至整个昇腾预处理链路的钥匙：**硬件化的本质，是把可预先计算的常量提前算掉，把运行期的工作压缩到最少**。

## 5 核心术语速查表

本节的术语集中在「图像预处理」语境，整理如下：

| 术语 | 含义 |
| --- | --- |
| AIPP | AI PreProcessing，昇腾硬件图像预处理模块 |
| 裁剪 | crop，把输入裁到目标区域 |
| 缩放 | resize，把图像调到模型要求尺寸 |
| 补边 | padding，填充边界到目标尺寸 |
| 色域转换 | RGB/BGR/YUV 等格式间的转换 |
| 归一化 | 减均值乘缩放，把像素映射到目标分布 |
| 静态 AIPP | 预处理参数固化进 .om，运行期不可变 |
| 动态 AIPP | 运行期下发预处理参数，同一模型多配置 |
| 仿射变换 | y = (x - μ)·s 的逐像素线性映射 |
| 硬件流水线 | 预处理在硬件模块内连续完成的处理链 |
| 数据折返 | 数据在 CPU 与设备间来回搬运的开销 |
| 逐像素 | 每个像素独立应用同一映射的操作类型 |

## 6 小结

- **AIPP 是硬件图像预处理模块**：几何变换、色域转换、数值归一化、格式转换在设备端一次完成。
- 收益核心是**消除数据折返**：图像进入设备后直接被加工成模型输入，CPU 与搬运都省下来。
- 静态 AIPP（配置固化进 `.om`）快而稳；动态 AIPP（运行期 `aclmdlSetAIPP`）灵活而有开销，按部署需求取舍。
- 配置文件的处理顺序即硬件流水线顺序：裁剪 → 缩放 → 色域 → 归一化。
- 归一化 $y=(x-\mu)\cdot s$
