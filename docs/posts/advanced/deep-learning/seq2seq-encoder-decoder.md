## 为什么从 Seq2Seq 与编码器-解码器开始

语言模型能「续写」，但很多任务需要「改写」：把英文翻译成中文、把文章总结成摘要、把问题转成答案。这类「源序列 → 目标序列」的任务，由**序列到序列学习（Sequence-to-Sequence, Seq2Seq）**完成。它的核心架构是**编码器-解码器（encoder-decoder）**：编码器把「源序列」读成「一个表示」，解码器基于这个表示**生成**「目标序列」。

Seq2Seq 是 2014 年神经机器翻译的开山范式（Sutskever 等、Cho 等），也是「一切条件生成」的母体——之后的注意力机制、Transformer、乃至 ChatGPT 的「对话式生成」都能追溯到它的「编码-解码」骨架。本节把 Seq2Seq 的结构、训练与推断、以及它的核心瓶颈（信息压缩）讲透——**理解了「编码-解码 + 压缩瓶颈」，就理解了为什么注意力机制是必然的下一步**。<span class="marginnote">「编码-解码」是人类信息处理的通用隐喻：读一段话（编码成「意思」），再根据「意思」组织语言（解码成输出）。Seq2Seq 把这个隐喻形式化了——编码器输出「语义向量」，解码器从它「展开」出目标序列。这个「压缩 → 展开」的结构，是一切「理解-生成」系统的骨架（也是 VAE、Transformer 的共同抽象）。</span>

## 1 编码器-解码器：压缩与展开

**Seq2Seq 的总体结构**：

```
源序列 x₁ x₂ … xₙ
     ↓
┌─────────────────────────┐
│    编码器 RNN            │  逐词读入，更新隐状态 h_t
└─────────────────────────┘
     ↓ 上下文向量 c = hₙ
┌─────────────────────────┐
│    解码器 RNN            │  以 c 为初始状态，自回归生成
└─────────────────────────┘
     ↓
目标序列 y₁ y₂ … y_m
```

**编码器（encoder）**：读入源序列，输出一个**上下文向量（context vector）**$\boldsymbol{c}$——通常取「编码器的最终隐状态」$\boldsymbol{c} = \boldsymbol{h}_n$：

$$
\boldsymbol{h}_t = \text{RNN}_{\text{enc}}(\boldsymbol{x}_t, \boldsymbol{h}_{t-1}), \qquad \boldsymbol{c} = \boldsymbol{h}_n
$$

**解码器（decoder）**：以 $\boldsymbol{c}$ 为初始状态，**自回归**地生成目标序列：

$$
\boldsymbol{s}_t = \text{RNN}_{\text{dec}}(\boldsymbol{y}_{t-1}, \boldsymbol{s}_{t-1}, \boldsymbol{c}), \qquad
P(\boldsymbol{y}_t \mid \boldsymbol{y}_{\\lt t}, \boldsymbol{c}) = \text{softmax}(\boldsymbol{W}\boldsymbol{s}_t)
$$

**「编码器把源序列压成一个向量，解码器从向量里展开出目标序列」**——这就是 Seq2Seq 的全部。<span class="marginnote">「上下文向量 $\boldsymbol{c}$」是 Seq2Seq 的信息瓶颈：整段源序列的所有信息，都要被压进<strong>一个固定维</strong>的向量。句子短还行，句子长（如一段话）时，这个「单向量压缩」会丢失细节——这就是著名的「长句翻译崩溃」问题，也是注意力机制（下一篇）要根治的：让解码器「直接看」编码器的每一步，而不是只依赖一个压缩向量。</span>

**易错点：** 解码器的初始状态是「上下文向量」还是「上下文向量的变换」？实现上有差异（有的直接 $\boldsymbol{s}_0=\boldsymbol{c}$，有的 $\boldsymbol{s}_0=\tanh(\boldsymbol{W}\boldsymbol{c})$），但思想相同——**$\boldsymbol{c}$ 是解码器的「出发点」**。生成时，解码器每步的输出词是「上一步输出词 + 当前状态 + 上下文」的函数。

## 2 训练：教师强制下的条件语言模型

Seq2Seq 的训练本质上是「**条件语言模型**」的训练：给定源序列与目标前缀，最大化「下一个目标词」的概率：

$$
L = -\sum_{t=1}^{m} \log P(\boldsymbol{y}_t \mid \boldsymbol{y}_{\\lt t}, \boldsymbol{c})
$$

**训练细节**：

1. **起始与结束标记**：目标序列前加 $\langle\text{start}\rangle$（解码器从这里开始）、后加 $\langle\text{eos}\rangle$（解码器到这里结束）——**「起止标记」让解码器知道「何时开始、何时停」**。
2. **教师强制（teacher forcing）**：训练时，解码器的每步输入用**真实的目标词** $\boldsymbol{y}_{t-1}$（而非模型上一步的预测）——训练稳定、收敛快。
3. **掩码损失**：$\langle\text{eos}\rangle$ 之后的词不参与损失（padding 部分也要掩码）——**「只对有效位置算损失」**是变长序列训练的通用规则。

**「Seq2Seq = 条件语言模型」**：它训练的「预测下一个目标词」能力，与语言模型完全同构，只是额外「以源序列为条件」——这个视角让你复用《序列模型采样与文本生成》的全部生成策略。<span class="marginnote">「Seq2Seq 是条件语言模型」这个等价值得钉死：语言模型建模 $P(\text{目标})$，Seq2Seq 建模 $P(\text{目标} \mid \text{源})$——只是「多了个条件」。所以「翻译 = 以英文为条件的中文语言模型」。这个统一视角让「预训练 + 微调」成为可能：先在大规模单语数据上预训练语言模型，再用「平行语料」微调成翻译模型（第六篇《预训练》的雏形）。</span>

**易错点：** 训练时「教师强制」用真实词，推断时用「自己的预测」——这个「训练/推断输入不一致」就是《采样与生成》里的「曝光偏差」。Seq2Seq 的经典缓解是**束搜索**（下一篇）与「计划采样」。

## 3 推断：束搜索与生成

**推断（解码）**：给定源序列，解码器自回归生成目标序列，使用**束搜索（beam search）**而非「贪心」：

**贪心**：每步只保留 1 个最佳候选。
**束搜索**：每步保留 $k$ 个最佳候选（$k$ 为束宽），最后选「整句得分最高」的。

束搜索的详细算法在下一篇，这里先理解它的动机：**贪心「只见局部」，束搜索「看整句」**——翻译质量显著提升（下一节详述）。<span class="marginnote">「束搜索 vs 贪心」是 Seq2Seq 推断质量的分水岭：贪心在「每步最可能」上选择，可能整句「跑偏」；束搜索同时保留多条轨迹，最后按「整句的对数概率」裁决——「多条路探索 + 全局择优」。这个「搜索」思想，与《对抗训练》里「找最坏方向」的 PGD、以及「束搜索在树里剪枝」的算法（第三级《算法》）是同族。</span>

## 4 公式解析：Seq2Seq 的联合概率分解

把「Seq2Seq 生成整句」的数学写清楚。给定源 $\boldsymbol{x}_{1:n}$，目标序列 $\boldsymbol{y}_{1:m}$ 的条件概率是**逐词条件概率的乘积**：

$$
P(\boldsymbol{y}_{1:m} \mid \boldsymbol{x}_{1:n}) = \prod_{t=1}^{m} P(\boldsymbol{y}_t \mid \boldsymbol{y}_{\\lt t}, \boldsymbol{x}_{1:n})
$$

- **第一步，看链式**：整句概率 = 每个「下一个词」条件概率的乘积——**与语言模型同构**，只是条件里多了源序列。
- **第二步，看推断目标**：最优翻译是「最大化整句概率」的序列：$\hat{\boldsymbol{y}} = \arg\max_{\boldsymbol{y}} P(\boldsymbol{y}_{1:m}\mid\boldsymbol{x}_{1:n})$——**这是组合搜索问题**（词表 $V$、长度 $m$，搜索空间 $V^m$），束搜索是它的近似。
- **第三步，看归一化**：束搜索比较「不同长度」的候选时，常按长度归一化（$\frac{1}{m}\sum \log P$），避免「短句占便宜」——**「长度惩罚」是束搜索的工程细节**。<span class="marginnote">「整句概率最大」的目标有一个已知问题：模型倾向「短而安全」的句子（短句的概率乘积通常更大，因为每项都 ≥ 对数上的平均）。这就是「长度归一化」存在的意义——现代 LLM 生成里同样有「重复惩罚」「长度惩罚」等「解码约束」，都是为了纠正「纯概率最大化」的偏置。</span>

## 5 Seq2Seq 的局限与演进

Seq2Seq 奠定了「编码-解码」范式，但有两个著名局限，直接催生了后续两篇的进展：

**局限一：信息压缩瓶颈。** 单一上下文向量 $\boldsymbol{c}$ 要装下整段源序列——**长句翻译质量崩塌**（「长句瓶颈」）。**解决**：注意力机制（下一篇）让解码器每步「直接看」编码器的所有隐状态，而非只看最后向量。

**局限二：串行生成。** 解码器逐词生成，无法并行——**生成速度慢**。**解决**：Transformer 的非自回归变体、以及「并行解码」研究。

**Seq2Seq 的应用**：机器翻译、文本摘要、语音识别（音频→文本）、图像描述（图像→文本）——**一切「一种序列 → 另一种序列」的任务**。<span class="marginnote">「Seq2Seq 是『一切条件生成』的母体」这句话值得展开：现代 LLM 的「指令跟随」本质上也是「指令序列 → 回答序列」的 Seq2Seq，只是「编码器」变成了「上下文窗口里的全部 token」，「解码器」变成了「自回归生成」。「编码-解码」的抽象如此通用，以至于它无处不在——识别出「什么在编码、什么在解码」，是读懂任何生成模型的第一视角。</span>

**易错点：** 「编码器-解码器」与「Seq2Seq」不是同义词——Seq2Seq 是「任务类型」，编码器-解码器是「架构实现」。有「无编码器的 Seq2Seq」（如纯解码器语言模型也能做翻译：给定「翻译：英文」，续写中文）。**「编码-解码」是经典的 Seq2Seq 架构，但「解码器直出」是现代的另一种选择**——GPT 就走后者。

## 6 数值算例：编码器「压成几个向量」

把「单向量瓶颈」的量级算出来，理解它为什么在长句上出问题。设源句长 $T_{\text{src}} = 50$ 个词，编码器隐状态维 $d = 512$。

**纯 Seq2Seq**：编码器把所有信息压进「最后一个隐状态」$h_T$——一个 512 维向量，要承载 50 个词的语义，压缩率 $50\times\text{嵌入维} \div 512$ 极高。**长句一进来，先被「压扁」再被「展开」，中间必然丢信息**（这也是「单向量瓶颈」的代价）。

**带注意力（Bahdanau/Luong）**：解码器每步「按需取用」源序列的 $T_{\text{src}}=50$ 个隐状态，而不是只盯着最后 1 个——信息不再被强制压扁。<span class="marginnote">对比两者的「信息通路」：<strong>纯 Seq2Seq 是「顺序压缩 → 逐词展开」的瓶颈结构；注意力是「编码器保留全部位置、解码器动态取用」的全连接结构</strong>。注意力让「长句翻译」从「先背下来再复述」变成「边看边译」——它同时解决了「信息压缩丢失」与「长距离依赖」两个问题。这个「从固定向量到动态取用」的演变，正是通往自注意力（Transformer）的最后一块跳板：自注意力把「取用源序列」推广成「每个位置取用所有位置」，彻底取消了「先压后展」的瓶颈结构。</span>

**一个易错点：Seq2Seq 的「上下文向量」概念在注意力出现后含义变宽。** 没有注意力时它指「编码器最后的隐状态 $h_T$」；有注意力后，每步的「上下文」是「源状态按注意力权重的加权和」——**「上下文向量」从一个固定量变成了「每步动态计算」**，这个用词变化正好反映了注意力的作用。
- **训练** = 条件语言模型：最大化「给定源 + 目标前缀 → 下一个目标词」；教师强制 + 起止标记 + 掩码损失。
- **推断** = 自回归生成 + 束搜索（保留多条候选、整句择优）。
- 整句概率 = 逐词条件概率乘积；最优翻译是组合搜索，束搜索是近似。
- **核心瓶颈**：单向量压缩装不下长句信息——「长句瓶颈」直接催生注意力机制。
- 编码-解码是「一切条件生成」的母体；现代 LLM 用「纯解码器」也做 Seq2Seq。

在下一节，我们给「穷举式生成」装上搜索——让模型同时保留多条候选轨迹，最后选整句最优，这就是**束搜索（Beam Search）**。
