## 为什么从实验管理开始

深度学习是「实验科学」——一次实验的结论要「可信」，必须「记录完整」与「可复现」。「我试了 50 个配置，最后这个最好」——但如果「没记录那 50 个配置」「换台机器复现不了」，这个「最好」就「不可信」。**实验管理（experiment management）**是让「实验结论可信」的工程方法——**日志**（记录发生了什么）、**可复现性**（换环境能重现）、**随机性控制**（随机源可固定）。

它是第九篇的收尾，也是「深度学习工程师」与「调参爱好者」的分水岭：**工程化实验 = 每次实验有完整的「配方 + 日志 + 结果」，可追溯、可复现、可对比**。本节把「日志系统」「随机性控制」「可复现性工程」讲透——它们是「让深度学习研究/开发『科学化』」的基础设施。<span class="marginnote">「实验管理的『复现危机』」：深度学习领域有过著名的「复现危机」——论文声称的「提升」复现不出来，原因常是「<strong>随机种子没固定、超参数没记录、代码版本没锁定</strong>」。「<strong>实验管理是『对抗复现危机』的第一道防线</strong>」。「记录 + 固定 + 锁定」——三个动作让实验「可复现」。</span>

## 1 日志系统：让训练「看得见、留得下」

**日志（logging）**是训练过程的「记录」——不只给「人看」，也给「对比用」。

**记录什么**：

**超参数**：学习率、batch、层数、正则——「配置的完整快照」。
**训练动态**：每步/每 epoch 的损失、梯度范数、验证指标——「过程的曲线」。
**环境信息**：GPU 型号、PyTorch 版本、随机种子——「环境的完整描述」。
**代码版本**：git commit 号——「代码的精确状态」。

**怎么做**：

**结构化日志**：TensorBoard / Weights & Biases / MLflow——「自动记录曲线、可对比」。
**自建日志**：CSV/JSON 记录每 epoch——「轻量、可自控」。
**实验命名**：约定式命名（如 `resnet50_lr1e-3_bs256_seed42`）——「实验可辨识」。

**「日志是实验的『黑匣子』」**——「训练出了什么事，日志要能『回放』」。<span class="marginnote">「『实验对比』的日志价值」：多个实验的日志放一起，才能「对比出『哪个配置更好、为什么』」——「<strong>『单实验日志』是记录，『多实验对比』是研究</strong>」。「wandb/tensorboard 的『多实验对比』功能，让『试过的配置』变成『可分析的数据库』」。「<strong>日志的终极价值 = 从『试过的』里学出『该试的』</strong>」。</span>

**易错点：** 「打印几行 loss」不算「日志系统」——日志要「结构化、完整、可对比」。**「『临时 print』 vs 『结构化日志』的区别是『能不能复用对比』」**——「正式实验用日志系统，调试才用 print」。

## 2 随机性控制：让随机可固定

深度学习的「随机源」很多，不控制就无法复现：

1. **数据打乱**（shuffle）：DataLoader 的 shuffle。
2. **模型初始化**：权重的随机初始化。
3. **Dropout/数据增强**：训练时的随机丢弃/增强。
4. **优化器**：个别优化器内部的随机（如采样子样本）。
5. **硬件非确定性**：GPU 并行（cudnn）的原子操作顺序。

**PyTorch 的种子控制**：

```python
import random
import numpy as np
import torch

random.seed(0)
np.random.seed(0)
torch.manual_seed(0)
torch.cuda.manual_seed_all(0)
```

**「固定种子 ≠ 完全复现」**：多卡并行、某些 GPU 算子（原子加法的顺序）仍可能非确定——「<strong>『尽可能确定』是目标，『完全确定』受硬件限制</strong>」。

**易错点：** 固定种子要「在实验一开始就设」（在数据加载、模型初始化**之前**）——「<strong>种子要在『一切随机』之前设置</strong>」。**「中途设种子」没有意义**——「随机源已经用了」。<span class="marginnote">「『种子』与『多次实验』」：固定种子保证「同配置同结果」（可复现）；但「评估『配置好坏』」要「换种子跑多次」（看均值/方差）——「<strong>『可复现』（同种子同结果）与『可靠评估』（多种子看分布）是两回事</strong>」。「<strong>报『均值 ± 标准差』（多种子）是可信实验的标准</strong>」——「固定种子给『复现』，换种子给『置信』」。</span>

## 3 可复现性工程：让「换环境」也能重现

**可复现性（reproducibility）**的完整含义：不只是「同机器同种子能复现」，而是「换机器、换环境也能复现」——这是「工程级可复现」。

**实现手段**：

1. **锁定依赖版本**：`requirements.txt` / `poetry.lock` / Docker——「固定库版本」。
2. **记录环境**：实验日志里记「库版本 + GPU + 驱动」——「环境快照」。
3. **固定代码版本**：git commit——「代码的精确状态」。
4. **端到端种子**：从数据到模型的完整随机控制——「全链路的确定性」。

**「工程级可复现 = 代码 + 数据 + 环境 + 种子 全部锁定」**——「四件套齐全，换机器也能重现」。<span class="marginnote">「Docker 的『可复现』价值」：Docker 把「环境」（库版本、依赖、系统）打包成「镜像」——「<strong>镜像 = 环境的『快照』，到哪都能重现</strong>」。「<strong>『在我机器上能跑』 vs 『在任何机器能跑』 = 环境锁定与否</strong>」。「容器化是『工程级可复现』的最强手段」。</span>

**易错点：** 「代码可复现」≠「数据可复现」——「数据集的版本也要锁定」（数据更新了，实验结果对不上）。**「可复现的四件套：代码 + 数据 + 环境 + 种子」**——「少一个，复现就『悬』」。

## 4 公式解析：可复现性的「实验配方」

把「可复现实验」抽象成「配方（recipe）」——一个实验的「完整描述」应该包含：

$$
\text{Recipe} = \underbrace{\{\text{超参数}\}}_{\text{配置}} \cup \underbrace{\{\text{数据版本}\}}_{\text{输入}} \cup \underbrace{\{\text{库版本, GPU}\}}_{\text{环境}} \cup \underbrace{\{\text{种子, commit}\}}_{\text{确定性}}
$$

- **第一步，看四块**：配置（超参数）、输入（数据）、环境（依赖）、确定性（种子/代码版本）——「四块缺一不可」。
- **第二步，看「复现」的操作**：拿到 Recipe → 装环境 → 拉数据 → 设种子 → 跑代码——「<strong>复现 = 按配方重做</strong>」。
- **第三步，读「配方」的本质**：实验管理的全部工作 = 让「Recipe」完整、可读、可存档——「<strong>『实验管理』 = 『配方的书写与存档』</strong>」。<span class="marginnote">「『实验配方』的『类比』」：好的实验像好的菜谱——「<strong>别人按菜谱能做出同样的菜</strong>」。「深度学习实验的『配方』 = 超参数 + 数据 + 环境 + 种子」——「<strong>配方完整，别人才能复刻</strong>」。「『记配方』是实验管理的全部精髓——『让结果可复刻』」。</span>

## 5 实验追踪工具与现代实践

**实验追踪（experiment tracking）工具**把「配方 + 日志 + 对比」自动化：

| 工具 | 特点 |
| --- | --- |
| Weights & Biases（wandb） | 云端日志、多实验对比、超参可视化——「最流行」 |
| MLflow | 开源的「实验 + 模型 + 部署」管理 |
| TensorBoard | 训练曲线可视化（PyTorch 内置支持） |
| 自建 CSV/JSON | 轻量、可控、无外部依赖 |

**现代实践**：

1. **脚本参数化**：训练脚本读「配置」（命令行/配置文件）——「改配置不改代码」。
2. **自动记录**：框架/工具自动记录「损失曲线 + 超参 + 环境」——「人不用手动记」。
3. **实验目录**：每次实验一个目录（配置 + 日志 + 检查点 + 指标）——「实验的『文件夹化』」。

**「从『手动记』到『自动追踪』，从『单实验』到『实验平台』」**——实验管理是「深度学习工程化」从「作坊」到「工厂」的进化。<span class="marginnote">「『实验的版本化』」：现代实践把「每次实验」当成「可回溯的版本」——「<strong>『这个配置的 0.73 准确率』要能『回放』到『那次实验』</strong>」。「实验平台（wandb/mlflow）让『回溯』一键可达」——「<strong>『可回溯』是实验管理的终极目标</strong>」。「没有平台的『人脑记实验』会在『几十次实验后』崩溃」。</span>

**易错点：** 「实验管理工具」不是「魔法」——「工具记录的是『你喂给它的』」——「<strong>喂给工具的信息要完整（超参、种子、数据版本），记录才有意义</strong>」。「工具的『自动化』替代的是『手动记录』，不是『记录意识』」。

## 6 小结

- **日志**：超参数 + 训练动态 + 环境 + 代码版本——「结构化、可对比、可回放」。
- **随机性控制**：数据/初始化/Dropout/GPU 的种子固定——「固定种子 ≠ 完全复现（多卡/硬件限制）」。
- **可复现性工程**：代码 + 数据 + 环境 + 种子 四件套锁定——「换环境也能重现（Docker/版本锁定）」。
- **实验配方**：配置 ∪ 数据 ∪ 环境 ∪ 确定性——「复现 = 按配方重做」。
- **追踪工具**：wandb/MLflow/TensorBoard——「自动记录、多实验对比、可回溯」。
- 实验管理 = 「让实验结论可信」——「记录 + 固定 + 锁定」的工程化基础设施。
