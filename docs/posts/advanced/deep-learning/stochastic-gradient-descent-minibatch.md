## 为什么从随机梯度下降与小批量策略开始

上一节诊断了优化地形的困难，本节给出最基础的应对引擎——**随机梯度下降（Stochastic Gradient Descent, SGD）**。直觉上，「最严谨」的优化应该每步都用**全部数据**算精确梯度（全批量梯度下降）；但现实里全批量不可行：数据集动辄千万样本，每步都要遍历全部数据，一步都慢如蜗牛。**SGD 的洞见是：用一个随机小批量的梯度近似全批量梯度，虽然「不准」，但快得多，而且这个「不准」反而带来好处。**

**小批量（minibatch）策略**是深度学习的默认范式：每个 epoch 把数据随机切成若干小批，每批算一个梯度、更新一次参数。本节讲清楚「为什么随机近似够用」「批大小怎么选」「SGD 的噪声如何帮忙」这三个核心问题。它是后续一切优化器（动量、Adam）的基座——所有「改进」都在 SGD 的框架上做文章。<span class="marginnote">SGD 的思想可以追溯到 Robbins & Monro（1951）的随机近似方法，但「深度学习标配」的身份是 2010 年代确立的。它与统计里的「随机近似」「在线学习」一脉相承：<strong>「噪声估计 + 迭代更新」在统计、优化、强化学习里是同一个母题</strong>——第二级《随机过程》里的随机逼近与这里同源。</span>

## 1 从全批量到小批量：三档梯度

梯度下降按「每步用多少数据算梯度」分成三档：

| 模式 | 每步数据 | 每步代价 | 梯度性质 | 收敛 |
| --- | --- | --- | --- | --- |
| 批量（batch）GD | 全部 $n$ | $O(nd)$ | 精确 | 每步保证下降 |
| 小批量（minibatch）SGD | 一个 batch，$m\ll n$ | $O(md)$ | 无偏估计 | 有噪声，总体下降 |
| 在线（online）SGD | 单个样本 | $O(d)$ | 噪声最大 | 波动大 |

**为什么小批量可行？** 因为小批量梯度是全批量梯度的**无偏估计**：若 batch 均匀随机采样，则 $\mathbb{E}[\nabla_{\boldsymbol{\theta}} J_{\text{batch}}] = \nabla_{\boldsymbol{\theta}} J_{\text{full}}$。期望正确，只是**方差**不为零——每步的方向带噪声，但「平均下来」指向真实下降方向。<span class="marginnote">「无偏但有噪声」是理解 SGD 的钥匙：方差来自「抽到的样本不能代表全体」。方差随 batch 大小 $\sqrt{m}$ 减小（大数定律），所以批越大，每步越接近精确梯度。但「精确」不是唯一目标——噪声本身有正则与逃逸作用，见第三节。</span>

**易错点一：** 小批量必须**随机采样**（每个 epoch 洗牌 shuffle）。若按顺序取 batch，数据中的隐藏顺序（如类别聚集）会让梯度有偏，训练不稳。**「每个 epoch 先 shuffle 再切批」是雷打不动的纪律**。

## 2 学习率与批大小的相互作用

SGD 有两个最核心的超参数：**学习率 $\eta$** 与**批大小 $m$**。它们的组合决定「有效步长」：

**步长（沿梯度方向走的距离）** $\approx \eta / \sqrt{m}$——直觉上，批越大梯度越「稳」，可以用更大学习率；批越小梯度越「躁」，学习率要更小。
**线性缩放规则（linear scaling rule）**：把 batch 从 $m$ 增大到 $km$，学习率也应近似增大到 $k\eta$（Goyal 等，2017 在大规模训练里验证）。这使「增大 batch 并行加速」成为可能：用 $k$ 倍 GPU 并行、$k$ 倍 batch、$k$ 倍学习率，训练步数可大幅减少。

**易错点二：** batch 不是越大越好。极端大 batch 的两个代价：其一，内存/显存限制；其二，**泛化差距**——大量实验观察到大 batch 训练出来的模型泛化略差（梯度噪声小，可能「过分追求最陡」而错过「宽而泛化好」的极小值）。「大 batch + 调学习率」是现代大规模训练的标准做法，但「batch 超过某阈值后泛化下降」是真实存在的现象。<span class="marginnote">「为什么大 batch 泛化差」有多个解释：噪声的消失让 SGD 更像确定性梯度（钻进尖锐极小值）、以及「大 batch 的隐式正则减弱」。实践中缓解手段包括「学习率预热 + 线性缩放」「batch 渐进增大」等——第九篇《调参方法论》有具体数值建议。一个经验锚点：ResNet 系列 ImageNet 训练常用 batch 256、lr 0.1；增大到 batch 1024 时 lr 升到 0.4 左右。</span>

## 3 SGD 的噪声：不只是坏事

SGD 的梯度噪声常被看作「不精确的缺陷」，但它其实有三大好处：

**好处一：逃离鞍点与平台。** 上一节说高维损失面的主要障碍是鞍点。确定性梯度在鞍点附近「无路可走」（梯度为零）；SGD 的噪声让参数**随机游走**，有机会「被推离」鞍点的平缓区——**噪声是逃离鞍点的「推力」**。

**好处二：隐式正则。** 噪声让 SGD 在损失曲面上的轨迹「扫过」更宽的区域，倾向于落在「宽而平坦」的极小值（对噪声不敏感、泛化更好），而非「窄而尖锐」的极小值。这被形式化为「SGD 的隐式正则化」——它没显式加惩罚项，却天然偏好平坦解。

**好处三：成本。** 每步代价 $O(md)$ 远小于 $O(nd)$。数据量大时，「快而噪」的 SGD 在同样的计算预算下能完成更多次更新，实际收敛远快于「慢而准」的全批量。

**易错点三：** 噪声是「学习率的函数」：学习率大 → 每步走的远 → 噪声影响大；学习率衰减到很小 → 噪声影响小 → 收敛稳定。**「噪声强度随学习率衰减而衰减」是 SGD 收敛性设计的关键**——所以几乎所有 SGD 训练都配学习率调度（见《学习率策略》）。<span class="marginnote">「噪声作为隐式正则」有一个直观例子：在同一个模型上，用「大 batch + 更少步数」和「小 batch + 更多步数」训练到相同训练损失，后者的泛化往往更好。这不是玄学，而是「小 batch 噪声大 → 隐式正则强」的体现。理解这条，就能解释为什么「同样的模型、同样的数据，仅靠调 batch」就能产生可观的泛化差异。</span>

## 4 公式解析：小批量梯度是无偏估计

把「小批量梯度无偏」与「方差随 batch 缩小」写清楚。设总损失 $J = \frac{1}{n}\sum_i J_i$，batch 大小 $m$，随机抽样的 batch 梯度为

$$
\boldsymbol{g}_m = \frac{1}{m}\sum_{i \in \mathcal{B}} \nabla_{\boldsymbol{\theta}} J_i
$$

- **第一步，验无偏**：$\mathbb{E}[\boldsymbol{g}_m] = \frac{1}{m}\sum_{i\in\mathcal{B}}\frac{1}{n}\sum_j \nabla J_j$——对随机 batch 取期望后，每个样本被抽中的概率相同，期望回到全批量梯度 $\nabla J$。**$\mathbb{E}[\boldsymbol{g}_m] = \nabla J$**。
- **第二步，算方差**：设单样本梯度的方差为 $\sigma^2$（各向同性近似），则 $\text{Var}[\boldsymbol{g}_m] = \sigma^2/m$——**方差随 batch 增大而线性减小**。
- **第三步，读权衡**：batch 越大方差越小（每步更准），但每步代价越大（$O(md)$）。「单位时间内能算的更新次数」与「每次更新的质量」此消彼长——最优 batch 常在「方差够小、步数够多」的折中点。<span class="marginnote">把方差 $\sigma^2/m$ 与步长 $\eta$ 合起来看「有效信噪比」：步长对噪声的「忍受力」决定你能用多大学习率。信噪比 $=\frac{\|\nabla J\|^2}{\sigma^2/m}$，批越大信噪比越高，能承受的学习率越大——这就是「线性缩放规则」背后的统计依据。</span>

## 5 小批量策略的工程要点

把「小批量 + SGD」的工程实践浓缩成清单：

1. **每个 epoch 洗牌**，然后按顺序切批（保证每批随机、全覆盖）。
2. **batch 取 2 的幂**（32、64、128、256），内存对齐与 GPU 利用率最优。
3. **学习率与 batch 联动**：增大 batch 时按比例放大学习率，并配合预热。
4. **学习率调度**：训练后期衰减学习率（step/余弦），让噪声缩小、收敛稳定。
5. **观察「每 epoch 平均损失」而非「每步损失」**：单步损失含噪声，epoch 平均更平滑，便于判断趋势。

**易错点四：** 「mini-batch」与「在线 SGD」的混淆。工程上的「SGD」几乎总指**小批量 SGD**（PyTorch 的 `torch.optim.SGD` 就是小批量版本），而不是严格意义的「单样本在线更新」。术语的历史遗留容易造成误会——**文档里的 SGD 通常 = minibatch SGD**。<span class="marginnote">一个实际的性能问题：batch 太小（如 1–2）时，GPU 的并行度吃不满，每步「墙钟时间」并不比 batch 32 少太多，但每步信息量少得多——所以「batch 太小」在 GPU 上既不快也不稳。经验下界通常 16–32。这个「算力利用率 vs 统计效率」的权衡是选 batch 的现实约束。</span>

## 6 数值算例：批大小、方差与信噪比

把「方差 $\sigma^2/m$」变成能指导选择的数字。设单样本梯度的各坐标方差 $\sigma^2 = 4$（这是一个量级上真实的估计，实际值取决于模型与数据），真实梯度范数平方 $\lVert\nabla J\rVert^2 = 1$。信噪比定义为「信号功率/噪声功率」：

$$
\text{SNR} = \frac{\lVert\nabla J\rVert^2}{\sigma^2/m} = \frac{m}{\sigma^2} \approx \frac{m}{4}
$$

| 批大小 $m$ | 梯度方差 $\sigma^2/m$ | 信噪比 | 建议学习率量级 |
| --- | --- | --- | --- |
| 1 | 4.0 | 0.25 | 很小（噪声淹没信号） |
| 32 | 0.125 | 8 | 常规 |
| 256 | 0.0156 | 64 | 可按线性缩放规则放大 |
| 1024 | 0.0039 | 256 | 可配大学习率 + 预热 |

**批大小每翻 4 倍，噪声功率减到 1/4、信噪比翻 4 倍**——这解释了线性缩放规则为什么敢把学习率按批大小比例放大：大 batch 的梯度「更可信」，每步可以走得更远而不至于被噪声带偏。反过来，batch = 1 时信噪比远小于 1，信号完全淹没在噪声里，学习率稍大就会发散——**「小 batch 必须配小学习率」不是保守，而是信噪比的必然**。<span class="marginnote">这张表是量级估计，不是普适定律：不同模型、不同数据的 $\sigma^2$ 差异很大，而且各坐标方向噪声并不各向同性。实践中的正确用法是「定性地对照」：<strong>当你把 batch 从 32 提到 128，先用 4 倍的学习率试探，再按验证集损失回退</strong>——线性缩放给出起点，验证集给出裁决。</span>

这个「信噪比」视角还能解释一个直觉反差：为什么「噪声大」反而常常泛化更好？因为小 batch 低信噪比迫使学习率偏小、步长偏短，参数轨迹更「稠密」地扫过损失面，更可能落在宽而平缓的盆地——噪声在优化上帮它逃离鞍点，在泛化上帮它找到平坦解，两个好处同源于「随机性」。

**易错点五：shuffle 的时机与「同分布」假设。** 随机采样的前提是「每个 mini-batch 与整体数据同分布」。若不 shuffle，训练早期数据若按类别排列，早期 batch 全是同类样本，梯度被系统性带偏；更隐蔽的问题是「时间分布漂移」——若数据按时间排序（如推荐系统日志），不 shuffle 会让模型「学到过时的分布」。**shuffle 不只是「为了随机」，更是「为了每批同分布」**，这在流式数据上要格外小心。

**易错点六：batch 大小与 BatchNorm 的耦合。** 若模型里有 BatchNorm，batch 变小会放大其统计量的噪声（见《批量归一化》）。所以「调小 batch 省显存」这类操作，在 BN 网络里会同时破坏梯度统计与 BN 统计，需要一并调整学习率与 BN 的 momentum。**「改 batch」在 BN 网络里是牵一发而动全身的操作**——这也是很多训练框架建议「保持 batch 不变、用梯度累积模拟大 batch」的原因。

**本节关键公式速查。**
- 小批量梯度：$\boldsymbol{g}_m = \frac{1}{m}\sum_{i \in \mathcal{B}}\nabla J_i$
- 无偏性：$\mathbb{E}[\boldsymbol{g}_m] = \nabla J$
- 方差：$\text{Var}[\boldsymbol{g}_m] = \sigma^2/m$
- 有效步长 ≈ $\eta/\sqrt{m}$
- 线性缩放规则：batch ×k → lr ×k（配合预热）
- 信噪比 ≈ $\frac{\lVert\nabla J\rVert^2}{\sigma^2/m}$
- 工程默认：batch 取 2 的幂、每 epoch 洗牌、看 epoch 平均损失
- batch 太小（1–2）在 GPU 上既不快也不稳，经验下界 16–32。
- 三档梯度（批量/小批量/在线）的取舍：代价与噪声的平衡。
- **学习率与 batch 联动**：线性缩放规则（batch ×k → lr ×k），但要配合预热。
- **噪声的三大好处**：逃逸鞍点、隐式正则（偏爱平坦解）、低成本。
- 工程要点：每 epoch 洗牌、batch 取 2 的幂、学习率调度、看 epoch 平均损失。
- 框架里的「SGD」通常指小批量 SGD。

在下一节，我们给 SGD 装一个「惯性」——让它记住历史方向、冲过平台与震荡，这就是**动量法与 Nesterov 加速梯度**。
