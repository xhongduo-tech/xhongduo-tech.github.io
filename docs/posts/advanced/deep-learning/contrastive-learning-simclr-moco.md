## 为什么从对比学习开始

自监督的重建式任务（语言模型、MAE）在「连续数据」（图像）上并不天然好用——图像的「重建」太难（像素空间巨大）又太简单（像素级重建 ≠ 语义理解）。**对比学习（contrastive learning）**走了一条「不重建、只比较」的路：**让「同一物体的两个不同视角」表示相近（正对），让「不同物体的视角」表示远离（负对）**——「不学『图像长什么样』，只学『哪些图该像』」。这个「比较式」的自监督在图像上大获成功，SimCLR 与 MoCo 是其中两大代表。

**对比学习的核心洞察**：**「不变性」比「重建」更能定义语义**——「同一只猫的两种增强视图应该相似」，这个「增强不变性」逼模型学出「语义级」的表示（忽略像素级变化、保留物体级信息）。本节把「正负对」「InfoNCE 损失」「SimCLR 的增强与批量」「MoCo 的动量编码器与队列」讲透——它是「CLIP」（图文对比）与「现代视觉预训练」的直接基础。<span class="marginnote">「对比学习的『自我标签』」：对比学习自己造「正负对」——「同一张图的两个增强视图」是正对（它们应该相似）、「不同图的视图」是负对（它们应该不同）——「<strong>增强 = 伪标签的生成器</strong>」。这个「数据增强造标签」的思路，把「对比」变成「可监督的训练」——「<strong>增强定义了『什么是不变』，对比学习了『不变性』</strong>」。</span>

## 1 对比学习的基本框架：正对与负对

**对比学习的框架**：

1. **数据增强**：同一图像 $\boldsymbol{x}$ 生成两个不同的增强视图 $\boldsymbol{x}_1, \boldsymbol{x}_2$（随机裁剪、颜色抖动、翻转等）。
2. **编码器**：两个视图经编码器 $f$ 得到表示 $\boldsymbol{h}_1, \boldsymbol{h}_2$。
3. **目标**：拉近 $\boldsymbol{h}_1, \boldsymbol{h}_2$（正对），推远「其他图像的表示」（负对）。

**「正对 = 同一物体的不同视角，负对 = 不同物体的视角」**——模型学到「忽略增强差异、保留物体本质」的表示。

**为什么「增强」能定义语义？** 增强模拟「真实世界的变化」（位置、光照、颜色）——「同一只猫换位置、换光照还是同一只猫」，所以「对这些增强不变」的表示，捕捉的是「猫的本质」而非「像素细节」。**「增强不变性 = 语义一致性」**是对比学习的理论基石。<span class="marginnote">「增强的选择决定表示的性质」：如果增强只包含「颜色抖动」，模型学会「对颜色不变」（忽略颜色信息）；如果增强包含「裁剪」，模型学会「对位置不变」。所以「<strong>增强 = 对『什么不重要』的声明</strong>」——你声明「颜色不重要」，模型就忽略颜色。「增强设计 = 语义先验的注入」（与《数据集增强》的「增强 = 先验」同源，只是这里「增强」是「训练信号」本身）。</span>

**易错点：** 「正对」与「负对」的定义是「同一图像的两个视图」vs「不同图像的视图」——**「图像级」的对比**（不是「像素级」）。同一个 batch 里，其他图像（含它们的增强）都是「负样本」。

## 2 InfoNCE 损失：拉近正对、推远负对

对比学习最常用的损失是 **InfoNCE（Info Noise-Contrastive Estimation）**：

$$
L_i = -\log \frac{\exp(\text{sim}(\boldsymbol{h}_i, \boldsymbol{h}_i^+)/\tau)}{\sum_{j=1}^{N} \exp(\text{sim}(\boldsymbol{h}_i, \boldsymbol{h}_j)/\tau)}
$$

其中 $\text{sim}$ 是相似度（通常用余弦相似度），$\tau$ 是温度，$\boldsymbol{h}_i^+$ 是正样本、$\boldsymbol{h}_j$ 是 batch 里所有样本（含正样本与负样本）。

**结构**：分子是「正对的相似度」（要大），分母是「所有对（含负对）的相似度之和」（要小）——**这本质是一个「softmax 分类」：在「一堆候选里认出正样本」**。

**InfoNCE 的理论含义**：它等价于「互信息的下界」——最大化「视图与表示的互信息」。「<strong>对比学习 = 最大化互信息</strong>」：让「表示」与「物体的身份」共享最多信息。

**温度 $\tau$ 的作用**：控制「对负样本的惩罚强度」——$\tau$ 小，分布尖，更「严格区分」正负；$\tau$ 大，分布平，更「宽松」。**「温度是『对比强度』的旋钮」**。<span class="marginnote">「InfoNCE 与『负采样的关系』」：InfoNCE 与 Word2Vec 的负采样「一脉相承」——都是「从一堆候选里认出正样本」的二分类/多分类变形。「<strong>对比学习 = 负采样的现代复兴</strong>」——Word2Vec 用「上下文词」当正样本、随机词当负样本；SimCLR 用「增强视图」当正样本、其他图像当负样本。「同一个『对比』框架，从词迁移到了图像」。</span>

**易错点：** InfoNCE 的「负样本」数量很重要——负样本太少，「对比」太容易（模型随便学）；负样本太多，计算与内存负担大。**「负样本规模」是对比学习的关键超参数**——这直接引出了 MoCo 的「队列」设计（见下）。

## 3 SimCLR：简单但有效

**SimCLR（A Simple Framework for Contrastive Learning of Visual Representations）**（Chen 等, 2020）：

**架构**：

1. **增强**：随机裁剪 + 颜色抖动等（两个视图）。
2. **编码器**：ResNet 提取表示 $\boldsymbol{h}$。
3. **投影头（projection head）**：一个小的 MLP 把 $\boldsymbol{h}$ 投影到 $\boldsymbol{z}$（对比发生在 $\boldsymbol{z}$ 空间）。
4. **InfoNCE 损失**：在投影空间里拉近正对、推远负对。

**SimCLR 的两个关键设计**：

**投影头（projection head）**：对比在「投影空间 $\boldsymbol{z}$」而非「表示空间 $\boldsymbol{h}$」做——**大幅提升效果**（投影头滤掉「与对比无关」的信息，让表示更干净）。
**大 batch**：负样本来自 batch 内的其他样本——**batch 越大负样本越多，效果越好**（SimCLR 用 4096 的 batch）。

**「SimCLR 的『简单』」**：没有复杂结构（无动量编码器、无队列），靠「强增强 + 投影头 + 大 batch」取胜——「<strong>简单的设计 + 充分的规模 = 好结果</strong>」（再次印证「简单 × 规模」哲学）。<span class="marginnote">「投影头的『妙处』」：SimCLR 发现「对比损失放在投影头输出 $\boldsymbol{z}$ 上」比「直接放在编码器表示 $\boldsymbol{h}$ 上」效果好得多——因为「投影头」可以「丢弃对对比任务无用但对下游有用的信息」（如颜色细节）——「<strong>投影头 = 对比任务的『信息过滤器』</strong>」。这让「$\boldsymbol{h}$」保留更全的信息、「$\boldsymbol{z}$」专注对比——「一个编码器、两种空间」的分工。</span>

**易错点：** SimCLR 的「大 batch」在显存受限时不可行（每张卡只能放小 batch，负样本少）——**「大 batch 依赖」是 SimCLR 的软肋**，MoCo 正是为此设计。

## 4 MoCo：动量编码器与队列

**MoCo（Momentum Contrast）**（He 等, 2020）解决 SimCLR 的「大 batch 依赖」——用**队列**提供大量负样本，用**动量编码器**保证一致性：

**架构**：

1. **两个编码器**：查询编码器 $f_q$ 与**动量编码器 $f_k$**（参数是 $f_q$ 的「动量滑动平均」）。
2. **队列（queue）**：存「最近 K 个样本的键表示」作为负样本——**负样本数量不再受 batch 限制**（队列可以很大）。
3. **动量更新**：$f_k$ 的参数 $\theta_k \leftarrow m\theta_k + (1-m)\theta_q$（$m\approx 0.999$）——**动量编码器缓慢追踪查询编码器**。

**为什么需要动量编码器？** 队列里的键来自「过去的样本」（旧的编码器产生）——如果查询编码器更新太快，新旧表示「不一致」（同一个物体的旧表示与新表示对不上），对比失去意义。**动量编码器让键「缓慢演化」，保持与查询的一致性**。

**「队列 + 动量」**：MoCo 用「大队列」（负样本多）替代「大 batch」，用「动量」保证「队列里的旧键仍然一致」——**「不靠大 batch，靠队列」**，显存友好。<span class="marginnote">「MoCo vs SimCLR 的哲学」：SimCLR「当前 batch 内对比」（简单但 batch 依赖），MoCo「跨 batch 的历史队列对比」（负样本更多更稳）。「<strong>负样本的『历史』与『当前』</strong>」——MoCo 用「过去算过的表示」当负样本（资源友好），代价是要「动量」维护一致性。「<strong>用『时间』换『内存』</strong>」是 MoCo 的工程智慧。</span>

**易错点：** MoCo 的动量编码器**不更新梯度**（它是「查询编码器的影子」）——只有查询编码器被训练。**「动量编码器是『目标编码器』，不是『训练编码器』」**——这是 MoCo 与「孪生网络」的关键区别（孪生网络两个分支都训练）。

## 5 公式解析：InfoNCE 与互信息

把 InfoNCE 的「互信息最大化」含义写清楚。InfoNCE 损失可以写成（理论上）：

$$
L_{\text{InfoNCE}} = -\mathbb{E}\Big[\log\frac{p(\boldsymbol{x}^+ \mid \boldsymbol{x})}{p(\boldsymbol{x}^+)} \cdot \text{(常数)}\Big] \approx -I(\boldsymbol{x}, \boldsymbol{x}^+)
$$

- **第一步，看「认出正样本」**：分子 $\exp(\text{sim})/\tau$ 近似「正样本的条件概率」，分母是「先验概率」——比值度量「正样本的『额外信息』」。
- **第二步，看互信息**：最小化 InfoNCE ≈ 最大化「$\boldsymbol{x}$ 与 $\boldsymbol{x}^+$ 的互信息」——**「对比学习 = 最大化视图间共享的信息」**。
- **第三步，读直觉**：互信息是「两个变量共享多少信息」——「同一物体的两个视图」共享的正是「物体身份」——**最大化互信息 = 让表示捕捉「物体身份」**。<span class="marginnote">「互信息的『身份提取』视角」：同一猫的两个增强视图，共享的信息几乎只有「这是同一只猫」（像素细节被增强破坏）——所以「最大化视图互信息」=「最大化表示里的『身份信息』」。「<strong>对比学习 = 从像素的『表面差异』里提取『深层身份』</strong>」——这是它的语义学基础（信息论：互信息见第一级《信息论》）。</span>

**易错点：** InfoNCE 是「互信息的**下界**」——它最大化「互信息的一个估计」，不是精确的互信息。**「估计的偏差取决于负样本数量」**——负样本越多，估计越准（这也是「大 batch / 大队列」重要的理论原因）。

## 6 对比学习的现代影响

对比学习的影响远超「图像自监督」：

**CLIP**：把对比学习用到「图文对」——拉近「匹配的图文」、推远「不匹配的」——学出「跨模态的通用表示」（第八篇《CLIP 与图文对齐》）。
**多模态**：CLIP 的对比框架成为「图文预训练」的标配。
**句向量**：SimCSE 把对比学习用到「句子」——同一个句子的两个 dropout 视图是正对。

**「对比学习 = 现代表示学习的『对比范式』」**——「CLIP、SimCSE、文本到图像的条件注入」都建立在「拉近正对、推远负对」的框架上。「<strong>从图像到文本到多模态，对比学习是最通用的表示学习框架之一</strong>」——它用「不变性」定义了「语义」，用「对比」实现了「学习」。<span class="marginnote">「对比学习的『元思想』」：对比学习背后是「<strong>关系比属性更重要</strong>」的哲学——它不学「猫长什么样」（属性），只学「猫与其他东西的关系」（像什么、不像什么）。这个「关系优先」的思想，在现代表示学习里无处不在——「<strong>学『什么像什么』，比学『是什么』更通用</strong>」——因为「关系」是可迁移的，「属性」是领域特定的。</span>

**易错点：** 对比学习不是「万能自监督」——它对「负样本的定义敏感」（负样本选错 → 学错「不变性」），且「需要精心设计增强」。**「对比学习的效果依赖『任务设计』（增强 + 正负对），不是自动的」**。

## 7 小结

- **对比学习**：拉近「正对」（同一物体的增强视图）、推远「负对」（不同物体）——「学不变性」。
- **InfoNCE 损失**：softmax 式「从候选中认出正样本」——等价于最大化互信息。
- **SimCLR**：强增强 + 投影头 + 大 batch——「简单 × 规模」取胜；投影头滤掉无关信息。
- **MoCo**：队列（大负样本池）+ 动量编码器（一致性）——「不靠大 batch，靠队列」。
- 增强定义「什么是不变」——增强设计 = 语义先验注入。
- 影响：CLIP/SimCSE/多模态预训练都建立在「对比」框架上——「关系比属性更重要」。

在下一节，我们把「对比学习」与「重建式」统一——用「掩码重建」学视觉表示，这就是**掩码自编码器（MAE）与掩码图像建模**。
