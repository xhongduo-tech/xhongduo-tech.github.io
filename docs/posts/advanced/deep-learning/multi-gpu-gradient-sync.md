## 为什么从多 GPU 训练与梯度同步开始

上一节讲了「数据并行」的概念，本节落到「怎么实现」——多 GPU 训练的具体操作：**梯度同步（gradient synchronization）**与**通信优化**。数据并行的核心动作是「每步把各卡的梯度合并（All-Reduce）」，但「怎么合并」「怎么减少通信开销」是决定「多卡加速比」的关键——**通信没优化好，8 张卡可能只有 2 倍的加速**。

现代多 GPU 训练的「事实标准」是 **PyTorch 的 DistributedDataParallel（DDP）**——它把「梯度同步」封装得几乎透明。理解 DDP 的内部机制（梯度归约、通信与计算重叠、ring-all-reduce），你才能理解「为什么多卡训练要这么写」「为什么通信是瓶颈」「怎么优化」。本节把「梯度同步的机制」「All-Reduce 的算法」「通信优化技巧」讲透——它是「数据并行」从概念到工程的落地。<span class="marginnote">「DDP vs DP」：PyTorch 早期的 `DataParallel`（DP）在「主卡」汇总梯度——主卡成为瓶颈、通信串行；`DistributedDataParallel`（DDP）用「每卡独立 + ring-all-reduce 并行通信」——「<strong>DDP 是工程化的数据并行：每卡独立算、梯度并行同步</strong>」。「<strong>现代多卡训练一律用 DDP，不用 DP</strong>」——「通信的『并行化』是 DDP 的核心改进」。</span>

## 1 梯度同步：All-Reduce

数据并行每步的「梯度同步」用 **All-Reduce** 操作——把 $N$ 张卡的梯度「归约」成一份（求和/平均），再让每张卡都拿到这份「全局梯度」。

**All-Reduce 的语义**：输入是「每卡一份向量（梯度）」，输出是「每卡一份『归约后的向量』（全局梯度）」：

$$
\boldsymbol{g}_{\text{global}} = \frac{1}{N}\sum_{i=1}^{N} \boldsymbol{g}_i \quad (\text{平均}), \qquad \text{每卡都拿到 } \boldsymbol{g}_{\text{global}}
$$

**「每卡算自己的 → All-Reduce 合并 → 每卡拿到全局梯度 → 每卡同步更新」**——这就是数据并行的每步循环。

**All-Reduce 的算法**：朴素实现是「主卡收集 + 广播」（主卡瓶颈）；现代用 **Ring-AllReduce**——把 $N$ 张卡排成环，梯度分块在环上「逐块传递累加」，最后「每块沿环广播」——**通信量均摊、无主卡瓶颈**。<span class="marginnote">「Ring-AllReduce 的『分块流水』」：Ring-AllReduce 把梯度切成 $N$ 块，每卡「同时」接收前卡的块、累加、传给后卡——「<strong>通信在环上『流水推进』，每卡都在传也在收</strong>」——「通信时间 ≈ 传输总量 / N（均摊），而不是『主卡独自扛』」。Ring-AllReduce 让「通信成本随卡数均摊」——「<strong>多卡训练『线性扩展』的前提是通信『可并行』</strong>」。</span>

**易错点：** All-Reduce 的「平均 vs 求和」——数据并行常用「平均」（梯度除以 $N$，等效于「平均损失」的梯度）；实现上「求和后除以 $N$」或「每卡先除以 $N$ 再求和」等价。**「归约操作（sum/avg）要与损失的定义一致」**——「平均损失 → 平均梯度」。

## 2 DDP 的机制：梯度归约 + 计算通信重叠

**PyTorch DDP** 的核心机制：

1. **前向**：每卡独立（各自的数据分片）。
2. **反向**：每卡算梯度；**在反向传播的同时**，梯度被「逐层」归约（不是等全部算完再同步）——**「计算与通信重叠」**。
3. **更新**：每卡用「归约后的梯度」同步更新。

**「计算与通信重叠（overlap）」**是 DDP 的关键优化：反向传播是「逐层」的（从输出层到输入层），每层的梯度算完就可以「立即」进入 All-Reduce——**「算第 $l$ 层梯度时，同时传输第 $l+1$ 层的梯度」**——通信「藏」在计算里，GPU 不空闲等通信。

**DDP 的「bucket」机制**：把梯度分成「桶」（bucket），按桶归约——「<strong>桶的大小平衡『通信粒度』与『重叠效率』</strong>」（桶太大同步延迟、桶太小通信次数多）。

**易错点：** DDP 要求「每卡看到同一份初始参数 + 同样的数据分片顺序」——**「随机种子、数据 shuffle 的一致性」**是 DDP 正确性的前提（各卡数据分片不同，但「每卡内部」的随机要一致或独立）。「<strong>DDP 的『可复现性』 = 各卡的随机源要控制好</strong>」。

## 3 通信优化：让多卡「真的」加速

多卡训练的「加速比」受通信限制——优化通信是「多卡训练」的核心工程。主要手段：

**手段一：梯度压缩**。把梯度量化（FP16/int8）再通信——「通信量减半/减 4 倍」，精度损失可接受（混合精度通信，见《混合精度训练》）。

**手段二：梯度累积 + 稀疏通信**。不是每步都同步，而是「攒几步再同步」——「减少通信频率」，但「梯度陈旧」（同步 vs 异步的取舍）。

**手段三：通信拓扑优化**。用「分层 All-Reduce」（节点内高速通信 + 节点间慢速通信）——「<strong>『快设备多传、慢设备少传』</strong>」（与《分布式训练》的「通信成本层级」一致）。

**手段四：混合精度**。FP16/BF16 通信——「通信量减半」（训练标配）。

**「通信优化的目标」**：让「通信时间 < 计算时间」——「<strong>通信不拖后腿，多卡才真加速</strong>」。<span class="marginnote">「『加速比』的『阿姆达尔』」：多卡训练的加速比上限受「通信/计算比」限制——「<strong>加速比 ≈ 卡数 /（1 + 通信/计算比 × 卡数）</strong>」。通信占比越高，加速比越「跑不上去」。「<strong>通信优化 = 把『通信/计算比』压下去</strong>」——「混合精度、梯度压缩、重叠」都是「压通信」的手段。</span>

**易错点：** 「卡越多，加速比越接近 1」（通信开销随卡数增长）——**「8 卡 6 倍加速、64 卡 40 倍加速」**是常态（不是「卡数 × 1」）。「<strong>多卡的『边际收益递减』来自通信</strong>」——「评估多卡训练看『加速比曲线』，不看『卡数』」。

## 4 公式解析：计算与通信的重叠时间

把「重叠优化」的收益用数学看穿。设每步「计算时间」$T_{\text{calc}}$、「通信时间」$T_{\text{comm}}$：

**不重叠**（先算完再同步）：

$$
T_{\text{step}} = T_{\text{calc}} + T_{\text{comm}}
$$

**重叠**（通信藏在计算里，通信时间 ≤ 计算时间）：

$$
T_{\text{step}} \approx \max(T_{\text{calc}}, T_{\text{comm}})
$$

- **第一步，看「不重叠」**：通信与计算「串行」——「GPU 算的时候网络闲着、网络传的时候 GPU 闲着」——「<strong>硬件利用率 < 100%</strong>」。
- **第二步，看「重叠」**：通信与计算「并行」——「算这层的时候传那层」——「<strong>总时间 = max(计算, 通信)，不是之和</strong>」。
- **第三步，读结论**：**「重叠让『通信拖后腿』变成『通信被藏住』」**——只要通信时间 ≤ 计算时间，通信「免费」（隐藏在计算里）。「<strong>重叠是 DDP 让多卡『真加速』的核心</strong>」。<span class="marginnote">「重叠的『条件』」：重叠要让「通信时间 ≤ 计算时间」才有意义——如果通信比计算还长（模型太大、网络太慢），重叠后仍被通信主导（$T_{\text{step}} = T_{\text{comm}}$）——「<strong>通信占比过高时，重叠救不了，要『减通信』（压缩/稀疏/换并行）</strong>」。「重叠治『轻度通信』，减通信治『重度通信』」。</span>

## 5 现代多卡训练的实践配置

把「多 GPU 训练」的实践配方总结：

1. **用 DDP**（不用 DP）——「每卡独立 + ring 归约」。
2. **混合精度**（BF16/FP16）——「训练快 2 倍 + 通信减半」。
3. **梯度裁剪**——「分布式下梯度爆炸要统一裁剪」。
4. **一致的随机性控制**——「各卡数据分片独立、种子可复现」。
5. **评估通信瓶颈**——「看加速比曲线，决定要不要加卡/换并行」。

**「多卡训练 = DDP + 混合精度 + 通信优化」**——这三件套是现代「单节点多卡」训练的标准配置；「跨节点 + 超大模型」再加「张量/流水线并行」（见《分布式训练》）。<span class="marginnote">「『单机多卡 vs 多机多卡』的通信差异」：单机多卡用「NVLink」（快，~600 GB/s），跨机用「InfiniBand/以太网」（慢，~25–400 GB/s）——「<strong>单机通信快、跨机通信慢</strong>」——「<strong>并行策略的『放置』要匹配通信速度</strong>」（张量并行放单机、流水线/数据并行放跨机）。「通信速度的层级决定了并行策略的层级」。</span>

**易错点：** 分布式训练的「调试」比单卡难——「<strong>先在单卡上把代码/模型跑通，再上多卡</strong>」。「多卡环境的问题（通信、同步）会掩盖单卡就有的 bug」——「先单卡后多卡」是分布式工程的第一纪律。

## 6 小结

- **梯度同步 = All-Reduce**：每卡梯度 → 归约成全局梯度 → 每卡同步更新——「数据并行的每步循环」。
- **Ring-AllReduce**：分块流水，通信均摊、无主卡瓶颈——「通信可并行的基础」。
- **DDP**：每卡独立 + 梯度逐层归约 + **计算与通信重叠**——「通信藏在计算里，GPU 不等通信」。
- **通信优化**：梯度压缩、稀疏通信、混合精度、分层拓扑——「压通信/计算比」。
- 重叠收益：$T_{\text{step}} = \max(\text{计算}, \text{通信})$——通信被「藏住」。
- 实践：DDP + 混合精度 + 通信优化；「先单卡跑通，再上多卡」——「多卡加速比曲线」评估瓶颈。
