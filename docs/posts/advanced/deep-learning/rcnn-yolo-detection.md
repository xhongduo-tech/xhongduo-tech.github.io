## 为什么从 R-CNN 系列与单阶段检测开始

上一节有了「锚框 + NMS」的基础语言，本节把「检测网络」组装起来。检测网络分两大流派：**两阶段检测（two-stage）**——R-CNN 家族（R-CNN → Fast R-CNN → Faster R-CNN）「先提候选框、再分类回归」，精度高；**单阶段检测（one-stage）**——YOLO、SSD「一步到位」，速度快。这两大流派的竞争，是检测领域「精度 vs 速度」的主线。

**R-CNN 系列**是「深度学习检测」的开端（2014–2015）：它把「候选区域 + CNN 分类」结合，让检测从「传统手工特征」跃迁到「深度学习」。**YOLO 与 SSD**则挑战「慢」——把检测变成「一次前向的回归问题」，让实时检测成为可能。本节把 R-CNN 的三代演进、YOLO/SSD 的单阶段设计、以及「mAP」评估讲透——它是「检测」从概念到网络的完整组装。<span class="marginnote">「检测的『速度-精度』权衡」：两阶段「慢而准」（候选框提得精），单阶段「快而略不准」（一步到位省时间）——「<strong>检测的演进史 = 在『精度-速度』曲线上移动</strong>」。「两阶段追求『上限精度』、单阶段追求『实时可用』——后来 YOLO 系把单阶段精度追平，成为主流」。</span>

## 1 R-CNN：候选区域 + CNN 分类

**R-CNN（Regions with CNN features）**（Girshick 等, 2014）是深度学习检测的开山之作：

**流程**：

1. **候选区域（region proposal）**：用传统方法（Selective Search）提出约 2000 个「可能含物体的区域」。
2. **裁剪 + 缩放**：每个区域缩放到固定大小。
3. **CNN 特征**：每个区域过 CNN（AlexNet）提取特征。
4. **分类 + 回归**：SVM 分类（是什么）+ 线性回归微调框。

**「R-CNN = 传统『候选区域』+ 深度学习『特征 + 分类』」**——它证明「CNN 特征 + 候选区域」能做检测。

**R-CNN 的痛点**：2000 个区域**每个都要过 CNN**——慢（一张图几十秒）、重复计算多。<span class="marginnote">「R-CNN 的『慢』」：2000 个候选区域每个独立过 CNN——「<strong>大量重叠区域被重复计算</strong>」。「<strong>R-CNN 的演进主线 = 消除『重复计算』</strong>」——「Fast R-CNN 共享卷积特征、Faster R-CNN 让网络自己提候选」——「每一代都省一点重复」。这个「省重复」的主线，是检测工程化的核心思路。</span>

**易错点：** R-CNN 的「候选区域」来自「传统方法」（不是网络学的）——「<strong>候选区域是『外部先验』，不是 CNN 的一部分</strong>」——「这是它慢 + 不可端到端的原因」。后来的 Faster R-CNN 把「候选区域」也交给网络——「全流程端到端」。

## 2 Fast R-CNN 与 Faster R-CNN：两阶段的成熟

**Fast R-CNN**（2015）：消除「重复计算」——**整图过一次 CNN** 得到「共享特征图」，每个候选区域在特征图上「裁剪（RoI Pooling）」取特征：

1. 整图过 CNN → 特征图（只算一次！）。
2. 候选区域映射到特征图，用 **RoI Pooling** 取「固定大小的区域特征」。
3. 区域特征 → 分类头（Softmax）+ 回归头（框偏移）。

**「Fast R-CNN 的关键：共享卷积特征」**——整图一次卷积，所有区域「共享」特征——「快一个数量级」。

**Faster R-CNN**（2015）：把「候选区域」也变成网络——**区域提议网络（Region Proposal Network, RPN）**：

RPN 在特征图上「用锚框」预测「哪些区域可能有物体」（粗分类 + 粗框）。
然后 RoI Pooling + 分类回归（精分类 + 精框）。

**「Faster R-CNN = RPN（提候选）+ Fast R-CNN（精修）」**——全流程端到端，两阶段检测的成熟形态（长期是检测精度标杆）。<span class="marginnote">「Faster R-CNN 的『两阶段』分工」：<strong>RPN（阶段 1）负责「找地方」（粗），RoI 头（阶段 2）负责「认物体」（精）</strong>——「<strong>先粗后精，各司其职</strong>」。「两阶段的『精度优势』来自『两次筛查』——先筛掉大量背景（RPN）、再精细分类（RoI 头）」。「<strong>两阶段是『精度优先』的经典选择</strong>」（Mask R-CNN 用它做检测 + 分割）。</span>

**易错点：** RoI Pooling 的「固定大小」——候选区域大小不一，RoI Pooling 把它们「池化」成固定尺寸（如 $7\times7$）——「<strong>『可变区域 → 固定特征』的桥</strong>」。「RoI Pooling 的『量化误差』由 RoIAlign（双线性插值）改进」——「Mask R-CNN 的 RoIAlign 更精确」。

## 3 YOLO：检测即回归

**YOLO（You Only Look Once）**（Redmon 等, 2016）是单阶段的代表——「只看一次，直接输出框」：

**核心思想**：把检测变成「一次前向的回归」——把图像分成 $S\times S$ 网格，每个网格预测「$B$ 个框 + 每个框的置信度 + $C$ 个类别」：

$$
\text{输出张量} \in \mathbb{R}^{\,S \times S \times (B \cdot 5 + C)}, \qquad \text{每个框的 5 个值} = (x,\, y,\, w,\, h,\, \text{confidence})
$$

其中 $(x, y)$ 是中心坐标、$(w, h)$ 是宽高（都相对网格归一化），confidence 表示「框内有物体的概率 × IoU」。

**「YOLO 一步到位」**：没有「候选区域」阶段——「<strong>整图过一次 CNN，直接输出所有框 + 类别</strong>」——「快（实时）」。

**YOLO 的优点与缺点**：

- **快**：一次前向 → 实时检测（早期 45 FPS）。
- **全局视角**：看整图（不像两阶段只看候选区域）——「减少背景误检」。
- **缺点**：小物体检测差（网格太粗）、定位精度略低（无精修阶段）。

**「YOLO = 用『一次回归』换『速度』」**——「牺牲两阶段的『精修』，换取『一步到位』的实时性」。<span class="marginnote">「YOLO 的『演进』」：YOLOv1（2016 单阶段首创）→ v2/v3（锚框、多尺度、更强骨干）→ v4/v5（工程极致）→ v8（Anchor-free）——「<strong>YOLO 系把单阶段的精度追平两阶段，成为工程主流</strong>」。「<strong>YOLO 的『版本迭代』是检测工程化的缩影——每个版本都在『精度-速度』曲线上推进</strong>」。</span>

**易错点：** YOLO 的「网格」不是「锚框」——YOLOv1 用「网格预测框」，v2 之后引入「锚框」——「<strong>YOLO 的『锚框』是后续版本加的，不是 YOLO 首创</strong>」。「早期 YOLO 无锚框，后期 YOLO 用锚框（又转向 Anchor-free）」——「锚框的『去留』是检测设计的摇摆」。

## 4 SSD：多尺度锚框的单阶段

**SSD（Single Shot Multibox Detector）**（Liu 等, 2016）：单阶段的另一种设计——**在多个尺度的特征图上做检测**：

**核心**：用「不同层」的特征图检测「不同大小」的物体——**浅层特征图（高分辨率）检测小物体、深层特征图（低分辨率）检测大物体**：

每层特征图配「该层的锚框」（小层小框、大层大框）。
每层输出「锚框的类别 + 偏移」。
合并所有层的检测结果，NMS 去重。

**「SSD = 多尺度特征图的锚框检测」**——「用『多尺度』弥补单阶段的『小物体弱点』」——比 YOLO 早期更准（尤其小物体）。

**「YOLO vs SSD」**：两者都是单阶段，但「YOLO 用整图网格、SSD 用多尺度特征图」——「SSD 的多尺度对『小物体』更好」。<span class="marginnote">「『多尺度』的检测直觉」：小物体在「浅层高分辨率特征图」上更清晰（细节多），大物体在「深层低分辨率特征图」上更显著（语义强）——「<strong>『在哪层检测』要匹配『物体大小』</strong>」。「<strong>SSD 开创的『多尺度检测』成为检测的标配</strong>」（FPN 特征金字塔把多尺度做得更系统）——「<strong>『多尺度特征』是检测处理『物体大小差异』的核心</strong>」。</span>

**易错点：** SSD 的「多尺度」要「不同层的特征图对齐锚框」——「每层的锚框尺寸与感受野匹配」——「<strong>锚框的『尺度设计』与『特征图层级』要配套</strong>」。「多尺度的『设计细节』决定了检测『哪些大小』的物体」。

## 5 评估与对比：mAP 与选型

**检测评估：mAP（mean Average Precision）**——「各类别 AP 的平均」：

**AP**：不同置信度阈值下的「精确率-召回率曲线」的面积——「<strong>综合『检出率』与『准确率』</strong>」。
**mAP**：所有类别的 AP 平均——「<strong>检测的总分数</strong>」。

**两大流派对比**：

| | 两阶段（Faster R-CNN） | 单阶段（YOLO/SSD） |
| --- | --- | --- |
| 流程 | 先提候选、再精修 | 一步到位 |
| 精度 | 高（尤其小物体） | 中→高（后期追平） |
| 速度 | 慢（非实时） | 快（实时） |
| 小物体 | 好（候选区域细） | 差→中（多尺度改进） |
| 典型 | 精度优先任务 | 实时任务（自动驾驶、视频） |

**选型**：实时性要求高（自动驾驶）→ YOLO；精度要求极致（医学、科研）→ Faster R-CNN；「<strong>后期 YOLO 系在速度与精度的平衡上胜出，成为工程主流</strong>」。<span class="marginnote">「检测的『现代演进』」：两大流派之后——「<strong>Anchor-free（CenterNet）去掉锚框、Transformer 检测（DETR）用『集合预测』替代『锚框 + NMS』</strong>」——「<strong>检测的设计从『手工先验（锚框）』走向『端到端学习』</strong>」。但「两阶段/单阶段」的速度-精度权衡与「mAP」评估，仍是检测的「坐标系」。</span>

**易错点：** mAP 的「IoU 阈值」影响分数——「<strong>mAP@0.5 vs mAP@0.75 是不同严格度的分数</strong>」——「报告 mAP 要说明 IoU 阈值」。「<strong>mAP 是『平均的』，可能掩盖『某类差』</strong>」——「关注每类的 AP，别只看 mAP」。

## 6 小结

- **R-CNN**：候选区域 + CNN 分类——开山之作，但 2000 个区域重复计算（慢）。
- **Fast R-CNN**：共享卷积特征 + RoI Pooling——快一个数量级。
- **Faster R-CNN**：RPN（网络提候选）+ RoI 精修——两阶段成熟形态、精度标杆。
- **YOLO**：检测即一次回归（网格预测框）——快、实时；后期版本追平精度。
- **SSD**：多尺度特征图 + 锚框——单阶段的小物体改进。
- **mAP**：检测的「总分数」；选型看「速度-精度」需求——「实时用 YOLO、精度用两阶段」。
