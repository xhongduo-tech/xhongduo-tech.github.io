## 为什么从数值梯度检验与高效实现开始

前两节完成了反向传播的算法理解与符号推导。现在进入工程现实：**你写了一个网络，怎么确定 `backward` 是对的？** 答案是用**数值梯度检验（gradient checking）**——用计算机最「笨」也最可靠的方式（差分近似）去验证最「聪明」的算法（反向传播）是否算得对。这是每个深度学习框架在发布前的必检项，也是你写自定义算子时的安全网。

另一半问题是**高效实现**：反向传播的正确公式知道了，但怎么写才快？同一段数学，写成三层嵌套循环（$O(n^3)$ 的 Python 循环）与写成矢量化矩阵运算（BLAS 加速），性能可以差三个数量级。本节把「正确性验证」与「效率优化」两个工程主题一起讲透。<span class="marginnote">本节与第三级《数值分析》的接口：数值差分属于数值微分的最朴素方法，其误差分析（截断误差 vs 舍入误差）正是那里讲的内容。理解「为什么 $\epsilon$ 不能太大也不能太小」，就是理解数值分析里「两种误差此消彼长」的活教材。</span>

## 1 数值梯度：用差分逼近导数

**数值梯度（numerical gradient）**：用函数值的变化率近似导数，不涉及任何求导公式。最常用的是**中心差分（central difference）**：

$$
f'(x) \approx \frac{f(x + \epsilon) - f(x - \epsilon)}{2\epsilon}
$$

相比**单侧差分** $\frac{f(x+\epsilon)-f(x)}{\epsilon}$，中心差分误差小一个数量级：单侧是 $O(\epsilon)$，中心是 $O(\epsilon^2)$。直觉：中心差分对称地取两侧，一阶误差项恰好相消。<span class="marginnote">为什么中心差分会更准？把泰勒展开写出来：$f(x+\epsilon)=f+f'\epsilon+\tfrac12 f''\epsilon^2+\cdots$，$f(x-\epsilon)=f-f'\epsilon+\tfrac12 f''\epsilon^2-\cdots$。两者相减时 $\epsilon$ 的一阶项翻倍保留，而 $\epsilon^2$ 项恰好抵消——所以中心差分「免费」消掉了二阶误差。这就是它比单侧差分高一阶的原因。</span>

对于**向量参数**，数值梯度要逐分量计算：

$$
\big[\nabla_{\boldsymbol{\theta}} f\big]_i \approx \frac{f(\boldsymbol{\theta} + \epsilon \boldsymbol{e}_i) - f(\boldsymbol{\theta} - \epsilon \boldsymbol{e}_i)}{2\epsilon}
$$

每个分量需要两次前向。若模型有 $P$ 个参数，一次完整梯度检验就是 $2P$ 次前向——所以**梯度检验只能用在参数少的模型上**（几百到几千参数）。

**易错点一：$\epsilon$ 的选择是门艺术。** $\epsilon$ 太大→截断误差主导（差分根本不像导数）；太小→舍入误差主导（$f(x\pm\epsilon)$ 与 $f(x)$ 在浮点下几乎相等，差商被噪声淹没）。经验值 $\epsilon \approx 10^{-6}$，在两种误差的平衡点附近。

## 2 检验的判据：相对误差

梯度检验不是「数值梯度与解析梯度相等」，而是**相对误差足够小**。定义

$$
\text{rel\_err} = \frac{\| \boldsymbol{g}_{\text{num}} - \boldsymbol{g}_{\text{analytic}} \|_2}{\max(\| \boldsymbol{g}_{\text{num}} \|_2, \| \boldsymbol{g}_{\text{analytic}} \|_2, \text{small\_const})}
$$

分母里的 $\text{small\_const}$（如 $10^{-12}$）防止两个梯度都接近零时分母为零。判据的经验值：

| 相对误差 | 含义 |
| --- | --- |
| $\le 10^{-7}$ | 极可能正确，放心用 |
| $10^{-5}$ 左右 | 可能正确，需仔细检查 |
| $10^{-3}$ 左右 | 很可能有 bug |
| $> 10^{-1}$ | 几乎确定有 bug |

**易错点二：为什么用相对误差而不用绝对误差？** 因为梯度的大小随网络深度与激活函数变化巨大，绝对误差没有可比性。深层网络里，浅层梯度天然比深层小几个数量级——相对误差把「尺度」归一化，才能跨层比较。<span class="marginnote">如果你做过梯度检验却总在「奇怪的小误差」上卡住，常见元凶是：用了 ReLU 等分段线性函数（在转折点附近差商跨越不连续点）、把 Softmax+CE 拆开实现、或忘记在检验时关闭 Dropout 等随机操作。梯度检验必须<strong>在确定性模式下进行</strong>——随机性会让数值梯度与解析梯度「各说各话」。</span>

## 3 梯度检验的工程流程

一套稳妥的梯度检验流程，按顺序执行：

1. **用最小模型**：参数量几百以内，单样本或小批量，输入维度小。目标不是「测大模型」，而是「测公式对不对」。
2. **关闭随机**：`model.eval()`、关闭 Dropout、固定随机种子；随机操作直接破坏检验。
3. **逐参数检验**：对每个参数张量，用中心差分算数值梯度，与 `.grad` 对比相对误差。
4. **放宽判断**：深层参数误差天然略大（梯度经多层连乘后量级变小），此时相对误差比绝对误差更可靠。
5. **修 bug 后重检**：定位到出错层后，缩小范围——只对该层做检验，逐层排查。

**易错点三：别在训练过程中做梯度检验。** 训练时参数在动、状态在变，检验结果无意义。检验要在**固定参数的快照**上进行：前向→backward→对比，全程不更新参数。

**易错点四：精度问题。** 梯度检验在 float32 下做，相对误差的「地板」大约在 $10^{-7}$。若需要更严苛的检验（验证到 $10^{-9}$），要用 float64 重算——否则你会把「float32 的精度限制」误判成「实现 bug」。<span class="marginnote">float32 下中心差分的精度天花板，源于「$f(x\pm\epsilon)$ 的相对误差」被放大 $1/\epsilon$ 倍。这是浮点数表示的本质限制——想深入可回看第一篇《数值计算：上溢、下溢与病态条件》对浮点误差的分析。</span>

## 4 高效实现：矢量化是第一生产力

正确性问题解决后，谈谈**效率**。反向传播的公式本身已经高效（O(前向)），但实现方式决定常数因子。三种写法对比：

| 实现方式 | 每次梯度计算代价 | 适用 |
| --- | --- | --- |
| Python 三层嵌套循环 | $O(hdk)$，常数极大 | 仅教学 |
| 半矢量化（逐层循环） | $O(hdk)$，常数较小 | 中等规模 |
| 全矢量化（矩阵运算） | $O(hdk)$，BLAS 加速 | 生产级 |

**为什么矢量化这么快？** 因为底层调用的矩阵乘法（BLAS）针对缓存局部性、SIMD 指令、多核并行做了极致优化。同样的 $O(hdk)$，手写循环的 Python 解释器开销是 BLAS 的几百倍。**「复杂度同阶，常数差几百倍」是深度学习性能的全部秘密之一**。

**示例**：计算输出层权重梯度 $\frac{\partial L}{\partial \boldsymbol{W}^{(2)}} = \boldsymbol{\delta}^{(o)} \boldsymbol{h}^{\top}$。矢量化写法是「一次外积」（`torch.outer(d_o, h)`）；若用循环写，就要嵌套 `for i in range(k): for j in range(h)`，慢一个数量级。**批量（batch）更是矢量化的大户**：把 $n$ 个样本堆成矩阵一次前向，而不是循环 $n$ 次——GPU 的并行度全部吃满。

## 5 公式解析：批量下的矢量化推导

把单样本公式推广到批量。设批量 $n$，输入矩阵 $\boldsymbol{X}\in\mathbb{R}^{n\times d}$，则：

$$
\boldsymbol{A}^{(1)} = \boldsymbol{X}\boldsymbol{W}^{(1)\top} + \boldsymbol{b}^{(1)}, \qquad
\boldsymbol{H} = \sigma(\boldsymbol{A}^{(1)}), \qquad
\boldsymbol{O} = \boldsymbol{H}\boldsymbol{W}^{(2)\top} + \boldsymbol{b}^{(2)}
$$

批量下反向公式的「批量版」：

$$
\frac{\partial L}{\partial \boldsymbol{W}^{(2)}} = \frac{1}{n}\sum_{i=1}^{n} \boldsymbol{\delta}^{(o)}_i \boldsymbol{h}_i^{\top} = \frac{1}{n} \boldsymbol{\Delta}^{(o)\top}\boldsymbol{H}, \qquad
\frac{\partial L}{\partial \boldsymbol{b}^{(2)}} = \frac{1}{n}\sum_i \boldsymbol{\delta}^{(o)}_i
$$

- **第一步，看形状**：$\boldsymbol{\Delta}^{(o)}\in\mathbb{R}^{n\times k}$ 是批量梯度，$\boldsymbol{H}\in\mathbb{R}^{n\times h}$ 是批量激活。$\boldsymbol{\Delta}^{(o)\top}\boldsymbol{H}$ 是 $k\times n$ 乘 $n\times h$ 得 $k\times h$——恰是权重形状。
- **第二步，看偏置**：偏置的梯度是**对批量取平均**——因为每个样本的偏置梯度都要「加总贡献」。
- **第三步，看实现**：全部是矩阵乘法，GPU 一次并行完成。**「把循环变成矩阵乘」就是矢量化**——识别出「对批量维度求和」的结构，就能写出高效代码。<span class="marginnote">批量梯度与单样本梯度之和的关系：$L = \frac{1}{n}\sum_i L_i$，所以 $\nabla L = \frac{1}{n}\sum_i \nabla L_i$——「平均损失」的梯度等于「梯度之平均」。这条线性关系让批量化在数学上零成本，纯粹是效率问题。这也是为什么梯度累积（分多次小批量再求平均）与单次大批量在数学上等价。</span>

## 6 高效反向的工程清单

把「高效实现」的经验浓缩成清单：

1. **永远用矢量化**：矩阵乘交给 BLAS/GPU，别手写循环。
2. **就地操作**：`+=`、`x = x + ...` 尽量复用内存，减少张量分配。
3. **利用对称性**：反向 = 前向的伴随，线性层反向只用转置与乘法，别「重新推导」。
4. **只在必要时保存中间量**：显存与算力的权衡（见梯度检查点）。
5. **用框架的原生算子组合**：`torch.nn.functional` 里每个算子都针对反向做过优化。

**易错点五：过早优化是万恶之源。** 先写清楚、验证正确，再profile 定位瓶颈。绝大多数情况下，瓶颈在「某个该矢量化却没矢量化的循环」或「频繁的 GPU↔CPU 拷贝」，而不是算法本身。

## 7 小结

- **数值梯度**用中心差分 $\frac{f(x+\epsilon)-f(x-\epsilon)}{2\epsilon}$ 逼近导数，误差 $O(\epsilon^2)$，每分量两次前向。
- $\epsilon$ 取 $10^{-6}$ 量级，太大截断误差、太小舍入误差。
- 判据用**相对误差**，$10^{-7}$ 级可信、$10^{-3}$ 级有 bug；检验需在**确定性、小模型**上做。
- **矢量化**是高效实现的第一生产力：把循环变矩阵乘，性能可差几百倍。
- 批量梯度 = 梯度之平均，数学上零成本，纯效率收益。
- 先写对、再优化；profile 定位瓶颈，别过早优化。
