## 为什么从 NVLink 域开始

上一篇讲了 NVLink 5 单条链路的带宽。但**一条链路只解决「两颗 GPU 之间怎么说话」，解决不了「几十颗 GPU 之间怎么都说上话」**——后者是「网络拓扑」的问题。这一篇把镜头从「链路」拉到「网络」：NVSwitch 是什么、NVLink 域是什么、为什么「把 72 颗 GPU 织成一个域」是 Blackwell 最核心的互联创新。

理解 NVLink 域，你才能真正看懂 NVL72 那句「72 颗 GPU 对外是一颗」——**它靠的不是每一颗 GPU 的算力，而是把全部 GPU 织进同一张「无阻塞」的网络。**

## 1 什么是 NVLink 域：一组全互连的 GPU

**NVLink 域（NVLink domain）**：一组通过 NVSwitch 或直接 NVLink 互连、能作为单一逻辑单元参与通信的 GPU 集合。域内任意两颗 GPU 之间都有高速 NVLink 通路，通信不需要绕道 PCIe 或外部网络。

一个域的规模可以很小，也可以很大：

- **8 卡节点**：8 颗 GPU 经 1–4 颗 NVSwitch 织成一个域，是 Hopper 时代的标准节点；
- **NVL72**：72 颗 B200 经 18 颗 NVSwitch 织成一个域，是 Blackwell 时代的「机柜级域」。

**「域」的关键属性是「全连接」**：域内任何一对 GPU 的通信带宽都接近 NVLink 的满带宽，而不是「部分对子快、部分对子慢」。这决定了张量并行（每次前向都要全域 AllReduce）能不能在域内高效运行。<span class="marginnote">对照《计算机网络》里的概念：<strong>「全连接」意味着任意节点对都有直达通路，近似于「完全图拓扑」。</strong>完全图的代价是交换机端口数随节点数平方增长——所以域规模不能无限扩大，这是 NVLink 域止步于机柜的根本原因。</span>

## 2 NVSwitch：把「一堆 GPU」变成「一张网」的交换机

单靠 GPU 的 18 条 NVLink 链路，一颗 GPU 只能直连少数邻居。要让任意两颗 GPU 都能通信，就需要**交换机**——NVSwitch 就是 NVIDIA 专门为 NVLink 设计的交换机。

**NVSwitch 的角色**：一颗 GPU 的 18 条 NVLink 中，一部分直连邻居 GPU，另一部分连到 NVSwitch；NVSwitch 内部按端口把数据在任意两条 NVLink 之间转发。于是「经交换机一跳」就能让任意两颗 GPU 通信。<span class="marginnote">类比：<strong>没有交换机时，两颗 GPU 说话要靠「中间人」转述（多跳、慢）；有了交换机，任意两颗 GPU 都是「直接对话」。</strong>NVSwitch 就是那个「接线总机」，只不过它以 50–100 GB/s 级别的带宽在工作。</span>

NVSwitch 5 的规格要点：

- 每个 NVSwitch 提供多个 NVLink 5 端口，支持全对全、无阻塞转发；
- 支持 **SHARP（网内归约）** 一类的集合通信卸载——数据「过交换机时顺手求和」，让 AllReduce 更快；
- 多颗 NVSwitch 可以组合，把域规模从 8 卡扩展到 72 卡。

## 3 拓扑对比：直接对连、环形、还是交换机

为什么不能只靠「每颗 GPU 直连邻居」？用三种拓扑对比看清交换机的价值。

| 拓扑 | 任意两卡通信 | 所需链路 | 适用规模 |
| --- | --- | --- | --- |
| 直接对连（全互联） | 直达 | $N(N-1)/2$ 条 | 2–8 卡 |
| 环形 / 网格 | 需多跳 | $O(N)$ 条 | 省线但慢 |
| 经交换机（星型） | 一跳直达 | $O(N)$ 条到交换机 | 8–72 卡 |

**核心权衡：全互联「快但费线」，环形「省线但慢」，交换机是「两者兼顾」**——GPU 只需一根线连到交换机，交换机内部负责任意两卡之间的转发。<span class="marginnote">这是网络设计的经典三选一：<strong>延迟、带宽、成本不可兼得。</strong>NVSwitch 用「一台昂贵但高效的交换机」换「每颗 GPU 只有一条昂贵的 NVLink」，在「域内全连接」这个目标下是最优解。同样的权衡在数据中心网络里还会出现一次。</span>

## 4 公式解析：全连接域的端口账

「全连接」到底要多少资源？用公式算一笔账，就知道为什么域规模有上限。

若 $N$ 颗 GPU 两两直连，需要的链路数为「$N$ 个点两两配对」：

$$
L_{\text{direct}} = \binom{N}{2} = \frac{N(N-1)}{2}
$$

逐项拆解：

- **$N$**：域内 GPU 数。
- **$\binom{N}{2}$**：$N$ 个点中任取 2 个配成一对的数目，即直连所需的链路数。
- **代入数字**：$N=8$ 时 $L=28$ 条；$N=72$ 时 $L=72\times71/2 = 2556$ 条——**每个 GPU 要 71 根线，物理上不可能。**

改用交换机后，每颗 GPU 只需一根线连到交换机，链路数降到 $O(N)$。**这就是「直连只适用于几颗卡、交换机才能织起几十颗卡」的数学理由。**<span class="marginnote">把 $O(N^2)$ 的链路压缩成 $O(N)$，正是交换机存在的全部意义。这也是「为什么全互联 GPU 集群必须用交换机、为什么域规模会停在机柜级」的底层逻辑——<strong>任何「两两都有高速通路」的需求，都要付出平方级的资源代价。</strong></span>

**给读者的落点**：NVLink 域的本质是「用交换机换全连接」——NVL72 的 72 颗 GPU 全互连，靠的是 18 颗 NVSwitch 把 $O(N^2)$ 的直连压缩成 $O(N)$ 的星型。

## 5 从 8 卡到 72 卡：NVSwitch 5 与域规模的跃迁

Hopper 时代的 NVSwitch 4 把域做到 8 卡；Blackwell 的 NVSwitch 5 把域扩大到 **72 卡**。这个跃迁靠的是两层升级：

**第一层，单端口带宽翻倍**。NVSwitch 5 的每个端口跑 NVLink 5 的 100 GB/s（双向），比 NVLink 4 的 50 GB/s 翻倍。同样的端口数，聚合带宽翻倍。

**第二层，交换机端口数增加**。NVL72 用 18 颗 NVSwitch，每颗承担多组 GPU 的互连，把 72 颗 GPU 全部纳入同一个域。18 颗交换机之间还要互联，保证「域内任意两颗 GPU 都能通信」。<span class="marginnote">把 72 卡织进一个域，交换层本身也成了一台「微型网络」：<strong>18 颗 NVSwitch 之间怎么连、每颗接多少 GPU，都要精心设计，否则某些卡对会绕远路。</strong>这也是 NVIDIA 把 NVL72 设计成「固定 72 卡整柜」的原因之一——拓扑最优解是固定的。</span>

**对软件的影响**：域越大，张量并行能切得越宽、MoE 的专家能放得越散。NCCL 会探测域内拓扑、为 AllReduce 选择最优路径。**「域规模」因此成为决定「模型并行度上限」的硬件变量。**

**给读者的落点**：读完这一篇，你应该能回答三个问题——NVSwitch 是做什么的（把 GPU 织成网的交换机）、NVLink 域是什么（一组全互连的 GPU）、为什么域不能无限大（全连接的资源代价是平方级的）。

## 6 术语速查与常见误解

NVLink 域相关的术语密度高，且容易与网络术语混在一起。收尾前理一张速查表：

| 术语 | 一句话定义 | 易混点 |
| --- | --- | --- |
| NVLink | GPU 间的高速点对点互连 | 与 PCIe 不同，专为 GPU 设计 |
| NVLink 域 | 一组全互连的 GPU 集合 | 与「网络域」无关，指互连拓扑 |
| NVSwitch | 为 NVLink 设计的交换机 | 与数据中心交换机不是一回事 |
| 全连接 | 任意两卡都有直达通路 | 「全」指节点对，不是「全部带宽相加」 |
| 对分带宽 | 切半后跨切面的总带宽 | 衡量「会不会堵」的标准量 |
| SHARP | 交换机内的网内归约 | 让 AllReduce 在数据经过时完成 |

**三个常见误解**：

**误解一：「NVLink 域 = NVLink 总带宽」**。域是「拓扑概念」，总带宽是「数字」——72 卡的域有 130 TB/s 聚合带宽，但「域」本身描述的是「任意两卡都有通路」，不是「带宽之和」。

**误解二：「NVSwitch 越多越好」**。交换机多了端口多、冗余好，但成本与功耗也涨；拓扑设计的任务是「用最少的交换机满足全连接需求」，不是「堆最多交换机」。<span class="marginnote">这个权衡与《集群级扩展》一篇的「对分带宽 vs 成本」同构：<strong>全连接不是免费的，域规模每扩大一档，交换层的代价就跳一档。</strong>NVL72 把域定格在 72 卡，正是「性能 × 成本」的平衡点。</span>

**误解三：「域内通信不要钱」**。NVLink 快，但仍有带宽上限（单卡 1.8 TB/s）；通信频繁到一定程度，域内也会排队。**「快」与「无限」是两回事。**

**给读者的落点**：NVSwitch 与 NVLink 域是「机柜即 GPU」的拓扑基础——理解它，你就理解了「为什么 72 颗 GPU 能像一颗 GPU 那样通信」。

## 7 小结

- **NVLink 域**：一组经 NVSwitch 或直接 NVLink 全互连的 GPU，域内任意两卡都有高速通路。
- **NVSwitch**：为 NVLink 设计的交换机，把「两两直连」的 $O(N^2)$ 链路压缩成「每卡一根线」的 $O(N)$ 星型。
- 三种拓扑的权衡：**全互联快但费线、环形省线但慢、经交换机两者兼顾**。
- 直连链路数 $\binom{N}{2}=N(N-1)/2$：8 卡要 28 条、72 卡要 2556 条——这就是「域必用交换机、规模止于机柜」的数学理由。
- NVSwitch 5 靠「端口带宽翻倍 + 端口数增加」把域规模从 8 卡扩到 72 卡。
- 域规模决定**模型并行度的上限**：域越大，张量并行切得越宽、MoE 专家放得越散。
