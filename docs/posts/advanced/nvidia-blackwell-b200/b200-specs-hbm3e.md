## 为什么从规格表开始

前五篇一直在「缩放」：裸片 → 超级芯片 → 机柜。这一篇落到最具体的一层：**B200 这颗 GPU 本身到底「是多少」**——多少个 SM、多少显存、多宽的总线、多快的时钟。规格表是硬件的「体检报告」，而理解 HBM3e 显存子系统则解释了规格表里最亮眼的一行：**192GB 容量 + 8 TB/s 带宽**。LLM 能不能单卡放下、张量并行切多细、KV 缓存能存多长上下文，全都由这行数字决定。

## 1 B200 规格全景表

以下数字来自 NVIDIA B200 官方文档，全部为每 GPU 口径：

| 项目 | 数值 |
| --- | --- |
| 架构 | Blackwell（计算能力 sm_100） |
| 晶体管数 | 约 2080 亿（双裸片，各约 1040 亿） |
| 制程 | TSMC 4NP |
| 裸片数 | 2，经 NV-HBI（10 TB/s）缝合 |
| SM 数 | 144（每 SM 128 个 FP32 CUDA 核心） |
| CUDA 核心（FP32） | 约 18,432 |
| 张量核心 | 第五代，每 SM 4 个，共 576 个 |
| L2 缓存 | 128 MB |
| 显存 | 192 GB HBM3e，8 组堆叠 |
| 显存带宽 | 8 TB/s |
| FP4 张量性能 | 约 9 PFLOPS 稠密 / 约 18 PFLOPS（2:4 稀疏） |
| FP8 张量性能 | 约 4.5 PFLOPS 稠密 / 约 9 PFLOPS（稀疏） |
| FP16/BF16 张量性能 | 约 2.25 PFLOPS 稠密 / 约 4.5 PFLOPS（稀疏） |
| 板级功耗（TDP） | 约 1000 W（需液冷） |
| 互连 | NVLink 5：1.8 TB/s；PCIe Gen6 支持 |

**读这张表有两个门道。** 其一，**晶体管数与 SM 数不按同比例放大**：B200 相比 H100，晶体管 2080 亿对 800 亿（2.6×），但 SM 数 144 对 132（1.09×）——多出来的晶体管大量投进了张量核心、NV-HBI、L2、安全与压缩引擎，而不是通用 CUDA 核心。其二，**FP4/FP8/FP16 性能严格按 2 倍递减**（9→4.5→2.25），这是张量核心「同一硬件、不同精度吞吐」的典型表现。<span class="marginnote">对照 H100：FP8 稠密约 1.98 PFLOPS，B200 的 4.5 PFLOPS 约是 2.3 倍；FP16 稠密 H100 约 0.99 PFLOPS，B200 的 2.25 PFLOPS 约 2.3 倍。低精度数字看似夸张，其实是「精度减半、吞吐翻倍」这一规律的延伸。</span>

## 2 HBM3e：把 DRAM 叠起来的显存革命

HBM（High Bandwidth Memory）与传统显存（GDDR）最大的不同在物理形态：

**GDDR 是平铺的**：一颗颗 DRAM 芯片贴在 PCB 上，通过很宽的 PCB 走线连到 GPU，位宽受限、功耗偏高；
**HBM 是堆叠的**：多层 DRAM 用**硅通孔（TSV，Through-Silicon Via）**垂直打通，叠成一座「塔」，再通过硅中介层（interposer）紧挨着计算裸片摆放。

**堆叠带来的直接好处是位宽可以做得极大。** 一组 HBM3e 堆叠提供 1024-bit 的接口位宽（16 个通道 × 64-bit），8 组就是 8192-bit——相比之下，GDDR 的接口位宽通常只有 256–512-bit。**位宽是带宽的第一要素**：带宽 = 位宽 × 数据率，把位宽做大，就能在不用把时钟推得过高（省功耗）的前提下获得高带宽。

B200 的 8 组 HBM3e 合计 192GB：**每组堆叠 24GB（8 层 × 24Gb 裸片）**，接口 1024-bit。为什么堆这么高、放这么近？因为**矩阵运算的「运算强度」极高**：每次从显存读一个数，张量核心要做很多次乘加，显存带宽就是吞吐的咽喉。<span class="marginnote">「运算强度（arithmetic intensity）= 每字节访存对应的浮点运算次数」是 Roofline 模型的核心轴，见《AI 芯片》与《高性能计算》专题。LLM 推理的 Prefill 阶段运算强度极高，对带宽敏感度相对低；但 Decode 阶段逐 token 生成、每 token 都要读全部权重，运算强度骤降，8 TB/s 的带宽就决定了生成速度。</span>

## 3 公式解析：8 TB/s 是怎么算出来的

显存带宽的公式是硬件课程的标准题：

$$
B = \frac{W}{8} \times R
$$

其中 $W$ 是总位宽（bit），$R$ 是数据率（GT/s，Giga-Transfers per second），除以 8 把 bit 换成字节。代入 B200：

$$
B = \frac{8 \times 1024}{8}\ \text{字节} \times 8\ \text{GT/s} = 1024\ \text{字节} \times 8\times10^9\ \text{次/s} = 8\ \text{TB/s}
$$

逐项拆解：

- **$8 \times 1024$**：8 组 HBM3e，每组 1024-bit 接口，合计 **8192-bit** 总线。
- **$\div 8$**：bit 转字节。
- **$8\ \text{GT/s}$**：HBM3e 的数据率，约 8 Gb/s 每引脚。注意这里不是「时钟频率」，而是「每周期一次的传输速率」——HBM3e 采用双沿/多沿采样，数据率是基础时钟的整数倍。
- **验算**：$1024\ \text{字节} \times 8\times10^9 = 8.192\times10^{12}\ \text{B/s} \approx 8\ \text{TB/s}$。

**关键结论：8192-bit 位宽 × 8 GT/s = 8 TB/s，是靠「极端位宽」而不是「极端时钟」换来的。** 如果改用 GDDR 的 512-bit 位宽，要拿到 8 TB/s 需要 128 GT/s 的数据率——远超当前任何 DRAM 的物理极限。这就是 HBM 路线的本质：**用堆叠与中介层换取位宽，用位宽换取带宽，用带宽换取功耗效率**。<span class="marginnote">同类推算也解释了 H100 的 3.35 TB/s（5 组 HBM3 × 1024-bit × 5.2 GT/s 上下）与 H200 的 4.8 TB/s。每代 HBM 的升级主线就是「堆叠更多层、数据率更高」，位宽结构则稳定在 1024-bit/组。</span>

## 4 HBM 与 GDDR 之争：为什么 AI 芯片都选 HBM

既然 HBM 这么贵、这么难造，为什么所有 AI 加速器（NVIDIA、AMD、英特尔、华为昇腾）都选了它？答案在「**每瓦带宽**」与「**面积效率**」两个词里。

对比 HBM3e 与消费级显存 GDDR7：

| 维度 | HBM3e | GDDR7 |
| --- | --- | --- |
| 每颗带宽 | 约 1.2 TB/s | 约 48 GB/s（单颗） |
| 位宽 | 1024-bit/堆叠 | 32-bit/颗 |
| 功耗 | 相对低（单位带宽） | 相对高 |
| 面积 | 占用中介层，紧贴芯片 | 平铺在 PCB |
| 成本 | 极高（堆叠 + 中介层） | 低 |
| 用途 | 数据中心 AI/HPC | 游戏显卡 |

**HBM 用「堆叠 + 中介层」换来两个 AI 计算最需要的特性**：一是带宽密度（每平方毫米的带宽远超 GDDR），二是把显存紧贴计算芯片、缩短物理距离、降低功耗。对张量运算这种「带宽即吞吐」的负载，HBM 是唯一现实解。<span class="marginnote">游戏显卡用 GDDR 是因为「便宜 + 够用」：游戏不要求单卡上百 GB 的容量与 TB/s 级带宽。而 AI 推理的 Decode 阶段每 token 都要读一遍全部权重，带宽不够模型就跑不快——<strong>需求不同，存储选型就分道扬镳</strong>。</span>

代价同样真实：HBM 的产能与成本是 AI 芯片出货的**硬约束**。一颗 B200 要 8 组 HBM3e 堆叠，而 HBM 的产量受限于台积电/三星/海力士的堆叠封装产能。这直接导致「AI 芯片卖多少」卡在「HBM 造多少」上——理解这一点，你就明白为什么「显存」在 AI 硬件新闻里永远是高频词。<span class="marginnote">市场上有句话：AI 算力的瓶颈在 HBM。NVIDIA 一边要 GPU 产能、一边要 HBM 产能，两者缺一不可。<strong>显存供应商（SK 海力士、三星、美光）因此成为 AI 产业链里被反复提起的名字。</strong></span>

## 5 小结

- B200 核心规格：**144 SM、约 1.8 万 CUDA 核心、576 张量核心、128MB L2、约 2080 亿晶体管、约 1000 W**。
- 显存：**192GB HBM3e，8 组堆叠，每组 24GB、1024-bit 接口，合计 8192-bit，8 TB/s**。
- HBM 的革命在于**堆叠 + TSV + 中介层**：用极大的位宽换取高带宽，而不是把时钟推高。
- 带宽公式 $B = W/8 \times R$
