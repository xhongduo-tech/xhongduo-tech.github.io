## 为什么从「层结构」开始

上一节回答了「为什么值得做条件计算」，这一节回答「做出来的东西长什么样」。GShard 的设计哲学极其克制：**不改动 Transformer 的整体骨架，只把每隔一层的「位置级前馈网络（FFN）」替换成混合专家层**。其余的一切——注意力、残差、层归一化——原封不动。
这种「只换一块积木」的做法意味着：你已经懂的 Transformer 知识全部复用，新增的只是 MoE 这一块积木的内部结构。
本文把这块积木拆开，看懂它，后面讲路由、讲并行才有抓手。

## 1 Transformer 块的「标准件」拆解

先回顾一个标准的 Transformer 块（block）。
每个块由两个子层堆叠而成：- **多头自注意力（MHA）子层**：让每个 token 与同序列的所有 token 交换信息；
- **前馈网络（FFN）子层**：对每个 token 逐位置做一次两层的非线性变换，通常写作

$$z = W_2\,\sigma(W_1 x)$$

其中 $\sigma$ 是激活函数（如 ReLU / GELU），$W_1 \in \mathbb{R}^{d_{\text{model}} \times d_{\text{ff}}}$ 先把维度放大到 $d_{\text{ff}}$（通常 4 倍），$W_2$ 再缩回 $d_{\text{model}}$。两个子层各自外面都挂着残差连接与层归一化：$h = x + \text{Sublayer}(\text{LN}(x))$。

在 Transformer 里，**注意力承担「token 之间」的交互，FFN 承担「每个 token 自己」
的变换**——这正是 MoE 的天然落点：FFN 是逐位置独立计算的，于是可以放心地把「每个 token 选哪条 FFN 通路」
交给路由器决定，而注意力必须保持稠密（所有 token 互相看见）。
<span class="marginnote">「token 之间稠密、token 之内稀疏」这条分工原则，在 GShard、Switch、Mixtral 等几乎所有 MoE 系统里都被保留。注意力若也被稀疏化，会破坏序列信息交换的完整性。</span>

## 2 用 MoE 替换「每隔一层」的 FFN

GShard 的具体做法是：**在编码器与解码器中，每隔一个 Transformer 块，把其中的 FFN 子层替换成一个 MoE 层**。
即一个共有 $N$ 层的模型，大约有 $N/2$ 层是 MoE 层，其余 $N/2$ 层保持稠密。

为什么是「每隔一层」而不是全部替换？三个原因：**保底能力**：稠密层保证每个 token 都有一份稳定的、不被路由风险影响的计算通路；
- **省通信**：MoE 层的 token 跨设备搬运（All-to-All）很贵，层数减半，通信量减半；
- **实践验证**：论文在消融里观察到「全部替换」带来的收益边际递减，而成本却线性上升。

于是整个模型呈现「稠密—稀疏—稠密—稀疏」的交替节律：奇数块走标准 FFN，偶数块走 MoE。
这套「每隔一层」的节奏后来成了 MoE 大模型的默认配方之一。
<span class="marginnote">为什么 MoE 层做在 FFN 位置而不是注意力位置？除了 FFN 天然逐 token 独立外，还因为 FFN 占据了 Transformer 参数的大头——把参数最重的地方稀疏化，省下的计算量才显著。这一观察直接决定了 MoE 层的收益上限。</span>

## 3 专家长什么样：就是个 FFN

GShard 里的**每个专家（expert）**，本身就是一个标准的两层 FFN：$$\text{FFN}_e(x) = W_2^e\,\text{GELU}(W_1^e x)$$

注意两点：- 每个专家有**自己独立**的 $W_1^e, W_2^e$，参数互不共享——这才是「专家」的实质：$E$ 个专家就是 $E$ 份互不相同的 FFN；
- 专家内部的宽度 $d_{\text{ff}}$ 与普通 FFN 保持一致（约 4 倍 $d_{\text{model}}$），所以单个专家很轻，**权重的大头来自「专家很多」而不是「单个专家很大」**。

在最大的 GShard 模型里，每个 MoE 层含 2048 个专家，专家总数约数万个。绝大多数专家在任一条样本上根本不参与计算——它们只是「储备」。
> 这里的「层内结构」只讲单个 token 如何流经 MoE 层；至于 2048 个专家怎么物理分布到上千张卡上，那是《专家并行》一节的内容。

## 4 参数账本：一个 MoE 层到底有多大

「专家很多、单个很轻」——到底多轻、多很多？算一笔账。设 $d_{\text{model}} = d$、专家内部宽度 $d_{\text{ff}}$，则：- 一个稠密 FFN 层：$W_1$ 是 $d \times d_{\text{ff}}$，$W_2$ 是 $d_{\text{ff}} \times d$，合计 $2 d d_{\text{ff}}$ 个参数；
- 一个 MoE 层：$E$ 个互不共享的专家，合计 $E \times 2 d d_{\text{ff}}$ 个参数；
- 取 GShard 大模型的典型值 $d = 1024$、$d_{\text{ff}} = 4096$、$E = 2048$：单个专家约 $2 \times 1024 \times 4096 \approx 8.4$M 参数，一个 MoE 层约 $2048 \times 8.4$M $\approx 17$B 参数。**一个 MoE 层的参数，是它要替换的那个稠密 FFN 层的约 2000 倍。** 这就是「参数大」的真正来源：不是某个专家特别大，而是专家「个数」乘出来的。
同样地，「算得省」也在此得到量化：一次推理只激活 2 个专家，激活参数约 $2 \times 8.4$M $\approx 17$M——**MoE 层把「170 亿参数的储备」压成了「1700 万参数的花销」**，两个数量级的杠杆，全靠稀疏激活兑现。**辨析｜易错点：** 不要把「MoE 层参数量大」误读成「MoE 层计算量大」。
参数量是「储备」、是静态的事实；计算量是「每次真正动用的部分」。
二者在 MoE 里被刻意解耦——这正是整个专题反复强调的那条主线。

把稠密 FFN 层与 MoE 层放到同一张账本上对比（取 $d=1024$, $d_{\text{ff}}=4096$, $E=2048$）：

| 项 | 稠密 FFN 层 | MoE 层 |
| --- | --- | --- |
| 参数量 | $2 d d_{\text{ff}} \approx 8.4$M | $E \times 2 d d_{\text{ff}} \approx 17$B |
| 每 token 激活参数 | 全部，约 8.4M | 仅 2 个专家，约 17M |
| 每 token 相对 FLOPs | 基准 1× | 约 2×（两个专家） |
| 显存需求 | 单卡即可容纳 | 必须跨设备切分 |
| 是否可稀疏 | — | 是（Top-2） |

表格读法：**参数与激活各走各的账**——同一层里「储备 17B」与「花销 17M」并存，这一行之差就是整篇《条件计算动机》里「容量 ≫ 计算」的层内版本。

## 5 一条 token 在 MoE 层内的流动

现在把一个 token $x_s$ 放进 MoE 层，走完全程：1. **打分**：路由器对 $E$ 个专家各算一个分数（细节见《Top-2 路由机制》）；
2. **选择**：选出得分最高的两个专家 $e_1, e_2$，并得到权重 $g_1, g_2$；
3. **分发**：token 被送往 $e_1, e_2$ 所在的设备；
4. **计算**：两个专家各自做 FFN 变换，得到 $\text{FFN}_{e_1}(x_s)$ 与 $\text{FFN}_{e_2}(x_s)$；
5. **加权合并**：$y_s = g_1\,\text{FFN}_{e_1}(x_s) + g_2\,\text{FFN}_{e_2}(x_s)$；
6. **残差**：$h_s = x_s + y_s$，再进入下一层。

![GShard MoE 层的数据流](/images/gshard/moe-layer-structure-1.svg)

被选中专家之外的通路完全不产生计算。整个 MoE 层对上层和下层的接口，与一个普通 FFN 子层完全一致——这正是「只换一块积木」的直接体现。

## 6 公式解析：一个 token 在 MoE 层的完整输出

把 2–4 步压缩成一个式子：$$
h_s = x_s + \sum_{i \in \{e_1, e_2\}} g_i(x_s)\,\text{FFN}_i(x_s)
$$

- **第一步，看懂 $\{e_1, e_2\}$**：求和只覆盖被选中的两个专家。这是与「软混合（soft mixture）」的本质区别——未选中的专家既不算 $\text{FFN}_i$，也不占计算量，这是「稀疏」二字的落点。
- **第二步，看懂权重 $g_i$**：$g_1, g_2$ 来自路由器输出，二者之和为 1（归一化后的概率）。它既是「加权系数」，也是让路由可微的关键通道——梯度通过 $g_i$ 回流到路由器参数。
- **第三步，看懂残差 $x_s$**：$h_s = x_s + y_s$ 保证即使路由出错，token 的原始信息也有一条恒等通路。它同时是「超容丢弃」时的兜底：当 token 因专家容量打满而无法路由时，直接让 $y_s$ 置零、只保留 $x_s$，等价于跳层。**辨析｜易错点：** 注意 $g_i$ 是「路由器的概率」，不是「专家的某种归一化输出」。有人误把 MoE 理解成对 $E$ 个专家输出做 softmax 加权——那是「软混合」的做法，计算量随 $E$ 线性增长；GShard 是「硬选择 + 软加权」，先硬选 2 个再按概率加权，两者计算复杂度完全不同。

## 7 术语速查表

| 术语 | 一句话定义 | 首次出现 |
| --- | --- | --- |
| 多头自注意力（MHA） | token 之间交换信息的子层，保持稠密 | §1 |
| 前馈网络（FFN） | 对每个 token 逐位置做两层非线性变换的子层 | §1 |
| MoE 层 | 把 FFN 替换为「专家 + 路由」的层 | §2 |
| 专家（expert） | 一个独立的双层 GELU-FFN，参数互不共享 | §3 |
| 容量因子（capacity factor） | 每个专家每批最多处理的 token 上限 | §5 预告 |
| 残差连接 | $h_s = x_s + y_s$ 的恒等通路，路由出错时的兜底 | §6 |
| All-to-All | token 跨设备搬往专家的集体通信 | §5 预告 |
| 超容丢弃 | token 因专家打满而跳过该 MoE 层 | §6 |

## 8 小结

- Transformer 块 = 注意力子层（token 间稠密）+ FFN 子层（token 内变换），MoE 替换的是后者。
- GShard **每隔一层**把 FFN 替换成 MoE 层，编码器、解码器都这么做，其余层保持稠密。
- **每个专家就是一个独立的双层 GELU-FFN**，参数互不共享；单个专家很轻，容量靠「专家个数」堆出来。
- token 在层内走六步：打分 → 选 Top-2 → 分发 → 计算 → 加权合并 → 残差。
- 层的对外接口与普通 FFN 子层一致，「只换一块积木」是 GShard 设计哲学的浓缩。

在下一节，我们放大「选择」这一步：路由器到底怎么打分、为什么是 Top-2、第二专家为什么还要随机——这就是**Top-2 路由机制**。
