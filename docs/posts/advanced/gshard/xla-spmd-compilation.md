## 为什么从「编译」开始

上一节画出了专家并行的切分地图，但还有一个悬而未决的问题：**这些 AllReduce、All-to-All 通信，到底由谁来写、谁来调度？** 手写的话，2048 张卡的通信代码几乎不可维护。
GShard 的回答是：**模型作者只管写「单设备语义」的代码，编译器自动生成多设备程序**。
这让「写模型」与「做并行」彻底分离——这正是 GShard 能优雅放大到 6000 亿参数的工程根基。
本文讲清楚这套「编译器魔法」的原理。

## 1 GShard 是什么：注解 + 编译器扩展

GShard 不是一个模型，而是一个**模块**，由两部分组成：1. **轻量注解 API**：模型作者在张量上标注想要的切分方式。
最常用的两种：   - `split(tensor, dim, num_partitions)`：把张量沿某维度切成若干份，分布到设备上；
- `replicate`：整张张量在所有设备各存一份副本。
2. **XLA 编译器扩展**：读取注解，把单设备的计算图翻译成多设备程序，并自动插入所需的集合通信。

模型代码本身仍然是「一台设备上怎么算」的普通代码——作者不需要知道 2048 张卡的存在。
切分的意图全部藏进注解，而执行细节全部交给编译器。**这就是 GShard 分离「模型描述」
与「并行实现」的设计哲学**：想换切分方案，改注解即可，不用动模型逻辑。
<span class="marginnote">这套「注解 + 自动切分」的思路与 PyTorch 的 DTensor、Megatron 的 tensor-parallel 注解、DeepSpeed 的 zero 切分殊途同归：都是把「并行怎么做」从「模型怎么算」里剥离出来。想对比各家自动并行方案的读者，可对照第四级《AI 基础设施》专题。</span>

## 2 SPMD：一份程序，跑遍所有设备

GShard 使用的并行执行模型是 **SPMD（Single Program, Multiple Data，单程序多数据）**：**所有设备执行同一份程序，但各自只操作自己拥有的数据切片**。

这和另一种经典方案 MPMD（多程序多数据，如流水线并行的 GPipe）有本质差别：**MPMD**：不同设备运行不同的子程序，跨设备的图规模随设备数线性增长，编译代价水涨船高；
- **SPMD**：只有一份程序，只是每个设备上的数据不同，编译代价与设备数无关——**O(1) 常数编译时间**。

编译器的 SPMD 切分器做的工作可以概括为三步：遍历计算图（XLA 的 HLO 中间表示）
→ 根据注解与数据依赖推断每个张量/算子的切分方案 → 把「本设备的计算 + 必要的通信」
重写进同一份程序。切分方案之间若冲突（比如某算子要求张量已 AllGather 完整），编译器自动插入通信原语补齐。<span class="marginnote">SPMD 的「O(1) 编译时间」是它的杀手锏：设备从 32 台加到 2048 台，编译一次的时间不变。这让 GShard 的规模伸缩实验几乎零成本——改一行配置就能重跑不同卡数的训练。</span>

## 3 自动插入的四种集合通信

XLA 的 SPMD 切分器在重写过程中，会按需插入四类集体通信原语：| 原语 | 作用 | 典型用途 |
| --- | --- | --- |
| AllReduce | 所有设备的结果求和，结果广播回各设备 | 稠密层梯度同步、张量切分的局部聚合 |
| AllGather | 收集所有设备的张量拼成完整张量 | 注意力层需要完整 token 序列时 |
| AllToAll | 每台设备向所有设备收发数据 | MoE 层的 token 分发与回收（见上节） |
| CollectivePermute | 按固定排列把数据交给指定设备 | 分组路由、序列位移类操作 |**关键洞察：模型作者从不手写这些通信。** 你只写 `split(..., dim=1, ...)` 或 `replicate(...)`，编译器看到「这个张量被切了，而下一个算子需要完整的它」时，就自动插入一个 AllGather；看到「专家参数被切分，路由把 token 发往其他设备」时，就自动插入 AllToAll。这保证了并行代码的正确性——**切分方案和通信的一致性由编译器保证，而非靠人肉**。

## 4 与 GPipe / 手写并行的对比

GShard 选择「自动切分」，代价是灵活性换来的工程简单。
它与主流替代方案的取舍一目了然：**GPipe（流水线并行，MPMD）**：把模型按层切成多段，逐段接力，引入「微批次」与「气泡」问题。
它把「层」作为切分单位，切分粒度粗；GShard 的注解可以切到任意张量维度，粒度细得多。
- **手写 AllReduce 的数据并行**：只复制、不切分，模型必须小到单卡放得下——对 600B 模型根本不成立。
- **Megatron 式张量并行**：切分的是单个矩阵乘的权重，通信密集、难以跨机器扩展；GShard 把「切分」集中在 MoE 层（通信稀疏的 All-to-All），把稠密层留给数据并行，各自扬长避短。

GShard 的定位是**面向「模型大、设备多、又要频繁换规模」的场景**：SPMD 让规模实验便宜，注解让切分方案可声明式地调，编译器的自动通信让正确性有保障。
这套取舍后来被 GSPMD（升级版，2022）继承，成为如今 JAX / TPU 上大规模训练的事实标准。
<span class="marginnote">GSPMD 把 GShard 的注解推广成「任何算子都可以自由切分」的通用方案，不需要作者显式标注。它是 GShard 的直系后代，想追更细的编译器细节可查 GSPMD 论文（arXiv:2105.06363）。</span>

## 5 一个具体的切分例子：MoE 层被编译成什么

把上一节的抽象落成一个具体例子。假设 4 张设备、4 个专家、一批 8 个 token，那么 MoE 层的「单设备程序」经 SPMD 切分后大致长这样：1. `x = replicate(输入)`：输入张量被标记为「复制」，每张卡各持一份；
2. `logits = dot(x, split(E, dim=专家轴, num_partitions=4))`：专家质心矩阵沿「专家维」切成 4 份，每卡只算自己 1/4 的得分——这是本地矩阵乘，无通信；
3. `top2 = argmax_topk(logits)`：本地选出 Top-2；
4. `dispatch = all_to_all(x, 按 top2 重排)`：编译器看到「token 要去专家宿主设备」，自动插入 All-to-All；
5. `y = expert_ffn(dispatch)`：每卡在自己那 1 个专家上做 FFN；
6. `result = all_to_all(y, 逆排列)`：结果送回原设备；
7. `out = x + weighted_sum(result)`：残差合并，MoE 层结束。

注意第 2 步：**「把专家矩阵切了」这一个注解，自动推导出后续所有的通信**。
你只写了 `split` 和 `replicate`，All-to-All、局部聚合全是编译器在做形状推断时自己补上的。这就是「声明式并行」：作者描述意图，编译器生成执行图。
<span class="marginnote">这一步一步的「形状推导 + 通信插入」，本质上是一个约束求解：每个算子的「输入形状 → 输出形状 + 所需通信」是固定的规则表，切分器沿图做前向传播即可。这也是为什么 SPMD 能把「程序员手写通信」这份苦差彻底消灭。</span>

## 6 公式解析：SPMD 的编译复杂度为什么是 O(1)

设设备数为 $D$。MPMD 方案要为每台设备生成一份程序，程序的规模正比于设备数；SPMD 方案所有设备共用一份程序，程序规模与 $D$ 无关：$$
T_{\text{compile}}^{\text{SPMD}} = O(1), \qquad
T_{\text{compile}}^{\text{MPMD}} = O(D)
$$

- **第一步**：SPMD 里「一份程序」就是「编译一次」——无论 $D=32$ 还是 $D=2048$，切分器都只重写这一份 HLO 图；- **第二步**：MPMD 里每台设备要独立编译各自的子程序（流水线各段的程序不同），图规模随 $D$ 线性增长；- **第三步**：编译只是「准备阶段」，真正上线跑起来之后，两者的执行效率差距取决于通信方案本身，而非编译时间——SPMD 的 O(1) 收益主要落在「快速迭代」和「大规模切分」两个环节。
- **第四步**：代价是 SPMD 的切分器必须在编译期静态推断所有张量的形状与切分方案，因此**所有张量形状必须静态可知**——这正是上一节「容量因子」存在的深层原因：专家收到的 token 数不确定，必须用静态上限（capacity factor）把形状钉死。**辨析｜易错点：** SPMD 不是说「每个设备算同样的东西」，恰恰相反，**每台设备算的是不同的数据切片**——「同一份程序、不同的数据」才是 SPMD 的精髓。程序相同、数据不同、通信自动补齐，这三者合起来才是完整的描述。

## 7 小结

- GShard = **轻量注解 API + XLA 编译器扩展**，模型代码保持「单设备语义」。
- 核心原语：`split`（切分）、`replicate`（复制）；执行模型是 **SPMD**（一份程序跑所有设备）。
- 编译器自动插入 **AllReduce / AllGather / AllToAll / CollectivePermute**，通信正确性由编译器保证。
- **O(1) 编译时间**让规模实验零成本；代价是要求张量形状静态可知（容量因子的深层原因）。
- GShard 的取舍：把切分集中在 MoE 层（稀疏通信），稠密层靠数据并行，与 GPipe / Megatron 路线互补。

在下一节，我们把前面的机制全部装进一次真实的大规模训练：6000 亿参数如何在 2048 张 TPU 上四天跑完——这就是**万亿参数模型训练**。
