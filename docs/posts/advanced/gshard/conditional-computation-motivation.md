## 为什么从「动机」开始

要读懂 GShard，先要回答一个问题：**为什么要做 MoE（混合专家）
？** 2020 年之前，把模型做大几乎只有一条路——把每一层都加宽加深，让每一个参数都参与每一条样本的计算。
这条路在「千亿」量级撞上了墙：参数越多，算得越慢、存得越贵，三者严格绑定。
而**条件计算（conditional computation）**提供了另一条路：让模型的**总容量（参数个数）**与**每次推理的计算量（FLOPs）**解耦。
本文是 GShard 这篇论文的第一课，回答「为什么值得拥有 6000 亿参数，却只为每个 token 激活其中一小撮」，也为后面的 MoE 层结构、Top-2 路由、负载均衡、专家并行打下概念地基。
<span class="marginnote">本专题的行进路线：动机（本文）→ MoE 层结构 → Top-2 路由机制 → 辅助负载均衡损失 → 专家并行 → XLA SPMD 编译 → 万亿参数训练 → 多语言翻译应用。逐节对应 Lepikhin 2020 论文的 §2–§7。</span>

## 1 稠密模型的「参数墙」

把一篇 Transformer 的参数量记为 $P$。稠密前向里每个参数都会被每个 token 流过，于是**每处理一个 token 的浮点计算量，与参数个数成正比**：$$\text{FLOPs}_{\text{dense}} \approx 2P \times (\text{前向 + 反向的激活次数})$$

这个「成正比」带来两个绑定：- **算力绑定**：参数量涨 10 倍，训练与推理的 FLOPs 也大约涨 10 倍；- **存储绑定**：参数必须常驻显存，显存占用随 $P$ 线性增长。

Kaplan 等人 2020 年的《Scaling Laws for Neural Language Models》把「质量随算力按幂律增长」
整理成经验律，但同一篇论文里还藏着一个反直觉的结论：**给定计算预算时，「更大的模型」
并不是最高效的用法**。真正棘手的问题是，稠密模型把「记住了多少知识」（容量）
和「算一遍要花多少钱」（计算量）焊死在一起——想让模型知道得更多，就必须让每次推理都更慢、更贵。
<span class="marginnote">Scaling Laws 的完整推导与「过参化」现象在第三级《大模型原理》专题有专文拆解。条件计算正是一类旨在打破「容量必须等价于计算量」这条绑定的设计。</span>

## 2 条件计算：容量与计算解耦**条件计算（conditional computation）**：一个模型内部包含大量可复用的「零件」，但每次处理一个输入时，只根据输入内容激活其中一小部分零件，其余零件这一轮不参与计算。

直觉来自生物大脑：人脑约 860 亿个神经元，但任意时刻只有约 1% 处于活跃放电状态——「海量的储备容量 + 稀疏的即时激活」。把这种分工移植进神经网络，就得到一个关键不等式：$$\text{容量} \gg \text{每次推理的实际计算量}$$

训练一个 6000 亿参数的模型，如果一次推理只激活其中 1%，那么单条样本的花销只相当于一个 6 亿参数的稠密模型——但模型的「知识上限」却按 6000 亿来计。

这个想法在深度学习里早有前身。2017 年，Shazeer 等人在《Outrageously Large Neural Networks》中提出了**稀疏门控混合专家（Sparsely-Gated Mixture-of-Experts, MoE）**：把一个大层替换成 $E$ 个相互独立的「专家」子网络，由**路由器（gating network）**为每个输入计算一个概率分布，只让 top-k 个专家真正参与计算。
他们在 LSTM 上把模型做到了 1370 亿参数，用的正是今天几乎所有 MoE 系统的祖先设计。
<span class="marginnote">Shazeer 2017 还留下两个被反复沿用的技巧：用「重要度损失 + 负载损失」抑制专家塌缩，以及给专家分组、让每个 token 只在组内路由以控制计算量。GShard 的 Top-2 路由与辅助损失正是它们的演化版。</span>

把三种「多参数」设计放到同一张表里，对照着看「省不省算力」的差别就一目了然：

| 设计 | 专家是否全部参与计算 | 每 token 计算量 | 是否省算力 | 可训练性 |
| --- | --- | --- | --- | --- |
| 稠密模型 | —（没有专家概念） | 正比于总参数 $P$ | 否 | 天然可训练 |
| 软混合（Jacobs 1991） | 是，全部求值再加权 | 正比于专家数 $E$ | 否 | 天然可训练 |
| 稀疏 MoE（Shazeer 2017 / GShard） | 否，只算被选中的 top-k | 与 $E$ 基本无关 | 是 | 靠直通式梯度 |

注意最后一行与第二行的区别：软混合省不了算力，恰恰是因为它「全部求值」；稀疏 MoE 把「算不算」从「全算」改成了「只算 top-k」，「省」字才真正落地。这张表也是后面《Top-2 路由机制》一篇反复要回到的坐标系。

## 3 从「几百亿」到「万亿」的鸿沟

Shazeer 2017 证明了稀疏激活在概念上的可行性，但想再上一个数量级，还差一块拼图：**工程系统**。
理由有三：第一，**参数放不下**。千亿参数哪怕只激活 1%，全部参数仍要分布到成千上万张加速卡上——这需要一套自动化的并行切分方案。

第二，**通信要跟上**。专家越多，路由与 token 搬运产生的通信越复杂，稀疏化省下的算力可能又被通信吃掉。

第三，**要可维护**。手写多机通信代码几乎不可维护，需要编译器自动把「单设备语义」的模型翻译成「多设备程序」。

GShard（Lepikhin 等，2020）正是为填平这条鸿沟而生的：它把 Shazeer 的 MoE 思想装进 Google 的 XLA 编译器，提出**轻量注解 API + SPMD 自动切分**，最终训练出 6000 亿参数的多语言翻译模型——这是当时公开报道的最大规模训练之一。
我们接下来几篇将沿着它的设计逐层解剖。

## 4 条件计算的早期尝试与两次转折

条件计算不是 2020 年的发明。它的历史本身就是一份「为什么难」的教科书：**1991 年，Jacobs 的专家混合（Mixture of Experts）**：把多个「专家网络」的输出按门控权重做加权平均，用于函数逼近与分类。
这是「混合」最早的形态——但它是**软混合**：所有专家都参与计算，门控只是加权系数，不省任何算力。
- **2013 年，Bengio 等的条件计算纲领**：在《Estimating or Propagating Gradients Through Stochastic Neurons》等工作中明确提出「条件计算」概念，主张让网络按输入稀疏激活。但当时的硬路由要么不可微（梯度断流、无法训练），要么退化成软混合（不省算力）。
- **2017 年，Shazeer 的稀疏门控 MoE**：把「硬选择 + 软权重 + 负载正则」三件套凑齐，才第一次让稀疏激活**既可训练、又真省算力**。

三次转折暴露出条件计算的两个难关：**路由必须可微**（靠直通式梯度），**选择必须真稀疏**（靠硬选而非软加权）。GShard 的全部设计，本质上都是在这两个难关上反复打磨的产物。
<span class="marginnote">1991 年 Jacobs 等人的论文是「Mixture of Experts」这一术语的源头，GShard 的 MoE 之名正是继承它。但前者是统计学习里的软混合，后者是稀疏系统里的硬选择——同名而异物，读文献时务必区分。</span>**辨析｜易错点：** 「混合」不等于「稀疏」。
软混合对 $E$ 个专家全部求值再加权，计算量随 $E$ 线性增长——这没有任何稀疏性收益；
稀疏 MoE 的精髓恰恰是「绝大多数专家根本不算」。二者共享「多个子网络 + 门控」的外壳，内里却是一笔「省算力」与「不省算力」的账。

把这条进化史压进一张表，看「省算力」与「可训练」两条轴如何先后被点亮：

| 年份 | 工作 | 混合方式 | 省算力？ | 可训练？ |
| --- | --- | --- | --- | --- |
| 1991 | Jacobs 专家混合 | 软加权、全部求值 | 否 | 是 |
| 2013 | Bengio 条件计算纲领 | 稀疏激活构想 | 是（设想） | 难 |
| 2017 | Shazeer 稀疏门控 MoE | top-k 硬选 + 软权重 + 负载正则 | 是 | 直通式梯度 |
| 2020 | GShard | Top-2 路由 + 辅助损失 + 专家并行 | 是 | 直通式梯度 |

四个格子分别补上了不同的洞：1991 给了「多子网络 + 门控」的框架，2013 给了「稀疏激活」的愿景，2017 让「真稀疏 + 可训练」兼得，2020 才把「稀疏 + 大规模工程」焊在一起。理解这张表，就理解了本专题要解剖的对象为什么是 GShard 而不是更早的工作。

## 5 公式解析：为什么稀疏激活能「白赚」容量

把问题量化。设模型总参数为 $P$，每次输入实际激活的参数为 $P_a$：$$
\frac{\text{FLOPs}_{\text{sparse}}}{\text{FLOPs}_{\text{dense}}} = \frac{P_a}{P} \ll 1, \qquad \text{但容量仍是 } P
$$

- **第一步，看懂分母**：稠密模型每 token 的 FLOPs 正比于总参数 $P$。
- **第二步，看懂分子**：MoE 模型每 token 只经过共享的稠密部分加上被选中的 $k$ 个专家，激活参数 $P_a$ 与 $P$ 无关，只由「选几个专家、专家多大」决定。
- **第三步，看比值**：$P_a/P$ 是「单次推理的真实代价 ÷ 模型总容量」。GShard 的 6000 亿模型里这个比值约在 1% 量级，于是**模型容量与单次计算量几乎彻底解耦**——这就是「容量白赚」的数学来源。**辨析｜易错点：** 很多人以为 MoE「节省了显存」。并非如此——**所有专家参数依然必须驻留显存**，稀疏只省计算量，不省存储量。专家并行的全部意义恰恰在于：把这份「省不掉的存储」摊到几千张卡上，同时靠稀疏把「计算量」压下来。这一点在后续《专家并行》与《XLA SPMD 编译》两篇里会反复出现。

## 7 小结

- **稠密模型**把容量与计算量焊死：参数量涨，FLOPs 与显存同比例涨。
- **条件计算**的核心是「容量 ≫ 激活量」：总参数量可以很大，单次推理只激活一小撮。
- 思想源头：生物大脑的稀疏放电、Shazeer 2017 的稀疏门控 MoE（top-k 路由、1370 亿参数 LSTM）。
- 从 Shazeer 到 GShard 的鸿沟是**工程系统**：自动并行切分、路由通信、编译器支持。
- GShard 用「轻量注解 + XLA SPMD 自动切分」把 MoE 放大到 6000 亿参数。

在下一节，我们走进 GShard 的 MoE 层本身：它长什么样、放在 Transformer 的哪个位置、一个 token 在层内是如何流动的——这就是**MoE 层结构**。
