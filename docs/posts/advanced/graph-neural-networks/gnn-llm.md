## 为什么从 GNN 与 LLM 结合开始

把整个专题放在时间线上看：图嵌入（2014）→ GNN（2017）→ 图自监督（2020）→ **图 × LLM（2023–）**。每一次跃迁，都是「图上的知识来源」被拓宽一次：从「只看结构」到「结构 + 特征」再到「结构 + 海量文本」。大语言模型带来的是「语义知识」——它读过维基百科、论文、代码，知道「苹果」通常与「手机、公司、乔布斯」相关；但 LLM 对「图结构」的理解是天然的短板：它不是为关系推理设计的。

**GNN 与 LLM 的结合，本质是把两种知识拼起来：LLM 的语义世界知识与 GNN 的结构世界知识**。这一篇不追赶具体模型，而是给一个「分类框架」——三种结合方式（LLM 喂 GNN、图喂 LLM、统一建模）各自解决什么问题、代价是什么，并落到文本属性图与图推理两个典型场景。它是本专题的收官之篇，把前面所有「结构」与这里的「语义」焊在一起。

GNN 与 LLM 的结合是当前图领域最活跃的方向，但也是最容易「赶时髦」的地方——三个术语（图、语言、大模型）摆在一起不等于有洞见。真正的问题只有一个：语义知识（LLM 有）与结构知识（GNN 有）如何在同一个系统里互补。把这个问题想清楚，三种结合方式的选择就顺理成章。

本篇按「互补性 → 三种结合方式 → 两个典型场景 → 展望」展开，聚焦「怎么选型」而非「哪个模型最强」。

先从「文本属性图」这个最小的结合场景入手，再谈更激进的结构。

## 1 两条知识的互补

先看清各自的「半场」：

| 维度 | GNN | LLM |
| --- | --- | --- |
| 擅长的 | 结构推理、关系传播、可解释、大规模图 | 语义理解、常识、开放世界泛化、少样本 |
| 短板 | 依赖顶点特征质量；读不懂文本语义 | 看不见结构；长图上「算不动」；幻觉 |
| 数据 | 图 + 结构标签 | 海量文本 |
| 推理 | 沿边传播，$O(\|E\|)$ | 自回归，$O(\text{序列长})$ |

一张文本属性图（text-attributed graph）最能说明问题：Cora 论文图里，每个顶点是一篇论文，其特征是**标题与摘要文本**。传统 GNN 把文本做词袋（bag-of-words）当特征——丢掉了全部语义；LLM 能读懂摘要，却看不到「引用关系」。**两边各自守着半张图，都在浪费另一半。**

**辨析｜易错点：** 「GNN + LLM」不是「用哪个替代哪个」，而是「谁的输出喂给谁」。选错方向，代价翻倍：LLM 直接读整张图，上下文长度装不下大图；GNN 直接学 LLM 生成的稠密向量，语义是进去了，但「图质量差 + 向量贵」的双重问题一起来。**先明确你要补的是哪半边，再决定结合方式。**

## 2 三种结合方式：分类框架

把 2023 年以来的工作放进一个三层框架，方向感立刻清晰：

**A. LLM 增强 GNN（文本特征 / 标签生成）**：让 LLM 当「语义特征提取器」。用 LLM 把顶点文本转成稠密向量（或生成增强标签），再喂给 GNN。**GNN 保持主力，LLM 打辅助。** 代表：TAPE（用 LLM 为每个顶点生成描述文本，再编码成特征）。

**B. GNN 增强 LLM（图进上下文）**：把图结构「线性化」成文本（「顶点 A 连接 B、C」），或把 GNN 编码的图表示作为额外 token 拼进 LLM 的上下文，让 LLM 基于结构做推理。**LLM 保持主力，图打辅助。** 代表：GraphLLM、GraphToken。

**C. 统一建模（图作为 LLM 的输入空间）**：把 LLM 的前几层直接作用在图上（把图当序列、顶点当 token），或设计「图感知的注意力」让 LLM 原生处理结构。**两者深度耦合。** 代表：GraphGPT、OneForAll。

| 方式 | 谁是主力 | 谁打辅助 | 典型场景 | 主要代价 |
| --- | --- | --- | --- | --- |
| A：LLM 喂 GNN | GNN | LLM 造特征 | 文本属性图分类 | 特征生成成本、LLM 幻觉污染 |
| B：图喂 LLM | LLM | GNN 编码结构 | 图问答、图推理 | 上下文长度、结构线性化丢失 |
| C：统一建模 | 深度耦合 | — | 图上指令理解 | 训练成本、图规模受限 |

**辨析｜易错点：** A 类看起来最「便宜」，但有个隐蔽坑：**LLM 生成的特征如果不稳定（同一文本两次生成不同向量），会直接变成 GNN 的输入噪声**。工程上要么用「确定性解码 + 固定种子」，要么把 LLM 特征与原始特征拼接（不替换），让 GNN 自己权衡。

## 3 文本属性图：LLM 造特征的正规军

**文本属性图（text-attributed graph, TAG）**：顶点带一段自然语言描述（论文摘要、商品评论、用户简介）。这是 A 类结合的主战场。传统做法（词袋）把文本「剁碎」成词频，语义全丢；LLM 时代的做法是**让 LLM 读懂文本，再吐给 GNN 能用的东西**：

- **语义特征**：让 LLM 为每条文本生成一段**描述 / 摘要 / 标签**，再用一个文本编码器（或 LLM 的最后一层）压成稠密向量，作为顶点特征。TAPE 让 LLM 生成「简洁描述文本」后再编码，比直接编码原始文本更聚焦。
- **增强特征**：不只一个向量——让 LLM 生成「关键词列表、实体链接、结构化属性」，拼成更丰富的特征。
- **虚拟邻居**：让 LLM 判断「两个顶点是否相关」（哪怕无边），把「语义相关但结构不相连」的顶点对补成虚拟边——**让 GNN 的结构传播也能利用语义相似性**。

**辨析｜易错点：** LLM 生成的「描述」有幻觉风险——它可能在摘要里加进原文没有的信息，这些幻觉会被 GNN 当作特征传播。缓解办法：**特征生成时用「抽取式」而非「生成式」**（让 LLM 从原文抽关键词，而不是自由发挥写摘要），或对生成结果做一致性校验。

## 4 图推理：让 LLM 在图上走一步

B 类结合的代表场景是**图推理**——「从 A 出发经过关系 R1、R2 能到达谁？」传统做法是 KG 上的规则推理或 GNN；现在有个大胆的替代：**把图线性化成文本，让 LLM 直接推理**。流程是：

1. 把目标顶点的一跳/多跳邻域描述成文本（「A 创立了苹果；苹果总部位于美国」）；
2. 把问题连同邻域文本一起喂给 LLM（few-shot 或 zero-shot）；
3. LLM 输出答案与推理步骤。

优势：**零训练、可解释（LLM 会说人话）、少样本泛化强**；软肋：**上下文长度限制**——邻域一放大就溢出；**结构迷失**——线性化后的图在 LLM 眼里是「一段文字」，长路径推理容易幻觉；**没有真正的结构计算**——LLM 不会「数路径条数」这类精确结构运算。<span class="marginnote">实测表明：LLM 在「小图 + 短路径」上推理不错（几乎达到监督 GNN），但图一大、路径一长就崩——它擅长的是「凭语义猜」，不是「按结构算」。这正是「GNN 编码结构 + LLM 组织语言」混合方案的动机：让 GNN 负责结构、LLM 负责表达。</span>

**辨析｜易错点：** 图线性化的**顺序与表示方式**对 LLM 推理质量影响巨大——按 BFS 排邻域、用「A 的 关系 是 B」句式、加显式路径标记，都能显著改善。提示工程的每一点细节都在 LLM 图推理里放大；且**「链式思考（CoT）」的每一步都要把中间节点也喂进去**，否则 LLM 会「跳步」产生幻觉。

### 一个 TAPE 式特征生成的完整例子

用 Cora 的「一篇论文顶点」把 A 类结合（LLM 喂 GNN）走一遍。设顶点是论文「Graph Attention Networks」，原始特征是它的标题 + 摘要的词袋向量。

- **第 1 步（LLM 生成描述）**：把标题摘要喂给 LLM，提示词「请用一句话总结这篇论文的核心贡献」。LLM 输出：「本文提出在图上用注意力机制加权聚合邻居信息，并验证多头注意力的有效性。」——这是**针对顶点的语义浓缩**，比原始摘要更聚焦。
- **第 2 步（编码成特征）**：用一个文本编码器（如 Sentence-BERT 或 LLM 的 pooling 层）把这段描述压成稠密向量 $\boldsymbol{e}_v$，作为 GNN 的顶点特征。
- **第 3 步（增强）**：把 $\boldsymbol{e}_v$ 与原始词袋向量**拼接**，或让 LLM 再抽一组关键词补进特征——GNN 既看到语义向量，也看到离散信号。
- **第 4 步（虚拟邻居）**：让 LLM 判断「这篇论文与引用列表之外的哪些论文主题相近」，若相关则补一条虚拟边，让 GNN 的结构传播也能「借语义」。

实验观察（TAPE 等论文）表明：在标签稀疏的文本属性图分类上，这种「LLM 特征 + GNN」能比「词袋 + GNN」高出几个百分点——**语义信息被成功注入了结构模型**。但代价也明确：LLM 推理每顶点一次调用，几百万顶点就需海量算力；且 LLM 的「总结」可能引入幻觉，需要用「抽取式 + 校验」来兜底。

## 5 展望：从「拼接」到「原生」

三种方式目前都是「拼接」，真正的愿景是**原生图语言模型**——把图结构直接内建进 LLM 的注意力机制：顶点当 token、边当注意力偏置、关系当特殊 token。这条路（C 类）有三个拦路虎：

- **规模**：图动辄上亿顶点，LLM 的注意力是 $O(n^2)$，必须配合图稀疏化（只在邻居间算注意力）；
- **训练代价**：从头训练图原生 LLM 的算力要求远超「GNN + LLM 拼接」；
- **评测缺位**：图与语言混合任务的标准基准还不成熟，无法公平比较各家。

务实的中间态是「**GNN 当图编码器 + LLM 当语言解码器**」：GNN 把大图压成紧凑的结构表示，LLM 把它翻译成自然语言答案——**结构留给图的专家，语言留给语言的专家**。这大概是未来几年落地最稳的形态。<span class="marginnote">当前学界共识（2023–2024 综述）是：<strong>「GNN + LLM」的收益主要在少样本、零训练、可解释性</strong>，而在「大规模、精确结构推理」上仍不如纯 GNN。推荐的工程路线：任务需要语义 → A 类（LLM 造特征）；需要结构化输出 → B 类（图进上下文）；两者都要 → GNN 编码 + LLM 解码。</span>

## 6 小结

- **GNN 与 LLM 互补**：GNN 强在结构、LLM 强在语义；文本属性图是「两边各守半张图」的典型。
- 三种结合方式：**A 让 LLM 造特征喂 GNN**、**B 把图线性化喂 LLM**、**C 原生统一建模**——按「补哪半边」选型。（本篇为纯概念 / 架构主题，核心对比表见第 2 节，替代公式解析。）
- **文本属性图**是 A 类主战场：LLM 生成描述 → 编码成特征 / 虚拟邻居；警惕幻觉污染特征。
- **图推理**是 B 类代表：邻域线性化 + 提示工程；LLM 擅长语义猜、不擅长结构算，上下文与幻觉是天花板。
- 原生图 LLM 受制于规模、训练代价与评测缺位；**GNN 编码 + LLM 解码**是近期最稳的落地形态。
- GNN 与 LLM 互补：结构 vs 语义，文本属性图是「两边各守半张图」的典型。
- 三种结合方式（A 喂特征 / B 喂上下文 / C 统一建模）按「补哪半边」选型，别追求最潮。
- LLM 生成特征的**幻觉污染**是 A 类的隐蔽坑：抽取式 + 一致性校验可缓解。
- B 类的图线性化与提示细节对 LLM 推理质量影响巨大——LLM 擅长语义猜、不擅长结构算。

至此，我们从「图的表示」出发，走过「GNN 模型」、「训练与应用」，最终来到「GNN × LLM」的前沿。**「从极限到大模型」的图神经网络这一段到此收束：结构是图的骨架，语义是图的血肉，而把两者缝在一起的，正是这一路学来的全部工具。**

作为本专题的收官，值得回望一遍这条学习路径：先是「图是什么」（表示与类型），再是「怎么把图变成向量」（游走与谱），然后是「怎么用神经网络读图」（消息传递与它的种种变体），最后是「怎么让图服务于真实世界」（训练、生成、推荐、分子、物理、知识图谱、大模型）。每一层都是下一层的铺垫，而贯穿始终的暗线只有两条——**结构如何被表达，表达如何被使用**。

从这里继续往前走，无论是深入某个应用领域，还是转向第四级《生成模型》《AI for Science》里的相邻主题，你都已经握着图表示学习的地图。
