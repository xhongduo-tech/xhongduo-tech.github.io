# 图嵌入的评价

## 为什么从评价开始

前面两篇教会了怎么把顶点变成向量，但还缺最后一块拼图：**怎么判断向量学得好不好。** 这不是一句「看效果」能糊弄过去的——「效果」本身就需要定义。把嵌入送进分类器、跑出准确率，那叫下游评测；直接算「图上相似的顶点在向量里是否相近」，那叫结构评测。两者回答的问题不一样，结论也常常互相矛盾：一个嵌入在社区分类上大杀四方，在链路预测上却平庸——这在图表示学习里是常态，不是 bug。

这一篇为「评价图嵌入」立一套方法论：**先问你要的是什么，再选评测协议，最后警惕数据划分与随机性的坑。** 这套方法论不只适用于 DeepWalk / Node2Vec，它也是后面评价 GNN 时反复使用的通用标尺——理解了「怎么评价」，才能理解「不同模型强在哪」。

## 1 两类评价：结构保真与任务表现

图嵌入的评价分两条大路，各有适用场景：

**结构保真评价（结构指标）**：不引入任何下游任务，直接在嵌入空间里检查「图上的关系有没有被保留」。

- **链路预测**：随机隐藏一部分边，用嵌入预测「这条边是否存在」。做法是把顶点对 $(u,v)$ 的嵌入变成特征（点积、余弦、距离等），训练一个二分类器或直接阈值化，度量用 AUC、AP。
- **社区 / 聚类评估**：把嵌入做 K-means 聚类，与真实社区标签比对，度量用 NMI、调整兰德指数 ARI。
- **图重建**：从嵌入反推「顶点是否相邻」，看重构的邻接矩阵与原图的重合度。

这类评价的好处是**可解释**：链路预测的 AUC 直接告诉「嵌入里有没有保存邻接信息」。但它的局限同样明显：没有任务上下文，「保真」未必等于「有用」。

**任务导向评价（下游表现）**：把嵌入当作特征，喂给一个浅层模型去完成真实任务。

- **顶点分类**：用带标签的一部分顶点训练 logistic 回归 / 线性 SVM，在其余顶点上测准确率 / F1——这是最主流的基准。
- **链路预测**、**顶点回归**（预测连续属性）、**图分类**同理。
- 关键约定：**下游模型要足够简单**。如果用一个深层的 MLP 在嵌入之上再大展拳脚，你评测的是 MLP 而不是嵌入——评测惯例是「线性分类器 + 嵌入」，让嵌入自己承担表达重任。<span class="marginnote">「嵌入 + 线性分类器」这一评测协议几乎是图表示学习论文的标准动作，最早由 DeepWalk 确立。它把「嵌入质量」与「下游模型复杂度」解耦：线性模型学到多少，直接反映嵌入的信息量。</span>

## 2 评测基准：数据集与比谁

评价必须有参照系。图嵌入的标准基准经历了三轮迭代：

**早期基准**：Zachary 空手道俱乐部（34 个顶点，社区分类经典小图）、Karate / Dolphins / Les Misérables 等几十上百顶点的小图，适合快速验证直觉，但统计噪声大。
**中等规模**：Cora、Citeseer、Pubmed——论文引用网络，顶点是论文、边是引用、标签是研究领域。Cora 约 2700 顶点，是「半监督顶点分类」事实上的标准测试场，后文 GCN 一文的实验也用它。
**大规模**：Reddit、社交网络、蛋白质相互作用（PPI）网络等，顶点数十万到上亿，考验方法的**可扩展性**而不只是精度。

**对比的基线**也要成体系，通常分四层：

| 层 | 方法 | 说明 |
| --- | --- | --- |
| 非学习 | 度、PageRank、共邻数 | 不学嵌入，仅用统计量，作为「下限」 |
| 矩阵分解 | Laplacian 特征映射、GraRep | 谱方法，线性代数直出嵌入 |
| 随机游走 | DeepWalk、Node2Vec、LINE | 游走 + 语言模型目标 |
| 深度图模型 | GCN、GraphSAGE、GAT | 共享参数、归纳式（后面几篇） |

正确的评测姿势是**同协议、同数据集、同划分**地横向比较——只换模型，不换评测器，否则比较没有意义。

## 3 三种评测协议的坑：数据划分与随机性

图数据与 i.i.d. 数据最大的不同是**样本不独立**：两个相邻顶点共享邻居，把它们的标签一起放进训练集，就发生了**信息泄漏**——测试顶点早在训练时「间接见过了」自己的邻居。围绕这一点，形成三种经典评测协议：

**随机划分（random split）**：标签按顶点随机分成训练 / 验证 / 测试。简单，但泄漏严重——尤其当图稠密、标签有强社区性时，测试准确率会虚高。它适合「在同一张图上，谁的表征更强」的相对比较，不适合报告绝对性能。
**按时间划分（temporal split）**：按边或顶点的出现时间切分，用早期训练、晚期测试。这是链路预测的标准做法，能模拟真实部署，但要求数据带时间戳。
**按图划分（graph split）**：把顶点划分成若干不连通的子图，用一部分子图训练、另一部分测试。这考验**归纳式**泛化——模型见过的图与没见过的图来自同一分布但结构不同，GraphSAGE 一文的 PPI 实验即用此协议。<span class="marginnote">按图划分是「模型能不能推广到没见过的图」的真正试金石。转导式方法（DeepWalk 查表）在此协议下直接失效——测试图的顶点根本没有嵌入；这正是 GNN 出现的重要动机之一。</span>

**辨析｜易错点：** 评测结果必须配**随机种子与方差报告**。DeepWalk 类方法依赖随机游走采样，同一份代码、不同种子，F1 可差几个点。规范做法是：跑多次（≥5）取均值 ± 标准差，或至少报告多次中位数。单次运行的数字不具有可比性。

## 4 评价链路预测：把「有没有边」变成可评测的问题

链路预测是图嵌入最常用的任务化评价，做法值得单独说清：

1. **隐藏**：随机（或按时间）移除一部分边，作为正样本；等量采样**不存在的顶点对**作为负样本。
2. **编码**：对每个候选顶点对，把两端嵌入组合成一条特征——常用点积 $\boldsymbol{z}_u^\top \boldsymbol{z}_v$、余弦相似度、或拼接后过一个小网络。
3. **评测**：训练二分类器，用 AUC / AP 度量排序质量。

这里的坑是**负样本的合理性**。随机采「不存在的边」虽然省事，但很多「负样本对」在图上其实距离很近（二级邻居），对模型过于友好；更严格的做法是负采样时考虑图的闭包性质（如「负采样需避免与正样本重叠」），或者用「随机负样本 + 困难负样本」的组合。另一个细节：**评测链路预测时，隐藏边不能直接参与嵌入训练**——如果嵌入是用包含所有边的图学的，测试边的信息已经泄进去了，AUC 不可信。正确流程是先隐藏，再在剩余图上训练嵌入，再预测隐藏边。<span class="marginnote">「先隐藏再训练」是链路预测评测的底线纪律。违反它的常见写法是：用全图学嵌入 → 隐藏边 → 预测——这样的 AUC 往往高达 0.95+，但不代表模型真的会推理，它只是「记住了」那条边。</span>

### 一个评测协议的完整决策树：先回答五个问题

评测协议的选择可以压缩成五个连续问题，逐个回答，评测设计就定了：

1. **任务要「表示质量」还是「模型质量」？** 前者 → 结构保真指标（链路预测 AUC、聚类 NMI）；后者 → 下游任务指标（分类 F1）。两者都要，就分开报告，别混在一个数里。
2. **数据带时间戳吗？** 带 → 按时间划分（用早期训练、晚期测试），模拟真实部署；不带 → 随机划分或按图划分。
3. **模型是归纳式还是转导式？** 归纳式 → 优先按图划分（测「没见过的图」）；转导式 → 只能用同一张图的随机划分。
4. **标签数量少不少？** 极少 → 用「嵌入 + 线性分类器」的协议，并跑多次取均值；充足 → 可以放开下游模型复杂度。
5. **负样本怎么来？** 链路预测必须「先隐藏边、再训练、再预测」；负采样用「随机 + 困难」组合，别只用随机。

把这五个问题答完，评测协议基本不会再犯「泄漏」与「不可比」的低级错误。特别提醒第 4 条：**跑多次（≥5）取均值 ± 标准差**是图表示学习论文的底线——游走采样与训练随机性让单次结果毫无可比性，而「均值 ± 方差」报告本身就能暴露出「模型在哪些数据集上不稳」。

**辨析｜易错点：** 五个问题里最容易踩的是第 2 条——很多人把「带时间戳的数据」默认成「静态图」，用随机划分，导致测试边「在训练时已被隐式看见」。时间划分在链路预测里是铁律，不是可选项。

## 5 公式解析：链路预测的 AUC 度量

链路预测的排序质量常用 **AUC（Area Under ROC Curve）** 度量，其几何定义是「随机一个正样本对排在随机一个负样本对前面的概率」：

$$
\mathrm{AUC} = \frac{1}{n_+ \, n_-} \sum_{e_+ \in \mathcal{E}_+} \sum_{e_- \in \mathcal{E}_-} \mathbb{I}\big[\mathrm{score}(e_+) > \mathrm{score}(e_-)\big]
$$

- **第一步，读懂符号**：$\mathcal{E}_+$ 是正样本（真实边）集合，$\mathcal{E}_-$ 是负样本（伪边）集合，$n_+ = |\mathcal{E}_+|$、$n_- = |\mathcal{E}_-|$；$\mathrm{score}(e)$ 是模型给这条候选边打的分数（如点积）。
- **第二步，读懂指示函数**：$\mathbb{I}[\cdot]$ 为 1 当且仅当括号内成立。这一项在说：**这一对「正—负」样本里，正样本的分数是不是更高。**
- **第三步，读懂外层平均**：对全部 $n_+ \cdot n_-$ 个「正—负」组合取平均，得到的就是概率解读。AUC = 0.5 表示随机乱猜（正样本不比负样本更可能排前），AUC = 1.0 表示完全分开，0.5 以下说明打分方向搞反了。
- **第四步，与分类准确率区分**：AUC 不依赖阈值，度量的是**排序**而非「分对多少」；这在「正负样本极不平衡」时（真实边远少于伪边）比准确率稳健得多。链路预测里「准确率」几乎总是被 AUC / AP 替代，就是这个原因。

## 6 小结

- 评价分两条路：**结构保真**（链路预测、聚类、图重建）与**任务导向**（顶点 / 图分类、回归）；前者解释性强，后者实用性直接。
- 评测协议有三种：**随机划分、按时间划分、按图划分**——各自回答「同一图上的相对强弱」「时间泛化」「未见图泛化」。
- 数据划分泄漏是头号坑：**隐藏边不能参与嵌入训练**，训练测试要按图或按时间切开。
- 下游模型必须**足够浅**（线性分类器 + 嵌入），否则评的不是嵌入；结果要**多次取均值 ± 标准差**。
- AUC 度量排序质量而非阈值准确率，天然适配正负样本极不平衡的链路预测。
- 评测协议先于模型：数据划分、负样本、下游模型复杂度、随机种子，每一项都决定「比的是不是模型」。
- 结构保真与任务表现可能矛盾：AUC 高不代表下游 F1 高——报告两者，并分开解释。
- 链路预测评测的底线纪律：**先隐藏边、再训练、再预测**；违反它得到的 AUC 没有意义。

在下一篇，我们从「图上随机游走」转向「图上的信号与频率」：用**谱图理论**给图装上傅里叶分析。理解它，是下一章 GCN 推导的直接前奏。

本篇的评测方法论在谱图理论里依然有效：谱方法的「表示质量」同样要用链路预测与聚类去验证——工具换了，标尺没换。
