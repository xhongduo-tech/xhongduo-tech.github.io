## 为什么从 BEVFormer 开始

上一节我们把 BEV 感知的问题框架立住了：**定义一个以自车为中心的网格，为每个网格位置跨视角收集证据**。这一节讲把它做到极致的一个方案——**BEVFormer**（ECCV 2022）。它的贡献一句话就能说清：**让 BEV 网格上的每个位置，自己学会「该去哪颗相机的哪个像素采样」**，而不是像 LSS 那样先把深度估出来再硬投影。

BEVFormer 是 2022 年以来多相机 BEV 感知的「事实标准之一」，也是理解后续所有 Transformer 系感知（PETR、StreamPETR、Occupancy）的入口。<span class="marginnote">它名字里的「Former」就是 Transformer；但 BEVFormer 的注意力是「可变形」的——它不在整张图上做全局注意力，而是在每个查询点附近采样少数几个点。这一设计直接继承自 2D 检测里的 Deformable DETR（见本章《基于相机的 2D 目标检测》）。</span>先立住一句话：**BEVFormer = BEV 网格（问题） + 可变形注意力（查证手段） + 时序注意力（把历史当上下文）**。

## 1 从 LSS 到 BEVFormer：显式深度的天花板

在讲 BEVFormer 前，先看清它要超越的东西。LSS 式方案（下一节详讲）的流程是：先用网络预测每个像素的深度分布，再把特征沿深度「抬升」、投影到 BEV。这条路有一个结构性的脆弱点——**深度估计一旦出错，投影就整体错位**。而深度恰恰是多相机几何里最难估准的量：它依赖纹理、遮挡与运动，在弱纹理、远距离、逆光场景下极易翻车。

BEVFormer 换了一种思路：**不显式估深度，而是把「深度」变成一个隐变量**。它让每个 BEV 位置直接对各个相机的图像特征做「注意」（attention），注意力自己决定「这个位置的信息主要来自哪个深度、哪块图像区域」。深度不再是一个要先算对的中间量，而是被「软」地吸收进了注意力权重里。这个转变，把「先几何后感知」变成了「感知与几何联合学习」——端到端、无需深度监督，这正是它后来居上的原因。

这个转变还有一个附带收益：**跨相机一致性**。显式深度方案里，同一物体在相邻两路相机中的深度是各自独立估计的，可能互相矛盾；而注意力方案里，同一个 BEV 位置同时采多路相机的特征，网络必须协调各方证据，天然带有「让证据互相印证」的压力——矛盾的深度信息在采样环节就被软性地协商掉了。

## 2 BEV queries：以问题为起点的网格

BEVFormer 的输入不是图像特征直接投影，而是一组**可学习的 BEV queries**：一个 $H \times W \times C$ 的参数张量，其中每个位置对应 BEV 网格上的一个单元（如 200 × 200，覆盖 100 m × 100 m，每格 0.5 m）。<span class="marginnote">200×200 的含义是：自车前后左右各约 50 m，一格 0.5 m——这正好覆盖高速场景下「当前决策所需的视野」。网格大小与分辨率是精度与算力的直接权衡。</span>

**query 不是「输出」，而是「问题」**：BEV 网格上的位置 $(x_p, y_p)$ 定义了一个问题——「这里到底有什么？」而 query 向量就是要被反复更新、最终承载答案的那个状态。每个 query 带有一个三维参考位置 $[x_p, y_p, z_{ref}]$：$z_{ref}$ 是人为设定的**参考高度**（通常取 1 m 左右），它把 BEV 网格「抬升」到世界空间里一个贴近地面的平面上，这样 query 才有三维坐标可以投影到相机图像上。

网格的疏密就是感知的分辨率：格子越细，能分辨的目标越小，但算力与显存随之上升。0.5 m 的格子能很好地描述一辆车的占据，却难以区分两个紧挨的行人——「一个格子装得下什么」，决定了感知能力的上限。

BEVFormer 的规格值得记一笔：BEV 特征 200×200、通道数 $C$ 取 256，6 层编码器叠深，训练用 nuScenes 的 700 个场景、6 路环视相机。这样一套配置在 8 张 A100 上也要训数天——它精确地告诉你，「免深度监督」的代价是「大算力」。这也是为什么 BEVFormer 率先在数据与算力都充裕的团队里开花结果。

```
BEV grid (200×200, 0.5m/格)  →  BEV queries Q (200×200×C)
                                    │  每个 query 附三维参考位置 [x, y, z_ref]
                                    ▼
        每层编码器：Spatial Cross-Attention（去图像找证据）
                   + Temporal Self-Attention（问历史帧）
                                    ▼
                            更新后的 BEV 特征
```

经过 6 层这样的编码器，BEV 特征被不断「查证」与「补全」，最终输出一张信息充分的 BEV 特征图，接检测头 / 分割头 / 占用头。

## 3 Spatial Cross-Attention：去图像里找证据

**空间交叉注意力（SCA）** 回答的问题是：「这个 BEV 位置，在六路相机图像里分别长什么样？」对每个 query，它的三维参考点 $[x_p, y_p, z_{ref}]$ 用相机内外参反投影到每一路相机的像素平面，得到一个**参考像素位置**，然后在这参考点周围做**可变形注意力**采样：

$$SCA(Q_p, \{\mathcal{I}_i\}) = \sum_{i=1}^{N_{cam}} \sum_{j=1}^{N_{ref}} \operatorname{DeformAttn}\Big( Q_p,\; \mathcal{P}(p,i,j),\; \mathcal{I}_i \Big)$$

直觉很妙：**每个 BEV 位置「同时看向」所有相机，但各自只关心自己视野里相关的局部**。前车的 query 会在前视与左前相机的对应像素附近取特征；空地的 query 在每颗相机里都只采到地面。注意力权重学会的是「哪颗相机、哪个深度、哪块区域对这个位置最有信息量」——**深度被隐式地编码在「采样位置 + 权重」里**。

采样的稀疏性还带来一个有趣的性质：**BEVFormer 的计算量不随图像分辨率平方增长**——它只关心采样点附近的图像特征，图像再大，每个 query 的采样成本不变。这让它在高分辨率相机上反而比全图注意力方案更有优势，也是它能扛住 6 层编码器的原因之一。

**辨析｜易错点：** SCA 的采样是**稀疏**的——每个 query 每颗相机只采 4 个点（$N_{ref}=4$），6 路相机一共 24 个点。这是刻意的省算力设计，但也意味着：如果相机外参标定漂移了，**所有采样点一起错位**，BEV 特征就整体「花了」。BEVFormer 对标定的敏感，是它在量产里必须配在线标定补偿的原因之一。

## 4 Temporal Self-Attention：让历史帧帮现在补全

单帧图像有天然的缺陷：遮挡、模糊、瞬时反光。BEVFormer 的第二个关键设计是**时序自注意力（TSA）**，让 BEV 特征「记得过去」。

做法是：把**上一帧的 BEV 特征**按照自车的运动补偿（ego motion）做一次坐标变换（warp），对齐到当前帧的自车坐标系——因为上一帧里「静止目标在世界系中的位置」和当前帧是同一个位置，只是自车坐标系变了。然后，当前帧的每个 query 对「上一帧对齐后的 BEV 特征」做自注意力，把历史信息融合进来。<span class="marginnote">warp 用的是自车运动（里程计/IMU/速度积分），所以它只能对齐<strong>静止世界</strong>；动态目标（旁边驶过的车）的运动对齐不了，但没关系——注意力会自己学会「哪些位置在动、该信多少」。</span>

这一手带来的收益是实实在在的：**遮挡时，历史帧能补上当前帧看不到的物体**（被大车挡住的行人）；静止目标的位置会随多帧累积而更稳；检测的召回率明显提升。TSA 也埋下了后面「流式感知」（StreamPETR 式）的种子——把时序从「两帧」扩展成「持续滚动」。

TSA 还有一个工程上的健壮性问题：**上一帧的 BEV 特征本身可能是残缺的**——比如上帧恰好被卡车完全挡住、或上帧某路相机出了帧。BEVFormer 让历史特征也参与注意力，由网络自己判断「历史值不值得信」，这比「把两帧直接平均」稳健得多；但代价是历史错误会像滚雪球一样跨帧累积，长时序下需要额外的状态重置策略。

BEVFormer 用的是「上一帧」这一最短的时序窗口。后续的 **StreamPETR** 把时序拉长成一串历史帧的滚动队列，并去掉历史帧上冗余的空间重采样，速度与精度双赢——这正是《时序融合与流式感知》一节的前奏。理解 TSA，就等于拿到了理解整类流式感知的钥匙。

## 5 公式解析：SCA 的采样点反投影

SCA 最核心、也最容易踩坑的是那个投影 $\mathcal{P}(p,i,j)$。把它拆开，就是上一节针孔投影公式的「实战应用」：

$$
\mathcal{P}(p,i,j) = \pi_i\big([x_p,\; z_{ref},\; y_p]^T\big) + \Delta p_{i,j}, \qquad
\pi_i(\cdot) = \pi\big(\mathbf{K}_i[\mathbf{R}_i \mid \mathbf{t}_i](\cdot)\big)
$$

- **第一步，抬升**：把 BEV 网格位置 $(x_p, y_p)$ 抬到参考高度 $z_{ref}$，得到世界坐标 $[x_p, z_{ref}, y_p]^T$。注意顺序：世界系里 $z$ 朝上，所以「高度」放在第二个分量。
- **第二步，投影 $\pi_i$**：先乘外参 $[\mathbf{R}_i \mid \mathbf{t}_i]$ 变到相机 $i$ 的坐标系，再乘内参 $\mathbf{K}_i$ 并除以深度，得到像素坐标——这就是该 BEV 位置「在相机 $i$ 里应该出现的位置」。
- **第三步，加可学习的偏移 $\Delta p_{i,j}$**：网络不满足于只采参考点本身，而是在它附近学出一组偏移，采到周围更信息密集的像素。$\Delta p_{i,j}$ 是**从数据里学出来的**——这正是「可变形」三个字的意思。

把这条反投影链倒过来看，还能得到一个重要推论：**BEV 特征与图像特征是多对多关系**。同一个图像像素可能同时被多个 BEV query 采样到（近处大目标的轮廓、远处路面的像素），因此 SCA 不能做「取最大值」式的硬选择，而要依赖可变形注意力的加权求和——权重大小由网络学，哪份证据更确定，谁就说得更响。

**辨析｜易错点：** 整个链条里，$z_{ref}$ 是**设计者拍板的超参数**，不是网络学出来的。物体实际高度高于或低于 $z_{ref}$ 时，参考点就会「投影偏」，网络靠学习偏移去补救——能补回来一部分，但立体场景（高架、天桥）仍然难。这也是后续 PETR 用「3D 位置编码」直接替代参考高度的动机：与其给一个固定高度，不如把整个位置信息编码进 query。

## 6 BEVFormer 的代价与辨析

BEVFormer 不是银弹，它的代价和争议同样值得写进笔记：

| 维度 | BEVFormer 的做法 | 代价 / 辨析 |
| --- | --- | --- |
| 深度监督 | 不需要 | 省去 LiDAR 深度蒸馏，纯视觉可训 |
| 计算量 | 6 层编码器 × 稀疏采样 | 训练显存开销大，部署需优化 |
| 时序 | 上一帧 warp + 自注意力 | 只显式补偿自车运动，动目标靠自学 |
| 标定敏感 | 采样点全靠外参投影 | 标定漂移 → BEV 整体错位，需在线补偿 |
| 小目标 | query 网格 0.5 m/格 | 远距离/小目标容易采不到有效特征 |

工程上落地 BEVFormer 还要直面一连串现实问题：6 层编码器在车端芯片上的推理延迟、逆光/雨天等长尾场景下的采样鲁棒性、以及固定网格对远处小目标的分辨率上限。量产方案因此常做「BEV 特征打底 + 稀疏 query 补远处」的混合设计，而不是原样部署整座 Transformer。

最后回到方法论：BEVFormer 的意义不只是「一个模型」，而是证明了 **「网格 + 查询」可以成为多相机感知的通用骨架**。它的下一站是占用网络（Occupancy）与端到端规划——当 BEV 特征足够好，检测、分割、占用、规划都能在这张画布上共同学习。这条「一张 BEV 特征喂所有下游」的路线，正是《端到端自动驾驶》部分的伏笔。

**辨析｜易错点：** 把 BEVFormer 理解为「把六路图像特征拼起来」是最大的误读——它没有「拼接」环节，是**每个 BEV 位置主动去采**各路图像，谁的信息有用就信谁。另外，200×200 的网格意味着**分辨率上限被定死**：网格越粗，远距离小目标越容易「糊」进同一个格子，这是所有网格化 BEV 方案的共同天花板。

## 7 小结

- BEVFormer 用 **BEV queries** 把「感知」重新定义为「为每个地面位置查证信息」，query 是问题、不是输出。
- **SCA（空间交叉注意力）** 让每个 BEV 位置跨六路相机可变形采样，**深度被隐式编码进采样位置与权重**，无需深度监督。
- **TSA（时序自注意力）** 把上一帧 BEV 特征按自车运动对齐后做注意力，用历史补全遮挡与稳定检测，是流式感知的雏形。
- 采样点反投影 = **抬升 + 外参 + 内参 + 可学习偏移**，其中参考高度 $z_{ref}$ 是拍板的超参数，高架场景是它的短板。
- 代价：算力大、对**标定敏感**、网格分辨率受限；优点：端到端、纯视觉可训、时序融合自然。
