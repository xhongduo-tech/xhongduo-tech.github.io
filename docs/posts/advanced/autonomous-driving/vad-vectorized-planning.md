## 为什么从 VAD 讲起

UniAD 把全栈统一进一个 Transformer，但它的场景表示仍是**稠密的**——BEV 特征图、占用网格，这些都是「以像素/网格为单位的空间表达」。稠密表示有个尴尬：**大部分网格是空的**（道路上大多数地方没有障碍物），而注意力/计算量却要为每一格付出。更重要的是，稠密表示与规划真正关心的「离散语义」脱节——规划关心的是「哪条车道、哪辆车、哪个路口」，而不是「第 137 号网格有没有东西」。

**VAD（Vectorized Autonomous Driving，2023）** 把端到端架构的场景表达从「稠密」推向「稀疏矢量化」：整个场景——车辆、车道、轨迹、决策——全部用**向量序列**表达，规划直接在这套矢量化场景上求解。它的口号是「**端到端矢量化**」——从感知到规划，全程没有一张网格图。

## 1 矢量化场景：把世界从「图」变成「向量集」

回顾《场景编码与矢量化预测》一节：矢量化把地图元素与目标轨迹抽成折线/点序列。VAD 把这一思想贯彻到底——**全场景矢量化**：

- **地图**：车道中心线、路缘、路口，都是折线（polyline），从 BEV 特征里解码出来。
- **动态目标**：每辆车/行人是一个「带状态的点 + 历史轨迹折线」。
- **自车意图**：规划输出也是一条折线轨迹。

于是「场景」从「一张 BEV 图」变成了「一组向量序列」。VAD 的洞察是：**自动驾驶的下游任务（预测、规划）本质都是「在向量空间里做几何推理」**——预测是「这些向量怎么演化」，规划是「自车的向量怎么插入这个集合」。用向量表达，任务与表示天然对齐。

<span class="marginnote">稠密 vs 稀疏不只是一个效率问题，更是<strong>「表示与任务的匹配度」问题</strong>。规划本质上是在做「避障 + 跟车道」的几何推理，而几何推理在向量（精确的点线面）上做，远比在网格（像素的聚合）上做自然。VAD 的矢量化选择，是「让表示迁就任务」而非「让任务迁就表示」——这一原则会不断在自动驾驶架构史里重现。</span>

## 2 架构设计：矢量场景编码器 + 规划头

VAD 的架构比 UniAD 更「轻」——它的任务不是四个并列模块，而是一个**统一的矢量场景编码器** + 任务头：

1. **矢量场景编码**：从多相机图像（BEVFormer 式）得到 BEV 特征，再用一组「地图 query」与「目标 query」解码出**矢量化地图**与**矢量目标**——这一层替代了 UniAD 的检测 + 建图两个独立模块。
2. **交互预测**：矢量目标之间做交互注意力，预测每个目标的未来轨迹（仍是矢量的折线）。
3. **矢量化规划**：以「目标轨迹 + 地图向量」为输入，规划 query 生成自车轨迹。

VAD 的关键设计是**规划直接消费矢量**：不像 UniAD 需要先把预测「渲染」成占用网格，VAD 的规划头直接在「车道向量 + 目标轨迹向量」上做注意力，规划输出就是一条矢量轨迹。**整条链路没有一个网格张量**——这就是「端到端矢量化」的含义。

## 3 与 UniAD 的对比：稠密 vs 稀疏

| 维度 | UniAD | VAD |
| --- | --- | --- |
| 场景表示 | BEV 特征 + 占用网格 | 矢量化向量集 |
| 中间任务 | 检测/建图/预测/占用/规划 | 矢量化 + 预测 + 规划 |
| 计算效率 | 高（稠密注意力） | 低（稀疏） |
| 可解释性 | 占用可可视化 | 矢量可解析 |
| 规划输入 | 占用约束 | 矢量场景 |

VAD 的三大优势：

**高效**：稀疏向量集远小于稠密网格，注意力计算量大幅下降，推理更快。
**简洁**：任务更少（无需占用渲染），训练更简单。
**可迁移**：矢量表示与地图格式天然兼容，可以低成本接入传统规划器的后处理校验。

代价是**矢量化是「有损压缩」**：从稠密特征抽成离散向量会丢细节（小物体、边缘情况），且矢量解码的质量成为全链路瓶颈——**「抽错了向量，后面再对也没用」**。

<span class="marginnote">VAD 与 UniAD 的关系，很像 VectorNet 与栅格化 CNN 的关系在端到端层的重演：<strong>用结构化的稀疏表达，换取效率与可解释，代价是特征提取的损失</strong>。这也是自动驾驶表示学习的一条主线——从稠密到稀疏、从像素到向量、从网格到语义。VAD 把这条主线推到了「规划」这一层。</span>

## 4 规划损失与专家监督

VAD 的规划头怎么训练？它采用「**模仿学习 + 安全正则**」的混合目标：

- **行为克隆**：用专家（真值）轨迹监督规划输出——让网络学「人类/真值会怎么开」。
- **碰撞正则**：显式惩罚「自车轨迹与预测目标轨迹重叠」——即使 BC 没学到避障，正则项也强制轨迹远离障碍物。
- **地图正则**：惩罚「轨迹偏离车道向量」——让轨迹贴合可行驶区域。

$$
\mathcal{L}_{\text{plan}} = \underbrace{\mathcal{L}_{\text{BC}}}_{\text{学专家}} + \underbrace{\lambda_1 \mathcal{L}_{\text{collision}}}_{\text{避碰}} + \underbrace{\lambda_2 \mathcal{L}_{\text{map}}}_{\text{贴车道}}
$$

这套「BC 打底 + 约束正则」的训练范式，是端到端规划器处理「长尾安全」的常用手段——**纯 BC 学不到「从未发生但必须避免」的碰撞，正则项把安全约束直接写进训练目标**。

## 5 公式解析：矢量化规划中的碰撞约束

VAD 的碰撞正则如何计算？设自车规划轨迹点集 $P_{\text{ego}} = \{p_1, \dots, p_T\}$，第 $j$ 个目标的预测轨迹点集 $P_j$，则在时刻 $t$ 的碰撞惩罚为「自车点与目标预测点距离太近」的度量：

$$
\mathcal{L}_{\text{collision}} = \sum_{t=1}^{T} \max\Big(0,\; r_{\text{safe}} - \min_j \| p_t^{\text{ego}} - p_t^{j} \|\Big)
$$

- **第一步，看内层 $\min_j$**：在时刻 $t$，找自车到**最近目标**的距离——规划只关心「会不会撞上最近的」，远的忽略。
- **第二步，看 max 与 $r_{\text{safe}}$**：当最近距离小于安全半径 $r_{\text{safe}}$ 时产生惩罚，否则为 0。**这是「软约束」**——不是硬性禁止（硬约束会破坏端到端训练的可微性），而是梯度惩罚。
- **第三步，看逐时刻求和**：对预测时域内所有时刻累加。**惩罚的是「整个预测时域内是否有任何时刻太近」**——哪怕只有一瞬间擦边也会被罚。
- **第四步，联系整体损失**：$\mathcal{L}_{\text{collision}}$ 的梯度反传到自车轨迹与目标预测，同时教会规划「避开」与预测「更准」——**安全约束以可微的方式参与全链路学习**。

## 6 矢量化表示的「信息守恒」问题

VAD 的矢量化是「有损压缩」，理解「损在哪」是评估它能否用于量产的关键。矢量化相对稠密表示丢失的信息：

- **形状细节**：矢量用「折线/点序列」近似目标形状，非刚性变形（行人的姿态、车辆的倾斜）会被抹平——**对「形变敏感的感知」有损**。
- **语义连续性**：稠密特征（BEV 网格）保留「每个位置的响应」，矢量化只保留「抽出来的对象」——**遗漏的「未抽出的东西」**（漏检的小物体）不会进矢量表示。
- **不确定性的表达**：稠密特征天然带「概率场」，矢量化的「抽点」把概率场压缩成「离散选择」——**「这里大概有东西」被变成了「这里有/没有」**。

这些「损失」决定了矢量化表示的适用边界：

| 场景 | 矢量化的表现 |
| --- | --- |
| 结构化道路（车道、车辆） | 好（结构适合矢量） |
| 精细场景（行人姿态、边缘物体） | 有损 |
| 长尾小物体 | 依赖「抽」的召回率 |

<span class="marginnote">矢量化与稠密表示的「取舍」背后是一个深层权衡：<strong>「表示的语义层级」与「信息的完整性」不可兼得</strong>——矢量（语义高、信息有损）vs 稠密（语义低、信息完整）。VAD 选择「语义优先」是因为规划「消费语义」；而感知的「兜底任务」（小物体、精细场景）仍需要稠密表示补充。工程上的答案不是「选一个」，而是「<strong>语义表示 + 稠密兜底</strong>」。</span>

把「VAD」放回「端到端演进」的「坐标」（UniAD → VAD → 扩散/世界模型），它的「位置」清晰：**VAD 是「统一 Transformer」与「生成式/世界模型」之间的「桥梁」**——

- **它继承了 UniAD 的「统一」**：一个骨干做感知-预测-规划，但把「稠密表示」换成「稀疏矢量」；
- **它为「生成式」铺路**：矢量化输出（地图、目标、轨迹）是「可离散、可 token 化」的结构——**「矢量轨迹」正是「扩散/世界模型」能「生成」的对象**；
- **它示范了「端到端 + 稀疏」的可行性**：证明「端到端规划」不必然「稠密」——「稀疏语义表示」同样能支撑「全栈学习」。

「稠密 → 稀疏 → 可生成」这条线，是「端到端表示学习」的「演进主线」：**「从「网格」到「向量」到「可采样的分布」**——每一步都让「表示」更「语义化」、更「可操作」、更「可生成」。VAD 站在「这条线的中段」，既完成了「统一」的「稀疏化」，又为「生成式端到端」（扩散、世界模型）准备了「接口」——**「VAD 是端到端从「判别式」走向「生成式」的「转折点」**。

## 7 小结

- **VAD** 把端到端架构的场景表达从稠密 BEV 换成**稀疏矢量化向量集**，全程无网格张量。
- 矢量化让表示与任务（预测/规划的几何推理）**天然对齐**，计算更高效、结果更可解释。
- 与 UniAD 相比，VAD **更轻、更简洁**，但矢量化是「有损压缩」，解码质量成为瓶颈。
- 规划训练用「**BC 打底 + 碰撞/地图正则**」，把安全约束以可微方式写进学习目标。
- 稠密→稀疏、像素→向量，是自动驾驶表示学习的一贯主线，VAD 把它推到规划层。
