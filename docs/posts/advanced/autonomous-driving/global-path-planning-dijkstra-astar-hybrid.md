## 为什么从图搜索讲起

路由规划的本质是「图上的最短路径」——这个问题的经典解法 Dijkstra 与 A*，是每一个做规划的人都要先学会的算法。但自动驾驶对「最短路径」的诉求并不平凡：**路网图是抽象的，车辆是连续的**——图上搜出来的折线路径，车根本开不了（转不过弯、没考虑车宽、没考虑动力学）。于是又有了 **混合 A***（Hybrid A*），它是 Apollo、百度和大量量产方案的「泊车与低速场景路径规划」主力。

这一节的脉络很清楚：先讲清楚两个「教科书算法」Dijkstra 与 A* 的原理与关系，再讲混合 A* 是怎么把「离散图搜索」与「连续车辆模型」揉在一起的。掌握这三者，你就掌握了全局路径规划的完整谱系。

## 1 图搜索的基础：Dijkstra 与 A*

**核心概念：Dijkstra 算法**：从起点出发，按「已确定最短路」的顺序逐个扩展节点，用**优先级队列**（按当前累计代价排序）保证每次弹出的都是代价最小的未确定节点，直到终点被弹出。它保证找到**从起点到所有节点的最短路径**，但代价是它向所有方向等速扩展，盲目性大。

**核心概念：A\* 算法**：在 Dijkstra 的代价函数上加上一个**启发式（heuristic）**——估计「从当前节点到终点的剩余代价」$h(n)$。节点 $n$ 的优先级为 $f(n) = g(n) + h(n)$，其中 $g(n)$ 是已走代价，$h(n)$ 是到终点的估计。

$$
f(n) = g(n) + h(n)
$$

A* 与 Dijkstra 的唯一区别就是多了 $h(n)$。当 $h(n)$ **可采纳（admissible）**——即从不高估真实剩余代价——A* 保证找到最短路径，且扩展节点数远少于 Dijkstra。**启发式就是「方向感」**：Dijkstra 像无头苍蝇四处扩散，A* 带着「终点在这边」的方向感直奔目标。

<span class="marginnote">启发式的设计有个精妙的权衡：<strong>$h$ 越接近真实剩余代价，A* 扩展越少、越快；$h$ 一旦高估，就失去最优性保证</strong>。欧氏距离是最常用的可采纳启发式（两点直线距离永远 ≤ 实际路径距离）。工业界常为了速度用「次优但更快」的启发式（加权 A*，$f = g + \epsilon h$），牺牲一点最优性换实时性。</span>

## 2 从 Dijkstra 到 A*：同一套框架

理解二者的关系，比分别背它们更有价值。Dijkstra 与 A* 其实是**同一个通用图搜索框架的两个特例**：

| 算法 | 优先级 | 启发式 | 特点 |
| --- | --- | --- | --- |
| Dijkstra | $g(n)$ | 无 | 保证全局最优，盲目扩展 |
| A* | $g(n) + h(n)$ | 可采纳启发式 | 保证最优，定向扩展 |
| 加权 A* | $g(n) + \epsilon h(n)$ | $\epsilon>1$ | 次优但快很多 |

Dijkstra 就是 $h(n) \equiv 0$ 的特例——「完全没有方向感」的 A*。反过来，A* 的可采纳性保证也由这个统一框架保证：**只要启发式不高估，弹出终点时它的 $g$ 就是全局最小**。理解了这个统一框架，面对任何「在图上求最优路径」的问题，你都能立刻判断该用哪个变体。

## 3 为什么图搜索不够：车辆是连续的

Dijkstra/A* 在路网图上工作良好，但直接套到车辆的**局部运动规划**就出问题了：

- **搜索空间是离散的**：图节点是固定位置，但车辆状态是连续的高维空间（位置 + 航向 + 速度）。
- **边是几何直线**：图上的边假设直线可达，但车辆有**最小转弯半径**，两点之间可能根本开不过去。
- **忽略动力学**：图搜索不考虑速度、加速度、转向执行时间，搜出来的路径只是「几何路径」，不是「可驾驶轨迹」。

这就是「全局/抽象路径」与「局部/可行轨迹」的分工：Dijkstra/A* 负责**宏观路网**（节点是路段，边是路段连接，车辆抽象为一个点），但当运动规划需要在**连续空间**找一条车能开的路时，需要新的工具。

## 4 混合 A*：在连续空间里做「智能离散化」

**核心概念：混合 A\*（Hybrid A\*）**：把 A* 的图搜索思想推广到**车辆的连续状态空间**。它用车辆的**运动学模型**（自行车模型）从每个节点向前「滚动」出一组离散的候选动作（方向盘角度档位），得到一组**满足车辆运动学约束**的下一状态，把这些状态当作图搜索的「节点」。

混合 A* 与朴素 A* 的关键区别：

- **节点不是网格**，而是「车辆真实可到达的状态」——由运动学模型前向仿真得到，所以搜索出的路径天然满足转弯半径约束。
- **边是运动学轨迹**，而非直线——每步走一小段「车真正能走的弧线」。
- **启发式设计**：用「无碰撞的 Reed-Shepp 曲线」（能算出的最短可行曲线）或「忽略障碍物的 A*」作为 $h$，引导搜索逼近最优。

$$
f(s) = g(s) + h(s), \qquad s = (x, y, \theta)
$$

其中状态 $s$ 含航向 $\theta$——这正是图搜索与运动规划的分水岭：**航向被当成状态的一部分**，因为车不能原地掉头，航向决定了它下一步能往哪走。

<span class="marginnote">混合 A* 的洞察是<strong>「智能离散化」</strong>：不在位置网格上盲目离散，而是让车辆模型决定「哪些状态值得访问」。这让它在狭窄停车场、复杂路口的路径规划上表现优异——先粗搜一条可行路径，再用后续的轨迹优化（Frenet/QP）平滑成最终轨迹。Apollo 的泊车模块、诸多量产自动泊车系统，核心就是混合 A*。</span>

## 5 公式解析：A* 的可采纳启发式与最优性

以 A* 在栅格地图上的应用为例，拆解最优性保证：

$$
f(n) = g(n) + h(n), \qquad h(n) \le h^*(n) \ \ (\text{可采纳})
$$

- **第一步，看 $g(n)$**：起点到节点 $n$ 的实际累计代价（已走的路径长度/耗时）。它随搜索推进而确定。
- **第二步，看 $h(n)$ 与可采纳性**：$h^*(n)$ 是 $n$ 到终点的真实最小代价。可采纳性要求 $h(n) \le h^*(n)$——**估计值永远不比真实更乐观**。欧氏距离可采纳，因为任何路径都不短于直线。
- **第三步，为什么可采纳保证最优**：当 A* 从队列中弹出终点时，假设存在一条更短的路径但还没被扩展——这条路径上的某个节点 $m$ 满足 $f(m) \le g(\text{终点}_{\text{较短}})$；由可采纳性 $g(m) + h(m) \le g(m) + h^*(m) = g(\text{较短路径})$，而该值小于已弹出终点的 $f$，矛盾于「队列优先弹出最小 $f$」。**启发式不高估，是这条证明成立的前提**。
- **第四步，工程上的权衡**：$h$ 越紧（越接近 $h^*$）搜索越快；为实时性可放宽为 $\epsilon h$（加权 A*），代价是最优性退化为「$\epsilon$ 倍以内」。

## 6 从图搜索到路径的「后处理」：平滑与可行化

无论 Dijkstra、A* 还是混合 A*，搜出来的原始路径都「不像车开的」——折线角点、贴障碍物、忽略动力学。工程上必须接「后处理」把搜索路径变成可执行轨迹：

- **路径平滑（smoothing）**：用样条插值（B 样条）或数值优化（梯度下降、QP）把折线磨成光滑曲线。**注意平滑不能改变路径的「拓扑」**——不能把「绕左边的路径」平滑成「从中间穿过」。
- **轨迹生成（trajectory generation）**：在平滑后的路径上叠加速度曲线（限速、加速度约束），得到带时间的轨迹——**路径是「几何」，轨迹是「几何 + 时间」**。
- **可行性校验**：后处理结果要重新过「动力学校验」（转弯半径、速度曲率匹配），不合格则回退重搜——**「搜-平-验」构成闭环**。

| 后处理步骤 | 解决什么 | 常用工具 |
| --- | --- | --- |
| 路径平滑 | 折线变曲线 | B 样条 / QP |
| 速度规划 | 路径变轨迹 | ST 图 / QP |
| 动力学校验 | 轨迹可执行 | 车辆模型 |

<span class="marginnote">图搜索（Dijkstra/A*/混合 A*）与轨迹优化（QP/样条）的关系是「<strong>搜索找拓扑，优化找形状</strong>」：搜索负责「绕哪边」的离散决策，优化负责「绕得多平滑」的连续求解。两者分工、缺一不可——这也是为什么「混合 A* + QP」成为泊车与复杂场景的黄金组合。</span>

「图搜索」在自动驾驶中的「位置」，最终要放在「整个规划体系」里看：**图搜索解决的是「离散空间的路径存在性」，而它上面的「每层规划」解决的是「连续空间的轨迹可行性」**——两者不是竞争，而是「上下游」：

- **路由层用图搜索**：在「路网图」上找「道路序列」——图搜索的「主场」；
- **局部规划用图搜索**：混合 A* 在「车辆状态空间」找「可行路径」——图搜索向「连续空间」的延伸；
- **优化层消费图搜索**：QP/样条把图搜索的「折线路径」精修成「光滑轨迹」——图搜索的「下游」。

这个「上下游」关系揭示了一个「规划设计的通用原则」：**「先用「搜索」保证「存在」（能到吗），再用「优化」保证「质量」（开得顺吗）」**——「搜索」是「下限」（可达），「优化」是「上限」（最优）。**「先有路径，再优路径」**——这是从「图搜索」到「轨迹优化」一以贯之的规划哲学，也是「自动驾驶规划」最基础的方法论。

## 7 小结

- **Dijkstra** 是盲目的最短路搜索，**A\*** 用启发式 $f = g + h$ 定向搜索，二者是同一框架的两个特例。
- 启发式**可采纳性**是 A* 最优性的前提，$h$ 越紧越快。
- 图搜索处理**抽象路网**；车辆是**连续、带航向与动力学约束**的，需要专门的连续空间规划。
- **混合 A\*** 用车辆运动学模型前向仿真生成「可到达状态」，把航向纳入状态，搜出**车真正能开的路径**。
- 混合 A* 是泊车、低速复杂场景的主力，之后通常接轨迹优化做平滑。

在下一节，我们进入运动规划的另一种经典思路：**不搜索确定性网格，而是用随机采样探索连续空间**——这就是 RRT 与 RRT*。
