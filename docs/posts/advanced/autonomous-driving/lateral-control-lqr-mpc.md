## 为什么从 LQR 与 MPC 讲起

纯跟踪与 Stanley 用几何直觉打方向盘，简单但「看不见未来」——它们不显式优化「接下来几秒内最好的动作序列」。当路径急弯、车速很高、车辆动态逼近极限时，几何法就会力不从心。于是横向控制进入第二大家族：**模型法**——用车辆模型把「转向」写成最优控制问题。

这一族的两个代表是 **LQR** 与 **MPC**。它们共享一个灵魂（基于模型的最优控制），但代表两种不同的哲学：**LQR 是「一眼望穿无限远」的稳态最优**，**MPC 是「走一步看三步再重新算」的滚动优化**。理解这对概念，不只对横向控制，对整个自动驾驶控制体系都至关重要。

## 1 最优控制视角：把转向写成优化

**核心概念：最优控制（optimal control）**：给定系统动态 $x_{t+1} = f(x_t, u_t)$ 与代价函数 $J$，求控制序列 $u_{1:T}$ 使 $J$ 最小。横向控制的最优控制形式是「让车辆状态跟踪参考路径，同时让转向动作不过激」：

$$
\min_{u_{1:T}} \; \sum_{t=1}^{T} \Big[ (x_t - x_{\text{ref},t})^\top Q (x_t - x_{\text{ref},t}) + u_t^\top R u_t \Big] \quad \text{s.t.} \quad x_{t+1} = f(x_t, u_t)
$$

$Q$ 与 $R$ 是权重矩阵：$Q$ 惩罚「偏离参考路径」，$R$ 惩罚「转向动作过大」。**这个优化想表达的驾驶直觉是：既要把车拉回路径，又不能猛打方向盘**——两个目标打架，权重 $Q/R$ 决定谁更重要。

横向控制的状态 $x$ 通常取「横向偏差 $e_d$ + 航向偏差 $e_\theta$」（相对参考路径的误差状态），控制输入 $u$ 是前轮转角 $\delta$。系统动态由车辆模型（运动学或线性化动力学）给出。问题就这么定了——剩下的区别是「怎么解」。

## 2 LQR：无限时域的解析解

**核心概念：LQR（Linear Quadratic Regulator，线性二次型调节器）**：当系统动态是线性的（$x_{t+1} = A x_t + B u_t$）、代价是二次的时，最优控制有**解析解**——控制律是状态反馈 $u_t = -K x_t$，增益 $K$ 由**黎卡提方程（Riccati equation）**解出。

$$
K = (B^\top P B + R)^{-1} B^\top P A
$$

其中 $P$ 是离散黎卡提方程 $P = A^\top P A - A^\top P B (B^\top P A + R)^{-1} B^\top P A + Q$ 的解。LQR 的优美在于：**解一次黎卡提方程，得到一个固定的反馈增益 $K$，之后每一时刻只需算一次 $u_t = -Kx_t$**——极快、极稳，完全适合实时控制。

<span class="marginnote">LQR 的隐含假设是「无限时域 + 线性系统」：它假设系统从现在到永远都是同一套线性动态，求的是「长期平均最优」的反馈律。对高速公路这类「参考路径近似直线/缓弯、车辆动态近似线性」的场景，LQR 非常合适；但遇到<strong>急弯、强非线性、带约束</strong>（转角限幅）的场景，LQR 无法显式处理约束，就得靠 MPC。</span>

## 3 MPC：滚动时域 + 约束处理

**核心概念：MPC（Model Predictive Control，模型预测控制）**：在每个控制时刻，用模型从当前状态出发**预测未来 N 步**，求解一个带约束的有限时域优化，执行第一步控制，然后**滚动到下一时刻重新求解**。

$$
\min_{u_{t:t+N}} \; \sum_{k=t}^{t+N} \big[ (x_k - x_{\text{ref},k})^\top Q (x_k - x_{\text{ref},k}) + u_k^\top R u_k \big] \quad \text{s.t.} \quad \text{动态 + 约束（转角限幅、加速度限幅、避障）}
$$

MPC 与 LQR 的三个本质区别：

- **有限时域**：只看未来 N 步，而不是「永远」。N 通常 10–30 步（0.5–1.5 秒）。
- **显式约束**：转角限幅 $\delta \le \delta_{\max}$、避障、速度限制可以直接写进优化——这是 MPC 对 LQR 最大的优势。
- **滚动更新**：每时刻都重新求解，用最新状态修正模型误差——**自带反馈与自校正**，对模型失配鲁棒。

MPC 的代价是**每步都要解一个优化问题**（而非 LQR 的一步矩阵乘），实时性压力大；但随着求解器与算力提升（见车端计算章节），MPC 已是量产横向/纵向控制的主流。

## 4 LQR vs MPC：何时用谁

| 特性 | LQR | MPC |
| --- | --- | --- |
| 时域 | 无限 | 有限滚动 |
| 求解 | 离线解一次、在线一步乘 | 每步在线解优化 |
| 约束 | 难以显式处理 | 天然支持 |
| 计算量 | 极小 | 较大 |
| 模型失配 | 弱 | 滚动校正、较鲁棒 |
| 适用 | 高速巡航、稳态跟踪 | 变道、避障、带约束、非线性 |

工程上的典型用法：**高速稳定场景用 LQR**（省算力、稳定），**需要约束或强动态场景用 MPC**（变道、避障、极限工况）。很多系统还做「LQR 打底 + MPC 覆盖关键场景」的分层——把算力花在刀刃上。

<span class="marginnote">一个经常被误解的点：<strong>MPC 的性能上限受「模型 + 预测时域」限制，而非优化本身</strong>。模型太糙，MPC 预测的未来就不可信，滚动校正也只能补救一部分。所以 MPC 工程的核心不是调求解器，而是<strong>调模型</strong>——非线性模型、轮胎模型精度、参数在线辨识。这是「模型比算法更值钱」论断在控制层的又一次印证。</span>

## 5 公式解析：LQR 反馈增益与黎卡提方程

以连续时间 LQR 为例，拆解其结构。设线性系统 $\dot x = A x + B u$，代价 $J = \int_0^\infty (x^\top Q x + u^\top R u) dt$，最优控制律 $u = -Kx$，其中 $K$ 来自**代数黎卡提方程（ARE）**：

$$
A^\top P + P A - P B R^{-1} B^\top P + Q = 0
$$

- **第一步，看黎卡提方程的解 $P$**：$P$ 是代价函数的**值函数矩阵**——它编码了「从状态 $x$ 出发的最优剩余代价 $x^\top P x$」。求解 ARE 即找到这个「最优代价的二次型表达」。
- **第二步，看增益 $K = R^{-1} B^\top P$**：最优控制 =「状态加权」($P$) ×「控制代价倒数」($R^{-1}$) ×「输入对状态的影响力」($B^\top$)。**权重 $Q$ 大（想快速纠偏）则 $P$ 大、$K$ 大；$R$ 大（怕动作大）则 $K$ 小**。
- **第三步，看时不变性**：$A, B, Q, R$ 都是常数，所以 $P$ 与 $K$ 也是常数——**解一次、用到底**。这就是 LQR「离线算、在线用」的来源。
- **第四步，联系实际**：横向 LQR 把 $A, B$ 取为「横向偏差 + 航向偏差」的线性化动态，$Q$ 权重偏向横向偏差（让车贴路），$R$ 权重偏向转角（让转向柔和）。**调 $Q/R$ 就是调「贴路 vs 柔和」**——与纯跟踪调预瞄距离、MPC 调预测时域，是同一类手感标定问题。

## 6 模型预测控制的「实时求解」工程

MPC 的性能取决于「能否在实时预算内解出优化」，这是它从论文走向量产的最大障碍。几个工程手段：

- **问题规模的裁剪**：预测时域 $N$、控制变量维度决定求解规模——**在「性能」与「实时」之间取 N=10~30**，并用「控制时域 < 预测时域」（控制量只优化前几拍，之后保持）压缩变量数。
- **求解器的选择**：内点法（准确但慢）、主动集法（中等）、一阶方法如 ADMM（快但精度略低）——**不同场景用不同求解器**（结构化道路用一阶快解、复杂场景用内点精解）。
- **问题的结构化利用**：轨迹优化的 QP 有特殊结构（带状稀疏矩阵、Toeplitz），**利用结构定制求解器**能提速一个数量级——「通用求解器」不是最优解。
- **失效降级**：MPC 求解超时/无解时，**必须有「预计算的兜底控制」**（安全减速、保持上一帧控制）——「求解失败也有控制输出」是实时控制器的底线。

| 手段 | 提速效果 | 代价 |
| --- | --- | --- |
| 控制时域裁剪 | 大幅 | 控制自由度下降 |
| 一阶求解器 | 数倍 | 精度略降 |
| 结构化定制 | 数量级 | 开发成本高 |
| 兜底降级 | 保底 | 保守 |

<span class="marginnote">MPC 在自动驾驶的「真实现状」值得冷静看待：<strong>它在纵向（ACC、AEB）与低速场景（泊车）已大规模量产，但在「高速 + 强非线性 + 长时域」场景仍受实时性制约</strong>。工程上常与「显式 MPC」（把最优解离线参数化、在线查表）或「多模型切换」结合，绕开「每步在线求解」的实时瓶颈——「能离线算的就不在线算」是实时控制的普遍智慧。</span>

「横向控制」的「进化谱系」（纯跟踪 → Stanley → LQR → MPC），其实是「控制理论」在「自动驾驶」上的「一次教科书式演进」——它展示了「控制方法」如何随「需求」升级：

- **几何法（纯跟踪/Stanley）**：满足「基本跟踪」——「车能沿着路走」，无需模型；
- **LQR**：满足「最优跟踪」——「在无约束下最优地走」，需要线性模型；
- **MPC**：满足「约束最优」——「在约束（转角、避障）下最优地走」，需要模型 + 优化；
- **未来**：满足「非线性 + 不确定」——「在非线性动力学与不确定性下最优地走」，需要更强的求解与感知。

这条「进化线」的「驱动」是「需求升级」：**「从「能走」到「走得最优」到「带约束最优」到「非线性不确定最优」」**——每一级需求，都对应「更高级的控制方法」。理解这条线，就理解了「控制方法的选择」不是「越新越好」，而是「**匹配当前需求与模型能力的「够用就好」**」——「需求」驱动「方法」，而非「方法」驱动「需求」。

## 7 小结

- 模型法把横向控制写成**最优控制问题**：状态是横向/航向偏差，控制是前轮转角。
- **LQR** 对线性二次系统给出解析反馈律 $u = -Kx$，极快极稳，适合高速稳态跟踪。
- **MPC** 滚动求解有限时域带约束优化，天然支持转角限幅与避障，对模型失配鲁棒。
- LQR 与 MPC 是「无限时域稳态最优 vs 有限时域滚动最优」的两种哲学，常分层配合使用。
- MPC 的性能上限受**模型精度与预测时域**限制，模型调校比求解器调优更关键。
