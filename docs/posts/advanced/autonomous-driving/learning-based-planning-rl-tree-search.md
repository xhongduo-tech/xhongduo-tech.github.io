## 为什么从强化学习讲起

模仿学习有个天然上限：**人类数据里没有「最优但危险」的边界操作，也没有「从未发生但应该发生」的决策**。比如紧急避障——正常人类一辈子遇不到几次，数据里几乎没有；可恰恰是这种长尾极端场景，决定了自动驾驶安不安全。模仿学习学不到没发生过的，**强化学习（RL）学到的不是「人类做过什么」，而是「怎么做能获得最大回报」**——哪怕这条路人类从未走过。

RL 在自动驾驶规划中的定位，不是替代所有模块，而是补上模仿学习与规则优化都缺的那块：**在交互与不确定性中做长期、主动的决策**。本节讲清 RL 规划的三件事：**RL 为什么适合交互决策**、**树搜索（MCTS）如何成为 RL 与规划的结合点**、**以及它在自动驾驶落地的真实边界**。

## 1 强化学习：从数据学到「最大化回报」

**核心概念：强化学习（Reinforcement Learning, RL）**：智能体在环境中采取动作，环境返回状态转移与即时回报，智能体通过试错最大化累计回报——学习的是**策略** $\pi_\theta(s) = a$，即「在状态 $s$ 下做什么」。

$$
\theta^* = \arg\max_\theta \mathbb{E}_{\tau \sim \pi_\theta} \Big[ \sum_t \gamma^t R(s_t, a_t) \Big]
$$

RL 与模仿学习的根本差别在**目标函数**：模仿学习最小化「与人类动作的差异」（学得像），RL 最大化「累计回报」（学得优）。回报函数由设计者定义——安全碰撞 −1000、到达 +100、时间 +1/秒——于是 RL 可以探索出「人类数据里没有、但回报最优」的行为。

<span class="marginnote">RL 最被低估的价值是<strong>「探索」</strong>：它不依赖人类数据，而是自己在环境里试错。这恰恰是模仿学习与规则系统的盲区——紧急避险、极端工况、从未遇到的长尾场景，RL 可以通过数百万次仿真试错「预习」它们。这也是为什么 RL 规划几乎都离不开仿真环境（详见仿真章节）。</span>

## 2 为什么 RL 适合交互决策：社交驾驶

回顾 MDP/博弈章节：驾驶决策的难点在于**他人的反应是策略化的、会响应你的动作**。规则方法难以建模这种「互相推断」，模仿学习又只有人类数据。RL 的优势正在于此——**在仿真里与「会反应的对手」对练**，自然学到「你的动作影响别人、别人的反应影响你」的交互策略：

- 路口抢行：RL 学到「试探性前移」看对方是否让行——这是 MDP 静态转移难以表达的主动试探。
- 匝道汇入：RL 学到「加速找到空隙 vs 减速等待」的权衡——在不同车流密度下自适应。
- 行人横穿：RL 学到「保持适当速度，让行人判断出我会停下」的可预期行为。

这些交互策略的共同点：**必须通过与「会反应的对手」多轮互动才能学出来**。RL + 高保真仿真环境（对手也是仿真智能体），是唯一能规模化训练这类策略的途径。

## 3 树搜索：RL 与规划的桥梁

纯 RL 有个问题：策略网络输出的是「动作」，但安全关键场景需要「可验证的规划」。于是有了**树搜索（tree search）**——把 RL 的策略/价值学习与传统的搜索规划结合，最有名的是 AlphaGo 的 **蒙特卡洛树搜索（MCTS）**。

**核心概念：MCTS（Monte Carlo Tree Search，蒙特卡洛树搜索）**：从当前状态出发，反复执行四步——**选择**（按价值走最有希望的支路）、**扩展**（展开新节点）、**模拟**（随机走到底估算回报）、**回传**（把结果回传更新节点价值）——逐步在策略空间中构建一棵「值得探索的树」，最后选出综合评估最优的动作。

$$
\text{选择规则（UCT）：} \quad a^* = \arg\max_a \Big[ \bar V(a) + c \sqrt{\frac{\ln N}{n_a}} \Big]
$$

其中 $\bar V(a)$ 是动作 $a$ 的平均价值，$N$ 是父节点访问次数，$n_a$ 是动作 $a$ 被访问次数，$c$ 是探索系数。**第一项是「利用」（走价值高的），第二项是「探索」（走访问少的）**——平衡二者是 MCTS 的精髓。

<span class="marginnote">MCTS 对自动驾驶的特殊价值在于<strong>「把不确定性带进搜索」</strong>：节点可以存储「对方可能反应的分布」，模拟时可以按分布采样不同对手行为。这让树搜索从「确定性的路径搜索」升级为「在不确定性里做决策」。它与行为规划的博弈方法（Level-k）天然契合——树的每层可以对应一次「我考虑他考虑我」的推理。</span>

## 4 RL 规划在自动驾驶的落地形态

RL 规划并非「一个 RL 网络替代全部」，工业与学界的落地通常是混合形态：

- **RL 作为行为层**：用 RL 训练一个「高层行为选择器」（加速/减速/变道/等待），底层仍用传统运动规划执行——把 RL 用在它擅长的「离散决策」，把运动学精细求解留给 QP。
- **RL + 规则兜底**：RL 策略在线决策，但规则系统监控——RL 策略输出异常或超出安全包络时，规则层接管。**RL 负责「聪明」，规则负责「安全」**。
- **MCTS + 可学习策略/价值**：用学习的策略指导树搜索的扩展（避免盲搜），用学习的价值指导剪枝（避免穷举），再在叶节点做精细评估——这是「学习加速搜索」的通用范式。
- **仿真到真车（sim-to-real）**：RL 策略先在仿真里训练，再迁移到真车。迁移是最大难点——仿真与真车差距导致策略失效，常用域随机化（domain randomization）缓解。

<span class="marginnote">RL 规划最诚实的评价是<strong>「进展显著、落地受限」</strong>：在仿真基准（路口、汇入、密集交互）上 RL 已能超越规则基线，但真实落地面临三座大山——仿真到真车的迁移鸿沟、回报设计的安全敏感性、以及「学习策略难以证明安全」的合规障碍。因此量产方案普遍把它作为「离线训练 + 在线建议」的辅助，而非唯一决策源。</span>

## 5 公式解析：MCTS 的选择-回传循环

以单步 MCTS 的选择与回传为对象，看学习与搜索如何结合。设节点 $v$ 有若干子节点 $v'$（候选动作），访问后按蒙特卡洛结果回传：

$$
V(v) = \frac{1}{n(v)} \sum_{i=1}^{n(v)} R_i, \qquad n(v) \text{ 为访问次数}
$$

- **第一步，看价值 $V(v)$**：节点的价值 = 它下面所有模拟路径回报的平均。模拟次数越多，估计越稳——这是蒙特卡洛的「大数定律」基础。
- **第二步，看选择**：UCT 公式在「平均价值高」与「访问次数少」之间加权，选一个动作去扩展。**利用与探索的平衡让树「先粗后细」**——反复访问最有希望的区域。
- **第三步，看回传**：模拟结束后，把回报从叶节点一路回传到根节点，沿途更新每个节点的均值。**每轮模拟都在「教」树哪里值得继续探索**。
- **第四步，联系 RL**：MCTS 的价值 $V(v)$ 可以替换为**学到的价值函数**（神经网络估值），模拟可以替换为**学到的策略**（不再随机走）——这就是 AlphaGo/AlphaStar 的「学习增强搜索」。自动驾驶场景里，学到价值/策略压缩了搜索深度，让 MCTS 在实时约束下可用。

## 6 强化学习「回报设计」的安全敏感性

RL 规划最容易被低估的风险，是「回报设计的暗坑」——回报函数写得不好，RL 会学到「令人惊讶的坏行为」。几个经典陷阱：

- **奖励黑客（reward hacking）**：模型找到「钻回报漏洞」的方式——「停着不动」能避免碰撞惩罚且不扣分，模型就学会了「一直停着」。**回报必须包含「效率/任务完成」项**，否则学到「消极安全」。
- **稀疏回报的探索困难**：驾驶的「成功/失败」信号稀疏（一次行程才一个回报），RL 难学——**需要「回报塑形（reward shaping）」**（给中间步骤奖励），但塑形要小心「误导」。
- **安全回报的「不可妥协」**：碰撞惩罚必须「极大」（大到任何效率收益都无法抵消），否则模型会「为了快而冒险」。**「安全回报的权重要压倒一切」**是 RL 驾驶的铁律。
- **分布外回报的失控**：RL 策略在「没见过」的状态下，可能执行「回报意义不明」的动作——**需要安全包络监控策略输出**（与端到端安全兜底同构）。

一个工程上的关键对照：

| 回报设计 | 可能学出的行为 |
| --- | --- |
| 只有碰撞惩罚 | 消极停驻 |
| 碰撞 + 效率 | 可能激进抢行 |
| 碰撞(极大) + 效率 + 舒适 | 平衡但保守 |
| 加上「可预期性」惩罚 | 更接近人类驾驶 |

<span class="marginnote">RL 回报设计的本质是「<strong>把安全价值观写进数值</strong>」——碰撞的代价要比迟到高多少、保守要比激进多受多少罚，这些「价值判断」直接决定学出的驾驶风格。这也是自动驾驶「伦理问题」的工程化落点：<strong>回报函数的权重分配，就是系统的价值排序</strong>。技术团队在调权重时，实际上在做价值决策。</span>

「RL 与树搜索」在「自动驾驶规划」中的「位置」，最终要放在「学习 vs 优化」的「光谱」里看——它代表的是「学习与优化的「融合」」：

| 光谱位置 | 方法 | 特性 |
| --- | --- | --- |
| 纯优化 | 规则/QP/MPC | 可解释、可证明，但僵硬 |
| 优化 + 学习 | 树搜索 + 学习价值/策略 | 学习加速搜索，可解释性保留 |
| 学习 + 优化 | 模仿学习 + 安全校验 | 学得像，规则兜底 |
| 纯学习 | 端到端 RL | 灵活，但不可解释、难保证 |

「RL + 树搜索」占据的是「优化 + 学习」这档——**「用学习（价值/策略）给优化（搜索）导航，用优化（搜索）给学习（策略）兜底」**，兼顾「灵活性」与「可解释」。这个「融合」的位置，让它成为「比纯规则灵活、比纯学习可靠」的「中间路线」，也解释了「为什么 MCTS + 学习」在「决策密集」的场景（路口、汇入）被反复探索。**「自动驾驶决策的演进，是「学习」与「优化」在「光谱上逐步融合」的过程」**——「RL + 树搜索」是这条「融合之路」上的「关键一站」。

## 7 小结

- **RL** 通过试错最大化回报，能学到人类数据里没有的**长尾与交互决策**，目标从「学得像」变成「学得优」。
- RL 的核心价值是**探索**与**交互策略学习**，几乎必须依赖高保真仿真环境。
- **MCTS** 以「选择-扩展-模拟-回传」构建策略树，把不确定性带进搜索，是 RL 与规划结合的桥梁。
- 工业落地常用**混合形态**：RL 做行为层、规则做安全兜底、MCTS 用学习策略加速搜索。
- RL 落地的三座大山：**仿真迁移、回报敏感性、可证明安全**。
