## 为什么从 VLA 讲起

VLM 让机器「看懂并描述世界」，但自动驾驶的终点不是「描述」，是「行动」。**VLA（Vision-Language-Action model，视觉-语言-动作模型）**把这一步补齐：在 VLM 的基础上，再加一个「动作」输出头——**输入视觉 + 语言（指令/场景），直接输出驾驶动作（轨迹/转向）**。VLA 是「大模型 + 具身智能」范式在自动驾驶的落地，也是机器人领域（RT-1、RT-2、OpenVLA）思想的汽车版。

VLA 的吸引力在于「**统一与泛化**」：一个大模型同时承载「世界知识 + 场景理解 + 行动策略」，用语言作为「任务接口」——「左转」「靠边停车」「前方施工绕行」都能通过语言指令驱动。本节讲清 VLA 的架构范式、它与端到端规划的区别，以及它面临的「输出维度鸿沟」难题。

## 1 VLA 的范式：视觉 + 语言 → 动作

**核心概念：VLA（Vision-Language-Action model）**：一种多模态大模型，输入为视觉观测与语言指令/上下文，输出为动作（或动作序列）。它将「感知、理解、决策、控制」统一进一个自回归 Transformer 范式。

VLA 的输入输出结构：

- **输入**：图像/视频（视觉）+ 文本指令（语言，如「前方障碍，靠右绕行」）+ 可选的历史动作。
- **输出**：动作——对自动驾驶，可以是离散 token（控制指令的量化）、连续轨迹（未来几秒的轨迹点）、或动作参数（目标速度/转向）。

VLA 的架构通常继承 VLM 的骨干，在末层加「动作预测头」——它与文本生成共享同一个 Transformer，只是输出空间从「词汇表」变成「动作表」或「轨迹 token」：

$$
\text{action} = \text{Decoder}\big(\text{VisionEncoder}(I), \text{Text}(c)\big)
$$

<span class="marginnote">VLA 的「语言接口」是它与传统端到端规划的本质区别：<strong>传统端到端从「视觉 → 动作」直接映射，VLA 从「视觉 + 语言 → 动作」</strong>。语言带来两个新东西——「任务可指定」（「下个路口右转」是显式指令，而非从数据里隐式学）与「知识可注入」（文本能携带「前方施工」这类感知看不出的信息）。语言在这里是「<strong>把外部知识与任务意图编码进动作决策的通道</strong>」。</span>

## 2 VLA 的三个关键设计：token 化、融合、动作头

VLA 的实现有三大关键设计，每个都决定成败：

**其一，动作的 token 化**：动作是连续的（轨迹坐标、转向角），而自回归模型输出离散 token。VLA 要把动作「离散化」——用**动作 token**（把连续动作量化为 K 类）或**动作序列 token**（把整条轨迹编码成离散序列）。RT-2 用「动作 token」把机器人动作当「特殊词汇」生成；自动驾驶方案则常把「轨迹」量化成 token 序列。**动作 token 化的粒度直接决定控制精度**。

**其二，视觉与语言的融合**：VLM 的跨模态对齐（图像特征 ↔ 文本 token）要扩展到「动作」——通过「视觉特征 + 语言指令」共同条件化动作头。融合的位置（早/中/晚）影响「语言多大程度指挥视觉」。

**其三，动作头的设计**：是「分类头」（从离散动作表选一个）、「回归头」（预测连续轨迹）、还是「自回归头」（逐 token 生成轨迹）——不同的输出形式对应不同的控制语义与精度。

## 3 VLA vs 传统端到端：范式差异

| 维度 | 传统端到端 | VLA |
| --- | --- | --- |
| 输入 | 视觉（+状态） | 视觉 + 语言 |
| 任务指定 | 隐式（从数据学） | 显式（语言指令） |
| 知识注入 | 靠数据覆盖 | 语言可携带外部知识 |
| 输出 | 轨迹/动作 | 动作 token / 轨迹 |
| 泛化 | 数据驱动 | 语言 + 数据双驱动 |

VLA 相对传统端到端的三个增量：**任务可指定**（语言给目标）、**知识可注入**（文本带常识）、**交互可解释**（语言可作为输出解释动作）。代价是：**多一个「语言」模态的处理成本**、**语言指令的歧义**、以及「语言 → 动作」对齐的训练数据稀缺。

<span class="marginnote">VLA 最被低估的可能是「<strong>语言作为抽象层</strong>」：传统端到端把「看见什么 → 怎么开」直接压进网络，VLA 中间隔了一层语言——「看见施工 → 理解『前方施工』→ 执行『绕行』」。这层抽象让「<strong>决策可被语言解释、被语言干预、被语言复用</strong>」——同样的「绕行」知识，可以用在「施工绕行」「事故绕行」「障碍绕行」。抽象带来的复用性，是 VLA 泛化能力的根源。</span>

## 4 VLA 在自动驾驶的代表与路线

VLA 在自动驾驶的探索沿两条路线展开：

**机器人 VLA 的汽车移植**：把 RT-2/OpenVLA 的思路搬到驾驶——视觉 + 语言指令 → 驾驶动作。代表如 Waymo 的 EMMA、以及各类「驾驶 VLA」研究。它们验证了「语言接口 + 驾驶动作」的可行性。
**驾驶专用的 VLA**：针对驾驶任务定制——用「导航指令」（从 A 到 B）作为语言输入，用「轨迹」作为输出，把「导航 + 规划」统一进一个 VLA。小鹏、理想等新势力的「端到端大模型」正在向这个方向演进。

无论哪条路线，VLA 都继承了「大模型 + 数据飞轮」的逻辑：**用海量「视觉-语言-动作」三元组训练，让模型同时获得「看得懂」「听得懂指令」「开得动」**。这背后是「自动驾驶基础模型」的终极图景（见本专题最后一节）。

<span class="marginnote">VLA 在量产的真实挑战是「<strong>数据从哪里来</strong>」：驾驶的「视觉-语言-动作」三元组需要「图像 + 指令 + 人类动作」对齐的数据——这类数据远比「图像 + 动作」稀缺。工业界的应对是「<strong>用合成指令 + 自动标注 + 大模型蒸馏</strong>」生成语言标签，或用「语言模型蒸馏」把「指令理解能力」注入驾驶网络。数据稀缺，是 VLA 从论文走向量产的第一道坎。</span>

## 5 公式解析：VLA 的自回归动作生成

以 VLA 输出轨迹 token 为对象，设视觉特征 $v$、语言指令 token 序列 $c_{1:M}$、动作 token 序列 $a_{1:N}$，VLA 的生成过程是自回归预测动作 token：

$$
p(a_{1:N} \mid v, c_{1:M}) = \prod_{n=1}^{N} p\big(a_n \mid a_{\\lt n}, c_{1:M}, v\big)
$$

- **第一步，看条件集合 $(v, c_{1:M})$**：每个动作 token 的生成都以「视觉 + 全部语言指令」为条件——**动作「看见场景、听懂指令」**。
- **第二步，看自回归 $a_{\\lt n}$**：动作 token 逐个生成，每个依赖前面已生成的动作——**轨迹是「一笔一笔画出来」的**，与文本生成同构。
- **第三步，看「统一」的机制**：视觉、语言、动作全部是「token 序列」，在一个 Transformer 里自回归——**这是 VLA「一个模型统三模态」的架构学基础**。
- **第四步，看控制精度的代价**：动作被离散成 token，量化粒度决定控制精度——token 太粗，轨迹不平滑；token 太细，序列太长难训练。**「动作离散化」是 VLA 控制精度的瓶颈**，也是它常与「连续细调」结合的工程原因。

## 6 VLA 的「训练」：数据、对齐与泛化的挑战

VLA 的「训练」是它的真正难关——不只是「算力大」，而是「数据与对齐」的结构性挑战：

- **三元组数据的稀缺**：驾驶的「视觉-语言-动作」三元组需要「图像 + 指令 + 人类动作」同时对齐——**这类数据远比「图像 + 动作」稀缺**，是 VLA 量产的第一瓶颈。
- **「语言-动作」的对齐歧义**：同一句「左转」在不同场景对应不同的轨迹——**「语言是抽象的，动作是具体的」**，对齐需要海量「指令-动作」配对才能学准。
- **动作离散化的精度损失**：动作 token 化损失控制精度——**「离散 token 的粒度」与「轨迹平滑性」的矛盾**是 VLA 的固有张力。
- **多任务遗忘与灾难**：VLA 同时学「描述、问答、动作」，任务间可能互相干扰——**「多任务训练的平衡」**是大模型的通病。

| 挑战 | 工程应对 |
| --- | --- |
| 三元组稀缺 | 合成指令 + 大模型蒸馏 |
| 对齐歧义 | 海量指令-动作配对 |
| 离散精度 | 连续细调 + 混合输出 |
| 任务干扰 | 课程式/分阶段训练 |

一个关键认识：**VLA 的「泛化」依赖「语言的抽象」**——如果「左转」在所有场景都学成「同一条轨迹」，VLA 就没有「泛化」，只是「记住」。**真正的 VLA 泛化是「同一句指令在不同场景产生正确的不同动作」**——这需要「语言 + 视觉」的深度对齐，也正是 VLA 训练最难的体现。

<span class="marginnote">VLA 的「理想」与「现实」之间，横着「数据」这道坎：<strong>理想中「一个模型，输入视觉 + 指令，输出动作」，现实中「没有足够的「视觉-语言-动作」三元组，模型只能「记住」而不能「泛化」</strong>。这也是为什么「VLA 的研究」火爆、「VLA 的量产」克制——<strong>「范式」的成立不难，「数据」的满足很难</strong>。看 VLA，先看它的数据从哪来。</span>

VLA 与「具身智能」的「跨领域关联」，值得最后点明——它是「从极限到大模型」主线里「自动驾驶」与「机器人」的「交汇点」：

- **VLA 的「母体」是机器人**：RT-1/RT-2/OpenVLA 诞生于「机器人操作」，「驾驶 VLA」是其「汽车化」；
- **两者的「共同范式」**：视觉 + 语言 → 动作，用「大模型 + 数据」做「具身决策」——「同一个范式，两种载体」；
- **两者的「差异」**：机器人「动作空间小、场景受控」，驾驶「动作连续、场景开放、安全要求更高」——「驾驶 VLA 更难，但范式相同」。

这个「交汇」意味着：「自动驾驶」与「机器人」的技术「正在合流」——**「视觉-语言-动作」的统一范式，是「智能体（Agent）走向物理世界」的「共同语言」**（与《AI 智能体》专题呼应）。VLA 的研究，不只是「自动驾驶的进展」，更是「具身智能」这个「更大图景」的「一部分」。**「自动驾驶是「具身智能」的「一个重要实例」」**——理解 VLA，就理解了「大模型 + 物理世界」的「共同未来」。

## 7 小结

- **VLA** 在 VLM 基础上加「动作输出」，输入「视觉 + 语言」、输出「动作」，把理解推进到行动。
- 三大关键设计：**动作 token 化、跨模态融合、动作头设计**，决定控制精度与泛化。
- 相对传统端到端的三个增量：**任务可指定、知识可注入、交互可解释**。
- 语言是「**抽象层**」——让「决策可解释、可干预、可复用」，是 VLA 泛化的根源。
- 量产瓶颈是「**视觉-语言-动作」三元数据稀缺**，工业界用合成指令与大模型蒸馏应对。
