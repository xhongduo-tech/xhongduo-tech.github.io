## 为什么从「两段式」讲起

回顾端到端章节：纯端到端（传感器 → 动作）在概念上优雅，在工程上「不可调、不可审、不可兜底」。而量产智驾（小鹏、理想、华为）对端到端的落地，几乎都选择了同一个折中——**「两段式」端到端**：不是「一个网络从头到尾」，而是「**感知（第一段）与规划（第二段）分别端到端，中间保留可解释的接口**」。

「两段式」是「端到端理想」与「工程现实」的产物：它保留了端到端「信息不被模块接口截断」的核心收益（感知与规划各自端到端、内部无手工特征），又恢复了「可审计、可兜底、可单独调试」的工程能力（中间有明确的语义接口）。本节讲清两段式的划分、它相对「单段式」的取舍，以及为什么它是当前量产的主流答案。

## 1 单段式端到端的问题：不可调、不可审

纯单段式端到端（如 Tesla V12 的早期形态）的问题，在量产语境下被放大成三个「不可」：

- **不可调**：感知想升级（换个更强的检测骨干），必须整个网络重训——因为感知与规划在同一个网络里耦合。**迭代成本高**。
- **不可审**：事故复盘时，无法回答「是感知没看见，还是规划选错了」——**错误不可定位**。
- **不可兜底**：安全监控器（见端到端安全章节）需要「监控感知输出」或「监控规划输出」，单段式没有明确的中间输出可监控——**兜底无抓手**。

这三个「不可」让单段式在「需要持续迭代、需要安全论证、需要责任归因」的量产环境难以落地。于是工程界走向「保留端到端的收益、恢复工程的能力」——两段式。

<span class="marginnote">单段式与两段式之争，本质是「<strong>联合优化的收益</strong>（单段式信息无损）<strong>vs 工程可操作性的收益</strong>（两段式可调可审）」。单段式的理论优势「梯度全链路」确实更优雅，但量产要的不是「最优」，而是「<strong>能迭代、能出问题、能修复</strong>」。两段式在「损失一点联合优化收益」的前提下，拿回了「工程可操作性」——这是量产工程对理论最优的务实修正。</span>

## 2 两段式的划分：感知端到端 + 规划端到端

**核心概念：两段式端到端（two-stage end-to-end）**：把驾驶系统分成两个「各自端到端」的段——

- **第一段：感知端到端（Perception E2E）**：从多传感器原始输入 → 统一场景表示（BEV 特征、目标列表、占用网格、矢量地图）。这一段是「端到端」的——内部没有手工设计的特征，从像素直接学到「场景表示」。
- **第二段：规划端到端（Planning E2E）**：从「场景表示 + 导航指令」→ 自车轨迹。这一段也是端到端的——从「表示」直接学到「动作」，不经过手工规则。

两段之间的接口是**「显式的场景表示」**（目标、占用、地图）——这个接口就是「工程抓手」：可以审计（感知输出对不对）、可以兜底（监控器检查场景表示）、可以单独迭代（感知换模型不影响规划接口）。

这个划分的合理性在于：**感知与规划是两种「学习难度」不同的问题**——感知是「表示学习」（从像素到语义结构），规划是「决策学习」（从表示到动作）。分开训练、各自端到端，比「一个网络硬融」更容易收敛、更容易调优。

## 3 两段式 vs 单段式的取舍

| 维度 | 单段式端到端 | 两段式端到端 |
| --- | --- | --- |
| 架构 | 一个网络 | 感知网络 + 规划网络 |
| 中间接口 | 无（隐式） | 显式场景表示 |
| 联合优化 | 全链路 | 分段 |
| 可调性 | 差（牵一发动全身） | 好（分段独立迭代） |
| 可审计 | 差 | 好（接口可检查） |
| 可兜底 | 差 | 好（监控接口输出） |
| 信息损失 | 无 | 接口处有损失 |

两段式用「接口处的信息损失」换「可调、可审、可兜底」。这里的「信息损失」是相对单段式的：场景表示是「有损压缩」（目标框丢失了像素细节），但**对量产而言，这个损失可以接受，而「可调可审可兜底」不可放弃**。

## 4 两段式的训练：端到端 + 中间监督

两段式的训练有一个关键技巧：**既端到端，又中间监督**。

- **第一段的训练**：用「感知真值」（目标框、占用、地图）监督场景表示——**第一段是「表示学习」**，优化「场景表示准不准」。
- **第二段的训练**：用「人类/专家轨迹」监督规划输出——**第二段是「决策学习」**，优化「开得好不好」。
- **两段的衔接**：第二段的梯度可以选择「反传到第一段」（端到端微调）或「冻结第一段」（两段独立）——**工业界常用「分段训练 + 可选联合微调」**。

这套「端到端 + 中间监督」的关键是：**第一段被「感知真值」约束，保证场景表示是可理解的（而不是任意的隐空间）**——这正是「两段式」与「单段式」的本质区别：**中间表示不是「学出来就行」，而是「必须符合人类可理解的语义」**。这个约束让「可审计」成为可能。

<span class="marginnote">「中间监督」是两段式的灵魂：<strong>单段式的中间表示是「自由的」（网络想怎么表示就怎么表示），两段式的中间表示是「被约束的」（必须对应可理解的目标/占用/地图）</strong>。这个「语义约束」牺牲了一点「表示自由度」，换来了「工程师能看懂中间发生了什么」——<strong>「能看懂」是「能审计、能兜底、能过审」的前提</strong>。两段式的真正价值，不是「分段」，而是「让中间表示可读」。</span>

## 5 公式解析：两段式的损失结构

以「感知端到端 + 规划端到端」的两段式训练为对象，总损失：

$$
\mathcal{L} = \underbrace{\mathcal{L}_{\text{perception}}(S, S_{\text{gt}})}_{\text{第一段：场景表示 vs 真值}} + \lambda \underbrace{\mathcal{L}_{\text{planning}}(\tau, \tau_{\text{expert}}, S)}_{\text{第二段：轨迹 vs 专家}}
$$

- **第一步，看第一段损失 $\mathcal{L}_{\text{perception}}(S, S_{\text{gt}})$**：让「感知输出的场景表示 $S$」贴近「感知真值 $S_{\text{gt}}$」（目标框、占用）。**这一项把中间表示「钉」在可理解的语义上**——它来自检测/分割/占用任务的监督。
- **第二步，看第二段损失 $\mathcal{L}_{\text{planning}}(\tau, \tau_{\text{expert}}, S)$**：让「规划的轨迹 $\tau$」贴近「专家轨迹 $\tau_{\text{expert}}$」，同时以场景表示 $S$ 为条件——**规划「看着感知的表示」学决策**。
- **第三步，看两段的衔接**：第二段以 $S$ 为输入，$S$ 来自第一段——**若允许梯度反传，第二段的损失会优化第一段的表示（让它对规划更有利）**；若冻结第一段，则两段独立。**「是否端到端微调」是两段式的一个可调旋钮**。
- **第四步，看「分段训练」的实践**：先单独训第一段（感知收敛），再训第二段（在冻结或微调第一段下），最后可选联合微调。**这种「课程式」训练解决了「一起训容易互相干扰」的问题**——两段式的可操作性，从训练流程上就比单段式友好。

## 6 「两段式」的演进方向：从「两段」到「多段」到「可插拔」

「两段式」不是终点，而是「按需切分」这个思想的一个实例——它正在向「更灵活的分段」演进：

- **「两段」→「多段」**：感知内部也可以再分（BEV 编码器 + 目标解码器）、规划内部也可以再分（意图决策 + 轨迹生成）——**「段的粒度」按「调试/审计需求」决定**，需要独立调试的环节就切成一段。
- **「可插拔」**：每一段都可以「单独替换」——升级感知骨干不重训规划、换规划范式不影响感知——**「段间接口稳定」是可插拔的前提**。
- **「端到端」的重新定义**：当「段」足够多、接口足够清晰，「端到端」这个词的意义已经模糊——**「联合训练的多段系统」**才是更准确的描述，它的「端到端性」只是「梯度可以贯穿」。

| 演进 | 含义 |
| --- | --- |
| 两段 → 多段 | 按调试需求切分 |
| 可插拔 | 段间独立替换 |
| 端到端 → 联合多段 | 语义澄清 |

这套演进的「深层逻辑」是：**「段的划分」本质是「在「联合优化收益」与「工程可操作性」之间取平衡点」**——需要优化的环节联合（端到端梯度贯穿）、需要调试的环节切开（独立可测）。**「最优的分段」不是固定的，而是随「团队能力、数据规模、调试需求」动态调整的**。

<span class="marginnote">「两段式」的演进揭示了一个更普遍的规律：<strong>自动驾驶架构的「终极形态」不是「全端到端」或「全模块化」，而是「一个随需求灵活分段的系统」</strong>——「段」是「工程的操作单元」，「端到端梯度」是「优化的连接方式」。理解了「分段」与「联合」是可以自由组合的两个维度，就跳出了「端到端 vs 模块化」的二元争论——<strong>真正的架构设计是「在哪分段、在哪联合」的工程判断</strong>。</span>

「两段式端到端」与「大模型」（VLM/VLA）的结合，是当前量产智驾最前沿的「架构形态」，值得点明它的「分层逻辑」：

| 层 | 职责 | 典型实现 |
| --- | --- | --- |
| 感知段 | 像素 → 场景表示 | BEV/占用编码器 |
| 语义层 | 表示 → 情境理解 | VLM/VLA（顾问） |
| 规划段 | 表示 + 语义 → 轨迹 | 端到端规划头 |

这个「三段（感知-语义-规划）」的分工，本质是「**把「理解」与「行动」分离**」：感知段「看清世界」、语义层「读懂世界」、规划段「行动于世界」。它既享受「大模型的语义能力」，又保留「端到端的联合优化」，还维持「段的清晰接口」——**「大模型 + 两段式」是「学习红利」与「工程可控」的最大公约数**。

这个架构的「演进方向」也清晰：**语义层的「话语权」会逐步增大**——从「顾问」到「决策参与者」，再到「主导决策」，随「大模型的可靠性」提升而提升。但「安全兜底」永远在「确定性模块」——**「大模型可以「越来越聪明」，但「安全底线」永远「不可让渡」**」，这是「大模型上车」的不可动摇的原则。

## 7 小结

- 单段式端到端的「不可调、不可审、不可兜底」让它难以量产落地。
- **两段式端到端** = 感知端到端（像素 → 场景表示）+ 规划端到端（表示 → 轨迹），中间是显式接口。
- 两段式用「接口处的信息损失」换「可调、可审、可兜底」，是量产的主流答案。
- 训练用「端到端 + 中间监督」：第一段被感知真值约束，让中间表示可读可审。
- 「让中间表示可读」是两段式的灵魂——可读才能审计、兜底、过审。
