## 为什么从点云 3D 检测开始

上一节我们用 RANSAC 分地面、用欧氏聚类聚目标——这些是**手工规则**，每条都凝结着工程师对场景的假设。但假设总有失效的时候：坡道上 RANSAC 崩坏，稀疏处聚类碎裂。深度学习给出的回答是：**让网络直接从原始点云回归出 3D 检测框，把「手工流程」吸收成可微的参数**。

这一节是点云感知的「主菜」：三个里程碑式的模型——VoxelNet、PointPillars、CenterPoint——串起了点云 3D 检测从「点 → 体素 → 支柱 → 中心点」的表示演进。<span class="marginnote">理解这一节的关键是抓住「表示」二字：点云无序、稀疏，无法直接上图像卷积，所以每个模型都在回答同一个问题——把点云<strong>组织成什么结构</strong>，才能让 CNN / Transformer 吃得下去？VoxelNet 组织成体素，PointPillars 组织成支柱，CenterPoint 则站在前两者之上。</span>先立住一句话：**点云 3D 检测 = 一种点云表示 + 一个检测头，模型之间的差异主要是「表示」的差异。**

## 1 为什么点云不能直接上卷积

图像是稠密的规则网格，卷积核可以在像素上滑动；点云却是**无序的、非均匀的**坐标集合——没有「第 3 行第 5 列」这种位置概念。若硬把点云按坐标排进网格，大部分格子是空的，卷积核滑过去全是零。

因此点云 3D 检测的第一步，永远是把点云**离散化 / 结构化**成网络能处理的形式。三种主流方案对应三条路：

- **体素化（Voxelize）**：把三维空间切成小立方体（体素），每个体素里聚合若干点。
- **支柱化（Pillarize）**：只在 XY 平面切柱体，Z 方向不切——相当于把所有点的垂直方向信息压进一个「柱子」里。
- **中心点化（Center-based）**：干脆不做规则网格，直接在点云特征上预测每个目标的中心点。

### 3D 框的表示与 BEV 视角

在深入模型前，先明确输出长什么样。自动驾驶只关心地面上的物体，因此 3D 检测框常用**鸟瞰视角（BEV）**参数化：中心 $(x, y)$、长宽 $(l, w)$ 与绕竖直轴的朝向 $\theta$，高度 $z$ 与 $h$ 相对次要。**这一选择的工程意义是巨大的**——在 BEV 下，物体的几何关系与道路坐标系天然对齐，检测结果可以直接喂给下游规划，也方便多传感器在同一个二维平面上融合。可以说，「先压到 BEV、再谈检测」是贯穿本章后面所有内容（BEVFormer、占用网络）的总体思路。

## 2 表示学习的基石：PointNet

在谈三大模型之前，必须先认识它们的「砖头」——**PointNet**（2017）。它回答了那个核心问题：**怎样对一个无序点集定义「有意义的特征」？**

答案是构造一个**置换不变的对称函数**。对点集 $\{x_1, \dots, x_n\}$，PointNet 用一个逐点 MLP $h$ 提取每个点的特征，再用 **max pooling** 把所有点的特征聚合，最后用一个 MLP $g$ 整理成全局特征：

$$
f(\{x_1, \dots, x_n\}) \approx g\left( \max_{i} \; h(x_i) \right)
$$

max 这个算子天然无视点与点的顺序——无论你把点云洗牌多少次，逐点过 $h$ 再取 max，结果都一样。**这就是 PointNet 对「无序性」的数学答案**。<span class="marginnote">为什么用 max 而不是求和或平均？max 更像「挑出最显著证据」：它让网络学到「只要有某个点支持「这里有车顶」，就把该特征激活」，而求和会被点数稀释、平均会被稀疏处拉低。后续的 PointNet++、Point Transformer 都在这条思路上演进，但「逐点 MLP + 置换不变聚合」的骨架一直没变。</span>

## 3 VoxelNet：体素化 + 稀疏卷积

**VoxelNet**（2018）把 PointNet 的思想搬进体素。流程是：

1. **体素化**：把点云按空间切成边长约 0.1–0.2 m 的体素，一个体素里通常有 0–5 个点。
2. **VFE（Voxel Feature Encoding）**：每个体素内部的点，用一个小型 PointNet 编码成一个体素特征向量。
3. **稀疏卷积**：绝大部分体素是空的，直接用稠密 3D 卷积会浪费巨额算力；VoxelNet 用**稀疏卷积**只在非空体素上计算。
4. **RPN 检测头**：把 3D 特征压到 BEV（鸟瞰图），接区域提议网络输出 3D 框。

VoxelNet 的另一个奠基性贡献是 **VFE（Voxel Feature Encoding）** 层：它对体素内点做两轮「逐点 MLP + max 聚合」，第一轮得到体素级特征，第二轮把该特征拼回每个点，让网络**同时看到「点自身的特征」与「它所在体素的上下文」**。

这种「局部特征 + 全局上下文」的双层编码，后来被 BEV 感知、Transformer 的位置编码广泛借用——先立住这一点，后面遇到「把上下文拼回特征」的设计就不会陌生。

**辨析｜易错点：** 3D 体素的算力问题在这里第一次暴露——真实驾驶场景 90% 以上的体素是空的，若按稠密张量算，分辨率稍高就爆显存。VoxelNet 的意义与其说在精度，不如说在证明了「体素 + 稀疏卷积」这条路的可行性；真正把它推上量产舞台的，是下一位。

## 4 PointPillars：支柱化，把 3D 问题变成 2D 问题

**PointPillars**（2019）做了个大胆的简化：**Z 方向不切体素，只切 XY 平面**，得到一根根竖立的「支柱（pillar）」。每根支柱内聚合成一个特征（把各点的 x, y, z, 反射强度、距柱中心的偏移拼起来，过一个 PointNet 式编码），于是点云被压成一张**稀疏的 2D 伪图像**——然后直接复用成熟的 2D 检测网络（如 SECOND 骨干 + SSD 头）。

这一手棋的关键收益是**速度**：3D 稀疏卷积被替换成 2D 卷积，计算量大降，PointPillars 在 P4 GPU 上可达 60+ FPS，成了早期量产点云感知的事实标准。之所以叫「支柱」，是因为它在 XY 平面切出的是一根根**竖直柱体**——同一根柱子里无论点高高低低，都压成一个特征。这个「把垂直方向折叠掉」的设计，牺牲了对悬空物体（过街天桥、高挂的路牌）的精细建模，但在绝大多数路面场景里是一笔划算的取舍。<span class="marginnote">PointPillars 的命名暗示了它的哲学：与其把点云当三维体积处理，不如把它当「带厚度的 2D 图」。这个「先压成 BEV 再走 2D 网络」的套路，几乎预言了后面整个 BEV 感知范式（见本章《BEV 感知的由来》）——端到端架构里相机与激光雷达在 BEV 空间对得齐，正是受益于这种统一的平面化视角。</span>

## 5 CenterPoint：去掉锚框，回归中心点

VoxelNet 与 PointPillars 都属于**锚框（anchor）流派**：预先在地面上铺一排固定尺寸、固定朝向的 3D 框，网络负责判断每个锚框里有没有目标、并回归偏移。锚框带来大量超参数，也让 NMS 后处理又重又难调。

**CenterPoint**（2021）走了 2D 检测里 CenterNet 的老路：**用热图（heatmap）直接预测每个目标的中心点**，再回归中心点的 3D 位置、尺寸、朝向与速度。它大大简化了训练目标，也把后处理从「锚框 + NMS」简化成「中心点局部极大值提取」。它在 Waymo 等排行榜上长期领先，并顺带输出了**速度回归**——这个速度可以直接喂给跟踪与预测模块。

### CenterPoint 的两段式精修

CenterPoint 的真正威力来自它的**两段式（two-stage）精修**：第一阶段用中心点热图得到粗框，第二阶段把每个粗框内的点云特征重新聚合，再回归一次更精细的框与速度。这个「粗检测 + 精修」的设计让它在精度榜上一骑绝尘，思路也启发了后续很多工作。<span class="marginnote">有趣的是，CenterPoint 的 two-stage 与 2D 检测里 Faster R-CNN 的 two-stage 在「先粗后精」上异曲同工，但实现完全不同——它不是在像素候选框上精修，而是按<strong>点云本身</strong>再做一次特征聚合，因此天然贴合点云的稀疏结构。这种「按物体取特征再精修」的范式，在后面的端到端架构里也会反复出现。</span>

### 3D 框怎么算「重合」：BEV IoU

锚框流派离不开 NMS，而 3D 框带朝向角，无法直接套用 2D 的轴对齐 IoU。工程上的标准做法是**在 BEV 平面算 IoU**：把两个 3D 框投影到地面，转成带旋转角的 2D 矩形，再用「相交多边形面积 ÷ 并集面积」计算——

$$
\text{IoU}_{\text{BEV}}(A, B) = \frac{\text{area}(A \cap B)}{\text{area}(A) + \text{area}(B) - \text{area}(A \cap B)}
$$

朝向角 $\theta$ 让这里的多边形求交比 2D 复杂得多，所以早期 3D NMS 实现普遍偏慢。**CenterPoint 之所以受欢迎，很大程度因为它用中心点热图绕开了这一大段「旋转框 NMS」**——需要「去重」时，只需在热图上做局部极大值提取，再按 BEV 中心距离轻量筛选。

| 模型 | 点云表示 | 检测头 | 特点 |
| --- | --- | --- | --- |
| VoxelNet | 体素 + 稀疏卷积 | 锚框 + NMS | 奠基之作，证明体素路可行 |
| PointPillars | 支柱 → 2D 伪图像 | 锚框 + NMS | 快，量产事实标准 |
| CenterPoint | 体素/支柱 + 中心点热图 | 无锚框，少 NMS | 准，常带速度回归 |

## 6 公式解析：PointNet 的置换不变性为什么成立

我们把那条对称函数公式再拆开一次——它是点云深度学习全部方法的「第一原理」。

$$
f(\{x_1, \dots, x_n\}) = g\left( \bigoplus_{i=1}^{n} \; h(x_i) \right), \qquad \bigoplus = \max
$$

- **第一步，逐点映射 $h(x_i)$**：$h$ 是一个多层感知机，把每个点的原始坐标与特征 $x_i \in \mathbb{R}^3$（或更高维）映射成一个高维向量 $h(x_i) \in \mathbb{R}^k$。这一步逐点独立，点的顺序无所谓。
- **第二步，对称聚合 $\max_i$**：对 $k$ 个通道各自取最大值，得到 $\mathbb{R}^k$ 的全局特征。**因为 max 只看「集合里有没有某个分量超过其他点」，与遍历顺序无关，所以整个函数对点的任意排列保持不变**。这正是置换不变性的来源。
- **第三步，高层整理 $g$**：把 $k$ 维全局特征再接一个 MLP，得到用于分类或分割的任务特征。$g$ 不接触单个点，自然也不破坏置换不变性。

**辨析｜易错点：** max 聚合是**信息有损**的——它只保留每个通道的「冠军」，丢弃了分布、次序等其余信息。这就是为什么后续工作要补注意力（Point Transformer）或多尺度（PointNet++）。

在 3D 检测里，**单个体素内点数很少**，max 的损失尚可承受；可一旦体素变大、点数变多，单纯 max 就喂不饱检测头了——这也是支柱/体素尺寸要细心标定的原因。体素切得太粗，特征被 max 抹平；切得太细，空体素暴增、算力失控。

### 一条主线：从手工对称函数到注意力

顺着 PointNet 往下看，其实能预见整个点云深度学习的走向：max 这种「硬选择」太粗暴，人们很快想用**软选择**——注意力（attention）。2019 年后的 Point Transformer、以及 BEV 感知里对位置编码的依赖，本质都是「逐点特征 + 按相关度加权聚合」对「逐点特征 + max」的升级。

**当你在后面的章节看到「自注意力」「跨模态注意力」时，不妨记住它只是把这里的 $\max$ 换成了加权平均 $\sum w_i h(x_i)$**——同一件事，更柔和、更可学习。这条「硬选择 → 软选择」的主线，正是从极限到大模型这条路上反复出现的思维升级。

## 7 小结

- 点云**无序、稀疏、非网格**，无法直接卷积；一切 3D 检测模型都在解决「用什么表示」。
- **PointNet** 用「逐点 MLP + max 聚合」实现了置换不变性，是所有点云表示学习的基石。
- 表示演进：**VoxelNet**（体素 + 稀疏卷积）→ **PointPillars**（支柱 + 2D 伪图像，快）→ **CenterPoint**（中心点热图，无锚框）。
- 从锚框到中心点，检测头不断简化，NMS 后处理被一步步「优化掉」——这条去复杂化的主线会一直延续到后面的 BEV 感知。

在下一节，我们将从单传感器视角跳到融合视角：**多传感器融合**如何处理相机与 LiDAR 的异步、异构信息——前融合、特征级融合与后融合三条路线的取舍，是感知系统设计的核心权衡。
