## 为什么从芯片对比讲起

上一节讲了车载计算平台，这一节落到「心脏」——自动驾驶芯片。这个市场的格局基本是几家巨头：**英伟达**（Orin、Thor）是「通用高性能」的代表，**地平线**（征程系列）是「国产高性价比」的代表，**特斯拉**（HW 系列）是「垂直自研」的代表。理解这些芯片的差异，不只关乎选型，更关乎自动驾驶的技术路线之争（通用 GPU vs 专用 ASIC vs 端到端定制）。

本节不做「参数罗列」，而是讲清三件更有价值的事：**芯片算力的真实含义**（TOPS 的猫腻）、**三条技术路线的差异**（通用/专用/自研）、**以及如何根据架构选芯片**。

## 1 芯片算力的真实含义：TOPS 只是起点

各家芯片宣传的核心数字是 **TOPS**（Tera Operations Per Second，每秒万亿次运算）。但 TOPS 有大量「水分」：

- **稀疏 vs 稠密**：稀疏 TOPS（激活稀疏性优化）可能是稠密 TOPS 的两倍，宣传常取高者。
- **INT8 vs FP16 vs FP32**：INT8 的 TOPS 通常是 FP16 的两倍、FP32 的四倍。模型用 FP16 跑，宣传用 INT8 数字，实际算力就打折。
- **理论 vs 实际**：标称 TOPS 是理论峰值，实际取决于内存带宽、数据复用率、算子调度——**真实利用率常只有 30–60%**。

所以「254 TOPS」与「200 TOPS」谁强，不能只看数字。要问：**什么精度下的 TOPS？稀疏还是稠密？实际能跑到标称的几成？** 这就像看发动机马力，还要看「什么转速下、油耗多少、能不能输出到轮上」。

<span class="marginnote">一个更本质的算力指标是<strong>「有效算力」</strong>——在某类真实模型、真实精度下的实际吞吐。英伟达的优势之一就是生态：CUDA/TensorRT 工具链成熟，实际利用率往往高于新玩家。选芯片时「<strong>算力 × 利用率 × 生态</strong>」的乘积，比裸 TOPS 更接近真实性能。</span>

## 2 英伟达：通用高性能 + 成熟生态

**核心概念：英伟达 Drive 平台**：面向自动驾驶的完整方案，核心是 SoC（片上系统）+ CUDA/TensorRT 软件栈 + Drive OS。

代表芯片：

- **Orin**：2019 年发布，254 TOPS（INT8 稀疏），8 个 Cortex-A78AE CPU + Ampere GPU，是 L2+~L3 量产的主流选择。支持多颗级联（2×Orin、4×Orin）提升算力。
- **Thor**：2022 年发布，宣称 2000 TOPS（FP8），统一「座舱 + 智驾」的中央计算芯片，目标 L4 与软件定义汽车。

英伟达的优势：**通用 GPU 架构**（什么算法都能跑，兼容快速演进的深度学习算法）、**生态垄断**（研究到量产全用 CUDA/TensorRT，算法迁移成本低）、**工具链成熟**（部署、调试、性能分析完善）。劣势：**功耗高**（大算力代价）、**成本高**、**供应链受制于台积电与地缘**。

<span class="marginnote">英伟达的路线是「<strong>算力军备竞赛</strong>」：用远超当前需求的算力，换取「算法随便演进我都跑得动」的通用性。对量产车，这套路线的问题是功耗与成本——一颗 Thor 的功耗可能接近普通家用电脑整机。这也催生了「专用化」与「自研」路线的机会。</span>

## 3 地平线：国产专用 + 极致性价比

**核心概念：地平线征程（Journey）系列**：中国地平线公司的自动驾驶芯片，主打「高算力密度（TOPS/W）」与「专用 NPU + 工具链」。

代表产品：**征程 5**（128 TOPS，面向 L2+~L3）、**征程 6**（宣称数百 TOPS，支持端到端）。地平线的关键设计：

- **专用 BPU（Brain Processing Unit）架构**：针对神经网络算子深度定制，同样的算力消耗更低的功耗——**「单位功耗算力」是其核心卖点**。
- **工具链开放性**：提供「地平线工具链」支持主流框架模型部署，同时强调「软硬协同」——与算法伙伴（如理想的 Mind 方案）深度绑定。
- **国产供应链**：本土设计、制造自主性，契合「国产替代」与供应链安全的产业需求。

地平线的定位是「**够用 + 便宜 + 开放**」：在 L2+ 量产市场以性价比抢份额，并通过「开放工具链」让车企保有算法自主权。劣势：**生态较新**（与英伟达 CUDA 生态差距）、**大算力上限仍在追赶**。

## 4 特斯拉：垂直自研 + 端到端定制

**核心概念：特斯拉 HW（Hardware）系列**：特斯拉完全自研的 FSD 芯片，与其纯视觉、端到端的技术路线深度绑定。HW3（2019）约 144 TOPS，HW4（2023）算力提升约 3–5 倍（官方未公布精确数字）。

特斯拉路线的独特性：

- **全栈自研**：芯片、算法、数据、车辆全链条打通——芯片为自家算法「量身定制」，没有「通用性浪费」。
- **专用设计**：针对自家端到端/视觉网络设计 DLA（深度学习加速器）与 CPU 的配比，追求「特定工作负载下的极致效率」。
- **软硬一体**：HW 与 FSD 软件同步迭代，芯片升级与算法升级互为条件。

特斯拉的启示是「**垂直整合的极致形态**」：不卖芯片、不依赖第三方生态，用「自家算法 × 自家芯片 × 自家数据」的最优匹配，在特定路线（纯视觉端到端）上做到系统最优。代价是**路线绑定**——押注纯视觉 + 端到端，若路线动摇，芯片架构也要重来。

<span class="marginnote">三条路线可以这样对照：<strong>英伟达是「军火商」</strong>（卖最通用的武器给所有人）、<strong>地平线是「国产军火商」</strong>（卖性价比武器并绑定生态）、<strong>特斯拉是「自家军队」</strong>（只为自己定制武器）。对车企而言，选哪条路线本质是选「<strong>算法自主权</strong>」：用英伟达/地平线，算法自主但受芯片生态约束；走特斯拉模式，需要自研芯片的巨大投入。</span>

## 5 对比与选型

| 维度 | 英伟达 Orin/Thor | 地平线征程 | 特斯拉 HW |
| --- | --- | --- | --- |
| 架构 | 通用 GPU | 专用 NPU | 全定制 DLA |
| 生态 | CUDA/TensorRT 成熟 | 国内工具链 | 全自研 |
| 供应 | 台积电 | 国产链 | 全自研 |
| 定位 | 通用高性能 | 性价比 L2+ | 端到端自用 |
| 代表客户 | 蔚来、理想、小鹏 | 理想（部分）等 | 特斯拉自家 |

选型逻辑：**要通用性 + 成熟生态 → 英伟达**；**要性价比 + 国内供应链 → 地平线**；**要走端到端自研全栈 → 特斯拉模式（仅头部玩家可选）**。现实里多数车企是「英伟达/地平线做智驾主芯片 + 自研部分算法」的组合。

## 6 芯片评测的「正确姿势」：别只看参数表

芯片选型是重决策，参数表（TOPS、内存、功耗）只是起点。工程上的「正确评测姿势」：

- **跑自己的模型**：厂商的「演示模型」跑得快不代表「你的感知/规划模型」跑得快——**拿自家代表性模型（BEV 感知、端到端规划）在目标芯片上实测**，测「真实端到端延迟与吞吐」。
- **测「多路并发」**：车端同时跑「相机感知 + 雷达 + 规划 + 监控」多个任务——**单模型快 ≠ 多任务总延迟达标**，要测「整栈并发下的端到端时延」。
- **测「动态场景」**：芯片在「负载波动」（急刹时感知重算、多个模型同时调度）下的稳定性——**「峰值负载下的最坏时延」比「平均时延」更重要**（实时性看最坏）。
- **看「生态与工具链」**：部署工具链（TensorRT 等）的成熟度、算子支持度、调试体验——**「部署的效率」直接决定「芯片的可用性」**，这是参数表看不出来的。

一个常被忽视的评测维度：**「算力余量」**——量产车要为「未来算法升级」（更大模型、更高分辨率）预留算力。**「当前够用但没余量」的芯片，车型还没卖完算法就升级不动了**——「选芯片」本质是「为未来 3–5 年的算法买算力」。

<span class="marginnote">芯片评测的本质是「<strong>用你的负载、你的场景、你的未来需求去测</strong>」——参数表是「厂商的定义」，实测才是「你的现实」。工程上有个经验：<strong>「芯片 + 工具链 + 你的模型」三者共同决定性能，任何一环短板都拖累整体</strong>。选芯片不是「选最强」，而是「选「最强组合」」——芯片、软件栈、算法团队的匹配度。</span>

最后，把「芯片」放回「自动驾驶技术栈」的位置，看清它的「生态位」：**芯片是「算力的载体」，而「算力」是「算法」与「数据」的「乘数」**——算法再好，算力不够就是空转；数据再多，算力不够就训练不动、推理不了。三者的关系：

- **算法 × 算力**：端到端大模型（算法）需要大算力（芯片）——「算法的进步」与「算力的进步」互相成就；
- **数据 × 算力**：数据飞轮（采集、标注、训练）消耗算力——「数据的规模」受「算力成本」制约；
- **三者的平衡**：哪一环短板，都成为系统瓶颈——「算法、数据、算力」是自动驾驶的「不可能三角」中的动态平衡。

所以「芯片选型」不只是「选一个处理器」，而是「选一个「算力-成本-生态」的组合」，它决定了「算法能走多远、数据能用多大」。**「芯片是自动驾驶的「底座」」**——底座不稳，上层再强也摇摇欲坠。

**辨析｜易错点：** 「TOPS 越大越好」是最常见的选型误区——实际瓶颈常在「内存带宽」与「算子利用率」，而非裸 TOPS。一个「小 TOPS 但带宽足、利用率高」的芯片，可能比「大 TOPS 但带宽卡脖子」的芯片跑得更快。**看芯片，先看「你的负载」能利用它多少**，而不是参数表的峰值数字。

**关联阅读**：芯片的「算力-成本」权衡见《车载计算平台演进：从 MCU 到中央计算》；「实际部署」见《模型车端部署：量化、剪枝与 TensorRT 推理优化》；「软硬协同」与《车载中间件：ROS 2、AUTOSAR 与 DDS》衔接。

**快速自查**：选芯片前问自己三个问题——「我的模型在它上面的实际利用率是多少」「它的工具链能不能流畅部署我的模型」「我的车型生命周期内，算法升级的算力余量够不够」。三个问题答不上来，参数表再好看也别急着下单。

## 7 小结

- TOPS 有**稀疏/稠密、精度、利用率**的猫腻，「有效算力」比裸数字更真实。
- **英伟达**：通用 GPU + 成熟生态，算力军备竞赛，高功耗高成本。
- **地平线**：专用 NPU + 高算力密度，国产供应链，L2+ 性价比之王。
- **特斯拉**：全栈自研 + 端到端定制，系统最优但路线绑定。
- 选芯片 = 选「算法自主权」：通用生态、专用性价比、还是全自研垂直整合。
