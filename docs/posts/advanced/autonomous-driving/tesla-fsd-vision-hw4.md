## 为什么从 Tesla FSD 讲起

如果说 Waymo 是 L4 的「保守教科书」，**Tesla FSD** 就是自动驾驶的另一极——**激进、纯视觉、端到端、以量产车为平台的数据飞轮**。它不追求「先证明再运营」，而是「让百万辆车在路上跑，用海量真实数据训练出自动驾驶」。这条路线在过去几年引发了最多的争论，也催生了「视觉 vs 激光雷达」与「端到端 vs 模块化」的世纪辩论。

理解 Tesla FSD，要抓住三个关键词：**纯视觉（Vision-only）、Occupancy 网络、端到端**，以及它的硬件基础 HW3/HW4。本节拆解这三个关键词的技术内涵，并分析这条路线「为什么能走、凭什么敢走」。

## 1 纯视觉：砍掉 LiDAR 的赌注

**核心概念：Tesla 的纯视觉路线**：只用相机（8 个摄像头，覆盖 360°）作为感知传感器，不用 LiDAR 与毫米波雷达（2022 年起新车上取消雷达）。理由是「人类视觉即可驾驶，相机信息足够，LiDAR 是拐杖」。

纯视觉的论据：

- **信息充分性**：相机提供最丰富的语义信息（颜色、文字、交通灯、车道线）——LiDAR 点云反而缺语义。
- **成本与规模**：相机便宜（一个 LiDAR 顶几十个相机），这让「百万辆车采集数据」成为可能——**纯视觉是数据飞轮的成本前提**。
- **硬件一致性**：不依赖外部 LiDAR 供应商，供应链可控，大规模量产可行。

纯视觉的挑战：**深度估计**（从 2D 图像恢复 3D 距离）、**恶劣环境**（雨雾、逆光）、**对算法泛化的更高要求**。Tesla 的回应是「用大规模数据 + 网络架构弥补」——它赌的是「数据+算法能战胜传感器冗余」。

<span class="marginnote">纯视觉路线的核心逻辑是「<strong>规模换冗余</strong>」：Waymo 用「多传感器冗余」换单次可靠性，Tesla 用「百万车的数据规模」换算法成熟度。<strong>一辆车有 LiDAR 但只有一万辆，不如一辆车只有相机但有一百万辆——数据飞轮的复利可以超越传感器冗余</strong>。这是 Tesla 与 Waymo 最根本的分歧：不是「视觉够不够」，而是「规模 vs 冗余谁更值钱」。</span>

## 2 Occupancy 网络：纯视觉的 3D 感知

纯视觉没有 LiDAR 的直接 3D 测量，如何做到 3D 感知？Tesla 的答案是 **Occupancy Network（占用网络）**——用网络从多相机图像直接预测**体素化的 3D 空间占用**：每个小立方体「是否有物体、是否可行驶」。

Occupancy 网络的优势：

**不依赖语义类别**：不需要把每个物体识别成「车/人/桶」，只判断「这格空间被占用了吗」——对**异形/未知物体**（翻倒的卡车、散落物）也有效。
**对感知不确定性的容忍**：输出是「占用概率」而非「检测框」，天然表达「这里可能有什么」。
**给规划提供空间约束**：占用网格直接告诉规划「哪块空间不能去」——是「空间级避障」而非「目标级避障」。

Occupancy 网络是 Tesla 从「目标检测」走向「场景占用」的关键一步——它让纯视觉系统有了「不依赖 LiDAR 的 3D 理解」，且对长尾物体更鲁棒。这与《Occupancy 占用网络》一节的内容直接呼应——Tesla 是把占用网络大规模商用的先行者。

## 3 端到端：从模块化到「一个网络」

Tesla FSD 的架构演进是理解其技术路线的核心：

**V9/V10（2021）**：多任务 CNN 架构（HydraNet），统一视觉特征、多任务头（检测、车道线、占用）。
**V11（2022）**：引入 Transformer 与「车道网络」，向「一个统一的视觉模型」收敛。
**V12（2023）**：**端到端神经网络**——从摄像头输入直接到控制输出，中间的感知/预测/规划全部内化为网络层。

V12 的端到端是 Tesla 路线的高潮：**它把「感知+预测+规划」压缩成一个可微的神经网络，用「人类驾驶行为」做监督，直接学「看到什么 → 怎么开」**。这背后是数据飞轮的终极形态——**百万辆车的影子模式（FSD 后台运行）持续收集「人类 vs 机器」的差异数据，不断训练端到端网络**。

<span class="marginnote">端到端的代价在 Tesla 身上同样显现：<strong>可解释性几乎为零</strong>——V12 无法回答「为什么在这里减速」，只有数据统计上的「行为分布合理」。Tesla 用「海量里程 + 影子模式比对」替代「逻辑可解释」，赌的是「<strong>统计足够好就不需要逻辑可解释</strong>」。这条赌注目前仍在验证中，也是监管对 FSD 谨慎的核心原因。</span>

## 4 HW4 与硬件迭代：算力军备竞赛

Tesla 的硬件沿着「算力随算法需求迭代」演进：

- **HW3（2019）**：144 TOPS（自研 FSD 芯片），支撑 V9–V11 的多任务视觉网络。
- **HW4（2023）**：算力约为 HW3 的 3–5 倍，摄像头分辨率提升、新增一个前向摄像头，目标是为「端到端 + 更高分辨率输入」提供余量。

Tesla 硬件的设计哲学是**「软硬协同、垂直定制」**：芯片为自家算法定制（DLA 加速器针对 Transformer/CNN），算法升级与硬件迭代绑定。HW4 的算力提升不是「追求 TOPS 数字」，而是「端到端模型 + 更高分辨率视频流」的实际需求。

HW4 与 FSD 的耦合值得注意：**Tesla 的路线高度绑定自家软硬件**——换一代算法就换一代硬件，这套「全栈自研」让它在「纯视觉 + 端到端」这条路上没有妥协与适配成本，但也把「押注的路线」变成了「不可回退的沉没成本」。

## 5 公式解析：数据飞轮的收益模型

Tesla 路线的数学内核是「数据飞轮」。设车队规模 $N$（搭载 FSD 的车辆数）、每车每日行驶 $L$ 公里、影子模式采集比例 $\eta$、有效数据率（标注/筛选后可用比例）$\rho$，则每日新增有效训练数据：

$$
D_{\text{daily}} = N \times L \times \eta \times \rho
$$

- **第一步，看规模项 $N \times L$**：车队越大、跑得越勤，原始数据越多。**这是 Tesla 相对所有 Robotaxi 公司的根本优势——它不用自建车队，百万用户替它采集数据**。
- **第二步，看影子模式 $\eta$**：不是所有里程都产生「训练价值」，只有「FSD 运行且与人类行为有差异」的里程才值得采——$\eta$ 衡量「影子模式的有效采集率」。
- **第三步，看有效数据率 $\rho$**：海量原始数据要经筛选（长尾挖掘）与标注（自动标注）才变成训练集——$\rho$ 衡量「数据管线的效率」。**这正对应数据闭环章节的筛选与标注工程**。
- **第四步，看飞轮的正反馈**：$D_{\text{daily}}$ 越大 → 模型越好 → FSD 更可用的用户越多 → $N$ 越大 → $D_{\text{daily}}$ 更大。**这个正反馈循环是 Tesla 路线的核心资产，也是竞争对手最难复制的部分**——它需要「百万车 + 影子模式 + 数据管线」三位一体。

## 6 Tesla 路线的「风险」：纯视觉与端到端的赌注

Tesla 路线的激进，意味着它承担了几类「结构性风险」，理解它们才能客观评价这条路线：

- **视觉的物理上限**：纯视觉的深度估计与「恶劣天气（暴雨、浓雾）」下的感知，受「物理信息」限制——**「相机没有 LiDAR 的主动测距」是物理事实**，算法只能逼近、不能超越。这是「纯视觉路线」被质疑的根基。
- **端到端的「可解释」缺失**：V12 无法回答「为什么这样决策」——**「监管、保险、事故归因」都需要可解释**。Tesla 赌「数据统计足够好就不需要解释」，但「统计好」与「可证明安全」是两回事。
- **法规与责任的边界**：FSD 仍属 L2（驾驶员负责），但宣传上接近「自动驾驶」——**「能力与责任的错配」**是 FSD 事故争议的制度根源。
- **单一路线的「沉没成本」**：HW 与算法深度绑定，若「纯视觉端到端」路线被证明不可行，Tesla 的芯片、数据、模型都要重来——**「全栈自研」的反面是「全栈绑定」**。

| 风险 | 表现 |
| --- | --- |
| 视觉物理上限 | 恶劣天气短板 |
| 可解释缺失 | 监管与归因难 |
| 责任错配 | 事故争议 |
| 路线绑定 | 沉没成本高 |

<span class="marginnote">Tesla 路线的价值，不在于「它一定对」，而在于「<strong>它做了一个全行业最大的「对照实验」</strong>」——用百万辆车、海量数据、端到端范式，检验「纯视觉 + 数据飞轮」能否通向自动驾驶。无论结果如何，这场实验都在「用真实世界的规模」回答「数据到底能补多少传感器与规则」——<strong>它把自动驾驶的「未知」变成了「正在被验证的假设」</strong>，这对整个行业都是知识资产。</span>

把 Tesla FSD 放回「从极限到大模型」的主线，它最有启发的不是「技术细节」，而是「一个方法论」：**「用「量产车 + 数据飞轮」验证「激进的技术假设」」**——它把「纯视觉能否替代激光雷达」「端到端能否替代模块化」这些「激进假设」，从「实验室辩论」变成了「百万辆车的实证」：

- **假设的「可证伪」**：Tesla 的路线是一个「可证伪的假设」——数据积累到一定规模，若仍未达到 L4，就证明「纯视觉 + 端到端」的边界；若达到了，就证明「数据可以补传感器与规则」；
- **验证的「规模」**：这种「用量产车验证」的方式，只有「有百万辆车 + 海量数据」的玩家能做——**「规模」本身就是「实验装置」**；
- **知识的「外溢」**：无论 Tesla 成败，这场「实验」都在用「真实世界的数据」回答「自动驾驶的技术路线问题」——**「行业共同的知识资产」**。

这个「方法论」给所有「技术路线之争」的启示是：**「没有数据的路线争论，都是空谈」**——「纸面上的优劣」与「规模化后的真实表现」，可能完全不同。**「让数据说话，用规模验证」**——这是 Tesla 给自动驾驶产业最重要的方法论遗产。

**辨析｜易错点：** 「纯视觉 = 不用激光雷达」不等于「纯视觉 = 更安全」——纯视觉的「成本优势」是明确的，但「安全冗余」确实更薄。**「纯视觉」是一个「成本换扩展」的赌注，不是「技术上的必然更优」**——评价它，要看「数据规模」能否补上「传感器冗余」，而非「视觉 vs 雷达」的口号之争。

## 7 小结

- Tesla FSD = **纯视觉 + Occupancy 网络 + 端到端 + 数据飞轮**，与 Waymo 的「多传感器 + 模块化」形成两极。
- 纯视觉的赌注是「**规模换冗余**」：相机便宜让百万车采集数据成为可能。
- **Occupancy 网络**让纯视觉有了 3D 空间理解，对长尾与异形物体更鲁棒。
- **V12 端到端**把全栈压成一个网络，用影子模式数据持续训练——代价是可解释性几乎为零。
- HW4 为端到端与高分辨率输入提供算力，软硬一体、垂直定制、路线绑定。
