## 为什么从状态机讲起

上一节把行为规划定义为「决定怎么开的高层决策」。这一层怎么实现？早期自动驾驶和今天量产车的绝大多数系统，给出的答案既朴素又强大：**把驾驶拆成一组离散的「状态」，用状态之间的转移规则组织决策**——这就是有限状态机（FSM）。Waymo 早期、百度的 Apollo、大量 L2+ 量产方案的行为层，核心都是（或曾是）一个精心设计的 FSM 或决策树。

为什么「老派」的状态机至今不可替代？因为它把「驾驶智慧」写成了**人类可读、可审计、可逐条调试的规则**。工程师可以明确地说「当自车车速 < 10 km/h 且前方无车时，进入『起步』状态」，并且精确知道它的触发条件——这种可解释性是深度学习决策至今难以提供的。本节讲清 FSM 与决策树这两个经典决策器的建模方式、优势与边界。

## 1 有限状态机：把驾驶写成「状态 + 转移」

**核心概念：有限状态机（Finite State Machine, FSM）**：由一组离散状态 $S = \{s_1, \dots, s_n\}$、一组转移条件与一个初始状态构成。任意时刻机器处于唯一状态，当转移条件满足时跃迁到另一状态。

自动驾驶的 FSM 里，状态就是驾驶行为：起步、跟车、巡航、变道、超车、路口通行、让行、靠边停车…… 转移条件由规则表达：

```text
# 有限状态机（FSM）转移规则示例
if   自车车速 < 10 km/h 且 前方无车:           状态 → 起步
elif 车头时距 < 2 s 且 制动距离不满足:         状态 → 减速跟车
elif 前车消失 且 车道畅通:                     状态 → 巡航
elif 目标车道更优 且 无碰撞风险:               状态 → 变道
elif 感知异常 或 定位漂移:                     状态 → 靠边停车（降级兜底）
```

<span class="marginnote">FSM 的核心设计决策是<strong>「状态粒度」</strong>：状态太粗，表达不了细腻行为（一个「路口通行」状态管不了路口内所有情况）；状态太细，转移规则爆炸、难以维护。工业界的做法是分层 FSM——顶层管行为大类，每类内部再嵌一层子状态机。粒度的权衡，是状态机设计的艺术。</span>

FSM 的优势：**计算量极小**（每次只要检查转移条件）、**行为可预期**（给定状态与条件，输出确定）、**易于调试**（问题可定位到某个状态/转移）。它天然适合「行为空间的离散性」——驾驶行为在抽象层面确实是离散的。

## 2 FSM 的困境：状态爆炸与语义模糊

FSM 的光环背后有三个结构性缺陷，理解它们才知道为什么现代系统要在 FSM 之外再加别的东西：

**状态爆炸（state explosion）**：真实驾驶的组合是巨大的——路口 × 车道数 × 交通灯 × 让行关系 × 障碍物组合，直接枚举状态会让规则表呈指数膨胀。
**转移条件语义模糊**：规则用阈值表达，但「安全距离」「机会窗口」这些概念本质是**连续且情境相关**的。固定阈值在一种场景好用、换一种场景就误判。
**无记忆、无不确定性**：经典 FSM 是确定性的，不会对「对方可能让也可能不让」表达概率；它也难以利用连续量（车速、车距的精确数值），只能粗糙地阈值化。

正是这些缺陷，推动行为规划从「规则状态机」走向「决策模型」——把决策空间从离散枚举变成**优化问题**。

## 3 决策树：把「如果-那么」组织成树

**核心概念：决策树（Decision Tree）**：把决策规则组织成树状结构——内部节点是条件判断，叶子节点是行为决策。相比平铺的 FSM 规则表，决策树显式表达「先判断什么、再判断什么」的优先级。

自动驾驶决策树的经典应用是 **ST 图上的行为选择**（后面 EM Planner 一节还会见到）：横轴时间、纵轴沿车道距离的时空图上，对每个候选动作（跟车、变道、停车等待）逐层判断「是否可行 → 是否安全 → 是否更优」，最终选中叶子对应的行为。

决策树与 FSM 的差别在于**结构信息**：树的深度代表决策优先级，同一层节点共享同一判据。例如「先判安全性（会不会撞），再判合法性（是否违反交规），最后判效率（是否更快）」——这个优先级顺序就是树的层级。

<span class="marginnote">决策树有一个直觉上的好处：<strong>可解释性比 FSM 更强</strong>——给定一条路径，你可以指着树的每一层说「这一步排除了哪些选择、为什么」。这也是为什么「规则 + 决策树」成为量产车行为层的主流底座：它在可解释的前提下，比纯 FSM 表达更复杂的策略。</span>

## 4 规则基决策的工程实践：参数、调试与兜底

规则基决策（FSM + 决策树）在工业界有成熟的工程方法论，值得了解几个关键实践：

- **参数调优是主要工作**：所有阈值（安全车距、变道提前量、路口停车线余量）都需要在真实道路与仿真中反复标定。很多公司为此建立了**参数自动标定**管线。
- **规则分层组织**：安全规则（永不碰撞、红灯必停）放在最顶层，不可覆盖；策略规则（何时变道更优）在底层，可动态调整。**「安全规则不可协商」**是铁律。
- **异常状态处理**：FSM 必须显式设计「未知状态」与「降级路径」——感知异常、定位漂移、行为决策失效时，转入保守模式（减速靠边）。**状态机设计的一半工作量在异常分支**。

工业界有一个经验数字：量产车行为层的规则代码动辄数十万行，绝大多数在处理长尾边界与异常。这也是「规则永远写不完」批评的由来——但反过来看，**它恰恰是规则基系统安全性的来源**：每个边界情况都被显式处理过。

## 5 公式解析：用「安全距离包络」写转移条件

状态机转移条件虽以规则呈现，背后都有解析模型支撑。以「能否进入跟车状态」为例，常用**车头时距（time headway）**与**制动安全距离**两个判据。

设自车速度 $v$、前车速度 $v_f$、两车距离 $d$，安全跟车需满足制动距离约束：

$$
d \;>\; v\,T_{\text{reaction}} \;+\; \frac{v^2 - v_f^2}{2\,a_{\max,\text{brake}}} \;+\; d_0
$$

- **第一步，看第一项 $v T_{\text{reaction}}$**：驾驶员/系统从感知到制动的反应时间内走过的距离。$T_{\text{reaction}}$ 是传感器延迟 + 决策延迟 + 执行延迟之和。
- **第二步，看第二项 $\frac{v^2 - v_f^2}{2 a_{\max}}$**：以最大减速度 $a_{\max}$ 把自车从 $v$ 减到与 $v_f$ 同速所需的制动距离。若 $v \le v_f$，该项为负（不需要减速），自动放宽约束。
- **第三步，看第三项 $d_0$**：停车后的最小安全余量，防贴脸。
- **第四步，翻译成转移条件**：当且仅当 $d \;>\; vT_{\text{reaction}} + \frac{v^2 - v_f^2}{2a_{\max,\text{brake}}} + d_0$ 时，允许进入「跟车」状态；否则维持「减速/停车」。**阈值不是拍脑袋的，而是由车辆动力学参数（$a_{\max}$、反应时间）推导出来的**——这是规则基系统「看起来简单、实则严谨」的体现。

## 6 规则基决策的「知识工程」与它的天花板

规则基决策（FSM + 决策树）本质是「知识工程」——把驾驶专家的经验「手写」成规则。这套方法有一个清晰的天花板，理解它能帮你判断「什么时候该换方法」：

- **规则的可组合爆炸**：两条规则单独正确，组合起来可能冲突（「让行」与「尽快通过」在无保护左转时打架）。**规则系统的难点不是单条规则，而是规则间的关系**——需要优先级、冲突消解机制。
- **情境特征难以穷举**：「路口的让行」在不同车道数、不同来车速度、不同视野下，最优决策不同——**规则的「情境粒度」写粗了误判、写细了爆炸**。
- **边际成本递增**：规则系统的「最后 10% 正确性」需要「最后 90% 的规则量」——**长尾场景的规则收益递减**，这正是学习方法的切入点。

什么时候继续用规则、什么时候上学习？一个实用的判断：

| 场景类型 | 规则基是否够用 |
| --- | --- |
| 结构化、可枚举（高速、跟车） | 够用且更可靠 |
| 交互复杂、情境多变（路口、汇入） | 不够，需要学习/博弈 |
| 长尾、罕见、不可枚举 | 规则写不动，靠数据/大模型 |

<span class="marginnote">规则基决策的「不可替代性」在于它的「<strong>可证明性</strong>」：每条规则都能被审计、被测试、被追溯——这是功能安全（ISO 26262）认证最看重的能力。所以量产系统的现实是「<strong>规则做底盘（安全、可证），学习做增量（复杂、长尾）</strong>」——不是「规则被淘汰」，而是「规则降级为安全底座」。</span>

「规则基决策」与「学习决策」（MDP/博弈/端到端）的关系，是「确定性」与「灵活性」的权衡，用一个「光谱」来看更清楚：

| 光谱位置 | 方法 | 特性 |
| --- | --- | --- |
| 极左（最确定） | FSM 纯规则 | 完全可解释、可证明，但僵化 |
| 中间 | 决策树 + 参数 | 结构化，但调参繁重 |
| 中右 | MDP/POMDP | 优化导向，但依赖模型 |
| 极右（最灵活） | 端到端学习 | 数据驱动，但不可解释 |

「选哪」取决于「对「可解释」与「灵活」的需求权重」：**安全关键（可解释优先）偏左，复杂交互（灵活优先）偏右**。而量产系统的现实是「**跨光谱的混合**」——FSM 做「安全兜底的骨架」、MDP/博弈做「交互决策」、学习/大模型做「长尾与语义」，各取所长。**「决策方法的选择」不是「站队」，而是「在光谱上按需求取点」**——这比「规则派 vs 学习派」的二元争论更有工程价值。

## 7 小结

- **FSM** 把驾驶写成「离散状态 + 转移条件」，计算极快、行为可预期、易于调试，是量产车行为层的主力。
- FSM 的缺陷是**状态爆炸、阈值语义模糊、无不确定性表达**。
- **决策树**用树结构显式表达决策优先级，可解释性更强，常与 FSM 并用。
- 规则基决策的工程核心是**参数标定、分层规则、异常兜底**，安全规则不可协商。
- 转移阈值背后有**解析的安全距离模型**支撑，不是拍脑袋设定。

在下一节，我们看规则基决策的「升级版」：**当行为决策被写成带状态转移与回报的马尔可夫决策过程（MDP），以及处理不确定性的 POMDP**——决策从规则走向优化。
