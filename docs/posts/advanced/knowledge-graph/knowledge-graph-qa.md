## 为什么从「问答」开始

图谱、抽取、嵌入、推理，全部技术最终要回答一个问题：**用户用一句话问知识，系统怎么答？** 这就是**知识图谱问答（Knowledge Base Question Answering, KBQA）**——自然语言问题 → 图谱上的查询 → 精确答案。它是知识图谱的「人机界面」，也是检验全链路（表示、抽取、嵌入、推理）的综合考场。<span class="marginnote">与大模型问答对照看最有意思：LLM 凭参数记忆作答，KBQA 从图上取事实作答——前者可能一本正经地胡诌，后者要么给精确答案、要么给「无解」。RAG 时代的问答正是把两者焊在一起。</span>

一条经典问题链贯穿本节：**「爱因斯坦的出生地在哪里？」** —— 实体链接锚定「爱因斯坦」，识别出「出生地」是关系，识别出「在哪里」是询问属性，然后翻译成图谱查询、执行、返回「乌尔姆」。看似简单的一问，拆开全是前几节的功夫。

## 1 任务设定：从问题到答案的距离

**KBQA**：给定自然语言问题 $q$ 与知识图谱 $\mathcal{K}$，返回正确答案集合（可能是实体、字面量、布尔值、列表）。按复杂度分两档：

**单跳问答（single-hop）**：问题只涉及一条三元组。「爱因斯坦的出生地？」= `(爱因斯坦, 出生地, ?)`。
- **多跳问答（multi-hop）**：答案要沿着关系链走多步。「爱因斯坦的母亲出生在哪座城市？」= `(爱因斯坦, 母亲, ?x), (?x, 出生地, ?y)`，先找母亲再找出生地。

数据集方面，**SimpleQuestions** 是经典基准——约十万条「人工从 Freebase 出题、答案来自图谱」的单跳问题，配套约 500 万条子图；多跳基准有 WebQuestionsSP 等。评估上，问答任务常报「答案完全正确的比例」（accuracy）——答案要么对要么错，没有排名可排；多跳问题还会额外报告「每一跳的证据命中率」，用来定位失败发生在哪一跳。<span class="marginnote">评估沿用上一节的口径：链接预测用 Hits@K/MRR，问答通常用「答案完全正确的比例」（accuracy）——因为问题要么答对要么答错，没有排名可排。指标永远跟着任务走。</span>

## 2 语义解析路线：问题 → SPARQL

最早的、也最「符号派」的路线是**语义解析（semantic parsing）**：把自然语言问题翻译成可执行的图查询语言——通常是 **SPARQL**（RDF 的查询语言，相当于图谱界的 SQL），然后直接在图上执行。

一句「爱因斯坦的出生地在哪里？」会被翻译成：

```sparql
SELECT ?answer WHERE {
  ex:Einstein ex:bornIn ?answer .
}
```

多跳问题对应更长的查询。问「爱因斯坦的母亲出生在哪座城市？」，翻译成带连接（join）的 SPARQL：

```sparql
SELECT ?city WHERE {
  ex:Einstein ex:hasMother ?m .
  ?m          ex:bornIn   ?city .
}
```

注意两行查询通过变量 `?m` 连接——这正是图查询与 SQL join 同构之处，也是第二级《数据库》的 join 概念在语义网上的重演；而「把自然语言翻译成查询」这件事，和编译器的「把高级语言翻译成指令」在结构上惊人地相似：都要做「词汇映射 + 结构解析」。

执行的难点在「翻译」本身：要把「出生地」映射到关系 `ex:bornIn`、把「爱因斯坦」映射到实体 `<ex:Einstein>`、把疑问句结构映射到查询模板。实现方式从早年的人工模板、到序列到序列模型（seq2seq 生成 SPARQL）、再到今天的 LLM 指令生成。<span class="marginnote">seq2seq 生成 SPARQL 的难点在于：语言模型要「生成」结构化查询而不是自由文本，语法错误率极高——这催生了「先生成查询草图、再填槽」的混合方案。第二级《形式语言与自动机》里的语法，在这里是工程问题。</span>

语义解析路线的优点：**答案可验证**——查询执行结果可回溯，解释性拉满；缺点：**天然脆弱**——问题稍有措辞变化，翻译就可能失败，泛化靠的是解析器的鲁棒性而非图谱本身。

## 3 信息检索与嵌入路线：在图上「检索答案」

另一条更「向量派」的路线不显式翻译成查询，而是把问答当**检索排序**：先用实体链接锚定问题中的实体，再在它的邻居图里为每个候选答案打分，取最高分者。打分信号混合了：

- **词语/语义相似**：候选答案的文本描述与问题有多接近；
- **路径证据**：从锚定实体到候选答案的关系路径有多合理；
- **类型与频次**：答案实体的类型、出现频次等先验。

嵌入路线则是把问题和候选答案都编码成向量，直接算相似度——整条链路变成「编码器 + 相似度」的可微分系统，可以与图谱嵌入联合训练。它在**泛化到未见关系**上更强，代价是**解释性差**、且同样依赖实体链接先锚定。

两条路线的分界并不总是清晰，现代系统常常**混合**：先用语义解析或模板把问题的「骨架」定下来（问的是出生地还是母亲），再用嵌入或检索把「骨架」里的实体与关系填实。这种「符号定结构、向量定取值」的混合架构，是 KBQA 工程中稳健性最高的选择——骨架错了无从修，取值错了还有回旋余地。

## 4 公式解析：嵌入问答的打分

设问题经编码器得到向量 $\mathbf{q} \in \mathbb{R}^d$。先用实体链接把问题锚定到实体 $e_0$，对每个候选答案 $a$（$e_0$ 的可达邻居），把它到 $e_0$ 的**路径表示**编码成向量 $\mathbf{p}_a$（路径上各关系的嵌入求和或求均值）。打分函数取问题与路径的相似度：

$$
a^* = \arg\max_{a \in \mathcal{C}(e_0)} \; \mathrm{sim}\!\left(\mathbf{q}, \; \mathbf{p}_a\right)
$$

其中 $\mathbf{p}_a$ 是对路径 $\rho = (e_0, r_1, \dots, r_k, a)$ 的编码：

$$
\mathbf{p}_a = \frac{1}{k} \sum_{i=1}^{k} \mathbf{r}_i
$$

三步拆解：

- **第一步，锚定起点**：$\mathcal{C}(e_0)$ 是 $e_0$ 一定步数内可达的候选答案集合——先「认出问题里的实体」，把搜索范围锁进它的邻域。
- **第二步，编码路径**：$\mathbf{p}_a$ 把「从 $e_0$ 怎么走到 $a$」这条路径变成向量——路径上的关系嵌入求平均，回答「该走哪条关系链」。
- **第三步，相似度排名**：$\arg\max$ 在候选里挑与问题最像的路径——问题问「出生地」，路径若经过 `bornIn` 关系，相似度就高。最终答案就是该路径终点 $a^*$。

**直觉**：这条路线把「问题」与「路径」放进同一个向量空间，让「理解问题」和「理解图」共用一把尺子。单跳问题对应 $k=1$ 的路径，多跳问题对应 $k>1$——**同一个公式、不同深度**，这也是为什么嵌入路线天然能应付多跳。

从工程角度看，这个公式还揭示了一条通用定律：**问答系统的好坏，一半由编码器决定，一半由路径质量决定**——路径里混进噪声关系，相似度就会失真，所以图谱质量（第四篇的对齐、第七篇的推理）永远是问答的地基。

## 5 多跳问答与大模型时代

**多跳问答**是 KBQA 的难点：它要沿关系链组合证据，任何一跳失败，答案就断。符号派用「在图上递归展开」处理（路径检索 + 打分），向量派用「多次推理」或图神经网络传播处理。<span class="marginnote">第四级《图神经网络》里的消息传递，本质上就是在图上做多跳的嵌入传播——GNN 问答与路径打分在多跳问题上殊途同归。</span>

进入 LLM 时代，KBQA 发生了有趣的合流：

- **LLM 当语义解析器**：让大模型把问题翻译成 SPARQL 或函数调用，再交给图谱执行器——大模型负责「翻译」，图谱负责「保真」。

LLM 当语义解析器有一个工程要点：直接让 LLM 输出 SPARQL，语法错误率仍不低，常见补救是「两步走」——先生成「查询意图」（单跳还是多跳、要找哪个关系），再由程序按模板组装 SPARQL，必要时把非法查询送回 LLM 重写一次（self-correction）。把「生成自由查询」降维成「生成意图 + 程序拼装」，错误率能降一个数量级。
- **RAG（检索增强生成）**：先在图谱上检索相关三元组或子图，拼进提示词让 LLM 生成答案——图谱提供事实证据，LLM 组织语言。
- **GraphRAG**：把图谱索引成社区摘要，让检索覆盖「跨实体的全局问题」——处理的是「这些实体共同涉及什么」而非单个实体查询。

GraphRAG 的要点值得多写一句：它先把图谱按社区结构聚类（例如社区发现算法），为每个社区生成「社区摘要」存入索引——查询时既检索单实体的路径，也检索社区摘要，从而把「逐实体」的问答升级成「跨实体」的综合问答。成本在离线建索引，收益是回答的全局性与可解释性同步提升。

**易错点：** 三个误区。其一，**别用 LLM 直接替代图谱**——参数记忆会幻象，图谱是「地面真相」的锚；其二，**别把 RAG 当免检通道**——检索质量决定答案质量，实体链接仍是第一道关卡；其三，**别忽视不可回答问题**——好系统要会说「图谱中没有这个事实」，而不是硬凑一个。这三点在第四级《RAG》与《AI 安全》里分别有更深的分工讨论——答案的「可追溯性」，正是符号与神经合流的核心契约。

## 6 小结

- **KBQA**：自然语言问题 → 图谱查询 → 精确答案；分单跳与多跳两档，SimpleQuestions 是单跳基准。
- **语义解析路线**把问题翻译成 SPARQL 后执行——可验证、可解释，但翻译脆弱。
- **检索/嵌入路线**把问答当排序：锚定实体 → 编码路径 → 相似度挑答案，天然支持多跳。
- 打分公式 $a^* = \arg\max_a \mathrm{sim}(\mathbf{q}, \mathbf{p}_a)$ 中，路径编码 $\mathbf{p}_a$ 用关系嵌入求平均——问题与图共用一把尺。
- LLM 时代：LLM 当解析器、RAG 当证据供给、GraphRAG 处理全局问题；图谱负责保真，模型负责表达。
- 符号定结构、向量定取值，混合架构最稳健；检索质量决定答案质量。

在下一节，我们从「用图」退后一步，审视「图是怎么被定义出语义的」：本体（ontology）与本体构建——给数据立规矩的那层结构。
