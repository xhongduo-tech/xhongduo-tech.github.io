## 为什么从"命名"开始

前三篇我们依次掌握了 TF、IDF、长度归一化三件工具。现在面临一个实际问题：**它们怎么组合？** TF 有原始计数、对数、二值三种形态；IDF 有加平滑与不加平滑两种；长度归一化有做与不做两种。粗算一下，$3 \times 2 \times 2 = 12$ 种组合，还没算其他自由度。论文里说"用 tf-idf 加权"，到底用的是哪一种？**没有统一的命名，学术交流与工程复现都会陷入混乱。**

**SMART 权重体系（SMART notation）** 就是为消除这种混乱而生的一套**命名法**：用三个小写/大写字母，精确指定"词项权重怎么算、文档权重怎么算、相似度怎么算"。它源自 Gerard Salton 在康奈尔开发的 SMART 检索系统（1970 年代），至今仍是检索论文里约定俗成的"配方语言"。<span class="marginnote">SMART 的名字是 System for the Mechanical Analysis and Retrieval of Text 的缩写。<strong>这套命名法最著名的用例，是《Introduction to Information Retrieval》里反复出现的 $\text{lnc.ltc}$</strong>——它被用作"默认的、表现良好的基准权重方案"，你会在无数检索实验里看到它作为基线的身影。</span>

## 1 三个字母分别代表什么

SMART 记号写作 `X.Y.Z` 三段：

**X（文档词项权重）**：小写字母，指定文档侧每个词项的权重怎么算。
**Y（查询词项权重）**：小写字母，指定查询侧每个词项的权重怎么算。
**Z（相似度）**：大写字母，指定用什么公式计算文档与查询的相似度。

每段字母的含义是固定的对照表。**词项权重**一段常用：

| 字母 | 含义 |
| --- | --- |
| b | 二值（binary）：出现为 1，不出现为 0 |
| t | 原始词频（raw tf）：出现次数 |
| n | 原始词频（同 t，不同文献略有差别） |
| a | 增权词频（augmented）：$0.5 + 0.5 \cdot \frac{\text{tf}}{\max \text{tf}}$ |
| l | 对数词频（log）：$1 + \log \text{tf}$ |
| d | 对数词频 + 长度归一化 |

**相似度**一段常用：

| 字母 | 含义 |
| --- | --- |
| c | 余弦相似度（cosine） |
| d | 点积（dot product） |

**重点：SMART 记号是一个"配方表"，每个字母是一个可替换的配料。** 读懂 `lnc.ltc`，就是在读一份"文档与查询各用什么 TF、是否归一化、最后怎么比较"的完整配方。<span class="marginnote">不同文献里字母的含义略有出入（比如 `n` 与 `t` 有时都指原始词频），<strong>阅读时以作者随文定义为准</strong>。SMART 的价值不是"统一字典"，而是"强制作者说清楚自己用了什么"——它让模糊的"tf-idf"变成可复现的 `lnc.ltc`。</span>

## 2 逐字拆解 lnc.ltc

把最著名的方案 `lnc.ltc` 逐字母拆开：

**文档侧 `lnc`**：

- **l**：对数词频，$1 + \log \text{tf}_{t,d}$——TF 用亚线性压缩。
- **n**：不做 IDF（none）——文档侧不用 IDF 加权。
- **c**：余弦归一化——每个文档向量除以自身模长，化为单位向量。

**查询侧 `ltc`**：

- **l**：对数词频，$1 + \log \text{tf}_{t,q}$。
- **t**：做 IDF 加权，$idf_t$——查询侧用 IDF（"t" 代表 tf-idf 里的 idf）。
- **c**：余弦归一化——查询向量也化为单位向量。

**组合效果**：查询侧对稀有词给更高的权重（IDF），文档侧不重复加权（避免双惩罚）；两侧都做对数 TF 与余弦归一化。于是相似度就是：

$$score(q, d) = \frac{\vec{q} \cdot \vec{d}}{|\vec{q}| \, |\vec{d}|}, \qquad w_{t,d} = 1 + \log \text{tf}_{t,d}, \qquad w_{t,q} = (1 + \log \text{tf}_{t,q}) \times idf_t$$

**辨析｜易错点：为什么查询侧要 IDF，文档侧不要？** 直觉是：IDF 的意义是"区分哪些词值得重视"——这个判断应该由**查询**做（决定用户重视什么），而不该由**文档**做（文档侧加权是给所有词统一发权重，再被查询挑）。若两侧都用 IDF，等于把"区分度"乘了两次，会过度放大稀有词。**lnc.ltc 的智慧在于"区分度只在一个地方生效"。**<span class="marginnote">其实两侧都用 IDF（如 `ltc.ltc`）也在文献里出现过，且实验表现尚可。SMART 的价值恰恰在此：<strong>你可以在记号里明确看出"这套方案是两侧都加权还是只查侧加权"</strong>，然后放心地复现或修改。</span>

## 3 公式解析：lnc.ltc 的完整计算

用一个完整例子走一遍 `lnc.ltc` 的端到端计算。设文集 $N = 10^4$，查询「深度学习 算法」，其中「深度学习」的 $df = 100$，「算法」的 $df = 500$。文档 $d$ 中「深度学习」出现 2 次，「算法」出现 1 次，文档长度归一化后向量为：

**查询侧权重**：
「深度学习」：$(1 + \log 1) \times \log(10^4/100) = 1 \times 2 = 2.0$
「算法」：$(1 + \log 1) \times \log(10^4/500) = 1 \times 1.30 = 1.30$

**文档侧权重**（不乘 IDF）：
「深度学习」：$1 + \log 2 = 1.30$
「算法」：$1 + \log 1 = 1.0$

**余弦**：内积 $= 2.0 \times 1.30 + 1.30 \times 1.0 = 3.90$，两侧都已是单位向量，除以模长后得到分数。

三步拆解：

**第一步，注意查询侧的 `l`（对数 TF）**：查询词只出现一次（在查询本身里），对数 TF 就是 1——查询侧的对数 TF 通常恒为 1，真正起作用的是 IDF。
**第二步，看文档侧的"无 IDF"**：「深度学习」与「算法」的文档权重只由 TF 决定（1.30 vs 1.0），区分度完全交给查询侧。
**第三步，看两侧归一化**：单位化让查询与文档的模长不影响分数——**剩下唯一决定排序的就是"方向"**。

这个例子里「深度学习」因为更稀有（df=100 vs 500）在查询侧权重更高，而文档侧若两者都频繁出现，稀有词「深度学习」对分数的贡献就更大。<span class="marginnote">记住这个例子的结构：<strong>查询侧 = TF + IDF（区分度），文档侧 = TF（强度），相似度 = 余弦</strong>。这套结构的继承者很多——BM25 的 IDF 项同样只在"查询-文档匹配"时生效一次，学习排序的特征里也常见"查询侧 IDF × 文档侧 TF"这类乘法特征。</span>

## 4 其他常用方案与它们的取舍

`lnc.ltc` 不是唯一方案，看看其他常用配方，理解它们的取舍：

| 方案 | 含义 | 适用场景 |
| --- | --- | --- |
| `bnn` | 二值 TF、无归一化 | 布尔式召回，只要"有没有" |
| `nnn` | 原始 TF、无 IDF、无归一化 | 最简单的加权，几乎不用 |
| `ntn` | 原始 TF + 查询侧 IDF | 朴素 tf-idf |
| `ltc.ltc` | 两侧都做对数 TF + IDF | 双侧加权变体 |
| `lnc.ltc` | 文档侧轻、查询侧重 | **经典默认基线** |
| `lnd.ltc` | 对数 TF + 查询侧 IDF + 长度归一化 | 更贴近 BM25 精神的变体 |

**重点：方案的选择反映"哪一侧承担区分度"。** `lnc.ltc` 让查询承担全部区分度（文档侧只留强度）；`ltc.ltc` 让两侧共同承担；二值方案则完全放弃强度。**没有"最好"的方案，只有"对当前任务最合适"的方案——SMART 记号让你能精确比较不同选择的差异。**<span class="marginnote">一个工程经验：在大多数文本检索数据集上，`<strong>`lnc.ltc` 与 `ltc.ltc` 的表现接近，且都明显好于"两侧都原始 tf-idf"的方案。但数据集的特性（查询长短、文档长短分布、停用词处理）会影响最优选择——这就是为什么"配方语言"比"一个固定公式"更有价值。</span>

## 5 从 SMART 到 BM25：命名法的遗产

SMART 体系在历史舞台上没有被 BM25 完全取代，而是完成了更重要的任务：**它教会检索社区"精确描述权重方案"的习惯**。

**可复现性**：今天的检索论文（尤其是语义检索的基线对比）仍会用 `lnc.ltc` 或 `ltc.ltc` 这样的记号精确声明基线。
**组件化思维**：SMART 把"权重"拆成"TF 形态 × IDF 形态 × 归一化"三个正交维度，这个拆解直接催生了 BM25 的设计——BM25 的每个参数（k1、b、IDF）恰好对应 SMART 三个维度的一个升级版。
**实验文化**：有了命名法，实验之间才能公平对比——**"比 nnn.nnn 好 15%"比"比 tf-idf 好 15%"精确得多**。<span class="marginnote">这引出一个方法论的提醒：<strong>做检索实验，永远要精确声明你的基线是什么</strong>。"tf-idf 基线"是个模糊词，可能是 bnn、ntn、ltc、lnc 中的任何一个，而它们的差异可能超过你新方法的提升幅度。SMART 记号就是这种声明精度的工具。</span>

**辨析｜易错点：SMART 是"描述语言"，不是"算法"。** 它不告诉你怎么实现、怎么优化，只告诉你"用什么权重"。**把命名法当算法，是只见其表。** 真正的算法是背后的 TF / IDF / 余弦计算，以及下一篇《BM25》对它们的系统升级。

## 6 小结

- **SMART 记号** `X.Y.Z`：文档侧权重、查询侧权重、相似度公式，三个字母一份完整配方。
- **`lnc.ltc`**：文档侧对数 TF + 无 IDF + 余弦归一化；查询侧对数 TF + IDF + 余弦归一化。
- **设计智慧**：区分度（IDF）只在查询侧生效一次，避免双重惩罚；两侧余弦归一化保证公平。
- **方案谱系**：二值（bnn）、朴素 tf-idf（ntn）、经典默认（lnc.ltc）、双侧加权（ltc.ltc）。
- **遗产**：可复现性、组件化思维、实验文化——SMART 为 BM25 与整个检索社区奠定了"精确描述"的规范。
