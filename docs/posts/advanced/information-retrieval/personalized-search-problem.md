## 为什么从"用户"开始

至此，我们构建的检索系统有个隐含假设：**同一个查询，对所有用户返回同样的结果**。但现实远非如此——「Python」对程序员（编程语言教程）和对动物园爱好者（蟒蛇资料）意味着完全不同的东西；「银行」对普通用户（附近网点）和对金融从业者（行业新闻）需求迥异。**同一个查询的"正确答案"因用户而异。**

**个性化搜索（personalized search）** 把这个维度放回检索：**利用用户的历史行为、偏好与上下文，为不同用户定制查询结果**。它不是给所有用户"更好的结果"，而是给每个用户"对他更好的结果"——相关性从"查询 × 文档"扩展到"用户 × 查询 × 文档"。这篇立住个性化搜索的问题定义：它要解决什么、它的输入输出是什么、它与非个性化检索的关系。<span class="marginnote">个性化搜索在学术上有清晰的实证基础：<strong>同一查询在不同用户间的"理想结果"差异很大，且这种差异能被用户历史行为预测</strong>（如 2007 年 Teevan 等人的研究：用用户历史重排，能让约 40% 的查询结果变得更符合个人偏好）。但个性化也是把双刃剑——过滤气泡（filter bubble）让用户只看到"想看的"，牺牲"该看的"。个性化的工程与伦理边界，是它最微妙的部分。</span>

## 1 个性化的价值：同一个查询，不同的答案

先看个性化要解决的三个典型场景：

**歧义消解**：「Java」对 Java 程序员（编程）与咖啡爱好者（咖啡）——**用户历史揭示"哪个意思"**。
**偏好重排**：「手机」对追求性价比的用户（红米）与追求品牌的用户（苹果）——**用户历史揭示"偏好方向"**。
**个性化召回**：「机器学习课程」对初学者（入门课）与研究者（进阶课）——**用户历史揭示"水平层级"**。

**重点：个性化的本质是"把相关性定义从'查询-文档'扩展到'用户-查询-文档'"——用户信息成为相关性的一个输入。** 检索从"千人一面"走向"千人千面"。<span class="marginnote">个性化的价值度量：<strong>对高频、歧义、需求差异大的查询，个性化的收益最大</strong>；对明确、低歧义的查询（如「姚明身高」），个性化几乎无收益甚至有害（干扰确定性）。工业实践因此是"选择性个性化"——按查询特性决定要不要个性化，而非所有查询一视同仁。这个"按需个性化"的判断，与查询理解的意图分类直接联动。</span>

## 2 个性化检索的形式化

**核心概念：个性化搜索（personalized search）**：在检索的排序阶段，把用户信息 $u$ 纳入相关性计算：

$$\text{score}(q, d, u) = f(\text{相关性特征}, \text{用户特征})$$

而非个性化的 $\text{score}(q, d)$。用户信息通常来自：

- **长期画像（long-term profile）**：用户长期的兴趣领域、点击/浏览历史、搜索历史。
- **短期上下文（short-term context）**：当前会话的行为、近期的查询、当前的会话目标。
- **静态属性（static attributes）**：地域、语言、设备、年龄段。

**重点：个性化的输入是"用户信息"，输出是"个性化排序"——它不改变检索结构，只改变排序信号。** 经典的实现是在排序阶段"根据用户信息调整文档分数"——**个性化是"排序的修正"，不是"检索的重做"**。<span class="marginnote">这个"个性化是排序修正"的定位很重要：<strong>召回阶段通常保持"非个性化"（个性化召回会让候选池因人而异，大幅增加索引与缓存复杂度），个性化发生在排序阶段</strong>——对同一候选池，不同用户看到不同的排序。这个"召回共享、排序定制"的分层，是工业个性化的主流形态：既得到个性化收益，又保留"结果缓存、索引复用"的工程优势。</span>

## 3 个性化 vs 相关反馈 vs 查询改写

个性化与前面学的相关反馈、查询改写容易混淆，先厘清边界：

| 维度 | 相关反馈 | 查询改写 | 个性化 |
| --- | --- | --- | --- |
| 信息来源 | 本次查询的结果 | 语言/模型知识 | 用户的历史行为 |
| 作用层面 | 查询本身 | 查询本身 | 排序信号 |
| 时间跨度 | 单次/会话 | 单次 | 长期 |
| 目标 | 改进本次查询 | 改进查询表达 | 匹配用户偏好 |

**重点：三者不是替代关系，而是"不同层面的用户适配"——相关反馈和改写改"查询"，个性化改"排序"；相关反馈用"当次结果"，个性化用"历史积累"。** 一个完整系统常三者并用：改写让查询更清晰，相关反馈修正本次查询，个性化让排序贴合用户。<span class="marginnote">一个更准确的分类视角：<strong>相关反馈与查询改写是"查询侧"的适配（改变"搜什么"），个性化是"用户侧"的适配（改变"对谁搜"）</strong>。两者正交——同一个查询，可以既被改写、又被个性化排序。理解这个正交性，你就能把不同技术组合进同一系统而不混乱。</span>

## 4 公式解析：个性化的收益与风险

个性化的收益可以用"个性化增益"来形式化。设非个性化排序的相关性为 $R_0(q, d)$，个性化后的相关性为 $R_u(q, d)$，个性化增益：

$$\Delta(q, d, u) = R_u(q, d) - R_0(q, d)$$

三步拆解：

- **第一步，读增益来源**：$R_u$ 利用用户历史——把"用户更可能想要的文档"分数拉高、把"用户不感兴趣的"压低。
- **第二步，看什么时候增益为正**：查询歧义大、用户历史丰富时，$\Delta > 0$（个性化帮上忙）；查询明确、用户历史稀疏时，$\Delta \approx 0$ 甚至 $< 0$（个性化是噪声）。
- **第三步，看风险**：个性化的"错误判断"（把用户历史过度泛化）会让 $\Delta < 0$——**个性化在"猜错用户"时比不个性化更糟**。

**核心结论：个性化的收益是"条件性的"——它只在"查询有歧义 + 用户有可用历史"时为正。** 个性化不是无脑加用户信号，而是"有选择地、有把握地"用用户信号。<span class="marginnote">这个"条件收益"直接导出工程策略：<strong>个性化要"分级应用"——高把握（歧义查询 + 丰富历史）强烈个性化，低把握（明确查询 + 稀疏历史）少个性化或退回非个性化</strong>。类似"查询性能预测"的分诊逻辑，个性化也需要一个"该不该个性化、个性化多强"的决策层。这个决策层的缺失，是很多个性化系统"越做越差"的根源。</span>

## 5 个性化的评测难题

个性化的评测是它最难的工程问题之一：

**没有统一的"标准答案"**：非个性化评测有固定的相关性标注（每个查询-文档对有一个相关分）；个性化的"正确结果"因用户而异——**标注成本暴涨（每个用户 × 查询 × 文档）**。
**离线评测难**：怎么在离线数据上衡量"这个排序对这个用户更好"？——常用"用户行为预测"（个性化后用户点击率是否更高）作为代理。
**在线评测是主裁判**：A/B 测试——个性化组 vs 非个性化组的点击率、满意度对比——**个性化的效果最终只能靠在线行为验证**。<span class="marginnote">个性化评测的经典做法是"行为代理指标"：<strong>离线看"重排后的结果是否更符合用户历史"（如与用户常点的文档类型相似度），在线看"点击率、停留、满意率"</strong>。但行为指标有自证循环（用户被个性化结果吸引 ≠ 结果更好，可能只是"顺眼"）。评测个性化，本质上是在评测"系统对用户的理解"，而用户理解很难被一次性标注——这也是个性化研究长期开放的难题（第十一篇最后一篇会展开）。</span>

**辨析｜易错点：个性化的"相关性"与"满意度"是两回事。** 个性化结果让用户"满意"（符合预期、熟悉），不等于"相关"（解决了当前需求）——**用户可能满意于"顺眼的结果"，而错过了"真正有用但陌生"的结果**。这个"满意度 vs 相关性的张力"，是过滤气泡的根源，也是个性化评测必须警惕的陷阱。

## 6 数值算例：一次个性化重排的分歧

把"同一查询、不同用户、不同结果"演算成一次排序。设查询 "Python"，两个用户的画像与重排结果：

| 用户 | 用户历史（示意） | 重排前 Top-3 | 个性化重排后 Top-3 |
| --- | --- | --- | --- |
| 程序员 | 常搜"编程、算法、机器学习" | Python 教程 / Python 蛇资料 / Python 框架 | Python 教程 / Python 框架 / Python 蛇资料 |
| 动物园爱好者 | 常搜"动物、宠物、饲养" | Python 教程 / Python 蛇资料 / Python 框架 | Python 蛇资料 / Python 教程 / Python 框架 |

三步读这张表：

- **看重排前的"一刀切"**：两个用户看到同样的 Top-3，第一个都是"Python 教程"——**对程序员正确，对动物园爱好者错位**。
- **看个性化的翻转**：个性化后，程序员看到编程结果优先，动物园爱好者看到蟒蛇资料优先——**同一个查询，不同的"正确答案"**。
- **看条件收益**：这个例子中个性化收益巨大（查询歧义 + 用户历史丰富）；但对"姚明身高"这类明确查询，个性化无法改变结果（也无收益）——**个性化的收益是"条件性"的**。

这个例子是"个性化增益 $\Delta = R_u - R_0$"的实证：**歧义查询 + 丰富历史 → $\Delta$ 显著为正；明确查询 → $\Delta \approx 0$**。它导出工程结论：个性化要"分级应用"——高把握强烈个性化、低把握退回非个性化，而不是对所有查询无脑加用户信号。

**辨析｜易错点：个性化的"用户历史"要区分"长期稳定兴趣"与"短期临时需求"。** 用户长期是程序员（长期兴趣=编程），但此刻可能只想查"Python"这种宠物蛇怎么养（短期需求）——**历史是概率性的，不是决定性的**。过度依赖历史会把"临时的不同需求"误判成"偏离长期兴趣"，导致个性化帮倒忙。工程上"长期兴趣 + 短期上下文"并用、且短期上下文权重更高，是缓解这类误判的常用做法。

## 8 小结

- **个性化搜索**：把用户信息纳入相关性——$\text{score}(q, d, u)$，从"千人一面"到"千人千面"。
- **价值**：歧义消解、偏好重排、个性化召回——对"歧义 + 需求差异大"的查询收益最大。
- **定位**：个性化是"排序修正"而非"检索重做"——召回共享、排序定制。
- **与相关反馈/改写的关系**：前者改查询，个性化改排序；正交可组合。
- **条件收益**：$\Delta = R_u - R_0$ 只在"歧义查询 + 丰富历史"时为正——个性化要分级应用。
- **评测难题**：没有统一标准答案、行为代理指标、在线 A/B 是主裁判。
