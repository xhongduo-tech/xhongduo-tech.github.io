## 为什么评测要走向真实用户

前面五篇（P/R、F、MAP、NDCG）都属于**离线评测**：用固定的测试集和人工判定给系统打分，不惊动真实用户。这套方法快、可复现，但它有个先天局限——**判定表是冻结的**。评估员在安静的环境里逐篇判定「相关 / 不相关」，而真实用户会受页面排版、响应速度、品牌信任、广告干扰等一堆「相关以外」的因素影响。一个在 Cranfield 测试集上 NDCG 很高的系统，上线后用户可能照样骂。

于是评测必须补上第二只眼睛：**在线评测（online evaluation）**——把系统放到真实流量上，观察用户的行为信号。本篇回答三个问题：点击率怎么用、停留时间怎么看、以及最关键的，**如何用 A/B 测试让「数据」而非「感觉」裁决系统好不好**。<span class="marginnote">在线评测的思路今天也被 RAG 产品沿用：离线用人工标注集快速迭代检索器，上线后用「回答采纳率」「追问率」等用户行为做最终验证。离线与在线是互补的两只眼睛，不是替代关系。</span>

## 1 从离线到在线：两套评测的分工

先厘清两套评测各自的定位，这是理解后续一切的前提：

| | 离线评测 | 在线评测 |
| --- | --- | --- |
| 数据 | 固定测试集 + 人工判定 | 真实用户流量 |
| 成本 | 低，可反复跑 | 高，需足够流量与时间 |
| 可复现性 | 强 | 弱（受时间、用户波动影响） |
| 度量对象 | 系统对相关性的处理质量 | 用户在真实环境中的满意度 |
| 典型指标 | MAP、NDCG、P@k | CTR、停留时间、放弃率、留存 |

工作流程上的分工是：**迭代期用离线评测快速筛方案，上线前用在线 A/B 测试做最终裁决。** 离线指标是「便宜但有偏差的代理」，在线指标是「昂贵但更接近真相的证据」。工程师的日常就是在两者之间来回跳：离线刷到 NDCG 新高 → 上线 A/B 验证 CTR 是否真的涨 → 若涨则合并，若不涨则回头查离线评测哪里失真。

## 2 点击率（CTR）与位置偏差

最基本的在线信号是**点击率（CTR，Click-Through Rate）**：

$$CTR = \frac{\text{点击次数}}{\text{曝光次数}}$$

直觉上，「更多人点」似乎等于「更满意」。但 CTR 有一个臭名昭著的敌人——**位置偏差（position bias）**：**排在前面的结果，即使内容一样，也会被更多人点击**。用户从上往下扫，越靠前越容易被看到，看到才有机会被点。

**辨析｜易错点：把两个不同位置的 CTR 直接比较，是常见的错误。** 第 1 位的 CTR 是 8%，第 5 位是 2%，这**不说明**第 1 位的结果比第 5 位好——可能只是位置在起作用。若 A 系统把一篇很烂的文档放在第 1 位、B 系统把它放在第 5 位，A 的 CTR 反而更高。**位置和相关性在 CTR 里被搅在一起，直接比较前必须先拆开。**

## 3 公式解析：位置偏差的分解

拆开「位置」与「相关性」的标准模型，是**检视假设（examination hypothesis）**：用户点击一篇文档，需要两个条件同时成立——**先看到它**（被检视），**再觉得它值得点**（有相关价值）。写成条件概率：

$$P(\text{click} \mid d, i) = P(\text{examine} \mid i) \cdot P(\text{click} \mid d, \text{examined})$$

四步拆解：

- **第一步，左边是什么。** $P(\text{click} \mid d, i)$ 是文档 $d$ 排在第 $i$ 位时被点击的概率——这是**能观测到**的原始 CTR。
- **第二步，$P(\text{examine} \mid i)$ 是什么。** 是「文档排在第 $i$ 位时被用户看到的概率」，它**只与位置有关**，与文档内容无关，且随 $i$ 增大单调衰减。这是位置偏差的来源：位置越靠后，被看到的概率越低。
- **第三步，$P(\text{click} \mid d, \text{examined})$ 是什么。** 是「用户已经看到 $d$ 后，点击它的概率」——这才真正反映文档的吸引力（相关性、标题质量、摘要说服力）。它是模型里**想知道却看不见**的部分。
- **第四步，拆完怎么用。** 原始 CTR 是「检视概率 × 点击意愿」的乘积，**两个因素纠缠在一起**。想用 CTR 比较不同文档的真实吸引力，要么在实验设计上把位置随机化（让每个文档均匀地出现在各个位置），要么用统计模型把位置因子估计出来并剔除（这正是第七篇《学习排序》里「无偏学习排序」的出发点）。<span class="marginnote">检视假设由 Craswell 等人 2008 年系统总结，是点击模型（click model）家族最基础的成员；更精细的版本还包括「信任偏差」——用户信任搜索引擎，会倾向于点击排在前面的结果，即使与内容无关。</span>

## 4 停留时间、跳过率与放弃率

CTR 回答了「用户点不点」，但「点了之后满不满意」需要更深的信号。业界常用的三个：

**停留时间（dwell time）**：用户点击结果后，在落地页停留的时长。经验法则：**停留 ≥ 30 秒的点击叫「长点击」（long click），视为满意；<30 秒的「短点击」视为不满意**。<span class="marginnote">30 秒阈值来自 Fox 等人 2005 年在微软的经典研究：他们把「长点击」与人工判定的满意度做对照，发现停留时间与满意度显著相关。今天许多搜索引擎仍沿用类似的阈值，但移动端浏览习惯改变了绝对时长，阈值需要重新标定。</span>
**跳过率（skip rate）**：用户跳过某条结果、直接点它下面的结果，或点了之后立刻返回（「跳出」）。高跳过率意味着「这条结果给了错误的期待」——标题吸引人，内容却对不上。
**放弃率（abandonment rate）**：有查询、却没有任何点击的比例。用户输入查询后一条都没点，通常意味着**没有看到任何值得点的结果**，是「系统性不满意」的强信号。

这些信号单独看都有噪声，但组合起来很有信息量：**点击率回答「吸不吸引」，停留时间回答「值不值得」，放弃率回答「整体有没有希望」。** 它们都只是用户满意度的**代理（proxy）**——真正测量用户内心感受，还是需要用户调研；在线行为信号的价值在于**量大、客观、可规模化**。

## 5 线上 A/B 测试：让数据做裁决

有了信号，还需要**实验方法**来比较两个系统，这就是 **A/B 测试（A/B testing）**，也叫分流实验：把真实流量随机分成两组，一组用旧系统（对照组 A），一组用新系统（实验组 B），跑一段时间后比较两组的关键指标差异，用统计显著性判断差异是真实效果还是随机波动。

标准流程五步：

1. **提出假设**：新排序算法会提升点击率（先想清楚要验证什么）。
2. **设计实验**：确定指标（主指标 + 护栏指标）、分流比例（如 50/50）、实验时长。
3. **随机分流**：把用户或查询随机分配到 A/B 组，**保证两组除了实验变量外无系统性差异**。
4. **统计检验**：比较两组指标差异是否显著（常用双比例 z 检验或 t 检验）。
5. **决定**：显著且方向正确 → 发布；否则保留旧系统，回到离线迭代。

随机化在这里至关重要——它把「位置偏差」等混淆因素变成对称噪声：A、B 两组都有同样的位置偏差，抵消后剩下的是「系统差异」的净效果。

**辨析｜易错点：A/B 测试度量的是「相对提升」，不是「绝对质量」。** 实验只告诉你 B 比 A 好或差，不告诉你 B 本身有多好。而且它受**时长与流量**的制约：效果越微弱，需要的样本越大——一个小改动要跑几周才有足够的统计功效。急着看几天的数据就下结论，很容易被随机波动骗过去。

## 6 用代码算一遍

一个最小的 A/B 检验：对照组 5000 次曝光、150 次点击；实验组 5000 次曝光、190 次点击。用**双比例 z 检验**看差异是否显著：

```python
import math

# 对照组（A）：5000 次曝光、150 次点击；实验组（B）：5000 次曝光、190 次点击
n_a, c_a = 5000, 150
n_b, c_b = 5000, 190

p_a = c_a / n_a                          # 对照组 CTR 3.0%
p_b = c_b / n_b                          # 实验组 CTR 3.8%
p_pool = (c_a + c_b) / (n_a + n_b)       # 合并比例
se = math.sqrt(p_pool * (1 - p_pool) * (1 / n_a + 1 / n_b))
z = (p_b - p_a) / se

print(f"对照组 CTR = {p_a:.1%}, 实验组 CTR = {p_b:.1%}")
print(f"z = {z:.2f}")                    # 约 2.21，大于 1.96 → 0.05 水平显著
```

这个例子里实验组点击率从 3.0% 升到 3.8%，$z \approx 2.21$，超过 1.96 的临界值，**在 0.05 水平显著**——可以比较有把握地说提升不是偶然。注意这只是检验「有没有差异」，要判断「值不值得发布」，还要看指标提升是否足以覆盖工程成本、以及护栏指标（如放弃率、服务延迟）有没有恶化。<span class="marginnote">更严谨的工程实践会用「序贯检验」或「贝叶斯 A/B 测试」在实验中途就评估并随时刹车，避免实验做太久伤及用户体验；这些都属于实验设计的高级话题，本博客的第四级《机器学习》与第二级《概率论与数理统计》都有对应的假设检验基础。</span>

## 7 辨析：离线指标与在线指标不是一回事

把两条评测线放回同一个坐标系，最容易被忽略的问题是**离线与在线并不自动一致**：

**离线 NDCG 上升，不等于在线 CTR 上升。** 离线判定是人工对「相关性」的度量，在线点击是真实用户对「标题 + 摘要 + 位置 + 信任」的综合反应。历史上多次出现「离线刷分、线上无感」甚至「离线提升、线上反而下降」的案例。
**连接两者的关键是「离线—在线一致性」验证。** 严谨的团队会定期做相关性研究：把离线指标变化与在线用户行为变化对照，确认你优化的离线指标**确实**是用户在意的在线指标的先导。这一步不做，离线评测就可能沦为「对着错误目标刷分」。
**长短期指标存在张力。** 短期 CTR 提升可能来自标题党（用户点了但不满意，停留时间暴跌）；长期留存与短期点击可能方向相反。所以 A/B 测试通常同时设**主指标**（你优化什么）与**护栏指标**（你不允许恶化什么，如放弃率、延迟、留存）。

一句话收束：**离线评测是「便宜的眼睛」，在线评测是「真实的裁决者」，A/B 测试是把后者变成可重复决策的工程工具。** 三者搭配，才构成一个搜索系统完整的评测闭环。<span class="marginnote">这条「离线迭代 → 在线验证 → 反馈回离线」的闭环，在大模型时代演变成「RAG 检索器离线刷 Recall → 上线看回答采纳率 → 用失败样例造难例回填训练集」。评测从来不是终点，而是改进循环里的一环。</span>

## 8 小结

- **在线评测的定位**：用真实用户行为度量满意度，与离线评测互补；离线便宜可复现、在线真实昂贵。
- **CTR 与位置偏差**：$CTR = \text{点击}/\text{曝光}$，但原始 CTR 混入位置因素，直接跨位置比较会误判。
- **检视假设**：$P(\text{click}|d,i) = P(\text{examine}|i) \cdot P(\text{click}|d,\text{examined})$——位置与吸引力纠缠，需随机化或建模剔除。
- **行为信号**：停留时间（≥30s 长点击 ≈ 满意）、跳过率、放弃率，都是满意度的有偏代理，组合使用更可靠。
- **A/B 测试**：随机分流 → 统计检验 → 决策；度量相对提升而非绝对质量，受流量与时长约束。
- **闭环**：离线刷分必须经过「离线—在线一致性」验证，短长期指标并用，评测是改进循环的一环。
