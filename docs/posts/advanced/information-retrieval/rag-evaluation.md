# RAG 的评测：忠实度、相关性与答案正确性

<div class="epigraph">

## 为什么从"三个维度"开始

传统搜索的评测用 NDCG、MAP——衡量"结果列表的相关性排序"。RAG 的评测对象是"生成的答案"，它不是"列表"，是"一段文本"。**一段答案的质量，需要从多个维度衡量**——答案是否基于证据（忠实度）、证据是否与问题相关（相关性）、答案本身对不对（正确性）。

这三个维度，对应 RAG 因果链的三个环节：**忠实度（faithfulness）**衡量"生成是否忠于证据"，**相关性（relevance）**衡量"证据是否回应问题"，**答案正确性（answer correctness）**衡量"最终答案是否准确"。一个答案可能"忠实但有偏差"（照证据答了但证据不相关）、"相关但不忠实"（证据对但生成时编了）、"正确但来源错"（蒙对的）。**RAG 评测的成熟标志，是分维度衡量，而不是一个总分数掩盖一切**。<span class="marginnote">RAG 评测在学术与工业上都快速发展：<strong>RAGAS 框架（2013 年后兴起）把 RAG 评测拆成忠实度、相关性、答案正确性三个核心指标，成为事实标准</strong>。它的兴起反映了 RAG 评测的根本难点：答案质量是"多维的"（好答案要同时满足多个条件），一个单一分数无法表达"哪里好、哪里差"。分维度评测的意义，不只是"打分"，而是"诊断"——每个维度对应一个可优化的环节（忠实度→生成约束，相关性→检索，正确性→整体）。</span>

## 1 忠实度：答案有没有乱说

**核心概念：忠实度（faithfulness）**：答案中的每个论断，是否都能在检索到的证据（上下文）里找到支持。忠实度高 = 答案"言必有据"；忠实度低 = 答案"编造"（幻觉）。

忠实度的评测方法：

- **抽取式检查**：把答案拆成若干论断（claim），逐个检查"论断能否在上下文中找到"——找不到的论断就是"不忠实的"（幻觉）。
- **生成式判断**：让 LLM 判断"答案是否完全基于提供的文档"——**LLM 作裁判（LLM-as-judge）**。
- **忠实度 = 有证据支持的论断数 ÷ 总论断数**。<span class="marginnote">"论断抽取 + 证据核对"是忠实度评测的经典方法：<strong>把答案拆成一句句的"断言"，对每个断言问"上下文里有没有依据"</strong>——这是 RAG 幻觉检测的核心技术。用 LLM 做"证据核对"是目前的主流（LLM 擅长"这个论断能否被这段文本支持"的判断）。忠实度是 RAG 特有的指标——传统搜索没有"生成"环节，也就没有"编造"问题；忠实度衡量的是"生成器的诚实度"。</span>

**重点：忠实度是 RAG 评测的"第一指标"——它直接衡量"幻觉"这个 RAG 要消灭的头号问题。** 一个忠实度高的 RAG 系统，答案至少"不编造"；忠实度低，再正确的答案也危险（可能是蒙对的）。

## 2 相关性：证据有没有回应问题

**核心概念：相关性（relevance）**：检索到的证据段落，是否真正回应了用户的问题。它衡量的是**检索质量**——证据与问题相关，生成才可能答对。

相关性是"检索侧"的指标，与传统搜索的相关性一脉相承：

- **检索层评测**：recall@K（正确答案在不在 Top-K）、MRR、NDCG——用标准相关性标注评测检索器（第一篇的指标）。
- **生成层评测**：让 LLM 判断"检索到的段落与问题的相关程度"——**检索结果是否"答非所问"**。

**重点：相关性是因果链的"中间环节"——检索的证据相关，答案才可能对；证据不相关，答案必然偏。** 相关性与忠实度要一起看：**忠实度高但相关性低 = "答得很好，但答的不是用户问的"**——这是 RAG 最常见的失败模式之一（检索召回了一堆相关但不回应问题的段落）。<span class="marginnote">"忠实但跑题"是 RAG 评测里一个重要的区分：<strong>一个答案可以完全基于证据（忠实度高），但证据本身没回应问题（相关性低）——比如问"深度学习有哪些应用"，检索召回的是"深度学习的数学基础"，生成器忠实但跑题</strong>。这说明：RAG 优化不能只盯生成（提升忠实度），更要盯检索（提升相关性）。两个指标对应两个优化环节——评测维度就是优化地图。</span>

## 3 答案正确性：最终答案对不对

**核心概念：答案正确性（answer correctness）**：最终答案是否准确、完整地解决了用户的问题。它是"端到端"的结果指标——不管过程如何，答案对就是对。

正确性的评测方法：

- **人工评测**：标注员判断答案与"参考答案"的匹配度（准确、部分准确、错误）。
- **LLM 评测**：让 LLM 对比"模型答案"与"参考答案"，打分（如 0–1）。
- **自动指标**：答案与参考答案的重合度（ROUGE、BLEU）、语义相似度（嵌入余弦）——**但"正确性"的自动指标常与人类判断有差距**（答案可以意思对但用词完全不同）。<span class="marginnote">答案正确性是"最难自动评测"的维度：<strong>"正确"的标准是语义级的——两个用词完全不同的答案可以都正确（"深度学习是一种机器学习方法" vs "深度学习是人工神经网络的训练技术"）</strong>。词面指标（ROUGE/BLEU）会误判，嵌入相似度略好但仍粗糙。LLM 作裁判是目前最接近人类判断的自动方法，但 LLM 判断本身也有偏差。答案正确性的"金标准"仍是人工评测——自动指标用于"筛"（快、粗），人工评测用于"定"（慢、准）。</span>

**辨析｜易错点：三个维度不是"总分制"，是"各自的短板制"。** 一个常见的评测错误是"算一个总分"——总分高掩盖了"某个维度崩了"（如忠实度 0.5，但相关性正确性高，总分还行）。**RAG 评测要看三个维度的分布，任何一个维度低都要单独处理**——忠实度低优化生成约束，相关性低优化检索，正确性低两者都要查。三个维度是"三块短板"，不是"三块可以互补的长板"。

## 4 公式解析：LLM 作裁判的评测

现代 RAG 评测的自动化核心是 **LLM-as-judge**——让 LLM 当裁判打分。以忠实度为例，设答案含 $n$ 个论断 $\{c_1, \dots, c_n\}$，LLM 逐个判断论断是否被上下文 $C$ 支持：

$$\text{Faithfulness} = \frac{1}{n} \sum_{i=1}^{n} \mathbb{1}\big[\text{LLM 判断 } c_i \text{ 被 } C \text{ 支持}\big]$$

三步拆解：

- **第一步，读论断分解**：答案被拆成 $n$ 个可独立核对的论断——**"拆论断"是忠实度评测的前提**。
- **第二步，读证据核对**：每个论断让 LLM 判断"能否在上下文 $C$ 中找到依据"——**LLM 的"核对能力"是裁判质量的关键**。
- **第三步，读聚合**：支持的比例就是忠实度分数——**忠实度 = "有据论断"的占比**。

**核心结论：LLM-as-judge 把"评测"本身变成了"用 LLM 打分"——它的质量取决于"LLM 的核对/判断能力"与"评测 prompt 的设计"。**<span class="marginnote">LLM-as-judge 的可靠性问题：<strong>裁判 LLM 本身可能"偏心"（偏好长答案、偏好自己风格）、可能犯与生成器同样的错误、可能被 prompt 诱导</strong>。工程缓解：用"多裁判投票"（多个 LLM 判断取多数）、"裁判校准"（用人工标注的样例检验裁判的准确性）、"结构化打分"（不只给分数，要求给出理由）。LLM-as-judge 是"便宜但不可全信"的工具——它替代人工做"粗筛"，人工做"终审"。</span>

## 5 RAG 评测的工程实践

RAG 评测在工程上要建立"评测集 + 评测流水线 + 迭代闭环"：

1. **评测集建设**：一批代表性问题 + 参考答案 + 标准文档——**问题覆盖不同类型（事实、概念、指令）、不同难度**。
2. **评测流水线**：对每个问题跑 RAG → 提取答案 → 分维度评测（忠实度/相关性/正确性）→ 汇总指标。
3. **回归与迭代**：改检索/改生成/改切分后，重跑评测集——**看哪个维度变好、哪个变差**（回归测试）。
4. **人工抽样复核**：自动指标 + LLM 裁判的结论，抽样人工复核——**保证评测本身的可靠性**。<span class="marginnote">RAG 评测集的"问题设计"是工程的重头：<strong>一个好的评测集要让"三个维度都能被检验"——既要有"上下文里有答案"的问题（检验检索 + 生成），也要有"上下文里没有答案"的问题（检验系统会不会诚实地拒绝/承认不知道，而不是编）</strong>。后者尤其重要——RAG 对"库外问题"的正确行为应该是"我不知道"（忠实拒绝），而不是幻觉。"诚实拒绝"的能力，是 RAG 评测最容易被忽略、也最能体现系统成熟度的维度。</span>

**重点：RAG 评测不是"跑一次打分"就完，而是"评测集 + 流水线 + 回归闭环"的持续工程——每次改系统，都用同一把尺子量"哪些维度变了"。** 评测维度是优化地图：忠实度低去查生成，相关性低去查检索，正确性低去查整体。

## 6 小结

- **三个维度**：忠实度（答案是否忠于证据）、相关性（证据是否回应问题）、答案正确性（最终答案对不对）。
- **忠实度**：论断级证据核对——衡量"幻觉"，是 RAG 的第一指标；LLM 拆论断 + 核对。
- **相关性**：检索侧指标（recall@K、MRR）+ 生成层判断——"忠实但跑题"是常见失败模式。
- **正确性**：端到端结果指标——人工是金标准，自动指标（ROUGE、嵌入、LLM-judge）用于粗筛。
- **短板制**：三个维度各自看短板，不搞总分制——每个维度对应一个优化环节。
- **工程闭环**：评测集 + 流水线 + 回归迭代 + 人工抽样复核；"诚实拒绝"也是评测维度。

在下一节，我们看 RAG 的高级形态——检索不再是"一次完成"，而是"由智能体规划的多轮行为"，这就是 **Agentic RAG 与多轮检索规划**。
