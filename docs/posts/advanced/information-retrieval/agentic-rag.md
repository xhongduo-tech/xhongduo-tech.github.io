## 为什么从"智能体"开始

朴素 RAG 的检索是"一次性的"：用户问 → 检索一次 → 生成答案。但很多问题"一次检索不够"：

- **复杂问题**："BERT 和 GPT 有什么区别？"——需要检索多类信息（BERT 架构、GPT 架构、对比分析），一次检索往往顾此失彼。
- **多步问题**："这篇论文引用了哪些工作？作者后续还写了什么？"——需要"先查 A，基于 A 再查 B"，检索是**有依赖关系**的多步。
- **信息不足**：第一次检索结果不够 → 需要"换个查询再搜"——检索是**迭代**的。

**Agentic RAG** 把这些场景统一起来：**让 LLM 扮演"智能体（agent）"，自主规划检索动作——决定"要不要检索""检索什么""查完还要不要再查""什么时候够了，可以生成答案"**。检索从"流水线的一步"变成"智能体的一项工具（tool）"。这是 RAG 从"程序化"走向"智能规划"的跃迁。<span class="marginnote">Agentic RAG 是"Agent 技术"与 RAG 的结合：<strong>Agent 的核心是"规划 + 工具使用 + 迭代"——LLM 会决定"下一步做什么"（规划）、"调用什么工具"（检索、计算、写代码）、"什么时候结束"</strong>。检索在这里被"工具化"：成为一个可以被 LLM 反复调用的 action。这个思想你会在《AI 智能体》专题里完整展开——这里聚焦"检索作为工具"在 RAG 里的形态。</span>

## 1 朴素 RAG 的局限：为什么需要 Agentic

先把朴素 RAG 的局限列清楚，它们就是 Agentic RAG 的动机：

**一次检索，信息可能不全**：复杂问题需要多类信息，一次检索只召回一部分——**答案不完整**。
**一次检索，没有反思**：检索结果不够好时，不会"换个查询再试"——**答案质量止步于第一次检索**。
**一次检索，不考虑依赖**：多步问题的第二步依赖第一步的结果，一次检索无法表达这种依赖——**复杂问题答不好**。

**重点：朴素 RAG 是"检索一次就生成"，Agentic RAG 是"生成器决定检索几次、怎么检索"——检索从"固定步骤"变成"智能决策"。** 这不是"检索变强了"，而是"检索的使用方式变聪明了"——**同样的检索器，在智能体的规划下能解决朴素 RAG 解决不了的问题**。<span class="marginnote">这个"使用方式的升级"值得强调：<strong>Agentic RAG 通常不换检索器（还是 BM25/嵌入），它换的是"检索的编排"</strong>——从"查一次"到"按需查多次、查完反思、不够再查"。检索器的能力没变，但"会用检索器的大脑"变了。这就像搜索引擎本身没变，但用户的搜索策略从"搜一次"变成"先搜、再精搜、再查关联"——Agentic RAG 是把"聪明的搜索策略"内建到系统里。</span>

## 2 Agentic RAG 的核心能力：规划与工具

Agentic RAG 的智能体具备几项核心能力：

**检索决策（decide whether to retrieve）**：判断"这个问题需不需要检索"——常识问题直接答，知识问题才检索（**self-RAG 的思想**）。
**查询构造（formulate queries）**：决定"这次检索用什么查询"——可以是原问题、子问题、多路查询。
**迭代检索（iterate）**：检索结果不够 → 分析缺什么 → 构造新查询再检索——**多轮检索循环**。
**答案合成（synthesize）**：信息够了 → 停止检索 → 基于所有收集的证据生成答案。

**重点：Agentic RAG 的本质是"把检索的决策权交给 LLM"——检索变成智能体可调用的工具，智能体决定"何时用、怎么用、用几次"。**<span class="marginnote">实现"把检索给 LLM 用"的技术，是"工具调用（tool calling / function calling）"：<strong>LLM 在生成过程中可以输出"调用检索工具"的结构化指令（查询参数），系统执行检索，把结果返回给 LLM，LLM 继续生成</strong>。这个"LLM ↔ 工具"的循环，让检索从"流水线步骤"变成"智能体的能力"。你会在《AI 智能体》里看到工具调用的完整机制——这里只需理解"检索是智能体最常用的工具"。</span>

## 3 多轮检索规划的模式

Agentic RAG 的多轮检索规划，有几个常见模式：

**迭代-反思模式（iterate-and-reflect）**：检索 → 生成中间答案 → 判断"够不够" → 不够再检索 → 再生成——**"生成-反思-再检索"的循环**。
**子问题分解（sub-question decomposition）**：把复杂问题拆成多个子问题，逐个检索——**"一个问题拆成多路检索"**。
**链式检索（chained retrieval）**：第二次检索依赖第一次的结果——**"查 A → 用 A 查 B"的依赖链**。
**路由检索（routing）**：根据问题类型路由到不同检索源（文档库、知识图谱、网页）——**"按需选路"**。<span class="marginnote">这些模式可以组合：<strong>一个 Agentic RAG 系统可能先"路由"（判断用哪个知识源），再"子问题分解"（把复杂问题拆开），再对每个子问题"迭代检索"（不够就换查询重查），最后合成答案</strong>。模式的组合由"任务复杂度"决定——简单问题走一步检索就够（Agentic RAG 也要"能简单就简单"，不能什么问题都大动干戈），复杂问题才启动完整规划。这个"按需启动规划"的设计，与查询性能预测（第九篇）"按难度分配资源"一脉相承。</span>

**辨析｜易错点：Agentic RAG 不等于"多检索几次"。** 多检索几次（机械地多路召回）不是 Agentic——**Agentic 的关键是"有规划的检索"**：检索动作由"分析缺什么"驱动，而非"多路碰运气"。**多轮检索是"工具"，规划是"智能"**——没有规划的多次检索，只是把朴素 RAG 放大成"多次朴素 RAG"，不会产生"拆解、反思、依赖"这些真正的智能行为。

## 4 公式解析：规划的成本与收益

Agentic RAG 的规划能力不是免费的——它用"更多 LLM 调用"换"更好的答案质量"。设朴素 RAG 的答案质量 $Q_0$、成本 $C_0$（一次检索 + 一次生成），Agentic RAG 经过 $k$ 轮规划-检索，答案质量 $Q_k$、成本 $C_k$：

$$Q_k \ge Q_0 \quad \text{但} \quad C_k \approx k \times C_0$$

三步拆解：

- **第一步，读质量收益**：$Q_k \ge Q_0$——多轮规划让复杂问题的答案更完整（检索覆盖多类信息、补齐遗漏）。
- **第二步，读成本代价**：$C_k \approx k \times C_0$——每轮规划都花一次 LLM 推理 + 检索——**成本随轮数线性涨**。
- **第三步，看权衡**：质量收益与成本代价的平衡点，取决于"问题复杂度"——简单问题 $k=1$ 就够（Agentic 不启动），复杂问题 $k=3\text{–}5$ 值得。

**核心结论：Agentic RAG 是"用成本换质量"的智能——它只在"复杂问题值得多轮"时启动规划，简单问题保持朴素。** "按需智能"是它的工程精髓——不是"所有问题都大动干戈"，而是"系统知道什么时候该动干戈"。<span class="marginnote">Agentic RAG 的成本控制是工程重点：<strong>每轮检索 - 生成循环都消耗 LLM token 与延迟，规划失控时（智能体反复检索不收敛）成本爆炸</strong>。工程措施：最大轮数上限（如 5 轮强制停止）、置信度阈值（生成答案足够自信就停）、成本感知的路由（贵模型只用于复杂问题）。"智能"与"成本"的平衡，是 Agentic 系统能否上线的决定因素。</span>

## 5 Agentic RAG 的评测与风险

Agentic RAG 的评测比朴素 RAG 更难：

**评测多轮行为**：不仅评最终答案，还要评"规划的合理性"——检索次数是否过多、是否漏检、是否及时收敛（**评测"过程"而非只评"结果"**）。
**评测工具使用**：智能体是否"该检索时检索了、不该检索时没检索"（self-RAG 的"检索必要性"判断）。
**风险放大**：规划的灵活性也是风险的来源——**智能体可能"固执地沿错误方向检索"（检索发散）、可能"过早停止"（证据不足就下结论）**。多轮规划把"单轮的随机错误"放大成"多轮的系统性错误"。<span class="marginnote">Agentic 系统的"发散"是特有的失败模式：<strong>智能体第一次检索没找到答案，构造新查询再查，还没找到，再构造……沿着错误方向越走越远</strong>——这是"多轮放大错误"的典型。工程缓解：检索结果质量监控（连续几轮无新信息就提示智能体"换个策略"）、路线回退（允许智能体"放弃当前路线重新来"）、最大轮数硬上限。Agentic RAG 的评测，要特别测"发散场景"——看系统能否及时止损。</span>

**重点：Agentic RAG 的评测从"答案质量"扩展到"过程质量"——规划合理性、工具使用、收敛性都要评。** 一个答案正确但检索了 10 次的系统，与答案同样正确但检索了 2 次的系统，后者明显更好（成本、延迟、稳定性）。

## 6 数值算例：一次多轮规划的成本推演

把"成本随轮数线性涨"算成数字。设一次 LLM 调用成本 $0.5$ 分、一次检索成本 $0.1$ 分，对比朴素 RAG 与 Agentic RAG 对同一个复杂问题的开销：

| 环节 | 朴素 RAG | Agentic RAG（3 轮） |
| --- | --- | --- |
| LLM 生成 | 1 次 = 0.5 分 | 每轮 1 次 = 1.5 分 |
| 检索调用 | 1 次 = 0.1 分 | 每轮 1 次 = 0.3 分 |
| 合计 | 0.6 分 | 1.8 分 |
| 答案质量 | 一次检索，可能不全 | 多轮覆盖，完整 |

三步读这张表：

- **看成本差距**：3 轮规划的成本是朴素 RAG 的 3 倍——**"智能"是有标价的**。
- **看质量的提升**：多轮覆盖了复杂问题的多类信息，答案从"可能不全"到"完整"——**质量收益明显**。
- **看"按需启动"的价值**：若系统只在"复杂问题"上启动 Agentic 规划（简单问题走朴素），**总成本 = 简单问题的便宜 + 复杂问题的值得**——这是"按需智能"的经济学。

这个推演也解释了为什么 Agentic RAG 需要"成本预算"机制：**最大轮数上限、置信度阈值、按查询价值路由**——否则智能体可能在简单问题上也大动干戈，成本失控。

**辨析｜易错点：Agentic RAG 的"多轮检索"与对话式搜索的"多轮"不是一回事。** 对话式搜索的"多轮"是**用户与系统的外部交互**（用户追问）；Agentic RAG 的"多轮"是**系统内部的检索规划**（智能体自己决定再查）。**一个是"外部对话"，一个是"内部规划"**——两者可以结合（对话里系统内部也做多步检索），但概念上必须分清。

## 8 小结

- **Agentic RAG**：LLM 作为智能体规划检索——决定"要不要检索、检索什么、够不够、何时生成"。
- **朴素 RAG 的局限**：一次检索信息不全、无反思、无法处理依赖——Agentic 补这三点。
- **核心能力**：检索决策、查询构造、迭代检索、答案合成——"检索成为智能体的工具"。
- **规划模式**：迭代-反思、子问题分解、链式检索、路由检索——组合使用，按需启动。
- **成本-质量权衡**：$Q_k \ge Q_0$ 但 $C_k \approx k C_0$——"按需智能"，复杂问题才启动规划。
- **评测扩展**：评测"过程质量"（规划、工具使用、收敛性）；防发散是工程重点。

到此，**第十三篇《搜索与 RAG》全部完成**。从下一节起，我们看检索交互的最新形态——从"单轮查询"到"多轮对话"，搜索变得像"聊天"，这就是**第十四篇《对话式搜索》**，从对话式搜索概述讲起。
