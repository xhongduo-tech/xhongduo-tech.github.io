## 为什么要把整条曲线浓缩成一个数

上一篇的 F 值解决了「单查询、两个维度」的合成，插值查准率解决了「多查询、横轴对齐」。但插值查准率有个工程上的尴尬：它要先选定一组召回水平网格，不同的网格会给出略有不同的数字。评测界需要一个**不依赖网格、定义干净、且对排序质量敏感**的单数指标。答案就是本篇的主角——**平均查准率（Average Precision，AP）**与它的跨查询平均 **MAP（Mean Average Precision）**。

AP 的思路很朴素：上一篇那张 P@k、R@k 的表格，**在每条曲线的相关文档位置上取 Precision，再求平均**。它把「整条 P-R 曲线的形状」浓缩成一个数，同时天然地对「相关文档排得靠前」给予奖励——这正是排序系统最想要的性质。MAP 则是把 AP 对查询集求平均，是 TREC 三十年来报告 ad hoc 检索的**头号单数指标**，也是今天 RAG 评测里评估检索器最常用的指标之一。<span class="marginnote">AP 的概念由科学家们在上世纪 60—70 年代逐步定型，是 Salton 的 SMART 系统与 TREC 早期评测共同塑造的。它和「P-R 曲线下面积」有干净的几何对应，因此比 11 点插值更「几何」、更不易被人为网格摆布。</span>

## 1 Average Precision：只在相关文档的位置上记账

定义很直接。设查询 $q$ 的相关文档集合为 $R_q$，系统返回一个排序列表，$rel_k \in \{0,1\}$ 表示第 $k$ 位的文档是否相关。**AP 是所有「相关文档被检出的位置」处 Precision 的平均**：

$$AP(q) = \frac{1}{|R_q|} \sum_{k=1}^{n} P@k \cdot rel_k$$

展开读：把每个 $rel_k = 1$ 的位置的 $P@k$ 加起来，再除以相关文档总数 $|R_q|$。

沿用上一篇的例子：相关文档位于第 1、3、5、6 位，$|R_q| = 4$。

| 截断点 k | 该位相关? | P@k | 计入 AP？ |
| --- | --- | --- | --- |
| 1 | 是 | 1.000 | 是 |
| 2 | 否 | 0.500 | 否 |
| 3 | 是 | 0.667 | 是 |
| 4 | 否 | 0.500 | 否 |
| 5 | 是 | 0.600 | 是 |
| 6 | 是 | 0.667 | 是 |
| 7–10 | 否 | ≤0.571 | 否 |

$$AP = \frac{1.000 + 0.667 + 0.600 + 0.667}{4} = \frac{2.934}{4} \approx 0.733$$

注意一个关键特性：**不相关文档不直接扣分，但会把后面的相关文档「往后推」，从而压低它们在相关位置上的 $P@k$**。第 4 位的不相关文档没有进求和，但它让第 5 位的相关文档从「第 4 个截断点」变成「第 5 个截断点」，$P@5$ 因此只有 0.6。<span class="marginnote">这就是 AP 与「把相关文档总数做分母的 Recall」的微妙差别：AP 通过「相关文档之间的不相关文档数」来惩罚排序错乱——<strong>位置就是惩罚的载体</strong>。</span>

## 2 公式解析：AP 的求和结构

把 $AP(q) = \frac{1}{|R_q|} \sum_{k} P@k \cdot rel_k$ 拆成四步：

- **第一步，$rel_k$ 是开关。** 它保证只有「相关文档被检出的那 $|R_q|$ 个位置」进入求和。若一篇相关文档根本不在返回列表里，它对应的项就不存在——这等价于给它的 Precision 记 0。
- **第二步，$P@k$ 是那一刻的纯度。** 第 $k$ 位是相关文档时，$P@k = \frac{tp@k}{k}$ 衡量「看前 $k$ 篇时，相关的占多少」。分子里的 $tp@k$ 包含当前这篇相关文档，所以**每个相关位置都会给 AP 贡献一个正的、介于 0 与 1 之间的数**。
- **第三步，除以 $|R_q|$ 是归一化。** 除以相关文档总数，让 AP 落在 $[0, 1]$：相关文档全部排在最前时 $AP=1$，全部没检到时 $AP=0$。这个归一化也让不同大小的 $R_q$ 之间的 AP 可以比较。
- **第四步，几何对应。** AP 正是**非插值 P-R 曲线下的近似面积**（对「相关文档之间的矩形」求和）。这一点解释了 AP 的直觉：它把「整条曲线的平均高度」用一个数表达出来，曲线越靠近右上角，面积越大，AP 越高。

**辨析｜易错点：AP 的分子是「相关位置处 P@k 之和」，不是「把 P 对所有位置平均」。** 把不相关位置（P@2 = 0.5）也算进去，会得到更小、也更「稀释」的数字——那是另一种指标，不是 AP。AP 的哲学是：**只有「找到了相关文档」的时刻才记账**，其余时刻系统无论表现如何都不参与平均。

## 3 Mean Average Precision：对查询取平均

AP 是单查询的；评测一个系统要对**一组查询**取平均，得到 **MAP（Mean Average Precision）**：

$$MAP = \frac{1}{|Q|} \sum_{q \in Q} AP(q)$$

再补一个查询让平均有意义。设查询 $q_2$ 有 3 篇相关文档，位于第 2、4、8 位：

- $P@2 = 1/2 = 0.500$，$P@4 = 2/4 = 0.500$，$P@8 = 3/8 = 0.375$
- $AP(q_2) = (0.500 + 0.500 + 0.375)/3 \approx 0.458$

于是两个查询的平均：$MAP = (0.733 + 0.458)/2 \approx 0.596$。

两个容易被忽略的约定，务必记牢：

- **「Mean」是对查询平均，不是对文档平均。** 每个查询在 MAP 里占一样的权重，**与它包含多少相关文档无关**。一个只有 1 篇相关文档的查询，和一个有 50 篇相关文档的查询，权重相同。<span class="marginnote">这种「查询等权」是有意为之：评测的对象是「系统对任意信息需求的平均满足度」，而不是「对任意文档的处理正确率」。若想按相关文档数加权，那是另一种指标设计，TREC 不用它。</span>
- **没有相关文档的查询怎么算？** 分母会出问题。TREC 的惯例是**在池化阶段保证每个主题都有相关文档**（若实在没有，该查询通常被剔除出平均），否则 MAP 会被「无答案查询」拉向不确定的 0。

MAP 为什么是「头号指标」？因为它**同时惩罚三件事**：相关文档没检出来（对应项记 0）、相关文档排得太靠后（对应位置的 P@k 小）、以及不相关文档插在相关文档前面（推后相关位置、压低 P@k）。一个数，覆盖了召回、排序、噪音三个维度。

## 4 R-Precision：一个恰好让 P 与 R 相等的工作点

R-Precision 是 AP 的「单点快照」版本：**在第 $|R_q|$ 个位置截断，读此时的 Precision**。在上一篇我们已经见过它的定义，这里补上它的一个漂亮性质。

**在截断点 $k = |R_q|$ 处，Precision 与 Recall 恰好相等。** 因为此时检出的总数等于相关文档总数：

$$P = \frac{tp}{|R_q|}, \qquad R = \frac{tp}{|R_q|} \qquad \Rightarrow \qquad P = R$$

于是这个点上的 F1 也等于同一个数：$F_1 = \frac{2P \cdot P}{P + P} = P$。换句话说，**R-Precision 就是「在 $|R_q|$ 处截断时的 F1」**——它把 P、R、F 三个概念在同一个工作点上统一起来。<span class="marginnote">这个恒等式是上一篇《F 值》与本篇之间的隐秘桥梁：R-Precision 看似只是 P 的一个特殊取值，实则是「F1 沿排序滑动到相关文档数位置时」的数值。</span>

用例子验证：$q_1$ 的 $|R_q| = 4$，第 4 位截断时 $tp = 2$，所以 R-Precision = 2/4 = 0.5；$q_2$ 的 $|R_q| = 3$，前 3 位里相关 1 篇，R-Precision = 1/3 ≈ 0.333。相比之下 AP 分别是 0.733 与 0.458——**AP 用整条曲线、R-Precision 用一个点**，两者常同场报告，AP 对排序更敏感，R-Precision 更直观、更容易解释给非专家。

**辨析｜易错点：R-Precision 的截断位置随查询而变。** 它不像 P@10 那样「固定看前 10 篇」，而是「看前 $|R_q|$ 篇」——相关文档多的查询，截断位置就靠后。因此 R-Precision 不是一个「固定前缀」指标，而是一个「自适应前缀」指标；它比 P@k 更能反映系统在「恰好覆盖全部相关文档」时的质量。

## 5 辨析：MAP 的边界与误用

MAP 虽好，边界要清楚，否则会误用：

- **对分级相关性无感。** MAP 建立在二元判定（相关 / 不相关）之上，「高度相关」与「勉强相关」在 AP 里地位相同。面对 0—3 分级判定，需要下一篇的 NDCG。<span class="marginnote">在大模型时代的 RAG 评测里，检索到的文档往往被 LLM 标注为「可用 / 部分可用 / 不可用」三级——此时 MAP 会丢失「部分可用」的层次，评测者常改用 NDCG 或面向生成的指标。</span>
- **查询等权可能掩盖「少数难点」。** 如果 90% 的查询都很容易，MAP 会被这 90% 拉高，掩盖系统在难查询上的崩溃。严谨的报告要同时看 MAP 与「分桶 MAP」（如按查询难度分组）。
- **无相关文档查询的处理不一致。** 不同评测集处理方式不同（剔除 / 记 0 / 记特殊值），跨数据集比较 MAP 前要确认口径一致。
- **MAP 不能跨异构查询集直接比较。** 它依赖 $R_q$ 的判定质量；用不同池化深度得到的 MAP 没有可比性。

这些边界不是 MAP 的缺陷，而是「用一个数总结一条曲线」的固有代价——正如博克斯所说，模型都是错的，但有些有用。

## 6 用代码算一遍

AP 与 MAP 的实现几乎是直译公式：

```python
def average_precision(relevant_ranks, total):
    """relevant_ranks: 相关文档在结果中的位置（1 起计）"""
    hits = 0
    sum_p = 0.0
    for k in range(1, total + 1):
        if k in relevant_ranks:
            hits += 1
            sum_p += hits / k            # 此刻的 P@k
    return sum_p / len(relevant_ranks)

def map_score(queries, total):
    """queries: 每个查询的相关文档位置列表"""
    return sum(average_precision(q, total) for q in queries) / len(queries)

q1 = {1, 3, 5, 6}
q2 = {2, 4, 8}
print(average_precision(q1, 10))     # 0.7333
print(average_precision(q2, 10))     # 0.4583
print(map_score([q1, q2], 10))       # 0.5958

# R-Precision：在第 |R_q| 位截断
for q in (q1, q2):
    k = len(q)
    hits = sum(1 for r in q if r <= k)
    print(f"R-Precision = {hits}/{k} = {hits / k:.3f}")
# q1 → 2/4 = 0.500；q2 → 1/3 = 0.333
```

注意 `hits / k` 这句：在遍历到相关位置 $k$ 时，`hits` 恰好是前 $k$ 篇里相关的数量，所以它就是 $P@k$。整段代码是对公式的最小翻译，没有额外魔法。

## 7 小结

- **AP**：$AP(q) = \frac{1}{|R_q|} \sum_k P@k \cdot rel_k$——只在相关文档被检出的位置上对 Precision 求平均，等价于非插值 P-R 曲线下的面积。
- **位置即惩罚**：不相关文档不直接扣分，但会把相关文档往后推、压低相关位置的 $P@k$。
- **MAP**：对查询集平均，$MAP = \frac{1}{|Q|}\sum_q AP(q)$；每个查询等权；无相关文档的查询通常被剔除。
- **R-Precision**：在第 $|R_q|$ 位截断的 Precision；此处 P 与 R 相等，故它也等于该点的 F1。
- **边界**：MAP 是二元指标，对分级相关性无感；跨数据集比较要注意无相关查询的处理口径。
