## 为什么从"重叠度"开始

上一篇末尾留下一个工程难题：**拼写矫正要对词典里每一个词都算一遍编辑距离**——词典 100 万词项、每个词 8 个字符，一次查询的代价是 $10^6 \times 8 \times 8 = 6400$ 万次字符比较，这在毫秒级的查询路径上不可接受。

但上一节我们已经在通配符里埋好了线索：**k-gram 索引**能让"含某子串"变成查表。拼写矫正复用同一套索引，思路非常直接：**两个词越相似，共享的 k-gram 就越多**。`recieve` 与 `receive` 共享大量 bigram，与 `quantum` 几乎不共享——于是可以用"共享 k-gram 数"做一把粗筛，把 100 万个候选压到几十个，再对几十个跑精确的编辑距离。**这就是基于 k-gram 重叠度的候选生成（candidate generation）**。<span class="marginnote">拼写矫正的完整流水线：<strong>k-gram 粗筛（廉价、宽）→ 编辑距离精排（昂贵、准）</strong>。这篇讲前半段，上一篇讲后半段。两篇合起来才是工业级拼写矫正的全貌。</span>

## 1 共享 k-gram 与相似性的关系

先建立一个量化直觉：两个字符串的**共享 k-gram 数**，是它们相似度的一个廉价代理。

以 $k=2$ 为例，看三组词：

| 词对 | 各自 bigram 集合 | 共享数 |
| --- | --- | --- |
| `receive` 与 `recieve` | `re,ec,ce,ei,iv,ve` 与 `re,ec,ci,ie,ev,ve` | 3 |
| `receive` 与 `reconvene` | `re,ec,ce,ei,iv,ve` 与 `re,ec,co,on,nv,ve,en,ne` | 3 |
| `receive` 与 `quantum` | 明显不相干 | 0 |

第一对（形近）与第二对（有关联但不同词）共享数差不多——**k-gram 共享数只能区分"明显不像"与"可能像"，不能区分"有点像"与"非常像"**。这正是它适合做**粗筛**的原因：它擅长把大量"肯定不像"的候选扔掉，但不擅长在幸存者之间排序。<span class="marginnote">为什么？因为 k-gram 是<strong>局部特征</strong>——它只看到"字符片段是否出现"，看不到片段在词里的<strong>顺序与位置</strong>。`receive` 与 `evicer` 可能共享不少 bigram 却毫不相关。局部特征适合召回，全局特征（编辑距离）适合精排——这是检索里"局部 vs 全局"的经典分工。</span>

## 2 用 Jaccard 系数量化重叠

"共享 k-gram 数"有个问题：它没有归一化。`receive` 与 `reconvene` 都长、共享 3 个，和一个 4 字母词共享 3 个，含义完全不同。需要一个**与长度无关**的度量。

**核心概念：Jaccard 系数（Jaccard coefficient）**：两个集合的交集大小与并集大小之比，取值 $[0,1]$，越接近 1 越相似。

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

对 k-gram 集合：`receive` 的 bigram 集合 $A$ 与 `recieve` 的 $B$，$|A \cap B| = 3$，$|A \cup B| = |A| + |B| - |A \cap B| = 6 + 6 - 3 = 9$，故 $J = 3/9 = 1/3$。<span class="marginnote">Jaccard 系数在推荐系统里也扮演核心角色——"协同过滤"衡量两个用户/物品相似度时常用它。你会在《推荐系统》里与它重逢：<strong>一个度量横跨检索与推荐，因为它们面对的是同一个问题——集合之间的相似性</strong>。</span>

**辨析｜易错点：Jaccard 系数不是"重叠度"的唯一选择。** 还有 Dice 系数 $2|A \cap B|/(|A|+|B|)$、余弦相似度等。选择的标准是"对你要区分的分布，哪个区分度好"。IIR 中拼写矫正常用 Jaccard 或其变体，因为它在"长度差异大"的词对上也表现稳健——**长词与短词之间的相似度，会被并集大小自然地惩罚**。

## 3 候选生成的工程流程

把 k-gram 候选生成在系统里铺开，流程是：

1. **预构建 k-gram 索引**：词典里每个词项切成 k-gram，建"k-gram → 词项列表"的倒排索引（与通配符共用同一份索引，一次构建两处受益）。
2. **查询切分**：把用户输入 $q$ 切成 k-gram 集合 $G(q)$。
3. **取回候选**：对每个 $g \in G(q)$，取出 $g$ 的倒排表，**合并（并集）**得到"至少共享一个 k-gram 的词项集合"。
4. **计算重叠**：对每个候选词 $t$，计算 $|G(q) \cap G(t)|$（或 Jaccard）。
5. **阈值筛选**：保留重叠度超过阈值的候选，交给下一级编辑距离精排。

注意第 3 步用的是**并集**而非交集——拼写矫正的召回要求"只要共享一个 k-gram 就可能相关"，不能像通配符那样求交收紧。<span class="marginnote">一个词的 bigram 集合大小约等于词长，查询词切出约 $L$ 个 k-gram，每个 k-gram 的倒排表平均覆盖词典的很小比例——合并后候选集通常只剩几百个。<strong>这就是"九成九先被筛掉"的具体含义</strong>：从 100 万到几百，只花了几次查表与一次并集。</span>

## 4 公式解析：重叠度阈值的取舍

阈值设多高？设查询词 $q$ 的 k-gram 集合为 $G(q)$，候选词 $t$ 的为 $G(t)$，定义**重叠率**：

$$\rho(q, t) = \frac{|G(q) \cap G(t)|}{|G(q)|}$$

三步拆解：

- **第一步，读分子**：共享 k-gram 的绝对数量，越大越可能相关。
- **第二步，看分母 $|G(q)|$**：以**查询词**的 k-gram 数做基准（而非两词的并集）。这使 $\rho$ 不受候选词长度影响——候选词再长，只要与查询词共享的比例够高就保留。
- **第三步，设阈值**：$\rho$ 低于阈值（如 0.6）的候选直接丢弃。阈值太高会漏掉真正的纠正（召回低），太低会放进大量噪声（精排负担重）。

**核心权衡：阈值是召回率与精排成本的旋钮。** 这与你学过的《查准率与查全率》直接挂钩——$\rho$ 阈值收紧，召回率降、候选质量升；放松则反之。**工程上常用"先宽后严"：粗筛阈值放低保证不漏，精排阶段再用更严的标准裁决。**<span class="marginnote">另一个细节：k 的选择影响全局。$k=2$（bigram）对 1–2 个字符的错误最敏感（一个替换字符只影响相邻 bigram）；$k=3$（trigram）更严格、误召回更少，但对短词错误不敏感。<strong>k 大则精、k 小则全——对英文词典，bigram 是拼写矫正的常用默认。</strong></span>

## 5 从候选到纠正：与编辑距离的接力

k-gram 候选生成的价值，只有和精排接力才显现。把完整流水线走一遍：

1. 用户输入 `recieve`，词典里没有。
2. k-gram 粗筛：`recieve` 的 bigram `re, ec, ci, ie, ev, ve` 各自的倒排表并集 → 候选几百个词。
3. Jaccard / 重叠率筛选：留下与 `recieve` 重叠率 > 0.5 的几十个。
4. **编辑距离精排**：对几十个候选计算加权编辑距离，`receive`（距离 1）胜出。
5. 输出建议：`你是不是想找 receive？`

**重点：粗筛保证"好候选不漏"，精排保证"坏候选不选"。** 任何一级的失败都让整体失败——粗筛漏掉 `receive`，精排再好也找不到；粗筛放进来几百个，精排就慢到不可用。<span class="marginnote">这条两级流水线是信息检索的<strong>元模式</strong>。你会一遍又一遍见到它：通配符（k-gram + 正则）、拼写矫正（k-gram + 编辑距离）、向量检索（ANN + 重排）、RAG（检索 + 精排）……<strong>理解"廉价召回 + 昂贵精排"的分层，就是理解搜索系统性能的全部秘密</strong>。</span>

## 6 小结

- **k-gram 共享数是相似度的廉价代理**：局部特征，适合粗筛，不适合精排。
- **Jaccard 系数** $J = |A \cap B|/|A \cup B|$ 归一化重叠度，长度无关。
- **候选生成流程**：查询切 k-gram → 倒排表并集召回 → 重叠率筛选 → 交编辑距离精排。
- **重叠率阈值** $\rho = |G(q) \cap G(t)|/|G(q)|$ 是召回-精排成本的旋钮；先宽后严是常用策略。
- **两级流水线**是检索系统的元模式，贯穿通配符、拼写矫正乃至 RAG。
