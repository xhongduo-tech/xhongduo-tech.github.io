# 检索系统的基本任务：相关性与用户需求

<div class="epigraph">
<p>信息检索，是这样一种过程或方法：一位潜在的信息用户，得以把他对信息的需求，转化为一份实际引用清单——指向存储中那些对他有用的文档。</p>

## 为什么从「任务」开始

上一篇我们回答了「什么是信息检索」，并把它定义成一句话：**从大规模非结构化集合中，找出满足信息需求的对象**。但「满足信息需求」这句话里藏着一个没有打开的黑箱——**系统到底凭什么判断一篇文档「满足」了需求？** 这一篇要把黑箱拆开：检索系统的基本任务到底是什么，「相关性」这个模糊的词能不能被定义得足够精确，以至于可以拿来设计算法、进行评测。

这一篇在整个专题里的位置很特殊。它几乎不涉及具体算法，却是后面所有算法的**验收标准**：布尔检索、TF-IDF、BM25、稠密检索，排的都是「相关度」；第三、四篇的查准率 / 查全率、NDCG，量的也是「相关度」。**如果「相关性」说不清，后面的一切都是空中楼阁。** 所以我们要在算法之前，先把「目标函数」定下来。<span class="marginnote">这也正是与第四级《大模型原理》第十四篇「检索增强生成（RAG）」对接的接口：RAG 里检索器召回什么、召回多少，最终都要用一个「相关性」的定义来评判。</span>

## 1 检索系统的基本任务：返回一个有序列表

把一个 IR 系统看成一个函数：输入是一个**查询（query）**，输出是一份**有序的文档列表**。

$$\text{检索系统}(q) \;\longrightarrow\; \langle d_1, d_2, d_3, \ldots, d_k \rangle$$

这个函数式的表述里，最关键的是那个「**有序**」。Manning 在第 1 章强调：检索系统的输出**不是**一个无差别的集合，而是一个**按相关度从高到低排列**的列表——用户只会看最前面那几篇。<span class="marginnote">「排序」之所以是任务的核心，是因为检索系统的输出永远有「预算」：用户的时间、屏幕的空间、RAG 里的上下文窗口都只装得下前面几条。排序排错一条，代价远大于召回漏掉一条。</span>

由此，检索系统的基本任务可以精炼成一句话：**对给定的查询，返回一份排序列表，使得排在最前面的文档尽可能多地是「用户真正想要」的文档。** 这句话里有三个待解的子问题：

- **「用户真正想要」如何表达？**——信息需求与查询的关系（第 2 节）。
- **「真正想要」如何定义？**——相关性（第 3 节）。
- **系统如何知道「真正想要」？**——它只能估计，这就是所有排序模型的共同起点（第 5 节的公式解析）。

## 2 三个层次：信息需求、查询与主题

用户心里那个模糊的念头，与敲进搜索框的那几个词，不是一回事。Manning 把这件事拆成了三个层次，是理解整个评测体系的前提：

- **信息需求（information need）**：用户心里真正的那个问题，主观、模糊、常常说不出口。
- **查询（query）**：用户真正输入系统的那串词，是对信息需求的一次粗糙编码。
- **主题（topic）**：评测中为了「让所有人审同一道题」而写出的规范陈述——它是信息需求的**外部化、可共享版本**。

举 Manning 第 1 章的经典例子：

| 层次 | 内容 | 特点 |
| --- | --- | --- |
| 信息需求 | 「我想知道喝红酒是不是比喝白酒更能降低心脏病风险」 | 主观、口语、藏在心里 |
| 查询 | `red wine heart attack` | 客观、简短、输入给系统 |
| 主题（TREC 风格） | 「找出讨论红葡萄酒与白葡萄酒对冠心病风险的相对影响的文档」 | 写成一段话，供评估员照此判断 |

### 一个直觉：查询是对需求的「压缩」

把「信息需求 → 查询」这条编码过程想成**压缩**：需求是几百字都能说清的念头，查询却是被压成几个词。压缩必然丢信息——丢掉的恰是语境、程度、优先级这些「说不清的部分」。**检索系统要做的，就是在信息已经丢失的情况下尽量还原。** 这也解释了为什么评测必须用「主题」而不是「查询」来定义相关：主题保留了需求的大部分语境，让评估员有一个尽量接近「真实需求」的参照系，判定才能可复现。

**辨析｜易错点：查询不是信息需求。** 同一个信息需求可以催生无数个不同的查询；同一个查询在不同人眼里可以对应完全不同的信息需求。因此，**检索系统永远是在为一个「近似」服务**——它看到的是查询，要服务的却是那个它看不见的需求。这个差距，是相关度评测中「系统打分」与「用户判定」总是存在裂缝的根源。<span class="marginnote">对话式搜索（本专题第十四篇）的一部分努力，就是让系统在返回结果之前先多问几句、把查询逼近需求；而大模型时代的查询改写、意图澄清，干的也是同一件事——缩小「查询」与「信息需求」之间的鸿沟。</span>

## 3 相关性：检索的北极星

三层次区分完毕，问题的焦点就落在「相关」两个字上。

**相关性（relevance）**：在给定的信息需求下，一篇文档**满足该需求的程度**。这是 Manning 全书反复强调的唯一「北极星」——排序算法排的是它，评测指标量的是它。

但相关性这个定义里埋伏着三个让初学者措手不及的属性：

- **它是关系属性，不是文档属性**。同一篇文档，对查询「红葡萄酒健康」相关，对查询「红酒配餐礼仪」就不相关。相关性从来不是文档「本身」的性质，而是「文档—信息需求」这个**二元关系**的性质。
- **它是主观的**。两个评估员对同一篇文档是否相关，常常给出不同的判定——这正是第三篇评测要面对的「判定者间一致性」问题。
- **它是分级的，不是二元的**。Manning 区分了**二元相关（binary relevance）**——相关 / 不相关两种取值；与**分级相关（graded relevance）**——如 0 到 3 四个等级，从「完全不相关」到「高度相关」。分级相关更贴近真实：一篇论文、一段综述、一个广告页，相关程度显然不同。

### 相关性的三个层次：主题、主观与效用

「主观」到底主观在哪里？信息检索理论家萨拉切维奇（Tefko Saracevic）把相关性拆成由浅入深的三个层次，这个划分至今仍是理解「为什么系统打分与用户感受总有缝隙」的最好框架：

- **主题相关（topical relevance）**：文档谈论的话题与查询话题是否一致。最易判定，评估员照着主题文字就能打标，TREC 的大部分判定就停在这一层。
- **主观相关（pertinence）**：文档是否切中**这位用户本人**的信息需求。同一篇「红酒与心脏健康」综述，对正在写论文的营养师高度相关，对只想找「今晚配餐酒单」的人就无关——话题相同，需求不同。
- **效用相关（utility relevance）**：文档最终是否**解决了用户的问题**。这是最高也最难判定的层次：一篇内容完全切题的文章，如果来得太晚、太难读，其「效用」也可能趋近于零。

**系统打分（TF-IDF、BM25、向量相似度）能自动捕捉的，主要是「主题相关」；「主观相关」与「效用相关」几乎必然要落到用户身上。** 这三层不是互相排斥，而是嵌套的同心圆——越往外层，越依赖对用户的了解，也越难在离线评测中复现。<span class="marginnote">这个「三层同心圆」也解释了为什么评测永远只能是近似：评估员能可靠判定「主题相关」，却很难替真实用户判定「效用相关」。因此所有离线指标（查准率、NDCG）本质量的都是第一层；要捕捉后两层，必须走上线的用户实验——这正是第一篇末《用户满意度评测》的课题。</span>

**辨析｜易错点：系统的「相关度分数」≠「相关性」。** 系统返回的 0.87、0.42 这类分数，是**可计算的估计值**；真实的相关性只能由用户在信息需求下判定，系统永远只能**猜**。把这两者混为一谈，是初学者最容易犯的错误——后面第四篇讲评测时，我们正是用「人工判定的相关性」做尺子，去量「系统估计的相关度」准不准。

## 4 一个必要的支点：评测需要「可判定的相关性」

如果相关性如此主观，评测怎么进行？答案是一个务实的折衷：**在受控环境下，把相关性「冻结」成一组人工判定。** 这就是第三篇《检索评测方法》的全部起点——我们把「文档是否相关」交给经过培训的评估员，让他们对「固定的文档集 × 固定的主题集」逐条打标，形成**相关性判定集合（relevance judgments）**。

这个「冻结」动作有一个重要的哲学后果，值得现在就说破：**评测中的相关性，是某个特定时刻、由特定一群人、针对特定主题做出的判定——它是相关性的一个「代理」，而不是真相本身。** 但它给了我们唯一可重复的尺子。有了这把尺子，前面那个函数式的输出 $\langle d_1, d_2, \ldots, d_k \rangle$ 才第一次可以被打分：排在前面的相关文档越多，系统越好。<span class="marginnote">这把「可判定的尺子」，在机器学习里有个更熟悉的名字——<strong>标注数据</strong>。第四级《机器学习》里训练与测试要划分训练集 / 测试集，评测文档集之于 IR，正如测试集之于监督学习：都是把「真实」降维成「可计算的代理」，再拿代理去度量系统。</span>

举一个具体的「冻结」产物。设主题是「红葡萄酒与白葡萄酒对冠心病风险的相对影响」，评估员对三篇文档给出分级判定：

| 文档 | 内容摘要 | 二元判定 | 分级判定 |
| --- | --- | --- | --- |
| Doc A | 直接对比两类酒与冠心病风险的随机对照试验综述 | 相关 | 3（高度相关） |
| Doc B | 研究葡萄酒中抗氧化剂对血管的生化作用 | 相关 | 2（相关） |
| Doc C | 一篇「如何为晚宴挑选红酒」的品酒指南 | 不相关 | 0（不相关） |

注意 Doc B 是「相关但不完全切题」，Doc C 是「话题擦边但需求无关」——分级判定把这些细微差别保存了下来，而二元判定会把 Doc A 与 Doc B 压成同一个「1」。**判定的粒度有多细，直接决定后面的排序指标（如 NDCG）能区分多细。**

## 5 公式解析：把「任务」翻译成一个概率

前面说了这么多，都是为了给「基本任务」一个可计算的数学形式。Manning 全书对「相关性」最简洁的数学化，是把「相关」看成一个**随机事件**，并用条件概率来描述：

$$P(R = 1 \mid q, d)$$

逐项拆解这条式子，四步：

- **第一步，什么是 $R$。** 定义 $R$ 为一个指示随机变量：$R = 1$ 表示「文档 $d$ 对查询 $q$ 是相关的」，$R = 0$ 表示不相关。注意 $R$ 是**随机的**——因为相关性由用户主观判定，在系统看来它带着不确定性。
- **第二步，为什么是条件概率。** $P(R = 1 \mid q, d)$ 读作「在给定查询 $q$ 与文档 $d$ 的条件下，$d$ 相关的概率」。这个形式精确地表达了第 3 节的结论：相关性是**文档—查询二元关系**的性质，不是文档自己的属性——所以两个条件变量 $q$ 和 $d$ 缺一不可。
- **第三步，理想排序就是按它降序。** 如果系统知道真实的 $P(R=1 \mid q, d)$，那么最优策略就是把文档按这个概率**从大到小**排列：概率越大的文档越应该排在前面。这就是「基本任务 = 排序」的概率论版本。
- **第四步，系统不知道真实概率，只能估计。** 现实中系统永远无法观测到用户心里的需求，于是用一个**可计算的评分函数** $\hat{s}(q, d)$ 去逼近 $P(R=1 \mid q, d)$。于是我们看到一条贯穿全专题的线索：**TF-IDF 是估计器，BM25 是估计器，稠密向量相似度也是估计器**——它们各不相同，但都在逼近同一个 $P(R=1 \mid q, d)$，只是逼近的手段与精度不同。<span class="marginnote">这条「所有排序模型都是概率估计器」的视角，是第五篇《概率检索与 BM25》的伏笔：那里会把 $P(R=1 \mid q, d)$ 用贝叶斯公式进一步展开，得到一个明确可计算的排序公式。今天先把「目标函数」立住。</span>

这一小节的结论可以浓缩成一句给整篇定调的话：**检索系统的基本任务，是估计 $P(R=1 \mid q, d)$ 并按它排序；而「评测」，就是用人工判定的相关性去检验这个估计准不准。**

## 6 小结

- **基本任务**：输入查询，输出**按相关度排序**的文档列表——排序而非匹配，是任务的核心。
- **三个层次**：信息需求（主观、模糊）、查询（输入的字面）、主题（评测中的规范陈述）；系统服务的是需求，看到的却是查询。
- **相关性**：文档—信息需求二元关系的性质，主观、分级、因人而异；系统的「相关度分数」只是对它的**估计**。
- **评测的前提**：把相关性「冻结」成一组人工判定，用可重复的尺子去量系统——它是相关性的代理，不是真相。
- **数学形式**：基本任务等价于估计 $P(R=1 \mid q, d)$ 并按它降序排列；TF-IDF、BM25、稠密检索都是这个概率的估计器。

在下一节，我们将从抽象的「概率」回到最具体的操作：用莎士比亚的四部剧做一次真实的手工索引，看看**倒排索引的一个例子：莎士比亚文集检索**——把「查询—文档」的匹配真正跑起来。
