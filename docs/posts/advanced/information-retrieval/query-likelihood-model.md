# 查询似然模型（Query Likelihood Model）

## 为什么从"翻转视角"开始

第五篇的概率检索（BIM/BM25）走的是"**区分文档**"路线：估计每篇文档"相关与否"的概率，用似然比排序。它把文档看成要被分类的对象。**语言模型检索（language model approach to IR）** 换了一个更"生成式"的视角：

> 每篇文档 $d$ 都是一个语言模型 $M_d$——它定义了"从这篇文档里会生成出什么词"的概率分布。检索变成：**哪篇文档的模型最可能"生成"出这个查询？**

直觉是：一篇关于"深度学习"的文档，其语言模型里"深度学习"这个词的概率很高；用户查询"深度学习"时，这个文档的模型生成该查询的似然就大——**文档与查询的匹配，从"词面重合"变成了"生成概率"**。这个视角翻转（**query likelihood**）是 1998 年由 Ponte 与 Croft 引入的，它开启了信息检索的"语言模型时代"。<span class="marginnote">语言模型检索的根基是统计语言模型——"一个词序列出现的概率"，你在《自然语言处理》里学过的 n-gram 模型正是它的实例。<strong>检索借用了语言模型，但方向反过来：NLP 用语言模型"生成文本"，检索用语言模型"判断生成某查询的可能性"</strong>。同一个工具，两个用途。</span>

## 1 核心公式：查询似然

**核心概念：查询似然模型（query likelihood model）**：对每篇文档 $d$，以文档的语言模型 $M_d$ 计算**生成查询 $q$ 的概率** $P(q \mid M_d)$，按此概率降序排序文档。

$$P(q \mid M_d) = \prod_{t \in q} P(t \mid M_d)$$

（假设查询词独立，乘积形式。）这里 $P(t \mid M_d)$ 是词 $t$ 在文档 $d$ 的语言模型中的概率——直觉上，**文档里出现越多的词，在这个文档模型里的概率越高**。所以查询似然高 ⇔ 查询词在文档里都很"常见" ⇔ 文档与查询高度相关。<span class="marginnote">"文档的语言模型"这个词需要拆解：它不是"文档里词的实际频率分布"，而是"一个从该文档抽象出的生成模型"。<strong>文档只是这个模型的"训练样本"</strong>——我们希望模型从文档学出"这篇文档大概率在讲什么"，而不是机械地复述文档本身。这个抽象层是语言模型检索区别于 TF-IDF 的地方：它显式地处理"未出现的词也可能有概率"。</span>

## 2 从"词频"到"概率"：为什么要平滑

$P(t \mid M_d)$ 最自然的估计是**最大似然估计（MLE）**：词在文档里出现的比例。

$$\hat{P}_{\text{MLE}}(t \mid M_d) = \frac{\text{tf}_{t,d}}{|d|}$$

但直接用 MLE 有一个灾难性问题：**查询里若有一个词没在这篇文档出现，$P(t \mid M_d) = 0$，整篇文档的似然直接归零**。一篇讲"深度学习的应用"的文档，若恰好没写"挑战"这个词，查询"深度学习 的 挑战"就把它淘汰——尽管它高度相关。**零概率把"文档里恰好没写"与"文档完全不相关"混为一谈**，这是不能接受的。<span class="marginnote">这就是检索语言模型里<strong>平滑（smoothing）</strong>登场的时刻：给"没出现的词"一个非零的、较小的概率，而不是 0。平滑的哲学是：<strong>"文档没写这个词"不等于"文档不可能写这个词"</strong>——模型的概率分布应该比文档的字面频率更"平滑"、更"泛化"。下一篇两篇文章专门讲平滑，这里先记住它的必要性。</span>

**重点：平滑不是锦上添花，是查询似然模型的生死线。** 没有平滑，任何含"文档未出现词"的查询都会让分数归零，检索直接失效。**所有查询似然模型的差异，本质上就是"平滑方式"的差异。**

## 3 一元语言模型与文档模型

查询似然模型使用的语言模型通常是一元模型（unigram）——**只考虑单个词的概率，不考虑词与词的顺序**。这听起来又回到了词袋假设，但有一个关键差别：

词袋模型（TF-IDF）里，词只有"在/不在"（或加权频率）。
一元语言模型里，词有**概率**，且未出现的词有**平滑后的非零概率**。

$P(t \mid M_d)$ 扮演的角色，与 BM25 里的权重类似，但它有更干净的**概率解释**：它直接告诉你"从这篇文档出发，遇到这个词的可能性"。

**辨析｜易错点：查询似然 ≠ 文档似然，方向别搞反。** 查询似然是 $P(\text{查询} \mid \text{文档模型})$——"这篇文档生成这句查询的概率"。它不是"这篇文档出现的概率"，也不是"查询条件下文档的概率"。**方向是"文档 → 查询"，不是"查询 → 文档"**——这是名字里"似然"的精确含义（似然总是"在参数下看到数据"的概率）。<span class="marginnote">用贝叶斯看：$P(d \mid q) \propto P(q \mid d) P(d)$。查询似然模型算了 $P(q \mid d)$，把先验 $P(d)$ 当作均匀（或与文档长度/权威性结合）。<strong>所以查询似然是"贝叶斯后验的似然部分"</strong>——它丢弃了文档先验，专注"文档模型生成查询"的强度。</span>

## 4 公式解析：为什么乘积会惩罚长查询

查询似然对多词查询的乘积形式，有一个容易被忽略的效应。设查询有两个词 $t_1, t_2$，文档 $d$ 的模型给出：

$$P(q \mid M_d) = P(t_1 \mid M_d) \times P(t_2 \mid M_d)$$

三步拆解：

- **第一步，看乘积 vs 求和**：乘积意味着"所有查询词都要有概率"——只要有一个词在文档模型里概率很低，整篇文档分数就被拖低。**这与布尔 AND 的语义神似，但连续化了。**
- **第二步，看对数化**：工程上取对数，$\log P(q \mid M_d) = \sum_t \log P(t \mid M_d)$——乘积变求和，数值更稳，也方便与 BM25 等模型对比。
- **第三步，看长度偏置**：乘积形式天然**惩罚长查询**——查询词越多，每个词的"概率门槛"叠乘，分数越小。这是查询似然模型的一个已知弱点：**长查询分数系统性偏低**，需要长度归一化或改用 KL 散度框架（第六篇后续）来缓解。

**核心直觉：查询似然把"相关性"翻译成"文档模型对查询词的生成概率乘积"**——乘积的每个因子都必须是"够格"的概率，一个零概率就毁掉全部。<span class="marginnote">对比 BM25：BM25 是"查询词的权重之和"（求和），查询似然是"查询词的概率之积"（乘积）。<strong>求和宽容、乘积严格</strong>——这解释了为什么查询似然对"文档漏掉某个查询词"更敏感，也因此更需要平滑。两种模型的这个差异，在《KL 散度检索模型》一篇会得到统一。</span>

## 5 查询似然模型的现代回响

查询似然模型看似"古典"，但它的思想是现代检索最深的几条根之一：

**生成式视角的回潮**：今天大模型检索（RAG）里，"生成器生成回答"的架构与查询似然的"文档模型生成查询"一脉相承——只是"生成"从统计语言模型换成了神经网络。
**对语义检索的启示**：查询似然证明"生成概率"是比"词面重合"更优雅的相关性定义；现代稠密检索把"生成概率"换成了"嵌入距离"，但"定义每个文档一个表示、比较表示"的框架未变。<span class="marginnote">更具体地：<strong>查询似然模型里"每个文档一个语言模型"，与双塔检索里"每个文档一个嵌入向量"，在结构上是同构的</strong>——都是"文档先变成自己的表示，查询再来匹配"。理解了查询似然，你就在理解现代稠密检索的路上迈出了第一步。</span>

**重点：查询似然模型的价值不在"被大规模使用"（它确实不如 BM25 普及），而在"提供了相关性概率化的清晰范式"。** 它的平滑、KL 散度变体、与反馈结合（RM3），构成了语言模型检索的完整工具箱——这套工具箱至今仍是检索研究与 RAG 设计的理论底色。

## 6 数值算例：一次"零概率"事故的现场

把"平滑是生死线"演算给你看。设文集只有两篇文档，查询 $q = $ "深度学习 挑战"，$d_1$ 的 MLE 词分布是 $\{$深度学习: 0.1, 挑战: 0.05, 应用: 0.85$\}$，$d_2$ 是 $\{$深度学习: 0.2, 应用: 0.8$\}$（没写过"挑战"）。

| 文档 | $P($深度学习$)$ | $P($挑战$)$ | MLE 似然 $P(q \mid M_d)$ | 平滑后似然（给未现词 $\epsilon$） |
| --- | --- | --- | --- | --- |
| $d_1$ | 0.1 | 0.05 | $0.1 \times 0.05 = 0.005$ | $0.1 \times 0.05 = 0.005$（词都在） |
| $d_2$ | 0.2 | **0** | $0.2 \times 0 = \mathbf{0}$ | $0.2 \times \epsilon$（非零，但很低） |

三步读表：

- **看 $d_1$ 的分数**：两个查询词都出现，似然 $0.005$——正常。
- **看 $d_2$ 的事故**："挑战"在 $d_2$ 里没出现，MLE 给 $0$，整篇文档的似然直接归零。**哪怕 $d_2$ 的"深度学习"概率更高、内容更相关，一个词未现就前功尽弃**——这是乘积模型的致命伤。
- **看平滑的救场**：给未现词一个很小的 $\epsilon$（如 $10^{-6}$ 量级），$d_2$ 从"完全淘汰"变成"分数极低但仍可参与排序"。**平滑保证"每篇文档都有机会"，再按质量排座次。**

这个例子也顺带解释了为什么要取对数：$\log P(q \mid M_d) = \log 0.005 \approx -5.3$，$\log 0 = -\infty$——**对数把"归零事故"放大成"负无穷"，肉眼可见地异常**，工程上便于调试。

这里再点一层细节：平滑的 $\epsilon$ 并非随便给。**常见做法是把文档概率与一个"全集词分布"（collection distribution）做插值**——文档里没出现的词，参考"整个文集中这个词出现的比例"。这样"挑战"在 $d_2$ 中的平滑概率，等于它在全集中的比例，语义是"虽然这篇文档没写，但它确实是常用的词"。**平滑的本质，是让文档模型"向全集靠拢一点"**——下一篇的 Jelinek-Mercer 与 Dirichlet 平滑，都是"靠拢程度"的不同算法。

**辨析｜易错点：MLE 词频 ≠ 文档语言模型。** $\text{tf}_{t,d}/|d|$ 只是模型的"训练样本统计"，不是模型本身。**模型是"文档可能生成哪些词的概率分布"，比字面频率更平滑、更泛化**——它回答了"这篇文档大概率在讲什么"，而不是"这篇文档写了什么"。这个区别正是语言模型检索与 TF-IDF 的分水岭。

读到这儿，你手里已经有了语言模型检索的第一块积木。**下一篇我们把"平滑"展开成两种具体算法（Jelinek-Mercer 与 Dirichlet），并比较它们对查询长度、文档长度的不同反应**——那才是平滑"怎么选"的完整答案。

## 8 小结

- **视角翻转**：不问"文档讲什么"，而问"文档的模型生成查询的概率"——$P(q \mid M_d)$。
- **核心公式**：$P(q \mid M_d) = \prod_{t \in q} P(t \mid M_d)$，查询词独立假设下的乘积。
- **平滑是生死线**：MLE 会让"文档未出现的词"概率归零，整篇分数归零——必须平滑。
- **方向别反**：查询似然是"文档 → 查询"的似然，不是"查询 → 文档"的条件概率。
- **现代回响**：生成式视角、每文档一表示的结构，是稠密检索与 RAG 的理论先声。

在下一节，我们把"生死线"挖深——平滑为什么必要、有哪些选择、怎么选，这就是**数据平滑：Jelinek-Mercer 平滑**。
