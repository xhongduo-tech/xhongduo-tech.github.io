## 为什么从"倒排"开始

上一篇把 ANN 分成了三大流派，其中"空间划分类"与倒排索引（第二篇）有一个令人亲切的同构：**倒排索引按"词项"分桶，IVF 按"向量簇"分桶**。这篇把它讲透——**IVF（Inverted File，倒排文件）** 是 FAISS（Facebook 的向量检索库）里最经典的索引，它用 K-means 聚类把向量空间切成若干"街区"，查询时只在最近的几个街区里搜。

但光有 IVF 还不够解决全部问题：**一个簇里可能有几十万篇文档，簇内还是线性扫描**；而且原始向量（768 维 float）占用内存巨大，一千万篇要 30GB。于是 IVF 通常与**乘积量化（Product Quantization，PQ）** 搭档——**PQ 把向量压成几百字节甚至几十字节，既省内存又加速簇内比较**。IVF 管"找街区"，PQ 管"街区里怎么比"，两者合起来才是完整的"聚类倒排 + 向量压缩"方案。<span class="marginnote">IVF 的思想与词项倒排索引同源，因此借用了它的名字——Inverted File 里的每个"簇"就像一个"词项"，簇内文档列表就像"倒排表"。<strong>PQ 的发明者是 Hervé Jégou 等（2011 年），FAISS 的向量压缩方案也基于它</strong>。理解 IVF+PQ，你就理解了 FAISS 的 `IndexIVFPQ` 到底在做什么——这是几乎所有工业向量检索系统的底层组件。</span>

## 1 IVF 的构建与查询

**核心概念：IVF（Inverted File）**：用 K-means 把 $N$ 个文档向量聚成 $K$ 个簇，建一个"簇 ID → 簇内文档列表"的倒排结构。

**构建（离线）**：
1. 对全部文档向量跑 K-means，得到 $K$ 个簇中心 $\{c_1, \dots, c_K\}$。
2. 每个文档向量分配到最近的簇。
3. 建倒排表：簇 ID → 该簇的文档 ID 列表。

**查询（在线）**：
1. 计算查询向量到 $K$ 个簇中心的距离。
2. 取距离最近的 $nprobe$ 个簇（$nprobe$ 是"查几个簇"的旋钮）。
3. 在这几个簇的文档里做线性扫描，找最近的 K 个。<span class="marginnote">$nprobe$ 是 IVF 的核心旋钮：<strong>$nprobe=1$ 只搜最近的那个簇（最快，但可能漏掉真近邻所在的簇）；$nprobe$ 增大，覆盖的簇变多，召回变高，但查询变慢</strong>。$nprobe$ 从 1 到 20 的召回率提升通常很陡，之后趋于平缓——工程上常在召回率-延迟曲线上找拐点。</span>

**重点：IVF 的查询代价 = $K$ 次"查簇" + $nprobe$ 个簇的"簇内扫描"。** 它把全量比较变成了"先粗筛（簇级）再细比（簇内）"——**两级结构，与倒排索引的"词典定位 + 倒排表遍历"完全同构**。

## 2 簇内扫描的代价：为什么需要 PQ

IVF 剩下一个问题：**簇内扫描依然是原始向量的线性比较**。若一个簇有 $10^5$ 篇文档，$nprobe=1$ 时还是要做 $10^5$ 次 768 维点积——**这可比 K-means 簇数更致命**。而且，原始向量占用内存大：768 维 float32 = 3KB/篇，$10^7$ 篇 = 30GB。

**乘积量化（PQ）** 一次解决两个问题：

**核心概念：乘积量化（Product Quantization，PQ）**：把高维向量切成若干子空间，对每个子空间独立量化（聚类），用"子空间的簇 ID"组合来近似表示整个向量。

具体做法：
1. 把 768 维向量切成 $m$ 个子向量（如 $m=96$，每段 8 维）。
2. 对每个子空间做 K-means，得到 $k_s$ 个"子中心"（如 $k_s=256$）。
3. 每个子向量用"它最近的子中心 ID"表示（1 字节）。

这样每个 768 维向量被压缩成 $m$ 个字节（如 96 字节），**比原始 3KB 省 30 倍**。<span class="marginnote">为什么叫"乘积"量化？<strong>因为完整的量化码本是各个子空间码本的笛卡尔积：每个子空间 $k_s$ 个码字，$m$ 个子空间的组合就是 $k_s^m$ 个"伪中心"</strong>——虽然我们从不显式存储这 $k_s^m$ 个组合（它们太多），但比较距离时只需查 $m$ 张查找表，这是 PQ 高效的关键。数学上"乘积"指的就是笛卡尔积。</span>

## 3 公式解析：PQ 的距离近似

PQ 的核心是"用压缩后的近似向量算距离"。设原向量 $x$ 切成 $m$ 个子向量 $x = [x^{(1)}, \dots, x^{(m)}]$，PQ 编码后每个子向量用子中心 $q(x^{(i)})$ 近似：

$$\hat{x} = [q(x^{(1)}), q(x^{(2)}), \dots, q(x^{(m)})]$$

查询向量 $y$ 与压缩向量 $\hat{x}$ 的距离近似为：

$$d(y, \hat{x}) \approx \sqrt{\sum_{i=1}^{m} d(y^{(i)}, q(x^{(i)}))^2}$$

三步拆解：

- **第一步，读分解**：把 768 维距离拆成 $m$ 个 8 维子距离的平方和——**距离计算被分解到子空间**。
- **第二步，看查找表**：对查询向量 $y$，每个子空间可以**预计算一张查找表**（$y^{(i)}$ 到该子空间全部 $k_s$ 个码字的距离）——比较每篇文档只需 $m$ 次查表 + 求和，**把点积变成查表**。
- **第三步，看误差来源**：$q(x^{(i)})$ 是 $x^{(i)}$ 的近似（量化损失），距离是近似值——**PQ 的精度损失来自"子空间聚类粒度不够细"**，$k_s$ 越大、$m$ 越大，近似越准，但编码越长。

**核心结论：PQ 用"子空间查表"替代"原始点积"，把内存与比较代价降低一个量级，代价是距离近似。**<span class="marginnote">PQ 的一个精妙延伸是<strong>不对称距离计算（ADC，Asymmetric Distance Computation）</strong>：查询向量保留原始精度，只把文档向量压缩——"查询不压缩、文档压缩"让距离更准（查询侧无损）。工业实现几乎都用 ADC 而非对称版本。<strong>这个"不对称"的细节说明了 PQ 的核心思路：压缩的粒度选在哪里、哪个角色能承受损失，是可以精心设计的</strong>。</span>

## 4 IVF + PQ 的完整流程

把两者组装成生产级索引：

**构建**：
1. 跑 K-means 得到 $K$ 个簇中心（IVF 的"词项"）。
2. 对每个簇内的向量，用 PQ 压缩存储（簇内是压缩码而非原始向量）。

**查询**：
1. 查询向量与 $K$ 个簇中心比较，取最近的 $nprobe$ 个簇。
2. 在候选簇内，用 PQ 查表法计算与压缩向量的距离。
3. 取距离最小的 K 个，返回（可选地再对候选做一次"精排"——用原始向量重新算距离）。

**工程收益**：一千万篇 768 维向量，原始 30GB；IVF+PQ（96 字节/篇）压到约 1GB，能进内存；查询从"全量 3KB×N"变成"簇级粗筛 + 簇内查表"。<span class="marginnote">一个重要的工程实践：<strong>IVF 的簇数 $K$ 与簇内 PQ 的召回是耦合的</strong>。$K$ 太大（簇太碎），K-means 失真、簇边界附近漏召回；$K$ 太小（簇太大），簇内扫描慢。FAISS 的经验是 $K \approx \sqrt{N}$ 量级——一千万文档约几千个簇。调 $K$ 与调 $nprobe$ 是 IVF 工程的两个主杠杆。</span>

**辨析｜易错点：PQ 压缩的不是"文档向量"，是"索引里的向量"。** 原始向量（如全精度 768 维）可以在索引之外保留一份（用于精排与更新），PQ 只负责"索引内的大规模近似检索"。**把"索引的压缩"与"存储的原始向量"混为一谈，会误以为 PQ 损失了全部信息——实际它只损失"索引阶段"的信息，精排阶段可以无损。**

## 5 IVF 与 HNSW 的对照（预告）

IVF 是"分区派"的代表，下一篇的 HNSW 是"图派"的代表，两者的取舍在选型时最关键：

| 维度 | IVF + PQ | HNSW |
| --- | --- | --- |
| 核心机制 | K-means 分区 + 子空间量化 | 近邻图 + 贪心搜索 |
| 内存 | 低（PQ 压缩） | 中（图结构 + 原向量） |
| 精度 | 中（受 PQ 量化损失影响） | 高（通常优于 IVF） |
| 构建速度 | 快 | 较慢 |
| 增删向量 | 容易（倒排表增删） | 难（图结构更新复杂） |

**重点：IVF 的优势在"内存友好 + 易增量更新"，HNSW 的优势在"高精度 + 低查询延迟"。** 工程选型看场景：**内存紧张、数据频繁更新 → IVF；精度优先、更新不频繁 → HNSW**。<span class="marginnote">工业上还有一种混合形态：<strong>IVF 做粗分区，簇内用 HNSW 而非线性扫描</strong>（FAISS 的 IndexIVFPQ + HNSW 组合）——两级都"聪明"，兼顾内存与速度。理解各流派的长短，你就能像搭积木一样组合出适合自己场景的索引。</span>

## 6 小结

- **IVF**：K-means 聚类 + 倒排表——"先找街区再敲门"，$nprobe$ 是查询宽度旋钮。
- **簇内扫描的代价**：簇内仍线性比较原始向量，内存 3KB/篇——这是 PQ 的用武之地。
- **PQ**：把高维向量切子空间、独立量化、字节编码——内存省 30 倍，距离靠查表。
- **距离近似**：子空间距离平方和 ≈ 原距离；ADC（查询不压缩）让近似更准。
- **工程组合**：IVF 管分区 + PQ 管压缩 + 原始向量留作精排；与 HNSW 的选择看内存、更新、精度需求。

在下一节，我们看 ANN 的"图派"——把向量建成一张可导航的近邻图，查询沿边走，这就是 **HNSW：分层可导航小世界图**。
