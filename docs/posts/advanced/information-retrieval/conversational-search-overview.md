## 为什么从"对话"开始

整个系列走完，我们看到的搜索形态都是"单轮"的：用户输入一个查询，系统返回一个结果（或一段答案）。但真实的人类信息获取不是这样的——**我们问一个问题，对方答了，我们追问、澄清、换角度、再深入**。搜索的终极形态，是像"和懂行的人聊天"一样获取信息。

**对话式搜索（conversational search）** 就是把这个"对话"引入检索：**用户与系统多轮交互，每一轮的查询都建立在前几轮的上下文之上**。`那红色的呢？`（省略主语，依赖上一轮）、`再说细一点`（指令，指向上一轮的结果）、`换个更便宜的吧`（修改，基于上文的偏好）——对话式搜索要理解这些"上下文依赖"的表达，并让检索结果在对话中持续演进。这是本系列的收官主题，也是检索形态最前沿的演变——从"查"到"聊"。<span class="marginnote">对话式搜索在学术上是 2018 年后兴起的主题（TREC Conversational Assistance Track 等），但它的形态在大模型时代爆发：<strong>今天的 AI 搜索产品（Perplexity、Bing Chat、各类"AI 搜索"）本质都是对话式搜索——用户与系统多轮对话，系统检索 + 生成</strong>。对话式搜索把本系列所有技术（检索、排序、查询理解、上下文、RAG、生成）整合成一个"交互式"的系统——它是信息检索全部积累的最终舞台。</span>

## 1 从单轮到多轮：本质变化是什么

对话式搜索相对单轮搜索，本质变化不是"可以发多条查询"，而是**"每一轮查询都依赖上下文"**：

- **单轮搜索**：每个查询是独立的——`iphone 15` 和 `红色` 是两个孤立查询，系统不认为它们相关。
- **对话搜索**：`iphone 15` 之后问 `红色`——系统必须知道"红色"指的是"红色的 iPhone 15"（指代消解）。

**重点：对话式搜索的核心是"上下文依赖的查询理解"——每一轮查询都要结合前几轮（甚至用户的反馈）来理解。** 这是它与"多轮搜索"（每轮独立）的本质区别：**多轮是"连续的单轮"，对话是"连贯的一体"**。<span class="marginnote">对话式搜索的"上下文依赖"具体包括：<strong>指代（"它""那个"）、省略（"价格呢"少了主语）、修正（"不对，我说的是另一种"）、追问（"再详细点"指向上一轮结果）、否定（"不是这个"）</strong>。这些在语言学里叫"话语现象"（discourse phenomena），在检索里必须被"翻译"成可检索的独立查询——这正是《对话上下文建模与查询重写》一篇的任务。理解"上下文依赖"是理解对话式搜索的钥匙。</span>

## 2 对话式搜索的架构

对话式搜索的系统架构，是"对话管理 + 检索 + 生成"的整合：

1. **对话状态（dialogue state）**：维护对话的历史（查询、结果、用户反馈）——**"记住"这轮对话进行到哪了**。
2. **查询理解（contextual understanding）**：结合对话状态，把当前轮次的表达重写为"可检索的独立查询"（上下文理解，第十一篇 + 本篇后续）。
3. **检索（retrieval）**：重写后的查询走完整检索流水线（召回、重排）。
4. **生成/回答（response）**：基于检索结果 + 对话上下文，生成这一轮的回答（RAG 的生成层）。
5. **反馈循环（feedback loop）**：用户对回答的反馈（点击、追问、修正）更新对话状态，进入下一轮。

**重点：对话式搜索 = 对话状态管理 + 上下文查询理解 + 检索 + 生成——它在检索系统之上加了一层"对话大脑"。** 检索与生成是现成的（前十三篇），新增的是"怎么管理对话、怎么理解上下文查询"。<span class="marginnote">这个架构里"对话状态"是核心新增组件：<strong>它记录"这轮对话的来龙去脉"——之前问过什么、系统答过什么、用户确认了什么、正在找什么</strong>。对话状态是查询理解的输入（知道上下文才能重写查询）、也是回答生成的输入（知道来龙去脉才能答得连贯）。没有对话状态，就没有"对话"——只有"一串不连贯的单轮搜索"。</span>

## 3 对话式搜索与相关概念的边界

对话式搜索常与几个概念混淆，先厘清：

- **对话式搜索 vs 多轮 RAG**：多轮 RAG（Agentic RAG）的"多轮"是"检索的多步规划"（系统内部行为）；对话式搜索的"多轮"是"用户与系统的交互"（外部对话）。**对话式搜索是"外部的多轮"，Agentic RAG 是"内部的多轮"——两者可以结合（对话中系统内部也做多步检索）**。
- **对话式搜索 vs 聊天机器人（chatbot）**：聊天机器人是"通用对话"（闲聊、写作）；对话式搜索是"信息获取"（检索事实、回答问题）——**对话式搜索是"以检索为中心的对话"**。
- **对话式搜索 vs 传统搜索 + 追问**：传统搜索不支持"记住上下文"；对话式搜索的每轮都"记住并利用"前几轮——**"记忆"是对话式搜索的门槛**。<span class="marginnote">一个精确的区分：<strong>对话式搜索 = 检索 + 对话管理 + 上下文理解 + 生成</strong>，它是"搜索"的对话形态，不是"聊天"的搜索点缀。判断标准：系统是否"用对话上下文改进检索结果"——只是"能聊天但每轮都独立搜索"不是对话式搜索，"记住上一轮并据此改进本轮检索"才是。这个"检索被对话上下文改进"的性质，是对话式搜索的灵魂。</span>

## 4 公式解析：对话式检索的形式化

把对话式检索形式化。设对话历史 $H_t = \{(\text{查询}_1, \text{回答}_1), \dots, (\text{查询}_{t-1}, \text{回答}_{t-1})\}$，第 $t$ 轮的查询为 $q_t$。对话式检索的目标是结合历史理解 $q_t$：

$$\text{score}(d \mid q_t, H_t) = f\Big(\text{rel}(d, \psi(q_t, H_t)), \, \text{ctx}(d, H_t)\Big)$$

其中 $\psi(q_t, H_t)$ 是"结合对话历史的重写查询"，$\text{ctx}(d, H_t)$ 是文档与对话主题的匹配度。

三步拆解：

- **第一步，读历史重写**：$\psi(q_t, H_t)$——把"依赖历史的表达"（`红色`）重写为"独立可检索的查询"（`红色 iphone 15`）——**这是对话理解的落地点**。
- **第二步，读主题匹配**：$\text{ctx}(d, H_t)$——文档与"整个对话的主题"的契合度——**让检索结果在对话中保持连贯**。
- **第三步，看合成**：重写查询的匹配 + 对话主题的契合，共同决定文档分数——**检索既被"本轮重写"驱动，也被"对话主题"约束**。

**核心结论：对话式检索的公式 = "历史重写查询的匹配" + "对话主题的契合"——对话上下文通过两条路径（改查询 + 改排序）进入检索。** 这与第十一篇《基于上下文的查询理解》完全同构——**对话式搜索是上下文理解的"对话化"形态**。<span class="marginnote">这个"同构"值得点明：<strong>第十一篇的"会话内个性化"已经是对话式搜索的雏形——它用"会话上下文"改进排序；对话式搜索在此基础上加上"对话管理 + 生成回答"</strong>。所以你学过的第十一篇不是孤立的——它是对话式搜索的"上下文理解"那一半。本系列的第十四篇，是把前十三篇的组件组装成"完整的对话系统"。</span>

## 5 对话式搜索的挑战与前沿

对话式搜索面临的挑战，反映了它的前沿性：

- **上下文建模的复杂度**：对话历史多长、怎么压缩、怎么提取"当前焦点"——上下文建模是核心难题（下一篇）。
- **检索与对话的耦合**：查询重写的好坏直接决定检索质量——**对话式搜索对"查询理解"的依赖远超单轮搜索**。
- **多轮交互的评测**：怎么衡量"一场对话"的质量，而不是"一轮"的质量——评测从"查询级"升级到"对话级"。
- **大模型的融合**：现代对话式搜索几乎都用 LLM 做"对话理解 + 生成"——**LLM 既是对话大脑，也是答案生成器**（第十三篇的 RAG 在这里变成"对话式 RAG"）。<span class="marginnote">现代对话式搜索的形态，几乎就是"LLM + 检索"的对话版：<strong>LLM 读对话历史理解当前查询（上下文重写）、LLM 决定检索什么（Agentic）、LLM 基于检索结果生成回答（RAG）</strong>——前十三篇的技术全部被 LLM"调度"。这个趋势在最后一篇《大模型时代的搜索形态》会完整展开——对话式搜索正在变成"AI 搜索产品"的核心交互形态。</span>

## 6 小结

- **对话式搜索**：用户与系统多轮交互——每一轮查询都依赖上下文，检索在对话中持续演进。
- **本质变化**：从"连续的单轮"到"连贯的一体"——"上下文依赖的查询理解"是核心。
- **架构**：对话状态 + 上下文查询理解 + 检索 + 生成 + 反馈循环——在检索系统上加了"对话大脑"。
- **概念边界**：对话式搜索（外部多轮）≠ Agentic RAG（内部多轮）；≠ 聊天机器人（以检索为中心）。
- **形式化**：$\text{score} = f(\text{rel}(\psi(q_t,H_t)), \text{ctx}(d,H_t))$——历史重写 + 对话主题双路径。
- **挑战**：上下文建模、检索-对话耦合、对话级评测、LLM 融合。
