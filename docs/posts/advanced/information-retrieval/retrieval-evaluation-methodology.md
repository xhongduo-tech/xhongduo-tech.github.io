## 为什么需要评测

检索系统是拿来比较的：这个查询处理算法比那个快，这个排序函数比那个准……但「准」字怎么度量？上一篇我们建立了一个朴素信念——**相关性是检索的北极星**。可北极星在天上，怎么把它拽下来量一量？这是 IR 学科七十年来最核心的方法论问题，答案是一套叫**测试集（test collection）**的工程装置。

本篇是第一篇评测博文，回答两个问题：**评测需要哪些原料？相关性的「金标准」是怎么造出来的？** 它直接为下一篇《查准率与查全率》提供原料——没有这里定义的相关性判定，下一篇的分子分母都是空谈。这套「测试集」方法论也不是 IR 独有：第四级《机器学习》里「训练集 / 测试集划分 + 人工标注」的范式，与它是同一个思想的两副面孔。<span class="marginnote">把「真实」降维成「可计算的代理」，再用代理去度量系统——这个模式贯穿 IR、机器学习和今天的 RAG 评测。理解评测，就是理解整个学科怎么给自己「打分」。</span>

## 1 Cranfield 范式：评测的三件套

现代 IR 评测的基本框架，来自 1960 年代英国 Cranfield 学院的系列实验，史称 **Cranfield 实验**。图书管理员出身的 Cyril Cleverdon 在 Cranfield 航空学院用几批文献做了当时最系统的检索实验，证明「测试集」可以充当检索系统的实验台，从而奠定了 **实验室评测（laboratory evaluation）** 的范式。

**测试集（test collection）**由三部分组成，缺一不可：

| 组成 | 内容 | 说明 |
| --- | --- | --- |
| 文档集（corpus） | 固定的文档集合 $C$ | 所有系统在**同一批文档**上检索，才能横向比较 |
| 查询集（queries / topics） | 一组查询或主题陈述 $Q$ | 常写成一段「信息需求」描述，而非几个关键词 |
| 相关性判定（relevance judgments） | 每个查询对应的相关文档集合 | 由人工评估员判定，是唯一的地面真值 |

Cranfield 留下的经典测试集规模不大——约 **1400 篇文档、225 个查询**，却养活了几代研究者：Gerard Salton 的 SMART 系统、剑桥的研究团队都用它做实验基准。**测试集的价值不在「大」，而在「共享」**：同一份文档、同一组查询、同一套判定，任何系统放上来跑一遍，分数就能跟所有历史系统直接比较。

Cranfield 实验其实做了两轮，各有分工。**Cranfield I（1962）** 用不同的索引语言做对照，探索「用什么方式给文档建索引」会影响检索效果；**Cranfield II（1966）** 产出了那个经典的 1,400 篇 / 225 查询测试集，并得到一个影响深远的结论：**自动索引（机器分词、自动加权）的检索效果，并不逊于昂贵的人工索引。** 这个结论当年震动整个情报学界，也为后来「全自动检索」的兴起铺平了道路——今天搜索引擎里没有人工逐篇标引，理论根基就在这里。<span class="marginnote">Cranfield 实验由美国国家科学基金会（NSF）资助，主持者 Cyril Cleverdon 出身图书馆学而非计算机科学。他留下的最有价值的遗产不是某个具体结论，而是「用共享测试集做对照实验」这套方法本身。</span>

**辨析｜易错点：查询集 ≠ 用户真实输入的查询。** 评测中的「查询」往往以**主题（topic）**的形式给出——一段完整的、描述信息需求的文字，而不是用户敲进搜索框的那两个词。这样做的目的是**去个性化**：让所有评估员照着同一段文字判断「什么算相关」，否则每个评估员心里都有自己版本的查询，判定就乱套了。<span class="marginnote">这正是上一篇《检索系统的基本任务》里「信息需求 / 查询 / 主题」三层次在评测中的落地：评测要用「主题」而不是「查询」，因为主题把主观的信息需求外部化了。</span>

## 2 相关性判定：把主观变成可重复

测试集的第三件套——相关性判定——是整套装置里最「手工」、也最微妙的部分。判定由**评估员（assessor）**完成：给评估员一个主题和一批文档，让他们逐篇判定「这篇文档对这个主题相不相关」。

相关性判定有两种粒度：

- **二元判定（binary）**：相关 / 不相关，记 1 / 0。简单、可统计，是 TREC 大多数任务的标准做法。
- **分级判定（graded）**：如 0—3 四个等级（不相关 / 略相关 / 相关 / 高度相关）。更贴近真实，代价是评估员之间的分歧更大。

举个具体的例子。设主题是「红葡萄酒与白葡萄酒对冠心病风险的相对影响」，评估员对三篇文档做判定：

| 文档 | 内容摘要 | 二元判定 | 分级判定 |
| --- | --- | --- | --- |
| Doc A | 直接对比两类酒与冠心病风险的随机对照试验综述 | 相关（1） | 3（高度相关） |
| Doc B | 研究葡萄酒中抗氧化剂对血管的生化作用 | 相关（1） | 2（相关） |
| Doc C | 一篇「如何为晚宴挑选红酒」的品酒指南 | 不相关（0） | 0（不相关） |

二元判定下 Doc A 与 Doc B 完全等价；分级判定却能区分「高度相关」与「只是沾边」。**分级判定保留了更多信息，代价是评估员之间更容易产生分歧**——这两头之间的平衡，正是评测设计要反复权衡的地方。

评估员也是人，两个人的判定不可能完全一致。因此 IR 评测还有一个重要的质量指标：**判定者间一致性（inter-assessor agreement）**，常用 Cohen 的 κ（kappa）系数度量——κ 越高，说明「相关性」这个主观概念在判定中被冻结得越牢。<span class="marginnote">κ 系数的计算在第二级《概率论与数理统计》与第四级《机器学习》的分类评估中都会见到：它扣除「瞎猜也能碰对」的随机一致，只留下真实的判定共识。评测时如果两个评估员 κ 很低，通常不是评估员不认真，而是主题写得太模糊。</span>

**辨析｜易错点：相关性判定是「代理」，不是「真相」。** 评估员基于一段主题文字做出的判定，只是特定时刻、特定一群人对相关性的快照。真实用户的信息需求更复杂、更时变。所以**任何评测分数都只能说明「系统在某个测试集上表现如何」，不能断言「系统在真实世界表现如何」**——测试集是对检索过程的抽象，抽象就有偏差。

## 3 公式解析：池化法（Pooling）

相关性判定的最大工程障碍是规模：一个测试集有几十万篇文档、每个查询有几十个主题，**对每个查询判断全部文档「相不相关」，工作量是「查询数 × 文档数」，完全不可行。** 举个例子：TREC 早期的测试集有 2GB 文本、上百万篇文档，逐篇判定等于让评估员读完整座图书馆。

解法是 **池化（pooling）**——让参加评测的系统们「帮评估员先筛一遍」。假设有 $m$ 个参评系统，每个系统对查询 $q$ 给出一个排序结果，取各自的前 $k$ 篇，全部合并成一个候选池，评估员只对这个池子里的文档做判定：

$$J_q = \bigcup_{i=1}^{m} \text{top}_k(s_i, q)$$

逐项拆解，四步：

- **第一步，$\text{top}_k(s_i, q)$ 是什么。** 系统 $s_i$ 对查询 $q$ 返回的排序列表中，**最靠前的 $k$ 篇**。$k$ 称为**池深（pool depth）**，TREC 传统上取 100。
- **第二步，并集 $\bigcup$ 干什么。** 把 $m$ 个系统各自选出的前 $k$ 篇**合并去重**，得到一个候选池 $J_q$。它的规模从「全部文档」骤降到「每个系统贡献约 $k$ 篇」，评估员的负担从不可行变成可行。
- **第三步，判定的哲学。** 评估员只判定池内的文档：池内的按真实判定记，**池外的文档一律视为不相关**。这是一个「没有检出来，就当不存在」的近似——它成立的前提是：**真正相关的文档，几乎一定被某个参评系统排进了前 $k$。** 系统越多、$k$ 越大，这个前提越可靠。
- **第四步，为什么这是一个合理的近似。** 相关性文档在全部文档里是极稀疏的「少数派」，靠人工无法定位；但多个互不相同的系统「英雄所见略同」地把它们顶到前排的概率很高。池化就是用**系统集合的共识**去替代**全量人工排查**——这是评测工程对「不可行」的第一次也是最重要的一次妥协。<span class="marginnote">池化有个著名的副作用：<strong>新系统若检索到池外文档，会不公平地吃亏</strong>——它找到的相关文档不在判定里，被当成不相关扣分。这是「用旧系统建池、评测新系统」的固有偏差，学术界叫它「池化偏差」（pooling bias），至今仍是评测设计要小心的地方。</span>

用一组袖珍数字感受池化的量级。假设有 $m$ 个参评系统、池深 $k$，则每个查询最多产生 $m \times k$ 篇候选文档；取 TREC 常见的 $m = 50$、$k = 100$，一个查询最多只需判定 $5000$ 篇——相比全量判定的百万篇量级，评估员的工作量被压缩了两个数量级以上。用 Python 模拟三个系统的池化，观感更直接：

```python
# 三个参评系统对同一查询 q 各自返回的前若干篇文档编号
topk = {
    "s1": [3, 7, 42, 88],
    "s2": [7, 88, 133, 210],
    "s3": [42, 88, 999],
}

pool = set()
for system in topk:
    pool.update(topk[system])      # 每个系统的 top-k 全部并入池
print(sorted(pool))
# [3, 7, 42, 88, 133, 210, 999]    ← 评估员只需判定这 7 篇，而非全库
```

注意三份列表的交集 $\{7, 88\}$ 被保留、去重后只算一次——**「英雄所见略同」越集中，池子越小，评估负担越轻**，这正说明池化把系统共识变成了评估效率。

## 4 从实验室到基准：TREC 的诞生

Cranfield 范式在 1960—1990 年代被各个研究组各自使用，但彼此不共享、不比较——「每个实验室都有自己的测试集」成了学科进步的瓶颈。转折点是 **TREC（Text REtrieval Conference，文本检索会议）**。

1992 年，美国国家标准与技术研究院（NIST）的 Donna Harman 在 DARPA 资助下组织了第一届 TREC：提供约 2GB 的 TIPSTER 文本集，规定一个共享任务（ad hoc 检索，50 个主题），请全球各团队用同一套评测方法在同样的数据上比拼。**TREC 的贡献不是发明了测试集，而是把「评测」从私人工具变成了公共基准**——参评系统、池化判定、统一指标、公开发布的判定文件，让「在 TREC 上刷分」成为 IR 领域近三十年的标准叙事。

池化正是随 TREC 而成为标准方法的：TREC 用参与系统的结果建池，评估员判定后把**判定文件公开**，后来的系统无需重复判定，直接拿来当金标准。由此，IR 评测的完整流水线固定下来：**建语料 → 定主题 → 系统跑分 → 池化 → 人工判定 → 发布判定 → 公开比较**。<span class="marginnote">这套「公共基准 + 共享任务」的玩法，后来被 CLEF、NTCIR、INEX 等评测活动复制到多语言、东亚语言与 XML 检索；再后来，图像识别的 ImageNet、大模型的多任务基准，都是同一个「用公共测试集给系统打分」思想的延伸。</span>

至此，读者应该留意到：我们一直在谈的都是**离线评测（offline evaluation）**——用固定的测试集和人工判定给系统打分，不惊动真实用户。与它相对的还有**在线评测（online evaluation）**——把两个版本的检索系统同时放到真实流量上做 A/B 实验，用点击率、停留时间等用户行为间接推断系统好坏。两条路线各有分工：**离线评测快、可复现，适合系统迭代期反复试验；在线评测真实、能捕捉「效用相关」，适合上线前的最终裁决。** 本篇与接下来的几篇专注离线这一支；在线评测留到第一篇末的《用户满意度评测》专门展开。<span class="marginnote">今天大模型的 RAG 评测也继承同样的分工：离线用人工标注集（NDCG、忠实度分数）快速迭代检索器，线上再用点击 / 采纳率做最终验证——离线与在线互为补充，而非互相替代。</span>

## 5 从判定到指标：为下一节铺路

测试集的产出，归根到底是一张**查询 × 文档**的判定表。对每个查询 $q$，从判定里可以取出它的**相关文档集合**：

$$R_q = \{ d \in C \mid d \text{ 与 } q \text{ 相关} \}$$

而系统对 $q$ 的返回，是它自己的**检出集合**：

$$A_q = \{ d \in C \mid \text{系统判定 } d \text{ 与 } q \text{ 相关} \}$$

有了这两个集合，评测就从「判相关性」进入了「算指标」阶段：**$R_q$ 是答案，$A_q$ 是答卷，比较两者重合了多少。** 下一篇我们就定义第一个、也是最经典的两个指标——查准率与查全率，它们的全部分母、分子，都来自这里定义的 $R_q$ 与 $A_q$。<span class="marginnote">留意：$R_q$ 与 $A_q$ 的名字里都带个下标 $q$——因为指标是按查询计算的，最后再对查询集做平均。这个「先按查询算、再跨查询平均」的两层结构，是 IR 评测所有指标的公共骨架。</span>

## 6 小结

- **评测为什么需要测试集**：相关性主观且不可直接度量，必须用「文档集 + 查询集 + 相关性判定」三件套把它冻结成可重复计算的代理。
- **Cranfield 范式**：Cleverdon 在 1960 年代的实验奠定了实验室评测；经典 Cranfield 测试集约 1400 篇文档、225 个查询。
- **相关性判定**：由评估员逐篇判定，有二元与分级两种粒度；判定者间一致性用 Cohen 的 κ 度量。
- **池化法**：$J_q = \bigcup_{i=1}^m \text{top}_k(s_i, q)$——用参评系统的「前排共识」替代全量人工排查，池深 $k$ 传统上取 100；代价是存在池化偏差。
- **TREC**：1992 年由 NIST 的 Donna Harman 创办，把评测变成公共基准，池化由此成为标准方法。
- **接口**：测试集产出相关文档集合 $R_q$，系统产出检出集合 $A_q$——它们是下一节所有指标的分母与分子。

在下一节，我们将把 $R_q$ 与 $A_q$ 放进一张四格表，定义信息检索最经典的两个指标——这就是**查准率与查全率（Precision / Recall）及其权衡**。
