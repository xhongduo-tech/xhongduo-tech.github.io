## 为什么从"生成"开始

前十二篇构建的检索系统，输出的都是"结果列表"——一堆文档链接，用户自己读、自己判断。这是搜索引擎几十年的形态。但大语言模型（LLM）的出现，让一种全新的答案形态成为可能：**直接生成一段通顺的答案**。你问"深度学习是什么"，它给你一段完整的解释，而不是十个链接。

但纯 LLM 有一个致命缺陷：**它会"编"**——训练数据里没有的知识，它要么不知道，要么**幻觉（hallucination）**，一本正经地给出错误答案。于是诞生了**检索增强生成（Retrieval-Augmented Generation，RAG）**：**让 LLM 先生成答案前，先从检索系统里取回相关资料，再基于这些资料生成答案**——把"检索"与"生成"结合，让 LLM 的答案"有据可依"。RAG 是信息检索与大模型最深刻的交汇——**检索给生成提供"事实"，生成把检索变成"答案"**。<span class="marginnote">RAG 这个词来自 2020 年 Facebook 的论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》——它用"检索器 + 生成器"的结构处理开放域问答。RAG 的动机直指 LLM 的两个死穴：<strong>一是"知识过时"（模型的知识停在训练时），二是"幻觉"（模型不知道却不承认）</strong>——检索实时提供知识，生成器照实回答。今天 RAG 已是"给 LLM 接上最新知识"的工业标准架构：所有 AI 搜索产品（Perplexity、Bing Chat、以及第十四篇的各类 AI 搜索）都是 RAG 的形态。</span>

## 1 LLM 的两大死穴：过时与幻觉

为什么需要 RAG？先看清 LLM 的两个根本缺陷：

**缺陷一：知识过时（knowledge cutoff）**。LLM 的知识来自训练语料，训练停止的那一刻就是它的知识边界——**"2026 年的最新规定是什么"它不知道**，因为它没看过 2026 年的数据。模型无法自己更新知识，只能靠"外部接入"。

**缺陷二：幻觉（hallucination）**。LLM 对"不知道的事"不会说"我不知道"，而是**编一个听起来合理的答案**——这是生成模型的天性（它被训练成"生成最可能的词"，不是"确认事实"）。幻觉在大模型应用里是灾难性的：医疗、法律、金融场景，一个幻觉答案的代价极大。

**重点：LLM 是"流畅的生成器"，不是"可靠的知识库"——它知道怎么说得漂亮，但不知道"什么是对的"。** RAG 的定位，就是给这个"流畅但不可靠"的生成器，接上一个"可靠但不流畅"的检索器——**检索管"事实"，生成管"表达"**。<span class="marginnote">幻觉的根源值得想清楚：<strong>LLM 的预训练目标就是"预测下一个词"，它学的不是"事实数据库"，而是"文本的统计规律"</strong>。回答"中国的首都是什么"，它生成"北京"是因为训练语料里这句话的规律如此——不是因为它"知道"这个事实。当问题超出训练分布，它仍按统计规律生成，结果就是"流畅的胡说"。"检索增强"的本质，是<strong>把"从参数里回忆知识"改成"从检索结果里读取知识"——让 LLM 从"背"变成"看"</strong>。</span>

## 2 RAG 的核心思想：检索喂给生成

**核心概念：检索增强生成（RAG）**：生成答案前，先用检索系统从知识库（文档集）中检索相关资料，把检索结果作为"上下文"与用户问题一起交给 LLM，让 LLM 基于这些资料生成答案。

$$\text{答案} = \text{LLM}\Big(\text{问题} \;|\; \text{检索结果}(\text{问题})\Big)$$

RAG 的意义：

- **知识实时**：知识库可以随时更新——新文档进库，RAG 立刻能答新问题（LLM 知识不再过时）。
- **答案有据**：答案基于检索到的文档生成——**有出处、可核对**（能告诉用户"这是根据哪篇文档"）。
- **幻觉可控**：生成被限定在"检索到的内容"范围内——**不依赖模型记忆，减少编造**。<span class="marginnote">RAG 有一个优雅的工程性质：<strong>它把"知识更新"从"重新训练模型"变成"更新文档库"</strong>——预训练一个 LLM 要花几千万美元、几个月，更新一个文档库只要几秒钟。这个"知识更新成本"的数量级差异，是 RAG 在工业界被广泛采用的根本原因：<strong>需要新知识的场景（企业内部文档、实时新闻、最新法规），重训模型不现实，RAG 是唯一经济的方案</strong>。</span>

**重点：RAG 的架构本质是"检索器 + 生成器"——检索器决定"答案的依据"，生成器决定"答案的表达"。** 前半部分（检索器）是本系列前十二篇的全部内容；后半部分（生成器）是 LLM 的事。**RAG 是检索系统在生成时代的"出口"——检索不再只产出链接，它产出"答案的依据"。**

## 3 RAG 的三种工作模式

RAG 在实际使用中有几种模式，按"检索与生成的交互方式"区分：

**朴素 RAG（naive RAG）**：检索一次 → 生成一次。简单，但"一次检索"可能漏掉关键信息。
**进阶 RAG（advanced RAG）**：检索前做查询改写/重写，检索后做重排/过滤——**把查询理解与重排（第九篇、第八篇）接进 RAG 流水线**。
**模块化 RAG（modular RAG）**：检索、记忆、路由、融合、生成——按需组合模块，甚至多轮检索（Agentic RAG，最后一篇）。<span class="marginnote">这个"朴素 → 进阶 → 模块化"的谱系，本质是"检索增强的工程化程度"的递增：<strong>朴素 RAG 是"检索一次就生成"，进阶 RAG 把检索"精装修"（改查询、重排、去噪），模块化 RAG 把检索变成"可规划的智能模块"</strong>。你学过的查询理解（第九篇）与重排（第八篇）在进阶 RAG 里直接复用——RAG 不是新体系，是检索体系在生成时代的重组。</span>

## 4 公式解析：为什么"检索 + 生成"能减少幻觉

从概率角度理解 RAG 为什么能压幻觉。设答案由生成器产生，生成器对答案的条件概率依赖"上下文 $C$"（检索结果）。RAG 的关键是把答案生成条件在"检索到的证据"上：

$$P(\text{答案} \mid \text{问题}) = \sum_{C} P(\text{答案} \mid \text{问题}, C) \cdot P(C \mid \text{问题})$$

三步拆解：

- **第一步，读证据注入**：$P(\text{答案} \mid \text{问题}, C)$——生成器在"看到证据 $C$"的条件下生成答案——**答案被约束在证据范围内**。
- **第二步，读证据选择**：$P(C \mid \text{问题})$——检索器选择"与问题相关的证据"——**证据质量决定答案质量**。
- **第三步，看幻觉抑制**：当证据 $C$ 含正确答案时，生成器"照着写"而非"凭记忆编"——**幻觉被"证据约束"抑制**；当证据不含正确答案时，生成器仍可能编（幻觉没被完全消除）——**"检索质量"是幻觉抑制的天花板**。

**核心结论：RAG 减少幻觉的机制是"把生成约束在检索到的证据上"——证据质量（检索质量）直接决定答案质量与幻觉程度。** 这也是为什么"检索质量对生成质量的影响"值得单独一篇（下一篇）：**在 RAG 里，检索是答案质量的第一决定因素**。<span class="marginnote">一个关键的推论：<strong>RAG 的幻觉风险从"模型不知道"转移成了"检索没搜到"</strong>——如果检索没召回正确答案，生成器照样可能编。所以 RAG 系统的优化重点，很大程度在"检索召回质量"上（这就是本系列前十二篇的所有内容）。"检索增强生成"这个名字的顺序很准确：<strong>先有"检索增强"（检索提供依据），才有"生成"（模型表达依据）</strong>——检索在前，是 RAG 的地基。</span>

## 5 RAG 与搜索引擎的关系

RAG 不是"取代搜索引擎"，而是"搜索引擎的下一代形态"：

| 维度 | 传统搜索 | RAG / AI 搜索 |
| --- | --- | --- |
| 输出 | 结果列表（链接） | 生成式答案 + 引用 |
| 用户动作 | 自己读、自己判断 | 直接得到答案 |
| 知识来源 | 索引文档 | 索引文档（检索器不变） |
| 核心组件 | 检索 + 排序 | 检索 + 生成 |
| 新组件 | — | LLM、上下文窗口、答案生成 |

**重点：RAG 的"检索器"与搜索引擎的"检索器"是同一个东西——索引、召回、排序全复用，新增的是"生成层"。** 搜索引擎的整套基建（索引、ANN、两级架构）在 RAG 里原样工作，只是输出从"文档列表"变成了"基于文档的答案"。<span class="marginnote">这个"基建复用"是理解 RAG 工程的最重要视角：<strong>一个团队如果已经建好了检索基建（索引、召回、排序），加 RAG 只需"加一个生成层"</strong>——把 Top-K 文档喂给 LLM，让 LLM 基于它们生成答案。检索基建的成熟度，决定了 RAG 的质量下限。这也是为什么我们花十二篇把检索讲透——它是 RAG 的"另一半"，而且是更基础的那一半。</span>

**辨析｜易错点：RAG ≠ 把检索结果塞进 prompt 就完事。** 检索结果怎么选、怎么截断、怎么排序、怎么在 prompt 里组织、答案怎么引用出处——每一步都是影响答案质量的工程决策。**"检索到"到"答得好"之间，还有一整套上下文工程**（下一篇的切分、检索质量影响、混合检索应用，都在展开这些决策）。

## 6 数值算例：一场幻觉事故的完整复盘

把"RAG 为什么能压幻觉"演算成一次事故复盘。设用户问"2026 年诺贝尔物理学奖得主是谁"，三种系统的表现：

| 系统 | 处理 | 结果 |
| --- | --- | --- |
| 纯 LLM（无检索） | 凭训练记忆"猜" | 幻觉：编造一个 2024 年的得主，一本正经 |
| 朴素 RAG（检索差） | 检索没召回正确答案 | 仍可能编造（证据不含答案） |
| 优质 RAG（检索好） | 检索召回权威报道 | 照着报道回答，并附引用 |

三步读这张表：

- **看纯 LLM**：2026 年的知识超出训练范围，模型只能"编一个合理的"——**这是幻觉的根源：知识过时 + 生成天性**。
- **看检索差的 RAG**：检索召回的是无关文档，证据不含答案，生成器照样可能编——**RAG 不是万能，检索质量决定幻觉抑制程度**。
- **看检索好的 RAG**：证据含正确答案，生成器"照着写"——**答案有据、可核对、不编造**。

这场复盘揭示了 RAG 的完整逻辑：**RAG 不消灭幻觉，它把幻觉的"源头"从"模型记忆"转移到"检索结果"**——检索好，幻觉少；检索差，幻觉依旧。这就是为什么"检索质量"在 RAG 里是第一优先级的优化对象。

**辨析｜易错点：RAG 的"有据"是"引用有据"，不是"答案必对"。** 生成器照着一篇"权威但有误"的文档回答，答案是"有依据的错误"——**RAG 保证"答案来自证据"，不保证"证据是正确的"**。所以 RAG 系统还要做"证据质量"的把关（权威性过滤、多源交叉验证），而不是把"检索到的"当成"正确的"。

## 8 小结

- **LLM 两大死穴**：知识过时（停在训练时）+ 幻觉（不知道却编）——需要外部知识接入。
- **RAG**：检索增强生成——生成前先检索相关资料，答案基于证据生成，有据可查。
- **核心思想**：检索管"事实"（依据），生成管"表达"（答案）——答案被约束在证据上。
- **三种模式**：朴素（一次检索一次生成）、进阶（加改写重排）、模块化（可规划可多轮）。
- **幻觉抑制机制**：$P(\text{答案}\mid\text{问题},C)$——生成被证据约束；检索质量是幻觉抑制的天花板。
- **与搜索的关系**：检索器完全相同，新增"生成层"——AI 搜索是搜索引擎的下一代形态。

在下一节，我们把 RAG 的骨架立起来——检索器与生成器怎么分工、上下文怎么组织，这就是 **RAG 的基本架构：检索器 + 生成器**。
