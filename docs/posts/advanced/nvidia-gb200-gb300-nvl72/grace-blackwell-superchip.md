## 为什么从超级芯片开始

上一站我们停在 NVIDIA H100/Hopper，看到一颗 GPU 怎样通过 Tensor Core 与 NVLink 变成一台「能塞进服务器的超算」<span class="marginnote">H100 时代的基本单元是「GPU 卡 + 外部 CPU 主机」，CPU 与 GPU 之间隔着 PCIe 或 NVLink，见《AI 硬件：NVIDIA H100/Hopper》。</span>。但 2024 年之后，NVIDIA 回答「如何训练万亿参数模型」的答案变了：**不再是单颗 GPU 有多强，而是把 CPU、GPU、内存、互连、供电、散热全部重新焊进同一块基板，先造出「超级芯片」，再把超级芯片组装成整个机架**。GB200 NVL72 就是这条路线上的旗舰：一座 72 颗 GPU、功耗约 120 kW 的液冷机架，被称为「机架级超级计算机」。

## 1 为什么要发明「超级芯片」

先回到一个朴素的问题：H100 不是已经在训练大模型了吗，为什么还要把 CPU 和 GPU 封在一起？

因为**大模型训练是一个「吃互连」的负载**。Transformer 的每一层都有两次全局通信——一次前向的 all-reduce、一次反向的 all-reduce，通信量与模型并行度直接挂钩。当模型从百亿参数涨到万亿参数，节点之间的数据搬运时间开始反超计算时间，系统便不再「算得快」，而是「等得久」。<span class="marginnote">更精确地说：每步训练的总时间 ≈ 计算时间 + 通信时间，二者必须同时被压下去，见《大模型预训练》与《AI 基础设施》中的并行策略。</span>

NVIDIA 的解法是双管齐下：

**横向**：把 GPU 之间的互连带宽从 PCIe 的几十 GB/s 一路推到 NVLink 的 TB/s 级——这一条线演化出本专题第 2 篇的 NVLink5 与 NVSwitch。
**纵向**：把「喂数据」的 CPU 直接焊到 GPU 旁边，用超高带宽的一致性互连 NVLink-C2C 替代 PCIe，让 CPU 不再成为瓶颈——这就是**超级芯片（Superchip）**。

「喂数据不够快」到底有多严重，把互连带宽排成一列就能看见差距：

| 互连 | 双向带宽 | 典型角色 |
| --- | --- | --- |
| PCIe Gen5 ×16 | 128 GB/s | 传统服务器 CPU-GPU |
| NVLink4（H100 时代） | 900 GB/s | Hopper GPU 之间 |
| NVLink-C2C（Grace-Blackwell） | 900 GB/s | 超级芯片内 CPU-GPU |
| NVLink5（Blackwell） | 1800 GB/s | Blackwell GPU 之间 |

PCIe 是通用总线，走的是「拷贝 → 发送 → 接收 → 拷贝」的流程；而 NVLink 系列是 NVIDIA 为 GPU 生态量身定制的私有互连，把带宽提高了整整一个数量级。**超级芯片的诞生，本质上是把「GPU 等数据」这件最贵的事，从软件层搬到了物理层解决。**

「超级芯片」这个词不是营销噱头，它对应一个具体的硬件事实：**原本分处两块电路板的 CPU 与 GPU，现在被封装到同一块基板上，用芯片间互连（chip-to-chip）直连**。GB200 超级芯片 = 1 颗 Grace CPU + 2 颗 B200 GPU。

## 2 GB200 超级芯片的三个成员

拆开一块 GB200 超级芯片，里面住着三个主角：

**Grace CPU**：72 核 Arm Neoverse V2 处理器，搭配 480 GB LPDDR5X 内存，内存带宽约 1 TB/s。它不承担矩阵运算，只负责数据搬运、调度与通信。<span class="marginnote">用 Arm 而非 x86 做数据中心 CPU，是 NVIDIA 在 GH200 上第一次的大胆试验；省电与高内存带宽让它更适合 AI 训练这类「内存墙」问题突出的负载。</span>

**两颗 B200 GPU**：每一颗都是一块独立的 Blackwell 加速器——2080 亿晶体管、192 GB HBM3e、8 TB/s 显存带宽，FP4 稠密算力约 10 PFLOPS。两颗 GPU 通过 NVLink-C2C 与 Grace CPU 相连，每颗 GPU 获得 900 GB/s 的 CPU 直连带宽。

**NVLink-C2C 互连**：这是超级芯片的灵魂。C2C（Chip-to-Chip）是一类**片间一致性互连**：两颗芯片共享同一份内存地址空间，CPU 可以直接读写 GPU 内存，GPU 也能直接访问 CPU 内存，无需像 PCIe 那样把数据先拷贝到宿主内存再搬运。<span class="marginnote">一致性（coherency）意味着「CPU 写、GPU 读」不再需要显式拷贝与同步——这把传统异构计算的「搬数据」改成了「共享数据」，是编程模型层面的一次简化。</span>

一个值得追问的细节是：**为什么是「一颗 CPU 配两颗 GPU」这个 2:1 的配比？** 答案藏在带宽里。Grace CPU 提供约 1 TB/s 的内存带宽，而两颗 B200 各自需要 900 GB/s 的 CPU 直连带宽，合计 1.8 TB/s——CPU 的内存带宽恰好是两颗 GPU「入口带宽」的一半，而 GPU 的算力增长又比 CPU 快得多。让一颗 CPU 同时喂养两颗 GPU，既把 CPU 侧的总线喂满，又不至于让昂贵的 CPU 核闲置。<span class="marginnote">这个配比不是拍脑袋：NVIDIA 在 GH200 上验证过 1:1，发现 CPU 侧带宽有富余，于是在 GB200 上改成 1:2，用同样的 CPU 支撑两倍的 GPU 算力，摊薄了单颗 GPU 的 CPU 成本。</span>

把三者放在一起，GB200 超级芯片提供的是一套**完整的、可独立训练的节点**：Grace CPU 负责喂数据与调度，两颗 B200 负责计算，C2C 让它们像一台机器那样协作。而 36 个这样的超级芯片，再通过 NVLink5 全部互连，就组成了 GB200 NVL72。

**辨析｜超级芯片 ≠ 传统主机：** 传统服务器里，CPU 是「主人」，GPU 是插在 PCIe 槽里的「外设」，CPU 通过驱动把数据写进 GPU 显存；而在超级芯片里，Grace 与 Blackwell 是**对等伙伴**，共享同一份一致性地址空间，CPU 可以直接访存 GPU 的显存，反之亦然。前者是「把数据搬过去」，后者是「大家读写同一块内存」——这是两代异构计算在编程体验上最本质的区别。

## 3 公式解析：1.4 exaflops 是怎么算出来的

GB200 NVL72 白皮书反复出现一个数字：**FP4 精度下最高 1.4 exaflops 的算力**。这个数字不是测得的目标值，而是从「单卡 × 数量」推出来的上限，拆开看只有三步：

$$
P_{\mathrm{NVL72}} = 72 \times P_{\mathrm{B200}} = 72 \times 20\ \mathrm{PFLOPS} \approx 1.44\ \mathrm{exaFLOPS}
$$

- **第一步，读懂 $P_{\mathrm{B200}} = 20\ \mathrm{PFLOPS}$**：这是单颗 B200 在 FP4 精度、启用 **2:4 结构化稀疏**时的峰值。2:4 稀疏是一种硬件加速技巧——权重矩阵每 4 个元素里只保留 2 个非零，Tensor Core 就能跳过一半的乘法，稠密算力近似翻倍。没有这个前提，B200 的 FP4 稠密算力是约 10 PFLOPS。
- **第二步，乘以 72**：GB200 NVL72 一共装 72 颗 B200 GPU（36 个超级芯片 × 2 颗）。所有 GPU 的峰值相加，就得到机架的聚合峰值。
- **第三步，单位换算**：$72 \times 20 = 1440\ \mathrm{PFLOPS}$，而 $1\ \mathrm{exaFLOPS} = 1000\ \mathrm{PFLOPS}$，所以 $1440\ \mathrm{PFLOPS} \approx 1.44\ \mathrm{exaFLOPS}$——白皮书取整为「最高 1.4 exaflops」。
- **注意「稠密 vs 稀疏」两个口径**：20 PFLOPS 是开启 2:4 稀疏的「峰值」；若用不开启稀疏的稠密口径，72 × 10 = 720 PFLOPS ≈ 0.72 exaFLOPS。GB200 NVL72 白皮书里的「稠密 FP4 约 720 PFLOPS」与「最高 1.4 exaflops（稀疏）」，就是这两个口径的差别——**读到「exaflops」先问一句：稀疏了没有**。

1.4 exaflops 到底意味着什么？把它换算成「每秒多少次 FP4 矩阵运算」约 $1.4 \times 10^{18}$ 次——作为参照，H100 时代的旗舰 DGX H100（8 卡）FP8 稠密算力只有约 16 PFLOPS，**一台 NVL72 的 FP4 稀疏算力约等于 90 台 DGX H100 的 FP8 算力**。这个量级差距，正是 NVIDIA 把 NVL72 称为「机架级超级计算机」而非「一台服务器」的原因。

把这个量级再落回「从极限到大模型」的主线：**极限是单点能做到多快，而 exaflops 级算力意味着「把单点极限乘以 72 颗 GPU、再配上液冷供电与 NVLink 域」，才造出了能训练万亿参数模型的机器**。超级芯片就是这条乘法的第一块积木——它的每一项参数，都会在整架尺度被放大 36 倍。

## 4 从超级芯片到整架：36 与 72 的拼图

GB200 超级芯片不是孤立存在的，它是 NVL72 机架的「原子积木」。36 个超级芯片如何拼成整架？

**18 个计算托架**：每个托架装 2 个超级芯片——36 个超级芯片装进 18 块托架。
**72 颗 GPU**：36 × 2 = 72 颗 B200，全部进同一个 NVLink 域。
**36 颗 Grace CPU**：每个超级芯片一颗，构成机架的 CPU 侧。
**130 TB/s 域内互连**：72 颗 GPU 通过 18 颗 NVSwitch 全互连（见本专题《NVLink5 与 NVSwitch 无阻塞全互联》一篇）。<span class="marginnote">36 = 18 × 2 这个整除关系不是巧合：托架数、超级芯片数、GPU 数之间必须保持整洁的倍数关系，模型切分才能「恰好用完」。GPU 数选型里的「整除灵活性」，在《NVLink 域与 72-GPU 单域互连》一篇里会专门展开。</span>

这个「拼图」在软件里的意义是：**36 个超级芯片 = 36 个可独立调度的「节点」**。训练框架不直接面对 72 颗 GPU，而是面对 36 个「1 CPU + 2 GPU」的节点——调度粒度变粗、每个节点的资源定义更清晰。超级芯片把「节点」这个概念从「一张卡」重新定义为「一颗 CPU + 两颗 GPU 的铁三角」。

每个超级芯片的功耗也值得单独算一笔：两颗 B200 各约 1000 W、一颗 Grace 加 C2C 与内存约 300–400 W，**一个超级芯片满载约 2.3–2.4 kW**。36 个超级芯片 × 约 2.4 kW ≈ 86 kW，加上交换层（18 颗 NVSwitch）与电源损耗，正好对上整架约 120 kW 的功耗预算——**「超级芯片」的功耗粒度，决定了整架供电与散热的设计颗粒**。这也是为什么从单颗 GPU 算功耗算不出机架的账，必须从超级芯片这个「节点」开始算。

**辨析｜「超级芯片」≠「把两张 GPU 贴在一起」：** 区别在于那张 Grace CPU。仅仅是「两颗 GPU 合封」并没有解决「喂数据」问题——GPU 仍然要从外部的 x86 主机取数；而超级芯片把 CPU 一并焊进来，用 C2C 的一致性互连让 CPU 与 GPU 共享地址空间，把「喂数据」从「搬过去」变成了「共享」。**有没有那颗 Grace，是「合封 GPU」与「超级芯片」的分水岭**。

为什么 NVL72 不直接用 72 颗「散装」B200，而坚持用 36 个超级芯片？因为「喂数据」这件事必须就近解决：散装 GPU 要靠外部主机喂数据，走 PCIe 的 128 GB/s 会成为 72 颗 GPU 共同的瓶颈；而 36 个超级芯片把「喂」分散到 36 颗 Grace CPU 上，每颗 Grace 的约 1 TB/s 内存带宽就近供养两颗 GPU——**数据搬移被彻底去中心化**。这是「超级芯片」在整架尺度上最被低估的价值。

在软件里，CUDA 把超级芯片中的两颗 GPU 当作两个独立的设备，但 C2C 让它们共享地址空间——统一内存可以直接跨 CPU 与两颗 GPU 管理数据。训练框架把「一颗 CPU + 两颗 GPU」当一个节点的同时，也能利用 C2C 让两颗 GPU 互相直访显存。**超级芯片的硬件创新，最终是通过 CUDA 的编程模型「翻译」给程序员的**——硬件改了，软件接口也要同步简化，这正是本专题《机架管理、固件与 NVIDIA 软件栈》一篇要展开的「软硬件一体」。

## 5 为什么先学「超级芯片」

把超级芯片放在第 1 篇，是因为它是 NVIDIA 全新「系统叙事」的起点。回顾本专题第 1 篇的展开顺序：

**本篇**：超级芯片——「一台机器的最小节点」由什么组成。
**第 2 篇**：Blackwell GPU 架构——超级芯片里「算」的部分。
**第 3 篇**：Transformer Engine 与 FP4——「怎么算得更快」。
**第 4 篇**：Grace CPU 与 C2C——「怎么喂得更快」。
**第 5 篇**：HBM3e 显存——「怎么装得下」。

超级芯片把「CPU、GPU、内存、互连」四者焊成一体，后面每一篇都是把其中一个部件放大细看。**理解超级芯片，就是先拿到整幅地图，再逐格放大**——这正是「从极限到大模型」里「先见森林、再认树木」的学习路径。

## 6 小结

- **GB200 超级芯片 = 1 颗 Grace CPU + 2 颗 B200 GPU + NVLink-C2C**，是 NVL72 的最小节点。
- **超级芯片的诞生**是为了解决「大模型训练吃互连」：CPU 直接焊到 GPU 旁边，用一致性互连 C2C 替代 PCIe，带宽从 128 GB/s 跳到 900 GB/s。
- **2:1 配比**是「CPU 内存带宽与两颗 GPU 入口带宽」的平衡点；1 颗 CPU 喂 2 颗 GPU，摊薄了单 GPU 的 CPU 成本。
- **NVL72 = 36 超级芯片 = 72 GPU**；1.4 exaflops 是「72 × 20 PFLOPS」的稀疏峰值，稠密口径是约 720 PFLOPS。
- **每个超级芯片约 2.3–2.4 kW**：36 个 × 约 2.4 kW ≈ 86 kW，加上交换层与电源损耗，对上整架约 120 kW——超级芯片是整架功耗的天然计价单位。
- **「喂数据」去中心化**：36 颗 Grace 各供养两颗 GPU，把 PCIe 时代的单一瓶颈拆成 36 条就近通道——这是超级芯片在整架尺度上最被低估的价值。
- **超级芯片是乘法积木**：它的每一项参数都会在整架尺度被放大 36 倍——「单点极限」与「系统规模」在这里第一次相遇。
- **产品节奏的小步试错**：从 GH200 的 1:1 到 GB200 的 1:2，NVIDIA 用一代代的试错找到了「一颗 CPU 配两颗 GPU」的最优配比——配比不是拍脑袋，而是带宽账算出来的。
- **「对等伙伴」而非主从**：Grace 与 Blackwell 之间没有「主从」，只有「分工」——数据在两者之间像在一台机器内部流动，「一台机器」的幻觉正来源于此。
