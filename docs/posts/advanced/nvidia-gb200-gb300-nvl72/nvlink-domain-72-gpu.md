## 为什么从「域」开始

上一节我们把 72 颗 GPU 与 18 颗 NVSwitch 连成了「无阻塞全互联」。但「连起来」只是物理层，真正让 NVIDIA 敢说「一台机架 = 一台 GPU」的，是它给这 72 颗 GPU 起了一个逻辑上的名字——**NVLink 域（NVLink Domain）**。域是一个「边界」：域内，GPU 之间用 NVLink 直连、互相访问显存、共享地址空间；跨出这个边界，通信就要走网络。这个边界决定了软件能怎么切模型、通信能省多少、瓶颈在哪儿。<span class="marginnote">「域」的概念在分布式系统里无处不在：NUMA 节点是内存域、Kubernetes 里的节点是资源域、NVLink 域是「GPU 互连域」。边界之内资源昂贵且高速，边界之外便宜但慢——理解一个系统，先找它的域边界。</span>

读这一节时，请把注意力从「芯片」挪到「边界」上：上一节讲的是互连怎么连，这一节讲的是互连「连到哪儿为止」。<strong>域，就是 NVIDIA 对「互连的边界」的精确回答</strong>——它让「72 颗 GPU」在软件里等价于「一台 GPU」。这一节把「域」拆开：它凭什么成立、为什么恰好是 72、以及它如何塑造训练与推理的软件。

## 1 什么是 NVLink 域

**NVLink 域**：一组通过 NVLink 完全互连、彼此可以直接访问对方显存、并共享一致内存地址空间的 GPU 集合。GB200 NVL72 的 72 颗 GPU，就构成一个完整的 NVLink 域。

拆开这个定义，有三个递进的要点：

**完全互连**：域内任意两颗 GPU 之间都有 NVLink 路径，任意通信模式都不需要绕道——这正是上一节「无阻塞」的成果。
**直接访存**：一颗 GPU 的内核可以**直接读写另一颗 GPU 的显存**，不需要先把数据拷回自己的显存。对 CUDA 而言，域内 GPU 的内存像是一块「共享的大内存」。
- **一致地址空间**：跨 GPU 的指针可以直接使用，硬件负责同步。软件看到的不是「72 块独立显存」，而是一块 13.5 TB 的统一内存。

这三个特点，把「72 台计算机」变成了「一台有 72 块内存的巨型计算机」。域外的世界（另一台 NVL72、另一批卡）则完全是另一回事——那里没有共享内存，只有网络报文。<span class="marginnote">可以类比多核 CPU 的 NUMA：同一个节点内的核共享内存，跨节点要走总线。NVLink 域就是「GPU 世界的 NUMA 域」，只不过这个域大得多、带宽高得多。</span>

一个容易混淆的点值得先划清：**「NVLink 域」不等于「一个机架」**。NVL72 恰好把 72 颗 GPU 放进一个机架，所以「一域 = 一机架」在此成立；但域是逻辑概念，理论上域也可以跨多个机柜（比如下一代 NVL576 就把 576 颗 GPU 扩进一个更大的域）。**域看的是「互连是否 NVLink」，机架看的是「物理装在哪里」**——别把逻辑与物理混为一谈。

## 2 为什么恰好是 72

72 这个数字不是随便拍的，它是一组约束的「交点」：

**物理约束**：72 = 36 个 GB200 超级芯片 × 2 颗 GPU。36 个超级芯片放进 18 个计算托架、每个托架 2 个——这个数量刚好铺满一个机架的功率与散热预算（约 120 kW 液冷）。再多放，供电与散热会撑不住。

**互连约束**：18 颗 NVSwitch（9 托架 × 2），每颗为 72 颗 GPU 各提供 1 端口，恰好匹配 72 × 18 条链路（见上一篇的整除关系）。这个规模正好让 NVLink 域做到「一跳无阻塞」——换一个 GPU 数，整除关系就可能被打破。

**应用约束**：72 颗 GPU 聚合 13.5 TB 显存，以 FP4 精度可以装下约 27 万亿参数的模型（$27 \times 10^{12} \times 0.5\ \mathrm{字节} = 13.5\ \mathrm{TB}$）。NVIDIA 宣称 NVL72 支持「27 万亿参数模型」，数字就是这么来的。<span class="marginnote">27T 参数是「把 FP4 权重全塞进显存」的理论值，实际训练还要留梯度、优化器状态与激活的空间，真实能训的模型要小一个量级。厂商的「支持 X 参数」多数是「装得下」，不是「训得起」，见《大模型预训练》。</span>

**软件约束**：72 是「单机架、单域、单机」的自然规模。在软件里，一个 NVLink 域对应一个可被整体调度的资源单位——你不需要再操心域内通信，框架直接把它当一台机器用。

**辨析｜为什么不把域做得更大或更小：** 往小了看，DGX 时代一个域只有 8 颗 GPU，训练万亿模型要跨很多域、走很多网络，通信成了大头；往大了看，域若做到几百颗 GPU，NVLink 的铜线距离拉不长、供电散热撑不住，交换层也会因为端口不够而失去「一跳无阻塞」。72 恰好卡在「域内装得下一个完整模型并行组、域外只剩低频通信」的甜点上——**域的大小，本质是「单机架物理极限」与「软件并行粒度」之间的最优妥协**。

顺带一提，72 不是 2 的幂（64、128），但它是 18（NVLink 链路数）与 4（托架数）的倍数，且能被 6、8、9 整除——这让模型切分（张量并行的 8 路、流水线的 9 段、数据并行的任意整除）都游刃有余。**「整除的灵活性」是 GPU 数选型里常被忽视但极其实际的考量**：你总希望模型并行度能整除 GPU 数，否则会有空闲的卡。

## 3 域内与域外：两个世界

NVLink 域最有价值的副产品，是它把系统清晰切成了「域内」与「域外」两个世界，而优秀的大模型系统设计，就是在刻意放大「域内」、压缩「域外」。

**域内（机架内）**：GPU 间走 NVLink，带宽 1.8 TB/s、延迟微秒级、共享内存。张量并行、数据并行、流水线并行的全部高通信并行度都放这里。

**域外（机架间）**：走 InfiniBand / 以太网，带宽几十到几百 Gb/s、延迟数十微秒、无共享内存。只有「跨域不得不同步」的数据才放这里。

一个具体的设计准则是：**把「每个 step 都要通信」的模式放在域内，把「偶尔通信」的模式放在域外**。例如训练一个万亿参数模型，可以把张量并行组完全限制在一个域内（72 颗 GPU 足够组成 8 路甚至 72 路的张量并行组），域间只做数据并行的一次 all-reduce——通信量骤减，训练效率大幅提升。<span class="marginnote">「通信模式的频率 × 通信量」决定了它该放域内还是域外：高频大流量（张量并行的 all-reduce）必须域内，低频小流量（checkpoint、跨域梯度聚合）可以域外。这是分布式训练里的顶层设计原则，见《大模型预训练》与《AI 基础设施》。</span>

域外连接本身也有一套讲究：NVL72 通过 ConnectX 网卡接入 InfiniBand 网络，多个域按「胖树」（fat-tree）或类似的拓扑组成大型集群。多个 NVL72 域再合在一起，就构成 NVIDIA 口中的 **SuperPOD**——一组由高速网络互连的域集合，是「万卡集群」的最小构建单元。域是「一台机器」，SuperPOD 才是「一个集群」；训练框架在这两层分别做并行切分与数据并行。

把「从小到大的每一层」排成一张表，就能看清系统设计的层次：

| 层级 | 规模 | 互连 | 软件中的角色 |
| --- | --- | --- | --- |
| 单颗 GPU | 1 GPU | — | 最小计算单元 |
| 超级芯片 | 1 CPU + 2 GPU | NVLink-C2C | 最小节点 |
| NVLink 域 | 72 GPU | NVLink5 + NVSwitch | 「一台巨型机」 |
| SuperPOD / 集群 | 多个域，数百到上万 GPU | InfiniBand / 以太网 | 「一组巨型机」 |

每一层都有自己独立的互连与软件抽象——**理解 NVLink 域，就是抓住了这棵层级树从「节点」跳到「集群」的关键一跳**。

## 4 公式解析：域内 all-reduce 要花多久

「域内通信快」到底有多快？用环形 all-reduce（ring all-reduce）的公式算一笔。NCCL 的环形算法把 $N$ 颗 GPU 排成一个环，每颗 GPU 只和邻居通信，总时间近似为：

$$
T_{\mathrm{allreduce}} \approx 2 \times \frac{N-1}{N} \times \frac{V}{B} \approx 2 \times \frac{140\ \mathrm{GB}}{1.8\ \mathrm{TB/s}} \approx 156\ \mathrm{ms}
$$

- **$N = 72$**：域内 GPU 数。当 $N$ 很大时，$(N-1)/N \approx 1$，公式退化为 $2V/B$。
- **$V = 140\ \mathrm{GB}$**：待聚合的数据量——一个 70B 模型在 FP16 下的梯度体积（梯度和权重一样大）。
- **$B = 1.8\ \mathrm{TB/s}$**：每颗 GPU 的 NVLink5 带宽。
- **系数 2**：环形 all-reduce 要「reduce-scatter + all-gather」两个阶段，每阶段搬一遍数据，所以乘以 2。

156 毫秒看起来不小，但它是「把 140 GB 数据在全域广播并求平均」的代价。同样的数据走 400G 网卡（约 50 GB/s）要 5.6 秒——**域内比域外快 36 倍**。<span class="marginnote">这个对比是「为什么要把高通信并行度留在 NVLink 域内」的量化证据。真实训练里梯度体积与 batch、并行度相关，但「域内便宜两个数量级」的结论不变。</span>当每个 step 的计算时间在秒级时，156 ms 的域内通信只是零头；若换成域外，通信时间就会反超计算时间——训练就卡在网络上。

顺带修正一个误差来源：上面的公式假设「先收集、后求和」的朴素流程。而上一节提到的 **NVLink SHARP** 让交换机在转发途中直接做加法，all-reduce 实际只要搬一遍数据而非两遍，真实延迟比公式值还要低不少。<span class="marginnote">所以公式给的是「无 SHARP 的上界」，实际 NVL72 上 NCCL 的 all-reduce 会比 2V/B 更快。把公式当「量级感」，把 SHARP 当「锦上添花」，是最准确的读法。</span>这再次印证：域内通信的优化是「结构 + 算法」双管齐下。

## 5 域与软件：一块 13.5 TB 的「假内存」

对软件栈而言，NVLink 域意味着什么？最直观的答案是：**域内的显存可以当作一块巨大的统一内存来编程**。

在 CUDA 层面，NVLink 域支持「细粒度内存访问」——一个 kernel 可以随机读写域内任意 GPU 的显存，就像访问本地显存一样（带宽不同，但语义一致）。这催生了几类只有在 NVL72 上才优雅的软件形态：

**单进程多 GPU 编程**：一个进程握有 72 块显存，模型切分（张量并行）由框架在域内自由调度，无需感知网络。
**大模型直接放置**：权重、KV 缓存、激活可以按层分布在 13.5 TB 上，域内访存让跨卡依赖近乎零成本。
- **推理的「单机体验」**：服务端只需要把它当一台超大显存的机器，而不必搭建多机推理管线。<span class="marginnote">推理侧尤其受益：vLLM、TensorRT-LLM 等引擎把「多卡推理」当作「单卡推理的大显存版本」，PagedAttention 的显存池可以直接铺满整个域，详见《大模型部署》。</span>

NVSwitch 还藏着另一个加速域内通信的秘密武器——**NVLink SHARP（In-Network Reduction）**。它让交换机本身具备「求和 / 求最大值」的运算能力：all-reduce 时，GPU 把数据发给交换机，交换机在转发途中直接完成加法，再把结果广播回去——**聚合计算被搬进了网络**。这样 GPU 只需要收发一次数据，而不是先全部发给某颗 GPU 累加、再广播，通信量几乎减半，延迟大幅下降。<span class="marginnote">「在网络里做计算」的思想最早来自 InfiniBand 的 SHARP（Sharp Networking），NVIDIA 把它移植进了 NVSwitch。这与「可编程交换机」「在网计算」（In-network Computing）是同一条技术脉络，也是网络研究的前沿方向。</span>NVL72 的 all-reduce 之所以快，一半功劳要记在 NVSwitch 的 SHARP 上。

当然，「假内存」不是万能药：跨 GPU 访存的带宽仍只有 1.8 TB/s（远低于本地 8 TB/s），所以编程上仍要「数据尽量本地化」。**域让编程变简单，但没有让「跨卡访存」变免费**——它是把复杂度从「网络协议」降级成「NUMA 距离」。

## 6 小结

- **NVLink 域**：一组经 NVLink 完全互连、直接访存、共享一致地址空间的 GPU；NVL72 的 72 颗 GPU 构成单域，聚合成 13.5 TB「统一内存」。
- **一句话记忆**：域内「像一台机器」，域外「要过网络」——所有高通信并行度都放域内。
- **72 的来历**：36 超级芯片 × 2、18 颗 NVSwitch 端口整除、120 kW 供电散热上限、27T 参数（FP4）的应用目标——四组约束的交点。
- **域内 vs 域外**：域内 1.8 TB/s 微秒级，域外几十 Gb/s 数十微秒；「每个 step 都通信」的并行度必须留在域内。
- **环形 all-reduce 公式** $T \approx 2V/B$
