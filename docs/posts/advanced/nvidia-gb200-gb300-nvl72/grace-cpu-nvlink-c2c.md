## 为什么从 CPU 开始

前面三篇我们把镜头几乎全对准了 GPU：双 Die、Tensor Core、FP4。但一个朴素的常识是：**GPU 不会自己运行**。在 CUDA 程序里，负责「启动内核、管理内存、调度任务」的永远是 CPU——它是 GPU 的管家、司机与搬运工。传统服务器用 x86 CPU 当管家，而 GB200 超级芯片换上了 NVIDIA 自研的 **Grace CPU**，并用一条 **NVLink-C2C** 高速互连把管家和工人焊在一起。<span class="marginnote">在传统服务器里，CPU 与 GPU 之间走 PCIe 总线；在超级芯片里，Grace 与 Blackwell 之间走 NVLink-C2C。这条路的带宽从 128 GB/s 跳到 900 GB/s，是「异构计算」体验质变的关键。</span>这篇把 Grace 与 C2C 拆开看：一颗 Arm CPU 凭什么进数据中心，一条片间互连又凭什么取代 PCIe。

回到「从极限到大模型」这条主线上，CPU 是那个被忽略的「极限」：微积分的极限回答「无穷细怎么算」，而系统里的「极限」回答「数据搬运的天花板在哪里」。**GPU 算得再快，如果数据喂不进去，一切归零**。Grace 与 C2C 正是 NVIDIA 对这个「喂数据极限」的正面回应——理解它，才算理解大模型训练系统里「算力之外的那一半」。

## 1 Grace CPU 的硬件画像

Grace 不是普通 Arm 芯片，它是 NVIDIA 专门为 AI 工作负载设计的**数据中心级 CPU**，三个关键词就能勾勒出它的性格：

**Arm Neoverse V2 核心**：72 个 Armv9 架构的 Neoverse V2 核心。相比消费级 Arm 核心，Neoverse V2 是为服务器设计的——支持可伸缩向量扩展（SVE），单指令就能处理更长的向量，在数据搬运、向量化计算上比通用核更高效。<span class="marginnote">x86 也有 AVX-512 之类的向量指令，但 Arm 的 SVE 走的是另一条路：向量长度不锁定在 512 位，而是由硬件实现决定，软件按「最少长度」写、硬件按「最大长度」跑——为未来核心留了升级余地。这套向量思想在第一级《计算机组成原理》与第三级《计算机体系结构》里都能找到对应。</span>

**480 GB LPDDR5X 内存**：内存直接封装在 CPU 附近，而不是插在可拆卸的 DIMM 插槽上。LPDDR5X 本是手机用的低功耗内存，被 Grace 用在了数据中心——它带宽高（约 1 TB/s）、功耗低，代价是不可升级。这个「内存焊死」的设计，换来的是接近 GPU 显存的速度体验。

**高内存带宽优先**：Grace 把「内存带宽」当成第一设计目标，而不是「单核性能」。AI 训练里 CPU 的活大多是搬运数据、查表、通信，这些活吃带宽不吃单核。<span class="marginnote">对比一下：顶级 x86 服务器的内存带宽通常几百 GB/s，Grace 把它推到约 1 TB/s，翻了一两倍。这在「数据搬运」型负载上的体感，比核心数翻倍还明显。</span>配上 480 GB 的大容量，Grace 甚至能装下模型嵌入表、KV 缓存这类「不想塞进显存」的大家伙。一个直观类比：**显存像你的工作台，Grace 内存像伸手可及的书架**——工作台放正在算的，书架放随时要用的。

还有一个战略层面的问题值得回答：**NVIDIA 为什么要自己造 CPU，而不是继续买 AMD/Intel？** 答案有三层。第一层是**控制力**：只有自己造 CPU，才能把「CPU 内存带宽」「C2C 一致性」「GPU 互连」放在同一张图纸上设计，x86 厂商不会为 NVIDIA 改芯片。第二层是**功耗**：同样的算力，Arm 方案的整体功耗低于 x86，放在 120 kW 的机架里，每一瓦都要精打细算。第三层是**生态闭环**：CUDA 生态再往上是 Grace 的 Arm 软件栈，NVIDIA 可以像苹果那样「硬件软件一起发」，让每一代新特性第一时间被软件用起来。<span class="marginnote">这个「全栈自研」的路线，与华为昇腾（达芬奇架构 + CANN）、特斯拉 Dojo 殊途同归——AI 算力竞争已经从「买芯片」演变成「造系统」，见本专题的姊妹篇《AI 硬件：华为昇腾》。</span>

## 2 NVLink-C2C：把「搬运」改成「共享」

超级芯片的另一个主角是 **NVLink-C2C（Chip-to-Chip）**。理解它最好的方式是和 PCIe 对比：

**PCIe 是「外设总线」**：CPU 是主人，GPU 是外设。数据要进 GPU，必须先拷贝到 CPU 内存，再通过 PCIe 写进显存；反过来也一样。一次往返是两次拷贝、两次跨越。
**NVLink-C2C 是「一致性互连」**：Grace 与 Blackwell 共享同一份地址空间。CPU 可以直接读 GPU 显存里的数据，GPU 也可以直接访问 CPU 的 LPDDR5X 内存——不需要显式拷贝，硬件自动维护两边的一致性。

这个差别看起来是工程细节，实际是编程模型的质变。<span class="marginnote">「一致性」（coherency）的意思是：同一地址在两个芯片上读到的是同一份数据的最新值，硬件负责同步。没有了它，你得手动刷新缓存、手动拷贝、手动同步——正是传统异构编程里最折磨人的那部分。</span>带宽数字同样惊人：每颗 B200 通过 C2C 获得 **900 GB/s** 的 CPU 直连带宽，两条加起来，Grace 向两颗 GPU 提供共 1.8 TB/s 的互连带宽——这已经超过任何 PCIe 总线好几个量级。

「一致性」在硬件上靠的是**缓存一致性协议**：C2C 的每一端都有各自的一级缓存，当一个芯片写了某个地址，协议会通过监听或目录机制通知另一端「你的缓存过期了」，保证下一次读取拿到最新值。这套机制在操作系统课程里叫「缓存一致性」，在多路 CPU 服务器里已经跑了几十年；NVIDIA 只是把它第一次大规模搬到了「CPU 与 GPU 之间」。<span class="marginnote">代价是协议带来的延迟与硬件复杂度。所以 C2C 不是「免费的一致」——NVIDIA 让 Grace 与 Blackwell 共享一套地址空间，但把「读多写少、以流式为主」的 AI 负载特性设计进协议，才让开销可接受。</span>对程序员来说，效果是「零拷贝」：数据不需要从一个内存搬到另一个内存，写一次，双方都能读。

**辨析｜NVLink-C2C ≠ NVLink：** 虽然名字里都有 NVLink，但它们是两套东西。**NVLink**（本专题第 2 篇）是 GPU 与 GPU 之间的互连，跑在 NVSwitch 上，目标是「GPU 集群内高带宽通信」；**NVLink-C2C** 是芯片与芯片（这里是 CPU 与 GPU）之间的互连，目标是「异构融合」。一条 C2C 只有两个端点，而 NVLink 是全网状、可穿越交换机的。<span class="marginnote">一句话记忆：C2C 是「贴脸直连」，NVLink 是「全城高速路网」。前者让一颗 CPU 管两颗 GPU，后者让 72 颗 GPU 连成一台机器。</span>

## 3 Grace 在 NVL72 里到底干什么

放进整个机架，Grace CPU 的角色可以用四个「喂」字概括：

**喂数据**：训练时每个 step 都要读入样本、做预处理、送进 GPU。Grace 的 1 TB/s 内存带宽保证数据管线不成为瓶颈。<span class="marginnote">大模型训练的数据管线（DataLoader）经常被忽略却最容易卡脖子：CPU 读盘、解压、增强的速度，直接决定 GPU 有多少时间在「空等数据」。Grace 把这段最廉价的硬件成本补上了，见《大模型预训练》中的数据处理。</span>

**喂通信**：跨机架的梯度聚合（all-reduce）需要 CPU 参与协调，NCCL 库的集体通信操作由 Grace 调度。机架内 GPU 之间走 NVLink，出了机架走 ConnectX 网卡——网卡挂在 Grace 的 PCIe 总线上，CPU 是 Scale-out 出口的把关人。

**喂嵌入**：推荐系统、大模型的 embedding 表往往有几十 GB 到几百 GB。把嵌入表放在 Grace 的 480 GB 大内存里，GPU 通过 C2C 按需取用，既省显存又保持高速访问——这是 Grace 内存「大而快」的最典型用法。

**喂显存（内存扩展）**：当模型、KV 缓存超过显存时，可以把一部分冷数据放到 Grace 内存里，GPU 需要时再拉回来。C2C 的 900 GB/s 让这种「显存溢出」不再慢到不可用——这是把 Grace 当成「第三级显存」来用。

其中「喂显存」这条，在 **MoE（混合专家）模型推理**里是杀手锏。MoE 模型只有一小部分专家参数在每次前向被激活，绝大部分专家「躺」在内存里用不上。把全部专家权重放在 Grace 的 480 GB 内存里，GPU 每次只通过 C2C 拉取被选中的几个专家——显存立刻够用，且 C2C 带宽足以支撑专家切换的流量。<span class="marginnote">MoE 的结构与推理策略见《MoE 混合专家架构》与《大模型部署》；「CPU 内存装专家、GPU 显存装热参数」正是 GB200 相对传统服务器最典型的 MoE 推理加速姿势。</span>这也是「超级芯片 = 算力 + 大内存」这个组合在真实负载里最锋利的一次体现。

## 4 公式解析：1 TB/s 到底快在哪

Grace 的 1 TB/s 内存带宽，换成「读一遍大模型权重要多久」就特别直观。设模型权重大小为 $V$，读取时间为 $t = V / B$：

$$
t_{\text{C2C}} = \frac{140\ \mathrm{GB}}{900\ \mathrm{GB/s}} \approx 0.16\ \mathrm{s}, \qquad
t_{\text{PCIe}} = \frac{140\ \mathrm{GB}}{128\ \mathrm{GB/s}} \approx 1.1\ \mathrm{s}
$$

- **$V = 140\ \mathrm{GB}$**：一个 70B 参数模型在 BF16 下的权重体积（$70 \times 10^9 \times 2$ 字节）。
- **$B_{\text{C2C}} = 900\ \mathrm{GB/s}$**：每颗 B200 通过 NVLink-C2C 拿到的 CPU 直连带宽。
- **$B_{\text{PCIe}} = 128\ \mathrm{GB/s}$**：PCIe Gen5 ×16 的双向带宽，代表传统服务器里「GPU 从宿主内存取数」的速度。

结果一目了然：**同样读一遍 70B 权重，C2C 只要 0.16 秒，PCIe 要 1.1 秒，差近 7 倍**。<span class="marginnote">7 倍是什么概念？训练时每次 optimizer step 之间的参数同步、推理时每次把新 KV 写进 CPU 内存，7 倍的延迟差会直接变成吞吐差。这也是为什么「内存扩展」在 Grace 上可行、在 PCIe 时代不可行。</span>真实负载不会只读一遍，而是每个 step 都在搬——所以带宽的差距会被线性放大成训练时间的差距。

把 Grace 放进整个存储层次里，能更清楚地看到它的位置。一个 NVL72 里的数据「从快到慢」排下来是这样的：

| 层级 | 容量 | 带宽量级 | 角色 |
| --- | --- | --- | --- |
| 显存 HBM3e | 72 × 192 GB | 8 TB/s / GPU | 主战场，放权重与热 KV |
| Grace 内存 LPDDR5X | 36 × 480 GB | 约 1 TB/s / CPU | 扩展内存，放嵌入表与专家 |
| 机架外网络 | — | 数十 Gb/s 级 | 跨机架数据交换 |
| 本地 / 远端存储 | 数 TB 以上 | GB/s 级 | 冷数据与 checkpoint |

Grace 内存正好卡在「显存之下、网络之上」的位置：比显存慢一个数量级，但比网络与磁盘快两三个数量级，容量又是显存的 2.5 倍。**这套「金字塔」正是现代大模型系统能同时塞下大模型、长上下文与高并发的物理前提**——也是《大模型部署》里「异构内存 / 分级缓存」策略的硬件底座。

## 5 与 x86 主机节点的一页对比

把「Grace + C2C 超级芯片」和传统「x86 主机 + PCIe GPU」并排比较，差异一目了然：

| 维度 | 传统 x86 主机 | Grace CPU 节点 |
| --- | --- | --- |
| CPU | 2 路 x86（几十核） | 1 颗 Grace（72 核 Arm） |
| CPU 内存 | DDR5 DIMM，几百 GB/s | 480 GB LPDDR5X，约 1 TB/s |
| CPU 内存容量 | 可扩展 512 GB–2 TB | 固定 480 GB |
| CPU-GPU 互连 | PCIe Gen5，128 GB/s | NVLink-C2C，900 GB/s |
| 数据搬运模式 | 拷贝进显存 | 共享地址空间 |
| 每 GPU 分摊的 CPU 带宽 | 128 GB/s | 900 GB/s |

最大的变化不在绝对数值，而在**「每颗 GPU 分到的 CPU 带宽」**：传统架构里一颗 GPU 只有 128 GB/s 的入口带宽，GB200 里每颗 GPU 独享 900 GB/s——**7 倍的路，而且是「共享内存」而非「拷贝数据」的路**。这是整个超级芯片概念能成立的技术底座。<span class="marginnote">当然 x86 也有它的主场：兼容性、生态成熟度、通用服务器软件。Grace 的代价是只能跑 NVIDIA 自己的 Arm 生态。选型时「性能 vs 生态」是永远的天平。</span>

**辨析｜带宽 ≠ 延迟：** 900 GB/s 是带宽——单位时间能搬多少数据；而访问一笔数据的**延迟**（往返时间）则是另一回事。C2C 的一致性协议每次访问都有同步开销，所以 Grace 内存的延迟明显高于显存；它能当「扩展内存」用，但当不了「主显存」用。正确的姿势是：**把大块的、流式的、对延迟不敏感的数据放 Grace，把高随机访问的、热的数据放显存**——把两种内存当两级缓存用。这也是所有「Grace 加速」案例背后的通用设计原则。

回到 NVL72 的「家底清单」：36 颗 Grace CPU × 480 GB 就是约 17 TB 的 CPU 侧内存，加上 72 × 192 GB 的显存，整架共有约 30 TB 的可用内存。对万亿参数模型来说，权重、嵌入、KV 缓存可以分层铺在这 30 TB 上——**显存放热数据、Grace 内存放温数据、跨机架网络兜底冷数据**，一台机架就是一个自洽的存储系统。

## 6 小结

- **Grace CPU**：72 核 Arm Neoverse V2，480 GB LPDDR5X，约 1 TB/s 内存带宽——为「搬运数据」而非「单核跑分」而生；NVIDIA 自研 CPU 是为了全栈控制与功耗。
- **NVLink-C2C**：CPU-GPU 片间一致性互连，每颗 B200 独享 900 GB/s；它把「拷贝数据」变成「共享内存」，是异构编程质变的关键。
- **C2C ≠ NVLink**：C2C 是两个芯片贴脸直连，NVLink 是 GPU 集群的高带宽路网，两者服务于不同目标。
- **Grace 的四重角色**：喂数据、喂通信、喂嵌入、喂显存扩展；480 GB 大内存让它能装下嵌入表与 KV 缓存。
- **存储层次位置**：显存之下、网络之上——比显存慢一个量级、比网络与磁盘快两三个量级，容量是显存的 2.5 倍，是存储金字塔里关键的中间层。
- **整架内存约 30 TB**：36 颗 Grace × 480 GB + 72 × 192 GB 显存——权重、嵌入、KV 缓存分层铺在这 30 TB 上，一台机架就是一个自洽的存储系统。
- **MoE 杀手锏**：把全部专家权重放 Grace 内存、GPU 按需拉取，显存立刻够用——「超级芯片 = 算力 + 大内存」最锋利的一次体现。
- **读带宽公式** $t = V/B$：70B 权重经 C2C 读一遍约 0.16 s，走 PCIe 要 1.1 s，差近 7 倍——带宽差距会线性放大成训练时间差距。
- **CUDA 统一虚拟寻址**：C2C 让「CPU 直接读写 GPU 显存」近乎零成本——异构程序天然「显存可溢出到 CPU 内存」，这是超级芯片对编程体验最实在的简化。

C2C 的「共享内存」还有一个常被忽略的软件含义：**NVIDIA 的 CUDA 统一虚拟寻址（UVM）与 Grace 的硬件一致性让「CPU 直接读写 GPU 显存」的代码几乎零成本**——程序员不必关心数据在哪块芯片上，写出来的异构程序天然「显存可溢出到 CPU 内存」。这是超级芯片对编程体验最实在的简化。
