## 为什么评估这么难

前七篇我们一路建智能体，但有一个问题一直被推迟：**怎么知道它真的行？** 对单次问答，答案是唯一的，对错一目了然；对智能体，任务的答案往往不是唯一的——「订一张合适的机票」没有标准答案，「整理一份报告」更是开放结局。加上任务的长程性（几十步动作）、环境的随机性（同样动作可能不同结果）、以及动作成本（每步都花 token 与时间），评估就变成一件需要专门设计的事。<span class="marginnote">这正是 Xi 等人综述 §6 的主题：智能体评估没有「唯一正确答案」可言，只能靠「环境 + 指标 + 归一化」三件套逼近。评估设计得不好，模型调得再准也是自我感动。</span>本节梳理基准的谱系与指标的设计逻辑，最后给出两个最容易踩的坑。

## 1 基准谱系：从单步到长程

把现有基准按「任务要智能体走多远」排成一条光谱：

| 基准 | 类型 | 典型任务 | 难度定位 |
| --- | --- | --- | --- |
| GSM8K | 数学推理 | 小学数学应用题 | 单步推理，无需外部动作 |
| MMLU / BBH | 通识推理 | 多选 / 难题 | 单步知识检索 |
| HumanEval / MBPP | 代码生成 | 补全函数 | 生成即评判，无环境 |
| ToolBench / API-Bank | 工具调用 | 多轮调 API 完成目标 | 多步动作 + 状态 |
| ALFWorld / WebShop | 决策交互 | 家居 / 网购 | 长程、稀疏反馈 |
| WebArena / SWE-bench | 真实环境 | 网页操作 / 修 GitHub bug | 开放、真实、难归因 |

读这张表的要领：**越往下的基准，越接近「智能体的真实考卷」**。推理类基准（GSM8K、MMLU）考察的是模型的「知识存量」，工具与决策类基准才考察「与环境交互的能力」——后者才是本专题定义的智能体。**AgentBench** 的出现是一个标志性事件：它把操作系统、数据库、知识图谱、网页购物等 8 个环境打包，统一衡量 LLM 的「代理能力」，试图回答「不同模型做真实任务谁更强」。

## 2 指标：怎么把「任务完成」量化

基准定好了任务，还要定「算不算完成」。主流的度量分三类：

**成功率（Success Rate, SR）**：完成任务的次数除以总次数。直观，但**二值化**——差一点和差十万八千里都算失败，不反映「接近程度」。
- **部分完成率 / 任务完成比例**：对可分步打分的任务（如网页操作做了 5 步中的 3 步），按完成比例给分，比 SR 更细腻。
- **pass@k / 经济性指标**：一次不行允许试 k 次；同时统计平均步数、平均 token 开销，衡量「聪明地完成」而非「蛮力地完成」。

评估还要回答「跟谁比」：**归一化与基线**。随机策略、贪婪策略、无推理的单轮模型，各自构成下限；人类专家构成上限。智能体的分数只有落在「明显高于无推理基线、且成本可控」的区间才有意义。<span class="marginnote">评估报告里的一个微妙点：智能体的得分必须伴随<strong>成本（步数、token、延迟）</strong>一起看——同一个 90% 成功率，用 3 步达到和用 30 步达到，含金量完全不同。</span>

## 3 公式解析：pass@k 的统计学

代码与数学基准常用 **pass@k**：生成 $n$ 个样本，其中 $c$ 个通过测试，问「最优的 $k$ 个里至少有一个通过」的概率。如果只把这 $c$ 个通过样本取出来直接算，会**高估**（因为 $n$ 有限、通过样本被挑着看了）。正确估计式（Chen 等人，Codex 论文）是：

$$
\mathrm{pass@k} \;=\; \mathbb{E}\!\left[\, 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}\,\right]
$$

四步拆解：

- **$n$ 与 $c$**：总共生成 $n$ 个候选解，其中 $c$ 个通过测试。$n$ 越大估计越准；$c=0$ 时 pass@k 恒为 0。
- **$\binom{n}{k}$**：从 $n$ 个候选中任取 $k$ 个的组合数——所有「选择 $k$ 个」的等可能情况总数。
- **$\binom{n-c}{k}$**：从**没通过的 $n-c$ 个**里取 $k$ 个的组合数——即「选的 $k$ 个全是坏的」的情况数。
- **整体含义**：分数 = 1 −「随机挑 $k$ 个却一个都没中」的概率。**$k$ 越大越容易碰对**（允许更多次重试），所以报告 pass@k 必须同时报告 $k$ 与成本——$k$ 从 1 涨到 100，分数的提升是以 100 倍生成成本换来的。

**为什么这个公式存在**：直接拿「$c$ 个通过的里面取 $k$ 个」算会低估失败率。正确式用组合数校正了「$n$ 有限」造成的偏差，让「生成 100 个、过 80 个」和「生成 10 个、过 8 个」在同一个尺度下比较。

## 4 易错点：基准会骗人

**辨析｜易错点：** 评估最大的敌人不是智能体笨，而是基准不可信。

- **训练集污染（contamination）**：基准题出现在模型的预训练数据里，等于**开卷考试**。GSM8K、HumanEval 都出现过被污染的报告，学界因此要求公开所用数据与消融。判据：模型分数对「见过/没见过」极端敏感，就是污染的征兆。
- **评估者偏差**：让 LLM 当评委打分开放任务时，评委可能偏好「话多」而非「正确」。对策是双盲、多次采样取平均、人工抽查一致性。
- **单一指标迷信**：只看 SR 会漏掉「步数爆炸、成本失控」的假赢家。好评估必须**指标 + 成本一起报**——这在第 2 节已强调，值得再重复一次：没有成本的成功率，是营销数字。

## 5 实战：一组评估数字的读法

把第 2、3 节的指标接到一张真实的评估表上，看怎么读。假设两个智能体在同一批任务上的结果：

| 指标 | 智能体 A | 智能体 B |
| --- | --- | --- |
| 成功率 SR | 90% | 88% |
| 平均步数 | 25 步 | 6 步 |
| 平均 token | 3.2 万 | 0.9 万 |

单看 SR，A 赢了。把成本列进来，结论反转：B 用约 1/4 的成本拿到几乎同样的成功率——**A 的成功率是拿 25 步的蛮力堆出来的**，放到真实部署里，A 的时延与账单会把它拖垮。这就是第 2 节「成本与成功率必须一起报」的实证。

再看 pass@k 的数字敏感性。设 n=10、c=3（生成 10 个样本，其中 3 个通过）：

```
pass@1 = 0.3
pass@5 = 1 - C(7,5) / C(10,5) = 1 - 21 / 252 ≈ 0.917
```

**一个反直觉的结论**：只生成 10 个样本、3 个通过，pass@5 却高达约 0.92——因为「5 个候选里至少有一个通过的组合」占绝大多数。这提醒读报告的人：**pass@k 与 pass@1 的差距，衡量的是「重试的性价比」，而不是模型本身的进步**。看到「pass@10 = 99%」的营销数字，第一反应该是：对应的 pass@1 是多少、每次重试花多少钱。

顺带澄清一个常见误解：pass@k 里的 k 与「允许试错次数」并不等价。工程上 pass@k 常常来自**同一次任务上采样的 k 个候选**，而不是「试 k 次、错了就换」。两者语义相近、实现不同——前者一次性并行，后者串行依赖前一次的结果。报告里写清楚这一点，能避免把「并行候选数」误读成「串行重试数」。

最后补一句关于「部分完成率」的细节：它看似比 SR 细腻，却引入了**打分的主观性**——「完成 3/5 步」的 0.6 分，究竟怎么定义才算合理？分步任务（如网页操作）容易打分，开放任务（如写报告）则很难。部分完成率适合「步骤可枚举」的场景，否则宁可用 SR 加成本，也别用一个拍脑袋的 0.6。

把「如何读一份评估报告」整理成一张检查清单：

| 检查项 | 看什么 | 防什么坑 |
| --- | --- | --- |
| 指标定义 | SR / 部分完成率 / pass@k | 口径不一致，不可横向比 |
| 成本列 | 步数、token、延迟 | 高成功率 + 高成本的假赢家 |
| 数据集来源 | 是否公开、是否可能被污染 | 训练集污染的开卷考试 |
| 评测者 | 规则还是 LLM 评委、是否双盲 | 评委偏好话多的偏差 |
| 基线 | 随机、无推理、人类三条线 | 没有参照系的自嗨分数 |

评估报告的正确打开方式是：**先看基线，再看成本，最后才看那个最醒目的成功率数字**。顺序反了，就容易被营销数字带跑。

## 6 术语速查

评估这一行黑话很多，收进一张速查表，日后查起来方便：

| 术语 | 含义 | 常见误读 |
| --- | --- | --- |
| SR（成功率） | 完成任务次数 ÷ 总次数 | 误以为反映「接近程度」，实际是二值判断 |
| pass@k | $k$ 个候选中至少一个通过的期望概率 | 误以为等于「串行试错次数」 |
| 部分完成率 | 分步任务的完成比例打分 | 打分依赖规则，否则主观 |
| 归一化 / 基线 | 与随机、无推理、人类三条线的相对比较 | 误以为只看绝对分数 |
| 成本曲线 | 步数、token、延迟随分数变化的曲线 | 只看成功率会漏掉成本爆炸 |

一句话记住评估的行业默契：**凡是没报成本的成功率，都要打个问号；凡是没报基线的分数，都没有参照系。**

## 7 小结

- 基准谱系从**单步推理（GSM8K）到长程决策（ALFWorld、WebArena、SWE-bench）**，越靠后越接近「智能体真实考卷」；AgentBench 是打包多环境的里程碑。
- 三类指标：**成功率 SR、部分完成率、pass@k + 经济性指标**。
- pass@k 的正确估计：$1 - \binom{n-c}{k} / \binom{n}{k}$，用组合数校正有限采样偏差；必须同时报告成本。
- 评估要讲**归一化与基线**：随机、无推理、人类三条参照线。
- 易错点：**训练集污染、评估者偏差、单一指标迷信**。

在下一节，我们手握架构、规划、工具、记忆、协作、评估的全套理论，是时候看它们在真实框架里的落地产物了——**AutoGPT 与 MetaGPT**，一个代表「单智能体自动循环」的野望，一个代表「多智能体流水线」的工程化。
