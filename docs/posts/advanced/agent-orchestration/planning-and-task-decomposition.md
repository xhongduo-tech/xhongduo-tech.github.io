## 为什么规划先讲

上一篇的架构图里，规划模块连接着记忆与行动：它负责回答「接下来做什么」。别小看这一步——让模型直接回答「怎么订一张从北京到上海的机票」这类开放问题，它通常会答得洋洋洒洒却一个动作都做不了。**规划的本质是把一个模糊的大目标，递归地翻译成一串可执行的小动作**。这也是「智能体看着聪明」与「智能体只会耍嘴皮」之间的分水岭。本节的脉络来自 Yao 等人的 ReAct 论文及其前后辈：思维链给了模型「自言自语」的能力，ReAct 再把「自言自语」与「动手做事」缝在一起。

## 1 从思维链到可执行计划

2022 年的**思维链（Chain-of-Thought, CoT）**证明了一件事：让模型在给出答案前先输出中间推理步骤，复杂问题的正确率大幅提升——不是模型变强了，而是推理路径被显式地放在了上下文里。<span class="marginnote">CoT 是提示工程的一课，也是智能体的前奏：它第一次把「推理轨迹」物化为文本。第三级《自然语言处理》里讲的 few-shot 范式，到智能体时代变成了「few-shot 推理示范」。</span>但 CoT 有个致命缺陷：它只产生文字，不产生动作。模型可以推理得头头是道，却无法把「搜索」这个动作真正发出去——推理与执行是断开的。

随后的**计划式提示（Plan-and-Solve）**让模型先输出「整体计划」，再逐条执行；**思维树（Tree-of-Thoughts, ToT）**则把推理当成搜索问题：每一步生成多个候选想法，用评估器打分，再探索最优分支。<span class="marginnote">ToT 把「推理」建模成树上的搜索：分支 = 多个候选，回溯 = 放弃走不通的路。它继承了搜索算法（如深度优先、广度优先）的骨架，只是「扩展节点」由 LLM 完成。</span>这些方法的共同进化方向是：推理越来越结构化，越来越贴近「先规划、后执行」的工程实践。

## 2 ReAct：思考与行动的交替循环

Yao 等人在 2022 年底提出的 **ReAct**（Reasoning + Acting）把「推理轨迹」与「可执行动作」放进同一条文本流，让模型在两者之间自由切换。一条 ReAct 轨迹长这样：

```
Thought 1: 我需要先确认「唐纳火腿」在哪家店有卖。
Action 1: search[唐纳火腿]
Observation 1: 搜到 3 家店，其中「老李食铺」有货。
Thought 2: 老李食铺有货，那就预定它。
Action 2: reserve_table[老李食铺, 2 人, 18:00]
Observation 2: 预定成功。
Answer: 已为您在老李食铺预定……
```

关键在交替本身：**Thought 决定下一步做什么，Action 把它发出去，Observation 把结果接回来，再触发下一个 Thought**。推理不是一次性写完的，而是随着环境反馈不断修正。这与人类做事的方式一致：先猜一步，做了再看结果，错了就改。实验里，ReAct 在需要多步查询的任务（HotPotQA、FEVER）上显著压过「只推理不动手」的 CoT 和「只动手不推理」的 Act 基线，原因是推理锚定了动作、动作校验了推理。

## 3 任务分解的两种范式

规划模块的具体实现方式，可以归成两条路线。

**自上而下（层级规划）**：先把大目标拆成子目标，再为每个子目标派子任务，甚至可以递归到第三层。优点是结构清晰、可审计；缺点是拆错了顶层就全盘皆错，且每层的代价随层数指数上升。AutoGPT、BabyAGI 这类早期框架走的就是这条路。

**交错式规划（ReAct 路线）**：不做全量预计划，而是「走一步看一步」——当前步的 Thought 只决定这一步。优点是灵活、能即时响应环境变化；缺点是可能短视，看不到十步之外的更优路径。<span class="marginnote">两种范式不是互斥的：主流实践是「先用计划式提示生成一个粗粒度计划，再在执行中逐段细化、随机应变」，相当于给交错式导航一个地图。</span>

分解的质量还取决于一个朴素的直觉：**子任务的粒度要恰好落在模型能直接执行的尺度上**。「写一个网站」太大了，要拆到「生成 index.html」「生成样式表」才可执行；而「调用 os.mkdir 前先检查目录是否存在」又太小，属于过度分解。

## 4 公式解析：ReAct 的单步生成

ReAct 本质上是一个带条件的状态机。把轨迹里的三种角色写成形式：

$$
\tau = \big(\mathrm{Thought}_1, \mathrm{Action}_1, \mathrm{Observation}_1, \; \ldots, \; \mathrm{Thought}_T, \mathrm{Action}_T\big)
$$

其中 $\tau$ 是完整轨迹，第 $t$ 步的生成概率为：

$$
\mathrm{Thought}_t,\ \mathrm{Action}_t \sim \pi_\theta\!\left(\cdot \mid \tau_{<t}\right), \qquad \mathrm{Observation}_t = \mathcal{E}(\mathrm{Action}_t)
$$

三步拆解：

- **轨迹 $\tau$ 的构成**：Thought（推理）与 Action（动作）由模型生成，Observation（观测）由环境 $\mathcal{E}$ 生成。三者按「想法—动作—结果」严格交替，这保证了推理与执行共享同一条上下文。
- **$(\mathrm{Thought}_t, \mathrm{Action}_t) \sim \pi_\theta(\cdot \mid \tau_{<t})$**：模型在已有轨迹的条件下，一起采样出「这一步的想法 + 这一步的动作」。通常用一段 prompt 约束输出格式（如以 `Thought:` / `Action:` 开头），动作还受白名单动作集约束。
- **$\mathrm{Observation}_t = \mathcal{E}(\mathrm{Action}_t)$**：观测不是模型编的，是环境真实返回的。这一条正是上一篇「接地（grounding）」的具体化——模型下一步的条件里混入了真实世界的信息，幻觉因此被框住。

**为什么「交替」能降低幻觉**：因为每一步动作都要被观测校验。模型如果说「我已经查过了」，但观测里根本没有搜索记录，后续推理就被迫承认事实不符——撒谎的成本变高了。

## 5 辨析：计划不等于执行

**辨析｜易错点：** 三个经典误区。

- **「我计划了」≠「我做了」**：只输出 `Thought: 我先搜索一下` 而不真正发起 `Action: search[...]`，是 CoT 的老毛病。ReAct 的纪律是：每条 Thought 之后必须跟一个可执行的动作，否则轨迹无效。
- **过度计划 vs 计划不足**：计划太粗，执行时每步都要现想，退化成交错式；计划太细，生成成本爆炸，且环境一变计划就全作废。健康的规划是「粗计划 + 细执行」。
- **把 ReAct 当成固定的 prompt**：ReAct 是一个循环协议，不是一段静态提示词。它的威力来自循环里的观测回写，少了环境反馈这一环，它退化成普通 CoT。

## 6 实战：一个目标的分解全过程

用「写一份养老行业调研报告」把两种分解范式都演一遍。

**先做自上而下的粗计划**，模型输出计划：

```
目标：写一份 3000 字的养老行业调研报告。
计划：
1. 调研行业现状（市场规模、政策、主要玩家）
2. 收集 3 个代表性案例
3. 组织成报告结构并撰写
4. 检查数据来源与表述
```

注意计划只到「能分配子任务的粒度」，具体怎么执行留给交错式。**执行时**，模型带着计划逐段推进：

```
Thought: 子任务 1 需要市场数据，先检索权威来源。
Action: search[养老产业 市场规模 2025]
Observation: 多家机构给出 5-10 万亿量级的不同口径……
Thought: 口径不一致，需交叉验证再采用。
Action: lookup[民政部 养老服务业 报告]
Observation: 官方口径，可作为主数据源。
```

这里能看到两种范式的合流：**粗计划提供地图，交错式应对岔路**。市场数据临时搜不到怎么办？模型不会死守原计划，而是调整子任务 1 的取材范围——计划修订，本身就是环境反馈驱动的又一轮规划。

把两种范式放在决策表里，选择依据一目了然：

| 场景 | 推荐范式 | 理由 |
| --- | --- | --- |
| 任务高度开放、步骤不定 | 交错式 | 灵活应对未知，避免计划作废 |
| 任务分块清晰、步骤固定 | 自上而下 | 结构可审计，失败可定位到块 |
| 长任务 + 中途反馈多 | 混合（粗计划 + 细执行） | 兼顾方向感与应变力 |
| 资源有限、只能跑一轮 | 自上而下 | 一次成型，不留试错空间 |

这个例子最值得带走的一条认知：**分解的产物不必是一次性的终极方案**。好的规划系统把计划当作「可修订的工作假设」，而不是「不可违抗的命令」——从 ReAct 到 AutoGPT，所有框架都默认遵守这条。

## 7 小结

- **规划 = 把大目标递归翻译成一串可执行动作**，是「会耍嘴皮」与「会干活」的分水岭。
- 进化路线：**CoT（只推理）→ Plan-and-Solve（先计划后执行）→ ToT（推理即搜索）→ ReAct（推理与执行交替）**。
- ReAct 轨迹 $(\mathrm{Thought}, \mathrm{Action}, \mathrm{Observation})^*$：想法与动作由模型生成，观测由环境生成，三者在同一条上下文里交替。
- 任务分解两种范式：**自上而下层级规划**与**交错式规划**，实践中常混合使用。
- 易错点：**计划 ≠ 执行**、过度/不足分解、把循环协议当静态提示词。
