## 为什么从 ReAct 开始

到目前为止，所有提示方法都在做同一件事：**让模型在它脑内的文本里把问题想清楚**。可模型脑内没有事实——维基百科、网页、数据库、真实环境，它一概接触不到。于是它只能靠记忆编造，一编造就幻觉。ReAct（Reasoning + Acting，Yao et al., ICLR 2023）走出了关键一步：让模型**边推理、边行动、边观察**——推理给行动方向，行动给推理事实，二者交叠成一个循环。这一设计后来成了几乎所有「智能体（agent）」架构的教科书范式。

## 1 循环：思考 → 行动 → 观察

ReAct 用 few-shot 示范教会模型一种**交错格式**，每一步交替出现三种元素：

- **思考（Thought）**：用自然语言说明「我目前知道什么、还缺什么、下一步该做什么」；
- **行动（Act）**：输出一个具体动作，例如调用搜索 API、执行计算、操作环境；
- **观察（Observation）**：把工具返回的结果作为新上下文接回模型。

模型就这样循环迭代，直到它认为证据足够，才输出最终答案。

一条真实的 ReAct 轨迹（HotpotQA，简化）长这样：

> Thought 1：我需要知道「《罗马假日》」的导演是谁。
> Act 1：搜索[罗马假日 导演]
> Observation 1：罗马假日（Roman Holiday），1953 年，导演威廉·惠勒。
> Thought 2：还需要确认女主演的名字。
> Act 2：搜索[罗马假日 主演]
> Observation 2：奥黛丽·赫本、格利高里·派克。
> Thought 3：两个信息都已拿到，可以回答。
> Answer：导演是威廉·惠勒，女主演是奥黛丽·赫本。

注意 Thought 并不是「正确答案」，而是「下一步行动的决策说明」——模型在每一轮只被要求回答「现在还缺什么、该查什么」，而不是一次性吐出答案。<span class="marginnote">这是 ReAct 与 CoT 最直观的差别：CoT 的每一步是「想」，ReAct 的每一步是「想 → 做 → 看」。前者只有内部文本，后者在每一轮都能拿到外部世界的真实反馈。</span>

![ReAct 循环：思考、行动、观察三个环节交替进行，直至给出最终答案](/images/prompt-engineering/react-cycle.svg)

这个循环的本质，是把语言模型从「只会续写的文本生成器」变成「一个会使用工具、能感知反馈的决策主体」。每一步行动都来自上一步的思考，每一步观察都回馈给下一步的思考——推理不再自说自话，而是被外部世界的反馈不断校正。<span class="marginnote">这一设计与第三级《人工智能导论》里的「感知—思考—行动」智能体环一脉相承，也让人想起强化学习里的「状态—动作—奖励」回路。ReAct 的贡献，是把这套经典框架用纯提示的方式装进了冻结的 LLM。</span>

## 2 从提示到工具：动作空间

ReAct 的「行动」落在哪，取决于任务给它开的动作空间：

**HotpotQA 多跳问答**：动作用一个维基百科搜索 API，模型可以「搜索某实体」「查看某段落」；
- **ALFWorld**：一个虚拟家庭环境的指令执行任务，动作用环境允许的操作指令（拿、放、打开等）；
- **WebShop**：模拟网购，模型在搜索、浏览、选择商品之间行动。

few-shot 示范按「Thought → Act → Observation」的格式给出若干轮，模型便学会了这个「打字节奏」。动作空间是封闭的、受限的——这正是后面讲安全时「最小权限」的雏形。

动作空间的封闭性是个被低估的设计点：任务只给模型一个搜索 API，模型就「只能搜索、不能删库」——提示里的动作空间，就是模型行为的上限。这与「最小权限」的原则同构：**给模型开多大的口子，模型被劫持时的破坏半径就有多大**。到安全那一节，这个点会从「工程便利」升格为「安全铁律」。

## 3 成绩与「诚实性」

ReAct 在四个基准上的结果（PaLM 540B）耐人寻味：

| 基准 | 指标 | ReAct |
| --- | --- | --- |
| HotpotQA | EM（500 个随机 dev 样本） | 29.4 |
| FEVER | EM | 62.2 |
| ALFWorld | 成功率 | 70.9 |
| WebShop | 成功率 | 40 |

最有意思的不是绝对分数，而是对比：**在 HotpotQA 上，纯 CoT 反而比 ReAct 高出约 2 分**。论文对此做了诚实归因：ReAct 会遭遇「搜索噪声」——检索到的页面不相关时，模型会被带偏（search-induced distraction）。但随后的错误分析揭示了 CoT 的代价：

- 在正确推理轨迹率上，ReAct 为 **94%**，CoT 只有 86%；
- CoT 的**幻觉率高达 56%**——纯脑内推理的模型，编造事实是常态而非例外。

于是正确的工程结论是：**ReAct 用「偶尔被搜索噪声带偏」换来了「大量减少编造」**，且两者可以组合——把 ReAct 与自洽性（CoT-SC 多路径投票）叠加得到最佳结果，微调后再上一层楼。<span class="marginnote">这条经验在当下依然成立：凡是要落地到「查资料、办事」的场景，RAG 或 ReAct 带来的「可核对」价值，远大于那一点点检索噪声的损失。可核对性，是生成系统的诚实底线。</span>

把「幻觉」与「搜索噪声」放在同一天平上称一称：CoT 有 56% 的轨迹含编造事实，ReAct 的「搜索噪声」即便发生，也只是把模型带向一个「可被下一轮观察纠正」的偏差。前者是系统性错误，后者是偶发性偏差——工程上这两者的性质完全不同，也是为什么「宁要可核对、不要流利」逐渐成为落地共识。

## 4 公式解析：行动循环的迭代方程

把整个循环压缩成三行递推式。设 $h_t$ 为截至第 $t$ 步的完整对话历史，$a_{t+1}$ 为模型下一步的动作，$o_{t+1}$ 为环境对该动作的反馈：

$$
a_{t+1} = \pi\bigl(h_t\bigr), \qquad o_{t+1} = \operatorname{Env}(a_{t+1}), \qquad h_{t+1} = h_t \cup \{a_{t+1}, o_{t+1}\}
$$

- **第一步，看策略 $\pi$**：$\pi$ 就是「带 ReAct 提示的 LLM」。它读入历史 $h_t$（包括之前的思考、行动、观察），输出下一步动作。提示在这里扮演的角色，是规定 $\pi$ 的输出**格式**（先 Thought 后 Act），而不是规定它干什么——干什么由历史与工具反馈决定。
- **第二步，看环境 $\operatorname{Env}$**：环境是不可微的、模型之外的黑盒（搜索 API、模拟器、真实系统）。动作 $a_{t+1}$ 进入环境，返回观察 $o_{t+1}$——这一步**不在模型内部完成**，这正是 ReAct 与纯推理方法的根本分野。
- **第三步，看历史增长**：$h_{t+1}$ 不断把新动作与新观察追加进上下文。历史越长，模型「记得」的事实越多，但也越占上下文窗口——所以工程上常要做截断或摘要。

由这三行式可以读出 ReAct 的一切性质：推理（$\pi$ 的内部生成 Thought）、行动（输出 $a_{t+1}$）、记忆（$h_t$ 增长）、以及**迭代终止条件**——当 $\pi$ 认为证据充分时，输出格式切换为「最终答案」，循环结束。

上下文增长可以套一个数字：每轮「思考 + 行动 + 观察」大约消耗 150—400 token，一个 10 轮的任务会让上下文净增几千 token。这在长任务里很快逼近窗口上限，于是工程上常见两种对策——**截断**（只保留最近几轮）与**摘要**（把早期轮次压缩成一句状态描述），两者都在「保留关键事实」与「控制长度」之间做取舍，这也直接决定了后续智能体系统的记忆设计。

## 5 辨析｜ReAct vs CoT vs 只行动（Act-only）

三种范式各缺一样东西：

| 范式 | 有推理 | 接触外部 | 致命弱点 |
| --- | --- | --- | --- |
| CoT | 有 | 无 | 幻觉、无事实核对 |
| 只行动（Act-only） | 无 | 有 | 乱走、无规划（如早期 WebGPT 式行为） |
| **ReAct** | 有 | 有 | 搜索噪声、延迟、上下文占用量 |

**辨析｜易错点：** 推理与行动不是「二选一」，而是互为前提。没有行动的推理是闭门造车（CoT 的幻觉）；没有推理的行动是横冲直撞（Act-only 缺乏方向感）。ReAct 用「Thought 决定 Act、Observation 修正 Thought」把两者焊死在一个循环里。

## 6 术语速查表

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 思考 | Thought | 用自然语言说明当前已知与下一步计划 |
| 行动 | Act | 调用工具的具体动作（搜索、计算、操作） |
| 观察 | Observation | 工具返回的结果，接回上下文 |
| 动作空间 | action space | 任务允许模型调用的工具集合 |
| 搜索噪声 | search-induced distraction | 检索到不相关页面把推理带偏的现象 |
| 多跳问答 | multi-hop QA | 需要多步检索才能回答的问题 |
| 可核对性 | verifiability | 回答可被外部证据回溯检查的性质 |

## 7 小结

- **ReAct** 让模型在「思考 → 行动 → 观察」之间循环，用外部工具的真实反馈给推理兜底。
- 行动空间是任务给的封闭 API（维基搜索、环境指令、网购），few-shot 示范教会模型交错格式。
- HotpotQA 上 CoT 略胜约 2 分，但 ReAct 的正确推理轨迹率 94% vs 86%，且 CoT 幻觉率高达 56%——**用可核对性换掉幻觉，是更划算的买卖**。
- 迭代方程 $a_{t+1}=\pi(h_t),\; o_{t+1}=\operatorname{Env}(a_{t+1}),\; h_{t+1}=h_t\cup\{a_{t+1},o_{t+1}\}$ 概括了推理、行动、记忆与终止条件。
- ReAct 开启了「智能体」范式，与自洽性、微调组合使用效果最佳。
- 动作空间就是行为上限：封闭的工具集合天然是「最小权限」的雏形，也决定了被劫持时的破坏半径。

在下一节，我们暂时放下「模型怎么想、怎么动」，转过头来研究提示的**形式**：怎么设计一套稳定可复用的提示模板，以及为什么让模型「扮演」一个角色，会显著改变它的输出——这就是**提示模板与角色扮演**。
