## 为什么从提示优化开始

前面所有方法都默认一个前提：提示是**人**写出来的。可手工调提示像在黑暗里摸钥匙——一句「让我们一步一步地想」可能是神器，也可能是废柴，全靠试。提示优化要回答的是：**能不能让机器自己找出更好的提示？** 答案是能，而且有两代思路——AutoPrompt 用**梯度**在白盒模型里搜离散触发器（Shin et al., EMNLP 2020），OPRO 用**大模型自己当优化器**在黑盒 API 上迭代搜索指令（Yang et al., ICLR 2024）。<span class="marginnote">注意克努特的这句名言放在这里别有意味：它本意是劝人别过早手工微调代码——用在提示工程上恰成反讽：既然手工「优化」提示既不可复现又耗人力，不如把优化自动化。</span>

## 1 AutoPrompt：用梯度搜索离散触发器

AutoPrompt 的设定与前面完全不同：它针对的是**掩码语言模型（MLM）**，把任务改写成「完形填空」：

> 电影评论文本 + [T][T][T] 触发器 + 情感标签

模板里有固定的触发器槽位 $[T]$ 和一个 $[\text{MASK}]$。例如一条正面影评会变成：

> a real joy. atmosphere slot dialogue Clone totally [MASK].

训练的目标，是找出一组共享的触发器 token，让 $[\text{MASK}]$ 处的预测以最高概率指向正确的情感类标签。方法叫**梯度引导搜索**：对每个触发器位置，把该位置的嵌入扰动一点，用损失对嵌入的梯度估算「换成哪个 token 收益最大」：

$$
V_{\text{cand}} = \operatorname{Top}\text{-}k\Bigl( (w_{\text{in}})^{\mathsf{T}} \, \nabla_{\mathbf{e}} \log p\bigl(y \mid x_{\text{prompt}}\bigr) \Bigr)
$$

对候选集中的每个 token 做一次前向，取 loss 最低者替换，逐位迭代——本质是**离散空间里的爬山**。<span class="marginnote">这条式子里最妙的是「用梯度在离散 token 上搜」：MLM 的 token 嵌入是连续向量，梯度 $(\nabla_{\mathbf e}\log p)$ 指向「把该位置的嵌入往哪个方向挪，目标概率涨得最快」，再把它投影回词表，取方向最一致的 top-k 个词。把连续梯度翻译回离散选择，是 AutoPrompt 的核心洞见。</span>

由于类别不是单个词，AutoPrompt 还引入**标签 token 边缘化**：类别 $y$ 的概率等于该类别下所有标签词的概率之和，$p(y\mid x)=\sum_{w \in V_y} p([\text{MASK}]=w \mid x)$。效果如何？SST-2 情感分析上，手工提示的 BERT 只有 63.2% 正确率，AutoPrompt 搜出的提示把它提到 80.9%（dev）/ 82.3%（test）；RoBERTa 从 85.3% 提到 91.2% / 91.4%，全程**不做任何微调**；在 LAMA 事实检索上，AutoPrompt 的 P@1 达到 43.3%，远超最佳手工单提示的 34.1%。

## 2 OPRO：让大模型当优化器

AutoPrompt 需要白盒梯度与掩码模型，而现实世界到处都是黑盒 API。OPRO（Optimization by PROmpting）换了一个更狂野的思路：**让大模型自己设计提示**。

做法是把「优化」本身描述成一个提示任务。每次迭代，构造一个**元提示（meta-prompt）**，包含四部分：

1. 优化问题的自然语言描述（目标、约束）；
2. 该任务的一小组示例；
3. 历史优化轨迹——之前试过的所有提示及其得分，从低到高排列；
4. 要求：「参考上面的轨迹，生成一个新的、更好的提示。」

然后让优化器 LLM 读元提示、输出若干候选指令，用打分模型在评估集上跑出准确率，回写进轨迹，再进入下一轮。

GSM8K 上，OPRO 搜出的最优指令把准确率做到 80.2%（用 PaLM 2-L-IT 当优化器），**比人类设计的零样本提示高出最多 8 个百分点**；它最著名的产物是一句话：「Take a deep breath and work on this problem step-by-step」（深呼吸，然后一步一步地解这道题）。在 Big-Bench Hard 上，OPRO 的指令比人类设计高出最多 50%。<span class="marginnote">「深呼吸」这句咒语常被当作段子传播，但它揭示了一个严肃事实：大模型对某些措辞的敏感度远超直觉，而手工调参几乎不可能穷举到这类表达——这正是自动化搜索的价值。</span>

## 3 公式解析：两代搜索的更新规则

把两代方法各自的「更新规则」摆在一起，差异一目了然。AutoPrompt 是逐 token 的梯度爬山：

$$
x_{t+1} = \operatorname{Replace}\Bigl( x_t, \;\arg\min_{w \in V_{\text{cand}}} \mathcal{L}\bigl(p(\cdot \mid x_t[w])\bigr) \Bigr)
$$

每一步只替换一个触发器 token，候选来自梯度排名；它需要**白盒**（能算梯度）与**掩码模型**（有固定 $[\text{MASK}]$ 接口）。

OPRO 是整条指令的生成式更新：

$$
x_{t+1} = \operatorname{LLM}_{\text{opt}}\bigl( \text{任务描述}, \; \text{示例}, \; \text{轨迹}_t \bigr), \qquad \text{轨迹}_{t+1} = \text{轨迹}_t \cup \{(x_{t+1},\; \text{Score}(x_{t+1}))\}
$$

- **第一步，看 $V_{\text{cand}}$ 与轨迹**：AutoPrompt 的候选来自「词表的 top-k」，OPRO 的候选来自「优化器 LLM 的自由生成」——搜索空间一个在词级别，一个在句子级别。
- **第二步，看 $\mathcal{L}$ 与 Score**：AutoPrompt 每步要前向算 loss（细粒度、代价高）；OPRO 每轮在完整评估集上打分（粗粒度、但也更接近真实指标）。
- **第三步，看信息的来源**：AutoPrompt 的信息来自梯度（模型内部结构），OPRO 的信息来自「历史指令—得分对」（纯黑盒反馈）。后者与任何 API 兼容，因此落地更广。

## 4 辨析与局限

**辨析｜易错点：** 自动搜索找到的「最优提示」只是**针对特定打分模型与特定任务的局部最优**，不是普适咒语。「深呼吸」这句指令是为「PaLM 2-L 打分 + GSM8K」这一组合搜出来的，换一个模型或换一个基准，胜出的措辞就完全不同——它并不具有跨场景的魔力。这提醒我们两点：

1. **评估成本不可忽视**：每次迭代都要跑评估集，搜索几轮下来，token 账单与算力开销相当可观；
2. **自动化不替代理解**：搜索负责在给定搜索空间里找局部最优，而「用什么任务公式化、用什么评估、约束什么」仍是人的判断——搜索空间的设计者永远是人。

**辨析｜易错点（AutoPrompt 的边界）：** AutoPrompt 针对的是掩码模型的「触发词」搜索，它找到的触发器往往是不像自然语言的词（如「Clone」「totally」），可读性差、迁移性弱；而 OPRO 找到的是完整可读的指令，可读、可迁移到同类任务。选择哪一代方法，取决于你手里是白盒模型还是黑盒 API。

## 5 小结

- **提示优化**让机器替人找提示：AutoPrompt 用梯度搜离散触发器，OPRO 让 LLM 自己迭代生成指令。
- AutoPrompt 的更新规则是「逐 token 梯度爬山」：用 $\nabla_{\mathbf e}\log p$ 挑 top-k 候选再前向筛选；SST-2 上把 BERT 从手工提示的 63.2% 提到 80.9%，全程不微调。
- OPRO 的更新规则是「生成式 + 轨迹回写」：元提示含任务描述与历史指令—得分对，迭代产出新指令；GSM8K 上最高比人工提示高 8 个百分点，代表作是「深呼吸」指令。
- 白盒梯度 vs 黑盒迭代、词级 vs 句级、内部结构信息 vs 外部打分反馈——两代方法的分野清晰。
- **搜索到的提示只是针对特定模型与任务的局部最优**：会过期、会失效，搜索空间的设计仍是人的责任。

在下一节，我们从「怎么写出好提示」走向工程最硬核的一面：让模型的输出**严格符合 JSON/XML 格式**，把它变成可被程序安全消费的数据——这就是**结构化输出提示**。
