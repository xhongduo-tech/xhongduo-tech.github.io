## 为什么从提示模板开始

前面几节我们研究的是「让模型怎么想」——推理、搜索、投票。这一节转向「提示本身长什么样」：如何把一段提示组织成**稳定可复用的模板**，以及为什么在模板里让模型「扮演」一个角色，会显著改变它的输出风格与质量。这是把提示从「手写一次性的文本」升级为「生产级可维护的接口」的关键一步（对标 Jurafsky & Martin, SLP3 §13.5）。

## 1 提示的结构：系统 / 用户 / 助手

现代对话式 API 把上下文划分为三种消息，这是模板的结构骨架：

- **系统消息（system message）**：给模型立规矩——它是谁、任务是什么、输出格式是什么、有什么边界。它对用户不可见，通常由开发者控制；
- **用户消息（user message）**：真实用户或调用方输入的待处理内容；
- **助手消息（assistant message）**：模型的历史回复，以及 few-shot 示范（把「预期回复」写成 assistant 消息，是最规范的 few-shot 写法）。

**提示模板（prompt template）**：一段带占位符的固定文本骨架，运行时把「当前输入」填进占位符。例如：

```
你是专业的数学老师。请一步一步解答下列题目，只输出最终答案。
题目：{question}
```

模板的价值在于**复用**：同样的任务，不管用户输入怎么变，任务描述、格式约束、角色设定都保持一致——稳定性是生产环境的第一要求。<span class="marginnote">这就像编程里把重复逻辑抽成函数：提示模板是把「任务定义」与「具体数据」分离的工程手段。分离得越干净，越容易维护、测试与迁移。</span>

同一个模板换上不同角色，就是不同的「产品」。把上一节的模板改一行，数学老师变成审校员：

```
你是专业的英文审校。请检查下列句子的语法与拼写，只输出修订后的句子。
原文：{text}
```

模板的「变」与「不变」要分清：占位符 {question}、{text} 是变的部分，角色、任务、格式声明是不变的部分。**不变的部分才是模板的资产**——它们沉淀了你对任务的全部理解，也是 few-shot 之外最值得版本管理的东西。<span class="marginnote">工程上常把模板放进独立的配置文件或模板库，与代码分离管理：提示的演进速度比代码快得多，把两者耦合会拖慢迭代。</span>

## 2 角色扮演：为什么一句「你是谁」管用

**角色扮演（role-playing / persona prompting）**：在提示中给模型指定一个身份，让它以该身份的口吻与知识范围作答。例如：

> 你是一位有 20 年经验的儿科医生。请用通俗的话向家长解释疫苗接种。

一个朴素的疑问是：模型又不是真的医生，这有什么意义？答案藏在条件概率里。模型输出的是 $P(y \mid x)$——它的「知识」其实是一整套按文本分布组织起来的**续写习惯**。「扮演医生」这句话，把条件分布整体偏移到了「医学语料」所在的那片高概率区域，于是模型更可能用医学的口吻、医学的术语、医学的谨慎来续写。<span class="marginnote">角色的本质是「分布偏置」：它不改权重，只是把采样引向语料中某一类文本的风格与知识簇。这与第二级《概率论》里的「条件分布」概念一一对应——给定「角色」这个条件，输出的分布就变了。</span>

角色扮演在实践中至少有三个可观测的收益：

1. **风格一致性**：律师、医生、客服，各自的措辞与详略完全不同；
2. **格式约束**：「你是一名严谨的审计员，请输出结构化清单」——角色自带格式倾向；
3. **边界约束**：「你是心理咨询师，不提供法律建议」——角色附带的行为边界，比直接命令「不要回答法律问题」更自然。

同一个事实，不同角色说出的话完全不同，这是检验「角色是否生效」最直观的实验。以「建议多喝水」为例：

| 角色 | 输出风格 |
| --- | --- |
| 医生 | 每天饮水量建议 1500—2000 ml，少量多次，观察尿液颜色 |
| 健身教练 | 训练前后补水，每 15 分钟 200 ml，别等渴了再喝 |
| 客服 | 感谢您的咨询，请留意不要饮用生水，如有不适请及时就医 |

三种回答的信息各有侧重，语气与详略天差地别——模型的「知识」其实高度重叠，真正改变的是**条件分布被角色带向哪片语料**。

## 3 提示模板的七要素清单

一个生产级模板，建议按以下清单逐项自查：

| 要素 | 要做什么 | 常见反例 |
| --- | --- | --- |
| 角色 | 一句话定义身份与立场 | 角色缺失，输出风格漂移 |
| 任务 | 用祈使动词说清「做什么」 | 任务含糊，模型自由发挥 |
| 输入 | 用占位符/分隔符隔离待处理数据 | 数据与指令混排，互相污染 |
| 输出格式 | 声明格式（JSON、列表、段落） | 不提格式，输出不可解析 |
| 约束 | 明确边界（不要什么、多长、给不给理由） | 无约束，模型啰嗦或越界 |
| 示例 | 给 1—3 个精确示范 | 无示例，格式跑偏 |
| 歧义处理 | 预判「输入不合法时怎么办」 | 无兜底，异常输入导致崩溃 |

**辨析｜易错点：** 负面指令（「不要……」「不要……」）并非越多越好。模型对「不要 X」的理解有偏差，一串否定句反而挤占了正面指令的空间。更稳健的写法是**正面描述期望行为**：「请用不超过三句话总结，不要提及价格」可以改写为「请用三句话内总结重点，价格相关信息忽略」。

用七个要素把同一个「摘要任务」写成两条模板，一好一坏，直观感受差距：

```
坏模板：把下面的文章总结一下。{article}

好模板：你是一位资深编辑。请把下面的文章压缩成 3 条要点，每条不超过 20 字，
按重要性排序，不要给出评论。{article}
```

好模板集齐了角色（资深编辑）、任务（压缩成要点）、输入（占位符）、格式（3 条、每条 20 字）、约束（按重要性、不评论）五层；「坏模板」只有任务一层，模型每回输出的结构都可能不同。

## 4 公式解析：从离散模板到连续提示

提示模板的一切技巧都建立在「文本」上——离散的 token。但在 2021 年前后，研究界发现更激进的一招：**不写文本，而是直接训练一组连续向量（软提示）拼在输入前面**。这就是**前缀调优（prefix tuning）**与 P-tuning 的思路（Li & Liang, 2021）。设软提示为连续向量 $\theta_p$，主模型参数 $\Theta$ 冻结，优化目标是

$$
\max_{\theta_p} \; \log P\bigl(y \mid [\theta_p;\, x];\, \Theta\bigr)
$$

- **第一步，看 $[\theta_p; x]$**：软提示 $\theta_p$ 是一组可学习的连续向量，与真实文本嵌入拼在一起，作为模型的新前缀。它不像模板那样是「可读的话」，而是一串纯数字向量。
- **第二步，看「冻结 $\Theta$」**：主模型参数 $\Theta$ 全程不动，只有 $\theta_p$ 通过反向传播被更新——所以每个任务只需存一小段向量，极其轻量。
- **第三步，看与角色扮演的关系**：角色扮演是**离散**的分布偏置（用一句话把模型推向某类语料风格），软提示是**连续**的分布偏置（用梯度把前缀优化成最能引出目标行为的表示）。同一个思想的两端：一个靠人写，一个靠梯度学。

**辨析｜易错点：** 离散提示（模板、角色）可读、可移植、零训练成本，但表达力受限于「能找到那句话」；连续提示表达力更强、更省 token，但不可读、不可迁移、需要训练。工程上两者并非对立：模板负责「任务与格式」，软提示负责「再压榨几个点性能」，可叠加使用。

离散与连续两条路线最终可以收进一张对照表：

| 维度 | 离散提示（模板/角色） | 连续提示（软提示） |
| --- | --- | --- |
| 形态 | 可读文本 | 连续向量 |
| 训练 | 无需 | 需少量数据反向传播 |
| 可读性 | 好 | 差（不可解释） |
| 迁移性 | 好（跨任务复用） | 差（绑任务） |
| token 开销 | 高 | 低 |
| 适用 | 生产模板、角色设定 | 性能极致压榨 |

工程上最常见的组合拳是「模板保底 + 软提示提分」：先用离散模板把任务与格式钉住，再用一段软前缀把最后几个点的精度榨出来。

## 5 小结

- 模板的三层骨架：**系统消息立规矩、用户消息装数据、助手消息放示范**。
- **提示模板**把「任务定义」与「具体数据」分离，是生产环境稳定性的第一道保障。
- **角色扮演**的本质是条件分布偏置：一句「你是谁」，把输出推向语料中对应身份的风格与知识簇。
- 模板自查七要素：角色、任务、输入、输出格式、约束、示例、歧义处理。
- 软提示把「分布偏置」从离散文本扩展到连续向量：$[\theta_p; x]$ 拼进输入、主模型冻结、只优化前缀。
- 模板里「不变的部分」才是资产；工程上模板与代码分离管理，便于随提示演进迭代。

在下一节，我们把「写提示」这件事本身交给机器：不再靠人手搜词句，而是用梯度或大模型自动搜索更优的提示——这就是**提示优化与自动提示搜索（AutoPrompt / OPRO）**。
