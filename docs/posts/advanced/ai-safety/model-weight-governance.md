## 为什么从权重治理开始

上一节的算力治理管「训练」，但**训练完之后呢？** 一个模型训练好，开发者面临一个岔路口：**把权重「开源发布」（开放），还是「封闭保留」（通过 API 访问）？** 这个选择——**模型权重的开放与封闭**——是当前 AI 治理最激烈、最分裂的争论之一。开放派说「开源促进安全（可审计、可研究）」；封闭派说「开源放大风险（不可控、不可撤回）」。<span class="marginnote">「权重」是模型的核心资产——一组决定「模型会做什么」的数值。<strong>权重一旦公开发布，就像「信息」一样「永不删除」：任何拿到权重的人都能部署它、修改它、绕开它的安全限制</strong>。这就是「开放 vs 封闭」争论的根源——权重是「可无限复制的数字产品」，发布即「不可撤回」。</span>

这一节把两派的论证都讲清楚，并给出一个更精细的框架：**「开放」不是一个开关，而是一个光谱**。

## 1 开放权重（Open Weights）的论证：透明度即安全

**开放权重**：把模型的权重参数公开发布（如 Llama、Mistral、DeepSeek 的开放模型），任何人可以下载、部署、微调。

**开放派的安全论证**：

- **可审计性**：安全需要「检查」——开放权重让研究者能「真正看穿」模型（第 4 章机制可解释性需要权重）；封闭模型只能「黑盒测试」，无法「白盒审计」——**「能审计」是「能保证安全」的前提**。
- **可研究性**：大量对齐研究（第 2-4 章）依赖「访问权重」；封闭模型限制了「独立研究」——**安全研究需要开放**。
- **「更多人检查 = 更快发现问题」**：开源的「许多眼睛」能更快发现漏洞（安全领域的「林纳斯定律」：足够多的人看，bug 就无所遁形）。
- **去中心化的韧性**：开放权重让「能力」不被少数公司垄断——「防止权力集中于少数主体」本身是一种治理价值。<span class="marginnote">开放派最强的主张是「<strong>安全依赖独立审计，而审计依赖访问权</strong>」——如果只有开发公司能「看」自己的模型，外部安全研究者只能「猜」。这让人想起「加密算法必须公开接受同行评审」的密码学传统——「靠保密的算法不安全，靠公开的算法才安全」。</span>

**开放派的局限**：开源论证假设「公开」能让「好人」审查并「修复」；但对「恶意使用者」，开放权重意味着「免于任何监管地使用」——「审查」能发现问题，「发布后无法撤回」的问题却无人能解。

## 2 封闭权重（Closed Weights）的论证：控制即安全

**封闭权重**：模型权重不公开，用户通过「API」访问——公司控制「谁能用、怎么用、能不能绕过安全限制」。

**封闭派的安全论证**：

- **可撤回性**：发现模型「有危险能力」时，封闭模型可以「撤回、打补丁、下架」；开放权重「发布即失控」——**「能撤回」是「纠错」的前提**。<span class="marginnote">「不可撤回性」是封闭派的核心论据：<strong>权重一旦公开，等于「不可收回的能力扩散」——任何后来发现的风险，都无法通过「收回模型」来缓解</strong>。相比之下，API 可以「随时停止服务」。这对应第 16 章「失控风险」：开放权重把「未来的风险」永久化。</span>
- **可过滤性**：API 可以让提供者「在输入端过滤」危险请求、「在输出端拦截」危险内容（第 17 章护栏）；开放模型「谁拿到谁用，没有中间层」。
- **可问责性**：API 的使用有「记录、账户、责任」——出了问题「找得到人」；开放权重的使用「匿名、无痕」。
- **可限制的能力**：公司可以「刻意不发布某些能力」——封闭模型可以「能力裁剪」（弱化危险能力）；开放权重「能力全开」。

**封闭派的局限**：封闭意味着「少数公司掌握全部判断权」——「公司安全」与「社会安全」可能不一致；且「封闭」本身阻碍了「独立审计」（开放派的核心论点）。**「封闭」用「集中」换「控制」，代价是「失去外部的眼睛」**。

## 3 公式解析：「开放度」光谱与治理阶梯

「开放 vs 封闭」是「二分」，但现实的治理需要更细的粒度。研究者提出了「**开放度光谱（spectrum of openness）**」——从「完全封闭」到「完全开放」之间存在多个层级，每级对应不同的「治理要求」：

$$
\text{Openness} \in \{ \underbrace{\text{完全封闭}}_{\text{仅 API}} ,\; \underbrace{\text{受限 API}}_{\text{分级访问}} ,\; \underbrace{\text{受控权重}}_{\text{审批下载}} ,\; \underbrace{\text{开放权重}}_{\text{自由下载}} ,\; \underbrace{\text{开放权重+开放数据}}_{\text{全开放}} \}
$$

**治理阶梯（governance ladder）**：开放度越高，治理越难，所以需要「越前置的治理」：

- **完全封闭（仅 API）**：提供者承担全部治理（内容过滤、账户、监测）——「治理集中在服务层」。
- **受限 API / 结构化访问（第 47 篇）**：按「用途、身份、能力」分级开放——「治理集中在访问层」。
- **受控权重（审批下载）**：发布权重但「需要审批、实名」——「治理前移到分发层」。
- **开放权重**：权重自由下载——「治理失效」于「分发之后」，只能靠「训练时治理」（算力治理）+「事后法律追责」。

**关键结论**：**「开放度」不是「要不要开放」的简单选择题，而是一个「开放度越高，越需要在『训练与分发』阶段就把治理做足」的权衡**。<span class="marginnote">这条「开放度-治理」的配比关系，是权重治理的总纲：<strong>如果你要「全开放」，就得在「训练前」把安全做足（因为发布后无法补救）；如果你「封闭」，可以把治理放在「服务时」</strong>——「开放度」决定「治理的时机与位置」。这也解释了为什么「开放权重模型」的安全争论，最终会落到「训练时要不要加算力阈值」「发布前要不要做危险能力评估」（第 12 章）上。</span>

## 4 现实的争议：前沿模型的「开源止损」

对「前沿模型」（能力接近 AGI 级别），开放 vs 封闭的争论更加尖锐：

- **「开源止损」论点**：当模型能力达到「危险线」，开放权重意味着「任何人都能微调掉安全限制」——**开源 = 永久性能力扩散**。这是 Anthropic、OpenAI 等对「前沿模型开源」持谨慎态度的核心理由。
- **「开源安全」论点**：即便前沿模型，开放也能让「独立研究者」提前发现危险能力——「封闭公司的安全判断」不如「开放社区的集体检查」可靠。
- **动态平衡的现实**：业界当前的做法是「**分级开放**」——小模型开源（风险可控）、前沿模型封闭（风险高需控制）；或「**时间延迟开源**」（先封闭发布，成熟后再考虑开源）。<span class="marginnote">「分级开放」是当前工业界的务实解：<strong>「风险与开放度匹配」——低能力模型承担得起开放的治理代价，高能力模型则优先「控制」</strong>。但「分级」的边界（能力多强才算「该封闭」）没有共识，这正是第 14 章「国际标准」要解决的分歧之一。</span>

**辨析｜易错点：** 「开源」≠「免费可用」。开源模型可以「免费下载」，但「开源协议」可以附带「使用条款」（如禁止滥用、禁止二次发布）——**「开源」是「权重可见」，不必然等于「无任何限制」**。现实中有「开放权重但协议受限」的中间态（如 Llama 的社区许可）。

## 5 拓展：「开源 vs 封闭」的实证与「开放度」的评估

「开放 vs 封闭」的争论不能只停在「哲学论证」——它需要「实证」与「评估方法」来支撑。这一节补两块：实证证据与「开放度评估」。

### 实证证据：开源模型的「安全记录」

- **「越狱更容易」的证据**：研究反复表明「开源模型比封闭模型更容易被越狱」——因为「攻击者可以微调掉安全限制」「可以白盒研究弱点」。
- **「微调攻击」**：对开源权重，攻击者可以「微调」去掉「安全对齐」——「开源权重的安全是可被移除的」。
- **「但开源也有安全贡献」**：开源的「透明」让「独立安全研究」得以进行——「黑盒 API」研究受限。

**实证的「综合结论」**：开源「放大滥用风险」与「增强安全研究」同时为真——**「开源的风险」是「真实」的，「开源的价值」也是「真实」的**——争论的实质是「怎么权衡」。

### 开放度评估：「开放」不是一个开关

「开放」是「多维度」的，评估「开放度」要看多个轴：

| 维度 | 全封闭 | 全开放 |
| --- | --- | --- |
| 权重可访问性 | 仅 API | 自由下载 |
| 使用条款 | 受限 | 几乎无限制 |
| 微调权限 | 禁止 | 允许 |
| 二次分发 | 禁止 | 允许 |
| 数据透明度 | 不公开 | 全公开 |

**「开放度评估」的意义**：把「开放 vs 封闭」的「二元争论」转成「多维度的精确描述」——「这个模型开放了多少、在哪几个维度上开放」——比「开源/闭源」的「标签」更准确。

### 「开放度」与「风险」的匹配

「开放度评估」最终要服务「风险决策」：

- **低能力模型**：可以「高开放度」——「滥用风险低，开放收益大」。
- **高能力模型**：倾向「低开放度」——「滥用风险高，需要控制」。
- **「能力阈值」**：在「能力到达某水平」后，「开放度」应「随能力下降」——「能力-开放度」的「权衡曲线」。

**辨析｜易错点：** 不要把「开源」与「透明」划等号。**「开源权重」≠「开源数据」≠「开源训练细节」**——一个模型可以「权重开放」但「数据、训练过程、安全评估不透明」。「开放」是「多维的」，不能「一刀切」地称为「透明」或「不透明」。

## 6 小结

- **权重治理**：模型核心资产（权重）「开放 vs 封闭」的选择——「权重是可无限复制的信息，发布即不可撤回」是争论根源。
- **开放派**：可审计、可研究、多眼睛检查、去中心化韧性——「安全依赖独立审计」。
- **封闭派**：可撤回、可过滤、可问责、可限制能力——「发布即失控」是核心论据。
- **开放度光谱**：完全封闭 → 受限 API → 受控权重 → 开放权重 → 全开放——**开放度越高，治理越要在「训练与分发阶段」前置做足**。
- 现实路径：**分级开放**（低风险开源、前沿封闭）——「风险与开放度匹配」是当前的务实平衡。
