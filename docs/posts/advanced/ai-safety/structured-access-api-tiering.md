## 为什么从结构化访问开始

上一节的「开放度光谱」里，中间那一档最精细、也最值得单独研究：**结构化访问（structured access）**——模型权重不公开，但通过「受控的接口（API）」提供访问，并在访问中嵌入「安全治理」。它是「封闭」与「开放」的中间道路：**既要「可控」（不发布权重），又要「可用」（开放能力）**。<span class="marginnote">结构化访问的哲学是「<strong>把治理从『拥有权』转移到『访问权』</strong>」：不纠结「谁能拥有权重」，而精细设计「谁能以什么条件访问模型能力」——就像「图书馆提供阅读但不让带走书」「实验室提供使用但不让带走样本」。治理对象从「拷贝」变成了「会话」。</span>

这一节讲结构化访问的机制、它怎么「分级开放」，以及它的局限。

## 1 结构化访问：治理「使用权」而非「所有权」

**结构化访问（structured access）** 的核心思想：**开发者保留权重的「所有权」，但通过精心设计的「访问接口」，把「使用方式」置于治理之下**。用户不「拥有」模型，只「获得访问」——于是开发者在「每次会话」里都能施加控制。

与传统「下载权重」相比，结构化访问的治理优势：

**可撤回**：任何会话都能「随时终止」——危险使用可以被「立即掐断」（封闭派的优势）。
**可过滤**：每次请求/响应都过「安全层」——输入过滤、输出审查、内容监控（第 17 章护栏的天然落点）。
**可追踪**：每个访问者「可识别」（API 账户、身份）——责任可归因。
**可限制**：可以「按会话/按用途」限制能力——同一个模型，对不同用户「能力裁剪」不同（「分级开放」的落点）。<span class="marginnote">结构化访问把「开放 vs 封闭」的二元争论，转化成了「访问条件怎么设计」的工程问题：<strong>不再问「开不开放」，而问「开放给谁、开放多少、以什么协议开放」</strong>——这让治理粒度从「模型的发布决策」细化到「每个会话的访问决策」。</span>

**结构化访问的代价**：它放弃了「开放权重」的「可审计性」——外部研究者「看不到权重」，只能「黑盒测试」。**「可控」与「可审计」在结构化访问里难以兼得**——这是它一直被开放派批评的软肋。

## 2 API 分级开放：同一模型，不同权限

**API 分级开放（tiered API access）** 是结构化访问最常见的实现：**同一个模型，对不同类型的用户、不同用途，开放不同级别的能力**。分级维度包括：

**按身份分级**：个人用户 vs 企业用户 vs 研究机构 vs 政府——不同身份获得不同权限（研究机构获得「高能力 + 强监管」，普通用户获得「受限能力」）。
**按用途分级**：用途决定能力范围——「写作助手」账户不能用「代码执行」功能；「医疗咨询」服务不能用「高风险建议」能力。
**按能力分级**：模型能力可以「分级裁剪」——给低风险用户「弱化版」（如限制推理深度、限制工具调用），给受信任用户「完整版」。<span class="marginnote">「能力分级」是 API 分级最精细的一档：<strong>同一个权重，通过「系统提示 + 功能开关 + 输出约束」，对不同的用户呈现「不同能力上限」</strong>——就像「同一本工具书，对不同读者翻开不同的章节」。这避免了「一开放全开放、一封闭全封闭」的粗糙。</span>
- **按信任分级**：基于「用户的可信度」（身份验证、历史记录）动态调整访问权限——「新用户受限，长期可信用户升级」。

**分级开放的设计原则**：

- **「最低权限」原则**（第 20 篇的延伸）：给用户「完成任务所需的最低能力」——不多给。
- **「能力与风险匹配」**：能力越强的访问档位，审核越严、追踪越紧。
- **「动态调整」**：基于「使用行为」调整档位——「异常使用」降级，「可信使用」升级。

## 3 公式解析：分级开放的「能力-信任」矩阵

API 分级开放可以用一个「能力 × 信任」矩阵来形式化。设「模型能力档位」为 $c \in \{c_1, c_2, \dots, c_K\}$（从低到高），「用户信任档位」为 $t \in \{t_1, t_2, \dots, t_M\}$（从低到高）。访问决策是「一个映射」：

$$
\text{Access}(u, \text{task}) = c^* = \max\Big\{ c_k \;:\; \text{Risk}(c_k, \text{task}) \le \text{Budget}(t_u) \Big\}
$$

- **$\text{Risk}(c_k, \text{task})$：能力档位 × 任务的风险**——「高能力 + 高风险任务」风险最高。
- **$\text{Budget}(t_u)$：用户信任档位对应的「风险预算」**——高信任用户「预算大」，可获得更高能力。
- **决策逻辑**：给用户「风险不超过其信任预算」的最高能力档位——「信任越高、任务越安全，能力给得越足」。

**这条矩阵的含义**：分级开放不是「一刀切给个版本」，而是「对每个（用户, 任务）组合，动态决定开放多少」——**「开放」被精细化到「会话粒度」**。<span class="marginnote">这个「能力-信任」矩阵呼应了「最小权限」的工程化：<strong>结构化访问把「最小权限」从「静态的权限设置」变成「动态的访问决策」</strong>——每一次访问，都重新评估「该给多少能力」。这是「纵深防御」（第 21 篇）在「访问层」的实现。</span>

## 4 结构化访问的边界与争议

**「控制幻觉」**：结构化访问给的「控制」可能是「表面」的——用户可以通过「越狱」（第 7 章）、「提示注入」（第 8 章）绕过「API 的安全层」；「过滤器不是防火墙」。**「访问控制」不能替代「模型本身的安全」**。
**「可审计性」的缺失**：开放派持续批评——「黑盒的 API」让「独立研究」无法进行；「封闭访问」让「安全发现」只能依赖「公司自证」。
**「能力分级」的可绕过性**：「低能力档位」可能被「提示技巧」解锁（「能力泄露」）——分级不是「物理隔离」，是「软约束」。
**权力集中**：结构化访问把「判断权」集中在「API 提供者」手里——「谁该被信任、哪个任务危险」由少数公司决定——「治理权集中」本身是治理问题。<span class="marginnote">「权力集中」是结构化访问最难解的治理难题：<strong>「让提供者控制访问」解决了「安全」，却制造了「权力不对称」——提供者既是「运动员」（开发模型）又是「裁判」（决定谁能用）</strong>。平衡「安全控制」与「权力制衡」，需要「外部监督」（政府、审计、用户代表）参与「访问决策」——这正是第 14 章治理框架的落点。</span>

**辨析｜易错点：** 结构化访问 ≠ 「封闭模型」。封闭模型是「不开放」，结构化访问是「有控制地开放」——它「开放能力」但「控制访问方式」。**「API 访问」就是「结构化访问」的典型形态**——今天绝大多数商业大模型（ChatGPT、Claude 等）都通过 API 提供，本质上都是「结构化访问」。**「结构化访问」不是少数公司的特殊做法，而是当前主流大模型的默认形态**。

## 5 拓展：结构化访问的「实践形态」与「治理争议」

第 47 篇讲了结构化访问的「原理」——但「现实里长什么样」「有什么治理争议」需要「补全」。这两块让「结构化访问」从「概念」落到「现实」。

### 实践形态：结构化访问的现实案例

- **「API 分级定价」**：商业 API 的「不同档位」——「免费档（低能力/低速率）」「专业档（高能力）」——「能力分级」的「商业实现」。
- **「企业级审核」**：企业 API 的「合规审核」——「实名认证 + 用途审核 + 协议约束」——「访问前」的「治理」。
- **「研究访问」**：给「研究机构」的「特殊访问」——「白盒或半白盒」——「受控的可审计性」。
- **「政府/关键基础设施」**：给「高风险领域」的「受限访问」——「能力裁剪 + 强监管」。

### 「能力裁剪」的技术实现

「分级开放」依赖「能力裁剪」——技术上怎么实现「同一权重、不同能力」：

- **「系统提示约束」**：不同档位用「不同的系统提示」——「限制能力范围」（最常用，但「可被越狱绕过」）。
- **「功能开关」**：在「架构层」关闭某些「功能模块」（工具调用、代码执行）——「物理级」裁剪，更可靠。
- **「输出过滤」**：对不同档位用「不同的输出过滤器」——「能力」与「过滤」组合。

**「能力裁剪」的可靠度排序**：「功能开关 > 系统提示」——「物理不存在」的接口比「提示禁止」可靠（第 21 篇）。

### 治理争议：结构化访问的「权力」问题

结构化访问「集中治理权」，引发「治理争议」：

- **「谁决定谁能用」**：API 提供者「决定谁能访问」——「访问权」成为「治理权」——「谁掌握访问权，谁决定谁用得上 AI」。
- **「平台中立性」**：提供者可能「基于商业利益」而非「安全」决定「访问」——「安全的借口」与「商业的动机」难分。
- **「审查与寒蝉」**：结构化访问可能「压制正当使用」——「担心被拒」让研究者「不敢研究敏感话题」——「安全」与「自由」的张力。

### 结构化访问的「监管方向」

对「结构化访问」的「监管」正在形成：

- **「访问的透明度」**：要求提供者「公开访问政策」——「为什么拒绝谁」要「可解释」。
- **「申诉机制」**：被拒的「正当用户」要有「申诉渠道」——「拒绝」要「可复核」。
- **「外部制衡」**：「访问决策」不能「完全由公司垄断」——「政府/第三方」参与「监督」。

**辨析｜易错点：** 不要把「结构化访问」当成「『既安全又开放』的免费午餐」。**结构化访问在『控制』上强于『开放』、在『透明』上弱于『开放』**——它「牺牲了『可审计性』（开放派的立场）」换取「可控性（封闭派的立场）」。「结构化访问」是「权衡的中间点」，不是「没有代价的最优解」。

## 6 小结

- **结构化访问**：不发布权重、通过受控接口开放能力——把治理从「所有权」转移到「访问权」。
- 优势：**可撤回、可过滤、可追踪、可限制**；代价：**失去开放权重的可审计性**。
- **API 分级开放**：按身份、用途、能力、信任分级——同一模型对不同用户开放不同能力档位。
- 「能力-信任」矩阵：给用户「风险不超其信任预算」的最高能力档——「开放」精细化到「会话粒度」。
- 边界：控制可能是「表面」的（越狱可绕过）、可审计性缺失、能力分级可被解锁、权力集中——需外部制衡。
