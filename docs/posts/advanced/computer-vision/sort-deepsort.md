## 为什么从多目标跟踪开始

前几节的 Kalman、粒子滤波都是**单目标**跟踪：预先知道跟踪谁，一路跟下去。但真实场景（行人计数、自动驾驶、体育分析）里是**多个目标同时出现**，而且目标数量、目标身份都在变。多目标跟踪（MOT，Multi-Object Tracking）面对的是一个更本质的问题：**给定每帧的检测框，怎么把它们串成"谁是谁"的轨迹？**

2016 年，Bewley 等人提出的 **SORT（Simple Online and Realtime Tracking）**给出了一个极简而惊人的答案：**只用检测 + Kalman 预测 + 匈牙利匹配（IoU 关联），就能达到接近当时最先进水平的跟踪精度，而且实时**。2017 年的 **Deep SORT** 给它加了一个**外观特征（deep appearance descriptor）**，大幅减少 ID 切换。SORT/Deep SORT 是 MOT 的黄金基线，理解它就读懂了多目标跟踪的全部核心模块。<span class="marginnote">多目标跟踪的独特难点不是"跟"而是"关联（data association）"：这一帧这个框，是上一帧的哪个目标？目标靠近、交叉、遮挡时，关联一旦出错，两个目标的"身份"就互换了（ID switch）。MOT 的评估指标（MOTA、IDF1、IDs）几乎全在惩罚关联错误——因为它才是 MOT 的真正难点。</span>

## 1 检测跟踪范式：tracking-by-detection

现代 MOT 的主流范式是 **tracking-by-detection**：

1. **检测（detection）**：每帧用目标检测器（YOLO、Faster R-CNN）找出所有目标框。
2. **关联（association）**：把当前帧的检测框与已有轨迹（tracklet）匹配。
3. **状态更新**：匹配上的轨迹用 Kalman 更新；没匹配上的检测框**新建轨迹**；没匹配上的轨迹**进入待删除**（可能丢失/出画面）。

**关键洞察：跟踪的质量上限由检测器决定**——检测漏了，跟踪就断；检测错了，跟踪就串。所以"检测跟踪"的名字很诚实：检测是主角，跟踪是"把检测连成线"的后处理。

SORT 就是这套范式的最简实现：检测器给框，Kalman 给运动预测，匈牙利算法给匹配，三步走完。

## 2 SORT：Kalman + IoU 匈牙利匹配

SORT 的核心步骤：

1. **状态**：每个轨迹用 Kalman 跟踪，状态是检测框的几何量 $(u, v, s, r)$（中心坐标、尺度、长宽比），运动模型是**恒定速度**（位置随速度线性演化）。
2. **预测**：Kalman 预测每个轨迹在当前帧的位置。
3. **关联**：把预测框与当前帧检测框做**IoU 代价矩阵**，用**匈牙利算法**求全局最优匹配。**IoU 高 → 代价小 → 倾向匹配**。
4. **规则**：
   - IoU 低于阈值（如 0.3）的匹配**拒绝**（框对得太差不算关联）。
   - 未匹配的检测 → **新建轨迹**。
   - 未匹配的轨迹 → 连续 $A_{\max}$（如 1~3）帧没匹配就删除（目标可能遮挡或出画面）。

**匈牙利算法（Hungarian algorithm）**在一句话里是：**求"一组一对一的匹配，使总代价最小"的多项式时间算法**——它是关联问题的核心引擎，MOT 之外在调度、指派问题上也到处出现。<span class="marginnote">为什么关联用"全局最优"的匈牙利而不是"贪心"？贪心匹配"每个检测找最近轨迹"，两个检测抢同一轨迹时先到先得，会制造不必要的 ID 切换。匈牙利算法同时考虑所有候选对，保证总代价最小——全局优化在这里真的比局部贪心更稳。SORT 里这个"全局匹配"替换，是它比早期贪心 MOT 好的关键之一。</span>

## 3 SORT 的缺陷：遮挡与 ID 切换

SORT 用纯几何（IoU + 运动）关联，问题也出在这：

- **目标密集交叉时**：两个行人靠近、交错，Kalman 预测的框重叠，IoU 关联会**把轨迹 A 的框配给目标 B**——ID 切换。
- **遮挡恢复后**：遮挡期间 Kalman 预测继续飘，恢复后 IoU 关联不上，轨迹被删除，目标被当作**新目标**重新建档——ID 丢失。
- **重识别能力为零**：SORT 不"认识"目标的长相，只认位置。

一句话：**SORT 有"跟踪"（Kalman）与"关联"（IoU），但没有"身份的外观记忆"**——它在短暂遮挡与密集交叉时保不住身份。

## 4 Deep SORT：外观特征融入关联

**Deep SORT** 的改进只有一处但至关重要：**给每个检测框算一个"外观特征"（appearance embedding），把外观相似度与 IoU 一起放进关联代价**。

1. **外观特征**：用一个小 CNN（在 ReID 数据集上训练的余弦度量学习网络）把每个检测框编码成一个 128 维向量。
2. **级联匹配（cascaded matching）**：**优先给"近期出现过"的轨迹匹配**（防止长时未更新的轨迹抢走新检测），再逐步放宽。
3. **代价融合**：匹配代价 = 马氏距离（运动）与余弦距离（外观）的加权组合：

$$
c(i,j) = \lambda \, d^{(1)}(i,j) + (1-\lambda)\, d^{(2)}(i,j)
$$

其中 $d^{(1)}$ 是 Kalman 预测与检测的马氏距离，$d^{(2)}$ 是外观向量的余弦距离。

**外观特征的加入让"被挡了几秒的目标"仍能被认回来**——因为它的长相特征还在轨迹的记忆里。这是 Deep SORT 相比 SORT 把 ID 切换率大幅压低的原因。

**辨析｜易错点：** Deep SORT 的外观网络是**离线训练、在线使用**的——它不在跟踪时学习，而是预先在行人重识别（ReID）数据上练好。训练数据与场景不匹配时（卡车、无人机视角），外观特征失效，Deep SORT 退化回 SORT。**"特征好不好"决定了关联的上限。**

## 5 公式解析：级联匹配为何优先"年轻的轨迹"

**为什么 Deep SORT 要"级联"而不是一次性全局匹配？** 从匹配的动力学看。

- **第一步，全局匹配的问题**：一次性把所有轨迹与所有检测做全局最优匹配，代价小的优先配对。但**长时未更新的轨迹**（被挡了 30 帧）Kalman 预测已严重漂移，其马氏距离大——它既抢不到新检测，又占着匹配的名额。
- **第二步，级联的动机**：先匹配"最近刚更新"（年轻）的轨迹——它们预测准、外观新，应当优先；再匹配"越来越老"的轨迹。**把"确定性高"的匹配先做掉，把不确定性留到最后**，减少误配。
- **第三步，代价结构**：$c = \lambda d^{(1)} + (1-\lambda)d^{(2)}$ 是运动与外观的**线性加权**；$d^{(2)}$ 还常与"轨迹外观特征的历史均值"比较（轨迹记录每帧的外观，取均值为其"长相"）。
- **第四步，为什么有效**：级联匹配 + 外观代价，本质是把"位置预测"（短期、几何）与"长相记忆"（长期、外观）两个信号**分层次**使用——短期信号快但漂移，长期信号慢但可靠。

**一句话：Deep SORT 用"级联 + 外观"把关联从"纯几何贪心"升级为"分层的运动-外观联合决策"，换来更稳的身份保持。**

## 6 MOT 的评估与现代演进

MOT 的评估指标：

- **MOTA（多目标跟踪准确度）**：综合漏检、误检、ID 切换的单一分数。
- **IDF1 / ID switch 次数**：专门衡量"身份保持"——IDF1 越高、IDs 越少，关联越好。
- **MOTP（跟踪精度）**：框对齐的精确程度（与身份无关）。

SORT/Deep SORT 之后，MOT 的演进主线：**关联学习化**（如 Tracktor 用检测器回归直接做跟踪）、**端到端 MOT**（JDE、FairMOT 把检测与 ReID 并到一个网络）、**Transformer 跟踪**（MOTR 用集合预测做轨迹）。但**"检测 + Kalman + 关联"的骨架在几乎所有实时系统里依然存在**——SORT 的简洁性让它至今是工程基线。<span class="marginnote">把 MOT 与视觉 Transformer 联系一下：MOTR 把每个轨迹当"一个查询（query）"，用 Transformer 的集合预测同时输出检测与轨迹关联——它把"手工关联"整个换成了"学习式集合匹配"。但评估它是否进步，看的还是 MOTA、IDF1——<strong>目标函数没变，变的只是求解工具</strong>。这是计算机视觉技术演进的普遍模式：任务定义稳定，实现工具换代。</span>

## 7 多目标跟踪的评测与现代演进

MOT 的评测与演进，是理解"跟踪任务价值"的关键：

**评测指标（MOT Challenge 标准）**：

- **MOTA（准确度）**：漏检 + 误检 + ID 切换综合——"**综合跟踪质量**"。
- **IDF1（身份保持）**：轨迹身份正确率——"**ID 不换的比例**"。
- **IDs（ID switch 次数）**：轨迹身份被错误切换的次数——"**身份稳定性的直接度量**"。
- **MOTP（定位精度）**：框的对齐精度——"位置准不准"。
- **数据集**：MOT17（行人）、MOT20（密集人群）、DanceTrack（运动相似外观）——"难度逐级上升"。

**现代演进**：

- **端到端 MOT**：JDE、FairMOT——**"检测与 ReID 特征一个网络"**（省掉两阶段的特征分离）。
- **Transformer MOT**：MOTR——"**查询做检测 + 轨迹关联**"（把跟踪变成集合预测）。
- **跟踪与分割统一**：跟踪 + 分割（视频实例分割）——"从框跟踪到掩码跟踪"。
- **多模态 MOT**：RGB + 红外/深度/点云融合——"跨模态的鲁棒跟踪"。

**MOT 的挑战与本质**：MOT 的核心矛盾是"**精度 vs 实时 vs 密集鲁棒**"——检测器越准 MOT 越好（跟踪是检测的下游）；密集场景（MOT20）的"遮挡 + 相似外观"是最大挑战。**"MOT 的上限由检测决定，下限由关联决定"**——这是理解 MOT 的钥匙。

**MOT 与全书主线**：它是"检测 + 运动建模 + 关联"的集成——**"检测给候选、Kalman 给预测、匈牙利给匹配"**（SORT 的三段式）。MOT 也是通往"视频理解"的桥梁（跟踪给轨迹、轨迹给行为）——**"跟踪不是终点，是视频理解的入口"**。

## 8 小结

- **MOT** 的核心是**关联**：把每帧检测框串成轨迹，难点在密集、遮挡、ID 切换。
- **SORT** = 检测 + Kalman 预测 + **IoU 匈牙利匹配**：极简、实时，但无外观记忆，遮挡即丢身份。
- **Deep SORT** 加**外观特征 + 级联匹配**：外观认回遮挡目标，级联优先"年轻"轨迹，ID 切换大幅下降。
- 关联代价 = 运动（马氏）+ 外观（余弦）加权；外观网络离线训练。
- 评估：**MOTA / IDF1 / IDs**；现代 MOT 把关联学习化，但检测-跟踪骨架不变。
