## 为什么从路由策略对比讲起

前几节我们默认「路由 = 可学习门控 + top-k」，仿佛这是唯一的答案。但路由其实是一个**设计空间**：要不要学习？学的话学什么（打分还是直接选）？选几个？要不要噪声？要不要随机性？Shazeer 2017 的论文之所以叫「Outrageously Large」，不仅因为模型大，还因为它**第一次系统对比了多种门控策略**，用实验说明了「稀疏学习门控」为什么胜过其他候选。<span class="marginnote">把路由策略摆成一排对比，是理解「为什么 MoE 长成今天这个样子」最直接的方法。每一条被否掉的路线，都藏着一条重要的权衡；而幸存下来的那条，成了现代大模型的默认项。</span>

这一节把主流路由策略放进同一张坐标系：**谁来决定去哪个专家（学习 or 固定）、决定得有多「硬」（概率 or 硬选）、如何保持探索与均衡**。再给出一个统一直觉：所有策略都是在「算力、质量、负载」三个目标的 Pareto 前沿上选点。

## 1 路由策略的三条设计轴

任何路由策略都可以用三个问题归类：

1. **是否学习**：路由规则是手工固定（哈希），还是由梯度学习（门控网络）？
2. **决策软硬**：专家是全参与（软加权）、还是只算少数（硬 top-k）？
3. **探索机制**：有没有噪声/随机性来打破正反馈、帮助负载均衡？

沿着这三条轴，主流策略排成一张光谱：

| 策略 | 学习? | 软/硬 | 探索 | 代表工作 |
| --- | --- | --- | --- | --- |
| 哈希路由（hash） | 否 | 硬 | 无 | 早期 MoE，FasterMoE 等 |
| 稠密软混合 | 是 | 软（全算） | 无 | Jacobs 1991 |
| top-k 稀疏门控（无噪声） | 是 | 硬 | 无 | Shazeer 消融 |
| top-k 稀疏门控 + 噪声 | 是 | 硬 | 有（高斯噪声） | Shazeer 2017 主力 |
| top-1 + aux loss | 是 | 硬 | 弱（靠正则） | Switch 2022 |
| top-2 + 随机第二专家 | 是 | 硬 | 有（随机抽样） | GShard 2020 |
| sigmoid top-k | 是 | 硬 | 弱（独立打分） | DeepSeek-MoE 2024 |

## 2 哈希路由：不学习的下限

最朴素的路由是**哈希路由（hash routing）**：对 token 的特征（或 token id）做哈希，取模得到目标专家——完全不需要学习，也没有门控参数。它有两个致命缺点：

**哈希随机 ≠ 语义相关**：语义相近的 token 可能被哈希到不同专家，专家之间没有「分工」，纯粹是随机切块——等于把一个大 FFN 打散，几乎没有专家化收益。
- **负载不可控**：哈希的均匀性只对「足够多的 token」成立，小 batch 或高频 token 会造成明显偏斜，专家利用率方差大。

哈希唯一的优点是**零学习成本、零路由开销**。它在「模型极小、不想训练路由器」的场景还有一席之地，但一旦模型够大，学一个路由器花的钱完全值得——Shazeer 的实验给出了这个结论的定量证据。

## 3 Shazeer 的门控消融：学习、稀疏与噪声的逐项贡献

Shazeer 2017 在 LSTM + MoE 上做了门控的**逐项消融（ablation）**，拆出三个变量的贡献：

- **学习 vs 哈希**：学习门控远胜哈希——这是压倒性的，也是 MoE 现代形态的定音锤。理由就是上一节说的：只有学习，专家才能「为特定语义专门化」。
- **稀疏 vs 稠密**：纯稠密软混合（所有专家加权求和）在参数量相同下打不过稀疏——因为稀疏在相同 FLOPs 下能放更多专家。**注意比较口径**：同 FLOPs 时稀疏赢；同参数量且 FLOPs 无约束时，稠密也未必输。<span class="marginnote">「比什么」决定「谁赢」。这是路由对比里最容易混淆的点——论文里不写清比较口径，结论就失去意义。后文《MoE 训练稳定性》里 Switch 的「固定 FLOPs 赛制」也是同一种纪律。</span>
- **噪声 vs 无噪声**：加噪声的稀疏门控比不加噪声的稳定且略好——噪声的探索价值在「负载均衡」和「跳出正反馈」上兑现，这是它存在的全部理由。

## 4 公式解析：不同策略的参数量与计算量

把各策略的「代价账本」写成一个统一点：

$$\mathrm{Params} = E \cdot P_{\mathrm{expert}} + P_{\mathrm{router}}, \qquad
\mathrm{FLOPs/token} \approx k \cdot \mathrm{FLOPs}_{\mathrm{expert}} + \mathrm{FLOPs}_{\mathrm{router}}$$

- **$\mathrm{Params}$**：参数随专家数 $E$ 线性增长（$P_{\mathrm{router}}$ 通常可以忽略）。哈希路由 $P_{\mathrm{router}} = 0$，学习门控则有 $P_{\mathrm{router}} \approx dE$。
- **$\mathrm{FLOPs/token}$**：单 token 算力随「实际激活的专家数 $k$」线性增长——稠密软混合 $k = E$（全算），top-1 $k = 1$（最省），top-2 $k = 2$。**专家 FFN 成本 $\mathrm{FLOPs}_{\mathrm{expert}}$ 相同，区别只在乘了多少个。**
- **平衡点**：同样预算下，$k$ 越小 → 能放的 $E$ 越大 → 参数量越大 → 容量越大。**这就是「稀疏换容量」的精确会计。**

代入一个具体例子：设 $E = 64$、每个专家 FFN 约 $4d^2$ 乘加。稠密软混合每 token 要 $64 \cdot 4d^2$；top-1 只要 $1 \cdot 4d^2$——**64 倍的算力差距**，换来的是「省下的算力可以再雇 63 个专家」。这个数字把「为什么 top-1 比 top-2 更有吸引力」量化到了极致。

## 5 现代路由的「收敛」：为什么最终都长一个样

看今天的 DeepSeek-V2、Mixtral、Switch，路由策略惊人地趋同，几乎都是：

- 可学习的**内积打分**（$u_t^T e_i$）或线性打分；
- **sigmoid/softmax 归一化**后取 top-k（$K \in \{1, 2, 6\}$）；
- 一组**辅助损失**（aux loss、z-loss）维持均衡与稳定；
- 偶发**探索机制**（训练早期噪声或随机抽样）。

它们之间的差异大多是「参数」而非「范式」：$K$ 取几、分数用 sigmoid 还是 softmax、aux loss 系数多大。这背后是同一组权衡在起作用——**学习给容量、稀疏给效率、正则给稳定**——这三件事的 Pareto 前沿上，目前所有主流模型都落在了几乎同一个角落。<span class="marginnote">一个值得思考的开放问题：路由真的需要「学习」吗？像 BASE Layers（2021）用线性规划直接优化路由、Mixture-of-Depths 让「算多少层」也可学习——它们都想证明「不学或换个学法也行」。这提醒我们：路由策略的收敛是「当前算力与网络环境下的局部最优」，不是终极答案。</span>

### 一个具体例子：哈希 vs 学习门控的差距在哪

用一句话对比哈希与学习门控的「分工能力」。设语料里高频出现「（」与「）」这对结构词：

- **哈希路由**：把 token 的哈希值取模分专家，`（` 和 `）` 大概率被分到**不同的**专家——它们之间没有「因为语义相近所以共享专家」的任何保证，专家划分是「随机切块」；
- **学习门控**：路由器会学到「括号类 token 倾向于同一个专家」，因为把这类高频 token 集中到一个专家，能最大化该专家对「括号语境」的适配——**专家化（specialization）正是学习的产物**。

这个例子揭示了对比的本质：**哈希是「均匀但无意义」的划分，学习是「不均匀但有分工」的划分**。MoE 的全部价值都在「分工」上——所以「要不要学路由器」这一票，现代模型几乎毫无悬念地投给了学习。

### 路由对比之外：两个「反学习」实验

「学习门控必胜」并非铁律，两个有影响力的反例值得记住：

- **BASE Layers（2021）**：不用可微门控，而是把「路由」写成**线性规划（LP）**——直接优化「哪些 token 去哪个专家、每个专家最多收多少」的整数分配问题，目标函数仍是主任务。它证明了「负载均衡 + 路由分配」可以当作**显式的优化问题**解，而不必靠梯度学习。
- **Mixture-of-Depths（2024）**：把「算不算某一层」也变成可学习的路由——token 在**层**的维度上被稀疏化，每层只处理部分 token。它把 MoE 的「专家稀疏」扩展成「深度稀疏」，说明「稀疏在哪」本身就是一个可设计空间。

这两个反例提醒我们：**路由策略的收敛不是终点**。「学习 + top-k + 正则」只是当前算力环境下的局部最优——当通信、显存、训练目标变化时，路由策略完全可能改道。这正是《MoE 推理部署》里「以系统需求反推路由设计」的思路来源。

### 软混合在什么场景仍有价值

稠密软混合（所有专家加权求和）并非一无是处，它有两个不可替代的场景：

- **小模型 / 推理成本不敏感**：当模型小、专家少、硬件算力有富余时，软混合省去了「稀疏导致的负载、通信、稳定性」一堆麻烦，还保留了「所有专家参与」的表达，实现最简单；
- **与稀疏混合的「两段式」**：有些系统先做一层稀疏挑选、再做一次软混合微调，把「容量」与「平滑度」都拿到。

所以对「稠密 vs 稀疏」的正确态度不是「稀疏必胜」，而是：**稀疏解决的是「参数量大但算力有限」的问题；没有这个约束，稠密反而更省事**。判断要不要稀疏，先问自己的约束是参数还是算力——这也是第三级《深度学习》里「容量 vs 效率」权衡在 MoE 语境下的具体化。

### 一句话总结

路由策略对比的结论浓缩成一句：**谁来决定、决定多硬、如何探索——三个问题的答案共同决定了 MoE 是「省钱的技巧」还是「更强的架构」**。

## 6 小结

- **三条设计轴**：学习/固定、软/硬、探索/正则——所有路由策略都是在这三条轴上取点。
- **哈希路由**：零学习成本，但语义无关、负载难控，只在小模型有存在意义。
- **Shazeer 消融结论**：学习 > 哈希；稀疏（同 FLOPs）> 稠密；噪声 > 无噪声。
- **会计等式**：参数 $\propto E$、算力 $\propto k$、$k$ 越小能放的 $E$ 越大——稀疏换容量的数学本质。
- **现代收敛**：主流模型路由趋同为「内积打分 + top-k + 辅助损失」，差异只是参数；但「学路由」本身仍有被挑战的空间。
