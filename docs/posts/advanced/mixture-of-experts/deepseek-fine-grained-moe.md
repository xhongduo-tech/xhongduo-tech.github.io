## 为什么从细粒度专家讲起

到了 2024 年，MoE 的骨架已经定型：一堆专家 + top-k 路由 + 辅助损失。DeepSeek-MoE（Dai et al., 2024）在这个框架里做了一件看似朴素却影响深远的事：**把专家切得更碎**。它不是把 8 个大专家换成 8 个更大的专家，而是把 FFN 的中间维度拆成 N 个小段，每段独立成一个专家——于是路由的组合数爆炸式增长，模型在几乎不增加计算量的前提下，容量与泛化都显著提升。<span class="marginnote">「细粒度」（fine-grained）在这里是字面意义的：DeepSeek-MoE 把每个专家 FFN 的中间维度切成 N 个「小 FFN」，专家数量从 8 个量级涨到 64+ 个量级。组合数不是 $N$ 倍，而是「$\binom{N}{K}$ 量级」——这是容量增长的本质来源。</span>

这一节我们回答：细粒度切分为什么有效、激活组合数如何暴涨、以及 DeepSeek-MoE 如何与上一节的共享专家、sigmoid 路由协同，成为一个完整的防退化 + 提效方案。

## 1 细粒度切分：把一个 FFN 拆成一排「小专家」

先回顾一个稠密 Transformer 的 FFN：中间层把 $d$ 维扩张到 $d_{ff}$（通常 $d_{ff} = 4d$），再做非线性。DeepSeek-MoE 的做法是：**把 $d_{ff}$ 均匀切成 $N$ 段**，每段配一个独立的权重矩阵，于是得到 $N$ 个小专家 FFN；每个 token 路由激活其中的 $K$ 个（$N = 64$、$K = 6$）。<span class="marginnote">对比 GShard/Switch：它们每个专家是一个「完整 FFN」（$d \to d_{ff} \to d$），专家数 8~2048；DeepSeek-MoE 每个专家是「FFN 的 1/N 段」，专家数 64+。同样是「FFN 被路由拆开」，切分粒度从「按层」变成了「按段」。</span>

为什么要切这么细？作者给出的核心论证是 **专家组合的多样性**：

- 粗粒度下，一个 token 只能选「几大块」之一，表达空间由「块内是什么」决定；
- 细粒度下，$N$ 个小专家可以拼出 $\binom{N}{K}$ 种组合，token 之间的「分工」可以精细到「这 6 个组合 vs 那 6 个组合」——**路由变成了在组合空间里做选择**，而不是在大块里做选择。

更关键的是成本账：把 $N$ 从 8 提到 64、$K$ 从 2 提到 6，**每个 token 的激活计算量几乎不变**（$K$ 个小专家之和 ≈ 原 FFN 的一小部分），但激活组合数从 $\binom{8}{2}=28$ 涨到 $\binom{64}{6} \approx 7.5\times10^7$——**参数量涨、计算量不涨，这正是 MoE 的「以参数换容量」哲学的极限放大**。

## 2 激活组合数：为什么细粒度更「能装」

把上一节的会计等式用到细粒度上：

$$\binom{N}{K} = \frac{N!}{K!(N-K)!}, \qquad
N = 64,\ K = 6 \ \Rightarrow\ \binom{64}{6} \approx 7.5 \times 10^7$$

- **$N$ 个专家、激活 $K$ 个**：路由每次在 $N$ 选 $K$，可能的「专家子集」是组合数 $\binom{N}{K}$。
- **组合数随 $N$ 超指数级增长**：$N$ 从 8 翻到 64（8 倍），$\binom{8}{2}=28$ 到 $\binom{64}{6}$ 约 7 亿（7 个数量级）——**容量不是线性放大，是组合爆炸**。
- **前提是每个小专家都能被激活**：组合爆炸要兑现，必须让负载足够均匀、专家都能被选到——这正好接上《负载均衡与专家退化》里的共享专家与 sigmoid 路由设计：**细粒度放大容量，共享专家保负载**，两者缺一不可。<span class="marginnote">为什么 K 取 6 而不是更小？K 太小则每个 token 的表达是「少数专家的线性组合」，细粒度优势发挥不出；K 太大则激活计算量上涨。K=6 是在「组合多样性 × 计算量」之间的实测平衡点——这是典型的「以实验定超参」。</span>

## 3 共享专家与路由专家的分工

DeepSeek-MoE 的完整 MoE 层 = 2 个**共享专家**（必算，承接通用知识）+ 64 个**路由专家**（top-6 挑选，承接专业差异）。前面我们已经讲过共享专家的防退化价值，这里补上它与细粒度的协同：

- **共享专家吸收高频**：通用模式（句法、常见词搭配）不走路由，路由专家不必为此「抢饭碗」，负载更平、组合更有区分度。
- **路由专家专注差异**：top-6 选出的 6 个小专家组合，专门表达「这个 token 与同类不同的部分」。
- **算力账**：共享专家约占 5% 的额外 FLOPs，但换来的是「路由器可以放心大胆地细粒度选择」——这是一笔典型的「小成本买大收益」。

## 4 公式解析：DeepSeek-MoE 的完整前向

把整层的输入输出写成一张图：

$$h_t^l = \underbrace{\sum_{j=1}^{N_s} \mathrm{FFN}_j^s(u_t)}_{\text{共享专家}} + \underbrace{\sum_{i \in \mathrm{TopK}_t} s_{i,t} \cdot \mathrm{FFN}_i^r(u_t)}_{\text{路由专家}}$$

$$s_{i,t} = \mathrm{Sigmoid}\big(u_t^T e_i\big), \qquad
\mathrm{TopK}_t = \{i \mid s_{i,t} \in \text{前 } K \text{ 大}\}$$

- **$u_t$**：上一层归一化后的 token 表示，先输入 MoE 层；**注意先经过 RMSNorm** 再进路由器与专家，这是 DeepSeek 系列对路由稳定性的标准处理。
- **第一项（共享专家）**：$N_s = 2$ 个专家**无条件全算**，无门控权重（权重隐含为 1）。承接通用知识。
- **第二项（路由专家）**：$N_r = 64$ 个专家里，只有 top-6 被选中；选中的专家输出乘以 sigmoid 分数 $s_{i,t}$ 加权求和。未选中的 $58$ 个专家输出视为 0，**不计算**。
- **$s_{i,t}$（sigmoid 门控）**：与 softmax 的关键区别——分数**逐专家独立**，不互相归一化。$u_t^T e_i$ 是内积打分，$e_i$ 是可学习的专家表征向量。独立打分削弱了「专家间竞争」，配合共享专家让路由器更稳（见退化一节）。
- **平衡损失**（防退化）：$L_{bal} = \alpha \sum_{i=1}^{N_r} f_i P_i$，$f_i$ 是命中率、$P_i$ 是平均 sigmoid 分数，$\alpha$ 取 0.01 量级——这是 GShard aux loss 在 sigmoid 拓扑下的直系后代。

## 5 规模化验证：从 2B 到 DeepSeek-V2

DeepSeek-MoE 论文用 2B 参数（约 21B 稠密等价）的系统实验证明了细粒度的收益；随后的 **DeepSeek-V2**（2024）把这个方案推上工业级：MoE 部分 160 个路由专家 + 2 个共享专家、top-6，配 Multi-head Latent Attention（MLA）压缩 KV 缓存，总参数 236B、单 token 激活约 21B——**推理成本仅约为同等质量稠密模型的 1/3**。<span class="marginnote">「236B 总参、21B 激活」是 MoE 的招牌叙事：总参数决定「装了多少知识」，激活参数决定「跑一次要多少钱」。DeepSeek 把这对数字拉开到一个数量级，正是细粒度 + 共享专家的规模化兑现。</span>

这个「细粒度 × 共享专家 × sigmoid」的组合，后来也被 V3 等后续版本继承并进一步放大。它给出的工程教训是：**MoE 的收益不止来自「把专家变多」，更来自「把专家切对」**——切分粒度是一个独立的、被低估的设计维度。

### 一个具体例子：从 8 个专家到 64 个小专家

把「细粒度」的收益用一个可比的设定说透。设一个 MoE 层总预算固定：中间维度 $d_{ff} = 4096$。

- **粗粒度**：$N = 8$ 个完整 FFN，每 token 激活 $K = 2$，激活算力 $= 2 \times 4096$ 维 FFN；
- **细粒度**：$N = 64$ 个小 FFN（每段 $64$ 维），每 token 激活 $K = 6$，激活算力 $= 6 \times 64 = 384$ 维 FFN——**激活算力只有粗粒度的 1/10**，而参数量相当（64 个小段总和仍是 4096），组合数却从 $\binom{8}{2}=28$ 变成 $\binom{64}{6} \approx 7.5\times10^7$。

这个例子回答了一个常见疑问：「细粒度到底省在哪？」**省在激活算力，赚在组合容量**。DeepSeek 论文的核心消融正是「同算力下，细粒度的困惑度更低」——因为 6 个小专家的组合能比 2 个大专家更细腻地表达 token 的差异。

### 与 GShard 的路线对照

把 DeepSeek-MoE 放回本专题的谱系里，它的定位更清楚：GShard 用「top-2 + 随机路由 + 容量因子」解决负载；Switch 用「top-1 + aux loss + z-loss」简化路由；DeepSeek-MoE 则换了一条路线——**不靠更复杂的路由机制，而靠更合理的结构设计**（细粒度 + 共享专家 + sigmoid）让负载问题自然减轻。三者其实在回答同一个问题：「路由怎么才能既均衡又不牺牲质量？」GShard 靠随机性、Switch 靠正则、DeepSeek 靠结构——**这是 MoE 三条路线的代表性分工**，也是本专题把四篇论文并列成体系的原因。

### 细粒度为什么还带来了泛化收益

细粒度不只是「容量」账面上的赢家，它在**泛化**上也有独立贡献。直觉是这样：粗粒度专家是「大而全」的块，token 一旦被路由进去，就要接受整个块的所有能力；细粒度专家是「小而专」的块，token 的组合可以按需拼配——**它把「专家-能力」的绑定从「粗放」变成「精细」，让模型在没见过的输入上也能拼出合适的组合**。DeepSeek 论文把这种收益归因于「细粒度专家促进了 token 与专家之间更细粒度的对齐」，说白了就是：**分工越细，越能用「新组合」应对「新情况」，而不是被迫套用大而化之的旧块**。这也是「分而治之」在 MoE 里的真正含义——不是把模型切小，而是把「决策单元」切细。

### 细粒度 vs 粗粒度：一张对比表

把 DeepSeek-MoE 与经典 MoE 的「切法」排成一张表，差异一目了然：

| 维度 | 经典 MoE（GShard/Switch） | DeepSeek-MoE |
| --- | --- | --- |
| 专家粒度 | 完整 FFN | FFN 的 1/N 段 |
| 每 token 激活 | K=1~2 | K=6（N=64） |
| 专家数/层 | 8~2048 | 64+（V2 为 160） |
| 负载手段 | aux loss + 随机路由 | 共享专家 + sigmoid + aux |
| 参/算比 | 中 | 更高 |

这张表的「参/算比」一列最能说明问题：DeepSeek-MoE 把「参数和算力之比」推到更高——**同样的算力下，它能装下更多参数**。这就是「细粒度」在工程上最直接的兑现。

### 与《MoE 推理部署》的衔接

细粒度还埋了一个推理端的伏笔：专家越细、越多，推理时「激活哪些专家」的粒度也越细——这让专家卸载（本专题最后一节）能做得更精准：不再是把「一个大专家」整个搬走，而是只搬「本轮 token 真正需要的那几个小专家」。**细粒度既服务训练（组合容量），也服务推理（卸载粒度）**——同一个设计决策，在两个阶段同时兑现，是 DeepSeek-MoE 能压低推理成本的根本原因之一。

最后补一句反直觉的事实：**细粒度并不必然带来更贵的推理**。激活算力由 $K$（而不是 $N$）决定，DeepSeek-V2 的 236B 总参里每 token 只激活 21B——细粒度把「参/算比」做大，正是为了在同样的单 token 预算里塞下更多知识。这也是本节与整条 MoE 主线反复呼应的一句话：**决定成本的从来不是「有多少参数」，而是「每次动用了多少参数」**。

**一句话记忆**：细粒度专家 = 同样的 FFN 预算，切成更多更小的「组合单元」——容量随组合数涨，成本随激活数定。

## 6 小结

- **细粒度切分**：把 FFN 中间维度切成 $N$ 个小专家（DeepSeek-MoE：$N=64$、$K=6$），激活组合数从 $\binom{8}{2}=28$ 爆炸到 $\binom{64}{6}\approx 7.5\times10^7$。
- **成本账**：参数量随 $N$ 涨、激活算力随 $K$ 涨——细粒度让「参数/算力」比值进一步提升，是 MoE 哲学的极限放大。
- **结构协同**：2 个共享专家保负载（通用知识不走路由）+ 64 个路由专家保区分度（top-6 组合表达差异）+ sigmoid 门控去归一化竞争。
- **规模化**：DeepSeek-V2 用 236B 总参 / 21B 激活把推理成本压到稠密模型的约 1/3——「总参量装知识、激活量定成本」的招牌叙事。
- **通用教训**：专家切分粒度是被低估的设计维度——「切对」比「切多」更关键。
