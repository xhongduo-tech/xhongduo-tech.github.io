## 为什么从负载均衡损失开始

马太效应是 MoE 训练的头号天敌。上一节我们说过，top-1 路由的梯度只回传给被选中的专家；如果路由器某一步开始偏好某几个专家，这几个专家会因训练更充分而变得更好，于是路由器更偏好它们——**强者愈强、弱者愈弱**，最终少数专家承担全部工作，其余专家形同虚设。专家闲置不仅是「浪费参数」：闲置专家收不到梯度、永远学不会，而活跃专家过载、被一堆不合适的 token 污染，模型质量整体滑坡。

对抗马太效应最标准的工具，就是 **负载均衡损失（load-balancing loss，也叫 aux loss 辅助损失）**。它在 GShard（Lepikhin et al., 2020）里被写成简洁的公式，成为后续所有 MoE 工作的标配。<span class="marginnote">其实 Shazeer 2017 已用变异系数惩罚做过负载均衡；GShard 的贡献是把损失写成一个<strong>可微、简洁、可随 batch 实时计算</strong>的闭式，并且对 top-2 路由天然成立。公式越简单，越容易被规模化采用。</span>这一节我们从「负载失衡为什么无法靠梯度自然修正」出发，推导出 aux loss 的形态，再辨析它与 Shazeer 变异系数损失的区别。

## 1 负载失衡为什么「靠训练自己」修不好

先想一个问题：能不能不加任何正则，让路由器自己学会均衡？答案是不能，原因有三层：

**梯度只沿被选路径回传**：某个专家连续几个 batch 没被选中，它这一路就没有梯度，永远不会「变强」——冷门专家被锁死在冷门里。
- **正反馈环**：热门专家训练充分 → 打分离 → 被选更多；这本质是一个自我强化的偏好，不是均衡的吸引子。<span class="marginnote">这和推荐系统里的「流行度偏差」同构：热门内容被更多人看，算法越推它越热门，长尾内容饿死。MoE 的负载均衡损失，相当于给路由器加了一个「去偏」项。</span>
- **容量上限的叠加效应**：下一节会讲专家容量。一旦某专家满员，后续 token 会被**丢弃**（drop），模型信息直接流失——负载失衡不只是浪费，还会直接伤害质量。

所以必须**显式地惩罚不均衡**，把它写进损失函数，让「均衡」成为路由器优化的方向。

## 2 GShard 的负载均衡损失

GShard 处理的是 Transformer 机器翻译里的 top-2 路由（$E$ 个专家，每 token 选 2 个）。设一个 batch 有 $N$ 个 token，定义两个量：

- **路由分数（fraction of tokens routed）**：$f_i = \dfrac{1}{N} \sum_{x \in B} \mathbb{1}\{\text{token } x \text{ 被路由到专家 } i\}$——专家 $i$ 实际接到的 token 占比（top-2 时一个 token 可同时计入两个专家）。
- **平均门控概率（average gate probability）**：$P_i = \dfrac{1}{N} \sum_{x \in B} p_i(x)$——路由器对专家 $i$ 的「平均偏心程度」。

辅助损失定义为：

$$L_{aux} = \alpha \cdot E \cdot \sum_{i=1}^{E} f_i \cdot P_i$$

其中 $\alpha$ 是损失系数（GShard 用 $\alpha = 0.01$ 量级），$E$ 是专家数。总损失 = 主任务损失 + $L_{aux}$。<span class="marginnote">这个损失只依赖 router 的 logits 与离散路由结果，两部分都可微分（$f_i$ 视作常数、$P_i$ 随 $p_i$ 可微），工程上实现极便宜——一个 batch 内就能算完。</span>

**直觉**：乘积 $f_i \cdot P_i$ 只有当「实际去的 token 多」且「路由器偏心它」同时成立时才大。两项全大 → 损失大 → 惩罚重。当负载完全均匀（$f_i = P_i = 1/E$）时，$\sum_i f_iP_i = 1/E$，乘 $E$ 后损失恒为 1，不惩罚——所以这个损失**以「均匀路由」为最小化目标**。

## 3 公式解析：为什么 f_i · P_i 能测出偏心

$$\min \sum_{i=1}^{E} f_i \cdot P_i, \qquad f_i = \frac{1}{N}\sum_{x}\mathbb{1}\{i \in \text{routes}(x)\},\; P_i = \frac{1}{N}\sum_x p_i(x)$$

三步拆解：

- **第一步，读懂 $f_i$**：它统计的是**离散事件**——「这个 token 究竟被发往哪个专家」，用的是指示函数。$f_i$ 大说明专家 $i$ 接待的 token 多。注意 top-2 时，一个 token 会给两个专家的 $f$ 各加 $1/N$，所以 $\sum_i f_i = 2$（对 top-1 则是 1）。
- **第二步，读懂 $P_i$**：它统计的是**连续概率**——路由器对专家 $i$ 的平均打分。$P_i$ 大说明路由器「偏心」专家 $i$。
- **第三步，乘积与求和**：只有 $f_i$ 与 $P_i$ 都偏大的专家才贡献大的乘积项。如果一个专家 $f_i$ 大但 $P_i$ 小（被路由了但门控权重低），乘积不大；反之亦然。**两者都大才被惩罚**，这精确抓住了「路由器既喜欢去、又给高权重」的病态偏心。

**最小值在哪？** 由 Cauchy-Schwarz 或 AM-HM 不等式可知，给定 $\sum_i f_i$、$\sum_i P_i$ 固定，$\sum_i f_iP_i$ 在 $f_i \propto P_i$（即两者同比例）时最小。对 top-1 且均衡的理想情形，$f_i = P_i = 1/E$，损失取到下界 $1$。实际训练中损失落在 1 附近就说明路由基本均衡。

## 4 与 Shazeer 变异系数损失的对比

Shazeer 2017 用变异系数（CV = 标准差 / 均值）惩罚负载，Switch 与 GShard 用 $E\sum f_iP_i$。两者殊途同归，但有两点值得辨析：

- **衡量对象不同**：变异系数衡量的是「$I_i$ 或 $Load_i$ 这些量彼此差多少」，对**均匀性**敏感；GShard 乘积衡量的是「路由行为与偏心的一致性」，对**马太效应**更直接。
- **训练友好度**：CV 需要对整个 batch 算均值与标准差，还要开根号，梯度不够光滑；$E\sum f_iP_i$ 是光滑的二次型结构，在现代框架里用一个矩阵乘法 + 归约就能算——所以后者成了事实标准。<span class="marginnote">一个易错点：<strong>aux loss 对主任务是有损的</strong>。它强行让路由器「雨露均沾」，而这与「把每个 token 送进最合适的专家」在目标上略有冲突。$\alpha$ 调太大，模型会因为牺牲路由质量而变差；$\alpha$ 太小，又压不住失衡。这个矛盾的更优雅解法，要到《负载均衡与专家退化》里看 DeepSeek 的共享专家设计。</span>

## 5 GShard 的配套手段：随机路由

光有辅助损失还不够。GShard 在 top-2 的**第二个专家的选择**上动了个小心思：第一个专家取 $\arg\max$（硬选择），第二个专家则**按概率随机抽样**——以门控概率为权重、从剩余 $E-1$ 个专家里采样。随机性让负载在 batch 内天然更均衡，与 aux loss 双管齐下。<span class="marginnote">这正是 Shazeer 噪声门控思路在 Transformer 里的延续：一个是训练时加探索噪声，一个是在离散抽样里引入随机性。两者本质都是「用随机性打破正反馈」。</span>

配合**容量上限**（专家满员后新 token 被丢弃，下一节讲）与**分组调度**（group dispatch，把去同一专家的 token 打包成块以减少通信），GShard 把 6 000 亿参数的机器翻译模型训了出来——它是第一个把 MoE 真正搬进 Transformer 大模型的里程碑。

### 一个具体例子：用手算一遍 aux loss

设 $E = 4$、batch 有 $N = 4$ 个 token，每 token 各选 1 个专家。设路由结果：专家 1 收到 3 个 token、专家 2 收到 1 个、专家 3、4 空手。于是：

- $f = (3/4,\ 1/4,\ 0,\ 0)$；
- 假设门控概率近似 $P = (0.6,\ 0.25,\ 0.1,\ 0.05)$；
- $\sum_i f_i P_i = 0.45 + 0.0625 + 0 + 0 = 0.5125$；$L_{aux} = \alpha \cdot 4 \cdot 0.5125 = 2.05\alpha$。

再设想一个完全均衡的 batch：$f = (1/4,1/4,1/4,1/4)$、$P = (1/4,1/4,1/4,1/4)$，则 $\sum_i f_iP_i = 4 \times (1/16) = 1/4$，$L_{aux} = \alpha \cdot 4 \cdot (1/4) = \alpha$——**均衡时损失恒等于 $\alpha$，这是它的下界**。两相对比，失衡 batch 的 $2.05\alpha$ 被明显惩罚。这就是「用 $f_iP_i$ 测偏心」的最直观演示。

### aux loss 与容量因子的耦合

负载均衡损失不是孤立起作用的，它和下一节的容量因子**成对工作**：aux loss 把路由按向均匀，容量上限则保证「万一没按均匀，也不至于灾难」。工程上这两个超参数是一起调的——$\alpha$ 调大，路由更均匀，容量可以调小（省算力）而不丢 token；$\alpha$ 太小，就不得不靠大容量兜底。**一个实用的经验法则：训练日志里丢弃率应接近 0（<1%），一旦丢弃率抬头，优先加大 $\alpha$ 而不是直接放大容量**——因为放大容量只治标，aux loss 才治本。

### GShard 论文里的硬数字：600B 与 2048 块 TPU

GShard 的实验数字是「负载均衡工程」的第一次工业级验收：

- **6000 亿参数**：100 多语言 → 英语的机器翻译模型，MoE 层包含 2048 个专家，参数量远超当时任何稠密模型；
- **2048 块 TPU v3**：专家并行 + 张量并行的混合布局（专家并行一节详述），aux loss、容量因子、随机路由三件套把负载压住，训练稳定收敛；
- **质量收益**：在相同的翻译质量下，稀疏模型的参数量可以大幅放大而计算成本近似不变——质量-成本前沿被显著推进。

这些数字让「负载均衡损失」从「一篇论文的技巧」变成「万亿参数系统的必备件」。没有它，2048 个专家里必然出现大片 dead experts，600B 模型根本无法稳定训练。

### 辨析：aux loss 调大就一定好吗

一个常见的认知误区是「aux loss 越大负载越均衡越好」。事实并非如此：aux loss 与主任务损失在**争夺同一个路由器**——主任务想让「每个 token 去最合适的专家」，aux loss 想让「负载均匀」，两者目标不完全一致。$\alpha$ 过大时，路由器会为了「均衡」牺牲「路由质量」，把 token 送进次优专家，模型整体变差；$\alpha$ 过小时，负载失衡又压不住。**经验上 $\alpha$ 通常落在 0.001~0.1 量级，且要与容量因子联动调参**——「均衡」是手段，「模型质量 + 系统吞吐」才是目的，不要为了均衡而均衡。

### 与《大模型预训练》的衔接

aux loss 的哲学——「给离散的、不可微的决策配一个可微的辅助目标」——在大模型预训练里无处不在：稀疏注意力用「注意力稀疏性正则」、蒸馏用「软标签」、对齐用「KL 散度项」。它们的共同点是：**主目标往往是离散的（选谁、答什么），而真正训练需要连续的梯度信号**。负载均衡损失正是「离散路由 × 可微正则」这一模式的第一个教科书案例。到第四级《大模型预训练》再遇到类似的辅助损失时，你可以把它认出来：先问「哪个环节是离散的」，再问「这个辅助项压的是什么」。这个「识别模式」的能力，比记住任何一个公式都值钱。

另一个值得留意的细节是 aux loss 的**可移植性**：它是「加在损失上的一个标量项」，不依赖任何特定硬件或并行布局，从单卡实验到千卡训练都能原样使用——这与其他手段（如专家并行、容量预分配）的强硬件耦合形成鲜明对比。**可移植的正则，往往比精巧的结构传播得更远**。不妨记下这条设计品味：当一个约束能被写成「损失上的一个小项」时，优先这么写——它让约束同时获得可微、可监控、可移植三样好处。

一句话记忆：**aux loss = 用「路由偏心」的乘积当罚金**——让路由器既不能只去某些专家，也不能只给某些专家高分。

动手练习：在你最喜欢的 MoE 实现里把 $\alpha$ 从 0 调到 0.1，观察 expert utilization 直方图从「长尾」变「平缓」的过程——这是整章理论最直观的一次落地。

这个练习同时会暴露一个边界：$\alpha$ 过大时，路由器为了均衡开始把 token 送进「平均但不合适」的专家——loss 反升。**你亲手触到了「均衡」与「质量」的边界**。

## 6 小结

- **马太效应**是 MoE 训练的核心病：正反馈锁死负载，冷门专家饿死、热门专家过载。
- **aux loss 的标准形态**：$L_{aux} = \alpha E \sum_i f_i P_i$，$f_i$ 量实际路由占比、$P_i$ 量平均门控偏心，乘积惩罚「既爱去又给高权重」的专家。
- **损失下界**：理想均衡时 $f_i = P_i = 1/E$，$L_{aux} = \alpha$，训练时损失贴近 $\alpha$ 即均衡。
- **对比**：GShard 乘积损失比 Shazeer 变异系数损失更光滑、更好算，成为事实标准；但 $\alpha$ 与路由质量存在根本矛盾。
- **配套**：GShard 用随机抽样选第二个专家，与 aux loss 一起把负载按住。

在下一节，我们看马太效应的极端后果——**专家退化（dead experts）**，以及 DeepSeek-MoE 如何用「细粒度专家 + 共享专家」从结构上绕开这个病。
