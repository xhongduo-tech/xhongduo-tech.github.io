## 为什么从专家退化讲起

上一节的负载均衡损失是一个「打补丁」：问题已经发生（路由偏心），我们用额外的损失去纠正它。这一节我们看问题的极端形态——**专家退化（expert degeneration / expert collapse）**：当失衡严重到某个专家在大量 batch 里一个 token 都收不到，它就变成了 **dead expert（死专家）**。

死专家不是「用不上」那么简单。它收不到梯度，训练损失里那部分参数被永久冻结；更糟的是，它的存在污染了建模——路由器偶尔仍会给它打分（概率不为 0），把宝贵的 token 送进一个从未训练好的网络，得到垃圾表示。DeepSeek-MoE（Dai et al., 2024）在论文里把「专家退化」列为稀疏模型的核心痛点，并给出了一套从**结构上**绕开它的方案。这一节我们回答三个问题：专家退化是怎么发生的、如何观测、以及如何从结构上预防。<span class="marginnote">为什么 2024 年才认真讨论退化？因为 DeepSeek-MoE 把专家数推到了 64+ 的量级，并系统性实验了「细粒度」切分——规模越大、越细，退化越容易被观察到、越致命。这是「问题被规模逼出来」的典型。</span>

## 1 退化的动力学：一个正反馈的完整链条

专家退化不是一夜发生的，它的每一步都有明确的因果：

1. **初始化差异**：路由器权重 $W_r$ 初始化后，各专家的打分天然有微小差异；某专家初始分略高。
2. **自我强化**：该专家被多选 → 多收到梯度 → 参数更适配高频 token → 打分更高 → 更被多选。<span class="marginnote">这就是「富者愈富」：训练不是让路由趋向均衡，而是趋向锁死。初始化差异被指数级放大——这正是上一节马太效应注释里埋的线。</span>
3. **容量挤压**：热门专家迅速满员（见下一节容量上限），后续 token 被丢弃；冷门专家空转。
4. **饿死**：长期收不到梯度的专家权重停留在初始值附近，但路由器偶尔仍会给它高分——把 token 送进「没学过」的网络，输出近似随机，反过来再压低该路径的质量。

一条关键性质：**退化的方向是「局部稳定」的**。一旦某个专家被饿死，几乎没有任何梯度会把它救活——因为它不参与任何有效计算。所以对退化，靠「让它自然回血」是徒劳的，必须要么惩罚偏心（上节的 aux loss）、要么在结构上让每个专家都有「保底流量」（本节的共享专家）。

## 2 如何观测：路由熵、利用率与 Top-K 命中率

退化是训练时的「暗病」，需要用统计量把它照亮。业界常用的观测指标有三个：

**路由熵（routing entropy）**：$H = -\sum_i \bar{p}_i \log \bar{p}_i$，其中 $\bar{p}_i$ 是 batch 内平均门控概率。熵接近 $\log E$（理论最大）说明路由均匀；熵显著偏低说明路由器「思想僵化」，偏好集中。
- **专家利用率（expert utilization）**：统计每个专家实际被选中的 token 数。某专家的利用率长期为 0，即判定为 dead expert。训练日志里画出「利用率直方图」，能直接看到负载有没有坍塌成「少数高峰 + 一条长尾」。<span class="marginnote">分布式训练里，利用率指标要按<strong>全局 token 流</strong>统计，而不是单看某台设备——专家分散在设备上，一台设备的热门专家可能掩盖同一设备上另一个专家的冷清。这是工程上一个容易踩的坑。</span>
**Top-K 命中率**：给定 batch，统计「被选中的 $K$ 个专家里，概率最大那一个占了多少」。若几乎总是同一个专家排第一，说明路由基本失去多样性。

这些指标不仅要看，还要配合**早停守则**：一旦利用率直方图出现长尾、且 aux loss 持续偏离下界，就要立即调 $\alpha$、改初始化、或考虑结构改造——拖得越久，死专家越「死透」。

## 3 从「打补丁」到「结构性预防」

aux loss 本质是在路由器的目标函数里加约束，属于**软手段**。DeepSeek-MoE 提出的是**硬手段**：直接在结构上保证每个专家都有流量。它的方案有两根支柱，这里先讲与退化直接相关的一根——**共享专家（shared experts）**。

**共享专家**：在 MoE 层里固定放 $N_s$ 个（DeepSeek-MoE 取 $N_s = 2$）不参与路由的专家，**每个 token 都必过**。它的职责是吸收「所有 token 共有的通用知识」（句法、常见搭配、通用模式），从而把路由的负担留给真正需要「按需分配」的专业知识。<span class="marginnote">共享专家为什么能防退化？因为通用知识占了训练语料的大头，如果让路由器负责这些高频模式，它必然偏心少数专家（那些恰好吸收了通用知识、因此得分最高的专家）——把通用知识从路由范围里拆出去，就断掉了「高频偏心」最粗的一条供给线。其余路由专家只需消化剩余的专业差异，负载天然更平。</span>

于是每个 token 的 MoE 输出变成两部分之和：

$$h_t^l = \underbrace{\sum_{j=1}^{N_s} \mathrm{FFN}_j^s(u_t)}_{\text{共享专家，必算}} + \underbrace{\sum_{i \in \mathcal{S}_t} g_{i,t} \cdot \mathrm{FFN}_i^r(u_t)}_{\text{路由专家，top-K}}$$

其中 $\mathcal{S}_t$ 是本 token 被选中的 $K$ 个路由专家，$g_{i,t}$ 是门控权重。共享专家不参与路由、稳定占用固定算力（DeepSeek-MoE 约多 5% 的 FLOPs），换来的是路由器的「心理负担」大减。

## 4 公式解析：DeepSeek 的 sigmoid 路由与平衡损失

DeepSeek-MoE 把路由器的打分从 softmax 换成 **sigmoid**——这是另一个防退化的细节：

$$s_{i,t} = \mathrm{Sigmoid}\big(u_t^T e_i\big), \qquad
g_{i,t} = \begin{cases} s_{i,t}, & s_{i,t} \in \mathrm{TopK}(\{s_{j,t}\}, K) \\ 0, & \text{otherwise} \end{cases}$$

- **第一步，sigmoid 打分**：$u_t^T e_i$ 是 token 与专家表征 $e_i$ 的内积，再过 sigmoid 压到 $(0,1)$。**与 softmax 不同，sigmoid 是逐专家独立的**——专家之间的分数不再互相「竞争归一化」。这削弱了「某专家分数高必然压低其他专家」的零和耦合，减少路由的恶性集中。
- **第二步，top-K 硬选**：取 $K$ 个 sigmoid 分数最高的专家，其余置 0（不计算）。$K$ 是激活的专家数，DeepSeek-MoE 里 $K=6$、路由专家 $N_r=64$。

再配一个**平衡损失**，形式上与 GShard 同构、按自己的拓扑重定义 $f_i$：

$$L_{bal} = \alpha \sum_{i=1}^{N_r} f_i P_i, \qquad
f_i = \frac{N_r}{K N} \sum_{x \in B} \mathbb{1}\{s_{i,x} \in \mathrm{TopK}_x\}, \qquad
P_i = \frac{1}{N} \sum_{x \in B} s_{i,x}$$

- **$f_i$**：token 中命中专家 $i$ 的比例，乘上 $N_r/(KN)$ 归一化——因为每 token 选中 $K$ 个，理想均匀时 $f_i = K/N_r$，乘 $N_r/(KN)$ 后归一到 $1/N_r$。
- **$P_i$**：平均 sigmoid 分数。
- 乘积在「又常被选中、分又高」时最大——与 GShard 的惩罚逻辑一致，但基于 sigmoid 分数而非 softmax 概率。

**辨析｜易错点：** softmax 与 sigmoid 的负载行为完全不同。softmax 门控里「提高专家 A 的分数」必然「降低专家 B 的归一化概率」，这是一个隐性的竞争项，容易放大偏心；sigmoid 门控消除了这种归一化竞争，配合共享专家，路由器更不容易塌缩。但代价是 sigmoid 分数不再是概率、没有「总和为 1」的天然约束，输出加权时需要自己保证尺度合理（DeepSeek 直接乘原始 sigmoid 分数）。

## 5 退化问题的全景图：所有手段一览

把前几节与本节的手段放在一张表里，可以看到「防退化」从软到硬的光谱：

| 手段 | 类型 | 机制 | 出处 |
| --- | --- | --- | --- |
| 噪声门控 | 软（探索） | 加随机噪声打破正反馈 | Shazeer 2017 |
| 变异系数损失 | 软（正则） | 惩罚负载/重要性不均衡 | Shazeer 2017 |
| GShard aux loss | 软（正则） | $E\sum f_iP_i$ 惩罚路由偏心 | GShard 2020 |
| 随机第二专家 | 软（探索） | 随机抽样分散负载 | GShard 2020 |
| 共享专家 | 硬（结构） | 通用知识不走路由，断高频偏心 | DeepSeek-MoE 2024 |
| sigmoid 路由 | 硬（结构） | 去掉 softmax 归一化竞争 | DeepSeek-MoE 2024 |

观察这张表：**软手段治标（把偏心的代价显式化），硬手段治本（让偏心没有发生的土壤）**。现代 MoE 几乎都是「软硬兼施」——这也解释了为什么 DeepSeek-MoE 即使保留 aux loss，也要在结构上做共享专家与细粒度切分。

### 一个具体例子：肉眼识别退化

设 $E = 16$，训练日志里统计最近 1000 步的专家利用率（每个专家收到的 token 数占比）。把利用率排个序：

- **健康**：最高的专家约 8%，最低约 4%，直方图呈平缓分布，aux loss 贴着下界 $\alpha$ 走；
- **临界**：最高 15%，最低 1%，直方图右偏长尾——路由开始「抱团」，该考虑加大 $\alpha$ 或检查初始化；
- **退化**：最高的 3 个专家合计吃掉 70%，有 5 个专家利用率长期为 0——**dead experts 已经出现**。此时光调 $\alpha$ 可能不够，因为饿死的专家梯度为零、已经「死透」，更可靠的做法是从结构入手（共享专家、sigmoid 路由），并在下一个 checkpoint 重启训练。

这个「三段式观察」是把退化从概念变成可操作的判断标准：**先看直方图形状，再看 aux loss 与下界的距离，最后看有没有长期零利用率的专家**。

### 共享专家与细粒度切分的组合逻辑

DeepSeek-MoE 的共享专家并不是孤立设计，它与另一项改——细粒度专家切分——配合使用（下一节详述）。把两者的协同说清楚：细粒度把专家切碎，组合数暴涨（容量红利），但也让「单个专家能吃到的高频 token」变少——每个小专家只负责「一小块语义」，更容易出现「某块语义太少、对应专家饿死」的局部退化。**共享专家恰好把最丰沛的「通用语义」从这批脆弱的小专家里抽走，让剩下的专业小专家面对更均匀的流量**。一个防退化、一个放大容量，两个改动互为前提——这正是理解 DeepSeek-MoE 的关键：它不是「加了个共享专家」，而是「把负载问题从结构上重新分配了一遍」。

### 与强化学习的「探索-利用」同构

专家退化与强化学习里的「探索-利用两难」是同一个数学结构：路由器是 agent，选专家是动作，token 的损失是回报——**一旦 agent 锁定「当前看起来最优」的专家（利用），就不再尝试冷门专家（探索），于是对冷门专家的价值估计永远不准，形成退化的死锁**。这也解释了为什么噪声门控、随机第二专家这些「探索机制」从 Shazeer 到 GShard 一直被保留：它们本质是强化学习里的「$\epsilon$-greedy」探索，只是以 MoE 的语言出现。在第二级《强化学习》里你会学到「Exploration vs. Exploitation」的形式化表述，这里的专家退化就是它的一个具体实例——**同一套数学，隔了一个领域再次出现**。

### 一句话总结

退化的全部要点浓缩成一句：**路由的正反馈是「系统性的疾病」，只能靠「探索、正则、结构」三类药物中的至少一种来治**——而 DeepSeek 的答案，是三类全上、再加一个「共享专家」的手术。

## 6 小结

- **专家退化**是负载失衡的极端后果：初始化差异被正反馈放大，冷门专家收不到梯度而「饿死」。
- **退化是局部稳定的**：不会自然回血，必须主动干预——惩罚偏心或结构性保底。
- **观测指标**：路由熵、专家利用率直方图、Top-K 命中率；要按全局 token 流统计，警惕设备级假象。
- **结构性预防**：DeepSeek-MoE 的共享专家把通用知识移出路由范围，从根上断掉「高频偏心」；sigmoid 路由去掉 softmax 的归一化竞争。
- **全景**：防退化手段从「探索」「正则」的软手段，到「结构」的硬手段；现代模型软硬兼施。
