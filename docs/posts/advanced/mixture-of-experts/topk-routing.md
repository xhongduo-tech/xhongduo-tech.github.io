## 为什么从 top-k 路由讲起

上一节我们见过了稀疏门控的完整形态：噪声 + KeepTopK，每 token 挑 $k$ 个专家。Shazeer 2017 用的是 $k \ge 2$（论文里多为 2），因为两个专家的输出可以互补，语言建模上确实比 $k=1$ 好。可 $k \ge 2$ 意味着每个 token 要同时算两个专家、做两次跨设备通信，而路由这个「决策」本身也变得复杂。

2021 年（JMLR 2022），Fedus 等人在《Switch Transformers: Scaling to Trillion Parameter Models》里做了一件反直觉的事：**把 $k$ 砍到 1**。每个 token 只路由给门控打分最高的那一个专家，其余专家一律不碰。<span class="marginnote">「Switch」这个名字就来自思想实验「Switch-Activation」：一个电话交换台，每个电话（token）只被接通到一条线路（专家）。</span>结果不是变差，而是更好：路由更简单、通信更省、模型更大，一路把 MoE 推到 1.6 万亿参数。这一节我们拆解 top-k 路由本身：它怎么算、top-1 为什么够用、又埋下了哪些问题。

## 1 路由就是一次「定向广播」

在 MoE 层里，**路由（routing）**指门控为每个 token 决定「去哪个专家、权重多少」的完整过程。Transformer 里 MoE 层替换 FFN，设输入是第 $l$ 层的 token 表示 $x_t$，路由分两步：

**第一步，打分**：用一个可学习的路由器矩阵 $W_r \in \mathbb{R}^{d \times E}$ 给 $E$ 个专家打分，再过 softmax 归一化成概率：

$$p(x_t) = \mathrm{Softmax}\big(x_t W_r\big)$$

**第二步，挑选**：取概率最大的前 $k$ 个专家作为本 token 的「路由目标」。$k$ 是超参数：$k=1$ 是 Switch 的做法（又叫 **top-1 路由** 或 **switch 路由**），$k>1$ 是 Shazeer 式的 **top-k 路由**。

被选中的专家真正执行前馈计算，输出的加权求和就是本 token 在这一层的表示。不同 token 去不同专家——这就是**稀疏**的体现：$E$ 可以很大，但每个 token 只经过 $k$ 个专家。<span class="marginnote">注意一个细节：打分只花 $O(dE)$ 的矩阵乘法，而一个专家 FFN 的代价约 $O(8d^2)$。只要 $d \ll 8d^2/E$… 事实上通常 $E$ 个专家、$d$ 维，路由器成本远小于「全算一遍」的成本，所以路由这一步在工程上几乎免费。</span>

## 2 top-1：Switch 的「极简」赌注

Switch Transformer 把 $k$ 定为 1，输出形式最简：

$$y_t = p_{i^*}(x_t) \cdot \mathrm{FFN}_{i^*}(x_t), \qquad i^* = \arg\max_i p(x_t)_i$$

即：找到概率最高的专家 $i^*$，只算它的 FFN，再乘上概率 $p_{i^*}$ 作为门控权重。对比 Shazeer 的公式，这里去掉了噪声、去掉了第二专家，只留下一个决定。

**为什么 top-1 反而更好？** 作者给出三点理由：

- **计算效率**：每个 token 只算一个专家 FFN，FLOPs 降到最低；$k=2$ 时专家计算量翻倍，而收益有限。
- **通信减半**：每个 token 只需把数据送到一个设备、再收回来。在专家分布在不同设备上时，`k=2` 的 all-to-all 通信量是 `k=1` 的两倍——后文《专家并行》会算这笔账。
- **模型容量更大**：省下的算力可以换更多专家。同一个 FLOPs 预算下，Switch 用 128 个专家/层、更大的隐藏维度，容量远超 $k=2$ 的配置。

**top-1 的代价**是明显的：路由决策太「硬」。一旦打分出错、或专家负载不均，token 可能被送进一个不太合适的专家，而没有任何第二候选兜底。于是 top-1 必须配三样东西才能站住脚：**负载均衡辅助损失**（下一节）、**专家容量上限**（下下节）、**训练稳定性技巧**（z-loss，倒数第二节）。它们几乎是 top-1 的共生器官。

## 3 公式解析：switch 路由的输出

$$y_t = p_{i^*}(x_t) \cdot \mathrm{FFN}_{i^*}(x_t), \qquad i^* = \arg\max_i \big(x_t W_r\big)_i$$

逐项拆解：

- **$x_t W_r$**：token 表示与路由器矩阵相乘，得到 $E$ 维原始分。$W_r$ 与专家共享输入空间：它衡量「这个 token 与哪个专家的『风格』更搭」。
- **$\arg\max_i (\cdot)_i$**：取原始分（注意这里是未归一化的 logit，与公式 1 里 softmax 后的 $p$ 不同）最高的一维，得到唯一目标专家 $i^*$。**硬决策在这里发生**——只有一个专家被选中。
- **$p_{i^*}(x_t)$**：softmax 归一化后的概率，作为门控权重乘在 FFN 输出上。乘这个概率很重要：它让路由器的「信心」可以参与梯度传播，同时让不同 token 对同一专家的输出做出不同比例的贡献，等价于「软」地组合了 $E$ 个专家的能力。
- **$\mathrm{FFN}_{i^*}(x_t)$**：只有被选中的专家执行前馈。**其余 $E-1$ 个专家输出视为 0，连算都不算**——这是计算节省的全部来源。

一个关键直觉：**路由器的梯度信号只来自被选中专家的损失**。没被选中的专家在这条路径上梯度为 0，只能靠辅助损失或其他 batch 里的 token 间接学习——这解释了为什么路由器的训练如此依赖负载均衡与稳定性技巧。

## 4 路由的「数学形态」：从概率到硬选择

把 top-k 路由放在更广的光谱上看，它位于两个极端之间：

- **软混合（soft mixture）**：$y = \sum_{i=1}^E p_i(x) E_i(x)$，所有专家都算，权重是概率。这是 1991 年 MoE 的形态，参数多、计算也全量——不省算力。
- **硬路由（hard / top-1）**：只有一个专家被算，权重乘门控概率。Switch 采用，最省算力。
- **top-k 中间态**：Shazeer 的 $k \in [1,4]$。一个经验结论：**top-1 在「同 FLOPs 比质量」的赛制下往往不输 top-2**，因为省下的算力可以换更多专家；而 top-2 的软互补在「同参数量比质量」时仍有价值——这解释了为什么后来的 Mixtral 又回到 top-2。<span class="marginnote">「同 FLOPs」还是「同参数量」决定选哪种：比成本（FLOPs）时 top-1 赢，比容量（参数量）时 top-2 赢。这个权衡在《路由策略对比》一节会专门展开成一张对照表。</span>

路由还有一个常被忽略的维度：**路由矩阵 $W_r$ 的初始化与维度**。Switch 里 $W_r$ 与 token 表示同维相乘，输入规范化（norm）对路由稳定性影响很大——这是「路由策略对比」里常出现的消融项。

## 5 top-1 打开的世界

Switch 论文的实验结论值得单独记：在**固定 FLOPs** 的赛制下，稀疏模型（1.6T、每 token 只经 1 个专家）比稠密模型在同预算下取得**更低的预训练损失**；在编码器、编码器-解码器、解码器三种架构上都成立。这意味着「稀疏」不是「省钱的替代品」，而是**同成本下更强的模型**。

由此，大模型时代的事实标准被确立下来：**MoE 层的 FFN 换成一堆「细粒度」专家 + top-k 路由 + 一堆辅助机制**。今天的 DeepSeek、Mixtral 都在这个框架内做变体：DeepSeek 把 top-6 与共享专家结合，Mixtral 用 top-2。理解 top-k，就理解了这些现代架构的公共语法。

### 一个具体例子：128 专家的路由器开销

用数字验证「路由几乎免费」。设 $E = 128$、$d = 2048$，路由器矩阵 $W_r \in \mathbb{R}^{2048 \times 128}$，一次打分 $xW_r$ 约 $2 \times 2048 \times 128 \approx 52$ 万次乘加；而一个专家 FFN（$2048 \to 8192 \to 2048$）约 $2 \times 2048 \times 8192 \times 2 \approx 6700$ 万次乘加。**路由器打分比一个专家前馈便宜约 130 倍**——即使每个 token 都要算路由器，它的成本占比也微乎其微。这正是「专家可以多、路由可以贵」的底气。

### top-1 与 top-2 的消融记忆点

Switch 论文对 top-1 与 top-2 做过同规模对比，结论是：**在固定 FLOPs 预算下，top-1（配更多专家）的质量不输、常优于 top-2（配较少专家）**。原因在上面的会计等式里已能读出：top-2 的专家计算量是 top-1 的两倍，把省下的算力换成「更多更小的专家」，容量收益更大。但结论有适用条件：这是「固定 FLOPs 赛制」的结论；若「固定参数量、不限制 FLOPs」，top-2 的软互补仍可能带来额外收益——后来 Mixtral 采用 top-2，正是这个视角的体现。

### 路由器输入规范化的隐藏作用

top-k 路由的稳定性很大程度取决于**路由器的输入尺度**。token 表示 $x$ 若范数很大、且随训练波动，$xW_r$ 的 logit 就会剧烈抖动，softmax 在「分散」与「接近 one-hot」之间来回跳——这是训练不稳的常见隐蔽来源。实践里几乎都要求**先对路由输入做规范化**（RMSNorm/LayerNorm），把 $x$ 的尺度压平；DeepSeek 系列在 MoE 入口统一做 RMSNorm，Switch 论文也把路由稳定性列为训练成败的关键。这条线索在《MoE 训练稳定性》一节会专门展开，这里先记住：**路由的输入规范，是 top-k 能稳定工作的前置条件**。

### Switch 论文里的硬数字：万亿参数与 7 倍加速

Switch Transformer 的招牌数字同样值得记住：

- **1.6 万亿参数**：把一个 T5-XXL（110 亿参数）的 FFN 换成「更宽 + 更多专家」的 MoE 层，总参数做到 1.6T，单 token 激活参数仍是十亿量级——参数量与激活量拉开约两个数量级；
- **7 倍加速**：在「同 FLOPs 同质量」赛制下，Switch-Base 比 T5-Base 快约 7 倍——注意这里的「快」指**用更少的 FLOPs 达到同样的质量**，不是单位时间的吞吐；
- **三个架构通吃**：编码器（T5）、编码器-解码器、解码器（自回归）三种形态下，稀疏都优于同 FLOPs 的稠密。

这些数字确立了「固定 FLOPs 赛制」的行业惯例——**比模型质量先比算力预算**。它让「稀疏模型」从「省钱的技巧」升格成「同成本下更强的架构」，直接催生了后来 Mixtral、DeepSeek 的稀疏化竞赛。

### 从 top-1 到 top-6：K 是一枚可调旋钮

今天的模型早已不满足于 $k=1$：Mixtral 用 $k=2$，DeepSeek-V2 用 $k=6$。$k$ 的增大意味着「每个 token 用更多专家的算力」，但换来更丰富的组合表达（细粒度一节会展开）。所以更准确的表述是：**Switch 的贡献不是「top-1 永远最优」，而是证明了「top-1 已足够好，足以支撑万亿参数」**——它把 $k$ 从「必须大于 1」的教条里解放出来，让 $k$ 变成一枚可以随算力预算调节的旋钮。

### 一个连接

路由的「打分—挑选」两段式在信息检索里也有对应：打分是召回（retrieval），挑选是精排（ranking）。router 的 softmax 打分与搜索引擎的召回排序在数学上同构——「先广筛、后精选」是信息处理里反复出现的结构，从 MoE 到 RAG（第三级《检索增强生成》）都是同一句话。给路由配上「先打分、再 top-k、再按分加权」的三段式，你会发现它和「召回—重排—融合」的检索流水线几乎是同一个模子。

最后提醒一个常被忽略的点：**top-k 路由的「k」与 batch 内 token 数没有直接关系**——它是每个 token 独立的决策，无论 batch 多大，每个 token 都只去 $k$ 个专家。k 影响的是「单 token 算力」与「通信量」（专家并行一节），这是它和容量因子（管「每个专家收多少」）最本质的分工。

## 6 小结

- **路由 = 打分 + 挑选**：$p(x)=\mathrm{Softmax}(xW_r)$ 打分，取 top-k 个专家执行，输出乘门控权重。
- **top-1（switch 路由）**：每 token 只算一个专家，输出 $y = p_{i^*}\cdot \mathrm{FFN}_{i^*}(x)$；换来了最低 FLOPs、减半的通信与更大的容量。
- **top-1 的代价**：决策硬、无兜底，必须配套负载均衡损失、容量上限与稳定性技巧才能稳定训练。
- **光谱定位**：软混合（全算）→ top-k（算 k 个）→ top-1（算 1 个）；「比 FLOPs 还是比参数量」决定选哪种。
- **历史意义**：Switch 证明了 top-1 稀疏能在万亿参数规模上超越稠密基线，确立了现代 MoE 的公共语法。

在下一节，我们补上 top-1 的第一块拼图：**负载均衡损失**——它是如何强迫路由器「雨露均沾」，避免少数专家包揽一切的。
