## 为什么需要策略

状态跟踪告诉我们「对话进行到哪一步」，但知道位置不等于知道下一步。系统接下来该**问哪个槽**、**确认哪个值**、还是直接**查库下结论**？这个「从状态到动作」的选择，就是**对话策略（dialogue policy）**。它是整个任务型系统里最接近「智能」的一环——其他模块都在把信息搬运、压缩、翻译，只有策略在做决策。<span class="marginnote">策略问题与博客第四级《强化学习》专题完全同构：状态、动作、奖励、长期回报。换句话说，对话策略几乎是强化学习最自然的教科书用例之一——不确定性来自用户，目标来自任务。</span>本篇对标 Tur 与 De Mori 第 6 章，先看手工规则策略，再把它变成可学习的问题。

## 1 策略：从状态到动作

**对话动作（dialogue act）**：系统在某一轮「做什么」的抽象描述，与具体措辞无关。常见动作类型：

- `request(出发城市)`：向用户询问某个槽值
- `inform(航班=CA123, 时间=10:00)`：告知信息
- `confirm(目的地=北京)`：向用户确认某个值
- `query_db()`：查询知识库
- `greet()`、`bye()`：寒暄与收尾

动作的括号里是它的**参数**——`request(出发城市)` 的括号明确「问的是哪个槽」。**动作 + 参数合起来，才是 NLG（第 6 篇）的完整输入**：策略输出 `inform(航班=CA123, 时间=10:00)`，NLG 才知道这句话里必须出现 CA123 与 10:00 这两个值。动作抽象层把「决策」与「措辞」彻底分开，这也是流水线各模块能独立演进的前提。

**对话策略（policy）**：一个映射，给定当前状态（或信念状态）$s$，输出一个动作的概率分布 $\pi(a \mid s)$。有了策略，系统每轮的行为就确定下来：以 $\pi$ 为据采样或取最优动作。

为什么要写成概率分布而不是确定的「查表」？因为**同一状态可能有多个合理动作**，且系统对状态本身不完全确定——概率化让策略可以表达「此时更倾向问时间，但也可能直接确认」。

## 2 手工规则策略与它的天花板

最朴素的策略是**手工规则**：把「状态 → 动作」写成 if-else 或有限状态机。经典的订票系统是**槽位填满循环**：检查还有哪个槽没填 → 逐个 request → 全部填满 → query_db → 汇报结果。这种「按固定顺序逐个问槽」的模式至今仍是许多真实客服机器人的默认行为——**它不聪明，但永远不会胡说**。

这套方案的可控性极好，但天花板明显：

- **规则不可枚举**：状态是槽值组合，组合数随槽位与取值指数爆炸，规则写不完。
- **无法权衡**：状态噪声高时，直接问 vs 先确认 vs 按最可能值往下走，各有代价——规则给不出「当前最优」。
- **不可迁移**：换个领域，规则全部重写。
- **不可优化**：规则里没有任何参数，无从根据真实用户反馈改进。

一句话：**手工规则把策略当「编程问题」，而策略真正是个「决策优化问题」**。

### 一个最小的订票策略长什么样

把规则翻译成「状态 → 动作」表，最小的订票策略大致是这样一张表（状态用「哪些槽已填」表示）：

| 状态（已填槽位） | 动作 |
| --- | --- |
| 无 | greet + request(出发城市) |
| 出发城市 | request(目的地) |
| 出发城市、目的地 | request(日期) |
| 出发城市、目的地、日期 | query_db() |
| 查库有结果 | inform(航班) + confirm(航班) |
| 查库无结果 | request(日期范围放宽) 或 inform(无票) |

看到问题了吗？表里每一行都清晰，但**「有结果」依赖真实数据库的返回**，而「用户答非所问」会打乱这个顺序——第 2 行用户若答「我想订明天的票」，系统要先判断「这句是不是回答了出发城市」。规则写到这里就开始发散：答非所问怎么处理？听错了怎么处理？改主意怎么处理？每一种情况都要在表里加新分支，组合数随之爆炸。**这就是为什么规则策略只能停在 demo 阶段**——它把「决策」写死了，而真实对话需要「在不确定中权衡」。

## 3 公式解析：把「选动作」写成优化目标

要优化，先定义「一个策略有多好」。引入价值函数与贝尔曼方程：

$$
V^{\pi}(s) = \mathbb{E}_{\pi}\left[ \sum_{t=0}^{\infty} \gamma^{t} r_{t} \;\middle|\; s_0 = s \right],
\qquad
V^{*}(s) = \max_{a}\left[ R(s,a) + \gamma \sum_{s'} T(s'\mid s,a)\, V^{*}(s') \right]
$$

拆成四步：

- **第一步，$V^{\pi}(s)$：策略 $\pi$ 的状态价值**。从状态 $s$ 出发、永远按 $\pi$ 行动，未来所有折扣回报之和的期望。它量化「这个策略在这个状态下有多好」。
- **第二步，$R(s,a)$：立即奖励**。在状态 $s$ 采取动作 $a$ 立刻得到的回报——任务成功 +100、每轮 -0.1 这类设计。
- **第三步，$\sum_{s'} T(s'\mid s,a)\, V^{*}(s')$：未来的期望**。动作 $a$ 之后状态跳到 $s'$（对话里由用户反应决定），再按最优策略继续。对 $s'$ 求和，就是「这一步之后还剩多少好日子」。
- **第四步，$\max_a$：最优决策原则**。最优策略在每个状态只做一件事：**选择使「立即奖励 + 折扣后的未来最优价值」最大的动作**。这条递归方程（贝尔曼方程）把「长期优化」化成了「逐步的贪心」，是整个序贯决策理论的支点。

**一句话：策略学习 = 求解 $V^*$ 或等价地最优 $\pi$，而贝尔曼方程给了递归求解的钥匙**。<span class="marginnote">贝尔曼方程的『递归结构』是它最重要的气质：一步的最优选择，只取决于『这一步的立即回报』与『下一步的最优价值』——把无限长的未来折叠成一步，这就是动态规划在序贯决策里的全部魔法。</span>但注意这个式子假定 $T$ 已知且状态可观察——对话里这两条都不成立，这就是第 5 篇引入强化学习与 POMDP 的原因。

## 4 监督学习：从人类对话里模仿策略

不先建模 $T$，另一条路是**直接从数据学策略**：收集一批人类对话日志（专家在状态 $s$ 说了动作 $a$），做**模仿学习 / 行为克隆**：

$$
\theta^{*} = \arg\max_{\theta} \sum_{(s,a)\in \mathcal{D}} \log \pi_{\theta}(a \mid s)
$$

把策略参数化成神经网络 $\pi_\theta$，用专家日志最大化对数似然。方法简单、不需要奖励设计，但有深刻缺陷：

- **暴露偏差（exposure bias）**：训练时输入是专家状态，测试时输入是系统自己走出来的状态——分布不一样，误差会累积。
- **无法修正**：专家日志里没有「错误状态」，策略学不到「从自己造成的坏状态里爬出来」。
- **只能模仿见过的**：日志覆盖不到的状态，策略完全没依据。

**这三点归结为同一句话：模仿学习把『策略』当成了『条件概率』来拟合，而策略真正的任务是『在对自己最不利的状态里也做出好决策』**——后者的数据恰恰是日志里最稀缺的，因为专家很少犯错，自然也就很少留下『从错误中爬出来』的样本。

模仿学习适合当**冷启动**：先让系统像人一样说话，再用强化学习在真实交互中继续改进——这正是很多工业系统「先学人类，再用反馈打磨」的范式。注意模仿学习与第 8 篇 seq2seq 的 MLE 在数学上是同构的（都是最大化专家数据的对数似然），区别只在**模仿对象与输入形式**：对话策略模仿的是「状态 → 动作」的决策，闲聊模型模仿的是「上文 → 话」的文本——**『学人类行为』这个母题，横跨了策略与生成两条路线**。

## 5 辨析：对话里的转移你说了不算

**辨析｜易错点：** 学强化学习时人们常拿围棋、雅达利游戏类比——那里状态转移完全由规则决定、可观察。**对话完全不同**：$T(s'\mid s,a)$ 由「用户怎么反应」决定，而你只能影响它、不能控制它；且用户反应常被 ASR/NLU 噪声污染，真实状态不可直接观察。**结论：对话策略必须处理的不是 MDP，而是 POMDP（部分可观察马尔可夫决策过程）**——下一篇文章的主角。把对话当普通 MDP 硬套，是新手最容易犯的建模错误。

| 维度 | 模仿学习 | 强化学习 |
| --- | --- | --- |
| 数据 | 人类专家日志（静态） | 交互采样（动态） |
| 奖励 | 不需要 | 必须设计 |
| 能否修正自己的错误 | 不能 | 能 |
| 主要风险 | 暴露偏差、分布外状态 | 奖励设计、样本效率 |

## 6 小结

- **对话策略**是从状态到动作的映射 $\pi(a\mid s)$；动作以**对话动作（dialogue act）**为单位。
- 手工规则策略**可控但不可扩展**，本质是拿编程问题代替决策问题。
- 策略的价值由**贝尔曼方程**递归定义：$V^*(s)=\max_a[R(s,a)+\gamma\sum_{s'}T(s'\mid s,a)V^*(s')]$。
- **模仿学习**可从专家日志冷启动，但有暴露偏差；最终要走向**强化学习**。

在下一节，我们正式进入强化学习：把对话写成 **POMDP**，用 Q 学习与模拟用户训练策略，并回顾 Williams 与 Young 2007 年那座里程碑——这也是本专题唯一一篇以单篇论文为主体的内容。
