## 为什么从「规模」开始

前八篇把重建、生成、显示都讲了一遍，但所有方法的默认前提都是「一个小场景」：一张桌子、一个房间、一段短视频。可空间智能真正要服务的对象——导航的机器人、运营的数字孪生、漫游的城市元宇宙——面对的是**整栋楼、整座城市**。<span class="marginnote">规模的跃迁不是「把参数调大」就能糊弄过去的：NeRF 训练一块桌面场景要几分钟，同样的方法要训练一条街区，内存会先爆炸；3DGS 对一个小场景存几百 MB，对一座城市就是几百 GB。<strong>「大」不是「小」的十倍，而是「小」的问题全部指数级放大</strong>——这正是第九篇存在的理由。</span>

这一篇回答一个朴素的问题：**能不能把一整个城市重建进一个神经/显式表示，还能实时查询？** 答案分两条技术路线合流：一条是**离线的大场景神经重建**（Block-NeRF、MegaNeRF），另一条是**在线的神经 SLAM**（把「我走到哪了」与「周围是什么」同时算出来）。前者追求「精」，后者追求「活」——而 2023 年后 3D 高斯把两者的实时性都推高了一个台阶。

在进入技术之前，先给「大规模」一个可操作的标尺，避免空谈：**10 米级**是「一个房间」（前八篇已经解决）；**100 米级**是「一栋楼或一条街」，需要分块；**1 公里级**是「一片园区」，需要场景图与层次化索引；**10 公里级**是「一座城区」，只能靠「多传感器 + 众包 + 云端协作」。不同尺度对应的不是「同一方法放大」，而是**不同的系统架构**——理解这一点，比记住任何单一论文都重要。

数据侧的现状也值得摆清楚：真正的城市级数据来自**测绘级采集**——车载激光雷达（LiDAR）+ 多相机的「移动测量车」，或用无人机做倾斜摄影测量。这些设备产出的是「带位姿的稠密点云 + 高精度影像」，它们本身已经把「几何」采集出来了，神经重建的职责被简化为「把点云 + 影像变成可渲染、可编辑、可查询的表示」。**换句话说，在城市尺度，「重建」的重心正从「解几何」转移到「做表示」**——这也解释了为什么本篇与第五、十篇（生成与数据）越走越近。

从时间线上看，大场景重建也有一个清晰的「代际」：2010 年代是**基于 SfM/MVS 的离散重建**（点云 + 网格，COLMAP 时代）；2021—2023 年是**神经隐式场**（NeRF 一族，追求连续与可微）；2023 年后是**显式高斯 + 分块索引**（3DGS 一族，追求实时与可编辑）。每一代都继承了上一代「分块、索引、由粗到细」的骨架，只是把「表示」换得更快、更可控。**把这三代放在一起看，就是前四篇（NeRF→3DGS）在大尺度上的重演**——尺度没有改变技术史的规律，只是放大了它的代价。

## 1 规模的三重挑战

先看清「大规模」到底难在哪，后面所有方案都是为了回应这三难：

- **数据挑战**：一座城市级场景需要成千上万张图（或数小时的视频）。采集端往往是车载摄像头、无人机或手机众包，覆盖不均匀、光照多变、有大量重复纹理（玻璃幕墙、墙纸）。**「采什么、怎么采」第一次变成重建的瓶颈**。

数据挑战还有一个「众包」的现实版本：Google 的「众包地图」、手机厂商的「众包测绘」都靠用户随手拍的街景与室内视频，覆盖随用户流动而不可控——于是重建系统必须具备**「给什么吃什么」的鲁棒性**：图多的地方做精细，图少的地方用先验补，完全没图的地方宁可留「空洞」也不要「胡编」。**「诚实地留白」是大规模重建的伦理与工程双重底线**——这也预告了第十一篇评测里「真实感 vs 正确性」的取舍。
- **内存挑战**：显式表示（点云、高斯）随场景线性膨胀；隐式表示（NeRF）虽紧凑，但训练单个全局 MLP 会「顾此失彼」——网络容量有限，学不完整座城。**「一个表示装下整座城」在物理上不成立，必须拆**。
- **一致性挑战**：误差会累积。SfM 在城市尺度下漂移（第二篇提过），光照随时间变化（早上 vs 黄昏），遮挡随季节变化（树叶 vs 落叶）。**「同一个地方，不同时间采的图，重建出来不能对不上」**——这是大规模重建最隐蔽、也最伤筋动骨的难题。<span class="marginnote">一致性挑战还有一个「车拍」特例：车辆在街道上行驶，相机基本是「前进方向」，多视图几何里「纯前向」会造成严重的尺度与姿态退化——因此车拍重建常依赖 GPS/IMU 先验来锚定位姿，甚至用「闭环」把回到起点时发现的对不齐摊平。这是城市级重建与室内重建最显著的工程差异。</span>

这三重挑战还互相放大，形成「死亡螺旋」：数据越杂（光照不均、重复纹理）→ 位姿越容易错 → 重建越糊 → 反过来更难匹配更多图。破解螺旋的关键是<strong>先给一个「大致对的全局骨架」</strong>——用 GPS/IMU 把相机摆到大致位置，再用 SfM 精修；或先做一次稀疏重建，再稠密化。<strong>「先骨架、后血肉」在大规模场景里不是可选项，而是生存必需</strong>——这与第二、四、七篇反复出现的「先粗后精」范式完全一致，只是骨架的来源从「两视几何」升级为「多传感器先验」。

## 2 离线路线：分块、层次化与「场景图」

既然「一个全局表示装不下」，最直接的对策就是**拆**。分块（block-wise）的祖师爷是 **Block-NeRF**（2022）：把一个大区域切成一个个重叠的小块，每块训练一个 NeRF，渲染时按相机位置「挑选」相关的块并做加权融合。<span class="marginnote">「分而治之」在空间智能里反复出现：第七篇是「把时间冗余压缩」，这里是「把空间切块」，第九篇之前之后，<strong>「局部小模型 + 全局索引」都成了大型表示的标准形态</strong>——它本质上是一次「索引 + 缓存」的数据库思想，只是作用在 3D 表示上。</span>

**MegaNeRF**（2022）把分块推向更细：用空间网格把场景切成大量微块，渲染时只激活相机附近的一小撮块，并用「场景图（scene graph）」组织——把「哪块在哪、块与块怎么衔接」建一张图，既省算力又保连贯。Instant-NGP 的哈希网格则从另一头解决内存：把坐标哈希进特征表，一个紧凑网格就能覆盖超大范围（配合「多分辨率哈希」还能由粗到细）。**三条离线路线共同确立了「大场景 = 分块 + 索引 + 由粗到细」的工程范式。**

「分块」之后还要回答一个棘手问题：**块与块之间的「接缝」**。每块 NeRF 独立训练，边界处的密度与颜色必然有微小差异，渲染出来就是一道「补丁线」。Block-NeRF 用重叠分块 + 加权平均模糊接缝，MegaNeRF 用「按距离激活多个块再做 α 融合」。这个看似琐碎的问题，恰恰是「大场景质量」的试金石——**接缝处理得不好，整座城就像一张「打了补丁的被子」**。工程里没有「细节不重要」这回事。

与「接缝」同样折磨人的是**光照不一致（appearance）**：同一栋楼，早上拍的图与黄昏拍的图颜色完全不同；若把「光照」也当成「场景的一部分」学，重建就会「学出一团矛盾的颜色」。Block-NeRF 的解法是**外观嵌入（appearance embedding）**——给每张图分配一个「光照向量」，让它把「稳定的几何/颜色」与「可变的亮度」分开表示；渲染时按需选一个光照向量，就能实现「同一场景、任意打光」。**「把不变的几何与可变的外观解耦」这个思路，在本篇、第七篇（时间与形变）、第四篇（球谐颜色）反复出现**——它是空间智能处理「世界的不确定性」的统一武器。

## 3 在线路线：神经 SLAM——边走路边建图

离线重建是「采集完再算」，**SLAM（同步定位与建图）**则要求「边走边算」：机器人/手机上实时估计「我在哪」（定位）并同步更新「周围是什么」（建图）。传统 SLAM 用稀疏特征点（ORB-SLAM, 2015）或直接光度对齐（DSO, 2016）建图，但产出的是「点 + 轨迹」，不是「可渲染的 3D 场景」。**神经 SLAM** 把神经/显式场景表示接进了这个实时闭环。

值得先给「传统 SLAM 与神经 SLAM」的边界画条线：传统 SLAM 的「图」是稀疏特征点 + 位姿轨迹，主要服务于「定位」；神经 SLAM 的「图」是一块可渲染的连续场景，顺带服务于「定位」——**它把 SLAM 从「导航工具」升级成了「建图 + 渲染 + 导航三合一」**。这个升级的直接受益者是机器人：它不再需要「先建图、再导航」两套系统，一边走一边就有了可渲染、可查询、可规划的场景。

- **iMAP**（2021）：第一个「一个 MLP 做 SLAM」，把整张图存进隐式场，实时优化「位姿 + 场景」。
- **NICE-SLAM**（2022）：用分层特征网格缓解「一个 MLP 忘了前面的场景」，支持更大场景。
- **SplaTAM / GS-SLAM**（2023）：改用 3D 高斯做场景表示，实时性大幅提升，也印证了第四篇「显式化」的势能——**连 SLAM 都开始泼高斯了**。

神经 SLAM 有一个传统方法没有的**两难（catastrophic forgetting）**：场景表示是在线更新的，当机器人转过一个弯、看到一片新区域，梯度会「覆盖」之前学过的区域——老地方被忘掉。解决方向有三：一是**分层/局部特征**（NICE-SLAM），不同区域用不同层的特征，更新互不干扰；二是**关键帧回放**，定期重放历史关键帧，让旧区域「别被忘光」；三是**先全局后局部**（Co-SLAM），先用粗网格锁住整体，再细修。**「在线学习怎么不忘记」这个机器学习老问题，在神经 SLAM 里以最尖锐的形式重现**——读到这里你会发现，空间智能的很多难题，都是机器学习经典难题的新面具。

神经 SLAM 的核心是一个联合优化：每一步，用「当前位姿假设」把「当前场景表示」渲染出来，与「当前观测帧」比对，误差同时回传给位姿与场景。

$$
\mathcal{E}_{\mathrm{frame}} = \sum_{\text{pixels}} \left\|\, I(\mathbf{r}) - \hat{I}(\mathbf{r}) \,\right\|^2
$$

其中 $I(\mathbf{r})$ 是真实帧沿射线 $\mathbf{r}$ 的像素，$\hat{I}(\mathbf{r})$ 是场景表示渲染出的预测像素。<span class="marginnote">这条误差与第三篇 NeRF 的重建误差「长得一样」，但含义完全不同：NeRF 的位姿是「已知常数」，这里位姿是「正在被优化的变量」——<strong>「场景」与「相机」在同一个目标函数里互相纠错</strong>。这正是 SLAM 与离线重建的分水岭：离线是「先定位姿、再建场景」，在线是「同时求两者」。</span>

## 4 公式解析：SLAM 为什么能「同时定位与建图」

上面的 $\mathcal{E}_{\mathrm{frame}}$ 太简单，真实神经 SLAM 还要加两项，把它们拆开看：

- **第一项，重投影/光度误差**：上式的逐像素差异，负责「场景要像真实观测」。它是「建图」项——让表示贴着现实长。
- **第二项，位姿先验/平滑项**：相邻帧的位姿不能跳变，常加「恒定速度」或「IMU 预积分」约束。它是「定位」项——让轨迹平滑合理。
- **第三项，关键帧/局部地图约束**：不只与当前帧比，还定期与「过去的关键帧」比，防止「只盯着当下而忘了前面」——这是 SLAM 里「闭环（loop closure）」的思想：**认出「我回到了以前去过的地方」，就把累计漂移一次摊平**。

三项合起来，机器在每一时刻都在回答「我在哪 + 世界长什么样」——而两个答案互相咬合，越走越准。**「互相咬合」正是 SLAM 的精髓：定位帮助建图（知道相机在哪才渲染得对），建图帮助定位（场景对得上才知相机在哪），两个「病腿」互相搀扶着前进。**

这背后的数学结构也值得点破：联合优化（位姿 + 场景）本质上是一个**因子图（factor graph）**——每个观测帧是一条「因子」，连接着「相机节点」与「场景节点」；所有因子一起做一次稀疏非线性最小二乘，就是一次「全图优化」。SLAM 研究者常说的「滑窗」「后端优化」「闭环平差」，说的都是同一件事的**不同规模**：只优化最近几帧叫滑窗，优化所有历史叫全局平差。**把问题看成一张图，节点怎么连、哪些边该激活，就是 SLAM 的全部设计自由**——这个视角也能帮你读懂任何一篇 SLAM 论文的「系统架构」段落。<span class="marginnote">一个值得注意的工程现实：神经 SLAM 虽然优雅，但「一个 MLP/高斯场」的容量仍有限，跑整层楼都吃力；所以工业级 SLAM（ARKit、HoloLens）仍以「传统几何 SLAM + 深度网络增强」为主。<strong>「神经表示做 SLAM」是 2023 年后最火的研究方向，但离「替代手机里的 ORB-SLAM」还有距离</strong>——这提醒我们，学术热与工程熟是两回事。</span>

评判一个神经 SLAM 系统，可以用三条线：<strong>精度</strong>（ATI 轨迹误差、重建与真值的几何误差）、<strong>实时性</strong>（帧率与建图延迟）、<strong>鲁棒性</strong>（快速转动、运动模糊、无纹理走廊里是否崩）。当前的格局是「每条线都有赢家，但没人全胜」——iMAP 胜在简洁、SplaTAM 胜在实时画质、NICE-SLAM 胜在规模。<strong>选型看任务：导航看重精度，渲染看重画质，AR 看重实时</strong>——这又是「按目标选方法」的教科书案例。

## 5 核心对比表：离线重建 vs 在线 SLAM

| 维度 | 离线大规模重建 | 在线神经 SLAM |
| --- | --- | --- |
| 时序 | 先采集、后处理 | 边采集边处理 |
| 位姿来源 | SfM（COLMAP） | 实时估计 |
| 场景表示 | 分块 NeRF/高斯 | 单全局场/高斯 |
| 规模上限 | 很大（可加块） | 较小（受实时性限） |
| 误差行为 | 一次性整体平差 | 漂移需闭环纠正 |
| 代表 | Block-NeRF、MegaNeRF | iMAP、SplaTAM、GS-SLAM |
| 用途 | 数字孪生、城市漫游 | 机器人、手机 AR |

表中「规模上限」与「时序」两行是两者的核心权衡：**离线求「精与广」，在线求「活与快」**。空间智能的完整体系两者都要——机器人要在线 SLAM 实时避障，城市运营要离线重建做数字孪生，而 2024 年的方向是把「离线重建的精度」逐步压进「在线 SLAM 的实时」。

一个正在成形的融合愿景值得记录：**「云端离线建图 + 端侧在线定位」**。机器人不再自己跑完整 SLAM，而是先上传数据、由云端离线重建出一份高精度城市模型，端侧只需做「我在模型里的哪」的轻量定位——这正好复用本篇「分块索引」的思想：**把「重建」这个重活交给云，把「查询」这个轻活留在端**。它与第八篇空间计算平台的「云边协同」、第十二篇数字孪生的「一处建模、处处使用」完全同构——大规模空间智能的基础设施形态，正在收敛到同一个答案。

这个愿景也提醒我们注意「安全与隐私」这条暗线：城市级重建一旦规模化，就涉及**地图数据的所有权、位置隐私与敏感场所的遮蔽**——已有法规要求对军事区、民居做「脱敏」。**空间智能的工程问题从来不只是技术问题**；读本篇时可以把它当作第一次「技术落地前的社会性预演」，到第十二篇产业应用时我们再系统展开。

## 6 小结

- 规模带来三重挑战：**数据（采集与覆盖）、内存（表示放不下）、一致性（误差累积 + 光照/季节漂移）**，三者还会互相放大成「死亡螺旋」。
- 大场景重建有清晰代际：SfM/MVS 离散重建 → 神经隐式场 → 显式高斯 + 分块索引；每一代都继承「分块 + 索引 + 由粗到细」的骨架。
- 不同尺度对应不同架构：房间、街区、园区、城区是**四种系统设计**，不是同一个方法的四次放大。
- 离线路线靠**分块 + 索引 + 由粗到细**：Block-NeRF 分块、MegaNeRF 加场景图、Instant-NGP 哈希网格；接缝处理是质量试金石。
- 在线路线是**神经 SLAM**：iMAP → NICE-SLAM → SplaTAM/GS-SLAM，把 SLAM 从「导航工具」升级成「建图 + 渲染 + 导航三合一」。
- SLAM 的公式是「**光度误差 + 位姿平滑 + 关键帧闭环**」三项合成，本质是因子图上的稀疏最小二乘——定位与建图互相搀扶。
