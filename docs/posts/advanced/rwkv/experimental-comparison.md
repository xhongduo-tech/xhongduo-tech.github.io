## 为什么从实验对比开始

前七篇把 RWKV 的动机、原理、算子、位置表达、扩展路径全部拆完了。但架构论文的最后一问永远躲不掉：**它到底行不行？** 本文带读者读论文的实验部分——数据怎么配、基线是谁、在语言建模与下游任务上打到什么程度，以及在效率和推理成本上，RWKV 的结构性优势如何兑现为数字。<span class="marginnote">这是本专题的收官篇，也把前面所有概念（FLOP 对齐、WKV、恒定状态）拉回同一个战场：与同算力的 Transformer 正面对表。读实验时请始终带着一个问题——「这个优势是结构性的，还是工程调参的结果？」</span>

## 1 实验设置：谁跟谁比

论文的实验设计相当干净，关键的三条设定：

**数据**：全部模型在 **The Pile**（EleutherAI 整理的 800GB 级多源语料）上训练。选择 Pile 很关键——它同时是 Pythia 系列（EleutherAI）的训练语料，保证基线可比。
- **基线**：同 FLOP 预算下的 **Pythia**、**OPT**、**BLOOM** 三个 Transformer 家族。Pythia 与 RWKV 同语料，是最硬的对照；OPT/BLOOM 训练数据不同，作为参照。
- **模型**：第 7 篇那张表里的六个 RWKV（169M–14B），每个都有对应参数量级的 Transformer 基线。

这种"FLOP 对齐、同语料对齐"的设计，让差异主要归因于**架构本身**，而不是谁多用了算力或数据。

## 2 语言建模：困惑度打到什么水平

语言建模的主指标是**困惑度（perplexity，PPL）**——模型对测试语料赋予的平均负对数概率的指数。PPL 越低，模型越"懂"这段文本。

论文报告的核心结论是：**RWKV 的 PPL 与同规模的 Pythia 基本持平，且随着模型增大，两者的差距没有拉开。** 也就是说，在"把下一个词猜准"这个最基础的能力上，去掉注意力并没有让 RWKV 付出显著代价。

值得注意的细节：

- 在**较小规模**（169M–1.5B），RWKV 与 Transformer 的差距通常小于训练随机性造成的波动——说明线性注意力在小模型上并不吃亏。
- 在**大规模**（7B–14B），差距仍然被控制住，这支撑了"RWKV 可以像 Transformer 一样扩展"的主张。
- PPL 是一个**聚合指标**，它平滑了局部的优劣——长程主题一致、句法精细度这些具体能力，要结合下游任务看（见下节）。<span class="marginnote">读 PPL 的常见误区：PPL 直接取决于词表与分词器，跨不同词表的模型不能粗暴比较 PPL 小数位。论文的对比都在同一分词体系下进行，所以我们只需关注"趋势是否拉开"，而不是纠结 0.1 的差距。</span>

## 3 下游任务：12 项基准

困惑度之外，论文在 12 个 NLP 基准上评测了零样本 / 少样本能力，覆盖了阅读理解、常识推理、句子补全等类别，包括 ARC-Easy、ARC-Challenge、BoolQ、COPA、HellaSwag、LAMBADA、OpenBookQA、PIQA、ReCoRD、SciQ、Winogrande 等。

综合结果可以概括为一句：**RWKV 的表现曲线与 Pythia 高度贴近，并一致地优于 OPT 与 BLOOM。** 逐项看有几个值得玩味的模式：

**在依赖局部句法与模式匹配的任务上**（如 LAMBADA 的最后一个词预测），RWKV 与 Transformer 几乎无差别——这类任务吃的是局部上下文，线性注意力完全够用。
- **在需要长程证据检索的任务上**（如 BoolQ 这类阅读理解），RWKV 偶有下滑，但差距不大——逐通道衰减的"长记忆通道"部分补偿了缺失的显式注意力。
- **没有出现系统性崩溃**：没有哪一类任务让 RWKV 彻底失败，这比"平均打平"更说明问题——说明它的归纳偏置覆盖了语言建模的主要需求面。<span class="marginnote">横向联系：HellaSwag 与 LAMBADA 也是第三级《LLM 预训练》里评估模型时反复使用的基准。把两处的分数对照着看，能直观体会「架构选择」与「评测指标」之间的拉扯。</span>

## 4 推理效率：恒定状态的优势兑现

如果说语言质量是"不输"，推理效率就是 RWKV"大赢"的地方。两条结构性优势直接翻译成数字：

- **显存恒定**：Transformer 推理要缓存不断增长的 KV cache（每层 $2 \times T \times C$）；RWKV 每层只维护定长的 $(a_t, b_t)$ 状态。论文与社区实践报告，14B 的 RWKV 在 int8 量化下只需 **约 3GB 显存**就能在任意长度下持续生成——Transformer 在长上下文下远远做不到。
- **单 token 生成代价恒定**：Transformer 生成第 $t$ 个 token 要重新过一遍注意力（与全部 $t$ 个缓存交互），RWKV 只做一次 O(1) 状态更新。社区实测在 GPU 上长序列生成可达数量级加速，且由于不需要庞大的缓存，**RWKV 可以顺畅地在 CPU 上跑**——这是很多离线、端侧场景的刚需。

下面这张对比把推理代价模型摆在一起，是理解 RWKV 效率主张的钥匙（详见公式解析）。

$$
\begin{aligned}
C_{\text{Transformer}}^{(t)} &= 2N + 4t C_h H \quad &\text{（随生成步数 t 增长）} \\
C_{\text{RWKV}}^{(t)} &= 2N \quad &\text{（恒定）}
\end{aligned}
$$

## 5 公式解析：推理代价模型

把第 7 篇的 FLOP 讨论用到**自回归生成**上：生成第 $t$ 个 token 时，模型要对前 $t$ 个 token 做一次前向。

- **Transformer**：注意力项要跟 $t$ 个历史交互，成本 $4t C_h H$ 随 $t$ 增长；KV cache 占用的显存也随 $t$ 线性增长。序列越长，每个新 token 越贵。
- **RWKV**：WKV 递推只更新定长状态，成本恒定 $2N$；显存恒定。**序列长度不影响单步成本**——生成第 100 万个 token 与第 10 个 token 一样便宜。

这就是论文"10 倍量级推理加速"类主张的数学基础：不是常数因子的小优化，而是**把随 $t$ 增长的那一项整个删掉**。注意这个优势的兑现依赖长上下文——序列很短时，常数因子可能让差距不明显，这正是"短序列不赚、长序列大赚"的边界。

## 6 局限与讨论

作为一篇 2023 年的论文，实验部分也有它诚实的边界，读论文时值得一并看到：

- **评测以语言建模为主**：12 项基准偏"理解类"，对需要精确位置计数的任务（如"第 3 个词是什么"）RWKV 的软位置表达可能吃亏，论文没有展开这类压力测试。
- **长上下文压力测试有限**：当时的评测序列长度还不算极端，RWKV 在超长上下文（百万 token）下的表现主要由后续工作（RWKV-5/6/7）与社区实验补齐。
- **效率对比缺统一基准**：速度数字受实现、硬件、框架影响大，论文更多依赖复杂度论证而非标准化的端到端基准。
- **后续版本的分叉**：论文的 RWKV-4 是"纯线性递推"的极致形态；后来的 RWKV-5/6 又引入矩阵态（matrix state），RWKV-7 用动态状态演化进一步提升表达力——说明"纯线性"与"表达力"之间的权衡，至今仍在被探索。

### 一张表看懂：质量与效率的结论

把论文的结论浓缩成一张"质量 × 效率"的对照表，方便回看：

| 维度 | 结果 | 结构性原因 |
| --- | --- | --- |
| 语言建模 PPL | 与同规模 Pythia 持平 | 键指数 × 逐通道衰减足以建模序列分布 |
| 下游 12 项任务 | 贴近 Pythia、优于 OPT/BLOOM | 局部句法与长程主题都被覆盖 |
| 训练吞吐 | 与高效 Transformer 相当 | 线性递推可并行扫描，核函数通道并行 |
| 推理单 token 成本 | 恒定 $2N$，不随 $t$ 增长 | WKV 递推只有定长状态 |
| 推理显存 | 恒定（int8 14B 约 3GB） | 无 KV cache，只有 $(a_t,b_t)$ |
| 短板 | 精确位置计数、超长上下文压力测试 | 软位置表达、论文范围所限 |

这张表的结构很像第 4 篇里时间/通道混合的分工表：**每一项"赢"都能追溯到一个具体的架构设计，每一项"短板"也都能追溯到位置表达的软性。** 读论文最舒服的状态，就是能在"结论"与"设计"之间来回映射。

### 易错点辨析：「接近」不是「超越」

**辨析｜易错点：** 论文的措辞很克制——RWKV 与 Transformer 是"可比的"（comparable）、"接近的"（closely tracks），不是"全面超越"。这个措辞差异背后是严谨的方法论：

- 实验结论是**"没有显著变差"**，而不是"显著更好"。语言质量打平 + 推理效率领先，这是 RWKV 的主张；若宣称"质量也全面碾压"，就需要更多任务与重复实验来支撑。
- 效率优势也带条件：它随**序列长度与并发规模**放大。短序列、小 batch 下，常数因子与实现差异可能让优势消失。
- 任何单篇论文的实验都有边界（语料、调参、实现、硬件），把"在一组条件下的可比"读成"在所有条件下的更优"，就过度解读了。

一句话：**RWKV 的卖点是"在相近质量下换结构性的效率"**——评估它时，永远把这两个词放在一起看，缺一不可。

## 7 小结

- **设置**：六个 RWKV（169M–14B）在 The Pile 上训练，与 FLOP 对齐的 Pythia、OPT、BLOOM 对比。
- **语言建模**：PPL 与同规模 Pythia 基本持平，规模放大不拉开差距。
- **下游任务**：12 项基准上与 Pythia 贴近、优于 OPT/BLOOM；没有系统性崩溃，局部任务偶有下滑。
- **推理效率**：显存恒定、单 token 成本恒定；int8 的 14B 约 3GB 显存即可持续生成，CPU 可跑。
- **代价模型**：$C_{\text{Transformer}} = 2N + 4tC_hH$ 随 $t$ 增长，$C_{\text{RWKV}} = 2N$ 恒定——优势随上下文长度放大。
- **边界**：评测偏语言建模、软位置表达在精确计数上可能吃亏、超长上下文验证留给了后续版本。

至此，本专题用八篇博文走完了 RWKV 论文的完整弧线：从 RNN 与 Transformer 的宿命对决，到线性注意力、时间混合、通道混合、WKV 算子、时间衰减与位置编码、模型扩展，最后到实验答卷。**RWKV 的核心启示可以浓缩成一句话：把"显式的两两注意力"换成"可训练的逐通道指数衰减递推"，你就能同时拥有 Transformer 的并行训练与 RNN 的恒定推理——而语言建模质量几乎不打折扣。** 如果你想继续往下走，下一站可以进入第四级的《AI 基础设施》专题，看这类线性架构在集群训练与部署时如何落地；或者转向《状态空间模型》专题，认识 Mamba 这一支与 RWKV 同源而异流的邻居。
