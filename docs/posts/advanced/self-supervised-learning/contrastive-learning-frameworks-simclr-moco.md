## 为什么从「字典查找」开始

第 1 篇我们给自监督画了一张全局地图：生成式与对比式两大族。这一篇走进对比式的腹地。**对比学习（contrastive learning）** 的核心问题不是「怎么预测缺失」，而是「怎么区分」——把同一样本的不同视角拉近，把不同样本推远。SimCLR 与 MoCo 是 2020 年把这条思路变成视觉自监督主力的两个里程碑。它们共享同一个抽象：**把表征学习写成一个「字典查找」问题**——给一个查询（query），在一大堆候选键（key）里找出唯一正确的那一个。理解了这把钥匙，后面第 3 篇的 InfoNCE 损失、第 5 篇的 BYOL、乃至第 10 篇的 CLIP，都只是在这把钥匙上的不同转法。<span class="marginnote">本专题对标综述 Liu et al., TNNLS 2023 的 §3 正是以「对比学习的通用框架」为纲，把 SimCLR、MoCo 以及后来的 CMC、SwAV 等统一进同一张图——本篇就画这张图。</span>

## 1 对比学习的核心思想：把「区分」翻译成「检索」

先给定义。**对比学习（contrastive learning）**：通过「正样本对拉近、负样本对推远」来学习表征的自监督方法族。**正样本对（positive pair）** 来自同一个数据点的两个不同视角（由数据增强产生），**负样本对（negative pair）** 来自不同数据点。它有一个前提假设：数据的内在语义在增强后保持不变——一只猫的图再怎么裁剪、调色、加模糊，仍然是那只猫。

MoCo 论文把对比学习形式化为一个漂亮的比喻——**字典查找（dictionary look-up）**：给定一个查询 $q$（比如「某张猫图的一个视角」），要从一本字典 $\{k_0, k_1, \dots\}$ 里把与它语义相同的键 $k_+$（另一个视角）挑出来，同时排斥其余键（其他图像）。训练结束时留下的副产品——编码器——就是我们要的表征。

这个比喻的力量在于，它把「怎么做对比学习」拆成了三个独立的设计自由度：

1. **字典多大**——负样本的数量；
2. **键怎么编码**——编码器是否一致、是否稳定；
3. **怎么算「匹配」**——相似度函数与损失（第 3 篇专讲）。

SimCLR 与 MoCo 的分歧，恰好就落在这三个自由度上：一个把字典建在 batch 里，一个把字典建在队列里。

**辨析｜易错点：** 不要把自监督里的「数据增强」等同于传统监督里的「数据增广」。增广是为了「扩充样本量」；这里的增强是为了「制造正样本对」——它不是给数据「加量」，而是给学习目标「定义」——「什么是同一只猫」正是由增强管线定义的。这是第 1 篇「难度充分」原则的另一种表达：增强是让「捷径失效」的手段。

## 2 SimCLR：同一张图的两次变身

SimCLR（Chen et al., 2020, "A Simple Framework for Contrastive Learning of Visual Representations"）的名字里有个「Simple」——它的卖点就是配方简单：不要特殊架构、不要记忆库，一个编码器加一套增强就够了。

流程四步：

1. 取一张图 $x$，做两次随机增强，得到两个视角 $v_1 = t_1(x)$、$v_2 = t_2(x)$；
2. 编码器 $f(\cdot)$（如 ResNet-50）分别编码，得到 $h_1 = f(v_1)$、$h_2 = f(v_2)$；
3. 投影头 $g(\cdot)$（两层 MLP，把 2048 维压到 128 维）得到 $z_1 = g(h_1)$、$z_2 = g(h_2)$；
4. 在 $z$ 空间算对比损失（NT-Xent），batch 内其余样本的视图全部当负样本。

**增强管线是 SimCLR 最容易被低估的部分**：随机裁剪缩放 + 颜色扰动 + 高斯模糊，其中颜色扰动是「大杀器」——实验表明去掉它，ImageNet 线性评估要掉十几个点。为什么？因为图像里最容易让模型偷懒的捷径是「颜色直方图」——光靠颜色就能分对很多类，模型就不去学形状与语义了。颜色扰动把这个捷径堵死。<span class="marginnote">这与第 1 篇的「难度充分」原则直接呼应：增强不是「锦上添花」，而是「逼模型学语义」的核心手段。你还可以对照第 4 篇 MAE——MAE 用「遮蔽」堵住「像素插值」的捷径，SimCLR 用「增强」堵住「颜色」的捷径，殊途同归。</span>

两个关键设计值得单独说：

**投影头（projection head）**。训练时用 $z$ 算损失，训练完把 $g$ 丢弃，用 $h$（投影头之前的表征）做下游任务。实验证明这个「先投影、再对比、后丢弃」的操作值几个点精度——因为 $z$ 空间刻意滤掉了与对比无关的信息（如颜色、纹理），$h$ 因此更干净。这是「表征在哪一层迁移」的经典例子。

**batch 越大越好**。SimCLR 用 batch 4096、LARS 优化器、训练 1000 epoch，在 ImageNet 线性评估上达到 76.5%。负样本越多，对比越充分——§4 与第 3 篇会解释为什么。代价也很直观：batch 4096 需要专门的分布式优化器，显存开销巨大。

## 3 MoCo：动量编码器与「大字典」

SimCLR 的局限也在这里：**字典大小被 batch 锁死**。想要更多负样本，就得堆更大的 batch，显存与优化器都变得昂贵；而且 batch 内的「键」每个 step 都随编码器一起更新——字典一直在「晃动」。

MoCo（He et al., 2020, "Momentum Contrast for Unsupervised Visual Representation Learning"）把字典从 batch 中解放出来，用了两个办法：

**第一个办法：负样本队列（queue）**。把最近几个 batch 产出的键放进一个先进先出（FIFO）的队列，作为当前 batch 的负样本。队列长度（MoCo 用 65536）与 batch 解耦——想要更多负样本，直接调长队列，不增加当步的显存压力。<span class="marginnote">这个「用内存换字典」的招法与数据结构课上的「队列」完全同构（第三级《数据结构》）：元素先进先出，字典随训练缓慢翻新。区别只是队列里存的是高维嵌入，不是标量。</span>

**第二个办法：动量编码器（momentum encoder）**。队列里的键由另一个编码器 $f_k$ 产出，而 $f_k$ 的参数不用梯度更新，而是查询编码器 $f_q$ 的滑动平均：$\theta_k \leftarrow m\theta_k + (1-m)\theta_q$，$m = 0.999$。这个「慢速更新」保证了队列里的键来自一个「几乎不变」的编码器——它们是**一致的（consistent）**，不会像 SimCLR 那样每步全部翻新。

MoCo 论文把对比学习成功的要素总结为两条：**字典要够大，键的编码器要一致**。队列管「大」，动量管「一致」。有意思的是，MoCo v1 在 ImageNet 线性评估只有 60.6%，并不如当时的 SimCLR；但当 MoCo 吸收 SimCLR 的投影头与增强后（MoCo v2），一举达到 71.7%——这印证了两个框架其实是互补的：增强与投影头是「数据侧」的功夫，队列与动量是「结构侧」的功夫，合体才最强。

## 4 公式解析：对比损失与动量更新

对比家族共享同一个损失骨架（NT-Xent，InfoNCE 的简化写法）：

$$
\mathcal{L} = -\log \frac{\exp(q \cdot k_+ / \tau)}{\exp(q \cdot k_+ / \tau) + \sum_{j=1}^{K} \exp(q \cdot k_j^- / \tau)}
$$

逐项拆解：

- **$q$**：查询向量（SimCLR 的 $z_1$、MoCo 的查询嵌入）；
- **$k_+$**：正样本键——同一数据点另一视角的嵌入；
- **$k_j^-$**：第 $j$ 个负样本键（SimCLR 中是批内其余视图，MoCo 中是队列里的历史键）；
- **$q \cdot k$**：点积相似度。对 L2 归一化后的向量，点积即余弦相似度；
- **$\tau$**：温度参数，控制分布的锐利程度，第 3 篇专讲；
- **$K$**：负样本个数。

**整体含义**：这是一个 $(K+1)$ 类的 softmax 分类——在「1 个正样本 + K 个负样本」里认出正样本。梯度会同时把 $q$ 拉向 $k_+$、把 $q$ 从所有 $k_j^-$ 推开。它在数学上是「互信息下界」的估计（第 3 篇拆），在工程上是「检索式判别」的载体。

MoCo 的动量更新是第二个关键公式：

$$
\theta_k \leftarrow m\,\theta_k + (1-m)\,\theta_q, \qquad m = 0.999
$$

- **$\theta_q$**：查询编码器参数——接收梯度，学习得快；
- **$\theta_k$**：键编码器参数——不接梯度；
- **$m$**：动量系数。0.999 意味着键编码器每步只向查询编码器挪 0.1%，它几乎是「冻结」的，缓慢跟随。

为什么这个「慢」如此重要？对比学习里，负样本的特征必须来自「同一个世界」——如果键编码器每步剧烈变化，队列里的历史键就和当前查询「不在同一个语义坐标系里」，比较就失去意义。动量编码器把键编码器的更新压慢，让字典自洽。这也是「动量」名字的由来：物理里动量描述运动的惯性，这里指指标更新的惯性。

## 5 SimCLR 与 MoCo：一对互补的取舍

| 维度 | SimCLR | MoCo |
| --- | --- | --- |
| 负样本来源 | 批内其余视图 | 历史键队列（FIFO） |
| 字典大小 | 随 batch 增长（4096 → 约 8190） | 独立可调（65536） |
| 编码器 | 单一编码器，梯度更新 | 查询/键双编码器，键用动量更新 |
| 键的一致性 | 每 step 全部更新（「晃动」） | 动量保证缓慢演化（「稳定」） |
| 主要开销 | 大 batch + LARS + 长训练 | 队列内存 + 动量调参 |
| 主要风险 | batch 小则字典小 | 队列键陈旧（受动量控制） |

<span class="marginnote">把两栏并排看，真正的分歧是「键从哪来」：SimCLR 让键随查询一起快速演化（每一刻都是最新的，但字典小），MoCo 让键缓慢演化（字典大，但略旧）。第 5 篇 BYOL 的激进在于——它连「键」都不要了。这张对照表可以帮助理解为什么 BYOL 的出现如此反直觉。</span>

## 6 小结

- 对比学习 = 把表征学习写成「字典查找」：给定查询，在候选键中认出正样本、排斥负样本。
- 三个设计自由度：字典大小、键的编码方式、匹配的度量方式——SimCLR 与 MoCo 的分歧就落在这三点。
- SimCLR：单一编码器 + 数据增强 + 投影头，负样本全部来自 batch 内部，batch 越大越好。
- 增强与投影头是「数据侧」的关键：颜色扰动堵死颜色捷径，投影头滤掉与对比无关的信息。
- MoCo：FIFO 队列提供与 batch 解耦的大字典（65536），动量编码器保证键的一致性。
- 动量更新 $\theta_k \leftarrow m\theta_k + (1-m)\theta_q$ 让键编码器缓慢跟随查询编码器，字典自洽。
- 「字典要大、键要一致」——MoCo 对对比学习成功要素的两条总结。
- SimCLR 与 MoCo 互补：数据侧功夫与结构侧功夫合体（MoCo v2）效果最好。
