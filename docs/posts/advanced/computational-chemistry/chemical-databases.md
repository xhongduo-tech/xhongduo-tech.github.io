## 为什么从化学数据库讲起

机器学习势、QSAR、分子生成，全都依赖海量带标注的分子数据。这些数据散落在哪里、以什么格式组织、如何被查询与清洗，决定了建模的起点与天花板。**化学数据库（chemical database）**是化学信息学的地基：从小分子的 PubChem，到大分子结构的 PDB，再到反应数据库与材料数据库。这一节盘点主流数据库、它们的核心概念（标识、规范化、数据质量），以及如何把它们喂给下游计算任务。

## 1 数据库谱系：按数据对象分类

- **小分子数据库**：PubChem（1 亿+ 化合物，来自期刊、专利与各国机构）、ZINC（可购买的类药分子，主打虚拟筛选）、ChEMBL（**带生物活性标注**，是 QSAR 建模的核心金矿）。<span class="marginnote">PubChem 与 ChEMBL 的定位不同：PubChem 是「尽可能全」的化学实体档案（身份、物性、来源），ChEMBL 是「活性数据仓库」（化合物 + 靶标 + 活性值 + 实验条件）。<strong>做 QSAR 的答案库是 ChEMBL，不是 PubChem</strong>——因为建模需要「分子 + 活性标签」成对出现。</span>
- **大分子结构库**：PDB（蛋白质/核酸三维结构，~20 万+ 结构）、EMDB（冷冻电镜密度图）。PDB 是结构生物学的通货，也是对接、MD、机器学习结构预测（如 AlphaFold）的训练与验证数据源。
- **反应数据库**：Reaxys、USPTO（美国专利反应集）等，记录「反应物 → 产物」对，用于反应预测与逆合成。
- **材料数据库**：Materials Project、OQMD、AFLOW——带计算性质（带隙、形成能）的晶体结构库，支撑《材料计算化学》一节的机器学习工作。

## 2 标识与规范化：化学数据库的命脉

数据库的核心问题：**怎么确定「两个条目是同一个分子」**？答案是一套标识体系：

- **CAS 号**：传统人工登记号，商业数据库里广泛使用，但对应关系需人工维护。
- **InChI / InChIKey**：规范化字符串表示。**同一分子的任何写法（SMILES、2D/3D 结构、盐的拆解）都会规范化成同一个 InChI**——这是去重与跨库匹配的黄金标准。
- **规范化 SMILES（canonical SMILES）**：由同一算法生成的唯一 SMILES，用于库内去重。

**数据清洗是建模前最重要的步骤**：加氢、质子化态归一（pH 7.4）、盐与溶剂去除、互变异构归一、立体化学核对。<span class="marginnote">互变异构是去重的大敌：酮-烯醇互变让同一分子可能以两个不同结构入库。清洗管线需要先统一互变异构（如用标准规则选「最稳定形式」），否则同分异构体、互变异构体会在数据里重复计分，污染相似性搜索与 QSAR 标签。<strong>「拿到库直接开跑」是建模事故的常见源头</strong>。</span>

## 3 活性数据的结构：从 IC50 到标签

QSAR 与机器学习建模需要「分子 → 活性」的配对。ChEMBL 这类活性库的核心字段：

- **活性值**：IC50 / EC50 / Ki / Kd（浓度，常以 log 形式存，如 pIC50 = -log10(IC50)）。**活性必须转成负对数才适合回归**，因为浓度跨越多个数量级。
- **靶标信息**：靶蛋白、UniProt 标识、物种。
- **实验条件**：测定方法（酶活/细胞活）、pH、温度、溶剂。
- **数据质量标记**：ChEMBL 有「confidence score」区分直接测量与推导数据。<span class="marginnote"><strong>IC50 不是结合自由能</strong>：IC50 是「抑制 50% 活性的浓度」，依赖实验条件（底物浓度、竞争机制），不同实验间的 IC50 不可直接比较。而 Ki 是真正的平衡解离常数。做 QSAR 时把混合来源的 IC50 与 Ki 混进一个模型，是常见的系统性误差——<strong>标注来源与实验条件是数据工程的职责</strong>。</span>

## 4 数据库查询与检索：相似性 vs 子结构

化学数据库的检索分两类核心操作：

- **相似性搜索**：用指纹（上一节的 Tanimoto 系数）找「结构相近」的分子——用于先导化合物系列扩展、专利新颖性检查。可预计算指纹索引加速（如用倒排结构）。
- **子结构搜索**：找「包含某个片段」的分子（如所有含硝基芳香环的分子），用 SMARTS 模式匹配。这需要图同构算法（如 Ullmann、VF2），数据库会建子结构索引加速。<span class="marginnote">相似性搜索与子结构搜索是互补的：「相似」是连续量（结构相近），「子结构」是离散判断（含不含）。<strong>两者的实现差异极大</strong>——相似性靠指纹位运算 + 排序，子结构靠图同构。理解这个区别，你在选数据库/工具链时才不会拿错武器。</span>

## 5 数据规模与质量：机器学习的燃料

机器学习在化学中的成败，一半由数据决定。几个关键工程问题：

- **规模**：大模型时代的分子数据集——QM 属性（QM9：~13 万个小分子）、大分子（PDB：~20 万结构）、活性（ChEMBL：~2000 万活性值）。**数据量级决定你能用什么模型**：百万级才能训大图模型。
- **分布偏差**：ChEMBL 偏向已验证的活性化合物，化学空间采样不均；训练出来的模型外推到全新化学空间时会失效。
- **标注一致性**：同一分子不同实验给出不同 IC50（实验误差可差 10 倍），建模时需做多标签合并（取几何平均等）并估计噪声。<span class="marginnote">化学 ML 有一个「啤酒效应」式的困境：<strong>可用的数据越多，通常是因为某个体系被研究得越透彻——而这样的体系往往是「好做的」体系</strong>。用这种偏斜数据训练，模型会系统性偏爱热门化学。做性质预测时，务必报告训练集的化学空间覆盖度，这是审稿人关注的高频问题。</span>

## 6 数据获取与工程工具

- **API 访问**：PubChem 有 REST API（`https://pubchem.ncbi.nlm.nih.gov/rest/pug/...`），ChEMBL 有 Python 客户端（`chembl_webresource_client`），支持批量拉取活性数据。
- **本地化处理**：下载的 SDF/SMILES 用 RDKit 批量读取、清洗、计算描述符——这是标准流水线。
- **大文件格式**：SDF（带 3D 坐标的小分子标准格式）、SMILES 串文件、PDB/mmCIF（大分子结构）、HDF5（大批量 ML 数据）。
- **工具链**：RDKit（分子操作）、Open Babel（格式转换）、MDAnalysis / MDTraj（轨迹处理）、ASE（结构与原子模拟接口）。<span class="marginnote">工程上的一个高频陷阱是<strong>编码与换行</strong>：SMILES 文件在不同系统间的换行符差异、SDF 的空格填充规范，都可能让批量解析悄悄出错。<strong>建立「读入 → 校验（分子数、SMILES 合法性、理化性质范围）→ 处理」的流水线</strong>，比事后排查数据错误省心得多。</span>

## 7 数据质量评估：建模前的体检

拿到数据集先体检，再谈建模：

- **重复与矛盾**：同一分子多条活性记录（不同实验），取几何平均或按来源加权；跨库重复用 InChIKey 去重。
- **活性值分布**：pIC50 的分布是否覆盖足够范围？偏态分布会让回归模型偏向主流值。
- **活性悬崖（activity cliff）**：结构几乎相同但活性差几个数量级的分子对——它们是模型最难学、也最容易被高估的样本，需专门检查。
- **数据泄露**：训练/测试划分时，同一分子的不同盐/互变异构必须同属一边，否则测试成绩虚高。
- **标注缺失**：活性数据的实验条件（pH、方法）缺失时要标记，不能当完整数据用。<span class="marginnote">数据质量的底线判断：<strong>「垃圾进，垃圾出」在化学 ML 里比任何领域都真实</strong>——活性数据的实验误差可达 0.5–1 个 log 单位，而建模常常追求比这更细的精度。用「质量过滤 + 标注置信度」把不可靠样本排除，往往比换更好的模型更能提升真实性能。</span>

## 8 化学数据库的边界与未来

- **覆盖偏差**：ChEMBL/PubChem 偏向已知活性分子，化学空间采样远非均匀——训练出来的模型「见过」的化学空间有系统性偏好。
- **专利 vs 期刊**：专利数据的活性标注更粗糙、更容易带噪声，但覆盖面更广；两者融合需处理格式差异。
- **合成空间数据库**：可购买库（Enamine REAL）已达数十亿虚拟分子，但只有少数可实际合成——「可合成性」筛选成为新热点。
- **大模型时代的数据库**：知识图谱（反应 + 性质 + 文献）与向量检索的结合，正把「查数据库」升级为「查知识」。<span class="marginnote">数据库的「覆盖偏差」有一个深层后果：<strong>模型在热门化学空间过拟合、在冷门空间乱猜</strong>。负责任的做法是在论文里报告「模型适用域」（训练集的化学空间覆盖），并对冷门预测标注低置信度——这与《构效关系》一节的「适用域」概念是同一个纪律。</span>

## 9 数据使用规范与伦理

化学数据的使用越来越开放，也带来了几个必须正视的规范问题：

- **引用与出处**：每条数据的来源（期刊、专利、机构）必须可追溯——**数据没有出处，等于没有数据**。建模论文里应注明数据集版本与下载日期。
- **许可协议**：不同库的许可不同（CC0、CC-BY、专有），商用前必须核对。RDKit/PubChem 的开放政策与 ChEMBL 的许可各有边界。
- **数据质量责任**：下游模型的质量由上游数据决定，模型使用者有责任披露训练数据的偏差（种族/地域/化学类型偏差在医疗与材料预测里都真实存在）。
- **共享与复现**：按 FAIR 原则（可发现、可访问、可互操作、可复用）公开你清洗后的数据与代码——**让下游能复现，是数据工作者的职业底线**。<span class="marginnote">数据伦理有一个常被忽视的维度：<strong>「用脏数据训出的模型，可能比没有模型更有害」</strong>——它会给出「看起来精确」的错误预测，而用户无法分辨。负责任的数据实践不只是「上传数据」，还包括「标注数据质量、披露偏差、给出置信区间」。这条原则贯穿所有数据驱动的科学。</span>

### 一句话记住化学数据库

**「标识靠 InChI、活性看 ChEMBL、清洗是命门」**。跨库去重与匹配用 InChIKey，建模要活性数据去 ChEMBL，拿到任何库先过清洗管线（加氢、质子化态、去盐、互变异构）。数据地基不牢，上面的模型全是沙上之塔。

**速记要点**：
- 小分子库（PubChem/ZINC/ChEMBL）、大分子库（PDB）、反应库（Reaxys/USPTO）、材料库（Materials Project）。
- InChIKey 是跨库匹配黄金标准；pIC50 = -log10(IC50)。
- 相似性搜索靠指纹，子结构搜索靠图同构。
- 清洗管线（加氢、质子化、去盐、互变异构）是建模前第一关。
- 数据偏差要披露；数据没有出处等于没有数据。

**拓展思考**：数据库不只用来「取数据」，还用来「发现数据里缺什么」——统计 ChEMBL 里各化学类型的活性数据量，你就能画出「数据沙漠地图」，知道哪些化学空间建模还靠不住。**数据科学的一半工作，是先理解数据分布的形状**。

**本节启下**：有了可靠的分子表示与数据库，下一步就是把这些数据喂给建模——QSAR、图神经网络与分子生成都将以此为起点。

**一句提醒**：数据库是「别人整理的世界」，使用前永远先检查版本、许可与清洗状态——**别人留下的脏数据，不会因为你没看到而变得干净**。

## 10 小结

- 数据库按对象分：**小分子库**（PubChem、ZINC、ChEMBL）、**大分子结构库**（PDB）、**反应库**（Reaxys、USPTO）、**材料库**（Materials Project）。
- **标识与规范化**是数据库命脉：InChIKey 是跨库匹配的黄金标准，数据清洗（加氢、质子化态、去盐、互变异构）是建模前的第一关。
- 活性数据用 **pIC50 = -log10(IC50)** 才适合回归；IC50 与 Ki 混用是常见系统性误差。
- 检索分**相似性搜索**（指纹 + Tanimoto）与**子结构搜索**（SMARTS + 图同构），实现路径不同。
- 数据规模、分布偏差、标注一致性决定 ML 模型的天花板；**报告化学空间覆盖度是可靠建模的底线**。

在下一节，我们把这些数据真正喂给模型——**构效关系（QSAR）**，看经典的「分子结构 → 活性」回归建模如何设计与验证。
