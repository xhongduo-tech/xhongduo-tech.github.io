## 为什么从开放域问答开始

前三篇的 MRC 有个前提：**文档已经给定**。真实世界里没人给你「那篇该读的文档」——「比尔·盖茨的母校在哪」的答案可能藏在几十亿篇网页里的某一篇。**开放域问答（Open-domain QA）**不给定文档，让系统自己**从大规模语料里找到并读出答案**。它把「检索」与「阅读」组装成一个端到端可训的系统——这就是今天大模型 RAG（检索增强生成）的鼻祖。<span class="marginnote">开放域 QA 的两阶段框架（Chen et al., 2017《Reading Wikipedia to Answer Open-Domain Questions》）是里程碑：<strong>检索器（retriever）负责召回候选文档，阅读器（reader）负责从文档里抽答案</strong>。这个「先找后读」的分解，后来被 RAG（Lewis et al., 2020）推广成「检索 + 生成」，成为大模型时代的核心范式——本篇是理解 RAG 的关键一环。</span>

这一篇讲两阶段框架的每一环：检索器（稀疏 → 稠密）、阅读器（抽取式 → 生成式），以及它们如何联合评测。

## 1 两阶段框架：先找后读

**开放域 QA**：给定问题，从大规模语料库 $\mathcal{C}$（如整个维基百科）中找出答案。

**两阶段分解**：

1. **检索器（retriever）**：从 $\mathcal{C}$ 召回与问题相关的 Top-K 段落——把「几十亿段落」缩小到「几十段」；
2. **阅读器（reader）**：从 Top-K 段落里定位/生成答案——上一节的 MRC 模型直接复用。

**为什么拆成两段**：全库精读不现实（算力爆炸）；检索器用**廉价**的匹配先过滤，阅读器用**昂贵**的深度模型精读少量候选。**「粗筛 + 精读」是规模问题的标准解**（第二篇 KBQA 也用过）。<span class="marginnote">两阶段的瓶颈传导很清晰：<strong>检索召回率决定了 QA 的上限</strong>——答案段落没被召回，阅读器再好也答不出。因此开放域 QA 的改进往往先在检索器上做文章（稠密检索、多路召回），阅读器反而是「成熟组件」。理解这个「检索决定上限」的规律，就抓住了开放域 QA 的命脉。</span>

## 2 检索器：从稀疏到稠密

**稀疏检索（sparse retrieval）**：经典 **BM25**——词袋 + TF-IDF 加权 + 文档长度归一化。简单、可解释、无需训练，但对「语义相近、字面不同」的匹配无力（「创始人」vs「创立者」字面不同）。

**稠密检索（dense retrieval）**：**DPR**（Dense Passage Retrieval，Karpukhin et al., 2020）——把问题与段落各编码成向量，用**向量相似度**检索：

1. 双编码器：问题编码器 $E_Q$ 与段落编码器 $E_P$（各是一个 BERT 类模型）；
2. 离线：把全部段落编码成向量，建索引（向量检索，第四级《信息检索》的 ANN 技术）；
3. 在线：编码问题 → 与全部段落向量算相似度 → 取 Top-K。<span class="marginnote">稠密检索的关键优势是<strong>语义匹配</strong>：「微软的创始人」与段落「比尔·盖茨创立了微软」即使没有共同关键词，向量也相近——这突破了 BM25 的「字面匹配」天花板。DPR 的训练数据来自「问题-含答案段落对」（构造正样本）+ 同批次的负样本，这正是下一节的对比学习。</span>

**工程实践**：稀疏 + 稠密**多路召回**再融合，比单路稳得多——BM25 保字面、DPR 补语义。

## 3 公式解析：双编码器的对比学习

稠密检索的训练是**对比学习（contrastive learning）**——拉近「问题与正确答案段落」、推开「问题与负样本段落」。设问题 $q$、正样本段落 $p^+$、负样本段落 $p^-$，损失函数：

$$
\mathcal{L} = - \log \frac{ e^{\text{sim}(E_Q(q), E_P(p^+))} }{ e^{\text{sim}(E_Q(q), E_P(p^+))} + \sum_{k} e^{\text{sim}(E_Q(q), E_P(p^-_k))} }
$$

逐步拆解：

- **第一步，$\text{sim}(E_Q(q), E_P(p))$（相似度）**：问题向量与段落向量的点积（或余弦）——相似度越高，检索排名越靠前。
- **第二步，分子（正样本分）**：真实答案所在段落的相似度，希望它高。
- **第三步，分母（正 + 负样本分）**：正样本的相似度 + 所有负样本的相似度之和。**负样本来自哪里**：同批次的其他段落（in-batch 负样本）、BM25 挑的高分假段落（hard negative）——这是对比学习质量的关键。
- **第四步，$\log$ 比值**：这是 softmax 交叉熵——「正样本在所有候选里被选中」的负对数概率。优化它，就是让「正样本在检索结果里的排名尽量靠前」。

**直觉**：对比学习 = 「教检索器把正确答案段落排到最前面」。**负样本的选择决定学习难度**——全是简单负样本（随机段落）学不到判别力，配一点「像答案但不是答案」的难负样本，检索器才学得犀利。

## 4 阅读器：抽取式与生成式

**抽取式阅读器**：Top-K 段落各过一遍 MRC 模型（上一篇的 BERT 起止预测），取**所有段落里置信度最高的区间**作为答案。答案必须「在原文里」。

**生成式阅读器（RAG）**：把 Top-K 段落**拼进输入**，让生成模型（BART/T5）**直接生成答案**：

$$
P(a \mid q) = \sum_{z \in \text{Top-K}} P(z \mid q) \, P(a \mid q, z)
$$

答案 = 「检索到的段落 $P(z\mid q)$ 生成答案」的加权和——既用到了检索证据，又能生成原文没有的表述。<span class="marginnote">RAG 的公式里 $P(z\mid q)$ 是检索概率、$P(a\mid q,z)$ 是生成概率——<strong>检索与生成联合建模</strong>：检索给「证据」，生成给「表达」。RAG 是开放域 QA 从「抽取」走向「生成」的关键一跃，也开启了「检索增强生成」这个后来大模型系统的标准形态。你已经在第十二篇知识增强语言模型里见过它的思想萌芽。</span>

**抽取 vs 生成**：抽取**忠实可追溯**（答案有出处），生成**自然灵活**（能重述、能综合多段落）但可能幻觉。

## 5 评测与挑战

**评测数据**：**Natural Questions**（NQ，谷歌真实搜索问题）、**TriviaQA**（百科问答）、**WebQuestions**；中文有 **DuReader**、**CMRC-2019**。
**指标**：**精确匹配（EM）** 与 **F1**（同 SQuAD）；NQ 的答案短（实体/短语），EM 是主指标。

**四大挑战**：

**召回上限**：答案段落没被召回，系统必错——提升检索召回是第一优先；
**证据聚合**：答案的证据常分散在多个段落——阅读器要跨段落综合；
**无答案问题**：开放域里「没有答案」是常态，系统要会拒绝；
**幻觉**：生成式阅读器可能编造——答案与证据不一致时如何检测。<span class="marginnote">「证据聚合」是开放域 QA 与单文档 MRC 的关键差异：MRC 答案在一个段落里，开放域答案可能「微软成立于 1975」在 A 段、「创始人是盖茨」在 B 段——两段综合才是完整答案。现代系统用「重排序 + 多段落生成」处理，但仍是活跃的研究难点。</span>

## 6 从开放域 QA 到 RAG：大模型时代的延续

开放域两阶段框架的遗产，直接长成了今天的 **RAG**：

| 组件 | 开放域 QA（2017–2020） | RAG / 大模型时代 |
| --- | --- | --- |
| 检索器 | BM25 / DPR | 向量检索 + 多路召回 |
| 阅读器 | 抽取式 MRC | 生成式 LLM |
| 训练 | 两阶段分别训练 | 检索-生成联合或解耦 |
| 扩展 | 维基百科 | 企业知识库、私有数据 |

**核心思想不变**：**「先找证据，再给答案」**——大模型把「生成答案」这一环换成 LLM，检索器依然不可或缺（因为 LLM 的参数知识会过时、会幻觉，检索给它们「当下的事实」）。<span class="marginnote">理解开放域 QA，就等于理解了大模型时代的 RAG 原理：为什么「检索增强」能减少幻觉？因为它给模型<strong>证据</strong>，模型从证据上「照答」，而不是凭记忆编。这也解释了为什么「从极限到大模型」的课程里，RAG 的核心组件（检索、编码、阅读）都在前面的专题里出现过——它们是同一套技术的不同组装。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

**检索器决定了上限，阅读器决定下限**：检索召回率高但阅读器差 → 有答案但读不出；检索召回率低 → 答案根本进不来。评测时**分别报检索召回率与阅读准确率**，别只报端到端 EM。<span class="marginnote">自检：你的开放域系统 EM 低，先看是「检索没召回」（召回率低）还是「召回但没读对」（阅读 F1 低）——两个瓶颈的修法完全不同。</span>
- **稠密检索不是「免费的语义」**：DPR 的训练依赖「问题-段落」标注（从 QA 数据里构造），数据质量决定检索质量。没训好，稠密检索可能还不如 BM25。
- **对比学习的负样本要「难」**：全是随机负样本，模型学不到判别力；配一些「高相似但不是答案」的难负样本（hard negative），效果才显著提升。
- **生成式答案要「忠于证据」**：RAG 生成可能脱离检索到的段落（幻觉）。评测生成式 QA 时，检查「答案能否在证据里找到依据」——只报 ROUGE 会掩盖幻觉。

## 8 小结

- **开放域 QA**：不给定文档，从大规模语料里找答案——「先找后读」的两阶段框架。
- **检索器**：稀疏（BM25，字面匹配）→ 稠密（DPR，语义匹配）；多路召回更稳。
- **双编码器对比学习**：拉近问题-正段落、推开负段落——负样本要「难」。
- **阅读器**：抽取式（BERT 起止预测，忠实）→ 生成式（RAG，自然灵活但可能幻觉）。
- 评测：NQ/TriviaQA；指标 EM/F1；挑战：召回上限、证据聚合、无答案、幻觉。
- **RAG 延续**：检索 + 生成是今天大模型系统的标准形态——先找证据、再给答案。
