## 为什么从基于转移的解析开始

上一篇的 CYK 一次填一张大表，把整句的所有可能结构都算出来再选最优——**全局搜索**。基于转移的方法换一种思路：**把解析当成「逐步搭树」的动作序列**，每一步做一个小决定（把词推进栈、在两个词之间画一条弧），几步之内拼出一棵完整的依存树。<span class="marginnote">CYK 是「全局、完备、慢」，转移解析是「局部、贪心、快」。前者 $O(n^3)$，后者只 $O(n)$——对长句、对实时系统，速度是决定性优势。MaltParser（Nivre 等人，2003 起）把转移解析系统化，一度是依存句法的事实标准。</span>

这种「把复杂问题拆成一系列小决策」的思想，与第三级《机器学习》里的自回归生成、第十篇 Seq2Seq 解码一脉相承：**每步只做一次分类**。理解转移解析，你就理解了「结构化预测的贪心路线」。

## 1 转移系统：解析即动作序列

**基于转移的依存解析（transition-based dependency parsing）**把「构造一棵依存树」定义成一个**状态机**：从初始配置出发，不断执行**转移动作（transition）**，直到达到终态。每个动作都是一个小步（压栈、建弧……），动作序列的终点就是一棵完整的树。

三个关键组件：

- **配置（configuration）**：解析过程的当前状态，由「栈 + 缓冲区 + 弧集」三件套刻画；
- **转移集合（transition set）**：允许执行的动作集合；
- **转移函数**：配置 + 动作 → 新配置，定义每个动作的效果。

**核心问题变成：每一步选哪个动作？** 这一步通常用一个分类器（统计时代用 SVM/感知机，神经时代用神经网络）来做——给定当前配置的特征，预测「最该执行的转移」。**所以转移解析的学习 = 学一个「动作分类器」**。

## 2 配置：栈、缓冲区与弧集

一个配置记作 $c = (\sigma, \beta, A)$：

- **栈 $\sigma$**：已经「读过」但还没处理完的词，从栈顶往下排。栈顶是我们当前最关注的词。
- **缓冲区 $\beta$**：还没读进来的词序列，从左到右。
- **弧集 $A$**：已经建立的依存弧集合（每条弧是「中心词 → 依存词」带标签）。

**初始配置**：栈空、缓冲区是整句词、弧集空。**终态**：缓冲区空、栈里只剩根节点（或特定结构）。从初始到终态，每执行一个动作，配置更新一次。

```
栈: [ ]           缓冲区: [我, 爱, 猫]        弧: {}
```

处理「我 爱 猫」时，过程大致是：压「我」进栈 → 压「爱」→ 判断「我 爱」的关系建弧 → 压「猫」→ 建弧 → 结束。<span class="marginnote">栈与缓冲区是经典的数据结构（第三级《数据结构》），在这里扮演「工作记忆」与「输入流」。栈顶的词是「最近关注的词」，缓冲区头部是「下一个待处理词」——解析的本质就是在这两个容器之间倒腾词、同时记录它们的关系。</span>

## 3 Arc-Standard：三种动作

**Arc-Standard（Nivre，2004）**是最经典的转移系统，只有三种动作：

- **SHIFT**：把缓冲区头部的词压进栈。$(\sigma, w|\beta, A) \to (\sigma|w, \beta, A)$。
- **LEFT-ARC**：在栈顶两个词之间建一条弧——**栈顶第二个词是中心词**（头），栈顶第一个词是依存词（尾），然后把依存词弹出栈。$(\sigma|u|v, \beta, A) \to (\sigma|u, \beta, A \cup \{u \to v\})$。
- **RIGHT-ARC**：与 LEFT-ARC 相反——**栈顶第一个词是中心词**，栈顶第二个词是依存词。$(\sigma|u|v, \beta, A) \to (\sigma|v, \beta, A \cup \{u \to v\})$。

用「我 爱 猫」走一遍：

1. SHIFT：栈 `[我]`，缓冲 `[爱, 猫]`；
2. SHIFT：栈 `[我, 爱]`，缓冲 `[猫]`；
3. SHIFT：栈 `[我, 爱, 猫]`，缓冲 `[]`；
4. LEFT-ARC(爱→我)：栈 `[爱, 猫]`，弧 `{爱→我}`；
5. RIGHT-ARC(爱→猫)：栈 `[爱]`，弧 `{爱→我, 爱→猫}`。

三句 SHIFT、两句 ARC，一棵以「爱」为根的树就搭好了。**Arc-Standard 的约束**：每步最多建一条弧，且**只处理栈顶两个词**——它建出的树保证是**投影性**的（弧不交叉）。<span class="marginnote">关键性质：Arc-Standard 建弧时，LEFT-ARC 把依存词从栈里弹出，意味着<strong>该词的左右依赖都已完成</strong>——这保证它只能建「栈内相邻词之间」的弧，天然投影。想处理非投影结构（如英语的 wh 移动），就要 Arc-Eager 或额外机制。</span>

## 4 Arc-Eager：四种动作

**Arc-Eager（Nivre，2003）**比 Arc-Standard 多一个动作，代价是更灵活：

- **SHIFT**：同上，压缓冲区头进栈。
- **LEFT-ARC**：在**缓冲区头与栈顶**之间建弧——**缓冲区头是中心词**，栈顶是依存词，然后弹出栈顶。$(\sigma|u, w|\beta, A) \to (\sigma, w|\beta, A\cup\{w \to u\})$。
- **RIGHT-ARC**：在**栈顶与缓冲区头**之间建弧——**栈顶是中心词**，缓冲区头是依存词，然后把缓冲区头**压入栈**。$(\sigma|u, w|\beta, A) \to (\sigma|u|w, \beta, A\cup\{u \to w\})$。
- **REDUCE**：把栈顶弹出——**栈顶词的右侧依赖已全部完成**，退场。

**注意 Arc-Eager 的 LEFT/RIGHT-ARC 都不要求两个词同时在栈里**——它可以让「栈顶」与「缓冲区头」直接建弧，因此能处理非投影结构，解析也更灵活。<span class="marginnote">两种系统的速度差异：Arc-Standard 每步建弧都要等两个词都进栈，Arc-Eager 在词还在缓冲区时就能建「左弧」。实际效果上 Arc-Eager 动作序列略长，但对非投影语言（捷克语、德语、部分汉语结构）鲁棒得多。</span>

## 5 公式解析：贪心转移解析与动作分类器

转移解析的每一步，本质是一次**多分类**：给定当前配置 $c$，从动作集合里选一个。用判别式模型（神经时代用 MLP/双仿射打分）对每个候选动作打分：

$$
a^* = \arg\max_{a} \, \text{score}(a \mid c)
$$

拆解：

- **第一步，$\text{score}(a \mid c)$（动作打分）**：度量「在当前配置 $c$ 下执行动作 $a$ 有多合适」。特征来自配置的三件套——栈顶词、缓冲区头词、它们的词性、已有的弧、甚至左右邻居（神经版直接喂词向量与上下文表征）。
- **第二步，$\arg\max_a$**：取分最高的动作执行。配置更新，进入下一轮。
- **第三步，贪心**：每一步只选局部最优，**不回退、不回溯**——这就是「贪心（greedy）」的含义，也是转移解析 $O(n)$ 快的根源。
- **第四步，解码结束**：达到终态，弧集 $A$ 就是输出树。

**重点：贪心是双刃剑。** 好处是快、简单；坏处是**错误会积累**——第 5 步建错一条弧，后面所有决策都在错误的基础上做。改进办法是 **beam search**：每步不只保留 1 个最优配置，而是保留 $k$ 个（束宽 $k$），最后在终态里挑全局分最高的——用内存换回一些全局性。<span class="marginnote">贪心 vs 集束是解码的永恒权衡，你在第十六篇《文本生成的解码策略》还会见到：贪心快而短视，束搜索稳而稍贵。转移解析的 beam 与文本生成的 beam 是同一个思想。</span>

## 6 训练：oracle 与错误传播

转移解析的训练需要**正确答案的动作序列**——从标注树库（如 Universal Dependencies）里怎么得到？

- **oracle（神谕）**：给定一棵目标树，**模拟**转移系统在它约束下「最该走的动作序列」——每个配置下，若树里要求栈顶两词建弧，就输出 LEFT/RIGHT-ARC，否则输出 SHIFT。这样每棵训练树都转成一条「标准动作序列」，分类器照此学。
- **动态 oracle**：标准 oracle 只给「全局最优」的动作，但贪心过程常在「非最优但可救」的配置里——动态 oracle 允许「还能通向最优树的动作」也算对，训练更稳健。<span class="marginnote">oracle 是把「树的正确性」翻译成「动作序列的正确性」的桥梁——没有它，转移解析无从训练。动态 oracle（Goldberg & Nivre 2013）让分类器学会「在偏离最优时如何挽回」，是提升鲁棒性的关键改进。</span>

神经时代的转移解析（如 2014 年 Chen & Manning 的 neural greedy parser）用词向量 + 栈/缓冲区上下文的稠密表征替换手工稀疏特征，准确率大幅提升，但**贪心 + 错误传播**的结构性短板仍在，直到下一篇基于图的方法用「全局打分」补上。

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

- **LEFT-ARC 与 RIGHT-ARC 的中心词方向别搞反**：Arc-Standard 的 LEFT-ARC 是「**栈顶第二个词**当中心词」，RIGHT-ARC 是「**栈顶第一个词**当中心词」。方向反了，整棵树就反了。<span class="marginnote">记法：LEFT-ARC = 左边的词作中心词（指向右）；RIGHT-ARC = 右边的词作中心词（指向左）。标签（nsubj/obj）随弧方向一起确定。</span>
- **Arc-Standard 建不了非投影弧**：它只允许「栈顶相邻两词」建弧，非投影结构（弧线交叉）必须用 Arc-Eager 或其他系统。用错系统会直接失败。
- **贪心没有「重来」机会**：一步错步步错，所以 beam search 几乎总是值得加。别指望贪心单跑就达到最优。
- **SHIFT 不是「什么都不做」**：它是「把下一个词纳入考虑」，是解析的必要步骤。动作序列里 SHIFT 数量 ≈ 句长，别把它当空操作忽略。

## 8 小结

- 转移解析 = **把解析变成动作序列**：配置（栈、缓冲区、弧集）→ 执行转移 → 终态得树。
- **Arc-Standard**：SHIFT / LEFT-ARC / RIGHT-ARC 三动作，只能建投影树，$O(n)$ 贪心。
- **Arc-Eager**：加 REDUCE 四动作，栈顶可与缓冲区头直接建弧，支持非投影结构。
- 动作选择 = **每步一次多分类**：$\text{score}(a\mid c)$ 打分取最大；贪心快而短视，beam search 补救。
- 训练靠 **oracle** 把目标树翻译成标准动作序列；动态 oracle 提升鲁棒性。
- 与 CYK 对照：全局完备 vs 贪心快速；后续基于图的方法将用全局打分兼取两者之长。

在下一节，我们走另一条依存解析路线：**基于图的方法与神经依存解析器**——直接给「每对词之间的弧」打分，用全局最优化替代贪心。
