## 为什么从实体链接开始

NER 找到了「苹果」是人名还是组织——但这还不够：文本里的「苹果」可能指水果、苹果公司、还是「苹果日报」？**NER 只给类型，实体链接（Entity Linking, EL）要落到「具体是哪一位」**——把文本里的实体指称（mention）链接到**知识库**（如维基百科/Wikidata）中的**唯一条目**。<span class="marginnote">NER 回答「这是什么类型的实体」，EL 回答「这个实体在知识库里是哪一个」。一个是「分类」，一个是「解析到唯一身份」。后者是知识库导向的——这也是 MUC/ACE 之后，TAC-KBP 评测把 EL 推向主流的背景。</span>

这一篇讲 EL 的任务定义、流水线四步与核心的**消歧**机制。它是连接文本世界与知识库世界的桥，也是第十二篇知识图谱问答（KBQA）的输入保障。

## 1 从 NER 到实体链接

一条文本走到 EL，需要经过「指称识别 → 候选生成 → 消歧 → 链接」：

> 「乔布斯在 2007 年发布了 iPhone。」

**指称（mention）**：「乔布斯」——被 NER 识别为 PER；
**知识库条目（entity）**：史蒂夫·乔布斯（维基百科条目）；
**链接（link）**：把「乔布斯」→ 史蒂夫·乔布斯。

**实体链接与 NER 的差别**：

NER 输出类型（PER），EL 输出**具体条目 ID**（Q19835）；
同一个指称可能链接到不同条目——「苹果」在句子 A 链接水果、在句子 B 链接苹果公司；
EL 必须处理 **NIL**（知识库里没有的指称——需要新建条目或聚成「NIL 簇」）。<span class="marginnote">NIL 处理是 EL 的独有难点：真实文本里大量实体不在知识库中（尤其长尾实体）。系统的做法是把无法链接的指称聚成「NIL 簇」——同一指称（同文、同写法、同上下文）的归为一簇，供后续人工建条目。</span>

## 2 流水线四步

EL 的标准流水线：

1. **指称检测（mention detection）**：找出候选实体指称——通常直接复用 NER 结果，或额外识别「与知识库条目同名的文本串」；
2. **候选生成（candidate generation）**：为每个指称从知识库**召回**可能的候选条目——靠「名称词典」「别名表」「重定向」；
3. **实体消歧（entity disambiguation）**：从候选里**选出最匹配**的条目——EL 的核心；
4. **NIL 处理**：无匹配时聚成 NIL 簇。

前三步是「召回-排序」结构——候选生成要**高召回**（别漏掉正确条目），消歧要**高精确**（别选错）。这与信息检索（第四级《信息检索》）的检索-排序框架完全同构。<span class="marginnote">「先召回一大批、再精细排序」是信息检索的核心思想（第四级专题），EL 把它用在「实体消歧」上：名称词典保证不漏（召回），上下文相似度保证选对（排序）。这个「粗筛-细选」的两段式，在几乎所有「链接/匹配」类任务里都是标配。</span>

## 3 候选生成：名称词典与维基红利

候选生成靠「**名称 → 条目**」的映射表。英语里维基百科给了天然的宝藏：

**锚文本（anchor text）**：维基内部链接的显示文字——「苹果」链接到苹果公司条目，锚文本「苹果」就记录了「苹果 → 苹果公司」；
**重定向（redirect）**：「Apple Inc.」重定向到苹果公司条目；
**消歧页（disambiguation）**：一个名称多个条目时，消歧页列出全部候选。

把这些汇集起来，就得到一张**名称词典**：

```python
# 名称词典：名称 → 候选条目集合（由锚文本、重定向、消歧页汇集）
name_dict = {
    '苹果':  {'苹果公司', '苹果（水果）', '苹果日报'},
    '乔布斯': {'史蒂夫·乔布斯'},
    'Python': {'Python（编程语言）', 'Python（爬行动物）'},
    'Apple': {'苹果公司', '苹果（水果）'},
}
# 召回：为指称取出候选条目，供后续消歧排序
candidates = name_dict.get('苹果', set())   # {'苹果公司', '苹果（水果）', '苹果日报'}
```

中文没有现成的维基锚文本规模时，要用别名库、音译规则、或从知识库描述里挖「别名」。<span class="marginnote">候选生成的质量直接决定消歧的上限——<strong>正确条目不在候选里，消歧再好也白搭</strong>。因此候选生成追求「宁可多召、不可漏召」：常用策略是名称词典 + 字符串近似（编辑距离）+ 音译匹配。召回率是这一步的生命线。</span>

## 4 公式解析：实体消歧的评分

实体消歧给「指称 $m$（含上下文）→ 候选条目 $e$」打分，选最高分：

$$
e^* = \arg\max_{e \in C(m)} \; \lambda_1 \underbrace{\text{prior}(e \mid m)}_{\text{先验}} + \lambda_2 \underbrace{\text{sim}(\text{ctx}(m), \text{desc}(e))}_{\text{上下文-描述相似度}}
$$

逐步拆解：

- **第一步，$\text{prior}(e\mid m)$（先验）**：指称 $m$ 在训练数据（锚文本统计）里**多常链接到 $e$**——「苹果 → 苹果公司」的先验远高于「苹果 → 苹果日报」。它捕捉「最常见的链接对象」。
- **第二步，$\text{sim}(\text{ctx}(m), \text{desc}(e))$（上下文相似度）**：指称所在句子的上下文，与候选条目的描述（维基首段）的**语义相似度**——「今天水果店里的苹果」上下文与水果条目描述更像。这是判别「这一次到底指谁」的证据。
- **第三步，$\lambda_1, \lambda_2$ 加权**：先验与上下文证据的权衡（可学习或经验设定）。**先验是「通常指谁」，上下文是「这次指谁」**——两者结合，兼得「常见」与「当前」。
- **第四步，$\arg\max$**：候选集 $C(m)$ 里选分最高者；若最高分低于阈值，判 NIL。

**直觉**：消歧 = 「先验（多数时候是谁）× 证据（这次上下文像谁）」的双重确认。上下文相似度用嵌入（第五篇）或预训练模型计算——把「句子里的苹果」与「苹果公司的描述」都编码成向量，算余弦相似度。

## 5 基于嵌入的实体链接

现代 EL 靠**嵌入相似度**大幅提升：

- **文本嵌入**：指称上下文编码成向量 $q$；
- **实体嵌入**：知识库条目编码成向量 $e$（用条目描述、共现图训练——第十二篇的 TransE 一类）；
- **打分**：$s(m, e) = q \cdot e$——上下文与条目语义越近，分越高。

预训练模型（BERT 类）的做法更直接：把「上下文 + 候选条目描述」拼起来过模型，二分类「匹配/不匹配」——精度比纯嵌入高，但每个候选要过一遍模型、较贵。<span class="marginnote">这又是「浅层嵌入 vs 深层模型」的权衡：浅层嵌入快（一次算好向量、批量点积），深层模型准（每个候选精细判断）。工业系统常两者结合——嵌入做<strong>粗排序</strong>筛掉大多数候选，深层模型对 Top-K 做<strong>精排序</strong>。</span>

## 6 挑战与评测

**评测**：**准确率**（链接到正确条目的指称占比）；TAC-KBP 的 EL 任务还评测 NIL 聚类。对「无指称检测」的纯消歧任务，直接报消歧准确率。
**经典数据**：AIDA/CoNLL-YAGO（新闻）、TAC-KBP 评测数据、中文有 **NLPCC** 与基于百度百科/维基的语料。

**四大挑战**：

**歧义与主题漂移**：同一指称在不同领域指不同实体（「Python」= 蛇/语言/人名）；
**长尾与缺失**：大量实体不在知识库，NIL 处理难；
**多语言**：不同语言的指称映射到同一实体（跨语言 EL）；
**动态更新**：知识库不断变（新公司、新歌），指称-条目映射要跟上。<span class="marginnote">主题漂移是 EL 最经典的难点：「乔丹」在体育新闻里是迈克尔·乔丹，在商学院报道里可能是经济学家迈克尔·乔丹。全局上下文（整篇文章的主题）比局部句子更关键——好的 EL 系统会用「文章主题先验」约束消歧。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

**候选生成失败 = 消歧上限为零**：正确条目不在候选集里，再强的消歧也救不回。评测时先看「候选召回率」，再谈消歧准确率。<span class="marginnote">一个常被忽略的数字：很多 EL 系统的候选召回率只有 90% 出头——这意味着即使消歧 100% 正确，整体也只有 ~90%。提升候选召回（更好的名称词典、模糊匹配）往往比抠消歧模型更划算。</span>
- **先验不是「正确的概率」**：锚文本统计的 $\text{prior}(e\mid m)$ 是「这个写法历史上链接到谁」，会被维基的写作者偏好带偏。别把先验当真理，它只是「常见的默认值」。
- **NIL 不是「随便不链接」**：判 NIL 需要有依据（最高分低于阈值、候选都不匹配）——把「不会做」当成「没有」，会系统性丢实体。
- **上下文窗口不是越大越好**：消歧证据常在指称**局部**（前后几词），但主题信息在**全篇**。只取小窗口会漏主题线索，只取全篇会稀释局部证据——分层利用（局部 + 全局）才是正解。

## 8 小结

- **实体链接**：指称 → 知识库条目的唯一解析，是文本世界与知识库世界的桥。
- 流水线四步：**指称检测 → 候选生成 → 实体消歧 → NIL 处理**。
- 候选生成靠**名称词典**（锚文本、重定向、消歧页）；召回率决定消歧上限。
- 消歧打分：先验 $\text{prior}(e\mid m)$ × 上下文-描述相似度 $\text{sim}$，加权取最大。
- 现代 EL：**嵌入相似度**做粗排，预训练模型做精排。
- 挑战：主题漂移、长尾缺失、多语言、动态更新；评测看准确率 + 候选召回。
