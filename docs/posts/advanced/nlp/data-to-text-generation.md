## 为什么从 Data-to-Text 开始

「今天晴，气温 25–31 度，偏东风 3 级」——这句天气预报是从一堆气象数据「翻译」出来的。**数据到文本生成（data-to-text generation）**：把**结构化数据**（表格、数据库记录、知识图谱、传感器时序）转成自然语言文本。它是 NLG 里「忠实度」要求最高的一类——**数据是事实，文本不能说错**。<span class="marginnote">Data-to-Text 是最早工业化的 NLG：天气报告（1970s 就有）、体育赛事播报、财报解读、病历小结——这些「数据 + 固定模板」的任务天生适合自动化。它也是「文本生成 vs 事实准确」矛盾的集中爆发地——一句话把 25 度说成 30 度，天气报告就废了。</span>

这一篇讲 Data-to-Text 的输入形态、核心难点（内容选择与忠实度），以及端到端建模与评测。

## 1 从数据到文字：任务与形态

**Data-to-Text**：输入**结构化数据**，输出**描述性文本**。

常见输入形态：

- **表格**：一行行记录（球队战绩表 → 比赛报道）；
- **知识图谱三元组**：`(球队A, 击败, 球队B)` → 「球队A击败了球队B」；
- **数据库记录**：传感器读数、交易记录；
- **时序数据**：股价曲线、气象数据。

**输入的特点是「结构化、离散、事实明确」**——每个数据点都是一个「事实」，文本的任务是**把这些事实组织成连贯的话**。与「自由生成」的最大区别：**文本有确定的内容依据**——不能说数据里没有的东西。

## 2 内容选择：该说什么

数据很多（一支球队有几十项统计），文本不能全说——**内容选择（content selection）**决定「哪些数据进入文本」。

- **选择标准**：显著性（重要的先说）、相关性（与主题有关）、新颖性（别重复）、用户需求（用户关注什么）；
- **排序**：选出的内容按什么顺序讲——时间序、重要度序、逻辑序。

**内容选择是 Data-to-Text 的第一难点**：选多了文本冗长，选少了漏关键，选错了答非所问。<span class="marginnote">内容选择对应经典 NLG 流水线的「内容确定」步骤（第一篇讲过）。端到端模型把它「隐含」进了生成——模型自己决定「提哪些数据」，这让「内容选择的正确性」很难单独评测，也容易出「该说的没说、不该说的说了」的问题。</span>

## 3 公式解析：结构化输入的编码

端到端 Data-to-Text 的关键一步：**怎么把结构化数据喂给神经网络**。表格/图谱不是「文本序列」，需要**线性化（linearization）**：

$$
\mathcal{L}(D) = \big[ \text{field}_1 : \text{value}_1 ;\; \text{field}_2 : \text{value}_2 ;\; \dots \big]
$$

把每条记录展平成「字段 : 值」的 token 序列，再作为条件 $c$ 喂给 Seq2Seq：

$$
P(\text{文本} \mid \mathcal{L}(D)) = \prod_t P(y_t \mid y_{<t}, \mathcal{L}(D))
$$

逐步拆解：

- **第一步，线性化 $\mathcal{L}(D)$**：把结构化数据**摊平**成文本 token——「球队: A; 比分: 3; 对手: B; 赛事: 决赛」。这是「结构化 → 序列」的桥。
- **第二步，特殊分隔符**：字段名与值之间、记录与记录之间用分隔 token（`:`, `;`）隔开——让模型知道「这是什么字段、值到哪结束」。
- **第三步，条件生成**：Seq2Seq 把线性化数据当输入，生成文本。**模型学会「从数据序列 → 自然语言」的映射**——把「比分: 3」翻译成「A 队以 3 分获胜」。
- **第四步，图谱输入**：知识图谱三元组类似地线性化（`(头, 关系, 尾)` 展平成 token），或用图编码器（第四级《图神经网络》）——用图结构而非展平，保留关系信息。

**直觉**：Data-to-Text 的建模 = 「把数据摊平 + Seq2Seq 翻译」——**本质是结构化数据与文本之间的「翻译」**，与第十篇 NMT 共用同一骨架。

## 4 忠实度：数据的头号难题

**忠实度（faithfulness）**是 Data-to-Text 的生死线：**生成文本的事实必须与输入数据一致**。

「球队A 击败 球队B，比分 3:2」——生成的文本必须说「A 胜 B」；说成「B 胜 A」就是**幻觉（hallucination）**。

**幻觉的来源**：

- 模型「自由发挥」：数据里没有的信息被「脑补」（模型见过类似数据，把其他场景的细节搬来）；
- 数据理解错：把「主队」当「客队」；
- 过度泛化：从「连续 3 场获胜」推成「本赛季全胜」——数据只支持前者，文本却说后者。

**忠实度治理**：

- **内容规划先行**：先显式选择内容（确定「要说什么事实」），再生成——减少模型自由发挥；
- **事实验证**：生成后把文本「回查」数据——NLI（第九篇）判断「文本是否被数据蕴含」；
- **受约束生成**：解码时约束「数据里的关键值（球队名、比分）必须出现」——把事实「钉死」。<span class="marginnote">「受约束生成」是数据到文本里最实用的忠实度手段：数据里的实体与数值（球队名、比分、日期）是「必须说对的事实」——解码时把这些 token 的生成概率<strong>钳制</strong>（强制出现），或事后检查「数据里的每个关键值是否都在文本里」。<strong>把「该对的」焊死，是忠实度治理的第一道防线</strong>。</span>

## 5 端到端 vs 模块化

Data-to-Text 的建模路线延续「模块化 vs 端到端」之争：

- **模块化**：内容选择 + 句子规划 + 表面实现分开做——内容可显式控制（说哪些数据），忠实度有保障，但流程繁琐；
- **端到端**：一个 Seq2Seq 从数据直接生成——灵活、免工程，但「内容选择」隐式化，忠实度难控。

**现代趋势**：预训练模型（T5/BART）做端到端为主，**配合内容规划与事实验证**补忠实度——「端到端生成 + 忠实度护栏」是当前主流配方。<span class="marginnote">一个值得注意的反差：纯粹的数据到文本（天气、体育）其实<strong>模块化/模板依然好用</strong>——数据形态固定、文本结构固定，「模板 + 槽值」既忠实又便宜。端到端模型的优势在「数据形态多样、文本需要灵活」的任务（如跨领域报告）。<strong>别为简单任务上重型模型</strong>——这是工程里常被忽略的务实判断。</span>

## 6 评测与数据集

- **数据集**：
  - **E2E**（餐厅点评）：属性表 → 点评文本；
  - **WebNLG**：知识图谱三元组 → 文本（多语言）；
  - **WikiBio**：维基百科信息框 → 生平简介（大规模）；
  - **RotoWire**：NBA 比赛统计表 → 体育报道（长文本，忠实度挑战大）。
- **评测**：
  - **BLEU/ROUGE**（与参考文本的重合，测流畅与内容）；
  - **忠实度指标**：**基于 NLI 的事实性检测**、人工判断「文本是否忠于数据」——Data-to-Text 评测的独特之处是**忠实度必须单独测**，不能只看 BLEU。<span class="marginnote">RotoWire 的「幻觉」是著名现象：早期端到端模型生成的比赛报道流畅但满是编造（球员没上场却说上场、比分对不上）——BLEU 还不低。这逼着社区开发「事实性评测」——把生成文本与数据记录比对，查「数据里没有的断言」。<strong>忠实度评测从 Data-to-Text 开始成为生成评测的标配维度</strong>。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

- **「忠实」≠「流畅」**：一段数据报告可以「通顺但全是错的」——忠实与流畅是两个维度。只看 BLEU 会奖励「流畅的编造」。<span class="marginnote">自检：把生成文本里的每个「事实断言」（球队名、比分、日期）与输入数据逐条核对——数据里找不到依据的断言就是幻觉。这是忠实度的「人工版」评测。</span>
- **线性化的顺序有影响**：数据记录的排列顺序（哪个字段先）会**引导生成的内容顺序**——「比分在前」生成先提比分。线性化顺序是数据到文本的一个隐藏超参数。
- **字段名是「条件」，不是「要生成的文本」**：模型要「翻译」数据成自然语言，不是复述「球队: A」——线性化输入里的字段名是给模型的「线索」，不是输出的一部分。
- **别把「模板」当「生成」**：固定模板 + 填槽（天气、体育简讯）是「组装」，端到端是「生成」——两者忠实度与灵活度不同，别混为一谈（模板忠实但死板，生成灵活但要控忠实）。

## 8 小结

- **Data-to-Text**：结构化数据（表格/图谱/数据库）→ 自然语言——NLG 里忠实度要求最高的一类。
- 输入形态：表格、图谱三元组、数据库记录、时序。
- **内容选择**（说什么、按什么顺序）是第一难点——端到端把它隐式化。
- 建模 = **线性化 + Seq2Seq**：$P(\text{文本}\mid\mathcal{L}(D))$——把结构化数据当「翻译的源语言」。
- **忠实度**是生死线：幻觉治理靠内容规划、事实验证（NLI）、受约束生成。
- 数据：E2E、WebNLG、WikiBio、RotoWire；评测：BLEU/ROUGE + **忠实度单独测**。
