## 为什么从构建技术开始

上一篇勾勒了知识图谱的全貌，这一篇深入**构建的核心环节**——图谱里的实体、关系与属性，是怎么从文本里「长」出来的。构建技术是第十一篇信息抽取的直接延续：NER、实体链接、关系抽取在这里被整合成一条「文本 → 图谱」的流水线。<span class="marginnote">知识图谱构建的本质是「非结构化 → 结构化」的批量转换，而 NLP 技术是这条转换链的主角。理解构建技术，就等于理解了「IE 技术如何被组织成工业系统」——这是第十一篇各子任务的实战集成。</span>

这一篇讲构建流水线的四段：**实体获取、关系获取、属性获取、质量保障**——以及它们各自的 NLP 技术。

## 1 从文本到知识图谱的流水线

把一篇文档变成图谱里的若干三元组，标准流水线是：

```
文本 → [实体识别 NER] → [实体链接/消歧] → [关系抽取] → [属性抽取] → [质量校验] → 图谱三元组
```

每一段各用一个（或多个）第十一篇的技术：

| 流水线段 | 主要 NLP 技术 | 输出 |
| --- | --- | --- |
| 实体识别 | NER（第六/十一篇） | 实体跨度 + 类型 |
| 实体链接/消歧 | 实体链接（第十一篇） | 指称 → 图谱节点 ID |
| 关系抽取 | 有监督 RE / 远程监督 / Open IE | `(实体1, 关系, 实体2)` |
| 属性抽取 | 属性值识别（「成立于 1975」→ 成立年份: 1975） | 实体属性 |
| 质量校验 | 冲突检测、去重、置信度过滤 | 可信三元组 |

**重点：流水线每段都会犯错，错误沿链累积**——NER 漏了实体，关系就抽不出来；链接错配，图谱里就是错的节点。这与第十一篇流水线架构的错误级联是同一个问题。<span class="marginnote">工业界的应对是「多路抽取 + 融合」：同一份文本用多种抽取器（NER 用不同模型、关系用监督+远程监督），再把多个结果<strong>投票融合</strong>——比单一流水线稳得多。这是构建工程与「纯论文模型」的一个显著区别。</span>

## 2 实体获取：从 NER 到实体对齐

实体获取分三步，越往后越难：

1. **NER**：找出「哪些词是实体」——第十一篇讲过，BiLSTM-CRF / BERT 微调是标准；
2. **实体链接**：把指称对到知识库条目——「乔布斯」→ `Steve_Jobs`（第十一篇实体链接篇）；
3. **实体对齐（entity alignment）/ 实体消解（entity resolution）**：**把不同来源的实体合并**——DBpedia 里的「北京」与 Wikidata 里的「北京」是不是同一个？「北京」「北京市」「Beijing」三个节点该不该并成一个？<span class="marginnote">实体对齐是构建中最「脏」的活：要处理<strong>同义</strong>（北京/北京市/Beijing）、<strong>异写</strong>（简繁、音译）、<strong>同名异指</strong>（两个不同的「王伟」）。算法上用「属性相似度 + 邻居相似度 + 嵌入相似度」打分，超过阈值合并——本质上与第十一篇实体链接是同一类「匹配」问题，只是跨数据源。</span>

**实体获取的质量直接决定图谱的下限**：节点错了，后面所有关系都挂在错误节点上。

## 3 关系与属性获取

**关系获取**：判定实体对之间有没有关系、是什么关系。三种路线（第十一篇关系抽取篇详述）：

- **有监督 RE**：精确、规范，但需要标注数据；
- **远程监督**：知识库自动标注、覆盖广，但有噪声；
- **Open IE**：无 schema、覆盖任意关系，但输出不规范。

**属性抽取**：把「实体的属性值」从文本中抽出——「微软成立于 1975 年」→ `微软 (成立年份, 1975)`。属性抽取与关系抽取本质同构（属性 = 一种特殊关系，属性值 = 尾实体），常共用同一套模型。

**多源融合**：图谱通常不止从文本建，还从**结构化数据**（数据库、表格）与**半结构化**（百科模板、JSON）导入——**多种来源的实体/关系要做对齐与冲突消解**：数据库说微软 1975 年成立、百科说 1976，信谁？<span class="marginnote">冲突消解没有银弹：按<strong>来源可信度</strong>加权（百科可信度 > 自动抽取）、按<strong>时间戳</strong>取新、或保留多值。工程上常记「证据（source + confidence）」——图谱里每一条边都该能追溯出处，这是可信图谱的底线。</span>

## 4 公式解析：实体对齐的相似度

实体对齐的核心是给「两个实体候选是否同一」打分。设实体 $e_1$ 与 $e_2$，综合相似度常写成三部分加权：

$$
\text{sim}(e_1, e_2) = \lambda_1\, \text{sim}_{\text{name}} + \lambda_2\, \text{sim}_{\text{attr}} + \lambda_3\, \text{sim}_{\text{embed}}
$$

逐步拆解：

- **第一步，$\text{sim}_{\text{name}}$（名称相似度）**：字符串相似度——「北京」vs「北京市」的编辑距离很近（插入「市」），「北京」vs「Beijing」要靠音译/翻译映射。这是最粗糙也最便宜的信号。
- **第二步，$\text{sim}_{\text{attr}}$（属性相似度）**：比较两实体的属性重叠——「成立年份、总部、创始人」都相同，强烈提示同一实体。
- **第三步，$\text{sim}_{\text{embed}}$（嵌入相似度）**：实体嵌入（下一篇 TransE 一类的向量）的余弦相似度——两个实体的「语义邻居」越像，越可能同一。嵌入捕捉**结构相似性**（属性之外的邻居关系）。
- **第四步，加权 + 阈值**：总分超过阈值判定合并。权重 $\lambda$ 与阈值从「标注的对齐对/非对齐对」里学出来。

**直觉**：实体对齐 = 「名称（表面） + 属性（内容） + 结构（邻居）三重证据投票」。单靠名称会漏掉「北京/Beijing」，单靠结构会被「同名不同人」骗——**多信号加权**是对齐算法的定式。

## 5 本体学习与 schema 发现

构建还要处理一个「上层」问题：**schema（本体）从哪来？** 除了人工设计，也有自动发现的路线——**本体学习（ontology learning）**：

- **概念聚类**：把语义相近的实体聚成类型——从「北京、上海、广州」归纳出「城市」；
- **关系类型归纳**：从高频关系短语归纳关系类型——Open IE 的「创立了」「创建了」归一化为「创始人」；
- **is-a 层次发现**：从「苹果是水果」学出「苹果 ⊂ 水果」的上下位关系（Hearst 模式，第十一篇）。

本体学习让 schema 可以**从数据里长出来**，缓解「人工设计 schema 慢、覆盖不全」的问题。<span class="marginnote">本体学习与第八篇句法分析的「规则→统计」转向有相似的逻辑：先人工、后自动。但本体学习至今仍是辅助——<strong>完全自动的 schema 设计很难保证语义正确</strong>，工业界主流仍是「人工设计核心 schema + 自动补充子类型」。</span>

## 6 质量保障

图谱建成后，质量是生死线：

- **准确性（accuracy）**：三元组是否真实——人工抽检 + 冲突检测；
- **一致性（consistency）**：图谱内是否自洽——「比尔·盖茨 出生在 1955」与「比尔·盖茨 年龄 25」矛盾，要检测；
- **完整性（completeness）**：是否覆盖目标领域——与外部知识源对比，发现缺失；
- **时效性（timeliness）**：关系是否过时——「苹果 CEO」在 2020 年前后不同。

**自动错误检测**：用「三元组在语料里的支持度」（有多少独立文本佐证）、图谱的**逻辑一致性**（推理出不矛盾结论）、以及**表示学习打分**（下一篇 TransE 会给可疑三元组低分）来筛选。<span class="marginnote">表示学习打分做错误检测是个聪明的循环：TransE 一类的模型学「正常三元组的模式」，对「不正常的」给低分——于是模型既用于补全（第五篇）又用于纠错。<strong>同一个嵌入，既能填空又能挑错</strong>，这是知识表示学习的一鱼两吃。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

- **实体对齐不是「字符串去重」**：同名不一定同实体（两个「王伟」），异名可以是同实体（北京/Beijing）。靠编辑距离做对齐，会又漏又错。<span class="marginnote">记忆：对齐判的是「同一真实世界对象」，不是「同一写法」。字符串只是证据之一，不是答案本身。</span>
- **远程监督的噪声会「污染图谱」**：自动标注的关系有假阳性，直接入图谱会积累错误。远程监督结果必须配置信度过滤与人工抽检。
- **多源冲突不是「谁对」而是「可信度」**：数据库与百科冲突时，别武断取一——按来源权重、时间戳、证据条数综合裁决，并保留出处。
- **schema 改了，数据要迁移**：构建初期 schema 设计不周，后期加类型要处理已有数据的兼容。schema 是「改起来很贵的先验」——先想清楚再定。

## 8 小结

- 构建流水线：**NER → 实体链接 → 关系抽取 → 属性抽取 → 质量校验**——IE 技术的集成。
- **实体获取**三步：NER、实体链接、实体对齐/消解——对齐是跨源合并的难点。
- **关系/属性获取**：有监督 / 远程监督 / Open IE 三路线；属性与关系共用一套模型。
- 对齐打分：名称 + 属性 + 嵌入三重相似度加权 $\text{sim}=\lambda_1\text{sim}_{\text{name}}+\lambda_2\text{sim}_{\text{attr}}+\lambda_3\text{sim}_{\text{embed}}$。
- **本体学习**：从数据自动归纳类型、关系与 is-a 层次——辅助人工 schema。
- 质量四维：**准确性、一致性、完整性、时效性**；表示学习打分可同时用于纠错与补全。
