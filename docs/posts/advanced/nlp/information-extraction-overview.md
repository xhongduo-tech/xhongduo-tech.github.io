## 为什么从信息抽取概述开始

前面十篇教的都是「理解」——分词、句法、语义、翻译。**信息抽取（Information Extraction, IE）**的目标更直接：**从非结构化的文本里，抽出结构化的知识**——「比尔·盖茨创立了微软」→ `(比尔·盖茨, 创立, 微软)` 这样的三元组。它是把「读懂」变成「可用数据」的工程，也是知识图谱（第十二篇）、问答（第十三篇）的上游。<span class="marginnote">信息抽取是 NLP 里「离数据最近」的分支：它的输出不是给人看的句子，而是给机器查的知识。从 1987 年起，美国国防部的 MUC 评测与后来的 ACE 评测用「能不能抽准」检验 NLP 系统——IE 是 NLP 历史上第一个「以评测驱动」的规模化研究范式。</span>

这一篇先把 IE 的**任务版图**、**评测历史**与**系统架构**讲清楚，为后面六篇（NER、实体链接、关系抽取、事件抽取、指代消解、开放 IE）立好框架。

## 1 什么是信息抽取：从非结构化到结构化

**信息抽取（IE）**：从自由文本中自动识别**命名实体**、它们之间的**关系**与参与的事件，并表示为结构化形式（元组、图、表格）。

对比输入与输出：

- **输入**：「苹果公司今天在加州库比蒂诺发布了新款 iPhone，库克主持了发布会。」
- **输出**（结构化事实）：
  - 实体：`(苹果公司, 机构)`、`(加州库比蒂诺, 地点)`、`(iPhone, 产品)`、`(库克, 人)`；
  - 关系：`(苹果公司, 总部位于, 库比蒂诺)`、`(库克, 任职于, 苹果公司)`；
  - 事件：`发布(发布方=苹果公司, 发布物=iPhone, 时间=今天, 地点=库比蒂诺)`。

**本质**：IE 把「一段话」翻译成「一张知识小图」。它是文本与知识库（第十二篇）之间的桥梁。<span class="marginnote">一句话概括 IE 与「理解」的区别：语义分析回答「这句话什么意思」，IE 回答「这句话里有什么事实可提取」。同一个句子，理解是目的，抽取是手段——抽取结果直接可入库、可查询、可推理。</span>

## 2 四大核心子任务

IE 的任务版图由四个子任务构成，本篇后四篇逐一展开：

1. **命名实体识别（NER）**：找实体 + 打类型（人名/地名/机构/时间/金额……）——第六篇的序列标注框架直接可用；
2. **关系抽取（Relation Extraction）**：判定实体对之间的关系——`(苹果公司, 总部位于, 库比蒂诺)`；
3. **事件抽取（Event Extraction）**：识别事件触发词、事件类型与参与论元——`发布(时间, 地点, 发布方, 发布物)`；
4. **指代消解（Coreference Resolution）**：把「他」「该公司」这类指代词还原到所指实体——「库克主持了发布会」里的「库克」与上文「苹果公司的 CEO」是同一个。

**重点：这四个子任务不是孤立的**——NER 是关系与事件的输入，指代消解让实体保持一致。工业系统的 IE 常把它们串成**流水线**（第四节）。

## 3 从文本到知识：IE 的形式化

IE 的最终产物是**事实元组**。最核心的形式是**关系三元组**：

$$
\text{Fact} = (\text{实体}_1, \text{关系}, \text{实体}_2)
$$

例如 $(\text{比尔·盖茨}, \text{创立}, \text{微软})$。更完整的**事件结构**是一组论元：

$$
\text{Event} = (\text{触发词}, \text{类型}, \{(\text{论元角色}, \text{实体})\})
$$

例如 $(\text{发布}, \text{产品发布}, \{(\text{发布方},\text{苹果公司}), (\text{发布物},\text{iPhone}), (\text{时间},\text{今天})\})$。

**把文本映射成元组的数学描述**：设文本 $T$，实体集合 $\mathcal{E}$、关系集合 $\mathcal{R}$、事件集合 $\mathcal{V}$，IE 学习映射 $f: T \to (\mathcal{E}, \mathcal{R}, \mathcal{V})$。**每个事实元组可以看成「文本中的一个局部断言」**——后续知识图谱（第十二篇）就是把海量元组组织成图并推理。<span class="marginnote">这个「文本 → 元组」的映射，是 IE 与语义解析（第九篇）的接合点：语义解析产出的逻辑形式也能转成元组，但 IE 的元组更「工程化」——不追求完备的语义，只追求「可入库的事实」。</span>

## 4 评测会议：MUC 与 ACE

IE 的每一次飞跃都与评测会议绑在一起：

- **MUC（Message Understanding Conference，1987–1998）**：美国国防部资助，任务从「模板填充」起步——把海军军事情报文本里的舰船、事件填进固定模板。**MUC 定义了 IE 的基本任务形态**：命名实体、共指、模板元素、场景模板。它让「可评测的 IE」成为可能，也催生了 NER 的经典标注（MUC 的实体类型被沿用至今）。
- **ACE（Automatic Content Extraction，2000–2009）**：美国 NIST 组织，任务升级为**实体检测与跟踪、关系检测、事件检测**，并把评测扩展为「端到端」——从文本直接产出结构化的实体/关系/事件图。<span class="marginnote">ACE 相对 MUC 的关键进步：一是<strong>跨文档</strong>（同一实体在多篇文本里追踪），二是<strong>任务体系化</strong>（实体—关系—事件统一评测），三是<strong>双语</strong>（英语、中文、阿拉伯语）。中文 IE 研究大量基于 ACE 中文语料。</span>
- 后来的 TAC-KBP 把 IE 进一步推向知识库（实体链接到维基/Wikidata，见「实体链接」篇）。

**评测指标**：各子任务用「精确匹配」或「宽松匹配」的 **F1**（正确识别数、召回数与查准数的综合，第十九篇详述）——`(实体, 类型)` 全对才算一个正确实体。

## 5 流水线架构：四段式

经典 IE 系统是**流水线（pipeline）**，四段依次推进：

1. **预处理**：分词、词性标注、句法分析（第三、八篇）——给下游提供特征；
2. **实体识别与消解**：NER 找实体，指代消解把「他/它/该公司」归并到同一实体；
3. **关系抽取**：对实体对判关系（分类或抽取）；
4. **事件抽取**：识别事件触发词、类型与论元。

**流水线的优点**：模块清晰、各段可独立改进；**缺点**：错误沿流水线累积（NER 错 → 关系必错），且各段无法共享中间信息。<span class="marginnote">流水线的错误传播与第八篇句法「解析→下游」的问题同构。神经时代开始尝试<strong>联合模型</strong>——一个网络同时输出实体与关系（如「标注实体 + 关系序列」的联合解码），减少级联错误。但流水线因其模块化、可调试、可替换，仍是工业系统的主流。</span>

## 6 信息抽取的应用

- **知识图谱构建**（第十二篇）：IE 是把非结构化文本变成知识图谱三元组的主要途径；
- **问答系统**（第十三篇）：抽取出的结构化事实可直接用于事实问答；
- **舆情与情报分析**：从新闻、报告中抽取「谁、何时、在哪、做了什么」；
- **搜索引擎增强**：抽取实体与关系，改进查询理解与知识卡片；
- **金融/医疗**：从财报、病历中抽取结构化字段。<span class="marginnote">一个务实观察：IE 的工业价值取决于「抽取结果的准确性是否够格入库」。因此工业 IE 更看重<strong>高精确率</strong>（宁缺毋滥）——抽错一条事实比漏掉十条更致命。这是 IE 系统设计与评测的一个重要取向。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

- **NER 是 IE 的地基，不是 IE 的全部**：只做 NER 不算完整 IE——实体之外的关系、事件、共指才是 IE 的完整版图。别把「识别出人名」当作「抽取了知识」。
- **关系与事件的「槽位」不是句法成分**：关系三元组的元素是**实体**，事件论元是**实体 + 角色**——不是主语/宾语（第八篇的句法成分）。语义角色（第十篇）与事件论元有重合，但事件论元更具体（绑定事件类型）。<span class="marginnote">对照：SRL（第十篇）标注「谓词的论元角色」，事件抽取标注「事件模板的槽位」。前者是语言学视角，后者是任务视角——事件模板（如「产品发布」需要发布方/发布物/时间）是应用定义的。</span>
- **评测「精确匹配」很严**：实体边界差一个字（「苹果公司」vs「苹果」）就算错。跨系统比较时要看清是精确匹配还是宽松匹配。
- **IE 输出是「事实」，不等于「真理」**：抽取出的三元组是文本的断言，可能含错误、矛盾或过时信息——入库前需要校验与去重（第十二篇知识图谱会讨论）。

## 8 小结

- **IE**：从非结构化文本抽取结构化事实（实体、关系、事件），是文本到知识的桥梁。
- 四大子任务：**NER、关系抽取、事件抽取、指代消解**——层层递进、相互依赖。
- 输出形式：**事实元组** `(实体1, 关系, 实体2)` 与事件论元结构。
- 评测历史：**MUC**（模板填充、奠定任务形态）→ **ACE**（跨文档、任务体系化）→ **TAC-KBP**（知识库导向）。
- 流水线四段：预处理 → 实体识别与消解 → 关系 → 事件；错误级联是软肋，联合模型是趋势。
- 应用：知识图谱、问答、舆情、搜索、金融医疗；工业界重**精确率**。
