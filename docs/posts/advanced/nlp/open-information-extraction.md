## 为什么从 Open IE 开始

前六篇的关系与事件抽取都有一个前提：**关系类型是预先定义好的**（schema）。但真实世界的文本里，关系千变万化——「他抗议价格上涨」「咖啡因会让人失眠」……没有哪个 schema 能穷尽所有关系。**开放域信息抽取（Open Information Extraction, Open IE）**彻底卸掉这个枷锁：**不预设关系类型，直接从任意文本里抽取「（论元1, 关系短语, 论元2）」三元组**。<span class="marginnote">Open IE 由华盛顿大学 Banko 等人 2007 年提出（TextRunner 系统），口号是「无需人工标注、无需预定义 schema」——它把 IE 从「按图索骥」变成「照单全收」。对有监督 RE（第十一篇）来说，schema 是约束也是天花板；Open IE 用「关系短语（relation phrase）」替代「固定类型」，突破了天花板。</span>

这一篇讲 Open IE 的任务定义、规则方法与神经方法、以及它的评测与挑战。

## 1 从固定 schema 到开放抽取

对比两种 IE 的哲学：

**有监督 RE**（上一篇）：预先定义关系集合 $\mathcal{R}$（创始人、任职于……），模型把实体对分类到 $\mathcal{R}$——**精确但封闭**：$\mathcal{R}$ 之外的关系一概抽不出。
**Open IE**：不设 $\mathcal{R}$，把「关系」本身作为**可抽取的内容**——从文本里抽出「谁做了什么」的自由三元组。

**Open IE 的输出**：

> 「莫扎特创作了《安魂曲》。」
> → （莫扎特；创作了；《安魂曲》）

> 「小明的抗议导致了会议推迟。」
> → （小明的抗议；导致了；会议推迟）——论元甚至可以是事件性短语，不只是命名实体。

**核心区别**：关系是「抽取出来的短语」而非「分类到预定义类」。这让 Open IE 能覆盖无限关系，代价是输出**不规范**（同一关系可以有无数种说法：创作了/写过/是……的作者）。<span class="marginnote">Open IE 与有监督 RE 是「广度 vs 精度」的取舍：Open IE 覆盖全、但三元组噪音多、关系表达不统一；有监督 RE 精确、规范，但 schema 外一片空白。工业上常两者结合——Open IE 做<strong>冷启动挖掘</strong>，有监督 RE 做<strong>规范入库</strong>。</span>

## 2 论元与关系短语

Open IE 的三元组由两部分组成：

**论元（argument）**：参与关系的「东西」——不限于命名实体，可以是名词短语（「这场暴雨」）、事件（「小明的抗议」）、甚至整句；
**关系短语（relation phrase）**：表达关系的**动词/介词短语**——「创作了」「导致了」「是……的创始人」。

**抽取的难点**：论元的边界（「莫扎特」vs「著名的作曲家莫扎特」）、关系短语的多词性（「是……的创始人」横跨多个词）、以及论元之间的**连接结构**（「小明给小红送了一本书」= 送书(小明→小红) 还是 送书(小明→书)？）——这些都需要句法/语义证据。<span class="marginnote">Open IE 与第十篇 SRL 有亲缘：SRL 的「谓词 + 论元角色」结构，Open IE 把「角色」换成「自由的关系短语」。事实上不少 Open IE 系统直接借用句法分析（第八篇依存树）找「动词 + 主宾语」作为抽取骨架。</span>

## 3 基于规则与模式的方法

第一代 Open IE 靠**模式/规则**从句法结构中抽取：

**TextRunner**：自监督——从语料自动学习「可信的动词模式」，再按模式抽取。
**ReVerb**：用**句法约束**（关系短语必须是动词短语、长度受限）过滤噪声，并处理「关系短语过长」的问题——比 TextRunner 精确。
**Ollie / ClausIE**：基于**依存句法**的规则——ClausIE 先找句子的**子句（clause）**结构，再按「主语-动词-宾语/补语」的固定模式抽出多个三元组。<span class="marginnote">ClausIE 的思路很有代表性：<strong>先把句子按句法拆成子句，再在每个子句里按固定模板抽三元组</strong>。它不训练模型，只靠第八篇的句法分析 + 规则模板，却能达到相当高的精确率——「规则在结构规整的句子上依然能打」是 Open IE 的持久经验。</span>

**规则方法的优点**：零标注、可解释、精确率高；**缺点**：依赖句法分析质量、复杂句式（被动、从句、并列）容易漏抽或抽错。

## 4 公式解析：神经 Open IE 的论元打分

神经 Open IE 常用「**枚举论元对 + 打分**」的框架：枚举句子里的「候选论元1、候选论元2」对，给「论元对是否构成一个抽取」打分：

$$
s(a_1, a_2) = \mathbf{h}_{a_1}^\top W\, \mathbf{h}_{a_2} + \mathbf{w}^\top \mathbf{h}_{\text{sentence}}
$$

逐步拆解：

- **第一步，$\mathbf{h}_{a_1}, \mathbf{h}_{a_2}$（论元表征）**：候选论元跨度（如「莫扎特」「《安魂曲》」）的语义向量——来自编码器（BERT）对句子编码后的跨度池化。
- **第二步，双线性项 $\mathbf{h}_{a_1}^\top W \mathbf{h}_{a_2}$**：度量「论元1 与论元2 的契合度」——与第八篇双仿射、第十一篇指代打分的双线性同源。模型学「什么类型的论元对之间会形成事实」。
- **第三步，$\mathbf{w}^\top \mathbf{h}_{\text{sentence}}$（句级证据）**：整句表征提供「这句话整体在说什么」——帮助判断「这对论元在句子里确实有关系」。有些实现还会加入「论元之间的词序列编码」作为关系短语的证据。
- **第四步，阈值决策**：得分高的一对论元 → 输出三元组；关系短语通常另外**抽取**（动词短语）或用**生成**的方式给出。<span class="marginnote">神经 Open IE 与有监督 RE 的差别在「关系怎么出」：有监督 RE 的关系是<strong>分类</strong>到固定类，Open IE 的关系是<strong>生成/抽取</strong>的自由短语——所以神经 Open IE 常把「关系短语生成」也并进模型（用序列标注或生成式），这让它天然无法用「分类准确率」评测，只能用三元组匹配。</span>

## 5 生成式 Open IE

预训练生成模型（BART/T5）带来了新一代 Open IE：**把抽取当成「文本 → 三元组文本」的生成任务**。

输入：「莫扎特创作了《安魂曲》。」
输出（生成）：莫扎特 | 创作了 | 《安魂曲》 ——直接生成三元组的文本表示。

**生成式 Open IE 的优势**：免去「枚举论元对」的搜索、天然处理多个三元组、能生成规范化的关系短语（模型学会把「创作了」「是……的作者」统一成一种说法）。**代价**：生成可能不合规范、需要约束解码（第十篇讲过）、训练数据仍要标注。<span class="marginnote">生成式 Open IE 是「把结构化预测变成生成」这股浪潮（第十篇语义解析、第十一篇事件抽取都提到过）在 Open IE 上的落点——预训练模型用「学会怎么说话」的知识来「说出事实」。这是当前 Open IE 研究的主流方向。</span>

## 6 评测与挑战

**评测**：Open IE 没有「固定 schema」，评测用**抽取三元组与参考答案的匹配**——三元组与参考完全一致（论元与关系短语都匹配）才算对；参考用「**人工标注的抽取全集**」构建（如 OIE2016 评测数据）。指标报精确率、召回率与 F1。
**经典数据**：**OIE2016**（基于句子的人工抽取参考）、**CaRB**（改进版，按论元与关系的多重匹配评分）、中文 Open IE 数据相对稀少（多借用英文方法 + 中文句法）。

**四大挑战**：

**冗余抽取（redundancy）**：同一事实被抽成多个变体（创作了/写过/是作者）——需要归一化；
**论元嵌套与并列**：「A 和 B 都抗议」要拆成两条，容易漏；
**隐含关系**：无动词的「名-名」关系（「北京—上海—高铁」）规则难抓；
**评测的主观性**：人工标注的「应抽三元组」本身就因人而异——Open IE 的评测一致性低于有监督 RE。<span class="marginnote">冗余是 Open IE 最头疼的问题：一个「乔布斯创立苹果」在语料里可能被抽成「创立了」「创建了」「是联合创始人」……十几种变体。下游（如知识库构建）必须先做<strong>三元组归一化</strong>（把等价的关系短语合并），否则图谱里全是重复边。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

**Open IE 的「关系」是短语，不是类型**：输出的是「创作了」这种自由表达，不是「创作者」这种固定类。拿「分类准确率」评测 Open IE 是错的——它没有「类」。<span class="marginnote">记忆：有监督 RE 是「把实体对分到关系类」，Open IE 是「把实体对 + 关系短语抽出来」。前者分类，后者抽取。</span>
- **论元不限于命名实体**：Open IE 的论元可以是名词短语、事件短语（「小明的抗议」）——把论元限定成 NER 实体会漏掉大量抽取。
- **规则方法依赖句法分析**：句法错了（第八篇的解析错误），规则抽取跟着错。评测时要把「句法错误导致的问题」与「规则本身的问题」分开看。
- **生成式输出的规范性问题**：生成三元组可能语法正确但论元错位（幻觉）——需要约束解码或后验证，别把「生成出来了」当「抽取正确」。

## 8 实例：一个句子的 Open IE 抽取对照

用「乔布斯创立了苹果公司，并推出了 iPhone。」走一遍 Open IE 与有监督 RE 的对照：

**Open IE**（自由抽取）：

- （乔布斯；创立了；苹果公司）
- （乔布斯；推出了；iPhone）

关系短语「创立了」「推出了」是抽出来的**自由表达**——换成「创建了」「是……的联合创始人」，Open IE 会照抽不误，但表达不统一。

**有监督 RE**（预定义 schema，如 创始人/任职于/发布）：

- 乔布斯 —创始人→ 苹果公司；
- 乔布斯 —发布→ iPhone。

关系被**归入固定类**「创始人」「发布」——规范统一，但 schema 里没有的关系（如「乔布斯开创了个人电脑时代」）就抽不出来。

**两点启示**：

- Open IE 是「广度」：覆盖无限关系，代价是变体多、需归一化；有监督 RE 是「精度」：规范但封闭；
- 工业常「Open IE 挖掘 + 有监督规范化」组合——冷启动靠 Open IE 发现新关系，再把高频关系抽进 schema。

## 9 小结

- **Open IE**：不预设 schema，抽取自由三元组（论元1；关系短语；论元2）——从封闭分类到开放抽取。
- 论元可不限于命名实体；关系短语是「抽取/生成」而非「分类」。
- **规则方法**（ReVerb/ClausIE）：句法模板驱动，零标注、精确、可解释。
- **神经方法**：论元对打分 $s(a_1,a_2)=\mathbf{h}_{a_1}^\top W\mathbf{h}_{a_2}+\mathbf{w}^\top\mathbf{h}_{\text{sentence}}$——枚举 + 打分 + 阈值。
- **生成式 Open IE**：把抽取当「文本→三元组」生成，预训练模型的主流路线。
- 评测：三元组匹配（OIE2016/CaRB）；挑战：冗余、嵌套并列、隐含关系、评测主观性。
