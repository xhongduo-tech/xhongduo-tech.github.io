## 为什么从词典方法开始

上一篇我们把中文分词拆成了「歧义切分」与「未登录词」两个难点。面对这些难点，最直接的想法是：既然词的集合可以事先收进一张表，那分词不就是「在表里找最合适的切法」吗？这就是**基于词典的分词方法（dictionary-based segmentation）**：以词表为唯一知识来源，用匹配或图搜索在词表里挑选切分。它不需要任何标注语料，一夜之间就能跑起来，至今仍是快速原型与工业兜底的标配。<span class="marginnote">词典方法的历史与中文信息处理同龄：1970 年代开始，第一批汉字输入法、第一批中文文本系统都用词典 + 匹配规则做分词。它朴素，却把「分词 = 搜索」这个框架牢牢立住了——后面所有统计方法，不过是给搜索换了一个更好的打分函数。</span>

这一篇我们从两条经典路线看起：**最大匹配法**与**最短路径分词**。它们一个用「贪心」、一个用「全局最优」，正好展示同一件事的两种工程品味，也暴露词典方法共同的瓶颈——为下一篇引入统计方法埋下伏笔。

## 1 词典的组织：匹配的快慢取决于它

词典方法的第一步，是让「查词」够快。中文分词的词典动辄几十万词条，若每次匹配都线性扫描全表，分词会慢到不可用。常用的两种结构：

- **哈希表（hash table）**：把每个词映射到一个桶，查词 O(1) 平均。适合「整词精确查询」。
- **Trie 树（前缀树 / 字典树）**：把词按前缀组织成一棵树，根到叶的路径就是一个词。「武」「武汉」「武汉市」共享前缀「武」，一次沿前缀下行即可判断「武汉」是不是词、还能不能继续匹配。它天然支持「最长匹配」这类需要逐字试探前缀的操作。<span class="marginnote">Trie 树我们并不陌生——它在第三级《数据结构》与《算法》里是字符串检索的经典结构，也是搜索引擎倒排索引的底层伙伴。分词里的 Trie 与哈希表之争，是「查询速度」与「前缀灵活性」的权衡，到互联网文本检索时你还会再次遇见。</span>

词典本身还带权重信息：词条可以标注**词频**或**概率**。不带的词典，只能做「等权」的匹配；带了概率的词典，才有能力让「概率高的切法」胜出——这是下一节统计方法与「带权最短路径」的关键区别。

## 2 最大匹配法：贪心的艺术

**最大匹配法（maximum matching）**的核心直觉是：**中文分词中，词的长度多数在 2–4 个字，切分时优先取「最长可能的词」，剩下的字再继续。** 它把「最合适的切分」粗略等价于「每一步都取最长词」。

### 正向最大匹配（FMM）

设词典中最长词长度为 $L$。从句子开头取长度为 $L$ 的候选串，若不在词典，则去掉末尾一个字再查，直到命中或退化为单字。算法如下：

```python
def fmm_segment(text, lexicon, max_len=5):
    """正向最大匹配：从前往后，每次取最长的词典词"""
    words, i, n = [], 0, len(text)
    while i < n:
        for L in range(min(max_len, n - i), 0, -1):
            if text[i:i + L] in lexicon:      # 命中则切出
                words.append(text[i:i + L])
                i += L
                break
        else:
            words.append(text[i])             # 单字兜底，必然成词
            i += 1
    return words
```

对「武汉市长江大桥」按 FMM（假设词典含「武汉」「武汉市」「市长」「长江」「大桥」）会切出：**武汉市 / 长江 / 大桥**。

### 逆向最大匹配（BMM）

**逆向最大匹配**把方向反过来，从句子末尾向前匹配。经验表明它对汉语往往效果更好——因为汉语的修饰语在前、中心语在后，歧义字段的错误倾向与正向恰好互补。例如「研究生命科学」正向会贪心地切出「研究生 / 命 / 科学」，逆向则倾向「研究 / 生命 / 科学」，通常后者更正确。

### 双向最大匹配（BiMM）

**双向最大匹配**同时跑正向与逆向，再按启发式仲裁：

1. 若两边切分相同，任取其一；
2. 若不同，选**切分次数更少**者；
3. 若次数仍相同，选**单字词更少**或**非词典词更少**者。

**辨析｜易错点：** 最大匹配是「贪心」，不保证全局最优。它只用了「最长优先」这一条启发式，既没有词频信息，也不会回头修改已经切出的词——一个位置切错，后续全部跟着错，且**没有任何机制能在切错后自我修正**。把「最大匹配」说成「最优分词」是初学者最常犯的误读；它只是「快而可用」的近似。

## 3 最短路径分词：把切分变成图上的最优路径

最大匹配的「局部贪心」让人不安：能不能**全局**地找最好的切法？可以。**最短路径分词（shortest-path segmentation）**把整个句子建成一张有向无环图，分词变成在图上找一条从起点到终点的最短路径。

### 建图

句子 $S = c_1 c_2 \cdots c_n$，共有 $n+1$ 个**字符间隙**，记作节点 $0, 1, \dots, n$。凡「从第 $i$ 个间隙到第 $j$ 个间隙之间的子串 $c_{i+1} \cdots c_j$ 是一个词」，就连一条边 $(i, j)$，权重记 $w(i,j)$。**切分 $\Leftrightarrow$ 从 0 到 $n$ 的一条路径**——路径上每条边对应一个切出的词。

对「武汉市长江大桥」建图（7 个字，节点 0–7）：候选词「武汉 (0,2)」「武汉市 (0,3)」「市长 (2,4)」「长江 (3,5)」「江 (4,5)」「大 (5,6)」「大桥 (5,7)」，再加上每个单字成词的边。图如下：

![「武汉市长江大桥」的最短路径分词图](/images/nlp/dictionary-segmentation-1.svg)

### 边权与目标

若每条边权重都取 1，最短路径就是「**词数最少**」的切分；若把权重设成 $-\log P(w)$（词频概率的负对数），最短路径就是「**整句概率最大**」的切分——后者已经是一只脚踏进统计语言模型的领域了。<span class="marginnote">注意：边权越小越优，所以取 $-\log P(w)$ 而非 $P(w)$，把「概率最大」翻转为「代价最小」，从而复用最短路径算法。这个「取负对数转成最短路」的套路，在第四篇《n-gram 语言模型》与第十篇《机器翻译》里会反复出现。</span>

### 求解

对词数最少的切分，用动态规划即可（从起点向后递推，见下节公式解析）。路径在「武汉市 / 长江 / 大桥」（3 词）与「武汉 / 市 / 长江 / 大桥」（4 词）之间比较，前者词数更少，胜出。

**重点：最短路径分词给「歧义消解」一个全局的、可解释的框架**——歧义不再是局部纠纷，而是多条候选路径的竞争。它比最大匹配聪明，但仍然只认「词数 / 词频」，不认「语义」；「武汉市长江大桥」若是讲武汉市长，最短路径也会错切。

## 4 公式解析：最短路径的递推

设 $D(j)$ 表示从节点 0 切到节点 $j$ 的最少词数（或最小代价），$w(i,j)$ 是边 $(i,j)$ 的权重。**重点：动态规划的核心递推式是——**

$$
D(j) = \min_{i:\ (i,j)\ \text{是词}} \big\{\, D(i) + w(i,j) \,\big\}, \qquad D(0) = 0
$$

- **第一步，读懂状态 $D(j)$**：它回答「切到第 $j$ 个字符间隙，最少需要多少词 / 多少代价」。$D(0)=0$ 是边界：还没开始切，代价为 0。
- **第二步，读懂转移**：到达 $j$ 之前，必定经过某个 $i < j$ 且 $(i,j)$ 是一个词。于是「切到 $j$ 的代价」=「切到 $i$ 的代价」+「切出 $c_{i+1..j}$ 这一个词的代价」。所有可能的 $i$ 里取最小。
- **第三步，回溯还原切分**：递推同时记录「使 $D(j)$ 最小的那个 $i$」为 $D(j)$ 的前驱，最后从 $j=n$ 沿前驱一路回溯到 0，就得到整条最短路径（即切分结果）。

对「武汉市长江大桥」，$D(7)$ 会分别考虑前驱 $i=5$（切出「大桥」）与 $i=6$（切出「桥」）等；因为「大桥 (5,7)」比「桥 (6,7)」一次省一个词，$D(7)$ 最终取前驱 5，得到三词切分。下面是完整实现：

```python
def shortest_path_segment(text, lexicon):
    """最短路径分词：词数最少 / 边权为 1 的动态规划"""
    n = len(text)
    edges = {}                          # j -> [i, ...]：所有以 j 结尾的词
    for i in range(n):
        for j in range(i + 1, n + 1):
            if text[i:j] in lexicon or j == i + 1:   # 词或单字兜底
                edges.setdefault(j, []).append(i)

    D = [float('inf')] * (n + 1)
    prev = [-1] * (n + 1)
    D[0] = 0
    for j in range(1, n + 1):
        for i in edges.get(j, []):
            if D[i] + 1 < D[j]:         # 更新更优前驱
                D[j] = D[i] + 1
                prev[j] = i

    words, k = [], n
    while k > 0:
        words.append(text[prev[k]:k])   # 回溯还原
        k = prev[k]
    return words[::-1], D[n]
```

**辨析｜易错点：** 最短路径 ≠ 语义最正确。它只是「词数最少 / 词频最大」这个目标下的全局最优，而该目标本身只是真实语言规律的近似。两个经典误区：一是把「最少词数」当成「正确切分」的充分条件——「乒乓球拍卖完了」里「球拍 / 卖完」与「拍卖 / 完」词数相同，路径法依然会左右为难；二是忘了**单字兜底边**——若某个未登录词序列让路径断掉，图必须保证单字总能成词，否则无解。词典方法的共同软肋（未登录词）在这里暴露得最清楚：**图里根本没有未登录词的边，再优的路径也切不中它。**

## 5 小结

- **词典的组织**：哈希表快在整词查询，Trie 树强在前缀匹配与最长试探；词典可带词频/概率，为统计方法预留接口。
- **最大匹配法**：正向（FMM）、逆向（BMM）、双向（BiMM）三种变体，用「最长优先」贪心切分，快但局部最优、无法纠错；逆向对汉语通常更优。
- **双向最大匹配仲裁**：优先切分次数少、其次单字词少。
- **最短路径分词**：把句子建成 DAG，节点是字符间隙、边是词，用动态规划求 0 到 n 的最短路径；边权取 1 得最少词数，取 $-\log P(w)$ 得最大概率。
- **共同瓶颈**：词典方法的候选集完全受限于词表，未登录词永远切不中；改进必须换知识来源——统计方法登场。
