## 为什么从生成评测开始

分类、抽取有「标准答案」，生成没有——「这句翻译得好不好」不是「对错」问题。**生成类任务的评价**是 NLP 评测里最难、也最没有定论的一块：自动指标（BLEU/ROUGE）快但「字面」，人工评价准但贵，LLM-as-judge 是新工具但有自己的偏见。它是第十六篇「评测困境」的系统化展开，也是「大模型输出质量怎么判」的当代核心问题。<span class="marginnote">生成评测的「难」本质：<strong>输出是一个「分布」而不是一个「点」</strong>——「你吃饭了吗」的合适回答有几百种，没有「标准答案」。这让「与参考比对」（自动指标）与「主观判断」（人工）都充满困难。理解生成评测的困境，就理解了「为什么大模型的『好不好』这么难说清」。</span>

这一篇讲生成评测的完整版图：自动指标（n-gram、语义、多样性）、人工评价、LLM-as-judge，以及评测设计的原则。

## 1 自动指标：从 n-gram 到语义

生成自动指标按「测什么」分几代：

**第一代：n-gram 重合**——**BLEU**（精确，翻译）与 **ROUGE**（召回，摘要）：

原理：生成与参考的 n-gram 重合度；
优点：便宜、可复现、与人工有一定相关；
致命局限：**只看字面**——「这台电脑很棒」与「这台电脑性能优秀」语义相同，重合却低。

**第二代：语义相似**——**BERTScore**、**MoverScore**：

原理：用预训练模型算「生成与参考的语义相似度」；
改进：同义词/改写不再被罚；
局限：仍不测「忠实度」（生成是否忠于输入）。

**第三代：任务专用 + 多维**——忠实度（FactCC）、多样性（distinct-n）、风格强度……<span class="marginnote">自动指标的「代际演进」规律很清楚：<strong>从「字面」走向「语义」、从「单一」走向「多维」</strong>——因为第一代总被「刷爆」（复读参考刷 BLEU），第二代缓解字面、但又不测忠实，于是第三代「任务专用化」。<strong>每一代指标都是「补上一代漏洞」的产物</strong>——理解这个演进，就理解「为什么没有终极指标」。</span>

## 2 公式解析：BERTScore

**BERTScore**（Zhang et al., 2020）用预训练表征算「语义重合」。设生成的 token 表征 $\mathbf{g}_i$、参考的 $\mathbf{r}_j$，逐 token 算余弦相似度：

$$
\text{BERTScore} = \frac{1}{|G|} \sum_{i=1}^{|G|} \max_{j} \; \cos(\mathbf{g}_i, \mathbf{r}_j)
$$

逐步拆解：

- **第一步，$\cos(\mathbf{g}_i, \mathbf{r}_j)$（token 相似度）**：生成的第 $i$ 个词与参考的第 $j$ 个词的向量余弦——「很棒」与「优秀」的向量接近，余弦高；
- **第二步，$\max_j$（找最佳匹配）**：对生成的每个词，在参考里找**最像的参考词**——「很棒」找到参考里的「优秀」，匹配成功；
- **第三步，$\frac{1}{|G|}\sum_i$（平均）**：所有生成词的「最佳匹配相似度」平均——「整句的语义覆盖」；
- **第四步，补充精确率版**：也可对「参考每个词找生成的最近邻」求平均（召回视角）；BERTScore 常报 F1（两者结合）。

**直觉**：BERTScore = 「**把‘n-gram 是否相同’换成‘词向量是否相近’**」——它是 ROUGE 的「语义升级版」。同义改写不再被罚，与人工评价的相关性显著高于 ROUGE。<span class="marginnote">BERTScore 的局限仍在：它测「与参考的语义接近度」，<strong>不测「生成是否忠于输入」</strong>——一篇「流畅但编造」的摘要，如果参考也这么写（数据集风格相近），BERTScore 照样高。所以现代摘要论文「BERTScore 报相似 + FactCC 报忠实」配合用——<strong>没有单一指标，只有指标组合</strong>。</span>

## 3 多样性与概率指标

生成评测还需要「非内容」的维度：

**多样性（diversity）**：**distinct-n**（第十六篇）——「不同 n-gram / 全部 n-gram」——测「是否爱说重复话」；
**困惑度（perplexity, PPL）**：语言模型层面的「流畅度」——低 PPL = 语言更「像人话」；但它不测「内容是否合适」（流畅的废话 PPL 也低）；
**长度与覆盖率**：生成长度、关键词覆盖——任务相关的辅助指标。

**这些指标的共同点**：测「表面属性」，不测「语义质量」——它们是**筛选器**（快速排除明显差的），不是**裁判**（不能定论好坏）。<span class="marginnote">「筛选器 vs 裁判」是理解自动指标的钥匙：自动指标便宜、可复现，适合<strong>在大量候选里快速筛掉明显差的</strong>；但「最终好坏」的判断权，始终在<strong>人工评价</strong>手里。工业界「自动筛 + 人工审」的两段式，就是这个分工的工程化——<strong>自动指标负责效率，人工负责真相</strong>。</span>

## 4 人工评价：生成评测的准绳

**人工评价（human evaluation）**是生成评测的「金标准」——但设计有讲究：

**评什么（维度）**：**流畅度**（语言通顺）、**忠实度/相关性**（内容对不对、贴不贴输入）、**信息量**（内容全不全）、**自然度/多样性**（像不像人）；
**怎么评**：**李克特量表**（1–5 打分）、**成对比较**（A 和 B 哪个好）、**排序**（几个模型排座次）；
**评多少**：样本量要够（几十到几百条）、标注者要多（多人独立 + 一致性检验）。

**人工评价的坑**：

**贵且慢**：高质量标注成本高；
**主观偏差**：标注者偏好长文、流畅文、自己的风格；
**不一致**：同一篇生成，两个标注者打分可能差异大（Kappa 低）。<span class="marginnote">人工评价的「一致性」问题需要正视：生成质量的主观性让「标注者一致性」天然偏低（比分类标注低得多）。<strong>设计人工评测的要点是「控制变量」</strong>——同一组标注者、同一套维度定义、同一批样本——让「比较」尽量公平。成对比较（A vs B）比绝对打分（1–5）的一致性更好，是更可靠的形态。</span>

## 5 LLM-as-judge：新工具与新问题

大模型时代的新评测工具：**LLM-as-judge**——让 GPT 等大模型给生成打分/判断。

**为什么流行**：便宜（比人工便宜几个数量级）、可复现（同输入同输出）、接近人工（大模型内化了人类偏好）。

**它的已知问题**：

**偏好偏差**：偏爱更长、更流畅、更「像自己风格」的输出；
**位置偏差**：对比时偏爱排在前面的候选；
**自评偏差**：模型给自己「同族模型」打分偏高；
**幻觉判决**：裁判模型可能「编造理由」为错误辩护。<span class="marginnote">LLM-as-judge 的定位是「人工的廉价近似」——不是「真理」。它让生成评测「可规模化」（评几百条不心疼），但要「知其偏差」：报 LLM 打分时，常配「人工抽检校准」——「LLM 大规模评 + 人工小样本校验」是现代生成评测的务实组合。</span>

## 6 评测设计的原则

综合来看，生成评测的设计有几个共识原则：

1. **多维分开**：忠实、流畅、相关分开测——「流畅但不忠实」不能被一个总分掩盖；
2. **自动 + 人工互补**：自动指标快速筛选、人工最终判定——两层结合；
3. **任务化指标**：翻译看「准」、摘要看「全与实」、对话看「自然」——**每个任务定义自己的「好」**；
4. **报告透明**：报指标要说明「指标 + 样本量 + 标注者数 + 一致性」——让读者能判断评测可信度。

**生成评测的未来**：面向目标的评测（任务是否完成）、对抗性评测（是否经得起扰动）、多信号融合（自动 + 人工 + LLM 加权）——「没有单一答案」是生成评测的宿命，也是它持续活跃的原因。<span class="marginnote">一个总结性的视角：<strong>生成评测的「没有完美指标」不是缺陷，而是「生成质量本身多维」的反映</strong>——「好」不是一维的，评测自然不能是一维的。理解「多维」与「互补」，就掌握了生成评测的底层逻辑——这也是为什么本章四篇（指标、基准、生成评测、偏差鲁棒性）都要讲：评测没有银弹，只有「理解原理后的组合运用」。</span>

## 7 辨析｜易错点：四个常见坑

**辨析｜易错点：**

**BLEU/ROUGE 高 ≠ 生成好**：它们只测「与参考的字面重合」——「复读参考」能刷高分。报自动指标时注明「仅作参考，需人工校验」。<span class="marginnote">自检：一个模型「总是返回参考句里的话」，BLEU 可能极高——但它不是「好的生成器」。自动指标的分数，永远要问「它测的是哪个维度的什么」。</span>
- **PPL 低 ≠ 内容好**：困惑度只测「语言层面的流畅」——「嗯嗯嗯嗯」PPL 很低但毫无内容。别拿 PPL 当「质量指标」。
- **人工评测「一个人打分」不可信**：主观偏差大——要多人独立 + 一致性检验。单标注者的分数是「噪声」。
- **LLM-as-judge 不是「零成本真相」**：它快、便宜、接近人工，但**有偏好、有幻觉**——用它要「知其偏差」，配人工校准。

## 8 小结

- **生成评测**最难也最无定论：输出是「分布」不是「点」，没有标准答案。
- 自动指标三代：**n-gram（BLEU/ROUGE）→ 语义（BERTScore）→ 任务专用（忠实/多样）**——每代补前代漏洞。
- **BERTScore**：$\frac{1}{|G|}\sum_i\max_j\cos(\mathbf{g}_i,\mathbf{r}_j)$——词向量版的「语义 ROUGE」，仍不测忠实。
- **人工评价**是准绳：多维分开（流畅/忠实/相关）、成对比较、多人 + 一致性。
- **LLM-as-judge**：便宜可复现但**有偏好有幻觉**——「LLM 大规模评 + 人工小样本校准」。
- 原则：**多维、互补、任务化、透明**——评测没有银弹，只有理解原理后的组合运用。
