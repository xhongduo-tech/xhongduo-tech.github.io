## 为什么从序列标注开始

回头看我们走过的路：分词、词性标注、命名实体识别、槽位填充、组块分析……这些任务长得各不相同，但骨子里是同一个问题——**给输入序列的每个位置贴一个标签**。<span class="marginnote">本专题第三篇的《由字构词（字标注）分词》其实已经在做序列标注了：给每个汉字打 B/M/E 标签来切词。今天我们把「贴标签」这件事从任务里抽象出来，正式立为建模框架。</span>这个框架叫**序列标注（sequence labeling）**，它上承表示学习（上一节的词向量与上下文表示都是它的输入），下启本专题第六、七篇的 HMM、CRF、BiLSTM-CRF 等一系列模型。

这一篇先做两件事：一是给「序列标注问题」下一个严格定义，二是把最常用的**标注策略 BIO/BIOES** 讲透。别小看「打标签」这件看似琐碎的事——**标注方案选错了，后续模型与评测全都会跟着错**。

## 1 什么是序列标注

**序列标注（sequence labeling）**：给定一个长度为 n 的输入序列 $X = (x_1, x_2, \dots, x_n)$（通常是句子分词后的 token 序列），输出一个等长的标签序列 $Y = (y_1, y_2, \dots, y_n)$，其中 $y_t$ 是 $x_t$ 的标签，标签取自一个有限的**标签集合（label set）**。

核心特征是**输出之间不独立**：$y_t$ 往往依赖相邻的标签。例如「北京」如果被标成 B-LOC，下一个字几乎必然是 I-LOC；如果前一个标签是 O，后一个标签应是 B-xxx 或 O，而绝不会是孤零零的 I-xxx。**这类「输出有结构」的预测问题，统称为结构化预测（structured prediction）**——它不是给每个位置独立分类，而是给整条序列找一个最优的标签组合。<span class="marginnote">为什么不能逐词独立分类？因为局部决策会累积出非法序列。举个例子：把「北京」的「北」标成 I-LOC 而前面没有 B-LOC，就是非法标注——独立分类器不会知道这条规则。</span>

序列标注能覆盖的常见任务：

**词性标注**：标签是词性（名词、动词……），见本专题第三篇《词性标注》。
**命名实体识别**：标签是 B/I/O 加实体类型（人名、地名、机构名）。
**中文分词**：标签打在「字」上（B/M/E），见《由字构词（字标注）分词》。
**组块分析**：给词打「名词短语开始/内部/外部」。
**槽位填充**：任务型对话里给词打「出发地/目的地/时间」等槽位标签。

## 2 标注策略：BIO 与 BIOES

标签集合怎么设计？最常用的两套：

**BIO（也叫 IOB2）**：**B**egin（片段首字）、**I**nside（片段中间）、**O**utside（不属于任何片段）。需要区分实体类型时，写作 B-PER、I-PER、O、B-ORG 等。
**BIOES（也叫 IOBES/BILOU）**：在 BIO 基础上再加 **E**nd（片段末字）与 **S**ingle（单字成片段）。

以「小明在北京大学读书」为例（人名 + 机构名），BIO 与 BIOES 的标签对照：

| token | BIO | BIOES |
| --- | --- | --- |
| 小明 | B-PER | S-PER |
| 在 | O | O |
| 北京 | B-ORG | B-ORG |
| 大学 | I-ORG | E-ORG |
| 读书 | O | O |

**BIOES 的标签信息更密**：看到 I-ORG 就能确定「这个词在实体内部、后面还有词」；看到 E-ORG 则知道「实体到此结束」。这意味着**解码阶段可以更早地确定边界**。<span class="marginnote">解码时用维特比算法搜索整条最优路径，BIOES 把「实体边界」信息显式编码进标签，约束更强，通常能得到更好的解码结果——我们在下一篇 HMM 的维特比解码里会看到具体机制。</span>

## 3 两种方案不是「二选一」，而是可互相转换

**重点：BIO 与 BIOES 的信息量不同，但可以无损互相转换。** 从 BIOES 到 BIO 是「丢掉 E 与 S」：S-PER 变 B-PER，E-ORG 变 I-ORG。反过来，从 BIO 到 BIOES 需要**看相邻标签**才能还原：

- 某个 B-ORG 后面紧跟 I-ORG，则该 B-ORG 保持为 B-ORG；
- 某个 I-ORG 后面不再是 I-ORG，则它应改成 E-ORG；
- 某个 B-ORG 后面直接是 O 或别的 B-xxx，则它是单字实体，应改成 S-ORG。

所以在训练时用 BIOES、评测前转回 BIO，或用 BIO 训练、解码时约束成合法序列，都是常见做法。**真正禁止的是「混用而不转换」**——比如训练数据用 BIO、测试时却期望模型输出 BIOES 标签，标签分布都对不上。

## 4 公式解析：标注序列的联合概率

序列标注的学习目标，通常写成「输入 X 下输出 Y 的条件概率」$P(Y \mid X)$。用链式法则展开：

$$
P(Y \mid X) = P(y_1 \mid X) \prod_{t=2}^{n} P(y_t \mid X,\; y_1, \dots, y_{t-1})
$$

- **第一步，$P(y_1 \mid X)$**：第一个位置的标签只依赖输入，这是序列的起点。
- **第二步，$P(y_t \mid X, y_1,\dots,y_{t-1})$**：第 t 个位置的标签，依赖整句输入**和**此前所有标签。这就是「输出不独立」的数学表达。
- **第三步，为什么这个式子重要**：它把「整条序列的联合概率」拆成「逐个位置的局部条件概率」的乘积——这是后面 HMM、MEMM、CRF 共同的数学地基。三个模型的分野，正在于「如何近似 $y_1,\dots,y_{t-1}$ 这段历史」：HMM 假设历史只通过 $y_{t-1}$ 起作用（一阶马尔可夫假设，见第二级《概率论与数理统计》与《随机过程》）；CRF 则让 $y_t$ 与相邻标签建立全局一致的依赖。
- **第四步，预测时**：模型不再贪心地逐位置取最大，而是在整个标签序列空间里找 $Y^* = \arg\max_Y P(Y \mid X)$，这需要动态规划（维特比）——这正是下一篇的主题。

一句话：**序列标注 = 结构化预测 = 对整条标签序列打分**，而不是给每个词独立打分。

## 5 训练数据怎么来：手工标注与 BIO 生成

序列标注需要**标注语料**：每个 token 一行，空格分隔 token 与标签。以 CoNLL-2003 风格的 NER 数据为例：

```text
小明 B-PER
在 O
北京 B-ORG
大学 I-ORG
读书 O
```

生产里常用半自动方式：先跑一个基座模型预标注，再人工修正。把「实体起止下标」转成 BIO 标签的代码很短：

```python
def spans_to_bio(tokens, spans):
    # spans: [(start, end, label), ...]，start/end 为 token 下标，end 不包含
    labels = ["O"] * len(tokens)
    for start, end, label in spans:
        labels[start] = f"B-{label}"
        for i in range(start + 1, end):
            labels[i] = f"I-{label}"
    return labels
```

**评测指标**上，序列标注常报**实体级 F1**：预测出的一个实体与真实实体的「起止 + 类型」完全一致才算对（严格匹配）。只看 token 级准确率会被大量 O 标签稀释——一个全是 O 的预测也能拿到 80% 以上的 token 准确率，毫无意义。<span class="marginnote">关于准确率、召回率、F1 的定义与陷阱，见本专题第十九篇《NLP 评测方法》。这里先记住一条：序列标注必须按「片段（span）」而非「token」来算指标。</span>

## 6 辨析｜易错点：IO 的坑与相邻实体

**辨析｜易错点：**

**IO（只有 I 与 O）的致命缺陷**：IO 方案里，连续两个相邻的同类型实体（如「北京 上海」两个地点）无法区分——第二个实体的词只能标 I-GPE，解码时会被并成一个实体。BIO/BIOES 里的 **B 正是为了标记「新实体开始」**，专门解决这个歧义。<span class="marginnote">「北京、上海」这种连续实体在真实文本里极常见（并列列举），这是 IO 方案被淘汰的根本原因。</span>
- **I 不能出现在句子开头或紧跟 O**：这是标签合法性的核心约束，模型必须学会；独立分类器无法保证，这也是必须用结构化模型的原因之一。
- **BIOES 的 E/S 在解码时才兑现**：训练时标签是给定的，但预测时要靠维特比在「合法序列」约束下搜索。若模型直接贪心逐词取最大，仍可能输出非法序列。
- **标签不平衡**：O 标签通常占 80% 以上。样本不平衡会影响训练，需要加权损失或对 O 降采样，这与分类任务里的类不平衡是同一个问题。

**一个更广的视角**：BIO/BIOES 不只是 NER 的标签方案，凡是「切分 + 分类」并存的任务（分词、组块、槽位填充）都可以套用——理解它，等于拿到了 NLP 半壁江山的建模钥匙。

## 7 小结

- **序列标注**：给输入序列每个位置贴标签，输出有结构、相互依赖，属于**结构化预测**。
- 标签方案：**BIO**（B/I/O）与 **BIOES**（+E/S）；BIOES 信息更密、解码约束更强。
- 两种方案可**无损转换**，但训练与评测的标签体系必须一致。
- 目标函数 $P(Y \mid X)$ 用链式法则展开，是 HMM/MEMM/CRF 的共同地基。
- 评测要看**实体级 F1**（span 严格匹配），不能只看 token 准确率。
- **IO 方案的坑**：相邻同类型实体无法区分，B 标签必不可少。

在下一节，我们给「序列标注」装上第一个概率模型——**隐马尔可夫模型（HMM）**：它是这套框架里最简单的生成式解法，也是理解维特比算法与后续判别式模型（MEMM、CRF）的起点。
