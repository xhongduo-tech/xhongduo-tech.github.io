## 为什么从评价开始

我们已经连续造了三类词向量：Word2Vec、GloVe、FastText。它们各自声称「更好」，可「好」到底由谁说了算？<span class="marginnote">回顾一下本专题的路线：词向量是分布式语义的载体，见第五篇《分布式假设与分布式语义表示》。评价就是给这批「语义载体」办一次质检。</span>没有评价，调参就变成撞运气：窗口大小用 5 还是 10？维度是 100 还是 300？负采样取 K=5 还是 K=20？——每一个超参数，都该由「评价」来回答。

这一篇讲词向量的**验收标准**：内在评价与外在评价两条路线，以及其中最经典的**词相似度**与**词类比**两类任务。理解了它们，你不仅能看懂论文里的评测表格，还能在以后做任务时正确地选择「用哪个词向量」。

## 1 内在评价与外在评价

词向量评价分两条路线，它们回答不同的问题：

| 评价类型 | 回答的问题 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| 内在评价（intrinsic） | 向量本身是否编码了语义？ | 相似度、类比、聚类等任务 | 快、便宜、可解释 | 与真实任务表现未必一致 |
| 外在评价（extrinsic） | 换了词向量，下游任务是否变好？ | NER、情感分析、机器翻译等 | 反映真实价值 | 慢、成本高、受任务噪声干扰 |

**内在评价优先于外在评价使用**：调参阶段用内在任务快速筛出几组候选，最后再用外在任务做终审。<span class="marginnote">这是个工程节奏问题，和深度学习里的「用验证集调参、用测试集终评」思路一致——详见第四级《机器学习》专题的模型评估篇。</span>

## 2 词相似度任务与评测数据

**词相似度（word similarity）任务**是内在评价的基石：给定一对词（如（tiger, cat）），让人工标注它们的语义相似度（通常 0～10 打分），再把机器算出的相似度与人类打分做相关性比较。<span class="marginnote">这里要区分两个概念：相似（similarity）指两个词在语境中可互换（tiger 与 cat）；相关（relatedness）指经常同现（tiger 与 zoo）。WordSim-353 混入了大量「相关」对，SimLex-999 专门修正了这一点。</span>

经典数据集：

- **WordSim-353**（1998）：353 对英文词，最常被引用，但相似/相关混杂。
- **SimLex-999**（2014）：999 对词，严格按「相似」标注，更纯粹。
- **MEN**（2013）：基于众包的 3000 对词，语料来自网络。
- 中文侧常用 **WordSim-240 / 296** 或自建集，评价中文词向量时不要直接套英文数据集。<span class="marginnote">评测集的语言必须与词向量语言一致——拿中文词向量去跑 WordSim-353 会得到一堆未登录词，测不出任何东西。</span>

机器侧怎么算相似度？最常用**余弦相似度**，它只关心方向、不关心长度，正好契合「语义方向决定词义」的直觉：

$$
\cos(v_a, v_b) = \frac{v_a^{\top} v_b}{\|v_a\|\, \|v_b\|}
$$

## 3 公式解析：斯皮尔曼相关系数

机器给出的相似度与人类打分可能量纲不同，直接算皮尔逊相关系数（对线性关系敏感）往往不合适。词向量评测默认用**斯皮尔曼秩相关系数（Spearman's rank correlation）**：它只比较「排序」是否一致。

把 N 对词按人类打分排序得到秩 $r_i$，按机器相似度排序得到秩 $s_i$，则：

$$
\rho = 1 - \frac{6 \sum_{i=1}^{N} d_i^2}{N (N^2 - 1)}, \qquad d_i = r_i - s_i
$$

- **第一步，$r_i$ 与 $s_i$**：把两列分数各自转换成名次。比如人类打分最高的一对词秩为 1，第二高为 2，以此类推；机器侧同理。
- **第二步，$d_i = r_i - s_i$**：同一对词在两个排序里的名次差。若机器排序与人类完全一致，所有 $d_i = 0$，$\rho = 1$。
- **第三步，为什么除以 $N(N^2-1)/6$**：这是当两列秩完全无关时 $\sum d_i^2$ 的期望值。把实际差距除以这个基准，就把 $\rho$ 归一化到 $[-1, 1]$：1 是完全一致，0 是毫无关系，负值表示「机器越觉得像、人类越觉得不像」。
- **第四步，为什么用秩而不用原值**：人类打 4 分和 5 分的差距，不一定等于打 8 分和 9 分的差距——分数是序数而非等距。用秩只保留「谁高谁低」，不强行假设分数间隔均匀。这是它比皮尔逊更稳的原因。

在 gensim 里，词相似度往往一条命令就能算：

```python
import gensim.downloader as api
wv = api.load("glove-wiki-gigaword-50")     # 50 维 GloVe 词向量
sim = wv.similarity("tiger", "cat")          # 余弦相似度
print(round(sim, 3))                         # 0.51 左右

# 整表评测：对数据集里的每一对词算相似度，再与人工打分算 Spearman
wv.evaluate_word_pairs("wordsim353.tsv")
```

## 4 类比任务：3CosAdd 与 3CosMul

如果说相似度考「静态语义」，**词类比（analogy）**则考「语义关系能否做向量算术」。最经典的例证是：

$$
\vec{king} - \vec{man} + \vec{woman} \approx \vec{queen}
$$

即「国王是男人的国王，如同女王是女人的女王」——关系向量的这种平移特性，正是 Word2Vec 论文里最出圈的一张图。<span class="marginnote">关系向量的平移后来被质疑「只在部分语义关系上成立」（罗杰斯等人 2017 年的复现研究），但它仍是衡量词向量质量的便捷探针。</span>

用向量算术解题的方式有两种：

- **3CosAdd**（Mikolov 等，2013）：在词表里找使下式最大的词 d：

$$
\hat{d} = \mathop{\arg\max}_{d \in V \setminus \{a, b, c\}} \cos(v_b - v_a + v_c,\; v_d)
$$

- **3CosMul**（Levy 等，2014）：把加法换成乘法，更强调每个方向的独立约束：

$$
\hat{d} = \mathop{\arg\max}_{d \in V \setminus \{a, b, c\}} \frac{\cos(v_d, v_b) \cdot \cos(v_d, v_c)}{\cos(v_d, v_a) + \varepsilon}
$$

两者都基于同一个假设：**语义关系 = 向量空间里的方向平移**。a→b 的关系方向与 c→d 的关系方向对齐时，$v_b - v_a \approx v_d - v_c$。3CosMul 引入「乘法 + 分子分母」后，对低频词与噪声的鲁棒性更好，在很多评测集上是更优的默认选择。

## 5 实践中怎么用：代码与经验

gensim 内置了相似度与类比的评测入口，这是快速验收的捷径：

```python
import gensim.downloader as api
wv = api.load("word2vec-google-news-300")    # 300 维 Word2Vec

# 类比：a 之于 b，如同 c 之于 ?
wv.most_similar(positive=["king", "woman"], negative=["man"], topn=5)
# [('queen', 0.71), ('princess', 0.58), ('monarch', 0.58), ...]

# 相似度评测：返回 (皮尔逊, 斯皮尔曼, OOV 占比) 等
wv.evaluate_word_pairs("wordsim353.tsv")
wv.evaluate_word_analogies("questions-words.txt")
```

实际项目里的几条经验：

- **维度**：常见 100～300。小语料用低维，大语料可适当增高，收益会递减。
- **窗口**：小窗口（2～5）更强调句法/词性邻近，大窗口（10+）更偏向主题相关。做语法任务用小窗口，做语义任务可放大窗口。
- **语料规模**：在词向量上「数据 > 算法」，加大干净语料往往比换模型更有效。
- **高频词下采样**：超高频功能词（的、了、the、of）会稀释相似度，训练时可做 word2vec 式的 subsampling。

## 6 辨析｜易错点：评价里最常见的四个坑

**辨析｜易错点：**

- **相似 ≠ 相关**：WordSim-353 里（car, automobile）是相似，而（car, traffic）是相关。SimLex-999 才严格区分。用错数据集会高估模型「语义相似」的能力。
- **皮尔逊 ≠ 斯皮尔曼**：皮尔逊要求两列分数线性可比，而人类打分是序数。词向量评测默认看斯皮尔曼；论文里若只报皮尔逊，要警惕「打分分布被线性拉伸」带来的虚高。
- **OOV 直接影响分数**：词表不含评测词对时，机器只能给默认向量。对比不同词向量前，先看各自 OOV 比例，否则分数差异可能只是覆盖率差异。
- **类比任务 ≠ 纯语义任务**：Google Analogy 数据集混有大量**句法**类比（如（bad, worse, good, ?）→ better），它测的不只是语义。报告结果时最好区分句法类与语义类。<span class="marginnote">本专题《Word2Vec：CBOW 与 Skip-gram》里提过，句法类比主要反映词形/词缀的线性规律，语义类比才反映概念关系——两者在 3CosMul 下的表现可以差异很大。</span>

## 7 小结

- 词向量评价分**内在**（相似度、类比，快而可控）与**外在**（下游任务，真而昂贵）两类。
- **词相似度任务**：让机器相似度与人类打分比序，数据集有 WordSim-353、SimLex-999 等，指标用 **Spearman 秩相关** $\rho$。
- **词类比任务**：用向量平移找关系词，解法有 **3CosAdd** 与 **3CosMul**，后者鲁棒性更好。
- 常见经验：小窗口偏句法、大窗口偏主题；数据量比模型更重要；先看 OOV 覆盖率再比分数。
- 评测结论要区分**相似/相关**、**皮尔逊/斯皮尔曼**、**句法/语义类比**，否则容易得出假结论。
