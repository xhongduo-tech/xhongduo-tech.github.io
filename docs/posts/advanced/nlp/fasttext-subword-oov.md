## 为什么从子词开始

前两篇我们拿到了 Word2Vec 与 GloVe，它们把每个词映射成一个固定向量，语义相近的词在向量空间里彼此靠近。<span class="marginnote">如果你还没读过，建议先看本专题《Word2Vec：CBOW 与 Skip-gram 模型》与《GloVe：基于全局词共现统计的词向量》——「共现窗口」与「负采样」是理解本篇的前提。</span>但这类**静态词向量（static word embedding）**有一个藏不住的短板：**遇到训练语料里从没出现过的词，它们给不出任何向量**。你或许觉得词表有几十万词兜底就够了，但真实文本里的「未登录词」远比想象中常见——拼写变体、专有名词、形态变化、网络新词，总有一个会突破词表的边界。

FastText 的回答直白又优雅：**别把「词」当成不可再分的最小单位，把它拆成一串字符片段，让没见过的词也能从见过的小片段里拼出向量。** 这一篇顺着这条线索展开：先看清静态词向量的三个缺口，再拆解 FastText 的模型与训练，最后厘清它与 BPE、字标注这些「表亲」的边界。<span class="marginnote">FastText 由博扬诺夫斯基（Bojanowski）、格拉夫（Grave）、茹兰（Joulin）与米科洛夫（Mikolov）等人于 2016 年提出，配套的 fastText 库同时提供无监督词向量与有监督文本分类两类工具。</span>

## 1 静态词向量的三个缺口

把 Word2Vec 与 GloVe 的产物统称为静态词向量：每个词对应一个**与上下文无关**的向量，训练结束后直接查表。它们有三个相互关联的缺口。

- **未登录词（out-of-vocabulary, OOV）**：测试时遇到词表里没有的词，查表直接落空。词表定多大都无法穷尽真实文本——人名、地名、产品名、错拼词，永远是漏网之鱼。<span class="marginnote">中文的未登录词问题在本专题第三篇《中文分词问题：歧义切分与未登录词识别》里已经打过照面：新词不断产生，词典法永远追不上。</span>
- **形态信息缺失（morphology）**：英语的 walk、walks、walked、walking 在词典里是四个词，在 Word2Vec 里是四个互不相干的向量。但它们共享词根 walk，语义高度相关——静态词向量把这层结构白白浪费了。
- **低频词表示差（sparsity）**：一个词只出现几次，训练信号太少，学出的向量往往偏离真实语义。形态丰富的语言（德语、土耳其语，以及构词灵活的中文）里，低频与未登录问题尤其严重。

## 2 FastText：把词拆成字符 n-gram

FastText 的破局点是把词**从字符层面**再做一次分解。定义：**字符 n-gram（character n-gram）** 是从词的字符序列中截取的、长度为 n 的连续片段，并用 < 与 > 标记词首与词尾，以区分「词首片段」「词中片段」与「词尾片段」。

对词 where、取 n=3，它的全部三元组是：

$$
G_{\text{where}} = \{\text{<wh},\ \text{whe},\ \text{her},\ \text{ere},\ \text{re>}\}
$$

除了这些片段，FastText 还要求把**整词本身**（记作 <where>）也作为一个单元放进集合，保证高频词的完整表示仍被直接学习。下图演示了这次分解：

![FastText 的字符 n-gram 分解](/images/nlp/fasttext-subword-oov-1.svg)

**一个词的向量，由它的全部字符 n-gram 向量求和得到。** 每个字符 n-gram 学习一个维度为 d 的向量 $z_g$，词 w 的输入表示就是：

$$
v_w = \sum_{g \in G_w} z_g
$$

由于同一字符片段（如 whe）会出现在大量词里，**参数被不同词共享**——这正是子词方法能让低频词「借光」的根本原因。

## 3 公式解析：子词如何参与打分

FastText 在训练目标上几乎完全继承 Skip-gram + 负采样，唯一的改动是：原来「中心词 w 的向量 $v_w$」被替换成子词向量的和。给定中心词 w、预测上下文词 c，打分函数是：

$$
s(w, c) = \sum_{g \in G_w} z_g^{\top} v_c
$$

- **第一步，读符号**：$G_w$ 是词 w 的字符 n-gram 集合（含整词）；$z_g \in \mathbb{R}^d$ 是片段 g 的向量；$v_c \in \mathbb{R}^d$ 是上下文词 c 的向量。注意这里 $v_c$ 仍然是一词一向量——**被子词化的只有中心词一侧**，上下文词仍按整词查表。
- **第二步，为什么用内积**：$z_g^{\top} v_c$ 度量「片段 g 与上下文词 c 的语义一致性」。如果 c 经常出现在含片段 g 的词附近，这个内积会被训练得很大。这与 Word2Vec 里「词向量与上下文向量内积度量共现强度」是同一逻辑。
- **第三步，为什么求和**：把中心词 w 的所有片段都算一遍，等于说「w 的语义 = 它所有构词成分的语义叠加」。于是 where 与 whe、her 共享成分，即使某个词完全没出现在语料里，只要它的片段出现过，就能凑出一个合理的向量。
- **第四步，概率仍是 softmax**：$P(c \mid w) = \frac{\exp(s(w,c))}{\sum_{j} \exp(s(w, c_j))}$，分母对整词表求和——所以实际训练仍然用上一篇学的**负采样**来近似，损失函数与 Skip-gram 的负采样损失一模一样，只是把中心词向量换成了 $\sum_{g\in G_{w_t}} z_g$。

## 4 参数共享：低频词为什么受益

要理解 FastText 对低频词的拯救，关键在「共享」二字。一个只出现 3 次的罕见词，Word2Vec 用 3 次梯度更新去学 d 维向量，几乎学不出名堂；而 FastText 里，这个词的向量是几十个字符片段之和，**每一个片段又同时出现在成千上万个词里**，它们的向量早已被训练得很充分。<span class="marginnote">拼写变体也被顺带解决了：fasttext 与 fastText 共享 f-a-s-t 开头的片段，两者的向量天然接近——这对搜索、去重、纠错场景很有用。</span>

效果可以量化：原始论文在形态丰富的语言（德语、捷克语等）的词相似度评测上，FastText 相比 Word2Vec 有明显提升，尤其对低频词。代价是参数更多、训练更慢——因为每个词被拆成了多个单元。

## 5 哈希技巧与工程实现

所有字符 n-gram 的总数相当可观：假设字符集 70 个，n 取 3～6，光三元组就有 $70^3 \approx 34$ 万个；考虑所有长度，几百万量级是常态。fastText 的实现用一个简单粗暴的**哈希技巧（hashing trick）**：不维护一张完整的 n-gram 词典，而是把每个片段哈希映射到固定大小的「桶」上，多个片段可以共用一个桶，内存被硬性限制住。<span class="marginnote">哈希技巧在特征工程里是老朋友——本专题《文本表示基础：词袋模型与 TF-IDF》里对哈希特征（hashing vectorizer）也用过同样的思路。</span>

生成片段与哈希映射的代码很短：

```python
def char_ngrams(word, n=3, bound="<>"):
    """返回词的全部字符 n-gram（含整词）。"""
    w = f"{bound}{word}{bound}"
    grams = {f"{bound}{word}{bound}"}            # 整词作为一个单元
    for i in range(len(w) - n + 1):
        grams.add(w[i : i + n])
    return grams

grams = char_ngrams("where")
print(grams)
# {'<wh', 'whe', 'her', 'ere', 're>', '<where>'}，共 6 个单元

def hash_bucket(gram, B=2_000_000):
    return (hash(gram) % B + B) % B              # 稳定映射到非负桶号
```

注意 Python 内置 `hash` 对字符串默认随机化（跨进程不稳定），工程实现里应改用确定性的哈希函数（如 xxHash）；这里仅为示意。

## 6 辨析：字符 n-gram、BPE 与字标注

**辨析｜易错点：** 「子词（subword）」这个词同时指代了好几种不同的技术，最常被混为一谈的是下面三样，它们不是一回事：

| 技术 | 切分方式 | 是否重叠 | 数据驱动 | 用途 |
| --- | --- | --- | --- | --- |
| fastText 字符 n-gram | 固定窗口、全部截取 | 重叠 | 否 | 词表示（无监督） |
| BPE 子词切分 | 贪心合并高频字符对 | 不重叠 | 是 | 词表压缩（翻译/语言模型） |
| 字标注分词 | 按字打 B/I/E 标签 | 不重叠 | 是 | 中文分词（任务） |

- fastText 的 n-gram 是**表示手段**：它仍以「词」为单位组织语义，片段只是拼成词向量的零件。
- BPE 是**词表策略**：把稀有词切成更常见的子词单元，直接改变「什么是一个 token」。大模型的词表就是用 BPE 类的算法造的，见本专题机器翻译篇的子词切分。<span class="marginnote">BPE 与 fastText 的分工常被记反：前者决定「输入长什么样」，后者决定「向量怎么算」。GPT、BERT 用的是 BPE 词表加静态位置编码，不是 fastText。</span>
- 字标注分词是**任务**：中文分词本质上是一个「给每个字打 B/I/E 标签」的序列标注问题，与本专题第三篇《由字构词（字标注）分词》一脉相承。fastText 里的 n-gram 是字符片段，而字标注的「字」是完整的语言单位，两者层级不同。

**再辨析一个同名陷阱：** fastText 库里有「词向量」也有「文本分类器」，两者都叫 fastText。分类器是**有监督**的（用文本-标签对训练，见本专题第七篇文本分类），词向量是**无监督**的（只用文本本身）。同门但不同用途，别混用。

## 7 小结

- 静态词向量有三个缺口：**未登录词、形态信息缺失、低频词表示差**。
- FastText 把每个词拆成**字符 n-gram**（含整词），词向量等于全部片段向量之和：$v_w = \sum_{g \in G_w} z_g$。
- 训练沿用 **Skip-gram + 负采样**，只是把中心词向量换成子词向量之和；打分函数 $s(w,c) = \sum_g z_g^{\top} v_c$。
- **参数共享**让低频词与未登录词「借光」：没见过整词也能从片段拼出向量。
- **哈希技巧**把片段映射到固定桶，控制内存；片段生成只需几行代码。
- 与 **BPE**（词表策略）、**字标注**（分词任务）不同，fastText 的 n-gram 是纯粹的表示手段。

在下一节，我们把镜头转向「验收」：词向量到底好不好，不能只靠直觉，而要交给**词相似度与类比任务**去度量——这就是词向量的评价。
