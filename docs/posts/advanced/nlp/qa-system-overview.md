## 为什么从问答系统开始

搜索给你一屏链接，问答给你一个答案——「比尔·盖茨的母校是哪所大学？」的答案应该直接是「哈佛大学」，而不是十个网页。**问答系统（Question Answering, QA）**：用自然语言提问，直接返回精确答案。它是 NLP 诸多能力的**集大成检阅**：实体识别、句法、语义、推理、知识图谱，全都在一个「问答」任务里被检验。<span class="marginnote">问答系统是 NLP 最早的应用愿景之一——1950 年代就有「baseball」等早期的封闭域问答系统。它经历了<strong>规则模板 → 信息检索 → 知识库 → 机器阅读理解 → 开放域两阶段 → 大模型时代</strong>的演进，几乎是 NLP 技术史的一个微缩版本。第十三篇五篇博文，正好对应这几次技术跃迁。</span>

这一篇先立框架：QA 的任务类型、发展历程与评测——为后面四篇（检索 QA、KBQA、MRC、开放域）铺路。

## 1 什么是问答系统

**问答系统（QA）**：输入自然语言问题，输出**精确答案**（一个词、一个短语、一句话），或「无答案」。

与搜索的区别：

- **搜索**返回文档列表，用户自己找答案；
- **问答**直接返回答案，是「检索的终极形态」。

与对话系统（第十四篇）的区别：

- **问答**：一问一答，目标是**正确**；
- **对话**：多轮交互，目标是**自然**——可能没有「标准答案」。

**QA 的核心挑战**：理解问题（问的是什么）、定位答案（答案在哪）、验证答案（答得对不对）——每一步都考验不同的 NLP 能力。<span class="marginnote">QA 与信息检索（第四级专题）关系密切但不同：IR 是「找文档」，QA 是「找答案」。QA 常复用 IR 的检索技术做第一层召回（本篇第五篇开放域问答的「检索-阅读」框架正是如此）——检索负责缩小范围，阅读负责精确回答。</span>

## 2 QA 的任务类型

QA 可以从多个维度分类，先记最常用的四组：

**按答案来源**：

- **基于检索（retrieval-based）**：从文档库/网页里检索候选段落，再抽取答案；
- **知识库问答（KBQA）**：把问题映射成知识图谱查询，在图谱上拿答案；
- **生成式问答**：用生成模型直接「写」出答案（大模型时代的形态）。

**按领域范围**：

- **封闭域（closed-domain）**：限定领域（如只答医疗问题），问题类型受限、可深度定制；
- **开放域（open-domain）**：任意领域、任意问题——需要大规模知识源。

**按答案形态**：

- **抽取式（extractive）**：答案是从文本里**摘出的一段**（起止下标）；
- **生成式（abstractive）**：答案是**生成的句子**——可能不在原文里；
- **是/否与多项选择**：判断题、选择题形态。

**按问题类型**（IR 时代的经典分类）：事实型（谁/什么/何时/何地）、列表型、定义型、关系型、推理型……<span class="marginnote">事实型问题是 QA 的「基本盘」——「某公司的 CEO 是谁」这类单一事实问题，答案明确、评测容易。推理型（「如果 A 比 B 高，B 比 C 高，谁最高？」）与复杂问题（需要多步推理）是 QA 的进阶战场，考验的不只是「检索」而是「推理」。</span>

## 3 发展历程：五代问答系统

QA 的演进可以切成五代：

1. **规则时代（1950s–1970s）**：**BASEBALL**（1961）用模板解析「棒球数据」问题；**LUNAR**（1973）回答月球岩石数据问题。封闭域、规则模板、可工作但极受限。
2. **IR 时代（1990s–2000s）**：TREC QA 评测推动「检索 + 答案抽取」——先检索文档，再在文档里找答案片段。问题类型分类、答案类型预测成为关键技术。
3. **知识库时代（2010s）**：Freebase/Wikidata 兴起，**KBQA** 成为主流——问题转成图查询。后来深度学习加入（把问题转成查询生成，第十篇的语义解析）。
4. **机器阅读理解时代（2016–2019）**：**SQuAD** 数据集引爆 MRC——给定一篇文档 + 问题，从文档里抽取答案区间。BiDAF、QANet、BERT 一路刷新纪录（本篇第三、四篇）。
5. **开放域 + 大模型时代（2019 至今）**：**检索-阅读两阶段**（第五篇）覆盖任意问题；大语言模型把「生成式答案」推向主流——也带来**幻觉**问题（答案说得像真的却是编的）。<span class="marginnote">值得注意：每一代 QA 都没有「消灭」前代——今天的开放域 QA 系统里，检索（第二代）、KBQA（第三代）、抽取（第四代）技术依然在协同工作。大模型只是把「答案生成」这一环升级了，问题理解、证据检索仍然是整个系统的骨架。</span>

## 4 评测：从精确匹配到机器裁判

QA 评测随任务形态变化：

- **TREC 式检索 QA**：答案的**正确性**由人工/自动与标准答案比对——**MRR**（第一个正确答案的倒数排名）是经典指标。
- **SQuAD 式抽取 QA**：答案区间与标准答案**精确匹配（EM）**或 **F1**（按词重叠）。SQuAD 是 MRC 的事实基准。
- **开放域**：检索召回率 + 阅读准确率的组合，或用 **答案 F1**。
- **大模型生成式**：自动评测困难——常用 **ROUGE**（摘要指标）、**基于语言模型的打分**、以及**人工评测**（答案是否相关、忠实）。<span class="marginnote">生成式 QA 的评测是当前难点：模型的答案可能「语义正确但表达不同」——ROUGE 会误判，纯人工又贵。近年「用大模型当裁判」（LLM-as-judge）评测答案质量成为流行做法，但裁判模型自身的偏差仍是争议点。评测方法的演进，本身是 QA 研究的一部分。</span>

## 5 QA 的系统架构：一个统一的视角

把五代技术放进一个统一框架，QA 系统大致是**四段式**：

1. **问题理解**：类型分类（是/否、事实型）、实体/意图识别（第十二篇的查询理解）——「比尔·盖茨的母校」解析出实体「比尔·盖茨」与「母校」这个关系/属性；
2. **证据检索**：从知识源（文档库 / 知识图谱 / 网页）**召回候选**——IR 或图谱查询；
3. **答案抽取/生成**：从候选证据里定位答案——抽取（span）或生成（语言模型）；
4. **验证**：答案与问题、证据的一致性检查——「答非所问」的过滤。

**不同时代只是「每一段用什么技术」不同**——问题理解从模板变成 BERT，检索从 BM25 变成向量检索，答案从规则变成大模型生成。**架构的骨架始终没变**。<span class="marginnote">这个四段框架是理解后面四篇的「地图」：KBQA（第二篇）的答案是「查图谱」，MRC（第三、四篇）的答案是「从文档抽 span」，开放域（第五篇）是「检索 + 阅读」的组合。记住四段式，各篇博文只是在给不同段落换技术。</span>

## 6 辨析｜易错点：四个常见坑

**辨析｜易错点：**

- **QA 不是「检索 + 截取」**：把搜到的第一段话截一半当答案，是「伪问答」。真正的 QA 需要**问题理解 + 答案验证**——答案要对得上问题。
- **抽取式答案是「区间」，不是「句子」**：SQuAD 的答案是一个**连续区间**（可能是短语），评测按区间与标准答案匹配。把「整个句子」当答案会拉低 EM/F1。<span class="marginnote">一个细节：SQuAD 的 F1 按「词级重叠」算，即使区间不完全一致也有部分分；EM 则必须逐字相同。两个指标一起报，是 MRC 评测的惯例。</span>
- **开放域 ≠ 文档库里有答案**：开放域问题可能知识源里根本没有答案——系统要能说「无答案」或给出低置信度，而不是硬编一个。
- **生成式答案 ≠ 事实正确**：大模型能写出流畅答案，但可能**幻觉**（编造事实）。评测生成式 QA 必须同时看「流利」与「忠实」，只看流利会被骗。

## 7 小结

- **问答系统**：自然语言提问 → 精确答案，是 NLP 能力的集大成检阅。
- 任务类型四维：**检索式/KBQA/生成式**、**封闭域/开放域**、**抽取式/生成式**、**问题类型**。
- 五代演进：**规则（BASEBALL/LUNAR）→ IR 检索 → KBQA → MRC（SQuAD）→ 开放域 + 大模型**。
- 评测：TREC 用 MRR、SQuAD 用 EM/F1、生成式用 ROUGE + 人工 + LLM-as-judge。
- 统一架构：**问题理解 → 证据检索 → 答案抽取/生成 → 验证**——四段式骨架不变。
- 核心挑战：问题理解、证据召回、答案验证、幻觉控制。
