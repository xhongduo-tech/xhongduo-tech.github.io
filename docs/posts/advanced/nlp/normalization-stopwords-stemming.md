## 为什么从文本规范化开始

前面几篇我们已经把文本拆成了句子、切成了词、标上了词性。但一个诚实的现实是：**真实世界的原始文本远没有教科书里的例子干净**。英文有大小写与屈折变化——`run`、`runs`、`ran`、`running` 是一个意思的四种写法；数字有五花八门的格式——「2026年8月7日」「08/07/2026」「August 7, 2026」说的是同一天；网页文本里还混着标签、URL、表情符与拼写错误。如果把这样的文本直接送进统计模型，模型会把 `run` 和 `running` 当作两个毫无关系的词，把三种日期格式当作三个不同的特征——这正是我们在《语料统计基础：词频、齐普夫定律与稀疏性问题》里见过的稀疏性灾难的源头。<span class="marginnote">回想 Zipf 定律：少数高频词占据大部分出现次数，而大多数词只出现寥寥几次。屈折变化把本可以合并的统计量（run 的四种形式）拆成了四个「稀有词」，让低频问题雪上加霜。规范化就是对抗稀疏性的第一道手段。</span>

**文本规范化（text normalization）**：把原始文本转换为统一、规范形式的一整套预处理操作。它发生在分词与词性标注之前，是整个 NLP 流水线的第一站。<span class="marginnote">这一篇与《正则表达式与文本匹配》《中文分词问题》《词性标注》同属「文本预处理」篇：正则给了我们匹配的工具，分词解决了中文的切分，词性标注统一了词的类别，而规范化处理的是「同一个实体的不同写法」。四者合起来，才把自由文本变成可统计的单元序列。</span>这一篇我们聚焦规范化里的三件典型工作：**命名实体规范化、停用词处理、词形还原**。它们看似琐碎，却直接决定了下游每一个统计模型「看见」什么样的词表。

## 1 真实文本有多脏：规范化的流水线

把一段英文原始文本「走一遍」，看看规范化到底在收拾哪些残局：

> `The cats are running faster than the foxes!! Dr. Smith's office is at 123 Main St., and he was born on 08/07/2026.`

这段文本至少藏了四类问题：大小写不一致（句首 `The` 与句中 `the`）、屈折变化（`cats`、`running`、`foxes`）、标点与缩写（`!!`、`Dr.`、`St.`、`'s`）、以及非标准的日期格式（`08/07/2026`）。规范的流水线通常长这样：

1. **统一大小写**：英文全部小写化（中文无此步）。<span class="marginnote">小写化有一个代价：专有名词的信息会被抹掉（`Apple` 公司 vs `apple` 水果）。因此有些系统先做命名实体识别再小写化，或者保留大小写作为特征。这就是为什么「规范化」是一系列权衡，而不是机械的清理。</span>
2. **处理标点与特殊符号**：用正则把标点从词上剥下来，把 URL、邮箱、表情符替换成统一占位符（如 `<URL>`）。
3. **数字与日期规范化**：把各种格式的日期、货币、数字换算成统一形式。
4. **词形还原**：把屈折形式合并回原形（`running`→`run`、`cats`→`cat`）。
5. **停用词过滤**（可选）：按任务需求去掉高频但信息量低的词。

每一步都在做同一件事：**让「同一个东西」在文本里只以一种形式出现**。下面三节分别讲第 3、5、4 步。

## 2 命名实体规范化：把同一天写成同一串

**命名实体规范化（named entity normalization）**：把表示同一实体的不同书写形式，换算为统一的规范表示。注意它与**命名实体识别（NER）**的区别——识别回答「这个词是不是一个实体、是什么类型」（人名、地名、日期、金额），规范化回答「这个实体应该写作什么标准形式」。识别是找出来，规范化是统一写法。<span class="marginnote">命名实体识别我们会在第十一篇《信息抽取》专门展开；规范化往往是它的下游步骤。两者常被合称「实体识别与规范化」，但在工程上是两个阶段。</span>

举三个最常见的类别：

- **日期**：「2026年8月7日」「2026-08-07」「Aug 7, 2026」「明天」应统一成同一个内部表示，例如 ISO 格式 `2026-08-07`。
- **数字与金额**：「3,000,000」「三百万」「3 million」应统一为 `3000000` 或带单位的规范形式。
- **时间**：「五点半」「17:30」「5:30 PM」统一为 `17:30`。

**规范化与识别的一个关键区别：规范化可以「丢信息」而识别不能。** 比如把「08/07/2026」规范化成 `2026-08-07`，就丢掉了它原来「斜杠格式」的表面信息——而这对统计模型通常是好事，因为格式本身很少携带语义。

## 3 停用词：去掉还是留下？

**停用词（stop words）**：在文本中频繁出现、但对任务判别作用很小的功能词，如英文的 `the`、`is`、`a`，中文的「的」「了」「在」。把停用词从词表中剔除，可以显著压缩特征维度、降低噪声。

但停用词有一个著名的坑：**「高频」与「无用」并不等价**。

- 在情感分析里，`not`、`never` 这样的否定词极高频，却恰恰是翻转极性的关键——把它们当停用词删掉，`I am not happy` 就会与 `I am happy` 变成同一个向量。
- 在翻译与语义任务里，`the` 的译法（汉语没有冠词）本身就是要学的对应关系。

**辨析｜易错点：** 停用词不是语言的客观属性，而是**任务与模型决定的工程选择**。严谨的做法不是背一份固定词表，而是先做词频统计、观察哪些词在任务里确实无判别力，再决定是否剔除。现代神经网络模型（词向量、Transformer）一般**不删停用词**——它们能把低频与功能词都编码进稠密向量；停用词过滤主要在词袋模型、TF-IDF 这类离散表示的时代是标配。这个区别，下一篇《文本表示基础：词袋模型与 TF-IDF》会看得更清楚。

## 4 词形还原：Stemming 与 Lemmatization

英语词形变化丰富，但 `run`、`runs`、`running`、`ran` 指向同一个词汇单位。**词形还原**把屈折形式合并，主要有两条路线。

### 词干提取（Stemming）

**词干提取**：用规则砍掉词的词缀，得到「词干」。最经典的是波特词干器（Porter Stemmer，1980），它对英语制定了一整套后缀替换规则。例子：

- `cats` → `cat`
- `running` → `run`（Porter 的双写辅音规则同时处理了 `ing`）
- `relational` → `relat`（把 `-ational` 砍成 `-at`，结果不是一个词——词干提取不保证产出合法词）
- `went` → `went`（不规则形式，规则法无能为力）

### 词形还原（Lemmatization）

**词形还原**：借助词典与词法知识，把屈折形式还原为词典原形（lemma）。它通常需要先做词性标注，因为同一个词的不同词性要还原到不同的原形：`saw` 作名词还原为 `saw`（锯子），作动词还原为 `see`（看见）。

- `running` → `run`
- `went` → `go`
- `cats` → `cat`

两者的对比用一张表收住：

| 维度 | 词干提取（Stemming） | 词形还原（Lemmatization） |
| --- | --- | --- |
| 手段 | 规则砍词缀，不查词典 | 查词典 + 词形表，需要词性 |
| 结果 | 未必是词典词（`runn`） | 一定是词典原形（`run`） |
| 不规则形式 | 处理不了（`went`→`went`） | 可以（`went`→`go`） |
| 速度与代价 | 快、便宜 | 慢、需要词典与标注器 |
| 典型场景 | 信息检索、词频统计 | 语义分析、需要词义的地方 |

**重点：词干提取保速度、词形还原保精度。** 检索系统通常用词干提取——`runn` 虽然丑，但检索时与 `running` 撞得上；而需要语义精确的任务（词义消歧、翻译）则用词形还原。

## 5 公式解析：编辑距离

规范化的另一项工作是把拼写错误拉回正轨：`recieve` 应该被识别为 `receive` 的笔误。衡量两个字符串差异的经典工具是**编辑距离（edit distance，Levenshtein distance）**：把一个字符串变成另一个所需的最少编辑操作数，操作包括**插入、删除、替换**。

设两个字符串 $a$（长度 $m$）与 $b$（长度 $n$），$D(i,j)$ 表示「$a$ 的前 $i$ 个字符」变成「$b$ 的前 $j$ 个字符」的最小编辑数，则有递推式：

$$
D(i,j) = \min \begin{cases}
D(i-1, j) + 1 & \text{删除 } a_i \\
D(i, j-1) + 1 & \text{插入 } b_j \\
D(i-1, j-1) + \text{cost}(a_i, b_j) & \text{替换或相同}
\end{cases}
$$

其中 $\text{cost}(a_i, b_j) = 0$ 当 $a_i = b_j$，否则为 1；边界 $D(i,0)=i$、$D(0,j)=j$。逐步拆解这条公式：

- **第一步，看懂 $D(i,j)$ 的语义**：它是「前缀到前缀」的距离。$a$ 的前 $i$ 个字符与 $b$ 的前 $j$ 个字符对齐，越小的 $D$ 表示两串越相似。
- **第二步，三种操作对应三种「最后一步」**：要么删掉 $a$ 的最后一个字符（状态回到 $D(i-1,j)$），要么在 $b$ 侧补一个字符（回到 $D(i,j-1)$），要么让最后一个字符对齐、相同则零代价、不同则付一次替换（回到 $D(i-1,j-1)$）。
- **第三步，取最小值并填表**：从 $D(0,0)=0$ 出发，按行从左到右、逐行向下填满整个 $(m+1)\times(n+1)$ 表格，右下角的 $D(m,n)$ 就是最终答案。

例：$a=\text{cat}$，$b=\text{cut}$。$D(3,3)$ 的最优路径是「替换 $a$→`u`」，其余字符相同，因此编辑距离为 1——`recieve` 与 `receive` 的编辑距离为 1（一次交换位置在标准 Levenshtein 里记 2，若用 Damerau 变体可记 1）。<span class="marginnote">编辑距离不只是拼写纠错的度量：它在语音识别里用于比较识别结果与转写文本，在机器翻译评测 BLEU 的兄弟指标 WER（词错误率）里也是核心，后面第十篇讲机器翻译评测时还会见面。</span>

## 6 一段代码：把整个流水线走一遍

用 Python 的 `nltk` 把本节流程串起来：

```python
import re
from nltk.stem import PorterStemmer, WordNetLemmatizer
from nltk.corpus import stopwords

text = "The cats are running faster than the foxes!!  Dr. Smith was born on 08/07/2026."

# 1) 小写化 + 去掉标点，切分
tokens = [re.sub(r"[^a-z0-9\s]", "", t) for t in text.lower().split()]
tokens = [t for t in tokens if t]                      # 去掉空串

# 2) 停用词过滤
tokens = [t for t in tokens if t not in set(stopwords.words("english"))]

# 3) 词干提取（快，但可能产生非词）
ps = PorterStemmer()
stems = [ps.stem(t) for t in tokens]

# 4) 词形还原（慢，但还原到词典原形）
wnl = WordNetLemmatizer()
lemmas = [wnl.lemmatize(t, pos="v") for t in tokens]  # 按动词还原

print(tokens)   # ['cats', 'running', 'faster', 'foxes', 'dr', 'smith', 'born', '08072026']
print(stems)    # ['cat', 'run', 'faster', 'fox', 'dr', 'smith', 'born', '08072026']
print(lemmas)   # ['cat', 'run', 'faster', 'fox', 'dr', 'smith', 'bear', '08072026']
```

注意 `08072026` 是一串「规范」的数字——真正的工程里会用正则把 `08/07/2026` 先捕获成日期再格式化；这也是为什么规范化流水线里正则与实体规范化总是搭配出现。

## 7 小结

- **文本规范化**把自由文本变成统一形式，是对抗 Zipf 稀疏性的第一道手段，发生在分词与标注之前。
- **命名实体规范化**回答「怎么写」，与回答「是不是实体」的 NER 是两回事；日期、数字、时间都要统一格式。
- **停用词**是任务相关的工程选择，不是语言客观属性；情感分析里删 `not` 是灾难。
- **词干提取**靠规则、快、产出非词；**词形还原**靠词典、慢、回到原形，需要词性信息。
- **编辑距离**用递推公式计算字符串的最小编辑操作数，是拼写纠错与评测指标的基础。

在下一节，我们将把规范化后的文本变成机器能算的东西——**词袋模型（BoW）与 TF-IDF**，也就是向量空间模型的开端。
