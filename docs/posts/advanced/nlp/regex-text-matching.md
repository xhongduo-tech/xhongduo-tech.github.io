## 为什么先学正则表达式

语料库是原料，但在把原料喂给任何模型之前，还有一道工序：**把需要的部分从原始文本里精确地抠出来**。剥掉 HTML 标签、找出所有邮箱或日期、按规则切分 token、把「3rd 届」这种噪声标准化……这些听起来琐碎、却每天都得做的活儿，靠的是一个几十年不过时的工具——**正则表达式（regular expression，regex）**。<span class="marginnote">正则表达式是「文本处理的基本语法」：任何一段语料清洗都绕不开它，它也是把词法分析的思想落地到工程的接口。第三级《编译原理》里的词法分析器，本质上就是在手工构造正则→自动机的等价物。</span>

这一节的目标很实用：掌握正则的核心语法、看懂并写出匹配模式、在 Python 里用它处理真实语料，并躲开几个必踩的坑。

## 1 什么是正则表达式

**正则表达式（regular expression）**：一套描述「字符串模式」的微型语言。它用少量符号组合出「什么样的字符串算匹配」的规则，再由引擎在文本里找出所有满足规则的片段。

它与形式语言理论有深刻渊源：正则表达式描述的语言恰是**正则语言（regular language）**，而正则语言正好等于**有限自动机**能识别的语言。<span class="marginnote">正则表达式的概念源自数学家 Kleene 在 1956 年对神经网络的建模研究；后来 Ken Thompson（Unix 之父）把它实现进文本编辑器与 grep，才进入工程世界。grep 这个名字就是「global regular expression print」的缩写。</span>这意味着一个干净的正则匹配可以在**线性时间**内完成——这是它能成为大数据量文本预处理主力工具的原因。

**辨析｜易错点：** 正则表达式不是「任意模式匹配」。它描述的是**正则语言**，因此**无法**表达需要「记忆递归结构」的模式——比如「括号必须成对嵌套」这类匹配，超出正则的表达能力（需要上下文无关文法，见第八篇）。遇到这种需求，正确的做法是换用解析器，而不是硬写正则。

## 2 核心语法速查

正则的核心语法可以浓缩成一张表。掌握了这张表，绝大多数文本任务就能上手：

| 语法 | 含义 | 示例 |
| --- | --- | --- |
| `猫` | 字面字符 | `猫` 匹配「猫」 |
| `.` | 任意一个字符（不含换行） | `.` 匹配「a」、「b」 |
| `[abc]` | 字符类：a、b、c 中任意一个 | `[0-9]` 匹配任意数字 |
| `[^abc]` | 排除字符类：非 a、b、c | `[^0-9]` 匹配任意非数字 |
| `*` | 前一项重复 0 次或多次 | `ab*` 匹配「a」、「ab」、「abb」 |
| `+` | 前一项重复 1 次或多次 | `ab+` 匹配「ab」、「abb」，不匹配「a」 |
| `?` | 前一项出现 0 次或 1 次 | `colou?r` 匹配「color」与「colour」 |
| `{n,m}` | 前一项重复 n 到 m 次 | `\d{3,4}` 匹配 3 或 4 位数字 |
| `^` `$` | 行首 / 行尾锚点 | `^第` 匹配行首的「第」 |
| `\b` | 词边界 | `\bcat\b` 不匹配 category 里的 cat |
| `\|` | 交替（或） | `猫\|狗` 匹配「猫」或「狗」 |
| `(...)` | 分组与捕获 | `(ab)+` 匹配「abab」 |
| `\d` `\w` `\s` | 数字 / 词字符 / 空白 | 等价于 `[0-9]`、`[A-Za-z0-9_]`、`[ \t\n]` |
| `\D` `\W` `\S` | 上述的取反 | `\D` 匹配任意非数字 |

几个常用转义要特别注意：要匹配「字面意义上的特殊符号」（如 `.`、`*`、`+`、`?`），必须用反斜杠转义成 `\.`、`\*`、`\+`、`\?`。

## 3 分组、捕获与反向引用

括号 `(...)` 除了改变优先级，还带来两个重要能力：

**捕获（capture）**：被括号包住的部分会在匹配结果里单独取出来。提取结构化信息全靠它——比如从「张三 1990-05-03」里分别抓出姓名和日期。
**反向引用（backreference）**：用 `\1`、`\2` 引用前面第 1、2 个捕获组的内容，要求「再次出现同样的文本」。例如 `(\w+)\s+\1` 能匹配「word word」这种完全重复的相邻词。

捕获组也让「提取」有了优雅的写法。Python 里用 `re.search()` 拿到匹配对象后，`match.group(1)` 就是第一个括号里的内容。

```python
import re
text = "张三 1990-05-03"
m = re.search(r"(\w+)\s+(\d{4}-\d{2}-\d{2})", text)
name = m.group(1)   # '张三'
date = m.group(2)   # '1990-05-03'
```

## 4 贪心与懒惰：最容易踩的坑

默认情况下，量词 `*`、`+`、`?` 都是**贪婪（greedy）**的：它们会尽可能多地匹配字符。而这经常不是我们想要的。

**辨析｜易错点：贪心 vs 懒惰。** 对文本 `"foo" and "bar"`，正则 `".*"` 贪婪匹配会吞掉整个 `"foo" and "bar"`（从第一个引号一路吃到最后一个引号），而不是两个独立的引号片段。只要在量词后加一个 `?` 变成 `".*?"`，它就转为**懒惰（lazy）**匹配，遇到第一个满足条件的就停下，于是分别匹配出 `"foo"` 和 `"bar"`。<span class="marginnote">判断该用贪婪还是懒惰，一句话：<strong>「能多就多」还是「够就停」</strong>。提取 HTML/引号内的内容、找一对定界符之间最短片段时，几乎都要用懒惰量词。注意正则引擎也可能因回溯而性能退化——过度嵌套的贪婪量词是正则匹配变慢的常见原因。</span>

```python
import re
text = '"foo" and "bar"'
re.findall(r'".*"', text)    # 贪婪：['"foo" and "bar"']——整个吞掉
re.findall(r'".*?"', text)   # 懒惰：['"foo"', '"bar"']
```

## 5 公式解析：一条邮箱正则的逐步拆解

正则本身就是一种「模式公式」。把一条真实的邮箱匹配正则逐块拆开，比背语法更有效。考虑：

```python
EMAIL_RE = r'^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'
```

对这条模式做四步拆解：

**第一步，两端词边界 `\b`**：确保匹配到的是完整独立的「词」，避免 `foo@bar.com` 躲在 `xfoo@bar.com` 里被误抓。`\b` 匹配「词字符与非词字符的交界」。
**第二步，用户名 `[A-Za-z0-9._%+-]+`**：字符类列出邮箱用户名允许出现的字符，`+` 表示至少一个。注意字符类里的 `-` 放在末尾就失去「区间」含义，变成普通字符。
**第三步，域名主体 `[A-Za-z0-9.-]+` 与 `\.`**：域名部分允许字母数字、点与连字符；`\.` 是被转义的**字面点号**——这里如果写成未转义的 `.`，就变成「任意一个字符」，匹配范围就错了。这是正则里最高频的错误之一。
**第四步，顶级域名 `[A-Za-z]{2,}`**：`com`、`cn` 这类顶级域，至少 2 个字母。

**辨析｜易错点：写正则时先想「允许什么」而不是「所有可能长什么样」。** 上面的模式不是要穷举所有合法邮箱，而是**定义一个保守可接受的字符集合**——这是工程上正确的态度：宁可少匹配，不可乱匹配。

## 6 在 Python 里处理语料：三个实战场景

Python 的 `re` 模块是 NLP 预处理最常用的搭档。注意正则本身也含有反斜杠，所以**模式串一律写成原始字符串 `r"..."`**，否则 `\b`、`\d` 会被 Python 字符串先吃掉一层。

**场景一：语料清洗——去掉 HTML 标签并折叠空白**

```python
import re
html = "<p>Hello,  <b>world</b>!</p>"
clean = re.sub(r"<[^>]+>", "", html)  # 去掉标签 → "Hello,  world!"
clean = re.sub(r"\s+", " ", clean)    # 折叠空白 → "Hello, world!"
```

**场景二：切分 token 的雏形——按非字母数字切分**

```python
text = "Hello, world! NLP is fun."
tokens = re.split(r"[^A-Za-z0-9]+", text)  # → ['Hello', 'world', 'NLP', 'is', 'fun', '']
tokens = [t for t in tokens if t]          # 去掉首尾空串
```

**场景三：批量抽取——抓出文本里的所有日期**

```python
text = "发布于 2023-05-17，修订于 2023/12/30。"
dates = re.findall(r"\d{4}[-/]\d{2}[-/]\d{2}", text)
# → ['2023-05-17', '2023/12/30']
```

第三个例子里用字符类 `[-/]` 同时容忍两种分隔符——**用「或」与「字符类」去兼容真实世界的多样性**，是正则处理脏数据的核心思想。<span class="marginnote">要注意 `\w` 在 Python 3 里默认匹配任意 Unicode 词字符，<strong>包含中文与下划线</strong>，而不只是 `[A-Za-z0-9_]`。这方便了中文处理，但也意味着「我以为 `\w` 只匹配英文」的想法在中文语料上会出错——需要只匹配英文时，老老实实写 `[A-Za-z0-9_]`。</span>

## 7 小结

- **正则表达式**描述正则语言，等价于有限自动机，可在线性时间内匹配；但**无法**表达需要递归记忆的结构（如成对嵌套括号）。
- 核心语法：**字符类、量词、锚点、交替、分组**；匹配特殊符号要转义。
- **分组捕获**用于提取结构化信息；**反向引用** `\1` 要求文本重复出现。
- **量词默认贪婪**，加 `?` 变懒惰——提取定界符之间的最短片段时用懒惰量词。
- 实战三件事：**清洗（`re.sub()`）、切分（`re.split()`）、抽取（`re.findall()`）**；模式串一律用 `r"..."` 原始字符串。
- 写正则的原则：**定义「允许什么」的保守集合**，宁缺毋滥。
