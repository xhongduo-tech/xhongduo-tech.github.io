# 表征评估与线性探测

<div class="epigraph">
<p>评估表示质量的最佳方式，是看它在目标任务上的下游表现——尤其是用很少的监督就能达到的性能。</p>

## 为什么「学表示」必须配「评表示」

前八篇都在生产表示，但缺少一把尺子。一个残酷的事实是：**表示的好坏无法直接从它的形态判断**——你不能看一眼 latent 向量就说它「好」。甚至本专题内部已经埋下证据：InfoNCE 的损失绝对值不可比，β 调高解耦指标上升但重构变差——那到底哪个表示更好？

Bengio 综述把答案说得很朴素：**表示的好，只有在下游任务上才知道**。本篇介绍一套科学的评估框架，其中最重要的工具是**线性探测**——用「一个简单分类器能在冻结的表示上达到多好」来度量表示本身。<span class="marginnote">「用线性模型评估表示」有个深刻理由：冻结表示 + 线性分类器 = 只考验「表示是否把信息组织成可分离的形式」，排除「深层分类器足够强、靠它硬记」的干扰。这样测出来的性能，才近似等于「表示的信息含量」。这一节在 2013 年写就，如今仍是自监督学习论文的标准评估套路。</span>

评估不是「收尾可有可无的一步」，它其实是表示学习**方法论的地基**——没有可靠的尺子，「哪种表示更好」就只能停留在口头争论。

## 1 为什么线性模型是「公平的探针」

先立原则：**评估表示时，探针越简单越好。** 如果你在表示后面接一个 20 层分类器一起微调，测出来的成绩是「表示 + 分类器」共同贡献的，无法归因于表示。

反之，线性分类器只有一层权重，能拟合的映射极其有限——它几乎测不出「深层非线性结构」，只测得出「表示本身把类别分得有多开」。<span class="marginnote">这正是上一篇《流形学习假设》的工程兑现：好的表示应把流形展平，让「线性可分」成立。所以线性探测的准确率，本质上是在检验「表示是否完成了展平流形这件工作」。</span>

**线性探测（linear probing）**：冻结预训练编码器 $f$ 的参数，在其输出 $h = f(x)$ 上训练一个线性分类器（softmax / 逻辑回归），用这个分类器在测试集上的准确率作为「表示质量」的指标。

注意「冻结」这个动作的分量：**探针不许改表示，只许用表示**。一旦允许微调表示本身，就又回到「表示 + 分类器」的混合测量了。线性探测能回答三种问题：

**表示里有没有这个信息**？线性分类器都学不出来，说明信息在表示里不可用（被丢弃或纠缠到非线性）；
- **表示里的信息有多「线性可用」**？同样是 80% 准确率，用线性 vs 深度探针的差距，反映表示的组织方式；
- **不同方法学的表示哪个更优**？同数据、同探针、同协议下，准确率直接可比。

## 2 评估的三个维度

Bengio 综述把评估拆成三个互补的维度，缺一不可：

**监督性能（supervised performance）**：在标准数据集（如 ImageNet、下游分类任务）上，用（最好是很小的）标签集微调或线性探测，报告准确率。**关键细节是「标签量」**——Bengio 特别强调：好的表示应当在**极少标注**下也能快速达到较高性能，因为它把「信息」与「分类器」分离了：表示若把知识组织好，一小撮样本就能教会线性层利用它们。<span class="marginnote">这正是自监督学习论文的惯例：ImageNet 线性探测准确率、以及「10% 标签」协议。一个表示如果只在 100% 标签下厉害、10% 标签下崩盘，说明信息藏在「需要大量监督才能榨出」的地方，质量有限。</span>

「标签量」这个视角还解释了为什么**评估要测曲线而不是测单点**：好的表示应该在「标签从 1% 到 100%」的全谱上都保持优势，而不是只在某个标签量上领先。单点比较常常被运气主导，曲线比较才暴露方法本质。

直观记忆：**表示把「信息」存好，线性层负责「读出」**——标签越少，「读出」越难，此时正是表示存储质量最见真章的时刻。

**迁移性能（transfer performance）**：表示是从任务 A 学的，拿到任务 B 上测。好的表示应当**跨任务可复用**——因为它学的是「数据底层结构」而非「任务特有捷径」。多模态与跨域场景（图像→视频、分类→检测）尤其看重这一点。

**无监督的诊断（unsupervised diagnostics）**：不依赖标签的辅助指标——聚类的纯度（purity）与标准化互信息（NMI）、表示的维度相关性、互信息估计、t-SNE 可视化等。它们不直接等于任务性能，但能暴露「表示里信息的组织方式」，适合在标签稀缺时快速体检。<span class="marginnote">NMI 的思想：把「真实标签」与「对表示做的聚类结果」看成两个随机变量，看它们共享多少信息（用熵归一化到 0–1）。它是《深度聚类表示》一篇的主角指标之一，本篇先打个照面。</span>

三个维度各有分工：**监督性能回答「够不够好」**，**迁移性能回答「通用不通用」**，**无监督诊断回答「长得规不规整」**。一篇完整的评估报告，三问缺一不可。

顺带一提，「迁移」与「泛化」在直觉上常被混用：**泛化**指「没见过的新样本」，**迁移**指「没见过的新任务」——前者测的是「表示贴不贴数据流形」，后者测的是「表示里的知识能不能搬走」。一字之差，评估的正是完全不同的东西。

## 3 公式解析：线性探测的优化目标

把线性探测写成优化问题。给定冻结表示 $\{h^{(i)} = f(x^{(i)})\}_{i=1}^n$ 与标签 $\{y^{(i)}\}_{i=1}^n$（$C$ 类），训练一个线性层（权重 $W \in \mathbb{R}^{d \times C}$，偏置 $b$）：

$$
\min_{W, b} \ \frac{1}{n}\sum_{i=1}^{n} \ell\Big(W^{\top} h^{(i)} + b,\ y^{(i)}\Big) + \lambda\,\lVert W \rVert_F^2
$$

- **第一步，读结构**：$W^{\top} h + b$ 把表示线性映射成 $C$ 维类别得分；$\ell$ 常用交叉熵（分类）或平方误差（回归）。**$f$ 的参数全程不更新**——这是「探测」与「微调」的分水岭。
- **第二步，读正则**：$\lambda \lVert W \rVert_F^2$ 是权重衰减，防止线性层在小标签集上过拟合，保证探针「尽力而为」、测的是表示而不是探针本身。
- **第三步，读归因逻辑**：线性层能拟合的决策面只是超平面，所以准确率 $a_{\text{probe}}$ 高的含义非常干净——**数据在表示空间里本来就靠近「按类别的超平面分离」**。若 $a_{\text{probe}}$ 低而深度探针高，说明信息存在但被纠缠得需要非线性才可分——这本身就是对「解耦/线性化」程度的诊断。
- **第四步，读比较协议**：同数据集、同切分、同探针、同 $\lambda$ 下比较不同表示——所有条件等同时的准确率差，才归因于表示质量。**没有协议的可比性，就没有评估。**

## 4 线性探测的局限与补强

线性探测如此常用，也因为它被验证简单有效，但必须诚实交代它的三个局限：

第一，**它低估「非线性结构」的价值**。如果表示里信息组织是「局部线性但全局弯曲」的，线性探针会打低分，而真实下游任务（如检测、分割）可能表现不差——此时应同时报 k-NN 探针或轻量微调结果作对照。<span class="marginnote">惯例是「双探针」：线性探测 + k-NN（在表示空间做最近邻）一起报。k-NN 不需要训练，还能反映表示空间的局部几何——两者差距大时，往往藏着表示组织方式的重要线索。</span>

第二，**它测的是「可分性」而非「可解释性」**。解耦得漂漂亮亮的表示与瞎打乱维度的表示，线性探测分数可以相同——评估可解释性需要专门的解耦指标（见《解纠缠表示与 β-VAE》篇）。

第三，**协议细节会左右结论**。增强、温度、批次、epoch、学习率，甚至「用投影头输出还是编码器输出」，都会改变分数。近年的共识是：**比较时固定协议，且多报几个视角（linear + kNN + few-shot + 下游微调）**，结论才站得住。

**辨析｜易错点：** 最危险的错误是**在测试集上调参**——用验证集调探针/选温度后再碰测试集，本无可厚非；但不少工作「反复试到测试集分数最高」再报告，等于把测试集泄漏进训练。负责任的报告必须写明「探针超参在哪张集上调的」。

补充一个容易忽视的细节：**线性探测对「表示均值是否被居中」敏感**——BN 层、是否减去均值都会显著改变分数；而 k-NN 不受此影响。所以「双探针差很大」时，先检查是不是这种平凡的预处理差异，再谈「组织方式不同」。

## 5 回到主线：评估如何反哺设计

评估不是终点，它反过来塑造了表示学习的「审美」——哪类目标函数会被选中，常常取决于它在线性探测上的表现。这一点在本专题的脉络里特别清楚：<span class="marginnote">2018 年后的自监督工作把「线性探测准确率」当成头号榜单，于是增强设计、投影头、大批次、负样本工程全部围绕「怎么让线性探测分更高」被反复打磨——这是评估与设计共同进化、互相驯化的一个鲜活案例。</span>

- InfoNCE 的投影头就是评估反馈的产物：直接在编码器上算 InfoNCE，表示会被「对比任务的度量」带偏；换成线性探测，发现「投影前的特征」反而更通用——于是投影头被拆出来专门做对比、编码器专门做表示；
- 自编码器/VAE 评估的重构误差，与下游线性探测经常「打架」——重构好不代表表示可分；
- 因此一篇完整表示学习论文的结尾，永远是三件套：**上游目标（怎么学）→ 评估协议（怎么测）→ 下游应用（有什么用）**，缺一不可。

一句话收束：**评估标准选择了方法，方法又反哺评估标准**——这个闭环就是我们整个专题「从学表示到评表示」的动力学。

## 6 一份「负责任报告」的检查清单

把本篇的教训收敛成一张可操作的清单。当你要比较两个表示时，先逐项核对报告里是否写清了：

| 检查项 | 为什么必须写清 | 常见踩坑 |
| --- | --- | --- |
| 探针类型（线性 / k-NN / 微调） | 不同类型测不同的东西 | 只报深度探针，掩盖线性可分性差 |
| 用了多少标签（10% / 100%） | 好表示应小标签量也强 | 只报 100% 标签，掩盖「靠监督硬喂」 |
| 数据集与切分 | 跨数据集不可比 | 换数据集横向比分数 |
| 温度 / 批次 / epoch | 超参敏感、影响巨大 | 同损失不同超参比分数 |
| 增强与投影头选择 | 决定「表示 vs 度量」 | 用投影头分数冒充编码器分数 |
| 超参在哪张集上调 | 防测试集泄漏 | 在测试集上反复试到满意再报 |

对照这张表，还能得到一个更宏观的判断标准：**一个报告的「诚实度」，几乎与它披露的控制变量数量成正比**。披露得越少，越要警惕它报的分数。

反过来，这张清单也是设计实验的路线图——从「学表示」到「报分数」，每一步的变量都要能追溯到上游方法的一个设计决策。这才是评估反哺设计的完整闭环。

## 7 小结

- 表示的好坏**只能在下游任务上判断**；评估时探针越简单，结果越能归因于表示本身。
- **线性探测**：冻结编码器、只训线性层，准确率 ≈ 「表示把类别分开的程度」，即流形展平的工程度量。
- 评估三维度：**监督性能（重视小标签量）**、**迁移性能（跨任务复用）**、**无监督诊断（NMI / 纯度 / 可视化）**。
- 线性探测局限：低估非线性结构、不测可解释性、协议敏感——建议「双探针 + 多视角」。
- 辨析：别在测试集上调参；报告必须写明协议。
- 评估反哺设计：投影头、增强、批次这些设计，很大程度上是被线性探测的榜单「驯化」出来的。
