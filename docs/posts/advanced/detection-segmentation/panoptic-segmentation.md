# 全景分割：让每个像素都有身份

<div class="epigraph">

## 为什么从 Panoptic 开始

语义分割把「类别」涂满每个像素，实例分割把「可数的物体」逐个切开——但它们都只回答了一半问题：语义分割把三个人糊成一片「人」，实例分割对天空、道路这类**不可数背景**无能为力。**全景分割（panoptic segmentation）**（Kirillov 等，2019）把两者焊成一个完整任务：**给图像的每一个像素同时分配「类别」与「实例身份」**——可数的「物体（things）」既要类别又要逐个分开，不可数的「背景（stuff）」给类别即可。

它是分割任务的「终极形式」，也是衡量「一个视觉系统是否真正理解画面」的标尺——**「每个像素都知道」是比「每块区域都认识」更强的理解**。<span class="marginnote">「things vs stuff」是全景分割的世界观基石：things 是有独立形状、可数的物体（人、车），stuff 是无固定形状、连绵成片的背景（天空、道路、草地）。生物学家会说：things 是「个体」，stuff 是「物质」——这个划分也呼应了图像理解里「前景-背景」的古老直觉，只是现在要统一在一个框架里。</span>

## 1 things 与 stuff：分割世界的两个阵营

理解全景分割，先要理解它要统一的两类对象。这个划分看起来平淡，实则是整个任务设计的支点——**things 需要「数数」的能力，stuff 不需要**，这决定了它们在表示与度量上的根本差异。

| 维度 | things（物体） | stuff（背景） |
| --- | --- | --- |
| 实例身份 | 需要逐个区分 | 不需要，一个类别一片 |
| 形状 | 有明确边界、可数 | 连绵成片、无定形 |
| 方法 | 实例分割（Mask R-CNN） | 语义分割（U-Net/DeepLab） |
| 例子 | 人、车、猫、瓶 | 天空、道路、草地、墙 |

**全景分割的输出**是「一张图 + 一份清单」：每个像素都被标上一个标签「$(c_i, id_i)$」——类别 $c_i$ 与实例编号 $id_i$。

stuff 类别的所有像素共享同一个实例编号（等于类别本身），things 类别则每块单独编号。**于是全景图 = 一张逐像素类别图 + 一张逐像素实例 ID 图**——两张图叠起来，就是「整幅画面的完整清单」。

三种分割任务放在同一张表里，界线就清楚了：

| 任务 | 输出 | 背景（stuff） | 前景（things） |
| --- | --- | --- | --- |
| 语义分割 | 逐像素类别 | ✓ | ✓（不分个体） |
| 实例分割 | 前景实例掩码 | ✗ | ✓（分个体） |
| 全景分割 | 逐像素类别 + 实例 ID | ✓ | ✓（分个体） |

**语义分割与实例分割各缺一半，全景分割把它们补全**——这正是它被称为「终极形式」的原因。

## 2 Panoptic FPN：两路输出，一处融合

**Panoptic FPN**（Kirillov 等，2019，与《全景分割》同年）是全景分割的标准基线实现，它的设计思路是「**各干各的，最后缝合**」：

1. **共享骨干（FPN）**：一个特征金字塔提供多尺度特征——FPN 的语义见《R-CNN 系列》与《YOLO 单阶段检测》的多尺度讨论。
2. **双头**：一个**语义分割头**预测 stuff 类别的逐像素语义图；一个**实例分割头**（Mask R-CNN 风格）预测 things 的实例掩码。
3. **融合模块（merging）**：把两路输出拼成一张全景图——先铺语义背景，再把实例掩码按「置信度优先」覆盖上去。

融合时要遵守几条硬规则：**每个像素只属于一个标签**（要么 stuff 要么某个 thing）、**实例掩码之间不许重叠**、**stuff 区域不许被实例洞穿**。

**辨析｜易错点**：全景分割不是「语义分割 + 实例分割的简单叠图」。如果两路输出冲突（比如一个像素既被语义头标成「人」，又被实例头标成「车」），必须有一个裁决规则——Panoptic FPN 用「按置信度排序、先高后低地粘贴」解决，但这只是众多可能规则之一。**「如何消解两路的冲突」才是全景分割真正的设计难点**，而不是「两路各自做得准」。<span class="marginnote">「缝合」听起来容易，实现却要处理很多冲突：实例掩码可能互相重叠、可能伸出候选框、可能盖住本该是 stuff 的区域。Panoptic FPN 用「按置信度排序、先高后低地粘贴」的贪心策略解决——这不禁让人想起检测里的 NMS，都是「冲突消解」的不同形态。</span>

## 3 PQ：全景分割的评分标准

有了任务就要有标尺。**全景质量（Panoptic Quality, PQ）**把「分割得好不好」拆成「匹配 + 质量」两步：

$$
\mathrm{PQ} = \underbrace{\frac{\sum_{(p,g)\in \mathrm{TP}} \mathrm{IoU}(p,g)}{|\mathrm{TP}|}}_{\mathrm{SQ}} \times \underbrace{\frac{|\mathrm{TP}|}{|\mathrm{TP}| + \frac{1}{2}|\mathrm{FP}| + \frac{1}{2}|\mathrm{FN}|}}_{\mathrm{RQ}}
$$

其中预测片段 $p$ 与真值片段 $g$ 先按「IoU $> 0.5$」配对，配上的记 TP、多余的预测记 FP、漏掉的真值记 FN。

**关键细节：PQ 的匹配不区分 things 与 stuff——两类片段用同一套规则比拼**，这样「一个分数评全部」。**这个「统一」不是偷懒，而是刻意的设计**：如果 things 与 stuff 分开评分，就无法回答「哪个系统整体理解得更好」这个唯一重要的问题。

**一个具体例子**让 PQ 落地。假设一幅街景图里有 3 个真值片段（两辆车 + 一片天空）；预测给出了 4 个片段（两辆车、一片天空、一段错报的「墙」）。

- 两辆车的预测与真值都配对成功（IoU > 0.5），TP $=2$，且两者 IoU 平均为 0.8，则 SQ $=0.8$。
- 天空配对成功，TP 加 1；那面错报的「墙」记为 FP $=1$；真值里没有漏检，FN $=0$。
- 于是 RQ $= 3 / (3 + 0.5\times 1 + 0) = 0.857$，PQ $= 0.8 \times 0.857 \approx 0.686$。

**辨析｜易错点**：FP 与 FN 都只记 0.5 的代价（而非 1），意味着「多报一块」或「漏报一块」对 PQ 的伤害比「报错形状」轻——这是 PQ 对「切错」比「多切/漏切」更宽容的原因，也是它被质疑「对过分割不够敏感」的由来。

拆解 PQ：

- **分割质量 SQ（Segmentation Quality）**：所有匹配对 IoU 的平均——度量「切得准不准」。
- **识别质量 RQ（Recognition Quality）**：类似 F1 分数——度量「找全了没、多找了没」。
- **PQ = SQ × RQ**：**只切得准却找不到目标（SQ 高、RQ 低），PQ 照样不高**；两个子指标相乘，缺一不可。<span class="marginnote">PQ 的设计哲学是「宁可少错、不要贪多」：FP 与 FN 都只记 0.5 的代价（而非 1），因为全景任务里「把一块东西切错比漏掉它更常见」。这个 0.5 的权衡是数据集统计出来的经验值，它让 PQ 对「过度分割」和「欠分割」都敏感但都不惩罚过重。</span>

**拆开 SQ 与 RQ 看模型行为**：一个 PQ 低的系统，若 SQ 低，说明「切得糊」；若 RQ 低，说明「找不全/找多了」——**PQ 不仅给分数，还给了诊断的方向**，这是它作为评估指标的第二重价值。

## 4 公式解析：PQ = SQ × RQ 的信息学直觉

PQ 之所以设计成 SQ × RQ 而非简单加和，有深刻的信息学考量，我们分三步看：

**第一步，把分割看成「通信」**：分割系统从图像中「恢复」真值片段集合。RQ 度量「有多少片段被正确找到」（召回/查准的信息量），SQ 度量「找到的片段里细节还原得有多准」（单片段质量）。
- **辨析｜易错点**：注意 SQ 与 RQ 的分工——SQ 只管「已经匹配上的片段切得准不准」，**完全不管**没找到的片段；漏掉的片段全部算进 RQ 的 FN。**「质量」和「数量」被拆成两个因子相乘，这正是 PQ 能同时惩罚形状误差与漏检的原因**。
- **第二步，为什么相乘**：如果相加，系统可以「用大量质量差的片段堆出高分」，也可以「用极少数高质量片段刷分」；相乘迫使两个维度同时要好——**RQ 低则整体被惩罚，SQ 低同样被惩罚**。

这类似于概率里「独立事件同时发生」的乘法原理（见第一级《概率》）：只有两个条件都满足，结果才成立。**「两个都好的系统才是好系统」——这种「相乘而非相加」的评分哲学，在 PQ 里体现得最纯粹**。
- **第三步，数学性质**：SQ ∈ [0,1]、RQ ∈ [0,1]，所以 PQ ∈ [0,1]。当预测完全正确时 PQ = 1；当预测完全落空时 PQ = 0。**一个标量，同时惩罚分类错误、漏检、误检与形状误差**——这是全景分割能成为「统一标尺」的原因。

**这个性质让 PQ 可以跨数据集比较**：不管数据集里是 stuff 多还是 things 多，PQ 都用同一把尺子量「系统对整幅画面的理解程度」。<span class="marginnote">对比一下：检测界用 mAP（召回-精度曲线下的面积）评估，分割界用 mIoU（逐像素交并比）评估；PQ 把两者统一——对 things 片段它像 mAP（有匹配概念），对 stuff 片段它像 mIoU（逐类覆盖）。「一个分数全兼容」让全景分割可以直接比拼。</span>

## 5 全景分割与自动驾驶、通用视觉

全景分割不是学术玩具，它是**视觉理解任务的完整形态**：

**自动驾驶**：车辆需要同时知道「那是行人（things，要数清有几个）」和「那是车道线（stuff，只要类别）」，并让两者对齐到同一坐标系——BEV 全景分割（见《3D 检测与 BEV 感知》）正是量产方案的核心。
- **通用视觉助手**：图像描述、视觉问答、编辑都需要「逐像素全知道」的理解；Panoptic 输出是这些系统最自然的「像素级语义接口」。
- **评价体系**：PQ 已经成为全景分割事实标准，并催生了延伸指标（如 panoptic IoU、基于边缘的 PQ）。

它的局限也摆在明面上：**things 与 stuff 两个头各自训练，融合仍是手工规则**；同一类的两个重叠实例、严重遮挡时的实例分裂，仍难完美。

后续的 Mask2Former、Panoptic SegFormer 改用「mask + 查询」的 Transformer 范式统一建模——那是 DETR 血脉在分割领域的延伸，也预告了本专题的收尾主题：**「每个任务一个专门头」终将被「一套查询跑所有任务」取代**。<span class="marginnote">Mask2Former 的一步关键简化：把「语义头 + 实例头」两套流水线，换成「一组 mask 查询 + 一个分类」——things 与 stuff 都用「mask + 类别」表示，融合冲突从源头消失。这再次印证检测-分割史的同一轨迹：从手工模块走向「让网络自己学」。</span>

## 6 小结

- **全景分割**统一语义分割（stuff）与实例分割（things），要求每个像素都有「类别 + 实例身份」。
- **Panoptic FPN**用「语义头 + 实例头 + 手工融合」实现基线，冲突消解靠置信度贪心粘贴。
- **PQ = SQ × RQ**：SQ 度量切得准，RQ 度量找得全，相乘保证两个维度同时好。
- PQ 的匹配不区分 things 与 stuff，一类标尺评全部，兼顾 mAP 与 mIoU 的精神。
- 全景分割是视觉理解的「完整形态」，但双头 + 手工融合的局限引向 Transformer 统一范式（Mask2Former）。
