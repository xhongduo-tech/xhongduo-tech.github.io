## 为什么从数据构造开始

上一节的规模定律给出了一个反直觉的结论：**参数不是最稀缺的资源，数据才是**。Chinchilla 告诉我们最优配比是「每 20 参数配 1 token」，那一个 70B 模型就需要约 1.4T token。去哪里找这么多高质量文本？直接抓互联网会混入垃圾、重复、机器噪声——**喂错数据，模型学到的是垃圾分布的「规律」**。<span class="marginnote">「垃圾进，垃圾出」（garbage in, garbage out）在统计学习里是老话，但在大模型时代被抬到了新的高度：语料分布直接决定模型能学会什么、不能学会什么。</span>

**预训练数据构造（pretraining data construction）**：把原始网页语料转成可用于训练的 token 序列的全流程——清洗、过滤、去重、配比、分词。它的目标不是「最大化数据量」，而是「在给定算力下最大化数据的有效信息量」。

## 1 原始语料：从 Common Crawl 说起

绝大多数开源预训练语料的源头是 **Common Crawl**——一个免费爬取的网页存档，量级在 PB 级。但 Common Crawl 是「原生态」的：夹杂广告、导航栏、重复段落、机器生成垃圾、代码、乱码。

LLaMA 的数据来源与配比（论文 §2.1 原文表 1）：

| 数据源 | 量级 | 说明 |
| --- | --- | --- |
| CommonCrawl | 3.3T tokens | 经清洗去重，占大头 |
| C4 | 0.8T tokens | 更干净的网页子集 |
| GitHub | 0.8T tokens | 代码，训练代码能力 |
| Wikipedia | 0.05T tokens | 高质量百科，多次过采样 |
| Books | 0.15T tokens | 图书，长文档能力 |
| ArXiv / StackExchange | 0.15T tokens | 学术与问答 |

**辨析｜易错点：** 直觉上应该「让数据源占比反映互联网真实分布」，但 LLaMA 做了完全相反的事——**对高质量小语料（Wikipedia、Books、ArXiv）反复过采样**。原因正是规模定律的另一面：高噪声网页语料的「有效信息密度」远低于高密度文本，模型从 1 个高质量 token 学到的比从 10 个噪声 token 学到的多。<span class="marginnote">这也是「数据配比」成为一门手艺的原因：不同语料的学习价值差异可能达到数量级。</span>

## 2 清洗与过滤：去噪的四道工序

LLaMA 对 CommonCrawl 做了四步处理，这几乎是所有预训练数据管线的标准动作：

**第一步，语言识别**：用 fastText 等分类器过滤掉非英语页面（多语言模型则按语言拆分保留）。
- **第二步，启发式规则**：过滤掉包含「lorem ipsum」、导航字样、JavaScript 错误提示等机器痕迹的页面——这些是模板化垃圾的特征签名。
- **第三步，质量筛选**：训练一个**分类器**（以高质参考语料为正例）来打分，保留分数高的一段窗口。这本质上是把「质量」变成了可排序的标量。
- **第四步，去重**：在文档级与行级做**模糊去重**。LLaMA 用 MinHash（一种近似指纹）在段落粒度去重，再在文档级做后缀数组去重。

**去重为什么如此重要？** 因为重复数据会让模型**背题**而非**学会**——当某个文本出现 100 次，模型对它的过拟合程度会被放大 100 倍，同时挤占了其他独特文本的学习机会。<span class="marginnote">数据去重还有隐私与评估上的双重意义：重复的训练文本可能「泄漏」到测试集里，污染 benchmark 结果（见《评估基准与 zero-shot》）。</span>

## 3 配比的艺术：数据不平衡与「瓶颈优先级」

配比（mix）决定各数据源在训练时的采样权重。它有一个朴素但重要的原则：**越接近「模型部署时面对的分布」，权重越高；越「稀有但关键」，越要过采样**。

$$ p(\text{源}_i) = \frac{w_i \cdot |\text{源}_i|}{\sum_j w_j \cdot |\text{源}_j|} $$

其中 $w_i$ 是源 $i$ 的过采样倍数，$|\text{源}_i|$ 是它的原始 token 数。当 $w_i > 1$ 时，该源会被**重复采样**（一轮训练中同一份文本出现多次）。LLaMA 里 Wikipedia 的 $w$ 就明显大于 1。

**核心思想：数据配比 = 在「多样性」与「关键性」之间做权衡。** 过多网页噪声会稀释数学与代码能力；完全不要噪声又失去世界知识。业界流行「proportional + 小源过采样」配方：先按规模比例给一个大权重，再给高质量小源补一个额外的提升系数。<span class="marginnote">配比还有时间维度的版本：有些训练管线用「课程学习」（curriculum learning），先喂简单数据再喂难数据，或用「quality upsampling」在训练后期提高高质量数据比例，像学外语先读绘本再读报刊。</span>

## 4 数据管线与 Token 的关系

数据构造的最后一环是**分词**（tokenization），把文本切成 token 流。这里有个常被忽视的反馈：**配比通常按 token 数而非字符数计量**。一段中文在 BPE 分词下 token 数可能与英文差异很大，于是「token 预算 1.4T」实际对应多少「人类可读文本」取决于分词器。我们在《分词算法（BPE/SentencePiece/Unigram）》专门展开。

**辨析｜易错点：** 新手常把「数据构造」等同于「下载+清洗」。实际上预训练时代的数据工程还要处理：**混合数据源的批次均衡**（防止某一批全是同质文本导致梯度震荡）、**重复数据的跨批次追踪**（同一网页被多次清洗进不同批次）、以及**数据污染的持续监控**（训练后评估集里出现训练文本的「复读现象」）。数据管线不是一次性脚本，而是与模型共同演化的常设工程。

## 5 小结

- 预训练数据的根基是 **Common Crawl 等原始网页语料**，量级在 PB 级、噪声极高。
- 四道核心工序：**语言识别 → 启发式过滤 → 分类器质量打分 → 模糊去重**（MinHash + 后缀数组）。
- **去重**防止「背题」，质量**过采样**让模型从高密度语料中受益——LLaMA 对 Wikipedia、Books 大幅过采样。
- **数据配比** $p_i \propto w_i \cdot |\text{源}_i|$ 是在多样性（网页）与关键性（数学/代码/百科）之间权衡的工程决策。
- 数据构造与分词、训练稳定性紧密耦合，是一条与模型共同演化的常设管线。
