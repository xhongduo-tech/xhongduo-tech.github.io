## 为什么从检查点开始

《训练稳定性与损失尖峰》里我们提到：尖峰事故的恢复依赖检查点。但检查点本身是预训练工程里一个**与「成本」正面交锋**的组件——一个 70B 模型的完整状态（权重 + 优化器状态 + 梯度 + 随机数状态）可能超过 1TB，全量保存一次就要几分钟、占满多个节点带宽。<span class="marginnote">训练 100 天、每天存一次检查点，光存储开销就可能是数 TB 量级；而一次硬件故障（GPU 掉线、NIC 断连）若没有近期检查点，代价是几十小时算力归零。检查点策略 = 在「存得勤」与「存得起」之间找平衡。</span>

**检查点（checkpoint）**：训练过程中周期性保存的「训练状态快照」，包含模型权重、优化器状态、学习率调度器位置、随机数生成器状态等，用于故障恢复与断点续训。**断点续训（resume training）**：从某个检查点加载状态、继续训练，而不必从头开始。

## 1 一个检查点里到底有什么

新手常以为检查点 = 模型权重。实际上完整恢复训练需要四类状态：

**模型权重**：所有参数张量（FP16/BF16 副本 + FP32 主权重）。一个 $N$ 参数的模型约 $2N$（半精度）+ $4N$（主权重）字节。
- **优化器状态**：Adam 的 $m_t, v_t$——**每参数 8 字节**，是最大的一块（见《高效训练与并行》的显存表）。没有它，恢复后动量历史清零，训练效果退化。
- **调度器位置**：当前训练步数、学习率（Cosine 调度依赖步数，位置错了后续衰减全偏）。
- **随机数状态**：数据加载的采样顺序（shuffle 的 RNG）、dropout 的 RNG。**不保存 RNG 会破坏数据顺序的确定性**，导致恢复后的样本分布与原始计划不一致。

<span class="marginnote">Megatron-LM 明确指出：真正的「训练状态」是上述四者的完整集合。只存权重、不存优化器状态的「轻量检查点」只用于模型发布，不能用于续训。</span>

## 2 保存频率：每 N 步 vs. 按时间

保存频率是第一个工程权衡。常见策略：

**固定步数间隔**（如每 100 步）：Megatron 建议每 100 步存一次——这是「尖峰事故恢复成本」与「存储开销」的平衡点。<span class="marginnote">为什么是 100 而不是 10000？《训练稳定性》里尖峰可能在任意步数出现，检查点太稀疏意味着回滚损失大；太频繁则存储与通信开销吞掉训练收益。100 步是实践中的常见折中。</span>
**异步保存**：把「保存」操作卸载到独立进程/线程，**不阻塞训练**——否则每 100 步的训练会被保存 I/O 打断数秒。
- **滚动保留**：保留最近 K 个检查点（如 K=3），覆盖更旧的——磁盘有限，且「最近的」通常最有价值。
- **保存中同步点**：分布式训练里保存必须是**全局一致的**——所有 rank 保存的是同一训练步的状态，否则恢复后各卡状态错乱。

## 3 恢复的两种场景与坑

### 场景一：正常断点续训（如显存 OOM 后重启）

加载四类状态 → 从第 $s$ 步继续。此场景最隐蔽的坑是**状态不一致**：

- **参数与优化器状态不匹配**：若权重存了 FP32 主权重而优化器只存了半精度，恢复后数值漂移。
- **数据顺序错位**：RNG 状态没恢复，shuffle 顺序变掉，同一批数据被重复喂——**这等价于悄悄改了数据分布**（《预训练数据构造》里的随机性工程因此至关重要）。

### 场景二：硬件故障恢复（含 loss spike 回滚）

故障恢复额外要处理**分布式拓扑变化**：某几张 GPU 掉线后，并行组（TP/PP/DP 配置）可能变化。恢复时要么等待原拓扑、要么用**弹性训练**（dynamic re-sharding）把检查点重新分片到新拓扑。PyTorch 的 DCP（Distributed Checkpoint）把「每个 rank 存它拥有的分片」改为「按张量全局命名 + 惰性加载」，天然支持弹性续训。<span class="marginnote">Megatron 的持久化策略里还有一层：检查点分片按「张量名 + rank」保存，配合元数据 JSON，恢复时按新拓扑重建分片映射——这就是弹性恢复的原理。</span>

**辨析｜易错点：** 回滚到尖峰前的检查点后，**不能直接用原始学习率重放**——这正是《训练稳定性》里的恢复流程：加载检查点 + 调低学习率 + 更保守的梯度裁剪，从「出事前一步」谨慎地重新推进。若只是「原样续训」，尖峰大概率重演。

## 4 检查点与训练曲线：保存本身就是工具

检查点不只是「灾难保险」，它还被用来做训练期的**决策与诊断**：

- **回退决策**：训练中定期评估中间检查点（在《评估基准》的任务子集上），发现 loss 反弹或能力不升时，回滚到表现更好的历史版本——这本质上是「在检查点尺度上做早停/选择」。
- **梯度检查（gradient checkpoint）的区分**：注意「activation checkpointing」（《高效训练与并行》里重算激活省显存）与「训练状态 checkpoint」是**两个不同的东西**——前者是显存优化、后者是状态快照，中文都叫「检查点」但别混淆。
- **中间产物发布**：很多团队用「训练中期的检查点」做小规模评估、消融对比，甚至提前给对齐团队用——一个训练 run 的检查点序列就是一个完整的「模型时间线」。

## 5 小结

- 完整检查点 = **权重 + 优化器状态 + 调度器位置 + RNG 状态**，缺一不可；只存权重只能发布、不能续训。
- 保存频率在「回滚损失」与「存储/通信开销」间权衡：实践常用**每百步 + 异步保存 + 滚动保留 K 份**。
- 恢复的两类场景：**正常续训**（防状态不一致、RNG 错位）与**故障恢复**（弹性拓扑 + 尖峰回滚配低学习率）。
- 检查点序列本身就是**训练期的决策工具**：定期评估、回滚选择、中间产物发布。
- 检查点工程与《训练稳定性》《高效训练与并行》深度耦合，是漫长预训练的「安全网与方向盘」。
