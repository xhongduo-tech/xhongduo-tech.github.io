## 为什么从并行开始

前面几节我们讨论了「喂什么数据、用什么结构」，但一个 70B 参数模型单单存参数就要约 140GB（FP16），远超单张 GPU 的显存。把训练铺开在数百上千张卡上，靠的是一整套并行策略。<span class="marginnote">并行不只是「快」的问题——它是<strong>可行性</strong>问题：单卡装不下的模型，只能靠并行拆开。理解并行，才能理解为什么预训练的成本曲线长这样。</span>

**高效训练与并行（efficient training & parallelism）**：把一个大模型的训练拆解到多张 GPU 上的三种互补技术——**数据并行**（DP）、**张量并行**（TP）、**流水线并行**（PP）——以及它们组合出的 3D 并行。核心矛盾是：怎么在「每张卡放得下」与「卡间通信别成为瓶颈」之间取平衡。

## 1 三种并行的基本盘

### 数据并行（Data Parallelism, DP）

每张卡都持有一份完整的模型副本，各吃一批不同的数据，算完梯度后用**梯度同步**（all-reduce）求平均，再各自更新。直觉：N 张卡 = 把 batch size 放大 N 倍。

$$ \theta \leftarrow \theta - \eta \cdot \frac{1}{N}\sum_{i=1}^{N} g_i, \qquad g_i = \nabla_\theta \mathcal{L}(\theta; \mathcal{B}_i) $$

- 优点：实现简单、扩展性好，适合模型能装进单卡的情况。
- 缺点：**每张卡都要存全量模型**，模型一大于单卡显存就失效；且每步通信量随参数规模线性增长。

### 张量并行（Tensor Parallelism, TP）

**按层内把矩阵切开**。把一个大矩阵乘法拆成两块卡各算一半，再拼接结果。Megatron-LM 对 MLP 与注意力做了对称切分：让每一层的前向只产生一次 all-reduce。<span class="marginnote">Megatron 的关键工程细节：把「列切分」与「行切分」交错（f 与 f^-1 的拼接），让每层只通信一次而不是多次——通信次数从 O(层数) 压到 O(1)。</span>

优点：解决「单层放不下」的问题，且对序列长度不敏感。
- 缺点：**通信极其密集**——每个 token 每个子层都要同步，TP 只在单机内部（如 8 张卡通过 NVLink）使用。

### 流水线并行（Pipeline Parallelism, PP)

**按层纵向切段**，把模型分成若干「阶段」（stage），每个阶段放在一张（或一组）卡上，数据像流水线一样在阶段间流动。经典实现是 **1F1B（one forward, one backward）调度**：交替执行前向与反向，让每个阶段的空闲气泡（bubble）最小化。

- 优点：卡间通信量小（只传中间激活，每 batch 一次），跨机器扩展友好。
- 缺点：存在**气泡空洞**（部分卡在等前面阶段算完）——流水线越深、微批越多，气泡占比越小。

## 2 3D 并行：组合的艺术

真实的大模型训练几乎总是三种并行的组合（如 Megatron-Turing、LLaMA、GPT-4）：

- **张量并行**在同一机内跨 8 卡（NVLink 高速互联），解决单层装不下；
- **流水线并行**在机间跨阶段切层，把通信降到每 batch 一次；
- **数据并行**在最外层复制整条流水线，吃满所有数据并行度。

**辨析｜易错点：** 常见误区是「并行度越多越好」。实际上三种并行的**通信成本与收益完全不同**：TP 通信最贵（每子层都要同步）、PP 次之（每 micro-batch 同步一次）、DP 最便宜（每步一次）。所以经验法则是：**TP 只在机内用、PP 跨节点用、DP 做整体扩容**——把「贵的通信」限制在「快的互联」内部。

## 3 并行之外的提速三件套

并行解决「怎么铺开」，还有三个组件解决「单步多快」：

- **混合精度训练（Mixed Precision）**：用 FP16/BF16 做前向与反向、FP32 存权重与梯度副本。**BF16 因动态范围大，成为大模型默认**——它避免了 FP16 在小数值处溢出、大数值处下溢的问题。代价是数值精度损失，需要配合下面两条。
- **梯度累积（Gradient Accumulation）**：显存放不下大 batch 时，分多个 micro-batch 各算梯度、累加后再更新——**等效于增大 batch，且与流水线并行的微批天然配合**。<span class="marginnote">梯度累积的数学本质：$\sum$ 的偏导 = 各分量偏导之和，所以「分批算梯度再相加」与「一次性算」在数学上等价——只要权重在累积期间不更新。这也是它与 DP 的最本质区别：DP 跨卡同步，累积在单卡内串行。</span>
**ZeRO / 优化器状态切分**：大模型的显存大头其实是**优化器状态**（Adam 要存 m、v，加上主权重，是参数量的 16 倍）。ZeRO 把优化器状态、梯度、参数分别切分到各卡，用通信换显存，让「单卡装不下」变成「单卡也装得下但慢一点」。

## 4 一张图看显存去哪了

一个 $N$ 参数的模型在混合精度下，显存的主要去向（粗略）：

| 项目 | 大小（每参数） | 说明 |
| --- | --- | --- |
| 主权重（FP32） | 4 字节 | Adam 更新的精度来源 |
| 优化器状态 m、v | 8 字节 | Adam 的一阶/二阶矩 |
| 梯度（FP16/FP32） | 2–4 字节 | 反向传播结果 |
| 激活（中间结果） | 依序列长度 | 前向时保留，反向要用 |
| 参数副本（FP16） | 2 字节 | 前向/反向使用 |

**合计：仅权重+优化器状态+梯度就约 16N 字节**，一个 70B 模型 ≈ 1.1 TB——这就是必须并行、必须 ZeRO 的根本原因。<span class="marginnote">激活显存随序列长度线性增长（还有 TP 带来的重复），所以长上下文训练必须配合激活重计算（activation checkpointing）：反向时重新算激活、不存全量，用 30% 的额外计算换约 60% 的显存。</span>

## 5 小结

- **数据并行**复制模型、同步梯度，等价于放大 batch；**张量并行**切矩阵、层内并行；**流水线并行**切层、跨机流水。
- 3D 并行按通信成本分层：**TP 机内、PP 机间、DP 扩容**——贵的通信只放在快的互联上。
- **混合精度（BF16 优先）+ 梯度累积 + ZeRO** 是单步提速的三件套，共同解决显存与数值稳定性。
- 显存大头是**优化器状态（Adam 的 16 倍开销）**，这是 ZeRO 与各种显存优化的目标。
- 并行与通信的分工是预训练工程的「物理层」，直接决定训练曲线与成本。
