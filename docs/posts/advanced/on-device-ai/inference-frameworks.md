## 为什么从推理框架开始

模型再高效、硬件再强大，中间还差一层「翻译官」：把 PyTorch 训练出来的模型，翻译成 NPU 上真正能跑的算子序列。这层翻译官就是**推理框架（inference framework）**。没有它，模型只是权重与结构的一堆描述；有了它，模型才能变成手机上每一毫秒的推理。克努斯提醒「过早优化是万恶之源」，但端侧推理恰恰相反——**算力与内存都抠到极致，这里的优化必须提前做、系统化做**。<span class="marginnote">推理框架与第四级《AI 基础设施》的推理引擎、第三级《大模型原理》的部署章节同源，区别只在目标硬件：这里的一切都围绕「手机这颗小芯片」展开。</span>

## 1 推理栈的四层分工

一个端侧推理框架要打通四层，缺一层模型都跑不起来：

- **模型格式层**：把 PyTorch/ONNX 模型导入、解析为中间表示（IR），同时做格式转换。
- **图优化层**：在整张计算图上做变换——算子融合、常量折叠、内存复用规划。
- **算子实现层**：为每个算子准备 CPU/NPU/GPU 后端实现，含量化与稀疏内核。
- **硬件后端层**：调用具体的硬件驱动（NPU 驱动、GPU 框架），管理内存分配与调度。

这四层环环相扣。端侧框架的常见形态：苹果 **Core ML**（Swift 生态、自动做内存规划）、**ONNX Runtime Mobile**（跨平台、算子可插拔）、Meta **ExecuTorch**（PyTorch 直通）、**MLC-LLM** 与 **llama.cpp**（开源社区、LLM 专用）、苹果 **MLX**（Apple Silicon 上的类 NumPy 推理栈）。<span class="marginnote">《NPU/DSP 硬件》里的「算子支持矩阵」，正是框架「算子实现层 + 硬件后端层」要填的坑：查矩阵、做降级、选实现，是框架工程师的日常。</span>

## 2 算子融合：把碎片焊成整块

**端侧推理最大的性能敌人是「碎片化」**：模型里几十上百个算子，如果每个算子都「写一次中间张量、再读一次」，内存带宽就会被无谓消耗。**算子融合（operator fusion）**把相邻的小算子合并成一个内核：

- **MatMul + BiasAdd + ReLU** → 单个融合内核，中间结果留在寄存器/片上缓存，不落地。
- **LayerNorm + 量化** → 融合，减少一次量化来回。
- **注意力内部融合**：QKV 投影、RoPE、缩放、Softmax 一次流水算完。

融合的效果往往是数量级的：MobileNet 上算子融合可以让时延降到未融合的一半以下。<span class="marginnote">这也解释了克努斯那句话的适用边界：端侧推理里，融合是「必然要做的优化」而不是「过早的优化」——因为内存带宽是硬约束，不融合就是直接把能效扔掉。</span>

## 3 内存规划与 KV cache 管理

端侧内存小，推理框架必须**事前规划**每一块缓冲：

- **静态内存池**：图优化阶段就规划好所有中间张量的生命周期，把可复用的内存重叠复用，峰值内存降到最低。
- **KV cache 管理**：自回归生成时，框架按上下文长度动态分配注意力缓存；长上下文下 KV cache 常占内存大头，需要分页管理（page-based）与量化（FP8 KV）来救场。
- **权重加载**：权重按需从闪存/内存流式加载，MMU 式分片，避免一次性整装。

这些与《端侧大模型部署》的内存工程互为表里——框架做的是「运行时怎么省」，部署做的是「整体预算怎么算」。

## 4 公式解析：带宽决定单 token 时延

**端侧自回归生成是「带宽受限」的，框架优化的目标函数由此而来。** 生成每个 token 都要把全部权重读一遍：

$$
t_{\text{token}} \approx \frac{\text{权重字节数}}{B_{\text{有效}}}
$$

拆开来看：

- **权重字节数**：如 3.8B 模型 INT4 约 1.8 GB；INT8 则约 3.6 GB。
- **$B_{\text{有效}}$**：NPU 实际能吃到权重的有效带宽，远小于芯片标称的 DRAM 带宽（受访存模式、缓存命中率影响）。
- **$t_{\text{token}}$**：每生成一个 token 的最小耗时——这就是生成速率 $r = 1 / t_{\text{token}}$ 的上限。

代入粗略值：若有效带宽 25 GB/s，则 1.8 GB 权重每 token 要 $1.8 / 25 \approx 72$ 毫秒，约合 14 token/s——与 Phi-3-mini 在 iPhone 上的实测速率同量级。<span class="marginnote">框架的每一项优化（融合省带宽、量化减字节、KV 复用降开销）最终都汇入这一个公式。它把「跑多快」从玄学变成了可算的工程量。</span>

## 5 小结

- **四层分工**：模型格式 → 图优化 → 算子实现 → 硬件后端，环环相扣。
- **框架生态**：Core ML、ONNX Runtime Mobile、ExecuTorch、MLC-LLM、llama.cpp、MLX 各占山头。
- **算子融合**：把 MatMul+Bias+ReLU 等焊成单内核，省中间张量落地，性能常是数量级提升。
- **内存规划**：静态内存池 + KV cache 分页/量化管理，把峰值内存压到最低。
- **带宽公式**：$t_{\text{token}} \approx \text{权重字节}/B_{\text{有效}}$，端侧生成速率由带宽与权重大小共同决定。

在下一节，我们将把这些技术全部装进一台手机——**端侧大模型部署**，算算手机跑 7B 模型的内存与功耗总账。
