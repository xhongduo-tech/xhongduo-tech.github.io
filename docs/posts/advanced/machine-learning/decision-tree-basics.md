## 为什么从决策树开始

前三章我们学了两类模型：线性模型用一组系数把样本投影到一维再切一刀，对数几率回归再套一个 sigmoid；它们有一个共同点——**用一个全局的、光滑的决策边界**把整个特征空间一分为二。而本章的**决策树（decision tree）**是完全不同的思路：它不做任何光滑假设，而是用一连串「特征是否满足某个条件」的判断题，把样本空间一层层切碎，像答问卷一样走到最终的类标记。

决策树是人类可读性最好的模型——医学里医生的诊断流程图、银行的信贷审批表、程序里层层嵌套的 if-else，本质上都是决策树。理解「决策树是怎么长出来的」，是后面第6章集成学习（随机森林、GBDT 都是树的集成）的必经之路，也是整个机器学习里「结构主义」路线的代表。

## 1 决策树的结构一棵决策树由**节点（node）**和**有向边**组成，三种节点各司其职：- **根节点（root node）**：包含全部训练样本，是整棵树的人口。- **内部节点（internal node）**：对应一个属性测试，每个内部节点把到达它的样本按测试结果分到不同的子分支。
- **叶节点（leaf node）**：对应一个决策结果（类标记或回归值），样本流到这里就得到答案。<span class="marginnote">用第1章《基本术语》的语言：内部节点是「在某个属性上做的测试」，叶节点是「结论」；从根到叶的一条路径，就是一条 if-then 判定规则，整棵树等价于一组互不重叠、覆盖全空间的规则集合。</span>

例如判断一个西瓜是否是好瓜：根节点问「色泽？」，若「青绿」走左分支，再问「根蒂？」，若「蜷缩」则到达叶节点「好瓜」。这串问答就是一棵树。<span class="marginnote">决策树的「可解释性」正来自这种问答结构：任何一条预测都可以回溯成「为什么」——沿着根到叶的路径读出全部判定条件，无需黑箱。</span>

## 2 递归生成：分而治之决策树的生成是一个**自顶向下的递归分治过程**。用「判定西瓜好坏」的直觉说：1. 一开始，全部样本都在根节点；2. 选一个属性（如「色泽」）来测试，按属性取值把样本分到若干分支；
3. 对每个分支，若其中的样本已属于同一类，或已无属性可选，则该分支成为叶节点；否则**递归地重复第2步**，在更小的样本子集上再选属性、再分叉。

这个过程写成伪代码，就是教科书里的**TreeGeneration** 算法：

```text
输入：训练集 D = {(x_1, y_1), ..., (x_m, y_m)}；属性集 A = {a_1, ..., a_d}
过程：TreeGenerate(D, A)
1:  生成结点 node
2:  if D 中样本全属于同一类别 C then
3:      将 node 标记为 C 类叶节点；return
4:  end if
5:  if A = ∅ 或 D 中样本在 A 上取值相同 then
6:      将 node 标记为叶节点，类别标记为 D 中样本数最多的类；return
7:  end if
8:  从 A 中选择最优划分属性 a*
9:  for a* 的每一个值 a*_v do
10:     为 node 生成一个分支；令 D_v 为 D 中在 a* 上取值为 a*_v 的样本子集
11:     if D_v 为空 then
12:         将分支结点标记为叶节点，类别标记为 D 中样本最多的类；return
13:     else
14:         以 TreeGenerate(D_v, A \ {a*}) 为分支结点
15:     end if
16:  end for
输出：以 node 为根结点的一棵决策树
```

注意两个**边界情况**：一是样本已同类或属性已用完，直接停止；二是某个分支没有样本落进来，此时该分支不能留空，需用一个「占位叶节点」标记为**父节点样本中最多的类**——这就是后剪枝里常说的「把样本比例当作概率的朴素估计」。

## 3 三个关键问题递归框架本身很简单，决策树研究的全部复杂性都集中在一个问题上：**每一步选哪个属性来划分？** 它衍生出三个环环相扣的问题：- **划分选择**：如何量化「这个属性划分后，子节点越来越『纯』」？这引出信息增益、增益率、基尼指数——是本章的重头戏，下一节专门展开。- **剪枝处理**：树分得太细会过拟合（把训练集背下来），如何适当「截枝」换取泛化？有预剪枝与后剪枝两种策略。
**连续值与缺失值处理**：决策树天然处理离散枚举属性，但真实数据常是连续的，且常缺字段，需要专门的处理手段。

**辨析｜易错点：** 决策树**不要求特征数值化**，也不要求数据「可分」——它是纯符号式的划分。这与线性模型形成鲜明对比：线性模型必须把特征映射为数值并假设线性可分，决策树只要划分后子集纯度提升就继续长。换句话说，**线性模型拟合一个光滑超平面，决策树拼出一块块互不相交的「决策区域」**。

## 4 核心对比表：决策树 vs 线性模型| 维度 | 决策树 | 线性模型（线性回归 / 对数几率回归） || --- | --- | --- || 决策边界 | 分段常量，轴对齐的矩形块 | 全局光滑超平面 || 特征要求 | 离散、连续均可，支持符号特征 | 必须是数值，常需标准化 |
| 可解释性 | 极高，可读出 if-then 规则 | 中，系数大小可解读但整体黑箱 |
| 对特征尺度 | 不敏感（按值比较） | 敏感（梯度优化依赖尺度） |
| 非线性拟合 | 天然支持（无需特征工程） | 需人工构造非线性特征或核技巧 |
| 过拟合风险 | 高，易长成完整背记训练集 | 相对低，但欠拟合风险高 |

这张表是理解「为什么第4章先讲树、第6章再讲集成」的钥匙：**树的单个模型方差大（换个数据子集树形就变）、偏差小；线性模型偏差大、方差小。** 把许多棵树平均起来（Bagging、随机森林），恰好用「方差抵消」补上了单棵树的短板——这正是第8章集成学习的地基。<span class="marginnote">「偏差小、方差大」的判断在集成学习里会被精确量化（误差-分歧分解），那里你会看到为什么「不稳定」反而成了可用的资产。</span>


决策树的「可解释」不只是一种感觉，它可以用几个可计算的性质来刻画：- **深度（depth）**：从根到叶的最大路径长——越浅越易被人读完；- **叶子数（leaves）**：规则总数——每片叶就是一条 if-then；- **平均路径长**：随机样本从根走到叶要问几个问题——度量「决策成本」；- **规则置信度**：叶节点里多数类占比——每条规则「多可信」。工程上常用「规则提炼（rule extraction）」：把训练好的树（甚至随机森林/GBDT）转成规则清单，按置信度排序，交给业务人员审计——这是「可解释 AI」的经典落地。**思考题**：1. 为什么树的「深度」比「叶子数」更能反映人读起来的难度？2. 决策树与「if-else 规则集」在表达上等价，为什么树仍值得学？（提示：共享前缀的组织效率）

## 知识速查：决策树基本流程

**本节关键词**
- 决策树
- 根/内部/叶节点
- 递归分治
- 属性测试
- if-then 规则
- 互斥完备
- 占位叶节点
- 可解释性

**三条常见误区**
1. 把「每个样本全对」当成功——树会过拟合；
2. 忽略「分支无样本」的占位叶节点处理；
3. 把决策树与线性模型的边界混为一谈——树是分段常量。

**核心结论**
1. 决策树是递归分治：选属性、分样本、递归至纯；
2. 分支无样本时用父节点多数类占位；
3. 根到叶路径即一条 if-then 规则；
4. 树偏差小方差大，可解释性强。

**与全书/后续的连接**
- 第4章划分选择决定树怎么长；
- 第8章集成学习把树当基学习器；
- 第15章规则学习把树路径提炼为规则。

**常见面试题**
1. 问：决策树与线性模型的决策边界有何不同？ 答：树是轴对齐矩形块，线性模型是全局超平面。
2. 问：为什么树容易过拟合？ 答：结构自由、可无限细分，能把训练集整个背下来。

**一句话记忆**
决策树 = 用一串 if-else 把样本空间切块，根到叶一条路径即一条规则。

## 5 小结- **决策树**由根节点、内部节点、叶节点组成，根到叶的一条路径即一条 if-then 规则。- 生成算法是**递归分治**：不断选最优属性划分样本，同类样本或属性耗尽则停止。- 分支无样本时，用**父节点样本最多的类**作为占位叶节点。- 三个核心问题：**划分选择、剪枝处理、连续值与缺失值处理**，共同决定树的最终形态。
- 与线性模型对比：树是**分段常量的符号模型**，偏差小方差大，可解释性极强。
