## 为什么从 LightGBM 开始

XGBoost 很快，但它的「快」有一个隐藏代价：**预排序 + 逐特征扫切分点**在特征多、样本大时仍然吃内存、耗时间。2017 年微软开源的 **LightGBM（Light Gradient Boosting Machine）**专为「更大、更快」而生：它用三大招——**直方图算法、GOSS 采样、EFB 特征捆绑**——把训练速度再提升一个量级，内存占用大幅下降，成为大数据量 + 高维特征场景下与 XGBoost 并列的工业双雄。

LightGBM 的哲学是「**用近似换速度，而且近似得聪明**」：把连续特征**分箱**成直方图（丢掉精确切分点）、按梯度**采样**（丢掉低信息样本）、把互斥特征**捆绑**（减少特征数）——每一步都在「精度微损」与「速度大增」之间精准取舍。<span class="marginnote">「LightGBM 的轻」体现在内存：XGBoost 预排序要存「每个特征的排序索引」，LightGBM 只存「分箱后的直方图」——内存可以省到原来的几分之一，训练速度提升 5–10 倍。它特别适合「样本千万级、特征上千」的工业表格数据（推荐、风控的典型规模）。</span>

## 1 直方图算法：把「精确切分」变成「分箱切分」XGBoost 找切分点要遍历「特征的全部排序值」；**LightGBM 的直方图算法**先对每个特征**分箱（binning）**——把连续值离散成 $B$ 个桶（如 255 个），每个桶累计「一阶导和 $G$、二阶导和 $H$」：
1. **建直方图**：一次扫描，把每个特征的值分进桶，桶内累计 $G, H$；
2. **找切分**：在桶之间找最优切分——只需扫 $B$ 个桶，而非全部排序值；
3. **分裂**：按直方图增益选切分点，分裂后子节点的直方图由**父直方图做差**快速得到（直方图相减技巧）。

**代价与收益**：分箱丢掉了「精确切分点」（最优切分可能在桶内），但实验表明精度损失极小、速度与内存收益巨大——**「近似到 256 个桶通常够用」**。<span class="marginnote">「直方图相减」是 LightGBM 的细节优化：子节点的直方图 = 父直方图 − 兄弟直方图（一个 O(B) 减法而非重扫一遍），这让分裂的代价从 O(样本数) 降到 O(桶数)。这个「用已算好的量算新量」的思路，和 HMM 前向算法、动态规划是同一类「避免重复计算」的哲学。</span>

## 2 三种生长策略与两种采样**Level-wise vs Leaf-wise**：
- **XGBoost 按层生长（level-wise）**：每层所有节点一起分裂——均衡但浪费（有些节点增益小也长）；
- **LightGBM 按叶生长（leaf-wise）**：每次只分裂**增益最大的叶子**——同样的树数下误差更低、树更「偏科」，但**可能过深**，需限制最大深度/叶子数。

**GOSS（Gradient-based One-Side Sampling）**：样本不是平等重要——**梯度大的样本（拟合差）信息量大**。GOSS 保留全部「大梯度」样本，对小梯度样本**随机采样**一部分，再按比例放大它们的权重——用「少而精」的样本子集算分裂，速度大增而精度几乎不降。<span class="marginnote">「GOSS 保留大梯度样本」与 Boosting 的「关注前一轮错误」精神一脉相承：梯度大 = 当前模型还没学会 = 最有信息量。它把「样本重加权」的 Boosting 思想用在「样本采样」上，是「按重要性采样」在 GBDT 的落地——与第8章「多样性 + 准确性」的平衡同构。</span>

## 3 公式解析：直方图分裂的增益LightGBM 在直方图上的分裂增益（沿用 XGBoost 的二阶公式，只是「样本的 $G,H$」换成「桶的 $G,H$」）：
$$\text{Gain} = \frac{1}{2}\left[\frac{(\sum_{L}G)^2}{\sum_L H + \lambda} + \frac{(\sum_{R}G)^2}{\sum_R H + \lambda} - \frac{(\sum G)^2}{\sum H + \lambda}\right]$$

- **第一步，看聚合粒度**：$\sum_L G$ 是「左桶集合的一阶导和」——桶代替了样本，增益在**桶**上算；
- **第二步，看复杂度**：每特征只需扫 $B$ 个桶（而非 $N$ 个样本），总分裂代价从 $O(\text{特征数} \times N)$ 降到 $O(\text{特征数} \times B)$；
- **第三步，看与 XGBoost 的关系**：公式与 XGBoost 完全相同——**LightGBM 没改「分裂准则」，只改了「在什么粒度上算」**（桶 vs 样本）；
- **第四步，看精度**：桶边界内的最优切分点被略过，但增益差异通常微小——「近似得聪明」的含义。

**直觉一句话**：LightGBM 用「把样本聚成桶」换速度——分裂准则不变，只是「先分箱再算」，从而在几乎不损失精度的情况下把速度翻量级。

## 4 EFB：把互斥特征捆在一起**EFB（Exclusive Feature Bundling）**处理「特征太多」：很多特征**几乎互斥**（同时非零的样本极少——如独热编码的类别特征），把它们**捆绑成一个特征**，分裂时在这个「合成特征」上找切分，等效于「一次处理多个原特征」。
- 互斥特征合并后，**特征数大幅减少**，建直方图的扫描次数下降；
- 这特别适合「高维稀疏」数据（独热编码、ID 类特征）——**稀疏是 EFB 的燃料**。<span class="marginnote">「EFB 专治独热编码」：比如 1000 个类别的特征独热成 1000 列稀疏列，几乎互斥（一个样本只有一个 1），EFB 把它们合成少数「捆绑特征」，直方图扫描从 1000 次降到几次——这是 LightGBM 在高维稀疏场景碾压 XGBoost 的关键。它与「特征哈希」「分组」有相似动机，但更自动。</span>

## 5 核心对比表：XGBoost vs LightGBM| 维度 | XGBoost | LightGBM || --- | --- | --- |
| 切分粒度 | 预排序精确切分 | **直方图分箱** |
| 生长方式 | 按层（level-wise） | **按叶（leaf-wise）** |
| 采样 | 列采样/行采样 | **GOSS（按梯度）** |
| 高维稀疏特征 | 较慢 | **EFB 捆绑、快** |
| 内存占用 | 较高 | **低** |
| 训练速度 | 快 | **更快（5–10×）** |
| 精度 | 高 | 相当（略快略偏） |

**辨析｜易错点：** Leaf-wise 在「样本少」时**容易过拟合**（树长太深）——LightGBM 官方也建议小样本时限制最大深度或用 XGBoost。「快」不等于「必然更好」——**数据规模决定了选谁**：中小数据两者都可，超大数据/超高维稀疏 → LightGBM 优势明显。<span class="marginnote">「选 XGBoost 还是 LightGBM」是表格竞赛的经典问题：结论通常是「数据大 → LightGBM（快、省内存），数据小或追求精确可解释 → XGBoost 或 GBDT」。下一节我们给出系统的选型指南——「三大框架对比与实战选型」。</span>

## 知识速查：LightGBM

**本节关键词**
- LightGBM
- 直方图
- leaf-wise
- GOSS
- EFB
- 分箱
- 高维稀疏
- 内存

**三条常见误区**
1. 把 LightGBM 当 XGBoost 换皮——分箱/采样/捆绑是三大招；
2. 忽略 leaf-wise 在小样本下易过拟合；
3. 以为直方图精度必然差——256 桶通常够用。

**核心结论**
1. LightGBM 用直方图分箱加速分裂；
2. leaf-wise 生长精度高但易过深；
3. GOSS 保留大梯度样本采样；
4. EFB 捆绑互斥特征治高维稀疏。

**与全书/后续的连接**
- 专题一 GBDT/XGBoost 对照；
- 第8章采样思想；
- 工业大数据表格场景。

**常见面试题**
1. 问：直方图算法省在哪？ 答：分裂代价从 O(样本) 降到 O(桶数)，内存大减。
2. 问：为什么 leaf-wise 小样本易过拟合？ 答：只分裂增益最大的叶，树会长得太深。

**一句话记忆**
LightGBM = 直方图分箱 + GOSS 采样 + EFB 特征捆绑，把速度翻量级。

## 6 小结- **LightGBM** 用「直方图 + 采样 + 特征捆绑」三招，把 GBDT 训练速度提升量级、内存大幅下降。- **直方图算法**：分箱建直方图，分裂代价从 O(N) 降到 O(桶数)；直方图相减加快分裂。
- **Leaf-wise** 按最大增益叶生长，误差更低但可能过深；**GOSS** 保留大梯度样本、采样小梯度样本。
- **EFB** 把互斥特征捆绑，专治高维稀疏（独热编码）。
- 对比 XGBoost：速度与内存占优、精度相当；小数据时 Leaf-wise 易过拟合需限深。
