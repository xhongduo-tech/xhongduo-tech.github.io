## 为什么从三大框架对比开始

前三节把 GBDT、XGBoost、LightGBM 逐一拆解——它们其实是**同一个算法家族的三代**：原理最朴素的 GBDT、工程最完善的 XGBoost、速度最极端的 LightGBM。这一节把它们摆在一起：**它们究竟差在哪？什么场景该选谁？调参该怎么调？** 这是「从原理到实战」的最后一公里。

选型不是「谁最强用谁」，而是「**数据与目标决定工具**」。样本量、特征类型（稠密/稀疏）、训练预算、精度要求、可解释性需求，每个维度都指向不同的选择。这一节给出一张系统的「选型地图」，并总结 GBDT 家族的通用调参顺序。<span class="marginnote">「三大框架是三代同堂」这个认知很重要：它们共享同一棵「梯度提升树」的知识树（损失函数、负梯度、分裂增益），差异集中在「工程近似与系统优化」。所以「理解原理」可以一次学会三个；「选型」则看工程参数。这也是为什么前三节反复强调「分裂准则没变，变的粒度」。</span>

## 1 一张表看透三大框架| 维度 | GBDT（经典实现） | XGBoost | LightGBM || --- | --- | --- | --- |
| 切分粒度 | 精确（排序） | 精确（预排序） | **分箱（直方图）** |
| 二阶导数 | 否（一阶） | **是** | 是 |
| 显式正则化 | 弱（靠学习率） | **是（$\gamma,\lambda$）** | 是 |
| 生长方式 | 按层 | 按层 | **按叶** |
| 采样技巧 | 无/子采样 | 列/行采样 | **GOSS + EFB** |
| 训练速度 | 慢 | 快 | **最快** |
| 内存 | 高 | 中高 | **低** |
| 小样本表现 | 稳 | 稳 | **易过拟合（需限深）** |
| 高维稀疏特征 | 慢 | 较慢 | **快（EFB）** |
| 可解释性 | 高 | 高 | 高 |

**核心结论**：三者的**算法内核一致**（梯度提升树），差异全在「工程近似程度」——从「最精确但慢」到「最近似但快」，是一条「精度-速度」的连续谱。<span class="marginnote">「从 GBDT 到 LightGBM 是精度换速度的连续谱」是选型的底层逻辑：没有「免费」的提升，XGBoost 用二阶导+正则换精度，LightGBM 用分箱+采样换速度。理解这个「交换」，就不会迷信「最新的一定最好」——<strong>对的数据规模下，「老」的 GBDT 可能已经够好且更可解释</strong>。</span>

## 2 选型决策树：按场景对号入座**决策路径（从数据特征出发）**：
1. **样本量小（< 1 万）** → 三者都行；LightGBM 注意限深防过拟合，XGBoost/GBDT 更稳；
2. **样本量大（百万级）** → **LightGBM**（速度/内存优势明显）；
3. **特征高维稀疏（独热、ID 特征）** → **LightGBM**（EFB 专治稀疏）；
4. **特征稠密、样本中等** → XGBoost（精确切分，精度略优）；
5. **追求极简/可解释** → GBDT（sklearn 的 `GradientBoostingClassifier`）或三者选一，特征重要性都可读；
6. **有 GPU / 分布式集群** → XGBoost 与 LightGBM 都支持，选你更熟的。

**一条经验法则**：**「数据大、特征稀、预算紧」→ LightGBM；「数据中、求精确、要稳定」→ XGBoost；「教学、可解释、小规模」→ GBDT。**<span class="marginnote">「预算紧」很常被忽略：训练时间是成本，内存是成本，跨团队的可维护性也是成本。选型不只是「谁精度高」，而是「在这个数据规模、硬件、工期下，谁最划算」——这正呼应第2章「没有免费午餐」，也预告了工程专题三「AutoML 自动选型」。</span>

## 3 调参的通用顺序GBDT 家族的超参数虽多，但调参有固定套路——**先结构、后细节、最后精修**：
1. **学习率 $\eta$ 与树数 $n\_estimators$**：先定 $\eta$（0.01–0.1），树数靠**早停**（验证集）决定；
2. **树的结构**：树的深度/叶子数——决定「每棵树多强」，浅树（3–6 层）+ 多棵是默认；
3. **正则化**：XGBoost 的 $\gamma,\lambda$、LightGBM 的 `lambda_l1`、`lambda_l2`——压过拟合；
4. **采样与子特征**：`subsample`（样本采样）、`colsample_bytree`（特征采样）——引入多样性（第8章）；
5. **细调**：最优学习率衰减、`max_bin`（分箱数）、叶节点样本数。<span class="marginnote">「学习率/树数 → 结构 → 正则 → 采样」这个顺序有内在逻辑：先让「模型能学会」（学习率+树数），再定「每棵多强」（结构），再防「学过头」（正则），最后提「多样性」（采样）。盲目网格搜索全部参数（工程专题三会讲）效率极低——<strong>按因果顺序调参，比随机乱试快得多</strong>。</span>

## 4 实战陷阱与最佳实践**辨析｜易错点：**
**早停必须用验证集**：用训练集早停会让树数「虚高」，过拟合；用测试集早停 = 泄漏（第2章红线）；
**类别特征的处理**：LightGBM 原生支持 `categorical_feature`（不用独热），XGBoost 一般要自己编码——**选框架时把「类别特征多不多」算进去**；
**特征重要性别盲目信**：GBDT 的重要性偏向「高基数特征」——与随机森林交叉验证，结论更稳；
**缺失值**：三者都原生处理缺失，**不要**在喂模型前「填均值」——可能反损精度；
**小数据别迷信大框架**：几千样本时，一个调好的逻辑回归或决策树可能就够，GBDT 反而易过拟合。<span class="marginnote">「缺失值让模型自己处理、别手动填」是 GBDT 家族的最佳实践，与「逻辑回归要自己处理缺失」形成对比——因为树的稀疏感知/分箱天然容忍缺失。这条「不同模型族有不同的数据预处理惯例」，正是工程专题二《特征工程》要系统化的核心内容。</span>

## 知识速查：三大框架对比与选型

**本节关键词**
- 选型
- 梯度提升家族
- 速度-精度谱
- 调参顺序
- 早停
- 类别特征
- 缺失值
- 无万能框架

**三条常见误区**
1. 把「最新框架」当万能——数据规模决定工具；
2. 忽略早停必须用验证集；
3. 以为缺失值要先填——树模型原生处理。

**核心结论**
1. 三大框架是梯度提升树的三代；
2. 差异在工程近似（速度-精度谱）；
3. 调参顺序：学习率/树数→结构→正则→采样；
4. 选型由数据规模与特征类型决定。

**与全书/后续的连接**
- 专题一三节是知识基础；
- 专题二特征工程配合；
- 专题三 AutoML 自动选型。

**常见面试题**
1. 问：什么时候该用 LightGBM？ 答：大数据、高维稀疏、预算紧的场景。
2. 问：调参为什么先定学习率与树数？ 答：先让模型能学会，再定结构、正则、采样。

**一句话记忆**
选型 = 大数据/稀疏/预算紧用 LightGBM，中数据求精确用 XGBoost，小规模可解释用 GBDT。

## 5 小结- 三大框架是**梯度提升树的三代**：算法内核一致，差异在工程近似（速度-精度谱）。- 选型法则：**大数据/稀疏/预算紧 → LightGBM；中数据/求精确/要稳 → XGBoost；小规模/教学/可解释 → GBDT**。
- 调参顺序：**学习率+树数（早停）→ 树结构 → 正则化 → 采样 → 细调**。
- 实战陷阱：早停用验证集、类别特征选框架、缺失值别手填、重要性交叉验证。
- 没有「万能框架」——数据规模与目标决定工具，理解交换比迷信最新更重要。
