## 为什么从一阶规则学习开始

到目前为止，规则里的条件是「属性 = 值」或「属性 > 阈值」——这叫做**命题规则（propositional rule）**，它只能描述「单一样本」的属性。但很多知识本质是**关系**的：**「张三是李四的父亲，李四是王五的父亲 ⇒ 张三是王五的祖父」**——这条规则描述的是**多个对象之间的关系**，无法用「某个样本的属性」表达。要表达这类知识，需要把逻辑从「命题」升级到「一阶」。

**一阶规则学习（first-order rule learning）**用**一阶逻辑**写规则，条件里可以出现**变量与关系谓词**（$Father(x,y)$）。**FOIL（First-Order Inductive Learning）**是其中最著名的算法——它把序贯覆盖框架推广到一阶规则，并用一个漂亮的「信息增益」式函数指导规则生长。<span class="marginnote">「命题 → 一阶」是逻辑表达力的质变：命题规则只能「贴标签」（这个样本属于哪类），一阶规则能「描述关系」（哪些对象之间存在什么关系）。这让规则学习从「属性表数据」扩展到「关系数据库、知识图谱」——也是「归纳逻辑程序设计」（下一节）的入口。</span>

## 1 从命题到一阶：规则长出新能力**命题规则**的例子：「含糖率 > 0.3 ∧ 密度 > 0.6 → 好瓜」。它判断的是**一个样本**。
**一阶规则**的例子：

$$\text{Father}(x, y) \land \text{Father}(y, z) \rightarrow \text{Grandfather}(x, z)$$

这条规则说：「若 $x$ 是 $y$ 的父亲、$y$ 是 $z$ 的父亲，则 $x$ 是 $z$ 的祖父」。**变量 $x,y,z$ 可以取任意对象**，谓词描述对象间的关系——规则不再是「贴标签」，而是「发现关系模式」。<span class="marginnote">一阶规则的「变量化」让它能泛化到<strong>任何规模的对象</strong>：$Father(x,y)$ 里的 $x,y$ 可以代换成任何两个人。这种「带变量的规则」是逻辑编程（Prolog）的基本单元，也让人工智能能表达「家族关系、分子结构、图结构」这类本质是关系的知识。</span>

## 2 FOIL 算法：序贯覆盖 + 一阶规则FOIL 沿用序贯覆盖框架，只是「单条规则」换成「一阶规则」，生长方式也升级：
1. **目标**：为某个关系谓词（如 $Grandfather(x,z)$）学出一阶规则集；
2. **单条规则生长**：从空条件开始，逐步**添加一阶文字（literal）**——如「加一个条件 $Father(x,y)$」或「$y=z$ 之类的约束」，让规则更精确；
3. **候选文字**：可添加的文字包括「加一个新变量的关系」「限制已出现变量的关系」「变量之间的约束」等——搜索空间远比命题规则大；
4. **评价**：每个候选文字用 **FOIL 增益**打分，选增益最高的添加；
5. **序贯覆盖**：学完一条规则后删除其覆盖的正例，继续学下一条，直到覆盖全部正例。<span class="marginnote">FOIL 的生长是「自顶向下」的一阶版：从最一般（无条件的规则）开始，一步步加「限制」——每加一个文字，规则覆盖的正例减少但精确度上升。与命题规则的差别在于「文字」更丰富：不仅「属性测试」，还有「变量间关系、新变量的引入」，这让它能在关系数据上长出一阶规则。</span>

## 3 公式解析：FOIL 增益设添加候选文字 $L$ 前，规则覆盖的正例数为 $R_0^+$、反例数为 $R_0^-$；添加后为 $R^+$、$R^-$。**FOIL 增益**定义为：
$$\text{Gain} = |R^+| \times \left( \log_2 \frac{|R^+|}{|R^+| + |R^-|} - \log_2 \frac{|R_0^+|}{|R_0^+| + |R_0^-|} \right)$$

- **第一步，看括号里**：添加文字后「正例占比」的**对数提升**——$\log_2\frac{R^+}{R^++R^-}$ 减 $\log_2\frac{R_0^+}{R_0^++R_0^-}$，即「精确度的信息量增益」；
- **第二步，看乘数**：$|R^+|$ 是添加后覆盖的正例数——**保留的正例越多，增益越大**（条件不能把正例全丢光）；
- **第三步，看直觉**：FOIL 增益奖励「**仍覆盖足够正例、且精确度大幅提升**」的文字——同时追求「准」与「全」；
- **第四步，与信息增益对比**：它类似第4章信息增益，但用「正例占比」的对数差，专为「序贯覆盖里每条规则只负责部分正例」设计——也自然避免了「偏爱多值属性」的毛病。

**直觉一句话**：FOIL 增益对每个候选条件打分 =「保留正例数 × 精确度的信息量提升」——**既想多捞正例，又想捞得准**。

## 4 辨析：一阶规则学习的价值与成本**价值**：
- 表达**关系结构**知识（家族、分子、图），是命题规则做不到的；
- 输出可读的一阶规则，可直接喂给逻辑推理系统（Prolog）；
- 是「符号 AI」与「统计学习」的桥梁。

**成本与边界**：

- **搜索空间爆炸**：候选文字的组合远多于命题条件，效率是难题；
- **对数据要求高**：关系数据（多张表、对象间关系）比属性表难获取与整理；
- **噪声处理难**：一阶规则 + 噪声数据，剪枝与评价更复杂。<span class="marginnote">FOIL 的思想在现代 AI 里以「关系学习（relational learning）」延续：知识图谱补全、图神经网络的「关系推理」、以及「从数据归纳一阶规则」的神经符号系统（如 DeepLogic）——一阶规则把「逻辑表达」与「统计学习」缝合起来，是符号主义与联结主义的连接点。理解 FOIL，等于理解了「关系推理」的统计起源。</span>

**三条常见误区**
1. 把 FOIL 当命题规则学习——它处理对象间关系；
2. 忽略 FOIL 增益「保留正例×对数提升」的结构；
3. 以为一阶规则搜索便宜——候选文字组合爆炸。

**核心结论**
1. FOIL 学带变量的一阶规则；
2. 一阶规则能表达对象间关系；
3. FOIL 增益 = 保留正例 × 精确度对数提升；
4. 搜索空间远大于命题规则。

**常见面试题**
1. 问：命题规则与一阶规则的差别？ 答：命题判单样本属性，一阶表达关系谓词+变量。
2. 问：FOIL 增益为什么乘保留正例数？ 答：既想捞得多、又想捞得准。

**一句话记忆**
FOIL = 在关系数据上学习带变量的一阶规则，用 FOIL 增益引导规则生长。

## 5 小结- **命题规则**只判单样本属性；**一阶规则**用带变量的关系谓词表达对象间的关系。- **FOIL** 把序贯覆盖推广到一阶：逐条学一阶规则、逐文字自顶向下生长、覆盖后删正例。
- **FOIL 增益** = 保留正例数 × 正例占比的对数提升——兼顾「准」与「全」。
- 一阶规则可读、可推理、可表达关系知识；但搜索空间大、需关系数据。
- FOIL 是「归纳逻辑程序设计」的入口，也是关系学习与神经符号系统的思想源头。
