## 为什么从离线 RL 开始

真机 RL 要「边试边学」，
摔一次修一次——太贵。**离线强化学习（offline RL）** 换个思路：**只用一份固定数据集学习，不再在线交互**。
数据可以是历史轨迹、遥操作记录、仿真日志——机器人不用冒险就能「吃」海量数据。
但离线 RL 有个致命难点：**分布偏移**——数据集里没有的动作，
价值网络会「瞎猜」出离谱的高值。
CQL、IQL 与 Decision Transformer 是三条主流解法<span class="marginnote">离线 RL 与行为克隆的区别：BC 只学「复刻数据里的动作」，
离线 RL 要「从数据里学到更好的策略」——它试图「温故而知新」。
但「知新」必须在数据覆盖的范围附近，
否则就是幻觉。
离线 RL 的核心技术史，
就是一部「如何控制分布偏移」的历史。
</span>。

## 1 离线 RL 的问题：分布偏移

在线 RL 里，
策略产生的数据源源不断，
价值网络总是「见过」策略要用的动作。
离线 RL 中：

- 学习过程中**不再产生新数据**；
- 价值网络 $Q(s,a)$ 对**数据集之外的动作**（策略偶尔输出的陌生动作）没有任何依据——它会**外推（extrapolate）出荒谬的高值**；
- 策略发现「哎，
这个没见过的动作价值超高」，
于是疯狂选择它——**训练过程爆炸**。

这是离线 RL 的**分布偏移（distribution shift）** 与**价值过估计（value overestimation）** 问题：**策略在「没见过的动作」上越走越远，Q 网络在「没见过的数据」上越猜越离谱**。

## 2 CQL：把 Q 往下压，保守一点

**CQL（Conservative Q-Learning）** 的思路：**惩罚「策略喜欢但数据不支持」的动作**。
在 Q 更新里加一项正则：

$$
\min_Q\;\; \alpha\Big( \mathbb{E}_{s,a\sim\pi_\theta}\big[Q(s,a)\big] - \mathbb{E}_{s,a\sim\mathcal{D}}\big[Q(s,a)\big] \Big) + \text{标准 TD 项}
$$

- 第一项把**当前策略选的动作**的 Q 值压低——「策略想去的、数据没支持的地方，
价值打折」；
- 第二项把**数据集里的动作**的 Q 值抬高——「数据见过的，
价值真实」；
- 两项一推一拉，
Q 函数变得**保守**：陌生动作不虚高，
策略自然不敢冒险离开数据覆盖区。
<span class="marginnote">CQL 是「悲观主义」的代表：<strong>宁可低估，
不要幻觉</strong>。
它的效果立竿见影——几乎成了离线 RL 的基准方法。
代价是过保守会「不敢用更好的动作」，
性能天花板受限于「数据 + 一点泛化」。
</span>

## 3 IQL：不学 OOD，只查「数据集内的值」

**IQL（Implicit Q-Learning）** 走另一条路：**根本不让 Q 去评估策略选的动作**，
只评估「数据集里有的动作」。

- 用**期望分位数回归（expectile regression）** 拟合价值：对 TD 目标按上分位数回归，
得到「比平均值好一点」的价值；
- 更新策略时**只在数据集里的动作上做**——**避免任何 OOD 动作的 Q 查询**。

**直觉**：IQL 像个「只查证过的资料」的学者——不猜没见过的，
只从见过的数据里挑出「看起来更好」的动作。
它实现简单、稳定，
对数据质量鲁棒，
成了离线 RL 的另一个标配。

## 4 Decision Transformer：把 RL 当成序列生成

**Decision Transformer（DT）** 完全换框架：不学 Q、不学策略梯度，**把 RL 当成条件序列生成**：

- 序列 = (目标回报 R, 状态 $s_1$, 动作 $a_1$, R, $s_2$, $a_2$, …)；
- 用 Transformer 训练：给定「期望回报 + 状态历史」，
预测下一个动作；
- 推理时指定「想要多高的回报」，
模型生成一条达到该回报的轨迹。

**关键区别**：DT 是**监督式**训练（预测动作），
没有 TD、没有价值外推——**分布偏移问题被「绕开」而不是「压制」**。
它把「目标」编码成**回报-到-来（return-to-go）**，
通过「条件生成」实现「目标导向」。

**局限**：DT 本质接近「条件行为克隆」——**它从数据里学到的是「给定回报的条件下该怎么做」，泛化上限受数据覆盖限制**，
对超出数据水平的最优性追求有限。
但它的简单与「大模型式」风格让它成为连接 RL 与序列模型/LLM 的桥梁。

## 5 公式解析：CQL 的保守项与 IQL 的分位数

$$
\min_Q\; \underbrace{\alpha\,\mathbb{E}_{a\sim\pi_\theta}\big[Q(s,a)\big]}_{\text{压陌生动作}} - \underbrace{\alpha\,\mathbb{E}_{a\sim\mathcal{D}}\big[Q(s,a)\big]}_{\text{抬数据动作}} + \tfrac{1}{2}\mathbb{E}\big[(Q(s,a)-\mathcal{T}Q)^2\big]
$$

- **第一步，看第一项的语义**：$\mathbb{E}_{a\sim\pi_\theta}Q$ 是「策略想去的地方的平均价值」。**最小化它 = 让策略喜欢但数据没覆盖的地方价值变低**。
- **第二步，看第二项的语义**：$\mathbb{E}_{a\sim\mathcal{D}}Q$ 是「数据里真实出现过的动作的价值」。**最大化它 = 让数据里的好动作价值不被误压**。
- **第三步，看第三项（TD 项）**：标准 Bellman 更新让 $Q$ 对齐真实的时序价值——三者的平衡由 $\alpha$ 控制，
$\alpha$ 大则更保守（更稳但更不敢冒险）。
- **第四步，对照 IQL**：IQL 不压陌生动作，
而是**根本不评估**陌生动作（策略更新只在数据集动作上做）；
DT 连 TD 都不用，
直接监督式生成。**三条路线 = 「压」OOD、「不碰」OOD、「绕开」OOD——离线 RL 的全部智慧都在「怎么对付没见过的动作」**。

## 6 辨析｜离线 RL vs BC；CQL vs IQL vs DT

**辨析｜易错点一：离线 RL ≠ 行为克隆。** BC 只复刻数据，
性能上限 = 数据质量；
离线 RL 试图「从数据学到更好策略」（如挑出数据里高回报的轨迹风格）。
但**离线 RL 的收益依赖数据覆盖**——数据里没有「更好」，
离线 RL 也变不出来。
<span class="marginnote">选型经验：<strong>数据质量高、覆盖好 → 离线 RL 能超越 BC；
数据稀疏、覆盖差 → 离线 RL 可能不如 BC 稳</strong>（BC 至少不会因价值外推而崩）。
工业上「BC 起步、离线 RL 精选」是稳妥组合。
</span>

**辨析｜易错点二：CQL 偏悲观，DT 偏模仿。** CQL 会为了「不冒风险」而牺牲最优性（过保守）；
DT 没有价值外推但本质是条件模仿，
无法「发现数据里没有的策略」。**追求「在数据分布内尽量好」→ CQL/IQL；追求「风格统一、好部署」→ DT**。
两者都不是「万能离线算法」。

**再辨析｜离线数据的「奖励标注」本身是工程**。
离线 RL 需要每条轨迹有奖励——真实机器人数据（遥操作、日志）往往没有奖励。
常见做法：**事后用规则/模型标注（如「到达目标 +1」）**，
或用 IRL/偏好模型学奖励。**「数据没有奖励」是离线 RL 落地的第一道坎**，
比算法选择更现实。

## 7 小结

- **离线 RL**：用固定数据集学习，
不再在线交互；
难点是分布偏移与价值过估计。
- **CQL**：保守 Q——压策略喜欢的陌生动作、抬数据动作，
悲观但稳。
- **IQL**：期望分位数回归，
只在数据集动作上更新，
不评估 OOD，
简单鲁棒。
- **Decision Transformer**：把 RL 当条件序列生成，
监督式、绕开 OOD，
但本质接近条件模仿。
- 「压」「不碰」「绕开」OOD 是三条路线；
数据覆盖与奖励标注决定落地成败。
