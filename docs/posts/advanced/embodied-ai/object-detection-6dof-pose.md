## 为什么从检测与位姿开始

机器人要抓杯子，
得先在画面里**认出杯子在哪（检测）**，
再知道它**在空间里怎么摆（6D 位姿）**。
检测回答「这是什么、大致在哪」，
位姿回答「它的坐标系相对相机坐标系是哪组 $(R,t)$」——后者才是机械臂能下手的前提<span class="marginnote">从检测到位姿是一条能力阶梯：2D 框只能告诉你「屏幕里有个杯子」，
抓取需要的是「杯子坐标系到机械臂坐标系的旋转和平移」。
差着一整层几何，
所以工业项目里 2D 检测跑通只算完成 20%。
</span>。

## 1 2D 目标检测：先认出「这是什么、在哪」

**2D 目标检测**输出图像中每个物体的**边界框 + 类别 + 置信度**。
三代主流路线：

**两阶段（two-stage）**：先由区域建议网络（RPN）提出候选框，
再对每个候选分类回归。
代表 Faster R-CNN。
精度高、慢。
**单阶段（one-stage）**：直接在特征图上预测框与类别，
一个网络搞定。
代表 YOLO 系列、SSD、RetinaNet。
快、适合实时。
**Transformer 端到端**：把检测当成「集合预测」问题，
匈牙利匹配做标签分配，
无需锚框与 NMS。
代表 DETR、DINO。
流程简洁，
大模型时代成为主流底座。

对机器人而言，**帧率与延迟**往往比极限精度重要——抓取闭环里 30 FPS 的 YOLO 比 3 FPS 的暴力精度实用得多。

## 2 3D 目标检测：在三维空间里定位

2D 框没有深度，
抓取不够。**3D 目标检测**输出 **3D 包围盒**：中心 $(x,y,z)$、尺寸（长宽高）与朝向（偏航角 $\theta$，
对地面物体常见）。

按输入分三路：

**点云路线**：把点云体素化（VoxelNet、SECOND）或柱状化（PointPillars），
再用稀疏卷积/MLP 提特征，
输出 3D 框。
对几何精确、无光照问题，
是自动驾驶主流。
<span class="marginnote">PointPillars 的思路：把点云投影到鸟瞰平面（BEV）的柱子（pillar）里，
每个柱子聚合成一个特征向量——把无序点云变成了规则的「柱状特征图」，
直接上 2D 卷积。
几何信息损失少、速度快，
是工业落地的常客。
</span>
**单目/双目相机路线**：从图像直接回归 3D 框（CenterNet 系），
受尺度不确定性限制，
远距离误差大；
双目可恢复尺度。
**融合路线（BEV）**：把相机与雷达特征都投影到鸟瞰平面融合（LSS、BEVFormer），
几何与语义互补。

## 3 6D 位姿估计：不只框，还要 R,t

**6D 位姿** = 物体坐标系到相机坐标系的刚体变换 $(R,t)$，
$R\in SO(3)$、$t\in\mathbb{R}^3$。
经典方法分四代：

**对应点 + PnP（经典）**：提取 2D 特征点并与已知 CAD 模型上的 3D 点匹配，
用 PnP + RANSAC 解出 $(R,t)$。
依赖纹理，
鲁棒性受特征质量限制。
**直接回归（deep regression）**：PoseCNN 直接从图像回归旋转、平移与对称性；
缺点是旋转回归不稳定，
后续多用旋转表示（四元数、旋转矩阵的连续化）改进。
**稠密对应（dense correspondence）**：对每个像素/点预测其在物体坐标系中的坐标（PVN3D、DenseFusion），
再对稠密对应做最小二乘解位姿。
几何信息利用率高，
精度领先。
**类别级（category-level）**：对从未见过的同类物体估计位姿。**NOCS**（Normalized Object Coordinate Space）把物体归一化到标准空间，
网络预测每个像素的 NOCS 坐标，
再做形变匹配。
是「泛化到新实例」的关键一步。
<span class="marginnote">实例级与类别级的差别：实例级认「这个具体杯子」（需要 CAD 模型），
类别级认「所有杯子」（只需类别先验）。
抓取系统要能在货架上认新杯子，
就必须走类别级路线——这也是 VLA 时代「开放词汇操作」的地基。
</span>

## 4 公式解析：PnP 与 ADD 指标

**PnP（Perspective-n-Point）**：已知 $n$ 对 2D-3D 对应（像素 $u_i$ ↔ 模型点 $x_i$），
求 $(R,t)$ 使重投影误差最小：

$$
(R^*,t^*) = \arg\min_{R,t}\sum_i \rho\big(\| \pi(K(Rx_i + t)) - u_i \|\big)
$$

其中 $\pi$ 是针孔投影，
$\rho$ 是鲁棒核（配合 RANSAC 抗离群）。

**ADD 指标（Average Distance）** 衡量位姿估计质量：

$$
\text{ADD} = \frac{1}{m}\sum_{i=1}^{m}\big\| (R x_i + t) - (\hat R x_i + \hat t) \big\|
$$

- **第一步，看 ADD 的语义**：把模型点分别用真值位姿与估计位姿变换，
算所有点的平均距离。**ADD 小 ⇔ 模型在估计位姿下与真值重合**，
是度量「位姿对不对」的物理指标。
- **第二步，理解阈值判定**：BOP 等基准把 ADD < 物体直径 × 10% 记为成功，
统计成功率。
不同物体的阈值不同，
直径归一化让指标跨物体可比。
- **第三步，看对称物体的修正**：对轴对称物体（杯子、瓶子），
绕对称轴的旋转错判并不改变外观，
ADD 会「错罚」正确估计。
于是有 **ADD-S**：让模型点与真值/估计之间取「最近距离」（允许整体对称匹配）。
用 ADD 还是 ADD-S，
取决于物体是否对称——这是评测里最常见的坑。

## 5 辨析｜检测 ≠ 位姿；实例 ≠ 类别；对称 ≠ 一般

**辨析｜易错点一：检测输出框，位姿输出 $(R,t)$**。
2D 检测跑通 ≠ 能抓取。
很多项目在「检测准确率 95%」上沾沾自喜，
一上机械臂就抓空——因为缺了位姿这一整层。
3D 检测给的 3D 框也只是「粗位姿」（中心+朝向），
精抓取还要 6D 精配准（ICP 或稠密对应）。

**辨析｜易错点二：实例级与类别级不可混谈。** 实例级要求测试物体与训练 CAD 一致；
类别级要求泛化到新实例。
做部署评估前先问「我的测试集是见过的物体还是没见过的」，
否则指标会误导。
<span class="marginnote">一个实务建议：抓取部署用「实例级 + 精配准」打底（精度高、可控），
再用类别级或 VLA 兜底泛化（换物体不断流）。
两套并行，
是工业抓取的标准分层。
</span>

**再辨析｜对称物体的评测陷阱**：对杯子、瓶子这类旋转对称物体，
评估指标必须用 ADD-S 而非 ADD，
否则一个「实际正确」的位姿会被判错。
反过来，
训练时也要意识到：对称轴的旋转方向在数据里是「多解的」，
直接回归旋转会对齐到任意一个等效解，
导致训练不稳定——很多工作因此对对称轴做旋转增强。

## 6 小结

- **2D 检测**：两阶段/单阶段/Transformer 三代，
机器人场景看帧率与延迟。
- **3D 检测**：点云（体素/柱状）、单目、BEV 融合三路，
输出 3D 框。
- **6D 位姿估计**：经典 PnP、直接回归、稠密对应、类别级 NOCS 四代路线。
- **PnP** 用 2D-3D 对应 + RANSAC 解 $(R,t)$；**ADD/ADD-S** 是位姿评测的通行指标。
- 检测给框、位姿给 $(R,t)$；
实例级与类别级、对称与一般物体，
评测口径要分清。
