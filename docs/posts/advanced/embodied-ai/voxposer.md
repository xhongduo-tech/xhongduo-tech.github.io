## 为什么从 VoxPoser 开始

SayCan 要预训练技能库、CaP 要设计好 API——它们都依赖「机器人侧的准备」。**VoxPoser** 换一个更「开箱即用」的思路：**让大模型（LLM + VLM）直接生成 3D 价值地图（voxel value map）**——语言指令被翻译成「哪里该去（正价值）、哪里别碰（负价值）」的体素地图，
再用这张地图引导运动规划。**零训练、零技能库、开放词汇**——它把「语言 → 3D 空间语义」这件事直接做到了规划层<span class="marginnote">VoxPoser 的论文叫《VoxPoser: Composable 3D Value Maps for Robotic Manipulation with Language Models》。
它的核心洞见：<strong>语言最终要变成「空间偏好」——哪个区域好、哪个区域坏</strong>。
与其让语言去选技能，
不如让语言直接「画出」空间里的好恶，
然后规划器照着地图走。
</span>。

## 1 从语言到 3D 价值地图

**VoxPoser** 的流程：

1. **感知**：RGB-D 相机拍当前场景，
构建**3D 体素网格（voxel grid）**（含语义标签：物体、桌面、障碍）；
2. **LLM + VLM 生成价值函数**：LLM 把语言指令分解成「程序化操作」，
VLM 把「物体/区域」与 3D 位置对齐；
3. **合成 3D 价值地图**：程序在体素网格上**画出正负价值**——「目标物体附近 +1」「障碍物附近 −1」「桌面下方禁止」；
4. **规划**：把价值地图当**代价/吸引力场**，
用运动规划/轨迹优化找出「价值高的路径」；
5. **执行**：末端沿路径移动，
完成操作。

**关键**：**价值地图是「空间偏好」的显式表达**——「把杯子放到盘子上」变成「杯子位置附近高价值 + 盘子正上方高价值 + 撞到其他物体低价值」的一张 3D 图。

## 2 可组合的价值函数

VoxPoser 的「价值函数」是**可组合的**：LLM 生成的不是一张图，
而是一组**带权重的小价值项**：

$$V(x) = \sum_i w_i\, v_i(x)$$

- $v_1(x)$：「目标物体附近 +」（把末端吸引到目标）；
- $v_2(x)$：「目标区域上方 +」（放置位置）；
- $v_3(x)$：「障碍物 −」（避障）；
- $w_i$：LLM 给的权重（「先靠近再放」决定权重顺序）。

**组合**让价值地图能表达复杂任务：「先接近再放置」= 目标吸引项 + 放置项 + 避障项的加权和——**一张图表达整个任务的空间偏好**。

## 3 零样本与开放词汇

VoxPoser 的核心卖点：**不需要任何机器人训练**。

- 大模型（LLM + VLM）的「世界知识」提供「杯子长什么样」「放上去意味着什么」；
- 3D 感知（分割 + 位姿）把「语义」接到「空间」；
- **换任务只需换语言指令**——「把书放到书架」与「把苹果放进碗」共用同一套系统，
只是价值图不同。

**对比 SayCan/CaP**：它们需要技能库/API 的「机器人侧准备」；
VoxPoser 只需要「大模型 + 感知」，**零训练**——这是「LLM 具身」走向「开箱即用」的一步。
<span class="marginnote">VoxPoser 的「零样本」本质：<strong>它把「语言到空间」的翻译外包给大模型，
把「空间到动作」的翻译外包给规划器</strong>——机器人侧的「准备」被压缩到只剩感知与规划器，
大模型承担了其余一切。
这是「基础模型时代」的具身范式：尽量让模型「天生就会」，
机器人只补物理接口。
</span>

## 4 价值图驱动的规划

规划器如何用价值图？

- **作为吸引/排斥场**：正价值区域「拉」、负价值区域「推」，
用势场法或轨迹优化沿「价值梯度」走；
- **作为代价函数**：价值图进入轨迹优化的代价（价值低的路径被惩罚），
找到「高价值路径」；
- **作为可行域**：负价值区域（障碍）排除在可行解外。

**与经典规划的关系**：VoxPoser 的价值图本质是**把「任务语义」编译成「空间偏好」**，
再喂给「成熟的空间规划器」——**大模型管语义，规划器管几何**，
分工清晰。

## 5 公式解析：价值图合成与规划

$$
V(x) = \sum_{i} w_i\, v_i(x), \qquad x^* = \arg\min_{x(t)} \int \big( -V(x(t)) + \lambda\, \|\ddot x(t)\|^2 \big) dt
$$

- **第一步，看价值合成**：$V(x)$ 是多个价值项 $v_i$ 的加权和——**每个 $v_i$ 来自一句语言子指令（LLM 生成）与空间对应（VLM 对齐）**；
- **第二步，看价值图的几何**：$v_i(x)$ 是定义在 3D 体素网格上的标量场（近目标正、近障碍负）——**「空间偏好」的数字表达**；
- **第三步，看规划目标**：轨迹 $x(t)$ 要「价值积分最大 + 平滑项最小」——**既往好的地方去，又走得稳**；- **第四步，看权衡**：$\lambda$ 控制「追求价值」与「保持平滑」的权重——$\lambda$ 大则轨迹稳但可能绕远，小则直奔高价值区但可能走得不自然。**价值图让规划器「知道任务要什么」，平滑项让轨迹「像机器人走的」**。## 6 辨析｜VoxPoser vs SayCan/CaP；价值图 vs 技能
**辨析｜易错点一：VoxPoser 与 SayCan 是「空间」与「技能」的路线差。** SayCan 用价值函数**选技能**（离散动作），
VoxPoser 用价值图**引导连续运动**——<span class="marginnote">前者「选一个已会做的」，
后者「现场生成一条路径」。
SayCan 需要技能库（要预训练），
VoxPoser 不需要（零训练）——代价是 VoxPoser 只做「运动层」，
复杂接触任务（要专门技能）不如 SayCan 的 RL 技能。
</span>

**辨析｜易错点二：价值图不是「轨迹」，是「引导」。** 价值图只给出「空间哪里好」，
具体路径由规划器解出——**价值图是「软约束」，不是「硬轨迹」**。
正因如此它能实时适应场景变化（物体被挪了，
价值图重算，
路径自动变）。

**再辨析｜VoxPoser 的局限**：依赖 **RGB-D 感知质量**（分割错了价值图就错）；
价值图是「运动层」表达，**精细接触（拧瓶盖）价值图表达不了**。
它是「大模型 + 规划器」的中层方案——**上层语义、中层价值图、下层控制**的分层骨架没变，
只是中层从「技能」换成了「价值图」。

## 7 小结

- **VoxPoser** = LLM + VLM 生成可组合的 3D 价值图，
引导运动规划。
- **价值图** $V(x)=\sum_i w_i v_i(x)$：目标附近正、障碍负——语言指令的「空间翻译」。
- **零样本**：不需要技能库、不需要训练——大模型管语义、规划器管几何。
- **规划**：价值图当吸引/排斥场，
轨迹优化找「高价值 + 平滑」的路径。
- 价值图是软约束不是硬轨迹；
精细接触任务仍需专门技能，
价值图是运动层方案。
