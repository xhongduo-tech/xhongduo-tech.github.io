## 为什么从 PaLM-E 开始

**PaLM-E**（2023，
谷歌）把「具身」放进大模型的名字：一个**嵌入物理世界传感器数据的大语言模型**。
它首次把**连续的机器人观测（图像、状态、3D）token 化后直接注入 LLM**——于是「会推理的大模型」与「物理世界」接通了。
2025 年的 **Gemini Robotics** 把这条线推进到 Gemini 级别，
成为当前具身多模态大模型的旗舰代表。
这一节纵览「具身多模态大模型」这条主线<span class="marginnote">PaLM-E 的「E」是 Embodied——它不只是「视觉语言模型」，
而是「吃真实世界信号的大模型」：机器人相机、关节状态、3D 点云都变成 token 进 LLM。
这比 RT-2（只吃图像）更进一步——<strong>把「世界的身体信号」直接接进推理</strong>。
</span>。

## 1 PaLM-E：把传感器数据注入 LLM

**PaLM-E** 的架构：

- **输入**：图像 token（视觉编码器）+ **状态 token**（机器人关节角、物体位姿，
编码成向量） + 文本 token（指令）；
- **骨干**：PaLM（大 LLM），
所有 token 一起做自回归；
- **输出**：文本（任务规划、视觉问答）+ **动作 token**（机器人动作）。

**关键创新**：**状态 token**——不只在「图像」层接世界，
还把**连续状态/3D 信息**直接翻译成 token 喂给 LLM。
这让 LLM 能「推理物理世界」：它知道物体的 3D 位姿、机器人当前状态，
从而规划「物理上可行」的步骤。

## 2 为什么「多模态 + 具身」有效

- **互联网知识迁移**：PaLM-E 的底座在大规模文本/图像上预训练——「杯子」「桌子」「放上去」这些概念已经懂，
机器人任务只是「把这些知识用到物理世界」；
- **统一的推理与动作**：同一个模型既能「视觉问答」（描述场景）又能「规划动作」（决定做什么）——**感知、推理、规划不再分家**；
- **开放性**：多模态输入让「长尾任务」可描述——「把红色的那个放到蓝色的旁边」这类**开放指令**不再需要预定义技能。

**规模效应**：参数量从 12B 到 562B，
PaLM-E 展示了「模型越大、具身推理越强」——**大模型的「通用智能」正是具身任务稀缺的「常识」**。

## 3 Gemini Robotics：Gemini 级别的具身模型

**Gemini Robotics**（Google DeepMind，
2025）把 PaLM-E 的路线推进到 Gemini 级：

- **Gemini Robotics**：一个「具身推理 + 动作生成」的多模态模型——语言、视觉、动作统一，
直接输出机器人动作；
- **Gemini Robotics-ER（Embodied Reasoning）**：专注**空间理解**——从图像/视频生成 3D 场景理解（分割、位姿、可供性），
供下游规划/控制使用；
- **新一代基础模型**：强调「跨形态」（不同机器人）+「实时」（低延迟控制）+「可微调」（适配新平台）。

**趋势**：具身多模态大模型从「研究原型」（PaLM-E）走向「平台级基础模型」（Gemini Robotics）——**「一个模型，多种机器人，开放任务」成为目标**。
## 4 与 VLA 的关系

PaLM-E/Gemini Robotics 与 RT-2/π0 等 VLA 是**同一思潮的两面**：

- **VLA（RT-2、π0）**：专注「视觉 + 语言 → 动作」——**动作输出**是核心；
- **具身多模态大模型（PaLM-E、Gemini）**：更广——**推理、规划、问答、动作**一个模型全包，
机器人只是「一种输出」。

**界限在模糊**：RT-2 用 VLM 底座、PaLM-E 也输出动作；
Gemini Robotics 直接就是「Gemini + 动作」。**共同趋势**：用「互联网级大模型」做「具身智能的地基」——世界知识 + 推理 + 动作。
<span class="marginnote">一句话把握全局：<strong>「具身大模型」= 把机器人任务塞进「已经懂世界的大模型」</strong>。
VLA 是最小形态（图 → 动作），
PaLM-E 加了状态 token（图 + 状态 → 推理 + 动作），
Gemini Robotics 把它做成平台（跨形态、实时、可微调）。
尺度在变、架构在变，
「大模型当具身地基」没变。
</span>

## 5 公式解析：状态 token 化

$$
\text{input} = \big[ E_{img}(I),\; E_{state}(s),\; T(\text{instruction}) \big], \qquad \text{output} = \big[ T(\text{plan}),\; E_{act}^{-1}(\text{action tokens}) \big]
$$

- **第一步，看输入拼装**：图像经 $E_{img}$、状态经 $E_{state}$、指令经文本编码 $T$，**全部拼成 token 序列**喂给 LLM——**「世界信号」与「语言」共用同一个模型**；
- **第二步，看状态 token**：$E_{state}(s)$ 把连续状态（关节角、物体位姿）映射到 token——**这是 PaLM-E 相对「纯视觉 VLM」的核心差异**：机器人「知道自己现在的姿势」；
- **第三步，看输出**：模型既出文本（计划/问答）也出动作 token（$E_{act}^{-1}$ 反离散化成动作）——**推理与动作同源**；
- **第四步，看为什么难**：状态 token 与语言 token 要**在同一语义空间**里协调——模型要理解「我的手臂现在举着杯子」这种「身体状态」与「语言目标」的关系。**「身体感」进模型，是具身大模型区别于普通 VLM 的本质**。
## 6 辨析｜PaLM-E vs RT-2；具身推理 vs 动作模型

**辨析｜易错点一：PaLM-E 是「通用具身推理」，RT-2 是「动作专用」。** RT-2 的底座也是 VLM，
但专注「图 → 动作」；
PaLM-E 加了状态 token、输出范围更广（规划 + 问答 + 动作）。
<span class="marginnote">实务判断：<strong>任务就是「操作」→ VLA（RT-2/π0）更聚焦、更成熟；
任务要「推理 + 规划 + 操作」→ 具身多模态大模型更全面</strong>。
Gemini Robotics 的「双模型」策略（Robotics 出动作、Robotics-ER 出空间理解）正是「聚焦动作 + 通用推理」的分工。
</span>

**辨析｜易错点二：具身多模态大模型 ≠ 自动驾驶/操作专用模型。** 它们是大模型（通用智能），
不是专用控制器——**输出是「高层意图」而非关节力矩**，
低层控制仍由传统控制器/策略执行。
「大模型管决策、控制器管执行」的分层（第 20 章）在具身大模型里依然成立。

**再辨析｜「具身」不是「加个相机」**。
给 LLM 加图像输入只是「视觉语言模型」；**PaLM-E 的「具身」在于状态 token（身体感）与动作输出（能动）**——「感觉到自己 + 能行动」才是具身。
VLM ≠ 具身大模型，
这个区分很关键。

## 7 小结

- **PaLM-E** = 嵌入物理世界信号的大语言模型：图像 + 状态 token + 文本 → 推理 + 动作。
- **状态 token**是「具身」的关键：机器人的身体状态进 LLM，
VLM 没有。
- **Gemini Robotics**：Gemini 级具身模型——Robotics（动作）与 Robotics-ER（空间理解）分工。
- **趋势**：用互联网级大模型当具身地基，
VLA 是最小形态，
PaLM-E/Gemini 是全面形态。
- 具身 ≠ 加相机，
要「身体感 + 行动」；
大模型管决策、控制器管执行的分层不变。
