## 为什么从 Octo 开始

**Octo**（2024，
伯克利/斯坦福/CMU 等）是另一款开源的**通用机器人策略（generalist robot policy）**：不绑定单一机器人，
而是**在多个机器人平台的混合数据上训练**，
用一个 Transformer 通吃不同机械臂、不同夹爪、不同任务。
它和 OpenVLA 并列为开源具身智能的两大基座，
但走了一条不同路线——**模块化观测编码 + 扩散动作头**，
并特别强调**跨具身迁移**<span class="marginnote">Octo 与 OpenVLA 的路线分野：<strong>OpenVLA 用「LLM 当大脑」（动作是文本 token），
Octo 用「Transformer 当骨干 + 扩散头」（动作是连续生成）</strong>。
两者都吃 Open X-Embodiment，
但架构哲学不同——一个靠语言模型的智能，
一个靠序列模型的通用性。
</span>。

## 1 通用策略要解决什么

传统策略「一机器人一模型」：换平台就重训。**通用策略（generalist policy）** 的目标：

- **跨具身（cross-embodiment）**：在一个机器人上学到的「抓取」，
能迁移到另一台机器人；
- **跨任务**：一个模型处理多任务（语言/目标图像条件）；
- **可微调**：新机器人用少量数据适配即可。

**核心假设**：不同机器人的「抓、放、推」在**抽象层面是同一个技能**——只是执行机构不同。
通用策略要学的是「技能」，
而不是「某台机器」。

## 2 架构：模块化观测 + Transformer + 扩散头

Octo 的架构三块：

- **模块化观测编码器**：图像用视觉编码器（如 ViT）、本体感受用 MLP——**不同模态各编码，再拼成 token**。
模块化让它能**换传感器**（新机器人的相机数量、位姿不同，
只要换编码器配置）。
- **Transformer 骨干**：把观测 token、任务条件 token（语言/目标图像）、历史动作 token 一起做**交叉注意力**——**条件注入（conditioning）与历史建模**。
- **扩散动作头**：用**扩散模型**生成动作块（action chunking）——预测未来 $H$ 步动作，
连续、多模态（第 13 章扩散策略的路子）。

**任务条件**：Octo 支持三种条件——**语言指令、目标图像、或两者结合**——这让它在「没有语言标注的数据」上也能训练（用目标图像当条件）。

## 3 跨具身：怎么让一个模型服务多台机器人

Octo 的跨具身设计细节：

- **按具身添加 token**：给每个机器人平台一个**具身 token（embodiment token）**，
输入时告知模型「现在是在哪台机器人上」；
- **统一动作空间**：把不同机器人的动作归一化到「末端增量」等**通用形式**——不同关节数的机器人也能共享；
- **微调新平台**：冻结大部分骨干，
只微调观测编码器 + 少量层，
用**几十条数据**适配新机器人。

**效果**：Octo 在「从未见过的机器人」上**零样本**有基础成功率，
微调后显著提升——**「见过很多机器人」让「没见过的那台」不那么陌生**。
<span class="marginnote">跨具身迁移的直觉：<strong>就像学了很多种方言的人，
学一门新方言更快</strong>——Octo 见过的「手臂-夹爪」组合越多，
对新组合的「先验」越强。
具身 token 让模型「知道现在这台长什么样」，
从而在共享的「技能空间」里正确检索。
</span>

## 4 数据：Open X-Embodiment

Octo 在 **Open X-Embodiment** 数据集上训练：20+ 机构、数十台机器人、百万条真实示范。**数据混合（data mixing）** 的策略：

- **按具身加权**：数据量少的平台适当加权，
防止大平台淹没小平台；
- **统一格式**：把不同平台的动作、观测、指令格式统一成 Octo 的接口；
- **质量筛选**：去掉失败示范、不对齐的样本。

**「数据混合」本身就是一门技术**——通用策略的瓶颈常不是架构而是「怎么把不同来源的数据喂好」。

## 5 公式解析：扩散动作头的生成

$$
x_{t-1} = \mathrm{denoise}\big( x_t,\; \epsilon_\theta(x_t, t, \text{obs}, \text{cond}) \big), \qquad x_0 = \text{动作块}
$$

- **第一步，看条件**：去噪网络 $\epsilon_\theta$ 吃观测与任务条件（语言/目标图像）——**生成「满足当前观测与指令」的动作块**。
- **第二步，看迭代去噪**：从噪声 $x_T$ 迭代 $T$ 步到 $x_0$——**动作是「采样」出来的**，
天然支持多模态（同一观测可采样出「左边够」或「右边够」）。
- **第三步，看动作块**：$x_0$ 是 $H$ 步的动作序列——**一次生成一段**，
时序一致（动作分块，
第 13 章）。
- **第四步，看与 token 化的对比**：RT/OpenVLA 把动作离散成 bin（分类），
Octo 用扩散**连续生成**——**连续 vs 离散的取舍**：扩散更精细但推理慢（迭代），
分类快但有量化误差。

## 6 辨析｜Octo vs OpenVLA；扩散头 vs token 化；通用 vs 专用

**辨析｜易错点一：Octo 与 OpenVLA 是「序列通用性」与「语言智能」的分野。** OpenVLA 把动作当文本，
靠 LLM 的世界知识；
Octo 不依赖 LLM，
靠「多具身数据的通用性 + 扩散的精细动作」。
<span class="marginnote">选型判断：<strong>任务需要「语义理解」（新指令、关系推理）→ OpenVLA；
任务需要「精细连续动作」（插孔、装配、多模态）→ Octo/扩散类</strong>。
两者不互斥——π0 正是想把「语言智能 + 精细动作」都拿到（下一节）。
</span>

**辨析｜易错点二：通用 ≠ 什么都会。** 通用策略在「见过的技能分布」内通用，
「没见过的技能」（全新动作类型）仍需微调。**「通用」是「起点通用」，不是「终点全能」**——Octo 的定位是「好基座」，
不是「毕业模型」。

**再辨析｜跨具身迁移的边界**。
跨具身迁移对「相似形态」（不同机械臂、不同夹爪）有效；
「形态差异过大」（桌面臂 → 人形全身）时，
动作空间的差异让迁移收益骤减。**「具身距离」决定迁移难度**——同形态族的迁移是「锦上添花」，
跨形态是「重新开始」。

## 7 小结

- **Octo**：开源通用机器人策略，
多具身混合数据上训练，
Transformer 骨干 + 扩散动作头。
- **架构**：模块化观测编码（可换传感器）+ Transformer 交叉注意力 + 扩散生成动作块。
- **跨具身**：具身 token + 统一动作空间 + 微调少量层，
新机器人几十条数据适配。
- **数据**：Open X-Embodiment 百万条，
按具身加权 + 统一格式混合。
- 扩散头 vs token 化、通用 vs 专用、语义 vs 精细——选型看任务需求与形态距离。
