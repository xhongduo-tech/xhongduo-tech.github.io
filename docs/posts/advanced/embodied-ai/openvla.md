## 为什么从 OpenVLA 开始

RT-2 证明了 VLA 的威力，
但它**不开放**——模型、数据、训练细节都在谷歌手里。**OpenVLA**（2024，
斯坦福 + 谷歌 + 多家）把 VLA 做成**开源**：7B 参数、公开权重、可在消费级 GPU 上微调。
它填补了「VLA 研究」与「VLA 可用」之间的鸿沟，
成了学界与中小团队做具身智能的事实起点<span class="marginnote">OpenVLA 的定位一句话：<strong>「VLA 界的 LLaMA」——把封闭的大模型做成社区可用的开源模型</strong>。
7B 参数让它在 24GB 显存的单卡上能微调，
这让「人人可做 VLA」从口号变成现实。
</span>。

## 1 架构：视觉编码器 + LLM + 动作头

OpenVLA 基于 **Prismatic VLM**（开源视觉-语言模型），
三件套：

- **视觉编码器**：**SigLIP**（图像 → 视觉 token）；
- **大语言模型**：**LLaMA-2 7B**（融合视觉 token 与指令，
生成动作）；
- **动作头**：把 LLM 输出的动作 token **反离散化**成连续动作（末端位置、旋转、夹爪），
送底层控制。

**动作 token 化**沿用 RT-1/RT-2 的路线：连续动作量化成 bin，
LLM 以文本方式预测动作 token，
动作头把它们还原成连续值。**架构哲学**：能用开源组件（SigLIP、LLaMA）就绝不自己造——这让 OpenVLA 天然与开源生态（HuggingFace、transformers）兼容。

## 2 训练：Open X-Embodiment 数据

OpenVLA 在 **Open X-Embodiment 数据集**上训练（第 18 章会展开）——一个汇集了 20+ 机构、多个机器人平台、百万条示范的开源具身数据集：

- **跨具身**：不同机械臂、不同夹具、不同相机布局；
- **多任务**：桌面操作、导航、双手机器人；
- **统一格式**：RT-1 风格的动作 + 自然语言指令。

**跨具身的意义**：一个模型在「多种机器人」上训练，
学到的是**任务与动作的抽象**而不是某一台机器的细节——这让 OpenVLA 部署到**新机器人**时「预训练已经见过类似的」。

## 3 微调：用 LoRA 适配新场景

OpenVLA 的核心卖点是**好微调**。
对新的机器人/新任务，
不需要重新训练整个 7B 模型，
而是用 **LoRA（Low-Rank Adaptation）**：

- **冻结**原模型权重，
只训练小的**低秩适配矩阵**（在原权重旁加 $\Delta W = BA$，
$B\in\mathbb{R}^{d\times r}$、$A\in\mathbb{R}^{r\times d}$，
$r\ll d$）；
- 训练参数量从 70 亿降到**几百万**——24GB 显存单卡即可；
- **几十到几百条新任务数据**就能把模型适配到新平台/新任务。

**LoRA 的哲学**：原模型是「通用智能」（懂世界、懂动作），
LoRA 是「领域适配」（这台的相机、这个任务的写法）——**保留通用性，只改局部**。
<span class="marginnote">LoRA 适配的直觉：<strong>大模型已经「什么都懂」，
新机器人只是「它的知识要在新接口上表达」</strong>——低秩矩阵 $\Delta W$ 就是「新接口的转换层」。
一个 OpenVLA 微调出多个「机器人专用版」，
每个 LoRA 才几 MB——这是开源 VLA 生态能活起来的工程基础。
</span>

## 4 评测：OpenVLA 能做什么

OpenVLA 在 LIBERO（第 23 章操作基准）等标准基准上评估：

- **微调后**：在未见任务上达到与 RT-2 相当甚至更好的水平（开源模型 + 针对性微调）；
- **零样本**：在跨具身场景有一定泛化，
但远不如微调；
- **对比 RT-2**：7B 参数 vs 55B，
性能有差距但在「可微调」面前可接受——**OpenVLA 卖的是「你能改它」**。

## 5 公式解析：LoRA 微调

$$
W_{eff} = W_0 + \Delta W = W_0 + BA, \qquad B\in\mathbb{R}^{d\times r},\; A\in\mathbb{R}^{r\times k},\; r \ll \min(d,k)
$$

- **第一步，看低秩分解**：$\Delta W$ 被分解成两个小矩阵 $B$、$A$ 的乘积——**秩 $r$ 很小（如 16），参数量从 $d\times k$ 降到 $r(d+k)$**
  - **第二步，看冻结与训练**：$W_0$ 冻结不动
  只训练 $B$、$A$——**训练参数量降低几个数量级**
  显存与算力要求骤降。
- **第三步，看为什么够用**：大模型的权重空间里，
「适配到新任务」只需要很小的扰动方向——**低秩近似足够**。
这也是「大模型微调」在参数效率上的理论依据。
- **第四步，看组合**：多个 LoRA 可以共存（多任务多适配器），
推理时按需挂载——**一个基座模型，多个专用版**。

## 6 辨析｜OpenVLA vs RT-2；开源 vs 闭源；7B vs 55B

**辨析｜易错点一：OpenVLA 的「小」是取舍不是缺陷。** RT-2 的 55B 有更强的世界知识，
但**不可微调、不可部署**；
OpenVLA 的 7B 在「微调后」能追平，
「零样本」不如大模型。
<span class="marginnote">选型判断：<strong>要闭箱即用、能力拉满 → 闭源大 VLA；
要改造成自己机器人 → 开源 VLA + LoRA</strong>。
OpenVLA 生态证明了后者在「真实落地」上反而更有生命力——能改的模型才有长期价值。
</span>

**辨析｜易错点二：OpenVLA 的泛化上限受「底座」限制。** 它的世界知识来自 7B 的 LLaMA + SigLIP，
不如 55B 的 PaLM-E——**「开源」与「规模」在 VLA 里仍是矛盾**。
改进方向（持续更新中）：更强的开源底座、更大的开源数据集、更好的动作表示（π0 的流匹配动作头）。

**再辨析｜微调 ≠ 万能**。
LoRA 适配新机器人快，
但**如果新机器人的「动作语义」与训练分布差异过大**（比如从桌面臂换到人形全身），
仅靠 LoRA 不够——需要更多数据、更大秩，
甚至重新预训练。**「微调的力度」要匹配「迁移的距离」**。

## 7 小结

- **OpenVLA** = SigLIP 视觉编码 + LLaMA-2 7B + 动作头，
基于 Prismatic VLM，
开源。
- **训练数据**：Open X-Embodiment 跨具身百万条示范，
学到任务-动作抽象。
- **LoRA 微调**：冻结基座、训练低秩适配，
参数量降到百万级，
单卡 24GB 可跑。
- **性能**：微调后追平 RT-2 级别，
零样本不如大模型——卖点是「可改」。
- 开源 vs 闭源、7B vs 55B 是取舍；
微调力度要匹配迁移距离。
