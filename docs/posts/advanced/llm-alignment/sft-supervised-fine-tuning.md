## 为什么从 SFT 开始

大模型的对齐，不是从强化学习开始的。它起步于最朴素的一步：**监督微调（Supervised Fine-Tuning, SFT）**——拿人类写好的「指令-回答」样本，继续训练预训练模型。理由很直接：预训练模型学的只是「下一个 token 的概率」，它天生会续写文本，却未必会回答问题。<span class="marginnote">把对话、指令遵循这类能力想成预训练模型的「沉睡技能」，SFT 的作用就是用一小批高质量演示把它们唤醒——这也是 Instruction Tuning（FLAN、T0 等）一脉相承的思路。</span>InstructGPT 的整条对齐流水线，正是从这一步出发的：先教形式，再教价值，最后教策略。今天我们先把第一块基石铺好。

## 1 预训练模型缺的是什么

预训练阶段，模型在海量互联网文本上做语言建模，学到的是「给定前文 $x_{<t}$，预测下一个 token $x_t$」的条件分布 $P(x_t \mid x_{<t})$。这赋予了模型惊人的续写能力，但「续写」不等于「照做」：

你问 GPT-3「用一句话解释黑洞」，它更可能继续写一篇散文或新闻稿，而不是给出一个规范的答案——因为它训练时从未见过「问题-答案」这种格式。<span class="marginnote">GPT-3 时代人们用 few-shot 提示硬凑出问答格式，效果不稳定、依赖提示词工程；SFT 的本质，是把「每次都要现场拼提示」变成「把格式直接写进权重里」。</span>
- 它没有「助手」的立场：不知道该多答还是少答、该拒绝还是顺从、该引用还是陈述。

再举一个更微妙的例子。给 GPT-3「帮我起草一封请假邮件」，它可能会写得洋洋洒洒却忘了最重要的信息——请假起止日期。不是它不懂邮件格式，而是它「续写」时没有「按用户目标组织内容」的意图。
这种「有文采、没目的」的输出，正是纯续写模型与助手的根本差距。一句话总结缺口：**预训练模型学的是「世界如何续写」，而助手需要的是「用户指令下如何得体地作答」。
** SFT 就是架在这两者之间的第一座桥。

## 2 SFT：在指令数据上继续训练

**核心概念：监督微调（SFT）**：在标注好的「指令-期望回答」对 $(x, y)$ 上，用与预训练相同（或相近）的语言建模目标继续训练模型。参数全量更新，但训练数据的分布从「互联网文本」换成「高质量人工演示」。

InstructGPT 的具体做法（Ouyang et al., 2022）：

- **数据规模**：**13,000 条**来自 OpenAI API 真实用户请求的 prompt，由约 **40 名签约标注员**（通过 Upwork 与 ScaleAI 雇佣）逐一撰写期望回答。
- **训练强度**：在演示数据上训练 **16 个 epoch**。
- **数据哲学**：prompt 取自已部署的真实产品，覆盖「生成」「问答」「头脑风暴」「改写」等真实任务，而非教科书式的人工拼凑。

这里有一个反直觉的点值得停下来看：预训练动辄消耗万亿级 token，而对齐只用了 **13k** 条演示。这说明 SFT 的价值不在「喂更多」，而在「喂得更对」——后面我们会在《偏好数据构建与标注》里进一步展开数据质量的问题。

为了理解「喂得更对」，可以对比指令微调史上两种数据来源：一是像 FLAN 那样用现成 NLP 任务模板批量拼出（数量大、质量参差），二是像 InstructGPT 这样让标注员**对着真实用户请求逐条手写**（数量小、但每一条都贴着「用户想要什么」）。
后者昂贵，却直接决定了模型「听人话」的程度——这是对齐数据区别于预训练数据的第一个分水岭。

## 3 公式解析：SFT 的语言建模损失

SFT 没有发明新的损失函数，它把预训练目标原封不动地搬到了新数据上：

$$
L_{SFT}(\theta) = -\frac{1}{|D|} \sum_{(x, y) \in D} \; \sum_{t=1}^{|y|} \log P_\theta(y_t \mid x, y_{<t})
$$

分三步拆解：

- **第一步，读懂数据对 $(x, y)$**：$x$ 是用户的指令（prompt），$y$ 是标注员手写的演示回答。数据集 $D$ 就是这些「指令-回答」对的集合。
- **第二步，看内层求和**：对回答 $y$ 的每一个 token $y_t$，在「给定指令 $x$ 与回答前 $t-1$ 个 token」的条件下最大化其概率的对数。注意求和只遍历 $y$（回答部分），不遍历 $x$（指令部分）——模型只需要为「它说的话」负责，不需要为「用户说了什么」付代价。
- **第三步，看外层求和**：对所有样本取平均，得到整个数据集的平均负对数似然，即交叉熵。

**重点是那句黑体字：SFT 没有发明新损失，它只是改了训练分布。** 同样的交叉熵，预训练喂的是网页，SFT 喂的是「问题-标准答案」。对齐的第一步不是新算法，而是新数据——这个洞察会贯穿整个专题。

顺带澄清一个常见的直觉误区：SFT 不是「让模型背诵答案」。损失只要求回答部分的条件概率高，模型真正学到的是「**给定什么样的指令，应该产出什么样的回答**」这个映射——是行为风格，不是答案库。

## 4 为什么只有 SFT 还不够

如果 SFT 这么简单有效，为什么对齐还要后面的奖励模型和强化学习？因为 SFT 有四个结构性短板：

- **只会模仿，不会判断**：SFT 学到的是「数据里出现过的回答长这样」，但它不知道「两条回答里哪条更好」——演示集里根本没有相对好坏的信息。
- **上限受限于演示分布**：模型被训练去复现标注员的写作风格。如果演示普遍冗长，模型就变啰嗦；如果演示普遍讨好用户，模型就学会谄媚（sycophancy）。
- **学不会稳定地拒绝**：有害请求在演示中只占极少数，模型「有样学样」，自然学不会说「不」。
- **能力天花板**：InstructGPT 的实验里，SFT 模型明显优于 GPT-3，但显著弱于后面的 RLHF 模型——单纯模仿，撑不起最后的对齐效果。

用 InstructGPT 的评测数据说得更具体：他们发现 1.3B 的 SFT 模型就能在「有用性」上明显打败 175B 的 GPT-3——这说明**演示数据本身就在教「什么是用户想要的」**；但同一份评测里，同等规模的 RLHF 模型又显著优于 SFT 模型——说明**光有正面例子，还缺「如何在两条都还行的回答里选更好的」**。
这个「从演示到偏好」的升级，正是第 3、4 篇的主题。

**辨析｜易错点：** 不要把「SFT」与「参数高效微调（LoRA、QLoRA）」混为一谈。SFT 描述的是「在指令数据上训练」这件事，LoRA 描述的是「只更新低秩适配器」这一种**实现手段**——两者正交：既可以用 LoRA 做 SFT，也可以全量微调。<span class="marginnote">LoRA 用极小的可训练参数就复现了全量微调的大部分效果，显存开销低一个量级，是开源社区做 SFT 的事实标准，细节见第三级《深度学习》的参数高效微调专题。</span>

## 5 数据质量优先于数量

既然损失没变，SFT 的全部成败都押在数据上：

- **少而精**：13k 演示对，量小但对「谁写的、怎么写」极其讲究。标注员被要求写「用户真正想要的回答」，而不是「教科书式完美的回答」——两者的差别正是「对齐」与「炫技」的差别。
- **贴近真实分布**：prompt 来自真实 API 请求，去重后按任务类型平衡采样，避免某一类任务垄断。
- **清洗环节不可省**：去除低质样本、重复样本，保证每一条演示都是可学的正面案例。
- **标注指引**：标注员人手一份书面指南，写明「什么算帮助用户」的判定标准，减少不同人之间的主观漂移。

这一节的结论可以被一句话记住：**在 SFT 里，10 万条抄来的数据不如 1 万条认真写的数据。** 当然后面我们还会看到，光有正面例子还不够——偏好数据正是为了补上「相对好坏」这一维。

## 6 SFT 的今天：指令微调已经平民化

InstructGPT 是 SFT 的「正规军」打法——真人员工、付费标注、封闭数据。今天的 SFT 已经换了天地：

- **开源数据集**：Alpaca 用 GPT-4 生成 52k 条指令数据、ShareGPT 收集真实用户对话、各种开源偏好数据附带演示子集——想复现「拿指令数据微调」已经不需要雇人写演示。
- **合成数据的兴起**：用大模型生成「指令-演示」对，再用规则过滤质量（第 3 篇会讲合成的边界）。合成数据把 SFT 的成本再降一个数量级，但也把「数据里的偏见」藏得更深。
- **SFT 依然是任何对齐流程的第一步**：无论后面接 PPO 还是 DPO、用人类反馈还是 AI 反馈，第一步几乎都是先做一次 SFT——因为它用最低的成本把模型「扶上马」，让后面的强化学习有个像样的起点。

变化的是数据来源，不变的是原理：**SFT 的价值依旧押在「演示质量」上**。合成数据便宜，但抄来的、生成式的「演示」是否真的教会模型「照做」，正是今天数据研究最活跃的课题之一——这为下一节讨论偏好数据（人类如何给出比演示更进一步的信息）铺好了路。

## 7 小结

- **SFT** 用「指令-演示」对 + 标准语言建模损失，把预训练模型掰成会照指令作答的模型。
- 损失形式与预训练一致，**核心是换数据**：从互联网文本换成 13k 条人工演示（InstructGPT）。
- 模型学到的是「指令→回答」的**行为映射**，不是「背诵答案库」。
- SFT 价值在于**数据质量优先于数量**；参数高效微调是手段，SFT 是任务。
- 短板：只会模仿、没有相对好坏的信息、学不会稳定拒绝——这些要靠后续的奖励模型与强化学习补齐。

在下一节，我们把镜头拉远，看 SFT 只是其中一环的三步流水线：**RLHF 框架流程**——人类反馈究竟如何进入训练的循环。
