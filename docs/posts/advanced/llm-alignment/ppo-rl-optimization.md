## 为什么用强化学习而不是继续微调

有了奖励模型，为什么不能直接把「RM 分数」加进 SFT 的损失里继续微调？因为 RM 分数只在**整段回答生成完之后**才能给出，而 SFT 是按 token 一步一练的监督信号——两者形态对不上。人类偏好是**序列级**的延迟奖励，只有强化学习天然擅长处理「整条轨迹完成后才来信号」的问题。<span class="marginnote">这也是 RL 与监督学习的分水岭：监督学习需要逐 token 的即时监督，RL 只需要整段轨迹结束后的一个奖励信号。语言生成恰恰是后者。</span>本节讲 PPO 在语言模型上是怎么落地的，以及 InstructGPT 做了哪些工程化改造。

## 1 把「生成」看成「决策」

强化学习的语言模型视角，只需要做一个翻译：

| 强化学习术语 | 语言生成里的对应 |
| --- | --- |
| 环境（environment） | 上下文 + 已生成的文本 |
| 状态（state $s_t$） | 指令 $x$ 与已生成的前缀 $y_{<t}$ |
| 动作（action $a_t$） | 下一个 token $y_t$ |
| 策略（policy $\pi_\theta$） | 语言模型本身 $\pi_\theta(y_t \mid x, y_{<t})$ |
| 奖励（reward） | RM 分数 $r_\phi(x, y)$——只在整段 $y$ 生成完才给出 |

于是「生成一段回答」=「走一条长度为 $|y|$ 的决策轨迹」，PPO 负责在每条轨迹的 RM 分数引导下更新策略。所有 token 共用同一个延迟奖励，这正是 RL 擅长的场景。

这套翻译里最容易忽略的一个细节是「谁对谁负责」：一条轨迹里有 $|y|$ 个 token，但只有一个总分数，**无法说清「是哪几个 token 立功、哪几个拖后腿」**。PPO 的做法是把总分数通过值函数分摊回每一步——这正是下面 GAE（优势估计）要解决的信用分配（credit assignment）问题。

## 2 从 REINFORCE 到 PPO：为什么需要裁剪

PPO 不是凭空出现的，它是强化学习 30 年演进的结果。理清这条线，你才能真正理解 PPO 每个零件为什么存在：

- **REINFORCE**：最朴素的策略梯度方法——「轨迹总收益为正就提概率，为负就降概率」。但它方差极大：同一条指令，随机生成两段回答，分数可能一个 3 分一个 -1 分，梯度方向全被噪声淹没。
- **基线（baseline）**：给收益减去一个「均值」$V(s_t)$，让梯度只看「超出预期多少」，方差大幅下降——值函数在这里第一次登场。
- **优势（advantage）**：把「超预期」写成 $\hat{A}_t = \text{实际收益} - \text{预期收益}$，这是后续所有稳定策略梯度算法的核心对象。
- **PPO 的裁剪**：最后再补上「更新步幅限制」。REINFORCE 类方法最怕一步跨太大导致策略崩掉；裁剪把每次更新压在安全范围内。

记住这条线，PPO 的每个术语（值函数、优势、裁剪）都有明确的历史分工——它不是一堆随机超参数的堆砌，而是针对「方差大、易崩」这两个老毛病逐层打补丁的结果。

## 3 PPO：为什么它能稳定更新

PPO（Proximal Policy Optimization, Schulman et al., 2017）是 RLHF 事实上的标准算法。它要解决的核心问题是：**策略在更新，训练数据却来自旧策略的采样，怎么用旧数据安全地更新新策略？**

答案有两个支柱：

- **重要性采样（importance sampling）**：用新旧策略的概率比 $r_t(\theta)$ 给旧轨迹的收益重新加权，让旧数据「折算」成新策略视角下的信号。
- **裁剪（clipping）**：当 $r_t(\theta)$ 偏离 1 太多（新旧策略差异过大）时，直接把梯度贡献截断——防止一次更新步子太大、策略崩溃。

这两条合起来，让 PPO 在「大步快走」与「不摔跤」之间找到了一个工程上极其稳的平衡点。正因为它稳，它才从众多 RL 算法（TRPO、A2C、DDPG……）中胜出，成为 RLHF 的默认选项——对齐场景里模型巨大、训练昂贵，没人敢用一个动不动就崩的算法。

## 4 公式解析：PPO 的裁剪目标

PPO 的每一步更新，最大化的是下面这个裁剪过的代理目标：

$$
L^{CLIP}(\theta) = \mathbb{E}_t \left[ \min\Big( r_t(\theta)\, \hat{A}_t,\; \operatorname{clip}(r_t(\theta),\, 1-\epsilon,\, 1+\epsilon)\, \hat{A}_t \Big) \right]
$$

其中概率比 $r_t(\theta) = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{old}}(a_t \mid s_t)}$。

- **第一步，读懂概率比 $r_t(\theta)$**：同一位置 $t$ 上，新策略给这个 token 的概率与旧策略概率之比。等于 1 表示没变，大于 1 表示新策略更可能选这个 token。
- **第二步，看优势 $\hat{A}_t$**：这个 token 带来的「好处」——在语言模型里，$\hat{A}_t$ 常用广义优势估计（GAE）从整段奖励倒推：$\hat{A}_t = \delta_t + \gamma\lambda\,\delta_{t+1} + \cdots$，其中 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$。
符号决定方向：好处为正就提升该 token 概率，为负就降低。
- **第三步，看 clip 与 min 的组合**：把 $r_t(\theta)$ 夹在 $[1-\epsilon, 1+\epsilon]$（通常 $\epsilon = 0.2$），再与未裁剪项取 min。
**当新策略想比旧策略激进太多时，min 会把收益砍掉**——即「允许把好 token 的概率涨上去，但涨到某个程度就不再奖励」。这个非对称设计是 PPO 稳定性的灵魂。

用一组数字演示这个非对称性。设 $\hat{A}_t = +1$（好动作），$\epsilon = 0.2$：若 $r_t(\theta) = 1.5$（新策略想把这个动作的概率涨 50%），clip 把 $r_t$ 压回 1.2，于是 min(1.5, 1.2) = 1.2——收益被打了八折；若 $r_t(\theta) = 0.8$（新策略略微降低了它），min(0.8, 0.8) = 0.8——没被裁剪。
**这个「奖而不纵」的设计，让 PPO 既学得快又不容易翻车。**

一句话记忆：**PPO = 让「被证明好的动作」概率温和上涨、让「坏动作」概率温和下跌，但禁止任何一步涨跌过猛。**

## 5 InstructGPT 的工程化改造

把通用 PPO 搬到 RLHF 上，InstructGPT 做了三处关键改动：

- **KL 惩罚进奖励**：每个回答的最终奖励是 $r_\phi(x,y) - \beta \log \frac{\pi^{RL}_\phi(y \mid x)}{\pi^{SFT}(y \mid x)}$。这个 token 级的 KL 惩罚对应总目标里的 $\beta D_{KL}$，防止策略离 SFT 模型太远、语言崩坏。<span class="marginnote">注意这里用 KL 惩罚替代了原版 PPO 的信任域约束——语言生成不像连续控制那样需要严格信任域，KL 惩罚更简单且效果相当。</span>
**值函数初始化自 RM**：PPO 需要值函数 $V(s_t)$ 估计未来收益（算 $\delta_t$ 用）。InstructGPT 直接用 RM 的标量头做值函数初始化——因为 RM 已经「会打分」，比随机初始化收敛快得多。
- **预训练梯度混合**：总目标里额外加一项 $\gamma \cdot \mathbb{E}_{x \sim D_{pretrain}}[\log \pi^{RL}_\phi(x)]$，让模型不忘本（保持一般能力）。175B 模型上取 $\gamma = 1.32$——相当于每轮 RLHF 更新都附带约 32% 大小的预训练梯度。<span class="marginnote">这条设计后来被广泛沿用，因为纯 RLHF 会让模型在某些通用任务上退化——也就是第 9 篇《对齐税与平衡》要讲的「税」的一部分。</span>

做 RLHF 的人还都知道一个「隐形第四处改造」：**奖励与 KL 都要做归一化**。RM 分数分布随训练漂移，KL 惩罚的量级也在变，若不把两者标准化到同一尺度，$\beta$ 的实际效果会悄悄变化——这也是第 4 篇「分数漂移」坑在 PPO 阶段的延续。

**辨析｜易错点：** PPO 更新的是**策略的 token 概率**，不是 RM 本身。RM 是冻结的、只读的裁判；训练期间绝不应让 RM 参与梯度更新，否则评委和考生一起变，奖励黑客会失去参照系。

## 6 工程调试：RLHF 训练现场的三道坎

理论说完，说点实战——跑 RLHF 的人几乎都会碰到这三道坎：

- **KL 尖峰（KL spike）**：训练中某一步策略突然剧烈漂移，KL 惩罚瞬间暴涨。常见原因是某条样本的隐状态异常（比如生成了一个超长 token 序列）。对策是给 KL 惩罚做 clip、限制单步更新幅度，必要时回滚权重到上一检查点。
- **浮点溢出**：策略在低精度（fp16/bf16）下计算 $\log \pi_\theta(y \mid x)$ 时，概率极小可能导致对数趋于负无穷。工程上普遍做法是给概率加一个下界（如 $1e{-8}$），或对 log 概率做 clamp。
- **奖励与 KL 的尺度失衡**：RM 分数分布随训练漂移、KL 惩罚量级也在变，两者不归一化的话，$\beta$ 的实际效果会「悄悄漂移」。第 4 篇的「分数归一化」在这里就是刚需。

这三道坎共同说明一件事：**PPO 在数学上简单，在工程上「脆」**。这也是为什么 DPO 能迅速流行——它把「RL 的工程脆性」整个移除了。但如果你需要在训练中加入「探索」「多轮交互」「非 BT 偏好」等能力，PPO 依然无可替代。工程上选谁，取决于你需要哪种自由度。

## 7 小结

- 语言生成被翻译成**序列决策问题**：状态是已生成前缀，动作是下一个 token，奖励在整段生成后给出。
- PPO 是策略梯度 30 年演进的结果：基线降低方差、GAE 做信用分配、裁剪防崩——每个零件都有历史分工。
- PPO 的稳定秘诀是**重要性采样 + 非对称裁剪**：好动作温和涨价、坏动作温和降价，禁止猛冲。
- InstructGPT 三处改造：KL 惩罚进奖励、值函数初始化自 RM、预训练梯度混合（$\gamma=1.32$）；另有奖励/KL 归一化这条隐形改造。
- RM 全程冻结，只当评委；梯度只更新策略。

在下一节，我们将看到 RLHF 被「化简」的一种激进方案——它证明无需 RM、无需 PPO，用一份偏好数据就能直接优化策略：**DPO 直接偏好优化**。
