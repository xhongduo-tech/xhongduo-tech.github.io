## 为什么安全是对齐的另一半

对齐如果只追求「顺从」，会得到一台**什么都肯做的机器**——这比什么都不肯做更危险。因此对齐有两翼：**有用（helpful）**与**无害（harmless）**，两者要同时落地。而「无害」比「有用」难检验得多——攻击者总能找到你没训练过的刁钻问法。<span class="marginnote">「无害」与「有用」的差别可以浓缩成一句：有用是「该做的做得好」，无害是「不该做的不做」——后者没有穷尽的测试集，只能靠不断对抗逼近。</span>本节讲 InstructGPT 如何评估安全，以及「红队」——主动攻击自己模型的对抗训练法——如何成为安全对齐的标配。

## 1 安全对齐评估什么

InstructGPT 的安全评估覆盖三个可量化的维度：

**帮助度（helpfulness）**：标签员在真实任务上的偏好对比，RLHF 模型显著优于 GPT-3。<span class="marginnote">帮助度不是玄学，它有一套可复现的评测流程：抽一组真实 API 请求，让标签员盲比两个模型的回答谁更有用。</span>
- **真实性（truthfulness）**：在 TruthfulQA 基准上，RLHF 模型的真实回答占比显著更高——模型不再「一本正经地编」。
- **毒性（toxicity）**：在 RealToxicityPrompts 基准上，RLHF 模型的毒性输出显著更少。

三个维度的共同结论是：**对齐不仅让模型更听话，还让它在客观指标上更安全**。但这些基准测的是「平均安全」，测不出「被针对时的安全」——这正是红队要补的。

这里有个值得强调的细节：安全性评估不只是「跑一遍基准拿个分」，还包括**对失败样本的定性分析**。同样是有害输出，模型是「无意中说漏了」，还是「被精心诱导破防」，处理方式完全不同——前者靠补数据，后者靠对抗训练。所以安全评测总是「定量 + 定性」两条腿走路。

## 2 红队：对抗式地攻击自己的模型

**核心概念：红队（red teaming）**：招募专门的攻击者（可以是外包标注员，也可以是自动化系统），**有组织地尝试诱导模型输出有害内容**，把成功的攻击样本收集起来，用于发现弱点、补充训练数据。

Anthropic 的红队研究报告（Ganguli et al., 2022）贡献了几个至今影响深远的事实：

- **规模化**：用众包平台发起红队，规模可以做很大（数千攻击者、数万攻击样本），成本可控。
- **攻击有效性随模型规模上升**：模型越强，红队攻击越难成功，但红队样本的可迁移性也越高——一个越狱方法往往能打穿一系列模型。
- **按危害类别组织**：把攻击样本按「暴力、欺诈、性相关、危险建议……」分类，训练时按类别平衡，避免只修好了某一类漏洞。

红队的产出不是「报告」而是**数据**：每一次成功攻击都变成一条「有害指令 + 成功诱导」的样本，被喂回偏好数据（第 3 篇）、参与 RM 训练（第 4 篇）——于是红队与对齐流水线闭环了。

## 3 从攻击到修复：红队样本如何进入训练

把红队和前面的流水线接起来，一次完整的「修复循环」长这样：

1. 红队成员发现一个攻击手段，例如「用角色扮演伪装身份，诱导模型描述犯罪过程」。
2. 该手段产生了若干成功攻击样本——**这些样本就是宝贵的偏好数据**。
3. 把它们整理成「有害请求 + 正确拒绝式回答」的偏好对，加入数据集。
4. 用更新后的数据重训 RM（第 4 篇），再跑 RLHF 或 DPO（第 6、7 篇）。
5. 发布新模型，开始下一轮红队。

注意这个循环的关键点：**红队不是「测试报告」，而是「数据生产车间」**。一次成功攻击，不仅暴露了一个漏洞，还为修复它提供了训练数据。这也是为什么红队成本能被接受的底层逻辑——每一分攻击投入，都转化成了修复素材。

## 4 攻击与防御的类型学

红队攻击手段五花八门，但可以归纳成几类，每类都有对应的防御思路：

| 攻击类型 | 典型手段 | 防御思路 |
| --- | --- | --- |
| 越狱（jailbreak） | 「DAN 模式」「忽略此前指令」 | 对抗训练 + 红队数据回灌 + 拒绝提示词强化 |
| 角色扮演 / 情景伪装 | 「假装你是法律顾问描述犯罪细节」 | 无害度偏好数据覆盖此类套路 |
| 间接提示注入 | 网页/文档里藏指令，诱导模型执行 | 输入与指令来源分离、权限控制 |
| 数据投毒 | 训练数据里混入有害样本 | 数据清洗、出处追踪、红队测试 |
| 渐进诱导 | 把有害请求拆成多步无害请求 | 长上下文监测、逐步意图识别 |

这张表的中心思想只有一句：**防御没有银弹，只能靠「攻击-修复-再攻击」的循环逼近**。这也是为什么「红队」不是一次性的活动，而是对齐流水线里一个常驻的环节。特别要警惕「渐进诱导」这一类——它利用的正是模型的「帮助度」：每个单步请求都无害，合起来却完成了有害目标。这类攻击在长上下文模型出现后显著增多，是当前红队研究的热点。

## 5 评测基准的演进：安全不可一测了之

红队之外，安全对齐还需要公开的评测基准来横向比较。从早期到现在，基准经历了几轮演进：

- **静态毒性/真实性基准**（RealToxicityPrompts、TruthfulQA）：测「平均安全」，成本低，但容易过拟合——模型刷分后就不再有区分度。
- **HHH 类综合基准**（Helpful-Honest-Harmless）：把三维目标放进一组精心设计的提示里，测的是「平衡」，更贴近真实产品。
- **对抗性基准**（AdvBench、各种越狱套件）：直接把红队攻击公开成基准，测「被针对时的安全」，与红队数据互为镜像。

基准演进的方向很明确：**从「测平均」走向「测最坏」**。因为安全对齐的对象从来不是「大多数情况」，而是「被精心针对的那一次」。

**辨析｜易错点：** 安全对齐追求的不是「零有害输出」，而是**可控的失败模式**。过度追求零有害会让模型变成「什么都不敢答」的保险箱——这正是第 9 篇《对齐税与平衡》里帮助度与无害度博弈的落点。安全工程师的目标是让模型的失败**可预测、可修正**，而不是让模型不失败。

## 6 谁定义「有害」：安全对齐的伦理与限度

安全对齐的技术之外，还有一个绕不开的问题：**「无害」的标准由谁、按什么文化来定？** 这个问题的答案，直接决定红队往哪里攻、宪法怎么写、评测基准怎么设计：

- **标准是文化的**：同一句「这药能不能治病」，在严格监管地区与在医疗资源匮乏地区，模型的回答边界完全不同。安全不是绝对的，是「对谁、在何种语境下」的相对判断。
- **审查偏见的风险**：过度训练「无害」，模型可能把「批评政策」「讨论敏感话题」也一并拒绝——安全变成审查，这是帮助度与无害度博弈的另一个侧面（第 9 篇）。
- **工程上的应对**：把「安全标准」当作一个**显式、可配置的参数**，而不是藏在数据里的隐式偏好——宪法 AI（第 8 篇）的明文原则正是这种思路；产品侧则通过系统提示词调节安全边界。

一句话总结安全对齐的限度：**技术能做的，是让模型的失败变得可控、可审计；技术不能代替的，是「什么算有害」这件事本身的公共讨论。** 对齐工程师的职责，是保证无论选择哪种安全标准，模型都能忠实地执行它、并且能清楚地报告自己拒绝了什么。

## 7 小结

- 对齐 = **有用 + 无害**两翼；无害无法穷尽测试，只能靠对抗逼近。
- 安全评估三维度：帮助度、真实性、毒性（TruthfulQA、RealToxicityPrompts 等基准）；定量 + 定性两条腿。
- **红队** = 有组织地攻击自己的模型，成功攻击样本回灌训练数据，形成闭环；红队是「数据生产车间」而非「测试报告」。
- 攻击类型学：越狱、角色伪装、提示注入、数据投毒、渐进诱导——防御靠「攻击-修复」循环而非银弹。
- 评测基准从「测平均」走向「测最坏」；目标不是「零有害」，而是**可控、可预测、可修正**的失败模式。
