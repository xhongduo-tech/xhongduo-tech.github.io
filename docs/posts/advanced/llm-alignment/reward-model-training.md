## 为什么需要专门的奖励模型

上一节我们造好了偏好数据：一堆 $(x, y_w, y_l)$ 三元组。但数据本身不会动——它只是一堆「谁赢谁输」的记录。要让这些记录驱动训练，需要一个**可微分的函数**：输入指令 $x$ 和回答 $y$，输出一个标量分数，分数越高代表「人类越可能偏好这个回答」。这就是**奖励模型（Reward Model, RM）**。<span class="marginnote">奖励模型把「人类判断」冻结成一个参数函数，让强化学习循环可以随时调用——它是 RLHF 框架里连接「人类」与「优化器」的翻译器。</span>本节讲清楚三件事：RM 用什么架构、用什么损失、训练时容易踩哪些坑。

## 1 架构：从 SFT 换头

奖励模型的架构是「拿来主义」的：

**核心概念：奖励模型（RM）**：以一个预训练/SFT 语言模型为骨架，把它的最后一个 unembedding 层（把隐状态映射回词表的那一层）摘掉，换成一个标量输出头，输出一个实数 $r_\phi(x, y) \in \mathbb{R}$。

为什么这么做？

- **复用语言知识**：判断「这个回答好不好」，首先要「读懂」这个回答——阅读理解能力来自预训练，不需要重新学。
- **参数规模即评委水平**：InstructGPT 的 RM 从 SFT 模型初始化，论文里直接试验不同规模（1.3B / 6B / 175B），结论是**越大越好**——评委也需要「学识」。
- **与策略共用词表无关**：RM 不生成文本，只打分，因此它和策略模型可以是同一个骨架、两个不同的头。

直觉：**RM 是一个被改装成「裁判」的语言模型——它不再续写，而是报告「这段文本值几分」。** 用一个类比加深印象：同一个法学生（预训练骨架），一个去当律师（策略模型，负责写诉状），一个去当法官（RM，负责判案子）——两者共享法学功底，但用途截然不同。

## 2 公式解析：成对排序损失

奖励模型的训练目标，是把偏好三元组里的次序关系压进分数差里。InstructGPT 用的损失是（对每条 prompt 的 $K$ 个回答，遍历所有 $\binom{K}{2}$ 对取平均）：

$$
L_{RM}(\phi) = -\frac{1}{\binom{K}{2}} \;
\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\big( r_\phi(x, y_w) - r_\phi(x, y_l) \big) \right]
$$

- **第一步，看内层**：$r_\phi(x, y_w) - r_\phi(x, y_l)$ 是「胜者分数减败者分数」。我们希望这个差越大越好。
- **第二步，Sigmoid 与 log**：$\sigma(\Delta) = \frac{1}{1 + e^{-\Delta}}$ 把任意实数差压到 $(0,1)$，解释为「模型认为 $y_w$ 优于 $y_l$ 的概率」；再取 $\log$ 转成负对数似然，最小化它。
- **第三步，外层平均**：对 prompt 的 $K$ 个回答形成的所有有序对取平均。$\binom{K}{2}$ 是上一节的组合数——排序标注拆出的每一对都贡献一个监督信号。
- **第四步，与 Bradley–Terry 的关系**：这正是 Bradley–Terry 模型的极大似然估计：设胜率 $p(y_w \succ y_l) = \sigma(r_\phi(x,y_w) - r_\phi(x,y_l))$，最大化全体对的对数似然，等价于最小化上面的 $L_{RM}$。

用一组具体数字走一遍能加深直觉。假设某对样本里，RM 给胜者打了 2 分、给败者打了 0.5 分，那么 $\Delta = 1.5$，$\sigma(1.5) \approx 0.82$，这对样本贡献的损失是 $-\log 0.82 \approx 0.20$。
如果 RM 打反了（胜者 0.5、败者 2），则 $\Delta = -1.5$，$\sigma(-1.5) \approx 0.18$，损失飙到 $-\log 0.18 \approx 1.71$——**判反一次的惩罚是判对的 8 倍多**。
成对损失的「拉开差距」本性，就是靠这种非对称压强实现的。

一句话记忆：**奖励模型训练 = 用「谁赢谁输」的监督信号，拟合一个能拉开胜败分数差的打分器。**

## 3 为什么「成对」比「绝对打分」更稳

上一节从标注一致性角度论证了「两两比较」更可靠，这里从训练角度再补一刀：

- 成对损失只关心**相对次序**，对分数的绝对尺度不敏感——RM 输出 0.5 还是 5 都没关系，只要胜者分数更高。这天然容忍标注噪声中的「尺度漂移」。
- 单点回归（把「7 分」当监督目标）会让模型去拟合不一致的绝对分，等于把标注员的尺度差异当成真值去学，浪费容量、引入偏差。

因此学界几乎一致采用成对损失。<span class="marginnote">这也解释了一个看似奇怪的现象：RM 输出的分数绝对值没有含义，只有「同一 prompt 下不同回答之间的相对大小」才有意义——所以 RM 分数不能跨 prompt 比较。</span>「RM 分数不能跨 prompt 比较」这条规律，做对齐实验时几乎天天踩到：一条回答在 prompt A 下得 1 分、在 prompt B 下得 4 分，并不代表它在 B 下「更好」，只是两个 prompt 的分数标定不同。

## 4 RM 如何被验收：评委也需要考试

训练完 RM，怎么知道这个评委合不合格？工程上有一套独立的验收流程：

**留出集准确率**：在与训练集严格隔离的偏好样本上，统计 RM「判对胜负」的准确率。InstructGPT 在验证集上报告了接近甚至超过 70% 的偏好判断准确率——记住这个量级，一个准确率不到 60% 的 RM 基本等于随机猜测。<span class="marginnote">70% 这个数字在很长一段时间里成了 RLHF 的「及格线」：超过它，RM 才有资格当评委；低于它，先回去加数据。</span>
- **校准检查**：RM 判对的概率是否与其置信度相符？一个自信却总判错的 RM，比不自信的 RM 更危险（它会给强化学习提供坚定但错误的信号）。
- **分布外抽查**：拿训练时没见过的任务类型、回答风格让 RM 打分，看是否明显失灵——这是 reward hacking 的预警。

**把验收当成训练的一部分**，而不是事后检查：RLHF 流水线里，RM 的每一点偏差都可能被下游放大，评委「考试」的意义远超一般模型的评测。

## 5 训练中的四个常见坑

- **过拟合偏好数据**：130 万对听起来很多，但共享同一批 prompt，真实有效信息密度有限。RM 在训练集上可轻松把准确率推到 90%+，却在验证集上停滞——**必须留出与训练集严格隔离的验证 prompt**（InstructGPT 留了 16k 条做验证）。
- **偏好排序的「洗牌」**：同一 prompt 的 $\binom{K}{2}$ 对共享样本，直接打乱喂会引入冗余；应按 prompt 分组后组内批处理。
- **分数分布漂移**：训练初期 RM 分数集中在 0 附近，随训练方差变大。若不做分数归一化（减去均值、除以标准差），下游 PPO 的 KL 惩罚系数 $\beta$ 的语义会随训练漂移。
- **代理偏置预警**：RM 是对真人类判断的**近似**。近似误差一旦被策略「钻空子」放大，就会出现奖励黑客（reward hacking）——这正是下一篇的主题，也是为什么训练 RM 时必须同步监控它在分布外输入上的表现。

**辨析｜易错点：** 很多人误以为「RM 分数越高，回答越好」。严格的说法是：**RM 分数只在训练它的偏好分布内有相对意义**。给 RM 看一条它从未见过的任务、或一种全新的回答风格，它的打分可能完全不可靠——把 RM 当成绝对真理，是过度优化的起点。

## 6 RM 的开源生态与「评委外包」

工程上未必每次都自己训 RM。随着领域成熟，出现了两条替代路径，值得了解：

- **开源的预训练 RM**：像 OpenAssistant 等项目公开了自己的奖励模型权重，可以直接下载当评委，省去数据与训练成本；对应的评测基准 RewardBench 也在推进「哪家 RM 更可靠」的横向比较。
- **LLM-as-a-judge（用大模型当评委）**：不再训练专用 RM，而是直接用 GPT-4 级别的大模型，读偏好对、输出「哪条更好」的判断。这条路线把「训练评委」换成了「调用评委」，成本极低、可复现性好。

但「评委外包」都有同一个前提：**你相信外包的评委在你的数据分布上也可靠**。RewardBench 的测评反复提醒我们，一个在通用偏好上很强的 RM，换了任务域可能判错一半。
所以成熟的团队往往两手抓：通用场景用现成评委，核心场景仍然自己训 RM 并做验收（第 4 节）。这再次印证了本专题的主线——**评价器的质量，永远是对齐的天花板。
**

## 7 小结

- RM 架构 = 语言模型骨架 + 标量打分头：**把「阅读」能力复用，新增「评价」能力**。
- 训练损失是成对排序损失（Bradley–Terry 极大似然）：拉开 $r_\phi(x,y_w) - r_\phi(x,y_l)$；判反一次的代价远大于判对一次。
- 成对损失天然容忍标注尺度漂移，**比绝对打分稳定**；RM 分数只在同 prompt 内有相对意义。
- RM 需要独立验收：留出集准确率（~70% 量级）、校准、分布外抽查。
- 四个坑：过拟合、分组洗牌、分数漂移、代理偏置——最后一个直接引出奖励黑客。
