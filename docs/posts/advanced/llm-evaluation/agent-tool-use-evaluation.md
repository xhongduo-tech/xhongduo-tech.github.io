## 为什么评测要走进「环境」

前九篇的模型都在「答题」：读 prompt，给输出。但 2023 年起，大模型开始「做事」——**调用搜索 API、写代码执行、操纵网页、规划多步行动**。这类「智能体（agent）+ 工具（tool）」的使用方式，让评测发生了质变：**模型不再面对一道题，而是面对一个不断变化的环境，要做出一连串决策。**

这一范式的里程碑是 **ReAct**（Yao 等人，2023）：让模型在「思考（Thought）— 行动（Action）— 观察（Observation）」之间循环，交替进行推理与工具调用。<span class="marginnote">Yao, S. 等，「ReAct: Synergizing Reasoning and Acting in Language Models」，ICLR 2023。ReAct 论文本身是方法贡献，但它同时确立了「如何在环境里评测模型」的协议，这正是本篇关注的视角。</span>评测也随之从「判答案」变成「判轨迹」。

## 1 智能体评测的三个新维度

智能体评测与静态问答有本质差别，至少引入三个新维度：

**交互性**：输入不是一次给完的。模型调用工具 → 环境返回观察 → 模型再决策，如此循环。评测必须**逐轮记录并判分**，而不是「对一道题打一个分」。

**环境性**：模型的对手是真实（或仿真）的环境——网页、操作系统、数据库、游戏。环境可能**部分可观察**、有状态、甚至随机，模型必须在不完全信息下决策。

**目标性**：智能体评测以「**任务完成度**」为最终判据。任务（task）被拆成有序的子目标（subgoal），全部按序完成才算成功——这与 MMLU 的「选对一项」截然不同。

**重点：智能体评测的「单位」从「答案」变成了「轨迹（trajectory）」**——即从任务开始到结束的全部「动作-观察」序列。评判一条轨迹好不好，要看结果、看过程、还要看代价。

## 2 两层指标：结果层与过程层

评测一条轨迹，至少要回答两个层次的问题：

**结果层（outcome）——任务完成了吗？**
**任务成功率（success rate）**：完成全部子目标的任务占比；
- **平均完成子目标数（average success count）**：对「半途而废」的任务，量化完成到第几步。

**过程层（process）——怎么完成的？**
- **步数效率**：平均几步完成任务，越少越好；
- **工具调用正确率**：调用了多少次不存在的工具、传错了多少次参数；
- **成本**：调用了多少 token、多少次外部 API——效率是智能体最现实的成本。

两者的关系是评测设计的关键：**结果层回答「能不能做成」，过程层回答「是不是用合理的方式做成的」**。一个模型可能靠「穷举乱调 API」做成任务——结果层满分、过程层不及格。只报结果层，会奖励浪费。

## 3 评测环境：从仿真到真实

环境是智能体评测的「考卷」，常见类型如下：

| 环境 | 形态 | 代表任务 |
| --- | --- | --- |
| ALFWorld | 文本化的家居交互 | 「把杯子放进水槽并冲洗」 |
| WebShop | 仿真购物网站（118 万商品） | 「按条件挑选并下单」 |
| HotpotQA/FEVER | 带检索工具的问答 | 「联网查证后回答」 |
| AgentBench | 8 个环境（OS/DB/网页/卡牌等） | 「用命令行完成任务」 |
| τ-bench | 真实零售 API | 「调用后端接口完成退换货」 |

**辨析｜易错点：** 仿真环境与真实环境对「成功」的定义常常不同。仿真里「调用函数成功」就加分，真实里「函数返回的数据对不对、业务是否合法」才算数——**把仿真结果直接当真实能力，是智能体评测最常见的过度解读**。<span class="marginnote">τ-bench 等真实 API 环境正是冲着这一点而来：用真实可调用的后端服务评测，让「成功」必须是端到端的业务成功。</span>

## 4 公式解析：为什么多步任务这么难

任务成功率是智能体评测的核心读数：

$$
\mathrm{SR} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}\!\left[\text{任务 } i \text{ 的全部子目标按序完成}\right]
$$

拆成三步理解：

- **第一步，$\mathbb{1}[\cdot]$ 是「全有或全无」**：只有全部子目标完成才算 1，完成一半也是 0——这是它与 MMLU 准确率的根本差别。
- **第二步，取平均得成功率**：$N$ 个任务里「做成的比例」。
- **第三步，对照单步正确率理解「为什么难」**：若每个决策步骤的正确率是 $p$，任务共 $k$ 步且近似独立，则整体成功率的期望约是 $p^k$。当 $p=0.9, k=10$ 时，$p^{k} \approx 0.35$——**单步再准，步骤一多，成功率就被「连乘」拖垮**。这正是智能体评测与静态问答最大的鸿沟：它把「模型每一步的水平」翻译成「多步累积的可靠度」。

这也是为什么智能体评测报告里，**单步工具调用正确率与任务成功率必须并列**：前者高、后者低，说明模型单点强但链条脆；两者都高，才谈得上「可信的智能体」。

## 5 局限与演进

智能体评测仍在早期，问题成堆：**环境复现难**（仿真环境版本、随机种子、工具接口都会影响分数）、**污染随环境更新而反复出现**、**真实环境评测贵且慢**、**不同论文的「成功」定义不统一**导致数字不可比。演进方向则很清晰：更真实的工具接口、更严格的子目标定义、以及把「成本/效率」纳入正式指标——**智能体评测正在从「能不能做成」走向「能不能又好又省地做成」。**

## 6 小结

- 智能体评测的单位从**答案**变为**轨迹**，新增**交互性、环境性、目标性**三个维度。
- 指标分**结果层**（成功率、完成子目标数）与**过程层**（步数、工具正确率、成本）。
- **ReAct** 确立了「思考—行动—观察」循环与配套的评测协议。
- 成功率是「全有或全无」的 $\mathbb{1}[\cdot]$，被多步连乘效应拖垮——单步准 ≠ 任务成。
- 仿真 vs 真实的「成功」定义常不一致；环境复现与效率指标是下一步方向。

在下一节，我们把评测的目光从「会做什么」转向「会不会伤人」——**安全与偏见评估**。
