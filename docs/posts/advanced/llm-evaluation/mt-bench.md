## 为什么固定题库测不出「好用」

MMLU 让模型做单选题，HELM 让它做基准任务，BigBench 让它应付 204 种考题——它们都是「一次提问、一次作答」的**单轮考试**。可是真实世界里，用户是在和模型**对话**：追问、纠正、反问、让它在上一句的基础上继续。一个单轮满分、一对话就露怯的模型，在现实里依然是「不好用」的模型。

2023 年，郑连民（Lianmin Zheng）等人提出了**人类对齐评估**的两件套：**MT-Bench**（多轮对话基准）与 **Chatbot Arena**（众包竞技场）。它们的共同目标是把评测从「考卷」推向「交互」，从「对不对」推向「好不好」。<span class="marginnote">「对齐（alignment）」在这里指模型的输出符合人类使用者的偏好与期望。它的评测困难在于：好答案没有唯一标准，最终裁决者只能是人类——或退而求其次的「人类偏好代理」，这正是下一篇的主角。</span>

## 1 MT-Bench：把「对话」变成可测的考卷

MT-Bench（Multi-Turn Benchmark）的核心设计是**两轮对话**：每条题目都先抛出一个问题，等模型答完，再追问一个**紧跟上一轮的 follow-up**。

这个设计直指单轮基准的盲区：

**第二轮测「延续能力」**：模型能否基于自己刚给出的答案继续，而不是把对话当独立问题重新作答；
- **第二轮测「纠错能力」**：例如第一问让模型给出行车建议，第二问立刻指出「这违反交通规则，重新回答」——测的是模型能否接受反馈并修正自己。

MT-Bench 共 80 道题，横跨 8 个类别，每类 10 题：

| 类别 | 示例 |
| --- | --- |
| 写作 Writing | 写一封辞职信并润色 |
| 角色扮演 Roleplay | 扮演历史人物对话 |
| 抽取 Extraction | 从长文本提取关键信息 |
| 推理 Reasoning | 逻辑谜题 |
| 数学 Math | 应用题 |
| 代码 Coding | 写一段函数并解释 |
| 自然科学 STEM | 科学解释 |
| 人文 Humanities | 文学、哲学讨论 |

**重点：80 道题不是用来「赌对错」的，而是用来「催生差距」的。** 题目刻意选择让顶尖模型也容易答偏的开放问题，这样裁判才能从 1–10 分里拉开层次。

## 2 谁给对话打分：参考答案制

MT-Bench 的回答按 1–10 打分，但**不是直接让裁判裸判**，而是采用**参考式（reference-based）评测**：每题都附一份由 GPT-4 精心写就的**标准参考答案**，裁判把模型回答与参考答案并列比较后打分。这比「凭空打分」客观得多——有参照物，裁判更容易识别「漏了什么、错在哪」。

打分者是谁？MT-Bench 论文的核心实验正是回答这个问题：**让 GPT-4 当裁判，去复现 3000+ 份人类标注**。结果发现 GPT-4 与人类裁判的一致性高达 **80% 以上**，远超此前任何自动评测。<span class="marginnote">「GPT-4 当裁判」听起来像用运动员当裁判——如何保证公平、如何消除偏见，是整篇论文后半部分的主题，也是我们下一篇《LLM-as-a-Judge》的全部内容。</span>

## 3 Chatbot Arena：让真实用户投票

如果 MT-Bench 是「出题考试」，那 **Chatbot Arena（聊天机器人竞技场）** 就是「擂台比武」。它不预设任何题目：用户随便输入自己的问题，两个匿名模型各答一遍，用户投出「哪个更好」的一票。数十万用户、上百万次投票汇聚成一张**两两比较**的网络，再用 **Elo 评分**（源自国际象棋的等级分系统）算出每个模型的最终排名。

Arena 的价值在于**天然生态效度**：问的都是真实问题，比的是真实体验。它的代价是**噪声极大**——用户水平参差、题材分布不均、模型匿名性难以完全保证。但作为「人群智慧」的度量，它是唯一能持续滚动更新的「活」排行榜。

## 4 公式解析：Elo 评分如何更新

Elo 系统的核心是一个更新式，用来回答「这局赢了，等级分该加多少」：

$$
R'_{a} = R_{a} + K\left(S_{a} - E_{a}\right), \qquad
E_{a} = \frac{1}{1 + 10^{(R_{b} - R_{a}) / 400}}
$$

拆成四步理解：

- **第一步，$E_a$ 是期望胜率**：根据当前等级分 $R_a, R_b$ 预测模型 $a$ 赢下这一票的概率。若 $R_a = R_b$，则 $E_a = 0.5$；分差 400 分，期望胜率约为 10:1。
- **第二步，$S_a$ 是实际结果**：赢了取 1，平局取 0.5，输了取 0。
- **第三步，$K$ 是更新步长**：一把定胜负的 Arena 投票通常取 $K$ 较小（如 4–16），让排名缓慢漂移而非剧烈震荡。
- **第四步，组合起来**：$R'_{a} = R_{a} + K(S_a - E_a)$——**「超预期」获胜就加分，「爆冷」输掉就减分，胜负本身不直接决定分数。** 这正是 Elo 能处理「不同模型从未同台对决」这一问题的原因：用期望胜率把所有人的分数锚定在同一把尺上。

**辨析｜易错点：** Arena 排名是**相对**的，不是**绝对**的。它告诉你「谁更受这批用户欢迎」，不告诉你「模型在某项能力上达到什么水平」。用户群体变化，榜单就会漂移——因此 Arena 分数适合看趋势，不适合当严谨的科学测量。

## 5 小结

- **MT-Bench** 用 80 道两轮对话题把「对话能力」变成可测考卷，覆盖 8 类日常交互。
- 采用**参考式打分**：以标准答案为参照，由 GPT-4 裁判给 1–10 分。
- **Chatbot Arena** 用真实用户投票 + Elo 评分构造「活」排行榜，生态效度高、噪声大。
- Elo 更新式的精髓是**按期望胜率而非胜负本身**调整分数。
- 相对排名 ≠ 绝对能力，Arena 分数只适合读趋势。
