## 为什么从哼唱检索开始

「听歌识曲」要求你**有原曲的录音**（在放那首歌时识曲）。但更多时候你**哼得出旋律、却不知道歌名**——「那个、啦啦啦～的那首」。**哼唱检索（Query by Humming, QbH）** 解决这个问题：你把旋律哼给机器，机器从歌库里找出「哪首歌的旋律与你哼的最像」。它比音频指纹难得多——因为**哼唱不是原曲录音**：没有伴奏、音高不准、节奏随意、还可能跑调。

QbH 是「旋律匹配」的核心案例。它把「找歌」从「音频对音频的精确匹配」变成「**旋律对旋律的结构比对**」——这需要把哼唱与歌谱都抽象成「旋律表示」，再容忍「音高误差、节奏误差、绝对调性不同」去匹配。

## 1 任务定义：难点在于「不精确」

QbH 的 query 与库里的歌差异远超音频指纹：

| 差异维度 | 听歌识曲（指纹） | 哼唱检索（QbH） |
| --- | --- | --- |
| query 是什么 | 原曲的录音（带伴奏） | 人哼的旋律（无伴奏） |
| 音高 | 与原曲一致 | **不准（±半音级误差）** |
| 节奏 | 与原曲一致 | **自由（哼得随意）** |
| 调性 | 与原曲一致 | **可能整体移调** |
| 匹配对象 | 原曲音频 | 歌库的**旋律（乐谱/MIDI）** |

**核心概念：QbH 要容忍「同一旋律的不同表达」。** 同一首歌，你可以哼高一个调、哼快一点、某个音哼错半个音——机器要认出「这还是那首歌」。所以匹配**不能比绝对音高、绝对时值**，要比「旋律的**轮廓（contour）**」——音高**相对走向**（上、下、平）与时值**相对长短**。

**音高提取的第一步**：把哼唱的音频变成**音高序列**（用基频估计，见《基音周期估计》一节）——哼唱是单音旋律，单音高估计就够用（比多音高转录简单得多）。<span class="marginnote">哼唱检索与「语音基频估计」的接口：哼唱本质是「人声单音」，基频估计（YIN、自相关）把哼唱波形变成 F0 曲线。但哼唱可能「跑调」（音高滑移）、「断断续续」（喘气）——提取后还要<strong>清理</strong>：去掉无音段、平滑抖动。这段「哼唱 → 干净的旋律轮廓」的预处理，是整个 QbH 成败的第一关。</span>

## 2 旋律表示：从绝对音高到相对轮廓

匹配前，把哼唱与歌谱都表示成「**旋律轮廓（melodic contour）**」——丢绝对音高、保留相对走向：

- **音高轮廓**：把逐帧 F0 序列**量化成相对音高级**——每个音高相对前一个的「+1、0、−1」（升、平、降）或相对「首个音」的间隔。
- **时值轮廓**：把音符时长归一化成相对比例（长/短），或直接丢弃时值、只看音高走向序列。
- **调性归一**：把整体音高**移调到参考**（如首个音归 0）——同一旋律哼在不同调上，归一后等价。

**公式解析：相对音高序列。**

$$
\text{Query: } Q = \big[ \Delta_1, \Delta_2, \dots, \Delta_n \big], \qquad \Delta_i = \text{pitch}(q_{i+1}) - \text{pitch}(q_i)
$$

- **第一步，看差分序列**：$Q$ 是「相邻音符的音高差」——`[+2, -1, +1, 0]` 表示「升、降、升、平」。这消除了**绝对调性**（不管你在 C 调还是 D 调哼，走向一样）。
- **第二步，看符号化与量化**：差分量化为「半音数」或「方向符号」（升/平/降）——方向符号对「哼错半个音」鲁棒（+2 与 +1 都算「升」）。
- **第三步，看歌谱表示**：歌库里的每首歌（MIDI/乐谱）也用同样方法转成轮廓序列——query 与候选歌都在同一表示空间。
- **第四步，看匹配的容错目标**：匹配 = 在「允许音高误差、节奏误差」的前提下，找「轮廓最接近」的候选。这天然需要**序列比对算法**——下一节的 DTW。

**核心要点：QbH 的表示 = 「丢绝对、留相对」的旋律轮廓。** 相对走向对调性、微误鲁棒——这是「哼得不准也能找到」的数学基础。

## 3 动态时间规整（DTW）：容忍节奏差异的比对

哼唱的节奏与歌谱**不对齐**（哼得快慢随意），直接逐音符比对会错位。**动态时间规整（Dynamic Time Warping, DTW）** 是序列比对的经典算法——允许「时间轴局部伸缩」，找两序列的最优对齐。

**公式解析：DTW 的距离递推。**

$$
D(i,j) = d\big(q_i, c_j\big) + \min\big( D(i-1,j),\; D(i,j-1),\; D(i-1,j-1) \big)
$$

- **第一步，看局部距离**：$d(q_i, c_j)$ 是哼唱第 $i$ 个音符与候选歌第 $j$ 个音符的**音高差**（轮廓距离）。
- **第二步，看转移选择**：$D(i,j)$ 由三种前驱累加——(i-1,j) 表示「哼唱的一个音符对齐候选的多个音符」（哼慢了）、(i,j-1) 表示「候选一个音符对齐哼唱多个」（哼快了）、(i-1,j-1) 表示「一对一对齐」。
- **第三步，看 min**：取三者最小——**让时间轴「伸缩」以最小化总距离**。哼快了就把哼唱音符「拉伸」对齐候选，哼慢了就「压缩」。
- **第四步，看最终距离**：$D(n, m)$ 是整条序列的最优比对距离——越小越像。对所有候选歌算 DTW，取最小的候选作为结果。

**核心要点：DTW = 「允许时间轴伸缩的序列距离」。** 它是哼唱检索（与语音比对、手势识别）的通用工具——只要两个序列「结构相同、速度不同」，DTW 都能对齐。代价是 $O(nm)$ 计算（动态规划），长序列、大数据量时要用下界剪枝加速。<span class="marginnote">DTW 与语音识别的渊源：DTW 是 1980 年代孤立词识别的核心算法（用动态规划对齐「模板语音」与「测试语音」），后被 HMM 取代。哼唱检索是 DTW 的「文艺复兴」——旋律匹配与孤立词识别在结构上同构（一个模板、一个 query、容错比对）。理解 DTW，也补上了语音识别史的一块拼图。</span>

## 4 现代哼唱检索：深度化与多模态

经典 QbH 是「手工旋律表示 + DTW」，现代演进：

- **深度旋律嵌入**：用对比学习把「哼唱」与「歌谱旋律」映射到同一嵌入空间——**不用手工建轮廓**，网络自己学「哼唱与乐谱的对应关系」。query 嵌入 → 与库嵌入比余弦相似度，检索用 ANN（近似最近邻）加速。
- **多模态**：哼唱（音频）+ 歌词记忆（文本）+ 节奏（拍手）混合 query——「我只记得歌词片段 + 哼一段」。
- **与指纹结合**：哼唱得到「候选曲」后，再用音频指纹确认——「先粗后精」。

**辨析｜易错点：QbH ≠ 指纹。** 指纹比「**原曲音频 vs 原曲音频**」（同曲同指纹）；QbH 比「**哼唱旋律 vs 乐谱旋律**」（结构相似、表达不同）。指纹是「精确匹配」，QbH 是「容错结构匹配」。判断任务：「有原曲录音」→ 指纹；「哼唱/口哨」→ QbH。两者共享「检索」框架，但匹配对象与容错策略完全不同。<span class="marginnote">哼唱检索的「用户行为」建模也很重要：真实用户哼唱「不准」是有规律的——音高系统性偏低、节奏越到后面越自由、开头最准。把这些「人类哼唱偏差」建模进训练（深度方法）或模板（经典方法），能显著提升检索率——这是「以人为中心」的音频检索设计。</span>

## 5 哼唱检索的评测与挑战

QbH 系统「找没找到」怎么评，以及为什么这比听歌识曲难评：

- **Top-N 命中率**：query 对应的歌在「前 N 个候选」里的比例——Top-1 命中率是最严指标，Top-10 更实用（让用户选）。
- **按难度分层**：哼唱质量差异大——按「哼得准/哼得飘/跑调」分层报命中率，才知道系统「卡在哪」。
- **歌库规模**：1000 首和 100 万首的难度完全不同——报结果必须注明库规模。
- **挑战**：哼唱音高提取错误（跑调、断音）、歌库旋律表示不全（无 MIDI 只有音频）、多曲同旋律（不同歌同一旋律）——「旋律相同但歌不同」是原理性难点。

**公式解析：Top-K 命中率。**

$$
\text{Hit@K} = \frac{1}{N} \sum_{i=1}^{N} \mathbb{1}\big[ \text{目标歌} \in \text{Top-}K(\text{query}_i) \big]
$$

- **第一步，看候选**：$\text{Top-}K(\text{query}_i)$ 是系统给第 $i$ 个哼唱 query 返回的 $K$ 个候选歌。
- **第二步，看命中判断**：目标歌是否在候选里——在则记 1。
- **第三步，看平均**：N 个 query 的命中率平均——**Hit@1 是最严、Hit@10 是实用**。
- **第四步，看公平**：不同系统要在**同一歌库、同一 query 集**上比——否则命中率不可比。

**核心要点：QbH 评测 = 「Top-N 命中率 + 难度分层 + 库规模注明」。** 哼唱检索是「容错匹配」的极端案例，评测要如实反映「它容忍到什么程度」。

## 6 小结

- **QbH** 从哼唱旋律找歌，比指纹难在「哼唱 ≠ 原曲录音」——音高、节奏、调性都不准。
- 核心是**旋律轮廓**：丢绝对音高（差分/方向符号）、丢绝对时值，留「相对走向」。
- 匹配用 **DTW**（允许时间轴伸缩的序列比对），对哼得快慢鲁棒。
- 经典 = 手工轮廓 + DTW；现代 = 深度旋律嵌入 + 向量检索。
- QbH ≠ 指纹（结构容错匹配 vs 精确匹配）；建模「人类哼唱偏差」可显著提升。

**附：关键概念速记**

- **QbH**：哼唱旋律找歌——比指纹难在「哼唱 ≠ 原曲录音」。
- **旋律轮廓**：丢绝对音高（差分/方向符号）、丢绝对时值——留「相对走向」。
- **容错对象**：音高不准（±半音）、节奏自由、整体移调——全要容忍。
- **DTW**：允许时间轴伸缩的序列比对——对哼得快慢鲁棒，$O(nm)$。
- **哼唱预处理**：基频估计 → 清理无音段、平滑抖动——「哼唱 → 干净轮廓」是第一关。
- **评测**：Top-N 命中率 + 难度分层 + 库规模注明。
- **深度嵌入**：对比学习把哼唱与乐谱映射到同一空间——不用手工建轮廓。
- **与 DTW 的渊源**：DTW 是 1980 年代孤立词识别的核心——哼唱检索是它的文艺复兴。

**延伸思考**：QbH 的「丢绝对、留相对」与语音识别的「归一化」、声纹的「信道补偿」是同一哲学——**去掉「无关变化」，保留「本质结构」**。哼唱的「本质」是旋律走向，音高绝对值、速度都是「可变的皮」。这揭示了一个通用设计原则：**每个识别任务，先想清楚「什么该保留、什么该忽略」**——想清楚了，匹配算法（DTW、嵌入）自然选对。
