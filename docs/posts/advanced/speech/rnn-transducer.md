## 为什么从 RNN-T 开始

前两节的两条端到端路线各有短板：**CTC 流式但假设帧间独立**（输出不看已生成的文本），**LAS 能建模上下文但非流式**（要听完整个句子才能开始翻译）。能不能有一个模型，**既像 LAS 一样让输出依赖历史输出，又像 CTC 一样逐帧推进、实时可用**？

**RNN-Transducer（RNN-T）** 正是为这个问题设计的。它在 2012 年由 Alex Graves 提出，2019 年后被谷歌用于 Google Assistant 的流式语音识别而名声大噪。RNN-T 的架构用一个**预测网络（prediction network）** 补上 CTC 缺失的「输出依赖」，同时用**单调的音频推进**保证流式能力——它今天的地位，相当于「流式端到端 ASR 的标准答案」。

## 1 三个网络：声学、语言与联合

RNN-T 由三个模块组成：

- **编码器（encoder / transcription network）**：把音频特征 $X$ 映射成高层表征 $h_1, \dots, h_T$，只做「听」。与 LAS 的编码器同类，常用 BiLSTM 或 Conformer。
- **预测网络（prediction network / language model）**：把**已生成的标签序列** $y_1, \dots, y_u$ 编码成 $p_u$，相当于一个「轻量语言模型」——它让输出依赖历史输出，正是 CTC 缺失的那一块。常用单层 LSTM 或 embedding 查表求和。
- **联合网络（joint network）**：把 $h_t$（声学侧）与 $p_u$（语言侧）融合，预测「下一个输出符号」。融合方式是**加性融合**：两个向量相加后过一个全连接 + softmax，输出在扩展字母表（含 $h_t$）上的分布。

**核心概念：两个时间轴。** 音频有 $T$ 步，输出文本有 $L$ 步，RNN-T 在 $(t, u)$ 的二维格子上工作：$t$ 轴随音频单调推进，$u$ 轴随已输出文本推进。每个「网格点」都对应一个 softmax 分布——模型随时可以「输出下一个字符」或「跳过（blank，等待更多音频）」。

## 2 对齐格子：一边走音频，一边吐字符

RNN-T 的对齐可以直观地想象成一个**棋盘格**：

- 每个格点 $(t, u)$ 表示「已听完前 $t$ 帧、已输出前 $u$ 个字符」。
- 从 $(t, u)$ 有两个合法移动：**向右**（$t{+}1$，听下一帧，不输出）对应输出 $t{+}1$；**向上**（$u{+}1$，输出第 $u{+}1$ 个字符）。<span class="marginnote">这里的「blank」与 CTC 不同：RNN-T 的 blank 是「什么也不输出，继续推进音频」的动作标记，不是字符分隔符。重复字符在 RNN-T 里天然合法——因为输出动作之间隔着音频推进，没有「合并重复」规则。这也是 RNN-T 相比 CTC 的一个简化：无 collapse 逻辑。</span>

一条对齐路径 = 一条从 $(1,0)$ 走到 $(T,L)$ 的格上路径，**先向右走再向上走（先听完音频再输出）不合法吗？** 注意边界：格子上必须先到某个 $t$ 才有音频表征，所以实际路径是「音频推进」与「输出字符」交错进行——这正是**边说边识别**的物理含义：不必等整句结束，边说边出字。

由于音频必须单调推进，RNN-T 天然是**流式（streaming）**的：编码器可以按块处理，每推进一块就能决定是否输出字符。<span class="marginnote">工程上 RNN-T 用「chunk 编码器」实现真流式：编码器一次只看一小段（如 640ms），联合网络基于当前块的表征做判断。这引出流式 ASR 的核心工程问题——局部上下文够不够用、块间怎么拼接，见《流式识别》一节。</span>

## 3 训练：格上前向—后向

与 CTC 一样，RNN-T 的目标是**所有对齐路径的似然和**。但注意：CTC 每条路径是「$T$ 个符号」，RNN-T 每条路径是「$T$ 次音频推进 + $L$ 次字符输出」的交错序列，路径数更多（$\binom{T+L}{L}$ 量级）。求和靠格上的前向—后向算法：

$$
P(Y \mid X) = \sum_{\text{所有对齐路径}} \prod_{\text{路径上每个动作}} P(\text{该动作} \mid \text{格点})
$$

递推结构：设 $\alpha(t, u)$ = 到达格点 $(t,u)$ 的全部路径概率和，则 $\alpha(t,u)$ 由左边格点（输出 blank 走到）与下边格点（输出字符走到）累加而来。这与 CTC 的递推神似，只是格子的两个方向分别对应「音频」与「文本」两个轴。训练时对每个动作位置的 softmax 求梯度，模型学到「在什么声学上下文 + 什么文本上下文下，应该输出这个字符 / 输出 blank」。

**公式解析：格点上的分布。**

$$
P(y_{u+1} \mid X, Y_{1:u}) = \text{softmax}\Big( W_j \big[\, h_t \oplus p_u \,\big] + b_j \Big)
$$

- **第一步，看两个输入**：$h_t$ 是编码器对第 $t$ 帧的声学表征，$p_u$ 是预测网络对已输出 $u$ 个字符的语言表征。两者都编码进同一个格点。
- **第二步，看 $\oplus$ 与 $W_j$**：$h_t \oplus p_u$ 是向量拼接（或相加），$W_j$、$b_j$ 是联合网络的权重与偏置，把两路信息映射到扩展字母表空间。
- **第三步，看 softmax**：输出一个分布，覆盖「全部字符 + blank」。取 **blank** 概率意味着「这一步不输出、推进音频」；取某字符概率意味着「输出该字符、推进文本轴」。
- **第四步，理解训练含义**：$h_t$ 与 $p_u$ 通过同一个格点交互——模型在训练中学会「这个音 + 已经说过的话 → 下一个该说什么」。这是 RNN-T 相比 CTC 的增量：**输出概率显式依赖已生成文本**，条件独立假设被局部解除。

**辨析｜易错点：RNN-T 是流式，但「流式」不等于「块式流式」。** 理论 RNN-T 每帧都能推进，是逐帧流式；工程上为了用 Transformer 类编码器，常退化为 chunk-based 流式（每块几十上百帧才推进一次），这时「块边界」就成了新的对齐约束。初学者常把「RNN-T」与「流式」画等号——架构保证单调，工程实现才决定延迟。

## 4 解码：贪婪与束搜索

RNN-T 解码比 LAS 简单，因为**没有注意力、没有输出重排**：

- **贪婪解码**：从格点 $(1,0)$ 开始，每一步取概率最大的动作——若取到 $t=T$ 则 $t{+}1$，否则输出该字符且 $u{+}1$。直到 $t=T$ 且输出 $t=T$（或到终止）为止。简单快速，实际精度已经不错。
- **束搜索（beam search）**：维护多条候选（前缀 + 格点位置），逐格点展开，按前缀概率排序。束搜索可以进一步融入外部语言模型（shallow fusion）做重打分。

RNN-T 的束搜索有一个细节：不同路径可能到达**同一格点 $(t,u)$** 且输出相同前缀——这些要合并（加总概率），否则束会被重复候选占满。这与 CTC 束搜索「按合并前缀去重」是同一思想。

## 5 RNN-T 的继承与超越

RNN-T 站在 CTC 与 LAS 的交汇处，是流式端到端 ASR 的基准：

- **对 CTC**：预测网络补上了输出依赖，条件独立假设缓解，精读通常更高。
- **对 LAS**：单调音频推进保证流式，无注意力错位问题；代价是**上下文受限于已生成文本**，不能像 LAS 那样回看整句，长程依赖靠编码器的局部表征补足。
- **工程实践**：Google Assistant、语音输入法大多用「RNN-T + 语言模型重打分 + 级联编码器」的组合；Conformer 编码器 + RNN-T 是 2021–2023 年的主流流式方案。<span class="marginnote">近年来「RNN-T 与注意力混合」也流行：训练时加 CTC 或注意力辅助目标，或用「非流式模型 distill 流式模型」的知识蒸馏把大模型的能力灌进流式 RNN-T——两遍解码与蒸馏的谱系会在语音大模型章节延续。</span>

## 6 RNN-T 的工程实践要点

把 RNN-T 从论文变成产品，有一批关键工程细节：

- **预测网络的「语言模型」角色**：预测网络内置了一个「轻量 LM」——它在训练中学会「下一个字符的文本先验」。但它在有外部大 LM 时会「碍事」——流式系统常做「内部 LM 去除」（见《语言模型融合》的 ILME 一节）。
- **联合网络的维度**：$h_t$ 与 $p_u$ 拼接后过投影——**联合网络是瓶颈**（维度太小信息不够、太大计算爆炸），常用 256–512 维。这一层的设计直接影响「声学 × 语言」的融合质量。
- **对齐的初始化**：RNN-T 训练初期「blank 概率过高」（模型只会输出 blank）——用「**先训短句/用 CTC 初始化**」或「blank 偏置」让模型先学会「输出字符」。
- **解码的实时性**：RNN-T 流式解码是「增量格点搜索」——每帧更新格点、输出「已确认」的字符（不要回改），这是流式 ASR 的工程核心。

**公式解析：联合网络的信息瓶颈。**

$$
\mathbf{z}_{t,u} = \text{Projection}\big( [\,h_t \oplus p_u\,] \big), \qquad \dim(\mathbf{z}) \ll \dim(h) + \dim(p)
$$

- **第一步，看拼接输入**：$[h_t \oplus p_u]$ 是声学与语言表征的拼接——信息都在这。
- **第二步，看投影压缩**：投影把拼接压到低维 $\mathbf{z}$——**强迫声学与语言信息在低维「融合」**。维度太小则信息互斥（学不下），太大则算力浪费。
- **第三步，看融合质量**：联合网络学的是「在这个声学上下文 + 文本上下文下，下一个字符是什么」——投影层的容量决定融合的精细度。
- **第四步，看调试**：联合网络维度是「精度—速度」旋钮——扫维度找拐点（再加大精度不涨了）是标准调试。

**核心要点：RNN-T 的工程 = 「预测网络管语言、联合网络管融合、对齐初始化管收敛、增量解码管流式」。** 每块都有专门的工程技巧。

## 7 小结

- **RNN-T = 编码器 + 预测网络 + 联合网络**：声学、语言两路信息在格点上融合。
- **两个时间轴**：音频轴单调推进（blank），文本轴逐字符输出，天然流式。
- **对齐是格上路径**：目标函数对所有路径概率求和，靠前向—后向算法高效计算。
- **格点分布** $P(y_{u+1} \mid h_t, p_u) = \text{softmax}(W_j[h_t \oplus p_u])$：输出概率显式依赖已生成文本。
- 贪婪解码简单，束搜索需合并相同格点；可接外部 LM 重打分。
- 相比 CTC 补上输出依赖，相比 LAS 赢得流式，是流式端到端 ASR 的标准框架。

**附：关键概念速记**

- **RNN-T = 编码器 + 预测网络 + 联合网络**——声学、语言两路在格点上融合。
- **两个时间轴**：音频轴单调推进（blank）、文本轴逐字符输出——天然流式。
- **预测网络**：把已生成文本编码成语言表征——补上 CTC 缺失的「输出依赖」。
- **联合网络**：$h_t \oplus p_u$ 融合预测下一个符号——「这个音 + 已说的话 → 下一个字」。
- **对齐格子**：棋盘格上的路径 = 「边说边出」的动作序列。
- **格上前向—后向**：对所有路径概率求和——训练高效。
- **解码**：贪婪（简单）或束搜索（需合并相同格点）——可接外部 LM 重打分。
- **流式属性**：架构保证单调，工程（chunk 编码器）决定延迟。

**延伸思考**：RNN-T 的「预测网络」本质是把一个「语言模型」装进了识别器——**识别器从此「自带语言」，不再依赖外部 LM**。但它自带的 LM 弱，于是又发展出「内部 LM 去除」来配合强外部 LM（见《语言模型融合》）。**「内置 vs 外置」的循环——识别器内置语言能力，又因不够强而外挂**——是序列识别系统的永恒张力。理解 RNN-T，就理解了流式识别的「精度与自包含」的平衡。
