## 为什么从 EER 与 minDCF 开始

说话人验证（「是不是张三」）的输出是一个相似度分数 + 阈值——调阈值，两种错误此消彼长：阈值高，把「陌生人当张三」少（误接受 FAR 低）但「把张三拒之门外」多（误拒绝 FRR 高）；阈值低则相反。**怎么评价一个系统「好坏」，且与阈值无关？** 这就是 **EER（等错误率）** 与 **minDCF（最小检测代价函数）** 的用武之地——它们是说话人识别（和人脸识别）的标准评测指标，报一个数就能跨系统、跨阈值比较。

理解 EER 与 minDCF，就是理解「**错误率如何在不同工作点之间权衡**」——这是所有「阈值型判决」系统（声纹、KWS、异常检测）评测的通用框架。

## 1 两类错误与混淆矩阵

说话人验证的判决有四格（对验证语音 $x$，声称身份 $A$）：

| 真实情况 | 判决接受 | 判决拒绝 |
| --- | --- | --- |
| 真是 A | 正确接受 | **误拒绝（FRR）** |
| 不是 A | **误接受（FAR）** | 正确拒绝 |

- **误接受率 FAR（False Acceptance Rate）**：把**冒名者**当真的比例。
- **误拒绝率 FRR（False Rejection Rate）**：把**本人**当冒名者的比例。

**核心概念：FAR 与 FRR 由阈值 $\tau$ 此消彼长。** $\tau$ 提高 → 更难通过 → FAR↓ 但 FRR↑；$\tau$ 降低 → 更容易通过 → FAR↑ 但 FRR↓。**一个系统没有「唯一的 FAR 或 FRR」——只有「随阈值变化的曲线」**。评测要回答：这条曲线「多靠近左下角」（完美=两者都 0）。

## 2 EER：等错误率

**EER（Equal Error Rate）** 是「FAR = FRR」那一点对应的错误率——「两个错误相等时的共同错误率」。

**公式解析：DET 曲线与 EER。**

$$
\text{EER} = \text{FAR}(\tau^\*) = \text{FRR}(\tau^\*), \qquad \text{其中 } \tau^\* \text{ 满足 } \text{FAR}(\tau^\*) = \text{FRR}(\tau^\*)
$$

- **第一步，看阈值扫描**：把阈值从低扫到高，每个 $\tau$ 得到一对 (FAR, FRR)——在坐标系描点，得到 **DET 曲线**（Detection Error Tradeoff，检测错误权衡曲线，FAR vs FRR 的对数坐标）。
- **第二步，看对角线交点**：DET 曲线与「FAR = FRR」对角线交点对应 EER——「冒名者误入」与「本人被拒」恰好等价的点。
- **第三步，看系统好坏**：DET 曲线越靠左下，EER 越低，系统越好。**EER 是「与阈值无关」的单数指标**——不管你在实际部署选哪个阈值，EER 都描述「系统的上限错误」。
- **第四步，看 EER 的局限**：EER 假设「误接受与误拒绝同等严重」——但真实场景**通常不相等**：银行核身「误接受（放陌生人进）」的代价远大于「误拒绝（让本人再试一次）」。EER 不考虑代价差异。

**核心要点：EER = 「两种错误等权时的系统错误率」，直观、可比、与阈值无关。** 它是声纹论文的「必报指标」，但只回答「系统多准」，不回答「对业务多合适」。

## 3 minDCF：代价敏感的最小检测代价

**DCF（Detection Cost Function，检测代价函数）** 把「错误的代价」显式建模。设 $C_{FA}$ 是误接受代价、$C_{FR}$ 是误拒绝代价、$P_{\text{target}}$ 是「说话人先验概率」（验证请求中真本人的比例），定义：

$$
\text{DCF}(\tau) = C_{FA} \cdot \text{FAR}(\tau) \cdot (1 - P_{\text{target}}) + C_{FR} \cdot \text{FRR}(\tau) \cdot P_{\text{target}}
$$

**公式解析：minDCF 为什么比 EER 更实用。**

- **第一步，看加权**：FAR 乘「非本人先验 $(1-P_{\text{target}})$ 与代价 $C_{FA}$」，FRR 乘「本人先验 $P_{\text{target}}$ 与代价 $C_{FR}$」——**错误按「发生概率 × 后果代价」加权**。若先验是 1%（100 次验证 1 次是本人），FRR 的权重小，因为误拒绝「不常发生」。
- **第二步，看最小化**：$\text{minDCF} = \min_\tau \text{DCF}(\tau)$——在所有阈值里找**代价最小的工作点**。它回答「这个系统在最优化配置下，平均代价有多低」。
- **第三步，看标准设定**：NIST SRE 挑战给标准参数（如 $P_{\text{target}}=0.01, C_{FA}=1, C_{FR}=10$）——**在同一参数下报 minDCF，跨系统可比**。
- **第四步，看与 EER 的关系**：minDCF 是「带代价的 EER 推广」——当 $C_{FA}=C_{FR}$、$P_{\text{target}}=0.5$ 时，minDCF 退化为接近 EER 的指标。**EER 是 minDCF 的特例（等权），minDCF 是更一般的「业务相关」指标**。

**核心结论：minDCF = 「给定代价与先验，系统能达到的最低平均代价」。** 它把「业务后果」塞进评测——银行选 minDCF（误接受代价高），智能门禁可能更看重 EER——**指标选择本身就是业务策略**。

## 4 评测协议的完整要素

报 EER/minDCF 时，必须附评测协议（protocol），否则数字不可比：

- **测试集与说话人划分**：训练/注册/测试的说话人**不重叠**（评测"未见说话人"的泛化）。
- **试次（trial）**：正试次（同一人注册+验证）与负试次（不同人）的数量与比例——比例影响先验。
- **分数校准（calibration）**：系统输出的「相似度」要能跨系统比较，需**校准**（把分数映射到似然比）——校准质量单独用 **Cllr** 度量。
- **注册与验证条件**：注册音频时长、信道（电话/麦克风）、说话内容（文本相关/无关）。<span class="marginnote">「分数校准」与 minDCF 的关系：minDCF 在「最优阈值」处取值——但实际系统阈值是<strong>固定的</strong>（上线前定死），不能用测试集的最优阈值自欺。所以正规评测分「minDCF（理想校准，上限）」与「actual DCF（固定阈值，实际）」两个数——差距大说明<strong>系统校准差</strong>，即使嵌入质量高也用不好。</span>

**辨析｜易错点：EER 低 ≠ 实际用得好。** EER 是「等权 + 最优阈值」的理论数；实际部署用**固定阈值**，且代价不均等——所以「EER 更低」的系统在「业务工作点」可能反而更差。评测要看 **minDCF（配业务参数）** 与 **固定阈值下的实际表现**。**指标是「体检报告」，业务是「临床决策」——两者要对得上。**

## 5 从指标到业务：选择工作点的实践

指标是「体检」，业务是「临床」——把 EER/minDCF 落到产品，要过几关：

- **确定业务代价**：核身场景「误接受」代价极高（放陌生人进账户），「误拒绝」只是用户重试——所以工作点要「FAR 极低」；门禁场景「误拒绝」更烦（用户进不去），工作点要「FRR 低」。**代价比 $C_{FA}:C_{FR}$ 是业务给的，不是技术定的。**
- **估计先验 $P_{\text{target}}$**：验证请求中真本人的比例——冒名攻击多的场景先验低（本人少）。先验影响工作点。
- **选实际阈值**：minDCF 是「理论最优阈值」的代价；上线用**固定阈值**——在开发集上按「业务目标」选阈值（如「FAR ≤ 0.1%」），测实际 DCF。
- **持续监控**：上线后 EER/minDCF 会漂移（新攻击、新用户群）——定期重测、重校准。

**公式解析：业务约束下的阈值选择。**

$$
\tau^* = \min \big\{ \tau : \text{FAR}(\tau) \le \text{FAR}_{\text{max}} \big\}
$$

- **第一步，看业务约束**：$FAR_{\text{max}}$ 是业务能承受的最大误接受率——如金融场景 0.01%。
- **第二步，看阈值方向**：FAR 随阈值单调下降——找「刚好满足 FAR ≤ 上限」的最小阈值，即「在安全前提下最不麻烦用户」的点。
- **第三步，看校验**：选完阈值要在**独立测试集**上验证 FAR/FRR——开发集选点、测试集验证，防过拟合。
- **第四步，看指标报告**：报告「业务工作点」的 FAR/FRR（实际数），而非只报 EER/minDCF（理论数）——**上线报告要有「实际的」而非「理想的」**。

**核心要点：从指标到业务 = 「代价比 + 先验 → 阈值 → 实测 → 监控」。** EER/minDCF 是「系统的上限体检」，业务的阈值决策是「在体检结果上选工作点」。

## 6 小结

- 说话人验证的两种错误：**误接受（FAR）**与**误拒绝（FRR）**，由阈值此消彼长。
- **EER** = FAR = FRR 时的错误率，与阈值无关，直观可比，是必报指标。
- **minDCF** = 给错误配「先验 + 代价」后的最小平均代价，更贴近业务。
- EER 是 minDCF 的等权特例；指标选择反映业务策略（误接受 vs 误拒绝哪个更贵）。
- 报数必附**评测协议**（说话人划分、试次、校准）；EER 低 ≠ 实际用得好。

**附：关键概念速记**

- **两类错误**：误接受（FAR，放陌生人）与误拒绝（FRR，拒本人）——阈值此消彼长。
- **DET 曲线**：FAR vs FRR 随阈值的轨迹——越靠左下越好。
- **EER**：FAR = FRR 时的错误率——与阈值无关、直观可比，是「必报指标」。
- **minDCF**：带「先验 + 代价」的最小平均代价——更贴近业务。
- **代价敏感**：$C_{FA} \times FAR \times (1-P_{\text{target}}) + C_{FR} \times FRR \times P_{\text{target}}$——错误按「发生概率 × 后果」加权。
- **校准（calibration）**：分数映射到似然比——minDCF 与 actual DCF 的差反映校准质量。
- **评测协议**：说话人划分、试次、注册/验证条件——报数必附，否则不可比。
- **业务工作点**：EER 是体检，实际部署按业务代价选阈值、实测 FAR/FRR。

**延伸思考**：EER 与 minDCF 的取舍，本质是「公平」与「实用」的取舍——EER 给「系统能力的公平上限」，minDCF 给「业务场景的实用代价」。这个「指标是否带先验」的争论，贯穿一切「阈值型判决」系统（声纹、KWS、异常检测）。**选择指标，就是在选择「你优化的是能力，还是后果」**——理解这一点，比记住公式更重要。
