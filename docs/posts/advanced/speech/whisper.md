## 为什么从 Whisper 开始

前面所有模型都遵循同一个范式：**先精心构造数据集，再训练专用模型**——LibriSpeech、AISHELL、Common Voice 都是人工或半自动转写的「干净」语料，模型在它们上做监督训练。OpenAI 的 **Whisper**（2022）彻底颠覆了这个范式：它不去精修数据，而是**直接抓取互联网上 68 万小时的「有噪声」音频—文本对**，用超大规模模型把它们「硬吃下去」。结果是一个开箱即用的多语言、多任务识别系统——不需要词典、不需要强制对齐、不需要 WFST，一个 Transformer 端到端搞定转写、翻译、时间戳与语种识别。

Whisper 的意义远超「一个模型」：它是「**弱监督 + 规模**」路线在语音领域的旗舰证明，也定义了后续语音大模型的训练配方——数据管道、token 设计、多任务格式都成了行业模板。

## 1 数据：68 万小时弱监督从哪来

Whisper 的根基是 **68 万小时**带转写的音频，其中 11.7 万小时覆盖 96 种语言、12.5 万小时是「X→英语」的翻译对。数据的核心原则是**弱监督（weak supervision）**：

- **来源不是精标数据，而是互联网**：抓取网页上「音频 + 附近文字」的对（字幕、旁白、播客文字稿），而非人工转写。
- **噪声被当作特征而非障碍**：这些对的文本未必逐字对应音频（可能有错别字、字幕不同步、说话人漏词）。Whisper 赌的是**规模压过噪声**——样本足够多时，模型从干净样本学到的模式会「稀释」噪声样本的错误。
- **多任务自动涌现**：语料自带语言标签、段落边界、时间信息，模型顺带学到「这段是哪国话」「这句话从哪秒开始」。

**核心要点：弱监督的三步滤波。** 数据不是拿来就用，而是经过清洗——(1) **语言过滤**：用语言识别器筛掉与文本标签不符的样本；(2) **时长过滤**：丢弃文本过短/过长或音频与文本比例畸形的样本；(3) **去重**：去掉近似重复的音频。即便这样，Whisper 论文也坦言：数据中的噪声（比如歌曲、纯音乐被误标为语音）依然是真实存在、被模型「记下」的部分——**弱监督的数据质量天花板，就是模型的天花板**。<span class="marginnote">对比一下传统路线：LibriSpeech 约 960 小时、AISHELL 约 178 小时，都是人工校验过的干净语料。Whisper 用 68 万小时「脏」数据把规模放大三个数量级，赌的是「规模 > 噪声」——这与大语言模型「网络文本 + 预训练」的思路完全一致，是「大力出奇迹」在语音上的翻版。</span>

## 2 架构：一个纯 Transformer 端到端

Whisper 的结构简单得令人惊讶——它基本就是 **Transformer 编码器—解码器**，没有 CTC、没有 WFST、没有词典：

**前端特征**：80 维 **log-Mel 谱**（25ms 窗、10ms 步长），不拼接 delta，不归一化——比 MFCC 简单得多。
**输入分段**：音频切成 **30 秒**的段，段与段间有少量重叠；长音频由「时间戳 token」在段间衔接。
**编码器**：多层 Transformer，全局建模整段 30 秒的表征。
**解码器**：自回归 Transformer，输入一串**特殊 token**（见下节），输出文本 token，词表为 BPE 子词。

最值得注意的设计是**完全没有「流式」**：Whisper 必须等一个 30 秒段输入完才能解码，是纯离线模型。它没有 HMM 的状态结构、没有 CTC 的对齐，一切对齐信息都由**解码器学会的软注意力**与**时间戳 token** 隐式表达。<span class="marginnote">Whisper 不流式、无词典，直接对比经典系统：GMM-HMM 需要词典 + WFST，RNN-T 需要联合网络 + 束搜索，注意力系统需要语言模型融合——Whisper 把这些全部丢掉，用一个「翻译式」的序列到序列模型通吃。代价是离线、延迟高、有幻觉倾向，但换来极简与通用。</span>

## 3 多任务 token 设计：一次推理做五件事

Whisper 最优雅的设计在**解码器的输入 token**：它把「任务、语言、时间戳」全部编码进 token 序列，一个模型用同一套参数处理所有任务。典型解码输入：

$$\text{[SOT]}\; \text{`<|en|>`}\; \text{`<|transcribe|>`}\; \text{`<|notimestamps|>`}\; y_1\, y_2 \cdots y_n$$

- **`<|startoftranscript|>`**：句首标记，标识「开始生成」。
- **`<|en|>`**：语种 token，告诉解码器「输出应为英语」——由编码器末端的语言分类头先预测。
- **`<|transcribe|>`** vs **`<|translate|>`**：任务 token——转写（原语言输出）还是翻译（转英语）。
- **`<|timestamps|>`** vs **`<|notimestamps|>`**：是否输出时间戳 token（如 <|1.24|>` 表示 1.24 秒）。<span class="marginnote">时间戳 token 把「音频对齐」变成「生成式」问题：模型在文本 token 之间穿插输出时间戳，等于让解码器自己「报时」——这套设计后来被语音大模型继承为「多模态 token」的雏形。</span>

训练时，这些 token 与文本一起构成**多任务目标**：

$$
\mathcal{L} = -\sum_{t} \log P(\text{token}_t \mid \text{token}_{\\lt t}, \text{logMel})
$$

即：给 30 秒 log-Mel 谱，按自回归方式最大化整个「任务 + 语种 + 文本」序列的似然。一个损失，同时训练转写、翻译、语言识别、时间戳四个任务——这就是 Whisper「一个模型五件事」的机理。

## 4 公式解析：log-Mel 谱特征与 30 秒分段

Whisper 的前端只有一步特征化：

$$
X = \log\Big( \text{Mel}\big( |\text{STFT}(x)|^2 \big) \Big)
$$

逐步拆解：

- **第一步，STFT 取幅度**：把波形 $x$ 分帧加窗后做短时傅里叶变换，取幅度谱平方（能量谱）。这步把「时间—波形」变成「时间—频率」。
- **第二步，Mel 滤波**：把频率轴按人耳感知的 Mel 刻度压缩成 80 个 bin（见《临界频带与 Mel 刻度》一节）——低频 bin 密、高频 bin 疏，匹配听觉特性。
- **第三步，取对数**：$\log$ 把能量动态范围（横跨好几个数量级）压到可训练的尺度——声音大小差异巨大，但对数谱让人耳「等响」的感知规律变成模型「线性」的输入。
- **第四步，30 秒切段**：30 秒音频 ≈ 3000 帧（10ms 步长），送入编码器。不拼接 delta、不做 CMVN——Whisper 让模型自己学统计特性，靠规模兜底。

**核心结论：Whisper 的特征尽量「原始」，把一切可学习的东西都交给模型。** 对比 MFCC（手工感知设计 + 差分 + 归一化），Whisper 只保留 log-Mel，剩下的全部靠 Transformer 的容量——这同样是「规模优先」哲学的一部分：能学的就不手工设计。

**辨析｜易错点：Whisper 的多任务 token 与提示词（prompt）不同。** 前者是 `<|transcribe|>` 这类**结构化任务控制 token**，训练时固定出现；后者是可选的前缀文本（如「以下是普通话的转写」），用于冷启动或术语引导。两者都能放进解码输入，但任务 token 是训练目标的一部分，prompt 更像「条件生成」的先验。另外，Whisper 的已知短板——**幻觉**（静音/音乐段凭空生成文本）与**不稳定时间戳**——是弱监督数据与自回归生成的双重产物，评测时要用 VAD 配合规避。

## 5 Whisper 之后的语音世界

Whisper 的影响远超 ASR 本身：

- **数据管道成为模板**：音频 + 网络文本对的弱监督范式，被后来的语音大模型（Qwen-Audio、Gemini）直接继承。
- **多任务 token 成为规范**：「任务 token + 语种 token + 时间戳 token」的设计，成为语音-语言统一模型的标配。
- **蒸馏与微调生态**：Whisper 权重公开，社区用它在低资源语言、特定领域（医疗、会议）上微调——「大模型开箱 + 小数据适配」取代「从零训练」。
- **评测基准升级**：Whisper 成为 FLEURS、Common Voice 的对照基线，几乎所有后续语音模型都报告「vs Whisper」的 WER。<span class="marginnote">Whisper 的离线属性让它在「实时字幕」场景受挫，催生了「Whisper 流式化」的研究（chunk 拼接、前缀缓存）；而它把「识别」做成「翻译式生成」，直接铺平了通往「音频语言模型」（把音频当 token 序列建模）的道路——那是语音大模型章节的主题。</span>

## 6 Whisper 的工程使用要点

把 Whisper 部署到真实场景，有一批「开箱即踩」的经验：

- **长音频的分段**：Whisper 吃 30 秒段——长音频要切段，段间要「上下文重叠 + 时间戳衔接」，否则句子被拦腰切断、词被重复识别。
- **幻觉的规避**：静音/音乐段 Whisper 会「脑补」文本——**前端先接 VAD**，只有人声段才喂 Whisper；另用「温度回退」（低置信度重新采样）缓解。
- **语言与任务 token**：推理时**显式指定语言**（如 `language="en"`）与任务（转写/翻译）比让模型「自己猜」稳——「猜语言」在多语混杂时会翻车。
- **提示词（prompt）工程**：用前文文本做 prompt（如「以下是普通话的转写」）能引导术语与风格——但 prompt 太长反而有害。
- **微调与蒸馏**：领域适配用「小数据微调」（几百小时）或「蒸馏成小模型」——Whisper-large 太大，蒸馏到 medium/small 是端侧部署的常规路线。

**公式解析：温度回退的幻觉缓解。**

$$
\hat{y} = \begin{cases} \text{beam}(T=0) & \text{置信度} \ge \theta \\ \text{sample}(T=0.8) & \text{置信度} < \theta \end{cases}
$$

- **第一步，看贪心生成**：温度 $T=0$ 的 beam 搜索是「最可能路径」——但可能「自信地」编出幻觉。
- **第二步，看置信度判断**：若输出置信度低于阈值 $\theta$——「模型自己也拿不准」——说明可能在幻觉。
- **第三步，看重采样**：低置信时改用**高温采样**（$T=0.8$）重新生成——引入随机性打破「重复/幻觉」的循环，常能得到更合理的输出。
- **第四步，看工程配合**：温度回退 + VAD 过滤是「Whisper 防幻觉」的双保险——**先防输入（VAD），再防输出（回退）**。

**核心要点：Whisper 工程 = 「分段衔接 + VAD 防幻觉 + 显式 token + 提示词 + 蒸馏部署」。** 模型强，但「喂对音频」与「控输出」仍是工程责任。

## 7 小结

- **Whisper** = 68 万小时弱监督数据 + 纯 Transformer 编码器—解码器 + 多任务 token，无词典、无对齐、无 WFST。
- **弱监督三支柱**：互联网数据对、规模压噪声、清洗三过滤（语言、时长、去重）。
- **多任务 token**（语种 + 任务 + 时间戳）让一个模型同时做转写、翻译、语种识别与时间戳。
- 前端只用 **log-Mel 谱**，把可学习的都交给模型；30 秒分段 + 自回归解码。
- 局限是**离线、有幻觉、时间戳不稳**；它的数据与 token 设计成为语音大模型的行业模板。
