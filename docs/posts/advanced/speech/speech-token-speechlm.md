## 为什么从 Speech Token 开始

上一节 AudioLM 证明「音频 = token 序列」足以生成自然的音乐与语音，但它生成的 token 是「音频专用」的，与文本 token 仍是两套互不相通的语言。**语音语言模型（Speech Language Model, Speech LM）** 走得更远：把语音 token 与文本 token 放进**同一个序列、同一个 Transformer**，让模型既能「听」（音频 token → 语义），也能「说」（语义 → 音频 token），还能「想」（在文本 token 层面推理）。SpeechGPT、VALL-E、Qwen-Audio 乃至 GPT-4o 的语音模式，都是这个范式下的产物。

**离散语音单元（Speech Token）** 是这个范式的「货币」：一段音频被神经编解码器切成 token 流，语言模型像处理词一样处理它们。理解 Speech Token 与语音 LM 的架构，就理解了「为什么语音大模型能端到端听说」——也理解了它的技术代价：序列过长、声学细节与语义纠缠、多任务难以平衡。

## 1 Speech Token：语音的「离散字母表」

**Speech Token**：把连续音频映射成离散编号序列的单元，由神经编解码器（SoundStream / EnCodec）的量化层或表征聚类（HuBERT）产出。按承载的信息层次，Speech Token 分两类，几乎所有语音 LM 都使用它们的组合：

- **语义 token（semantic / content token）**：低帧率（约 25 Hz），管「说了什么」——近似音素与词的层次。来自 HuBERT 聚类或编解码器浅层，序列短，适合让模型「思考」。
- **声学 token（acoustic / unit token）**：高帧率（约 50–100 Hz），管「怎么发声」——音色、韵律、说话人细节。来自编解码器 RVQ 深层，承载「渲染」，序列长。

两类 token 的差别，用一张表看清：

| 维度 | 语义 token | 声学 token |
| --- | --- | --- |
| 帧率 | 约 25 Hz | 约 50–100 Hz |
| 信息 | 音素 / 词级内容 | 音色、韵律、说话人 |
| 来源 | HuBERT 聚类、编解码器浅层 | 编解码器 RVQ 深层 |
| 序列长度 | 短 | 长 |
| 角色 | 语义「思考」 | 声学「渲染」 |

Speech Token 怎么从连续波形里「切」出来？主流神经编解码器（EnCodec / SoundStream）用**残差矢量量化（Residual Vector Quantization, RVQ）**：编码器先把波形压缩成低频表征帧（如 24 kHz 音频每 20 ms 一帧，约 50 Hz），再对每帧做多级量化——第一本码本量化出最粗糙的近似，残差交给第二本码本，逐级细化。EnCodec 常用 8 级码本，于是一帧对应 8 个 token：

| 码本级 | 承载信息 | 典型角色 |
| --- | --- | --- |
| 前 1–2 级 | 整体频谱轮廓 | 语义 token |
| 中间级 | 精细结构 | 过渡 |
| 末 1–2 级 | 高频细节、噪声纹理 | 声学 token |

越靠前的码本承载整体轮廓，越靠后的码本只补细节——**浅层量化出语义 token、深层量化出声学 token**，两类 token 并非来自两套模型，而是同一套 RVQ 的不同深度。

**核心概念：Speech Token 的价值 = 让音频进入语言模型的序列。** 文本 token 编码语义，Speech Token 编码「语义 + 音色 + 韵律」；一旦两者可互换地躺在同一序列里，模型就能做「听、说、想」的任意组合。<span class="marginnote">Speech Token 与「词」的关键差别：<strong>词是离散语义单位（可计数、可组合），Speech Token 是声学单位（带音色、依赖说话人）</strong>。同一句话由不同人说出，token 序列并不相同——所以语音 LM 往往需要「说话人嵌入」或「把音色独立出来」，这也是「语音 token + 说话人信息」常同时出现的原因。</span>

## 2 语音语言模型的架构：单流与双流

把 Speech Token 与文本 Token 组织进一个模型，有两种主流架构。

**单流（unified / single-stream）**：文本与语音 token 在同一序列里，用一套参数处理，任务用**特殊 token** 区分。一个序列可以写作：

$$[\text{speech}] \; s_1 s_2 \cdots s_a \; [\text{text}] \; w_1 w_2 \cdots w_b \; [\text{answer}] \; \hat{s}_1 \hat{s}_2 \cdots$$

训练时把「识别、合成、对话」全部表达成「序列补全」——**一个模型、一个损失（下一个 token 预测）、所有任务**。SpeechGPT 是早期代表：输入音频 → 识别成文本 → 用 LLM 思考 → 合成音频回答，整条链在同一个模型里完成。<span class="marginnote">单流的魅力是「简单」：任务边界由特殊 token 表达，模型只需要学会「接着写」。代价是文本与语音共享一套表征，语音的声学噪声可能污染语义推理；双流架构正是为了「净化」语义侧而出现。</span>

**双流（dual-stream / two-tower）**：文本与语音各走一条流，中间用桥接层对齐。语音编码器把音频转成语音侧表征，再通过交叉注意力或投影与文本侧相连。优点是文本语义不被声学噪声污染；缺点是结构复杂、跨模态对齐难，训练也更重。

单流与双流的取舍可以总结为：

| 维度 | 单流 | 双流 |
| --- | --- | --- |
| 序列组织 | 文本与语音同序列 | 各走一条流 + 桥接 |
| 表征纯度 | 语义受声学噪声影响 | 语义与声学解耦 |
| 实现难度 | 低（一个模型） | 高（对齐训练） |
| 代表 | SpeechGPT | VALL-E（文本—音频两流） |

## 3 公式解析：统一序列补全的损失

语音 LM 的训练目标，就是把「所有任务」写成同一个自回归条件语言模型的极大似然。设序列中第 $l$ 个 token 为 $t_l$，其前文为 $t_{\lt l}$，任务 token（如 `transcribe`、`synthesize`）为 $c$，则：

$$\mathcal{L} = \sum_{l} - \log P\big( t_l \mid t_{\lt l},\, c \big)$$

- **第一步，看懂前文 $t_{\lt l}$**：$t_{\lt l}$ 是位置 $l$ 之前的所有 token——既包括文本 token，也包括语音 token。模型每预测一个 token，都要「看到」前面所有模态。
- **第二步，看懂任务 token $c$**：$c$ 告诉模型「现在干什么」。`transcribe` 把音频 token 序列翻译成文本；`synthesize` 把文本补全成音频 token；`dialogue` 则混合两者。任务边界被编码成「条件」，而不是「不同模型」。
- **第三步，看损失为何统一**：所有任务共享同一个 $P$，梯度同时更新一套参数——这就是「一个模型多件事」的机理：识别、合成、翻译、对话只是**不同的条件与序列布局**。
- **第四步，看与单任务模型的差别**：传统 ASR 的损失只对文本 token 求期望；语音 LM 对「混合序列」里的每个 token（含音频 token）都求期望。模型被迫同时学会「听懂」与「说出」。

## 4 三大工程挑战

Speech Token 的代价藏在数字里。一段 10 秒的语音，按 25 Hz 语义 token 是 250 个，按 100 Hz 声学 token 则是 1000 个——而对应文本可能只有 20 来个词。这让语音 LM 面对三个绕不开的挑战：

- **序列过长**：音频 token 比文本 token 密集一到两个数量级，注意力与生成成本随之暴涨。工程上常用**降采样**、**声学流并行**（如 VALL-E）或「先语义后声学」的两阶段生成来缓解。
- **内容与音色纠缠**：同一个词，不同人、不同情绪说出来 token 都不同。若不把「说话人」解耦，模型分不清「说的内容」与「谁在说」。主流做法是显式注入说话人嵌入，或用归一化把音色从内容里剥离。
- **多任务平衡**：识别、合成、翻译放在一个模型里，梯度可能互相打架——合成任务想让声学 token 更精细，识别任务想让表征更抽象。常用多任务损失加权、分阶段训练（先识别后合成）来驯服。

一个具体的应对是**两阶段生成**：第一阶段只用语义 token 生成「内容」，第二阶段以语义 token 为条件生成声学 token。这样序列被切成两段管理，音色也能在第二阶段独立控制。对比起来：

| 方案 | 序列组织 | 音色控制 | 代表 |
| --- | --- | --- | --- |
| 单阶段 | 语义 + 声学同一序列 | 弱（隐式） | SpeechGPT |
| 两阶段 | 先语义后声学 | 强（独立条件） | VALL-E |

**核心要点：Speech Token 的「通用」与「代价」是一体两面。** 通用性来自把音频离散进语言模型的序列；代价则是序列暴涨与信息纠缠。理解了这三点，就能明白为什么后面会看到「语音 token + 说话人嵌入」的组合，以及为什么端到端语音对话模型要做专门的结构设计。

## 5 辨析｜离散与连续，级联与端到端

- **辨析｜离散 token vs 连续表征：** 离散 token 能直接复用语言模型的训练与推理框架（稳定、可缓存、可检索），代价是**量化丢失连续声学信息**——音色微差、微韵律被抹平。连续表征（如 GPT-4o 语音的隐层向量）信息无损，却不能直接套用 token 预测框架。这不是纯工程取舍，而是「语言的抽象」与「声音的实在」之间的张力。
- **辨析｜语音 LM vs 级联系统：** 级联方案「ASR + LLM + TTS」用三个模型拼出对话能力，成熟、可控、各环节可替换；语音 LM 一个模型端到端，免去中间文本的往返，延迟低、更自然，但难调试、难干预。把两者并排看：

| 维度 | 级联（ASR+LLM+TTS） | 语音 LM |
| --- | --- | --- |
| 模型数量 | 三个独立模型 | 一个模型 |
| 中间表示 | 文本（显式） | token 序列（隐式） |
| 可控性 | 各环节可单独替换 | 难干预 |
| 端到端自然度 | 受级联误差影响 | 高 |
| 工程成熟度 | 高 | 研究前沿 |

## 6 小结

- **Speech Token** 把连续音频变成离散 token，分语义 token（25 Hz、管内容）与声学 token（50–100 Hz、管音色）两类。
- **单流架构**把文本与语音放进同一序列，用任务 token 区分任务；**双流架构**各走一条流再加桥接，语义更纯但更难训。
- **统一损失** $\mathcal{L} = \sum_l -\log P(t_l \mid t_{\lt l}, c)$ 让「识别、合成、对话」共享一套参数。
- **三大挑战**——序列过长、内容—音色纠缠、多任务平衡——决定了语音 LM 的结构设计。
- **离散 vs 连续**是「抽象 vs 保真」的权衡；**级联 vs 端到端**是「可控 vs 自然」的权衡。
