## 为什么从歌声合成开始

前面的 TTS 与 VC 都处理**说话声**。但有一类声音极其特殊——**歌声**。**歌声合成（Singing Voice Synthesis, SVS）**：输入乐谱（音符序列 + 节奏）+ 歌词，输出会「唱歌」的音频。它比 TTS 难得多，因为唱歌对**音高的精确性**要求是苛刻的：说话时「音高大概对」就行（语调是平滑的曲线），唱歌时「音高必须落在规定的音符上」——唱走一个半音，听众立刻皱眉。

SVS 处于语音与音乐的交界：它用 TTS 的语言学能力（歌词发音），又要满足音乐学的要求（音高、节奏、和声、呼吸、颤音）。它是理解「语音大模型做音乐」「歌声转换」的必经跳板，也是本专题从「人声」走向「音乐」的过渡。

## 1 任务定义：比 TTS 多了「音高与节奏」

SVS 的标准输入是一份「**乐谱 + 歌词**」：

$$
\text{输入} = \big\{ \text{音符序列 } (f_i, d_i)_{i=1}^{N}, \quad \text{歌词 } \text{音节序列} \big\}
$$

- $f_i$：第 $i$ 个音符的**基频**（音高），来自 MIDI 音高（如 A4 = 440 Hz）。
- $d_i$：音符的**时值**（节奏），几拍、几分音符。
- 歌词：与音符**对齐**的歌词音节——一个音符常对应一个音节（一字一音），但也有一音多字、一字多音的装饰音。

输出：一段歌声波形，要求**音高严格落在 $f_i$ 上、时长符合 $d_i$、歌词清晰可辨**。

**核心概念：SVS 与 TTS 的第一性差异是「音高从自由度变成约束」。** TTS 的 F0 是「模型自由预测的韵律」，SVS 的 F0 是「谱面规定的目标」——模型不是「预测」音高，而是「实现」音高。这个转变让 SVS 的建模对象从「自然度」转向「**音准 + 节奏 + 表现力**」三元组。<span class="marginnote">「音准」的感知是非线性的：人对歌唱音高的偏差极敏感，±50 音分（半音的一半）已能被察觉，±100 音分（一个半音）就是「走音」。相比之下说话时 F0 偏差几百音分听众也未必在意——这就是为什么「说话模型」直接搬到唱歌会「唱歌跑调」。</span>

## 2 歌声的声学特性：难在哪

歌声与说话声共享声道模型，但多了几样「音乐性」成分：

**精确 F0 台阶**：说话 F0 平滑滑动，唱歌 F0 在音符间**跳变**（从一个音高跳到另一个）——跳变处正是歌声的「骨架」。
**颤音（vibrato）**：长音上 F0 周期性地轻微波动（约 5–7 Hz、±30–70 音分），是歌声「活」的关键。没有颤音的长音像「直愣愣的警报」。
**延音与辅音**：元音被拉长（唱「啊——」），辅音快速闪过；歌唱的发音比说话更「慢吞吞、拖长音」。
**呼吸与气息**：句间换气、气声、强音头（attack）——气息是歌声表现力的核心。
**多音高范围**：歌声的 F0 范围远超说话（男中音到花腔女高音可跨 3 个八度），模型要在宽范围上稳定发声。

**核心要点：歌声 = 说话的音段结构 + 音乐的音高骨架 + 表现性的细微波动。** 建模歌声，本质是在「谱面规定的骨架」上「长出自然的血肉」——骨架来自输入，血肉来自生成模型。

## 3 建模方法谱系

SVS 的方法沿「越来越端到端、越来越生成式」演进：

| 范式 | 代表 | 思路 | 音高控制 |
| --- | --- | --- | --- |
| **传统参数** | HMM-singer、Vocaloid（拼接） | 波形拼接或参数合成 | 显式 F0 建模 |
| **早期端到端** | DeepSinger、ByteSing | 编码器—解码器从音符/歌词生成谱 | 学到的注意力 |
| **显式 F0 端到端** | VISinger、DiffSinger | 显式预测/指定 F0 + 生成模型 | F0 作为硬输入 |
| **神经编解码** | ACE-Step、SingSong（歌声转换） | 离散 token + 语言模型 | token 隐式 |

**传统方法**：Vocaloid 用拼接（把录音库的音节拼成歌），HTS-singer 用 HMM 参数合成——音准好、可控，但「机器味」重。
**早期端到端**：DeepSinger（微软，2019）把「音符 + 歌词」编码进序列到序列模型，让模型学「音符 → 歌声谱」——但模型自己学 F0 容易跑调。
**显式 F0 端到端**：**关键进化**——不再让模型「预测」F0，而是把**谱面 F0 直接作为输入**（硬条件）喂给生成器。模型只负责「在这个音高上唱出自然的声音」。DiffSinger、VISinger 都是这条线：显式 F0 让音准「有保证」，生成模型负责自然度。<span class="marginnote">「显式 F0 作为输入」是 SVS 相对 TTS 最深刻的架构差异：TTS 里 F0 是「中间变量」（模型预测它），SVS 里 F0 是「外部指定」（从乐谱来）。这好比 TTS 是「自己编旋律」，SVS 是「照着谱子演奏」——照着谱子，音准就有谱可依。</span>

**公式解析：SVS 的条件生成目标。**

$$
p(y \mid \underbrace{F0_{\text{notes}}, D_{\text{notes}}}_{\text{谱面音高节奏}}, \underbrace{\text{歌词音素}}_{\text{语言}}, \underbrace{e_{\text{spk}}}_{\text{音色}})
$$

- **第一步，看四路条件**：谱面 F0（音高）、谱面时值（节奏）、歌词音素（内容）、说话人/歌手嵌入（音色）。SVS 模型 = 在这四个条件约束下生成波形。
- **第二步，看 F0 的角色**：$F0_{\text{notes}}$ 是**离散音符序列**（如 [A4, A4, C5, E5]），要经「平滑/插值」变成**逐帧 F0 曲线**——音符之间的过渡（滑音、起音）由模型补充。这一步把「乐谱」变成「声学目标」。
- **第三步，看时长**：$D_{\text{notes}}$ 决定每个音符持续多少帧，配合歌词音节对齐，形成「音节—音符—帧」的三级映射。
- **第四步，看生成**：生成器（VITS 式/扩散式）在这四个条件下重建歌声；训练时用真实歌声做重建目标。

**核心结论：SVS 的目标是「用谱面约束生成自然歌声」——谱面是硬骨架，生成模型是软组织。**

## 4 音高与节奏的评测

SVS 的评测在 TTS 的「自然度」之外，加了两把音乐尺子：

- **音准（pitch accuracy）**：合成歌声的 F0 与谱面 F0 的偏差——自动提取合成 F0，算与目标音符的**平均音分偏差**与走音率。
- **节奏准确（duration accuracy）**：每个音符的实际时长与谱面时值的偏差。
- 再加上自然度 MOS、相似度（像不像目标歌手）与歌词可懂度。

**辨析｜易错点：SVS 与 TTS 的「端到端」是两码事。** 有人以为「SVS 就是 TTS 加个音符输入」——不。TTS 的「端到端」指「文本 → 波形」；SVS 的输入是「乐谱 + 歌词」，比 TTS 多一条**独立的音高时间线**，且这条时间线是**硬约束**而非软条件。直接把 TTS 模型拿来唱歌，会犯两个错：音高自由飘（不跟谱）、节奏失控（音符时长不听使唤）。所以 SVS 必有「时长预测/对齐」与「F0 指定」两个 TTS 没有的模块。<span class="marginnote">SVS 数据稀缺是硬约束：带乐谱对齐标注的歌唱数据远少于语音（公开集如 M4Singer、OpenSinger 都在百小时量级）。于是「用自监督表征做内容 + 少量歌唱数据微调」成为主流——SVS 与 SVC（歌声转换）因此深度纠缠：SVC 可以「把任何语音转成歌手的嗓音」，本质上给 SVS 提供了「不用对齐乐谱」的捷径。</span>

## 5 歌声合成的工程细节

把 SVS 系统做好，一批「音符级细节」决定成败：

- **音符边界与滑音**：乐谱的音符是「阶跃」，但歌声有**滑音（portamento）**——从 C 滑到 E 不是瞬间跳变。工程上要在音符边界插值 F0 过渡（起音/滑音），否则「像电子琴」。
- **发音与音符的错位**：歌词音节常「先于音符起始」（辅音提前、元音对拍）——**对齐要从「元音起点」算**，否则歌词「黏拍」。
- **颤音（vibrato）的建模**：长音的自然感来自颤音——**显式建模颤音参数**（频率、幅度、起止）比让模型「瞎学」更可控；但过度的固定颤音又「假」——「学 + 控」结合。
- **呼吸声与换气**：句间换气音、气声是歌声的「血肉」——数据里有、模型要会学；合成时按乐句结构「插换气」。

**公式解析：音符到 F0 曲线的映射。**

$$
\text{F0}(t) = \text{noteF0} + \underbrace{\text{portamento}(t)}_{\text{滑音}} + \underbrace{\text{vibrato}(t)}_{\text{颤音}}
$$

- **第一步，看音符基值**：$\text{noteF0}$ 是当前音符的标称基频——「谱面要求」。
- **第二步，看滑音项**：$\text{portamento}(t)$ 在音符切换处加过渡——从一个音符「滑」到下一个，消除阶跃感。
- **第三步，看颤音项**：$\text{vibrato}(t)$ 在长音上叠加周期性微调——让长音「活」。
- **第四步，看可解释性**：把 F0 拆成「标称 + 滑音 + 颤音」三项，每一项都能单独控制——**SVS 的可控性来自这个分解**（关掉颤音 = 直愣愣；加滑音 = 圆润）。

**核心要点：SVS 的工程 = 「F0 分解（标称/滑音/颤音）+ 发音对齐 + 呼吸建模」。** 音符是骨架，滑音与颤音是血肉，换气是呼吸——三者齐了歌声才「像人唱」。

## 6 小结

- **SVS** 从「乐谱 + 歌词」生成歌声，比 TTS 多「音高精确 + 节奏精确」两大硬约束。
- 歌声的声学特性：**F0 台阶、颤音、延音、呼吸**——谱面是骨架，生成模型长血肉。
- 方法谱系：拼接/参数 → 早期端到端（模型学 F0，易跑调）→ **显式 F0 端到端**（谱面 F0 作硬输入）→ 神经编解码。
- 评测加两把尺子：**音准偏差**（音分）与**节奏准确**，再加自然度与相似度。
- SVS ≠ TTS 加音符，它的音高/时长是硬约束，需要专门的对齐与 F0 模块。

**附：关键概念速记**

- **SVS**：乐谱 + 歌词 → 歌声——比 TTS 多「音高精确 + 节奏精确」两大硬约束。
- **F0 台阶**：歌声在音符间跳变——谱面规定音高，不是「自由预测」。
- **颤音（vibrato）**：长音上 F0 的周期性波动——歌声「活」的关键。
- **显式 F0 输入**：谱面 F0 作为硬条件——音准「有谱可依」，生成器只管自然。
- **音符 → F0 曲线**：标称 F0 + 滑音 + 颤音——可解释、可控制的三项分解。
- **音域**：歌声跨多个八度——模型要在宽 F0 范围稳定发声。
- **评测**：音准偏差（音分）+ 节奏准确 + 自然度/相似度。
- **SVS ≠ TTS 加音符**：音高/时长是硬约束，需要专门的对齐与 F0 模块。

**延伸思考**：SVS 的「谱面 F0 作硬条件」与 TTS 的「F0 自由预测」，是「**约束与自由**」的两种哲学——唱歌时音高是「规定动作」，说话时语调是「即兴发挥」。这启示：**当任务有「外部规范」时（乐谱、节拍、剧本），把规范当「条件输入」而非「让模型猜」**，往往更稳更可控。SVS 的显式 F0 就是「信任外部规范」的典范。
