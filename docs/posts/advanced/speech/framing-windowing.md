## 为什么从分帧加窗开始

预加重之后，我们手里是一整段干净的数字波形。但如果直接对它做傅里叶变换，会得到一个**毫无意义的结果**——因为整段语音从头到尾都是变化的：这句话的元音、辅音、停顿混在一起，频谱每秒都在变。傅里叶变换假设信号平稳，而语音恰恰相反。

所以语音分析采取了一个经典的折中：**把长波形切成一小段一小段，假定每段内部近似平稳，逐段做频谱分析**。这就是**分帧（framing）**；而每段在切开时不能「硬切」，要乘以一个平滑的**窗函数（window）**。这一课的两个概念——短时平稳假设与窗函数——是把「时间波形」变成「时间—频谱」的最后一跳，也是下一课 STFT 与语谱图的直接铺垫。

## 1 短时平稳假设

**核心概念：短时平稳（short-time stationarity）**——语音的声道形状（发什么音）约在 10–100 ms 的尺度上变化；如果取一段足够短的语音（如 20–30 ms），期间声道近似固定，信号可以看作**准平稳**的。于是可以用平稳信号分析的手段（FFT、自相关）来处理这一段，得到的谱近似代表这一时刻的声道特性。

这个假设并不是理所当然的：它把「无限长的非平稳信号」拆成「有限长的准平稳片段」，本质是一种**局部近似**。帧太长，段内语音已明显变化，假设失效；帧太短，频率分辨率不足，低频细节（基频、共振峰）看不清。工程上 20–25 ms 是语音识别的常用折中，30–40 ms 更适合低基频的基音分析。<span class="marginnote">这里藏着一条贯穿全文的权衡曲线：<strong>时间分辨率与频率分辨率不可兼得</strong>。加博尔（D. Gabor，1946）把这一约束写成 $\Delta t \cdot \Delta f \ge 1/(4\pi)$ 量级的不等式——它与第一级《函数与极限》里「局部线性近似」的精神一致：想看得越细，能看清的窗口就越小。</span>

## 2 分帧：帧长、帧移与重叠

分帧把波形切成一串**帧（frame）**，每个帧是一个等长的样本段。两个参数决定怎么切：

**帧长（frame length）** $N$：一帧包含的样本数，$N = \text{round}(f_s \times T_{frame})$。例：$f_s = 16$ kHz、帧长 25 ms，则 $N = 400$ 个样本。
**帧移（frame shift / hop）** $H$：相邻两帧起点之间的距离（样本数）。例：帧移 10 ms，则 $H = 160$ 个样本。

**重点：帧移小于帧长，相邻帧大幅重叠。** 25 ms 帧长、10 ms 帧移意味着每帧与前帧有 $400 - 160 = 240$ 个样本重叠（60%）。重叠不是浪费——它保证帧间特征平滑过渡、不遗漏音节边界的瞬变，也让基音/共振峰的轨迹在时间上连续。<span class="marginnote">帧移 10 ms 并非巧合：特征序列以 100 Hz 的帧率产生，与人类发音的音节节奏、以及 HMM/CTC 建模的「逐帧」粒度都天然对齐。几乎所有的语音工具包都默认 25 ms / 10 ms。</span>

总帧数由信号长度决定：

$$\text{num\_frames} = \left\lfloor \frac{L - N}{H} \right\rfloor + 1$$

$L$ 是信号总样本数。不足一帧的末尾通常直接丢弃，或用零填充补齐。

## 3 加窗：为什么不能直接硬切

把信号切成帧，等价于把无限长信号乘以一个矩形函数——**在频域就是与一个 sinc 函数做卷积**。于是问题来了：

**核心概念：频谱泄漏（spectral leakage）**——对一个有限长片段做傅里叶变换，得到的谱不是「真实谱」，而是真实谱与窗函数频谱的卷积。一个纯净的单频正弦，经过矩形窗截断后，能量不再集中在一条谱线上，而是摊成一个主瓣加一串旁瓣的形状——能量「泄漏」到了附近的频率上。<span class="marginnote">直觉：矩形窗在边界处「啪」地一刀切，这个陡峭的跳变在频域对应着丰富的高频分量（旁瓣）。窗越平滑，边界越缓，旁瓣就越小。泄漏是「截断」的数学必然，无法消除，只能抑制。</span>

矩形窗的旁瓣只衰减 **−13 dB**——旁瓣里的能量可能盖过真正的弱信号（如轻声、辅音段）。要抑制旁瓣，就要用**两端平滑过渡**的窗函数。

**辨析｜易错点：** 加窗「牺牲」了一点幅度（窗两端接近 0，帧两端的信息被有意弱化），换来的是旁瓣的大幅下降。这不是「数据丢了」，而是**用幅度精度换频谱纯度**——后续短时能量、自相关等计算通常要按窗的有效增益做归一化补偿。

## 4 常用窗函数

设帧内样本 $n = 0, 1, \dots, N-1$，常用窗函数及关键指标：

| 窗函数 | 定义 $w[n]$ | 主瓣宽度 | 第一旁瓣 |
| --- | --- | --- | --- |
| 矩形（Rectangular） | $1$ | $4\pi/N$ | −13 dB |
| 汉宁（Hann / Hanning） | $0.5 - 0.5\cos\left(\frac{2\pi n}{N-1}\right)$ | $8\pi/N$ | −31 dB |
| 汉明（Hamming） | $0.54 - 0.46\cos\left(\frac{2\pi n}{N-1}\right)$ | $8\pi/N$ | −43 dB |
| 布莱克曼（Blackman） | $0.42 - 0.5\cos\left(\frac{2\pi n}{N-1}\right) + 0.08\cos\left(\frac{4\pi n}{N-1}\right)$ | $12\pi/N$ | −58 dB |

**重点：旁瓣压得越低，主瓣越宽；主瓣越宽，频率分辨率越差。** 这是一条无法绕开的交换——窗函数在频域的形状决定了「泄漏抑制」与「分辨率」的取舍：

**汉明窗（Hamming）**：旁瓣 −43 dB，主瓣适中。它是语音特征提取的默认选择（MFCC、FBank、Kaldi、HTK 都默认 Hamming）——对共振峰与谱包络的提取，主瓣宽度足够、旁瓣足够低。
**汉宁窗（Hann）**：旁瓣 −31 dB，主瓣同宽但两端严格归零。用于基音估计、音乐分析时更稳健（对窗两端的噪声不敏感）。
**布莱克曼窗（Blackman）**：旁瓣 −58 dB，主瓣最宽。需要极低泄漏的测量场景（如频谱分析仪）使用，代价是频率分辨率损失约 3 倍。<span class="marginnote">汉明与汉宁只差两个系数（0.54/0.46 vs 0.5/0.5），工程上常被混用，但行为不同：汉明在边界不归零，旁瓣更低；汉宁在边界严格归零，时域更平滑。特征提取默认汉明，做精确谱分析常用汉宁或布莱克曼。</span>

## 5 公式解析：加窗在频域做了什么

把「加窗 = 频域卷积」用公式说透。设窗函数频谱为 $W(e^{j\omega})$，加窗后帧的频谱 $Y(e^{j\omega}) = X(e^{j\omega}) * W(e^{j\omega})$——卷积。

以汉明窗为例，它的频谱是三个平移的**狄利克雷核（Dirichlet kernel，即归一化 sinc）**之和：

$$W_{ham}(\omega) = 0.54\,D(\omega) + 0.23\,D\!\left(\omega - \frac{2\pi}{N-1}\right) + 0.23\,D\!\left(\omega + \frac{2\pi}{N-1}\right)$$

- **第一步：矩形窗的频谱是狄利克雷核 $D(\omega)$。** 矩形窗长度 $N$，其离散时间傅里叶变换是 $D(\omega) = \frac{\sin(N\omega/2)}{\sin(\omega/2)}$，主瓣宽度 $4\pi/N$，第一旁瓣 −13 dB。这是所有窗函数的「母体」。
- **第二步：汉明窗 = 三个 $D$ 的加权平移。** 把常数 0.54 的贡献放在 0 处，把余弦项 $0.46\cos(2\pi n/(N-1))$ 拆成两个指数（$0.23 e^{\pm j2\pi n/(N-1)}$），分别平移 $D$ 到 $\pm 2\pi/(N-1)$。**旁瓣抑制的秘密就在这里**：主瓣两侧的头两个旁瓣恰好相位相反，叠加后相互抵消，于是第一旁瓣从 −13 dB 压到 −43 dB。
- **第三步：代价是主瓣加宽。** 三个核叠加，主瓣宽度从 $4\pi/N$ 翻到 $8\pi/N$——频率分辨率损失一半。这就是第 4 节那张表格里「主瓣宽、旁瓣低」这对矛盾的具体来源。
- **第四步：分辨率到底多少。** 帧长 $N$ 个样本、采样率 $f_s$，FFT 频率分辨率 $\Delta f = f_s / N$。16 kHz、25 ms 帧（$N=400$）给出 $\Delta f = 40$ Hz——足够分辨基频（男声 ~100 Hz）与共振峰（间隔数百 Hz），但分辨不了 20 Hz 内的细节。**帧长与分辨率绑定，想看清更低频，就得用更长的窗。**

用 numpy 把「分帧 + 加窗」写成一个函数，就是下面这几行：

```python
import numpy as np

def frame_and_window(x, frame_len=400, hop=160, win_type="hamming"):
    """分帧 + 加窗：返回 [num_frames, frame_len] 的加窗帧矩阵。"""
    n = len(x)
    num_frames = (n - frame_len) // hop + 1
    idx = np.arange(frame_len)[None, :] + hop * np.arange(num_frames)[:, None]
    frames = x[idx]                                  # 步幅索引切出各帧

    if win_type == "hamming":
        w = 0.54 - 0.46 * np.cos(2 * np.pi * np.arange(frame_len) / (frame_len - 1))
    elif win_type == "hann":
        w = 0.5 - 0.5 * np.cos(2 * np.pi * np.arange(frame_len) / (frame_len - 1))
    else:                                            # 矩形窗（不做平滑）
        w = np.ones(frame_len)
    return frames * w                                # 逐帧乘窗
```

## 6 从分帧到短时谱

分帧加窗做完，每个帧是一个「准平稳的短段」，逐帧做 FFT，就得到一帧一列的频谱——把时间轴与频率轴拼起来，就是下一课的**语谱图（spectrogram）**，也是 MFCC、FBank 等一切特征的第一级产物。

现代工具包把这套参数固化成了接口：librosa 的 `librosa.util.frame`、`librosa.stft`，torchaudio 的 `torchaudio.functional.spectrogram`，Kaldi 的 `compute-fbank-feats`，窗口默认全是汉明、帧长 25 ms、帧移 10 ms。<span class="marginnote">值得记住的对应：25 ms / 16 kHz → 帧长 400 样本、FFT 常用 512 点（补零到 512，频率分辨率仍由 400 决定，补零只让谱线更密、不增加真实分辨率）。帧移 10 ms → 特征帧率 100 Hz。</span>这些参数在不同模型（GMM-HMM、CTC、Attention）里几乎原封不动地延续——**「25 ms 汉明窗」是语音领域最忠实的传统。**

分帧参数不只在离线工具里固定——在**流式识别**里，它直接决定了延迟预算：帧移 10 ms 意味着特征每 10 ms 产出一帧，模型必须在这 10 ms 内完成一帧的处理，否则实时性告破。这也是为什么流式 ASR（RNN-T、U2/U2++）的编码器下采样倍数总是与帧移对齐，让「10 ms 一帧」成为端到端系统里流式 chunk 的基本时间单位。到本专题《流式识别》一课，我们会看到这一课的帧移如何一路传导成流式架构的延迟设计。

不同任务对窗与帧长有自己的偏好，列成一张速查表：

| 任务 | 常用窗 | 典型帧长 | 典型帧移 |
| --- | --- | --- | --- |
| ASR 特征（MFCC/FBank） | 汉明 | 25 ms | 10 ms |
| 基音估计 | 汉宁 | 30–40 ms | 5–10 ms |
| 音乐频谱分析 | 布莱克曼 | 40–50 ms | 10 ms |

**选择逻辑只有一条：先定需要多细的频率分辨率（帧长），再在旁瓣与主瓣之间选窗。** 需要看清低频（低基频、慢共振峰）就加长帧；被旁瓣掩盖了弱信号就换旁瓣更低的窗。参数没有「最优」，只有「够用」。

## 7 小结

- **短时平稳假设**：语音在 20–30 ms 内近似平稳，可逐段做谱分析；帧过长假设失效，帧过短分辨率不足。
- **分帧参数**：帧长 25 ms、帧移 10 ms 是事实标准（16 kHz 下 $N=400$、$H=160$，帧间 60% 重叠）。
- **频谱泄漏**：截断 = 频域卷积；矩形窗旁瓣仅 −13 dB，会掩盖弱信号，必须用平滑窗抑制。
- **窗函数权衡**：主瓣越窄、旁瓣越高的矛盾无法回避——矩形（−13 dB）< 汉宁（−31 dB）< 汉明（−43 dB）< 布莱克曼（−58 dB）；特征提取默认**汉明窗**。
- **频率分辨率** $\Delta f = f_s/N$；16 kHz、25 ms 帧 → 40 Hz，这是「看得清什么」的物理边界。
