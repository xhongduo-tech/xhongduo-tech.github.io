## 为什么从神经编解码器开始

语音大模型想用「语言的玩法」处理音频——把音频当成**离散 token 序列**，像词一样喂给 Transformer。但「怎么把连续波形变成离散 token」曾经是个问题：直接把波形分帧量化（PCM）比特率太高、浪费；传统编解码器（Opus 等）压缩率高但 token 没有「语义」。**神经音频编解码器（neural audio codec）** 解决了这个接口问题：用神经网络把波形压成**紧凑的离散 token**，且 token 保留了「可重建的声学信息」与「可学习的语义结构」。

**SoundStream**（2021，谷歌）与 **EnCodec**（2022，Meta）是两条奠基工作。它们用「编码器 + 残差向量量化（RVQ）+ 解码器 + 对抗/重建损失」把 48kHz 音频压到几千 bps 还能高保真重建——更重要的是，**它们产出的离散 token 成了 AudioLM、VALL-E、MusicLM 等音频语言模型的「词汇表」**。理解神经编解码器，就理解了「音频如何被语言模型『读』进去」。

## 1 任务与传统对比

**音频编解码（audio coding）** 的目标：把波形 $x$ 压成**紧凑比特流**，再解码恢复 $\hat x \approx x$。核心指标是**比特率（bitrate）**——每秒多少比特——与**重建质量**（MOS/PESQ）的权衡。

- **传统编解码器**（Opus、AAC）：信号处理 + 心理声学模型，在 12–32 kbps 上做到「几乎无损」。但它们输出的是**连续压缩比特**，没有「离散、可计数」的 token 结构——不好喂给神经网络当「词」。
- **神经编解码器**：用神经网络学习「压缩的离散表示」——输出一串**离散 token**（每个 token 是码本中的一个编号），既低比特又**结构化**。SoundStream 用 3 kbps 达到接近传统编解码器的质量，而 token 化的表示直接服务下游大模型。<span class="marginnote">比特率的换算直觉：EnCodec 在 24 kHz 下 1.5 kbps ≈ 每秒 375 个 token（每个 token 2 bit 的码字×多层）。对比语音大模型的「词表」，音频 token 是「帧级」的——每秒上百个，序列比文本长得多。这解释了为什么音频语言模型的计算量天然大，也解释了为什么「帧级离散化」是它们的命门。</span>

## 2 架构三件套：编码器、量化、解码器

神经编解码器的标准架构：

```text
波形 x → 编码器（卷积下采样） → 帧级潜变量 z → RVQ 量化器 → 离散 token → 解码器（反卷积） → 波形 x̂
```

- **编码器**：卷积网络把波形**下采样**成帧级连续潜变量 $z$（每秒约 50–100 个帧）。
- **量化器**：把 $z$ 的每个帧**离散化**成 token——关键组件，见下节。
- **解码器**：反卷积网络把离散 token 重建回波形。

训练损失（与声码器几乎同构）：
- **重建损失**：波形/频谱的 L1 距离（让 $\hat x \approx x$）。
- **对抗损失**：判别器判断波形真假（HiFi-GAN 系，让重建「像真声音」）。
- **量化损失**：码本学习（EMA 或直通梯度）。
- **特征匹配 / 多尺度频谱**：稳定训练 + 细节保真。

**核心概念：神经编解码器 = 「编码器 + 量化器 + 解码器」的生成模型，训练目标与神经声码器同构。** 它与 WaveNet/HiFi-GAN 的关系是「倒过来」：声码器是「参数 → 波形」，编解码器是「波形 → token → 波形」。两者共享「神经网络重建波形」的核心，只是中间表示从「连续参数」换成了「离散 token」。

## 3 公式解析：残差向量量化（RVQ）

**残差向量量化（Residual Vector Quantization, RVQ）** 是神经编解码器的核心，也是「多码本分层」的来源：

$$
z_1 = z, \qquad \text{码字}_k = \text{quantize}(z_k), \qquad z_{k+1} = z_k - \text{码字}_k
$$

逐步拆解：

- **第一步，看第一层量化**：$z_1 = z$ 是原始潜变量，第一层码本把 $z_1$ 量化为最近的码字 $\hat z_1$（用向量距离）。
- **第二步，看残差传递**：算**残差** $z_2 = z_1 - \hat z_1$——第一层「没表达干净的部分」。第二层码本量化**残差**，得 $\hat z_2$。
- **第三步，看逐层叠加**：每层量化上一层残差，共 $N$ 层（EnCodec 用 32 层、SoundStream 用 12–16 层）。重建时把各层码字**加起来**：$\hat z = \hat z_1 + \hat z_2 + \cdots + \hat z_N$——层越深，残差补得越细，重建越准。
- **第四步，看比特率控制**：每层一个码本（如 1024 个码字 = 10 bit），$N$ 层就是 $10N$ bit/帧。**想降比特率就只用前几层**（量化粗糙但省比特），想高质量就用全部层——「**质量—比特率**」的旋钮就是层数。

**核心结论：RVQ = 「逐层量化残差」，用多层小码本逼近连续向量。** 它解决了「单层码本太大（1024^32 无法穷举）」的问题——用 $N$ 个 1024 码本组合出 $1024^N$ 的表示空间。**每层 token 对应一个「粒度层级」**：浅层是整体框架、深层是精细细节——这个结构后来被语言模型当成「不同粒度的时间线」使用。

**辨析｜易错点：神经编解码器 ≠ 声码器，尽管长得像。** 声码器（WaveNet、HiFi-GAN）是「连续声学参数 → 波形」；编解码器是「波形 → 离散 token → 波形」。关键差异在**离散 token**——声码器不产生离散表示，编解码器以离散表示为「产品」。它们共享生成器与对抗训练，但定位不同：声码器服务合成，编解码器服务**压缩 + 表示**。<span class="marginnote">「离散 token 有语义吗？」——起初没有，token 只是码本编号。但 AudioLM 的惊人发现是：<strong>在语言模型上训练后，token 序列会涌现语义</strong>——低层 token 承载「声学细节」、高层 token 承载「语义内容」（词、句子）。也就是说，编解码器提供「空白 token」，语言模型赋予「意义」——这是音频语言模型「先离散、后学习」范式的根基。</span>

## 4 EnCodec 与 SoundStream 的差异与工程

| 维度 | SoundStream（谷歌） | EnCodec（Meta） |
| --- | --- | --- |
| 采样率 | 48kHz / 24kHz | 48kHz / 24kHz / 16kHz |
| 量化 | RVQ（12–16 层） | RVQ（32 层，可裁剪） |
| 比特率 | 3–24 kbps | 1.5–24 kbps |
| 流式 | 支持（因果卷积） | 支持（流式 + 重叠窗口） |
| 目标 | 音频生成 token | 音频生成 token（MusicLM 用） |

两者核心技术几乎一致，工程差异在**层数与带宽配置**。EnCodec 的「可裁剪层」设计特别实用：**训练时用满 32 层，推理时按需取前 $k$ 层**——同一模型适配「低比特（快、省）」与「高保真（慢、精）」两种场景。

**核心要点：神经编解码器是「音频语言模型的词表生成器」。** 没有它，AudioLM/VALL-E 无从「读」音频；有了它，音频被翻译成「模型能说话的离散语言」。**编解码器的质量直接决定音频大模型的上限**——token 重建不清，模型学的就是「含噪声的语言」。

## 5 编解码器的评估与选型

音频编解码器怎么评、怎么选，是音频大模型训练前的现实问题：

- **重建质量**：**PESQ/STOI**（语音）与 **VISQOL/主观听感**（音乐）——在不同比特率下测。编解码器要报「**比特率—质量**」曲线，不是单点。
- **token 的可用性**：对语言模型而言，「重建质量高」不等于「token 好用」——还要看**下游生成质量**（用 token 训语音 LM 的效果）。两个重建分差不多的编解码器，作 tokenizer 的效果可能差很多。
- **帧率与带宽**：token 帧率（每秒几个 token）决定语言模型序列长度——帧率越低越好训，但信息损失越大。选型要看「下游的序列长度预算」。
- **流式能力**：实时语音对话需要**流式编解码器**（因果卷积、低延迟）——非流式版本不能用。

**公式解析：比特率与帧率的关系。**

$$
\text{bitrate} = \text{帧率} \times \sum_{\text{层}} \log_2(\text{码本大小}_{\text{层}})
$$

- **第一步，看帧率项**：每秒 token 数（帧率）——EnCodec 约 50–75 Hz。
- **第二步，看每层码本**：每层码本大小取对数 = 每层每个 token 的比特数（如 1024 码本 = 10 bit）。
- **第三步，看求和**：RVQ 多层相加——8 层 × 10 bit = 每 token 80 bit；乘帧率 75 = 6 kbps。
- **第四步，看控制**：降比特率 = 降帧率（丢时间分辨率）或减层数（丢细节）——**「比特率预算」直接对应「token 结构的选择」**。

**核心要点：编解码器选型 = 「重建质量 + token 可用性 + 帧率/比特率 + 流式」四维。** 对音频大模型，**「token 好不好训」往往比「重建分高不高」更重要**——这是编解码器评测与声码器评测的最大区别。

## 6 小结

- **神经音频编解码器**用「编码器 + RVQ 量化 + 解码器」把波形压成紧凑离散 token，是音频大模型的词表生成器。
- 传统编解码器输出连续压缩比特，神经版输出**结构化离散 token**，可喂给语言模型。
- 训练目标与神经声码器同构：重建 + 对抗 + 量化损失。
- **RVQ** 逐层量化残差，$N$ 层小码本组合出巨大表示空间，层数即「质量—比特率」旋钮。
- SoundStream/EnCodec 奠基；token 在语言模型训练后**涌现语义**（浅层声学、深层语义）。

**附：关键概念速记**

- **神经音频编解码器**：波形 → 离散 token → 波形——音频大模型的「词表生成器」。
- **架构**：编码器（卷积下采样）+ 量化器（RVQ）+ 解码器（反卷积）。
- **RVQ（残差向量量化）**：逐层量化残差——$N$ 层小码本组合出巨大表示空间。
- **层数 = 质量/比特率旋钮**：层少省比特（粗）、层多保真（细）。
- **训练损失**：重建 + 对抗 + 量化——与神经声码器同构。
- **token 的语义**：起初只是码本编号，语言模型训练后**涌现语义**（浅层声学、深层语义）。
- **SoundStream vs EnCodec**：RVQ 层数与带宽配置不同——技术几乎一致。
- **音频大模型的词表**：token 质量决定下游上限——「token 好不好训」比「重建分高不高」更重要。

**延伸思考**：RVQ 的「残差分层」是一个被低估的普适思想——**先表达主干、再补残差**，从神经编解码器到语言模型的「token 层级」，都是这个模式。它把「巨大的表示空间」分解成「一串小码本的接力」——**「分而治之」在离散表示上的极致应用**。这也是为什么 EnCodec 的 token 能被语言模型当成「不同粒度的层级」使用——**结构上的分层，天然对应语义上的分层**。
