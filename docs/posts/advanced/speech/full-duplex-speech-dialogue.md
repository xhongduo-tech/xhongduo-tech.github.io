## 为什么从全双工语音对话开始

「半双工（half-duplex）」是绝大多数语音助手的工作方式：**你说话时它听着，它说话时你只能等**——话轮严格交替，像对讲机。这造成尴尬：用户想插话（「等等，我说的不是那个」）必须等模型说完；模型想追问也得等用户停顿。**全双工（full-duplex）语音对话**的目标：模型**同时听与说**——它边说边听，你随时可以打断、它可以随时接话，像真人聊天一样自然。

全双工是语音对话的终极形态，也是 GPT-4o 语音模式「下一个十年」。它的技术难点不在「听懂」或「说好」（那已解决），而在**「对话流管理」**——何时该说、何时该停、被打断怎么办、自己的声音会不会被当成输入。理解全双工，就是理解「语音系统如何管理'时间与注意力'」。

## 1 从半双工到全双工：话轮管理的进化

半双工系统的「话轮」由 VAD 决定：检测到用户停顿 → 判定「你说完了」→ 开始回答。这个规则**脆弱**：用户喘口气就被当成「说完了」，被抢话；用户真的说完了但语气未落，又被当成「没说完」。

全双工系统把「话轮」从「规则」变成「**模型学习的信号**」：

| 维度 | 半双工 | 全双工 |
| --- | --- | --- |
| 听与说 | 严格交替 | **同时进行** |
| 话轮判定 | VAD 规则（停顿检测） | 模型学习「何时该说」 |
| 打断 | 不支持（必须等说完） | **随时可打断、可被打断** |
| 体验 | 对讲机式 | 真人对话式 |

**核心概念：全双工 = 从「状态机」走向「流式模型」。** 半双工是「状态切换」（听状态 → 说状态），全双工是「两个流并行」（输入流一直听、输出流一直说），由模型在**每个时刻**决定「此刻该说什么、该听什么」。<span class="marginnote">人类对话的话轮有丰富线索：<strong>语气下落</strong>（陈述结束）、<strong>音节拉长</strong>（话没说完）、<strong>眼神与手势</strong>（语音之外的模态）。全双工语音系统要学的是「语音版的话轮线索」——停顿长度、语调曲线、句末能量。这也是为什么「话轮预测（turn-taking prediction）」成为语音对话研究的独立课题：它本质是「从声学信号预测'对方是否要交话轮'」。</span>

## 2 打断与回听：全双工的核心机制

全双工最锋利的测试是**打断（barge-in）**：模型正在说话，用户插话，模型要**立刻停止并转向听用户**。实现打断需要「同时听说」的三个组件：

- **回听（echo-aware listening）**：模型说话时麦克风仍开着，但**自己的声音会进麦克风**——必须用 AEC（回声消除，见《AEC》一节）把「自己的声音」从输入里消掉，才能「边说自己边听别人」。**AEC 是全双工的物理前提**——没有它，模型的「说」会淹没「听」。
- **打断检测（barge-in detection）**：模型在说话的同时持续监听「用户有没有插话」——检测到「麦克风里有非回声的人声」就**立即中断生成**。判断「是不是回声」正是 AEC 的双讲检测（DTD）的活：DTD 说「双讲了」，模型就该停。
- **快速停止（fast stop）**：中断后要「干净地」停止——不能把半句话硬生生切断，要有自然的收尾（或直接让位）。工程上用「生成器级联暂停」+「状态回滚」。

**公式解析：打断的判定。**

$$
\text{打断}(t) = \mathbb{1}\Big[ \underbrace{\text{DTD 检测到近端语音}}_{用户插话} \;\wedge\; \underbrace{\text{模型正在输出}}_{\text{自我说话}} \Big]
$$

- **第一步，看两个条件**：打断 = 「用户真的在说话」（近端人声，经 AEC 后非回声）+「模型正说着」——两者同时成立才触发。
- **第二步，看 AEC 的角色**：`近端语音` 的判定依赖 AEC 先消掉「自己的回声」——若 AEC 没消干净，模型会把「自己的声音」误判成「用户插话」，自我打断（说一句停一句）。**AEC 质量直接决定打断的准确率**。
- **第三步，看 DTD 的角色**：双讲检测（DTD）判断「麦克风里除了回声还有没有人声」——DTD 报「双讲」即用户插话。**打断 = DTD 在「模型说话期间」的报警**。
- **第四步，看延迟要求**：打断检测要**极低延迟**（几十 ms）——等用户说完才反应过来就晚了。所以打断用「流式 DTD 的早期报警」而非「等整句分析完」。

**核心结论：打断 = 「AEC 保证能听清 + DTD 判断有人插话 + 快速停止」。** 三个组件都是「实时、流式、低延迟」的——全双工的难点全在「实时性」。

## 3 系统架构：两条流并行

全双工系统的工程架构是「**输入流与输出流并行 + 一个中央调度**」：

```
输入流：麦克风 → AEC → 流式 ASR/语义理解 → 更新对话状态
输出流：对话状态 → 流式生成 → 语音合成 → 扬声器
调度器：打断检测 → 状态切换 / 生成暂停
```

- **输入流**始终运行（一直听、一直理解），输出流在「该说时」运行（生成 + 合成）。
- **中央调度器**管理两流的并发：什么时候「让出」输出流（用户插话）、什么时候「重启」输出流（用户说完）。
- **对话状态**（已听内容 + 已说内容 + 意图）在流间共享——模型「记得」自己在说什么、用户插了什么。

**核心要点：全双工的架构本质是「两条并发流 + 一个状态」。** 它不再是「单输入单输出的管道」，而是「双工操作系统」——这是语音对话系统从「功能」走向「平台」的转变。<span class="marginnote">全双工的工程实现里，「流式语音合成」也必须是「增量」的——模型边生成语义边合成语音，而不是等整句想完再说。这要求 TTS 与 LLM「流式对接」（LLM 出一个片段，TTS 立刻合成播放），且「停止播放」要能瞬时生效。所以全双工系统 = 流式 ASR + 流式 LLM + 流式 TTS + AEC/DTD 的「四流并发」——任何一个环节不流式，全双工就塌陷。</span>

## 4 评测与现状

全双工的评测比传统语音系统复杂：

- **任务级**：打断成功率、插话后是否理解、被插话后能否「续上」。
- **对话级**：话轮自然度、响应延迟、并行说话时的正确性。
- **拟人度**：用户是否觉得「像在跟真人说话」。

现状：GPT-4o 语音模式演示了「接近全双工」的体验（低延迟 + 可打断），但「真正的同时听说」（用户与模型同时持续输出）仍是研究前沿——多数系统是「**准全双工**」：能快速切换、能打断，但「完全并行输出」还不成熟。<span class="marginnote">全双工与「心理声学」相关的一个细节：人类对「对话延迟」有严格直觉——超过 500ms 就会觉得「对方不在认真听」。所以全双工的每个环节（AEC 几 ms、打断检测几十 ms、合成首 token 一百多 ms）都要「按人类节奏」优化。这是语音技术里少见的「以人感知为硬指标」的系统设计。</span>

## 5 全双工的关键技术栈

全双工不是一个模型，而是一套「流式技术栈」的组合：

- **流式 ASR（增量识别）**：输入音频边到边出「部分识别结果」——用 CTC/RNN-T 的流式版本（见《流式识别》一节），不是等整句。
- **流式 LLM（增量生成）**：LLM 边生成边「吐语义片段」，不等待完整回答——用「前缀缓存 + 增量解码」让首 token 极快。
- **流式 TTS（增量合成）**：LLM 出一个片段，TTS 立刻合成播放（边想边说）——见《FastSpeech》的并行合成与声码器的低延迟。
- **AEC + DTD（双讲感知）**：模型说话时持续「听」，靠 AEC 消回声、DTD 判插话——见《AEC 与双讲检测》一节。
- **打断控制**：DTD 报警 → 暂停生成 → 回滚到「用户打断点」——状态管理是双工的「操作系统」。

**核心要点：全双工 = 「四个流式模块 + 一个双讲感知」的集成。** 每个模块单独都是「已解决」的技术；把它们**同时、低延迟、协同**地跑起来，才是全双工的挑战。这也是「远场语音交互」一节的系统集成思想在全双工场景的极致化。

**公式解析：端到端延迟预算。**

$$
\text{延迟} = t_{\text{ASR 首结果}} + t_{\text{LLM 首 token}} + t_{\text{TTS 首音频}} \lesssim 300\text{ms}
$$

- **第一步，看三段延迟**：从「用户说完」到「听到回答」，经历识别、生成、合成三段——每段都要流式化，否则加总爆炸。
- **第二步，看预算分配**：300ms 目标下，每段约 100ms——ASR 流式（增量输出）、LLM 前缀缓存、TTS 并行合成缺一不可。
- **第三步，看「边说边出」**：真正的全双工是「不用等用户说完」——ASR 在用户说话时就在产出，LLM 在用户快说完时就开始想。
- **第四步，看工程约束**：300ms 是「人类对话感」的门槛——超了就「迟钝」。每个模块的优化都以「挤进预算」为目标。

**核心要点：全双工是「延迟预算驱动的系统设计」——每个模块都在为「几百毫秒」服务。**

## 6 小结

- **全双工**让模型同时听与说，话轮从「VAD 规则」变成「模型学习的信号」。
- **打断（barge-in）** = AEC（消自己回声）+ DTD（判用户插话）+ 快速停止——实时性是关键。
- 系统架构是**两条并发流 + 一个共享对话状态** + 中央调度器。
- 四个流式环节（ASR/LLM/TTS/AEC）缺一不可，任何一个不流式全双工就塌陷。
- 当前多是「准全双工」（可打断、低延迟），完全同时听说仍是前沿。

**附：关键概念速记**

- **全双工**：模型同时听与说——从「状态机」（半双工）走向「流式模型」。
- **话轮管理**：VAD 规则（半双工）→ 模型学「何时该说」（全双工）。
- **打断（barge-in）** = AEC（消回声）+ DTD（判插话）+ 快速停止——实时性关键。
- **AEC 是物理前提**：不消自己的回声，「边说自己边听」就淹没。
- **两条并发流 + 共享状态**：输入流一直听、输出流该说时说、调度器管切换。
- **四流并发**：流式 ASR + 流式 LLM + 流式 TTS + AEC/DTD——缺一个就塌陷。
- **延迟预算**：300ms 是「对话感」门槛——每段约 100ms。
- **现状**：多是「准全双工」（可打断、低延迟），完全同时听说仍是前沿。

**延伸思考**：全双工的难点不在「单个模型」，而在「**并发与中断管理**」——它本质是一个「实时操作系统」问题：两个流并行、谁打断谁、状态怎么回滚。这提醒我们：**语音系统做到「人机交互」的极限时，瓶颈不再是「识别准不准」，而是「系统像不像一个会插话、会等话的人」**。全双工是语音技术从「功能」走向「体验」的分水岭。
