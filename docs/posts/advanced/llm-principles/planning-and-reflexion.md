## 为什么「走一步看一步」不够

ReAct 是「边想边做」——但它是「短视」的：每一步只看当下，没有「全局视野」。复杂任务（写一篇完整报告、规划一次旅行）需要**先列计划、再执行**——这是 **Plan-and-Execute** 的动机。而「执行出错」怎么办？——**Reflexion** 让 Agent「反思错误、记住教训、再来一次」。**规划（前瞻）与反思（后顾）是 Agent 超越「走一步看一步」的两大能力**。<span class="marginnote">ReAct、Plan-and-Execute、Reflexion 构成了 Agent 的三级范式：<strong>ReAct 是「走一步看一步」（反应式），Plan-and-Execute 是「先计划再执行」（前瞻式），Reflexion 是「失败后反思再试」（反思式）</strong>。三者可以组合：ReAct 是执行层、Plan 是规划层、Reflexion 是反思层——「高级 Agent = 规划 + 执行 + 反思」。</span>

## 1 Plan-and-Execute：先规划，再执行

**Plan-and-Execute** 把任务分成两阶段：

**① 规划阶段（Plan）**：

- LLM 先「理解任务」，生成一份「执行计划」——把大任务拆成「有序的子任务」。

```text
目标：写一篇关于「强化学习」的综述文章

1. 收集 RL 基础知识资料（定义、经典算法）          依赖：无
2. 梳理经典算法脉络（Q-learning、策略梯度、DQN）    依赖：1
3. 查阅最新进展（深度 RL、离线 RL、RLHF）           依赖：2
4. 组织大纲并撰写初稿                              依赖：2, 3
5. 修改完善与校对                                  依赖：4
```

- 计划是「结构化」的——「子任务列表」或「DAG」（有依赖关系的任务图）。

**② 执行阶段（Execute）**：

- 按计划逐个「执行子任务」——每个子任务可能又用 ReAct（边想边做）。
- 执行结果「更新计划」——「做完 1，做 2」。

**为什么规划有用**：

- **全局视野**：计划让 Agent「知道全貌」——不被「当下的一步」带偏。
- **任务分解**：大任务拆小——「每步的负担」变小，执行更可靠。
- **可跟踪**：计划让 Agent「知道自己做到哪了」——不会「重复或遗漏」。

**Plan-and-Execute 的变体**：**动态规划**——执行中「发现计划不对」就「修订计划」——「计划不是死的，边执行边调整」。

## 2 Reflexion：失败后反思，记住教训

**Reflexion** 解决「执行出错后怎么办」——让 Agent 从「错误」中学习：

**循环**：

1. **执行**：Agent 执行任务（ReAct/Plan-and-Execute）。
2. **评估**：判断任务是否成功（用验证器/人工/测试）。
3. **反思**：若失败，LLM「回顾失败过程」，写一条「教训」——「我哪里错了、下次该怎么改」。

```text
反思（第 2 次尝试失败后）：
- 失败原因：调用「天气查询」工具时，没有先核对参数格式，导致工具报错。
- 教训：所有工具调用必须先查工具的参数 schema，再构造参数。
- 下次改进：先读工具文档，再传参；若报错先看错误信息，不盲目重试。
```

4. **重试**：带着「教训」重新执行——「不再犯同样的错」。

**Reflexion 的关键**：**「教训」被持久化**——进入「记忆」（self-reflection memory）——后续尝试「引用」它，避免「重蹈覆辙」。

**为什么反思有效**：

- **错误是有模式的**：Agent 的失败往往「重复同样的错误」（选错工具、参数不对、方向偏）。
- **反思「识别模式」**：LLM 分析失败轨迹，「提取教训」——「下次避免」。
- **教训「引导重试」**：重试时「参考教训」——「朝正确方向走」。

**Reflexion 的本质**：**把「失败经验」转化为「可复用的改进策略」**——像「人类记笔记、吸取教训」。

## 3 规划 + 反思：高级 Agent 的「思维层」

把三者组合成一个「高级 Agent」：

```text
┌─────────────────────────────┐
│ 规划层（Plan）               │  往哪走：拆任务、定顺序、定依赖
├─────────────────────────────┤
│ 执行层（ReAct）              │  怎么走：边想边做、调用工具、观察结果
├─────────────────────────────┤
│ 反思层（Reflexion）          │  错了吗：评估失败、提取教训
└─────────────────────────────┘
        │  教训持久化进入「记忆」
        └──────────► 反馈给规划层 / 执行层
```

**层次分工**：

- **规划层**：「往哪走」（全局方向）。
- **执行层**：「怎么走」（当下行动）。
- **反思层**：「走错了吗、怎么改」（事后修正）。

**这正是「o1 式思维链」的 Agent 版**：o1 在「文本空间」里规划-执行-反思（长思维链），Agent 在「真实环境」里规划-执行-反思（工具调用）——**「慢思考」的结构（计划、执行、检查）从「文本」延伸到「行动」**。

## 4 公式解析：反思的「策略更新」

Reflexion 的「反思-重试」可以写成「策略更新」：

$$
\pi_{k+1} = \pi_k + \text{Reflect}(\tau_k, \text{失败}), \qquad
\text{Reflect}(\tau_k, \text{失败}) = \text{LLM 从失败轨迹 } \tau_k \text{ 提取的教训}
$$

对这条式子做三步拆解：

- **第一步，读懂 $\tau_k$**：第 $k$ 次尝试的「完整轨迹」（思考-行动-观察）。失败时，这条轨迹是「犯错记录」。
- **第二步，读懂 Reflect**：LLM「回顾轨迹」，提取「教训」——「哪一步错了、为什么错、下次怎么改」。**教训是「结构化的改进信号」**。
- **第三步，读出迭代改进**：$\pi_{k+1} = \pi_k + \text{教训}$——**每次失败「累积一条教训」，策略「逐步改进」**——这是「从错误中学习」的形式化：Agent 的「策略」通过「反思」逐轮优化。

**辨析｜易错点：** Reflexion 的「反思」不是「保证下次成功」——它「降低犯同样错误的概率」，但不消除「新错误」。反思「基于语言」——**「教训」的质量取决于 LLM 的「自我分析能力」**——反思可能「总结错教训」（归因错误）。所以「反思 + 验证」要结合：反思「引导方向」，验证「把关结果」。

## 5 高级 Agent 的工程实践

- **规划的表达**：计划用「结构化文本/JSON」——「子任务 + 依赖 + 状态」。
- **执行的可控**：每个子任务「独立 ReAct」+「超时」——「不失控」。
- **反思的触发**：任务失败（评估器判失败）才反思——「不是每步都反思」。
- **教训的存储**：反思教训进「记忆」——跨任务「复用」。
- **组合策略**：简单任务用 ReAct，复杂任务「规划 + 执行」，反复失败「加反思」。

## 6 小结

- **Plan-and-Execute**：先规划再执行——「全局视野 + 任务分解 + 可跟踪」。
- **Reflexion**：失败后反思、记教训、重试——「从错误中学习」。
- 高级 Agent = **规划（前瞻）+ 执行（ReAct）+ 反思（后顾）**——三层思维。
- 反思 = 策略更新：$\pi_{k+1} = \pi_k + \text{教训}$——逐轮改进。
- 与 o1 同构：**「慢思考」的结构从文本延伸到行动**。
