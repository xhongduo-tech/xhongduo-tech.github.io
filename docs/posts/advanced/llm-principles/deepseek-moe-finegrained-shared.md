## 为什么"更多、更小的专家"更聪明

Switch 的 MoE 是「几个大专家」：每个专家都是完整的 FFN，中间维度 $d_{\text{ff}}$ 很大。DeepSeekMoE 提出了两个反直觉的改进：**把专家切得更细、更多**（细粒度专家），以及**加一组永远被激活的共享专家**。这两个设计让 DeepSeek-V2/V3 在同样参数下，用更低的激活参数达到更高的质量。<span class="marginnote">DeepSeekMoE 的直觉：大专家是「全科医生」——什么都懂一点，但每个 token 只用 1-2 个，知识重叠浪费。细粒度专家是「专科医生」——切得更专，激活同样数量时「覆盖面更广」。共享专家是「急诊科」——处理每个 token 都需要的通用能力（语法、常识），不必每次去挤占专科名额。</span>

## 1 细粒度专家切分：更小、更多、更专

传统 MoE 每个专家是完整 FFN：中间维度 $d_{\text{ff}}$（如 4d）。DeepSeekMoE 把**每个专家的中间维度缩小**，从而在同样的「总专家容量」下**切出更多专家**。

设原来有 $E$ 个专家、每个专家 FFN 维度 $m$；DeepSeekMoE 把专家数增加到 $mE/n$ 个、每个专家维度 $n$（$n < m$）。**总参数不变，但专家数变多了**。

效果：

**激活更精细**：激活 $k$ 个「细专家」相当于激活 $k$ 个不同「专科」，比激活 $k$ 个「全科」覆盖更多样的知识。
**组合更灵活**：细粒度让「token 与专家」的匹配更精准——一个小专家可以专精一个很窄的模式，而大专家被迫「平均」多种模式。
**负载更平滑**：更多专家 = 更细的负载分配粒度，均衡更容易。

**代价**：专家数变多导致**通信量上升**（路由、all-to-all 的元数据变多）——DeepSeekMoE 通过「设备受限路由」缓解（限制每个 token 只能路由到同一设备上的专家，减少跨设备通信）。<span class="marginnote">用一个比喻：把「一家综合医院」换成「一个专科诊所群」——每个诊所只擅长一件事，病人按需分流。综合医院每个科室要覆盖所有病，专科诊所可以做到「极致专业」。细粒度专家就是这个思路：<strong>小到极致的专科，配上灵活的转诊（路由）</strong>。</span>

## 2 共享专家：常驻的"公共能力层"

传统 MoE 里，**每个 token 只激活 top-k 专家**——通用能力（如语法、停用词处理、常见搭配）也要占用专家的「名额」。DeepSeekMoE 加了一组 **$K_s$ 个共享专家（shared experts）**：

$$
y = \underbrace{\sum_{i=1}^{K_s} \text{Shared}_i(x)}_{\text{共享专家，始终激活}} + \underbrace{\sum_{j \in \mathcal{T}(x)} w_j \, \text{Routed}_j(x)}_{\text{路由专家，按需激活}}
$$

**共享专家的作用**：

- 兜住「每个 token 都需要」的通用能力，不让它们**挤占路由专家的名额**；
- 路由专家因此可以**更专**——它们只学「差异化知识」，不必被迫学通用能力；
- 共享专家**始终激活**，其梯度稳定，是模型「稳定的常识底座」。

**参数与计算**：共享专家 $K_s$ 通常很小（DeepSeek 用 2 个），但始终参与每个 token 的计算。所以「激活专家数」= $K_s$ + $k$（路由），比传统 MoE 略多——但换来的是「路由名额被解放」的质量收益。<span class="marginnote">共享专家的思想在人类组织里很常见：一个公司既有「通用部门」（行政、财务，每个项目都要用），又有「项目组」（按需组建）。把「通用支持」与「专项执行」分开，整体效率最高。DeepSeekMoE 把它做成模型结构——共享层 + 路由层。</span>

## 3 公式解析：DeepSeekMoE 的前向

DeepSeekMoE 层的完整输出：

$$
y = \sum_{i=1}^{K_s} \text{Shared}_i(x) + \sum_{j=1}^{k} w_j \cdot \text{Routed}_j(x)
$$

其中路由权重由门控给出：

$$
w_j = \text{softmax}\big(\text{top-k}(x W_r)\big)_j
$$

对这套式子做四步拆解：

- **第一步，读懂第一项**：$K_s$ 个共享专家**全部激活**，权重固定为 1（不加权）——这是「常驻知识」。
- **第二步，读懂第二项**：$k$ 个路由专家，权重 $w_j$ 由门控决定——这是「按需知识」。
- **第三步，理解总激活量**：激活专家总数 = $K_s + k$。DeepSeek 用 $K_s=2, k=6$（如 V2），激活 8 个；而传统 MoE 激活 $k=2$。**激活数多，但每个专家更小、更专，总激活参数量反而更优**。
- **第四步，读出设计哲学**：把「通用 + 专用」分开，让**每份激活都花在刀刃上**——共享专家负责「人人都要的」，路由专家负责「这个 token 独有的」。这是对「固定容量」的最优配置。

**辨析｜易错点：** 共享专家 ≠ 「无负载均衡」。共享专家是「永远激活」，不参与路由，所以它们**没有路由不均衡问题**；但路由专家之间仍有均衡问题，DeepSeekMoE 用「专家级偏置」处理。别把「共享」理解成「所有专家共享参数」——共享专家是一组独立的、固定的专家，只是「每个 token 都用」。

## 4 训练与推理的考量

- **负载均衡**：DeepSeekMoE 不用辅助损失，改用**专家级偏置（expert bias）**——每个路由专家一个可学习标量，加到路由分数上，通过「偏置反馈」自然调节负载。这避免了辅助损失对路由质量的「污染」。
- **设备受限路由**：限制 token 只能路由到「本设备上的专家」，减少跨设备 all-to-all 通信——细粒度专家带来的通信开销被这条约束抵消。
- **推理**：DeepSeek-V2/V3 把细粒度 MoE 与 MLA（上一节）结合——**MLA 压 KV、MoE 压计算**，双管齐下，让 V3 在推理成本上极具竞争力。

## 5 与标准 MoE 的对比

| 维度 | 标准 MoE（Mixtral 式） | DeepSeekMoE |
| --- | --- | --- |
| 专家粒度 | 大而少（8 个完整 FFN） | 细而多（几十到上百个） |
| 共享专家 | 无 | 有（2 个常驻） |
| 激活策略 | top-2 路由 | 2 共享 + 6 路由 |
| 负载均衡 | 辅助损失 | 专家级偏置 |
| 通信优化 | 标准 all-to-all | 设备受限路由 |

**经验结论**（DeepSeek 论文）：同样总参数与训练算力下，DeepSeekMoE 的困惑度低于「大专家」MoE；在 2T token 规模上稳定训练，且知识密度更高。

## 6 小结

- **细粒度专家**：把专家切小、切多，用「专科化」替代「全科化」，激活覆盖更广。
- **共享专家**：常驻的「公共能力层」，解放路由名额，让路由专家更专。
- 前向 = **共享（固定激活）+ 路由（按需激活）**，总激活量 $K_s + k$。
- 负载均衡用**专家级偏置**，避免辅助损失污染路由。
- 与 MLA 结合，DeepSeek-V2/V3 实现「KV 压显存、MoE 压计算」的双降本。
