## 为什么「等攻击」不如「主动打」

安全对齐「训好了」模型——但「训好」不等于「防住」。对齐的漏洞（越狱、注入、偏见）只有「被攻击」才暴露——等「真实攻击」来发现，代价太大。**红队测试（red teaming）** 是「主动攻击自己的模型」——**在发布前，用「攻击者思维」找漏洞、修漏洞**——「组织内的攻击者」让安全「提前暴露」。<span class="marginnote">红队（red team）一词来自军事演习——<strong>「蓝队」防守、「红队」进攻</strong>。对 LLM，红队就是「专门的攻击者团队/系统」，用「越狱、注入、偏见、隐私」等各种手法「攻破」模型的护栏——<strong>目的不是「打败模型」，而是「发现漏洞让团队修」</strong>。红队是「安全对齐的质检环节」。</span>

## 1 红队测试的方法论

红队测试的「完整流程」：

**① 明确测试范围**：

- 定义「什么算不安全」——有害内容、隐私泄漏、偏见歧视、越狱成功。
- 定义「测试的输入分布」——哪些任务/场景。

**② 设计攻击策略**：

- 从「已知攻击手法」出发——越狱、注入、编码绕过、多轮诱导。
- 结合「模型特点」——中文模型测中文越狱、Agent 测注入。

**③ 执行攻击**：

- 人工红队：真人「绞尽脑汁」攻击——发现「机器想不到的漏洞」。
- 自动化红队：程序「批量」攻击——覆盖「大规模」。

**④ 记录与分析**：

- 记录「成功的攻击」——「漏洞库」。
- 分析「漏洞的模式」——「为什么能被攻破」。

**⑤ 修复与回归**：

- 修复漏洞——补数据、调对齐、加过滤。
- 回归测试——「同样的攻击不再成功」。

**红队的「心智」**：**攻击者思维**——「护栏一定有缝，我的任务是我缝」——「不预设『防住了』，只找『没防住』」。

## 2 人工红队 vs 自动化红队

| 维度 | 人工红队 | 自动化红队 |
| --- | --- | --- |
| 攻击创造力 | 高（人类想象力） | 中（依赖模板/模型） |
| 覆盖规模 | 低（人力有限） | 高（批量生成） |
| 发现漏洞类型 | 新颖、意想不到 | 已知模式的变体 |
| 成本 | 高 | 低 |
| 适用阶段 | 深度安全审查 | 持续监测/大规模 |

**人工红队的价值**：发现「机器想不到」的攻击——「人类的语言创造力」是「越狱攻击」的源头——「真人」才能模拟「真实攻击者」。

**自动化红队的价值**：规模化——「十万条攻击样本」批量测——「覆盖广」。**两者结合**：自动化「先扫一遍」，人工「深挖重点」——「广度 + 深度」。

## 3 自动化红队的技术

**自动化红队** 让「程序」生成攻击样本，主要技术：

**① 模板攻击（template-based）**：

- 预写「攻击模板」——「角色扮演」「场景包装」——批量变体生成。

**② LLM 生成攻击（LLM-based red team）**：

- 用一个「攻击 LLM」生成「越狱 prompt」——让「攻击模型」学「怎么攻破目标模型」。
- **对抗进化**：攻击 LLM 与目标模型「对抗」——攻击失败就「改进攻击」。

**③ 进化/搜索攻击**：

- 把攻击当作「搜索问题」——遗传算法、对抗样本搜索——「自动找最有效的越狱」。

**④ 越狱基准**：

- 标准化的越狱数据集——如「HarmBench」「JailbreakBench」——「统一的攻击测试集」——**横向对比模型的鲁棒性**。

**自动化红队的「评估指标」**：

- **攻击成功率（ASR）**：攻击样本中「攻破护栏」的比例。
- **护栏拒答率**：模型「拒绝有害请求」的比例——「安全性的直接度量」。

## 4 公式解析：攻击成功率与鲁棒性

红队测试的核心产出是「攻击成功率」——它衡量「护栏的薄弱程度」：

$$
\text{ASR} = \frac{\text{成功攻破的攻击}}{\text{总攻击样本}}
$$

对这条式子做三步拆解：

- **第一步，读懂分子**：成功攻破 = 「模型给出了有害/越权回答」——判定需要「评估器」（人工或自动判「是否有害」）。
- **第二步，读懂分母**：总攻击样本——「红队测试集的规模」——**测试集要有代表性**（覆盖攻击手法、任务类型）。
- **第三步，读出「鲁棒性的度量」**：**ASR 高 = 护栏弱、模型容易被攻破**；ASR 低 = 护栏强。**红队的目标是「把 ASR 降到可接受」**——「0」不现实（攻击无限），「可接受」才是目标——**「安全不是绝对，是可接受的风险」**。

**辨析｜易错点：** ASR 的「判定」很关键——「什么叫攻破」要定义清楚。**「模型给了危险信息」与「模型礼貌地拒绝」是两条线**——判定要「基于输出内容」而非「攻击是否被识别」。**「拒答率」与「有用性」要平衡**——「全拒答」的模型 ASR 为 0 但「没法用」——红队测试也要测「过度拒答」（安全过度伤有用性）。

## 5 红队的工程实践

1. **测试集建设**：越狱 + 注入 + 偏见 + 隐私——「分类攻击库」。
2. **人工 + 自动结合**：自动先扫、人工深挖——「广度 + 深度」。
3. **漏洞库**：记录「成功攻击」——「修复的依据」。
4. **持续监测**：发布后「持续红队」——「新攻击不断出现，防御不断跟进」。
5. **红队-蓝队循环**：红队找漏洞 → 蓝队修 → 红队再测——「对抗循环」。

## 6 小结

- **红队**：主动攻击自己的模型——「发布前找漏洞」。
- 方法论：**定范围 → 设计攻击 → 执行 → 分析 → 修复回归**。
- **人工红队**（深度、新颖）vs **自动化红队**（规模、持续）——结合。
- 自动化技术：模板、LLM 生成攻击、进化搜索、越狱基准。
- 核心指标：**ASR（攻击成功率）**——「可接受的风险」而非「绝对安全」。
