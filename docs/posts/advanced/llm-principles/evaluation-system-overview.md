## 为什么「评测」是 LLM 的地基

没有评测，就无法「知道模型有多强」「对比模型谁好」「判断改进有没有效」。评测是「模型的尺子」——但「好」是多维的（知识、推理、代码、对话、安全……），**评测体系** 把「好」拆成「可测量的能力维度」与「可靠的评测方式」。这是「大模型原理」的收官篇——**把前面所有能力（知识、推理、RAG、Agent、安全）变成「可量化」的指标**。<span class="marginnote">评测的「地位」：<strong>「没有评测，就没有改进」</strong>——缩放定律、架构创新、对齐效果——一切「结论」都建立在「评测」上。但评测也有「陷阱」：<strong>「测错的能力」「测不到的能力」「过拟合评测」</strong>——理解评测的「分类」与「局限」，才能「正确地用尺子」。</span>

## 1 能力维度：评测「测什么」

LLM 的能力可以按「维度」分类：

**① 知识与事实**：模型「知道多少」——学科知识（MMLU）、常识（CommonsenseQA）。

**② 推理能力**：模型「会不会想」——数学（GSM8K、MATH）、逻辑（LogiQA）、多步推理（BBH）。

**③ 代码能力**：模型「会不会写代码」——代码生成（HumanEval）、代码修复（SWE-bench）。

**④ 语言能力**：模型「语言功底」——翻译、摘要、语法。

**⑤ 对话与指令遵循**：模型「会不会聊天、听不听话」——指令遵循（IFEval）、多轮对话（MT-Bench）。

**⑥ 安全与鲁棒性**：模型「安不安全」——有害内容拒答、越狱鲁棒性、偏见。

**⑦ 长上下文**：模型「能不能处理长文」——NIAH、RULER（第十一篇讲过）。

**⑧ 多模态**：模型「看不看得懂图」——视觉问答（VQA）、图文理解。

**能力维度的「覆盖」**：**没有一个评测能覆盖全部能力**——「全能力评测」要「多个基准的组合」——「模型的能力画像」是「多维雷达图」而非「一个分数」。

## 2 评测方式：怎么测

评测方式分几类，各有「适用场景」与「局限」：

**① 标准基准（标准化测试）**：

- 固定数据集 + 固定评分（如 MMLU 的多选题准确率）。
- 优点：可复现、可对比、规模化。
- 局限：**可能有「数据污染」**（模型见过测试题）；「接近饱和」（大家都满分，测不出差异）。

**② 生成式评测（open-ended）**：

- 模型「自由生成」，用「规则/模型/人工」评分（如对话质量、摘要质量）。
- 优点：更真实（不是选择题）。
- 局限：**评分难自动化**——「什么是好对话」难量化。

**③ 对抗性评测（红队）**：

- 主动「攻击模型」——越狱、注入、偏见测试（上一节讲过）。
- 优点：测「鲁棒性与安全」——标准基准测不到的。
- 局限：**「攻击库」有限**——测不到「未知的攻击」。

**④ 人类评测（人工打分）**：

- 真人评估「回答质量」——最真实。
- 优点：**「最终标准」**——「机器打分都是近似，人才是目标」。
- 局限：**贵、慢、主观**——不同人打分可能不一致。

## 3 评测的「目的」决定「方式」

不同「目的」要「不同的评测」：

| 目的 | 评测方式 | 例子 |
| --- | --- | --- |
| 横向对比模型 | 标准基准 | MMLU、HumanEval |
| 发布前安全审查 | 红队 + 人类 | 越狱测试、人工审查 |
| 训练中监控 | 快速子集 | 训练 loss、子集基准 |
| 产品落地 | 任务专属 | 你的任务的成功率 |
| 研究改进 | 消融对比 | 加/减某组件的前后对比 |

**关键**：**「评测要对齐目的」**——「训练中」用快速子集（不用完整基准），「对比发布」用标准基准，「落地」用任务专属指标——**「目的错配」会让评测「误导决策」**。<span class="marginnote">评测的「目的导向」很重要：<strong>「同一个模型」在「不同评测」下「表现不同」——不是模型「不稳定」，而是「评测测的是不同能力」</strong>。比如「MMLU 高」≠「对话好」≠「代码强」——「读评测」要「知道它测的是什么」——「评测的解读」与「评测本身」同等重要。</span>

## 4 公式解析：评测的「可靠性」

评测的「可靠性」由「样本量」决定——**样本太少，分数「波动大」**。设真实能力为 $\mu$，评测分数 $\hat{\mu}$ 的标准误差：

$$
\text{SE}(\hat{\mu}) \approx \frac{\sigma}{\sqrt{N}}
$$

其中 $\sigma$ 是样本的标准差、$N$ 是样本量。

对这条式子做三步拆解：

- **第一步，读懂 $\sigma$**：样本间的「波动」——任务难度不一、样本差异大，$\sigma$ 大。
- **第二步，读懂 $\sqrt{N}$**：样本量越大，标准误差越小——**分数越「可信」**。
- **第三步，读出「评测要多少样本」**：要「分辨 1% 的差距」，需要「足够大的 $N$」——**小样本基准（几十题）的「分数差」可能是「噪声」**。所以评测报告要「给置信区间」——「±2%」比「一个裸分数」诚实。

**辨析｜易错点：** 评测的「分数」不是「绝对真理」——它受「样本、评分方式、数据污染」影响。**「两个模型的分数差」要「大于噪声」才有意义**——「48% vs 49%」可能「没有差异」（样本不够）。**「评测的统计学素养」是读评测的基本功**。

## 5 评测体系的总览图

一个完整的评测体系 = 多个「能力维度」× 多个「评测方式」：

```
能力维度: 知识 / 推理 / 代码 / 语言 / 对话 / 安全 / 长上下文 / 多模态
评测方式: 标准基准 / 生成式 / 对抗式 / 人类
评测矩阵: 每个「维度 × 方式」的「组合」都是「评测的一个侧面」
```

**评测的「演进」**：从「单点基准」（MMLU）到「综合套件」（HELM、Open LLM Leaderboard）——「一个分数」到「能力画像」——「评测的全面性」在提升。

## 6 小结

- 能力维度：**知识、推理、代码、语言、对话、安全、长上下文、多模态**。
- 评测方式：**标准基准、生成式、对抗式、人类**——各有限制。
- **目的决定方式**——「训练监控」用快速子集、「对比发布」用标准基准。
- 可靠性：**SE ≈ σ/√N**——小样本的分数差可能是噪声。
- 完整评测 = **维度 × 方式**的矩阵——「能力画像」而非「一个分数」。
