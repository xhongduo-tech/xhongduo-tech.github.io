## 为什么词嵌入值得单独讲

在数据流总览里，词嵌入是第一步：把 token id 变成向量。它的代码往往只有一行 `nn.Embedding(vocab_size, d_model)`，但正是这一行隐藏着「分布假设」「初始化玄学」与「权重共享」三个值得深挖的点。<span class="marginnote">嵌入层在参数里占比不大（前面词表篇算过约 1–2%），但它定义了模型「如何把离散符号放进连续空间」——这是整个 Transformer 的起点。很多关于「词向量语义」的直觉（king − man + woman ≈ queen）都来自这一层。</span>

## 1 查表：嵌入层是"查表"而不是"计算"

**词嵌入层（token embedding）**：一个形状为 $|\mathcal{V}| \times d_{\text{model}}$ 的矩阵 $E$，第 $i$ 行就是 token id $i$ 的嵌入向量。前向时只需按 id 取行：

```python
import torch.nn as nn

# 词嵌入矩阵：形状 [V, d_model]，第 i 行是 token id i 的向量
embedding = nn.Embedding(vocab_size, d_model)

x = embedding(token_ids)   # token_ids: [B, L] → 输出 [B, L, d_model]
```

它的本质是**查表（lookup）**：没有卷积、没有 MLP，就是一次按索引取行的 `index_select` 操作。这让嵌入层在 GPU 上是**内存密集型**操作而非计算密集型——搬数据比算数据贵，这也是为何嵌入层常常成为显存与带宽的瓶颈之一。

嵌入向量的语义：训练后，语义相近的 token 会聚到相近的向量区域。「猫」与「狗」、「苹果」与「香蕉」在嵌入空间里距离更近——因为它们在训练中频繁出现在相似上下文。<span class="marginnote">这种「由上下文塑造的语义」正是分布式表示的核心思想，源于 Word2Vec 时代的「分布假说」（Harris, 1954）：词的语义由它出现的上下文决定。大模型的嵌入层继承了这一思想，但上下文来自深层 Transformer 而非浅层窗口。</span>

## 2 初始化：为什么不能全是零

嵌入层必须**随机初始化**，且方差要受控。若所有嵌入向量初始化为零或相同的值，则对称性无法打破——梯度更新会把所有 token 的嵌入推向相同方向，模型完全退化。

标准做法是**从均值为 0、方差为 $\sigma^2$ 的正态分布**中采样：

$$
E_{ij} \sim \mathcal{N}\left(0, \sigma^2\right), \qquad \sigma \text{ 常取 } 0.02
$$

对这条式子做三步拆解：

- **第一步，读懂 $\sigma = 0.02$**：这是一个远小于 1 的方差。为什么？因为嵌入向量会逐层通过注意力与 FFN 放大。初始方差过大，前向信号剧烈波动，反向传播梯度爆炸；过小则信号消失。
- **第二步，理解「按模型规模缩放」**：GPT-2 论文里 $\sigma = 0.02$ 是固定值；而 GPT-3 及以后流行「按宽度缩放」的初始化，例如 $\sigma \propto 1/\sqrt{d}$——隐藏层越宽，初始权重越小，因为宽层累加的信号更多。
- **第三步，读出与残差的配合**：残差连接要求每层的「增量」保持小尺度，初始权重小正是为了让第一层输出接近输入，训练早期保持稳定。这与后面 Pre-LN 的动机同源。<span class="marginnote">初始化是深度学习的「玄学」里最有科学成分的一块。它解决的不是「最好」而是「不坏」——保证训练能启动、不爆炸。Xavier/He 初始化、GPT 的 scaled init、以及 μP（第十篇）都在回答同一个问题：初值多大才恰到好处。</span>

**辨析｜易错点：** 嵌入层初始化后不是「固定的」。它随训练更新，最终词向量的语义来自训练数据；预训练模型的嵌入层甚至能反映出训练语料的偏见（如性别职业关联）。初始化只是起点，不是终态。

## 3 权重共享：输入嵌入 = 输出头转置

Transformer 原论文有一个巧妙的参数节省：**输出头权重与输入嵌入共享**。具体地，输出头 $W_{\text{out}} \in \mathbb{R}^{V \times d}$ 直接取输入嵌入的转置：

$$
W_{\text{out}} = E^{\top}, \qquad \text{logits} = E^{\top} h_t
$$

- **参数节省**：省掉 $|\mathcal{V}| \times d$ 个独立参数。对 150k 词表、$d=4096$，一次省下约 6 亿参数。
- **语义一致性**：输出头打分「表示 $h_t$ 与词嵌入 $w$ 的内积」，如果输出头与输入嵌入同一张表，则「模型认为哪个词最该出现」与「这个词的嵌入」自然对齐——一个词在输入侧语义相近，在输出侧打分也相关。<span class="marginnote">权重共享让「预测下一个词」变得像「在嵌入空间中找一个最近的邻居」：模型本质上是在问「哪个词的嵌入与我当前的表示最像」。LLaMA、Qwen 都采用共享；部分模型（如某些多模态）为了解耦理解与生成的嵌入语义，会取消共享。</span>

注意：权重共享下，**输入嵌入与输出头同时更新**。它们在训练中协同演化，而不是互相独立。这带来一个微妙的性质：词嵌入的「语义」实际上被输出侧的判别任务约束，可能比纯输入侧嵌入更「判别化」。

## 4 嵌入层的实际实现细节

**padding 处理**：`<pad>` token 的嵌入通常不做特殊处理，但在 loss 计算时对应位置会被 mask 掉——嵌入层「有向量」，但 loss 不统计它。
**unembedding 的反向**：输出头把隐藏状态 $h_t$ 投影到 $V$ 维 logits，反向时梯度要穿过 $V$ 维大矩阵——这是全模型里 FLOPs 最大的单点之一（与词表大小线性相关）。权重共享恰好把这个成本与嵌入层合并。
**与位置编码的关系**：输入嵌入与位置编码通常**相加**（绝对位置）而非拼接，因此维度必须一致。RoPE 之后流行「只对 Q/K 旋转、不加位置向量」，于是嵌入层可以更纯净。
**tie 与 untie**：HuggingFace 配置里 `tie_word_embeddings` 控制是否共享。微调时解绑（untie）偶尔能小幅提升任务效果，但会显著增加参数量。<span class="marginnote">实践中还有一个细节：<strong>词嵌入乘以 $\sqrt{d}$ 缩放</strong>（`x = x * (d_model ** 0.5)`）。Transformer 原论文这么做，是为了让嵌入向量与位置编码量级匹配；现在很多实现已不需要，但老代码里常见。</span>

## 5 嵌入层与下游任务

- **冻结 vs 微调**：参数高效微调（LoRA）通常把嵌入层也冻结，只训低秩增量——因为嵌入层参数巨大、梯度更新慢，且其语义在预训练中已固化。
- **嵌入空间的可解释性**：通过对嵌入向量做 PCA/t-SNE，能可视化词义聚类、多语言对齐、甚至「线性类比」结构。
- **连续提示**：Soft Prompt、Prefix-Tuning 本质是在嵌入层「前面」插入可学习的连续向量——把「提示工程」升级成「在嵌入空间里优化」。

## 6 小结

- 词嵌入是**查表**操作：`embedding(token_ids)` 按 id 取行，内存密集而非计算密集。
- 嵌入语义来自**分布假说**：上下文塑造词义，训练后相近词聚在一起。
- 初始化要**随机、小方差**（$\sigma \approx 0.02$ 或按宽度缩放），避免对称与爆炸。
- **权重共享**（$W_{\text{out}}=E^\top$）同时带来参数节省与语义一致性，是 LLaMA/Qwen 的标准配置。
- 嵌入层参与训练更新，冻结策略、连续提示等下游技巧都围绕它展开。
