## 为什么语音是「另一种 token 化」

多模态不只视觉——**语音**（音频）是 VLM 之外的另一个主战场。让语言模型「听懂语音」，与「看懂图像」遵循同一套三段式：**音频编码器**（把声波变成特征）→ **对齐**（音频特征到文本空间）→ **LLM**（图文之外的第三种 token）。区别在于「音频怎么变成 token」——它比图像更「连续」，需要先「离散化」。Whisper 是音频编码的基石，而「端到端语音语言模型」正在把「语音识别 + 理解 + 生成」统一进一个模型。<span class="marginnote">音频多模态的「特殊性」：语音是「时序连续信号」，没有图像那种「天然分块」（patch）。<strong>「语音怎么切成 token」是音频多模态的第一问题</strong>——可以用「编码器下采样」（Whisper 式），也可以用「语音 tokenizer」（离散化，如 HuBERT 的单元）。「连续编码」与「离散 token」是两条路线。</span>

## 1 Whisper：语音识别的「编码器-解码器」地基

**Whisper**（OpenAI, 2022）是「语音 → 文本」的强基线，架构是标准的 **Encoder-Decoder Transformer**：

**输入**：80 通道的 log-Mel 频谱（音频被切成 30 秒片段）。
**编码器**：处理频谱，输出「音频特征」。
**解码器**：从音频特征「生成」文本（转录、翻译）。

**Whisper 的贡献**：

**海量弱监督数据**：68 万小时「语音-文本对」——规模碾压之前的语音识别。
**多任务**：同一个模型做「转录」「翻译」「时间戳」——用「任务 token」区分。
**鲁棒性**：在噪声、口音上表现好——弱监督数据覆盖广。

**Whisper 作为「音频编码器」**：VLM 用 Whisper 的**编码器**把音频变成特征，再接入 LLM——**Whisper 编码器是「音频世界的 CLIP ViT」**。<span class="marginnote">Whisper 的「30 秒固定窗口」是个工程细节：音频比图像长得多（一段对话几十分钟），必须「分段」。Whisper 用「30 秒一段 + 重叠」切分，每段独立转录，最后合并。<strong>「长音频怎么分段」是音频多模态的独特问题</strong>——图像是「一张」，音频是「一长串」。</span>

## 2 语音 token 化的两条路线

语音要进 LLM，必须先「变 token」。两条路线：

**路线一：连续编码器特征（Whisper 式）**。

音频 → Whisper 编码器 → 连续特征序列（每 20ms 一个特征）。
特征序列直接「拼接」进 LLM（像视觉 patch）。
特点：信息无损（连续）、但 token 量大（每秒 50 个特征）。

**路线二：离散语音 token（SpeechTokenizer / HuBERT 式）**。

音频 → 语音 tokenizer → 离散 token 序列（每秒 25 个或更少）。
离散 token 像「文本 token」一样进 LLM。
特点：token 量小、可与文本「同构」，但有「量化损失」（语音细节丢失）。

**两条路线的取舍**：连续保留「音质细节」（语气、音色），离散更「LLM 友好」（与文本 token 同构）。**主流趋势是「离散化」**——因为 LLM 是「token 的世界」。<span class="marginnote">语音的「离散化」比图像「更必要」：图像 patch 是「空间分块」，天然离散；语音是「连续波形」，必须「人为切」+「量化」。SpeechTokenizer 把语音离散成「语义单元 + 声学单元」两层——语义层像「词」，声学层像「音色」——<strong>「离散到多细」直接决定「听懂 vs 听清」</strong>。</span>

## 3 端到端语音语言模型

**端到端语音语言模型（Speech LLM）** 的目标：不再「语音→文本→LLM→文本→语音」的「级联」，而是让 LLM **直接处理语音 token**——「听懂」与「回应」在同一个模型里。

**代表方案**：

**Qwen-Audio / Qwen2-Audio**：Whisper 编码器 → 对齐 → Qwen LLM——「语音理解」（听懂指令、语音问答、音频理解）。
**SALMONN / SpeechGPT**：语音 token 直接进 LLM——「语音对话」。
**语音生成侧**：LLM 输出「语音 token」，再用「声码器（vocoder）」合成波形——「语音回复」。

**级联 vs 端到端的对比**：

| 维度 | 级联（ASR→LLM→TTS） | 端到端 Speech LLM |
| --- | --- | --- |
| 架构 | 三个独立模型 | 一个模型 |
| 误差 | 级联传播（ASR 错 → 理解错） | 语音直接进 LLM |
| 语音信息 | 丢失（转成文本就没了语气） | 保留（音色、语气在 token 里） |
| 工程 | 简单（复用现成组件） | 复杂（语音 token 训练） |

**端到端的价值**：语音里的「副语言信息」（语气、情绪、重音）在「级联转文本」时丢失；端到端让 LLM「听到语气」——**「听语气」是端到端独有的能力**。<span class="marginnote">「级联 vs 端到端」之争与 NLP 早期「统计管道 vs 端到端」完全同构：级联「模块复用、误差传播」，端到端「一体化、信息保真」。语音多模态的当前阶段是「端到端理解已成熟、端到端生成在路上」——<strong>语音生成的「音质」仍是难点</strong>（声码器是最后瓶颈）。</span>

## 4 公式解析：音频特征的时间下采样

音频「太长」——所以音频编码器要做**时间下采样**。Whisper 编码器把「每 20ms 一帧」压到「每 320ms 一特征」：

$$
\text{帧数} = \frac{\text{时长}}{20\text{ms}}, \qquad
\text{特征数} = \frac{\text{帧数}}{\text{下采样率} \times 2} \approx \frac{\text{时长}}{320\text{ms}}
$$

（Whisper 编码器有 2 层「时间卷积 + 池化」，整体下采样 32 倍）

对这条式子做三步拆解：

- **第一步，读帧数**：30 秒音频 = 1500 帧（20ms 一帧）——帧率太高，LLM 装不下。
- **第二步，读下采样**：Whisper 编码器通过卷积/池化把时间维压 32 倍——1500 帧 → 1500/32 ≈ 47 个特征。
- **第三步，读出「时间 token」量级**：30 秒音频 ≈ 47 个特征——**与视觉 token 量级相当**。这就是「为什么音频要先编码器下采样」：把「原始帧」压到「LLM 可处理的 token 数」。

**辨析｜易错点：** 音频的「特征」是「时间序列」——它没有「空间结构」（不像图像 patch 有 2D 布局）。所以音频特征进 LLM 时**不需要 2D 位置编码**，只用「时间顺序」——音频是「一维序列」，比图像「更接近文本」。

## 5 音频多模态的训练配方

- **阶段一**：音频编码器（Whisper/HuBERT）预训练——「听懂语音」。
- **阶段二**：对齐预训练——音频特征与文本空间对齐。
- **阶段三**：语音指令微调——「听指令、答问题」。
- **特殊挑战**：长音频（记忆）、噪声鲁棒、多说话人区分。

## 7 数值算例：语音 token 的量级

对比不同语音表示的「每秒 token 数」：

| 表示方式 | 每秒 token | 30 秒音频 |
| --- | --- | --- |
| 连续特征（Whisper 下采样后） | 约 3 个 | 约 90 |
| 连续特征（原始帧） | 50 个 | 1500 |
| 离散 token（SpeechTokenizer） | 约 25 个 | 约 750 |

**读这张表**：原始音频帧（50/s）对 LLM 是天文数字；必须「下采样」或「离散化」压到可控量级。**音频 token 化的本质是「时间压缩」**——把「每秒 50 帧的声学细节」压到「LLM 能处理的语义 token」。压缩率越高、语义越抽象，但「音色、语气」等细节丢得越多。

**辨析｜易错点：** 语音 token 与文本 token 的「长度对齐」很重要——LLM 在处理「语音 token 序列」时，要能理解「这段语音对应哪些语义」。**「token 对齐」（音频 token 与文本 token 的对应）是语音 LLM 训练的关键细节**——对齐错了，模型「听不懂哪段语音说了什么」。

## 8 各模态的 token 效率对照

| 模态 | tokenizer | 每秒/每帧 token |
| --- | --- | --- |
| 文本 | 无（直接） | 每秒约 5–10 词 |
| 音频连续 | Whisper 编码器 | 约 3 特征 |
| 音频离散 | SpeechTokenizer | 约 25 token |
| 视频 | 帧采样 | 每帧 196–1024 token |

**读这张表**：音频与视频的「信息密度」远高于文本——**多模态的「token 贵」是全方位的**。这也是为什么「模态 token 压缩」是每一类多模态（图像、音频、视频）的共同效率课题。

## 9 小结

- **Whisper**：语音识别的编码器-解码器地基——「音频世界的 CLIP ViT」。
- **两条 token 路线**：连续编码器特征（保音质）vs 离散语音 token（LLM 友好）——主流偏离散。
- **端到端 Speech LLM**：语音直接进 LLM——「听语气」是它独有的能力。
- **时间下采样**：音频编码器把「20ms 一帧」压到「320ms 一特征」——「时间 token」量级可控。
- 音频是「一维时序」，比图像更接近文本——位置只用「时间顺序」。
