## 为什么「三段式」不是终点

三段式 VLM（编码器-对齐-LLM）是「拼接」——视觉和文本各走各的，靠「翻译」桥接。**原生多模态（native multimodal）** 追求另一种形态：**所有模态从一开始就在同一个 token 空间里**——图像、文本、音频、视频都是「token」，模型做「统一的 Next-Token 预测」。理解与生成不再分「编码器」与「解码器」，而是「同一个预测过程」。<span class="marginnote">三段式的「拼接感」在于：视觉编码器、投影器、LLM 是「三个可分的组件」。原生多模态想「消掉拼接」——<strong>让模型从输入起就把图像当 token 处理</strong>。Gemini 是「原生多模态」的代表（虽然细节未公开），而「统一 token 空间」正在成为下一代多模态的方向。</span>

## 1 从「拼接」到「统一」：范式的转变

**三段式的逻辑**：图像 →（视觉编码器）→ 视觉特征 →（投影器翻译）→ LLM 认识 →（LLM）→ 文本。

**原生多模态的逻辑**：图像 →（tokenizer）→ 图像 token → 与文本 token 一起 →（一个 Transformer）→ 下一个 token。

关键差异：

| 维度 | 三段式 | 原生多模态 |
| --- | --- | --- |
| 组件 | 编码器 + 投影器 + LLM | 一个统一模型 |
| 图像表示 | 连续特征（进投影器） | 离散 token（进 Transformer） |
| 理解/生成 | 理解靠编码器、生成靠 LLM | 同一个 Next-Token |
| 模态间交互 | 靠「拼接 + 注意力」 | 从一开始「同构」 |

**原生多模态的「统一」**：图像 token 与文本 token 有**相同的格式**——Transformer 不需要「知道」哪个是图像、哪个是文本，只需要「预测下一个 token」。「模态」的区别只体现在「token 的来源」，不体现在「处理方式」。

## 2 图像怎么「原生 token 化」：从 patch 到 token

原生多模态的核心技术是「**图像 tokenizer**」——把图像变成「离散 token」，就像文本 tokenizer 把词变成 id：

**① Patch-based（类 ViT）**：图像切 patch，每个 patch 是「一个 token」。

- 用「离散化」：把 patch 特征映射到「离散码本」（VQ-VAE 式）——patch → 码本 index。
- 或直接「连续 token」（图 patch 特征当 token）——但这样「不是离散的」。

**② VQ-GAN / VQ-VAE（离散图像 token）**：

- 编码器：图像 → 连续特征。
- 码本（codebook）：把特征映射到「最近的码本向量」——得到「离散 index」。
- 解码器：从 index 重建图像（用于「生成图像」）。

**离散图像 token 的意义**：**让「生成图像」变得像「生成文本」**——模型预测「图像 token 序列」，就是「在生成图像」。这就是「统一生成」的基础：**一个 Next-Token 预测器，既能生成文本也能生成图像**。

## 3 统一理解与生成：一个模型做所有事

原生多模态的「终极目标」：**一个模型，既理解又生成，且所有模态统一**。

**「理解」是 Next-Token 预测**：给图像 + 问题 → 预测「答案 token」——「理解」通过「生成正确答案」体现。

**「生成图像」是 Next-Token 预测**：给文本提示 → 预测「图像 token 序列」→ 解码成图像。

**「语音」也是 token**：语音 tokenizer → 语音 token——「听懂」是预测「正确的文字/动作 token」，「说话」是预测「语音 token」。

**这就是「统一」的哲学**：**所有智能行为都是「在给定上下文中预测下一个 token」**——CLM 的「功」（第一篇讲过）在多模态上被推向极致。<span class="marginnote">原生多模态把「CLM 的野心」发挥到极限：<strong>「预测下一个 token」不限于文本——图像 token、音频 token、视频 token 都是「下一个」</strong>。这带来一个优雅的统一：理解和生成（文本/图像/语音）不再是「不同任务」，而是「同一个预测器的不同输入输出」。代价是「图像 token 的生成质量」与「跨模态的对齐」需要更强的训练。</span>

## 4 公式解析：统一的 Next-Token 目标

原生多模态的训练目标，形式上与文本 CLM 完全一样：

$$
\mathcal{L} = \sum_{t=1}^{T} \log p(x_t \mid x_{<t}), \qquad x_t \in \text{所有模态的 token}
$$

其中 $x_t$ 可以是文本 token、图像 token、音频 token——**混合在一个序列里预测**。

对这条式子做三步拆解：

- **第一步，读懂 $x_t$ 的「跨模态」**：序列 $x_1, x_2, \ldots$ 是「图文声混合」的 token 流——比如「图像 token → 文本 token → 语音 token」。模型「不知道」哪种 token，只知道「预测下一个」。
- **第二步，读懂条件的跨模态**：$x_{<t}$ 包含所有模态的过去——预测「文本 token」时，条件里有「图像 token」（看图说话）；预测「图像 token」时，条件里有「文本 token」（文生图）。**跨模态的信息流动靠「同一个注意力」**。
- **第三步，读出统一性**：**目标函数不区分模态**——这就是「原生」的含义：不是「图像用编码器、文本用解码器」的分工，而是「一切皆 token、预测即一切」。

**辨析｜易错点：** 原生多模态 ≠ 三段式的消失。Gemini 等「原生」模型**内部仍有视觉编码器**（图像要「预处理」成 token）——「原生」指的是「模型内部统一处理」，不是「没有编码器」。区别在于：**三段式的编码器输出「连续特征」（另一套表示），原生模型的编码器输出「token」（与文本同构）**。

## 5 原生多模态的挑战与现状

- **挑战一：图像 token 的生成质量**——离散图像 token 的「信息损失」导致「生成模糊」。
- **挑战二：训练数据**——需要「图文声对齐」的联合数据，比纯文本难得多。
- **挑战三：计算**——视觉 token 量大，统一模型的计算负担重。
- **现状**：Gemini（Google）宣称原生多模态；Qwen2.5-Omni、GPT-4o 等「全能模型」正在逼近「一个模型做所有模态」。

## 6 小结

- 三段式是「拼接」——编码器/投影器/LLM 可分；原生多模态是「统一」——一切皆 token。
- **图像 tokenizer**（VQ-VAE 式）让「图像生成」变得像「文本生成」。
- **统一目标**：$\sum \log p(x_t \mid x_{<t})$，$x_t$ 跨所有模态——「预测即一切」。
- 原生 ≠ 无编码器：区别在「输出连续特征」还是「输出 token」。
- 挑战：图像 token 质量、联合数据、计算——「全能模型」正在路上。
