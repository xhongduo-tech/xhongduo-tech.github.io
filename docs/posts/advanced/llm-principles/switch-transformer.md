## 为什么 Switch 是 MoE 大规模化的"起点"

在 Switch Transformer 之前，MoE 论文（Shazeer 2017）用 Top-2 路由且训练不稳定，规模被限制。Switch Transformer 做了两件「化繁为简」的事：**每个 token 只路由到 1 个专家（Top-1）**，以及**引入容量因子从物理上约束负载**。靠着这两个简化，它训练出 1.6 万亿参数的模型——比当时的 T5-XXL 快 4–7 倍预训练速度，成为 MoE 大规模化的里程碑。<span class="marginnote">Switch 的哲学是「路由越简单，规模越能推大」：Top-1 省去「两个专家的混合权重」，把 MoE 层的计算从「2 个专家 + 加权」简化成「1 个专家 + 门控」。计算量与通信量都大幅下降，从而支持上万专家的大规模并行。Google 后来用它在 30 亿 token 上验证了「大 MoE 的训练速度优势」。这篇拆解它的两个核心设计。</span>

## 1 Top-1 路由：只去一个专家

Switch 的路由器输出每个 token 与 $E$ 个专家的概率，然后**只选概率最高的那一个**：

$$
p_i(x) = \text{softmax}\big(x W_r\big)_i, \qquad \text{expert}(x) = \arg\max_i p_i(x)
$$

**为什么 Top-1 反而更好？**

- **计算量减半**：Top-2 要算 2 个专家的 FFN；Top-1 只算 1 个，MoE 层的 FLOPs 直接减半。
- **通信量减半**：token 只需被送到 1 张卡的专家，**all-to-all 的通信量（每个 token 的拷贝份数）**减半。
- **实现更简单**：不需要「混合两个专家的输出」，门控即 **$\arg\max$（硬选择）**。
- **负载更易控制**：每个 token 的「去向」唯一确定，容量管理更直接。

**代价**：路由一旦选错，没有备选纠错。但 Switch 的实验发现：Top-1 的质量损失很小，而规模化的收益巨大——**「更简单的路由」在规模上赢过「更聪明的路由」**。<span class="marginnote">这个「简化反而更好」的现象在深度学习中反复出现：Switch 的 Top-1、FlashAttention 的精确重排、Pre-LN 的稳定优先——都是「去掉复杂度、换取可规模化性」的案例。MoE 的规模化瓶颈常常不是「算法不够聪明」，而是「工程不够简单」。</span>

## 2 专家容量因子：硬性的负载上限

**容量因子（capacity factor, C）** 定义每个专家每轮最多能处理的 token 数：

$$
\text{capacity} = C \cdot \frac{T}{E}
$$

其中 $T$ 是 batch 的 token 总数，$E$ 是专家数，$T/E$ 是「完全均衡」时每个专家的理想负载，$C$ 是松弛因子。

- **$C = 1.0$**：每个专家恰好处理 $T/E$ 个 token——最严格，任何不均衡都会导致 token 被丢弃。
- **$C = 1.25$（Switch 默认）**：每个专家能多处理 25%——容忍轻微不均衡。
- **$C = 2.0$**：更宽松，几乎不丢 token，但专家计算出现空闲。

**被丢弃的 token 怎么办**：Switch 把超容量的 token 直接**跳过**（不经过任何专家），只经过残差路径——输出等于输入。这听起来「丢信息」，但实际上：

- 被丢弃的 token 在训练里仍通过残差流前向，其梯度仍然存在（只是不经过专家）；
- 容量因子对「多少 token 被丢」有直接控制，实践中 $C=1.25$ 只丢不到 1% 的 token，影响可忽略。<span class="marginnote">容量因子的价值在于「把负载均衡从『软损失』升级为『硬约束』」：辅助损失是「鼓励均衡」，容量因子是「强制均衡」——超出的物理上处理不了。两者的配合（损失引导 + 容量兜底）让 Switch 在 1.6T 参数上稳定训练。代价是容量因子过高会浪费算力（专家空转），需要调优。</span>

## 3 Switch 的架构细节

- **专家替换 FFN**：Switch 只把「前馈层」替换成 MoE，注意力与其余结构不变——与 MoE 的通用做法一致。
- **可并行计算**：同一层的 $E$ 个专家可分布在 $E$ 张卡上，batch 内 token 按路由分发给各卡。
- **辅助损失**：用上一节的 $\alpha E \sum f_i P_i$，与容量因子双保险。
- **精度/规模权衡**：Switch 论文的一个重要发现——**用更多专家时，可以把每个专家的「尺寸」缩小**（如 FFN 中间维度减半），在同样算力下获得更优的「参数-质量」曲线。

**Switch 的「缩放公式」**：一个 MoE 模型的质量由「总参数 × 激活参数比」决定。Switch 实验表明，在固定 FLOPs 下，**MoE 的困惑度随专家数增加而下降**——更多专家 = 更大容量 = 更低 loss，而计算量不变。这就是「免费午餐」：用参数换质量，不用算力换。

## 4 公式解析：容量因子对有效批量的影响

设容量因子 $C$，专家 $i$ 本轮收到 $n_i$ 个 token，则实际处理的 token 数：

$$
n_i^{\text{actual}} = \min(n_i, \; C \cdot \frac{T}{E})
$$

被丢弃的 token 比例（**token 丢弃率**）：

$$
\text{drop rate} = \frac{\sum_i \max(0, n_i - C T/E)}{T}
$$

对这两条式子做三步拆解：

- **第一步，读懂上限**：每个专家最多处理 $C T/E$ 个 token——**硬性上限**，与「实际分配多少」无关。
- **第二步，理解丢弃的来源**：只有「分配不均」才产生丢弃——完全均衡时 $n_i = T/E \le CT/E$（$C \ge 1$），零丢弃。**丢弃率是负载失衡的「惩罚度量」**。
- **第三步，读出调参**：$C$ 增大 → 丢弃减少但专家空转增加；$C$ 减小 → 强制均衡但可能丢信息。**$C$ 是「效率 vs 完整」的旋钮**，Switch 的经验值是 1.0–1.25。

**辨析｜易错点：** 容量因子是「每层每个专家每轮」的约束，不是「全局 token 上限」。$C \cdot T/E$ 里的 $T$ 是该 MoE 层的 token 总数（= batch × 序列长），不是整个模型的数据量。另外「丢弃 token」不等于「丢弃数据」——它仍走残差路径，梯度仍回传。

## 5 Switch 的影响与局限

**影响**：

- 确立「**Top-1 + 容量因子 + 辅助损失**」为标准 MoE 配方，后续 GShard、Mixtral、DeepSeekMoE 都在这基础上演化。
- 证明「**参数换质量不换算力**」的规模化路径，让万亿参数模型在经济上可行。
- 带火了「稀疏激活」在 NLP 大模型中的应用。

**局限**：

- Top-1 的「单选」在长上下文、精确检索任务上可能不如 Top-2 稳。
- 容量因子调参敏感，且「丢弃」在推理期不可接受（推理不能丢 token）。
- 未解决「专家间通信」的根本成本（all-to-all）。

## 7 数值算例：容量因子与丢弃

设 batch token $T=8192$、专家 $E=64$、容量因子 $C=1.25$：

$$
\text{capacity} = 1.25 \times \frac{8192}{64} = 1.25 \times 128 = 160 \text{ token/专家}
$$

- **完全均衡**：每个专家 128 token，低于 160，零丢弃。
- **某专家过热**：收到 200 token → 只处理 160，丢弃 40 个（约 0.5% 总 token）。
- **$C=1.0$**：容量 128——任何「不是恰好均衡」都触发丢弃。

**读这笔账**：$C$ 给负载「留了 25% 的缓冲」，把「轻微失衡」吸收掉；$C=1.0$ 则「零容忍失衡」。**容量因子是「失衡容忍度」的旋钮**——太大浪费算力（专家空转），太小逼得太紧（频繁丢弃）。

**辨析｜易错点：** 被丢弃的 token「跳过专家」不等于「消失」——它仍通过残差路径前向、梯度仍回传。**训练时丢弃「可接受」（贡献不经过专家的梯度），推理时丢弃「不可接受」（推理不能丢 token）**——所以推理的容量因子通常取较大值或换用其他方案。

## 8 Top-1 vs Top-2 路由：一张对照

| 维度 | Top-1 | Top-2 |
| --- | --- | --- |
| 每 token 计算 | 1 个专家 | 2 个专家 |
| 通信量 | 少 | 多 |
| 质量 | 略低 | 略高 |
| 负载控制 | 直接 | 复杂 |
| 代表 | Switch | Mixtral、GShard |

Top-1 的「简化」换来「规模化」：**当「规模收益」大于「单点质量损失」时，简化更优**——Switch 在 1.6T 参数上证明了这一点。

## 9 小结

- Switch = **Top-1 路由 + 容量因子 + 辅助均衡损失**的三件套。
- Top-1 让**计算量与通信量减半**，是「简化换规模化」的典范。
- 容量因子 $C \cdot T/E$ 从物理上强制均衡，超量 token 被丢弃（只走残差）。
- 「参数换质量、不换算力」——MoE 的规模化红利。
- Switch 是 MoE 大规模化的起点，后续方案都是它的演化。
