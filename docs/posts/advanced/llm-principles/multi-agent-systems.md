## 为什么「一群 Agent」可能比「一个 Agent」强

单个 Agent 受「一个视角」与「一个上下文」的限制——它「想不到别的角度」「记不住所有细节」。**多智能体系统（Multi-Agent System）** 让多个「各司其职」的 Agent 协作：**角色分工**（一个写代码、一个审查、一个测试）、**辩论**（一个提方案、一个挑毛病）、**协作**（各自完成一部分，拼成整体）。群体智能的假设：**「多视角 + 多角色」能覆盖「单视角」的盲区**。<span class="marginnote">多智能体的「灵感」来自「真实组织」：<strong>软件公司不是「一个程序员」，而是「产品经理 + 开发 + 测试 + 设计」的分工协作</strong>——每个角色有「独特视角与专长」，协作产生「个体做不到的产出」。AutoGen（微软）、MetaGPT、ChatDev 都是「让 LLM 扮演不同角色协作」的代表。</span>

## 1 角色分工：让每个 Agent 各司其职

**角色分工（role specialization）** 给每个 Agent 一个「身份 + 职责」：

```text
产品经理 Agent：拆解需求 → 输出任务清单
开发 Agent：按任务清单实现 → 输出代码
测试 Agent：验证代码 → 输出测试报告
```

**每个角色的 prompt**：

**身份**：「你是一名资深 Python 开发者」。
**职责**：「你负责根据需求实现功能」。
**边界**：「你只负责实现，不负责测试」。

**为什么分工有效**：

**专注**：每个 Agent 的上下文「聚焦」自己的职责——「记忆负担」小。
**多视角**：不同角色「看到不同问题」——开发看不到的 bug，测试能看到。
**质量把关**：审查/测试 Agent「独立检查」——「自己写的自己看不见错」。

**分工的关键**：**角色间「交接」要清晰**——「产品经理的输出」是「开发的输入」——「接口」定义清楚，协作才顺畅。

## 2 辩论：让 Agent 互相挑错

**辩论（debate）** 让多个 Agent「观点交锋」——一个提方案、一个质疑、再综合：

```text
提案者：我的方案是「用贪心解码」。
质疑者：贪心容易陷入重复，应该改用采样。
提案者：那折中——beam search + 温度控制。
综合者：采纳「top-p 采样」，兼顾质量与多样性。
```

**辩论的形式**：

**双人辩论**：提案者 vs 质疑者——「一问一答」逼近最优。
**多人陪审团**：多个 Agent 给方案、互相评估、投票。

**为什么辩论有效**：

**打破「思维定势」**：单 Agent 可能「陷在第一个想法」；质疑者「逼它重新考虑」。
**暴露「盲区」**：提案者「看不到的缺陷」，质疑者「能发现」。
**多视角综合**：辩论的结论「吸收多个视角」——比「单视角」更全面。

**辩论的局限**：**「嘴仗」可能不收敛**——两个 Agent 各说各话、循环争论。需要「主持人」或「投票机制」终止辩论。<span class="marginnote">辩论的「收敛性」是工程难点：<strong>没有「终止条件」的辩论是「无限嘴仗」</strong>——需要「轮数上限」「投票决胜」「主持人裁决」。这也提示「辩论」是「手段」不是「目的」——「产出最优结论」才是目的，辩论只是「逼近」的方式。</span>

## 3 协作框架：AutoGen 与角色编排

**AutoGen**（微软）提供了「多 Agent 协作」的框架基础：

**核心概念**：

- **Agent**：一个「角色」——LLM 背后加上「工具 + 记忆」。
- **ConversableAgent**：能「对话」的 Agent——可配置「角色 + 工具 + 终止条件」。
- **GroupChat**：多个 Agent 的「群聊」——消息在 Agent 间传递。

**协作模式**：

- **接力**：A 做完传给 B，B 做完传给 C——「流水线」。
- **群聊**：所有 Agent 在「一个群」里发言——「自由讨论」。
- **层级**：一个「管理者」Agent 调度「下属」Agent——「经理-员工」模式。

**AutoGen 的关键设计**：**「终止条件」**——每个对话要定义「何时结束」（达成目标/超时/轮数）——**否则协作「停不下来」**。

## 4 公式解析：多智能体的「分工增益」

多智能体「分工」的收益可以用「概率」量化。设任务分解为 $K$ 个子任务，单 Agent「全做」的正确率为 $p$，分工后每个子任务由「专精 Agent」做、正确率 $p_i > p$：

$$
\text{单 Agent: } P_{\text{all}} = p^K, \qquad
\text{多 Agent 分工: } P_{\text{all}}' = \prod_{i=1}^{K} p_i
$$

对这两条式子做三步拆解：

- **第一步，读单 Agent**：$p^K$——「每步正确率 $p$、$K$ 步都对」——**任务越长，成功概率指数下降**（$p=0.9, K=5 \to 0.59$）。
- **第二步，读多 Agent 分工**：$\prod p_i$——每个子任务的正确率 $p_i$（因专精而更高）——**分工提升每一步的正确率**。
- **第三步，读出分工的价值**：如果专精让 $p_i = 0.98 > 0.9$，$K=5$ 时 $\prod p_i = 0.9$ vs $p^K = 0.59$——**分工的「专精增益」随任务复杂度放大**。这就是「为什么复杂任务用多 Agent」——**分工的收益在「长任务」上最大**。

**辨析｜易错点：** 多智能体不是「必然更好」——有「协作成本」：Agent 间「通信开销」（上下文传递）、「协调难度」（谁做什么）、「错误传播」（上游错下游难发现）。**「分工的收益」要大于「协作的成本」才值得**——简单任务用单 Agent，复杂任务才上多 Agent。

## 5 多智能体的工程实践

- **角色设计**：给每个 Agent「清晰的身份 + 职责 + 边界」——「分工要明确」。
- **通信协议**：Agent 间「结构化消息」（JSON）——「传递什么、格式如何」。
- **终止条件**：轮数/目标/投票——「协作要能停」。
- **状态管理**：全局状态（任务进度、产出物）——「共享的工作台」。
- **评测**：多 Agent 的「端到端成功率」+「协作效率」——「分工值不值」。

## 6 小结

- **多智能体**：多个角色 Agent 分工、辩论、协作——「群体智能」。
- **角色分工**：每个 Agent 专注一职——「专注 + 多视角 + 把关」。
- **辩论**：提案 vs 质疑——「打破定势 + 暴露盲区」，但要注意收敛。
- **AutoGen**：接力/群聊/层级三种协作模式 + 终止条件。
- 分工增益：**专精提升每步正确率——长任务上收益最大**；但协作有成本——「按需上多 Agent」。
