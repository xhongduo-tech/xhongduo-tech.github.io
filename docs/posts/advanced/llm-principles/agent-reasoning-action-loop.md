## 为什么 LLM 需要「行动」

纯 LLM 是「语言模型」——它「生成文本」，但「不能做事」：不能查数据库、不能调 API、不能运行代码。**Agent（智能体）** 让 LLM 具备「行动能力」——模型在「推理」与「行动」之间循环：**思考该做什么 → 调用工具执行 → 观察结果 → 再思考下一步**。**ReAct（Reasoning + Acting）** 是这个范式的经典框架——把「推理」（想）与「行动」（做）交错进行，让模型「边想边做」地完成任务。<span class="marginnote">ReAct 来自 Yao et al. 2022，它融合了两条思路：<strong>CoT（推理）让模型「想」，工具调用（Acting）让模型「做」</strong>——两者交错，模型「想一步、做一步、看结果、再想」。这像人类解决问题：<strong>「先想怎么做、然后动手做、看结果对不对、再调整」</strong>——Agent 是把「人类的做事方式」教给模型。</span>

## 1 ReAct 的循环：Thought → Action → Observation

ReAct 让模型交替生成三种「动作」：

一个典型轨迹长这样：**Thought：「用户问天气，需要查天气 API」→ Action：`Search[北京 天气]` → Observation：「晴，最高 25°C」**——模型看到观察后，生成下一轮 Thought，直到给出最终答案。

**Thought（思考）**：模型「想」——「我现在需要做什么」。
**Action（行动）**：模型「调用工具」——搜索、计算、代码执行。
**Observation（观察）**：工具返回结果——「查到的数据」「计算结果」。

**循环**：Thought → Action → Observation → Thought → ……直到任务完成。

**为什么「思考」与「行动」交错重要**：

纯推理（CoT）：光想不做——「想对了但没执行」。
纯行动：光做不想——「做了但没方向」。
ReAct：**「想一步做一步」**——行动「验证」思考，观察「更新」思考——**闭环修正**。<span class="marginnote">ReAct 的「闭环」价值：<strong>行动的结果（Observation）成为下一轮思考的「事实输入」</strong>——模型「看到真实结果」，不再「凭空想」。这大幅减少了幻觉：模型「不确定就查」，而不是「编」。这也是「Agent 比纯 LLM 可靠」的根本原因——<strong>Agent 的「知识」来自「实时观察」，而非「参数记忆」</strong>。</span>

## 2 Agent 的核心组件

一个完整的 Agent 系统有四个组件：

**① 大语言模型（大脑）**：负责「推理」——决定「做什么、怎么做」。

**② 工具（Tool）**：模型可调用的「外部能力」——搜索、计算、代码执行、API 调用、数据库查询。

**③ 观察（Observation）**：工具的结果——模型的「感知」——「看到」行动的效果。

**④ 循环控制器（Loop）**：控制「推理-行动-观察」的循环——何时继续、何时停止（任务完成/超时/失败）。

**工具是 Agent 的「手和眼」**：

| 工具 | 能力 | 例子 |
| --- | --- | --- |
| 搜索 | 实时信息 | web search、知识库检索 |
| 计算 | 精确计算 | calculator、代码执行 |
| 代码执行 | 运行程序 | Python REPL、SQL 查询 |
| API | 外部服务 | 天气 API、数据库、购物 |
| 文件 | 读写文件 | 读文档、写报告 |

## 3 ReAct 与其他范式的对比

Agent 范式有几种「变体」，各有侧重：

| 范式 | 特点 | 适合 |
| --- | --- | --- |
| ReAct | 推理-行动交错 | 需要「边做边想」的任务 |
| Plan-and-Execute | 先规划、再执行 | 复杂任务（先列计划） |
| Reflexion | 失败后反思、再试 | 需要「从错误学习」的任务 |
| Toolformer | 训练「何时调用工具」 | 工具调用内化为能力 |

**ReAct 的定位**：**最基础的 Agent 范式**——「思考 + 行动」的循环骨架——后续的 Plan-and-Execute（加「规划层」）、Reflexion（加「反思层」）都是 ReAct 的扩展。

**ReAct 的局限**：

- **短视**：每一步「只看当下」——没有「全局规划」。
- **循环低效**：可能「来回试错」——没有「计划」约束。
- **工具选择依赖推理**：模型「选错工具」就「做错事」。

## 4 公式解析：Agent 的「轨迹」概率

Agent 的完整行为是一条「轨迹」（trajectory）——思考、行动、观察交替：

$$
\tau = [\text{Thought}_1, \text{Action}_1, \text{Obs}_1, \text{Thought}_2, \text{Action}_2, \ldots, \text{Final}]
$$

Agent 的「策略」$\pi_\theta$ 生成这条轨迹的概率：

$$
p(\tau) = \prod_{t} p_\theta(\text{Thought}_t, \text{Action}_t \mid \text{历史}) \cdot p(\text{Obs}_t \mid \text{Action}_t)
$$

对这条式子做三步拆解：

- **第一步，读懂第一项**：$p_\theta(\text{Thought}_t, \text{Action}_t \mid \text{历史})$——模型基于「之前的轨迹」决定「下一轮想什么、做什么」——**这是「策略」**（模型可学习的部分）。
- **第二步，读懂第二项**：$p(\text{Obs}_t \mid \text{Action}_t)$——工具对「行动」的返回——**这是「环境的响应」**（模型不可控、只能观察）。
- **第三步，读出 Agent 的本质**：Agent = **「模型策略」×「环境反馈」的循环**——模型「决定动作」、环境「返回观察」、模型「再决定」。**Agent 是一个「与环境交互的闭环系统」**——这也是它被归入「强化学习」语境的原因（策略优化训练 Agent）。

**辨析｜易错点：** Agent 的「工具调用」不是「模型生成的代码被无条件执行」——**工具执行是「环境动作」，有副作用**（改数据库、发邮件）。生产级 Agent 要「工具白名单」「权限控制」「人工确认」——「安全」是 Agent 工程的核心（第十六篇会讲越狱与注入）。

## 5 Agent 的评测与工程

- **任务成功率**：Agent 完成任务的「端到端成功率」——核心指标。
- **工具使用正确率**：选对工具、用对参数的比率。
- **鲁棒性**：面对「错误观察」「工具失败」时的恢复能力。
- **工程**：ReAct 的 prompt 模板、工具注册、循环超时、错误处理——「让 Agent 在真实环境稳定跑」是工程难点。

## 6 小结

- **Agent**：LLM + 工具 + 观察 + 循环——从「聊天」到「办事」。
- **ReAct**：Thought → Action → Observation 的循环——「边想边做」。
- 核心组件：**LLM（大脑）+ 工具（手眼）+ 观察（感知）+ 循环（控制）**。
- ReAct 是基础范式——Plan-and-Execute、Reflexion 是它的扩展。
- Agent 是「与环境交互的闭环」——**「安全与鲁棒」是工程核心**。
