## 为什么「加个视觉编码器」就行

让语言模型理解图像，最主流的做法是「三段式」：**视觉编码器**（把图像变成向量）→ **对齐模块**（把视觉向量翻译成语言模型能懂的表示）→ **大语言模型**（基于视觉+文本做推理）。这套「先翻译再理解」的架构统治了 LLaVA、Qwen-VL、GPT-4V 等几乎所有 VLM。<span class="marginnote">「三段式」的聪明之处在于「复用」：语言模型的「世界知识」与「推理能力」已经在预训练里练好了，不必为图像重练——<strong>只需要「教会它读视觉输入」</strong>。这像给一个博学的人配一副「眼镜」：知识不用重学，只需「看得见」。这比「端到端训练多模态模型」省得多。</span>

## 1 第一段：视觉编码器——把图像变成「向量序列」

**视觉编码器（vision encoder）** 把图像 $I$ 映射成「视觉 token」序列：

$$
Z_v = \text{ViT}(I), \qquad Z_v \in \mathbb{R}^{N \times d_v}
$$

$N$ 是视觉 patch 数（如 14×14 的网格），$d_v$ 是视觉特征维度。主流选择是 **ViT**（视觉 Transformer）或其变体：

- **ViT**：把图像切成 patch（如 14×14），每个 patch 过一层 Transformer 得到「patch 特征」。
- **SigLIP / CLIP 的 ViT**：用对比学习预训练过的视觉编码器——特征「语义对齐」更好。
- **动态分辨率**（Qwen-VL 等）：不同尺寸图像用不同 patch 数——保留细节。

**视觉 token 的含义**：一个 patch 特征 ≈ 「这个小区域的语义」（颜色、形状、物体、文字）。$N$ 个 patch 特征组成「图像的视觉序列」——**图像被「token 化」了**。<span class="marginnote">「图像 → 视觉 token」是整条链路的起点：它让图像「进入了序列的世界」——后面才能和文本 token 一起喂给语言模型。视觉编码器的质量决定了「模型能看到多细」：patch 越小、特征越好，模型「眼神越好」。</span>

## 2 第二段：对齐模块——把视觉特征翻译成「LLM 语言」

视觉特征 $Z_v$（维度 $d_v$）与语言模型的文本嵌入（维度 $d$）**不在一个空间**——必须「翻译」成 LLM 能懂的表示。这就是**对齐模块（projector / adapter）**：

$$
Z = \text{Projector}(Z_v), \qquad Z \in \mathbb{R}^{N \times d}
$$

对齐模块的常见形态：

- **线性投影**：一层线性层，把 $d_v$ 映射到 $d$——最简单。
- **MLP**：两三层 MLP——更灵活，LLaVA 用 MLP。
- **Q-Former / 交叉注意力**（BLIP-2）：用「查询向量」从视觉特征里「提炼」固定数量的信息——更精细。
- **下采样**（Qwen-VL）：把 $N$ 个视觉 token 压到更少（如 256 个）——省 LLM 的计算。

**对齐模块的「翻译」本质**：它让「图像 patch 的语义」以「LLM 词嵌入」的形式进入模型——**对齐模块是「图像世界」与「语言世界」的桥梁**。<span class="marginnote">对齐的质量决定「LLM 能不能『读懂』图像」：如果对齐不好，视觉特征「语无伦次」，LLM 无从理解。训练时，对齐模块通过「视觉指令微调」学习——<strong>用「看图问答」的数据，逼它对齐模块学会「把图像翻译成人话」</strong>。这是三段式里「最需要训练」的一段。</span>

## 3 第三段：大语言模型——基于「视觉+文本」推理

对齐后的视觉 token 与文本 token **拼在一起**，喂进 LLM：

$$
\text{input} = [\text{图像token}: Z_1, \ldots, Z_N, \text{文本token}: w_1, \ldots, w_M]
$$

LLM 基于「图像 + 文本」做自回归生成——回答关于图像的问题、描述图像、按图推理。

**关键**：LLM 的「世界知识」被复用——它「读过」大量文本，知道「猫、汽车、巴黎」是什么；现在「看见」图像，就把「视觉信息」与「已有知识」结合。

**LLM 是否冻结**：三种策略：

- **完全冻结**：只训对齐模块（轻量，但能力有限）。
- **部分微调**：训对齐 + LLM 的低秩增量（LoRA）——主流。
- **全量微调**：所有参数都训——最强但最贵。<span class="marginnote">「LLM 冻结与否」是 VLM 训练的核心权衡：冻结省算力但「读图能力」受限；全量微调最强但可能「遗忘」纯文本能力。主流（LLaVA 系列）是「对齐 + LoRA」——在「成本」与「能力」之间取平衡。这也解释了为什么 VLM 训练「先对齐、后微调」两阶段。</span>

## 4 公式解析：三段式的「形状对齐」

用张量形状把三段式钉死。设图像 patch 数 $N$、视觉特征维 $d_v$、LLM 宽度 $d$：

$$
\underbrace{\mathbb{R}^{H \times W \times 3}}_{\text{图像}} \xrightarrow{\text{ViT}} \underbrace{\mathbb{R}^{N \times d_v}}_{\text{视觉token}} \xrightarrow{\text{Projector}} \underbrace{\mathbb{R}^{N \times d}}_{\text{对齐}} \xrightarrow{\text{拼接}} \underbrace{\mathbb{R}^{(N+M) \times d}}_{\text{LLM输入}}
$$

对这条式子做三步拆解：

- **第一步，读懂前两段**：ViT 把「像素空间」变成「patch 特征空间」——$H\times W$ 图像 → $N$ 个 patch → $N \times d_v$ 的特征序列。
- **第二步，读懂对齐**：Projector 把 $d_v$ 维映射到 $d$ 维——**「翻译」发生在维度变化上**。$N$ 不变（patch 数守恒），维度变了（对齐到 LLM）。
- **第三步，读懂拼接**：视觉 token 与文本 token 拼成一条序列，一起过 LLM——**LLM 看到的是一条「图文混合」的 token 流**。这就是「多模态」的序列化表达：**一切模态最终都变成「token 序列」**。

**辨析｜易错点：** 视觉 token 的「数量」$N$ 通常远大于文本 token 数——一张 448×448 图像有 1024 个 patch token。**视觉 token 是「大头」**——LLM 计算量主要花在视觉 token 上。这就是「为什么要下采样/压缩视觉 token」（Qwen-VL 压到 256 个）：**省视觉 token = 省 LLM 计算**。

## 5 三段式的演化与局限

- **演化**：线性投影（早期）→ MLP（LLaVA）→ Q-Former/下采样（BLIP-2/Qwen-VL）→ 原生多模态（统一 token 空间，第十二篇末讲）。
- **局限一**：视觉编码器是「预训练好的」——它的「分辨率/领域」受限，模型「眼神」的天花板由编码器决定。
- **局限二**：对齐是「翻译」——翻译难免「丢失细节」（复杂空间关系、细粒度计数）。
- **局限三**：三段式是「拼接」——图像与文本的「深度融合」（如「图像里的逻辑」）不如原生多模态。

## 7 数值算例：视觉 token 是计算大头

设一张 448×448 图像过 patch=14 的 ViT：$32 \times 32 = 1024$ 个视觉 token。配上 100 个文本 token，LLM 单层注意力的开销（$\propto L^2$）：

- **不压缩**：$(1024+100)^2 \approx 126$ 万——视觉占 99%。
- **下采样到 256**：$(256+100)^2 \approx 12.7$ 万——**省约 10 倍**。

**读这笔账**：视觉 token 是 VLM 计算成本的绝对大头。这也是为什么 Qwen-VL 把视觉 token 压到 256 个、为什么「视觉下采样」成为 VLM 标配——**省视觉 token = 省 LLM 计算 = 省 GPU 成本**。理解这个数字，就理解了 VLM 效率优化的主战场。

**辨析｜易错点：** 视觉 token 压缩是「有损」的——压得越狠，细节丢得越多。256 个 token 能装下「全局语义」但装不下「每块小字的细节」。**「压缩率」与「细节保真」是 VLM 的核心矛盾**——文档 OCR 类任务需要高分辨率多 token，简单分类则适合高压缩。

## 8 对齐模块形态对照

| 形态 | 参数 | 视觉 token 数 | 特点 |
| --- | --- | --- | --- |
| 线性投影 | 少 | 不变 | 最简单 |
| MLP | 中 | 不变 | 灵活（LLaVA 标配） |
| Q-Former | 中 | 压缩 | 精细提炼（BLIP-2） |
| 下采样池化 | 少 | 减少 | 省计算（Qwen-VL） |

对齐模块的「形态」同时决定「翻译质量」与「token 预算」——线性/MLP 不压缩 token，Q-Former/下采样会压缩。**选哪种对齐，是在「翻译精细度」与「LLM 计算成本」之间做权衡**。

## 9 小结

- 三段式：**视觉编码器（图像→token）+ 对齐模块（视觉→LLM 空间）+ LLM（图文混合推理）**。
- 核心价值：**复用 LLM 的世界知识与推理**——「配眼镜」而非「重学知识」。
- 对齐模块是「翻译桥梁」——线性/MLP/Q-Former/下采样，形态多样。
- 视觉 token 是「大头」——压缩视觉 token 是 VLM 效率的关键。
- 局限：编码器决定「眼神」上限、翻译丢细节——原生多模态是下一步。
