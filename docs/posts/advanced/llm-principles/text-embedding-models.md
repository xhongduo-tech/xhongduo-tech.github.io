## 为什么「语义」能被「坐标化」

检索的核心是「判断两段文本语义相关」。**文本向量化（embedding）** 把「一段文本」映射成「一个高维向量」——语义相近的文本，向量「距离近」；语义无关的，向量「距离远」。这样，「语义相关」变成了「向量相似」——可计算的、可索引的。Embedding 模型的质量决定了「语义检索」的上限，而它的训练方法是**对比学习**（我们在 CLIP 篇讲过——同样的思想，这次用在「文本-文本」对上）。<span class="marginnote">Embedding 的「语义坐标」直觉：<strong>把「苹果」与「水果」放得近，把「苹果」与「汽车」放得远</strong>——语义空间里「位置」编码「意义」。这个空间是「学出来的」——Embedding 模型从海量「相关文本对」里学「什么该近、什么该远」。RAG 的检索就是「在语义空间里找最近邻」。</span>

## 1 Embedding 模型是什么

**Embedding 模型（文本向量化模型）**：输入一段文本，输出一个固定维度的向量（如 768 或 1024 维）。

**与 LLM 的区别**：

| 维度 | Embedding 模型 | LLM |
| --- | --- | --- |
| 输出 | 一个向量（固定维度） | token 序列（生成） |
| 目标 | 表示语义（相似度） | 预测/生成文本 |
| 典型模型 | BGE、E5、text-embedding-3 | GPT、LLaMA、Qwen |
| 用途 | 检索、聚类、去重 | 理解、生成 |

**Embedding 模型的架构**：通常是「编码器」（BERT 式或类似），对文本做「池化」（取 `[CLS]` token 表示或平均池化）得到「句向量」。

**关键性质**：**归一化 + 余弦相似度**——向量归一化到单位球面，相似度用余弦：

$$
\text{sim}(a, b) = \frac{\vec{a} \cdot \vec{b}}{\|\vec{a}\| \|\vec{b}\|}
$$

相似度 ∈ [-1, 1]——越接近 1 越相关。

## 2 训练方法：对比学习的「文本版」

Embedding 模型的训练与 CLIP 同构——但「配对」是「文本-文本」而非「图文」：

**数据构造**：需要「相关文本对」——「query 与它的答案/上下文」「同一句话的翻译」「同义改写」。来源：

- **搜索引擎数据**：用户的「查询」与「点击的文档」——天然的相关对。
- **检索数据集**：MS MARCO（搜索点击）、NQ（问答）。
- **合成数据**：LLM 生成「相似句对」（数据增强）。

**对比学习训练**：

- 正样本对：相关文本对（query + 相关文档）。
- 负样本对：不相关文本对（query + 无关文档）。
- 目标：正对相似度高、负对相似度低——**InfoNCE 损失**（与 CLIP 相同）。

**负样本的「难易」很关键**：

- **简单负样本**：明显无关的（好区分，但「学不到细粒度」）。
- **难负样本**：语义接近但不匹配的（如「苹果手机」vs「苹果公司」）——**逼模型「精细区分」**。难负样本是提升 Embedding 质量的关键。<span class="marginnote">Embedding 训练的「难负样本」技巧：<strong>检索时的「假相关」往往是「难区分」的</strong>（两个都提「苹果」，但一个是手机、一个是水果）。训练时加入「难负样本」，模型学会「精细的语义区分」——检索才「不会找错」。这像「考试时出迷惑选项」——逼考生「真懂」。</span>

## 3 领域适配：通用 Embedding vs 领域 Embedding

**通用 Embedding**（BGE、E5、OpenAI embedding）在通用语料上训练——对「通用语义」好，但对「领域术语」可能「不够懂」。

**领域 Embedding**：在领域语料上「继续训练」——法律、医疗、代码的 Embedding「更懂领域语义」。

**为什么领域适配重要**：领域里「术语的语义」与通用不同——「检索」在法律文档里找「合同纠纷」，通用 Embedding 可能「匹配不准」。**领域继续训练（领域微调）让 Embedding「学会领域的语义关系」**。

**一个常见问题**：query 与文档的「风格差异」——用户的「口语 query」（「怎么赔」）与文档的「书面语」（「损害赔偿的构成要件」）——语义相同但「表述不同」。**Embedding 要「跨风格匹配」**——训练时加入「query-文档」对（而非仅「文档-文档」）。

## 4 公式解析：Embedding 的对比损失

Embedding 模型的 InfoNCE 损失（与 CLIP 相同形式）：

$$
\mathcal{L} = -\log \frac{e^{\text{sim}(q, d^+) / \tau}}{e^{\text{sim}(q, d^+) / \tau} + \sum_{j=1}^{B-1} e^{\text{sim}(q, d^-_j) / \tau}}
$$

对这条式子做三步拆解：

- **第一步，读懂 $\text{sim}(q, d^+)$**：query 与「相关文档」的相似度——正样本对。分子大 = 正对「靠近」。
- **第二步，读懂负样本求和**：分母加「$B-1$ 个负样本」的相似度——**让正对「比所有负对更近」**。
- **第三步，读出检索的本质**：训练让「相关对」的相似度「压倒」负样本——**检索就是「在向量空间里找相似度最高的」**。模型学到的「相似度」≈「检索的相关性」。

**辨析｜易错点：** Embedding 的「相似度」是「语义相似」，不是「词面相似」——「猫」与「毛茸茸的宠物」语义相近但词面不同——好的 Embedding 让它们「近」。但 Embedding 也**不是「完全语义理解」**——它对「精确匹配」（「找出包含 XYZ 的所有段落」）可能不如「词面检索」（BM25）——**这就是「稠密 + 稀疏混合检索」存在的原因**（第十四篇讲）。

## 5 Embedding 的评测与选型

- **MTEB（Massive Text Embedding Benchmark）**：跨任务、跨语言的 Embedding 排行榜——选型的参考。
- **检索召回率**：在「自己的领域数据」上测「召回率」——比 MTEB 更贴合实际。
- **选型考虑**：维度（存储与速度）、领域适配、中文支持、开源/商用。

## 7 数值算例：向量的存储成本

设文档库 100 万篇，对比不同维度与精度的存储：

| 配置 | 存储 |
| --- | --- |
| dim=768，FP32 | 约 3.0 GB |
| dim=384，FP32 | 约 1.5 GB |
| dim=768，INT8 量化 | 约 0.75 GB |
| dim=384，INT8 | 约 0.38 GB |

**读这张表**：维度与精度直接决定索引的「驻留显存/内存」。在「百万级文档 + 低延迟检索」场景，维度与精度是头号预算项——**「维度够用就好」比「越大越准」更符合工程现实**。这也是为什么「降维（Matryoshka）/ 量化」是 Embedding 部署的标配优化。

**辨析｜易错点：** 「维度高 = 更准」不成立。过高的维度在数据量有限时反而「稀释语义」（维数灾难）；过低的维度装不下精细语义。**维度是「任务复杂度」的函数，不是越大越好**——用「领域数据上的召回率」定维度，而不是凭直觉。

## 8 通用 vs 领域 Embedding：一张对照

| 维度 | 通用 Embedding | 领域微调 |
| --- | --- | --- |
| 训练数据 | 通用语料 | 领域语料 |
| 领域术语 | 弱 | 强 |
| 额外成本 | 现成可用 | 需微调数据 |
| 适用场景 | 通用检索 | 法律 / 医疗 / 代码 |

通用 Embedding「什么都懂一点、什么都不精」，领域微调「在领域内更懂」。**生产 RAG 的常见误区是「直接用通用 Embedding 做领域检索」**——术语漂移会让召回明显下降。优先「领域微调」，至少要在领域数据上验证召回率。

## 9 小结

- **Embedding** 把文本「坐标化」——语义相近则向量相近。
- 训练用**对比学习**（文本对）：正对近、负对远——InfoNCE 损失。
- **难负样本**是关键——逼模型「精细区分」。
- **领域适配**：领域继续训练让 Embedding「懂领域语义」。
- 评测：MTEB + 领域召回率——「数据说话」。
