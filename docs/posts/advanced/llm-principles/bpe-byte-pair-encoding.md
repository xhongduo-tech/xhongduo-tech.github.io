## 为什么先学 BPE

上一节我们把子词定义为「整词保留、罕见词拆碎」的折中，但「怎么决定拆到哪一层」还是个悬案。BPE 给出了第一个优雅的答案：**把最常一起出现的字符对反复合并，合并次数封顶时词表就定型了。** 它简单到用几十行代码就能实现，却统治了 GPT、LLaMA 等绝大多数开源模型——从 2016 年被引入机器翻译至今，BPE 一直是子词分词的默认基线。<span class="marginnote">BPE 的原名「字节对编码」来自它的前身——1994 年由 Gage 提出的数据压缩算法，它的思想是「把频繁出现的字节对替换成一个新记号」。Sennrich 等人 2016 年把它改造成词表学习方法，从此进入 NLP。</span>

## 1 BPE 的训练：一遍遍数「相邻对」

BPE 的训练输入是一份**预分词后的语料**（每个词后加一个空格标记 `</w>` 以便还原词尾），输出是一张**合并表（merge table）**。整个过程是一个贪心循环：

1. 初始化词表为**所有单字符**（加上特殊记号），把语料中每个词拆成字符序列。
2. 统计所有**相邻字符对**的出现次数。
3. 选出**出现次数最多**的一对，合并成新记号，加入词表。
4. 重复 2–3 步，直到达到预设的合并次数（如 32k 次）或词表大小上限。

每一步合并都让语料长度减少、词表增大 1。关键点在于：合并是**全局贪心**的——每一次都选当前语料里出现最多的相邻对，不回头、不反悔。<span class="marginnote">用数据压缩的视角看：BPE 是「以频率为序的逐步凝聚」。高频的字符组合（如 `th`、`ing`）在早期就被合并，成为稳定的词根；低频组合留在最后，甚至永远不合并。这保证了词表从「常见模式」开始学习。</span>

**示例。** 语料里有大量 low、lower、lowest，初始切分为 l、o、w、e、r、s、t 等。第一步统计相邻对，发现 l+o 出现最多，合并为 lo；接着 lo+w 频繁，合并为 low；之后 e+s 出现（来自 lowest 与同类词），合并为 es，再与 t 合并为 est……最终 low、lower、lowest 可能被分别切成 low、low+er、low+est，词根与词缀各得其所。

## 2 BPE 的编码：走一遍合并表

训练只产出一张合并表，真正给新文本分词时，要**按合并表顺序回放**：

1. 把输入文本预分词成词序列（英文按空格，中文先按字符）。
2. 把每个词拆成单字符。
3. 从头到尾遍历合并表：若当前词内部存在该合并规则对应的相邻对，就执行合并。
4. 所有合并执行完毕后，得到的记号序列就是该词的分词结果。

注意这里的顺序至关重要：合并表里**先出现的规则优先级更高**，因为早期合并的是全局高频对。编码时必须严格按训练时的顺序应用，否则分词结果会与训练语料的统计不一致，产生「词表漂移」。<span class="marginnote">这也是 BPE 的一个工程细节：合并表必须按顺序存储与加载，任何重排都会破坏可复现性。业界把「合并表 + 词表」打包成一个 tokenizer 模型文件（如 `tokenizer.json`），原因就在这里。</span>

**一个未登录词的例子。** 假设训练时没见过 lowest，但词表里有 low、est。编码时：lowest → 按合并表，l+o→lo，lo+w→low，然后 e+s→es，es+t→est，最终得到 low + est 两个记号。**子词让 OOV 从「无法表示」降级为「表示得略碎」**——这正是上一节的结论在此落地。

## 3 BPE 的变体：字节级 BPE

传统 BPE 的最小单位是 Unicode 字符，但 Unicode 字符数量上万（表情、生僻字、组合字符），词表会白白膨胀。**字节级 BPE（byte-level BPE，BBPE）** 把最小单位降为 **UTF-8 字节**（256 种），从根本上解决了两个问题。

**任何文本都可表示**：任何 Unicode 字符都由 1–4 个字节构成，所以无论多生僻的输入都能用 256 个字节拼出来，彻底消灭 OOV（未登录词）。
**词表不再被字符集绑架**：词表大小与「世界有多少字符」解耦，只由合并次数决定。<span class="marginnote">GPT-2 是最早大规模使用字节级 BPE 的模型，其词表 50257 = 256 字节 + 少量特殊记号 + 49920 个合并结果。今天的 LLaMA、Qwen 等主流模型全部继承了这个设计。</span>

字节级 BPE 的代价是：单字节的序列更长，且字节层面的「形态学直觉」被稀释——`th` 在字符级是一目了然的相邻对，在字节级要绕几个字节才聚拢。但它换来的**完备性**在工业界是压倒性的优势。

## 4 公式解析：BPE 的合并选择准则

BPE 每一步的选择可以写成形式化准则。设当前相邻对 $(a, b)$ 的共现次数为 $\text{count}(a, b)$，则合并次序由下式决定：

$$
\text{merge order}(a,b) \propto \text{count}(a,b)
$$

对这条式子做三步拆解：

- **第一步，读懂 $\text{count}(a,b)$**：它统计的是「$a$ 紧邻 $b$」在**当前语料**中出现的次数。语料会随合并而变——每次合并把两段文本拼成一个记号，其相邻关系随之更新。
- **第二步，理解「当前语料」的时变性**：合并不是在一份静态统计上做的。`s` 和 `t` 的共现一开始可能不多，但一旦 `s` 与前面的 `e` 合并成 `es` 后，`es` 与 `t` 的相邻次数就重新统计。这就是「贪心」的含义：每一步只着眼当下频率，不规划全局。
- **第三步，读出本质**：BPE 是在**拟合语料的分层统计结构**——先从单字节凝聚出常见模式，再让模式继续凝聚。它与哈夫曼编码同族：用频率自底向上构建结构，只不过哈夫曼最优、BPE 贪心。

**辨析｜易错点：** 三个概念常被混淆——**BPE 是词表学习算法**，**tokenizer 是完整的分词流水线**（预处理 → BPE 编码 → 特殊记号处理），**token 是分词结果**。BPE 只是 tokenizer 内部的一个组件；论文里「用 BPE 训练 tokenizer」指的是把后者整套搭起来。

## 5 BPE 的局限

- **贪心不可回溯**：早期的一次错误合并（如把 `t` 与 `h` 合了）会在语料层面扩散，且无法在后续纠正。
- **频率驱动 ≠ 语义驱动**：`the` 这类高频词被整词保留，而语义重要的罕见术语被拆碎——合并只看共现，不看意义。
- **多语言不公平**：拉丁字母语言中字节模式集中，BPE 效率高；音节文字（如中文、日文假名）字节分布分散，同样词表下每 token 携带的信息少，导致「中文 token 开销大」。

## 6 小结

- BPE 训练是一个**贪心合并循环**：反复合并当前出现次数最多的相邻字符对，直到词表达到目标大小。
- 编码是**按合并表顺序回放**：先拆到单字符，再依次应用合并规则。
- **字节级 BPE（BBPE）** 以 UTF-8 字节为最小单位，**消灭 OOV** 并让词表与字符集解耦，是 GPT/LLaMA 系的标准做法。
- 合并准则即**共现频率最大化**：先合并高频模式，后合并低频模式，天然拟合语料的分层结构。
- BPE 的局限在于**贪心、频率驱动、多语言不平衡**。
