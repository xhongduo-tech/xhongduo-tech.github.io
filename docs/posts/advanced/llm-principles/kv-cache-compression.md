## 为什么「缓存」也要压缩

长上下文下，KV Cache 线性膨胀，成了显存的头号黑洞（第七、十一篇讲过）。除了架构级压缩（GQA/MLA），**推理期的 KV 压缩**是另一条独立路线：把已缓存的 KV「变小」——**量化**（用更少字节存）、**驱逐**（删掉不重要的）、**选择性保留**（只留关键）。这篇讲推理期 KV 压缩的三类手段与取舍。<span class="marginnote">架构级压缩（GQA/MLA）是「训练时定死」的；推理期压缩是「部署时灵活」的——<strong>两者互补：架构压缩管「每 token 多大」，推理压缩管「哪些 token 值得存」</strong>。推理期压缩的价值在于「动态适应」：不同任务、不同位置，KV 的重要性不同，按需压缩。</span>

## 1 量化：用更少的字节存同一个 KV

**KV 量化（quantization）** 把 KV 从 FP16（2 字节）压到 INT8（1 字节）或 INT4（0.5 字节）：

**INT8 KV**：显存减半，质量损失很小（多数场景 < 1%）。
**INT4 KV**：显存减四分之三，但质量损失明显——通常需要「补偿」。
**非对称量化**：K 与 V 用不同精度——**K 更敏感**（参与分数计算），常保留高精度；V 可低精度。

**为什么要「逐层/逐 token」量化**：KV 的分布在不同层、不同位置差异大——全局一个量化范围会损失精度。**per-token / per-head 量化**（按 token 或按头定范围）更准。

**量化的取舍**：**省显存 vs 精度损失**——INT8 几乎无损、INT4 需权衡。量化是「KV 压缩的默认第一步」，因为它**实现简单、效果确定**。<span class="marginnote">KV 量化的一个技巧：<strong>K 的量化误差会直接进注意力分数</strong>（K 参与点积），V 的误差只影响「加权内容」——所以 K 通常用更高精度。实践中「K 保持 FP16/INT8、V 用 INT4」的不对称量化，能在「省最多显存」与「损失最小」之间取最优。</span>

## 2 驱逐：扔掉「不重要」的 token

**KV 驱逐（eviction）** 的核心洞察：长上下文里**大部分 token 的 KV 其实用不到**——模型对绝大多数历史位置的注意力权重趋近于 0。驱逐「修剪」掉低重要性的 KV，让缓存有界。

**如何判断「重要性」**：

**注意力累计分数**：历史上「被关注得多」的 token 更可能再被关注——**H2O（Heavy Hitter Oracle）** 方法用「累计注意力权重」识别「重头 token」，只保留它们。
**位置/结构**：句子开头、标题、特殊 token 往往更重要。
**近期优先**：最近的位置（local window）几乎总是重要——「recency + 重要性」结合。

**驱逐的取舍**：**显存有界 vs 信息丢失**——被驱逐的 token 无法「回看」。若被驱逐的 token 恰恰是答案所在，性能崩。**驱逐是「赌注」**：赌「被丢的都是不重要的」——好的重要性估计让赌注赢面大。<span class="marginnote">驱逐与「滑窗」的区别：滑窗是「固定只看最近 w 个」；驱逐是「动态保留重要的，不论远近」——一个远端但重要的 token（如问题的关键词）在驱逐里能留下，在滑窗里会被丢。驱逐的「智能」在于「重要性判断」，这也是它比滑窗更精妙（也更复杂）的原因。</span>

## 3 选择性保留：融合「量化 + 驱逐」

**选择性保留（selective retention）** 是「量化 + 驱逐」的组合与升级：

- **对重要的 token**：保留高精度 KV（甚至不压缩）。
- **对不重要的 token**：低精度 KV 或直接驱逐。

**关键洞察**：不是所有 token 都「值同样的字节」——**把预算花在刀刃上**。重要 token 给足精度，边缘 token 给最少。

**实现方式**：

- 按「重要性分数」分层：top 10% 用 FP16、中间 30% 用 INT8、其余驱逐。
- 或按「注意力头」区分：不同头对 KV 的敏感度不同，头级选择性压缩。

**收益**：在同样的显存预算下，选择性保留比「均匀量化」或「盲目驱逐」质量更高——**因为预算被「智能分配」**。

## 4 公式解析：驱逐的「重要性-显存」账

设序列有 $L$ 个 token 的 KV，驱逐「重要性 > 阈值 $\tau$」的 token，保留率 $r$：

$$
\text{Mem}_{\text{kv}} = 2 \cdot r \cdot L \cdot N \cdot H_{kv} \cdot d_k \cdot \text{bytes}, \qquad
\text{信息损失} \propto \sum_{\text{被驱逐}} \text{importance}(i)
$$

对这两条式子做三步拆解：

- **第一步，读懂第一项**：显存与保留率 $r$ 成正比——驱逐一半，显存减半。$r$ 是「显存预算」的旋钮。
- **第二步，读懂第二项**：信息损失 = 被驱逐 token 的重要性之和——**驱逐的目标是「在给定 $r$ 下最小化被驱逐的重要性」**。这是一个「Top-重要性保留」问题：保留重要性最高的 $rL$ 个 token。
- **第三步，读出权衡**：$r$ 小 → 显存省但可能丢重要信息；$r$ 大 → 显存贵但信息全。**最优 $r$ 取决于「任务的远距离依赖程度」**——需要精确回看的任务（问答、代码）要大 $r$，流式摘要可小 $r$。

**辨析｜易错点：** 驱逐是「硬删除」——被驱逐的 KV 无法恢复。与「量化」（软压缩，信息还在只是精度低）不同，驱逐是「真的丢」。所以驱逐的「重要性估计」一旦错了，就是「不可逆的损失」——**驱逐比量化更危险，更需要保守**。

## 5 工程实践与对比

| 方法 | 原理 | 显存 | 风险 | 适合场景 |
| --- | --- | --- | --- | --- |
| KV 量化（INT8） | 少字节 | 减半 | 极低 | 默认 |
| KV 量化（INT4） | 少字节 | 减四分之三 | 中 | 显存紧 |
| 驱逐（H2O） | 删不重要 | 有界 | 中-高 | 超长 |
| 选择性保留 | 分级压缩 | 可调 | 低-中 | 高要求 |

**组合拳**：GQA/MLA（架构）→ KV 量化（默认）→ 驱逐/选择性（超长）——**层层压缩**，每层省一部分。

## 7 数值算例：压缩手段层层叠加

设 $L=32768$、32 层、$H_{kv}=8$、$d_k=128$：

- **基线（FP16）**：$2 \times 32768 \times 32 \times 8 \times 128 \times 2$ 字节 ≈ **4.3 GB**。
- **INT8 量化**：减半 → 约 2.1 GB。
- **INT8 + 驱逐 $r=0.5$**：再减半 → 约 1.05 GB。
- **不对称量化 + 选择性保留**：可压到 1 GB 以下且质量损失更小。

**读这张账**：单一手段的压缩倍数是固定的（2×、4×），但**手段可以叠加**——量化管「每 token 多少字节」，驱逐管「存多少 token」，两者相乘就是「总显存」。现实部署几乎总是「架构压缩（GQA/MLA）+ 量化 + 驱逐」三层一起上。

**辨析｜易错点：** 量化与驱逐的「风险不对称」：量化是把所有 KV「整体变模糊」——误差均匀、可预期；驱逐是「删掉一部分」——误差集中在被删的 token 上、可能致命。**预算越紧，越该优先量化、谨慎驱逐**；驱逐前一定要用保守的重要性估计。

## 8 场景化选型速查

| 场景 | 首选 | 理由 |
| --- | --- | --- |
| 默认长上下文 | INT8 量化 | 几乎无损、实现简单 |
| 显存极紧 | INT4 + 驱逐 | 极致压缩 |
| 超长、需要回看 | H2O 驱逐 | 缓存有界、保留重头 |
| 高精度要求 | 选择性保留 | 预算智能分配 |

没有「最好」的压缩方法，只有「适合当前显存预算与质量要求」的组合。KV 压缩的通用心法：**先量化、后驱逐，把预算花在刀刃上**。

## 9 小结

- KV 压缩三类：**量化**（少字节）、**驱逐**（删不重要）、**选择性保留**（分级分配）。
- **量化**几乎无损（INT8）、实现简单——默认第一步。
- **驱逐**让缓存有界，但「硬删除不可逆」——重要性估计是成败关键。
- **选择性保留**把预算花在刀刃上——重要 token 高精度、边缘 token 低精度/删除。
- 组合拳：**架构压缩 + 量化 + 驱逐**层层叠加，撑起超长上下文。
