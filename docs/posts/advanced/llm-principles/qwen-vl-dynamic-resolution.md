## 为什么「分辨率」是 VLM 的隐形天花板

LLaVA 把图像「缩放到固定尺寸」（如 336×336）再喂 ViT——小图能行，但**遇到文字密集的截图、小物体的图像、表格，模型「看不清」**。Qwen-VL 的核心贡献之一就是 **动态分辨率处理**：图像不强行缩放到固定尺寸，而是「按内容选择合适的分辨率切分」，让模型「该放大时放大、该缩小时缩小」。这篇拆解 Qwen-VL 的动态分辨率与它代表的「细节优先」路线。<span class="marginnote">固定分辨率的问题：<strong>把 2000×3000 的图压到 336×336，细节丢 90%</strong>——小字、小物体直接消失。动态分辨率的思路：<strong>「不压缩到固定大小，而是把大图切块、每块用合适分辨率处理」</strong>——像人「眯眼细看」，想看细节就凑近。这是「视觉 token 效率」与「信息保真」的平衡术。</span>

## 1 固定分辨率的缺陷

LLaVA 的做法（简化）：图像 → resize 到固定尺寸（如 336×336）→ ViT（patch=14 → 24×24=576 token）。

**两个问题**：

**长宽比失真**：16:9 的图压成 1:1，物体变形。
**细节丢失**：小物体、小字、密集表格在压缩中消失——**VLM 对「文本密集图」（文档、截图、图表）表现差**的根源在此。

**为什么「固定尺寸」仍然流行**：简单、批量友好（所有图同尺寸，GPU 计算规则）。但代价是「眼神」被固定分辨率锁死。

## 2 Qwen-VL 的动态分辨率：M-ER 策略

Qwen-VL 用 **M-ER（Multi-Resolution Encoding）动态分辨率**：

**核心思想**：把大图「切成合适大小的块」，每块按「接近 ViT 输入尺寸」处理，再拼回特征。

**具体流程**：

1. **自适应网格**：根据图像长宽比，决定「切几行几列」——如 1600×900 的图切成 2×2 网格（接近 1:1 的块）。
2. **每块独立编码**：每块缩放到 ViT 输入尺寸（如 448×448），过 ViT 得到「块特征」。
3. **拼接特征**：所有块的特征按「空间位置」拼回完整序列——**保留了每块的细节**。
4. **加位置信息**：给每块加「空间位置编码」，让模型知道「块在图的哪里」。

**关键效果**：

长宽比不扭曲（按比例切，不硬压）。
**细节保留**：每块有独立的高分辨率特征——小字、小物体「看得清」。
**token 数可控**：切块数由「分辨率需求」决定——大图多 token、小图少 token。<span class="marginnote">动态分辨率与「固定尺寸」的本质区别：<strong>「固定」让所有图花同样的 token（不管内容），「动态」让「重要的图花更多 token」</strong>——token 预算按「信息需求」分配。这像「相机变焦」：远处看不清就拉近。代价是「块与块之间」的边界信息（跨块物体）需要模型从「空间位置编码」里推断。</span>

## 3 为什么动态分辨率对「文档/图表」特别重要

Qwen-VL 在「文档理解」（OCR、图表问答）上表现突出——动态分辨率是主要原因：

- **文字密集的截图**：固定分辨率下字被「糊」成一团；动态分辨率下每块足够大，字「清晰可读」。
- **小物体检测**：图像里的小物体（远处的人、桌上的小物件）在固定分辨率下「消失」；动态分辨率下「出现在某块里」。
- **细粒度属性**：「车牌号」「价格标签」这类「需要看清」的信息，动态分辨率是关键。

**一个直观对比**：同一张「超市小票」，固定分辨率下模型「看不清价格数字」，动态分辨率下「每块放大、数字可读」——**「看得清」是「读得懂」的前提**。

## 4 公式解析：动态分辨率的「token 预算」

动态分辨率的 token 消耗由切块数决定。设原图尺寸 $W \times H$、ViT 输入尺寸 $S \times S$、patch 大小 $P$：

$$
N_{\text{patch/token}} = \left\lceil \frac{W}{S} \right\rceil \times \left\lceil \frac{H}{S} \right\rceil \times \left(\frac{S}{P}\right)^2
$$

对这条式子做三步拆解：

- **第一步，读懂 $\left\lceil W/S \right\rceil \times \left\lceil H/S \right\rceil$**：图像被切成「宽 $\lceil W/S \rceil$ 列 × 高 $\lceil H/S \rceil$ 行」的块网格——**每块约 $S \times S$ 像素**。
- **第二步，读懂 $(S/P)^2$**：每块过 ViT 产生「$(S/P)^2$ 个 patch token」（$S=448, P=14 \to 32 \times 32 = 1024$ token/块）。
- **第三步，读出 token 量级**：1600×900 的图，切 2×2 网格 → 4 块 × 1024 ≈ **4096 个视觉 token**——远多于固定分辨率（576）。**动态分辨率用「更多 token」换「更多细节」**——「看得清」是有代价的。

**辨析｜易错点：** 动态分辨率的「切块」不是「裁剪丢弃」——每块都**保留全部**（块内缩放，不裁剪内容）。它只是把「一张大图」拆成「多块小图」，每块都「完整编码」——**信息不丢，只是 token 变多**。代价是「LLM 的计算量」（视觉 token 是计算大头，前面讲过）。

## 5 Qwen-VL 的其他设计

- **视觉 token 下采样**：Qwen-VL 用「2D 池化」把视觉 token 压缩（如从 4096 压到 256）——**细节与效率的平衡**。
- **原生多语言 + 中文**：Qwen-VL 的 LLM 是 Qwen——中文 VLM 的领先者。
- **定位能力**：支持「物体位置」输出（bounding box）——视觉 token 带空间信息。
- **训练配方**：三阶段（对齐 → 多任务 → 指令微调）——比 LLaVA 多一个「多任务」阶段。

## 7 数值算例：一张大图的 token 账单

设 ViT 输入 $448\times448$、patch $14\times14$，则每块产生 $(448/14)^2 = 1024$ 个视觉 token。一张 $1600\times900$ 的截图：

$$
\text{块数} = \lceil 1600/448 \rceil \times \lceil 900/448 \rceil = 4 \times 3 = 12
$$

$$
\text{原始 token} = 12 \times 1024 = 12288 \approx 12\text{k}
$$

再经 2D 池化（stride 2）压缩 4 倍 → 约 **3072 个视觉 token**。对比固定分辨率模型的 576 个：**动态分辨率花了约 5 倍的 token 预算，换来的是「小票上的数字看得清」**。对一张普通照片，块数可能只有 2×2 = 4 块 → 约 1024 token——「重要的图花得多，简单的图花得少」正是这套策略的精髓。

**辨析｜易错点：** 视觉 token 多 ≠ 一定更好。token 过多会让 LLM 的注意力被「细节」淹没，反而「捡了芝麻丢西瓜」。Qwen-VL 的 2D 池化下采样，本质是在「细节保真」与「语义聚焦」之间再取一次平衡——**动态分辨率只是第一层，下采样才是真正定调的第二层**。

## 8 固定 vs 动态：一张对照表

| 维度 | 固定分辨率 | 动态分辨率 |
| --- | --- | --- |
| 长宽比 | 失真 | 保持 |
| 细节 | 丢失 | 保留 |
| token 数 | 恒定 | 按内容分配 |
| 批处理 | 规则、高效 | 不规则、难并行 |
| 适合场景 | 简单分类 | 文档、图表、小物体 |

固定的优势在「工程简单」，动态的优势在「信息保真」。工业界往往折中：**预筛「简单图走固定、复杂图走动态」**，让绝大多数请求便宜、少数难图高质量——这也是很多生产级 VLM 的默认路由策略。

## 9 小结

- **固定分辨率**的缺陷：长宽比失真 + 细节丢失——「眼神」被锁死。
- **动态分辨率（M-ER）**：按长宽比切块、每块独立编码、拼回——**细节保真**。
- 对**文档/图表/小物体**特别重要——「看得清」是「读得懂」的前提。
- token 预算：$(\lceil W/S \rceil \times \lceil H/S \rceil) \times (S/P)^2$——**细节用 token 换**。
- 视觉 token 下采样平衡「细节 vs 效率」——Qwen-VL 的工程关键。
