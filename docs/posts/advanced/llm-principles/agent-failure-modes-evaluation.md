## 为什么「成功率」不够

评测 Agent 最直观的指标是「任务成功率」——但只盯成功率会「掩盖问题」：一个「成功率 80%」的 Agent，剩下的 20% **为什么失败**？是「选错工具」「死循环」「浪费预算」还是「胡说八道」？理解 Agent 的**失败模式**，才能「对症下药」地改进。Agent 评测要「多维」——不只「成不成」，还有「效率」「鲁棒性」「安全性」「成本」。<span class="marginnote">Agent 的失败与「纯 LLM 的失败」不同：<strong>Agent 在「真实环境」里失败——有副作用、有成本、可能「越做越糟」</strong>。评测 Agent 要「模拟真实环境」+「追踪过程」——不只「看结果」，还要「看轨迹」。AgentBench（2023）等基准把「环境」引入评测——Agent 在「模拟的网页/数据库/代码环境」里干活。</span>

## 1 Agent 的六大失败模式

**① 工具误用**：

选错工具（该用计算器用了搜索）、传错参数、忽略工具返回的错误。
后果：任务做错，或「浪费一次调用」。

**② 推理偏差（死循环）**：

Agent「反复调用同一个工具」停不下来——「执迷不悟」地重复失败操作。
后果：浪费预算、永不完成。

**③ 幻觉式成功**：

Agent「假装完成」——「我以为做完了」但「实际没做」或「做错了」。
后果：**最危险**——用户「信了」但结果是错的。

**④ 规划失败**：

复杂任务「计划不合理」——「漏步骤」「顺序错」「目标漂移」。
后果：做了一半发现「方向错了」。

**⑤ 上下文丢失**：

长任务中「忘了早期信息」——「前面查到的事实」被「截断/遗忘」。
后果：重复劳动、前后矛盾。

**⑥ 安全违规**：

执行「危险操作」（删数据、发消息）——「没被授权就干」。
后果：真实环境下的「事故」。

**失败模式的「分布」**：不同 Agent 的失败「侧重不同」——评测要「识别主要失败模式」，改进才「有的放矢」。<span class="marginnote">「幻觉式成功」是 Agent 评测里最值得警惕的：<strong>Agent「自信地报告成功」但「实际失败」</strong>——因为 LLM「会说谎」而不自知。缓解：「验证器」把关（任务结果可验证则自动验证）、「用户确认」兜底（危险操作人工确认）。评测里要「区分真成功与假成功」——「结果验证」比「Agent 自述」可信。</span>

## 2 Agent 评测的维度

除了「成功率」，Agent 评测要看多个维度：

| 维度 | 内容 | 指标 |
| --- | --- | --- |
| 成功率 | 任务完成质量 | 端到端成功、部分成功 |
| 效率 | 资源消耗 | 步数、工具调用次数、成本 |
| 鲁棒性 | 面对干扰/失败 | 错误恢复、抗噪声 |
| 安全性 | 危险操作规避 | 违规率、副作用控制 |
| 可解释性 | 轨迹可理解 | 推理质量、决策可追溯 |
| 泛化性 | 新任务/新环境 | 分布外表现 |

**「效率」维度**：同样完成一个任务，「5 步」与「50 步」差别巨大——**「少步完成」是「会干活」的体现**。评测要「成功率 / 步数」的平衡。

**「鲁棒性」维度**：Agent 面对「工具失败」「环境变化」「错误观察」时「能不能恢复」——**「不出错」不如「出错能救」**。

## 3 Agent 评测的环境与基准

Agent 评测的关键是「真实或模拟环境」：

**AgentBench**：8 个环境——操作系统、数据库、网页、代码、游戏等——「Agent 在真实环境干活」。
**GAIA**：通用助手基准——「真实世界问题」——需要「多步 + 多工具」。
**WebArena / WebVoyager**：网页操作——「点击、填表、导航」。
**代码类**：SWE-bench（修 bug）、RepoBench（仓库任务）。

**环境评测 vs 静态评测**：

**静态**（纯 QA）：只测「语言能力」——不能测「行动能力」。
**环境**（AgentBench）：测「在环境里干活」——**Agent 评测必须是「环境的」**。

**评测的「仿真度」**：模拟环境「越接近真实」评测越可信——但「真实环境」有「副作用与成本」——「安全仿真」是 Agent 评测的工程挑战。<span class="marginnote">Agent 评测的「环境设计」是核心难点：<strong>环境要「足够真实」（Agent 学到真能力）又「足够安全」（不会真造成破坏）</strong>——「沙箱」「模拟器」「回放」是常用手段。这也解释了为什么 Agent 基准「比 LLM 基准」难建得多——「交互环境」比「静态数据集」复杂一个量级。</span>

## 4 公式解析：评测的「成本加权成功率」

Agent 评测常需要「综合多个维度」——「成本加权成功率」把「效率」纳入：

$$
\text{Score} = \frac{\text{成功率}}{\max(1, \frac{\text{实际步数}}{\text{最优步数}})}
$$

对这条式子做三步拆解：

- **第一步，读懂分子**：成功率——「做没做成」。
- **第二步，读懂分母**：「实际步数 / 最优步数」——「效率惩罚」——步数越超，得分越低。分母用「max(1, ...)」——不惩罚「最优或更优」。
- **第三步，读出「效率-质量」平衡**：一个「100% 成功但 50 步」的 Agent 与「80% 成功但 10 步」的 Agent——得分可能相近——**评测「奖励高效成功，惩罚低效成功」**。这就是「成功率之外」的维度：**「怎么做成的」与「做成没有」同等重要**。

**辨析｜易错点：** 评测 Agent 的「成功率」要「结果验证」而非「自述验证」——**「Agent 说做完了」≠「真做完了」**。自动验证（检查产物、跑测试）是评测的基础——否则「幻觉式成功」会「虚高成功率」。**「可验证的任务」是 Agent 评测的前提**。

## 5 Agent 评测的工程实践

1. **任务设计**：可验证的任务（有「标准答案」或「可自动检查」）。
2. **环境模拟**：沙箱/模拟器——「真实 + 安全」。
3. **轨迹记录**：记录「每一步」——「失败模式分析」的基础。
4. **多维度打分**：成功率 + 效率 + 鲁棒性 + 安全——「不只看一个数」。
5. **失败归因**：对失败轨迹「分类」（工具误用/死循环/幻觉）——「改进的靶子」。

## 6 小结

- **六大失败模式**：工具误用、死循环、幻觉式成功、规划失败、上下文丢失、安全违规。
- 评测维度：**成功率 + 效率 + 鲁棒性 + 安全 + 可解释 + 泛化**。
- 环境评测（AgentBench）> 静态评测——「Agent 要在环境里验货」。
- 成本加权成功率：**「怎么做成的」与「做成没有」同等重要**。
- 结果要「自动验证」——**防「幻觉式成功」虚高分数**。
