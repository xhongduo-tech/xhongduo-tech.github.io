# 分词的基本问题：字符、词与子词粒度的权衡

## 为什么从分词开始

大模型的一切都从一段文本开始，而文本在进入模型之前，必须先被切成**记号（token）**。这一刀切在哪里，直接决定了词表大小、训练成本、OOV 处理与下游效果——它是整条流水线的第一道工序。<span class="marginnote">在前面《从统计语言模型到神经语言模型》中我们见过「词」粒度的 N-gram 与 Word2Vec；这一篇要回答的是：为什么今天的模型既不按「词」切，也不按「字符」切，而是折中成了「子词」。</span>理解三种粒度的权衡，是理解 BPE、WordPiece、Unigram 与 SentencePiece 全部后续内容的前提。

## 1 三种候选粒度：字符、词、子词

**分词（tokenization）**：把一段原始文本切分成有限个基本单位（记号）的过程。候选的基本单位有三档：

**字符（character）**：以单个字母 / 汉字 / 标点为记号。中文天然适合，英文里 **`apple`** 会被切成 **a**、**p**、**p**、**l**、**e** 五个字符。
**词（word）**：以空格与标点为界切分。英文直观，但中文没有天然空格；且英语词形变化繁多——**run**、**runs**、**ran**、**running** 各算一个词。
**子词（subword）**：介于两者之间，**tokenization** 可能被切成 **token** + **ization**，**unhappiness** 切成 **un** + **happiness**。

三者的核心矛盾是**词表大小**与**语义完整性**之间的拉锯。字符粒度词表最小（几千），但每个记号携带的信息太少，序列长度被拉长好几倍；词粒度语义最完整，但词表动辄几十万甚至上百万，且永远兜不住新词；子词粒度站在中间，用一个几万词的词表兼顾两者。

## 2 为什么纯字符不够

字符粒度的模型真的存在过，而且并不算差——RNN 时代有很多 character-level LM。<span class="marginnote">字符级 RNN 的语言模型在 2010 年前后相当流行（Sutskever et al. 2011），它们能生成拼写正确的长词，但代价是序列长、记忆窗口短。</span>但它有两个难以回避的弱点。

**其一，序列长度爆炸。** 注意力机制的计算量随序列长度平方增长。同一个句子，字符粒度比子词粒度长 3–5 倍，训练与推理成本随之成倍上升。这在今天的长上下文时代是难以承受的。

**其二，长程依赖更难学。** 把 **长单词（如 internationalization）** 切成十几个字符后，模型要从第一个字符开始一路记住信息才能在该词末尾做出合理预测——对自回归模型来说，这是一条又长又脆的依赖链。字符之间缺少稳定的「词边界」信号，统计规律更稀疏。<span class="marginnote">这也解释了为什么字符级模型擅长「拼写」而非「语义」：它们见过太多 <strong>q + u、t + h</strong> 这类相邻字符对，却难以在几千字符的距离上维持主题信息。</span>

## 3 为什么纯词也不够

词粒度看似自然，但它的病根在**词表与生词**。

**病根一：词表爆炸。** 英语的词形变化、派生、复合词让真实词数远超想象。一个覆盖常用词的词表约 5 万，但加上人名、地名、专名、术语，轻松破百万。更大的词表意味着更大的嵌入矩阵——这既是显存负担，也让大量罕见词只有极稀疏的训练样本，学到的是噪声。

**病根二：OOV（out-of-vocabulary）。** 再大的词表也挡不住新词。**人名地名、专有名词、缩写（如 GPT-4o）**、网络新词、拼写变体……凡不在词表里的一律被换成一个笼统的 **`<unk>`** 记号，信息直接丢失。这是词粒度模型最致命的短板。

**病根三：中文无空格。** 词粒度依赖空格切分，而中文的词边界需要分词器先做一层分词（如 jieba），多一层就多一层错误传播——这被称为**中文的分词税**，我们会在第六篇专门展开。

## 4 子词：压缩与还原之间的平衡

**子词（subword）** 的思想非常朴素：**常用词整词保留，罕见词拆成更小片段，保证任何词都能被有限片段拼回来。** 它同时解决了三个问题：

**词表可控**：用几万个子词单元就能覆盖全部词汇，因为任意单词都可表示为子词的拼接。
**OOV 终结**：真正完全没见过的字符组合几乎不存在——最坏情况可以退化到字符级。子词把「OOV」从「无法表示」变成「表示得略碎」。
**形态共享**：**work**、**works**、**working** 共享 **work** 这一个子词，模型能在不同词形间迁移统计信息。<span class="marginnote">这正是人类语言学习的直觉：掌握词根 <strong>work</strong>`，再加上后缀规则 <strong>-s</strong>`、<strong>-ing</strong>，就能应付一整族词。子词让模型天然获得了一点「构词法」能力。</span>

用一张表对比三种粒度：

| 粒度 | 词表大小 | 序列长度 | OOV 问题 | 典型代表 |
| --- | --- | --- | --- | --- |
| 字符 | 数千 | 最长 | 几乎无 | Char-RNN |
| 词 | 5万–百万 | 短 | 严重 | Word2Vec、N-gram |
| 子词 | 3万–10万 | 中等 | 基本解决 | BPE、WordPiece、Unigram |

## 5 公式解析：分词是「压缩 + 还原」的编码问题

把分词放到信息论框架里看，它就变成一个可计算的权衡。设原始文本为 $T$，切分方案把 $T$ 变成 $n$ 个记号 $t_1, t_2, \ldots, t_n$，则**单记号平均信息量**由熵给出：

$$
H = -\frac{1}{n}\sum_{i=1}^{n} \log p(t_i)
$$

对这条式子做三步拆解：

- **第一步，读懂 $p(t_i)$**：$p(t_i)$ 是记号 $t_i$ 在语料中的概率，可以由词频估计为 $\frac{\text{count}(t_i)}{\text{总记号数}}$。高频记号概率大，$\log p(t_i)$ 为绝对值较小的负数。
- **第二步，理解信息量与长度的张力**：同一文本，切得越碎，$n$ 越大、平均概率越高、$H$ 越小——但序列变长，模型要处理的步数变多。切得越整，$n$ 越小、但稀有词概率极低、$H$ 飙升，且可能出现 $p(t_i) \approx 0$ 的未登录记号。
- **第三步，读出权衡**：子词分词的「最优」切分，本质是在**最小化平均熵**与**控制记号数量**之间取平衡。Unigram 语言模型分词正是把这个思想形式化：给定一个「期望平均长度」，用 EM 迭代求解使语料似然最大的切分。

**辨析｜易错点：**「token」与「词」不是一回事。一个 token 可能是整词（**the**）、词根（**run**）、甚至标点与数字片段（**。**、**123**）。所以「这个模型有 100B 参数、上下文 32k tokens」中的 tokens 是模型自己的记号，不是自然语言的单词——我们后面数显存、算 KV Cache 时，单位都是 token 而非词。

## 6 术语速查表

| 术语 | 英文 | 一句话定义 |
| --- | --- | --- |
| 分词 | tokenization | 把原始文本切成记号的预处理步骤 |
| 记号 | token | 模型处理的最小文本单位 |
| OOV | out-of-vocabulary | 词表外的未登录词 |
| 子词 | subword | 介于字符与词之间的切分粒度 |
| 词表 | vocabulary | tokenizer 的全部记号集合 |
| 分词税 | token tax | 无空格语言因分词产生的额外成本 |

## 7 数值算例：粒度如何放大成本

取一段 100 词的英文文本，三种粒度的 token 数大致为：词粒度约 100，子词粒度约 130，字符粒度约 650——字符粒度大约是子词的 5 倍。

注意力的计算量随序列长度**平方**增长，于是单层注意力开销之比是 $650^2 : 130^2 = 25:1$——**同一个句子，字符粒度让注意力成本放大 25 倍**。KV Cache 也随长度线性放大 5 倍。若再把「上下文预算」换算进显存，字符粒度的「每句成本」对部署方是灾难级的。

**辨析｜易错点：** 「token 数少」不一定「更好」。词粒度 token 数最少，但 OOV 与词表爆炸带来的损失远大于节省的计算。子词粒度的价值恰恰在于：**它在「序列长度」与「词表/OOV」之间同时取得了可接受的平衡**——这正是「折中」的工程含义。

## 8 一个 token 到底有多大

不同语言下「一个 token」承载的语义量差别很大，直接影响上下文预算：

| 语言 | 每 token 平均语义量 | 说明 |
| --- | --- | --- |
| 英语 | 约 0.8 词/token | 常用词整词入表 |
| 中文 | 约 0.6–0.7 字/token | 高频双字词可整词 |
| 代码 | 差异极大 | 缩进/空白也占 token |

同样是「32k 上下文窗口」，英语能装下约 2.5 万词，中文只能装下约 2 万字——**「上下文长度」按 token 计，但「实际容纳的信息量」按语言而异**。这解释了为什么中文社区的「长文本诉求」往往比英文更强，也呼应了第六篇的「分词税」。

## 9 小结

- 三种粒度——**字符、词、子词**——在词表大小、序列长度、OOV 之间各有取舍。
- 字符粒度**无 OOV 但序列太长**；词粒度**语义完整但词表爆炸且 OOV 严重**；子词粒度**折中两者**，是现代 LLM 的默认选择。
- 子词的三个优势：**词表可控、OOV 终结、形态共享**。
- 分词本质是**信息论中的压缩问题**：在平均熵与记号数量之间做权衡。
- 中文没有空格边界，词粒度需要额外分词器，引入**分词税**。
