## 为什么「凭记忆」不够

大模型的知识「冻结」在训练时刻——它不知道「训练之后的新事」，也可能「记错」「编造」。**RAG（Retrieval-Augmented Generation，检索增强生成）** 的解法：**回答前先「检索」相关资料，把资料放进上下文，再生成答案**。这像「开卷考试」——不靠「背」，靠「查」。RAG 是当下「缓解幻觉 + 补充新知识」最实用的工程范式。<span class="marginnote">RAG 的思想可以追溯到 2020 年 Lewis 等人的论文，但真正流行是 2023 年后——因为「私有知识」「实时知识」「长尾知识」让「纯参数记忆」显得不够。RAG 的核心洞察：<strong>「知识可以存在外部（数据库/文档），模型只负责『用』」</strong>——「记忆」与「推理」解耦。</span>

## 1 RAG 的三段式流程

RAG 系统由三个核心模块构成：

```text
[知识库文档]
    │ ① 索引：切分 → 向量化 → 建索引（离线）
    ▼
[向量索引库]
    │ ② 检索：问题向量化 → 取回最相关的 top-k 片段（在线）
    ▼
[问题 + 相关资料]
    │ ③ 生成：LLM 基于资料作答
    ▼
[带引用的答案]
```

**① 索引（Indexing）**：把「知识库」（文档、网页、数据库）预先处理成「可检索的形式」——切分、向量化、建索引。

**② 检索（Retrieval）**：用户提问时，从索引里找出「最相关的 k 段资料」。

**③ 生成（Generation）**：把「问题 + 检索到的资料」拼进 prompt，LLM 基于「资料 + 问题」生成答案。

**关键设计**：

**k 值**：检索多少段资料（通常 3–10）。
**上下文组织**：资料怎么放进 prompt（顺序、格式、标注来源）。
**引用**：生成时「标注资料来源」——「可追溯」是 RAG 的重要卖点。

## 2 为什么 RAG 能缓解幻觉

幻觉的根源是「模型在编造它不知道的东西」。RAG 从三个层面缓解：

**① 提供「事实锚点」**：把「相关资料」放进上下文，模型「看到了」事实——**生成时「有据可依」**，不再「凭空编造」。模型倾向于「引用上下文」而非「自己发挥」。

**② 把「记忆负担」转给「检索」**：模型不必「记住」所有事实（记不住就编）；检索器负责「找事实」——**「记忆」与「生成」解耦，模型「只负责组织语言」**。

**③ 提供「纠错信号」**：当检索资料与模型「记忆」冲突时，模型可以「被资料纠正」——**资料是「更可信的真相来源」**。

**但 RAG 不是万能**：

**检索不到** → 模型「没看到」资料 → 仍会编。
**检索到错的** → 模型「被误导」→ 按错误资料回答。
**模型「不听话」** → 即使有资料，模型可能「忽略资料、凭记忆答」。

**RAG 缓解幻觉的前提：检索「准」+ 模型「用」**——「检索质量」与「模型遵循性」双关键。<span class="marginnote">一个有意思的现象：RAG 缓解「事实性幻觉」（编造事实），但缓解不了「忠实性幻觉」（模型「不按资料说」）。如果模型「无视资料」，「给它资料」也没用——所以「prompt 引导模型用资料」（如「只根据提供的资料回答」）是 RAG 的必要组件。这也提示：<strong>「RAG 的效果 = 检索准 × 模型愿意用」</strong>。</span>

## 3 为什么 RAG 能解决「知识过期」

大模型的知识「冻结」在训练时——「2025 年的新闻」在「2024 年训练的模型」里不存在。RAG 的解法：

**知识在外部**：新知识进「知识库」，模型「不必重训」。
**实时更新**：知识库「动态增删」——「今天的新闻」入库后，「下次提问」就能检索到。
**领域私有知识**：公司文档、个人笔记——不必「泄漏进训练数据」，存外部「安全访问」。

**「RAG vs 重训」的成本对比**：

| 维度 | 重训/微调 | RAG |
| --- | --- | --- |
| 成本 | 训练算力、数据准备 | 索引 + 检索（便宜） |
| 更新速度 | 慢（要重训） | 快（改知识库） |
| 知识类型 | 长期、通用 | 短期、私有、实时 |
| 幻觉风险 | 仍可能 | 靠检索缓解 |

**RAG 的「知识即插即用」**：加知识 = 加文档，不用动模型——**「知识的成本」从「训练」转移到「索引」**。<span class="marginnote">RAG 与「微调」是「知识更新的两种手段」：<strong>「微调」改「模型记忆」（重、慢、持久），「RAG」改「外部知识」（轻、快、可撤）</strong>。实践中常「结合」：长期稳定的知识微调进模型，短期/私有知识用 RAG——「各管一段」。</span>

## 4 公式解析：RAG 的生成概率

RAG 的生成模型：给定问题 $x$，检索器返回文档 $z$，生成器基于「问题 + 文档」生成答案 $y$：

$$
p_{\text{RAG}}(y \mid x) = \sum_{z \in \mathcal{R}(x)} p_{\text{gen}}(y \mid x, z) \cdot p_{\text{ret}}(z \mid x)
$$

其中 $\mathcal{R}(x)$ 是检索到的文档集合，$p_{\text{ret}}$ 是检索的相关性，$p_{\text{gen}}$ 是生成概率。

对这条式子做三步拆解：

- **第一步，读懂求和**：答案的概率 = 对所有「检索到的文档」求和——「答案通过任一文档生成」的概率加权。
- **第二步，读懂 $p_{\text{ret}}(z \mid x)$**：文档 $z$ 与问题 $x$ 的相关性权重——**检索质量决定「哪些文档主导生成」**。
- **第三步，读出 RAG 的本质**：$p_{\text{RAG}}$ = 「检索器选文档」×「生成器用文档」——**RAG 把「生成条件」从「仅问题」扩展为「问题 + 检索文档」**。这就是「开卷」的数学表达：生成「看到」了外部知识。

**辨析｜易错点：** RAG 的「检索」在「生成前」发生——「先检后生」是标准 RAG；「边检边生」是迭代式 RAG（第十四篇末讲）。别把「一次性检索」当作 RAG 的全部——**RAG 家族里「检索时机」「检索次数」「检索粒度」都是可变设计**。

## 5 RAG 的工程全景

一个生产级 RAG 系统涉及：

- **文档切分**（下一节）：文档 → 适合检索的「块」。
- **向量化**：块 → 向量（Embedding 模型）。
- **索引与向量库**：向量 → 高效检索的数据结构。
- **检索策略**：稠密/稀疏/混合。
- **重排序**：粗检 → 精排。
- **高级 RAG**：查询改写、HyDE、迭代检索。

**RAG 的失败模式**：检索不到、检索不准、模型不用资料——**RAG 的工程难点在「检索侧」与「遵循侧」**。

## 6 小结

- **RAG 三段式**：索引（建库）→ 检索（找资料）→ 生成（用资料）。
- 缓解幻觉：**事实锚点 + 记忆解耦 + 纠错信号**——但依赖「检索准 × 模型愿用」。
- 解决过期：**知识在外、动态更新、私有安全**——「知识即插即用」。
- 概率视角：$p_{\text{RAG}} = p_{\text{ret}} \times p_{\text{gen}}$——「开卷考试」。
- 工程全景：切分、向量化、索引、检索、重排——下一节开始逐个拆解。
