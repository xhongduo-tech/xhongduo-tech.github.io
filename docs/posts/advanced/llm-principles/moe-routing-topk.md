## 为什么路由是 MoE 的"灵魂"

MoE 的价值全在「把 token 分给对的专家」——这个分诊动作就是**路由（routing）**。路由器做得差，专家分化不出来、负载失衡、训练崩溃。做得好，每个专家专精一类，稀疏激活才有意义。<span class="marginnote">路由器的本质是一个「可学习的分诊台」：它是个线性层 + softmax，把 token 表示映射成对每个专家的「就诊分数」，取 top-k。别看它参数少（一个 $d \times E$ 矩阵），它的梯度直接决定专家怎么分化——它是 MoE 里「唯一会说话的调度器」。</span>

## 1 路由器：一个线性层 + top-k

路由器的前向：

```python
def router(x, W_r, k):
    scores = x @ W_r                        # [L, E]：每个 token 对每个专家的打分
    probs = F.softmax(scores, dim=-1)       # 归一化为概率
    topk_probs, topk_idx = probs.topk(k, dim=-1)  # 取概率最高的 k 个专家
    return topk_probs, topk_idx
```

**打分**：$E$ 是线性投影，把 $d$ 维 token 表示映射到 $E$ 维专家空间。每个维度代表「这个 token 适合这个专家吗」。
**softmax**：把分数变成概率，便于归一化输出。
**top-k**：取概率最高的 $k$ 个专家（通常 $k=1$ 或 $2$）。

**为什么用 softmax + topk 而不是直接 argmax**：argmax 只有 1 个专家且不可微（无法梯度回传路由器）；softmax 可微，topk 允许「多专家软混合」。$k=1$ 时退化为「硬路由」，$k=2$ 时是「软混合」。

**路由器的训练方式**：路由器通过「最终输出的 loss」间接学习——它不知道「正确专家是谁」，只能通过梯度试探「哪个专家对这个 token 有帮助」。这是**隐式的分工学习**：没有监督标签，全靠损失信号让专家自动分化。<span class="marginnote">这种「无监督分工」非常像真实组织的形成：没有中央规划，只是「哪个科室解决病人问题，病人就更多流向哪里」——正反馈让专家逐渐专精。它的副作用是「马太效应」：越强的专家越多人用，导致负载失衡（下一节讲）。</span>

## 2 Top-1 vs Top-2：硬路由与软混合

**Top-1（Switch Transformer）**：每个 token 只去 1 个专家。

- 计算量最小（$k=1$）。
- 风险：路由一旦选错，没有「备选」纠错；负载更容易失衡。
- 实现简单：`topk`（k=1）即 argmax，稀疏性最强。

**Top-2（GShard / Mixtral）**：每个 token 去 2 个专家，输出加权混合。

- 质量通常更好：2 个专家的「混合」比 1 个的「单选」更稳。
- 计算量翻倍（但 2 个 vs 8 个，仍是稀疏）。
- 更平滑：softmax 权重在两个专家间分配，类似「软路由」。
- Mixtral 8×7B 用 Top-2，是事实标准。

一张表对比：

| 配置 | $k$ | 计算量 | 质量 | 负载风险 | 代表 |
| --- | --- | --- | --- | --- | --- |
| Top-1 | 1 | 最小 | 略低 | 高 | Switch Transformer |
| Top-2 | 2 | 2×Top-1 | 更高 | 中 | GShard、Mixtral |

**辨析｜易错点：** Top-2 的「2」是「2 个专家」，不是「2 层」。别把「每 token 激活 2 个专家」理解成「MoE 有 2 层」——MoE 层的总数与专家激活数是两个独立概念。Mixtral 有 32 个 MoE 层，每层 8 个专家、每 token 激活 2 个。

## 3 公式解析：路由的归一化与噪声

带噪声的 Top-k 路由（Shazeer 2017 的原始设计）有训练稳定性的考虑：

$$
w = \text{softmax}\left(x W_r + \epsilon \cdot \text{softplus}(x W_{\text{noise}})\right)
$$

其中 $\epsilon \sim \mathcal{N}(0, 1)$ 是标准正态噪声，$W_{\text{noise}}$ 是学习「噪声幅度」的投影。

对这条式子做四步拆解：

- **第一步，读懂 $x W_r$**：基础路由分数——token 与专家的亲和度。
- **第二步，读懂噪声项**：$\text{softplus}(xW_{\text{noise}})$ 学出「该加多少噪声」。**训练时**在路由分数上注入随机噪声，**推理时去掉**。
- **第三步，理解为什么加噪声**：噪声促进「探索」——让一些分数接近的 token 偶尔路由到次优专家，避免路由过早固化、帮助专家更均匀地被访问。它像 RL 里的 ε-greedy：给次优选择留机会。
- **第四步，读出温度的作用**：softmax 的「温度」也可调——低温让路由更「硬」（更确定），高温更「软」（更随机）。噪声与温度是同一个「探索-利用」权衡的两个旋钮。

**辨析｜易错点：** 推理时**必须去掉噪声**（把噪声项设 0）。如果推理还带随机路由，同样的输入会路由到不同专家、输出不稳定。噪声是「训练期的正则/探索工具」，不是「推理期的特性」。

## 4 路由的负载：为什么专家会失衡

路由学习的是「最大化模型质量」，它**不关心负载均衡**——于是「马太效应」出现：少数专家因性能好被大量使用，多数专家被冷落。后果：

- **训练浪费**：热门专家过载、冷门专家欠训练，模型容量没被充分利用。
- **硬件瓶颈**：同一批 token 若集中在某专家，该专家的计算成为瓶颈，其他专家闲置（MoE 并行部署时尤其严重）。
- **专家坍塌**：极端情况下某专家几乎不被路由，其参数退化，进一步恶化路由——恶性循环。

缓解手段分两类（下一节专讲）：

- **辅助负载均衡损失**（aux loss）：给路由加「均匀分布」的惩罚。
- **无辅助损失的替代**（如 DeepSeekMoE 的「专家级偏置」、Switch 的「容量因子」）。

## 5 路由器的工程细节

- **token 并行**：路由是「逐 token」的，天然并行——GPU 上把打分矩阵（`[L, E]`）一次算完，再按 topk 索引 gather 对应专家的输入。
- **专家分片**：推理时专家分布在多卡，路由后需要 **all-to-all** 通信把 token 送到对应专家的卡——这是 MoE 推理的通信成本来源。
- **dropout 与路由**：训练中路由器的 dropout（在 softmax 概率上）能进一步防过拟合与促进均衡。

## 6 小结

- 路由器 = **线性打分 + softmax + top-k**，参数少但决定专家分工。
- **Top-1** 最省、**Top-2** 更稳更准（Mixtral 用 Top-2）。
- 带噪声路由在训练期促进**探索**，推理期必须去噪。
- 路由的「马太效应」导致**负载失衡**——下一节专门解决它。
- 工程上路由 + **all-to-all** 通信是 MoE 推理成本的核心。
