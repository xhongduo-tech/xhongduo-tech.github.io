## 为什么先看全局

前面我们讲完了 tokenizer——模型「怎么读文本」。现在要进入模型的**主体**：一排 Transformer 解码层。真正理解一个 GPT 模型，不需要先把每一层都抠到公式级，而应该先建立一张**数据流地图**：一个 token id 从嵌入层进去，经过哪些模块，变成什么形状的张量，最后如何变成一个 logits 向量。<span class="marginnote">这篇是「总览」：只讲数据流的形状与阶段划分，细节（注意力、FFN、归一化）留给本专题后续各篇。学习架构的诀窍是先有地图，再逐块精读——否则很容易「只见树木不见森林」。</span>

## 1 一次前向的完整旅程

输入是分词后的一串 token id，长度为 $L$（假设 8）。逐层跟踪张量形状，设 $d=768$（隐藏维度）、词表大小 $V=50257$：

1. **嵌入层**：每个 token id 查表得到一个 768 维向量，得 $[8, 768]$。
2. **位置编码**：叠加位置信息（绝对位置编码向量 或 RoPE 旋转，后者不改变形状），仍为 $[8, 768]$。
3. **N 个解码层**（如 12 层），每层内部依次：
**归一化 + 因果注意力**：输出 $[8, 768]$；
**残差连接**：与输入相加，$[8, 768]$；
**归一化 + 前馈网络（MLP）**：$[8, 768]$；
**残差连接**：再加回，$[8, 768]$。
4. **最终归一化**：$[8, 768]$。
5. **输出头**：线性层把 768 维映射到词表大小 $V$（如 50257），得 $[8, 50257]$——这就是 **logits**。
6. **Softmax + 采样**：对最后一个位置的 logits 取 softmax 得到概率分布，采样出下一个 token id。

**形状守恒定律**：除了最后的输出头，Transformer 主干的每一层都保持 $[B, L, d]$ 不变。这条定律让整个架构像「一个向量在被反复精炼」——每一层都在同一维度的空间中细化表示。<span class="marginnote">记住「形状守恒」，读任何 Transformer 代码都会轻松很多：所有中间张量几乎都是 $[B, L, d]$ 的排列。后面讲注意力时，Q/K/V 只是这个形状的内部投影。</span>

## 2 三个"视图"：编码视图、因果视图、并行视图

理解 Decoder-only，关键是区分它看待序列的三种方式。

**编码视图**：每个位置的输出「看到了」哪些输入？在 Decoder-only + 因果掩码下，第 $t$ 个位置的输出只能依赖位置 $\le t$ 的输入——**不能看未来**。这是它与 BERT（双向）的根本区别。

**因果视图**：训练时我们一次喂进整段文本，但要求模型像「逐词写作」一样，每个位置只预测「它前面的文本的下一个词」。这是通过**因果掩码**在注意力矩阵上实现的——第 $t$ 行只允许关注第 $t' \le t$ 列。<span class="marginnote">训练时的「并行」与推理时的「自回归」是一体两面：训练一口气算 $L$ 个位置的下一个词预测；推理时一次只前进一个 token，但每个新位置同样只能看历史。因果掩码把这两种模式统一起来。</span>

**并行视图**：因为有了因果掩码，模型可以在训练时**并行处理所有位置**——整个序列一次前向，同时得到 $L$ 个「下一个词」预测。这个并行性是 GPU 能高效训练的根本原因，也是「自回归模型 + 因果掩码」这组搭配的意义所在。

## 3 为什么「Decoder-only」赢了

2018 年后出现过 Encoder-only（BERT）、Encoder-Decoder（T5）、Decoder-only（GPT）三足鼎立的局面，但今天的开源主力几乎全是 Decoder-only。原因有三：

**统一的预训练目标**：Decoder-only 用「下一个词预测」，简单到只需要「把文本按顺序喂进去」就能构造无限训练样本，无需 MLM 的掩码取样、无需 encoder-decoder 的序列构造。
**原生支持生成**：chat、写作、代码补全都是自回归生成，Decoder-only 结构与生成目标天然一致；encoder 结构在生成时要多一层「编码-解码」的转换。<span class="marginnote">T5 这样的 encoder-decoder 也能生成，但 decoder 的交叉注意力依赖 encoder 输出，结构更重、部署更复杂。Decoder-only 在「从零开始续写」上最自然。</span>
- **统一推理服务**：KV Cache 只在 decoder 里存在，纯 decoder 结构让推理引擎（vLLM、TensorRT-LLM）只需优化一条路径，工程上大幅简化。

一张表对比三种结构：

| 结构 | 预训练目标 | 生成方式 | 典型代表 | 现状 |
| --- | --- | --- | --- | --- |
| Encoder-only | MLM（掩码预测） | 需附加生成头 | BERT、RoBERTa | 偏理解任务 |
| Encoder-Decoder | 完形填空/翻译 | 交叉注意力 | T5、BART | 少数专项场景 |
| Decoder-only | 下一个词预测 | 自回归 | GPT、LLaMA、Qwen | 主流 |

## 4 公式解析：Logits 与下一个词分布

数据流的终点是输出头。设最后一层输出为 $h \in \mathbb{R}^{d}$，输出头权重 $W_{\text{out}} \in \mathbb{R}^{V \times d}$，则第 $t$ 个位置对下一个词的 logits 与概率为：

$$
\text{logits} = W_{\text{out}}\, h_t, \qquad
p(w_t \mid w_{\\lt t}) = \text{softmax}(\text{logits})_t
$$

对这两条式子做三步拆解：

- **第一步，读懂 $W_{\text{out}} h_t$**：这是把 $d$ 维表示 $h_t$ 线性投影到 $V$ 维词表空间。每个词「得分」就是它与 $h_t$ 的内积——表示与词嵌入越接近，得分越高。这解释了为什么通常做**输入输出权重共享**（weight tying）：词嵌入与输出头共用同一张表，语义一致。
- **第二步，读懂 softmax**：$\text{softmax}(z)_t = \frac{e^{z_t}}{\sum_j e^{z_j}}$，把 $V$ 个得分转成和为 1 的概率分布。温度参数 $\tau$ 就是给 logits 乘上 $1/\tau$，控制分布的尖锐程度。
- **第三步，读出条件概率结构**：$p(w_t \mid w_{\\lt t})$ 是**条件概率**——给定所有历史 token，预测下一个。整个模型就是一个**关于 token 序列的概率分布**：$p(w_1,\ldots,w_L) = \prod_t p(w_t \mid w_{\\lt t})$。所有生成行为、困惑度、loss，都建立在这个链式分解上。

## 5 从数据流看训练与推理的差异

数据流在训练与推理时形状相同，但模式不同：

| 阶段 | 输入 | 输出 | 特点 |
| --- | --- | --- | --- |
| 训练 | 整段 $[L]$ token | 每位置 logits $[L, V]$ | 并行、算全部位置 loss |
| 推理 | 前缀 $[t]$ token | 仅最后位置 logits $[V]$ | 每次只取最后一个位置 |

推理时若每步都重算整个前缀的注意力，代价随 $t$ 线性增长，总代价 $O(L^2)$。**KV Cache** 把已算过的 K/V 缓存下来，让每步只算新 token 的注意力——这是推理加速的核心，我们会在第七篇《KV Cache》专门拆解。<span class="marginnote">训练「并行的因果预测」与推理「逐token的自回归」，是同一个模型的两副面孔。理解这一点，就理解了为什么 GPT 训练快、推理是「一步步来」——以及为什么 KV Cache 是服务端优化的头号主题。</span>

**辨析｜易错点：** Decoder-only 不等于「没有编码器就能瞎生成」。它同样有严格的输入输出约束：因果掩码保证「不能看未来」。如果去掉因果掩码，训练时模型直接「抄袭」答案，loss 归零但毫无泛化能力——掩码是自回归的灵魂。

## 6 术语速查表

| 术语 | 英文 | 一句话定义 |
| --- | --- | --- |
| Decoder-only | decoder-only | 纯自回归解码架构 |
| 形状守恒 | shape preservation | 主干每层保持 $[B,L,d]$ |
| 因果掩码 | causal mask | 挡住未来的注意力掩码 |
| Logits | logits | 未归一化的词表得分 |
| 链式分解 | chain rule | 序列概率的逐项乘积 |
| KV Cache | KV cache | 推理时缓存的 K/V |

## 7 数值算例：KV Cache 省了多少

设 $L=4096$，比较「每步全重算」与「KV Cache」的解码成本：

| 方案 | 单步代价 | 总代价 |
| --- | --- | --- |
| 无 KV Cache（每步全重算） | $O(t^2)$ | $O(L^3) \approx 6.9\times10^{10}$ |
| 有 KV Cache（增量） | $O(t)$ | $O(L^2) \approx 1.7\times10^{7}$ |

**读这张表**：无缓存时总成本是 $L^3$ 量级，有缓存降到 $L^2$——**差距约 4000 倍**。这就是为什么「生成一个 token 只花常数级注意力」对实际产品如此重要：KV Cache 不是优化，而是让「对话式交互」成为可能的必要设施。

**辨析｜易错点：** KV Cache 省的是「重复计算」，但它本身占显存——长上下文下 KV 是显存大头（第七篇展开）。「省时间」与「占显存」是 KV Cache 的一体两面，部署时要按「并发 × 长度」预算显存。

## 8 训练 vs 推理：数据流对照

| 阶段 | 输入 | 输出 | 模式 |
| --- | --- | --- | --- |
| 训练 | 整段 $[B,L]$ | 每位置 $[B,L,V]$ | 并行 |
| 推理首 token | 前缀 $[1,t]$ | $[1,V]$ | 自回归 |
| 推理续 token | 单 token + KV | $[1,V]$ | 增量 |
| 流式 | 单 token | 每步一个 | 恒定成本 |

训练与推理共享「因果 + 自回归」的底层逻辑，只是「并行度」不同：训练一次算完所有位置，推理一步一步推。理解这张表，就理解了为什么「训练用 GPU 集群、推理用 KV Cache + 批量」的分工如此自然。

## 9 小结

- **数据流**：token id → 嵌入 → 位置编码 → N 层（归一化→注意力→残差→归一化→MLP→残差）→ 最终归一化 → 输出头 logits → softmax 采样。
- **形状守恒**：主干每层保持 $[B, L, d]$，只有输出头升到词表维度 $[B, L, V]$。
- **因果掩码**让训练可并行、推理可自回归，是 Decoder-only 的灵魂。
- Decoder-only 因**目标统一、生成原生、服务简单**而成为主流结构。
- 输出头把表示投影到词表空间，模型本质是**token 序列的条件概率分布**。
