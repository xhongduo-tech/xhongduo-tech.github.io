## 为什么 Agent 需要「记忆」

Agent 在一次任务里要「记住」：用户说过什么、查到过什么、做到哪一步了。而 LLM 的「上下文」是有限的（128k 是极限）——长任务、多轮对话、跨会话，上下文「装不下」。**记忆机制** 把 Agent 的「记忆」从「上下文窗口」扩展到「外部存储」——像人类用「笔记」「档案」补足「短期记忆」的不足。<span class="marginnote">Agent 记忆的「范式」借鉴了「人类记忆」：<strong>短期记忆（上下文）与长期记忆（外部存储）</strong>——短期「随时用、易丢失」，长期「保存、可检索」。MemGPT 甚至把「LLM 的操作系统」类比引入——上下文是「内存」，外部存储是「磁盘」——Agent「换页」把「当前需要的」换进上下文。</span>

## 1 短期记忆：上下文窗口

**短期记忆（short-term memory）** 就是 LLM 的上下文窗口——当前对话/任务的所有「历史消息」：

用户请求、历史对话、工具观察、中间推理——都在上下文里。
**容量有限**（几万到几十万 token）——装不下无限历史。

**短期记忆的管理**：

**窗口截断**：超过容量就「丢最老的」——简单但「丢信息」。
**摘要压缩**：把「旧对话」压缩成「摘要」——「留精华、丢细节」。
**滑动窗口 + 关键保留**：保留「最近的」+「重要的」（类似 KV 驱逐，第十五篇的知识复用）。

**短期记忆的局限**：容量有限 + 任务结束即「清空」——**跨任务/跨会话的信息无法保留**——这就是长期记忆的用武之地。

## 2 长期记忆：外部存储

**长期记忆（long-term memory）** 把 Agent 的重要信息「存到外部」——跨任务、跨会话「持久化」：

**长期记忆的形态**：

**向量数据库**：把「事实/经验」向量化存储——按「语义相似」检索（RAG 复用）。
**键值存储**：结构化信息——「用户偏好」「任务状态」。
**文件**：完整记录——「报告草稿」「对话存档」。

**长期记忆的内容**：

**用户偏好**：「用户喜欢简洁的回答」「用户关注技术细节」。
**历史经验**：「上次这个任务失败了，原因是……」（Reflexion 的教训存储）。
**领域知识**：「项目的技术栈」「团队的规范」。

**Agent 与长期记忆的交互**：

**写入**：任务中「重要信息」写入记忆。
**读取**：新任务开始时「检索相关记忆」——「想起」历史经验。<span class="marginnote">长期记忆让 Agent 从「每次从零开始」变成「有连续经验的个体」——<strong>「跨任务的学习」成为可能</strong>。Reflexion 的教训、用户的偏好、项目的知识——都存在长期记忆里，下次任务「直接调用」——这是「Agent 的记忆」与「RAG 的知识库」在技术上的统一：<strong>都是「向量检索 + 存储」</strong>。</span>

## 3 记忆的分层：感知、工作、长期

借鉴「认知科学」的记忆模型，Agent 记忆可以分三层：

| 层级 | 类比 | 内容 | 存储 | 生命周期 |
| --- | --- | --- | --- | --- |
| 感知记忆 | 感官 | 当前输入 | 上下文 | 瞬时 |
| 工作记忆 | 短期 | 任务状态 | 上下文（摘要管理） | 任务期间 |
| 长期记忆 | 长期 | 经验/知识/偏好 | 外部存储 | 持久 |

**工作记忆**：当前任务「手里要拿的」——用「上下文 + 摘要」管理。

**长期记忆**：跨任务「存下的」——用「外部存储 + 检索」。

**Agent 的记忆循环**：

1. 任务开始 → 从长期记忆「检索相关」→ 装入工作记忆（上下文）。
2. 任务执行 → 工作记忆（上下文）逐步积累 → 超限时「压缩/摘要」。
3. 任务结束 → 重要经验「写入」长期记忆 → 下次检索可用。

## 4 公式解析：记忆管理的「上下文预算」

短期记忆的管理核心是「上下文预算」——在有限窗口里「放什么」。设窗口容量 $C$、当前上下文 $S$、新信息 $s$：

$$
\text{决策}(s) = \begin{cases} \text{保留 } s & |S| + |s| \le C \\ \text{压缩旧信息 + 保留 } s & |S| + |s| > C \end{cases}
$$

对这条式子做三步拆解：

- **第一步，读「装得下就装」**：上下文没满，新信息直接加入——工作记忆「累积」。
- **第二步，读「装不下就压缩」**：超限时，把「旧信息」压缩成「摘要」，腾出空间给「新信息」——**「摘要」替代「原文」**。
- **第三步，读出权衡**：压缩「丢细节」（摘要不保留原文）——**「记忆的容量」与「记忆的精度」的权衡**——「压缩率」是记忆管理的核心旋钮。长期记忆的「检索」也是同一权衡：**「检索到多少相关」与「上下文装不装得下」**。

**辨析｜易错点：** 记忆的「写入」不是「自动的」——**Agent 要知道「什么值得记」**。不是所有对话都该写入长期记忆（写太多 = 检索噪声）。「写入策略」要设计：任务结束时的「关键结论」写入、过程细节不写——**「记忆的质量」决定「记忆的价值」**。

## 5 记忆系统的工程实践

- **短期管理**：上下文摘要 + 窗口截断——「装得下 + 留精华」。
- **长期存储**：向量库（语义检索）+ 键值库（结构化）+ 文件（完整）。
- **写入策略**：重要结论、用户偏好、失败教训——「值得记的才记」。
- **读取策略**：任务开始时「检索 top-k 相关记忆」——「想起该想起的」。
- **记忆更新**：旧记忆「过期」要「淘汰」——「记忆保鲜」。

## 6 小结

- **短期记忆**：上下文窗口——容量有限，靠「截断/摘要」管理。
- **长期记忆**：外部存储——跨任务/会话持久化，靠「向量检索」调用。
- 三层记忆：**感知（瞬时）→ 工作（任务期）→ 长期（持久）**。
- 记忆循环：**检索装入 → 执行积累 → 压缩/写入**。
- 关键权衡：**记忆容量 vs 精度**；「值得记的才记」——记忆质量决定价值。
