## 为什么 LLaVA 是「最朴素的成功」

LLaVA（Large Language and Vision Assistant）的多模态方案简单到「令人怀疑」：**一个 MLP 投影器 + 视觉指令微调**。没有花哨的 Q-Former、没有复杂的跨模态注意力——但它在开源 VLM 里长期领先，并成为「最容易被复现」的基线。它的成功证明了：**当视觉编码器够好、训练数据够精，简单的架构也能很强**。<span class="marginnote">LLaVA 的哲学：<strong>「把复杂留给预训练，把简单留给架构」</strong>——视觉编码器用 CLIP 预训练好的（复杂），对齐用一层 MLP（简单），理解用 LLM（预训练好的）。它证明「三段式的极简版」就够用——<strong>架构的简单性 + 数据的质量 = 竞争力</strong>。</span>

## 1 LLaVA 的架构：极简三段式

LLaVA 的完整架构：

```text
[图像] → [CLIP ViT 视觉编码器] → patch 特征 Z_v (N × d_v)
                                        │
                                        ▼
                             [MLP 投影器（2 层）]
                                        │
                                        ▼
                               视觉 token 序列 (N × d)
                                        │
                                        ▼
   [ <image> 视觉 token … , "user: 这是什么?" ] → [LLM Decoder-only] → 回答
```

**投影器**：一个两层的 MLP（LLaVA-1.5 用 MLP-2x）：

$$
Z = W_2 \cdot \sigma(W_1 \cdot Z_v), \qquad Z_v \in \mathbb{R}^{N \times d_v}, Z \in \mathbb{R}^{N \times d}
$$

- $W_1$：$d_v \to d$ 的映射（视觉特征维 → LLM 宽）。
- $\sigma$：GELU 激活。
- $W_2$：再映射一层。

**为什么 MLP 而非线性层**：LLaVA-1.5 实验显示，MLP 比「单层线性」的对齐效果好——**非线性让「翻译」更灵活**（视觉特征与文本空间的关系不是纯线性的）。

**视觉 token 与文本 token 拼接**：

$$
\text{input} = [\text{Patch}_1, \ldots, \text{Patch}_N, \text{user: 这是什么?}]
$$

LLM 生成回答——**视觉信息通过「patch token 序列」进入 LLM 的注意力**。<span class="marginnote">LLaVA 的「图像 token 放前面」是 VLM 的默认布局——图像像「被看的背景材料」，文本指令跟在后面。这种布局让 LLM「先看图、再读题」。有些 VLM 把图像放「任意位置」甚至「穿插在文本中」——布局也是可设计的。</span>

## 2 两阶段训练：对齐预训练 + 指令微调

LLaVA 的训练分两阶段，目标完全不同：

**阶段一：特征对齐预训练（Feature Alignment Pretraining）**。

**数据**：约 60 万「图像 + 简短描述」对（CC3M 子集）。
**训练**：**冻结视觉编码器与 LLM**，只训练投影器（MLP）。
**目标**：让投影器学会「把视觉特征翻译成 LLM 认识的表示」——「纯翻译」。
**效果**：这一阶段后，模型「能看图说话」了，但「不会做指令任务」。

**阶段二：视觉指令微调（Visual Instruction Tuning）**。

**数据**：约 15 万「视觉指令数据」——「看图 + 回答问题/描述/推理」的三元组。
**训练**：**冻结视觉编码器，微调 LLM（LoRA 或全量）+ 投影器**。
**目标**：让模型「遵循视觉指令」——「看图答问」「看图描述」「看图推理」。
**效果**：这一阶段后，模型「成为助手」——能执行各种视觉任务。<span class="marginnote">两阶段的「分工」很清晰：<strong>阶段一解决「能不能懂图」（翻译），阶段二解决「会不会干活」（任务）</strong>。如果把阶段二的数据直接用于阶段一，投影器「还没学好翻译就学任务」——效果差。这个「先对齐、后指令」的次序，是 VLM 训练的普遍规律。</span>

## 3 视觉指令数据：怎么造

LLaVA 的数据是「数据工程的代表作」——它用「ChatGPT/GPT-4 辅助」造了高质量视觉指令数据：

1. **图像 + 描述**：从 COCO 收集图像，配上详细描述。
2. **指令生成**：让 GPT-4「看着图像描述与框选区域」，生成「问题-答案」对——**问题类型覆盖**：详细描述、物体识别、位置问答、关系推理、常识问答。
3. **过滤**：人工筛选质量。

**数据形态**（指令-图像-答案）：

「这张图里有什么？」→「有一只猫在沙发上」。
「猫和沙发的位置关系？」→「猫在沙发上面」。

**为什么合成指令数据有效**：自然图像没有「配套问题」——合成指令「无中生有」地造出「训练任务」。这与「Self-Instruct」（第九篇）同源：**用强模型生成训练数据**。<span class="marginnote">LLaVA 数据用 GPT-4「看图说话」——但 GPT-4 是「语言模型」，它「看」的是「图像的区域描述」而非图像本身。这是「语言模型辅助造视觉数据」的巧劲：<strong>把「视觉」翻译成「文本描述」，语言模型就能参与造数据</strong>。后来更强的 VLM 直接「看图造数据」，但 LLaVA 的「文本中介」思路仍是有效方法。</span>

## 4 公式解析：投影器与 LLM 的梯度

两阶段训练的「梯度流」差异：

**阶段一（对齐）**：

$$
\text{只更新：} \text{MLP}(W_1, W_2), \qquad \text{冻结：} \text{ViT}, \text{LLM}
$$

**阶段二（指令）**：

$$
\text{更新：} \text{LLM}_{\text{LoRA}} + \text{MLP}, \qquad \text{冻结：} \text{ViT}
$$

对这套式子做三步拆解：

- **第一步，读阶段一**：只有投影器的参数有梯度——**LLM 的输出梯度「穿过 LLM」流到投影器**，教它「怎么翻译」。LLM 冻结但「提供翻译的反馈」。
- **第二步，读阶段二**：LLM 的 LoRA 参数 + 投影器一起更新——**任务能力「长」在 LLM 上，翻译能力「长」在投影器上**。
- **第三步，读出冻结的意义**：冻结 ViT 是「省算力 + 保特征」——CLIP 预训练的特征「不能乱动」（动了就「忘掉」语义对齐）。**冻结是「信任预训练」，微调是「补任务」**。

**辨析｜易错点：** 阶段一的「冻结 LLM」不是「LLM 完全不参与」——**LLM 前向参与**（提供输出与梯度路径），只是「参数不更新」。别把「冻结」理解成「不用 LLM」。梯度流：**LLM 冻结时，输出 loss 的梯度仍会「穿过」 LLM 的权重传到投影器**——LLM 是「梯度的通道」，只是「参数的看客」。

## 5 LLaVA 的影响与演进

- **LLaVA-1.5/1.6**：用 SigLIP 换 CLIP、加更高分辨率、扩充数据——简单架构 + 更好组件。
- **社区地位**：LLaVA 是「最容易复现」的 VLM 基线——无数 VLM 论文从它出发。
- **启示**：**架构不是 VLM 的唯一战场，数据（视觉指令）才是**——LLaVA 的数据配方被广泛复用。

## 6 小结

- **LLaVA 架构**：CLIP ViT + **MLP 投影器** + LLM——极简三段式。
- **两阶段训练**：先「对齐预训练」（冻结全部、只训投影器），再「视觉指令微调」（训 LLM+投影器）。
- **视觉指令数据**：GPT-4 辅助合成「看图问答」——数据质量是竞争力的核心。
- 冻结 ViT = 信任预训练；梯度穿过 LLM 教投影器翻译。
- 启示：**架构简单 + 数据精良 = 竞争力**。
