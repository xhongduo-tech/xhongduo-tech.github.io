## 为什么从短语模型看统计翻译的高潮

上两节我们有了 IBM 模型与对齐，但词级翻译有一个根深蒂固的缺陷：**词与词的对应太局部**。「don't know」不是「don't」和「know」两个词分别翻译出来的，它是一个整体；「洗手间」三个字拆开翻译会闹笑话；习语、搭配、固定结构的翻译根本无法逐词完成。2003 年前后，Och、Koehn 与 Marcu 等人把翻译单位从**词**提升到**短语**，短语翻译模型（PBMT）就此诞生，并统治统计翻译十多年，直到 Moses 这样的开源系统把它送进每个翻译工程师的工具箱。<span class="marginnote">注意这里的「短语」不是语言学里的短语（phrase），而是「任意连续 n 个词构成的串」——一个纯粹从数据切出来的翻译单位，与句法无关。这个命名差异是初学最容易踩的坑。</span>

短语模型继承了上一节的宝藏——词对齐——并把它升级：对齐好的词块，直接合并成**短语对（phrase pair）**，作为翻译的最小积木。

## 1 从词对齐到短语对

上一节我们通过对称化得到了一张稠密的双向对齐矩阵。现在把它切成块：**一个短语对** $( \bar{e}, \bar{f} )$ 由源文连续串 $\bar{f}$ 与译文连续串 $\bar{e}$ 组成，它合法当且仅当：$\bar{f}$ 与 $\bar{e}$ 内部词对齐一致，且**不与其他词块相交**——形式化地说，$(\bar{e}, \bar{f})$ 必须**与对齐一致（consistent）**：$\bar{f}$ 中每个词的对齐目标都在 $\bar{e}$ 里，$\bar{e}$ 中每个词的对齐来源都在 $\bar{f}$ 里。

这个约束保证：词块要么整体一起译，要么都不译，绝不「只译一半」。举个例子，德语「Ich weiß es nicht」对齐到英语「I don't know it」，如果对齐允许，就可以抽出短语对（weiß es nicht → don't know）——这是词级模型永远学不到的对应。

短语对全部收集起来，组成**短语翻译表（phrase table）**。表中每一项存一组特征：反向短语概率 $P(\bar{f} \mid \bar{e})$ 与正向概率 $P(\bar{e} \mid \bar{f})$（都由语料频次估计），以及两个**词汇权重（lexical weighting）** $\text{lex}(\bar{e} \mid \bar{f})$ 与 $\text{lex}(\bar{f} \mid \bar{e})$——后者用短语内部词对齐的词汇概率把短语概率「稀释」一遍，用来惩罚那些「整体碰巧共现、但词并不真对应」的假短语。<span class="marginnote">词汇权重是统计时代的「细粒度校验」：短语概率只看整块，lex 权重下探到词，两者互相制衡，防止翻译表塞满偶然共现的噪声。</span>

## 2 调序模型：短语的摆放顺序

短语对内部是固定的，但**短语与短语之间的顺序**需要模型决定。源文「我 喜欢 喝茶」按词序翻成「I like tea」，但「他 昨天 来 了」却不能按词序翻成「He yesterday came」——副词的位置两语不同。统计短语模型用一个**调序模型（distortion model）**给「改变相对顺序」的行为定价：

$$
d(a_i - b_{i-1} - 1)
$$

其中 $a_i$ 是第 $i$ 个短语对源文开始位置，$b_{i-1}$ 是上一个短语对源文结束位置，差值 $a_i - b_{i-1} - 1$ 衡量「跳跃」了多少词。跳跃越多，惩罚越重（$d$ 通常随距离指数衰减）。这个模型粗糙——它只数「跳了几步」，不关心语言结构——但它简单有效，也正因如此，才让基于句法的调序模型有了改进空间。<span class="marginnote">调序与语言模型（$P(e)$ 项的 $n$-gram）分工不同：语言模型管「生成出来的英语是否通顺」，调序模型管「按什么顺序取用源文短语」。两者都可能纠正词序，但纠正的来源不同。</span>

## 3 对数线性模型：把各特征拧成一股绳

短语翻译系统里有太多特征：短语概率、词汇权重、语言模型、调序惩罚、词数惩罚……它们量纲不同、性质各异，怎么合并？Och 与 Ney 给出的答案是**对数线性模型（log-linear model）**：翻译得分是各特征的对数线性组合：

$$
P(e \mid f) \propto \exp\Big( \sum_{k} \lambda_k h_k(e, f) \Big)
$$

其中每个 $h_k$ 是一个**特征函数**（如 $\log P(\bar{f} \mid \bar{e})$、$\log P_{\text{LM}}(e)$、调序惩罚等），$\lambda_k$ 是它的**权重**。搜索解码时，目标就变成最大化这个得分。权重 $\lambda_k$ 怎么定？用**最小错误率训练（MERT，minimum error rate training）**在开发集上直接优化 BLEU——为评估而训练权重，这在当时是理念上的突破，也是第九节《BLEU 与翻译评估》的伏笔。<span class="marginnote">对数线性模型是特征工程时代最通用的「融合框架」：任意能算分的特征都能塞进去，权重统一用 MERT 调。这个「把多种信号加权相加」的思路，与神经时代把多种表示加权求和，结构上是同构的。</span>

对数线性模型的核心，就是把所有信号统一成「可加权的特征」，一个系统常用的特征表如下：

| 特征 $h_k$ | 含义 | 大致作用 |
| --- | --- | --- |
| $\log P(\bar{e} \mid \bar{f})$ | 正向短语概率 | 越大越忠实 |
| $\log P(\bar{f} \mid \bar{e})$ | 反向短语概率 | 越大约稳健 |
| $\log \mathrm{lex}(\bar{e} \mid \bar{f})$ | 词汇权重 | 惩罚偶然共现的假短语 |
| $\log P_{\mathrm{LM}}(e)$ | 语言模型 | 整句通顺度的主心骨 |
| $\sum d(a_i - b_{i-1} - 1)$ | 调序惩罚 | 跳跃越少越好 |
| $\|e\|$ | 词数惩罚 | 微调译文长度偏好 |

其中 `$\|e\|$` 的权重可正可负——想让译文长一点就取负权重、短一点就取正权重，都交给 MERT 在开发集上定。注意特征之间常常相互抵消：语言模型喜欢「又长又顺」的句子，翻译模型喜欢「逐词都忠实」的译文，最终天平倾向哪边，完全由数据投票决定。

## 4 解码：在短语图里搜索

训练结束，翻译一个新句子时要做的事：把源句切成短语块，对每块查翻译表得到候选，再以某种顺序拼成译文，使总得分最高。这是**搜索**问题——候选数量指数级，只能近似求解。Moses 用**柱搜索（beam search）**在「翻译假设栈」里维护得分最高的若干部分翻译，逐步扩展。这就是第八节《解码策略与束搜索》的前身：神经时代的束搜索直接继承了这个柱搜索的框架。

搜索里还有一个常常被忽略的细节：**词数惩罚**与**未知词处理**。源文里查不到对应短语的词，要么原样复制（人名、数字、网址），要么被丢弃——统计时代没有子词，未知词（OOV）是真实痛点，直到 BPE 出现才被根治。

解码的复杂度也值得量化：若源句有 $n$ 个词、每个词最多对应 $c$ 个候选短语，则候选短语数以 $O(nc)$ 计，而把短语拼成完整译文的排列方式更是天文数字——这就是为什么必须用柱搜索而不是穷举。工程上还会限制短语最大长度（常见 3–5 词）与最大跳跃步数（常见 6），把搜索空间进一步压到可控范围，也让「先切哪里、后切哪里」的搜索策略有了明确的裁剪边界。

## 5 公式解析：短语模型的总得分

把整个短语模型的决策公式收拢成一条：

$$
\hat{e} = \arg\max_e \Big[ \lambda_{\text{LM}} \log P_{\text{LM}}(e) + \sum_i \lambda_{\text{TM}} \log \phi(\bar{e}_i \mid \bar{f}_i) + \lambda_{\text{dist}} \sum_i d(a_i - b_{i-1} - 1) + \lambda_{\text{len}} |e| \Big]
$$

逐项拆解：

- **第一项，语言模型** $\log P_{\text{LM}}(e)$：整句通顺度。它作用在**全局**译文上，天然能纠正文法错误与搭配，是质量的主心骨。
- **第二项，翻译模型** $\sum_i \log \phi(\bar{e}_i \mid \bar{f}_i)$：逐短语的忠实度。$\phi$ 通常是反向短语概率或词汇权重的组合，把整句忠实度拆成短语块的乘积之和。
- **第三项，调序惩罚**：对每步「跳跃」记账。$a_i - b_{i-1} - 1 = 0$ 时按顺序取用，无惩罚；跳跃越大扣分越多。
- **第四项，词数惩罚** $|e|$：在长度上稍作倾斜，避免译文过长或过短。

这条式子把**忠实度、流利度、词序、长度**四个维度并排放在同一个加号里，权重全靠 MERT 从数据里学——统计机器翻译「手工特征 + 自动调参」的范式在此登峰造极。

给这条式子配一个数字算例，体会「权重如何改变选择」。设两句候选译文 $e_1$、$e_2$ 的其他特征得分相同，只有语言模型项不同：$e_1$ 的 $\log P_{\mathrm{LM}}$ 更高（更通顺）但翻译模型项略低，$e_2$ 反之。若开发集上调出的权重偏向语言模型（$\lambda_{\mathrm{LM}}$ 大），最终选 $e_1$——模型「宁可忠实差一点，也要读起来顺」；换个数据集若权重偏向翻译模型，则选 $e_2$。**MERT 的整场戏，就是在开发集上找出让 BLEU 最高的那套权重**——它不拍脑袋，而是把「要流利还是忠实」的选择交给数据投票。<span class="marginnote">「权重是学出来的」这一点值得反复强调：统计翻译的工程师不手动决定语言模型和翻译模型谁更重要，而是交给 MERT 在开发集上投票。这种「自动调参」的哲学，正是神经时代端到端训练的雏形。</span>

## 6 辨析｜易错点：三个常见误读

**辨析｜易错点：**

1. **短语 ≠ 语言学短语**：PBMT 的「短语」是数据切出的任意连续串，跟主谓宾结构无关。「the cat on the mat」可以整体是一个短语，也可以切成三块——怎么切由解码时搜索决定。
2. **调序模型 ≠ 语言模型**：前者决定「源文短语的取用顺序」，后者判断「生成译文是否通顺」。两者都管词序但机制不同，初学时容易混为一谈。
3. **lex 权重 ≠ 短语概率**：短语概率是整块统计，lex 权重是内部词对齐的词汇概率。前者可能被数据稀疏骗到，后者是它的「防骗机制」。
4. **短语模型不是「更长的词对齐」**：短语对携带的不只是对齐，还有频率统计出的概率与词汇权重——它把「共现结构」浓缩成可打分的积木，而不是简单把词块粘在一起。

### 术语速查

| 术语 | 含义 | 一句话直觉 |
| --- | --- | --- |
| 短语对 $(\bar{e}, \bar{f})$ | 源 / 译连续串的对 | 翻译的最小积木 |
| 一致约束 | 短语内词对齐不越界 | 要么整体译、要么不译 |
| 短语翻译表 | 全部短语对及其特征 | 翻译的「词典」 |
| 词汇权重 | 词对齐级词汇概率 | 短语概率的「防骗机制」 |
| 调序模型 | 按跳跃距离定价重排 | 决定短语的摆放顺序 |
| 对数线性模型 | 特征加权求和再取指数 | 把所有信号拧成一股绳 |
| MERT | 在开发集上优化 BLEU 调权重 | 为评估而训练权重 |
| 柱搜索 | 维护前 $K$ 条部分翻译 | 神经束搜索的前身 |

## 7 小结

- **短语翻译模型**把翻译单位从词提升为任意连续串，靠上一节的词对齐切出**短语对**。
- 短语对要求与对齐**一致**，并携带短语概率与**词汇权重**两类特征。
- 句子间的顺序由**调序模型**负责，按跳跃距离惩罚重排。
- 全部特征用**对数线性模型**加权求和，权重用 **MERT** 直接优化 BLEU。
- 解码用**柱搜索**在短语图上近似搜索最优译文——统计时代的「束搜索」。

下一节我们将跨越范式：神经网络接管机器翻译，RNN 编码器—解码器如何用「连续向量 + 梯度下降」替换掉手工特征与搜索，翻译由此进入神经时代。
