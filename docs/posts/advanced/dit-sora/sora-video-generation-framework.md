## 为什么从「把 DiT 搬到视频」开始

2024 年 2 月 15 日，OpenAI 发布了 Sora 的技术报告，标题毫不谦虚：*Video Generation Models as World Simulators\*——**把视频生成模型当作世界模拟器**。这个模型能从一句文字生成最长 60 秒、1080p、任意宽高比的高清视频：穿行雪地的毛绒猛犸象、在东京街头奔跑的女郎、被风吹动的樱花……而它的技术底座，恰好是我们前四篇铺好的全部积木：DDPM 的扩散引擎、DiT 的 Transformer 骨干、AdaLN-Zero 的条件注入、scaling 的缩放律。

Sora 本质上是**把 DiT 从图像搬到视频的工程化实现**：同一个扩散 Transformer 框架，输入从二维图像 latent 变成三维视频 latent。本文讲 Sora 的宏观框架：它由哪几层堆叠而成，训练配方有什么讲究，以及为什么说它是「套着 DiT 外壳的视频生成器」。

在动手拆架构之前，值得先立一个坐标系：Sora 不是第一个视频扩散模型，它之前有 VideoGPT、Make-A-Video、Imagen Video 等一批工作；Sora 的突破点也不在「会用扩散」——那已是标配——而在「把规模做上去之后，能力自然涌现」。所以读这篇，重点是记住它的三个积木与它们如何拼装，而不是纠结某个超参。

## 1 三层堆叠：压缩、Patch 化、去噪

Sora 的架构可以拆成三个相互咬合的部件，正好对应「先变小、再切块、后去噪」三个步骤：<span class="marginnote">这套「压缩 → latent 扩散 → 条件去噪」的范式源自 Latent Diffusion（LDM，2022），Stable Diffusion 用它生成图像，Sora 把它推广到视频——区别只在压缩网络从 2D VAE 变成时空 3D 的版本。</span>

**第一层，视频压缩网络（video compression network）**：把原始视频压进一个低维 latent 空间。视频比图像信息量爆炸——60 秒 1080p 的视频在像素空间里有数十亿个数字，直接做扩散既贵又慢；压缩网络把空间和时间都「瘦身」，让后续的扩散只发生在紧凑的 latent 上。生成时再由配套的解码器把 latent 还原成像素视频。

**第二层，时空 Patch 化**：在压缩后的视频 latent 上，把「视频」切成三维的小块——空间上像 ViT 一样切 patch，时间上沿帧轴切段，得到一条 patch token 序列。这一层是 Sora 表示设计的核心，我们下一篇单独展开。

**第三层，扩散 Transformer（DiT）**：在 patch token 序列上跑我们熟悉的去噪过程。骨干是 DiT——堆叠的 Transformer 块、AdaLN-Zero 式条件注入、从噪声预测到清晰 latent 的反向采样。唯一的扩展是条件里多了**文本**：把文字提示编码成向量，作为另一路条件注入。

三层各司其职，恰好回应视频生成的三个痛点：压缩层对付「数据太大」，Patch 化对付「表示不统一」，DiT 对付「条件与质量」。注意顺序的必然性——必须先压缩、后切块，因为切块得到的 token 数是后续注意力成本的底数；顺序反了，token 会爆炸。

视频压缩网络的具体结构报告没有完全公开，但定位清晰：它是一个在视频与图像上训练过的自动编码器，输入原始视频、输出压缩 latent，配套一个把 latent 还原回视频的解码器。生成阶段模型只处理 latent，用户看到的是解码器重建的像素。**压缩率的设计需要权衡：压得太狠，细节与高频运动丢失；压得不够，token 太多、训练太贵。** 这个权衡在缩放篇里会再次出现。

## 2 一个视频生成器的完整链路

把三层串起来，Sora 的一次生成是这样的：

- **训练时**：取一段真实视频 → 压缩网络编码成 latent → 时空 Patch 化 → 加噪 → 让 DiT 预测噪声；损失就是上一篇的简化扩散损失，只不过条件从「时间步 + 类别」升级为「时间步 + 文本」。
- **采样时**：从纯噪声 latent 出发 → DiT 逐步去噪（条件为「时间步 + 文本」）→ 得到清晰的视频 latent → 解码器还原成像素视频。

**逐帧逐帧看，它是扩散模型；整体看，它是一个「文本进、视频出」的条件生成器。** 与图像 DiT 相比，几乎一切组件都可复用，Sora 的「新」主要在表示（时空 Patch）与规模（数据与算力），这正是后面几篇的主线。

与图像 DiT 相比，Sora 还有一处工程细节：patch 化不是对压缩后的整体 latent 一次性做，而是先切出「空间块 × 时间段」的三维 patch；视频长、分辨率高时，token 序列可以长到百万级，需要配合序列并行等分布式训练手段。这些工程细节不改变理论框架，却是「理论可行」到「真的能跑」之间的关键距离。

文本条件的技术路径沿用了图像生成的标准做法：一个文本编码器（如 CLIP 或更大的语言模型）把提示词变成向量序列，再以「条件」的身份进入扩散 Transformer——既可以拼进条件向量 $c$ 供 AdaLN-Zero 调制，也可以作为额外的 token 参与注意力。Sora 报告没有公布编码器细节，但强调了「描述越细、生成越贴合」的规律，这正是重打标能发力的原因。

## 3 公式解析：视频上的扩散损失

视频扩散的损失与 DDPM 逐行同构，只是变量变成了视频 latent、条件多了文本。写公式前先做一次符号移植：图像 DiT 里的 $x_0$ 是 $32 \times 32 \times 4$ 的 latent，Sora 里的 $x_0$ 则是压缩后的视频 latent——形状从三维变四维，但加噪、去噪、损失的形式一字未改。这套「换张量、不换方程」的复用，是生成模型工程化的最高境界：

$$
L(\theta) = \mathbb{E}_{t,\,x_0,\,\epsilon}\left[\left\|\epsilon - \epsilon_\theta\Big(\mathrm{patchify}\big(\sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\epsilon\big),\ t,\ \mathrm{text}\Big)\right\|^2\right]
$$

- **第一步，看输入**：$x_0$ 现在是**压缩后的视频 latent**（一个四维张量），前向加噪的重参数化公式原封不动；括号里加了一步 $\mathrm{patchify}$——把带噪 latent 切成时空 patch 序列，再喂给 Transformer。
- **第二步，看条件**：$\epsilon_\theta(\cdot, t, \mathrm{text})$ 里的条件从两个变成三个：时间步 $t$、文本提示 $\mathrm{text}$（还有训练时的图像/视频条件，报告里称为「prompt」）。AdaLN-Zero 的调制公式不变，只是回归参数的输入拼接了文本向量。
- **第三步，看损失**：仍是真实噪声与预测噪声的均方误差。**唯一的差异是网络结构从「在图像 patch 上」变成「在视频 patch 上」**——而这恰恰是 Sora 的全部秘密所在：它没有发明新的训练目标，而是发明了把视频变成 token 的表示。

**所以理解 Sora 的关键不在损失，而在表示。** 扩散引擎、条件注入、缩放律都是现成的；真正让视频「可被 transformer 处理」的，是下一篇的时空 Patch 表示。

再补一层直觉：为什么视频模型可以直接复用图像扩散的目标函数？因为目标函数只要求「输入是可加噪声的张量」——视频 latent 恰好满足；剩下的「如何把张量切成 token、如何把条件送进去」都发生在损失函数之外。**这就是为什么我们说 Sora 的贡献在表示与规模，而非损失设计。**

## 4 训练配方：互联网视频与重打标

框架之外，Sora 的训练配方也值得记一笔，因为它复用了 OpenAI 在文本侧验证过的成熟招数：

- **数据**：在**互联网规模的视频与图像**上联合训练。视频提供时间动态，图像提供静态细节与高分辨率样本——两者共享同一套 Patch 表示，天然可以混训。
- **可变性即特性**：训练时让每个样本保持**原始时长、分辨率、宽高比**，而不是像多数方法那样统一裁剪成固定方块。这让模型学会适应任意画幅，也直接支撑了后面「无缝延展、改分辨率」的能力。<span class="marginnote">固定裁剪在视频里会放大代价：同样的物体、同样的动作，被裁掉的时间与空间信息是<strong>不可恢复的</strong>。Sora 的「保真训练」是它能生成任意画幅视频的前提。</span>
- **重打标（re-captioning）**：沿用 DALL·E 3 的技术——用一个强模型（GPT 系）为训练视频**重新生成高质量、描述性的文字说明**。这大幅提升文本与视频的对齐质量，让「文字描述细节」真正传到画面里。

「重打标」值得多说几句，因为它直接继承了 DALL·E 3 的教训：早期文生图模型的一大瓶颈是「训练数据的文字描述太短、太粗糙」，模型学到的是「文字与图像的大致对应」而非「细节对应」。DALL·E 3 用生成式模型自动为每张图写详细描述，效果立竿见影；Sora 把同一招用到视频——**用强文本模型为弱标注的视频补上高质量字幕，等于在数据层面做了一次「蒸馏」**。

「可变性即特性」还有一层更实际的回报：**同一个模型可以服务所有下游任务**——做竖屏短视频、做横屏电影、做超长视频的首帧续写，都不用重新训练。对比之下，早期视频模型常按固定分辨率/时长训练，一到新画幅就退化；Sora 的「保真训练」从源头规避了这类兼容性问题。

这三条合起来的效果是：**一个能吃下「任意视频 + 任意文字」的通用视频生成器**。它不挑格式、不挑画幅、不挑时长，这正是「通用」的工程定义。

## 5 小结

- Sora 是 **DiT 的视频版**：三层堆叠——视频压缩网络、时空 Patch 化、扩散 Transformer。
- 生成链路：压缩 → Patch 化 → 加噪去噪 → 解码；损失与 DDPM 逐行同构，条件升级为「时间步 + 文本」。
- 理解 Sora 的关键在**表示**：视频如何变成 token 序列，是它与图像 DiT 的根本分野。
- 训练配方三件套：**互联网规模视频与图像联合训练、保留原始时长/分辨率/宽高比、重打标提升文本对齐**。
- Sora 没有发明新目标函数，而是把「统一表示 + 可缩放骨干」这套范式从图像平移到了视频。

在下一节，我们将钻进 Sora 最核心的发明：**时空 Patch 表示——视频和图像如何被切成同一种 token，让一套模型能生成任意时长、任意画幅的内容。**
