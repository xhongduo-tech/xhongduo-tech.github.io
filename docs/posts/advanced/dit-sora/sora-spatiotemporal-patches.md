## 为什么从「表示」开始

上一节我们说：**理解 Sora 的关键不在损失，而在表示。** 为什么一个「怎么把数据装进网络」的问题，能成为整篇报告的核心？因为视频天生难伺候：时长有长有短、分辨率有高有低、画幅有横有竖，还有一维「时间」需要刻画。如果一种表示能把这些「不一致」全部抹平，让视频和图像变成同一种东西——一条 token 序列，那么一个模型就能通吃所有形态的内容，后面的 scaling 才有意义。

Sora 的答案是**时空 Patch（spatiotemporal patches）**：把视频切成空间和时间上的三维小块，让「一个 patch」成为视频世界的基本单元，就像 token 之于文本、像素之于图像。<span class="marginnote">这是视觉表示史上又一个「找基本单元」的时刻：CNN 的像素、ViT 的图像 patch、LLM 的 token，到 Sora 的时空 patch——每一代模型都先回答「最小语义碎片是什么」，再谈架构。参见第二级《离散数学》与第三级《深度学习基础》。</span>

顺带一提，时空 Patch 并非 Sora 首创：ViT 用空间 patch，视频 transformer（如 ViViT、VideoMAE）早已试过时间维度的切块。Sora 的独特之处是把这套表示放进扩散生成，并与压缩网络、可缩放骨干三者绑定，让「表示」成为可随规模放大的资产。读这篇时请带着一个问题：为什么「表示」值得单独花一整篇讲？**因为生成模型的上限，往往先被表示卡住。**

## 1 视频压缩网络：先瘦身再切块

直接对原始像素视频切 patch 会得到一个天文数字的 token：一段 60 秒 1080p 视频的像素量以十亿计，Transformer 的注意力（上一篇的 $O(N^2)$ 代价）会瞬间爆炸。所以 Sora 在切块之前，先做一次**降维**：

**视频压缩网络（video compression network）**把原始视频 $\mathbb{R}^{T \times H \times W \times 3}$ 压缩成低维 latent $\mathbb{R}^{T' \times H' \times W' \times C}$——空间上像 VAE 一样降采样，时间上也会抽帧、把相邻帧的运动信息融进通道。压缩比例由训练时调节，决定「token 预算」与「信息保真」的权衡。<span class="marginnote">这与 Stable Diffusion 的策略一脉相承：VAE 把 $512 \times 512$ 图像压成 $64 \times 64$ 的 latent。Sora 把同一个套路推广到三维，用可学习的压缩网络（而非人工设定的下采样）决定表示的成本。</span>

一个细节值得注意：压缩网络是对视频与图像**联合训练**的，且压缩比例不是拍脑袋定的，而是与整体扩散模型共同优化——压缩得越狠，token 越少、训练越便宜，但重建损失越大、细节越糊。这个「压缩率 vs 保真度」的权衡，会在下一篇的缩放公式里变成显式的变量。

有人会问：为什么不让模型直接学像素视频？答案藏在注意力成本里。1080p 视频单帧约 200 万个像素，60 秒 30fps 就是 36 亿个数字——即便切成 patch，token 数也会压垮注意力的二次代价。压缩网络的作用就是把「像素海」变成「latent 塘」：token 数降几个数量级，模型才谈得上「用注意力看全局」。

这里还有个容易混淆的点：压缩网络与 VAE 的「隐空间」不是一回事，但思想同源——都是「编码器压、解码器还」。区别在于压缩网络的输入是视频（含时间），且要与扩散模型联合训练，追求的是「去噪容易」而不只是「重建无损」。

做完这一步，Sora 面对的是一个紧凑得多的高维张量；接下来才是真正的创新——在这个视频 latent 上切 patch。

## 2 时空 Patch：把时间也切成块

动笔之前先立定义：**时空 Patch 表示（spatiotemporal patch representation）**：把视频 latent 在时间与空间两个方向同时切成三维小块，每块线性嵌入为一个向量，从而把任意视频翻译成一条 token 序列的表示方法。

**Patch 化**在空间上与我们熟悉的 ViT、DiT 完全一致：把 latent 切成 $p_s \times p_s$ 的方块，每个块线性嵌入成一个向量。Sora 的扩展只有一点：**时间轴上也切**——沿帧轴每 $p_t$ 帧切一段，把「空间块 + 时间段」合并成一个三维 patch。于是每个 token 不再对应一张画面里的一小块，而是对应**一小段时间里的一小片空间**。

这些三维 patch 按「先空间、后时间」的顺序（光栅扫描展开）排列成一条 token 序列，送进扩散 Transformer。展平顺序也有讲究：同一帧的空间 patch 排在一起，再推进到下一帧——这个顺序让相邻 token 在序列里也「空间相邻」，自注意力的局部结构更容易被学到。**顺序即先验**：展平方式虽不增加参数量，却悄悄给模型注入了「空间与时间的组织方式」。

![视频经压缩网络与时空 Patch 化得到 token 序列](/images/dit-sora/sora-spatiotemporal-patches-1.svg)

这条序列有几条漂亮的性质。其一，**视频与图像统一**：单帧视频就是图像，图像天然是视频的特例，一套表示通吃。其二，**画幅与时长自由**：token 数随「帧数 × 分辨率」变化，模型不绑定固定尺寸，这解释了 Sora 为什么能生成任意宽高比的视频。其三，**继承 transformer 的序列操作**：视频拼接、续写、插帧，本质上都是「在 token 序列上做拼接、续写、插值」——这为下一篇的涌现能力埋下伏笔。

还有一条性质容易被忽略：**patch 是有「感受野」的时间结构**。一个时空 patch 覆盖了若干帧内的一小片区域，模型对它的处理天然要综合时间上下文——这让注意力既能捕捉空间细节，也能感知运动模式，而不必为「时序建模」专门设计组件。**时间，被表示吃掉了。**

## 3 公式解析：一段视频变成了多少 token

把「视频 → 时空 patch 序列」这步写成公式，能清楚地看到每个设计变量：

$$
N = \frac{T'}{p_t} \times \frac{H'}{p_s} \times \frac{W'}{p_s}, \qquad
\text{注意力代价} \sim N^2 d
$$

- **第一步，看三维网格**：压缩后的视频 latent 是 $T' \times H' \times W' \times C$ 的四维张量。时间轴切成 $\frac{T'}{p_t}$ 段，空间两轴各切 $\frac{H'}{p_s}$ 与 $\frac{W'}{p_s}$ 段。
- **第二步，看 token 总数**：三个方向段数相乘就是 patch 数 $N$。它随分辨率、随时长**线性**增长——$N$ 与 $T'$ 成正比，这是视频 scaling 的起点：视频天然比图像贵。
- **第三步，看注意力**：注意力代价与 $N^2$ 成正比，所以「时长翻倍 → token 翻倍 → 注意力 ×4」。这条二次膨胀曲线，正是压缩网络必须存在的根本原因，也是视频 scaling 比图像难的本质（见下一篇）。

代入一个具体场景：假设压缩后视频 latent 的时间维度为 24 帧、空间为 64×64、通道数 4，patch 取 $p_t=2, p_s=8$，则 token 数 $N = \frac{24}{2} \times \frac{64}{8} \times \frac{64}{8} = 12 \times 8 \times 8 = 768$ 个。如果把 patch 在时间上也切得更细（$p_t=1$），token 数直接翻倍到 1536，注意力成本 ×4——**视频模型的超参调优，本质上都在这个公式里打转**。

公式里的 $C$（压缩后通道数）容易被忽略，但它同样关键：patch 线性嵌入的输入维度是 $p_t \times p_s \times p_s \times C$，$C$ 越大，单个 patch 携带的信息越多、token 可以切得越粗。**时间与空间信息被压进通道，是「用通道换 token」的另一种权衡**——压缩网络的设计自由度，很大一部分藏在通道数的选择里。最后提醒一句：第三步的「注意力代价 $\sim N^2 d$」里 $d$ 是 token 向量维数；若把通道 $C$ 全塞进 $d$，token 变少但每 token 变长，二次项依然存在——**缩短序列永远比加长向量更省注意力的钱**。

**时空 Patch 设计的全部智慧，浓缩成一句话：用一次可学习的压缩，把视频的「贵」压到可控范围，再用三维切块把任意形态的视频翻译成 transformer 听得懂的序列。** 表示自由了，模型就自由了。

## 4 统一表示的回报

时空 Patch 不只是「一个漂亮的切法」，它直接兑现了 Sora 报告里展示的一系列能力，因为它们在表示层都是同一个操作：

- **图像生成**：把视频当单帧处理，模型天然能生成图像——「图生视频、视频生图」在同一模型内完成。
- **视频延展与插帧**：在 token 序列上「续写」，模型可以把视频向前、向后延长时间，或在两端之间插入过渡帧。
- **视频拼接**：把两段视频的 token 序列接起来去噪，模型学会无缝过渡——两个镜头可以「弥合」成一段连续视频。<span class="marginnote">这些能力本质上都是<strong>序列操作</strong>：续写、补全、拼接。LLM 能做的文本操作，换到 token 序列上的视频同样能做——「视频是序列」这一认识，是 Sora 能力清单的底层逻辑。</span>

还有一个值得单独拎出的能力：**视频提示词里可以同时含图像与文字**（如「把这张图延展成视频」「两张图之间插值」）。在表示层面，它们都是「把特定 token 的位置填上已知内容，其余留给去噪」——同一个序列框架，覆盖了从「文生视频」到「图生视频」到「视频插帧」的整个光谱。这是统一表示最直观的回报。

值得一提的还有：这套表示对「数字世界」同样有效。报告展示了 Sora 为 Minecraft 生成画面、模拟 3D 渲染过程——在表示层面，它们与真实视频没有本质区别：都是时空 grid 上的 token 序列。**统一表示的终点，是让模型分不清「真实世界」与「数字世界」的边界。** 这一句为最后一篇的「世界模拟器」埋下伏笔。

**一个表示，多种能力**——这就是统一表示的全部回报。模型不必为「图像」「长视频」「短视频」「竖屏」「横屏」各训一个，一套表示 + 一个可缩放的骨干，覆盖所有形态。

## 5 小结

- 视频原生复杂（时长、分辨率、画幅不一），Sora 用**统一的时空 Patch 表示**把它们全部抹平成 token 序列。
- 第一步是**视频压缩网络**：把视频 latent 降维，压住 token 预算与注意力成本。
- 第二步是**时空 Patch 化**：空间切块 + 时间切段，每个 token 对应「一小段时间 × 一小片空间」。
- token 数 $N = \frac{T'}{p_t} \cdot \frac{H'}{p_s} \cdot \frac{W'}{p_s}$，随时长线性增长、注意力代价随 $N^2$ 增长——压缩是视频 scaling 的前提。
- 统一表示的回报：图像/视频一体、延展插帧、视频拼接，都是同一条 token 序列上的不同操作。
