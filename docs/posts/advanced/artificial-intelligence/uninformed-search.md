## 为什么从「盲搜」开始

上一篇我们把问题求解翻译成了「在状态空间图上找路径」。但图摆在那里，怎么找？直觉上，人总是盯着目标走——先看看哪个方向更像出口。**无信息搜索（uninformed search）**恰恰相反：它**拒绝一切关于目标的提示**，只靠系统性的遍历保证「只要解存在，就一定找得到」。<span class="marginnote">盲搜不是蠢，而是一种理论基准：它先确立「无任何领域知识时能做到多好」的底线，下一篇的启发式搜索则在这个底线上做加法。理解基线，才能理解 A\* 的收益究竟来自哪里。</span>

这一篇的三位主角——**广度优先搜索（BFS）**、**深度优先搜索（DFS）**、**一致代价搜索（uniform-cost search）**——差别只有一个：**它们用什么样的顺序从待探索队列里取出下一个节点**。队列顺序不同，搜索树展开的形状就完全不同，时空复杂度也因此天差地别。这就是本篇的核心叙事：**调度策略决定一切**。

## 1 搜索的基础设施：边界与已探索集合

所有无信息搜索共享同一套骨架。算法维持两个数据结构：

**边界（frontier / open list）**：已生成但尚未被扩展的节点集合，是「待办清单」。<span class="marginnote">边界就是搜索算法内存里的「队列」——它装着所有「发现了、但还没看下一步」的状态。BFS 用先进先出队列实现它，DFS 用后进先出栈实现它，一致代价搜索用优先队列实现它。三个算法、三张调度表，仅此而已。</span>

**已探索集合（explored / closed set）**：已经被扩展过的状态集合，用于避免重复展开——这是上一篇讲过的图搜索与树搜索的分水岭。

单步操作是固定的：从边界取出一个节点；若通过目标测试则成功返回；否则扩展它（生成全部后继），把新状态加入边界，把自己移入已探索集合。**三个算法的全部差异，都浓缩在「从边界取出节点」这一行里。**

$$\text{循环：取节点 } n \leftarrow \text{Frontier.pop()} \;\Rightarrow\; \text{若 Goal}(n)\ \text{返回}\;\Rightarrow\; \text{扩展 } n,\ \text{更新 Frontier}$$

读作：从边界取一个节点，若它已是目标就返回，否则生成它的后继、更新边界与已探索集合，再回到开头——**直到边界为空（无解）或命中目标**。整篇的三个算法只是把「取节点」的策略换掉。

## 2 广度优先搜索：按「层」推进

**广度优先搜索（breadth-first search, BFS）**：每次总是先扩展深度最浅的节点。实现上，边界用**先进先出（FIFO）队列**——新节点排到队尾，队头永远是最浅的节点。搜索树像水波一样一圈圈向外推。

BFS 的性质非常干净，但代价也极其明确：

| 性质 | 结论 | 原因 |
| --- | --- | --- |
| 完备性 | 是（状态空间有限时） | 逐层扫描，最浅解必被遇到 |
| 最优性 | 是（每步代价相同时） | 第一个找到的目标必是最浅的 |
| 时间 | $O(b^d)$ | 展开到深度 $d$ 前所有节点 |
| 空间 | $O(b^d)$ | 边界里同时存放一整层节点 |

其中 $b$ 是**分支因子（branching factor）**，$d$ 是**最浅解所在的深度**。空间 $O(b^d)$ 是 BFS 的致命伤：深度每加一层，内存需求乘以 $b$。<span class="marginnote">一个具体到可怕的数字：若 $b = 10$、$d = 14$，BFS 的边界里会有约 $10^{14}$ 个节点——远超任何机器的内存。这就是为什么「盲搜」在现实里常需配合内存有界的变体，也解释了为什么 A\* 的「带知识的剪枝」如此宝贵。</span>

**辨析｜易错点：完备性与最优性是两个不同的「好」。** 完备性只承诺「有解必找到」，最优性承诺「找到的是最好的解」。BFS 在步代价相同时两者兼得；但若边权不同，最浅的路径未必是最便宜的——这正是要引入一致代价搜索的理由。不少教材把 BFS 直接当作「最优算法」，实则是隐式假设了每步代价相等。

## 3 深度优先搜索：一条道走到黑

**深度优先搜索（depth-first search, DFS）**：每次总是先扩展深度最深的节点。实现上，边界用**后进先出（LIFO）栈**——最新生成的节点最先生成后继，搜索树像挖井一样直往下钻。

DFS 的看家本领是**空间效率**：

| 性质 | 结论 | 原因 |
| --- | --- | --- |
| 完备性 | 有限图是；无限图否 | 可能沿着无穷分支一直钻下去 |
| 最优性 | 否 | 找到的第一个目标未必最浅/最优 |
| 时间 | $O(b^m)$ | $m$ 是最大深度，最坏遍历整棵树 |
| 空间 | $O(bm)$ | 只保留一条根到叶的路径 + 兄弟节点 |

空间 $O(bm)$ 对比 BFS 的 $O(b^d)$ 是巨大胜利：深井里只需要记住当前这条探险路线，而不是整层的水波。<span class="marginnote">这个空间优势让 DFS 成为很多实际系统的默认选择——即使它不保证最优。八皇后、数独的求解器、编译器的语法分析都偏爱 DFS 式回溯，因为它们「只求一个解」且「状态空间天然有界」。</span>

DFS 的顽疾是**会陷进无穷分支**。当状态空间有环，或存在无限深的路径时，DFS 可能永远不回头。补救方案是**深度受限搜索（depth-limited search）**：把深度封顶在 $\ell$，超过即放弃；再配合**迭代加深（iterative deepening）**——把 $\ell$ 从 0 逐次加 1 重复 DFS。迭代加深的代价只是常数倍的重复展开，却能同时拿到 BFS 的完备性与 DFS 的空间优势，是工程里最常用的折中。<span class="marginnote">迭代加深重复展开同一批节点看起来「浪费」，但第 $d$ 层节点占整棵树的比例约 $(b-1)/b$，重复展开的额外开销只有常数倍——这是一个反直觉但被严格证明的事实。</span>

## 4 一致代价搜索：让代价说话

前两个算法都假设「每步代价相同」。**一致代价搜索（uniform-cost search, UCS）****取消这个假设**：边界用**优先队列**实现，键值正是**路径代价 $g(n)$**——每次扩展 $g(n)$ 最小的节点。

UCS 是 Dijkstra 最短路算法的搜索版：它永远优先处理「目前花销最少」的路径。当所有边权为正时，UCS 是**完备且最优**的——它找到的第一个目标一定代价最小。<span class="marginnote">为什么「第一个被扩展的目标」就最优？因为在边界里所有节点的 $g$ 值都 ≥ 当前目标的 $g$，而所有未扩展路径的代价只会继续增加（边权为正）。这个论证在《启发式搜索》里会被 A\* 继承并加强。</span>

| 性质 | 结论 |
| --- | --- |
| 完备性 | 是（边权为正、有限） |
| 最优性 | 是（边权为正） |
| 时间 | $O(b^{1 + \lfloor C^*/ \epsilon \rfloor})$ |
| 空间 | 同时间量级 |

其中 $C^*$ 是最优解代价，$\epsilon$ 是最小边权。当边权相等时，UCS 退化为 BFS——可见 **BFS 只是 UCS 在单位代价下的特例**。

一个直观例子：设最优路径代价 $C^* = 14$，最小边权 $\epsilon = 1$，则 UCS 至多展开到代价 $\le 14$ 的所有节点，即大约 $b^{15}$ 的量级——它不会去碰任何「总花销超过已知最优」的分支。这正是它与 BFS 的本质差别：BFS 按**层**推进，UCS 按**代价**推进。

## 5 公式解析：为什么「复杂度」都要写成 $b$ 和 $d$

复杂度分析里反复出现的 $O(b^d)$、$O(bm)$，其含义值得拆到底。

$$N = 1 + b + b^2 + \cdots + b^d = \frac{b^{d+1} - 1}{b - 1}$$

- **第一步，读清记号**：$b$ 是分支因子——每个节点平均有几个后继；$d$ 是深度——从根到目标要走几步。
- **第二步，数节点**：第 0 层 1 个根，第 1 层 $b$ 个，第 2 层 $b^2$ 个……第 $d$ 层 $b^d$ 个，加起来是等比级数。
- **第三步，看主导项**：$b^d$ 远大于其余各项，因此 BFS 展开到深度 $d$ 的节点总数约是 $b^d$ 量级——时间与空间都记作 $O(b^d)$。

**一个经验法则**：$b$ 对复杂度的影响是指数级的。$b$ 从 2 变到 10，深度 10 的搜索量从 $2^{10} \approx 10^3$ 暴涨到 $10^{10}$。这就是为什么「状态空间建模得好不好」（能否把 $b$ 压小）比「搜索算法本身聪不聪明」更影响成败。<span class="marginnote">这条法则也解释了搜索的「知识 vs 蛮力」之争：给算法塞进一点领域知识（启发式、剪枝、对称消去），等价于把有效 $b$ 大幅缩小——下一节的 A\* 正是这么做的。</span>

## 6 三种策略如何选

选型原则可以浓缩成一张决策表：

- **要保证最优、且每步代价相同** → BFS（或 UCS）。
- **空间紧张、只求任意一个解** → DFS（或迭代加深）。
- **边权不同、必须最便宜** → UCS。
- **解可能很深** → 迭代加深优先，因为它兼有 DFS 的空间与 BFS 的完备性。

**辨析｜易错点：不要混淆「扩展顺序」与「返回条件」。** BFS 在「生成节点时」就可以检查目标，UCS 却必须在「扩展节点时」才检查目标——若 UCS 在生成时就返回，可能因边权问题返回非最优解。这个细节是历届学生调试搜索算法的头号陷阱，务必在实现时注意。

## 7 小结

- **无信息搜索**靠「边界数据结构的选择」区分三种策略：FIFO 队列 → BFS，LIFO 栈 → DFS，优先队列 → UCS。
- **BFS** 完备且（单位代价下）最优，但空间 $O(b^d)$ 是硬伤。
- **DFS** 空间 $O(bm)$ 极省，但可能陷入无穷分支、不保证最优；**迭代加深**折中两者。
- **UCS** 用路径代价 $g(n)$ 排序，边权为正时完备最优，是 Dijkstra 的搜索形态。
- 复杂度的主导项是 $b^d$——**降分支因子比换算法更改变量级**，这是「状态空间建模」先于「算法选择」的根本原因。
- **选型口诀**：要最优且每步代价相同 → BFS；空间紧张只求一解 → DFS 或迭代加深；边权不同必须最便宜 → UCS。
- **迭代加深**用常数倍的重复展开，同时拿到 BFS 的完备性与 DFS 的空间优势，是工程里的默认折中。

在下一节，我们给盲搜装上「方向感」：让算法用启发式函数估计「离目标还有多远」，据此优先扩展更有希望的方向——这就是**启发式搜索**（A\*/贪心最佳优先）。
