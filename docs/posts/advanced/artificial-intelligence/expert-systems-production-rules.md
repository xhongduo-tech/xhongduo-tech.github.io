## 为什么从「方法」收拢到「系统」

前十篇讲的是**方法**：搜索、逻辑、表示、规划、概率。但方法堆在一起还不叫产品——真实世界的符号主义 AI 需要一个把这些方法装起来的**外壳**。**专家系统（expert system）**就是符号主义在 20 世纪 80 年代最成功的封装：一个把「某个领域的专家知识」编译成规则、并用推理引擎自动运用这些规则的软件系统。<span class="marginnote">专家系统的黄金时代诞生了多个改变产业的系统：MYCIN 诊断细菌性血液感染、DENDRAL 推断有机分子结构、XCON 为 DEC 公司配置计算机订单——XCON 一年为 DEC 省下数千万美元。它们证明了一件事：<strong>领域知识 + 规则引擎，可以产生工业级价值</strong>。这也正是「符号主义」得名的由来——知识被显式地写成符号规则。</span>

本篇是专题收官：把前面所有方法放进一个真实可用的架构里。我们会拆解**产生式规则系统**（production rule system）的组成与运行循环、**前向/后向链接**两种推理方向、**MYCIN 的确定性因子**如何给规则加可信度，最后讨论专家系统为何盛极而衰，又给今天的 AI 留下了什么。

## 1 专家系统的架构：知识库 + 推理引擎

一个经典专家系统由四大件构成：

**（1）知识库（knowledge base）**：存放领域知识——通常是「IF-THEN 规则」的集合，外加事实与元知识。**（2）推理引擎（inference engine）**：运用规则得出结论的程序——它与知识分离，同一个引擎可以驱动不同领域的知识库。**（3）工作内存（working memory）**：推理过程中的临时事实集，随推理不断增删。**（4）人机界面**：向用户提问、展示结论与**解释**。<span class="marginnote">「知识库与推理引擎分离」是专家系统最核心的工程哲学：更新知识不必改代码，换领域只需换知识库。这个「数据与逻辑分离」的思想后来被规则引擎（Drools）、业务规则系统甚至现代 Agent 的「提示词即知识」反复继承——<strong>关注点分离是符号主义留下的最持久遗产</strong>。</span>

推理引擎对规则库做**规则匹配**：把工作内存里的事实与规则的前提比对，命中就执行规则的结论。这个「匹配 → 选择 → 执行」的循环，是产生式系统的运行心脏。

## 2 产生式规则与运行循环

**产生式规则（production rule）**就是「IF 前提 THEN 动作/结论」的形式：

$$\text{IF } \underbrace{\text{发热} \land \text{血液培养阳性}}_{\text{前提}} \text{ THEN } \underbrace{\text{考虑细菌性菌血症}}_{\text{结论}}$$

产生式系统（production system）在三个存储间循环：

**工作内存（fact base）**：存放已知事实；**规则库（rule base）**：存放全部规则；**推理引擎**：反复做三步——**匹配**（找出前提全部满足的规则）、**冲突消解**（匹配出多条规则时，决定先执行哪条）、**执行**（把结论/动作加入工作内存或触发副作用）。

**冲突消解（conflict resolution）**的策略包括：**规则序优先**（按书写顺序取最早匹配）、**专门性优先**（前提更具体的规则优先）、**最近性优先**（使用最新事实的规则优先）。<span class="marginnote">冲突消解决定了「多条规则同时可用时先跑谁」，直接影响推理路径。它很像规划里的「动作选择」与博弈里的「走法排序」——都是「从可选集中挑一个」的决策问题。好的消解策略减少无谓回退，差的策略让系统绕远路甚至死循环。</span>

## 3 两种推理方向：前向与后向

**前向链接（forward chaining）**：**数据驱动**——从已有事实出发，不断匹配规则、产生新事实，直到问不出新结论或命中目标。适合**监控与配置**类问题：传感器的数据不断涌入，系统持续推导「接下来该提醒什么」。<span class="marginnote">前向链接可以看作「常识的雪崩」：每条规则把已知事实推成新事实，事实越来越多，直到答案浮现。XCON 配置计算机订单用的就是前向链接——从订单规格一路推导出全套配件清单。它与「逻辑编程的前向推理」、以及规则引擎 Drools 的默认行为同构。</span>

**后向链接（backward chaining）**：**目标驱动**——从目标结论出发，反向找「哪些规则能推出它」，再验证这些规则的前提。MYCIN 的血液感染诊断正是后向链接：系统先问「是不是菌血症」，若规则说「发热且培养阳性」才能推出，就反问用户「发热吗？培养结果如何？」——**像一个不断追问的医生**。<span class="marginnote">后向链接把「推理」变成了「提问的树」：要证目标 $G$，找结论含 $G$ 的规则，把前提变成新的子目标继续下钻——这正是 Prolog 的 SLD 归结在规则引擎里的工程化。它天然生成<strong>解释</strong>：「我要推出 $G$，所以需要知道前提 $P_1, P_2$」——每一步都有据可查。</span>

**辨析｜易错点：前向 ≠ 后向 ≠ 聪明程度。** 两者只是方向不同：数据充足、目标开放 → 前向；目标明确、数据稀疏 → 后向。选错方向会让系统在无关分支上浪费大量匹配。

## 4 MYCIN 与确定性因子：给规则加可信度

纯产生式系统只能处理确定知识。MYCIN 开创性地给每条规则配一个**确定性因子（certainty factor, CF）**——一个 $[-1, 1]$ 的数值，表示结论的可信程度（正为支持、负为反对、0 为未知）。

MYCIN 的**合成公式**把两条规则对同一结论的支持合起来：

$$\text{CF}(H) = \text{CF}_1 + \text{CF}_2 - \text{CF}_1 \cdot \text{CF}_2 \quad (\text{CF}_1, \text{CF}_2 > 0)$$

**公式解析：CF 的并行合成。** 三步：

- **第一步，读符号**：$\text{CF}_1, \text{CF}_2$ 是两条独立规则对假设 $H$ 的可信度（都为正）。
- **第二步，看增长**：合成后比任一条都大——两条证据叠加，可信度上升，但被 $-\text{CF}_1\cdot\text{CF}_2$ 项封顶在 1，不会「爆表」。
- **第三步，体会直觉**：这模仿「两条独立线索互相印证」：每加一条支持，可信度增加「还没信的部分」的比例，渐近收敛到 1。<span class="marginnote">CF 是「概率的工程妥协」：MYCIN 的作者发现纯贝叶斯推理在当时难以落地（先验难取、独立性假设难验证），于是用 CF 这种「经验加权」代替严格概率。它不满足概率公理，但足够好用——这也解释了为什么它被称为「朴素但实用的不确定性」。</span>

**串行合成**处理「证据本身不可靠」：若规则「IF 培养阳性 THEN 菌血症」的 CF 是 0.8，而「培养阳性」本身的证据可信度只有 0.6，则结论的 CF 为 $0.8 \times 0.6 = 0.48$——**证据的可信度沿着规则链向下传递**。

## 5 解释机制：专家系统最被低估的财富

专家系统区别于普通决策程序的一大特征，是**解释能力（explanation facility）**。用户问「为什么开这个药」，系统能回溯推理链回答：

**为什么（Why）**：因为「IF 菌血症 THEN 处方万古霉素」这条规则被触发，而菌血症已被当前证据支持。
**如何（How）**：菌血症的结论来自「发热 + 血液培养阳性」两条证据的合取，其中发热由用户直接提供、培养阳性来自检验数据。<span class="marginnote">解释能力源于「规则即证据链」：结论不是黑箱算出来的，而是沿着可读的规则逐步推出来的。这条「可解释性」传统在符号主义里与生俱来，却在深度学习时代成为必须重新争取的能力——今天的<strong>可解释 AI（XAI）</strong>、大模型的<strong>思维链（CoT）</strong>，某种意义上都是在「找回专家系统天生就有的东西」。想系统了解，见第四级《可解释 AI》专题。</span>

### 一个跑通的例子：迷你菌血症诊断

把后向链接跑一遍，就看清产生式系统的工作方式。规则库三条：

R1：IF 发热 AND 血液培养阳性 THEN 菌血症（CF 0.8）
R2：IF 菌血症 THEN 处方万古霉素（CF 0.9）
R3：IF 免疫低下 AND 发热 THEN 怀疑真菌感染（CF 0.6）

用户初始提供的事实：`发热`、`免疫低下`、`血液培养阳性`。目标是「决定处方」：

- 推理引擎后向展开「处方 X」：R2 是唯一结论含处方的规则，前提是 `菌血症`——变成子目标。
- 继续展开 `菌血症`：R1 前提是 `发热 ∧ 血液培养阳性`，工作内存里两者都有，规则命中，CF 合成得 $0.8$。
- R2 触发，结论可信度 $0.9 \times 0.8 = 0.72$，系统处方万古霉素并给出解释：**「因为 R2 + R1，而发热与培养阳性来自您的病历。」**

注意 R3 虽也命中 `发热`，但冲突消解选了专门性/目标相关的 R2——**目标驱动让系统只走通往处方的路径，不浪费在真菌怀疑上**。<span class="marginnote">这个例子里 CF 只做「数字上的叠加」，真正的智能来自<strong>规则与目标的方向</strong>：后向链接让每一步都「为了回答处方而问」，前向链接则会让系统同时推出「真菌感染」等无关结论。方向选对，系统才显得「聪明」。</span>

## 6 规模化的关键：Rete 匹配算法

规则库一大（上千条规则、上万条事实），「每次循环都全量匹配所有规则」就太慢了。**Rete 算法**（Forgy, 1982）是产生式系统的性能救星：它把规则匹配**增量缓存**起来——事实加入工作内存时，只重新匹配与它相关的规则部分，而不是全库重扫。

Rete 把规则编译成一张**匹配网络**：共享同一前提片段的规则共用节点，事实在网络里流动，「走到终点」的规则就是命中的规则。因为网络结构在运行期不变，**事实变更只触发网络局部更新**，匹配成本从「全库 O(规则数×事实数)」降到「近增量」。<span class="marginnote">Rete 的设计思想与数据库查询优化、以及现代流式处理的「增量物化视图」异曲同工：<strong>把重复计算缓存起来，只算变化的部分</strong>。Drools 等现代规则引擎至今仍内嵌 Rete 的变体。它的存在说明：符号系统的工程性能，靠的是精妙的算法而非蛮力。</span>

**辨析｜易错点：Rete 不改变逻辑结果，只改变匹配速度。** 它只是匹配层的加速器，冲突消解与推理策略完全不受影响。评价一个专家系统，先看规则正确性，再看匹配性能——顺序别颠倒。

## 7 盛极而衰与留下的遗产

专家系统在 1980 年代后期退潮，原因值得深思：

**知识获取瓶颈（knowledge acquisition bottleneck）**：把专家头脑里的经验转成规则，需要知识工程师与专家漫长的访谈——成本极高且难以扩展。**脆弱性（brittleness）**：遇到知识库外的情形，系统没有「不知道」的优雅退路，常常给出荒谬结论。**无学习能力**：规则不会自动更新，环境一变就过时。**维护困难**：规则库动辄上千条，修改一条可能引发连锁冲突。

但这些「失败」恰恰照亮了它留给今天的遗产：

**知识显式化**：可解释、可审计、可传授——与黑箱模型形成鲜明对照；
**关注点分离**：知识库 / 推理引擎 / 界面解耦，是现代 Agent 架构的原型；
**规则即程序**：产生式系统的「匹配-消解-执行」循环，启发了现代规则引擎、工作流系统与决策树式推理；
- **混合范式**：专家系统与机器学习并非对立——今天的 LLM Agent 用「工具 + 提示词 + 规则」重构了专家知识，而专家系统「知识库可解释」的优点正借大模型重新发光。<span class="marginnote">一个直观的延续：现代智能客服、诊疗决策支持、甚至大模型的「系统提示词 + 工具调用」编排，本质都是「把领域规则显式地交给推理系统」。符号主义没有消失，它换了个形态活在每一个「规则 + 推理」的软件里——从数据库的约束到 Agent 的 ReAct 循环，都是本专题全部思想的子孙。</span>

## 8 小结

- **专家系统** = 知识库（规则）+ 推理引擎 + 工作内存 + 界面；**知识库与引擎分离**是核心工程哲学。
- **产生式规则**：IF 前提 THEN 结论；系统在**匹配 → 冲突消解 → 执行**间循环。
- **前向链接**数据驱动，适合监控配置；**后向链接**目标驱动，适合诊断问答（如 MYCIN）。
- **确定性因子 CF** 用 $[−1,1]$ 表示结论可信度；并行合成 $\mathrm{CF}_1+\mathrm{CF}_2-\mathrm{CF}_1\mathrm{CF}_2$ 封顶于 1，串行合成沿证据链衰减。
- **Rete 算法**把规则匹配增量缓存成网络，事实变更只触发局部更新，是规则引擎的性能核心。
- **解释能力**（Why/How）是专家系统最被低估的财富，是今天可解释 AI 与思维链的直接先声。
- **盛极而衰的教训**：知识获取瓶颈、脆弱性、无学习能力；遗产是知识显式化与关注点分离。

在下一节，符号主义的这场漫游就此告一段落——但它的方法论没有消失：搜索、逻辑、表示、规划、概率、规则，都会在机器学习与今天的大模型里以新的形态重获新生。我们将在第四级《AI 智能体》与《机器学习》专题继续这段旅程。
