## 为什么从双塔模型开始

上一篇的多路召回里，有一条路我们只点了名没展开——**向量路**。它是今天召回层的事实主力：YouTube 的召回、Google 的 Match 塔、Meta 的向量检索，底层都是同一个结构，**双塔模型（Two-Tower Model）**。

双塔的核心思想一句话就能说清：**把用户和物品各编码成一个稠密向量，用内积表示「匹配度」**。你可能会说——这不就是第三篇矩阵分解干的事吗？确实，矩阵分解就是双塔的「朴素版」：MF 里 $P$ 矩阵是用户塔、$Q$ 矩阵是物品塔，内积就是打分。双塔的升级在于：**塔不再是一张线性表，而是任意深度的神经网络**，可以吃进更丰富的特征。<span class="marginnote">从 MF 到双塔的演进，本质是「把 $p_u$、$q_i$ 从<strong>查表得到的向量</strong>，升级为<strong>网络计算出来的向量</strong>」。查表只能给每个用户一个向量，网络却能用行为序列、年龄、场景等特征动态生成向量——这正是第三篇《矩阵分解的局限》里「特征利用不足」的药方。</span>

这一篇回答三个问题：双塔**长什么样**、用什么**目标训练**、以及它为什么**天生适合召回层**。

## 1 从矩阵分解到双塔：三步升级

回顾第三篇的 Funk-SVD：用户向量 $p_u$、物品向量 $q_i$ 都是直接查表的 Embedding，打分是内积 $\hat{r}_{ui} = p_u^{\top} q_i$。双塔沿着同样的骨架做了三步升级：

1. **特征化**：用户侧输入从「用户 ID」扩展成用户特征（历史物品 ID 序列、统计特征、画像），物品侧输入扩展成物品特征（ID、类目、内容 Embedding）。<span class="marginnote">这一步把「冷启动的用户/物品」也变成了可编码的对象——<strong>只要特征存在，向量就能生成</strong>。这直接缓解了第二篇《协同过滤的优缺点》里「无行为无向量」的冷启动痛点：新物品没有交互，但它的类目、文本、图片特征照样能喂进物品塔。</span>
2. **非线性化**：查表变成「Embedding 拼接 → 若干层 MLP → 输出向量」，塔内部可以建模特征间的复杂交叉。
3. **统一到内积**：两个塔各自输出 $d$ 维向量，匹配度仍用内积（或余弦），从而在最后一步保持「向量检索」的高效性。

**重点：** 双塔不是「更深的矩阵分解」，而是**把推荐问题重构成「表示学习 + 近邻检索」两步**：先让网络把匹配关系压进向量空间，再靠向量距离做召回。这个重构，是它能在毫秒级扛住十亿物品的关键。

## 2 双塔的结构：两支塔，一个内积

结构上双塔由三部分组成：

- **用户塔**：输入用户侧特征，输出用户向量 $\vec{u} \in \mathbb{R}^d$。
- **物品塔**：输入物品侧特征，输出物品向量 $\vec{v} \in \mathbb{R}^d$。
- **打分函数**：$\hat{y}_{ui} = \langle \vec{u}, \vec{v} \rangle = \vec{u}^{\top} \vec{v}$。

两塔的输出维度 $d$ 必须一致（常见 64 / 128 / 256）。两塔的**参数不共享**——它们处理的输入空间完全不同，没有理由共享权重。<span class="marginnote">一个关键的结构特性：<strong>双塔的塔和塔之间在打分前没有任何交互</strong>。这意味着用户塔和物品塔可以<strong>分开推理</strong>——物品塔离线把所有物品向量算好、建好索引，线上只算一次用户向量，然后用 ANN（近似最近邻，第十二篇的 HNSW）检索，这就是「双塔天生适合召回」的工程根源。</span>

```python
# 伪代码（PyTorch 风格）：双塔结构
class TwoTower(nn.Module):
    def __init__(self, d=128):
        self.user_tower = nn.Sequential(nn.Linear(u_dim, 256), nn.ReLU(), nn.Linear(256, d))
        self.item_tower = nn.Sequential(nn.Linear(i_dim, 256), nn.ReLU(), nn.Linear(256, d))
    def encode_user(self, u_feat):
        return self.user_tower(u_feat)          # 线上只算这一支
    def encode_item(self, i_feat):
        return self.item_tower(i_feat)          # 物品向量可离线预计算
    def score(self, u_feat, i_feat):
        u, v = self.encode_user(u_feat), self.encode_item(i_feat)
        return (u * v).sum(dim=-1)              # 内积打分
```

## 3 训练目标：从 pointwise 到 sampled softmax

向量空间要学成什么样子？需要一个目标函数告诉网络「什么样是匹配的」。主流有三档：

- **pointwise**：把「是否点击」当二分类，用交叉熵。简单，但对负例的采样方式不敏感，容易收敛到「热门物品向量普遍偏大」的捷径。
- **pairwise**：让正样本对的得分大于负样本对，如 BPR 损失（第三篇提过）。$\mathcal{L} = -\log\sigma(\langle\vec{u},\vec{v}_+\rangle - \langle\vec{u},\vec{v}_-\rangle)$。训练更稳，但对负例质量要求高。
- **sampled softmax**：把召回当「从十亿物品里选出正例」的多分类，用负采样近似全词表 softmax。这是双塔召回**事实上的标准**，下一篇《负采样》会展开，这一篇先给公式。

## 4 公式解析：sampled softmax 损失

把「用户 $u$ 在物品全集 $I$ 中选择了 $i$」建模为一个分类概率：

$$
P(i \mid u) = \frac{\exp\big(\langle \vec{u}, \vec{v}_i \rangle / \tau\big)}{\sum_{j \in I} \exp\big(\langle \vec{u}, \vec{v}_j \rangle / \tau\big)}
$$

全词表求和算不动，于是用一个小负样本集 $\mathcal{N}$（比如 batch 内其他物品）来近似，得到训练损失：

$$
\mathcal{L} = - \log \frac{\exp\big(\langle \vec{u}, \vec{v}_+ \rangle / \tau\big)}{\exp\big(\langle \vec{u}, \vec{v}_+ \rangle / \tau\big) + \sum_{j \in \mathcal{N}} \exp\big(\langle \vec{u}, \vec{v}_j \rangle / \tau\big)}
$$

四步拆解：

- **第一步，看分子**：正样本对的相似度 $\langle \vec{u}, \vec{v}_+ \rangle$。$\vec{u}$ 与 $\vec{v}_+$ 越相似，分子越大，这个样本的「概率」越高。
- **第二步，看分母的 $\sum_{j \in \mathcal{N}}$**：把所有负样本对的相似度做指数和。分子除以分母，就是在问「**在正例和这些负例的对比中，正例有多突出**」——负例越不相似、正例越相似，概率越接近 1，损失越小。
- **第三步，看温度 $\tau$**：$\tau$ 是**温度系数**，控制分布的尖锐程度。$\tau$ 越小，指数函数越「陡」，模型越要用力拉开正负样本的距离（对难负样本敏感）；$\tau$ 越大，分布越平缓，训练越稳但区分度下降。<span class="marginnote">温度是双塔里最敏感的超参数之一——文献里常见 $\tau \in [0.05, 0.2]$ 量级。它是对比学习（第四级《自监督学习》、CLIP 那句"temperature"）里同一个量的移植：<strong>调小温度 = 提高对负样本的惩罚强度</strong>。</span>
- **第四步，为什么是「采样」**：$\mathcal{N}$ 只是全集的极小抽样。采样质量直接决定训练效果——**随机采样偏「简单负例」，难负样本采样才能逼模型学到精细区分**。这正是下一篇的主题，这一篇先记住：$\mathcal{N}$ 是核心旋钮。

## 5 训练细节：batch 内负采样与归一化

纸上公式落地，有三个工程细节决定成败：

**batch 内负采样（in-batch negatives）**：训练时把一批用户、一批物品喂进去，**用同一 batch 里其他样本当负例**——零额外成本，负例数量还随 batch 增大而增加。但它的隐患是**采样偏差**：热门物品在 batch 里出现频率高，被当负例的概率也高，模型会误以为「热门 = 负例」，把热门物品的向量压扁。<span class="marginnote">对策一是<strong>去偏</strong>：对物品按出现频率做重要性采样校正（类似 NCE 里的 $P(j)$ 修正项）；对策二是叠加<strong>额外难负样本</strong>（从全局索引里捞几个「长得像正例」的样本混进 $\mathcal{N}$）。这两招在下一篇《负采样》里细讲。</span>

**向量归一化**：给输出向量做 L2 归一化再算内积，让内积退化为余弦相似度，打分被限制在 $[-1,1]$。归一化能稳定训练，但会丢「模长」信息（热度信息），是否归一化是经典的取舍。<span class="marginnote">不归一化时，模型容易走捷径：给热门物品学出「大模长」向量，靠模长大来刷高内积，而不是真正学语义相似。归一化强制模型只靠方向分高下，与第四篇内容推荐里「余弦只看方向」是一脉相承的取舍。</span>

**一致性**：线上打分的输入必须和训练时的输入完全一致——用户塔吃哪些特征、物品塔吃哪些特征，稍有偏差，向量空间就「错位」了。这条工程红线，到第十二篇《特征平台》会反复强调。

**正样本从哪来**：正样本通常取「有点击/有播放/有购买」的用户-物品对，但行为强度差异很大——一次「划走」和一次「看完 90%」不该是同一个正样本。常见做法是按行为类型分级（曝光无反馈 < 点击 < 深度播放 < 购买），对弱行为降权或过滤，对强行为加权。**正样本的清洗决定了向量空间「把什么当作相近」**，是比模型结构更先要做的功课。<span class="marginnote">这与第二篇《数据来源》的「显式 vs 隐式反馈」一脉相承：<strong>隐式行为要转成监督信号，必须先定义「什么算正例」</strong>。工业界常把「曝光未点击」显式当成负样本加入训练，逼模型学会区分「看了但没兴趣」——这也是后面精排模型里常见的人肉特征。</span>

## 6 为什么双塔天生属于召回层

把双塔放回上一篇的漏斗里，它的定位非常清晰：

- 召回层要的是**快**：物品塔离线把十亿物品全部向量化、建成 ANN 索引；线上只算一个用户向量（毫秒级），一次近邻检索就拿到候选。
- 排序层要的是**准**：精排的深度模型要建模特征交叉，必须让用户特征和物品特征**在打分前就交互**（Concat、注意力），这正是双塔**刻意不做**的——两塔分离是为了效率，代价是损失了特征级交互。

**辨析｜易错点：** 不要指望双塔「打得准」。双塔是「**粗而快**」的表示学习器：它擅长把候选从十亿缩到一千，但不擅长在候选内部排出精细名次。把双塔拿去当精排，等于放弃交叉特征建模，精排层的 AUC 会明显掉。**两塔分离的结构决定了它的天花板，也决定了它的战场——召回层。** 这也是为什么漏斗需要粗排、精排这些「能交互」的模型来补位。换句话说，双塔把「算得动」排在「算得准」前面，而漏斗设计正是为了让这两种诉求各得其所。

## 7 小结

- 双塔 = 用户塔 + 物品塔 + 内积打分；是矩阵分解把「查表向量」升级为「网络生成向量」。
- 两塔分离让**物品向量可离线预计算、线上只算用户塔**，配合 ANN 检索在毫秒级扛住十亿候选——天生属于召回层。
- 训练目标三档：pointwise、pairwise、**sampled softmax**（事实标准）；温度 $\tau$ 与负样本集 $\mathcal{N}$ 是两个核心旋钮。
- batch 内负采样零成本但有热门偏差，需去偏与难负样本补充；向量归一化强制模型学方向而非模长。
- 双塔「粗而快」、不做特征交叉，**定位是召回而非精排**。
- 正样本的构造（行为分级、曝光未点击当负例）先于模型结构决定向量空间「把什么当作相近」。
- 温度 $\tau$ 越小越逼模型拉开正负距离、对难负样本越敏感；它是双塔超参调优的第一站。

在下一节，我们将聚焦双塔训练里那个最关键的旋钮：**负采样**——batch 内负采样怎么去偏、难负样本怎么构造，它们如何决定双塔召回的质量上限。
