## 为什么从基于内容推荐开始

第三篇收官时，我们把矩阵分解的四条局限摊在了手术台上。其中最扎眼的一条是冷启动：**没有交互，就没有向量**——新物品在 MF 眼里与「不存在的物品」几乎没有区别。可一个物品明明带着一身的属性：标题、简介、类目、导演、封面图。这些信息在协同过滤里全部被视而不见。

这一篇我们换一个截然不同的立场：**不再问「别人怎么看这个物品」，而是问「这个物品本身是什么」**。这就是**基于内容的推荐（Content-based Recommendation）**——它不看集体智慧，只看物品的内容与用户的历史。它是破解冷启动的第一把钥匙，也是后续所有「把特征喂给模型」工作的雏形。<span class="marginnote">基于内容的思想并不新鲜：图书管理员向读者推荐「同主题的书」，正是内容推荐的原始形态。它比协同过滤古老得多，却在互联网时代被「集体智慧」的光芒盖过——直到冷启动与个性化瓶颈逼它重新登场。</span>

## 1 换个立场：不看别人，看物品本身

协同过滤的信条是「**用户没看过的东西，可以靠相似用户或相似物品的交互推出来**」。基于内容的信条则朴素得多：**用户喜欢什么样的物品，我就找和他喜欢的物品「长得像」的东西**。

两者分岔在「相似」的定义上：

| 维度 | 协同过滤（ItemCF） | 基于内容（Content-based） |
| --- | --- | --- |
| **相似依据** | 行为共现：同时被喜欢 | 内容属性：本身长得像 |
| **数据来源** | 用户 × 物品交互矩阵 | 物品属性 + 用户历史行为 |
| **冷启动物品** | 无交互即无表示 | 新物品立即可用（属性已知） |
| **可解释性** | 「因为你还喜欢……」 | 「因为你看过相似的《X》」 |
| **发现惊喜** | 可能跨类目发现 | 被困在同类目内 |

**重点：** 基于内容的核心矛盾，是把「喜欢」这个动作翻译成「两个特征向量靠近」。这个翻译分两步——先把物品和用户都刻画成**画像（profile）**，再在画像之间算相似度。<span class="marginnote">注意与第二篇《相似度计算》的衔接：那边学的是「怎么算相似」，这一篇要解决更根本的「拿什么算相似」——<strong>画像才是相似度的输入</strong>。</span>

## 2 物品画像：给物品建一张「身份证」

**物品画像（item profile）**：一个描述物品「是什么」的结构化表示，通常是一个特征向量 $\vec{i}$。画像里的信息分两类：

**结构化属性**：类目、导演、演员、语言、出品年份、时长。它们本身是离散的标签，可以直接编码成向量。
**非结构化属性**：标题、简介、评论、剧情摘要。它们是自由文本，必须先变成向量（词袋、TF-IDF，下一篇的主角）。

结构化属性的编码是最朴素的向量化：类目「科幻 / 动作 / 爱情 / 喜剧」是一个 4 维多热向量，某部电影可能是 $(1, 0, 0, 1)$（既是科幻又是喜剧）；导演「诺兰 / 卡梅隆 / …」同理；再拼上出品年份、时长等数值特征。<span class="marginnote">多热编码里，一个物品可以在多个类目上同时「点亮」——这正好呼应第一级《集合》里讨论的<strong>集合与多重集</strong>：类目更像集合（互异、无序），而词频更像多重集（允许重复），后面说到 TF-IDF 时会用上这个区分。</span>

把结构化与非结构化特征拼在一起，就得到物品画像：

$$
\vec{i} = \big[\,\underbrace{0,1,0,\dots}_{\text{类目多热}}\;\big|\;\underbrace{0.3, 0.1, \dots}_{\text{文本词向量}}\;\big|\;\underbrace{2009, 148, \dots}_{\text{数值特征}}\,\big]
$$

**辨析｜易错点：** 画像向量不是「天生」就在同一量纲上的。多热编码取值是 0/1，词向量取值可能带符号或远大于 1，年份则动辄上千——**直接用内积会让数值大的维度统治一切**。所以构建画像时通常要对数值特征做标准化（减均值除以标准差），让每个维度大致落在同一尺度。这也是为什么相似度计算普遍选用余弦而不是内积——余弦只关心方向，天然对尺度不敏感。

## 3 用户画像：从历史行为反推兴趣

物品画像描述「物品是什么」，**用户画像（user profile）**则回答「用户喜欢什么」。它的构建思路朴素到令人安心：**用户喜欢过的东西的画像，平均起来就是用户的画像**。

设用户 $u$ 的历史交互物品集合为 $H_u$，每个物品有画像 $\vec{i}$，则：

$$
\vec{u} = \frac{\sum_{i \in H_u} w_{ui}\, \vec{i}}{\sum_{i \in H_u} w_{ui}}
$$

其中 $w_{ui}$ 是物品 $i$ 在用户历史里的**权重**。权重的选择决定了画像的质量：

- **等权平均**：$w_{ui} = 1$，最简单，但看完没区别——评分 5 星和 1 星一个待遇。
- **评分加权**：$w_{ui} = r_{ui}$，让高评价物品主导画像，低评价自然稀释。
- **行为强度加权**：看完的权重高于只看不买的；买过的高于点过的——不同行为代表不同的承诺程度。<span class="marginnote">这就是第一篇《数据来源》里「显式反馈与隐式反馈」的落地：<strong>买、收藏是强信号，点击、曝光是弱信号</strong>，给不同信号配不同权重，是画像工程的第一步。更细的权重设计属于第九篇《冷启动》与第十二篇《特征平台》。</span>

## 4 公式解析：画像如何变成推荐分数

画像的最终归宿是打分。把用户画像 $\vec{u}$ 与候选物品画像 $\vec{i}$ 放进同一个特征空间，用**余弦相似度**给出「用户有多喜欢这个物品」：

$$
\hat{r}_{ui} = \cos(\vec{u}, \vec{i}) = \frac{\vec{u} \cdot \vec{i}}{\lVert \vec{u} \rVert \; \lVert \vec{i} \rVert} = \frac{\sum_{f} u_f\, i_f}{\sqrt{\sum_{f} u_f^2}\; \sqrt{\sum_{f} i_f^2}}
$$

这条式子值得三步拆解：

- **第一步，看分子 $\vec{u} \cdot \vec{i}$**：逐维度把「用户在这个特征上的浓度」与「物品在这个特征上的含量」相乘再求和。用户偏爱科幻（$u_{\text{科幻}}$ 大）、物品恰好是科幻（$i_{\text{科幻}}$ 大），这一维就贡献大——**与第三篇 LFM 的内积直觉完全一致**，只是这里的维度有了真实的名字。
- **第二步，看分母 $\lVert \vec{u} \rVert \lVert \vec{i} \rVert$**：把长度归一化。用户历史长、画像向量长，不代表他更「贪心」；物品属性多、向量长，也不代表它更「重要」。除以长度，让相似度只看**方向**，不看**模长**。
- **第三步，看结果区间**：余弦值落在 $[-1, 1]$。现实中特征向量多为非负，结果通常落在 $[0, 1]$，值越大越相似。**对全部候选物品算一遍余弦，取 Top-N，就是这一篇最基本的推荐算法**。

**重点：** 打分这一行字里藏着基于内容推荐的全部优雅与全部局限——优雅在于它**不需要任何其他用户的数据**，新物品只要有属性就能被推荐；局限在于它只能「顺着」用户已有的兴趣走，永远推荐「和喜欢过的很像」的东西。这个缺陷我们会在下一篇、以及第十一篇《重排与多样性》反复回到。

## 5 完整流程：从画像到推荐结果

把上面几节串起来，一次基于内容的推荐在线上长这样：

```python
# 线上一次基于内容的推荐：用户画像 → 与候选物品画像做余弦 → Top-N
u = load_user_vector(user_id)             # 读取用户画像向量（随行为增量更新）
for item, v in candidate_items:           # 候选物品画像离线算好、可缓存
    scores[item] = cosine(u, v)           # 只做向量运算，不查邻居
result = top_k(scores, k=100)
```

这个循环与协同过滤的在线流程有一个关键区别：**它不做任何「邻居查找」，只做向量运算**。候选物品的画像可以离线算好、缓存起来，线上只需把用户的画像向量与候选集逐个做余弦——在物品数千万量级时，这依然需要向量检索的加速，那就是第五篇《向量召回》的任务了。<span class="marginnote">另一个工程细节：<strong>用户画像要随行为实时更新</strong>——用户刚看完一部电影，$\vec{u}$ 就应该立刻向这部电影倾斜。延迟越低，推荐越「跟手」。这与第二级《算法》里讨论的「在线 / 离线」权衡一脉相承。</span>

画像构建、打分、更新这套「流水线」做完，基于内容推荐的基本框架就完整了。剩下两个追问——**文本到底怎么变成词向量？用户兴趣除了平均还能怎么建？**——正是接下来两篇的主题。

## 6 与协同过滤的对照：各得其所

基于内容不是要取代协同过滤，两者解决的是不同的问题。把两种范式放进同一张表，各自的位置就清楚了：

| 能力 | 基于内容 | 协同过滤（ItemCF） |
| --- | --- | --- |
| 新物品冷启动 | **强**：有属性即可推荐 | 弱：无交互无表示 |
| 新用户冷启动 | 中：需先积累行为 | 弱：无行为无法画像 |
| 多样性 / 惊喜度 | **弱**：困在既有兴趣 | 强：可能跨类目发现 |
| 可解释性 | **强**：「因为你看过《X》」 | 中 |
| 依赖集体数据 | 不依赖 | 强依赖 |

**重点：** 基于内容的短板恰好是协同过滤的长板，反之亦然——**两者在真实系统里几乎总是被混合使用**（第四篇最后一篇会专门讲混合策略）。今天先记住一个判断标尺：**当物品属性丰富、用户行为稀疏时，基于内容占优；当物品属性贫瘠、行为稠密时，协同过滤占优**。

## 7 小结

- **基于内容的推荐**：不看集体行为，只看物品属性与用户历史，用「画像 + 相似度」做推荐。
- **物品画像** $\vec{i}$：结构化属性（类目多热、数值特征）与非结构化属性（文本向量）拼接而成的特征向量。
- **用户画像** $\vec{u}$：历史交互物品画像的加权聚合，权重由行为强度 / 评分决定。
- **打分公式**：$\hat{r}_{ui} = \cos(\vec{u}, \vec{i})$，取 Top-N；余弦对尺度不敏感，是画像匹配的首选。
- 基于内容**擅长新物品冷启动与可解释性，不擅长惊喜度**；与协同过滤互补，工业上常混合使用。
