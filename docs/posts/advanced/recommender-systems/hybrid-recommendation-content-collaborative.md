## 为什么从混合策略开始

第四篇的前四节，我们分别走完了内容推荐的两条腿：**物品画像与用户画像**、**文本表示与物品 Embedding**、**用户兴趣建模与相似度匹配**。它们各有绝活，也各有硬伤——内容推荐擅长新物品冷启动与可解释，却困在「只推同类」的过度窄化里；协同过滤（UserCF、ItemCF、矩阵分解）能借集体智慧把用户推出舒适区，却在新用户、新物品面前毫无办法。**没有哪一种单一算法能同时赢下冷启动、稀疏与惊喜度三场战役。**

这一篇回答第四篇的收官命题：**内容与协同过滤，怎么混合才恰到好处？** 我们会看到，混合不是「把两个模型的结果拼在一起」这么简单——它有一整张方法图谱，从最简单的加权平均，到工业界真正在用的**分层混合**。<span class="marginnote">学术界把混合推荐整理成一张「七宫格」图谱，出自 Robin Burke 的综述论文 <em>Hybrid Recommender Systems: Survey and Experiments</em>（2002）。七种方式不是相互排斥的，真实系统往往是好几种的组合。</span>

## 1 为什么要混合：两张「错误清单」刚好互补

先看清两类算法的失败模式，混合的动机就藏在这里。

- **协同过滤的错误清单**：新物品没有交互 → 无向量 → 冷启动失败；交互矩阵稀疏 → 相似度算不准 → 推荐质量崩坏；热门物品霸榜 → 长尾被淹没。它错在**「没有数据」**。
- **内容推荐的错误清单**：过度窄化、惊喜度趋零、信息茧房、需要可用的内容特征（画像不完整就寸步难行）。它错在**「太依赖自我」**。

**重点：** 两者的错误来源几乎是正交的——CF 缺数据时，CB 恰好只需要物品属性；CB 陷在舒适区时，CF 恰好擅长跨类目挖掘集体偏好。**混合的价值不是「两个模型取平均」，而是让一种方法在另一种方法失明的地方亮起来。**

这很像第一级《概率论与数理统计》里的「集成思想」：单个弱估计器各有偏置，把**偏差方向不同**的估计器组合起来，才能同时压低偏差与方差。推荐算法的混合是同一个道理的工程版。

## 2 混合方式的第一层：输出级融合

最简单的一类混合发生在**输出端**——两个算法各自算分，再把分数合并成最终排序。

### 加权式（Weighted）

每个算法对物品 $i$ 给出一个分数，线性加权求和：

$$
\hat{r}_{ui} = \lambda \cdot \hat{r}^{\text{CF}}_{ui} + (1 - \lambda) \cdot \hat{r}^{\text{CB}}_{ui}
$$

$\lambda$ 是**混合权重**，控制两类信号的信任比例。它的直觉是「两个专家投票，权重大的专家说了算」。<span class="marginnote">$\lambda$ 可以固定，也可以动态：新用户历史行为少，CF 不可信，就调小 $\lambda$ 让 CB 主导；老用户行为充足，再逐步调大 $\lambda$。<strong>按用户成熟度动态调权</strong>是工业界常见的「冷启动温启动」手法。</span>

### 切换式（Switching）

按某种**置信度准则**决定当前请求用哪个算法：能算出高置信度 CF 分数就用 CF，算不出（比如新物品）就切到 CB。

**辨析｜易错点：** 加权式混合最容易被误用的一点是——**两个算法的分数尺度往往不同**。CF 的余弦相似度在 $[-1,1]$，CB 的 TF-IDF 余弦也在 $[-1,1]$，但 MF 的内积分数可能被推到几十上百。直接线性加权等于让分数尺度大的那个算法「喧宾夺主」。所以加权前必须先**归一化**（min-max 或 rank 归一化），这正是本篇第 4 节公式解析的重点。

## 3 混合方式的第二层：特征级与级联

把混合再往模型内部推一层：

### 特征组合（Feature Combination）

把 CF 的「协同信号」当作**特征**喂给内容模型。例如给 CB 模型增加「看过同一物品的其他用户还喜欢什么」这类特征，让内容模型自己学出协同信号的价值。这不再需要两个模型，而是一个模型、两组特征——现代深度学习排序模型（第六篇的 Wide & Deep、DeepFM）骨子里就是这种思路：**Wide 侧塞协同记忆，Deep 侧塞内容泛化**。

### 级联（Cascade）

**用第一个模型做粗筛，第二个模型在幸存者里精排。** 例如先用 CB 召回一批「用户可能感兴趣」的候选（保住新物品），再用 CF 模型精排（保证排序质量）。级联的本质是**把两种算法的职责按阶段切分**——它不是平分秋色，而是「一个负责海选，一个负责精判」。

### 元级（Meta-level）

把一种算法的**输出模型**作为另一种算法的输入。最经典的是：先用 LFM/矩阵分解学出物品的隐因子向量，再把**隐向量当物品特征**喂给内容模型——这是「把协同信号蒸馏进内容表示」，也是第五篇双塔模型的前身。<span class="marginnote">元级混合最有想象空间：<strong>协同过滤不再只是「打分来源」，而是「特征来源」</strong>。矩阵分解学出的 Embedding，本质上就是物品的「协同画像」，把它与内容画像拼接，就是多模态表征的雏形，见第四级《多模态学习》。</span>

## 4 公式解析：归一化加权融合

把第 2 节的加权式写完整，关键在于**分数归一化**。设 CF 与 CB 对同一批候选各自算出原始分数，先用 min-max 映射到 $[0,1]$：

$$
\tilde{r}^{\text{CF}}_{ui} = \frac{r^{\text{CF}}_{ui} - \min_k r^{\text{CF}}_{uk}}{\max_k r^{\text{CF}}_{uk} - \min_k r^{\text{CF}}_{uk}}, \qquad \tilde{r}^{\text{CB}}_{ui} = \frac{r^{\text{CB}}_{ui} - \min_k r^{\text{CB}}_{uk}}{\max_k r^{\text{CB}}_{uk} - \min_k r^{\text{CB}}_{uk}}
$$

再做加权：

$$
\hat{r}_{ui} = \lambda\, \tilde{r}^{\text{CF}}_{ui} + (1-\lambda)\, \tilde{r}^{\text{CB}}_{ui}
$$

四步拆解：

- **第一步，为什么用 min-max**：它把任意尺度的分数线性压到 $[0,1]$，且保留同一算法内部的相对大小。注意分母用的是**同一批候选里的极差**，所以归一化是「每批请求内」做的——这保证了两路分数可比。
- **第二步，归一化的副作用**：min-max 对**离群值敏感**。一个 CF 分数飙到 100 的异常物品会把其余全部压到接近 0，相当于把「异常点」抬成了满分。稳健的做法是截断（clamp）后再归一化，或用 rank 归一化（把分数换成其在候选中的排名比例）。
- **第三步，权重 $\lambda$ 的语义**：$\lambda$ 不是「CF 比 CB 重要多少」，而是「这一批候选里，我更信任哪一路信号」。$\lambda = 0.7$ 意味着排序主要跟着 CF 走，CB 只做微调。
- **第四步，上限检查**：$\lambda \in [0,1]$ 时，$\hat{r}_{ui} \in [0,1]$，与单路阈值、多样性重排（第十一篇 MMR）都能无缝衔接——**归一化的一个隐藏收益是让下游模块的假设统一了**。

一个数字例子。某候选的 CF 原始分 2.0（批内 $[\ 0, 5\ ]$）、CB 原始分 0.6（批内 $[\ 0.1, 0.8\ ]$）：

$$
\tilde{r}^{\text{CF}} = \frac{2.0 - 0}{5 - 0} = 0.4, \qquad \tilde{r}^{\text{CB}} = \frac{0.6 - 0.1}{0.8 - 0.1} \approx 0.71
$$

取 $\lambda = 0.5$，得 $\hat{r} = 0.5 \times 0.4 + 0.5 \times 0.71 = 0.56$。若不做归一化直接加权，CF 的 2.0 会把 CB 的 0.6 完全淹没——**归一化前后，排序结果可能天差地别**。

## 5 工业界的正解：分层混合

论文里的七种方式到了工业界，收敛成一句话：**在不同的架构层，用不同的混合方式。**

- **召回层**：多路召回同时跑 CF 路、CB 路、热门路、向量路，各路独立产出候选，**合并去重**——这是「加权式」在大规模下的变体（各路的分数先归一化再融合），也是第五篇的主题。
- **排序层**：把 CF 信号与内容特征**一起喂给一个模型**（特征组合式），模型自己学权重，不再手工调 $\lambda$。
- **解释层**：CB 负责给推荐写「因为你看过……」的理由，CF 负责保证「别人也喜欢」的多样性——**混合的最后一步是混合「叙事」**，让推荐既准又可信。<span class="marginnote">为什么分层是最优解？因为每一层的时间预算不同：召回层要扛住毫秒级海选，只能跑轻量模型；排序层时间预算宽裕，可以跑重模型。把复杂的混合逻辑全塞进一层，会撞上延迟天花板。</span>

## 6 代码：一个最小加权混合推荐

```python
def min_max(r, lo, hi):
    """把原始分 r 线性归一化到 [0, 1]，lo/hi 为该路的批内边界。"""
    return (r - lo) / (hi - lo)

def hybrid_score(u, i, lam=0.5):
    """最小加权混合：CF 与 CB 分数先归一化再线性加权。"""
    r_cf = min_max(cf_scorer(u, i), 0.0, 5.0)    # CF 原始分域 [0, 5]
    r_cb = min_max(cb_scorer(u, i), 0.1, 0.8)    # CB 原始分域 [0.1, 0.8]
    return lam * r_cf + (1 - lam) * r_cb
```

## 7 小结

- 混合的动机是**错误互补**：CF 缺数据时 CB 恰好只要属性，CB 窄化时 CF 恰好会跨类目。
- 混合方式分层级：**输出级**（加权式、切换式）、**特征/模型级**（特征组合、级联、元级）。
- 加权混合前**必须归一化**分数，否则尺度大的算法喧宾夺主；min-max 对离群值敏感，必要时用 rank 归一化。
- 工业界正解是**分层混合**：召回层多路并集、排序层特征融合、解释层叙事混合。
- 混合是推荐系统的「组合拳」：**没有万能算法，只有把对的方法放到对的层**。
