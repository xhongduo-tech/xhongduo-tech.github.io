## 为什么从用户兴趣建模开始

前三篇我们准备好了三块积木：物品画像（把物品变成向量）、TF-IDF（把文本变成可算的向量）、词向量与物品 Embedding（把「意思」变成稠密坐标）。但推荐系统真正要回答的问题是**用户**：他到底喜欢什么？怎么把他的历史行为翻译成一个能打分的向量？

这一篇把内容推荐组装成完整的算法。核心有两个动作：**建用户兴趣模型**（从历史行为算出 $\vec{u}$）与**相似度匹配**（用 $\vec{u}$ 给候选物品打分）。同时我们会诚实面对内容推荐的两个面孔——**它擅长冷启动与可解释，却也自带「过度窄化」的先天病**。<span class="marginnote">用户兴趣建模是内容推荐的分水岭：做得粗，就是「你看过什么我再推什么」的复读机；做得细，才能跟上兴趣漂移、抓住多面兴趣。这一篇的「细」，正是后续深度模型（DIN、DIEN、MIND）想用网络学出来的东西。</span>

## 1 用户兴趣建模的三层递进

上一篇的用户画像是最朴素的等权平均。真实系统里，兴趣建模至少要跨过三个台阶：

**第一层：简单平均。** $\vec{u} = \frac{1}{\lvert H_u \rvert}\sum_{i \in H_u}\vec{i}$。把用户所有历史物品的画像求平均。问题显而易见：三年前追的言情剧和今天看的纪录片，权重一模一样。

**第二层：加权聚合。** 给不同物品不同的权重 $w_{ui}$——评分高的、行为强的（买 > 收藏 > 点击 > 曝光）权重更大。上一篇已展开，这一篇直接沿用。

**第三层：时间衰减。** 兴趣会**漂移（interest drift）**。用户的电影品味、购物需求都随时间变化，三年前的消费行为对今天的参考价值应当递减。于是给每个历史物品乘以一个随时间衰减的系数：

$$
w_{ui}(t) = \alpha^{\,t_{\text{now}} - t_i}, \qquad 0 < \alpha < 1
$$

其中 $t_i$ 是用户与物品 $i$ 交互的时间，$\alpha$ 是**衰减因子**。$\alpha$ 越接近 1，衰减越慢（长记忆）；$\alpha$ 越小，衰减越快（短记忆）。<span class="marginnote">时间衰减与第二级《概率论与数理统计》里的「指数平滑」、以及强化学习里的「折扣因子 $\gamma$」是同一种直觉：<strong>未来的价值要打折，过去的信号要折价</strong>。$\alpha$ 的取值是业务超参数——卖场推荐 $\alpha$ 取小值（今天买什么比上周重要），影音推荐可稍大。</span>

**辨析｜易错点：** 时间衰减不只是「给排序当权重重排一下」那么简单——**它同时改变了用户画像向量的方向**。把三年前的旧口味降权，$\vec{u}$ 会整体偏向近期兴趣，于是余弦匹配的候选集也跟着换了风格。所以衰减因子的效果要放在「画像构建」这一步验证，而不是只盯着排序分数看。

## 2 相似度匹配：结构化与文本特征的各自打法

用户画像和物品画像都齐了，最后一步是匹配。**匹配用什么相似度，取决于特征的类型**：

**文本特征（稠密向量）**：用**余弦相似度**。词向量、TF-IDF 向量都在高维空间里，余弦只关心方向、对尺度不敏感，是最稳的选择。<span class="marginnote">这正是第二篇《相似度计算》里余弦的主角地位：<strong>余弦适合「连续、稠密、方向有意义」的向量</strong>；而 TF-IDF 这种稀疏向量是否要加平滑、要不要按维度加权，属于特征工程细节。</span>
- **结构化特征（稀疏标签）**：用 **Jaccard 相似度**。两个物品共有的标签数除以总标签数，对「有没有」这类二元属性最自然。
- **混合特征**：把两类相似度分开算，再加权求和：$\text{sim}(u, i) = \lambda \cos(\vec{u}^{\text{文本}}, \vec{i}^{\text{文本}}) + (1-\lambda)\, \text{Jaccard}(u^{\text{标签}}, i^{\text{标签}})$。$\lambda$ 控制两类特征的信任比例。

**重点：** 相似度选择的原则是「**向量长什么样，就用对应的度量**」。在第二篇里我们分别学过余弦、皮尔逊与 Jaccard，这一篇就是它们的第一次分工：稠密向量归余弦，稀疏标签归 Jaccard。

## 3 公式解析：时间衰减加权画像与余弦打分

把三层建模与匹配写进同一条链路。用户的当前画像为：

$$
\vec{u} = \frac{\sum_{i \in H_u} \alpha^{\,t_{\text{now}} - t_i}\, w_i\, \vec{i}}{\sum_{i \in H_u} \alpha^{\,t_{\text{now}} - t_i}\, w_i}
$$

候选物品 $i$ 的打分就是：

$$
\hat{r}_{ui} = \cos(\vec{u}, \vec{i}) = \frac{\vec{u} \cdot \vec{i}}{\lVert \vec{u} \rVert \; \lVert \vec{i} \rVert}
$$

对画像公式做四步拆解：

- **第一步，看分子里的每一项 $\alpha^{t_{\text{now}}-t_i} w_i \vec{i}$**：历史物品 $\vec{i}$ 先乘以行为权重 $w_i$，再乘以时间衰减 $\alpha^{t_{\text{now}}-t_i}$。$t_{\text{now}}-t_i$ 越大（交互越久远），$\alpha$ 的幂次越高、贡献越小——**旧信号指数级退场**。
- **第二步，看分母**：把所有历史物品的「有效权重」求和。分子除以分母后，$\vec{u}$ 是历史物品向量的**加权质心**——权重越大的物品，把质心拉得越近。
- **第三步，看 $w_i$ 与衰减的分工**：$w_i$ 编码「**行为多强**」（点击还是购买），衰减编码「**行为多老**」。强而新的信号双重放大，弱而旧的信号双重折价——这正是直觉上「用户现在想要什么」。
- **第四步，看余弦打分**：$\hat{r}_{ui}$ 是 $\vec{u}$ 与 $\vec{i}$ 的方向余弦。全部候选算一遍、按分数取 Top-N，就是最终的推荐。**整套公式里没有任何其他用户的数据——这是内容推荐「新物品可推」的底气。**

用一个数字例子把衰减算出来。设 $\alpha = 0.9$，今天用户的历史里有两部电影：一周前（$t_{\text{now}}-t_1 = 1$）看完的《银翼杀手》，向量 $\vec{i}_1 = (0.9, 0.1, 0.5)$，行为权重 $w_1 = 1$（看过）；一年前（$t_{\text{now}}-t_2 = 52$，按周算）的《变形金刚》，$\vec{i}_2 = (0.1, 0.9, 0.2)$，$w_2 = 1$：

$$
\vec{u} = \frac{0.9^1 (0.9, 0.1, 0.5) + 0.9^{52}(0.1, 0.9, 0.2)}{0.9^1 + 0.9^{52}} \approx \frac{(0.81, 0.09, 0.45) + (0.0004, 0.0036, 0.0008)}{0.9 + 0.0004} \approx (0.90, 0.10, 0.50)
$$

一年前的《变形金刚》贡献被压到千分之几，几乎不影响画像——**用户的画像几乎完全由近期兴趣塑造**。若不加衰减，两个向量等权平均会得到 $(0.50, 0.50, 0.35)$，一个「什么都沾一点」的中庸向量，推荐就会在科幻与爆米花之间摇摆。

## 4 完整算法：从历史到 Top-N

把上面的公式组装成可运行的推荐流程：

```python
def recommend(history, items, alpha=0.9, k=10):
    """基于内容推荐：历史行为 → 加权质心画像 → 余弦打分 → Top-N。"""
    profile = zero_vector(); w_sum = 0.0
    for t_i, w_i, v_i in history:            # (距今天数, 行为权重, 物品向量)
        decay = alpha ** t_i                 # 时间衰减：旧信号指数级退场
        profile += decay * w_i * v_i         # 增量累加，无需重新求和
        w_sum  += decay * w_i
    profile /= w_sum                         # 用户画像 = 历史物品的加权质心
    scored = [(cosine(profile, v), item) for item, v in items]
    return [item for _, item in sorted(scored, reverse=True)[:k]]
```

这个流程在线上有一个明确的成本结构：**用户画像的更新是增量的**（来一条新行为就 $\vec{u} \mathrel{+}= \text{decay} \cdot w \cdot \vec{i}$），而候选打分是一个**向量批量运算**，配合第五篇的向量检索可以做到毫秒级。<span class="marginnote">注意用户画像的更新是「加权和」而非「重新求和」——<strong>增量更新的设计让在线实时推荐成为可能</strong>，这与第十二篇《特征平台》里「特征要能增量计算」的工程约束是一致的。</span>

## 5 内容推荐的优势：冷启动与可解释

内容推荐被冷启动困局逼上场，它的长处也恰好在冷启动两端兑现：

**新物品冷启动**：物品一上线就有属性、有文本，画像立即可建，**不需要等任何用户行为**。这与第三篇 MF「无交互无向量」的窘境形成最鲜明的对照。
**解释自然**：「推荐《沙丘》是因为你看过《银翼杀手》」——内容推荐的解释来自物品画像本身，不需要事后编造。可解释性对信任与留存的价值，我们在第一篇就强调过。
**隐私友好**：纯内容推荐只用「这个用户自己」的数据，不依赖其他用户的集体行为——这在隐私合规收紧的今天格外重要。<span class="marginnote">这一点在第十四篇《LLM 与推荐》会再次放大：<strong>当模型不再需要「别人看过什么」也能给出好推荐时，隐私与体验的矛盾就有了缓解空间</strong>。</span>

## 6 内容推荐的局限：过度窄化与惊喜度缺失

内容推荐有一道绕不开的墙，学界叫它**过度窄化（overspecialization）**：

- **只推同类**：用户只看过科幻，模型就只推科幻——向量越「像」，越被困在同类目里。
- **惊喜度趋零**：回头看第一篇《超越准确性》，内容推荐在准确率上可能漂亮，在**多样性、新颖性、惊喜度（serendipity）**上全面垫底。它永远顺着已知兴趣走，几乎不会「跨界」给你推一部从未接触过的纪录片。
- **信息茧房**：长此以往，用户的视野被算法固化成单一兴趣的回音室——这正是「推荐系统要负责任」的伦理起点。

**辨析｜易错点：** 不要误以为「提高相似度阈值」能解决窄化——恰恰相反，**相似度阈值越高，推荐越窄**。真正的缓解手段是主动引入「不相似」的候选：随机探索一小部分流量、对类目做多样性约束（第十一篇 MMR、DPP 就是干这个的），以及——最重要的——**与协同过滤混合**，让「集体智慧」把用户推出舒适区。

## 7 小结

- **用户兴趣建模三层递进**：简单平均 → 行为加权 → **时间衰减**；衰减因子 $\alpha$ 让旧信号指数级退场，反映兴趣漂移。
- **匹配度量按特征分家**：稠密文本向量用**余弦**，稀疏标签用 **Jaccard**，混合特征加权求和。
- **打分链路**：$\vec{u} = \dfrac{\sum \alpha^{\Delta t} w_i \vec{i}}{\sum \alpha^{\Delta t} w_i}$，再 $\hat{r}_{ui} = \cos(\vec{u}, \vec{i})$，Top-N 输出；用户画像可增量更新，支撑在线实时推荐。
- **优势**：新物品冷启动、可解释、隐私友好。
- **局限**：过度窄化、惊喜度缺失、易成信息茧房；单向量模型还抹掉了多面兴趣。
- 单一内容推荐扛不住全部场景——**把内容与协同过滤结合，是第四篇的收官命题**。
