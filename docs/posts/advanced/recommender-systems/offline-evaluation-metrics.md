## 为什么从评估指标开始

上一节我们讲了三种实验方法，离线实验被当作最便宜的第一道筛子。可离线实验做完了，拿什么数字来「打分」？这就轮到评估指标登场。**评估指标是把「算法好不好」这个模糊问题翻译成「具体数字」的翻译官**——没有它，离线实验只是一堆没有结论的运行。

项亮在书中把离线评估指标分为两大族，对应推荐系统的两种输出形态：**评分预测**与 **Top-N 推荐**。<span class="marginnote">这两族的差别本质上是「系统输出什么」的差别：评分预测输出一个具体的分数（如 4.2 分），Top-N 推荐输出一个有序列表（如推荐 10 部电影）。评分预测是回归问题，Top-N 推荐是排序问题——评估方式自然不同。</span>这一篇就把两族的代表指标逐一算透：RMSE、MAE、准确率（Precision）、召回率（Recall），并回答那个贯穿始终的问题——**这些数字到底在度量什么？**

## 1 评分预测指标：RMSE 与 MAE

当推荐系统的输出是「预测评分」时，我们需要比较预测值 $\hat{r}_{ui}$ 与真实评分 $r_{ui}$ 的差距。设测试集为 $T$（一组「用户—物品—真实评分」三元组），两个最经典的指标是：

$$
\mathrm{RMSE} = \sqrt{\frac{1}{|T|} \sum_{(u,i) \in T} (r_{ui} - \hat{r}_{ui})^2}, \qquad
\mathrm{MAE} = \frac{1}{|T|} \sum_{(u,i) \in T} \left| r_{ui} - \hat{r}_{ui} \right|
$$

**RMSE（均方根误差，root mean squared error）** 先把每个误差平方、求平均、再开方；**MAE（平均绝对误差，mean absolute error）** 直接对误差取绝对值再平均。两者都衡量「预测离真实有多远」，值越小越好，但它们的性格不同：<span class="marginnote">为什么同一个数据集上总是 RMSE ≥ MAE？因为平方会让大误差被放大——这是「凸函数的琴生不等式」在起作用，也正因如此，RMSE 对「离谱的预测」更敏感。项亮在书中明确说：RMSE 对预测不准的惩罚更大，因此对系统的「不可靠预测」更为敏感。</span>

用一组真实数字感受。设真实评分 $[5, 3, 4, 2]$，某模型预测 $[4, 3, 5, 2]$，则误差是 $[1, 0, -1, 0]$。MAE $= (1+0+1+0)/4 = 0.5$；RMSE $= \sqrt{(1+0+1+0)/4} = \sqrt{0.5} \approx 0.707$。同样的数据，RMSE 比 MAE 大——**平方把「猜错 1 分」变成了更重的罪过**。这一点在需要容忍少数「大错误」还是惩罚「任何错误」的场景里，会直接影响你该选哪个指标。

## 2 Top-N 推荐指标：准确率与召回率

评分预测很直观，但项亮特别提醒：**用户使用推荐系统时，看的不是「评分」而是「列表」**——用户打开 App 看到的永远是「给你推荐的 10 个东西」，而不是一排预测分数。所以工业界更常用的评估视角是 Top-N 推荐。

给定用户 $u$，设 $R(u)$ 是系统给他推荐的 Top-N 物品列表，$T(u)$ 是测试集中 $u$ 真正有过行为（即「相关」）的物品集合。定义：

$$
\mathrm{Precision} = \frac{|R(u) \cap T(u)|}{|R(u)|}, \qquad
\mathrm{Recall} = \frac{|R(u) \cap T(u)|}{|T(u)|}
$$

**准确率（Precision）**：推荐的 N 个物品里，有多少是用户真正相关的——**测的是「推荐得对不对」**。**召回率（Recall）**：用户真正相关的物品里，有多少被我们推荐出来了——**测的是「该推的是否都推了」**。<span class="marginnote">两个指标天然互斥：把推荐列表拉到无穷长，召回率一定趋近 1（相关的全被覆盖），但准确率会被大量垃圾冲垮；反之只推最热门的一件，准确率可能很高，召回率却极低。真实系统在这两者之间用 N 和阈值做权衡，画出 precision–recall 曲线。</span>

这里有两个关键细节。第一，**分子是同一个集合 $R(u) \cap T(u)$**，两指标共享同一个分子，区别只在分母。第二，这两个指标按**用户**计算——实际评测时通常先对每个用户算 precision、recall，再对全体用户取平均（所谓 macro 平均），得到全局的评估值。

## 3 混淆矩阵：四个格子讲清一切

准确率与召回率的分子分母看起来很绕，但把它们放进**混淆矩阵（confusion matrix）**，一切一目了然。把「系统是否推荐了」当作预测，把「用户是否相关」当作真实，一个用户—物品对落入四种结局之一：

![混淆矩阵：二分类预测的四种结局](/images/recommender-systems/offline-evaluation-metrics-1.svg)

从图里可以直接读出两个指标的几何意义：**准确率是「第一列」里的命中比例**——预测为正的一列中，TP 占了多大比重；**召回率是「第一行」里的命中比例**——真实为正的一行中，TP 占了多大比重。两个指标都用同一个 TP 做分子，区别只在分母——一个数 FP（误报），一个数 FN（漏报）。

**辨析｜易错点：** 把「准确率」和「正确率」混为一谈是新手最常见的错误。分类问题里常说的 accuracy（正确率）$= (TP + TN)/(TP + FP + FN + TN)$，四个格子全用上；而推荐系统里的 precision（准确率）只用第一列，根本不管 TN。**两者名字相近、含义完全不同**。在一个 99% 都是「不相关」的场景里，一个什么都不推的系统 accuracy 高达 99%，precision 却是 0——这正是为什么推荐系统几乎不用 accuracy，而用 precision 与 recall。

## 4 公式解析：一个数值例子走完两族指标

把两族指标放进一个完整的小例子，一次算清。设某用户在测试集中的相关物品是

$$
T(u) = \{a, b, c\}
$$

系统给出的 Top-5 推荐列表是

$$
R(u) = [a, d, e, b, f]
$$

**第一步，求交集**：$R(u) \cap T(u) = \{a, b\}$，命中数 $= 2$。这是所有计算共用的分子。

**第二步，算准确率**：分母是推荐列表长度 $|R(u)| = 5$，所以 $\mathrm{Precision} = 2 / 5 = 0.4$。含义：系统推荐的 5 件物品里，有 40% 是用户真正相关的。

**第三步，算召回率**：分母是相关集合大小 $|T(u)| = 3$，所以 $\mathrm{Recall} = 2 / 3 \approx 0.667$。含义：用户真正相关的 3 件物品里，有 2/3 被系统找了出来。

**第四步，感受二者的此消彼长**：若把推荐列表砍短成 $R'(u) = [a, d]$，则 Precision 升到 $1/2 = 0.5$，Recall 跌到 $1/3 \approx 0.333$——**列表越短，越「精」但越「漏」**。若拉长到 $R''(u) = [a, d, e, b, f, g, h, c, i, j]$，则 Recall 升到 $3/10$ 相关命中 3 → Recall $= 3/3 = 1.0$，Precision 跌到 $3/10 = 0.3$。<span class="marginnote">这就是推荐列表长度 $N$ 的杠杆作用：N 是准确率与召回率之间唯一的旋钮。项亮建议在实际评测中「选择不同的推荐列表长度 N，画出准确率 / 召回率曲线」，观察系统在整个 N 范围内的表现，而不是只看一个点。</span>

评分预测的例子前面已经算过：真值 $[5,3,4,2]$、预测 $[4,3,5,2]$ 时 RMSE $\approx 0.707$、MAE $= 0.5$。两族指标放在一起看，逻辑是同一个：**定义误差或命中，再对全体测试样本取平均。**

## 5 用代码算一遍

上面的例子可以用一段小代码直接跑通（这段代码可直接运行）：

```python
def precision_recall(recommended, relevant):
    """输入：推荐列表、相关物品集合；输出：(Precision, Recall)。"""
    hits = len(set(recommended) & set(relevant))
    return hits / len(recommended), hits / len(relevant)

recommended = ['a', 'd', 'e', 'b', 'f']   # Top-5 推荐
relevant    = {'a', 'b', 'c'}              # 测试集中真实相关的物品
p, r = precision_recall(recommended, relevant)
print(f"Precision = {p:.3f}, Recall = {r:.3f}")
# 输出约为：Precision = 0.400, Recall = 0.667

def rmse_mae(true, pred):
    """输入：真实评分与预测评分两个列表；输出：(RMSE, MAE)。"""
    n = len(true)
    mae = sum(abs(t - p) for t, p in zip(true, pred)) / n
    rmse = (sum((t - p) ** 2 for t, p in zip(true, pred)) / n) ** 0.5
    return rmse, mae

rmse, mae = rmse_mae([5, 3, 4, 2], [4, 3, 5, 2])
print(f"RMSE = {rmse:.3f}, MAE = {mae:.3f}")
# 输出约为：RMSE = 0.707, MAE = 0.500
```

注意 precision/recall 与 RMSE/MAE 处理的对象不同：前者面对的是**集合**（相关与否），后者面对的是**实数**（评分高低）。别把两族代码混在一起用。

## 6 指标选择：评分还是排序？

两族指标各服务一种输出形态，选哪个取决于你的产品形态与优化目标：

| 维度 | 评分预测（RMSE / MAE） | Top-N 推荐（Precision / Recall） |
| --- | --- | --- |
| 输出形态 | 一个预测分数 | 一个有序列表 |
| 对应问题 | 回归 | 排序 |
| 用户视角 | 用户很少直接看评分 | 用户只看列表 |
| 对误差的态度 | 数值偏差都算错 | 只关心是否「命中」 |
| 数据要求 | 需要真实评分 | 只需行为记录 |

**辨析｜易错点：** 有两个陷阱值得单独点出。其一，**评分指标不能度量排序质量**——两个模型把评分分别从 4.0 改成 4.2 和 3.8，RMSE 一样，可前者把物品排到了更前面，用户感知完全不同。其二，**离线指标不等于用户满意度**——项亮在书中反复强调，预测准确度只是「用户满意度」的一个组成部分；一个预测极准的系统，可能因为推荐的都是用户已知的东西而让用户觉得「没意思」。后一种「惊喜度」「多样性」等指标，正是本专题第一篇规划里「超越准确性」那一节的内容。

这些指标还有一个共同的重要属性：**它们都作用于「一个用户」再取平均**。把每个用户当作独立个体分别度量，避免了「热门用户淹没长尾用户」的偏差——这与「从极限到大模型」主线里评估模型的思路一脉相承：**不看总量，看个体上的一致表现。**

## 7 小结

- **两族指标**对应两种输出：评分预测用 RMSE / MAE（回归），Top-N 推荐用 Precision / Recall（排序）。
- **RMSE 与 MAE** 都度量「预测离真实多远」，但 RMSE 因平方对离谱误差惩罚更狠，且总是 RMSE ≥ MAE。
- **Precision = 命中数 / 推荐数**，**Recall = 命中数 / 相关总数**；两者共享同一个分子，分母不同，天然此消彼长。
- **混淆矩阵**把四种结局 TP / FP / FN / TN 摆进 2×2 表格：Precision 怕误报（FP），Recall 怕漏报（FN）；别与分类的 accuracy（正确率）混淆。
- **列表长度 N** 是准确率与召回率之间的旋钮，应画整条 P–R 曲线而非只看单点。
- 离线指标只是「用户满意度」的一部分，惊喜度、多样性等维度要另算。
