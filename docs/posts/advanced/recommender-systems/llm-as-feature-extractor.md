## 为什么从 LLM 特征提取器开始

上一节说了范式演进，现在看大模型在推荐里「最轻、最稳」的一种落地：**用 LLM 的文本理解能力，把物品/用户的内容编码成语义表示，作为特征喂给现有推荐模型**。这条路不改变推荐链路，只升级「表示」——风险小、收益直接。<span class="marginnote">LLM 在推荐里扮演多种角色（直接推荐、生成检索、解释生成），而「特征提取器」是侵入性最小的一种：经典 CTR/召回模型照跑，只是物品 embedding 从「ID 或浅层文本向量」升级成「LLM 的语义向量」。</span>

这一节讲 LLM 特征提取的三种形态：**物品内容表示、用户内容表示、以及「文本辅助特征」**。

## 1 物品表示：从 ID embedding 到语义 embedding

经典推荐里物品 $i$ 的表示靠 ID embedding（行为驱动）。LLM 特征提取的做法是：**把物品的内容（标题、描述、评论）输入 LLM 编码器，输出一个语义向量**：

$$
\mathbf{v}_i^{\text{sem}} = \text{LLM}_e(\text{title}_i, \text{description}_i, \text{tags}_i, \dots)
$$

$\text{LLM}_e$ 是文本编码器（如 Sentence-BERT、text-embedding 系列）。这个语义向量可以：

- **直接当物品 embedding**：进双塔召回（[[two-tower-model-vector-recall]]）、进排序模型（[[deepfm]]）。
- **与 ID embedding 拼接/加权**：向量拼接（concatenation）或加权和，让模型同时用「记忆」与「理解」。

**核心收益**：新物品无需行为即有语义向量，冷启动被结构性缓解（见 [[recommender-paradigm-evolution-id-to-semantic]]）。

## 2 用户表示：把「历史行为」翻译成语义画像

用户的兴趣同样可以语义化：把用户的历史行为「翻译」成一段语义描述，再编码成用户向量。

例如：用户最近点过「咖啡烘焙教程」「手冲壶测评」「精品豆购买」，LLM 可以生成一句「用户近期对精品咖啡冲煮感兴趣」，编码成用户语义向量 $\mathbf{u}^{\text{sem}}$：

$$
\mathbf{u}^{\text{sem}} = \text{LLM}_e\left( \text{summarize}(\text{history}_u) \right)
$$

**语义用户画像 vs ID 用户向量的差异**：ID 向量只表达「这位用户的行为模式」，语义向量表达「这位用户感兴趣的内容主题」——**后者可直接与物品语义匹配，泛化到没见过的物品**。

## 3 文本辅助特征：让经典模型「读懂」内容

除了表示升级，LLM 还能产出「结构化辅助特征」，喂给经典模型：

- **类目与标签的补全**：新物品没有人工标注，LLM 自动给出类目、关键词、主题标签。
- **内容摘要与属性抽取**：从标题/正文抽出「品牌」「人群」「卖点」等结构化字段。
- **兴趣标签生成**：把用户行为概括成兴趣词（「咖啡」「露营」「极简家居」）。

这些「文本辅助特征」进入特征平台（见 [[feature-platform-offline-online-consistency]]），与原始特征一起喂给排序模型——**LLM 相当于一个「自动标注员 + 特征工厂」**。

## 4 公式解析：语义向量如何进入推荐打分

把「LLM 特征提取」接入推荐打分拆三步：

- **第一步，表示融合**：物品表示 = ID embedding 与语义 embedding 的融合：

$$
\mathbf{v}_i = \lambda \, \mathbf{e}_{\text{id}(i)} + (1 - \lambda) \, \mathbf{v}_i^{\text{sem}}
$$

$\lambda$ 控制「记忆 vs 理解」的权重——**ID 保「用户对特定物品的行为记忆」，语义保「对内容主题的理解」**，两者互补。
- **第二步，匹配打分**：$\text{score}(u, i) = \langle \mathbf{u}, \mathbf{v}_i \rangle$（双塔）或进深度排序网络。**语义向量让「没见过的新物品」也能被「语义相似」地匹配**。
- **第三步，离线编码 + 在线缓存**：语义编码是 LLM 前向，成本高——**物品语义向量离线算好、存库，在线只查表**；用户语义向量可随行为更新做「低频重算 + 缓存」。这是「LLM 进推荐」的工程关键。

## 5 收益与注意

**收益**：

- 冷启动结构性改善：新物品/新用户上线即有语义表示。
- 跨领域泛化：语义向量让「不同场景但内容相似」的物品互相迁移。
- 可解释：语义向量可映射回「文字」，解释「为什么推这个」。

**注意**：

- **语义 ≠ 偏好**：语义相似的物品用户未必都喜欢——语义向量必须与「行为信号」结合，不能单独当用户兴趣。
- **编码成本**：全量物品离线编码是大工程（亿级 × LLM 前向），要规划算力与缓存。
- **语义漂移**：LLM 版本升级会导致语义向量分布变化，影响线上一致性——需「版本化 + 重算」管理。

## 辨析｜LLM 语义向量的「三个工程陷阱」

LLM 特征提取器看起来「把文本过一遍编码器就行」，但工程上有三个陷阱会让「语义增强」翻车：

**陷阱一：语义向量与「行为向量」的空间错位。** LLM 的语义 embedding 是在「通用语料」上训练的，而推荐的行为 embedding 是在「你平台的点击数据」上训练的——**两者所在的向量空间「坐标系不同」**。直接把语义向量与行为向量「拼接或加权」，可能不是「互补」，而是「两套坐标系打架」。**解法**：在「推荐数据」上「对齐/微调」语义编码器（把语义向量向行为空间校准），或把语义向量当作「输入特征」而非「最终向量」，让下游模型自己学「怎么用」。

**陷阱二：语义向量的「粒度」与「任务」不匹配。** 文本编码器有「句向量」「词向量」「分类向量」等多种输出，粒度不同。**物品的「类目」用粗粒度、用户的「精细兴趣」用细粒度**——用错粒度，语义信号要么「太泛」（类目都对，但分不出喜好）要么「太碎」（细节都对，但抓不住主题）。**上线前要验证「哪个粒度对推荐指标增益最大」**。

**陷阱三：LLM 版本升级的「语义漂移」。** LLM 一升级，同一段文本的 embedding 分布就变了——**已经缓存的「物品语义向量」与「新版本算出的」不一致**，模型在线表现可能突变。**解法**：语义向量要「版本化」——缓存带「LLM 版本号」，升级时「全量重算 + 灰度切换」，避免「新旧向量混用」。

**一个评估提醒**：语义增强的收益要在「行为数据不足」的场景里验证（冷启动、长尾）——**行为数据充足的头部物品，语义向量的增益通常有限**。别用「头部物品的指标」判断「语义增强有没有用」。

## 6 小结

- **LLM 特征提取器**是大模型进推荐「最轻、最稳」的落地：升级表示，不改链路。
- 三种形态：**物品语义表示、用户语义画像、文本辅助特征**。
- 融合方式 $\mathbf{v}_i = \lambda \mathbf{e}_{\text{id}} + (1-\lambda)\mathbf{v}^{\text{sem}}$：**ID 保记忆、语义补理解**。
- 工程关键是「离线编码 + 在线缓存」；注意「语义≠偏好」与编码成本。
- **评估提醒**：语义增强的收益在冷启动与长尾最明显，别用头部物品指标判断有没有用。

**术语速查**：

| 术语 | 一句话 |
| --- | --- |
| 语义向量 | LLM 编码器输出的物品/用户内容表示 |
| 语义画像 | 把历史行为翻译成兴趣主题的向量 |
| 文本辅助特征 | LLM 产出的类目/标签/摘要结构化字段 |
| 表示融合 | ID embedding 与语义 embedding 的加权混合 |
| 语义漂移 | LLM 版本升级导致向量分布变化 |

**一个数值对照**：设 $\lambda = 0.5$，物品的 ID 与语义向量各贡献一半——头部物品（行为多）应让 ID 主导（$\lambda \to 1$），长尾/新物品（行为少）应让语义主导（$\lambda \to 0$）。**固定 $\lambda$ 是次优的：按「行为量」动态调节 $\lambda$，是语义增强里常被忽略却收益明显的优化**。

**一个落地提示**：语义向量「全量离线编码 + 增量补算 + 版本号缓存」是标准运维模式——全量亿级物品一次批处理需要可观的 LLM 算力，之后只对新物品做增量编码，并在升级 LLM 时全量重算灰度切换。

**一个心态**：LLM 特征提取器不是「革命」而是「升级」——它把「物品是什么」讲得更好，但「用户想要什么」仍要靠行为数据回答；把它当「表示增强」而非「推荐革命」，是最不容易翻车的定位。
