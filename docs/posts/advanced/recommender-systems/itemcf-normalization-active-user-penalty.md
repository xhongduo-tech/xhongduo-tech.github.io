## 为什么还需要两个补丁

上一篇的 ItemCF 已经能给出不错的推荐，但它还藏着两个「不公平」：

- **不同类目的物品，相似度天然不在一个量级**——电影和电影都「很像」，电影和书永远「不太像」，于是同类目永远霸榜，跨类目的好物品被饿死；
- **活跃用户让两个物品「假相似」**——一个书店老板把店里 80% 的书都标记为「想读」，任何两本书都会因为他的存在而「共现」。

这一篇把两个补丁讲透。它们与 IUF 一起，构成邻域方法的完整武器库<span class="marginnote">把三个补丁放到一起对比，是理解本章最后一块拼图的捷径，第 4 节有完整对照表。</span>。

## 1 补丁一：物品相似度的归一化

先看现象。设物品属于不同类目：i1、i2 是电影，b1、b2 是书籍。直觉上，类内相似度（$w_{i1,i2}$）普遍偏高，类间相似度（$w_{i1,b1}$）普遍偏低。如果直接按相似度排序推荐，**用户的推荐列表永远被同一类目霸占**，跨类目的惊喜无从谈起。

问题不在某个 $w_{ij}$ 算错了，而在**量纲不可比**——类内与类间相似度用同一把尺子量，但尺子的刻度密度不一样。

解药是按行归一化：把每个物品 $i$ 的相似度，除以它那一行的最大值：

$$
w_{ij}' = \frac{w_{ij}}{\max_{k} w_{ik}}
$$

**归一化做了什么？** 对每个物品 $i$，「最像 $i$ 的邻居」的相似度被拉到 1，其他邻居按比例缩放。这样，类目间的量纲差异被抹平——$i$ 的「最强电影邻居」与「最强书邻居」现在都落在 1 附近，**跨类目推荐不再被阈值和排序天然压制**。<span class="marginnote">项亮在书中报告：归一化在物品类目差异明显的数据集上，推荐质量提升更显著；对同类目占绝对主导的数据集，提升有限。这与「量纲差异越大，归一化收益越大」的直觉一致。</span>

**辨析｜易错点：** 归一化按**行**做，不是按列。物品相似度矩阵 $W$ 的第 $i$ 行是「$i$ 与其他所有物品的相似度」，归一化是对每行内部做相对化。如果你按列归一化，等于给「被 $i$ 相似的物品」做缩放，语义完全变了。

## 2 补丁二：惩罚活跃用户

归一化治的是「类目不可比」，活跃用户是另一个独立病灶。

设想一个经营书店的用户，把店里 80% 的书都标记为「想读」。他的行为给所有书都创造了「共现」，于是任意两本书都可能因为他的存在而显得相似。**一个用户的行为不该有这么大的话语权**——他的一次「想读」是随意的，而一个只标记过 3 本书的用户，每次标记都信息量巨大。

解药与 UserCF 的 IUF 完全对偶：给每个「共同用户」按其活跃度降权：

$$
w_{ij} = \frac{\sum_{u \in N(i) \cap N(j)} \frac{1}{\log(1 + |N(u)|)}}{\sqrt{|N(i)| \cdot |N(j)|}}
$$

$|N(u)|$ 是用户 $u$ 喜欢过的物品总数，即用户的活跃度。<span class="marginnote">注意结构上的对偶：IUF 里 $\frac{1}{\log(1+|N(i)|)}$ 惩罚的是「热门物品」（$|N(i)|$ 大），这里 $\frac{1}{\log(1+|N(u)|)}$ 惩罚的是「活跃用户」（$|N(u)|$ 大）。同一个对数函数，一个站在物品维度，一个站在用户维度。</span>

## 3 公式解析：活跃用户惩罚

四步拆解：

- **第一步，取共现用户集 $N(i)\cap N(j)$**：同时喜欢 $i$ 和 $j$ 的用户，是相似度的「票仓」。
- **第二步，逐用户降权** $\frac{1}{\log(1+|N(u)|)}$：用户越活跃，$|N(u)|$ 越大，这一票的权重越小。书店老板的票几乎被压没，只标记过 3 本书的用户的票几乎原样保留。
- **第三步，求和**：把降权后的票累加，得到「有效共现强度」——它比原始共现数更能反映真实的、非偶然的相似。
- **第四步，除以 $\sqrt{|N(i)||N(j)|}$**：分母保持不变，仍然抑制「单独就热」的物品。

**为什么分母不变？** 活跃用户惩罚针对的是「共现的来源」，而不是「物品自身的热度」。分母 $\sqrt{|N(i)||N(j)|}$ 已承担了热门物品的抑制，两者职责互补，不该混淆。

## 4 三个改进的一次性对照

把三个补丁放在一起看，很容易记混。它们各自治理一个病灶，作用对象各不相同：

| 补丁 | 作用对象 | 核心公式改动 | 对应问题 |
| --- | --- | --- | --- |
| IUF（UserCF 侧） | 热门物品 | 逐物品降权 1/log(1+物品热度) | 人人「变像」 |
| 活跃用户惩罚（ItemCF 侧） | 活跃用户 | 逐用户降权 1/log(1+用户活跃度) | 假相似 |
| 按行归一化（ItemCF 侧） | 相似度矩阵 | 每行除以行最大值 | 类目不可比 |

**辨析｜易错点：** IUF 与活跃用户惩罚虽然共享 $\frac{1}{\log(1+|\cdot|)}$ 的结构，但**一个在 UserCF 里、一个在 ItemCF 里**；一个降权热门物品、一个降权活跃用户。把「IUF 惩罚活跃用户」挂在嘴边是最常见的错误——IUF 的名字里有「用户频率」，指的却是「物品的热门程度」。

## 5 代码：两个补丁一起打

把归一化与活跃用户惩罚接进上一篇的 `item_similarity`：

```python
import math
from collections import defaultdict

def item_similarity_improved(train, penalty_active_user=True, normalize=True):
    C = defaultdict(float)      # 存降权后的共现贡献
    N_item = defaultdict(int)   # |N(i)|
    N_user = defaultdict(int)   # |N(u)|
    for u, items in train.items():
        N_user[u] = len(items)
        for i in items:
            N_item[i] += 1
            for j in items:
                if i != j:
                    # 活跃用户惩罚：每个共同用户 u 的票被降权
                    w = 1.0 / math.log(1 + N_user[u]) if penalty_active_user else 1.0
                    C[(i, j)] += w

    W = defaultdict(dict)
    for (i, j), cnt in C.items():
        W[i][j] = cnt / math.sqrt(N_item[i] * N_item[j])

    if normalize:
        # 按行归一化：除以该行最大值
        for i in W:
            mx = max(W[i].values())
            for j in W[i]:
                W[i][j] /= mx
    return W
```

归一化是**后处理**——它在相似度全部算完之后，对矩阵每行做一次缩放，因此可以独立开关；活跃用户惩罚则发生在**累加阶段**，改的是相似度定义本身。这种「先定义相似度、再后处理修正量纲」的两段式结构，与第三级《机器学习》里「先算特征、再对特征做缩放（feature scaling）」的思路如出一辙。

## 6 小结

- **归一化** $w_{ij}'=\frac{w_{ij}}{\max_k w_{ik}}$ 按行缩放，抹平类目间的量纲差异，让跨类目推荐不被天然压制。
- **活跃用户惩罚** $\sum_{u\in N(i)\cap N(j)} \frac{1}{\log(1+|N(u)|)}$ 给每个共同用户按其活跃度降权，书店老板式的「什么都买」不再污染相似度。
- 归一化是**后处理**，惩罚发生在**累加阶段**——两者可独立开关。
- 三个补丁的对照：IUF（惩罚热门物品）、活跃用户惩罚（惩罚活跃用户）、归一化（修正量纲），作用对象各不相同。
