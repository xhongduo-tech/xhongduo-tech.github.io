# FM（因子分解机）：稀疏数据下的二阶特征交互

## 为什么从 FM 开始

GBDT+LR 解决了「树自动交叉」，但树对高维稀疏的 ID 特征无能为力。而推荐系统的特征恰恰是海量稀疏的：用户 ID、物品 ID、类目——one-hot 之后绝大多数维度是 0。**FM（Factorization Machines，因子分解机）** 正是为这种数据而生的模型：它把「特征对（i, j）的交叉权重」参数化为两个向量内积，让稀疏数据也能学到可靠的高阶交互。<span class="marginnote">FM 与矩阵分解一脉相承：SVD 把「用户×物品」矩阵分解为两个低秩向量（见 [[funk-svd-matrix-factorization]]），FM 把这个思想推广到「任意特征对」上——用户特征 × 物品特征、用户特征 × 上下文特征、任意两两特征都可以分解。</span>

这一节讲 FM 的数学形式、它如何解决「交叉权重学不到」的稀疏困境、以及它的高效计算技巧。

## 1 问题的根源：稀疏数据下的交叉权重

先看朴素做法：把二阶交叉特征显式加进 LR，交叉项权重记为 $w_{ij}$：

$$
\hat{p} = \sigma\left(w_0 + \sum_i w_i x_i + \sum_{i<j} w_{ij} \, x_i x_j\right)
$$

问题出在 $w_{ij}$ 的估计上。**$w_{ij}$ 只在「特征 $i$ 与 $j$ 同时非零」的样本上才有梯度**。在 one-hot 稀疏场景里，绝大多数特征对从没在一条样本里同时出现——$w_{ij}$ 就是 0 或噪声，交叉项形同虚设。

## 2 FM 的核心：把交叉权重换成向量内积

FM 的关键改动：**用两个向量的内积替代每个交叉权重**。假设特征 $i$ 对应一个 $k$ 维隐向量 $\mathbf{v}_i \in \mathbb{R}^k$，则二阶交叉项变为：

$$
\hat{y}(x) = w_0 + \sum_{i} w_i x_i + \sum_{i<j} \left\langle \mathbf{v}_i, \mathbf{v}_j \right\rangle x_i x_j
$$

其中 $\langle \mathbf{v}_i, \mathbf{v}_j \rangle = \sum_{f=1}^{k} v_{i,f} v_{j,f}$。**每个特征只有一个 $k$ 维向量，交叉权重不再各自独立，而是被「共享的隐向量」参数化**。

这为什么能解决稀疏问题？特征 $i$ 和 $j$ 没同时出现过，但特征 $i$ 和 $j$ 各自的向量 $\mathbf{v}_i$、$\mathbf{v}_j$ 都分别通过与其他特征的交互学到过。**只要 $\mathbf{v}_i$ 和 $\mathbf{v}_j$ 各自被训练充分，它们的交互权重 $\langle \mathbf{v}_i, \mathbf{v}_j \rangle$ 就能被估计**——这是「参数共享」带来的泛化。

## 3 公式解析：FM 二阶项怎么高效算

二阶项 $\sum_{i<j} \langle \mathbf{v}_i, \mathbf{v}_j \rangle x_i x_j$ 直接算需要 $O(n^2 k)$ 次操作，$n$ 是特征维数（百万级），不可接受。Rendle 给出了一个 $O(nk)$ 的改写：

$$
\sum_{i<j} \langle \mathbf{v}_i, \mathbf{v}_j \rangle x_i x_j =
\frac{1}{2} \sum_{f=1}^{k} \left[ \left(\sum_{i} v_{i,f} x_i\right)^2 - \sum_{i} v_{i,f}^2 x_i^2 \right]
$$

三步拆解这条公式：

- **第一步，展开**：$\langle \mathbf{v}_i, \mathbf{v}_j \rangle x_i x_j = \sum_f v_{i,f} v_{j,f} x_i x_j$，把对特征对求和换成对隐维求和。
- **第二步，配对技巧**：$(\sum_i v_{i,f} x_i)^2$ 展开后包含 $i=j$ 的平方项 $\sum_i v_{i,f}^2 x_i^2$ 和两两乘积 $2 \sum_{i<j} v_{i,f} v_{j,f} x_i x_j$。用「平方和减去自身平方」就恰好得到「两两乘积」，正好对应 $i<j$ 的交叉项。
- **第三步，复杂度**：$\sum_i v_{i,f} x_i$ 对每个 $f$ 只需一次遍历，总代价 $O(nk)$。**从 $O(n^2k)$ 降到 $O(nk)$，百万特征也能实时推理**。

## 4 FM 与矩阵分解、SVM 的关系

| 模型 | 二阶交互来源 | 处理稀疏 ID | 输入泛化 |
| --- | --- | --- | --- |
| LR + 人工交叉 | 人工构造 | 差（权重学不到） | 只能学见过的组合 |
| 矩阵分解（SVD） | 用户×物品矩阵低秩分解 | 好 | 只能用户—物品 |
| FM | 任意特征对向量内积 | 好 | 任意特征（含上下文） |

FM 可以看作**矩阵分解的超集**：当特征只有「用户 ID + 物品 ID」时，FM 的二阶项恰好退化成 SVD 的 $p_u^\top q_i$；加入任意辅助特征（年龄、类目、时间）后，FM 仍统一处理，不必为每种交互单独建模型。相比 SVM 的核方法，FM 的线性复杂度与参数共享也让它更适合大规模 CTR 预估。

## 5 从 FM 到 FFM、DeepFM

FM 打开了「参数化特征交互」的大门，后续演进都从这里出发：

- **FFM（Field-aware FM）**：不同 field 用不同向量，交互更精细（[[ffm-field-aware-factorization-machines]]）。
- **DeepFM**：FM 做低阶交叉，深度网络做高阶交叉，联合训练（[[deepfm]]）。
- **xDeepFM / DCN**：进一步显式建模高阶交叉（[[dcn-xdeepfm-explicit-feature-crossing]]）。

FM 作为这些模型的基础模块，今天仍是很多 CTR 模型二阶交互的标准实现。

## 辨析｜FM 与「特征交互」的几个易错细节

FM 公式看着简洁，用起来有几个细节常被忽略，值得单独立出来：

**细节一：$k$ 的取值不是越大越好。** 隐向量维度 $k$ 决定「每个特征能表达的交互复杂度」。$k$ 太小，隐向量表达不了足够丰富的语义，交互学不好；$k$ 太大，参数增多、稀疏特征向量估计不稳、过拟合。经验上 $k$ 取 8~64 之间，按数据规模与特征稀疏度调——**不要默认取大**。

**细节二：特征「是否非零」本身就是信号。** FM 对稀疏 one-hot 特征直接做内积，但「某个 field 有没有值」这个信息没有被显式利用。实践里常加「field 存在性」特征，或对「缺失 field」的隐向量做专门处理——**「没有值」和「值是 0」是不同的信号**。

**细节三：二阶项只处理「非零特征对」。** 公式里 $x_i x_j$ 只要有一个是 0，该项就消失。这意味着**稀疏数据下，实际参与二阶交互的特征对远少于 $\binom{n}{2}$**——这是 FM 高效的原因，但也意味着「冷门特征对的交互」仍然学不到。这正好引出 FFM 的「按 field 分组」与深度模型的「高阶显式交叉」（[[dcn-xdeepfm-explicit-feature-crossing]]）。

**细节四：FM 与「线性项 + 二阶项」的分工。** 一阶项 $w_i x_i$ 刻画「特征独立影响」，二阶项刻画「两两交互」——**不要把「该进一阶的」塞进二阶，也不要把「该进二阶的」只留在一阶**。业务上「用户活跃度」「物品热度」这类强独立信号放一阶，交互信号（用户×类目）放二阶，模型更易收敛。

**补充｜FM 的「损失函数」选择**：FM 本身是个「打分函数」，配什么损失取决于任务：

- **二分类（CTR）**：配 sigmoid + 交叉熵——$\hat{p} = \sigma(\hat{y}(x))$，训练用点击标签。
- **回归（评分）**：直接平方损失——$\hat{y}(x)$ 逼近真实评分，此时 FM 退化成「评分预测」的矩阵分解扩展（[[funk-svd-matrix-factorization]] 的推广）。
- **排序（pairwise）**：配 BPR 损失——让「正样本得分 > 负样本得分」（[[fpmc-markov-chain-sequential]] 用的正是这个思路）。

**同一个 FM 打分函数，换损失就是换任务**——这也是 FM 被称为「通用模型」的原因：它把「特征交互」这个核心机制独立出来，任务相关的只是「损失头」。

**补充｜FM 的「在线学习」与「多值特征」**：

FM 落地有两个常见的「扩展需求」：

- **在线学习**：FM 的参数（$w_i$ 与 $\mathbf{v}_i$）可以「按样本增量更新」——**FTRL 的 FM 版**是广告/推荐「在线 CTR」的经典实现（[[realtime-recommendation-streaming]]）。在线更新的关键是「稀疏特征只更新非零项」，与 FM 的「非零对」结构天然契合。
- **多值特征（multi-hot）**：FM 的 $x_i$ 通常假设「每 field 一个值」（one-hot），但真实场景常有「多值」（用户关注了多个频道、物品有多个标签）。**扩展**：把 field 的「多值」展开成「多个特征」，或用「多值聚合」$\mathbf{v}_{\text{field}} = \sum_{v \in \text{values}} \mathbf{v}_v$——**「多值怎么聚合」是 FM 建模里一个常被低估的设计点**。

**一个提醒**：FM 的「隐向量」在「embedding 语义」上是「特征的向量化表示」——**FM 学出的 $\mathbf{v}_i$ 可以直接当「特征 embedding」复用**（如作为双塔的初始化或特征），这也是「FM 与深度模型」的衔接点。

**补一句**：FM 的价值在于「把『稀疏数据下的特征交互』第一次变成『可计算、可泛化』」——它是「参数化交互」的开山之作，后续模型的交互设计大多能在 FM 里找到影子。

**补一句**：FM 的「$O(nk)$ 高效公式」是它能在「百万特征」上实时推理的工程根基——「理论优雅」与「工程高效」在 FM 里第一次同时成立。

## 6 小结

- 稀疏数据下交叉权重 $w_{ij}$ 学不到，**FM 用隐向量内积 $\langle \mathbf{v}_i, \mathbf{v}_j \rangle$ 替代独立权重**，靠参数共享泛化。
- FM 是**矩阵分解向任意特征对的推广**，对 ID 特征与辅助特征统一建模。
- 二阶项可改写为 $\frac{1}{2}\sum_f[(\sum_i v_{i,f}x_i)^2 - \sum_i v_{i,f}^2 x_i^2]$，**复杂度从 $O(n^2k)$ 降到 $O(nk)$**。
- FM 是后续 FFM、DeepFM 等模型的基础模块，二阶交互的「标准答案」。
