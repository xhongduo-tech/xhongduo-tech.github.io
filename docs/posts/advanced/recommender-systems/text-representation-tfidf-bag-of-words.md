## 为什么从文本表示开始

上一篇我们搭起了基于内容推荐的框架：物品画像 $\vec{i}$ = 结构化属性 + 文本属性。可一个现实问题立刻卡在面前——**文本怎么进公式？** 电影简介里写着「末日之后，人工智能与人类伦理的冲突」，算法看不懂汉字，它只认得数字。

对推荐系统而言，文本往往比结构化标签携带更丰富的信息：类目只能告诉你「这是一部科幻片」，而简介能告诉你「它在探讨意识上传」。**把文本翻译成向量，是内容推荐的地基。** 这一篇讲两件递进的事：**词袋模型（Bag of Words）** 把文本变成数字，**TF-IDF** 让数字真正反映「重要性」。<span class="marginnote">文本表示不只是推荐系统的技术：搜索引擎、情感分析、一切 NLP 任务都要先过这一关。在「从极限到大模型」的主线里，它是通往第十四篇《LLM 与推荐》的必经阶梯——<strong>大模型的 token 表示，正是词袋思想的现代化形态</strong>。</span>

## 1 把一句话变成向量：词袋模型

**词袋模型（Bag of Words，BoW）**：把一段文本看作一个装着词的「袋子」，忽略语法和顺序，只统计每个词出现与否或出现几次，得到「词典 → 频数」的向量。

以简介「人工智能改变教育，也改变医疗」为例，先分词：

```text
人工智能 / 改变 / 教育 / 也 / 改变 / 医疗
```

若整个语料（所有物品简介）的词典是「人工智能、改变、教育、医疗、也、爱情」，则这句话的**词频向量**是：

$$
\vec{d} = \big(1,\; 2,\; 1,\; 1,\; 1,\; 0\big)
$$

六个维度依次对应六个词：人工智能出现 1 次、改变出现 2 次、教育 1 次、医疗 1 次、也 1 次、爱情 0 次。**「改变」出现两次，向量里就是 2**——这正是第一级《集合》里强调过的**多重集（multiset）**：词袋允许重复计数，所以它是多重集而不是集合。<span class="marginnote">集合的互异性在这里失效了：{改变} 只有一种元素，而词袋里改变可能占两个槽位。<strong>把「词袋」理解成「词的多重集」，能避免很多后续的困惑</strong>——比如「两个文档的向量相似度」本质是比较两个多重集。</span>

**重点：** 词袋模型最关键的假设是**放弃词序**。「人工智能改变教育」与「教育改变人工智能」在词袋里是同一个向量——这对推荐里的物品简介通常损失不大，但对情感分析可能是灾难。先记住这个「顺序不重要」的假设，它是词袋一系列局限的总根源。

## 2 TF：词频与长度归一化

词袋给的是**词频（Term Frequency，TF）**：$tf(t, d)$ 表示词 $t$ 在文档 $d$ 中出现的次数。原始频数有一个明显的毛病：**长文档天然词频高**。一篇 2000 字的简介里「电影」出现 10 次，不一定比一篇 200 字的简介里出现 3 次更「强调电影」。

常用的三种 TF 变体：

| 名称 | 公式 | 直觉 |
| --- | --- | --- |
| 原始频数 | $tf = \mathrm{count}(t, d)$ | 直白，但受文档长度干扰 |
| 对数归一 | $tf = \log(1 + \mathrm{count})$ | 压缩极端大数，减缓「重复词」收益递减 |
| 长度归一 | $tf = \mathrm{count} / \lvert d \rvert$ | 除以文档长度，公平比较长短文档 |

**TF 回答的问题只有一个：这个词在「这篇」文档里有多频繁。** 它完全不关心「这个词在全语料里是不是谁都在用」——后者正是 IDF 的活。

## 3 IDF：为什么「罕见词」更值钱

试着想一个极端例子。假设语料里有 1000 篇物品简介：

- 「电影」出现在其中 800 篇——它几乎不能区分任何两篇简介；
- 「厄里斯」（一个冷门角色的名字）只出现在 2 篇——谁提到厄里斯，谁几乎肯定是那部特定的电影。

**词频是「这篇文档有多需要这个词」，而区分度要靠「这个词在全语料里有多独特」**。**逆文档频率（Inverse Document Frequency，IDF）** 正是给「稀有」加分：

$$
idf(t) = \log \frac{N}{df_t}
$$

其中 $N$ 是文档总数，$df_t$ 是包含词 $t$ 的文档数（document frequency）。<span class="marginnote">为什么要取对数？因为「稀有」的跨度太大：从出现在一半文档（$N/df_t = 2$）到只出现在一篇（$N/df_t = 1000$），比值可以差几百上千倍。<strong>对数把这个巨大的动态范围压缩成好用的标度</strong>——这也和第一篇里「RMSE 用平方放大误差」的思路相反，这里是用对数缩小差异。</span>

「电影」的 $idf = \log(1000/800) \approx 0.22$，「厄里斯」的 $idf = \log(1000/2) \approx 6.21$——**同样出现一次，后者的信息量是前者的近 30 倍**。IDF 把「谁都在说的废话」压下去，把「只有少数文档才有的记号」抬起来。

## 4 公式解析：TF-IDF 的完整计算

把两个分数相乘，就得到**TF-IDF**——目前仍是最常用的文本特征之一：

$$
tfidf(t, d) = tf(t, d) \times idf(t) = tf(t, d) \times \log \frac{N}{df_t}
$$

对这条公式做四步拆解：

- **第一步，分词**：把文档切成词序列。中文没有天然空格，需要分词工具（jieba、词表匹配等）；英文按空格切分即可。<span class="marginnote">分词质量直接决定 TF-IDF 质量：同一句话切出「人工 / 智能」还是「人工智能」，是两套完全不同的词典。对物品标题、标签这类短文本，也常直接用「词 + 标点分隔」的粗糙切法——<strong>推荐系统里的文本通常不追求完美的语言学分词，够用即可</strong>。</span>
- **第二步，算 TF**：统计词 $t$ 在文档 $d$ 中的出现情况（原始频数、对数或长度归一）。这一步是「文档内部的频率」。
- **第三步，算 IDF**：统计有多少篇文档包含 $t$，代入 $\log(N/df_t)$。这一步是「全语料层面的稀有度」，需要事先遍历整个语料。
- **第四步，相乘**：高频且稀有的词得分高，高频且普遍的词被压低，低频的词即使稀有也翻不出大浪——**乘积同时惩罚「太普遍」与「太罕见」的两端**。

用一个数字例子把它钉死。设语料 $N = 1000$，两个词「电影」与「厄里斯」在某篇文档里都出现 2 次，$tf = 2$：

$$
tfidf(\text{电影}, d) = 2 \times \log \frac{1000}{800} \approx 2 \times 0.223 = 0.446
$$

$$
tfidf(\text{厄里斯}, d) = 2 \times \log \frac{1000}{2} \approx 2 \times 6.215 = 12.43
$$

「厄里斯」的 TF-IDF 是「电影」的 **27.9 倍**——**这就是 TF-IDF 想让向量拥有的性质：文档在哪些词上「异常突出」，哪些词就主导它的向量方向**。<span class="marginnote">于是两个简介的余弦相似度，本质上由它们共享的「稀有词」决定——这非常合理：都讲厄里斯的两部电影，几乎肯定是同一题材。TF-IDF 用最朴素的统计，逼近了「语义相似」。</span>

**辨析｜易错点：** TF-IDF 是离线算好、在线复用的，这引出一个必须警惕的坑——**IDF 必须在训练集上统计，评估 / 上线时沿用同一套 IDF，绝不能用测试集重算**。否则等于把测试集的信息泄漏进了特征，离线指标会虚高。另一个常见误解是「IDF 越大越好」：其实 $df_t = 1$ 的词往往只是专有名词甚至拼写错误，区分度是有了，但匹配性极差——所以工程上常给 $df_t$ 一个下限（比如 $df_t \ge 5$）或对 IDF 做平滑。

## 5 用代码算一遍 TF-IDF

不依赖库，用 NumPy 手算一遍，把上面的公式落到实处：

```python
import numpy as np
from collections import Counter

docs = [
    "人工智能改变教育，也改变医疗",
    "人工智能改变影视，但爱情是永恒主题",
    "教育医疗人工智能，是科技的三件大事",
]
# 1. 分词（粗糙切法：按字符「非空白」成词演示，真实项目用分词工具）
def tokenize(text):
    return [w for w in text.replace("，", "").replace("，", " ").split()]

corpus = [tokenize(d) for d in docs]
vocab = sorted({w for doc in corpus for w in doc})
V, N = len(vocab), len(corpus)
print("词典：", vocab)

# 2. TF：对数归一
tf = np.zeros((N, V))
for di, doc in enumerate(corpus):
    cnt = Counter(doc)
    for w in vocab:
        tf[di, vocab.index(w)] = np.log(1 + cnt[w])

# 3. IDF：log(N / df)，df 用整个语料统计
df = np.array([sum(1 for doc in corpus if w in doc) for w in vocab])
idf = np.log(N / df)

# 4. TF-IDF = TF * IDF（逐元素相乘）
tfidf = tf * idf

print("IDF：  ", np.round(idf, 3))
print("TF-IDF：")
print(np.round(tfidf, 3))
```

这份代码每一步对应第 4 节的四步拆解：先建词典，再算 TF，再统计全局 IDF，最后相乘。**注意 IDF 只用了一次 `corpus` 遍历——它必须来自全语料，而不是来自当前文档。**

## 6 词袋与 TF-IDF 的局限

TF-IDF 把文本变成了可以算余弦的向量，但它的天花板清晰可见：

- **高维且稀疏**：词典有几万到几十万维，一篇简介的向量绝大多数维度是 0——内存与计算压力巨大，需要第五篇的向量检索才能扛住。
- **无语义**：「电影」和「影片」是不同维度，算出相似度为零，哪怕它们同义。TF-IDF 只认识「词面」，不认识「词义」。
- **忽略顺序与搭配**：「人工智能」四个字被拆成独立的字词（若按字切分），「智能 × 人工」的组合意义丢失；词袋对否定句、双关也无能为力。<span class="marginnote">顺序信息可以部分补救：用 <strong>N-gram</strong>（相邻 2–3 个词的连续片段）代替单个词作为「词」，能把「不 好看」与「好看」分开——但维度进一步爆炸，只是把「无语义」推迟而已。</span>
- **新词（OOV）失明**：语料里没出现过的词在向量里没有位置，而推荐系统的物品是不断更新的。

这些局限指向同一个结论：**词袋模型把文本变成了「数字」，但没变成「意思」。** 要让「电影」与「影片」在向量空间里靠在一起，需要学习型的稠密表示——这正是下一篇 Word2Vec 要解决的问题。<span class="marginnote">这一篇的进阶版是直接把 TF-IDF 向量喂给降维（第二级《线性代数》的 PCA / SVD）做语义近似，这也是 LSA 的思路；但它仍不及 Word2Vec 直接从语料学语义来得干净。</span>

## 7 小结

- **词袋模型（BoW）**：忽略词序，统计「词典 → 频数」，本质是一个**词的多重集**。
- **TF**：词在「这篇」文档里的频率；三种变体解决文档长度干扰。
- **IDF**：$idf(t) = \log(N/df_t)$，给「全语料里稀有的词」加分，压缩了稀有度的大动态范围。
- **TF-IDF**：$tf \times idf$，让文档向量被「异常突出的词」主导，是两个相似度计算（余弦）的好输入。
- **易错点**：IDF 必须来自训练集统计，不能泄漏测试信息；TF-IDF 高维稀疏、无语义、OOV 失明。

在下一节，我们把「词面」升级成「词义」：用 Word2Vec 把每个词学成一个稠密向量，让「电影」和「影片」在向量空间里真的靠在一起——并最终把这个能力带到**物品 Embedding** 上。
