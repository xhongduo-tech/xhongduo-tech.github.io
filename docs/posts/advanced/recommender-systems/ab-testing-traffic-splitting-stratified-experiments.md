## 为什么从 A/B 测试开始

前面两篇把离线指标算了个遍，可它们都有一个致命前提：**「离线好」是否等价于「线上好」？** 答案常常是不等价。于是工业界把**在线实验**当作最终裁决者，它就是俗称的 **A/B 测试（A/B test）**。<span class="marginnote">在《实验方法》一篇我们已经认识了三种方法：离线实验便宜但失真，用户调查能问态度但样本小、易说谎，<strong>在线实验流量真实、结论可信，是最终拍板的一环</strong>。</span>

**A/B 测试**：把用户随机分成两组，一组看新版（实验组 A），一组看旧版（对照组 B），比较两组的关键指标，再用统计方法判断差异是「真」还是「随机波动」。费希尔那句话的忠告是：**统计学家应在实验设计时进场，而不是事后收尸**——这篇讲的就是「怎么设计才不会让实验死于随机误差」。

## 1 离线很好、线上崩盘：为什么需要 A/B 测试

先看三个离线指标「失灵」的场景：

- **分布漂移**：离线用的历史数据是旧系统产生的；上线新系统后，用户看到的东西变了、行为也跟着变，离线评估的「正确分布」已不复存在。
- **闭环效应**：推荐系统会改变用户行为，而行为又成为下一次训练的数据。离线把系统当「旁观者」测，线上它是「参与者」——这会引入反馈回路，离线永远测不出。
- **代理指标失真**：离线优化 RMSE，用户在意的是点击与留存。**RMSE 降了 5%，用户真的更满意吗？** 只有线上数据知道。

所以业界的共识是：**离线实验筛候选，在线实验做裁决**。<span class="marginnote">「从极限到大模型」主线里的一个思想在这里复现：<strong>极限 = 用「无限逼近」取代「一步到位」</strong>。离线→在线，正是一次次「用更大规模的真实数据逼近真相」的过程；而统计显著性的本质，也是用样本量让估计逼近真值。</span>

## 2 分流设计：随机化是对照组的灵魂

A/B 测试的第一要务是**随机分流（random assignment）**。只有随机，两组才在一切未知变量上「平均」地相同，唯一的系统差异就是你要测的那个改动。

两个关键设计决策：

**第一，按用户分流，而不是按请求分流。** 同一个用户这次看到 A、下次看到 B，会造成「实验污染」——他不知道自己在实验里，但体验不一致会影响行为；更糟的是，推荐系统有记忆，一个用户同时吃两种算法会让双方都被「脏数据」干扰。**按用户分流的单位是 user_id**：对 user_id 做哈希取模，模值落在某个区间就进 A 组，否则进 B 组。<span class="marginnote">为什么用哈希而不是轮流分配？哈希保证同一个用户每次都被分到同一组——这是「分流的稳定性」，也是后续追踪用户行为的前提。工程上常用 <code>hash(user_id) % 100 &lt; 50</code> 之类的方式切 50% 流量。</span>

**第二，只动一个变量。** 实验组和对照组之间，除了被测改动，其他一切（页面、推荐算法、曝光位）都必须一致。同时改两个变量，结果归因就说不清了。

## 3 分层实验：正交层与互斥层

一个成熟平台有几十个算法同时在测，可流量只有 100%。怎么让多个实验并行而不互相踩踏？答案是**两层结构**：

- **互斥层（exclusive layer）**：一块流量只属于一个实验。比如把 100% 流量切给「排序模型 v2 vs v1」，实验结束再给下一个实验用。缺点是流量利用率低——大实验吃掉了所有用户。
- **正交层（orthogonal layer）**：同一批用户同时参与多个实验，但用「正交切分」保证各实验互不干扰。用户 id 在不同层用**不同的哈希盐**再取模，这样两层实验的分组近似相互独立。

**正交 + 互斥的分层架构**是现代 A/B 平台的标准做法：把流量按「主题」划成若干互斥层（如「推荐算法层」「UI 层」），每层内部再做正交切分。<span class="marginnote">直观理解正交：假设推荐算法层和 UI 层各把流量切成两半，<strong>一个用户有 1/4 概率同时进算法实验组和 UI 实验组，但两层之间彼此无关</strong>——就像掷两枚硬币，互不影响。这样两个实验可以同时跑，各用各的样本。</span>

分层实验的代价是**假设层间无交互**。若 UI 改动会改变算法效果（交互效应存在），正交层就失真了——所以交互风险高的实验要放进同一个互斥层。

## 4 公式解析：z 检验，判断差异是否「真」

分完流、跑完实验，拿到两组指标：实验组点击率 $\hat{p}_A$，对照组点击率 $\hat{p}_B$。直觉上 A 比 B 高，可这是不是随机波动？**z 检验**回答这个问题。

设 $n_A, n_B$ 为两组样本量，$x_A, x_B$ 为两组的「成功数」（如点击次数），两组点击率 $\hat{p}_A = x_A / n_A$，$\hat{p}_B = x_B / n_B$。检验统计量：

$$z = \frac{\hat{p}_A - \hat{p}_B}{\sqrt{\hat{p}(1-\hat{p})\left(\frac{1}{n_A} + \frac{1}{n_B}\right)}}, \qquad \hat{p} = \frac{x_A + x_B}{n_A + n_B}$$

逐项拆解：

- **第一步，看分子 $\hat{p}_A - \hat{p}_B$**：两组点击率之差。若真实效果为零，分子应在 0 附近随机游走。
- **第二步，看分母**：这是「差值」的标准误（standard error）。$\hat{p}$ 是两组合并后的总体点击率，$\hat{p}(1-\hat{p})$ 是方差，除以样本量再求和开方，度量「这个差值有多不稳定」。<span class="marginnote">分母的标准误为什么长这样？因为点击「成功/失败」近似二项分布，而二项分布在大样本下按中心极限定理逼近正态——<strong>这就是「极限」思想在统计里的化身</strong>，第二级《概率论与数理统计》有完整推导。</span>
- **第三步，查 p 值**：$z$ 越大，说明差值越「超乎寻常」。把 $z$ 代入标准正态分布，得到 **p 值**——「假设真实效果为零，观测到如此极端差值的概率」。约定俗成 $p < 0.05$ 判定显著。

用一个具体数字感受。设实验组 $n_A = 1000$、点击 $x_A = 120$（$\hat{p}_A = 0.12$），对照组 $n_B = 1000$、点击 $x_B = 80$（$\hat{p}_B = 0.08$）。合并点击率 $\hat{p} = (120+80)/2000 = 0.10$。分母 $= \sqrt{0.10 \times 0.90 \times (0.001 + 0.001)} = \sqrt{0.00018} \approx 0.0134$，于是 $z = (0.12 - 0.08)/0.0134 \approx 2.98$，对应的 $p \approx 0.003 < 0.05$——**这个 4 个百分点的提升在统计上显著**。若差值只有 2 个百分点（0.12 vs 0.10，$z \approx 1.43$，$p \approx 0.15$），同样样本量下就不显著——**不是没效果，是样本不够大**。

## 5 显著性、置信区间与效应量

p 值只是第一关，成熟的评估还看两样东西：

**置信区间（confidence interval）**。点击率差值的 95% 置信区间约为 $\hat{p}_A - \hat{p}_B \pm 1.96 \times SE$。它比 p 值更有信息量：区间 `[0.014, 0.066]` 不但告诉你显著，还告诉你**效果大概多大**。

**效应量（effect size）与商业显著性**。$p < 0.05$ 只说明「效果很可能不是零」，不说明「效果值得上线」。提升了 0.01% 的 CTR，统计显著却毫无商业价值。<span class="marginnote">这就是「统计显著 ≠ 商业显著」：显著性回答「是不是真的有效」，商业判断回答「值不值得上」。真正的决策是两问都过。</span>上线前最好先做**样本量估算**：给定想测出的最小效果 $\delta$、显著性水平 $\alpha$ 与统计功效 $1-\beta$，每组约需

$$n \approx \frac{2\,(z_{\alpha/2} + z_{\beta})^2}{\delta^2}$$

可见效果越小，所需样本量平方级增长——**想测出 0.1% 的提升，样本量是测 1% 的 100 倍**。

## 6 用代码算一遍

把第 4 节的 z 检验写成可直接运行的 Python（依赖 `scipy`）：

```python
from math import sqrt
from scipy import stats

def two_proportion_ztest(xa, na, xb, nb):
    """两组点击数据 (成功数 x, 样本量 n)，返回 (z 值, 双尾 p 值, 95% 置信区间)。"""
    pa, pb = xa / na, xb / nb
    p_pool = (xa + xb) / (na + nb)                    # 合并点击率
    se = sqrt(p_pool * (1 - p_pool) * (1/na + 1/nb))  # 差值标准误
    z = (pa - pb) / se
    p = 2 * (1 - stats.norm.cdf(abs(z)))              # 双尾 p 值
    ci = (pa - pb) - 1.96 * se, (pa - pb) + 1.96 * se
    return z, p, ci

z, p, ci = two_proportion_ztest(xa=120, na=1000, xb=80, nb=1000)
print(f"z = {z:.3f}, p = {p:.3f}, 95% CI = [{ci[0]:.3f}, {ci[1]:.3f}]")
# z ≈ 2.98, p ≈ 0.003, 95% CI ≈ [0.014, 0.066]
```

把样本量砍到一半再跑一次（$x_a = 60, n_a = 500$；$x_b = 40, n_b = 500$），点击率不变但 $z \approx 2.11$、$p \approx 0.035$、置信区间变宽——**同样的效果量，样本量减半，显著性打折扣**。这正是「样本量估算」要在实验设计阶段做掉的原因。

## 7 辨析｜易错点：A/B 测试的五个坑

**辨析｜易错点：** A/B 测试看似简单，翻车点极多，这里列五个高频坑：

- **多重比较（multiple testing）**：一次实验看十个指标，每个指标都有 5% 的假阳性机会，十个看下来「至少一个假显著」的概率约 $1 - 0.95^{10} \approx 40\%$。**指标越多，越需要校正**（如 Bonferroni 校正）。
- **新奇效应（novelty effect）**：新功能上线头几天，用户因新鲜感而点击偏高，之后回落。跑实验时间太短会把「新奇」误判成「有效」。
- **样本量不足**：第 4 节说过，效果小、样本少时差异全在噪声里。别拿 1000 个用户去测 0.1% 的差异。
- **辛普森悖论（Simpson's paradox）**：忽略某个分层变量（如新老用户）时，总体结论可能被反转。**实验前想清楚要分层对比的维度**，否则结论可能是幻觉。
- **偷看与提前终止（peeking）**：实验没跑完就频繁看 p 值、看着显著就提前叫停，会系统性放大假阳性。**预先定好样本量与时长，跑完再看。**

## 8 小结

- **A/B 测试**是在线实验的标准形态：随机分流 → 跑实验 → 显著性检验 → 决策。
- **分流**要按用户（user_id 哈希）而非按请求，且实验组与对照组只差一个变量。
- **分层实验**用「互斥层 + 正交层」让多个实验并行；代价是假设层间无交互。
- **z 检验**：$z = \frac{\hat{p}_A - \hat{p}_B}{SE}$，p 值 < 0.05 判显著；还要看置信区间与商业效应量。
- **易错点**：多重比较、新奇效应、样本量不足、辛普森悖论、偷看提前终止。

在下一节，我们终于从「评估」走向「建模」。评估告诉我们「好不好」，而推荐算法的第一个大流派——**协同过滤**——将回答「怎么推荐」。它不用任何内容属性，只看用户的行为数据，是「从极限到大模型」道路上最古老也最经典的一课。
