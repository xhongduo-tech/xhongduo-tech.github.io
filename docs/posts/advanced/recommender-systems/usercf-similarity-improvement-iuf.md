# UserCF 的相似度改进：对热门物品的惩罚（IUF 思想）

<div class="epigraph">
<p>两个用户对冷门物品采取过同样的行为，更能说明他们兴趣的相似。</p>

## 为什么从「改进」开始

上一篇的 UserCF 已经能跑通「找相似用户 → 聚合投票」的全流程，但它有一个致命病灶：**热门物品会让所有用户「变像」**。这一篇是 UserCF 最著名的改进——IUF（Inverse User Frequency，逆用户频率）<span class="marginnote">注意中文译名里的「用户频率」容易误导：IUF 惩罚的对象是热门物品，其权重与「包含该物品的用户数」成反比，本文稍后专门辨析。</span>。

## 1 病灶：热门物品制造虚假相似

回到相似度公式：

$$
w_{uv} = \frac{|N(u) \cap N(v)|}{\sqrt{|N(u)| \cdot |N(v)|}}
$$

分子是两人共同喜欢的物品数。问题就出在分子上：**如果这个「共同」来自一部人人都看的爆款，它就不该算作两人「口味相似」的证据。**

设想两个用户都看了《流浪地球2》——这能说明他们兴趣相近吗？不能，因为上映期间几乎所有人都看了。同理，都买过《新华字典》、都用过某款国民软件，这类「全民物品」说明不了任何个性。

**辨析｜易错点：** 这里的直觉与统计学里的「信息量」一脉相承——一个事件越稀有，携带的信息量越大<span class="marginnote">信息量与概率的关系是第二级《信息论》的核心：自信息 $I(x)=-\log p(x)$。IUF 的 $\frac{1}{\log(1+|N(i)|)}$ 正是「越常见，权重越低」的信息量思想在推荐里的朴素应用。</span>。物品越热门，两人「共同喜欢它」能提供的信息越少。

## 2 IUF：给共同物品按冷热度加权

布雷兹等人在 1998 年的论文中提出了 IUF：**计算用户相似度时，对每个共同喜欢的物品，按其热门程度降权**。热门物品（$|N(i)|$ 大）权重小，冷门物品（$|N(i)|$ 小）权重大：

$$
w_{uv} = \frac{\sum_{i \in N(u) \cap N(v)} \frac{1}{\log(1 + |N(i)|)}}{\sqrt{|N(u)| \cdot |N(v)|}}
$$

其中 $N(i)$ 是喜欢过物品 $i$ 的用户集合，$|N(i)|$ 是它的用户数。<span class="marginnote">一部被 1000 万人看过的电影，$\frac{1}{\ln(1+10^7)}\approx 0.062$；一部只有 100 人看过的冷门书，$\frac{1}{\ln(1+100)}\approx 0.217$——冷门物品的贡献约为热门物品的 3.5 倍。</span>

对比原公式：原来交集里的每个物品「贡献 1」，现在贡献 $\frac{1}{\log(1+|N(i)|)}$——**总交集大小不变，但每个共同物品的「话语权」被重新分配**。

## 3 公式解析：IUF 相似度

把 IUF 公式拆成四步：

- **第一步，取交集 $N(u) \cap N(v)$**：仍然只关心两人共同喜欢过的物品，这一步没变。
- **第二步，逐物品降权** $\frac{1}{\log(1+|N(i)|)}$：$|N(i)|$ 是喜欢物品 $i$ 的用户总数，$\log(1+|N(i)|)$ 把「热门度」压缩到对数尺度——**一惩罚就是对数级的温和压制**，避免冷门物品的权重反客为主。
- **第三步，求和**：把交集里所有物品的降权贡献累加，得到「加权后的共同兴趣强度」。
- **第四步，除以 $\sqrt{|N(u)||N(v)|}$**：分母保持余弦形式不变，仍然惩罚「总兴趣面过宽」的用户。

**为什么用 $\log(1+|N(i)|)$ 而不是直接除 $|N(i)|$？** 直接除会让一个只被 2 个人看过的物品贡献 $1/2=0.5$，权重爆炸；对数把极端热门度的差异压平，更稳健。**为什么 +1？** 因为当 $|N(i)|=1$ 时 $\log 1=0$，分母为 0——+1 保证「只有一个用户喜欢」的物品也能安全参与计算。

## 4 另一个维度：相似度矩阵的定期更新

IUF 改变了相似度的「含义」，但没改变它的「成本」——用户相似度矩阵依然是 $O(n^2)$ 量级的。项亮在书中专门提醒：**UserCF 的用户相似度矩阵不能每次请求都现场算**，工业实现通常每隔几天或几小时离线重算一次，线上直接查表<span class="marginnote">这个「离线算、在线查」的取舍，是推荐系统工程篇《特征平台》与《在线推理服务》的伏笔——离线能承受的复杂度，在线不一定能承受。</span>。

这也是 UserCF 在用户规模极大时被诟病的根源：**用户数增长快、新用户层出不穷，离线矩阵很快过期**。这个痛点正是下一篇 ItemCF 登场的理由。

## 5 代码：给 UserCF 打上 IUF 补丁

在上一篇 `user_similarity` 的基础上改一行就能得到 IUF 版本：

```python
import math
from collections import defaultdict

def user_similarity_iuf(train):
    item_users = defaultdict(set)
    for u, items in train.items():
        for i in items:
            item_users[i].add(u)

    # N_item[i] = 喜欢物品 i 的用户数，即 |N(i)|
    N_item = {i: len(users) for i, users in item_users.items()}

    C = defaultdict(float)   # 注意：C 从 int 变成 float，存的是降权后的贡献
    N_user = defaultdict(int)
    for i, users in item_users.items():
        iuf = 1.0 / math.log(1 + N_item[i])   # 本物品的降权系数
        for u in users:
            N_user[u] += 1
            for v in users:
                if u != v:
                    C[(u, v)] += iuf          # 原来是 += 1，现在 += iuf

    W = defaultdict(dict)
    for (u, v), cnt in C.items():
        W[u][v] = cnt / math.sqrt(N_user[u] * N_user[v])
    return W
```

核心变化就一处：`C[(u, v)] += 1` 变成了 `C[(u, v)] += iuf`。**倒排表的遍历结构完全复用**——IUF 只是改了一个累加量，这正是它能在工业界被无缝接进旧代码的原因。`recommend` 函数与上一篇完全相同，无需改动。

## 6 小结

- UserCF 的病根：**热门物品在分子里制造虚假共同**，让人人「变像」。
- **IUF**：对共同喜欢的物品按 $\frac{1}{\log(1+|N(i)|)}$ 降权，冷门物品贡献更大。
- 对数尺度的降权**稳健**；$+1$ 防止分母为 0；分母保持余弦形式。
- 用户相似度矩阵**离线定期重算、线上查表**，是工程上的必然取舍。
- IUF 惩罚「热门物品」；下一篇 ItemCF 里有个**对偶**改进——惩罚「活跃用户」，注意不要混淆。

在下一篇，我们把「人以群分」换成「物以类聚」，看看业界应用最广的**基于物品的协同过滤（ItemCF）**——它会复用我们今天建立的大部分直觉，只是把相似度的主角从用户换成物品。
