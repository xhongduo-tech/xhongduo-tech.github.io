## 为什么从负采样开始

上一节我们讲完了双塔模型的结构与训练目标：用户塔输出用户向量，物品塔输出物品向量，训练时让「点击过的用户—物品对」在向量空间里尽量靠近。听起来简单，但一个关键问题被悄悄绕过了——**召回的数据里只有正样本（用户点击/购买过的东西），负样本从哪来？**<span class="marginnote">召回与精排最大的差异就在这里：精排面对的是「候选集里选一个」，有明确的负例；召回面对的是「海量物品里挑几百个」，谁该被当成负例，本身就是一个设计问题。</span>

负采样决定了双塔模型学到什么、学成什么样。采样太随意，模型学不到区分度；采样太苛刻，又可能把模型带偏。这一节我们把它讲透：**负样本的本质、batch 内负采样的原理与偏差、以及难负样本如何补齐随机负样本的短板**。

## 1 召回训练的配对结构与 softmax 损失

双塔召回一般把训练建模成「**一个用户、一批物品**」的配对分类问题。对用户 $u$ 和正样本物品 $i^+$，我们希望用户向量与正样本物品向量的相似度，高于用户向量与任何负样本物品向量的相似度：

$$\text{score}(u, i) = \left\langle \mathbf{u}, \mathbf{v}_i \right\rangle$$

其中 $\mathbf{u}$ 是用户塔输出，$\mathbf{v}_i$ 是物品 $i$ 的物品塔输出，$\langle \cdot, \cdot \rangle$ 是内积（也可换成余弦）。配对的损失常用**带温度参数的 softmax 交叉熵**：<span class="marginnote">温度 $\tau$ 调节相似度分布的尖锐程度：$\tau$ 小则内积差异被放大，训练更「较真」；$\tau$ 大则更平滑、更鲁棒。它源自对比学习（见 [[word2vec-item-embedding]] 中负采样与温度的联系）。</span>

$$
L(u, i^+) = -\log \frac{\exp\left(\text{score}(u, i^+) / \tau\right)}
{\exp\left(\text{score}(u, i^+) / \tau\right) + \sum_{j \in \mathcal{N}_u} \exp\left(\text{score}(u, j) / \tau\right)}
$$

分子让正样本得分变高，分母里的负样本集合 $\mathcal{N}_u$ 让所有负样本得分变低。**理想情况下 $\mathcal{N}_u$ 应该包含「除 $i^+$ 外全库所有物品」**——但那意味着每次更新都要把几亿个物品过一遍物品塔，计算量不可接受。于是我们只能采样一小部分物品当作负样本。

## 2 负样本的本质：全量物品分布的一个估计

采样是有代价的：**分母从「全体物品」缩成「几个采样物品」，softmax 的分母被低估，损失函数就失真了**。更微妙的是，负样本的分布本身会塑造模型。

如果负样本全部来自「随机物品」（uniform 采样），模型学到的是「随机物品的向量离用户远」——这当然正确，但不够用。因为召回线上真正难的是区分「看起来都相关、但一个被点击一个没被点击」的物品对。随机负样本大多是「八竿子打不着」的物品，模型轻轻松松就能把它们推开，梯度信号很快饱和，**对精排阶段会挑出来的那些「近似相关」的物品毫无分辨力**。

因此现代双塔召回几乎总是**混合采样**：

- **随机负样本**：保证基础的正确性，让模型学会「不相关的物品要远离」。
- **难负样本（hard negative）**：让模型面对「只差一点就相关」的物品，逼它学到更细的边界。

## 3 batch 内负采样：零成本的随机负样本

在 batch 训练中，一个自然的想法是：**把同一个 batch 里「其他用户的正样本物品」当作当前用户 u 的负样本**。这就是 **batch 内负采样（in-batch negative sampling）**。<span class="marginnote">实现上几乎零成本：一个 batch 内所有用户的正样本物品构成一个共享的物品集合，任何一个用户都以「除自己正样本外」的全部 batch 内物品为负例。既不用额外采样，又能让所有物品塔向量在 batch 内被充分比较。</span>

假设 batch 大小为 $B$，用户 $u_b$ 的正样本是物品 $i_b$。batch 内负采样把损失写成：

$$
L(u_b, i_b) = -\log \frac{\exp(s(u_b, i_b) / \tau)}
{\sum_{b' = 1}^{B} \exp(s(u_b, i_{b'}) / \tau)}
$$

分母求和遍历 batch 内全部 $B$ 个物品。这有个隐藏的问题：**热门物品出现在 batch 里的概率远高于冷门物品**。于是「作为负样本的物品」的分布，不是全库物品的均匀分布，而是被「采样频率」扭曲过的分布——分母里热门物品出现次数过多，导致模型过分压低热门物品的得分。

## 4 公式解析：logQ 修正

Facebook 的 EBR 论文给出了对 batch 内负采样偏差的修正。**核心思想：把「被采样频率」从相似度里减掉，等效于在均匀采样假设下做无偏估计。**

$$
s^c(u, i) = s(u, i) - \log p(i)
$$

三步拆解这条公式：

- **第一步，认清偏差来源**：$p(i)$ 是物品 $i$ 被采样进 batch 的概率，近似等于它在训练流中的出现频率。热门物品 $p(i)$ 大，作为负样本被反复看到，模型会误以为它「天然不相关」。
- **第二步，理解减法的作用**：从得分中减去 $\log p(i)$，等价于对热门物品「网开一面」——虽然它总当负样本，但模型不再把它压得过狠。这相当于在分母里把采样概率给「除回去」。
- **第三步，直觉**：可以把 $s^c$ 看成「**排除曝光偏差之后的真实偏好**」：一个物品被频繁看到，不是因为用户不喜欢，而是因为它本来就热门。

没有 logQ 修正的后果很典型：**模型对热门物品的得分系统性偏低，召回结果偏向冷门**，离线指标看着不错、线上却丢了头部流量。修正后分布才回到「均匀负样本」的语义。

## 5 难负样本：从 batch 里挖，也单独造

batch 内负采样提供的是随机负样本。要获得难负样本，工业界常用两条路：

**第一条路：用上一个版本的模型挖难负样本（难负样本挖掘，hard negative mining）。** 拿当前模型对「用户—物品」打分，把「得分很高但用户并没有点击」的物品当成难负样本，混进训练。<span class="marginnote">注意挖出的难负样本可能本来就「真的相关」，只是用户没看到或没点。因此难负样本的比例要控制，通常随机负样本与难负样本按 4:1～10:1 混合，避免把「潜在偏好」误当「负反馈」学进模型。</span>

**第二条路：利用 batch 内「近似物品」做难负样本。** 在双塔里，batch 内得分最高的非正样本物品，天然就是当前 batch 里的难负样本。可以直接取 batch 内相似度最高的若干物品作为难负样本，无需额外计算。

| 负样本类型 | 来源 | 作用 | 风险 |
| --- | --- | --- | --- |
| 随机负样本 | 均匀采样 / batch 内 | 保证「不相关就远离」 | 对近似物品无分辨力 |
| 难负样本 | 前版模型挖掘 / batch 内高分项 | 逼模型学细边界 | 误伤真实偏好 |

## 6 工程上的一点提醒

- **温度参数 $\tau$ 要调**：$\tau$ 太小，难负样本造成的梯度震荡剧烈；$\tau$ 太大，模型分辨力不足。常见起搜范围 $0.05 \sim 0.2$。
- **batch 越大，in-batch 负样本越丰富**：但显存有限，可用「**跨 GPU 的 batch 内负采样**」把其他卡上的物品也拿来做负样本。
- **难负样本要有「新鲜度」**：固定难负样本会过拟合，定期用新模型重挖。
- 负采样与采样修正、多兴趣召回（[[mind-comirec-multi-interest-recall]]）配合时，修正项要按各自分布分别算。

## 辨析｜负采样相关的三个常见误区

负采样看似简单，工程上却藏着几个反复踩的坑：

**误区一：负样本越多越好。** 增加负样本能提升训练区分度，但比例失调会带来偏差——随机负样本太多，模型过度学习「把一切推开」，对「近似相关」的正例判断反而变钝；难负样本太多，则可能把「潜在偏好」学成「负反馈」。经验上先跑「随机:难负样本 ≈ 8:1」起步，再看指标调。

**误区二：batch 内负采样可以「零成本」地无限扩大 batch。** batch 越大 in-batch 负样本越丰富，但显存与跨卡通信成本随 batch 线性涨，且「热门物品重复出现」的频率也更高、logQ 修正的估计误差更大。**修正项 $p(i)$ 的估计本身要准**：用「物品在训练流中的出现频率」近似采样概率，需要单独统计并定期更新。

**误区三：难负样本挖出来就可以一直用。** 难负样本的「难度」会随模型更新而衰减——上一版模型的难负样本，新模型很快就能分辨。**定期重挖（如每若干轮用当前模型重新采样难负样本）才能维持难度**，否则难负样本退化成普通负样本。

**一个实用技巧**：把「模型预测概率偏高但未点击」的物品作为难负样本时，可以对预测概率做一次「截断」——只取概率在 $[p_{\text{low}}, p_{\text{high}}]$ 区间内的，过滤掉「预测最高」的极端值（那可能是真的相关），让难负样本集中在「模棱两可」的区域。

**一个提醒**：负采样方案要与「评估口径」绑定——离线评估召回率（[[recall-layer-evaluation-hit-rate]]）时，测试集的负样本分布也要与线上「曝光分布」一致；否则离线「看起来提升」的采样方案，线上未必兑现。

**最后一步自查**：写完负采样方案，回看「在线评估」——用「线上曝光分布」构造测试集负样本，确认离线指标与线上一致，才算「采样方案真的可用」。

## 7 小结

- 召回训练本质是「**用户 vs 一批物品**」的配对分类，损失是带温度的 softmax 交叉熵。
- 负样本是分母的估计，**分布决定模型学到的边界**，随机负样本与难负样本需要按比例混合。
- **batch 内负采样**零成本，但引入「按频率采样」的偏差，需用 **logQ 修正** $s^c = s - \log p$ 把偏差除回去。
- **难负样本**让模型区分「近似相关但没被点击」的物品，可从前版模型或 batch 内高分项挖掘，比例需控制。

在下一节，我们将回答：一个用户的兴趣往往不止一类，如何让召回「一个用户召回多条兴趣线」——这就是 **MIND 与 ComiRec 的多兴趣召回**。
