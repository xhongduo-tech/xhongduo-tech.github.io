## 为什么从范式演进开始

至此，我们已经走完了经典推荐系统的全部技术栈。本专题的最后一篇，回头看整个体系的演进脉络，并看向正在发生的范式转移：**从「ID 推荐」走向「语义推荐」**。<span class="marginnote">经典推荐（协同过滤、矩阵分解、深度排序）的核心是「ID 本位」：用户 ID、物品 ID 被 one-hot 成稀疏向量，模型学习它们之间的「共现关系」。这套体系极其有效，但也有天花板——ID 只是「编号」，不携带「这个物品是什么」的语义。大模型的出现，让「语义」第一次可以大规模地进入推荐。</span>

这一节梳理推荐范式的三阶段演进：**ID 推荐 → 特征/内容增强 → 语义推荐**，并指出每条路在解决什么、牺牲什么。

## 1 范式一：ID 推荐——「关系」本位

经典推荐的全部力量，来自「**谁和谁一起出现过**」：

- 协同过滤：用户点击过的物品集合 → 相似物品。
- 矩阵分解：把「用户 × 物品」共现矩阵分解成隐向量。
- 深度排序：ID embedding 进网络，学特征交互。

这套范式的优势：**数据就是行为，无需理解内容**，模式学习能力强；短板也明显：

- **冷启动困难**：新 ID 没有共现关系，向量无从学起（见 [[cold-start-classification]]）。
- **缺乏语义泛化**：模型只认识「见过一起出现的组合」，遇到「语义相似但没共现过」的组合就失灵。
- **ID 离散**：每个 ID 是一个独立符号，无法利用「物品本身的信息」。

## 2 范式二：内容增强——把「属性」塞进 ID

经典体系自己也在补短板：用物品的内容特征（类目、文本、图像）增强 ID 表示——这正是前面讲过的「内容推荐」与「双塔」：

$$
\mathbf{v}_i = f(\underbrace{\text{ID embedding}}_{\text{ID 本位}} + \underbrace{\text{content embedding}}_{\text{语义增强}})
$$

EGES（[[graph-embedding-recall-deepwalk-node2vec-pinsage]]）用属性 embedding 加权平均、双塔用内容 embedding 做物品表示。**这一阶段把「语义」作为「补充特征」加入了 ID 体系**，缓解冷启动、提升泛化，但语义仍是「辅助」——排序的主干还是 ID 驱动的。

## 3 范式三：语义推荐——把「理解」当主干

大模型带来的新范式是：**让「语义」成为推荐的主干，而非补充**。三个层次的「语义化」：

- **物品表示语义化**：不再只靠 ID embedding，而是用文本/多模态编码器把「物品的内容」编码成语义向量——**新物品一上线就有语义向量**（冷启动被结构性解决）。
- **用户表示语义化**：用户的兴趣可以用「自然语言」表达（「最近喜欢研究咖啡烘焙」），大模型理解语义化的用户画像。
- **推荐过程语义化**：用户意图、候选解释、甚至「为什么推荐这个」都能用自然语言生成（见 [[llm-as-feature-extractor]] 与 [[llm-prompt-based-recommendation]]）。

## 4 公式解析：ID 与语义的「表示对比」

把两代范式的表示差异形式化：

- **ID 表示**：物品 $i$ 的向量 = $\mathbf{e}_{\text{id}(i)}$——**只由「编号」决定**，两个语义几乎相同的物品（同款不同 ID）向量完全无关。
- **语义表示**：物品 $i$ 的向量 = $\text{Encoder}(\text{content}_i)$——**由「内容」决定**，语义相近的物品向量天然靠近。

$$
\text{ID: } \mathbf{v}_i = \mathbf{e}_{\text{id}(i)}, \quad \text{语义: } \mathbf{v}_i = \text{Encoder}(\text{text}_i, \text{image}_i, \dots)
$$

- **第一步，信息含量**：ID 向量只含「编号信息」，语义向量含「物品本身的信息」——**后者的信息量多一个量级**。
- **第二步，泛化方式**：ID 靠「共现」泛化（见过才认识），语义靠「相似」泛化（理解就认识）——**语义推荐对新组合的泛化能力结构性更强**。
- **第三步，权衡**：ID 的优点是「精确记住用户对特定 ID 的行为」（记忆性强，见 [[wide-and-deep]]）；语义的优点是「理解与泛化」。**工业趋势是「ID 与语义融合」**——保留 ID 的记忆，叠加语义的理解。

## 5 语义推荐带来的新问题

范式转移不是免费的，语义推荐有新的挑战：

- **语义 ≠ 偏好**：用户点「军事」内容，不代表「对军事的一切都点」——语义相似度高不等于用户偏好一致，需要「语义 + 行为」结合。
- **冷启动的新形态**：新物品有语义向量了，但「语义向量会不会被用户接受」仍然未知，探索仍需要（见 [[exploration-exploitation-problem]]）。
- **计算与成本**：语义编码（大模型）比查 ID 表贵得多，需要「离线编码 + 在线缓存」的工程设计。
- **可解释与可控**：语义推荐更容易解释（「因为你最近在研究咖啡」），但也更容易「过度泛化」。

## 辨析｜「ID 本位」的三点价值：别急着全盘抛弃

范式转移的文章容易给人「ID 该被淘汰」的印象——但 ID 本位有它不可替代的价值，理解这一点才能「正确地融合」：

**价值一：ID 是「行为记忆」的锚点。** 用户对「特定 ID」的行为记忆，是语义无法替代的——用户可能「就是喜欢某个具体作者/店铺」，不是因为「内容类型」。语义向量会说「这个人喜欢咖啡」，但只有 ID 向量能记住「他特别喜欢『XX 咖啡店』这一家」。**「偏好落在具体对象上」这件事，语义表示天然抓不住**。

**价值二：ID 处理「同义不同物」的能力。** 语义表示会把「语义相同」的物品「合并」——但「两本同名书」「两个同款但不同卖家的商品」语义一样、商业上完全不同。**ID 把「个体」分开，语义把「个体」合并**——在「个体很重要」的电商场景，ID 的「分」是必要的。

**价值三：ID 的「可解释性」在行为维度。** 「这个用户买过这个商品的类似品」——这种「行为上的相似」是最强的推荐理由。语义表示「内容相近」的解释，反而不如「行为相近」的解释有力（用户能听懂「因为你买过 X」）。**ID 体系天然贴近「行为解释」，语义体系贴近「内容解释」**。

**一句话**：范式演进不是「ID 被淘汰」，而是「ID 与语义互补」——**ID 管「记住具体的」，语义管「理解抽象的」**。工业趋势（也是本专题结尾的落点）是把两者的优势在一条链路上融合，而不是二选一。

**补充｜「语义推荐」的落地路径：不是「一步革命」，而是「渐进增强」**：

从「ID 推荐」到「语义推荐」的范式转移，工业上不是「一步切换」，而是「三条渐进路径」：

- **路径一：语义「补表示」**（最轻）：保留 ID 体系，用语义向量「增强」物品/用户表示——[[llm-as-feature-extractor]] 的「ID + 语义」融合。**改动小、风险低，先走这条**。
- **路径二：语义「开新路」**：在经典链路之外，用 LLM 开「语义召回」「语义解释」等「新模块」——[[llm-prompt-based-recommendation]]、[[llm-traditional-recsys-integration]]。**经典链路不动，新能力并行加**。
- **路径三：语义「成主干」**（最重）：全语义表示、生成式检索、对话式推荐——[[generative-retrieval-semantic-id-tiger]] 的方向。**代表未来，但目前「贵、慢、难控」，只在「新场景/长尾」试点**。

**一个判断**：**「语义推荐的收益」集中在「行为数据不足」的地方**（冷启动、长尾、新场景）——行为数据充足的「头部」，ID + 经典模型已经很强。**渐进增强的正确打开方式是「让语义补经典补不了的部分」**，而不是「推翻经典」。

## 6 小结

- 推荐范式三阶段：**ID 推荐（关系本位）→ 内容增强（语义作补充）→ 语义推荐（语义作主干）**。
- ID 范式强在「记忆共现」，弱在「冷启动与语义泛化」。
- 语义范式让「物品表示 = 内容编码」，**新物品结构性解决冷启动、泛化能力更强**。
- 现实路径是 **ID 与语义融合**：ID 保记忆、语义补理解；同时要处理「语义≠偏好」、编码成本、探索等新问题。
- **核心取舍**：ID 精确但孤立、语义泛化但可能过度——「融合」而非「二选一」。

**术语速查**：

| 术语 | 一句话 |
| --- | --- |
| ID 表示 | 由编号决定的向量，靠共现泛化 |
| 语义表示 | 由内容编码的向量，靠相似泛化 |
| 内容增强 | 用内容特征补充 ID 的中间阶段 |
| 行为记忆 | ID 对特定对象偏好的精确记录 |
| 渐进增强 | 语义补经典补不了的短板 |

**一个数值感**：两个「语义相同但 ID 不同」的物品，ID 表示下余弦相似度接近 0（编号无关）、语义表示下接近 1（内容相同）——**同一对物品，在两代范式里的距离判若云泥**。这正是语义推荐「新物品一上线就能被匹配」的数学来源，也是「ID 保记忆、语义补理解」互补的证据。

**一个演进观察**：ID → 内容增强 → 语义推荐，不是「三选一」而是「叠加演进」——每一代都保留前一代的能力、再补一层新能力：语义推荐仍然需要 ID 的记忆、内容增强的特征、以及行为数据的驱动。
