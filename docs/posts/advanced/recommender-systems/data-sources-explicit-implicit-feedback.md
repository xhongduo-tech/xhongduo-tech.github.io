## 为什么从数据开始

上一篇我们给推荐系统下了定义：分析用户与物品之间的交互历史，主动推荐可能感兴趣的物品。定义里最要紧的一个词不是「算法」，而是**交互历史**——推荐系统的所有判断都从数据里长出来。算法再精巧，若没有数据支撑，也只是空转的公式。<span class="marginnote">项亮在书中第 2 章开篇就强调：推荐算法的设计，很大程度上取决于它所使用的用户行为数据的形式。<strong>先有数据形态，后有算法设计</strong>——这个顺序在整本书里反复出现。</span>

这一篇要回答的问题很朴素：推荐系统到底「吃」什么数据？答案是两类信号——**显式反馈（explicit feedback）**与**隐式反馈（implicit feedback）**。它们的差别是理解后续所有算法的第一把钥匙：为什么有的算法需要评分矩阵、有的只需行为日志；为什么有些场景数据稀疏得吓人、有些却数据泛滥。先看清数据，再看算法，路才走得顺。

## 1 显式反馈：用户明说的答案

**显式反馈（explicit feedback）**：用户主动、明确地向系统表达自己偏好的行为。最典型的是**评分**——Netflix 的五分制星级、豆瓣的打分、电商的商品评价；此外还有**点赞 / 点踩、收藏、加入心愿单、写文字评论**。这些信号的共同点是：用户花力气「亲口告诉」系统自己喜欢什么、不喜欢什么。

显式反馈的价值在于**信号纯净**。用户打出 5 星，就表示他明确喜欢；打出 1 星，就表示他明确不喜欢。系统不用猜测意图，可以直接把评分当作「偏好强度」来用。<span class="marginnote">Netflix 在 2006 年发起「Netflix Prize」比赛，用 1–5 星评分数据做训练集，把 RMSE 作为官方指标，悬赏 100 万美元把预测误差降低 10%。这是「显式评分驱动推荐」的黄金年代，也是本专题第三篇《矩阵分解》最直接的动机。</span>

但显式反馈有一处致命伤：**贵而稀**。评分要用户专门花时间去打，绝大多数用户绝大多数时候不愿意打。一个典型电商平台的评分矩阵，非零元素常常不足 1%——这就是上一篇提到的**稀疏性**。想靠「用户亲口说的偏好」做推荐，往往会发现数据少到不足以支撑任何精细建模。

## 2 隐式反馈：行为留下的痕迹

**隐式反馈（implicit feedback）**：用户没有明确表达偏好，但在使用产品时被动留下的行为痕迹。电商里的**浏览、点击、加购、购买、搜索**，内容平台的**播放、看完、点赞、停留时长、滑动速度、快进快退**，都是隐式反馈。

隐式反馈的关键是**无需用户费心**——用户只是在正常使用产品，系统在后台把每一次行为记成一条日志。所以它的量级通常比显式反馈大几个数量级：一个用户一天可能产生几十次隐式行为，却难得打一次分。这是隐式反馈最大的资产：**多、便宜、持续产生**。<span class="marginnote">正因为如此，现代工业界推荐系统几乎都以隐式反馈为主战场——深度学习时代的推荐模型训练动辄消耗 TB 级行为日志，显式评分那点数据根本喂不饱它们。</span>

但隐式反馈也有一个根深蒂固的缺陷：**信号不干净，而且只有「正」没有「负」**。用户点了某个视频，说明他至少有点兴趣；但用户「没点」某个视频，能说明他不喜欢吗？不能——他可能根本没看到、没时间、或者压根没被推荐到。这就是常说的**单边数据（one-sided data）**问题：我们只观察得到「发生了的行为」，大量「未发生的行为」既可能是「不喜欢」，也可能是「没机会」。

## 3 核心对比：显式与隐式

把两条信号放在一张表里对照，差别一目了然：

| 对比维度 | 显式反馈 | 隐式反馈 |
| --- | --- | --- |
| 典型形式 | 评分、点赞/踩、收藏、评论 | 浏览、点击、购买、播放、停留时长 |
| 获取方式 | 用户主动表达（费力气） | 系统被动采集（无感知） |
| 数据量 | 稀疏、量小 | 稠密、量大 |
| 信号纯净度 | 高，意图明确 | 低，噪声大、需推断 |
| 正负信号 | 有明确正负（5 星 vs 1 星） | 只有正样本，缺失 ≠ 负样本 |
| 实时性 | 低频、延迟大 | 高频、接近实时 |
| 典型用途 | 评分预测、兴趣精调 | 召回、行为序列建模、CTR 预估 |

**辨析｜易错点：** 初学者常把「隐式反馈」当成「低配版显式反馈」——反正都是用户对物品的某种反应，归一化一下就能混用。这是错的。二者最本质的区别在**信号的语义**：显式反馈的评分自带「偏好强度」刻度，隐式反馈只告诉你「行为发生了」，偏好强度要靠**行为类型**去推断——看完一部电影，比点击它更能说明喜欢；买下了，比加入购物车更能说明想要。所以工业界会为不同行为赋予不同权重，形成一条**信号强度阶梯**：完整观看 / 购买 > 加购 / 收藏 > 点击 > 曝光。<span class="marginnote">这条阶梯正是第八篇《多目标与多任务学习》里「多行为建模」的雏形——同一个用户的不同行为被当成不同目标分别建模，再统一融合。</span>

## 4 公式解析：把「行为次数」翻译成「置信度」

显式反馈可以直接用评分 $r_{ui}$ 表示偏好强度，但隐式反馈只有一个行为计数 $r_{ui}$——比如「用户 $u$ 看了物品 $i$ 三次」。三次观看到底意味着多喜欢？我们需要一个把次数翻译成偏好的模型。Netflix 的 Koren 等人在 2008 年那篇经典的隐式反馈协同过滤论文里，给出了一个如今被广泛使用的翻译公式<span class="marginnote">这里引的是 Yifan Hu、Yehuda Koren、Chris Volinsky 的《Collaborative Filtering for Implicit Feedback Datasets》（KDD 2008）。这个公式直接孕育了本专题第三篇的 ALS-WR（加权交替最小二乘），到时候你会再次遇见它。</span>：

$$
c_{ui} = 1 + \alpha \, r_{ui}
$$

逐项拆解：

- **$r_{ui}$（行为计数）**：用户 $u$ 对物品 $i$ 产生的行为次数，如观看次数、购买次数。$r_{ui} \geq 0$，取值越大表示行为越频繁。它是隐式反馈里唯一能直接观测到的数字。
- **$c_{ui}$（置信度，confidence）**：我们对「用户 $u$ 喜欢物品 $i$」这一判断有多大的把握。$c_{ui}$ 越大，模型在拟合时就越要「迁就」这个判断。注意 $c_{ui}$ 不是偏好值本身，而是**这个偏好值有多可信**。
- **$\alpha$（置信度增长速率）**：一个超参数，控制「多看一次，置信度涨多少」。$\alpha$ 越大，行为次数对置信度的边际贡献越强；论文里常取 $\alpha \approx 40$ 这样的量级。
- **$+1$（基础置信度）**：最关键也最容易忽略的一项。它保证即使 $r_{ui} = 0$（用户从没碰过这个物品），$c_{ui} = 1$ 也大于零——因为我们并不能确定「没看过」就等于「不喜欢」，只能给它一个最低限度的、非零的把握。<span class="marginnote">正是这个「+1」承载了单边数据的哲学：<strong>未观测 ≠ 负样本</strong>。若把它取成 0，模型就会把「没见过」和「讨厌」混为一谈——这是处理隐式反馈最容易犯的错误之一。</span>

用一个具体数字感受它。设 $\alpha = 2$：某用户完整观看了一个视频 3 次，则 $c = 1 + 2 \times 3 = 7$；另一个视频他只点击过 1 次，$c = 1 + 2 \times 1 = 3$；还有一个从没出现过，$c = 1$。三条置信度 7、3、1，把「看了三遍 > 点过一次 > 没看过」的相对强弱干净地编码进了数值——这就是隐式反馈建模的第一步，也是后续矩阵分解里每一项权重的最初来源。

## 5 从日志到矩阵：行为数据的统一表示

无论显式还是隐式反馈，底层都是同一种东西：**一条条行为日志**。每条日志记录一件事——「用户 $u$ 在时刻 $t$ 对物品 $i$ 做了行为 $a$」。规范化之后，一条行为可以写成四元组：

$$
(u,\ i,\ a,\ t)
$$

项亮在书中 2.1 节正是用这四个字段统一了形形色色的行为数据：

- **$u$（用户）**：谁做的，如用户 ID 或设备 ID。它是「哪一行」的坐标。
- **$i$（物品）**：对谁做的，如商品 ID、视频 ID。它是「哪一列」的坐标。
- **$a$（行为）**：做了什么，这是显式与隐式反馈的落点——$a$ 可以是「评分 5 星」，也可以是「点击」「购买」「播放到 80%」。行为类型决定了这条日志的语义与权重。
- **$t$（时间戳）**：什么时候做的。它记录行为的先后与新旧，是后续一切「时间切分」「时间衰减」「序列建模」的前提。<span class="marginnote">时间戳常被初学者忽视，却是最容易「返工」的字段：没有时间，就无法区分「先看后买」还是「先买后看」，也无法做训练/测试集的合法切分——那是下一篇《实验方法》的地基。</span>

把海量四元组按用户与物品重新组织，就得到第一篇提到的**用户—物品矩阵 $R$**：第 $u$ 行第 $i$ 列填 $u$ 对 $i$ 的某种「交互值」。显式反馈填的是评分（空白处是没评过），隐式反馈填的是行为计数或置信度 $c_{ui}$。**矩阵只是日志的一种「视图」**——同一个日志集，可以投影成评分矩阵、行为计数矩阵、行为序列等不同形态，分别喂给不同的算法。下面这段代码把日志压成计数矩阵（可直接运行）：

```python
from collections import defaultdict, Counter

# 原始日志：每条 (用户, 物品, 行为, 时间戳)
logs = [
    ("u1", "i1", "click", "2026-08-01 10:00"),
    ("u1", "i2", "buy",   "2026-08-01 10:05"),
    ("u2", "i1", "click", "2026-08-01 10:10"),
    ("u2", "i1", "click", "2026-08-02 09:00"),
    ("u2", "i2", "view",  "2026-08-02 09:01"),
]

# 把日志压成「用户 × 物品」计数矩阵（隐式反馈的原始形态）
counts = defaultdict(Counter)
for u, i, a, t in logs:
    counts[u][i] += 1

# 稀疏存储：只打印非零项
for u in sorted(counts):
    print(u, dict(counts[u]))
# u1 {'i1': 1, 'i2': 1}
# u2 {'i1': 2, 'i2': 1}
```

**辨析｜易错点：** 原始日志里往往藏着「假行为」——用户误触、爬虫点击、刷单播放。把日志直接当真相喂进算法，等于把噪声当作信号。真实系统的第一步永远是**清洗**：去重、过滤异常行为、按业务口径定义「什么算一次有效行为」。「先清洗，再建矩阵」这个顺序，与「从极限到大模型」主线里「数据质量决定模型上限」的原则一脉相承。

## 6 数据的工程现实：日志、埋点与负样本的缺席

把概念落到工程上，还有三层现实需要面对：

**一切从日志开始**。离线实验、在线推荐，都依赖日志系统把用户行为原样记录下来。一条行为日志至少要包含三个要素：**用户 ID、物品 ID、行为类型与发生时间**。少了时间戳，就无法区分「先看后买」还是「先买后看」，也无法做时间窗口切分——那是下一篇《实验方法》的地基。<span class="marginnote">日志的采集与落库、特征的一致性校验，是第十二篇《推荐系统工程》的主题；现在只需记住：<strong>推荐系统的精度，不会超过它日志的精度。</strong></span>
- **隐式反馈没有「负样本」，得自己造**。模型的训练需要正负两类样本，可隐式反馈只有正样本。常见做法是**负采样（negative sampling）**：从用户没交互过的物品里随机抽一些当作负样本。抽多抽少、怎么抽，直接影响模型质量——这是本专题第五篇《召回策略》里双塔模型的核心话题，先在这里埋个伏笔。
- **信号会衰减与过时**。用户三个月前看了十遍《甄嬛传》，不代表现在还想看。行为数据要带时间衰减，越近的行为越重要——这是第七篇《序列推荐》要系统处理的问题。

**辨析｜易错点：** 很多人以为「数据越多越好」。对隐式反馈要警惕的是**垃圾进、垃圾出**——曝光但没点的数据、被机器人刷出来的播放量、用户误触产生的点击，都是噪声。反过来说，显式评分虽少，却常是「金样本」。所以工业界的普遍做法是**以隐式反馈为骨架（量）、以显式反馈为精调（质）**：海量隐式行为训练出兴趣的大致方向，少量显式信号把边界修准。这个「大语料预训练 + 少量精调」的思路，恰好和大模型训练的范式同构——大量廉价的自监督信号学通用表示，少量高质量标注做定向对齐，正是「从极限到大模型」主线上反复出现的一条旋律。

## 7 小结

- **数据先于算法**：推荐系统的设计起点是它吃什么样的数据；数据形态决定了算法形态。
- **显式反馈**：用户明说的偏好（评分、点赞、收藏），信号纯净但稀疏昂贵，正负明确。
- **隐式反馈**：行为留下的痕迹（点击、购买、播放、时长），量大廉价但噪声大，且只有正样本。
- **单边数据**是隐式反馈的核心难题：未发生的行为 ≠ 不喜欢，只能用置信度、负采样等技术迂回处理。
- **置信度模型** $c_{ui} = 1 + \alpha r_{ui}$ 把行为次数翻译成偏好可信度，是隐式反馈建模的第一块基石，也是第三篇 ALS-WR 的前奏。
