## 为什么从 LLM 与经典链路结合开始

前四节我们看了 LLM 在推荐里的各种形态：特征提取、直接推荐、生成式检索。它们的共同教训是——**纯 LLM 推荐还不够强（不了解行为先验、贵、慢），纯经典推荐有天花板（缺语义、难解释）**。于是工业界的共识是「**结合**」：LLM 进经典链路，各取所长。<span class="marginnote">结合的方式很像本专题反复出现的「双通道」思想（[[wide-and-deep]] 的记忆/泛化、[[mmoe-multi-gate-mixture-of-experts]] 的共享/专有）：经典链路提供「行为数据的精确记忆」与「毫秒级规模推理」，LLM 提供「语义理解」与「自然语言表达」，两者在一条链路上协作。</span>

这一节系统梳理 LLM 与经典推荐结合的三条主线：**召回增强、排序特征、解释生成**——这也是 LLM 进推荐最务实的落点。

## 1 召回增强：LLM 作为新一路召回

LLM 可以直接参与「从海量物品里捞候选」：

- **语义召回**：用 LLM 生成用户兴趣的语义查询，做语义检索——弥补「行为召回」对「新兴趣」的盲区。
- **生成式检索**：TIGER 式的「生成语义 ID」作为一路召回（[[generative-retrieval-semantic-id-tiger]]）。
- **查询改写/意图扩展**：把用户的稀疏行为「翻译」成丰富的兴趣描述，扩展召回的查询空间。

**召回层是 LLM 最合适的进场位置**：召回允许「粗」——LLM 提供「相关但不那么精确」的候选，后续排序再精细甄别。**多路召回体系（[[multi-channel-recall-design-principles]]）天然欢迎「新的一路」**，只要这路候选与现有路互补。

## 2 排序特征：LLM 语义信号进精排

LLM 的语义理解可以变成「排序特征」，进入经典精排模型：

- **语义相关性特征**：候选物品与用户近期兴趣的语义匹配分，作为一个新特征。
- **内容质量特征**：LLM 评估物品的标题质量、图文一致性、内容新鲜度。
- **兴趣-意图匹配**：LLM 判断「这个物品是否符合用户当前意图」，输出匹配分数。

$$
x_{\text{new}} = \left[ x_{\text{classic}}, \underbrace{\text{SemMatch}_{\text{LLM}}(u, i)}_{\text{LLM 语义特征}} \right]
$$

**LLM 特征进入排序的特征平台**（见 [[feature-platform-offline-online-consistency]]），与经典特征一起训练。收益：排序模型「看到」了语义维度；代价：LLM 特征计算贵，需离线算 + 在线缓存。

## 3 解释生成：推荐「为什么」的最后一公里

LLM 最独特的能力是**生成自然语言解释**——这是经典推荐完全做不了的：

- **「为什么推荐这个」**：根据用户历史与候选属性，生成「因为你最近看了 A，而这个和 A 类似」这类解释。
- **「这个怎么样」**：为候选生成摘要、卖点、适用场景。
- **「不满意换一批」**：理解用户的自然语言反馈（「太贵了」），调整推荐。

**解释生成的工程形态**：经典链路选出 top-N 后，LLM 为每条候选离线/在线生成解释文案，随结果一起展示——**LLM 不参与排序，只负责「说话」**，侵入性最小、风险最低。

## 4 公式解析：LLM 在链路中的「位置」分工

把 LLM 与传统链路的协作写成一个「分层分工」：

$$
\text{召回} = \underbrace{\text{行为召回} \cup \text{语义召回}}_{\text{经典 + LLM}} \to \text{精排} = f_{\text{classic}}(x_{\text{classic}}, x_{\text{LLM}}) \to \text{展示} + \text{LLM 解释}
$$

拆三步看分工：

- **第一步，召回层**：经典行为召回 + LLM 语义召回「多路融合」。LLM 负责「用户说不清、行为没记录的新兴趣」，经典负责「行为已经证明的稳定兴趣」——**互补**。
- **第二步，精排层**：经典深度模型（快、懂行为）为主，LLM 语义特征为辅。**排序的「主裁判」仍是经典模型**，LLM 只提供「加分项」——因为精排要毫秒级响应，LLM 全量推理不可行。
- **第三步，表达层**：展示后由 LLM 生成解释。**LLM 在链路中「越靠后越安全」**：召回粗用、排序特征用、解释随便用——越靠近展示端，对延迟与正确的约束越小，LLM 越能放开手脚。

## 5 结合的三个原则

- **各取所长**：LLM 的理解/表达，经典链路的记忆/规模——**不要用 LLM 硬做经典擅长的事（亿级排序），也不要用经典硬做 LLM 擅长的事（自然语言解释）**。
- **按延迟分配**：LLM 的昂贵计算放到「离线/低延迟敏感处」——语义向量离线编码、解释离线预生成、线上只查缓存。
- **可回退**：LLM 模块随时可关——语义召回失败退回纯行为召回，解释生成失败退回「不解释」。**LLM 是增强，不是依赖**。

## 6 展望：从「结合」到「融合」

结合是当前主流，融合是方向：

- **端到端语义推荐**：物品/用户全语义表示，排序模型直接吃语义向量（ID 逐渐退场）。
- **推荐即对话**：LLM 作为交互界面，用户用自然语言表达需求，系统实时调整推荐（多轮、可解释、可纠偏）。
- **生成式整体链路**：召回、排序、重排逐步「生成化」，经典打分环节被生成决策替代。

**不变的内核**：无论范式怎么变，「理解用户、匹配物品、表达理由」这个三角始终是推荐的本质——LLM 让后两者第一次有了质变。

## 辨析｜LLM 进推荐的三条「评估」铁律

LLM 与传统链路结合后，「怎么评估」比「怎么接」更难——LLM 带来的收益与风险都需要专门的手段验证：

**铁律一：评估要「分模块」而不是「看整体」。** LLM 可能同时做了「语义召回 + 解释生成」——整体指标涨了，不知道是哪块的功劳；降了，不知道是哪块拖的后腿。**正确做法**：每个 LLM 模块「独立开关」（feature flag），A/B 实验「逐模块开关」，单独归因每块的增益。这是「模块化集成」的必然要求。

**铁律二：评估要「防解释幻觉」与「防语义偏见」。** LLM 生成的解释可能「听起来合理但实际错误」（幻觉：编造「你买过 X」其实没买过）——**解释的「真实性」要单独校验**。更隐蔽的是「语义偏见」：LLM 的语义表示可能在「性别、地域」等维度上有偏，导致语义推荐「系统性偏向某些人群」——**LLM 推荐的公平性要专门审计**（见 [[multi-objective-ranking-click-duration]] 的生态目标视角）。

**铁律三：评估要「与经典基线对比」而不是「与无推荐对比」。** LLM 推荐上线，对比对象应该是「成熟的双塔 + 精排 + 重排」经典链路，而不是「什么都不做」。**很多 LLM 推荐「看起来惊艳、指标平平」**——因为经典链路在「行为数据充足」的场景已经很强，LLM 的语义增益主要落在「行为数据不足」的长尾与冷启动。**评估要分层看：头部（行为充足）、长尾（行为稀疏）、冷启动（无行为）分别报指标**，才能看清 LLM 到底补了哪块。

**一句话**：LLM 进推荐的价值「看得见摸不着」——必须「逐模块开关 + 防幻觉偏见 + 分层对比基线」，三件事一起做，才能确认 LLM 是真增益还是「高级的装饰」。

## 7 小结

- LLM 与传统推荐结合的三条主线：**召回增强（新一路语义候选）、排序特征（语义信号进精排）、解释生成（自然语言说理由）**。
- 分工原则：**召回层粗用、精排层当特征、表达层放开用**——越靠展示端，LLM 越安全。
- 结合要点：**各取所长、按延迟分配、模块可回退**。
- 从「结合」走向「融合」：端到端语义、对话式推荐、生成式链路——但「理解-匹配-表达」的本质不变。

至此，从基础算法到大规模在线服务、再到 LLM 推荐的完整图谱已经画完。愿你带着这套「从极限到大模型」的推荐系统全景，去构建下一个真正理解用户的系统。
