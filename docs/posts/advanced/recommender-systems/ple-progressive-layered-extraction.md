# PLE：渐进分层抽取与任务间冲突缓解

## 为什么从 PLE 开始

MMOE 让任务「按需取用」专家，但所有专家都是**共享的**——任务再冲突，也还是从同一个专家池里挑。腾讯在 2020 年提出 PLE，理由是：**真正互斥的任务，需要的不是「挑选」，而是「各立门户」**——每个任务要有自己的专家，同时保留一部分共享专家用于「互通有无」。<span class="marginnote">PLE 的洞察来自一个常见场景：短视频里「完播时长」与「点踩举报」可能高度负相关。这种任务塞进同一个专家池，无论怎么门控，专家都得「左右互搏」。PLE 的解法是显式分层：任务独有专家各干各的，共享专家负责「两边都能用的知识」。</span>

这一节讲 PLE 的 CGC 结构、多层渐进抽取、以及它在推荐任务上的表现。

## 1 从 MMOE 到 CGC：显式分出「共有」与「独有」

PLE 的第一版结构叫 **CGC（Customized Gate Control）**，它在 MMOE 基础上加了一层「任务独有专家」。对任务 $k$：

$$
\mathbf{h}_k = \underbrace{\sum_{e \in \text{shared}} g_k^s(x)_e \, f_e^s(x)}_{\text{共享专家}} + \underbrace{\sum_{e \in \text{specific}_k} g_k^t(x)_e \, f_e^k(x)}_{\text{任务 } k \text{ 独有专家}}
$$

每个任务的表示 = **共享专家的门控加权 + 自己独有专家的门控加权**。相比 MMOE：<span class="marginnote">关键区别在「独有专家」：任务 A 的独有专家只被任务 A 的梯度更新，绝不被任务 B 污染；共享专家则被所有任务共同更新。CGC 因此给了「完全冲突的任务」一个「互不干扰」的物理隔离空间。</span>

- **共享专家**：承担任务间可复用的知识（如通用的用户兴趣表示）。
- **任务独有专家**：只服务单个任务，防止冲突任务的梯度互相破坏。

## 2 PLE：多层渐进抽取

CGC 只有一层专家。PLE 把 CGC 结构**堆叠成多层**，每一层都对输入做「共享 + 独有」的抽取，层与层之间渐进提炼：

- **第 1 层**：接收原始特征，做粗粒度的共享/独有抽取。
- **第 2 层**：把第 1 层的输出（各任务的表示）作为输入，再做一层抽取。
- …… 逐层往上，**每层的输出都是「渐进精化」的任务表示**，直到最后一层接各任务的输出塔。

这被称为「**渐进分层抽取（Progressive Layered Extraction）**」：每一层都显式区分「通用知识」与「任务知识」，避免深层网络把两者搅在一起。模型名字 PLE 正来源于此。

## 3 公式解析：多层结构里的「信息流」

把 PLE 的每层抽取拆三步：

- **第一步，单层内部**：每层对每个任务 $k$ 计算 $\mathbf{h}_k^{(l)}$，公式与 CGC 相同——共享专家与任务独有专家分别门控加权。**输入是上一层的所有任务表示**。
- **第二步，跨层传递**：第 $l+1$ 层的输入是第 $l$ 层输出的全部 $\mathbf{h}_k^{(l)}$。**共享专家看到「所有任务上一层的表示」，独有专家只看「自己任务的表示」**——任务 A 的知识可以通过共享专家传到任务 B 那一侧，但不会直接进入任务 B 的独有空间。
- **第三步，结构收益**：层数加深让模型能学「低阶共享、高阶分化」的模式——浅层处理通用特征，深层处理任务差异。**这比「共享到底层、顶层才分叉」的硬共享更能平衡通用与特化**。

## 4 PLE 与 MMOE 的对比

| 维度 | MMOE | CGC / PLE |
| --- | --- | --- |
| 专家类型 | 全部共享 | 共享 + 任务独有 |
| 任务隔离 | 无（靠门控选择） | 显式（独有专家物理隔离） |
| 极端冲突任务 | 仍互相干扰 | 独有空间不干扰 |
| 层级 | 单层 | 可多层渐进抽取 |
| 参数规模 | 中 | 较高（多套独有专家） |

**代价**：PLE 的参数量随任务数线性增长（每个任务一套独有专家），训练更重；但换来的是**对任务关系更精细的建模**。在腾讯视频等场景，PLE 相对 MMOE 在多个目标上同时提升，成为多目标建模的重要升级。

## 5 工程要点

- 任务数 $m$ 与独有专家数直接决定参数量，**任务太多时共享专家占比要调高**，避免参数爆炸。
- 共享/独有专家的比例是超参：任务相关性高 → 多共享；相关性低 → 多独有。
- PLE 常与 MMOE 做对比实验选择——**先 MMOE 起步，任务冲突明显再升级 PLE**。
- 多目标之外，PLE 也适用于「多场景」建模（首页/搜索/广告共用底座）。

## 辨析｜PLE 与 MMOE 的选型：何时值得「为任务隔离付费」

PLE 比 MMOE 多一套「任务独有专家」，参数更重、结构更复杂。选型的关键是判断「任务冲突到底有多严重」：

**信号一：任务相关性矩阵。** 上线前算各任务「梯度/指标」的相关性——若任务高度正相关（点击与时长通常正相关），共享专家就能处理，MMOE 够用；若存在「负相关任务」（如「快速完播」与「深度互动」可能冲突、或「点击」与「不误点」这类），独有专家的隔离才有价值。

**信号二：MMOE 的表现。** 最直接的判断：**先上 MMOE，看是否出现「任务互相拖累」**——某个任务的指标单独训练时更高、联合后明显下降。若联合训练让某任务「明显被牺牲」，说明任务冲突严重，此时升级 PLE 的「独有空间」通常能救回来。

**信号三：任务数。** 任务越多，共享专家越容易被「平均化」、每个任务越需要「自己的地盘」。任务数从 2 涨到 5+ 时，PLE 的相对收益通常上升——**但参数也随任务数线性涨**，需要权衡。

**一个工程提醒**：PLE 的「共享/独有比例」是超参，且各任务的「独有专家」数量可以不同——重要任务（如核心转化）给更多独有专家，次要任务少给。**隔离不是「平均分配」**，而是按任务重要性倾斜。

**一句话**：MMOE 是「默认选择」，PLE 是「冲突明显的升级」——先看任务相关性、先跑 MMOE，再决定要不要为隔离付费。

**补充｜PLE 的「参数与显存」预算与「共享/独有配比」**：

PLE 的参数量比 MMOE 大（多了每任务的独有专家），工程上有几个预算要点：

- **显存估算**：参数 ≈「共享专家」+「各任务独有专家」× 任务数。任务 5 个、每专家 2 层 512 维，参数量就上亿——**上线前先算「模型文件大小 + 加载显存」**，再决定「专家规模」。
- **共享/独有配比**：不是「各一半」——**任务相关性高，共享占比高（如 70% 共享、30% 独有）；相关性低或冲突明显，独有占比高**。配比是「可调的超参」，按「任务相关性矩阵」初设，再按指标微调。
- **独有专家按任务「倾斜」**：核心任务（GMV、核心转化）给「更多、更宽」的独有专家，次要任务（辅助信号）少给——**「隔离」也要「按重要性分配资源」**。
- **与 MMOE 的「渐进切换」**：先跑 MMOE，若「负迁移明显」再切 PLE——切换时「共享专家」可以「从 MMOE 的专家池初始化」，让「历史训练成果」不浪费。

**一个提醒**：PLE 的「多层堆叠」不是「越深越好」——层数加深让「参数翻倍、训练更不稳」，通常 1~3 层已够；「渐进抽取」的价值在「结构」，不在「深度」。

## 6 小结

- MMOE 的专家全是共享的，**PLE 显式分出「共享专家 + 任务独有专家」**，给冲突任务物理隔离空间。
- **CGC** 是单层的「共享 + 独有」门控结构；**PLE** 把它堆叠多层，逐层渐进抽取。
- 跨层信息流：共享专家可以传通用知识，独有专家只收本任务的梯度——**「共有」与「私有」分离**。
- PLE 参数更重，但更精细；**先 MMOE 起步、冲突明显再上 PLE** 是稳妥路线。
- **工程要点**：共享/独有配比按任务相关性调，核心任务给更多独有专家，参数与显存先算账。

**术语速查**：

| 术语 | 一句话 |
| --- | --- |
| 共享专家 | 所有任务共同更新的专家 |
| 任务独有专家 | 只被本任务梯度更新的专家 |
| CGC | 单层「共享 + 独有」门控结构 |
| 渐进抽取 | 多层堆叠、逐层提炼任务表示 |
| 任务相关性 | 度量任务间梯度/指标的关系 |

**一个数值感**：设任务 A（点击）与任务 B（点踩）负相关。MMOE 里两个任务的梯度同时更新同一个专家池，专家被迫「取平均」，两个任务都学不好；PLE 给 A、B 各配独有专家，A 的独有专家只管点击、B 的只管点踩，共享专家只学「通用兴趣」——**冲突被物理隔离在各自地盘之外**。

**一个选型清单**：任务数 ≤ 2、相关性高 → MMOE 足够；任务数 ≥ 3、存在负相关或明显冲突 → 考虑 PLE；任务更多、共享专家被平均化 → 独有专家配比要提高。**「冲突越明显，越值得为隔离付费」**。

**一个训练提示**：PLE 的多层堆叠训练更不稳，常见做法是「逐层预训练 + 全局微调」——先把底层共享专家训稳，再叠加高层抽取层，避免「一上来就端到端」导致梯度爆炸或塌缩。

**一个对照**：PLE 与 MMOE 的差异本质是「隔离的粒度」——MMOE 靠门控选择实现软隔离，PLE 用独有专家实现硬隔离；软隔离灵活但冲突任务仍可能互相拉扯，硬隔离彻底但参数更贵。**从 MMOE 到 PLE，是从「选」到「分」的升级**。

**一个提醒**：别把「任务独有专家」当成「把多任务拆成多个单任务」——PLE 仍保留共享专家与门控，任务之间仍能借力；「独有」是「隔离冲突」，不是「切断共享」。
