## 为什么从物品属性开始

新用户冷启动用「人群特征」和「主动反馈」，新物品冷启动则相反：**物品没有行为，但物品的内容自带信息**。一部新电影有导演、类型、时长；一件新商品有类目、品牌、价格；一条新资讯有标题、关键词。<span class="marginnote">物品冷启动与基于内容推荐（[[content-based-filtering-framework-item-user-profiles]]）共用同一套工具箱：把「物品是什么」翻译成特征。区别在于目的——内容推荐是常态建模，物品冷启动是「行为为零时的临时方案」，二者常常融合。</span>

这一节讲物品属性如何被利用：如何让新物品「挤进」向量空间、如何利用相似物品迁移、以及探索性曝光的配合。

## 1 物品属性：新物品的「天生画像」

新物品能拿到的信号全部来自**内容属性（content features）**，按结构化程度分三类：

| 类型 | 例子 | 表示方式 |
| --- | --- | --- |
| 类别属性 | 类目、品牌、作者、导演 | one-hot / embedding |
| 文本属性 | 标题、描述、标签 | TF-IDF / 词向量 / 文本 embedding |
| 多模态属性 | 封面图、音频、视频帧 | 视觉/音频 embedding |

这些属性**不需要任何用户行为**，物品一创建就有——它们是物品冷启动的全部弹药。

## 2 关键思想：用属性映射到已有向量空间

物品冷启动的核心操作是：**把新物品从「行为空间」映射到「属性空间」，再在属性空间里与已有物品对齐**。

例如用文本属性：新物品的标题/描述经过与已有物品相同的文本编码器（如 [[text-representation-tfidf-bag-of-words]] 的 TF-IDF，或 [[word2vec-item-embedding]] 的 embedding），得到向量：

$$
\mathbf{a}_{\text{new}} = \text{Encoder}(\text{text}_{\text{new}})
$$

**只要编码器对「新旧物品」用的是同一套**，新物品就落进了「与已有物品可比」的向量空间——可以用「与旧物品的向量相似度」来推测它该推荐给谁。

## 3 公式解析：从属性到「可推荐性」

把新物品的冷启动打分拆三步：

- **第一步，属性向量**：$\mathbf{a}_{\text{new}}$ = 新物品的内容 embedding。类目、文本、图像各出一个向量，可拼接或加权融合。
- **第二步，相似旧物品**：$\text{sim}(\mathbf{a}_{\text{new}}, \mathbf{a}_j)$ 是「新物品与旧物品 $j$ 的属性相似度」。**旧物品有行为数据，它们的「该推荐给谁」是已知的**。
- **第三步，迁移打分**：新物品的冷启动得分由「相似旧物品的表现」加权迁移而来：

$$
\hat{y}(u, i_{\text{new}}) \approx \sum_{j \in \text{TopSim}} \frac{\text{sim}(\mathbf{a}_{\text{new}}, \mathbf{a}_j)}{\sum \text{sim}} \, \hat{y}(u, j)
$$

即**「新物品 = 属性最像的几个旧物品的加权平均」**。旧物品「在用户身上表现好」，新物品就「借」这个表现。

## 4 相似物品迁移的两种工程形态

属性迁移在工程上有两种落地：

- **物品冷启动「代偿向量」**：为没有 embedding 的新物品，用相似旧物品 embedding 的加权平均作为临时 embedding，直接进向量召回/排序。等它有了真实行为，再换成自己的 embedding——**临时替身**。
- **内容到内容（C2C）的协同**：构建「物品属性相似度表」，新物品上线时查表拿到「相似旧物品」，复用它们的「用户」关系。这是 [[content-based-filtering-framework-item-user-profiles]] 与协同过滤的混合（[[hybrid-recommendation-content-collaborative]]）。

## 5 探索性曝光：给新物品「破零」

属性迁移给了「起始画像」，但**没有真实行为的画像终究是估计**。工业界必须配合**探索性曝光**：把新物品注入小流量，用真实反馈验证/修正：

- **加噪 Embedding**：给新物品 embedding 加少量随机噪声再进召回，制造「少量曝光」。
- **探索通道**：在召回/排序链路专门留「新物品探索位」，保证新内容有固定比例的展示机会。
- **探索预算**：用 Bandit 思想（见 [[exploration-exploitation-problem]]）分配「探索多少新物品」与「利用多少已验证物品」。

**属性建模解决「能不能被看见」，探索曝光解决「看见之后有没有反馈」**——两者缺一不可。

## 辨析｜物品冷启动的三条落地链路与「质量」陷阱

物品冷启动的工程落地有三条常见链路，各有适用与陷阱：

**链路一：属性 → 相似旧物品 → 迁移打分。** 新物品靠「内容相似度」找到旧物品，借用旧物品的「用户」关系。**陷阱**：相似度用什么度量？文本关键词重合度容易「抓错重点」（标题都含「新品」就被判相似）；向量语义相似度更稳，但依赖编码质量（见 [[llm-as-feature-extractor]] 的语义表示）。**关键**是「相似」要贴合「用户为什么喜欢」——最好用「行为验证过」的相似度（两个物品常被同一批用户喜欢），而不是纯文本相似。

**链路二：属性 → 直接进双塔/排序。** 新物品用内容 embedding 当物品向量，直接进 [[two-tower-model-vector-recall]] 或排序模型。**陷阱**：内容 embedding 与「行为 embedding」在向量空间里可能「不兼容」——内容相近不等于行为相近。常见解法是「混合向量」：新物品先用内容向量「占位」，等有行为后逐步过渡到「行为主导的向量」。

**链路三：探索曝光 → 行为积累。** 属性建模让新物品「能被看见」，真正「立得住」靠探索曝光积累行为。**陷阱**：探索曝光要给「足量且分散」的机会——只在新品池里随机试，或只在冷门位置试，都会让「好物品」被埋没（见 [[exploration-exploitation-problem]]）。

**一个质量提醒**：物品冷启动最常见的失败不是「没方法」，而是「属性质量差」——类目乱标、标题党、图片与内容不符，会让「属性相似」变成「错误相似」。**清洗与标注是物品冷启动的第一优先级**。

**一句话**：三条链路（迁移、进模型、探索）要组合用——属性给「起始画像」，迁移给「初始关系」，探索给「真实反馈」，三者缺一不可。

**补充｜物品冷启动的「多模态」与「语义化」升级**：

前面讲的物品属性以「文本/类目」为主，现代物品冷启动有两个升级方向：

- **多模态属性**：视频用「封面图 + 标题 + 音频」、商品用「主图 + 描述 + 规格」——**不同模态的 embedding 融合**（拼接、注意力加权），让新物品的「画像」更立体。多模态编码的细节见第四级《多模态学习》专题。
- **语义化属性**：用 LLM 给新物品生成「语义向量」（[[llm-as-feature-extractor]]）——**新物品一上线就有「语义身份」**，冷启动从「找相似旧物品」升级成「按语义直接匹配用户兴趣」，这是「语义推荐」范式（[[recommender-paradigm-evolution-id-to-semantic]]）在物品冷启动上的落地。

**一个提醒**：属性/语义给的是「起始画像」，但「用户会不会接受」仍然未知——**属性建模 + 探索曝光**是「能不能被看见」与「会不会被喜欢」的两个环节，缺一不可（呼应 [[exploration-exploitation-problem]]）。

## 6 小结

- 新物品的弹药是**内容属性**：类目、文本、多模态，创建即得、无需行为。
- 核心操作是**用同一套编码器把新物品映射进已有向量空间**，与旧物品对齐。
- 冷启动打分 = **相似旧物品表现的加权迁移**；工程形态是「临时替身 embedding」或「内容到内容协同」。
- 属性建模之外必须配**探索性曝光**：属性给起始画像，探索给真实反馈。
