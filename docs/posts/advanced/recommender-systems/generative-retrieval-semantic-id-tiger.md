## 为什么从生成式检索开始

上一节的生成式推荐有个瓶颈：**LLM 的「词汇表」是词，而推荐要输出「物品」**。物品有上亿个，不可能让 LLM 把每个物品当成一个「词」来生成。怎么让生成式推荐「够得到」亿级物品？答案是把物品编码成 LLM 能生成的「符号」——**语义 ID（semantic ID）**。<span class="marginnote">这就像给每个物品起一个「可拼写的名字」：LLM 学会了「怎么拼出用户想要的物品的名字」。TIGER（2023，Google）把物品 ID 用 RQ-VAE 量化成语义编码，让推荐变成「自回归地生成一段物品编码」，首次让「生成式检索」在十亿级物品上可行。</span>

这一节讲生成式检索的核心：**语义 ID 怎么构造、TIGER 怎么做生成式推荐、以及它与传统检索的对比**。

## 1 问题：LLM 无法直接「生成」亿级物品

生成式模型输出的是「词汇表上的分布」。想让 LLM 生成「第 7 号物品」，有两条路：

- **每个物品一个 token**：十亿物品 = 十亿词表，训练与解码的 softmax 不可行。
- **物品编码成 token 序列**：把物品 ID 表示成一段「小词表」上的编码——每个物品 = 几个 token，LLM 生成「这段编码」即可指认物品。**这就是语义 ID 的思路**。

## 2 语义 ID：把物品编码成「可生成的符号」

**语义 ID（semantic ID）** 是用「物品内容」生成的一段离散编码：语义相近的物品，编码也相近。TIGER 用 **RQ-VAE（残差量化变分自编码器）** 把物品的内容 embedding 量化成语义 ID：

1. **物品内容编码**：物品（标题/图片）经过编码器得到连续向量。
2. **残差量化**：把连续向量量化为「多级码本索引」——第一级码本记「大方向」（类目级），残差逐级细化，得到一串离散编码。
3. **语义 ID** = 这串编码（如 `[code_1, code_2, code_3]`），词表小（如每级 2048 个码），但组合起来能表达亿级物品。

$$
\text{semantic\_id}(i) = \text{RQ-VAE}(\text{content}_i) = [c_1, c_2, c_3]
$$

**语义 ID 的关键性质**：它是「离散的」（LLM 可生成）、「语义的」（相近内容编码相近）、「分层的」（前几位是大类、后几位是细类）。

## 3 TIGER：把「召回」变成「序列生成」

**TIGER（Transformer-based Index for Generative Recommendation，2023）** 的推荐流程：

1. **离线**：用 RQ-VAE 把所有物品编码成语义 ID；把「用户历史物品的语义 ID」与「下一个物品的语义 ID」配对，训练一个 Transformer（生成式）。
2. **在线**：给定用户历史序列，Transformer **自回归地生成一段语义 ID**——这段 ID 就是「预测的用户下一步想要物品」。
3. **解码映射**：生成的语义 ID 反查回具体物品（用索引表），得到推荐候选。

训练目标（生成式）：

$$
\Pr(\text{sem\_id}(i_{t+1}) \mid \text{sem\_id}(i_1), \dots, \text{sem\_id}(i_t))
$$

**TIGER 把「向量检索」换成了「序列生成」**——不再在向量空间里搜最近邻，而是让模型「说出」用户要的东西。

## 4 公式解析：RQ-VAE 的分层量化

把语义 ID 的「分层」拆三步：

- **第一步，第一级量化**：内容向量 $z$ 找到最近的「一级码」$c_1$（用一级码本），量化后还剩残差 $r_1 = z - \hat{z}_1$。
- **第二步，残差逐级量化**：对残差 $r_1$ 再找最近的「二级码」$c_2$，残差再减；重复直到 $L$ 级。**每一级编码「上一级没说完的部分」**：

$$
r_l = r_{l-1} - \hat{z}_l, \quad \text{sem\_id} = [c_1, c_2, \dots, c_L]
$$

- **第三步，信息分层**：$c_1$ 捕获「大主题」（如电影类型），后面的码捕获「细节」（导演、风格）。**因为残差量化，语义 ID 天然是「粗→细」的分层结构**——这与「先类目、后细类」的推荐层级思维一致，也便于「生成的 ID 逐级验证」：前几级对了，大致方向就不会错。

## 5 生成式检索 vs 向量检索

| 维度 | 向量检索（ANN） | 生成式检索（TIGER） |
| --- | --- | --- |
| 索引 | 向量库 + ANN 索引 | 语义 ID 的索引表 |
| 查询 | 用户向量 × 物品向量 | 生成「物品编码」 |
| 复杂度 | 检索式（近似搜索） | 生成式（自回归解码） |
| 泛化 | 依赖向量空间相似 | 依赖语义编码结构 |
| 冷启动 | 新物品要有向量 | 新物品要有语义 ID |

**生成式检索的优势**：**索引不随物品增长而变重**（解码只需查 ID 表）、天然生成「序列整体」（可做列表级推荐）、语义编码可解释。**劣势**：解码慢（自回归）、生成的 ID 可能非法（需校验）、训练要端到端学「编码 + 生成」两条腿。

## 6 生成式检索的工程现实

- **解码加速**：自回归生成要控制长度（语义 ID 通常 3~6 级），用束搜索/并行解码降延迟。
- **合法性校验**：生成的语义 ID 可能没有对应的真实物品，需「回退到最近合法 ID」或「校验失败则用向量召回兜底」。
- **与经典链路结合**：TIGER 常作为「召回一路」，与其他召回（双塔、图）融合——**生成式检索不是取代向量检索，而是新的一路候选来源**（见 [[multi-channel-recall-design-principles]]）。

## 辨析｜生成式检索的「三个工程决策」：量化、解码与兜底

生成式检索的落地不只是「训一个 Transformer」，三个工程决策决定它能不能「真上线」：

**决策一：语义 ID 的「码本规模」与「级数」。** RQ-VAE 的码本大小（每级多少码）与级数（$L$）共同决定「表达能力 vs 生成难度」：码本太小或级数太少，表达不了亿级物品的区分度（两个物品可能共享同一语义 ID）；级数太多，解码的「自回归步数」变长、推理变慢。**经验平衡**：级数 3~6、每级码本 1024~8192，按「物品总量」与「解码延迟预算」调。

**决策二：解码的「束搜索」与「延迟」。** 生成式检索的自回归解码是延迟瓶颈。常用手段：

- **束搜索（beam search）**：每次保留 top-$k$ 个「部分 ID」，最后选「整体最优」——质量高但慢。
- **限长解码**：语义 ID 级数固定（如恒 4 级），解码步数确定，避免「生成长度不定」的失控。
- **提前退出**：前 1~2 级就能确定「大类」时，可先粗筛再细生成——与「粗排/精排」的分层思想一致。

**决策三：生成结果的「合法性校验」与「兜底」**。LLM 生成的语义 ID 可能「没有对应的真实物品」（码本组合存在但没物品落在那里）。**必须**：解码后查「ID → 物品」映射表，查不到就「回退到最近合法 ID」或「丢弃」。**更稳的做法**：生成式检索作为「一路召回」，与其他路（双塔、图）融合——生成失败就「少一路」，不致命（[[multi-channel-recall-design-principles]]）。

**一个评估提醒**：生成式检索的「召回率」不能只看「生成的物品对不对」，还要看「覆盖」——**如果生成结果集中在「少数热门语义 ID」，召回率虚高但多样性差**（见 [[recall-layer-evaluation-hit-rate]]），要配合「多样性」一起评估。

**一个展望**：生成式检索的「语义 ID」不只是「召回的索引」，它本身是「可解释的推荐理由」——「生成出的语义 ID 前几级落在哪个类目」，就能解释「模型认为用户想要哪一类内容」。这与 LLM 推荐的「可解释性」诉求（[[llm-traditional-recsys-integration]]）打通，是生成式检索的额外红利。

**收尾一句话**：生成式检索是「把『搜向量』换成『报名字』」的范式跃迁——它最值得盯的不是「能不能跑通」，而是「语义 ID 的编码质量」决定了「报名字」报得准不准。

（生成式检索的「报名字」逻辑：**只要每个物品都有「可拼写的名字」（语义 ID），推荐就从「搜空间」变成「报名字」**——而「名字起得好不好」（RQ-VAE 的编码质量），决定了这套范式能走多远。）

## 7 小结

- **生成式检索**用「语义 ID」把物品编码成 LLM 能生成的符号，让推荐从「搜向量」变成「报名字」。
- **语义 ID** 由 RQ-VAE 残差量化而来：**离散、语义、分层（粗→细）**。
- **TIGER** 用 Transformer 自回归生成「下一个物品的语义 ID」，离线编 ID、在线生成、解码映射回物品。
- 对比向量检索：索引轻、生成整体、可解释；代价是解码慢、需校验。
- 工程上常作为**召回新一路**，与经典检索融合，而非取代。
