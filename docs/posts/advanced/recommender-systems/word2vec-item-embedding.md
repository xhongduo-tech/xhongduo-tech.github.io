## 为什么从词向量开始

上一篇我们拿到了一张能算余弦的 TF-IDF 向量，但它的三宗罪同样醒目：**高维稀疏、词面无语义、新词失明**。「电影」和「影片」明明是同一个意思，TF-IDF 却让它们毫不相干。推荐系统要推荐的恰恰是「相似的意思」，而不只是「相同的字」。

这一篇介绍的 Word2Vec（Mikolov 等，2013）是 NLP 史上一次真正的转向：**给每个词学一个稠密、低维的实数向量，让语义相近的词在向量空间里靠在一起**。它把「词」从符号变成坐标，也让「物品 Embedding」成为可能——这是推荐系统从「统计」迈向「表示学习」的关键一步。<span class="marginnote">在「从极限到大模型」的主线上，词向量是第一代「表示学习」：<strong>用低维连续向量代替高维离散符号</strong>。这条思路一路延伸到第十四篇——LLM 里的 token 表示，正是 Word2Vec 思想的集大成者。</span>

## 1 独热编码的三宗罪

先看 TF-IDF 的底层表示：每个词是词典里一个维度，本质上仍是**独热（one-hot）**的——「电影」是 $(0,0,\dots,1,0,\dots)$，「影片」是另一个维度的 $1$。独热编码有三个结构性的缺陷：

- **维度爆炸**：词典十万到几十万维，向量的绝大部分维度永远为零，存储与计算都被迫为「可能的词」买单。
- **正交即无语义**：任意两个 one-hot 向量的余弦相似度都是 0。「电影」和「影片」的相似度与「电影」和「香蕉」完全一样——**向量空间里没有「远近」的概念**。
- **OOV 失明**：词典之外的词没有位置，而推荐系统的物品简介每天都在冒出新词。

**重点：** 三个缺陷有一个共同根源——**one-hot 用「词的身份」表示词，而不用「词的含义」表示词**。要修复它，必须让「含义」在向量里显式地出现。

## 2 分布假说：词义由邻居决定

「含义」从哪来？语言学家早就给出过一个极有力的答案：**分布假说（distributional hypothesis）**——一个词的意义，由其出现的上下文决定。弗斯的原话成为经典：

> You shall know a word by the company it keeps.

「电影」和「影片」为什么同义？因为它们频繁出现在相似的上下文里：都跟在「一部」后面、都出现在「导演、主演」附近。**如果两个词身边的词高度重合，我们就认为它们语义相近。**<span class="marginnote">分布假说的源头可以追溯到 Zellig Harris（1954）的结构语言学，弗斯（1957）把它凝练成这句名言。它背后是一句朴素的话：<strong>「含义」不是先验定义的，而是从共现统计中涌现的</strong>——这与协同过滤「从行为中涌现相似」的哲学如出一辙。</span>

把分布假说工程化，就得到 Word2Vec 的终极目标：**让「上下文相似」的两个词，在向量空间里距离近**。剩下的问题只是——这个向量怎么学出来？

## 3 Skip-gram 与 CBOW：两种训练目标

Word2Vec 用「预测」来学向量。它有两种对称的训练目标：

- **CBOW（Continuous Bag-of-Words）**：给定上下文词，预测中心词。适合小语料、高频词。
- **Skip-gram**：给定中心词，预测它上下文窗口内的词。对低频词、小数据集更友好，推荐场景常用。

以 Skip-gram 为例。设句子里有一串词，取窗口大小 2，对中心词 $w_t$ 而言，上下文是 $w_{t-2}, w_{t-1}, w_{t+1}, w_{t+2}$。训练时不断做这样的事：**给出 $w_t$，让模型把概率压到真实的上下文词上**。

![Skip-gram 结构：中心词 one-hot 经查表 W 得到 K 维嵌入，再经 W' 投影到全词表打分](/images/recommender-systems/word2vec-item-embedding-1.svg)

网络结构出奇地简单（见上图）：中心词 $w_t$ 的 one-hot 向量乘以矩阵 $W$（$V \times K$），得到 $K$ 维向量——**$W$ 的第 $t$ 行就是词 $t$ 的嵌入向量 $v_{w_t}$**。再乘以矩阵 $W'$（$K \times V$），得到对所有词的打分，softmax 归一化成概率。训练完成时，$W$ 的行就是我们要的词向量。<span class="marginnote">注意这里的「预测」是伪装：我们并不真的关心语言模型好不好，<strong>矩阵 $W$ 才是唯一要的产物</strong>。语言模型只是「诱饵任务」，词向量是它的副产品——这个「用代理任务学表示」的思路，后来被广泛复制。</span>

## 4 公式解析：Skip-gram 的 Softmax 概率

Skip-gram 的核心是一个条件概率：给定输入词 $w_I$（中心词），模型输出 $w_O$（上下文词）的概率：

$$
P(w_O \mid w_I) = \frac{\exp\big(v'_{w_O}^{\mathsf{T}}\, v_{w_I}\big)}{\sum_{w=1}^{V} \exp\big(v'_w^{\mathsf{T}}\, v_{w_I}\big)}
$$

逐项拆解：

- **第一步，看 $v_{w_I}$**：这是输入词 $w_I$ 的嵌入向量（$K$ 维），来自查表矩阵 $W$ 的对应行——它是「这个词是谁」的稠密压缩。
- **第二步，看 $v'_w$**：每个词 $w$ 还有另一套「输出向量」$v'_w$，来自矩阵 $W'$ 的对应行。$v'_w$ 与 $v_{w_I}$ 同处 $K$ 维空间，两者做内积 $v'_{w_O}^{\mathsf{T}} v_{w_I}$，得到「$w_I$ 与 $w$ 有多匹配」的分数——**内积越大，越倾向预测 $w$**。
- **第三步，看分母**：对所有 $V$ 个词的内积做指数求和。除以它之后，每个分数都被压进 $[0,1]$，且全部词的分数加起来等于 1——**这就是 softmax：把「任意实数打分」归一化成「概率分布」**。
- **第四步，看训练目标**：对语料里每一对「中心词—上下文词」，最大化真实上下文词的概率 $P(w_O \mid w_I)$，等价于最小化负对数似然。梯度会推动 $v_{w_I}$ 靠近真实上下文词的 $v'$，远离随机抽到的负样本——迭代收敛后，**语义相近的词在空间里自然聚拢**。

分母要对全词典求和，$V$ 百万量级时计算不可承受，所以实践中用**负采样（negative sampling）**：不从全词典归一化，只把「真实上下文词」与「随机抽的少数几个负例」分开。这是工程上的近似，但理论结果几乎一样——2014 年 Levy 与 Goldberg 证明，**Word2Vec 本质上是在做「共现矩阵的隐式分解」，等价于给「点互信息矩阵」做低秩近似**。<span class="marginnote">这条「Word2Vec ≈ PMI 矩阵分解」的等价性极其重要：它把词向量与第三篇的矩阵分解直接连起来了——<strong>MF 分解「用户—物品」共现，Word2Vec 分解「词—上下文」共现，两者是同一个数学动作在不同数据上的重演</strong>。这也是为什么说「一切 Embedding 皆分解」。</span>

## 5 从词向量到物品 Embedding

词向量本身不会推荐物品，但它是构建**物品 Embedding** 的原料。常见的两条路：

**路线一：聚合描述文本。** 物品 $i$ 的简介里有若干词 $w_1, \dots, w_m$，把这些词的向量平均（或用 TF-IDF 加权平均）就得到物品向量 $\vec{i}$：

$$
\vec{i} = \frac{1}{m} \sum_{j=1}^{m} v_{w_j} \quad \text{或} \quad \vec{i} = \frac{\sum_j tfidf(w_j)\, v_{w_j}}{\sum_j tfidf(w_j)}
$$

对标题、简介这类短文本，这条路线简单有效，直接喂给上一篇的打分公式即可。用代码落地这一聚合：

```python
import numpy as np

# 预训练词向量表：word2vec[k] 是词典里第 k 个词的 K 维向量
# 假设已用 gensim / fastText 等在语料上训练完毕
def item_vector(words, word2vec, idf=None):
    vecs, ws = [], []
    for w in words:
        if w in word2vec:
            vecs.append(word2vec[w])
            ws.append(idf[w] if idf is not None else 1.0)  # TF-IDF 加权或等权
    if not vecs:
        return np.zeros(next(iter(word2vec.values())).shape)
    vecs = np.stack(vecs)
    ws = np.asarray(ws, dtype=float)
    return (vecs * ws[:, None]).sum(axis=0) / ws.sum()     # 加权平均

brief = "末日之后，人工智能与人类伦理的冲突"          # 物品简介
item = item_vector(tokenize(brief), word2vec, idf)   # 一个稠密物品向量
```

对标题、简介这类短文本，这条路线简单有效，直接喂给上一篇的打分公式即可。

**路线二：Item2Vec。** 2016 年 Barkan 与 Koenigstein 提出一个漂亮的移花接木：**把用户的行为序列当作「句子」，把物品当作「词」，直接跑 Skip-gram**——用户依次看过 A、B、C，就得到「句子」AB C，其中「A 的邻居是 B」等价于「A 与 B 常被同一个用户先后消费」。这样训练出的物品向量**根本不需要文本**，纯粹从行为共现中长出来。<span class="marginnote">Item2Vec 的「邻居」定义比语言更自由：可以是一段会话、一次加购序列、一个播放列表。<strong>它让「内容特征」与「协同行为」第一次在 Embedding 里握手</strong>——这是第五篇《向量召回》、第七篇《序列推荐》的直接前身。</span>

## 6 辨析：词向量、MF 隐向量与物品 Embedding

把这一篇的向量与前面几篇的向量放一起，很多初学者会困惑：它们到底是不是一回事？

| 向量 | 从什么学 | 数据形态 |
| --- | --- | --- |
| 词向量（Word2Vec） | 词—上下文共现 | 语言语料 / 物品描述文本 |
| MF 隐向量 | 用户—物品共现 | 评分 / 行为矩阵 |
| Item2Vec 物品向量 | 物品—物品共现 | 用户行为序列 |

**重点：** 三者共享同一个骨架——**用「共现」推「相似」，用「低维向量」压缩「高维共现」**。区别只在于共现的「主语」不同：词和上下文、用户和物品、物品和物品。理解了这一点，整个「Embedding 家族」就融会贯通了。

**辨析｜易错点：** 三个常见误判需要澄清。其一，**词向量「相似」不等于「同义词」**——「电影」与「演员」可能距离很近，那是「相关」而非「同义」；推荐场景要的往往正是这种「相关」。其二，**不要把「训练词向量」与「用词向量」混为一谈**——前者要在语料上跑几小时，后者是查表；生产系统常直接下载预训练词向量，用 TF-IDF 加权平均即可，不必自己训练。其三，**平均会稀释语义**——一篇简介若有一半词是噪音，平均值就被拖向中间；这也正是后续双塔模型用「端到端学习物品向量」而非「手工平均」的原因。

## 7 小结

- **分布假说**：词义由上下文决定，「与谁为伴」定义「是什么」；这是词向量的哲学基础。
- **Word2Vec** 用「预测上下文」的代理任务学表示；**Skip-gram** 由中心词预测上下文，**CBOW** 反之。
- **公式**：$P(w_O \mid w_I) = \dfrac{\exp(v'_{w_O}^{\mathsf{T}} v_{w_I})}{\sum_w \exp(v'_w^{\mathsf{T}} v_{w_I})}$，负采样加速。
- **Word2Vec ≈ PMI 矩阵分解**，与 MF 是同一数学动作，只是共现对象不同。
- **物品 Embedding** 两条路线：聚合描述文本的词向量，或用行为序列直接训练 **Item2Vec**。
- **易错点**：相似≠同义；训练≠使用；平均会稀释语义。
