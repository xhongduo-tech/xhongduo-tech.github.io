## 为什么从稀疏注意力开始

上一节我们算清了注意力的账：每个 token 要看向每个 token，于是有了 $O(n^2)$ 的平方墙。Beltagy 等人 2020 年的 Longformer 提出一个反常识的问题：**真的需要每个人认识每个人吗？** 人类读长文档时，眼光只落在眼前几行（局部），偶尔跳到重要位置（全局），绝不会逐字两两配对。既然注意力是「让模型像人一样读」，为何不直接把这个阅读习惯写进架构？

Longformer 的答案是**稀疏注意力（sparse attention）**：让大多数 token 只看一个固定大小的滑动窗口，只让少数特殊 token 拥有全局视野。代价从 $O(n^2)$ 直接降到 $O(n)$，而实验显示，在长文档阅读理解、指代消解等任务上，性能不降反升。<span class="marginnote">这是一次「结构先验」的胜利：用领域知识（文本的局部性）约束模型结构，换取可扩展性。同样的思路在图像里早有先例——CNN 的局部感受野就是「滑动窗口」的卷积版。</span>

## 1 滑动窗口注意力：让 token 只看邻居

为什么局部先验对文本成立？自然语言有强烈的**短程依赖**（相邻词、就近搭配），而长程结构（篇章主题、指代）通常只靠少数「枢纽」token 维系。滑动窗口恰好捕捉短程，全局 token 恰好补上枢纽——**稀疏注意力不是「退化的注意力」，而是「按语言结构剪枝的注意力」**。

**滑动窗口注意力（sliding window attention）**：给每个 token 设置一个固定窗口大小 $w$，它只能与左右各 $\frac{w}{2}$ 个 token 计算注意力。<span class="marginnote">窗口外的键不参与 softmax——注意力矩阵变成一条宽度为 $w$ 的带状矩阵（banded matrix），其余位置为 $-\infty$。这与卷积里「感受野」的局部性如出一辙，见第四级《计算机视觉》卷积网络一节。</span>

**核心概念：** 设序列长度为 $n$、窗口大小为 $w$（通常取 512），每个查询只对窗口内的 $w$ 个键计算注意力，于是注意力矩阵的非零元素从 $n^2$ 个降到 $n \cdot w$ 个：

$$
\text{复杂度} = O(n \cdot w \cdot d) = O(n d) \quad (w \text{ 为常数})
$$

当 $w$ 取固定值（如 512），$n \cdot w$ 随 $n$ **线性**增长——平方墙的第一道裂缝就此打开。多层叠加后，窗口信息可以通过网络的深度逐层传播：第 $l+1$ 层的一个 token，能间接「看见」第 $l$ 层里 $w$ 步以内的信息，于是深层模型的有效感受野可达 $l \cdot w$——这是 Longformer 不损失长距离能力的关键直觉。

把 Longformer 与标准稠密注意力的「模式」摆在一起对比，稀疏性看得最清楚：

| 模式 | 每个 token 关注的键 | 复杂度 | 长程能力 |
| --- | --- | --- | --- |
| 稠密（标准） | 全部 $n$ 个 | $O(n^2)$ | 直接可见，但最贵 |
| 滑动窗口 | 窗口内 $w$ 个 | $O(n w)$ | 靠深度传播 $l \cdot w$ |
| 扩张滑动窗口 | 窗口内隔步取点 | $O(n w)$ | 跨距更大、信息更稀 |
| 全局 token | 全部 $n$ 个 | $O(g n)$ | 指定位置的直达通道 |

关键洞察是「**谁拥有全局视野谁承担 $O(n)$ 的跨距成本**」：稠密模式下每个人都承担，稀疏模式把这项成本**集中**到少数 token 身上，让大多数 token 只付 $O(w)$ 的本地账。

## 2 扩张滑动窗口：在不加窗口的条件下看得更远

窗口小，直接后果是「远亲不相往来」。Longformer 借鉴了**扩张卷积（dilated convolution）**的做法：窗口里不是取连续 $w$ 个 token，而是每隔 $\text{dilation}$ 步取一个，用同样的窗口大小覆盖更长的跨度。<span class="marginnote">扩张卷积由 Yu & Koltun 于 2015 年在语义分割中提出：同样的卷积核参数，插洞后感受野指数级扩大。Longformer 把这一招原样搬到注意力上。</span>

**辨析｜易错点：** 扩张滑动窗口并不是「更好的窗口」，而是「更稀疏的窗口」——它用覆盖跨度的代价换取了信息密度，连续局部信息反而可能丢失。因此 Longformer 在实践中**默认不使用扩张**，只在个别任务（如 Character-level LM）中开启，且常与标准滑动窗口交替叠加。

**扩张的具体做法**：设扩张率为 $r$，窗口从「连续 $w$ 个」变成「每 $r$ 步取一个」，跨距从 $w$ 扩到 $r \times w$。Longformer 在字符级语言模型实验里用了「标准窗口 + 扩张窗口」的双层配置（一层 dilation = 1，一层 dilation = 4），在不增加窗口尺寸的前提下把感受野翻了四倍。字符级任务对精确的局部拼写依赖低、对长程统计依赖高，扩张在这里才划算——这也从反面解释了它为什么默认关闭。

## 3 全局注意力：给少数 token 配望远镜

只靠局部窗口，模型永远「只见树木不见森林」。Longformer 的关键设计是**全局注意力（global attention）**：预先指定少数「全局 token」（如每个句子的 `[CLS]`、问题-回答任务中的问题 token），它们**对序列中所有 token 计算注意力，也被所有 token 注意**——既是望远镜向外看，也是灯塔被众人望。

**全局 token 的成本要细算**：全局 token 数 $g$ 若随任务增大（例如长问答里的问题很长），$g \cdot n$ 项会重新变成平方的嫌疑——所以工程上要严格控制 $g$，通常取几十个以内。「谁配当全局」因此成为一项精打细算的设计决策。

**核心要点：** 设全局 token 数为 $g$（通常 $g \ll n$，例如几十个），全局注意力的代价是 $O(g \cdot n)$。它与滑动窗口 $O(nw)$ 相加，总复杂度仍为 $O(n)$：

$$
\text{总复杂度} = O(n \cdot w \cdot d + g \cdot n \cdot d) = O(n d)
$$

以指代消解（coreference resolution）为例：文档里「奥巴马」与后面十几句处的「他」需要跨越数千 token 建立联系，滑动窗口够不着，而把文档首部的 `[CLS]` 设为全局 token，就为这种长程依赖留了一条直达的「高速公路」。

**全局 token 怎么选**：不同任务有不同约定——问答里把问题与候选答案设为全局，指代消解把指称边界处的 token 设为全局，语言模型则常在每个句子开头取一个。选哪些 token 是**任务先验**，Longformer 论文把各任务的选取规则都写在了附录里。它提醒我们：全局 token 不是模型学出来的，而是设计者递给模型的「望远镜清单」。

Longformer 的长文档问答实现是这套组合的典型：输入拼接成「问题 + 文档」，问题里的每个 token 设为全局、文档部分用滑动窗口——模型既知道问什么，又能细读全文。**「局部精读 + 全局粗看」**的配置，后来被几乎所有长文档 QA 系统沿用。<span class="marginnote">指代消解是 Longformer 论文里收益最明显的任务之一，因为在篇章级任务中，重要信息往往出现在文档开头或结尾，全局 token 恰好覆盖这些位置。</span>

## 4 公式解析：滑动窗口注意力的掩码

用掩码（mask）的方式，稀疏注意力可以写成对标准注意力公式的约束。设 $M$ 是 $n \times n$ 的掩码矩阵，允许的位置为 0、禁止的位置为 $-\infty$：

$$
\text{Attention}(Q, K, V) = \mathrm{softmax}\left( \frac{Q K^{\top} + M}{\sqrt{d_k}} \right) V, \qquad
M_{ij} = \begin{cases} 0, & |i - j| \le \frac{w}{2} \text{ 或 } i, j \text{ 为全局 token} \\ -\infty, & \text{否则} \end{cases}
$$

- **$M_{ij} = 0$**：第 $i$ 个 token 与第 $j$ 个 token 距离在窗口内，或两者之一是全局 token——正常计算相似度。
- **$M_{ij} = -\infty$**：窗口外且非全局——softmax 的指数把 $-\infty$ 压成 0，等价于「不许看」。
- **复杂度陷阱**：把掩码加进去只是数学上的写法，**如果仍把整张 $n \times n$ 矩阵算出来再乘掩码，复杂度依然是 $O(n^2)$**。Longformer 的实现是直接只计算带状区域的元素，跳过窗口外部分——稀疏必须落实到**计算路径**，而不是事后抹零。

**窗口大小怎么选**：Longformer 的实验取 $w = 512$（与 RoBERTa 的 512 位置上限一致）。窗口太小则每层覆盖不足，太大则失去稀疏意义——它与卷积核宽度的选择是同一类问题，用验证集上「速度 × 质量」的联合曲线来定，而不是拍脑袋。

**掩码在实现里的两种形态**：Longformer 的官方实现直接用稀疏矩阵参与运算，而 flash-attention 等后续库则把窗口编码成「块掩码」跳过大块。两种形态数学等价，性能却差一个数量级——**稀疏注意力的性能，取决于它的掩码长什么样**。

**辨析｜易错点：** 「稀疏注意力」常被误以为是「截断注意力」——即直接丢掉窗口外的信息。不对：Longformer 的窗口外信息**没有参与本层计算**，但会通过**深层传播**（每层感受野扩大 $w$）被间接吸收。稀疏的是注意力，不是信息。

## 5 训练策略：从 RoBERTa 出发

Longformer 没有从零训练，而是**把预训练的 RoBERTa 继续训练成 Longformer**——这是它性价比极高的原因之一：

**核心要点：** 把 RoBERTa 的每个注意力头从「全局稠密」替换为「滑动窗口 + 少量全局」结构，窗口外的权重用零填充初始化（配合 mask 让初始阶段不受影响），然后用长文档语料继续预训练，把位置编码从 512 外推到 4096。<span class="marginnote">「先稠密预训练，再稀疏化继续训练」后来成为稀疏注意力模型的标准配方，Sparse Transformer、BigBird 都沿用类似的初始化迁移思路。</span>

训练成本上，$O(n)$ 意味着每 token 成本固定：处理 4096 个 token 的 FLOPs 约为 RoBERTa-512 处理 512 个 token 的 $w/512$ 倍（$w$ 取 512 时约为 1 倍）——**读八倍长的文档，算力几乎不涨**。稀疏性的价值，在这一句里体现得最直接。

效果方面：在长文档 QA（如 TriviaQA 的长文档设置）、指代消解、Text8 字符级语言模型上，Longformer 以 $O(n)$ 的代价追平甚至超过了稠密 Transformer，并支持一次性输入 4096 个 token——比当时主流模型的 512 高出八倍。它发布时直接放出了 `longformer-base-4096` 与 `longformer-large-4096` 两个权重，前者从 RoBERTa-base 迁移、后者从 RoBERTa-large 迁移，还把长文档问答微调版一并开源——「稀疏结构 + 开源权重」的组合让社区两天内就能跑起来，这是它影响力远超同期 Sparse Transformer 的重要原因。以指代消解为例：长文档里「奥巴马」与十几句之后的「他」要跨数千 token 建立联系，稠密模型是「杀鸡用牛刀」，而 Longformer 只靠首部 `[CLS]` 的全局 token 就提供了同等的通路，速度却快得多。<span class="marginnote">论文在 OntoNotes 与 CorefQA 上的对照显示：稠密 RoBERTa 需要把文档截断到 512 才能训练，Longformer 一次性读完 4096，指代 F1 反而更高——「读完」本身就带来信息优势。</span>

实现层面还有一处与普通直觉相反的细节：**滑动窗口也可以用「分块」高效实现**。Longformer 的论文给出一个 chunked 实现：把 $K, V$ 切成不重叠的块，让块与窗口对齐，用块间矩阵乘代替逐位置循环——同样的窗口语义，GPU 吞吐却高一个量级。<span class="marginnote">这预告了本专题《分块注意力》与《滑动窗口注意力》两节的内容：稀疏只是「模式」，落地要靠分块计算，二者在工程上是同一件事的两面。</span>

这一结果的意义不在于某一个任务的得分，而在于**证明了「局部 + 少数全局」的稀疏模式足以逼近全连接注意力的表达能力**。它的局限也被后续工作看得更清：滑动窗口在「长程跳跃」上仍弱，BigBird 随后引入随机连接补强，Mistral 则干脆只保留窗口加 attention sink——**Longformer 的真正遗产，是证明了「稀疏 = 局部 + 少量全局」这个公式本身**。

顺着这个结论再看它在长上下文谱系里的位置：Longformer 的「滑动窗口 + 全局」后来被 BigBird（加随机连接）、Mistral（纯窗口）、Gemma（窗口 + 全局锚点）等模型以不同配比继承。**「局部是主、全局为辅」从一篇文章变成了一个设计模式**——窗口定多少、全局选谁，成了长上下文架构师手里的两个自由旋钮。

## 6 小结

- **滑动窗口注意力**：每个 token 只看窗口内 $w$ 个邻居，代价 $O(nw)$，深层传播提供长程感受野。
- **扩张滑动窗口**：插洞扩大跨度，默认关闭，用信息密度换覆盖范围。
- **全局注意力**：少数 token 全视野、被全视野，为长程依赖修高速公路，代价 $O(gn)$。
- 三种模式叠加，总复杂度仍为 $O(n)$——平方墙的第一道裂缝。
- 稀疏注意力必须落实到**计算路径**（只算带内元素），掩码只是数学写法。
- 训练配方：稠密预训练 → 稀疏化继续预训练，用 RoBERTa 长文档扩展。
- 适用场景：局部强依赖、长程靠枢纽的文本；跨文档跳跃相关时需补检索或全局 token。
- 全局 token 是任务先验，不是学出来的；$g$ 要严控，否则 $gn$ 项重新变平方。

在下一节，我们将走另一条更彻底的路：既然 $n^2$ 来自「每个 token 与其他所有 token 两两计算」，能不能**根本不做两两计算**，把注意力的复杂度直接写成 $O(n)$ 的递推？——这就是**线性注意力机制**的答案。
