## 为什么从滑动窗口开始

Longformer 那节我们见识了它的三种模式，其中**滑动窗口**是主力。本节把滑动窗口单独请出来——因为在后来的长上下文模型里，它从「Longformer 的一个组件」升级成了**独立的主角**：Mistral 7B 的每个注意力头默认就是纯滑动窗口（窗口 4096），Gemma 7B 用局部滑动窗口加全局锚点，而 T5 之后的编码器模型也常把窗口注意力当作默认配置。原因很实在：**它把 $O(n^2)$ 切成 $O(n)$，同时在局部任务上的表现几乎不受损，而且实现极其干净——一张带状掩码、一个滚动的缓存，就够了。**

这一节讲三件事：滑动窗口注意力的定义与复杂度；它如何与 FlashAttention 的分块实现合流；以及它给推理带来的礼物——**滚动 KV Cache（rolling KV cache）**。

## 1 定义与复杂度：一张带状掩码

**核心概念：** **滑动窗口注意力（sliding window attention）**让每个 token 只对**距它不超过 $w$** 的键计算注意力。因果模型里只看左侧，于是第 $i$ 个 token 的注意力范围是键 $j \in [i - w, i]$。注意力矩阵的非零区域变成一条沿对角线的**带**，带外全部是 $-\infty$：

$$
M_{ij} = \begin{cases} 0, & j \in [i - w, i] \\ -\infty, & \text{否则} \end{cases}, \qquad
\text{复杂度} = O(n \cdot w \cdot d)
$$

$w$ 是常数（Mistral 取 4096，但相对序列而言仍是常数），于是复杂度对 $n$ **线性**。<span class="marginnote">与卷积感受野的关系在 Longformer 节已点过：$w$ 就是注意力的「核宽」。区别在于注意力是自适应的——窗口内每个位置的权重由内容决定，而卷积核权重是学习好的常量。</span>

窗口的小并不会真的困住长程信息。设模型共 $L$ 层，每层窗口 $w$，则第 $L$ 层某个位置能「间接看见」的距离是 $L \times w$——信息像水一样一层层向远处渗透。以 Mistral 7B 为例：$L = 32$、$w = 4096$，理论感受野 $32 \times 4096 = 131072$——**约 128k**，这正是其官方宣称「可用 128k 上下文」的数学依据。

**滑动窗口并不新鲜**：Child 等人 2019 年的 Sparse Transformer 已经把「局部注意力 + 间隔注意力」写进图像与文本模型；GPT-3 的一个早期变体也尝试过局部注意力。Longformer 的贡献，是把窗口与全局组合打磨成「长文档默认配方」，并给出了从 RoBERTa 迁移的成熟训练策略。理解这一点，就不会把窗口注意力当成 Longformer 的独创，而是稀疏注意力家族里的一环。**窗口与标准注意力还是连续的**：窗口内计算与标准注意力逐位一致、窗口外直接不计算——因此「把窗口开大」可以无缝退化为标准注意力，架构是连续的而非断裂的。**回到本专题主线**：窗口注意力正是「稀疏结构」与「IO 优化」两大流派的交汇点——它在数学上稀疏（掩码），在实现上分块（flash-attention 的 `window_size`），两个视角缺一不可。

窗口背后的归纳偏置在深度学习里源远流长：CNN 用局部卷积核扫全图、窗口注意力用局部窗口扫全序列，本质是同一个假设——**邻近的事物相关，远处的事物偶发**。差别在于注意力是内容自适应的：窗口内的权重由 token 内容实时决定，卷积核却是静态的学习量。理解这层传承，窗口注意力就不是「注意力的残缺版」，而是「局部先验在注意力里的合法化身」。<span class="marginnote">对 32 层的 Mistral，$32 \times 4096 = 131072$——有效感受野达 128k。这是「局部模式 + 深度」能覆盖长程的理论依据，也是为什么纯滑动窗口敢用在长上下文模型上。</span>

## 2 滑动窗口与分块合流：块状实现

滑动窗口的朴素写法仍是「先建一张 $n \times n$ 矩阵再抹零」——复杂度又会回到 $O(n^2)$。上一节 FlashAttention 的**分块骨架**恰好为此提供了正解：把 $K, V$ 切成块，**整块落在窗口外就直接跳过**，只有落在带内的块才被读进 SRAM 计算。<span class="marginnote">flash-attention 库为此专门暴露了 `window_size` 参数：传入 `(left, right)` 后，实现会自动跳过窗口外的块——滑动窗口与 FlashAttention 的分块在工程上无缝合一。</span>

**辨析｜易错点：** 滑动窗口 ≠ 分块注意力（chunked attention）。分块注意力是把序列切成不重叠的块、块内做稠密注意力，块之间**不互通**；滑动窗口是**块间有 $w$ 的重叠**，相邻块互相可见。两者复杂度同为 $O(n)$，但信息传播特性不同——分块更容易造成「块边界的信息断层」，而滑动窗口是渐进的。Longformer 论文中同时讨论了这两种，读者常混为一谈。

**窗口在实现里的真实形状**：把窗口写进 FlashAttention，就是给每一行指定「非 $-\infty$ 的列区间」。flash-attention 的 `window_size=(left, right)` 参数让实现自动跳过窗口外的 KV 块；对因果窗口，第 $i$ 行的有效列是 $[i - w, i]$，带内平均每行 $w$ 个元素。数值上，窗口注意力与稠密注意力在**带内逐位一致**——它不是近似，而是精确的「截断版注意力」。**窗口的块粒度表达**：在 flash-attention 里窗口就是「哪些 KV 块值得读」的规则——滑动窗口于是从「数学上的掩码」变成了「工程上的跳过」，性能与语义同时成立。**窗口还把「上下文上限」从资源问题变成结构问题**：标准注意力的可处理长度受显存与算力限制，窗口注意力只要不要求信息可达，序列可以无限长。

## 3 滚动 KV Cache：推理时的礼物

生成阶段的标准做法是：每生成一个 token，把它的 $K, V$ 追加进缓存（KV Cache），注意力对所有缓存里的键求——缓存长度随输出**线性增长**。滑动窗口打破了这一点：**窗口外的旧键永远不会再被用到**，于是缓存根本不必保留它们。

**滚动 KV Cache（rolling KV cache）**：维护一个长度固定为 $w$ 的环形缓冲区，新键覆盖最旧的键。缓存大小从 $O(n)$ 降到 $O(w)$——**与上下文总长无关**。

把几种缓存策略放在同一张表里对比，各自的定位立刻清楚（单层单头、$d$ 维）：

| 策略 | 缓存大小 | 每步计算 | 记忆范围 |
| --- | --- | --- | --- |
| 标准 KV Cache | $O(n d)$ | $O(n d)$ | 全部历史 |
| 滚动 KV Cache（窗口） | $O(w d)$ | $O(w d)$ | 最近 $w$ 个 |
| GQA 分组共享（下节） | 除以组数 $H/G$ | 除以组数 | 全部历史 |

滚动缓存与 GQA 是两种**正交**的压缩：一个按时间「遗忘」旧键，一个按头「共享」键值——现代推理引擎常常同时启用，压缩效果相乘。

**一个关键认识**：滚动缓存把「生成复杂度不随总长增长」做成了结构保证——只要窗口不滚出必要信息，推理时间就是平的。这是它与标准 KV Cache 最本质的差异：后者生成第 $n$ 个 token 时已累计了 $n$ 步注意力，前者每一步永远是 $w$ 步。**窗口模型的时间复杂度曲线是一条水平线，这正是「长上下文推理」梦寐以求的形状。**

一个具体的数字：单层单头、$w = 4096$、$d = 128$ 的滚动缓存，每 token 只需 $2 \times 4096 \times 128 \times 2$ 字节 ≈ 2 MB；32 层叠下来每 token 约 64 MB。对比稠密 128k 的 KV Cache（约 17 GB 量级），滚动窗口把同样长度的推理显存压到不足其十分之一——代价是窗口外信息失忆。

**与批处理的矛盾**：滚动缓存假设的是单一长流；当同一批次里多条序列长度不一、各自滚动时，缓存分配立刻复杂起来——这正是 PagedAttention 按页管理显存用武之地。窗口与分页管理正交叠加，现代推理引擎（vLLM 等）把两者都做成可选项。<span class="marginnote">环形缓冲区（ring buffer）是第一级《数据结构》的经典结构：头尾相接、写指针回绕。滑动窗口推理 = 注意力里的环形缓冲区，这是数据结构知识在模型部署里的直接变现。</span>

代价是什么？窗口外的旧信息对推理而言**彻底失忆**——文档开头的系统提示、指令、首次出现的概念，都会随着窗口滚动被丢出缓存。所以 Mistral 等模型还配套一个 trick：**attention sink**——在序列最前面额外保留几个固定 token 的 KV，让它们作为「记忆锚点」承担基础概率质量。<span class="marginnote">StreamingLLM 的实验显示，注意力分布里前几个 token 吸收了不成比例的「无关注力」（约占总权重的一成以上）。把它们锚定在缓存里，模型就有一块稳定的底座，滚动窗口才敢放心滚动。</span>

**辨析｜易错点：** 窗口大小 $w$ 不等于「模型实际能用的上下文长度」。Mistral 报的「32k 上下文」里，滑动窗口只保证最近 4096 个 token 的**直接**注意力，更早的信息全靠 32 层感受野间接传播——所以同样标着 32k，Mistral 的「32k」与 Llama 3.1 那种纯稠密 128k 的「128k」在**信息可达性**上不是一个量级。读模型规格表时，先问一句：窗口之外，模型靠什么想起你？<span class="marginnote">attention sink 来自 StreamingLLM（Xiao et al., 2023）：观测发现窗口模型丢弃前几个 token 后困惑度骤升，因为初始 token 会吸收大量「无关注力」。保留它们，模型才能稳定长跑。</span>

## 4 公式解析：滚动缓存的复杂度账

把滚动缓存的开销写全。设序列长度 $n$、窗口 $w$、单头维度 $d$、层数 $L$：

$$
\text{每步缓存内存} = O(L \cdot w \cdot d), \qquad
\text{每步计算} = O(L \cdot w \cdot d)
$$

- **$w$ 而非 $n$**：滚动缓存里最多同时存在 $w$ 个键值，这是与标准 KV Cache 最本质的分野——后者每步都是 $O(L \cdot n \cdot d)$，生成越长越吃内存。
- **每步 $O(w d)$**：新 token 只需对窗口内 $w$ 个键算注意力。与线性注意力那节对比：线性注意力每步 $O(d^2)$（与窗口无关），滑动窗口每步 $O(w d)$——当 $w < d$ 时窗口更快，当 $w > d$ 时线性更快。两者的边界正是模型设计者的权衡场。**再点一次公式的名字**：本节与《注意力计算复杂度》那节是对偶关系——那节算的是「全对全」的 $O(n^2)$，本节算的是「窗口内」的 $O(n w)$。同一个注意力公式，换一张掩码，复杂度就从平方降为线性——**掩码，就是架构师手里的复杂度开关**。<span class="marginnote">Mistral 取 $w = 4096, d = 4096$——恰好 $w = d$，两个方案的常数势均力敌，选择取决于对局部先验的信任程度。</span>

## 5 局限：局部先验何时失效

滑动窗口的假设是「文本相关性随距离衰减」——**大部分时候对，但不是永远对**。跨文档的指代（前一章引用的某句话出现在 50 页之后）、检索增强中插入的长篇材料，都可能让相关性在距离上**跳跃**。这正是 Longformer 要补全局 token、现代模型要配 attention sink、而检索系统干脆把窗口换成「top-k 命中」的原因。

**窗口与位置的耦合**：窗口只限制「注意力范围」，不负责「位置关系」——窗口内键的相对顺序依然要靠位置编码（RoPE / ALiBi）来读。若窗口内没有位置信息，模型连「最近邻居里谁在前谁在后」都无法区分。两种机制一个管「谁能看」，一个管「看到之后怎么摆」，缺一不可——这也是为什么《位置编码外推》那节是理解本节的必要前提。

**滑动窗口的选择题**：窗口到底开多大，是「局部先验强度」与「缓存预算」的折中。$w$ 越大，局部覆盖越充分，但缓存与算力向 $O(n)$ 回归的风险越高；$w$ 太小，则连层数堆出来的感受野都救不了跨段指代。Mistral 把窗口开到 4096——与单层维度 $d$ 同量级——可以看作「预算内尽量大」的实用选择。

**窗口失效的两个典型场景**：一是「远距离单点依赖」——第 1000 句的决定性证据在第 100 句，中间 900 句全是干扰，窗口与层数感受野都救不了这种「罕见但关键」的远跳；二是「位置敏感的长程计数」——要跨 50k 距离统计某事件的发生次数。这两个场景，恰好就是 LongBench 合成任务（PassageRetrieval、PassageCount）要暴露的短板。

**窗口与全局的配比光谱**：Longformer 用「窗口 + 少量全局 token」，Gemma 7B 用「窗口 + 每层固定数量的全局锚点」，Mistral 用「纯窗口 + attention sink」——从全窗口到窗口加锚点，是一个连续的配比光谱。锚点越多，长程直达能力越强，但全局 token 的 $O(gn)$ 成本也越高。架构选择的关键，是估算你的任务里「长程直达」到底有多频繁。

**与检索增强的互补**：当上下文实在装不下、或相关性在距离上跳跃时，与其开大窗口，不如先做**检索**：把 100 万字压成与问题最相关的 2k token，再交给窗口模型精读——这就是 RAG 的基本盘。窗口保证「读得动」，检索保证「读得准」，两者互补而非竞争。这为下一专题《检索增强（RAG）》埋下了接口：**长上下文优化的终点，是让「选着读」与「读得动」各司其职**。

**把优化叠起来的最终账单**：滑动窗口（按时间淘汰）、GQA（按头共享）、KV 量化（按精度压缩）三者相乘，128k 推理的缓存可以从 17 GB 压到不足 0.5 GB。长上下文推理的落地，从来不是某一种优化的独角戏，而是「结构 + 架构 + 数值」三板斧的合奏——这也正是本专题各节最终要交汇的方向。

**窗口的工程成熟度**：从 Longformer 的稀疏矩阵，到 flash-attention 的 `window_size`，再到 Mistral 的滚动缓存，窗口注意力已经积累了整整一代工程实现。今天选用窗口注意力，几乎不需要自己写 kernel——这本身就是它成为默认架构的原因之一。

**窗口模型是「以记忆换速度」的典型**：它牺牲的是无限记忆，换来的是与总长无关的生成速度——这个交换在现代长对话场景里几乎总是划算的。**窗口的现代变体**：除了纯窗口，还有「窗口 + 全局锚点」（Gemma）、「窗口 + attention sink」（Mistral）、「窗口 + 随机连接」（BigBird）——它们都在同一个公式上换掩码，因此共享本节的全部复杂度结论。

**辨析｜易错点：** 不要因为「窗口 = $O(n)$」就以为窗口注意力是长上下文的万能解。它解决的只是**计算与内存的可扩展性**，不解决**信息的可达性**——窗口外的东西除非被深层感受野覆盖，否则物理上看不见。衡量一个长上下文架构，既要看它能算多长，也要看它能不能把该用的信息用上。

## 6 小结

- 滑动窗口注意力：每个 token 只看 $w$ 个邻居，复杂度 $O(nwd)$，对 $n$ 线性。
- 有效感受野 = 层数 × 窗口 $L \times w$，局部模式靠深度覆盖长程。
- 工程上由分块实现跳过窗口外块；滑动窗口 ≠ 块间不互通的分块注意力。
- 推理利器**滚动 KV Cache**：缓存固定为 $w$，与总长无关；配套 attention sink 保稳定。
- 局限：局部先验在跨文档跳跃相关时失效——可扩展性 ≠ 信息可达性。
- 与 GQA、KV 量化正交叠加；工程实现成熟（flash-attention `window_size`、滚动缓存）。
- 窗口先验 = 邻近相关、远处偶发；与 RAG 互补：窗口保「读得动」，检索保「读得准」。
- 衡量标准是「算得动 × 读得懂」：窗口保证前者，后者要看位置编码与深层感受野。
- 工程成熟度：flash-attention 的 `window_size`、滚动缓存与 attention sink 已是一代默认配置。
