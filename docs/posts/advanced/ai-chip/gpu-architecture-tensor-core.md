## 为什么从 GPU 开始

当代 AI 的每一次浪潮背后都站着一个共同的硬件：**GPU（图形处理单元）**。
2012 年，AlexNet 在两张 GTX 580 上拿下 ImageNet 冠军，深度学习由此复兴，GPU 成了训练的「默认硬件」；
2017 年，NVIDIA 在 Volta V100 里装进 **Tensor Core**，又让 GPU 长出专门吃矩阵乘法的牙齿。
本专题把 GPU 放在第一篇，是因为它既是眼下最普及的 AI 计算平台，
也是后面理解 TPU、昇腾、Groq 等一切专用加速器的坐标系——那些加速器几乎都在回答同一个问题：**GPU 哪里「贵」，我们把它省掉。**

## 1 GPU 是「吞吐机」：SIMT 与线程组织

先看设计哲学的分野。**CPU 是「低时延机」**：少数几个强大的核心，配上超大缓存和深流水线，为「把单条指令尽快跑完」而优化；
**GPU 是「高吞吐机」**：一颗芯片上集成数千个轻量核心，为「让成千上万条指令同时推进」而优化。
深度学习任务恰恰是后者：一整个 batch 的图像推理，天然有海量可并行的数据。
<span class="marginnote">同一个应用场景里，CPU 与 GPU 的换算常常差出三个数量级：处理单张 224×224 图像的一层卷积，CPU 毫秒级、GPU 微秒级。你并不需要「算得更快」，你需要「同时算得更多」。</span>

GPU 的并行模型叫作 **SIMT（单指令多线程，Single Instruction, Multiple Threads）**，
与 CPU 上常见的 SIMD（单指令多数据）常被混淆，必须辨析：

**辨析｜易错点：** SIMD 是对**一条很宽的向量**执行同一操作（如一次加 8 个 32 位浮点）；
SIMT 是让 **32 个独立的标量线程**在同一时钟周期执行同一条指令，各自作用于自己的数据。
SIMT 多出来的灵活性是「线程发散」（warp divergence）——当某个 `if` 分支让线程走向不同路径时，
一个 warp 只能分次执行各分支，这会让吞吐打折。
CPU 的 SIMD 没有这个问题，因为它根本没有线程这个概念。

NVIDIA 把 32 个线程绑成一个 **warp**，这是一个调度的基本单位；
若干 warp 组成**线程块（thread block）**，若干线程块组成 **grid**，对应 CUDA 编程模型的三个层次。
每次调度，一个**流式多处理器（SM，Streaming Multiprocessor）**让整个 warp 的同一条指令分发给 32 个线程同时执行。
<span class="marginnote">「同一个 SM、同一个时刻、32 个线程执行同一条指令」——这句话值得反复咀嚼：GPU 的「并行」不是把 32 个线程各自乱跑，而是让它们像阅兵方阵一样步伐整齐，只有遇到分支才「分裂」再汇合。</span>V100 有 80 个 SM，
每 SM 有 64 个 FP32 CUDA Core，全芯片共 5120 个 CUDA Core——一个 2017 年的消费级芯片上，
密密麻麻塞了五千多个算术单元。

## 2 存储层次：寄存器、共享内存、缓存与显存

GPU 的存储层次与 CPU 同构但有本质区别：**寄存器**（最快，
每个线程私有）、**共享内存**（片上 SRAM，线程块内可编程访问）、**L1/L2 缓存**（透明硬件管理）与**显存**（GDDR6 或 HBM，
芯片外的 DRAM）。
<span class="marginnote">「可编程」是关键词：CPU 的缓存对程序员是透明的（不知道也照样工作），而 GPU 的共享内存需要显式分配与同步（`__syncthreads()`）。对深度学习者，这层显式控制正是省电省带宽的抓手——我们会在《内存层次与带宽》一篇详细展开。</span>

**重点：** 深度学习计算的瓶颈常常不在算力，而在**带宽**。以 A100 为例，
它有 80 GB HBM2e，峰值带宽约 2 TB/s——听着很大，
但 GPU 要喂饱自己的算力，每取回 1 字节数据就要做约 62 次浮点运算（算术强度），
远高于实际卷积层的需求。
带宽不够，算力只能「饿着」。这一观察是后面 Roofline 模型与「数据流」分析的出发点。

## 3 Tensor Core：为矩阵乘法而生

**Tensor Core** 是 NVIDIA 在 Volta V100（2017）引入的专用矩阵乘加单元，
一条指令完成一个 **4×4×4** 的矩阵乘加：

$$D = A \times B + C$$

其中 $A, B$ 是 FP16 的 4×4 矩阵，$C, D$ 是 FP32 的 4×4 矩阵。
把中间结果留在 FP32 是刻意的：矩阵乘法连续累加 64 项，若全程用 FP16 累加会因舍入误差发散，用 FP32 累加则精度与训练一致。
<span class="marginnote">这一条细节决定了 Tensor Core 能直接用于训练：如果只用低精度累加，模型可能不收敛；FP32 累加让「低精度输入 + 高精度累加」成为业界标准配方，后来的 TF32、INT8 全是同一个思想。</span>

每个 SM 内放 8 个 Tensor Core，V100 全芯片 80 个 SM 共 **640 个 Tensor Core**。
代价是清晰的：Tensor Core 不做通用算术（不能跑 `sin`、不能做分支），它只做 GEMM；
回报也是清晰的——FP16 张量算力高达约 **112 TFLOPS**，
而同芯片 FP32 只有 **15.7 TFLOPS**，专用化带来了约 **7 倍**的算力提升。

到 Ampere A100，Tensor Core 迭代到第三代：加入 TF32、BF16、INT8、INT4 多种精度，
并支持 **2:4 结构化稀疏**（见《量化与稀疏计算》一篇）；
Hopper H100 又加上 FP8 与 Transformer Engine。
这条演进线说明：**GPU 正在主动「加速器化」**——把越来越大的芯片面积让位给专用单元，而不是通用单元。

## 4 公式解析：一个 Tensor Core 指令算多少 FLOPs

把上面几句话换算成一个可验证的数字，是理解专用算力的第一步。一次 HMMA（半精度矩阵乘加）指令的 FLOPs：

$$
\text{FLOPs/指令} = 4 \times 4 \times 4 \times 2 = 128
$$

- **第一步，数 MAC 数**：$D = A \times B + C$，$A$ 是 $4 \times 4$，$B$ 是 $4 \times 4$，乘积 $A \times B$ 共 $4 \times 4 = 16$ 个输出元素，每个输出元素要累加 $K=4$ 次乘法——一共 $16 \times 4 = 64$ 个 **MAC（乘加）**。
- **第二步，算 FLOPs**：一次 MAC = 一次乘法 + 一次加法 = 2 FLOPs，所以 64 MAC = **128 FLOPs**。
- **第三步，推算芯片峰值**：每 SM 每周期有 8 个 Tensor Core 同时工作，80 个 SM 在频率 $f$ 下：
  $$P_{\text{tensor}} = 80 \times 8 \times 128 \times f = 81920 \times f$$
  取 $f = 1.37\text{ GHz}$ 得 $P \approx 112 \text{ TFLOPS}$——这正是 V100 官方标称的峰值。
对比 FP32：$80 \times 64 \times 2 \times f \approx 15.7\text{ TFLOPS}$。
专用化的收益（约 7 倍）不是玄学，是这条式子里**每周期多做的工作量**。

**辨析｜易错点：** 别把「MAC 数」当「FLOPs」。芯片厂商的 TOPS（每秒整数万亿次操作）数字，多数是 MAC 数 × 2 得来的；
而论文里报的 FLOPs 有时只数乘不算加。比较两个加速器之前，先统一口径——这也正是《AI 芯片评测基准》一篇里 MLPerf 要统一「Closed 赛制」的初衷。

## 5 从 GPU 到专用加速器

GPU 交出了「最普及 AI 硬件」的答卷，但它身上仍留着大量「贵」的通用性：warp 调度器、分支单元、缓存一致性、CUDA 生态——这些对纯粹的矩阵流水线都是开销。
于是专用加速器登场：Google 的 TPU 直接砍掉通用调度，把芯片压成一片脉动阵列；
华为昇腾、寒武纪走同一路线；Groq 更进一步，把编译器调度做到了极致（详见《TPU 脉动阵列》《代表性 AI 加速器案例》）。
<span class="marginnote">把本专题串起来的暗线其实是「能耗账」：一次 DRAM 访存消耗的能量大约是 200 次 MAC 运算（45 nm 工艺量级）。谁能在片上消化更多数据复用，谁就省下这 200 倍的差价——Tensor Core、脉动阵列、存内计算，全是这笔账的不同解法。</span>而 GPU 与专用加速器的胜负手，
终究要放到统一的标尺——Roofline 模型与能效——上衡量（见《能效评估与 Roofline》一篇）。

## 6 算例：训练一个大模型需要多少算力

把算力换算成「能不能训练大模型」，是这套知识的第一次实战。用 Chinchilla 法则：训练一个参数量为 $N$、数据量为 $D$（tokens）的模型，
浮点运算量约为 $C \approx 6ND$。

**第一步，算总量**：70B 参数、2 万亿 token：$C = 6 \times 70 \times 10^9 \times 2 \times 10^{12} \approx 8.4 \times 10^{23}$ FLOPs。
- **第二步，算单机速度**：一台 8 卡 A100 服务器，BF16 张量峰值约 $8 \times 312 \times 10^{12} \approx 2.5 \times 10^{15}$ FLOPs/s。
- **第三步，看差距**：$8.4 \times 10^{23} / (2.5 \times 10^{15}) \approx 3.4 \times 10^{8}$ 秒 ≈ **3.9 年**。

于是答案很清楚：单台服务器根本不可能，必须上**数百台甚至上千台** GPU 服务器，
配合张量并行与流水线并行（详见《AI 系统》专题），把「3.9 年」压到几周。
而这还只是理想值——真实训练的**模型利用率（MFU，Model FLOPs Utilization）**常只有 40%–60%，意味着还要翻倍。
<span class="marginnote">MFU 是一个极其重要的工程指标：模型理论上该花的 FLOPs，除以实际运行时间对应的 FLOPs。它把「算力有没有被浪费」量化——MFU 低往往不是芯片不行，而是通信、同步、访存占了时间，这正是本专题后续所有「少搬」技巧要救的命。</span>

**重点：** 这个算例想传达的不是「数字」，而是**运算量思维**：有了 $6ND$ 与芯片峰值，任何「训练大模型要多少机器」的问题都能立刻估算。
反过来，它也是理解 MLPerf 训练基准为何采用「time-to-accuracy」指标的一把钥匙。

## M 小结

- **GPU 是吞吐机**：数千轻量核心 + SIMT 模型，与 CPU 的「低时延」哲学相对；线程层次为 thread → warp → block → grid。
- **存储层次**含可编程共享内存，为「已知的数据复用」留了显式抓手；深度学习的真瓶颈常是带宽而非算力。
- **Tensor Core** 一条指令做 4×4×4 的 FP16 矩阵乘加、FP32 累加，V100 共 640 个，带来约 7 倍于 FP32 的专用算力。
- **峰值算力可推演**：$80 \times 8 \times 128 \times f \approx 112$ TFLOPS，公式拆解即硬件结构。
- **GPU 在加速器化**，但通用性的开销仍在，这为专用加速器留出了空间。

把这一讲的算例再往回接一步：GPU 的 7 倍专用化、大模型训练的天文数字，都指向同一个判断——**未来的算力增量主要来自专用化，而不是通用核的提速**。
这也正是本专题接下来每一讲的出发点：TPU 脉动阵列会把「专用」再推进一步。

在下一节，我们将走进第一颗真正「砍掉通用性」的专用芯片——Google 的 TPU，看它的脉动阵列如何把 92 TOPS 装进一颗 28 nm 的芯片。
