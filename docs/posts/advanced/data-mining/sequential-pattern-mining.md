# 序列模式挖掘

## 为什么从序列模式开始

购物篮分析丢掉了时间：
它只知道「尿布和啤酒被同时买了」，
却不知道「顾客先买手机、两周后再买手机壳」。
当每条数据带上了**顺序**，
问题就升级为**序列模式挖掘（sequential pattern mining）**：
在大量有序数据中找出「反复出现的先后顺序」。
它的应用无处不在——用户浏览网页的先后路径、患者用药的时序、DNA 里的碱基序列、交易中的「先小额试探、再大额转账」骗局。
序列模式是频繁模式家族里「从空间到时间」的延伸，
也是连接数据挖掘与时间序列分析（第二级）的桥梁。
<span class="marginnote">序列模式与时间序列（time series）是两个不同概念：时间序列是数值随时间的连续观测（股价、温度），序列模式是<strong>离散事件的先后排列</strong>（行为、状态）。
一个讲究「数值怎么变」，一个讲究「事件什么顺序」——别混。
</span>

## 1 序列、子序列与支持度

**项（item）**与关联规则相同，但顺序结构引入了两级集合：

**元素 / 事件（element / event）**：
同一时间点同时发生的若干项，
用花括号表示，如 $\{a, b\}$。
**序列（sequence）**：
若干元素按时间先后排列，
用尖括号表示，如 $\langle \{a,b\}, \{c\}, \{d\}\rangle$——记 $s_1, s_2, \ldots, s_n$。
**序列的长度**是其中项的个数；
含 $k$ 个项的序列叫 $k$-序列。

**子序列（subsequence）**：
$s$ 是 $t$ 的子序列，
若 $t$ 能通过删除若干元素中的若干项得到 $s$——注意**顺序必须保持**，
但中间可以跳过。例：
$\langle \{a\}, \{c\}\rangle$ 是 $\langle \{a\}, \{b\}, \{c\}\rangle$ 的子序列；
$\langle \{c\}, \{a\}\rangle$ 不是，因为顺序反了。

一条**数据序列（data sequence）**是一个顾客按时间排序的行为序列。
序列 $s$ 的**支持度** = 包含 $s$ 作为子序列的数据序列占比：

$$
\text{support}(s) = \frac{\#\{\text{数据序列 } d : s \preceq d\}}{\#\{\text{数据序列}\}}
$$

给定 min_sup，
支持度达标的序列叫**序列模式（sequential pattern）**。
<span class="marginnote">注意与关联规则支持度的差别：关联规则在一个事务（集合）里看共现，序列模式在一整条数据序列（含多个时间点）里看包含——所以序列支持度天然覆盖了「跨时间点」的共现。
</span>

## 2 序列模式的性质：仍是向下闭包

好消息是：**序列模式保持了向下闭包性质**——若序列 $s$ 是频繁的，
则它的每个子序列也频繁。
理由与项集相同：包含 $s$ 的数据序列必然包含它的任何子序列，
所以子序列支持度 ≥ 原序列支持度。

这条性质让 Apriori 的逐层思路可以直接搬来：
先找频繁 1-序列，
再扩展成频繁 2-序列，
如此递推。但序列的扩展比项集多一种方式，
这正是序列挖掘的核心难点。
<span class="marginnote">项集扩展只有一种：把新项加进集合。
序列扩展有两种：<strong>把新项加进现有元素的内部</strong>（同时间共现），
或<strong>追加一个新元素</strong>（新时间点）。
GSP 算法把这两种扩展分别叫「频繁项扩展」与「序列扩展」，两者都要枚举。
</span>

## 3 GSP 算法：序列版 Apriori

**GSP（Generalized Sequential Patterns）**是序列模式的经典 Apriori 式算法，
逐层走「候选生成—扫描验证」：

**候选生成**：由频繁 $k$-序列连接成频繁 $(k+1)$-序列。
两个 $k$-序列连接的条件是：
去掉第一个元素的第一项后与去掉最后一个元素的最后一项后**相同**——即「首尾重叠」。例：

$$
\langle \{a\}, \{b,c\}\rangle \ \text{与}\ \langle \{b,c\}, \{d\}\rangle \xrightarrow{\text{连接}} \langle \{a\}, \{b,c\}, \{d\}\rangle
$$

**剪枝**：删除含非频繁子序列的候选（向下闭包）。
**计数**：扫描数据库，
统计候选支持度，保留频繁者进入下一层，直到候选为空。

<span class="marginnote">GSP 与 Apriori 的差别全在「连接条件」更复杂：项集连接只需前 $k-1$ 项相同，序列连接要处理「元素边界」——一个项被删后，前一个元素的尾部与后一个元素的头部是否自然衔接。这个边界处理是 GSP 实现里最容易出错的细节。</span>

**辨析｜易错点：** 序列连接时，
「删除第一个元素的第一项」可能导致第一个元素变空而消失，
也可能第一个元素删后仍有剩余——这两种情况都要按规则处理成不同的连接候选。
教科书常强调：GSP 的连接实际上可能生成**多个**候选，
不像项集连接只生成一个。

## 4 公式解析：用支撑性的「头尾重叠」理解连接

设两个频繁 3-序列 $s_1 = \langle \{1\}, \{2,3\}\rangle$ 与 $s_2 = \langle \{2,3\}, \{4\}\rangle$，
希望连接成 4-序列。

**第一步，看 $s_1$ 去头**：去掉第一个元素 $\{1\}$ 的项 1，剩 $\langle \{2,3\}\rangle$。
- **第二步，看 $s_2$ 去尾**：去掉最后一个元素 $\{4\}$ 的项 4，剩 $\langle \{2,3\}\rangle$。
- **第三步，判断重叠**：两者去掉后**相等**（都是 $\langle \{2,3\}\rangle$），满足连接条件。于是 $s_2$ 的尾元素 $\{4\}$ 可以追加到 $s_1$ 末尾，得 $\langle \{1\}, \{2,3\}, \{4\}\rangle$。
- **第四步，验证频率**：剪枝——检查新序列的所有 3-子序列是否都频繁，然后扫库计数。若 $\langle \{1\}, \{2,3\}, \{4\}\rangle$ 的支持度 ≥ min_sup，它就是新的频繁 4-序列。

「首尾重叠」保证了连接出的序列**唯一且合法**：
重叠部分确保 $s_2$ 能无缝接在 $s_1$ 之后，
不产生重复候选，也不丢失任何合法扩展。

## 5 更快的序列挖掘：前缀投影

GSP 逐层扫库，代价随序列长度增长。
Han 团队的 **PrefixSpan** 采用「分治不生成候选」的思路，
与 FP-Growth 异曲同工：
不断对序列库做**前缀投影**——把「以某个频繁前缀开头」的数据序列投影成各自的**后缀数据库**，再递归挖掘。
