## 为什么从语料流水线开始

大模型的能力上限不是模型结构，而是**预训练语料的质量**。GPT-3 论文花了大篇幅讲数据清洗，LLaMA 的团队把「去重与质量过滤」当作核心贡献之一。语料里的脏数据——重复文本、机器生成垃圾、格式噪声——不仅浪费算力，还会直接损害模型能力（重复数据导致记忆过拟合、生成重复）。

本篇把大规模语料预处理的三道工序讲透：**去重、清洗、tokenize**。这是数据管线里「最不 glamorous 却最影响效果」的一环——也是预训练基建的地基。

## 1 三道工序总览

大规模语料预处理的标准流水线：

1. **清洗（cleaning）**：去掉格式噪声、低质量内容、有害内容。
2. **去重（deduplication）**：消除重复文本，跨样本与样本内两级。
3. **tokenize**：文本 → token 序列，打包成固定长度。

顺序通常「清洗 → 去重 → tokenize」，每一步都产出「下一层的输入」。每一道工序都在 TB 级数据上运行，工程上要**分布式 + 流式**处理——这也是它为什么是「基础设施」而非「脚本」。<span class="marginnote">语料预处理的「规模感」：C4 数据集从 745GB 原始数据清洗到 806GB 过滤后数据，LLaMA 用了约 4.7TB 的 CommonCrawl 去重。TB 级数据的每一道工序都要求「能跑完」——单机脚本在此规模下根本不可行，必须 MapReduce/Spark 级别的分布式处理。</span>

## 2 清洗：质量是算力的第一性价比

清洗的目标是「把垃圾挡在训练外」。常见规则：

**格式清理**：去 HTML 标签、去 URL、统一 Unicode、去多余空白。
**语言过滤**：按语言比例/语言模型分类器筛选目标语言。
**质量过滤**：按「困惑度/句子长度/标点比例」启发式过滤——C4 用一组规则（去「Lorem ipsum」等模板、去重复词高比例）。
**有害内容过滤**：按关键词/分类器去除色情、暴力、广告内容。

**关键思想**：清洗的每一分算力都「花在训练前」，直接决定「训练时的每一分算力值不值」。**脏数据进模型 = 算力白烧 + 模型受损**。<span class="marginnote">质量过滤的经典启发式（LLaMA 论文）：用「一个分类器判断是否为维基百科风格」给每个文档打分，低于阈值就丢。这套「高质量参考集 + 分类器打分」的做法，比手工规则更能捕捉「什么是好的训练文本」——但它本身也是预处理阶段的大工程。</span>

## 3 去重：重复是记忆过拟合的温床

重复文本对预训练危害极大：

**记忆过拟合**：重复样本让模型「背下」而非「学会」。
**训练效率浪费**：同一文本训 N 遍，等于算力浪费。
**生成质量下降**：模型学会「重复输出」。

去重的两级：

**精确去重**：完全相同的文档（hash 比对）——SHA1/哈希即可。
**近似去重**：语义相近、略有改动的文档——用 **MinHash（最小哈希）+ LSH**，把「相似文档」归到同一桶，桶内比对。
**文档内去重**：同一文档里的重复段落（如重复的 n-gram），防「生成重复」。

**MinHash 的直觉**：把文档转成「特征集合」，用「最小哈希」签名，签名相近则文档相似——用「集合相似度（Jaccard）」近似「内容相似度」，再靠 LSH 在百万级文档里高效找「疑似重复对」。<span class="marginnote">去重的规模是挑战：几十亿文档的两两比对不可能（$O(N^2)$），MinHash + LSH 把它降到「每个桶内小范围比对」。LLaMA 团队用「8-gram + 5 个 hash 的 MinHash」在 TB 级数据上完成去重——这套组合是当前大模型去重的标准配方。</span>

## 4 tokenize：从文本到 token

tokenize 把清洗后的文本切成 token ID。现代大模型几乎都用 **BPE（Byte Pair Encoding）** 或其变体：

词级切分太粗（OOV 问题）、字符级太细（序列过长）。
BPE 从字符/字节开始，反复合并「出现最频繁的相邻 token 对」，学到「词/子词」的合理粒度。
SentencePiece 在 BPE 基础上支持「文本 ↔ token 无损往返」与「字节回退」。

tokenize 后还有**打包（packing）**：把不等长的 token 序列拼成固定长度（如 4096），减少 padding 浪费。**「短样本拼接」**能让训练吞吐提升 20%–40%（padding 少了）。<span class="marginnote">BPE 的细节（词表大小 32K–128K、特殊 token 分配、是否 byte-level）会微妙影响模型行为——这是《大模型原理》篇 tokenizer 章节的内容。这里只强调工程面：tokenize 是<strong>离线、分布式、一次完成</strong>的，产出二进制格式（如 mds/parquet），训练时直接读。</span>

## 5 公式解析：去重与打包的定量收益

**打包的收益**：设样本平均长度 $s_{\text{avg}}$、目标长度 $S$、不打包时 padding 比例 $\frac{S - s_{\text{avg}}}{S}$。打包（贪心拼接）后 padding 降到接近 0，有效 token 率：

$$\text{Efficiency} = \frac{\text{有效 token}}{\text{总 token}} = \begin{cases} \frac{s_{\text{avg}}}{S}, & \text{不打包} \\[2pt] \approx 1, & \text{打包} \end{cases}$$

**去重的收益**：设语料重复率 $\rho$（重复 token 占比），去重后的有效训练量：

$$\text{Effective} = (1 - \rho) \cdot \text{Total}$$

- **$\frac{s_{\text{avg}}}{S}$（不打包的效率）**：样本短、目标长时大量 padding，算力浪费可达 30%–40%。
- **$1 - \rho$（去重后的有效量）**：$\rho=10\%$ 时，去重省 10% 的算力且提升质量——**去重既是效率优化也是质量优化**。
- **两者叠加**：打包 + 去重合起来，可以把「有效训练量」提升 30%–50%，同时模型质量更好。<span class="marginnote">一个常被低估的事实：打包不仅是「省 padding」，它还会改变「样本边界」——拼接样本时在边界加分隔 token（如 `<|endoftext|>`），模型仍能学到跨样本依赖。现代预训练普遍「全局打包 + 边界 token」，配合「文档级注意力掩码」来精确保留文档边界。</span>

## 6 辨析｜易错点：语料预处理的常见误区

**辨析｜易错点：**
- **「去重随便做做就行」是错觉**：近似去重（MinHash）不做，语义重复的文档会悄悄混进训练。
- **「清洗过头」也有害**：过度过滤可能把高质量但「不标准」的文本（方言、代码、口语）洗掉，损失多样性。
- **「tokenize 在线做」是性能灾难**：几 TB 语料实时 BPE 会让训练慢到不可用，必须离线。
- **「打包后不需要文档边界」是错的**：不标记边界，模型学不到「文档起始/结束」，生成质量受影响。
- **忽略「语料的时间分布」**：预训练数据应覆盖目标时间范围，时间敏感的语料（新闻）要控制比例。

## 7 小结

- **三道工序**：清洗（质量过滤）→ 去重（精确 + MinHash 近似 + 文档内）→ tokenize（BPE + 打包）。
- **清洗原则**：脏数据进模型 = 算力白烧 + 模型受损，清洗算力花在训练前最值。
- **去重**：重复是记忆过拟合与生成重复的温床，MinHash + LSH 是 TB 级标准方案。
- **tokenize**：BPE 离线一次完成，打包（短样本拼接）省 padding、提吞吐 20%–40%。
- **定量收益**：去重省 $1-\rho$、打包提效率到 ≈1，两者叠加让有效训练量大增。

## 8 进阶与延伸

**动手试一次 MinHash 去重**：用 datasketch 库对一小批文本算 MinHash 签名，把相似文档归组——你会直观看到「集合相似度 ≈ 内容相似度」的近似如何工作，以及阈值怎么影响「误伤 vs 漏网」。

**几个值得进一步挖的方向**：

- **去重的「误伤」**：MinHash 阈值太高会漏掉重复、太低会误删「内容相似但不同」的高质量文本——怎么评估去重对下游任务的影响？
- **tokenizer 的「往返一致性」**：`tokenizer.decode(tokenizer.encode(text))` 能否无损还原原文？SentencePiece 的「字节回退」与 BPE 的「unk 风险」——这决定 tokenize 是否可逆。
- **打包的「文档边界」**：拼接样本时加 `<|endoftext|>` 分隔符 + 文档级注意力掩码——为什么不加边界的打包会损害「跨文档学习」？

**自测题**：为什么「重复数据 = 算力白烧 + 模型受损」？如果你能说清「记忆过拟合 + 生成重复」两个危害，就理解了去重「既是效率优化、也是质量优化」的双重价值。

- 调 MinHash 阈值，观察「误伤 vs 漏网」的权衡。
- 对一批语料做精确去重（hash），统计重复率。
- 验证 `tokenizer.decode(tokenizer.encode(text))` 的往返一致性。
