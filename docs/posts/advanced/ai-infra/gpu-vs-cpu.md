## 为什么从「设计哲学」开始

任何一个被问过「为什么 GPU 跑大模型这么快」的人，得到的第一个答案往往不是某个玄妙的指令，而是一句话：**CPU 为「快」而设计，GPU 为「多」而设计。** 这句话背后是一场关于芯片晶体管预算的根本分歧——同样一块硅，CPU 把它押在「让一条指令尽快跑完」，GPU 把它押在「同时跑完尽可能多的指令」。这两种路线分别叫**延迟优先（latency-first）**与**吞吐优先（throughput-first）**。

这一课是《AI 基础设施》技术栈的第一块砖。后续要讲的流式多处理器（SM）、SIMT 与 warp、内存层次、FlashAttention，乃至 NCCL 与集群调度，全都建立在这两条设计哲学之上；而理解「为什么 GPU 长这样」，也能解释训练卡（H100/A100）为何动辄数万美元、显存带宽为何比算力更贵。在第三级《计算机体系结构》里我们已经反复用「量化方法」审视过性能，<span class="marginnote">第三级《计算机体系结构》第一篇讲性能度量（CPU 时间、CPI）、Amdahl 定律与功耗墙，第二篇讲指令级并行（乱序执行、分支预测、投机执行）——今天这篇文章是这些概念在 GPU 世界的落地。</span>今天我们把视角从「单处理器有多快」换成「整块芯片能吞下多少工作」。

## 1 延迟与吞吐：两种衡量速度的尺子

先立住两个会被频繁使用的词：

**延迟（latency）**：一个请求从发出到完成所经过的时间。去咖啡馆点一杯咖啡，从下单到拿到手的时间就是延迟。

**吞吐（throughput）**：单位时间内完成的工作量。同一家咖啡馆每分钟能出多少杯咖啡，就是吞吐。<span class="marginnote">排队论里有一条 Little 定律 $L = \lambda W$：系统内的平均顾客数 = 到达率 × 平均逗留时间。它把「延迟」与「吞吐」在统计意义上绑在一起——这是一个可直接迁移到后面《推理基础设施》排队分析的公式。</span>

一个直觉错误必须当场纠正：**低延迟不等于高吞吐，高吞吐也不等于低延迟。** 一条流水线上每个工位只花 1 秒，但工件要经 100 个工位，单个工件的总耗时仍是 100 秒（延迟高）；可整条线每秒能吐出一个成品（吞吐高）。反过来，一位老师傅单件活儿 10 分钟搞定（延迟低），但一天只做得了 48 件（吞吐有限）。CPU 更像那位老师傅，GPU 更像那条流水线。

这两个量之间有一个教科书级的定量关系，我们在第 4 节拆开。

## 2 CPU：延迟优先的「单线程加速器」

翻开任何一颗现代 CPU 的 die 照片，第一印象是「面积大头根本不在算数上」。以一颗高端桌面 CPU 为例，它会花掉大量晶体管在四件事上：

**大缓存**：L1/L2/L3 三级缓存动辄数十 MB。缓存的意义是让数据尽量留在离核心近的地方——一次命中只要几个纳秒，一次访存却要几百纳秒，命中率直接决定平均访存延迟。<span class="marginnote">缓存的底气来自<strong>局部性原理</strong>：程序在时间和空间上倾向于反复访问相近的地址。这是第三级《计算机体系结构》第四篇「存储层次」的主角，也是 CPU 用「多存」换「少等」的根本依据。</span>
**复杂控制**：乱序执行（out-of-order execution）、分支预测、投机执行（speculation）、超标量调度器……它们的目的只有一个：让指令流水线尽量不空转。一次分支预测失误的代价可达几十个周期，所以 CPU 宁可把面积砸在预测器上。<span class="marginnote">乱序执行与寄存器重命名是第三级《计算机体系结构》第二篇的核心内容——那里你会看到 CPU 为了多发射 3–4 条指令、把指令级并行（ILP）榨到极限付出了多大的控制复杂度。而 GPU 几乎不靠 ILP，它走的是线程级并行。</span>
**高主频与深流水**：现代 CPU 主频 3–5 GHz，流水线十几级。高主频意味着每条指令的周期数少，但代价是功耗随频率的平方上升——这正是第三级《计算机体系结构》里讲的功耗墙。
**少量大核**：桌面旗舰 8–16 个大核（外加若干能效核），服务器 64–96 核。相对 GPU 仍是小数目，但每个核都是「全能冠军」，能独立处理分支密集、依赖串行、交互式的任务。

把这一节的逻辑压缩成一句话：**CPU 的晶体管预算，主要花在「让单条指令更快、少等待」上。** 它的绩效指标是单线程延迟，因为它要伺候的，是操作系统、数据库、编译器和人类交互这类「每一步都不可预测、又要求及时响应」的工作。

## 3 GPU：吞吐优先的「并行吞吐机」

把 GPU 的 die 摊开，你会看到完全相反的风景：**控制单元被压缩成一小条，缓存被压缩成一小条，其余近 80% 的面积密密麻麻全是算力单元。** 一颗 H100 上分布着 132 个流式多处理器（SM），每个 SM 里有 128 个 FP32 核心，合计 16,896 个 CUDA 核心；而它的 boost 主频只有约 1.83 GHz，比 CPU 低得多。每一个核心都小、都慢，但一千多个核心合在一起，FP32 峰值算力来到 67 TFLOPS，内存带宽高达 3.35 TB/s（HBM3）。

GPU 的处理单元遵循**单指令多线程（SIMT，Single Instruction, Multiple Threads）**的执行模型：一个 warp（通常 32 个线程）在同一时刻执行同一条指令，只是作用在各自的数据上。<span class="marginnote">按 Flynn 分类法，CPU 是 SISD（单指令单数据）或多核 MIMD，GPU 是 SIMD 的工程化变体——第三级《计算机体系结构》第一篇的 Flynn 分类在这里第一次有了真实的硬件对应。把 SIMT 与 warp 展开，就是本专题的下一课。</span>

为了吞吐，GPU 做了几个与 CPU 相反的取舍：

- **用并行隐藏延迟，而不是用缓存消除延迟**。CPU 一旦缓存未命中就只能干等；GPU 的逻辑是「反正我有几千个线程在排队」，一个线程访存未命中，调度器立刻换上一批就绪的线程，把等待时间「藏」进别人的计算里。这让 GPU 敢用小缓存，省下的面积全给算力单元。
- **精简控制逻辑**。没有复杂的乱序执行、没有激进的分支预测，warp 调度器以极低成本在就绪 warp 间轮转。代价是分支分化（divergence）会让 warp 里的部分线程空转——这是后话，但设计哲学在此已埋下伏笔。
- **极端的内存带宽**。H100 用 HBM3，带宽高达 3.35 TB/s；CPU 桌面平台的 DDR5 双通道约 90 GB/s。AI 计算是典型的访存密集计算，带宽往往比算力更稀缺，GPU 把大量引脚与面积花在「喂饱」算力单元上。

一句话：**GPU 的晶体管预算，主要花在「同时执行更多指令、搬运更多数据」上。** 它不为「这一次」快，而为「每一批」快。

用一张表把两种哲学并排摆开：

| 维度 | CPU（延迟优先） | GPU（吞吐优先） |
| --- | --- | --- |
| 设计目标 | 最小化单条指令延迟 | 最大化整体吞吐 |
| 核心数量与大小 | 少量大核，高主频 | 海量小核，较低主频 |
| 控制逻辑 | 复杂（乱序、分支预测、投机） | 精简（warp 级统一调度） |
| 缓存 | 大容量多层缓存（数十 MB） | 较小缓存 + 共享内存 |
| 隐藏延迟的手段 | 缓存命中 + 分支预测 | 线程级并行（TLP）掩盖等待 |
| 内存带宽 | DDR5 数十～数百 GB/s | HBM 数 TB/s |
| 擅长任务 | 串行、分支密集、交互式 | 数据并行、计算密集 |

## 4 公式解析：吞吐 = 工作 ÷ 时间

把上一节的直觉定量化。设单个任务从发起到完成耗时 $L$（延迟），系统用 $P$ 个并行单元同时处理任务，单位时间完成的任务数为吞吐 $T$：

$$
T = \frac{P}{L}, \qquad \text{单单元吞吐 } T_1 = \frac{1}{L}
$$

对这条式子做三步拆解：

- **第一步，读懂 $T = P/L$**：吞吐 = 并行度 ÷ 单次延迟。它说明吞吐由两个因素共同决定——延迟 $L$ 越小、并行单元 $P$ 越多，吞吐越高。
- **第二步，看两个极端**：若 $P = 1$（单核串行），$T = 1/L$，想提高吞吐只能降低延迟——这就是 CPU 路线；若 $L$ 固定，$T$ 与 $P$ 成正比——这就是 GPU 路线：**在单条指令延迟不变甚至变大的前提下，用更大的 $P$ 把吞吐顶上去。** GPU 的核心更慢（$L$ 略大），但 $P$ 大了上千倍。
- **第三步，读出它的前提**：$T = P/L$ 暗含「任务互相独立、可被并行分摊」。一旦任务之间存在串行依赖，加速就受制于那条不能并行的关键路径——这正是 **Amdahl 定律** $S = 1 / (1 - f + f/P)$ 要讲的事：可并行部分 $f$ 之外的串行尾巴，是并行加速的天花板。<span class="marginnote">Amdahl 定律的完整推导与应用在第三级《计算机体系结构》第一篇第 6 条。它在 AI 里无处不在：kernel 并行度再高，启动开销、CPU 侧预处理、通信同步都是「串行尾巴」——这也是后面讲 kernel fusion、overlap、大 batch 的出发点。</span>

再用两个量级对比让「吞吐优先」落地。先看算力密度——单位时间完成的浮点运算，即 FP32 峰值算力之比：

$$
\frac{F_{\text{H100 FP32}}}{F_{\text{高端桌面 CPU FP32}}} \approx \frac{67\,\text{TFLOPS}}{1\text{–}2\,\text{TFLOPS}} \approx 30\text{–}60 \times
$$

再看内存带宽——AI 计算最贵的资源：

$$
\frac{B_{\text{H100 HBM3}}}{B_{\text{DDR5 双通道}}} \approx \frac{3.35\,\text{TB/s}}{0.09\,\text{TB/s}} \approx 37 \times
$$

两个比值都在「一两个数量级」的档位。这不是巧合：**算力密度与带宽是芯片在面积、功耗预算下的一组配套决策**——GPU 把预算投给算力与带宽，换来的是对「数据并行、计算密集」问题几十倍的加速；代价是对「串行、分支密集、交互式」问题的低效。于是你在数据中心里看到的真实形态，是 CPU 与 GPU 各司其职：CPU 管调度、数据管线与通信，GPU 管矩阵乘与张量运算。

## 5 从 CPU 到 GPU：GPGPU 与 CUDA 的引子

GPU 并不是为 AI 而生的。它在 1990 年代是**图形处理器**：为光栅化、纹理映射这类「每个像素做同样运算」的工作定制。1999 年，NVIDIA 随 GeForce 256 首次使用「GPU」一词；2001–2003 年间，学界开始尝试把图形 API 当成通用并行计算的后门，用像素着色器硬算矩阵——这就是 **GPGPU（General-Purpose computing on GPU）** 的雏形。<span class="sidenote-number"></span><span class="sidenote">当时的学者把通用计算「伪装」成绘图指令提交给显卡，思路惊艳但极其痛苦——要手动把数据打包成纹理，把计算写成「着色程序」。这个时代以 BrookGPU（2003，斯坦福）为代表。</span>

真正把 GPU 解放出来的，是 2006 年 NVIDIA 随 G80 架构发布的 **CUDA**（次年 Tesla 产品线推向通用计算市场）：程序员可以直接写一段「每个线程做一件事」的代码，由硬件与编译器负责把它铺到几千个核心上。同一个向量相加，CPU 写法是一个循环：

```c
void vector_add(const float *a, const float *b, float *c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];          // 单线程顺序遍历整个数组
    }
}
```

CUDA 的写法是让每个线程各管一个元素：

```cuda
__global__ void vector_add(const float *a, const float *b, float *c) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // 每个线程一个 i
    c[i] = a[i] + b[i];                              // 只处理自己的元素
}
// 启动：vector_add<<<n / 256, 256>>>(a, b, c);
```

对比这两段代码，设计哲学之差一目了然：CPU 的循环强调「一条指令把一批数据算完」（SIMD 向量化），CUDA 强调「一件事拆成几千个线程同时做」（SIMT 线程化）。<span class="sidenote-number"></span><span class="sidenote">CUDA 把「有多少线程」的决定权交给程序员，把「怎么调度几千个线程」的复杂度交给硬件。这层可编程性让 GPU 从图形专用硬件变成通用并行计算资源，是 AI 时代一切软件生态的起点。</span>而「怎么调度几千个线程」的硬件组织最小单位，正是流式多处理器（SM）与 warp，也就是下一课的内容。

从工程视角看，CUDA 的胜利不只是硬件，更是**可编程性**：它让「GPU 算力」从图形程序员专属的工具，变成任何人的通用计算资源。今天的大模型训练与推理，本质是「把 Transformer 里那些数据并行的矩阵乘，尽可能多地填满 GPU 的 16,896 个核心」——填得越满，吞吐越高，GPU 的设计哲学兑现得越彻底。<span class="marginnote">「填满核心」的定量工具是占用率（occupancy）与 Roofline 模型，我们会在第一篇第 9 条与第 14 条分别展开；到那时你会发现，调优 GPU 的一切手段，都是为了让吞吐优先的设计哲学不打折扣地兑现。</span>

## 6 小结

- **两条设计哲学**：CPU 延迟优先——把晶体管投给「让单条指令更快」；GPU 吞吐优先——把晶体管投给「同时执行更多指令」。
- **延迟与吞吐**：延迟是单次耗时，吞吐是单位时间完成量；两者并不等价，$T = P/L$ 说明并行度 $P$ 是 GPU 提高吞吐的根本杠杆。
- **CPU 的手段**：大缓存、复杂控制（乱序/分支预测/投机）、高主频、少量大核，服务串行与交互式任务。
- **GPU 的手段**：海量小核、SIMT、线程级并行隐藏延迟、精简控制、极致内存带宽，服务数据并行与计算密集任务。
- **量级差距**：H100 的 FP32 算力约为高端桌面 CPU 的 30–60 倍，内存带宽约为 DDR5 双通道的 37 倍。
- **历史节点**：GPU 从图形硬件经 GPGPU 演进到 CUDA（2006），可编程性让通用并行计算成为现实；但并行加速始终受 Amdahl 定律的串行尾巴约束。
