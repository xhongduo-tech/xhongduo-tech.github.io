## 为什么从 GPU 内存层次开始

上一课我们结束了对执行模型的讨论：一个 warp 的 32 个线程在硬件上以锁步方式执行同一条指令，调度器用「换 warp」来藏延迟。但「执行得快」只回答了问题的一半——**指令要操作的数据在哪里？** 如果数据躺在几十毫米外的 HBM 里，指令再快也要干等几百个周期。GPU 的峰值算力动辄每秒几十万亿次浮点运算，而显存带宽的增长永远追不上算力的增速，两者的鸿沟一年比一年宽。<span class="marginnote">这正是「从极限到大模型」主线上的关键事实：训练大模型的每一步——矩阵乘、注意力、激活——都要在<strong>「算得飞快」与「搬得动」</strong>之间挣扎。理解了内存层次，才读得懂为什么大模型训练常常卡在访存而非算力，也才看得懂后续 FlashAttention、激活重计算这些看似花哨的技巧到底在解决什么。</span>

于是，所有追求吞吐的设计最终都收敛到同一个问题：**如何把数据放在离计算最近的地方**。这一课我们完整展开 GPU 的内存地图，并给出判断「一个 kernel 到底卡在计算还是卡在内存」的第一个定量工具——它是后面所有显存优化、算子融合、FlashAttention 讨论的公共底座。

## 1 带宽与延迟：两个被混淆的瓶颈

**带宽（bandwidth）**：单位时间里能搬运多少字节。**延迟（latency）**：一次访问从发出到数据回到寄存器，要等多少个周期。两者经常被混为一谈，但在 GPU 上它们指向完全不同的优化手段：

- **带宽瓶颈**：搬运的数据总量太大，吞吐被内存总线卡死。对策是**减少数据移动**——复用、融合、压缩。
- **延迟瓶颈**：每次访问都要等几百个周期，但 GPU 靠大量并发 warp 把等待「藏」起来。对策是**提高并发度**（occupancy）与指令级并行。

一句话：**带宽是水管有多粗，延迟是水要流多远。** GPU 对付延迟的策略不是「等」，而是「换一批线程来算」。<span class="marginnote">数量级感受：A100 80GB 的 HBM2e 聚合带宽约 2 TB/s，H100 的 HBM3 约 3.35 TB/s；而片上 SRAM（寄存器 + Shared Memory）的聚合带宽可达几十 TB/s。也就是说，<strong>数据一旦离开片上，每字节的搬运成本立刻高出一个数量级</strong>——这就是「能片上就别下片」这句话的物理基础。</span>

## 2 五层内存地图

从快到慢、从近到远，先看全貌：

| 层级 | 位置 | 容量（A100 / H100） | 延迟（约） | 管理者 |
| --- | --- | --- | --- | --- |
| 寄存器 | SM 内 | 64K × 32bit / SM（每线程 ≤ 255 个） | ~1 周期 | 编译器分配 |
| Shared Memory | SM 内 | 164 KB / 228 KB | ~20–30 周期 | 程序员显式 |
| L1 缓存 | SM 内 | 128–256 KB（与 Shared 可配置切分） | ~30 周期 | 硬件自动 |
| L2 缓存 | 芯片级 | 40 MB / 50 MB | ~200 周期 | 硬件自动 |
| 全局内存 | 片外 HBM | 40 / 80 GB | ~400–800 周期 | 程序员显式 |

**寄存器（register）**：每个线程私有的最快存储，由编译器自动分配；装不下的局部变量会被「溢出」到 local memory。**Shared Memory**：同一 block 内所有线程共享的片上高速暂存，程序员显式管理——它是整张内存地图里**唯一一块你能精确控制的快速层**，下一课就讲它的编程。**L1 / L2 缓存**：硬件自动管理的缓存，缓存的是全局内存的内容，程序员一般「看不见」，但它的命中率决定了你的**有效带宽**——同样一条全局读指令，L2 命中与直接打 HBM，代价差一个数量级。**全局内存**：整张卡共享的主存，容量最大、最慢，所有进出显存的数据都要过它。<span class="marginnote">为什么片上这么快、片外这么慢？因为物理不同：片上 SRAM 每个比特用 6 个晶体管构成、无需刷新、靠逻辑门直连；片外 DRAM 每个比特是「1 个晶体管 + 1 个电容」，要行列寻址、要周期性刷新充电。<strong>快与慢，是工艺与物理决定的，不是工程师偷懒。</strong></span>

![GPU 内存层次示意图](/images/ai-infra/gpu-memory-hierarchy-1.svg)

图中自上而下的每一层，都是**用容量换速度、用层次换「有效容量」**的一次交易。CPU 上你靠缓存自动命中，GPU 上多了一层——Shared Memory 要你手动管。

## 3 隐藏在缝隙里的三种存储

除了五大层，还有三个「藏起来的存储」经常被忽视：

- **Local Memory**：寄存器溢出时，局部数组会被搬到 local memory。它逻辑上像寄存器、物理上是全局内存的隔间，访问要几百个周期——**寄存器溢出是隐蔽的性能杀手**。<span class="marginnote">编译器通常不会告诉你它溢出了多少。一个快速体检办法：用 <code>ptxas -v</code> 看编译报告里的 <code>spill stores / loads</code> 数字，或者直接用 Nsight Compute 看 local memory 相关指标（第十篇会专门讲剖析）。</span>
- **常量内存（constant memory）**：只读、带专用缓存，warp 内所有线程读同一地址时被广播，一拍搞定；适合存放「所有线程共享的参数」。
- **纹理内存（texture memory）**：带专用缓存与插值硬件，主要为图形设计，在 CUDA 里做只读采样偶尔有奇效，一般用不到。

## 4 公式解析：判断一个 kernel 是计算瓶颈还是内存瓶颈

把「快与慢」翻译成一条可计算的式子。一个 kernel 的墙上时间，粗略地由两者中的**较大者**决定：

$$
t_{\text{kernel}} \approx \max\left(\frac{W}{P_{\text{peak}}},\ \frac{B}{\beta_{\text{peak}}}\right)
$$

对这条式子做三步拆解：

- **第一步，读第一项 $\frac{W}{P_{\text{peak}}}$**：$W$ 是总浮点运算量（FLOPs），$P_{\text{peak}}$ 是 GPU 峰值算力（FLOPS）。这一项的含义是「如果只算数、完全不搬数据，要多久」——它是计算时间的下界。
- **第二步，读第二项 $\frac{B}{\beta_{\text{peak}}}$**：$B$ 是 kernel 实际搬运的字节数，$\beta_{\text{peak}}$ 是峰值内存带宽（bytes/s）。这一项的含义是「如果只搬数据、完全不算数，要多久」——它是内存时间的下界。
- **第三步，理解 $\max(\cdot)$**：算数与搬运在硬件上部分重叠，但总有一个更慢的「主约束」卡住总时间。当第二项更大时，称该 kernel 为**内存瓶颈（memory-bound）**：此时再优化算子、再加计算单元都无济于事，唯一有效的是**减小 $B$**——少搬字节，或把字节搬得更高效（这正是下一课合并访存与后续 FlashAttention 的主题）。

两个数的比值 $\frac{W}{B}$（每搬运 1 字节载荷多少浮点运算）叫**算术强度（arithmetic intensity）**，它是《Roofline 模型》一节的正式主角。今天先记住一个会反复出现的经验结论：**绝大多数深度学习算子——逐元素操作、归一化、attention 的中间层——都是内存瓶颈，而不是计算瓶颈**。这也解释了为什么第五篇《显存优化》里的招数（激活重计算、混合精度降字节）往往比「把 kernel 写得更快」收益更大。<span class="marginnote">把这条结论接到第十二篇《成本工程》：训练时 MFU 上不去，主因往往不是算力利用率低，而是<strong>内存 / 通信把算子「饿」住了</strong>。后面讲并行策略时你会看到，数据并行要同步梯度、张量并行要切分通信，本质都是在调「每字节载荷多少运算」这个比值。</span>

## 5 辨析｜易错点

- **「Shared Memory 就是 L1 缓存」**——错。近几代架构里它们是同一块片上 SRAM 的两个「功能面孔」（可通过编译选项切分配比），但语义完全不同：L1 是**硬件自动管理**的缓存，靠命中率；Shared 是**程序员手动管理**的暂存，靠确定性。缓存可能把同一份数据换进来换出去，Shared 的内容在你 `__syncthreads()` 之前一直待在那里。
- **「访问全局内存快慢都一样」**——大错。连续的、合并的访问与随机的、跨步的访问，实际带宽可以相差一个数量级。这是下一课的全部内容，先记住结论：**地址的「排布」和「远近」一样重要**。
- **「容量越大越好」**——容量与速度天然相反。内存层次的本质就是拿容量换速度，所以「为什么 80GB 的显存这么慢」的答案不是「显存差」，而是「它是为了装下大模型，不是为了快」。

## 6 小结

- GPU 内存是五层金字塔：**寄存器 → Shared Memory → L1 → L2 → 全局内存**，自上而下容量增大、带宽减小、延迟增大。
- **带宽是水管有多粗，延迟是水要流多远**；GPU 用高并发 warp 隐藏延迟，却无法逃避带宽上限。
- Shared Memory 是唯一一块**程序员可精确控制**的片上快速存储；L1/L2 是硬件自动缓存，命中率决定有效带宽。
- 判断瓶颈用 $t_{\text{kernel}} \approx \max(W/P_{\text{peak}},\ B/\beta_{\text{peak}})$；算术强度低的 kernel 注定内存瓶颈，优化应指向**减少搬运的字节数**。
- 寄存器溢出会掉进 Local Memory，是隐蔽的性能陷阱；常量内存与纹理内存在特定场景各有价值。
