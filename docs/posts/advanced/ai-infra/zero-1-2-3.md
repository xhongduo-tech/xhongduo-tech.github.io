## 为什么从 ZeRO 开始

数据并行（DP）是最简单的并行：每张卡复制完整模型、各算各的 batch、最后 AllReduce 梯度。但 DP 有一个致命弱点——**显存随参数量线性增长，而且每张卡都存着一份完整的模型状态**。7B 模型用 Adam 混合精度训练，光模型状态就要约 112GB，单卡根本放不下。DP 对「大模型」束手无策。

ZeRO（Zero Redundancy Optimizer）的回答是一句洞见：**DP 里每张卡都存了「全体」的优化器状态、梯度、参数，这是三份巨大的冗余**。把它们从「每卡一份」改成「每卡一份分片」，DP 的显存上限立刻被放大几十倍。ZeRO 由此分三级递进：先切优化器状态（ZeRO-1）、再切梯度（ZeRO-2）、最后连参数也切（ZeRO-3）。理解 ZeRO，就理解了现代大模型训练显存工程的半壁江山。

## 1 DP 的显存账本：三样东西被复制了

训练一个参数量为 $\Psi$ 的模型，采用 Adam + 混合精度（FP16），每张卡需要维护三类状态：

- **优化器状态（optimizer states）**：Adam 要存 FP32 的主参数副本 $4\Psi$、一阶动量 $4\Psi$、二阶动量 $4\Psi$，合计 $12\Psi$ 字节。
- **梯度（gradients）**：混合精度下梯度存 FP16，$2\Psi$ 字节。
- **参数（parameters）**：模型权重以 FP16 存，$2\Psi$ 字节。

于是**每张卡的模型状态总量 = $12\Psi + 2\Psi + 2\Psi = 16\Psi$ 字节**。<span class="marginnote">为什么 Adam 的 FP32 主权重是 $4\Psi$？因为 Adam 更新需要 FP32 精度，而优化器状态（m、v）各占 $4\Psi$（FP32）。「16Ψ」是单卡训练时的硬性显存下限（不含激活与中间量），记住这个 16 倍关系，后面成本工程篇还会用到。</span>

DP 用 $N$ 张卡，只是把 **batch 切成了 $N$ 份**，模型状态依然是每卡 $16\Psi$——**总显存消耗 $16N\Psi$，其中 $15N\Psi$ 是冗余**。ZeRO 的出发点就是质问：为什么每张卡都要存全量？

## 2 ZeRO 的核心洞察：划分而非复制

ZeRO 的答案极其朴素：**把这些状态沿数据并行维度切成 $N$ 片，每张卡只持有 $1/N$**。需要某一片时，向持有它的卡 AllGather 取来用，用完即丢。

参数：需要前向/后向时 AllGather 全量参数，算完丢弃本地不持有的部分。
梯度：后向产生梯度后，ReduceScatter 把梯度汇总到「该梯度片所属」的那张卡。
优化器状态：每张卡只更新自己那 $1/N$ 片的状态与参数。

于是内存模型从「每卡一份全量」变成「每卡 $1/N$ 份全量」——**总显存消耗从 $16N\Psi$ 降到 $16\Psi$**，增长不再随卡数线性爆炸，而是被均匀摊薄。这是 ZeRO 一切收益的来源。<span class="marginnote">ZeRO 论文标题里的 "Redundancy"（冗余）正是要点：DP 的冗余不在计算而在内存。ZeRO 用通信（AllGather/ReduceScatter）换内存，把「空间冗余」转成「时间开销」——这是并行计算中空间换时间/时间换空间的又一例证。</span>

## 3 三级递进：ZeRO-1/2/3 各切什么

ZeRO 是渐进式设计，每一级在前一级基础上多切掉一类冗余，通信代价也逐级上升：

**ZeRO-1（切优化器状态）**：只切 Adam 状态 $12\Psi$。每卡显存降到 $2\Psi + 2\Psi + \frac{12\Psi}{N}$。通信增加很少（优化器状态只在更新时用到，跨卡交互有限），几乎不损失吞吐。
**ZeRO-2（再切梯度）**：梯度也从每卡一份改为每卡 $1/N$。每卡显存降到 $2\Psi + \frac{14\Psi}{N}$。后向末尾的梯度 AllReduce 被换成 ReduceScatter，通信量不变但早于参数更新释放梯度。
**ZeRO-3（再切参数）**：连参数也分片。每卡显存降到 $\frac{16\Psi}{N}$。代价是**每个算子前后都要 AllGather 参数**，通信量显著上升——这正是它需要高效的通信重叠（后文第五篇、第十篇）来兜底的原因。<span class="marginnote">ZeRO-3 与 DP 的关系要分清：ZeRO-3 是「参数也分片的 DP」，它保留了 DP 的每层计算模式，只是参数要用 AllGather 取回来。这一步让单卡能装下远超自身显存的模型——7B 模型的模型状态约 112GB，用 8 卡 ZeRO-3 每卡只需 14GB。</span>

**ZeRO-3 是最常用的一档**：今天跑 7B 级模型，业界默认就是 ZeRO-3（或其等价实现 FSDP）。ZeRO-1/2 更多作为理解阶梯与轻量场景的选择。

## 4 公式解析：三级切分的显存公式

设参数量 $\Psi$，优化器系数 $K=12$（Adam），DP 规模 $N_g$。ZeRO 论文给出各档每卡模型状态显存：

$$\text{ZeRO-1} = 2\Psi + 2\Psi + \frac{K\Psi}{N_g}, \qquad
\text{ZeRO-2} = 2\Psi + \frac{(2+K)\Psi}{N_g}, \qquad
\text{ZeRO-3} = \frac{(2+2+K)\Psi}{N_g}$$

逐项解读：

- **第一项 $2\Psi$（参数）**：ZeRO-1/2 仍每卡存全量 FP16 参数，只有 ZeRO-3 把它摊成 $2\Psi/N_g$。
- **第二项 $2\Psi$（梯度）**：ZeRO-1 梯度未切；ZeRO-2 起梯度摊薄。
- **$K\Psi$（优化器状态）**：$K=12$ 对应 Adam 的「FP32 权重 $4$ + 动量 $4$ + 二阶动量 $4$」。ZeRO-1 就开始摊薄。
- **$N_g$（DP 规模）**：摊薄的依据——注意 ZeRO 沿 DP 维切分，所以规模用 DP 卡数而不是总卡数。<span class="marginnote">ZeRO 摊薄的是「数据并行维度」：如果一张卡上还叠着 TP/PP，ZeRO 的分片逻辑仍只沿 DP 组进行。理解这一点，才能正确估算 3D 并行下每卡真实显存（后面《3D 混合并行》会算总账）。</span>

代入 $N_g = 8$、$\Psi = 7\text{B}$：ZeRO-1 约 $28 + 98 = 126$GB → 不对，逐项算：$2\Psi=14$GB，$K\Psi/N_g = 84/8 = 10.5$GB，ZeRO-1 ≈ 38.5GB；ZeRO-2 ≈ $14 + 14/8 + 84/8 = 14+1.75+10.5 = 26.25$GB；ZeRO-3 ≈ $112/8 = 14$GB。**同样的 7B 模型，单卡从 112GB 一路降到 14GB**——这就是三级递进的直观威力。

## 5 辨析｜易错点：ZeRO 与 FSDP、DP 的关系

| 维度 | 数据并行（DP） | ZeRO-3 | FSDP |
| --- | --- | --- | --- |
| 参数 | 每卡全量复制 | 每卡 $1/N$ 分片 | 每卡 $1/N$ 分片 |
| 梯度同步 | AllReduce | ReduceScatter | ReduceScatter |
| 通信原语 | AllReduce | AllGather + ReduceScatter | AllGather + ReduceScatter |
| 本质 | 空间冗余 | 用通信换空间 | ZeRO-3 的 PyTorch 实现 |

**辨析｜易错点：**
- **ZeRO-3 ≠ 张量并行**：TP 是把单个矩阵按行/列切开、单算子要联合算；ZeRO-3 每层仍由单卡完整算，只是参数要临时取回。计算模式完全不同。
- **ZeRO 没有牺牲收敛**：分片只是存储布局变化，数学上每步更新与全量 DP 一致。
- **ZeRO-3 的通信不是免费的**：它把 DP 的一次 AllReduce 换成「每个算子前 AllGather + 后向 ReduceScatter」，通信量变大，需要第二篇的通信计算重叠来掩盖。
- **ZeRO-2 与 ZeRO-3 分界**：切不切「参数」是唯一区别；注意 ZeRO-2 仍然每卡有全量参数副本。

## 6 小结

- **DP 的显存账本**：单卡模型状态 $16\Psi$（参数 $2$ + 梯度 $2$ + Adam 状态 $12$），DP 下每卡一份，冗余巨大。
- **ZeRO 的洞见**：把优化器状态、梯度、参数沿 DP 维分片，用 AllGather/ReduceScatter 通信换取显存。
- **三级递进**：ZeRO-1 切优化器状态（$12\Psi/N$）、ZeRO-2 再切梯度、ZeRO-3 连参数也切（$16\Psi/N$）。
- **典型收益**：7B 模型单卡显存从 112GB 降到 14GB（$N_g=8$ 时），大模型训练成为可能。
- **后续**：ZeRO-3 的工程化实现就是 FSDP；而把优化器状态卸载到 CPU/NVMe 则是 ZeRO-Offload，见第五篇。

## 7 进阶与延伸

**动手算一笔账**：用 DeepSpeed 的配置把 ZeRO stage 从 1 切到 3，观察 $1/N$ 里每卡显存的变化。你会看到模型状态从「每卡全量」变成「每卡 $1/N$」——用 ZeRO 篇的公式核对，误差应在一个批次量级内。

**几个值得进一步挖的方向**：

- **ZeRO 与 TP 的叠加**：ZeRO 沿 DP 维分片，TP 沿隐藏维切——两者都开时，显存摊薄的乘法关系怎么算？这就是 3D 并行显存账本的来源。
- **通信量与 ZeRO stage 的关系**：ZeRO-1 几乎不增加通信，ZeRO-3 每算子都要 AllGather——这个通信增量能否被「通信计算重叠」完全隐藏？瓶颈在哪。
- **ZeRO-Offload 的延伸**：ZeRO-3 把状态摊到卡上，Offload 把状态摊到卡外——两者组合后的显存极限是「仅剩激活」，吞吐代价是多少？

**自测题**：ZeRO-2 与 ZeRO-3 的边界在「参数是否分片」——为什么这一刀切下去，通信量就显著上升？如果你能说清「参数分片 → 每算子 AllGather」这条因果链，就算真的懂了。
