## 为什么从存储成本开始

前六篇都在讲数据管线「怎么更快」，但「快」是要花钱的。训练基础设施的成本大头不只 GPU——**存储**是那个「悄悄涨」的账单：TB 级的训练语料、频繁的 checkpoint、加上轮转保留的多份副本，一年下来存储费可能超过一个小团队的预算。而存储成本的特点是**「存着不删就会无限累积」**——它不像 GPU 按小时计费，而是「按量按月」的持久开支。

本篇把训练场景的两大存储对象——**数据**与 **checkpoint**——的成本结构与管理手段讲透。学会「让数据分层、让 checkpoint 瘦身」，是成本工程的基础课。

## 1 存储成本从哪来

训练场景的存储账单主要有四块：

- **原始语料**：TB–PB 级，常驻对象存储。
- **预处理结果**：tokenize 后的二进制（可能与原始语料同量级）。
- **Checkpoint**：每次存档都占「模型 + 优化器状态」的容量，且要轮转保留多份。
- **日志/实验产物**：tensorboard、评估结果、代码与镜像。

四块里，**语料是「一次性写入、长期驻留」，checkpoint 是「频繁写入、不断累积」**——两者的成本特征完全不同，管理手段也各异。<span class="marginnote">一个容易忽略的点：<strong>checkpoint 的容量 ≈ 16Ψ 模型状态</strong>（含优化器），比「模型权重」大 8 倍。一个 70B 模型的一次 checkpoint 约 200GB+，每 1000 步存一次、保留 10 份，就是 2TB——<strong>checkpoint 的存储成本常被低估一个数量级</strong>。</span>

## 2 数据的成本管理：分层与生命周期

语料是「写一次、读 N 次」的长期数据，成本管理靠**分层存储 + 生命周期策略**：

- **热层（SSD/高性能盘）**：正在训练用到的 shard。
- **温层（对象存储标准档）**：全量语料。
- **冷层（归档档/低频档）**：不常用的旧数据、历史版本——价格是热层的几分之一。

云对象存储都提供「生命周期策略」：数据 N 天未被访问，自动降到低频档；M 天后转归档。**把「访问频率」映射到「存储价格」**，是数据成本管理的第一杠杆。<span class="marginnote">生命周期策略的本质是「用自动规则代替人的记忆」：你设定「30 天不访问 → 转冷」，云存储自己执行。这样即使没人记得清理，数据也会「自动变便宜」。训练数据的冷热分层能省 50%–80% 的存储费，几乎零成本操作。</span>

## 3 Checkpoint 的成本管理：瘦身与轮转

Checkpoint 是「频繁写入 + 不断累积」的动态数据，成本管理手段更多：

- **轮转保留（rotation）**：只保留最近 N 份（如 3–5），旧的自动删除。
- **稀疏保存**：每 100 步全量存、每 1000 步再额外留「长间隔快照」——降频保存用于回溯。
- **只存权重不存优化器**：用于「评估/发布」的 checkpoint 不必带优化器状态（省 8/9 的体积）。
- **压缩**：checkpoint 可压缩（但压缩耗时间，需权衡）。
- **冷热分离**：近期 checkpoint 在热存储，历史 checkpoint 转归档。

**「发布用 checkpoint 瘦身」是性价比最高的一招**：发布时只需要「模型权重 + tokenizer」，不需要 8 倍体积的优化器状态——转成 HuggingFace 格式（fp16 权重）后体积只有训练 checkpoint 的 1/10。<span class="marginnote">瘦身的关键区分：「训练 checkpoint」（要恢复训练，必须完整）与「发布 checkpoint」（只需模型，可瘦身）。工程上两套并存——训练期间保留完整存档做容错，发布时导出瘦身版。别让「发布版」占着训练级的存储。</span>

## 4 跨任务的成本协同

多团队共用集群时，存储成本还能跨任务协同：

- **共享语料库**：公共数据集（C4、RedPajama）只存一份，各任务引用而非复制。
- **去重**：语料级去重（上上节）同时省存储——重复数据不存。
- **统一预处理产物**：同一语料 tokenize 一次，多个训练任务复用。
- **镜像/缓存**：基础镜像、常用库缓存，避免每任务重复存储。

**「共享而非复制」** 是存储成本协同的总原则：一份数据被 N 个任务引用，成本是 1 而非 N。<span class="marginnote">这里的「引用而非复制」在对象存储里就是「同一个 bucket 的 object 被多个任务读」——数据不搬家，任务只拿路径。工程上常配一个「共享数据仓库」：所有团队的公共数据统一管理、统一版本，避免「每个团队都拷一份」的存储爆炸。</span>

## 5 公式解析：存储成本模型

设语料总量 $D$、checkpoint 单份体积 $C$、保存频率 $f$（每步一次）、轮转保留 $K$ 份、总训练步数 $S$。

**训练期间的存储峰值**：

$$\text{Peak} = D + K \cdot C$$

**年化存储成本**（语料常年驻留 + checkpoint 轮转）：

$$\text{Cost} = \alpha \cdot D + \frac{S}{f} \cdot \beta \cdot C \cdot K$$

- **$\alpha \cdot D$（语料驻留成本）**：$\alpha$ 是单位容量年费，语料常驻所以是「总量 × 单价」。
- **$\frac{S}{f} \beta C K$（checkpoint 累积）**：总次数 $\frac{S}{f}$ 次写入 × 单份体积 × 保留份数。K 越大、f 越频，成本越高。
- **降本杠杆**：$\alpha$（分层转冷）、$K$（轮转少留）、$C$（瘦身/去优化器）、$f$（降低保存频率）。<span class="marginnote">从公式看降本优先级：$K$ 和 $C$ 是「乘法项」，动它们收益最大——轮转只留 3 份、发布 checkpoint 瘦身到 1/10，直接把成本降 3–10 倍。而「降 $f$」有代价（故障损失变大），要和容错需求平衡。</span>

## 6 辨析｜易错点：存储成本管理的常见误区

**辨析｜易错点：**
- **「checkpoint 越大越安全」不成立**：完整 checkpoint 用于容错，但「轮转无上限」会让存储无限涨——K 必须封顶。
- **「原始语料不能删」过度**：语料有生命周期，旧版本/低质量批次可转冷甚至清理，不是「永远热存」。
- **「压缩 checkpoint 总是赚」不一定**：压缩省存储但费 CPU 时间，高频保存时压缩可能拖慢训练。
- **「把 checkpoint 存对象存储就行」有坑**：对象存储写慢、读慢，checkpoint 的恢复是「关键时刻」，要放高性能存储 + 异步同步到冷层。
- **忽略「删除前的验证」**：删 checkpoint 前要确认「有更近的可用版本」，否则一次误删 = 训练进度全失。

## 7 小结

- **四大存储对象**：语料（常驻）、预处理结果、checkpoint（累积）、实验产物。
- **数据分层**：热/温/冷三层 + 生命周期策略自动转档，省 50%–80%。
- **Checkpoint 管理**：轮转 K 份、稀疏保存、发布瘦身（去优化器）、冷热分离。
- **成本协同**：共享语料库、去重、统一预处理产物，「共享而非复制」。
- **成本模型**：峰值 $D + KC$、年费 $\alpha D + \frac{S}{f}\beta C K$，降本优先动 $K$ 与 $C$。

## 8 进阶与延伸

**动手算你的存储账**：统计你最近训练任务的「语料量 + 预处理产物 + checkpoint 轮转量」，用本篇的成本公式算一年的存储成本——你会发现「没人记得删」的那部分占了多少，并由此制定清理策略。

**几个值得进一步挖的方向**：

- **生命周期策略的配置**：云对象存储的「30 天未访问 → 转冷、90 天 → 归档」规则，怎么与训练节奏（epoch 间隔、checkpoint 保留）对齐？设太短会误伤「低频但关键」的数据。
- **checkpoint 的「稀疏保留」**：每 100 步全量 + 每 1000 步长间隔快照——「近密远疏」的保留策略怎么实现（轮转 + 归档双层）？
- **「共享语料库」的版本管理**：多个团队共用一个语料 bucket，怎么避免「谁改了都不知道」？对象版本的不可变性 + 元数据管理。

**自测题**：为什么「发布 checkpoint 要瘦身到 1/10」？如果你能说清「去掉优化器状态 + 转 FP16 权重」，就理解了「训练存档 vs 发布存档」的区别。

## 9 动手实践清单

- 统计你训练的「语料 + 预处理产物 + checkpoint 轮转」存储量。
- 用成本公式算年存储成本，找出「没人记得删」的部分。
- 配「30 天转冷、90 天归档」的生命周期策略。
- 用「近密远疏」的 checkpoint 保留策略：每 100 步全量 + 每 1000 步长快照。
- 把发布 checkpoint 瘦身（去优化器 + FP16），对比体积。
- 设计「共享语料库」避免多团队重复存储。
- 画「存储分层 × 成本」的降本杠杆表。
