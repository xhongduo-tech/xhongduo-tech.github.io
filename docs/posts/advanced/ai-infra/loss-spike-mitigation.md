## 为什么从尖刺应对开始

上一节我们分析了尖刺的四大成因，但「知道为什么」不等于「救得回来」。训练集群上每分每秒都在烧钱，尖刺一出现，工程师需要的是**立刻能用、按场景可选的预案**：这个尖刺是跳过当前 batch 就能自愈，还是要回滚检查点，或者干脆降学习率硬扛过去？

本篇把尖刺应对整理成一套「决策树 + 操作手册」：三种手段（跳过 batch、回滚 checkpoint、调 LR）各自适用什么场景、怎么做、代价是什么。读完你就能在训练日志报警时，冷静地按表操作。

## 1 先判断尖刺类型：可自愈 vs 破坏性

应对前先分类，这是整套决策树的根：

- **可自愈尖刺**：loss 单次跳高后，后续步数内自然回落。成因多是「一次性坏 batch」或「偶发大梯度」，模型没有被破坏。
- **破坏性尖刺**：loss 跳高后**持续不回落**，或持续波动放大。说明权重已被推出正常区域，模型状态坏了。

区分方法：尖刺后观察 10–50 步，看 loss 是否回到尖刺前水平。<span class="marginnote">这个「观察窗口」是应对的第一步：如果尖刺后 50 步内 loss 自然恢复，什么都不用做；如果没有恢复迹象，才动用下面的手段。过早干预（比如见尖就回滚）会打断正常训练、浪费算力——「先看后动」是运维纪律。</span>

## 2 应对一：跳过 batch（skip batch）

**适用**：数据类尖刺——疑似坏样本、坏 batch 导致的一次性大梯度。

**做法**：检测到 `grad_norm` 超阈值（或 loss 跳升），把当前 batch 的梯度丢弃，**不执行 optimizer.step()**，直接进入下一步（或重新采样一个 batch）。

**代价**：几乎为零——只是浪费一个 batch 的算力。这是最轻量、最常用的应对。

**判断技巧**：跳过该 batch 后如果后续正常，几乎可以断定是数据问题；如果跳过仍复现，说明根源不在数据。<span class="marginnote">工程实现里「跳过」不是真的丢弃整个 batch，而是检测到异常梯度后 `optimizer.zero_grad()` 并 `continue`——很多框架（如 Megatron）内置 `--skip-train-iteration` 或异常检测钩子。注意跳过 batch 会改变「有效步数」与 LR 调度的对应关系，跳过频繁时要小心 warmup/cosine 的错位。</span>

## 3 应对二：回滚检查点（rollback）

**适用**：破坏性尖刺——loss 持续不回落、模型明显被破坏。

**做法**：从最近的健康 checkpoint 恢复（通常是尖刺前 100–500 步的存档），重新训练。

**代价**：丢失尖刺之后、回滚点之前的训练进度——可能白烧几小时算力。这是「重资产」手段，用在救不回来的情况。

**关键优化**：**checkpoint 频率与回滚代价的权衡**。存档越频繁，回滚损失越小，但存档本身也费时间/存储。业界常用「定期快照 + 更频繁的轻量快照」分级：每 100 步存全量、每 1000 步存超长快照。<span class="marginnote">OPT 训练团队的教训是「不要靠回滚解决一切」：频繁回滚会掩盖根因，且回滚本身有风险（checkpoint 恢复错位）。正确姿势是「回滚救急 + 排查根因并行」，而不是把回滚当常规操作。</span>

## 4 应对三：学习率调整

**适用**：超参类尖刺，或尖刺后模型「半坏不坏」需要慢慢恢复。

**三种做法**：

- **临时降 LR**：把 LR 降一个数量级（如 $3\times10^{-4} \to 3\times10^{-5}$）跑几百步，等 loss 平稳再升回。
- **LR warmup restart**：把 LR 归零重新 warmup，给模型一个「重来」的平稳期。
- **永久放缓调度**：若尖刺反复出现，考虑全局调低 LR 或延长 warmup。

**代价**：降 LR 会暂时放慢收敛，但通常比回滚便宜。这是「软性恢复」手段——模型没坏，只是需要慢点走。<span class="marginnote">LR 调整的工程直觉：尖刺后的权重处于「高方差区」，大步更新只会继续放大波动。降 LR 相当于「踩刹车慢慢稳住方向盘」，给 Adam 的二阶矩时间重新校准。经验值是尖刺后降 LR 跑 100–300 步再恢复，效果通常好于硬回滚。</span>

## 5 公式解析：三种手段的决策阈值

把应对做成可编程的规则。设梯度范数 $g = \| \nabla \mathcal{L} \|_2$，历史滑动平均 $\bar{g}$，当前步的 loss 为 $L_t$：

$$\text{异常} \iff \left( \frac{g}{\bar{g}} > R_{\text{norm}} \right) \ \text{或} \ \left( L_t - \text{EMA}(L) > R_{\text{loss}} \right)$$

- **$\frac{g}{\bar{g}} > R_{\text{norm}}$（梯度比）**：当前梯度范数超过历史的 $R_{\text{norm}}$ 倍（如 10 倍）→ 判为异常。这是「跳过 batch」的触发条件。
- **$L_t - \text{EMA}(L) > R_{\text{loss}}$（loss 偏离）**：loss 超过滑动平均 $R_{\text{loss}}$（如 5）→ 判为严重异常。这是「回滚/降 LR」的候选条件。
- **分层响应**：梯度异常 → 先跳过；loss 持续偏离 → 降 LR；偏离 50 步以上 → 回滚。<span class="marginnote">这套「阈值分级」在训练框架里可以做成自动化：低阈值只记录告警，中阈值自动跳过 batch，高阈值暂停并告警人工介入。工业集群通常三步分级，避免「见尖就跳、见跳就滚」的过度反应。</span>

## 6 辨析｜易错点：尖刺应对的常见误区

**辨析｜易错点：**
- **「跳过 batch 万能」是错觉**：它只治数据类尖刺；数值/硬件类尖刺跳了还会来。
- **「一尖就回滚」是浪费**：可自愈的尖刺回滚纯属白烧算力——先观察 50 步再决定。
- **「降 LR 是逃避问题」**：降 LR 只能缓解超参类尖刺，SDC 等硬件问题必须查根因。
- **跳过/回滚会打乱 LR 调度**：跳过频繁时 cosine 调度与有效步数错位，要注意同步调整。
- **别忘了记录尖刺现场**：尖刺时的 loss、grad_norm、loss_scale、batch id 都要留日志——没现场数据，根因排查无从谈起。

## 7 小结

- **决策树**：先观察 50 步分类（可自愈 vs 破坏性）→ 数据类用跳过、超参类用降 LR、破坏性用回滚。
- **跳过 batch**：最轻量，丢弃异常梯度不更新，零代价试错。
- **回滚 checkpoint**：重资产，用于救不回来的情况；靠分级 checkpoint 降低回滚损失。
- **LR 调整**：软恢复，降 LR 跑几百步让模型稳住，通常优于硬回滚。
- **自动化阈值**：梯度比 $g/\bar{g}$ 与 loss 偏离 $L_t-\text{EMA}$ 双信号、三档响应。

## 8 进阶与延伸

**动手做一张「尖刺应对决策卡」**：把本篇的决策树（观察 50 步 → 分类 → 跳过/降 LR/回滚）画成一张流程图，贴在工位上。下次训练日志报警时，你就能按卡操作而不是慌。

**几个值得进一步挖的方向**：

- **自动化的阈值分级**：把「梯度比 > 10 倍 → 跳过」「loss 偏离 > 5 → 降 LR」「偏离持续 50 步 → 回滚」写成训练框架的钩子——自动化后，尖刺处理从「人工救火」变成「系统自愈」。
- **LR 恢复的策略**：降 LR 后多久升回？「cosine 调度 + 尖刺旁路」怎么设计——降到 $1/10$ 跑 300 步再恢复，还是重新 warmup？
- **回滚与容错的结合**：回滚 + 自动重启（第六篇容错训练）配合后，「尖刺自愈」的全流程长什么样？——把「检测、跳过、回滚、重启」串成一条自动链。

**自测题**：为什么「一尖就回滚」是浪费？如果你能说清「可自愈的尖刺回滚等于白烧算力」，就理解了「先观察 50 步」这条纪律的价值。

- 记录「尖刺现场」供回滚后根因分析。
- 把「观察 50 步 → 分类 → 应对」做成自动化钩子。
