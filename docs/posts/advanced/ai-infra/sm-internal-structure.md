## 为什么从 SM 的内部结构开始

上一课我们确立了 GPU 的「吞吐优先」设计哲学，并抛出了两个数字：H100 有 16,896 个 CUDA 核心、132 个流式多处理器（SM）。但「16,896 个核心」这个说法其实有误导性——这些核心并不是 16,896 个互相独立的处理器，而是被组织进 132 个 SM，每个 SM 内部再细分为若干计算单元。要理解「为什么 GPU 能同时跑几千个线程」「为什么矩阵乘比逐元素运算快一个数量级」「为什么每线程寄存器数量决定你能开多少线程」，都得先钻进一个 SM 的内部。

在第三级《计算机体系结构》里，我们把「处理器」当作一个整体来测量性能；今天要解剖处理器本身。<span class="marginnote">第三级《计算机体系结构》第二篇讲过指令级并行（ILP）与超标量发射；SM 内部是线程级并行（TLP）的工程样板——同一块硅上，调度单位从「指令」变成了「warp」。</span>这一课的结论将反复出现在本专题后续：Occupancy、共享内存、FlashAttention、并行切分，全都建立在「SM 里有什么、每个周期能干什么」之上。

## 1 一个 SM 是什么

**流式多处理器（SM，Streaming Multiprocessor）**：NVIDIA GPU 的**基本执行单元**，是 GPU 内部重复排列的「多核处理器」。整颗 GPU 由若干 SM、一块共享的 L2 缓存和若干内存控制器组成——GPU 的「多核」是多到 100 个以上的 SM，而每个 SM 自身又是一台能同时调度成百上千个线程的小型并行计算机。<span class="marginnote">「SM」是 NVIDIA 术语：Ampere（A100）与 Hopper（H100）沿用此叫法；AMD 的对应物叫「CU（Compute Unit）」。结构上 GPU 先分成若干 GPC（图形处理簇），每个 GPC 含若干 TPC，每个 TPC 含 2 个 SM——这套层级我们在《GPU 内存层次》一课会再遇到。</span>

- A100（GA100，7nm）：**108 个 SM** 被启用（die 上共有 128 个，屏蔽 20 个用于提高良率）。
- H100（GH100，4nm）：**132 个 SM** 被启用（die 上共有 144 个）。

每个 SM 是「独立」的：它有自己的**指令调度器、寄存器堆、共享内存、L1 缓存**以及一批计算单元。把 SM 类比成 CPU 的「一个核」并不准确——它更像一台「拥有 4 个调度器的迷你并行机」，每个调度器各自管辖一批线程。

**重点：GPU 的并行度是「两级」的。** 第一级是 SM 之间的并行（一百多个 SM 同时工作），第二级是 SM 内部的并行（每个 SM 同时运行几百到几千个线程）。后面所有并行策略（TP/PP/DP）最终都要落回这两级。

## 2 SM 内部的功能单元总览

以 A100/H100 为例，一个 SM 内部通常包含以下功能单元：

| 功能单元 | 职责 | A100 每 SM | H100 每 SM |
| --- | --- | --- | --- |
| Warp 调度器 | 每周期挑选一个就绪 warp 并发射指令 | 4 | 4 |
| FP32 核心（CUDA Core） | 单精度浮点 FMA（乘加） | 64 | 128 |
| INT32 核心 | 整数运算 | 64 | 64 |
| FP64 核心 | 双精度浮点 | 32 | 64 |
| Tensor Core | 矩阵乘加（FP16/BF16/INT8/FP8） | 4（第三代） | 4（第四代） |
| SFU（特殊函数单元） | 超越函数（sqrt、sin、log 等） | 16 | 16 |
| LD/ST 单元 | 加载/存储访存指令 | 32 | 32 |
| 寄存器堆 | 为全部线程提供私有寄存器 | 64K×32-bit（256 KB） | 64K×32-bit（256 KB） |
| Shared Memory / L1 | 块内共享存储与一级缓存 | 最高 164 KB | 最高 228 KB |
| 最大线程数 / warp 数 | 该 SM 同时容纳的线程/束上限 | 2048 / 64 | 2048 / 64 |

![一个流式多处理器（SM）的内部结构示意](/images/ai-infra/sm-internal-structure-1.svg)

从上表能读出几条关键设计：

**第一，计算单元按「类型」分工，而不是每个单元全能。** FP32 核心只管单精度浮点，INT32 核心管整数，Tensor Core 管矩阵乘，SFU 管超越函数。这种分工与 CPU「一个 ALU 什么都能算」截然不同，是吞吐优先哲学的又一处体现：每种运算用专门硬件，面积效率最高。<span class="marginnote">CPU 里一条加法指令既算整数也算浮点（用同一套或高度耦合的 ALU），GPU 却把 FP32/INT32/FP64 拆成独立单元——收益是纯浮点吞吐拉满，代价是指令混合时部分单元闲置。这也是为什么 kernel 里混入大量整数索引运算会「挤占」发射槽位、拖慢浮点吞吐。</span>

**第二，寄存器堆与调度器是 SM 的「命脉」。** 寄存器堆 256 KB，是片上寄存器的绝对主力；4 个 warp 调度器负责把指令喂给所有计算单元。这两个部件的结构直接决定能开多少线程、能藏多少延迟——我们放到第 3、4 节展开。

**第三，Tensor Core 与 CUDA Core 的吞吐差异巨大。** 一个 SM 的 64 个 FP32 核心每周期合计执行 128 次浮点运算，而 4 个 Tensor Core 每周期合计执行 2048 次 FP16 浮点运算——差了 16 倍。这就是为什么矩阵乘（GEMM）是大模型的绝对主角：它专吃 Tensor Core。

## 3 寄存器堆与 warp 调度器：吞吐的引擎

寄存器堆（Register File）是 SM 里面积最大的部件之一。它由 64K 个 32 位寄存器组成（合计 256 KB），按 4 个分区（partition）组织，每个分区 16K 寄存器，对应一个调度器与一组计算单元。

**寄存器是每个线程的私有存储。** 编译器决定每个线程占用多少个寄存器（通常十几个到上百个），寄存器一旦分配，这个线程在 SM 的生命周期内独占它们。因为寄存器是片上最快、无冲突的存储，线程的中间结果几乎全部住在寄存器里。<span class="marginnote">寄存器总量固定（64K 个），于是「每线程寄存器数 × 每 block 线程数」直接决定一个 SM 能容纳多少线程——这就是后文 Occupancy（占用率）的起点：想开更多线程，就得压低每线程寄存器用量，二者是零和博弈。编译器可用 <strong>maxrregcount</strong> / <strong>__launch_bounds__</strong> 干预这个取舍。</span>

**warp 调度器（warp scheduler）** 是 SM 的「指挥」。A100/H100 每个 SM 有 4 个调度器，每个调度器管辖约 16 个 warp（64 warp ÷ 4）。每个时钟周期，调度器做一件事：**从自己管辖的就绪 warp 里挑一个，发射它的下一条指令**。

这里的关键词是「就绪」。一个 warp 可能因为访存未命中、等待依赖而暂时无法执行；调度器不等它，而是切换到另一个就绪的 warp。这个「随时换人」的机制，就是上一课说的**用线程级并行隐藏延迟**的硬件实现——它是吞吐优先哲学最核心的落地装置。

**辨析｜易错点：** 很多人把「CUDA Core 的个数」当成「CPU 核心数」来理解，进而困惑「为什么 6912 个核心的主频才 1.4 GHz」。**CUDA Core 不是一个完整的处理器核心**，它只是一个 FP32 乘加单元（一条执行流水线的一个端口）；真正「拥有调度能力、寄存器分配、控制逻辑」的处理器级实体是 SM，SM 的个数（108/132）才与 CPU 的「核数」更可比。营销文案里的「N 核心」与体系结构里的「N 处理器」是两个概念。

## 4 公式解析：GPU 峰值算力 = SM 数 × 单元数 × 频率

GPU 的峰值算力（Peak FLOPS）是所有调优工作的天花板，它有一个非常直白的乘法公式：

$$
F = N_{\text{SM}} \times U_{\text{per SM}} \times O_{\text{per unit}} \times f
$$

其中 $N_{\text{SM}}$ 是启用的 SM 数量，$U_{\text{per SM}}$ 是每个 SM 内某类计算单元的数量，$O_{\text{per unit}}$ 是每个单元每周期完成的浮点运算数（一次 FMA 记 2 次浮点运算），$f$ 是核心时钟频率（Hz）。对这条式子做三步拆解：

- **第一步，代入 FP32 核心**：A100 有 $N_{\text{SM}} = 108$，每 SM 有 $U = 64$ 个 FP32 核心，每个核心每周期做一次 FMA（$O = 2$），主频 $f = 1.41 \times 10^9$ Hz：

$$
F_{\text{FP32}} = 108 \times 64 \times 2 \times 1.41 \times 10^9 \approx 19.5 \times 10^{12} = 19.5\,\text{TFLOPS}
$$

这正是 NVIDIA 官方给出的 A100 FP32 峰值。公式里的每个因数都能在架构图里找到对应物，没有任何神秘成分——峰值算力不是测出来的，是「数」出来的。

- **第二步，换成 Tensor Core**：每 SM 有 $U = 4$ 个 Tensor Core，每个每周期完成 512 次 FP16 浮点运算（第三代 Tensor Core 的吞吐规格）：

$$
F_{\text{FP16 tensor}} = 108 \times 4 \times 512 \times 1.41 \times 10^9 \approx 312\,\text{TFLOPS}
$$

与官方数字一致。对比可见：**Tensor Core 路径的算力是 FP32 路径的 16 倍**（$312/19.5 = 16$）。原因从公式里看得清清楚楚：每个 Tensor Core 每周期的浮点运算数（512）是每个 FP32 核心（2）的 256 倍，而单元数量之比只有 $4/64$，二者相乘 $256 \times 4/64 = 16$。

- **第三步，读出公式的局限**：$F$ 是「理论峰值」，假设所有单元每个周期满负荷且指令完全连续。真实 kernel 只能达到峰值的一部分——这个比值就是 MFU（Model FLOPs Utilization），我们在第十二篇成本工程里专门讨论。现在只要记住：**峰值算力由「单元数 × 频率」决定，调优就是让实际执行的指令尽可能逼近这条乘法链**。

H100 的对应数字（FP32 67 TFLOPS、FP16 Tensor 约 990 TFLOPS）是同一公式在更多 SM（132）、更多 FP32 核心（128/SM）、更高频率下的结果，不再重复推导。

## 5 Tensor Core：为矩阵乘定制

大模型里 90% 以上的浮点运算量是**矩阵乘法（GEMM）**：全连接层是 $Y = XW$，注意力里的 Q/K/V 投影与 softmax 加权也是矩阵乘，卷积也能改写成矩阵乘。既然计算如此集中，硬件就该为它定制。

**Tensor Core** 是 NVIDIA 自 Volta（2017）起引入的专用矩阵乘单元。它的一条核心指令 HMMA（Half-precision Matrix Multiply-Accumulate）在一个时钟周期内完成一个小矩阵的乘加：

$$
D = A \times B + C
$$

其中 $A, B, C, D$ 都是小的稠密矩阵（例如 $4\times4$）。A100 的第三代 Tensor Core 支持 FP16/BF16 输入、FP32 累加，还支持 TF32（把 FP32 截断到约 19 位精度参与输入）；H100 的第四代进一步支持 FP8。**累加保持 FP32 精度**这一设计很关键——矩阵乘的误差主要来自累加，用高精度累加器能显著抑制数值漂移。<span class="marginnote">FP32 累加 + 低精度输入正是混合精度训练的硬件根基：存储用 FP16/BF16（省显存、吞吐翻倍），累加用 FP32（保精度）。后面《混合精度训练》一课会专门讲 loss scaling 与主权重机制。</span>

为什么 Tensor Core 比 CUDA Core 快这么多？因为矩阵乘具有**极高的数据复用率**：$C[i,j]$ 需要 $A[i,:]$ 与 $B[:,j]$ 的所有元素，一次载入寄存器的数据会被反复使用。普通核心按「标量乘加」逐元素算，浪费了大量取数带宽；Tensor Core 按「矩阵乘加」一次算一整块，把寄存器与片上带宽的利用率拉满。<span class="marginnote">这一思想正是 FlashAttention 的雏形——「让数据在片上多复用几次，少访问几次慢速存储」。我们会在第一篇第 15 条把 IO 感知设计展开。</span>

**辨析｜易错点：** Tensor Core 不是「软件库」，而是硬件电路；调用它靠特定的矩阵乘指令（WMMA / mma.sync），普通代码若不满足数据布局与指令要求，根本走不到 Tensor Core。cuBLAS 与 cuDNN 之所以快，本质是它们把 GEMM 拆成能喂给 Tensor Core 的瓦片序列——这正是《矩阵乘法 kernel 优化实战》一课要手写的对象。

## 6 小结

- **SM 是 GPU 的基本执行单元**：GPU = 若干 SM + 共享 L2 + 内存控制器；A100 有 108 个 SM，H100 有 132 个。
- **SM 内部按功能分工**：FP32/INT32/FP64 核心、Tensor Core、SFU、LD/ST 单元各司其职，寄存器堆与调度器统管全局。
- **寄存器堆 256 KB、4 个 warp 调度器**：寄存器是线程私有的最快存储，调度器靠「就绪 warp 轮转」隐藏延迟。
- **峰值算力公式** $F = N_{\text{SM}} \times U \times O \times f$：A100 FP32 为 19.5 TFLOPS、FP16 Tensor 为 312 TFLOPS，全部可逐因数核对。
- **Tensor Core 是为 GEMM 定制的硬件**：一个时钟周期做一次小矩阵乘加，FP32 累加保精度，吞吐是 FP32 路径的 16 倍。
- **CUDA Core ≠ CPU 核心**：它只是 FP32 乘加单元，处理器级实体是 SM。

在下一节，我们将回答「一个 warp 到底是什么、32 个线程凭什么被当成一条指令来调度」——这就是 **SIMT 执行模型与 warp（线程束）的工作原理**。
