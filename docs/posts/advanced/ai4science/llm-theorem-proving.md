## 为什么从具体系统开始

前两篇建立了「为什么形式化」「怎么把证明当搜索」的框架。但框架落地成系统时，细节决定成败——**同样是大模型 + 内核验证，GPT-f、LeanDojo、DeepSeek-Prover 走出了三条截然不同的技术路线**，它们的取舍恰好刻画了「AI 定理证明」这个领域三年的演化：从「证明项生成」到「检索增强」再到「合成数据 + 大规模预训练」。<span class="marginnote">2024 年的标志性事件是 DeepMind 的 <strong>AlphaProof</strong> 在 IMO 2024 上达到银牌水平（4 题满分）。它不是本文的主角（未开源），但它把「大模型 + Lean + 强化学习」这套范式带到了世界面前——而它的技术祖先正是下面这三条路线。</span>

这一篇逐个解剖这三个系统：它们各自解决什么问题、核心设计是什么、代价与边界在哪。读完后你会有能力评价任何一个「AI 数学系统」的新闻。

## 1 从 GPT-f 到 Lean 时代：范式的延续

**GPT-f**（2020）在 **Metamath** 上开创了「语言模型逐 token 生成证明 + 内核验证 + 专家迭代」。它的三个关键决策至今仍是默认配置：

- **证明 = 序列生成**：把「证明」当作文本，用 Transformer 一个 token 一个 token 地写——不搞专门的证明语法，直接利用语言模型对序列的建模能力。
- **验证即奖励**：Metamath 的验证器是「裁判」，专家迭代把成功证明回流训练。
- **搜索补足生成**：生成 + 最佳优先搜索，一次生成多条候选，内核挑能过的。

它在 Metamath 语料上达到了约 46% 的自动证明率，证明了「生成式证明」可行。但 Metamath 有两个局限：**表达力抽象**（类似汇编语言，数学结构晦涩）与**库规模小**。社区的目光很快转向 Lean + mathlib——表达力强、库庞大、社区活跃。<span class="marginnote">Metamath 与 Lean 的差别，就像「机器码」与「高级语言」：Metamath 的证明是长长的替换序列，可读性差；Lean 的策略语言让证明接近人类写作。GPT-f 证明了「生成能行」，接下来的问题是「在更真实的系统上能行吗」——LeanDojo 接下了这个挑战。</span>

## 2 LeanDojo：开源基准与检索增强

**LeanDojo**（Yang et al., 2023）的贡献分两块，都成了社区的公共基础设施：

**其一，可复现的基准。** 它从 mathlib 里提取「证明状态-策略」对，构建标准化的训练/测试集，把「证明成功了多少个测试定理」变成可比指标。此前各论文自说自话、不可复现，LeanDojo 终结了这种混乱——**后续几乎所有 Lean 证明研究都拿它当标尺**。<span class="marginnote">LeanDojo 的基准深刻揭示了「前提选择」的难度：许多测试定理的证明需要引用 mathlib 深处的引理，模型必须学会「检索对的引理」，否则再强的生成也无米下锅。它的数据切分还做了「去重」，防止训练/测试定理共享同一段证明而泄漏。</span>

**其二，检索增强的 ReProver。** 它的核心架构是把「选前提」与「出策略」拆开：

1. **前提检索**：用检索器（BM25 + 稠密检索）从 mathlib 中为当前证明状态召回 Top-k 相关引理。
2. **策略预测**：把「状态 + 检索到的前提」拼接，喂给一个小型 Transformer，逐 token 生成下一个 tactic。
3. **搜索**：对每个状态展开 Top-N 策略，用内核验证，最佳优先推进。

结果：在基准上比 GPT-f 式「无检索生成」的解法数量高出数倍（论文报告约 8 倍）——**「检索增强」直接破解了前提选择这一命门**。

## 3 DeepSeek-Prover：合成数据与大规模

DeepSeek-AI 的 **DeepSeek-Prover**（v1/v2，2023–2024）代表了第三条路线：**不靠「读人写的证明」，而是「大规模合成训练数据 + 大模型预训练」**。它有两个关键动作：

- **自动形式化（autoformalization）**：把自然语言数学题翻译成 Lean 形式命题。DeepSeek-Prover 用一个模型「把题翻译成 Lean」，再用另一个模型检查翻译的正确性——**自己造题、自己判卷**。这极大扩充了训练数据，因为自然语言数学题（竞赛题、教科书题）远比形式化定理丰富。
- **整证明生成 + 专家迭代**：让模型一次生成整个证明（而非逐步 tactic），内核裁决；成功样本回流。v2 还引入「证明完备性」策略——在搜索中对「已部分证明的目标」做完整求解，减少「卡在半途」的死角。<span class="marginnote">DeepSeek-Prover 的规模是量级差异：7B 参数、在海量合成数据上训练。它在 miniF2F（Lean）上把基准从「小模型的玩具」推到了「可与人类竞赛题相提并论」的高度，还顺带在 AMC/AIME 级题库上做了测试。它的教训：<strong>定理证明的性能，很大程度是「数据与规模」的函数</strong>——这与其他 LLM 领域并无二致。</span>

**重点：三条路线不是互相取代，而是互补的三块拼图。** GPT-f 证明了「生成范式」可行；LeanDojo 解决了「前提检索」这一工程命门；DeepSeek-Prover 验证了「合成数据 + 规模」是性能主引擎。AlphaProof 把它们揉在一起（Lean + 大模型 + RL + 合成），把系统推到 IMO 银牌。

## 4 公式解析：检索增强的 tactic 预测管线

把 LeanDojo 式「检索 + 生成」的推理过程写成数学管线，一目了然。设当前证明状态为 $s$（目标的 token 序列）：

$$
k = \mathrm{Retrieve}(s),\quad k \subseteq \mathcal{P},\ |k| = K
$$

$$
P(\mathrm{tactic}\ \tau \mid s) = \prod_{t=1}^{|\tau|} p_\theta\big( \tau_t \;\big|\; s,\ k,\ \tau_{<t} \big)
$$

- **$\mathcal{P}$**：全部可用前提（mathlib 的定理库）。**$\mathrm{Retrieve}(s)$** 用双编码器（查询 = 状态 $s$，文档 = 前提）算相似度，取 Top-$K$ 前提 $k$。<span class="marginnote">为什么检索而不是把整个库喂给模型？因为 Transformer 的上下文窗口装不下 30 万条定理——<strong>检索是把「无限知识」压缩进「有限上下文」的标准手段</strong>。这与 RAG（检索增强生成）在问答里的角色同构：不是让模型记住一切，而是让它「当场查到需要的」。</span>
- **$p_\theta(\tau_t \mid s, k, \tau_{<t})$**：Transformer 逐 token 预测策略文本的条件概率——它以「状态 + 检索前提」为上下文，自回归地写出一个完整 tactic（如 `rw [h1, h2]; simp`）。
- **搜索的整合**：对每个状态展开概率最高的若干策略，把「生成的概率」当作搜索的启发式，最佳优先推进直到 `no goals`（证毕）。<span class="marginnote">这里有一个微妙的设计：为什么「检索」与「生成」分开，而不是让模型自己选前提？答案是<strong>工程可靠性与可调试性</strong>——检索器是确定的、可替换的（换更强的检索器立刻提升），生成模型专注于「写对策略」。解耦让两个组件各自精进。</span>

**辨析｜易错点：** 别以为「检索到正确的引理」就万事大吉——**tactic 的语法细节、参数顺序、类型匹配仍有大量坑**。检索增强了「知道用什么」，生成模型仍要「知道怎么用」。两者的配合，才是系统成败的关键。

## 5 评测与现状：miniF2F、IMO 与诚实的一瞥

怎么判断「AI 证明能力」进步了？社区用标准基准说话：

- **miniF2F**：跨 Metamath / Lean / Isabelle 的标准化定理集（来自竞赛题与教科书），是「证明难度」的公共温度计。近年记录：GPT-f 时代约百分之几 → DeepSeek-Prover 时代突破 50%（验证集）。
- **IMO 2024**：AlphaProof 用 Lean 解决了 6 题中的 4 题（银牌线），其中一道代数题答出满分——**AI 首次在数学奥林匹克达到人类奖牌水平**。

但成绩需要诚实解读：**benchmark 之外的「分布外」数学仍是短板**。AI 擅长的题目与训练分布相近；真正全新的、需要构造性洞见的数学（如新定理的发现）仍遥不可及。<span class="marginnote">一个常被忽略的现实：<strong>「解题」与「发现」是两回事</strong>。miniF2F 的题目答案已知（库里已有或可验证），AI 在做「搜索证明」；而数学家的工作常常是「先猜后证」——猜是提出新命题，证是验证它。AI 目前强在后者，前者（下一篇文章的 Pattern Boost 与 AlphaGeometry）才是「AI 辅助发现」的处女地。</span>

**重点：定理证明的 AI 进展，衡量的是「证明能力」而非「数学创造力」。** 这丝毫不减其价值——能自动验证的证明系统，本身就是给人类数学家配的「超级验算员」；但当我们在谈「AI 发现数学」时，要意识到那是一个更高、也还未达到的目标。

## 6 进阶辨析：三个系统背后的「统一范式」与「演进脉络」

把 GPT-f、LeanDojo、DeepSeek-Prover 并排看，能提炼出「AI 定理证明」的统一范式与清晰脉络——这对「判断下一个系统」至关重要。

**统一范式：验证器是地基。** 三个系统共享同一个不可动摇的地基——**「内核验证」**。没有「可机械裁决的对错」，就没有「训练信号」，就没有「搜索剪枝」。**「验证器」是 AI 定理证明的『制度前提』**——它决定了这个领域「能自动化到什么程度」。这也是为什么「形式化数学」（本专题《Lean 入门》）是「AI 数学」的先决条件——**「先有可验证的形式系统，才有可学习的证明」**。

**演进脉络一：从「生成」到「检索 + 生成」。** GPT-f 是「纯生成」（模型直接写证明）；LeanDojo 加「检索」（先选前提再生成）——**「给生成配上上下文」**。这一演进说明：「证明不是『从零发明』，而是『在正确的前提库里组合』」——前提选择的权重被验证了。

**演进脉络二：从「专家数据」到「合成数据 + 规模」。** GPT-f 用「人写的证明」训练；DeepSeek-Prover 用「自动形式化 + 自造题」——**「摆脱人类数据」是规模化的关键**。「合成数据」让「训练数据量」不再受「人类证明产量」限制——这是「性能主引擎从『数据』到『算力』」的转移。

**演进脉络三：从「单体」到「搜索 + 迭代」。** 三者的精度都来自「搜索 + 专家迭代」——不是「单次生成的正确率」，而是「多步搜索 + 验证反馈」的累积。「**生成给候选、搜索给覆盖、验证给反馈**」——三者缺一不可。

把「统一范式 + 演进脉络」连起来，就得到了「判断 AI 数学系统」的框架：**「验证器成熟吗？前提检索到位吗？合成数据够吗？搜索与迭代闭环吗？」**——四个问题问完，一个系统的「真实水平」就清楚了。

**辨析｜易错点：** 别用「单次生成的正确率」衡量证明器——那是「生成模型」的指标，不是「证明系统」的指标。「证明系统的能力 = 单步生成 × 搜索策略 × 验证反馈」——**「搜索与反馈」常常比「单步生成」更决定成败**。

## 7 小结

- **GPT-f** 确立范式：证明 = 序列生成 + 内核验证 + 专家迭代；在 Metamath 上验证「生成式证明」可行。
- **LeanDojo** 提供公共基准 + 检索增强 ReProver：「前提检索 + 策略生成」解耦，破解前提选择命门，解法量提升数倍。
- **DeepSeek-Prover** 走「合成数据 + 大规模」：自动形式化自造题、整证明生成 + 专家迭代，把 miniF2F 推到新高度。
- **检索管线公式**：$k = \mathrm{Retrieve}(s)$ 选前提，$P(\tau \mid s, k)$ 逐 token 生成策略，搜索在概率指引下展开。
- **评测**：miniF2F 是公共温度计；AlphaProof 在 IMO 2024 达银牌——但「解题」与「发现」仍是两回事。
- **能力边界**：AI 强于「搜索证明」，弱于「提出新猜想」；后者是下一批系统要啃的骨头。
