## 为什么从先导优化开始

虚拟筛选和生成模型擅长「找新分子」，但药物发现还有另一个更贴近实战的任务：**先导化合物优化（lead optimization）**。你手上已经有一个活性不错的先导分子（lead），但它可能溶解度差、代谢快、或选择性不够——需要**在不破坏核心药效团的前提下，系统地改进它的性质**。这不是「从零造一个」，而是「沿着化学空间一步步挪」——这恰恰是强化学习（RL）最擅长的形态：**一个 agent 通过一系列小动作，逐步逼近奖励最大化的状态**。<span class="marginnote">RL 在分子设计里的独特价值：生成模型（VAE/扩散）一次性「画」出一个分子，RL 则把优化当成<strong>多步决策</strong>——每步加一个官能团、改一个键，像化学家改结构一样循序渐进。这让它天然贴合「先导优化」这种「沿着先导走」的直觉。</span>

这一篇讲 RL 分子设计的三种主流形态：**序列式策略梯度（SMILES 上的 REINFORCE/REINVENT）、离散 Q-learning（MolDQN）与基于片段的生长式 RL**，以及它们共同的敌人——奖励黑客、模式坍缩与目标漂移。

## 1 任务设定：在「药效团」与「性质」之间走钢丝

先导优化的目标函数通常不止一个。一个典型的奖励函数长这样：

$$
R(x) = w_1\, S_{\text{activity}}(x) + w_2\, S_{\text{ADMET}}(x) + w_3\, S_{\text{sim}}(x, x_{\text{lead}}) - w_4\, S_{\text{synth}}(x)
$$

- **$S_{\text{activity}}$**：活性打分——对接分数或活性预测器。
- **$S_{\text{ADMET}}$**：上一篇讲的成药性端点。
- **$S_{\text{sim}}(x, x_{\text{lead}})$**：与先导的相似度——**防止优化跑偏到完全不同的分子**，保证「优化」而非「重设计」。
- **$S_{\text{synth}}$**：合成可及性（synthetic accessibility）——化学家造得出来才谈得上优化。<span class="marginnote">多目标奖励是 RL 分子设计的常态，也是它最容易翻车的地方：权重 $w_i$ 调不好，优化就偏科。实践中常用「加权求和」的简单形式，或用帕累托多目标方法——但工业界仍以加权为主，因为<strong>权重可解释、好调试</strong>。</span>

**核心概念：先导优化 vs 从头设计。** 从头设计从噪声生成全新分子；先导优化从已知先导出发做**局部修改**，保留核心骨架（药效团）以维持活性，同时改善 ADMET。RL 的「动作空间」因此常被设计成「修改动作」——加原子、加键、删基团、替换片段。

## 2 序列式 RL：把分子生成当作策略

最直接的 RL 分子设计：让一个**生成模型（agent）**像写文章一样逐 token 生成 SMILES，用奖励函数给整条分子打分，再用策略梯度把「生成高分分子的概率」推高。代表是 **REINVENT**（Guilloux et al., 2020）及其后续版本。<span class="marginnote">REINVENT 的架构极具代表性：先用 ChEMBL 的全部分子<strong>预训练一个「先验模型」</strong>（agent 的起点，负责「说人话」——只生成合法、像药的分子），再让 agent 在优化过程中<strong>以 KL 散度为绳，约束自己别离先验太远</strong>。这套「先验 + KL 刹车」是它稳定性的核心。</span>

为什么需要先验约束？因为纯 RL 会陷入**目标漂移（objective drift）**：agent 为了刷奖励，逐渐忘掉「分子的基本化学」——生成的分子越来越合法率低、越来越不像药。先验模型保存了「化学常识」，KL 惩罚让 agent 在「追求奖励」与「保持化学合理性」之间找平衡。

## 3 公式解析：REINFORCE 与 KL 正则

序列式 RL 的目标是最大化期望奖励。设 agent 生成分子 $x = x_1\cdots x_T$ 的概率为 $p_\theta(x)$，奖励为 $R(x)$，目标为：

$$
J(\theta) = \mathbb{E}_{x \sim p_\theta}\big[ R(x) \big] \qquad\Longrightarrow\qquad
\nabla_\theta J(\theta) = \mathbb{E}_{x \sim p_\theta}\Big[ R(x)\, \nabla_\theta \log p_\theta(x) \Big]
$$

- **$\log p_\theta(x)$**：整个分子的对数概率——由逐 token 概率相乘再取对数得到。它是「这条分子怎么被生成」的完整轨迹。
- **$R(x) \nabla_\theta \log p_\theta(x)$**：策略梯度的核心——**奖励高的分子，其生成概率被推高；奖励低的被压低**。这是 REINFORCE 的全部内容：加权最大似然。
- **为什么能这样写**：$\nabla_\theta \log p_\theta(x) = \frac{\nabla_\theta p_\theta(x)}{p_\theta(x)}$ 把「概率对参数的导数」变成「对数概率的导数」——这让不可微的离散采样（token 是离散的）也能被优化。<span class="marginnote">REINFORCE 的代价是方差大：奖励是个标量，无法告诉模型「具体哪一步好哪一步坏」。改进的方向一是加基线（减平均奖励）、二是用更细粒度的奖励（如逐片段）。这条「用可微目标逼近离散优化」的路，也是 GAN 里 Gumbel-softmax 想解决的老问题。</span>

REINVENT 的完整目标在奖励之外加了一项 **KL 正则**：

$$
J_{\text{REINVENT}}(\theta) = \mathbb{E}_{x \sim p_\theta}\Big[ R(x) \Big] - \beta\, \mathbb{E}_{x \sim p_\theta}\Big[ \log \frac{p_\theta(x)}{p_{\text{prior}}(x)} \Big]
$$

- **$p_{\text{prior}}(x)$**：预训练先验模型的概率。
- **$\beta\, \mathrm{KL}(p_\theta \| p_{\text{prior}})$**：惩罚 agent 偏离先验过远。$\beta$ 大 → 更保守（分子更合法、更不易出新）；$\beta$ 小 → 更激进（奖励驱动，但可能漂移）。**它是「探索 vs 化学合理性」的旋钮。**

**辨析｜易错点：** KL 正则不是万能的——它约束「分布距离」，不保证「单个分子的合法性」。agent 仍可能为了高奖励生成先验里罕见但非法的分子。实践中要叠加硬过滤器（价键校验、可合成性）。另一个陷阱是**奖励黑客（reward hacking）**：agent 很快学会「骗预测器」——例如钻打分函数空子生成「打分高但实际无活性」的分子。奖励设计比训练技巧更决定成败。

## 4 离散动作的另一种路：MolDQN 与片段生长

不是所有 RL 分子设计都走「逐 token 生成」。**MolDQN**（2019）把分子优化建模为 **Q-learning**：把分子看成状态，把「加原子/加键/删键」等修改看成动作，用深度 Q 网络学习「在状态 $s$ 做动作 $a$ 能带来多少长期奖励」，再据此贪心/采样地走动作序列。它像下棋：每一步选择把分子改向「未来奖励最大」的方向。<span class="marginnote">Q-learning 与策略梯度的差别：策略梯度直接学「动作概率」，Q-learning 学「动作价值」再决策。在分子这种「状态巨大、动作有限」的离散空间，Q-learning 的价值估计更稳，但要维护状态合法性检查——每个动作都要确认改完还是合法分子。</span>

另一条路线是**基于片段的生长式 RL**：把分子当作「片段（fragment）拼图」，agent 每一步从片段库挑一个片段接上。代表有基于 SYNTHIA/逆向合成片段库的方法。它的优点：

**动作空间大幅缩小**（片段库远小于原子对组合）；
**可合成性天然更高**（片段本身来自已知可合成砌块）；
**化学语义更强**（片段 = 官能团，改动更有意义）。

**重点：动作空间设计 = 归纳偏置。** 逐 token 生成自由度高但易非法；片段生长受限但合法率高；MolDQN 介于之间。选择取决于：你要「探索新化学」（token 级）还是「稳健改进先导」（片段级）。<span class="marginnote">把「分子优化的自由度」看作光谱：SMILES token 级改动自由度最大、也最野；片段级自由度受限但稳定；固定骨架只改侧链自由度最小——先导优化的经典形态。RL 的用武之地正是光谱中段：<strong>既要动得开，又别跑偏</strong>。</span>

## 5 三大挑战与评估

RL 分子设计最常见的三个失败模式，值得每个使用者警惕：

**奖励黑客（reward hacking）**：agent 发现预测器的漏洞，生成「分数爆表但化学荒谬」的分子。对策：奖励函数多样化、周期性人工审查、用鲁棒的集成预测器。
**模式坍缩（mode collapse）**：agent 收敛到少数几个高奖励分子，多样性归零。对策：KL 正则、多 agent、温度采样、周期性重新初始化。<span class="marginnote">一个反直觉的应对是 <strong>GFlowNet</strong>：它不最大化单一奖励，而是让采样概率<strong>正比于奖励</strong>——「奖励高的多采，奖励低的也采」，从而保住多样性。它在分子设计里正成为「RL 之外」的新宠，因为它天然对抗模式坍缩。
<strong>目标漂移（objective drift）</strong>：多目标权重失衡，优化偏科（只顾活性忘了 ADMET）。对策：多目标加权的周期性校验、日志回看分子性质分布。</span>

评估 RL 分子设计的标准组合：**合法率、多样性、奖励均值、与先导的相似度、关键性质（活性/ADMET）的达标率**——以及最重要的**「改进是否真实」**：用独立的验证集（不在奖励函数里的预测器或真实实验）复核 agent 声称的改进。

## 6 进阶辨析：RL 分子设计的「工业整合」与「从 RL 到 GFlowNet」

把 RL 分子设计放进「真实的药物发现管线」，几个整合问题与「范式延伸」值得展开。

**工业整合一：多目标奖励的「权重校准」。** 前文提到奖励是「活性 + ADMET + 相似度 + 可合成性」的加权和——**「权重怎么定」不是「拍脑袋」，而是「与项目目标对齐」**：早期项目「活性优先」（$w_1$ 大），后期项目「ADMET 与可合成性优先」。**「权重是『项目阶段』的函数」**——「不同阶段，奖励函数要重新校准」。

**工业整合二：与「湿实验闭环」的耦合。** RL 优化依赖「奖励函数」（性质预测器）——而「预测器有误差」——**「RL + 湿实验闭环」是纠偏方式**：RL 推荐的分子送实验，实验结果（真实活性/ADMET）回流「校正预测器」→ 再 RL。**「预测器 + 实验 + RL」的三方循环**，与本专题《自动化化学实验室》的闭环同构——「预测误差靠实验数据持续校准」。

**工业整合三：多样性约束的「硬编码」。** 只最大化奖励的 RL 会「收敛到几个高分分子」——**「工业要的是『一个多样化的候选池』，不是『一个分子』」**——「在奖励里加『多样性惩罚』（与已选分子的最小相似度）」——「让 RL 输出『一组互相不同的好分子』」。

**范式延伸：从「最大化奖励」到「按奖励比例采样」。** 本专题《先导优化》已提到 **GFlowNet**——它不「最大化」奖励，而是「让采样概率 ∝ 奖励」：

$$
p_\theta(x) \propto R(x)
$$

- **意义**：奖励高的分子「多采」，奖励低的「也采但不放弃」——**「多样性天然保留」**——「GFlowNet 输出的是『奖励加权的分布』，不是『奖励峰值』」。
- **与 RL 的差别**：RL「只往山顶爬」（收敛到峰），GFlowNet「按高度分布」（山峰采得密、山谷也采得稀）——**「要『最好的一个』用 RL，要『多样的一群』用 GFlowNet」**——「分子设计的『候选池』需求，让 GFlowNet 越来越受青睐」。

把「工业整合 + 范式延伸」合起来，就是 RL 分子设计的「成熟形态」：**「权重对齐项目阶段 + 预测器与实验闭环 + 多样性硬约束 + 按奖励采样」**——「RL 只是『搜索引擎』，它的价值要靠『奖励设计 + 实验闭环 + 多样性管理』共同兑现」。

**辨析｜易错点：** 别把「RL 优化的奖励提升」当「分子性质的提升」——「奖励提升」是「预测器分数的提升」，「预测器分数」≠「真实性质」。「奖励黑客」的风险让「奖励提升」可能「完全不代表真实改善」——「用独立验证器与实验复核，是 RL 分子设计的纪律」。

## 7 小结

- **先导优化** = 保持药效团下改进性质；奖励函数是「活性 + ADMET + 相似度 + 可合成性」的多目标加权。
- **REINFORCE**：$\nabla_\theta J = \mathbb{E}[R(x)\nabla_\theta\log p_\theta(x)]$，把离散 token 生成变成可优化目标。
- **REINVENT** 用「先验模型 + KL 正则」防止目标漂移，$\beta$ 是探索 vs 化学合理性的旋钮。
- **MolDQN** 把优化当 Q-learning（状态=分子，动作=修改）；**片段生长式 RL** 用片段库缩小动作空间、提高可合成性。
- **三大挑战**：奖励黑客、模式坍缩、目标漂移——奖励设计比训练技巧更决定成败；GFlowNet 是「按奖励比例采样」的抗坍缩替代。
- 评估要「独立复核」：合法率、多样性、达标率之外，用不参与训练的验证器确认改进真实。
