## 为什么从反应表示开始

本专题第三篇讲的是「分子」的表示——那是「静态」的：一个分子长什么样。但化学的灵魂是**反应（reaction）**：分子怎么变成新分子。预测反应产物、设计合成路线、推荐反应条件——这些任务的共同前提是：**怎么把「一个反应」表示成机器能学的形式**。这一篇讲三种反应表示：**反应 SMILES**（字符串）、**原子映射**（对齐）、**反应图与模板**（结构）——以及为什么「原子映射」是反应表示的命门。<span class="marginnote">反应表示比分子表示难一个维度：<strong>分子表示描述「一个静态对象」，反应表示描述「一个变换」</strong>——变换的核心是「哪些键断裂、哪些键生成、电子怎么流动」。如果你不知道「反应物里的哪个原子变成了产物里的哪个原子」（原子映射），反应的「故事」就没讲清楚——这也是反应表示里最容易出错、也最决定后续任务成败的一环。</span>

这一篇讲清反应表示的三件套：反应 SMILES 怎么编码反应、原子映射为什么是「对齐问题」、反应图与模板怎么把「反应中心」结构化。它是本篇章后续（产物预测、逆合成、条件推荐）的共同地基。

## 1 反应是什么：原子映射、反应中心与电子转移

**核心概念：化学反应**，从表示的角度看有三层信息：

1. **参与者**：反应物（reactants）与产物（products）——两组分子。
2. **原子映射（atom mapping）**：反应物里的每个原子，对应产物里的哪个原子——**「谁变成了谁」**。
3. **反应中心（reaction center）**：哪些键被断裂、哪些键被生成、哪些原子变了（电荷、杂化）——**「哪里发生了变化」**。

有了映射才能谈「变化」：对比「映射后的反应物原子」与「产物原子」，差异就是「反应中心」。**电子转移的表示**（亲核取代、加成消除）在细粒度上可以表示为「电子对的移动」——但工程上常简化到「键的增减」层级。<span class="marginnote">「原子映射是反应的坐标系」：<strong>没有映射，「反应物 + 产物」只是两个分子列表，无法知道「哪个键断了、哪个键生了」</strong>。有了映射，反应中心、模板、产率预测全都可计算。所以反应表示的第一课，是「把反应对齐到原子级」。</span>

## 2 反应 SMILES：字符串形式的反应

**核心概念：反应 SMILES（reaction SMILES）**：把「反应物」与「产物」用 `>>` 分隔的 SMILES 串：

```
乙醇氧化为乙酸：   CCO>>CC(=O)O
酰胺水解：         CC(=O)NC>>CC(=O)O.N
```

- **`>>` 左边是反应物、右边是产物**（可用 `.` 连接多个分子）。
- **没有原子映射时**：`CCO>>CC(=O)O` 只说「乙醇变成了乙酸」——但「哪个 C 变成了羧基碳」没说。**对人类可行，对机器学习是歧义源**。
- **原子映射版**：给原子编号，标出「对应关系」：

```
C[C:1]O>>C[C:1](=O)O
```

这里的 `[C:1]` 表示「1 号碳」——`>>` 两边都出现 `:1`，说明「反应物的这个碳 = 产物的那个碳」。<span class="marginnote">「反应 SMILES 的歧义」是实际建模的大敌：同一反应，不同软件给不同 SMILES（规范化的差异）；无映射的反应 SMILES 让「机器学习对齐」多此一举。<strong>「先原子映射、再反应 SMILES」是反应建模的标准前置</strong>——RXNMapper、ChemAxon 等工具专做这件事。</span>

## 3 原子映射：反应表示的「对齐」问题

**核心概念：原子映射（atom-atom mapping）**：寻找「反应物原子 → 产物原子」的双射，使「原子的元素一致、结构最相似」。它本质是一个**图论优化问题**：

$$
\sigma^* = \arg\max_{\sigma \in \mathrm{Perm}} \mathrm{Score}\big( \text{反应物图},\ \text{产物图},\ \sigma \big)
$$

- **$\sigma$ 是「原子对应关系」**：把反应物的每个原子映射到产物原子。
- **$\mathrm{Score}$**：衡量「按 $\sigma$ 对齐后，两边的分子图有多一致」——常用「最大公共子结构（MCS）」或「图同构扩展」。
- **约束**：映射必须「保元素」（C 不能映射到 O）、「保价键合理性」。
- **求解**：MCS 是 NP-难问题，工程上用「图同构 + 启发式 + 机器学习」（RXNMapper 用 Transformer 预测映射）。

**为什么映射是「命门」**：映射错了，后续一切（反应中心提取、模板构造、逆合成）全错。**「映射的质量决定了反应 ML 的上限」**——这是反应表示里最被低估的工程事实。<span class="marginnote">「映射的自动求解」本身就是一个 ML 任务：RXNMapper（2021）用 Transformer 把「无映射反应 SMILES」翻译成「有映射反应 SMILES」，精度超过传统 MCS 方法。<strong>「用深度学习解决表示问题」在反应化学里特别明显——映射、规范化、模板提取，都被神经网络重做了一遍</strong>。</span>

## 4 公式解析：反应图与模板

**反应图（reaction graph）**把反应表示成「结构对象」而非字符串。一种自然的构造：把「反应物分子图」与「产物分子图」通过「原子映射」对齐，把「变化」标在图上：

- **反应中心子图**：由「发生变化的原子 + 断裂/生成的键」组成——记为 $G_{\text{rc}}$。
- **完整反应图**：反应物图 + 产物图 + 映射关系——一个「带对应关系的双图」。

**模板（template）**是反应表示的「可复用单元」——从反应中心提取、泛化得到的「反应规则」：

$$
\text{Template} = \text{广义化的反应中心} + \text{局部环境}（\text{半径 } r \text{ 内的原子/键}）
$$

- **提取**：从「带映射的反应」里取反应中心，保留「一定半径的环境原子」作为「模板的上下文」，把具体取代基泛化成「任意基团」（R 记号）。
- **应用**：给定一个「底物」，模板匹配它的「子结构」，即可得到「产物」——**模板是「反应规则」的形式化**。
- **公式化**：模板匹配 = 子图同构问题：找「底物」中与「模板的环境子图」同构的子结构，按模板的「反应中心变化」生成产物。<span class="marginnote">「模板 vs 无模板」是反应预测/逆合成的分水岭（下一篇详述）：<strong>模板方法 = 「查规则库」（可解释、快，但覆盖不了新反应）；无模板方法 = 「直接学映射」（覆盖广，但难保证化学正确）</strong>。模板的「半径 $r$」是重要旋钮——$r$ 太小模板过拟合单反应，$r$ 太大模板太专一、泛化差。</span>

## 5 表示的选择：字符串 vs 图 vs 模板

三种反应表示各有用途，按「任务」选择：

| 表示 | 信息层级 | 典型模型 | 适合任务 |
| --- | --- | --- | --- |
| 反应 SMILES（字符串） | 序列 + 映射标记 | Transformer、Seq2Seq | 反应产物预测、无模板逆合成 |
| 反应图（双图/超图） | 结构 + 映射 | GNN（双图编码） | 反应分类、产率预测、条件推荐 |
| 模板（规则） | 反应中心 + 环境 | 模板检索/匹配 | 模板化逆合成、路线规划 |

**重点：三种表示不是「互相排斥」而是「互补的抽象层次」**——字符串最「平」（好进 Transformer）、图最「结构化」（好进 GNN）、模板最「可解释」（好做规则推理）。现代系统常「混合」：用图/字符串学「新反应的规律」，用模板做「已知反应的保底」——「<strong>数据驱动覆盖新、规则保证旧</strong>」的组合。<span class="marginnote">回到本专题的方法论主线：<strong>「表示的选择 = 对化学的假设」</strong>——字符串假设「反应是序列变换」、图假设「反应是结构变换」、模板假设「反应遵循规则」。哪个假设对？——看任务与数据。预测「常见反应类型」用模板就够，预测「全新反应」必须数据驱动。<strong>没有「最好的表示」，只有「最匹配问题与数据的表示」</strong>。</span>

## 6 进阶辨析：反应表示的「常见错误」与「数据工程现实」

把反应表示做对，几个「常见错误」与「数据现实」要提前知道——它们决定「下游模型的上限」。

**常见错误一：用「未原子映射」的数据直接训练。** 反应 SMILES 不标映射，模型要靠「自己猜对齐」——**「映射是『标注』，不是『可选的』」**——「没有映射，反应中心/模板/变化信息全部丢失，模型只能学『字符串模式』」——「先跑 RXNMapper 补映射，是反应 ML 的标准前置」。

**常见错误二：反应物/产物的「顺序敏感」误用。** 反应 SMILES 里「多个反应物的顺序」若随意排列——「同一反应被写成不同输入，模型要学『顺序不变性』」——**「用『规范化反应 SMILES』（排序规则、统一表示）消除顺序歧义」**——「输入的『确定性』是模型稳定性的前提」。

**常见错误三：把「产物」当「目标」直接学。** 反应表示里「产物」是「结果」——但「哪些是反应物、哪些是试剂、哪个是主产物」的「语义标注」常被忽略——**「反应表示要显式区分『底物/试剂/催化剂/产物』」**——「语义混淆会让模型『学错关系』」。

**数据工程现实一：数据源的「质量参差」。** 反应数据库（USPTO 等）从专利/文献抽取——**「含错误（产物标错、条件缺失、结构错误）」**——「清洗（去重、去错、规范映射）是反应 ML 的最大工作量」——「『干净数据』比『更多数据』更决定模型上限」。

**数据工程现实二：反应类型的「长尾」。** 常见反应类型（酰胺化、酯化）数据海量，稀有反应类型（复杂环化、立体专一）数据稀缺——**「模型擅长『热门反应』、稀烂『冷门反应』」**——「评测要按『反应类型分层』报告，别只看『整体准确率』」。

**数据工程现实三：条件信息的「缺失」。** 很多反应数据「只有结构、没有条件」（温度、催化剂缺失）——**「条件缺失让『条件推荐』类任务无从训练」**——「含条件的反应数据（Reaxys 等）价值高、但获取受限」——「条件信息是反应数据的『高价值字段』」。

把「错误 + 现实」合起来，就是反应表示的「工程清醒」：**「先映射、再规范、后语义标注；数据要清洗、评测要分层、条件要补齐」**——「反应表示的地基不牢，下游一切模型都是沙上建塔」。

**辨析｜易错点：** 别把「反应 SMILES 的『化学正确』当『数据正确』」——「一个化学上合法的反应 SMILES」可能是「数据库里的错误记录」——「合法性」与「真实性」是两回事——「数据清洗要验『真实性』，不只是『合法性』」。

## 7 小结

- **反应的三层信息**：参与者（分子集合）、原子映射（谁变谁）、反应中心（哪些键断/生）。
- **反应 SMILES**：`反应物>>产物` 的字符串编码——无映射时歧义，原子映射版（`[C:1]`）是标准。
- **原子映射**：图论优化（MCS/图同构）——「映射质量决定反应 ML 上限」，RXNMapper 用 Transformer 自动映射。
- **反应图与模板**：反应中心子图 + 模板（广义规则 + 环境半径）——模板匹配 = 子图同构，「查规则库」式推理。
- **表示三角**：字符串（Transformer）、图（GNN）、模板（规则）——互补的抽象层次，常混合使用。
- **第一原则**：先原子映射、再谈表示——「对齐」是反应表示的地基。
