## 为什么从科学知识增强开始

大语言模型「什么都懂一点」，但科学要求「精确、可溯源、不编造」——LLM 的天生缺陷（幻觉）在科学里是致命的。**科学知识增强的 LLM（scientific LLM）** 的思路：**不给模型「自由发挥」，而是让它「基于真实知识回答」**——通过**文献挖掘**（从论文抽结构化知识）、**知识图谱**（把关系织成网）、**检索增强生成（RAG）**（让模型在回答前先查库）。目标是：**LLM 成为「能查会用的科学助手」，而不是「自信的胡编机器」**。<span class="marginnote">「LLM 的幻觉在科学里有多危险」：问「阿司匹林对某种罕见病有效吗」，LLM 可能「顺滑地」编出一个貌似合理的答案——但它引用的「证据」可能不存在。<strong>科学要求「每个结论可溯源到某篇论文/某个实验」</strong>——这直接排除「纯参数记忆」的 LLM，逼出「检索 + 引用」的架构。</span>

这一篇讲科学知识的三种形态、文献挖掘怎么把「非结构化论文」变成「结构化知识」、知识图谱怎么组织关系、RAG 怎么把「检索」接进「生成」，以及科学 LLM 最核心的挑战——**幻觉与可信度**。

## 1 科学知识的形态：文献、数据库与知识图谱

科学知识有三种「组织程度」递进的形态：

**文献（非结构化）**：论文、预印本——**信息最丰富，但机器难读**。三亿篇论文里藏着的知识，90% 以上「沉睡」在非结构化文本里。
**数据库（半结构化）**：DrugBank、UniProt、PubChem——**条目化、可查询**，但「关系」只在字段里隐含。
**知识图谱（结构化）**：把「实体 + 关系」织成图——**基因「调控」蛋白、药物「治疗」疾病、化合物「属于」某类**——机器可推理、可补全。<span class="marginnote">「知识图谱的价值」：数据库回答「这个蛋白是什么」，知识图谱回答「这个蛋白和什么相互作用、参与什么通路、与什么疾病相关」——<strong>「关系网」让知识从「查表」升级为「推理」</strong>。PrimeKG、DRKG、CORD-19 等是科学知识图谱的代表。</span>

**科学 LLM 的「知识来源」选择**：从「参数记忆」走向「检索 + 引用」——**「背得越多越容易错，查得越准越是好助手」**。

## 2 文献挖掘：从论文里抽取结构化知识

**核心概念：文献挖掘（literature mining）**——把「非结构化论文」变成「结构化知识三元组」。核心技术是信息抽取（IE）的两个子任务：

**命名实体识别（NER）**：从文本里找出「实体」——基因名、药物名、疾病名、蛋白名（如「阿司匹林」「COX-2」）。
**关系抽取（RE）**：判断实体间的关系——「阿司匹林『抑制』COX-2」「COX-2 『参与』炎症通路」。

**输出**：「（头实体，关系，尾实体）」三元组，如（阿司匹林，抑制，COX-2）——**文献里的知识被「结构化」成可入库、可查询、可推理的形式**。

**现代做法**：用 LLM 做抽取——给定一段论文文本，让模型输出「实体 + 关系」；再用「人工/规则」校验。LLM 的抽取能力让「从海量文献挖知识」从「手工标注」变成「半自动流水线」。<span class="marginnote">「文献挖掘的难点」：<strong>科学命名的歧义与多义词</strong>——「COX-2」可以是蛋白也可以是基因、「Mercury」可以是元素也可以是行星；「同一实体多个名字」（阿司匹林 = 乙酰水杨酸）需要「实体消歧/链接（entity linking）」到标准数据库。<strong>「把自由文本链接到规范实体」是文献挖掘最烦也最关键的一步</strong>。</span>

## 3 科学知识图谱：知识的「关系网」

**核心概念：科学知识图谱（scientific knowledge graph, KG）**：节点是实体（基因、蛋白、药物、疾病、化合物、通路），边是关系（抑制、治疗、编码、参与、结合）。**KG = 科学知识的关系网络**。

**KG 的价值**：

**可查询**：SPARQL/图查询——「所有抑制 COX-2 的药物」秒回。
**可推理**：图算法/图嵌入——「与阿司匹林相似的药物还有哪些」（基于网络相似性）——这正是药物重定位（本专题第三篇）的知识底座。
**可补全**：链接预测——「预测图中缺失的边」（药物-疾病新关联），是 KG 嵌入模型（TransE 等）的主场。<span class="marginnote">「KG 与 LLM 的结合」是当前热点：<strong>KG 给 LLM「确定的事实」，LLM 给 KG「抽取与生成」</strong>——LLM 从文献抽三元组进 KG，KG 的事实被检索出来「喂」给 LLM 回答。这种「LLM ↔ KG」的互哺，是「科学知识增强」的核心循环。</span>

## 4 公式解析：RAG 检索增强生成

**核心概念：RAG（Retrieval-Augmented Generation，检索增强生成）**——让 LLM 在「生成前先检索」。对科学 QA，RAG 的工作流：

$$
y = \mathrm{LLM}\big( \text{query},\ \text{Retrieve}(\text{query}) \big)
$$

1. **检索（Retrieve）**：对问题 $q$，从「知识库（文献库/KG/数据库）」检索最相关的 $k$ 条知识片段：$\mathcal{K} = \mathrm{Retrieve}(q)$——用「稠密检索」（向量相似度）或「稀疏检索」（BM25）。
2. **增强（Augment）**：把检索到的知识片段拼进「上下文」：$\text{prompt} = [\text{query};\ \mathcal{K}]$——**模型在「看到事实」的前提下回答**。
3. **生成（Generate）**：LLM 基于「问题 + 检索事实」生成答案——**答案的「事实基础」来自检索，不是来自「记忆」**。

**RAG 的优势**：

- **可溯源**：答案引用的知识片段「可回溯到具体文献」——「你凭什么这么说」有答案。
- **知识不过时**：知识库可以持续更新（新论文入库），模型参数不用重训。
- **减少幻觉**：模型被「事实上下文」约束——比「凭记忆编」靠谱得多。<span class="marginnote">「RAG 的检索质量决定一切」：<strong>检索不对，再强的 LLM 也只能「看着错误的上下文编」</strong>——「检索」是 RAG 的咽喉。科学检索的难点：语义相似 ≠ 事实相关（「阿司匹林」与「水杨酸」语义近，但「是否治某病」要看具体证据）；「检索到旧结论 vs 新结论」的权衡（新论文可能推翻旧结论）——「检索的时效与相关性」是科学 RAG 的专门课题。</span>

## 5 幻觉与可信度：科学 LLM 的生死线

科学 LLM 的「可信度」问题，比任何领域都严峻：

**幻觉（hallucination）**：模型生成「貌似合理但不存在」的内容——在科学里可能误导「是否该试这个药、这个基因是否致病」。
**过度自信**：模型给「编造的事实」配上「自信的语气」——用户无法凭文本「感觉」判断真假。
**评估缺失**：「科学答案对不对」需要专业核验——自动评估困难，人工评估昂贵。

**缓解手段**：

**RAG + 引用**：强制「基于检索回答」+ 输出「引用的文献编号」——**「无引用不回答」是科学 LLM 的纪律**。
**知识图谱校验**：答案与 KG 事实做一致性检查——「模型说 A 治疗 B，KG 里有没有这条边」。
**不确定性表达**：模型输出「置信度/不确定提示」——「这个结论来自单篇论文，证据有限」。
**人机协同**：LLM 提供「候选 + 证据」，科学家做「裁决」——**「AI 是参谋，人是司令」在科学 LLM 里是硬性要求**。<span class="marginnote">「科学 LLM 的正确使用姿势」：<strong>把它当「会查文献的助理」，不是「会下结论的专家」</strong>——让它「汇总证据、指出争议、建议下一步」，而不是「宣判某个科学结论」。可信度不是「模型训练能解决的」，而是「架构（RAG）+ 纪律（引用）+ 流程（人审）」共同保证的。</span>

**辨析｜易错点：** 「科学 LLM」≠「通用 LLM 微调一下」。**微调只能让模型「说科学的话」，不能让它「说得对」**——「说话的风格」与「知识的事实性」是两回事。真正的科学 LLM 必须「外接知识」（RAG/KG）才能「可信」——「参数记忆」在科学里永远是「不足够」的。

## 6 进阶辨析：科学 LLM 的「部署形态」与「信任的建立」

把科学 LLM 从「演示」推进到「可用」，要选对「部署形态」、并系统地「建立信任」。

**部署形态一：本地 vs API vs 私有化。** 科学数据高度敏感（患者基因、未发表研究）——**「数据不出域」是科学 LLM 部署的硬约束**。本地部署（开源模型）保护数据但算力受限；API（闭源模型）方便但数据出境。「私有化部署 + 开源模型」是「数据安全 + 能力」的主流折中。**「先定数据边界，再选部署形态」**。

**部署形态二：检索层 vs 微调层。** 「RAG（检索）为主、微调为辅」是科学 LLM 的主流架构——「检索负责『知识新鲜』、微调负责『输出风格/格式』」。**「用 RAG 扛『知识』，用微调扛『行为』」**——「知识更新只换索引、行为调整只微调」——「两层的解耦」让维护变得便宜。

**建立信任一：从「引用」到「证据链」。** 科学 LLM 的答案要「引用的文献/数据 + 引用的位置」——「不只是『我引用了 XX 论文』，而是『这段结论来自该论文的某个图/表/段落』」——**「证据链的粒度越细，可信度越高」**。「答案 + 证据链」让科学家能「快速核验」，而不是「重新读一遍文献」。

**建立信任二：显式的「不确定分层」。** 模型要能区分「确定事实」「当前共识」「争议观点」「推测」——**「把『已知/共识/争议/猜测』分层标注，是科学 LLM 的诚实度标志」**——「敢于说『这是争议点』的模型，比『一律肯定』的模型更可信」。

**建立信任三：失败模式的「预声明」。** 可信的助手要「知道自己会怎么错」——「对罕见病、对新领域、对证据不足的问题，模型应『主动声明低置信』而非『硬答』」——**「知道自己不知道，是信任的起点」**。

把「部署形态 + 信任建立」合起来，就是科学 LLM 的「生产级画像」：**「数据不出域的部署 + 检索/微调解耦 + 细粒度证据链 + 诚实的不确定分层」**——「能力」与「信任」必须同时上线，缺一不可。

**辨析｜易错点：** 别把「模型说『我引用了一篇论文』」当「可信」——**「引用的存在」不等于「引用与答案相关」**；「幻觉」可以伪装成「引用」。验证「引用真的存在 + 真的支持结论」，才是「信任的落地」。

## 7 小结

- **科学知识三形态**：文献（非结构化、信息最全）、数据库（半结构化、可查）、知识图谱（结构化、可推理）。
- **文献挖掘**：NER（找实体）+ 关系抽取（找关系）→ 三元组——「非结构化 → 结构化」；实体消歧是命门。
- **科学 KG**：实体 × 关系的网络——可查询、可推理、可补全；与 LLM 互哺（LLM 抽知识进 KG、KG 事实喂 LLM）。
- **RAG 公式**：$y = \mathrm{LLM}(\text{query},\ \text{Retrieve}(\text{query}))$——检索增强上下文、答案可溯源、知识不过时。
- **幻觉与可信度**：RAG + 引用 + KG 校验 + 不确定性表达 + 人机协同——「无引用不回答」是纪律。
- **核心区分**：微调给「科学的语气」，外接知识给「科学的事实」——可信度靠「架构 + 纪律 + 流程」，不靠「训练」。

在下一节，我们把「能查会用的 LLM」再进一步，变成「会行动的智能体」：**科学 Agent——自主规划、工具调用与实验执行**。

> **延伸辨析：科学 LLM 的『版权与归因』**。科学 LLM 引用文献——但「引用是否尊重了『数据的版权与作者的贡献』」？——**「『引用』不只是『技术正确』，也是『学术伦理』」**——「模型『总结/转述』论文时，是否侵犯版权、是否给了原作者应有的归因」。
>
> 这正在成为科学 LLM 的「制度难题」：**「AI 时代的学术引用规范」尚未建立**——「如何『公正地使用、正确地归因』科学文献」，需要学术界与出版界共同制定新规则。
