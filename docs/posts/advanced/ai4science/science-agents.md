## 为什么从科学 Agent 开始

前面讲的科学 LLM 是「回答问题」——你问它，它答，然后停止。但科学工作不是「一问一答」，而是「一个多步流程」：提出假设 → 查文献 → 设计实验 → 跑工具 → 分析结果 → 修正假设 → 再试。**科学 Agent（scientific agent）** 把 LLM 从「答题机」升级为「执行者」：**它自主规划多步任务、调用外部工具（数据库、模拟器、计算引擎、实验室设备）、根据结果反思并迭代**。这代表 AI 在科学中的角色从「参谋」走向「研究员」——尽管还很稚嫩。<span class="marginnote">「Agent 与 LLM 的本质区别」：<strong>LLM 是「单轮问答」，Agent 是「多轮行动循环」——「观察 → 思考 → 行动 → 再观察」</strong>。Agent 拥有「工具」（不然只能空谈）与「循环」（不然只能一步）。「ReAct 范式」（Reason + Act 交替）让「思考」与「行动」交织——是当前科学 Agent 的主流骨架。</span>

这一篇讲科学 Agent 的能力边界、三大核心能力（规划、工具、反思）、ReAct 循环的数学形式、代表系统（ChemCrow、Coscientist、AI Scientist），以及最诚实的讨论——**Agent 离「自主科研」还有多远**。

## 1 从「助手」到「执行者」：科学 Agent 的能力边界

科学 Agent 的「任务形态」比 QA 复杂得多。以「设计一个合成路线」为例：

**QA 形态**：「告诉我阿司匹林的合成路线」——一个答案。
**Agent 形态**：「帮我设计并验证一条可执行的合成路线」——需要：查数据库 → 规划路线 → 用逆合成工具跑 → 检查原料可得性 → 评估成本 → 返回完整方案。

**Agent 的「能力边界」由三件事决定**：

1. **工具**：能调用什么？——数据库（PubChem、UniProt）、计算引擎（RDKit、DFT）、模拟器、甚至机器人实验平台。
2. **规划**：能把大任务拆成小步骤吗？——「先查文献 → 再算性质 → 最后验证」。
3. **反思**：能根据中间结果修正自己吗？——「这条路线走不通，换一条」vs「撞了南墙不回头」。<span class="marginnote">「Agent 的『工具』是它的『手』」：<strong>没有工具的 Agent 只能「说」，有工具的 Agent 才能「做」</strong>——工具的丰富度直接决定 Agent 的能力上限。这也是为什么「工具生态」（RDKit、ChemPy、PyMOL、数据库 API）是科学 Agent 的基石——「工具的 API 化」程度 = 科学可自动化的程度。</span>

## 2 核心能力：规划、工具、反思

**规划（planning）**：把「目标」分解成「子任务序列」。科学任务的分解常有「天然的层级」——「先理解问题 → 再选方法 → 后执行 → 终验证」。LLM 的规划能力来自「见过大量『怎么做科学』的文本」，但**规划的「幻觉」是 Agent 的头号风险**——它可能规划一个「看起来合理但实际不可执行」的流程。

**工具调用（tool use）**：Agent 在行动中调用外部函数——`query_uniprot`（查蛋白序列）、`calc_logp`（算分子性质）、`run_dft`（做量子化学模拟）。工具调用的关键是「参数生成」——LLM 要「正确地填参数」，工具要「正确地返回结果」，两者都要对。

**反思（reflection）**：Agent 在得到工具结果后，**评估「结果是否符合预期」、决定「继续还是修正」**——「这个反应预测的收率太低，换催化剂」。反思是 Agent 区别于「一次生成」的「自我修正」能力，也是「多轮循环」的价值所在。<span class="marginnote">「规划 vs 反思」的张力：<strong>规划是「先想后做」，反思是「做后想」</strong>——好 Agent 两者都要。纯规划（不反思）会「按计划撞墙」，纯反思（不规划）会「走一步算一步、毫无方向」。ReAct 把两者交织——「每步先想（Reason）、再动（Act）」——是当前最实用的平衡。</span>

## 3 公式解析：ReAct 循环

把 ReAct 式科学 Agent 的「行动循环」写成数学。设任务为 $T$，Agent 维护「轨迹 $\tau_t$」（已发生的历史：思考、行动、观察）。每一步：

$$
\tau_{t+1} = \tau_t \cup \{ \underbrace{\text{Thought}_t}_{\text{思考：分析当前状态}}, \underbrace{\text{Action}_t}_{\text{行动：调用工具}},\ \underbrace{\text{Observation}_t}_{\text{观察：工具结果}} \}
$$

- **Thought$_t$**：LLM 对「当前状态」的分析——「我查到了候选分子，下一步应该验证它的可合成性」。
- **Action$_t$**：LLM 输出的工具调用——`calc_logp("CC(=O)O")` 或 `run_dft("benzene")`——**一个结构化动作**（工具名 + 参数）。
- **Observation$_t$**：工具执行后的真实结果——「可合成性分数 = 0.3，偏低」。
- **循环终止**：当「Thought 判定目标达成」或「超过最大步数」——Agent 输出最终答案/方案。

**为什么「思考与行动交替」优于「先全部规划再执行」**：科学任务的执行常有「不可预见的中间结果」——「计划赶不上变化」。「边想边做」让 Agent 能「根据真实反馈调整」——**「行动中反思」是 Agent 应对「开放世界」的核心机制**。<span class="marginnote">「ReAct 的成功秘诀」：<strong>「Thought 让推理可见、Action 让步骤可执行、Observation 让反馈真实」</strong>——三者循环让「LLM 的单步能力」放大成「多步任务解决能力」。科学 Agent 的工程重点在「工具的可靠性」与「观察的正确解析」——「工具返回错、Agent 再聪明也白搭」。</span>

## 4 代表系统：ChemCrow、Coscientist、AI Scientist

**ChemCrow**（2023）：LLM + 18 个化学工具（RDKit、PubChem、合成规划、毒性预测）——能「设计合成路线、评估毒性、检索化合物」。它的意义：**证明了「通用 LLM + 领域工具」能完成「需要专业知识 + 工具调用」的化学任务**。

**Coscientist**（2023）：LLM + 网络搜索 + 文档 + **机器人实验平台**——「自主完成整个化学研究」：搜索文献 → 设计反应 → 调用机器人执行 → 分析结果。它在「钯催化偶联」等反应上成功「自动跑通了实验」——**「AI 规划 + 机器人执行」的端到端闭环**（与自动化实验室一章呼应）。

**AI Scientist**（Sakana AI, 2024）：全自动科研管线——「提出想法 → 跑实验 → 写论文 → 自我评审」——试图「完整复刻科研流程」。它的意义与争议并存：**「全自动」看似完整，但「想法的质量、实验的严谨、论文的贡献」都远未达人类水平**——它更像「自动化的科研流程演示」，而非「真的科研」。<span class="marginnote">「三个系统的共同模式」：<strong>「LLM 大脑 + 工具生态 + 循环反馈」</strong>——区别只在「工具的种类」（计算工具 vs 实验平台）与「自主的程度」（人监督 vs 全自动）。<strong>「Agent 的『科学能力』= LLM 的『推理』 × 工具的『能力』 × 循环的『质量』」</strong>——这个乘积关系决定了「换更强的 LLM、加更好的工具、改进循环」各自的价值。</span>

## 5 挑战：可靠、安全、评估

科学 Agent 的「三个死刑问题」：

**可靠性**：错误会「传播放大」——第一步的小错（查错数据、调错参数）会沿着循环滚成「看起来合理但全错」的结论。**「错误的累积」是 Agent 与「单步模型」的本质区别**——单步错一步，Agent 错一整套流程。

**安全性**：Agent 可能「调用工具造成实际后果」——在实验室里「执行一个危险反应」、「合成一个有毒化合物」。**「物理世界里的 Agent」需要安全约束**：权限限制、危险操作拦截、人工审批关卡。

**评估**：怎么评价「一个 Agent 完成科学任务的好坏」？——「最终答案对错」不够，还要看「过程的合理性、工具使用的正确性、反思的有效性」。**「流程级评估」是 Agent 研究的开放难题**。<span class="marginnote">「安全的边界」：<strong>科学 Agent 的「行动空间」从「纯文本」延伸到「工具调用」再到「物理操作」——每延伸一步，安全约束重一分</strong>。「只读工具」（检索、计算）风险低，「写工具」（修改数据库、提交计算任务）风险中，「物理工具」（机器人实验）风险高——「分层授权 + 人工审批」是当前的主流安全设计。Agent 再聪明，也必须在「权限围栏」里跑。</span>

**辨析｜易错点：** 别把「能跑通 Demo」当「能可靠科研」——演示场景（精心挑选的任务）与真实科研（开放、模糊、出错率高）差距巨大。**「论文里的 Agent 成功率」与「真实科研的可依赖度」之间，隔着「鲁棒性」这道鸿沟**。科学的诚实要求：把 Agent 当「探索性工具」，不当「可靠的研究员」。

## 6 进阶辨析：科学 Agent 的「可靠性工程」

Agent 从「演示」走向「可用」，靠的不是「更强的 LLM」，而是「围绕可靠性的工程」。把四个关键机制展开：

**第一，工具调用的「沙盒化」。** 科学 Agent 的工具分「只读」与「写/物理」两档——检索、计算可以放开；修改数据库、提交任务、控制实验设备必须「审批」。**「工具的权限分级」是 Agent 安全的物理边界**：只读工具可以「自由试错」，危险工具需要「人确认」——「Agent 的自由度与它的权限半径成正比」。

**第二，错误检测与恢复。** 一个可靠 Agent 必须能「发现自己错了」：工具返回异常、结果违反物理约束（能量不守恒、价键非法）、步骤之间矛盾——**都要有「检查器」拦下来**。设计良好的 Agent 会「反思后重试」而不是「一路错到底」——「重试策略」与「最大重试次数」是重要的可靠性旋钮。

**第三，可审计的轨迹。** Agent 的每一步（思考、行动、观察）都要「留痕」——**「决策可回溯」是科学 Agent 被信任的前提**。「为什么这么做、依据什么、结果如何」——这条轨迹让人类能「审阅 Agent 的工作」，而不是「盲信它的结论」。

**第四，人的介入点。** 可靠的 Agent 不是「全程无人」，而是「在关键节点请人确认」——任务开始时的「目标确认」、执行中「异常时的求助」、结束时的「结果审查」。**「在不确定时承认不确定、请求帮助」是 Agent 最珍贵的品质**——比「硬着头皮做完」可靠得多。

把「可靠性」拆成四个可操作的机制，就理解了「Agent 成熟度」的度量：

| 机制 | 问题 | 反例 |
| --- | --- | --- |
| 权限沙盒 | 危险操作被拦住吗 | Agent 直接调用实验设备 |
| 错误检查 | 发现自己错了吗 | 拿着错误数据继续推理 |
| 轨迹留痕 | 决策可回溯吗 | 黑箱跑完给结论 |
| 人的介入 | 关键点有人确认吗 | 全程无人、出错无人管 |

**辨析｜易错点：** 别用「成功率」单一指标衡量 Agent——「偶尔成功、经常悄悄出错」的 Agent 比「成功率低但会明确说不会」的 Agent 更危险。**「知道自己不会」比「假装会」可靠**——科学 Agent 的评估要同时看「成功率」与「错误时的诚实度」。

## 7 小结

- **科学 Agent** = LLM + 工具 + 多轮循环——从「答题机」升级为「执行者」。
- **三大核心能力**：规划（拆任务）、工具调用（做动作）、反思（自我修正）。
- **ReAct 循环**：$\tau_{t+1} = \tau_t \cup \{\text{Thought}, \text{Action}, \text{Observation}\}$——「边想边做」应对开放世界。
- **代表系统**：ChemCrow（化学工具）、Coscientist（机器人实验）、AI Scientist（全自动流程）——「LLM × 工具 × 循环」的乘积决定能力。
- **三大挑战**：可靠性（错误传播）、安全性（物理后果）、评估（流程级评价）。
- **诚实定位**：Agent 是「探索性工具」，不是「可靠研究员」——「能跑 Demo」≠「能可靠科研」。

在下一节，我们回答「怎么衡量科学 AI 到底行不行」：**AI 科研助手的评测基准——ScienceQA、DiscoveryBench 等**。

> **延伸辨析：Agent 评测的『任务保真度』**。Agent 的评测任务（如 DiscoveryBench）是「人工设计的模拟发现」——**「模拟任务与真实科研的差距，决定了评测的可迁移性」**——「在模拟任务上强的 Agent，面对真实科研的『开放性、混乱、长周期』未必强」。
>
> 「任务保真度」是 Agent 评测的核心矛盾：太简单（玩具任务）没信息量，太真实（真实科研）不可复现——「在『可控』与『保真』之间找平衡」，是 Agent 评测的持续难题。

> **延伸辨析：Agent 的『工具生态』与『标准化』**。科学 Agent 的能力上限 = 工具生态的丰富度——**「工具越多、API 越标准，Agent 能做的科学越多」**——「当前科学工具的『API 化程度』参差，是 Agent 落地的瓶颈」。「推动『科学工具的标准化接口』（数据库、模拟器、仪器），与改进 Agent 本身同等重要」——「Agent 与工具生态是『相互成就』的」。

> 一个判断：**「下一个五年，科学 Agent 的最大进展可能来自『工具生态的标准化』，而不是『LLM 本身』」**——「生态建设与模型能力，是 Agent 进步的两条腿」。
