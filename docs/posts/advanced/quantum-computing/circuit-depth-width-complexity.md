## 为什么从线路复杂度开始

前面的线路图里，门从左到右画成一条「时间线」。这条时间线不是一个摆设：**线路的形状直接决定了量子算法在真实硬件上的运行时间与所需资源。** 深度（depth）对应时间、宽度（width）对应比特数，而复杂度（complexity）则是衡量「一条线路到底多难」的抽象标尺。<span class="marginnote">经典复杂度理论以「时间」与「空间」衡量算法（见第二级《计算复杂性理论》）；量子线路模型把同样的权衡翻译成深度与宽度。先有线路指标，后有量子算法复杂度。</span>本节把这些量定义清楚，为后面分析 Shor、Grover 等算法的时间代价铺路。

这里还要区分一个容易被忽略的层次：**线路复杂度**衡量的是「实现一个已知酉变换要花多少门」，而**查询复杂度**衡量的是「要达到一个由黑盒定义的目标要问多少次黑盒」。两者回答的是不同的问题，本节的最后会说明它们如何互补。

## 1 线路宽度与深度

**线路宽度（width）**：线路中的量子线（比特）总数，即同时使用的最大量子比特数。它对应经典算法里的「空间复杂度」。<span class="marginnote">宽度不计入被丢弃或重用的线，只计并行存在的线。硬件上宽度 ≤ 芯片上的物理比特数——这是 NISQ 时代最硬的约束之一。</span>

**线路深度（depth）**：线路中「最长依赖链」的长度。定义方式是：一列（time slice）内互不作用的门可以并行执行，算同一时间步；深度就是最少的时间步数。<span class="marginnote">直觉：如果两个门作用在不相交的比特集合上，它们就能放在同一列同时执行；若共用比特（或有数据依赖），就必须先后执行。深度≈运行时间（假设每步耗时固定）。</span>

深度与宽度之间存在经典的**权衡（trade-off）**：用更多比特往往能换来更浅的深度，反之亦然——这与经典并行计算中「更多处理器换更短时间」完全同构。

**一个具体的数值算例**：考虑一个简单的两比特线路「先对每个比特做 $H$，再做一次 $CNOT$，再各做一次 $Z$」。把 $H_1, H_2$ 放在同一列（互不依赖，深度 +1），$CNOT$ 要等两者完成（深度 +1），最后的 $Z_1, Z_2$ 又可在同一列（深度 +1）——总深度 3，宽度 2，门数 5。若把所有门串行画成一条直线，深度就是 5、宽度仍 2。同一个算法，仅仅因为并行安排的不同，深度就从 3 变成 5——**这就是「编译」改变线路指标的直观例子**。<span class="marginnote">这里的「同一列」规则正是 Qiskit 编译器做调度优化的基础：它把互相独立的门塞进同一时间片，从而压缩深度。真实硬件的「深度限制」来自比特寿命——在退相干之前必须跑完。</span>

## 2 线路复杂度：量子电路的渐进分析

**线路复杂度**通常指线路中**门的总数**（size），记为 $C(C)$。对一条 $n$ 比特、深度 $d$ 的线路，若每层最多有 $w$ 个并行门，则大小满足

$$
C(C) \le d \cdot w \le d \cdot n
$$

因为每列至多 $n$ 个门（每个比特每列至多作用一次）。这条不等式把三个量串在一起：**门总数 = 深度 × 每层平均宽度**。<span class="marginnote">这解释了为什么算法论文同时报告「门数」与「深度」：门数决定总工作量，深度决定关键路径上的等待时间。NISQ 硬件两者都约束——比特寿命限制深度，比特数量限制宽度。</span>

复杂度的三种标准度量：**门复杂度（gate complexity）** 按基本门数量计；**线路复杂度（circuit complexity）** 按门加深度综合计；**T 计数（T-count）** 在容错场景只数昂贵的 T 门。<span class="marginnote">对于深层问题（如 Shor 的模幂线路），还有更细致的划分：$T$ 深度（T-depth）衡量 T 门在关键路径上的层数，因为 T 门并行性差，往往成为瓶颈。</span>

**辨析｜易错点：** 深度、宽度、门数都针对**编译后**的线路而言。同一算法的不同分解会给出不同指标：比如把单比特门全部用 $\{H,T\}$ 展开，T 深度会涨而门数也涨（见上一节 Solovay-Kitaev）。**比较两个算法时，必须约定同一门集与同一误差下**，否则数字没有可比性。另一个常见误区是把「深度小」等同于「运行快」——若每步门耗时相差两个数量级（如 T 门 vs Clifford 门），深度小的线路未必更省时间。

## 3 公式解析：量子傅里叶变换的深度与宽度

用一个具体例子看这些量如何计算。$n$ 比特的**量子傅里叶变换（QFT）**，其标准线路由 $\frac{n(n+1)}{2}$ 个受控旋转门与 $n$ 个 Hadamard 门组成（详见第五篇《量子傅里叶变换》）。我们来算它的复杂度：

$$
\text{门数} = \frac{n(n+1)}{2} + n = O(n^2), \qquad \text{深度} = O(n)
$$

- **第一步，数门数**：第 $k$ 个比特后面连 $n-k$ 个受控相位门，累加 $\sum_{k=1}^{n} (n-k) = \frac{n(n-1)}{2}$ 个受控门，加上 $n$ 个 $H$ 门，合计 $\frac{n(n+1)}{2} + n = O(n^2)$。
- **第二步，看深度**：虽然门数平方，但 QFT 线路结构是「每比特连续操作、不同比特可交错」，关键路径上每个比特至多经历 $O(n)$ 层，所以深度只有 $O(n)$。
- **第三步，权衡**：若加入可丢弃辅助比特与「半经典」技巧，深度还能进一步压低。这里的要点是：**门数与深度可以差距很大**——$O(n^2)$ 门数配 $O(n)$ 深度，说明大量门是并行执行的。<span class="marginnote">这个「$O(n^2)$ 门、$O(n)$ 深度」的组合是 QFT 效率的关键，也是 Shor 算法总复杂度里模幂那部分之外的主要开销。经典 FFT 的线路模型也有类似并行化，但量子版本多了一层「相位旋转」语义。</span>

**数值算例：$n=4$ 的 QFT 具体有多少门？** 用上式：受控门数 $\frac{4\cdot 3}{2}=6$，$H$ 门 4 个，合计 10 个门；深度约 $2n-1 = 7$ 层。若用「半经典 QFT」（测量与反馈交替），深度可降到约 $n$ 层，但每层多了经典条件相位——这是 Shor 算法实际实现里用的技巧。

## 4 复杂度分析与查询复杂度

线路复杂度是「时间×宽度」的物理化度量，但它有一个前置条件：假设我们已经知道**要实现的酉变换是什么**。在实际算法里，目标往往只由一个**黑盒（oracle）** 定义——比如 Grover 里的翻转 oracle。这时更自然的度量是**查询复杂度（query complexity）**：黑盒被调用的次数。<span class="marginnote">查询复杂度剥离了门实现的细节，纯粹衡量「需要问黑盒多少次」——它是量子算法分析中最常用的框架，将在第五篇《量子查询复杂度与黑盒模型》系统展开。</span>线路复杂度与查询复杂度是互补的：查询复杂度给出算法的**信息论下界**，线路复杂度给出**工程可实现性**的估计。

**辨析｜易错点：** 不要混淆「算法复杂度」与「线路复杂度」。算法复杂度指输入规模 $n$ 的渐近时间（含 oracle 调用、门数、测量），而线路复杂度专指给定 $n$ 时线路的门/深度/宽度。同一算法「Grover 是 $O(\sqrt{N})$ 查询」指的是查询复杂度；把它翻译成完整线路还要乘上 oracle 本身的代价。

**线路复杂度与经典复杂度的关系**：量子线路模型可以看作「经典线路模型 + 叠加态」的推广。任何经典可逆计算都能用量子门实现（见上一篇《通用量子门集》），所以量子线路复杂度蕴含经典线路复杂度；反过来，量子线路可以通过模拟经典门来「假装经典」。因此，**量子算法优于经典算法，靠的不是线路模型更强，而是同一线路里利用了叠加与纠缠**——这正是为什么「量子并行不是免费的」那条红线（见第零篇《指数加速不是免费的》）会在复杂度层面反复出现。

## 5 常用算法的线路指标对照

把几个代表算法的线路指标放在一起，能建立「复杂度直觉」：

| 算法 | 宽度 | 深度 | 门数（渐近） | 备注 |
| --- | --- | --- | --- | --- |
| QFT | $O(n)$ | $O(n)$ | $O(n^2)$ | 深度远小于门数，并行度高 |
| Grover 单次迭代 | $O(n)$ | $\mathrm{poly}(n)$ | $\mathrm{poly}(n)$ | 迭代 $\sqrt{N}$ 次 |
| Shor（总） | $O(n)$ | $\mathrm{poly}(n)$ | $O(n^3)$ 量级 | 模幂是主要成本 |
| 单比特任意门分解 | $O(1)$ | $O(\log^c(1/\epsilon))$ | $O(\log^c(1/\epsilon))$ | 由 Solovay-Kitaev 控制 |

这张表值得记住的核心信息：**量子算法论文里的「复杂度」通常指查询复杂度或门复杂度中的一种，阅读时要先弄清楚作者在数什么**——否则容易把「查询 $O(\sqrt{N})$」误当成「总运行时间 $O(\sqrt{N})$」。

## 6 从三个算法看线路指标的取舍

把抽象指标放回具体算法，能看清「不同算法的瓶颈其实不同」这件事：

**Grover 的瓶颈在「迭代次数 × 单次门数」**。单次 Grover 迭代的线路规模是 $\mathrm{poly}(n)$（门数与深度都是输入规模的温和多项式），但需要约 $\sqrt{N} = 2^{n/2}$ 次迭代，所以**总深度约 $\sqrt{N}\times\mathrm{poly}(n)$**——指数级，因此 Grover 不改变「需要指数时间」的事实，只把指数从 $2^n$ 压到 $2^{n/2}$。<span class="marginnote">对 NISQ 硬件，Grover 的致命点在这里：总深度远超比特寿命，所以目前实验只能跑「一次迭代以内」的搜索。线路指标分析提前告诉我们：Grover 需要「容错 + 长相干」，而不是「浅线路」。</span>

**Shor 的瓶颈在「模幂线路本身」**。模幂用「重复平方 + 受控乘法」实现，约 $O(n^2)$ 个受控乘法门、每个乘法门又由 $O(n)$ 个加法门组成，总门数约 $O(n^3)$。这里没有大幅并行化的余地，门数与深度都很大——这就是为什么 Shor 的实用化要等硬件先解决「门保真度」。

**变分算法（VQE/QAOA）的瓶颈在「深度受硬件限制」**。变分线路深度通常被刻意压到几十层以内（否则噪声淹没信号），此时线路指标分析告诉你的是：**每层能容纳多少个双比特门**直接决定参数化线路的表达力，而表达力又是「是否遇到贫瘠高原」（见第十篇）的关键。

## 7 术语速查表

| 术语 | 含义 |
| --- | --- |
| 宽度（width） | 线路中并行存在的量子线总数，对应空间 |
| 深度（depth） | 最长依赖链的时间步数，对应时间 |
| 门数 / size | 线路中基本门的总数，对应总工作量 |
| T 计数（T-count） | 线路中 T 门的个数，容错场景的昂贵资源 |
| T 深度（T-depth） | T 门在关键路径上的层数 |
| 查询复杂度 | 算法需要调用黑盒 oracle 的次数 |
| 时间片 / 列 | 互不依赖的门所在的时间层，可并行执行 |
| 半经典 QFT | 测量与经典反馈交替进行的 QFT 实现，降低深度 |
| 关键路径 | 决定总深度的最长依赖链，优化深度就是压缩它 |
| 编译调度 | 把独立门塞进同一时间片以压缩深度的优化步骤 |

## 8 小结

- **宽度** = 比特数（空间），**深度** = 关键路径时间步数（时间），**门数** = 总工作量，且 $\text{门数} \le \text{深度} \times \text{宽度}$。
- 三量之间存在**权衡**：加宽可降深，加长可降宽。
- QFT 实例：$O(n^2)$ 门、$O(n)$ 深度——门数可远大于深度，因为并行。
- 查询复杂度与线路复杂度互补，前者给信息论下界，后者给工程代价。
- 比较两个算法的线路指标时，必须约定同一门集与同一误差。
- 不同算法的瓶颈不同：Grover 受「迭代×单次门数」限制，Shor 受「模幂线路本身」限制，变分算法受「深度上限」限制。
- 线路复杂度蕴含经典复杂度；量子优势来自叠加与纠缠，而非「线路模型更强」。
- 编译调度可以显著改变同一算法的深度——「深度」永远是对具体编译产物而言。
- 术语上区分清楚：宽度（空间）、深度（时间）、门数（工作量）、查询复杂度（黑盒次数）。
- 实际阅读算法论文时，先确认作者在数「门数、深度还是查询次数」，再谈加速倍数。
