## 为什么从「值迭代」开始

上一节的策略迭代有个「奢侈」的习惯：每一轮改进之前，都要把当前策略的价值**评估到几乎收敛**。可在 $4\times 4$ 的棋盘上奢侈得起，在真实问题上就未必了。想想：如果为了每改一次策略都要跑几百轮价值扫描，而每轮扫描又要遍历几百万个状态，那学习就变成了体力活。

这一节我们问一个「拆台」式的问题：**评估真的需要做到底吗？** 答案是惊人的——**不需要。** 只要把评估压缩到一步，再和贪心改进合并成同一次更新，就能以「极限收敛」的方式抵达最优价值。这个算法叫**值迭代（value iteration）**，它比策略迭代简单、便宜，也是通往无模型方法（蒙特卡洛、TD）的一座关键桥梁：当你要面对的不是「完备模型 + 表格」，而是「只会采样的世界」时，值迭代「一步一更新」的形态才是可以推广的形态。

## 1 最优性递归：贝尔曼最优方程回顾

第三篇我们推导过最优价值函数满足**贝尔曼最优方程**：

$$v_*(s) = \max_{a} \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v_*(s') \right], \qquad \forall s \in \mathcal{S}$$

复习它和普通贝尔曼方程的区别，这里藏着值迭代的全部秘密：

- **普通贝尔曼方程**（针对固定策略 $\pi$）：等式右端是「按 $\pi$ 加权平均」，是**线性**的。
- **贝尔曼最优方程**（针对最优策略 $\pi_*$）：等式右端是「对所有动作取最大值」，是**非线性**的。

**重点：最优方程里的 $\max$ 就是「策略改进」的化身。** 它没有显式写出策略——因为最优策略在每个状态就是「挑 $\max$ 对应的那个动作」；策略被折叠进了最大值运算。这解释了为什么值迭代只需要一张价值表：策略是价值的「副产品」，随时可以用 $\arg\max$ 取出来。

就像普通贝尔曼方程定义了算子 $T_\pi$ 一样，最优方程定义一个**贝尔曼最优算子** $T_*$：

$$(T_* v)(s) \doteq \max_a \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v(s') \right]$$

$v_*$ 就是 $T_*$ 的不动点：$v_* = T_* v_*$。<span class="marginnote">「把策略折叠进 max」这件事，是表格型 DP 与深度 RL 之间一个意味深长的分水岭：基于价值的深度方法（DQN，第十四篇）依旧在逼近这个 $T_*$ 的不动点；而基于策略的方法（第十三篇）则显式维护策略、把 max 换成「沿梯度的软选择」。两条路线在最优方程这个根上分岔。</span>

## 2 值迭代：把不动点方程当更新规则

值迭代的定义极简：**反复套用最优算子，直到不动点**。

$$v_{k+1}(s) = \max_{a} \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v_k(s') \right], \qquad \forall s \in \mathcal{S}$$

和迭代式策略评估长得几乎一样——唯一差别是「$\sum_a \pi(a\mid s)$ 加权平均」换成了「$\max_a$」。但这一个字的差别，蕴含了两层深意。

**第一层，值迭代是「一步评估 + 贪心改进」的合并。** 每次更新同时做了两件事：先按当前价值 $v_k$ 找到最佳动作（改进），再用这个动作的动作价值刷新状态价值（评估一步）。也就是说，值迭代 = 策略迭代中「完整评估」被截断成「一步」、再与改进合并为同一次扫描。策略迭代在「评估充分」的极端，值迭代在「评估一步」的极端。

**第二层，值迭代不需要显式策略。** 算法从头到尾只维护一张价值表 $v_k$；策略只在最后需要时提取。它跳过了「评估—改进—评估—改进」的双层循环，直接对价值表做单层迭代。<span class="marginnote">代价是什么？值迭代<strong>不保证</strong>中间策略单调改善——某一步贪心出的策略可能比上一步差，只有价值本身在向 $v_*$ 收敛。所以「看中间的价值表」没有意义，只有「等 $v_k$ 稳定下来再取贪心」才得到最优策略。这是初学最容易误读的点。</span>

## 3 公式解析：为什么 $\max$ 算子也能收敛

普通贝尔曼算子 $T_\pi$ 的压缩性我们上一节证过：$\lVert T_\pi u - T_\pi v \rVert_\infty \le \gamma \lVert u - v \rVert_\infty$。但 $T_*$ 里多了个 $\max$，还能压缩吗？能，而且证明只比之前多一步。

- **第一步，一个关于 $\max$ 的小不等式**。对任意两个函数族 $\{f_a\}$、$\{g_a\}$（这里 $a$ 遍历动作），有

$$\left|\max_a f_a - \max_a g_a\right| \le \max_a \left|f_a - g_a\right|$$

直觉：取最大值只是「挑选」，挑选不会放大两个集合之间的最大差距——两边各自挑走最大的那个，彼此差的绝对值不可能超过「逐一对应差」的最大值。这是分析里常用的「$\max$ 是 1-Lipschitz」性质。

- **第二步，套用这个不等式**。逐状态写开：

$$\left|(T_* u)(s) - (T_* v)(s)\right| = \left|\max_a \sum_{s',r} p(s',r\mid s,a)\left[r + \gamma u(s')\right] - \max_a \sum_{s',r} p(s',r\mid s,a)\left[r + \gamma v(s')\right]\right|$$

由第一步，它 $\le \max_a \left|\sum_{s',r} p(s',r\mid s,a)\; \gamma \left(u(s') - v(s')\right)\right|$。剩下的就完全是上一节的套路：概率非负和为一、三角不等式把绝对值挪进求和，得

$$\le \max_a \gamma \sum_{s',r} p(s',r\mid s,a)\; \lVert u - v \rVert_\infty = \gamma \lVert u - v \rVert_\infty$$

- **第三步，两边取最大**，得到与 $T_\pi$ 完全同构的压缩不等式：

$$\lVert T_* u - T_* v \rVert_\infty \le \gamma \lVert u - v \rVert_\infty$$

于是同样的不动点定理收尾：$T_*$ 是压缩映射，$v_{k+1} = T_* v_k$ 从任意 $v_0$ 出发收敛到唯一不动点 $v_*$，速度至少几何级数。**值迭代收敛，且收敛到的正是最优价值。**

**辨析｜易错点：别把「值迭代中间的价值」当策略价值。** 值迭代第 $k$ 轮的 $v_k$ **不是**任何单一策略的价值函数——它是「每步都贪心地重新选动作」得到的混合价值，介于不同策略之间。因此：调试时不要盯着中间 $v_k$ 看「这个策略好不好」，而要看「$v_k$ 和 $v_{k+1}$ 的差距够不够小」。收敛判据是价值的稳定，不是策略的稳定。

## 4 实现：值迭代的一页代码

值迭代的代码比策略迭代更短——因为它没有内层评估循环：

```python
import numpy as np

def value_iteration(terminal, gamma=1.0, theta=1e-4):
    actions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    n = 4
    V = np.zeros((n, n))

    while True:
        delta = 0.0
        for r in range(n):
            for c in range(n):
                if (r, c) in terminal:
                    continue
                v_old = V[r, c]
                best_val = -float("inf")
                for dr, dc in actions:                 # 对动作取 max
                    r2, c2 = min(max(r + dr, 0), n - 1), min(max(c + dc, 0), n - 1)
                    best_val = max(best_val, -1 + gamma * V[r2, c2])
                V[r, c] = best_val
                delta = max(delta, abs(V[r, c] - v_old))
        if delta < theta:
            break

    # 迭代结束后，从收敛的价值表提取贪心策略
    policy = np.zeros((n, n), dtype=int)
    for r in range(n):
        for c in range(n):
            if (r, c) in terminal:
                continue
            vals = [-1 + gamma * V[min(max(r + dr, 0), n - 1),
                                   min(max(c + dc, 0), n - 1)]
                    for dr, dc in actions]
            policy[r, c] = int(np.argmax(vals))
    return policy, V
```

对照上一节的策略迭代，值迭代**少了一层 while 循环**——这就是「评估只做一步」的全部含义。跑在 $4\times4$ 网格世界上，它收敛出的价值与策略迭代完全一致：最优策略会指向一条最短路径到终止。<span class="marginnote">实践提示：网格世界里 $\gamma=1$、每步 $-1$，值迭代每次更新都在「离终止更近一步」的方向上传递信息；所以从 $v_0 = 0$ 出发，第 $k$ 轮扫描后，距离终止不超过 $k$ 步的状态已经被正确赋值。信息的传播速度 = 一次扫描的半径，这是直觉上理解「为什么轮次越多越精确」的好抓手。</span>

## 5 辨析：策略迭代 vs 值迭代，一张表看懂

两个算法都解决同一个问题（求 $v_*$ 与 $\pi_*$），风格却针锋相对：

| 维度 | 策略迭代 | 值迭代 |
| --- | --- | --- |
| 结构 | 双层循环：评估（到底）→ 改进（贪心） | 单层循环：$v_{k+1} = T_* v_k$ |
| 每次改进前评估 | 完整评估到收敛 | 只评估一步 |
| 收敛方式 | **有限步**严格改善到最优 | **极限**收敛到 $v_*$ |
| 中间产物 | 每个 $v_\pi$ 都是真实策略的价值 | 中间 $v_k$ 不属任何单一策略 |
| 每轮成本 | 高（完整评估扫描） | 低（单次扫描） |
| 适用直觉 | 状态少、想得到显式策略序列 | 状态多、追求便宜的单轮更新 |

**两者其实是广义策略迭代（GPI）的两个极端。** 值迭代把「改进」压缩到每轮一次，策略迭代把「评估」拉满到每轮一次；两者之间还有无穷多种「评估做几步就改」的中间态。把这个连续谱讲清楚，正是下一节《异步动态规划与广义策略迭代》的任务。<span class="marginnote">在深度强化学习里，策略迭代的「完整评估」被 Q-learning/DQN 用「经验回放 + 多次采样」近似，值迭代的「单步更新」则对应 TD 风格的一步自举（第六篇）。可以说：今天理解清楚的这两个极端，就是明天 DQN 与 TD 家族的谱系图。</span>

## 6 小结

- **贝尔曼最优方程**：$v_*(s) = \max_a \sum_{s',r} p(s',r\mid s,a)\left[r + \gamma v_*(s')\right]$，最优策略被折叠进 $\max$，方程是**非线性**的。
- **值迭代**：$v_{k+1} = T_* v_k$，即「一步评估 + 贪心改进」合并成的单层更新；从任意 $v_0$ 收敛到 $v_*$。
- **收敛证明**：$\max$ 是 1-Lipschitz（$\left|\max f - \max g\right| \le \max|f-g|$），于是 $T_*$ 仍是压缩算子，不动点定理照常成立。
- **与策略迭代的对照**：策略迭代有限步终止、中间都是真实策略价值；值迭代极限收敛、中间价值不属任何策略。两者是 GPI 连续谱的两个端点。
- **易错点**：值迭代的收敛判据看价值稳定，不看策略稳定；中间 $v_k$ 不能当策略价值解读。
- **地位**：值迭代的「单步更新」形态，是无模型方法（TD、Q-learning）在表格型领域的直系祖先。

在下一节，我们把视线从「算法长什么样」抬到「这些算法共享什么骨架」：**评估与改进之间到底该如何配速？更新顺序能不能乱来？**——异步动态规划与广义策略迭代，将给我们一个统一所有表格型算法的全景视角。
