## 为什么「模型对了」还不够

Dyna 的模型由真实经验覆写更新，乍看天衣无缝。但教材用两个迷宫实验泼了冷水：**模型本身能学会新情况，不代表规划会及时利用它**。Dyna 的规划在「曾见过的状态」里**均匀随机**采样，这有个致命弱点——**它不会特意去更新价值正在剧变的状态**。当捷径出现，新价值要从墙洞沿着路径往外扩散，均匀采样却把珍贵的规划步浪费在早已收敛的角落里。**优先扫描（prioritized sweeping）** 正是为此而生：它维护一个按「价值变化量」排序的优先队列，把规划火力精确投放到「最需要被重新估计」的状态及其前驱上。<span class="marginnote">优先扫描的名字来自操作系统的「优先级调度」：不是先来先服务，而是按紧急程度插队。这里「紧急程度」= 一个状态的价值刚发生了多大变化——变化越大，它的前驱越需要被重估。</span>

规划效率不只是「快一点」的工程优化：在机器人控制、推荐系统与语言模型对齐这类真实场景里，每一次环境交互都要付出高昂的物理或经济代价。让模型经验的每一次「回想」都精准落位，是把「少样本学习」变成现实的杠杆——**一条捷径被发现后，理想的规划应该用最小步数把它内化**，这正是优先扫描比均匀撒网更接近真实学习者的地方。

## 1 阻塞迷宫与短路迷宫：模型错误的两种剧本

教材用一对孪生实验把「模型错了」拆成两种情形。

**阻塞迷宫（Blocking Maze）**：原本绕远路的通道被堵死，需要改道。这里 Dyna 的覆写式模型**能**适应：新经验一旦撞见堵墙，模型表立刻覆写为「此路不通」，规划的模拟经验也随之修正——Dyna-Q 最终找到了新路，只是稍慢。

**短路迷宫（Shortcut Maze）**：原本的远路旁**新开了一条捷径**。此处 Dyna-Q 的短板暴露了：模型表确实记住了捷径（覆写式更新），但**规划仍在均匀随机采样曾见状态**，而捷径的价值扩散需要规划步恰好抽到捷径入口附近的状态——均匀随机采样很少抽到那里，于是价值沿捷径扩散得极慢。<span class="marginnote">直觉对比：Dyna 的规划像「每块地都均匀浇一遍水」，而捷径的价值只在一小片土壤里疯长；水浇到别处全浪费了。真正的解法是「哪块地刚裂开新渠，就优先给它浇水」。</span>结论：**模型及时更新是必要不充分条件，规划还必须知道「该往哪里使力」**。

把两种剧本并排看，问题定位更清楚：

| 对比维度 | 阻塞迷宫（Blocking） | 短路迷宫（Shortcut） |
| --- | --- | --- |
| 模型能否自修正 | 能，覆写式立即改 | 能，覆写式立即改 |
| 价值扩散的瓶颈 | 模型更新本身 | 均匀随机的规划步 |
| Dyna-Q 最终结果 | 找到新路，但偏慢 | 也能找到，但慢得多 |
| 优先扫描的增益 | 中等 | 巨大（数十倍加速） |

**关键结论是：模型表在两种情形里都「学会了」，差的是规划把修正传导出去的速度**——短路迷宫把这一短板逼到了显微镜下。

## 2 优先扫描：把规划步变成「紧急优先」

优先扫描做三件事，让规划资源跟着「价值剧变」走：

1. **维护优先队列**：每个状态（或 $(s,a)$）有一个优先级，初值设为「发现状态价值明显变化时触发」。
2. **反向传播变化**：当 $Q(s,a)$ 更新后变化量 $\Delta$ 超过阈值，就查**反向模型（reverse model）**——哪些 $(s',a')$ 会转移到 $(s,a)$——把这些前驱按与 $\Delta$ 成正比（或相关）的优先级推入队列。<span class="marginnote">反向模型是优先扫描的额外记忆：它对每个 $(s,a)$ 记录「哪些前驱转移会到达这里」。正向模型回答「我走了会发生什么」，反向模型回答「谁把我带到了这里」——价值变化的涟漪正是沿着反向边向上游扩散。</span>
3. **按优先级处理**：每次取队首最高优先级的 $(s,a)$，做一次**期望更新**（用分布模型对前驱做完整求和），再把它的前驱按新变化推入队列。

关键改进：**更新用期望更新而非采样更新**。因为被选中的状态往往「值得精确对待」，分布模型可用时，期望更新的单次收益远高于采样更新。

### 对照表：均匀随机规划与优先扫描

| 对比维度 | 均匀随机规划（Dyna-Q） | 优先扫描 |
| --- | --- | --- |
| 采样分布 | 曾见状态上均匀随机 | 按价值变化量加权 |
| 更新类型 | 采样更新 | 期望更新（表格型） |
| 需要的模型 | 正向模型 | 正向 + 反向模型 |
| 触发信号 | 无（盲目撒网） | 变化量超过阈值 |
| 计算开销 | 低 | 略高（队列 + 反向表） |
| 最适用场景 | 状态空间大、变化均匀 | 稀疏剧变（捷径/堵塞） |

**一行总结：优先扫描不是换了一种更新公式，而是换了一种「把规划步分配到哪个状态」的调度策略**——算法骨架与 Dyna 完全相同，只多了一张优先队列和一张反向模型表。

### 数值算例：一次捷径发现引发的涟漪

用一条 3 状态走廊 $S \to A \to B$ 来跟踪优先队列。设终点 $B$ 处奖励 $+1$、$\gamma = 0.9$、所有 $Q$ 初值为 $0$、阈值 $\theta$ 取很小的正数：

1. **发现捷径**：真实经验撞见 $A \to B$（$R=+1$）。Q-learning 更新得 $\Delta = |1 + 0.9 \times 0 - 0| = 1$，超过阈值，$(A,\to B)$ 以优先级 $1$ 入队。
2. **取队首重估**：取出 $(A,\to B)$，其值已被更新到接近 $1$，不再产生新的显著变化；反向模型查得「谁转移到了 $A$」——起点 $S$ 经 $S \to A$ 到达。
3. **涟漪上游**：$(S,\to A)$ 以约 $\Delta' = 0.9 \times 1 = 0.9$ 的优先级入队。取出后 $Q(S,\to A) = 0.9 \times 1 = 0.9$，变化依旧显著，继续向更上游传播，直到走廊起点。

三步之内，价值就沿着「发现的先后顺序」而非「均匀随机」铺满了整条路径——这正是短路迷宫里规划步数百倍差距的来源。均匀随机的 Dyna 往往要恰好抽到 $S \to A$ 本身，才会意识到该重估它。

### 阈值与队列实现的两个细节

**阈值 $\theta$**：决定「多小的变化才算值得传播」。$\theta$ 设太大，小变化被忽略，价值更新可能停滞在一个粗糙的近似；$\theta$ 设太小，队列被高频小扰动塞满，规划火力被稀释。实践中常取一个很小的正数，并用「与阈值比较」决定是否入队。

**队列里的重复项**：同一个 $(s,a)$ 可能被多次推入。实现上通常保留其优先级的最大值（或更新已存在项的优先级），保证每个状态动作对在队列中至多出现一次，避免同一目标被反复重估。教材把优先级设为「新变化量」而非累积值，队列因此天然按「最新、最大的波动」排序。

## 3 公式解析：变化量如何变成优先级

$$
\Delta(s,a) \;=\; \Big|\, R(s,a) + \gamma \sum_{s'} p(s' \mid s,a) \max_{a'} Q(s', a') - Q(s,a) \,\Big| \;\longrightarrow\; \text{push } (s,a) \text{ with priority } \Delta
$$

- **第一步，认变化量**：$\Delta$ 是 Q-learning 式目标的绝对差——「这个 $(s,a)$ 的价值离它应有的值还差多少」。它既是**更新量**，也是**优先级**。
- **第二步，认传播方向**：每次 $Q(s,a)$ 被更新后，计算 $\Delta$；若 $\Delta > \theta$（阈值），就**沿着反向模型**找前驱 $(s',a')$，把它们的优先级设为（比如）$\Delta$ 的某个函数——**价值变化沿反向边向上游涟漪般扩散**。
- **第三步，认重估**：从队列取出 $(s',a')$ 后，用期望更新重估它。重估又会产生新的 $\Delta'$，继续把变化传向更上游。**一轮「发现捷径」就被放大成一次沿着整条路径的快速重估浪潮**——这正是短路迷宫需要的。<span class="marginnote">细节：优先级队列里每个状态通常只保留一个最新优先级（若已在队列中，取最大值）；阈值的设定决定「多小的变化算事」。教材的实验中，优先扫描在短路迷宫的收敛速度比均匀随机规划的 Dyna 快数十倍。</span>

这里还有个容易被忽略的隐含差别：Dyna 的规划预算 $n$ 是**每步固定投入**，优先扫描则把「队列清空」当作一轮收敛的结束——**规划预算从「每步固定 $n$ 次」换成了「跟随变化量自动伸缩」**。在变化稀疏的长尾环境里，这一差别让优先扫描既省下无谓的规划步，又不会错过任何一处剧变。把「按误差大小调度计算」再往前推一步，就得到深度 RL 里优先经验回放（PER）的思想雏形——表格型里排的是状态，深度版里排的是经验元组。

## 4 易错点辨析

**辨析｜易错点：** 以为优先扫描「解决了模型出错」。它解决的是**规划效率**：让模型修正尽快传导到价值。若模型表本身错得离谱（例如环境随机性下的频率估计偏颇），优先扫描依然会基于错的模型快速规划——**它优化的是「在给定（可能错的）模型下把价值算对」的速度，不是「模型正确性」**。

**另一个易错点**：混淆「优先级」与「访问频率」。优先扫描是**按价值变化量**排队，不是按状态被访问多频繁。均匀随机的 Dyna 恰好排除了这个信息；优先扫描刻意利用「变化量」作为规划价值的信号——越活跃的状态越该被规划。

**第三个易错点**：以为期望更新需要完整的 $p(s'|s,a)$。优先扫描用**采样模型的分布版本**——在表格型里，模型表存的就是经验转移频率，对每个 $(s,a)$ 对下一状态求和是可行的；但在大规模/函数逼近里，期望更新不可行，优先扫描也退化成「按变化量优先的采样更新」。**优先的是位置，不是更新类型**。

**第四个易错点**：以为变化量 $\Delta$ 的大小可以直接横向比较。不同奖励尺度的环境里，$\Delta$ 的绝对值相差巨大——若直接把原始 $\Delta$ 当优先级，大奖励环境会把所有状态都塞进队列，优先扫描退化为均匀扫描。实践中需要对优先级做归一化或按比例缩放，让「相对剧烈的变化」而非「绝对数值」决定调度。

## 5 小结

- **阻塞迷宫**：Dyna 靠覆写式模型能适应，但慢。
- **短路迷宫**：模型学得快，**规划却因均匀随机采样而跟不上**——「模型对」不等于「规划用得上」。
- **优先扫描**：按价值变化量 $\Delta$ 维护优先队列，沿**反向模型**把重估浪潮向上游传播。
- 关键三步：**队列维护、反向传播、期望更新**——把规划火力精确投放到最需要的地方。
- 它优化的是「给定模型下的规划效率」，不是模型正确性本身。
- 优先队列以「变化量」为信号，与访问频率无关——越活跃的状态越该被规划。
- 反向模型是优先扫描的额外记忆：记录「谁到达了我」，代价是双倍的存储。
- 表格型可用分布模型做期望更新；函数逼近下退化为「按变化量优先的采样更新」。
- 规划预算从「每步固定 $n$ 次」变为「随变化量自动伸缩」，变化稀疏时更省算力。
- 深层关联：这一「按误差大小调度计算」的思想正是深度 RL 里优先经验回放（PER）的表格型祖先，详见第十四篇《优先经验回放与 Rainbow》。
- 与 Dyna 一脉相承：换的是调度策略与模型记忆，价值备份的骨架不变。
- 两种故障要分得清：阻塞迷宫是「模型更新快、规划跟得上」，短路迷宫是「模型更新快、规划跟不上」——修法也完全不同。
- 一句话记住优先级：**变化越大、越靠前的状态，越先被重估**——规划火力跟着误差走。
- 若只记一个动作：**发现变化（入队）→ 反向传播（扩散）→ 期望更新（精修）**，三拍构成一轮优先扫描。

在下一节，我们回答规划里的最后两个「怎么抽样」问题：**轨迹采样**与**实时动态规划**——前者从真实分布出发沿轨迹规划、避开全状态扫描，后者只关心当前状态附近「此刻最重要」的子问题。
