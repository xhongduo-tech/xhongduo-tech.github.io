## 为什么从「策略改进」开始

上一节我们把「给策略打分」这件事做完了：迭代式策略评估，从任意起点出发，反复套用贝尔曼方程的右端，就能把 $v_\pi$ 算出来。可拿到这张地图之后，一个更野心勃勃的问题立刻冒出来：**地图告诉我当前策略有多好，但我要的不是「知道它多好」，而是「让它更好」。**

这一节干三件事。第一，证明一个反直觉但深刻的定理：**如果你在某个状态换一个动作、别处照旧，而换动作后的期望回报不低于原策略，那么整条策略的价值只会涨、不会跌**——这就是**策略改进定理（policy improvement theorem）**。第二，顺着定理把「贪心」变成一条严谨的改进机制：在每个状态选「当下看起来最好的动作」。第三，把「评估」与「改进」交替起来，拼出本章第一个完整的求解算法——**策略迭代（policy iteration）**。它会成为后面几乎所有强化学习算法的骨架：评估、改进、再评估、再改进，直到收敛。

## 1 直觉：如何在给定策略上「局部动手」

假设我们手里有一个确定性策略 $\pi$（每个状态只选一个动作），并且已经通过策略评估算出了它的价值 $v_\pi$。现在问：**在状态 $s$ 上，值不值得冒险换一个动作 $a \neq \pi(s)$，其余状态继续照旧？**

判据是现成的——上一节我们定义了动作价值

$$q_\pi(s, a) = \mathbb{E}_\pi\left[G_t \mid S_t = s, A_t = a\right]$$

它回答的正是「在 $s$ 上先做 $a$、之后一切照旧，平均能拿多少」。于是自然的分寸是：

- 若 $q_\pi(s, a) > v_\pi(s)$：在 $s$ 上做 $a$ 比按 $\pi$ 行动更划算，值得换。
- 若 $q_\pi(s, a) < v_\pi(s)$：别换，原动作更好。

**重点：改进的判据是「动作价值」而非「状态价值」。** $v_\pi(s)$ 隐藏了「策略替我选了动作」这一层，用它没法在动作之间比较；要比，必须把动作钉死、看 $q_\pi(s, a)$。这是上一节留下的辨析，现在派上了用场。

把所有状态上「值得换」的动作一起换上，就得到**贪心策略（greedy policy）**：

$$\pi'(s) = \mathop{\arg\max}_{a} q_\pi(s, a), \qquad \forall s \in \mathcal{S}$$

「贪心」的意思是：**只看眼前这一步动作价值最高的动作，不看长远博弈**。直觉上，在每个状态都挑局部最好的动作，整条策略应该「至少不更差」——但直觉要成定理，还得过数学这一关。<span class="marginnote">注意贪心策略在每个状态<strong>只挑一个动作</strong>（有并列则任选其一），所以它仍是确定性策略。后面我们会看到：对任意 MDP 总存在一个确定性的最优策略，所以把搜索范围限定在确定性策略上并不损失最优性。</span>

## 2 公式解析：策略改进定理

**策略改进定理**：设 $\pi$ 与 $\pi'$ 都是确定性策略，且对所有状态都满足 $q_\pi(s, \pi'(s)) \ge v_\pi(s)$，则 $\pi'$ 的价值处处不劣于 $\pi$：

$$v_{\pi'}(s) \ge v_\pi(s), \qquad \forall s \in \mathcal{S}$$

这条定理的证明只有四步，但每一步都踩在「价值 = 期望回报」这个定义上。我们逐条拆。

- **第一步，写下一个局部不等式**。对任意状态 $s$，由条件得

$$v_\pi(s) \le q_\pi(s, \pi'(s)) = \mathbb{E}_\pi\left[R_{t+1} + \gamma\, v_\pi(S_{t+1}) \mid S_t = s, A_t = \pi'(s)\right]$$

右边那句大白话是：在 $s$ 上执行 $\pi'$ 的动作，得到的期望「一步奖励 + 贴现的下一状态价值」。它之所以 $\ge v_\pi(s)$，正是定理假设本身。

- **第二步，把下一步也替换掉**。右边式子里挂着 $v_\pi(S_{t+1})$——这是「下一步仍按 $\pi$ 行动」的价值。但我们要论证的是「处处按 $\pi'$ 行动」更好，于是对 $S_{t+1}$ 再一次套用第一步的不等式：$v_\pi(S_{t+1}) \le q_\pi(S_{t+1}, \pi'(S_{t+1}))$。代入后，期望里露出 $R_{t+2}$：

$$\le \mathbb{E}_\pi\left[R_{t+1} + \gamma R_{t+2} + \gamma^2 v_\pi(S_{t+2}) \mid S_t = s, A_t = \pi'(s), A_{t+1} = \pi'(S_{t+1})\right]$$

- **第三步，反复展开**。对 $S_{t+2}, S_{t+3}, \ldots$ 不断重复第二步，价值项被一路「拆」成奖励项，直到无穷：

$$v_\pi(s) \le \mathbb{E}_{\pi'}\left[R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \mid S_t = s\right] = v_{\pi'}(s)$$

- **第四步，读结果**。右边正是「从 $s$ 出发、处处按 $\pi'$ 行动的期望折扣回报」，也就是 $v_{\pi'}(s)$。于是 $v_{\pi'}(s) \ge v_\pi(s)$，定理得证。

**这套「代入—展开—收敛」的证明手法，是全书最值得背的样板之一。** 它不依赖任何具体的状态转移，只依赖期望的线性与回报的递归定义；后面几乎所有「某种改法至少不更差」的定理（比如策略梯度定理的变体）都在反复使用这个套路。<span class="marginnote">定理还有个「严格版」：若至少在一个状态上 $q_\pi(s, \pi'(s)) > v_\pi(s)$ 严格成立，则至少在这个状态上 $v_{\pi'}(s) > v_\pi(s)$ 也严格成立——这保证「改进」不是原地踏步，只要动过手就真的在变好。</span>

## 3 策略迭代：评估与改进交替前进

策略改进定理给了我们一台永动机：评估出 $v_\pi$ → 贪心得到更优的 $\pi'$ → 评估出 $v_{\pi'}$ → 贪心得到更优的 $\pi''$ → …… 把这两步交替起来，就是**策略迭代（policy iteration）**。

$$ \pi_0 \xrightarrow{\text{评估}} v_{\pi_0} \xrightarrow{\text{改进}} \pi_1 \xrightarrow{\text{评估}} v_{\pi_1} \xrightarrow{\text{改进}} \pi_2 \xrightarrow{\text{评估}} \cdots \xrightarrow{} \pi_* \xrightarrow{\text{评估}} v_* $$

**重点：策略迭代是一个「评估」与「改进」交替的双层循环。** 内层（评估）把当前策略的价值算到位，外层（改进）让策略贪心地跳到更高一阶。什么时侯停？当改进不再带来变化——即贪心策略 $\pi'$ 与当前策略 $\pi$ 完全一致时，说明当前策略已经「贪无可贪」。

而「贪无可贪」恰恰是**最优**的判据：如果 $\pi'(s) = \pi(s)$ 对所有 $s$ 成立，那么 $v_\pi(s) = q_\pi(s, \pi(s)) = \max_a q_\pi(s, a)$，这正是上一节第三篇里的**贝尔曼最优方程**的形态，它保证 $\pi$ 是最优策略。于是有

**策略迭代终止定理：** 对有限 MDP，策略迭代**在有限步内**终止于最优策略 $\pi_*$ 与最优价值 $v_*$，且它产生的一系列策略严格单调改善。<span class="marginnote">「有限步终止」是策略迭代区别于值迭代的招牌性质：每轮改进都严格变好（或已最优），而有限 MDP 上确定性的策略总数有限，所以它不会像值迭代那样「无限逼近」，而是「走有限步到达」。读者可以回忆第二级《离散数学》里的收敛与终止之别——前者是极限概念，后者是过程概念。</span>

## 4 实现：策略迭代的一页代码

策略迭代的代码，等于「上一节的评估函数 + 一个贪心外壳」：

```python
import numpy as np

def policy_iteration(terminal, gamma=1.0, theta=1e-4):
    actions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    n = 4
    policy = np.random.randint(0, 4, size=(n, n))     # 初始随机确定性策略
    V = np.zeros((n, n))

    while True:
        # ---- 策略评估：在给定 policy 下迭代算 v_π ----
        while True:
            delta = 0.0
            for r in range(n):
                for c in range(n):
                    if (r, c) in terminal:
                        continue
                    v_old = V[r, c]
                    a = policy[r, c]
                    dr, dc = actions[a]
                    r2, c2 = min(max(r + dr, 0), n - 1), min(max(c + dc, 0), n - 1)
                    V[r, c] = -1 + gamma * V[r2, c2]
                    delta = max(delta, abs(V[r, c] - v_old))
            if delta < theta:
                break

        # ---- 策略改进：贪心更新 ----
        policy_stable = True
        for r in range(n):
            for c in range(n):
                if (r, c) in terminal:
                    continue
                best = policy[r, c]
                best_val = -float("inf")
                for a, (dr, dc) in enumerate(actions):
                    r2, c2 = min(max(r + dr, 0), n - 1), min(max(c + dc, 0), n - 1)
                    val = -1 + gamma * V[r2, c2]      # 用 q 的当前估计比较
                    if val > best_val:
                        best_val, best = val, a
                if best != policy[r, c]:
                    policy_stable = False
                policy[r, c] = best

        if policy_stable:                             # 贪无可贪即最优
            break

    return policy, V
```

注意改进这一步用的是 `-1 + gamma * V[r2, c2]`——它是 $q_\pi(s,a) = \sum_{s',r} p(s',r\mid s,a)[r+\gamma v_\pi(s')]$ 在网格世界里的特例（转移确定、奖励恒为 $-1$）。**改进一定发生在评估完全收敛之后**：这里的 $V$ 已经是 $v_\pi$ 的近似，用它算出的贪心动作才站得住。<span class="marginnote">这里为了演示清晰，内层评估每次都收敛到阈值 $\theta$ 以下才停。下一节的值迭代将揭示一个惊人的事实：评估根本不必算到底——只评估一步，也能抵达最优。那才是大规模 RL 里真正被采用的松弛方式。</span>

## 5 辨析：改进的成本与「贪心」的边界

策略迭代漂亮，但有个明显的开销问题：**每一轮改进之前，都要把价值评估到几乎收敛**。在网格世界这种小棋盘上这无伤大雅；可当状态数以百万计，每轮完整评估都是沉重的扫描。于是自然产生两个疑问，正好是两个常见误区：

- **「能不能不把评估做完？」**——能。下一节的值迭代就是「评估只做一步就改进」的极端；评估做几步再改进，则落在两者之间。这个「评估与改进的松紧配比」问题，是第四篇最后一节《广义策略迭代》的主题，也是从表格型算法通往函数逼近、深度强化学习的桥梁。
- **「贪心会不会掉进局部最优？」**——在表格型、有完备模型、评估精确的设定下，**不会**：策略改进定理保证每一步都单调改善，策略迭代收敛到全局最优。所谓「贪心有害」的担忧，属于模型不完备、函数近似有误差的深度 RL 语境（第九篇会正面讨论），不该把两个语境混为一谈。

**辨析｜易错点：改进用的是 $q_\pi$ 的 argmax，不是 $v_\pi$ 的 argmax。** 一个典型错误是「在 $s$ 上找一个让 $v_\pi$ 最大的后继状态」。$v_\pi$ 是关于**状态**的函数，你不知道该用哪个动作到达那个状态；而 $q_\pi(s,a)$ 把动作钉死、直接可比。动手写代码前，先问自己一句：我在 argmax 的是动作，还是状态？

## 6 小结

- **策略改进定理**：若 $q_\pi(s, \pi'(s)) \ge v_\pi(s)$ 对所有 $s$ 成立，则 $v_{\pi'} \ge v_\pi$ 处处成立；证明靠「代入—展开—收敛」三步，是全书证明套路的样板。
- **贪心策略**：$\pi'(s) = \arg\max_a q_\pi(s, a)$，由改进定理保证不劣于 $\pi$；若严格成立则严格更优。
- **策略迭代**：评估（算 $v_\pi$）与改进（贪心）交替进行；对有限 MDP 在有限步内单调收敛到最优策略。
- **终止判据**：改进后策略不再变化 ⇔ 当前策略满足贝尔曼最优方程 ⇔ 最优。
- **成本**：每轮改进前需要近乎完整的评估，这是它的主要开销，也是引出值迭代与广义策略迭代的动机。
- **易错点**：改进比的是 $q_\pi(s, \cdot)$ 而非 $v_\pi$；表格型设定下贪心不会掉进局部最优。

在下一节，我们把「评估必须做到底」这条自我设限拆掉：**如果评估只做一步就急着改进，会怎样？** 答案是一个更简洁、也更容易扩展到大规模问题的算法——值迭代。
