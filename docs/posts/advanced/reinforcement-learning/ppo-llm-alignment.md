## 为什么 RLHF 的「RL 阶段」用 PPO

第48课说 PPO 成了 RLHF 的默认策略优化器——为什么？因为 LLM 对齐的 RL 任务恰好戳中 PPO 的全部优点：**策略是 on-policy 的（每次用当前模型生成）、奖励是稠密可得的（奖励模型打分）、而「别走太远」的约束（KL）与 PPO 的「近端」哲学天然契合**。但 LLM 对齐的 PPO 实践有它自己的门道：**token 级的状态与奖励、参考模型的 KL 惩罚、以及一整套防止「奖励黑客」与训练崩溃的工程细节**。<span class="marginnote">RLHF 的 PPO 与传统 RL 的 PPO 的差别：传统 PPO 在「环境」里跑（奖励来自环境），LLM 的 PPO 在「文本生成」里跑（奖励来自奖励模型）；状态是「token 序列」，动作是「下一个 token」。<strong>「策略」「轨迹」「价值」在文本世界里各就各位，但实现细节完全不同</strong>。</span>

## 1 把 PPO 装进 token 世界

LLM 对齐的 PPO 里：

**策略 $\pi_\theta$**：当前 LLM——给定「提示 + 已生成前缀」，输出下一个 token 的分布。
**轨迹**：一次「提示 → 完整回答」的生成——每个 token 是一步。
**奖励**：通常在**回答末尾**给一次奖励模型打分 $R(x, y)$；中间 token 的奖励由**KL 惩罚**填充。
**价值函数（critic）**：对每个 token 位置预测「从这往后的期望回报」——PPO 的优势估计（GAE）需要它。

**token 级的处理**：一条回答里有几百个 token（= 几百个「状态」），PPO 在**每个 token 位置**计算策略梯度与价值损失——这与「一个回合一个动作」的经典 RL 不同，是「一条轨迹几百步」的长回合。<span class="marginnote">「一个回答 = 一个 episode」的视角让一切 RL 工具可用，但也带来现实约束：一条回答的生成开销不小、reward 只在末尾有信号——<strong>稀疏奖励 + 长轨迹</strong>让「KL 惩罚提供的稠密信号」变得格外重要（它让每个 token 都有梯度）。</span>

## 2 KL 约束的两种实现：惩罚式与目标式

LLM 对齐的 PPO 有 KL 约束的两种主流实现：

**实现一：逐 token KL 惩罚（KL penalty）**。把「与参考模型的 KL」直接写进每步奖励：

$$
r_t \;=\; -\beta\, \log\frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)} \qquad (\text{末尾 token 再加 } R(x,y))
$$

**每个 token 的「奖励」= 负的 KL 项**——「当前策略越偏离参考模型，这一步的奖励越负」。它像一根橡皮筋，随时把策略往回拽。

**实现二：PPO 目标里的 KL 约束**。把 KL 写进 loss 而不是奖励：

$$
\mathcal{L}^{\text{PPO-KL}} = \mathbb{E}\big[\min(\rho\hat A,\ \operatorname{clip}(\rho)\hat A)\big] - \beta\, \mathbb{E}\big[D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})\big]
$$

**两种都常用，且常叠加**（惩罚式保证「每步不飘」、目标式保证「整体不偏」）。<span class="marginnote">KL 约束在这里的角色比传统 RL 更关键：<strong>奖励模型是「人类偏好的近似」，它的高分不一定意味着「真的好」</strong>——没有 KL，策略会快速钻奖励模型的空子（如「谄媚、格式正确但内容空洞」）。KL 是「保持模型还在说人话」的护栏。$\beta$ 是「敢多偏离」的旋钮——$\beta$ 大则保守、$\beta$ 小则激进。</span>

## 3 训练稳定性：LLM 版 PPO 的工程细节

LLM 对齐的 PPO 稳定训练，靠的是一堆「教科书外的工程」：

**参考模型冻结**：$\pi_{\text{ref}}$ 是训练前的模型（常是 SFT 版），**全程冻结**，只用来算 KL。它是不动的「锚」。
**价值网络（critic）**：需要为每个 token 预测价值——通常与策略共享底座的另一个头。critic 不准，优势就偏，训练就抖。
**批量与长度控制**：PPO 的 batch 是「提示批次」，每条提示的回答长度不同——需要 padding、mask，且**超长回答的计算开销**要控制。
**奖励缩放与正则**：奖励模型的打分范围需要归一化；对「拒绝回答」等特殊情况要有处理。
**不要过度优化（not over-optimize）**：**PPO 的 KL 系数要配合「限制策略偏离参考模型的程度」**——论文观察到过度优化 KL 太小会让奖励分数虚高但真实质量下降。<span class="marginnote">InstructGPT 论文的系统实验显示了一个关键现象：<strong>「奖励模型分数」与「真实质量（人类评估）」会随 KL 约束的放松而背离</strong>——KL 太松，奖励分数一路涨、人类评估却掉头向下（奖励黑客的证据）。这让「KL 不能太小」成了 RLHF 的铁律，也让「监控 KL 大小」成为训练的日常指标。</span>

## 4 公式解析：逐 token 的奖励到底怎么算

$$
r_t = \underbrace{-\beta \log\frac{\pi_\theta(a_t|s_t)}{\pi_{\text{ref}}(a_t|s_t)}}_{\text{KL 惩罚：每步都有}} + \underbrace{\mathbf{1}\{t = T\}\cdot R(x,y)}_{\text{奖励模型：只在末尾}}
$$

- **第一步，认中间步**：$t < T$ 时只有 KL 惩罚项——「这步的输出偏离参考模型多少，就扣多少」。它让每个 token 都有梯度（稠密信号），防止「长回答中间无信号」。
- **第二步，认末尾**：$t = T$（回答结束）才加奖励模型的打分 $R(x,y)$——「整体回答有多好」在终点一次性结算。
- **第三步，认权衡**：KL 惩罚是「约束」，$R$ 是「目标」——**「讨好奖励模型」与「别偏离参考模型」在每步拉扯**。$\beta$ 决定天平倾向哪边；这个拉锯的平衡点，就是「对齐后模型」的样子。<span class="marginnote">一个常见困惑：为什么 KL 惩罚要让「逐 token」而不是「整体一次」？因为逐 token 惩罚给<strong>每一步</strong>梯度——若只在末尾给一次 KL，中间几百个 token 的「偏离责任」无法精确分配，PPO 的优势估计会模糊。<strong>逐 token 的 KL 惩罚 ≈ 对「每一步该多像参考模型」做了精细的信用分配</strong>。</span>

## 5 易错点辨析

**辨析｜易错点：** 以为「KL 约束小 = 模型更顺从」。恰恰相反——**KL 太小（$\beta$ 太小）会让模型「过度优化」奖励模型，输出谄媚但空洞的高分话术**；KL 合适才既提升奖励模型分数又保持真实质量。**「约束」是质量的一部分，不是阻碍**。

**另一个易错点**：忽略 critic（价值网络）的重要性。LLM 的 PPO 同样需要 token 级的价值预测来算优势——**critic 不准，GAE 优势就偏，策略更新就抖**。很多「PPO 训 LLM 不稳」的案例，根源是 critic 没训好（学习率、初始化、与策略共享参数的平衡）。

**第三个易错点**：把「奖励模型的分数」当「对齐质量的指标」。**奖励模型分数 ≠ 真实质量**——它是「偏好的代理」，会被策略游戏。判断对齐质量要用**独立的人类评估/基准**，而不是训练用的奖励模型。**「用自己的尺子量自己」是奖励黑客的来源**。

## 6 小结

- **LLM 版 PPO**：策略=LLM（token 级）、轨迹=一次回答、奖励=奖励模型 + KL 惩罚。
- **KL 约束两实现**：逐 token KL 惩罚（进奖励）与 PPO 目标 KL（进 loss）——常叠加使用。
- **参考模型冻结**：$\pi_{\text{ref}}$ 全程不动，作为「别走太远」的锚。
- **稳定性工程**：token 级 critic、长度控制、奖励归一化、不过度优化。
- **铁律**：KL 太小 → 奖励分数涨但真实质量跌——「约束」是对齐质量的一部分。
