## 为什么大模型的「奖励」只能从人那里学

大语言模型要「对齐」人类偏好——回答要 helpful、honest、harmless。但「有用、诚实、无害」**无法写成奖励函数**（你写不出「安全」的解析式）。**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）** 把第18篇的逆强化学习思想带到极致：**从「人类偏好判断」里学出一个奖励模型（reward model），再用强化学习优化策略**。这是「从极限到大模型」主线的收束点——**RL 的全部理论（策略梯度、KL 约束、PPO）在 LLM 对齐里迎来最大规模的实战**。<span class="marginnote">RLHF 的三段式（预训练 → 监督微调 → 偏好对齐）中，「偏好对齐」阶段把 LLM 当作 RL 里的「策略」，人类偏好当作「奖励来源」。这一视角的转换，让「对齐」从「模仿」升级为「优化」——也是本专题与《大模型微调》分类的交汇点。</span>

这篇是第19篇的开篇，也是整个专题「RL 理论 → 大模型实战」的最后一座桥。前18篇学的价值函数、策略梯度、信赖域方法，在这里第一次面对「奖励是学来的、还可能是错的」这一全新挑战。**读本篇之前，建议先把第13篇策略梯度与第14篇 PPO 的骨架在脑子里过一遍**——它们将在下面两课（PPO 对齐、DPO）反复出场。

## 1 把「生成回答」看成一次 RL 回合

在 RLHF 里，LLM 被放进 RL 框架：

**状态 $s$**：提示词 + 已生成的 token 序列（上下文）。
**动作 $a$**：生成下一个 token（或整段回答）。
**策略 $\pi_\theta(a|s)$**：LLM 本身——给定上下文，下一个 token 的分布。
**奖励 $R(s,a)$**：**由奖励模型给出**（人类偏好的代理），不是环境给的。
**回合**：从提示词开始，逐 token 生成，到停止符结束——一次生成就是一次 RL episode。<span class="marginnote">与第3章 MDP 的标准设定相比，RLHF 有两点不同：状态包含「已生成的全部文本」（高维、非表格），奖励要「整段才给一次」（延迟且由网络给出）。这两点让 RLHF 天然落在「函数逼近 + 策略梯度」的范畴，而不是表格型方法。</span>

**关键视角**：LLM 不是「下一个词的预测器」，而是「在 token 序列上的 RL 策略」。**「生成一段好回答」=「走出一条高奖励的轨迹」**——RL 的价值函数、策略梯度、KL 约束全部有了落点。<span class="marginnote">「文本生成 = 序贯决策」的视角其实很老（第19世纪的语言模型就被当序列问题），但直到 RLHF 才把「人类偏好」接进奖励——<strong>「偏好」第一次成为可优化的标量目标</strong>。这也是 RL 理论（本专题前18篇）在大模型时代的最大输出口。</span>

**一个具体的「回合」想象**：提示词是「如何用 Python 读 CSV 文件？」，状态从空序列出发，策略逐个生成 token：「`import`」「`pandas`」「`as`」「`pd`」……直到「」结束符。整段轨迹末尾，奖励模型给这整段回答打一个分——高分回答通常「给了代码、给了解释、格式整齐」。**注意奖励是「整段给一次」，不是每 token 给一次**——这就是「延迟奖励」，也正是第13篇策略梯度方法擅长处理的情形：整个轨迹共享一个回报，用策略梯度把「高分 token 序列」的概率抬起来。

**为什么不用「每 token 奖励」？** 逐 token 打分（比如「这个字好、那个字差」）几乎无法从人类标注中获得——人对「一段回答好不好」有整体判断，对「哪个 token 对」却给不出可靠信号。**「整段一个回报」不是无奈，而是贴合人类真实反馈的自然粒度**。这也意味着动作空间是「整段文本的分布」而不是「单个 token」——策略梯度（而非逐 token 的 TD）因此是更自然的选择。

## 2 奖励模型：从成对偏好到标量打分

奖励模型 $R_\phi$ 用**人类成对偏好数据**训练。数据形式：同一提示 $x$ 下两个回答 $y_1, y_2$，人类标注「哪个更好」（或打分）。训练用 **Bradley–Terry 模型**——人类选择 $y_1 \succ y_2$ 的概率由奖励差决定：

$$
P(y_1 \succ y_2) \;=\; \sigma\big(R_\phi(x, y_1) - R_\phi(x, y_2)\big)
$$

奖励模型（通常是「给回答打一个标量分」的分类器头）在这批偏好对上做**最大似然**：

$$
\mathcal{L}_{\text{RM}} \;=\; -\mathbb{E}_{(x,y_1,y_2)}\Big[\log \sigma\big(R_\phi(x,y_1) - R_\phi(x,y_2)\big)\Big]
$$

**训练出的 $R_\phi$ 是「人类偏好的代理」**——它对「人类更可能偏好的回答」给更高分。**这是第18篇「从偏好推断奖励」的现代版**：不是从「专家轨迹」学，而是从「成对比较」学。<span class="marginnote">实操上奖励模型常取「共享主干 + 两个输出头」：给两个回答分别打分的结构，能天然利用 Bradley–Terry 的相对损失。这避免了「绝对打分」在标注者之间的尺度漂移——比较是相对的，打分是绝对的，相对更容易一致。</span><span class="marginnote">奖励模型与 IRL 的对照：IRL 从「专家做了什么」推断奖励；RLHF 从「人类喜欢哪个」推断奖励。<strong>成对偏好是比示范更轻量的数据形式</strong>（标注者只需比较，不需要生成完美示范）——这让「偏好数据」可以大规模众包，RLHF 因此能规模化。</span>

**IRL 与 RLHF 的奖励学习对照**：

| 维度 | 逆强化学习（第18篇） | RLHF 奖励模型 |
| --- | --- | --- |
| 数据形式 | 专家示范轨迹 | 人类成对偏好 |
| 人类角色 | 提供「好行为」 | 提供「哪个更好」 |
| 数据难度 | 需生成完美示范 | 只需比较，可众包 |
| 推断对象 | 环境中的真实奖励 | 人类偏好的标量代理 |
| 输出 | 奖励函数（可解释） | 神经网络打分器 |
| 规模 | 小样本、可解释 | 大规模、不可解释 |

两行对比的深层含义：**RLHF 把「奖励学习」从「科研工具」变成了「规模化工程」**——人类不再需要写完美答案，只需要做廉价的「挑一个」，于是偏好数据能堆到百万级。代价是学出的奖励是「黑盒」，这为后面的「奖励黑客」埋下了伏笔。

**奖励模型的训练细节还有一层**：同一提示下往往采集 **4 个以上回答**做两两比较，配对数量越多，标注噪声越被平均。实际操作中还会对奖励模型的分数做**标准化**（减均值除标准差），让不同提示之间的奖励尺度可比，避免某个提示的偏好「霸占」训练目标。

## 3 对齐的 RL 阶段：最大化奖励，守住 KL

有了奖励模型，第三阶段是**真正的强化学习**：优化策略（LLM）让奖励模型打分最高，但**不能偏离参考策略太远**：

$$
\max_\theta\; \mathbb{E}_{x \sim \mathcal{D},\, y \sim \pi_\theta(\cdot|x)}\big[R_\phi(x, y)\big] - \beta\, \mathbb{E}_{x}\big[D_{\text{KL}}\big(\pi_\theta(\cdot|x) \,\|\, \pi_{\text{ref}}(\cdot|x)\big)\big]
$$

其中 $\pi_{\text{ref}}$ 是**参考策略**（通常是监督微调后的模型）。**KL 项防止「奖励黑客（reward hacking）」**——奖励模型只是偏好的近似，若不加约束，策略会钻奖励模型的空子（输出语法正确但无意义的「高分话术」），偏离自然语言分布。**KL 约束是 RLHF 稳定性的命门**。<span class="marginnote">「奖励黑客」是 RLHF 里最著名的失败模式：策略找到奖励模型的漏洞（如输出特别长、堆砌空话）去刷分，而不是真正变好。KL 约束是第一道防线，但<strong>根本解法是不断用新偏好数据重训奖励模型</strong>，让奖励模型自己也「跟上」策略的进化。</span><span class="marginnote">KL 约束与第14篇 TRPO/PPO 的「信赖域」一脉相承：TRPO 用 KL 限制「新旧策略距离」，RLHF 用 KL 限制「对齐策略与参考策略距离」——<strong>「别走太远」是同一个思想</strong>。而第19篇下一课会看到：PPO 是这个约束最常用的实现载体。</span>

**为什么用「KL 到参考策略」而不是「KL 到初始模型」？** 参考策略 $\pi_{\text{ref}}$ 不是随机初始化的模型，而是**已经过监督微调、会说人话的模型**。KL 约束把对齐策略钉在「会说人话」附近，而不是钉回「只会接词的原始模型」——这样优化的自由度仍很大，但又不会让策略跳进「高分胡话」的暗区。**「参考锚点选谁」本身就是一个设计决策**：锚点太松（原始模型）会失守语言质量，锚点太紧（冻结的 SFT 模型）则对齐空间不足。<span class="marginnote">$\beta$ 的取值也讲究：太小，对齐激进、奖励黑客风险高；太大，对齐乏力、回答几乎不变。实践中常让 $\beta$ 在训练早期较大、后期衰减——先稳住语言质量，再逐步放开对齐空间，是 RLHF 调参的常见套路。</span>

## 4 公式解析：偏好如何变成「可优化的奖励」

$$
\underbrace{\max_\theta \mathbb{E}\big[R_\phi(x,y)\big] - \beta\, \underbrace{\text{KL}(\pi_\theta \| \pi_{\text{ref}})}_{\text{守住分布}}}_{\text{RL 目标}} \qquad R_\phi \text{ 来自 } \underbrace{\max_\phi \log\sigma(R_\phi(y_1)-R_\phi(y_2))}_{\text{偏好似然}}
$$

- **第一步，认奖励来源**：$R_\phi$ 是**学出来的**——从「成对偏好」的 Bradley–Terry 似然里训出。它把「人觉得哪个好」变成「连续打分」。
- **第二步，认优化对象**：策略 $\pi_\theta$ 用 RL（PPO）最大化「奖励模型的期望」——**把「人喜欢」翻译成「策略优化」**。
- **第三步，认约束**：KL 项把策略钉在参考策略附近——**「提升奖励」与「别漂移」两个目标互相拉锯**，$\beta$ 决定「多敢偏离」。**这一拉锯就是 RLHF 的全部张力：既要更有用，又要不说胡话**。<span class="marginnote">RLHF 的整个链条在数学上是一个「双层优化」：外层学奖励（偏好似然）、内层学策略（RL 目标）——<strong>「先学『好』的定义，再朝它优化」</strong>。奖励模型的误差会污染策略优化（第65课配分函数的教训），所以 KL 约束不仅是稳定器，也是「对奖励模型不完美的防御」。</span>
- **第四步，认双层结构**：外层 $R_\phi$ 与内层 $\pi_\theta$ 是**两个交替优化的网络**——先训奖励模型（监督），再训策略（RL）；策略训一轮后，奖励模型对「新分布」的打分可能失真，于是可能要重训奖励模型。**「先学『好』的定义，再朝它优化；定义过时，就再学一遍」**——这是 RLHF 稳定运行的全过程。

**把这个双层结构与第1篇的 MDP 对照**：标准 RL 里奖励由**环境固定给定**，智能体只学策略；RLHF 里奖励由**另一个学习器**给出，且这个学习器本身也会被优化。**「奖励在学习」是 RLHF 与经典 RL 最本质的差别**——它把「目标函数」也变成了「学出来的东西」，这让整个优化问题的分析和调试都更难，也更有趣。

**一个 KL 的数字直觉**：设参考策略对 token 序列给概率 $p_{\text{ref}}=0.10$，对齐策略想把它推到 $p_\theta = 0.30$——单序列的 KL 贡献约 $0.30\ln(0.30/0.10) + 0.70\ln(0.70/0.90) \approx 0.33 - 0.22 = 0.11$。若 $\beta = 0.1$，则该项在目标里占 $0.011$ 的「惩罚」。**$\beta$ 放大后，哪怕奖励模型对这段话给 +1 分，KL 惩罚也会把它拉回来**——这就是「守分布」的数学抓手：奖励模型越想让你说胡话，KL 项越用力踩刹车。

## 5 易错点辨析

**辨析｜易错点：** 以为 RLHF 是「用 RL 直接学人类偏好」。RLHF 分两步：**先学奖励模型**（监督学习），**再用 RL 优化策略**（以奖励模型为目标）——偏好本身不直接进策略梯度，它先被蒸馏成「奖励代理」。**「偏好 → 奖励 → 策略」是一条链，不是一步到位**。

**另一个易错点**：把 KL 项当「可选的正则」。KL 约束是 RLHF 的**必需组件**——没有它，奖励模型的高估（它是近似的）会让策略「钻空子」崩溃。**「约束」不是锦上添花，是「用不完美奖励」的生存条件**。

**第三个易错点**：忽略「奖励模型也会过拟合/被游戏」。奖励模型在偏好数据上训练，对「数据外的表达方式」可能给出错误高分——**奖励黑客（reward hacking）** 是 RLHF 的真实风险。缓解手段（KL 约束、奖励模型校准、偏好数据多样性）是工程的核心课题。

**第四个易错点**：把「Bradley–Terry」当成唯一的偏好模型。它假设「偏好可用奖励差 + sigmoid 描述」，但真实人类偏好在**多样性与确定性之间**并非总是这样单调可比（同一个回答有人偏好详细、有人偏好简洁）。替代方案如 Plackett–Luce（对多个回答排序）、约束满足偏好模型等会改变目标形态。**Bradley–Terry 是默认选项，不是必然选项**——理解它的假设，才能知道 RLHF 的边界。

## 6 小结

- **RLHF**：从人类偏好学奖励模型，再用 RL 优化策略——「偏好」第一次可优化。
- **RL 视角**：LLM 是策略（token 生成=轨迹）、奖励模型是奖励、提示词是初始状态。
- **奖励模型**：Bradley–Terry 偏好似然训练——成对比较 → 标量打分。
- **RL 阶段**：$\max \mathbb{E}[R_\phi] - \beta\,\text{KL}(\pi\|\pi_{\text{ref}})$——提升奖励、守住分布。
- **KL 约束**是「用不完美奖励」的生存条件——与 TRPO 的信赖域同源。
- 整段给一次奖励（延迟奖励），正是策略梯度方法擅长的场景。
- 「奖励在学习」是 RLHF 与经典 RL 的本质差别：目标函数本身也是学出来的。
- KL 数字例：单序列从 $0.10$ 推到 $0.30$，KL≈0.11，$\beta$ 越大刹车越猛。
- Bradley–Terry 是默认偏好模型，不是唯一——理解假设才知道边界。
- 双头奖励模型 + 分数标准化，是「成对偏好」落到工程的关键细节。
