## 为什么从「策略评估」开始

上一节我们把价值的递归结构——贝尔曼方程——写了出来：

$$v_\pi(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v_\pi(s') \right]$$

但方程写在纸上是一回事，把它算出来是另一回事。**给定一个策略 $\pi$，如何求出每个状态的 $v_\pi(s)$？** 这是本章要回答的第一个问题，称为**预测（prediction）问题**，也叫**策略评估（policy evaluation）**。

你也许会说：这不就是解一个线性方程组吗？确实，对固定策略 $\pi$，贝尔曼方程是「$|\mathcal{S}|$ 个未知数、$|\mathcal{S}|$ 个方程」的线性方程组，高斯消元就能解。可一旦 $|\mathcal{S}|$ 大起来——围棋的状态空间比可观测宇宙的原子还多——矩阵消元就彻底失效。我们需要一条**不依赖状态总数、只靠反复迭代**的路。这条路，就是本章「动态规划」的起点，也是后面蒙特卡洛、时序差分两大算法家族共同的方法论母体。<span class="marginnote">「动态规划（Dynamic Programming）」这个词在强化学习里特指：<strong>有完美环境模型</strong>（已知 $p$ 与奖励）时，把复杂问题分解成递归子问题求解的一类方法。它是后面一切「无模型」算法的理论原乡。</span>

## 1 预测问题：把等式变成「待解的方程组」

先给问题一个准确的名字。回顾第三篇的分工：

- **预测（prediction / evaluation）**：给定策略 $\pi$，求价值函数 $v_\pi$。
- **控制（control）**：不给定策略，找最优策略 $\pi_*$。

策略评估是「控制」的一半——你得先知道当前策略有多好，才能谈得上改进它。而评估的全部工作，都围绕一个结构性的观察：

**重点：对固定策略 $\pi$，贝尔曼方程是一个「价值在等式两边都出现」的方程组，未知量正是各状态的 $v_\pi(s)$。** 它不是一个「代入就能算」的显式公式，而是一组**自指**的约束。既然直接解在规模上不可行，自然想到：把「$=$」改写成「$:=$」，用迭代去逼近那个满足约束的解。

这就像解一个方程 $x = f(x)$：如果 $f$ 温和，从任意 $x_0$ 出发反复代入 $x_{k+1} = f(x_k)$，序列就会朝不动点爬过去。贝尔曼方程正是「$v = T_\pi v$」的形式，$T_\pi$ 就是「一步期望」的算子。<span class="marginnote">不动点迭代在数学里是老面孔：第一级的数列极限、第三级《数值分析》里的雅可比迭代，都是同一个思想。RL 的独特之处只在于——被迭代的「$x$」不是一个数，而是<strong>整个状态空间上的一个函数</strong>。</span>

## 2 迭代式策略评估：把「贝尔曼方程」变成「更新规则」

于是我们定义迭代式策略评估（iterative policy evaluation）：从任意初始估计 $v_0$（比如全 0）出发，反复套用贝尔曼方程的右端：

$$v_{k+1}(s) = \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v_k(s') \right], \qquad \forall s \in \mathcal{S}$$

每一轮把**所有状态**更新一遍，叫作一次**扫描（sweep）**。核心性质：

$$v_k \to v_\pi \quad (k \to \infty)$$

**重点：迭代式策略评估是把「一次算对」换成了「一步步逼近」。** 每一步都是旧估计 $v_k$ 到新估计 $v_{k+1}$ 的一次「原地重写」——用旧价值算出新价值，新价值又成为下一步的输入。这个「用自己的输出当输入」的结构，正是上一节贝尔曼方程递归性的直接利用。

实现上有两种更新次序，对应数值分析里两个熟悉的名字：

- **双数组更新（同步）**：用一整份 $v_k$ 同时算出 $v_{k+1}$，两者互不干扰。相当于雅可比迭代。
- **就地更新（异步）**：在同一个数组上逐个状态刷新，刷新的状态立刻被后面用上。相当于高斯-赛德尔迭代，实践中通常收敛得更快。<span class="marginnote">就地在同一个数组上改，会引入「新旧混用」——但这恰恰是它的优点：信息传播更快。后面第四节《异步动态规划》会把这种「不等完备」的思想推向极致，而它在数值线性代数里早就被高斯-赛德尔证明是有益的。</span>

终止条件很自然：当两次扫描之间价值的最大变化小于某个阈值 $\theta$（比如 $10^{-4}$），就认为已经收敛，返回当前估计。

## 3 4×4 网格世界：一张能「手算」的桌子

抽象叙述容易悬空，我们用一个可以完全手算的例子把上面的更新规则钉死。这是 Sutton & Barto 书上的经典例子（Example 4.1）。

**4×4 网格世界**：一个 $4\times 4$ 的棋盘，左上与右下两个格子是**终止状态**，其余 14 个格子是非终止状态。智能体每步从「上、下、左、右」四个动作中选一个；若动作会撞到边界，则原地不动。**每一步（包括走向终止）都获得奖励 $-1$**，直到到达终止状态为止。假设一个**随机策略**：在每个状态四个动作等概率（各 $1/4$）。任务是评估这个随机策略的价值函数。

直觉先行：既然每步都扣 1 分，任何非终止状态的「期望累计负奖励」都该是负数；越靠近终止状态、越快解脱，负得越少。迭代若干轮后收敛的结果是：

![4×4 网格世界在随机策略下的最终价值函数](/images/reinforcement-learning/policy-evaluation-1.svg)

这张表值得盯住看三秒钟。**离终止状态越近，价值越高（负得越少）**：与左上终止相邻的格子是 $-14$，而棋盘中央的格子在 $-18 \sim -20$ 之间。这是「距离」的另一种度量——价值把「还要走多少步、每步都要付 $-1$」的期望，折算成了棋盘上的一张地图。<span class="marginnote">仔细观察 $-14$ 与 $-22$ 之间的差距：对角上最远的格子要走约 22 步才到终止。价值函数在这里退化成「到终点的期望步数的负值」——因为 $\gamma = 1$ 且每步奖励恒为 $-1$，价值恰好编码了距离信息。下一节我们让 $\gamma < 1$，这张表就会长出「贴现」的纹理。</span>

## 4 公式解析：迭代为什么收敛到 $v_\pi$

「反复套用右端就会收敛」——这话不能白听，我们要把它变成三步数学。

- **第一步，把更新写成算子**。定义算子 $T_\pi$：

$$(T_\pi v)(s) \doteq \sum_a \pi(a \mid s) \sum_{s', r} p(s', r \mid s, a)\left[ r + \gamma\, v(s') \right]$$

于是迭代式评估就是 $v_{k+1} = T_\pi v_k$。而贝尔曼方程说 $v_\pi = T_\pi v_\pi$——**$v_\pi$ 是算子 $T_\pi$ 的不动点**。

- **第二步，证明 $T_\pi$ 是压缩映射**。取任意两个价值函数 $u, v$，看它们经 $T_\pi$ 作用后的差距，用**最大值范数** $\lVert \cdot \rVert_\infty$（取所有状态上绝对值的最大者）来衡量。逐状态拆开：

$$|(T_\pi u)(s) - (T_\pi v)(s)| = \left|\sum_a \pi(a\mid s) \sum_{s',r} p(s',r\mid s,a)\; \gamma\, \left(u(s') - v(s')\right)\right|$$

概率是非负且和为 1 的，绝对值可以「挪进」求和里放大——三角不等式：$\left|\sum_i w_i x_i\right| \le \sum_i w_i |x_i|$（当 $w_i \ge 0$ 时）。于是

$$|(T_\pi u)(s) - (T_\pi v)(s)| \le \gamma \sum_a \pi(a\mid s) \sum_{s',r} p(s',r\mid s,a)\; \lVert u - v \rVert_\infty = \gamma\, \lVert u - v \rVert_\infty$$

两边对 $s$ 取最大，得到关键的压缩不等式：

$$\lVert T_\pi u - T_\pi v \rVert_\infty \le \gamma\, \lVert u - v \rVert_\infty$$

- **第三步，调用不动点定理**。当 $\gamma < 1$（或任务保证有限步终止、$\gamma = 1$ 也可）时，$T_\pi$ 把任意两个函数之间的距离**至少缩小 $\gamma$ 倍**，是一个压缩映射。由巴拿赫不动点定理（Banach fixed-point theorem），反复作用 $T_\pi$ 必收敛到唯一不动点 $v_\pi$，且收敛速度至少是几何级数（每轮误差至多乘 $\gamma$）。

**这段推导是全书最值得收藏的三步之一。** 它把「反复重写」这个朴素操作，变成了有理论保证的收敛算法；而后面蒙特卡洛、TD 的收敛性证明，走的全是同一套「找压缩算子」的路子。

**辨析｜易错点：终止状态要不要更新？** 终止状态是吸收态，价值恒为 0，**不进更新列表**——更新它会把 $v_{k+1}(终止)=0$ 写回去，纯属浪费。真正要小心的陷阱是：**一次迭代（一个 $k$）不等于一步经验**。$v_k(s)$ 的语义是「只往后看 $k$ 步的截断回报期望」：$v_k(s) = \mathbb{E}_\pi\left[\sum_{t=0}^{k-1}\gamma^t R_{t+1} \mid S_0 = s\right]$，它随 $k$ 逼近完整的无限和。把「迭代次数」误当成「时间步」是初学最常犯的错。

## 5 实现：一页纸的迭代评估

把上面的更新规则写成代码，不过二十来行。下面是在 4×4 网格世界上运行的完整实现：

```python
import numpy as np

def policy_eval(policy, terminal, gamma=1.0, theta=1e-4):
    """迭代式策略评估：policy[r, c, a] 是状态 (r,c) 下选动作 a 的概率。"""
    V = np.zeros((4, 4))                    # v_0 = 全 0
    actions = [(-1, 0), (1, 0), (0, -1), (0, 1)]
    while True:
        delta = 0.0
        for r in range(4):
            for c in range(4):
                if (r, c) in terminal:
                    continue                # 终止状态不更新
                v_old = V[r, c]
                v_new = 0.0
                for a, (dr, dc) in enumerate(actions):
                    r2, c2 = r + dr, c + dc
                    if r2 < 0 or r2 > 3 or c2 < 0 or c2 > 3:
                        r2, c2 = r, c      # 撞墙原地不动
                    v_new += policy[r, c, a] * (-1 + gamma * V[r2, c2])
                V[r, c] = v_new             # 就地更新
                delta = max(delta, abs(v_new - v_old))
        if delta < theta:                   # 收敛判定
            break
    return V

# 随机策略：每个状态四个动作等概率
policy = np.full((4, 4, 4), 0.25)
terminal = {(0, 0), (3, 3)}
V = policy_eval(policy, terminal)
print(np.round(V, 1))
```

运行这段代码，打印出的矩阵就是上一节那张「地图」——`[[  0.  -14. -20. -22.]  [-14. -18. -20. -20.]  [-20. -20. -18. -14.]  [-22. -20. -14.   0.]]`。注意这里用的是**就地更新**（直接写回 `V[r, c]`），它比同步双数组版本收敛得更快，也正是第四篇后面「异步」思想的雏形。<span class="marginnote">这段代码里 `gamma * V[r2, c2]` 就是「自举」：用自己对价值的旧估计来更新新估计。这个动作在动态规划里是理论核心，等我们进入第六篇《时序差分》，会发现它被保留了下来、只是把「取期望」换成了「采一个样本」。</span>

## 6 辨析：预测与控制，别混为一谈

策略评估回答「这个策略有多好」，控制回答「哪个策略最好」。两者在本章会纠缠在一起，但概念上务必分清：

- **评估的输入是策略，输出是价值**；它对策略的好坏不置可否，只负责「打分」。
- **控制的输入是环境，输出是策略**；它要用评估得到的分数去挑更好的动作。

一句话记忆：**评估给地图，控制找山峰。** 评估得到的 $v_\pi$ 是控制的下游原料——有了地图，下一步自然问：能不能顺着地图把策略改得更好？这正是下一节「策略改进」要做的事。

这条「先评估、再改进」的流水线，也是大模型对齐的骨架：RLHF 里奖励模型给策略「打分」（评估），策略梯度更新让语言模型「顺着高分的方向调整」（改进）——第十九篇会证明，PPO 与本章的策略迭代在数学结构上是近亲。

## 7 小结

- **预测问题**：给定 $\pi$ 求 $v_\pi$；对固定策略，贝尔曼方程是 $|\mathcal{S}|$ 元的线性方程组，但大规模下必须用迭代。
- **迭代式策略评估**：$v_{k+1}(s) = \sum_a \pi(a\mid s) \sum_{s',r} p(s',r\mid s,a)\left[r + \gamma v_k(s')\right]$，反复扫描直到收敛，$v_k \to v_\pi$。
- **收敛保证**：$T_\pi$ 是压缩映射（$\lVert T_\pi u - T_\pi v \rVert_\infty \le \gamma\lVert u - v \rVert_\infty$），由不动点定理保证唯一解与几何收敛速度。
- **更新次序**：同步（双数组）等价雅可比，就地（异步）等价高斯-赛德尔、收敛更快。
- **实现要点**：终止状态不更新；$v_k$ 是「截断 k 步回报」的期望，迭代次数 ≠ 时间步。
- **评估 vs 控制**：评估给地图、控制找山峰；评估是控制的前置原料。

在下一节，我们拿着刚算出的 $v_\pi$ 问一个大胆的问题：**能不能顺着这张地图，把策略改得更好？** 答案将引出一条以「贪心」为核心的定理——策略改进定理，并拼出本章第一个完整算法：策略迭代。
