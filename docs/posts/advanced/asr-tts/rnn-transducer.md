## 为什么从 RNN-T 开始

CTC 做到了端到端，但它有一个隐藏的代价：**帧间独立假设**。每一帧的字符分布是独立算的，模型看不到「自己已经输出了什么」，于是无法用语言知识帮忙——「输出了一个 th 之后，下一个更可能是 e」。注意力 seq2seq 补上了这个短板，可它又引入了新麻烦：**注意力要对整句音频「看过一遍」才能开始输出**，离线延迟高，流式场景（语音助手、实时字幕）直接用不了。

**RNN-T（RNN Transducer，RNN 转换器）** 由 Alex Graves 在 2012 年提出，恰好站在两条路的中间：**保留 CTC 的单调对齐，同时用「预测网络」建模输出之间的依赖**。它既做得到流式，又做得到语言建模——今天几乎所有主流语音助手（Google、Apple、Amazon 的在线识别）都跑在 RNN-T 及其变体上。<span class="marginnote">RNN-T 原论文 2012 年发表于 arXiv，当时深度学习尚未席卷语音；真正爆发是 2018–2019 年 Google 将其工程化并用于 Google Assistant。一篇论文要等六七年才找到工业时机，这在语音史上并不罕见。</span>

**核心概念：RNN-T**：一种端到端序列转换模型，由「声学编码器 + 预测网络 + 联合网络」构成，在保持「按时间单调推进、随时可输出」的同时，用循环结构建模「已经输出过的文本」对下一个输出分布的影响。

## 1 两种端到端的困境

先摆清 RNN-T 要解决的矛盾：

- **CTC**：每帧独立输出，对齐单调，天然流式；但不会「用已输出的词」帮助后面的预测。
- **注意力 seq2seq（如 LAS）**：输出依赖全部上下文，模型很聪明；但注意力权重原则上允许「回头再看」，必须看完整句才能输出，流式困难。

三种路线的取舍，并排放一张表看得最清楚：

| 维度 | CTC | 注意力 seq2seq | RNN-T |
| --- | --- | --- | --- |
| 对齐是否单调 | 是 | 否（可回头） | 是 |
| 能否流式 | 能 | 难 | 能 |
| 输出依赖建模 | 无（帧间独立） | 有（整句注意力） | 有（预测网络） |
| 对齐谁负责 | 空白符号隐式学 | 注意力软对齐 | 网格上的两个步进 |
| 代表应用 | 早期端到端 | 离线翻译式 | 在线语音助手 |

RNN-T 的思路是：**让「输入推进」与「输出推进」成为两个独立的步进动作**。在时刻 $t$（音频第 $t$ 帧）与输出步 $u$（已输出 $u$ 个 token）的交点，模型决定「是再读一帧音频，还是吐一个词」。听一段→能吐则吐→不能吐就继续听——像人说话时的「边听边猜边确认」。

这个「两个步进」的抽象很强大：它不规定「必须先读完多少帧才能开口」，而是把**开口时机也交给模型学习**。读得多、听得准再开口，与急着猜、先吐出来再纠偏，成了同一套可微目标里的两种策略——人说话时同样如此：有人听完一整句才答，有人半句就抢着接话。

## 2 三个网络：编码、预测、联合

RNN-T 由三部分组成：

- **声学编码器（transcription network）** $f$：把输入帧序列编码成高层表示 $h_t$（可用双向 RNN、TDNN、Conformer 等），只管「这一帧像什么」。
- **预测网络（prediction network）** $g$：接收「已经输出的 token 序列」，用一个自回归循环模型预测「接下来大概会说什么」，输出 $g_u$——它扮演的就是语言模型的角色。
- **联合网络（joint network）**：把 $h_t$ 与 $g_u$ 拼起来，算「此时此地该输出哪个 token」的分布。

$$
z_{t,u} = \tanh\big( W_{\text{enc}} h_t + W_{\text{pred}} g_u + b \big), \qquad
P(y \mid t, u) = \text{softmax}\big(W_{\text{out}} z_{t,u}\big)
$$

$z_{t,u}$ 是二者的融合表示，softmax 输出层覆盖「词表 + 空白」，空白表示「不吐词、继续听」——**这里的空白和 CTC 的 blank 是同一个思想，只是出现时机由网络自己学**。

工程上，联合网络通常先把 $h_t$ 与 $g_u$ 各自线性映射到同一维度再相加，激活后接 softmax；推理时，模型在「吐词」与「听下一帧」之间反复抉择，每抉择一次就调用一次联合网络——**每次调用只依赖当前的 $h_t$ 与 $g_u$**，这正是它能一帧一帧增量部署的结构性原因。

## 3 对齐与训练：把所有路径加起来

RNN-T 的对齐空间有多大？在 $T$ 帧里输出 $U$ 个 token，空白负责「多出来的帧」。合法对齐数约为 $\binom{T+U}{U}$——又是天文数字。训练技巧与 CTC 完全同构：**对所有合法对齐求概率和**。定义「t,u 网格」上的前向变量：

$$
\alpha(t,u) = \alpha(t-1,u)\, p(t-1,u) + \alpha(t,u-1)\, p(t,u-1)
$$

其中 $p(t,u)$ 表示在交点 $(t,u)$ 输出当前 token 的概率。递推的两种来源正是那两个步进：从「再读一帧」过来，或从「再吐一词」过来。<span class="marginnote">这张 $T \times U$ 网格是 RNN-T 的心脏：行是音频推进、列是输出推进，每条从左上到右下的单调路径就是一个合法对齐。训练就是在这张网格上做前向后向——比 CTC 多了一个「预测网络」的维度，但动态规划的灵魂一模一样。</span>

**数值算例**：设 $T=2$ 帧、$U=1$ 个 token，合法对齐数 $\binom{2+1}{1}=3$——blank 承担「多出来」的那一帧。三条路径分别是「读一帧、读一帧、吐一个词」「读、吐、读」「吐、读、读」，在 $(t,u)$ 网格上各自对应一条从 $(0,0)$ 到 $(2,1)$ 的单调折线。若三条路径概率为 $0.2, 0.3, 0.1$，输出该 token 的总概率就是三者之和 $0.6$——**与 CTC 同构：文本概率 = 所有合法对齐的概率和**，区别只在这张网格多了一个由预测网络驱动的「输出」维度。

对照两个网格能一眼看出差异：CTC 的网格只有一个维度——时间 $t$，字符在时间轴上摊开、空白夹在中间；RNN-T 的网格多了一维「输出步 $u$」，于是「已经说了几个词」也成了状态的一部分。**这多出来的一维，就是 RNN-T 比 CTC 多出的全部能力**——输出依赖、流式决策、对齐与输出的同时建模，都由它承载。

## 4 公式解析：联合网络的得分

把联合网络的公式拆开：

**第一步，看两种输入的相加**：$W_{\text{enc}} h_t$ 携带「这一帧声学像什么」，$W_{\text{pred}} g_u$ 携带「已经说了 $u$ 个词、下一个该说啥」。二者相加，是**声学证据与语言先验的逐维混合**。
- **第二步，tanh 的作用**：把混合结果压缩到 $(-1,1)$，限制幅度、稳定训练——与普通网络的激活函数扮演同一角色。
- **第三步，softmax 与空白**：输出覆盖词表 + 空白。空白概率高 = 「先听再说」，词概率高 = 「先说了再说」。**模型在学习自主决策何时发言**。
- **第四步，理解为什么能流式**：联合网络的输入只有 $h_t$ 与 $g_u$ 两个「当前值」，没有「未来帧」。编码器若用因果/单调结构（只依赖过去），整套模型就能一帧一帧地跑——这正是它成为流式工业标准的结构性原因。

## 5 流式解码与工业实践

解码时，贪心策略很直接：在网格上从 $(0,0)$ 出发，每步比较「空白 vs 最可能的词」，空白则 $t{+}1$，词则输出并 $u{+}1$——直到听完所有帧。束搜索则维护多条路径。

**数值算例（贪心解码）**：设 $T=3$ 帧、词表 $\{a, \epsilon\}$。从 $(0,0)$ 出发，第一个交点联合网络给「空白 0.8、a 0.2」→ 选空白，$t$ 前进到 1；第二个交点「空白 0.3、a 0.7」→ 输出 a，$u$ 前进到 1；第三个交点「空白 0.6、a 0.4」→ 空白。最终结果只有一个「a」。全程只用了当前帧与已输出的词，**没看过任何未来帧**——这就是「流式」的直观画面：每读一帧，立刻决定说还是不说。

贪心解码虽简单，却会错过「宁可多听一帧再开口」的更优解——束搜索正是为此准备的升级：它同时维护多条路径，把「何时开口」的取舍也一并放进搜索空间。

值得一提，「流式」不等于「逐样本流式」：工程上按块（几十毫秒一帧块）推进，块内注意力仍可局部非因果——**块内看未来、块间只依赖过去**，是流式 ASR 的常见折中。

工业落地有几个关键工程点：<span class="marginnote">延迟与质量的权衡是 RNN-T 产品的日常课题：允许「delay penalty」微调「先说还是先听」的偏向；与外部 LM 做二次重打分；对预测网络做剪枝、对编码器做流式注意力。架构吃透了，工程的苦功都在细节里。</span>一个现实例子：2019 年 Google 宣布 Google Assistant 的语音识别全面转向 RNN-T，并把「流式 vs 质量」的平衡交给训练时的延迟正则项自动调节——**用模型自己的可微目标取代人工设定的延迟阈值**。

**辨析｜易错点：** RNN-T 的 blank 与 CTC 的 blank 都在表示「此刻不输出」，但机制完全不同：CTC 的 blank 在每一帧独立决定、只管局部；RNN-T 的 blank 与词 token 一样由联合网络算出——它同时看「这一帧声学像什么」与「已经说了什么」，因此是一个**全局语境下的发言决策**，而不是「静音帧专属」。把两者画等号，是读 RNN-T 论文时最常见的误解。

RNN-T 家族仍在演进：**Emformer** 用记忆块与块级注意力提升流式编码器效率；**fastEmit** 微调空白偏好以压低延迟；近年主流系统常把 RNN-T 与 Conformer 编码器、外部 LM 重打分组合——架构的骨架上，工程细节持续堆叠。

训练复杂度也值得算一笔：网格前向后向约需 $O(TU)$ 次联合网络调用。设 $T=300$ 帧、$U=50$ 个 token，就是约 15000 次浅层 MLP 前向，与 CTC 的 $O(T(2L+1))$ 量级相当——只是多算了「输出步」这一维的每个交点，这正是 RNN-T 训练比 CTC 略贵的原因。

**术语速查**：

| 术语 | 一句话含义 |
| --- | --- |
| 声学编码器 $f$ | 把帧序列编码成高层表示 $h_t$ 的网络 |
| 预测网络 $g$ | 用已输出的 token 自回归预测下一个「大概说什么」 |
| 联合网络 | 融合 $h_t$ 与 $g_u$，输出「词表 + blank」的分布 |
| $T\times U$ 网格 | 行=音频推进、列=输出推进，单调路径=合法对齐 |
| 延迟正则 | 训练时惩罚「太晚才吐词」，自动平衡流式与质量 |

## 6 小结

- **RNN-T 解决双重矛盾**：保留 CTC 的单调对齐（流式），同时用预测网络建模输出依赖（语言建模）。
- **三网络结构**：声学编码器 $h_t$、预测网络 $g_u$、联合网络 $z_{t,u}=\tanh(W_{\text{enc}}h_t+W_{\text{pred}}g_u+b)$，softmax 覆盖词表+空白。
- **对齐空间 $\binom{T+U}{U}$**：用 $T\times U$ 网格上的前向后向动态规划训练，与 CTC 同源。
- **流式的结构性保证**：联合网络只看当前 $h_t$ 与 $g_u$，不依赖未来帧。
- RNN-T 是语音助手在线识别的事实标准；它的「两个步进」思想在语音、甚至流式视频理解里都广泛复用。
