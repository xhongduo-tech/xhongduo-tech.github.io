## 为什么从 Whisper 开始

前面的几节讲的是「怎么做端到端」——CTC、RNN-T、Conformer。但 2022 年的 Whisper 提出的是另一个层级的问题：**在「怎么做」之前，数据从哪来？** 传统语音识别依赖人工转录的标注语料，昂贵、稀有、且以少数语言为主。Whisper 的答案是：直接从互联网上抓取「音频 + 文本」对——大量来自 YouTube 的配音视频、字幕、旁白——用 **68 万小时的弱监督数据**训练一个统一的序列到序列模型。<span class="marginnote">68 万小时是什么概念？按一年 8760 小时算，约合 78 年不间断的语音。而传统标注语音数据集通常只有几十到几千小时。数据量的三个数量级差距，是 Whisper 之后语音识别「范式换轨」的根本原因。</span>

Whisper 的意义不在某一条创新技巧，而在**把「规模 + 弱监督 + 多任务统一」这套 GPT 式配方，第一次完整地搬到语音识别**。它也因此成为后面 TTS 数据管线、以及一切「语音大模型」叙事的坐标原点。

**核心概念：弱监督（weak supervision）**：用「并非人工逐句标注、但足够有信息量」的自动数据（如字幕与音频的时间对齐、网页成对的文本图像）来监督训练，质量低于强标注，但规模可以大几个数量级。

## 1 弱监督范式：用「脏」数据赢「净」数据

Whisper 的数据管线是典型的「以脏换多」：

1. 从 Web 抓取音频与配对文本（字幕、描述、旁白），自动对齐过滤出「音频文本基本对得上」的片段。
2. 训练时直接以文本为标签，**不人工清理每个样例的错字**——用训练本身的损失惩罚那些对不上的噪声。
3. 在**多个语言、多个口音、多类噪声**上同时学，模型被迫学会「剥离噪声、抓住语言内容」。

这套思路与图像领域的 CLIP、文本领域的 GPT 如出一辙：**不追求每条数据干净，而追求数据总量与分布足够大**。模型有了规模，就有了在噪声中找信号的余量。<span class="marginnote">这也是「从极限到大模型」主题词的最佳注脚之一：当数据规模逼近某个阈值，涌现出的不是某一处指标的微小提升，而是「零样本泛化」这种质的改变——Whisper 第一次证明，ASR 也有这种涌现。</span>

## 2 单一模型的多任务：一切皆 token

Whisper 最惊艳的设计，是把「多语言识别 + 翻译 + 语言检测 + 时间戳」全部折叠进一个序列到序列模型。秘密武器是**特殊 token**：解码器读入一段「指令前缀」，就知道自己该干什么：

$$<|\text{startoftranscript}|> \; <|\text{en}|> \; <|\text{transcribe}|> \; <|\text{notimestamps}|> \cdots$$

- 语言 token（如 `<|en|>`）告诉模型「这是英语」——模型先听一耳朵、自报语言；
- 任务 token：`<|transcribe|>` 转写本语言，`<|translate|>` 翻译成英语；
- 时间戳 token（`<|0.00|>`, `<|13.42|>` 等）让模型输出片段的起止时刻，直接把语音与字幕对齐做出来。

**多任务不需要多个模型，只需要一套 token 词汇表**——这个「用 token 协议取代模型协议」的思想，后来被 LLM 的 function calling、语音大模型的 VAD 与说话人任务反复复用。

## 3 模型结构：Encoder–Decoder 的语音实现

Whisper 是标准的 **Transformer 编码器–解码器**：编码器（多个 Conformer 式 Transformer 块）接收 30 秒语音的 80 维 log-mel 特征，解码器以自回归方式逐 token 输出文本。训练时用**多语言字节级 BPE tokenizer** 统一词表，一条样本就是「30 秒音频 → 一段 token 序列」。推理时把长音频切成 30 秒窗口，重叠滑窗后按时间戳拼接。

**核心要点：Whisper 不接外部语言模型**——它坚持「声学与语言在同一个模型里联合建模」，这正是它与经典「声学+LM 两段式」范式的分水岭。

## 4 公式解析：条件语言建模的完整形式

Whisper 的每个输出 token 由「音频」与「前面已输出的所有 token」共同决定：

$$
P(y_1 \dots y_m \mid X) = \prod_{t=1}^{m} P(y_t \mid y_1 \dots y_{t-1},\, X)
$$

分步拆解：

- **第一步，看懂条件对象**：$X$ 是 30 秒的音频特征，$y_1\dots y_m$ 是 token 序列（含指令前缀与内容）。解码器每一步的条件是「整段音频 + 之前所有 token」。
- **第二步，为什么能多任务**：指令前缀 token（语言、任务、时间戳标记）只是 $y_1\dots y_{t-1}$ 的一部分——**「要转写还是翻译」本身就成了模型要学到的条件**。
- **第三步，束搜索解码**：推理时不再枚举，而是用上一节的束搜索，让 `argmax` 变为「束宽内的近似最优」。
- **第四步，看对齐从哪来**：时间戳 token 出现在词序列中间，模型把「正在输出的词」与「音频里的大致时刻」关联起来——时间对齐**不是独立模块，而是同一个语言建模任务的副产品**。CTC 时代需要显式对齐，这里连对齐都是学出来的。

## 5 影响与反思：零样本与幻觉

Whisper 带来的不只是更好的识别：

- **零样本泛化**：没有微调就能听多种口音、背景音乐、不同采样率——在传统基准上远超当时微调过的系统。
- **下游基石**：Whisper 的 30 秒分段 + 时间戳被 TTS 数据清洗、语音翻译、说话人日志广泛复用；OpenAI 后续的语音模型也都以它为基础。
- **清醒的代价**：弱监督引入**幻觉（hallucination）**——在静音或噪声段，模型会自信地「编」出句子；对稀有语言、非母语口音仍不稳。这提醒我们：**规模解决了数据分布问题，却没有解决「模型何时该承认不知道」的问题**——这个课题，会一直延续到今天的语音大模型。

## 6 小结

- **弱监督范式**：用 68 万小时「音频+文本」自动配对数据，以脏换多，赢在规模与分布。
- **多任务统一**：语言 token、任务 token、时间戳 token 把转写/翻译/检测/对齐折叠进一个解码器。
- **结构**：Encoder–Decoder Transformer，编码器吃 80 维 log-mel，解码器自回归出 token，不接外部 LM。
- **条件建模** $P(y\mid X)=\prod_t P(y_t \mid y_{<t},X)$：指令前缀是条件的一部分，对齐是语言建模的副产品。
- 零样本能力改变下游生态，但幻觉与稀有语言仍是未解难题。
