## 为什么从稀疏专家讲起

上一站我们在《大模型原理》与《MoE 混合专家架构》里认识了**稀疏专家（sparse experts）**：模型不再是「一个巨大的前馈网络」，而是几百个互相竞争的小网络。今天要写的 ktransformers，全部设计都建立在一个事实上——**超大 MoE 模型虽然参数多，但每个 token 只激活其中一小部分**。这正是「消费级显卡也能跑满血 DeepSeek-V3」的第一性前提。<span class="marginnote">参数总量与激活量是两个完全不同的数字。ktransformers 的整套思路可以浓缩成一句话：<strong>把「永远用不到的那部分权重」藏进便宜的大内存里。</strong></span>不把这一层算清楚，后面所有「为什么 CPU 能算」「为什么能省显存」都无从谈起。

## 1 从稠密到稀疏：MoE 的设计动机

经典 Transformer 的每一个 Transformer 块里，前馈网络（FFN）是**稠密（dense）**的：所有参数对每个 token 都要算一遍。参数量一大，推理开销就与总参数量线性挂钩——而训练一个几万亿参数的全稠密模型，算力成本几乎是天文数字。

**混合专家（Mixture of Experts，MoE）**把这条路改道：不训练一个巨型稠密网络，而是训练**一组专家（experts）**，每个专家是一个较小的 FFN；外加一个**路由网络（router / gating）**，由它来决定每个 token 该交给哪几个专家处理。<span class="marginnote">MoE 的「条件计算」（conditional computation）思想可追溯到 1991 年 Jacobs 等人的工作；GShard、Switch Transformer 让它在现代大模型里复活。这一系谱在第四级《MoE 混合专家架构》里有完整梳理。</span>

**条件计算**是理解 MoE 的关键词：网络的计算路径**依赖于输入**。不同的 token 走不同的专家，「不相关的参数就不计算」——这就是「稀疏」二字的来历。模型变大了，但单次推理只触碰参数总集的一小片，计算量被「解耦」出参数量之外。

「解耦」是这里最值得停留的词：**在稠密模型里，参数量与计算量严格绑定**——70B 模型每个 token 就要算 70B 参数；而 MoE 打破了这条绑定——671B 模型每 token 只算 37B。这个「打破」意味着：**你可以把模型做得很大（能力更强），而不必付出同等的计算代价（推理更便宜）**。这是 MoE 在「规模」与「成本」之间解出的一个漂亮折中，也是它成为当代超大模型主流架构的根本原因。

「参数量与计算量解耦」的历史意义值得放大：在 MoE 之前，「更大模型 = 更贵推理」是铁律；MoE 第一次让「模型大小」与「单次推理成本」**不再成正比**。这一变化深刻影响了整个 AI 基础设施——它让「把模型堆到万亿参数」从「算力无底洞」变成「存储问题」（权重要存，但不必每次全算）。**ktransformers 的整个存在，正是建立在这个「解耦」之上**：正因为「存储 671B」与「计算 37B」是两件独立的事，才可能「把 671B 存在便宜的大内存、只把高频的 37B 放在贵的显存」。**没有这个解耦，异构就没有操作空间**——这是 MoE 之于本专题的第一性价值。

## 2 DeepSeekMoE 的组成：共享专家 + 路由专家

ktransformers 的看家模型 DeepSeek-V3 用的正是 DeepSeekMoE 结构。**每个 MoE 层由两部分专家组成**：

**共享专家（shared expert）**：每个 token 必算，负责「几乎所有 token 都需要的通用知识」，提供稳定的基础能力。DeepSeek-V3 每层有 1 个共享专家。

**路由专家（routed experts）**：数量庞大、各司其职，负责「按需分发的专项知识」。DeepSeek-V3 每层有 **256 个路由专家**，而每个 token 只在其中选 1 个来算（top-1 路由）。

于是每层每 token 实际计算的 FFN 专家只有 **1 个共享专家 + 1 个路由专家 = 2 个**。路由选择靠一个轻量门控网络：

路由网络（gating）本身的代价要算清楚：它是一个「**把一个向量投影成 256 个分数**」的小线性层，维度只有隐藏层的一小部分——**与专家 FFN 的矩阵乘相比，路由的算力开销几乎可以忽略**。但路由有一个独特属性：它是**每 token、每层都要执行的串行依赖点**——先算出路由分数，才知道该派哪个专家。这个「依赖点」决定了异构调度里「路由在 GPU 上算、专家在 CPU 上算」的先后顺序（第 2 篇会展开）。**路由虽小，却是整条稀疏计算链的「指挥棒」**——它决定了每个 token 接下来要触发哪些计算，也决定了 ktransformers 每次前向要唤醒哪些专家。

「路由」还有工程上的一层含义：**路由是「可复现的稀疏」**——同一个 token 在同一份权重下，路由结果确定。这意味着「专家放置」（谁在 GPU、谁在 CPU）可以**离线统计**得出：先跑一批代表性输入，记录每个专家的被激活次数，就能知道「谁值得放 GPU」。**稀疏性 + 可复现的路由，让「按频率放置」成为可能**——这是后面第 2 篇「频率感知放置」的伏笔，也是 MoE 稀疏性从「模型性质」走向「系统策略」的关键桥梁。

对比「2/257」这个比例（256 路由专家里选 1，加 1 共享，共 257 个专家里激活 2 个），稀疏度达到约 99.2%——**每层每 token 有 255 个专家完全不被计算**。这个「99.2% 不计算」就是一切性能优化的空间：不需要的权重，可以安心地放到慢速存储里吃灰。MoE 的稀疏性，本质上是一张「可安全忽略」的清单。

$$
\text{expert}_t = \arg\max_{e \in \{1,\dots,256\}} \big(\text{softmax}(W_g\, x_t)\big)_e
$$

这行式子说的是：把 token 的表示 $x_t$ 经过门控投影 $W_g$ 打分，取分数最高的那一个专家。<span class="marginnote">DeepSeek-V3 的 top-1 比 V2 的 top-8 更极端——稀疏到极致，也给「只把少数专家放上 GPU」的异构方案腾出了空间。激活粒度越细，ktransformers 越游刃有余。</span>

## 3 激活的稀疏性：671B 与 37B 的落差

DeepSeek-V3 的总参数量是 **671B**，但每个 token 实际激活的参数只有约 **37B**。这个落差从哪来？把 61 层 Transformer 拆开看：

- **Attention 部分**（含 MLA 的投影）与**共享专家**：稠密，每 token 必算。
- **256 个路由专家**：稀疏，每 token 只碰 1 个。

671B 参数里，路由专家占了约 **500B+**，也就是七成半以上的权重是「靠运气才被摸到」的。**激活率（activation ratio）**——激活参数量与总参数量的比值——决定了稀疏性的强度：

$$
\text{activation ratio} = \frac{\text{37B 激活参数}}{\text{671B 总参数}} \approx 5.5\%
$$

平均下来每个参数只有约 5.5% 的 token 会用到它。

5.5% 这个数字也给出了「异构可行」的边界：若激活率高达 50%（每 token 要碰一半参数），那么「冷专家」几乎不存在，卸载的收益会大幅缩水。**MoE 的稀疏程度，直接决定了异构推理的收益上限**——激活率越低，能安全放慢速存储的权重越多，CPU/DRAM 的「接单量」越大。这也是为什么 ktransformers 最适配的是 DeepSeek-V3 这种「高稀疏」模型（每 token 只激活 37B/671B），而不是激活率偏高的中等 MoE。<span class="marginnote">5.5% 是「平均」，真实的分布远非均匀——少数「热专家」被高频命中、多数「冷专家」几乎无人问津，这正是下一篇《专家激活幂律分布》的主角。那个分布才是 ktransformers 一切放置策略的根。</span>

把「37B 从哪来」再拆细一点，它由三部分拼成：**① Attention 相关的稠密投影（每层都算）；② 共享专家（每层必算）；③ 每层被选中的那个路由专家（256 选 1）**。前两部分是「固定成本」——不管路由选谁都要付；第三部分是「可变成本」——随 token 不同而变。对 671B 模型，路由专家的权重占了七成半以上，所以「第三部分」正是稀疏性最大的藏身处：**固定成本躲不掉，可变成本才是可省的空间**。理解这三部分的构成，你就明白为什么 ktransformers 的优化重点落在「路由专家的放置」上——那是整个模型里「最值得被差异化对待」的那块权重。

## 4 公式解析：稀疏激活比例与推理成本

把「稀疏性」翻译成可比较的数字，是理解异构推理的第一步。设模型总参数为 $P$，单 token 激活参数为 $P_{\text{act}}$，则**单 token 的计算量（FLOPs）**约正比于 $P_{\text{act}}$，而**权重存储量**正比于 $P$。两者之比即激活率：

$$
\text{FLOPs per token} \approx 2 \times P_{\text{act}}, \qquad \text{weights} \approx P
$$

对 671B 模型，逐项拆解：

- **第一步，激活**：$P_{\text{act}} \approx 37\text{B}$，所以推理时真正要做的矩阵乘，规模只与 37B 相当。
- **第二步，存储**：$P \approx 671\text{B}$，所以权重存储量仍是 671B 的量级——**激活省的是计算，存储省不了**。

「存储省不了」这一点至关重要：**MoE 的稀疏性只帮你「少算」，不帮你「少存」**——671B 权重哪怕只有 5.5% 被激活，全部 671B 仍要放在系统里。这直接导向下一章的问题：「既然权重都要存，那存哪？」——答案正是 ktransformers 的异构分层：把高频激活的 37B 留在高速显存，把 94% 的「低频权重」安心放进慢速大内存。**「稀疏」与「异构」的衔接点就在这里：稀疏性决定了「哪些权重必须快」，存储层次决定了「哪些权重可以慢」。**

## 5 辨析｜易错点：稀疏 ≠ 剪枝

**辨析｜易错点：** 把「MoE 稀疏」与「模型剪枝」混为一谈，是最常见的误解。**稀疏（sparsity）**是「每 token 只激活一部分专家，但所有专家都存在、都可被激活」；**剪枝（pruning）**是「直接删掉一部分权重，模型变小」。前者是「动态选择」，后者是「永久移除」。

- **稀疏**：671B 权重全在，只是每个 token 用其中 37B——**能力不减，计算减**。
- **剪枝**：权重被删，模型变小——**存储减，但能力可能损失**。

顺带一提，「稀疏」这个词在深度学习里还有一层「参数稀疏」的含义（权重矩阵里很多零元素）——那是「结构稀疏」，与 MoE 的「专家稀疏」不同。**MoE 是「计算路径稀疏」**：不是权重里有很多零，而是「每个 token 只走少数专家的计算路径」。分清「计算稀疏」与「参数稀疏」，在读技术文章时能避免混淆——「稀疏矩阵运算」（参数稀疏）与「稀疏专家」（MoE）是两套完全不同的技术栈。

另一个易错点：把「top-1 路由」误解为「模型每次只用一个专家」。**每个 MoE 层每次是「1 个共享专家 + 1 个路由专家 = 2 个」**，而且 61 层各有自己的 2 个——「只激活 1 个」说的是「每层 256 个路由专家里选 1 个」，不是「整个模型只算 1 个专家」。把「每层的稀疏」与「全局的稀疏」分清，才不会把「37B 激活」误算成「只有 1 个专家在工作」。<span class="marginnote">「每层 2 个、共 61 层」才是完整画面：<strong>每次前向实际走的是 61 层 × 2 个专家 + Attention</strong>——稀疏是针对「每层的候选集」而言，不是针对「整个模型」。</span>

第三个易错点：以为「路由专家选得越少越好」。top-1 是 DeepSeek-V3 的选择，但**不是唯一选择**——DeepSeek-V2 用的是 top-8（每层 8 个路由专家），Qwen MoE、Mixtral 也各有自己的路由设定。top-1 更省算力（激活量更小），但 top-k（k>1）往往能力更强（多个专家协同）。**「激活几个专家」是「能力 × 成本」的权衡，不是越大/越小越好**——DeepSeek-V3 选 top-1 是为了极致稀疏，恰好也最适配「异构卸载」这种「激活越少越好」的场景。把「top-k 是个可调参数」记在心里，你就不会把「DeepSeek 用 top-1」误当「所有 MoE 都用 top-1」。

## 5 辨析｜易错点：稀疏 ≠ 剪枝

## 6 小结

把这一篇收成「三个数字、两个方向」：**671B（总参数）、37B（激活参数）、5.5%（激活率）**——稀疏性让「模型很大」与「计算不贵」可以兼得。

- **MoE = 一组专家 + 路由**：每 token 由门控网络决定走哪几个专家，条件是计算路径依赖输入。
- **DeepSeekMoE**：每层 1 个共享专家 + 256 个路由专家，top-1 路由——每层每 token 实际算 2 个专家。
- **稀疏度约 99.2%**：每层 257 个专家里 255 个不被计算——这是「可安全忽略」的清单。
- **激活率 5.5%**：37B/671B——**激活省计算，存储省不了**。
- **稀疏 ≠ 剪枝**：一个动态选择、一个永久移除；能力不减 vs 存储缩小。
- **异构的衔接**：稀疏性决定「哪些要快」，存储层次决定「哪些可以慢」——下一篇讲「谁快谁慢」的分布规律。
- **路由的三个要点**：算力便宜、串行依赖（先路由后派专家）、可复现（让离线统计放置成为可能）。
- **稀疏是双刃剑**：既省计算、允许多层存放，也带来路由依赖与汇合开销——看全「省与多」才算理解 MoE。

「路由可复现」这条值得再叮嘱一句：它让「ktransformers 的放置不是玄学」——**先用一批数据跑出激活统计，再据此决定专家放哪**，整个过程可重放、可验证。这与你后面学到的「频率感知放置」直接衔接，也是「从模型性质推导系统策略」的完整示范：**MoE 的稀疏结构，决定了系统该把资源花在「路由专家」上，而路由的可复现性，决定了系统能「提前算好怎么花」**。

再补一句「反着读」的心得：**稀疏既是机会，也是约束**——机会在于「可以少算、可以分层」，约束在于「路由必须每 token 先算、专家结果必须汇回主路径」。理解 MoE 的完整面貌，既要看到它「省了什么」，也要看到它「多了什么」（路由、汇合、负载不均）。把「省与多」都看清，才能像 ktransformers 一样在稀疏的棋盘上设计出真正高效的布局。

在下一节，我们将追问稀疏的「结构」：**37B 不是均匀激活的——哪些专家被反复命中、哪些几乎无人问津？这就是专家激活的幂律分布。**带着「稀疏 = 机会 + 约束」的完整认知，我们就能在下一节更准确地判断：这个「机会」到底有多大、又该怎么抓。
