## 为什么「内存放哪」也值得研究

权重放 CPU 内存只是第一步，**放 CPU 内存的哪个位置**同样影响性能——尤其当机器是**多路（multi-socket）服务器**或**工作站级 CPU** 时。现代 x86 平台用 **NUMA（非均匀内存访问）**组织内存：CPU 访问「自己的内存」快，访问「对家 CPU 的内存」慢。把几百 GB 的专家权重放错 NUMA 节点，等于给 CPU 侧计算加上无谓的延迟。<span class="marginnote">这一节讲两件事：<strong>NUMA 感知的内存分配</strong>（权重放对位置）与 <strong>Pinned Memory 缓冲</strong>（GPU 传输的落点）。它们是「异步调度」能跑得快的地基——数据流经的每一段内存都要「就地、就近」。</span>

## 1 NUMA：访问不是均匀的

**NUMA（Non-Uniform Memory Access，非均匀内存访问）**是服务器级 x86/ARM 平台的内存组织方式。多路服务器有多个 CPU（socket），每个 socket 直连一部分内存条——本地访问与远端访问的延迟/带宽不同。

| 访问类型 | 相对延迟 | 说明 |
| --- | --- | --- |
| CPU 访问本地内存 | 低（1×） | 内存直连该 CPU，跨内存控制器 |
| CPU 访问远端内存 | 高（约 1.5–2×） | 数据要经 CPU 间互联（如 UPI/Infinity Fabric） |
| 本地 vs 远端带宽 | 本地更高 | 远端访问还占用互联带宽 |

「1.5–2× 的延迟」在直觉上好像不算大，但在带宽受限的推理场景里，**延迟翻倍会转化为吞吐减半**——因为解码的每一步都在等权重，而等待时间主要由「读权重的往返延迟」决定。更糟的是，远端访问还**占用 CPU 间互联的带宽**，多个 CPU 同时访问对方内存时，互联通道会成为新的瓶颈。**NUMA 的影响不是「慢一点」，而是「叠加在带宽账上的又一个折扣」**——这正是它在 ktransformers 里被单列一节的原因。

ktransformers 场景里，冷专家权重要被「某颗 CPU」反复读取做 GEMM。**如果权重落在错误的 NUMA 节点**——例如绑在 socket 0 的线程，权重却分配在 socket 1 的内存——每次读取都跨节点，延迟翻倍、带宽减半，CPU 侧专家计算被白白拖慢。

为什么「多路服务器」特别容易踩 NUMA 坑？因为多路平台的内存控制器是**分散**的——每个 socket 只管自己直连的内存，CPU 间通过 UPI（Intel）/ Infinity Fabric（AMD）互联。负载均衡器或 OS 默认的「首次接触分配」（first-touch allocation）常常把内存分到「发起分配的线程所在节点」——如果该线程后来被迁移到别的核，内存就「错位」了。**NUMA 优化的本质，就是对抗这种「分配与访问错位」**：要么让访问去找分配（线程绑核），要么让分配去找访问（`numa_alloc_onnode`），ktransformers 两者都做。<span class="marginnote">NUMA 的经典对策是<strong>「先绑核，再就近分配」</strong>：CPU 亲和性（affinity）决定线程跑在哪颗核上，`numa_alloc_onnode` 决定内存分配在哪个节点。ktransformers 正是让「跑专家内核的线程」与其「读取的权重」落在同一节点。</span>

## 2 ktransformers 的 NUMA 感知分配

**NUMA 感知内存分配（NUMA-aware memory allocation）**在 ktransformers 里落实为两条原则：

**原则一：按专家归属对齐节点**。每个冷专家的权重分配在「负责计算它的 CPU 线程」所在的 NUMA 节点上。若系统有多个节点，专家按线程亲和性分组，权重随线程走——**算在哪、数据就在哪**。

「算在哪、数据就在哪」这句口诀，其实是存储局部性（locality）原则的极致版：数据访问的所有成本——延迟、带宽、能耗——都随「距离」上升。CPU 访问本地内存是「近」，访问远端内存是「远」，而这个「远近」在现代多路平台上是**硬件级的事实**，不是抽象概念。ktransformers 的 NUMA 感知分配，就是把这些「硬件级事实」翻译成「分配策略」——**每一层系统优化，都是在某条物理约束上做文章**，NUMA 优化做的是「内存访问距离」这篇文章。<span class="marginnote">多线程矩阵乘里，「线程分块」与「数据分块」必须对齐：线程 A 算权重块 W_A，W_A 就必须在 A 的本地内存。错位一次，每次读块都跨节点。</span>

**原则二：负载与内存容量按节点平衡**。几百 GB 权重不应挤在一个节点（可能放不下、也可能造成单节点带宽饱和）。分配器按各节点的空闲容量与带宽把专家均匀铺开。

## 3 Pinned Memory：让 GPU 传得动

另一类内存是 **Pinned（页锁定）内存**。GPU 要从 CPU 内存搬数据（冷专家结果回传、token 输入下发），走的是 **PCIe DMA**。普通内存是**可分页（pageable）**的，操作系统可能把页换到磁盘——DMA 无法直接处理可分页内存，于是 CUDA 运行时要先「锁页 + 拷贝一份」，多一次搬运、不可预测。

**Pinned Memory（锁定页内存）**是**预先锁定的、DMA 可直达**的内存。数据经 PCIe 传输时，直接从 pinned 缓冲进/出，跳过「锁页-拷贝」步骤。

「预先锁定」四个字值得拆开：普通内存页是**可分页**的——OS 为了给别的进程腾空间，可能把某页换出到磁盘；DMA 引擎访问这种「可能被换走」的页是危险的（地址随时失效）。Pinned 就是向 OS 声明「这几页别动，我要让硬件直接访问」——OS 把页固定在物理内存里，DMA 才能安全地按物理地址搬运。**Pinned 的本质，是「用锁定换确定性」**：牺牲一点「让 OS 灵活管理内存」的自由，换取「跨设备传输可预测、可直达」。<span class="marginnote">pinned 内存的代价：它不能被换出、占用固定的物理页，过量使用会挤压系统内存。工程上是<strong>「少量、高频、专用」</strong>——只给跨设备热路径用，比如专家结果回传缓冲与输入 batch 缓冲。</span>

在异步流水线里，pinned 缓冲的作用是**降延迟**：GPU 侧 CUDA Graph 等「专家结果就位」时，结果直接从 pinned 缓冲 DMA 到显存，不经过不可预测的页错误路径——这正是「decode 只调一次 CUDA Graph」能稳定成立的数据面保障。

pinned 缓冲还有一个「隐藏功能」：**它是零拷贝（zero-copy）传输的基础**。某些小张量场景下，GPU 可以直接从 pinned 内存读取/写入，而不必先搬到显存——省掉一次复制。但零拷贝只适合「小、少次」的传输，大权重仍要正经 DMA。ktransformers 在「专家结果回传」这类小张量上用固定 pinned 地址 + 直接读写，正是把零拷贝的收益用在了刀刃上。

## 3.5 消费级机器也要 NUMA 吗？

一个常见的疑问：我只有一颗 CPU（单 socket），还要管 NUMA 吗？**单 socket 机器没有「跨 socket 的 NUMA」问题，但仍有「内存通道」的布局问题**：

- **多 socket**：NUMA 问题明显——访问对家内存慢 1.5–2×，必须绑核 + 就近分配。
- **单 socket**：所有内存都「本地」，但**内存条的数量与通道数**决定带宽——同样 384GB，插 8 条（八通道）比插 4 条（四通道）带宽高一倍。

**「单 socket 不是没有内存问题，只是问题从『远近』变成『通道』」**——对 ktransformers 这种「带宽受限」的场景，通道数的差别直接决定 CPU 侧吞吐。**「内存够大」与「内存够快」是两件事**：单 socket 用户要检查的是「内存条插满了没、通道用满了没」，而不是「该不该绑 NUMA」。

「单 socket 看通道、多 socket 看远近」——这条判断也呼应了本专题的带宽主线：**无论什么形态的机器，带宽永远是 CPU 侧的天花板**。NUMA 也好、通道也罢，本质都是「让内存带宽被有效利用」的手段。**「带宽意识」比「具体机制」更根本**——掌握了「处处留意带宽」的意识，你就能在任何硬件形态下找到「带宽被浪费在哪」的答案。<span class="marginnote">这里也能解释为什么官方部署建议常写「382GB+ DDR5」：<strong>它同时要求「容量够」（装 377GB 权重）与「带宽够」（DDR5 而非 DDR4）</strong>——容量与带宽是两笔独立的账，一笔都不能省。</span>

## 4 公式解析：跨设备传输的有效带宽

pinned vs 可分页的差异可以量化。设单次专家结果传输的数据量为 $B$ 字节：

- 可分页路径：先锁页拷贝，时间 $t = \frac{B}{BW_{pcie}} + t_{\text{lock}}$，其中 $t_{\text{lock}}$ 是页锁定与拷贝的固定开销，可能含页错误。
- pinned 路径：DMA 直达，$t = \frac{B}{BW_{pcie}}$，无固定开销。

注意 $t_{\text{lock}}$ 里那个「可能含页错误」——这是可分页路径最阴险的地方：它不只是「慢一点」，而是**不确定性**。某个时刻页面恰好不在物理内存（被换出了），锁页就要先触发一次磁盘读回，延迟可能飙到毫秒级——在逐 token 的解码路径上，一个毫秒级的抖动就是一次明显的卡顿。pinned 消除的不只是「固定开销」，更是**这层不可预测性**——对延迟敏感的服务，确定性往往比平均性能更重要。

**有效带宽**的定义：

$$
BW_{\text{eff}} = \frac{B}{t} = \begin{cases} \frac{B}{B/BW_{pcie} + t_{\text{lock}}}, & \text{可分页} \\ BW_{pcie}, & \text{pinned} \end{cases}
$$

逐项拆解：

- **第一步**：$B$ 小时，$t_{\text{lock}}$ 占比大——可分页路径的有效带宽被固定开销压低，pinned 优势明显。
- **第二步**：$B$ 大时，两项都接近 $BW_{pcie}$——大传输时固定开销占比变小，pinned 优势被摊薄。
- **第三步**：关键在**小传输场景**——解码的专家结果回传正是「小 B」：pinned 消除了 $t_{\text{lock}}$，有效带宽从「被固定开销压低」恢复到 $BW_{pcie}$。

「小 B 场景 pinned 优势最明显」与「解码的跨设备传输恰好是小 B」——这两个事实撞在一起，正是 ktransformers 在解码热路径上用 pinned 的原因：**它不是为「大传输」优化（那种场景固定开销可忽略），而是为「小传输、高频次」优化（那种场景固定开销占比最大）**。解码路径上每层都要回传专家结果（小 B、高频），pinned 的收益被高频放大——**「优化要瞄准『高频小操作』而非『低频大操作』」**，这是性能工程的又一个通用原则：高频路径上的微小改进，会被次数放大成巨大收益。

## 5 辨析｜易错点：NUMA 与 pinned 不是「同一件事」

**辨析｜易错点：** 把「NUMA 感知」与「Pinned Memory」混为一谈。它们服务不同的问题：

- **NUMA 感知**：解决「CPU 访问自己内存（快）vs 对家内存（慢）」——**数据在 CPU 侧的远近**。
- **Pinned Memory**：解决「DMA 能否直达 vs 需要锁页拷贝」——**数据跨设备（PCIe）时的可达性**。

一个管「CPU 侧的远近」，一个管「跨设备侧的直达」——**一个水平、一个垂直**。NUMA 管「权重放哪颗 CPU 旁边」，pinned 管「结果从哪块内存经 PCIe 出去」。两者都是「让数据更快到位」，但作用在不同维度——**把两者分开理解，才能在排障时对症下药**：CPU 慢查 NUMA，跨设备慢查 pinned。

「对症下药」还可以再具体一点：**NUMA 错位的典型症状是「CPU 利用率低、但内存等待高」**（线程跑在 A 节点、数据在 B 节点）；**pinned 缺失的典型症状是「跨设备传输抖动、延迟忽高忽低」**（锁页-拷贝路径不确定）。两个症状不同，排查方向就不同——**「症状 → 维度 → 根因」的排查链，比「乱试」高效得多**。这也是为什么本专题强调「可度量的优化」：能区分症状，才能定位根因。

## 6 小结

把 NUMA 与 pinned 收成「两个维度、一句口诀」：**NUMA 管「CPU 侧远近」，pinned 管「跨设备直达」**——两者共同保证「数据就地、就近」到位。

- **NUMA 非均匀访问**：本地快、远端慢（1.5–2×），多路服务器尤其要防「错位」。
- **NUMA 感知分配**：算在哪、数据就在哪——按专家归属对齐节点，负载与容量按节点平衡。
- **Pinned Memory**：页锁定、DMA 直达，跳过「锁页-拷贝」；代价是固定物理页、不可换出。
- **有效带宽公式**：$BW_{\text{eff}} = B/t$，可分页路径有 $t_{\text{lock}}$ 开销，pinned 无——小传输场景优势最大。
- **解码热路径用 pinned**：专家结果回传恰好是「小 B、高频」，pinned 收益被高频放大。
- **两者分工**：NUMA 管水平（CPU 侧远近）、pinned 管垂直（跨设备直达）——症状不同，排查方向不同。
- **单 socket 看通道**：内存条数量与通道数决定带宽——「够大」不等于「够快」，带宽是 CPU 侧永恒的天花板。
- **带宽意识 > 具体机制**：NUMA、通道、pinned 都是「让带宽被有效利用」的手段——先有意识，再谈机制。

再补一句「从机制到意识」的收尾：NUMA 与 pinned 是两条具体的机制，但它们背后是同一个「带宽意识」——**数据必须就地、就近、直达地到位**。带着这个意识，你在任何新机器上都能立刻问出正确的问题：内存通道够吗？数据在哪个 NUMA 节点？跨设备走的是不是 pinned？**「机制会过时（新架构可能有新名字），意识不会（带宽永远是稀缺资源）」**——这正是本专题反复强调的「掌握方法论而非记忆参数」的又一次体现。
