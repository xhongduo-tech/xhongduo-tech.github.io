## 为什么 GPU 侧的内核「必须是 Marlin」

放置与调度把算子分好了家：Attention、共享专家、热专家都留在 GPU。但「留在 GPU」不等于「算得快」——GPU 上跑什么内核，决定了单次矩阵乘的实际效率。ktransformers 在 GPU 侧的王牌，是 **Marlin**——一个专为**4-bit 量化权重**设计的 GEMM 内核，能显著榨出 RTX 4090 的算力。

为什么 GPU 侧特别需要「专门内核」？因为 GPU 的编程模型与 CPU 差异巨大：数千个线程、warp 级同步、共享内存与寄存器的显式管理、Tensor Core 的特殊数据路径——**通用矩阵乘库（如 cuBLAS）为「全精度、任意形状」优化，无法为「4-bit + 特定形状」这种小众组合做极致特化**。Marlin 这类「为一种格式、一种场景写死」的专用内核，才是榨干硬件的方式。专用胜过通用，是高性能计算里反复出现的规律。<span class="marginnote">论文报告 Marlin 内核带来约 <strong>3.87×</strong> 的效率提升。它不是 ktransformers 发明的，而是来自 Frantar et al. 的开源工作（Marlin: A 4-bit GEMM kernel），ktransformers 把它集成进自己的注入框架。理解 Marlin，等于理解「量化权重如何在 GPU 上被高效计算」。</span>

## 1 量化 GEMM 的核心矛盾

量化矩阵乘的输入是：激活矩阵 $X$（通常 BF16/FP16）+ 量化权重 $W$（INT4 + 缩放因子）。朴素实现每算一次都要：

1. 把 INT4 权重**反量化**回浮点（解包 + 乘缩放）。
2. 做浮点矩阵乘。

问题：**解包与反量化在 GEMM 主循环里逐元素进行，会拖慢访存与计算**。INT4 权重在内存里是「两个数挤一个字节」，读取后要拆开；拆开后还要乘上 per-channel 的缩放因子——这些开销若摊进每一次乘加，GEMM 的算术强度优势就被稀释了。

把「朴素实现的浪费」算一笔账：假设一个 4-bit GEMM 里，反量化需要「拆字节 + 乘缩放」两步额外操作，而乘加本身只有一步——那么朴素实现里**每 1 次有用的乘加，要付出 2 次反量化开销**，有效吞吐最多打三折。这不是「慢一点」，是「数量级地慢」。Marlin 的全部技巧，都是为了把这两步「额外操作」从热循环里赶出去——要么移到循环外，要么藏进流水线。

**Marlin 的核心思路**：把「解包、反量化」与「乘加」**流水化**，并让权重布局匹配 GPU 的访存模式——用**软件流水**把权重加载、反量化与乘加重叠起来，让 Tensor Core 永远有活干。

「让 Tensor Core 永远有活干」这句话值得反复品味：GPU 峰值算力很高，但只有在「数据及时到位」时才能兑现。内核优化的所有技巧——布局、流水、展开——本质上都在解决一个问题：**如何让计算单元不被「等数据」打断**。这个视角也解释了为什么 Marlin 这类内核的优化重点不是「算得快」，而是「喂得饱」——算力本身就在那里，缺的是「持续供应数据」。<span class="marginnote">GPU GEMM 的瓶颈往往不是算力，而是<strong>喂不饱算力</strong>——数据没到位，Tensor Core 就空转。Marlin 的所有技巧，本质都是「让数据流水不断流」。</span>

## 2 布局：为 GPU 量身定做的权重摆放

Marlin 的第一个秘密在**内存布局**。权重不按「行优先」朴素存放，而是按**固定大小的 tile** 重排：

权重矩阵按组（group）组织，每组共享一个缩放因子（per-group quantization）。
组内的 4-bit 值被打包成 32-bit 整数存储——**一次读 32 bit = 8 个权重**，减少访存指令数。
- tile 的尺寸与 GPU 线程块、寄存器分配对齐，让每个线程负责连续、规整的一块数据。

这种布局的目标是**访存连续性**：GPU 的 memory coalescing 要求「同一 warp 的线程访问相邻地址」。Marlin 的布局保证线程读权重时地址连续，最大化每字节带宽的利用率。

Marlin 的 tile 尺寸也不是随便定的：它要同时满足几个约束——**寄存器容量**（tile 太大，寄存器放不下）、**warp 大小**（tile 要与 32 线程对齐）、**Tensor Core 形状**（tile 要与硬件矩阵单元的形状吻合）。这些约束交织在一起，决定了「每个 tile 是几乘几」。**内核设计本质上是在「多组硬件约束」之间找可行解**——这正是内核开发难、也最见功力的地方。

「访存连续性」的物理基础是 GPU 的缓存行与 DRAM 突发：一次缓存行加载 128 字节，只有「连续访问」才能让这 128 字节全部派上用场；不连续访问则每次只用到其中的一小段，带宽浪费严重。**布局优化的本质，是把「逻辑上相关的数据」摆成「物理上相邻的数据」**——这是一切高性能存储访问的共同法则，从 CPU 的 cache-line 到 GPU 的 coalescing，再到上一节讲过的 NUMA，都是它的变体。<span class="marginnote">反观朴素布局：权重按行存，量化打包后跨线程访问不连续，warp 的一次访存被拆成多次——带宽利用率掉一半以上。布局即性能，这在 GPU 内核里是铁律。</span>

## 3 反量化流水：把解包藏进计算

Marlin 的第二个秘密是**反量化流水**。它不再「每算一个元素就解包一次」，而是把循环展开成多级流水：

**加载级**：预取下一批 32-bit 打包权重到寄存器。
**反量化级**：把当前批权重解包、乘缩放因子，得到浮点值。
- **计算级**：浮点值与激活做乘加，喂给 Tensor Core。

三级用**循环展开 + 预取**重叠：计算当前批时，反量化级已在处理下一批、加载级已在取更下一批。这样，**解包的延迟被藏进乘加的计算时间里**，Tensor Core 不再等数据。<span class="marginnote">这就是「软件流水」（software pipelining）：把串行的「加载→反量化→计算」三级摊开重叠。Marlin 之所以在 4-bit 场景比通用 GEMM 库快近 4 倍，正是把反量化这个「额外负担」彻底藏住了。</span>

软件流水是「隐藏延迟」的经典技术，它背后的原理是**并行性与流水线**：只要各级之间没有数据依赖，就能重叠执行。这里的「没有依赖」来自 GEMM 天然的结构——第 $i+1$ 批权重的加载与第 $i$ 批的计算互不干扰。**把「串行的步骤」在空间上铺开、在时间上重叠，是内核优化的通用手法**——你在 CPU 指令流水线、网络协议栈、甚至工厂流水线上都能看到同一个思想：把「等待」变成「并行工作」。

顺带一提，「三级流水」的级数不是越多越好：级数越多，需要预取的缓冲越多（占用寄存器/共享内存），且启动的「排空延迟」越长。Marlin 选三级是「够用且不浪费」——它把反量化这级藏住了，再加深一级的收益就低于成本。**「藏住主要的延迟」即可，不必藏住所有延迟**——这是工程上的性价比判断，也是「三级」而非「六级」的原因。

## 4 公式解析：量化 GEMM 的分解

把一次 Marlin 内核做的事写成公式。对激活行 $x$ 与权重列 $w$（含 per-group 缩放 $s$、零点 $z$），量化权重反量化后参与点积：

$$
y = \sum_i x_i \cdot \big( (w_i^{\text{int4}} - z) \times s \big) = s \cdot \Big( \sum_i x_i \cdot w_i^{\text{int4}} \Big) - s \cdot z \cdot \sum_i x_i
$$

逐项拆解：

- **第一步**：反量化是线性的——「先反量化再乘」等价于「先乘再整体缩放」。
- **第二步**：于是主循环只需做**整数点积** $\sum_i x_i \cdot w_i^{\text{int4}}$（整数的乘加），缩放 $s$ 与零点修正 $s z \sum x_i$ 拖到最后统一处理。
- **第三步**：整数点积可以积累在 INT32 累加器里，最后一次性转换并缩放——**把每元素一次浮点乘，换成一次整数乘加 + 末尾一次缩放**。

**一句话**：Marlin 利用「量化是线性变换」这一性质，把昂贵的逐元素反量化**推迟到 GEMM 末尾**，主循环变成高效的整数点积。

这条公式还有一个「隐藏的精妙」：$s \cdot z \sum x_i$ 这一项里的 $\sum x_i$（激活行和）与权重无关，可以在**整个 GEMM 前**预计算一次，多个权重列共享；$s z$ 是每组的常数，也提前算好。于是「末尾缩放」实际上只是**两次向量乘法**（一次乘 $s$、一次减 $sz\sum x$）——代价极小。好公式的价值就在于此：**每一步都能被预计算吸收，热循环保持最简**。

把这条公式拆解出来的「整数点积 + 末尾缩放」结构，与 CPU 侧 INT4/INT8 推理（第 3 篇《INT4/INT8 量化权重在 CPU 端的推理》）完全同构——**GPU 与 CPU 在量化推理上共享同一套数学技巧**，区别只在硬件的实现方式（Tensor Core  vs VNNI 指令）。这是「同一思想、两套实现」的典型案例：理解了 Marlin，就理解了 CPU 侧量化内核的一半。

「线性性」是这一节最关键也最容易被忽略的数学前提。正因为反量化是线性运算（乘常数 $s$、减常数 $sz$），它才能与点积「交换顺序」——先整数点积、后整体缩放。若量化用的是非线性变换（比如某些非对称的非线性量化），这套「推迟反量化」的技巧就失效了。**量化算法的可线性性，决定了内核优化的空间**——这也是为什么主流量化（GPTQ、AWQ）都保持「仿射」形式：它们让硬件加速成为可能。<span class="marginnote">$\sum x_i$ 这一项（激活和）只依赖激活、与权重无关，可以提前算好复用；$s \cdot z$</span>
