## 为什么从「复用技巧」切入

上一节讲了 MTP 投机解码的机制与理论保障，这一节落到工程：**推理器里到底怎么把 MTP 头「接」进解码循环**。复用不是把训练模块原样搬来就完事——参数共享、KV Cache、算子调度、流水线编排，每个环节都有让加速翻倍的技巧，也都有让加速归零的坑。

## 1 复用的三个层面：参数、KV Cache、词表映射

MTP 头在推理时的复用，可以拆成三个互相独立的层面：

- **参数复用**：MTP 模块的 Transformer 块参数直接加载，不新增权重文件。主干的输出头同时当验证器——**一个头两用**。
- **KV Cache 复用**：MTP 模块有自己的自注意力，因此有自己的 KV Cache；但它只有一层，Cache 开销只占主干的一层份额。更重要的是，**草稿步不需要重新计算主干的 KV**——主干前向算出 $h_t$ 时 KV 已经就位，MTP 模块直接消费。
- **词表映射复用**：草稿分布与验证分布都用同一个共享输出头，省掉一套独立的词表投影。

<span class="marginnote">对照标准投机解码：独立草稿模型需要<strong>整套</strong> KV Cache、<strong>整套</strong>词表投影、<strong>整套</strong>参数。MTP 方案把这三大块全部压缩到「一层 Transformer 块」的量级——这是「复用」二字在显存与带宽上的真实含义。</span>

## 2 草稿-验证的流水线：γ=1 的编排

DeepSeek-V3 的 MTP 草稿长度取 $\gamma=1$，其解码循环可以精确描述为：

1. **主干前向**：给定当前上下文，主干算出 $h_t$（同时产出主模型的下一步分布，即验证基准）。
2. **草稿前向**：MTP 模块以 $h_t$ 与 $\text{Emb}(x_t)$ 为输入，算出一个草稿分布 $q(\cdot)$，采样得 $\hat{x}_{t+1}$。
3. **验证**：用共享输出头给出主模型对 $\hat{x}_{t+1}$ 的真实概率 $p(\hat{x}_{t+1})$，按 $\min(1, p/q)$ 接受或拒绝。
4. **推进**：接受则 $\hat{x}_{t+1}$ 成为新 token，主干与 MTP 的 KV 同步追加，进入下一步；拒绝则按修正分布重采样，回退。

**关键工程点：草稿步与验证步共享主干的 $h_t$**——草稿步只多算一个 MTP 块，验证步只多查一次输出头，两者都远小于主干的一层成本。<span class="marginnote">由于 $\gamma=1$，这里不存在「多草稿 token 的 KV 批量追加」复杂度——每一步只处理一个候选，流水线极简。这也是 DeepSeek 选 K=1 的另一个工程理由：<strong>草稿长度越短，接受/拒绝的簿记越简单，流水线越稳</strong>。</span>

## 3 算子级优化：让复用真正「免费」

推理加速的差距往往藏在算子层。MTP 复用的几个常见优化：

**融合草稿步**：MTP 块的 RMSNorm、融合加法、注意力、FFN 可以合并成少数 kernel，减少 kernel 启动次数与中间张量的显存往返。
**共享显存分配**：草稿分布与验证分布使用同一块输出缓冲，避免反复分配/释放。
- **KV Cache 预分配**：MTP 块的 KV Cache 与主干的 KV Cache 一并预分配，避免运行时动态扩容。
- **批处理重叠**：多个请求的解码可以交错——一个请求在「验证」时，另一个请求的「草稿」可以并发执行，隐藏彼此延迟。

**这些优化没有一项改变算法，但每一项都在削减「复用」身上的隐性成本**——复用模型是免费的，复用得好不好才是工程分水岭。<span class="marginnote">一个常见误区：以为「复用 MTP 头」=「推理零成本」。实际上草稿步仍要跑一个小 Transformer 块，验证步仍要多一次输出头查询——<strong>这些成本只是「小」，不是「零」</strong>。加速能否为正，取决于接受率带来的「少跑主干步数」能否覆盖「多跑 MTP 块」的开销。</span>

## 4 公式解析：加速比 = 少跑的 / 多花的

把推理加速写成收益与成本之比，是判断「复用值不值」的通用公式：

$$
\text{Speedup} \approx \frac{\gamma \cdot T_{\text{main}}}{\underbrace{T_{\text{main}} + T_{\text{draft}}}_{\text{草稿+验证}}}
$$

- **第一步，认符号**：$T_{\text{main}}$ 是主干一步前向的耗时（访存主导），$T_{\text{draft}}$ 是草稿步的额外耗时（MTP 块 + 输出头），$\gamma$ 是草稿长度。
- **第二步，看理想情形**：若 $\gamma=1$、草稿完美、验证与主干前向可复用，则分子 $1 \cdot T_{\text{main}}$，分母 $T_{\text{main}} + T_{\text{draft}}$，加速比约 $\frac{1}{1 + T_{\text{draft}}/T_{\text{main}}}$——**当 $T_{\text{draft}} \ll T_{\text{main}}$ 时，即使每步只多生成一个 token，也有接近 1× 的收益**。
- **第三步，引入接受率**：更真实的公式要乘以期望步长 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$
