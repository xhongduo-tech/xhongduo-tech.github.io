## 为什么从定义开始

上一节指出，单 Token 预测有两个效率痛点：推理时访存浪费，训练时样本只用一次。**多 Token 预测（Multi-Token Prediction, MTP）**就是对这两个痛点正面回应的训练范式。这一节先把它的定义钉死：模型到底「一次预测什么」「用什么结构预测」「为什么这样能成立」——这是理解后续所有架构细节与加速技巧的地基。

## 1 定义：不是「一步解码」，而是「一个输入配 K 个输出」

**多 Token 预测**：给定上文 $x_{<t}$，让模型同时预测接下来 K 个 token $x_t, x_{t+1}, \dots, x_{t+K-1}$，而不是只预测 $x_t$。<span class="marginnote">注意措辞的微妙差别：MTP 是「一个输入位置预测 K 个未来 token」，与「自回归地解码 K 步」不同——后者每步把新 token 接回输入，前者用<strong>一个固定的隐藏表示</strong>一次性产出 K 个预测。</span>

形式化地，模型不再是单个映射 $f: x_{<t} \mapsto \hat{x}_t$，而是

$$f: x_{<t} \mapsto \left(\hat{x}_t,\; \hat{x}_{t+1},\; \dots,\; \hat{x}_{t+K-1}\right)$$

**每一个预测头** $\hat{x}_{t+i}$ 都输出一个词表大小的分布。K 个预测可以来自同一个共享表示（Gloeckle 式的并联头），也可以来自逐层递进的结构（DeepSeek-V3 式的 MTP 模块）——**「同时预测多个未来 token」是共有的灵魂，「头怎么接」是流派的分野**。

## 2 核心思想：用「远期目标」倒逼「近期表征」

为什么多预测几步就能让模型变好？Gloeckle 等人给出一个很朴素却很深的直觉：**下下一个 token 是下一个 token 最好的「教师信号」之外的第二信号**。

- 只预测 $x_t$ 时，模型只要学到「主语之后常跟动词」这种**短程统计**就能取巧。
- 同时预测 $x_{t+1}$ 时，模型被迫回答「这个动词之后会跟什么」——它必须在表示里提前编排**计划**、**语法骨架**与**语义走向**，而这些正是推理、代码、数学这类长程任务真正需要的表征。

<span class="marginnote">论文里的一个实验佐证：把 K 从 1 增到 4，模型在 MBPP（代码生成）与 HumanEval 上的 pass@k 显著上升，而 GLUE 上的理解类任务基本持平——<strong>多步预测对「长程生成」的帮助远大于对「单步判断」的帮助</strong>，见第4篇《MTP 在推理与代码生成任务上的增益》。</span>

一句话概括：**MTP 用更远的监督，把模型的隐藏表示从「只顾当下」逼成「要管全局」。**

## 3 三种实现路线的分野

「同时预测 K 个 token」在工程上有三条实现路线，理解它们的差别，是后面所有章节的地图：

| 路线 | 结构 | 代表 | 特点 |
| --- | --- | --- | --- |
| **独立头** | 共享主干 + K 个并联输出头 | 早期多任务风格 | 简单，但各头看不到彼此的中间状态 |
| **递进头** | 每个头建立在上一头输出之上 | DeepSeek-V3 MTP 模块 | 表达力强，参数略增，推理可复用 |
| **双头推理** | 训练 MTP，推理时用它做投机采样 | DeepSeek-V3 | 训练范式直接转化为推理加速 |

**三条路线不是互斥的**：DeepSeek-V3 同时用了「递进头」（训练）与「双头推理」（加速）；Gloeckle 的方法则是「共享主干 + K 个独立头」的纯训练范式，主要红利在样本效率与表征质量。<span class="marginnote">关键区分是<strong>训练范式</strong>与<strong>推理加速</strong>：MTP 首先是一种训练目标；把它用于投机解码是后续工程化的一步，两者不要混为一谈——这正是《MTP 与单 Token 预测的本质差异》里要展开的辨析。</span>

## 4 公式解析：共享主干的 K 个预测头

Gloeckle 式的 MTP 目标可以写成一条清晰的式子：

$$
\mathcal{L}_{\text{MTP}}(\theta) = -\frac{1}{T} \sum_{t=1}^{T} \sum_{i=1}^{K} \log P_\theta\left(x_{t+i} \mid h_t\right)
$$

- **第一步，认符号**：$h_t$ 是主干 Transformer 在位置 $t$ 输出的隐藏表示（**所有头共用同一个**），$x_{t+i}$ 是第 $i$ 个未来 token，$T$ 是序列长度。
- **第二步，看求和**：外层对每个位置 $t$ 求和，内层对 K 个未来 token 求和——**同一个 $h_t$ 被 K 个监督信号复用**。标准下一 token 预测只是 $K=1$ 的特例。
- **第三步，看共享**：所有头共用 $h_t$，只各自接一个小型输出层（+ 可选的投影层）。于是**参数增加微小，而梯度信号翻 K 倍**——这就是 MTP「便宜的丰富」所在。
- **第四步，看极限**：当 $i$ 增大，预测 $x_{t+i}$ 越来越难（不确定累积），对应梯度噪声变大；因此实际 K 取 2–4 而非贪大，DeepSeek-V3 取 $K=1$
