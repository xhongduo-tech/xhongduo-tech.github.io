## 为什么从投机解码切入

第1篇反复强调：自回归解码是访存瓶颈——每生成一个 token 都要重读全部权重。**投机解码（speculative decoding）**是打破这一步一访存的经典思路：用一个便宜的草稿模型先猜 γ 个 token，主模型一次性并行验证。DeepSeek-V3 的特殊之处在于：**草稿模型不是另训的，而是把训练期的 MTP 模块直接拉来复用**。这一节拆开这个机制的完整链路。

## 1 投机解码的原理：草稿 + 验证

标准投机解码的工作流分三步：

1. **草稿**：用一个又小又快的草稿模型，从当前位置 $t$ 连续推测出 $\gamma$ 个候选 token：$\hat{x}_{t+1}, \dots, \hat{x}_{t+\gamma}$。
2. **验证**：主模型把这 $\gamma$ 个候选**一次性并行**算一遍，得到每个位置的真实分布 $p(\cdot \mid x_{\le t}, \hat{x}_{t+1}, \dots)$。
3. **接受/拒绝**：逐位比较草稿分布与主模型分布，接受一致的部分，在第一个不一致处按主模型分布重采样，然后**回退到不一致位置**继续。

<span class="marginnote">验证步是投机解码的加速核心：主模型一次前向处理了 γ 个 token，却只花了「一个 token 的访存量」——这正好对准第1篇《单 Token 预测范式的效率局限》的瓶颈公式。如果 γ 个草稿都被接受，<strong>一步就生成了 γ 个 token</strong>，访存被摊薄 γ 倍。</span>

**关键：投机解码不改变输出分布**——只要拒绝时按正确的方式重采样，最终样本分布与标准自回归完全一致。这是它能放心用的理论保障。

## 2 MTP 如何充当草稿：训练架构的直接复用

DeepSeek-V3 的草稿模型来自训练期的 MTP 模块。复用成立的前提，是 MTP 模块训练时就在学「吃一个 token，猜一个 token」：

$$
\hat{x}_{t+1} \sim \text{MTP\_Module}\!\left(h_t,\; x_t\right)
$$

推理时的角色分配：

| 组件 | 训练时的角色 | 推理时的角色 |
| --- | --- | --- |
| 主干（前 $L$ 层） | 编码前文 | 计算 $h_t$（草稿的输入之一） |
| MTP 模块 | 辅助预测头 | **草稿模型**：猜 $\hat{x}_{t+1}$ |
| 主输出头 | 主 CE 预测 | **验证器**：给 $\hat{x}_{t+1}$ 打分 |

**这个复用免去了训练独立草稿模型的全部成本**——草稿模型的参数在训练时已经和主干联合优化好了。<span class="marginnote">对比标准投机解码：它需要一个比主模型小得多、又足够准的草稿模型，训练这个草稿本身就是一大笔开销，还要保证它与主模型的「默契」。MTP 方案里草稿与主干共享训练、共享词表映射，「默契」是天然形成的。</span>

## 3 接受与拒绝：无损的采样规则

草稿提出 $\hat{x}_{t+1}$，主模型给它的真实概率是 $p(x = \hat{x}_{t+1} \mid \text{context})$。接受的规则采用**保分布的重采样**：

$$
\text{接受概率} = \min\!\left(1,\; \frac{p(\hat{x}_{t+1})}{q(\hat{x}_{t+1})}\right)
$$

其中 $q$ 是草稿分布，$p$ 是主模型分布。**这个公式保证：接受与否的联合决策，等价于直接从 $p$ 采样**——草稿猜得越准（$q$ 接近 $p$），接受率越高，加速越多；草稿猜错了，就以 $1 - p(\hat{x}_{t+1})$ 的概率拒绝并按修正分布重采样，保证分布无损。

<strong>辨析｜易错点：</strong>「接受率」不等于「正确率」。草稿可能给出一个主模型也认为很可能的 token（两者都认为它概率高），但采样时主模型本来就可能抽到别的 token。**接受率衡量的是「草稿与主模型分布的重合度」，而非「草稿是否猜中最终采样结果」**——这是读投机解码论文时最常见的误解。<span class="marginnote">DeepSeek-V3 的 MTP 草稿接受率处于「比随机小模型高、比专用草稿模型不差」的位置——因为它与主干共享表征，天然了解主模型的「口味」。具体接受率数值见下一节《接收率提升与延迟收益分析》。</span>

## 4 公式解析：期望步长与接受率

投机解码的加速效果可以用**期望步长（expected tokens per step）**衡量。设草稿每步接受概率为 $\alpha$，草稿长度 $\gamma$，则期望每步生成的 token 数为

$$
\mathbb{E}[\text{tokens/step}] = \frac{1 - \alpha^{\gamma+1}}{1 - \alpha}
$$

- **第一步，认变量**：$\alpha$ 是单步接受率（草稿分布与主模型分布的重合度），$\gamma$ 是草稿长度。
- **第二步，读分子**：$1 - \alpha^{\gamma+1}$ 表示「在连续 $\gamma$ 个候选里至少被拒绝一次之前」的几何分布概率质量。$\alpha$ 越接近 1，这个和越接近 $\gamma+1$。
- **第三步，看极限**：若 $\alpha = 1$（草稿完美），期望步长 $= \gamma+1$，一步生成全部候选；若 $\alpha \to 0$（草稿瞎猜），期望步长 $\to 1$，投机解码退化为标准自回归。
- **第四步，落 DeepSeek-V3**：DeepSeek 取草稿长度 $\gamma = 1$（一个 MTP 模块预测一个 token）。代入公式，只要单步接受率 $\alpha$ 高于「1 / 主模型前向成本比」，MTP 投机解码的净收益就为正——**MTP 模块极便宜（一个小块），所以即使 $\alpha$ 不算极高，加速依然成立**。

## 5 小结

- 投机解码 = **草稿 + 并行验证 + 保分布重采样**，不改变输出分布。
- DeepSeek-V3 用 **MTP 模块当草稿模型**，免去独立草稿训练，与主干天然默契。
- 接受规则 $\min(1, p/q)$ 保证分布无损；**接受率衡量分布重合度，不是正确率**。
- 期望步长 $= (1-\alpha^{\gamma+1})/(1-\alpha)$
