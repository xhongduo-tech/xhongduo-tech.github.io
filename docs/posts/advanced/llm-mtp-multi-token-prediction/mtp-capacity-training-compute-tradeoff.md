# 模型容量与训练时长的权衡

<div class="epigraph">
<p>预算从来不变，变的是钱花在哪里——是花在更大的模型上，还是花在更久的训练上。</p>

</div>

## 为什么从权衡切入

预训练的黄金法则是 Chinchilla 式的**计算最优**：给定算力预算，模型大小与训练 token 数要匹配。MTP 的出现改写了这条等式的某一侧——它把「每个 token 的信息利用率」提高了。于是问题来了：**同样的算力预算，MTP 应该让你把模型做大，还是把训练跑短？** Gloeckle 2024 §5 用系统的规模实验回答了这个问题，结论对工程决策极其重要。

## 1 预算守恒：同样的 FLOPs，两种花法

设总计算预算为 $C$（FLOPs），粗略地有

$$C \approx 6 \cdot N \cdot D$$

其中 $N$ 是模型参数量，$D$ 是训练 token 数（$6ND$ 是经典的前向+反向 FLOPs 估计）。**预算守恒意味着 $N$ 与 $D$ 只能此消彼长**——大模型就得少训些 token，反之亦然。

MTP 的独特之处在于它几乎不改变 $C$（K 个头只占主干 1%–3% 参数），却把每个 token 的监督信号变多。**它让「花同样的 FLOPs」买到「更高的数据利用率」**，相当于在 $C$ 不变的前提下撬动了 $D$ 的「有效值」。<span class="marginnote">这正是 MTP 与「加大模型」的本质区别：加大模型动的是 $N$，MTP 动的是「$D$ 的有效性」。两者不冲突，可以叠加——但理解它们各自撬动的是哪一头，才谈得上权衡。</span>

## 2 规模效应：为什么大模型从 MTP 受益更多

Gloeckle 2024 §5 最值得注意的实验结果是**规模效应的方向**：MTP 相对于单 Token 的收益**随模型规模增大而扩大**，而不是缩小。

小模型上，MTP 与单 Token 的差距很小——小模型容量有限，多步监督的「规划能力」无处安放。
模型越大，MTP 的收益越明显——大模型有足够的容量去利用远期监督，把「提前编排」变成真实的表征能力。

<span class="marginnote">直觉：MTP 给的是「更难的题」（预测远期），小模型做不动，差距小；大模型做得到，差距立刻拉开。这解释了为什么 MTP 在 DeepSeek-V3（671B）这种超大模型上被工业级采纳——<strong>规模越大，MTP 越值</strong>。</span>

**工程含义**：如果你的模型只有几亿参数，MTP 带来的增益有限，不值得为其引入额外的训练复杂度；如果模型在数十亿参数以上，MTP 的收益开始显著，值得认真考虑。

## 3 数据效率的量化：同等质量，更少 token

另一个视角是**以终为始**：为了达到同一个下游指标，MTP 需要多少训练 token？

| 目标 | 单 Token 所需 token | MTP（K=4）所需 token | 相对节省 |
| --- | --- | --- | --- |
| 达到某代码基准分数 | $D$ | 约 $0.5D–0.7D$（实测随任务波动） | 约 30%–50% |
| 达到某数学基准分数 | $D$ | 同样显著减少 | 视任务 |
| 通用语言理解 | $D$ | 接近持平 | 几乎无 |

**「数据效率提升」不等于「训练变快」**——这两者需要严格区分：<strong>辨析｜易错点：</strong>MTP 的每步计算比单 Token 多（K 个头的前向/反向），所以**单位步数的速度反而变慢**；它省的是「达到同等质量所需的总步数」。最终是赚是亏，取决于「每步多花的计算」与「少跑的步数」谁大——这正是本节的权衡核心。<span class="marginnote">DeepSeek-V3 的账是这么算的：MTP 增加的训练开销（一个稠密 Transformer 块）约 1% 上下，而训练侧换来的表征红利 + 推理侧白得的草稿模型，让这笔「1% 的投资」回报远大于成本——这是工业决策的典型框架。</span>

## 4 公式解析：计算最优点的移动

Chinchilla 式的分析试图找到「给定 $C$，最优 $(N^*, D^*)$」。MTP 通过提升数据有效性，把「等量数据带来的收益」曲线抬高，从而**移动最优点**：

$$
\min_{N, D} \; \mathcal{L}(N, D) \quad \text{s.t.} \quad 6ND = C
$$

- **第一步，认框架**：在固定预算 $C$ 下，找一个模型大小 $N$ 与训练 token 数 $D$ 的组合使最终损失最小。
- **第二步，看 MTP 改了什么**：MTP 不改约束 $6ND=C$，但改了损失函数 $\mathcal{L}$ 对 $D$ 的依赖——同等 $D$ 下，MTP 的损失更低（数据利用率高）。因此对每个 $N$，MTP 都能用更少的 $D$ 达到同样的 $\mathcal{L}$。
- **第三步，读新均衡**：因为「$D$ 的有效性」提高了，最优配置倾向于**把预算更多地挪向 $N$**（模型做大）、相对少花在 $D$ 上——MTP 让你在同样预算下「更有底气把模型做大」。
- **第四步，落实践**：这个分析是方向性的，具体最优点依赖实测 scaling curve。工程上的落地顺序是：先测小规模 scaling，外推估计最优 $N$，再在预算内决定 $D$——MTP 让「外推出来的最优点」整体向更大 $N$ 偏移。

## 5 小结

- 预算守恒 $C \approx 6ND$：MTP 撬动的是「$D$ 的有效性」，加大模型撬动的是 $N$。
- **规模效应**：模型越大，MTP 相对单 Token 的收益越显著。
- **数据效率**：达到同等质量，代码/数学任务上 MTP 可省约 30%–50% token；通用语言基本持平。
- MTP 每步计算更贵但总步数更少——**「变快」是净效果，取决于具体账本**。
- 计算最优视角：MTP 把预算配比推向「更大 $N$、更少 $D$
