## 为什么从「接受率」切入

投机解码的理论很漂亮，但它所有收益都压在一个数字上：**接受率（acceptance rate）**——草稿 token 被主模型认可的比例。接受率低了，期望步长趋近 1，一切加速化为泡影。这一节先讲清接受率由什么决定、MTP 草稿为什么天然接受率高，再量化它带来的延迟与吞吐收益。

## 1 接受率的决定因素：分布重合度

回顾接受概率 $\min(1, p(\hat{x})/q(\hat{x}))$，它在**统计上**等于两个分布的相似度。接受率不是「猜中率」，而是**草稿分布 $q$ 与主模型分布 $p$ 的重合度**：

$$
\mathbb{E}[\text{accept}] = \sum_{x} \min\!\left(p(x),\, q(x)\right)
$$

- 若 $q = p$，右边求和 $= \sum_x p(x) = 1$，接受率 100%。
- 若 $q$ 与 $p$ 相差越大，$\min$ 越被拉低，接受率越低。

**接受率的三个实际决定因素**：

1. **草稿模型与主模型的「默契」**——两者表征越接近，分布越重合。
2. **草稿长度 $\gamma$**——预测越往后越难，接受率随位置衰减。
3. **采样配置**——温度、top-p 会同时改变 $p$ 与 $q$ 的形状，影响重合度。<span class="marginnote">有一个很反直觉的事实：<strong>把草稿分布 $q$「调准」比「调尖」更重要</strong>。一个自信但错误的草稿（尖而不准）会让 $\min(p,q)$ 很小；一个保守但贴合的草稿反而接受率高。投机解码追求的不是「草稿更有主见」，而是「草稿更懂主模型」。</span>

## 2 为什么 MTP 草稿天然高接受率

MTP 草稿的接受率优势来自它的**出身**——它不是独立训练的旁路模型，而是与主干共享表征的「分身」：

**共享隐藏表示**：草稿步吃的是主干刚算出的 $h_t$，草稿与主模型的「视角」从同一个表示出发，分布天然趋近。
**共享词表映射**：草稿分布与验证分布走同一个输出头，「语言出口」完全一致，消除了两个模型词表分布的系统性偏差。
- **联合训练**：MTP 模块的训练损失里有主 CE 的成分（通过主干梯度），它从一开始就被训练成「猜主模型之所想」。

<strong>辨析｜易错点：</strong>「共享表征」既带来了高接受率，也限制了草稿的**多样性**。独立草稿模型可能提出主模型没想到的 token（牺牲接受率换取探索）；MTP 草稿只会提主模型「自己也大概率会选」的 token。**MTP 的定位是「高接受率、低探索」**——这恰恰是投机解码最需要的性格，因为投机解码只认「接受」，不奖励「惊喜」。<span class="marginnote">这也是为什么 DeepSeek-V3 不需要额外的「接受率提升」技巧（如动态温度）：共享表征已经把接受率推到足够高，剩下的只是把 $\gamma$ 调到收益最大化的点。</span>

## 3 延迟收益分析：从 TPOT 到吞吐

投机解码改善的核心指标是 **TPOT（time per output token，每输出 token 耗时）**。标准自回归的 TPOT 约等于主干一步前向耗时 $T_{\text{main}}$；引入 MTP 草稿后，每步可能产出多个 token：

| 指标 | 标准自回归 | MTP 投机解码 |
| --- | --- | --- |
| 每步主模型前向数 | 1 | 1（验证）+ 草稿步（小） |
| 期望每步产出 token | 1 | $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$ |
| TPOT | $T_{\text{main}}$ | $\approx T_{\text{main}} / \text{期望步长}$ |

DeepSeek-V3 技术报告与公开评测普遍显示，MTP 投机解码把生成速度提升到约 1.8× 量级——即同样的硬件上，单位时间生成的 token 数明显增加，TPOT 相应下降。<span class="marginnote">注意 TPOT 下降不直接等于「首 token 延迟（TTFT）下降」——TTFT 由 prefill（预填充）决定，投机解码主要优化 decode（解码）阶段。所以 MTP 加速的典型特征是：<strong>首 token 等待不变，后续 token 节奏变快</strong>，长输出场景收益最大。</span>

**收益随场景分布**：输出越长，decode 阶段占比越高，MTP 加速的绝对收益越大；短问答（一问一答）场景，prefill 占主导，加速被稀释。

## 4 公式解析：端到端延迟模型

把 prefill 与 decode 都纳入，端到端生成延迟可以写成一个清晰的模型：

$$
T_{\text{total}} = \underbrace{T_{\text{prefill}}}_{\text{首 token}} + \underbrace{\frac{M}{s} \cdot t_{\text{step}}}_{\text{后续 token}}
$$

- **第一步，认符号**：$M$ 是待生成的 token 总数，$s$ 是期望步长（投机解码的每步产出），$t_{\text{step}}$ 是单步耗时，$T_{\text{prefill}}$ 是预填充阶段（处理输入上下文）耗时。
- **第二步，看 $s$ 的贡献**：标准自回归 $s=1$，$M$ 个 token 要 $M$ 步；MTP 投机解码 $s = \frac{1-\alpha^{\gamma+1}}{1-\alpha} > 1$，把步数压缩。
- **第三步，看边界**：当 $M$ 很大，$T_{\text{prefill}}$ 被摊薄，总延迟几乎由 $\frac{M}{s}t_{\text{step}}$ 决定——**输出越长，$s$ 的提升越值钱**。
- **第四步，看结论**：延迟收益 = 期望步长 $s$ 的提升，减去草稿步的额外开销 $T_{\text{draft}}$。只要 $s \cdot T_{\text{main}} > T_{\text{main}} + T_{\text{draft}}$，净收益为正——MTP 草稿的「小开销 + 高接受率」让这个不等式很容易成立。

## 5 数值算例：长输出 vs 短问答

把延迟模型填上数字。设 $T_{\text{prefill}} = 0.05$ 秒、$t_{\text{step}} = 0.02$ 秒、MTP 期望步长 $s=1.8$：

**场景一：长报告（$M=2000$）**

- 标准自回归：$0.05 + 2000 \times 0.02 = 40.05$ 秒。
- MTP 投机解码：$0.05 + \frac{2000}{1.8} \times 0.02 \approx 22.3$ 秒。
- **节省约 44%**——decode 主导，加速充分兑现。

**场景二：短问答（$M=20$）**

- 标准自回归：$0.05 + 20 \times 0.02 = 0.45$ 秒。
- MTP 投机解码：$0.05 + \frac{20}{1.8} \times 0.02 \approx 0.27$ 秒。
- 节省约 40% 但绝对量只有 0.18 秒——**收益比例相近，绝对收益很小**，且 prefill 占比更高时稀释更明显。

**结论**：MTP 加速是「长输出专用放大镜」——输出越长，decode 占比越高，加速收益越实在；短问答场景里收益被 prefill 摊薄，这也是为什么部署时要按场景决定是否开启。

<strong>辨析｜易错点：</strong>「吞吐翻倍」不等于「每个用户的延迟减半」。多用户共享 GPU 时，投机解码把算力从「等待内存」挪回「实际计算」，服务的是**整体吞吐**；单个用户感知到的延迟改善可能小于吞吐提升。**读评测数字前先分清它报的是吞吐还是单用户延迟**。

## 6 收益场景对照表

| 场景 | decode 占比 | MTP 加速收益 | 建议 |
| --- | --- | --- | --- |
| 长文档生成 | 极高 | 最大（可省 40%+） | 必开 |
| 代码补全 | 高 | 显著 | 推荐 |
| 中长对话 | 中 | 中等 | 按需 |
| 短问答 | 低 | 被 prefill 稀释 | 可关 |
| 首 token 敏感（TTFT） | — | 无帮助 | 投机解码不治 TTFT |

**一句话**：MTP 加速的价值随「输出长度 / 输入长度」的比值上升而上升——选场景，再开开关。

## 7 延伸：TPOT 与 TTFT 的分工

接受率与加速都作用在 decode 阶段，但延迟有两个组成部分，分工要分清：

- **TTFT（首 token 延迟）**：由 prefill（处理输入）决定，与投机解码无关。
- **TPOT（每输出 token 耗时）**：由 decode 决定，是投机解码的主战场。

**MTP 加速的是 TPOT，不是 TTFT**——对「要等首 token 很久」的服务，投机解码帮不上忙；对「生成长文本很慢」的服务，它正好对症。读评测时先看它报的是哪个指标，再判断对你的场景有没有用。

## 8 小结

- 接受率 = **草稿分布与主模型分布的重合度** $\sum_x \min(p,q)$，追求「贴合」而非「自信」。
- MTP 草稿天然高接受率：**共享隐藏表示、共享词表映射、联合训练**三管齐下。
- 加速优化的是 **TPOT**（每输出 token 耗时），TTFT 由 prefill 决定、基本不变。
- 输出越长，decode 占比越高，MTP 加速的绝对收益越大。
- 端到端延迟模型 $T_{\text{total}} = T_{\text{prefill}} + \frac{M}{s}t_{\text{step}}$：期望步长 $s$ 是唯一可撬动的杠杆。
