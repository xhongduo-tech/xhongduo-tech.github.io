# 推理算法与服务实验

## 问题

围绕一种模型和代表性负载，解释解码、缓存、并行或调度怎样影响质量与运行代价。从一个问题开始，逐渐连接系统。

## 计划交付

- 模型、框架、硬件、数据与生成参数的固定版本。
- 自回归或当前稳定配置的合理基线。
- 一个机制或系统因素的受控对照，以及失败定位。
- 质量、延迟、吞吐、内存与适用范围的报告。

投机解码、MTP和DSpark依赖先修主题；先做CPU机制验证，再按实际资源评估匹配硬件。当前没有个人实测数据或性能提升结论。

## 第一轮机制实验

1. 在两词表上算清普通采样与投机接受/校正的输出分布，再做采样检查。
2. 画出MTP不同深度的标签偏移，分清训练信号、草稿和目标验证。
3. 参考DSpark与DeepInfer固定版本，检查给定预算的前缀分配约束，复算选择偏差反例。
4. 追踪一步DeepInfer的引擎、worker、验证与采样状态，标出公开实现边界。

每次完成一个问题再推进下一个；源码解释、机制实验与硬件性能分别验收。具体前提和资料见各专题页。
