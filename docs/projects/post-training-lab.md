# 偏好优化与后训练实验

## 问题与前置

偏好优化究竟改善了任务表现，还是只学到长度、格式或裁判偏好？进入前需要[SFT与重载](/projects/finetuning-lab)可复现、开发/测试隔离可信，并能计算目标token的序列log概率。

## 实验路径

| 阶段 | 核心工作 | 验收 |
| --- | --- | --- |
| 偏好数据 | 同一prompt的chosen/rejected、依据、歧义与噪声；按prompt/source分组切分 | 标注规范、人工复核与反例 |
| 目标正确性 | 参考策略、策略概率比、β、序列长度与mask | 手算/CPU小batch目标与参数更新检查 |
| 有界DPO | 固定SFT初始化、参考设置、数据与训练预算 | 配置、日志、检查点与重载 |
| 偏差诊断 | 正确性、长度/格式、拒答及任务外保留能力 | SFT/DPO配对对照、反例和退化切片 |
| 联合回归 | checkpoint回到原服务与质量协议 | 质量、延迟、资源与实际成本 |

目标、数据约定与第一方资料见[偏好优化](/training/preference-optimization)。训练loss或偏好训练集胜率不能代替隔离评测；使用模型裁判时另外检查顺序、冗长和自偏好等偏差。

## RL何时进阶

完成DPO不等于完成在线RL。进入前需要rollout可追溯、验证器有反作弊检查、独立质量集、能解释优势与策略更新，以及明确的资源/时长/费用上限。参见[RL、推理能力与蒸馏](/training/rl-training)。

先做可验证奖励的反例与CPU目标实验；只有条件满足才进行真实策略更新。PPO、GRPO与RLVR分别按算法和奖励来源理解；单独运行reward脚本不记为RL训练。蒸馏数据的教师、采样与筛选规则另记，不声称学生复现教师的同样训练过程。

## 验收与当前状态

需要偏好依据、真实DPO记录、SFT与DPO的隔离对照、至少一个偏差或退化分析，以及部署回归。本人能修改一项规则并定位问题，保留AI协作与未解问题。

当前数据、训练与对照均待实践，不预设提升结果。
