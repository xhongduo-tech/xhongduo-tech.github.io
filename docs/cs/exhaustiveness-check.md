# 穷尽性检查

<div class="epigraph">
<p>若存在一个值，使得所有子句都失败，则匹配不穷尽。无用子句是永远被前面挡住的模式。二者都可在构造子有限时判定。</p>
<footer>—— 据 Maranget, Warnings for Pattern Matching, 2007；Peyton Jones 等 GHC 诊断；Pierce 对 case 穷尽的讨论整理</footer>
</div>

上一课[模式匹配编译](/cs/adt-pattern-compile)把子句变成判定树。缺口是**静态诊断**：没写 `Nothing`、或 `x::_` 挡住了后面的 `[]`。Maranget 用「反例值」与矩阵的有用性。本课钉检查，不重写分派代码生成。

## 问题

编译判定树时，默认边若到达「无子句」则运行时失败（ML 的 `Match` 异常）。语言可拒绝不穷尽，或警告。算法：在子句矩阵上求是否存在向量 $v$ 逃过所有行；若存在，pretty-print 成模式当反例。无用行：去掉该行后覆盖不变。缺口是**覆盖关系**，不是词法。

与[子类型](/cs/subtyping-variance)：开世界（可另编译新子类）不能穷尽；ADT 闭世界可以。OOP 的 visitor 穷尽靠密封类或默认方法。<span class="marginnote">术语翻译：穷尽性检查就是用「找一个能绕过所有分支的值」的手段来做「判断 match 是否漏了分支」的事——找不到这样的值，才算穷尽。所以它的输出往往是反例，而不只是「通过/不通过」。</span>

### 警告不是健全性定理

忽略警告仍可生成代码。依值类型里「穷尽」更强，后课点名。此处是代数数据类型上的模式覆盖。

<span class="marginnote">Maranget 2007（JFP）。GHC `-Wincomplete-patterns`。本课不把 SMT 当穷尽引擎，尽管守卫里的布尔可用求解器辅助。</span>

## 方法

空类型、空构造子、通配。递归：按列展开构造子，对每个构造子形成子矩阵。反例：沿失败边收集构造子前缀。守卫：保守当「可能失败」，故带守卫的子句不贡献穷尽——除非语言另有分析。

```mermaid
flowchart TD
  M["子句矩阵"] --> U["有用性"]
  U --> EX["反例值或穷尽"]
  U --> RED["无用子句"]
```

与错误恢复：不穷尽是类型/模式层诊断，不是语法 `error` 记号。<span class="marginnote">数字实例：对 `type t = A | B`，若两个构造子的分支都没写，编译器会把 `A`、`B` 两个反例都列出来；只漏 `A` 时就只报 `A`。反例精确指出该补哪一枝，而不是笼统甩一句「不穷尽」。</span>

## 机制

指数：构造子笛卡尔积。实用：按列剪枝、共享。记录模式、或模式（or-pattern）是覆盖的糖。可变与并发不在覆盖里：值在匹配中途被改是内存模型，后课。

```mermaid
flowchart TD
  A["输入：子句矩阵"] --> B{"首列是什么？"}
  B -->|"通配符"| C["删去该列与对应行"] --> R["递归判定剩余矩阵"]
  B -->|"构造子"| D["按该类型每个构造子展开成子矩阵"] --> E["各子矩阵分别递归"]
  R --> F{"逃逸路径全被堵死？"}
  E --> F
  F -->|"是"| G["判定穷尽"]
  F -->|"否"| H["输出反例：拼接构造子前缀"]
```

<span class="marginnote">直觉类比：可以把它想象成安检演练——每一行模式是一扇门，编译器扮演「千方百计想溜进去的入侵者」；只要还存在一条没人拦的路，演练就报警，并把那条路线画给你看，这条路线就是反例值。</span>

不要用「加一个 `_`」当唯一建议而不展示反例；反例才教人补哪一枝。

## 边界

本课不写 GADT 细化后的不可达模式全文。后课默认：闭 ADT 可查穷尽与无用。下一课依值类型：穷尽可依赖值，检查变成证明。

也不把 Prolog 的子句搜索当穷尽性。

## 小结

- 穷尽 = 不存在逃逸值；无用 = 覆盖不变。
- 闭的构造子世界可判定；开世界不能。
- 守卫使检查保守。
- 出处：Maranget, 2007；对照 Augustsson；Pierce TAPL case。
