# Merkle–Damgård

<div class="epigraph">
<p>把固定长压缩函数迭代起来，吃掉任意长消息：Merkle–Damgård 给 MD5、SHA-1、SHA-2 这族骨架。碰撞安全可从压缩函数归约，但也带上长度扩展这份遗产。</p>
<footer>—— Merkle, 1979；Damgård, A Design Principle for Hash Functions, CRYPTO 1989</footer>
</div>

上一课[填充预言](/cs/padding-oracle)关掉解密错误通道。密码学哈希在主干[哈希与碰撞](/cs/hash-collision)已有三条性质。缺口是**构造**：压缩函数如何接成长消息哈希，以及填充规则为何变成后课 HMAC 的理由。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

压缩函数 $h:\{0,1\}^{n+b}\to\{0,1\}^n$ 只吃一块。MD：把消息分块，链上链接值 $IV$，最后一块含长度。若 $h$ 抗碰撞，则迭代后的 $H$ 也抗碰撞（在填充得当时）。缺口是这条归约，以及链上状态泄漏带来的长度扩展——不是再定义原像。

### MD5/SHA-1 已不当碰撞哈希

骨架仍值得学，因为 SHA-2 还在用它。碰撞已被找到的算法只当反例。

<span class="marginnote">Damgård CRYPTO 1989。长度填充是归约的一部分：不同长度不能默默撞进同一链。本课不给碰撞搜索程序。</span>

## 方法

画 IV → 压缩 → 压缩 → 输出。写长度填充的动机。指出 SHA-256 仍是 MD；SHA-3 不是。下一课海绵。

<span class="marginnote">数字实例：SHA-256 块长 512 位。消息 447 位时补一个 1、再接 64 位长度，正好一块；448 位时塞不下，要整块填充、凑成两块。这就是「最后一块含长度」的具体含义：不同长度的消息不会默默撞进同一条链。</span>

```mermaid
flowchart LR
  IV["IV"] --> C1["压缩 h"]
  M1["块 1"] --> C1
  C1 --> C2["压缩 h"]
  M2["块 2"] --> C2
  C2 --> OUT["摘要"]
```

## 机制

签名与承诺吃的是 $H(m)$。MD 让 $H$ 可流式更新。链上链接值等于「内部状态」；若敌手知道 $H(m)$ 且 $H$ 是裸 MD，状态可被继续压缩——这是长度扩展，下一课用 HMAC 关。

<span class="marginnote">术语翻译：长度扩展就是「拿到 $H(m)$ 且不知道 $m$，也能算出 $H(m \,\|\, \text{任意后缀})$」——因为链上链接值本身就是内部状态，敌手可以从这个状态直接续链。把裸 MD 哈希当 MAC 用会中招，HMAC 是封住它的标准做法。</span>

<span class="marginnote">直觉类比：压缩函数像一台固定口径的绞肉机，一次只吃一小块、吐出固定大小的一团；MD 构造就是把上一团和下一块肉一起再塞回去，最后吐出的那团就是整条消息的摘要。</span>

```mermaid
flowchart LR
  H["敌手拿到 H(m) 与 len(m)"] --> GLUE["把 H(m) 当作新链的内部状态"]
  GLUE --> APP["继续压缩后缀并按 len(m) 补填充"]
  APP --> H2["不用知道 m 也得到 H(m 拼后缀)"]
  H2 --> FIX["HMAC 内外夹密钥即可封住"]
```

## 边界

本课不证全部填充变体，不把 Keccak 提前讲完。海绵结构下一课换掉「链上状态即摘要」这一条。

## 小结

- 主动加密预言之后，回到哈希骨架。
- MD：压缩函数迭代 + 长度填充。
- 碰撞归约成立，长度扩展是遗产。
- SHA-3 海绵是下一种结构。
- 出处：Merkle；Damgård, 1989；对照 NIST SHA-2。
