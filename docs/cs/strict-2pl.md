# 严格与强严格 2PL

<div class="epigraph">
<p>严格 2PL 把写锁留到提交，堵住脏读与级联回滚；强严格连读锁也留到提交，调度成为可恢复的严格串行。</p>
<footer>—— 据 Eswaran et al.；Bernstein 对严格 2PL；Gray and Reuter</footer>
</div>

[上一课](/cs/two-pl)给出增长/收缩两阶段，保证冲突可串行。本课不重画锁点。缺口是收缩太早：写锁在提交前释放，别人读到未提交值，然后你回滚——级联。严格：直到结束才放写锁。强严格（SS2PL）：读写锁都留到结束。MVCC 下一课对照读为何可不加锁。

## 问题

2PL 课留下「严格 2PL 顺带挡住脏读」。需要钉术语。可恢复调度：若 i 读了 j 的写，j 必须先提交。级联回滚：j 撤则 i 也要撤。严格 2PL 通过「提交前不放 X 锁」得到可恢复且无级联。强严格再推迟 S 锁，便于提交序与锁点一致。缺口是**锁释放时机相对提交点**。

<span class="marginnote">级联回滚翻译成白话：你读了我没提交的数，我反悔（回滚），你的计算就建立在凭空数据上，也只能跟着反悔——一个回滚拖着别人一起滚。严格 2PL 让「未提交的写」根本读不到，级联链条从源头断掉。</span>

<span class="marginnote">生产系统几乎都用严格或更严，很少在收缩阶段提前放写锁。死锁概率上升是代价，后课检测。</span>

## 方法

事务提交/中止时一次性释放。隔离级别若允许提前放 S 锁，会换来不可重复读——后课级别表。本课只钉严格族与 2PL 的关系：严格 2PL ⊂ 2PL，仍可串行，且可恢复。

<span class="marginnote">数字实例：一个事务执行 10 ms、第 8 ms 提交，严格 2PL 下写锁要持到第 10 ms 才放——锁持有时间约等于事务全长；收缩阶段提前放锁能把最后 2 ms 让给别人，但换来的可能是一整条级联回滚。</span>

```mermaid
flowchart TD
  TWO["2PL 可串行"] --> ST["严格: 写锁留到提交"]
  ST --> SS["强严格: 读锁也留到提交"]
  ST --> REC["可恢复、无级联"]
```

## 机制

写锁持有到提交，使 wr 边的源头必已持久或尚未被读。这与 [WAL](/cs/wal) 配合：未提交写可以 steal 到页上，但别人读不到（锁），UNDO 不必追读者。读锁提前放则允许 rw 在提交前发生，可串行仍可能，重复读不保证。

```mermaid
flowchart TD
  T1["事务 T1：写 x"] --> H["持有 X 锁继续运行"]
  T2["事务 T2：读 x"] --> W["被 X 锁阻塞等待"]
  H --> C["T1 提交：锁一次性释放"]
  W --> C
  C --> R["T2 读到已提交值：无脏读、无级联"]
```

<span class="marginnote">常见误区：以为「严格 2PL 比 2PL 更可串行」。两者的调度都只保证可串行；严格 2PL 收窄的是锁什么时候放——它多买到的是可恢复与无级联，不是更强的串行化能力。</span>

## 边界

本课不把 SI 当 2PL 的一种。长读挡住写的问题，下一课用多版本缓解。

后课默认：锁实现常用严格 2PL。只读不想挡写，走 MVCC。

## 小结

- 严格 2PL 提交前不放写锁，避免脏读与级联。
- 强严格连读锁一起留。
