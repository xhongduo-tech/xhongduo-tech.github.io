# 二进制加固与混淆

<div class="epigraph">
<p>加固是让控制流劫持变贵：NX、ASLR、CFI、RELRO。混淆是让分析变贵：控制流平坦、字符串加密。前者是默认应开的合同；后者不能当秘密算法，也常被恶意软件用来拖分析员。</p>
<footer>—— 据 Szekeres SoK 的缓解谱；Collberg 对混淆的限度；对照 GNU 硬化和 LLVM CFI</footer>
</div>

上一课[rootkit](/cs/rootkits)说明特权下检测难。缺口是**用户态二进制自己的默认编译选项**与「靠混淆藏逻辑」的幻想。本课分清加固与混淆，不教反调试对抗。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

发行构建若关 PIE/NX，利用课的开口回来。混淆不增加密码学假设，只增加逆向时间；密钥仍在端上。缺口是发布清单：该开的缓解、不该指望的秘密。

<span class="marginnote">术语翻译：NX 是「这段内存只许存数据、不许当代码执行」的页属性；ASLR 是每次进程启动都把栈、堆、库的地址随机挪位，让攻击者猜不准该往返回地址里写什么数。</span>

层层加固如何抬高一次栈溢出的成本：

```mermaid
flowchart TD
  AT["攻击者：溢出覆盖返回地址"] --> NX["NX：注入的栈上代码不可执行"]
  NX --> ROP["改走 ROP：复用已有代码片段"]
  ROP --> ASLR["ASLR：片段地址随机，位置未知"]
  ASLR --> LEAK["只能先泄漏地址，成本上升"]
  LEAK --> CFI["CFI：非法跳转目标再拦一道"]
```

### 恶意软件也混淆

分析员要用沙箱与内存转储，而不是假设混淆等于不可分析。

<span class="marginnote">直觉类比：混淆像把说明书全换成啰嗦的同义长句再写密码笔迹——看懂要多花十倍时间，但内容没变；它藏不住「钥匙就在盒子里」，因为程序要运行，钥匙就必须进内存。</span>

<span class="marginnote">Collberg：混淆没有密码学意义上的一般不可破解。本课禁止写商业软件保护绕过教程。</span>

## 方法

列加固开关（PIE、Fortify、CFI）。对照混淆：可作知识产权延迟，不可作唯一控制。软件安全单元封口，下一单元 Web。

```mermaid
flowchart TD
  HARD["NX ASLR CFI RELRO"] --> COST["提高利用代价"]
  OBF["混淆"] --> TIME["提高分析时间"]
  OBF -.->|"非密码学保密"| LIM["密钥仍在端上"]
```

## 机制

发现与工程课序结束于「如何发行」。Web 单元从 XSS 起：解释器在浏览器里，洞的形状换成脚本注入。

<span class="marginnote">为什么重要：发布那一刻的编译选项基本决定了二进制一生的防御水位；「先上线、以后再加固」往往等于永远不加固，因为重新分发要靠千千万万用户配合升级。</span>

## 小结

- rootkit 在特权层；用户态仍要开加固。
- 混淆拖时间，不是 Shannon 保密。
- 发行清单对准缓解，不对准秘密算法。
