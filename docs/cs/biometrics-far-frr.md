# 生物识别 FAR / FRR

<div class="epigraph">
<p>生物识别是测量不是口令：假接受率与假拒绝率对调，阈值决定你把谁当成谁。模板泄漏不可像口令那样作废再选一个新拇指。</p>
<footer>—— 据 Jain, Ross and Prabhakar 对生物识别的综述；NIST 生物识别测试报告；对照 800-63B 对生物作为因素的限制</footer>
</div>

## 问题

口令相等比较是精确的。生物是分数与阈值。人口大时，即使很小的 FAR 也会产生假匹配。缺口是错误率与威胁模型（呈现攻击、模板存储），不是传感器电路。

<span class="marginnote">数字实例：FAR 若为百万分之一，一间 1 万人次的办公楼每天扫 3 次，一年约 750 万次比对，期望发生约 7 次「陌生人被当成本人」。对单台手机是小概率，对大规模系统是必然事件。</span>

### 不可作废

种子可换，指纹难换。泄漏的模板要当长期凭证事故，配合设备密钥与衰减。

<span class="marginnote">直觉类比：口令像可重配的门锁密码，泄露了换一个就行；指纹像你的脸本身——「密码」只有十个，丢了没法补办，所以宁可让模板根本不出设备。</span>

<span class="marginnote">ISO/IEC 19795 测试方法点名。本课不写欺骗传感器的步骤。PAD（呈现攻击检测）只当需求点名。</span>

## 方法

画 ROC：阈值左移 FAR 降、FRR 升。对照：解锁手机是本机一对一；一对多识别是另一游戏。服务器不要收原始模板。

```mermaid
flowchart TD
  SCORE["匹配分数"] --> TH["阈值"]
  TH --> FAR["假接受"]
  TH --> FRR["假拒绝"]
  TPL["模板"] --> LOC["宜留认证器内"]
```

## 机制

MFA 里生物常是「本地解锁认证器」，服务器只看见 WebAuthn 成功。把生物当远程共享秘密会复制口令问题且更难轮换。下一课用形式工具看协议：ProVerif/Tamarin。

阈值一动，两个错误率怎么反向走：

```mermaid
flowchart TD
  LO["阈值调低（宽松）"] --> FA["FAR 升：陌生人更易混入"]
  LO --> FRD["FRR 降：本人更少被拒"]
  HI["阈值调高（严格）"] --> FAD["FAR 降：陌生人更难混入"]
  HI --> FRU["FRR 升：本人更易被拒"]
  FA --> ROC["同一根 ROC 曲线上的两点，只能取舍"]
  FAD --> ROC
```

<span class="marginnote">常见误区：以为「指纹登录网站」是把指纹发给服务器核对。实际是传感器本地比对模板、解锁设备里的私钥，再由 WebAuthn 用私钥签名向服务器证明——服务器从头到尾没见过任何生物特征。</span>

## 小结

- 口令可轮换；生物是带错误率的测量。
- FAR/FRR 随阈值对调；大规模一对多更险。
- 模板宜留在认证器，配合 WebAuthn。
