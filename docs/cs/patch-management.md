# 补丁与 N-day

<div class="epigraph">
<p>洞一旦公开，时钟对防御方启动。N-day 不是新科学，是补丁滞后、依赖滞后、测试滞后叠成的窗口。优先级应对准暴露面，而不是只对准 CVSS 红字。</p>
<footer>—— 据 Anderson 对补丁经济学；NIST SP 800-40；对照 CISA KEV 目录的思想</footer>
</div>

## 定位

上一课[CVSS](/cs/cve-cvss)给了分。缺口是**时间**：已知洞在你系统里还活着。本课收补丁管道与例外，不写 exploit 开发。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

虚拟补丁、WAF、配置关闭可缩窗口，但不能代替供应商补丁。依赖滞后：库已修，镜像未编。缺口是资产清单（SBOM）与暴露面。

### 例外要过期

「系统太老不能打」必须有补偿与截止日期。


<span class="marginnote">SP 800-40。CISA KEV：正在被用的已知洞。本课禁止利用 N-day 的步骤。</span>

## 方法

画：情报→影响分析→测试→部署→验证。对照红队后课：他们吃的就是这窗口。下一课逆向：你如何在没有源码时理解补丁在改什么。

```mermaid
flowchart TD
  ADV["公告 / KEV"] --> AFF["资产是否受影响"]
  AFF --> TEST["测试补丁"]
  TEST --> DEP["部署"]
  DELAY["滞后"] --> WIN["N-day 窗口"]
```

图中节点是本课的机制骨架；课程不把图展开成可运行的攻击步骤。
