# IDS / IPS

<div class="epigraph">
<p>入侵检测看流量或主机事件是否像已知滥用；防护系统还加上阻断。它们识别的是模式与异常，不是应用不变量。漏报与误报同时存在，所以要和日志、响应流程一起设计。</p>
<footer>—— 据 Roesch, Snort；Paxson, Bro；对照 NIST SP 800-94</footer>
</div>

上一课[BOLA](/cs/api-security-bola)在应用授权。缺口是**网络层可见性**：应用仍会漏，流量侧能否看见扫描、已知利用特征、C2 形态。本课分工 IDS 与 IPS，不写逃避检测的步骤。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

防火墙课管策略放行。[防火墙](/cs/firewall-state)不深检载荷。IDS：旁路告警；IPS：串接阻断。缺口是部署点（网络、主机）与加密流量的盲区。

<span class="marginnote">直觉类比：IDS 是监控室的保安——看得见、能喊人，拦不住正在发生的撬门；IPS 是装在门上的闸机——当场拦人，但认错（误报）就把真顾客挡在门外。保安出错没代价，闸机出错直接影响可用性，这是两者部署取舍的核心。</span>

### 加密后载荷

TLS 后 IDS 只见五元组与 SNI 一类元数据，除非终止 TLS——那是另一威胁模型。

<span class="marginnote">SP 800-94。Snort/Bro 历史。禁止编写逃避 IDS 的教程。下一课规则语言。</span>

## 方法

对照误报成本（可用性）与漏报成本。主机 IDS 看系统调用。下一课 Snort/Suricata 规则形态。

<span class="marginnote">为什么误报是「合同」：每天百万级连接里若误报率百分之一，值班员就会被假警报淹没，真告警也跟着被忽略（狼来了效应）。所以旁路 IDS 宁可偏松、再靠响应流程核实；敢串接的 IPS 规则必须极准，因为每一次误报都在直接丢正常流量。</span>

```mermaid
flowchart TD
  TAP["流量复制"] --> IDS["检测告警"]
  INLINE["串接"] --> IPS["检测并阻断"]
  TLS["加密"] --> META["元数据可见"]
```

## 机制

检测服务完整与可用的观测。它不修复 BOLA。规则下一课把「像什么」写成可维护的签名。

```mermaid
flowchart TD
  F["进入的流量"] --> TAP["镜像一份给旁路 IDS"]
  F --> INLINE["原路径穿过串接 IPS"]
  TAP --> AL["命中：只能告警，流量照走"]
  INLINE --> BLK["命中：直接丢弃或重置"]
  INLINE --> PASS["未命中：放行"]
  AL --> OPS["告警交响应流程处理"]
  BLK --> OPS
```

<span class="marginnote">常见误区：以为 IDS 能看见 TLS 里的内容。加密后可用的只剩五元组、包大小与时序、SNI 等元数据——像只能看到信封的大小、重量和收件人，读不到信本身。所以「检测服务的完整与可用」首先要保证观测点没被绕开、没被加密挤成瞎子。</span>
