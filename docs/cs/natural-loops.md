# 自然循环识别

<div class="epigraph">
<p>回边的头支配尾。自然循环是头加上不经过头而能到达该回边尾的节点。嵌套由头的包含关系给出。</p>
<footer>—— 据龙书 9.6；Muchnick；Tarjan 区间分析对照整理</footer>
</div>

上一课[多面体](/cs/polyhedral-model)用统一代数改写仿射循环，前提是先认出循环。LICM、IV、展开都要**循环对象**。主干 CFG 课有块与边。缺口是**自然循环**：从回边识别头与体。不可约 CFG 没有整齐的自然循环树，要先变换或放弃部分循环优化。本课钉定义，不写 PGO。

## 问题

回边：尾到头，且头支配尾。自然循环：体是所有「不经头能到尾」的节点加头。缺口是**嵌套森林**，不是 φ 放置。

<span class="marginnote">术语翻译：「支配」就是「必经」——从入口到 n 不管怎么绕都躲不开 d，就记作 d 支配 n。回边要求「头支配尾」，翻译成大白话：想走这条回头路，必然先路过 h，所以 h 是这个圈唯一的门口，进出都得打招呼。</span>

前置头：造一个唯一外入块，方便 LICM。不可约：两个入口，无单一头，自然循环定义失败。

### 自然循环不是「源码的 for」

`goto` 可造不可约。识别结果可能与程序员写的 `for` 不同（多个 break）。优化认的是 CFG 循环，不是 AST 循环——除非前端保留元数据。

<span class="marginnote">常见误区：初学者以为「循环就是源码里的 for」。编译器只认 CFG 上的回边：`goto` 能拼出两个互相进入、谁也不支配谁的怪圈（不可约，连唯一的头都没有）；带多个 `break` 的 `for` 也会被识别成多出口循环——识别结果与关键字无关。</span>

<span class="marginnote">龙书循环。Havlak 不可约循环。LLVM LoopInfo。本课以可约为主。</span>

## 方法

算支配。找回边。对每条回边扩体（反向 CFG 搜索）。按头支配关系建嵌套。插入 preheader。

```mermaid
flowchart TD
  DOM["支配"] --> BE["回边"]
  BE --> BODY["自然循环体"]
  BODY --> PH["前置头"]
```

与多面体：SCoP 检测也要循环树。与向量化：最内自然循环是候选。

## 机制

开关与多出口：循环仍自然，只是退出边多，LICM 安全条件更严。不要把 `do-while` 当没有 preheader 就不能优化——可以造。

<span class="marginnote">直觉类比：扩体像从回边倒着灌水找湖的范围——水从尾节点倒灌，凡是「不经过头（门口）」就能流到尾的房间都会被淹到；淹到的房间合起来就是循环体。门口 h 本身也算一间。</span>

深度：内层先处理是 LICM/IV 的标准序。

```mermaid
flowchart TD
  BE["回边 n → h（h 支配 n）"] --> INIT["body = {h, n}，n 入工作表"]
  INIT --> POP["取出节点 m"]
  POP --> PRED["遍历 m 的前驱 p"]
  PRED --> INS["p 不在 body：加入并入栈"]
  INS --> POP
  POP -->|"工作表空"| DONE["体确定：头 h 加全体可达前驱"]
```

## 边界

本课不写全部不可约变换（节点分裂）。后课默认：可约 CFG 有循环树。后课 PGO 会用轮廓给循环行程与分支概率，驱动展开与内联。下一课[别名分析](/cs/alias-analysis)：循环内的访存优化要先回答是否同一对象。

也不把自然循环当链表上的「环检测」算法课。

## 小结

- 回边 + 支配 ⇒ 自然循环；嵌套成树。
- preheader 服务外提。
- 不可约要另处理。
- 出处：Aho et al. 龙书 9.6；Muchnick；对照 Tarjan 区间。
