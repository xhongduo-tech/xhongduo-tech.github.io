# 堆 UAF

<div class="epigraph">
<p>释放后指针仍被解引用，对象槽可能已租给别人。读则泄，写则改别人的对象——包括函数指针。生命周期错误与越界写是两条路，都能到达同一类控制数据。</p>
<footer>—— 据 Szekeres et al., SoK: Eternal War in Memory, Oakland 2013；对照 CWE-416</footer>
</div>

上一课[JOP](/cs/jop-cop)要函数指针可写。缺口是**堆生命周期**：UAF。本课讲悬挂指针与分配器复用，不给利用堆布局的步骤。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

`free` 后未置空，后续使用碰到新对象。类型若不同，就是混淆的入口。缺口是所有权，不是再讲栈帧。语言与 GC、或 borrow checker，从根上删这类。

<span class="marginnote">术语翻译：悬挂指针就是「钥匙还在手里、房间已退租」的状态——free 只还内存，不销毁指针变量，地址数值照旧。之后谁入住你不知道：读一下是串门，写一笔就是改了别人家的东西。</span>

### 双重释放

重复 `free` 破坏分配器元数据，下一课专门收。UAF 是「用」；double-free 是「还两次」。

<span class="marginnote">Szekeres SoK。ASan 后课检测。本课禁止构造 UAF 利用。</span>

## 方法

画：分配→释放→槽复用→悬挂指针。防御：置空、隔离释放、延迟复用、内存安全语言。对照 canary：帮不上堆对象内部。

<span class="marginnote">直觉类比：「延迟复用/隔离释放」像酒店把退房房间晾一晚再出租——刚退租就复制的旧钥匙，开不进新客人的门。代价是内存占用升高：晾着的房间不能立刻接客，峰值「入住率」变低。</span>

```mermaid
flowchart TD
  ALLOC["分配"] --> FREE["释放"]
  FREE --> REUSE["槽复用"]
  DANG["悬挂指针"] --> REUSE
  DANG --> BUG["读泄或写串对象"]
```

## 机制

堆把时间轴引进空间安全。下一课分配器自身的元数据：chunk 头被改时，分配器成为原语。

各层防御分别切断链条的哪一环：

```mermaid
flowchart TD
  F["free(p)"] --> Q1{"free 后置空 p?"}
  Q1 -- "是" --> S1["后续访问崩在空指针, 当场暴露"]
  Q1 -- "否" --> Q2{"槽已租给新对象?"}
  Q2 -- "是" --> UAF["旧指针读写别人的对象"]
  Q2 -- "延迟复用隔离中" --> S2["悬空窗口收窄, 危害降级"]
```

<span class="marginnote">为什么重要：canary 这类守卫对 UAF 无能为力——它守「越界」，UAF 却是「合法地址、错误时间」。堆对象里若住了函数指针或 vtable 指针，一次错时的写就能改控制流，这正是 UAF 单列为 CWE-416 的原因。</span>
