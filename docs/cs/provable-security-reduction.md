# 可证明安全与归约

<div class="epigraph">
<p>证明不是「没人破过」，而是：若敌手能赢这个游戏，就能构造算法赢那个被认为难的问题。归约把产品安全感绑到假设上；假设外的误用，证明沉默。</p>
<footer>—— Goldwasser and Micali, Probabilistic Encryption, 1984；Bellare and Rogaway 的游戏化方法；Katz and Lindell</footer>
</div>

上一课[同态](/cs/homomorphic-intuition)把电路评在密文上。本单元从一次一密走到外包计算，缺口是把**游戏与归约**收成方法论：IND-CPA/CCA、EUF-CMA、ROM。不把证明助手课的 Coq 再讲一遍；那是形式核，这里是密码学归约。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

Shannon 完善保密不需计算假设。其余原语都有假设：PRP、RSA、LWE。可证明安全：写清敌手能力与获胜条件，给归约。随机预言机模型把哈希当理想黑盒，现实哈希只是近似。缺口是读证明时要问「假设是什么、游戏禁了什么」。

### 证明不管实现

归约不管计时、nonce 复用、填充预言。那些在游戏外，误用课收。

<span class="marginnote">GM 1984 语义安全。Bellare–Rogaway 把实践协议游戏化。本课不伪造论文。seL4 更后是系统形式化，对象不同。</span>

<span class="marginnote">归约的直觉可以这样说：「假如你有个程序一小时就能伪造签名，我就把它当零件，拼出一个同样快分解大整数的算法」——分解大整数公认做不到，所以伪造签名的程序也不该存在。证明安全从来不是「没人破过」，而是「破了它就等于破了难题」。</span>

## 方法

用 IND-CPA 游戏回顾对称。指出一次一密是信息论，AES-GCM 是计算+nonce 合同。签名用 EUF-CMA。强调具体安全（优势、时间）比渐近一句话有用。

```mermaid
flowchart TD
  ADV["协议敌手"] --> RED["归约"]
  RED --> HARD["打破假设问题"]
  GAME["游戏前提"] --> ADV
  MIS["前提外误用"] -.-> SIL["证明沉默"]
```

## 机制

安全进阶的密码学单元到此有语言：完善 vs 计算、游戏、归约、ROM。下一课把常见「证明外失败」列成清单，作为协议单元的入口。

```mermaid
flowchart TD
  S1["敌手交来两条明文 m0 与 m1"] --> S2["挑战者掷硬币得 b"]
  S2 --> S3["用密钥加密 mb 发回"]
  S3 --> S4["敌手任意查询后猜 b 撇"]
  S4 --> S5{"b 撇 等于 b ?"}
  S5 -->|"是"| W["敌手赢一局"]
  S5 -->|"否"| L["敌手输"]
  W -.统计大量局数.-> ADV["优势 = 赢的频率 减 二分之一"]
```

<span class="marginnote">上图回答「IND-CPA 游戏具体怎么玩」：敌手唯一的目标是从密文里猜出掷硬币结果。方案安全当且仅当任何多项式时间敌手的优势都可忽略——也就是猜对的可能性怎么也甩不开抛硬币的 1/2 太多。</span>

<span class="marginnote">初学者容易把「可证明安全」读成「无条件安全」。证明的结论严格绑定游戏写下的前提：密钥不泄、nonce 不复用、随机数真随机。这些前提之外（比如计时侧信道），证明一字不说——那是下一课误用清单的内容。</span>

## 边界

本课不证 GCM 的论文全文。误用清单下一课：从 nonce 到 JWT，全部是合同外。

<span class="marginnote">「具体安全」给个数的感觉：不说「AES-GCM 安全」，而是说「敌手做 $2^{128}$ 次操作前优势不超过 $2^{-64}$」。工程选型时，这一句能直接换算成「该用多长的密钥、允许打多少次加密询问」。</span>

## 小结

- 同态等到现在，都该能问：游戏是什么。
- 归约连到假设；假设外证明不说话。
- ROM、具体安全、敌手能力都要写进合同。
