# 收缩层次 CH

<div class="epigraph">
<p>按重要性收缩顶点，用捷径补上被删点的最短路角色；查询只向上走，路网规模上比朴素 Dijkstra 快几个数量级。</p>
<footer>—— 据 Geisberger, Sanders, Schultes and Delling, Contraction Hierarchies, 2008 整理</footer>
</div>

上一课[双向与 ALT](/cs/bidirectional-alt)用路标造 $h$。收缩层次（CH）把预处理做成**改图**：删点加捷边。不重写三角启发。缺口是收缩顺序与查询的向上搜索。本课路网静态；动态边权下一课换连通性结构，不是 CH 更新全文。

## 问题

给顶点重要性（度、捷边数、层级启发式）。收缩 $v$：对 $v$ 的邻对 $(u,w)$，若 $u$–$v$–$w$ 是唯一或必要最短，加捷边 $u\to w$ 权 $d(u,v)+d(v,w)$（见证搜索判断是否已有不经 $v$ 的更短路）。查询：从 $s$ 与 $t$ 只走向层级更高的邻接（含捷边），双向直到稳定。最短路在「先升后降」的层级上。

<span class="marginnote">捷边（shortcut）就是预处理时补的「跳板边」：删掉 v 之前，若 u→v→w 是绕不开 v 的最短路，就直接连一条 u→w、权重为两段之和的边。查询时它不代表真实道路，只是让最短路的数值不因 v 被删而断；输出路径时再展开成真实路段。</span>

缺口是捷边维护最短路，不是 A* 的 $f$。

### 顺序是启发不是定理

差顺序导致捷边爆炸。实践用局部重要性排队。正确性：任意顺序只要捷边补全「经被删点的最短」，查询图仍保留最短路。空间与时间是工程。

<span class="marginnote">Geisberger 等 2008。后续 Customizable CH、PHAST 全源。本课直觉：收缩 + 向上。后课动态连通性是边插删，不是路网权更新的 CH 维护。</span>

## 方法

离线：按序收缩，见证 Dijkstra 决定捷边。在线：双向只走更高层。还原路径时展开捷边为原路径。

```mermaid
flowchart TD
  ORD["收缩顺序"] --> SH["删点加捷边"]
  SH --> UP["查询只向上"]
  UP --> SP["最短路"]
```

与 ALT 可叠加，本课单独 CH 已够。

## 机制

低层点被收缩后，高层仍通过捷边「看见」它们的中转。查询向上：类似最高点当 LCA 式的交会。与 Kruskal 重构树：都是预处理树/层，但 CH 针对最短路而非瓶颈。与 Dijkstra：查询图边少、方向受限。

```mermaid
flowchart LR
  S["起点 s: 低层"] --> U1["只走向更高层的邻点"]
  U1 --> M["高层交会点"]
  T["终点 t: 低层"] --> U2["反向搜索同样只向高层"]
  U2 --> M
  M --> SP["两侧距离相加 = 最短路"]
```

<span class="marginnote">数字实例：在千万级顶点的国家路网上，朴素 Dijkstra 一次查询要松弛几百万条边；CH 预处理后通常几百到几千次松弛即交会。代价是预处理多花几分钟、图多占一倍内存——导航服务正是用这笔「一次换千万次」的账活着的。</span>

不要在任意稠密图上期望 CH 奇迹：路网低度和层次结构是前提。

## 边界

本课不写时间窗、不写并行定制化 CH 细节。不进导航产品。后课默认：静态路网最短路预处理首选 CH 一类。下一课动态连通：边插删下维护连通。

## 小结

- 收缩补捷边，查询只向高层。
- 顺序启发决定空间；正确性靠捷边语义。
- 适合稀疏有层次的路网。
- 出处：Geisberger, Sanders, Schultes and Delling, 2008。

<span class="marginnote">常见误区：以为 CH 是万能加速器。它的奇迹建立在路网「低度数、有层次」的前提上——路口只连几条路、且有主干道层级可爬。换成社交网络那类稠密且无层次的图，捷边数量会爆炸，预处理既跑不动也存不下。</span>
