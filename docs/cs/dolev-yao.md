# Dolev–Yao

<div class="epigraph">
<p>网络敌手可以拆、拼、重放它看见的项，但不能从密文算出明文，除非它有密钥——协议在这个代数里证明安全或不安全。</p>
<footer>—— Dolev and Yao, On the Security of Public Key Protocols, IEEE TIT 1983；Anderson 对协议假设的整理</footer>
</div>

[上一课](/cs/stride)用清单问数据流图。本课不重列六类。缺口是协议课的敌手：不是「黑客」口号，而是形式化能力。Dolev–Yao：控制信道，任意组合已知消息，密码原语当黑盒。后课对称加密在此模型里才有「够用的那一层」。

## 问题

STRIDE 的「篡改/伪造」在网上太宽。Needham–Schroeder 一类协议要问：在能改包的敌手下，认证还是否成立。Dolev–Yao 把加密当成理想锁：没有钥匙打不开，有钥匙可以构造新项。缺口是**协议分析的默认敌手**，不是某一分组算法。

<span class="marginnote">计算模型（概率多项式时间）更细，后课只在需要时点名。侧信道不在 DY 里，后课瞬态执行再扩展模型。</span>

## 方法

消息是项：原子、对、加密。敌手封闭于投影、配对、用已知键加解密、重放。协议是角色进程。安全目标写成「敌手项集里不出现某秘密」或「会话绑定到声称身份」。本课不跑具体攻击轨迹。

```mermaid
flowchart TD
  CH["信道由敌手中继"] --> DY["拆分 / 配对 / 重放"]
  DY --> BOX["无密钥不能开密文"]
  BOX --> GOAL["秘密不出现在敌手项集"]
```

## 机制

把敌手钉成代数，后课 TLS、Kerberos 才能说「防的是 DY 主动者，不防已泄露的私钥」。Kerckhoffs 已在威胁模型课：算法公开。DY 再加：算法理想。真实分组模式若误用，会漏出 DY 假定锁不住的性质——下一单元对称加密与模式。

```mermaid
flowchart LR
  ADV["DY 敌手"] --> CAN1["拆消息：取加密项的组成部分"]
  ADV --> CAN2["重组：用已知密钥加密任意项"]
  ADV --> CAN3["重放：把旧消息原样或改头再发"]
  ADV --> CANT["不能：无密钥从密文还原明文"]
  CANT --> OUT["模型外：侧信道、弱随机、私钥泄露"]
```

<span class="marginnote">术语翻译：Dolev–Yao 模型就是「把整条网络交给攻击者全权控制，同时把密码算法当成打不开的完美保险箱」的分析方法。它故意把两头都推到极端——网络最坏、密码最好——从而把安全问题只聚焦在协议逻辑本身。</span>

<span class="marginnote">直觉类比：DY 的项代数像乐高积木。攻击者可以捡到散落积木、拆开拼好的作品、按图纸重组，甚至加上自己已有的积木；但它不能凭空把一块积木变成它没有的新形状——那一步对应「没有密钥就解不开密文」。</span>

## 边界

本课不把模型检测工具当必会软件。共享密钥下明文如何藏进密文，下一课对称加密。

<span class="marginnote">常见误区：初学者容易以为「协议在 DY 模型下证明了安全」就等于绝对安全。实际上模型里只覆盖理想化的密码原语——侧信道、弱随机数、私钥被偷、算法实现有洞都不在内。证明说的是「只要锁真的完美，逻辑就站得住」。</span>

后课默认：协议敌手是 DY 主动者。对称密码服务「无密钥则不可读」。

## 小结

- Dolev–Yao：控制网络，密码当理想锁。
- 不覆盖侧信道与弱随机数。
- 对称加密下一课。
- 出处：Dolev and Yao, *IEEE TIT* 1983；Anderson。
