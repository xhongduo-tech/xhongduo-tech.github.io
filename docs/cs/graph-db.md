# 图数据库

<div class="epigraph">
<p>点与边是一等存储：多跳邻接用指针或邻接表，不是反复自连接。查询语言是遍历与模式匹配，优化器面对的是路径基数爆炸。</p>
<footer>—— 据 Angles and Gutierrez 图数据库；Neo4j/属性图实践；关系递归 CTE 对照</footer>
</div>

[上一课](/cs/wide-column-bigtable)靠行键编码图会把边挤进单元格。本课把图当模型：属性图（点边带属性）或 RDF 三元组。缺口是访问：关系用递归 CTE 表达传递闭包，计划弱；图引擎邻接索引让 $k$ 跳更自然，但基数估计更差。

## 问题

多对多：关系用连接表，图用边记录。遍历：从点沿边过滤。缺口是**爆炸**：度高时 $k$ 跳组合爆炸，必须限制、最短路算法、或预计算。<span class="marginnote">数字实例：平均度 $f=10$ 时，3 跳的路径上限就是 $10^3=1000$ 条，6 跳是 $10^6$ 条——起点多几个，路径数就压过一张千万行的表。这是「限制遍历深度」成为图查询默认合同的算术原因。</span>事务：改边与点的原子，隔离下的幻边（间隙锁的图版）难。分片：图切会切断边，跨片多跳即分布式 shuffle 的最坏形状。

索引：点标签、边类型、属性 B+。全文与向量可挂在点上，后课。

<span class="marginnote">Angles and Gutierrez 综述。SPARQL vs Cypher 点名。本课不教查询语法课。递归 CTE 课是关系侧对照。</span>

## 方法

OLTP 图：局部遍历、事务。分析图：批量 Pregel/Giraph，另引擎。混合：图投影从关系 nightly 建，新鲜度合同像 HTAP。

与 ART：内存图可用邻接数组。与 LSM：边日志追加，读放大在邻居列表 compaction。

```mermaid
flowchart TD
  V["点"] --> E["邻接边"]
  E --> V2["邻点"]
  Q["k 跳模式"] --> CARD["路径基数爆炸"]
  CUT["图分片"] --> XSH["跨片多跳 shuffle"]
```

## 机制

优化器：选择率在相关邻居上独立假设更假。物理：变长邻接、CSR 只读分析。<span class="marginnote">CSR（压缩稀疏行）翻译到图上就是：把所有点的邻居列表首尾相接拼成一个大数组，另存一张「每个点从哪一格开始」的目录。只读分析时它砍掉全部指针开销、缓存友好；代价是改一个点就得重排——所以它属于只读分析引擎，不属于 OLTP。</span>锁：点级或边级，死锁沿环路径——WFG 仍用。

```mermaid
flowchart TD
  S["起点：1 个"] --> H1["1 跳后：f 个邻居"]
  H1 --> H2["2 跳后：约 f^2 条路径"]
  H2 --> HK["k 跳后：约 f^k 条路径"]
  HK --> EST["优化器按独立假设估基数，误差随跳数放大"]
  HK --> CTRL["限深 / 单源最短路 / 预计算闭包"]
```

关系对照：能用 SQL 几跳的不要上图库；图库赢在深度与变结构边类型。

## 边界

本课不讲时序压缩。也不把知识图谱训练当数据库课。向量 ANN 下一课之后。

后课默认：多跳 OLTP 用图引擎或限制深度的 CTE；分片图要认切边。时序数据库：时间为主键，压缩与保留策略第一。

图切分是 NP 难启发式，生产靠业务分区（租户）少切。<span class="marginnote">直觉类比：图切像把社交网络按「住哪个城市」分库——同城好友在一个库里查得飞快，跨城好友的边却被切断，查一次「朋友的朋友」就要跨库跑一趟网络。所以生产上按租户这类天然聚类分片，让被切的边尽量少。</span>

## 小结

- 属性图让遍历成为原生访问路径；k 跳基数难估。
- 分片切断边；分析图常用批量框架。
