# IPv6 地址与 NDP

<div class="epigraph">
<p>128 位地址仍用前缀划定链路；链路上的解析改成邻居发现，不再广播 ARP。</p>
<footer>—— 据 Deering and Hinden, RFC 8200；Narten 等对邻居发现的整理</footer>
</div>

[上一课](/cs/ipv6-contrast)对照了头格式：无中间分片、无头校验、地址变长。本课不重列扩展头。缺口是地址怎么用、链路上怎么找到邻机：前缀仍决定直连，解析协议换成 NDP（邻居请求/通告），路由器通告代替很多 DHCP 选项。本课不把距离向量提前。

## 问题

[IPv6 对照](/cs/ipv6-contrast)说邻居发现取代 ARP，但没写表怎么填。主机仍要判断目的是否在链路上（前缀长），再把下一跳 IPv6 地址译成 MAC。NDP 用 ICMPv6 消息、组播而不是以太网广播问遍全网。无状态地址自动配置（SLAAC）让主机用通告的前缀自生成接口标识。缺口是**IPv6 的一跳合同**，与 [ARP 缓存](/cs/arp-cache) 同层、不同报文。

<span class="marginnote">链路本地地址 `fe80::/10` 只在一跳有效。全局前缀由路由器通告。重复地址检测在启用前先邻居请求自己。</span>

## 方法

查邻居缓存；未命中则向被请求节点组播发邻居请求，对端单播通告。路由器通告携带前缀、MTU、是否当默认路由。重定向告诉「更好的下一跳」。缓存同样有可达性探测与超时，避免把流量打到已离开的 MAC。

```mermaid
flowchart TD
  DST["下一跳 IPv6"] --> NC["邻居缓存"]
  NC --> NS["组播邻居请求"]
  NS --> NA["邻居通告填表"]
  RA["路由器通告"] --> PFX["前缀与默认路由"]
```

## 机制

NDP 把 ARP + 部分 ICMP 路由器发现收进 ICMPv6，仍只服务一跳。[LPM](/cs/lpm) 在 IPv6 上同样按最长前缀。NAPT 不再是地址不足的理由；防火墙状态仍可存在。端到端：NDP 不保证全球到达，只保证这一跳封装对。

```mermaid
flowchart TD
  UP["主机上线"] --> LL["先自配链路本地 fe80::/10"]
  LL --> RS["发路由器请求 RS"]
  RS --> RA["路由器回 RA: 全局前缀+MTU"]
  RA --> IID["前缀 + 接口标识拼成全球地址"]
  IID --> DAD["重复地址检测: 邻居请求自己"]
  DAD --> USE["没人应答: 地址可用"]
```

<span class="marginnote">数字实例：邻居请求不走广播，走「被请求节点组播」——把目的地址的**最后 24 位**拼到 `ff02::1:ff` 后面。如主机找 `2001:db8::a1b2`，就发到 `ff02::1:ff00:a1b2`；只有接口标识末 24 位同是 `a1b2` 的极少数网卡会收下这帧，其余网卡在硬件层就过滤掉了。</span>

<span class="marginnote">直觉类比：SLAAC 像自助入住公寓——物业（路由器 RA）广播「本楼前缀是 2001:db8:1::/64」，住户自己用设备指纹（MAC 生成的接口标识）拼出房间号，入住前喊一嗓子「有没有人跟我同名」（DAD），没人应答就正式挂牌。全程没有 DHCP 发证。</span>

<span class="marginnote">常见误区：初学者容易把 NDP 当成「IPv6 版的 ARP」逐字替换。它实际还兼任路由器发现、前缀通告、重定向和重复地址检测——这些在 IPv4 里要 DHCP 和 ICMP 各管一段；把 NDP 只当地址解析用，就看不懂 RA 关掉后主机为何「没地址」。</span>

## 边界

本课不把 SEND 与全部 RA 选项当必背，不引入 IPv4/IPv6 双栈过渡的全部隧道。路由如何填全球表，下一课距离向量。

后课默认：IPv6 链路上用 NDP 缓存邻接。控制平面如何学前缀，下一课。

## 小结

- RFC 8200 的地址仍靠前缀划链路；解析用 NDP。
- 路由器通告给出前缀与默认路由。
- 填全球转发表是下一课距离向量。
- 出处：RFC 8200；Kurose and Ross；邻居发现文献（Narten 等）。
