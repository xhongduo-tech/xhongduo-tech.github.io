# 令牌桶与整形

<div class="epigraph">
<p>速率 $r$、桶深 $b$ 限制平均与突发；整形等令牌，监管丢或染色，给 WFQ 的延迟界提供入口合同。</p>
<footer>—— 据 Turner 令牌桶通识；RFC 2697 / 2698 srTCM/trTCM；Parekh–Gallager 条件整理</footer>
</div>

[上一课](/cs/wfq-fair-queue) 的延迟界要流被整形。缺口是**令牌桶**：平均速率、突发、整形 vs 监管。本课不把 DSCP 码点写完。

## 问题

接入合同写 100 Mb/s，但缓冲允许微突发。令牌以 $r$ 产生，桶最多 $b$，发 $L$ 字节耗 $L$ 令牌。无令牌：整形器等待（加延迟），监管器丢或标红。双速三色（RFC 2698）给黄/红。与 AIMD：桶在边缘，cwnd 在端，两者叠加。BDP 突发 $b$ 过小会切峰，过大则瞬间打满下游浅队列（incast 亲戚）。

<span class="marginnote">数字实例：合同取 $(r,b)$ = (100 Mb/s, 1 MB)。空闲 80 毫秒可攒满 1 MB 令牌，允许一口气发 1 MB 突发；想连发 2 MB，多出的部分只能等令牌（整形）或被丢（监管）。平均由 $r$ 钉死，突发上限由 $b$ 钉死。</span>

不要把令牌桶写成加密代币。

<span class="marginnote">RFC 4115 等更新变体。本课钉 $(r,b)$。漏桶对照：恒定出速率。</span>

### $(r,b)$ 合同

整形等令牌加延迟，监管丢或染色。$b$ 无限等于没限。TSO 大段看起来像突发。测速可能只是在量桶。

## 方法

对照：整形 / 监管 / 优先级。画：包 → 扣令牌 → 过或等或丢。与 PAUSE：令牌桶是端或边缘政策，PAUSE 是邻跳反压。

```mermaid
flowchart TD
  TOK["以 r 产生令牌"] --> B["桶深 b"]
  PKT["包长 L"] --> B
  B --> PASS["有令牌则发"]
  B --> WAIT["整形等待"]
```

## 机制

WFQ+令牌桶 ⇒ 端到端延迟上界（理论）。DiffServ 用类桶而不是每用户桶。卫星 $r$ 小，$b$ 要能装一个 BDP 突发否则永远喂不饱。TSO 大段会一次扣很多令牌，看起来像突发。

测速：iperf 被边缘桶限，不是路径 $C$。

```mermaid
flowchart TD
  P["包到达,令牌不足"] --> Q{"这台设备是什么角色?"}
  Q -->|"整形器"| S["排队等令牌,延迟变大"]
  Q -->|"监管器"| D["直接丢弃,或降为黄色"]
  Q -->|"染色器"| C["打上颜色,照常转发"]
  S --> S1["下游看到平滑的流"]
  D --> D1["下游看到缺口与重传"]
```

<span class="marginnote">直觉类比：令牌桶像游乐园发手环——每秒发 $r$ 个、最多存 $b$ 个。攒了一沓手环的人可以带一队朋友同时进场（突发）；漏桶则是旋转门，每分钟只放行固定人数，一点弹性都没有。</span>

## 边界

本课不引入层次令牌桶的全部 classful qdisc。DiffServ 是下一课。后课默认：$(r,b)$ 描述突发约束；整形加延迟，监管丢/染色。

合同写 $r$ 却把 $b$ 设成无限，等于没限。

<span class="marginnote">常见误区：以为测速结果就是链路带宽。边缘挂着令牌桶时，iperf 打出的吞吐只是桶的 $r$；只写 $r$、把 $b$ 设成无限的合同等于不限突发，微突发照样能瞬间打满下游的浅队列。</span>

下一课[DiffServ](/cs/diffserv-qos)。

## 小结

- 令牌桶钉平均与突发。
- 整形等待，监管丢或着色。
- 与 WFQ 一起才有延迟合同。
- 后课只引用本课钉死的对象，不从该领域总问题重开。
- 出处：RFC 2697/2698；Parekh–Gallager。
