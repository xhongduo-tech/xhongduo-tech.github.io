# TLS 攻击史

<div class="epigraph">
<p>TLS 的历史是合同一次次被实现与降级打穿：明文恢复、填充预言、导出密钥、版本回退。TLS 1.3 删掉的东西，多半是这份名单教过的。</p>
<footer>—— 据 RFC 8446 的设计动机；Rescorla, *The Transport Layer Security Protocol*；对照 Vaudenay 与 BEAST/Lucky Thirteen 的公开分析</footer>
</div>

上一课[ACME](/cs/acme)让证书常见。缺口是**记录层与握手曾怎样失败**。主干[TLS 握手](/cs/tls-handshake)已有 1.2/1.3 形状。本课用历史当反例清单：降级、可区分错误、压缩、重协商——不给复现步骤。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

证书对了，记录层仍可能用 CBC+MAC、导出、压缩。攻击史说明：主动敌手改握手选弱套件；计时区分填充；压缩与密钥同流。TLS 1.3：只 AEAD、HKDF、去掉重协商与压缩。缺口是「为何删」，不是再背扩展号。

<span class="marginnote">术语翻译：填充预言（padding oracle）里的 oracle 不是数据库，是「问一句、答对错」的应答器——服务器把「填充格式错」和「校验错」用不同方式说出来，攻击者就得到了一个免费的猜测验证器。</span>

### 降级是协议漏洞

回退到 SSL 3.0 或出口套件不是用户偏好，是敌手可选的模式。版本与套件必须认证绑定。

<span class="marginnote">RFC 8446 引言即针对旧缺陷。POODLE、BEAST、CRIME、Heartbleed 作为失败模式点名：实现越界读也算史。本课禁止操作指导。</span>

## 方法

按层分类：握手绑定、记录完整性、压缩、实现内存。每类对应 1.3 的一条删除或加固。指出中间盒终止 TLS 会重开这些选择。

```mermaid
flowchart TD
  OLD["旧套件与降级"] --> DROP["TLS 1.3 删除"]
  PAD["可区分填充"] --> DROP
  COMP["压缩与重协商"] --> DROP
  DROP --> AEAD["只留 AEAD + HKDF"]
```

## 机制

协议安全是版本化的合同。部署「兼容一切」等于把最弱环留给主动者。后课 SSH/IPsec/WireGuard 是另一些合同，不要假设「已有 TLS」覆盖它们的威胁模型。

```mermaid
flowchart TD
  A["攻击者改写一段密文"] --> S["服务器尝试解密"]
  S --> Q{"填充格式对吗?"}
  Q -->|"对"| OK["回答不同,猜测被确认"]
  Q -->|"不对"| NO["换一个猜测重发"]
  NO --> A
  OK --> N["推进到下一字节"]
  N --> A
```

<span class="marginnote">直觉类比：「兼容一切」像一台允许拨回上世纪老组合的保险柜密码盘——方便了老用户，也方便了撬锁的人。主动攻击者只需逼会话降级到最老的那一档，整台机器的安全就按最低档计算。</span>

## 边界

本课不分析某一 CVE 的报文。SSH 下一课：主机钥与用户钥，另一条远程管理信道。

<span class="marginnote">常见误区：初学者容易以为攻破 TLS 靠数学硬解（比如分解大数）。这份名单里几乎全是工程与协商错误——错误可区分、压缩泄露长度、实现越界读。合同写得对，实现和握手照样能把它输掉。</span>

## 小结

- 证书自动化之后，记录层历史说明要删弱合同。
- 降级、填充预言、压缩是主动敌手的经典通道。
- 1.3 的缩小表面是设计结论，不是审美。
