# FCFS 与 SJF

<div class="epigraph">
<p>先来先服务实现最直；短作业优先降低平均等待，但要知道或估计下一次 CPU 突发有多长。</p>
<footer>—— 据 Silberschatz et al., Operating System Concepts 整理</footer>
</div>

[上一课](/cs/runqueue)给出可运行容器。[调度指标](/cs/scheduling-metrics)已警告：换尺子，名次就换。缺口是两条经典**非抢占**（SJF 可做成抢占的 SRTF）策略：FCFS 按入队序；SJF 按下一次突发最短者先跑。本课对着同一组到达与突发比较，不引入时间片。

## 问题

FCFS：runqueue 当 FIFO，实现即入队出队。长 CPU 型先到，后面一串 I/O 型的等待被拖长，即传送带效应。SJF：选估计突发最短的，平均等待往往更优；证明「非抢占 SJF 平均等待最优」教材可引，本课只锁定直觉与代价——**长度未知**。缺口不是新的队列结构，而是用指标解释这两种取队头的规则。

<span class="marginnote">直觉类比：传送带效应就像超市只有一个收银台——排你前面的人推着满满一车，你只买一瓶水，也得等他把整车结完。FCFS 不看购物多少只看排队先后，于是短任务的平均体验被长任务拖垮。</span>

<span class="marginnote">抢占式最短剩余时间（SRTF）在新短作业到达时打断当前长作业，响应更好，切换更多。估计常用指数平均：最近突发与历史的凸组合。</span>

## 方法

给定到达时间与突发，画出甘特图，算平均等待与周转。FCFS 不需要估计。SJF 需要预言或估计；估计偏长则退化成近 FCFS，偏短则可能饿死长作业——饥饿是公平尺子，不是平均等待。本课点名饥饿，不把多级反馈请进来。

```mermaid
flowchart TD
  ARR["到达"] --> FCFS["FCFS: 入队序"]
  ARR --> SJF["SJF: 最短突发先"]
  FCFS --> M["等待与周转"]
  SJF --> M
```

两者默认跑到突发结束（阻塞或结束）才再选，除非用 SRTF。

## 机制

FCFS 对 I/O 型不友好当它排在长计算后面；SJF 照顾 I/O 型（短突发）从而抬利用率。交互响应仍可能差：一个中等突发也能挡住击键，因为没有时间片上限。这把下一课轮转的动机钉在「即使长度未知，也要定期让出」。

```mermaid
flowchart TD
  J["三个作业同时到达: A 要 24, B 要 3, C 要 3"] --> F["FCFS 按先后: 先跑 A"]
  F --> F1["顺序 A, B, C"]
  F1 --> FW["B 等 24, C 等 27, 平均等待 17"]
  J --> S["SJF 按长短: 先跑 B 和 C"]
  S --> S1["顺序 B, C, A"]
  S1 --> SW["B 等 0, C 等 3, A 等 6, 平均等待 3"]
```

<span class="marginnote">常见误区：初学者容易以为 SJF 只是「让长作业多等一会儿」。实际上若短作业源源不断到达，长作业可能一次都轮不上——这叫饥饿。平均等待这把尺子根本不度量公平，所以「平均等待最优」与「有人永远等不到」可以同时成立。</span>

<span class="marginnote">术语翻译：指数平均就是把「上一次实际跑了多久」和「之前的估计」按比例掺在一起：$\tau_{n+1} = \alpha t_n + (1-\alpha)\tau_n$。取 $\alpha = 0.5$ 意味着最新一次突发占一半话语权——既不像只看上次那样大惊小怪，也不会对行为变化反应迟钝。</span>

## 边界

本课不把实时截止当成短作业。也不把 SJF 说成 Linux 默认。估计误差与恶意谎报长度（用户说自己很短）在开放系统里存在；内核若用实测突发，谎报无效。

后课默认：非抢占策略平均等待可以很好，响应仍可很差。定期抢占的时间片轮转，下一课收。

## 小结

- FCFS 简单，有传送带效应；SJF 降平均等待，依赖估计，可饿死长作业。
- 两者都不自动给出交互响应上限。
- 时间片轮转是下一课。
