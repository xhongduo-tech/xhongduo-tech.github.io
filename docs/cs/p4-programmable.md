# P4 可编程

<div class="epigraph">
<p>P4 描述解析器与匹配-动作流水线，编译到 ASIC 或 CPU；协议头不再焊死在硅里，但仍受阶段数与 TCAM 形状约束。</p>
<footer>—— 据 Bosshart et al., P4, ACM SIGCOMM CCR 2014；P4<sub>16</sub> 语言规范整理</footer>
</div>

[上一课](/cs/sdn-openflow) 的匹配域是固定的。新隧道头要等芯片代次。缺口是**可编程数据面**：P4 写 parse → match-action → deparse。本课不把 Clos 拓扑写完。

## 问题

OpenFlow 加字段靠规范版本。P4：声明头、解析图、表、动作，目标无关再映射到 Tofino 或智能网卡。仍不是通用 CPU：无任意循环、表宽与阶段固定。INT 带内遥测、自定义熵、新封装可在此做。控制面仍要某协议装表——P4 不替代 BGP，只替换「转发 ASIC 焊死」那一层。

不要把 P4 写成智能合约或机器学习训练。

<span class="marginnote">P4<sub>16</sub>。PSA/PNA 架构。本课不写完整编译器。</span>

### 不是通用 CPU

解析与表可描述，阶段数与表宽仍硬。不取消 BGP，只放开头格式。错误程序可成黑洞。

## 方法

画：解析图 → 多级表 → 出端口。对照 TCAM：表仍可能编译成 TCAM/SRAM。与线路码对照：都是「可描述的转发」，一层在 PHY，一层在 L2–L4。

```mermaid
flowchart TD
  PAR["可编程解析"] --> MA["匹配-动作阶段"]
  MA --> DEP["重组"]
  CTL["控制面"] --> MA
```

## 机制

VXLAN/SR 新 SID 可用 P4 先部署再等标准芯片。错误程序可把交换机变成黑洞，需要测试与资源上限。C10K 后课是主机端；这里是网络端可编程。容量 $C$ 仍由端口 PHY 决定，P4 只动如何选口。

把一个隧道包放进流水线走一遍，可编程与固定的差别就看见了：解析图换成认 VXLAN 头只需要改程序描述，表与动作按新头编排，硬件还是那几级阶段。

```mermaid
flowchart TD
  PKT["进包：外层以太网帧"] --> P1["解析图逐头认：Eth → IP → UDP → VXLAN"]
  P1 --> T1["表 1：按外层目的 IP 查隧道终点"]
  T1 --> T2["表 2：匹配 VNI，定位内层主机"]
  T2 --> ACT["动作：剥外层头，TTL 减一"]
  ACT --> DEP["deparse 按解析图重组帧"]
  DEP --> OUT["查转发表，选出口发出"]
```

<span class="marginnote">直觉类比：固定 ASIC 像只卖固定菜单的厨房，P4 是把菜谱（解析图加表加动作）交给同一个厨房——灶眼数量（阶段数）与货架宽度（表大小）仍然焊死，能换的只是做什么菜。</span>

<span class="marginnote">常见误区：初学者容易以为 P4 让交换机变成通用服务器。它没有任意循环、表宽与阶段数固定、每包预算按纳秒算——能在流水线几跳内表达的转发逻辑才是 P4 的疆域，更复杂的就交给主机端 CPU。</span>

<span class="marginnote">为什么重要：P4 程序写错往往不是报错而是黑洞——错误表项让匹配不上的包无声消失；所以可编程数据面上线必须配测试与资源上限，这套功夫与控制面协议的容错是两码事。</span>

与 HOL：流水线阶段加深可能加纳秒，不解决输出热点。

## 边界

本课不引入 eBPF 与 P4 的全部对照。数据中心 Clos 是下一课。后课默认：数据面可编程受流水线资源约束，不是通用计算。

把全部政策塞进 P4 会让控制面版本与芯片资源强耦合。

## 小结

- P4 定义解析与表，编译到受限硬件。
- 不取消控制面协议，只放开头格式。
- 资源阶段数是硬边界。
- 后课只引用本课钉死的对象，不从该领域总问题重开。
