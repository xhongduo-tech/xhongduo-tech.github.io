# 5G 切片与 URLLC

<div class="epigraph">
<p>切片把同一物理 RAN/核心切成隔离的逻辑网络；URLLC 用短时隙与高可靠编码换毫秒级空口，牺牲频谱效率。</p>
<footer>—— 据 3GPP TS 23.501 切片；TS 22.261 与 38 系列 URLLC 相关条款整理</footer>
</div>

[上一课](/cs/cellular-ran-core) 给出 RAN 与核心。eMBB 大带宽与工厂控制不能共用同一张「尽力而为」承载。缺口是**切片**与 **URLLC**：NSI 隔离资源；URLLC 要 $10^{-5}$ 量级空口可靠与毫秒延迟。本课不把卫星轨道写完。

## 问题

DiffServ 后课给 IP  hop 着色；切片更强：独立的控制面与用户面实例、SLA、可能独立的 UPF。URLLC：迷你时隙、免授权上行、重复传输，工作点远离香农极限换延迟——与 Wi‑Fi OFDMA 调度同类但有牌照与更硬的时间槽。不是 PFC：空口不能「暂停邻站一整口」来保证工厂周期。

不要把切片写成 VLAN：隔离在核心与 RAN 资源上，不止 802.1Q 标签。

<span class="marginnote">常见误区：初学者容易把切片想成「给流量打个 VLAN 标签就完事」。实际上切片是把一块无线频谱资源加一组核心网功能（如独立的 UPF）整块划给一类业务——eMBB 用户再拥挤，也不该挤占 URLLC 切片预留的资源。</span>

<span class="marginnote">术语翻译：URLLC（超可靠低时延通信）就是用「更短的时隙 + 同一包多发几遍」的手段，来做「把空口丢包率压到十万分之一量级、延迟压到毫秒级」这件事。代价是频谱效率：同样的无线电资源能装下的普通数据变少了。</span>

<span class="marginnote">eMBB / URLLC / mMTC 是 5G 三类场景。实现参差，本课钉合同：隔离与时延可靠指标，不点名某运营商套餐。</span>

### 切片强于 DSCP

隔离的是实例与资源，不只 hop 着色。URLLC 用效率换尾延迟，工作点远离容量极限。实验室演示不等于全国 SLA。

## 方法

画：物理网 → 切片实例 → 不同 SLA。URLLC 路径：短 TTI → 编码重复 → 核心低时延转发。对照以太网 PFC：一跳反压 vs 端到端时延预算。

```mermaid
flowchart TD
  PHY["物理 RAN/核心"] --> SL["切片实例"]
  SL --> EMBB["eMBB 容量"]
  SL --> URL["URLLC 时延"]
  URL --> SHORT["短时隙与重复"]
```

## 机制

容量 $C$ 被切片划分：给 URLLC 的资源不能同时给 eMBB 满载。这是显式资源预留，与互联网核心的统计复用对照。移动性仍走核心锚，切片要跟着会话走。主干端到端：再可靠的空口也不替代应用校验。

与 Wi‑Fi 6 调度：都是时频资源分配；5G 有许可频谱与更硬的同步。

第一张图画的是「切片把物理网拆成几个 SLA 不同的逻辑网」；这里补上第二个问题：URLLC 单个包靠什么把丢包率压到 $10^{-5}$ 量级——答案是短时隙调度加多副本传输，接收方任一副本成功即可交付。

```mermaid
flowchart TD
  APP["工厂控制包"] --> SCHED["调度器：迷你时隙"]
  SCHED --> C1["副本 1：频段 A"]
  SCHED --> C2["副本 2：频段 B"]
  C1 --> RX["接收机分别解码"]
  C2 --> RX
  RX --> OK{"任一副本成功？"}
  OK -->|"是"| DELIVER["按时隙边界交付"]
  OK -->|"否"| DROP["本时隙丢弃，靠上层兜底"]
```

<span class="marginnote">数字实例：普通 5G 一个时隙约 1 毫秒（30 kHz 子载波下含 14 个符号），迷你时隙可以只占 2 个或 7 个符号，也就是零点二到零点五毫秒就能发一次——「短 TTI」省的就是这段时间。再叠加两个副本走不同频段，单个副本丢 $10^{-2}$ 量级时，两个独立副本同时失败的概率就压到了 $10^{-4}$ 到 $10^{-5}$ 量级。</span>

## 小结

- 切片隔离 SLA，强于单跳 DSCP。
- URLLC 短时隙、重复、远离容量极限。
- 资源预留与互联网统计复用对照。
