# 时间片轮转

<div class="epigraph">
<p>轮转给每个可运行任务一个量子；用完则排到队尾。片太短切换税吃掉吞吐，片太长退化成 FCFS。</p>
<footer>—— 据 Silberschatz et al., Operating System Concepts 整理</footer>
</div>

[上一课](/cs/fcfs-sjf)的非抢占策略对交互没有响应上限。时钟中断已经能把 CPU 抢回来。[调度指标](/cs/scheduling-metrics)里响应时间正是为这种抢占准备的。缺口是 **RR**：runqueue 当环形 FIFO，每条任务最多连续跑一个量子 $q$。本课钉量子与指标的折中，不引入多级队列。

## 问题

击键处理若要等当前编译突发结束，响应不可接受。RR：时钟减量子，到零则切换并把当前任务接到队尾。I/O 型往往用不完 $q$ 就阻塞，等于自动偏向短突发。缺口不是 SJF 的估计，而是用**固定抢占周期**逼近公平的人次均等。<span class="marginnote">直觉类比：RR 就像幼儿园排队玩秋千——每人荡固定时间（一个量子），计时器一响必须把秋千让给队尾的下一个人，自己重新去排队尾。人越多，同一孩子两次上秋千的间隔越长，但没人能一直霸着不让。</span>

<span class="marginnote">$n$ 个可运行任务时，一条任务最迟大约 $(n-1)q$ 后再摸到 CPU（忽略切换税）。这是响应的上界直觉，不是硬实时保证。</span>

## 方法

选 $q$。相对一次突发：若 $q$ 大于绝大多数突发，RR ≈ FCFS；若 $q$ 接近一次内核切换的代价，利用率塌掉。教材常用几十毫秒量级作讨论，不是定律。切换仍走[上下文切换](/cs/context-switch)；FPU 惰性在 RR 下更值钱，因为切得勤。<span class="marginnote">数字实例：设单次上下文切换约花 10 μs。$q=10$ ms 时，切换税占比约 0.1%，几乎免费；把 $q$ 压到 100 μs，占比涨到 10%；再压到 20 μs，一半的 CPU 时间在切换而非干活。量子越短，税不是线性变贵，是占比指数式恶化。</span>

```mermaid
flowchart TD
  RQ["FIFO 就绪队列"] --> RUN["跑至多 q"]
  RUN --> EX["用尽: 到队尾"]
  RUN --> BL["阻塞: 离开队列"]
```

唤醒入队位置：队尾（常见）或按规则插队；本课默认队尾，以免刚唤醒的立刻垄断。

## 机制

RR 把公平定义成人次轮流，不认权重：后台编译与前台击键同一 $q$。这正是后课 CFS 要改的点，本课先把「无权重轮转」钉死。对纯 CPU 型集合，平均等待往往差于 SJF，但响应方差小。传送带效应被量子切开。<span class="marginnote">常见误区：初学者容易以为 RR 的平均等待时间一定比 SJF 短——恰好相反，RR 用更高的平均等待换来了更小的响应方差：每个任务都「不久就会轮到」，但短任务可能被排在一堆长任务各切一刀的后面。RR 买的是「没有饿死」，不是「最快完成」。</span>

```mermaid
flowchart TD
  PICK["问题：量子 q 该取多大"] --> CMP{"q 与典型突发长度相比"}
  CMP -- "q 远大于绝大多数突发" --> F1["退化成 FCFS：交互响应回到老问题"]
  CMP -- "q 接近一次切换的代价" --> F2["切换税吃掉利用率"]
  CMP -- "q 落在中间地带" --> F3["轮流公平且开销可容忍"]
  F3 --> TUNE["随任务构成重调：没有普适常数"]
```

与 idle：只有 idle 可跑时不轮转它与自己。

## 边界

本课不把 POSIX `SCHED_RR` 的实时轮转与分时 RR 混成一种队列。也不把动态调整 $q$ 的启发式写完。优先级尚未进场；所有人同一档。

后课默认：固定量子改善响应、人次公平。要用近期行为把任务分进不同量子档，下一课讲多级反馈队列。

## 小结

- RR：量子到则队尾；响应有与 $n q$ 相关的直觉上界。
- $q$ 在切换税与 FCFS 化之间折中；无权重。
- 按行为分档是 MLFQ 的缺口。
- 出处：Silberschatz et al., *OSC*；Tanenbaum and Bos, *MOS*。
