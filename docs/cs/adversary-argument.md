# 对手论证

<div class="epigraph">
<p>下界不必列出所有输入：对手在比较时才固定答案，只要与某个尚未排除的输入一致，就逼算法问够多次。</p>
<footer>—— 据 Knuth TAOCP 卷 3；CLRS 第 8.1 节排序下界整理</footer>
</div>

上一课[排序网络](/cs/sorting-networks)是上界构造。比较排序 $\Omega(n\log n)$：决策树叶子 $\ge n!$，$\log_2(n!)=\Omega(n\log n)$。缺口是对手法：求最大与次大 $n+\lceil\log n\rceil-2$ 次比较等。不重写主定理。后课 word RAM 换模型。主干[排序下界](/cs/sort-lower-bound)若已写则只补对手图像。

## 问题

算法问「$a_i?a_j$」，对手选 $\lt $ 或 $\gt $ 使尽可能多输入仍活。直到只剩一种序或一种最大。求最大：$n-1$ 次必要（锦标赛）。次大：败给冠军的人里再赛，$\lceil\log n\rceil-1$。信息论：中位数、极值都有对手或决策树界。

缺口是自适应对手，不是「最坏数组已经写好」。

### 不是在线竞争的对手

那里对手生成序列对付在线决策。这里对手回答比较。模型不同，精神同：延迟承诺。

<span class="marginnote">CLRS 8.1 决策树。Knuth 卷 3 对手。后课 word RAM 打破比较模型。</span>

<span class="marginnote">直觉类比：对手像猜数字游戏里那位「怎么难受怎么答」的出题人——只要还存在一个与你目前听到的回答不矛盾的数，他就绝不认输。你被迫问的次数，就是他逼出来的下界；他不是先藏好一个数，而是边玩边保持「多种可能都还活着」。</span>

## 方法

维护尚未排除的输入集合或不变量（谁仍可能最大）。每次比较缩小，给出最少次数。与决策树高度对照。

```mermaid
flowchart TD
  Q["比较 i:j"] --> ADV["对手选仍相容的答案"]
  ADV --> LIVE["活输入集合"]
  LIVE --> LB["次数下界"]
```

线性时间排序靠非比较模型（桶、基数）。

方法一节的图回答「对手论证的一般循环」，下面这张回答另一个具体问题：求最大与次大，那 $n+\lceil\log n\rceil-2$ 次比较花在哪里。

```mermaid
flowchart TD
  N["n 个候选"] --> T["锦标赛: 两两比, 胜者晋级"]
  T --> W["冠军: 共赢 n-1 场"]
  T --> L["直接败给冠军的集合"]
  L --> L2["共 ceil(log2 n) 人, 每人恰败一场"]
  L2 --> R["败者内部再赛"]
  R --> S["次大: 再比 ceil(log2 n) - 1 场"]
```

<span class="marginnote">数字实例：$n=8$ 时——冠军赛 $8-1=7$ 场；冠军一路打了 $\log_2 8=3$ 场，所以次大只能在直接输给他的那 3 人里，再赛 $3-1=2$ 场。合计 $7+2=9=8+\lceil\log_2 8\rceil-2$ 场，正好对上公式。</span>

<span class="marginnote">常见误区：初学者容易以为下界证明要穷举所有输入，实际上对手只需让每次回答至少与一个未被排除的输入相容；也容易把这里的「回答比较的对手」与在线算法里「预先生成序列的对手」混为一谈——前者卡比较次数，后者卡竞争比，共享的只是「延迟承诺」这个精神。</span>

## 机制

活集合大小每问最多减半（平衡时），故 $\log$；排序活集合 $n!$。对手可不平衡提问，下界仍至少最坏路径。与 Karger 对手无关。与分页对手是在线。

## 边界

本课不写代数判定树全文。不写元素唯一性 $\Omega(n\log n)$。后课默认：比较模型下界用决策树或对手。下一课 word RAM 与位并行。

## 小结

- 对手延迟固定输入，逼出比较次数。
- 排序 $\Omega(n\log n)$；最大 $n-1$。
- 与在线对手模型不同。
- 出处：Knuth TAOCP 卷 3；CLRS 第 8.1 节。
