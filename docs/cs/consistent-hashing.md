# 一致性哈希

<div class="epigraph">
<p>机器与键都映射到环上；键跟顺时针第一台机器。加一台只动邻近弧上的键，不是全表 $\bmod n$。</p>
<footer>—— 据 Karger, Lehman, Leighton, Panigrahy, Levine and Lewin, Consistent Hashing and Random Trees, STOC 1997；Karger et al. 后续 Web 缓存文献整理</footer>
</div>

[上一课](/cs/perfect-hashing) 钉死静态槽。[通用散列](/cs/universal-hashing) 的 $m$ 一变，$h(x)\bmod m$ 几乎所有键换家。缓存集群、分片要的是**扰动最小**。本课不造 FKS 二级表。缺口是一致性哈希：环 + 虚拟节点。

## 问题

$n$ 台机器，$\bmod n$ 在 $n\to n+1$ 时期望几乎全部键迁移。一致性：键、节点都哈希到 $[0,1)$ 环（或 $2^{w}$），键归属顺时针下一节点。新节点只接管它到前驱之间的弧。期望每键迁移比例 $\Theta(1/n)$。缺口不是完美无碰撞，而是**映射随节点集平滑变化**。

<span class="marginnote">环可以类比一面圆形钟面：把机器想成随机撒在钟面上的几枚图钉，每个键也撒一枚，归属「顺时针碰到的第一枚图钉」。加一枚新图钉，只有它逆时针方向到上一枚之间的那段键要改姓，其余键一概不动。</span>

<span class="marginnote">Karger et al., *STOC*, 1997。虚拟节点：每机多个环上位置，改善负载方差。Rendezvous / 跳跃哈希是亲戚，本课点名。</span>

## 方法

查找：对键哈希，在有序节点环上后继（树或跳表）。增删节点：插/删环上点，只迁移受影响键。虚拟节点数 $v$ 权衡均匀与元数据。权重机可按权重复制虚点。<span class="marginnote">「虚拟节点」翻译成白话：一台物理机器在环上冒充几十到几百个位置。机器少时弧长方差大——有人分到一长条、有人只分到一小点；多冒充几个点就把弧切得更碎、摊得更匀。容量大的机器多冒充几个点，还能顺手表达权重。</span>

```mermaid
flowchart LR
  KEY["h(key)"] --> RING["环"]
  NODE["h(node, v)"] --> RING
  RING --> OWN["顺时针下一节点"]
```

与 Count-Min：一致性解决放置；草图解决近似计数。

## 机制

负载：无虚点时单机弧长方差大；虚点使弧更碎。哈希仍建议通用或密码学视对抗模型。故障：节点消失，弧并到后继，与「加节点」对偶。

<span class="marginnote">给个数字实例：$n=4$ 台机器时加第 5 台——取模法从 $h(k)\bmod 4$ 变成 $\bmod 5$，绝大多数键换家、缓存全冷；环法只迁走期望 $1/5$ 的键，而且全部是搬给新节点的那一段。宕机同理：消失节点的弧整个并给顺时针后继。</span>

```mermaid
flowchart TD
  MOD["取模法：h(k) mod n"] --> A1["n 从 4 变 5：几乎所有键换家"]
  RING["环法：键与节点都哈希上环"] --> A2["n 从 4 变 5：只迁新节点到前驱那条弧"]
  A1 --> C1["期望迁移比例 ≈ 全部键"]
  A2 --> C2["期望迁移比例 Θ(1/n) = 约 1/5"]
  FAIL["节点宕机：弧整个并给顺时针后继"] --> DUAL["与加节点对偶，同样只动一段弧"]
```

后课近似结构假定流或多重集，不再假设能存全体键。

## 边界

本课不把 Dynamo 论文当词条抄。不保证全局最优平衡（那是负载均衡另一层）。草图从 Count-Min 开始允许误差。

后课默认：集群成员变化用一致性哈希减迁移。流上近似频次用 Count-Min。

## 小结

- 一致性哈希：环上后继，增删只动邻近键。
- 虚拟节点改善平衡。
- 下一课用草图近似计数，不存键。
- 出处：Karger et al., *STOC*, 1997。
