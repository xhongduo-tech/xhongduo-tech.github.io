# UDP 校验与端口

<div class="epigraph">
<p>端口把主机上的数据报交给某个套接字；校验和覆盖伪首部，发现的是端到端比特翻转，不是到达保证。</p>
<footer>—— 据 Postel, RFC 768；Kurose and Ross 对端口与校验的整理</footer>
</div>

[上一课](/cs/udp)给出最薄传输：数据报、不保证序与到达。本课不重讲「无连接」。缺口是两个字段如何用：目的端口解复用到进程，校验和（IPv4 上可选、IPv6 上实质必有）把 [IP](/cs/ip-subnet) 地址绑进检查范围。本课不把 TCP 握手提前。

## 问题

[UDP](/cs/udp) 说有端口与可选校验，但没钉解复用键与伪首部。同一主机多个接收者：[进程](/cs/process-image) 用端口区分。校验覆盖 UDP 头、载荷以及源/目的 IP 等伪首部字段，使「改了 IP 头却不动 UDP」也能被发现——链路 [CRC](/cs/frame-crc) 覆盖不到中间节点改写。缺口是**解复用与端到端检错**，仍不是可靠流。

<span class="marginnote">「伪首部」并不是真的头——它不发上线路，只是发送方和接收方各自把源/目的 IP 等字段临时拼进校验计算，用来抓「IP 层地址被中间设备改写而 UDP 部分原样转发」这类错。</span>

<span class="marginnote">IPv4 校验和为 0 表示发送方未算。NAPT 改地址/端口后必须重算。分片重组前载荷可能不齐，校验在完整数据报上做。</span>

## 方法

发送：填源端口（常由内核分配）、目的端口、长度，按 RFC 768 算校验。接收：按目的端口（及可选源过滤）投递；校验错则静默丢。无端口监听则 ICMP 端口不可达——那是上一层 ICMP 课已有的回报，UDP 自己不重试。

```mermaid
flowchart TD
  DG["UDP 数据报"] --> PORT["按目的端口解复用"]
  DG --> CKS["伪首部校验"]
  CKS --> DROP["错则丢"]
  PORT --> SOCK["投递到套接字"]
```

## 机制

为什么链路 CRC 不够、伪首部要补哪一块——两道防线各管一段：

```mermaid
flowchart TD
  SEND["发送端按伪首部算校验和"] --> HOP1["链路 CRC 逐跳验证"]
  HOP1 --> RTR["路由器改写 IP 头再转发"]
  RTR --> GAP["跳与跳之间无人看管"]
  GAP --> ARR["到达接收端"]
  ARR --> RECALC["按伪首部重算校验和"]
  RECALC --> Q{"一致吗"}
  Q -->|"一致"| DELIVER["按端口投递"]
  Q -->|"不一致"| DISCARD["静默丢弃"]
```

端口是传输层名字，MAC 与 IP 都不是进程。[端到端](/cs/layering-e2e) 在这一层第一次有了「进程到进程」的检错，但仍无序号。后课 TCP 用同一端口空间的另一协议号，把校验、序号、握手叠在一起。套接字 API 更后才把端口暴露给 `bind`。

<span class="marginnote">数字实例：UDP 头只有 8 字节——源端口、目的端口、长度、校验和各占 2 字节；IPv6 下校验和不可省略，全 0 的包会被接收方直接丢弃。</span>

## 边界

本课不把 QUIC 的 UDP 复用提前写完，不引入全部知名端口登记表。可靠、有序的字节流如何同步初始序号，下一课三次握手。

后课默认：数据报能按端口投递，校验错则丢。要流语义，下一课 TCP。

<span class="marginnote">常见误区：初学者容易以为校验和能「修复」坏数据。它只检错不纠错——发现比特翻转的唯一动作是静默丢弃，应用层只会感觉这个包没了，绝不会收到内容坏掉的包。</span>

## 小结

- 端口解复用到进程；校验含伪首部。
- 校验发现翻转，不恢复丢失。
- 有状态字节流从下一课握手开始。
- 出处：RFC 768；Kurose and Ross。
