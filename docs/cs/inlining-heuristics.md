# 内联启发

<div class="epigraph">
<p>内联用调用点的体替换 `call`，消除开销并暴露过程内优化。预算、热度与是否递归决定做不做，而不是「凡是能内联都做」。</p>
<footer>—— 据 Davidson and Holler；Ayres 等内联研究；Appel；龙书过程间优化整理</footer>
</div>

上一课[调用图](/cs/interprocedural-callgraph)知道 callee。缺口是**复制体的决策**：小函数几乎总内联；大函数只在热路径；递归要阈值。本课钉启发与副作用（代码膨胀、编译时间），不写尾调用——下一课。

## 问题

每次调用有 ABI 开销与屏障（许多优化不跨 `call`）。内联后常量实参触发 SCCP，虚调用可能去虚。代价：I-cache、编译时间、调试。缺口是**成本模型**，不是 CG 构造。

<span class="marginnote">数字实例：一个 2 KB 的热函数被内联进 10 个调用点，指令体积大约多出 18 KB——这还只是一层。代码膨胀的真实代价在 I-cache：热循环的工作集被撑大后，取指miss变多，「消除了 call 开销」省下的几拍可能远不够赔。</span>

始终内联：`always_inline`、模板单态化后的小函数。永不：函数指针外部、`noinline`、过大。

### 内联不是宏

宏是记号改写，无作用域；内联是 IR 级，遵守作用域与类型。C 的 `inline` 关键字还与链接（弱符号）纠缠，后课符号。

<span class="marginnote">经典编译器内联启发式。LLVM InlineCost。PGO 后课提供热度。本课静态：体大小、调用深度、是否有 alloca。</span>

## 方法

自底向上沿 CG（先叶）。对每个调用点打分：指令数、是否可常量传播、是否在循环。超过预算停。递归：允许浅层或只内联一次（peel）。

```mermaid
flowchart TD
  CG["调用图"] --> COST["代价 / 收益"]
  COST --> IN["复制体"]
  IN --> OPT["SCCP / DCE / LICM"]
```

与单态化：特化后的体更小更值得内联。与栈：内联加深帧，除非再缩。

## 机制

间接调用：先去虚（唯一目标）再内联。失败则留 `call`。不要内联改变可观察异常表顺序的语言细节而不更新表。

常量实参在内联后引发的连锁优化：

```mermaid
flowchart TD
  A["调用点：f(4096)"] --> B["复制 callee 体到调用点"]
  B --> C["SCCP 让 4096 沿体传播"]
  C --> D["依赖该常量的死分支被剪掉"]
  D --> E["DCE / LICM 继续清理残留"]
  E --> F["特化后的体可能比原调用更小更快"]
```

<span class="marginnote">术语翻译：「去虚化」就是编译器发现某个虚调用实际上只有一个可能目标，把它改写成直接调用——改完才有资格内联。去虚与内联互为放大器：内联暴露信息让去虚更容易，去虚产生的小直接调用又更值得内联。</span>

<span class="marginnote">常见误区：初学者容易以为「能内联就内联，反正更快」。预算存在的理由正是反例：大函数反复复制推高 I-cache 压力与编译时间，冷路径上的内联几乎零收益。启发式做的是打分排序，不是无条件复制。</span>

链接期内联（LTO）看见其它 TU 的体——后课 LTO。

## 边界

本课不写完整 profile 计数。后课默认：内联由预算与热度约束。下一课尾调用：不内联也能把调用变成跳转。

也不把内联当混淆（故意复制）。

## 小结

- 内联消除调用并暴露优化；膨胀是代价。
- 启发：大小、热度、递归深度。
- 与摘要分析互补：不内联也能传 mod/ref。
- 出处：Davidson/Holler；Appel；龙书；对照 LLVM InlineCost。
