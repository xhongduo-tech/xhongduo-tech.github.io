# 功耗分析 DPA

<div class="epigraph">
<p>运算的功耗与数据相关时，统计多条曲线就能抽出密钥比特。防护是掩码、随机化与恒定功耗设计，而不是把算法换成「更长的密钥」一句话。</p>
<footer>—— Kocher, Jaffe and Jun, Differential Power Analysis, CRYPTO 1999</footer>
</div>

上一课[固件](/cs/firmware-security)还在逻辑更新层面，缺口降到**物理可观测**：功耗。主干侧信道已给时间；本课 DPA。不给采集与分析步骤。<span class="marginnote">SPA 与 DPA 一字之差，问的问题不同：SPA（简单功耗分析）盯着**一条**曲线找结构，好比看一次落笔的笔迹就认出写的是谁；DPA（差分功耗分析）攒**成千上万条**曲线做统计，好比把同一段低语录一万遍再叠加，噪声相互抵消、内容浮出水面。前者怕随机化打乱节奏，后者只能靠压低每一条的相关性来对抗。</span>

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

智能卡、安全元件一旦落到敌手手上，密码算法就只在他的示波器里运行：门电路翻转时充放电，瞬时功耗与翻转的比特相关，而翻转的比特由密钥决定。SPA 读单条曲线，直接看出模幂的平方/乘法序列这类结构；DPA 更进一步：采集多条曲线，按「猜某密钥比特为 1 或 0」分组取均值，猜对时两组在泄漏点出现可统计区分的差值，猜错只剩噪声。因此密钥加长不自动有效——泄漏是逐比特的。缺口是实现对策：掩码把中间值拆成随机份额、隐藏让功耗与数据无关、随机延迟打散对齐——代价是性能与随机数质量。

### 实验室模型

课程只要求把功耗标进威胁模型：发出去的设备按「敌手可长期物理接触」评估，而不是只按网络攻击评估。不指导搭建探针。

<span class="marginnote">Kocher et al. 1999。禁止 DPA 实验指导。故障注入下一课是主动物理。</span>

## 方法

把泄漏与对策对应着陈述：哪类运算泄漏——查表、模乘、比较器；哪层对策接——算法层掩码、电路层隐藏、协议层限速与随机化。两者的失败模式不同：掩码怕随机数质量差或份额被单点攻破，隐藏怕工艺偏差让「恒定功耗」假设不成立。下一课故障注入。

```mermaid
flowchart TD
  OP["密钥相关运算"] --> PWR["功耗曲线"]
  PWR --> STAT["统计区分比特"]
  MASK["掩码与随机化"] --> HARD["提高代价"]
```

<span class="marginnote">常见误区：初学者遇到侧信道的第一反应是「把密钥从 128 位换成 256 位」。这对功耗分析几乎无效——泄漏是逐字节逐比特发生的，攻击者从不面对整把密钥，只面对一个字节里的 256 种猜测，一次攻破一个字节，逐个收网。密钥加长改变的是代数攻击的代价，不改变「每次运算都在发光」这个事实。</span>

## 机制

物理层把条件熵泄漏出去：密钥的条件熵随观测次数单调下降，DPA 的分组平均正是把单条曲线里低于噪声的信号累加出来——每条曲线一点微小偏差，上万条叠加就成了清晰峰值。防护核心因此不是「藏住算法」，而是压低每次运算与数据的相关性。与下一课对照：故障注入是主动改计算，DPA 是被动听计算。

把一个字节的猜测到判定走一遍，就能看清「差分」二字的含义：

```mermaid
flowchart TD
  A["猜测目标字节 = k"] --> B["按模型预测每个时刻的翻转比特"]
  B --> C["把曲线按预测 0/1 分成两组"]
  C --> D["两组各自求平均再相减"]
  D --> E{"出现明显峰值?"}
  E -- "是" --> F["猜测正确，该字节攻破"]
  E -- "否" --> G["换下一个候选值重来"]
```

<span class="marginnote">数字实例：统计平均的威力按 $\sqrt N$ 结账。设单条曲线里泄漏信号幅度为 $1$、噪声幅度为 $100$，一条曲线完全淹没；平均 $N$ 条后噪声缩为 $100/\sqrt N$——$N=10000$ 时噪声降到 $1$，信号与噪声打平；$N=1000000$ 时噪声只剩 $0.1$，峰值清晰可辨。这就是「多采一万条曲线」比「换更强算法」对攻击者更划算的原因。</span>

## 小结

- 固件逻辑之后，功耗把数据变成曲线。
- DPA 是统计侧信道；对策是掩码与隐藏。
- 密钥加长不自动关功耗泄漏。
