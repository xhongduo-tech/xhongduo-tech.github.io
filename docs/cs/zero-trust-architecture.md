# 零信任架构

<div class="epigraph">
<p>零信任架构把每请求的认证、授权与加密当默认，网络位置降为弱信号。策略引擎、身份、设备姿态组成控制平面。它是 NIST 的架构语言，不是某厂商产品名。</p>
<footer>—— Rose et al., NIST SP 800-207</footer>
</div>

## 问题

传统架构的毛病是隐式信任区过大：进了内网就像进了没有摄像头的后厨，横向移动无阻。缺口是三件事：策略引擎（PE）与策略执行点（PA）分离、对每个请求持续评估信任、把网络切成微分段限制爆炸半径。身份的零件——认证、令牌、设备姿态——来自本课程身份单元。

### 遗留

遗留系统关不掉也关不快：迁移的现实形态是并行控制——同一资源先由零信任策略与 VPN 双轨放行，再逐段收窄旧边界。

<span class="marginnote">术语翻译：「微分段」就是把内网切成许多个小隔间，每个隔间只许特定身份以特定方式通过——数据库只收应用服务器的请求，而不是"都在内网就随便连"。爆炸半径从整个内网缩到一间小屋。</span>

<span class="marginnote">SP 800-207。纵深防御下一课把多层写进同一画面。</span>

## 方法

方法是把控制平面与数据平面画开：策略引擎收集身份与设备姿态做每请求决策，策略执行点在数据路径上强制执行，决策经加密通道下发。设计次序是先列保护对象与访问关系、再放执行点，不是先买产品再找位置。下一课纵深防御。

```mermaid
flowchart TD
  ID["身份与设备"] --> PE["策略引擎"]
  PE --> PA["策略执行点"]
  PA --> RES["资源"]
```

## 机制

机制是请求级授权：会话内不再「一次登录终身可信」，每个请求重估身份、设备、行为与上下文，信任随风险动态衰减——令牌到期、步调异常都会压低评分。它防的是横向移动与边界内裸奔，但不是单层银弹：策略引擎本身是新的高价值单点，它的误判即全局误判。纵深下一课强调仍要多层。

<span class="marginnote">常见误区：初学者容易以为零信任就是"多买一套零信任产品"。实际它是一种默认值的替换——把"在网内即可信"换成"每请求重验"。边界没消失，只是从防火墙搬到了策略执行点；执行点照样可以被绕，仍要纵深。</span>

<span class="marginnote">数字实例：一次登录的隐式信任好比进楼刷一次卡、之后 8 小时所有房门全开；请求级评估好比每扇门都重刷一次，且门禁还看表——令牌只剩 2 分钟、来源 IP 突变，评分立刻下调，这扇门就拒绝放行。</span>

```mermaid
flowchart TD
  REQ["资源请求到达"] --> SIG["收集信号：身份 设备 行为 上下文"]
  SIG --> SCORE{"策略引擎算信任分"}
  SCORE --> HI["分够：放行，会话限时"]
  SCORE --> LO["分不够：重认证或拒绝"]
  HI --> STEP["步调或来源突变"]
  STEP --> RE["分数下调，下次请求重估"]
  LO --> REAUTH["多因素重认证后重评"]
  REAUTH --> SCORE
```

## 边界

不写厂商对照表；边界要点名：持续评估的信号（设备姿态、行为基线）可被对抗者投毒，而误报的代价是频繁重认证造成的用户疲劳——控制太烦会被用户自己绕掉。纵深防御下一课。

## 小结

- 量化指出隐式信任贵；零信任改默认。
- 策略引擎每请求评估。
- 位置弱信号；身份单元零件接上。
