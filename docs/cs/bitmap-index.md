# 位图索引

<div class="epigraph">
<p>每个值一条位向量，行号对位；AND/OR 做谓词交并，扫描变成位运算，适合低 NDV 的分析列。</p>
<footer>—— 据 O'Neil 位图索引；Wu, O'Neil 等压缩位图；Ramakrishnan and Gehrke</footer>
</div>

[上一课](/cs/zone-maps)用粗摘要跳过区。本课不维护 min/max。缺口是低基数列（国家、状态、日期天）上的精确过滤：B+ 叶子对每个键挂 RID 列表，列表很长时交谓词要排 RID。位图：值 $v$ 对应长度为 $N$ 的位向量，第 $i$ 位表示行 $i$ 是否取 $v$。

## 问题

NDV 高（主键）则位图张数爆炸、几乎全 0，不如 B+。NDV 低则向量少，压缩后（Roaring、BBC、WAH）更小。多谓词：`color=red AND size=L` 是两向量 AND，再从置位取行。缺口是**只读或追加型分析表**上维护便宜；OLTP 频繁改行则要改多张向量，写放大差。

<span class="marginnote">术语翻译：NDV 就是「这一列总共有多少个不同的值」。「国家」列 NDV 只有几百，建几百条位向量就够了；主键列 NDV 等于行数，每行一条位图、每条几乎只有一个 1——这时的位图既大又没用，该交给 B+ 树。</span>

NULL 单独一向量。与连接：星型后课可用位图做维表过滤再探事实表。本课单表过滤。

<span class="marginnote">Patrick O'Neil 位图索引工作。压缩位图让稀疏也可接受。本课不把位图当全文倒排——倒排下一课，键是词项不是低 NDV 维值。</span>

## 方法

建：全表扫，为每个值置位。查询：取向量、位运算、解码 RID。与 zone：先 zone 跳区，区内再位图或再扫。向量化：把置位转成选择向量。

维护：原地更新翻比特；插入追加位。删除可翻或延迟与 vacuum 一起重建。MVCC：位图必须对应某一行版本集合，否则看见幽灵——常对只读副本或物化快照建位图。

```mermaid
flowchart TD
  V1["值 A 的位图"] --> AND["按位 AND / OR"]
  V2["值 B 的位图"] --> AND
  AND --> RID["置位行号"]
  RID --> FETCH["回表或覆盖列"]
```

<span class="marginnote">直觉类比：每个值的位向量就是一页点名册——第 $i$ 格写 1 表示第 $i$ 行「是这个值」。两个条件的 AND 就是把两页名册对齐，一格一格比：「两页都写 1 的行才留下」。一次 CPU 位运算同时「点名」64 行，这正是它对分析查询快的原因。</span>

## 机制

优化器：位图扫描代价 ≈ 向量体积 + 置位密度 × 回表。选择率估错会低估回表随机 I/O。覆盖：若查询列都在别处，可能只定位行号。

并行：按行号分段切向量。exchange 传位图段比传行宽。

该不该选位图，可以按两个轴决策。

```mermaid
flowchart TD
  COL["要建索引的列"] --> NDV{"NDV 低吗"}
  NDV -->|"是"| RO{"更新频繁吗"}
  NDV -->|"否"| BTREE["用 B+ 树"]
  RO -->|"只读 / 追加"| BM["位图合适"]
  RO -->|"OLTP 高频改"| NO["写放大差，慎用位图"]
```

<span class="marginnote">数字实例：100 万行的「性别」列（NDV=2）只需 2 条位向量，每条 $10^6$ 位 = 125 KB，总共 250 KB。同样 100 万行的主键列则要 100 万条向量、几乎全 0——前者位运算扫描飞快，后者纯属浪费。常见误区是以为位图「又小又快到处能用」，它其实只在低 NDV、少更新这一角占优。</span>

## 边界

本课不讲倒排词表。也不把位图连接索引（join index）写完，只点名星型可用。学习索引不替代位图的位运算。

后课默认：低 NDV 分析列可位图；高更新表慎用。倒排与全文：词项→位置列表，是搜索引擎与 `LIKE`/`@@` 的结构。

位图是行集合的特征函数，不是哈希索引。

## 小结

- 低 NDV 列用位向量做谓词交并，CPU 友好。
- 高更新与高 NDV 不适合；版本要与 MVCC 对齐。
- 倒排与全文下一课：词项列表而非维值。
- 出处：O'Neil；压缩位图文献；Ramakrishnan and Gehrke。
