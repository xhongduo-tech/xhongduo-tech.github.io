# rootkit

<div class="epigraph">
<p>rootkit 要的是隐瞒：改内核对象、拦截列举、住进引导。检测若只问用户态 API，看见的是它安排的剧场。信任应下沉到度量启动与带外取证。</p>
<footer>—— 据 Hoglund and Butler, *Rootkits*；对照 NIST SP 800-155 对 BIOS 完整性的讨论；seL4 对最小 TCB</footer>
</div>

上一课[恶意软件](/cs/malware-analysis)常仍在用户态。缺口是**隐蔽与持久在更高特权**。本课讲为何 API 不可信、检测要下沉，不给编写 rootkit 的步骤。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

用户态列举进程可被钩子过滤。内核或虚拟化 rootkit 改的是观察者本身。缺口是：完整性要从不可被目标改写的根度量（后课安全启动）。

<span class="marginnote">常见误区：初学者容易以为装了终端安全软件就等于系统可信。实际上扫描器跑在被感染的系统里时，它调用的每个 API 都可能已被安排好答案——相当于「在嫌疑人家里审嫌疑人」，问答本身成了剧场的一部分。</span>

### 课程禁止实现

不教挂钩、不教隐藏模块。只讲防御观察点。

<span class="marginnote">Hoglund and Butler 是历史技术书；本课当威胁模型引用。检测：交叉视图、内存取证、TPM 度量。</span>

## 方法

对照用户态 / 内核 / 引导。防御：安全启动链、内核模块签名、远程证明后课。下一课加固与混淆：防御方与恶意方都会用混淆，目标相反。


## 机制

特权一旦丢，同机自检变弱。下一课二进制加固与混淆：合法软件防篡改 vs 恶意软件抗分析——本课只站在防御与审计。

从「视图不一致的怀疑」到「确认与处置」，检测链是这样的：

```mermaid
flowchart TD
  A["用户态清单与内核级清单对比"] --> D{"两份视图一致？"}
  D -->|"一致"| N["暂无藏匿迹象，回到常规监控"]
  D -->|"不一致"| B["判定存在被隐藏的对象"]
  B --> C["带外取证：停机取内存镜像离线分析"]
  C --> E{"镜像里找到内核残迹？"}
  E -->|"是"| F["确认 rootkit，转入隔离与重建"]
  E -->|"否"| G["复核启动度量值与信任根"]
```

<span class="marginnote">直觉类比：交叉视图像「问两个互不通气的证人同一件事」。用户态 API 是系统自己聘的发言人说的话，物理内存里扫出来的结构才是证物；两份口供对不上，谎言就现形。</span>

## 边界

本课无 rootkit 源码。二进制加固与混淆下一课。

## 小结

- 恶意软件分析在用户态会碰到撒谎的 API。
- rootkit 把观察者变成目标。
- 检测下沉到度量启动与带外。
- 下一课加固与混淆。
