# RSA 攻击面

<div class="epigraph">
<p>RSA 的数学对象很稳，工程对象很脆：填充实现、密钥复用、小指数广播、侧信道比「分解模数」更常把系统打穿。</p>
<footer>—— Boneh, Twenty Years of Attacks on the RSA Cryptosystem, Notices of the AMS, 1999；对照 Anderson 对实现失败</footer>
</div>

上一课[OAEP](/cs/rsa-oaep)给出正确填充。缺口是**错误清单**：哪些合同一破，归约作废。本课只列机制与防御，不提供利用步骤或参数求解程序。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

OAEP 在实现里若回退到 PKCS#1 v1.5 加密，历史 Bleichenbacher 预言机就会回来——只陈述「可区分的填充错误」。共模多指数、低加密指数广播、公共私钥因子，都是密钥管理与参数选择失败。缺口是把这些收成「不要做」，而不是重讲分解算法。<span class="marginnote">术语翻译：「预言机」就是用「把系统当成只会答对/错的应答机、反复喂给它精心改造过的密文、从对错里榨出信息」的手段来做「不正面硬破、从侧面问出来」的事——服务器报不报「填充格式错误」，本身就是一条可被利用的判据。</span>

### 侧信道也算攻击面

模幂若按比特走不同时间或不同缓存，密钥位可漏。[侧信道](/cs/side-channel)已给模型，本课只把 RSA 实现标进同一模型。

<span class="marginnote">Boneh 1999 综述是合法文献。课程禁止复现其中的构造步骤。防御：OAEP/PSS、恒定时间、一密钥一用途、足够大的随机填充、换 ECDH。</span>

## 方法

按来源分类：填充预言、代数关系（共模/广播）、弱素数生成、实现泄漏。每类对应一条工程规则。指向后课 ECDH：许多新协议直接离开 RSA 封装。<span class="marginnote">常见误区：初学者容易以为「模数够大就安全」——2048 位模数照样挡不住共模攻击：两个用户共用同一个 $n$、各自用小指数加密同一消息，不用分解模数就能恢复明文。模数大小只管「分解有多难」，管不了「密钥怎么用」。</span>

## 机制

可证明安全只在游戏前提成立时成立。攻击面课的工作是列出前提：唯一用途、不可区分失败、随机填充、大模数、无泄漏实现。分解本身仍难，不等于产品安全。<span class="marginnote">直觉类比：可证明安全像保险合同——条款（前提）逐条成立才赔；实现里出现可区分错误、密钥复用、时序泄漏，任何一条违约，理赔（安全归约）就作废，数学本身不背锅。</span>

```mermaid
flowchart TD
  GAME["安全归约依赖的前提"] --> P1["密钥一密钥一用途"]
  GAME --> P2["填充错误不可区分"]
  GAME --> P3["素数独立且随机"]
  GAME --> P4["实现恒定时间"]
  P1 -- "违约" --> A1["共模/广播：明文被代数推出"]
  P2 -- "违约" --> A2["填充预言机：密文被逐位问出"]
  P3 -- "违约" --> A3["弱素数：模数被分解"]
  P4 -- "违约" --> A4["时序/缓存侧信道：密钥位外漏"]
```

## 边界

本课不写因数分解或 Coppersmith 方法的操作指导。下一课椭圆曲线 DH：换群，不换「封装会话键」这一层目标。

## 小结

- OAEP 是正确形状；实现与密钥管理才是常见破口。
- 可区分填充错误、共模、弱随机，都让归约退出。
- 一密钥一用途；恒定时间。
- 后课 ECDH/X25519 换群做协商。
