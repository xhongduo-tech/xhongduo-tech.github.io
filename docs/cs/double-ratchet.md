# Signal 双棘轮

<div class="epigraph">
<p>DH 棘轮换根，对称棘轮用 KDF 推下一条链密钥：每条消息一把键，过去的键删掉。前向保密变成消息粒度，延迟乱序用跳过的键缓存来收。</p>
<footer>—— Perrin and Marlinspike, The Double Ratchet Algorithm；对照 Krawczyk 的 KDF 提取</footer>
</div>

上一课[前向保密](/cs/forward-secrecy)停在「每个会话一把临时 DH」。缺口是**长时间对话**：消息很多、可乱序、可延迟。双棘轮把 PFS 推到消息级，并引入后向保密（泄漏后未来仍能自愈）的工程直觉。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

TLS 会话相对短。即时通讯里同一对端持续数年。每条消息都做完整握手太贵。双棘轮：收到新 DH 公钥就进一格 DH 棘轮；同格内用 HKDF 推链。缺口是状态机，不是再定义 ECDH。

### 不是区块链

棘轮是密钥演化，不需要全局账本。不要把本课写成加密货币。

<span class="marginnote">Signal 协议规格公开。本课不写客户端取证步骤。跳过的消息键要限时缓存，否则乱序无法解密。</span>

## 方法

画 DH 棘轮与对称棘轮两条轴。指出会话建立仍要身份（X3DH 只点名）。丢失消息：保留若干跳过键。对照 TLS：记录层序号 vs 消息链。

```mermaid
flowchart TD
  DH["DH 棘轮换根"] --> CK["链密钥"]
  CK --> MK["消息键"]
  MK --> DEL["用后删除"]
  CK --> CK2["HKDF 推下一链键"]
```

## 机制

消息键短命，服务前向：旧密文在键删后不可解。新 DH 进格服务后向：当前链泄漏后，下一格根与之独立。身份仍依赖长期身份钥与预密钥包——那是PKI/信任启动，不是棘轮算术。

```mermaid
flowchart LR
  subgraph AX1["DH 棘轮：收到新公钥才进一格"]
    R0["根 v0"] -->|"对方新 DH 公钥"| R1["根 v1"]
    R1 -->|"再换 DH"| R2["根 v2"]
  end
  R0 -->|"HKDF 推链"| C0A["链键 → 消息键 M1 → 删除"]
  C0A --> C0B["消息键 M2 → 删除"]
  R1 -->|"HKDF 推链"| C1A["新链键：与 v0 独立"]
  C0B --> SKIP["乱序到达的旧消息：用跳过键缓存解开"]
```

<span class="marginnote">术语翻译：「棘轮」就是那种只能单向扳动、扳不回去的机械齿条。这里指密钥只能用 KDF 一步步往前推——推过去的旧密钥被删掉后，即使攻击者拿到当前状态，也算不出任何一条已经用过的消息键，倒不回历史。</span>

<span class="marginnote">数字实例：跳过键缓存是这么用的——对方连发第 1 到第 10 条消息，你只收到第 3 条。协议必须为第 1、2 条各算一个消息键暂存（缓存通常设上限，比如 1000 个、并带过期时间），等对方补传到达时才能解。上限是防御：无限缓存会被「蒸发消息」撑爆内存。</span>

## 边界

本课不把 X3DH 的全部代数写完。后量子下一课：KEM 替换 DH 格时，棘轮形状仍在，困难问题换成格上封装。

## 小结

- 会话级 PFS 不够长对话；棘轮到消息键。
- DH 换根 + HKDF 链；用后删键。
- 乱序靠有限跳过缓存，不是无限保留。
<span class="marginnote">常见误区：前向保密和后向保密方向相反。前向：今天的密钥被偷，偷不到**过去**的消息（旧键已删）。后向：今天的密钥被偷，等下一次 DH 换格后，**未来**的密钥与小偷手里的状态无关，自动自愈。双棘轮的两个方向各管一头。</span>
