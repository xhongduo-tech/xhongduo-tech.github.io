# MPC 应用

<div class="epigraph">
<p>多方计算让机构在不交出明文表的前提下算交集或统计。应用落点是反洗钱式的集合交集、联合分析；成本在通信轮次与恶意模型。</p>

上一课[令牌化](/cs/data-masking-tokenization)仍有保险库存明文；缺口是更进一步——**计算时也不把表集中到任何一方**。密码学单元已讲过 MPC 直觉；本课收应用与限制。

## 问题

两家银行想比对客户重叠、几家机构想做联合统计，但明文交换违法或违约。PSI（隐私集合求交）与 MPC 让协议在密文份额上运算，最后只打开约定的输出。缺口是三件：多数协议只假设半诚实而非任意叛徒、性能比明文慢几个数量级、以及输出本身会泄漏。

### 输出仍可能漏

输出仍可能漏：交集本身是信息——「某人同时在两家名单里」常常就是结论。要压这个泄漏，可以在输出上再叠差分隐私噪声。

<span class="marginnote">Yao；PSI 文献。PIR 下一课是检索隐私。</span>

## 方法

方法先对照令牌化的中心化保险库：令牌化把明文锁进一家，MPC 干脆让明文不出现。应用清单按成熟度排：PSI 已是反洗钱与通讯录发现里的量产技术；联合统计（均值、直方图）次之；通用两方计算仍然贵。下一课 PIR。

## 机制

机制落点是治理语义变了：「数据不出域」从管理承诺变成协议性质——各方只学到函数输出，学不到对方输入的其余部分，审计对象从数据流转变成协议与实现的正确性。代价同样实在：通信轮次随电路深度增长，换成恶意模型还要给每个份额加可验证性，开销再涨一截。PIR 下一课是用户对数据库的隐私查询。

## 边界

不把 MPC 写成量化交易的部署方案；边界要点名：参与方串通超过阈值、输入长度这类元数据侧信道、协议实现错误，都不被理论安全覆盖。PIR 下一课。

## 小结

- 令牌化仍有库；MPC 让计算分散。
- 输出策略与模型假设决定泄漏。
- 应用是交集与统计，不是万能。
