# 形式等价检查

<div class="epigraph">
  <p>综合可能改结构但不该改功能：等价检查把 RTL 与网表切成逻辑锥，用 SAT/BDDs 证明对应点相同，不依赖测试向量有没有打到。</p>
  <footer>—— 据 Brand, Verification of Large Synthesized Designs, ICCAD 1993；IEEE Std 1800；Hennessy and Patterson 体系结构验证实践 整理</footer>
</div>

[上一课](/cs/verification-testbench)的仿真会漏未覆盖状态。[证明助手](/cs/proof-assistants)已展示「核检查」；数字流程里更常用的是**组合/时序等价检查**（LEC）：同一设计的两个视图是否功能相同。缺口是把这层签核接到综合网表，而不是再写 TB。

## 问题

综合优化、资源共享、FSM 编码可能改变中间节点。仿真回归成本随 NRE 涨。缺口：需要与向量无关的**结构对应证明**，把「工具没改功能」从「碰巧测过」里拆出来。

### 等价不是「符合 IEEE 754 规范」

两边都错会显示等价。规范符合性仍靠 TB、断言或更高层形式（属性检查）。把 LEC 通过当成 FMA 正确舍入的证明，黄金模型从未出场。

<span class="marginnote">可以把它想象成两个学生独立解题后「对答案」：答案一致只能说明两人的计算过程没走样；如果题目本身都理解错了，两人会错得一模一样，对答案照样通过。LEC 检查的是「变换没走样」，规范本身对不对它管不着。</span>

<span class="marginnote">Brand, ICCAD 1993 是组合等价的经典工业问题表述。现代工具用 SAT。本课不发明 arXiv。属性检查（model checking）在计算理论补层的[模型检验](/cs/model-checking)已给直觉，这里用在网表签核。</span>

## 方法

对应点：RTL 寄存器与网表 FF，由名称或映射文件配对。每个组合锥：从输入与寄存器 Q 到下一状态 D 与输出。证明两锥布尔等价。失败：给出反例向量，可送回仿真。时钟门控、扫描插入、流水线重定时会改寄存器边界，必须告诉工具「这些变换合法」，否则误报。

<span class="marginnote">术语翻译「逻辑锥」：从某个输出点往回追，把所有影响它的门和线收拢成一堆——形状像倒过来的漏斗。一个 64 位加法器的输出是一个锥，内部也许几百个门，但 SAT 只回答一个问题：两个视图里这堆逻辑从输入到输出的布尔函数是否完全相同，与门怎么摆、怎么共享无关。</span>

时序等价（retimed）更难，本课以组合锥+寄存器映射为主。

```mermaid
flowchart TD
  RTL["RTL"] --> CONE["寄存器映射与逻辑锥"]
  NL["综合网表"] --> CONE
  CONE --> SAT["SAT / BDD 等价"]
  SAT --> LATER["后课：硅上还要可测性"]
```

DFT 插入扫描 MUX 后要再跑一遍 LEC，或把扫描使能当约束常数做功能模式等价。

## 机制

后课扫描链改变了 FF 的 D 输入（测试 MUX）。BIST 再加模式。每次网表变换后等价检查是物理设计的闸门。CDC 结构（格雷指针）的功能正确性通常仍靠仿真/断言，LEC 只保证实现视图一致。

<span class="marginnote">初学者容易以为「LEC 通过 = 芯片正确」。实际上它只回答「综合和后端工具没有改变功能」这一件事；规格写错了、覆盖率没打到的 corner case，依然要靠测试台和断言去抓。它是流程的闸门，不是质量的终点。</span>

```mermaid
flowchart LR
  RTL["RTL:黄金视图"] --> SYN["综合工具"]
  SYN --> NL1["网表 v1"] --> G1{"LEC:与 RTL 等价?"}
  G1 -- "通过" --> SCAN["扫描插入/时钟门控/重定时"]
  SCAN --> NL2["网表 v2"] --> G2{"LEC:与上一版等价?"}
  G2 -- "不等价" --> DBG["给出反例向量,回仿真定位"]
```

## 边界

本课不把完整芯片当定理证明作业，不写 SAT 求解器内部。不把模拟电路等价（SPICE vs Verilog-A）算进来。不重开依值类型。

后课默认：RTL↔网表用等价检查签核功能不变；规范正确性仍要 TB；扫描插入后再比一次。

## 小结

- LEC 证两视图逻辑锥相同，不靠覆盖率。
- 两边同错仍等价；规范靠其他手段。
- 门控、扫描、重定时须建模为合法变换。
- 出处：Brand, ICCAD 1993；IEEE 1800；与模型检验课衔接。
