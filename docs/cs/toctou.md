# TOCTOU

<div class="epigraph">
<p>先检查后使用之间，客体可以换人；权限判断必须落在同一不可分割的引用上，而不是落在可被改写的路径名上。</p>
<footer>—— 据 Saltzer and Schroeder 对完整中介；Anderson；文件系统 TOCTOU 的经典机制叙述</footer>
</div>

[上一课](/cs/capability-vs-acl)对照了能力与 ACL。本课不重讲混淆代理人。缺口是时间：在 `stat` 与 `open` 之间，路径指向的 inode 可以变。这是完整中介失败，不是新的矩阵形状。防御是原子打开、对已打开描述符检查、用能力当稳定引用。缓冲区溢出下一课是另一类内存错误。

## 问题

能力课留下「持票即允许」。许多 API 却用路径名两次：一次检查，一次使用。两次解析可以落到不同客体上。缺口是**检查与使用的绑定**。本课只讲机制与防御合同，不给可复现的利用序列。

<span class="marginnote">直觉类比：先「看一眼工牌」再「放人进门」，两步之间工牌可以递给别人。TOCTOU 的缝就在这两步之间——被检查的不是进门的那个人，而是递工牌的那个瞬间。</span>

<span class="marginnote">网络上的同类缝是「先查会话再办事」之间会话被换。对象不同，结构同构：缺少单一引用上的原子判决。</span>

## 方法

防御：一次系统调用完成「按意图打开」（目录文件描述符 + 不跟随、或等价的安全打开）；之后只对 fd 做 `fstat`/`fchmod`。把路径换成能力或 fd 传递。锁与事务在数据库里解决的是另一对象上的同一句话：判决与更新同一快照。本课不写具体攻击者操作。

```mermaid
flowchart TD
  NAME["路径名检查"] --> GAP["中间状态可改"]
  GAP --> USE["使用时已是另一客体"]
  FD["打开得到稳定 fd"] --> SAME["随后只对同一引用判决"]
```

## 机制

TOCTOU 破坏引用监视器的「每次访问都检查」——检查的不是后来那次访问的客体。能力与 Unix fd 把客体钉成句柄，路径只在获得句柄时解析一次。后课内存破坏是改返回地址，不是换路径。

```mermaid
flowchart TD
  T1["时刻 1: 程序 stat 某路径"] --> T2["时刻 2: 攻击者把该路径换成符号链接"]
  T2 --> T3["时刻 3: 程序 open 同一路径"]
  T3 --> R["打开的已是另一个客体"]
  FIX["修复: 一步 open 直接拿 fd"] --> FS["fstat 同一 fd,判决与使用绑同一引用"]
```

<span class="marginnote">数字实例：`stat` 与 `open` 是两次独立系统调用，中间隔着微秒到毫秒；攻击脚本每秒可切换符号链接上千次。撞中窗口只是概率问题——所以防御要消灭窗口本身，而不是赌它撞不上。</span>

## 边界

本课不把全部竞态类漏洞分类写成清单。越界写如何碰到控制数据，下一课只讲机制直觉与防御，仍无利用配方。

后课默认：判决必须绑在稳定引用上。内存里的越界是另一边界。

<span class="marginnote">常见误区：以为加把锁、或在 open 前再 stat 一次就安全。重查仍是路径名判决，窗口只是变窄；只有把判决绑到打开后的 fd 或能力这类稳定引用上，检查与使用才真正不可分割。</span>

## 小结

- TOCTOU：检查与使用之间客体被替换。
- 防御是原子打开与句柄上的再检查。
- 缓冲区溢出直觉下一课。
- 出处：Saltzer and Schroeder；Anderson。
