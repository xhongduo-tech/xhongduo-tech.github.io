# 门限签名与 MPC 直觉

<div class="epigraph">
<p>门限签名让 $t$ 方一起签发，任何一方拿不到完整私钥。安全多方计算把「一起算 $f$」当成协议目标，中间值按共享走，输出才打开。</p>
<footer>—— 据 Yao 百万富翁问题；Goldreich, Micali and Wigderson；对照 Boneh, Lynn and Shacham 对门限的后续工程</footer>
</div>

上一课[Shamir](/cs/shamir-secret-sharing)重构后秘密又聚回一点。缺口是**计算阶段也不聚合明文**。本课直觉：门限 ECDSA/EdDSA 与 MPC 的诚实多数/恶意模型，不写可部署的协议抄本。

后课默认已经读完本课钉下的合同，只补差，不从该领域第一性原理重开。

## 问题

HSM 是单盒；组织要「五人中三人签字」。门限：KeyGen 分布式，Sign 交互，Verify 仍用普通公钥。MPC：各方输入保密，只揭示 $f(x_1,\ldots)$。缺口是目标陈述与敌手模型，不是电路乱码的实现作业。

### 中止与公平

恶意敌手可让协议中止。公平性（要么都得输出要么都不得）更贵。工程上常退让。

<span class="marginnote">Yao；GMW。DKLS 等门限 ECDSA 是工程文献，本课不点具体利用。后课同态是另一条「算密文」的路。</span>

## 方法

对比三种：重构再签（弱）、门限签（私钥永不出现）、通用 MPC。写诚实多数 vs 恶意、带广播 vs 点对点。指出 nonce 在门限 ECDSA 里仍危险，EdDSA/Schnorr 更贴线性。

```mermaid
flowchart TD
  SH["份额留下"] --> SIGN["交互产生签名"]
  SIGN --> PUB["普通公钥可验"]
  IN["私有输入"] --> MPC["协议算 f"]
  MPC --> Y["只打开输出"]
```

## 机制

最小特权：单人无法签。这服务治理，不服务「防所有侧信道」——交互本身有时序。网络异步下要小心同步假设。同态加密下一课把计算丢给持密文的一方，交互模式不同。

<span class="marginnote">直觉类比：门限 3/5 像保险柜要三把钥匙同时插——任何两个人凑不齐份额就开不了柜。但「签出一份有效签名」不需要先拼出整把钥匙：三人各自用份额算出一部分，拼起来的是签名本身，私钥从头到尾没在任何人手里完整出现过。</span>

## 边界

本课不提供门限 nonce 复用的攻击步骤。同态直觉下一课：密文上加乘，解密才见结果。

三条路线的私钥暴露点对比：

```mermaid
flowchart TD
  K["5 人各持 3/5 份额"] --> R["方案A: 先重构再签"]
  R --> RX["明文私钥短暂聚合: 单点风险回来了"]
  K --> T["方案B: 门限签名"]
  T --> TX["交互直接产出签名: 私钥永不聚合"]
  T --> TH["少于 3 人推不出任何东西"]
  K --> M["方案C: 通用 MPC"]
  M --> MX["任意函数都能算: 交互与成本更高"]
```

## 小结

- 共享若重构再签，秘密又单点化。
- 门限签名：交互产出，公钥仍单把。
- MPC 把任意 $f$ 当协议；模型要写清恶意与中止。
- 下一课：同态加密直觉。
- 出处：Yao；Goldreich, Micali and Wigderson；Shamir, 1979。

<span class="marginnote">常见误区：初学者容易以为「份额多的人权力大」——标准 Shamir 份额是等权的：任取 3 份都能重构，某人多拿 2 份也不会更容易。门限说的是「几人可解」，不是「谁多谁少」。</span>

<span class="marginnote">为什么重要：门限 ECDSA 里 nonce 复用一次就可能泄露私钥——单机签名尚且如此，多方交互让 nonce 随机性的审计更难。这就是工程文献更偏爱线性结构的 EdDSA/Schnorr 类协议做门限化的原因。</span>
