# MTEB

<div class="epigraph">
<p>检索、聚类、分类、改写、语义相似度不是同一个几何。一张嵌入榜必须分任务报，禁止用单任务召回签发通用嵌入。</p>
<footer>—— Muennighoff 等, MTEB</footer>
</div>

[上一课](/llm/splade)学习稀疏词表权重，倒排可含扩展词；稀疏正则是可用性条件，常作混合一路。前课从 InfoNCE、难负例、嵌套维、指令、多向量、BM25、SPLADE 堆出一排配方。缺口是比较协议：不能只用单任务召回签发通用嵌入。Muennighoff 等人的 MTEB 把多种任务收成套件；本课写怎么读这张榜，不重推 SPLADE 的正则。后课长文档嵌入默认：MTEB 多数任务偏短文，长文要另测。

## 问题

只在 MS MARCO 上刷召回，会选出非对称检索模型，聚类与 STS 可能很差。只在 STS 上刷，会选出对称相似度模型，检索标识符弱。MTEB 的点是强制多任务：检索、重排、聚类、分类、对相似度、摘要等。总分平均会重演 MMLU 课的陷阱——专长被抹平。应看任务族，尤其是与产品同构的那一族。<span class="marginnote">术语翻译：「非对称检索」指短查询找长文档（如搜「怎么退机票」应召回整页退票政策），两端长度与角色都不同；「对称相似度」（STS）指判断两句话是不是一个意思，两端地位平等。前者练的是「从海量文档里找到那篇」，后者练的是「给两句话的相似度打分」——几何要求不同，单练一个就偏科。</span>

指令嵌入必须用官方任务指令；不用指令的模型与用指令的模型分表。多语言子集（MMTEB 等扩展）与英文主表不可互换，见[多语言基准](/llm/multilingual-benchmarks)同一纪律。

<span class="marginnote">MTEB 分数绑定评测脚本版本与是否归一化、是否用特定池化。换脚本等于换榜。</span>

## 方法

发布：按任务族报，附模型类型（稠密双塔 / 稀疏 / 多向量）、最大输入长度、是否指令。不要把交叉编码器的重排分写进双塔表。污染：部分任务来自公开数据集，可能进过对比训练；应披露训练任务列表，与评测重叠的任务降级为回归。

```mermaid
flowchart TD
  EMB["嵌入模型"] --> RET["检索族"]
  EMB --> CLU["聚类 / 分类"]
  EMB --> STS["对称相似度"]
  RET --> FAM["分族读榜"]
  CLU --> FAM
  STS --> FAM
```

## 机制

不同任务对应不同的「正对」定义。检索正对是相关文档，聚类正对是同类，STS 正对是同义句。同一 InfoNCE 无法同时最优，指令与多任务采样是在帕累托面上选点。MTEB 平均分奖励折中模型；产品应在面上选自己的点，而不是选平均冠军。

```mermaid
flowchart TD
  Q["同一个句子对 或 句子与文档"] --> T1{"任务族"}
  T1 -- "检索" --> A1["正对：查询与相关文档"]
  T1 -- "STS" --> A2["正对：意思相同的两句话"]
  T1 -- "聚类" --> A3["正对：同一类别的两个样本"]
  T1 -- "分类" --> A4["正对：文本与其标签"]
  A1 --> D["同一嵌入空间 被拉向不同几何"]
  A2 --> D
  A3 --> D
  A4 --> D
```

<span class="marginnote">直觉类比：嵌入空间像一间可自由布置的展厅，任务就是不同的布展要求——检索要求「问题牌子贴在相关展品旁边」，聚类要求「同类展品摆在一起」，STS 要求「意思相同的展品挨着放」。一个展厅没法同时按三种逻辑摆到最优，多任务训练就是在几种摆法之间找折中。这也是为什么看榜要盯与你产品同一种布展逻辑的那一族任务。</span>

## 边界

套件对长文档、代码、法律条款、多模态覆盖不足。下一课补长文档；再后课补多模态嵌入。不要用 MTEB 总分代理 RAG 端到端。<span class="marginnote">常见误区：以为「MTEB 总分最高 = 我的 RAG 一定检索最好」。榜单任务是离线的、文本干净的、多数偏短文；真实 RAG 里查询是口语化的、文档可能超长或含表格，端到端还叠着重排与生成。正确用法是把 MTEB 当初筛——在检索族里挑前几名，再在自己的真实查询与文档上跑端到端验收。</span>

## 小结

- MTEB 是多任务嵌入协议，按族读，不单报总分。
- 指令、长度、模型类型必须与分数绑定。
- 训练任务与评测重叠要披露。
- 出处：Muennighoff 等 *MTEB*。
