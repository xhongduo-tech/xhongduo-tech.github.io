# 脉动阵列 / 权重驻留矩阵核

<div class="epigraph">
<p>权重先装进阵列格子里站住，激活从格子间泵过：少一次把大参数从远处内存请回来的往返。</p>
<footer>—— 公开报道对 Jalapeño 矩阵引擎的描述：MXFP 数值、weight-stationary 脉动阵列，类似 TPU 但强调更小的可高效形状</footer>
</div>

Transformer 推理的热循环是矩阵乘：注意力投影、FFN、MoE 专家。怎么把乘加铺到硅上，决定了还要搬多少权重。Hot Chips 现场稿把 Jalapeño 写成空间架构，核上有张量 / SIMD / 标量引擎；**脉动阵列与权重驻留**这一更细的矩阵核叙事，主要出现在随后的公开分析（SemiAnalysis 等）里，用来对照 TPU 式 systolic、MXFP 格式与「较小形状仍能打满」。OpenAI 幻灯原文若未逐字写出阵列尺寸，本文就把阵列尺寸当作**未公开**，只写已经反复见报的数据流选择：weight-stationary，以及公开的 13.4 PFLOP/s MXFP4×MXFP4 封装算力。不编造阵列行列数、脉动节拍、未披露的累加精度。

## 问题

通用 GPU 的张量核吃的是块状 MMA：权重、激活、输出都可能在寄存器与共享内存之间来回翻。Decode 的 $M$ 维往往是 batch×1，权重矩阵 $K\times N$ 却很大。输出驻留或输入驻留在小 $M$ 时，会把大权重反复从 HBM 或共享缓冲读进来——这正是显存墙的矩阵侧面。TPU 一类加速器用脉动阵列把乘加做成格子：数据在相邻格子间流动，减少对统一内存的随机访问。驻留策略决定谁停在格子里：权重驻留（weight-stationary）让 $W$ 装一次、激活流过；输出驻留让部分和留在格子里。推理里 $W$ 重用跨 token、激活每步都变，权重驻留与「少搬参数」的目标一致。

公开报道称 Jalapeño 的矩阵引擎采用 MXFP 数值与权重驻留脉动阵列，并相对「很大一颗 systolic、形状不对就掉崖」的设计，强调对更小矩阵维仍能保持效率。这是为了 decode 小 batch、以及模型隐藏宽不能被某一种阵列尺寸整除时的填充浪费。问题是：在没有官方阵列几何的前提下，能确定的只有数据流与数值格式家族，不能确定「这颗核等于 N×N TPU 阵列」。

### 空间核 ≠ 已经公布阵列图纸

空间架构（每个物理核一块、显式通信）说明编程模型是「把图铺到核上」，不等于矩阵单元内部必须是脉动。SIMD/标量引擎还要做归一化、激活、路由。把整颗 Jalapeño 叫成「一颗大 TPU」会抹掉切片 HBM 与集合网络。更干净的说法是：矩阵热路径被报道为权重驻留 systolic，外围是空间化的核与本地内存视图。MXFP4 的 13.4 PFLOP/s 是这条热路径的封装峰值，不是 SIMD 的峰值。

<span class="marginnote">TPU 的权重驻留是公开教科书；Jalapeño 的阵列边长、是否双缓冲、累加用哪种浮点，在可靠公开源里并不完整。遇到博客写出具体 128×128 一类数字且不引幻灯，应视为猜测。</span>

## 方法

实现层面（按公开报道）把大 GEMM 映射成：把权重量化/打包成 MXFP 块，装入阵列并保持驻留；激活（或激活的一块）沿阵列脉动，部分和在另一方向流出；再经 SIMD 做激活函数与残差。小形状支持的工程含义是：当 $M$、$N$、$K$ 不能被「理想块」整除时，仍有可用的小阵列模式或更细的流水，而不是整块空转。这与「只服务一种隐藏宽的固定功能芯片」不同，也与 [推理专用但仍能跑开源模型篮](/llm/jalapeno-inference-only) 的叙事一致。

与 [减少搬运](/llm/jalapeno-data-movement) 合在一起：切片让权重先到本地 HBM，驻留让权重再升到阵列格子；两跳都是为了 decode 时不要每 token 从远处拉完整 $W$。MoE 专家切换会打破驻留——换专家就要换一组 $W$。公开系统用门控与调度去应付阶段变化；专家频繁切换时，驻留的优势会下降。这不是秘密，是权重驻留的固有边界。

```mermaid
flowchart LR
  HBM["本地 HBM 切片中的 W"] --> LOAD["装入阵列并驻留"]
  X["激活流"] --> SYS["脉动格子"]
  LOAD --> SYS
  SYS --> Y["部分和 / 输出"]
  Y --> SIMD["SIMD：激活与归一化"]
```

### MXFP4 是数值，不是脉动的替代

13.4 PFLOP/s 钉的是 MXFP4×MXFP4 矩阵。低精度减少的是搬运字节与乘加能量；脉动减少的是搬运的**距离与次数**。两者一起才能让 700 W 封装在 InferenceX 的每千瓦图上靠近前沿。不要把「用了 MXFP4」写成已经解决利用率——格式错了仍会空等，只是每次空等搬得更少。公开对照里 Jalapeño 演示多用单 token；GPU 对照常用 MTP。数值格式与解码算法都要在表格表头里写清。

二次报道还提到 B0 步进相对 A0 约 25% 的每瓦提升，并把 13.4 PFLOP/s 联系到 B0、reticule 级 N3P 裸片。步进差异属于工艺与实现收敛，不是「换了一种脉动」。在 OpenAI 未单独发布步进白皮书前，把 13.4 当作 Hot Chips 给出的封装算力即可，不必在本篇展开 A0/B0 电路。

## 机制

脉动阵列的时间是规则的：每一拍，格子把数据传给邻居。编译器可以按拍去对齐 [显式数据移动](/llm/jalapeno-data-movement)，这与 LPU 的确定性时间表是亲戚，但存储层次不同（HBM 切片 vs 整片 SRAM）。权重驻留时，摊销公式是：装载 $W$ 的代价被随后的 $T$ 个 token（或 batch 维）分母化。$T=1$ 且专家每步都换，摊销失败，阵列退化为「很贵的点积器」。连续批处理提高 $T$ 的有效值，驻留重新划算——这与 GPU 上「decode 也要靠 batch 喂满张量核」是同一逻辑，只是 Jalapeño 用驻留减少 $W$ 的重复装载。

较小形状支持，是为了让 $T$ 不大时仍有一条不满载但不是悬崖的曲线。TPU 类大阵列在 $M$ 很小时必须堆 batch 或浪费 lanes；报道认为 Jalapeño 有意把悬崖往更小维推。没有阵列几何，我们不能定量说「小到多少」。能定量的是封装级 MXFP4 峰值与 700 W，以及评测在小并发下仍出现在 Pareto 上（公开材料强调低延迟点，而不仅仅是最大吞吐点）。

<span class="marginnote">权重驻留与 output-stationary 没有绝对优劣。训练大 GEMM 常爱 output-stationary 以留下部分和；推理 decode 爱 weight-stationary 以留下 $W$。Jalapeño 不做训练一等公民，选择与空白设计一致。若未来有人在这颗芯片上硬训，驻留策略可能并不合适——公开定位本来就不是训练器。</span>

### 和 SIMD / 标量的分工

注意力里 softmax、RoPE、RMSNorm 不是大 GEMM，走 SIMD/标量。矩阵核再快，归一化若走远内存，仍会插入空等。空间架构把这些引擎放在同一核的本地内存视图周围，目的是融合，而不是再发起一次全局搬运。公开 1.5×–1.8× 的注意力/MoE 核提升，更可能来自融合与放置，而不是来自「把 systolic 再加大一倍」——加大阵列的数字从未公布。

## 边界与工程取舍

本篇最硬的边界是：**阵列几何未在可引用的官方表里出现**。任何具体行列、任何「等同于 N 个 TPU 核」的换算，都当猜测。MXFP 的块大小、是否与 OCP MX 规范逐位兼容，亦未在本篇当作已核验。不要把 13.4 PFLOP/s 除以一个臆造的阵列面积去反推频率。

MoE 高切换、极短上下文、几乎无权重复用的工作负载，会削弱驻留。极大 $M$ 的 prefill 反而可能让输出驻留或 GPU 式 MMA 更自然；Jalapeño 用同一套核扛 prefill，靠的是「均衡芯片」而不是「只为小 $M$ 存在」。若某一层形状落到报道所防的悬崖外，只能靠编译器 padding 或切并行——开销未公开。

<span class="marginnote">出处：Hot Chips 2026 的空间核 / 张量引擎 / MXFP4 算力表；weight-stationary 脉动与小形状叙述来自 SemiAnalysis 等公开分析，已标明为报道。不填写未公开的阵列尺寸。</span>

## 小结

- 公开报道把 Jalapeño 矩阵热路径写成 MXFP、权重驻留的脉动阵列，动机是 decode 少搬 $W$。
- 空间核、SIMD/标量与切片 HBM 是更大的图；不要把整芯片叫成一块 TPU。
- 13.4 PFLOP/s 是封装级 MXFP4×MXFP4 峰值；阵列边长未公开。
- 驻留的摊销依赖权重复用；MoE 频繁换专家会打断摊销。
- 较小形状支持是报道中的差异点，用于避免大阵列在小 $M$ 上掉崖；定量几何未知。
- 出处：Hot Chips 规格表 + 标明来源的微架构报道。
