# LALM：先理解音频再生成转写

<div class="epigraph">
<p>模型先对音频信号形成高层次理解，再在该理解上生成转写，而不是只做自底向上的声学模式匹配。</p>
<footer>—— Qwen Team，Qwen3-ASR Technical Report，arXiv:2601.21337</footer>
</div>

自动语音识别长期由判别式端到端模型主导：CTC 把帧映射到字母并允许折叠空白，Transducer 在对齐路径上做流式标签生成，AED（Listen–Attend–Spell 一类）用编码器加注意力解码器直接出词。它们都在「声学模式 → 词面」这条短路径上工作，语言模型容量有限，世界知识与专名要靠外部融合。Large Audio Language Model（LALM）把路径拉长：音频先被编码为可被 LLM 阅读的表示，LLM 形成对内容、语种、噪声和场景的理解，再自回归生成转写。Qwen3-ASR 技术报告把这一范式与传统 E2E 明确对立，并以此解释长音频、噪声、专名和方言为何更自然。本篇只澄清「先理解再转写」是什么、不是什么；不是纯 CTC，也不是把 Whisper 换个名字。

## 问题

CTC 假设条件独立（给定帧对齐后标签近似独立），用外挂 LM 补语言。噪声和口误时，声学分数平、LM 乱猜。AED 已经有解码器语言模型，但仍通常从零训或从语音数据训，词表与世界知识远小于当代文本 LLM。长音频上，编码器状态与注意力长度成为瓶颈；方言与语码转换需要的是语言侧覆盖，不是多加一层卷积。

LALM 把同一目标拆成两段。先得到音频理解状态 $h=f_{\mathrm{enc}}(x)$，再由 LLM 生成

$$
p(y\mid h,\text{format})
=\prod_t p(y_t\mid y_{<t},h,\text{format}),
$$

其中 $\text{format}$ 规定语种标签与 `<asr_text>` 一类槽位。语言先验进入第二段，声学证据留在 $h$ 里。要解决的是：把文本 LLM 已经学到的句法、实体和语种先验，变成转写解码器的先验，同时保留足够的声学证据，避免「听成」常见句。Qwen3-ASR 指出，在公开测试集上各系统分数接近标注噪声上限时，真实场景的差异仍然很大——内部评测覆盖复杂声学、方言、老人小孩与多语。范式比较不能只看 LibriSpeech 小数点。

### 理解先于词面

「理解」在这里不是哲学词。它指编码器+LLM 的隐状态已经可以支撑多种音频任务（语种识别、有无语音、实体、甚至非语音场景），转写只是这些隐状态上的一种生成格式。Qwen3-ASR 的输出样式是 `language English<asr_text>...` 或无语音时 `language None<asr_text>`，说明解码器先（或同时）承诺语种与是否有人声，再写词面。纯 CTC 没有这种中间言语行为，它只有对齐路径。

<span class="marginnote">LALM 仍可能在内部使用注意力编码器，甚至预训练阶段用过 AED。对立面是「部署时只靠 CTC 头从帧分类出字」，不是「网络里不许出现过交叉注意力」。Qwen3-ASR 的 AuT 本身就是 AED 风格的音频 Transformer，但它的编码器输出被投影进 Qwen3，由 LLM 生成转写。</span>

## 方法

Qwen3-ASR-1.7B 与 0.6B 从 Qwen3-Omni 基座做后训练，支持 52 个语种与方言的识别及语种识别。音频经 AuT 编码，经学习型 projector 进入 Qwen3 解码器，自回归产生带语种标签的转写。训练分阶段：AuT 预训练、Omni 多模态预训练、ASR 监督微调、GSPO 强化学习。SFT 把模型收成 ASR-only，减轻指令注入：它不再当通用聊天模型，输出格式固定。RL 用约 5 万句提升噪声稳健与难例。

这与 CTC 管线的差别在推理接口上就看得见：没有帧级字母后验要格子解码，没有外部 WFST。有的是 LLM 采样或贪心解码，以及可选的上下文偏置写在 system prompt 里，当背景知识。ForcedAligner 另走非自回归时间戳，因为 LALM 的转写本身不保证帧对齐——先理解再生成，时间是另一条任务。

```mermaid
flowchart LR
  X["波形"] --> E["AuT 音频理解表示"]
  E --> P["projector"]
  P --> L["Qwen3 LLM"]
  L --> Y["语种 + 转写文本"]
```

### 与 AED、CTC 的关系

AED 已经是「编码器理解、解码器生成」。LALM 把解码器换成通用 LLM，并把编码器的训练目标从单一 ASR 扩展到大规模音频理解（在 Omni / AuT 阶段）。信息流仍是交叉或前缀条件，不是 CTC 的帧分类。可以说 LALM 是 AED 的解码器被 LLM 替换、编码器被大规模音频预训练加厚之后的形态。Whisper 是强 AED，但解码器不是通用文本 LLM，世界知识更窄。Qwen3-ASR 报告把传统范式举例为 Transducer 与 AED（含 Whisper），把自身放在 LALM 一侧。

## 机制

先理解再生成，意味着错误模式改变。语言模型可以修复口误、补专名、在噪声里选合语法的句子——对的时候是稳健，错的时候是幻觉替换，WER 可能看起来还行但语义已换。CTC 更常删插字母，较少整词替换成近义。评测需要实体错误、专名、歌词（报告强调歌声与歌曲识别）而不只是总体 WER。

长上下文上，LLM 可以把分钟级转写维持在同一话题下，这是传统解码器状态难以做到的。代价是自回归延迟与计算。Qwen3-ASR-0.6B 给出约 92 ms 的平均首 token 时间，并在高并发下强调吞吐，说明 LALM 并不必然比 CTC 慢一个数量级——编码器下采样到 12.5 Hz 后，LLM 前缀并不长。慢的是生成长文本本身，这与所有自回归 ASR 相同。

<span class="marginnote">SFT 把模型训练成不遵循自然语言指令，是安全与稳定性选择：避免提示词把转写改写成摘要或翻译。这与通用 Audio LM「听指令」相反。LALM 作为 ASR 产品时，理解能力被收口到转写格式，而不是被删掉。</span>

### 时间戳为何要另模型

生成式转写的 token 边界不是 10 ms 帧。要从 LLM 字面回推发音时间，需要对齐假设。Qwen3-ForcedAligner-0.6B 用非自回归 LLM 做强制对齐，支持 11 语种与多种粒度。报告强调 LALM 路线也可以把时间戳做快做准，但那是独立头，不是 CTC 后处理的免费礼物。把 LALM 理解成「自带逐帧时间」会在字幕场景失败。

## 边界与工程取舍

无语音、音乐、重叠说话人：理解模块可能输出 `language None` 或把歌声当歌词（报告将歌曲列为优势场景之一，仍不是会议叠音的解）。指令被关掉后，用户不能靠 prompt 让模型「只转写第二个人」。要说话人过滤，需另接分离或提示音频。

公开基准饱和时，LALM 的宣传差异来自内部集与真实日志。复现应同时报公开集与自建噪声/方言集，否则无法验证「先理解」是否真的转化为专名和噪声收益。RL 阶段数据仅约 50k 句，说明理解先验大部分来自 Omni 与 AuT，ASR 后训练是格式与稳健性，不是从零学语言。

<span class="marginnote">不要把 LALM 写成「不用声学模型」。AuT 就是声学前端。差别是词面由 LLM 生成，帧分类头不是主角。</span>

## 小结

- LALM 先形成音频的高层次理解，再条件生成转写；与 CTC/Transducer 的帧级或路径级分类不同。
- Qwen3-ASR 以 Qwen3-Omni 为基座、AuT 为音频编码器、Qwen3 为解码器，输出语种加转写。
- AED/Whisper 已是编码器–解码器，LALM 进一步把解码器换成通用 LLM 并加厚音频预训练。
- 语言先验提升专名与长音频，也带来整词替换式幻觉；时间戳需独立对齐模型。
- 产品形态把指令跟随收口，避免转写器被提示词改任务。
