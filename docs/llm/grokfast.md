# Grokfast

<div class="epigraph">
<p>把每一步梯度看成时间上的信号：快变分量把训练误差迅速压到零，慢变分量才把测试误差拖过那道延迟泛化的坎；放大后者，grokking 不必再等上万步。</p>
<footer>—— Lee, Cho, Lee, Grokfast: Accelerated Grokking by Amplifying Slow Gradients, 2024</footer>
</div>

Power 等人把 grokking 写成一种训练曲线：训练集准确率早已饱和，验证集却在很久之后才突然升起。延迟本身对做大模型的人通常只是轶事——没人会在模运算上再跑五万步等顿悟。Lee、Cho 与 Lee 的 Grokfast 不解释顿悟的表示几何，只处理**延迟**：把参数上的梯度序列当作随时间的随机信号，拆成快变（拟合）与慢变（泛化）两段频谱，用低通滤波抽出慢分量再加回当前梯度。论文报在模运算一类任务上可把 grokking 加速五十倍量级，实现是优化器前面几行滤波。本篇把它当作优化器笔记：改的是送进 [AdamW](/llm/adamw) 之前的梯度，不是新的二阶预条件。名称易与 xAI 的 Grok 模型混淆，对象完全不同。

## 问题

grokking 的工程痛点不是「最后能泛化」，而是中间那段已经过拟合、验证还在随机的墙钟。若算法必须先把训练集背完再等慢过程，实验室不会把它当默认日程。已有工作从表示、权重范数、数据量去解释突然泛化；Grokfast 把问题收窄成：在**不替换损失、不改架构**的前提下，能否让慢过程的时间尺度变短。

他们的观察是频谱式的。训练轨迹里，梯度对时间的序列可以看成快振荡叠加慢漂移。消融表明：只保留慢分量（相当于用很大的重叠 batch 做平滑）会让拟合变慢、训练不稳；只放大快分量则验证更晚或不来。结论是两种分量都要：快的负责把训练误差打下去，慢的负责把已经拟合的解推进到可泛化的区域。算法因此不能「换成纯低通」，只能**放大**低通，同时保留瞬时梯度。

### 梯度是时间序列，不是单步方向

普通优化器每步只看见当前 mini-batch 的 $g_t$。Adam 的 $m,v$ 也是时间平滑，但平滑的目的是自适应步长，不是按「快/慢对应过拟合/泛化」来加权。Grokfast 在优化器外再挂一层明确的低通滤波器，把 $\mathrm{LPF}(g)$ 以系数 $\lambda$ 加回 $g$。这与动量有亲缘，但意图不同：动量是为了惯性与噪声；这里的滤波器窗口或 EMA 系数是为了对准 grokking 里那条慢包络。<span class="marginnote">把 Grokfast 理解成「再加一组 Adam 超参」会调错对象。$\lambda$ 是慢分量的增益，不是学习率；$\alpha$ 或窗口长度是截止频率。学习率日程仍然按原优化器走。先固定 AdamW，再扫滤波，否则分不清是日程有效还是频谱有效。</span>

## 方法

记当前梯度为 $g_t$。滑动平均版（Grokfast-MA）维护长度 $w$ 的队列 $Q$，输出

$$
\hat g_t = g_t + \lambda \cdot \mathrm{mean}(Q),\qquad Q \leftarrow Q \cup \{g_t\}.
$$

指数滑动平均版（Grokfast-EMA）只存一份与参数同形状的 $f_t$：

$$
f_t = \alpha f_{t-1} + (1-\alpha) g_t,\qquad \hat g_t = g_t + \lambda f_t.
$$

$\hat g_t$ 再交给原优化器。论文与参考实现把滤波插在 `backward` 与 `optimizer.step` 之间，几行即可。EMA 更省显存：不必为每个参数保留 $w$ 份历史。推荐扫描区间大致是 $\lambda \in [0.1,5]$，$\alpha \in [0.8,0.99]$；MA 的 $\lambda$ 常取更大（实现默认曾见 $5$），因为窗口均值与 EMA 的稳态增益不同，不能把两个默认 $\lambda$ 互换。

他们强调不能删掉 $g_t$ 只留滤波项。替换实验里，一阶段从开头就只用慢梯度，或二阶段在过拟合之后再切换，训练都更慢更不稳。算法形态因此是**残差式放大**，不是低通替换。

```mermaid
flowchart LR
  G["当前梯度 g"] --> LPF["低通：MA 或 EMA"]
  G --> ADD["g + λ · 慢分量"]
  LPF --> ADD
  ADD --> OPT["原优化器一步"]
```

### 与「更大 batch」不是同一件事

只用慢梯度时，窗口均值确实像更大、重叠的 batch。Grokfast 的有效做法却是小 batch 的瞬时梯度叠加平滑项，既保留随机性带来的快拟合，又给慢方向额外步长。把 grokking 加速理解成「直接把 batch 加五十倍」，会先撞上泛化与显存的另一套曲线，也解释不了「必须保留 $g_t$」这一消融。

## 机制

在模加法一类任务上，训练准确率很快到 100%，测试准确率在很晚的拐点升起。放大慢梯度后，拐点左移，论文给出超过 $\times 50$ 的延迟压缩。图像、语言、图上的实验被用来主张：这一频谱分解不是模运算特有的文字游戏，只要任务呈现「先过拟合、后泛化」的双时间尺度，滤波就有机会。机制叙事是：快分量迅速进入插值区（训练集可零误差），慢分量在权重空间里走向更平坦或更算法化的解；给慢分量更大的系数，等于缩短等待。

这不是对 grokking 的完整理论。没有证明慢特征等于电路实现，也没有证明语言模型预训练存在可分离的双时间尺度。它是一条可运行的归纳偏置：若你的曲线真的 grokking，值得试滤波；若验证损失与训练损失同步下降，滤波可能只是另一种动量，收益应在验证上重新量，而不是默认五十倍。

<span class="marginnote">预训练日志里偶尔出现的「突然学会某种格式」不要自动命名为 grokking。grokking 原文要求训练集已经近乎完美、泛化滞后一个数量级步数。格式突变可能只是学习率进入余弦尾部、或数据里该模式的频率被排到。Grokfast 的适用前提是双时间尺度真的存在。</span>

### 滤波与自适应分母的相互作用

Adam 会按 $\sqrt{v}$ 缩放 $\hat g$。若 $\lambda$ 很大，慢分量长期同号，会同时抬高 $g$ 与 $v$，有效步长不一定按 $\lambda$ 线性放大。实践上应把滤波当作改变了「Adam 看见的梯度分布」，必要时略降峰值学习率，而不是假设与 SGD 上的 $\lambda$ 可迁移。权重衰减仍作用在参数上，与滤波正交；[学习率日程](/llm/lr-schedule) 的 warmup 过短时，EMA 尚未形成可靠慢估计，$\lambda$ 过猛会在初期晃。

## 边界与工程取舍

公开主实验仍以中小模型、合成或中等规模任务为主。把 $\times 50$ 抄到千亿语言模型预训练上，没有论文担保。语言模型的验证损失通常与训练损失一起降，缺乏「先背诵、后顿悟」的平台期；此时 Grokfast 更像多了一组难扫的滤波超参。图与视觉上的阳性结果说明跨域有可能，不说明每个域的最优 $\alpha,\lambda$ 相同。

显存上 EMA 只需一份额外状态，与动量同量级；MA 按窗口复制历史，大模型上不划算。实现必须对冻结参数、混合精度下的梯度缩放、梯度裁剪的顺序有约定：先裁剪再滤波，或先滤波再裁剪，会改变慢分量的幅度。分布式下每张卡的 $g_t$ 是局部 batch，滤波应在 All-Reduce 之后做，否则慢分量是数据并行切片上的局部漂移。

<span class="marginnote">Grokfast 不是二阶方法，也不替代 [Sophia](/llm/sophia) 或 [Muon](/llm/muon)。它不估计曲率，只重加权时间频谱。优化器笔记里应把它放在「梯度预处理」一格，与损失、预条件、矩阵正交化分开记账。</span>

若任务没有 grokking，优先把预算给数据与学习率，而不是默认打开 $\lambda=2$。需要报告的是验证拐点的步数，而不是训练损失更快——训练损失本来就已经很快到底。

## 小结

- Grokfast 把梯度当作时间信号，放大低通（慢）分量并保留瞬时梯度，以缩短 grokking 的泛化延迟。
- 不能只用慢梯度替换 $g_t$；快拟合与慢泛化都需要。
- 实现是 `backward` 与 `step` 之间的 MA 或 EMA 滤波，$\lambda$ 是增益，$\alpha$ 或窗口是截止频率。
- 论文在模运算上报告约五十倍加速，并在图像、语言、图任务上展示可用性；大模型预训练是否存在可分离双时间尺度，仍要单独验证。
- 与 Adam 的 $v$、学习率日程会耦合，滤波应在通信后、对全部参与训练的参数一致地做。
- 出处：Lee, Cho, Lee, *Grokfast: Accelerated Grokking by Amplifying Slow Gradients*，arXiv:2405.20233；代码 https://github.com/ironjr/grokfast。
