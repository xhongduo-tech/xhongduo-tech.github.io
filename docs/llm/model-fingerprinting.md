# 模型指纹

<div class="epigraph">
<p>特有的错误、特有的水印、特有的触发完成，可以当指纹。指纹证明「像」，很少单独证明「就是偷来的权重」。</p>
<footer>—— 对照水印与权重指纹文献；检测服务于提取与泄露，不是新的能力基准</footer>
</div>

[上一课](/llm/model-extraction-attack)留下举证缺口。本课补指纹：用行为或权重上的独特模式，识别「这是不是那一家的模型 / 学生」。缺口不是评测排行，而是取证——误报会冤枉独立训练，漏报会放过提取。

## 问题

开源微调、合并、量化会改变表面文风，但可能保留教师的特有缺陷或水印。产品需要：一组只有本模型（或本水印密钥）才会稳定表现的测试。公共基准题不能当指纹，人人都会。

<span class="marginnote">指纹应在你控制的密钥或持有提示上，不应依赖「只有我们会答错这道著名题」——著名题会被下一版修掉，也会被别人碰巧答错。</span>

## 方法

三类。**水印**：生成时嵌入统计模式，验证器持有密钥。**触发完成**：训练或系统层保留秘密前缀→固定短语（类似合法的后门，仅用于取证）。**错误谱**：在私有难例上的对错向量，比较学生与教师的相关。权重指纹（哈希、特定层统计）只适用于你仍能拿到参数的泄露场景。

<span class="marginnote">直觉类比：水印像纸币里的防伪纤维——肉眼读不出、但持灯一照就有；秘密触发像只有本行知道的暗语；错误谱则像笔迹鉴定——不靠某个暗号，而靠「这份笔迹连容易写错的字都错得一样」。</span>

```mermaid
flowchart TD
  M["待测模型"] --> W["水印检验"]
  M --> T["秘密触发"]
  M --> E["私有错误谱"]
  W --> V["像 / 不像"]
  T --> V
  E --> V
```

## 机制

水印改变 token 采样的绿色列表，密钥未知则难以抹掉且难以伪造（在假设内）。微调、改温度、转写会衰减信号，验证要报功效。错误谱依赖「教师特有的失败」在蒸馏中被模仿——提取越成功，指纹越容易命中，这是故意的。

```mermaid
flowchart TD
  C["上一个 token 的上下文"] --> H["用密钥哈希出绿色词表"]
  H --> B["采样时偏置：绿色 token 更容易被选"]
  B --> OUT["输出文本"]
  OUT --> CHK{"验证方是否持有密钥？"}
  CHK -->|"持有"| Y["统计绿色词占比，显著偏高即判『像』"]
  CHK -->|"没有"| N["看不出规律，难以抹除也难以伪造"]
```

<span class="marginnote">数字实例：设不加偏置时每个位置选到绿色词的概率约 50%。嵌水印后若稳定到 55%，单看一句什么都说明不了；但几千个 token 的文本上，这个差值足以把误报率压到极低。结论是统计性的——报的是显著性水平，不是「找到了某个暗号」。</span>

## 边界

指纹不能替代访问控制。秘密触发若泄漏，就变成可被滥用的后门，必须当密钥管。<span class="marginnote">常见误区：初学者容易把指纹当「铁证」，宣称对方偷了权重。指纹证明的是行为像——微调、合并、量化都可能让信号衰减，所以正规结论要报检测功效与置信度，慎用「就是原权重」这类断言。</span>下一课安全等级把「危险能力是否可被提取到无门控学生」写进部署政策，指纹只是检测手段之一。

## 小结

- 指纹：水印、秘密触发、私有错误谱。
- 证明「像」，慎称「就是原权重」。
- 密钥与私有集是生命线；公共基准不是指纹。
- 出处：水印课；提取课。
