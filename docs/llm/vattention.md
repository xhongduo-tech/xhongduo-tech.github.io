# vAttention

<div class="epigraph">
    <p>物理页可以按需补上，虚拟地址却不必切碎；把连续的键值视图留给注意力核，分页就可以退回操作系统该做的那一层。</p>
    <footer>—— Prabhu 等，vAttention，ASPLOS 2025</footer>
</div>

PagedAttention 把 KV 切成用户态管理的块，换来接近零的内部碎片，也换来一件连带后果：键值在**虚拟地址**上不再连续，注意力核必须带着块表去做间接寻址。Prabhu、Nayak、Mohan、Ramjee、Panwar 的 vAttention 走另一条路：用 CUDA 的虚拟内存管理接口，把「虚拟连续」和「物理按需」拆开。核仍然看见一整段 $K,V$，真正缺页时再映射物理页。本篇写这条设计为什么能成立、CUDA 大页带来什么麻烦、以及它和分页 KV 各自卡在哪；块大小与布局见 [分页 KV](/llm/paged-kv-block-size)、[KV 布局](/llm/kv-layout)。

## 问题

解码长度事先不知道。按模型最大上下文给每条请求预留 KV，内部碎片会把批次打得很小——Yi-34B 一类宣称极长上下文的模型，若按上限预留，实际对话只用几百生成 token，浪费极为刺眼。vLLM 的 PagedAttention 把缓存切成固定块、用时再分配，几乎消灭了这种预留浪费，于是成为服务框架的默认内存模型。

代价在软件层。一旦块在虚拟空间里也不连续，FlashAttention、FlashInfer、cuDNN SDPA 这些假定「$K,V$ 是稠密张量」的核都要改：循环里多一次块表翻译，预填充尤其容易变慢。Prabhu 等人量到：带分页的 FlashAttention-2 预填充核可比非分页核慢约三成，FlashInfer 预填充可慢约四成；vLLM 自带的分页核相对 FlashAttention-2 可慢到数倍，且换块大小会让核时间差出近两倍。新核——例如面向 Hopper 的 FlashAttention-3——发布时往往还没有分页变体，服务栈只能继续跑旧核，或再等一次移植。

<span class="marginnote">碎片有两种。内部碎片是「块内没用满」；外部碎片是「空闲物理页凑不成用户想要的连续虚地址」。PagedAttention 用用户态块表躲开第二种；vAttention 用操作系统的按需分页，让第一种靠更小的物理页去压，第二种根本不进入注意力核。</span>

## 方法

### 虚实分离：先留虚拟，后补物理

CUDA 的 `cudaMalloc` 一次同时拿到虚拟区间和物理页。vAttention 改用 CUDA Virtual Memory Management：先为每条请求（或每个槽位）保留一块覆盖最大上下文的**连续虚拟缓冲区**，物理页暂不提交。每生成若干 token，再把对应的物理页映射进这段虚地址。注意力核的指针算术与训练时、与单机脚本时相同：偏移就是 token 下标乘上每 token 字节数。服务框架不必再实现一套块表翻译，也不必为每个注意力实现维护分页分支。

物理页的粒度受驱动限制。官方 CUDA 虚拟内存接口按 $2\,\mathrm{MiB}$ 大页分配。对 KV 这种「一次只增长一个 token」的工作负载，大页意味着新的内部碎片：一条还很短的请求也可能被钉上一整页。论文因此改开源的 CUDA 统一虚拟内存驱动，补上 $64\,\mathrm{KiB}$（以及 $128$、$256\,\mathrm{KiB}$）的页组。评测里 $64\,\mathrm{KiB}$ 页没有把注意力核打进 TLB 抖动；碎片则明显小于 $2\,\mathrm{MiB}$。

### 把分配延迟藏进计算

虚拟内存 API 每次映射都要进内核，延迟远高于在预分配池里拿一个块指针。vAttention 用几条推理特有的重叠把这笔税藏起来：计算当前层时，异步为后续增长预映射下一组页；回收不立刻做，等请求结束后批量解除映射，避免在解码热路径上同步 `unmap`。再配合「提前一页」的乐观分配，使缺页几乎不落在注意力核的关键路径上。

### 不改核，只改分配器

作者把分配器接到 vLLM 一类框架里，让未修改的 FlashAttention-2 / FlashInfer / 后来的 FlashAttention-3 直接吃连续张量。可移植性是一等目标：新核只要仍假设连续 KV，就能立刻享受动态物理内存。他们在 Yi-6B、Llama-3-8B、Yi-34B、一至两张 A100 上对比分页变体：用非分页 FlashAttention-2 时，解码吞吐相对 vLLM 可到约 $1.99$ 倍；端到端相对 FlashAttention-2 与 FlashInfer 的分页核，最高约 $1.18$ 与 $1.23$ 倍；在当时尚无分页支持的 FlashAttention-3 上，相对分页版 FlashAttention-2 约 $1.26$–$1.5$ 倍。

## 机制

连续虚拟地址让编译器和核作者回到熟路径：向量化加载、swizzle、tensor core 的 $K$ 布局，都可以按稠密张量写，不必在内层循环查 `block_table[i]`。分页核的慢，往往不是算法更差，而是间接寻址打散了合并访存、让预填充的大块 $K,V$ 读不成连续突发。把翻译从 GPU 核挪回 CPU 侧的内存管理器（更准确：挪回驱动的页表），GPU 只看见命中后的连续映射。

动态性仍然在。物理页总数受 HBM 限制，批次过大时映射会失败，服务层仍要做抢占或拒绝——这一点与 PagedAttention 相同，只是失败发生在 `map` 而不是「空闲块列表为空」。前缀共享则更尴尬：分页块可以在块表里让两条请求指向同一物理块；连续虚地址若要共享前缀，需要把同一物理页映射进两个虚拟区间（写时复制或只读共享），CUDA 上能做，但实现复杂度和基数树加块表不同。vAttention 的论文焦点是单请求缓冲的碎片与核性能，不是 [RadixAttention](/llm/radix-attention) 那种多级前缀索引。

<span class="marginnote">「不用分页」指的是注意力核不用分页，不是系统里没有页。页还在，只是在 GPU 页表里，而不是在 Python 的 `block_table` 里。</span>

## 边界与工程取舍

CUDA 虚拟内存接口的可移植性受硬件与驱动绑定。改 UVM 驱动以支持 $64\,\mathrm{KiB}$ 页，在论文环境里可行，在托管云、封闭驱动或非 NVIDIA 设备上就不是一键开关。不改驱动、只用 $2\,\mathrm{MiB}$ 大页时，碎片可能吃掉「相对预留上限」省下的大部分红利，尤其是大量短请求的解码。此时 PagedAttention 的 $16$–$32$ token 块反而更省。

前缀缓存、抢占换出、KV 卸载到 CPU，分页模型更顺手：一块就是迁移单位。vAttention 要在虚地址连续的约束下做同样的事，要么把整段虚缓冲换出，要么在中间插入「空洞页」，核又要开始处理非密集区间。多租户共享系统提示时，块表共享是现成原语；虚实分离要额外做一次多映射。

延迟隐藏依赖「计算足够盖住 `map`」。极短解码、或 CPU 侧调度已经很满时，映射延迟会露出来。回收延迟则可能造成「请求已结束、物理页还占着」的拖尾，高峰期看起来像泄漏。工程上必须有强制回收的水位线。

选择可以写成：若你的瓶颈是分页核相对稠密核的退化、且要跟进没有分页分支的新注意力实现，vAttention 更干净；若你的瓶颈是前缀共享、细粒度卸载和跨请求块复用，用户态分页仍更合适。两者也可以分层——物理层用 VMM，逻辑层仍用树索引——但那是组合，不是论文默认形态。

<span class="marginnote">评测数字随核版本变动。把 $1.23$ 倍抄进容量规划没有意义；要抄的是方法：同一套未改动的稠密核，动态物理内存是否还撑得住目标批次。</span>

## 小结

- vAttention 用 CUDA 虚拟内存把 KV 的虚拟连续与物理按需拆开，注意力核无需分页分支。
- 官方 $2\,\mathrm{MiB}$ 大页对逐 token 增长过粗，论文用定制驱动提供 $64\,\mathrm{KiB}$ 级页组以压碎片。
- 映射延迟靠与计算重叠、提前一页、延迟回收来隐藏。
- 收益主要来自「跑得动更快的非分页核」，以及新核不必等分页移植。
- 前缀共享、细粒度换出、跨设备卸载，仍是用户态块表更顺手的区域。
- 可移植性受驱动与厂商 API 限制，不是纯算法开关。
- 出处：Prabhu、Nayak、Mohan、Ramjee、Panwar，*vAttention: Dynamic Memory Management for Serving LLMs without PagedAttention*，ASPLOS 2025。
