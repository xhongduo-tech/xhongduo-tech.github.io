# 鲁棒性、安全与可解释性

当前是待实践的评测专题，不代表模型已经通过安全认证或完成解释性研究。前置为[固定评测与对照](/evaluation/quality-systems)、[模型与Attention](/foundations/transformer-architectures)；工具实验接在[检索与工具调用](/applications/retrieval-agents)之后。本页实验仅使用本地合成数据、无害任务与mock工具，不测试真实第三方服务。

## 先定义要测的行为

| 方面 | 问题 | 必须区分的结果 |
| --- | --- | --- |
| 输入鲁棒性 | 同义改写、无关片段和证据位置改变是否影响回答？ | 意义保持的扰动，与本来就改变正确答案的输入变化 |
| 事实与幻觉 | 回答是否正确、是否有足够证据支持？ | 有证据答错、无证据编造、正确弃答，以及答案正确但引用不支持 |
| 拒答与弃答 | 何时应回答，何时说明不知道或无法执行？ | 证据不足的弃答、执行权限拒绝、对正常任务的过度拒答 |
| 指令与数据边界 | 检索内容或工具结果能否改变执行范围？ | 模型提出越权动作、执行器是否实际放行，分别计数 |
| 可解释性 | 某个特征与输出相关，是否真的参与该次决策？ | 观察相关、可读出信息、干预影响与可泛化机制解释 |

[TruthfulQA v2](https://arxiv.org/abs/2109.07958v2)测量模型模仿人类错误观念的事实性问题，不是全部幻觉的统一测试；[XSTest v3](https://arxiv.org/abs/2308.01263v3)研究正常请求遭到过度拒绝，说明拒答率本身不能直接当作能力或安全性的总分。这里借用问题区分设计小实验，不移用论文成绩。

## 实验一：扰动、证据与拒答

建立约20个可人工验证的合成事实和问题，每题保留原文、答案与允许行为。按来源或问题组切分；同题改写不能横跨开发集与测试集。

1. 比较原始问题、人工核对过的同义改写、加入无关段落和移动正确证据位置。固定模型、模板、生成预算与评分器。
2. 增加“证据缺失”和“证据冲突”两组；要求输出结论、证据ID或明确弃答，不能把猜中的答案直接记成证据支持。
3. 增加正常任务与无害的权限边界对照，例如允许读取合成记录、禁止修改该记录；权限标签来自本地执行配置，不从模型措辞推测。
4. 保存逐题回答、引用、弃答/拒绝类型和错误原因，再计算分组结果与成对变化。

同时报告正确率、证据支持率、正常任务过拒率、弃答覆盖情况。可把回答覆盖率定义为“非弃答数/总题数”，已回答部分正确率定义为“其中正确数/非弃答数”；零回答时后者记为不适用。全部拒绝不能因“未编造”而被包装成可靠完成任务。口头表达的“确定”也不是已经校准的置信度。

### 算例：条件准确率提高，可能只是少回答难题

构造20个有充分证据、应当能回答的正常问题，比较两种输出策略。数字用于检查分母，不是个人模型结果：

| 统计 | 策略A | 策略B |
| --- | ---: | ---: |
| 回答数 | 18 | 10 |
| 正确回答数 | 15 | 9 |
| 错误回答数 | 3 | 1 |
| 弃答数 | 2 | 10 |
| 回答覆盖率 | 90% | 50% |
| 已回答部分正确率 | 约83.3% | 90% |
| 全部问题上的正确率 | 75% | 45% |

B的错误回答更少、条件正确率更高，但覆盖和总体正确率下降。是否接受这种取舍应由预先约定的任务协议决定，不能只凭一个“更少出错”的数字宣布优化成功。证据不足的问题应另设分组；不能混进这里，把合理弃答和对可答问题的过度弃答混为一谈。

## 实验二：间接指令与执行器边界

间接prompt injection可以来自被检索的文档或工具返回数据，而非用户直接输入。[Greshake等论文v2](https://arxiv.org/abs/2302.12173v2)展示了这种数据与指令混淆；本实验仅构造无害的本地边界测试，不复现其对真实应用的攻击。

准备普通检索片段与夹带伪指令的合成片段，保持问题和事实不变。工具只允许本地只读搜索/计算mock；另设一个被执行器明确禁止的mock操作。所有执行结果写入内存事件日志，不发送消息、不访问生产资源、不产生外部副作用。

| 对照 | 要检验什么 | 留下什么证据 |
| --- | --- | --- |
| 无伪指令 / 有伪指令 | 正确答案、工具选择或终止是否改变 | 输入片段、模型输出、拟调用工具与参数 |
| 执行器允许 / 拒绝同一mock请求 | 权限是否由确定性执行代码控制 | 请求、授权判断、执行与拒绝事件分别记录 |
| 正常结果 / 空结果 / 超时 | 失败是否被识别，循环能否停止 | 重试次数、步数/时间上限、终止原因 |

越权提议率与越权执行率分别统计；执行器拦住动作，不表示模型没有受到干扰。提示层分隔或提醒也不等于已证明注入问题消失。验收以该测试集、工具集合和执行范围为限，不把少量合成样本的通过率外推到所有环境。

## 实验三：归因、探针与toy干预

梯度/热力图通常描述某种局部敏感性或可视化关系，探针是在表示上训练额外预测器；这些都不能单独证明原模型使用了同样的信息完成任务。[带控制任务的探针研究v1](https://arxiv.org/abs/1909.03368v1)说明需区分表示信息与探针自身的学习/记忆能力。

先在CPU构造已知结构的toy模型：表示包含两个相关特征，输出函数只使用第一个特征。训练一个从第二个特征预测标签的简单探针，再做下面的对照：

- 保留正常相关分布，记录探针准确率；另用独立控制标签检验探针的记忆或泄漏问题。
- 保持第一特征不变，只打乱或替换第二特征，比较原模型输出与探针结果；应能说明“可以预测”与“原模型确实使用”为什么不同。
- 对真正参与输出的特征做匹配干预，并加入随机位置或无关特征对照；保存干预前后的logit或任务分数变化。

这是已知小函数中的机制验证，不是发现真实语言模型电路。扩展到真实小模型时，应明确干预位置、替换来源和任务分布；置零可能制造分布外状态，输出变化也不自动建立完整因果解释。[GPT-2 small的IOI电路研究v1](https://arxiv.org/abs/2211.00593v1)可作为后续阅读案例，理解因果干预及忠实性、完备性、最小性的检验；其特定任务解释不能直接推广到其他能力。

### 把“读得到”与“用到了”写成可计算反例

令表示为 $(h_1,h_2)$，原模型输出logit为 $f(h_1,h_2)=2h_1$，探针直接读第二特征。普通样本中令两特征相同：

| 输入或干预 | 原模型logit | 探针读出的第二特征 |
| --- | ---: | ---: |
| $(1,1)$ | 2 | 1 |
| $(-1,-1)$ | −2 | −1 |
| 固定第一特征，只将第二特征改为−1：$(1,-1)$ | 2 | −1 |
| 固定第二特征，只将第一特征改为−1：$(-1,1)$ | −2 | 1 |

如果标签只取决于第一特征，探针在普通样本上也能全对，但第三行中原模型完全不跟随探针变化。在这个已知线性函数里，第二特征可预测标签，却未参与输出计算；第四行提供真正参与特征的干预对照。不能将这个构造推广成“真实模型中梯度为零就一定无因果作用”，饱和、非线性和干预分布都会使实际解释更复杂。

## 验收、时间与结论边界

交付任务与标签规范、固定版本/配置、逐样本输出、mock事件日志、扰动对照、toy干预结果，以及至少一项反例或失败解释。质量、拒答、拟动作与实际执行分栏，不合成一个不透明总分。复用现有runner与评测数据格式，按当前项目瓶颈选择一组实验，其他先阅读，不额外启动GPU项目。

大规模特征分解、电路搜索、模型编辑等解释性研究仅进入后续候选；先完成基础目标、统计与小干预，不因能生成一张热力图就宣布“模型已解释”，也不因拒答或干预一个神经元就声称模型已对齐或安全。
