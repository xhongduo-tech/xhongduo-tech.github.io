# 评测与复现

评测贯穿推理、微调和后训练。先定义问题与基线，再看结果；把内容质量、服务成功和运行成本分开记录。

## 共同记录

| 类别 | 应记录什么 |
| --- | --- |
| 版本 | 模型、tokenizer、代码commit、库与驱动 |
| 数据 | 来源、许可、样本范围、划分与散列 |
| 配置 | 模板、生成参数、训练参数与随机种子 |
| 模型质量 | 正确性、格式、证据支持、失败类别与退化 |
| 系统表现 | 延迟分布、吞吐、内存、失败与资源回收 |
| 对照 | 相同条件、改变因素、重复次数和原始结果 |
| 边界 | 未验证的条件、估算、模拟和真实硬件的区别 |

## 四种证据层次

**机制分析**解释算法与假设；**源码追踪**固定版本定位执行路径；**CPU机制实验**检验小规模性质；**真实硬件实测**记录模型与系统表现。它们都可以有价值，结论范围分别表述。

## 写作检查

论文的性能结果注明来源与条件。个人结果附配置、原始数据和复现方法。模拟后端可验证错误处理，不能证明模型推理提速。一次loss下降不能直接证明任务质量改善。

具体写作结构见[博文方法](/writing/)。
