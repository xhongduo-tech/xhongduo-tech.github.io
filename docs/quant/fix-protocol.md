# FIX 协议

<div class="epigraph">
<p>FIX 把「我要买、我改过、我成交了」收成带标签的字段序列；它不是撮合，是会话层上的业务语言。同一经济意图，在不同柜台的标签子集里可以合法地不一样。</p>
<footer>—— FIX Trading Community, FIX Protocol 规范（4.2 / 4.4 / 5.0 SP2）；对照 Harris 对订单生命周期与报文的讨论</footer>
</div>

[上一课](/quant/orderbook-reconstruction)从引擎输出重建簿。本课的缺口是**你如何把意图送进引擎、又如何收到私有回报**：金融信息交换协议（FIX）是机构订单与分配的事实标准。它不替代撮合核，也不替代后课的二进制交易所协议。后课默认你会区分：会话层序号、业务 ClOrdID、以及交易所 OrderID。

## 问题

策略对象是目标仓位；交易所对象是一笔带生命周期的订单。中间必须有一份双方同意的字段字典：方向、数量、价格、时效（Day / IOC / FOK）、账户、容量（agency / principal）。FIX 用 `Tag=Value` 的文本（或后课二进制封装）携带这些字段。问题不是「会不会发 NewOrderSingle」，而是：哪些字段是会话完整性（MsgSeqNum、PossDupFlag），哪些是业务幂等（ClOrdID），哪些是交易所状态（OrdStatus、ExecType）。三者混用，撤单会对错对象，重连会重复下单。

FIX 4.2 仍在大量经纪商柜台；4.4 补了分配与多腿；5.0 把应用层与会话层拆开（FIXT）。版本不是品味：对方只实现的子集才是你的契约。同一 `35=D`（新订单）在 A 股柜台还要带股东账户、是否两融、是否程序化报备字段；美股可能带路由与防自成交指令。把美股样例直接打到上交所网关，会在前置风控被拒，而不是在撮合核里「差不多能用」。

### 会话重连是状态机，不是重发最近一笔

TCP 断开后，FIX 会话用序号对齐：我的下一发送序号、我期望的下一接收序号。缺口则要求重放（Resend Request），对方用 PossDup 重发。业务层必须忍受「同一 ClOrdID 的执行报告再来一次」。幂等只能落在 ClOrdID 上：同一客户订单号不得生成第二笔新订单。引擎侧的 OrderID 在你尚未收到前不存在，不能拿来做本地主键。

<span class="marginnote">执行报告（35=8）的 ExecType 与 OrdStatus 不是同义词。前者说「本条消息是一次新的什么事件」，后者说「订单现在处于什么状态」。部分成交会多次 35=8，CumQty 递增；用最后一次的 LastQty 当全部成交量会少算。</span>

## 方法

把 FIX 映射成内部订单对象时，固定三套标识：`cl_ord_id`（你生成、全局唯一）、`order_id`（交易所回报后填）、`exec_id`（每笔成交唯一，用于去重）。数量用 `OrderQty / CumQty / LeavesQty` 三角校验；对不上就停交易并人工对账，不要用「大概剩多少」继续改单。改价在多数市场是 Cancel/Replace，新 ClOrdID 链回 OrigClOrdID；时间优先是否保留看交易所，不看 FIX 标签是否还叫 replace。

会话层与应用层日志分开存。监管与事故回放需要：原始出入站报文、本地解码后的对象、以及与撮合核时间戳的对齐。不要只存数据库里的「已报、已成」枚举——那是投影，丢了 PossDup 与部分成交序列。对 A 股，拒单原因码（价格超出涨跌幅、超过可卖量、未报备程序化）要进[监控](/quant/trading-telemetry)，它们是制度过滤器，不是网络噪声。

### 分配与 Drop Copy 不是交易主路径

机构成交后的分配（Allocation）走另一组消息，时钟可以晚于撮合。Drop Copy 是只读的执行报告副本，给风控与对账，不能当第二次下单通道。研究若把 Drop Copy 当完整订单流，会漏掉未成交的挂单与已拒绝的意图。完整生命周期必须含 New / Cancel / Replace 的确认与拒绝，而不能只有成交。

## 机制

FIX 把异步世界收成「请求–确认」。你以为的「已挂单」只在收到确认（或交易所 OrderID）之后成立；在此之前，本地应处于 pending new / pending cancel。用 pending 状态去再发一笔，制造重复。这与撮合核的全序不同：核内没有 pending，只有已接受或未接受。延迟来自会话跳数（你的 EMS → 经纪商 → 交易所网关 → 核），FIX 本身的文本编码只是其中一截；后课二进制协议会把这截再削薄。

文本 FIX 的字段可以重复、可以乱序（除会话头），解析必须按字典而不是按位置。校验和（10=）只能抓传输损坏，抓不住「价格单位错了两位」。单位与小数位属于柜台契约，必须在预交易校验里写死。

## 边界

FIX 不是行情主馈送。用 FIX 的市场数据消息做微观结构重建，带宽与精度都不够，应走交易所本地行情。本课不写如何构造可逃避监管的隐蔽指令或拆单到监控阈值以下。加密场外、即时通讯下单、ISO 20022 清算报文是相邻但不同的语言。

中国市场的报盘接口大量是柜台二次封装的 FIX 或二进制私有协议；标签含义以会员接口说明书为准，不能假设 FIX.org 样例字段齐全。

## 小结

- FIX 是订单生命周期的会话语言，不是撮合；主键是 ClOrdID，交易所 OrderID 后到。
- 重连按序号重放，业务幂等按 ClOrdID；部分成交通过 CumQty 累加。
- 日志留原始报文；拒单原因是制度状态，不是噪声。
