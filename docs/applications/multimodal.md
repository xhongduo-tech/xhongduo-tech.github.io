# 多模态机制与成本

本专题先建立可解释的结构认识，再做低成本实验；不把从零训练大规模视觉、视频或语音模型作为入门任务。当前没有个人训练或性能结果。前置为张量形状、Attention、[训练与后训练](/training/)中的监督与数据划分，以及[质量与服务评测](/evaluation/quality-systems)。

## 视觉与语言怎样连接

| 组件 | 需要掌握的内容 | 应能解释的边界 |
| --- | --- | --- |
| 输入处理 | 解码、缩放、裁剪/切片、归一化与patch组织 | 原图尺寸不一定是编码器实际输入尺寸 |
| 视觉编码器 | patch embedding、位置、视觉特征形状 | 图像特征不是天然的语言token ID |
| 连接层 | 线性映射、MLP或其他特征压缩/对齐结构 | 不同模型的连接方式不能套用同一实现 |
| 语言骨干 | 视觉表示与文本上下文怎样进入生成 | 占位符、实际视觉序列与attention mask需对应 |
| 训练 | 图文对齐、视觉指令数据、冻结范围和label mask | 接通编码器不等于已经具备图像理解能力 |

[CLIP v1](https://arxiv.org/abs/2103.00020v1)提供图文对比学习的起点；[LLaVA论文v2](https://arxiv.org/abs/2304.08485v2)展示连接视觉编码器与语言模型的视觉指令学习路线。这两类训练目标不同，不能把CLIP检索相似度直接解释为生成回答的可靠程度。

源码阅读从LLaVA固定commit `c121f0432da27facab705978f83c4ada465e46fd` 的[projector builder](https://github.com/haotian-liu/LLaVA/blob/c121f0432da27facab705978f83c4ada465e46fd/llava/model/multimodal_projector/builder.py)入手：该文件按配置建立线性、MLP或identity映射。先追踪输入与输出维度，再向前查特征选取、向后查文本拼接；这里只记录入口核验，没有宣称完成整个模型的数据流复现。

## 视觉token与服务成本

对于无额外切片、无压缩且处理后尺寸可被patch边长整除的简单网格，可用 $N_{\text{patch}}=(H/P)(W/P)$ 做形状练习，$H,W$为处理后的尺寸、$P$为patch边长。不能整除时，padding、裁剪与无padding卷积会得到不同边界计数。真实模型还可能缩放、增加特殊位置、合并patch或动态切片，最终视觉token数必须由对应processor和实现核对。

分辨率、图像数和视频帧数会影响编码计算与语言侧上下文。对decoder输入中实际参与注意力的总序列，需要连同视觉token评估prefill、[KV缓存](/inference/kv-cache)和上下文预算；不能只按文字token估算。也不能把粗略的 $O(T^2)$ 注意力计算量直接写成某个框架必然分配同等大小的显存。

[Qwen2-VL论文v2](https://arxiv.org/abs/2409.12191v2)以动态分辨率和多模态位置表示说明另一类实现路线。它是理解“尺寸与token数由架构决定”的实例，不是适用于所有VLM的统一计费公式。

## 音频与视频的认识边界

音频至少区分语音识别、翻译、语音生成与实时对话；视频至少增加帧采样、时间顺序和跨帧信息。认识这些结构，不等于已经掌握端到端统一多模态训练。

可先从[Whisper论文v1](https://arxiv.org/abs/2212.04356v1)认识语音到文本的序列建模；固定commit `86098128c0b4f24f0e2aa2994de830614b474227` 的[audio.py](https://github.com/openai/whisper/blob/86098128c0b4f24f0e2aa2994de830614b474227/whisper/audio.py)可用于追踪重采样、补齐/截断和log-Mel特征。不要由此推断Whisper具备语音生成或完整实时对话能力。

## 低成本实验与对照

1. **CPU形状实验**：使用自己生成的图像或许可清楚的少量公开图像，记录不同分辨率下的预处理结果、patch/视觉序列长度与张量形状。先做手算，再核对一个固定processor的实际输出；手工网格只属于机制实验。
2. **CPU连接层练习**：用小随机张量验证视觉维度到语言隐藏维度的映射、mask与拼接顺序；这不验证图像语义，也不代替训练。
3. **真实VLM小任务**：准备约20条可人工核对的OCR、计数或图表问题，比较同模型两档分辨率。保留正确/错误答案、实际视觉token、总输入、延迟与内存；先解释低分辨率是否丢失任务信息，再讨论代价。
4. **音频扩展**：自录或选取许可清楚的短音频，核对采样率、长度、特征形状；有条件再跑小型ASR，固定转写规范，按语言选择WER或CER，并单独记录噪声和静音样本。

GPU实验以模型适配和显存估算通过为前提，限制样本数、输出长度和运行时间；训练连接层或多模态LoRA留到文本SFT与评测闭环能够独立解释后再排期。

## 验收产物与常见错判

至少交付一张输入到输出的数据流图、形状与token记录、固定版本的预处理配置、分辨率对照、失败案例和证据边界。多模态评测按文档/视频或说话人等来源划分，避免同源近重复泄漏。

常见错判：只上传图片成功就称掌握VLM；把图像尺寸直接当视觉token数；认为提高分辨率一定提高正确率；仅评估流畅描述而不核对图片事实；把一张视频帧的判断当作时序理解；把音频转写错误归因于语言模型知识；把CPU形状测试包装成GPU加速或训练成果。

核验日期：2026-11-16。论文与源码版本如上；实验选择的模型权重、processor和库版本仍须在实际运行时另外固定。
