MTP 的训练目标与推理作用 ​

专题计划 · 待研究

以 DeepSeek-V3 报告的具体设计为教学锚点。计划完成标签与损失检查，尚无本人的模型训练或推理实测。

要解决的问题 ​

普通 next-token prediction 在每个位置预测下一 token；multi-token prediction 扩展训练目标到后续多个位置。不同论文的 MTP 实现不完全相同：Gloeckle 等的论文采用共享主干上的独立输出头，而 V3 报告 §2.2使用顺序连接的额外模块，维持各预测深度的因果链。

本页要回答：多步目标怎样对齐，训练时输入了哪些已知 token，推理时预测模块如何变成草稿，为什么训练采用 MTP 不代表部署后自动加速。

前置依赖 ​

需要会读张量 shape、embedding、交叉熵和 loss mask，区分 teacher forcing 与生成时的历史输入。先看基础地图，再理解投机解码中的目标验证与修正；第一次做标签检查无需训练大模型。

V3 中的模块和训练目标 ​

按报告的索引：主模型在位置 i 预测 ti+1；深度 k 的 MTP 模块把前一深度表示与 ti+k 的 embedding 组合，再预测 ti+k+1。额外模块包含投影和 Transformer block，并与主模型共享 embedding 与输出头。V3 §2.2，式 21–25

将总训练目标示意为：

Ltotal=LNTP+λD∑k=1DLMTP(k).

D 是额外预测深度，λ 控制辅助损失权重。这里省略其他训练项，位置范围、归一化及序列边界以具体实现为准；不能把一个简化目标当作完整训练配方。

路径在位置 i 的新增 token 输入预测目标
主模型因果主干已有历史ti+1
MTP 深度 1ti+1 的 embedding 与主干表示ti+2
MTP 深度 2ti+2 的 embedding 与深度 1 表示ti+3

训练时这些后续 token 来自已知训练序列；生成时尚未确定的未来真值不可用，必须使用相应生成历史。更深预测层不意味着可以绕过因果约束。

从训练走到推理，还缺什么 ​

V3 报告明确给出两种用法：推理可移除 MTP 模块，让主模型独立运行；也可利用这些模块提出投机草稿。MTP in Inference

后者还要求对应权重公开且可加载、引擎实现草稿路径、目标验证、采样与状态回退。收益取决于额外计算、草稿匹配程度、硬件和并发；MTP 的训练目标本身不构成加速证明。后续的 DSpark还研究专门的草稿模型、置信度估计和验证预算，不能只用“MTP”三个字概括。

一个三位置例子：目标对齐与可见信息同时检查 ​

本例的输入是 t1=A,t2=B,t3=C，另有已知训练标签 t4=EOS，因此输入长度 T=3。教学上取两个额外深度来暴露对齐边界，不声称这是 V3 实际训练深度配置。EOS 作为该教学文档的末目标，后面不跨入另一个文档；padding 不进入损失。

基础位置 i主模型目标深度 1 新增输入 → 目标深度 2 新增输入 → 目标
1，当前历史 ABB → CC → EOS
2，当前历史 A、BCC → EOS无有效目标
3，当前历史 A、B、CEOS无有效目标无有效目标

共有 3、2、1 个有效训练目标。这里“新增输入 B → 预测 C”不表示让模块看见 C 的真值；B 在这个预测条件下属于已知历史。主模型与各深度之间的 causal mask 仍须与目标位置匹配。

从依赖集合看，在每个预测深度也可作归纳：

dep(hi(k))⊆{t1,…,ti+k}.

主模型 k=0 只依赖截至 i 的历史。额外深度加入 ti+k，再使用因果的顺序模块，仍不应看到目标 ti+k+1。如果把后一个 token 的 embedding 误作输入，即使 loss 降得很快，也可能只是标签泄漏。这是依赖结构的论证，不是训练收益的证据。V3 报告式 21–24

loss mask 相同，归一化不同，辅助目标权重也会不同 ​

给定各有效位置上真标签的预测概率：

  • 主目标：0.8、0.5、0.25；
  • 深度 1：0.5、0.25；
  • 深度 2：0.25。

只需真标签概率即可复算交叉熵，不声称这些概率来自已训练模型。按照报告式 24 的共同 1/T 归一化，并取 λ=0.2,D=2：

LNTP=−ln⁡(0.8⋅0.5⋅0.25)3≈0.767528,L1=−ln⁡(0.5⋅0.25)3≈0.693147,L2=−ln⁡(0.25)3≈0.462098.

主目标和两个辅助目标加权后的总损失可写成

Ltotal=0.767528+0.1(0.693147+0.462098)≈0.883053.

若实现悄悄改成每个深度各自除以有效目标数 2 和 1，则两项变为约 1.039721、1.386294，总目标约为 1.010130。标签完全相同，但各项相对权重已经变了。这两种约定可以各自被设计使用，不能在复现或对照中不加说明地混用。

实际代码还要核对 packing、文档边界、mask 和分布式归一化。本例只针对给定三位置定义，不把它当作完整 V3 训练配方。

训练信号、草稿质量与执行成本怎样接上 ​

辅助目标改变的是训练时的监督与参数更新；它能否改善主模型任务质量，要用训练对照检验。推理时把模块用于草稿，则进一步涉及草稿分布与目标分布是否接近，以及引擎验证和执行成本。

因此这里有三个不能互相代替的结论：

要支持的主张必需证据单独不足以证明它的东西
目标实现正确标签／mask、可见信息与 loss 数值对齐训练 loss 持续下降
辅助训练有收益控制数据、token／计算预算与评价的训练对照多了若干预测头或训练信号
推理产生收益模型权重和引擎兼容、验证正确、总成本对照使用了 MTP 目标或接受率较高

投机页的质量守恒处理第二条路径中的采样正确性；DSpark继续处理草稿与验证预算。任何加速数字都需要在这两层之后才讨论。

源码级验收还有什么缺口 ​

本页固定的 V3 inference/model.py可对照主干、输出头与 attention；本轮未在这个文件中定位到完整的 MTP 训练模块和损失路径，不能拿它替代该部分实现证据。

计划继续定位明确匹配论文结构的公开实现，逐项核对：深度循环、共享参数身份、输入 shift、目标 shift、mask 与归一化。若尚未找到，就将交付限定为机制推导和教学 reference，并保留这项源码缺口；也不把另一代模型的 next-n 实现直接当成 V3 同一设计。

负对照包括把目标错移一位、向模块输入其预测目标真值、把尾部 padding 算入损失、混用两种 reduction，以及误把共享头变为独立副本。预期是相应依赖检查或手算 loss 明确失败，而不是仅观察最终训练分数。

CPU 小实验：标签、mask 与损失 ​

计划构造含 BOS、EOS、padding 的短序列，不下载大权重：

  1. 输出主目标、深度 1 和深度 2 的位置对齐表，用可读 token 与 token ID 双重检查。
  2. 给每个位置写出允许看到的 token 和目标，检查尾部越界、跨文档边界和 padding 是否按约定屏蔽。
  3. 用手工 logits 计算各深度交叉熵，分别打印有效位置数、归一化方法和加权总损失。
  4. 以随机小张量检查投影和共享输出头的 shape；若做最小可训练示例，明确它是教学结构，不是 V3 复训。

标签移位正确是必要检查，不能单凭 loss 下降判断模型实现正确。

后续 GPU 实测 ​

先确认所选小模型是否真的提供可用 MTP 权重，以及引擎支持的准确版本。若进行辅助目标训练对比，须控制训练数据、token 预算与评价方法；若研究推理，则比较同一主模型开启／关闭受支持草稿路径的行为与成本。这是两类独立实验，不用一个结果替代另一个。

保存草稿长度、接受长度、验证耗时、总延迟和质量检查。V3 是本页固定教学对象，不是当前模型或当前引擎支持现状的代称。

验收产物 ​

  • 可核对的三层标签表、mask 断言和损失计算脚本。
  • 一张分开的训练图与推理图，标清共享参数、输入历史、草稿及验证。
  • 兼容性清单：具体模型 revision、MTP 权重、引擎 commit、采样模式；未支持项写明。

常见错误 ​

  • 把多步辅助预测等同于一次无条件产出多个可信 token。
  • 在推理演示中输入未来真值，却当作真实生成结果。
  • 将所有 MTP 论文画成独立并行头，或把 V3 的设计推广到全部后续架构。
  • 用主模型示例源码证明全部训练模块已公开。源码中找不到的实现应标为未核验。
