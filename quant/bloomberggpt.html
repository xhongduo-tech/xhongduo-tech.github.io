BloombergGPT ​

我们在彭博自有金融语料与通用语料的混合上训练一个 500 亿参数模型，使金融任务显著提升，同时不牺牲通用基准。

—— Wu, İrsoy, Lu, Dabravolski, Dredze, Gehrmann, Kambadur, Rosenberg and Mann, BloombergGPT: A Large Language Model for Finance, arXiv:2303.17564

Wu 等人给出第一篇被广泛引用的金融领域从零预训练大模型报告：BloombergGPT，约 50.6B 参数的 decoder-only，训练在 FinPile（约 3630 亿金融 token）加上约 3450 亿公开通用 token，合计约 7090 亿，实际训练约 5690 亿（不足一整 epoch）。架构按 BLOOM 族与缩放律选在 50B 附近，70 层、40 头，Unigram 分词，512 张 A100，ZeRO-3，BF16。权重与 FinPile 不发布，附录 Chronicles 记录训练过程。评测分三块：通用 LLM 基准、公开金融基准、内部票据任务。本篇写混训为什么是那条路、内部基准不可复现意味着什么、以及量化研究应如何引用这篇论文——当领域适配的存在性证明，而不是当可下载的交易模型。

问题 ​

金融 NLP 任务谱很宽：情绪、实体、新闻分类、问答、内部支持工单。通用 LLM 在公开金融集上已经能做，但术语、数字、表格与「Bloomberg 英语」仍有缺口。两条极端路：极大通用模型，指望涌现覆盖金融；或小模型只在金融语料上训，牺牲通用能力。彭博的产品约束是：大多数应用在金融内，但仍需要通用语言能力。于是走混合：领域 token 与通用 token 近乎一半对一半。问题变成配比、分词、以及如何证明增益来自 FinPile 而不是来自多训了 50B。

不可复现是这篇论文的结构性事实。内部情感与分类集最能代表「打算怎么用」，也最不能被外部审计。公开集（如 ConvFinQA、FiQA 情绪）可以对照 GPT-NeoX-20B、BLOOM-176B、OPT-66B，但公开集容易被后续通用模型追上。因此 BloombergGPT 的科学贡献主要在配方与负结果记录：混训可行、50B 在当时基础设施上可训、以及 Chronicles 里的数值事故；不是在提供一个可插入回测的检查点。

为何不是 176B ​

BLOOM-176B 更大，但金融任务上并不自动更好，且推理成本与延迟不适合终端内大量分类。作者用缩放律在给定计算预算下选宽深，落到 50B 量级。这对量化实验室的启示是：领域模型的尺寸应由任务延迟与数据量定，而不是由排行榜最大模型定。内部分类要的是稳定 F1 与可部署，不是长链推理。后来的开源路线（FinGPT 的 LoRA）把同一问题改写成「不训 50B」，两者回答的工程约束不同。

论文标题是「a large language model for finance」，评测主结果是 NLP 任务，不是截面收益。把 BloombergGPT 写成「彭博的交易模型」，是把文档模型误认为组合模型。

方法 ​

FinPile。 金融侧来自新闻、申报、彭博终端相关文本等内部源，规模在当时被称为最大的领域专用集之一。通用侧是标准公开语料。混合的目的是防止灾难性遗忘：只在金融上训，通用基准会掉；只在通用上训，金融术语与内部格式弱。分词用 Unigram，强调金融数字、代码与专有名词的切分——这直接影响后续所有数字任务。外部无法验证 FinPile 的去重、时效与泄漏（测试新闻是否出现在训练里）。

训练。 Decoder-only 因果语言建模，BF16，ZeRO stage 3 分片。训练日志记录损失尖峰、硬件故障与超参。对试图复现的人，Chronicles 比「50B」这个数字更有用：大规模混训的失败模式是工程事实。评测协议把内部任务与公开任务分开报，避免只用内部集宣称 SOTA。

对照。 公开金融任务上相对 GPT-NeoX、BLOOM、OPT 有明显间隔；内部情感加权 F1 相对 GPT-NeoX 的差距更大（论文表中内部情感平均约 62 对 29 量级）。通用基准上不牺牲，是混训主张的另一半。间隔有多少来自数据、多少来自训练配方、多少来自提示，外部不能分解。

量化研究里的合法引用 ​

引用 BloombergGPT 应限于：（1）领域混训的存在性与配比经验；（2）内部任务与公开任务必须分开报告；（3）闭源导致后续工作转向适配器与开源基准。不应引用为：（a）某个可复现的情绪 alpha；（b）终端数据可被外部模型等价替代。文本因子仍应建立在可冻结、可时间戳的模型上。若只用论文表格里的 F1 去论证「金融 LLM 能交易」，对象错了。

ConvFinQA 一类数值问答测的是读表与多步算术，与 EDINET 式长文档欺诈检测不是同一难度，见EDINET-Bench。BloombergGPT 在公开金融 QA 上的领先，不能外推到「读完有价证券报告就能识别舞弊」。

机制 ​

混训起作用，是因为词表与表示同时看见「earnings」「EPS」「guidance」的共现，以及通用英语的句法。金融语料提供领域共现，通用语料提供指令与常识，避免模型只会票据腔。50B 提供容量去记实体与数字格式，但不保证事实永真：因果 LM 的目标是下一 token，不是审计一致性。内部任务增益更大，符合「训练分布靠近测试分布」；这也是不可复现的根源——测试分布是私有的。

与适配器路线的机制差异：从零混训改先验，LoRA 改任务条件分布。先验强的模型在零样本金融术语上更稳；适配器在基座已够用时更便宜。2023 年之后通用模型变强，公开金融集上的专有优势被部分吞食，这并不否定 FinPile 在内部工单上的价值，只说明公开基准饱和不是领域问题消失。

分词机制常被低估。金融文本充满代码、小数、百分号、表格对齐。Unigram 若把 10.5% 切碎，后续分类头仍可能靠上下文猜对情绪，但抽取与算术会错。这解释了为何文档多模态基准（FinMMDocR）要把视觉版面单独测：纯文本模型从未真正看见表格线。

数据特权与评测特权 ​

彭博的数据特权是真实的：新闻到达、公司关系、内部标签。评测特权同样真实：内部基准可以紧贴产品。科学上应把两者标成「不可迁移的优势」。开源基准（CFinBench、FinSearchComp）存在的理由，就是把评测特权从单一机构手里拿出来。混训论文没有义务开源 FinPile；读者也没有义务把内部 F1 写进自己的因子备忘录。

边界与工程取舍 ​

不要试图「复现 BloombergGPT」作为交易研究的前置条件。不要用通用模型在公开金融集上超过 2023 年表格，就宣布领域预训练过时——内部分布可能仍偏。不要把训练计算（512×A100）当成自己微调预算的参照；那是从零预训练的数字。合规上，终端文本有合同约束，不能进公开训练仓。

对量化平台，BloombergGPT 的可迁移教训是协议：混训配比要扫、通用与领域任务要同时报、训练过程要记日志、模型与数据不发布时要把这一条写在摘要里。后续工作应把力气花在可审计基准与 PIT 文本特征，而不是花在猜测 FinPile 里有什么。

缩放律选 50B 是给定 2023 年算力与数据的解。换到 2026 年的长上下文与推理模型，最优尺寸与目标都会变。引用时应写清「当时的 50B 混训」，不要写成金融 LLM 的永恒标准形态。

小结 ​

  • BloombergGPT（Wu et al., arXiv:2303.17564）是约 50B 的金融混训 decoder-only：FinPile 363B + 通用 345B，权重与语料不发布。
  • 主张是混合配比同时服务金融任务与通用基准；内部集增益最大，也最不可复现。
  • 量化上它是领域适配的存在性与工程记录，不是可交易检查点；文本 alpha 仍需可冻结模型与时间戳。
  • 开源后续（FinGPT 等）用适配器回避从零 50B；公开基准用于收回评测特权。
  • 出处：Wu, İrsoy, Lu, Dabravolski, Dredze, Gehrmann, Kambadur, Rosenberg, Mann, BloombergGPT: A Large Language Model for Finance，arXiv:2303.17564。
