Kronos K 线基础模型 ​

通用时序基础模型在金融 K 线上往往弱于专门的非预训练架构；Kronos 用层次化离散 token 与自回归预训练，把 K 线当成市场的语言来建模。

—— Shi, Fu, Chen, Zhao, Xu, Zhang and Li, Kronos: A Foundation Model for the Language of Financial Markets, arXiv:2508.02739，AAAI 2026

清华大学史宇、傅宗亮等人提出 Kronos：面向金融 K 线（OHLCVA：开高低收、成交量、成交额）的开源基础模型。通用 TSFM 的预训练语料里金融占比低，且很少覆盖波动预测与合成路径生成；直接套到 K 线上，常打不过 iTransformer 一类专门模型。Kronos 的回答是两段式：先用带层次重构的 tokenizer 把一根 K 线离散成粗粒度 + 细粒度子 token，再用 decoder-only Transformer 做自回归。预训练语料超过 120 亿条 K 线、45 家交易所、7 种粒度。论文报告零样本价格预测 RankIC 相对领先 TSFM 提升约 93%、相对最强非预训练基线约 87%，波动 MAE 低约 9%，合成 K 线保真度高约 22%。本篇把它当作市场语言的离散化与预训练对象，评估仍走量化的信息集、泄漏与成本，而不是把 RankIC 直接翻译成可交易 \(\mu\)。

问题 ​

K 线是固定区间上的多元记录，不是单变量收盘价。高低价约束、量价耦合、隔夜跳空、不同品种的最小报价单位，构成一种紧致的「语言」（Nison 对 K 线的经典叙述在这里变成数据约束）。通用 TSFM 的归纳偏置来自气象、交通、电力：信噪比高、季节性强、跨域可迁移。金融序列信噪比低、非平稳、体制切换快，OHLCVA 各分量还带会计式约束（高 \(\ge\) 开收低）。把六维连续向量当普通多元时序，模型可以输出违反这些约束的路径。

第二个缺口是下游任务谱。预测收盘只是一块；波动、合成数据（压力测试、数据增强）、跨品种迁移，才是量化日常。通用 TSFM 很少为这些任务设计生成式接口。Kronos 把它们统一成「离散 token 上的条件生成」：预测是向前采样，合成本质上是无条件或条件采样，波动可以从生成路径的统计量读出。问题于是变成：离散化会不会把已经很弱的信号量化掉，以及自回归会不会把未来 K 线的信息泄漏进历史 token。

连续回归为何不够「基础」 ​

在单市场、单粒度上训一个 iTransformer，可以很强，但换交易所、换 1 分钟到日线，就要重做。基础模型的承诺是：同一套表示服务多任务、多市场。这要求输入空间可对齐。连续值的尺度差几个数量级（价格与成交量），层归一化不能代替经济学上的相对化。离散 token 把「今天这根 K 线像词表里的哪一类形态」变成分类问题，尺度被码本吸收。代价是码本崩塌与量化误差：若粗 token 只记住「大涨/大跌」，细 token 就要承担残差；若码本过大，自回归词表爆炸。

RankIC 是截面排序相关，不是可交易夏普。论文用它比较预测质量，合理；把它乘上杠杆当实盘期望，会跳过成本、可交易日历与拥挤。基础模型的零样本增益，首先应对照同一宇宙上的线性与树模型基线。

方法 ​

Tokenizer。 每根 K 线 \(\mathbf{x}_t\in\mathbb{R}^{6}\) 经 Transformer 自编码器进入 Binary Spherical Quantization（BSQ / LFQ 一族）。\(k\) bit 的二元码被拆成等长的粗子 token \(b_t^c\) 与细子 token \(b_t^f\)，从而把词表 \(2^k\) 变成两次 \(2^{k/2}\) 的预测。训练损失是

\[\mathcal{L}_{\mathrm{tokenizer}}=\mathcal{L}_{\mathrm{coarse}}+\mathcal{L}_{\mathrm{fine}}+\lambda\mathcal{L}_{\mathrm{quant}}, \]

其中 \(\mathcal{L}_{\mathrm{coarse}}\) 只用粗码重构，\(\mathcal{L}_{\mathrm{fine}}\) 用完整码重构，\(\mathcal{L}_{\mathrm{quant}}\) 把连续潜变量拉向二元码。层次损失强迫粗码捕捉主结构、细码补残差，而不是事后再猜解码顺序。

自回归。 Decoder-only 对历史 token 做因果注意。下一步的联合写成

\[p(b_t\mid \mathbf{b}_{\lt t})=p(b_t^c\mid\mathbf{b}_{\lt t})\,p(b_t^f\mid\mathbf{b}_{\lt t},b_t^c). \]

先预测粗、再条件预测细。两个子 token 各自嵌入后拼接、线性融合，作为该时刻的输入。这与语言模型的「先主题后细节」类似，但对象是一根 K 线而不是一个子词。

语料与零样本。 45 所交易所、七种粒度、约 120 亿条。评测含价格预测、波动、合成路径。开源权重见 shiyu-coder/Kronos。使用时应按时间切分：预训练若包含测试年的同一标的，零样本就不是零样本。跨市场迁移若测试日与训练日重叠在全球交易时段上，也要检查时钟。

从 token 到量化管道 ​

生成式接口便于做情景：给定历史，采样多条未来 OHLCVA，再在路径上计算波动、回撤、保证金。这与压力 VaR 的情景生成是同一类对象，但约束不同：K 线必须满足高低价不等式、成交量非负、停牌日成交为零。采样后应做可行投影，不能把违约束路径当成压力情景。预测任务上，把 token 解码成收益，再在截面做 rank，接到IC / IR；标签窗口与训练窗口的重叠仍按重叠调整处理。

自回归按时间步展开，并不自动保证无前视。若 tokenizer 在全样本上拟合码本，再拿历史序列编码，码本边界已经看见未来的极值。码本与 AR 权重都必须按 \(\mathcal{F}_t\) 冻结，或至少按年滚动重估。

机制 ​

离散化起作用，是因为它把「形态」与「尺度」分开：同样的大阳线在不同价格水平上落到相近的粗 token，细 token 再编码影线与量。这接近技术分析的离散语言，但码本是数据驱动的，不是人工 K 线词典。粗到细的条件分解降低了一步分类的难度，也给生成过程一个脚手架：先定方向与波动档位，再填高低影线。

预训练的跨市场语料提供共享的短程结构（波动聚集、价量同步、开盘跳空后的回复），不提供永恒的 alpha。非平稳意味着 token 转移概率会漂移；零样本 RankIC 高，可能来自对短期动量或隔夜跳空的统计 Regularity，而这些 Regularity 在成本与容量下未必可交易。合成保真度高，说明模型学会了无条件分布的若干矩，不等于学会了条件可预测成分。

与101 公式化 alpha 的分工：公式是稀疏、可审计的算子树；Kronos 是稠密、生成式的先验。把 Kronos 的隐状态或生成分位当特征，仍要走截面中性与样本外，与把 ts_rank(close,10) 当特征是同一纪律。它不能替代点-in-time 基本面，也不能看见盘口队列。

粒度、时区与微观结构 ​

七种粒度共享同一词表，意味着 1 分钟与日线被当成同一语言的不同句长。这对「形态可迁移」是优点，对微观结构是风险：分钟 K 线的 OHLC 受微观结构噪声支配，日线还含隔夜信息。时区上，全球 45 所的「同一自然日」并不是同一信息集。用纽约收盘的日 K 去条件亚洲早盘的分钟 K，必须显式对齐，否则预训练学到的是日历泄漏。

边界与工程取舍 ​

不要在含测试期的语料上预训练再报告零样本。不要把合成 K 线直接当新的训练标签——那是模型自我强化，不是数据增强，除非合成器与预测器严格隔离。不要假设输出自动满足套利约束；高低价、成交额与均价的会计恒等需要后处理。计算上，长上下文的 K 线序列仍是二次注意；交易研究常用的 512–2048 根窗口应预先固定，避免用未来更长的窗口回头选超参。

监管与风控要路径，不要只要一个 RankIC。若用 Kronos 做情景，应报告违约束率、极端分位是否比历史极值更肥，以及条件生成是否在压力周校准。它是研究用先验，晋级模拟前必须冻结 tokenizer 版本、语料截止日与随机种子，见研究、模拟、实盘隔离。

论文的「语言」是比喻：K 线没有语法审稿人。Tokenizer 崩塌时，模型仍会给出流畅的下一根 K 线，只是信息量接近无条件均值。监控码本使用率与粗 token 熵，比监控训练损失更接近金融对象。

小结 ​

  • Kronos（Shi et al., arXiv:2508.02739，AAAI 2026）是开源 K 线基础模型：BSQ 层次离散化 + decoder-only 自回归，预训练约 120 亿条、45 所交易所。
  • 粗/细子 token 把大词表拆成两步预测，并显式把主结构与残差分开。
  • 零样本 RankIC 与合成保真度是论文指标；量化管道仍要 PIT、成本与约束投影。
  • 码本与权重必须按信息集冻结；跨市场、跨粒度共享词表会引入时钟与噪声体制的错配。
  • 出处：Shi, Fu, Chen, Zhao, Xu, Zhang, Li, Kronos: A Foundation Model for the Language of Financial Markets，arXiv:2508.02739；代码 shiyu-coder/Kronos。
