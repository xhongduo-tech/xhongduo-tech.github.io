FinSearchComp 检索基准 ​

金融分析师的日常是在时效数据、历史披露与多源对账之间做检索与推理；没有开放域搜索的评测，测不到智能体真正缺的那一层。

—— Hu, Jiao, Liu, Ren, Wen et al., FinSearchComp, arXiv:2509.13160

字节跳动 Seed 与哥伦比亚商学院顾问合作的 FinSearchComp，是面向开放域金融搜索与推理的端到端智能体基准。635 道专家题，70 名金融专家标注，覆盖全球与大中华，三类任务：时效数据获取（最新收盘、汇率）、简单历史查询（某年某科目）、复杂历史调查（多年对比、极值月份）。21 个带网页的产品与 API 对照：全球子集上 Grok 4（web）约 68.9%，接近人类专家约 75%，仍落后约 6 个百分点；大中华子集上豆包等中文产品领先，但距人类约 88% 的差距更大（论文称逾 34 个百分点）。联网与金融插件显著加分。本篇写它测的是搜索深度、新鲜度与口径对齐，不是闭卷知识，也不是可交易信号。

问题 ​

BrowseComp 一类通用浏览基准故意要短而可核验的冷僻事实，不要求 TTM 对财年、单位与币种、修订与财报日历。FinQA 一类金融问答把上下文预先放进题目，绕过搜索。结果是：模型可以会做表内算术，却不会去找「哪一份 10-K 的哪一行」，或用过期网页上的市值当「最新」。金融检索的失败会直接变成估值与合规错误。FinSearchComp 把任务写成分析师工作流的三个频段：现在时、点历史、多源综合。

时效题的正确答案每天在变，因此评测必须连到实时或准实时数据源，并用容差带（修订、舍入、收盘相对结算）。这与静态考试集不同，也使排行榜具有时间性：同一模型在不同评测日分数会动。复杂调查题则要求跨年拼接、来源对账、防止把开盘当成收盘、把财政年度当成自然年。

开放域不是「允许百度一下」 ​

开放域意味着不指定唯一 URL，智能体要选择源：交易所、监管、公司 IR、专业库。论文发现常见失败：该调金融插件时却用了不可靠网页；源对了但字段错（开盘/收盘）；把简单市值问句拆成过深的多步而算错。国家来源与工具栈显著影响大中华子集——中文披露与人民币口径对英文浏览代理不友好。这不是「中文模型更懂投资」，是源覆盖与语言。

人类专家全球 75%、大中华 88%，说明题本身并非不可做，而是需要专业检索习惯。模型接近全球子集、远离大中华子集，应解释为工具与语料地理，而不是「推理能力差 34 分」。

方法 ​

三类任务。 T1 时效获取：价格、汇率、金价等，强调新鲜度与核验。T2 简单历史：如某季度 iPhone 收入、某年员工数，强调回到正确披露与报告期。T3 复杂调查：如 2010 年以来标普 500 单月最大涨幅、多年云收入对比，强调多期综合与来源一致性。全球 / 大中华分子集，避免单一市场口径。

标注与评分。 70 名专家，多阶段质检，基于量规的 LLM 评分加容差，并辅以专家抽查。答案允许合理区间，以吸收统计修订。工具：允许任意网页与插件，评测的是产品级智能体，而不是固定检索器+固定阅读器的实验室套件。发布见项目页与 HuggingFace ByteSeedXpert/FinSearchComp。

消融。 联网相对闭卷、金融插件相对通用搜索，均显著提升。失败案例分析指向搜索过浅与过期信息。对照表把 FinSearchComp 标成同时满足开放域、工具、时效、端到端、整体评测的集合，以区别 Finance Agent Benchmark 等限于自建系统或纯历史、可被记忆打穿的集。

与量化信息集对齐 ​

检索智能体若进入研究管道，必须把「查询时点」写成 as-of。回测 2019 年的策略时，禁止调用 2026 年的网页；应查询当时的披露快照或本地镜像。FinSearchComp 的时效题是为今天的产品设计的，不是为历史回测设计的。历史查询题更接近 PIT：指定报告期，要求回到当时文件。复杂调查在回测中最危险——模型可能用后来修订的宏观序列。本地化做法：冻结爬取的文档库，检索只打这个库，用 FinSearchComp 的题型做回归，但答案改为库内金标。

容差带处理修订，不等于允许任意源。专业库之间定义不一致时，基准选择官方披露优先。研究备忘录应写死「以哪个源的定义为准」，否则 IC 会变成源切换的函数。

机制 ​

搜索起作用，是因为金融事实不在权重里：最新价格、刚发布的 8-K、修订后的 GDP。闭卷 LLM 只能背训练截止日期前的数字，时效题上会系统性过期。插件起作用，是因为结构化库提供字段语义（收盘价 vs 结算价），网页 HTML 不提供。复杂调查失败，常因为浅搜索停在第一篇新闻综述，而综述用了复权或不同指数口径。

地理机制：大中华披露在交易所网站、巨潮、公司公告 PDF，英文代理的搜索词与源白名单不覆盖，分数塌缩。这与中文知识基准 的语言优势同源，但对象是检索图而不是选择题。多源对账机制：同一指标在新闻与 10-K 不一致时，专家会按层级取舍；模型常平均或取最新抓到的数。单位与币种是乘法误差，一次错就会让 T3 全错。

端到端产品评测的机制是：真实用户用的是带搜索的 App，而不是论文里的固定 pipeline。优点是外部有效性；缺点是不可复现——网页变、插件变、模型日期变。科学报告应记录评测日与工具版本，否则 68.9% 不可重复。

不能测什么 ​

FinSearchComp 不测交易执行、冲击成本、也不测未公开信息。高分只说明「能把公开数字找对并做初等综合」。它不替代文档内视觉推理（FinMMDocR）或整份年报上的舞弊检测（EDINET）。把检索准确率当成选股能力，是把分析师助理的技能当成组合经理的技能。

边界与工程取舍 ​

不要用会变的在线评测当唯一发版门槛而不记录日期。不要在回测里接入实时搜索。不要把插件供应商的错误数据当成模型能力——对账至少两个官方源。评分用 LLM 裁判时，量规必须公开，并抽查；否则裁判模型的偏见会进入排行榜。复杂调查的计算应尽量在代码里做，检索只负责取数。

对量化平台，FinSearchComp 适合评测「研究助理智能体」：能否在规定时钟下取对数、对齐 TTM/FY、标注来源。它不适合评测 alpha。闸门：没有来源与时间戳的数字不得进入特征；来源不在白名单不得进入。见迟到数据 与 PIT。

记忆可以打穿纯历史闭卷集；时效子集是抗记忆的。若某模型在 T2/T3 很高、T1 很低，它可能在背数字而不会搜索。分任务报告比总分更有诊断价值。

小结 ​

  • FinSearchComp（Hu et al., arXiv:2509.13160）用 635 道专家题评测开放域金融搜索：时效、简单历史、复杂调查，全球与大中华分子集。
  • 带搜索与插件的产品显著更好；Grok 4（web）在全球子集接近人类，大中华子集仍大幅落后人类。
  • 失败模式是浅搜索、过期信息、字段与口径错误。评测具有时间性，须记录日期与工具版本。
  • 量化上只作为助理取数能力的回归；回测必须用冻结快照，禁止实时网页。
  • 出处：Liang Hu, Jianpeng Jiao, Jiashuo Liu, Yanle Ren, Zhoufutu Wen et al., FinSearchComp: Towards a Realistic, Expert-Level Evaluation of Financial Search and Reasoning，arXiv:2509.13160。
